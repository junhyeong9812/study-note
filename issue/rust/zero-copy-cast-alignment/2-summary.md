# issue/rust/zero-copy-cast-alignment — 정리 (힌트)

## 전체 흐름

```text
[재해석 캐스트가 성공하려면 — 네 조건]
  &Page (바이트 16384개)  ──cast──▶  &Node { u64, u64, [u64; N], ... }
     │
     ├─ ① 모든 비트 패턴이 유효한가   → derive(Pod)가 검사 (컴파일 타임)
     ├─ ② 패딩이 없는가                → derive(Pod)가 검사 (컴파일 타임)
     ├─ ③ 크기가 같은가                → const assert!(size_of == PAGE)로 직접 단언
     └─ ④ 주소가 대상 정렬의 배수인가  → 런타임에서만 판정 ← 여기가 함정

[정렬 1인 버퍼 — 주소 운]
  버퍼 시작 오프셋 0  ── 8의 배수 ──▶ 성공
  버퍼 시작 오프셋 1  ── 어긋남  ──▶ Err(TargetAlignmentGreaterAndInputNotAligned)
                                     (그냥 cast_*면 패닉)
  버퍼 시작 오프셋 8  ── 8의 배수 ──▶ 성공
     └─ 주소가 우연히 정렬돼 있는 동안은 테스트가 초록 → 간헐 실패

[고친 뒤]
  #[repr(C, align(8))] struct Page([u8; PAGE]);
     → 컴파일러가 모든 Page 값의 주소를 8의 배수로 보장 → ④가 타입 수준에서 사라짐

[곁가지 — 빌드 단계]
  derive(Zeroable) on [u8; 16384] → E0277
     기본 배열 impl은 정해진 길이 목록(0..=32, 48, 64, …, 4096)뿐
     → 임의 길이는 const generics 기능 플래그로 켠다
```

## 핵심 문장

- 바이트를 구조체로 재해석하려면 비트 유효성·패딩 없음·크기·**주소 정렬** 네 조건이 필요하다 — 앞의 둘은 derive가, 크기는 const 단언이, 정렬은 **타입의 정렬 속성**이 지킨다.
- 정렬 1인 버퍼의 주소가 우연히 8의 배수이면 통과한다 — 그래서 결함이 "가끔"만 터지고 테스트는 우연히 통과할 수 있다.
- 정렬은 런타임 검사에 맡기지 않고 **타입에 박아** 운을 없앤다(`#[repr(C, align(N))]`). 사본 비용을 감수할 수 있으면 정렬 무관 읽기도 된다.
- 재해석 경로의 가드는 변이로 확인한다 — 패딩을 만들거나 크기를 한 칸 줄였을 때 **컴파일 오류**가 나야 가드가 살아 있다.
- 결정적 재현: 버퍼 안에서 시작 오프셋을 직접 1로 밀어 캐스트해 본다.
