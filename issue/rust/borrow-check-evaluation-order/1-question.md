# issue/rust/borrow-check-evaluation-order — 가변 빌림은 인덱스 식보다 먼저 시작된다: `&mut a[f(&self)]`가 E0502로 거부되는 이유 — 질문

## 질문
1. (예측) `let b = &mut self.items[self.slots[self.slot(key)]];` — `slot`은 `fn slot(&self, key: u64) -> usize`다. 이 줄은 컴파일되는가? 안 된다면 어떤 빌림과 어떤 빌림이 겹친다고 말하는가.
2. (왜) `v.push(v.len())`는 컴파일되는데 `v[v.len() - 1] = x`는 E0502로 거부된다. 둘 다 "가변 빌림 안에서 불변 빌림"인데 무엇이 다른가 — 2단계 빌림(two-phase borrow)은 어디까지 적용되는가.
3. (경계) 같은 식에서 `self.slot(key)` 대신 필드를 직접 읽는 `self.slots[k]`를 쓰면 컴파일된다. 메서드 호출과 필드 읽기는 빌림 검사기에게 어떻게 다르게 보이는가 — 검사기는 메서드 본문을 보는가, 시그니처를 보는가.
4. (설계) 이 에러를 고치는 방법 두 가지 — "인덱스를 먼저 지역 변수로 계산"과 "필요한 필드만 받는 연관 함수로 쪼개기" — 는 각각 무엇을 바꾸는가. 어느 쪽이 언제 맞는가.
5. (경계) 인덱스를 먼저 계산하도록 옮긴 코드는 원래 코드와 같은 값을 쓰는가. 같은 줄 안에서 계산하던 값을 앞 문장으로 올렸을 때 의미가 달라질 수 있는 경우는 언제인가.
6. (연결) 컴파일러가 거부한 원래 코드는 실행했다면 아무 문제도 없었을 것이다. 그런데도 거부하는 것이 왜 맞는 설계인가 — `slot`이 `&self` 전체를 받는다는 시그니처가 약속하는 것은 무엇인가.
