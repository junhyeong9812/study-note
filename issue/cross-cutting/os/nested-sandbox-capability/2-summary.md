# issue/os/nested-sandbox-capability — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[바깥 샌드박스]  에이전트·CI 셸 — 네임스페이스·네트워크 조작 권한이 이미 깎여 있음
   │
   └─ spawn ─▶ [도구] --sandbox read-only
                 │
                 └─ 내부 샌드박스 생성 시도 (새 user namespace + 루프백 인터페이스 설정)
                        │
                        ▼
                  bwrap: loopback: Failed RTM_NEWADDR: Operation not permitted
                  (새 네트워크 네임스페이스의 루프백 주소 설정이 거부됨)
                        │
                        ├─ 변형 A: 도구 안의 셸 명령(파일 읽기) 전부 실패
                        │          → 도구는 "읽지 못했다"는 보고서를 쓰고 exit 0
                        │
                        └─ 변형 B: 보조 자식 프로세스가 멈춤 → 타임아웃 후 진행
                                   → 종료를 타임아웃까지 기다리면 호출마다 +수십 초 지연

교정(입력이 텍스트로 충분할 때):
   파일 경로를 주고 "읽어라" ─▶  필요한 내용을 표준입력에 인라인으로 담아 전달
                                 (내부 샌드박스는 그대로, 파일 읽기 자체가 불필요)
확인:
   종료 코드 + 필수 산출물 + 결과 본문의 검토 범위("읽지 못함/검증 불가")를 함께 본다
   (인라인은 변형 A용 — 변형 B 지연은 타임아웃 상한으로 대응)
```

## 핵심 문장

- 샌드박스는 **권한을 덜어낸 실행 문맥**이고, 자식은 그 문맥을 **상속**한다 — 안에서 또 격리를 만들 조작(네임스페이스·인터페이스 설정)이 허용된다는 보장이 없다.
- 도구의 `read-only`는 **쓰기** 제한이다. 읽기 범위를 강제하려면 접근 정책이 필요하고, 미러·지시는 작업 범위 안내다.
- 실패를 도구가 **내부**에서 처리하면 종료 코드가 0일 수 있다 — 완료 판정은 종료 코드·산출물·본문의 검토 범위를 함께 본다.
- 우회는 **덜 포기하는 순서**로: 입력 인라인 → (명시 승인 후) 내부 샌드박스 끄기 → 바깥 밖에서 실행.
