# issue/os/os-api-limits-and-semantics — OS API의 고정 한계와 미정의 동작 — 질문

## 질문
1. 유닉스 도메인 소켓(UDS)의 경로는 왜 길이 제한이 있는가. 리눅스에서 대략 몇 바이트이며, 긴 임시 디렉토리나 런타임 디렉토리 아래에 소켓을 만들면 어떤 증상이 나는가.
2. 예측: 소켓을 만들기 전에 "부모 디렉토리를 0700으로 조인다"는 코드가 있다. 사용자가 소켓 경로를 `/tmp/x.sock`으로 지정하면 무슨 일이 일어나는가. 왜 그런가.
3. 경계: 2번의 실패는 "막히는 쪽"(기동 실패)이다. 이것을 당장 고치지 않고 알려진 창으로 등재한 판단은 어떤 기준에서 정당한가. 반대로 "열리는 쪽" 실패였다면 어떻게 달라야 하는가.
4. 디렉토리를 `read_dir`로 순회하는 도중 같은 디렉토리에 파일을 새로 쓰면, 새 파일이 순회에 보이는가. POSIX는 이것을 어떻게 규정하는가.
5. 4번을 안전하게 바꾸는 가장 단순한 구조는 무엇인가. "모았다가 나중에 쓰기"가 왜 플랫폼 독립적으로 정확한가.
6. 연결: 세 사건 모두 "API가 문서상 전제를 갖고 있었는데 설계가 그 전제를 확인하지 않았다"로 묶인다. 새 OS API를 쓰기 전에 확인할 목록(고정 크기 버퍼·권한 소유권·순회 중 변경 등)을 스스로 만든다면 무엇을 넣겠는가.
