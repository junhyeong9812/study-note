# issue/cross-cutting/infra/shallow-clone-history-boundary — 얕은 clone 의 "부모 없음 · 조상 아님"은 "모름"이다 — 질문

## 질문
1. (왜) `fetch --depth=N` 으로 받은 저장소에서 이력의 가장 오래된 커밋을 `git show` 하면 그 커밋이 바꾼 줄이 아니라 파일 전체가 "추가"로 나온다. git 은 무엇을 기준으로 diff 를 만들길래 이런 답이 나오는가?
2. (예측) 배포마다 `fetch --depth=50` 을 다시 하는 서버에서, 직전 배포 커밋 A 의 객체는 로컬에 남아 있다. 새 배포 커밋 B 와의 관계를 `merge-base --is-ancestor A B` 로 물으면 언제 "조상 아님"이 나오는가? 그 답은 참인가?
3. (경계) "조상 아님"이 나왔을 때 그것을 믿어도 되는 경우와 믿으면 안 되는 경우를 무엇으로 가르는가? 확실한 되돌림(B 가 A 의 조상)은 왜 따로 보는가?
4. (왜) 위 두 경우가 오류가 아니라 200 과 그럴듯한 값(전부 추가된 diff · 빈 목록)으로 나간다는 점이 왜 더 위험한가?
5. (연결) "없음"과 "모름"을 같은 답으로 뭉개는 다른 사례 하나와 이 사례를 한 문장으로 묶어 보라. 응답에 세 번째 값(`unknown`)을 두면 소비자는 무엇을 해야 하는가?
6. (경계) 얕은 경계 목록을 판정에 쓰는데, 다른 프로세스(배포의 fetch)가 그 목록을 바꿀 수 있다면 이 판정은 무엇에 새로 기대게 되는가?
