# issue/cross-cutting/infra/deploy-artifact-scope — 배포 단위는 "실행에 필요한 것"으로 정의한다: 저장소 전체를 실으면 커밋된 데이터가 버전마다 복제된다 — 질문

## 질문
1. (왜) 측정할 커밋을 원격 서버의 버전별 폴더에 푸는 배포가 처음 수십 번은 문제없다가, 어느 날 서버 디스크를 100%로 채우고 배포가 실패했다. 디스크 사용량은 무엇과 무엇의 곱으로 커졌는가.
2. (경계) "저장소의 한 커밋 = 배포 단위"라고 정의하면 무엇이 함께 실리는가. 실행에 필요한 파일과 저장소에 커밋된 파일은 어떻게 다른가.
3. (연결) 버전마다 새 폴더에 풀고 완료 표식을 남기는 배포(불변 배포본)는 재시도·재현성에 유리하다. 그 장점이 왜 디스크 쪽에서는 대가가 되는가.
4. (예측) 결과 경로를 배포에서 제외해 한 번의 배포가 3.5GB에서 1.3MB로 줄었다. 그래도 남아 있는 증가 요인은 무엇인가.
5. (교정) 제외 목록(exclude)으로 배포 범위를 줄이는 것과 포함 목록(allowlist)으로 정의하는 것은 무엇이 다른가 — 각각 무엇을 놓칠 수 있는가.
6. (운영) 다른 서비스와 같이 쓰는 서버의 디스크를 비우려고 오래된 배포 폴더를 지울 때, 지우기 직전에 무엇을 다시 확인해야 하는가.
