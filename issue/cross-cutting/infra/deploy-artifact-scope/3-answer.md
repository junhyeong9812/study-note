# issue/cross-cutting/infra/deploy-artifact-scope — 정답

태그: `resource-bounding`

## 정답
<!-- 질문 1:1 대응 -->

1. **배포 수 × 페이로드.** 배포는 측정할 커밋마다 서버에 새 폴더(`base/<SHA>/`)를 만들어 그 커밋의 트리 전체를 풀었다.\
   저장소에는 이전 측정의 원시 결과가 GB 단위로 커밋돼 있었으므로 배포 한 번이 약 3~3.5GB였다.\
   버전 폴더 24개와 중간에 실패한 임시 폴더 1개가 쌓여 배포 루트가 53GB가 됐고, 98GB 디스크가 100%(여유 0)가 되자 다음 배포가 실패해 측정 회차가 비정상 종료됐다.\
   한 번의 배포는 늘 성공했기 때문에, 증가는 배포가 실패하는 순간에야 보였다.
   > **페이로드(payload)** — 배포 한 번이 실제로 옮기는 내용물. 배포 정의가 정하며, 실행에 필요한 것과 같다는 보장은 없다.

2. **저장소에 있는 것 전부.** "커밋 하나 = 배포 단위"는 재현성(무엇을 실행했는지 SHA로 특정)에는 좋은 정의지만, 저장소에 들어 있는 것을 **실행 여부와 무관하게** 전부 싣는다.\
   실행에 필요한 것은 앱 소스·실행 스크립트·설정이고, 측정 결과·문서·대용량 산출물은 서버에서 쓰이지 않는다.\
   저장소가 기록 보관소 역할도 겸하면(결과를 커밋해 남기는 실험 저장소) 페이로드는 시간이 갈수록 커진다 — 실행에 필요한 부분은 그대로인데도.

3. **불변성은 개수로 대가를 낸다.** 버전마다 새 폴더에 풀고 끝나면 완료 표식을 남기면, 재시도 때 "이미 배포됨"을 표식으로 판단할 수 있고 반쯤 풀린 트리를 배포됨으로 보지 않는다(임시 폴더에 푼 뒤 이름 변경).\
   대신 이전 버전을 덮어쓰지 않으므로 폴더가 배포 수만큼 남는다 — 페이로드가 크면 이 개수가 곧 디스크 사용량이다.

4. **개수와 실패 잔재.** 결과 경로를 제외하자 배포 한 번이 3.5GB에서 1.3MB로 줄었다(배포 후 폴더 1.8MB).\
   하지만 버전 폴더를 지우는 보존 정책은 없으므로 폴더 수에는 여전히 상한이 없다 — 위험이 줄었을 뿐 사라지지 않았다.\
   중간에 끊긴 배포의 임시 폴더도 같은 버전을 다시 배포하지 않으면 남는다(정리 대상 목록에 실제로 1개가 있었다).

5. **놓치는 방향이 반대다.** 제외 목록은 "알려진 큰 것"만 빼므로, 나중에 새 대용량 경로가 커밋되면 다시 실린다 — 이 사례는 결과 경로를 glob으로 제외했다.\
   포함 목록은 실행에 필요한 경로만 싣으므로 새 대용량 경로에 안전하지만, 실행에 필요한 새 파일을 목록에 넣지 않으면 서버에서 빠진다(이 누락은 기동·실행 오류로 드러난다).
   > **pathspec exclude** — `git archive <SHA> -- . ':(exclude,glob)<경로>/**'`처럼, 트리에서 특정 경로를 빼고 내보내는 git 경로 지정 문법.

6. **경로·목록·개수.** 이 사례는 사용자 승인("오래된 폴더 전부 삭제")을 받은 뒤, 지우기 직전에 대상 경로와 실제 목록을 다시 확인했고, 승인 때 말한 개수(23)와 실제 목록(버전 폴더 24 + 실패 임시 폴더 1)이 달라 그 차이를 알린 뒤 삭제했다 → 디스크 44%(여유 53GB).\
   공유 디스크의 대량 삭제는 되돌릴 수 없으므로, 승인 시점의 인식과 삭제 시점의 실제 상태가 같은지를 삭제 직전에 확인한다.

## 문제 구조 (추상화 코드)

### 변형 A — 배포 단위 = 저장소 전체 (커밋된 데이터가 함께 실림)
① 문제 코드
```bash
deploy() {                                            # 버전별 불변 폴더 + 완료 표식
  remote "test -f $BASE/$SHA/.deployed" && return 0
  git archive "$SHA" \
    | remote "mkdir -p $BASE/.tmp-$SHA && tar -x -C $BASE/.tmp-$SHA \
              && touch $BASE/.tmp-$SHA/.deployed && mv $BASE/.tmp-$SHA $BASE/$SHA"
}                                                     # 트리 전체 — 커밋된 결과(~3GB)까지
```
② 고친 코드
```bash
deploy() {
  remote "test -f $BASE/$SHA/.deployed" && return 0
  git archive "$SHA" -- . ':(exclude,glob)<결과 경로>/**' \
    | remote "...같은 풀기..."                         # 배포 1회 3.5GB → 1.3MB
}
# 작업 트리의 스크립트를 덮어 푸는 보조 배포 경로도 같은 경로를 제외(tar --exclude)
```
무엇이 깨졌나: 실행과 무관한 커밋 데이터가 배포마다 복제되어, 배포 수에 비례해 공유 디스크를 채웠다.

# ① 현재: 정리는 사람이 승인 후 일회 수행
