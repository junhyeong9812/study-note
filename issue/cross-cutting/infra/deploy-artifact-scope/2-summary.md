# issue/cross-cutting/infra/deploy-artifact-scope — 정리 (힌트)

## 전체 흐름

```
배포 1회 (버전별 불변 폴더)
  로컬 저장소 @SHA ── archive(전체 트리) ──▶ 서버 base/<SHA>/   + 완료 표식
                                              ├─ 앱 소스·스크립트       (~MB)
                                              └─ 커밋된 측정 원시 결과   (~3~3.5GB)  ← 실행에 불필요

누적
  디스크 사용 ≈ Σ 버전 폴더(배포 수 × 페이로드) + 실패한 임시 폴더
  버전 폴더 24개 + 임시 1개 → 배포 루트 53GB → 공유 디스크 98GB 100% (여유 0)
        ▼
  다음 배포 실패 → 측정 회차 비정상 종료 · 같은 디스크의 다른 서비스도 위험

고친 것
  ① 정리(일회): 승인 → 삭제 직전 경로·목록 재확인(승인 때 말한 개수와 다르면 고지) → 삭제 → 44%
  ② 재발 방지: archive(전체 트리 − 결과 경로) → 배포 1회 3.5GB → 1.3MB
  남은 것: 버전 폴더 개수에는 여전히 상한이 없다(보존 정책 없음 — 페이로드가 작아져 위험이 줄었을 뿐)
```

## 핵심 문장

- 배포 단위를 "저장소의 한 커밋 전체"로 정의하면, 저장소에 **커밋된 데이터**(측정 결과·대용량 산출물)가 실행과 무관하게 함께 실린다.
- 버전별 불변 폴더는 재시도·재현에 유리하지만 **배포 수 × 페이로드**로 디스크가 커진다 — 페이로드가 저장소와 함께 자라면 곱이 빨리 커진다.
- 고칠 곳은 두 축이다: **페이로드**(실행에 필요한 것만 — 제외 목록 또는 포함 목록)와 **개수**(보존 정책).
- 공유 서버 디스크 고갈은 자기 배포만이 아니라 같은 디스크를 쓰는 다른 서비스의 장애가 된다.
- 지우기 직전 경로·목록·개수를 다시 확인한다 — 승인 때 알던 상태와 지금 상태가 다를 수 있다.
