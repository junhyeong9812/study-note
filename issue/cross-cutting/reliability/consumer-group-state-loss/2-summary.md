# issue/reliability/consumer-group-state-loss — 정리 (힌트)

## 전체 흐름

```
생산자 ──XADD(길이 상한)──▶ [브로커: 스트림 · 소비자 그룹 · 미확인 목록]  ◀──읽기·확인── 소비자
                              └─ 이 상태는 브로커의 것이다. 소비자는 "있다고 기억"할 뿐

[사건 1] 브로커 재시작(디스크 저장 없음) → 스트림·그룹·미확인 목록이 함께 사라짐
   소비자 메모리: groupReady = true            (낡은 기억)
   다음 읽기:     "그룹 없음" 오류
   재시도 루프:   읽기만 다시 한다 → 같은 오류 → 같은 오류 → ...  (그룹을 만드는 경로를 다시 밟지 않음)
   고침:          어떤 실패든 groupReady = false → 다음 바퀴에 그룹 만들기(이미 있으면 무시)부터

[사건 2] 받았지만 확인하지 못한 항목이 길이 상한에 밀려남
   미확인 목록:   ID 는 남아 있다
   다시 읽기:     [ID, (필드 없음)]  ← 내용이 비어서 온다
   그대로 저장:   빈 행
   건너뛰기만:    영원히 미확인으로 남아 매 바퀴 다시 온다
   고침:          내용이 전부 없는 항목은 저장하지 않고 확인만, 잃은 건수를 경고로 남김

[이어지는 것]
   헬스의 "미확인 건수"도 그룹이 있어야 답한다 → 그룹이 없으면 다른 단계의 실패가 "브로커 불통"으로 가려진다
   → 바퀴 안에서 그룹 확인을 가장 먼저
```

## 핵심 문장
- 소비자 그룹의 상태는 **소비자가 만들었지만 브로커가 가진다** — 브로커의 재시작·길이 상한이 소비자에게 알리지 않고 지운다.
- "준비됨"을 한 번 확인하고 기억하는 것은 원격 상태의 **사본**을 쥐는 일이다 — 실패하면 사본을 버리고 다음 바퀴에 다시 확인한다.
- 재시도가 회복이 되려면 실패한 단계만이 아니라 **그 단계의 전제(그룹 만들기)**까지 다시 밟아야 한다.
- 미확인 목록은 항목의 **내용**이 아니라 **ID** 를 기억한다 — 내용이 밀려나면 ID 만 돌아온다.
- 내용을 잃은 항목은 저장하지 않되 **확인은 하고 잃은 건수를 남긴다** — 조용한 빈 행도, 영원한 미확인도 만들지 않는다.
