# issue/cross-cutting/data/denormalized-counter-drift — 정리 (힌트)

## 전체 흐름

```
원본: 보유 행 + 확정 행 ──(같은 사실)──  사본: 카운터 행 cnt  (CHECK cnt >= 0)
                                           ▲ 선점 +1 (조건부 upsert, 한도 판정)
                                           ▼ 만료 배치 −n (실제로 지운 행 수)

[만료 배치 — 트랜잭션 하나]
  BEGIN
   ├─ 만료된 보유 전체 조회 → 삭제
   ├─ 쌍마다 UPDATE cnt = cnt − n
   │     ├─ 행 없음        → 영향 0 → 명시적 check 실패 ─┐
   │     ├─ cnt < n        → 음수   → CHECK 위반 ─────────┤→ ROLLBACK (전 쌍 되돌림)
   │     └─ cnt ≠ 실제, ≥ n → 성공 (조용히 틀림)           │
  COMMIT                                                     │
                                                             ▼
  다음 틱: 같은 만료 보유를 다시 조회 → 같은 쌍 → 또 실패 → 사람이 고칠 때까지 매 틱
           = 모든 범위의 만료 정지 (보유가 풀리지 않음)

[조용한 갈래]
  cnt < 실제 → 한도 판정이 낮은 값을 봄 → 한도 넘게 보유 허용
  cnt > 실제 → 한도 판정이 높은 값을 봄 → 정당한 요청을 조용히 거절

[드러나는 것 vs 숨는 것]
  배치 실패(시끄러움)  ⊂  전체 어긋남
  나머지 = 원본 재계산과의 대조(정합 점검)로만 보인다

[예방 — 전환 시]
  쓰기 주체 정지(cutover) → 백필(잠금 + 원본에서 재계산해 덮어쓰기, 멱등) → 직후 불일치 0 확인
[남은 것 — 이 사례는 후속 설계로 넘김]
  어긋났을 때의 탐지·복구·격리 (지금은 없음)
```

## 핵심 문장

- 카운터는 원본 행 수의 **사본**이다 — 두는 순간 "모든 쓰기 경로가 사본도 갱신한다"는 의무가 생기고, 그 의무를 지키지 않는 경로 하나가 어긋남을 만든다.
- 어긋남은 **일부만 오류로 드러난다** — 행 없음·음수는 시끄럽게 실패하지만, 지운 수 이상인 어긋남은 감소가 성공해 조용히 남는다.
- 넓은 트랜잭션의 배치에서 시끄러운 어긋남 하나는 **다음 틱에 다시 잡혀** 매 틱 전체를 롤백한다 — 한 쌍의 결함이 전역 정지가 된다.
- 조용한 어긋남은 한도 판정을 틀리게 한다 — 과소면 초과 허용, 과대면 부당 거절.
- 그래서 "배치가 돈다"는 정합의 증거가 아니다 — 원본에서 다시 센 값과의 **별도 대조**가 있어야 보인다.
- 카운터 정의는 **감소가 일어나는 시점**이 정한다 — 삭제 때 내린다면 만료됐지만 안 지운 행도 카운터에 남아 있어야 한다.
- 백필 안의 잠금은 **실행 중의** 쓰기만 막는다 — 백필 뒤에 옛 버전이 쓰는 것은 cutover(쓰기 주체 정지)로만 막는다.
