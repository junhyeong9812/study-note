# issue/cross-cutting/data/line-terminator-not-separator — 정리 (힌트)

## 전체 흐름

```
텍스트        "l1\nl2\n"                  ← 줄마다 \n 으로 끝난다 (종결자)
split("\n")   ["l1", "l2", ""]            ← \n 을 사이에 둔 것으로 본다 (구분자) → 끝에 빈 조각
wc -l         2                           ← \n 의 개수

[실패] 소비처 셋이 각자 split
   상한 판정    lines.length > 500        → 정확히 500줄이면 501 → "더 있음" 오표시
   전체 줄 수   lines.length              → 실제보다 1 많음
   화면 표      lines.map(row)            → 끝에 빈 행
   테스트       가짜 서버의 patch 가 \n 으로 끝나지 않음 → 결함이 안 보임

[교정] 줄 나누기 규칙 한 곳
   splitLines(text) = (text.endsWith("\n") ? text.slice(0, -1) : text).split("\n")
   상한 판정 · 전체 줄 수 · 화면 표 → 모두 splitLines
   자른 patch = 앞 500줄.join("\n") + "\n"   ← 결과도 같은 꼴(종결자)로
   가짜 서버 → 실제 응답과 같은 꼴(\n 으로 끝남)
```

## 핵심 문장
- 텍스트 파일·도구 출력의 줄바꿈은 줄의 **끝**(종결자)이다 — `split` 은 그것을 **사이**(구분자)로 다뤄 끝에 빈 조각을 하나 더 만든다.
- 줄 수가 하나 틀리면 상한 경계(정확히 N줄)에서 "더 있음" 같은 거짓 표식이 나온다.
- 줄 나누기 규칙을 한 함수로 모으고 모든 소비처가 쓴다 — 소비처마다 고치면 하나는 남는다.
- 테스트 더블의 데이터는 실제 응답과 같은 꼴이어야 한다 — 끝 줄바꿈 하나가 다르면 결함 전체가 사라진다.
