# issue/cross-cutting/data/line-terminator-not-separator — 줄바꿈은 구분자가 아니라 종결자다: `split("\n")` 의 끝 빈 조각 — 질문

## 질문
1. (예측) `"a\nb\n"` 을 `split("\n")` 하면 몇 조각이 나오는가? 같은 텍스트를 `wc -l` 은 몇 줄로 세는가? 둘이 다른 까닭을 "구분자"와 "종결자"로 설명하라.
2. (예측) patch 를 500줄까지만 보이고 넘으면 "더 있음"을 표시한다. 정확히 500줄이고 `\n` 으로 끝나는 patch 에 `split("\n").length > 500` 을 쓰면 화면은 무엇을 보이는가?
3. (왜) 이 결함은 테스트가 수백 개 있는데도 통과했다. 테스트용 가짜 서버가 준 patch 는 어떤 꼴이었고, 실제 응답은 어떤 꼴이었는가?
4. (경계) "끝의 줄바꿈 하나는 줄이 아니다"로 고칠 때, 줄바꿈이 없는 마지막 줄(`"a\nb"`)과 빈 문자열은 각각 몇 줄이어야 하는가? 줄바꿈이 둘(`"a\n\n"`)이면?
5. (연결) 상한 판정 · 전체 줄 수 · 화면 표가 각자 `split` 을 부르던 것을 한 함수로 모은 까닭은 무엇인가? 자른 patch 를 다시 이어 붙일 때 끝에 줄바꿈을 붙이는 까닭은?
6. (연결) 같은 시스템의 다른 쪽(Go)은 `SplitAfter` 로 나누고 빈 조각을 건너뛰었다. 이 방식은 왜 같은 결함을 피하는가?
