# issue/cross-cutting/data/line-terminator-not-separator — 정답

태그: `single-source-of-truth`

## 정답
<!-- 질문 1:1 대응 -->

1. **`split` 은 3조각(`"a"`, `"b"`, `""`), `wc -l` 은 2줄이다.**\
   `split("\n")` 은 `\n` 을 두 값 **사이**에 놓인 구분자로 본다. 마지막 `\n` 뒤에도 값이 하나 있다고 보니 빈 조각이 생긴다.\
   POSIX 의 텍스트 줄은 `\n` 으로 **끝나는** 문자열이다 — `\n` 은 종결자다. `wc -l` 은 `\n` 의 개수를 센다.\
   git 의 patch 출력도 줄마다 `\n` 으로 끝난다. 이 사례에서 실제 응답의 patch 넷이 모두 `\n` 으로 끝났다.
   > **종결자(terminator) / 구분자(separator)** — 종결자는 항목마다 뒤에 붙고(항목 N개 = 기호 N개), 구분자는 항목 사이에만 놓인다(항목 N개 = 기호 N−1개).

2. **500줄짜리 patch 에 "더 있음"이 붙는다.**\
   끝의 빈 조각 때문에 길이가 501 이 되어 상한을 넘었다고 판정한다. 전체 줄 수도 하나 많게 보인다.\
   실제 사건에서는 37줄을 추가한 파일의 `split` 결과가 39 였고, 500줄 patch 에 "더 있음"이 표시됐다.

3. **가짜 서버의 patch 는 `\n` 으로 끝나지 않았고, 실제 응답은 끝났다.**\
   가짜 데이터에서는 `split` 의 끝 빈 조각이 생기지 않으니 줄 수가 맞았다. 테스트는 결함 없는 입력만 본 셈이다.\
   결함은 리뷰에서 실제 서버(배포 시스템의 중계·조회 서버를 실제 이미지로 띄운 미리보기)의 응답을 보고서야 재현됐다.

4. **`"a\nb"` 는 2줄, `""` 는 1조각, `"a\n\n"` 은 2줄(두 번째는 빈 줄)이다.**\
   규칙은 "끝의 줄바꿈 **하나**만 줄로 세지 않는다"이다. 끝 줄바꿈이 없는 텍스트는 그대로 나누고, 둘이면 하나만 떼므로 빈 줄 하나는 진짜 줄로 남는다.\
   빈 문자열은 `split` 이 빈 조각 1개를 준다 — 이 사례에서는 patch 가 없을 때(`null`)를 따로 처리하므로 빈 문자열의 줄 수는 쟁점이 아니었다(기록 없음).

5. **소비처마다 규칙이 다르면 한 화면 안에서 숫자가 서로 어긋나기 때문이다.**\
   상한 판정이 501, 화면 표가 500 행이면 "더 있음"이 붙었는데 행은 다 보이는 모순이 생긴다. 한 함수로 모으면 세 값이 함께 맞거나 함께 틀린다.\
   자른 patch 끝에 `\n` 을 붙이는 것은 결과를 입력과 같은 꼴(종결자)로 유지하기 위해서다 — 그래야 다음 소비처가 같은 함수로 다시 나눠도 줄 수가 맞는다.\
   고친 뒤 미리보기에서 실제 응답의 README diff 13줄이 화면 표 13행과 같았다.
   > **단일 출처(single source of truth)** — 같은 사실(여기서는 "줄이란 무엇인가")을 한 곳에서만 정하고 나머지는 그것을 가져다 쓰는 것.

6. **`SplitAfter` 는 각 조각에 종결자를 붙인 채 나누므로, 끝의 빈 조각만 건너뛰면 조각 수 = 줄 수가 된다.**\
   `SplitAfter("a\nb\n", "\n")` 는 `"a\n"`, `"b\n"`, `""` 를 준다. 마지막 빈 조각은 "종결자 뒤에 아무것도 없음"이라 건너뛰면 된다.\
   종결자가 조각 안에 남아 있으니, 마지막 줄에 줄바꿈이 있었는지도 잃지 않고 다시 이어 붙일 수 있다.

## 문제 구조 (추상화 코드)

### 변형 A — 종결자로 끝나는 텍스트를 구분자로 나눈다
① 문제 코드
```ts
const lines = patch.split("\n");                       // "…\n" → 끝에 "" 하나 더
const cut = lines.length > LINE_LIMIT;                 // 정확히 LINE_LIMIT 줄이면 거짓 "더 있음"
return {
  patch: cut ? lines.slice(0, LINE_LIMIT).join("\n") : patch,
  truncated: cut,
  totalLines: lines.length,                            // 실제보다 1 많음
};
// 화면 쪽 표는 또 다른 곳에서 patch.split("\n") — 규칙이 소비처마다 있다
```
② 고친 코드
```ts
/** 줄 — \n 으로 나누되 끝의 줄바꿈 하나는 줄로 세지 않는다. 상한 판정·전체 줄 수·화면 표가 함께 쓴다. */
export function splitLines(text: string): string[] {
  return (text.endsWith("\n") ? text.slice(0, -1) : text).split("\n");
}

const lines = splitLines(patch);
const cut = lines.length > LINE_LIMIT;
return {
  patch: cut ? `${lines.slice(0, LINE_LIMIT).join("\n")}\n` : patch,   // 자른 결과도 종결자로 끝낸다
  truncated: cut,
  totalLines: lines.length,
};
```
깨진 것: 텍스트의 줄바꿈이 종결자라는 꼴을 소비처마다 따로, 그리고 틀리게 해석했다.

### 변형 B — 테스트 더블이 실제 꼴과 다르다
```ts
// 문제: 가짜 서버의 patch — 끝 줄바꿈 없음
fakeUpstream.patch = "@@ -0,0 +1,2 @@\n+a\n+b";
// 고침: 실제 응답과 같은 꼴
fakeUpstream.patch = "@@ -0,0 +1,2 @@\n+a\n+b\n";
```
깨진 것: 테스트 데이터가 결함을 일으키는 입력을 표현하지 못했다([green-masking](../../testing/green-masking/) 변형 D 와 같은 구조).
