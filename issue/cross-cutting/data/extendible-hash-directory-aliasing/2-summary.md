# issue/cross-cutting/data/extendible-hash-directory-aliasing — 정리 (힌트)

## 전체 흐름

```text
[구조 — 칸 → 버킷은 다대일]
  전역 깊이 g = 2  → 칸 4개 (해시 하위 2비트로 고름)
   칸 00 ─┐
   칸 10 ─┴─▶ 버킷 A (지역 깊이 1, 끝 1비트 = 0)   ← 칸 2^(g-d) = 2개
   칸 01 ──▶ 버킷 B (지역 깊이 2, 끝 2비트 = 01)
   칸 11 ──▶ 버킷 C (지역 깊이 2, 끝 2비트 = 11)
  지역 깊이 d = "이 버킷이 실제로 구분에 쓰는 비트 수" = 별칭 칸 수를 정함

[분할 — d가 진행을 만든다]
  넘침 → d == g 이면 디렉터리 두 배(g += 1)
       → bit = 1 << d, bit가 1인 키만 새 버킷으로
       → old.d = new.d = d + 1             ← 이 줄이 진행 그 자체
       → 끝 d+1비트 = suffix|bit 인 칸(시작 suffix|bit, 간격 2^(d+1))만 새 버킷으로

[d를 안 올리면]
  SPLIT d=0 g=0 → DOUBLE (g=1)
  SPLIT d=0 g=1 → d≠g라 두 배 없음 → bit = 1<<0 (같은 비트)
                → 그 비트가 1인 키는 이미 나감 → 옮길 키 0개, 빈 새 버킷만 할당
                → 여전히 넘침 → SPLIT d=0 g=1 → ... (계측: 10초에 약 20만 회)

[훑기 — 칸을 세면 버킷을 중복해서 센다]
  칸 순회: A, B, A, C  → A의 키가 두 번
  정렬해도 중복은 남음 → 결과가 정답과 다름 (비용이 아니라 정확성)
  고침: 쓰는 칸(앞 2^g개)만 → 버킷 id 정렬 + 중복 제거 → 버킷마다 한 번
        (쓰지 않는 칸 = 0 = 메타 페이지 번호 → 버킷으로 오독)
```

## 핵심 문장

- 확장 해싱 디렉터리는 칸 → 버킷이 **다대일**이고, 그 배수(`2^(g-d)`)와 위치(끝 d비트가 같은 칸들)를 **지역 깊이**가 기술한다.
- 분할의 진행은 지역 깊이 증가가 만든다 — 빠지면 같은 비트로 무한히 나누며 빈 버킷만 쌓인다(두 배는 한 번뿐).
- 칸을 훑는 것은 버킷을 훑는 것이 아니다 — **버킷 단위로 중복을 제거**해야 결과가 맞는다. 정렬은 순서만 맞출 뿐 중복을 지우지 않는다.
- 고정 크기 페이지 안의 논리 길이(`2^g`)를 넘어 읽으면 빈 칸의 0이 유효한 페이지 번호로 해석된다.
- 무한 루프의 원인은 예측보다 **계측**으로 확정한다 — "매번 두 배"라는 직관은 틀렸다.
