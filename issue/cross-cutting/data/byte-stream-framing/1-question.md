# issue/data/byte-stream-framing — 읽기 경계는 줄·문자·이스케이프 경계와 무관하다 — 질문

## 질문
1. 다른 프로세스가 쓰고 있는 JSONL 파일을 주기적으로 tail하면, 한 번의 read가 끝나는 위치는 레코드 경계와 어떤 관계인가. 조각을 그대로 파싱하면 무엇을 잃는가.
2. 완성된 줄(`\n`까지)만 디코드하면 멀티바이트 UTF-8 문자 경계도 자동으로 안전해진다 — 왜 그런가(`0x0A`와 continuation 바이트의 관계).
3. 예측: 터미널 출력(PTY)을 청크마다 UTF-8 text로 디코드해 웹소켓 text 프레임으로 보낸다. 한글이 청크 경계에 걸리면? 디코딩은 누가 해야 하는가.
4. 파일 끝 N KB 창을 읽을 때 "첫 줄은 항상 잘렸으니 버린다"는 규칙은 언제 틀리는가. tail 대상 파일이 truncate·재생성되면 무엇을 감지해 리셋해야 하는가.
5. 경계: 메모리 상한을 넘은 출력 버퍼를 "중간"에서 드롭하면 터미널에서 무엇이 깨지는가. 앞에서부터 드롭하는 것은 왜 비교적 안전한가. 절단본을 디스크 스냅샷에 저장하면 무엇이 달라지는가.
6. 동기 `reset()`과 비동기 write 큐를 섞으면 왜 순서가 뒤바뀌는가. 초기화 명령을 어떻게 보내야 FIFO가 지켜지는가.
