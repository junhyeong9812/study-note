# issue/distributed/active-instance-from-routing-truth — 정리 (힌트)

## 전체 흐름

```
무중단 교체: 구(A)와 새(B)가 잠시 함께 떠 있다
   요청       ──▶ 프록시 ──▶ 한쪽만            (겹쳐도 안전)
   주기 작업  ──▶ A 도 돌고 B 도 돈다           (겹치면 두 번 한다)

[처음 설계] 소유권 = "교체 신호를 받았는가"
   배포기 ──전환──▶ 프록시(B)      배포기 ──신호──▶ A: 주기 작업 중지
   실패 지점: 신호는 갔는데 A 정지가 보류(프록시가 여전히 A 로 보냄)
              A: 주기 작업 꺼짐 + 헬스 200 "정상"   B: 전환 전이라 원래 안 함(또는 없음)
              → 아무도 하지 않는데 밖에서는 정상으로 보인다
   실패 지점: B 는 뜨자마자 주기 작업 시작 → 전환 전부터 A 와 함께 두 번

[교정] 소유권 = "프록시가 지금 누구에게 보내는가" (매 주기 확인)
   A, B ──GET──▶ 프록시 ──응답 헤더: 지금 보내는 자리──▶ 내 자리면 활성, 아니면 대기
   교체 신호     = 곧바로 대기로 내리는 힌트. 다음 확인이 다시 판정한다
   프록시 불통   = 직전 판단 유지 / 한 번도 판정 못 한 채 유예 시간이 지나면 스스로 활성

[이어받기] 대기 → 활성이 되는 그 주기에
   저장소에서 "지금 장애 중" 상태를 다시 읽는다        (뜰 때 읽은 것은 낡았다)
   내려가는 쪽: 메모리의 재시도 대상을 내려놓는다
   맡는 쪽:     기록에서 미발송 건을 되살린다(기록 후 일정 시간이 지난 것만)

[밖에서 보는 눈]
   대기 인스턴스의 헬스 = 200 + "standby"   (배포기는 이 인스턴스가 떴는지 봐야 한다)
   밖의 감시자는 "standby" 가 계속 보이면 실패로 센다  (아무도 맡지 않았다는 뜻)
```

## 핵심 문장
- 겹쳐 뜨는 교체에서 요청은 프록시가 한쪽으로 모으지만, **주기 작업은 인스턴스마다 스스로 돈다** — 소유권을 따로 정하지 않으면 두 번 하거나 아무도 하지 않는다.
- 소유권의 기준은 "누가 신호를 받았나"가 아니라 **"트래픽이 실제로 어디로 가나"** 다. 신호는 보내는 쪽의 의도이고, 프록시의 응답은 지금의 사실이다.
- 신호는 버리지 않고 **힌트**로 쓴다 — 곧바로 내려놓게 해 겹침을 줄이되, 사실 확인이 언제든 뒤집을 수 있어야 한다.
- 사실을 확인할 수 없을 때의 규칙은 **어느 쪽 실패를 받아들일지**의 선택이다 — 감시·알림이면 "두 번 하기"가 "아무도 안 하기"보다 낫다.
- 이어받는 상태는 **맡는 순간에** 공유 저장소에서 읽는다. 메모리에만 있는 상태(재시도 대상·중복 억제 창)는 교체에서 사라지거나 둘로 갈라진다.
- "대기"는 프로세스로서는 정상이지만 역할로서는 부재다 — 헬스 응답에 **역할을 드러내고**, 밖의 감시자가 그 값을 본다.
