# issue/kotlin/spring/default-argument-evaluated-on-proxy — Kotlin 기본 인자는 호출 쪽에서 계산된다: 프록시를 통해 부르면 프록시의 빈 필드를 읽는다 — 질문

## 질문
1. (왜) 트랜잭션 어노테이션이 붙은 빈의 메서드에 `loader: (Long) -> Item? = repository::findById`처럼 **필드를 쓰는 기본 인자**를 줬더니, 그 인자를 생략하고 부르는 경로에서 NPE가 났다. Kotlin 기본 인자 식은 어디에서, 어떤 인스턴스를 수신자로 계산되는가.
2. (연결) 다른 빈이 주입받아 들고 있는 참조는 대상 객체가 아니라 프록시다. 프록시 인스턴스의 필드는 왜 비어 있는가 — 의존성이 주입된 것은 어느 객체인가.
3. (예측) 같은 메서드에 `beforeMutation: (Item) -> Unit = {}` 같은 기본 인자도 있었다. 이 인자는 프록시를 통해 생략해도 문제가 없었다. 두 기본 인자의 차이는 무엇인가.
4. (경계) 프록시 없이 대상 객체를 직접 만들어 부르는 단위 테스트라면 이 결함이 드러나는가. 그렇다면 어떤 종류의 테스트가 이것을 잡는가.
5. (교정) 기본값을 `null`로 두고 본문에서 `loader ?: repository::findById`로 고르면 왜 안전한가. 본문은 어느 인스턴스 위에서 실행되는가.
6. (발견) 이 결함은 "새 인자를 생략한 기본 경로는 기존 동작과 같다"는 가정을 착수 직후 기존 테스트로 실증하다 잡혔다. 그 실증을 미루고 그 위에 구현을 쌓았다면 무엇이 어려워졌겠는가.
