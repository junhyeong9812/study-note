# issue/shell/script-modified-while-running — 실행 중인 스크립트를 고치면 실행이 깨진다: 동결 사본으로 실행 — 질문

## 질문
1. (왜) bash는 스크립트 파일을 실행 전에 한 번에 다 읽는가, 실행하면서 읽어 나가는가? 수 시간 도는 스크립트를 실행 도중 편집기로 고쳐 저장하면, 그다음 명령은 파일의 어디서부터 읽히는가.
2. (예측) 긴 `for` 루프가 도는 동안 루프 **뒤**의 정리 코드(원격 컨테이너 내리기)를 고쳤다. 루프 안의 명령은 왜 멀쩡히 끝까지 돌고, 루프가 끝난 순간에 무슨 일이 일어나는가. 정리 코드가 실행되지 않으면 무엇이 남는가.
3. (경계) 같은 "수정"이라도 파일을 제자리에서 덮어쓰는 경우와 새 파일로 쓴 뒤 이름을 바꿔(rename) 교체하는 경우, 실행 중인 bash가 보는 내용은 어떻게 다른가. 왜 이 차이 때문에 "고쳐도 괜찮았던 적이 있다"는 경험이 안전의 근거가 못 되는가.
4. (방법) 시작할 때 스크립트 디렉터리를 임시 위치로 복사해 그 사본을 `exec`하는 "동결"을 설계하라. 무한 재복사를 어떻게 막고, 결과 파일은 어디에 쓰게 하며, 끝난 뒤 임시 사본을 지울 때 무엇을 확인해야 작업 트리를 지우는 사고를 막는가.
5. (경계) 진입 스크립트 하나만 동결했더니 같은 사고가 다시 났다. 동결 범위에서 빠지기 쉬운 것 두 가지(직접 실행하는 하위 도구, 스크립트가 읽는 시나리오·데이터 파일)는 각각 어떻게 막는가.
6. (연결) 동결과 짝을 이루는 "실행하는 코드 = 기록되는 커밋" 검사를 상위 실행기와 하위 실행기 양쪽에 두었다. 리뷰에서 "실행 중 작업 트리를 고치면 남은 조건이 전부 즉시 실패하고 상위 실행기는 done으로 끝난다"는 구조가 드러났다. 어떤 두 결함이 겹친 것이며, 각각 어떻게 고치는가.
