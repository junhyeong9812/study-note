# issue/shell/script-modified-while-running — 정리 (힌트)

## 전체 흐름

```
bash runner.sh  (파일을 열어 둔 채, 명령 단위로 읽고 → 실행 → 다음 명령을 "현재 바이트 위치"부터 읽음)

  파일 (실행 시작 시점)                    파일 (실행 도중 제자리 덮어쓰기 후)
  ┌──────────────────────────┐            ┌──────────────────────────┐
  │ setup                    │            │ setup                    │
  │ for c in ...; do         │ ◀ 루프 전체를 │ for c in ...; do         │
  │   run_one "$c"           │   파싱해 메모리│   run_one "$c" --opt     │  ← (예시) 앞쪽 줄이 길어짐
  │ done                     │   에서 실행   │ done                     │
  │ cleanup_remote  ◀── 오프셋 N ──────────▶ │ ...p_remote  ◀── 같은 N = 줄 중간
  └──────────────────────────┘            └──────────────────────────┘
                                                   │
                                    루프가 끝나면 N부터 읽음 → 문법 오류(exit 2)
                                    → cleanup 미실행 → 원격 컨테이너 잔존

실패 지점
  ① 실행 중 원본 편집            루프 뒤 줄을 어긋난 오프셋에서 읽음 → 문법 오류·엉뚱한 명령
  ② 동결 범위 누락               진입점만 동결, 하위 도구를 직접 실행하면 원본에서 돎 → 재발
  ③ 상·하위 이중 검사 + 실패 무시  실행 중 편집 → 남은 조건 전부 즉시 거부, 상위는 "done"

교정
  시작 시 동결:  scripts/ → mktemp 사본 → exec 사본 (환경변수로 재복사 방지, 결과 위치는 원래 경로로 전달)
  입력도 동결:  시나리오는 작업 트리가 아니라 기록된 커밋에서 꺼냄 (git archive <SHA>)
  실행 코드 = 기록 커밋: 작업 트리(추적·미추적)가 SHA와 다르면 시작 거부 — 검사는 최상위 한 번
  상위는 하위 비정상 종료에 중단(ABORT) — 조용히 다음으로 넘어가지 않음
  정리: 임시 사본은 mktemp 경로 패턴일 때만 삭제
  운영 규칙: 실행 중에는 그 디렉터리를 편집하지 않는다
```

## 핵심 문장

- bash는 스크립트를 **실행하면서 읽는다** — 실행 중 파일을 제자리에서 고치면 다음 명령은 어긋난 바이트 위치부터 읽힌다.
- 복합 명령(루프·if·함수 정의)은 통째로 파싱된 뒤 실행된다 — 그래서 사고는 루프 안이 아니라 **루프가 끝난 뒤**(정리 코드)에서 난다.
- 해결은 "조심해서 고치기"가 아니라 **동결 사본을 실행**하는 것이다 — 원본은 자유롭게 고쳐도 실행은 영향을 받지 않는다.
- 동결은 **모든 진입점과 입력 파일**에 걸어야 한다 — 하나라도 원본을 직접 읽으면 같은 사고가 재발한다.
- "실행한 코드 = 기록한 커밋"은 최상위에서 한 번 확인하고, 하위 실패는 상위를 멈춰야 한다 — 아니면 실패가 "done"으로 위장된다.
