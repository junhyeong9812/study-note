# issue/shell/argument-size-limit — 정리 (힌트)

## 전체 흐름

```text
[문제 — 데이터를 인수로]
  echo ok > status                                   ← 상태가 먼저 "끝남"
  jq -n --argjson pre "$(cat pre.json)" ... > meta.json
        │                       │                  │
        │                       │                  └─ 셸이 리다이렉트를 먼저 연다 → meta.json 0바이트 생성
        │                       └─ 명령 치환 결과 약 190KB = 인수 문자열 하나
        ▼
  execve(jq, argv)  ── 인수 하나 > 128KB(MAX_ARG_STRLEN) ──▶ E2BIG "인수 명단이 너무 김"
        │                                                    jq는 시작조차 못 함
        ▼
  회차 결과: status = ok · meta.json = 빈 파일   ← 무음 (9회차가 이렇게 남음)
  집계: 메타에서 읽는 칸(조건 표의 일부 행·비율 칸)이 비어 있음 — 측정 데이터 자체는 유효

[같은 구조 — 페이지 이어 붙이기]
  page=$(query) && jq --argjson p "$page" '. + $p' acc > acc.n && mv acc.n acc
        └─ 약 700행부터 인수 한도 초과 → && 사슬이 끊겨 그 페이지만 조용히 빠짐

[교정]
  데이터는 파일로:   jq --slurpfile pre pre.json '... $pre[0] ...'     (파일 내용은 argv를 거치지 않음)
  없음·깨짐:         유효 JSON이면 그 경로, 아니면 "null" 한 줄 임시 파일 경로
  쓰기:              > meta.json.tmp  →  jq -e '검증' meta.json.tmp  →  mv → meta.json
  실패:              status = meta-write-failed (재측정 대상) + 오류 로그 한 줄
  순서:              meta 먼저, status 마지막 (중간에 끊기면 status 없음 → 이어하기가 다시 잰다)
  감사:              인수로 데이터를 넘기는 자리 전수 → 페이지 루프도 파일로 + 실패 시 비0 반환
```

## 핵심 문장

- 명령행 인수에는 커널 상한이 있다 — 리눅스는 인수 문자열 **하나**를 128KB(`MAX_ARG_STRLEN`)로, 인수+환경 **전체**를 `ARG_MAX`로 막는다.
- 상한 초과는 실행할 프로그램이 아니라 `execve`가 거부한다 — 프로그램은 시작조차 못 하고, 오류 메시지는 셸이 찍는다.
- 리다이렉트(`> out`)는 명령 실행 전에 셸이 연다 — 명령이 실행되지 못해도 **빈 출력 파일**은 생긴다.
- 상태("끝남")를 산출물보다 먼저 쓰면 산출물 실패가 성공으로 위장된다 — 상태는 산출물을 검증한 **뒤**에 쓴다.
- 입력에 비례해 자라는 데이터는 인수가 아니라 **파일·표준 입력**으로 넘긴다(`--slurpfile`·`--rawfile`·파이프).
- 한 곳에서 찾았으면 같은 모양(인수로 데이터 운반)을 전수 감사한다 — 작은 입력에서는 모두 정상이라 테스트가 잡지 못한다.
