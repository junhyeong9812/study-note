# issue/shell/closed-pipe-sigpipe — 정리 (힌트)

## 전체 흐름

```
스크립트 ──printf──▶ stdout = 파이프 ──▶ 읽는 쪽 (이미 끝남)
                         │
                         ├─ 기본 동작 (SIGPIPE 를 처리하지 않음)
                         │    커널: write(2) 대신 SIGPIPE 를 보낸다 → 쓰던 프로세스가 죽는다
                         │    종료 코드 128 + 13 = 141 · 다음 줄 실행 안 됨 · "|| 처리" 도 안 돈다
                         │
                         └─ trap '' PIPE (무시)
                              write(2) = -1, EPIPE → printf 가 rc 1 을 돌려준다
                              "|| 처리" 가 돈다 (되돌리기·경고 rc 구분이 의도대로)

[실패 1] 출력 실패를 rc 로 처리하는 코드
   ( 기록 ; printf "$notice" && exit 0 ; 되돌리기 ; exit 20 )  ── SIGPIPE ──▶ 서브셸 rc 141
   → 되돌리기 건너뜀 · 바깥 case 의 "그 밖" 분기 → 경고가 원인을 "기록 실패"라고 잘못 말한다
   교정: 그 서브셸 안에만 trap '' PIPE

[실패 2] 실패를 알리는 경고가 죽음을 만든다
   stdout 끊김 → 출력 실패 → echo "경고" >&2 ── stderr 도 끊김 ──▶ SIGPIPE → 스크립트 exit 141
   계약 "실패해도 통과(exit 0)" 가 경고 한 줄 때문에 깨진다
   교정: ( trap '' PIPE; echo "경고" >&2 ) || true      — 경고마다 서브셸

[방어선 판별] 변형 실험
   감싸기 전체 제거          → 사례 빨강 (exit 141)
   경고를 2>/dev/null 로 버림 → 사례 18개 빨강 (정상 실패 경로의 경고 한 줄이 사라짐)
   trap 한 줄만 제거         → 초록   ← 서브셸이 대신 죽고 "|| true" 가 rc 를 삼킨다
```

## 핵심 문장
- 닫힌 파이프에 쓰면 쓰기 명령이 실패하는 것이 아니라 **쓰던 프로세스가 신호로 죽는다** — `|| 처리` 로 쓴 실패 처리는 돌 기회가 없다.
- `trap '' PIPE` 는 신호를 **쓰기 실패(EPIPE)로 바꿔** 돌려준다 — 실패를 종료 코드로 다루는 코드가 비로소 의도대로 돈다.
- "실패를 알리는 경고"도 쓰기다 — stderr 까지 끊기면 경고가 새 실패를 만든다. 실패 경로의 출력도 실패할 수 있다고 보고 감싼다.
- 신호를 받아 죽을 프로세스를 따로 두면(서브셸) 바깥 스크립트는 살아남는다 — `( … ) || true` 가 실제 방어선이고, 그 안의 `trap` 은 테스트로 구별되지 않는 보조였다.
- 무시 상태는 자식 명령에도 이어진다 — `trap '' PIPE` 는 필요한 서브셸 안에만 건다.
- 경고를 버려서 죽음을 막지 않는다 — stderr 가 살아 있는 정상 실패 경로의 경고 한 줄은 그대로 나가야 한다.
