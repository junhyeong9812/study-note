# issue/shell/closed-pipe-sigpipe — 닫힌 파이프에 쓰면 스크립트가 신호로 죽는다: 경고를 쓰다 죽는 스크립트 — 질문

## 질문
1. (예측) 읽는 쪽이 이미 끝난 파이프로 bash 스크립트가 `printf '%s\n' "$message" || handle_failure` 를 실행했다. `printf` 는 실패(비0)를 돌려주고 `handle_failure` 가 도는가? 스크립트의 종료 코드는 무엇인가?
2. (왜) 같은 줄 앞에 `trap '' PIPE` 를 걸면 무엇이 달라지는가? 그때 쓰기 실패는 어떤 모양으로 스크립트에 돌아오는가?
3. (예측) "출력이 실패하면 방금 쓴 기록을 되돌리고, 실패 원인을 종료 코드로 구분해 경고한다"는 서브셸이 닫힌 파이프를 만났다. 되돌리기 줄은 실행되는가? 바깥의 경고는 원인을 무엇이라고 말하는가?
4. (경계) "알림에 실패해도 스크립트는 통과(exit 0)한다"가 계약인 스크립트에서 stdout 과 stderr 가 **함께** 끊겼다. 실패를 알리려고 쓰는 `echo "경고: …" >&2` 는 무엇을 만드는가?
5. (왜) 경고를 `( trap '' PIPE; echo "경고: …" >&2 ) || true` 로 감쌌다. 변형 실험에서 `trap` 한 줄만 빼도 테스트가 초록이었다. 실제로 종료를 막는 것은 무엇이고, `trap` 은 어떤 역할로 남는가?
6. (경계) 경고를 `2>/dev/null` 로 버리면 141 은 사라진다. 이 방법을 선택하지 않은 까닭은 무엇이고, `trap '' PIPE` 를 스크립트 전체가 아니라 작은 서브셸 안에만 거는 까닭은 무엇인가?
7. (연결) "읽는 쪽이 없는 파이프"를 테스트에서 시간에 기대지 않고 만들려면 어떻게 하는가? `>&-`(닫힌 fd)·`/dev/full`(가득 찬 장치)과는 무엇이 다른가?
