# issue/java/lazy-resolution-context-propagation — 정리 (힌트)

## 전체 흐름

```text
[클래스 파일에서 메타데이터 읽기 — 클래스 로드 없음]
  속성값 = "com.example.Thing" (이름 문자열)
  루트 뷰 = { 원천, 속성 맵, 값 추출기, loader = 커스텀 로더 }
        │
        ├─ 루트 뷰 그대로 사용 ───────────────▶ resolve(name, 커스텀 로더) ─▶ 정상
        │
        └─ 파생 팩토리 (상위 단계 뷰 만들기)
              원천 ✔  속성 맵 ✔  값 추출기 ✔  loader ✘ (null 전달)
                    │
                    ▼
           파생 뷰.get(속성, Class) ─▶ 지연 해석: resolve(name, null)
                    │
                    ▼  null → 기본 로더(스레드 컨텍스트 / 앱 로더)로 대체
           ┌────────┴─────────────────────────┐
           ▼                                  ▼
  기본 로더가 클래스를 못 봄           기본 로더도 같은 이름을 봄
  → TypeNotPresentException            → 다른 로더가 정의한 Class 반환
    (시끄러운 실패)                       이름 같음 · 타입 정체성 다름
                                          (예외 없음 — 조용히 틀림)

[교정]
  파생 팩토리의 private 오버로드로 루트의 loader를 그대로 넘긴다
  (형제 팩토리들은 이미 넘기고 있었다 — 대칭 회복)
  리플렉션 경로는 null 유지: 값이 이미 해석된 Class라 지연 해석이 일어나지 않는다

[검증]
  자식 우선 로더가 클래스 하나를 직접 정의 → 같은 이름, 다른 Class
  단언: 꺼낸 Class의 정의 로더 isSameAs 커스텀 로더
  고치기 전: 앱 로더 → 실패 / 고친 뒤: 통과
```

## 핵심 문장

- 지연 해석되는 값(이름·바이트·로컬 시각)은 **해석 문맥과 한 쌍**이다 — 값만 복사하고 문맥을 빼면 다른 문맥으로 해석된다.
- `null = 기본값` 대체는 **빠진 문맥을 조용한 오답으로 바꾼다** — 기본 문맥이 우연히 같은 이름을 알면 예외조차 없다.
- JVM에서 클래스의 정체성은 **이름 + 정의 로더**다 — 이름이 같아도 로더가 다르면 다른 타입이다.
- 파생·복사 팩토리는 원본의 **모든 해석 문맥 필드**를 넘기는지 형제 팩토리와 대칭으로 점검한다.
- 값이 이미 해석된 경로(리플렉션)는 문맥이 필요 없다 — 문맥이 필요한지는 **지연 해석이 일어나는가**로 판정한다.
- 테스트는 "예외 없음"이 아니라 **정체성(정의 로더)**을 단언해야 조용한 오답을 잡는다.
