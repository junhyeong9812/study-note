### A. 문제 (Trigger 4종 + Scheduler 의 TODO)

#### 1. TODO 1·2 — FixedRateTrigger / FixedDelayTrigger (각각 한 줄)

```java
// FixedRateTrigger
public long nextFireTime(long lastScheduled, long lastFinished, long now) {
    // TODO 1: 예정 시각 기준으로 다음을 정한다.
    //
    // 인자 셋 중 **하나만** 쓴다. 어느 것인지가 이 방아쇠의 정의다.
    // now 를 보고 싶어질 텐데, 보는 순간 이것은 건너뛰는 주기가 된다.
}

// FixedDelayTrigger
public long nextFireTime(long lastScheduled, long lastFinished, long now) {
    // TODO 2: 끝난 시각 기준으로 다음을 정한다.
    //
    // 여기도 인자 하나만 쓴다. 고정 주기와 다른 것을 써야 한다.
    // 예정 시각을 쓰면 드리프트가 안 쌓이는데, 그러면 고정 주기와 같은 물건이 된다.
}
```

- 고정 주기·고정 지연은 각각 인자 셋 중 무엇을 쓰는가?
- 고정 주기가 now 를 보는 순간 무엇이 되어버리는가?
- 고정 주기가 지나간 시각을 그대로 반환하는 것이 왜 "몰아서 하기"가 되는가?
- 고정 지연이 예정 시각을 쓰면 왜 존재 이유가 사라지는가?

#### 2. TODO 3 — SkippingRateTrigger (지나간 슬롯은 버린다)

```java
// TODO 3: 예정 시각 기준인데 **지나간 슬롯은 버린다.**
//
// now 를 넘는 첫 슬롯을 준다. 한 칸씩 더하며 찾으면 안 된다.
// 10분 밀렸을 때 그 방식은 열 번을 도는데, 그건 고정 주기와 같은 동작이다.
// 나눗셈 한 번으로 건너뛴 칸 수를 구해라.
//
// 시작 시각의 정렬을 지켜야 한다. 0분에 시작했으면 밀렸다 살아나도 정각에 돈다.
// now 에 주기를 더하면 살아난 시각에 맞춰 어긋나고, 그건 고정 지연이다.
//
// **건너뛴 수를 세라.** 안 세면 이 방식을 쓰고 있다는 사실 자체가 안 보인다.
// 예외도 안 나고 로그도 안 남는 채로 실행이 사라진다.
```

- 한 칸씩 더하며 찾는 풀이는 왜 안 되는가(무엇과 같은 동작이 되는가)?
- 나눗셈 한 번으로 건너뛴 칸 수를 구하는 식은 무엇인가?
- now 에 주기를 더하면 무엇이 깨지고 어느 방아쇠가 되어버리는가?
- 건너뛴 수를 세지 않으면 어떤 종류의 사고가 되는가?

#### 3. TODO 4·5 — CronTrigger (간격 표기 · 다음 일치 시각)

```java
// TODO 4: 간격 표기를 값 집합으로 편다.
//
// min 부터 step 씩 더하되 **max 를 넘으면 멈춘다.** 한 바퀴 돌지 않는다.

//
// 예정 시각도 끝난 시각도 안 본다. 크론은 벽시계만 본다.
// 그래서 밀린 것을 몰아서 하지 않는다. 구조적으로 건너뛰기다.
//
// **지금과 같은 분을 주면 안 된다.** 주면 스케줄러가 그 자리에서 무한히 돈다.
// 다음 분부터 봐야 한다.
//
// 못 찾는 경우에 대비해 상한을 둬라. 안 두면 잘못된 식에서 영원히 돈다.
```

- `*/7` 을 값 집합으로 펴면 어떤 분들이 나오고, 시 경계에서 간격이 왜 4분이 되는가?
- 한 바퀴 돌게 만들면 왜 "크론이 아니게" 되는가?
- 크론이 lastScheduled 도 lastFinished 도 안 보는 것은 어떤 성질로 이어지는가?
- 지금과 같은 분을 반환하면 스케줄러에 무슨 일이 생기는가?
- 다음 일치 시각 탐색에 상한이 필요한 이유는 무엇인가?

#### 4. TODO 6·7 — Scheduler.runDue / fire

```java
// TODO 6: 지금 시각까지 예정된 것을 전부 돌린다.
//
// 한 번 부르는 동안 같은 작업이 **여러 번** 돌 수 있다. 그것이 몰아서 하는 것이고,
// 고정 주기 방아쇠에서 실제로 그렇게 된다. 한 바퀴만 돌면 그 현상이 안 나타난다.

// 상한을 둬라. 작업이 주기보다 계속 오래 걸리면 고정 주기는 영원히 못 따라잡는다.

// TODO 7: 한 번 돌린다. 그리고 다음 실행을 예약한다.
//
// 기록에 남기는 시각은 **예정됐던 시각**이다. 실제로 돈 시각이 아니다.
// 작업이 던져도 **다음 실행을 예약해라.** 그리고 예외를 밖으로 던지지 마라.
// 방아쇠에 넘기는 lastScheduled 는 **예정됐던 시각**이다. 실제 시각을 넘기면
// 고정 주기가 고정 지연이 되어버린다.
```

- runDue 가 한 바퀴만 돌면 어떤 현상이 안 나타나는가?
- runDue 의 상한이 없으면 "영원히 못 따라잡는" 상태는 어떻게 보이는가?
- 기록에 실제 돈 시각이 아니라 예정 시각을 남기는 이유는 무엇인가?
- 작업이 던졌을 때 다음 실행을 예약하지 않으면 무엇이 되는가?
- 예외를 밖으로 던지면 어떤 사고가 나는가(몇 번 챕터가 막으려던 사고인가)?
- 방아쇠에 실제 시각을 lastScheduled 로 넘기면 왜 고정 주기가 고정 지연이 되는가?
