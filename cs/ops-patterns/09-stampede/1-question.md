#### 2. TODO 2 — SingleFlightCache.get (본체)

```java
// TODO 2: 같은 키는 하나만 계산하고 나머지는 그 결과를 기다린다.
//
// **자리를 잡는 일이 한 연산이어야 한다.** "계산 중인가 본다" 와 "계산 중이라고 표시한다"
// 를 나누면 그 사이에서 둘 다 자리를 잡고, 그러면 아무것도 안 막은 것이다.
// 06번 NonAtomicStore 와 정확히 같은 자리다. ConcurrentHashMap 을 쓰는 것으로는 안 된다.
//
// 자리를 잡는 시점에는 값이 아직 없다. 그래서 **앞으로 값이 될 것**을 담는다.
// inFlight 필드의 타입이 그것을 말하고 있다.
//
// 넷을 잊지 마라.
//
//   1. 값을 map 에 담아라. 안 담으면 동시 요청만 막히고 순차 요청은 매번 DB 로 간다.
//      그리고 그 사실이 조용하다. 스탬피드 테스트는 그대로 통과한다.
//   2. 실패하면 기다리던 쪽에도 알려라. 안 알리면 그들은 영원히 기다린다.
//   3. **성공이든 실패든 자리를 비워라.** 실패한 약속을 남기면 그 뒤 모든 요청이
//      그 실패를 영원히 받는다. 원인이 사라져도 안 낫는다.
//   4. hits, misses, loads, waits, peak 를 세라. 이 상자의 결론이 그 수들이다.
```

- "자리를 잡는 일이 한 연산이어야 한다"는 것을 어떤 API 로 실현하는가?
- 보기와 표시를 나누면 정확히 어떤 순서로 둘 다 자리를 잡게 되는가?
- ConcurrentHashMap 을 "쓰는 것"만으로는 왜 안 되는가?
- 자리를 잡는 시점에 값이 없는데 무엇을 담는가?
- 자리를 못 잡은 99개는 무엇을 하는가?
- 자리를 잡았는지(내가 계산 담당인지)는 어떻게 판별하는가?
- 값을 map 에 안 담으면 어떤 테스트는 통과하고 어떤 요청이 어떻게 되는가?
- loader 실패를 약속에 안 알리면 기다리던 쪽은 어떻게 되는가?
- 실패한 약속을 inFlight 에 남겨두면 무슨 일이 벌어지는가?
- 자리 비우기는 코드의 어느 블록에서 해야 안전한가?
