### A. 문제 (NaiveRunner · Saga 의 TODO)

#### 1. TODO 1 — NaiveRunner.run (기준선: 보상 없음)

```java
public SagaResult run() {
    // TODO 1: 차례로 실행하다가 실패하면 멈춘다. **되돌리지 않는다.**
    //
    // 되돌리는 코드를 여기 쓰고 싶어질 텐데, 그러면 이 기준선의 존재 이유가 사라진다.
    // 이 클래스는 "보상이 없으면 무엇이 남는가" 를 보여주려고 있다.
    //
    // 실패해도 예외를 밖으로 안 던진다. 실패도 정상적인 결과다.
    throw new UnsupportedOperationException("TODO 1: run");
}
```

- 이 기준선 클래스는 무엇을 보여주려고 존재하는가?
- 재고✓ → 결제✓ → 배송✗ 이후 시스템에는 정확히 무엇이 남는가?
- 되돌리는 코드를 여기 쓰면 왜 안 되는가?
- 실패해도 예외를 밖으로 던지지 않는 이유는 무엇인가?
- 실패한 걸음의 이름은 결과의 어느 자리에 담기는가?

#### 2. TODO 2 — Saga.run (실패하면 되돌린다)

```java
public SagaResult run() {

    // 예외를 밖으로 던지지 마라. 던지면 부르는 쪽이 "그래서 되돌려졌나" 를 알 수 없다.

    throw new UnsupportedOperationException("TODO 2: run");

```

- executed 목록에는 언제 이름을 넣어야 하는가(execute 전인가 후인가)?
- 실패한 걸음 자신을 executed 에 넣으면 구체적으로 무슨 일이 벌어지는가?
- run 이 예외를 밖으로 던지면 부르는 쪽은 무엇을 알 수 없게 되는가?
- 전부 성공했을 때와 중간에 실패했을 때 반환되는 SagaResult 는 각각 무엇인가?

### B. 개념

#### 4. 왜 사가인가 (트랜잭션이 없는 곳)

- 07번(outbox)에서는 있었던 롤백이 여기서는 왜 없는가?

- 사가의 걸음(SagaStep)은 왜 execute 와 compensate 가 짝으로 있는가?

#### 5. 실패한 걸음 자신은 되돌리지 않는다 (원본 README 생각해볼 것 1)

- execute 가 던진 걸음을 되돌리면 왜 "하지도 않은 일을 취소"하게 되는가?

- execute 가 절반쯤 하고 던지면 어떻게 되는가, 그것을 막는 수단은 무엇인가?

#### 6. 보상의 멱등 (원본 README 생각해볼 것 2)

- 06번 멱등성과 이번 멱등성은 지키는 주체가 어떻게 다른가?

#### 7. 보상 실패의 처리 (원본 README 생각해볼 것 3·4·5)

#### 8. 보상은 롤백이 아니다
