### A. 문제 (구현 대상 TODO — `src/main/java/com/ops/bulkhead/`)

#### 1. SharedPool — 기준선 (TODO 1~4)

```java
@Override
public void release(String key) {
    // TODO 3: 자리를 돌려준다. 잡은 적 없으면 던진다.
    //
    // **Semaphore.release 는 용량을 안 본다.** 부르는 만큼 자란다.
    // 막지 않으면 이중 반납 한 번에 정원이 영구히 늘어나고, 늘어난 정원은 격리를 깬다.
}

@Override
public <T> T call(String key, Callable<T> task) throws Exception {
    // TODO 4: 자리를 잡고, 일을 시키고, **반드시** 돌려준다.
    //
    // 자리가 없으면 BulkheadFullException 이고 **일은 시작조차 안 한다.**
    // 돌려주는 자리를 try/finally 밖에 두면 예외가 날 때마다 칸이 하나씩 영영 준다.
}
```

- 칸을 안 나누는 SharedPool을 왜 먼저 만들게 하는가?
- 칸을 안 나누는데도 이름별 잡은 수·거절 수를 세는 이유는?
- 시간 제한 tryAcquire에서 0 이하를 직접 갈라내는 이유는?
- release가 "잡은 적 없으면 던진다"를 세마포어에 맡기지 못하는 이유는?
- call에서 release가 finally 안에 있어야 하는 이유는 — 밖에 두면 무엇이 얼마나 누적되는가?
- 자리가 없을 때 일을 시작조차 안 하는 것이 왜 "좋은 실패"인가?
- 세마포어를 공정(fair) 모드로 만든 이유는?

#### 3. ElasticBulkhead.tryAcquire — 내 칸 먼저, 그다음 공용 (TODO 8~9)

```java
@Override
public boolean tryAcquire(String key) {
    // TODO 8: 내 칸을 먼저 쓰고, 없으면 공용에서 빌린다.
    //
    // 순서가 중요하다. 공용을 먼저 쓰면 남의 보장을 갉아먹지는 않는데,
    // 공용이 빨리 말라서 정작 자기 칸이 남았는데 남들이 못 빌리는 상태가 된다.
    // **빌렸으면 빌렸다고 세어둬라.**
}

@Override
public boolean tryAcquire(String key, long timeoutMillis) throws InterruptedException {
    // TODO 9: 기다리는 쪽. 자기 칸은 **기다리지 말고 먼저 확인**하고,
    //         기다리는 것은 공용에서만 한다.
}
```

- 내 칸과 공용 중 내 칸을 먼저 쓰는 이유는 — 공용을 먼저 쓰면 무엇이 마르는가?
- 빌린 개수를 이름마다 세어두는 이유는 무엇을 정하기 위해서인가?
- 시간 제한 쪽에서 자기 칸을 기다리지 않고 먼저 확인만 하는 이유는?
- 자기 칸과 공용을 둘 다 기다리면 어떤 약속을 어기게 되는가?
- 자기 칸을 안 보고 공용만 기다리면 어떤 보장이 사라지는가?

#### 4. ElasticBulkhead.release — 빌린 것은 빌린 곳으로 (TODO 10)

```java
@Override
public void release(String key) {
    // TODO 10: **빌린 것은 빌린 곳으로 돌려준다.** 이 구현의 함정이 전부 여기 있다.
    //
    // 전부 자기 칸으로 갚으면 공용이 점점 마르고 자기 칸은 보장보다 커진다.
    // 전부 공용으로 갚으면 반대로 보장 칸이 사라져 격리가 통째로 없어진다.
    // 어느 쪽이든 예외는 안 난다. 몇 시간 뒤에 "공용이 왜 0 이지" 로 나타난다.
    //
    // 여러 스레드가 동시에 돌려준다. loans 를 읽고 쓰는 사이에 남이 끼어들 수 있다.
    // 읽은 값이 그대로일 때만 쓰는 방법을 써라.
}
```

- 전부 자기 칸으로 갚으면 시간이 지나며 무엇이 어떻게 변형되는가?
- 전부 공용으로 갚으면 무엇이 사라지는가?
- 두 오류 모두 예외가 안 나고 몇 시간 뒤에 나타나는 이유는?
- 빌린 것부터 먼저 갚는(공용 우선 반납) 이유는?
- "읽은 값이 그대로일 때만 쓰는 방법"은 무엇이고, 왜 단순한 `loans.decrementAndGet()` 으로는 안 되는가?
