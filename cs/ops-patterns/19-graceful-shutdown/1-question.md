// TODO 1: 즉시 멈춘다. **기다리지 않는다.**

#### 3. TODO 3 — GracefulServer.shutdown (이 상자의 본체)

```java
// TODO 3: 우아하게 종료한다. 이 상자의 본체다.
//
// 순서가 계약이다.
//
//   1. **먼저** DRAINING 으로 바꾼다. 새 요청을 막는 것이 첫 일이다
//   2. 처리 중인 것이 0 이 될 때까지 기다린다
//   3. 기한이 지나면 남은 것을 **세어서** 보고하고 끝낸다
//
// 넷을 조심하라.
//
//   1. 막는 것이 먼저다. 안 막고 기다리면 계속 들어와서 안 끝난다.
//   2. 기한이 없으면 종료가 아니다. 하나가 안 끝나면 영원히 기다리고,
//      그러면 오케스트레이터가 SIGKILL 을 보내 **보고할 기회도 없이** 죽는다.
//   3. 기한 판정은 이상이다. 초과로 쓰면 확인 주기만큼 더 기다린다.
//   4. 보고하는 완료 건수는 **종료 시작 뒤의 것만**이다. 누적을 그대로 보고하면
//      종료와 상관없는 숫자가 되고, 기한이 맞는지 판단할 근거가 사라진다.
//
// 기다리는 동안 ticker.sleep 을 부른다. 시계를 주입받은 이유가 그것이고,
// 그래서 테스트가 10초를 실제로 안 기다린다.
```

- 종료를 한 단계로 하면 무엇과 무엇이 섞이고, 그 결과는 무엇인가?
- 왜 막는 것이 먼저인가?
- 기한이 없으면 무슨 일이 벌어지고, 그 끝은 무엇인가?
- 기한 판정을 `>` 로 쓰면 무엇이 나빠지는가?
- 완료 건수를 누적으로 보고하면 무엇을 잃는가 — 그래서 무엇을 종료 시작 시점에 기억해 둬야 하는가?
- 기한이 지나 버리는 것은 즉시 종료와 무엇이 같고 무엇이 다른가?
- 기다릴 때 `Thread.sleep` 이 아니라 `ticker.sleep` 을 부르는 이유는 무엇인가?
- 루프가 확인해야 하는 두 가지 종료 조건은 무엇이고, 어느 쪽을 먼저 보는가?
