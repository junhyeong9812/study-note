### A. 문제 (구현 대상: LamportClock TODO 1\~3 · VectorClock TODO 4\~6)

#### 1. 램포트 시계 — tick / receive / compare (TODO 1\~3)

```java
// LamportClock.java (src/main) — 채울 것
public synchronized Long tick() {
    ticks++;
    // TODO 1: 내 값을 하나 올리고 그 값을 준다.
}

public synchronized Long receive(Long other) {
    receives++;
    // TODO 2: 받은 값과 내 값 중 큰 쪽을 고르고 하나 더한다.
    //
    // 큰 쪽을 안 고르고 그냥 1 을 더하면, 상대가 앞서 있을 때 받은 값이 보낸 값보다 작아진다.
    // 그러면 "먼저 일어난 일이 더 작다" 는 **이 시계의 유일한 보장**이 깨진다.
    // 1 을 안 더해도 안 된다. 받은 것과 같은 값이 되어 새 사건이 새 타임스탬프를 못 받는다.
}

public Ordering compare(Long a, Long b) {
    // TODO 3: 크기 비교. 같으면 무엇인가.
    // 서로 다른 노드에서 같은 값이 나오는 것은 흔하고, 그 둘 사이에는 인과가 없다.
    // 이 시계가 CONCURRENT 를 말할 수 있는 **유일한** 경우다.
}
```

- 램포트 시계의 규칙 두 줄(tick / receive)은 각각 무엇인가?
- receive 에서 max 를 안 고르고 내 값에 +1 만 하면 어떤 보장이 어떻게 깨지는가? (출처: README 생각해볼 것 1)
- receive 에서 +1 을 안 더하면 무슨 일이 생기는가? (출처: README 생각해볼 것 2)
- compare 에서 값이 같으면 왜 CONCURRENT 로 판정하는가?
- 램포트가 보장하는 것은 어느 방향 한 줄인가, 그 역은 왜 성립하지 않는가?
- "램포트 compare 답의 절반은 근거가 없다"는 말은 무슨 뜻인가?

#### 2. 벡터 시계 — tick / receive / compare (TODO 4\~6, compare 가 본체)

```java
// VectorClock.java (src/main) — 채울 것
public synchronized VersionVector receive(VersionVector other) {
    receives++;
    // TODO 5: 칸마다 큰 쪽을 고르고, **그 다음에** 내 칸을 올린다.
    //
    // 순서를 바꾸면 내 칸이 상대 값에 덮인다. 그리고 평소에는 안 드러난다.
    // 남이 나에 대해 나보다 많이 아는 경우가 없기 때문이다.
    // 재기동하거나 스냅샷에서 복구하면 그 경우가 생기고, 그때 새 사건이
    // 받은 것과 같은 타임스탬프를 갖는다.
}

public Ordering compare(VersionVector a, VersionVector b) {
    // TODO 6: 칸마다 비교한다. 이 상자의 본체다.
    //   한쪽이 전부 작거나 같고 하나라도 작다   ->  그쪽이 먼저
    //   그 외                              ->  동시
    // 셋을 조심하라.
    //   1. **양쪽 키의 합집합**을 봐야 한다.
    //   2. "작은 칸이 있다" 만 보면 안 된다. **상대에게 작은 칸이 없어야** 먼저인 것이다.
    //   3. 아무 칸도 안 다르면 같은 상태다. 그것도 동시로 본다.
}
```

- 벡터 시계의 receive 에서 "합친 다음 내 칸 올리기" 순서를 바꾸면 정확히 무엇이 잘못되는가? (출처: README 생각해볼 것 3)
- 그 잘못은 왜 평소에는 안 드러나고, 어떤 상황에서 드러나는가? (출처: README 생각해볼 것 3·8)
- compare 에서 왜 양쪽 키의 합집합을 돌아야 하는가? (출처: README 생각해볼 것 4)
- "a 에 작은 칸이 있다"만 보고 BEFORE 를 판정하면 어떤 경우를 틀리는가? (출처: README 생각해볼 것 5)
- 두 벡터가 완전히 같으면(칸이 하나도 안 다르면) 결과는 무엇이고 왜인가?
- 0 인 칸과 없는 칸을 같게 취급해야 하는 이유는? (출처: README 생각해볼 것 6)
- `width()` 가 재는 것은 무엇이고, 그 값이 왜 "비용"인가?
