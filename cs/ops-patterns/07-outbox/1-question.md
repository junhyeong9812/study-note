#### 2. TODO 2 — OutboxPublisher.placeOrder (저장소를 하나로 만든다)

```java
// TODO 2: 주문 저장과 이벤트 기록을 **한 트랜잭션 안에서** 한다.
//
// 브로커를 부르지 않는다. 이 클래스는 브로커를 아예 모른다. 그것이 요점이다.
//
// 트랜잭션을 두 번 쓰고 싶어질 수 있다. 그러면 그 사이에 다시 창이 생기고
// 아무것도 안 고친 것이 된다. 그런데 **결과만 보면 똑같아 보인다.**
// 정상 경로도, 앞에서 죽어도, 뒤에서 죽어도 결과가 같기 때문이다.
// 그 사이에서 죽어봐야만 드러나는데 그 지점은 주입할 수도 없다.
//
// 그래서 이 계약은 결과가 아니라 **커밋 횟수**로 검사한다. 주문 하나에 커밋 하나다.
```

- 이 클래스가 브로커를 아예 모른다는 것이 왜 "요점"인가?
- 여기서는 어디서 죽어도 잃을 것이 없는 이유를 두 경우로 나눠 말하면?
- 트랜잭션을 두 번 쓰면 무엇이 안 고쳐지는가?
- 그 결함이 결과로는 안 보이는 이유는 무엇이고, 테스트는 그래서 무엇을 세는가?
- 이 방식이 대신 지불하는 비용은 무엇이고, 그 비용을 줄이려 하면 또 무엇을 지불하는가?
