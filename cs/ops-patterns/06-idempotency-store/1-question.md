#### 5. IdempotentExecutor.execute — 네 갈래 판정 (TODO 5)

```java
// TODO 5: 자리를 노리고, 잡으면 실행하고, 못 잡으면 기존 기록을 보고 판정한다.
//
//   1. tryBegin 이 true 면 **우리 차례다**
//        - executions 를 센다. **실패해도 실행은 실행이다.** action 을 부르기 전에 센다
//        - action.call() 이 던지면 store.fail(key) 하고 **그 예외를 그대로** 던진다
//        - 성공하면 store.complete(key, 응답) 하고 응답을 반환한다
//
//   2. false 면 남이 먼저 잡았다. store.find(key) 로 기록을 본다
//        - 비어 있다     -> 그 사이 만료·청소됐다. **한 바퀴 더 돈다**
//        - 지문이 다르다 -> KeyReuseException. **이 검사가 상태 판정보다 먼저다.**
//        - COMPLETED     -> replays 를 세고 **저장된 응답을 그대로** 반환한다
//        - IN_PROGRESS   -> conflicts 를 세고 ConflictException
//        - FAILED        -> 자리가 비었다는 뜻이다. **한 바퀴 더 돈다**
//
//   3. 반복문을 다 돌았는데 못 잡았으면 conflicts 를 세고 ConflictException
```

- 재생할 때 `replays` 를 안 세면 운영에서 무엇을 모르게 되는가?
