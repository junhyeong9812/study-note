# data-engineering/06-event-data-modeling — 질문

## 질문

1. (왜) 이벤트 시각·수집 시각·처리 시각은 각각 누가 찍나? 업무 지표 "10월 1일 매출"은 보통 어느 시각으로 자르고, 나머지 두 시각은 어디에 쓰나?
2. (예측) 한국 시간 10-01·10-02에 하루 1,000건씩 고르게 일어난 주문이 있다. 30건 중 1건은 90분 늦게 처리된다. (a) 처리 시각의 KST 날짜, (b) 이벤트 시각의 UTC 날짜로 하루씩 자르면 날짜별 건수는 어떻게 나오나?
3. (경계) CloudEvents 1.0.2의 필수 속성 넷과 선택 속성 넷은? 이벤트 본문 스키마의 버전은 어디에 담고, `specversion`은 무엇의 버전인가?
4. (예측) 2,000건에 재전송 40건이 섞였다. ID 없이 적재할 때와 `(source, id)` 기본 키 + `ON CONFLICT DO NOTHING`으로 적재할 때 행 수·합계는? ID 대신 "시각·금액이 같으면 중복"으로 지우면 무엇이 잘못되나?
5. (장애 진단) 이벤트 일부가 수집 시각보다 몇 시간 "미래"다. 원인과 확인 쿼리, 처리 정책은? Kafka `CreateTime` 토픽이라면 어떤 설정이 추가로 작동하나?
6. (연결) 회원 등급을 하루 1회 상태 스냅샷으로만 보낼 때 잃는 정보 두 가지는? 변경 이벤트로 바꾸면 소비자는 무엇을 해야 "현재 상태"를 얻나?
7. (연결) 중복 제거용 키 저장소를 블룸 필터로 바꾸면 메모리는 줄지만 무엇이 위험한가? 어떤 이벤트에 특히 맞지 않나?
8. (장애 진단) 재무팀 매출과 대시보드 매출이 날짜별로 다르지만 일주일 합계는 거의 같다. 이벤트 모델 관점에서 의심할 원인 두 가지와 각각을 가르는 쿼리는?
