# data-engineering/08-idempotent-pipelines-and-backfill — 질문

## 질문

1. (왜) 배치 잡이 다시 도는 경우 세 가지는? 각 경우에 결과가 바뀌지 않으려면 태스크가 어떤 성질을 가져야 하나(Beauchemin의 "pure task")?
2. (예측) 10-01 주문 100건(× 10,000원, 수수료 2.5%)을 집계하는 잡을 두 번 실행한다. append(`INSERT`) 방식과 `DELETE` 후 `INSERT` 덮어쓰기 방식에서 `daily_fee`의 행 수·주문 수·수수료는 각각?
3. (예측) 덮어쓰기 잡이 `DELETE` → 3초 → `INSERT`를 한다. (a) 한 트랜잭션일 때, (b) 문장마다 자동 커밋될 때, 시작 1초 뒤 다른 세션이 읽은 주문 수는? 왜 그런가?
4. (예측) 수수료율이 10-01부터 3% → 2.5%로 바뀌었다. 09-28~09-30(하루 100건 × 10,000원)을 (a) 유효 기간 요율 테이블로 조인하는 잡, (b) 2.5%를 코드에 박은 잡으로 백필하면 9월 수수료 합계는? Beauchemin의 세금 예는 무엇을 경고하나?
5. (그림) 백필을 "파티션 DAG에서 다시 계산할 파티션을 고르는 일"로 그려라. 같은 테이블의 이전 파티션에 의존하는 잡이 있으면 백필이 어떻게 달라지나?
6. (장애 진단) 어제 매출이 원천보다 7건 적고 며칠이 지나도 맞지 않는다. 원인과, 다시 계산할 파티션을 찾는 쿼리는? 왜 적재 시각 컬럼이 필요한가?
7. (경계) Beauchemin은 늦게 오는 사실이 있으면 적재 파티션을 무엇으로 나누라고 하나? 그 이점과 대가는?
8. (연결) 1년치 백필을 운영 시간에 시작했더니 API 지연이 올랐다. 무엇이 부하를 만들고, 어떻게 나눠 돌리나? 백필이 끝났다고 말하기 전에 확인할 것은?
