# data-engineering/14-lakehouse-table-formats — 질문

## 질문

1. (왜) "객체 저장소의 디렉터리 하나 = 테이블"로 쓰면 무엇이 깨지나? 쓰기 잡이 중간에 죽을 때, 두 잡이 동시에 쓸 때, 테이블 파일 목록을 알아낼 때로 나눠 답하라.
2. (그림) Iceberg 테이블의 메타데이터 트리를 카탈로그 포인터부터 데이터 파일까지 그려라. 새 append 커밋 하나가 만드는 객체는 무엇이고, 무엇을 이전 스냅샷과 공유하나?
3. (예측) 8개 작성자가 같은 테이블에 50번씩 append한다(커밋당 파일 1개·100행). 커밋을 (a) 포인터 CAS로, (b) 검사 없이 포인터 덮어쓰기로 구현하면 최종 행 수는 각각 어떻게 되나? 오류는 나나?
4. (예측) compaction이 10-01 파티션의 작은 파일 4개(각 100행)를 1개로 합치는 동안, 다른 커밋이 그중 1개를 지웠다. compaction의 재시도가 (a) "원본 파일이 아직 다 있나"를 검증하면, (b) 검증하지 않으면 최종 행 수는? 명세는 어느 쪽을 요구하나?
5. (경계) Iceberg 명세의 커밋 충돌 규칙에서 append, replace, 파일 지정 delete, 식 기반 delete, 스키마 변경은 각각 재시도 전에 무엇을 확인하나? 왜 append에는 조건이 없나?
6. (연결) 테이블 포맷의 스냅샷·만료·고아 파일 삭제·compaction을 PostgreSQL MVCC의 무엇과 짝지을 수 있나? Merkle 트리와는 무엇이 닮았고 무엇이 다른가?
7. (경계) Iceberg·Delta Lake·Hudi는 커밋의 원자성을 각각 무엇에 기대나? CIDR 2021 논문의 Hudi 서술과 현재 Hudi 문서는 무엇이 다른가?
8. (장애 진단) 스트리밍 적재를 시작한 테이블에서 쿼리 실행은 1초인데 전체는 10초가 걸린다. 무엇을 의심하고 어떤 메타데이터 테이블로 확인하나? 해법은?
9. (장애 진단) 행 수는 그대로인데 저장 비용이 매달 오르고, 감사 요청의 `TIMESTAMP AS OF` 쿼리는 실패한다. 두 증상은 어떻게 같은 설정 문제의 양면인가? 어떻게 둘 다 해결하나?
10. (장애 진단) 고아 파일 삭제를 돌린 직후 일부 쿼리가 "파일 없음"으로 실패한다. 무엇이 잘못됐을 수 있나?
