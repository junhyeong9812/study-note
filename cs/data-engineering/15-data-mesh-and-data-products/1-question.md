# data-engineering/15-data-mesh-and-data-products — 질문

## 질문

1. (왜) 중앙 데이터 팀 하나가 모든 분석 데이터를 만드는 구조는 회사가 커질수록 왜 느려지나? Dehghani(2019)가 든 세 실패 모드로 답하라.
2. (그림) 데이터 메시의 네 원칙을 적고, 각 원칙이 빠지면 무엇이 깨지는지 짝지어라. 왜 "도메인 소유"만 도입하면 안 되나?
3. (경계) 데이터 제품은 "도메인이 내놓는 테이블 하나"와 무엇이 다른가? 2020년 글의 아키텍처 퀀텀 세 구성 요소로 답하라.
4. (경계) 연합 계산 거버넌스에서 전역으로 정할 것과 도메인이 정할 것을 둘씩 들어라. "계산(computational)"은 무엇을 뜻하나?
5. (예측) 사용자 1000명의 같은 이벤트 로그에서 성장팀은 "30일 내 로그인", 콘텐츠팀은 "30일 내 재생", 결제팀은 "30일 내 로그인 또는 결제", 마케팅은 "7일 내 로그인"을 활성 사용자로 센다. 네 숫자는 같은가? 오류는 나나? 실험의 숫자 크기 순서는?
6. (예측) ODPS v1.1.0 모양의 서술자 4개가 있다 — (a) 소유 팀·계약·SLO 모두 있음, (b) 출력 포트에 계약 ID 없음, (c) 소유 팀 없음, (d) retired인데 소비자가 있음. 표준 필수 필드 검사와 "소유자·계약·SLO 필수" 조직 정책 검사는 각각 몇 개를 통과시키나? 이유는?
7. (연결) 데이터 메시의 데이터 제품 경계는 domain-modeling의 무엇과 같은 생각인가? 도메인을 넘나드는 '사용자'·'아티스트' 같은 개념(다의어)은 어떻게 다루나?
8. (장애 진단) 데이터를 도메인별로 나눈 지 1년, 주인을 모르는 테이블이 수백 개다. PostgreSQL에서 후보를 찾는 쿼리와, 다시 쌓이지 않게 하는 장치는?
9. (장애 진단) 은퇴(retired) 처리한 데이터 제품의 테이블을 지웠더니 월말 정산이 깨졌다. 무엇이 빠졌고 어떤 순서로 은퇴시켜야 했나?
