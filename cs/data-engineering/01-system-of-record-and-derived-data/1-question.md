# data-engineering/01-system-of-record-and-derived-data — 질문

## 질문

1. (왜) 같은 값이 운영 DB·캐시·검색 인덱스·집계 테이블에 다 있을 때, "원천은 하나"라고 정해 두지 않으면 무엇을 할 수 없나?
2. (그림) 주문 이벤트 로그에서 주문 요약 테이블이 만들어지는 과정을 폴드로 그려라. 같은 로그로 두 번 재구축한 결과가 같으려면 `apply` 함수에 어떤 조건이 필요한가?
3. (예측) 파생 테이블 `order_view`에서 주문 7을 `total=0, status='refunded'`로 직접 고친 뒤 `rebuild_view()`를 돌리면 주문 7은 어떻게 되나? 실험 출력으로 답하고, 같은 환불을 남기는 올바른 방법을 대라.
4. (경계) 캐시·검색 인덱스·CQRS 조회 모델·이벤트 소싱의 현재 상태 테이블 가운데 원천은 무엇이고 파생은 무엇인가? 이벤트 소싱에서는 그 관계가 어떻게 뒤집히나?
5. (연결) "비정규화는 파생본을 하나 더 두는 결정이다"라는 말을 정규화(database/03)와 연결해 설명하라. 비정규화할 때 같이 정해야 할 세 가지는?
6. (장애 진단) 목록 화면과 상세 화면의 주문 금액이 50건에서 다르다. 에러 로그는 없다. 무엇을 의심하고, 어떤 쿼리로 어긋난 행을 찾나? 대조 기준은 왜 파생본이 아니라 원천이어야 하나?
7. (장애 진단) CRM과 주문 DB가 고객 등급을 서로 다르게 가지고, 양방향 동기화 잡이 값을 번갈아 덮어쓴다. 원인과 대처는?
8. (장애 진단) 프로젝터 버그를 고쳤는데 조회 모델을 재구축할 수 없다고 한다. 어떤 상황일 수 있고, 미리 무엇을 정해 두었어야 하나?
