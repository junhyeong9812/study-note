## 질문

**1. (연결)** SOLID와 CLEAN은 어떤 관계인가? 왜 하나는 "수단", 다른 하나는 "상태"라고 부르는가?

**2. (충돌)** CLEAN 5속성 중 서로 **긴장 관계**에 있는 쌍을 짝지어 보라. 각 쌍은 무엇으로 판정하는가? (요약표를 보기 전에 스스로)

**3. (판단)** 하나의 값 객체(예: `Money`)가 여러 서비스에 복붙되어 있다. 이것은 **N(비중복) 위반**인가, **L(느슨한 결합)을 지키기 위한 정당한 중복**인가? 무엇을 재료로 판정하는가?

**4. (경계)** "Assertive(단정적)"와 SOLID의 SRP(단일 책임)는 어떻게 다른가?
   - 힌트: 하나는 책임의 **개수**, 다른 하나는 책임의 **위치**.

**5. (판단)** 캡슐화가 잘 된 코드는 테스트하기 **쉬운가, 어려운가?** 왜인가?
   - 힌트: 내부 상태를 확인할 수 없다 vs 의미 있는 조작만 검증하면 된다.

**6. (경계)** CLEAN 5속성은 어느 추상화 레벨까지 올라가는가? **서비스 레벨**에도 적용되는가?
   - 힌트: 응집도 → 바운디드 컨텍스트, 결합도 → 서비스 간 통신, 캡슐화 → API 경계.

**7. (왜)** setter는 "대체로" 캡슐화를 깨뜨리는데 getter는 "경우에 따라" 다르다. 무엇이 이 차이를 만드는가? getter가 캡슐화를 깨는 것은 정확히 어떤 경우인가?

**8. (경계)** 겉모양이 똑같은 코드 두 조각이 있다. 이것이 **진짜 중복**인지 **우연한 중복**인지 한 문장으로 판정하는 기준은 무엇인가? 잘못 합치면 왜 "더 위험한 버그"가 되는가?

**9. (왜)** 플래그 인자(`f(x, true, false)`)가 왜 "이 메서드는 사실 두 가지 일을 한다"는 자백인가? 어떻게 고치는가?

**10. (예측)** 응집을 높이려 관련된 것들을 한곳에 모았더니, 그것이 다른 곳의 코드와 중복되기 시작했다. C와 N 중 무엇을 우선하는가? 왜 그런가?

**11. (경계)** 빈약한 도메인 모델(Anemic Domain Model)은 항상 나쁜가? 오히려 합리적인 경우 셋을 들고, 그 셋을 관통하는 판단 기준 하나를 말하라.

**12. (예측)** 결합을 줄이려고 두 클래스 사이에 이벤트 버스를 넣거나 인터페이스를 남발했다. 결합은 줄었는데 무엇을 잃었는가? 이때 "손해였다"고 판정하는 기준은?

**13. (연결)** 응집도·결합도의 7등급 사다리에서, **가장 나쁜 등급**과 **목표 등급**을 각각 대고, 그 사이에 무엇이 있는지 순서대로 떠올려 보라.
