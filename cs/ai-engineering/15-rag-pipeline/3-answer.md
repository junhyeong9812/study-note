# ai-engineering/15-rag-pipeline — 정답

## 정답

### 1. RAG가 푸는 것

- 모델은 학습 때 본 것만 가중치에 담고 있다. 우리 회사의 규정은 그 안에 없거나 옛 버전이다. 그럴듯한 숫자를 지어낼 수 있다.
- *파라미터 지식*: 가중치에 녹은 지식. 바꾸려면 다시 학습한다.
- *비파라미터 지식*: 검색 인덱스의 문서. 문서를 고치고 다시 색인하면 다음 질의부터 반영된다.
- Lewis 외(NeurIPS 2020) 초록은 RAG를 두 메모리의 결합으로 설명하고, 출처 제공과 지식 갱신을 열린 문제로 꼽는다.

### 2. 파이프라인

```text
  오프라인: 수집 → 정제 → 청킹 → 임베딩 → 색인(벡터 + 문서 ID·권한·버전)
  온라인:   질문 → 임베딩 → 검색 top-k(권한 필터는 검색 질의 안)
                → 점수 임계값·0건 확인 → 프롬프트 조립(청크마다 [ID])
                → LLM → 출처 검증(인용 ID ⊆ 건넨 ID) → 응답
```

- 권한 필터는 검색 질의 안에, 임계값은 검색 직후, 출처 검증은 생성 직후다.

### 3. 맥락 없는 작은 청크

(실험 1, Python 3.12.3)

```text
  문장 단위 40자, 접두 없음
    [d00#0] 0.464  KA-504 제품은 가정용 제습기이다.
    [d08#2] 0.372  환불 기한은 구매 후 30일이다.     ← 다른 제품
    [d12#2] 0.372  환불 기한은 구매 후 30일이다.     ← 다른 제품
```

- 정답 문장 "환불 기한은 구매 후 7일이다"에는 제품 코드가 없다. 30편이 같은 틀이라 다른 제품의 환불 문장과 구별되지 않는다.
- 적중: 접두 없음 0.07 → 제목 접두 1.00. 제목을 붙이면 청크 안에 "KA-504"가 들어가 질문과 일치한다.

### 4. 겹침

- 고정 40자 겹침 0: 잘린 정답 73/90, 적중 0.02(접두 없음)·0.19(접두).
- 고정 40자 겹침 15: 잘린 정답 2/90, 적중 0.98.
- 대가: 청크 수가 150 → 240으로 늘어 색인 크기·임베딩 비용이 커진다. 같은 문장이 두 청크에 들어가 top-k에 중복으로 올 수 있다(해석).

### 5. 통째 청크의 문제

- 적중은 1.00이지만 top-3 프롬프트가 평균 543자다. 문장 단위 40자 + 접두(71자)의 약 7.6배다.
- 늘어난 글자만큼 토큰 비용과 지연이 커진다([04](../04-tokenization-and-token-cost/2-summary.md)·[10번](../10-inference-latency-metrics/2-summary.md)).
- 무관한 문장이 정답 사이에 끼어 정답이 긴 문맥의 중간에 놓일 수 있다. Liu 외(TACL 2024) 초록: 관련 정보가 중간에 있으면 성능이 크게 떨어진다.
- 이 실험의 문서는 짧다(평균 182자). 실제 문서는 수천~수만 자라 통째 청크는 프롬프트 한도 자체를 넘길 수 있다(해석).

### 6. 근거 없는 질문

- top-k 검색기는 관련 문서가 없어도 "가장 가까운 것"을 돌려준다. "QQ-101"이 색인에 없어도 "환불 기한" 바이그램이 맞는 KA-504의 환불 청크가 top1로 왔다(점수 0.288).
- 모델은 받은 자료로 답하려 해 "7일"이라고 말한다.
- 신호: top1 점수. 실험에서 답 없는 질문 6개의 최대 0.288 < 답 있는 질문 90개의 최소 0.367. 점수 0인 질문도 결과 1건이 왔다.
- 임계값은 평가셋에서 답 있는/없는 질문 분포를 보고 정한다. 임베딩 모델·말뭉치를 바꾸면 다시 잰다.

### 7. 권한

- 검색 질의 안에서 거른다(`WHERE acl_groups && 사용자그룹`). 그래야 권한 밖 청크가 프롬프트에 들어가지 않는다.
- 생성 뒤에 거르면 늦다. 프롬프트에 들어간 내용은 답의 다른 문장에 녹아 나올 수 있다(해석). 모델이 "이 자료는 쓰지 마라" 같은 지시를 지킨다고 기대할 수 없다([22번](../22-prompt-injection-and-llm-security/2-summary.md)).
- 근사 인덱스는 필터를 탐색 **뒤에** 적용해 결과가 LIMIT보다 적을 수 있다([16번](../16-vector-index-ann/2-summary.md) 실험 2: 선택도 10%에서 평균 4.26행, 점검 재실행 4.21행). 반복 스캔·부분 인덱스·파티션을 함께 본다.

### 8. 출처 표기와 검증

- 청크마다 시스템이 붙인 ID(`[d00#1]`)로만 인용하게 한다.
- 응답의 인용 ID가 이번에 건넨 ID 집합 안에 있는지 검사한다. 링크는 검증된 ID로 시스템 메타데이터에서 만든다. 응답 텍스트의 문서명·URL을 파싱하지 않는다.
- 실험 2(JDK 21)
  - `구매 후 7일입니다 [d00#1].` → 통과
  - `… [d00#1]. … [d07#2].` → 실패, `unknown=[d07#2]`(건네지 않은 ID)
  - `구매 후 7일입니다.` → 실패(인용 없음)
  - `… [d00#1]. … [d100#1].` → 실패, `unknown=[d100#1]`. ID 꼴만 모으는 패턴이었다면 `[d100#1]`이 빠져 통과했다 — 대괄호 표기를 전부 모아 검사한다.
- 이 검사는 ID 실재만 본다. 인용한 청크가 문장을 실제로 뒷받침하는지는 평가에서 따로 본다.

### 9. 실패 단계 가르기

1. 정답 문장을 통째로 담은 청크가 색인에 있나? 없으면 청킹.
2. 그 청크가 top-k에 들어왔나? 없으면 검색(맥락 접두·하이브리드·인덱스 recall).
3. top-k에 있었는데 틀렸나? 프롬프트 조립(순서·양)·생성.
4. 원래 답이 없는 질문이었나? 임계값·거절 경로.

- 기록: 질문, top-k 청크 ID와 점수, 최종 프롬프트에 넣은 청크 ID, 응답의 인용 ID와 검증 결과. 프롬프트 원문 기록은 개인정보 문제가 있다([23번](../23-llm-observability-and-cost/2-summary.md)).
