# ai-engineering/12-prompt-and-semantic-caching — 질문

## 질문

1. (왜) 프리픽스(프롬프트) 캐시와 의미 캐시는 각각 무엇을 재사용하나? 어느 쪽이 틀린 답을 줄 위험이 있고, 왜인가?
2. (그림) Anthropic 프롬프트 캐시의 키를 tools → system → messages 블록과 누적 해시로 그려라. 시스템 프롬프트 한 글자가 바뀌면 어느 위치의 키가 바뀌나?
3. (예측) 요청 100개, 고정 접두 3,000토큰. 요청마다 바뀌는 값을 접두 앞에 둘 때와 뒤에 둘 때, 쓰기 1.25·읽기 0.1 단가로 입력 비용은 캐시 없을 때의 몇 배인가? 실험 출력으로 확인하라.
4. (계산) 접두 하나를 한 번 쓰고 한 번 읽으면 캐시 없이 두 번 처리할 때보다 싼가? 한 번 쓰고 한 번도 안 읽으면?
5. (경계) Anthropic에서 `cache_control`을 붙였는데 응답의 캐시 쓰기·읽기 토큰이 둘 다 0이다. 오류는 없다. 무엇을 의심하나? TTL은 언제부터 재나?
6. (예측) 문자 2-gram 모형 의미 캐시에서 "환불이 불가능한가요"와 "주문 1002 배송 상태"의 최고 유사도는, 옳은 재사용인 "주문 취소 어떻게 해요"보다 높을까 낮을까? 그 결과가 임계값 선택에 주는 뜻은?
7. (장애 진단) 의미 캐시 도입 뒤 A 고객사 사용자가 B 고객사 정책이 담긴 답을 받았다. 유사도는 1.00이었다. 임계값을 0.99로 올리면 해결되나? 무엇을 해야 하나?
8. (적용) 의미 캐시의 파티션 키에 들어가야 할 것을 대고, 각각 빠지면 어떤 사고가 나는지 말하라. 의미 캐시를 쓰지 말아야 할 질문은 어떤 것인가?
9. (연결) 의미 캐시에서 놓침이 한꺼번에 몰릴 때 생기는 문제와 대처는 어떤 주제에서 다루나? 일반 캐시 키 설계 규칙과는 어떻게 이어지나?
