# ai-engineering/12-prompt-and-semantic-caching — 정답

## 정답

### 1. 무엇을 재사용하나

- 프리픽스 캐시: 제공자가 같은 접두의 **계산 결과(KV 상태)**를 재사용한다. 답은 매번 새로 생성된다. 접두가 정확히 같을 때만 적중하므로 답이 틀려질 위험은 없다.
- 의미 캐시: 앱이 **전에 만든 답**을 재사용한다. 임베딩 유사도가 임계값 이상이면 적중한다. "비슷하지만 다른 뜻"의 질문에도 적중할 수 있어 틀린 답을 줄 위험이 있다.

### 2. 누적 해시 키

```text
  [tools b1] [system b2] [msg b3] [msg b4 ◄중단점]
  h1=H(b1)   h2=H(h1,b2) h3=H(h2,b3) h4=H(h3,b4)
```

- b2가 바뀌면 h2가 바뀌고, h3·h4는 h2를 품고 있으니 모두 바뀐다. h1(tools)만 같다.
- 그래서 system·messages 쪽 캐시가 무효가 된다. 도구 정의를 바꾸면 전부 무효다(계층 무효화).

### 3. 가변값 위치 실험

- 앞: 쓰기 300,100토큰·읽기 0 → **1.25배**. 매번 다른 키라 쓰기만 했다.
- 뒤: 쓰기 3,000·읽기 297,000 → **0.13배**. 첫 요청만 쓰고 99번 읽었다.
- 내용은 같고 배치만 다르다.

### 4. 손익

- 한 번 쓰고 한 번 읽기: 1.25 + 0.1 = 1.35배 < 캐시 없이 두 번 2배. 싸다(OpenAI 문서의 같은 계산).
- 한 번 쓰고 안 읽기: 1.25배 > 1배. **손해**다. 재사용될 접두에만 캐시를 건다.
- 배수는 제공자·모델·TTL 옵션마다 다르니 가격표로 확인한다. 예: OpenAI GPT-5.6 이전 모델은 쓰기 추가 요금이 없어 이 손해가 생기지 않는다(2026-10-08 확인).

### 5. 쓰기·읽기 둘 다 0

- 최소 캐시 길이 미달을 먼저 의심한다. Anthropic은 모델별 512~4,096토큰 아래면 `cache_control`이 있어도 **오류 없이** 캐시하지 않는다.
- 둘 다 0이 아니라 **쓰기는 있고 읽기만 0**이면 다른 원인이다: 중단점이 요청마다 바뀌는 블록에 있거나, 직전 쓰기가 lookback(20블록) 밖이다. 이때는 매 요청 새 항목을 쓰므로 쓰기 토큰이 0이 아니다(Anthropic "Prompt caching", 2026-10-08 확인).
- TTL은 캐시를 쓰거나 읽은 요청의 **시작** 시각부터 잰다. 응답 생성에 걸린 시간도 수명을 소모한다. 사용할 때마다 추가 비용 없이 갱신된다(기본 5분).

### 6. 모형 의미 캐시의 유사도

- 높다. "환불이 불가능한가요" 0.84, "주문 1002 배송 상태" 0.86 vs "주문 취소 어떻게 해요" 0.64(옳은 재사용), "환불 가능한가요" 0.82(옳은 재사용).
- 뜻: 어떤 임계값을 골라도 옳은 적중만 남기고 오적중을 0으로 만들 수 없다. 임계값 조정만으로는 안 되고, 정확 일치로 갈라야 할 것(식별자)은 키로 빼고, 남는 위험(부정어)은 범위를 좁혀 받는다.
- 모형 임베딩이라 수치는 실제 모델과 다르다. 실제 모델에서도 오적중이 있다는 근거는 GPT Semantic Cache 논문 표 1의 범주별 positive hit 92.5~97.3%다(초록은 "97% 초과"로 요약). 범주에 따라 적중의 약 3~7.5%가 GPT-4o Mini 판정에서 맞는 답이 아니었다(해석 — 모델 판정이라 실제 오답률 그 자체는 아님).

### 7. 다른 고객사의 답

- 임계값을 올려도 해결되지 않는다. 질문 문장이 같아 유사도가 1.00이다(실험: θ = 0.95에서도 적중).
- 테넌트를 **파티션 키**에 넣어 다른 테넌트의 항목은 비교 대상조차 되지 않게 한다(실험: 넣자 오적중 사라짐).
- 고객사별 정책·개인 데이터가 섞인 답은 의미 캐시에 저장하지 않는다. 사고는 보안 사건으로 다룬다.

### 8. 파티션 키

| 키 | 빠지면 |
|---|---|
| 테넌트·권한 범위 | 다른 고객사·사용자의 답 노출 |
| 언어(locale) | 다른 언어로 답 |
| 모델·프롬프트 버전 | 배포 뒤에도 옛 답 |
| 임베딩 모델 | 옛·새 임베딩 공간 혼합으로 유사도 무의미([05번](../05-embeddings-and-similarity/2-summary.md)) |
| 질문 속 식별자(주문 번호 등) | 다른 주문의 상태를 답함 |

- 쓰지 말아야 할 질문: 답이 사람·시점에 따라 달라지는 것(주문 상태·잔액·권한·재고). 이런 것은 정확 키 캐시나 원천 조회를 쓴다.

### 9. 연결

- 놓침이 몰리면 같은 질문으로 LLM을 여러 번 부른다(비용·한도 소진). 요청 합치기(single-flight)·조기 갱신으로 막는다 — [reliability/29-cache-stampede](../../reliability/29-cache-stampede/2-summary.md).
- 키 설계는 일반 캐시 규칙 "키 = 값이 의존하는 모든 것" 그대로다 — [database/31](../../database/31-cache-key-versioning-and-serialization/2-summary.md). 의미 캐시는 거기에 "유사도 비교는 파티션 안에서만"이 더해진다.
