# ai-engineering/03-cross-entropy-and-perplexity — 정답

## 정답

### 1. 세 토큰의 평균 NLL

- NLL: −ln 0.50 = 0.693, −ln 0.80 = 0.223, −ln 0.05 = 2.996.
- 평균 NLL = 3.912 / 3 = 1.304 nats. perplexity = e^1.304 ≈ 3.68.
- 확률 0.05를 준 셋째 토큰이 손실 대부분(2.996)을 만들었다. NLL은 "놀란 만큼" 커진다.

### 2. 교차 엔트로피와 KL

- 식 3.51: `H(P, Q) = H(P) + D_KL(P‖Q)`.
- H(P)는 데이터 분포에만 의존하고 모델 Q와 무관하다. 그래서 Q를 바꿔 교차 엔트로피를 줄이면 줄어드는 것은 KL 몫뿐이다(Goodfellow 외 3.13).
- KL ≥ 0이므로 교차 엔트로피는 H(P)보다 작아질 수 없다. 엔트로피·KL 정의는 [math/14](../../math/14-information-theory-basics/2-summary.md).

### 3. exp와 2^

- `bits = nats / ln 2`이므로 `2^bits = 2^(nats/ln 2) = e^nats`. 밑만 바꾼 같은 양이다.
- 실험 A에서 평균 NLL 1.9803 nats → exp = 7.2452. 이것을 `2^1.9803`으로 계산하면 약 3.95로 틀린 값이 된다(계산).
- 그래서 loss 이름에 단위(nats·bits)를 넣는다.

### 4. 단어 vs 2조각

- 텍스트 전체 log P는 둘 다 −792.1346으로 같다.
- 단어 단위: 평균 NLL = 792.13/400 = 1.98 → PPL 7.2452.
- 2조각 단위: 평균 NLL = 792.13/800 = 0.99 → PPL 2.6917(= √7.2452).
- 바이트당 비트는 둘 다 0.4840이다. 분모(UTF-8 2361바이트)가 토크나이저와 무관하기 때문이다(실험 B).

### 5. perplexity 절반

- 먼저 두 모델의 토크나이저(어휘)가 같은지 본다. SLP3 3.3: 어휘가 같을 때만 비교할 수 있다. 7.7.1: 토크나이저 차이에 매우 민감하다.
- 같은 시험 텍스트인지, 그 텍스트가 학습에 쓰였을 가능성은 없는지([01](../01-ml-in-one-page/2-summary.md)), 단위(nats·bits)가 적혀 있는지도 본다.
- 꼭 비교하려면 텍스트 전체 NLL을 바이트 수로 나눈 bits per byte로 바꾼다. 최종 판정은 실제 작업 평가로 한다(SLP3 3.3).

### 6. 큰 로짓·작은 로짓

- `[1000, 999, 998]`: `exp(1000)`이 ∞로 넘쳐 ∞/∞ → NaN 세 개.
- `[-1000, -1001, -1002]`: `exp`가 모두 0으로 사라져 0/0 → NaN 세 개.
- log-sum-exp는 두 경우 모두 `[-0.4076, -1.4076, -2.4076]`(실험 D).
- 같은 이유: softmax는 모든 입력에 같은 상수를 더해도 출력이 같다(Goodfellow 외 6.2.2.3). 두 입력은 서로 2000만큼 이동한 것뿐이다.

### 7. 평균 손실 Infinity

- 원인 ① 평활 없는 빈도 모델에서 학습에 없던 토큰의 확률이 0이다(실험 C: `retry`). 대처: 평활(SLP3 3.6).
- 원인 ② 확률을 먼저 계산한 뒤 log를 취하는 코드에서 `exp`가 0으로 사라졌다(실험 D: 로짓 차 800 → NLL Infinity). 대처: 로짓에서 log-softmax(log-sum-exp)로 로그 확률을 바로 계산한다(안정 구현은 800.0).
- 클리핑의 부작용: 무한은 막지만 그 토큰의 손실을 −ln 1e-12 = 27.6으로 잘라 실제보다 작게 보고한다. 클리핑된 토큰 수를 따로 기록한다.

### 8. 확률 곱 = 0.0

- 400개 확률의 곱은 e^(−792) 수준이라 double로 표현할 수 있는 가장 작은 양수보다 작다. 언더플로로 0.0이 된다.
- SLP3 3.1.3: 언어 모델 확률은 로그 공간에서 저장·계산한다. 로그를 더하는 것이 곱하는 것과 같다.

### 9. API logprobs

- OpenAI Chat Completions에서 `logprob`은 그 토큰이 상위 20위 안일 때의 값이고, 아니면 센티널 −9999.0이다(2026-10-08 확인). 그대로 평균하면 NLL이 터무니없이 커진다. 센티널은 평균에 넣지 않고 따로 센다. 다만 뺀 뒤의 평균은 남은 토큰만의 값이라 텍스트 전체의 NLL·perplexity가 아니다 — 센티널이 있으면 전체 값은 계산 불가로 보고한다.
- 그 값은 그 모델의 토크나이저 단위라 다른 제공자 모델과 토큰당 값을 나란히 비교할 수 없다. 모든 토큰의 `logprob`이 실제 값이고 `bytes`가 모두 있을 때(`bytes`는 `null`일 수 있다) 그 길이 합으로 나눈 bits per byte로 바꾸면 분모는 맞출 수 있다. 다만 두 모델이 같은 텍스트를 채점한 것이 아니면(각자 생성한 텍스트) 그것도 비교가 아니다(해석).
