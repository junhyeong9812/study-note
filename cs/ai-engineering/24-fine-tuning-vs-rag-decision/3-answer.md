# ai-engineering/24-fine-tuning-vs-rag-decision — 정답

## 정답

### 1. 두 종류의 "모른다"

- 지식(사실): 가격·정책·고객사 계약처럼 바뀌고, 출처가 필요한 것 → **RAG**. 지식을 가중치 밖 색인에 두면 갱신이 문서 갱신이고 출처를 붙일 수 있다.
- 행동(형식·말투·작업 방식): JSON 형식·분류 기준·말투 → **프롬프트(지시·예시)·구조화 출력** 먼저, 그래도 안 되면 **파인튜닝**. 지식이 아니라 "어떻게 하나"라서 검색할 문서가 없다.

### 2. 네 축 비교

| | RAG | 파인튜닝 |
|---|---|---|
| 갱신 | 문서 행 갱신·재임베딩 | 데이터 준비·재학습·재평가 |
| 출처 | 검색된 문서 ID를 붙임 | 짚을 수 없음 |
| 삭제 | 행 삭제 | 특정 사실만 빼기 어려움 |
| 요청당 비용 | 검색 결과만큼 입력 토큰↑ | 짧은 프롬프트 가능, 학습·호스팅 비용 |

- 해석인 항목: "삭제 어려움". 근거는 구조다 — 파인튜닝은 학습 신호를 가중치 전체에 섞고, RAG는 지식이 행 단위로 분리돼 있다.
- 출처 항목의 근거: Lewis 외 RAG 초록이 파라미터 모델의 "출처 제공·지식 갱신"을 열린 문제로 적었다.
- 시간 규모(분~시간 vs 일~주)는 예시다.

### 3. LoRA 순전파

```text
  x ──┬──> W0 (d×k, 동결) ─────────────┐
      └──> A (r×k) ──> B (d×r) ── ×α/r ─(+)──> h = W0x + (α/r)·B·A·x
```

- A: 무작위 가우스로 시작. B: 0으로 시작(Hu 외 4.1절).
- 시작 때 B = 0이므로 BA = 0, 덧셈 항이 0이다. 출력이 원래 모델과 같다. 학습이 진행되며 B가 0에서 벗어난다.

### 4. 파라미터 수

- 식: `|Θ| = 2 × L̂ × d_model × r`(5.1절 — 적용 행렬이 모두 `d_model × d_model`일 때. 일반 `d × k` 행렬 하나는 `r(d+k)`).
- Wq·Wv, r = 4: L̂ = 96 × 2 = 192 → 2 × 192 × 12,288 × 4 = **18,874,368**.
- 한 종류 r = 8: L̂ = 96 → 같은 18,874,368. 네 종류 r = 2: L̂ = 384 → 같은 18,874,368.
- 논문 7.1절 표 5가 "학습 파라미터 18M" 예산에서 r = 8(한 종류)·4(두 종류)·2(네 종류)를 비교했다. 계산이 정확히 맞는다.
- 전체 1,750억 대비 약 9,272배 적다(초록의 "약 1만 배"와 같은 규모).

### 5. 작은 행렬 실험

- (a) B = 0: 최대 차이 0.0. (b) 병합 전후: 2.22e-16(float64 반올림 수준). (c) rank(BA) = 4 = r.
- 이점: 병합하면 원래 층과 같은 모양의 행렬 하나라 추론 지연이 늘지 않는다. BA를 빼면 W0로 돌아와(차이 5.55e-17) 베이스 하나에 어댑터를 갈아 끼울 수 있다.
- 한계: 병합해 버리면 서로 다른 어댑터를 쓰는 요청을 한 배치로 묶기 어렵다. 병합하지 않고 요청마다 어댑터를 고르면 가능하지만 연산이 더 든다(4.2절).

### 6. QLoRA

- 더한 것: 베이스 모델을 **4비트로 양자화해 동결**하고 그 위에서 LoRA 어댑터를 학습한다. 장치는 NF4 데이터형·이중 양자화·페이지드 옵티마이저.
- 규모(초록): 65B 모델을 48GB GPU 한 장에서 미세조정, 16비트 전체 미세조정 성능 유지.

### 7. 옛 가격

- 원인: 자주 바뀌는 사실을 가중치에 넣었다. 갱신하려면 재학습이 필요하고, 그동안 옛 사실이 나온다. 출처가 없어 어디서 나온 숫자인지도 추적이 안 된다.
- 대처: 가격·정책은 RAG로 옮겨 문서 갱신만으로 반영되게 하고, 답에 출처 문서 ID를 붙인다. 파인튜닝은 잘 안 바뀌는 행동에만 쓴다. 평가셋에 "최신 사실" 항목을 두어 개정 뒤 회귀를 잡는다.

### 8. 베이스 교체 뒤 어댑터

- 어댑터는 특정 W0에 대한 차이 ΔW다. 새 베이스 W0′에 같은 ΔW를 더하면 학습한 적 없는 가중치가 된다. 모양이 다르면 로드부터 실패하고, 모양이 같으면 조용히 품질이 떨어질 수 있다.
- 막는 법: 어댑터 메타데이터에 베이스 모델 ID·가중치 해시를 넣고, 배포 때 배포 대상과 대조한다(Java `checkCompatible` → `DENY ... retrain and re-evaluate`). 평가 보고서가 없는 어댑터도 막는다.

### 9. 파인튜닝 전에

- 갖출 것: 목표 작업 + 지켜야 할 기존 능력을 담은 평가셋, 프롬프트 기준선, 학습 데이터(개인정보 정리 포함), 그 작업이 오래 쓰일 것이라는 판단.
- 순서: 평가셋 → 프롬프트 기준선 → 실패를 지식/행동으로 분류 → 지식은 RAG, 행동은 구조화 출력·예시 → 행동 실패가 남으면 파인튜닝.
- 판정: 베이스와 같은 평가셋에서 점수 차이와 신뢰구간([data-analysis/08](../../data-analysis/08-confidence-intervals/2-summary.md))으로 개선·회귀를 판정한다. 평가 보고서를 배포 조건으로 둔다.
