# ai-engineering/05-embeddings-and-similarity — 정답

## 정답

### 1. 임베딩으로 얻는 것과 잃는 것

- 얻는 것: 문장마다 모델을 한 번만 돌린다. 비교는 벡터 연산이다.
  - Sentence-BERT 초록: 1만 문장에서 가장 비슷한 쌍을 BERT(쌍마다 함께 입력)로 찾으면 약 5천만 번 추론, 약 65시간. SBERT 임베딩으로는 약 5초.
- 잃는 것: 질의와 문서가 서로를 보지 못한 채 각각 고정 길이로 압축된다. 미세한 차이(부정·조건)는 놓칠 수 있다. 크로스-인코더 재순위([17번](../17-hybrid-search-and-reranking/2-summary.md))가 이를 보완한다.

### 2. 바이-인코더 흐름

```text
  미리:     문서 N개 ──[모델]──> 벡터 N개 저장 (모델 호출 N번, 한 번만)
  요청마다: 질의 1개 ──[같은 모델]──> 벡터 1개 ──> 저장된 N개와 유사도 → top-k (모델 호출 1번)
```

- 요청 시간은 질의 임베딩 1회 + 벡터 탐색이다. 문서 수가 늘면 탐색 비용이 늘고, 그때 ANN을 쓴다.

### 3. 세 기준이 같아지는 조건

- 조건: 모든 벡터의 길이가 1(정규화)일 때. 그러면 내적 = 코사인, `|u−w|² = 2 − 2cos θ`([math/13](../../math/13-linear-algebra-essentials/2-summary.md)).
- 깨지는 경우
  1. 정규화되지 않은 벡터에 내적 → 노름이 큰 벡터가 위로.
  2. 차원을 잘라 길이가 1보다 작아졌는데 재정규화 없이 내적.
  3. 다른 모델의 벡터를 섞음 — 이건 기준 선택과 무관하게 거리 자체가 무의미하다.

### 4. 절반 혼합의 결과

- recall@10 1.00 → 0.52. 1위 점수 평균 0.693 → 0.677.
- 오류는 없고, 점수 분포도 거의 그대로다. 정답의 절반 가까이가 옛 공간에 있어 새 질의와 무관한 점수를 받으니 상위에 못 들었다.
- 교훈: "평균 유사도 점수"나 "결과 수" 같은 표면 지표로는 공간 혼합을 못 잡는다. 정답을 아는 고정 질의셋의 recall@k를 재야 한다. 그리고 애초에 모델 열로 섞이지 않게 막는다.

### 5. 차원 절단

- 재정규화 없이 내적: 평균 6.8/10 겹침. 재정규화 후 내적: 10.0/10.
- 자른 벡터의 길이가 0.46~0.89로 제각각이라, 내적이 길이를 점수에 곱했다.
- 코사인 식은 두 벡터의 길이로 나누므로 길이와 무관하다. 문제는 "길이가 1이니 내적이 곧 코사인"이라는 가정으로 내적 연산자(속도 때문에 흔히 고른다)를 쓸 때 생긴다.

### 6. `<#>`와 차원 검사

- `<#>`는 **음의** 내적이다. PostgreSQL 인덱스 스캔이 오름차순만 지원해서 "작을수록 비슷"하게 만들었다(pgvector README). `DESC`로 정렬하면 가장 덜 비슷한 것부터 나온다. 오름차순으로 바꾸고 점수는 `* -1`로 보인다.
- 차원이 다르면: `ERROR: expected 3 dimensions, not 2`로 거부(실험).
- 차원이 같은 다른 모델 벡터: 아무 오류 없이 들어가고 계산된다. 막을 수 있는 것은 앱이 둔 모델 열과 질의 필터뿐이다.

### 7. 교체에 안전한 설계

- 테이블: `(doc_id, model)`을 기본 키로, `model`에 이름·버전·차원(필요하면 정규화 여부)까지 넣는다. 교체 기간에는 문서마다 두 모델의 행이 공존한다.
- 인덱스: 모델마다 부분 인덱스 `WHERE model = '...'` + 표현식 `(embedding::vector(1024))`. 같은 차원끼리만 색인할 수 있기 때문이다.
- 질의: `WHERE model = :현재모델`로 거른 뒤 같은 표현식으로 정렬한다.
- 전환: 새 모델 벡터를 모두 채우고 recall 게이트를 통과하면 "현재 모델" 설정을 한 번에 바꾼다. 옛 행은 롤백 기간 뒤 지운다.
- pgvector README의 FAQ "Can I store vectors with different dimensions in the same column?"이 `model_id` 열 + 표현식·부분 인덱스로 같은 모양을 보인다.

### 8. 힙과 ANN

- 전수 탐색: 모든 벡터와 점수를 계산하면서 크기 k의 힙에 상위 k만 남긴다. 루트에는 남긴 k개 중 가장 나쁜 후보가 와야 한다 — 유사도(클수록 좋음)면 최소 힙, 거리(작을수록 좋음)면 최대 힙. O(N·d + N log k).
- N이 커져 요청당 지연·CPU가 감당 안 되면 ANN 색인(HNSW·IVFFlat)으로 넘어간다.
- 달라지는 것: 결과가 근사가 된다(정확 탐색과 다를 수 있음). 필터를 인덱스 스캔 뒤에 적용하는 등 동작이 바뀐다. 그래서 recall@k를 다시 재야 한다([16번](../16-vector-index-ann/2-summary.md)).
