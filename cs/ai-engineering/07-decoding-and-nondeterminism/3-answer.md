# ai-engineering/07-decoding-and-nondeterminism — 정답

## 정답

### 1. 디코딩 규칙이 따로 있는 이유

- 모델은 한 단계에 어휘 전체에 대한 점수(로짓)만 낸다. 그중 하나를 고르는 것은 모델 밖 규칙이다. 고른 토큰이 다음 단계 입력이 된다.
- greedy만: 늘 최댓값을 고르므로 같은 로짓에서 같은 결과지만, 개방형 글 생성에서는 글이 밋밋하고 반복되기 쉽다(Holtzman 외 초록 — §2.2는 번역·요약처럼 입력이 출력을 좁히는 작업에서는 덜 문제라고 구분).
- 순수 샘플링만: 다양하지만 확률 낮은 꼬리의 엉뚱한 토큰도 뽑힌다. 출력이 길수록 그 확률이 쌓인다.

### 2. 파이프라인과 top-k vs top-p

```text
  로짓 z ─①exp(z/T) 정규화─> 확률 p ─②절단─> 남은 것 ─③재정규화─> p' ─④u~U[0,1) 역CDF─> 토큰
```

- top-k: 늘 상위 k개를 남긴다. 분포 모양과 무관하다.
- top-p: 확률 순 누적이 p 이상이 되는 최소 집합만 남긴다. 뾰족한 분포면 적게, 평평한 분포면 많이 남긴다(Holtzman 식 2).

### 3. top-p 계산

- 0.9: 누적 .382 → .606 → .790 → .891 → .943. 처음 ≥ 0.9가 5번째 → **5개**.
- 0.5: 1위 .498 < 0.5이므로 2위까지 → **2개**(누적 .722). 실험에서 T=1.0, top-p 0.5가 200·OK 두 토큰만 낸 이유다.

### 4. 설정별 빈도 (seed 7, 1만 회)

- T = 0.2: 1위 9,782회(97.8%), 꼬리 2개 0%.
- T = 1.5: 1위 3,880회(38.8%), 꼬리 2개 2.02%(바나나 135, #$% 67).
- T = 1.5 + top-p 0.9: fine·바나나·#$% 0회. 남은 5개만 나온다.
- 로짓은 같은데 손잡이만으로 출력 분포가 이만큼 달라진다.

### 5. temperature 0 ≠ 결정적

- 흔한 설명: GPU에서 부동소수 덧셈 순서가 어느 코어가 먼저 끝나느냐에 따라 달라진다("동시성 + 부동소수"). 글은 이것이 전부가 아니라고 한다. 같은 행렬곱을 반복하면 비트까지 같다.
- 실제 원인: **배치 불변성 부재**. 커널이 배치 크기에 따라 리덕션 분할 전략을 바꾸고, 배치 크기는 다른 사용자 부하가 정한다. 그래서 내 요청의 로짓이 마지막 자리에서 흔들린다.
- 숫자: Qwen3-235B, temperature 0, 1,000회 → 서로 다른 완성 80개(최빈 78회). 102토큰까지 같고 103번째에서 갈림(992 vs 8). 배치 불변 커널을 켜면 1,000개 동일.
- Anthropic API 문서도 "temperature 0.0이어도 완전히 결정적이지 않다"고 적는다(2026-10-08 확인).

### 6. 리덕션 분할 실험

- 같지 않다. 2,000쌍 중 1,906쌍(95%)에서 로짓 값이 달라졌다.
- 거의 동점이던 4쌍은 greedy 1위가 뒤집혔다.
- 결합법칙이 없는 부동소수 덧셈에서 묶음이 바뀌면 반올림 위치가 바뀐다([math/15](../../math/15-numerical-stability/2-summary.md)). 실제 생성에서는 한 단계의 1위가 바뀌면 그 뒤 전체가 갈라진다.

### 7. 스냅샷 테스트 간헐 실패

- 원인: temperature 0이어도 서버 배치 구성에 따라 로짓이 흔들려 출력이 달라진다. 실패 비율이 부하에 따라 달라지는 것도 이 때문이다.
- 대처
  - 단위 테스트는 외부 호출을 녹화된 응답으로 바꾼다.
  - 실제 모델을 부르는 테스트는 문자열 대신 계약(스키마·필수 사실·금지 패턴)을 검사한다(Java `satisfiesContract` 예: 3개 표현 모두 통과, `equals`는 1개만).
  - 품질은 평가셋 점수 분포로 본다([19번](../19-llm-evaluation/2-summary.md)).

### 8. 새 모델에서 400

- Anthropic Messages API에서 Opus 4.6보다 뒤에 출시된 모델은 temperature 1.0 외 값, top_p 0.99 미만, top_k를 400으로 거부한다(2026-10-08 확인, deprecated 표시).
- 재시도로 안 낫는다. 400은 요청 자체가 잘못됐다는 뜻이다. 모델별 파라미터 호환표를 두고, 모델 교체 시 계약 테스트로 확인한다.

### 9. 출력 문자열 캐시 키

- 출력은 샘플링과 배치 불변성 부재로 같은 입력에도 바뀐다. 출력 기반 키는 같은 입력을 매번 새 항목으로 만든다.
- 키는 입력 쪽: 모델·프롬프트 버전·파라미터·입력 해시. 첫 출력을 값으로 저장한다(`generateOnce`: 3번 불러도 LLM 호출 1번).
- 뜻이 같은 출력·질문의 중복은 임베딩 유사도로 판정한다([05번](../05-embeddings-and-similarity/2-summary.md)). 그 위험(오적중)은 [12번](../12-prompt-and-semantic-caching/2-summary.md) 의미 캐시에서 다룬다.
