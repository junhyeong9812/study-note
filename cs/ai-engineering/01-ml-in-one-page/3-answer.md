# ai-engineering/01-ml-in-one-page — 정답

## 정답

### 1. 학습 손실과 일반화 오류

- 학습 손실은 이미 본 데이터에서의 값이다. 용량이 큰 모델은 학습 데이터를 외워 학습 손실을 0 가까이 만들 수 있다(실험 B의 k=1 학습 정확도 1.000).
- 줄이고 싶은 양은 *일반화 오류*다. 앞으로 만날 입력 분포에서 오류의 기댓값이다(Goodfellow 외 5.2).
- 일반화 오류는 직접 볼 수 없어 학습과 따로 모은 시험셋으로 추정한다.

### 2. 세 갈래의 쓰임과 검증 오류의 과소 추정

- 학습셋: 파라미터 θ를 맞춘다.
- 검증셋(devset): 하이퍼파라미터·후보를 고른다. 여러 번 봐도 된다.
- 시험셋: 모든 선택이 끝난 뒤 한 번 잰다. 어떤 선택에도 쓰지 않는다(Goodfellow 외 5.3, SLP3 3.2).
- 과소 추정 이유: 검증셋 점수를 보고 하이퍼파라미터를 골랐으니 검증셋에 맞춘 셈이다. Goodfellow 외 5.3은 이를 검증셋으로 하이퍼파라미터를 "학습"시킨다고 표현한다. 다만 학습 오류보다는 덜 과소 추정한다.

### 3. 후보 50개 중 1등

- 높다. 실험 A(반복 2000, seed 1)에서 1등의 검증 정확도 평균은 0.772(5~95% 0.750~0.795)였다.
- 같은 후보를 새 시험 200건으로 재면 평균 0.700(5~95% 0.645~0.750)으로 참값에 돌아온다.
- 이유: 50개 모두 실력은 같고 검증 점수의 차이는 잡음이다. 최댓값을 고르면 잡음이 위로 튄 후보를 고르게 된다.

### 4. 행 분할 vs 고객 분할의 1-NN

- 행 분할: 시험 정확도 1.000. 시험 고객 196명 전원이 학습에도 있었다. 이것이 누설의 근거다. 1.000은 처음 보는 고객에게 기대할 수 있는 최고 정확도 0.75를 시험 300행의 우연 변동으로는 설명할 수 없을 만큼 넘어 그 결과를 드러낸다(0.75는 기댓값이라 유한한 시험셋에서 조금 넘는 것만으로는 증거가 아니다).
- 고객 분할: 0.667. 처음 보는 고객에 대한 추정이다.
- 0.75는 라벨 = `X + E > 0`(X, E 독립 표준정규)에서 X의 부호로 맞힐 확률 1/2 + arcsin(1/√2)/π로 계산했다.

### 5. 과소적합·과적합

- 과소적합: 학습셋에서도 오류를 충분히 낮추지 못한다.
- 과적합: 학습 오류와 시험 오류의 간격이 너무 크다(Goodfellow 외 5.2).
- 실험 B 고객 분할 k=1은 학습 1.000, 시험 0.667이다. 간격이 큰 과적합 모양이다.
- k=15로 용량을 줄이면 학습 0.782, 시험 0.660으로 간격이 줄었다. 이 데이터에서는 시험 점수가 오르지는 않았다.

### 6. 오프라인 0.95, 운영 0.7

1. 분할 단위: 같은 고객·문서·대화 ID가 학습셋과 시험셋 모두에 있나? → 누설 경로 ①(같은 개체가 양쪽에). 교집합 키 수를 센다.
2. 선택 과정: 0.95가 후보를 고르는 데 쓴 셋의 점수인가? → 경로 ②(시험셋으로 선택), 실험 A의 낙관 편향.
3. 특징 시점: 예측 시점에 없는 열(결과 뒤에 기록되는 값)이 특징에 있나? → 경로 ③([data-analysis/22](../../data-analysis/22-multiple-and-logistic-regression/3-answer.md)의 누설 변수).
- 시간 분할(과거로 학습, 미래로 시험)로 다시 재는 것도 같은 점검의 일부다.

### 7. 그룹 분할 코드

- 행이 아니라 그룹 키(고객 ID)를 해시해 버킷을 정한다. 같은 키는 같은 버킷 → 같은 갈래.
- 고정할 것: 해시 함수(SHA-256처럼 실행마다 같은 값을 내는 것)와 소금 문자열(`split-v1`). 소금을 바꾸면 분할이 바뀐다.
- 정확히 80/10/10이 아닌 이유: 고객 단위로 버킷이 정해지므로 각 갈래의 고객 수가 이항 분포처럼 흔들린다(실험 B′: 2417·283·300명). 16비트 값을 100으로 나눈 나머지라 버킷 간 아주 작은 치우침도 있다.
- 교집합 0 검사를 파이프라인 단계로 넣는다.

### 8. 평가셋 점수만 오름

- 평가셋 점수를 보고 프롬프트를 고치는 일을 반복해 평가셋에 암묵적으로 맞췄다. 그 셋은 사실상 검증셋이 되었다(SLP3 3.2, Goodfellow 외 5.3의 벤치마크 노후화).
- 막는 법: 개발용 셋과 배포 판정용 시험셋을 나누고, 판정용 셋은 드물게 돌린다. 주기적으로 운영 입력에서 새 표본을 뽑아 시험셋을 갱신한다.

### 9. 벤치마크 순위와 사내 품질

- 데이터 오염: 벤치마크 문항이 학습 말뭉치에 섞이면 벤치마크 점수가 부풀려진다(SLP3 3.2 data contamination).
- 분포 차이: 시험셋은 실제로 만날 입력과 같은 분포여야 일반화 오류의 추정이 된다(Goodfellow 외 5.2). 벤치마크 분포는 우리 입력 분포와 다르다.
- 그래서 우리 입력에서 뽑은 평가셋으로 짝지어 비교한다(같은 영역 [19편](../19-llm-evaluation/2-summary.md)).
