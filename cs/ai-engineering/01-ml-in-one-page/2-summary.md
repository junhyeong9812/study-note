# ai-engineering/01-ml-in-one-page — 학습 한 장 요약: 손실 최소화·데이터 분할·과적합·누설 — 정리 (힌트)

## 해결하는 문제

모델 카드에 "정확도 92%", 사내 파인튜닝 보고서에 "검증 점수 0.95"가 적혀 있다. 백엔드 개발자는 이 숫자를 믿고 모델을 바꾸거나 배포를 승인한다.
그런데 숫자만으로는 **어떤 데이터에서, 몇 번 고른 뒤에** 잰 값인지 모른다.

```text
  같은 "0.95"라도
  ┌───────────────────────────┬──────────────────────────────────────┐
  │ 학습에 쓴 데이터에서 잰 값   │ 외운 것을 다시 맞힌 점수 — 거의 정보 없음 │
  │ 검증셋으로 50번 고른 뒤 그 셋 │ 고르는 과정이 점수를 부풀린다(실험 A)     │
  │ 한 번도 안 본 시험셋          │ 운영 성능의 추정치에 가장 가깝다          │
  └───────────────────────────┴──────────────────────────────────────┘
```

쉬운 예: 기출문제 유출.
- 학생이 시험 문제를 미리 봤다면 점수는 높지만 실력을 말해 주지 않는다.
- 모의고사를 스무 번 보고 가장 잘 나온 회차 점수를 성적표에 적어도 실력보다 높게 나온다.

똑같은 구조다.\
학습 데이터 = 연습문제, 시험셋 = 본시험, 누설 = 문제 유출, 검증셋 재사용 = 가장 잘 나온 모의고사 고르기.

실무 예:
- 고객 문의 분류 모델이 오프라인 정확도는 높았는데 운영에서 크게 낮다. 같은 고객의 비슷한 문의가 학습·시험에 나뉘어 들어가 있었다(실험 B).
- 프롬프트·설정 후보 여러 개를 같은 평가셋으로 비교해 1등을 골랐다. 그 1등의 점수를 그대로 "예상 품질"로 보고했다(실험 A).
- 공개 벤치마크 문제가 학습 말뭉치에 섞여 있으면 벤치마크 점수가 부풀려진다. SLP3는 시험 문장이 학습 말뭉치에 들어간 상황을 "training on the test set" 또는 *data contamination*이라 부르고, 확률이 모두 너무 높게 나오는 편향을 만든다고 쓴다(SLP3 2026-08-19판 3.2 — 언어 모델 평가 맥락).

## 동작·원리

### 1. 학습 = 손실을 줄이는 반복

```text
        ┌──────────── 파라미터 θ 갱신 ◀──────────────┐
        ▼                                            │
  입력 x ──▶ 모델 f(x; θ) ──▶ 예측 ŷ ──▶ 손실 L(ŷ, y) ──▶ 기울기 ∂L/∂θ
                                          ▲
                                       정답 y
  반복이 끝나면 θ가 고정된다 → 이 θ로 새 입력을 예측한다(추론)
```

- *파라미터(parameter)*: 학습이 바꾸는 값(가중치). LLM에서는 수십억 개 이상이다(예: LLaMA 논문 초록의 7B~65B, arXiv 2302.13971).
- *손실(loss)*: 예측이 정답에서 얼마나 먼지를 하나의 수로 낸 것. 분류·언어 모델에서는 대개 교차 엔트로피다([03](../03-cross-entropy-and-perplexity/2-summary.md)).
- *하이퍼파라미터(hyperparameter)*: 학습이 직접 바꾸지 않고 사람이(또는 탐색이) 정하는 값. 학습률, 모델 크기, k-NN의 k 등.
- 기울기를 따라 θ를 옮기는 방법(경사 하강)은 [data-analysis/22](../../data-analysis/22-multiple-and-logistic-regression/2-summary.md) 4절이 단일 출처다. 기울기를 계산하는 법(역전파)은 [02](../02-gradient-descent-and-backprop/2-summary.md).
- 핵심 어긋남: 학습은 **학습 데이터의 손실**을 줄인다. 우리가 원하는 것은 **새 입력에서의 오류**(일반화 오류)가 작은 것이다(Goodfellow 외 5.2).
  - *일반화 오류(generalization error)*: 앞으로 만날 입력 분포에서 오류의 기댓값. 학습과 따로 모은 시험셋으로 추정한다(Goodfellow 외 5.2).

### 2. 세 갈래 분할 — 무엇을 어디에 쓰나

```text
  전체 데이터
  ├── 학습(train)      θ를 맞춘다                       ← 손실을 줄이는 대상
  ├── 검증(validation, dev) 하이퍼파라미터·후보를 고른다   ← 여러 번 봐도 된다, 대신 점수가 낙관적
  └── 시험(test)        마지막에 한 번 잰다               ← 어떤 선택에도 쓰지 않는다
```

- Goodfellow 외 5.3: 시험 예제는 하이퍼파라미터를 포함해 **모델에 관한 어떤 선택에도** 쓰지 않는다. 그래서 검증셋은 학습 데이터에서 떼어 만든다. 흔히 학습 데이터의 약 80%로 학습하고 20%를 검증에 쓴다.
- 같은 절: 검증셋은 하이퍼파라미터를 "학습"시키는 데 쓰였으므로 **검증 오류는 일반화 오류를 과소 추정한다**(학습 오류보다는 덜).
- SLP3 3.2: 시험셋을 여러 번 돌려 보며 바꾸면 암묵적으로 시험셋에 맞추게 된다. 그래서 개발은 devset에서 하고 시험셋은 마지막에 한 번(또는 아주 적게) 돌린다.
- 데이터가 적으면 k-겹 교차 검증을 쓴다. 다만 전체를 시험에 쓰는 셈이라 데이터를 들여다보며 설계하면 "peeking"이 된다. SLP3 4.10은 고정 시험셋을 떼어 두고 학습셋 안에서 교차 검증하는 방식을 보인다.
  - *k-겹 교차 검증(k-fold cross-validation)*: 데이터를 k조각으로 나눠 한 조각씩 돌아가며 평가하고 평균한다.

### 실험: 검증 점수 1등을 고르면 점수가 부풀려진다 (실험 A)

참 정확도가 **모두 0.70**인 후보 50개(예제마다 독립적으로 70% 확률로 맞히는 모형)를 검증 200건으로 비교해 1등을 고른다. 고른 후보를 새 시험 200건으로 다시 잰다.

```python
# scratchpad ai/01/e01/split_leak.py 핵심
vals = [sum(rng.random() < 0.70 for _ in range(200)) / 200 for _ in range(50)]
i = max(range(50), key=lambda j: vals[j])                 # 검증 1등
test = sum(rng.random() < 0.70 for _ in range(200)) / 200 # 같은 후보, 새 데이터
```

(실험, Python 3.12.14 python:3.12-slim 컨테이너, 2026-10-08 — 반복 2000, seed 1)

```text
[A] 후보 50개, 참 정확도 모두 0.7, 검증 200·시험 200, 반복 2000, seed 1
    고른 후보의 검증 정확도: 평균 0.772  (5~95% 0.750~0.795)
    같은 후보의 시험 정확도: 평균 0.700  (5~95% 0.645~0.750)
```

- 관찰: 후보는 모두 똑같이 0.70인데, 1등의 검증 점수는 평균 0.772다. 새 데이터에서는 0.700으로 돌아온다.
- 해석: "가장 높은 값을 고른다"는 행위가 검증 잡음 중 운 좋은 쪽을 고른다. 후보가 많고 검증셋이 작을수록 이 차이가 커진다. 평가셋 크기와 신뢰구간은 [data-analysis/08](../../data-analysis/08-confidence-intervals/2-summary.md), 여러 후보 비교의 함정은 [data-analysis/11](../../data-analysis/11-multiple-comparisons/2-summary.md).
- 이 모형은 후보끼리 독립이라고 가정했다. 실제 후보(비슷한 프롬프트 변형)는 서로 상관이 있어 부풀림 크기가 다를 수 있다(해석).

### 3. 과적합과 과소적합 — 학습 오류와 시험 오류의 간격

```text
  용량(모델이 외울 수 있는 정도) →  작음 ─────────── 적당 ─────────── 큼
  학습 오류                         높음             낮음             거의 0
  시험(일반화) 오류                 높음             가장 낮음        다시 높아짐
  간격(시험 − 학습)                 작음             중간             큼
  상태                              과소적합                          과적합
                                    (Goodfellow 외 그림 5.3을 표로 옮긴 것)
```

- Goodfellow 외 5.2: *과소적합(underfitting)* = 학습셋에서도 오류를 충분히 낮추지 못함. *과적합(overfitting)* = 학습 오류와 시험 오류의 간격이 너무 큼.
- *용량(capacity)*: 모델이 맞출 수 있는 함수의 폭. k-NN에서는 k가 작을수록 용량이 크다(k=1은 학습 데이터를 그대로 외운다).
- SLP3 4.14: 특정 특징이 우연히 한 클래스에만 나오면 큰 가중치를 받아 학습 데이터의 잡음까지 맞춘다. 이를 막는 방법 하나가 정규화 항이다.

### 4. 누설 — 시험셋이 학습 쪽 정보를 미리 본다

```text
  경로 ①  같은 개체가 양쪽에         고객 A의 기록 5건 → 무작위 행 분할 → 학습 3건 · 시험 2건
  경로 ②  시험셋으로 선택            후보 비교·조기 종료·프롬프트 수정을 시험셋 점수로 → 시험셋이 검증셋이 됨
  경로 ③  예측 시점에 없는 특징      결과가 정해진 뒤 기록되는 열 → data-analysis/22 5절
  경로 ④  공개 벤치마크가 학습 말뭉치에  벤치마크 문항 자체를 학습 → 점수가 부풀려짐 (SLP3 3.2)
```

- *데이터 누설(data leakage)*: 학습·선택 과정이 시험셋 정보(또는 예측 시점에 없는 정보)를 보는 것.
- 결과는 같다. 오프라인 점수가 높고 운영에서 떨어진다.
- 경로 ③(누설 변수)은 [data-analysis/22](../../data-analysis/22-multiple-and-logistic-regression/2-summary.md) 5절이 단일 출처다. 여기서는 ①·②를 실험으로 보인다.
- 경로 ②의 확대판: Goodfellow 외 5.3은 같은 시험셋을 여러 해 반복해 여러 알고리즘 평가에 쓰면 시험셋 평가도 낙관적이 되어 벤치마크가 낡는다(stale)고 쓴다. 문항이 학습 말뭉치에 들어가는 경로 ④와는 다른 경로다.

### 실험: 같은 고객이 양쪽에 — 행 분할 vs 고객 분할 (실험 B)

고객 300명 × 기록 5건(합성). 같은 고객의 기록은 특징이 거의 같고 라벨도 같다. 라벨은 `첫 특징 + N(0,1) 잡음 > 0`이라 **처음 보는 고객에게 특징으로 기대할 수 있는 최고 정확도(기댓값)는 0.75**다(= 1 − 베이즈 오류, 베이즈 오류는 Goodfellow 외 5.2. 계산: 두 독립 표준정규 X, E에서 P(sign X = sign(X+E)) = 1/2 + arcsin(1/√2)/π = 0.75).

```python
# 무작위 행 분할 vs 고객(그룹) 단위 분할, k-NN 다수결
r = rows[:]; rng.shuffle(r); tr_row, te_row = r[:1200], r[1200:]
gs = list(range(300)); rng.shuffle(gs); tg = set(gs[:240])
tr_grp = [x for x in rows if x[0] in tg]; te_grp = [x for x in rows if x[0] not in tg]
```

(실험, Python 3.12.14 python:3.12-slim 컨테이너, 2026-10-08 — seed 7)

```text
[B] 고객 300명 × 기록 5건 = 1500행, 특징 8차원, seed 7
    무작위 행 분할: 시험 300행의 고객 중 학습에도 있는 고객 196/196
    분할           k      학습 정확도      시험 정확도
    행 무작위        1       1.000       1.000
    행 무작위       15       0.785       0.757
    고객 단위        1       1.000       0.667
    고객 단위       15       0.782       0.660
```

- 관찰 1: 무작위 행 분할에서는 시험 고객 196명 **전원**이 학습에도 있었다. 1-NN은 시험 정확도 1.000을 냈다. 기댓값 0.75는 유한한 시험셋에서 우연히 조금 넘을 수 있지만, 시험 300행에서 1.000은 우연 변동으로 설명되는 폭이 아니다(해석). 일반화가 아니라 같은 고객의 다른 기록을 찾아낸 것이다.
- 관찰 2: 고객 단위로 나누면 같은 1-NN이 0.667로 떨어진다. 이쪽이 처음 보는 고객에 대한 추정이다.
- 관찰 3: k=1은 두 분할 모두 학습 정확도 1.000이다. 고객 분할에서 학습 1.000 vs 시험 0.667의 간격이 과적합의 모양이다(3절).
- 관찰 4: k=15도 행 분할(0.757)이 고객 분할(0.660)보다 높다. 이웃 15개 중 같은 고객 기록 최대 4개가 표를 던지기 때문이다(해석).

## 적용 — 풀어나가는 법

### 1. 모델 품질 숫자를 받았을 때 — 증상 → 원리 → 확인

1. **증상**: "검증 0.95인데 운영에서 0.7", 또는 숫자 하나만 적힌 보고.
2. **원리**: 그 숫자가 어느 갈래(학습·검증·시험)에서, 몇 번의 선택 뒤에, 어떤 단위의 분할로 잰 값인지에 따라 뜻이 다르다.
3. **확인 질문**

| 질문 | 위험 신호 | 근거 |
|---|---|---|
| 어느 셋에서 쟀나? | 학습셋 점수, 또는 고르는 데 쓴 검증셋 점수 | 2절, 실험 A |
| 후보를 몇 개 비교했나? | 많은 후보 중 1등의 점수 그대로 | 실험 A |
| 분할 단위는? | 같은 사용자·문서·대화가 양쪽에 | 실험 B |
| 시간 순서는? | 미래 데이터로 학습, 과거로 시험 | [data-analysis/22](../../data-analysis/22-multiple-and-logistic-regression/2-summary.md) 적용 2절 |
| 시험셋 크기는? | 100건 정도로 1~2%p 차이를 주장 | [data-analysis/08](../../data-analysis/08-confidence-intervals/2-summary.md) |
| 공개 벤치마크인가? | 학습 말뭉치에 섞였을 가능성(오염) | SLP3 3.2 |

### 2. 분할 코드 — 그룹 키로 결정적 분할 (Java 21)

같은 고객의 기록이 한쪽에만 가도록 **행이 아니라 고객 키**를 해시한다. 소금(salt) 문자열을 바꾸지 않으면 재실행해도 같은 분할이다.

```java
// scratchpad ai/01/e01/GroupSplit.java 핵심
static Part partOf(String groupKey, String salt) throws Exception {
    byte[] h = MessageDigest.getInstance("SHA-256")
            .digest((salt + ":" + groupKey).getBytes(StandardCharsets.UTF_8));
    int bucket = Math.floorMod(((h[0] & 0xff) << 8) | (h[1] & 0xff), 100); // 0..99
    return bucket < 80 ? Part.TRAIN : bucket < 90 ? Part.VALID : Part.TEST;
}
```

(실험, JDK 21.0.12 eclipse-temurin:21-jdk 컨테이너, 2026-10-08 — 합성 고객 3000명 × 5건)

```text
TRAIN 고객 2417명  행 12085
VALID 고객  283명  행  1415
TEST  고객  300명  행  1500
TRAIN∩TEST 고객 수 = 0
재실행 같은 결과? true
```

- 비율은 80/10/10에 가깝지만 정확히 맞지는 않는다. 해시 버킷이 고객 단위라 고객 수의 우연 변동을 따른다.
- 16비트 값을 100으로 나눈 나머지라 버킷마다 아주 작은 치우침이 있다(65536 = 655×100 + 36). 정확한 비율이 중요하면 더 많은 비트를 쓴다.
- 희귀 라벨 비율까지 맞추려면 "그룹은 한 갈래에만"을 제약으로 지키면서 라벨 비율을 가능한 만큼 맞춘다. 한 그룹 안에 라벨이 섞여 있으면 라벨마다 따로 나누는 방식은 같은 그룹을 두 갈래로 찢는다(scikit-learn `StratifiedGroupKFold` 문서: 그룹 비중복 제약 아래에서 클래스 비율을 "as much as possible" 보존, 2026-10-08 확인). 층화는 [data-analysis/02](../../data-analysis/02-sampling-and-bias/2-summary.md).

### 3. LLM을 쓰는 서비스에서

- 제공자의 벤치마크 점수는 "그 벤치마크에서"의 값이다. 우리 작업의 품질은 우리 평가셋으로 잰다. 평가셋 설계·판정자·회귀 게이트는 같은 영역의 [19편](../19-llm-evaluation/2-summary.md)(llm-evaluation)에서 다룬다.
- 프롬프트를 고칠 때 보는 셋(검증)과 배포 판정용 셋(시험)을 나눈다. 판정용 셋으로 프롬프트를 고치기 시작하면 그 셋은 검증셋이 된다(2절, 경로 ②).
- 파인튜닝 데이터와 평가 데이터 사이에 같은 문서·대화·고객이 겹치지 않게 그룹 분할한다(실험 B).

## 장애 시나리오와 대처

### 1. 평가 데이터가 학습·튜닝에 섞임 → 오프라인 점수는 높은데 운영에서 급락 (⚠ 커리큘럼)

- 현상: 오프라인 정확도 0.95로 배포했는데 운영 지표가 크게 낮다.
- 보이는 형태: 실험 B처럼 처음 보는 입력에서 기대할 수 있는 최고 정확도(0.75)를 우연으로 볼 수 없을 만큼 넘는 시험 점수(1.000). 같은 사용자·문서 ID가 학습셋과 시험셋에 모두 있다.
- 원인: 무작위 행 분할로 같은 개체의 기록이 양쪽에 들어갔다(누설 경로 ①). 또는 결과 뒤에 생기는 열을 특징에 넣었다(경로 ③).
- 대처: 개체 키로 그룹 분할한다(적용 2). 학습셋과 시험셋의 키 교집합이 0인지 검사를 파이프라인에 넣는다. 특징 열마다 생성 시각을 확인한다([data-analysis/22](../../data-analysis/22-multiple-and-logistic-regression/2-summary.md)).

### 2. 검증셋으로 고른 뒤 같은 셋의 점수를 최종 성능으로 보고 → 낙관 편향 (⚠ 커리큘럼)

- 현상: 후보 50개 중 검증 1등(0.772)을 "예상 정확도"로 공지했다. 새 데이터에서는 0.700이다(실험 A).
- 보이는 형태: 배포 후 지표가 보고치보다 일관되게 낮다. 보고 문서에 "검증셋 최고 점수"만 있다.
- 원인: 최댓값 선택이 검증 잡음 중 운 좋은 쪽을 고른다. Goodfellow 외 5.3: 검증 오류는 일반화 오류를 과소 추정한다.
- 대처: 선택에 쓰지 않은 시험셋으로 한 번 다시 잰다. 후보 수와 셋 크기를 보고서에 함께 적는다.

### 3. 학습 정확도를 성능으로 보고 → 과적합을 놓침

- 현상: 학습 정확도 1.000을 보고했는데 새 고객에게서는 0.667이다(실험 B, 고객 단위 k=1).
- 보이는 형태: 학습 점수와 시험 점수의 큰 간격.
- 원인: 용량이 큰 모델은 학습 데이터를 외울 수 있다. 학습 오류는 일반화 오류의 추정치가 아니다(Goodfellow 외 5.2).
- 대처: 학습·시험 점수를 함께 보고한다. 간격이 크면 용량을 줄이거나(k를 키우기·정규화) 데이터를 늘린다.

### 4. 시험셋을 반복해서 보며 개선 → 시험셋이 낡는다

- 현상: 몇 달 동안 같은 평가셋 점수가 꾸준히 올랐는데 사용자 체감 품질은 그대로다.
- 보이는 형태: 평가셋 점수 상승과 운영 지표·사용자 피드백의 괴리.
- 원인: 시험셋 점수를 보고 결정을 반복하면 시험셋에 암묵적으로 맞춘다(SLP3 3.2, Goodfellow 외 5.3의 벤치마크 노후화).
- 대처: 판정용 시험셋은 접근을 제한하고 드물게 돌린다. 주기적으로 새 표본을 모아 시험셋을 갱신한다.

### 5. 공개 벤치마크 점수로 모델을 고름 → 우리 작업에서 기대 이하

- 현상: 벤치마크 순위가 높은 모델로 바꿨는데 사내 작업 품질이 오르지 않았다.
- 보이는 형태: 사내 평가셋에서 차이가 신뢰구간 안이거나 오히려 낮다.
- 원인: 벤치마크 문항이 학습 말뭉치에 섞였을 수 있다(SLP3 3.2 data contamination). 벤치마크 분포와 우리 입력 분포가 다르다(Goodfellow 외 5.2의 "같은 분포" 전제).
- 대처: 우리 입력에서 뽑은 평가셋으로 짝지어 비교한다([19편](../19-llm-evaluation/2-summary.md)).

## 핵심 문장

- 학습은 학습 데이터의 손실을 줄이고, 우리가 원하는 것은 처음 보는 입력에서의 오류가 작은 것이다 — 그 차이를 재려고 데이터를 나눈다.
- 학습셋은 맞추는 데, 검증셋은 고르는 데, 시험셋은 마지막에 한 번 재는 데 쓴다. 시험셋을 선택에 쓰면 그것은 검증셋이 된다.
- 여러 후보 중 1등의 검증 점수는 부풀려진다(참 0.70인 후보 50개 → 1등 검증 0.772, 시험 0.700).
- 같은 개체가 학습·시험 양쪽에 있으면 시험 점수가 처음 보는 입력에서 기대할 수 있는 최고값(0.75)마저 크게 넘는다(1.000). 분할은 개체 단위로 한다.
- 모델 품질 숫자는 "어느 셋·몇 번 고른 뒤·어떤 분할 단위"와 함께 읽는다.
