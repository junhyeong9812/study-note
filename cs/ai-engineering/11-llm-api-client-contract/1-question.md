# ai-engineering/11-llm-api-client-contract — 질문

## 질문

1. (왜) LLM 스트리밍 호출에서 "HTTP 200이면 성공"이라는 규칙이 왜 틀리나? 200을 받은 뒤 실패가 드러나는 경로 셋을 대라.
2. (그림) 호출 하나의 상태 기계를 그려라. 보냄 → 헤더 → 스트리밍 → 종료 이벤트까지, 각 종료 상태(성공·잘림·거부·스트림 오류·불완전·타임아웃 셋·영구 실패)를 표시하라.
3. (경계) Anthropic Messages API, OpenAI Responses API, OpenAI Chat Completions에서 "출력 한도에 잘렸다"는 신호는 각각 무엇인가? Anthropic의 `model_context_window_exceeded`는 언제 나오나?
4. (예측) 실험 [3]에서 순진한 클라이언트(받은 텍스트를 모두 모아 반환)는 ① 200 뒤 error 이벤트 ② 종료 이벤트 없이 끊김 ③ `stop_reason=max_tokens` 각각을 어떻게 처리하나? 계약 클라이언트는?
5. (예측) 실험 [4]에서 전체 타임아웃 5초 하나와 "첫 토큰 4초 + 이벤트 사이 2초 + 전체 60초"를 slowStart(첫 토큰 3초)·longGen(6초 동안 꾸준히)·stall(10토큰 뒤 10초 멈춤)에 각각 적용하면 결과가 어떻게 되나?
6. (장애 진단) 긴 보고서 생성만 매번 타임아웃되고, 재시도해도 같은 지점에서 끊기며, 비용이 성공 건수에 비해 크게 늘었다. 원인과 대처는? 실험 [5]의 수치로 설명하라.
7. (경계) 429를 받았다. `retry-after`가 있을 때, 없을 때, 오류 type·code가 지출·쿼터 소진일 때 각각 어떻게 하나? Anthropic과 OpenAI 문서는 지출 한도 상황을 어떻게 알려 주나?
8. (장애 진단) 429가 한 번 나기 시작하면 몇 분째 끝나지 않는다. 요청 수는 평소보다 많다. 어떤 문서 문장이 원인을 설명하고, 클라이언트에서 무엇을 바꾸나?
9. (연결) 일반 SSE의 `Last-Event-ID` 이어 받기와, Anthropic 문서가 안내하는 끊긴 스트림 복구는 무엇이 다른가? 처음부터 다시 요청하는 것과 비용 면에서 어떻게 다른가?
10. (연결) JDK `HttpClient`의 요청 `timeout`만으로 첫 토큰·이벤트 사이·전체 타임아웃을 구현할 수 없는 이유는? 실험 클라이언트는 어떻게 구현했나?
