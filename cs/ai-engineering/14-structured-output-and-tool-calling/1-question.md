3. (경계) 스키마를 강제해도 앱이 다시 확인해야 하는 것 다섯 가지를 대라. Anthropic과 OpenAI 문서는 숫자 범위(`minimum`·`maximum`) 지원을 어떻게 다르게 적나(2026-10-08 확인)?
4. (예측) 실험의 모형 응답 중 "필드 누락"·"타입 불일치"·"남의 주문"을 순진한 코드(파싱만, 없는 필드는 0)와 계약 코드가 각각 어떻게 처리하나? 셋 중 스키마 검증으로 막을 수 없는 것은?
5. (왜) 응답 처리에서 중단 사유를 JSON 파싱보다 먼저 봐야 하는 이유는? 잘림과 거부를 같은 "파싱 실패"로 다루면 무엇이 잘못되나?
6. (경계) JSON Schema 2020-12에서 `additionalProperties`를 생략하면 정의 밖 속성은 허용되나? `3000.0`은 `"type": "integer"`에 맞나?

8. (장애 진단) 에이전트가 고객 A의 대화 중에 고객 B의 주문을 취소했다. 도구 인자는 strict 모드로 스키마를 완벽히 따랐다. 어디서 막았어야 하나? 도구 구현에서 확인할 것을 순서대로 적어라.
9. (연결) Anthropic의 `tool_use`/`tool_result`와 OpenAI의 `function_call`/`function_call_output`에서 호출과 결과는 무엇으로 짝을 맞추나? 도구 실행이 실패하면 모델에게 무엇을 돌려주나?
