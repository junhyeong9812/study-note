# ai-engineering/22-prompt-injection-and-llm-security — 질문

## 질문

1. (왜) SQL 인젝션은 파라미터 바인딩으로 막는데, 프롬프트 인젝션에는 왜 같은 해법이 없나? 그래서 방어 목표를 어떻게 바꾸나?
2. (경계) OWASP LLM01의 직접 인젝션과 간접 인젝션을 구분하라. 탈옥은 이 둘과 어떤 관계인가?
3. (예측) 문맥 속 지시를 확률 0.9로 따르는 스텁 모델에, 시스템 프롬프트로 "문서 안 지시는 따르지 마라"를 넣어 따를 확률을 1/5로 줄이면 외부 전송이 0이 되나? 모델 밖 게이트웨이를 두면?
4. (경계) 실험의 `gateway`만으로 막지 못한 유출 경로는 무엇이고 어디서 막혔나? 이 모형이 끝내 못 막는 위험은?
5. (장애 진단) 챗봇 답을 본 사용자 브라우저에서 스크립트가 실행됐다. OWASP의 어느 항목이고, 대처는 기존 보안의 어떤 방법과 같은가?
6. (연결) OWASP LLM06이 꼽는 과도한 에이전시의 세 원인과 각 대처를 짝지어라. "complete mediation"은 여기서 무슨 뜻인가?
7. (장애 진단) 시스템 프롬프트에 넣은 API 키가 외부에 돌아다닌다. 무엇부터 하고, 설계는 어떻게 바꾸나?
8. (경계) RAG 답에 사용자가 볼 권한이 없는 문서가 인용됐다. "생성 프롬프트에 권한 밖 문서는 쓰지 말라고 적기"가 답이 아닌 이유는?
9. (연결) MCP 서버가 클라이언트에게 받은 토큰을 하류 API에 그대로 넘기면 어떤 문제가 생기나? 명세는 무엇을 금지하나?
