# ai-engineering/22-prompt-injection-and-llm-security — 정답

## 정답

### 1. 바인딩이 없는 이유

- SQL은 문법이 코드 자리와 값 자리를 나누고, 바인딩은 값을 값 채널로만 보낸다([security/18-injection](../../security/18-injection/2-summary.md)).
- 프롬프트는 시스템 지시·사용자 질문·검색 문서가 한 토큰 열로 이어진다. 모델이 어느 부분을 지시로 읽을지 문법으로 고정할 수 없다. Greshake 외(2023)의 표현대로 LLM 통합 앱은 데이터와 지시의 경계를 흐린다.
- OWASP LLM01도 완전한 예방법이 있는지 불분명하다고 적는다. 그래서 목표를 "모델이 속지 않게"에서 "속아도 피해가 경계 밖으로 나가지 않게"로 바꾼다 — 권한·출력·소비를 모델 밖에서 통제한다.

### 2. 직접·간접

- 직접: 사용자가 프롬프트에 넣은 입력이 모델 동작을 바꾼다(고의·실수 모두).
- 간접: 웹사이트·파일 등 외부에서 받아들인 내용 속 문장이 동작을 바꾼다(OWASP LLM01).
- 탈옥은 안전 장치를 완전히 무시하게 만드는 인젝션의 한 형태로 구분된다(같은 문서).

### 3. 프롬프트 방어와 게이트웨이

- 0이 되지 않는다. 실험(seed 22, 세션 1000)에서 p=0.9일 때 외부 전송이 none 189건 → prompt 41건이었다. 줄어든 폭 자체는 스텁의 가정(1/5)에서 온 것이라 실제 모델의 효과를 말하지 않는다.
- 게이트웨이(고위험 도구에 수신 도메인 허용 목록 + 수신자 값이 신뢰 출처에 있는지 확인 — 실험 코드에 도구 허용 목록은 없다)를 두면 p=0.1·0.5·0.9 모두 0건이었다. 게이트웨이를 통과할 수 있는 행동 집합이 모델의 속는 정도와 무관하기 때문이다.
- 이 0은 실험한 공격(외부 도메인 수신자)에 한정된다. 수신자 문자열이 사용자 입력에 *언급*됐다고 *승인*된 것은 아니므로, 운영에서는 사용자가 승인한 행동·대상과 인자 출처를 따로 추적한다.
- 사용자가 직접 요청한 정상 메일 288건은 모든 방어에서 다 나갔다.

### 4. gateway가 못 막은 것

- 답 텍스트의 외부 이미지 링크. 렌더링되면 URL에 실린 데이터가 외부로 나간다(OWASP LLM01 시나리오 2). 도구 호출이 아니라 출력 렌더링 경로라 `gateway+output`의 출력 처리(외부 이미지 제거·HTML 인코딩)에서 0이 됐다.
- 끝내 못 막는 것: 답 내용 자체의 조작(틀린 요약·편향된 추천). 행동과 렌더링은 경계에서 막지만 내용의 정확성은 출처 표기·평가([19-llm-evaluation](../19-llm-evaluation/2-summary.md))로 따로 다룬다.

### 5. 브라우저 스크립트 실행

- OWASP LLM05 출력 처리 부실 — 모델 출력을 검증·인코딩 없이 하류(브라우저)에 넘겼다.
- 대처는 기존 XSS 대처와 같다: 문맥별 출력 인코딩, 엄격한 CSP([security/19-xss-and-csp](../../security/19-xss-and-csp/2-summary.md)). LLM05는 모델을 다른 사용자처럼 제로 트러스트로 대하라고 한다.

### 6. 과도한 에이전시

- 과도한 기능 → 필요한 도구만 노출, 열린 도구(셸·URL 가져오기) 대신 좁은 도구.
- 과도한 권한 → 하류 접속 계정의 권한 최소화(조회만이면 SELECT만), 사용자 권한 맥락으로 실행.
- 과도한 자율성 → 고위험 행동은 사람 승인.
- complete mediation: 행동이 허용되는지를 LLM이 판단하게 두지 않고, 하류 시스템이 확장 기능을 통한 모든 요청을 보안 정책으로 검증한다(OWASP LLM06 완화책 7, 원칙은 [security/01](../../security/01-security-principles/2-summary.md)).

### 7. 시스템 프롬프트의 키

- 먼저 키를 폐기·교체한다(이미 유출된 것으로 본다).
- 설계: 시스템 프롬프트는 비밀도 보안 통제도 아니다(OWASP LLM07). 비밀은 모델이 직접 접근하지 않는 시스템에 두고, 도구 호출에 필요한 키는 게이트웨이 코드가 붙인다(LLM01 완화책 4). 권한·역할 구조도 프롬프트에 넣지 않고 인가는 결정적 코드에서 집행한다.

### 8. 생성 프롬프트로 권한 거르기

- 그것은 모델 안 방어다. 모델이 지시를 어길 확률이 0이 아니고, 권한 밖 문서 내용은 이미 모델 문맥에 들어가 있다.
- 권한 필터는 검색 단계에서 건다. 권한 밖 문서가 문맥에 들어가지 않게 하는 것이 결정적 통제다(OWASP LLM02 — 최소 권한 접근 통제, 데이터 출처 제한).

### 9. 토큰 전달

- 하류 API는 그 토큰을 MCP 서버가 검증한 것으로 오인할 수 있다(혼동된 대리인). 레이트 리밋·검증 같은 통제가 우회되고, 감사 로그에서 누가 호출했는지 흐려진다(MCP 2026-07-28 "Security Best Practices" Token Passthrough).
- 명세: MCP 서버는 자기에게 명시적으로 발급되지 않은 토큰을 받아들이면 안 된다(MUST NOT).
