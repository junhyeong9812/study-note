# distributed/05-logical-clocks — 정답

## 정답

### 1. 벽시계 정렬의 문제

- 노드마다 벽시계가 어긋난다. 받는 쪽 시계가 메시지 지연보다 더 느리면, 받고 나서 만든 사건의 시각이 원인보다 작아진다.
- 그러면 정렬 결과에서 결과가 원인보다 앞에 온다(인과 역전).
- 시각 값 자체는 정상 범위의 숫자라서 검증에 걸리지 않는다. 그래서 에러 없이 틀린 순서가 저장된다.

### 2. happens-before와 동시

- 세 규칙(Lamport 1978)
  1. 같은 프로세스 안에서 a가 b보다 먼저면 a → b.
  2. a가 메시지를 보내고 b가 그 메시지를 받으면 a → b.
  3. a → x, x → b이면 a → b(이행성).
- 동시(a ∥ b): a → b도, b → a도 아니다. 서로 정보가 닿을 경로가 없었다는 뜻이다. 실제 시각이 몇 초 떨어져 있어도 동시일 수 있다.

### 3. 계산

| 사건 | 램포트 | 벡터 |
|---|---|---|
| a | 1 | [1,0,0] |
| b | 2 | [2,0,0] |
| g | 3 | [3,0,0] |
| c | 1 | [0,0,1] |
| d | max(0,2)+1 = 3 | [2,1,0] |
| e | 4 | [2,2,0] |
| f | max(1,4)+1 = 5 | [2,2,2] |

- c와 d: [0,0,1] vs [2,1,0] → 서로 큰 칸이 있다 → 동시.
- g와 f: [3,0,0] vs [2,2,2] → 동시. 램포트로는 3 < 5라 g가 먼저처럼 보인다.
- 서머리 실험 출력의 표와 같다.

### 4. 예측

- 벽시계: a=100, d=130−80=50 → d가 앞에 온다. 실험 출력 `벽시계 정렬: d e a b c g f`.
- 램포트: a=1, d=3 → a가 앞. a → d 인과를 지킨다. 실험 출력 `램포트 정렬: a c b g d e f`.

### 5. 램포트의 보장 범위

- 보장: a → b이면 C(a) < C(b) (Clock Condition).
- 비보장: C(a) < C(b)라고 a → b는 아니다. 동시일 수 있다.
- 실험: 동시 쌍 43678개 중 39089개(89.5%)가 램포트 값이 달랐다. (이 비율은 실험의 무작위 부하 기준이다.) 값 차이를 순서로 읽으면 이 쌍들에 근거 없는 순서를 붙인다.

### 6. 램포트 전순서의 쓰임

- 쓰임: 모든 노드가 **같은** 순서에 동의해야 하는 경우. 예) Lamport 논문의 분산 상호 배제 요청 큐, 여러 로그의 결정적 병합.
- 이 순서는 →를 어기지 않는 여러 전순서 중 하나다. 동시 쌍의 앞뒤는 노드 번호 같은 임의 규칙이 정한다.
- 동시 쓰기 충돌 해결에 쓰면 "큰 쪽이 이긴다"가 되어 다른 쪽 쓰기가 조용히 사라진다. 동시를 감지하려면 벡터(버전 벡터)가 필요하다(24번).

### 7. 숨은 채널

- 지킬 수 없다. 전화는 시스템이 나르는 메시지가 아니라서 시스템은 두 요청을 동시로 본다. B가 더 작은 시계 값을 받을 수 있다(Lamport 1978 "anomalous behavior").
- 방법 1: 요청 A의 타임스탬프를 사용자에게 돌려주고, 요청 B에 실어 보내 그보다 큰 값을 받게 한다.
- 방법 2: 물리 시계를 충분히 맞춰 Strong Clock Condition에 가깝게 한다. HLC·TrueTime(26번)이 이 방향이다.

### 8. 재배포 후 옛 이벤트 취급

- 의심: 시계 값이 메모리에만 있어 재시작 후 작은 값부터 다시 셌다.
- 확인: 그 노드 이벤트의 시계 값 추이를 본다. 배포 시점에 값이 작은 수로 떨어진다. 원인-결과 쌍에서 결과 값이 원인 값보다 작거나 같은 행을 SQL로 찾는다.
- 수정: 시계 값을 사건과 함께 영속화하고 재기동 시 저장된 최댓값(주기 저장이면 여유분 추가)부터 이어 간다. 받는 메시지가 오면 max로 따라잡는 경로도 확인한다.

### 9. 버전 벡터 메타데이터 증가

- 원인: 칸이 참여자마다 하나다. 요청을 처리한 서버·클라이언트 id를 칸으로 쓰면 오토스케일링·재생성마다 칸이 늘고, 사라진 주인의 칸도 계속 남는다.
- 대처: 칸의 주인을 개수가 고정된 복제본으로 잡는다. Riak 2.0 이후는 dotted version vector로 형제 폭증을 줄인다(Riak 문서).
- Dynamo(2007 §4.4): (노드, 카운터) 쌍마다 갱신 시각을 두고, 쌍 수가 임계값(예: 10)에 닿으면 가장 오래된 쌍을 지운다. 대가는 후손 관계를 정확히 못 구해 동시 판정이 틀릴 수 있다는 것이다. 논문은 이 문제가 운영에서 드러나지 않았다고 적는다.
