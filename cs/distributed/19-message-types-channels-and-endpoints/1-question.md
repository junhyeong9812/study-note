# distributed/19-message-types-channels-and-endpoints — 질문

## 질문

1. (왜) 주문 서비스가 `PayOrder`·`AddPoint`·`SendMail`을 각각 보내던 구조를 `OrderPlaced` 이벤트 하나로 바꾸면 결합 방향이 어떻게 달라지나? 그래도 명령으로 남겨야 할 단계는 어떤 것인가?
2. (경계) Command·Event·Document 메시지는 바이트 형식이 아니라 무엇으로 구분되나? EIP는 Event와 Document의 차이를 무엇으로 설명하나?
3. (예측) 요청 100개를 응답 채널 하나로 받고, 응답자 4개의 처리 시간이 0~2ms로 제각각이다. 응답을 "보낸 순서대로 온다"고 가정하고 짝지으면 몇 건쯤 틀릴까? correlation ID로 짝지으면?
4. (경계) Dead Letter Channel과 Invalid Message Channel은 각각 누가 "처리할 수 없다"고 판단한 메시지를 받나? 둘을 한 채널로 섞으면 무엇이 어려워지나?
5. (예측) 주문 2,000개의 `CREATED → PAID → SHIPPED` 이벤트를 (A) 한 큐 + 경쟁 소비자 4개, (B) 주문 ID 해시 → 레인 4개(레인당 소비자 1개)로 처리한다. 처리가 "상태 := 이벤트 상태" 덮어쓰기라면 최종 상태가 `SHIPPED`가 아닌 주문은 각각 대략 몇 건인가?
6. (연결) Kafka 4.1에서 Sequential Convoy는 어떻게 구현되나? 기본 분할기가 키로 파티션을 고르는 식을 쓰고, 파티션 수를 3에서 6으로 늘리면 키 단위 순서에 무슨 일이 생기는지 설명하라.
7. (경계) Kafka 토픽의 `retention.ms`(4.1 기본 `log.retention.hours=168`)를 메시지 유효 시한으로 쓸 수 있나? RabbitMQ의 메시지별 `expiration`은 만료된 메시지를 언제 버리나?
8. (장애 진단) 프로모션 기간에 일반 주문 큐의 가장 오래된 메시지 나이가 몇 시간째 오른다. 우선순위 큐 구성에서 무엇을 의심하고, 어떤 대처를 하나? 과부하에서 에이징이 공짜가 아닌 이유는?
9. (장애 진단) 소비자 장애 30분 뒤 복구하자 이미 취소된 예약 명령이 대량 실행됐다. 원인과 재발 방지책을 메시지 겉봉·소비자 코드 두 층에서 말하라.
