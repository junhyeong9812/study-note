# distributed/28-consensus-paxos — 질문

## 질문

1. (왜) 주·대기 두 대에 "응답이 없으면 대기가 넘어간다"만 두면 왜 split brain이 생기나? Paxos는 무엇을 더해 이것을 막나?
2. (그림) proposer 하나와 acceptor 셋으로 Paxos 기본형의 두 단계를 메시지 순서도로 그려라. 각 단계에서 acceptor가 보고 바꾸는 상태(np·na·va)를 표시하라.
3. (예측) S1이 n=1로 X를 S1·S3에 수락시킨 뒤 죽었다. S2가 Y를 원하며 n=2로 S2·S3에 prepare를 보낸다. 무엇이 선택되나? S2가 promise에 실려 온 값을 무시하면?
4. (예측) acceptor가 accept(n, v)를 받을 때 `n >= np` 검사를 빼면 어떤 순서에서 두 값이 선택되나? 재부팅하며 np만 잃는 경우는?
5. (계산) 5대에서 정족수 크기를 2로 하면 서로 겹치지 않는 정족수 쌍이 몇 개 나오나? 3이면? 이것이 "2f+1대가 f대 장애를 견딘다"와 어떻게 이어지나?
6. (경계) Paxos의 안전성과 진행은 각각 무엇에 기대나? 결투하는 제안자가 보여 주는 것은 무엇이고, 논문은 진행을 위해 무엇을 두나? 그것이 FLP와 어떻게 이어지나?
7. (연결) Paxos 기본형과 Raft를 순서 번호·1단계·리더·정하는 대상으로 비교하라. 두 알고리즘의 안전성이 공유하는 뿌리는?
8. (장애 진단) 합의 요청이 끝나지 않고 제안 번호만 빠르게 커진다. 원인과 대처는?
9. (장애 진단) 클라이언트는 타임아웃을 받았는데 나중에 그 값이 선택돼 있었다. 어떻게 가능한가? 클라이언트와 learner는 각각 무엇을 해야 하나?
