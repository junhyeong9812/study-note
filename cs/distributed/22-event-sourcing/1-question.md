# distributed/22-event-sourcing — 질문

## 질문

1. (왜) 상태만 저장할 때 답할 수 없는 질문 두 가지를 대라. Fowler(2005)가 이벤트 로그 위에 세울 수 있다고 한 기능 세 가지는?
2. (예측) 잔액 1000(version 3)인 계좌에 두 요청이 동시에 700 출금을 검증하고 이벤트를 version 4로 넣는다. (a) 이벤트 ID만 PK인 테이블, (b) (stream_id, version)이 PK인 테이블에서 각각 최종 잔액과 이벤트 수는? (b)에서 늦게 넣은 쪽은 언제, 어떤 오류를 받나?
3. (경계) 검증은 명령 처리 때만 하고 재생(접기) 중에는 하지 않는다. 왜인가? 재생 중 `if (잔액 < 0) throw`를 넣으면 무엇이 깨지나?
4. (예측) 100만 이벤트 스트림을 처음부터 접는 것과, version 999,863 스냅샷에서 137건만 접는 것의 결과와 시간은 어떻게 다른가? 스냅샷이 틀렸다면 어떻게 하나?
5. (예측) 이벤트 클래스의 필드 `amount`를 `amountMinor`로 바꿨다. Jackson 기본 설정으로 옛 이벤트 `{"amount":100}`을 재생하면? `FAIL_ON_UNKNOWN_PROPERTIES`를 끄면? 어느 쪽이 더 위험한가?
6. (적용) 이벤트 형식 변경을 다루는 방법 세 가지(업캐스터 포함)를 대고, 필드 추가와 이름 변경에 각각 무엇이 맞는지 말하라.
7. (연결) 프로젝션을 재구축하려고 이벤트를 처음부터 다시 흘렸다. 무엇이 안전하고 무엇이 사고를 내나? Fowler의 "External Updates"·"External Queries"가 말하는 처방은?
8. (경계) Kafka 토픽을 이벤트 저장소로 그대로 쓸 때 부족한 점 세 가지는?
9. (장애 진단) 오래된 계좌일수록 조회가 느려지고 몇 년 된 계좌는 타임아웃이 난다. 무엇을 쿼리해 확인하고, 어떻게 고치나? 고칠 때 조심할 경계 버그는?
