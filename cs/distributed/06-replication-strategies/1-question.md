# distributed/06-replication-strategies — 질문

## 질문

1. (왜) 데이터를 여러 노드에 복제하는 이유 세 가지는? 복사 자체가 아니라 무엇이 어려운가?
2. (그림) 단일 리더·다중 리더·리더리스를 "쓰기를 누가 받나 / 쓰기 순서를 누가 정하나 / 충돌이 생기나"로 그려 비교하라.
3. (예측) Redis 7.4.9 리더 1 + 복제본 1을 같은 호스트에 띄우고, `SET`을 리더에 보낸 직후 `GET`을 복제본에 보내기를 300번 한다. 복제 링크가 직결일 때와 50ms 늦을 때 옛 값은 각각 몇 번쯤 나오겠나? `WAIT 1 100`을 넣으면?
4. (예측) 같은 구성에서 복제 링크를 3000ms 늦추고 `SET` 1000건을 OK 받은 직후 복제본을 승격하면 새 리더에 몇 건이 남겠나? 지연이 50ms일 때 같은 셸 절차로 돌렸더니 1000건이 모두 남았다. 왜 그런가?
5. (경계) 다중 리더에서 LWW로 충돌을 해소하면 모든 리더가 같은 값이 된다. 그런데 왜 "데이터를 잃지 않았다"고 말할 수 없나? 시계가 500ms 늦은 리더가 있으면 어떻게 달라지나?
6. (경계) 다중 리더의 충돌을 다루는 네 가지 방법은? 장바구니 "항목 추가"와 사용자 "닉네임 변경"에 각각 어떤 방법이 맞나?
7. (장애 진단) 리더리스 저장소에서 어떤 키는 읽을 때마다 새 값과 옛 값이 번갈아 나오고, 잘 안 읽히는 키는 몇 주째 옛 값이다. 원인과 대처는? 읽기 복구만으로 충분하지 않은 이유는?
8. (장애 진단) 페일오버 뒤 "결제 완료" 응답을 받은 주문이 새 리더에 없다. 어떤 지표로 확인하고, 재발을 줄이는 설정은 무엇인가? GitHub 2018-10-21 사고에서는 이것이 어떻게 나타났나?
9. (연결) 단일 리더 복제가 충돌이 없는 이유를 "복제 로그"와 "상태 기계 복제"로 설명하라. 문장 기반 로그가 위험한 경우는?
