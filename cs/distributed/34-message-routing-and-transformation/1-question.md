3. (그림) Aggregator를 설계할 때 정해야 할 세 가지를 쓰고, EIP가 든 완료 조건 전략 다섯 가지 중 "모두 기다림"의 약점을 시간축 그림으로 보여라.
4. (예측) 주문 10만 개를 3조각으로 나눠 보내고 조각마다 2%가 유실된다. 완료 조건이 "3조각 도착"뿐인 Aggregator의 버퍼에는 끝에 몇 개쯤의 묶음이 남을까? 트래픽이 두 배가 되면? 타임아웃을 더하면 어떻게 달라지나?
5. (예측) Kafka 4.1 기본 설정에서 2,000,000바이트 레코드를 콘솔 프로듀서로 보내면 어떤 예외가 나고, 셸의 종료 코드는 몇일까? 프로듀서 `max.request.size`만 5MB로 올리면?

7. (연결) Resequencer의 재정렬 버퍼로 최소 힙을 쓰는 이유는? 순번 하나가 영영 오지 않으면 무슨 일이 생기고, 어떻게 풀어 주나?
8. (계산) 앱 6개가 서로 모두 메시지를 주고받는다. 직접 변환하면 Message Translator가 몇 개, Canonical Data Model을 쓰면 몇 개 필요한가? 앱 2개일 때는? 이 이점에도 공용 모델을 전사 범위로 강제하면 어떤 장애가 생기나?
