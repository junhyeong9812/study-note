# engineering-practice/09-dora-metrics — 질문

## 질문

1. (왜) DORA 지표 없이 "배포가 나아졌나"를 논의하면 무엇이 안 되나? 다섯 지표를 처리량과 불안정성으로 나눠 이름과 정의를 대라(dora.dev 2026-01 기준).
2. (경계) 실패 배포 복구 시간은 처리량인가 안정성인가? 2015년 모델과 지금 모델의 답이 다른 이유, 그리고 2023년에 MTTR을 이 지표로 바꾼 이유는?
3. (예측) 실험의 honest 시나리오(배포 9회, 실패 2, 계획에 없던 배포 1)에 "기능 커밋마다 이미 배포된 버전을 다시 배포"하는 재배포 17회를 더하고 핫픽스를 "계획됨"으로 적으면, 배포 빈도·리드 타임·변경 실패율·재작업률은 각각 어떻게 변하나?
4. (진단) 3번처럼 숫자가 좋아졌을 때 게이밍인지 진짜 개선인지 가려낼 신호 두 가지는? 실험의 daily 시나리오와 비교해 답하라.
5. (계산) 배포 로그에 같은 SHA 재배포와 롤백(옛 SHA 재배포)이 섞여 있다. `git rev-list <직전 배포 SHA>..<이번 배포 SHA>`로 "이번 배포에 처음 들어간 커밋"을 구하면 무엇이 틀리나? 어떻게 고치나?
6. (장애 진단) 측정 도구를 바꾼 날 리드 타임이 절반 이하로 떨어졌다. 일하는 방식은 그대로다. 의심할 원인 두 가지(하나는 git 동작)와 대처는?
7. (연결) "속도와 안정성은 맞바꿈이 아니다"는 어떤 종류의 근거인가? 이 문장에서 "배포 횟수를 늘리면 장애가 준다"를 끌어내면 무엇이 잘못인가?
8. (적용) 리더가 팀별 배포 빈도 순위를 전사 대시보드에 걸자고 한다. dora.dev가 든 함정 중 어느 것들에 해당하나? 대신 무엇을 제안하겠나?
