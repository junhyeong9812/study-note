# engineering-practice/16-operational-standards — 질문

## 질문

1. (왜) 서비스마다 로그·지표 형식이 다르면 평소보다 사고 때 훨씬 큰 문제가 되는 이유는? "공용 도구"라는 말로 설명하라.
2. (그림) 운영 표준을 "서비스 ↔ 공용 운영 도구 사이의 계약"으로 그리고, 계약 항목 다섯 가지와 각각을 쓰는 도구를 연결하라.
3. (예측) 실험 A에서 Logback 기본 설정 서비스는 이벤트 3건을 몇 줄로 냈나? 줄 단위로 수집하면 ERROR 한 건은 어떻게 보이나?
4. (경계) "JSON으로 로그를 내면 표준을 따른 것"이 왜 틀렸나? 실험의 Logback `JsonEncoder` 출력과 서비스 D가 팀 표준 검사에서 걸린 이유를 각각 대라.
5. (예측) trace_id `4bf92f35…4736`을 글자로 검색할 때와 표준 필드(`"trace_id":"…"`)로 검색할 때, 서비스 D에서 찾는 이벤트 수는 각각 몇 건인가? 왜 다른가?
6. (경계) Prometheus 명명 문서 기준으로 `payment_latency_ms`, `paymentRequestCount`, `shipping_label_user_10234_total`의 문제는 각각 무엇인가? 이름 검사기가 잡지 못하는 단위 문제는?
7. (연결) OpenTelemetry Logs Data Model과 W3C Trace Context는 운영 표준의 어느 부분에 근거를 주나? SeverityNumber가 필요한 이유는?
8. (장애 진단) 포스트모템 타임라인에서 원인 이벤트가 결과 이벤트보다 늦게 적혔다. 로그에서 무엇을 확인하고, 표준으로 무엇을 정해야 하나?
9. (적용) 표준을 위키 문서로만 두었더니 새 서비스가 따르지 않았다. 강제 수단을 약한 것부터 강한 것까지 나열하고, 출시 전 PRR이 확인하는 영역(SRE Book 32장)을 대라.
