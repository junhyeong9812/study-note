# engineering-practice/04-branching-strategies — 질문

## 질문

1. (왜) git에서 브랜치는 파일 하나짜리 포인터라 만드는 비용이 거의 없다. 그런데도 "장수 브랜치는 비싸다"고 하는 이유는? 무엇이 쌓이나?
2. (경계) trunk-based development의 기준을 trunkbaseddevelopment.com, DORA, SWE@G 16장은 각각 어떻게 말하나? 공통점과 수치 차이를 구분하라.
3. (경계) git-flow는 어떤 소프트웨어를 위해 설계됐고, 저자는 2020년 노트에서 어떤 팀에 다른 흐름을 권했나?
4. (예측) 개발자 4명이 20일 동안 같은 편집 흐름을 만든다. 매일 통합하는 경우와 20일 끝에 한 번 통합하는 경우, 충돌 줄 합계와 "충돌 난 병합 1회당 줄 수"는 어떻게 다를까? 충돌 덩어리 **수**만 보면 왜 오해할 수 있나?
5. (예측) 한 브랜치는 `Pricing.total()`을 `totalWithShipping()`으로 이름을 바꾸고, 다른 브랜치는 새 파일에서 `Pricing.total()`을 호출한다. git 병합 결과와 빌드 결과는?
6. (연결) 미완성 기능을 "브랜치에 숨기기"와 "런타임에 숨기기"는 통합 시점이 어떻게 다른가? Hodgson의 플래그 네 분류 중 미완성 기능 숨기기에 쓰는 것은 무엇이고, 수명은?
7. (적용) 결제 모듈 구현을 몇 주에 걸쳐 갈아끼워야 한다. 장수 브랜치 없이 트렁크에서 하려면 Branch by Abstraction의 어떤 단계를 밟나?
8. (장애 진단) 1.2 릴리스 브랜치에서 고친 버그가 1.3에서 재발했다. 원인과, trunkbaseddevelopment.com이 권하는 수정 방향은?
9. (장애 진단) 팀이 trunk-based로 바꿨는데 PR이 리뷰를 며칠씩 기다리고 `main`이 자주 빨갛다. DORA가 꼽은 함정 세 가지와 대처는?
