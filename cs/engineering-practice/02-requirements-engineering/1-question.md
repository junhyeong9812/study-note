# engineering-practice/02-requirements-engineering — 질문

## 질문

1. (왜) "검색은 빨라야 한다"는 요구가 왜 재작업으로 이어지나? 같은 요구를 검증 가능한 문장으로 고쳐 써 보라(수치는 예시로).
2. (경계) ISO/IEC/IEEE 29148이 구분하는 요구 검증(verification)과 요구 확인(validation)은 각각 무엇을 묻나? 하나만 통과하고 다른 하나는 실패하는 예를 들어라.
3. (경계) 개별 요구의 특성 중 "단일(singular)"이 왜 추적·테스트에 중요한가? 단일하지 않은 문장을 하나 만들고 쪼개라.
4. (예측) 실험에서 v1(모호한 요구 3개)과 v2(고쳐 쓴 요구 5개)의 테스트 수와 요구 커버는 각각 얼마로 나올까? v2에서 테스트가 0개로 남는 요구는 어떤 종류이고 왜인가?
5. (경계) 실험의 단어 검사기가 잡지 못한 문제 두 가지는 무엇인가? 이 검사기를 어디에 써야 하나?
6. (그림) 요구 추적의 "위로"와 "아래로"를 그림으로 그리고, 각 방향이 답하는 질문을 하나씩 대라.
7. (연결) 추적 매트릭스가 역색인·집합 차와 어떻게 같은 구조인가? "테스트 연결이 없는 요구"와 "고아 테스트"를 집합식으로 써라.
8. (장애 진단) 기능 테스트는 다 통과했는데 출시 직전 부하 테스트에서 응답이 몇 초씩 걸린다. 요구공학 쪽에서 무엇이 빠졌고, 다음에는 어떻게 막나?
9. (장애 진단) 취소 가능 시간이 24시간에서 48시간으로 바뀌었는데 배치 하나가 옛 기준으로 동작했다. 원인과 재발 방지책은?
