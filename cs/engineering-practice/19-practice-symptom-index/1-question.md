# engineering-practice/19-practice-symptom-index — 질문

## 질문

1. (왜) 변경의 흐름을 일곱 칸(작성 → 리뷰 → 통합 → 빌드·CI → 배포 → 운영 → 기억)으로 나누고, 커리큘럼의 다섯 증상(머지 지옥·CI 불신·배포 공포·리뷰 병목·"이건 왜 이렇게 했지?")을 각 칸에 놓아라. 증상이 보인 칸의 "한두 칸 앞(왼쪽)"을 함께 봐야 하는 이유를 예 두 개로 설명하라.
2. (장애 진단) "CI가 빨갛다"는 같은 증상에 원인이 여럿이다. 싼 질문부터 세 개를 들고, 각 답이 가리키는 원인·처방·leaf를 말하라. 이것들을 한 원인으로 묶어 재시도를 켜면 어떻게 되나?
3. (예측) PR A와 PR B가 각자 CI 초록이고 병합 충돌도 0개다. 둘을 차례로 main에 병합하면 main CI는 어떻게 되나? 06 실험의 출력으로 답하고, 텍스트 병합이 이것을 못 잡는 이유와 처방을 말하라.
4. (예측) 같은 변경 흐름을 통합 주기 1일·5일·20일로 재생한 04 시뮬레이션에서 "충돌 난 병합 1회당 충돌 줄 수"와 "충돌 줄 합계 비율"은? 충돌 덩어리 수만 보면 어떤 오해가 생기나?
5. (장애 진단) 운영 서버 8대 중 한 대만 이상한 주문을 낸다. 첫 진단으로 무엇을 모으고, 결과를 어떻게 읽나? 06 모형 실험의 출력을 들고, 응답하지 않는 서버를 어떻게 세야 하는지도 말하라.
6. (장애 진단) 운영 번들에 스테이징 API 주소가 박혀 나갔다. 빌드 로그에는 "cache hit"만 있고 오류가 없다. 07 실험 두 개(직접 만든 해시 캐시, GNU Make)로 원인 두 갈래를 설명하고, 의심될 때의 확인 방법을 말하라.
7. (구분) 리뷰 병목의 "시간 문제"와 "질 문제"를 구분하라. 05 실험의 섞인 PR 수치(파일·줄)와 동작 변경 줄 수를 들고, 두 문제를 함께 줄이는 처방이 무엇인지 말하라.
8. (장애 진단) 세율 정책을 바꾼 뒤 환불 금액만 고객 문의가 들어온다. 예외도 에러도 없다. "이건 왜 이렇게 했지?"를 풀어 가는 순서(명령 포함)와 10 실험의 출력을 말하라. 이유를 끝내 찾지 못하면 무엇을 남기나?
9. (경계) 09 실험의 gamed 출력에서 좋아진 지표와 그대로인 지표를 나누어라. 게이밍을 알아채는 데 쓴 점검 줄은 무엇인가? 같은 모양을 이 영역의 다른 leaf에서 두 개 더 들어라.
10. (연결) 사고 회고가 "작업자가 서버 하나를 빠뜨렸다"로 끝났다. 무엇을 놓쳤나? Knight Capital에 대한 SEC의 지적과 연결하고, "주의하자" 대신 둘 장치를 세 개 들어라.
