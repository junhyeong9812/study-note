# engineering-practice/11-documentation-practices — 질문

## 질문

1. (왜) "틀린 문서는 없는 문서보다 나쁠 수 있다"는 말은 왜 성립하나? SWE@G 10장이 낡은 문서에 대해 권하는 최소한의 행동은?
2. (분류) Diátaxis 나침반의 두 질문은 무엇인가? 다음 문서의 유형을 정하라. (a) 설정 키 전체 목록과 기본값 (b) 신입이 처음 서비스를 로컬에서 띄워 보는 안내 (c) DB 장애 조치 런북 (d) 왜 주 DB 하나와 복제본 구조를 택했는지
3. (경계) 튜토리얼과 방법 가이드는 둘 다 단계가 있다. 무엇이 다르고, 섞이면 어떤 일이 생기나?
4. (연결) SWE@G 10장이 말하는 "문서를 코드처럼"의 항목을 다섯 개 이상 대라. GooWiki 사례에서 무엇이 문제였고 무엇으로 나아졌나?
5. (예측) 실험의 런북은 3월에 쓰였고 6월에 스크립트 옵션과 설정 구조만 바뀌었다. 10월 5일에 90일 상한으로 점검하면 런북에서 어떤 종류의 문제가 몇 건 나오나? 런북 명령을 그대로 실행하면?
6. (예측) 그 런북의 내용은 그대로 두고 `reviewed`만 2026-10-01로 올려 커밋한 뒤 다시 점검하면, 어떤 검사가 사라지고 어떤 검사가 남나? 왜 그런가?
7. (장애 진단) "배포 방법" 문서가 위키에 셋, 저장소에 하나 있고 내용이 다르다. 원인과 대처는?
8. (적용) 문서 점검을 CI에 넣을 때 어떤 검사는 머지를 막고 어떤 검사는 알림만 보내야 하나? 이유는?
