# engineering-practice/13-build-vs-buy-and-adoption — 질문

## 질문

1. (왜) Fowler의 범용(utility)·전략(strategic) 구분에서 둘의 "가장 큰 위험"은 각각 무엇이고, 그래서 만들기/사기 결정이 어떻게 갈리나? 구분 기준은 기술의 성질인가?
2. (예측) 실험 A의 가정(만원, 1인월 1,000)에서 초기 개발비와 구독료만 비교하면 어느 쪽이 싸 보이나? 유지보수·온콜·인프라·연동·벤더 관리를 넣은 3년 TCO에서는? 종료 비용 3,000을 더하면?
3. (계산) 실험 A에서 구독료가 매년 몇 % 넘게 오르면 "구매 + 종료 비용"이 직접 만들기보다 비싸지나? 이 숫자를 결정 기록에 어떻게 쓰겠나?
4. (경계) 가중합 행렬에서 차별화 가중치를 1·3·5로 바꾸면 1위가 어떻게 바뀌었나? 가중치 5에서 3.35 vs 3.29라는 결과를 어떻게 읽어야 하나?
5. (연결) 벤더 종속은 어느 층에서 생기나? 코드 층과 데이터 층의 종속을 각각 무엇으로 줄이나?
6. (진단) Scorecard 공개 API로 `junit-team/junit5`를 조회했더니 스캔 날짜가 1년 넘게 전이고 점수가 새 이름 저장소와 다르다. 무슨 일이며, 조회 결과에서 무엇부터 확인해야 하나?
7. (경계) Scorecard 집계 점수는 어떻게 계산되나? README가 밝힌 한계를 들어, "집계 7점 미만 의존성 금지" 규칙의 문제를 설명하라. Guava의 Code-Review 0은 어떻게 읽어야 하나?
8. (장애 진단) 의존하던 OSS의 다음 버전이 소스 공개 라이선스로 바뀌었다(예: Redis 7.4). 이미 쓰던 버전은 어떻게 되나? 당장 할 일과 중장기 선택지는?
9. (적용) 회사가 자체 로그인·MFA 개발에 1년째 핵심 개발자를 쓰고 있다. 어떤 계산과 어떤 구조 변경을 제안하겠나?
