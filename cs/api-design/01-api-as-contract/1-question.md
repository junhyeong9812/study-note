# api-design/01-api-as-contract — 질문

## 질문

1. (왜) 같은 프로세스 안의 메서드 계약과 비교해, 네트워크 API의 계약은 왜 더 깨지기 쉬운가? 서버 빌드가 초록색이어도 장애가 나는 이유는?
2. (그림) "명시 계약 · 관찰 가능한 동작 · 구현"의 세 겹을 그리고, `GET /users`에서 각 겹에 속하는 예를 둘씩 들어라.
3. (경계) Hyrum의 법칙 원문을 한 문장으로 옮겨라. 이것은 측정된 법칙인가, 경험적 관찰인가? 출처는?
4. (예측) 서버가 저장소를 LinkedHashMap → ConcurrentHashMap으로, 응답 레코드 필드 순서를 (id, name) → (name, id)로, 404 문구를 `"user u-9999 not found"` → `"No user with id 'u-9999'"`로 바꿨다. (A) 이름으로 읽고 직접 정렬·`code`로 분기, (B) 목록 끝 원소 = 최근 가입자, (C) 원문 JSON 정규식 `{"id":..,"name":..}`, (D) 문구 `startsWith("user ")` 로 판정하는 클라이언트는 각각 어떻게 되나? 예외가 나는 클라이언트는 몇 개인가?
5. (예측) 위 실험을 사용자 5명으로 돌렸을 때 B는 깨졌나? 12명일 때와 왜 다른가?
6. (연결) `Map.of(...)`의 순회 순서는 같은 코드에서도 실행마다 다를 수 있다. JDK는 왜·어떻게 그렇게 하나? 이것이 API 응답에 주는 함의는?
7. (경계) Google AIP-180의 소스·와이어·의미 호환을 구분해 설명하라. "기본값이면 필드 생략"을 "항상 포함"으로 바꾸는 것은 어디에 걸리나? Stripe 블로그(2017)와 RFC 9457은 각각 무엇을 계약의 기준으로 삼나?
8. (장애 진단) 문구 개선 배포 뒤 특정 클라이언트가 404 요청을 짧은 간격으로 반복한다. 원인 가설과 서버·클라이언트 양쪽 대처를 말하라. AIP-193은 기존 API의 에러 메시지 변경에 어떤 조건을 거나?
9. (연결) 서버가 응답에 `tier` 필드를 추가했다. AIP-180·Stripe 기준으로는 호환 변경인데, Jackson 2.x 기본 설정의 소비자는 어떻게 되나? 소비자 쪽 대처와 그 한계는?
