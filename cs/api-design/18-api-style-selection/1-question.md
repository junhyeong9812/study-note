# api-design/18-api-style-selection — 질문

## 질문

1. (왜) API 스타일을 "어느 것이 더 빠르고 유연한가"가 아니라 제약 조건으로 골라야 하는 이유는? 이 노트가 쓰는 질문 네 가지를 대라.
2. (그림) REST·gRPC·GraphQL·WebSocket/SSE·메시지 큐의 요청 모양을 한 줄씩 그리고, 각각이 무엇을 대가로 무엇을 얻는지 적어라. Fielding이 균일 인터페이스의 단점으로 적은 것은?
3. (예측) 모든 응답에 `Cache-Control: public, max-age=60`을 붙인 백엔드 앞에 기본 설정 nginx `proxy_cache`를 두고, REST GET·GraphQL POST·GraphQL GET으로 같은 조회를 5번씩 보낸다. 각각 백엔드 도달 횟수는?
4. (경계) RFC 9110은 POST 응답을 캐시할 수 있다고 하나, 없다고 하나? 조건과 한계를 정확히 말하라.
5. (경계) 브라우저 앱이 내부 gRPC 서비스를 직접 부를 수 있나? gRPC-Web으로 가능한 것과 불가능한 것은?
6. (계산) 접속자 10,000명(예시)이 1초 간격으로 상태를 폴링한다. 초당 요청 수와 평균 감지 지연은? SSE로 바꾸면 비용이 어디로 옮겨 가나?
7. (연결) 외부 공개 API, 자사 앱 → 백엔드, 내부 서비스 간 동기 호출, 결과를 기다리지 않는 후속 작업에 각각 흔히 어떤 스타일을 고르나? 근거는?
8. (장애 진단) 트래픽이 늘었는데 CDN 적중률이 0이고 DB 부하가 오른다. 공개 상품 조회가 GraphQL POST로 되어 있다. 원인과 대처 두 가지는?
9. (장애 진단) 결제 API가 알림·포인트·추천을 동기로 순차 호출해, 추천 서비스 하나가 느려지자 결제 응답이 느려졌다. 스타일 선택 관점에서 무엇을 바꾸고, 그 대가는 무엇인가?
