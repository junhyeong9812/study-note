# api-design/28-api-symptom-index — 질문

## 질문

1. (왜) API 장애에서 "보이는 계층"과 "원인 계층"이 다른 예를 셋 들어라(구 앱 크래시·ID 끝자리 변형·이중 결제). 증상을 받으면 왜 보인 계층과 시작 시각부터 적나?
2. (장애 진단) "결제가 두 번 됐다"는 문의가 왔다. 두 요청의 `Idempotency-Key`가 (가) 없을 때 (나) 서로 다를 때 (다) 같을 때 각각 무엇을 의심하고 어느 leaf로 가나? 05 실험 S1·S2·S3의 결과(결제 행 수)로 답을 뒷받침하라.
3. (장애 진단) 클라이언트는 `504`를 봤고, nginx 로그에는 `upstream timed out ... while reading response header from upstream`이 있고, 앱 로그에는 같은 리포트 생성이 두 건 정상 완료됐다. 사건의 순서를 복원하고, 13 실험의 서버 집계 값을 말하라. "LB 타임아웃을 늘린다"가 왜 원인 처방이 아닌가?
4. (예측) 페이지마다 맨 앞에 새 글 3개가 들어오고 본 글 1개가 지워지는 동안 offset으로 1,000개를 넘기면 중복·누락은 어느 쪽으로 생기나? 06 실험의 수치와, 데이터가 안 바뀌는데도 경계에서 흔들리는 다른 원인을 말하라.
5. (구분) 서버 지표는 200으로 정상인데 구 앱 주문 목록만 안 열린다. 크래시 리포트가 (가) `not one of the values accepted for Enum class` (나) `Unrecognized field "memo"` (다) 예외 없이 금액 0원일 때 각각 원인은? Jackson 2.19.2와 3.0.0에서 (나)의 결과는 어떻게 달랐나?
6. (예측) 서버 로그에 `GET /orders/9007199254740992 → 404`가 웹 클라이언트에서만 쌓인다. 원래 ID는 무엇이었을 가능성이 크고, 왜 모바일(Java)은 정상인가? 08 실험의 출력 두 줄로 답하고, 이미 숫자로 내던 API의 대처 순서를 말하라.
7. (구분) 412·409·429를 받은 클라이언트가 다시 보내기 전에 각각 해야 할 일은? 셋을 같은 재시도 루프에 넣으면 412는 어떻게 되나? 11 실험 L3에서 412가 난 이유는?
8. (장애 진단) 웹훅 수신에서 (가) 상태 이력에 `SHIPPED` 뒤 `PAID` (나) 프레임워크 업그레이드 뒤 서명 실패 100% (다) 서버 한 대에서만 `timestamp` 사유 거부가 났다. 각각의 원인과, 받는 쪽 처리 순서 다섯 단계 중 어디가 빠졌는지 말하라. 09 실험 C의 두 최종 상태는?
9. (연결) "에러율 대시보드는 0%인데 사용자는 실패를 본다"의 원인을 REST·Problem Details·GraphQL에서 하나씩 들고, 각각 무엇을 지표로 세야 하나?
10. (경계) 이 색인의 메시지로 운영 로그를 검색했는데 같은 문구가 안 나온다. 왜 그럴 수 있나? 메시지 대신 무엇으로 찾나? 07 실험에서 판에 따라 결과가 갈린 예를 들어라.
