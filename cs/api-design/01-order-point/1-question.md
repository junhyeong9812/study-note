### A. 문제 (REQUIREMENTS.md — 주문 포인트 적용 API)

```text
POST /orders/{order_id}/point
{ "use_point_amount": 3000 }

기대 동작
  1. 요청한 주문에 사용할 포인트 금액을 적용합니다.
  2. 사용자의 보유 포인트에서 해당 금액을 차감합니다.
  3. 주문에는 사용된 포인트 금액이 기록되어야 합니다.
  4. 실패 상황에서는 적절한 에러 응답을 반환해야 합니다.
  5. 동일한 주문에 여러 번 호출되거나, 동시에 호출되는 상황에서도
     포인트가 잘못 차감되지 않아야 합니다.

참고
  - 사용자 테이블에는 보유 포인트 잔액 컬럼이 있습니다.
  - 주문 테이블에는 주문자, 주문 총액, 주문 상태 컬럼이 있습니다.
  - 결제 승인은 별도 API가 담당합니다. 이 API의 범위가 아닙니다.

구현 조건
  - 명시되지 않은 정책은 질문하며 진행해 주세요.
```

#### 1. 지문 읽기 — 숨은 요구

- 이 지문에서 난이도를 혼자 결정하는 한 줄은 어디이고, 왜 그 한 줄인가?
- 이 문제가 코드를 짜는 문제가 아니라면 무엇을 훈련하는 문제인가?
- 지문만 읽고 "확정해야 할 것"을 나열하라면 어떤 축들이 나와야 하는가(대략 10개 구획)?

#### 2. 잔액 차감 (D — 1차 변별점)

- 잔액을 SELECT 해서 앱에서 빼고 UPDATE 하는 코드는 언제, 왜 틀리는가?
- 그 버그(lost update)를 잔액 5000·동시 3000 사용 두 건으로 재연해보라 — 최종 잔액은 얼마가 되는가?
- 조건부 UPDATE 한 문장은 어떻게 생겼고, 무엇과 무엇이 한 문장 안에서 같이 일어나는가?
- 잔액 부족은 무엇으로 판정하는가(별도 SELECT 없이)?
- 잔액이 음수가 될 수 없음을 보장하는 것은 앱 코드인가, 다른 무엇인가?
- `SELECT ... FOR UPDATE` 대안의 트레이드오프는 무엇인가?
- 이 버그는 왜 테스트로 안 잡히는가?

#### 3. 멱등성 (E — 2차 변별점)

- 이 API에 별도 `Idempotency-Key` 헤더가 필요 없는 이유는 무엇인가?
- 멱등 판정의 최종 방어선은 사전 조회인가 UNIQUE 제약인가 — 왜?
- "조회해서 없으면 넣기"는 어떤 틈으로 뚫리는가(TOCTOU)?
- 같은 주문에 같은 금액 재요청과 다른 금액 재요청은 응답을 어떻게 갈라야 하는가?
- "타임아웃 후 재시도해서 409를 받으면 그것은 성공이다"라는 문장은 누구와 누구의 계약인가?
- 같은 키 재요청에 대한 Stripe와 GoCardless의 선택은 어떻게 정반대인가?
- Airbnb가 멱등성 데이터를 오직 master DB에서만 읽고 쓰는 이유는?

#### 4. 동시 요청 (F)

- 같은 주문에 정확히 동시에 2건이 들어오면 각 방어선에서 무슨 일이 일어나는가?
- 애플리케이션 락(`synchronized`)이 방어가 아닌 이유는?
- 최종 방어선이 DB 제약이어야 하는 이유는?

#### 5. 부분 실패와 원장 (G — 3차 변별점)

- 잔액만 UPDATE 하고 끝내면 안 되는 이유는 — 어떤 질문이 왔을 때 무너지는가?
- 원장과 잔액 중 무엇이 정본이고, 불일치가 나면 어느 쪽이 이기는가?
- 원장 기록·잔액 차감·주문 기록을 한 트랜잭션에 묶는 선택과 나누는 선택의 트레이드오프는?
- 중간에 프로세스가 죽으면 DB에 무엇이 남고, 복구 재시도가 두 번 차감하지 않음은 무엇이 보장하는가?

#### 6. 권한·상태·응답 (B, C, H)

- 요청 바디로 `user_id`를 받으면 안 되는 이유는 — 포인트 소유자는 어디서 식별하는가?
- 이 API가 주문 상태를 전이시키면 안 되는 이유는?
- 4xx와 5xx를 가르는 기준 한 문장은 무엇인가?

#### 8. 파생 — 왜 / 예측 / 경계 / 연결

- "코드는 돌아가고 테스트도 통과하는데 동시에만 틀린다"는 버그는 왜 유독 위험한가?
- 사전 조회를 "최적화"라고 부르는 이유는 — 방어와 최적화의 차이는 무엇인가?
- 멱등 응답 정책(재생 vs 409)의 선택이 프론트엔드 복잡도를 결정한다는 말의 뜻은?
- Twilio 과금 사고(2013)에서 추가된 fail-safe 한 문장은 무엇이고 왜 그 방향인가?
- Mercari 데드락은 무엇을 통제하지 않아 생겼고 어떻게 풀었는가?
- 올리브영 쿠폰 사고에서 Lua 스크립트(정확도 100%)를 기각한 근거는 무엇을 말해주는가?
- "명시되지 않은 정책은 질문하며 진행"이 지문에 적혀 있다는 것은 평가에서 무엇을 뜻하는가?
- 이 문제의 세 축(D·E·G)은 debugging 저장소의 어느 박스와 각각 짝인가?
