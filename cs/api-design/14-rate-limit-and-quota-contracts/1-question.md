# api-design/14-rate-limit-and-quota-contracts — 질문

## 질문

1. (왜) 서버에 리미터만 있고 계약이 없으면 어떤 일이 생기나? 요금제 쿼터와 보호용 스로틀은 목적·창·넘었을 때의 응답이 어떻게 다른가?
2. (경계) RFC 6585 §4는 429에 대해 무엇을 정하고 무엇을 정하지 않나? `Retry-After`는 필수인가? 429 응답을 캐시해도 되나? 429와 503은 무엇이 다른가?
3. (예측) 실험 A에서 성공 20건이 필요한 클라이언트가 `Retry-After`를 무시하고 즉시 재시도할 때와 지킬 때, 걸린 시간과 서버가 받은 요청·429 수는? 왜 무시해도 빨라지지 않나?
4. (예측) 회사 NAT 뒤 300명이 IP 하나를 쓰고 사용자당 3건을 보낸다. 한도가 "키당 100건"일 때 IP를 키로 쓰면 몇 명이 429를 받나? API 키를 키로 쓰면?
5. (그림) `RateLimit-Policy: "burst";q=100;w=60` 과 `RateLimit: "burst";r=50;t=30`을 풀어 써라. 이 헤더는 어느 단계의 문서에 정의돼 있나? 클라이언트가 이 헤더에 대해 하면 안 되는 가정 두 가지와, `Retry-After`가 함께 오면 무엇을 따르나?
6. (연결) GitHub의 `x-ratelimit-reset`과 초안의 `t`는 무엇이 다른가? 초안이 그 방식을 고른 이유는?
7. (경계) Stripe에서 429를 받았는데 `Stripe-Rate-Limited-Reason` 헤더가 없다. 무엇을 의심하고 어떻게 대처하나? GitHub는 한도 초과에 어떤 상태 코드를 쓰나?
8. (장애 진단) 크리덴셜 스터핑 공격 중에 일반 사용자도 로그인하지 못한다. 원인과, OWASP가 권하는 카운터 위치·잠금 방식은?
9. (장애 진단) 공유 한도에서 테넌트 A가 1000건, B가 10건을 보낸다(창당 100건). B는 몇 건 성공하나? 테넌트별 50건으로 나누면? 이 문제를 운영에서 어떻게 알아보나?
10. (장애 진단) 월 쿼터를 다 쓴 고객의 SDK가 몇 주째 몇 초마다 재시도한다. 응답 설계의 무엇이 잘못됐고 어떻게 고치나?
