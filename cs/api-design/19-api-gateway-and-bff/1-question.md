# api-design/19-api-gateway-and-bff — 질문

## 질문

1. (왜) 서비스를 여러 개로 나눈 뒤 클라이언트가 각 서비스를 직접 부르면 무엇이 문제인가? API 게이트웨이가 맡는 세 가지 일은?
2. (그림) Gateway Routing·Aggregation·Offloading·Gatekeeper·Valet Key를 한 그림에 놓고, 각각 무엇을 해결하는지 한 줄로 적어라.
3. (예측) nginx에 `location /api/`와 `location /api/orders/`를 이 순서로 적었다. `GET /api/orders/3`은 어느 쪽으로 가나? 순서를 바꾸면 결과가 달라지나?
4. (예측) API 키별 `rate=60r/m`, `burst=2 nodelay`, `limit_req_status 429`인 경로에 같은 키로 6건을 연달아 보내면 상태 코드 순서는? 키 헤더가 없는 요청을 따로 막지 않으면 `limit_req`는 그 요청을 어떻게 다루나?
5. (예측) 하위 서비스 지연이 50ms·80ms·3000ms일 때 순차·병렬(타임아웃 없음)·병렬+호출별 300ms 예산의 집계 응답 시간은 대략? 세 번째에서 응답은 어떤 모양이어야 하나?
6. (경계) 게이트웨이에 두면 안 되는 것은 무엇이고 왜인가? Azure 문서는 이를 어떻게 적나?
7. (경계) BFF를 두는 것이 맞는 경우와 맞지 않는 경우를 둘씩 대라. BFF의 소유자는 누구가 되어야 하나?
8. (연결) 대용량 업로드를 앱 서버가 중계하지 않게 하는 패턴은? 토큰에 넣을 제한과 남는 위험 두 가지는?
9. (장애 진단) 홈 화면 API의 p99가 추천 서비스 지연과 똑같이 움직인다. 무엇을 확인하고 어떻게 고치나?
10. (장애 진단) 게이트웨이에서 인증·속도 제한을 하는데도 일부 요청이 인증 없이 서비스에 도달한 흔적이 있다. 원인과 대처는?
