# api-design/17-graphql — 질문

## 질문

1. (왜) REST 자원 여러 개를 부르는 화면에서 GraphQL이 줄여 주는 것은 무엇인가? 대신 클라이언트가 쿼리를 마음대로 쓴다는 점이 서버에 만드는 새 문제 두 가지는?
2. (그림) `{ posts(limit: 10) { title author { name } } }`를 리졸버 그대로 실행하면 DB 쿼리가 몇 번 나가나? 리졸버 호출 트리를 그리고, 왜 그렇게 되는지 리졸버의 관점에서 설명하라.
3. (예측) 사용자 10명·글 100개(작성자 = i % 10)에서 `posts(limit: 100)`에 `author { name }`을 붙여 DataLoader로 실행하면 SQL은 몇 개이고, `IN` 목록에는 id가 몇 개 들어가나? 이유는?
4. (경계) DataLoader 배치 함수가 지켜야 할 계약 두 가지는? DB가 키와 다른 순서로 결과를 주거나 일부 키가 없으면 어떻게 하나?
5. (경계) DataLoader 인스턴스를 서버 전역 싱글턴으로 두면 무엇이 잘못되나? README는 어떻게 쓰라고 하나?
6. (예측) `User.posts`는 배치하지 않고 `Post.author`만 DataLoader로 감싼 상태에서 `posts { author { posts { author { ... } } } }`를 한 단계씩 깊게 하면 응답 크기와 SQL 수는 어떻게 변하나? DataLoader가 이 문제를 해결하지 못하는 이유는?
7. (연결) 쿼리 비용 방어를 파싱 전·검증·실행 중 단계로 나눠 하나씩 대라. graphql-js 16에 일반 깊이 제한 규칙이 내장돼 있나?
8. (장애 진단) HTTP 에러율 대시보드는 0%인데 사용자 화면의 일부 위젯이 비었다. GraphQL 응답에서 무엇을 봐야 하고, GraphQL over HTTP 초안은 이런 응답의 상태 코드를 어떻게 정하나?
9. (장애 진단) GraphQL 응답 `errors[].message`에 내부 DB 오류 문구가 보인다. 무엇이 문제이고 어떻게 고치나?
