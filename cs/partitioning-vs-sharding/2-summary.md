## 전체 흐름

```text
공통     큰 데이터를 작은 단위로 나눈다
차이     파티셔닝 = 논리적으로 하나인 테이블을 같은 DB 인스턴스 안에서 물리적으로 쪼갬
         샤딩     = 수평 파티셔닝을 여러 독립 DB 서버에 걸쳐 적용 — 각 샤드는 전체의 일부만 가진 독립 인스턴스
목적     파티셔닝은 쿼리 성능(프루닝)·관리(오래된 파티션 삭제), 샤딩은 스케일 아웃(단일 서버 한계 돌파)
대가     파티셔닝은 키를 잘못 잡으면 역효과, 샤딩은 조인·트랜잭션·핫스팟·리밸런싱 — 단점이 커서 신중해야 한다
```

## 1. Partitioning

하나의 큰 테이블을 더 작은 단위(파티션)로 나누는 기법. 핵심은 **논리적으로 하나의 테이블이지만 물리적으로 분할해서 저장**한다는 점이고, 보통 같은 DB 인스턴스 안에서 이뤄진다.

**방향**

- **수평(Horizontal)** — 행(row) 기준. 주문 테이블을 2024년 파티션, 2025년 파티션으로. 스키마는 동일하고 담긴 데이터만 다르다. 분할 기준에 따라 Range / List / Hash로 세분.
- **수직(Vertical)** — 열(column) 기준. 자주 조회되는 컬럼(이름, 이메일)과 드물게 조회되는 대용량 컬럼(프로필 소개글, 이미지)을 별도 테이블로. 정규화와 비슷해 보이지만 **이미 정규화된 테이블을 성능 목적으로 더 쪼갠다**는 점이 다르다.

**장점**: 파티션 프루닝으로 필요한 파티션만 스캔 → 쿼리 성능. 오래된 데이터의 손쉬운 삭제/아카이빙(파티션 drop), 관리 편의.
**단점**: 파티션 키를 잘못 잡으면 오히려 나빠진다(대부분의 쿼리가 키를 안 쓰면 모든 파티션을 훑는다). 조인이나 파티션 간 쿼리가 복잡해진다.

## 2. Sharding

데이터를 **여러 개의 독립적인 DB 서버(샤드)**에 분산 저장하는 기법. 본질적으로 수평 파티셔닝을 여러 물리 서버에 걸쳐 적용한 것이다. 각 샤드는 독립 DB 인스턴스이고 전체 데이터의 일부만 가진다. 예: 유저 ID 1~100만은 shard A, 100만~200만은 shard B.

**분산 방식**: Hash 기반(샤드 키를 해싱해 배정) · Range 기반(범위별) · Directory 기반(별도 매핑 테이블로 관리).

**가장 큰 목적은 스케일 아웃(수평 확장)** — 단일 서버의 저장 용량·CPU·메모리·커넥션 한계를 넘어서고, 부하가 여러 서버로 분산된다.

**단점이 생각보다 커서 도입 시 신중해야 한다**:

- 샤드 간 조인이 사실상 불가능하거나 매우 비싸다
- 트랜잭션을 여러 샤드에 걸쳐 보장하기 어렵다
- 특정 샤드에 데이터가 몰리는 핫스팟
- 샤드 추가 시 리밸런싱(재분배) 비용

## 3. 한 표로

```text
                 Partitioning                    Sharding
나누는 곳        같은 DB 인스턴스 안              여러 독립 DB 서버
논리적 모습      하나의 테이블 (DB가 투명하게)     애플리케이션/미들웨어가 어느 샤드인지 알아야 함
주 목적          쿼리 성능·관리                  스케일 아웃
조인·트랜잭션    DB 안에서 그대로 됨              샤드를 넘으면 어렵거나 불가
확장 한계        단일 서버의 한계 그대로           서버 수만큼
```

## 4. 연결 — Kafka의 파티션은 어느 쪽인가

Kafka의 "파티션"은 이름은 파티션이지만 동작은 샤딩에 가깝다 — 각 파티션이 다른 브로커에 놓이고, 파티션 간 순서·조인이 없고, `hash(key) % N`으로 배정하며, 파티션 수를 늘리면 기존 key의 배정이 깨진다(리밸런싱 비용). 샤딩의 단점 목록(핫스팟, 리밸런싱)이 그대로 Kafka 파티션 설계 주의사항에 다시 나온다(→ [kafka-why-fast](../kafka-why-fast/) §4).

## 핵심 문장

- 파티셔닝은 "한 DB 안에서 물리적으로 쪼갬", 샤딩은 "여러 DB 서버로 쪼갬" — 경계는 인스턴스다.
- 파티셔닝의 이득은 프루닝과 관리이고, 샤딩의 이득은 스케일 아웃이다. 목적이 다르다.
- 샤딩은 조인·트랜잭션을 포기하는 대가로 확장을 산다. 핫스팟과 리밸런싱은 샤드 키 선택이 결정한다.
- 수직 파티셔닝은 정규화가 아니라 이미 정규화된 것을 성능 목적으로 더 쪼개는 것이다.
