# reliability/47-server-design-antipatterns — 질문

## 질문

1. (왜) 서버 설계 안티패턴 대부분이 "좋은 의도"에서 나온다는 말을 예 둘로 설명하라. 공통으로 생기는 것은 무엇인가?
2. (그림) 숨은 결합 네 종류를 그리고, 각각에 원본 항목을 둘 이상 넣어라.
3. (계산) 99.9% 서비스 5개 직렬, 3계층이 각각 3회 시도, 2대 각 70% 이중화에서 1대 장애 — 각각 결과는? N대 이중화의 평소 사용률 상한은?
4. (예측) 인스턴스 3대가 각자 메모리 스케줄러로 자정 정산(100ms)을 실행한다. 조정 없음, 실행 중에만 잡는 advisory lock, 회차 유일 키 — 시각차 0ms와 150ms에서 지급 행 수는 각각 몇 개일까?
5. (경계) 4번에서 락이 시각차 150ms일 때 막지 못한 이유는? 락과 유일 키가 각각 기억하는 것은?
6. (연결) 회차 유일 키가 정확히 한 번을 만들려면 실행 기록과 지급이 어떤 관계여야 하나? 그렇지 않으면 무엇이 깨지나?
7. (적용) 운영 중인 시스템에서 "같은 회차 중복 실행", "한 대 빠지면 여유 없음", "무한 큐"를 찾는 쿼리를 하나씩 써라.
8. (장애 진단) 앱을 10대에서 30대로 늘리자 DB가 연결을 거절한다. 보이는 에러와 원인, 대처는?
9. (장애 진단) DB가 2초 느려졌을 뿐인데 전 인스턴스가 로드 밸런서에서 빠졌다. 무엇이 원인이고 헬스체크를 어떻게 나누나?
10. (경계) `Executors.newFixedThreadPool(8)`이 원본 8번(무한 큐) 안티패턴이 되는 이유와 처방은?
