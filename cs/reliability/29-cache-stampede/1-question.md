# reliability/29-cache-stampede — 질문

## 질문

1. (구분) 스탬피드·눈사태·관통을 "무엇이 몰리나"로 구분하고, 각각을 막는 대표 수단을 하나씩 대라.
2. (계산) 인기 키에 초당 2000요청이 오고 DB 재계산이 50ms 걸린다. 방어가 없으면 만료 순간 DB에 동시 조회가 대략 몇 개 들어가나? DB가 느려져 재계산이 200ms가 되면?
3. (예측) 만료 직후 동시 200요청(DB 조회 50ms)에 나이브 캐시, 싱글플라이트 1대, 각자 싱글플라이트를 가진 인스턴스 4대를 쓰면 DB 호출 수는 각각? 실험 수치로 답하라.
4. (경계) 싱글플라이트가 줄이는 것과 줄이지 못하는 것 두 가지는? 실험 B의 "50ms 넘게 기다린 요청" 수로 설명하라.
5. (원리) XFetch의 판정식을 쓰고 Δ·β·rand()가 각각 무슨 역할인지 설명하라. 왜 만료가 가까울수록 일찍 갱신할 확률이 커지나?
6. (예측) 1ms마다 1요청, TTL 1000ms, 재계산 100ms에서 XFetch만 쓰면 동시 재계산이 1로 줄까? 실험 결과와 이유, 그리고 고친 방법의 결과를 말하라.
7. (연결) Facebook memcache 리스는 스탬피드를 어떻게 막나? 프로세스 로컬 싱글플라이트에 비해 무엇이 다른가?
8. (예측) 키 1000개를 같은 시각에 채우고 TTL을 ±20% 지터로 흩뜨리면 DB 호출 **합**과 100ms 구간 **최대**는 각각 어떻게 바뀌나? 실험 수치로 답하라.
9. (장애 진단) 적중률이 낮고 DB 조회 결과가 대부분 0행이다. 무슨 사고이고, 무엇을 담거나 걸러야 하나? 부정 캐시 TTL을 길게 잡으면 생기는 부작용은?
10. (장애 진단) DB 장애가 끝났는데 특정 키만 계속 같은 예외를 낸다. 재시작하면 낫는다. 싱글플라이트 구현의 어디를 의심하나?
