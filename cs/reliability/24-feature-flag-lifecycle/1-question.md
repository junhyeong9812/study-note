# reliability/24-feature-flag-lifecycle — 질문

## 질문

1. (왜) 피처 플래그가 "배포와 릴리스를 분리한다"는 말의 뜻은? 그 대가로 무엇이 늘어나나?
2. (경계) Hodgson의 네 유형(릴리스·실험·운영·권한)을 수명과 판정의 동적성으로 구분하라. 킬 스위치는 어디에 들고, 다른 플래그와 관리가 어떻게 다른가?
3. (예측) 사용자 10,000명이 화면 10개를 연다. 새 UI 비율 20%를 요청마다 무작위로 정할 때와 사용자 해시 버킷으로 정할 때, 신·구를 섞어 본 사용자는 각각 몇 %일까? 계산식과 실험 값을 함께 써라.
4. (예측) 해시 버킷으로 20%에 켜 두었다가 50%로 올린다. 솔트를 그대로 둘 때와 바꿀 때, 20%일 때 켜졌던 사람 중 꺼지는 사람은 몇 명일까? 왜 그런가?
5. (경계) 해시 입력에 플래그 키를 넣지 않으면 무엇이 잘못되나? 실험 3의 1,959명과 407명이 각각 무엇을 뜻하나?
6. (장애 진단) 플래그 서비스가 내려간 순간 5%에만 열려 있던 미완성 기능이 전원에게 열렸다. 어떤 계약 때문에 이런 일이 생기고, 무엇으로 막나?
7. (연결) Knight Capital 2012 사고에서 플래그가 한 역할은? 배포 누락·죽은 코드·플래그 재사용이 어떻게 맞물렸나?
8. (적용) 플래그를 지울 때 코드 분기와 설정 중 무엇을 먼저 지우나? 순서를 거꾸로 하면 무엇이 보이나?
9. (경계) 플래그가 30개면 켜짐·꺼짐 조합은 몇 개인가? 다 테스트할 수 없다면 Hodgson은 어떤 조합을 테스트하라고 하나? 그 권고가 성립하려면 어떤 관례가 필요하나?
10. (적용) 플래그를 만들 때 등록부에 무엇을 적고, 방치를 막는 장치로 무엇을 두나?
