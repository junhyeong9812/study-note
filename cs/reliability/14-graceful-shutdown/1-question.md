# reliability/14-graceful-shutdown — 질문

## 질문

1. (왜) 우아한 종료의 여섯 단계(준비 해제 → 전파 대기 → 새 요청 거절 → 드레이닝 → 정리 → 종료) 중 "전파 대기"를 빼면 무엇이 깨지나? 쿠버네티스 파드 종료에서 이 틈이 생기는 구조적 이유는?
2. (예측) 800ms짜리 요청이 100ms마다 들어오는 서버를 종료 훅 없이 `docker stop` 한다. 종료는 몇 초 걸리고 종료 코드는 무엇인가? 같은 서버에 "준비 해제 → 1초 대기 → `HttpServer.stop(5)`" 훅을 걸면 실패 수는 어떻게 바뀌나?
3. (예측) 2번의 우아한 종료에서 `stop()`이 리스닝 소켓을 닫은 뒤에도 서버가 새 요청을 받을까? 받는다면 왜, 그리고 드레이닝 기한을 3초로 줄이면 무엇이 보이나?
4. (경계) 드레이닝 중 응답에 `Connection: close`를 붙이면 드레이닝은 빨리 끝난다. 그런데도 실패가 0이 되지 않을 수 있는 조건은?
5. (장애 진단) 파드 종료가 매번 정확히 유예 시간을 채우고 종료 코드 137로 끝난다. 종료 훅 로그는 없다. 무엇을 의심하고 무엇으로 확인하나?
6. (연결) Spring Boot 3.3과 3.4에서 `server.shutdown` 기본값은 각각 무엇인가? 쿠버네티스 기본 유예 시간과 Spring 기본 드레이닝 기한을 그대로 두고 `preStop`에 10초 sleep을 넣으면 무슨 문제가 생기나?
7. (설계) 유예 시간, 전파 대기, 드레이닝 기한, 정리 시간 사이의 부등식을 세워라. 어느 값을 먼저 정하고 무엇을 역산하나?
8. (연결) HTTP 서버만 드레이닝하고 Kafka 컨슈머·백그라운드 작업은 그냥 끊으면 어떤 현상이 나오나? 종료 순서에 무엇을 넣어야 하나?
