## 질문

1. (왜) 이 노트의 안티패턴들이 테스트·코드 리뷰를 통과하고 운영에서 터지는 공통 이유는? 리뷰 때 던질 질문 하나로 줄이면?
2. (예측) 같은 서버로 GET 300번을 보낸다. (a) 클라이언트 하나 재사용 (b) 요청마다 `new HttpClient`, 닫지 않음 (c) 요청마다 만들고 `close()`. 각각 클라이언트 쪽 연결·TIME_WAIT·스레드 수는 대략 어떻게 나오나? (c)는 왜 TIME_WAIT가 남나?
3. (장애 진단) 트래픽이 오를 때 외부 API 호출이 `Cannot assign requested address`로 간헐 실패한다. 무엇을 세어 보고, 원인을 어떻게 좁히고, 무엇으로 고치나?
4. (경계) Chatty I/O를 고치려다 Extraneous Fetching으로 가는 경로는? 둘 사이의 균형점은 무엇으로 잡나?
5. (예측) 요청 스레드 4개짜리 서버에 5초 걸리는 외부 호출 주문 8건이 동시에 온다. 0.5초 뒤 같은 서버의 `/health`(타임아웃 1초)는 성공하나? 외부 호출에 300ms 타임아웃을 주면 첫 헬스체크는 몇 ms쯤 걸리고 왜 그런가? 헬스체크를 별도 스레드로 분리하면?
6. (연결) 타임아웃과 격벽은 각각 무엇을 줄이고 무엇을 못 줄이나? 실험 결과로 설명하라.
7. (장애 진단) 몇 달 잘 돌던 서비스가 특정 고객 요청에서만 OOM으로 죽는다. 어떤 안티패턴을 의심하고, 무엇을 보고, 상한은 누가 정해야 하나?
8. (적용) 매일 00:00 DB CPU가 치솟는다. Dogpile과 Self-Denial은 어떻게 다르고, 각각 무엇으로 흩나?
