# reliability/22-capacity-and-load-testing — 질문

## 질문

1. (계산) 클러스터 하나의 한계가 5,000 QPS, 서비스 피크가 19,000 QPS다. N + 2로 몇 개 클러스터가 필요한가? 대당 한계는 왜 "추정"이 아니라 "측정"이어야 하나?
2. (그림) open 모델과 closed 모델의 요청 흐름을 시간축으로 그려라. 서버가 느려질 때 두 모델의 도착률은 각각 어떻게 되나?
3. (선택) 다음 각각에 open과 closed 중 무엇이 맞나? (a) 공개 쇼핑몰 API (b) 큐에서 꺼내 처리하는 배치 워커 8개 (c) 정원 50명 콜센터 상담 화면.
4. (예측) 워커 16개, 캐시 적중 2ms·미스 20ms인 서비스에 도착률 1,800/s를 넣는다. 테스트 키 2,000개 균등일 때와, 운영처럼 100만 개 Zipf일 때 p99와 처리량은 어떻게 다른가? 실험 숫자로 답하라.
5. (계산) 4번 서비스의 prod 분포 적중률이 57%다. 대당 한계를 계산하고 실험의 1,800/s 처리량(1,629/s)과 비교하라. 캐시가 완전히 비면 한계는?
6. (예측) 같은 prod 서비스를 closed 모델(사용자 200명, think 100ms)로 재면 처리량과 p99는? 대화형 응답 시간 법칙으로 평균 응답 시간을 검산하라.
7. (경계) 실험의 open 모델은 지연을 "요청을 실제로 보낸 시각"이 아니라 "도착 예정 시각"부터 쟀다. 왜 그래야 하나?
8. (연결) 지연 캐시와 용량 캐시를 구분하라. 실험 서비스는 어느 쪽이고, 부하 테스트에 무엇을 더 넣어야 하나?
9. (장애 진단) 부하 테스트 도구의 RPS가 목표보다 낮은 채로 평평하고, 서버 CPU는 40%다. 무엇을 의심하고 어떻게 확인하나?
10. (장애 진단) 평소 이용률 85%로 운영하던 서비스가 피크에 한 대를 잃자 나머지가 연쇄로 넘어졌다. 왜 그렇고, 부하를 조금 줄이면 회복되나? 무엇으로 막나?
