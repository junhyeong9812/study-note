# reliability/08-time-budget-allocation — 질문

## 질문

1. (그림) 총 예산 1000ms 요청의 예산표를 그려라. 무엇을 먼저 예약하고, 직렬 단계와 병렬 단계는 각각 어떻게 합하나?
2. (왜) AWS Builders' Library는 하류 호출 타임아웃을 어떻게 고르라고 하나? 이 방법이 맞지 않는 두 경우와 그때의 보정은?
3. (예측) 하류 지연이 정상 94.5%·느림 5%·멈춤 0.5%인 모델(시도 독립)에서, 단계 예산 1000ms 안에 "per-try 없이 최대 3회"로 재시도하면 시도/요청과 성공률은 단일 시도와 비교해 어떻게 되나? 왜인가?
4. (예측) 같은 모델에서 per-try를 p50(83ms)로 두고 최대 3회면 성공률과 하류 부하(시도/요청)는 대략 얼마인가? 식으로 설명하라.
5. (경계) Envoy의 route `timeout`과 `per_try_timeout`은 어떤 관계여야 하나? per-try는 언제까지만 적용되나? 전체 timeout을 넘겨 504가 나면 재시도하나?
6. (연결) "남은 예산이 최소치 미만이면 시작하지 않는다"는 규칙의 근거(SRE 22장)는? 실험에서 이 규칙의 효과가 작게 나온 이유와, 효과가 커지는 조건은?
7. (장애 진단) 장애 때 폴백이 있는데도 사용자는 504를 본다. 폴백 실행 로그는 거의 없다. 원인과 대처는?
8. (장애 진단) 하류 지연이 조금 오르자 하류 요청량이 사용자 요청량의 거의 두 배가 되고 장애가 커졌다. 타임아웃 설정에서 무엇을 의심하나?
9. (경계) 이 노트 실험의 "시도는 서로 독립" 가정은 언제 깨지나? 깨지면 per-try + 재시도는 무엇을 하게 되나?
