# reliability/21-scaling-principles — 질문

## 질문

1. (왜) "병목은 없어지지 않고 옮겨 간다"를 앱 서버 → 커넥션 풀 → DB 순서로 설명하라. 병목 자원이 한 건에 D초를 쓰면 처리량 상한은 얼마인가?
2. (계산) 피크 800 req/s, 부하 상태 평균 응답 0.25초다. Little's Law로 필요한 동시 처리 수는? 인스턴스 4대에 여유 25%를 두면 인스턴스당 스레드는 몇 개인가? 이 숫자가 틀어지는 조건 하나를 대라.
3. (경계) Little's Law가 성립하는 조건은 무엇이고, 어떤 상황에서 L이 수렴하지 않나? 도착이 포아송이 아니어도 쓸 수 있나?
4. (그림) USL 식을 쓰고, α=β=0 / β=0 / β>0일 때 처리량 곡선을 그려라. 정점 N_max의 식은?
5. (예측) 노드마다 2ms 대기 + 전역 락 0.1ms(contention)인 경우와, 거기에 다른 노드마다 락 0.02ms를 더한 경우(coherence)를 N=1→64로 늘린다. 각각 처리량이 어떤 모양이 되나? 실험의 실제 숫자와 비교하라.
6. (연결) 실험의 닫힌 루프에서 L = N이다. contention 모드 N=64의 처리량이 5,016 req/s였다면 평균 W는? 측정값과 비교하라.
7. (경계) 실험 contention 모드에서 USL을 적합하니 β가 0이 아니게 나왔다. 이것을 "조율 비용이 있다"로 읽어도 되나? coherence 모드의 α가 음수인 것은?
8. (연결) 무상태화가 수평 확장의 전제인 이유는? 상태를 밖으로 밀어내면 USL의 α·β 관점에서 무엇이 새로 생기나?
9. (장애 진단) 노드를 8 → 16대로 늘렸더니 처리량이 줄었다. 인스턴스당 CPU는 낮다. 무엇을 보고 원인을 좁히며, 어떻게 고치나?
10. (장애 진단) 평소 W = 50ms로 풀 크기를 정한 서비스에서 하류 지연이 500ms가 되자 무관한 엔드포인트까지 느려졌다. Little's Law로 설명하고 대처를 적어라.
