# reliability/20-performance-method-and-amdahl — 질문

## 질문

1. (왜) 성능 작업에서 "한 번에 한 가지만 바꾸고 같은 조건으로 재측정"을 고집하는 이유는? 여러 개를 한꺼번에 바꾸면 무엇을 잃나?
2. (계산) 전체의 5%인 구간을 2배 빠르게 하면 전체 실행 시간은 몇 % 주나? 95% 구간을 2배 빠르게 하면? 직렬 부분이 10%인 프로그램을 코어 무한대로 돌리면 최대 몇 배인가?
3. (예측) 실험 2에서 5% 구간만 2배 빠르게 한 결과는 예측(2.5% 단축)대로 나왔나? 왜 그렇게 나왔고, 여기서 얻는 실무 교훈은?
4. (그림) USE 체크리스트를 그려라. 실험 3의 시스템(워커 + 커넥션 4개 풀)에서 U·S·E는 각각 무엇으로 보이나?
5. (예측) 요청이 앱 처리 5ms + DB 호출 10ms(풀 4개)다. 워커를 2 → 4 → 8 → 32로 늘리면 처리량과 요청당 지연은 어떻게 되나? 워커 32일 때 Little's Law로 평균 체류 시간을 계산하고 실험값과 비교하라.
6. (경계) Amdahl의 법칙이 설명하지 못하는 확장 실패는 무엇인가? 그때는 어떤 모델을 쓰나?
7. (연결) Gregg의 안티 방법론 중 Streetlight와 Random Change를 설명하라. Random Change는 측정을 하는데도 왜 안티 방법론인가?
8. (장애 진단) JVM·커널 플래그 다섯 개를 한 배포에서 바꾼 뒤 일주일 만에 p99 회귀가 났다. 원인을 어떻게 찾고, 앞으로 어떻게 막나?
9. (적용) 주문 API p99가 SLO의 3배다. 첫날 할 일을 순서대로 적어라(문제 정의 질문, 측정, 병목 특정, 개선 후보 순위 매기기).
