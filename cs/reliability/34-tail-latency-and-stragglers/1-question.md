# reliability/34-tail-latency-and-stragglers — 질문

## 질문

1. (계산) 리프 하나가 1초 넘게 걸릴 확률이 1%다. 루트가 리프 10개·100개·1000개를 전부 기다리면 사용자 요청이 1초를 넘을 확률은? 1만 건 중 1건만 느린 리프 2000개라면?
2. (예측) 실험 1에서 N=100일 때 사용자 요청의 p50은 얼마로 나왔나? 이것이 "리프의 p99가 사용자의 중앙값이 된다"는 말과 어떻게 이어지나?
3. (왜) Dean–Barroso는 꼬리를 "없애기"보다 "견디는" 기법이 필요하다고 본다. 리프가 느려지는 원인 몇 가지를 들고, 왜 견디는 쪽이 현실적인지 설명하라.
4. (그림) hedged request와 tied request를 각각 시간축으로 그려라. 두 번째 요청을 언제 보내고, 중복 실행을 어떻게 줄이나?
5. (예측) 실험 2(복제본 2개, 400건/s)에서 hedge@10ms는 p99와 추가 실행을 어떻게 바꿨나? 논문의 BigTable 수치와 같은 모양인가?
6. (예측) 같은 시스템에 600건/s를 걸고 hedge@0ms(처음부터 두 복제본에)를 쓰면 무슨 일이 생기나? 복제본 사용률로 설명하라.
7. (경계) 실험에서 tied@1ms는 추가 실행 없이 꼬리를 줄였지만, 400건/s의 p99는 hedge@10ms보다 높았다. 왜인가? 두 기법이 각각 어떤 꼬리를 줄이나?
8. (연결) hedge를 쓰려면 요청이 어떤 성질을 가져야 하나? gRPC `retryThrottling`이 hedge 과다를 막아 주지 못하는 경우는?
9. (장애 진단) 리프 서비스들은 각자 p99 SLO를 지키는데 사용자 페이지 p50이 1초다. 무엇을 계산·측정하고 어떻게 대처하나?
10. (장애 진단) hedge 비율은 3%인데 하류 CPU가 30% 늘었다. 무엇을 의심하고 어떻게 고치나?
