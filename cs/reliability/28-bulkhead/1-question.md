# reliability/28-bulkhead — 질문

## 질문

1. (왜) 공용 요청 스레드 풀 하나를 여러 하류가 쓸 때 무엇이 일어나나? 서킷 브레이커가 이것을 막지 못하는 구간은?
2. (그림) 세마포어 격벽과 스레드풀 격벽을 그림으로 비교하라. 각각 하류 호출은 어느 스레드에서 실행되나?
3. (예측) 요청 스레드 20개, 추천 하류 1000ms, 결제 10ms. 500ms 동안 추천 100건과 결제 25건이 섞여 온다. 격벽이 없을 때 결제 지연 p50은 대략 얼마인가? 추천에 세마포어 격벽 4칸(대기 0)을 주면?
4. (예측) 같은 상황에서 추천 격벽의 `maxWaitDuration`을 2초로 주면 결제 지연은 격벽이 없을 때보다 좋아지나 나빠지나? 이유는?
5. (경계) 추천 전용 스레드 풀(4 스레드, 큐 10)에 넘기고 호출자가 200ms 뒤 포기한다. 결제는 빨라지는데, 하류 쪽에서는 무엇이 그대로 남나? 무엇으로 막나?
6. (경계) Resilience4j 2.4.0 `BulkheadConfig`·`ThreadPoolBulkheadConfig`의 기본값은? 스레드풀 격벽 기본값이 기계마다 다른 이유는?
7. (연결) 결제 격벽 칸이 10인데 결제용 커넥션 풀이 5면 무엇이 보이나? 격벽은 어디에 두어야 하나?
8. (연결) `BulkheadFullException`을 서킷 브레이커가 실패로 세면 어떤 일이 생기나?
9. (적용) 격벽 칸 수는 무엇으로 잡나? 초당 50건, 하류 평균 지연 0.2초면 몇 칸인가(예시 계산)?
10. (장애 진단) 추천 하류만 느려졌는데 결제·로그인까지 타임아웃 난다. 무엇을 보고 원인을 좁히나?
