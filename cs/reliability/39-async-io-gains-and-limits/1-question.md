# reliability/39-async-io-gains-and-limits — 질문

## 질문

1. (왜) 가상 스레드·논블로킹 I/O가 늘려 주는 것은 무엇이고 늘려 주지 못하는 것은 무엇인가? Little's Law로 설명하라.
2. (예측) 2코어 컨테이너에서 100ms I/O 대기 작업 1만 개를 플랫폼 스레드 풀 200과 가상 스레드로 각각 돌린다. 처리량과 "작업 본문 시간"은 각각 어떻게 되나? 실험 숫자로 답하라.
3. (예측) 같은 환경에서 약 150ms짜리 CPU 계산 16건을 플랫폼 풀 2와 가상 스레드로 돌리면? 이유는?
4. (예측) DB 커넥션 10개, 쿼리 20ms, 커넥션 대기 한도 300ms인 서비스에 요청 2,000건이 한꺼번에 온다. 플랫폼 풀 50과 가상 스레드에서 각각 무슨 일이 나나? 대략 몇 건이 성공하나?
5. (경계) JDK 21 가상 스레드의 "고정(pinning)"이란 무엇이고 언제 생기나? 고정과, 파일 I/O처럼 운반 스레드를 붙잡는 블로킹은 스케줄러가 어떻게 다르게 다루나?
6. (예측) 가상 스레드 100개가 각자 다른 객체에서 락을 잡고 50ms 블로킹한다. `synchronized`와 `ReentrantLock`으로 JDK 21과 JDK 25에서 각각 몇 초 걸리나? 왜 다른가?
7. (계산) 가상 스레드로 작업 6,000개를 내고, 각 작업이 64KB 버퍼를 잡고 200ms를 기다린다. 동시 한도 200이면 걸리는 시간은? 한도를 없애면 메모리는 어떻게 되나?
8. (연결) JEP 444는 가상 스레드를 풀로 묶지 말라고 한다. 그러면 하류 동시 접근은 무엇으로 제한하나? 코드로 보여라.
9. (장애 진단) WebFlux로 옮긴 뒤 부하가 조금만 와도 전부 느려진다. 스레드 덤프에서 무엇을 보고, 어떻게 고치나?
10. (장애 진단) 가상 스레드 전환 후 피크에 `Connection is not available, request timed out after …ms`가 쏟아진다. 원인과 대처를 쓰라. 풀 크기를 키우는 것이 왜 첫 대처가 아닌가?
