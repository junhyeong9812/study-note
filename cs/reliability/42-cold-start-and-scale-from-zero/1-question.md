# reliability/42-cold-start-and-scale-from-zero — 질문

## 질문

1. (그림) 요청이 왔는데 인스턴스가 없을 때부터 제 속도가 날 때까지의 구간을 순서대로 그려라. Lambda의 Init 단계는 어디까지이고, 어떤 세 작업으로 이루어지나?
2. (경계) Lambda Init 단계의 시간 제한은? 넘으면 어떻게 되나? 이 제한이 적용되지 않는 구성은?
3. (예측) 작은 Java HTTP 서버(JDK 21)를 띄우고 순차 요청 2,000건을 보낸다. 첫 요청, 2~10번, 11~100번, 1,001번 이후의 서버 처리 시간은 대략 어떻게 되나? 실험 숫자로 답하라.
4. (경계) 3번 실험을 `-Xint`(JIT 끔)로 돌리면 첫 요청과 이후 요청은 어떻게 되나? 이 결과로 "첫 요청이 느린 것"과 "워밍업"을 어떻게 구분할 수 있나?
5. (비교) 같은 앱에서 JDK 21 AppCDS와 JDK 25 AOT 캐시는 시작→READY, 시작→첫 응답을 각각 얼마나 줄였나? AOT 캐시를 쓰려면 훈련 실행과 운영 실행이 무엇을 맞춰야 하나?
6. (설계) readinessProbe와 startupProbe를 콜드 스타트 관점에서 어떻게 설계하나? startupProbe가 300초를 허용하려면 설정은?
7. (계산) 피크에 초당 200건, 평균 실행 시간 0.25초인 Lambda 함수에 provisioned concurrency를 몇으로 두어야 피크의 콜드 스타트를 피하나? 평균 초당 80건으로 계산하면 무엇이 문제인가?
8. (경계) SnapStart가 빠른 이유는? 스냅숏 복원 때문에 생기는 문제 두 가지와 대처는?
9. (장애 진단) 오토스케일이 동작할 때마다, 그리고 배포 직후 몇 분간 p99만 튄다. 평균은 멀쩡하다. 무엇을 보고 어떻게 고치나?
10. (장애 진단) 한동안 호출이 없던 API의 첫 요청이 게이트웨이에서 타임아웃 나고 재시도하면 빠르다. 로그에서 무엇을 보고 어떤 순서로 줄이나?
