# reliability/25-high-availability-topology — 질문

## 질문

1. (왜) 이중화를 하면 새로 생기는 문제 세 가지는? 각각 어떤 사고로 나타나나?
2. (그림) 페일오버를 탐지·결정·전환 세 단계로 그리고, 각 단계에서 틀리면 무슨 일이 생기는지 적어라. 탐지가 "추정"일 수밖에 없는 이유는?
3. (그림) HEALTHY·SUSPECT·DOWN 헬스 판정 상태 기계를 그려라. failureThreshold와 successThreshold는 각각 무엇을 막나?
4. (예측) 0.5초마다 검사(타임아웃 0.3초)하는 판정기에 임계값 1·3·6을 둔다. 주 노드가 1.2초 멈춤, 2.5초 멈춤, 진짜 죽음을 차례로 겪으면 임계값마다 페일오버 결정이 몇 번 나오고 진짜 죽음은 몇 초 뒤 잡힐까? 실험 결과와 비교하라.
5. (경계) Kubernetes probe 기본값(periodSeconds·timeoutSeconds·failureThreshold·successThreshold)으로 두면 응답하지 않는(프로세스는 살아 있는) 컨테이너를 대략 몇 초 뒤에 실패로 보나?
6. (경계) split-brain을 막는 데 쿼럼과 펜싱이 각각 맡는 몫은? 쿼럼만 있고 펜싱이 없으면 무엇이 남나?
7. (연결) GitHub 2018-10-21 사고에서 43초 단절이 24시간 11분 저하가 된 경로를 설명하라. 도구는 "설정대로" 동작했는데 무엇이 문제였나?
8. (경계) 주·부를 같은 AZ에 두면 병렬 합성 공식 1 − (1−A)²이 왜 틀리나? 01 노트의 공통 원인 실험 결과와 연결하라.
9. (적용) 주 DB 고장을 10초 안에 잡되 최대 2초짜리 GC 멈춤으로는 승격하지 않게 하려면 검사 간격·타임아웃·임계값·관찰자 수를 어떻게 고르나?
10. (장애 진단) 페일오버 직후 새 주가 부하를 못 버티고 같이 쓰러졌다. 무엇을 보고, 무엇을 고치나?
