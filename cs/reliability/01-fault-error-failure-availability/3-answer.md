# reliability/01-fault-error-failure-availability — 정답

## 정답

### 1. 결함·오류·고장

- 고장(failure): 내보낸 서비스가 올바른 서비스에서 벗어나는 **사건**. 오류(error): 이후 고장으로 이어질 수 있는 **상태의 일부**. 결함(fault): 오류의 원인으로 판정·가정된 것(논문 2.2절).
- 주문 서비스 입장
  - 결함: DB 디스크 불량(주문 서비스 밖에서 온 외부 결함).
  - 오류: 캐시에 들어간 깨진 값.
  - 고장: 사용자에게 나간 틀린 잔액.
- DB 팀 입장: 디스크 불량은 DB 안의 결함이고, DB가 틀린 값을 내준 순간이 **DB의 고장**이다. 이 고장이 주문 서비스에는 외부 결함으로 들어간다(3.5절 사슬). 어느 경계에서 보느냐로 이름이 바뀐다.

### 2. 가용성 vs 신뢰성

- 가용성: 올바른 서비스를 내줄 **준비가 된 정도**. 신뢰성: 올바른 서비스가 **끊기지 않고 이어지는 정도**(2.3절).
- 1시간에 1초 끊김: 가용성은 1 − 1/3600 ≈ 99.97%로 높다. 신뢰성(끊김 없이 이어지는 시간)은 1시간 남짓이라 낮다. 긴 작업(1시간 넘는 업로드)에는 신뢰성이 문제다.

### 3. 두 가지 가용성

- 시간 기반 = 가동 시간 / (가동 + 중단). 요청 기반 = 성공 요청 / 전체 요청(SRE 3장).
- 1대 장애로 10% 실패: 서비스는 "떠 있으니" 시간 기반으로는 100%로 셀 수 있다. 요청 기반으로는 그 기간 90%다.
- SRE 3장: 전 세계에 퍼진 서비스는 어딘가에서는 늘 일부가 동작해 "가동 시간"이 의미가 약하다. 그래서 요청 성공률로 정의한다.

### 4. 99.9% 직렬 5개

- 0.999⁵ = 99.5010%(실험 공식). 시뮬레이션 99.4957%(200년치·seed 고정 — 표본 오차 범위).
- 월 허용 중단: 99.9%는 43.2분, 99.5%는 3.6시간(SRE 부록 A). 약 다섯 배로 늘었다.

### 5. MTTF·MTTR 두 부품

- 999/(999+1) = 99.9%, 499.5/(499.5+0.5) = 99.9%. 같다(실험 공식 두 줄).
- 다른 것: 둘째 부품은 고장이 두 배 잦고 한 번이 짧다. 사용자는 끊김을 두 배 자주 겪는다. 끊김 한 번이 비싼 일(긴 트랜잭션·세션 유실)이면 첫째가 낫고, 짧은 끊김을 재시도로 흡수할 수 있으면 둘째도 괜찮다.

### 6. RBD 계산

```text
 ──┬─[LB 99.9]─┬──┬─[앱 99]─┬──[DB 99.95]──
   └─[LB 99.9]─┘  ├─[앱 99]─┤
                  └─[앱 99]─┘
 LB 병렬 = 1−0.001² = 0.999999
 앱 병렬 = 1−0.01³  = 0.999999
 전체   = 0.999999 × 0.999999 × 0.9995 ≈ 99.9498%  (실험 출력과 같다)
```

- 손볼 곳: DB. 병렬 칸은 이미 99.9999%라 더 좋아져도 거의 안 오른다. 직렬 칸에서 가장 약한 DB가 상한(99.95%)을 정한다. DB 이중화(복제 + 자동 페일오버)가 가장 크게 올린다. 단 페일오버 자체의 실패와 공통 원인을 함께 계산한다.

### 7. 병렬 식의 가정

- 부품이 **독립적으로** 고장 난다는 가정이다.
- 실험: 99% 부품 둘을 독립으로 두면 99.9903%(공식 99.99%). 둘을 함께 쓰러뜨리는 공통 원인(단독 99.8953%)을 넣자 99.8856%로 떨어졌다. 공통 원인의 가용성 아래다. 이중화의 이득이 공통 원인에서 막혔다.

### 8. 부품은 다 지켰는데 SLA 위반

- 볼 것: 게이트웨이(종단)에서 잰 성공률, 요청 경로의 직렬 의존성 수, 각 서비스의 측정 가용성.
- 설명: 약속은 종단에 걸렸는데 목표는 부품에 걸렸다. 직렬 5개면 0.999⁵ ≈ 99.5%라 부품이 모두 목표를 지켜도 종단 99.9%는 깨질 수 있다.
- 바꿀 것: 종단 SLI를 게이트웨이에서 재고(그 앞 DNS·LB 실패는 클라이언트 쪽 측정·합성 프로브로 따로), RBD로 계산한 값보다 낮게 SLA를 잡는다. 부품 목표를 종단보다 높게 두고, 직렬 칸을 비동기·폴백으로 줄인다.

### 9. 에러 없이 틀린 정산

- 신호 없는 고장(unsignaled failure)이다. 내용 고장(content failure)이기도 하다 — 시간이 아니라 값이 틀렸다(3.3.1절). 그 전 단계에서는 탐지되지 않은 오류, 곧 잠재 오류(latent error — 3.4절)가 쌓였다.
- 막는 법: 상태를 직접 검사하는 장치 — 정기 대조, 불변식 검사(합계·건수), 체크섬. 탐지 장치가 실제로 도는지도 감시한다. "에러율 0"은 "틀리지 않음"이 아니다.
