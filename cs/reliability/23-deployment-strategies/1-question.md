# reliability/23-deployment-strategies — 질문

## 질문

1. (왜) 배포 전략이 가용성 설계의 일부인 이유를 SRE 책 1장이 든 숫자와 권하는 세 가지 관행으로 설명하라.
2. (그림) 인스턴스 4대를 기준으로 재생성·롤링·블루그린·카나리를 시간축으로 그려라. 각각 신·구 공존 구간이 얼마나 긴가?
3. (예측) 사용자가 "폼 받기 → 제출" 두 요청을 보낸다. 새 버전이 토큰 형식을 바꿨고 옛 버전은 새 형식을 못 읽는다. 새 버전 비율이 5%·25%·50%일 때 흐름이 깨지는 비율은? 실험의 카나리 5% 결과와 비교하라.
4. (예측) 같은 실험에서 롤링·블루그린·롤링(확장 배포 `v2read`)의 토큰 거절 합계를 순서대로 예측하고, 실제 값이 왜 그렇게 나왔는지 설명하라.
5. (경계) Kubernetes Deployment의 롤링 업데이트가 해 주는 것과 해 주지 않는 것은? `maxSurge`·`maxUnavailable`·`progressDeadlineSeconds`·`revisionHistoryLimit`의 기본값과 의미를 들어라.
6. (경계) "롤백하면 원래대로 돌아간다"는 말이 틀리는 경우 세 가지를 들어라. Knight Capital 사고에서 롤백 시도가 어떤 결과를 냈나?
7. (연결) 확장 배포(읽기 먼저, 쓰기 나중)는 DB의 expand/contract와 어떻게 같은 구조인가? 배포를 몇 번에 나눠야 하나?
8. (경계) 카나리 판정에서 before/after 비교가 위험한 이유는? 무엇과 비교해야 하나?
9. (장애 진단) 블루그린 전환 직후 몇 초 동안 "socket hang up"류 오류가 몇 건 나오고 사라졌다. 원인 가설과 확인 방법, 대처는?
10. (장애 진단) 배포를 시작하면 오류율이 오르고 배포가 끝나면 내려간다. 롤백해도 롤백 중에 다시 오른다. 무엇을 보고 어떻게 고치나?
