# reliability/40-batching-and-round-trips — 질문

## 질문

1. (왜) 서버가 초당 10만 요청을 처리할 수 있어도, RTT 250ms 링크에서 한 건씩 기다리는 클라이언트는 초당 몇 요청밖에 못 하나? 파이프라이닝이 RTT 말고 또 줄여 주는 비용은?
2. (예측) 같은 5000행을 자동 커밋 1행씩 / 한 트랜잭션 1행씩 / 1000행 배치 / 배치 + `reWriteBatchedInserts` / `COPY`로 넣으면 순위와 대략의 시간은? (실험 1)
3. (경계) 실험 1의 직결 환경에서 자동 커밋 1행씩이 한 트랜잭션 1행씩보다 20배 가까이 느렸다. RTT 때문인가, 다른 것 때문인가? 어떻게 확인했나?
4. (예측) RTT를 약 3ms로 늘리면 위 다섯 방식 중 어느 것이 크게 느려지고 어느 것은 거의 그대로인가? 이유는?
5. (그림) 크기 트리거 + 시간 트리거 배처를 그려라. 항목 하나가 버퍼에서 기다리는 최대 시간을 식으로 쓰고, 실험 2(maxSize 100, maxWait 20ms)의 50건/s·5000건/s 결과로 확인하라.
6. (경계) redis-benchmark에서 파이프라인 길이를 1 → 16 → 100으로 늘리자 처리량과 p50 지연은 각각 어떻게 변했나? 무엇을 뜻하나?
7. (경계) 배치가 너무 크면 생기는 문제 세 가지를 제품 한도와 함께 들어라.
8. (연결) DataLoader의 배치 함수가 지켜야 할 규칙 두 가지는? 키 하나만 없을 때는 무엇을 돌려주나? 기본 `maxBatchSize`는?
9. (장애 진단) 10행 JDBC 배치 중 1건이 중복 키다. pgjdbc 42.7.4 + PostgreSQL 17에서 결과와 테이블 상태는? 같은 상황이 Redis 파이프라인이라면? 각각 어떤 장애로 이어질 수 있나?
10. (적용) 야간 적재가 1건씩 INSERT로 수 분 걸린다. 고치는 순서와, 고친 뒤 확인할 것을 적어라.
