# reliability/38-microbenchmarking — 질문

## 질문

1. (왜) `System.nanoTime()` 두 번으로 메서드 하나를 재면 JVM에서 무엇이 측정을 왜곡하나? 세 가지를 들어라.
2. (예측) JMH에서 `void deadCode() { compute(x); }`, `int returned() { return compute(x); }`, 빈 `baseline()`을 재면 각각 대략 어떤 값이 나오나? `deadCode`가 baseline과 같다면 무엇을 뜻하나? (실험 1로 확인)
3. (경계) 입력을 `final int fx = 42`에서 읽는 벤치마크와 `int x = 42`(비-final)에서 읽는 벤치마크는 왜 다르게 나오나? JMH 샘플은 IDE의 어떤 조언을 무시하라고 하나?
4. (경계) 결과가 둘인 벤치마크에서 하나만 반환하면 무엇이 문제인가? 해결 방법 두 가지는?
5. (예측) 실험 2에서 같은 계산을 1만 회 묶음으로 반복 측정했다. 1번째·100번째·300번째 묶음의 ns/op는 어떻게 나왔나? 결과를 버린 손 루프는 제거됐나? 여기서 얻는 교훈은?
6. (그림) JMH 기본 실행 구조(포크·워밍업·측정)를 그리고 JMH 1.37의 기본값을 적어라. 포크는 무엇을 막나?
7. (예측) `@Fork(0)`으로 `c1` → `c2` → `c1 again` 순서로 재면 `c1`의 처음과 다시 잰 값은 어떻게 다른가? 왜 그런가? (실험 3)
8. (연결) A 37 ± 17ns, B 33 ± 5ns다. B가 빠르다고 말할 수 있나? Georges 외(2007)는 자바 성능 비교에서 무엇을 권하나?
9. (장애 진단) "새 파서가 100배 빠르다"는 PR의 벤치마크 결과가 0.4 ns/op다. 무엇을 의심하고 어떻게 확인하나?
10. (적용) JSON 직렬화 라이브러리 두 개를 비교하는 JMH 벤치마크를 설계하라. 입력 준비, 결과 소비, 파라미터, 실행 옵션, 보고 항목을 포함하라.
