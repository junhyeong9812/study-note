## 질문

1. (왜) 메모리보다 큰 데이터를 메모리 안 정렬로 처리하면 무엇이 일어나나? 외부 정렬은 이를 어떤 두 단계로 피하나?
2. (그림) 런 4개를 최소 힙으로 4-way 병합하는 과정을 그려라. 힙에는 무엇이 들어 있고, pop 다음에 무엇을 push하나?
3. (계산) 입력 N 블록, 메모리 B 블록일 때 런 수·병합 패스 수·총 I/O를 식으로 써라. N = 1,000, B = 11이면 각각 얼마인가?
4. (예측) 128MB 파일을 `-Xmx64m`에서 16MB 런 8개로 나눠 외부 정렬한다. 팬인 8·4·2에서 병합 패스 수와 "디스크에 쓴 바이트 ÷ 입력"은 각각 얼마일까?
5. (경계) 팬인을 무작정 키우면 안 되는 이유는? 무엇과 무엇을 맞바꾸나?
6. (예측) k개 런을 병합할 때 원소 하나를 내보내는 데 드는 비교 수는 선형 탐색과 최소 힙에서 각각 k에 대해 어떻게 자라나? k=512에서 Java `PriorityQueue`로 잰 값이 log₂ k보다 큰 이유는?
7. (경계) 대체 선택은 무엇이고, 무작위·정렬·역순 입력에서 런 길이는 메모리 크기 M에 비해 각각 어떻게 되나? PostgreSQL은 왜 이것을 버렸나?
8. (장애 진단) 대시보드 쿼리 계획에 `Sort Method: external merge  Disk: 26936kB`가 보이고 느리다. 무엇이 일어났고, 메모리를 전역으로 올리는 것 말고 어떤 대처가 있나?
9. (장애 진단) 외부 정렬 배치가 끝났는데 출력 행 수가 입력보다 적다. 에러는 없다. 의심할 원인과 막는 검증은?
10. (연결) "정렬된 것 여러 개를 하나로 합친다"는 이 노트의 연산이 LSM compaction·정렬 병합 조인·MapReduce에서 각각 어디에 나오나?
