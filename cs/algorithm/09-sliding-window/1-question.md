- 결과 배열(sums)의 길이가 왜 n-k+1인가?
- 폭을 10에서 1,000으로 100배 넓혔는데 읽기가 19,990에서 19,000으로 오히려 준 이유는?

#### 2. 가변 폭 — VariableWindow (TODO 5~6)

```java
/**
 * 합이 target 이상인 가장 짧은 구간의 길이. 없으면 0.
 * 값이 전부 양수여야 한다.
 */
public static int shortestAtLeast(CountedArray a, long target);

/** 같은 값이 두 번 안 나오는 가장 긴 구간의 길이. */
public static int longestDistinct(CountedArray a);

// TODO 5: 왼쪽을 당기는 것은 while 인가 if 인가. 왜 그런가.
//   답의 길이를 언제 재야 하나. 당기기 전인가 당긴 후인가.
//   안쪽 while 만 보면 O(n^2) 처럼 보인다. 그런데 아니다.
//   음수가 섞이면 왜 이 방법이 무너지나.
//   target 이 0 이하로 들어오면 답이 무엇인가.
// TODO 6: 값마다 마지막으로 본 자리를 기억해두면 왼쪽을 한 번에 옮길 수 있다.
//   그런데 그 자리가 이미 창 밖일 수 있다. 그때도 옮기면 무슨 일이 생기나.
```

- 왼쪽을 당기는 것이 `if`가 아니라 `while`이어야 하는 이유는?
- 답의 길이를 당기기 전에 재야 하는 이유는 — 당긴 뒤에 재면 무엇이 틀리는가?
- 답이 없을 때 무엇을 돌려주고, 그것을 "합이 0인 답"과 어떻게 구분하는가?
- 안쪽 while이 있는데도 전체 읽기가 2n(측정 19,822)을 못 넘는 이유는?
- 값에 음수가 섞이면 이 방법이 왜 무너지는가?
- target이 0 이하일 때 답이 모호해지는 이유와 예외(계약)로 막은 이유는?
- longestDistinct에서 같은 값을 다시 만나면 lo를 어디로 옮기는가?
- 다시 만난 값의 자리가 이미 창 밖이면 왜 lo를 옮기면 안 되는가?
- longestDistinct의 읽기가 2n이 아니라 정확히 n(측정 10,000)인 이유는?
