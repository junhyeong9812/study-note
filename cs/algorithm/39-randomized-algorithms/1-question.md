# algorithm/39-randomized-algorithms — 질문

## 질문

1. (왜) 결정적 퀵정렬의 "최악 입력"과 무작위 피벗 퀵정렬의 "최악"은 무엇이 다른가? 무작위화가 최악의 원인을 어디서 어디로 옮기나?
2. (경계) 라스베이거스 알고리즘과 몬테카를로 알고리즘을 "답"과 "시간" 두 축으로 구분하라. 몬테카를로를 라스베이거스로 바꿀 수 있는 조건은?
3. (경계) "퀵정렬은 평균 O(n log n)"과 "무작위 퀵정렬은 기대 O(n log n)"은 각각 무엇에 대한 평균·기대값인가? 이미 정렬된 입력이 깨는 것은 어느 쪽인가?
4. (예측) 이미 정렬된 n개 배열을 마지막 원소 피벗 Lomuto 퀵정렬과 무작위 피벗 퀵정렬로 정렬한다. n=2000에서 고정 피벗의 비교 수는 정확히 몇인가? n을 두 배로 늘리면 두 방식의 비교 수는 각각 몇 배쯤 되나?
5. (예측) 무작위 피벗 퀵정렬이 `new Random(42)`를 쓴다는 것을 아는 공격자가 McIlroy 방식으로 n=16000짜리 입력을 만들었다. 이 입력을 시드 42로 정렬할 때와 시드 43으로 정렬할 때 비교 수는 대략 얼마인가? 왜 그런가?
6. (예측) 카마이클 수 561에서 밑 a(2..559) 중 페르마 검사를 통과하는 비율과 Miller–Rabin 한 라운드를 통과하는 비율은 대략 얼마인가? Miller–Rabin의 이론적 상한은?
7. (연결) OpenJDK 21에서 `BigInteger.valueOf(n).isProbablePrime(1)`과 `isProbablePrime(4)`는 100비트 미만 수에 Miller–Rabin을 몇 라운드 돌리나? 홀수 합성수 82,016개에 돌렸을 때 틀린 개수의 규모는?
8. (장애 진단) 특정 사용자의 업로드에서만 정렬 API가 매번 수천 배 느리다. 재시도해도 같다. 어떤 원인을 의심하고, 무엇을 확인하며, 어떻게 막나?
9. (장애 진단) 무작위 입력을 쓰는 단위 테스트가 CI에서 가끔 실패하는데 로컬에서 재현되지 않는다. 시드는 어떻게 다뤄야 하나? 고정 시드가 답이 아닌 이유는?
