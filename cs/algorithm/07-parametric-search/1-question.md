### A. 과제 (구현 대상 — src/main TODO 1~8)

#### 1. firstTrue / lastTrue (`ParametricSearch` — TODO 1·2)

```java
/**
 * 판정이 거짓에서 참으로 바뀌는 첫 후보. [lo, hi] 에서 찾는다.
 * 전부 거짓이면 hi + 1 을 돌려준다.
 */
long firstTrue(long lo, long hi, LongPredicate feasible);

/**
 * 판정이 참에서 거짓으로 바뀌기 직전의 마지막 후보. [lo, hi] 에서 찾는다.
 * 전부 거짓이면 lo - 1 을 돌려준다.
 */
long lastTrue(long lo, long hi, LongPredicate feasible);

// TODO 1: 06 번의 firstTrue 와 같은 루프다. 타입만 long 이다.
//   중간값 계산에서 넘침에 주의해라. 후보가 long 이면 더 쉽게 넘친다.
// TODO 2: 새 루프를 쓰지 말고 firstTrue 로 표현해봐라.
//   판정을 뒤집으면 무엇이 되나. 그 결과에서 한 칸을 어느 쪽으로 옮겨야 하나.
//   루프를 두 벌 들고 있으면 한쪽만 고치는 일이 생긴다.
```

- 06번의 firstTrue와 여기의 firstTrue는 무엇이 같고, 훑는 대상은 어떻게 다른가?
- 후보가 long이면 `(lo + hi) / 2` 의 넘침이 왜 06번(int 인덱스)보다 쉽게 나는가?
- 넘치지 않는 중간값 식은 무엇인가?
- lastTrue를 새 루프 없이 firstTrue로 표현하는 한 줄은 무엇인가?
- 판정을 뒤집으면 무엇을 찾게 되고, 거기서 한 칸을 어느 쪽으로 왜 옮기는가?
- 이분 탐색 루프를 두 벌 들고 있으면 어떤 사고가 나는가?
- 전부 거짓일 때 firstTrue는 hi+1, lastTrue는 lo-1 — 왜 예외 대신 구간 밖의 값인가?
- 판정을 뒤집어 lastTrue로 풀어도 판정 횟수(비용)는 같은가(측정치)?
- 10^18 크기의 후보 구간은 판정 몇 번이면 좁혀지는가(측정치)?

#### 2. 나무 자르기 (`WoodCutter` — TODO 3·4)

```java
/** 높이 h 로 잘랐을 때 얻는 나무의 총합. */
long harvest(int[] trees, int h);

/**
 * need 이상을 얻을 수 있는 가장 높은 절단기 높이.
 * 어떤 높이로도 need 를 못 채우면 -1 을 돌려준다.
 */
int maxHeight(int[] trees, long need);

// TODO 3: 돌려주는 타입이 왜 long 인가. 나무 100 만 그루에 각 20 억이면 얼마인가.

//   후보 범위는 어디부터 어디까지인가.
//   need 가 0 이하로 들어오면 특별히 처리해야 하나.
//   (정답 구현에는 이 경우를 위한 코드가 없다. 넣었다가 지웠다.)
```

- harvest의 반환 타입이 long인 이유는(나무 100만 그루 × 각 20억이면 합이 얼마인가)?
- 합을 int로 받으면 값이 어떻게 되고, 그것이 판정을 어떻게 뒤집는가?
- h가 커지면 harvest는 늘어나는가 줄어드는가 — 그래서 firstTrue와 lastTrue 중 무엇인가?
- 후보 범위의 위끝을 가장 높은 나무로 잡아도 되는 근거는?
- 위끝을 20으로 잡을 때와 10억으로 잡을 때 판정 횟수는 각각 몇 번인가(측정치)?
- need ≤ 0 가드를 지웠는데도 테스트가 안 깨진 이유는?
- "테스트가 안 깨지는 방어 코드는 둘 중 하나다"의 둘은 무엇인가?
- `t > h` 를 `t >= h` 로 바꿔도 결과가 같은 이유는?
- 어떤 높이로도 need를 못 채우면 lastTrue가 무엇을 주고, maxHeight는 그것을 어떻게 -1로 만드는가?

### B. 개념

#### 5. 생각해볼 것 (원본 README 이관)

- 답이 실수(소수점)면 이분 탐색을 몇 번 돌려야 끝나나 — 종료 조건이 무엇이 되나?
- 판정 함수가 그리디인 문제가 많다(공유기, 배열 분할) — 그 그리디가 최적이라는 것을 어떻게 아나?
- 판정이 확률적이면(예: 시뮬레이션) 이분 탐색을 쓸 수 있나?
- groupsNeeded는 구간 수를 세지만 실제 분할을 알려주지는 않는다 — 답을 알고 나면 어떻게 복원하나?

#### 6. 파생 질문 (서머리 기반)

- "답을 이분한다"는 말은 06번 이진 탐색의 무엇이 무엇으로 바뀐 것인가?
- ParametricSearch가 데이터를 아예 모른다는 것이 왜 이 기법의 핵심인가?
- 나무가 10그루에서 10만 그루로 1만 배 늘어도 판정 횟수가 30번 그대로인 이유는?
- O(n log C)에서 n과 C가 "서로 아무 관계가 없다"는 말은 무슨 뜻인가?
- 단조성이 깨지면 왜 예외가 아니라 조용한 오답이 나오는가(x == 3 || x >= 70 예시로)?
- "반례를 못 찾았다"가 단조라는 증명이 되지 못하는 이유는?
- 완전 탐색과 이분 탐색은 같은 판정 함수를 쓰는데 무엇이 3300만 배 차이를 만드는가?
- lastTrue의 lo-1과 groupsNeeded의 MAX_VALUE — "경계값 처리가 판정과 물려 있다"를 이 둘로 설명하면?
- 실무에서 매개변수 탐색 모양이 되는 문제를 하나 들면?
