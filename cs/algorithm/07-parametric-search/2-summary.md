## 한눈에 — 쉽게 말하면

**매개변수 탐색 = 정답을 계산하는 공식은 몰라도, "이 답이면 되나?"를 물을 수 있으면 업다운 게임으로 답을 찾는 것.**

- 라면을 몇 인분까지 끓일 수 있는지 공식으로는 모른다. 그런데 "5인분 되나?"는 해 보면 안다. 5인분 되면 7인분을 물어보고, 안 되면 3인분을 물어본다 — **답 후보를 업다운으로 좁힌다.**
- 06번 이진 탐색은 배열의 **인덱스**를 훑었다. 여기서는 **답 후보**를 훑는다. 그래서 데이터를 아예 몰라도 된다 — 후보의 범위와 판정 함수만 알면 된다.
  - *판정 함수*: 답 후보 하나를 받아 "가능/불가능"을 돌려주는 함수. 06번의 술어(predicate)와 같은 것.
- 되는 조건: 판정이 **단조**여야 한다 — "5인분이 되면 4인분도 당연히 된다"처럼, 참/거짓이 한 방향으로만 바뀌어야 절반을 버릴 수 있다.

```text
답 후보:   1    2    3    4    5    6    7    8
판정:      T    T    T    T    T    F    F    F     ("이만큼 가능한가")
                              ^
                     마지막 참(lastTrue) = 5 가 답  ← 최대화 문제
```

실무 예: "서버 몇 대면 이 트래픽을 버티나"(부하 테스트는 할 수 있음), "이 속도로 하면 마감 안에 끝나나" — 정답 공식은 없지만 판정은 되는 문제들.

## 전체 흐름

```text
1. 답 후보의 범위 [lo, hi] 를 잡는다        (좁게 잡을수록 판정 횟수가 준다)
2. 판정 함수 feasible(x) 를 만든다          (대개 그리디 한 번 훑기 O(n))
3. 판정의 방향을 확인한다
     x 커질수록 T→F : lastTrue  (최솟값을 최대화 류)
     x 커질수록 F→T : firstTrue (최댓값을 최소화 류)
   ※ "최대화면 lastTrue" 같은 암기 규칙은 없다 — 판정을 어떻게 썼는지 문제마다 봐야 한다
4. 이분 탐색으로 경계를 찾는다              전체 비용 = O(n log C)
     n = 데이터 크기(판정 한 번의 비용), C = 후보 범위 크기 — 둘은 서로 무관
```

## 동작 — firstTrue / lastTrue (`ParametricSearch`)

**언제 쓰나**: 모든 매개변수 탐색 문제의 공통 엔진. 06번 firstTrue와 같은 코드인데 후보가 `long`이다(합·범위가 int를 잘 넘기니까).

전 상태:

```text
후보:   lo ..................... hi
판정:   F  F  F  F  T  T  T  T  T
                    ^ firstTrue: 처음 참이 되는 후보. 전부 거짓이면 hi+1
```

단계 (그림 해설):

- 가운데 후보 mid를 판정해서, 참이면 위쪽 끝을 mid로(mid도 후보로 남김), 거짓이면 `lo = mid + 1`.
- mid는 `lo + (end - lo) / 2` — 후보가 long이라 `(lo + end) / 2`는 더 쉽게 넘친다.
- **lastTrue는 새 루프를 짜지 않는다**: `firstTrue(lo, hi, x -> !feasible(x)) - 1` — 판정을 뒤집어 "처음 거짓" 자리를 찾고 한 칸 앞으로. 이분 탐색 루프를 두 벌 들고 있으면 한쪽만 고치는 일이 생기기 때문이다.
- lastTrue는 전부 거짓이면 `lo - 1`을 돌려준다 — 호출자가 이 값을 그대로 답으로 쓰면 사고가 난다(아래 공유기 절).

후 상태: 경계 인덱스 하나가 돌아온다. "가능/불가능의 경계"가 곧 답이다.

**비용**: 판정 O(log C)번 — 후보 범위가 절반씩 준다. 측정: 후보 10억이면 29번, 100만이면 19번 — 1000배 넓혀도 10번 더 볼 뿐.

## 동작 — 나무 자르기 (`WoodCutter`) : lastTrue 형

**언제 쓰나**: "절단기 높이 h로 자르면 h보다 높은 부분이 잘린다. need 이상 얻는 **가장 높은** h는?" — 답(h) 공식은 없지만 "h로 자르면 얼마 나오나"(harvest)는 한 번 훑으면 된다.

전 상태 — 나무 `[20, 15, 10, 17]`, need = 7:

```text
높이
 20 |  #
 17 |  #        #
 15 |  #  #     #
 10 |  #  #  #  #
    +---------------
      20 15 10 17
후보 h: 0 ~ 20 (가장 높은 나무보다 높이 잡으면 수확 0 — 볼 이유가 없다)
```

단계 (그림 해설):

```text
h=15 로 자르면: (20-15) + 0 + 0 + (17-15) = 5+2 = 7 ≥ 7  → 참
h=16 으로 자르면: 4 + 0 + 0 + 1 = 5 < 7                   → 거짓

후보 h:  ... 14   15   16   17 ...
판정:    ...  T    T    F    F ...      h 가 커질수록 수확은 줄기만 한다(단조)
                   ^ lastTrue = 15 가 답
```

- harvest는 `t > h`인 나무마다 `t - h`를 long으로 더한다 — 100만 그루 × 각 20억이면 2×10^15라 int를 넘긴다.
- `t >= h`로 바꿔도 결과가 같다(t == h면 더하는 값이 0) — 변종으로 확인된 사실.
- 어떤 높이로도 need를 못 채우면 -1.

후 상태: maxHeight = 15.

**비용**: O(n log C) — 판정 1회가 나무 전체 훑기 O(n), 그걸 log C번. 측정: 나무 10그루든 10만 그루든 판정은 **30번 그대로** — 판정 횟수는 후보 범위만 본다. 위끝을 가장 높은 나무(20)로 잡으면 4번, 10억으로 잡으면 30번 — 답은 둘 다 맞고, 차이는 비용이다.

**죽은 방어 코드 교훈**: `need <= 0`이면 `max(trees)`를 돌려주는 가드가 있었는데, 변종으로 지워도 테스트가 하나도 안 깨졌다. need ≤ 0이면 판정이 모든 후보에서 참이라 lastTrue가 이미 max(trees)를 준다. **테스트가 안 깨지는 방어 코드는 검증이 부족하거나, 필요 없거나 둘 중 하나다** — 여기는 후자라 지웠다.

## 동작 — 공유기 설치 (`RouterPlacement`) : lastTrue 형

**언제 쓰나**: "일직선 위 집들에 공유기 C대를 놓아 **가장 가까운 두 공유기 사이 거리를 최대로**." — "최솟값을 최대화하라"는 말이 나오면 대개 이 모양.

전 상태 — 집 위치 `[1, 2, 4, 8, 9]` (정렬해 둠), 공유기 3대:

```text
위치:  1  2  3  4  5  6  7  8  9
집:    @  @     @           @  @
판정(간격 d): "이웃 간격을 d 이상 지키면 몇 대 놓을 수 있나" ≥ 3 ?
```

단계 (그림 해설):

```text
d=3: 1 에 놓고 → 4(≥1+3) 에 놓고 → 8(≥4+3) 에 놓음 = 3대  → 참
     1  2  3  4  5  6  7  8  9
     *        *           *
d=4: 1 에 놓고 → 8(≥1+4) 에 놓음 = 2대                      → 거짓
판정:  d= 1  2  3  4  5 ...
           T  T  T  F  F        d 커질수록 놓을 수 있는 대수는 줄기만 한다
                 ^ lastTrue = 3 이 답
```

- 판정(countInstalled)은 그리디다: 왼쪽 끝에 무조건 놓고, 마지막 놓은 자리에서 d 이상 떨어진 첫 집마다 놓는다. "첫 공유기를 왼쪽 끝으로 밀어도 손해가 아니다"가 이 그리디의 근거.
  - *그리디(greedy)*: 매 순간 눈앞의 최선만 고르는 방식. 여기서는 "되는 첫 자리에 바로 놓기".
- 입력을 정렬하되 **복사본을 정렬한다**(`positions.clone()`) — 원본을 정렬하면 호출자의 배열이 바뀐다.
- 후보 범위는 1 ~ (양 끝 집 거리). 공유기가 2대 미만이거나 집보다 많으면 -1.

후 상태: maxMinGap = 3.

**lastTrue의 함정이 실제로 터진 자리**: 같은 자리에 집이 여럿이면 간격 1로도 못 놓아 전부 거짓 → lastTrue가 `lo - 1 = 0`을 준다. 그걸 그대로 돌려주면 "간격 0이 답"으로 읽힌다. 처음엔 이 검사가 없었고 **무작위 대조 테스트가 그 입력을 만들어 잡았다.** 지금은 `answer < 1 ? -1`.

**비용**: O(n log C) + 정렬 O(n log n) — 판정 1회가 집 전체 훑기.

## 동작 — 배열 분할 (`ArraySplit`) : firstTrue 형 — 방향이 반대다

**언제 쓰나**: "배열을 연속 K조각으로 나눌 때 **조각 합의 최댓값을 최소로**." 이것도 최소화·최대화 문제인데 **앞의 둘과 방향이 반대다** — 외우면 틀리는 이유.

전 상태 — `[7, 2, 5, 10, 8]`, K = 2조각:

```text
판정(합 한도 x): "각 조각 합이 x 를 안 넘게 나누면 몇 조각 필요한가" ≤ 2 ?
x 가 클수록 조각 수는 줄어든다 → x 커질수록 판정은 거짓→참 (firstTrue)

후보 범위: lo = 가장 큰 원소(10)  ~  hi = 전체 합(32)
```

단계 (그림 해설):

```text
x=17: [7,2,5] (14, +10이면 24>17 → 자름) [10] (+8이면 18>17 → 자름) [8] = 3조각 → 거짓
x=18: [7,2,5] (14)  [10,8] (18)                                     = 2조각 → 참

판정:  x= ... 16  17  18  19 ...
              F   F   T   T
                      ^ firstTrue = 18 이 답  ([7,2,5 | 10,8])
```

- 판정(groupsNeeded)도 그리디: 왼쪽부터 담다가 한도를 넘기 직전에 자른다.
- **불가능 표시가 설계의 급소**: 어떤 원소 하나가 x보다 크면 못 나눈다 — 이때 `Integer.MAX_VALUE`("아주 많이 필요")를 돌려준다. 0이나 -1로 표시하면 판정이 "적게 필요하다 = 참"으로 읽어 **답이 뒤집힌다.**
- 아래끝을 0으로 잡아도 답은 같다(변종으로 확인) — 가장 큰 원소보다 작은 후보에서 groupsNeeded가 MAX_VALUE라 판정이 거짓이 되어 알아서 지나치니까. **다만 이건 불가능을 "아주 큰 수"로 표시했기 때문에 성립한다.** 두 설계가 서로 물려 있어서 한쪽만 고치면 다른 쪽이 조용히 깨진다.

후 상태: minMaxSum = 18.

**비용**: O(n log(합)) — 판정 1회가 배열 한 번 훑기.

## 비교 — 세 문제, 판정과 방향

| 문제 | 판정 | 후보가 커지면 | 쓰는 것 |
|---|---|---|---|
| 나무 자르기 | 높이 h로 자르면 need 이상 나오나 | 참→거짓 | lastTrue |
| 공유기 설치 | 간격 d를 지키면 C대 놓을 수 있나 | 참→거짓 | lastTrue |
| 배열 분할 | 합 x 한도로 나누면 K조각 이하인가 | 거짓→참 | firstTrue |

배열 분할도 "최댓값을 최소화"하는 문제인데 방향이 반대다 — **firstTrue/lastTrue는 문제 종류가 아니라 판정의 방향으로 정한다.**

측정 한 줄: 나무 1000그루·후보 10억에서 완전 탐색은 10^12번, 이분은 3만 번 — 3300만 배.

## 핵심 문장

- 매개변수 탐색 = **답을 이분한다**: 답을 직접 계산하는 공식이 없어도 "이 답이 가능한가"를 물을 수 있으면 경계를 찾을 수 있다.
- 전체 비용은 O(n log C) — 판정 횟수는 후보 범위(C)만 보고, 데이터 크기(n)는 판정 한 번의 비용에만 들어간다. 둘은 서로 무관하다.
- 판정의 단조성이 전부다 — 깨지면 예외 없이 **조용히** 틀린 답이 나오고, 반례를 못 찾았다는 것이 단조라는 증명이 아니다.
- firstTrue냐 lastTrue냐는 문제의 겉모습("최대화/최소화")이 아니라 **판정이 커질수록 참이 되는지 거짓이 되는지**로 정한다.
- 경계값 처리(lastTrue의 `lo-1`, 불가능의 표시 방식)가 판정 함수와 서로 물려 있다 — 한쪽만 보고 고치면 다른 쪽이 조용히 깨진다.

## 용어 풀이

- **매개변수 탐색(parametric search)**: 답 후보를 이분 탐색하는 기법. "가능한가" 판정만으로 최적값의 경계를 찾는다.
- **판정 함수(feasible)**: 답 후보 하나를 받아 가능/불가능을 돌려주는 함수. 대개 그리디 한 번 훑기.
- **단조(monotonic)**: 후보가 커질 때 판정이 한 방향으로만 바뀌는 성질(T...T F...F 또는 F...F T...T). 이 기법의 전제.
- **firstTrue / lastTrue**: 처음 참이 되는 후보 / 마지막으로 참인 후보. lastTrue는 firstTrue(판정 뒤집기) - 1로 파생.
- **그리디(greedy)**: 매 순간 눈앞의 최선만 골라 나아가는 방식. 여기서는 판정 함수의 구현 수단.
- **경계값**: 전부 거짓일 때 firstTrue는 hi+1, lastTrue는 lo-1 — 호출자가 해석해야 하는 약속된 값.
- **O(n log C)**: 판정 한 번 O(n) × 판정 횟수 O(log C). C는 답 후보 범위의 크기.
- **오버플로(overflow, 넘침)**: 자료형의 최대값을 넘어 값이 뒤집히는 것. 수확량 합·후보 중간값 계산에서 long이 필요한 이유.
- **죽은 코드(dead code)**: 지워도 동작이 안 변하는 코드. 변종(일부러 코드를 바꿔보는 실험)으로 드러난다.
- **무작위 대조 테스트**: 무작위 입력을 만들어 느린 확실한 풀이와 답을 비교하는 테스트. 사람이 못 떠올린 경계 입력을 만들어 준다.
- **완전 탐색(brute force)**: 모든 후보를 다 시험하는 방법. 여기서는 비교 기준선.
