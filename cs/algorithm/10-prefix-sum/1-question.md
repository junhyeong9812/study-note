#### 1. PrefixSum — 1차원 누적 합 (TODO 1·2)

```java
/**
 * 1 차원 누적 합. 구간 합을 O(1) 로 답한다.
 *
 * <p>미리 한 번 훑어 두고, 그 뒤로는 뺄셈 한 번으로 답한다.
 * 질의가 한 번뿐이면 손해다. 어디가 손익분기인지 생각해봐라.
 */
public PrefixSum(CountedArray a);       // 누적 합을 만든다
public long rangeSum(int from, int to); // 닫힌 구간 [from, to] 의 합

// TODO 1: 배열 길이를 n 으로 할까 n+1 로 할까.
//   n 으로 두면 구간 [0, j] 를 물었을 때 뺄 것이 없다. 그 경우를 따로 다뤄야 한다.
//   경계 하나를 없애려고 칸 하나를 더 쓰는 거래다. 어느 쪽이 나은가.
//   합이 int 를 넘긴다. 원소 10 만 개에 각 10 만이면 얼마인가.
// TODO 2: 잘못된 구간을 먼저 막아라. 어떤 경우가 잘못된 것인가.
//   그리고 뺄셈 하나로 답해라. 인덱스가 한 칸씩 밀려 있다는 것을 잊기 쉽다.
```

- 누적 합 배열의 길이를 n이 아니라 n+1로 잡는 이유는 무엇인가?
- "경계 하나를 없애려고 칸 하나를 더 쓰는 거래"에서 없어지는 경계는 정확히 어떤 경우인가?
- `rangeSum(from, to)` 를 뺄셈 하나로 쓰면 어떤 식이 되는가(인덱스가 한 칸 밀린 것 포함)?
- 잘못된 구간으로 막아야 하는 경우는 어떤 것들인가?
- 누적 합 배열을 long으로 잡는 이유는 — 원소 10만 개에 각 10만이면 합이 얼마인가?
- 원소에 음수나 0이 섞여 누계가 단조가 아니어도 뺄셈이 그대로 성립하는 이유는?
- 질의가 한 번뿐이면 왜 90배 손해인가(측정치 숫자로)?
- 질의를 1만 번 해도 배열 읽기가 10,000 그대로인 이유는?
- 손익분기가 질의 횟수가 아니라 질의 구간의 총 길이라는 말은 무슨 뜻인가(측정치 예로)?
