# algorithm/01-algorithm-basics — 정답

## 정답

### 1. 초가 아니라 증가율

- 절대 시간은 기계·언어·데이터 크기에 따라 바뀐다. 작은 n에서는 O(n²)도 빠르다.
- 증가율은 n이 커질 때의 모양을 알려 준다. 100건 → 100만 건은 1만 배다. O(n)이면 일도 1만 배, O(n²)이면 1억 배다.
- 그래서 테스트(100건)에서 몇 ms이던 O(n²) 코드가 운영(100만 건)에서 타임아웃 난다.

### 2. 이진 탐색 비교 횟수

- `[1..10]`, target 1: mid 인덱스 4 → 1 → 0으로 3번(실험 출력 "target=1 → 3회").
- 최악은 ⌊log₂10⌋ + 1 = 4번(예: 10을 찾거나 없는 값).
- n = 1,000,000: ⌊log₂10⁶⌋ + 1 = 19 + 1 = 20번. 실험 출력 "최악 20회"와 같다. 비교 횟수는 결정적이라 매번 같다.

### 3. 두 배 실험

- 거품 정렬: 두 배 → 약 4배. 실험(CPython 3.12.14, --cpus=2) 120.9 → 518.6 → 1845.6 ms(×4.3, ×3.6), 집필 2회 + 점검 1회 범위 ×3.6~×4.8.
- 퀵 정렬: 두 배 → 2배 남짓. 2.2 → 5.1 → 10.8 ms(×2.3, ×2.1), 범위 ×2.1~×2.4.
- 거품 n = 100,000 추정: n = 1,000의 (100,000 / 1,000)² = 10,000배 → 약 970~1,210초(약 16~20분). O(n²)라는 가정에 기댄 추정이고 실행하지 않았다.

### 4. 숨은 정렬

- 원본 `binary_search`는 함수 첫 줄에서 `data.sort()`를 한다. 이미 정렬된 리스트라도 CPython 정렬은 n−1번 비교로 한 번 훑으므로 호출마다 O(n)이다.
- 실험(n = 100,000, 질의 1,000번): 원본 4010~4190 ms, 한 번 정렬 + `bisect` 1.4~1.9 ms, 선형 탐색 8825~9322 ms(실행마다 다르다).
- 부작용: (1) 호출자의 리스트 순서를 바꾼다. (2) 돌려주는 인덱스가 정렬된 리스트 기준이라 원래 위치가 아니다.

### 5. 원본 §1 예의 조건

- map O(1): 해시가 고르게 퍼진다는 가정 아래 기대 비용(Java 21 `HashMap` Javadoc). 충돌이 몰리면 느려진다.
- BST O(log n): 균형일 때. 정렬된 순서로 넣은 비균형 BST는 높이 n → O(n).
- 퀵 정렬 O(n log n): 평균(무작위 입력 또는 무작위 피벗의 기대값). 최악은 Θ(n²)(CLRS 3판 7.2).

### 6. 중간값 오버플로

- 실험(OpenJDK 21.0.12): `(lo + hi) / 2` = −397483648, `lo + (hi - lo) / 2` = 1750000000, `(lo + hi) >>> 1` = 1750000000.
- Java `int`는 32비트라 3,500,000,000이 2³¹−1을 넘어 음수로 감긴다. `>>> 1`은 부호 없는 시프트라 감긴 비트 패턴을 양수로 읽어 올바른 평균을 낸다.
- 파이썬 정수는 크기 제한이 없어 `start + end`가 넘치지 않는다. Bloch(2006)는 JDK `Arrays.binarySearch`의 같은 버그를 보고했다.

### 7. 질의 1만 번

- 선형 탐색: 질의당 최악 10⁶ 비교 × 10⁴ = 10¹⁰ 급.
- 정렬 1번 + 이진 탐색: 정렬 약 n log₂n ≈ 2×10⁷ + 탐색 10⁴ × 20 = 2×10⁵ 급.
- 코드:

```java
int[] ids = loadIds();
Arrays.sort(ids);                                  // 한 번
for (int q : queries) {
    int pos = Arrays.binarySearch(ids, q);
    if (pos >= 0) { /* 찾음 */ }
    else { int insertionPoint = -pos - 1; /* 없음, 넣을 자리 */ }
}
```

- 음수 반환 = 없음. 값은 `-(삽입 위치) - 1`이다. 정렬되지 않은 배열이면 결과가 정의되지 않는다(Javadoc).

### 8. 운영에서만 타임아웃

- 확인: 운영 규모에 가까운 데이터를 n, 2n, 4n으로 만들어 시간을 잰다. 두 배 → 4배면 제곱 경로가 있다. 운영 중이면 느린 요청 동안 `jcmd <pid> Thread.print`를 몇 번 떠서 같은 이중 루프 프레임을 찾는다.
- 대처: 표준 정렬·해시 기반 대조로 차수를 낮춘다(O(n²) → O(n log n) 또는 O(n)). 운영 최대 n으로 성능 테스트를 고정하고, 데이터 증가 때 다시 잰다.

### 9. 거품 정렬의 최선

- 원본에는 조기 종료가 없어 정렬된 입력에도 (n−1) + (n−2) + … + 1 = n(n−1)/2번 비교한다.
- "이번 바퀴에서 교환이 한 번도 없었으면 멈춘다" 플래그를 넣으면, 정렬된 입력은 첫 바퀴 n−1번 비교로 끝난다 → 최선 O(n). 최악·평균은 여전히 O(n²).
