### A. 과제 (TODO 1~14)

#### 1. 버블 정렬 (BubbleSort, TODO 1~4)

기준 코드 (impl):

```java
int n = a.size();
for (int end = n - 1; end > 0; end--) {
    boolean swapped = false;
    for (int i = 0; i < end; i++) {
        if (a.compare(i, i + 1) > 0) {   // 등호 없음 — 같은 값은 안 바꾼다
            a.swap(i, i + 1);
            swapped = true;
        }
    }
    if (!swapped) return;                // 조기 종료
}
```

- 한 바퀴가 끝나면 **그 구간의 최댓값이 맨 뒤에 확정**된다.\
  그래서 다음 바퀴는 확정된 칸 앞까지만(`end` 를 1씩 줄여서) 보면 된다 — 끝까지 계속 보면 이미 제자리인 것을 매번 다시 비교한다.

> **패스(pass) / 바퀴** — 배열을 처음부터 끝까지 한 번 훑는 것.\
> 예: 위 코드의 바깥 `for (int end = ...)` 한 번이 한 바퀴다.

- `compare(i, i+1) > 0`(양수 = 앞이 더 큼)일 때 교환한다.\
  오름차순에 어긋난 상태이기 때문이다.

> **교환(swap)** — 두 칸의 값을 맞바꾸기.\
> 예: 계측기는 이걸 쓰기 2회로 센다 — 그래서 아래 삽입 정렬의 밀기(쓰기 1회)와 총 쓰기가 갈린다.

- 등호를 포함하면(`>=`) 값이 같은 둘끼리도 교환한다 — 결과는 그대로지만 같은 값의 원래 순서가 뒤집혀 **안정성**을 잃는다.\
  낭비이기도 하다(의미 없는 쓰기 2회).

> **안정 정렬(stable sort)** — 값이 같은 원소들의 원래 순서가 정렬 후에도 유지되는 정렬.\
> 예: 이름순 명단을 점수순으로 재정렬해도 동점자끼리는 이름순이 유지되는 것.

- 교환이 0번이면 어긋난 인접 쌍이 하나도 없다는 뜻 = 이미 정렬된 상태.\
  즉시 `return` 한다.
- 조기 종료가 있으면 정렬된 입력은 첫 바퀴(비교 n-1회)만에 끝나 O(n), 없으면 끝까지 돌아 O(n^2).\
  MeasurementTest 가 이 숫자를 고정해 두었다.

> **조기 종료(early exit)** — 버블에서 한 바퀴 동안 교환이 0이면 즉시 끝내는 것.\
> 예: 위 코드의 `if (!swapped) return;` 한 줄이 정렬된 입력을 O(n^2)에서 O(n)으로 만든다.

- 안정 O.\
  인접한 둘만, 그것도 `>`(엄격 부등호)일 때만 바꾸므로 같은 값끼리는 절대 자리를 바꾸지 않는다 — 상대 순서가 유지된다.

#### 2. 선택 정렬 (SelectionSort, TODO 5~7)

기준 코드 (impl):

```java
for (int i = 0; i < n - 1; i++) {
    int min = i;
    for (int j = i + 1; j < n; j++) {
        if (a.compare(j, min) < 0) min = j;  // 등호 없음
    }
    if (min != i) a.swap(i, min);            // 자기 자신과의 교환은 건너뜀
}
```

- 최솟값을 **확신**하려면 남은 구간 전체를 훑어야 한다.\
  입력이 이미 정렬돼 있어도 "이게 최솟값이다"를 안 보고는 알 수 없으므로 비교는 항상 n(n-1)/2 회 — 입력에 따라 변하지 않는다.
- `min == i` 인데도 `swap(i, i)` 를 해버리면 계측기에 교환·쓰기가 쌓여서 "정렬된 입력에서 교환 0"이라는 성질이 사라진다.\
  그래서 `min != i` 일 때만 교환한다.

> **계측기(CountedArray)** — 비교·교환·읽기·쓰기 횟수를 세는 껍데기 배열.\
> 예: 알고리즘이 이걸 통해서만 원소를 만지므로 `swap(i, i)` 같은 헛수고도 숫자로 남는다.

- 탐색에 등호를 포함하면(`<=`) 같은 값 중 **뒤쪽**으로 min 이 계속 갱신되어 불필요한 교환이 늘어난다.
- `[2a, 2b, 1]`: 첫 바퀴에서 최솟값 1과 맨 앞 2a 가 교환되어 `[1, 2b, 2a]` — 2a 가 2b 를 건너뛰어 뒤로 날아간다.\
  같은 값의 순서가 뒤집혔으므로 **안정 X**.
- 존재 이유: **교환이 최대 n-1 회로 보장**된다는 것 하나다.\
  원소 하나를 옮기는 비용이 아주 클 때만 의미가 있다.

#### 3. 삽입 정렬 (InsertionSort, TODO 8~11)

기준 코드 (impl):

```java
for (int i = 1; i < n; i++) {
    T key = a.get(i);                            // 배열 밖으로 빼둔다
    int j = i - 1;
    while (j >= 0 && a.compareTo(j, key) > 0) {  // 경계 검사가 먼저, 등호 없음
        a.set(j + 1, a.get(j));                  // 한 칸 뒤로 민다 (쓰기 1회)
        j--;
    }
    a.set(j + 1, key);                           // j+1 에 꽂는다
}
```

- key 를 빼두지 않고 인접 교환으로만 내리면 한 칸 이동마다 쓰기 2회(교환 1번)다.\
  빼두고 밀면 한 칸에 쓰기 1회 + 마지막에 꽂기 1회 — 쓰기가 거의 절반이 된다. (역순 100개 실측: 삽입 5,049 vs 버블 9,900)

> **key** — 삽입 정렬이 배열 밖으로 빼 들고 자리를 찾는 값.\
> 예: 위 코드의 `T key = a.get(i);` — 이 칸이 비어야 큰 값들을 그쪽으로 밀 수 있다.

> **밀기(shift)** — 값 하나를 옆 칸으로 복사해 자리를 비우기.\
> 예: `a.set(j + 1, a.get(j))` 한 줄이 쓰기 1회 — 교환(쓰기 2회) 대신 삽입·셸이 쓰는 방법이다.

- key 는 이미 배열 밖에 들려 있는 값이라 "배열 i번 칸 vs 배열 j번 칸"을 비교하는 `compare(i, j)` 로는 표현할 수 없다.\
  그래서 "j번 칸 vs 들고 있는 값"을 비교하는 `compareTo(j, key)` 가 따로 있다.
- 등호를 넣으면(`>=`) 같은 값을 만나도 멈추지 않고 지나쳐 그 **앞**에 꽂는다 — 결과는 정렬돼 있지만 같은 값의 순서가 뒤집혀 안정성이 깨진다.
- `j >= 0` 를 먼저 검사해야 한다.\
  `&&` 는 왼쪽이 거짓이면 오른쪽을 평가하지 않으므로(단락 평가) 순서를 바꾸면 j = -1 일 때 배열 밖(-1번 칸)을 읽어 예외가 난다.

> **단락 평가(short-circuit)** — `&&` 의 왼쪽이 거짓이면 오른쪽을 아예 평가하지 않는 규칙.\
> 예: `j >= 0 && a.compareTo(j, key) > 0` 에서 j = -1 이면 오른쪽 비교가 실행되지 않아 -1번 칸을 읽지 않는다.

- 루프가 끝난 시점의 j 는 "key 보다 크지 않은 첫 원소"의 자리다(또는 -1).\
  key 는 그 **바로 뒤**, 즉 j+1 에 꽂는다.
- 거의 정렬된 입력에서는 각 원소가 몇 칸만 밀리면 끝난다 — 밀기 횟수 = 그 원소가 만드는 뒤집힌 쌍의 수이므로, 어긋남이 적으면 일이 그만큼만 든다.\
  최선(정렬됨)은 원소마다 비교 1번, O(n).

> **뒤집힌 쌍(inversion)** — 앞에 있는 값이 뒤의 값보다 큰 쌍.\
> 예: 정렬이 끝나려면 전부 없어져야 하고, 인접 교환 1번은 정확히 1개를 없앤다.

#### 4. 셸 정렬 (ShellSort, TODO 12~14)

기준 코드 (impl):

```java
int gap = 1;
while (gap < n / 3) gap = gap * 3 + 1;   // 크누스: n/3 미만의 최대값에서 시작

for (; gap >= 1; gap /= 3) {
    for (int i = gap; i < n; i++) {
        T key = a.get(i);
        int j = i - gap;
        while (j >= 0 && a.compareTo(j, key) > 0) {
            a.set(j + gap, a.get(j));    // 이웃이 j-1 이 아니라 j-gap
            j -= gap;
        }
        a.set(j + gap, key);
    }
}
```

- 삽입 정렬의 약점 = 원소가 **한 칸씩만** 움직인다(맨 뒤의 작은 값이 맨 앞까지 n번 밀려야 함).\
  셸은 간격 gap 을 두고 비교·밀기를 해서 멀리 있는 원소를 한 번에 gap 칸 이동시킨다.\
  코드 차이는 `j-1` → `j-gap` 뿐이다.

> **간격(gap) / 크누스 수열** — 셸 정렬이 원소를 몇 칸 떨어진 것끼리 비교할지 정하는 값.\
> 예: 크누스 수열은 1, 4, 13, 40, …(3배+1) — 위 코드의 `gap = gap * 3 + 1` 이 그것을 만든다.

- 시작값은 n/3 을 넘지 않는 크누스 수열의 최대값.\
  n 이상의 간격에서는 안쪽 루프가 한 번도 안 돌아 그 바퀴가 통째로 헛돈다.
- n/2 로 잘못 잡아도 결과·비교 횟수가 똑같다(impl 주석 — 변종을 심어 확인).\
  헛도는 바퀴가 하나 늘 뿐이므로 **틀린 게 아니라 낭비**고, 테스트로는 잡히지 않는 종류의 차이다.
- 큰 gap 바퀴들이 원소를 멀리 옮겨 "거의 정렬됨"을 먼저 만들어 놓는다.\
  그래서 마지막 gap=1 바퀴(그냥 삽입 정렬)는 삽입 정렬의 최선 쪽 비용으로 끝난다.\
  크누스 수열 기준 전체 O(n^1.5)로 알려져 있다. (n 10배에 삽입 106배 vs 셸 19배 — README 실측)
- gap=1 로 끝내지 않으면 "인접한 둘이 모두 순서대로"라는 보장이 없다 — gap 단위로만 정렬됐을 뿐 **완전 정렬이 보장되지 않는다**.
- 각 바퀴 안에서는 안정적으로 밀지만, gap>1 일 때 원소가 gap 칸을 건너뛰며 **그 사이에 있던 같은 값을 넘어간다**.\
  예(서머리): gap=4에서 2a 가 2b 를 건너뛰어 뒤로 가면 순서가 `2b, 2a` 로 뒤집힌다.\
  그래서 안정 X.

### B. 개념

#### 5. 생각해볼 것 (원본 README 이관)

- 선택 정렬을 안정으로: 교환 대신 **삽입(밀기)** 을 쓰면 된다 — 최솟값을 빼 들고 그 앞 구간을 전부 한 칸씩 밀어 맨 앞에 꽂으면 같은 값을 건너뛰지 않는다. (원본에 정답 서술 없음 — 함정 절의 "교환 대신 무엇을" 힌트에서 추론)
- 잃는 것: 교환 최대 n-1 회라는 성질.\
  밀기가 바퀴마다 O(n) 이 되어 쓰기가 O(n^2) 로 늘어난다 — 선택 정렬의 존재 이유 자체가 사라진다. (원본에 근거 없음 — 내 추론)
- 버블의 비대칭 해소: 한 바퀴마다 방향을 바꿔 왼→오, 오→왼을 번갈아 돈다(칵테일 정렬).\
  오→왼 바퀴에서는 작은 값도 한 바퀴에 끝까지 온다. (원본은 질문만 — 방법은 README 의 괄호 힌트)
- 이진 탐색 삽입 정렬: 자리 **찾기**(비교)는 O(log n) 이 되지만, 찾은 자리에 꽂으려면 뒤 원소들을 **미는** 일이 여전히 O(n) 이다.\
  전체는 밀기가 지배해 O(n^2) 그대로 — 04번 dynamic-array 의 insertSorted 와 같은 구조의 결론.
- `Arrays.sort`: 원시 타입(int 등)은 값이 같으면 구별 자체가 안 되므로 안정성이 관측되지 않는다 — 빠른 비안정 정렬(듀얼 피벗 퀵)을 쓴다.\
  객체는 같은 값도 서로 다른 개체라 순서가 관측된다 — 안정 정렬(팀소트, 병합 계열)을 쓴다. (원본에 근거 없음 — 내 추론; 질문만 원본)

#### 6. 비용으로 구분하기 (파생)

- 넷 다 정렬된 배열을 내놓으므로 **결과만 보면 구분할 방법이 없다**.\
  무엇을 아끼고 무엇을 낭비하는지는 비교·교환·읽기·쓰기 숫자로만 보인다 — 그래서 계측기를 씌운다(README 첫 절).
- 교환은 두 칸의 값을 맞바꾸는 것 = 실제로 두 번 쓴다.\
  그래서 쓰기 2회로 센다.\
  이 셈법 덕에 "교환 정렬 vs 밀기 정렬"의 쓰기 차이(9,900 vs 5,049)가 드러난다.
- 버블에서 큰 값은 한 바퀴에 끝까지 떠내려가지만 작은 값은 한 바퀴에 **한 칸만** 앞으로 온다.\
  `[2,3,...,100,1]`(작은 값이 맨 뒤)은 1이 99바퀴에 걸쳐 와야 해서 비교 4,950, `[100,1,...,99]`(큰 값이 맨 앞)은 첫 바퀴에 100이 끝까지 가서 197 — 뒤집힌 쌍은 둘 다 99개로 같은데 25배 차이.
- "거의 정렬 = 버블도 빠름"이 성립하는 건 어긋난 원소가 **큰 값이 앞에 있는** 모양일 때뿐이다.\
  작은 값이 뒤에 있으면 느리다.\
  무작위로 다섯 쌍만 바꾼 입력에서 버블 3,774 vs 삽입 278 (README 실측).
- 역순에서 비교는 둘 다 4,950(모든 쌍이 어긋나 있으니).\
  쓰기는 버블이 교환(2회짜리)만 하고 삽입은 밀기(1회짜리)만 해서 9,900 vs 5,049 — 절반.
- 역순은 **규칙적**이라 셸의 큰 gap 한 바퀴에 거의 정리된다.\
  무작위는 어느 간격에서도 한 번에 안 된다.\
  100개 실측 500 vs 730 — "역순이 최악"이라는 짐작이 셸에서는 틀린다.
- 선택만 최선=최악인 이유: 다른 셋은 입력 상태가 일(밀기·교환·조기 종료)을 줄여주지만, 선택의 비교는 "최솟값 확신"을 위한 전수 탐색이라 입력이 어떤 상태든 똑같이 든다.

#### 7. 안정성 (파생)

- 안정 정렬 = 값이 같은 원소들의 원래 순서가 정렬 후에도 유지되는 것.\
  다단계 정렬에서 중요하다 — 이름순 명단을 점수순으로 재정렬해도 동점자끼리 이름순이 유지되어야 할 때.
- 갈리는 지점:

```text
 버블  O   인접 교환 + 엄격 부등호(>)
 선택  X   swap(i, min) 이 멀리 있는 원소를 건너뛰게 함
 삽입  O   밀기 비교의 엄격 부등호 (같은 값을 만나면 멈춤)
 셸    X   gap 만큼 건너뛰는 이동 자체
```

- 공통 원리: **같은 값을 "건너뛰거나 굳이 바꾸는" 코드가 한 줄이라도 있으면 깨진다.**
- `stable()` 선언 설계: 안정성은 정렬 결과의 값만 봐서는 안 보이는 성질이라, 구현자가 자기 코드를 **판단해서 계약으로 선언**하게 하고 테스트가 같은 값 원소의 순서 추적으로 실동작과 대조한다.\
  아무거나 적어 통과할 수 없게 — "선언 = 검증되는 계약"을 배우게 하는 장치다.

#### 8. 다음 챕터로 (파생)

- 공유하는 한계: 비교 기반 + (셸 제외) 원소가 이웃으로만 움직여 최악 O(n^2).\
  병합 정렬(02번)은 **추가 배열 O(n)** 을 대가로 항상 O(n log n) 을 보장한다 — "제자리 O(1) 메모리"를 내주고 시간 상한을 산다.

> **제자리 정렬(in-place)** — 추가 배열 없이(O(1) 메모리) 주어진 배열 안에서 정렬하는 것.\
> 예: 이 장의 넷은 전부 제자리지만, 02번 병합 정렬은 보조 배열 O(n) 을 쓰므로 제자리가 아니다.

- 그래도 짧은 구간에서는 O(n^2) 라도 상수가 작고 교환 0·거의 정렬 O(n) 인 삽입이 이긴다.\
  그래서 라이브러리 정렬(팀소트 등)은 재귀가 짧은 구간에 닿으면 삽입 정렬로 마무리한다. (원본 README 직접 언급 없음 — 02번 TunedMergeSort 로 이어지는 내용)
