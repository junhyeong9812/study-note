## 질문

1. (왜) DEFLATE는 왜 LZ77과 허프만을 둘 다 쓰나? 각자 어떤 "낭비"를 없애나? 하나만 쓰면 무엇이 남나?
2. (그림) `ABRACADABRA`(A 5, B 2, R 2, C 1, D 1)로 허프만 트리를 최소 힙으로 만드는 과정을 그려라. 총 비트 수는 얼마이고, 고정 길이 부호와 비교하면?
3. (예측) LZ77 디코더가 이미 `a` 하나를 내보낸 상태에서 `<거리 1, 길이 19>`를 받으면 무엇이 나오나? 이 복사를 `System.arraycopy` 한 번으로 구현하면 어떻게 틀리나?
4. (예측) 아래 네 입력을 gzip하면 각각 어떻게 될까? 줄어든다/거의 그대로/커진다로 예측하고 이유를 대라. ① 2바이트 `hi` ② `/dev/urandom` 1MiB ③ 0으로 채운 1 GiB ④ 같은 문자 100개.
5. (경계) 한 기호가 90%, 다른 기호가 10%인 원천에서 엔트로피는 약 0.469비트/기호다. 허프만은 기호당 몇 비트를 쓰나? 그런데 gzip은 그 원천 1,000,000바이트를 허프만 단독(125,000바이트)보다 작게(81,557바이트) 만들었다. 엔트로피 한계를 어긴 것인가?
6. (연결) DEFLATE는 왜 허프만 트리 대신 "부호 길이"만 보내나? 그러려면 부호 값에 어떤 규칙이 필요한가? 부호 길이를 15로 제한한 것은 무엇을 어렵게 만드나?
7. (연결) 매치 파인더의 해시 체인은 어떤 자료구조인가? 체인을 더 길게 따라가면 무엇을 얻고 무엇을 잃나? 실험에서 체인 128 → 4096의 토큰 수 변화가 말해 주는 것은?
8. (장애 진단) gzip 업로드를 받는 API 서버가 1MB 남짓한 요청 몇 개에 `OutOfMemoryError: Java heap space`로 죽었다. 무엇을 의심하고, 해제 코드를 어떻게 바꾸나? 꼬리의 ISIZE를 믿으면 안 되는 이유는?
9. (장애 진단) 한 서비스가 보낸 gzip 본문을 받는 쪽이 `java.io.EOFException: Unexpected end of ZLIB input stream`을 낸다. 다른 서비스에선 `ZipException: Not in GZIP format`이 난다. 각각 무엇이 원인일 수 있고 어떻게 확인하나?
10. (왜) "모든 파일을 조금씩이라도 줄이는 무손실 압축기"가 없다는 것을 세는 논증으로 설명하라. 이 사실이 "암호화 후 압축"이 무의미한 이유와 어떻게 연결되나?
