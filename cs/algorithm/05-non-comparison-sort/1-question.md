#### 2. LSD 기수 정렬 (`LsdRadixSort` — TODO 6\~8)

```java
/**
 * LSD 기수 정렬. 낮은 자리부터 8 비트씩 네 번 계수 정렬한다.
 * 키 범위가 아무리 넓어도 통과 횟수는 네 번으로 고정이다.
 */
private static final int BITS = 8;
private static final int BUCKETS = 1 << BITS; // 256
private static final int PASSES = 4;          // 32 비트를 8 비트씩

// TODO 6: 버퍼 하나를 잡고 통과할 때마다 원본과 버퍼를 번갈아 쓴다.
//   매 통과마다 새 버퍼를 만들면 무엇이 늘어나나. 계측기가 그걸 센다.
//   통과가 끝났을 때 결과가 어느 배열에 있는지 어떻게 아나.
// TODO 7: 한 통과는 그 자리에 대한 계수 정렬이다.
//   여기서 안정성을 잃으면 앞 통과에서 맞춰 둔 순서가 흐트러진다.
//   그러면 결과가 그냥 틀린다. 안정성이 부가 성질이 아니라 전제다.
// TODO 8: 키에서 해당 자리의 8 비트를 꺼낸다. 시프트하고 마스크를 씌우면 된다.
//   (>> 와 >>> 중 무엇을 쓰든 마스크가 뒤에 붙으면 결과가 같다. 확인해봐라.)
//   진짜 문제는 마지막 통과의 부호다. 2 의 보수에서 음수는 최상위 비트가 1 이다.
//   최상위 바이트만 어떻게 손보면 순서가 바로잡히나.
```

- 8비트씩 보면 세는 배열이 항상 256칸으로 고정되는 이유는 무엇인가?
- 통과가 4번인 이유는 무엇이고, 키 범위가 좁아도 4번을 다 도는가?
- 매 통과마다 새 버퍼를 만들면 계측기의 무엇이 늘어나는가?
- 통과가 끝났을 때 결과가 원본에 있는지 버퍼에 있는지는 무엇이 정하고, 코드는 그것을 어떻게 처리하는가?
- LSD에서 안정성이 "부가 성질이 아니라 전제"라는 말은 무슨 뜻인가?
- 안정성이 깨지면 예외가 나는가, 아니면 무엇이 나는가?
- 2의 보수에서 음수를 그냥 정렬하면 왜 양수보다 뒤로 가는가?
- `b ^ 0x80`이 그 순서를 바로잡는 원리는 무엇인가?
- 부호 처리를 마지막 통과에만 하는 이유는 무엇인가?
- `>>>`를 `>>`로 바꿔도 결과가 같은 이유는 무엇이고, 그런데도 `>>>`로 쓰는 이유는?
