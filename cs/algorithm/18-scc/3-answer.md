### A. 과제 (구현 대상 — src TODO 1~8)

#### 1. `Tarjan.components` / `Tarjan.visit` / `Tarjan.groups` (TODO 1~5)

impl 정답의 뼈대:

```java
Arrays.fill(order, -1);                       // 미방문 = -1 (0은 "0번째 방문"과 겹친다)
for (int v = 0; v < n; v++) {
    if (order[v] == -1) visit(g, v, ...);     // 모든 정점을 시작 후보로
}

// visit:
order[v] = clock[0]; low[v] = clock[0]; clock[0]++;
stack.push(v); onStack[v] = true;
for (각 이웃 to) {
    if (order[to] == -1) {                    // 아직 안 감
        visit(g, to, ...);
        low[v] = Math.min(low[v], low[to]);
    } else if (onStack[to]) {                 // 스택 위 = 위로 올라갈 길
        low[v] = Math.min(low[v], order[to]);
    }
    // 스택에 없는 정점(이미 다른 덩어리)은 무시한다
}
if (low[v] == order[v]) {                     // 뿌리다
    int id = nextComp[0]++;
    while (true) {
        int u = stack.pop(); onStack[u] = false; comp[u] = id;
        if (u == v) break;                    // 자기까지 잘라내면 한 덩어리
    }
}
```

- Q: order와 low는 각각 무엇을 뜻하는가?\
  A: order[v] = v에 몇 번째로 들어왔나(방문 시각).\
  low[v] = v에서 출발해 (트리 간선과 스택 위 정점으로 가는 간선을 통해) 닿을 수 있는 것 중 가장 이른 방문 시각.\
  "내 위로 올라갈 길이 있나"를 low가 요약해 들고 다닌다.

> **order(방문 시각)** — DFS에서 정점에 몇 번째로 들어왔는지 적은 숫자.\
> 예: 0→1→2 순으로 들어갔으면 order는 각각 0·1·2다.

> **low(최소 도달, low-link)** — 그 정점에서 출발해 닿을 수 있는 것 중 가장 이른 order.\
> 예: `low[2] = 0` 이면 2에서 order 0인 정점까지 거슬러 갈 길이 있다는 뜻이다.

- Q: 미방문 표시를 0으로 두면 무엇과 구분이 안 되고, impl은 무엇으로 표시하는가?\
  A: 시각이 0부터 시작하므로 "0번째로 방문한 정점"과 "아직 안 간 정점"이 구분이 안 된다.\
  impl은 `Arrays.fill(order, -1)` — 유효한 시각이 될 수 없는 -1을 쓴다.\
  comp도 같은 이유로 -1로 초기화한다(0번 덩어리와 구분).

- Q: 방향 그래프에서 왜 모든 정점을 시작 후보로 돌아야 하는가?\
  A: 방향 그래프는 한 정점에서 전부에 못 닿을 수 있다 — 들어오는 간선만 있는 정점은 어디서도 도달 못 한다.\
  그래서 `for (v = 0..n-1) if (order[v] == -1) visit(v)` — 안 가본 정점을 만날 때마다 새로 시작한다.\
  11번 BFS·12번 DFS에서 "연결 안 된 덩어리"를 도는 것과 같은 패턴이다.

- Q: 정점을 스택에 넣는 것 외에 `onStack` 표시를 따로 두는 이유는 무엇인가?\
  A: 이웃을 심사할 때 "방문했나"만으로는 부족하고 "아직 스택에 있나(덩어리 미확정인가)"를 물어야 하기 때문이다.\
  `ArrayDeque`는 특정 원소가 안에 있는지 O(1)로 답하지 못하므로 boolean 배열로 따로 기록한다.\
  이미 잘려나간 정점과 스택 위 정점을 가르는 것이 이 알고리즘의 정확성 그 자체다(다음 두 답).

> **onStack(스택 소속 표시)** — 그 정점이 아직 타잔의 스택 위에 있는가(= 덩어리가 아직 안 정해졌는가)를 적어 두는 boolean 배열.\
> 예: `ArrayDeque`는 "안에 있나"를 빨리 못 답하므로, 같은 정보를 배열로 따로 들고 다닌다.

- Q: 이웃이 "아직 안 간 정점"일 때 내 low를 무엇으로 갱신하는가?\
  A: 먼저 내려가서(재귀) 그 정점을 끝까지 처리한 뒤, `low[v] = min(low[v], low[to])` — **그 정점의 low**로 갱신한다.\
  자식이 발견한 "위로 가는 길"이 나에게도 길이기 때문이다(나→자식→저 위).\
  트리 간선에서는 low를 물려받는 것이 맞다 — 자식의 low는 그 시점에 확정되어 있다.

> **트리 간선(tree edge)** — DFS가 실제로 타고 내려간 간선(= 이웃이 미방문이라 재귀로 들어간 간선).\
> 예: 0→1→2로 내려간 두 간선이 트리 간선이고, 2→0처럼 이미 방문한 곳으로 가는 간선은 아니다.

- Q: 이웃이 "스택에 있는 정점"일 때 order로 갱신하는가 low로 갱신하는가, 그 근거는?\
  A: impl은 `low[v] = min(low[v], order[to])` — **order**를 쓴다.\
  스택 위 정점의 low는 아직 확정 전이기 때문에 order가 원칙에 맞다.\
  단, 변종으로 확인된 사실: **강연결 요소만 구할 때는 low[to]를 써도 답이 같다** — 스택 위 정점의 low도 결국 같은 덩어리 안의 order라서 뿌리 판정이 안 바뀐다.\
  그런데 다리·단절점 문제에서는 order만 맞다(B-4 참조).

- Q: 이웃이 "스택에 없는 정점"일 때는 어떻게 해야 하고, 빠뜨리면 무슨 일이 생기는가?\
  A: **무시한다** — low 갱신을 하지 않는다.\
  그 정점은 이미 다른 덩어리로 잘려나가 확정됐다.\
  잘려나간 덩어리로 가는 간선을 low에 반영하면, 이미 남남으로 확정된 덩어리의 이른 시각이 내 low를 끌어내려 서로 다른 덩어리가 하나로 붙는다.\
  계약 테스트가 정확히 이 실수를 잡는 그래프를 준다 — "이미 방문했다"만 보면 안 되는 이유다.

- Q: 그 구분이 12번 DFS의 3색 구분과 같은 종류라는 말은 무슨 뜻인가?\
  A: 정점의 상태가 2가지(안 감/갔음)가 아니라 3가지라는 구조가 같다.\
  타잔: 미방문(-1) / 스택 위(방문했고 덩어리 미확정) / 잘려나감(방문했고 확정) — 12번의 흰색/회색(처리 중)/검은색(처리 끝)과 대응한다.\
  "처리 중"과 "처리 끝"을 뭉개면 역간선과 교차 간선이 구분이 안 돼 판정이 틀리는 것도 같다.

> **역간선(back edge) / 교차 간선(cross edge)** — 아직 처리 중인 조상으로 되돌아가는 간선 / 이미 처리가 끝난 딴 가지로 건너가는 간선.\
> 예: 2→0은 역간선(위로 가는 길)이고, 이미 잘려나간 덩어리로 가는 간선은 교차 간선이라 low에 반영하면 안 된다.

- Q: 나올 때 low == order 라는 것은 무슨 뜻이고, 그때 스택에서 어디까지 잘라내는가?\
  A: 이 정점 위로 올라갈 길이 하나도 없다는 뜻 — 자기 서브트리 어디서도 자기보다 이른 시각에 못 닿았다.\
  그러면 이 정점이 한 강연결 요소의 뿌리이고, 스택에서 **자기 자신이 나올 때까지** pop한 것이 정확히 그 덩어리다.\
  impl: `while (true) { u = pop; onStack[u]=false; comp[u]=id; if (u == v) break; }`

- Q: `groups`가 "번호가 0부터 연속"이라는 성질을 어떻게 이용하는가?\
  A: 최대 번호 max를 찾아 리스트를 max+1개 만들어 두고, 정점을 `out.get(comp[v]).add(v)`로 던져 넣는다.\
  번호가 연속이라 빈 칸 걱정 없이 번호를 인덱스로 바로 쓸 수 있다 — 해시맵이 필요 없다.\
  05번(비교하지 않는 정렬)의 버킷 발상과 같다.

#### 2. `Kosaraju.components` (TODO 6~8)

impl 정답의 뼈대:

```java
// 1패스: 원래 그래프, 끝난 순서 쌓기
for (v = 0..n-1) if (!seen[v]) fillOrder(g, v, seen, finishOrder);
// fillOrder 마지막 줄: out.push(v);   <- 끝난 뒤에 쌓는다

CountedGraph reversed = g.reversed();   // 이 비용도 원래 그래프 계수기에 남는다

// 2패스: 늦게 끝난 것부터, 역그래프에서
while (!finishOrder.isEmpty()) {
    int v = finishOrder.pop();
    if (comp[v] == -1) { collect(reversed, v, comp, nextComp); nextComp++; }
}
```

- Q: 1패스에서 정점을 "나올 때" 쌓아야 하는 이유는 무엇이고, 들어갈 때 쌓으면 무엇이 깨지는가?\
  A: 원하는 것이 "끝난 순서"(의 역순 = 위상 순서)이기 때문이다 — 나올 때 쌓으면 스택에서 꺼내는 순서가 곧 늦게 끝난 순이다.\
  들어갈 때 쌓으면 방문 시작 순서가 되는데, 시작 순서는 위상 순서가 아니다 — 먼저 들어갔어도 나중 덩어리로 흘러들어가 늦게 끝날 수 있다.\
  impl `fillOrder` 마지막 줄 주석: "끝난 뒤에 쌓는다.\
  들어갈 때 쌓으면 위상 순서가 안 나온다."

> **위상 순서(topological order)** — DAG의 정점을 화살표가 항상 앞→뒤로만 가도록 줄 세운 순서.\
> 예: DFS의 "끝난 순서 역순"이 이것이다 — 그래서 끝날 때 스택에 쌓고 pop하면 그 순서가 나온다.

- Q: 1패스가 얻으려는 것은 무엇인가?\
  A: **축약 그래프의 위상 순서**다.\
  끝난 순서의 역순으로 보면, 먼저 나오는 정점이 속한 덩어리는 축약 DAG에서 상류(다른 덩어리로 가는 쪽)다.\
  2패스가 "상류 덩어리부터" 출발하기 위한 준비다.

- Q: 2패스는 어느 그래프에서 어떤 순서로 출발하는가?\
  A: **간선을 전부 뒤집은 역그래프**에서, **늦게 끝난 정점부터** 출발한다.\
  1패스에서 스택에 쌓았으므로 그냥 pop 순서가 그 순서다 — "스택에 쌓았다면 꺼내는 순서가 이미 뒤집힌 것이다".\
  이미 번호가 붙은(comp[v] != -1) 정점은 건너뛴다.

- Q: 역그래프에서 한 번의 DFS로 닿는 것들이 정확히 하나의 강연결 요소인 이유는 무엇인가?\
  A: 같은 덩어리는 서로 오갈 수 있으므로 역그래프에서도 서로 닿는다 — 덩어리 전체가 잡히는 것은 자명하다.\
  문제는 "밖으로 안 새는가"인데: 역그래프에서 다른 덩어리로 넘어간다 = 원래 그래프에서 그 덩어리로부터 들어오는 간선이 있다 = 축약 DAG에서 그 덩어리가 상류다.\
  그런데 출발 순서(위상 순서)상 상류 덩어리는 이미 앞에서 번호가 붙어 있다.\
  즉 새어 나가려는 곳은 전부 방문 완료라 멈춘다 — "벗어나려면 원래 그래프에서 뒤로 가는 간선이 있어야 하는데 DAG라 없다"(impl javadoc).

> **역그래프(reversed/transpose graph)** — 모든 간선의 방향을 뒤집은 그래프.\
> 예: 0→1, 1→2, 2→0 을 1→0, 2→1, 0→2 로 바꾼 복사본 — 코사라주 2패스가 도는 무대다.

- Q: 축약 그래프가 반드시 DAG인 이유는 무엇인가?\
  A: 덩어리 사이에 사이클이 있다고 하면, 그 사이클을 따라 두 덩어리가 서로 오갈 수 있다.\
  서로 오갈 수 있으면 정의상 그 둘은 애초에 **한** 강연결 요소였어야 한다 — "최대 묶음"이라는 정의에 모순.\
  그래서 축약하면 사이클이 남을 수 없다.

> **축약 그래프(condensation)** — 각 강연결 요소를 점 하나로 접은 그래프.\
> 예: {0,1,2}와 {3,4}를 각각 한 점으로 접으면 화살표가 한 방향뿐인 그림이 된다.

> **DAG(directed acyclic graph)** — 사이클(고리)이 없는 방향 그래프.\
> 예: 축약 그래프는 항상 이것이다 — 고리가 있었다면 두 덩어리가 애초에 한 덩어리였을 테니까.

- Q: 역방향 그래프를 만드는 비용을 왜 알고리즘 비용에 넣어야 하는가?\
  A: 역그래프는 입력이 아니라 코사라주가 스스로 만들어 쓰는 중간 산물이기 때문이다 — 만들려면 그래프를 한 번 다 훑어야 한다(E).\
  "역그래프를 공짜로 주면 코사라주가 실제보다 싸 보인다"(README) — 비교가 불공정해진다.\
  그래서 impl의 `g.reversed()`는 그 비용을 원래 그래프의 계수기에 남긴다.

- Q: 코사라주가 간선을 총 몇 번 훑는지 그 3E의 내역은 무엇인가?\
  A: 1패스(원래 그래프 DFS) E + 역그래프 만들기 E + 2패스(역그래프 DFS) E = **3E**.\
  타잔은 DFS 한 번뿐이라 정확히 E — 더도 덜도 아니다(측정).\
  둘 다 O(V+E)라고 부른다 — 표기가 버린 그 상수가 3배다.

> **O(V+E)** (빅오 표기) — 일의 양이 정점 수 + 간선 수에 비례한다는 뜻.\
> 예: 같은 O(V+E)라도 몇 번 훑느냐는 다를 수 있다 — 타잔 E, 코사라주 3E.

- Q: 메모리 사용은 타잔과 어떻게 다른가?\
  A: 타잔은 배열 몇 개(order, low, comp, onStack)와 스택 — O(V)다.\
  코사라주는 그 위에 **역방향 그래프 하나를 통째로** 더 든다 — O(V+E).\
  대신 low-link가 없어 사람이 읽기 쉽다 — "이해하기 쉬운 쪽"과 "적게 일하는 쪽"이 다를 때 무엇을 고를지는 상황이 정한다.

- Q: 타잔을 재귀로 썼는데 정점 100만 개면 어떻게 되는가?\
  A: 재귀 깊이가 최악 V까지 자란다 — 정점 100만 개짜리 한 줄 사슬이면 100만 겹 재귀다.\
  JVM 기본 스택(수백 KB~수 MB)은 보통 수천~수만 겹에서 터진다(StackOverflowError) — 12번에서 깊이를 실측해 확인한 위험.\
  고치려면 명시적 스택으로 반복문 변환을 해야 하는데, 타잔은 "나올 때 할 일"(low 병합·뿌리 판정)이 있어 BFS처럼 단순 변환이 안 되고 상태를 함께 쌓아야 한다.\
  (원본에 근거 없음 — 내 추론)

> **StackOverflowError(스택 넘침)** — 재귀가 너무 깊어져 JVM이 호출 기록을 더 못 쌓고 터지는 것.\
> 예: 정점 100만 개짜리 한 줄 사슬이면 재귀가 100만 겹이라, 수천~수만 겹에서 이미 터진다.

- Q: 2-SAT을 강연결 요소로 풀 때 `x`와 `not x`가 같은 덩어리면 무슨 뜻인가?\
  A: 함의 그래프에서 같은 덩어리 = 서로 함의한다 = x가 참이면 not x도 참이어야 하고 그 반대도 성립한다는 뜻.\
  둘 다 동시에 참일 수는 없으므로 **그 논리식은 충족 불가능**하다.\
  모든 변수에 대해 x와 not x가 딴 덩어리면 충족 가능하고, 축약 DAG의 위상 순서로 각 변수의 값을 정할 수 있다.\
  (원본에 근거 없음 — 내 추론, 표준 이론)

> **2-SAT** — "x이거나 y" 형태의 조건들을 모두 만족시키는 참/거짓 배정을 찾는 문제.\
> 예: 함의 그래프를 만들어 SCC를 구하고, x와 not x가 같은 덩어리면 충족 불가능이라고 판정한다.

- Q: 축약 그래프를 실제로 만들면 무엇에 쓸 수 있는가?\
  A: 사이클이 없는 DAG가 되므로, 사이클 때문에 못 쓰던 알고리즘이 전부 열린다 — 위상 정렬, DAG 위 DP(최장 경로, 도달 가능성 집계), 의존성 계층 분석.\
  실무로는 모듈 순환 참조 묶음을 한 단위로 접어 빌드/배포 순서를 정하거나, 데드락 분석에서 대기 사이클 덩어리를 찾는 식이다.\
  "복잡한 그래프 문제 → SCC 축약 → DAG 문제"는 표준 환원 경로다.\
  (원본에 근거 없음 — 내 추론)

- Q: 무방향 그래프에는 강연결 요소가 없는 이유는 무엇이고, 무엇이 그 자리를 대신하는가?\
  A: 무방향 간선은 항상 양방향이라, 이어져 있기만 하면 서로 오갈 수 있다 — "강연결"이 그냥 "연결"과 같은 말이 되어 개념이 무의미해진다.\
  그 자리를 대신하는 것이 **이중 연결 요소(단절점·다리 기준의 분해)**다 — "간선/정점 하나가 끊겨도 여전히 오갈 수 있는 묶음".\
  그래서 타잔의 같은 기법(order/low)이 무방향에서는 다리·단절점 찾기로 변형된다 — 바로 변종 실험이 건드린 자리다.\
  (원본에 근거 없음 — 내 추론)

> **이중 연결 요소(biconnected component)** — 간선이나 정점 하나가 끊겨도 여전히 서로 오갈 수 있는 묶음.\
> 예: 무방향 그래프에서 강연결 요소의 자리를 대신하는 개념이고, 단절점·다리를 기준으로 쪼갠다.

#### 4. 파생 질문 (서머리 기반)

- Q: 강연결 요소의 정의를 한 문장으로 말하면 무엇인가?\
  A: 방향 그래프에서 **서로 오갈 수 있는**(어느 쪽에서든 상대에게 닿는) 정점들의 **최대** 묶음이다.\
  "최대"가 빠지면 안 된다 — 더 키울 수 있는데 안 키운 묶음은 SCC가 아니다.\
  같은 덩어리 안에서는 어디든 왕복이 된다.

- Q: 두 알고리즘의 결과 배열을 그대로 비교하면 안 되는 이유는 무엇이고, 무엇을 비교해야 하는가?\
  A: 번호는 발견 순서라 두 알고리즘이 다르게 붙인다 — 타잔은 먼저 끝난 덩어리부터, 코사라주는 위상 순서 앞 덩어리부터.\
  같은 분할인데 배열 값은 딴판일 수 있다 — 배열 비교는 틀린 검증이다.\
  비교할 것은 **분할** — "같은 덩어리인가"의 관계(comp[u] == comp[v] 여부)가 일치하는지다.\
  17번의 "간선 집합이 아니라 합 비교"와 같은 교훈이다.

> **분할(partition)** — 원소들을 겹치지 않게 여러 묶음으로 나눈 것. 묶음에 붙은 이름·번호는 분할의 일부가 아니다.\
> 예: `[1,1,1,0,0]`과 `[0,0,0,1,1]`은 번호가 달라도 같은 분할이다.

- Q: "둘 다 O(V+E)인데 상수가 3배"라는 측정은 알고리즘 선택에 무엇을 시사하는가?\
  A: 빅오가 같으면 성능도 같다고 믿으면 안 된다 — 훑는 횟수 E vs 3E, 메모리 O(V) vs O(V+E).\
  그런데 코사라주는 low-link가 없어 읽기 쉽다 — 성능이 아쉽지 않은 자리면 이해 가능한 쪽이 나은 선택일 수 있다.\
  "이해하기 쉬운 쪽"과 "적게 일하는 쪽"이 다를 때 무엇을 고를지는 상황이 정한다(README).

- Q: 타잔의 덩어리 번호가 위상 순서의 역순이 되는 이유는 무엇이고, 그것이 왜 공짜 선물인가?\
  A: 뿌리 판정이 "나올 때" 일어나므로 하류(간선이 향하는 쪽) 덩어리가 먼저 끝나 먼저 번호를 받는다.\
  그래서 간선은 항상 `comp[u] >= comp[v]` 방향으로만 있다 — 번호를 뒤집으면 축약 DAG의 위상 순서다.\
  SCC 다음에 "덩어리 순서대로 처리"(DAG DP 등)를 할 때 위상 정렬을 따로 안 돌려도 된다 — 무작위 그래프 200개로 확인된 성질이다.

- Q: 역간선 갱신에 order 대신 low를 쓴 변종이 SCC 테스트에서 안 잡힌 이유는 무엇인가?\
  A: 강연결 요소 문제에서는 둘 다 맞기 때문이다 — 변종이 틀린 코드가 아니었다.\
  스택에 있는 정점의 low는 확정 전이지만, 그 값도 결국 **같은 덩어리 안의 order**라서 "뿌리인가"(low == order) 판정이 안 바뀐다.\
  테스트가 못 잡은 게 아니라 잡을 것이 없었다 — 변종 실험이 "이 자리의 자유도"를 알려준 사례다.

- Q: 같은 자리가 다리·단절점 문제에서는 왜 order여야만 하는가?\
  A: 다리 판정은 "자식의 low가 부모의 order보다 큰가"라는 **경계값 비교**라 low가 정확해야 한다.\
  거기서 low[to]를 쓰면 부모로 되돌아가는 간선이 low를 저 위까지 끌어내려, 실제로는 유일한 통로인 간선(진짜 다리)을 "우회로가 있다"고 착각해 놓친다.\
  "타잔이면 이렇게 쓴다"가 아니라 **"무엇을 판정하려는가"가 정한다** — 같은 코드 모양을 다른 문제에 옮길 때 조용히 깨지는 자리다.

- Q: 무작위 방향 그래프에서 정점당 간선 수를 늘리면 덩어리 수는 어떻게 변했는가(실측)?\
  A: 정점 2,000개에서 정점당 간선 1개 → 덩어리 1,971 / 2개 → 375 / 3개 → 102 / 5개 → **15**.\
  간선이 조금만 늘어도 덩어리가 급격히 뭉친다 — 거대 강연결 요소가 생기는 문턱이 **정점당 1개 근처**다.\
  무작위 그래프의 상전이(임계점을 넘으면 구조가 급변) 현상을 직접 관측한 것이다.

> **상전이(phase transition)** — 어떤 값을 조금씩 키우다 임계점을 넘는 순간 구조가 급격히 바뀌는 현상.\
> 예: 정점당 간선이 1개에서 2개로 늘자 덩어리가 1,971개에서 375개로 무너지듯 뭉친다.

- Q: SCC가 실무에서 순환 참조·데드락 탐지에 쓰이는 이유를 축약 DAG로 설명하면?\
  A: "서로 물고 있다"(순환 의존, 서로 대기)는 것이 정확히 "같은 SCC에 있다"는 것이기 때문이다.\
  SCC를 구하면 크기 2 이상인 덩어리가 곧 문제 지점(순환 참조 묶음, 데드락 후보 사이클)이고, 나머지는 DAG라 정상 처리 순서가 나온다.\
  탐지(덩어리 찾기)와 해소 계획(축약 DAG의 위상 순서) 두 가지가 한 번의 SCC로 나온다.\
  (원본에 근거 없음 — 내 추론)
