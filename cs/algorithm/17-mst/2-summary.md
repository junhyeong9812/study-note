## 한눈에 — 쉽게 말하면

**최소 신장 트리(MST) = 모든 마을에 전기가 들어가게 하되, 전선 총 길이를 가장 짧게 까는 방법.**

- 마을(정점)들 사이에 전선 후보(간선)가 여러 개 있고, 각각 비용(가중치)이 다르다.
- 전부 연결하는 데 필요한 전선은 정확히 **마을 수 - 1개**다. 그보다 많으면 어딘가에 사이클(고리)이 생겨 낭비다.
  - *사이클(cycle)*: 한 바퀴 돌아 제자리로 오는 고리. 이미 이어진 두 마을을 또 이으면 생긴다.
- 고르는 방법이 두 가지다. **크루스칼**: 전국의 전선 후보를 싼 순으로 줄 세워, 고리를 안 만드는 것만 채택. **프림**: 한 마을에서 시작해, 지금 연결된 동네에서 밖으로 나가는 전선 중 제일 싼 것을 하나씩 채택.
- 실무 예: 통신망/도로망 설계, 네트워크 케이블 배선, 클러스터링(비슷한 것끼리 묶기).

```text
마을 5개(동그라미 자리 0~4), 전선 후보 7개 (선 위 숫자 = 비용)

    0 ---4--- 1              MST: 채택한 4개만 남김 (총 비용 11)
     \       / \
      1     2   5                0         1
       \   /     \                \       / \
        \ /       \                1     2   5
         2----8----3                \   /     \
          \       /                  \ /       \
           10    3                    2         3
            \   /                              /
             4                                3
                                             /
                                            4
    (채택: 0-2(1), 1-2(2), 3-4(3), 1-3(5) — 버림: 0-1(4), 2-3(8), 2-4(10))
```

## 전체 흐름

```text
가중치 있는 무방향 그래프
   |
   +--> [크루스칼] 간선 "목록"으로 본다 (인접 리스트를 아예 안 봄)
   |      1. 간선 전체를 가중치 오름차순 정렬        <- 비용의 거의 전부
   |      2. 싼 것부터: 양 끝이 다른 덩어리면 채택   <- 유니온 파인드로 판정
   |      3. V-1개 고르면 종료
   |
   +--> [프림] "인접 리스트"로 본다 (간선 목록을 안 봄)
          1. 씨앗 정점 하나를 트리에 넣음
          2. 트리에 닿은 간선들을 힙에 넣음
          3. 힙에서 최소 간선을 꺼냄 — 반대쪽이 트리 밖이면 채택, 안이면 버림
          4. 채택한 정점의 간선을 힙에 추가, 반복
   |
   v
결과: 간선 V-1개, 가중치 합은 두 방법이 항상 같다 (간선 집합은 다를 수 있다)
```

## 동작 — 크루스칼

**언제 쓰나**: 간선 목록만 있으면 된다. 그래프가 안 이어져 있어도 각 덩어리의 MST를 알아서 만든다(간선을 전부 보니까).

위의 예시 그래프. 간선: 0-1(4), 0-2(1), 1-2(2), 1-3(5), 2-3(8), 2-4(10), 3-4(3).

```text
전: 정렬된 간선 줄  [0-2(1), 1-2(2), 3-4(3), 0-1(4), 1-3(5), 2-3(8), 2-4(10)]
    덩어리: {0} {1} {2} {3} {4}   (아직 다 따로)
```

```text
중: 싼 것부터 하나씩 심사
    0-2(1)  -> 0과 2는 딴 덩어리 -> 채택   덩어리: {0,2} {1} {3} {4}
    1-2(2)  -> 딴 덩어리        -> 채택   덩어리: {0,1,2} {3} {4}
    3-4(3)  -> 딴 덩어리        -> 채택   덩어리: {0,1,2} {3,4}
    0-1(4)  -> 같은 덩어리!     -> 버림   (넣으면 0-1-2 고리)
    1-3(5)  -> 딴 덩어리        -> 채택   덩어리: {0,1,2,3,4}
```

```text
후: 채택 4개 = V-1 -> 남은 간선(2-3, 2-4)은 볼 필요도 없이 종료
    MST = {0-2, 1-2, 3-4, 1-3},  합 = 1+2+3+5 = 11
```

단계 (그림 해설: 한 단계 한 문장):

- [1] 간선 전체를 가중치 순으로 정렬한다 — 이 알고리즘 비용의 거의 전부가 여기다.
- [2] 싼 간선부터 유니온 파인드에 `union(양 끝)`을 물어본다 — false(이미 같은 덩어리)면 넣는 순간 사이클이므로 버린다.
  - *유니온 파인드(union-find)*: "두 원소가 같은 덩어리인가"를 빠르게 답하고, 두 덩어리를 합치는 자료구조. 각 원소가 부모를 가리키는 나무 모양이고, 경로 압축(찾는 길에 만난 애들을 뿌리에 바로 붙임) + 랭크 합치기(낮은 나무를 높은 나무 밑에)로 한 번 묻는 비용이 사실상 상수가 된다.
- [3] V-1개를 채택하면 즉시 멈춘다 — 더 볼 이유가 없다.

**왜 되나**: 가장 가벼운 간선은 반드시 어떤 MST에 들어간다. 안 들어간다고 치면, 그 간선을 넣어 생기는 사이클에서 더 무거운 간선을 빼면 더 싼 신장 트리가 나와 모순이다. 이 논증이 남은 간선들에도 반복 적용된다.

**비용**: O(E log E) — 정렬이 지배한다. 측정: 정점 2,000에서 유니온 파인드는 `find` 7,994회에 올라간 걸음 7,043회(한 번에 평균 0.88걸음, 경로 압축 덕) — **정렬 비용의 약 6분의 1**. 조기 종료도 아끼는 건 이미 싼 유니온 파인드뿐이고 정렬은 이미 끝난 뒤라 실익이 작다 — "최적화했다"와 "빨라졌다"는 다른 말.

## 동작 — 프림

**언제 쓰나**: 인접 리스트로 트리를 한 정점에서부터 키운다. 원본 구현은 안 이어진 그래프도 처리한다 — 모든 정점을 씨앗 후보로 돌면서, 아직 트리 밖인 정점을 만나면 거기서 새로 키운다(한 씨앗만 쓰면 그 덩어리만 훑고 나머지를 놓친다).

같은 그래프, 0에서 시작.

```text
전: 트리 {0}      힙: [0-2(1), 0-1(4)]   (0에 닿은 간선들)
```

```text
중: 힙에서 최소를 꺼내 심사
    0-2(1) -> 2는 밖 -> 채택. 트리 {0,2}. 2의 간선 추가 -> 힙 [1-2(2), 0-1(4), 2-3(8), 2-4(10)]
    1-2(2) -> 1은 밖 -> 채택. 트리 {0,1,2}. 1의 간선 추가 -> 힙 [0-1(4), 1-3(5), 2-3(8), 2-4(10)]
    0-1(4) -> 1이 이미 트리 안! -> 그냥 버림  <- "낡은 항목" (다익스트라 14번과 같은 모양)
    1-3(5) -> 채택. 트리 {0,1,2,3}. 3의 간선 추가 -> 힙 [3-4(3), 2-3(8), 2-4(10)]
    3-4(3) -> 채택. 트리 {0,1,2,3,4}
```

```text
후: 남은 힙(2-3, 2-4)은 꺼내는 족족 "둘 다 트리 안"이라 버려짐
    MST 합 = 1+2+5+3 = 11  <- 크루스칼과 같은 합
```

단계 (그림 해설: 한 단계 한 문장):

- [1] 씨앗을 트리에 넣고, 씨앗에 닿은 간선을 힙에 넣는다 — 넣을 때 반대쪽이 이미 트리 안인 간선은 걸러서 힙을 작게 유지한다.
  - *힙(heap, 우선순위 큐)*: "지금 있는 것 중 최솟값"을 빨리 꺼내주는 자료구조. 넣기/꺼내기 각각 O(log 크기).
- [2] 힙에서 최소 간선을 꺼낸다 — 반대쪽 정점이 이미 트리 안이면 사이클이므로 버린다(낡은 항목).
- [3] 트리 밖이면 채택하고, 새 정점에 닿은 간선들을 힙에 추가한다 — 트리가 한 정점씩 자란다.

**왜 되나**: 트리와 나머지를 가르는 어떤 절단에서든, 그 절단을 건너는 가장 가벼운 간선은 반드시 어떤 MST에 들어간다 — 크루스칼의 논증을 "절단"에 대해 말한 것.
  - *절단(cut)*: 정점들을 두 편으로 나누는 것. 두 편 사이를 건너는 간선을 횡단 간선이라 부른다.

**비용**: 힙 프림은 O(E log E) — 트리에 닿은 간선이 전부 힙을 거칠 수 있다. 크루스칼과 **차수가 같다**.

## 비교 — 측정이 보여준 것

**"성긴 그래프는 크루스칼, 촘촘한 그래프는 프림"을 재봤더니 안 맞았다.**

| 그래프 | 크루스칼 비교 | 프림(힙) 비교 | 배수 |
|---|---|---|---|
| 성긴 V=2,000 | 42,725 | 175,892 | 4.1 |
| 촘촘 V=200 | 255,246 | 1,032,598 | 4.0 |
| 촘촘 V=400 | 1,086,307 | 4,778,296 | 4.4 |

- 밀도와 무관하게 **크루스칼이 약 4배 이긴다**. 둘 다 O(E log E)로 차수가 같은데, 힙은 넣기와 빼기를 각각 하므로 상수가 크다.
- "촘촘하면 프림"은 힙 프림이 아니라 **배열로 짠 프림(O(V²))** 얘기다 — 14번에서 배열 다익스트라가 촘촘한 그래프에서 이기던 것과 같은 이야기.
- 정렬 비교가 이론값(E log E = 284,181)보다 적게(255,246) 나온 건 자바 `List.sort`가 팀소트라 이미 정렬된 구간을 재활용하기 때문.
- 가중치가 같은 간선이 여럿이면 **MST가 여러 개**다(변이 전부 1인 정사각형은 답이 4개). 그래서 두 알고리즘을 비교할 때 간선 집합이 아니라 **가중치 합**을 비교해야 한다.

## 핵심 문장

- MST는 "모든 정점 연결 + 간선 V-1개 + 가중치 합 최소" — 사이클은 곧 낭비다.
- 크루스칼은 그래프를 **간선 목록**으로, 프림은 **인접 리스트**로 본다 — 같은 그래프를 다른 모양으로 보는 것이 출발점이다.
- 둘의 정당성은 같은 논증의 두 얼굴이다: "가장 가벼운 간선은 MST에 든다"(크루스칼) = "절단의 최소 횡단 간선은 MST에 든다"(프림).
- 크루스칼의 비용은 사실상 전부 정렬이고, 유니온 파인드는 경로 압축 덕에 거의 공짜다.
- "둘 다 O(E log E)"여도 상수가 4배 다르다 — 빅오 표기가 버린 상수는 재봐야 안다.
- 무거운 간선도 다리 역할이면 반드시 들어간다 — "가벼운 것부터"는 순서일 뿐 조건이 아니다.

## 용어 풀이

- **신장 트리(spanning tree)**: 그래프의 모든 정점을 포함하면서 사이클이 없는 부분 그래프. 간선이 정확히 V-1개다.
- **최소 신장 트리(MST, minimum spanning tree)**: 신장 트리 중 간선 가중치 합이 가장 작은 것. 여러 개일 수 있다.
- **가중치(weight)**: 간선에 붙은 비용 숫자 — 전선 길이, 도로 요금 같은 것.
- **사이클(cycle)**: 한 바퀴 돌아 제자리로 오는 고리. 트리에는 없다.
- **크루스칼(Kruskal)**: 간선을 싼 순으로 정렬해, 사이클을 안 만드는 것만 고르는 MST 알고리즘.
- **프림(Prim)**: 한 정점에서 트리를 키우며, 트리 밖으로 나가는 최소 간선을 반복해 고르는 MST 알고리즘.
- **유니온 파인드(union-find, disjoint set)**: "같은 덩어리인가"(find)와 "덩어리 합치기"(union)를 거의 상수 시간에 하는 자료구조.
- **경로 압축(path compression)**: find가 뿌리를 찾으며 지나온 정점들을 전부 뿌리에 바로 붙여, 다음 find를 한 걸음으로 만드는 기법.
- **랭크 합치기(union by rank)**: 낮은 나무를 높은 나무 밑에 붙여 나무가 길어지는 것을 막는 기법.
- **힙 / 우선순위 큐(heap / priority queue)**: 최솟값(또는 최댓값)을 빨리 꺼내주는 자료구조. 넣기/꺼내기 O(log n).
- **낡은 항목(stale entry)**: 힙에 넣을 때는 유효했지만 꺼낼 때는 이미 쓸모없어진 항목(반대쪽이 이미 트리 안). 꺼내서 확인하고 버린다.
- **절단(cut)** / **횡단 간선(crossing edge)**: 정점을 두 편으로 나누는 것 / 그 두 편 사이를 잇는 간선.
- **성긴/촘촘한 그래프(sparse/dense)**: 간선이 정점 수에 비해 적은/많은 그래프. E가 V에 가까우면 성기고 V²에 가까우면 촘촘하다.
- **인접 리스트(adjacency list)**: 정점마다 "나와 이어진 간선 목록"을 두는 그래프 저장 방식.
- **팀소트(Timsort)**: 자바·파이썬 기본 정렬. 이미 정렬된 구간(run)을 찾아 재활용해서 비교 횟수가 이론 상한보다 적게 나온다.
- **O(E log E)** (빅오 표기): 일의 양이 "간선 수 × 간선 수의 로그"에 비례한다는 뜻. 정렬 한 번의 비용이 이 급이다.
