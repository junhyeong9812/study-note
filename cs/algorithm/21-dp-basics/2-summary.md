# algorithm/21-dp-basics — 정리 (힌트)

## 해결하는 문제

"작은 답을 조합해 큰 답을 만드는" 문제를 재귀로 그대로 쓰면, 같은 작은 문제가 수없이 다시 풀린다.\
피보나치 n=35에서 재귀 호출이 2,986만 번인데 서로 다른 문제는 36개뿐이다.

```text
표 없는 재귀                             표를 쓰면
  fib(35) -> 29,860,703 번 호출            표 쓰기 34 번, 적중 32 번
  n 이 1 늘면 약 1.6 배 (지수)             n 에 비례 (선형)
  배낭 물건 20 개 -> 2^20 갈래             상태 (물건, 남은 무게) 4,221 칸
```

DP는 "같은 상태면 앞으로의 답도 같다"는 성질을 잡아, 한 번 푼 답을 표에 적어 두고 다시 쓴다 — 지수를 상태 수로 끌어내린다.\
쉬운 예: 숙제에서 "3+5"가 백 번 나오면 한 번만 계산해 적어두기 — 한눈에 절.\
똑같은 구조다: 상태 = "지금 어디까지 왔나"를 요약한 숫자 몇 개, 표 = 상태별 답.\
실무 예: 두 파일의 차이(diff)가 푸는 최장 공통 부분수열 문제, 맞춤법 교정의 편집 거리, 자원·예산 배분.

### 한눈에 — 쉽게 말하면

**DP(동적 계획법) = 한 번 푼 문제의 답을 공책에 적어두고, 같은 문제가 또 나오면 다시 풀지 않고 공책을 보는 것.**

- 수학 숙제를 하는데 "3+5"가 백 번 나온다면?\
  백 번 다 손으로 계산하는 사람은 없다.\
  처음 한 번 계산해서 적어두고, 그 다음부터는 적어둔 걸 본다.
- 재귀로 풀면 **같은 작은 문제가 수없이 반복해서 나오는** 문제들이 있다.\
  그때 답을 표에 적어두기만 해도 지수 시간이 선형 시간이 된다.
- 단, 아무 문제나 되는 게 아니다.\
  "**여기까지 어떻게 왔는지**가 앞으로의 답에 영향을 주지 않아야" 표에 적어둘 수 있다(최적 부분 구조).
- 이 챕터의 실측: 피보나치 n=35에서 재귀 호출 **29,860,703번**이 표 쓰기 **34번**으로 준다.\
  878,255배다.

> **재귀(recursion)** — 함수가 자기 자신을 더 작은 입력으로 다시 부르는 방식.\
> 예: `fib(n)`이 `fib(n-1)`과 `fib(n-2)`를 부르는 것.

> **DP(동적 계획법, dynamic programming)** — 큰 문제를 작은 문제로 쪼개 풀되, 작은 문제의 답을 표에 적어두고 재사용하는 방법.\
> 예: 같은 `fib(3)`을 다시 계산하지 않고 공책에서 꺼내 쓴다.

> **최적 부분 구조(optimal substructure)** — 여기까지 온 경로·순서가 앞으로의 최적 답에 영향을 주지 않는 성질.\
> 예: 배낭에서 "몇 번째 물건, 남은 무게"만 같으면 어떤 순서로 왔든 남은 답이 같다 — 이게 없으면 DP를 못 쓴다.

```text
표 없는 재귀: 같은 문제를 계속 다시 푼다      표를 쓰면: 한 번 풀고 적어둔다
        fib(5)                                fib(5)
       /      \                              /      \
   fib(4)    fib(3)  <- 또 나옴          fib(4)    (공책에서 봄)
   /    \    /    \                      /    \
fib(3) fib(2) ...   <- 또또 나옴     fib(3)  (공책에서 봄)
```

실무에서도 같은 구조다: 경로 찾기, 자원 배분, 문자열 비교(diff), 요금 최적화 — "작은 답을 조합해 큰 답을 만드는" 문제 전반에 쓰인다.

## 동작·원리

### 전체 흐름

```text
문제를 받는다
  |
  v
상태를 정한다  <- "지금 어디까지 왔나"를 숫자 몇 개로 요약. 여기가 전부다
  |               (오는 길·순서가 앞으로의 답에 영향을 주면 안 된다 = 최적 부분 구조)
  v
점화식을 세운다  <- 큰 상태의 답 = 작은 상태의 답들을 조합
  |
  v
표를 채운다 — 두 가지 방법
  |-- 메모이제이션: 위에서 아래로. 재귀하되, 푼 것은 표에서 꺼낸다 (필요한 칸만 채움)
  |-- 타뷸레이션 : 아래에서 위로. 작은 것부터 순서대로 전부 채운다 (재귀 없음)
  v
답을 꺼낸다  <- 답이 표의 "마지막 칸"이라는 보장은 없다. 어디에 있는지 문제마다 확인
```

> **상태(state)** — "지금 상황"을 요약한 숫자 묶음. 상태가 같으면 앞으로의 답도 같아야 한다.\
> 예: 피보나치는 `n` 하나, 배낭은 `(물건 번호, 남은 무게)` 둘.

> **점화식(recurrence)** — 큰 상태의 답을 작은 상태의 답으로 표현한 식.\
> 예: `fib(n) = fib(n-1) + fib(n-2)`.

### 동작 — 피보나치 (`Fibonacci.java`)

**언제 쓰나**: 표 하나가 지수를 선형으로 만드는 것을 가장 작게 보여주는 예제.\
상태는 `n` 하나뿐이다.

전 상태 — 표 없는 재귀는 같은 값을 계속 다시 계산한다:

```text
naive(5) 의 호출 트리 (일부)
              5
           /     \
          4       3
        /   \    / \
       3     2  2   1     <- 3 을 두 번, 2 를 세 번 푼다
      / \   / \
     2   1 1   0          n 이 1 늘 때마다 호출이 약 1.6 배씩 는다 (지수)
```

단계 (그림 해설: 한 단계 한 문장):

- **naive**: `n<=1`이면 그대로 반환, 아니면 `naive(n-1) + naive(n-2)`.\
  같은 n이 몇 번이고 다시 계산된다.
- **memoized(위에서 아래)**: 재귀는 같지만, 계산 전에 표를 본다 — 있으면 그대로 쓰고(적중), 없으면 계산해서 넣는다.
- **tabulated(아래에서 위)**: `표[0]=0, 표[1]=1`을 놓고, 2부터 n까지 차례로 `표[i] = 표[i-1] + 표[i-2]`.\
  재귀가 없어 깊이 걱정이 없다.

> **메모이제이션(memoization)** — 위에서 아래로 내려가며 "필요해진 값만" 계산해 표에 적는 방식.\
> 예: `fib(5)`를 부르면 5→4→3… 순으로 내려가고, 이미 적힌 칸을 만나면 거기서 멈춘다.

> **타뷸레이션(tabulation)** — 아래에서 위로, 작은 문제부터 순서대로 표를 전부 채우는 방식.\
> 예: `표[2]`부터 `표[n]`까지 차례로 채운다 — 재귀가 없어 깊이 걱정이 없다.

> **적중(hit)** — 표에서 이미 계산된 값을 찾은 횟수, 곧 다시 계산하지 않은 횟수.\
> 예: n=35에서 적중 32번 — 적중이 0이면 표를 쓸 이유가 없다는 뜻이다.

후 상태 — 표가 채워진 모습:

```text
n     0   1   2   3   4   5
    +---+---+---+---+---+---+
표  | 0 | 1 | 1 | 2 | 3 | 5 |   <- 각 칸을 정확히 한 번씩만 계산
    +---+---+---+---+---+---+
```

**비용**: naive는 O(2^n)에 가까운 지수(호출이 피보나치 수열처럼 는다), 표를 쓰면 O(n) — 칸이 n개고 칸마다 한 번씩만 채우기 때문.\
실측: n=35에서 재귀 호출 29,860,703 vs 표 쓰기 34, 적중 32번(= 다시 계산 안 한 횟수).\
**적중이 0이면 표를 쓸 이유가 없다는 뜻이다.**\
피보나치는 모든 칸이 필요해서 메모와 타뷸의 차이가 안 보인다 — 그 차이는 다음 배낭에서 갈린다.

### 동작 — 0-1 배낭 (`Knapsack.java`)

**언제 쓰나**: 물건마다 "넣는다/안 넣는다"를 골라, 무게 한도 안에서 가치 합을 최대로.\
**메모와 타뷸이 갈리는 첫 문제**다.

전 상태 — 전부 시도하면 2^n:

```text
물건: 무게(3,4,5) 가치(4,5,6), 한도 7

           넣나? 물건0
          /          \
      넣음(무게-3)    안 넣음
       /    \         /    \
   물건1 넣나?...   물건1 넣나?...    <- 갈래가 물건마다 2 배씩 = 2^n
```

단계 (그림 해설: 한 단계 한 문장):

- 핵심 관찰: 중요한 것은 "지금 몇 번째 물건을 보고 있고, 남은 무게가 얼마인가"뿐 — **어떤 순서로 여기 왔는지는 앞으로의 답에 영향을 안 준다**.\
  이 성질(최적 부분 구조)이 없으면 DP를 못 쓴다.
- 그래서 상태를 `(물건 번호, 남은 무게)`로 잡으면 상태가 n × W개뿐이다.
- 각 상태에서 두 갈래만 비교한다: `안 넣음 = 다음 물건으로(무게 그대로)` vs `넣음 = 가치 더하고 다음 물건으로(무게 줄임, 들어갈 때만)`.\
  큰 쪽이 답.
- 코드는 2차원 상태를 `key = index * (capacity+1) + remaining`으로 눌러 1차원 표에 담는다.
- **타뷸레이션은 채우는 방향이 중요하다**: 코드가 `index = n`(물건 끝, 답 0)부터 **거꾸로** 내려온다 — `index`의 답이 `index+1`의 답을 읽기 때문.\
  방향을 거꾸로 하면 아직 안 채운 칸을 읽는다.

> **0-1 배낭(0-1 knapsack)** — 물건을 쪼갤 수 없이 통째로 넣거나 말거나 하는 배낭 문제.\
> 예: 이름의 0-1이 "안 넣거나(0) 넣거나(1)"다.

후 상태 — 두 방법이 채우는 칸이 다르다:

```text
물건 20 개, 한도 200: 표는 4,221 칸
메모이제이션: 2,363 칸만 채움 (56%)   <- 도달 가능한 상태만
타뷸레이션 : 4,221 칸 전부 채움 (100%)

왜? 무게가 3, 7, 11 뿐이면 "남은 무게 1 이나 2" 인 상태는 애초에 안 생긴다.
메모는 그런 칸에 가지 않고, 타뷸은 모르고 다 채운다.
```

**비용**: naive O(2^n), DP O(n×W) — 상태 수 × 상태당 일(두 갈래 비교 = 상수).\
피보나치에서 안 보이던 메모/타뷸의 차이가 여기서 처음 보인다.

### 동작 — 최장 증가 부분수열, LIS (`LongestIncreasing.java`)

**언제 쓰나**: 배열에서 왼쪽→오른쪽 순서를 지키며 골라낸, 값이 점점 커지는 부분수열 중 가장 긴 것의 길이.\
**같은 문제를 푸는 두 알고리즘의 차수가 다른** 예제다.

> **부분수열(subsequence)** — 원래 순서는 지키되 중간을 건너뛰며 골라낸 열. 연속일 필요 없음.\
> 예: `[3,1,4,1,5]`에서 `[3,4,5]`는 부분수열이다.

> **LIS(최장 증가 부분수열)** — 값이 점점 커지는 부분수열 중 가장 긴 것.\
> 예: `[3,1,4,1,5,9,2,6]`의 답은 길이 4(3,4,5,9 또는 1,4,5,6)다.

전 상태 — 예시 입력:

```text
a = [ 3, 1, 4, 1, 5, 9, 2, 6 ]     답: 길이 4 (예: 3,4,5,9 또는 1,4,5,6)
```

단계 — O(n²) 판 (그림 해설: 한 단계 한 문장):

- 상태를 "**i로 끝나는** 최장 증가 부분수열의 길이"로 잡는다(표의 i번 칸).
- i마다 앞의 모든 j를 보고, `a[j] < a[i]`인 j 중에서 `표[j] + 1`의 최댓값을 취한다(없으면 1).
- **답은 표의 마지막 칸이 아니라 전체의 최댓값이다** — 가장 긴 수열이 마지막 원소에서 끝난다는 보장이 없다.

후 상태 — O(n²) 판의 표:

```text
a    =  3   1   4   1   5   9   2   6
표   =  1   1   2   1   3   4   2   4    <- "그 자리로 끝나는" 최장 길이
                            ^       ^
                        전체 최댓값 = 4 가 답 (마지막 칸 아님!)
```

단계 — O(n log n) 판 (그림 해설: 한 단계 한 문장):

- 관리하는 것이 다르다: `tails[k]` = "길이 k+1인 증가 수열의 **마지막 값 중 가장 작은 것**".
- 값을 하나씩 보며, tails에서 그 값이 들어갈 자리(자기보다 크거나 같은 첫 자리)를 이진 탐색으로 찾아 덮어쓴다.
- 맨 끝에 붙었으면 길이가 1 는다.\
  최종 길이가 답이다.

> **tails 배열** — 길이 k+1인 증가 수열의 마지막 값 중 최솟값을 담는 배열.\
> 예: 길이는 맞게 세지만 배열 내용 자체는 실제 부분수열이 아니다.

> **이진 탐색(binary search)** — 정렬된 범위에서 가운데를 보고 절반을 버리기를 반복해 자리를 찾는 방법. O(log n).\
> 예: tails가 항상 증가 상태라 여기에 쓸 수 있다.

후 상태 — tails의 변화:

```text
값:  3     1     4     1     5      9       2        6
tails [3]   [1]   [1,4] [1,4] [1,4,5] [1,4,5,9] [1,2,5,9] [1,2,5,6]
             ^덮음        ^덮음                    ^덮음     ^덮음
길이:  1     1     2     2     3      4       4        4    -> 답 4

주의: 마지막 tails [1,2,5,6] 은 실제 부분수열이 아니다!
(a 에서 1 -> 2 -> 5 순서로는 못 고른다. 5 가 2 보다 앞에 있다)
길이만 맞고 내용은 안 맞는다.
```

- **복원(reconstruct)**: 실제 수열 하나를 꺼내려면 O(n²) 판의 표가 필요하다.\
  표 최댓값 자리에서 출발해, 뒤에서 앞으로 가며 "길이가 1씩 줄어드는 첫 자리"를 이어 붙인다.\
  원본은 "값도 증가하는지"의 검사를 넣었다가, 변종·무작위 테스트로 못 잡자 **수학적으로 증명해서 지웠다** — 첫 자리는 항상 값이 작다는 것이 증명된다(코드 주석에 증명 전문).

> **복원(reconstruction)** — 표에서 최적 "값"만이 아니라 실제 "답 하나"(수열 자체)를 되짚어 꺼내는 것.\
> 예: 표 최댓값 자리에서 출발해 길이가 1씩 줄어드는 첫 자리를 이어 붙이면 수열이 나온다.

**비용**: O(n²) 판은 모든 쌍을 보고, O(n log n) 판은 원소마다 이진 탐색 한 번.\
실측 n=2,000에서 표 읽기 1,013,183 vs 비교 11,452 — 88배.\
단 계측기는 `a[j] < a[i]`일 때만 세므로 **훑기의 절반만 세고 있다** — 측정이 무엇을 안 세는지도 알아야 한다.

## 쓰이는 곳

- **diff · 버전 관리** — 두 텍스트의 최장 공통 부분수열(LCS) = 최단 편집 스크립트로 "무엇이 바뀌었나"를 계산한다. 교과서 DP는 O(nm) 표로 풀지만, `git diff`의 기본 알고리즘(Myers 1986)은 같은 문제를 O(ND) 탐색으로 푼다(D = 차이 크기) — 문제는 같고 푸는 법이 다르다.
- **편집 거리 · 맞춤법 교정** — 삽입·삭제·교체 최소 횟수(Levenshtein). 검색어 오타 보정, 유전자 서열 정렬(Needleman–Wunsch)이 점수 규칙만 다른 같은 모양의 표다.
- **배낭류 자원 배분** — 예산 한도 안에서 가치 최대(광고 슬롯, 클라우드 인스턴스 조합). 상태 = (항목, 남은 예산).
- **최단 경로의 뼈대** — [15-bellman-floyd](../15-bellman-floyd/2-summary.md)의 플로이드가 "경유지 k까지 허용한 최단 거리" 표를 채우는 DP다.
- **정규식·파서** — 와일드카드·간단한 정규식 매칭은 (패턴 위치 × 문자열 위치) 표로 풀 수 있다(실제 정규식 엔진은 보통 오토마톤이나 백트래킹을 쓴다). 문맥 자유 문법 파싱(CYK)은 (구간 × 비단말) 표를 채우는 DP다.
- **LIS 응용** — "순서를 지키며 최대한 많이 살리기". 예: patience diff(`git diff --patience`)가 두 파일에 한 번씩만 나오는 줄들의 짝을 LIS로 골라 뼈대를 잡는다. tails 판의 이진 탐색이 [06-binary-search](../06-binary-search/2-summary.md)의 lowerBound다.

## 적용 — 풀어나가는 법

실제 문제에 붙이는 순서: ① 재귀로 풀면 같은 부분 문제가 반복되는지 본다(반복이 없으면 표를 쓸 이유가 없다 — 적중 0) → ② 상태를 정한다: "무엇이 같으면 앞으로의 답이 같은가"만 남긴다(최적 부분 구조) → ③ 점화식을 세운다 → ④ 메모(필요한 칸만·재귀 깊이)와 타뷸(전부·채우는 방향) 중 고른다 → ⑤ 답의 위치를 확인한다(마지막 칸이 아닐 수 있다) → ⑥ 채운 칸·적중 횟수를 세어 "두 번 계산 안 함"을 확인한다.\
아래 원본 문제가 이 순서를 TODO 1~9로 쪼갠 것이다.

### 비교 — 메모이제이션 vs 타뷸레이션

```text
              메모이제이션 (위->아래)      타뷸레이션 (아래->위)
채우는 칸     필요한 것만 (배낭 56%)      전부 (100%)
재귀          있음 -> 깊이가 쌓임          없음 -> 깊이 걱정 없음
채우는 순서   신경 안 씀 (재귀가 알아서)   직접 정해야 함 (거꾸로 하면 틀림)
```

## 장애 시나리오와 대처

**1. 메모이제이션 재귀의 스택 넘침**

- 현상: 작은 입력은 되는데 n이 수만을 넘으면 `StackOverflowError`로 죽는다.
- 보이는 형태: 스택 트레이스에 같은 메서드가 수천 겹. 표 크기는 충분한데 깊이에서 터진다.
- 원인: 메모 판은 재귀라 깊이가 상태 사슬 길이(피보나치·배낭은 n)만큼 쌓인다(정답 B절 "언제 위험한가" 참고).
- 대처: 타뷸레이션으로 바꾼다(재귀 없음). 못 바꾸면 스레드 스택 크기를 키우거나 명시적 스택으로 변환한다.

**2. 타뷸레이션 채우는 방향이 거꾸로**

- 현상: 답이 항상 0이거나 작은 값으로 나온다.
- 보이는 형태: 배낭에서 `index`의 답이 `index+1`을 읽는데 앞에서부터 채워 아직 0인 칸을 읽는다. 예외는 없다.
- 원인: 읽히는 칸이 먼저 채워져 있어야 하는데 순서가 반대다.
- 대처: 점화식이 "무엇을 읽나"를 보고 그 칸이 먼저 오도록 루프 방향을 정한다. 작은 입력을 손으로 채운 표와 대조하는 테스트를 둔다.

**3. 답을 표의 마지막 칸에서 읽음**

- 현상: LIS가 실제보다 짧게 나온다.
- 보이는 형태: `[3,1,4,1,5,9,2,6]`에서 마지막 칸 4는 우연히 맞지만, `[1,2,3,0]`이면 마지막 칸 1을 돌려준다.
- 원인: "i로 끝나는 최장 길이" 상태는 답이 전체 최댓값이지 마지막 칸이 아니다.
- 대처: 상태 정의에서 답의 위치를 도출하고, 최장 수열이 마지막에서 끝나지 않는 입력을 테스트에 넣는다.

**4. 상태 수 폭발로 OOM**

- 현상: 배낭 한도 W가 수십억이면 `OutOfMemoryError`.
- 보이는 형태: 표 크기 n×W를 잡는 순간 죽는다.
- 원인: DP 비용은 상태 수에 비례하고, W는 입력 크기가 아니라 입력에 적힌 숫자다(의사 다항).
- 대처: 상태를 뒤집는다 — 가치 합을 상태로, 최소 무게를 값으로(정답 B절 "가치를 상태로" 참고). 또는 배열 대신 해시맵 메모로 도달 가능한 상태만 저장한다(원본 측정에서 메모는 표의 56%만 채웠다 — 단 도달 가능한 상태 수 자체가 작다는 보장은 없다).

## 핵심 문장

- DP는 "같은 작은 문제가 반복해서 나올 때, 한 번 푼 답을 표에 적어두고 재사용"하는 것이다 — 적중이 0이면 표를 쓸 이유가 없다.
- 상태를 잡을 수 있는 조건은 최적 부분 구조: "여기까지 어떻게 왔는지"가 앞으로의 답에 영향을 주지 않아야 한다.
- 메모이제이션은 필요한 칸만 채우고(배낭에서 56%), 타뷸레이션은 전부 채우되 재귀 깊이가 없다 — 이 차이는 도달 불가능한 상태가 많은 문제에서만 보인다.
- 같은 문제라도 관리하는 정보를 바꾸면 차수가 바뀐다 — LIS의 O(n²) 표와 O(n log n) tails.\
  단 tails는 실제 부분수열이 아니다.
- "같은 것을 두 번 계산하지 않는다"는 결과만 봐서는 안 보인다 — 채운 칸과 적중 횟수를 세야 확인된다.

### 용어 풀이

- **DP(동적 계획법, dynamic programming)**: 큰 문제를 작은 문제로 쪼개 풀되, 작은 문제의 답을 표에 적어두고 재사용하는 방법.
- **재귀(recursion)**: 함수가 자기 자신을 더 작은 입력으로 다시 부르는 방식.
- **상태(state)**: "지금 상황"을 요약한 숫자 묶음.\
  상태가 같으면 앞으로의 답도 같아야 한다.
- **점화식(recurrence)**: 큰 상태의 답을 작은 상태의 답으로 표현한 식.
- **최적 부분 구조(optimal substructure)**: 여기까지 온 경로·순서가 앞으로의 최적 답에 영향을 주지 않는 성질.\
  이게 없으면 DP를 못 쓴다.
- **메모이제이션(memoization)**: 위에서 아래로 재귀하며, 계산한 값을 표에 적어두고 재사용.\
  필요한 칸만 채운다.
- **타뷸레이션(tabulation)**: 아래에서 위로, 작은 문제부터 순서대로 표를 전부 채움.\
  재귀가 없다.
- **적중(hit)**: 표에서 이미 계산된 값을 찾은 횟수 = 다시 계산하지 않은 횟수.
- **0-1 배낭(0-1 knapsack)**: 물건을 쪼갤 수 없이 통째로 넣거나 말거나 하는 배낭 문제.\
  이름의 0-1이 "안 넣거나(0) 넣거나(1)"다.
- **부분수열(subsequence)**: 원래 순서는 지키되 중간을 건너뛰며 골라낸 열.\
  연속일 필요 없음.
- **LIS(최장 증가 부분수열)**: 값이 점점 커지는 부분수열 중 가장 긴 것.
- **tails 배열**: 길이 k+1인 증가 수열의 마지막 값 중 최솟값을 담는 배열.\
  길이는 맞지만 실제 부분수열은 아니다.
- **이진 탐색(binary search)**: 정렬된 범위에서 가운데를 보고 절반을 버리기를 반복해 자리를 찾는 방법.\
  O(log n).
- **복원(reconstruction)**: 표에서 최적 "값"만이 아니라 실제 "답 하나"(수열 자체)를 되짚어 꺼내는 것.
- **O(n), O(n²), O(2^n), O(n log n)** (빅오): 입력 n에 대해 일의 양이 어떻게 자라는지의 표기.\
  지수 O(2^n)는 n이 조금만 커져도 폭발하고, O(n log n)은 n에 로그 배만 붙는다.
