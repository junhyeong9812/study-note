## 한눈에 — 쉽게 말하면

**DP(동적 계획법) = 한 번 푼 문제의 답을 공책에 적어두고, 같은 문제가 또 나오면 다시 풀지 않고 공책을 보는 것.**

- 수학 숙제를 하는데 "3+5"가 백 번 나온다면? 백 번 다 손으로 계산하는 사람은 없다. 처음 한 번 계산해서 적어두고, 그 다음부터는 적어둔 걸 본다.
- 재귀로 풀면 **같은 작은 문제가 수없이 반복해서 나오는** 문제들이 있다. 그때 답을 표에 적어두기만 해도 지수 시간이 선형 시간이 된다.
  - *재귀(recursion)*: 함수가 자기 자신을 더 작은 입력으로 다시 부르는 방식.
- 단, 아무 문제나 되는 게 아니다. "**여기까지 어떻게 왔는지**가 앞으로의 답에 영향을 주지 않아야" 표에 적어둘 수 있다(최적 부분 구조).
- 이 챕터의 실측: 피보나치 n=35에서 재귀 호출 **29,860,703번**이 표 쓰기 **34번**으로 준다. 878,255배다.

```text
표 없는 재귀: 같은 문제를 계속 다시 푼다      표를 쓰면: 한 번 풀고 적어둔다
        fib(5)                                fib(5)
       /      \                              /      \
   fib(4)    fib(3)  <- 또 나옴          fib(4)    (공책에서 봄)
   /    \    /    \                      /    \
fib(3) fib(2) ...   <- 또또 나옴     fib(3)  (공책에서 봄)
```

실무에서도 같은 구조다: 경로 찾기, 자원 배분, 문자열 비교(diff), 요금 최적화 — "작은 답을 조합해 큰 답을 만드는" 문제 전반에 쓰인다.

## 전체 흐름

```text
문제를 받는다
  |
  v
상태를 정한다  <- "지금 어디까지 왔나"를 숫자 몇 개로 요약. 여기가 전부다
  |               (오는 길·순서가 앞으로의 답에 영향을 주면 안 된다 = 최적 부분 구조)
  v
점화식을 세운다  <- 큰 상태의 답 = 작은 상태의 답들을 조합
  |
  v
표를 채운다 — 두 가지 방법
  |-- 메모이제이션: 위에서 아래로. 재귀하되, 푼 것은 표에서 꺼낸다 (필요한 칸만 채움)
  |-- 타뷸레이션 : 아래에서 위로. 작은 것부터 순서대로 전부 채운다 (재귀 없음)
  v
답을 꺼낸다  <- 답이 표의 "마지막 칸"이라는 보장은 없다. 어디에 있는지 문제마다 확인
```

- *상태(state)*: "지금 상황"을 요약한 숫자 묶음. 피보나치는 `n` 하나, 배낭은 `(물건 번호, 남은 무게)` 둘.
- *점화식(recurrence)*: 큰 문제의 답을 작은 문제의 답으로 표현한 식. 예: `fib(n) = fib(n-1) + fib(n-2)`.

## 동작 — 피보나치 (`Fibonacci.java`)

**언제 쓰나**: 표 하나가 지수를 선형으로 만드는 것을 가장 작게 보여주는 예제. 상태는 `n` 하나뿐이다.

전 상태 — 표 없는 재귀는 같은 값을 계속 다시 계산한다:

```text
naive(5) 의 호출 트리 (일부)
              5
           /     \
          4       3
        /   \    / \
       3     2  2   1     <- 3 을 두 번, 2 를 세 번 푼다
      / \   / \
     2   1 1   0          n 이 1 늘 때마다 호출이 약 1.6 배씩 는다 (지수)
```

단계 (그림 해설: 한 단계 한 문장):

- **naive**: `n<=1`이면 그대로 반환, 아니면 `naive(n-1) + naive(n-2)`. 같은 n이 몇 번이고 다시 계산된다.
- **memoized(위에서 아래)**: 재귀는 같지만, 계산 전에 표를 본다 — 있으면 그대로 쓰고(적중), 없으면 계산해서 넣는다.
  - *메모이제이션(memoization)*: 위에서 아래로 내려가며 "필요해진 값만" 계산해 표에 적는 방식.
- **tabulated(아래에서 위)**: `표[0]=0, 표[1]=1`을 놓고, 2부터 n까지 차례로 `표[i] = 표[i-1] + 표[i-2]`. 재귀가 없어 깊이 걱정이 없다.
  - *타뷸레이션(tabulation)*: 아래에서 위로, 작은 문제부터 순서대로 표를 전부 채우는 방식.

후 상태 — 표가 채워진 모습:

```text
n     0   1   2   3   4   5
    +---+---+---+---+---+---+
표  | 0 | 1 | 1 | 2 | 3 | 5 |   <- 각 칸을 정확히 한 번씩만 계산
    +---+---+---+---+---+---+
```

**비용**: naive는 O(2^n)에 가까운 지수(호출이 피보나치 수열처럼 는다), 표를 쓰면 O(n) — 칸이 n개고 칸마다 한 번씩만 채우기 때문. 실측: n=35에서 재귀 호출 29,860,703 vs 표 쓰기 34, 적중 32번(= 다시 계산 안 한 횟수). **적중이 0이면 표를 쓸 이유가 없다는 뜻이다.** 피보나치는 모든 칸이 필요해서 메모와 타뷸의 차이가 안 보인다 — 그 차이는 다음 배낭에서 갈린다.

## 동작 — 0-1 배낭 (`Knapsack.java`)

**언제 쓰나**: 물건마다 "넣는다/안 넣는다"를 골라, 무게 한도 안에서 가치 합을 최대로. **메모와 타뷸이 갈리는 첫 문제**다.

전 상태 — 전부 시도하면 2^n:

```text
물건: 무게(3,4,5) 가치(4,5,6), 한도 7

           넣나? 물건0
          /          \
      넣음(무게-3)    안 넣음
       /    \         /    \
   물건1 넣나?...   물건1 넣나?...    <- 갈래가 물건마다 2 배씩 = 2^n
```

단계 (그림 해설: 한 단계 한 문장):

- 핵심 관찰: 중요한 것은 "지금 몇 번째 물건을 보고 있고, 남은 무게가 얼마인가"뿐 — **어떤 순서로 여기 왔는지는 앞으로의 답에 영향을 안 준다**. 이 성질(최적 부분 구조)이 없으면 DP를 못 쓴다.
- 그래서 상태를 `(물건 번호, 남은 무게)`로 잡으면 상태가 n × W개뿐이다.
- 각 상태에서 두 갈래만 비교한다: `안 넣음 = 다음 물건으로(무게 그대로)` vs `넣음 = 가치 더하고 다음 물건으로(무게 줄임, 들어갈 때만)`. 큰 쪽이 답.
- 코드는 2차원 상태를 `key = index * (capacity+1) + remaining`으로 눌러 1차원 표에 담는다.
- **타뷸레이션은 채우는 방향이 중요하다**: 코드가 `index = n`(물건 끝, 답 0)부터 **거꾸로** 내려온다 — `index`의 답이 `index+1`의 답을 읽기 때문. 방향을 거꾸로 하면 아직 안 채운 칸을 읽는다.

후 상태 — 두 방법이 채우는 칸이 다르다:

```text
물건 20 개, 한도 200: 표는 4,221 칸
메모이제이션: 2,363 칸만 채움 (56%)   <- 도달 가능한 상태만
타뷸레이션 : 4,221 칸 전부 채움 (100%)

왜? 무게가 3, 7, 11 뿐이면 "남은 무게 1 이나 2" 인 상태는 애초에 안 생긴다.
메모는 그런 칸에 가지 않고, 타뷸은 모르고 다 채운다.
```

**비용**: naive O(2^n), DP O(n×W) — 상태 수 × 상태당 일(두 갈래 비교 = 상수). 피보나치에서 안 보이던 메모/타뷸의 차이가 여기서 처음 보인다.

## 동작 — 최장 증가 부분수열, LIS (`LongestIncreasing.java`)

**언제 쓰나**: 배열에서 왼쪽→오른쪽 순서를 지키며 골라낸, 값이 점점 커지는 부분수열 중 가장 긴 것의 길이. **같은 문제를 푸는 두 알고리즘의 차수가 다른** 예제다.

  - *부분수열(subsequence)*: 순서는 지키되 건너뛰며 골라도 되는 것. `[3,1,4,1,5]`에서 `[3,4,5]`는 부분수열이다(연속일 필요 없음).

전 상태 — 예시 입력:

```text
a = [ 3, 1, 4, 1, 5, 9, 2, 6 ]     답: 길이 4 (예: 3,4,5,9 또는 1,4,5,6)
```

단계 — O(n²) 판 (그림 해설: 한 단계 한 문장):

- 상태를 "**i로 끝나는** 최장 증가 부분수열의 길이"로 잡는다(표의 i번 칸).
- i마다 앞의 모든 j를 보고, `a[j] < a[i]`인 j 중에서 `표[j] + 1`의 최댓값을 취한다(없으면 1).
- **답은 표의 마지막 칸이 아니라 전체의 최댓값이다** — 가장 긴 수열이 마지막 원소에서 끝난다는 보장이 없다.

후 상태 — O(n²) 판의 표:

```text
a    =  3   1   4   1   5   9   2   6
표   =  1   1   2   1   3   4   2   4    <- "그 자리로 끝나는" 최장 길이
                            ^       ^
                        전체 최댓값 = 4 가 답 (마지막 칸 아님!)
```

단계 — O(n log n) 판 (그림 해설: 한 단계 한 문장):

- 관리하는 것이 다르다: `tails[k]` = "길이 k+1인 증가 수열의 **마지막 값 중 가장 작은 것**".
- 값을 하나씩 보며, tails에서 그 값이 들어갈 자리(자기보다 크거나 같은 첫 자리)를 이진 탐색으로 찾아 덮어쓴다.
  - *이진 탐색(binary search)*: 정렬된 목록에서 가운데를 보고 절반을 버리기를 반복하는 찾기. tails가 항상 증가 상태라 쓸 수 있다.
- 맨 끝에 붙었으면 길이가 1 는다. 최종 길이가 답이다.

후 상태 — tails의 변화:

```text
값:  3     1     4     1     5      9       2        6
tails [3]   [1]   [1,4] [1,4] [1,4,5] [1,4,5,9] [1,2,5,9] [1,2,5,6]
             ^덮음        ^덮음                    ^덮음     ^덮음
길이:  1     1     2     2     3      4       4        4    -> 답 4

주의: 마지막 tails [1,2,5,6] 은 실제 부분수열이 아니다!
(a 에서 1 -> 2 -> 5 순서로는 못 고른다. 5 가 2 보다 앞에 있다)
길이만 맞고 내용은 안 맞는다.
```

- **복원(reconstruct)**: 실제 수열 하나를 꺼내려면 O(n²) 판의 표가 필요하다. 표 최댓값 자리에서 출발해, 뒤에서 앞으로 가며 "길이가 1씩 줄어드는 첫 자리"를 이어 붙인다. 원본은 "값도 증가하는지"의 검사를 넣었다가, 변종·무작위 테스트로 못 잡자 **수학적으로 증명해서 지웠다** — 첫 자리는 항상 값이 작다는 것이 증명된다(코드 주석에 증명 전문).

**비용**: O(n²) 판은 모든 쌍을 보고, O(n log n) 판은 원소마다 이진 탐색 한 번. 실측 n=2,000에서 표 읽기 1,013,183 vs 비교 11,452 — 88배. 단 계측기는 `a[j] < a[i]`일 때만 세므로 **훑기의 절반만 세고 있다** — 측정이 무엇을 안 세는지도 알아야 한다.

## 비교 — 메모이제이션 vs 타뷸레이션

```text
              메모이제이션 (위->아래)      타뷸레이션 (아래->위)
채우는 칸     필요한 것만 (배낭 56%)      전부 (100%)
재귀          있음 -> 깊이가 쌓임          없음 -> 깊이 걱정 없음
채우는 순서   신경 안 씀 (재귀가 알아서)   직접 정해야 함 (거꾸로 하면 틀림)
```

## 핵심 문장

- DP는 "같은 작은 문제가 반복해서 나올 때, 한 번 푼 답을 표에 적어두고 재사용"하는 것이다 — 적중이 0이면 표를 쓸 이유가 없다.
- 상태를 잡을 수 있는 조건은 최적 부분 구조: "여기까지 어떻게 왔는지"가 앞으로의 답에 영향을 주지 않아야 한다.
- 메모이제이션은 필요한 칸만 채우고(배낭에서 56%), 타뷸레이션은 전부 채우되 재귀 깊이가 없다 — 이 차이는 도달 불가능한 상태가 많은 문제에서만 보인다.
- 같은 문제라도 관리하는 정보를 바꾸면 차수가 바뀐다 — LIS의 O(n²) 표와 O(n log n) tails. 단 tails는 실제 부분수열이 아니다.
- "같은 것을 두 번 계산하지 않는다"는 결과만 봐서는 안 보인다 — 채운 칸과 적중 횟수를 세야 확인된다.

## 용어 풀이

- **DP(동적 계획법, dynamic programming)**: 큰 문제를 작은 문제로 쪼개 풀되, 작은 문제의 답을 표에 적어두고 재사용하는 방법.
- **재귀(recursion)**: 함수가 자기 자신을 더 작은 입력으로 다시 부르는 방식.
- **상태(state)**: "지금 상황"을 요약한 숫자 묶음. 상태가 같으면 앞으로의 답도 같아야 한다.
- **점화식(recurrence)**: 큰 상태의 답을 작은 상태의 답으로 표현한 식.
- **최적 부분 구조(optimal substructure)**: 여기까지 온 경로·순서가 앞으로의 최적 답에 영향을 주지 않는 성질. 이게 없으면 DP를 못 쓴다.
- **메모이제이션(memoization)**: 위에서 아래로 재귀하며, 계산한 값을 표에 적어두고 재사용. 필요한 칸만 채운다.
- **타뷸레이션(tabulation)**: 아래에서 위로, 작은 문제부터 순서대로 표를 전부 채움. 재귀가 없다.
- **적중(hit)**: 표에서 이미 계산된 값을 찾은 횟수 = 다시 계산하지 않은 횟수.
- **0-1 배낭(0-1 knapsack)**: 물건을 쪼갤 수 없이 통째로 넣거나 말거나 하는 배낭 문제. 이름의 0-1이 "안 넣거나(0) 넣거나(1)"다.
- **부분수열(subsequence)**: 원래 순서는 지키되 중간을 건너뛰며 골라낸 열. 연속일 필요 없음.
- **LIS(최장 증가 부분수열)**: 값이 점점 커지는 부분수열 중 가장 긴 것.
- **tails 배열**: 길이 k+1인 증가 수열의 마지막 값 중 최솟값을 담는 배열. 길이는 맞지만 실제 부분수열은 아니다.
- **이진 탐색(binary search)**: 정렬된 범위에서 가운데를 보고 절반을 버리기를 반복해 자리를 찾는 방법. O(log n).
- **복원(reconstruction)**: 표에서 최적 "값"만이 아니라 실제 "답 하나"(수열 자체)를 되짚어 꺼내는 것.
- **O(n), O(n²), O(2^n), O(n log n)** (빅오): 입력 n에 대해 일의 양이 어떻게 자라는지의 표기. 지수 O(2^n)는 n이 조금만 커져도 폭발하고, O(n log n)은 n에 로그 배만 붙는다.
