## 한눈에 — 쉽게 말하면

**BFS = 호수에 돌을 던졌을 때 물결이 퍼지는 순서.**

- 물결은 가까운 곳을 전부 적신 뒤에야 그다음 동심원으로 나간다.\
  그래서 어떤 지점에 물결이 **처음 닿은 순간**이 곧 가장 빨리 닿을 수 있는 순간이다.
- 그래프에서도 똑같다.\
  시작점에서 한 칸 거리인 정점을 전부 본 뒤에야 두 칸 거리를 본다.\
  그래서 **처음 만났을 때의 거리 = 최단 거리**다.

> **그래프(graph)** — 점(정점)과 점 사이를 잇는 선(간선)으로 관계를 나타낸 것. 지하철 노선도가 그래프다.\
> 예: 역이 정점이고 역과 역을 잇는 구간이 간선이다.

- 이 "가까운 순서 유지"를 실제로 해주는 도구가 **큐**다.\
  먼저 발견한 것을 먼저 처리하는 줄서기.

> **큐(queue)** — 먼저 넣은 것이 먼저 나오는 자료구조. 매표소 줄.\
> 예: 0을 꺼내며 발견한 1·2를 뒤에 세우면, 1·2는 0보다 늦게 나온다 — 그게 거리 순서를 지켜준다.

- 단, 이 성질은 **모든 간선의 비용이 같을 때만** 성립한다.\
  하나라도 다르면 무너진다(그게 14번 다익스트라의 시작점).
- 실무 예: 미로 최단 경로, SNS에서 "몇 다리 건너 아는 사이인가", 지하철 최소 환승 횟수.

```text
돌을 던진 곳(시작점)에서 물결이 퍼진다

      3  2  3
   3  2  1  2  3
   2  1  *  1  2      * = 시작점, 숫자 = 물결이 닿는 순서(=거리)
   3  2  1  2  3
      3  2  3
```

이 박스는 BFS 네 가지를 다룬다: 최단 거리(`distances`), 여러 시작점 동시 출발(`multiSource`), 거리별로 묶기(`levels`), 가중치가 0 또는 1일 때(`ZeroOneBfs`).

## 전체 흐름

```text
시작점을 큐에 넣고 거리 0 으로 표시
   |
   v
큐가 빌 때까지 반복:
   앞에서 하나 꺼낸다 (v)
   v 의 이웃을 하나씩 본다
      처음 만난 이웃이면 -> 거리 = dist[v] + 1 로 표시하고 큐 뒤에 넣는다
      이미 만난 이웃이면 -> 무시
   |
   v
큐가 비면 끝. 표시 안 된 정점 = 못 가는 곳(UNREACHABLE)
```

핵심 불변식: **큐에서 꺼내는 순서가 거리 순이다.**\
거리 d인 정점을 전부 꺼낸 뒤에야 d+1이 나온다.\
이게 유지되는 한 "처음 만난 거리"가 최단 거리다.

> **불변식(invariant)** — 알고리즘이 도는 내내 항상 지켜지는 약속.\
> 예: 여기서는 "꺼내는 순서 = 거리 순"이 그 약속이고, 이게 깨지면 최단 거리 보장도 함께 깨진다.

## 예시 그래프 (이 문서 전체에서 공용)

정점 6개짜리 무방향 그래프.\
12-dfs, 14-dijkstra 문서도 같은 모양을 쓴다.

```text
        0
       / \
      1   2
      |   |
      3   4
       \ /
        5

간선: 0-1, 0-2, 1-3, 2-4, 3-5, 4-5
```

> **무방향(undirected)** — 간선을 양쪽으로 다 지나갈 수 있다. 복도처럼.\
> 예: 간선 `0-1` 은 0에서 1로도, 1에서 0으로도 지나갈 수 있다.

## 동작 — distances / multiSource (최단 거리)

**언제 쓰나**: 시작점에서 각 정점까지 "간선 몇 개를 지나야 하나"를 알고 싶을 때.\
원본 코드에서 `distances`는 `multiSource`에 시작점 하나짜리 배열을 넘길 뿐이다 — **시작점이 하나인 것은 여러 개인 것의 특수한 경우**다.

> **멀티소스 BFS(multi-source)** — 시작점 여러 개를 전부 큐에 넣고 동시에 출발시키는 BFS.\
> 예: 시작점 100개를 한 번에 넣어도 한 번만 돌면 되므로, 100번 따로 도는 것보다 100배 싸다.

전 상태 (시작점 0):

```text
큐: [0]        dist: [0, -, -, -, -, -]    (- = 아직 못 만남)
```

단계 (한 줄 = 한 번 꺼내기):

```text
0 꺼냄 -> 이웃 1, 2 처음 만남     큐: [1, 2]    dist[1]=1, dist[2]=1
1 꺼냄 -> 이웃 3 처음 만남        큐: [2, 3]    dist[3]=2
2 꺼냄 -> 이웃 4 처음 만남        큐: [3, 4]    dist[4]=2
3 꺼냄 -> 이웃 5 처음 만남        큐: [4, 5]    dist[5]=3
4 꺼냄 -> 새 이웃 없음(5는 이미)  큐: [5]
5 꺼냄 -> 새 이웃 없음            큐: []        끝
```

꺼낸 순서 0, 1, 2, 3, 4, 5 — 거리 0, 1, 1, 2, 2, 3 순서 그대로다.

후 상태:

```text
dist: [0, 1, 1, 2, 2, 3]
```

구현에서 중요한 결정 세 가지(원본 코드 주석에 있는 그대로):

1. **방문 표시는 큐에 넣을 때 한다.**\
   뺄 때 해도 거리는 맞게 나온다 — 대신 같은 정점이 여러 번 들어가 큐만 커진다.\
   결과가 같고 비용만 다른 실수라 눈으로는 안 보인다(아래 측정 절).
2. **시작점 범위 검사는 전부 먼저 한다.**\
   검사와 넣기를 한 루프에 섞으면, 목록 뒤쪽이 잘못됐을 때 앞쪽 시작점만 큐에 들어간 채 예외가 나간다 — 호출자가 받은 큐가 반쯤 더럽혀진다.\
   "전부 하거나 아무것도 안 하거나"여야 한다.
3. **같은 시작점이 두 번 들어와도 한 번만 넣는다.**\
   답은 같은데 큐만 커진다.

> **방문 표시(visited)** — 이미 만난 정점을 기록해 두 번 처리하지 않게 하는 장치.\
> 예: 넣을 때 표시하면 정점 하나가 큐에 한 번만 들어가지만, 뺄 때 표시하면 같은 정점이 여러 번 들어간다.

**비용**: O(V+E) — 정점(V)마다 한 번 큐에 들어가고, 간선(E)마다 한 번 조회되기 때문이다.\
원본의 `CountedGraph`가 간선 조회를, `CountedDeque`가 큐 크기를 실제로 세어 이 주장을 숫자로 확인한다.

> **O(V+E)** — 정점 수 + 간선 수에 비례하는 시간. 그래프 전체를 딱 한 번 훑는 비용.\
> 예: 정점 6개·간선 6개짜리 그래프면 일의 양이 대략 12에 비례하고, 로그 같은 항이 더 붙지 않는다.

## 동작 — levels (거리별로 묶기)

**언제 쓰나**: "몇 번째 턴에 어디까지 퍼지나"처럼 층 단위로 뭔가 해야 할 때.\
`levels.get(d)` = 거리 d인 정점들.

> **층/레벨(level)** — 시작점에서 같은 거리에 있는 정점들의 묶음.\
> 예: 시작점 0에서 층 1은 `[1, 2]`, 층 2는 `[3, 4]` 다.

전 상태: 위와 같은 그래프, 시작점 0.

단계 — 요령은 하나다.\
**지금 큐에 들어 있는 것이 정확히 한 층이다.**\
안쪽 루프를 돌기 전에 큐 크기를 재둔다.\
도는 동안 큐가 커지기 때문에, 돌면서 재면 다음 층이 이번 층에 섞여 들어온다.

```text
큐: [0]        크기 1 재둠 -> 0 처리          층 0 = [0]
큐: [1, 2]     크기 2 재둠 -> 1, 2 처리       층 1 = [1, 2]
큐: [3, 4]     크기 2 재둠 -> 3, 4 처리       층 2 = [3, 4]
큐: [5]        크기 1 재둠 -> 5 처리          층 3 = [5]
```

후 상태:

```text
levels = [[0], [1, 2], [3, 4], [5]]
```

**비용**: O(V+E) — 하는 일은 distances와 같고 묶는 방법만 다르다.

## 동작 — ZeroOneBfs (가중치가 0 또는 1)

**언제 쓰나**: 간선 비용이 0 아니면 1일 때.\
예: "같은 역 안 환승은 공짜(0), 한 정거장 이동은 1".\
다익스트라를 써도 답은 나오지만 그건 O(E log V)고 이건 O(V+E)다 — 가중치가 두 종류뿐임을 알면 힙이 필요 없다.

> **가중치(weight)** — 간선을 지나는 비용. 이 박스에서는 0 또는 1만.\
> 예: 같은 역 안 환승은 0, 한 정거장 이동은 1이다.

보통 BFS가 왜 무너지나: 가중치 0인 간선으로 간 정점은 거리가 안 늘었으므로 **지금 층**에 속한다.\
그런데 큐 뒤에 넣으면 다음 층 뒤로 밀려난다 — "꺼내는 순서 = 거리 순"이 깨진다.\
고치는 방법은 한 줄: **가중치 0이면 덱의 앞에 넣는다.**

> **덱(deque)** — 앞뒤 양쪽으로 넣고 뺄 수 있는 큐.\
> 예: 가중치 1이면 뒤에, 가중치 0이면 앞에 넣어 "지금 층"을 먼저 꺼내게 만든다.

전 상태 (같은 모양, 가중치만 붙임 — 0-2와 4-5가 공짜 간선):

```text
        0
    1  / \  0
      1   2
    1 |   | 1
      3   4
    1  \ /  0
        5
```

단계:

```text
0 꺼냄 -> 1(무게1): dist=1, 뒤에    2(무게0): dist=0, 앞에    덱: [2, 1]
2 꺼냄 -> 4(무게1): dist=1, 뒤에                              덱: [1, 4]
1 꺼냄 -> 3(무게1): dist=2, 뒤에                              덱: [4, 3]
4 꺼냄 -> 5(무게0): dist=1, 앞에                              덱: [5, 3]
5 꺼냄 -> 3으로 가면 1+1=2, 지금의 2보다 안 짧음 -> 무시       덱: [3]
3 꺼냄 -> 새로 짧아지는 곳 없음                                덱: []
```

후 상태:

```text
dist: [0, 1, 0, 2, 1, 1]     (2와 5는 공짜 간선 덕에 거리가 안 늘었다)
```

보통 BFS와 다른 결정 두 가지(원본 코드 그대로):

1. **"처음 만났나"가 아니라 "더 짧아졌나"를 본다.**\
   가중치 0 간선 때문에 이미 꺼낸 정점의 거리도 다시 줄 수 있어서다.
2. **거리 초기값을 -1로 못 둔다.**\
   "더 짧아졌나"를 비교해야 하는데 -1은 어떤 거리보다 작다.\
   그래서 큰 값(`Integer.MAX_VALUE`)으로 채워두고 마지막에 못 간 곳만 UNREACHABLE(-1)로 바꾼다.

> **UNREACHABLE** — 시작점에서 못 가는 정점의 거리 표시값(원본에서 -1).\
> 예: 계산 중에는 `Integer.MAX_VALUE` 로 두고, 다 끝난 뒤 그대로 남은 자리만 -1로 바꾼다.

**비용**: O(V+E) — 단, 간선을 정확히 한 번씩 보는 건 아니다(아래 측정).\
그래도 간선 수의 2배 안에 묶이고 로그는 안 붙는다.

## 비교 — 측정이 알려준 것 (원본 README의 실측)

**하나. 방문 표시를 "뺄 때" 해도 최단 거리는 똑같이 나온다.**\
무작위 그래프 50개에서 두 판의 답이 완전히 일치 — **결과 테스트로는 이 실수를 못 잡는다.**\
차이는 큐에만 나타난다.\
정점 200개 완전 그래프:

> **완전 그래프(complete graph)** — 모든 정점 쌍이 간선으로 이어진 그래프.\
> 예: 정점 200개가 서로 다 이어져 있으면, 한 정점의 이웃만 199개다.

| | 큐에 넣은 횟수 | 큐 최대 크기 |
|---|---|---|
| 넣을 때 표시 | 200 | 199 |
| 뺄 때 표시 | 19,901 | 19,702 |

100배.\
그런데 **직선 그래프에서는 차이가 아예 없다**(둘 다 같음) — 이웃이 부모뿐이라 걸러지기 때문.\
개발용 작은 예제는 대개 성긴 그래프라 이 실수는 그대로 배포된다.\
"차이가 작다"가 아니라 "없다"는 것이 이 실수를 특히 위험하게 만든다.

> **성긴/촘촘한 그래프(sparse/dense)** — 간선이 정점 수에 비해 적으면 성김, V²에 가까우면 촘촘함.\
> 예: 직선 그래프는 성기고, 정점 200개 완전 그래프는 촘촘하다 — 실수가 드러나는 쪽은 촘촘한 쪽뿐이다.

**둘. 시작점 100개를 한 번에 넣으면 100배가 아니라 1배다.**\
100x100 격자에서 간선 조회 39,600 대 3,960,000.\
"꺼내는 순서가 거리 순"이 시작점이 여럿이어도 성립하기 때문에 한 번에 넣어도 된다.

**셋. 0-1 BFS는 간선을 한 번씩만 보지 않는다.**\
같은 격자에서 간선 39,600개인데 조회 51,872번 — 가중치 0 간선 때문에 이미 꺼낸 정점이 다시 들어가 이웃을 또 훑는다.\
그래도 2E 안이다.

**넷(변종).** BFS의 `if (dist[to] == UNREACHABLE)`에 `|| dist[v]+1 < dist[to]`를 붙여도 아무것도 안 달라진다 — 이미 거리 순으로 꺼내므로 그 완화 조건이 절대 안 걸린다.\
그 조건이 진짜 필요해지는 것이 다익스트라(14번)다.

> **완화(relaxation)** — "이 길로 가면 더 짧아지나?"를 보고 더 짧으면 거리를 고쳐 쓰는 것.\
> 예: 3까지 2로 알고 있는데 5를 거쳐 1+1=2로 가는 길은 더 짧지 않으므로 고치지 않는다.

## 핵심 문장

- BFS가 최단 거리를 주는 이유는 **큐에서 꺼내는 순서가 거리 순**이기 때문이고, 이 성질은 모든 간선 비용이 같을 때만 성립한다.
- 방문 표시를 넣을 때 하느냐 뺄 때 하느냐는 **결과가 같고 비용만 다르다** — 결과 테스트가 못 잡는 실수는 계측(큐 최대 크기)으로 잡는다.
- 시작점이 하나인 BFS는 여러 개인 BFS의 특수한 경우다.\
  전부 큐에 넣고 한 번 돌리면 O(V+E)로 끝난다.
- 가중치 0이 섞이면 "지금 층" 정점이 생기므로 덱 앞에 넣어 거리 순서를 복구한다 — 그리고 "처음 만났나" 대신 "더 짧아졌나"를 봐야 한다.
- 시작점 검사는 전부 먼저: 전부 하거나 아무것도 안 하거나.

## 용어 풀이

- **그래프(graph)**: 점(정점)과 선(간선)으로 관계를 나타낸 것. 지하철 노선도.
- **정점(vertex, V)** / **간선(edge, E)**: 그래프의 점 / 점과 점을 잇는 선. V, E는 각각의 개수.
- **무방향/방향 그래프**: 간선을 양쪽으로 다닐 수 있으면 무방향, 한쪽으로만이면 방향.
- **인접 리스트(adjacency list)**: 정점마다 "내 이웃 목록"을 들고 있는 그래프 저장 방식. 원본 `CountedGraph`가 이 방식이다.
- **BFS(너비 우선 탐색)**: 가까운 정점부터 물결처럼 퍼져나가는 탐색. 큐를 쓴다.
- **큐(queue)**: 먼저 넣은 것이 먼저 나오는 줄서기 자료구조(FIFO).
- **덱(deque)**: 앞뒤 양쪽으로 넣고 뺄 수 있는 큐. 0-1 BFS가 앞넣기를 쓴다.
- **방문 표시(visited)**: 이미 만난 정점을 기록해 두 번 처리하지 않게 하는 장치.
- **층/레벨(level)**: 시작점에서 같은 거리에 있는 정점들의 묶음.
- **가중치(weight)**: 간선을 지나는 비용. 이 박스에서는 0 또는 1만.
- **0-1 BFS**: 가중치가 0 또는 1뿐일 때, 0이면 덱 앞·1이면 뒤에 넣어 O(V+E)로 최단 거리를 구하는 방법.
- **멀티소스 BFS(multi-source)**: 시작점 여러 개를 전부 큐에 넣고 동시에 출발시키는 BFS.
- **완화(relaxation)**: 더 짧은 길을 발견하면 거리를 고쳐 쓰는 것.
- **불변식(invariant)**: 알고리즘이 도는 내내 항상 지켜지는 약속. 여기서는 "꺼내는 순서 = 거리 순".
- **UNREACHABLE**: 시작점에서 못 가는 정점의 거리 표시값(원본에서 -1).
- **O(V+E), O(E log V)** (빅오): 입력 크기에 따라 일이 얼마나 늘어나는지의 표기. O(V+E)는 그래프를 한 번 훑는 비용, O(E log V)는 간선마다 로그 비용이 붙는 것(힙을 쓰는 다익스트라).
- **성긴/촘촘한 그래프(sparse/dense)**: 간선이 정점 수에 비해 적으면 성김, V²에 가까우면 촘촘함.
- **완전 그래프(complete graph)**: 모든 정점 쌍이 간선으로 이어진 그래프.
