# algorithm/40-complexity-p-np — 정답

## 정답

### 1. 왜 알아야 하나, 다섯 갈래

- 어려운 문제를 못 알아보면, 작은 테스트 데이터에서만 검증한 정확 탐색이 운영 크기에서 끝나지 않는다. 미리 알아보면 설계 단계에서 대안을 고른다.
- 다섯 갈래
  - ① 입력이 작으면 정확해(비트마스크 DP·가지치기 백트래킹·분기 한정).
  - ② 특수 구조면 다항 시간(트리·이분 그래프·2-SAT).
  - ③ 품질 보장이 필요하면 근사 알고리즘(비율 ρ).
  - ④ 좋은 답이면 되면 휴리스틱·지역 탐색(보장 없음).
  - ⑤ 제약이 복잡하면 SAT/ILP/CP 솔버.
- 공통: 시간 상한과 중간 해 반환을 둔다.

### 2. P와 NP

- P: 다항 시간에 **푸는** 결정 문제.
- NP: "예"인 경우 다항 길이 인증서가 있고, 그것을 다항 시간에 **확인하는** 결정 문제(CLRS 34.2).
- NP는 Nondeterministic Polynomial의 약자다. 비결정적 기계가 다항 시간에 푸는 문제라는 뜻이고, "다항이 아님"이 아니다.
- P ⊆ NP: 다항 시간에 풀 수 있으면, 인증서를 무시하고 직접 풀어서 확인하면 된다.

### 3. 배낭 O(nW)

- 입력 길이는 숫자 W를 적는 비트 수(log W)에 비례한다. O(nW) = O(n·2^{log W})라 입력 길이에 대해 지수일 수 있다. 이를 의사 다항 시간이라 한다.
- 장애: 금액 단위를 원 → 0.01원으로 바꾸면 W가 100배, DP 표도 100배다. 운영에서 `OutOfMemoryError: Java heap space`나 시간 폭증으로 나타난다.

### 4. 3-SAT → 독립 집합

```text
  절1 삼각형: x1 ─ x2 ─ ¬x3 ─ x1
  절2 삼각형: ¬x1 ─ x3 ─ x2 ─ ¬x1
  반대 리터럴 간선: x1(절1)─¬x1(절2),  ¬x3(절1)─x3(절2)
  k = 절 수 = 2
```

- 삼각형 안에서는 하나만 고를 수 있으니, 크기 k 독립 집합은 절마다 하나씩 고른다.
- 반대 리터럴끼리 간선이 있으니 고른 리터럴들은 모순이 없다. 그것들을 참으로 하면 절마다 참이 하나 있다 → 충족.
- 역으로 충족 할당에서 절마다 참 리터럴 하나씩 고르면 크기 k 독립 집합이다.
- 예: {x2(절1), x2(절2)}, x2 = T.
- 실험: 무작위 3-SAT 500개(충족 가능 411, 불가 89)에서 두 판정이 500/500 일치했다.

### 5. 환원 방향

- 이미 NP-hard로 알려진 A를 내 문제 B로 환원한다: A ≤p B. B를 풀 수 있으면 A도 풀 수 있으니, B는 A만큼 어렵다.
- 반대(B ≤p A)는 "B는 A보다 어렵지 않다"는 상한 정보일 뿐이다. B가 쉬울 수도 있다. 예: 2-SAT도 SAT로 환원되지만 2-SAT는 P다.

### 6. 무차별 SAT의 시간

- 예측: 변수 하나에 2배 → 6개 늘면 2^6 = 64배 → 약 29 ms × 64 ≈ 1.9초.
- 실험(OpenJDK 21.0.12, `--cpus=2`)

```text
  n=20 할당   1,048,576개      29 ms  sat=false
  n=26 할당  67,108,864개    1679 ms  sat=false
```

- 약 58배로 예측과 비슷하다(n=21~26 각 단계는 약 2배). 사실 점검 재실행에서는 23 ms → 1432 ms로 약 62배였다(실행마다 다르다).
- 증명이 아닌 이유: 이것은 **무차별 대입이라는 특정 알고리즘**의 시간이다. 더 똑똑한 알고리즘이 다항 시간에 풀 가능성을 배제하지 못한다. 그것을 배제하는 것이 P ≠ NP 증명이고, 아직 없다.

### 7. 정점 덮개 2-근사

- 상한: 2(CLRS 35.1).
- 증명 아이디어: 알고리즘이 고른 간선들은 끝점을 공유하지 않는 매칭 M이다. 최적 덮개는 M의 간선마다 끝점 하나 이상이 필요하므로 OPT ≥ |M|. 알고리즘 답 = 2|M| ≤ 2·OPT.
- 실험: 평균 1.576, 최대 2.000. 상한에 닿은 그래프는 있었지만 넘은 그래프는 없었다.

### 8. 끝나지 않는 근무표 배치

- 알아보기
  - 직원 수를 1씩 늘리며 실행 시간 비율을 잰다. 크기 +1마다 상수배(2배 등)면 지수 시간을 의심한다(측정 비율은 단서이고, 확정은 코드의 탐색 구조 분석으로 한다).
  - 스레드 덤프(`jcmd <pid> Thread.print`)에 같은 재귀 탐색 프레임이 계속 보인다. CPU 한 코어 100%가 이어진다.
- 고치기
  - 시간 상한 + 지금까지의 최선 반환. 결과에 "최적 증명 여부"를 남긴다.
  - 탐욕 초기해 + 지역 탐색, 또는 근사(보장 필요 시), 또는 CP/ILP 솔버.
  - 입력 크기 상한을 문서화하고, 작은 입력에서 정확해와의 비율을 회귀 지표로 둔다.

### 9. Cook·Karp

- Cook(1971, STOC): SAT가 NP-완전임을 보였다. NP의 어떤 문제든 SAT로 다항 시간 환원된다(Cook–Levin 정리).
- Karp(1972): SAT에서 21개 조합 문제(CLIQUE, 해밀턴 사이클, 색칠, 분할 등)로 환원해 전부 NP-완전임을 보였다. 환원으로 어려움을 퍼뜨리는 방법을 정착시켰다.
- NP-완전 문제 하나가 다항 시간에 풀리면: NP의 어떤 문제든 그 문제로 환원되므로 NP 전체가 P가 된다(P = NP).
