```java
/** k 를 자기 자리까지 내려보낸다. 힙의 크기는 n 으로 본다. */

//   인덱스 k 의 두 자식은 어디인가.
```

- 인덱스 k 의 두 자식은 어디이고, 부모는 어디인가?

- 오른쪽 자식이 없는 경우를 안 막으면 무슨 일이 생기는가?
- 부모와 자식이 같은 값일 때 자리를 바꾸면 왜 안 되고, 그 실수는 왜 결과 테스트에 안 걸리는가?
- 힙 크기 n 을 배열 길이로 고정하면 정렬 단계에서 무슨 일이 생기는가?

#### 2. 상향식 구성 (BottomUpHeapSort, TODO 1~2)

```java
// TODO 1: 어느 인덱스부터 거꾸로 훑어야 하나.
//   잎은 그 자체로 이미 크기 1 짜리 힙이다. 잎을 건드릴 필요가 있나.
//   길이 n 인 배열에서 잎이 아닌 마지막 노드의 인덱스는 얼마인가.
//   0 부터 앞으로 훑으면 왜 안 되나. 내려꽂기가 성립하려면 아래쪽이 이미 힙이어야 한다.
// TODO 2: 힙을 만든 뒤, 꼭대기를 하나씩 빼서 뒤에 쌓는다.
//   최대 힙의 꼭대기는 최댓값이다. 그것을 어디로 보내야 오름차순이 되나.
//   보낸 다음 힙의 크기는 어떻게 되나. 여기서 보조 배열이 필요한가.
```

- 잎이 아닌 마지막 노드의 인덱스는 얼마이고, 왜 거기서 시작하는가?
- 0 부터 앞으로 훑으면 왜 안 되는가?
- 시작을 n-1 이나 n/2 로 잘못 잡아도 결과·계수기가 전부 같은 이유는 무엇인가?
- 정렬 단계에서 꼭대기를 어디로 보내고, 힙 크기는 어떻게 되는가?
- 오름차순을 원하는데 왜 최소 힙이 아니라 최대 힙을 쓰는가?
- 힙 정렬에 보조 배열이 필요 없는 이유는 무엇인가?

```java
//   그래서 루프의 종료 조건이 둘이다. 하나는 꼭대기에 닿는 것, 다른 하나는 무엇인가.
```

- swim 은 무엇을 하고, 루프의 종료 조건 둘은 무엇인가?

- 하향식의 정렬 단계가 상향식의 sink 를 그대로 써도 되는 이유는 무엇인가?
- 하향식 구성은 왜 O(n log n) 이고 상향식은 왜 O(n) 인가?
- 결과 힙이 똑같이 올바른데 두 방법의 비용 차이는 어디서 오는가?

### B. 개념

#### 5. 생각해볼 것 (원본 README 「생각해볼 것」 이관)

- 자식이 4개, 8개면 더 좋아지는가, 어디서 뒤집히는가?

- 정렬 단계에서 매번 꼭대기와 맨 뒤를 바꾸는데, 그 교환이 꼭 필요한가?
- 힙 정렬은 참조 지역성이 나쁘다고 하는데, 이 계측기로는 왜 그게 안 보이는가?

#### 6. 측정이 알려준 것 (파생)

- 상향식 힙 구성이 진짜 O(n) 이라는 것을 어떤 실측이 증명하는가?
- 그 선형이 성립하는 구조적 이유는 무엇인가(노드 분포)?
- 무작위 입력에서는 상향식과 하향식이 16% 차이뿐인데 오름차순에서 4배로 벌어지는 이유는 무엇인가?
- 내림차순 배열에서 세 판 모두 비교 999·교환 0 인 이유는 무엇인가?
- 3진 힙의 이득이 비교보다 교환에서 크게 나는 이유는 무엇인가?
- "힙 정렬에는 나쁜 입력이 없다"를 뒷받침하는 숫자는 무엇이고, 그 대가는 무엇인가?
- 전체만 재면 1.7% 차이인데 1단계만 재면 4배인 것이 API 설계(heapify/sort 분리)와 무슨 관계인가?

#### 7. 구조와 경계 (파생)

- 힙은 정렬된 배열이 아니다 — 힙 성질이 보장하는 것과 보장하지 않는 것은 각각 무엇인가?
- 완전 이진 트리는 왜 포인터 없이 배열로 표현할 수 있는가?
- "구현에 1단계 끝 표시를 시키는" 설계를 안 한 이유는 무엇인가(원본 README)?
- 잎에 sink 를 걸어도 아무 일도 안 일어난다 — "틀린 것"과 "헛도는 것"의 차이는 무엇이고 왜 계수기에 안 잡히는가?
- 힙 정렬과 우선순위 큐(PriorityQueue)는 무엇을 공유하는가?
- 퀵(03)·병합(02)·힙(04)을 "평균 속도 / 최악 보장 / 추가 메모리 / 안정성"으로 한 줄씩 비교하면?
