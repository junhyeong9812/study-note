### A. 과제 (TODO 1~10 — `src/main/java/com/algo/quick/`)

#### 1. 로무토 분할 (LomutoQuickSort, TODO 1~2)

```java
// TODO 1: 분할하고 양쪽을 각각 재귀한다.
//   구간에 원소가 하나 이하면 어떻게 하나.
//   분할이 돌려준 자리의 원소는 이미 최종 위치다. 그 자리를 재귀에 넣으면 어떻게 되나.
// TODO 2: 손가락 하나로 구간을 훑으면서 피벗보다 작은 것을 앞으로 모은다.
//   "피벗보다 작은 것들"의 끝을 가리키는 변수 하나를 두면 된다. 그 시작값은 얼마인가.
//   루프는 hi 를 포함해야 하나 빼야 하나. 포함하면 피벗을 자기 자신과 비교하게 된다.
//   비교에 등호를 넣으면 값이 전부 같은 배열에서 분할이 어떻게 되나.
//   마지막에 피벗을 제자리로 옮겨야 한다. 어디로 옮기나.
```

- 분할이 돌려준 자리를 재귀 범위에 포함시키면 무슨 일이 생기는가?
- "작은 것들의 끝" 손가락 i 의 시작값은 왜 lo 가 아니라 lo - 1 인가?
- 훑는 루프가 hi 를 빼야 하는 이유는 무엇인가?
- 비교에 등호를 넣으면 전부 같은 값 배열에서 분할이 어떻게 되는가?
- 루프가 끝난 뒤 피벗은 어디로 옮기고, 왜 그 자리가 최종 위치인가?
- 로무토가 정렬된 입력에서 정확히 최악이 되는 이유는 무엇인가?

#### 2. 3중앙값 + 호어 분할 (MedianOfThreeQuickSort, TODO 3~5)

```java
// TODO 4: 세 자리를 정렬한 뒤 중앙값을 lo 로 보낸다.
//   비교와 교환 세 번이면 a[lo] <= a[mid] <= a[hi] 를 만들 수 있다.
//   정렬된 입력에 이 방법을 쓰면 피벗은 어디가 되나. 그게 이 전략의 요점이다.
// TODO 5: 양쪽에서 손가락을 마주 보낸다.
//   왼쪽 손가락은 피벗보다 "크거나 같은" 것을 만나면 멈춘다.
//   오른쪽 손가락은 피벗보다 "작거나 같은" 것을 만나면 멈춘다.
//   왜 둘 다 등호에서 멈추나. 지나쳐 가면 값이 전부 같은 배열에서 무슨 일이 생기나.
//   두 손가락이 엇갈리면 끝이다. 그때 피벗을 어디로 보내야 하나.
//   손가락이 구간 밖으로 나가는 것도 막아야 한다. 어느 쪽이 위험한가.
```

- 세 자리(앞·중간·뒤)를 정렬한 상태에서 중앙값은 어디에 있고, 그걸 어디로 옮기는가?
- 정렬된 입력에서 3중앙값 피벗은 어디가 잡히는가, 그게 왜 이 전략의 요점인가?
- 호어 분할의 두 손가락이 등호에서 멈춰야 하는 이유는 무엇인가?
- 두 손가락이 엇갈리면 피벗을 어디로 보내는가?
- 손가락의 구간 이탈은 어느 쪽이 위험하고 어떻게 막는가?
- 호어 분할이 로무토보다 교환이 적은 이유는 무엇인가?

#### 3. 3분할 (ThreeWayQuickSort, TODO 6~7)

```java
// TODO 6: 경계 세 개(작은 구역의 끝, 큰 구역의 시작, 보고 있는 자리)로 한 번에 훑는다.
//   피벗을 인덱스로 들고 있으면 안 된다. 교환하는 동안 그 자리의 값이 바뀐다.
//   보고 있는 값이 피벗보다 작으면 어디로 보내나. 그 다음 보는 자리는 어디인가.
//   크면 어디로 보내나. 이때 보는 자리를 앞으로 옮기면 안 되는 이유가 있다. 무엇인가.
//   같으면 아무것도 안 해도 된다. 왜인가.
// TODO 7: 재귀는 두 번만 한다.
//   가운데 구역은 왜 재귀하지 않아도 되나.
//   값의 종류가 k 개뿐인 배열에서 이 성질이 깊이를 어디까지 눌러주나.
```

- 피벗을 인덱스가 아니라 값으로 들고 있어야 하는 이유는 무엇인가?
- 보고 있는 값이 피벗보다 작으면 어떻게 하고, i 는 어디로 가는가?
- 크면 어떻게 하고, 이때 i 를 올리면 안 되는 이유는 무엇인가?
- 같으면 아무것도 안 하고 i 만 올려도 되는 이유는 무엇인가?
- 가운데 구역을 재귀하지 않아도 되는 이유는 무엇인가?
- 값의 종류가 k 개뿐이면 재귀 깊이는 어디까지 눌리는가?

### B. 개념

#### 5. 생각해볼 것 (원본 README 「생각해볼 것」 이관)

- 무작위 피벗을 쓰면 최악이 사라지는가, 아니면 최악을 만나기 어려워지기만 하는가?
- 그 둘은 어떻게 다른가?
- 재귀를 두 번 하는 대신 짧은 쪽만 재귀하고 긴 쪽은 반복으로 돌리면 깊이가 어떻게 되는가?
- 3분할에 3중앙값을 얹으려면 어디를 고쳐야 하고, 그러면 잃는 것이 있는가?
- 퀵셀렉트의 최악까지 O(n) 으로 만드는 방법(중앙값의 중앙값)은 왜 실무에서 잘 안 쓰이는가?

#### 6. 측정이 알려준 것 (파생)

- 정렬된 입력에서 로무토의 비교가 정확히 선택 정렬과 같은 n(n-1)/2 인 이유는 무엇인가?
- "느린 것과 죽는 것은 다른 문제다"는 무슨 뜻인가(재귀 깊이 214 vs 23)?
- 무작위 입력에서 3중앙값이 로무토보다 비교가 많은데도 쓰는 이유는 무엇인가(보험료)?
- 전부 같은 값 1,000개에서 3분할이 비교 999·교환 0·쓰기 0으로 끝나는 이유는 무엇인가?
- 중복이 없으면 3분할이 손해가 되는 이유는 무엇인가(쓰기 3.3배)?
- "중복에 강한 것과 피벗을 잘 고르는 것은 별개다"는 어떤 측정이 보여주는가?
- 퀵셀렉트의 비교가 `n + n/2 + n/4 + ...` 로 2n에 수렴하는 이유는 무엇인가?

#### 7. 구조와 경계 (파생)

- 퀵 정렬 세 판이 전부 안정 정렬이 아닌 공통 이유는 무엇인가?
- 병합 정렬은 일이 "합칠 때" 일어나고 퀵 정렬은 "쪼갤 때" 일어난다 — 이 차이가 추가 메모리에 어떻게 나타나는가?
- 병합 정렬의 O(n log n)은 입력과 무관한데 퀵 정렬의 최악은 왜 입력에 달려 있는가?
- 실무 데이터에 "이미 정렬된 입력"이 흔하다는 사실은 판 선택에 무엇을 시사하는가?
