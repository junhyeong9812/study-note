### A. 문제 (src/main 의 TODO 1~10)

#### 1. 빠른 거듭제곱 (`FastPower` — TODO 1~3)

**정답 코드 (impl 기준, 핵심부)**

```java
public static long modPow(long base, long exponent, long mod, CountedOps ops) {
    if (exponent < 0) {
        throw new IllegalArgumentException("지수가 음수다: " + exponent);
    }
    if (mod <= 0) {
        throw new IllegalArgumentException("법이 0 이하다: " + mod);
    }
    ops.enter();
    try {
        if (exponent == 0) {
            return 1 % mod;                 // mod 가 1 이면 0 이어야 한다
        }
        long half = modPow(base, exponent / 2, mod, ops);   // 재귀는 딱 한 번
        ops.multiply();
        long squared = half * half % mod;
        if (exponent % 2 == 0) {
            return squared;
        }
        ops.multiply();
        return squared * (base % mod) % mod;                // 홀수면 한 번 더
    } finally {
        ops.leave();
    }
}

public static long naivePow(long base, long exponent, long mod, CountedOps ops) {
    long result = 1 % mod;
    for (long i = 0; i < exponent; i++) {
        ops.multiply();
        result = result * (base % mod) % mod;
    }
    return result;
}
```

**질문별 답**

- Q: `a^n` 을 `a^(n/2)` 로 표현하는 식은 무엇이고, 지수가 홀수면 무엇이 하나 더 필요한가?\
  A: `a^n = (a^(n/2))²` 이다 — 지수를 반으로 접고 결과를 제곱한다.\
  n 이 홀수면 정수 나눗셈에서 1 이 잘려 나가므로 `a` 를 한 번 더 곱한다: `a^13 = (a^6)² × a`.\
  코드에서는 `exponent % 2 == 0` 이면 제곱만, 아니면 `squared * (base % mod) % mod`.\
  이 한 식이 O(n) 을 O(log n) 으로 바꾸는 전부다.

> **빠른 거듭제곱(fast exponentiation)** — `a^n = (a^(n/2))²` 로 지수를 반씩 접어 O(log n)에 거듭제곱하는 방법.\
> 예: `a^13 = (a^6)² × a` — 홀수면 한 번 더 곱해 잘려 나간 1을 메운다.

> **mod(나머지 연산, modular arithmetic)** — 결과를 항상 m으로 나눈 나머지로 유지하는 계산.\
> 예: 곱할 때마다 `% mod` 를 취해 수가 long 범위를 넘지 않게 한다.

- Q: `pow(a, n/2) * pow(a, n/2)` 라고 쓰면 왜 O(log n) 이 사라지고 다시 O(n) 이 되는가?\
  A: 같은 값을 두 번 계산하기 때문이다.\
  재귀 호출이 층마다 2개로 갈라지면 호출 수가 `2^깊이` — 깊이가 log n 이니 `2^log n = n` 이 된다.\
  반으로 접어 얻은 이득을 갈라짐이 그대로 되돌려 놓는다.\
  그래서 원본 TODO 2 가 "재귀를 두 번 부르면 안 된다"를 못박고, MeasurementTest 가 곱셈 횟수로 그 차이를 고정해 둔다.

> **재귀 트리(recursion tree)** — 재귀 호출이 갈라지는 모양을 나무로 그린 것. 층수가 깊이, 층마다 노드 수가 갈래 수의 거듭제곱이다.\
> 예: 층마다 2개로 갈라지고 깊이가 log n이면 바닥 노드가 `2^log n = n` 개다.

- Q: 그 실수를 막는 장치가 코드에서 무엇 하나인가 — 21번은 같은 실수를 무엇으로 막았는가?\
  A: **지역 변수 `half`** 하나다 — 한 번 부르고 결과를 담아 두었다가 제곱한다.\
  21번(DP 기초)에서는 같은 부분 문제의 중복 계산을 **표(메모이제이션)** 로 막았다.\
  여기서는 겹치는 부분 문제가 한 층에 하나뿐이라 표가 필요 없고, 변수 하나면 충분하다.\
  "중복 계산을 없애는 것"이라는 목적은 같고, 규모에 맞는 도구가 다를 뿐이다.

- Q: 법이 1 이면 답이 항상 무엇이고, 0 제곱에서 `1` 을 그대로 돌려주면 왜 틀리는가?\
  (원본 함정)\
  A: 법이 1 이면 모든 수의 나머지가 0 이므로 답은 항상 **0** 이다.\
  0 제곱에서 `return 1` 이라고 쓰면 mod=1 일 때 1 을 돌려줘 틀린다 — `return 1 % mod` 여야 한다.\
  `1 % 1 = 0` 이라 자동으로 맞게 된다.\
  바닥 조건은 눈에 잘 안 띄는 자리라 이런 경계가 숨기 쉽다 — 행렬 쪽 단위 행렬에서도 똑같은 `1 % mod` 가 나온다.

> **바닥 조건(base case)** — 재귀를 더 쪼개지 않고 답을 바로 돌려주는 자리.\
> 예: 지수 0에서 `return 1 % mod` — `return 1` 로 쓰면 mod=1 인 경계에서 틀린다.

- Q: 지수가 음수이거나 법이 0 이하면 impl 은 무엇을 하는가 — 값으로 알리는가 예외인가?\
  A: **예외**(`IllegalArgumentException`)를 던진다.\
  음수 지수는 `a^(-n) = 1/a^n` 이라 정수 결과가 아니고, 법이 0 이하면 나머지 연산 자체가 정의되지 않는다.\
  둘 다 "계산은 되는데 답이 이상한" 경우가 아니라 **입력 계약 위반**이라 값이 아닌 예외로 알린다.\
  23번 동전의 음수 금액과 같은 판단 — "못 구함"과 "잘못된 입력"을 구분한다.

> **계약 위반(contract violation)** — 함수가 받기로 약속한 범위를 벗어난 입력이 들어온 것.\
> 예: 음수 지수·0 이하의 법은 "답이 없다"가 아니라 질문 자체가 잘못된 것이라 예외로 알린다.

- Q: `ops.enter()`/`ops.leave()` 를 `try/finally` 로 감싸는 이유는?\
  A: 중간에 return 이 여러 개라서다 — 바닥 조건, 짝수, 홀수 세 갈래가 각각 return 한다.\
  `finally` 가 없으면 return 경로마다 `leave()` 를 적어야 하고, 하나만 빠뜨려도 깊이 계측이 조용히 틀어진다.\
  예외가 나가는 경로에서도 짝이 맞는다는 것이 덤이다.\
  계측 코드는 틀려도 컴파일 에러가 안 나므로, 짝을 구조로 강제하는 편이 안전하다.

> **try/finally** — 중간에 어떤 경로로 빠져나가든 `finally` 블록은 반드시 실행된다는 자바 구문.\
> 예: `enter()`/`leave()` 짝을 여기에 넣으면 return이 세 갈래여도 깊이 계측이 안 틀어진다.

- Q: 지수 10억에서 곱셈이 43번이라는 수는 어떻게 나오는 수인가?\
  (원본 측정 하나)\
  A: **제곱 횟수 + 지수의 1 비트 개수**다.\
  10^9 은 2진수로 30비트이고 그중 1 이 13개 — 제곱 30번 + 홀수 보정 13번 = **43번**.\
  한 번씩 곱하면 10억 번이니 **2,325만 배** 차이다(README 표).\
  지수가 커져도 비트 수만큼만 늘어난다 — 10^18 이어도 90번 남짓이다.

- Q: 호출 수와 깊이가 둘 다 31로 같다는 것이 무엇을 증명하는가?\
  A: **재귀가 한 번만 불렸다**는 것 — 갈라지지 않고 한 줄로 내려갔다는 뜻이다.\
  호출이 갈라졌다면 호출 수가 `2^31` 이 됐을 것이다(README).\
  깊이 31 = 지수 10^9 을 반으로 접어 0 이 될 때까지의 층 수.\
  "호출 수 == 깊이"는 두 번 부르기 실수를 잡아내는 **계측 기반 계약**이다 — 성능이 아니라 구조를 테스트한다.

> **구조 계약(structural contract)** — 답이 아니라 "어떻게 계산했는가"를 테스트로 못박는 것.\
> 예: "호출 수 == 깊이" 를 단언해 두면, 답이 맞아도 재귀를 두 번 부른 구현은 잡힌다.

#### 2. 행렬 거듭제곱 (`MatrixPower` — TODO 4~7)

**정답 코드 (impl 기준, 핵심부)**

```java
static long[][] multiply(long[][] a, long[][] b, long mod, CountedOps ops) {
    long[][] out = new long[2][2];
    for (int i = 0; i < 2; i++) {
        for (int j = 0; j < 2; j++) {
            long sum = 0;
            for (int k = 0; k < 2; k++) {
                ops.multiply();
                sum += a[i][k] * b[k][j] % mod;   // 곱한 뒤 바로 mod
                ops.add();
            }
            out[i][j] = sum % mod;
        }
    }
    return out;                                    // 곱셈 2x2x2 = 8 번
}

public static long[][] power(long[][] base, long exponent, long mod, CountedOps ops) {
    if (exponent < 0) {
        throw new IllegalArgumentException("지수가 음수다: " + exponent);
    }
    ops.enter();
    try {
        if (exponent == 0) {
            return new long[][] {{1 % mod, 0}, {0, 1 % mod}};   // 단위 행렬
        }
        long[][] half = power(base, exponent / 2, mod, ops);    // 여기서도 한 번만
        long[][] squared = multiply(half, half, mod, ops);
        if (exponent % 2 == 0) {
            return squared;
        }
        return multiply(squared, base, mod, ops);
    } finally {
        ops.leave();
    }
}

public static long fibonacci(long n, long mod, CountedOps ops) {
    if (n < 0) {
        throw new IllegalArgumentException("n 이 음수다: " + n);
    }
    if (n == 0) {
        return 0;
    }
    long[][] m = power(new long[][] {{1, 1}, {1, 0}}, n - 1, mod, ops);
    return m[0][0] % mod;      // [[1,1],[1,0]]^(n-1) 의 왼쪽 위가 F(n)
}
```

```
[ F(n)   ] = [ 1 0 ] x [ F(n-1) ]      한 번 곱하면 한 칸 전진

[ 1 1 ]^(n-1)   [ F(n)   F(n-1) ]
[ 1 0 ]       = [ F(n-1) F(n-2) ]      왼쪽 위 칸이 F(n)
```

**질문별 답**

- Q: 2x2 행렬 곱 한 번에 곱셈은 몇 번 일어나는가?\
  A: **8번**이다 — 출력 칸 4개(2×2) × 각 칸마다 곱셈 2번(k 가 0,1).\
  코드의 삼중 루프 `i × j × k` = 2×2×2 = 8 이 그대로 보인다.\
  그래서 README 의 "곱셈 808번 = 행렬 곱 101번 × 8" 이 나온다.\
  일반화하면 `d×d` 행렬은 한 번 곱하는 데 `d³` 번 — 슈트라센이 줄이려는 것이 이 수다.

- Q: 곱한 뒤 바로 `% mod` 를 취하지 않으면 무엇이 넘치는가?\
  A: `long` 이 넘친다(오버플로).\
  mod 가 10^9 근처면 두 원소가 각각 10^9 이라 곱이 10^18, 그걸 여러 개 더하면 long 의 한계 9.2×10^18 를 넘어간다.\
  넘치면 예외가 아니라 **조용히 엉뚱한 값**이 되므로 테스트가 안 잡으면 그대로 통과한다.\
  그래서 곱하자마자 `% mod` 로 값을 작게 유지하는 것이 습관이다.

> **오버플로(overflow, 넘침)** — 계산 결과가 자료형의 범위(long은 약 9.2×10^18)를 넘어 엉뚱한 값이 되는 것.\
> 예: 예외가 아니라 조용히 엉뚱한 값이 되므로 테스트가 안 잡으면 그대로 통과한다.

- Q: 그 `% mod` 를 빼도 지금 테스트가 전부 통과하는 이유는 무엇인가?\
  (원본 변종)\
  A: 지금 조건에서는 합이 long 안에 들어가기 때문이다.\
  2×2 라 한 칸에 더해지는 항이 2개뿐이고, mod 가 10^9 근처면 곱이 10^18, 둘을 더해도 2×10^18 — long 의 9.2×10^18 안이다.\
  변종 검증(일부러 `% mod` 를 빼 보기)으로 이것을 확인했고, 테스트가 그 변종을 못 잡았다.\
  "테스트가 못 잡는다 = 그 코드가 불필요하다"가 아니라, **테스트 입력의 범위가 좁을 뿐**이었던 사례다.

> **변종 검증(mutation testing)** — 코드를 일부러 조금 망가뜨려(변종) 테스트가 그걸 잡는지 확인하는 기법.\
> 예: `% mod` 를 빼 봤더니 테스트가 안 깨졌다 — 코드가 불필요해서가 아니라 입력 범위가 좁아서였다.

- Q: 그런데도 `% mod` 를 남겨야 하는 이유는 — 어떤 조건이 바뀌면 터지는가?\
  A: mod 가 3×10^9 을 넘거나 행렬이 3×3 이 되는 순간 넘친다(README).\
  3×3 이면 한 칸에 더해지는 항이 3개가 되고, mod 가 커지면 항 하나가 커진다 — 둘 중 어느 쪽이든 합이 long 을 넘는다.\
  **"지금 안 터진다"와 "안전하다"는 다르다** — 안전은 지금 입력이 아니라 계약이 허용하는 입력 전체에서 성립해야 한다.\
  이 챕터가 같은 교훈을 두 번(여기, 그리고 카라추바의 `floorDiv`) 보여준다.

- Q: 행렬에서 "숫자 1"에 해당하는 것은 무엇이고, 그것도 왜 `1 % mod` 여야 하는가?\
  A: **단위 행렬**(대각선만 1, 나머지 0)이다 — 무엇에 곱해도 그대로라 곱셈의 항등원이다.\
  0 제곱의 값이 단위 행렬인 것은 `a^0 = 1` 의 행렬판이다.\
  mod 가 1 이면 모든 값이 0 이어야 하므로 대각선도 `1 % mod` 로 써야 한다 — FastPower 의 바닥 조건과 완전히 같은 함정이다.\
  같은 실수가 두 파일에 각각 숨는다는 것이 이 함정이 잘 안 보인다는 증거다.

> **단위 행렬(identity matrix)** — 대각선만 1이고 나머지가 0인 행렬. 곱셈의 항등원이다.\
> 예: 행렬의 0제곱이 이것이고, 숫자의 `a^0 = 1` 에 대응한다.

- Q: 피보나치 점화식을 어떤 2x2 행렬로 쓰는가, `F(n)` 은 그 행렬의 몇 제곱 어느 칸에 있는가?\
  A: `[[1,1],[1,0]]` 이다 — 이 행렬을 `[F(n), F(n-1)]` 에 곱하면 `[F(n+1), F(n)]` 이 된다(한 칸 전진).\
  그래서 `[[1,1],[1,0]]^(n-1)` 의 **왼쪽 위 칸 `m[0][0]`** 이 `F(n)` 이다.\
  곱셈이 결합법칙을 따르므로 빠른 거듭제곱을 그대로 적용할 수 있다 — 접는 대상만 숫자에서 행렬로 바뀐다.\
  행렬을 세우는 규칙은 일반적이다: 점화식이 앞 k 항의 상수배 합이면 `k×k` 행렬이 나온다.

> **결합법칙(associativity)** — `(A·B)·C = A·(B·C)`, 곧 묶는 순서를 바꿔도 결과가 같은 성질.\
> 예: 행렬 곱이 이 성질을 가지므로, 숫자에 쓰던 빠른 거듭제곱을 그대로 행렬에 적용할 수 있다.

- Q: `n = 0` 을 따로 다뤄야 하는 이유는?\
  A: `n - 1` 이 -1 이 되어 `power` 의 음수 지수 검사에 걸리기 때문이다.\
  식 `[[1,1],[1,0]]^(n-1)` 자체가 n ≥ 1 에서만 뜻이 있다.\
  그래서 impl 은 `if (n == 0) return 0;` 로 F(0)=0 을 직접 돌려준다.\
  "일반 공식이 가장 작은 입력에서 성립하는가"를 확인하는 것이 바닥 조건 점검의 정석이다.

- Q: `F(10^18)` 을 곱셈 808번으로 구한다는 수는 어떻게 쪼개지는가?\
  (원본 측정 둘)\
  A: **2×2 행렬 곱 101번 × 곱셈 8번 = 808번**이다.\
  행렬 곱 101번은 깊이 61(지수 10^18-1 이 60비트) 에서 제곱 60번 + 홀수 보정 41번으로 나온다.\
  즉 "거듭제곱을 접는 구조"는 FastPower 와 똑같고, 한 번의 곱셈 단가가 1 에서 8 로 바뀐 것뿐이다.\
  단가가 상수이므로 전체는 여전히 O(log n) 이다.

- Q: 21번의 표 방식으로는 왜 `n = 10^18` 에 갈 수 없는가?\
  A: 표의 칸이 `10^18` 개 필요해서다 — 만들 수 있는 크기가 아니다.\
  표 방식(DP)은 O(n) 시간이면서 O(n)(또는 롤링으로 O(1)) 공간인데, **시간이 n 에 비례하는 것 자체**가 벽이다.\
  10^18 번의 덧셈은 공간을 줄여도 끝나지 않는다.\
  행렬 방식은 n 을 지수 자리에서 다루므로 자릿수(로그)만큼만 일한다 — 차원이 다른 접근이다.

- Q: "상태 공간을 만들지 않고 푸는 방법이 있다"는 말은 피보나치 말고 무엇까지 적용되는가?\
  A: **선형 점화식이면 무엇이든** 적용된다(impl javadoc 이 "피보나치만의 기법이 아니다"라고 못박는다).\
  `F(n) = 2F(n-1) + 3F(n-3)` 같은 것도 3×3 행렬로 쓰면 그대로 O(log n) 이다.\
  조건은 "다음 항이 앞 항들의 **상수배 합**"일 것 — 계수가 n 에 따라 변하거나 비선형이면 이 변환이 안 된다.\
  일반화의 값은 도구가 아니라 **적용 조건을 아는 것**에 있다.

> **선형 점화식(linear recurrence)** — 다음 항이 앞 항들의 상수배 합인 식.\
> 예: `F(n) = 2F(n-1) + 3F(n-3)` 도 3×3 행렬로 쓰면 O(log n)에 풀린다 — 계수가 n에 따라 변하면 안 된다.

#### 3. 카라추바 곱셈 (`Karatsuba` — TODO 8~10)

**정답 코드 (impl 기준, 핵심부)**

```java
private static int[] multiplyRaw(int[] x, int[] y, CountedOps ops) {
    ops.enter();
    try {
        int n = x.length;
        if (n == 1) {
            ops.multiply();
            return new int[] {x[0] * y[0]};
        }
        int half = n / 2;
        int[] lowX  = Arrays.copyOfRange(x, 0, half);
        int[] highX = Arrays.copyOfRange(x, half, n);
        int[] lowY  = Arrays.copyOfRange(y, 0, half);
        int[] highY = Arrays.copyOfRange(y, half, n);

        int[] lowProduct  = multiplyRaw(pad(lowX,  n - half), pad(lowY,  n - half), ops);  // bd
        int[] highProduct = multiplyRaw(pad(highX, n - half), pad(highY, n - half), ops);  // ac

        // (a+b)(c+d) 하나만 더 계산한다. 여기가 카라추바의 전부다.
        int[] sumX = add(lowX, highX, ops);
        int[] sumY = add(lowY, highY, ops);
        int size = Math.max(sumX.length, sumY.length);
        int[] middle = multiplyRaw(pad(sumX, size), pad(sumY, size), ops);
        middle = subtract(subtract(middle, lowProduct, ops), highProduct, ops);   // - bd - ac

        int[] result = new int[2 * n];
        addInto(result, lowProduct,  0,        ops);
        addInto(result, middle,      half,     ops);
        addInto(result, highProduct, 2 * half, ops);
        return result;
    } finally {
        ops.leave();
    }
}

private static int[] carry(int[] raw) {
    int[] out = Arrays.copyOf(raw, raw.length + 2);
    int carry = 0;
    for (int i = 0; i < out.length; i++) {
        int value = out[i] + carry;
        carry  = Math.floorDiv(value, 10);    // / 가 아니라 floorDiv
        out[i] = Math.floorMod(value, 10);    // % 가 아니라 floorMod
    }
    ...
}
```

**질문별 답**

- Q: `ad + bc` 를 곱셈 한 번으로 얻는 항등식은 무엇인가?\
  A: `ad + bc = (a+b)(c+d) − ac − bd` 다.\
  `(a+b)(c+d)` 를 펼치면 `ac + ad + bc + bd` 이므로, 양 끝의 `ac` 와 `bd` 를 빼면 가운데 항만 남는다.\
  곱셈 하나와 뺄셈 둘의 맞바꿈이다 — 뺄셈은 O(n) 이고 곱셈은 재귀라 훨씬 비싸니 이득이다.\
  impl 의 `subtract(subtract(middle, lowProduct), highProduct)` 가 정확히 이 식이다.

- Q: 그 항등식이 "공짜"인 이유는 — 이미 계산해 둔 것이 무엇이기 때문인가?\
  A: `ac` 와 `bd` 를 **어차피 계산해야 하기** 때문이다 — 결과식의 `B²` 항과 상수항에 그대로 쓰인다.\
  이미 손에 있는 두 값을 재활용하니 새로 드는 비용은 `(a+b)(c+d)` 곱셈 하나뿐이다.\
  그래서 4번이 3번이 된다 — 부분 문제 개수 a 가 4 에서 3 으로 하나 준다.\
  "이미 계산한 것을 다시 쓴다"는 점에서 DP 와 뿌리가 같고, 다른 점은 표가 아니라 **대수 항등식**으로 재활용한다는 것이다.

> **카라추바(Karatsuba)** — 반으로 자른 곱셈에서 `ad+bc = (a+b)(c+d)−ac−bd` 를 이용해 곱셈 4번을 3번으로 줄이는 큰 수 곱셈.\
> 예: 부분 문제 개수 a가 4에서 3으로 하나 줄어 O(n²)가 O(n^1.585)가 된다.

- Q: 12 × 34 를 카라추바로 손으로 풀면 세 곱과 가운데 항이 각각 얼마인가?\
  A: a=1, b=2, c=3, d=4 (윗자리/아랫자리).\
  `ac = 1×3 = 3`, `bd = 2×4 = 8`, `(a+b)(c+d) = 3×7 = 21`.\
  가운데 = 21 − 3 − 8 = **10**.\
  합치면 `3×100 + 10×10 + 8 = 408` — 12×34 = 408 이 맞는다(가운데 자릿값이 10 을 넘어도 마지막 자리올림이 정리한다).

- Q: 자릿수가 홀수이거나 양쪽 길이가 다르면 impl 은 어떻게 맞추는가?\
  A: **0 으로 채워(pad) 길이를 맞춘다.**\
  입구 `multiply` 에서 `Arrays.copyOf(x, n)`·`copyOf(y, n)` 로 둘 다 `max(len)` 으로 늘린다 — 윗자리 0 은 값을 안 바꾼다.\
  재귀 안에서는 `half = n/2` 로 자른 뒤 `pad(..., n - half)` 로 양쪽 조각을 같은 길이로 만든다(홀수면 윗조각이 한 자리 길다).\
  `(a+b)` 가 자리올림으로 한 자리 길어질 수 있어, 가운데 곱 전에도 `size = max(sumX, sumY)` 로 다시 맞춘다.

> **패딩(padding, 0 채우기)** — 길이를 맞추려고 윗자리에 0을 덧붙이는 것.\
> 예: 윗자리 0은 값을 안 바꾸므로 `[1,2]` 를 `[0,0,1,2]` 로 늘려도 같은 수다.

- Q: 계산 중에 자릿값이 10 을 넘어도 되는 이유는, 정리는 언제 한 번 하는가?\
  A: 자릿값 배열은 "각 자리에 계수를 담은 다항식"이라, 계수가 10 을 넘어도 나타내는 **수 자체는 옳기** 때문이다.\
  `Σ digit[i]·10^i` 라는 의미가 유지되는 한 중간 표현은 자유롭다.\
  그래서 재귀 내내 정리하지 않고, 맨 바깥 `multiply` 에서 `carry(raw)` 를 **한 번만** 부른다.\
  정리를 층마다 하면 O(n) 작업이 층마다 붙어 손해다 — 불변식을 느슨하게 두고 마지막에 복원하는 전형적인 최적화다.

> **자리올림(carry)** — 한 자리가 10을 넘으면 윗자리로 넘겨 각 자리를 0~9로 되돌리는 정리 작업.\
> 예: 재귀 내내 미뤄 두었다가 맨 바깥에서 딱 한 번만 한다.

> **불변식(invariant)** — 그 자료구조가 늘 지켜야 하는 성질.\
> 예: 여기서는 "각 자리가 0~9"가 불변식인데, 중간에는 일부러 깨 두고 마지막에 복원한다.

- Q: 자바에서 `-3 / 10` 과 `-3 % 10` 은 각각 얼마이고, 그것이 자리올림에서 왜 문제인가?\
  A: `-3 / 10 = 0`, `-3 % 10 = -3` 이다 — 자바의 `/` 는 0 쪽으로 잘라낸다.\
  자리올림은 "이 자리를 0~9 로 만들고 넘치는 만큼 윗자리로 올린다"인데, 올림이 0 이고 자릿값이 -3 으로 **음수인 채 남는다**.\
  그러면 결과 배열이 정상적인 10진 표현이 아니게 되고, 값 비교·출력이 전부 틀어진다.\
  `Math.floorDiv(-3, 10) = -1`, `Math.floorMod(-3, 10) = 7` — 내림 방향이라 "7 을 두고 -1 을 올린다"가 되어 의미가 유지된다.

> **floorDiv / floorMod** — 자바에서 음수에도 "내림" 방향으로 일관된 몫/나머지를 주는 함수.\
> 예: `/`·`%` 는 0 쪽으로 잘라 `-3/10=0`, `-3%10=-3` 이라 자릿값이 음수로 남는다.

- Q: `/`·`%` 로 바꿔도 지금 테스트가 통과하는 대수적 이유는 무엇인가?\
  (원본 변종)\
  A: **지금은 음수 자릿값이 나오지 않기** 때문이다.\
  중간항 `(a+b)(c+d) − ac − bd` 의 i 번째 자릿값을 펼치면 `Σ a_p·d_q + Σ b_p·c_q` 만 남는데, 전부 0 이상이라 뺄셈 뒤에도 음수가 없다(impl javadoc).\
  변종 검증으로 `/` 로 바꿔 봐도 테스트가 다 통과했고, 대수적으로도 그렇다고 확인했다.\
  즉 테스트의 구멍이 아니라 **현재 전제 안에서는 정말 같은 동작**인 경우다.

- Q: 그래도 `floorDiv`·`floorMod` 를 쓰는 이유는?\
  A: 진법을 바꾸거나 뺄셈을 하나 더 넣는 순간 그 항등식이 깨지고 음수 자릿값이 나오기 때문이다.\
  그때 `/`·`%` 는 예외 없이 **조용히 틀린 답**을 낸다 — 가장 잡기 어려운 종류의 버그다.\
  `% mod` 사례와 같은 판단: 지금 안전한 이유가 "우연히 성립하는 좁은 전제"라면, 전제가 아니라 코드로 안전을 보장한다.\
  비용이 0 에 가까운 방어는 전제가 흔들릴 가능성이 조금만 있어도 남기는 것이 낫다.

- Q: `T(n) = 4T(n/2) + O(n)` 과 `T(n) = 3T(n/2) + O(n)` 의 답은 각각 무엇인가?\
  A: 각각 `O(n^log₂4) = O(n²)` 와 `O(n^log₂3) = O(n^1.585)` 다.\
  마스터 정리에서 `a` 는 부분 문제 개수, `b` 는 줄어드는 비율이고, 답의 지수는 `log_b a` 다.\
  둘 다 b=2, 합치는 비용 f(n)=O(n) 로 같고 **오직 a 만 4→3** 인데 차수가 바뀐다.\
  이것이 "부분 문제 개수가 지수 자리에 들어간다"는 말의 정확한 뜻이다.

> **마스터 정리(master theorem)** — `T(n) = a·T(n/b) + f(n)` 모양 점화식의 차수를 읽는 공식(a = 부분 문제 개수, b = 줄어드는 비율, f = 합치는 비용).\
> 예: b와 f가 같아도 a만 4에서 3으로 바뀌면 O(n²)가 O(n^1.585)가 된다.

- Q: 자릿수 64에서 729 대 4,096 이라는 수가 `3^6`·`4^6` 인 이유는?\
  (원본 측정 셋)\
  A: 64 자리를 반으로 접으면 1 자리까지 **6번** 접힌다(64→32→16→8→4→2→1).\
  층마다 가지가 3개(카라추바) 또는 4개(그대로)로 갈라지므로, 바닥의 곱셈 횟수가 `3^6 = 729`, `4^6 = 4,096` 이다.\
  배수는 자릿수 8에서 2.37, 16에서 3.16, 32에서 4.21, 64에서 **5.62** — 계속 벌어진다.\
  벌어진다는 것 자체가 상수 배가 아니라 **차수 차이**라는 증거다.

- Q: 호출 수 1,093 과 5,461 은 각각 어떤 트리의 무엇인가?\
  A: 가지 3개·4개짜리 재귀 트리의 **전체 노드 수**다.\
  `1 + 3 + 3² + ... + 3⁶ = (3⁷−1)/2 = 1,093`, `1 + 4 + ... + 4⁶ = (4⁷−1)/3 = 5,461`.\
  바닥의 곱셈 수(729·4,096)가 마지막 층이라면, 호출 수는 그 위 모든 층을 합친 것이다.\
  측정값이 닫힌 식과 정확히 일치한다는 것이 "구현이 이론대로 갈라졌다"는 확인이다 — 시간이 아니라 구조를 재는 계측의 힘이다.

### B. 개념

- Q: (원본 생각해볼 것) 슈트라센 행렬 곱은 8번을 7번으로 줄인다 — 차수가 얼마가 되는가?\
  A: (원본에 답 없음 — 내 추론 + 알려진 결과) `O(n^log₂7) ≈ O(n^2.807)` 이다.\
  `n×n` 행렬 곱을 2×2 블록으로 자르면 부분 문제가 8개(`T(n) = 8T(n/2) + O(n²)` → `O(n³)`), 슈트라센은 덧셈·뺄셈을 더 써서 그것을 7개로 줄인다.\
  카라추바와 정확히 같은 수법이다 — 곱셈 하나를 덧뺄셈 여럿과 맞바꿔 **a 를 줄인다**.\
  `log₂7 = 2.807` 이라 n 이 커질수록 이득이지만, 상수가 크고 수치 안정성이 떨어져 실무 적용은 제한적이다.

- Q: (원본 생각해볼 것) 카라추바는 자릿수가 작을 때 손해인데, 실제 라이브러리는 어디서 갈아타는가?\
  A: (원본에 답 없음 — 내 추론, 실측 필요) 대략 수십 자리 단위의 **문턱값(threshold)** 에서 갈아탄다.\
  카라추바는 곱셈을 하나 줄이는 대신 덧셈·뺄셈·배열 복사·재귀 호출을 더 쓴다 — 자릿수가 작으면 그 부대 비용이 이득보다 크다.\
  그래서 보통 "자릿수 < K 이면 O(n²) 교과서 곱셈, 아니면 카라추바" 식으로 재귀 바닥을 올려 잡는다(자바 `BigInteger` 도 같은 구조의 문턱값을 둔다 — 정확한 값은 본인 확인 필요).\
  일반 교훈: **차수가 낮다고 항상 빠른 것이 아니다** — 교차점을 실측으로 찾아야 한다.

- Q: (원본 생각해볼 것) 마스터 정리가 안 통하는 점화식은 어떤 모양이고, 행렬로 풀 다른 점화식을 하나 만들면?\
  A: (원본에 답 없음 — 내 추론) 마스터 정리는 `T(n) = a·T(n/b) + f(n)` 처럼 **부분 문제가 모두 같은 크기**일 때만 쓴다.\
  안 통하는 모양: 크기가 다르게 쪼개지는 것(`T(n) = T(n/3) + T(2n/3) + n`), 빼기로 줄어드는 것(`T(n) = T(n−1) + n`), f(n) 이 다항식 비교 구간에 안 들어가는 것(예: `f(n) = n log n` 에 대한 경계 사례).\
  행렬로 풀 다른 점화식 예: 트리보나치 `T(n) = T(n−1) + T(n−2) + T(n−3)` → 3×3 행렬 `[[1,1,1],[1,0,0],[0,1,0]]`.\
  조건은 "앞 k 항의 상수배 합" 하나 — 그러면 `k×k` 행렬의 거듭제곱으로 O(k³ log n) 이 된다.

- Q: 마스터 정리 `T(n) = a·T(n/b) + f(n)` 에서 a·b·f 는 각각 무엇이고, 왜 a 가 지수 자리에 들어가는가?\
  A: a = 부분 문제 **개수**, b = 크기가 줄어드는 **비율**, f = 쪼개고 합치는 **비용**이다.\
  재귀 트리를 그리면 층마다 노드가 a 배로 늘고, 깊이는 `log_b n` 이다 — 바닥의 노드 수가 `a^(log_b n) = n^(log_b a)` 가 된다.\
  즉 a 는 "몇 번 곱해지는가"의 밑이고 깊이가 지수이므로, 로그를 취하면 a 가 지수 자리로 올라온다.\
  그래서 a 를 1 줄이는 것(4→3, 8→7)이 상수 개선이 아니라 **차수 개선**이다.

- Q: "상수 배가 아니라 차수 차이"라는 말은 자릿수가 늘 때 배수 표에서 어떻게 보이는가?\
  A: **배수 자체가 계속 커진다**는 모양으로 보인다 — 8자리 2.37 → 16자리 3.16 → 32자리 4.21 → 64자리 5.62.\
  상수 배 차이라면 자릿수가 늘어도 배수가 어떤 값에 머문다.\
  여기서는 비가 `(4/3)^(접는 횟수)` 라 자릿수가 2배 될 때마다 4/3 배씩 벌어진다.\
  "지금 2배쯤 빠르다"가 아니라 "크기가 커질수록 격차가 무한히 벌어진다"가 차수 차이의 뜻이다.

- Q: 이 챕터의 세 가지(지수·점화식의 지수·자릿수)는 공통으로 무엇을 반으로 접는가?\
  A: **문제의 크기를 나타내는 수** 그 자체를 접는다 — 대상이 지수든, 점화식의 전진 횟수든, 자릿수든.\
  접을 수 있는 조건은 "크기 n 의 답을 크기 n/2 의 답으로 조립할 수 있는 대수 구조"다: 거듭제곱은 `a^n = (a^(n/2))²`, 행렬은 결합법칙, 곱셈은 자릿수 분해 항등식.\
  구조가 있으면 깊이가 `log n` 으로 떨어지고, 없으면 접히지 않는다.\
  그래서 새 문제를 만나면 "반으로 접을 구조가 있는가"를 먼저 묻는 것이 이 챕터의 전체 흐름 첫 단계다.

- Q: 24번의 빠른 거듭제곱과 28번 정수론의 이진 거듭제곱은 무엇이 같고 무엇이 다른가?\
  A: 같은 것: 지수를 2진수로 보고 `log n` 번의 제곱으로 끝낸다는 알고리즘 자체와 O(log n) 비용.\
  다른 것: 24번은 **재귀**(위에서 아래로 접고 되돌아오며 제곱)이고, 28번은 보통 **반복문**(아래 비트부터 밑을 제곱해 올리며 켜진 비트만 곱함)이다.\
  재귀판은 깊이만큼 호출 스택을 쓰고, 반복판은 상수 공간이다 — 대신 재귀판이 `(a^(n/2))²` 라는 식을 코드에 그대로 드러낸다.\
  실무에선 반복판을 쓰지만, 24번이 재귀로 쓰는 이유는 **깊이와 호출 수를 계측해 "두 번 부르기" 실수를 드러내기 위해서**다.

- Q: "지금 안 터진다"와 "안전하다"가 다르다는 것을 이 챕터는 어떤 두 사례로 보여주는가?\
  A: ① 행렬 곱의 `% mod` 생략 — 2×2 에 mod 10^9 이면 합이 long 안에 들어가 통과하지만, 3×3 이거나 mod 가 3×10^9 을 넘으면 넘친다.\
  ② 자리올림의 `/`·`%` — 지금은 중간항 자릿값이 항상 0 이상이라 통과하지만, 진법을 바꾸거나 뺄셈을 하나 더 넣으면 음수가 나와 조용히 틀린다.\
  둘의 공통점: 테스트가 통과하는 이유가 코드의 정확성이 아니라 **입력 범위·대수적 우연**이라는 것.\
  안전은 "지금 통과한다"가 아니라 "계약이 허용하는 입력 전체에서 성립한다"로 판정해야 한다.

- Q: 변종 검증(mutation testing)이 "테스트의 구멍"과 "불필요한 코드" 중 어느 쪽을 가리키는지 어떻게 판단하는가?\
  A: 살아남은 변종이 **어떤 입력에서 실제로 다른 결과를 내는지**를 따져 본다.\
  다르게 만드는 입력이 존재하는데 테스트에 없다면 → 테스트의 구멍(그 입력을 추가하거나, 최소한 이유를 기록).\
  계약이 허용하는 모든 입력에서 같은 결과라면 → 정말 불필요한 코드(지워도 된다).\
  이 챕터의 두 사례는 전자다 — 대수적으로 분석해 보니 "현재 전제에서만" 같았고, 전제 밖 입력에서는 갈린다.

- Q: 카라추바가 `10 × 10 = 10` 을 냈던 사건의 진짜 원인은 무엇이었고, 거기서 얻는 교훈은?\
  A: 원인은 코드가 아니라 **변종 검증이 남긴 빌드 산출물**이었다 — 소스는 복원됐는데 컴파일된 클래스가 마지막 변종 상태로 남아 있었다.\
  재컴파일하니 정상이었다.\
  교훈: **측정 도구가 무엇을 읽고 있는지도 확인해야 한다** — 이상한 결과를 보면 코드를 의심하기 전에 "내가 지금 재고 있는 것이 정말 이 코드인가"를 먼저 확인한다.\
  28번의 "측정 도구가 무엇을 읽고 있는지" 교훈과 같은 계열이고, 실무의 캐시·스테일 아티팩트·잘못된 환경 문제로 그대로 이어진다.

- Q: 02번 병합 정렬과 이 챕터는 분할 정복의 어떤 다른 면을 보여주는가?\
  A: 02번은 **데이터를 반으로 자르는** 분할 정복이고(`T(n) = 2T(n/2) + O(n)` → O(n log n)), 24번은 **크기를 나타내는 수를 반으로 접는** 분할 정복이다.\
  02번에서는 부분 문제 개수 2 가 자연스럽게 정해지지만, 24번은 그 개수 자체를 설계 변수로 다룬다(4→3).\
  또 02번은 합치는 비용 f(n) 이 병목(병합)인데, 24번의 거듭제곱은 합치는 비용이 상수라 깊이만 남는다 — 그래서 O(log n) 까지 내려간다.\
  같은 틀(마스터 정리) 안에서 a 와 f 중 무엇이 지배하느냐로 결과가 갈린다는 것을 두 챕터가 나눠 보여준다.
