## 한눈에 — 쉽게 말하면

**분할 정복 심화 = 문제를 반으로 접기. 접을 때마다 크기가 절반이 되니, 몇 번만 접으면 끝난다.**

- 종이를 반으로 접으면 두께가 두 배가 되듯, 거꾸로 큰 문제를 반으로 접으면 몇 번 만에 아주 작아진다. 10억도 30번쯤 접으면 1이 된다.
- 이 챕터의 세 가지: **지수를 접기**(빠른 거듭제곱, O(n)→O(log n)), **점화식의 지수를 접기**(행렬 거듭제곱, 표로는 못 가는 n까지), **자릿수를 접기**(카라추바 곱셈, O(n²)→O(n^1.585)).
- 접기의 성적표가 **마스터 정리**다: `T(n) = a·T(n/b) + f(n)`에서 **부분 문제 개수 a가 지수 자리에 들어간다** — 카라추바는 부분 문제를 4개에서 3개로 하나 줄여서 차수를 바꿨다.
- 실측: 지수 10억의 거듭제곱이 곱셈 **43번**으로 끝난다(한 번씩 곱하면 10억 번 — 2,325만 배).

```text
a^13 을 한 번씩 곱하면: a x a x a x ... (13 번)
반으로 접으면:  13 -> 6 -> 3 -> 1 -> 0     (깊이 4)
                a^13 = (a^6)^2 x a         홀수면 하나 더 곱함
```

## 전체 흐름

```text
문제를 받는다
  |
  v
반으로 접을 수 있는 구조를 찾는다   <- 지수? 자릿수? 구간?
  |
  v
점화식을 마스터 정리 모양으로 쓴다:  T(n) = a T(n/b) + f(n)
  |                                  a = 부분 문제 개수 (지수 자리에 들어감!)
  |                                  b = 줄어드는 비율, f = 합치는 비용
  v
a 를 줄일 수 있는지 본다            <- 카라추바: 4 -> 3, 슈트라센: 8 -> 7
  |
  v
구현 함정 확인                       <- 재귀를 두 번 부르면 로그가 사라진다
```

- *마스터 정리(master theorem)*: 위 모양의 점화식에서 전체 비용의 차수를 바로 읽어내는 공식. 예: `T(n)=4T(n/2)+O(n)` → O(n²), `T(n)=3T(n/2)+O(n)` → O(n^log₂3) = O(n^1.585).

## 동작 — 빠른 거듭제곱 (`FastPower.java`)

**언제 쓰나**: a^n mod m을 큰 n(10억, 10^18)에 대해 구할 때. 암호·해시·조합론 어디서나 나오는 기본기다.

  - *mod(나머지 연산)*: 곱할 때마다 m으로 나눈 나머지만 유지하는 것. 수가 무한히 커지는 걸 막는다.

전 상태:

```text
a^13 을 구한다. 13 = 2진수 1101
```

단계 (그림 해설: 한 단계 한 문장):

- 핵심 식: `a^n = (a^(n/2))² `, n이 홀수면 a를 한 번 더 곱한다 — `a^13 = (a^6)² × a`.
- 재귀로 지수를 반씩 줄이고, 되돌아오면서 제곱(+홀수면 한 번 더)한다.
- **재귀를 두 번 부르면 로그가 사라진다**: `pow(a, n/2) * pow(a, n/2)`라고 쓰면 같은 값을 두 번 계산해서 다시 O(n)이다. **한 번 부르고 결과를 변수에 담아** 제곱해야 한다 — 21번에서 표로 막았던 같은 실수를, 여기서는 표 없이 변수 하나로 막는다.
- 바닥 조건의 함정: 0제곱에서 `1`을 그대로 돌려주면 **mod가 1일 때** 틀린다(답은 항상 0이어야 함). `1 % mod`여야 한다.

후 상태:

```text
modPow(a, 13)
  -> modPow(a, 6)          되돌아오며:
    -> modPow(a, 3)          a^0 = 1
      -> modPow(a, 1)        a^1 = (a^0)^2 x a
        -> modPow(a, 0)      a^3 = (a^1)^2 x a
                             a^6 = (a^3)^2
                             a^13 = (a^6)^2 x a     곱셈 7 번으로 끝 (13 번 대신)
```

**비용**: 깊이 = 지수를 반으로 접는 횟수 = O(log n), 층마다 곱셈 1~2번. 실측: 지수 10억에서 43번 vs 10억 번. **호출 수가 깊이와 같다(둘 다 31)** — 재귀를 두 번 불렀다면 2^31이었을 것이다.

## 동작 — 행렬 거듭제곱 (`MatrixPower.java`)

**언제 쓰나**: 피보나치 같은 **선형 점화식**의 n번째 항을, n이 10^18처럼 표를 만들 수 없이 클 때 구한다.

  - *선형 점화식*: 다음 항이 앞 항들의 상수배 합으로 정해지는 식. `F(n) = F(n-1) + F(n-2)` 같은 것.

전 상태 — 점화식을 행렬로 쓴다:

```text
[ F(n+1) ]   [ 1 1 ]   [ F(n)   ]
[ F(n)   ] = [ 1 0 ] x [ F(n-1) ]      <- 한 번 곱하면 한 칸 전진

그러니 [[1,1],[1,0]] 의 (n-1) 제곱의 왼쪽 위 칸이 F(n) 이다.
```

단계 (그림 해설: 한 단계 한 문장):

- 행렬을 n번 곱하면 O(n) — 21번의 표 방식과 같은 차수라 이득이 없다.
- 그런데 행렬 곱은 결합법칙이 성립하므로, **빠른 거듭제곱을 행렬에 그대로 적용**해 O(log n)으로 접는다.
- 바닥 조건: 행렬의 0제곱은 **단위 행렬**(대각선 1, 나머지 0 — 숫자의 "1"에 해당). 여기서도 `1 % mod`.
- 곱한 뒤 바로 `% mod`를 취한다. **이걸 빼도 지금 테스트는 전부 통과한다**(2×2에 mod가 10^9 근처면 합이 2×10^18이라 long에 들어감) — 그런데 mod가 3×10^9을 넘거나 행렬이 3×3이 되는 순간 넘친다. **지금 안 터진다는 것과 안전하다는 것은 다르다.**

후 상태 — 실측:

```text
F(10^18) mod 10^9+7 : 깊이 61, 곱셈 808 번 (= 2x2 행렬 곱 101 번 x 8)
21 번의 표 방식이라면: 칸이 10^18 개 필요 -> 만들 수 없다
```

**비용**: O(log n)번의 행렬 곱, 행렬 곱 하나는 상수(2×2면 곱셈 8번). **상태 공간을 만들지 않고 푸는 방법이 있다** — 점화식이 선형이면 무엇이든 이렇게 된다. 피보나치만의 기법이 아니다.

## 동작 — 카라추바 곱셈 (`Karatsuba.java`)

**언제 쓰나**: 자릿수가 아주 많은 큰 수 둘을 곱할 때. **부분 문제를 하나 줄이면 차수가 바뀐다**는 것을 보여주는 예제다.

전 상태 — 반으로 자른 곱셈은 원래 4번:

```text
x = a·B + b,  y = c·B + d   (B = 10^(n/2), 윗자리/아랫자리로 자름)

x·y = ac·B² + (ad + bc)·B + bd     <- ac, ad, bc, bd : 곱셈 4 번

예: 12 x 34  ->  a=1, b=2, c=3, d=4
```

단계 (그림 해설: 한 단계 한 문장):

- 관찰: `ad + bc = (a+b)(c+d) − ac − bd`. ac와 bd는 어차피 필요하므로, **(a+b)(c+d) 하나만 더 곱하면** 가운데 항이 나온다 — 곱셈 3번.
- 세 곱을 각각 재귀로 (반 크기 문제로) 구하고, 뺄셈 두 번으로 가운데 항을 만든 뒤 자리를 맞춰 더한다.
- 예: 12×34 → ac=1×3=3, bd=2×4=8, (a+b)(c+d)=3×7=21, 가운데=21−3−8=10 → 3×100 + 10×10 + 8 = **408**. 맞다.
- 마지막에 자리올림 정리(carry): 각 자리를 0~9로 만든다. 여기서 `/`·`%` 대신 **`floorDiv`·`floorMod`**를 쓴다 — 지금은 중간항이 항상 0 이상이라(항등식을 펼치면 `Σa_p d_q + Σb_p c_q`만 남음) `/`로도 통과하지만, 진법을 바꾸거나 뺄셈을 하나 더 넣는 순간 그 항등식이 깨지고, 그때 자바의 `/`와 `%`는 음수에서 **조용히 틀린 답**을 낸다(-3/10=0, -3%10=-3 — 자릿값이 음수로 남는다).

후 상태 — 마스터 정리로 본 차이:

```text
그대로   : T(n) = 4 T(n/2) + O(n)  ->  O(n^log2 4) = O(n^2)
카라추바 : T(n) = 3 T(n/2) + O(n)  ->  O(n^log2 3) = O(n^1.585)

자릿수     카라추바    그대로     배수
   8          27         64      2.37
  16          81        256      3.16
  32         243      1,024      4.21
  64         729      4,096      5.62   <- 3^6 과 4^6. 배수가 계속 벌어진다
```

**비용**: O(n^1.585). **상수 배가 아니라 차수 차이**라 자릿수가 늘수록 배수가 계속 벌어진다. 호출 수도 트리 노드 수와 정확히 일치한다: 1,093 = (3^7−1)/2, 5,461 = (4^7−1)/3 — 가지 3개와 4개인 트리의 노드 수다.

## 곁가지 — 도구가 거짓말한 순간

측정 중 카라추바가 `10 × 10 = 10`을 낸다는 결과가 나왔다. 진짜 버그인 줄 알았는데, 원인은 **변종 검증이 남긴 빌드 산출물** — 소스는 복원됐는데 컴파일된 클래스가 마지막 변종 상태로 남아 있었다. 재컴파일하니 정상. **측정 도구가 무엇을 읽고 있는지도 확인해야 한다.**

## 핵심 문장

- 반으로 접으면 깊이가 log n이 된다 — 10억도 30여 번이면 1이 된다. 빠른 거듭제곱의 곱셈 43번이 그 숫자다.
- 마스터 정리 `T(n) = a·T(n/b) + f(n)`에서 부분 문제 개수 a가 지수 자리에 들어간다 — 카라추바는 4를 3으로 하나 줄여 O(n²)를 O(n^1.585)로 바꿨다. 상수 배가 아니라 차수 차이다.
- 재귀를 두 번 부르면 로그가 사라진다 — 한 번 부르고 변수에 담아 제곱하라. 21번의 표와 같은 역할을 변수 하나가 한다.
- 선형 점화식은 행렬 거듭제곱으로 상태 공간 없이 O(log n)에 풀린다 — 표로는 갈 수 없는 n = 10^18에 도달하는 방법이다.
- "지금 안 터진다"와 "안전하다"는 다르다 — `% mod` 생략과 `/` 나눗셈은 지금 테스트를 다 통과하지만, 전제가 조금만 바뀌면 조용히 틀린다.

## 용어 풀이

- **분할 정복(divide and conquer)**: 문제를 더 작은 같은 모양의 문제로 쪼개 풀고, 결과를 합치는 전략.
- **마스터 정리(master theorem)**: `T(n) = a·T(n/b) + f(n)` 모양 점화식의 차수를 읽는 공식. a = 부분 문제 개수, b = 줄어드는 비율, f = 합치는 비용.
- **빠른 거듭제곱(fast exponentiation)**: `a^n = (a^(n/2))²`로 지수를 반씩 접어 O(log n)에 거듭제곱하는 방법.
- **mod(나머지 연산, modular arithmetic)**: 결과를 항상 m으로 나눈 나머지로 유지하는 계산. 수가 커지는 걸 막는다.
- **단위 행렬(identity matrix)**: 대각선만 1이고 나머지가 0인 행렬. 곱셈에서 숫자 1처럼 아무것도 안 바꾼다. 행렬 0제곱의 값.
- **선형 점화식(linear recurrence)**: 다음 항이 앞 항들의 상수배 합인 식. 전부 행렬 거듭제곱으로 O(log n)에 풀 수 있다.
- **카라추바(Karatsuba)**: 반으로 자른 곱셈에서 `ad+bc = (a+b)(c+d)−ac−bd`를 이용해 곱셈 4번을 3번으로 줄이는 큰 수 곱셈.
- **자리올림(carry)**: 한 자리가 10을 넘으면 윗자리로 넘기는 정리 작업.
- **floorDiv / floorMod**: 자바에서 음수에도 "내림" 방향으로 일관된 몫/나머지를 주는 함수. `/`·`%`는 음수에서 0 쪽으로 잘라 자릿값이 음수로 남을 수 있다.
- **오버플로(overflow)**: 계산 결과가 자료형의 범위(long은 약 9.2×10^18)를 넘어 엉뚱한 값이 되는 것. `% mod`를 미루면 생긴다.
- **변종 검증(mutation testing)**: 코드를 일부러 조금 망가뜨려(변종) 테스트가 그걸 잡는지 확인하는 기법. 못 잡으면 테스트의 구멍이거나, 그 코드가 정말 불필요하다는 신호다.
- **O(log n), O(n^1.585)**: 로그는 "반으로 접는 횟수", n^1.585 = n^log₂3은 가지 3개짜리 재귀 트리의 총 일량.
