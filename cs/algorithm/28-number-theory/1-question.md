### A. 과제 (Sieve·Euclid·ModPow — TODO 1~7)

#### 1. 체와 최소 소인수 표 (`Sieve` — TODO 1~3)

```java
/**
 * TODO 1. n 이하의 소수 목록. 체를 쓴다.
 *   i*i 부터 지우는 이유. i 보다 작은 소수의 배수는 이미 지워졌다.
 *   i*2, i*3, ..., i*(i-1) 은 각각 2, 3, ..., i-1 의 배수이기도 하다.
 */
public static List<Integer> primesUpTo(int n, CountedArith arith)

/**
 * TODO 2. 각 수의 가장 작은 소인수 표.
 *   체를 지우는 대신 "누가 지웠나" 를 기록한다. 공짜로 얻는 정보다.
 *   이 표가 있으면 소인수분해가 나눗셈 없이 끝난다.
 */
public static int[] smallestPrimeFactor(int n, CountedArith arith)

/**
 * TODO 3. 최소 소인수 표로 소인수분해. 표를 타고 내려간다.
 *   x 를 자기 최소 소인수로 나누면 더 작아진다. 최소 소인수는 2 이상이므로
 *   적어도 절반이 된다. 그래서 반복이 log2(x) 를 안 넘는다.
 */
public static List<Integer> factorize(int x, int[] spf, CountedArith arith)
```

- 시행 나눗셈과 체는 질문의 방향이 어떻게 반대인가?
- 체가 나눗셈을 한 번도 안 쓴다는 것은 무슨 뜻인가?
- 체에서 지우기를 `i*2` 가 아니라 `i*i` 부터 시작해도 되는 이유는? (원본 함정)
- `i*i` 를 `(long) i * i` 로 올려야 하는 이유는? (원본 함정)
- 최소 소인수 표는 왜 `i*i` 가 아니라 `i` 부터 돌아야 하는가? (원본 함정)
- 최소 소인수 표에서 이미 채워진 칸을 덮어쓰면 어떤 수에서 무엇이 틀리는가?
- 표를 타는 소인수분해의 반복 횟수가 log2(x) 를 안 넘는 이유는?
- 소수(예: 999,983)가 시행 나눗셈 소인수분해의 최악인 이유는?
- "쓰기 수" 로는 최소 소인수 표가 체보다 싸 보이는데 "순회 수" 로는 비싼 이유는? (원본 측정 둘)

#### 2. 유클리드 호제법과 역원 (`Euclid` — TODO 4~6)

```java
/** TODO 4. 최대공약수. 항상 0 이상을 준다. */
public static long gcd(long a, long b, CountedArith arith)

/**
 * TODO 5. 확장 유클리드. gcd(a,b) 와 함께 a*x + b*y = gcd 를 만족하는 x, y 를 준다.
 *   재귀로 보면: gcd(b, a mod b) 에서 b*x1 + (a mod b)*y1 = g 를 얻었다면
 *   a mod b = a - (a/b)*b 이므로  x = y1, y = x1 - (a/b)*y1.
 */
public static long[] extendedGcd(long a, long b, CountedArith arith)

/**
 * TODO 6. 법 m 에서 a 의 역원. a*x = 1 (mod m) 인 x.
 *   gcd(a, m) 이 1 이 아니면 역원이 없다. 그때는 -1 을 준다.
 *   확장 유클리드의 x 가 음수일 수 있으므로 m 을 더해 범위로 넣는다.
 */
public static long modInverse(long a, long m, CountedArith arith)
```

- `gcd(a, b) = gcd(b, a mod b)` 가 반드시 끝나는 이유는?
- 반복 횟수가 log 인 이유(두 번 돌면 절반 아래)는 어떻게 성립하는가?
- 유클리드의 최악 입력이 피보나치 수 쌍인 이유는? (원본 측정 넷)
- 1 억짜리 수의 최악이 38 회라는 것이 시사하는 바는?
- `gcd(0, 0)` 과 음수 입력은 각각 어떻게 정해두는가? (원본 함정)
- 확장 유클리드의 x, y 가 "하나가 아니다" 는 것은 테스트를 어떻게 바꾸는가? (원본 함정)
- 역원이 존재하는 조건은 무엇이고, 없을 때 impl 은 무엇을 주는가?
- 확장 유클리드가 준 x 를 왜 `Math.floorMod(x, m)` 으로 접어야 하는가?

#### 3. 이진 거듭제곱 (`ModPow.power` — TODO 7)

```java
/**
 * TODO 7. a^e mod m. 이진 거듭제곱.
 *   a^13 = a^8 * a^4 * a^1        13 = 1101(2)
 *   지수를 이진수로 보면 곱셈이 지수의 비트 수만큼으로 준다.
 *   a 를 제곱해 나가면서 비트가 켜진 자리만 곱한다.
 *
 *   함정. a*a 가 long 을 넘을 수 있다. m 이 10 억 근처면 곱이 10^18 이라 아슬아슬하다.
 *   m 을 넘는 a 는 먼저 줄여둬야 한다.
 */
public static long power(long a, long e, long m, CountedArith arith)
```

- 지수를 이진수로 보면 곱셈이 왜 비트 수만큼으로 주는가?

- 오버플로가 예외 없이 "조용히 엉뚱한 값" 이 된다는 것이 왜 더 위험한가?
- `m == 1` 을 따로 처리하는 이유는?
- 24 번 분할 정복의 거듭제곱과 무엇이 같고 무엇이 다른가?
- 역원 두 방법(확장 유클리드 vs 페르마)의 비용과 조건 차이는? (원본 측정 여섯)
