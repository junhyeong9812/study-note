### A. 과제 (Subsets·TravellingSalesman — TODO 1~4)

#### 1. 켜진 비트 골라내기 (`enumerate`, `setBits` — TODO 1~2)

**impl 정답 코드**

```java
public static List<Integer> enumerate(int n, CountedBits bits) {
    List<Integer> all = new ArrayList<>();
    for (int mask = 0; mask < (1 << n); mask++) {
        bits.bitOp();
        all.add(mask);
    }
    return all;
}

public static List<Integer> setBits(int x, CountedBits bits) {
    List<Integer> positions = new ArrayList<>();
    while (x != 0) {
        bits.bitOp();
        int lowest = x & -x;
        positions.add(Integer.numberOfTrailingZeros(lowest));
        x &= x - 1;
    }
    return positions;
}
```

```
x = 1 0 1 1 0 0
x-1 = 1 0 1 0 1 1     1 을 빼면: 가장 낮은 1 이 0 이 되고, 그 아래가 전부 1
x&(x-1) = 1 0 1 0 0 0  -> 가장 낮은 1 만 꺼졌다

-x  = ~x + 1 (2의 보수)
x&-x = 0 0 0 1 0 0    -> 가장 낮은 1 만 남았다
```

- Q: 집합 = 정수가 왜 "배열 인덱스가 된다" 로 이어지는가?
  A: 원소 n 개의 부분집합 하나가 0 ~ 2^n - 1 의 정수 하나에 정확히 대응하기 때문이다.
  정수가 됐으니 `dp[mask]` 처럼 **집합마다 칸 하나**를 가진 배열을 만들 수 있다.
  "집합을 상태 이름으로 쓰는 DP" 가 가능해지는 것 — 그게 비트마스크 DP 의 전부다(원본 README).

- Q: `x & (x-1)` 이 가장 낮은 1 을 끄는 원리는?
  A: 1 을 빼면 가장 낮은 1 이 0 이 되고 그 아래 0 들이 전부 1 로 뒤집힌다(빌림).
  원래 x 와 AND 하면 — 뒤집힌 아래쪽은 원래 0 이라 0, 가장 낮은 1 자리는 0 이 됐고, 그 위는 둘 다 그대로다.
  결과: 가장 낮은 1 하나만 꺼진다.

- Q: `x & -x` 는 무엇을 남기고, 위치는 무엇으로 얻는가?
  A: 가장 낮은 1 **하나만** 남긴다 — `-x = ~x + 1` (2의 보수)이라 가장 낮은 1 아래·위가 전부 어긋나고 그 자리만 겹친다.
  위치는 `Integer.numberOfTrailingZeros(lowest)` — 아래쪽 0 의 개수가 곧 비트 위치다.
  impl 이 이 두 트릭을 함께 쓴다: `x & -x` 로 뽑고, `x &= x - 1` 로 끈다.

- Q: `x & (x-1)` 순회는 몇 번 돌고, 32 번 훑기와 언제 같아지는가?
  A: **켜진 비트 개수만큼만** 돈다 — 한 바퀴에 하나씩 끄니까.
  실측: 1,000 개 수에서 켜진 비트 1/4/16/32 개일 때 1,000/4,000/16,000/32,000 번, 훑기는 언제나 32,000 번.
  32 개 전부 켜진 꽉 찬 경우에 반복 횟수가 같아진다 — 희소할수록 이긴다.

- Q: "지지 않는다" 는 결론에 붙은 단서는?
  A: **이 계측기는 반복 횟수만 센다**는 것이다.
  한 바퀴 안에서 트릭 쪽이 하는 일(빼기·AND·자리 계산)이 더 많으므로, 꽉 찬 경우의 "동률" 은 실제로는 트릭이 지는 쪽에 가깝다.
  28 번의 함정(측정 도구가 무엇을 읽는지 확인하라)이 여기에도 있다 — 원본이 직접 이 단서를 단다.

- Q: `(x & (1 << i)) > 0` 이 `i=31` 에서 틀리는 이유는?
  A: `1 << 31` 은 int 의 부호 비트라 **음수**(Integer.MIN_VALUE)이기 때문이다.
  31번 비트가 켜져 있으면 `x & (1 << 31)` 의 결과도 그 음수 — `> 0` 은 거짓이 되어 "켜져 있는데 꺼졌다" 고 판정한다.
  `!= 0` 으로 써야 부호와 무관하게 맞다(대조 구현 setBitsByScan 도 `!= 0` 이다).

- Q: `1 << 40` 이 `1 << 8` 이 되는 이유는?
  A: 자바가 int 시프트 거리를 **32 로 나눈 나머지**만 쓰기 때문이다 — 40 mod 32 = 8.
  에러도 경고도 없이 조용히 엉뚱한 마스크가 된다.
  64 비트 마스크가 필요하면 `1L << i` — 피연산자를 long 으로 만들어야 거리도 64 기준이 된다.

#### 2. mask 의 부분집합만 돌기 (`subsetsOf` — TODO 3)

**impl 정답 코드**

```java
public static List<Integer> subsetsOf(int mask, CountedBits bits) {
    List<Integer> subsets = new ArrayList<>();
    int sub = mask;
    while (true) {
        bits.bitOp();
        subsets.add(sub);
        if (sub == 0) {
            break;
        }
        sub = (sub - 1) & mask;
    }
    return subsets;
}
```

```
mask = 1 0 1 1 (= 11) 의 부분집합 순회:

  1011 -> 1010 -> 1001 -> 1000 -> 0011 -> 0010 -> 0001 -> 0000 -> (멈춤)
  11      10      9       8       3       2       1       0

  sub - 1 : mask 무시하고 그냥 1 작은 수 (아래가 1 로 채워짐)
  & mask  : mask 밖 자리를 도로 끔 -> "mask 안에서" 다음으로 작은 수
```

- Q: `(sub - 1) & mask` 의 원리는?
  A: `sub - 1` 은 가장 낮은 1 을 끄고 그 아래를 전부 1 로 채운다 — 수로는 바로 1 작은 값이다.
  거기에 `& mask` 를 씌우면 mask 밖 자리가 도로 꺼진다.
  둘을 합치면 "mask 의 부분집합이면서 sub 보다 작은 것 중 **가장 큰 것**" — mask 안에서 내림차순으로 하나도 빠짐없이 도는 이유다.

- Q: `sub = 0` 에서 계속 돌리면?
  A: `0 - 1 = -1` 은 모든 비트가 1 이라 `-1 & mask = mask` — **처음으로 되돌아가** 무한 루프가 된다(원본 함정).
  빈 집합 다음이 다시 전체 집합인 순환 구조인 것이다.
  그래서 0 을 어떻게 다루느냐가 이 루프의 핵심 경계다.

- Q: 빈 집합도 담고 무한 루프도 피하는 루프 구조는?
  A: impl 은 `while (true)` 로 돌며 **먼저 담고**, `sub == 0` 이면 break, 아니면 갱신한다.
  "0 을 처리하고 나서 끊는다" — 담기 전에 끊으면 빈 집합이 빠지고, 갱신 후 조건 검사만 하면 무한 루프다.
  do-while 로 써도 같다. 요점은 종료 검사가 담기와 갱신 **사이**에 있어야 한다는 것.

- Q: 총 횟수가 4^n 이 아니라 3^n 인 이유는?
  A: 원소 하나마다 세 가지 경우뿐이기 때문이다 — `mask 밖` / `mask 안이고 sub 밖` / `mask 안이고 sub 안`.
  (mask, sub) 쌍의 개수 = 원소마다 3택 = 3^n.
  거르기 판은 mask 마다 2^n 을 다 보므로 2^n × 2^n = 4^n 이다.

- Q: 차수 트릭인가 상수 트릭인가?
  A: **차수를 바꾸는 트릭**이다 — 밑이 4 에서 3 으로 바뀐다.
  실측: n=10 에서 17 배, n=15 에서 74 배 — n 이 클수록 격차가 벌어지는 것이 차수 변화의 증거다.
  `x & (x-1)`(상수·반복 횟수 트릭)과 구별하는 것이 이 챕터의 주제다.

- Q: n=15 의 74 배는 어디서 오는가?
  A: 정확히 3^15 = 14,348,907 대 4^15 = 1,073,741,824 다.
  거르기 판은 mask 의 부분집합이 아닌 수까지 전부 보고 버린다 — 그 헛걸음이 (4/3)^n 으로 쌓인다.
  같은 답을 내는 두 코드의 차이가 "무엇을 아예 안 보느냐" 에서 온다.

#### 3. 비트마스크 DP — 외판원 (`shortestTour` — TODO 4)

**impl 정답 코드**

```java
public static int shortestTour(int[][] dist, CountedBits bits) {
    int n = dist.length;
    if (n <= 1) {
        return 0;
    }
    int full = 1 << n;
    int[][] dp = new int[full][n];
    for (int[] row : dp) {
        Arrays.fill(row, INF);
    }
    dp[1][0] = 0;

    for (int mask = 1; mask < full; mask++) {
        if ((mask & 1) == 0) {
            continue;
        }
        for (int at = 0; at < n; at++) {
            bits.bitOp();
            if (dp[mask][at] == INF || (mask & (1 << at)) == 0) {
                continue;
            }
            bits.visitState();
            for (int next = 0; next < n; next++) {
                if ((mask & (1 << next)) != 0) {
                    continue;
                }
                bits.transition();
                int cost = dp[mask][at] + dist[at][next];
                int nextMask = mask | (1 << next);
                if (cost < dp[nextMask][next]) {
                    dp[nextMask][next] = cost;
                }
            }
        }
    }

    int best = INF;
    for (int at = 1; at < n; at++) {
        if (dp[full - 1][at] < INF) {
            best = Math.min(best, dp[full - 1][at] + dist[at][0]);
        }
    }
    return best == INF ? -1 : best;
}
```

- Q: 상태를 (방문한 집합, 지금 있는 도시) 로 잡는 근거는?
  A: 남은 일이 그 둘에만 의존하기 때문이다.
  순열 `abc` 와 `acb` 는 다르지만 "{a,b,c} 를 다 보고 c 에 있다" 로 끝나면 **그 뒤는 완전히 같다** — 그래서 하나로 합친다.
  "방문 순서" 는 버리고 "방문 여부 + 현재 위치" 만 남긴 것이 상태 압축이다.

- Q: 왜 `dp[1][0] = 0` 에서 시작하는가?
  A: mask 1 = `{0}` — **출발 도시 0 이 이미 방문 집합에 들어 있어야** 하기 때문이다(원본 함정).
  "0 에서 출발했고 아직 0 에 있다, 비용 0" 이 유일한 참 시작 상태다.
  `dp[0][0] = 0` 으로 시작하면 "0 을 안 방문했는데 0 에 있다" 는 모순 상태에서 출발하게 된다.

- Q: 전이는 무엇을 하는가?
  A: 지금 상태 (mask, at)에서 아직 안 간 도시 next 로 한 발 가는 것이다.
  `cost = dp[mask][at] + dist[at][next]`, `nextMask = mask | (1 << next)` — next 를 집합에 넣으며 `dp[nextMask][next]` 를 min 으로 갱신한다.
  답은 마지막에 `dp[full-1][at] + dist[at][0]` (모든 도시 방문 후 0 으로 귀환)의 최솟값이다.

- Q: 순열을 상태로 접는 것은 21 번의 무엇과 같은가?
  A: **겹치는 부분 문제**를 찾아 하나로 합치는 판단 그대로다(원본 README).
  (n-1)! 개 순열이 2^n × n 개 상태로 접힌다 — n=10 실측: 상태 157 배, 전이 314 배.
  다른 점은 부분 문제의 "이름" 이 집합이라 배열 인덱스로 만들 도구(비트)가 필요했다는 것뿐이다.

- Q: n=25 면 DP 도 안 되는 이유는?
  A: 차수를 **낮춘 것이지 없앤 것이 아니기** 때문이다 — 2^n × n 은 여전히 지수다.
  실측 성장: DP 는 n 이 2 늘 때 대략 4.9 배, 순열은 n-1 배씩 — 격차는 폭발하지만(n=12 에서 3,543 배) DP 도 2^25 × 25 = 약 8 억 상태다.
  "이 도구는 어디까지 통하는가" 를 차수가 알려준다.

- Q: 0 번 없는 mask 를 통째로 건너뛰는 이유는?
  A: 출발 도시 0 은 항상 방문 집합에 있어야 하므로(`dp[1][0]` 에서 시작), 0 이 없는 mask 의 칸은 전부 INF 로 남는다 — 볼 이유가 없다.
  impl 의 `if ((mask & 1) == 0) continue;` 가 그것이고, 이 덕에 훑은 칸이 상한의 절반(49,152 → 24,576)이 된다.

- Q: 상한·훑은 칸·연 상태가 셋 다 다르다는 것의 경고는?
  A: n=12 실측 — 상한 2^n × n = 49,152, 실제 훑은 칸 24,576, 실제로 연(INF 아닌) 상태 11,265.
  **상한을 그대로 비용으로 쓰면 4 배 넘게 과대평가한다**(원본).
  복잡도 식은 울타리일 뿐, 실비용은 구조(여기서는 "0 포함" 제약)가 깎는다 — 예산 산정은 측정으로.

- Q: "INF 가 아니면 at 은 mask 안에 있다" 는 불변식은 어디서 보장되는가?
  A: 값이 쓰이는 곳이 두 군데뿐이기 때문이다 — 시작 `dp[1][0]`(0 ∈ {0})과, 전이 `dp[nextMask][next]`(nextMask 에 next 를 **넣으면서** 쓴다).
  둘 다 "쓰는 순간 at ∈ mask" 를 만족하므로 귀납적으로 항상 성립한다.
  그래서 `(mask & (1 << at)) == 0` 확인은 INF 확인과 겹치고, 마지막 루프의 at 범위를 0 부터 돌려도 `dp[full-1][0]` 이 INF 라 답이 안 바뀐다 — 살아남은 두 변종이 결함이 아닌 이유다.

- Q: 겹치는 확인 줄을 일부러 남겨둔 이유는?
  A: **불변식을 코드에 적어두기 위해서다**(원본 변종 검증).
  없어도 돌지만, 읽는 사람에게 "여기서 이것이 참이어야 한다" 를 문서 대신 코드로 말한다.
  불변식을 실제로 깨는 변종(전이에서 next 를 mask 에 안 넣고 쓰기)은 7 개 테스트가 잡는다 — 남긴 줄은 방어가 아니라 표명이다.

### B. 개념

#### 4. 생각해볼 것 (원본 README 이관)

- Q: 부분집합을 크기(원소 수) 순서로 돌려면?
  A: `(sub - 1) & mask` 는 **수의 내림차순**이지 원소 수 순서가 아니다 — 1000(원소 1개)이 0111(원소 3개)보다 먼저 나온다.
  (원본에 근거 없음 — 내 추론) 방법: ① 부분집합을 전부 만들어 `Integer.bitCount` 로 묶거나 정렬한다 — 간단하지만 저장이 든다. ② "켜진 비트 개수가 같은 다음 수" 를 주는 비트 트릭(아래 세 번째 질문의 Gosper's hack)으로 개수 k 를 1 부터 올려가며 돈다.
  DP 를 "작은 집합부터" 채워야 할 때 실제로 필요해지는 순회다.

- Q: 외판원 DP 메모리, n=20 이면 몇 MB 이고 줄일 수 있나?
  A: `int[2^20][20]` = 2^20 × 20 × 4 바이트 = **80MB** 다.
  (원본에 근거 없음 — 내 추론) 줄이기: 전이가 항상 "원소 수 k 인 mask → k+1 인 mask" 로만 가므로, 원소 수 층별로 돌며 두 층만 들고 있으면 된다 — 최대 층 C(20,10) × 20 × 4 × 2층 ≈ 30MB 수준으로 준다. 대신 mask 를 층 안 인덱스로 바꾸는 환산이 붙는다.
  값 범위가 작으면 int 대신 short 로 반을 줄이는 손쉬운 방법도 있다. 어느 쪽도 지수 자체는 못 없앤다.

- Q: 켜진 비트 개수가 같은 마스크만 돌려면?
  A: (원본에 근거 없음 — 내 추론) "같은 개수의 1 을 가진 다음 수" 를 O(1) 비트 연산으로 주는 **Gosper's hack** 이 표준 도구다:
  `c = x & -x; r = x + c; next = (((r ^ x) >> 2) / c) | r` — 가장 낮은 1 덩어리를 한 칸 올리고 남은 1 들을 바닥으로 내리는 조작이다.
  이 챕터의 `x & -x`(가장 낮은 1 뽑기)가 그 부품으로 들어간다. 간단하게는 전 범위를 돌며 `bitCount(mask) == k` 로 걸러도 되지만 그건 4^n 거르기와 같은 종류의 헛걸음이다.

#### 5. 파생 — 왜 그렇게 생겼는가

- Q: "짧은 것과 적게 하는 것은 다르다" 를 두 측정으로?
  A: `sub = (sub-1) & mask` 한 줄은 4^n 을 3^n 으로 — **차수**를 바꿔 n=15 에서 74 배를 만든다.
  `x & (x-1)` 한 줄은 반복 횟수만 줄이고, 꽉 찬 입력에선 사실상 지기도 한다 — **상수** 트릭이다.
  둘 다 한 줄로 짧다. 짧음은 비용의 증거가 아니다 — 세어 봐야 안다.

- Q: 3^n 의 "원소마다 세 가지 경우" 는?
  A: `mask 밖` / `mask 안이고 sub 밖` / `mask 안이고 sub 안`.
  (mask, sub) 쌍 하나가 원소별 3택 하나와 1:1 이라 총 3^n 이다.
  실측이 정확히 3^n(14,348,907)과 4^n 으로 떨어진 이유다.

- Q: 차수를 낮춤 vs 없앰의 구분이 왜 중요한가?
  A: 도구의 **적용 한계**를 정하기 때문이다.
  비트마스크 DP 는 (n-1)! 을 2^n × n 으로 낮췄지만 여전히 지수라 n=25 면 안 된다.
  "몇 배 빨라졌다" 만 보면 만능처럼 보이고, 차수를 보면 어디서 멈추는지 보인다.

- Q: 반복 횟수만 세는 계측기의 왜곡은 28 번의 어떤 교훈과 같은가?
  A: "측정 도구가 무엇을 읽고 있는지도 확인해야 한다" — 28 번에서 쓰기 수와 순회 수가 결론을 뒤집은 그 교훈이다.
  여기서는 `x & (x-1)` 의 "동률" 이 실제로는 패배인 것을 반복 카운터가 가린다.
  측정값을 읽기 전에 카운터의 정의부터 읽어야 한다.

- Q: 권한 플래그·요일 저장과 이 챕터의 트릭은 어디서 갈라지는가?
  A: 실무 플래그는 **표현**만 쓴다 — 집합 하나를 정수로 담고 `|`, `&` 로 켜고 끄고 검사하는 O(1) 편의다.
  이 챕터의 핵심은 그 표현을 **알고리즘의 상태 공간**으로 쓰는 것이다 — 부분집합 순회의 차수, DP 의 배열 인덱스.
  같은 비트인데 한쪽은 저장 형식이고 한쪽은 복잡도를 정하는 설계다.

- Q: 살아남은 변종이 결함이 아니라고 판정한 근거는?
  A: **불변식**이다 — "dp[mask][at] 이 INF 가 아니면 at 은 mask 안에 있다".
  변종이 지운 줄이 이 불변식 덕에 의미상 중복임을 보였고(멤버십 확인 ⊂ INF 확인, 마지막 at=0 무해), 불변식을 실제로 깨는 변종은 테스트가 잡음을 확인했다.
  "테스트가 안 잡았다" 가 아니라 "왜 안 잡히는지 설명이 된다" 가 판정 기준이다 — 27 번의 `hi = n` 변종과 같은 결론 구조다.
