#### 1. `BellmanFord.distances` (TODO 1~4)

정답 구현 (impl):

```java
static final long INF = Long.MAX_VALUE / 4;   // MAX_VALUE 를 쓰면 더할 때 넘친다

public static long[] distances(CountedGraph g, int start, int[] rounds) {
    long[] dist = new long[n];
    Arrays.fill(dist, INF);
    dist[start] = 0;

    for (int round = 0; round < n - 1; round++) {   // TODO 1: V-1 라운드
        boolean changed = relaxAll(g, dist);
        rounds[0] = round + 1;
        if (!changed) {                             // TODO 3: 조기 종료
            break;
        }
    }

    // TODO 4: 한 번 더 돌아서 아직도 줄어들면 음수 사이클이다.
    if (relaxAll(g, dist)) {
        throw new NegativeCycleException("음수 사이클이 있어 최단 거리가 정의되지 않는다");
    }

    for (int i = 0; i < n; i++) out[i] = dist[i] >= INF ? UNREACHABLE : dist[i];
    return out;
}

private static boolean relaxAll(CountedGraph g, long[] dist) {   // TODO 2: 한 라운드
    boolean changed = false;
    for (int i = 0; i < g.edgeCount(); i++) {
        CountedGraph.Edge e = g.edge(i);
        // 아직 안 닿은 정점에서 완화를 시도하면 안 된다.
        // INF 에 음수 가중치를 더하면 INF 보다 작아져서 없는 길이 생긴다.
        if (dist[e.from()] >= INF) continue;
        long candidate = dist[e.from()] + e.weight();
        if (candidate < dist[e.to()]) {
            dist[e.to()] = candidate;
            g.countRelaxation();
            changed = true;
        }
    }
    return changed;
}
```

- 논리: 확정 순서를 포기하고 "모든 간선을 반복해서 훑는다"로 바꿨다 — 순서가 없으니 음수 간선이 나중에 값을 되돌려도 괜찮다.

> **완화(relaxation)** — `dist[u] + w < dist[v]`면 거리를 고쳐 쓰는 것. 세 알고리즘의 공용 부품.\
> 예: 5까지 12로 알고 있다가 `4->5(-1)` 로 7-1=6이 보이면 12를 6으로 고친다.

> **라운드(round)** — 벨만 포드에서 "모든 간선을 한 바퀴 훑기".\
> 예: 라운드 1에서 여섯 간선을 넣은 순서대로 다 훑고, 라운드 2에서 아무것도 안 줄어 끝난다.

- 논리: V-1 라운드면 충분한 이유는 최단 경로가 간선을 V-1개보다 많이 쓸 수 없기 때문이다.
- 비용: O(VE) — 라운드 최대 V-1 × 라운드마다 간선 E개.\
  조기 종료 덕에 보통은 훨씬 일찍 끝난다.

> **조기 종료(early termination)** — 변화 없는 라운드에서 멈추는 것. 벨만 포드엔 있고 플로이드엔 없다.\
> 예: 예시 그래프는 라운드 2에서 아무것도 안 줄어 `rounds = 2` 로 멈춘다.

- 한계: 간선을 읽는 순서에 따라 라운드 수가 33배까지 달라진다 — 표기에는 안 보이는 차이다.

**질문별 답**

- Q: 최단 경로가 쓸 수 있는 간선의 최대 개수가 V-1개인 이유는 무엇인가?\
  A: 간선을 V-1개 쓰면 정점을 V개 지나는데, 그래프에 정점이 V개뿐이다.\
  그보다 많이 쓰면 어떤 정점을 두 번 지나게 되고, 그건 사이클을 도는 것이다.\
  그래서 최단 경로에 쓰이는 간선은 최대 V-1개이고, 라운드도 V-1번이면 충분하다.

- Q: 음수 사이클이 없다면 사이클을 도는 것이 이득인 경우가 있는가?\
  A: 없다.\
  사이클의 총 가중치가 0 이상이므로, 한 바퀴 돌면 거리가 같거나 늘어난다.\
  그러니 사이클을 잘라낸 경로가 항상 그만큼 짧거나 같다.\
  음수 사이클이 있으면 이 논증이 뒤집히고, 그때는 "최단"이 존재하지 않는다.

> **음수 사이클(negative cycle)** — 한 바퀴 돌면 총비용이 음수인 회로. 돌수록 싸져서 최단 거리가 정의되지 않는다.\
> 예: 무방향 그래프에 -3짜리 간선 하나만 있어도 a→b→a 왕복이 -6이 되어 무한히 줄어든다.

- Q: "한 라운드마다 무엇이 확정되는가"를 한 문장으로 말하면?\
  A: 간선을 **한 개 더 쓰는 경로까지**의 최단 거리가 확정된다.\
  라운드 1이 끝나면 간선 1개짜리 경로가, 라운드 2가 끝나면 2개짜리까지가 반영돼 있다(간선을 읽는 순서에 따라 더 빨리 갈 수도 있다).\
  경로 길이가 최대 V-1이므로 V-1 라운드면 전부 덮인다.

- Q: 무한대를 `Long.MAX_VALUE`로 두면 안 되는 이유는 무엇인가?\
  A: 거기에 음수 가중치를 더하면 `MAX + (-1) = MAX - 1`이 되어 **INF보다 작아진다**.\
  그러면 "못 가는 정점에서 출발하는 없는 길"이 실제 경로보다 짧게 보이고, 그 값이 퍼져 나간다.\
  14번에서는 양수만 있어 넘침(MAX+1이 음수)이 문제였다면, 여기서는 넘치지 않고도 값이 줄어드는 것이 문제다.

> **INF(무한대 대용값)** — "아직 못 감"의 표시. `Long.MAX_VALUE / 4` — 가중치를 더해도 넘치지 않는 크기로.\
> 예: `Arrays.fill(dist, INF)` 로 깔고, 끝까지 `dist[i] >= INF` 인 칸만 UNREACHABLE로 바꾼다.

> **오버플로(overflow)** — 표현 범위를 넘어 값이 엉키는 것.\
> 예: 14번은 `MAX+1`이 음수가 되는 것이 함정이었고, 여기서는 `MAX + (-1) = MAX - 1`로 없는 길이 생기는 것이 함정이다.

- Q: 원본은 그 함정을 **두 가지 방법으로 동시에** 막는데, 둘은 각각 무엇이고 왜 둘 다 하는가?\
  A: (ㄱ) `INF = Long.MAX_VALUE / 4`로 잡아 가중치를 몇 번 더해도 넘치지 않게 하고, (ㄴ) `dist[e.from()] >= INF`면 완화를 아예 건너뛴다.\
  둘 중 하나만 있어도 정상 동작하지만, README가 "둘 다 하면 실수가 겹쳐도 안 터진다"고 말한다.\
  값의 여유(ㄱ)는 계산 사고를 흡수하고, 가드(ㄴ)는 의미 자체를 막는다 — 서로 다른 층의 방어다.

- Q: 닿을 수 없는 곳에 있는 음수 사이클은 왜 무시해야 하고, 코드의 어느 한 줄이 그것을 저절로 처리하는가?\
  A: 시작점에서 못 가는 사이클은 그 시작점의 최단 거리에 아무 영향이 없으므로, 그것 때문에 예외를 던지면 답이 있는 질문을 거부하는 셈이 된다.\
  `if (dist[e.from()] >= INF) continue;` 한 줄이 처리한다 — 안 닿은 정점에서는 완화를 안 하니 그 사이클은 영영 값을 못 줄이고, 따라서 검사 라운드에서도 안 걸린다.\
  테스트 `ignoresUnreachableNegativeCycle`이 이것을 못박는다.

- Q: 조기 종료의 조건은 무엇이고, 그것이 성립하면 왜 남은 라운드가 전부 무의미한가?\
  A: 한 라운드 동안 **완화가 한 번도 안 일어났을 때**(`changed == false`)다.\
  다음 라운드는 같은 `dist` 배열에 같은 간선들을 같은 순서로 적용하는 것이므로 결과가 똑같다 — 한 번 변화가 없으면 영원히 없다.\
  측정: 좋은 순서에서는 정점 100개 그래프가 99라운드가 아니라 2라운드에 끝난다.

- Q: 음수 사이클 검출은 어떻게 하고, 왜 그때 "최단 거리"가 정의되지 않는가?\
  A: V-1 라운드를 마친 뒤 **한 라운드 더 돌려서** 여전히 줄어들면 음수 사이클이다 — 정상 그래프라면 V-1 라운드로 끝났어야 하니까.\
  음수 사이클이 있으면 그 회로를 돌 때마다 거리가 계속 줄어 하한이 없다 — 즉 "가장 짧은 거리"라는 값이 존재하지 않는다.\
  그래서 틀린 숫자를 돌려주는 대신 `NegativeCycleException`을 던진다.

- Q: 무방향 그래프에 음수 간선을 넣으면 왜 그 자체가 음수 사이클인가?\
  A: 무방향 간선은 양쪽 방향 간선 두 개다(`CountedGraph.addEdge`가 실제로 둘을 넣는다).\
  가중치 -3인 간선이면 a→b→a를 왕복해 -6이 되고, 계속 왕복하면 무한히 줄어든다.\
  그래서 이 박스의 예제는 방향 그래프이고, 테스트 `undirectedNegativeEdgeIsACycle`이 예외가 나는 것을 확인한다.

- Q: 정점 100개 직선 그래프에서 간선 순서만 뒤집으면 라운드 수와 간선 조회는 각각 얼마가 되는가(측정치)?\
  A: 앞에서 뒤로 넣으면 **라운드 2·조회 297**, 뒤에서 앞으로 넣으면 **라운드 99·조회 9,900**이다.\
  라운드는 49배, 조회는 33배 차이다(조회 297은 라운드 2 + 확인 1 = 3회 × 간선 99개).\
  그래프도 답도 알고리즘도 완전히 같고, 다른 것은 간선 목록의 순서뿐이다.

- Q: 그런데 완화 횟수는 둘 다 99로 같다 — 33배 차이의 정체는 무엇인가?\
  A: **간선을 보고도 아무 일도 안 하는 것**, 즉 헛도는 조회다.\
  실제로 한 일(거리를 줄인 횟수)은 99로 완전히 같은데, 나쁜 순서에서는 그 99번을 하려고 9,900번을 본다.\
  "얼마나 일했나"와 "얼마나 들여다봤나"가 다른 값이라는 것을 계측이 분리해 보여준다.

> **계측(instrumentation)** — 답에는 안 나타나는 비용을 따로 세어 밖으로 내보내는 장치. 여기서는 `countRelaxation()`·`rounds`.\
> 예: 완화 99번은 두 순서가 같지만 조회 297 대 9,900은 세어야만 보인다.

- Q: `O(VE)`라는 표기가 그 차이를 못 보여주는 이유는 무엇인가?\
  A: 표기는 최악의 상한이라 "라운드가 최대 V-1번"만 말하고, 실제로 몇 라운드에 끝나는지는 입력 순서가 정하기 때문이다.\
  두 실험은 V도 E도 같아서 표기상으로는 완전히 같은 비용이다.\
  같은 표기 안에서 33배가 나는 것이 이 박스의 요점 — 표기는 상한이지 예측이 아니다.

- Q: `rounds`를 배열(길이 1)로 받는 이유는 무엇인가?\
  A: 자바는 값 전달이라 `int`로 받으면 함수 안의 값이 호출자에게 안 돌아가고, 반환값은 이미 거리 배열이 차지하고 있어서다.\
  길이 1짜리 배열이 "밖으로 값을 내보내는 가장 싼 그릇"이다.\
  14번의 `scans`, 이 챕터의 `rounds`가 같은 수법이다.

> **간선 목록(edge list)** — 간선을 (from, to, weight)의 나열로 저장. 벨만 포드는 이걸 통째로 반복해 훑는다.\
> 예: 같은 그래프라도 `0->1, 0->2, ...` 순서로 넣느냐 `4->5, 3->5, ...` 순서로 넣느냐가 라운드 수를 바꾼다.

public static long[][] allPairs(CountedGraph g) {
    int n = g.vertices();
    long[][] d = g.toMatrix(INF);        // TODO 5: d[v][v] = 0, 중복 간선은 가장 작은 것만

    for (int k = 0; k < n; k++) {        // TODO 6: k 가 가장 바깥이어야 한다
        for (int i = 0; i < n; i++) {
            // i 에서 k 로 못 가면 k 를 거치는 길이 없다. 안쪽 루프를 통째로 건너뛴다.
            if (d[i][k] >= INF) continue;
            for (int j = 0; j < n; j++) {
                if (d[k][j] >= INF) continue;
                long candidate = d[i][k] + d[k][j];
                if (candidate < d[i][j]) {
                    d[i][j] = candidate;
                    g.countRelaxation();
                }
            }
        }
    }

    for (int v = 0; v < n; v++) {        // TODO 7: 대각선이 음수면 음수 사이클
        if (d[v][v] < 0) {
            throw new NegativeCycleException("정점 " + v + " 를 지나는 음수 사이클이 있다");
        }
    }
    // ... INF -> UNREACHABLE
}

- 논리: "경유해도 되는 정점 집합"을 0..k로 한 칸씩 넓혀가며 표 전체를 갱신한다 — 동적 계획법의 전형적인 층 쌓기다.

> **경유 정점(intermediate vertex)** — 경로의 중간에 지나는 정점. 플로이드의 k = "0..k번까지 경유 허용".\
> 예: k=2를 허용해야 0->2->1 이 보이고, 그제야 `d[0][1]` 이 4에서 3으로 줄어든다.

- 논리: 음수 사이클의 증거는 대각선 — 자기 자신으로 돌아오는 거리가 음수면 그 회로를 돌수록 싸진다는 뜻.
- 비용: O(V³) 고정.\
  조기 종료가 없어 입력에 반응하지 않는다.
- 한계: 루프 순서 하나가 맞고 틀림을 가르는데 틀려도 예외가 안 난다 — 검증은 전적으로 테스트 데이터의 질에 달렸다.

> **조용한 오답(silent failure)** — 예외도 경고도 없이 정상 종료하는데 결과만 틀린 것.\
> 예: 루프 순서를 바꾸면 배열 접근은 전부 유효해서 프로그램은 멀쩡히 끝나고, 답만 실제보다 크게 나온다.

**질문별 답**

- Q: 인접 행렬에서 자기 자신까지의 거리는 얼마로 두고, 중복 간선이 있으면 무엇을 남기는가?\
  A: `d[v][v] = 0`으로 둔다 — 아무 데도 안 가는 경로의 비용이 0이다.\
  같은 (from, to)에 간선이 여럿이면 **가장 작은 가중치**만 남긴다(`toMatrix`가 `if (e.weight() < m[from][to])`로 걸러낸다).\
  행렬은 쌍마다 값 하나만 담을 수 있으니 최단 거리를 구하는 이상 최솟값을 남기는 것이 맞다.

> **인접 행렬(adjacency matrix)** — V×V 표로 그래프를 저장하는 방식. 플로이드는 이 표 위에서 돈다(`toMatrix`).\
> 예: 정점 3개면 3×3 표를 만들고, 간선이 없는 칸은 INF, 대각선은 0으로 채운다.

- Q: `d[i][j] = min(d[i][j], d[i][k] + d[k][j])`를 말로 풀면 무슨 뜻인가?\
  A: "i에서 j로 가는 지금까지의 최선"과 "i에서 k까지 갔다가 k에서 j로 가는 길" 중 짧은 쪽을 남긴다는 뜻이다.\
  즉 정점 k를 **경유지로 새로 허용했을 때** 더 싸지는 쌍이 있는지 표 전체에 한 번 묻는 것이다.\
  이 한 줄을 k마다 반복하는 것이 알고리즘 전부다.

- Q: k 루프가 가장 바깥이어야 하는 이유를 "0..k까지만 경유 허용"이라는 뜻으로 설명하면?\
  A: `d[i][j]`의 의미가 "0..k까지만 경유해도 된다면 얼마인가"이고, k 단계는 **k-1 단계가 완성된 표**를 입력으로 받아야 하기 때문이다.\
  k를 바깥에 두면 k 한 값에 대해 모든 (i, j)를 채우고 넘어가므로 그 층이 통째로 완성된다.\
  k를 안쪽에 두면 어떤 (i, j)는 k를 다 본 값이고 어떤 (i, j)는 아직 아닌 값이라 층의 의미가 무너진다.

- Q: i나 j를 바깥에 두면 구체적으로 무엇이 잘못되는가?\
  A: `d[i][k]`나 `d[k][j]`를 읽을 때 그 값이 아직 해당 층까지 갱신되지 않은 **덜 된 값**일 수 있다.\
  그러면 실제로 존재하는 더 짧은 경로를 못 찾고 지나친다 — 답이 실제보다 크게 나온다.\
  배열 접근은 전부 유효하므로 프로그램은 정상 종료한다.

- Q: 루프 순서가 틀렸을 때 예외가 아니라 조용한 오답이 나오는 것이 왜 더 위험한가?\
  A: 실패 신호가 없으니 테스트가 그 케이스를 안 건드리면 영영 안 드러난다.\
  실제로 이 프로젝트에서 그 버그가 **처음에 안 잡혔고**, 계약 테스트가 통과하는 채로 남아 있었다.\
  "동작한다"와 "맞다"가 다르다는 것을 코드 세 줄로 보여주는 사례다.

- Q: `d[i][k]`가 INF면 안쪽 루프를 통째로 건너뛰는데, 그것이 막는 것과 아끼는 것은 각각 무엇인가?\
  A: 막는 것: INF에 값을 더해 "없는 길"이 생기는 오염(음수 가중치가 섞이면 INF + 음수 < INF가 된다).\
  아끼는 것: i에서 k로 못 가면 k 경유는 아예 불가능하므로 j 루프 V번을 통째로 생략한다.\
  정확성 가드와 성능 가드가 같은 한 줄에 겹쳐 있다.

- Q: 음수 사이클의 증거가 `d[v][v] < 0`인 이유는 무엇인가?\
  A: `d[v][v]`는 "v에서 출발해 v로 돌아오는 최단 거리"인데, 처음에 0으로 두었으니 그보다 작아졌다는 것은 **돌아오는 회로의 총합이 음수**라는 뜻이다.\
  그런 회로는 돌 때마다 싸지므로 최단 거리가 정의되지 않는다.\
  그래서 세 겹 루프가 끝난 뒤 대각선만 한 번 훑으면 검출이 끝난다 — V번이면 되는 검사다.

- Q: 음수 **거리**와 음수 **사이클**은 어떻게 다른가?\
  A: 음수 거리는 그냥 "어떤 쌍의 최단 거리가 음수"라는 뜻으로, 음수 간선이 있으면 자연스럽게 생기고 아무 문제가 없다.\
  음수 사이클은 "자기 자신으로 돌아오는 거리가 음수"라 최단 거리 자체가 정의되지 않는 상태다.\
  그래서 검사는 아무 칸이나가 아니라 **대각선만** 본다 — 테스트 `negativeDistanceIsNotANegativeCycle`이 이 구분을 잡는다.

> **음수 거리(negative distance)** — 어떤 쌍의 최단 거리가 음수인 것. 음수 간선이 있으면 자연스럽게 생기고 아무 문제가 없다.\
> 예: `0->2->1 = 2 + (-5) = -3` 은 음수 거리지만 음수 사이클이 아니라서, 그대로 맞는 답이다.

- Q: 플로이드가 "입력에 아예 반응하지 않는다"는 측정은 무엇을 보고 한 말인가?\
  A: 벨만 포드의 라운드 수를 33배 바꿨던 두 그래프(간선 순서만 다른)에서 플로이드는 **완화 횟수까지 똑같았다**(둘 다 1,711회).\
  세 겹 루프가 무조건 V³번 돌고 조기 종료가 없기 때문이다.\
  입력 순서·구조가 비용에 전혀 안 들어간다.

- Q: 조기 종료가 없다는 것이 왜 단점이자 장점인가?\
  A: 단점: 쉬운 입력에서도 V³을 다 낸다 — 벨만 포드라면 2라운드에 끝날 그래프에서도 마찬가지다.\
  장점: **최악이 곧 평균**이라 비용 예측이 정확하다 — "정점 60개면 216,000번"이라고 미리 말할 수 있다.\
  성능이 입력에 흔들리지 않는다는 것은 용량 산정에서 값어치가 있는 성질이다.

- Q: 모든 쌍이 필요할 때 벨만 포드 V번과 플로이드 한 번 중 어느 쪽이 싼지는 무엇이 정하는가(정점 60개 측정치)?\
  A: **밀도**가 정한다.\
  성긴 그래프(간선 59개): 벨만 포드 60번의 조회가 111,451로 V³ = 216,000보다 적다 → 벨만 포드 승.\
  촘촘한 그래프(간선 3,540개): 벨만 포드 **한 번**이 이미 조회 14,160이라 60번이면 849,600 → 플로이드 승.\
  E가 V²면 벨만 포드 한 번이 이미 V³이다.

> **밀도(density)** — 정점 수 V에 견준 간선 수 E의 비율. 벨만 포드 V번과 플로이드 한 번을 고르는 기준.\
> 예: 정점 60개에 간선 59개면 성겨서 벨만 포드, 간선 3,540개면 촘촘해서 플로이드가 싸다.

- Q: 플로이드의 루프 순서 버그가 처음에 안 잡힌 이유는 무엇이고, 무엇을 넣으니 잡혔는가?\
  A: 계약 테스트의 그래프가 전부 `0→1→2→3`처럼 **번호가 올라가는 사슬**이었기 때문이다 — 그런 그래프에서는 i를 바깥에 둬도 우연히 같은 답이 나온다.\
  번호가 **거꾸로 가는** 사슬(`0→4→3→2→1`)을 넣으니 잡혔다(테스트 `descendingChain`).\
  버그를 드러내려면 "갱신에 쓰는 값이 아직 덜 된 순서"를 강제하는 입력이 필요했다.

- Q: 무작위 테스트도 그 버그를 못 잡은 이유는 무엇인가?\
  A: 사이클을 피하려고 `from < to`인 간선만 넣었기 때문이다 — 결과적으로 번호가 올라가는 그래프만 만들어졌다.\
  **테스트 데이터를 편하게 만드느라 검증력을 잃은** 것이다.\
  무작위라는 말이 곧 다양성을 보장하지 않는다는 교훈이 여기에 있다.

> **검증력** — 테스트가 실제로 버그를 잡아낼 수 있는 힘.\
> 예: `from < to` 제약이 번호 역행 그래프를 통째로 배제해, 무작위 테스트인데도 루프 순서 버그를 못 잡았다.

**질문별 답**

- Q: 벨만 포드에서 갱신된 정점만 다음 라운드에 보면(SPFA) 무엇이 좋아지고, 최악은 그대로인가?\
  A: 헛도는 조회가 사라진다 — 33배 차이를 만들었던 "보고도 아무 일 안 하는 간선"을 큐로 걸러내므로 보통 그래프에서 크게 빨라진다.\
  최악은 **그대로 O**(VE)다.\
  특별히 설계된 그래프에서는 거의 모든 간선이 매 라운드 갱신을 만들어 SPFA도 전부 보게 된다.\
  즉 평균을 개선하는 최적화지 상한을 낮추는 알고리즘이 아니다. (최악 부분은 서머리 용어 풀이에 있고, 나머지는 내 추론)

> **SPFA** — 벨만 포드 개선 — 지난 라운드에 갱신된 정점의 간선만 다시 본다. 최악은 그대로 O(VE).\
> 예: 33배 차이를 만들었던 "보고도 아무 일 안 하는 간선"을 큐로 걸러내는 쪽이다.

- Q: 음수 사이클이 있을 때 그 사이클 자체를 찾아내려면 무엇을 더 기억해야 하나?\
  A: 완화할 때마다 `parent[v] = u`(어느 간선으로 줄었는지)를 기록해 둔다.\
  V번째 라운드에서 줄어든 정점 하나를 잡고 `parent`를 V번 거슬러 올라가면 반드시 사이클 안의 정점에 들어가고, 거기서부터 다시 돌아 같은 정점을 만날 때까지가 사이클이다.\
  추가 메모리는 O(V) 하나뿐이다. (원본에 근거 없음 — 내 추론)

- Q: 존슨 알고리즘은 벨만 포드로 가중치를 바꿔 다익스트라를 V번 돌리는데, 왜 그게 이득인가?\
  A: 벨만 포드를 한 번만 써서 모든 가중치를 **음수가 없게 다시 매기고**(각 정점에 퍼텐셜 값을 붙여 w' = w + h(u) - h(v)), 그 뒤로는 14번의 빠른 다익스트라를 V번 돌릴 수 있기 때문이다.\
  비용이 O(V³) 대신 O(VE log V)가 되어, **성긴 그래프**에서 플로이드보다 훨씬 싸다.\
  촘촘한 그래프에서는 E가 V²이라 이득이 사라진다. (원본에 근거 없음 — 내 추론)

- Q: 플로이드로 최단 경로 자체를 복원하려면 — 행렬 하나를 더 두면 되나?\
  A: 된다.\
  `next[i][j]`(또는 `via[i][j]`) 행렬을 하나 더 두고, `d[i][j]`를 갱신할 때마다 그 경로가 거쳐 간 k를 같이 기록한다.\
  복원은 `via[i][j] = k`를 보고 (i,k)와 (k,j)로 재귀적으로 쪼개면 된다.\
  메모리는 V² 하나 더, 시간은 그대로다 — 갱신할 때 한 칸 더 쓰는 것뿐이다. (원본에 근거 없음 — 내 추론)

#### 4. 파생 질문 (서머리 기반)

```
14 -> 15 : 전제를 버리면 무엇을 내주나

  다익스트라 : 음수 없음   가장 가까운 것부터 확정      O(E log V)   빠름
  벨만 포드  : 음수 OK     순서 포기, 전 간선 반복      O(VE)        느림
  플로이드   : 음수 OK     모든 쌍, 경유 허용을 넓힘    O(V^3)       고정

  셋 다 같은 부품을 쓴다 : 완화(relaxation)
    dist[u] + w < dist[v] 면 고쳐 쓴다
  다른 것은 "그 완화를 어떤 순서로 몇 번 하는가" 뿐이다
```

**질문별 답**

- Q: 14번과 15번의 관계를 "전제와 대가"라는 말로 설명하면?\
  A: 다익스트라는 "음수 간선이 없다"는 전제를 받고 그 대가로 확정 순서를 얻어 O(E log V)로 끝낸다.\
  15번은 그 전제를 버리는 대신 확정 순서를 포기하고 O(VE)·O(V³)을 낸다.\
  즉 알고리즘의 속도는 대체로 **입력에 대해 무엇을 가정했느냐**의 값이다.

- Q: 다익스트라가 음수 간선에서 틀리는 예(0→1(1), 0→2(2), 2→1(-5))에서 정확히 어느 순간에 틀린 답이 굳는가?\
  A: 힙에서 거리 1인 정점 1을 꺼내 **확정하는 순간**이다.\
  거리가 더 작은 것부터 꺼내므로 1(거리 1)이 2(거리 2)보다 먼저 나오고, 그 뒤에 2→1의 -5를 만나도 이미 확정이라 안 고친다.\
  실제 답은 0→2→1 = -3인데 1이 남는다 — 원본 테스트가 다익스트라를 직접 돌려 이 틀린 답을 기록해놨다.

- Q: 다익스트라·벨만 포드·플로이드 셋이 공유하는 부품은 무엇인가?\
  A: **완화(relaxation)** — `dist[u] + w < dist[v]`면 고쳐 쓰는 한 줄이다.\
  셋 다 이 연산을 반복할 뿐이고, 정확성도 전부 "완화를 충분히 많이 하면 최단 거리로 수렴한다"에 기댄다.\
  그래서 셋을 따로 외우는 것보다 "완화를 어떻게 배치하느냐"로 묶어 이해하는 편이 낫다.

- Q: 셋의 차이를 "완화를 어떤 순서로 하는가"로 정리하면?\
  A: 다익스트라는 **거리가 작은 정점부터** 한 번씩(그래서 정점당 한 번이면 끝난다 — 음수가 없다는 전제 덕).\
  벨만 포드는 **순서를 정하지 않고** 모든 간선을 V-1번 반복해서.\
  플로이드는 **경유 허용 정점을 하나씩 늘려가며** 모든 쌍에 대해.\
  순서를 강하게 고를수록 빠르고, 그만큼 전제가 필요하다.

> **확정 순서** — 다익스트라가 기대는 "가까운 것부터"라는 순서. 15번의 둘은 그것을 포기한 대가로 음수를 견딘다.\
> 예: 확정 순서가 있으면 정점당 한 번이면 끝나지만, 없으면 모든 간선을 V-1번 반복해야 한다.

- Q: 벨만 포드에는 조기 종료가 있고 플로이드에는 없는데, 그 차이는 두 알고리즘의 무엇에서 오는가?\
  A: 벨만 포드의 라운드는 "변화가 없으면 이후도 없다"는 고정점 성질이 있어 멈출 수 있다.\
  플로이드의 k 루프는 "경유 허용 집합을 넓히는" 단계라, 지금 k에서 변화가 없어도 다음 k에서 새 경유지가 열리며 값이 줄 수 있다 — 멈출 근거가 없다.\
  즉 같은 "반복"처럼 보여도 반복의 의미가 다르다. (플로이드 쪽 설명은 원본에 근거 없음 — 내 추론)

> **고정점(fixed point)** — 한 번 더 적용해도 값이 안 바뀌는 상태.\
> 예: 벨만 포드는 한 라운드에 변화가 없으면 그 뒤로도 영원히 없어서 거기서 멈춰도 된다.

- Q: 간선 순서가 라운드 수를 33배 바꾼 실험에서 "표기 복잡도"에 대해 배울 점은 무엇인가?\
  A: 표기는 **상한**이지 실제 비용이 아니고, 같은 표기 안에서 수십 배가 난다는 것이다.\
  V도 E도 같고 답도 같은데 조회가 297 대 9,900이었다 — 이 차이는 O(VE) 어디에도 안 적힌다.\
  그래서 "복잡도가 같다"는 말로 두 구현을 같다고 보면 안 되고, 실제로 세어봐야 한다.

- Q: 음수 사이클 검출이 실무에서 그 자체로 쓸모 있는 경우는 무엇인가?\
  A: 환율 차익 거래 탐지다 — 통화를 간선, 환율의 로그를 음수 가중치로 두면 음수 사이클이 "한 바퀴 돌면 돈이 늘어나는 경로"가 된다.\
  여기서는 예외를 던질 사고가 아니라 **찾아내야 할 답**이다.\
  같은 검출 로직이 문맥에 따라 오류 신호도 되고 결과도 된다. (서머리의 예시 — 구체적 로그 변환은 내 추론)

- Q: 테스트 데이터를 편하게 만들다 검증력을 잃은 사례에서, 같은 실수를 피하려면 무엇을 점검해야 하는가?\
  A: "생성기에 건 제약이 버그가 드러나는 조건까지 같이 지워버리지 않았나"를 본다 — 여기서는 사이클을 피하려 건 `from < to`가 번호 역행 그래프를 통째로 배제했다.\
  방법은 일부러 버그를 심어(변종) 테스트가 그것을 잡는지 확인하는 것이다 — 이 프로젝트가 실제로 그렇게 잡았다.\
  통과하는 테스트는 "코드가 맞다"가 아니라 "이 데이터에서는 안 틀렸다"까지만 말해준다.

- Q: 무한대를 표현하는 값의 선택(`MAX_VALUE` 대 `MAX_VALUE/4`)이 14번과 15번에서 왜 달라졌는가?\
  A: 14번은 가중치가 전부 0 이상이라 무한대에서 완화만 안 하면 덧셈 자체가 안 일어났고, 그래서 `Long.MAX_VALUE`를 그대로 써도 됐다.\
  15번은 음수 가중치 때문에 INF에 더하면 **넘치지 않고도 INF보다 작아져** 없는 길이 생긴다 — 값의 크기가 아니라 방향이 문제다.\
  그래서 `MAX_VALUE / 4`로 여유를 두고, 동시에 "안 닿은 정점에서 완화 금지" 가드도 함께 건다.
