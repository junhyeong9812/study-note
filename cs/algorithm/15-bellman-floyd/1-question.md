#### 1. `BellmanFord.distances` (TODO 1~4)

```java
/**
 * 벨만 포드. 음수 간선이 있어도 최단 거리를 구한다. O(VE).
 * 다익스트라는 "가장 가까운 것부터 확정" 이라는 순서에 기댄다.
 * 벨만 포드는 그 순서를 포기한다. 대신 무엇을 하나.
 */
public static long[] distances(CountedGraph g, int start, int[] rounds)

/** 무한대. Long.MAX_VALUE 를 쓰면 가중치를 더할 때 넘친다. */
static final long INF = Long.MAX_VALUE / 4;

// TODO 1: 라운드를 몇 번 도나.
//   최단 경로가 쓸 수 있는 간선의 최대 개수는 몇 개인가.
//   그보다 많이 쓰면 정점이 반복되고, 그건 사이클을 도는 것이다.
//   음수 사이클이 없다면 사이클을 도는 것이 이득인 경우가 있나.
// TODO 2: 한 라운드는 모든 간선을 한 번씩 훑으며 완화하는 것이다.
//   아직 안 닿은 정점(거리가 INF)에서 완화를 시도하면 안 된다.
//   INF 에 음수 가중치를 더하면 어떻게 되나. 없는 길이 생기나.
//   거리가 줄 때마다 g.countRelaxation() 을 불러라. 측정에 쓴다.
// TODO 3: 조기 종료.
//   한 라운드에 아무것도 안 줄었으면 다음 라운드는 어떻게 되나.
// TODO 4: 음수 사이클을 어떻게 알아채나.
//   V-1 라운드로 충분하다고 했다. 그런데 한 번 더 돌렸는데도 줄어들면?
//   그때 최단 거리라는 것이 정의되나.
```

- 최단 경로가 쓸 수 있는 간선의 최대 개수가 V-1개인 이유는 무엇인가?
- 음수 사이클이 없다면 사이클을 도는 것이 이득인 경우가 있는가?
- "한 라운드마다 무엇이 확정되는가"를 한 문장으로 말하면?
- 무한대를 `Long.MAX_VALUE`로 두면 안 되는 이유는 무엇인가?
- 원본은 그 함정을 **두 가지 방법으로 동시에** 막는데, 둘은 각각 무엇이고 왜 둘 다 하는가?
- 닿을 수 없는 곳에 있는 음수 사이클은 왜 무시해야 하고, 코드의 어느 한 줄이 그것을 저절로 처리하는가?
- 조기 종료의 조건은 무엇이고, 그것이 성립하면 왜 남은 라운드가 전부 무의미한가?
- 음수 사이클 검출은 어떻게 하고, 왜 그때 "최단 거리"가 정의되지 않는가?
- 무방향 그래프에 음수 간선을 넣으면 왜 그 자체가 음수 사이클인가?
- 정점 100개 직선 그래프에서 간선 순서만 뒤집으면 라운드 수와 간선 조회는 각각 얼마가 되는가(측정치)?
- 그런데 완화 횟수는 둘 다 99로 같다 — 33배 차이의 정체는 무엇인가?
- `O(VE)`라는 표기가 그 차이를 못 보여주는 이유는 무엇인가?
- `rounds`를 배열(길이 1)로 받는 이유는 무엇인가?
