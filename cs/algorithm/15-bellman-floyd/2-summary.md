## 한눈에 — 쉽게 말하면

**벨만 포드 = 순서 없이 "더 싼 길 발견!" 소식을 모두에게 반복해서 도는 방송. 플로이드 워셜 = "중간에 어디까지 경유해도 되나"를 한 칸씩 넓혀가며 채우는 모든-쌍 요금표.**

- 다익스트라(14번)는 "가장 가까운 것부터 확정"이라는 **순서**에 기댄다. 간선에 음수(할인·캐시백 같은 마이너스 비용)가 섞이면 그 순서가 깨진다 — 이미 확정한 정점이 나중에 더 싸질 수 있으니까.
- 이 박스의 둘은 그 **순서를 포기한다. 대신 훨씬 비싸다:**

| | 무엇을 하나 | 비용 |
|---|---|---|
| 벨만 포드 | 모든 간선을 V-1번 훑는다 | O(VE) |
| 플로이드 워셜 | 중간 정점을 하나씩 허용해가며 표를 채운다 | O(V³) |

- 음수 **간선**까지는 괜찮은데 음수 **사이클**(돌수록 총비용이 줄어드는 회로)이 있으면 "최단 거리"라는 것 자체가 정의되지 않는다 — 무한히 돌면 무한히 싸지니까. 두 알고리즘 다 이걸 **검출해서 던진다.**
- 실무 예: 환율 차익 거래 탐지(음수 사이클 = 돈 복사), 요금에 할인이 섞인 경로 계산, 모든 쌍 거리표 만들기.

```text
다익스트라: 가까운 순서로 확정   (순서에 기댐 -> 음수에 무너짐)
벨만 포드:  순서 없이 전 간선 반복 (느리지만 음수 OK)
플로이드:   모든 쌍을 한꺼번에    (V^3 고정, 조기 종료 없음)
```

## 문제 — 이 챕터가 시키는 것

원본 README는 이 박스를 한 줄로 소개한다: "**14번의 전제를 버리면 무엇을 내줘야 하는가.**"
다익스트라는 "가장 가까운 것부터 확정"이라는 순서에 기대는데, 음수 간선이 있으면 그게 깨진다. 이 박스의 둘은 그 순서를 포기하는 대신 훨씬 비싼 값을 치른다 — 벨만 포드는 모든 간선을 V-1번 훑고(O(VE)), 플로이드 워셜은 중간 정점을 하나씩 허용해가며 표를 채운다(O(V³)). 그 둘을 직접 구현하고, 음수 사이클 검출·무한대 오버플로·루프 순서 같은 함정을 실제로 밟아보는 것이 과제다.

README가 미리 못박는 함정: 무한대를 `Long.MAX_VALUE`로 두면 `MAX + (-1)`이 없는 길을 만든다 / 닿을 수 없는 음수 사이클은 무시해야 한다 / 무방향 그래프의 음수 간선은 그 자체가 음수 사이클이다 / 플로이드의 `k` 루프는 가장 바깥이어야 하고 순서를 바꾸면 **예외 없이 답만 틀린다** / 음수 **거리**와 음수 **사이클**은 다르다.

아래 서머리는 이 문제(README)를 분석·정리한 것이다.

## 다익스트라가 틀리는 것을 직접 보인다 (원본 README의 예)

```text
      (1)
  0 --------> 1
  |           ^
(2)|          |(-5)
  v           |
  2 ----------+
```

- 직접 가기: 1
- 2 경유: 2 + (-5) = **-3** ← 이쪽이 답

다익스트라는 거리가 작은 것부터 꺼낸다. 1(거리 1)이 2(거리 2)보다 먼저 나와 **거기서 확정된다.** 그 뒤에 -5를 만나도 이미 확정이라 안 고친다. 원본 테스트가 다익스트라를 직접 돌려 **1이라는 틀린 답이 나오는 것**을 기록해놨다. 14번의 그래프가 음수를 막는 이유가 이것이다.

## 전체 흐름

```text
벨만 포드 (한 시작점):
   dist[] = INF, dist[시작점] = 0
   최대 V-1 라운드 반복:
      모든 간선 (u -> v, w) 에 대해: dist[u] + w < dist[v] 면 갱신 (완화)
      한 라운드에 아무것도 안 줄었으면 조기 종료
   한 라운드 더 돌려서 그래도 줄어들면 -> 음수 사이클 -> 예외

플로이드 워셜 (모든 쌍):
   d[i][j] = 간선 있으면 그 무게, 없으면 INF, d[i][i] = 0
   k = 0..V-1 (가장 바깥!):
      모든 (i, j) 에 대해: d[i][k] + d[k][j] < d[i][j] 면 갱신
   d[v][v] < 0 인 정점이 있으면 -> 음수 사이클 -> 예외
```

## 예시 그래프 (11/12/14번과 같은 모양 — 4→5만 음수로 바꿈)

```text
        0
    2  / \  5
      v   v
      1   2
    1 |   | 2
      v   v
      3   4
    9  \ /  -1        <- 여기가 할인 간선
        v
        5

간선: 0->1(2), 0->2(5), 1->3(1), 3->5(9), 2->4(2), 4->5(-1)
```

주의: **무방향 그래프에 음수 간선을 넣으면 그 자체가 음수 사이클이다** — 왕복하면 두 배로 줄어든다. 그래서 여기서는 방향 그래프다.

## 동작 — BellmanFord (한 시작점, 음수 간선 허용)

**언제 쓰나**: 음수 간선이 있는 그래프의 한-시작점 최단 거리. 음수 사이클 검출도 겸한다.

**왜 V-1 라운드면 충분한가**: 최단 경로는 간선을 V-1개보다 많이 쓸 수 없다 — 더 쓰면 정점이 반복되고, 그건 사이클을 도는 것이라 (음수 사이클이 없다면) 손해다. 한 라운드마다 "간선 하나 더 쓰는 경로"까지가 확정되므로 V-1 라운드면 끝난다.

전 상태 (시작점 0):

```text
dist = [0, INF, INF, INF, INF, INF]
```

단계 (간선을 넣은 순서대로 전부 훑는 것이 1라운드):

```text
라운드 1: 0->1: dist1=2   0->2: dist2=5   1->3: dist3=3
          3->5: dist5=12  2->4: dist4=7   4->5: 7+(-1)=6 < 12 -> dist5=6
라운드 2: 전 간선 훑음 -> 아무것도 안 줄음 -> 조기 종료 (rounds = 2)
검사 라운드: 그래도 안 줄음 -> 음수 사이클 없음 -> 정상 반환
```

후 상태:

```text
dist = [0, 2, 5, 3, 7, 6]     (다익스트라 판 14번과 달리 5의 답이 할인 덕에 6)
```

구현에서 중요한 결정들(원본 코드 그대로):

1. **무한대를 `Long.MAX_VALUE`로 두면 안 된다.** `MAX + (-1)`은 `MAX - 1`이라 "없는 길"이 생긴다. 원본은 `INF = Long.MAX_VALUE / 4`로 잡고, **동시에** 아직 안 닿은 정점(`dist >= INF`)에서는 완화를 아예 안 한다. 막는 방법 둘을 **둘 다** 써서 실수가 겹쳐도 안 터지게 했다.
2. 닿을 수 없는 곳의 음수 사이클은 **무시해야** 하는데, "이미 닿은 정점에서만 완화"가 이것도 저절로 해결한다.
3. **음수 사이클 검출 = V-1 라운드 후 한 번 더 돌려보기.** 그래도 줄어들면 무한히 줄일 수 있다는 뜻 — `NegativeCycleException`을 던진다.

**비용**: O(VE) — 라운드 최대 V-1번 × 라운드마다 간선 E개. 단 조기 종료 덕에 보통은 훨씬 일찍 끝난다(아래 측정).

## 동작 — 간선 순서가 라운드 수를 바꾼다

같은 그래프, 같은 알고리즘, **간선 목록의 순서만 반대**로:

```text
순서: 4->5, 3->5, 2->4, 1->3, 0->2, 0->1  (뒤에서 앞으로)

라운드 1: 앞 네 개는 출발점이 아직 INF 라 전부 건너뜀. 0->2=5, 0->1=2 만 됨
라운드 2: 2->4=7, 1->3=3
라운드 3: 4->5=6 (3->5 의 12는 이미 6이라 짐)
라운드 4: 변화 없음 -> 종료 (rounds = 4)
```

답은 같은데 2라운드가 4라운드가 됐다. 소식이 흐르는 방향과 간선을 읽는 방향이 어긋나면 라운드마다 한 발짝밖에 못 전진한다. 원본 측정: 정점 100개 직선 그래프에서 순서만 뒤집으면 **라운드 2 vs 99, 간선 조회 297 vs 9,900 (33배).** 완화 횟수는 둘 다 99로 같다 — 헛도는 것은 "간선을 보고도 아무 일도 안 하는 것"이다. **O(VE)라는 표기에는 이 차이가 안 보인다.**

## 동작 — FloydWarshall (모든 쌍)

**언제 쓰나**: 모든 정점 쌍의 최단 거리표가 필요할 때. 음수 간선 허용.

아이디어: "i에서 j로 갈 때 **중간 경유지로 0..k번 정점까지만 허용**하면 얼마인가"를 k를 0부터 늘려가며 채운다. k를 하나 허용할 때마다 표 전체에 대해 "k를 경유하면 더 싼가"를 묻는다:

```text
d[i][j] = min( d[i][j],  d[i][k] + d[k][j] )
                지금 길    k 를 경유하는 길
```

작은 예 (정점 3, 간선 0→1(4), 0→2(1), 2→1(2)):

전 상태 (간선만 채운 표):

```text
       0    1    2
  0    0    4    1
  1    ∞    0    ∞
  2    ∞    2    0
```

단계:

```text
k=0 허용: 0 을 경유해 싸지는 쌍 없음 (0 으로 들어오는 간선이 없다)
k=1 허용: 1 은 나가는 간선이 없어 변화 없음
k=2 허용: d[0][1] = min(4, d[0][2]+d[2][1] = 1+2 = 3) -> 3 으로 갱신
```

후 상태:

```text
       0    1    2
  0    0    3    1      <- 0->2->1 이 직행(4)보다 싸다
  1    ∞    0    ∞
  2    ∞    2    0
```

구현에서 중요한 결정들(원본 코드·README 그대로):

1. **k 루프가 가장 바깥이어야 한다.** 순서를 바꾸면 아직 안 끝난 값을 쓰게 된다 — 예외 없이 **답만 조용히 틀린다.** 코드는 세 줄인데 그 순서 하나가 맞고 틀림을 가른다.
2. `d[i][k]`가 INF면 k를 거치는 길이 없으므로 안쪽 루프를 통째로 건너뛴다(INF 오염 방지 + 절약).
3. **음수 사이클의 증거는 `d[v][v] < 0`이지 아무 칸이나가 아니다.** 자기 자신으로 돌아왔는데 음수면, 그 회로를 돌수록 싸진다는 뜻. 음수 **거리**와 음수 **사이클**은 다르다.

**비용**: O(V³) — 세 겹 루프가 무조건 V³번. 조기 종료가 없다. **그게 단점이자 장점이다: 최악이 곧 평균이라 예측이 쉽다.** (원본 측정: 간선 순서를 바꿔도 완화 횟수까지 똑같았다 — 입력에 아예 반응하지 않는다.)

## 비교 — 어느 쪽을 쓰나 (원본 README의 실측)

**모든 쌍이 필요할 때, 벨만 포드를 V번 돌리기 vs 플로이드 한 번은 밀도가 정한다.** 정점 60개 기준:

- 성긴 그래프(간선 59): 벨만 포드 60번 = 조회 111,451 < V³ = 216,000 → **벨만 포드 승**
- 촘촘한 그래프(간선 3,540): 벨만 포드 **한 번**에 조회 14,160, 60번이면 849,600 → **플로이드 승**

E가 V²면 벨만 포드 한 번이 이미 V³이다.

**변종이 알려준 것 — 테스트 데이터의 함정.** 플로이드의 루프 순서 버그(k를 안쪽에)가 처음에 안 잡혔다. 계약 테스트의 그래프가 전부 `0→1→2→3`처럼 **번호가 올라가는 사슬**이라 우연히 같은 답이 나왔기 때문. 번호가 거꾸로 가는 사슬(`0→4→3→2→1`)을 넣으니 잡혔다. 무작위 테스트도 못 잡았다 — 사이클을 피하려고 `from < to` 간선만 넣었기 때문. **테스트 데이터를 편하게 만드느라 검증력을 잃고 있었다.**

## 핵심 문장

- 이 박스는 "14번의 전제(음수 없음)를 버리면 무엇을 내줘야 하는가"다 — 답: 확정 순서를 포기하고 O(VE) 또는 O(V³)를 낸다.
- 벨만 포드가 V-1 라운드면 되는 이유: 최단 경로는 간선을 V-1개보다 많이 못 쓴다. V번째에도 줄면 음수 사이클이다.
- 무한대는 `MAX_VALUE`가 아니라 넘칠 수 없는 값(MAX/4)으로 + 안 닿은 정점에선 완화 금지 — 둘 다 해서 실수가 겹쳐도 안 터지게.
- 플로이드는 k(경유 허용) 루프가 가장 바깥 — 바꾸면 예외 없이 답만 조용히 틀리고, 편하게 만든 테스트 데이터는 그걸 못 잡는다.
- 음수 사이클의 증거: 벨만 포드는 "한 라운드 더 돌려도 준다", 플로이드는 "d[v][v] < 0". 음수 거리와 음수 사이클은 다르다.

## 용어 풀이

- **벨만 포드(Bellman-Ford)**: 모든 간선을 최대 V-1번 훑어 음수 간선이 있어도 한-시작점 최단 거리를 구하는 알고리즘. O(VE).
- **플로이드 워셜(Floyd-Warshall)**: 경유 허용 정점을 하나씩 늘려가며 모든 쌍의 최단 거리를 채우는 알고리즘. O(V³).
- **음수 간선(negative edge)**: 지나면 총비용이 줄어드는 간선. 할인·캐시백. 다익스트라의 전제를 깬다.
- **음수 사이클(negative cycle)**: 한 바퀴 돌면 총비용이 음수인 회로. 돌수록 싸져서 최단 거리가 정의되지 않는다.
- **완화(relaxation)**: `dist[u] + w < dist[v]`면 거리를 고쳐 쓰는 것. 세 알고리즘(다익스트라 포함)의 공용 부품.
- **라운드(round)**: 벨만 포드에서 "모든 간선을 한 바퀴 훑기". 한 라운드에 변화가 없으면 끝난 것이다.
- **조기 종료(early termination)**: 변화 없는 라운드에서 멈추는 것. 벨만 포드엔 있고 플로이드엔 없다.
- **INF(무한대 대용값)**: "아직 못 감"의 표시. `Long.MAX_VALUE / 4` — 가중치를 더해도 넘치지 않는 크기로.
- **오버플로(overflow)**: 표현 범위를 넘어 값이 엉키는 것. `MAX + (-1) = MAX - 1`로 "없는 길"이 생기는 함정.
- **모든 쌍 최단 거리(all-pairs shortest path)**: 모든 (i, j) 쌍의 최단 거리표. 플로이드의 출력.
- **경유 정점(intermediate vertex)**: 경로의 중간에 지나는 정점. 플로이드의 k = "0..k번까지 경유 허용".
- **인접 행렬(adjacency matrix)**: V×V 표로 그래프를 저장하는 방식. 플로이드는 이 표 위에서 돈다(`toMatrix`).
- **간선 목록(edge list)**: 간선을 (from, to, weight)의 나열로 저장. 벨만 포드는 이걸 통째로 반복해 훑는다.
- **확정 순서**: 다익스트라가 기대는 "가까운 것부터"라는 순서. 이 박스의 둘은 그것을 포기한 대가로 음수를 견딘다.
- **SPFA**: 벨만 포드 개선 — 지난 라운드에 갱신된 정점의 간선만 다시 본다. 최악은 그대로 O(VE)(원본 '생각해볼 것').
- **O(VE) / O(V³)**: 벨만 포드/플로이드의 비용. 전자는 라운드 V × 간선 E, 후자는 세 겹 루프.
