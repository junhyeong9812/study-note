# algorithm/22-dp-advanced — 정리 (힌트)

## 해결하는 문제

21번에서 "표를 쓰면 빨라진다"를 배웠지만, 상태를 순서·경로 같은 것으로 잡으면 표를 써도 칸 수가 n!이라 지수를 못 벗어난다.\
외판원 12개 도시를 "지금까지의 방문 순서"로 표에 적으면, 출발지를 고정한 완성된 순서만 11! = 약 4천만 가지이고 중간까지의 부분 경로를 칸으로 두면 그보다 더 많다.

```text
상태 = 방문 순서                          상태 = (방문 집합, 현재 위치)
  0->1->2->4 와 0->2->1->4 가 다른 칸       둘 다 "[0,1,2,4] 에서 4" 한 칸
  완성 순서만 11! = 39,916,800 가지           2^12 x 12 = 49,152 칸 (채운 것 11,254)
  재귀 108,505,112 번                         채운 칸이 호출 수보다 9,641 배 적다
```

DP 심화는 "무엇이 같으면 미래가 같은가"를 찾아 상태를 최소로 누르는 기술이다 — 구간 `[i, j]`, 집합의 비트, 트리의 (정점, 골랐나).\
쉬운 예: 지도의 좌표를 무엇으로 잡느냐에 따라 지도가 쓸모 있기도 없기도 하다 — 한눈에 절.\
똑같은 구조다: 상태 = 미래에 영향을 주는 것만 남긴 요약.\
실무 예: DB 옵티마이저의 조인 순서 결정(집합 DP), 방문지가 적을 때의 정확한 최적 순회(비트마스크 TSP), 트리 구조 위의 최적 선택(트리 DP).

### 한눈에 — 쉽게 말하면

**DP 심화 = "표를 쓰면 빨라진다"(21번) 다음 단계: 표의 칸, 즉 상태를 어떻게 잡느냐가 승부를 가른다.**

- 지도를 그릴 때 무엇을 좌표로 삼느냐에 따라 지도가 쓸모 있기도, 쓸모없기도 하다.\
  DP도 같다 — **상태를 잘못 잡으면 표를 써도 지수를 못 벗어난다.**
- 이 챕터는 상태의 세 가지 새로운 모양을 다룬다:
  - **구간 DP**: 상태 = 구간 `[i, j]`.\
    "마지막에 어디를 자를지"가 문제를 둘로 쪼갠다.\
    (행렬 곱 순서)
  - **비트마스크 DP**: 상태 = (방문한 도시 **집합**, 현재 위치).\
    집합을 정수 하나의 비트로 눌러 담는다.\
    (외판원 순회)
  - **트리 DP**: 상태 = (정점, 골랐나/안 골랐나).\
    사이클이 없어서 자식들의 답을 독립적으로 합친다.\
    (최대 독립 집합)
- 실측: 외판원 12개 도시에서 순서 전부 시도 **108,505,112번** vs 상태로 눌러 담기 **11,254번** — 9,641배.

> **상태(state)** — "지금 상황"을 요약한 값 묶음. 상태가 같으면 앞으로의 답도 같아야 한다.\
> 예: "[0,1,2,4]를 방문했고 지금 4에 있음" — 여기까지 온 순서가 여럿이어도 한 칸으로 합쳐진다.

> **n!(팩토리얼)** — 1×2×…×n, 곧 순서(순열)의 개수.\
> 예: 도시 12개의 방문 순서는 11! = 약 4천만 가지다.

> **2^n** — 원소 n개의 부분집합 개수. 비트마스크 상태 수의 뼈대다.\
> 예: n=20이면 약 백만이라, 그 위로는 이 방법도 못 쓴다.

> ⚠ 정정(2026-09-28): 2^20 ≈ 105만은 집합 수이고 표는 2^n×n ≈ 2,100만 칸이다. "20 위로는 못 쓴다"는 원본 impl의 어림(TravelingSalesman.java:16)이지 보편 경계가 아니다 — 상한은 메모리·시간 제한에 따라 정한다.

```text
순서로 보면: 0->1->2->4, 0->2->1->4, ...  전부 다른 길 (11! = 약 4 천만 가지)
상태로 보면: "[0,1,2,4] 를 방문했고 지금 4 에 있음"  <- 위의 순서들이 전부 이 하나
                                                       (2^12 x 12 = 49,152 가지)
어떤 순서로 왔는지가 앞으로의 비용에 영향을 안 주니까 합칠 수 있다.
```

## 동작·원리

### 전체 흐름

```text
문제를 받는다
  |
  v
"무엇이 같으면 앞으로의 답이 같은가"를 찾는다  <- 상태 설계. 이 챕터의 전부
  |
  |-- 구간을 합치는 문제인가?      -> 상태 = [i, j] 구간          (구간 DP)
  |-- "어떤 집합을 거쳤나"가 핵심? -> 집합을 비트로 눌러 담는다    (비트마스크 DP)
  |-- 그래프가 트리인가?           -> 정점마다 (골랐다/안 골랐다)  (트리 DP)
  v
채우는 순서를 정한다  <- 작은 답이 먼저 준비되도록 (구간이면 짧은 것부터)
  |
  v
답의 위치를 확인한다  <- 뿌리의 두 칸 중 큰 쪽, 전체 구간 칸, ... 문제마다 다르다
```

### 동작 — 구간 DP: 행렬 곱 순서 (`MatrixChain.java`)

**언제 쓰나**: 행렬 여러 개를 곱할 때, 어떤 순서로 곱해도 결과는 같지만 비용은 크게 다르다.\
최소 곱셈 횟수를 찾는다.\
"구간을 하나로 합치는 최소 비용" 유형의 대표다.

> **행렬 곱 비용** — A(p×q)와 B(q×r)를 곱하면 곱셈이 p×q×r번 든다.\
> 예: `dims = [10, 30, 5]`의 두 행렬을 곱하면 10×30×5 = 1,500번이다.

> **구간 DP(interval DP)** — 상태를 구간 [i, j]로 잡고, 마지막에 자를 자리를 전부 시도해 양쪽 답을 합치는 DP.\
> 예: "[i, j]의 행렬들을 하나로 합치는 최소 비용"이 한 칸이 된다.

전 상태 — 순서가 비용을 바꾼다:

```text
A(10x30)  B(30x5)  C(5x60) 세 개를 곱한다. dims = [10, 30, 5, 60]

(AB)C : 10x30x5 + 10x5x60  = 1,500 + 3,000  =  4,500 번
A(BC) : 30x5x60 + 10x30x60 = 9,000 + 18,000 = 27,000 번   <- 6 배 차이
```

단계 (그림 해설: 한 단계 한 문장):

- 상태를 "구간 [i, j]의 행렬들을 하나로 합치는 최소 비용"으로 잡는다.
- 그 구간에서 **마지막에 자를 자리 k**를 전부 시도한다: `비용 = [i,k]의 답 + [k+1,j]의 답 + 두 덩어리를 곱하는 비용(dims[i] × dims[k+1] × dims[j+1])`.\
  최소를 고른다.
- 배낭과 다른 점: 배낭은 "앞에서부터" 하나씩 결정했지만, 여기는 마지막 자르기가 문제를 **양쪽으로** 쪼갠다.\
  그래서 구간 DP다.
- **채우는 순서는 짧은 구간부터** — 길이 1(비용 0)을 먼저 깔고, 길이 2, 3, …으로 늘린다.\
  긴 구간이 짧은 구간의 답을 읽기 때문이다.\
  `i`를 바깥 루프에 두면 순서가 안 맞는다(15번 플로이드에서 `k`를 바깥에 둬야 했던 것과 같은 종류).

> ⚠ 정정(2026-09-28): 길이 순만 가능한 것은 아니다. `i`를 **증가** 순으로 바깥에 두면 틀리지만, `i`를 n-1에서 0으로 **감소**시키고 안쪽 `j`를 `i`부터 증가시켜도 `[i,k]`·`[k+1,j]`가 먼저 채워져 의존성을 만족한다.

후 상태 — 표가 채워지는 순서:

```text
       j=0    j=1     j=2
i=0  [  0 ] [1500 ] [4500]   <- 길이 1 (대각선) 먼저, 그 다음 길이 2, 길이 3
i=1         [  0  ] [9000]      [0][2] 칸이 답 = 4,500
i=2                 [  0 ]
     (i > j 인 왼쪽 아래 절반은 "끝이 시작보다 앞" 이라 의미 없음 -> 안 씀)
```

**비용**: 구간 O(n²)개 × 자를 자리 O(n)개 = O(n³).\
실측: 행렬 60개에서 표 3,600칸 중 쓰기 1,830번 — 정확히 `n(n+1)/2`, **표의 절반만 쓴다**.\
최적 순서를 찾는 데 표 읽기 71,981번을 쓰고 곱셈 10,382,856 → 134,863번(76배)을 아꼈다 — 찾는 비용이 아끼는 비용의 0.7%다.

> **채우는 순서(fill order)** — 타뷸레이션에서 표의 어느 칸부터 채울지의 순서. 읽히는 칸이 먼저 채워져 있어야 한다.\
> 예: 구간 DP는 긴 구간이 짧은 구간을 읽으므로 길이 1부터 차례로 늘려 간다.

### 동작 — 비트마스크 DP: 외판원 순회 (`TravelingSalesman.java`)

**언제 쓰나**: 모든 도시를 한 번씩 들르고 출발지로 돌아오는 최소 비용(TSP).\
"어떤 집합을 이미 거쳤나"가 상태의 일부일 때 집합을 정수의 비트로 표현한다.

> **비트마스크(bitmask)** — 집합을 정수 하나의 2진 비트로 표현하는 기법. i번 원소가 있으면 i번째 비트가 1이다.\
> 예: {0, 2, 3} = 2진수 1101 = 13.

> **비트 연산** — `mask | (1 << i)` = i를 집합에 넣은 새 값, `mask & (1 << i)` = i가 집합에 있는지 확인.\
> 예: 원래 `mask`를 고치지 않고 새 값을 만들어 넘기는 것이 중요하다 — 고치면 형제 갈래가 오염된다.

> **외판원 순회(TSP, traveling salesman problem)** — 모든 도시를 한 번씩 들르고 출발지로 돌아오는 최소 비용 경로 문제.\
> 예: 도시 12개면 순서가 11! = 약 4천만 가지지만, 상태로 누르면 2^12 × 12 = 49,152개다.

전 상태 — 집합을 정수로:

```text
도시 4 개. mask 는 4 비트.
mask = 0101  ->  {0, 2} 방문함        비트 켜기: mask | (1 << next)
        ^^        2 0                 비트 확인: mask & (1 << next)
상태 = (mask, 현재 도시)  ->  전부 2^4 x 4 = 64 칸
```

단계 (그림 해설: 한 단계 한 문장):

- 시작: 0번 도시에서 출발하므로 `mask = 0001`(0번만 방문), 현재 위치 0.
- 각 상태에서 아직 안 간 도시(비트가 꺼진 도시)를 하나씩 시도한다: `이동 비용 + 그 다음 상태의 답` 중 최소.
- 모든 비트가 켜지면(`mask == 1111`) 출발지 0으로 돌아가는 비용을 반환한다.
- **원래 `mask`를 고치면 안 된다** — `mask | (1 << next)`로 새 값을 만들어 넘긴다(고치면 형제 갈래가 오염된다).
- 상태는 `key = mask * n + at`로 눌러 1차원 표에 담고, 메모이제이션으로 채운다.

후 상태 — 실측 숫자:

```text
도시 12 개:
  순서 전부 시도 : 108,505,112 번 호출     (11! = 39,916,800 가지 순서)
  비트마스크 DP  :      11,254 칸 채움     (상태는 2^12 x 12 = 49,152 개)
                                            -> 9,641 배

채운 칸이 49,152 중 11,254 (23%) 뿐인 이유:
  "집합에 없는 도시에 서 있다", "0 번을 안 거친 집합" 같은 상태는 도달 불가능.
  21 번 배낭의 56% 보다 낮다 — 상태를 넓게 잡을수록 빈 칸 비율이 커진다.
```

> **도달 불가능한 상태(unreachable state)** — 문제 규칙상 생길 수 없는 상태 조합.\
> 예: "집합에 없는 도시에 서 있다" 같은 칸 — 메모이제이션은 안 채우고 타뷸레이션은 모르고 채운다.

> ⚠ 정정(2026-09-28): 모든 칸을 채우는 것은 단순한 타뷸레이션 구현의 선택이다. 타뷸레이션도 루프에서 도달 불가능한 상태(예: 현재 도시가 집합에 없음)를 건너뛸 수 있다.

**비용**: 상태 2^n × n개, 상태마다 다음 도시 n개 시도 = O(2^n × n²).\
지수이긴 하지만 (n-1)!보다 훨씬 작다.\
**n이 20을 넘으면 이 방법도 못 쓴다** — 2^n이 백만을 넘기 때문(메모리가 먼저 터진다).

> ⚠ 정정(2026-09-28): 20은 원본 impl javadoc의 어림이지 보편 경계가 아니다. 시간 O(n²2ⁿ)·공간 O(n2ⁿ)을 실행 환경의 예산과 비교해 상한을 정한다(n=20이면 표만 약 2,100만 칸).

### 동작 — 트리 DP: 최대 독립 집합 (`TreeDp.java`)

**언제 쓰나**: 이웃한 두 정점을 같이 못 고를 때, 고른 정점들의 가중치 합을 최대로.\
일반 그래프에서는 NP 난해하지만 **트리에서는 선형**이다.

> **트리(tree)** — 사이클(빙 돌아 제자리로 오는 길)이 없는 연결 그래프.\
> 예: 정점 n개면 간선이 n-1개다.

> **독립 집합(independent set)** — 서로 이웃(간선으로 직접 연결)인 정점이 하나도 없는 정점 모음.\
> 예: 아래 트리에서 {3, 4, 2}는 서로 이웃이 아니라 독립 집합이고, 합이 2+6+4 = 12다.

> ⚠ 정정(2026-09-28): 보통 "최대 독립 집합"은 정점 **개수**를 최대로 하는 문제다. 이 챕터(TreeDp.java의 `weight`)처럼 가중치 합을 최대로 하는 것은 "최대 가중 독립 집합"이다 — 트리에서는 둘 다 같은 DP로 선형에 풀린다.

> **NP 난해(NP-hard)** — 모든 경우를 다 보는 것보다 본질적으로 나은 방법이 알려지지 않은 어려움의 등급.\
> 예: 최대 독립 집합은 일반 그래프에서 NP 난해지만 트리에서는 선형이다.

> ⚠ 정정(2026-09-28): NP 난해의 정의는 "NP의 모든 문제를 다항 시간에 이 문제로 환원할 수 있음"이다. NP 난해 문제에도 완전 열거보다 빠른 지수 시간 해법이 있을 수 있고, 다항 시간 해법이 없다는 것도 증명되지 않았다(P≠NP 미해결) — 근거: CLRS 34장.

> **트리 DP(tree DP)** — 잎에서 뿌리로 올라가며 자식들의 답을 합쳐 정점의 답을 만드는 DP.\
> 예: 정점마다 "골랐다/안 골랐다" 두 칸을 두고 재귀의 되돌아오는 길에 채운다.

전 상태 — 예시 트리:

```text
        0(3)          괄호는 가중치
       /    \         0 을 고르면 1, 2 는 못 고른다
    1(5)    2(4)      1 을 고르면 0, 3, 4 는 못 고른다
    /  \
  3(2) 4(6)
```

단계 (그림 해설: 한 단계 한 문장):

- 상태를 정점마다 **두 칸**으로 잡는다: `표[v][0]` = v를 안 고른 경우의 최대합, `표[v][1]` = v를 고른 경우의 최대합.
- 잎에서 뿌리로 올라가며(재귀의 되돌아오는 길에) 채운다: **고르면** 자식들은 못 고르니 `가중치(v) + Σ 자식[0]`, **안 고르면** 자식은 자유니 `Σ max(자식[0], 자식[1])`.
- 무방향 간선이라 이웃 목록에 부모도 들어 있다 — `child == parent`를 걸러야 한다(안 거르면 무한 재귀).
- **답은 뿌리의 두 칸 중 큰 쪽** — `max(표[0][0], 표[0][1])`.\
  하나만 보면 틀린다.

후 상태 — 표가 채워진 모습:

```text
채우는 순서(잎부터):  3      4      1               2      0
표[v][0] (안 고름):   0      0      8 (=2+6)        0      12 (=max(8,5)+max(0,4))
표[v][1] (고름)  :    2      6      5 (=5+0+0)      4      11 (=3+표[1][0]+표[2][0]=3+8+0)

답 = max(표[0][0], 표[0][1]) = max(12, 11) = 12   (고른 것: 3, 4, 2 -> 2+6+4)
```

**비용**: 정점마다 두 칸, 간선마다 한 번씩 오르내림 = O(n).\
실측: 정점 20개에서 전부 시도는 재귀 28,655번, DP는 표 쓰기 40번(= 20×2) — 716배.\
전부 시도는 정점이 늘 때마다 약 1.6배씩 는다 — **피보나치 수열과 같은 증가율**("고른다/안 고른다" 두 갈래가 겹치며 그 수열이 나온다).

**왜 트리에서만 쉬운가**: 사이클이 없으므로 어떤 정점의 결정이 자기에게 돌아오지 않는다.\
그래서 자식들의 답을 독립적으로 합칠 수 있다 — 부분 문제가 안 겹친다.

> **메모이제이션 / 타뷸레이션** — 위에서 아래로 필요한 칸만 채우기 / 아래에서 위로 전부 채우기(21번 참조).\
> 예: TSP는 도달 가능한 23%만 채우려고 메모이제이션을 쓴다.

## 쓰이는 자료구조·알고리즘

- **DB 쿼리 옵티마이저** — 여러 테이블의 조인 순서를 "조인한 테이블 집합"을 상태로 DP로 고른다. System R(Selinger 외 1979)에서 정립된 대표적인 비용 기반 방식이다. 모든 옵티마이저가 같은 방식은 아니고, 테이블이 많으면 다른 탐색으로 바꾸기도 한다(예: PostgreSQL은 테이블 수가 `geqo_threshold` 이상이면 유전 알고리즘 GEQO).
- **배송·순회 경로** — 방문지가 적을 때의 정확한 최적 순회(비트마스크 TSP, 시간 O(n²2ⁿ)·공간 O(n2ⁿ)). 허용 상한은 시간·메모리 예산에 맞춰 정하고, 그보다 크면 근사·휴리스틱으로 넘어간다.
- **컴파일러 최적화** — 표현식 트리의 명령어 선택(타일링)과, 트리 모양 식을 평가할 때 필요한 레지스터 수 최적화(Sethi–Ullman)가 트리 DP다. 일반적인 전역 레지스터 할당(그래프 색칠 등)은 별개 문제다.
- **텍스트 처리** — 부분 문자열 `[i,j]`가 팰린드롬인지 판정하는 표는 구간 DP다. 팰린드롬 분할·줄바꿈 최적화(TeX의 Knuth–Plass)는 "마지막 조각을 어디서 자르나"를 고르는 접두 DP로, 행렬 곱 같은 두 구간 합치기와는 모양이 다르다.
- **비트마스크의 재료** — 집합을 정수로 다루는 연산은 [29-bit-manipulation](../29-bit-manipulation/2-summary.md)에서 따로 다룬다. 외판원은 거기서도 같은 코드가 나온다.
- **트리 DP의 재료** — 잎에서 뿌리로 올라가는 순서는 [12-dfs](../12-dfs/2-summary.md)의 "나올 때" 처리다.

## 적용 — 풀어나가는 법

실제 문제에 붙이는 순서: ① "무엇이 같으면 앞으로의 답이 같은가"를 찾는다 — 순서·경로는 버리고 집합·구간·위치만 남긴다 → ② 문제 모양으로 상태를 고른다(구간을 합치면 `[i,j]`, 거쳐 온 집합이 핵심이면 비트마스크, 트리면 (정점, 골랐나)) → ③ 상태 수 × 상태당 전이 수를 세어 시간·메모리 예산과 비교한다(비트마스크 TSP면 칸 2^n×n, 시간 2^n×n²) → ④ 채우는 순서를 정한다(읽히는 칸이 먼저 — 짧은 구간부터, 잎부터) → ⑤ 답의 위치를 확인한다(뿌리의 두 칸 중 큰 쪽, 전체 구간 칸).\

## 장애 시나리오와 대처

**1. 비트마스크 상태 공간 폭발로 OOM**

- 현상: 도시 20개까지는 되는데 25개에서 `OutOfMemoryError`.
- 보이는 형태: 표 크기 2^n × n — n=25면 8억 칸을 잡는 순간 죽는다.
- 원인: 비트마스크 DP는 (n-1)!을 2^n 수준(시간 O(n²2ⁿ))으로 줄인 것이지 다항으로 만든 것이 아니다.
- 대처: n 상한을 문서와 입력 검증에 박는다 — 원본 impl javadoc은 "n이 20을 넘으면 못 쓴다"고 적었다(TravelingSalesman.java:16). 이 20은 그 구현의 어림이고, 실제 상한은 표 원소 크기·메모리·시간 제한에 따라 정한다. 그 이상은 근사·휴리스틱으로 바꾼다(MST 2배 순회의 2-근사는 삼각부등식을 만족하는 metric TSP에서만 보장된다).

**2. 원래 `mask`를 고쳐 형제 갈래가 오염됨**

- 현상: TSP 답이 실제보다 크거나 일부 도시를 못 간다.
- 보이는 형태: 같은 입력에서 재귀 순서에 따라 답이 달라진다.
- 원인: `mask |= 1 << next`처럼 원래 값을 바꾸면 되돌아온 뒤 다른 갈래가 "이미 간 것"으로 본다.
- 대처: `mask | (1 << next)`로 새 값을 만들어 넘긴다. 작은 입력(도시 4~6개)을 전부 시도와 대조하는 테스트를 둔다.

**3. 구간 DP를 `i` 증가 바깥 루프로 채워 빈 칸을 읽음**

- 현상: 행렬 곱 최소 비용이 0이나 작은 값으로 나온다.
- 보이는 형태: `[i, j]`가 `[k+1, j]`를 읽는데 그 칸이 아직 0이다. 예외는 없다.
- 원인: 긴 구간이 짧은 구간을 읽으므로, 읽히는 하위 구간이 먼저 채워져야 한다. `i`를 0부터 늘리면 `[k+1, j]`(더 큰 `i`)가 아직 비어 있다.
- 대처: 바깥 루프를 구간 길이로 두거나, `i`를 큰 쪽에서 줄이고 안쪽 `j`를 늘린다 — 둘 다 의존 순서를 지킨다. 15번 플로이드의 k 루프와 같은 종류의 실수다.

**4. 트리 DP에서 부모를 안 걸러 무한 재귀**

- 현상: `StackOverflowError`.
- 보이는 형태: 무방향 트리에서 자식 → 부모 → 자식 → …으로 되돌아간다.
- 원인: 인접 리스트에 부모도 들어 있다.
- 대처: `child == parent`를 건너뛴다. 답은 뿌리의 두 칸 중 큰 쪽이라는 것도 같은 자리에서 확인한다.

## 핵심 문장

- 21번은 "표를 쓰면 빨라진다"를 쟀고, 여기서는 "상태를 어떻게 잡느냐"를 잰다 — 상태를 잘못 잡으면 표를 써도 지수를 못 벗어난다.
- 순서가 달라도 "지나온 집합과 현재 위치"가 같으면 미래가 같다 — 그 관찰 하나가 (n-1)!을 2^n×n으로 줄인다.
- 구간 DP는 "마지막에 어디를 자르나"가 문제를 양쪽으로 쪼갠다 — 그래서 짧은 구간부터 채워야 한다.
- 트리는 사이클이 없어 결정이 자기에게 돌아오지 않는다 — NP 난해한 문제가 트리 위에서는 선형이 되는 이유.
- 상태를 넓게 잡을수록 도달 불가능한 칸의 비율이 커진다(배낭 56% → TSP 23%) — 타뷸레이션이면 그 빈 칸까지 전부 채운다.

### 용어 풀이

- **상태(state)**: "지금 상황"을 요약한 값 묶음.\
  상태가 같으면 앞으로의 답도 같아야 한다.
- **구간 DP(interval DP)**: 상태를 구간 [i, j]로 잡고, 마지막에 자를 자리를 전부 시도해 양쪽 답을 합치는 DP.
- **비트마스크(bitmask)**: 집합을 정수 하나의 2진 비트로 표현하는 기법.\
  i번 원소가 있으면 i번째 비트가 1.
- **비트 연산**: `mask | (1 << i)` = i를 집합에 넣은 새 값, `mask & (1 << i)` = i가 집합에 있는지 확인.
- **외판원 순회(TSP, traveling salesman problem)**: 모든 도시를 한 번씩 들르고 출발지로 돌아오는 최소 비용 경로 문제.
- **트리(tree)**: 사이클이 없는 연결 그래프.\
  정점 n개면 간선 n-1개.
- **트리 DP(tree DP)**: 잎에서 뿌리로 올라가며 자식들의 답을 합쳐 정점의 답을 만드는 DP.
- **독립 집합(independent set)**: 서로 이웃인 정점이 없는 정점들의 모음.\
  "최대"는 가중치 합 기준.
- **NP 난해(NP-hard)**: 사실상 모든 경우를 보는 것 이상의 방법이 알려지지 않은 문제 등급.\
  트리 같은 특수 구조에서는 쉬워질 수 있다.
- **메모이제이션 / 타뷸레이션**: 위에서 아래로 필요한 칸만 / 아래에서 위로 전부 채우기 (21번 참조).
- **도달 불가능한 상태**: 문제 규칙상 생길 수 없는 (상태) 조합.\
  메모이제이션은 안 채우고 타뷸레이션은 모르고 채운다.
- **n!(팩토리얼)**: 1×2×…×n.\
  순서(순열)의 개수.\
  12개 도시의 방문 순서가 11! = 약 4천만.
- **2^n**: 원소 n개의 부분집합 개수.\
  비트마스크 상태 수의 뼈대.\
  n=20이면 약 백만.

> ⚠ 정정(2026-09-28): 위 용어 풀이 중 — 독립 집합의 "최대"는 보통 정점 개수 기준이고 가중치 합 기준은 "최대 가중 독립 집합"이다. NP 난해는 "NP의 모든 문제가 다항 시간에 환원되는 문제"로 정의한다. 타뷸레이션도 도달 불가능한 상태를 건너뛰게 짤 수 있다. n=20 경계는 원본 impl의 어림이다.
