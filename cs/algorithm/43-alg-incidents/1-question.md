# algorithm/43-alg-incidents — 질문

## 질문

1. (왜) 세 사건(Bloch 2006, Stack Overflow 2016, Cloudflare 2019)은 각각 어떤 가정이 깨진 것인가? 셋 모두 평소 테스트로 잡히지 않은 공통 이유는?
2. (계산) 이진 탐색 루프 안에서 `0 <= low <= high <= n - 1`일 때 `low + high`가 넘칠 수 있는 최소 n은? 실험 D의 출력으로 확인하고, Bloch 원문의 "2^30 or greater"와 비교하라.
3. (구분) `(low + high) / 2`, `(low + high) >>> 1`, `low + (high - low) / 2`를 실험 D 마지막 줄의 값으로 비교하라. `>>> 1`이 맞는 이유는? C에서는 왜 Bloch가 2008년에 수정을 덧붙였나?
4. (사실) Stack Overflow 사후 보고서가 적은 장애 시간·원인 파악·수정 작성·배포 시간은? 정규식 하나가 사이트 전체 장애가 된 경로를 단계별로 말하라.
5. (예측) 실험 E에서 공백 2만 개와 4만 개의 `\s+$` 시간은? 두 배에 몇 배였고, 원문이 말한 차수와 맞나? 원문의 확인 횟수 합과 실험 마지막 줄의 합이 다른 점도 짚어라.
6. (그림) `.*.*=.*`에 `=`가 없는 길이 n 입력을 `find()`하면 왜 약 O(n³)인가? Cloudflare 원문의 단계 수 표(23·33·45·555·4,067·90·5,353)에서 무엇을 읽을 수 있나?
7. (예측) 실험 F에서 `[^=]*=`는 n 두 배마다 몇 배였나? 겹침을 없앴는데도 선형이 아닌 이유는? "어딘가에 `=`가 있나"가 의도라면 무엇을 쓰나?
8. (장애 진단) 규칙 변경이 리뷰·CI를 통과하고 배포된 직후 CPU가 치솟는다. 덤프와 입력으로 정규식 폭주를 확인하는 순서, 그리고 다시 막을 테스트를 말하라.
9. (경계) 백트래킹 폭주를 막으려고 RE2 계열 엔진으로 바꿀 때 생기는 문제는? 전환 전에 무엇을 확인하나?
10. (연결) 세 사건에서 알고리즘 결함의 크기보다 피해를 키운 "노출 범위"는 각각 무엇이었나? [data-structure/44-ds-incidents](../../data-structure/44-ds-incidents/2-summary.md)의 HashDoS와 같은 모양인 점을 하나 들어라.
