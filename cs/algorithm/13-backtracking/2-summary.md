## 한눈에 — 쉽게 말하면

**백트래킹 = 스도쿠 풀기: 칸에 숫자를 넣어보고, 모순이 생기면 지우개로 지우고 다른 숫자.**

- 한 칸씩 **골라 넣고**(선택), 더 못 가면 **지우고 되돌아가**(되돌리기), 다음 후보를 넣는다. 이 "넣기-내려가기-지우기"의 반복이 백트래킹의 전부다.
- 모든 경우를 다 만들어보는 것과 다른 점은 **가지치기**: "이 칸에 5를 넣으면 벌써 모순"임을 알면 그 아래 수백만 가지 경우를 통째로 안 만든다.
  - *가지치기(pruning)*: 나무(탐색 트리)에서 가망 없는 가지를 미리 잘라내는 것.
- 이 박스의 주제는 **"언제 자르느냐"가 전부**라는 것. 답은 같고 만드는 노드 수만 다르다 — 놓기 전에 검사하는 판과 다 놓은 뒤에 검사하는 판이 n=8에서 53배 차이 난다.
- 실무 예: 스도쿠·N퀸 솔버, 시간표 짜기, 조합 생성(테스트 케이스 만들기), 퍼즐류 전반.

```text
탐색 트리: 한 층 = 한 칸의 선택

            (빈 판)
          /    |    \
        1      2      3       <- 1번 칸의 후보
       / \    / \    / \
      2   3  1   3  1   2     <- 2번 칸의 후보
      |   |  |   |  |   |
      3   2  3   1  2   1     <- 3번 칸: 잎(완성)

내려가며 "넣기", 올라오며 "지우기". 가지치기 = X 표시된 가지를 통째로 생략.
```

세 가지를 다룬다: 순열(`permutations`), 조합(`combinations`), N퀸(`NQueens` — 가지치기 판과 걸러내기 판을 나란히).

## 전체 흐름

```text
solve(depth):
   depth 가 끝까지 왔으면 -> 답 하나 완성 (기록하고 돌아감)
   depth 번째 자리의 후보를 하나씩:
      (가지치기 판) 넣어도 되는지 먼저 검사 -> 안 되면 다음 후보
      후보를 넣는다
      solve(depth + 1)          <- 다음 자리로 내려감
      후보를 뺀다                <- 되돌리기! 빠뜨리면 다음 가지가 흔적을 물려받는다
```

핵심 계약 둘(원본 테스트가 실제로 확인): **탐색이 끝나면 판이 비어 있다**, **놓기 횟수 = 되돌리기 횟수**.

## 동작 — permutations (순열)

**언제 쓰나**: n개를 순서 있게 나열하는 모든 방법이 필요할 때. 후보 규칙 = **아직 안 쓴 것 전부**(`used[]` 배열로 기억).

  - *순열(permutation)*: 순서를 따지는 나열. [0,1,2]와 [2,1,0]은 다른 답. 개수는 n! 개.
  - *n!(팩토리얼)*: n × (n-1) × … × 1. 3! = 6, 8! = 40,320. 무섭게 빨리 커진다.

전 상태 (n=3):

```text
current = [_, _, _]    used = [F, F, F]
```

단계 (첫 답이 나오기까지, 이후는 되돌리며 반복):

```text
depth0: 0 넣음        current=[0,_,_]  used=[T,F,F]
depth1: 0은 사용중, 1 넣음   current=[0,1,_]  used=[T,T,F]
depth2: 2 넣음        current=[0,1,2]  -> depth==n, 답 기록!
        2 뺌, 1 뺌 (되돌리기) -> depth1 에서 다음 후보 2 넣음
depth2: 1 넣음        current=[0,2,1]  -> 답 기록!
        ... 같은 방식으로 계속
```

후 상태:

```text
[0,1,2] [0,2,1] [1,0,2] [1,2,0] [2,0,1] [2,1,0]   — 6개(=3!), 사전순
```

구현에서 중요한 결정 둘(원본 코드 그대로):

1. **답을 기록할 때 `current.clone()`을 넣는다.** 작업용 배열을 그대로 넣으면 결과 전부가 같은 배열 하나를 가리켜, 개수는 맞는데 내용이 마지막 것 하나뿐이 된다.
2. **`used[v] = false` 되돌리기를 빠뜨리면** 다음 가지가 앞 가지의 흔적을 물려받는다.

그리고 **n=0의 답은 1이다**(빈 나열 하나). 0이라고 답하면 재귀의 바닥을 잘못 잡은 것이다.

**비용**: 답이 n!개라서 O(n! × n) (답 하나 복사가 n). 만들 수 있는 한계가 낮다 — 20!은 약 243경(2.4 × 10^18)이라 아예 못 만든다.

## 동작 — combinations (조합)

**언제 쓰나**: n개 중 k개를 **순서 없이** 고르는 모든 방법. 후보 규칙 = **마지막에 고른 것보다 뒤에 있는 것만**(`start` 인자). 순열과 뼈대는 완전히 같고 이 한 줄만 다르다 — 그 한 줄이 n!을 C(n,k)로 만든다.

  - *조합(combination)*: 순서를 안 따지는 고르기. {0,1}과 {1,0}은 같은 답. 개수는 C(n,k).

전 상태 (n=4, k=2):

```text
current = [_, _]     start = 0
```

단계:

```text
depth0 에서 0 고름 -> depth1 은 1부터: [0,1] [0,2] [0,3]
depth0 에서 1 고름 -> depth1 은 2부터: [1,2] [1,3]
depth0 에서 2 고름 -> depth1 은 3부터: [2,3]
depth0 에서 3 고름 -> 남은 자리 1개인데 후보 없음 -> 가지 자체를 안 만듦
```

후 상태:

```text
[0,1] [0,2] [0,3] [1,2] [1,3] [2,3]   — 6개(=C(4,2)), 오름차순·사전순
```

마지막 줄이 원본의 가지치기 상한 `v <= n - (k - depth)`다: **남은 자리보다 후보가 적으면 어차피 못 채우니 그 가지를 안 만든다.**

**규모 감각**(원본 README): 20개의 순열 = 20! = 2,432,902,008,176,640,000 — 만들 수 없다. 20개에서 3개 조합 = C(20,3) = 1,140 — 금방 끝난다. **다른 것은 "다음에 무엇을 고를 수 있나" 한 줄뿐이다.**

**비용**: O(C(n,k) × k). 상한 가지치기 덕에 못 채울 가지는 아예 안 내려간다.

## 동작 — NQueens: 가지치기 판 (놓기 전에 검사)

**언제 쓰나**: n×n 체스판에 퀸 n개를 서로 못 잡게(같은 행·열·대각선 금지) 놓는 방법의 수. 행마다 하나씩 놓으므로 "r행의 퀸을 몇 열에 놓나"만 정하면 된다.

  - *퀸(queen)*: 체스 말. 가로·세로·대각선으로 무한히 간다.

전 상태 (n=4, 행 0·1에 이미 놓은 장면):

```text
     열0  열1  열2  열3
행0 |    | Q  |    |    |    queenCol = [1, 3, _, _]
행1 |    |    |    | Q  |
행2 |    |    |    |    |    <- 지금 여기 놓을 자리를 고르는 중
행3 |    |    |    |    |
```

단계 (행 2의 후보를 하나씩 **놓기 전에** 검사):

```text
열0: 행0의 Q(열1)와 대각선? |1-0|=1, 행차 2 -> 아님. 행1의 Q(열3)와? |3-0|=3, 행차 1 -> 아님. 통과!
열1: 열이 행0의 Q와 겹침 -> 자름 (이 아래 가지를 아예 안 만든다)
열2: 행1의 Q(열3)와 |3-2|=1 = 행차 1 -> 대각선 -> 자름
열3: 열이 행1의 Q와 겹침 -> 자름
-> 열0 에만 놓고 행 3으로 내려감. 행3도 다 막히면 행2의 퀸을 지우고 되돌아감
```

대각선 판정 한 줄: **행 차이의 절댓값 = 열 차이의 절댓값이면 같은 대각선.** 같은 행은 검사할 필요가 없다 — 행마다 하나씩만 놓으니까.

후 상태 (n=4의 답):

```text
|    | Q  |    |    |        |    |    | Q  |    |
|    |    |    | Q  |        | Q  |    |    |    |
| Q  |    |    |    |        |    |    |    | Q  |
|    |    | Q  |    |        |    | Q  |    |    |
[1,3,0,2]                    [2,0,3,1]              — 답 2개
```

**비용**: 최악은 지수적이지만 가지치기가 실제 노드 수를 크게 줄인다. n=8에서 놓기 2,056번(아래 비교표). n=0의 답도 1이다 — "아무것도 안 놓는 방법" 하나가 조건을 만족한다.

## 동작 — NQueens: 걸러내기 판 (다 놓은 뒤에 검사)

**언제 쓰나**: 대조용. 열 순열을 전부 만들고(열이 겹치는 배치는 애초에 안 만든다 — 순열이므로 n^n이 아니라 n!), **다 놓은 뒤에** 대각선만 확인한다.

```text
n! 개의 열 배치를 전부 완성 -> 잎에서 isFullySafe() 한 번 검사 -> 통과한 것만 센다

가지치기 판:  트리 중간중간에서 자름   (놓기 적음, 검사 많음)
걸러내기 판:  잎에서만 검사            (놓기 = n! 근처, 검사 = 잎마다 1번)
```

**비용**: n!개를 다 만드니 O(n! × n). 답은 가지치기 판과 완전히 같다 — **다른 것은 비용뿐이다.**

## 비교 — 언제 자르느냐가 전부다 (원본 README의 실측)

**하나. 놓기 횟수 — 격차가 n에 따라 벌어진다.**

| n | 놓기(가지치기) | 놓기(걸러내기) | 배수 |
|---|---|---|---|
| 6 | 152 | 1,956 | 12 |
| 8 | 2,056 | 109,600 | 53 |
| 9 | 8,393 | 986,409 | 117 |

걸러내기는 n!을 따라가고 가지치기는 훨씬 느리게 는다. 걸러내기도 바보는 아닌데(열 겹침은 애초 배제) **대각선 충돌을 마지막에야 알기 때문에** 진다.

**둘. 그런데 검사 횟수로 보면 작은 n에서는 가지치기가 진다.**

| n | 검사(가지치기) | 검사(걸러내기) |
|---|---|---|
| 6 | 894 | 720 |
| 8 | 15,720 | 40,320 |

가지치기는 노드마다 검사, 걸러내기는 잎에서 한 번만(정확히 n!번 — n=8에서 40,320 = 8!). n이 작으면 잎이 적어 "잎에서만 검사"가 싸고, n이 커지면 잎이 n!로 폭발해 뒤집힌다. **"가지치기가 항상 낫다"가 아니라 "무엇을 세느냐와 n이 얼마냐에 달렸다."**

**셋. 백트래킹의 비용은 자료구조에 안 남는다.** 만들었다가 되돌리니까. 그래서 원본 `CountedBoard`가 놓기·되돌리기·충돌 검사를 따로 센다.

**변종.** 조합의 `if (k > n) return 빈목록` 가드를 지웠더니 테스트가 안 깨졌다 — 가지치기 상한 `v <= n-(k-depth)`가 k>n이면 처음부터 음수라 루프가 안 돈다. 가드가 하려던 일을 이미 하고 있었다. 07번(`need<=0`), 12번(자기 간선)에 이어 세 번째: **테스트가 안 깨지는 방어 코드는 검증이 부족하거나 필요 없거나 둘 중 하나다.**

## 핵심 문장

- 백트래킹 = 넣고, 내려가고, **지우고**(되돌리기) — 되돌리기를 빠뜨리면 다음 가지가 앞 가지의 흔적을 물려받는다.
- 답은 같고 만드는 노드 수만 다르다: **언제 자르느냐**(놓기 전 검사 vs 다 놓고 검사)가 비용의 전부다.
- 순열과 조합은 뼈대가 같고 "다음에 무엇을 고를 수 있나" 한 줄만 다르다 — 그 한 줄이 n!과 C(n,k)를 가른다.
- 결과에는 작업용 배열의 **복사본**을 넣는다. 그대로 넣으면 개수만 맞고 내용은 하나뿐이다.
- n=0의 답은 1이다 — "아무것도 안 고르는 방법" 하나. 0이면 재귀 바닥을 잘못 잡은 것.

## 용어 풀이

- **백트래킹(backtracking)**: 한 자리씩 선택하며 내려가다 막히면 선택을 지우고 되돌아와 다른 후보를 시도하는 탐색.
- **탐색 트리(search tree)**: 선택의 갈래를 나무로 그린 것. 한 층 = 한 자리의 선택, 잎 = 완성된 답 후보.
- **잎(leaf)**: 탐색 트리의 맨 끝 — 모든 자리를 다 채운 상태.
- **가지치기(pruning)**: 조건을 이미 어긴 가지를 내려가기 전에 잘라 그 아래 전체를 생략하는 것.
- **걸러내기(filtering)**: 일단 끝까지 다 만든 뒤 잎에서 조건 검사로 거르는 방식. 대조군.
- **되돌리기(undo)**: 재귀에서 올라올 때 방금 한 선택을 지워 판을 원상복구하는 것. 놓기 수 = 되돌리기 수.
- **순열(permutation)**: 순서 있는 나열. n개 전부 나열하면 n!개.
- **조합(combination)**: 순서 없는 고르기. n개 중 k개면 C(n,k)개.
- **n!(팩토리얼)**: n × (n-1) × … × 1. 8! = 40,320, 20!은 약 243경 — 지수보다도 빨리 큰다.
- **C(n,k)**: n개에서 k개를 고르는 경우의 수. C(20,3) = 1,140.
- **N퀸(N-Queens)**: n×n 판에 퀸 n개를 서로 못 잡게 놓는 문제. 백트래킹의 고전.
- **대각선 판정**: 두 칸이 같은 대각선 위 ⇔ 행 차이의 절댓값 = 열 차이의 절댓값.
- **depth(깊이)**: 지금 몇 번째 자리를 채우는 중인지. depth == 끝이면 답 하나 완성.
- **used 배열**: 순열에서 "이미 쓴 숫자"를 기억하는 표시판.
- **clone(복사본)**: 배열을 새로 떠서 넣는 것. 참조만 넣으면 전부 같은 배열을 가리킨다.
- **죽은 코드(dead code)**: 지워도 동작이 안 변하는 코드. 변종 테스트(지워보기)로 드러난다.
- **지수적(exponential)**: n이 1 늘 때마다 일이 몇 배씩 불어나는 증가. 가지치기가 싸우는 대상.
