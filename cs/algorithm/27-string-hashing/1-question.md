### A. 과제 (RollingHash·RabinKarp·DuplicateSubstring — TODO 1~6)

#### 1. 롤링 해시 (`RollingHash` — TODO 1~3)

```java
/**
 * TODO 1. 문자열 전체의 해시.
 *   호너 방식으로 왼쪽부터 접는다. h = h * BASE + 글자, 매번 mod.
 */
public long hash(String s)

/**
 * TODO 2. B^power mod m.
 *   창을 옮길 때 맨 앞 글자의 기여를 빼려면 이 값이 필요하다.
 *   창 길이가 m 이면 맨 앞 글자에는 B^(m-1) 이 곱해져 있다.
 */
public long basePower(int power)

/**
 * TODO 3. 창을 한 칸 옮긴 해시.
 *   나가는 글자의 기여를 빼고, BASE 를 곱하고, 들어오는 글자를 더한다.
 *   함정. 빼기에서 음수가 나올 수 있다.
 *   자바의 % 는 음수를 그대로 돌려주므로 mod 를 더해 양수로 만들어야 한다.
 *   몇 번 더해야 하는지는 빼는 값의 범위를 보고 정하면 된다.
 */
public long roll(long hash, char outgoing, char incoming, long topPower)
```

- 해시를 `s[0]*B^(m-1) + ... + s[m-1]` 로 정의하는 것은 무엇에 비유되는가?
- 법(mod)으로 나눈 나머지를 들고 다니는 이유는 무엇이고, 그 대가로 무엇이 생기는가?
- 창 길이가 m 일 때 맨 앞 글자에 곱해진 자릿값이 `B^m` 이 아니라 `B^(m-1)` 인 이유는?
- 창을 한 칸 옮기는 세 단계(빼기·곱하기·더하기)는 각각 무엇을 하는 것인가?
- 자바의 `%` 가 음수를 그대로 준다는 것은 어디서 문제가 되고, 어떻게 고치는가? (원본 TODO 3)
- `+ mod` 를 한 번만 더해도 반드시 충분한 이유는? (원본 함정)
- 넉넉하게 `mod*mod` 를 더하면 무엇이 문제인가? (원본 함정)
- 굴리기가 창 길이를 비용에서 없앤다는 말은 무슨 뜻인가?
- 이 구조는 10 번 누적 합의 무엇과 같은가?

#### 2. 라빈 카프 (`RabinKarp.findAll` — TODO 4)

```java
/**
 * TODO 4. 패턴이 나타나는 모든 시작 위치.
 *   1. 빈 패턴은 0 부터 n 까지 모든 자리. 패턴이 본문보다 길면 빈 목록
 *   2. 패턴 해시와 첫 창 해시를 구한다. topPower = basePower(m-1)
 *   3. 창마다 hasher.compareHash() 후 해시를 비교
 *   4. 같으면 hasher.compareFull() 하고 text.startsWith(pattern, start) 로 확인
 *      실제로 다르면 hasher.collision()
 *   5. 마지막 창이 아니면 roll 로 한 칸 옮긴다
 */
public static List<Integer> findAll(String text, String pattern, long mod, CountedHasher hasher)
```

- 법이 10 억(10^9+7)이어도 충돌 쌍이 존재한다는 사실이 시사하는 것은?
- 입력을 남이 고를 수 있는 상황에서 확률 이야기가 의미 없는 이유는?
- KMP(25 번)와 비교해 라빈 카프는 무엇을 내주고 무엇을 얻는가?

#### 3. 가장 긴 중복 부분 문자열 (`DuplicateSubstring` — TODO 5~6)

```java
/**
 * TODO 5. 두 번 이상 나오는 가장 긴 부분 문자열. 없으면 빈 문자열.
 *   길이 1 부터 n-1 까지 이분 탐색한다.
 *   duplicateOfLength 가 찾으면 그것을 기억하고 더 긴 쪽으로, 못 찾으면 짧은 쪽으로.
 */
public static String longest(String s, long mod, CountedHasher hasher)

/**
 * TODO 6. 길이 length 짜리로 두 번 나오는 것이 있으면 그것을 준다. 없으면 null.
 *   해시별로 시작 위치 목록을 들고 간다. Map(Long, List(Integer)) 이다.
 *   왜 목록인가. 해시가 같아도 문자열이 다를 수 있어서다.
 *   비교할 때 s.regionMatches(other, s, start, length) 를 쓴다.
 *   substring 을 만들면 O(L) 이 또 든다.
 */
static String duplicateOfLength(String s, int length, long mod, CountedHasher hasher)
```

- 길이에 대한 이분 탐색이 성립하는 단조성은 무엇인가?
- 해시맵의 값이 위치 하나가 아니라 위치 **목록**이어야 하는 이유는? (원본 TODO 6)
- 비교에 `substring` 대신 `regionMatches` 를 쓰는 이유는? (원본 TODO 6)
- 전체 비용 O(n log n) 은 어떻게 나오고, 해시가 없으면 얼마가 되는가?
- 이분 탐색과 굴리기 둘 중 하나만 있으면 왜 안 되는가? (원본 측정 다섯)
- 이분 탐색 상한을 `hi = n-1` 에서 `hi = n` 으로 바꿔도 테스트가 통과하는데 왜 결함이 아닌가? (원본 변종 검증)
