# algorithm/34-modern-codecs-lz4-zstd-brotli — 질문

## 질문

1. (왜) DEFLATE가 있는데 LZ4·zstd·Brotli가 왜 따로 생겼나? 각 코덱이 밀어붙인 축(속도·비율·작은 데이터·웹 텍스트)과 그 수단을 하나씩 대라.
2. (예측) zstd 레벨을 `--fast=4` → `-19`로 올리면 압축 시간, 압축 크기, 해제 시간은 각각 어떻게 변할까? 실험(notes.txt 3.5MB)의 숫자로 확인하라. 레벨을 올렸는데 오히려 커지는 일도 있었나?
3. (그림) LZ4 시퀀스 하나(token·리터럴·offset·매치 길이)를 그려라. LZ4가 빠른 이유를 형식 관점에서 두 가지 대라. offset 최대값과 최소 매치 길이는?
4. (경계) 한 기호가 90%인 원천에서 허프만은 기호당 몇 비트이고 rANS는 몇 비트였나? 50%·50%이면? ANS 디코딩이 인코딩과 반대 방향인 이유를 상태 관점에서 설명하라.
5. (예측) 175바이트 JSON 로그 1,000개를 ① 하나씩 zstd -3 ② 학습 사전 + 하나씩 ③ 1,000개를 모아 한 번에 압축하면 비율이 각각 어느 정도일까? 왜 그런 순서가 나오나?
6. (연결) zstd 프레임 헤더에는 무엇이 적히나(매직·윈도·사전 ID·원래 크기·체크섬)? 파이프로 압축한 프레임에서 `Decompressed Size`가 사라진 이유는? 해제 쪽에 어떤 영향이 있나?
7. (연결) Brotli의 정적 사전과 문맥 모델링은 각각 무엇을 하나? 이것이 짧은 HTML·JS에 특히 유리한 이유는? Brotli CLI의 기본 품질은 얼마이고, 그것이 왜 운영 함정이 되나?
8. (장애 진단) 사전을 새로 학습해 생산자에 배포한 직후 일부 소비자가 `Decoding error (36) : Dictionary mismatch`를 낸다. 원인과 안전한 배포 순서, 보관 정책을 설명하라.
9. (장애 진단) 백업을 `zstd --long=30`으로 압축했더니 크기가 33MB → 1.65MB로 줄었다. 그런데 복구 서버에서 `Frame requires too much memory for decoding`이 난다. 무엇이 일어났고 어떻게 대처하나? 해제 메모리 상한을 그냥 크게 올리면 안 되는 이유는?
10. (장애 진단) API 서버에 동적 JSON 응답용 Brotli(또는 zstd -19)를 켠 뒤 CPU가 포화되고 p99가 뛰었다. 확인할 것과 바꿀 설정을 대라. 정적 자원은 어떻게 다루나?
