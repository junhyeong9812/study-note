### A. 과제 (AhoCorasick — TODO 1\~7)

#### 1. 트라이 만들기 (`build` — TODO 1)

**impl 정답 코드**

```java
public static CountedAutomaton build(List<String> patterns, CountedAutomaton automaton) {
    for (int p = 0; p < patterns.size(); p++) {
        int node = 0;
        for (char ch : patterns.get(p).toCharArray()) {
            int c = ch - 'a';
            if (automaton.edge(node, c) == -1) {
                automaton.setEdge(node, c, automaton.addNode());
            }
            node = automaton.edge(node, c);
        }
        automaton.addOutput(node, p);
    }
    linkFailures(automaton);
    return automaton;
}
```

> **트라이(trie)** — 글자를 한 자씩 따라 내려가는 나무 모양 사전.\
> 예: 앞부분(접두사)이 같은 단어들이 길을 공유해서 노드 수가 준다 — `he` 와 `hers` 는 `h → e` 를 함께 쓴다.

- Q: 글자를 0\~25 로 바꾼다는 것은 입력에 대해 무엇을 전제하는가?\
  A: 알파벳이 소문자 `a`\~`z` 26 종류뿐이라는 전제다.\
  `ch - 'a'` 로 글자를 배열 인덱스로 바꿔 노드마다 길이 26 간선 배열을 쓴다.\
  이 전제가 깨지면(유니코드) 배열 방식이 안 된다 — B.4 두 번째 질문이 그 얘기다.

- Q: 간선이 있을 때와 없을 때 각각 무엇을 하는가?\
  A: 있으면 그 간선을 따라 내려간다(길 공유).\
  없으면 `addNode()` 로 노드를 새로 만들어 간선을 걸고 내려간다.\
  그래서 앞부분이 같은 패턴들은 같은 길을 쓰고, 갈라지는 지점부터만 새 노드가 생긴다.

- Q: 패턴이 끝나는 노드에는 무엇을 기록하고, 그것이 나중에 어디에 쓰이는가?\
  A: 그 패턴의 번호를 출력 목록에 기록한다(`addOutput(node, p)`).\
  `findAll` 이 어떤 노드에 도착했을 때 그 노드의 출력 목록을 전부 결과에 담는다.\
  실패 링크를 건 뒤에는 물려받은 출력(겹쳐 끝나는 패턴)도 이 목록에 합쳐져 있다.

> **출력 목록(output)** — 그 노드에서 끝나는 패턴들의 번호 목록.\
> 예: `findAll` 은 도착한 노드의 출력 목록을 전부 결과에 담는다 — 물려받은 것까지 포함해서.

- Q: 같은 패턴이 두 번 들어오면 어떻게 되는가?\
  A: 두 번째는 이미 있는 길을 끝까지 따라 내려가 같은 노드에 도착한다.\
  거기서 `addOutput` 이 한 번 더 불려 같은 노드에 번호가 두 개(p 와 p') 기록된다.\
  그러면 그 자리에 도착할 때마다 매칭이 두 건씩 나온다 — 입력 중복이 결과 중복이 된다.

- Q: 서로 다른 패턴 여러 개가 한 노드에서 끝나는 입력은 어떤 모양인가?\
  A: 철자가 완전히 같은 두 패턴이 아니라면, **트라이 노드 자체는** 철자당 하나라 서로 다른 철자가 같은 노드에서 끝나지는 않는다.\
  하지만 출력 물려받기까지 합치면 얘기가 달라진다 — `she` 노드는 실패 링크 대상인 `he` 의 출력을 물려받아 출력이 두 개가 된다.\
  즉 "한 노드에 여러 패턴" 은 접미사 관계(she 의 꼬리 = he 전체)에서 나온다.

> **접두사(prefix) / 접미사(suffix)** — 문자열의 머리 부분 / 꼬리 부분.\
> 예: `"she"` 의 접미사 `"he"` 가 패턴 `"he"` 의 접두사(전체)와 겹치는 것이 출력 물려받기의 핵심이다.

- Q: `he` 와 `hers` 는 트라이에서 무엇을 공유하는가?\
  A: 접두사 `h → e` 두 노드(길)를 공유한다.\
  `hers` 는 `e` 밑에 `r`, `s` 두 노드만 더 판다.\
  이 공유가 노드 수를 "패턴 글자 수 합"보다 작게 만든다 — 실측에서 5,000 글자가 967 노드였다.

- Q: 트라이 만들기의 비용은 무엇에 비례하는가?\
  A: 패턴 길이 합 m 에 비례한다 — O(m).\
  글자 하나당 간선 하나를 따라가거나 만들 뿐이다.\
  (실패 링크 걸기까지 포함하면 간선 표를 채우느라 O(m × 26) 이 된다.)

#### 2. 실패 링크 걸기 (`linkFailures` — TODO 3\~6)

**impl 정답 코드**

```java
private static void linkFailures(CountedAutomaton automaton) {
    Deque<Integer> queue = new ArrayDeque<>();

    // 깊이 1 의 실패 링크는 전부 뿌리다.
    for (int c = 0; c < CountedAutomaton.ALPHABET; c++) {
        int child = automaton.edge(0, c);
        if (child == -1) {
            automaton.setEdge(0, c, 0);
        } else {
            automaton.setFailure(child, 0);
            queue.add(child);
        }
    }

    while (!queue.isEmpty()) {
        int node = queue.poll();
        // 실패 링크가 가리키는 곳의 출력을 물려받는다.
        for (int p : automaton.outputOf(automaton.failureOf(node))) {
            automaton.addOutput(node, p);
        }

        for (int c = 0; c < CountedAutomaton.ALPHABET; c++) {
            int child = automaton.edge(node, c);
            int fallback = automaton.edge(automaton.failureOf(node), c);
            if (child == -1) {
                // 없는 간선은 실패 링크 쪽으로 이어둔다.
                automaton.setEdge(node, c, fallback);
            } else {
                automaton.setFailure(child, fallback);
                automaton.hopFailure();
                queue.add(child);
            }
        }
    }
}
```

```
내 실패 링크 = "부모의 실패 링크에서 같은 글자로 간 곳"

    부모 node ──(글자 c)──> child
      |
      | 실패 링크 (이미 완성돼 있어야 한다!)
      v
    fail(node) ──(글자 c)──> fallback   =  child 의 실패 링크

    she 의 e:  부모 = sh, fail(sh) = h(깊이 1),  h 에서 e 로 가면 = he 의 e
               -> fail(she 의 e) = he 의 e     "she"의 꼬리 "he" = he 의 머리
```

- Q: 실패 링크는 어디로 가는 링크인가(한 문장으로)?\
  A: "지금까지 맞춘 것의 접미사이면서 어떤 패턴의 접두사인 **가장 긴** 것" 으로 간다.\
  다음 글자로 갈 길이 없을 때, 맞춘 것을 최소한만 버리고 이어가려는 점프다.\
  25 번 KMP 실패 함수를 트라이 위로 올린 것이다.

> **실패 링크(failure link)** — 다음 글자로 갈 길이 없을 때 점프할 곳.\
> 예: `she` 의 `e` 는 `he` 의 `e` 로 간다 — `"she"` 의 꼬리 `"he"` 가 어떤 패턴의 머리인 가장 긴 것이기 때문이다.

- Q: 어떤 노드의 실패 링크를 구하려면 무엇이 먼저 있어야 하는가?\
  A: **부모의 실패 링크**가 먼저 있어야 한다.\
  내 실패 링크 = 부모의 실패 링크가 가리키는 곳에서 같은 글자로 간 곳(`edge(failureOf(node), c)`)이기 때문이다.\
  의존 방향이 "얕은 노드 → 깊은 노드" 로 흐른다.

- Q: DFS 로 채우면 그 조건이 왜 깨지고, BFS 는 왜 지켜지는가?\
  A: DFS 는 한 가지를 끝까지 파고 내려간다 — 깊이 5 노드를 만났을 때 다른 가지의 깊이 2 노드(내 실패 링크가 가리킬 수 있는 곳)가 아직 미완성일 수 있다.\
  BFS 는 깊이 1 을 전부 끝내고 깊이 2, 깊이 3 순으로 층층이 돈다.\
  실패 링크는 항상 자기보다 얕은 노드를 가리키므로, 얕은 층이 전부 완성된 뒤에 깊은 층을 채우면 조건이 저절로 지켜진다.\
  "의존하는 것이 먼저 계산돼 있어야 한다" — 15 번 플로이드(경유지 k 루프가 바깥), 22 번 구간 DP(짧은 구간 먼저)와 같은 질문이다.

> **BFS(너비 우선 탐색)** — 얕은 노드부터 층층이 도는 순회.\
> 예: 여기서는 큐에 넣고 꺼내며 돌아 실패 링크를 채우는 순서를 만든다.

- Q: 깊이 1 노드의 실패 링크는 어디로 가는가, 왜 그런가?\
  A: 전부 뿌리로 간다.\
  깊이 1 은 지금까지 맞춘 것이 한 글자뿐이라, 그걸 잃으면 남는 꼬리(진접미사)가 빈 문자열밖에 없다.\
  빈 문자열 = 뿌리다.\
  impl 은 큐에 넣기 전에 `setFailure(child, 0)` 으로 먼저 처리한다.

> **진접미사(proper suffix)** — 자기 자신을 뺀 접미사.\
> 예: `"h"` 의 진접미사는 빈 문자열뿐이라, 깊이 1 노드의 실패 링크는 전부 뿌리다.

- Q: 없는 간선을 다루는 두 방법은 각각 무엇을 내주고 무엇을 얻는가?\
  A: (가) 찾을 때 실패 링크를 따라 올라가며 있는 간선을 찾기 — 메모리는 트라이 그대로지만, 글자 하나에 여러 번 점프하는 루프가 생긴다.\
  (나) 만들 때 없는 간선을 실패 링크 쪽 간선(`fallback`)으로 미리 이어두기 — 노드마다 26 칸 간선 표를 다 채우는 메모리를 내주고, 찾을 때 글자당 이동 딱 1 번을 얻는다.\
  impl 은 (나)다.\
  MeasurementTest 가 "본문 읽기 수 = 상태 이동 수" 를 전제로 횟수를 박아 두었다.

- Q: (나)를 골랐을 때 트라이는 무엇으로 바뀌는가?\
  A: **오토마톤**이 된다.\
  어떤 상태에서 어떤 글자가 와도 다음 상태가 표 한 칸으로 정해져 있는 기계다.\
  간선 표에 빈칸(-1)이 없어졌기 때문이다.

> **오토마톤(automaton)** — 상태와 "글자 → 다음 상태" 표로 움직이는 기계.\
> 예: 없는 간선까지 미리 채워 빈칸(-1)이 사라지면 트라이가 오토마톤이 된다.

- Q: 출력을 물려받지 않으면 어떤 입력에서 무엇을 놓치는가?\
  A: 패턴 `she`, `he` 에 본문 `"ushers"` — `she` 를 찾은 그 자리(끝 위치 3)에서 `he` 도 끝나는데 놓친다.\
  본문 훑기의 상태는 `she` 노드에 있고 `he` 노드를 지나가지 않기 때문이다.\
  한 패턴이 다른 패턴의 접미사를 품는 모든 입력에서 같은 문제가 난다.

> **출력 링크(출력 물려받기)** — 실패 링크가 가리키는 노드의 "여기서 끝나는 패턴 목록"을 내 목록에 합쳐 두는 것.\
> 예: 이게 없으면 `"ushers"` 에서 `she` 는 잡고 같은 자리에서 끝나는 `he` 는 놓친다.

- Q: 출력 물려받기는 왜 그 노드의 실패 링크가 정해진 뒤에 해야 하는가?\
  A: 물려받는 대상이 바로 실패 링크가 가리키는 노드의 출력이기 때문이다(`outputOf(failureOf(node))`).\
  링크가 정해지기 전엔 어디서 물려받을지 자체를 모른다.\
  또 그 대상 노드의 출력도 이미 완성돼 있어야(자기 것 + 자기가 물려받은 것) 사슬처럼 이어진 접미사들을 한 번에 다 받는다 — BFS 순서가 이것도 보장한다.

- Q: `she` 의 `e` 노드의 실패 링크는 어디로 가는가, 그 이유는?\
  A: `he` 의 `e` 노드로 간다.\
  지금까지 맞춘 `"she"` 의 접미사 중에서 어떤 패턴의 접두사인 가장 긴 것이 `"he"` 이기 때문이다.\
  계산 순서로는: 부모 `sh` 의 실패 링크가 `h`(깊이 1) → `h` 에서 글자 `e` 로 가면 `he` 의 `e`.

#### 3. 본문 훑기 (`findAll` — TODO 7)

**impl 정답 코드**

```java
public static List<Match> findAll(CountedAutomaton automaton, String text) {
    List<Match> found = new ArrayList<>();
    int node = 0;

    for (int i = 0; i < text.length(); i++) {
        automaton.readChar();
        int c = text.charAt(i) - 'a';
        // 간선 표가 완성되어 있으므로 한 번에 옮겨간다. 되돌아가는 루프가 없다.
        node = automaton.move(node, c);
        for (int p : automaton.outputOf(node)) {
            found.add(new Match(i, p));
        }
    }
    return found;
}
```

- Q: 본문 한 글자당 상태 이동은 몇 번인가?\
  A: 정확히 1 번이다.\
  `readChar()` 한 번에 `move(node, c)` 한 번 — 간선 표가 완성돼 있어서다.\
  실측에서 본문 10 만 글자일 때 읽기 100,000 = 이동 100,000 으로 확인됐다.

> **상태 이동(transition)** — 글자 하나를 읽고 노드를 한 번 옮기는 것.\
> 예: 간선 표가 완성돼 있으면 글자당 정확히 1 번이다 — 읽기 100,000 = 이동 100,000.

- Q: 되돌아가는 루프가 없는 이유는 무엇인가?\
  A: TODO 5 에서 (나)를 골랐기 때문이다.\
  "막히면 실패 링크를 타고 올라가기" 를 만들 때(`linkFailures`) 전부 계산해 간선 표에 넣어 두었다.\
  찾는 시점의 루프를 만드는 시점의 메모리로 바꾼 거래다.

- Q: 아무 패턴도 못 여는 글자를 읽으면 상태는 어디에 있는가?\
  A: 뿌리에 머문다.\
  뿌리의 없는 간선들은 전부 뿌리 자신으로 채워져 있다(`setEdge(0, c, 0)`).\
  `"ushers"` 의 `u` 가 그 경우다 — 뿌리에서 뿌리로 이동한다.

- Q: 결과를 시작 위치가 아니라 끝 위치로 주는 이유는?\
  A: 패턴마다 길이가 달라서다.\
  매칭이 확정되는 순간은 "패턴의 마지막 글자를 읽은 순간" 이고, 그때 알고 있는 것이 지금 읽는 위치 = 끝 위치다.\
  `she`(끝 3)와 `he`(끝 3)처럼 같은 자리에서 길이가 다른 패턴이 동시에 끝나도 끝 위치 하나로 한 번에 다룰 수 있다.

- Q: 시작 위치가 필요하면 어떻게 구하는가?\
  A: `끝 위치 - 패턴 길이 + 1` 로 계산한다.\
  패턴 번호를 알고 있으니 그 길이도 안다.\
  (예: `she` 는 3 - 3 + 1 = 1, `he` 는 3 - 2 + 1 = 2.)

- Q: 전체 비용 O(n + m + z) 에서 z 는 왜 따로 붙는가?\
  A: z 는 찾은 매칭의 개수 — 결과 목록에 담는 일 자체가 z 에 비례하는 비용이기 때문이다.\
  실측에서 본문 10 만·패턴 1,000 개일 때 97,043 개를 찾았다 — 본문 읽기(10 만)와 맞먹는 일이다.\
  "본문 한 번 훑기" 라는 말은 z 를 빼고 하는 말이다.

> **O(n + m + z)** — 본문 길이 n + 패턴 길이 합 m + 찾은 개수 z에 비례하는 비용.\
> 예: z가 크면 "한 번 훑기"여도 결과 담기가 비용의 대부분일 수 있다(10 만 훑고 97,043 개 담기).

### B. 개념

#### 4. 생각해볼 것 (원본 README 이관)

- Q: 출력 링크를 물려받는 대신 찾을 때 실패 링크를 따라 올라가면 무엇이 달라지나, 어느 쪽이 나은가?\
  A: 만들 때는 싸진다 — 출력 복사가 없어 노드당 출력 목록이 자기 것뿐이다.\
  대신 찾을 때 노드에 도착할 때마다 실패 링크 사슬을 뿌리까지 따라 올라가며 출력을 모아야 한다 — 글자 하나에 사슬 길이만큼의 추가 일이 붙는다.\
  (원본에 근거 없음 — 내 추론) 본문을 여러 번 검색하는 일반적 사용(오토마톤 한 번 만들고 계속 쓰기)에서는 만들 때 한 번 물려받는 impl 쪽이 낫다.\
  반대로 패턴 집합이 자주 바뀌고 매칭이 드물면 따라 올라가기가 메모리·구축 비용에서 유리할 수 있다.\
  어느 쪽이든 "만들 때 비용 ↔ 찾을 때 비용" 의 거래라는 구조는 TODO 5 의 간선 채우기와 같다.

- Q: 알파벳이 유니코드면 노드마다 배열 26 개로 안 된다 — 무엇으로 바꿔야 하나?\
  A: (원본에 근거 없음 — 내 추론) 노드마다 `HashMap<Character, Integer>` 같은 맵으로 바꾸는 것이 기본 답이다 — 실제로 쓰는 간선만 저장한다.\
  대신 "없는 간선을 미리 채우기"(나)가 불가능해진다 — 유니코드 전체 칸을 다 채울 수 없으니, 찾을 때 실패 링크를 따라 올라가는 (가) 방식으로 돌아가야 한다.\
  중간 타협으로 본문을 바이트 단위(UTF-8, 알파벳 256)로 보는 방법도 있다 — 배열 방식을 유지하되 칸이 26 → 256 이 된다.

- Q: 패턴을 나중에 하나 더 넣으려면 오토마톤을 통째로 다시 만들어야 하나?\
  A: 이 구현에서는 그렇다.\
  트라이에 길만 파는 것은 쉽지만, 실패 링크와 미리 채운 간선·물려받은 출력이 **기존 노드들 것까지** 새 패턴 때문에 달라질 수 있다(새 패턴이 기존 경로의 접미사가 되는 경우).\
  (원본에 근거 없음 — 내 추론) 동적 추가가 정말 필요하면 (가) 방식(간선 미리 채우기 없음)으로 두고 실패 링크만 다시 계산하거나, 오토마톤 여러 개를 두고 주기적으로 합치는 식의 별도 설계가 필요하다.\
  구축이 O(m × 26) 으로 싸기 때문에 보통은 통째로 재구축이 정답이다.

- Q: 겹치지 않는 매칭만 원하면(가장 긴 것 우선) 무엇을 바꿔야 하나?\
  A: (원본에 근거 없음 — 내 추론) 오토마톤이 아니라 **결과를 고르는 쪽**을 바꾼다.\
  지금 구조는 겹침 포함 전부를 (끝 위치, 패턴 번호)로 내놓으므로, 그 위에서 "끝 위치 순으로 보며 이미 채택한 구간과 겹치면 버리기 + 같은 끝 위치면 긴 패턴 우선" 같은 선택 규칙을 한 겹 얹으면 된다 — 23 번 그리디의 구간 선택과 같은 모양이 된다.\
  탐욕 규칙("지금 가장 긴 것")이 전역 최적과 다를 수 있는 문제(최다 개수? 최장 총길이?)라면 DP 로 골라야 한다.

#### 5. 파생 — 왜 그렇게 생겼는가

- Q: 아호 코라식은 25 번 KMP 의 무엇을 어디로 올린 것인가?\
  A: KMP 의 실패 함수를 **트라이 위로** 올린 것이다.\
  KMP 실패 함수가 "패턴 하나 안에서, 틀어졌을 때 돌아갈 접두사 길이" 였다면,\
  실패 링크는 "패턴 여러 개를 합친 트라이에서, 틀어졌을 때 점프할 노드" 다.

- Q: 시간에서 사라진 k 는 어디로 갔는가?\
  A: 메모리(노드 수)로 갔다.\
  본문 훑기는 패턴 수와 무관하게 글자당 이동 1 번이지만, 그 대가로 패턴 전부를 담은 트라이를 들고 있어야 한다.\
  단 정비례는 아니다 — 패턴 1,000 개 × 길이 5 = 5,000 글자가 노드 967 개였다.\
  접두사 공유 덕이다.

- Q: 노드 수를 정하는 것은 패턴 개수인가, 아니면 무엇인가?\
  A: 패턴들이 **닮은 정도**(접두사가 겹치는 정도)다.\
  실측: 같은 100 개 × 7 글자라도 앞 5 글자가 전부 같으면 26 노드, 무작위면 620 노드 — 24 배.\
  개수·길이가 같아도 이만큼 갈린다.

- Q: 패턴이 10 개든 1,000 개든 본문 읽기가 100,000 번 그대로인 이유는?\
  A: 본문 훑기가 "상태 하나 들고 글자당 이동 1 번" 이라 비용이 본문 길이 n 에만 걸리기 때문이다.\
  패턴 수 k 는 오토마톤을 만드는 쪽(m, 노드 수)에만 나타난다.\
  패턴별로 따로 훑었다면 k = 1,000 에서 1 억 번 — 1,000 배 차이가 실측됐다.

- Q: "본문 한 번 훑기 O(n)" 이 빼고 하는 비용은 무엇인가?\
  A: 찾은 개수 z (결과 담기)다.\
  전체는 O(n + m + z) — z 가 크면 결과 담기가 지배할 수 있다.\
  실측: 본문 10 만에서 97,043 개를 찾았다.\
  훑기와 담기가 거의 1:1 이었다.

- Q: BFS 순서 조건은 15 번·22 번의 어떤 공통 질문과 같은가?\
  A: "이 값을 계산하는 데 필요한 값이 먼저 계산돼 있는 순서가 무엇인가" 라는 질문이다.\
  플로이드는 경유지 k 루프가 가장 바깥이어야 하고, 구간 DP 는 짧은 구간이 먼저여야 한다.\
  여기서는 실패 링크가 항상 더 얕은 노드를 가리키므로 얕은 층 먼저 = BFS 다.

- Q: 없는 간선 미리 채우기는 19 번의 무엇과 같은 성격인가?\
  A: 역방향 간선과 같은 성격 — **메모리를 더 쓰고 탐색(찾기)을 단순하게 만드는 거래**다(원본 README 함정 절).\
  둘 다 "나중에 매번 계산할 것을 구조에 미리 넣어 두는" 선택이다.

- Q: URL 필터·금칙어 목록에서 특히 유리한 이유는?\
  A: 그런 데이터는 접두사가 많이 겹치기 때문이다(예: 같은 도메인으로 시작하는 URL 들).\
  접두사가 겹칠수록 트라이가 길을 공유해 노드 수가 준다 — 앞 5 글자가 같으면 24 배 차이 실측.\
  시간은 어차피 k 와 무관하니, 메모리 쪽 약점마저 데이터 모양이 지워 주는 경우다.
