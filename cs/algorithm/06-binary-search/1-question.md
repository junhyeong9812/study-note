### A. 과제 (구현 대상 — src/main TODO 1~8)

#### 1. lowerBound / upperBound (TODO 1·2·5·6)

```java
/**
 * key 이상인 첫 원소의 위치. 없으면 size().
 * C++ 의 lower_bound 와 같다. key 가 배열에 없어도 "넣을 자리"를 알려준다.
 */
<T> int lowerBound(CountedArray<T> a, T key);

/**
 * key 초과인 첫 원소의 위치. 없으면 size().
 * upperBound - lowerBound 가 key 의 개수다.
 */
<T> int upperBound(CountedArray<T> a, T key);

// TODO 1(반열린): 구간을 [lo, hi) 로 들고 간다. 처음 hi 는 얼마인가. size 인가 size-1 인가.
//   mid 가 key 이상이면 hi 를 mid 로 줄이나 mid-1 로 줄이나.
//   이 한 칸 차이가 무한 루프와 정답을 가른다.
// TODO 5(닫힌): 답 후보를 따로 기억할 변수를 두어라. 초기값은 무엇인가.
```

- lowerBound와 upperBound는 코드에서 정확히 무엇 하나만 다른가?
- `upperBound - lowerBound` 가 왜 그 값의 개수가 되는가?
- 반열린 판에서 처음 `hi` 는 size 인가 size-1 인가, 왜인가?
- mid 가 답 후보일 때 `hi = mid` 로 줄여야지 `mid - 1` 로 줄이면 안 되는 이유는?
- 반대로 닫힌 판에서는 왜 `hi = mid - 1` 로 줄여야 하는가?
- 닫힌 판의 답 후보 변수(answer)의 초기값은 무엇이고 그 값의 의미는?
- key 가 배열의 모든 값보다 클 때 반열린 판은 무엇을 돌려주고, 그게 왜 "저절로" 되는가?
- 두 판의 비교 횟수(성능)는 다른가, 같다면 고르는 기준은 무엇인가?

### B. 개념

#### 4. 생각해볼 것 (원본 README 이관)

- 균등 분포를 알면 중간 대신 예상 위치를 찍을 수 있다(보간 탐색) — 평균 log log n 인데 왜 안 쓰나?
- 술어가 단조가 아니면 이진 탐색은 무엇을 돌려주나 — 그것이 "틀린 답"인가 "정의되지 않은 답"인가?
- `Arrays.binarySearch` 는 못 찾으면 `-(삽입위치) - 1` 을 돌려준다 — 왜 그렇게 설계했을까?

- 삽입 위치·개수 세기·구간 잡기가 전부 lowerBound/upperBound 에서 나온다는 것을 예로 설명하면?
