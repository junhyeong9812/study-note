## 한눈에 — 쉽게 말하면

**DFS = 미로에서 한 길로 끝까지 가보고, 막히면 마지막 갈림길로 되돌아오는 탐색.**

- BFS(11번)가 물결처럼 사방으로 퍼진다면, DFS는 **한 갈래를 끝까지 파고든다.**\
  막다른 곳을 만나면 마지막 갈림길로 돌아와 다음 갈래를 판다.

> **DFS(깊이 우선 탐색)** — 한 갈래를 끝까지 파고들다 막히면 되돌아오는 탐색.\
> 예: 공용 그래프에서 방문 순서가 0, 1, 3, 5, 4, 2 로 나온다 — 한 갈래를 끝까지 간 자취다.

> **BFS(너비 우선 탐색)** — 가까운 곳부터 물결처럼 퍼지는 탐색(11번). DFS와 대비용.\
> 예: 같은 그래프에서 BFS의 방문 순서는 0, 1, 2, 3, 4, 5 다.

- "되돌아올 곳"을 기억하는 방법이 두 가지다: **재귀**(함수 호출 스택이 대신 기억)와 **명시적 스택**(내가 직접 쌓는다).

> **재귀(recursion)** — 함수가 자기 자신을 부르는 것. 되돌아올 위치는 언어의 호출 스택이 자동으로 기억한다.\
> 예: `visit(이웃)`을 부르고 그 호출이 끝나면, 이웃을 몇 번째까지 봤는지가 남아 있는 자리로 저절로 되돌아온다.

> **스택(stack)** — 마지막에 넣은 것을 먼저 꺼내는 자료구조(LIFO). 접시 쌓기.\
> 예: 이웃 [1, 2]를 역순으로 넣으면 0번 이웃인 1이 맨 위에 와서 먼저 꺼내진다.

> **명시적 스택(explicit stack)** — 호출 스택 대신 내가 직접 만드는 스택 자료구조.\
> 예: `iterativeOrder`는 시작점을 push하고 스택이 빌 때까지 pop하며 도는 판이다.

- 이 박스의 주제는 **"재귀를 스택으로 바꾸면 안전해진다"가 반쯤만 맞다**는 것 — 직선 그래프에선 스택 판이 이기고, 촘촘한 그래프에선 정확히 뒤집힌다.
- 실무 예: 폴더 트리 훑기, 패키지 순환 의존(사이클) 검사, 네트워크에서 서로 연결된 덩어리(연결 요소) 찾기.

```text
미로에서의 DFS: 한 길로 쭉 -> 막힘 -> 되돌아가 다른 길

  들어감 --> 갈림길 --> 왼쪽 끝까지 --> 막힘!
                ^                        |
                +---- 되돌아옴(백트랙) <--+
                +--> 이번엔 오른쪽으로
```

> **백트랙(backtrack)** — 막다른 곳에서 마지막 갈림길로 되돌아오는 것.\
> 예: 위 그림에서 왼쪽 끝이 막혔을 때 갈림길로 돌아와 오른쪽 길을 다시 고르는 동작이다.

다섯 가지를 다룬다: 재귀 순서(`recursiveOrder`), 스택 순서(`iterativeOrder`), 진입·종료 시각(`times`), 사이클 탐지(`CycleDetector`), 연결 요소(`Components`).

## 전체 흐름

```text
재귀 판:
  visit(v):
     v 방문 표시 + 순서에 기록
     v 의 이웃을 앞에서부터 하나씩:
        안 본 이웃이면 visit(이웃)     <- 끝까지 파고든다
     (이웃을 다 보면 자동으로 호출한 곳으로 되돌아간다)

스택 판 (같은 순서를 내야 한다):
  스택에 시작점 push
  스택이 빌 때까지:
     pop 한 v 가 이미 방문됐으면 버림
     v 방문 표시 + 기록
     v 의 이웃을 "역순으로" push      <- 0번 이웃이 맨 위에 오게
```

## 예시 그래프 (11-bfs와 같은 공용 그래프)

```text
        0
       / \
      1   2
      |   |
      3   4
       \ /
        5

간선(넣은 순서): 0-1, 0-2, 1-3, 2-4, 3-5, 4-5   (무방향)
```

## 동작 — recursiveOrder (재귀 판)

**언제 쓰나**: 방문 순서 자체가 필요할 때, 그리고 코드가 가장 짧고 자연스러운 기본형.

전 상태: 방문 표시 전부 false, 순서 목록 빈 상태.\
시작점 0.

> **방문 표시(visited/seen)** — 이미 처리한 정점 기록. 이 박스의 포인트는 "언제 찍느냐"(BFS: 넣을 때, DFS 반복 판: 꺼낼 때).\
> 예: 재귀 판은 정점에 들어가자마자 표시하고, 이웃 중 표시가 안 된 것만 골라 내려간다.

단계 (한 줄 = 한 번의 방문):

```text
0 방문 -> 첫 이웃 1이 미방문      깊이 파고듦
1 방문 -> 이웃 0은 봤음, 3이 미방문
3 방문 -> 이웃 1은 봤음, 5가 미방문
5 방문 -> 이웃 3은 봤음, 4가 미방문
4 방문 -> 이웃 2가 미방문
2 방문 -> 이웃 0, 4 다 봤음 -> 막다름
          5, 3, 1, 0 순으로 차례로 "되돌아옴" (백트랙)
0의 남은 이웃 2는 이미 봤음 -> 끝
```

후 상태:

```text
방문 순서: 0, 1, 3, 5, 4, 2      (BFS의 0,1,2,3,4,5 와 다르다 — 한 갈래를 끝까지)
```

**비용**: 시간 O(V+E) — 정점마다 한 번 방문, 간선마다 한 번 조회.\
공간은 재귀 깊이만큼 = 최악 O(V) (직선 그래프면 V층까지 쌓인다 — 아래 측정).

> **O(V+E)** — 정점 수 + 간선 수에 비례하는 비용. 그래프를 한 번 훑는 값.\
> 예: 재귀 판과 스택 판 모두 정점 300개 완전 그래프에서 간선 조회가 89,700번으로 같다.

> **호출 스택(call stack)** — 언어(JVM)가 함수 호출마다 쌓는 기록. 너무 깊으면 StackOverflowError.\
> 예: 직선 그래프에서 재귀 판은 정점 수만큼 프레임이 쌓여 10,000에서 죽는다.

## 동작 — iterativeOrder (명시적 스택 판)

**언제 쓰나**: 재귀 깊이 제한(StackOverflowError)을 피하고 싶을 때.\
**재귀 판과 정확히 같은 순서를 내는 것이 이 박스의 첫 계약이다.**\
순서가 달라지면 "반복으로 바꿨다"가 아니라 다른 알고리즘이다.

> **StackOverflowError** — 호출 스택이 한도를 넘었을 때 JVM이 던지는 에러. 직선 10만 정점 재귀 DFS가 이걸로 죽는다.\
> 예: 기본 JVM 설정에서 직선 5,000개는 되지만 10,000개에서 이미 이 에러가 난다.

같은 순서를 내기 위한 결정 두 가지(원본 코드 그대로):

1. **이웃을 역순으로 push한다.**\
   스택은 마지막에 넣은 것을 먼저 꺼내므로, 그냥 넣으면 순서가 뒤집힌다.\
   역순으로 넣어야 0번 이웃이 맨 위에 온다.
2. **방문 표시는 꺼낼 때 한다. 11번 BFS와 정반대다.**\
   스택에 들어간 뒤 꺼내기 전에 다른 경로로 먼저 도달할 수 있는데, 재귀 판은 그 경우 나중 것을 방문하지 않기 때문이다.\
   넣을 때 표시하면 순서가 달라진다.

전 상태: 스택 [0].

단계 (pop 기준):

```text
pop 0 -> 방문. 이웃 [1,2] 역순 push        스택: [2, 1]
pop 1 -> 방문. 이웃 [0,3] 중 3만 push      스택: [2, 3]
pop 3 -> 방문. 이웃 [1,5] 중 5만 push      스택: [2, 5]
pop 5 -> 방문. 이웃 [3,4] 중 4만 push      스택: [2, 4]
pop 4 -> 방문. 이웃 [2,5] 중 2 push        스택: [2, 2]   <- 2가 두 번 들어감!
pop 2 -> 방문. 새 이웃 없음                스택: [2]
pop 2 -> 이미 방문 -> 그냥 버림             스택: []       끝
```

마지막 두 줄이 "꺼낼 때 표시"가 필요한 이유를 그대로 보여준다 — 같은 정점이 스택에 두 번 들어올 수 있고, 두 번째 것은 꺼내서 버린다.

후 상태:

```text
방문 순서: 0, 1, 3, 5, 4, 2      (재귀 판과 완전히 같다)
```

**비용**: 시간 O(V+E) — 재귀 판과 간선 조회 횟수까지 완전히 같다.\
공간은 스택에 "아직 안 본 이웃 전부"를 쌓으므로 최악 **O(E)** — 여기가 함정이다(아래 측정).

## 동작 — times (진입·종료 시각)

**언제 쓰나**: "언제 들어갔고 언제 다 끝냈나"가 필요한 응용(조상 관계 판정, 위상 정렬, 18번 SCC의 재료).\
`times[v][0]` = 진입 시각, `times[v][1]` = 종료 시각.\
시계는 들어갈 때 한 번, 나올 때 한 번, 총 2V번 튄다.

> **진입/종료 시각(entry/exit time)** — DFS가 정점에 들어간 순번과 그 아래를 다 끝낸 순번. 괄호 구조를 이룬다.\
> 예: 공용 그래프에서 정점 0은 [0, 11], 정점 2는 [5, 6] — 0의 구간이 2의 구간을 통째로 품는다.

```text
0 진입(0) -> 1 진입(1) -> 3 진입(2) -> 5 진입(3) -> 4 진입(4) -> 2 진입(5)
2 종료(6) -> 4 종료(7) -> 5 종료(8) -> 3 종료(9) -> 1 종료(10) -> 0 종료(11)

정점:     0      1      3      5      4      2
시각:  [0,11] [1,10] [2,9]  [3,8]  [4,7]  [5,6]
```

괄호 구조와 같다: 0( 1( 3( 5( 4( 2() ) ) ) ) ).\
**한 구간이 다른 구간을 완전히 품으면 조상-자손 관계다.**

**비용**: O(V+E).\
재귀 DFS에 시계 하나만 더한 것.

## 동작 — CycleDetector (사이클 탐지)

**언제 쓰나**: 순환 참조·순환 의존이 있는지 검사할 때.\
**방향과 무방향의 방법이 다르다** — 이걸 섞으면 틀린다.

> **사이클(cycle)** — 출발한 정점으로 되돌아오는 길.\
> 예: 공용 그래프의 0-1-3-5-4-2-0이 한 바퀴 도는 사이클이다.

**방향 그래프 — 색 셋.**\
"이미 방문한 정점을 또 만났다"는 사이클의 근거가 안 된다.\
다이아몬드 모양이 반례다:

```text
      0
     / \        0->1, 0->2, 1->3, 2->3
    1   2       사이클 없음.
     \ /        그런데 0->1->3 을 마친 뒤 2 에서 3 을 만나면
      3         "이미 방문"에 걸린다 — 오탐!
```

> **다이아몬드 그래프** — 갈라졌다 다시 만나는 모양. "이미 방문 = 사이클"이 오탐하는 반례.\
> 예: 0→1, 0→2, 1→3, 2→3 은 사이클이 없는데도 2에서 3을 만나는 순간 "이미 방문"에 걸린다.

필요한 것은 "**지금 내려가는 경로 위**에서 다시 만났나"다.\
그래서 색이 셋이다:

```text
UNSEEN(0)      아직 안 봤다
IN_PROGRESS(1) 지금 내려가는 경로 위에 있다   <- 이 색을 다시 만나면 사이클
DONE(2)        그 아래까지 다 끝냈다          <- 이 색을 만나는 건 무죄
```

> **3색 기법(three colors)** — UNSEEN/IN_PROGRESS/DONE. 방향 그래프 사이클 탐지의 핵심 — IN_PROGRESS를 다시 만나야만 사이클.\
> 예: 다이아몬드에서 2가 3을 만날 때 3은 DONE이라 무죄로 넘어간다.

다이아몬드에서 2가 3을 만날 때 3은 DONE이라 무죄.\
3→0 간선을 하나 추가하면 0이 IN_PROGRESS인 채로 다시 만나져 사이클로 잡힌다.\
그리고 방향 그래프는 한 정점에서 전부에 못 닿으므로 **모든 정점에서 시작해 봐야 한다.**

**무방향 그래프 — 색 둘 + 부모 제외.**\
무방향 간선은 양쪽에 저장되어 자식이 부모를 이웃으로 본다.\
그 하나(직전에 온 부모)만 빼면, "이미 본 정점을 다시 만남 = 사이클"이 성립한다.\
공용 그래프(0-1-3-5-4-2-0이 한 바퀴)는 사이클 있음이 나온다.

**비용**: O(V+E) 최악.\
단 사이클을 찾으면 그 자리에서 멈춘다 — 원본 측정에서 정점 1,000개 그래프의 앞쪽에 사이클이 있으면 간선 조회 10번 아래로 끝났다.\
"최악 O(V+E)"와 "평균은 훨씬 빠를 수 있다"는 다른 이야기다.

## 동작 — Components (연결 요소)

**언제 쓰나**: 무방향 그래프를 "서로 오갈 수 있는 덩어리"로 나눌 때.\
친구 관계에서 무리 나누기.

> **연결 요소(connected component)** — 무방향 그래프에서 서로 오갈 수 있는 정점 덩어리.\
> 예: `0-1  2-3-4  5(외톨이)` 그래프는 덩어리가 셋이라 count = 3 이다.

방법: 정점 0부터 차례로, **아직 라벨이 없는 정점을 만나면** 거기서 DFS를 돌려 닿는 모든 정점에 같은 번호를 찍는다.\
이미 라벨이 있으면 건너뛴다.

```text
그래프:  0-1  2-3-4   5(외톨이)

v=0: 라벨 없음 -> DFS -> 0,1 에 라벨 0
v=1: 이미 라벨 -> 건너뜀
v=2: 라벨 없음 -> DFS -> 2,3,4 에 라벨 1
v=5: 라벨 없음 -> 라벨 2

labels = [0, 0, 1, 1, 1, 2],  count = 3
```

**비용**: O(V+E) — 시작점마다 새로 도는 게 아니라, 이미 본 정점은 건너뛰므로 전체를 딱 한 번 훑는다.

## 비교 — 재귀 대 스택 (원본 README의 실측)

**하나. 직선 10만 개에서 재귀는 죽는다.**\
기본 JVM 설정에서 5,000은 되고 10,000에서 `StackOverflowError`.\
반복 판은 10만 개를 처리하면서 스택 최대 크기가 **1** — 이웃이 둘인데 하나는 이미 본 부모라 걸러지기 때문.

**둘. 촘촘한 그래프에서는 정확히 뒤집힌다.**\
정점 300개 완전 그래프:

| | 최대 메모리 |
|---|---|
| 재귀 (호출 스택 깊이) | 300 이하 |
| 반복 (명시적 스택) | 44,552 |

148배.\
재귀 깊이는 O(V)인데 명시적 스택은 **아직 안 본 이웃을 전부 쌓아서** O(E)다.\
촘촘하면 E는 V의 제곱.\
둘 다 해결하려면 스택에 "정점"이 아니라 **"정점 + 지금 보는 이웃 번호"**를 넣어야 한다 — 그게 재귀가 실제로 하는 일이다.

> **성긴/촘촘한 그래프(sparse/dense)** — 간선이 적으면 성김, V²에 가까우면 촘촘함. 재귀 vs 스택의 승자를 가른다.\
> 예: 직선 그래프(성김)에서는 반복 판이 스택 1로 이기고, 정점 300개 완전 그래프(촘촘함)에서는 재귀가 148배로 이긴다.

**셋. 간선 조회 횟수는 두 판이 완전히 같다(89,700).**\
시간은 같고 공간만 다르다.\
"어느 쪽이 빠른가"는 잘못된 질문이다.

**변종 둘(지운 코드).**\
① 무방향 사이클의 자기 간선 검사 `if (to == v)`는 죽은 코드였다 — 그 지점에서 `seen[v]`가 이미 true라 아래 검사에서 걸린다.\
② 부모를 "인접 리스트 위치"로 기억하던 판도 지웠다 — 중복 간선은 자식이 아니라 **부모 쪽이 두 번째 간선으로 그 자식을 다시 만나며** 잡힌다.\
테스트가 안 깨지는 방어 코드는 검증이 부족하거나 필요 없거나 둘 중 하나다.

> **중복 간선(parallel edge)** — 같은 두 정점 사이에 간선이 두 개 이상 있는 것.\
> 예: 0-1 간선이 두 개면, 자식 1이 부모 0으로 가는 길을 전부 건너뛰어도 부모 0이 두 번째 간선으로 1을 다시 만나 사이클을 잡는다.

## 핵심 문장

- DFS는 한 갈래를 끝까지 파고들고, 되돌아올 곳은 재귀(호출 스택)나 명시적 스택이 기억한다.
- 스택 판이 재귀 판과 같은 순서를 내려면 **이웃 역순 push + 꺼낼 때 방문 표시** — BFS와 정반대다.
- "재귀→스택 변환은 안전"은 반쯤만 맞다: 재귀 깊이는 O(V), 순진한 명시적 스택은 O(E) — 그래프 밀도가 승자를 정한다.
- 방향 그래프의 사이클은 "이미 봤나"가 아니라 "**지금 내려가는 경로 위**에 있나"(3색)로 잡는다.\
  무방향은 부모 하나만 빼면 2색으로 된다.
- 연결 요소는 "라벨 없는 정점에서만 DFS 시작"으로 전체 O(V+E)를 유지한다.

## 용어 풀이

- **DFS(깊이 우선 탐색)**: 한 갈래를 끝까지 파고들다 막히면 되돌아오는 탐색.
- **BFS(너비 우선 탐색)**: 가까운 곳부터 물결처럼 퍼지는 탐색(11번). DFS와 대비용.
- **재귀(recursion)**: 함수가 자기 자신을 부르는 것. 되돌아올 곳은 호출 스택이 기억한다.
- **호출 스택(call stack)**: 언어(JVM)가 함수 호출마다 쌓는 기록. 너무 깊으면 StackOverflowError.
- **StackOverflowError**: 호출 스택이 한도를 넘었을 때 JVM이 던지는 에러. 직선 10만 정점 재귀 DFS가 이걸로 죽는다.
- **명시적 스택(explicit stack)**: 호출 스택 대신 내가 직접 만드는 스택 자료구조.
- **스택(stack)**: 마지막에 넣은 것을 먼저 꺼내는 자료구조(LIFO). 접시 쌓기.
- **백트랙(backtrack)**: 막다른 곳에서 마지막 갈림길로 되돌아오는 것.
- **방문 표시(visited/seen)**: 이미 처리한 정점 기록. 이 박스의 포인트는 "언제 찍느냐"(BFS: 넣을 때, DFS 반복 판: 꺼낼 때).
- **진입/종료 시각(entry/exit time)**: DFS가 정점에 들어간 순번과 그 아래를 다 끝낸 순번. 괄호 구조를 이룬다.
- **사이클(cycle)**: 출발 정점으로 되돌아오는 경로.
- **3색 기법(three colors)**: UNSEEN/IN_PROGRESS/DONE. 방향 그래프 사이클 탐지의 핵심 — IN_PROGRESS를 다시 만나야만 사이클.
- **다이아몬드 그래프**: 갈라졌다 다시 만나는 모양. "이미 방문 = 사이클"이 오탐하는 반례.
- **연결 요소(connected component)**: 무방향 그래프에서 서로 오갈 수 있는 정점 덩어리.
- **중복 간선(parallel edge)**: 같은 두 정점 사이에 간선이 두 개 이상 있는 것.
- **성긴/촘촘한 그래프(sparse/dense)**: 간선이 적으면 성김, V²에 가까우면 촘촘함. 재귀 vs 스택의 승자를 가른다.
- **O(V+E)**: 정점 수 + 간선 수에 비례하는 비용. 그래프를 한 번 훑는 값.
