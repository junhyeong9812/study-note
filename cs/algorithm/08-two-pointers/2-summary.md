## 한눈에 — 쉽게 말하면

**투 포인터 = 손가락 두 개로 이중 루프를 없애는 기법. 단, 없앨 수 있는 이유가 문제마다 따로 있다.**

- 가격순으로 진열된 물건 중 **합쳐서 딱 만 원**이 되는 두 개를 고른다고 하자. 모든 짝을 다 재보면(이중 루프) n×n번이다.
- 대신 **제일 싼 것과 제일 비싼 것에 손가락을 하나씩** 올린다. 합이 만 원보다 크면 비싼 쪽 손가락을 안으로(더 싼 것으로), 작으면 싼 쪽 손가락을 안으로. 손가락은 되돌아가지 않으니 n번이면 끝난다.
- 핵심은 손가락을 옮길 때 **"저쪽 절반은 볼 필요도 없다"고 통째로 버려도 되는 이유**가 있다는 것. 그 이유를 설명 못 하면 우연히 맞는 코드다.
  - *포인터(pointer)*: 여기서는 "지금 보고 있는 자리 번호(인덱스)"를 담은 변수. 손가락이라고 생각하면 된다.

```text
정렬된 배열에서 합 = target 인 짝 찾기

  1    3    5    7    9    11
  ^lo                       ^hi     합이 크면 hi 를 왼쪽으로,
  --->                  <---        작으면 lo 를 오른쪽으로. 되돌아가지 않는다.
```

두 가지 모양이 있다: **양끝에서 마주 오기**(두 수의 합, 세 수의 합, 물 담기)와 **같은 방향으로 가기**(중복 제거 — 읽는 자리/쓰는 자리를 나눔).

## 전체 흐름

```text
전제: 대개 정렬된 배열 (버려도 되는 이유가 정렬에서 나온다)

양끝에서 마주 오기            같은 방향으로 가기
lo →        ← hi              read →  (매 칸 전진)
합/넓이를 보고                write → (남길 때만 전진)
한쪽을 통째로 버린다           쓰는 쪽이 읽는 쪽을 앞지르지 않아 보조 배열이 없다

비용: 각 포인터가 배열을 최대 한 번씩만 지나간다 → O(n)
이 박스의 계측기는 "비교"가 아니라 "읽기"를 센다 — 이중 루프는 같은 원소를
n 번씩 다시 읽고, 투 포인터는 대체로 한 번씩만 읽는다. 차이가 읽기에 나타난다.
```

## 동작 — 두 수의 합 (`TwoSum`) : 양끝에서 마주 오기

**언제 쓰나**: 정렬된 배열에서 합이 target인 두 원소 찾기(findPair) / 그런 쌍의 개수 세기(countPairs).

전 상태 — `[1, 3, 5, 7, 9, 11]`, target = 16:

```text
idx    0    1    2    3    4    5
     +----+----+----+----+----+----+
     |  1 |  3 |  5 |  7 |  9 | 11 |
     +----+----+----+----+----+----+
      lo^                        ^hi
```

단계 (그림 해설 — 한 단계 한 문장):

```text
[1] 1 + 11 = 12 < 16  → lo++   (1 은 어떤 짝과도 16 을 못 만든다 — 지금 짝이 최대인데도 모자라니까)
[2] 3 + 11 = 14 < 16  → lo++
[3] 5 + 11 = 16       → 찾았다. [2, 5] 반환
```

- 합이 target보다 **크면**: 지금 hi 값은 남은 구간에서 가장 큰 값과 짝지어도 크다 → hi가 들어가는 모든 짝을 통째로 버린다(hi--). 작을 때는 반대로 lo를 버린다.
- 합은 `(long) a.get(lo) + a.get(hi)` — int 두 개를 더하면 넘친다(20억 + 20억은 음수).
- 못 찾으면 lo와 hi가 만나 루프가 끝나고 null.

**개수 세기(countPairs)의 함정**: 합이 맞으면 양쪽에서 같은 값의 개수를 각각 세어 곱한다(leftCount × rightCount). 그런데 남은 구간이 **통째로 같은 값**이면(`[2,2,2,2]`에서 합 4) 양쪽을 따로 세는 방법이 안 통한다 — k개에서 2개 고르는 `k(k-1)/2`로 세고 끝낸다. 이 경우를 빠뜨리면 개수가 두 배로 나온다.

**비용**: O(n) — lo와 hi가 합쳐서 배열을 한 번 지나간다. 측정: 답이 없을 때 1,000개에서 읽기 1,998 대 이중 루프 999,000 — **500배**. 단, 답이 맨 앞 두 개에 있으면 이중 루프가 2번 만에 끝나 오히려 900배 빠르다 — 투 포인터는 양끝에서 좁혀 와야 해서 일찍 못 끝난다. **최악을 없애는 대신 최선을 포기하는 거래다.**

## 동작 — 세 수의 합 (`ThreeSum`) : 고정 + 마주 오기

**언제 쓰나**: 합이 0인 세 값의 조합을 **값 기준 중복 없이** 전부 찾기. O(n³)이 O(n²)가 된다.

전 상태 — `[-4, -1, -1, 0, 1, 2]` (정렬됨):

```text
i 로 첫 수를 고정하고, 나머지 구간을 투 포인터로
     +----+----+----+----+----+----+
     | -4 | -1 | -1 |  0 |  1 |  2 |
     +----+----+----+----+----+----+
       i^   lo^                 ^hi
```

단계 (그림 해설):

```text
i=0 (-4): -4-1+2=-3<0→lo++, -4-1+2 … 짝 없음
i=1 (-1): -1-1+2=0 ✓ [-1,-1,2] → 양쪽 같은 값 건너뛰기 → -1+0+1=0 ✓ [-1,0,1]
i=2 (-1): 직전과 같은 값 → 통째로 건너뜀 (같은 첫 수 = 같은 조합이 또 나온다)
i=3 (0):  0+1+2=3>0→hi-- … 짝 없음.  첫 수가 양수면 break — 뒤는 전부 양수라 합이 0 이 될 수 없다
결과: [-1,-1,2], [-1,0,1]
```

- 어려운 건 알고리즘이 아니라 **중복 제거**다. 중복을 만들고 나서 걸러내면(Set 등) O(n²)가 아니게 된다 — **만들 때 안 만들어야 한다.**
- 건너뛰기는 두 군데: ① 바깥 루프에서 직전과 같은 첫 수 skip ② **조합을 찾은 뒤에도** lo/hi 양쪽에서 같은 값 skip — ②가 빠지면 `[0,0,0,0]`에서 조합이 여러 개 나온다.
- 바깥 루프는 n-2에서 멈춘다 — 한 칸 더 돌면 안쪽에 원소가 하나뿐이다.

**비용**: O(n²) — 첫 수 고정 n번 × 안쪽 투 포인터 O(n). 측정: 300개에서 읽기 74,581 대 삼중 루프 13,365,300 — 179분의 1. 값이 7종류뿐이면 1,681번까지 준다(같은 첫 수를 통째로 건너뛰니까) — 다 다르면 67,523번, 40배 차이.

## 동작 — 물 담기 (`MaxWater`) : 마주 오기 + 버리는 증명

**언제 쓰나**: 기둥 둘을 골라 물을 담을 때 최대 넓이. 넓이 = 두 기둥 거리 × **낮은 쪽** 높이.

전 상태 — 높이 `[1, 8, 6, 2, 5, 4, 8, 3, 7]`:

```text
 8 |    #              #
 7 |    #              #     #
 6 |    #  #           #     #
 5 |    #  #     #     #     #
 4 |    #  #     #  #  #     #
 3 |    #  #     #  #  #  #  #
 2 |    #  #  #  #  #  #  #  #
 1 | #  #  #  #  #  #  #  #  #
    +---------------------------
idx  0  1  2  3  4  5  6  7  8
    lo^                      ^hi   넓이 = min(1,7) × 8 = 8
```

단계 (그림 해설):

- 매 단계 넓이를 재서 최고 기록(best)을 갱신하고, **낮은 쪽 포인터를 안으로** 옮긴다.
- 왜 낮은 쪽인가 — 왼쪽(높이 1)이 낮다고 하자. 왼쪽을 고정한 채 오른쪽을 아무리 당겨도 거리는 줄고 높이는 여전히 왼쪽 1에 눌려 있다 → **왼쪽 기둥이 들어가는 모든 짝은 지금 값을 못 넘는다. 통째로 버려도 된다.**
- 이 논증이 없으면 그냥 운 좋은 휴리스틱이다.
  - *휴리스틱(heuristic)*: 대충 잘 맞는 어림법. 증명이 없으면 언제 틀리는지 모른다.
- 위 예에서 [1]을 버리고 나면 lo=1(높이 8), hi=8(높이 7): 넓이 = 7×7 = **49** — 이게 최종 답이다.
- 높이가 같을 때는 어느 쪽을 옮겨도 된다(둘 다 버려도 되기 때문). 넓이 계산은 `(long) min × 거리` — 넓이도 넘친다.

**비용**: O(n) — 매 단계 포인터 하나가 반드시 안으로 움직인다.

## 동작 — 제자리 중복 제거 (`Dedup`) : 같은 방향으로 가기

**언제 쓰나**: 정렬된 배열에서 중복을 없애고 남은 길이를 돌려준다. **보조 배열 없이 제자리에서.**

전 상태 — `[1, 1, 2, 2, 2, 3]`:

```text
idx    0    1    2    3    4    5
     +----+----+----+----+----+----+
     |  1 |  1 |  2 |  2 |  2 |  3 |    0 번은 항상 남는다.
     +----+----+----+----+----+----+    write=1 부터, read=1 부터 시작
       (남음) ^w,r
```

단계 (그림 해설 — read는 매 칸, write는 남길 때만 전진):

```text
read=1: 1 == a[write-1](1) → 중복, 건너뜀
read=2: 2 != 1 → a[1]=2 로 쓰고 write=2
read=3: 2 == a[write-1](2) → 건너뜀
read=4: 2 == 2 → 건너뜀
read=5: 3 != 2 → a[2]=3 으로 쓰고 write=3
```

후 상태:

```text
     +----+----+----+----+----+----+
     |  1 |  2 |  3 | (2)| (2)| (3)|   반환 3. 앞쪽 [0,3) 만 유효, 뒤는 쓰레기
     +----+----+----+----+----+----+
```

- 정렬돼 있으니 "마지막으로 남긴 값(`a[write-1]`)"과만 비교하면 된다.
- 보조 배열이 필요 없는 근거: **쓰는 쪽(write)이 읽는 쪽(read)을 절대 앞지르지 않는다** — 아직 안 읽은 값을 덮어쓸 일이 없다.
- 일반화 removeExcess(k): 같은 값을 최대 k개까지 남긴다 — 비교 대상만 "바로 앞"에서 "**k칸 앞**(`a[write-k]`)"으로 바뀐다.

**비용**: O(n) — read가 한 번 지나간다. 측정: 1,000개(값 100종류)에서 쓰기 **99번** — 남긴 것만 쓴다(0번은 이미 제자리). 새 배열 복사였다면 1,000번. 다만 중복이 없는 입력이면 자기 자리에 자기를 999번 쓰는 낭비가 된다 — "제자리면 건너뛰기" 분기를 넣으면 이번엔 중복 많은 입력에서 분기가 헛돈다. **어느 쪽이 나은지는 데이터를 알아야 정한다.**

## 변종이 알려준 것 — "등가"는 전제 딸린 등가다

`removeDuplicates`에서 `a.get(write - 1)`을 `a.get(read - 1)`로 바꿔도 결과가 같다 — 정렬돼 있으면 "직전 원본 값"과 "마지막으로 남긴 값"의 비교 결과가 같기 때문. **정렬이라는 전제 아래에서만 등가다.** 전제를 지우는 리팩토링을 하면 이런 자리가 조용히 깨진다.

## 핵심 문장

- 투 포인터는 이중 루프를 없애는 기법이 아니라, **"한쪽을 통째로 버려도 되는 이유"를 찾은 문제에서만** 이중 루프가 없어지는 기법이다 — 이유를 설명 못 하면 우연히 맞는 코드다.
- 양끝 마주 오기의 근거는 정렬(지금 짝이 그 원소의 최선이라는 보장), 같은 방향의 근거는 "write가 read를 앞지르지 않는다"(덮어쓰기 안전).
- 포인터가 되돌아가지 않으므로 O(n) — 대신 답이 앞에 몰려 있어도 일찍 못 끝난다. 최악을 없애고 최선을 포기하는 거래.
- 중복 제거는 나중에 거르는 게 아니라 **만들 때 안 만든다** — 안 그러면 복잡도 자체가 무너진다.
- int 합·넓이는 넘친다 — 더하기 전에 long으로.

## 용어 풀이

- **투 포인터(two pointers)**: 자리 번호 두 개를 규칙적으로 움직여 이중 루프를 한 번의 순회로 줄이는 기법.
- **포인터(pointer)**: 여기서는 지금 보는 자리의 인덱스를 담은 변수(메모리 주소가 아니다).
- **이중 루프(nested loop)**: 루프 안에 루프. 모든 짝을 보면 O(n²).
- **제자리(in-place)**: 보조 배열 없이 주어진 배열 안에서만 고치는 방식.
- **read / write 포인터**: 읽는 자리(매 칸 전진)와 쓰는 자리(남길 때만 전진). 같은 방향 투 포인터의 뼈대.
- **정렬(sorted)**: 오름차순으로 놓인 상태. "한쪽을 통째로 버려도 되는 이유"의 원천.
- **오버플로(overflow, 넘침)**: int 최대(약 21억)를 넘어 음수로 뒤집히는 것. 합·넓이 계산에서 long이 필요한 이유.
- **휴리스틱(heuristic)**: 증명 없이 대충 잘 맞는 어림법. 물 담기의 "낮은 쪽 옮기기"는 증명이 있어서 휴리스틱이 아니다.
- **경우의 수 `k(k-1)/2`**: k개 중 순서 없이 2개를 고르는 가짓수. 남은 구간이 전부 같은 값일 때 쌍 개수.
- **변종(mutation) 실험**: 코드를 일부러 조금 바꿔 테스트가 깨지는지 보는 실험. "등가로 보이는 코드"의 전제를 드러낸다.
- **O(n), O(n²)** (빅오 표기): 데이터 n개일 때 일의 양이 n에 비례 / n²에 비례한다는 뜻.
