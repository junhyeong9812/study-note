# cs/thrashing — thrashing(스레싱) — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> ⚠️ **이 정답은 Claude 초안이다(2026-08-23).** 본인이 2-summary를 닫고 기억으로 다시 쓴 뒤 대조해 확정하고 이 줄을 지운다.

## 정답

1. 동적 배열(ArrayList 류)이 capacity를 늘렸다가 줄였다 하는 재할당을 너무 자주 반복하는 현상. 비용이 드는 동작은 resize마다 일어나는 **새 배열 생성 + 기존 원소 전부 복사**다.

2. 확장 경계(size == capacity)와 축소 경계(size <= capacity/2)가 사실상 같은 자리에 붙어 있기 때문이다.
   capacity = 32, size = 16에서 1개 삭제 → size = 15 → 절반 이하이므로 capacity 16으로 축소(새 배열 + 복사).
   다시 2개 추가 → size = 17 → capacity 16을 넘으므로 32로 확장(새 배열 + 복사).
   몇 개 삭제하면 또 16으로 축소… 사용량이 경계 근처에서 왔다 갔다 하는 것만으로 `16 → 32 → 16 → 32 …` 재할당이 계속된다. 이게 thrashing이다.

3. size = 16 → 아직 안 줄임(1/2). size = 12 → 아직 안 줄임. size = 8 → capacity/4이므로 capacity를 16으로 축소.
   축소 직후 size = 8, capacity = 16. 다시 확장되려면 size가 16까지(두 배) 늘어야 한다.
   즉 축소 경계(C/4 = 8)와 확장 경계(C/2 = 16) 사이에 충분한 여유 구간이 생긴다.

4. **축소가 일어나는 경계와 확장이 일어나는 경계를 충분히 떨어뜨려 놓아서, 경계 근처에서 resize가 반복되는 것을 막는 것.** 1/4는 그 간격을 만드는 한 가지 값일 뿐이다.

5. 히스테리시스(hysteresis) — 올라갈 때의 기준과 내려갈 때의 기준을 다르게 두는 것.
