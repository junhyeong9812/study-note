# software-design/17-error-messages-and-log-level-policy — 질문

## 질문

1. (왜) 에러 하나의 독자 셋은 누구이고, 각자 무엇이 필요한가? 셋을 잇는 열쇠는?
2. (경계) RFC 5424는 Severity를 어떻게 다루나? 그렇다면 "ERROR"의 뜻은 누가 정하나?
3. (그림) ERROR·WARN·INFO·DEBUG의 조작적 정의를 "질문 한 줄"로 쓰고, 4xx 검증 실패가 어디에 들어가는지 말하라.
4. (예측) 요청 1000건(OK 952, 400 39, 404 3, 재시도 후 성공 4, DB 장애 500 2)을 "실패=ERROR" 정책과 조작적 정의 정책으로 기록하면 ERROR는 각각 몇 건이고, 그중 사람이 조치할 것은?
5. (예측) 없는 표를 조회한 `SQLException`의 `getMessage()`를 응답 본문에 넣으면 무엇이 보이나? 분리한 응답과 서버 로그에는 각각 무엇을 두나?
6. (경계) RFC 9457의 `detail`에 넣으면 안 되는 것과 클라이언트가 `detail`을 다루는 규칙은? 에러 코드를 따로 두는 이유는?
7. (연결) 계층마다 catch-log-rethrow를 하면 레벨 정책과 무관하게 무엇이 망가지나?
8. (예측) 사용자 이름 입력에 `\n2026-10-01T10:00:00Z INFO login success user=admin`이 들어 있다. 평문 로그에 그대로 쓰면? 막는 방법은?
9. (장애 진단) 고객 문의가 "오류가 발생했습니다"뿐이라 원인을 못 찾는다. 응답 설계에서 무엇이 빠졌고, 정보 누출 없이 어떻게 고치나?
