## 질문

1. (왜) 계층형·헥사고날·클린의 그림을 알아도 코드로 옮길 때 정해야 하는 다섯 가지 결정은 무엇인가?
2. (그림) "포인트 사용" 유스케이스를 세 구조로 그리고 의존 화살표 방향을 표시하라. 제어 흐름과 소스 의존이 반대인 곳은 어디인가?
3. (경계) Cockburn의 포트·어댑터 의도문은 무엇이고, 주도하는/주도되는 어댑터의 예는? Martin의 의존성 규칙은 무엇을 금지하나?
4. (예측) 같은 유스케이스의 파일 수는 세 구조에서 각각 몇 개였나? `jdeps`·ArchUnit 도메인 순수성 규칙에서 실패한 구조는?
5. (예측) 낙관적 락 `@Version` 컬럼을 추가하면 세 구조에서 각각 어느 파일이 바뀌었나? 헥사고날에서 매핑 코드를 고쳐야 했던 이유는?
6. (예측) 응답에 도메인 계산값(등급) 하나를 추가하면 바뀐 파일 수는? 도메인 규칙(1회 한도) 추가는?
7. (경계) 실험 결과로 "헥사고날·클린이 항상 변경 비용이 낮다"고 말할 수 있나? 어떤 변경이 잦을 때 어느 쪽을 고르나?
8. (장애 진단) `adapter/`·`domain/` 폴더가 있는데 DB 컬럼 변경 PR이 도메인 파일을 고친다. 무엇으로 확인하고 어떻게 고치나?
9. (장애 진단) 저장소를 바꾸려니 포트 인터페이스와 유스케이스까지 바뀐다. 포트 이름이 `JpaAccountPort`다. 원인과 대처는?
10. (연결) 트랜잭션 경계는 세 구조에서 어디에 두나? 영속 어댑터 메서드마다 트랜잭션을 열면 무엇이 생길 수 있나?
