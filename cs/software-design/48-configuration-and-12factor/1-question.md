# software-design/48-configuration-and-12factor — 질문

## 질문

1. (경계) 12-factor가 말하는 "설정"의 정의는? Spring 빈 연결 같은 내부 구성은 왜 그 설정이 아닌가? 설정이 제대로 분리됐는지 보는 시험법은?
2. (그림) 빌드 → 릴리스 → 실행을 그리고, 각 단계에서 설정이 언제 붙는지, 릴리스를 왜 수정하지 않는지 적어라.
3. (왜) 12-factor는 왜 `development`·`staging`·`production` 같은 환경 이름 묶음을 피하라고 하나?
4. (예측) jar 안 `app.payment.timeout-ms=1000`, 환경 변수 3000, `-D` 4000, `--` 5000을 차례로 더하면 각 단계의 실효 값은? 실험에서 이긴 소스 이름은?
5. (예측) 환경 변수를 `APP_PAYMENT_TIMEOUT=3000`(오타)으로 넣으면 어떻게 되나? 에러가 나나?
6. (예측) 기본값 없는 `@Value("${app.payment.api-key}")`인데 값을 안 주면? 이것이 기본값을 주는 것보다 나은 이유는?
7. (예측) Dockerfile에서 `COPY secret.env` 뒤 `RUN rm`으로 지웠다. 컨테이너 안과 `docker save`한 레이어에서 각각 무엇이 보이나? 왜 그런가?
8. (경계) 비밀을 실행 시점 환경 변수로 넣으면 이미지 문제는 사라진다. 그래도 남는 노출 경로는(실험)?
9. (장애 진단) 같은 이미지 태그가 스테이징에서는 통과하고 운영에서 결제 지연 장애를 냈다. 무엇을 비교하고, 어떻게 재발을 막나?
10. (장애 진단) 이미지에 결제 키가 들어간 것을 발견했다. 이미지를 다시 빌드하는 것만으로 충분한가?
