# software-design/40-codebase-structure — 질문

## 질문

1. (왜) 계층 다이어그램이 "컨트롤러는 서비스만 부른다"고 말하는데도 컨트롤러가 리포지토리를 바로 부르는 코드가 생기는 이유는? Brown이 "패키지가 폴더일 뿐"이라고 한 조건은?
2. (그림) by layer·by feature·by component를 "주문 조회" 기능으로 그려라. 각각에서 `public`이어야만 하는 타입은 무엇인가?
3. (예측) 전부 `public`인 by layer 프로젝트와 package-private을 쓴 by component 프로젝트에 같은 "서비스 우회" 컨트롤러를 넣었다. 각각 컴파일되나? 컴파일된 쪽을 실행하면 무엇이 빠지나?
4. (예측) "주문 조회 응답에 배송 메모 추가"를 두 배치에 적용하면 바뀐 파일 수와 디렉터리 수는 각각 어떻게 다른가?
5. (경계) package-private으로 부족해지는 때는 언제이고, JPMS는 무엇을 더 해 주나? `exports`하지 않은 패키지의 `public` 클래스를 다른 모듈에서 import하면?
6. (경계) 소리치는 아키텍처는 무엇을 요구하고, 무엇을 요구하지 않나? 기능별 폴더로 바꾸기만 하면 경계가 생기나?
7. (장애 진단) 보안 점검에서 일부 화면만 다른 사용자의 주문을 보여 준다. 테스트는 모두 통과한다. 무엇을 의심하고 무엇으로 확인하나?
8. (장애 진단) `util` 패키지의 날짜 함수 하나를 고쳤더니 무관한 모듈 테스트가 깨진다. 구조적 원인과 정리 방향은?
9. (연결) 순환 의존이 있는 두 패키지를 JPMS 모듈 둘로 나누면 무엇이 일어나나? 순환을 찾고 끊는 일은 어느 노트가 다루나?
