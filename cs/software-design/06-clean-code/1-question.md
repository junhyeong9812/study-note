# software-design/06-clean-code — 질문

## 질문

1. (왜) 감각으로 하는 코드 리뷰가 결합·중복을 놓치는 이유는? CLEAN 다섯 질문 중 클래스 하나만 열어 봐서는 답할 수 없는 둘은 무엇인가?
2. (예측) 실험 A에서 "해외 잠금 카드는 못 쓴다"를 Ask 설계에 grep으로 찾은 지점만 고쳐 적용했다. 바뀐 파일 수와 세 서비스의 실행 결과는? Tell 설계에서는?
3. (경계) 실험 B에서 합친 설계와 나눈 설계의 diff 크기는 어떻게 달랐나? 그런데도 한쪽만 테스트가 실패한 이유는?
4. (경계) PMD CPD는 실험 A의 사본 셋 중 몇 개를 잡았나? 도구가 비중복(N)을 대신 판정할 수 없는 경우 두 가지는?
5. (연결) 다섯 속성 사이의 긴장 넷을 들고, 공통 판정 질문 하나로 정리하라.
6. (연결) DRY 원문은 무엇을 중복의 단위로 삼나? 같은 절에서 Hunt–Thomas가 "중복이 아니다"라고 한 예는?
7. (경계) Tell, Don't Ask를 "getter를 모두 없애라"로 읽으면 무엇이 문제인가? Fowler 2013 bliki의 입장은?
8. (장애 진단) 배포 뒤 잠긴 카드에 포인트만 계속 쌓인다. 에러 로그는 없다. 무엇을 의심하고 어떤 순서로 찾나?
9. (연결) CLEAN 두문자어의 출처로 확인된 책과 장은? 원본 노트의 출처 기술과 무엇이 다른가?
