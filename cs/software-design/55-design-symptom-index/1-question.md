# software-design/55-design-symptom-index — 질문

## 질문

1. (왜) 소프트웨어 설계 영역에서 "깨졌다"는 대개 어떤 모양으로 보이나? 증상이 드러나는 시점을 여섯 칸으로 나누고, 늦은 칸일수록 비싼 이유를 말하라.
2. (장애 진단) "결제 수단 하나 추가에 파일 12개"라는 PR이 올라왔다. 원인 후보 둘은 서로 반대 방향의 처방을 요구한다. 둘을 가르는 첫 질문과 각각의 처방, 관련 leaf를 말하라.
3. (예측) 새 상태 `REFUNDED`를 추가했는데 처리 코드 한 곳을 빠뜨렸다. (가) `default`가 있는 `switch` 문, (나) `sealed` 인터페이스 + `default` 없는 `switch` 식일 때 각각 무엇이 보이나? (나)의 javac 메시지는?
4. (장애 진단) 운영에서 `NullPointerException: … because "this.repo" is null`이 한 메서드에서만 난다. 생성자 주입을 했고 다른 메서드에서는 `repo`가 정상이다. 무엇을 의심하나? `if (repo == null) return;`으로 닫으면 왜 더 나빠지나?
5. (구분) helpful NPE의 `because` 뒤가 `"<local5>"`, `"this.conn"`, `"this.clock"`일 때 각각 먼저 볼 설계 원인은? 같은 코드인데 `<local0>`과 변수 이름 `c`가 번갈아 나온다면 무엇이 다른가?
6. (경계) "빈 하나를 추가했더니 기동이 안 된다." 메시지별로 원인 셋을 들고, `allow-circular-references`·`allow-bean-definition-overriding`을 켜서 해결하면 안 되는 이유를 말하라.
7. (연결) 커스텀 어노테이션 `@Audited`를 붙였는데 감사 로그가 안 남고 오류도 없다. 원인과 확인 명령은? 이 증상이 ①~⑥ 중 어느 칸에 나타나며, 왜 그 칸인가?
8. (장애 진단) "테스트를 쓸 수 없다"와 "리팩터링마다 테스트가 수십 개 깨진다"는 각각 어떤 설계 원인을 가리키나? 첫 진단을 하나씩 말하라.
9. (연결) 에러 없이 값만 틀리는 증상 다섯(1원 차이, `label=기타`, 남의 주문 조회, `PAID`인데 `paidAt=null`, 예외 뒤에도 남은 행)의 흔한 설계 원인과 leaf를 하나씩 말하라.
10. (경계) "추상화하면 좋아진다", "복잡도 지표만 낮추면 된다", "테스트가 통과하니 리팩터링은 안전하다"가 틀리는 조건을 각각 실험 수치와 함께 말하라.
