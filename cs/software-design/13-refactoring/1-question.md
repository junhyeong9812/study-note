# software-design/13-refactoring — 질문

## 질문

1. (정의) Fowler의 리팩터링 정의(명사)를 말하라. "구조를 개선하면서 버그도 하나 고쳤다"는 리팩터링인가?
2. (그림) Fowler 2판 1장의 작은 단계 루프를 그려라. 테스트가 실패했는데 원인이 바로 안 보이면 Fowler는 어떻게 하나?
3. (경계) 자기 검증 테스트와 특성 테스트(골든 마스터)는 각각 무엇을 확인하나? 리팩터링 전 안전망으로 행복 경로 테스트 하나가 부족한 이유는?
4. (예측) 실험 A에서 "줄마다 반올림 후 합산"을 "합산 후 한 번 반올림"으로 바꿨다. 행복 경로 테스트(책 1권 10,000원)와 골든 300건은 각각 어떻게 나왔나? 왜 행복 경로는 못 잡나?
5. (예측) 실험 A에서 `git bisect run`은 무엇을 짚었고, 범인 커밋의 크기는 작은 단계와 큰 한 방에서 각각 얼마였나?
6. (예측) 실험 B에서 호출처 18곳을 바꾼 리팩터링 브랜치를 기능 커밋 3개 뒤에 머지했다. 텍스트 충돌은 몇 파일이었고, 충돌이 없던 파일에서는 무슨 일이 났나?
7. (적용) 호출처가 많은 시그니처 변경을 오래 사는 브랜치 없이 하는 순서는? 실험 B의 대안에서 첫 커밋은 무엇이었고 결과는?
8. (연결) IDE의 자동 Rename이 `sed` 치환보다 안전한 이유는 어떤 자료구조 덕분인가? 3-way 머지가 의미 충돌을 못 잡는 이유는?
9. (장애 진단) "구조만 바꿨다"는 배포 뒤 영수증 줄 금액의 합과 합계 줄이 1원씩 다른 건이 나온다. 에러 로그는 없다. 원인 후보와 찾는 법, 다음부터의 예방은?
