# software-design/49-multi-tenancy — 질문

## 질문

1. (그림) 사일로·풀·브리지를 그리고 각각 무엇을 공유하는지 적어라. AWS SaaS Lens가 사일로라도 공유한다고 한 것은?
2. (경계) 원본의 격리 4단계(행·스키마·DB·인스턴스)는 사일로·풀 스펙트럼과 어떻게 대응하나? 브리지에서 어떤 서비스를 사일로 쪽에 두나?
3. (예측) 조회 SQL에는 `WHERE tenant_id = ? AND id = ?`가 있다. 앞단 캐시 키를 `id`로만 두고 acme → globex 순서로 같은 `INV-1`을 조회하면 globex는 무엇을 받나? DB는 몇 번 조회되나?
4. (경계) 실험 A의 누출을 DB 행 수준 보안(RLS)으로 막을 수 있나? 왜 그런가?
5. (연결) Spring 캐시 추상화의 기본 키 생성 규칙은? tenant를 `ThreadLocal`로 넘기는 서비스에 `@Cacheable`만 붙이면 어떤 일이 생기나?
6. (예측) 워커 4개 공용 FIFO 풀에 A가 20ms 작업 200개를 먼저 넣고 B가 2ms 작업을 보내면 B의 응답은 대략 얼마인가? A를 동시 3개로 묶으면 B와 A는 각각 어떻게 되나(실험 수치)?
7. (왜) Azure는 시끄러운 이웃을 어떤 문제로 다루라고 하나? 각 테넌트가 작게 쓰는데도 생기는 경우는?
8. (경계) tenant_id를 파티션 키로 둘 때 얻는 것과 생기는 위험은? 해시만 쓰지 않고 매핑 테이블을 두는 이유는?
9. (장애 진단) 고객사가 "우리 것이 아닌 청구서가 가끔 보인다"고 신고했다. 간헐적이라는 점에서 무엇을 의심하고, 즉시 조치와 재발 방지는?
10. (장애 진단) 비동기 작업에서 저장한 행의 tenant_id가 NULL이거나 직전 요청의 테넌트로 들어간다. 원인과 대처는?
