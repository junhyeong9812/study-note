# software-design/14-tidy-first — 질문

## 질문

1. (왜) 정리(구조 변경)와 동작 변경을 한 커밋·한 PR에 섞으면 어려워지는 세 가지는?
2. (원리) Beck은 구조 변경과 동작 변경을 가르는 핵심 성질로 무엇을 드나? 그 성질이 리뷰 방식에 주는 함의는?
3. (분류) 정리 시점 네 가지(먼저·바로 뒤·나중에 따로·안 함)를 각각 언제 고르나? "먼저"의 근거가 된 Beck의 문장은?
4. (예측) 실험에서 섞은 커밋은 몇 줄이었고, 정책 변경은 그중 몇 줄이었나? 나눈 쪽의 동작 커밋 diff는 몇 줄이었나? 섞은 커밋에서 상한 줄이 "바뀐 줄"로 안 보인 이유는?
5. (예측) 특성 테스트 지문은 시작·정리 커밋·동작 커밋에서 각각 어떻게 나왔나? 정리 커밋의 지문으로 무엇을 증명할 수 있나?
6. (예측) 키오스크 커밋(새 이름 사용) 뒤 정책을 되돌리려고 `git revert`를 했다. 나눈 쪽과 섞은 쪽에서 충돌·컴파일·결과는 각각 어땠나?
7. (적용) 이미 정리와 변경이 섞인 작업 트리를 커밋 둘로 나누는 git 명령 흐름은? 정리 커밋이 정말 정리뿐인지 리뷰할 때 쓰는 `git diff` 옵션 셋은?
8. (장애 진단) 기능 PR이 "정리하느라" 2주째 열려 있고 리베이스마다 충돌이 난다. 원인과 대처는?
9. (연결) 『Tidy First?』 3부가 말하는 두 경제적 힘(시간 가치·옵션 가치)은 정리 시점 판단과 어떻게 이어지나? Constantine의 등가는 무엇을 말하나?
