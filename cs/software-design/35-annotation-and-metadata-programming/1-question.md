# software-design/35-annotation-and-metadata-programming — 질문

## 질문

1. (왜) 어노테이션은 그 자체로 무엇을 하나? 선언을 읽어 동작을 만드는 두 주체는 무엇이고, 각각 대표 예는?
2. (그림) `SOURCE`·`CLASS`·`RUNTIME`이 소스·클래스 파일·실행 중 어디까지 남는지 그려라. `@Retention`을 생략하면 무엇인가?
3. (예측) `@Retention`을 빠뜨린 `@RouteForgot("/refunds")`로 라우팅 표를 만들면 컴파일·실행·요청 결과는 각각 어떻게 되나? `javap -v`에서는 어느 속성에 기록되나?
4. (예측) 직접 만든 `BuilderProcessor`로 `record Order`를 컴파일하면 라운드가 몇 번 돌고, 각 라운드의 대상 수는? `class`에 붙이면?
5. (경계) MapStruct와 Lombok은 둘 다 어노테이션 처리기인데 생성물이 어떻게 다른가? 표준 `Filer` API의 제약과 연결해 설명하라.
6. (예측) 처리기 경로를 `mapstruct-processor:lombok` 순서로 바꾸면 컴파일 결과와 `toDto` 결과는? 이것을 컴파일에서 막는 설정은?
7. (경계) Spring Framework 6.2의 컴포넌트 스캔은 실험 B의 직접 구현과 무엇이 다른가? 미리 만든 후보 색인은 어떤 상태인가?
8. (연결) JDK 23에서 javac의 어노테이션 처리 기본 동작은 어떻게 바뀌었나? JDK 21은 무엇을 출력하나?
9. (장애 진단) JVM에서는 되는데 GraalVM 네이티브 이미지에서만 특정 기능이 실패한다. 원인과 대처는? 컴파일 타임 생성 코드는 왜 이 문제가 적은가?
10. (장애 진단) 서비스가 커지며 기동이 느려졌다. 실험 B는 무엇을 보였고, 어떤 대책이 있나?
