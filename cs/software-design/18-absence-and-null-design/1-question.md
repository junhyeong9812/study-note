# software-design/18-absence-and-null-design — 질문

## 질문

1. (왜) "없음"을 null로 표현하면 무엇이 호출처마다 퍼지나? 쿠폰 목록 API를 예로 들어라.
2. (그림) null·빈 컬렉션·Optional·Null Object·예외 다섯 방법을 "시그니처에 드러나나 / 호출자가 할 일 / 어울리는 자리"로 표를 그려라.
3. (예측) 쿠폰 목록을 null로 돌려주고 호출처 11곳 중 1곳이 검사를 빠뜨렸다. NPE는 몇 건이고 메시지는 어떻게 나오나? 빈 목록으로 바꾸면?
4. (예측) 빈 `Optional`에 `get()`을 부르면 무엇이 나오나? 이것이 NPE보다 나아진 것은 무엇이고 아닌 것은? 대안 두 가지는?
5. (경계) JDK 문서가 말하는 Optional의 용도는? 필드·인자에 쓰면 생기는 문제를 하나씩 말하라.
6. (경계) Null Object(할인 없음)가 맞는 경우와, 오히려 문제를 숨기는 경우는?
7. (예측) `HashMap`에 `put("A", null)` 뒤 `get("A")`, `get("B")`, `containsKey`는? `Map.of("A", null)`은?
8. (연결) JDK 21에서 helpful NPE 메시지가 `"<local5>" is null`로 나오는 이유와 변수 이름이 나오게 하는 방법은? 이 메시지를 응답에 그대로 넣으면 무엇이 문제인가?
9. (장애 진단) 할인율을 비워 둔 상품이 "0% 할인"으로 판매됐다. 원인과 설계 수정, 그리고 이미 저장된 데이터의 문제는?
