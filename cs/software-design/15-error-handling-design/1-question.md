# software-design/15-error-handling-design — 질문

## 질문

1. (왜) 에러 처리 코드가 설계 없이 망가지는 두 방향은 무엇이고, 각각 운영에서 어떻게 보이나?
2. (그림) 예외의 "던지는 곳·지나가는 곳·잡는 곳"을 그리고, 지나가는 곳에서 `catch`가 정당한 세 경우를 말하라.
3. (예측) 장애 하나가 repo → service → controller를 지나는데 계층마다 catch-log-rethrow를 하고 최상위 핸들러도 기록한다. SEVERE 레코드는 몇 건이고, 근본 원인 문장은 몇 번 나오나? 경계에서 한 번만 기록하면?
4. (예측) 저장 메서드가 `catch (Exception e) { }`로 예외를 삼키고, 20건 중 id가 4의 배수인 건에서 저장소가 실패한다. 호출자가 보는 결과, 에러 로그, 실제 저장 건수는?
5. (경계) `new Order(null, 1000)`이 생성 시점에 실패하는 설계와 출고 라벨에서 NPE가 나는 설계는 스택 트레이스 맨 위가 어떻게 다른가? 늦은 실패의 진짜 비용은 무엇인가?
6. (경계) APOSD 10장의 "에러를 정의로 없애기"를 `Files.delete`·`Files.deleteIfExists`로 설명하라. 이 기법을 쓰면 안 되는 상황은?
7. (연결) 아래 계층 예외를 번역할 때 붙여야 하는 두 가지는? `throw new SaveFailed(e.getMessage())`는 무엇을 잃나?
8. (장애 진단) 주문 접수 화면은 성공인데 정산에서 주문 수가 모자란다. 에러 로그는 0건이다. 무엇을 의심하고 어떻게 찾나?
9. (연결) Spring에서 경계 처리기를 두는 자리와, 여러 `@ExceptionHandler`가 맞을 때 고르는 규칙은?
