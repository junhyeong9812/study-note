# software-design/45-monolith-vs-microservices — 질문

## 질문

1. (그림) "배포 단위 수"와 "경계 강제" 두 축으로 2×2 표를 그리고 네 칸의 이름을 채워라. 분산 모놀리스는 어느 칸이고 왜 가장 나쁜가?
2. (왜) Lewis·Fowler의 마이크로서비스 정의에서 "독립 배포"를 뒷받침하는 조건은 무엇인가? Fowler가 말한 선행 조건 셋은?
3. (예측) 같은 주문 → 재고 → 결제 3단계를 한 프로세스 안 메서드 호출과 localhost HTTP 3홉으로 돌리면 p50은 대략 몇 배 차이가 날까? 실험에서는 각각 얼마였나?
4. (경계) 실험에서 JDK `HttpServer`의 기본 설정으로 3홉이 약 50ms였다. 무엇을 바꿨더니 약 3ms가 됐고, 이 일이 설계 판단에 주는 교훈은?
5. (예측) `orders.addr`를 `address_line`·`zip`으로 나누는 변경을 공유 DB 설계와 데이터 소유 설계에 적용하면 각각 몇 개 서비스가 바뀌나?
6. (경계) 데이터 소유 + 공개 계약 설계에서도 서비스 여럿이 함께 바뀌는 변경은 어떤 것인가? 그것을 안전하게 내보내는 순서는?
7. (연결) 동기 호출 체인이 가용성과 지연에 주는 영향은? 각 99.9%인 서비스 다섯 개 직렬이면 전체는 약 얼마인가?
8. (장애 진단) 서비스를 나눴는데 릴리스마다 "A·B·C 동시 배포 필요"가 붙는다. 어떤 증거로 분산 모놀리스임을 확인하고, 어떻게 대처하나?
9. (판단) Fowler의 MonolithFirst 주장 두 가지 이유는? 반대로 분산 구성에서 한 프로세스로 합쳐 비용을 줄인 사례와 그 원인은?
