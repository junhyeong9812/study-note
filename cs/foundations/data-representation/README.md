## 1. 진수 변환과 2의 보수

출처: `computer_science/chapter/chapter2.py`

```python
print(bin(25))
# 0b11001
```

`0b`은 binary(2진수를 의미), `0x`는 hexadecimal(16진수를 의미).

```python
a = 0xa
print(bin(a))  # 0b1010
f = 0xf
print(bin(f))  # 0b1111

address_8bit = 0b00101101
print(hex(address_8bit))
# 0x2d
```

이렇게 16진수로 표현하는 이유는 가독성을 높이기 위해서이다.

```python
address_32bit = 0x1234abcd
print(bin(address_32bit))
# 0b10010001101001010101111001101
```

컴퓨터는 음수를 보수 형태로 저장한다. 컴퓨터가 -4를 저장하는 방식:

```python
print((-4).to_bytes(1, byteorder='little', signed=True))
# b'\xfc'
```

컴퓨터는 + 연산이 더욱 효율이 좋기 때문에, 두 수를 합칠 때 맨 앞의 1은 버릴 수 있도록 데이터를 2의 보수로 정하고 더하면 그 차이가 나오게 되며, 음수의 형태로 앞이 1이면 역으로 -1을 하고 보수 형태로 정수값을 가져와서 -를 붙이면 된다.

## 2. 부동소수점

출처: `computer_science/chapter/chapter3.py`

### 2.1 0.01을 100번 더하면?

```python
a = 0.01
result = 0.0
for i in range(100):
    result += a
print(result)
# 1.0000000000000007
```

1에 매우 가까운 수라고 해도 1은 아니다.

```python
a = 0.015625
result = 0.0
for i in range(100):
    result += a
print(result)
# 1.5625  ← 값이 제대로 나온다.
```

이 기가 막힌 일이 일어나는 이유는 무엇인가 하니, 이것이 부동소수점이라는 문제점이다. ANSI/IEEE 754-1985라는 표준에 따라 실수를 표현한다. '부'는 떠다닌다는 의미로, 소수점으로 다양한 표시 방법에 의해 실수를 표현하는 방식을 부동소수점이라 부른다.

부동소수점에는 단정도 부동소수점과 배정도 부동소수점이 있다.

- 단정도는 실수를 32비트(4바이트)로 부호 1비트, 지수부 8비트, 가수부 23비트로 구성.
- 배정도는 실수를 64비트로 표현하며 부호 1비트, 지수부 11비트, 가수부 52비트로 구성. 실수를 표현하는 데 단정도보다 2배를 더 사용한다.

### 2.2 sys.float_info

```python
import sys
print(sys.float_info)
```

- `max=1.7976931348623157e+308` — 표현 가능한 가장 큰 양의 유한 실수로 이 값을 초과하면 무한대 inf가 됨.
- `max_exp=1024` — 2진수 지수부의 최댓값. 2^n 기준으로 2^1023까지 가능.
- `max_10_exp=308` — 10진수 기준으로 10^308까지 표현 가능하다는 의미이며 10^309는 오버플로우이다.
- `min=2.2250738585072014e-308` — 정규화된(normalized) 양의 실수 중 가장 작은 수. 이보다 작으면 비정규화 수가 되어 정밀도가 떨어진다.
- `min_exp=-1021` — 정규화된 수의 지수부 최솟값. 2^(-1021)이 정규화된 수의 하한.
- `min_10_exp=-307` — 10진수 기준으로 10^(-307)까지 정규화된 수로 표현 가능하다.
- `dig=15` — 10진수로 보장되는 유효 자릿수. 15자리까지는 정확하게 왕복 변환이 가능(float → String → float).
- `mant_dig=53` — 가수부(mantissa)의 2진수 비트 수이다.
- `epsilon=2.220446049250313e-16` — 1.0과 그 다음으로 표현 가능한 수의 차이이다. 부동소수점의 정밀도를 나타내며 1.0+epsilon != 1.0이 성립하는 가장 작은 값.
- `radix=2` — 부동소수점의 기수로 항상 2진수.
- `rounds=1` — 반올림 모드를 의미. 1은 가까운 값으로, 동점이면 짝수 쪽으로.

e는 지수를 뜻하는 exponent의 줄임말로, 다르게 표현하면 1.7976931348623157 × 10^308이다.

### 2.3 8비트 부동소수점으로 저장·복구 손실 예시

기본적으로 7.75를 8비트 부동소수점으로 저장하고 복구. 형식: 부호(1) + 지수부(4) + 가수부(3), bias = 7. bias = (2^(n-1))-1, n은 지수부 자릿수로 4.

```
--- 원래 값: 7.75 ---
7.75 = 111.11₂ = 1.1111₂ × 2^2

--- 저장 ---
부호: 0 (양수)
지수부: exp = 2 + 7 = 9 → 1001₂
가수부: 1111에서 3비트만 → 111 (마지막 1 잘림)
결과: 0 1001 111 → 01001111 → 0x4F

--- 복구 ---
부호: 0 → 양수
지수부: 1001₂ = 9 → 실제 지수 = 9 - 7 = 2
가수부: 111 → 1.111₂ (hidden bit 포함)
계산: 1.111₂ × 2^2 = 111.1₂ = 7.5

--- 결론 ---
원래 값: 7.75 / 복구 값: 7.5
손실: 0.25 (가수부 1비트 잘림으로 인한 정밀도 손실)
```

### 2.4 엡실론(epsilon)

1.0과 그 다음으로 표현 가능한 수 사이의 간격. 부동소수점은 연속적이지 않다. 실수를 띄엄띄엄 저장한다.

```python
print(1.0 + sys.float_info.epsilon)
# 1.0000000000000002
```

즉 1.0과 1.0000000000000002 사이에는 아무 수도 표현 못 한다. 그 간격이 바로 엡실론으로 epsilon = 2.220446049250313e-16.

왜 이런 일이 벌어질까? 64비트 float의 가수부는 53비트이며, 1.0 = 1.00000...0₂ × 2^0 (가수부 52비트가 전부 0). 다음 수를 만들려면 가수부 맨 끝에 1비트를 켜야 해. 1.0 다음 수 = 1.00000...1₂ × 2^0, 2^(-52) ≈ 2.22e-16 = epsilon.

```python
# epsilon보다 작은 값을 더하면?
a = 1.0 + 1e-16
print(a == 1.0)  # True (구분 불가!)

# epsilon을 더하면?
b = 1.0 + 2.22e-16
print(b == 1.0)  # False (구분 가능!)

big = 1e10
next_big = big + big * sys.float_info.epsilon
print(next_big - big)  # 약 1.9e-6 (epsilon보다 훨씬 큼!)
```

엡실론과 정밀도:

```python
ep = sys.float_info.epsilon
a = 9.25
diff = (2**3) * ep
print(diff)      # 1.7763568394002505e-15
b = a + diff
print(b)         # 9.250000000000002
half_diff = diff / 2
c = a + half_diff
print(a == c)    # True

a = (2.0)**53
print(a)         # 9007199254740992.0
b = a + 0.1
print(a == b)    # True
```

### 2.5 0.1 + 0.2 != 0.3 — 부동소수점 정밀도 문제

0.1을 이진수로 표현: 0.1₁₀ = 0.0001100110011001100110011...₂ (무한 반복). 0.2를 이진수로 표현: 0.2₁₀ = 0.00110011001100110011...₂ (무한 반복).

값 0.1을 정규화하면 1.1001100110011...₂ × 2^(-4), 실제 저장되는 값은 0.10000000000000000555.... 값 0.2를 정규화하면 1.1001100110011...₂ × 2^(-3), 실제 저장되는 근사값 0.20000000000000001110....

```python
print(f"{0.1:.20f}")        # 0.10000000000000000555
print(f"{0.2:.20f}")        # 0.20000000000000001110
print(f"{0.1 + 0.2:.20f}")  # 0.30000000000000004441
print(f"{0.3:.20f}")        # 0.29999999999999998890

a = 0.1
print(f"{a:.55f}")
# 0.1000000000000000055511151231257827021181583404541015625
print(0.1)         # 0.1 ← 반올림해서 예쁘게 보여줌
print(repr(0.1))   # 0.1 ← 복원 가능한 최소 표현
```

```python
import struct
bits = struct.pack('d', 0.1)
# struct.pack은 파이썬 값을 바이트 메모리로 표현
print(bits)        # b'\x9a\x99\x99\x99\x99\x99\xb9?'
print(bits.hex())  # 9a9999999999b93f
```

### 2.6 2^53 이후 — 정수 정밀도의 한계

```python
a = 2.0 ** 53  # 9007199254740992

print(a + 0.1)  # 9007199254740992.0  ← 0.1 무시
print(a + 0.5)  # 9007199254740992.0  ← 0.5도 무시
print(a + 0.9)  # 9007199254740992.0  ← 0.9도 무시
print(a + 1.0)  # 9007199254740993.0  ← 1은 됨!

b = 2.0 ** 54  # 약 1.8경
print(b + 1)   # 1이 무시됨!
print(b + 2)   # 2는 됨
```

53비트는 유효숫자 약 15~16자리야.

### 2.7 0.1의 비트 분해와 엔디안

```python
val = 0.1
raw = struct.pack('d', val)
as_int = int.from_bytes(raw, 'little')
binary = f"{as_int:064b}"

sign = binary[0]        # 0
exp = binary[1:12]      # 01111111011
mantissa = binary[12:]  # 1001100110011001100110011001100110011001100110011010
```

- 부호: 0 (양수)
- 지수부: 01111111011 (실제 지수 = 1019 - 1023 = -4)
- 가수부: 1001100110011... (무한 반복이 잘린 것)

리틀 엔디안이란 바이트를 메모리에 저장하는 순서. 빅 엔디안은 사람이 읽는 순서, 리틀 엔디안은 거꾸로(Intel CPU 방식).

```
빅 엔디안:   12 34 56 78  (사람이 읽는 순서)
리틀 엔디안: 78 56 34 12  (거꾸로, Intel CPU 방식)
```

## 3. ASCII와 유니코드, 파이썬 문자열의 불변성

출처: `computer_science/chapter/chapter4.py`

### 3.1 아스키 코드

총 7비트로 128개의 문자를 표시할 수 있다. 0-127까지 128개 코드 포인트.

```python
ch = 'A'
bch = ch.encode()
print(bch)     # b'A'
print(bch[0])  # 65 → A와 65가 매핑

ch_0 = '0'
print(ch_0.encode()[0])  # 48
```

int는 32비트 즉 4바이트이며, short는 16비트 즉 2바이트이다. 하지만 아스키코드는 7비트이기에 위의 비트는 낭비이므로 char라는 자료형이 생기게 된 것. char는 정수 자료형이므로 작은 수를 표현하는 데 사용하기도 한다.

### 3.2 유니코드

이때 아스키로는 다양한 사람들이 소통할 수 없었으며, 이 때문에 16비트로 문자를 표현하자는 방식이 된 것이고 65,536개의 문자를 표현할 수 있게 된 것. 이러한 테이블이 유니코드이다. 기존 128까지의 아스키코드와는 일치한다. 이때 유니코드에서 한국어는 U+AC00(가)부터 U+D7AF까지 자리 잡고 있다.

```python
print('가')  # 가
print('각')  # 각
```

코드 유닛은 코드 포인트를 특정한 방법으로 인코딩했을 때 변환되어 얻어지는 비트의 나열을 말한다. 문자 인코딩 방식(CES)은 코드 유닛을 옥텟으로 나열하여 변환하는 방식. 옥텟이란 데이터의 단위로 8비트. 유니코드는 2바이트로 숫자 하나에 문자 하나를 대응하여 문자를 표현한다. 기본 다국어 평면을 포함하여 평면이 열일곱 개 있으므로 모든 문자를 표현하려면 3바이트가 필요.

```python
ch = '가'
print(ch.encode())          # b'\xea\xb0\x80'
print(ch.encode("UTF-8"))   # b'\xea\xb0\x80'
print(ch.encode("UTF-16"))  # b'\xff\xfe\x00\xac'
print(ch.encode("UTF-32"))  # b'\xff\xfe\x00\x00\x00\xac\x00\x00'
```

### 3.3 파이썬 문자열의 불변성

기본적인 언어들은 프로그래머가 변경 가능성을 선택할 수 있다. 하지만 파이썬은 문자열의 요소를 변경할 수 없다.

```python
string = 'abcde'
# string[2] = 'a'
# TypeError: 'str' object does not support item assignment

new_string = string[:2] + 'x' + string[3:]
print(new_string)  # abxde

new_string1 = string.replace('c', 'x')  # 'abxde'
print(string)  # 'abcde' (변경 안 됨)
```

파이썬의 문자열이 불변인 이유는 크게 3가지이다.

1. 메모리의 효율성 — 파이썬은 동일한 문자열을 여러 변수가 공유할 수 있다.

```python
a = 'hello'
b = 'hello'
print(a is b)  # True
```

만약 이렇게 저장하는데 a를 수정하면 b도 의도치 않게 바뀌게 된다.

2. 해시 가능성(Hashable) — 불변이기 때문에 딕셔너리의 키나 set의 요소로 사용 가능. 변경 가능하면 해시값이 바뀔 수 있어서 이런 자료구조를 사용할 수 없다.

3. 스레드 안전성 — 여러 스레드가 같은 문자열을 동시에 읽어도 안전하다. 누군가 바꿀 수 없기 때문이다.

빈번한 문자열 조작이 필요하면 리스트로 변환하여 작업 후 다시 합치는 게 효율적이다.

```python
chars = list(string)   # ['a', 'b', 'c', 'd', 'e']
chars[2] = 'x'         # 리스트는 변경 가능
result = ''.join(chars)  # 'abxde'
```
