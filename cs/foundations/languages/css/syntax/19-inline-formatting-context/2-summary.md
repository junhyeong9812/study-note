# css/syntax/19 — 인라인 서식 문맥 — 행 상자·`vertical-align`·`line-height` — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Inline Layout Module Level 3](https://drafts.csswg.org/css-inline-3/) (행 상자·기준선 정렬·`line-height` 의 정본) · [CSS Display Module Level 3](https://drafts.csswg.org/css-display-3/) (인라인 서식 문맥이 어느 안쪽 값에서 열리나). 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 `demo` 블록 **4개 전부**와 본문의 모든 치수를 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워 `getBoundingClientRect()`·`Range.getClientRects()`·`getComputedStyle` 로 쟀다.\
> ★ **이 주제의 수치는 폰트에 달려 있다.** 이 머신의 `system-ui` 는 **Noto Sans CJK JP** 로 해석됐고(`fc-match` 로 확인), 치수 칸마다 그 사실을 적었다.\
> **WebKit(Safari)은 이 머신에 없고 Firefox 는 이 환경에서 headless 스크린샷이 산출되지 않는다** — 크로스 브라우저 주장은 하지 않았다.
> **버전** — CSS 에는 언어 버전이 없다. 행 상자·`vertical-align`·`line-height` 는 CSS2 부터 있던 오래된 규칙이다.
> **여기서 다루지 않는 것** — `display` 의 바깥/안쪽 값 구조는 [16번](../16-display-inner-outer/2-summary.md)이 정본이고, 여기는 **그 안쪽 값이 `flow` 일 때 줄 안에서 무슨 일이 일어나는가**다. 상자의 네 겹 치수는 [15번](../15-box-model-and-box-sizing/2-summary.md), BFC 는 [17번](../17-block-formatting-context/2-summary.md), 마진 상쇄는 [18번](../18-margin-collapsing/2-summary.md), 계산값이 상속된다는 규칙 자체는 [04번](../04-value-processing-stages/2-summary.md)이다. **줄을 미는 `float` 는 [20번](../20-float-and-clear/2-summary.md)**, 가운데 정렬의 오늘날 답인 flex 축은 [24번](../24-flexbox-axes/2-summary.md)이다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 수치는 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**인라인 서식 문맥(IFC)은 「공책의 줄 위에 글자를 세우는 규칙」이다.**

비유 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 공책에 그어진 밑줄 | **기준선**(baseline) |
| 그 줄 위에 발을 맞춰 선 글자 뭉치 | **인라인 상자**(inline box) |
| 한 줄이 통째로 차지하는 띠 | **행 상자**(line box) |
| 줄과 줄 사이 간격을 얼마로 잡을지 | `line-height` |
| 간격에서 글자 높이를 빼고 **위아래로 반씩 나눠 붙인 여유** | **반쯤 앞선 간격**(half-leading) |
| 밑줄 아래로 내려가는 `g`·`y` 의 꼬리 자리 | **하강부**(descender) — 이미지 아래 틈의 정체 |

```text
   line-height: 40px 인 한 줄

   ┌──────────────────────────────────── 행 상자 위끝
   │        ↕ 8   반쯤 앞선 간격 (위)
   │  ┌─────────────────────────────┐   인라인 상자의 내용 영역 (24)
   │  │   H  x  p                   │
   │  └──────────────┬──────────────┘
   │  ─ ─ ─ ─ ─ ─ ─ ─┴─ ─ ─ ─ ─ ─ ─    기준선 (p 의 꼬리는 이 아래)
   │        ↕ 8   반쯤 앞선 간격 (아래)
   └──────────────────────────────────── 행 상자 아래끝
```

*(Chrome 151 headless 실측 — `font: 16px/40px system-ui`. 내용 영역 높이 **24**, 행 상자 **40**, 위아래 각 **8**.)*

실무에서 이게 터지는 자리는 **"`<img>` 를 `<div>` 에 넣었을 뿐인데 아래에 정체불명의 빈 틈이 생긴다"** 는 증상이다.\
그 틈은 마진도 패딩도 아니다 — **기준선 아래로 내려뻗는 하강부 자리**다((6)에서 실측한다).

> **인라인 서식 문맥(IFC, inline formatting context)** — 상자들이 **한 줄 안에 가로로 늘어서는** 규칙이 도는 구역.\
> 예: 문단(`<p>`) 안에서 `<span>`·글자·`<img>` 가 줄을 따라 놓이는 것이 IFC 다. 블록이 위아래로 쌓이는 [BFC](../17-block-formatting-context/2-summary.md)의 짝이다.

> **행 상자(line box)** — 한 줄이 차지하는 직사각형 띠. **마크업에 대응하는 요소가 없다** — 엔진이 줄을 끊으면서 만든다.\
> 예: 세 줄짜리 문단에는 행 상자가 셋 있다. 어느 요소에도 붙어 있지 않아 CSS 로 직접 고를 수 없다.

> **기준선(baseline)** — 글자가 발을 딛는 가로선. **행 상자 안의 모든 것이 이 선을 기준으로 위아래로 정렬된다.**\
> 예: `H` 의 밑변이 기준선이고, `p` 의 꼬리는 그 아래로 내려간다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. `line-height` 를 키우면 그 여유가 **어디에 어떻게 붙는가** — 그리고 왜 무단위 값만 제대로 상속되는가.
2. 인라인 상자에 `height`·세로 마진·패딩을 주면 **각각 무엇이 되는가.**
3. `vertical-align` 은 **무엇을 기준으로 재는가** — 그리고 `middle` 은 왜 가운데가 아닌가.

## 동작 방식

### (1) 행 상자와 인라인 상자 — 이름이 비슷한 다른 상자다

**언제 쓰나** — 「줄 높이가 왜 이렇게 되지?」를 따질 때. **둘을 구분하지 못하면 나머지 절이 전부 안 읽힌다.**

```text
  <p>앞 <span>가운데</span> 뒤</p>

  +=====================================================+  행 상자 (엔진이 만든다)
  |  [ 앞 ]   [ 가운데 ]   [ 뒤 ]                       |
  |   익명     <span> 이   익명                          |
  |  인라인    만든 인라인  인라인                        |
  |   상자      상자        상자                         |
  +=====================================================+
      ↑ 행 상자의 높이 = 안에 든 인라인 상자들을 전부 담을 만한 높이
```

- **인라인 상자**는 요소(또는 벌거벗은 글자 뭉치)가 만드는 상자다. `<span>` 하나 = 인라인 상자 하나.
- **행 상자**는 **요소가 아니다.** 엔진이 줄을 끊으며 만드는 띠라 선택자로 고를 수 없다.
- 그래서 「줄 높이를 바꾸고 싶다」는 **행 상자를 직접 건드릴 수 없고**, 그 안의 인라인 상자들의 `line-height` 를 바꿔서만 된다.

★ **글자가 하나도 없어도 행 상자에는 키가 있다** — **스트럿**(strut) 때문이다.

> **스트럿(strut)** — 블록이 자기 `font`·`line-height` 로 만들어 행 상자 맨 앞에 세워 두는 **보이지 않는 0폭 인라인 상자**.\
> 예: 빈 `<div>` 안에 20px 짜리 상자 하나만 넣어도 줄 높이가 20 이 아닌 이유가 이것이다 — 스트럿이 같이 서 있다.

비용 — 행 상자의 높이는 **안에 든 것들의 정렬이 전부 끝나야** 정해진다. 그래서 `vertical-align` 하나를 바꾸면 줄 높이가 통째로 흔들린다((5)).

### (2) `line-height` 의 여유는 위아래로 반씩 나뉘어 붙는다

**언제 쓰나** — 줄 간격을 조절할 때. 그리고 **「글자 위에만 간격이 생긴다」고 오해했을 때.**

```text
  line-height 가 24 (= 내용 영역과 같다)      line-height 가 40

  ┌───────────────────┐ 행 상자 24           ┌───────────────────┐ 행 상자 40
  │┌─────────────────┐│                      │      ↕ 8          │  ← 반쯤 앞선 간격
  ││  내용 영역 24   ││                      │┌─────────────────┐│
  │└─────────────────┘│                      ││  내용 영역 24   ││
  └───────────────────┘                      │└─────────────────┘│
    위 0 / 아래 0                             │      ↕ 8          │
                                              └───────────────────┘
                                                 위 8 / 아래 8
```

계산은 한 줄이다 — **반쯤 앞선 간격 = (`line-height` − 내용 영역 높이) ÷ 2**, 그 값을 **위아래로 똑같이** 붙인다.

```html demo
<p class="tight"><span>line-height 가 1 이면 줄이 이렇게 된다 여기까지 두 줄</span></p>
<p class="loose"><span>line-height 가 2.5 면 줄이 이렇게 된다 여기까지 두 줄</span></p>
<style>
  p { width: 240px; font-family: system-ui; font-size: 16px;
      margin: 0 0 16px; background: #e5e7eb; }
  p span { background: #93c5fd; }
  .tight { line-height: 1; }
  .loose { line-height: 2.5; }
</style>
```

> **보이는 것** — 두 문단 다 **두 줄**이다. 위 문단에서는 파란 띠 두 개가 **서로 겹쳐** 회색 문단 배경이 한 점도 안 보이고, 파란색이 **문단 위아래로 삐져나와** 있다. 아래 문단에서는 파란 띠 두 개 **위·사이·아래에 회색 띠가 뚜렷하게** 보인다.\
> **바꿔 볼 것** — `.tight` 의 `1` → `normal` (겹침이 사라지고 띠 두 개가 **딱 맞닿는다**) · `.loose` 의 `2.5` → `2.5em` (겉보기는 같지만 상속 결과가 달라진다 — (3))

*(Chrome 151 headless 실측 — `line-height: 1` 문단(높이 32)의 두 띠가 **y −4\~20 과 12\~36** 으로 **8px 겹쳤고 문단 밖으로 4px 씩 삐져나왔다.** `2.5` 문단(높이 80)의 두 띠는 **y 8\~32 와 48\~72** 로 **16px 떨어졌다.**)*

*(Chrome 151 headless 실측 — `font: 16px system-ui` 에서 내용 영역 높이는 **24**. `line-height: 1`(=16px) 이면 반쯤 앞선 간격이 **−4** 로 음수가 되어 내용이 행 상자를 위아래로 4씩 삐져나온다. `line-height: 2`(=32px) 이면 **+4**, `40px` 이면 **+8** 이다. `normal` 은 이 폰트에서 **24** 로 내용 영역과 같아 간격이 **0** 이다.)*

- ★ **`line-height` 를 내용 영역보다 작게 주면 반쯤 앞선 간격이 음수가 된다.** 글자가 잘리는 게 아니라 **행 상자 밖으로 넘쳐 겹친다.**
- 그래서 `line-height: 1` 은 「딱 맞는다」가 아니라 **「4px 씩 넘친다」**(이 폰트 기준)이다.
- 「위에만 붙이고 싶다」는 `line-height` 로 안 된다 — 언제나 반씩이다. 그건 패딩이나 `margin` 의 일이다.

비용 — 공짜다. 다만 **행 상자 높이가 바뀌면 그 아래 모든 줄이 다시 흐른다.**

### (3) 무단위 `line-height` 만 「비율」로 상속된다

**언제 쓰나** — 부모에 줄 간격을 걸고 자식 글자 크기를 바꿨을 때. **리셋 CSS 가 무단위를 쓰는 이유가 이것이다.**

```text
  부모: font-size 20px

  line-height: 1.5   (무단위)      line-height: 30px      line-height: 150%
        ↓ 상속되는 것은                   ↓                      ↓
      숫자 1.5 그 자체                 30px                  30px
        ↓ 자식(font-size 40px)          ↓                      ↓
      1.5 × 40 = 60px                 30px                  30px
```

*(Chrome 151 headless 실측 — 부모 `font-size:20px` 에 세 가지를 각각 걸고 `font-size:40px` 인 자식을 넣었다. **세 부모의 계산값은 모두 `30px` 으로 똑같다.** 자식의 계산값은 무단위만 **`60px`**, 나머지 둘은 **`30px`** 이었다. 자식 행 상자 높이도 60 / 30 / 30.)*

- **상속되는 것은 계산값이다**([04번](../04-value-processing-stages/2-summary.md)). `line-height` 는 **무단위 값일 때만 「숫자」 그대로가 계산값**이고, `px`·`em`·`%` 는 그 자리에서 픽셀로 굳는다.
- 그래서 `%` 와 `em` 은 **겉보기가 무단위와 같은데 결과가 다르다** — 부모에서 픽셀이 되어 버린 뒤 그 픽셀이 내려간다.
- ★ **부모의 계산값만 찍어 보면 셋을 구분할 수 없다**(전부 `30px`). **자식에서 찍어야 갈린다.**

비용 — 없다. 무단위가 사실상 언제나 정답이다.

### (4) 인라인 비대체 요소에는 `height` 도 세로 마진도 안 먹는다

**언제 쓰나** — `<span>` 에 높이를 줬는데 아무 일도 안 일어날 때. [16번](../16-display-inner-outer/2-summary.md)의 「`width` 가 안 먹는다」의 세로 짝이다.

```text
  <span> 에 무엇을 주면 무엇이 되나

  width / height  ──────> 아무 일도 안 일어난다 (에러 없음)
  margin-top / bottom ──> 아무 일도 안 일어난다
  margin-left / right ──> 먹는다 (가로는 먹는다)
  padding-top/bottom ───> 그려지긴 한다. 그런데 행 상자 높이는 안 늘어난다 → 이웃 줄과 겹친다
  border-top/bottom ────> 같다. 그려지고, 겹친다
```

```html demo
<p>앞줄 채우는 글 앞줄 채우는 글 앞줄 채우는 글 앞줄 채우는 글
<span class="pad">패딩 20</span> 뒷줄 채우는 글 뒷줄 채우는 글 뒷줄 채우는 글 뒷줄 채우는 글</p>
<style>
  p { width: 240px; font: 16px/1.5 system-ui; background: #e5e7eb; margin: 0; }
  .pad { background: #93c5fd; padding: 20px 6px; }
</style>
```

> **보이는 것** — 파란 상자가 **위아래 줄의 글자를 덮고 있다.** 글자들이 파란 상자를 피해 비켜나지 않았다 — 줄은 **평소 간격 그대로**이고 파란 상자만 두꺼워져 그 위를 지나간다.\
> **바꿔 볼 것** — `padding: 20px 6px` → `margin: 20px 6px` (**아무 일도 안 일어난다** — 세로 마진은 무시된다) · `.pad` 에 `display: inline-block` 추가 (그때는 줄 간격이 실제로 벌어진다)

*(Chrome 151 headless 실측 — 같은 `<span>` 을 네 가지로 재 봤다. 보통: `rect` 24 높이, 부모 줄 높이 **24**. `padding: 20px 6px`: `rect` **64** 높이인데 부모 줄 높이는 여전히 **24** — 행 상자가 한 픽셀도 안 늘었다. `border: 10px`: `rect` **44**, 부모 **24**. `margin: 20px 6px`: `rect` **24**, 위치도 그대로 — **세로 마진이 통째로 무시됐다.** `width:200px; height:80px`: `rect` **73.61 × 24** 로 안 먹었다.)*

- ★ **`getComputedStyle` 은 `width: 200px` / `height: 80px` 을 그대로 돌려줬다.** **값은 담겼는데 레이아웃이 안 쓴 것**이다 — 진단 3창의 셋째 창(`getComputedStyle`)만 보면 **「먹었다」로 오진한다.**
- **가로는 먹고 세로는 안 먹는다.** 인라인 상자는 줄 안에서 가로로만 자리를 차지하기로 돼 있기 때문이다.
- 치수를 주고 싶으면 안쪽 값을 `flow-root` 로 바꾼다(= `inline-block` — [16번](../16-display-inner-outer/2-summary.md)).

비용 — 세로 패딩·테두리는 **그려지되 줄을 안 민다.** 이웃 줄을 덮는 사고의 원인이고, 배경색이 있으면 바로 보인다.

### (5) `vertical-align` 의 기준은 부모의 기준선 — `middle` 은 가운데가 아니다

**언제 쓰나** — 아이콘을 글자 옆에 세로로 맞출 때. **이 주제에서 가장 많이 당하는 자리다.**

```text
  기준이 무엇인가 — 값마다 다르다

                      ┌── top / bottom      : 행 상자의 위/아래끝
  행 상자 위끝 ───────┤
                      ├── text-top/bottom   : 부모 인라인 상자 내용 영역의 위/아래끝
   부모 내용 영역 ────┤
                      ├── middle            : 부모 기준선 + 부모 x-높이의 절반
  ─ ─ 기준선 ─ ─ ─ ─ ─┤
                      ├── baseline (기본)   : 부모 기준선에 내 밑변을 맞춘다
  행 상자 아래끝 ─────┘   <길이>/<%>         : 기준선에서 그만큼 위로
```

*(Chrome 151 headless 실측 — `font: 40px/60px system-ui` 인 줄에 20×20 상자를 넣고, 0폭 기준선 표식을 같이 세워 쟀다. 행 상자 60, 기준선은 행 상자 위끝에서 **47**.)*

| 값 | 상자 밑변이 기준선에서 | 상자 중심이 **행 상자 한가운데**에서 |
|---|---|---|
| `baseline` | **0** (딱 맞는다) | **+7.00** 아래 |
| `middle` | **−0.86** | **+6.14** 아래 |
| `top` | −27.00 | −20.00 위 |
| `bottom` | +13.00 | +20.00 아래 |
| `text-top` | −26.00 | −19.00 위 |
| `text-bottom` | +12.00 | +19.00 아래 |
| `super` | −14.33 | −7.33 위 |
| `10px` | −10.00 | −3.00 위 |

- ★★ **`middle` 을 줘도 상자 중심이 행 상자 한가운데에서 6.14px 아래에 있다.** 「가운데 정렬」이 아니다.
- `middle` 의 정의는 「**부모의 기준선 + 부모 x-높이의 절반**」이다. 실측에서 상자 중심이 기준선보다 **10.86px 위**였으니, 이 폰트의 40px 기준 x-높이는 **21.72px** 이다.
- 그래서 **폰트를 바꾸면 `middle` 의 위치가 움직인다.** 가운데 정렬을 원하면 이 속성이 아니라 [flex 의 `align-items`](../24-flexbox-axes/2-summary.md)를 쓴다.
- `top`/`bottom` 은 **행 상자** 기준, `text-top`/`text-bottom` 은 **부모 내용 영역** 기준이다 — 위 표(`line-height: 60px`)에서는 1px 씩밖에 안 달랐다(−27 대 −26, +13 대 +12).
- ★ **`line-height` 만 100px 으로 키워 다시 재면 그 차이가 21px 로 벌어진다**(실측). 반쯤 앞선 간격이 두 기준점 **사이에** 끼어들기 때문이다. **촘촘한 줄에서만 재 보고 「둘이 같다」고 외우면 틀린다.**

```html demo
<p>Hx<span class="v" style="vertical-align:baseline"></span><span class="v"
  style="vertical-align:middle"></span><span class="v"
  style="vertical-align:top"></span><span class="v"
  style="vertical-align:bottom"></span>Hx</p>
<style>
  p { width: 300px; font: 30px/70px system-ui; background: #e5e7eb; margin: 0; }
  .v { display: inline-block; width: 34px; height: 34px; background: #ef4444; }
</style>
```

> **보이는 것** — 빨간 정사각형 넷이 **한 줄 안에서 전부 다른 높이**에 서 있어 계단처럼 보인다. 첫째(`baseline`)는 양옆 `Hx` 글자의 **밑변에 딱 맞춰** 서 있고, 둘째(`middle`)는 첫째보다 **오히려 조금 내려가** 있다. 셋째(`top`)는 회색 띠의 **맨 위**에, 넷째(`bottom`)는 **맨 아래**에 붙는다. **넷 중 어느 것도 회색 띠의 정확한 한가운데가 아니다.**\
> **바꿔 볼 것** — `.v` 의 `height` 를 `16px` 로 줄이면 **첫째와 둘째가 거의 같은 높이가 된다**(둘의 차이는 상자 높이에 따라 달라진다) · `top` → `text-top` (조금 내려온다 — 기준이 행 상자에서 부모 내용 영역으로 바뀐다)

*(Chrome 151 headless 실측 — 행 상자 높이 70, 문단 위끝 기준 상자 위쪽 y: `baseline` **14.00** · `middle` **22.86** · `top` **0.00** · `bottom` **36.00**. 행 상자 한가운데는 35 인데 네 상자의 중심은 **31 · 39.86 · 17 · 53** 으로 하나도 안 맞는다.)*

비용 — `vertical-align` 을 하나만 바꿔도 **행 상자 높이가 통째로 다시 계산된다**(가장 위까지·가장 아래까지를 담아야 하므로).

### (6) 이미지 아래 생기는 정체불명의 틈 — 실측 5px

**언제 쓰나** — `<img>` 를 감싼 상자가 이미지보다 몇 px 더 높을 때. **이 주제의 대표 사고다.**

```text
  <div><img (높이 50)></div>     이 div 의 높이가 50 이 아니다

  ┌──────────────────────────┐  div
  │  ┌────────────────────┐  │
  │  │      이미지 50      │  │   <img> 는 기본이 인라인이다
  │  └────────────────────┘  │   → 밑변이 기준선에 맞춰진다
  │  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │   ← 기준선
  │         ↕ 5              │   ← 기준선 아래 하강부 자리가 남는다
  └──────────────────────────┘  div 높이 55
```

```html demo
<div class="before"><img src="data:image/gif;base64,R0lGODlhCAAIAIAAAAAAAP///yH5BAEAAAAALAAAAAAIAAgAAAIIhI+py+0PYysAOw=="></div>
<div class="after"><img src="data:image/gif;base64,R0lGODlhCAAIAIAAAAAAAP///yH5BAEAAAAALAAAAAAIAAgAAAIIhI+py+0PYysAOw=="></div>
<style>
  div { width: 120px; background: #ef4444; margin-bottom: 12px; font: 16px/1.5 system-ui; }
  img { width: 90px; height: 50px; background: #1e3a8a; }
  .after img { display: block; }
</style>
```

> **보이는 것** — 두 상자 모두 남색 이미지를 담고 있다. 위 상자는 **이미지 아래에 빨간 띠가 한 줄 남아** 보이고, 아래 상자는 **빨간색이 전혀 안 보인다** — 남색 이미지가 상자를 꽉 채운다.\
> **바꿔 볼 것** — `.after img` 의 `display: block` → `vertical-align: bottom` (**똑같이 사라진다**) · `.after` 에 `line-height: 0` 을 주고 `display: block` 을 지워도 사라진다

*(Chrome 151 headless 실측 — `font: 16px/1.5 system-ui`, 이미지 50px. **부모 높이 55, 틈 5.** 고치는 법 셋은 전부 **부모 높이 50, 틈 0** 이었다.)*

★ **틈의 크기는 4px 이 아니다 — 상수가 아니기 때문이다.** 기준선 아래 남는 자리이므로 **폰트·글자 크기·줄 간격이 전부 영향을 준다.**

| 부모 선언 | 틈 | 왜 |
|---|---|---|
| `16px/1.5 system-ui` | **5** | 이 폰트의 16px 하강부 |
| `32px/1.5 system-ui` | **10** | 글자 크기에 비례한다 |
| `16px/3 system-ui` | **17** | 하강부 5 + 아래쪽 반쯤 앞선 간격 12 |
| `16px/0.5 system-ui` | **0** | 반쯤 앞선 간격이 음수라 하강부를 삼켰다 |
| `16px/1.5 serif` | **6** | **폰트가 바뀌면 값도 바뀐다** |

- 「이미지 아래 **4px**」은 **옛 폰트 환경에서 외운 수치**다. 이 머신에서는 5 였다. **수치가 아니라 「기준선 아래 자리」로 외워야** 한다.

고치는 법 셋을 대조하면 **무엇을 끄는지가 각각 다르다.**

| 고치는 법 | 무엇을 끄나 | 대가 |
|---|---|---|
| `img { display: block }` | 이미지를 **IFC 밖으로 꺼낸다** | 줄 안에 글자와 나란히 못 둔다 |
| `img { vertical-align: bottom }` | 밑변을 **기준선이 아니라 행 상자 아래끝**에 맞춘다 | 같은 줄의 글자와 밑변이 안 맞는다 |
| 부모에 `line-height: 0` | **스트럿의 키를 0 으로** 만들어 기준선 아래 자리를 없앤다 | **상속된다** — 안의 글자 줄 간격까지 0 이 된다 |

비용 — 셋 다 공짜지만 **부작용이 다르다.** 이미지 하나만 있는 상자면 `display: block`, 글자와 섞이는 줄이면 `vertical-align: bottom` 이 안전하다.

## 문법 — 형태와 어디서 헷갈리나

### 최소 형태

```css
p  { line-height: 1.5; }          /* 무단위 — 비율이 상속된다 */
img{ vertical-align: bottom; }    /* 기준선 대신 행 상자 아래끝에 맞춘다 */
```

### 헷갈리는 자리 ① — 어느 요소에 걸어야 하나

```text
  <p style="line-height: 3">앞 <span style="line-height: 1">가운데</span> 뒤</p>

  행 상자 높이 = 안에 든 인라인 상자들의 정렬 결과를 전부 담을 만한 높이
                = max(스트럿 48, 「앞/뒤」 48, <span> 16 …)  → 48
```

- ★ **자식 하나만 `line-height` 를 줄여도 줄이 안 줄어든다.** 부모의 **스트럿**이 그대로 크기 때문이다.
- 줄을 줄이려면 **부모에 걸어야** 한다.

### 헷갈리는 자리 ② — 세 가지 「높이」

```text
  getComputedStyle(span).height      선언한 값을 그대로 돌려줄 수 있다 (안 먹어도!)
  span.getBoundingClientRect().height 인라인 상자가 실제로 차지한 세로 (패딩·테두리 포함)
  부모.getBoundingClientRect().height 행 상자들의 합 — 이것이 「줄 높이」다
```

실측에서 셋이 각각 `80px` · `24` · `24` 로 **전부 달랐다**((4)).

### 금지에 가까운 형태

```css
.icon { vertical-align: middle; }      /* 「가운데」가 아니다 — 폰트마다 움직인다 (5) */
.row  { line-height: 0; }              /* 이미지 틈은 사라지지만 글자 줄 간격까지 죽는다 */
span  { height: 40px; }                /* 아무 일도 안 일어난다 (4) */
```

## 구현 세부사항 대 언어 보장

- **「반쯤 앞선 간격을 위아래로 반씩 나눈다」는 명세다.** CSS Inline Layout Level 3 의 행 상자 규정이 근거다.
- ★ **「내용 영역의 높이가 얼마인가」는 폰트가 정한다.** 이 머신의 `system-ui`(**Noto Sans CJK JP**)에서 16px 글자의 내용 영역이 24 였다 — **CSS 의 보장이 아니라 그 폰트 파일의 수치**다. 폰트를 바꾸면 이 문서의 8·−4·5 가 전부 움직인다.
- ★ **「이미지 아래 4px」은 어느 명세에도 없다.** 위 표대로 **폰트·크기·줄 간격에 따라 0\~17 로 움직였다.** 상수로 외우면 안 된다.
- ★ **`middle` 의 x-높이도 폰트의 것이다.** 실측 21.72px 은 이 폰트의 40px 기준값이다.
- **`getComputedStyle().height` 가 안 먹는 선언을 그대로 돌려주는 것**은 이 브라우저에서 관찰한 것이다. 계산값 API 의 정본은 CSSOM 이고, 이 목록은 선언적 CSS 만 다룬다([04번](../04-value-processing-stages/2-summary.md)).

## 어디서 틀리나

### 1. `line-height: 1` 을 「딱 맞는다」로 안다

이 폰트에서는 **위아래로 4px 씩 넘친다**((2) 실측). 넘친 부분은 이웃 줄과 겹친다.\
「딱 맞는」 값은 `1` 이 아니라 **그 폰트의 내용 영역 높이**이고, 그건 `normal` 이 알아서 쓴다.

### 2. `line-height` 를 `em`·`%` 로 준다

부모에서 픽셀로 굳어 내려가므로 **글자 크기가 다른 자식에서 줄이 무너진다**((3) 실측: 자식 30px 대 60px).\
무단위를 쓴다.

### 3. `<span>` 에 `height` 를 주고 「안 먹네」 하고 넘어간다

에러가 없어서 그냥 지나간다. **`getComputedStyle` 은 `80px` 이라고 대답까지 한다.**\
`rect` 를 재야 안 먹은 것이 드러난다 — 진단 3창의 셋째 창만 믿으면 안 되는 대표 사례다.

### 4. `vertical-align: middle` 을 가운데 정렬로 쓴다

실측에서 **6.14px 아래**였다((5)). 게다가 폰트를 바꾸면 값이 움직인다.\
줄 안에서 세로 가운데가 정말 필요하면 그 부모를 flex 로 만들고 `align-items: center` 를 쓴다([24번](../24-flexbox-axes/2-summary.md)).

### 5. 이미지 아래 틈을 마진·패딩으로 안다

**마진도 패딩도 아니다.** 부모에 `padding: 0` 을 줘도 안 없어진다 — 기준선 아래 하강부 자리다((6)).\
증상은 「`margin-bottom: -4px` 로 때웠는데 폰트를 바꾸니 다시 어긋난다」로 나타난다.

### 6. 자식에 `line-height` 를 줄이고 줄이 안 줄었다고 한다

부모의 **스트럿**이 남아 있다. 부모에 걸어야 한다.

## 언제 쓰고 언제 안 쓰나

| 하고 싶은 것 | 고르는 것 | 왜 |
|---|---|---|
| 문단 줄 간격을 조절한다 | `line-height` **무단위** | 글자 크기가 다른 자식에서도 비율이 유지된다 |
| 줄 안 아이콘을 글자 밑변에 맞춘다 | `vertical-align: baseline`(기본) | 글자와 함께 움직인다 |
| 줄 안 아이콘을 줄 아래끝에 맞춘다 | `vertical-align: bottom` | 행 상자 기준이라 폰트에 안 흔들린다 |
| **세로 가운데 정렬** | flex `align-items: center` | `middle` 은 가운데가 아니다([24번](../24-flexbox-axes/2-summary.md)) |
| 이미지 아래 틈을 없앤다 | `img { display: block }` | 이미지를 줄 밖으로 꺼낸다 |
| 줄 안에 두면서 틈만 없앤다 | `img { vertical-align: bottom }` | 줄 안에 남는다 |
| 인라인 요소에 치수를 준다 | `display: inline-block` | 인라인에는 `height` 가 안 먹는다([16번](../16-display-inner-outer/2-summary.md)) |

판단 규칙 두 줄.

- **줄 안의 세로 문제는 전부 「기준선이 어디냐」로 환원된다.** 기준선을 안 쓰는 답(`bottom`·flex)이 대개 더 안전하다.
- **수치를 외우지 말고 재라.** 이 주제의 모든 상수는 폰트의 것이다.

## 핵심 문장

- **행 상자는 요소가 아니다** — 엔진이 줄을 끊으며 만든 띠라 선택자로 고를 수 없다. 그 안의 인라인 상자를 통해서만 건드린다.
- `line-height` 의 여유는 **위아래로 정확히 반씩** 붙는다(반쯤 앞선 간격). **음수도 된다** — `line-height: 1` 은 이 폰트에서 4px 씩 넘쳤다.
- ★ **무단위 `line-height` 만 「숫자」로 상속된다.** `%`·`em` 은 부모에서 픽셀로 굳는다 — **부모의 계산값만 보면 셋이 똑같다.**
- 인라인 비대체 요소에는 **`height`·세로 마진이 안 먹고**, 세로 패딩·테두리는 **그려지되 줄을 안 민다.**
- ★ **`vertical-align: middle` 은 가운데가 아니다** — 「부모 기준선 + x-높이 절반」이고, 실측에서 행 상자 한가운데보다 **6.14px 아래**였다.
- ★ **이미지 아래 틈은 마진이 아니라 기준선 아래 하강부 자리**이고, 이 머신에서 **5px**(4가 아니다)이었으며 **폰트·크기·줄 간격에 따라 0\~17 로 움직였다.**

## 용어 풀이

- **인라인 서식 문맥(IFC)** — 상자들이 한 줄 안에 가로로 늘어서는 규칙이 도는 구역. BFC 의 짝이다.
- **행 상자(line box)** — 한 줄이 차지하는 띠. **요소가 아니라 엔진이 만든 것**이라 선택자로 못 고른다.
- **인라인 상자(inline box)** — 인라인 요소나 벌거벗은 글자 뭉치가 만드는 상자. 행 상자 안에 놓인다.
- **익명 인라인 상자(anonymous inline box)** — 요소로 감싸지 않은 맨 글자가 만드는 인라인 상자.
- **기준선(baseline)** — 글자가 발을 딛는 가로선. 행 상자 안의 정렬은 전부 이 선이 기준이다.
- **스트럿(strut)** — 블록이 자기 `font`·`line-height` 로 행 상자 맨 앞에 세우는 보이지 않는 0폭 인라인 상자. 글자가 없어도 줄에 키가 있는 이유.
- **내용 영역(content area)** — 인라인 상자에서 글자가 실제로 그려지는 세로 범위. 높이는 **폰트가 정한다**(이 머신 `system-ui` 16px 에서 24).
- **반쯤 앞선 간격(half-leading)** — (`line-height` − 내용 영역 높이) ÷ 2. 위아래에 똑같이 붙는다. **음수가 될 수 있다.**
- **하강부(descender)** — 기준선 아래로 내려가는 글자 부분(`g`·`y`의 꼬리). **이미지 아래 틈의 정체.**
- **x-높이(x-height)** — 소문자 `x` 의 높이. `vertical-align: middle` 이 쓰는 기준이며 폰트마다 다르다.
- **대체 요소(replaced element)** — 내용이 CSS 밖에서 오는 요소(`<img>`·`<video>`·`<input>`). **인라인이어도 치수가 먹는다** — 그래서 `<img>` 는 `height` 가 적용된다.

## 더 들어가면

- **행 상자의 높이를 직접 정하는 속성은 없다.** CSS Inline Layout Level 3 에는 `line-fit-edge`·`text-box-trim` 처럼 **내용 영역의 어디를 기준으로 삼을지** 바꾸는 새 속성이 들어와 있다. 이 문서는 **실행으로 확인한 것만** 적으므로 이름만 적어 둔다(**안 돌려 봄** — 이 배치에서 다루는 범위 밖이다).
- **`vertical-align` 은 상속되지 않는다.** 그래서 부모에 걸어도 자식 아이콘이 안 움직인다. `line-height` 와 헷갈리기 쉽다.
- **기준선은 블록에도 있다.** `inline-block` 상자의 기준선은 **그 안 마지막 행 상자의 기준선**이고, 안에 줄이 없거나 `overflow` 가 `visible` 이 아니면 **자기 아래 margin 끝**이 기준선이 된다. 그래서 [23번](../23-overflow-and-scroll-containers/2-summary.md)의 `overflow` 하나가 줄 정렬을 바꿔 놓는 자리가 있다.
- **`text-align` 은 행 상자 안의 가로 배치**다. 이 문서가 다룬 세로 배치와 축이 다르다.
