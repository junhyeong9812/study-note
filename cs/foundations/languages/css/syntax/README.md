## 이 언어에서 무엇을 자르는 축

CSS 는 문법 언어가 아니다. 문법 표면은 「선택자 { 속성: 값 }」 한 줄로 끝나고, 실제로 배울 것은 **그 선언들이 어떤 순서로 이겨서 하나의 값이 되고, 그 값이 어떤 상자를 만들고, 그 상자가 어떤 파이프라인을 다시 돌게 하는가** — 곧 **계산 모델**이다. 그래서 축을 명세의 모듈 목록(cascade / selectors / box / flexbox / grid / color / transitions …)을 그대로 따르지 않고 **엔진이 값을 정하는 순서**로 세웠다.

`01` 이 **캐스케이드와 우선순위 계산**인 것은 우연이 아니다. CSS 에서 나는 사고의 대부분은 「왜 내 스타일이 안 먹지」이고, 그 답은 언제나 출처·레이어·명시도·순서 네 층으로 이뤄진 한 알고리즘 안에 있다. 선택자(`08`\~`14`)는 그 알고리즘의 **입력을 만드는 도구**이고, `:is()`/`:where()`/`:has()` 가 어렵게 느껴지는 이유도 문법이 아니라 **명시도에 어떻게 기여하는가**에 있다. 그래서 여러 주제가 `01` 또는 `02` 를 선행으로 건다.

그 위에 **박스·레이아웃**(`15`\~`32`)이 선다. 이 갈래가 가장 두꺼운 것은 CSS 의 실제 면적이 여기에 있기 때문이다 — `display` 가 무엇을 만들고, 서식 문맥이 무엇을 가두고, flex 와 grid 가 남는 공간을 어떻게 나누는가. **반응형·단위**(`33`\~`41`)는 그 상자의 치수를 조건에 따라 바꾸는 층이고, **시각 효과**(`42`\~`51`)는 상자가 정해진 뒤 그 위에 칠해지는 층이다.

마지막 **애니메이션**(`52`\~`60`)을 크게 잡았다. 여기서 갈리는 것은 문법이 아니라 **어느 속성을 건드리면 레이아웃부터 다시 돌고, 어느 속성은 합성 단계만으로 끝나는가**이며, 이것을 모르면 「동작은 하는데 끊긴다」는 증상 앞에서 할 수 있는 게 없다. `transform`·`opacity` 와 `width`·`top` 의 차이, `will-change` 가 사는 비용, 스크롤 연동 애니메이션과 뷰 전환이 왜 선언적으로 들어왔는지가 이 갈래의 뼈대다.

**「언제 들어왔나」는 여기가 아니다.** Flexbox 가 2012\~2017 에 어떻게 표준화됐는지, CSS3 가 왜 버전을 버리고 모듈로 쪼개졌는지, 컨테이너 쿼리가 왜 반응형의 다음 단계로 불리는지는 [`history/web/03-HTML-CSS-진화.md`](../../../../../history/web/03-HTML-CSS-진화.md) 의 몫이다. 이 목록은 **어떻게 쓰고 무엇을 못 하나**만 다룬다.

## 버전·지원 기준

CSS 에는 언어 버전이 없다(「CSS3」는 2000년대에 버려진 표현이다 — [`history/web/03`](../../../../../history/web/03-HTML-CSS-진화.md) §2.3). 대신 **모듈별 명세 단계**와 **브라우저 Baseline** 두 축으로 기준을 잡는다.

- **기준선**: Baseline **widely available**(주요 엔진 전부에서 30개월 이상) 인 것을 「그냥 써도 되는 것」으로 본다.
- **newly available** 인 것은 주제 이름·3파일에 「**Baseline newly, 저변 도달 시점 <날짜>**」를 명시한다.
- **limited** 인 것은 목록에서 뺐고(위 표), 뺀 근거를 아래에 남긴다.

**limited 라서 목록에서 뺀 것** (같은 조회)

| 기능 | Baseline | 실제 구현 상태 |
|---|---|---|
| 스크롤 연동 애니메이션 | **limited** | Chrome 115(2023-07)·Safari 26(2025-09) 에 있고 **Firefox 미구현**. `58` 로 **남겼다** — 이 갈래를 통째로 빼면 애니메이션 축이 무너지고, Chrome·Safari 두 엔진에서 실물 확인이 되기 때문이다. 3파일에 「Baseline limited, Firefox 미구현」을 명시한다 |
| 문서 간 뷰 전환 | **limited** | `59` 는 동일 문서 전환까지만 다루고 문서 간은 언급만 |
| 앵커 위치 지정 | **limited** | Chromium 계열만. 개발자 요구(developer-signals upvote 257)가 가장 높은 축에 속하므로 **다음 라운드 후보**로 남긴다 |
| Masonry / Grid lanes | **limited** | 문법 자체가 미확정 |
| `@function`·링크 파라미터·`paint()` | **limited** | 에디터 초안 |
| `text-wrap: pretty` | **limited** | `51` 안에서 `balance` 와 대비해 한 줄로만 |
| `accent-color` | **limited** | 폼 컨트롤 스타일링 갈래와 함께 보류 |
| 커스터마이즈 가능 `select`(`::picker()`) | **limited** | HTML 26 에서 마크업만 |

**확인하지 못한 것** — 없다. 위 표의 모든 행은 API 응답에서 직접 읽은 값이다. 다만 **`webstatus.dev` 자체가 2차 집계**라는 점은 남겨 둔다. 개별 기능의 「명세가 무엇을 요구하나」는 CSSWG 초안으로, 「내 브라우저에서 실제로 되나」는 이 머신의 Chrome 151 · Firefox 155 로 각각 다시 확인한다. **Safari/WebKit 은 이 머신에 없어 실행 확인이 불가**하므로, Safari 가 마지막으로 따라온 기능(`@scope`·`backdrop-filter`·뷰 전환)은 Baseline 날짜로만 접지한다.
