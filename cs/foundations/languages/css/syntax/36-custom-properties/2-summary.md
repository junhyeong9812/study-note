# css/syntax/36 — 사용자 정의 속성: 선언·`var()`·대체값·상속 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Custom Properties for Cascading Variables Level 1](https://drafts.csswg.org/css-variables-1/) 의 「Defining Custom Properties」·「Using Cascading Variables」·「Invalid Variables」 절과 [CSS Cascading and Inheritance Level 5](https://drafts.csswg.org/css-cascade-5/) 의 「invalid at computed-value time」 정의. 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 모든 값은 **Google Chrome 151.0.7922.173** headless 에 띄워 **네 창**으로 읽은 것이다 — `cssRules[i].style`(**무엇이 담겼나**) · `cssRules[i].style.getPropertyValue('--x')`(**변수에 무엇이 담겼나**) · `getComputedStyle(el).getPropertyValue('--x')`(**변수의 계산값**) · `getComputedStyle(el).color`(**쓰는 쪽이 무엇이 됐나**). **넷이 다른 자리가 이 주제의 값이다.** **손으로 계산해 유도한 수치는 없다.**\
> **엔진은 Chrome 하나다** — Firefox 155.0.1 은 이 환경에서 headless 산출이 조용히 실패하고 WebKit 은 이 머신에 없다. 「두 엔진에서 확인했다」고 적지 않는다.
> **버전** — CSS 에 언어 버전은 없다. 커스텀 속성은 오래전에 자리잡아 [목록 README](../README.md) 의 지원 표에 별도 행이 없을 만큼 보편적이다. 도입 경위는 [`history/web/03-HTML-CSS-진화.md`](../../../../../../history/web/03-HTML-CSS-진화.md) §2.7 이 정본이다.
> **여기서 다루지 않는 것** — **`@property` 로 등록했을 때 달라지는 것**(타입·초기값·상속 여부·애니메이션 가능성)은 [목록의 **37번 주제**](../37-at-property/)가 정본이다. 여기는 **등록하지 않은 커스텀 속성**까지다. 상속 일반은 [03번](../03-inheritance-and-global-keywords/2-summary.md), 무효한 선언이 버려지는 규칙은 [07번](../07-syntax-and-error-recovery/2-summary.md)이 정본이다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 값은 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**커스텀 속성은 「값」이 아니라 「봉투에 든 쪽지」다.**

보통 속성은 선언하는 자리에서 **뜻이 확정된다** — `color: red` 는 그 자리에서 `rgb(255,0,0)` 이 된다.\
커스텀 속성은 **뜻을 확정하지 않고 글자 그대로 담아 둔다.** 뜻은 **`var()` 로 꺼내 쓰는 쪽**에서 정해진다.

우편물에 비유한다. 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 봉투에 쪽지를 넣어 봉한다 | **`--x: redd`** — 내용이 말이 되는지 **안 따진다** |
| 봉투가 자손에게 계속 전달된다 | **상속** — 커스텀 속성은 **전부 상속된다** |
| 받은 사람이 봉투를 뜯어 읽는다 | **`var(--x)`** — 여기서 처음 뜻이 해석된다 |
| 읽어 보니 말이 안 된다 | **무효 대체(IACVT)** — **읽은 쪽이** `unset` 처럼 된다 |
| 봉투가 아예 없다 | **대체값** — `var(--x, 파랑)` 의 둘째 인자가 그때 쓰인다 |

```text
  같은 오타가 두 자리에서 전혀 다르게 처리된다

    보통 속성                        커스텀 속성
    .c1 { color: redd }              .v2 { --x: redd; color: var(--x) }
         │                                │
         v                                v
    파서가 '무효한 값' 으로 본다      파서가 그냥 담는다 (거의 아무 토큰이나 받는다)
         │                                │
         v                                v
    ★ 선언 하나가 버려진다            ★ 선언은 살아남는다 (--x = "redd")
      cssRules 속성 목록에서 사라짐      cssRules 목록 = [--x, color, background-color]
         │                                │
         v                                v
    앞선 선언·상속값이 그대로 남음    color: var(--x) 가 계산 시점에 무효가 되어
                                       ★ '쓰는 쪽' 이 unset 처럼 된다
```

*(Chrome 151 실측 — `.v2` 의 `cssRules` 속성 목록이 `[--x, color, background-color]` 로 **셋 다 담겼고**, `--x` 는 담긴 값·계산값 모두 `"redd"` 였다. 왼쪽 실측의 정본은 [07번](../07-syntax-and-error-recovery/2-summary.md)이다.)*

실무에서 이게 터지는 자리는 **테마 변수에 오타가 났을 때**다.\
「선언이 버려졌겠지」 하고 **`cssRules` 를 찍어 보면 멀쩡히 있다.** 값도 그대로 있다. 그런데 화면은 안 바뀐다 — **쓰는 쪽이 초기화됐기 때문**이다.

> **토큰 뭉치(token stream)** — 뜻을 해석하지 않고 글자 단위로만 잘라 둔 값.\
> 예: `--x: redd` 는 「빨강의 오타」가 아니라 **`redd` 라는 식별자 토큰 하나**로 보관된다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 네 질문을 둔다.

1. **오타가 난 커스텀 속성은 어디서 죽는가** — 선언이 버려지는가, 쓰는 쪽이 초기화되는가.
2. **`var()` 의 대체값은 언제 쓰이는가** — 「값이 무효일 때」인가 「변수가 없을 때」인가.
3. **커스텀 속성은 무엇으로 상속되는가** — 계산된 값인가, 글자 그대로인가.
4. **두 조상이 같은 변수를 선언하면 누가 이기는가** — 명시도인가, 거리인가.

## 동작 방식

### (1) 창이 하나 더 필요하다 — 변수는 따로 읽어야 한다

**언제 쓰나** — 커스텀 속성을 진단하는 모든 자리. **이 절이 나머지 전부의 도구다.**

```text
  [07번] 의 진단 3창                     이 주제가 더하는 창

  ① cssRules          규칙이 담겼나        ①-b cssRules[i].style
                                              .getPropertyValue('--x')
                                              ★ 변수에 무엇이 담겼나
  ② querySelectorAll  선택자가 잡았나

  ③ getComputedStyle  이겼나              ③-b getComputedStyle(el)
                                              .getPropertyValue('--x')
                                              ★ 변수의 계산값은 무엇인가

  => ①-b 와 ③-b 가 다를 수 있고, 둘 다 멀쩡한데 ③ 이 엉뚱할 수 있다
```

```text
실측 — .v2 { --x: redd; color: var(--x); background-color: #fde68a }

  ①   cssRules 속성 목록                 = [--x, color, background-color]
  ①-b cssRules 의 --x 값                 = "redd"
  ③-b getComputedStyle 의 --x            = "redd"
  ③   getComputedStyle 의 color          = rgb(0, 0, 0)   <- 부모 색을 상속한 값
  ③   getComputedStyle 의 background     = rgb(253, 230, 138)  <- 멀쩡하다
```

그림 해설 (한 단계씩):

- **①·①-b·③-b 가 전부 정상**인데 **③ 만 이상하다.** 세 창만 보면 「아무 문제 없다」로 읽힌다.
- **같은 규칙의 다른 선언(`background-color`)은 멀쩡히 살아 있다** — 규칙째 죽은 것이 아니라는 증거다.
- 그러므로 커스텀 속성 버그는 **「변수를 읽는 창」과 「쓰는 속성을 읽는 창」을 따로 열어야** 잡힌다.

비용 — 없음. 창 하나를 더 여는 습관이다.

### (2) ★ 무효한 값 — 07번과 규칙이 다르다

**언제 쓰나** — 변수에 오타가 났을 때. **이 절이 이 주제의 정점이다.**

```text
  [07번] 의 규칙 — 보통 속성                이 주제의 규칙 — 커스텀 속성

  .c1 { color: redd }                      .v2 { --x: redd; color: var(--x) }
       │                                        │
       ├─ 파서가 값을 검사한다                    ├─ 파서가 값을 ★ 검사하지 않는다
       │                                        │   (거의 아무 토큰이나 받는다)
       v                                        v
  ★ 선언 하나가 버려진다                     ★ 선언이 담긴다
    "declaration is dropped"                     --x = "redd"
       │                                        │
       v                                        v
    앞선 선언이 살아남는다                    var(--x) 를 쓴 '그 속성' 이
    (color: blue; color: redd 면 blue)        계산 시점에 무효가 된다
                                                  │
                                                  v
                                             ★ 그 속성이 unset 처럼 처리된다
                                                = IACVT
```

```text
실측 — 부모 #p 는 color: green, background: 없음

  무엇을 선언했나                          계산값             무엇과 같은가
  -------------------------------------    ----------------   ---------------
  #iacvt_inh  --x: redd; color: var(--x)   rgb(0,128,0)       ★ color: unset 과 같다
  #unsettest  color: unset                 rgb(0,128,0)       (대조군)
  #initialtest color: initial              rgb(0,0,0)         (대조군 — 다르다)

  비상속 속성에서는?  (부모 #bg 는 background-color: green)
  #noinh   --x: redd; background-color: var(--x)   rgba(0,0,0,0)
  #noinh2  background-color: unset                 rgba(0,0,0,0)   ★ 같다
```

그림 해설 (한 단계씩):

- ★ 「**선언이 버려진다**」가 아니라 「**쓰는 쪽이 초기화된다**」다. 두 문장은 결과가 다르다.
- **`unset` 과 같다는 것을 대조군으로 증명했다** — 상속 속성에서는 **부모 색(green)** 이 나왔고, `initial`(검정)과는 **달랐다.**
- 비상속 속성에서는 **초기값**이 된다 — `background-color: unset` 과 똑같이 `rgba(0,0,0,0)`(투명)이었다.
- ★ **앞선 선언으로 되돌아가지 않는다.** 실측: `#d { --x: redd; color: red; color: var(--x) }` 의 계산값이 **빨강이 아니라 상속된 검정**이었다.\
  캐스케이드에서 **`var()` 쪽이 이긴 뒤에** 무효가 되기 때문이다 — 진 선언은 이미 버려졌다.
- 이 차이 때문에 **점진적 향상이 커스텀 속성에서는 안 통한다.** `color: red; color: var(--maybe)` 는 폴백이 되지 않는다.

```html demo
<div class="panel">
  <p class="good">--ok 로 칠한 글자</p>
  <p class="typo">--bad 에 오타가 난 글자</p>
</div>
<style>
  .panel { color: #16a34a; --ok: #2563eb; --bad: bluee; }
  .good  { color: var(--ok); }
  .typo  { color: var(--bad); }
</style>
```

> **보이는 것** — 위 줄은 **파란 글자**(`--ok` 가 제대로 읽혔다)인데, 아래 줄은 **검정도 파랑도 아닌 초록 글자**다. `--bad: bluee` 라는 오타가 선언째 버려졌다면 아래 줄도 파랗거나 검정이어야 하는데, **부모 `.panel` 의 초록을 상속했다** — `color: var(--bad)` 가 `unset` 처럼 처리됐기 때문이다.\
> **바꿔 볼 것** — `.typo` 를 `color: var(--bad, #dc2626)` 로 바꾸면 → **여전히 초록이다**(대체값은 「무효일 때」가 아니라 「없을 때」 쓰인다 — 아래 (3))

*(Chrome 151 headless 실측: `.panel` `color: rgb(22,163,74)` · `.good` `rgb(37,99,235)` · `.typo` `rgb(22,163,74)`.)*

> **IACVT(invalid at computed-value time)** — 파싱은 통과했는데 **계산 시점에** 무효가 되는 값. 그 속성이 `unset` 처럼 처리된다.\
> 예: 실측에서 `color: var(--x)` (`--x` 가 `redd`)가 **부모 색을 상속**했다 — `initial`(검정)이 아니었다.

비용 — 없음. 다만 **증상이 「아무 일도 안 일어남」이라 원인 추적이 가장 어렵다.**

### (3) ★ 대체값은 「무효일 때」가 아니라 「없을 때」 쓰인다

**언제 쓰나** — 대체값을 넣어 뒀는데도 화면이 안 바뀔 때.

```text
Chrome 151 실측 — 부모 색을 purple 로 두어 '대체값' 과 '상속' 을 갈랐다

  선언                                  계산된 color        대체값이 쓰였나
  ------------------------------------  ------------------  --------------
  color: var(--none, green)             rgb(0,128,0)        ★ 쓰였다
  --x: redd;  color: var(--x, green)    rgb(128,0,128)      ★ 안 쓰였다
                                        = 부모 purple 상속    (있는데 무효라서)
  --x: redd;  color: var(--x)           rgb(128,0,128)      (대체값 없음)

  부모 색이 검정인 별도 판에서
  color: red; color: var(--nope)        rgb(0,0,0)          (대체값 없음)
  color: red; color: var(--nope, green) rgb(0,128,0)        ★ 쓰였다
  --empty: ;  color: var(--empty, teal) rgb(0,0,0)          ★ 안 쓰였다
```

```text
  var(--x, 대체값) 의 판정 순서

    --x 가 아예 없나? (또는 '보장된 무효' 인가)
        ├─ 예  ──> 대체값을 그 자리에 펼친다
        └─ 아니오 ──> --x 의 토큰 뭉치를 그 자리에 펼친다
                          │
                          v
                     펼친 결과가 그 속성의 문법에 안 맞나?
                          └─ 예 ──> ★ IACVT. 대체값은 쓰이지 않는다
```

그림 해설 (한 단계씩):

- **대체값은 「변수 조회」 단계에서만 쓰인다.** 변수를 찾았으면 그 값을 쓰고, **그 뒤에 무효가 되는 것은 대체값의 관할 밖**이다.
- ★ **`--empty: ;` 가 결정적인 근거다.** 빈 값도 **엄연히 존재하는 값**이라 대체값이 안 쓰였고, 펼친 결과 `color: ` 가 무효가 되어 IACVT 가 됐다(실측 검정).
- 즉 **「없다」와 「무효다」는 다른 상태**이고, 대체값은 앞엣것만 막는다.
- 실무 결론 — **오타 방어용으로 대체값을 넣는 것은 효과가 없다.** 대체값은 **「이 변수를 안 준 사용자」를 위한 기본값**이다.

비용 — 없음. 다만 **대체값이 있으니 안전하다**는 오해가 이 주제에서 가장 비싸다.

### (4) 대체값 안의 쉼표 — 첫 쉼표 뒤는 전부 대체값이다

**언제 쓰나** — `border` 나 `font-family` 처럼 값에 공백·쉼표가 들어가는 속성에 변수를 쓸 때.

```text
Chrome 151 실측

  선언                                              계산값
  ------------------------------------------------  ----------------------------
  border: var(--brd, 1px solid red)                 1px solid rgb(255,0,0)
  --sp: 1px solid red;  border: var(--sp)           1px solid rgb(255,0,0)
  font-family: var(--ff, "Courier New", monospace)  "Courier New", monospace
  color: var(--p, var(--q, teal))                   rgb(0,128,128)   <- 중첩 대체값
```

```text
  var() 의 인자를 자르는 규칙

    var( --brd , 1px solid red )
         ^^^^^   ^^^^^^^^^^^^^^
         이름     ★ 첫 쉼표 '뒤 전부' 가 대체값이다
                    (쉼표가 더 있어도 하나의 대체값으로 읽는다)

    그래서 font-family: var(--ff, "Courier New", monospace) 가 성립한다
    -> 대체값 = `"Courier New", monospace` 통째로
```

그림 해설 (한 단계씩):

- **`var()` 의 인자는 「이름」과 「대체값」 둘뿐**이다. 쉼표가 여럿이어도 **첫 쉼표만 구분자**다.
- 그래서 **쉼표를 품은 값도 대체값으로 넣을 수 있다** — `font-family` 목록 전체가 들어갔다.
- **공백을 품은 값도 마찬가지**다 — `1px solid red` 가 그대로 대체값이 됐다.
- **중첩도 된다** — `var(--p, var(--q, teal))` 로 「둘 다 없으면 teal」이 표현된다.
- 변수 자체에 단축 속성 값을 통째로 담는 것도 된다(`--sp: 1px solid red`).

비용 — 없음. 다만 **대체값이 길어지면 읽기 나빠진다** — 중첩 두 단계를 넘기지 않는 것이 관행이다.

### (5) 순환 참조·자기 참조 — 값이 사라지고 대체값은 살아난다

**언제 쓰나** — 변수를 리팩터링하다 서로를 가리키게 됐을 때. **던져서 확인한 자리다.**

```text
Chrome 151 실측 — 부모 #p 는 color: green

  선언                                              --a 계산값   color 계산값
  ------------------------------------------------  -----------  ---------------
  --a: var(--b); --b: var(--a); color: var(--a)     ""           rgb(0,128,0)
                                                                 = 부모 상속 (IACVT)
  --a: var(--b); --b: var(--a); color: var(--a, purple)  ""      rgb(128,0,128)
                                                                 ★ 대체값이 쓰였다
  --s: var(--s);                color: var(--s, navy)    ""      rgb(0,0,128)
                                                                 ★ 자기참조도 같다
```

그림 해설 (한 단계씩):

- **순환에 걸린 변수는 「보장된 무효(guaranteed-invalid)」가 된다.** 계산값이 **빈 문자열**로 나왔다.
- ★ **그러면 (3) 의 첫 갈래 — 「아예 없나?」에 걸린다.** 그래서 **대체값이 쓰인다**(purple · navy).
- 대체값이 없으면 `var()` 자체가 무효가 되어 **IACVT → 부모 색 상속**이 된다.
- **자기 참조(`--s: var(--s)`)도 순환으로 처리된다** — 한 칸짜리 고리다.
- **에러는 나지 않는다.** 콘솔도 화면도 조용하다 — 값이 빈 문자열인지 **읽어 봐야** 안다.

비용 — 없음. 다만 **순환이 생겨도 화면이 「그럴듯하게」 보일 수 있다** — 대체값이 대신 들어가기 때문이다.

### (6) ★ 대소문자를 가린다 — 보통 속성과 다르다

**언제 쓰나** — 변수 이름을 `--mainColor` 처럼 카멜케이스로 쓸 때.

```text
Chrome 151 실측

  #e { --X: blue; color: var(--x, orange) }

    computed --X    = "blue"
    computed --x    = ""            <- 없다
    computed color  = rgb(255,165,0)  = orange   ★ 대체값이 쓰였다
```

```text
  보통 속성                         커스텀 속성
  COLOR: red   == color: red        --X: blue   !=  --x: blue
  ^^^^^ 대소문자 무시               ^^^ ★ 다른 속성이다

  같은 규칙이 값에도 적용된다
  color: RED   == color: red        --x: Blue   !=  --x: blue  (글자 그대로 보관)
```

그림 해설 (한 단계씩):

- **커스텀 속성 이름은 대소문자를 가린다.** `--X` 와 `--x` 는 **서로 다른 속성**이다.
- 보통 속성 이름은 대소문자를 무시하므로 **CSS 안에서 이 둘만 규칙이 다르다.**
- **에러가 없다** — 오타가 나면 그냥 「없는 변수」가 되고, 대체값이 있으면 대체값이, 없으면 IACVT 가 된다.
- **담긴 값도 글자 그대로 보관된다** — 공백 처리 실측: `--ws:    hello   world   ;` 가 담긴 값·계산값 모두 **`"hello   world"`** 였다(앞뒤만 잘리고 **가운데 공백은 보존**).

비용 — 없음. 관행은 **전부 소문자 + 하이픈**(`--main-color`)이다 — 대소문자 사고를 원천 차단한다.

### (7) ★ 토큰 뭉치로 상속된다 — 보통 속성과 갈리는 결정적 자리

**언제 쓰나** — 변수에 `em` 같은 상대 단위를 담았을 때. **이 절이 「값이 아니라 토큰 뭉치」의 증거다.**

```text
Chrome 151 실측 — 같은 판에서 보통 속성과 커스텀 속성을 나란히 쟀다

  #tp { font-size: 20px; text-indent: 2em; --len: 2em }
      └ #tc { font-size: 40px; width: var(--len) }

  보통 속성 text-indent: 2em                커스텀 속성 --len: 2em
  --------------------------------------    --------------------------------------
  부모 계산값    = 40px                     부모 계산값 = "2em"   ★ px 이 안 됐다
  자식 상속값    = 40px                     자식 계산값 = "2em"   ★ 글자 그대로
  (자식 글꼴 40px 이어도 40px 그대로)
                                            자식의 width: var(--len) = ★ 80px
                                            (자식 글꼴 40px x 2 — 자식 자리에서 풀렸다)
```

```text
  무엇이 내려가는가

  보통 속성                          커스텀 속성
  +---------------------------+      +---------------------------+
  | 부모 자리에서 40px 로      |      | 부모 자리에서는 아무것도    |
  | ★ 계산이 끝난다            |      | 계산하지 않는다            |
  +---------------------------+      +---------------------------+
             │ 40px 이 내려간다                 │ "2em" 이 내려간다
             v                                  v
  +---------------------------+      +---------------------------+
  | 자식은 40px 을 그대로 쓴다 |      | 자식이 var() 로 꺼낼 때     |
  |                           |      | ★ 자식 글꼴로 계산한다 80px |
  +---------------------------+      +---------------------------+
```

그림 해설 (한 단계씩):

- **보통 속성은 부모 자리에서 계산값이 확정되고 그 픽셀이 내려간다.** 이 규칙의 정본은 [04번](../04-value-processing-stages/2-summary.md)이다.
- ★ **커스텀 속성은 계산값이 「토큰 뭉치 그대로」다.** 부모에서 `"2em"` 이었고 자식에서도 `"2em"` 이었다.
- **그래서 같은 변수가 자리마다 다른 픽셀이 된다** — 자식의 `width: var(--len)` 이 **80px**(자식 글꼴 40의 2배)이 됐다.\
  `text-indent` 쪽은 자식 글꼴이 두 배가 됐는데도 **40px 그대로**였다.
- 같은 성질을 다른 각도로도 확인했다 — `--a: 10px; --b: var(--a); --c: calc(var(--b) * 3)` 에서 **`--c` 의 계산값이 `"calc(10px * 3)"`** 이었다.\
  `var()` 는 펼쳐졌는데 **`calc()` 는 계산되지 않은 채** 남았다. **쓰는 쪽에서 비로소 30px 이 됐다.**
- 이 성질이 **테마·토큰 설계의 근거**다 — 한 번 선언해 두면 각 자리에서 그 자리 맥락으로 풀린다.

비용 — **값이 확정되는 시점이 뒤로 밀린다.** 파싱 시점에 접을 수 없고, 애니메이션도 안 된다((12)).

### (8) ★ 가까운 조상이 이긴다 — 명시도가 아니다

**언제 쓰나** — 특정 구역만 테마를 바꿀 때. 그리고 「`#id` 로 선언했는데 왜 안 이기지?」일 때.

```text
Chrome 151 실측

  [거리 대조]  .far { --tone: red }
                 └ #near { --tone: blue }
                     └ #leaf { color: var(--tone) }

     #leaf 의 --tone  = "blue"        가까운 쪽이 이겼다
     #leaf 의 color   = rgb(0,0,255)

  [명시도 대조] #hi { --tone2: red }        <- ID 선택자 (명시도 1-0-0)
                 └ .lo { --tone2: blue }    <- 클래스 (명시도 0-1-0)
                     └ #leaf2 { color: var(--tone2) }

     #leaf2 의 --tone2 = "blue"       ★ 명시도가 낮은 쪽이 이겼다
     #leaf2 의 color   = rgb(0,0,255)
```

```text
  왜 명시도가 아닌가 — 두 선언이 '같은 요소' 에 걸린 게 아니기 때문이다

    #hi   { --tone2: red }     <- #hi 라는 '요소' 의 --tone2 를 정한다
      │                            (여기서는 red 가 맞다)
      v  상속
    .lo   { --tone2: blue }    <- .lo 라는 '요소' 의 --tone2 를 정한다
      │                            ★ 상속받은 red 를 자기 선언 blue 가 덮는다
      v  상속
    #leaf2                     <- 부모 .lo 의 계산값 "blue" 를 물려받는다

  명시도는 '한 요소에 걸린 여러 선언' 중에서 고르는 규칙이다 (02번).
  여기서는 선언이 각각 다른 요소에 걸려 있어 명시도가 붙을 자리가 없다.
```

그림 해설 (한 단계씩):

- **커스텀 속성은 「전부 상속되는」 속성**이다([03번](../03-inheritance-and-global-keywords/2-summary.md)).
- 그러므로 규칙은 **캐스케이드가 아니라 상속**이다 — 자기 자신에게 선언이 있으면 그것, 없으면 부모 것.
- **명시도는 같은 요소에 걸린 선언끼리만 겨룬다.** 조상 둘이 각각 자기 자신에게 선언한 것은 겨루지 않는다.
- 실측이 그것을 보여 준다 — `#hi`(ID)가 `.lo`(클래스)에게 **졌다.**
- 이 성질이 **「구역만 테마 바꾸기」를 성립시킨다** — 바꿀 구역의 조상 하나에 변수를 다시 선언하면 그 안쪽만 바뀐다.

```html demo
<div class="theme">
  <button class="btn">기본</button>
  <div class="dark"><button class="btn">어두운 구역</button></div>
</div>
<style>
  .theme { --bg: #e0e7ff; --fg: #1e3a8a; }
  .dark  { --bg: #1e3a8a; --fg: #e0e7ff; padding: 8px; }
  .btn   { background: var(--bg); color: var(--fg);
           border: 1px solid currentColor; padding: 6px 12px; }
</style>
```

> **보이는 것** — 버튼 두 개의 클래스는 **똑같이 `.btn` 하나뿐**인데, 위 버튼은 **연한 배경에 진한 글씨**, 아래 버튼은 **진한 배경에 연한 글씨**로 색이 뒤집혀 있다. `.btn` 규칙은 하나도 안 바뀌었고, 아래 버튼의 조상 `.dark` 가 `--bg`·`--fg` 를 다시 선언했을 뿐이다.\
> **바꿔 볼 것** — `.dark` 의 `--bg`/`--fg` 두 줄을 지우면 → **두 버튼이 똑같아진다**(`.theme` 의 값이 그대로 내려온다)

*(Chrome 151 headless 실측: 위 버튼 `bg rgb(224,231,255)` / `color rgb(30,58,138)` · 아래 버튼 `bg rgb(30,58,138)` / `color rgb(224,231,255)`.)*

비용 — 없음. 다만 **「어느 조상이 마지막으로 선언했나」를 눈으로 추적해야** 한다 — 명시도 계산기가 도움이 안 된다.

### (9) `:root` 에 두는 관행과 그 한계

**언제 쓰나** — 디자인 토큰을 한곳에 모을 때. 그리고 그 관행이 안 통하는 자리를 만날 때.

```text
  왜 :root 인가

    :root = html 요소. 문서의 모든 요소의 조상이다.
    커스텀 속성은 전부 상속되므로 ★ 한 번 선언하면 문서 전체가 읽는다.

    :root { --brand: #2563eb }   ->  어느 요소에서든 var(--brand) 가 읽힌다
```

```text
  한계 ① — 미디어 쿼리 조건 안에서는 못 쓴다 (Chrome 151 실측)

    @media (min-width: var(--bp, 100px)) { #mq { outline: 2px solid red } }
       -> 규칙은 담겼다 (conditionText = "(min-width: var(--bp, 100px))")
       -> ★ 조건이 참이 되지 않는다 (#mq 의 outline-style = none)

    @media (min-width: 100px) { #mq2 { … } }
       -> 적용됐다 (outline-style = solid)

    이유: 미디어 쿼리는 '문서 트리 바깥' 에서 평가된다.
          커스텀 속성은 '요소에 붙어 상속되는 것' 이라 거기에 없다.
```

```text
  한계 ② — 선택자·속성 이름 자리에는 못 쓴다 (실측)

    #badname { --prop: color; var(--prop): red; width: 30px }
       cssRules 에 담긴 것 = "--prop: color; width: 30px;"
       ★ var(--prop): red 는 통째로 사라졌다
```

그림 해설 (한 단계씩):

- **`:root` 는 「가장 먼 조상」이라 전역이 된다.** 특별한 기능이 아니라 (8) 의 상속 규칙의 응용이다.
- **한계 ①** — 변수는 요소에 붙는데 미디어 쿼리는 요소를 보지 않는다. 그래서 **중단점을 변수로 뺄 수 없다.**
- **한계 ②** — `var()` 는 **속성 「값」 자리에서만** 산다. 속성 이름·선택자에는 못 쓴다 — 선언이 통째로 버려졌다.
- 그래서 **전역 토큰을 `:root` 에 두되, 「구역 테마」는 그 구역의 조상에 다시 선언하는** 두 층 구조가 실무 관행이다((8) 의 demo).

비용 — `:root` 에 전부 몰면 **어느 변수가 어디서 쓰이는지** 추적이 어려워진다. 컴포넌트 지역 변수를 섞는 편이 낫다.

### (10) 이름 규칙 — 무엇이 커스텀 속성으로 인정되나

**언제 쓰나** — 이름을 정할 때. 그리고 「분명히 썼는데 없다」일 때.

```text
Chrome 151 실측 — 한 규칙에 다섯 형태를 적고 cssRules 를 찍었다

  적은 것         담겼나   계산값      비고
  --------------  -------  ----------  --------------------------------
  --: 1px         ✗        —           이름이 비어 있다
  --1: red        ✓        "red"       ★ 숫자로 시작해도 된다
  --가나: blue    ✓        "blue"      ★ 비ASCII 도 된다
  --a-b_c: green  ✓        "green"     하이픈·밑줄 섞기 OK
  -x: red         ✗        —           ★ 하이픈 하나는 커스텀 속성이 아니다

  실제로 꺼내 써도 된다
    color: var(--가나)  ->  rgb(0,0,255)
    color: var(--1)     ->  rgb(255,0,0)
```

그림 해설 (한 단계씩):

- **`--` 두 개로 시작하고 그 뒤에 한 글자 이상**이면 된다. 보통 속성 이름에 못 쓰는 문자도 대부분 통과한다.
- **하이픈 하나(`-x`)는 벤더 접두사 자리**라 커스텀 속성이 아니다 — 선언이 버려졌다.
- **숫자로 시작해도 되고 한글도 된다** — 보통 식별자 규칙보다 훨씬 관대하다.
- 실무 관행은 **소문자 + 하이픈**이다((6) 의 대소문자 사고를 막는다).

비용 — 없음.

### (11) JS 로 읽고 쓰기 — `setProperty` 만 통한다

**언제 쓰나** — 테마 전환·슬라이더·드래그처럼 **값을 실시간으로 바꿔야** 할 때.

```text
Chrome 151 실측 — #js { --j: 5px; width: var(--j) }

  읽기
    getComputedStyle(el).getPropertyValue('--j')  = "5px"     계산값(상속 포함)
    el.style.getPropertyValue('--j')              = ""        인라인에만 있는 것

  쓰기
    el.style.setProperty('--j', '120px')
       -> el.style.cssText = "--j: 120px;"   width = 120px    ★ 된다
    el.style['--j'] = '9px'
       -> width 가 안 바뀌었다 (764px = auto)                  ★ 안 된다

  오타를 넣으면
    el.style.setProperty('--j', 'oops')
       -> computed --j = "oops"    width = 764px (auto)        ★ IACVT
```

```text
  테마 전환 (실측)

    :root { --brand: #2563eb };  #th { color: var(--brand) }
       -> #th color = rgb(37, 99, 235)

    document.documentElement.style.setProperty('--brand', '#dc2626')
       -> #th color = rgb(220, 38, 38)     ★ 한 줄로 문서 전체가 바뀐다
```

그림 해설 (한 단계씩):

- **읽을 때는 두 창을 구분한다** — `getComputedStyle` 은 **상속까지 반영한 값**, `el.style` 은 **그 요소의 인라인 선언만**이다.
- ★ **쓸 때는 `setProperty` 만 통한다.** `el.style['--j'] = …` 는 **조용히 무시됐다** — 카멜케이스 프로퍼티 접근이 커스텀 속성에는 안 매핑된다.
- **JS 로 넣은 오타도 똑같이 IACVT** 가 된다 — 값은 `"oops"` 로 담기고 `width` 만 `auto` 가 됐다((2)).
- **테마 전환의 실무 패턴**은 루트에 한 줄 쓰는 것이다. 상속 덕에 그 한 줄이 문서 전체에 퍼진다((8)).
- 더 흔한 형태는 **클래스 토글**이다 — `<html class="dark">` 에 `.dark { --bg: … }` 를 걸면 JS 는 클래스만 건드리면 된다.

비용 — 루트 변수를 바꾸면 **그 변수를 쓰는 모든 요소가 다시 계산**된다. 드래그처럼 초당 수십 번 바꾸는 자리에서는 **범위를 좁혀** 가까운 조상에 쓴다.

### (12) 애니메이션이 안 된다 — 37번이 그것을 푼다

**언제 쓰나** — 변수를 `transition`·`@keyframes` 에 태웠을 때.

```text
Chrome 151 실측 — 10초 linear 애니메이션을 네 시점에서 샘플링했다

  @keyframes k  { from { --w: 0px  } to { --w: 200px } }
  @keyframes kc { from { --c: red  } to { --c: blue  } }

  시점       --w        width      --c      color
  ---------  ---------  ---------  -------  ----------------
  2s (20%)   "0px"      0px        "red"    rgb(255,0,0)
  4s (40%)   "0px"      0px        "red"    rgb(255,0,0)
  6s (60%)   "200px"    200px      "blue"   rgb(0,0,255)
  9s (90%)   "200px"    200px      "blue"   rgb(0,0,255)

  대조군 — 보통 속성을 같은 조건으로 애니메이션
  @keyframes k2 { from { width: 0px } to { width: 200px } }
     5초 시점 width = 99.3281px    ★ 중간값이 나온다
```

```text
  왜 중간값이 없나

    등록하지 않은 커스텀 속성의 계산값 타입 = '토큰 뭉치' 다.
    토큰 뭉치는 두 값 사이를 보간할 방법이 없다 — "0px" 과 "200px" 의
    '중간 문자열' 이라는 것이 정의되지 않는다.
       │
       v
    그래서 ★ 이산(discrete) 보간이 된다 — 50% 지점에서 한 번 튄다.
       │
       v
    [37번] 의 @property 로 syntax: '<length>' 를 등록하면
    계산값 타입이 '길이' 가 되어 보간이 가능해진다.
```

그림 해설 (한 단계씩):

- ★ 「**안 움직인다**」가 아니라 「**50% 에서 한 번 튄다**」다. 40% 까지 `0px`, 60% 부터 `200px` 이었다.
- **길이든 색이든 같았다** — `--c` 도 red 에서 blue 로 **한 번에** 넘어갔다.
- 대조군이 결정적이다 — 같은 타이밍에 **보통 `width` 는 99.33px** 이라는 중간값을 냈다.
- **푸는 방법은 `@property` 등록**이다. 그 규칙과 실측은 [목록의 **37번 주제**](../37-at-property/)가 정본이므로 **여기서는 넘긴다.**

비용 — 없음. 다만 **「변수로 애니메이션한다」는 설계는 등록 없이는 성립하지 않는다.**

## 문법 — 형태와 어디서 헷갈리나

### 최소 형태

```css
:root { --brand: #2563eb; }            /* 선언 — 값은 검사되지 않는다 */
.btn  { color: var(--brand); }         /* 사용 */
.btn  { color: var(--brand, #333); }   /* 없을 때의 대체값 */
.box  { border: var(--b, 1px solid red); }  /* 첫 쉼표 뒤 전부가 대체값 */
.card { --gap: 8px; padding: calc(var(--gap) * 2); }  /* 계산과 섞기 */
```

### 헷갈리는 자리

| 적은 것 | 실제 | 왜 |
|---|---|---|
| `--x: redd; color: var(--x)` | **선언은 산다. 쓰는 쪽이 `unset`** | IACVT((2)) |
| `color: red; color: var(--x)`(`--x` 무효) | **red 로 안 돌아간다** | 캐스케이드에서 이긴 뒤 무효가 된다((2)) |
| `var(--x, green)`(`--x` 가 무효) | **green 이 안 쓰인다** | 대체값은 「없을 때」만((3)) |
| `--empty: ; var(--empty, teal)` | **teal 이 안 쓰인다** | 빈 값도 「있는 값」이다((3)) |
| `--X` 와 `--x` | **다른 속성이다** | 대소문자를 가린다((6)) |
| `#id` 조상 대 `.class` 조상 | **가까운 쪽이 이긴다** | 명시도가 아니라 상속이다((8)) |
| `@media (min-width: var(--bp))` | **절대 참이 안 된다** | 미디어 쿼리에 요소가 없다((9)) |
| `el.style['--x'] = '1px'` | **아무 일도 안 일어난다** | `setProperty` 만 통한다((11)) |

### 금지에 가까운 형태

```css
/* 점진적 향상인 줄 알고 쓰는 형태 */
.a { color: red; color: var(--maybe); }   /* --maybe 가 무효면 red 가 아니라 unset */

/* 대체값을 오타 방어로 쓰는 형태 */
.b { color: var(--brand, #333); }         /* --brand 에 오타가 나면 #333 이 아니라 unset */

/* 속성 이름을 변수로 */
.c { --prop: color; var(--prop): red; }   /* 선언이 통째로 사라진다 */

/* 중단점을 변수로 */
@media (min-width: var(--bp)) { }         /* 조건이 참이 되지 않는다 */
```

## 구현 세부사항 대 언어 보장

| 무엇 | 어느 쪽 |
|---|---|
| 커스텀 속성이 **전부 상속되는** 것 | **명세**(css-variables-1) |
| 값이 **토큰 뭉치로 보관·상속**되는 것 | **명세** — 실측으로도 확인했다(`--len: 2em` 이 자식에서 80px) |
| 무효한 `var()` 가 **IACVT → `unset`** 인 것 | **명세**(css-variables-1 + css-cascade-5) — 대조군 실측으로 확인했다 |
| 대체값이 **「없을 때」만** 쓰이는 것 | **명세** — `--empty` 실측이 근거다 |
| **첫 쉼표 뒤 전부**가 대체값인 것 | **명세** |
| 순환이 **보장된 무효**가 되고 대체값이 쓰이는 것 | **명세** — 실측으로 확인했다 |
| 이름이 **대소문자를 가리는** 것 | **명세** |
| 이름에 **숫자·비ASCII** 가 되는 것 | **명세**(`<custom-property-name>` 문법) |
| 등록 안 한 커스텀 속성이 **이산 보간**되는 것 | **명세**(web-animations 의 discrete) — 50% 전환도 실측했다 |
| **`--empty` 의 계산값이 `""`** 로 직렬화되는 것 | **CSSOM 직렬화** — 「빈 토큰 뭉치」를 문자열로 어떻게 보이느냐다 |
| `--c` 의 계산값이 **`"calc(10px * 3)"`** 으로 보이는 것 | **Chrome 151 직렬화** — 접기 범위는 구현 재량이다 |
| `el.style['--x']` 가 **안 먹는** 것 | **CSSOM** — 카멜케이스 매핑 대상이 아니다 |
| `@property` 등록 시 달라지는 것 전부 | **이 문서에서 재지 않았다** — [목록의 **37번 주제**](../37-at-property/) |

## 어디서 틀리나

### 1. 「선언이 버려졌겠지」 하고 `cssRules` 만 찍는다

**멀쩡히 담겨 있다**(실측 `[--x, color, background-color]`). 값도 `"redd"` 로 그대로 있다.\
진단 — **쓰는 쪽 속성의 계산값**을 따로 읽어야 한다((1)).

### 2. `color: red; color: var(--x)` 를 폴백으로 쓴다

`--x` 가 무효면 **red 로 안 돌아간다** — 상속값이나 초기값이 된다((2)).\
고치는 법 — CSS 안에서는 못 푼다. `@supports` 나 [07번](../07-syntax-and-error-recovery/2-summary.md)의 오류 복구를 쓰려면 **`var()` 를 안 쓰는 형태**여야 한다.

### 3. 대체값을 오타 방어로 쓴다

대체값은 「**변수가 없을 때**」만 쓰인다((3)). 오타는 「있는데 무효」라 안 걸린다.\
근거 — `--empty: ;` 에서도 대체값이 안 쓰였다.

### 4. `--mainColor` 처럼 카멜케이스를 쓰다가 대소문자를 틀린다

`--X` ≠ `--x` 다((6)). 관행대로 **소문자 + 하이픈**을 쓴다.

### 5. `#id` 로 선언했으니 이길 거라 생각한다

**가까운 조상이 이긴다**(실측: ID 조상이 클래스 조상에게 졌다)((8)).\
명시도는 **같은 요소에 걸린 선언끼리만** 겨룬다([02번](../02-specificity/2-summary.md)).

### 6. 중단점을 변수로 뺀다

`@media (min-width: var(--bp))` 는 **규칙이 담기지만 조건이 참이 되지 않는다**(실측)((9)).

### 7. 변수를 `transition`/`@keyframes` 에 태운다

등록하지 않으면 **50% 에서 한 번 튄다**(실측 40% 까지 0px, 60% 부터 200px)((12)).\
푸는 것은 `@property` — [목록의 **37번 주제**](../37-at-property/).

### 8. JS 에서 `el.style['--x'] = …` 로 쓴다

**조용히 무시된다**(실측). `el.style.setProperty('--x', …)` 만 통한다((11)).

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓰나 | 왜 |
|---|---|---|
| 색·간격 같은 디자인 토큰 | **쓴다** — `:root` 에 | 상속 덕에 한 번 선언으로 전역이 된다((9)) |
| 구역·컴포넌트별 테마 전환 | **쓴다** — 그 구역 조상에 | 가까운 조상이 이긴다((8)) |
| JS 로 실시간으로 바꿀 값 | **쓴다** — `setProperty` | 스타일시트를 다시 쓰지 않아도 된다((11)) |
| 단축 속성 값 묶음(`1px solid red`) | **쓴다** | 토큰 뭉치라 공백·쉼표가 든 값도 담긴다((4)) |
| 값을 부분 조립(`var(--a)var(--b)`) | **안 쓴다** | 토큰이 안 붙는다 — 실측에서 무효가 됐다 |
| 미디어 쿼리 중단점 | **못 쓴다** | 조건이 참이 되지 않는다((9)) |
| 선택자·속성 이름 | **못 쓴다** | 선언이 통째로 버려진다((9)) |
| 애니메이션할 값 | **등록 없이는 안 쓴다** | 이산 보간이 된다((12)) — [목록의 **37번 주제**](../37-at-property/) |
| 오타를 막고 싶을 때 | **CSS 로는 못 막는다** | 대체값도 `@supports` 도 안 걸린다((3)) |

## 핵심 문장

- **커스텀 속성은 「값」이 아니라 「토큰 뭉치」를 담는다.** 뜻은 `var()` 로 꺼내 쓰는 쪽에서 정해진다.
- ★ **오타는 「선언이 버려지는」 것이 아니라 「쓰는 쪽이 `unset` 이 되는」 것**이다(IACVT). [07번](../07-syntax-and-error-recovery/2-summary.md)의 규칙이 여기서는 안 통한다.
- ★ **대체값은 「무효일 때」가 아니라 「없을 때」 쓰인다.** `--empty: ;` 에서도 안 쓰였다.
- ★ **토큰 뭉치로 상속되므로 같은 변수가 자리마다 다른 값이 된다** — `--len: 2em` 이 부모에서 `"2em"`, 자식에서 80px 이었다.
- ★ **가까운 조상이 이긴다 — 명시도가 아니다.** ID 조상이 클래스 조상에게 졌다.
- **등록하지 않으면 애니메이션되지 않는다** — 50% 에서 한 번 튄다. 푸는 것은 [목록의 **37번 주제**](../37-at-property/).

## 용어 풀이

- **커스텀 속성(custom property)** — `--` 로 시작하는 속성. 값이 파싱 시점에 해석되지 않고 토큰 뭉치로 보관된다.
- **토큰 뭉치(token stream)** — 뜻을 해석하지 않고 글자 단위로만 잘라 둔 값. 예: `--x: redd` 는 `redd` 라는 식별자 토큰 하나로 보관된다.
- **`var()`** — 커스텀 속성을 그 자리에 **펼치는** 함수. 값을 대입하는 게 아니라 토큰을 밀어 넣는다.
- **대체값(fallback)** — `var(--x, 여기)` 의 둘째 인자. **변수가 없을 때만** 쓰인다. 예: `--empty: ;` 에서는 안 쓰였다.
- **IACVT(invalid at computed-value time)** — 파싱은 통과했는데 계산 시점에 무효가 되는 값. 그 속성이 `unset` 처럼 처리된다. 예: 실측에서 `color: var(--x)`(`--x`=`redd`)가 부모의 초록을 상속했다.
- **`unset`** — 상속되는 속성이면 `inherit`, 아니면 `initial` 로 되돌리는 전역 키워드. 정본은 [03번](../03-inheritance-and-global-keywords/2-summary.md).
- **보장된 무효(guaranteed-invalid)** — 커스텀 속성의 초기값이자, 순환에 걸린 변수가 되는 상태. 이 상태의 변수를 `var()` 로 꺼내면 **대체값이 쓰인다**.
- **순환 참조** — 변수 둘 이상이 서로를 가리키는 것. 예: 실측에서 `--a: var(--b); --b: var(--a)` 의 계산값이 둘 다 빈 문자열이었다.
- **진단 3창** — `cssRules` · `querySelectorAll` · `getComputedStyle`. 커스텀 속성에서는 **변수 값을 읽는 창 두 개**를 더 연다((1)).
- **이산 보간(discrete interpolation)** — 중간값 없이 50% 지점에서 한 번에 바뀌는 보간. 예: 실측에서 `--w` 가 40% 까지 `0px`, 60% 부터 `200px` 이었다.

## 더 들어가면

- **커스텀 속성의 초기값은 「보장된 무효」다.** 그래서 선언한 적 없는 변수를 읽으면 대체값이 쓰인다((3)·(5)).\
  `--t: initial` 을 명시하면 **상속을 끊고** 그 상태로 되돌릴 수 있다 — 실측: 부모가 `--t: red` 인데 자식에 `--t: initial` 을 주자 `var(--t, navy)` 가 **navy** 가 됐다.
- **`--x: ;`(빈 값)은 초기값이 아니라 「빈 토큰 뭉치」다.** 둘이 다르므로 대체값 동작도 다르다((3)).\
  「변수를 지우고 싶다」면 `initial` 이고, 「빈 값을 넣고 싶다」면 `;` 다.
- **값 조립은 생각보다 안 된다.** 실측: `--a: 10; --b: px; width: var(--a)var(--b)` 가 **무효**가 됐다(계산값 auto).\
  토큰은 이어 붙지 않으므로 **단위는 `calc(var(--a) * 1px)`** 로 붙인다.
- **`!important` 는 커스텀 속성에도 붙는다** — 실측: `--i: red` 를 `--i: blue !important` 가 덮었다.\
  다만 `var()` 를 쓰는 쪽의 `!important` 와는 별개로 도는 층이라 읽기 어려워진다.
- **인라인 스타일에서도 된다** — 실측: `style="--il: crimson; color: var(--il)"` 이 정상 동작했다.\
  JS 에서 스타일을 계산해 넣을 때 이 형태가 가장 싸다.
- **`content` 에도 쓸 수 있다** — 실측: `::before { --t: "hi"; content: var(--t) }` 가 `"hi"` 를 냈다.\
  생성 콘텐츠의 정본은 [13번](../13-pseudo-elements-and-generated-content/2-summary.md)이다.
- **성능은 「무엇이 다시 도는가」의 문제다.** 루트 변수 하나를 바꾸면 그 변수를 쓰는 모든 요소가 다시 계산된다.\
  드래그처럼 초당 수십 번 바꾸는 자리에서는 **가장 가까운 조상**에 써서 범위를 좁힌다. 파이프라인의 정본은 [목록의 **56번 주제**](../56-rendering-pipeline-and-will-change/).
