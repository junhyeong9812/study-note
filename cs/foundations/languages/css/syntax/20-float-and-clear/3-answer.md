# css/syntax/20 — 부동(float)과 해제(clear) — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **모든 치수는 Google Chrome 151.0.7922.173 headless 에서 실제로 렌더해 잰 값**이다. 단위는 px 다.\
> ★ **상자는 `getBoundingClientRect()` 로, 행 상자는 `Range.getClientRects()` 로 따로 쟀다.** 이 주제에서는 둘이 다른 것을 말한다.\
> **손으로 계산해 유도한 수치는 없다.** 규칙은 [CSS Display Level 3](https://drafts.csswg.org/css-display-3/) 과 [CSS Logical Properties Level 1](https://drafts.csswg.org/css-logical-1/) 로 접지했다.

## 정답

### 1. 형제 블록은 밀리는가

**실행 결과** (Chrome 151 headless — 폭 300 컨테이너, float 120×80 이 y=1\~81)

```text
         블록 상자 (rect)              그 안의 행 상자 (Range)
블록 1   x=1.0  w=300.0  y=1.0        x=121.0  w=76.2
블록 2   x=1.0  w=300.0  y=21.0       x=121.0  w=89.0
블록 3   x=1.0  w=300.0  y=41.0       x=121.0  w=89.0
블록 4   x=1.0  w=300.0  y=61.0       x=121.0  w=89.0
블록 5   x=1.0  w=300.0  y=81.0       x=1.0    w=101.9
```

**다섯 형제의 `rect.x`·`rect.width`**

- **전부 `x=1` · `width=300` 이다.** 한 픽셀도 안 움직였다. float 가 없는 것처럼 자리를 잡았다.

**행 상자는 어디서 시작하나**

- float 높이(1\~81) 안에 걸린 블록의 줄은 **x=121** 에서 시작하고 폭이 **89** 로 줄었다(float 120 만큼 깎였다).

**몇 번째부터 왼쪽 끝으로 돌아오나**

- **다섯째부터**다. 블록 5 의 y 가 81 이라 float 밑을 벗어난다 — 줄이 **x=1 · 폭 101.9** 로 돌아왔다.

**배경색을 주면 보이는 것**

- **배경이 float 밑으로 깔려 겹쳐 보인다.** 상자는 안 밀렸고 배경은 상자의 것이기 때문이다.
- 스크린샷 픽셀로 확인 — float(파랑)와 블록 배경(노랑)이 겹치는 지점의 색이 **`(147,197,253)` 곧 파랑**이었다. **float 가 블록 배경 위에 그려진다**(그 순서의 정본은 [22번](../22-stacking-context-and-z-index/2-summary.md)).

### 2. float 와 absolute 는 무엇이 다른가

**실행 결과** (Chrome 151 headless — 같은 폭 300 컨테이너에 같은 크기 상자)

```text
             블록 rect        행 상자                    줄 수   부모 높이
float        x=1  w=300     x=101  w=197.1               3       60 (감쌀 때)
absolute     x=1  w=300     x=1    w=287.3               2       흐름에서 완전 제외
```

**빠지는 정도**

- **float** — 블록 배치에서는 빠지지만 **행 상자는 민다.** 「반쯤 빠졌다.」
- **`absolute`** — **줄도 안 민다.** 그냥 덮는다. 「완전히 빠졌다.」

**행 상자의 시작 x 와 폭**

- float 쪽은 **x=101 · 폭 197.1** 로 세 줄, absolute 쪽은 **x=1 · 폭 287.3** 으로 두 줄이었다.
- 같은 크기 상자인데 **absolute 쪽은 글자가 상자 밑에 깔려 읽을 수 없게 된다.**

**부모 높이 계산에 참여하는가**

- **둘 다 참여하지 않는다.** 단 **BFC 루트는 자기 안의 float 까지 포함해 높이를 잡는다**([17번](../17-block-formatting-context/2-summary.md)) — `absolute` 는 그때도 제외다.

**텍스트가 감싸 돌게 하려면**

- **float** 뿐이다. 이것이 오늘 float 에 남은 유일한 일이다.

### 3. `<span>` 에 float 를 걸면

**실행 결과** (Chrome 151 headless — 폭 300 컨테이너)

```text
대상                              계산값 display   rect
짧은 글 <span> + float:left          block         25.77 × 20
아주 긴 글 <span> + float:left       block        300.00 × 40   ← 컨테이너 폭에서 멈춤
블록 <div> + float:left              block        168.00 × 20   ← 폭 300 을 다 안 쓴다
<span> + float:left (폭 200 선언)    block        200.00 × 44
```

**계산값 `display`**

- **`block` 이다.** float 가 상자를 **블록화**한다.

**`width`·`height` 가 먹는가**

- **먹는다.** float 를 안 걸었을 때는 `<span>` 이 `rect` 41.73 × 24 로 **안 먹었는데**([19번](../19-inline-formatting-context/2-summary.md)), float 를 걸면 200 × 44 가 된다.
- 블록이 됐기 때문이다.

**`width` 를 지우면**

- **축소 맞춤(shrink-to-fit)** 이 된다 — 「내용이 원하는 만큼, 단 쓸 수 있는 폭을 넘지 않게」.
- 실측에서 짧은 글은 **25.77**, 아주 긴 글은 컨테이너 폭인 **300 에서 멈췄다.**

**float 한 블록이 부모 폭을 다 쓰는가**

- **안 쓴다.** 실측 **168** — 내용만큼이다. 「블록인데 왜 좁아졌지」의 답이 이것이다.

### 4. `clear` 는 무엇을 하는가

**실행 결과** (Chrome 151 headless — 왼쪽 float 밑변 71, 오른쪽 float 밑변 41, 컨테이너 안 y 좌표)

```text
clear        대상 y    컨테이너 높이
(없음)         1.0          72
right         41.0          72
left          71.0          92
both          71.0          92
```

**`clear` 없음**

- **y=1.** float 밑으로 그냥 깔린다(상자는 안 밀린다 — 1번과 같은 규칙).

**`clear: right`**

- **y=41.** 오른쪽 float 의 밑변까지만 내려간다. **왼쪽 float 는 여전히 옆에 있어** 그 안의 줄은 밀린다.

**`clear: left` / `both`**

- **둘 다 y=71.** 왼쪽 float 가 더 아래까지 내려와 있으므로 `both` 도 같은 값이 된다.

**위쪽만 보는가**

- **위쪽(앞선) float 만** 본다. 자기 뒤에 오는 float 는 안 본다.

### 5. `clear` 와 마진이 같이 있으면

**실행 결과** (Chrome 151 headless — float 밑변 71)

```text
선언                              대상 y   계산값 marginTop
clear:left; margin-top: 10px        71.0        10px
clear:left; margin-top: 120px      121.0       120px
```

**두 경우의 y**

- `margin-top: 10px` → **71.** 마진 10 이 아니라 **float 아래**로 갔다.
- `margin-top: 120px` → **121.** 이번엔 **마진이 이겼다**(121 > 71).
- 즉 **둘 중 더 아래쪽**이 이긴다.

**`getComputedStyle().marginTop`**

- **선언한 값 그대로 `10px` / `120px` 을 돌려준다.** 빈틈이 끼어도 마진 값은 안 바뀐다.

**계산값만 보고 판정해도 되는가**

- ★ **안 된다.** 계산값은 `10px` 인데 상자는 60px 더 내려가 있었다. **「값이 담겼나」와 「레이아웃이 무엇을 했나」가 다른 자리**다.
- 이 주제에서 두 번째로 나오는 같은 함정이다(첫 번째는 7번의 flex 항목 `float`).

**그 간격의 이름**

- **빈틈(clearance)** 이다. 마진이 아니라 별도의 값이고, 그래서 그 자리의 **마진 상쇄가 깨진다**([18번](../18-margin-collapsing/2-summary.md)).

### 6. 높이 붕괴

**실행 결과** — 이 수치는 [17번](../17-block-formatting-context/2-summary.md)이 정본이고 여기서는 결론만 인용한다.

```text
보통 부모          rect.height = 4     ← 위아래 테두리뿐. 안쪽 높이 0
display: flow-root rect.height = 64    ← float 60 + 테두리 4
```

**`rect.height`**

- **4 다.** 테두리 2 + 2 뿐이고 **안쪽 높이가 0** 이다.

**버그가 아닌 이유**

- **float 는 부모의 높이 계산에 참여하지 않는다.** 흐름에서 빠졌기 때문이고, 그것이 float 의 정의다.
- 높이가 0 인 것은 **규칙대로 된 결과**다.

**다음 형제는 어디에 놓이나**

- 부모 바로 아래(실측 부모 bottom=122, 형제 top=**122**)다. 그런데 **float 는 y=120\~180 까지 내려와** 있어 **그 형제 위를 뚫고 지나간다**([17번](../17-block-formatting-context/2-summary.md) 실측).

**막는 법의 정본**

- **[17번 주제](../17-block-formatting-context/2-summary.md)**(BFC)다. `display: flow-root` 한 줄이고, `overflow: hidden` 등 다른 수단의 부작용 대조도 거기 있다.

### 7. flex 항목의 `float`

**실행 결과** (Chrome 151 headless — `display: flex` 컨테이너의 첫 항목)

```text
                  rect.x   rect.width   형제의 x   계산값 display   계산값 float
float 선언 없음     1.0        8.52        9.5        block          none
float: left        1.0        8.52        9.5        block          left
```

**`rect` 가 다른가**

- **한 픽셀도 안 다르다.** 자기도 형제도 같은 자리다.

**`getComputedStyle().float`**

- **`left` 를 돌려준다.** 값은 담겼다.

**계산값으로 판정할 수 있는가**

- **없다.** 담겼는데 **수행되지 않았다.**

**어느 창의 한계인가**

- 진단 3창의 **셋째 창(`getComputedStyle`)** 이다.
- 셋째 창은 「**캐스케이드에서 이겼나**」까지만 말한다. **레이아웃이 그 값을 썼는지**는 `rect` 로 재야 한다.
- 이 주제에서 같은 함정이 **두 번** 나온다(5번의 `marginTop`, 7번의 `float`). [19번](../19-inline-formatting-context/2-summary.md)의 인라인 `height` 까지 치면 이 사슬에서만 세 번이다.

### 8. 여럿을 띄우면

**실행 결과** (Chrome 151 headless — 폭 300, 120×40 짜리)

```text
셋만:          1번 (1,1)   2번 (121,1)   3번 (1,41)        컨테이너 높이 82
float:right 를 하나 더:                   right (181,41)
```

**세 개의 자리**

- 1번 **(1,1)** · 2번 **(121,1)** · 3번 **(1,41)** — 셋째가 **둘째 줄**로 내려갔다.

**왜 내려가나**

- 120 + 120 = 240 까지는 폭 300 에 들어가지만 셋째는 안 들어간다.
- ★ **float 끼리는 겹치지 않는다.** 자리가 없으면 아래로 내려가는 것이 규칙이다(`absolute` 끼리는 겹친다).

**500px 으로 키우면**

- 셋이 한 줄에 들어간다(120 × 3 = 360 ≤ 500).

**옛 그리드의 문제**

- **높이가 제각각이면 다음 줄이 엉뚱한 곳에 걸린다.** float 는 「앞 float 들의 밑변 중 가장 낮은 곳」이 아니라 **자리가 나는 첫 지점**에 붙으므로, 키 큰 카드 하나가 다음 줄 전체를 어긋나게 만든다.
- 그래서 [flex](../24-flexbox-axes/2-summary.md)·grid 가 나왔다.

### 9. 오늘 float 에 남은 용도

**float 만 할 수 있는 일**

- **글이 상자를 감싸 도는 것**이다. 실측에서 float 옆 행 상자가 **폭 197 로 깎였고**, float 밑을 벗어난 줄은 **폭 101.9** 로 돌아왔다 — **같은 블록 안에서 줄마다 폭이 달라진다.**

**flex 로는 왜 안 되나**

- flex 항목은 **통째로 한 덩어리**라 그 옆 글이 **줄마다 다른 폭**을 가질 수 없다. 두 칸으로 나뉠 뿐이다.

**감싸는 모양을 바꾸는 속성**

- **`shape-outside`** 다. **이 주제 밖이라 이름만 적는다.**

**옛 `float: left; width: 33.33%` 의 오늘**

- **grid** 다(`grid-template-columns: repeat(3, 1fr)`). 칸 사이 간격·높이 정렬이 전부 딸려 온다.
- 1차원이면 [flex](../24-flexbox-axes/2-summary.md).

### 10. 다른 주제로 잇기

**행 상자의 정본**

- [19번 주제](../19-inline-formatting-context/2-summary.md)(인라인 서식 문맥)다. **행 상자가 무엇인지**는 거기, **무엇이 그것을 미나**가 여기다.

**세로 마진 상쇄에 참여하는가**

- **참여하지 않는다.** 실측에서 `margin: 30px 0` 인 float 둘이 나란히 y=31 에 놓이고 컨테이너 높이가 **102**(30+40+30+테두리 2)였다 — 위아래 마진이 하나도 합쳐지지 않았다.
- 정본은 [18번 주제](../18-margin-collapsing/2-summary.md)다.

**float 옆 블록에 BFC 를 열면**

- **상자 자체가 밀린다.** [17번](../17-block-formatting-context/2-summary.md) 실측 — 보통 상자 `x=2 · w=300`(컨테이너 폭 전체), BFC 상자 **`x=102 · w=200`**.
- 즉 **보통은 줄만, BFC 면 상자까지** 밀린다. 이 주제의 1번과 정확히 짝이다.

**`float: inline-start` 의 정본**

- [목록의 **32번 주제**](../32-logical-properties-and-writing-mode/)(논리 속성과 글쓰기 방향)다.
- 실측에서 폭 120 짜리 `inline-end` float 가 폭 300 컨테이너의 **x=181** 에 붙었고 계산값이 `inline-end` 로 유지됐다.

## 용어 풀이

- **부동(float)** — 상자를 컨테이너 한쪽 끝에 붙이고 **행 상자가 그 옆을 흐르게** 하는 것.
- **해제(clear)** — 자기 위쪽 float 아래에서 시작하라는 지시. **자기 자신에게 거는 선언**이다.
- **빈틈(clearance)** — `clear` 가 만드는 별도의 세로 간격. 마진이 아니라 `marginTop` 계산값이 안 바뀐다.
- **보통 흐름(normal flow)** — 블록은 위아래로, 인라인은 줄을 따라 놓이는 기본 배치.
- **흐름에서 빠진다(out of flow)** — 형제들의 자리 계산에 참여하지 않는 상태. float 는 **줄은 밀고**, `absolute`/`fixed` 는 **줄도 안 민다.**
- **축소 맞춤(shrink-to-fit)** — 「내용만큼, 단 쓸 수 있는 폭을 넘지 않게」 폭을 정하는 방식.
- **블록화(blockification)** — 선언 때문에 바깥 `display` 가 `block` 으로 강제되는 것. `float` 와 `absolute` 가 그렇게 만든다.
- **높이 붕괴(height collapse)** — 안에 float 만 있는 상자의 높이가 0 이 되는 현상. 막는 법은 [17번](../17-block-formatting-context/2-summary.md).
- **`shape-outside`** — 감싸는 모양을 사각형 말고 다른 도형으로 바꾸는 속성. **이 주제 밖이라 이름만 적는다.**

**구현 의존 항목** — ★ **`float` 의 계산값이 flex 항목에서 `left` 로 남는 것은 이 브라우저의 관찰**이다. 명세가 말하는 것은 「부동을 만들지 않는다」이지 「계산값이 `none` 이 된다」가 아니다.\
