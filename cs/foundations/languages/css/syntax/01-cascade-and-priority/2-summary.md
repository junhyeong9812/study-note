# css/syntax/01 — 캐스케이드와 우선순위 계산: 출처·`!important`·레이어·명시도·순서 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Cascading and Inheritance Level 5](https://drafts.csswg.org/css-cascade-5/) 의 「Cascade Sorting Order」·「Cascading Origins」·「Cascade Layers」 절. 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 `demo` 블록 **3개 전부**를 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워 `getComputedStyle` 로 확인했다(CDP `Runtime.evaluate`). 「보이는 것」에 적은 색은 전부 그 실측값이다.\
> **WebKit(Safari)은 이 머신에 없다** — Safari 관련 서술은 하지 않았다.
> **버전** — CSS 에는 언어 버전이 없다. 이 주제의 두 축은 각각 Baseline **widely**: 캐스케이드·`!important` 는 CSS1 부터, `@layer` 는 newly 2022-03-14 / widely 2024-09-14(목록 README 의 지원 표).
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 화면은 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**캐스케이드 = 한 자리를 두고 후보가 여럿 붙었을 때, 심사위원 여섯이 순서대로 탈락시키는 토너먼트다.**

비유 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 한 자리 | 요소 하나의 속성 하나 (`p` 의 `color`) |
| 후보 | 그 자리를 노리는 **선언**(`color: red` 한 줄) |
| 심사위원 여섯 | 캐스케이드 정렬 기준 6단계 |
| 최종 당선자 | 그 속성의 **지정값(specified value)** |

- 후보는 여럿이지만 **당선자는 하나**다.\
  같은 요소의 `color` 에 선언이 다섯 줄 걸려 있어도 화면에 칠해지는 색은 하나다.
- 심사위원은 **차례대로** 본다.\
  1번 심사위원이 이미 한 명만 남기면 **2번부터는 아예 부르지 않는다.**
- 그래서 "명시도(5번 심사위원)를 올렸는데 왜 안 먹지"의 답은 거의 언제나\
  **이미 1번이나 4번에서 승부가 끝나 있었다**는 것이다.

```text
후보 5명 (같은 요소의 color 에 걸린 선언들)
   │
   ├─ 1 출처·중요도 ──> 여기서 한 명만 남으면 끝. 아래는 안 본다
   ├─ 2 문맥
   ├─ 3 요소 부착 스타일 (style="")
   ├─ 4 캐스케이드 레이어 (@layer)
   ├─ 5 명시도            <- 흔히 "우선순위"라 부르는 것은 여기 하나뿐이다
   └─ 6 등장 순서 (나중에 쓴 것)
   │
   v
 당선자 1명 = 그 속성의 지정값
```

실무에서 이게 터지는 자리는 **남의 CSS 를 덮어쓸 때**다.\
선택자를 길게 늘여도 안 먹어서 `!important` 를 붙이는 순간, 다음 사람도 `!important` 를 붙이고, 그 다음 사람은 붙일 게 없어진다.

> **선언(declaration)** — `속성: 값` 한 쌍. 규칙(`선택자 { ... }`) 하나에 선언이 여러 개 들어간다.\
> 예: `.btn { color: red; padding: 8px }` 은 규칙 1개, 선언 2개다.

> **지정값(specified value)** — 캐스케이드가 끝나 그 속성에 최종으로 배정된 값.\
> 예: `color` 에 선언이 다섯 줄 걸렸어도 지정값은 그중 이긴 하나다. 이 값이 계산값으로 넘어간다(목록의 **04번 주제**).

> **캐스케이드(cascade)** — 여러 출처에서 온 선언들을 한 줄로 세워 **속성마다 하나씩** 승자를 뽑는 알고리즘.\
> 예: 브라우저 기본 스타일·사용자 스타일·내 스타일시트가 같은 `color` 를 건드려도 결과는 하나다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. 같은 요소의 같은 속성에 선언이 여럿 붙었을 때, **엔진은 무엇을 어떤 순서로 보는가.**
2. "선택자를 더 길게 썼는데 안 먹는다"는 **여섯 심사위원 중 몇 번에서 이미 끝난 승부인가.**
3. `!important` 는 왜 **명시도를 올리는 게 아니라 그 위층을 통째로 바꾸는가.**

## 동작 방식

### (0) 캐스케이드가 도는 자리 — 수집 → 정렬 → 값 하나

**언제 쓰나** — 문서의 모든 요소, 모든 속성에 대해 매번. 내가 부르는 게 아니라 엔진이 스타일 계산 단계에서 자동으로 돈다.

```text
① 수집   이 요소에 매치되는 규칙을 전부 모은다
              (UA 기본 시트 + 사용자 시트 + 내 시트 + style="" + 애니메이션/전환)
              ↓
② 분해   규칙을 선언 단위로 쪼개 속성별 바구니에 담는다
              color 바구니 [5개] · padding 바구니 [2개] · display 바구니 [1개]
              ↓
③ 정렬   바구니마다 따로, 6단계 기준으로 줄을 세운다   <- 이 주제의 본체
              ↓
④ 확정   바구니마다 1등 하나 = 그 속성의 지정값
```

그림 해설 (한 단계씩):

- ②가 이 주제에서 가장 자주 잊히는 단계다 — **캐스케이드는 규칙 단위가 아니라 속성 단위로 돈다.**\
  `.a` 규칙이 `color` 에서 지고 `padding` 에서 이기는 일이 정상이다.
- ③은 바구니마다 **독립적으로** 돈다. 한 규칙이 통째로 이기거나 지는 일은 없다.
- ④ 이후는 캐스케이드가 아니다 — 상속(목록의 **03번**)과 값 처리(**04번**)가 이어받는다.

비용 — 요소 수 × 매치 규칙 수. 이 계산 자체는 눈에 안 보이고, 개발자 도구의 Styles 패널이 ③의 결과를 줄 그어 보여 주는 것이다.

### (1) 1단계 — 출처와 중요도: 여덟 칸짜리 사다리

**언제 쓰나** — 언제나 맨 먼저. `!important` 가 하나라도 끼면 여기서 승부가 난다.

명세(`css-cascade-5` 「Cascade Sorting Order」)가 정한 순서다. **위가 셈.**

```text
   센 쪽
     ^   1. 전환(transition) 선언            <- 전환이 도는 동안의 값
     |   2. user-agent 의 !important
     |   3. 사용자(user) 의 !important       <- 접근성 설정이 여기 산다
     |   4. 작성자(author) 의 !important     <- 내 시트의 !important
     |   5. 애니메이션(@keyframes) 선언
     |   6. 작성자(author) 의 normal          <- 내 시트의 보통 선언
     |   7. 사용자(user) 의 normal
     v   8. user-agent 의 normal              <- 브라우저 기본 스타일
   약한 쪽
```

그림 해설 (한 단계씩):

- **`!important` 는 명시도를 올리는 장치가 아니다.** 4번 칸에서 6번 칸으로 옮겨 타는 장치다.\
  칸이 다르면 명시도는 **비교조차 되지 않는다** — 5번 심사위원을 부르기 전에 1번이 끝내 버린다.
- 사다리의 `!important` 쪽은 **위아래가 뒤집혀 있다**(2·3·4번 대 6·7·8번).\
  normal 에서는 작성자가 사용자를 이기지만, important 에서는 **사용자가 작성자를 이긴다.**\
  글자 크기를 강제로 키워 쓰는 사람의 설정을 사이트가 못 덮게 하려는 장치다.
- 그래서 **`!important` 는 "가장 세게"가 아니다.** 2·3번과 1번이 그 위에 있다.

> **출처(origin)** — 그 선언이 어디서 왔나. `user-agent`(브라우저 기본 시트) · `user`(사용자 설정) · `author`(페이지가 싣는 시트)의 셋.\
> 예: `<a>` 가 파랗고 밑줄이 있는 것은 내가 안 썼는데도 있는 것 — user-agent 출처다.

> **`!important`** — 선언 끝에 붙여 그 선언을 같은 출처의 "중요" 칸으로 올리는 표시.\
> 예: `color: red !important;` — 세미콜론 **앞**에 붙는다.

**실행 확인하지 않음** — 1·2·3번 칸(전환 선언·UA/사용자 important)은 이 문서에서 실제로 돌려 보지 않았다. 명세 기술로만 적었다. 4·6번 칸은 아래 demo 로 확인했다.

### (2) 2단계 문맥 · 3단계 요소 부착 스타일

**언제 쓰나** — `style=""` 속성을 쓰거나 그림자 DOM 안의 스타일을 다룰 때.

- **2단계 문맥(context)** — 그림자 트리와 바깥 문서의 선언이 부딪힐 때 쓰는 기준이다.\
  이 목록에 그림자 DOM 주제가 없으므로 여기서는 **자리만 표시**하고 다루지 않는다.
- **3단계 요소 부착 스타일** — HTML 의 `style=""` 속성에 쓴 선언이다.\
  선택자가 없으므로 명시도가 없고, **4·5·6단계를 건너뛰고 여기서 이긴다.**

```html demo
<p id="p1" style="color:#1d4ed8">style 속성 대 시트</p>
<p id="p2" style="color:#1d4ed8">style 속성 대 시트의 !important</p>
<style>
  #p1 { color: #b91c1c; }
  #p2 { color: #b91c1c !important; }
  p { font: 20px/1.6 system-ui, sans-serif; }
</style>
```

> **보이는 것** — 첫 줄은 **파랑(#1d4ed8)**, 둘째 줄은 **빨강(#b91c1c)** 으로 나온다. 시트의 `#p1` 은 ID 선택자인데도 `style=""` 를 못 이기고(3단계에서 졌다), `#p2` 는 `!important` 로 1단계로 올라가 다시 이긴다.\
> **바꿔 볼 것** — `#p1` → `#p1#p1#p1`(명시도 3배) → **여전히 파랑**(명시도는 5단계라 안 불린다) · `style="color:#1d4ed8"` → `style="color:#1d4ed8 !important"` → 둘째 줄도 파랑으로 돌아온다

*(Chrome 151 headless 실측: `#p1` = `rgb(29, 78, 216)`, `#p2` = `rgb(185, 28, 28)`.)*

비용 — 없음. 다만 `style=""` 가 4·5·6단계를 통째로 건너뛰므로, **JS 로 인라인 스타일을 찍는 코드는 시트로 덮을 수 없다** — `!important` 말고는 수단이 없어진다.

### (3) 4단계 — 캐스케이드 레이어

**언제 쓰나** — `@layer` 를 쓴 문서. 안 쓰면 이 단계는 그냥 지나간다.

`@layer` 는 **명시도보다 위에 있는 서랍장**을 만든다. 서랍 순서는 처음 이름을 나열한 줄이 정한다.

```text
@layer base, theme;        서랍 순서를 먼저 선언한다

   normal 선언                       important 선언
   +---------------------+           +---------------------+
   | base   (먼저)       |  약함      | base   (먼저)       |  셈  <- 뒤집힌다
   | theme  (나중)       |  셈        | theme  (나중)       |  약함
   | 레이어 밖           |  가장 셈    | 레이어 밖           |  가장 약함
   +---------------------+           +---------------------+
```

명세가 이 뒤집힘을 이렇게 적는다.

> for normal rules the declaration whose cascade layer is latest in the layer order wins, and for important rules the declaration whose cascade layer is earliest wins.

레이어 밖 규칙의 자리도 명세가 못박는다.

> Unlayered rules are sorted later than any layered rules within the same parent layer (if any).

```html demo
<p class="a">normal 선언 — 어느 레이어가 이길까?</p>
<p class="b">important 선언 — 어느 레이어가 이길까?</p>
<style>
  @layer base, theme;                    /* 레이어 순서: base → theme */
  @layer base  { .a { color: #b91c1c; } .b { color: #b91c1c !important; } }
  @layer theme { .a { color: #15803d; } .b { color: #15803d !important; } }
  p { font: 20px/1.6 system-ui, sans-serif; }
</style>
```

> **보이는 것** — 첫 줄은 나중 레이어 `theme` 의 **초록(#15803d)**, 둘째 줄은 먼저 선언한 레이어 `base` 의 **빨강(#b91c1c)**. 두 규칙 집합은 완전히 대칭인데 `!important` 하나가 레이어 순서를 통째로 뒤집는다.\
> **바꿔 볼 것** — 첫 줄 `@layer base, theme;` → `@layer theme, base;` → 두 줄의 색이 서로 맞바뀐다 · `.b` 의 `!important` 를 양쪽 다 떼면 → 둘째 줄도 초록이 된다

*(Chrome 151 headless 실측: `.a` = `rgb(21, 128, 61)`, `.b` = `rgb(185, 28, 28)`.)*

그림 해설 (한 단계씩):

- 레이어는 **명시도보다 먼저** 본다. 그래서 `base` 안의 `#id` 선언이 `theme` 안의 타입 선택자 하나에 진다.\
  이것이 `@layer` 의 존재 이유다 — **남의 시트를 덮으려고 선택자를 길게 늘이는 일을 없앤다.**
- `!important` 를 레이어 안에서 쓰면 **의도와 반대로 동작하기 쉽다.**\
  "가장 나중 레이어에서 강제로 덮겠다"고 `!important` 를 붙이면 그 순간 가장 약해진다.
- 레이어 밖에 쓴 규칙은 normal 에서 가장 세다 — **레이어를 도입한 프로젝트에서 한 줄만 레이어 밖에 남겨 두면 그 한 줄이 전부를 이긴다.**

비용 — 없음(런타임 비용이 아니라 판정 순서다). 대신 **레이어 순서 선언을 한 곳에 모아 두지 않으면** 사람이 4단계를 추적할 수 없게 된다.

> **캐스케이드 레이어(cascade layer)** — `@layer` 로 만든, 명시도보다 위에서 비교되는 우선순위 서랍.\
> 예: `@layer reset, base, components;` 라고 선언하면 `components` 안의 어떤 약한 선택자도 `reset` 안의 어떤 센 선택자를 이긴다.

### (4) 5단계 명시도 · 6단계 등장 순서

**언제 쓰나** — 앞 네 단계가 전부 동점일 때. **평소 내가 쓰는 CSS 의 대부분이 여기까지 온다.**

- **5단계 명시도** — 선택자를 `(A, B, C)` 세 자리 숫자로 환산해 비교한다.\
  이 계산은 분량이 커서 **[02번 주제](../02-specificity/2-summary.md)가 정본**이다. 여기서는 "5번 심사위원"이라는 자리만 잡는다.
- **6단계 등장 순서** — 그것마저 같으면 **나중에 읽힌 선언**이 이긴다.\
  같은 파일 안이면 아래쪽, 파일이 여럿이면 나중에 `<link>` 한 쪽.

```text
같은 (0,1,0) 끼리 붙었을 때 — 6단계까지 내려온다

  a.css:  .btn { color: red }      (먼저 읽힘)
  b.css:  .btn { color: blue }     (나중 읽힘)   <- 이긴다

  <link href="a.css"><link href="b.css">   순서를 바꾸면 결과도 바뀐다
```

비용 — 없음. 다만 **6단계에 의존하는 CSS 는 파일 순서가 바뀌면 조용히 깨진다** — 번들러 설정 하나로 색이 달라진다.

### (5) 종합 — 한 요소를 손으로 판정해 본다

**언제 쓰나** — "왜 이 색이지"를 개발자 도구 없이 설명해야 할 때.

후보 셋이 같은 `color` 자리를 노린다.

```text
후보 A   p     { color: #15803d }              작성자 normal · (0,0,1)
후보 B   #lead { color: #1d4ed8 }              작성자 normal · (1,0,0)
후보 C   .note { color: #b91c1c !important }   작성자 important · (0,1,0)

1단계 출처·중요도
   C = 사다리 4번(작성자 important)
   A, B = 사다리 6번(작성자 normal)
   +---------------------------+
   | 4번 칸 : C                |  <- 더 위 칸에 후보가 있으므로
   | 6번 칸 : A, B             |     여기서 C 하나만 남는다
   +---------------------------+
         ↓
   남은 후보 1명 -> 2~6단계는 부르지 않는다
         ↓
   당선 : color = #b91c1c
```

```html demo
<p class="note" id="lead">이 줄은 무슨 색으로 나올까?</p>
<style>
  p     { color: #15803d; font: 20px/1.6 system-ui, sans-serif; } /* (0,0,1) */
  #lead { color: #1d4ed8; }                                       /* (1,0,0) */
  .note { color: #b91c1c !important; }                            /* (0,1,0) + ! */
</style>
```

> **보이는 것** — 줄이 **빨강(#b91c1c)** 으로 나온다. 명시도가 가장 높은 `#lead` 의 파랑도, 가장 마지막에 쓰인 `.note` 가 아니었다면 이겼을 순서도 소용없다 — `!important` 가 명시도를 보기도 전에 1단계에서 판을 갈랐다.\
> **바꿔 볼 것** — `.note` 에서 `!important` 를 떼면 → **파랑**(이제 1단계 동점, 5단계로 내려가 `#lead` 가 이김) · `p` 선언에도 `!important` 를 붙이면 → **여전히 빨강**(같은 important 칸끼리라 5단계로 내려가고 `(0,1,0)` > `(0,0,1)`)

*(Chrome 151 headless 실측: `rgb(185, 28, 28)`.)*

그림 해설 (한 단계씩):

- 승부는 **1단계에서 끝났다.** 명시도 세 자리를 아무리 잘 계산해도 이 판정에는 안 쓰인다.
- 그래서 "명시도를 올렸는데 왜 안 먹지"의 진단 순서는 **위에서부터**다 — `!important` 있나 → `style=""` 있나 → `@layer` 쓰나 → 그다음이 명시도다.
- 개발자 도구에서 이긴 선언 위의 줄 그어진 선언들이 **탈락한 후보 목록**이다.

비용 — 사람의 비용. 1단계에 의존하는 CSS 가 늘수록 5·6단계로 조정할 여지가 사라진다.

## 문법 — 형태와 규칙

직접 쓴 최소 예제다. 묻는 것 하나만 남겼다.

### `!important` 는 선언마다, 세미콜론 앞에

```css
.a { color: red !important; }        /* 유효 */
.b { color: red! important; }        /* 무효 — ! 와 important 사이는 붙여도 되고 공백도 되지만 ! 가 important 앞이어야 한다 */
.c { color: red; !important }        /* 무효 — 선언 밖 */
.d { margin: 0 auto !important; }    /* 단축에 붙이면 그 단축이 푸는 모든 하위 속성에 붙는다 */
```

- **규칙이 아니라 선언에 붙는다.** 한 규칙 안에서 어떤 선언만 important 로 만들 수 있다.
- `.b`·`.c` 처럼 잘못 쓰면 **그 선언 하나만 버려진다** — 규칙 전체가 죽지 않는다(목록의 **07번 주제**, 오류 복구).

### `@layer` 의 세 형태

```css
@layer reset, base, theme;              /* ① 순서만 먼저 선언 (권장) */

@layer base { p { color: #333 } }       /* ② 이름 붙은 블록 */

@layer { p { color: #333 } }            /* ③ 익명 레이어 — 그 자리에 새 레이어가 생긴다 */

@import url(x.css) layer(base);         /* ④ 외부 시트를 레이어에 넣기 */
```

- 레이어 순서는 **이름이 처음 나타난 순간** 정해진다. ①처럼 맨 위에 한 줄로 모아 두는 이유가 이것이다.
- 같은 이름의 `@layer base { }` 를 여러 번 써도 **레이어는 하나**이고, 순서는 처음 자리 그대로다.
- 레이어 안에 레이어를 넣으면 `@layer base.reset` 처럼 점으로 가리킨다.

### 사다리를 되돌리는 키워드

| 키워드 | 무엇으로 되돌리나 |
|---|---|
| `revert` | 이 출처의 선언을 없앤 셈 치고 **아래 출처의 값**으로 |
| `revert-layer` | 이 레이어의 선언을 없앤 셈 치고 **앞 레이어의 값**으로 |

둘 다 **[03번 주제](../README.md)(상속과 전역 키워드)가 정본**이고, 여기서는 "캐스케이드 결과를 한 칸 되돌리는 수단이 있다"는 것만 짚는다. *(이 문서에서 실행 확인하지 않았다.)*

## 어디서 틀리나

이 주제의 값어치는 전부 여기 있다. 다섯 다 **에러 없이 조용히 어긋난다.**

### 1. "명시도를 올렸는데 안 먹는다"

```text
내가 한 것                              실제로 진 곳
+-------------------------------+      +-------------------------------+
| .card .title  (0,2,0)         |      | 상대는 !important 였다        |
|   ↓ 안 먹어서                 |      |   -> 1단계에서 끝난 승부      |
| #app .card .title  (1,2,0)    |      |   -> 5단계는 불리지도 않았다  |
|   ↓ 그래도 안 먹어서          |      |                               |
| #app #main .card .title       |      | 선택자만 길어지고 결과는 같다 |
+-------------------------------+      +-------------------------------+
```

선택자를 늘리기 전에 **개발자 도구에서 이긴 선언에 `!important` 나 `style=""` 가 붙어 있는지부터 본다.**

### 2. `!important` 로 `!important` 를 이기려는 경쟁

같은 칸(작성자 important)에 둘 다 올라가면 다시 5단계로 내려간다.\
그래서 `!important` 싸움의 결말은 **명시도 싸움 + 되돌릴 수단 없음**이다 — 아무것도 해결하지 못하고 조정 여지만 잃는다.

### 3. `@layer` 안의 `!important` 는 의도와 반대로 간다

```text
의도                                     실제
+-------------------------------+       +-------------------------------+
| @layer theme {                |       | important 에서는 레이어 순서가 |
|   .btn { color: red !important}|       | 뒤집힌다                      |
| }                             |       |                               |
| "가장 나중 레이어니까 무조건   |       | theme 가 가장 나중이면         |
|  이기겠지"                     |       | important 에서는 가장 약하다   |
+-------------------------------+       +-------------------------------+
```

demo 의 둘째 줄이 바로 이 경우다 — 나중 레이어인 `theme` 가 졌다.

### 4. 레이어 밖에 남은 한 줄이 전부를 이긴다

`@layer` 를 도입하면서 기존 시트 한 장을 레이어에 안 넣으면, 그 시트의 **모든 normal 선언이 레이어 안의 모든 선언을 이긴다.**\
"레이어를 썼는데 왜 예전 스타일이 계속 이기지"의 답이 대개 이것이다.

### 5. 캐스케이드는 속성마다 따로 돈다 — 단축 속성의 함정

```css
/* 같은 요소에 .theme .card 둘 다 걸려 있다 */
.theme { background-color: navy; }
.card  { background: url(a.png) no-repeat; }   /* 단축 — 안 적은 하위 속성을 initial 로 되돌린다 */
```

단축 `background` 는 `background-color` 바구니에도 **`transparent`(initial) 후보를 하나 넣는다.**\
두 선언의 명시도가 같으면 6단계(순서)로 내려가 **나중에 쓴 `.card` 가 이기고, navy 가 사라진다.**

```text
background-color 바구니              background-image 바구니
+---------------------------+       +---------------------------+
| .theme  navy      (0,1,0) |       | .card  url(a.png) (0,1,0) |
| .card   transparent(0,1,0)| <- 나중 |                           |
+---------------------------+       +---------------------------+
  당선: transparent                    당선: url(a.png)
```

**바구니마다 승자가 따로**다 — 이미지는 살아 있고 색만 조용히 사라진다.\
순서를 뒤집어 `.card` 를 먼저 쓰면 색은 navy 로 남는다. *(Chrome 151 headless 실측: 뒤 순서 `rgba(0, 0, 0, 0)` · 앞 순서 `rgb(0, 0, 128)`, 두 경우 모두 `background-image` 는 그대로.)*

### 6. 상속은 캐스케이드가 아니다

부모의 값이 자식으로 내려오는 것은 캐스케이드가 끝난 **뒤** 일이다.\
자식에게 걸린 선언이 **하나라도 있으면** 상속은 일어나지 않는다 — 아무리 약한 선언이라도 상속을 이긴다.\
이 규칙은 목록의 **03번 주제**가 정본이다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 서드파티 시트를 통째로 아래에 깔고 싶다 | `@layer` 에 `@import` 로 넣기 | 내 선택자 길이 늘리기 |
| 유틸리티 클래스(`.mt-0`)가 항상 이겨야 한다 | 유틸리티를 **가장 나중 레이어**에 | `!important` 를 전부에 붙이기 |
| 남의 인라인 `style=""` 를 덮어야 한다 | `!important` (다른 수단이 없다) | 명시도 올리기 (5단계는 안 불린다) |
| 접근성 사용자 설정을 존중해야 한다 | 작성자 `!important` 를 아끼기 | 폰트 크기·색에 `!important` |
| 상태 하나만 예외로 덮고 싶다 | 같은 레이어 안에서 명시도·순서로 | `!important` |

판단 규칙 두 줄.

- **`!important` 는 "세게"가 아니라 "다른 칸으로"다.** 칸을 옮기면 되돌릴 수단이 사라진다.
- **우선순위 문제가 반복되면 명시도가 아니라 레이어 설계를 본다.** 5단계에서 싸우는 것은 4단계 설계가 없다는 신호다.

## 핵심 문장

- 캐스케이드는 **속성마다 따로** 도는 6단계 토너먼트이고, 앞 단계에서 갈리면 뒤 단계는 **부르지도 않는다.**
- `!important` 는 명시도를 올리지 않는다 — **출처·중요도 사다리에서 칸을 갈아탄다.** 그래서 명시도 비교 자체가 일어나지 않는다.
- 사다리는 `!important` 쪽에서 **위아래가 뒤집힌다** — 사용자의 important 가 작성자의 important 를 이긴다.
- `@layer` 는 명시도보다 **위**에 있고, `!important` 가 붙으면 레이어 순서도 뒤집힌다.
- `style=""` 는 선택자가 없어 명시도가 없고, 4·5·6단계를 건너뛴다 — 시트로 덮으려면 `!important` 말고 방법이 없다.

## 용어 풀이

- **캐스케이드(cascade)** — 여러 출처의 선언을 속성마다 한 줄로 세워 승자를 하나 뽑는 알고리즘.
- **선언(declaration)** — `속성: 값` 한 쌍. 캐스케이드의 후보 단위.
- **규칙(rule)** — `선택자 { 선언들 }` 한 덩어리. 캐스케이드는 규칙이 아니라 선언 단위로 돈다.
- **출처(origin)** — 선언이 온 곳. user-agent(브라우저 기본) · user(사용자 설정) · author(페이지 시트).
- **중요도(importance)** — `!important` 가 붙었나 안 붙었나. 출처와 짝지어 사다리 여덟 칸을 만든다.
- **`!important`** — 선언을 같은 출처의 "중요" 칸으로 올리는 표시. 세미콜론 앞, 선언마다 붙인다.
- **캐스케이드 레이어(cascade layer)** — `@layer` 로 만든, **명시도보다 위**에서 비교되는 우선순위 서랍.
- **레이어 밖(unlayered)** — 어떤 레이어에도 안 들어간 규칙. normal 에서 가장 세고 important 에서 가장 약하다.
- **요소 부착 스타일(element-attached style)** — HTML 의 `style=""` 속성. 선택자가 없어 명시도가 없다.
- **명시도(specificity)** — 선택자를 `(A, B, C)` 세 자리로 환산한 값. 5단계에서만 쓰인다. 정본은 02번.
- **등장 순서(order of appearance)** — 마지막 기준. 나중에 읽힌 선언이 이긴다.
- **지정값(specified value)** — 캐스케이드가 확정한 값. 상속·값 처리의 입력이 된다.
- **단축 속성(shorthand property)** — `background`·`margin` 처럼 여러 하위 속성을 한 번에 쓰는 속성. 안 적은 하위 속성을 initial 로 되돌린다.

## [Claude 추가] 더 알면 좋은 것

- 브라우저 개발자 도구의 Styles 패널은 **6단계 정렬 결과를 위에서부터 보여 주고, 진 선언에 줄을 긋는다.**\
  줄이 그어졌는데 이유를 모르겠으면 위 선언을 보는 게 아니라 **사다리 칸부터** 본다.
- `@layer` 는 **선언 순서가 아니라 레이어 순서**를 본다 — 파일을 나중에 `<link>` 해도 그 안의 규칙이 먼저 선언된 레이어에 들어 있으면 여전히 약하다.\
  이것이 번들 순서에 의존하던 CSS 아키텍처를 대체하는 지점이다.
- `!important` 를 아예 못 쓰게 만드는 관례 대신, **유틸리티 클래스를 마지막 레이어에 두는 설계**가 오늘의 표준 해법이다.\
  방법론(BEM·ITCSS)이 아니라 언어 기능으로 푸는 쪽이다(목록 README 의 「뺀 것과 이유」 참고).
- 전환·애니메이션 선언이 사다리에 **따로 칸을 갖는 이유**는, 그 값들이 스타일시트의 선언이 아니라 **시간에 따라 엔진이 만들어 내는 값**이기 때문이다.\
  그래서 전환이 도는 동안에는 `!important` 조차 그 값을 못 덮는다(목록의 **52번 주제**).
