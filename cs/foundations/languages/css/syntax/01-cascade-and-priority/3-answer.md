# css/syntax/01 — 캐스케이드와 우선순위 계산: 출처·`!important`·레이어·명시도·순서 — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일에 적힌 **모든 색·계산값은 Google Chrome 151.0.7922.173 headless 에서 실제로 돌려 `getComputedStyle` 로 읽은 값**이다.\
> 규칙은 [CSS Cascading and Inheritance Level 5](https://drafts.csswg.org/css-cascade-5/) 로 접지했다.\
> 사다리 1·2·3번 칸(전환 선언 · user-agent/사용자 `!important`)은 **돌려 보지 않았다** — 명세 기술만 옮겼고 그 자리에 표시해 두었다.

## 정답

### 1. 이 문단은 무슨 색인가

**실행 결과** (Chrome 151 headless, `getComputedStyle(p).color`)

```text
rgb(185, 28, 28)      = #b91c1c = red 쪽 (.note 가 이겼다)
```

**이 문단의 `color` 는 무엇이 되는가**

- **`red`** — `.note` 의 선언이 이긴다.

**`#lead` 가 명시도로는 가장 높은데 왜 지는가**

```text
1단계 출처·중요도 사다리

  4번 칸  작성자 important  :  .note   { color: red !important }
  ----------------------------------------------------  여기서 이미 갈렸다
  6번 칸  작성자 normal     :  #lead   { color: blue }
                               p       { color: green }

  4번 칸에 후보가 하나라도 있으면 6번 칸 후보는 전부 탈락한다.
  남은 후보가 하나이므로 2~6단계는 부르지 않는다.
```

- **명시도는 5단계**다. 1단계에서 승자가 하나로 갈리면 **5단계는 계산조차 되지 않는다.**
- `#lead` 의 `(1,0,0)` 은 계산해 봐야 쓸 곳이 없다.

**`.note` 의 `!important` 를 떼면 무슨 색이 되는가**

- **`blue`** — 세 후보가 전부 6번 칸(작성자 normal)에 모인다.\
  2·3·4단계 동점 → 5단계 명시도: `#lead` `(1,0,0)` > `.note` `(0,1,0)` > `p` `(0,0,1)`.

**`p` 선언에도 `!important` 를 붙이면 무슨 색이 되는가**

- **여전히 `red`** — 이제 4번 칸에 `.note`(0,1,0)와 `p`(0,0,1) 둘이 모인다.\
  같은 칸이므로 5단계로 내려가고, `(0,1,0)` > `(0,0,1)` 이라 `.note` 가 이긴다.
- **핵심**: `!important` 는 "이긴다"가 아니라 **"같은 칸에 올라간다"**이다. 칸이 같아지면 다시 명시도 싸움이다.

> **칸(사다리의 한 층)** — 출처 3종 × 중요도 2종 + 전환 + 애니메이션으로 만들어지는 여덟 층.\
> 예: 내 시트의 `color: red` 는 6번 칸, `color: red !important` 는 4번 칸이다.

### 2. `!important` 는 명시도를 얼마나 올리는가

**`!important` 는 `(A, B, C)` 세 자리 중 어느 자리를 얼마나 올리는가**

- **한 자리도 올리지 않는다.** 명시도는 선택자만 보고 계산하고, `!important` 는 선언에 붙는 표시라 선택자에 아무 영향이 없다.
- `!important` 가 하는 일은 **그 선언을 사다리의 다른 칸으로 옮기는 것**뿐이다(6번 → 4번).

**그 답이 이 주제에서 가장 자주 틀리는 자리인 이유**

```text
흔한 오해                              실제
+----------------------------+        +----------------------------+
| 명시도 사다리 하나 위에     |        | 칸이 다른 두 사다리         |
| !important = +10000        |        | 칸이 다르면 명시도는        |
| 그래서 무조건 이긴다        |        | 비교 대상이 아니다          |
+----------------------------+        +----------------------------+
  -> "숫자가 더 큰 쪽"으로 설명됨       -> "먼저 탈락시킨다"로 설명됨
```

- `+10000` 모델은 **결과가 자주 맞아떨어져서** 오해가 유지된다.\
  깨지는 자리는 `!important` 끼리 붙을 때와 레이어가 낄 때다 — 그때 이 모델은 순서를 거꾸로 예측한다.

**작성자의 `!important` 보다 위에 있는 칸**

1. 전환(transition) 선언
2. user-agent 의 `!important`
3. 사용자(user) 의 `!important`

*(이 세 칸은 이 문서에서 실행 확인하지 않았다 — 명세 기술만 옮겼다.)*

**사다리의 `!important` 구간에서 작성자와 사용자의 순서가 뒤집혀 있는 이유**

- normal 구간에서는 **작성자 > 사용자 > user-agent** 다 — 페이지 디자인이 브라우저 기본을 덮을 수 있어야 하니까.
- important 구간에서는 **사용자 > 작성자** 로 뒤집힌다.\
  사용자가 "글자를 크게"·"고대비로"를 `!important` 로 강제했을 때, **사이트가 그것을 되덮지 못하게** 하려는 접근성 장치다.
- 그래서 "가장 센 것"은 작성자의 `!important` 가 아니다.

### 3. "우선순위"는 여섯 단계 중 어디인가

**여섯 단계를 순서대로**

```text
 1  출처와 중요도            origin and importance
 2  문맥                     context        (그림자 트리 대 바깥 문서)
 3  요소 부착 스타일          element-attached styles  (style="")
 4  캐스케이드 레이어          layers         (@layer)
 5  명시도                   specificity    <- 흔히 "우선순위"라 부르는 것
 6  등장 순서                 order of appearance
```

**명시도는 몇 번째인가**

- **다섯 번째.** 여섯 중 하나일 뿐이고, 위에 넷이 있다.

**1단계에서 승자가 하나로 갈리면 5단계에서는 무슨 일이 일어나는가**

- **아무 일도 일어나지 않는다.** 후보가 하나 남았으면 그 뒤 단계는 실행되지 않는다.
- 이것이 "명시도 계산을 정확히 했는데 예측이 틀렸다"의 구조적 원인이다 — **틀린 단계를 계산한 것**이다.

**진단 순서**

1. 이긴 선언에 **`!important`** 가 붙어 있나 (1단계)
2. 요소에 **`style=""`** 가 있나 (3단계)
3. 이 프로젝트가 **`@layer`** 를 쓰나, 내 규칙이 어느 레이어인가 (4단계)
4. 그다음이 **명시도** (5단계)
5. 그것도 같으면 **파일·선언 순서** (6단계)

- 실무에서는 이 순서를 지키는 것만으로 대부분 끝난다.\
  개발자 도구 Styles 패널의 줄 그어진 선언들이 **탈락한 후보 목록**이고, 위에서부터가 정렬 결과다.

### 4. 두 줄의 색을 각각 예측하라

**실행 결과** (Chrome 151 headless)

```text
.a  ->  rgb(21, 128, 61)    = #15803d  (green,  나중 레이어 theme)
.b  ->  rgb(185, 28, 28)    = #b91c1c  (red,    먼저 레이어 base)
```

**첫째 줄과 둘째 줄은 각각 무슨 색인가**

- 첫째 줄(`.a`, normal) — **green**. 나중 레이어 `theme` 가 이긴다.
- 둘째 줄(`.b`, important) — **red**. 먼저 선언한 레이어 `base` 가 이긴다.

**대칭인데 결과가 갈리는 이유**

명세가 이 뒤집힘을 명시한다.

> for normal rules the declaration whose cascade layer is latest in the layer order wins, and for important rules the declaration whose cascade layer is earliest wins.

```text
@layer base, theme;      서랍 순서: base(먼저) → theme(나중)

  normal 선언 (.a)                 important 선언 (.b)
  +---------------------+          +---------------------+
  | base   red    약함   |          | base   red    셈    |  <- 이긴다
  | theme  green  셈    | <- 이긴다 | theme  green  약함   |
  +---------------------+          +---------------------+
```

- 레이어 순서가 `!important` 에서 뒤집히는 이유는 1단계 사다리의 뒤집힘과 같은 설계다 —\
  **"나중에 얹은 층이 normal 에서 덮는다면, important 에서는 아래층이 최후 방어선이어야 한다."**

**`@layer theme, base;` 로 바꾸면**

- 두 줄의 색이 **서로 맞바뀐다** — `.a` 는 red, `.b` 는 green.
- 레이어 순서는 **이름이 처음 나타난 자리**가 정하므로, 블록의 작성 순서를 바꾸지 않아도 이 한 줄로 전체가 뒤집힌다.

**`@layer` 안에서 `!important` 를 쓸 때 조심할 것**

- "가장 나중 레이어니까 무조건 이긴다"는 **normal 에서만 참**이다.
- `!important` 를 붙이는 순간 그 레이어는 **가장 약해진다.**
- 그래서 레이어 아키텍처를 쓰는 코드베이스에서 `!important` 는 **레이어 밖**이나 **가장 앞 레이어**에 두는 것이 의도와 맞는다.

### 5. 이 인라인 스타일을 시트로 덮을 수 있는가

**실행 결과** (Chrome 151 headless)

```text
#p1 의 color  ->  rgb(0, 0, 255)   = blue   (style="" 가 이겼다)
```

**이 문단은 무슨 색인가**

- **blue.** `style=""` 가 이긴다.

**선택자를 더 늘리면 달라지는가**

- **달라지지 않는다.**

```text
 3단계 요소 부착 스타일
   +----------------------------------+
   | style="color: blue"              |  <- 여기서 끝
   +----------------------------------+
 4·5·6단계
   | #p1#p1#p1        (3,0,0)         |  부르지 않는다
   | #p1#p1#p1#p1#p1  (5,0,0)         |  부르지 않는다
```

- `style=""` 에는 **선택자가 없다** — 명시도라는 개념 자체가 없다.\
  그래서 명시도를 아무리 올려도 **비교가 일어나는 단계에 도달하지 못한다.**

**시트에서 덮을 수 있는 수단**

- **`!important` 하나뿐이다.** 그러면 1단계(작성자 important)로 올라가 3단계 판정 전에 이긴다.\
  *(인라인 쪽도 `style="color: blue !important"` 로 올라오면 다시 1단계 동점이 되고, 거기서는 명시도가 없는 인라인이 유리하다.)*

**JS 가 인라인 스타일을 찍는 코드베이스의 장기 비용**

- 시트 쪽이 `!important` 로만 대응할 수 있게 되고, 그 `!important` 는 **다시 다른 `!important` 로만 덮인다.**
- 조정 여지가 5·6단계(명시도·순서)에서 1단계로 옮겨 가고, **되돌릴 수단이 없어진다.**
- 처방: 인라인으로 찍는 대신 **클래스나 사용자 정의 속성(`--x`)을 토글**하게 바꾼다. 값은 시트가 갖고, JS 는 스위치만 쥔다.

### 6. 레이어 밖에 남은 규칙

**실행 결과** (Chrome 151 headless, `#app` 조상이 있는 문서)

```text
.x  (양쪽 normal)      ->  rgb(255, 0, 0)   = red    (레이어 밖이 이겼다)
.y  (양쪽 important)   ->  rgb(0, 128, 0)   = green  (레이어 안이 이겼다)
```

**이 문단은 무슨 색인가**

- **red.** 레이어 밖의 `.x` 가 이긴다.

**레이어 안의 `#app .x` 가 레이어 밖의 `.x` 에 지는 이유**

```text
4단계 레이어
   +----------------------------------+
   | 레이어 밖   .x        (0,1,0)    |  <- normal 에서 가장 센 자리
   | theme      #app .x   (1,1,0)    |
   +----------------------------------+
        ↓ 4단계에서 갈렸다
   5단계 명시도는 부르지 않는다 — (1,1,0) 이 (0,1,0) 을 못 이긴다
```

명세가 레이어 밖의 자리를 이렇게 적는다.

> Unlayered rules are sorted later than any layered rules within the same parent layer (if any).

- 레이어는 **명시도보다 위**이므로, 레이어에서 갈리면 ID 가 몇 개든 소용이 없다.

**양쪽에 `!important` 를 붙이면**

- **승자가 뒤집혀 green** 이 된다 — important 에서는 레이어 순서가 뒤집히고, **레이어 밖이 가장 약한 자리**가 된다.
- 위 실행 결과의 `.y` 가 그 경우다.

**기존 시트에 `@layer` 를 도입할 때 먼저 확인할 것**

- **레이어에 안 들어간 규칙이 어디에 남아 있나.**\
  한 장이라도 레이어 밖에 남으면 그 시트의 normal 선언 전부가 레이어 안의 모든 것을 이긴다.
- 도입 순서: ① `@import ... layer(...)` 로 서드파티부터 **가장 앞 레이어**에 밀어 넣고 ② 내 시트를 레이어로 감싸고 ③ **레이어 밖에 남은 것이 0인지** 확인한다.

### 7. 이 배경은 어떻게 그려지는가

**실행 결과** (Chrome 151 headless — 두 순서를 모두 돌렸다)

```text
.theme 먼저, .card 나중   ->  background-image: url("data:image/gif;…")   background-color: rgba(0, 0, 0, 0)
.card  먼저, .theme 나중   ->  background-image: url("data:image/gif;…")   background-color: rgb(0, 0, 128)
```

**`background-image` 와 `background-color` 는 각각 무엇이 되는가**

- `background-image` — **`url(a.png)`** (살아 있다).
- `background-color` — **`transparent`** (navy 가 사라졌다).

```text
background-color 바구니                 background-image 바구니
+------------------------------+        +------------------------------+
| .theme  navy         (0,1,0) |        | .card  url(a.png)    (0,1,0) |
| .card   transparent  (0,1,0) | <- 나중 |  (다른 후보 없음)            |
+------------------------------+        +------------------------------+
  1~5단계 전부 동점 -> 6단계 순서          후보가 하나 -> 그대로 당선
  당선: transparent                       당선: url(a.png)
```

- 단축 `background` 는 **안 적은 하위 속성에 `initial` 후보를 넣는다.**\
  `background-color` 바구니에 `transparent` 가 한 표 들어간 것이지, `.theme` 규칙이 통째로 진 것이 아니다.

**순서를 뒤집으면 무엇이 달라지는가**

- **`background-color` 만** 달라진다 — navy 가 살아남는다.
- `background-image` 는 후보가 하나뿐이라 순서와 무관하게 그대로다.

**"캐스케이드는 규칙 단위가 아니라 속성 단위"와의 연결**

- 한 규칙이 통째로 이기고 지는 일은 없다.\
  같은 규칙이 **한 바구니에서는 이기고 다른 바구니에서는 진다.**
- 그래서 "이 규칙이 적용됐나"가 아니라 **"이 속성의 승자가 누구냐"**로 물어야 진단이 된다.

**순서에 기대지 않고 둘 다 지키려면**

- 단축 대신 **필요한 하위 속성만** 쓴다 — `.card { background-image: url(a.png); background-repeat: no-repeat; }`.
- 그러면 `background-color` 바구니에 `.card` 의 후보가 아예 안 들어가서, 순서가 어떻든 navy 가 남는다.

> **단축 속성(shorthand property)** — 여러 하위 속성을 한 줄로 쓰는 속성. 안 적은 하위 속성을 **`initial` 로 되돌린다.**\
> 예: `background: red` 는 `background-image: none`·`background-repeat: repeat` 등을 함께 선언한 것과 같다.

### 8. 다른 주제와 잇기

**부모에게 `color: red`, 자식에게 아무 약한 선언이 걸리면 자식은 무슨 색인가**

- **자식에게 걸린 그 선언의 색**이다. 상속은 지지 않는다 — **애초에 경쟁에 나오지 않는다.**

```text
자식의 color 바구니
  후보 있음  ->  캐스케이드가 승자를 뽑는다           (상속 안 일어남)
  후보 없음  ->  비어 있으므로 부모 값을 물려받는다   (상속 일어남)
```

**상속은 캐스케이드의 몇 단계에서 일어나는가**

- **캐스케이드 밖**이다. 캐스케이드가 끝나 바구니가 **비어 있을 때** 그다음 단계에서 채워 넣는 것이다.
- 그래서 "상속보다 센 선언"이라는 표현은 성립하지 않는다 — 비교가 일어나지 않는다.
- 정본은 목록의 **03번 주제**(상속과 전역 키워드).

**`:where()` 가 무력화하는 단계**

- **5단계(명시도)** 다. `:where()` 안에 무엇이 들어가도 명시도 기여가 `(0,0,0)` 이 된다.
- 그래서 `:where()` 로 감싼 규칙끼리는 승부가 **6단계(순서)로 내려간다.**
- 정본은 [02번 주제](../02-specificity/2-summary.md), 목록의 **11번 주제**(`:is()`·`:where()`·`:not()`).

**전환 값이 `!important` 에도 안 덮이는 이유**

- 사다리 **1번 칸이 전환 선언**이고, 작성자의 `!important` 는 **4번 칸**이다.\
  칸이 다르므로 1단계에서 전환 쪽이 이긴다.
- 이유는 전환 값이 스타일시트의 선언이 아니라 **엔진이 시간에 따라 만들어 내는 값**이기 때문이다.\
  시트가 그것을 덮을 수 있으면 전환이 도는 도중에 값이 튄다.
- *(이 항목은 실행 확인하지 않았다 — 명세 기술만 옮겼다.)* 전환 자체는 목록의 [52번 주제](../52-transition/2-summary.md).

## 용어 풀이

- **캐스케이드(cascade)** — 여러 출처의 선언을 속성마다 한 줄로 세워 승자를 하나 뽑는 알고리즘.
- **바구니** *(이 문서의 설명 장치)* — 한 요소의 한 속성에 걸린 후보 선언들의 집합. 캐스케이드는 바구니마다 따로 돈다.
- **칸(사다리 층)** *(이 문서의 설명 장치)* — 1단계에서 쓰는 출처·중요도 여덟 층. 칸이 다르면 명시도는 비교되지 않는다.
- **출처(origin)** — user-agent(브라우저 기본 시트) · user(사용자 설정) · author(페이지 시트).
- **중요도(importance)** — `!important` 유무. 출처와 짝지어 칸을 만든다.
- **요소 부착 스타일(element-attached style)** — `style=""` 속성의 선언. 선택자가 없어 명시도가 없다.
- **캐스케이드 레이어(cascade layer)** — `@layer` 로 만든 서랍. 명시도보다 위에서 비교된다.
- **레이어 밖(unlayered)** — 어떤 레이어에도 안 들어간 규칙. normal 에서 가장 세고 important 에서 가장 약하다.
- **명시도(specificity)** — 선택자를 `(A, B, C)` 로 환산한 값. 5단계에서만 쓰인다. 정본은 02번.
- **등장 순서(order of appearance)** — 마지막 기준. 나중에 읽힌 선언이 이긴다.
- **단축 속성(shorthand property)** — 여러 하위 속성을 한 줄로 쓰는 속성. 안 적은 하위 속성을 `initial` 로 되돌린다.
- **지정값(specified value)** — 캐스케이드가 확정한 값. 상속·값 처리의 입력.
