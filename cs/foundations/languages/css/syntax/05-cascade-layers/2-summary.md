# css/syntax/05 — `@layer` 캐스케이드 레이어: 선언 순서와 레이어 밖의 위치 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Cascading and Inheritance Level 5](https://drafts.csswg.org/css-cascade-5/) 의 「Cascade Layers」·「Cascade Sorting Order」 절. 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 모든 색은 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워 `getComputedStyle` 로 읽은 것이다. `@import` 를 쓴 실험만 **로컬 HTTP 서버**로 띄웠다(이유는 「어디서 틀리나」 7). 하네스는 [3-answer.md](3-answer.md) 의 `## 실행 검증` 절에 있다.\
> **엔진은 Chrome 하나다** — Firefox 155.0.1 은 이 환경에서 headless 산출이 조용히 실패하고 WebKit 은 없다. 「두 엔진에서 확인했다」고 적지 않는다.
> **버전** — CSS 에는 언어 버전이 없다. `@layer` 는 Baseline **widely available**(newly 2022-03-14 · widely 2024-09-14 — [목록 README](../README.md) 의 지원 표).
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 값은 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**`@layer` = 선언들을 미리 서랍에 나눠 넣어 두고, 서랍 순서로 먼저 승부를 내는 것이다.**

서랍장에 비유한다. 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 서랍장 | 문서 하나의 레이어 순서 |
| 서랍 한 칸 | 레이어 하나(`@layer base`) |
| 서랍에 안 넣고 위에 얹어 둔 것 | **레이어 밖(unlayered)** 규칙 |
| 서랍을 짜 넣은 순서 | 레이어 이름이 **처음 나타난** 순서 |
| 서랍 안에서 다시 줄 세우기 | 명시도·순서 (02번·01번) |

- 서랍 순서는 **명시도보다 먼저** 본다. 그래서 아래 서랍의 `#id` 가 위 서랍의 타입 선택자 하나에 진다.
- **서랍에 안 넣은 것이 보통은 가장 세다.** 「위에 얹어 둔 것」이라 그렇다.
- **`!important` 를 붙이면 서랍장이 통째로 뒤집힌다.** 위에 얹어 둔 것이 가장 약해진다 — 직관과 반대다.

```text
  normal 선언                          important 선언
  +---------------------------+        +---------------------------+
  | 레이어 밖        가장 셈  |        | base   (먼저)   가장 셈   |
  | theme  (나중)             |        | theme  (나중)             |
  | base   (먼저)    가장 약함|        | 레이어 밖       가장 약함 |
  +---------------------------+        +---------------------------+
          위아래가 통째로 뒤집힌다 — 레이어 밖까지 같이 뒤집힌다
```

실무에서 이게 터지는 자리는 **기존 프로젝트에 `@layer` 를 도입할 때**다.\
시트 한 장을 레이어에 안 넣고 남겨 두면 **그 한 장이 모든 레이어를 이기고**, 그걸 `!important` 로 덮으려 하면 **그 순간 가장 약해진다.**\
`@layer` 는 문법이 세 줄인데 **순서 규칙을 모르면 방향을 거꾸로 잡게 되는** 기능이다.

> **캐스케이드 레이어(cascade layer)** — `@layer` 로 만든, **명시도보다 위**에서 비교되는 우선순위 서랍.\
> 예: `@layer reset, base, components;` 라고 선언하면 `components` 안의 약한 선택자도 `reset` 안의 센 선택자를 이긴다.

> **레이어 밖(unlayered)** — 어떤 레이어에도 들어가지 않은 규칙.\
> 예: `@layer` 를 한 줄도 안 쓴 보통의 CSS 는 전부 레이어 밖이다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. **레이어 순서는 무엇이 정하는가.** 사전 선언·첫 등장·재개방·뒤에서 재나열이 각각 무엇을 바꾸는가.
2. **레이어 밖 규칙은 어디에 서는가.** normal 과 important 에서 자리가 어떻게 달라지는가.
3. `!important` 가 붙으면 왜 **레이어 순서가 뒤집히는가.** 그래서 무엇을 하면 안 되는가.

## 동작 방식

### (1) 레이어 순서는 「이름이 처음 나타난 자리」가 정한다

**언제 쓰나** — 레이어를 둘 이상 쓰는 모든 문서. 이 규칙 하나가 나머지 전부의 전제다.

```text
방식 ①  사전 선언 (권장)
   @layer reset, base, theme;      순서를 여기서 못박는다
   @layer theme { ... }            나중에 어느 순서로 열어도 상관없다
   @layer base  { ... }

방식 ②  첫 등장 순서
   @layer alpha { ... }            alpha 가 먼저
   @layer beta  { ... }            beta 가 나중                -> 실측 beta 가 이겼다

재개방은 자리를 안 옮긴다
   @layer base  { .u1 { red } }
   @layer theme { .u1 { green } }
   @layer base  { .u1 { blue } }   base 를 theme 뒤에서 다시 열었다
                                   -> 실측 green.  base 는 여전히 첫째 칸이다

뒤에서 이름만 다시 나열해도 안 바뀐다
   @layer gamma { .u3 { red } }
   @layer delta { .u3 { green } }
   @layer delta, gamma;            순서를 뒤집어 다시 적었다
                                   -> 실측 green.  이미 정해진 순서가 이긴다
```

그림 해설 (한 단계씩):

- 순서는 **이름이 처음 나타난 순간** 고정되고, 그 뒤로는 **무엇을 해도 안 움직인다.**
- 그래서 방식 ①이 권장된다 — 레이어 순서를 **파일 한 곳에서 읽을 수 있게** 만든다.
- 방식 ②만 쓰면 순서가 **번들러가 파일을 이어 붙인 순서**에 달리게 된다. `@layer` 를 도입한 이유가 그 의존을 없애는 것이었는데 그대로 남는다.

비용 — 없음(판정 순서다). 사람 쪽 비용만 있다 — **사전 선언 줄이 없으면 레이어 순서를 추적할 방법이 없다.**

### (2) 레이어 밖은 어디에 서는가 — normal 에서 가장 세다

**언제 쓰나** — 기존 시트에 `@layer` 를 도입할 때. **여기서 가장 많이 다친다.**

명세가 이렇게 못박는다.

> Unlayered rules are sorted later than any layered rules within the same parent layer (if any).

```text
같은 요소, 같은 속성, 같은 명시도 (0,1,0)

  @layer base, theme;
  @layer base  { .u1 { color: #b91c1c } }     빨강
  @layer theme { .u1 { color: #15803d } }     초록
  .u1 { color: #1d4ed8 }                      파랑 · 레이어 밖

  실측 -> rgb(29, 78, 216)   파랑이 이겼다
```

그림 해설 (한 단계씩):

- 레이어 밖은 「**맨 마지막 레이어 다음 칸**」에 선다. 레이어를 몇 개 만들든 그 위다.
- 그래서 **`@layer` 는 「내 코드를 아래로 내리는」 장치**로 쓴다 — 남의 시트를 레이어에 넣는 게 아니라, **남의 시트가 레이어 밖이면 내가 이길 수 없다.**
- 기존 프로젝트에 도입할 때의 첫 질문은 「**레이어에 안 들어간 시트가 남아 있나**」다.

비용 — 없음. 다만 **한 줄만 빠뜨려도 그 한 줄이 전부를 이긴다.**

### (3) ★ `!important` 는 레이어 순서를 뒤집는다 — 레이어 밖까지

**언제 쓰나** — 레이어 안에서 `!important` 를 쓰려 할 때. **직관과 정확히 반대라 반드시 실측으로 확인해야 하는 자리다.**

명세가 이렇게 적는다.

> for normal rules the declaration whose cascade layer is latest in the layer order wins, and for important rules the declaration whose cascade layer is earliest wins.

완전히 대칭인 두 판을 만들어 `!important` 하나만 다르게 준 실측이다.

```text
  @layer base, theme;
  @layer base  { .u1 { #b91c1c }           .u2 { #b91c1c !important } }
  @layer theme { .u1 { #15803d }           .u2 { #15803d !important } }
  .u1 { #1d4ed8 }                          .u2 { #1d4ed8 !important }

           normal (.u1)                    important (.u2)
  +---------------------------+   +---------------------------+
  | 레이어 밖  #1d4ed8  ← 이김 |   | base      #b91c1c  ← 이김 |
  | theme      #15803d        |   | theme     #15803d        |
  | base       #b91c1c        |   | 레이어 밖 #1d4ed8        |
  +---------------------------+   +---------------------------+

  실측  .u1 = rgb(29, 78, 216)  파랑      .u2 = rgb(185, 28, 28)  빨강
```

```html demo
<p class="u1">normal — 레이어 밖이 이긴다</p>
<p class="u2">!important — 레이어 밖이 가장 약하다</p>
<style>
  @layer base, theme;
  @layer base  { .u1 { color: #b91c1c; } .u2 { color: #b91c1c !important; } }
  @layer theme { .u1 { color: #15803d; } .u2 { color: #15803d !important; } }
  .u1 { color: #1d4ed8; }
  .u2 { color: #1d4ed8 !important; }
  p { font: 20px/1.6 system-ui, sans-serif; }
</style>
```

> **보이는 것** — 첫 줄은 **파랑**(`#1d4ed8`), 둘째 줄은 **빨강**(`#b91c1c`). 두 줄의 선언 집합은 색 말고는 완전히 같고 `!important` 하나만 다른데, **가장 센 것과 가장 약한 것이 통째로 뒤바뀐다.** 첫 줄에서 가장 셌던 레이어 밖 파랑이 둘째 줄에서는 가장 약해지고, 첫 줄에서 가장 약했던 `base` 빨강이 둘째 줄에서 이긴다.\
> **바꿔 볼 것** — 맨 위 `@layer base, theme;` → `@layer theme, base;` 로 바꾸면 → **둘째 줄이 초록으로 바뀐다**(이제 `theme` 이 첫째 칸) **첫 줄은 파랑 그대로**(레이어 밖은 여전히 normal 에서 가장 세다)

*(Chrome 151 headless 실측: `.u1` = `rgb(29, 78, 216)`, `.u2` = `rgb(185, 28, 28)`.)*

그림 해설 (한 단계씩):

- **뒤집히는 것은 레이어 사이만이 아니다.** 「레이어 밖」칸까지 같이 뒤집혀 맨 아래로 내려간다.
- 그래서 「나중 레이어에서 `!important` 로 강제로 덮겠다」는 **그 순간 가장 약해진다.** 두 번 실패한다.
- 왜 이렇게 설계했나 — `!important` 의 원래 뜻이 「**아래쪽 출처가 위쪽을 이기게 하는 비상구**」이기 때문이다. 출처 사다리에서 사용자가 작성자를 이기는 것([01번 주제](../01-cascade-and-priority/2-summary.md)의 1단계)과 같은 꼴을 레이어 안에서 반복한 것이다.

비용 — 없음. 대신 **레이어를 쓰는 문서에서 `!important` 의 의미가 바뀐다.** 도입 전에 쓰던 `!important` 를 그대로 두면 방향이 거꾸로 선다.

### (4) 레이어가 명시도를 이긴다 — 자리만 확인한다

**언제 쓰나** — 「선택자를 길게 늘였는데 안 먹는다」의 원인 후보로.

캐스케이드 6단계에서 **레이어는 4단계, 명시도는 5단계**다. 두 단계표의 정본은 [01번 주제](../01-cascade-and-priority/2-summary.md)·[02번 주제](../02-specificity/2-summary.md)이고, 여기서는 **결과만** 확인한다.

```text
  @layer base, theme;
  @layer base  { #app .t1 { color: #b91c1c } }    (1,1,0)  훨씬 세다
  @layer theme { p.t1    { color: #15803d } }     (0,1,1)

  실측 -> rgb(21, 128, 61)   초록.  명시도는 비교되지 않았다
```

그림 해설 (한 단계씩):

- 4단계에서 갈리면 **5단계는 계산조차 안 한다.** `(1,1,0)` 은 계산해 봐야 쓸 데가 없다.
- 이것이 `@layer` 의 존재 이유다 — **남의 시트를 덮으려고 선택자를 늘이는 일을 없앤다.**
- 명시도로 싸우고 있다면 「4단계 설계가 없다」는 신호로 읽는다.

비용 — 없음.

### (5) 이름 없는 레이어와 중첩 레이어

**언제 쓰나** — 서드파티 시트를 「어딘가 아래」에 깔고 싶은데 이름을 붙일 이유가 없을 때.

```text
익명 레이어 — @layer { } 를 쓸 때마다 '새' 레이어가 하나 생긴다
   @layer { .an { #b91c1c } }     익명 A
   @layer { .an { #15803d } }     익명 B  <- A 와 같은 레이어가 아니다
   실측 -> rgb(21, 128, 61)  초록 (나중 레이어가 이겼다)

중첩 레이어 — 점 표기로 가리킨다
   @layer outer {
     @layer inner { .ne { #b91c1c } }     outer.inner
     .ne { #15803d }                      outer 안의 '레이어 밖'
   }
   실측 -> rgb(21, 128, 61)  초록
   outer 안에서도 같은 규칙이 성립한다 — 안쪽 레이어보다 그 바깥이 세다
```

그림 해설 (한 단계씩):

- **익명 레이어는 다시 열 수 없다.** 이름이 없으니 가리킬 수단이 없다 — 한 번 쓰고 끝이다.
- 중첩 레이어는 **서랍 안의 칸막이**다. `outer` 전체가 다른 레이어와 비교될 때는 한 덩어리로 움직인다.
- **(2)의 규칙이 재귀적으로 적용된다** — 「같은 부모 레이어 안에서 레이어 밖이 더 세다」가 `outer` 안에서도 성립한다.

```html demo
<p class="an">익명 레이어 둘은 서로 다른 레이어다</p>
<p class="ne">중첩 레이어와 그 바깥</p>
<style>
  @layer { .an { color: #b91c1c; } }
  @layer { .an { color: #15803d; } }
  @layer outer {
    @layer inner { .ne { color: #b91c1c; } }
    .ne { color: #15803d; }
  }
  p { font: 20px/1.6 system-ui, sans-serif; }
</style>
```

> **보이는 것** — 두 줄 다 **초록**(`#15803d`)으로 나온다. 첫 줄은 익명 레이어 둘이 **서로 다른 레이어**라서 나중 것이 이기고, 둘째 줄은 `outer` 안에서도 **레이어 밖(`outer` 직속)이 안쪽 레이어(`outer.inner`)보다 세다**는 같은 규칙이 성립해서다.\
> **바꿔 볼 것** — 첫 줄의 두 `@layer { }` 를 `@layer solo { }` 두 개로 바꾸면 → **여전히 초록**(이번엔 같은 레이어 안의 순서로 나중 것이 이긴다 — 결과는 같지만 이유가 다르다)

*(Chrome 151 headless 실측: `.an` = `rgb(21, 128, 61)`, `.ne` = `rgb(21, 128, 61)`.)*

비용 — 없음. 다만 **익명 레이어가 늘면 순서를 사람이 못 읽는다.** 두 개를 넘기면 이름을 붙인다.

### (6) `@import` 로 통째로 레이어에 넣기

**언제 쓰나** — 서드파티 시트를 손대지 않고 아래에 깔 때. `@layer` 의 가장 실용적인 쓰임이다.

```css
@import url("vendor.css") layer(vendor);
@layer vendor, app;
@layer app { /* 내 규칙 — 선택자가 짧아도 vendor 를 이긴다 */ }
```

```text
실측 (로컬 HTTP 서버)
  vendor.css : .i1 { color: #b91c1c }
  @layer app { .i1 { color: #15803d } }
  -> rgb(21, 128, 61)   초록.  app 이 이겼다

  @import 만 두고 app 규칙을 지우면
  -> rgb(185, 28, 28)   빨강.  import 가 실제로 적용됐다는 확인
```

그림 해설 (한 단계씩):

- **`@import` 는 시트 맨 앞에 와야 한다**(`@charset`·`@layer` 선언 다음). 규칙 뒤에 쓰면 조용히 무시된다.
- `layer(이름)` 을 붙이면 그 시트 **전체**가 그 레이어에 들어간다. 시트 안을 안 고쳐도 된다.
- `layer` 만 쓰면(`@import url(x) layer;`) 익명 레이어가 된다.

비용 — `@import` 는 **직렬 요청**을 만든다(시트를 받아야 그 안의 `@import` 를 안다). 빌드에서 합칠 수 있으면 합치는 쪽이 낫다.

### (7) `revert-layer` — 레이어 한 칸 되돌리기

**언제 쓰나** — 테마 레이어만 무르고 앞 레이어의 값으로 돌아갈 때.

이 키워드의 **동작은 [03번 주제](../03-inheritance-and-global-keywords/2-summary.md)가 정본**이고, 여기서는 「앞 레이어」가 (1)의 순서로 정해진다는 연결만 짚는다.

```text
@layer base, theme;
@layer base  { .r1 { color: #b91c1c } }
@layer theme { .r1 { color: revert-layer } }    -> 실측 rgb(185, 28, 28)

레이어 밖에서 쓰면 revert 와 같다                -> 실측 rgb(0, 0, 0)
```

비용 — 없음.

## 문법 — 형태와 규칙

CSS 는 문법 표면이 단순하므로 이 절은 「**형태 — 어디서 헷갈리나**」로 읽는다.

### 형태

```css
@layer reset, base, theme;            /* ① 순서만 선언 — 블록 없음, 세미콜론으로 끝 */
@layer base { p { color: #333 } }     /* ② 이름 붙은 블록 */
@layer { p { color: #333 } }          /* ③ 익명 레이어 — 쓸 때마다 새로 생긴다 */
@layer outer.inner { ... }            /* ④ 중첩 레이어를 점으로 가리킨다 */
@layer outer { @layer inner { ... } } /*    ④와 같은 것 */
@import url(x.css) layer(vendor);     /* ⑤ 외부 시트를 레이어에 넣기 */
@import url(x.css) layer;             /*    익명 레이어로 */
```

### 금지 사례 — 조용히 안 먹는 형태

```css
p { color: red }
@import url(x.css) layer(v);   /* 무시된다 — @import 는 규칙보다 앞이어야 한다 */

@layer base, theme             /* 무효 — 사전 선언은 세미콜론으로 끝내야 한다 */
@layer base { ... }

@layer { ... }
@layer { ... }                 /* 유효하지만 서로 다른 레이어다 — 다시 열린 게 아니다 */
```

**에러는 안 난다.** 무효한 at-rule 은 통째로 버려지고 화면만 달라진다([07번 주제](../07-syntax-and-error-recovery/2-summary.md)).

### 어디서 헷갈리나

- **사전 선언(`@layer a, b;`)과 블록(`@layer a { }`)은 다른 문**이다. 앞엣것은 순서만 정하고 규칙을 담지 않는다.
- **이름을 다시 써도 레이어는 하나**다. 그런데 **익명은 쓸 때마다 새로 생긴다** — 같은 문법처럼 보여 헷갈린다.
- **레이어 순서와 파일 순서는 다르다.** 나중에 `<link>` 한 파일이라도 먼저 선언된 레이어에 들어 있으면 약하다.

## 어디서 틀리나

이 주제의 값어치는 전부 여기 있다. 일곱 다 **에러 없이 조용히 어긋난다.**

### 1. 나중 레이어에서 `!important` 로 덮으려 한다

```text
의도                                   실제
+-----------------------------+       +-----------------------------+
| @layer theme {              |       | important 에서는 순서가     |
|   .btn { color: red         |       | 뒤집힌다                    |
|          !important }       |       |                             |
| }                           |       | theme 이 가장 나중이면       |
| "가장 나중이니 무조건 이기지"|       | important 에서는 가장 약하다 |
+-----------------------------+       +-----------------------------+
```

실측 `.u2` 가 이 경우다 — 가장 나중 레이어 `theme` 이 **가장 먼저 레이어 `base` 에 졌다.**

### 2. 레이어 밖 `!important` 면 무조건 이길 거라 생각한다

**가장 약하다.** 실측에서 레이어 밖의 `#1d4ed8 !important` 가 **세 후보 중 꼴찌**였다.\
normal 에서 가장 셌던 것이 important 에서 가장 약해진다 — 한 줄에 `!important` 를 붙였다 뗐다 하면 승자가 양 끝으로 튄다.

### 3. 레이어에 안 넣은 시트 한 장을 남겨 둔다

그 시트의 **모든 normal 선언이 모든 레이어를 이긴다.**\
「레이어를 썼는데 왜 예전 스타일이 계속 이기지」의 답이 대개 이것이다. 도입 시 첫 점검 항목이다.

### 4. 레이어를 다시 열면 순서가 뒤로 간다고 생각한다

```text
@layer base  { .u1 { red } }
@layer theme { .u1 { green } }
@layer base  { .u1 { blue } }     "마지막에 썼으니 blue 겠지"

실측 -> green.   base 는 여전히 첫째 칸이고, blue 는 그 칸 안에서 red 를 이겼을 뿐이다
```

**자리는 첫 등장 때 고정된다.** 이것을 모르면 「왜 맨 마지막 줄이 안 먹지」에서 막힌다.

### 5. 뒤에서 `@layer b, a;` 로 순서를 고칠 수 있다고 생각한다

**안 고쳐진다.** 실측에서 `@layer gamma{} @layer delta{} @layer delta, gamma;` 의 승자는 여전히 `delta` 였다.\
사전 선언은 **아직 안 나온 이름의 순서를 정할 때만** 효력이 있다 — 그래서 파일 맨 위에 둔다.

### 6. 익명 레이어를 「다시 열었다」고 생각한다

`@layer { }` 두 개는 **레이어 두 개**다. 두 번째가 첫 번째를 이기는데, 그 이유가 「같은 레이어 안의 순서」가 아니라 「**나중 레이어**」다.\
결과가 같아 보여서 틀린 모델을 오래 유지하게 된다 — `@layer a, b;` 같은 사전 선언을 끼우는 순간 예측이 어긋난다.

### 7. `file://` 로 연 문서에서 `@import` 를 확인하려 한다

★ **이 문서를 쓰면서 실제로 당한 것이다.**

```text
file:// 로 연 문서            http://127.0.0.1 로 연 같은 문서
+---------------------------+  +---------------------------+
| .i1 = rgb(0, 0, 0)        |  | .i1 = rgb(185, 28, 28)    |
| (import 한 규칙이 안 먹음) |  | (import 한 규칙이 먹는다) |
| cssRules[0] 은 있다       |  | styleSheet.cssRules 도 읽힘|
| styleSheet.cssRules 는    |  |                           |
|   "Cannot access rules"   |  |                           |
+---------------------------+  +---------------------------+
```

`file://` 은 파일마다 **불투명 출처**라 가져온 시트가 적용되지 않는다. **에러도 경고도 없다.**\
`@import` 가 걸린 실험은 반드시 **HTTP 로 띄워 확인**한다 — 안 그러면 「`@import layer()` 가 안 되는구나」라는 거짓 결론을 얻는다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 레이어가 캐스케이드 4단계, 명시도가 5단계라는 것 | **명세**(css-cascade-5 「Cascade Sorting Order」) |
| 레이어 밖이 normal 에서 가장 세다는 것 | **명세**(위에 인용한 문장) |
| `!important` 에서 레이어 순서가 뒤집히는 것 | **명세**(위에 인용한 문장) |
| 순서가 「이름이 처음 나타난 자리」에 고정되는 것 | **명세** |
| 익명 레이어가 매번 새로 생기는 것 | **명세** |
| 위 다섯이 Chrome 151 에서 그대로 관찰된 것 | **관찰.** 다른 엔진에서는 확인하지 않았다 |
| `file://` 에서 `@import` 가 안 먹는 것 | **브라우저 보안 정책**(불투명 출처). 언어 규칙이 아니다 |
| `@layer` 를 쓸 수 있는지 | **Baseline widely available**(2024-09-14) — 2차 집계(`webstatus.dev`)로 접지 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 서드파티 시트를 아래에 깔고 싶다 | `@import url(x) layer(vendor)` | 내 선택자 길이 늘리기 |
| 유틸리티 클래스가 항상 이겨야 한다 | 유틸리티를 **가장 나중 레이어**에 | `!important` 를 전부에 붙이기 |
| 레이어 안에서 예외 하나를 덮고 싶다 | 같은 레이어 안의 명시도·순서 | 레이어 안 `!important`(방향이 뒤집힌다) |
| 기존 프로젝트에 도입한다 | 모든 시트를 레이어에 넣기 + 사전 선언 한 줄 | 「일단 새 코드만 레이어에」 |
| 레이어를 딱 하나만 쓴다 | 그냥 쓰지 않는다 | 레이어 하나 + 레이어 밖 규칙(가장 헷갈리는 조합) |
| 접근성 사용자 설정을 존중해야 한다 | `!important` 를 아끼기 | 레이어로 사용자 important 를 덮으려 하기(출처가 위다 — 01번) |

판단 규칙 두 줄.

- **레이어는 「올리는」 장치가 아니라 「내리는」 장치다.** 이기게 만들 것을 고르는 게 아니라, **지게 만들 것**을 서랍에 넣는다.
- **레이어와 `!important` 를 같이 쓰지 않는다.** 둘을 섞는 순간 방향을 사람이 추적할 수 없다.

## 핵심 문장

- 레이어 순서는 **이름이 처음 나타난 자리**에서 고정되고, 재개방·후속 재나열로는 **안 움직인다.**
- **레이어 밖 규칙은 normal 에서 모든 레이어를 이긴다** — 도입 시 시트 한 장만 빠져도 그 한 장이 전부를 이긴다.
- **`!important` 는 레이어 순서를 뒤집고, 레이어 밖까지 같이 뒤집어 맨 아래로 보낸다.** 「나중 레이어 + `!important`」는 두 번 실패한다.
- 레이어는 캐스케이드 **4단계**라 **5단계 명시도보다 먼저** 갈린다 — 아래 서랍의 `#id` 가 위 서랍의 타입 선택자에 진다.
- **익명 `@layer { }` 는 쓸 때마다 새 레이어**다. 「다시 열었다」가 아니다.
- `@import url(x) layer(v)` 는 **시트를 안 고치고** 통째로 아래에 깔 수 있는 유일한 수단이다.
- 이 문서의 `@import` 실험은 **`file://` 에서 조용히 실패했다** — HTTP 로 띄워야 확인된다.

## 용어 풀이

- **캐스케이드 레이어(cascade layer)** — `@layer` 로 만든, 명시도보다 위에서 비교되는 우선순위 서랍.
- **레이어 밖(unlayered)** — 어떤 레이어에도 안 들어간 규칙. normal 에서 가장 세고 important 에서 가장 약하다.
- **레이어 순서(layer order)** — 이름이 처음 나타난 순서. 한 번 정해지면 안 바뀐다.
- **사전 선언** — `@layer a, b;` — 순서만 정하고 규칙은 담지 않는 문.
- **익명 레이어(anonymous layer)** — `@layer { }` 로 만든 이름 없는 레이어. 쓸 때마다 새로 생기고 다시 열 수 없다.
- **중첩 레이어(nested layer)** — `@layer outer.inner` 또는 블록 중첩. 바깥 레이어 안에서 같은 규칙이 재귀적으로 성립한다.
- **`@import ... layer(이름)`** — 외부 시트 전체를 그 레이어에 넣는 형태.
- **`revert-layer`** — 이 레이어의 그 속성 선언을 없앤 셈 치고 앞 레이어 값으로. 정본은 03번.
- **명시도(specificity)** — 선택자를 `(A, B, C)` 로 환산한 값. 5단계. 정본은 02번.
- **불투명 출처(opaque origin)** — `file://` 문서처럼 다른 문서와 출처를 공유하지 않는 상태. `@import` 가 조용히 실패하는 원인.

## 더 들어가면

- **레이어는 런타임 비용이 아니다.** 판정 순서를 바꿀 뿐이라 렌더 성능에 영향이 없다. 비용은 전부 **사람이 순서를 추적하는 비용**이다.
- **레이어 순서를 한 파일에 모으는 관례**가 오늘의 표준 해법이다. `main.css` 맨 위에 `@layer reset, vendor, base, layout, components, utilities;` 한 줄을 두고, 나머지 파일은 그 이름만 쓴다.
- **BEM·ITCSS 같은 명명 방법론이 하던 일을 언어 기능이 가져간 것**이 이 기능의 뜻이다. 「명시도를 관리하려고 이름을 길게 짓는」 관행 자체가 필요 없어진다(목록 README 의 「뺀 것과 이유」).
- **`@scope` 와는 층이 다르다.** 레이어는 4단계, 스코프 근접성은 명시도 **뒤**에 끼어든다 — 둘을 같이 쓰면 「레이어 → 명시도 → 근접성 → 순서」 넷을 순서대로 읽어야 한다([06번 주제](../06-scope/2-summary.md)).
