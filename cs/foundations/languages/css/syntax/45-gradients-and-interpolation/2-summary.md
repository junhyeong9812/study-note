# css/syntax/45 — 그라디언트와 보간 색 공간 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Images Module Level 3](https://drafts.csswg.org/css-images-3/) (`linear-gradient`·`radial-gradient`·반복형·색 정지점 규칙의 정본) · [CSS Images Module Level 4](https://drafts.csswg.org/css-images-4/) (`conic-gradient`·보간 색 공간 지정) · [CSS Color Module Level 4](https://drafts.csswg.org/css-color-4/) (알파가 있는 색의 보간). 열어서 확인한 것만 적었다.
> **실행 검증** — **Google Chrome 151.0.7922.173** headless 하나. 그라디언트 **46종**을 렌더해 **PNG 픽셀의 `(r,g,b)` 를 파이썬으로 읽었다.** 중간점 색은 전부 그 픽셀값이고, **계산값만으로는 이 주제를 검증할 수 없다**((2) 참고).
> **엔진은 Chrome 하나다** — Firefox 155 는 이 환경에서 headless 스크린샷이 산출되지 않는다. 크로스 브라우저는 **Baseline 데이터로만** 접지했고 「두 엔진에서 확인했다」고 적지 않았다.
> **버전** — `Gradients` = **widely**(low 2015-07-29 · high 2018-01-29) · `Conic gradients` = **widely**(low 2020-11-17 · high 2023-05-17) · ★ `Gradient interpolation`(`in oklab` 등을 그라디언트에 지정하는 것) = **newly**(low 2024-06-11, Chrome 111 / Firefox 127 / Safari 16.2). `webstatus.dev` API 로 조회한 값이다(2026-09-23).
> **여기서 다루지 않는 것** — 색 **표기와 색 공간 자체**는 [42번](../42-color-notation-and-spaces/2-summary.md), 색 **둘을 한 점으로 섞는 것**은 [43번](../43-color-mix-and-relative-color/2-summary.md)이 정본이다. 그라디언트를 **배경 레이어로 배치하는 것**(`background-size`·`repeat`·`origin`/`clip`·레이어 순서)은 [44번](../44-backgrounds-and-object-fit/2-summary.md)이 정본이고, 여기는 **그라디언트 이미지 자체**만 다룬다. **혼합 모드·`filter`** 는 목록의 [**47**](../47-filter-and-backdrop-filter/)·[**48**](../48-blend-modes-and-isolation/)번 주제, **`clip-path`·`mask`** 는 [목록의 **49번 주제**](../49-clip-path-and-mask/)다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 수치는 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**그라디언트는 색이 아니라 「이미지」다. 브라우저가 그 자리에서 그려 내는 그림이다.**

비유 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 브라우저가 그려 주는 그림 한 장 | **`linear-gradient(...)` 한 덩어리** — `background-image` 자리에 온다 |
| 그림 위에 꽂은 색 핀 | **색 정지점(color stop)** — 「여기는 이 색」 |
| 핀 사이를 무슨 규칙으로 칠하나 | **보간 색 공간** — `in oklab`·`in hsl` … |
| 핀 두 개를 같은 자리에 꽂으면 | **하드 스톱** — 딱 끊긴다 |
| 그림을 몇 배로 키워 붙이나 | **`background-size`** — 이미지니까 먹는다([44번](../44-backgrounds-and-object-fit/2-summary.md)) |

- **핀 사이를 어떻게 칠하느냐가 보간 색 공간**이고, 이것이 이 주제의 과녁이다.\
  *(Chrome 151 실측: 빨강→파랑의 50% 지점이 `in srgb` 는 `rgb(127, 0, 127)`, `in oklab` 은 `rgb(140, 83, 162)`, `in hsl longer hue` 는 `rgb(0, 255, 1)` 초록이었다.)*
- **그라디언트는 색이 아니라 이미지라서** `background-color` 자리에는 못 쓰고 `background-image` 자리에 온다.
- **핀을 같은 자리에 둘 꽂으면 딱 끊긴다.** 줄무늬는 이 규칙 하나로 만든다.

```text
  그라디언트 한 덩어리 = 이미지 한 장

  linear-gradient(90deg, red 0 25%, lime 25% 50%, blue 50% 100%)
                          └────┬────┘ └────┬────┘ └─────┬─────┘
                            핀 두 개        핀 두 개      핀 두 개
                          (같은 자리)      (같은 자리)   (같은 자리)
                               ↓              ↓            ↓
                          [ 빨강 | 초록 | 파랑 ]  ← 딱 끊긴 세 칸
```

실무에서 이게 터지는 자리는 **「이미지 위에 아래로 갈수록 진해지는 막을 씌워 달라」** 는 요구다.\
`linear-gradient(transparent, black)` 을 쓰면 되는데, 가운데에 `transparent` 를 끼우면 **뒷배경이 그대로 비쳐 회색 띠처럼 보인다**((7) 실측).

> **색 정지점(color stop)** — 그라디언트 선 위의 한 자리와 거기의 색.\
> 예: `red 25%` 는 「그라디언트 선의 25% 지점은 빨강」이라는 뜻이다.

> **그라디언트 선(gradient line)** — 색이 변해 가는 축. 선형은 직선, 원형은 중심에서 뻗는 반지름, 원뿔형은 각도다.\
> 예: `linear-gradient(90deg, …)` 의 선은 왼쪽에서 오른쪽으로 간다.

> **하드 스톱(hard stop)** — 정지점 둘을 같은 자리에 두어 색이 섞이지 않고 끊기게 하는 것.\
> 예: `red 50%, blue 50%` 은 가운데서 딱 갈린다.

> **보간 힌트(interpolation hint)** — 정지점 둘 사이에 색 없이 위치만 적어, 「중간색이 나오는 자리」를 옮기는 것.\
> 예: `red, 20%, blue` 는 전체의 20% 지점에서 이미 중간색이 된다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 셋을 둔다.

1. 정지점에 **위치를 안 적으면** 어디에 놓이나. 그리고 **앞선 것보다 작게 적으면** 어떻게 되나.
2. 빨강과 파랑 사이의 **중간색이 왜 여럿인가** — 무엇을 바꾸면 어떻게 갈리나.
3. **`transparent` 로 페이드하면 회색이 낀다**는 고전 사고 — **지금도 그런가.**

## 동작 방식

### (1) 세 종류의 그라디언트 선

**언제 쓰나** — 무엇을 쓸지 고를 때. 셋의 차이는 **선의 모양**뿐이다.

```text
  linear-gradient            radial-gradient           conic-gradient
  선이 직선                   선이 반지름                선이 각도

  ──────────────→           ┌─────────────┐            ┌─────────────┐
  0%          100%          │      ●──────→│           │      ↑0deg   │
                            │     중심에서  │           │   ↙  ●  ↘    │
                            │     바깥으로  │           │   각도를 따라 │
                            └─────────────┘            └─────────────┘
```

실측 — 같은 두 색으로 셋을 그려 위치별 픽셀을 뽑았다.

```text
  200×100 상자, red → blue

  종류                              중심(100,50)        왼쪽(5,50)          위(100,5)
  --------------------------------  ------------------  -----------------  -----------------
  radial-gradient(red, blue)        rgb(253, 0,   2)    rgb(85, 0, 171)    rgb( 95, 0, 161)
  radial-gradient(circle, red, blue) rgb(253, 0,  1)    rgb(40, 0, 216)    rgb(154, 0, 102)
  conic-gradient(red, lime, blue, red) rgb(0, 223, 32)  rgb(64, 0, 192)    rgb(254, 1,   0)
```

- **`radial` 의 기본은 `ellipse`** 다. 상자가 가로로 길면 타원이 되어 **왼쪽과 위의 색이 비슷**해진다(첫 줄: 85 대 95).
- **`circle` 로 바꾸면 정원**이 되어 짧은 축이 먼저 끝난다(둘째 줄: 왼쪽 40, 위 154 — 크게 갈린다).
- **`conic` 은 위쪽(0deg)에서 시작해 시계 방향**으로 돈다. 실측에서 위쪽 픽셀이 첫 색(빨강)이었다.

비용 — 셋 다 **매 픽셀을 계산해 그린다.** 반복형을 아주 작은 주기로 쓰면 비싸다.

### (2) ★ 계산값은 이 주제를 검증하지 못한다

**언제 쓰나** — 진단 방법을 고를 때. **이 절이 이 주제의 방법론이다.**

```text
  적은 것                                       계산값
  --------------------------------------------  ------------------------------------------------
  linear-gradient(in oklab 90deg, red, blue)    linear-gradient(90deg in oklab, rgb(255,0,0), rgb(0,0,255))
  linear-gradient(in hsl longer hue 90deg, red, blue)
                                                linear-gradient(90deg in hsl longer hue, rgb(255,0,0), rgb(0,0,255))
  linear-gradient(90deg, red 0%, lime 80%, blue 20%)
                                                linear-gradient(90deg, rgb(255,0,0) 0%, rgb(0,255,0) 80%, rgb(0,0,255) 20%)
```

- **계산값은 내가 적은 것을 색만 정규화해 되돌려 준다.** 중간이 무슨 색인지는 **한 글자도 알려 주지 않는다.**
- 셋째 줄이 특히 중요하다 — **`blue 20%` 이 `lime 80%` 보다 앞이라 무효인데, 계산값은 `20%` 그대로 보관한다.** 잘라 올리는 일은 **그릴 때** 일어난다.
- ★ 그래서 **이 주제의 유일한 근거는 픽셀**이다. 진단 3창의 창 3(`getComputedStyle`)으로는 아무것도 못 가른다.

```text
  다른 주제의 검증                      이 주제의 검증
  ┌────────────────────┐               ┌────────────────────┐
  │ getComputedStyle 로 │               │ --screenshot 으로   │
  │ 값을 읽어 대조      │               │ PNG 를 뽑아         │
  └────────────────────┘               │ 픽셀 (r,g,b) 를 읽는다│
                                        └────────────────────┘
```

비용 — 실험 한 판이 더 비싸다. 대신 **지어낼 수가 없다.**

### (3) 색 정지점의 위치 규칙 — 넷

**언제 쓰나** — 정지점을 손으로 배치할 때.

**규칙 ① 위치를 안 적으면 균등 분배된다.**

```text
  linear-gradient(90deg, red, lime, blue)   →   red 0%, lime 50%, blue 100%

  실측 픽셀 (400px 폭)
    x=0    rgb(253,   2,   0)   빨강
    x=100  rgb(126, 128,   0)   빨강과 초록의 중간  ← 25% 지점
    x=200  rgb(  0, 254,   0)   초록                ← 50% 지점. 균등하다
```

**규칙 ② 첫 정지점과 끝 정지점의 기본 위치는 0% 와 100% 다.**

**규칙 ③ ★ 앞선 정지점보다 작은 위치를 적으면 앞 것까지 끌어올려진다.**

```text
  linear-gradient(90deg, red 0%, lime 80%, blue 20%)
                                        └─ 20% 는 앞의 80% 보다 작다 → 80% 로 올라간다

  실측 픽셀 (400px 폭, 검정 배경 위)
    20%  rgb(192,  64,   0)   빨강→초록 가는 중
    50%  rgb( 96, 159,   0)   〃
    75%  rgb( 17, 239,   0)   거의 초록
    80%  rgb(  1, 255,   0)   초록          ← 여기까지 red→lime
    90%  rgb(  0,   0, 255)   파랑 ★        ← 80% 에서 딱 끊겼다
```

```text
  적은 대로라면                     실제로 그려진 것
  red 0% ──→ lime 80% ──→ blue 20%   red 0% ──→ lime 80% ─│─ blue 80%
             (뒤로 갈 수 없다)                             └ 하드 스톱이 된다
```

- **올라간 결과 두 정지점이 같은 자리가 되므로 하드 스톱이 된다.** 실측에서 80% 와 90% 사이에 중간색이 하나도 없었다.
- 더 센 예: `red 60%, lime 30%, blue 90%` 에서 `lime` 이 60% 로 올라가 **60% 까지 순수 빨강**이었다(실측: 0\~60% 가 전부 `rgb(255, 0, 0)`).

**규칙 ④ 정지점 하나에 위치를 둘 적을 수 있다(이중 위치).**

```text
  적은 것                                    계산값이 푼 것
  -----------------------------------------  -------------------------------------------
  red 0 25%, lime 25% 50%, blue 50% 100%     red 0px, red 25%, lime 25%, lime 50%, blue 50%, blue 100%
                                              ↑ 정지점 세 개가 여섯 개로 펴졌다
```

- **이중 위치는 하드 스톱 줄무늬를 절반의 글자 수로 적는 문법**이다.
- 실측 픽셀: x=0 `rgb(255, 0, 0)` · 25% `rgb(0, 255, 0)` · 50% `rgb(0, 0, 255)` — **중간색이 전혀 없다.**

비용 — 없다. 규칙 ③은 **에러가 아니라 조용한 교정**이라 잘못 적어도 화면만 이상해진다.

### (4) 하드 스톱 — 줄무늬를 만드는 규칙 하나

**언제 쓰나** — 줄무늬·체크무늬·구분선을 그릴 때.

```text
  linear-gradient(90deg, red 50%, blue 50%)

  실측 픽셀 (400px 폭)
    x=1    rgb(255, 0,   0)
    x=100  rgb(255, 0,   0)   ← 25%. 아직 순수 빨강
    x=200  rgb(  0, 0, 255)   ← 50%. 이미 순수 파랑
    x=300  rgb(  0, 0, 255)
    중간색이 한 픽셀도 없다.
```

```text
  부드럽게                         하드 스톱
  red ─────────────→ blue          red ──────│────── blue
   0%             100%              0%      50%     100%
  [■■▓▓▒▒░░□□]                    [■■■■■|█████]
  섞인 색이 있다                    섞인 색이 없다
```

- **`background-size` 와 함께 쓰면 반복 무늬가 된다** — (8) 참고.
- `repeating-linear-gradient` 로도 같은 무늬를 만든다. 실측에서 **두 형태의 픽셀이 샘플한 모든 자리에서 같았다**((8)).

비용 — 없다. 다만 **하드 스톱은 계단 현상이 보일 수 있다**(대각선일 때 특히).

### (5) 보간 힌트 — 중간색이 나오는 자리를 옮긴다

**언제 쓰나** — 두 색 사이가 한쪽으로 치우쳐 보일 때.

```text
  linear-gradient(90deg, red, <힌트>, blue)     ← 색 없이 위치만 적는다

  힌트 위치   25% 지점의 픽셀        50% 지점의 픽셀
  ---------  --------------------  --------------------
  (없음)      rgb(191,   0,  64)    rgb(127,   0, 127)
  20%         rgb(114,   0, 140)    rgb( 65,   0, 189)   ← 이미 파랑 쪽
  80%         rgb(244,   0,  10)    rgb(225,   0,  30)   ← 아직 빨강 쪽
```

- **힌트는 「50:50 으로 섞인 색이 어디에 오나」를 옮긴다.** 정지점이 아니므로 색을 적지 않는다.
- 계산값에도 `20%` 하나로 남는다(실측: `linear-gradient(90deg, rgb(255, 0, 0), 20%, rgb(0, 0, 255))`).

비용 — 없다. 눈에 자연스러운 그라디언트를 만들 때 자주 쓴다.

### (6) ★★ 보간 색 공간 — 중간점을 픽셀로 잰 것

**언제 쓰나** — 두 색 사이가 탁하거나 엉뚱할 때. **이것이 이 주제의 과녁이다.**

빨강→파랑을 400px 에 그리고 **25% · 50% · 75% 픽셀**을 읽었다.

```text
  보간 공간                    25%                 50%                 75%
  -------------------------   -----------------   -----------------   -----------------
  (없음) = in srgb            rgb(191, 0,  64)    rgb(127, 0, 127)    rgb( 63,  0, 191)
  in srgb                     rgb(191, 0,  64)    rgb(127, 0, 127)    rgb( 63,  0, 191)
  in srgb-linear              rgb(224, 0, 137)    rgb(187, 0, 187)    rgb(136,  0, 224)
  in lab                      rgb(226, 0,  79)    rgb(192, 0, 136)    rgb(144,  0, 194)
  in oklab                    rgb(197, 73, 109)   rgb(140, 83, 162)   rgb( 80, 71, 209)
  in oklch                    rgb(232, 0, 123)    rgb(185, 0, 194)    rgb(122,  0, 243)
  in oklch longer hue         rgb(187, 99,   0)   rgb(  0, 147,  0)   rgb(  0, 130, 178)  ★
  in hsl                      rgb(255, 0, 128)    rgb(254, 0, 255)    rgb(126,  0, 255)
  in hsl longer hue           rgb(253, 255, 0)    rgb(  0, 255,  1)   rgb(  0, 253, 255)  ★
```

```text
  같은 두 색, 중간점 하나가 이렇게 갈린다

  in srgb            ■ rgb(127,   0, 127)   어두운 보라
  in srgb-linear     ■ rgb(187,   0, 187)   밝은 자주
  in lab             ■ rgb(192,   0, 136)   진분홍
  in oklab           ■ rgb(140,  83, 162)   탁한 보라   ← 지각적으로 고르다
  in oklch           ■ rgb(185,   0, 194)   선명한 자주
  in hsl             ■ rgb(254,   0, 255)   형광 자홍
  in oklch longer    ■ rgb(  0, 147,   0)   초록 ★★
  in hsl longer      ■ rgb(  0, 255,   1)   형광 초록 ★★
```

그림 해설 (한 단계씩):

- **`in srgb` 는 중간이 어둡다.** R 과 B 를 각각 평균하면 둘 다 127 이 되어 **전체 밝기가 떨어진다.**
- **`in srgb-linear` 는 밝다.** 빛의 양으로 평균한 뒤 감마를 씌우면 187 이 된다. 같은 「보라」인데 60 만큼 밝다.
- **`in oklch`·`in hsl` 은 각도를 따라 돌아서 채도가 안 죽는다.** 대신 **거치는 색상이 바뀐다.**
- ★★ **`longer hue` 는 색상환을 먼 쪽으로 돌아 중간이 초록이 된다.** 두 색 어디에도 초록이 없는데 나온다.
- **`in oklab` 만 중간이 「탁한 보라」** 인데, 이것이 **지각적으로 고른 보간**의 모습이다 — 다른 공간처럼 중간에서 밝기가 튀지 않는다.

비용 — **`in <공간>` 지정의 Baseline 이 `newly`**(2024-06-11)다. ★ **못 읽는 브라우저는 그 선언을 통째로 버리므로 배경이 아예 없어진다** — 자동으로 `in srgb` 로 떨어지지 않는다. 앞 줄에 `in` 없는 기본형을 두는 점진적 향상이 필요하다([07번](../07-syntax-and-error-recovery/2-summary.md)).

### (7) ★★ `transparent` 로 페이드하면 회색이 끼나 — 던져서 확인한 것

**언제 쓰나** — 이미지 위에 막을 씌울 때. **고전 사고로 알려진 자리라 직접 잰다.**

**고전 이야기** — 「`linear-gradient(red, transparent)` 를 쓰면 중간에 회색이 낀다. `transparent` 가 `rgb(0 0 0 / 0)` 이라 **검정 쪽으로 끌려가기** 때문이다. 그래서 `rgb(255 0 0 / 0)` 으로 적어야 한다.」

**실측 — Chrome 151 에서는 재현되지 않았다.**

```text
  검정 배경 위, 400px, red → (투명)

  끝 정지점                    20%                50%                80%
  ------------------------     ----------------   ----------------   ----------------
  transparent                  rgb(204, 0, 0)     rgb(128, 0, 0)     rgb(51, 0, 0)
  rgb(255 0 0 / 0)   (같은 색)  rgb(204, 0, 0)     rgb(128, 0, 0)     rgb(51, 0, 0)
  rgb(0 0 255 / 0)   (다른 색)  rgb(204, 0, 0)     rgb(128, 0, 0)     rgb(51, 0, 0)
                                       ↑ 세 줄이 한 글자도 다르지 않다
```

```text
  세 줄이 같다 = 알파가 0 인 색의 색 성분이 결과에 전혀 기여하지 않는다
                 = 미리 곱해진 알파(premultiplied alpha)로 보간하고 있다

  옛 방식 (비premultiplied)          지금 (premultiplied)
  red(1,0,0,1) ↔ transparent(0,0,0,0)   red ↔ (알파만 0 으로 간다)
   중간 = (0.5, 0, 0, 0.5)               중간 = red 에 알파 0.5
   → 알파를 풀면 어두운 빨강              → 알파를 풀면 그냥 red
   → 회색·검정 끼가 보인다                → 색기가 안 변한다
```

- ★ **세 줄이 byte 단위로 같다는 것 자체가 증거**다. 색 성분이 다른 `rgb(0 0 255 / 0)` 조차 결과를 안 바꿨다.
- **`in oklab`·`in hsl`·`in oklch` 로 바꿔도 같았다**(실측 — 네 공간에서 픽셀이 동일).
- **그러므로 `transparent` → `rgb(R G B / 0)` 고치기는 Chrome 151 에서 아무것도 안 바꾼다.** 「읽는 사람에게 의도가 드러난다」는 값은 남지만 **화면이 달라지지는 않는다.**
- ★ 한 걸음 더 — **끝 정지점을 배경색 그대로(알파 없이) 적어도 픽셀이 같다.** `#111` 배경 위에서 `red → transparent` 와 `red → #111` 의 픽셀이 다섯 자리 전부 한 글자도 안 달랐다(실측). 알파를 풀어 합성한 결과가 **배경색으로 보간한 것과 수학적으로 같아지기 때문**이다.

**그런데 「회색 띠」 증상 자체는 지금도 재현된다 — 원인이 다르다.**

```text
  회색 배경(#9ca3af = rgb(156, 163, 175)) 위, 300px

  선언                                              25%                 50%                 75%
  ------------------------------------------------  -----------------   -----------------   -----------------
  linear-gradient(90deg, #e11d48, transparent, #2563eb)
                                                    rgb(191, 96, 123)   rgb(156, 162, 175) ★ rgb( 97, 131, 205)
  linear-gradient(90deg, #e11d48, #7a2f7a 50%, #2563eb)
                                                    rgb(174, 38,  97)   rgb(122,  47, 122)   rgb( 80,  73, 178)
  linear-gradient(90deg, #e11d48, #2563eb)   (대조)  rgb(178, 46, 113)   rgb(131,  64, 153)   rgb( 84,  82, 194)
```

- ★ **첫 줄의 50% 픽셀 `rgb(156, 162, 175)` 은 배경색 `rgb(156, 163, 175)` 과 거의 같다.** 그라디언트가 그 자리에서 **완전히 투명**하기 때문이다.
- **가운데 정지점을 `transparent` 로 두면 그 자리가 뚫린다.** 배경이 회색이면 회색 띠로, 흰색이면 흰 띠로 보인다.
- **고치는 법은 `rgb(R G B / 0)` 이 아니다**(그것도 알파 0 이라 똑같이 뚫린다). **가운데를 실제 색으로 적거나, 2정지점 그라디언트로 쪼갠다.**

비용 — 없다. 다만 **원인을 잘못 배우면 안 듣는 처방을 쓰게 된다.**

### (8) ★ 그라디언트는 이미지다 — `background-size` 가 먹는다

**언제 쓰나** — 줄무늬를 반복할 때. **44번과 이어지는 자리다.**

```text
  두 형태가 같은 그림을 만든다

  A  background-image: linear-gradient(90deg, red 0 50%, blue 50% 100%);
     background-size: 40px 20px;                  ← 40px 짜리 그림을 반복

  B  background-image: repeating-linear-gradient(90deg, red 0 20px, blue 20px 40px);
     (background-size 없음)                        ← 그라디언트 자체가 반복
```

```text
  실측 픽셀 (400px 폭)
  x =        1      10      25      40      50     100     200     300
  A      (255,0,0)(255,0,0)(0,0,255)(255,0,0)(255,0,0)(0,0,255)(255,0,0)(0,0,255)
  B      (255,0,0)(255,0,0)(0,0,255)(255,0,0)(255,0,0)(0,0,255)(255,0,0)(0,0,255)
         ↑ 샘플한 여덟 자리에서 전부 같았다
```

- **그라디언트는 `background-image` 의 값**이므로 `size`·`position`·`repeat`·`origin`/`clip` 이 전부 그대로 먹는다.
- 실측: A 에 `background-repeat: no-repeat` 를 더했더니 **40px 까지만 그려지고 나머지는 흰색**이었다 — 「이미지 한 장」이라는 증거다.
- **`background-color` 자리에는 못 쓴다.** 색이 아니라 이미지이기 때문이다.

비용 — **`background-size` 방식이 대개 더 싸다.** 작은 그림 한 장을 반복하는 것이기 때문이다.

### (9) 반복형 — `repeating-*`

**언제 쓰나** — 주기가 명확한 무늬를 만들 때.

```text
  repeating-linear-gradient(45deg, red 0 10px, blue 10px 20px)
       계산값: repeating-linear-gradient(45deg, rgb(255,0,0) 0px, rgb(255,0,0) 10px,
                                                rgb(0,0,255) 10px, rgb(0,0,255) 20px)
       → 20px 주기로 무한 반복한다

  repeating-conic-gradient(#000 0 10deg, #fff 10deg 20deg)
       → 20도 주기의 방사형 체크무늬
       실측: 중심 근처 (100,50) rgb(255,255,255) / 왼쪽 (5,50) rgb(0,0,0)
             — 각도에 따라 흑백이 번갈아 나온다
```

- **마지막 정지점의 위치가 한 주기의 길이**다. 그 길이만큼씩 되풀이된다.
- **마지막과 첫 정지점의 색이 다르면 이음매에서 딱 끊긴다.** 부드럽게 이으려면 양 끝 색을 같게 한다.

비용 — **주기가 아주 작으면 비싸다.** 1px 주기의 반복형은 스크롤할 때 눈에 띄게 느려질 수 있다.

## 화면으로 — demo

### 보간 색 공간이 중간색을 바꾼다

```html demo
<div class=g style="background:linear-gradient(in srgb 90deg, red, blue)"><b>in srgb</b></div>
<div class=g style="background:linear-gradient(in oklab 90deg, red, blue)"><b>in oklab</b></div>
<div class=g style="background:linear-gradient(in hsl 90deg, red, blue)"><b>in hsl</b></div>
<div class=g style="background:linear-gradient(in hsl longer hue 90deg, red, blue)"><b>in hsl longer hue</b></div>
<style>
  .g { height: 42px; margin-bottom: 4px; position: relative; }
  .g b { position: absolute; left: 50%; top: 12px; transform: translateX(-50%);
         font: 12px system-ui; color: #fff; text-shadow: 0 1px 2px #000; }
</style>
```

> **보이는 것** — 띠 넷이 세로로 있다. **넷 다 왼쪽 끝이 빨강, 오른쪽 끝이 파랑으로 같은데 가운데가 전부 다르다.** 첫째는 어두운 보라, 둘째는 탁한 보라, 셋째는 형광에 가까운 자홍, **넷째는 가운데가 초록**이다. 넷째는 빨강에도 파랑에도 없는 색이 한가운데에 나온다.\
> **바꿔 볼 것** — `in hsl longer hue` 를 `in oklch longer hue` 로 → 가운데가 **더 어두운 초록**이 된다 · `in srgb` 를 `in srgb-linear` 로 → 같은 보라인데 **훨씬 밝아진다**

*(Chrome 151 headless 실측 — 뷰포트 585px 에서 이 블록을 띄워 각 띠의 가운데(x=292) 픽셀을 읽었다: `in srgb` `rgb(130, 0, 124)` · `in oklab` `rgb(143, 83, 159)` · `in hsl` `rgb(255, 0, 248)` · `in hsl longer hue` `rgb(12, 255, 0)`. 「바꿔 볼 것」도 같은 자리에서 확인했다 — `in oklch longer hue` `rgb(0, 146, 0)` · `in srgb-linear` `rgb(189, 0, 185)`. 그라디언트 픽셀은 디더링으로 2\~3 단위 흔들리므로 **마지막 자릿수를 근거로 삼지 않는다**.)*

### 정지점 둘을 같은 자리에 두면 딱 끊긴다

```html demo
<div class=a></div>
<div class=b></div>
<style>
  .a, .b { height: 46px; margin-bottom: 6px; }
  .a { background: linear-gradient(90deg, #dc2626, #2563eb); }
  .b { background: linear-gradient(90deg,
         #dc2626 0 25%, #16a34a 25% 50%, #2563eb 50% 75%, #f59e0b 75% 100%); }
</style>
```

> **보이는 것** — 위 띠는 빨강에서 파랑으로 **부드럽게 이어지고**, 아래 띠는 빨강·초록·파랑·주황 **네 칸이 칼로 자른 듯 딱 끊겨** 있다. 아래 띠의 네 칸은 폭이 똑같다. 두 띠 다 같은 `linear-gradient` 이고, 다른 것은 정지점에 **위치를 둘씩 적었는지**뿐이다.\
> **바꿔 볼 것** — 아래 띠의 `25% 50%` 를 `25% 45%` 로 → 45\~50% 구간에만 초록→파랑 그라데이션이 생긴다 · `90deg` 를 `45deg` 로 → 줄무늬가 비스듬해진다

*(Chrome 151 headless 실측 — 뷰포트 585px 에서 아래 띠의 픽셀: x=10 `rgb(220, 38, 38)` · x=100 `rgb(220, 38, 38)` · x=160 `rgb(22, 163, 74)` · x=300 `rgb(37, 99, 235)` · x=450 `rgb(245, 158, 11)`. 한 행을 왼쪽부터 훑어 색이 바뀐 자리를 뽑으니 **149→150 · 299→300 · 449→450 딱 세 군데**였고, 세 군데 모두 **한 픽셀 만에** `rgb(220, 38, 38)`→`rgb(22, 163, 74)` 처럼 바뀌었다 — 중간색이 없다. 「바꿔 볼 것」도 확인했다 — `25% 45%` 로 바꾸니 x 263\~292 구간에만 초록→파랑 그라데이션이 생기고 나머지 경계 둘은 그대로였다.)*

### 알파가 0 인 색은 색 성분이 안 쓰인다

```html demo
<div class=wrap>
  <div class=f style="background:linear-gradient(90deg, #e11d48, transparent)"></div>
  <div class=f style="background:linear-gradient(90deg, #e11d48, rgb(225 29 72 / 0))"></div>
  <div class=f style="background:linear-gradient(90deg, #e11d48, rgb(37 99 235 / 0))"></div>
</div>
<style>
  .wrap { background: #111; padding: 10px; }
  .f { height: 34px; margin-bottom: 6px; }
  .f:last-child { margin-bottom: 0; }
</style>
```

> **보이는 것** — 검은 바탕 위에 붉은 띠 셋이 있고 **셋 다 왼쪽에서 오른쪽으로 똑같이 사라진다.** 끝 정지점을 `transparent`(검정+알파 0) · 같은 붉은색의 알파 0 · **파란색의 알파 0** 으로 서로 다르게 적었는데 **셋을 구분할 수 없다.** 어디에도 회색 띠나 푸른 기가 없다.\
> **바꿔 볼 것** — `.wrap` 의 `#111` 을 `#9ca3af` 로 → 셋 다 회색 쪽으로 사라진다(여전히 셋이 같다) · 첫째의 `transparent` 를 `#111`(배경색 그대로, 알파 없음)로 → **그래도 셋과 구분되지 않는다**

*(Chrome 151 headless 실측 — 뷰포트 585px 에서 세 띠의 같은 높이 픽셀이 x=11·126·292·458·570 다섯 자리 전부 같았다: `rgb(224, 29, 72)` · `rgb(183, 27, 61)` · `rgb(124, 23, 45)` · `rgb(64, 20, 30)` · `rgb(24, 17, 19)`. **알파가 0 인 색의 색 성분이 결과에 전혀 기여하지 않는다**는 뜻이다. 「바꿔 볼 것」 둘 다 확인했다 — 배경을 `#9ca3af` 로 바꿔도 세 띠가 같았고(`rgb(225, 29, 72)` / `rgb(211, 56, 93)` / `rgb(192, 94, 122)` / `rgb(172, 133, 152)` / `rgb(159, 159, 172)`), `transparent` 를 `#111` 로 바꾼 띠도 다섯 자리가 **한 글자도 다르지 않았다.** 같은 실험을 `in oklab`·`in hsl`·`in oklch` 에서도 돌렸고 픽셀이 동일했다.)*

## 문법 — 형태와 규칙

CSS 는 문법 표면이 단순하므로 이 절은 「**형태 — 어디서 헷갈리나**」로 읽는다.

### 형태

```css
/* 선형 — 각도 또는 to <방향> */
linear-gradient(90deg, red, blue)
linear-gradient(to right, red, blue)
linear-gradient(in oklab 90deg, red, blue)        /* 보간 공간 — 각도 앞뒤 어느 쪽이든 된다 */
linear-gradient(90deg, red 0 25%, blue 25% 100%)  /* 이중 위치 */
linear-gradient(90deg, red, 20%, blue)            /* 보간 힌트 — 색이 없다 */

/* 원형 — 모양·크기·중심 */
radial-gradient(red, blue)                              /* 기본 ellipse farthest-corner */
radial-gradient(circle closest-side at 50px 50px, red, blue)

/* 원뿔형 — 시작 각도·중심 */
conic-gradient(red, lime, blue, red)
conic-gradient(from 90deg at 50% 50%, red 0 25%, lime 25% 50%, blue 50% 100%)

/* 반복형 — 마지막 정지점 위치가 한 주기 */
repeating-linear-gradient(45deg, red 0 10px, blue 10px 20px)
repeating-conic-gradient(#000 0 10deg, #fff 10deg 20deg)
```

### 금지 사례 — 안 되거나 조용히 교정되는 형태

```css
background-color: linear-gradient(red, blue);     /* 색이 아니라 이미지다. 선언째 버려진다 */
background: linear-gradient(90deg, red 0%, lime 80%, blue 20%);
                                                  /* 버려지지 않는다. 20% 가 80% 로 올라간다 ★ */
background: linear-gradient(90deg, red, 30%, 60%, blue);
                                                  /* 힌트를 연달아 둘 — 선언째 버려진다 */
```

### 어디서 헷갈리나 — 이름 여섯

| 이름 | 무엇인가 | 헷갈리는 짝 |
|---|---|---|
| `in <공간>` | 정지점 **사이**를 칠하는 좌표계 | `color-mix(in …)`(43번) — 같은 규칙, **한 점**에 적용 |
| `longer hue` | 색상환을 **먼 쪽으로** 돈다 | 「부드럽게」가 아니다. 없던 색이 나온다 |
| 보간 힌트 `20%` | 중간색이 **나오는 자리** | 정지점 — 색을 같이 적는다 |
| 이중 위치 `red 0 25%` | 정지점 **둘**로 펴진다 | `red 0 25%` 는 「0 에서 25% 까지 빨강」 |
| `repeating-*` | 마지막 정지점 위치가 **한 주기** | `background-repeat`(44번) — 이미지 한 장을 반복 |
| `transparent` | **검정 + 알파 0**([42번](../42-color-notation-and-spaces/2-summary.md)) | 보간에서는 **색 성분이 안 쓰인다**((7) 실측) |

## 어디서 틀리나

### 1. `getComputedStyle` 로 그라디언트를 검증하려 한다

**아무것도 못 가른다**((2)). 계산값은 내가 적은 것을 색만 정규화해 되돌려 준다. **픽셀을 읽어야** 한다.

### 2. 위치를 거꾸로 적으면 무효가 될 거라 기대한다

**버려지지 않고 앞 것까지 끌어올려진다**((3) 규칙 ③). 계산값에는 내가 적은 `20%` 가 그대로 남아 있어서 **계산값을 읽어도 안 보인다.**

### 3. 「`transparent` 로 페이드하면 회색이 낀다」를 지금 브라우저에 그대로 적용한다

**Chrome 151 에서 재현되지 않았다**((7) 실측 — 알파 0 인 색 셋이 byte 단위로 같은 픽셀을 냈다). 고치는 습관은 남아도 좋지만 **원인 설명이 틀리면 진짜 사고를 못 잡는다.**

### 4. 회색 띠의 원인을 보간 방식이라고 진단한다

**가운데 정지점이 투명해서 배경이 비치는 것**이다((7) 둘째 실측 — 50% 픽셀이 배경색과 같았다). `rgb(R G B / 0)` 으로 바꿔도 **안 고쳐진다.**

### 5. 적은 순서와 계산값의 순서가 다르다고 놀란다

`linear-gradient(in oklab 90deg, …)` 라고 적어도 계산값은 **`linear-gradient(90deg in oklab, …)`** 로 돌아온다. **두 순서 다 유효하고**(실측 — 둘 다 `cssText` 에 담겼다), 직렬화 형태가 뒤쪽으로 고정돼 있을 뿐이다. 문자열로 대조하면 안 맞는다.

### 6. `longer hue` 를 「더 부드럽게」로 읽는다

**색상환을 먼 쪽으로 돈다**는 뜻이다. 빨강→파랑의 중간이 **초록**이 됐다((6) 실측).

### 7. `background-color` 에 그라디언트를 넣는다

**색이 아니라 이미지**다. 선언째 버려지고 아무 말도 없다.

### 8. `radial-gradient` 가 항상 원이라고 생각한다

**기본은 `ellipse`** 다((1) 실측 — 가로로 긴 상자에서 왼쪽과 위의 색이 비슷했다).

| 정지점 둘이 같은 자리면 **하드 스톱**인 것 | **언어 보장** | 〃 |
| 이중 위치가 **정지점 둘로 펴지는** 것 | **언어 보장** | 계산값이 실제로 여섯 개로 펴졌다 |
| 보간 공간이 **중간색을 바꾸는** 것 | **언어 보장** | Images 4 + Color 4. 아홉 공간이 전부 다른 픽셀을 냈다 |
| **알파 0 인 색의 색 성분이 안 쓰이는** 것 | **언어 보장(Color 4 의 알파 보간 규칙)** | 실측이 근거다 — 색 성분이 다른 세 표기가 byte 단위로 같은 픽셀을 냈다 |
| 옛 브라우저에서 회색이 꼈다는 **이야기** | **과거 구현** ★ | **이 환경에서는 재현되지 않았다.** 재현해 보지 않은 과거 동작을 관찰로 적지 않았다 |
| 그라디언트 **픽셀의 마지막 1\~2 단위** | **구현 + 디더링** | 같은 색이 `rgb(254, …)`/`rgb(255, …)` 사이에서 흔들렸다. 그래서 **경계 근처를 근거로 삼지 않았다** |
| 계산값의 직렬화 형태(`90deg in oklab`) | **CSSOM 직렬화 형식** | 적는 순서(`in oklab 90deg`)와 다르다 |
| `in <공간>` 을 **쓸 수 있는가** | **구현 — Baseline `newly`**(2024-06-11) | webstatus.dev. ★ 못 읽으면 **선언째 버려져 배경이 아예 없어진다** — 기본형을 앞 줄에 두는 점진적 향상이 필요하다 |
| 화면에 실제로 칠해지는 색 영역 | **화면 + 구현** | 이 환경은 sRGB 다([42번](../42-color-notation-and-spaces/2-summary.md) (7)) |

★ **근거로 쓸 칸을 미리 갈랐다.** 이 주제의 픽셀은 **평평한 구간**(정지점 사이 한가운데, 하드 스톱의 칸 안쪽)에서는 안 흔들렸고, **경계에서 ±1px** 는 디더링으로 흔들렸다. 그래서 본문의 수치는 전부 평평한 구간에서 뽑았고, 하드 스톱의 경계는 **「한 픽셀 만에 바뀌었다」는 사실**만 근거로 썼다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 안 쓸 것 |
|---|---|---|
| 두 색 사이가 탁해 보인다 | `in oklch` 나 `in hsl` — 각도를 따라간다 | `in srgb` — 중간에서 밝기가 떨어진다 |
| 밝기가 고르게 변해야 한다 | `in oklab` | `in srgb` — 중간이 어둡다 |
| 줄무늬 | 이중 위치 하드 스톱 + `background-size` | 이미지 파일 — 확대하면 깨진다 |
| 이미지 위 자막 배경 | `linear-gradient(transparent, rgb(0 0 0 / 0.7))` 2정지점 | 가운데에 `transparent` 끼우기 — 배경이 비친다 |
| 무지개 | `in oklch longer hue` | 정지점을 손으로 여섯 개 나열 |
| 방사형 체크무늬·원형 차트 | `conic-gradient` | 이미지·SVG (간단한 것이면) |
| 주기가 1\~2px 인 무늬 | `background-size` 로 작은 그림 반복 | `repeating-*` — 매 픽셀 계산이 비싸다 |
| `background-color` 자리 | 단색 | 그라디언트 — 이미지라 안 들어간다 |

## 핵심 문장

- **그라디언트는 색이 아니라 이미지다.** `background-image` 자리에 오고 `background-size` 가 먹는다.
- **계산값으로는 이 주제를 검증할 수 없다.** 중간색은 픽셀을 읽어야 안다.
- **앞선 것보다 작은 위치는 버려지지 않고 끌어올려진다.** 그 결과 하드 스톱이 된다.
- **보간 공간이 중간색을 바꾼다.** 빨강→파랑의 중간이 어두운 보라에서 형광 초록까지 갈렸다.
- **알파가 0 인 색의 색 성분은 안 쓰인다.** 「`transparent` 때문에 회색이 낀다」는 Chrome 151 에서 재현되지 않았고, 회색 띠의 진짜 원인은 **가운데 정지점이 투명해 배경이 비치는 것**이었다.

## 용어 풀이

- **색 정지점(color stop)** — 그라디언트 선 위의 한 자리와 거기의 색. 예: `red 25%`.
- **그라디언트 선(gradient line)** — 색이 변해 가는 축. 예: `linear-gradient(90deg, …)` 의 선은 왼쪽에서 오른쪽이다.
- **하드 스톱(hard stop)** — 정지점 둘을 같은 자리에 둬 색이 안 섞이게 하는 것. 예: `red 50%, blue 50%` 의 경계에서 한 픽셀 만에 색이 바뀌었다.
- **이중 위치(double position)** — 정지점 하나에 시작·끝 위치를 함께 적는 문법. 예: `red 0 25%` 가 정지점 둘로 펴진다.
- **보간 힌트(interpolation hint)** — 색 없이 위치만 적어 중간색이 나오는 자리를 옮기는 것. 예: `red, 20%, blue`.
- **보간 색 공간(interpolation color space)** — 정지점 사이를 계산하는 좌표계. 예: `in oklab` 과 `in hsl` 이 같은 두 색에서 다른 중간색을 냈다.
- **미리 곱해진 알파(premultiplied alpha)** — 색 성분에 알파를 미리 곱해 두고 보간하는 방식. 예: 알파 0 인 색의 색 성분이 결과에 안 나타나는 것이 이 방식의 표시다.
- **반복형 그라디언트(repeating gradient)** — 마지막 정지점까지를 한 주기로 무한 반복하는 그라디언트. 예: `repeating-linear-gradient(45deg, red 0 10px, blue 10px 20px)` 는 20px 주기다.
- **디더링(dithering)** — 표현할 수 있는 색이 모자랄 때 점을 섞어 눈속임하는 것. 예: 그라디언트 경계 픽셀이 1\~2 단위 흔들린 원인이다.
- **Baseline** — 주요 브라우저에 그 기능이 언제부터 다 들어갔는지를 나타내는 지표. 예: `Conic gradients` 는 `widely`, `Gradient interpolation` 은 `newly` 다.

## 더 들어가면

- **정지점에 `<length>` 와 `<percentage>` 를 섞어 쓸 수 있다.** `red 0 20px, blue 20px 50%` 같은 형태가 유효하다.
- **`conic-gradient` 로 원형 진행 막대를 만든다.** `conic-gradient(#2563eb 0 var(--p), #e5e7eb var(--p))` 한 줄이면 된다 — 단 `--p` 를 애니메이션하려면 `@property` 등록이 필요하다([목록의 **37번 주제**](../37-at-property/)).
- **`radial-gradient` 의 크기 키워드는 넷이다** — `closest-side`·`closest-corner`·`farthest-side`·`farthest-corner`(기본). 실측에서 `closest-side at 50px 50px` 은 중심에서 50px 만에 끝나 상자 대부분이 끝 색이었다.
- **`in oklch longer hue` 한 줄로 무지개가 나온다** — 정지점을 손으로 여섯 개 나열할 필요가 없다((6) 실측).
- **그라디언트는 `mask-image` 에도 쓴다** — [목록의 **49번 주제**](../49-clip-path-and-mask/)가 정본이다. 거기서는 알파만 읽힌다.
