# css/syntax/46 — 테두리·`border-radius`·`outline`·`box-shadow` — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **모든 치수는 Google Chrome 151.0.7922.173 headless 에서 실제로 렌더해 `getBoundingClientRect()`·`getComputedStyle()` 로 잰 값**이고,
> **모든 색은 스크린샷 PNG 를 파이썬 표준 라이브러리(`zlib`)로 디코드해 그 좌표의 `(r,g,b)` 를 읽은 값**이다.\
> **손으로 계산해 유도한 수치는 없다.** 규칙은 [CSS Backgrounds and Borders 3](https://drafts.csswg.org/css-backgrounds-3/) 과 [CSS UI 4 §outline](https://drafts.csswg.org/css-ui-4/#outline) 으로 접지했다.\
> ★ 렌더는 `--disable-gpu` **소프트웨어 렌더링**이다. 곡선 경계의 중간색은 GPU 합성과 미세하게 다를 수 있다 — 값 하나가 아니라 **띠의 폭과 불투명 지점**으로 읽어라.

## 정답

### 1. 테두리가 안 보인다 — 상자 치수는 어떻게 되나

**실행 결과** (Chrome 151 headless)

```text
.a  border-style=none    계산된 border-width=0px   rect=232x32
.b  border-style=solid   계산된 border-width=8px   rect=248x48
```

**`.a` 의 `borderTopWidth`**

- **`0px`** 이다. `8px` 이 아니다.
- `border-style` 의 초깃값이 `none` 이고, 명세는 그때 **계산된 `border-width` 를 0 으로** 만든다.

**두 `rect.width`**

- `.a` 는 **232**(220 + 패딩 12), `.b` 는 **248**(232 + 테두리 16)이다.

**나중에 `solid` 를 넣으면**

- 상자가 **가로·세로로 16px 씩 커지고** 그만큼 이웃이 밀린다.\
  「안 보이던 테두리가 보이기만 하는」 변화가 아니다.

**`hidden` 으로 바꾸면**

- `.a` 와 같아진다 — 실측: `border-style=hidden`, 계산된 폭 `0px`, `rect` 232×32.
- `hidden` 과 `none` 이 갈리는 곳은 `border-collapse: collapse` 인 표 하나뿐이다.

### 2. 선언한 반지름과 그려진 반지름이 갈린다

**실행 결과** (Chrome 151 headless — 200×200 `#cc0000` 상자 셋)

```text
선언      getComputedStyle().borderRadius   45도 대각선 첫 불투명 픽셀 d   100px 판과 다른 픽셀(40,000 중)
150px     "150px"                           30                           2    (최대 채널 차 8)
120px     "120px"                           30                           279  (최대 채널 차 56)
100px     "100px"                           30                           기준
```

**`.x` 의 계산값**

- **`"150px"`** 을 그대로 돌려준다. 축소가 반영되지 않는다.

**픽셀 비교**

- 40,000 픽셀 중 **2개**만 다르고, 그 2개는 둘 다 **곡선 경계 한 줄**(`x=0`, `y=91`·`92`)이며 채널 차가 8 이하다. 안티앨리어싱 반올림이다.
- 안쪽·바깥쪽은 **한 픽셀도 다르지 않았다.** 곧 `150px` 은 화면에서 `100px` 이다.
- `120px` 판도 대각선 진입점 `d` 가 똑같이 30 이었다(차이 279픽셀 역시 전부 곡선 경계).

**축소 비율**

- 네 변 각각에 대해 `f = 변 길이 / 그 변의 두 반지름 합` 을 구하고, **넷 중 가장 작은 값**(그리고 1)을 골라 **모든 반지름에** 곱한다.
- 그래서 **한 변만 넘쳐도 네 모서리가 전부 줄어든다.**
- 여기서는 위 변이 `200 / (150+150) = 0.666…` 이라 `150 × 0.666… = 100` 이 됐다.

**계산값 API 로 확인 가능한가**

- **불가능하다.** 축소는 사용값 단계에서 일어나고 `getComputedStyle` 은 그 전 값을 돌려준다.
- 이 주제에서 「진단 3창」의 세 번째 창이 **거짓 안심**을 주는 자리다. 픽셀을 읽는 수밖에 없다.

### 3. `/` 가 가르는 두 반지름

**실행 결과** (Chrome 151 headless — 200×200 `#cc0000` 상자)

```text
선언             위 변(y=0) 첫 불투명 x    왼 변(x=0) 첫 불투명 y
60px             59                      60
60px / 20px      59                      20
20px / 60px      20                      60
```

**위 변의 `x`**

- **59** 다(가로 반지름 60 의 경계).

**왼 변의 `y`**

- **20** 이다(세로 반지름 20).

**`/` 앞뒤**

- **앞이 가로 반지름, 뒤가 세로 반지름**이다. `60px / 20px` 은 「가로로 눕힌 타원」이다.
- 값이 하나면 둘이 같아 원이 된다.

**최대 숫자 개수**

- **여덟 개**다. `/` 앞에 네 모서리(`TL TR BR BL`)의 가로 반지름, 뒤에 같은 순서의 세로 반지름.

### 4. `outline` 과 `border` — 이웃의 `x` 좌표

**실행 결과** (Chrome 151 headless)

```text
(가) demo 와 같은 판 — 90px 상자 + 8px, 줄 시작 x=16
행        대상 rect.width   이웃 rect.left
border    106              122
outline    90              106

(나) 셋을 한 문서에서 비교한 판 — 80px 상자 + 10px, 줄 시작 x=0
행                       대상 rect.width   이웃 rect.left
border: 10px             100              100
outline: 10px             80               80
box-shadow: 0 0 0 10px    80               80
```

**`.brd`** (판 (가))

- `rect.width` = **106**(90 + 8×2), 이웃 `left` = **122**.

**`.out`**

- `rect.width` = **90**, 이웃 `left` = **106**.
- 곧 **8px 테가 자기 치수에도, 이웃의 위치에도 들어가지 않았다.**

**겹치는 지점의 픽셀**

- **이웃의 배경색**이다. 실측에서 그 좌표는 `(219,234,254)` = `#dbeafe`(이웃 배경)였지 초록이 아니었다.
- 이유는 **나중에 그려지는 형제가 위에 온다**는 것이다. `outline` 은 자리를 안 차지하는 대신 가려진다.
- 테가 안 가려지는 쪽(위·아래 바깥)에서는 초록 `(34,197,94)` 로 읽혔다.

**`outline-offset: 12px` 를 주면**

- 이웃의 `x` 는 **안 바뀐다.** 실측: 오프셋 없는 판과 12px 판 모두 이웃 `x` = 90(폭 90 상자 기준), 스크롤 영역도 둘 다 같았다.

### 5. 그림자 두 개, 순서만 다르다

**실행 결과** (Chrome 151 headless — 상자 왼쪽 끝 `x=40`)

```text
선언                                       x=32 (바깥 8px)     x=20 (바깥 20px)
.a  0 0 0 30px 빨강, 0 0 0 15px 파랑        (239,68,68) 빨강    (239,68,68) 빨강
.b  0 0 0 15px 파랑, 0 0 0 30px 빨강        (59,130,246) 파랑   (239,68,68) 빨강
```

**`.a` 의 8px 바깥**

- **빨강**이다. 먼저 쓴 30px 빨강 그림자가 위에 와서 **파란 띠를 통째로 덮는다.**

**`.b` 의 같은 지점**

- **파랑**이다. 먼저 쓴 15px 파랑이 위에 온다.

**20px 바깥**

- **두 판 다 빨강**이다. 그 자리는 파란 띠(15px)가 닿지 않는다.

**이중 링을 만들려면**

- **작은 것을 먼저** 쓴다. `box-shadow: 0 0 0 3px #93c5fd, 0 0 0 5px #2563eb` 처럼.
- `z-index` 와 달리 「**먼저 쓴 게 위**」다. 값의 크기는 순서와 무관하다.

### 6. 둥근 상자에 테를 두르면

**실행 결과** (Chrome 151 headless — 상자 왼쪽 위가 `(30,30)`, 100×100, 반지름 50)

```text
좌표                          픽셀              읽는 법
(30,30)  상자 모서리            (255,255,255)    페이지 배경 — 테가 각지지 않았다
(26,80)  왼쪽 바깥 4px          (22,163,74)      초록 테
(80,26)  위쪽 바깥 4px          (22,163,74)      초록 테
(45,45)  대각선 안쪽            (29,78,216)      상자색
대각선 첫 비백색 픽셀 d = 10                      고리가 대각선 방향으로도 돈다

같은 선언 + border-radius:0
(367,27) 모서리 바깥           (22,163,74)      초록 — 각진 테
```

**상자 모서리 픽셀**

- **배경색**이다. `outline` 이 각진 사각형이면 여기가 초록이어야 한다.

**왼쪽 바깥 4px**

- **초록**이다. 곧 테는 **둥근 고리 모양**으로 상자를 돈다.

**`border-radius: 0` 으로 바꾸면**

- 모서리 바깥이 **초록**이 된다. 각진 테다.

**보장인가 관찰인가**

- ★ **관찰이다.** `css-ui-4` 는 모서리 모양을 UA 재량으로 남기는 표현을 쓴다.
- 다만 Baseline 조회에서 `outline`(CSS UI 4 §outline) 항목이 **Chrome 94(2021-09-21)·Firefox 88(2021-04-19)·Safari 16.4(2023-03-27)** 로 갈리고 **widely 가 2023-03-27** 이다. 그 항목이 정확히 무엇을 세는지는 API 가 말해 주지 않으므로 「그때 둥근 `outline` 이 들어왔다」고 단정하지는 않았다.

### 7. `spread` 는 `blur` 와 무엇이 다른가

**실행 결과** (Chrome 151 headless — 상자 왼쪽 끝 `x=450`, `spread` 15px)

```text
0 0 0 15px 주황     x=445 (245,158,11) 주황 · x=434 (255,255,255) 흰색 — 15px 에서 딱 끊긴다
0 0 10px 30px 빨강  x=5 (252,218,218) · x=10 (246,153,153) · x=14 (242,103,103)
                    · x=18 (239,76,76) · x=22 부터 (239,68,68) — 경계가 번진다
inset 0 0 0 15px    x=658 주황(안쪽) · x=680 상자색 · x=645 (255,255,255) — 바깥에 아무것도 없다
```

**두 선언의 차이**

- `0 0 0 15px` 는 **또렷한 15px 띠**다. 그림자 모양을 사방으로 15 부풀리기만 한다.
- `0 0 15px 0` 은 **흐릿하게 번지는 후광**이다. 모양은 그대로 두고 경계를 흐린다.

**`border` 와의 구별**

- **화면에서는 구별이 안 된다.** `spread` 만 준 그림자는 또렷한 선이라 테두리처럼 보인다.
- **레이아웃에서 갈린다.** `border` 는 상자를 키우고 이웃을 밀지만, 그림자는 `rect.width` 도 이웃 `x` 도 안 바꾼다.

**`inset` 을 붙이면**

- 상자 **바깥에는 아무것도 안 남는다.** 실측에서 바깥 5px 지점은 흰색이었다.

**길이 값을 하나만 쓰면**

- **선언 자체가 버려진다.** `box-shadow: 10px #f00` 은 `cssRules` 에 아예 담기지 않았고 계산값은 `none` 이었다.

### 8. 자리를 안 차지하는 것의 대가

**실행 결과** (Chrome 151 headless — 200px 자식 하나가 120px 스크롤 상자 안에 있을 때)

```text
선언                       자식 rect.width   컨테이너 scrollWidth
없음                       200              200
box-shadow: 0 0 0 60px     200              200
outline: 60px solid        200              200
border-right: 60px solid   260              260
```

**두 숫자**

- **자기 `rect.width`** 와 **다음 형제의 `rect.left`** 다. 둘 다 안 바뀌면 공간을 0 차지한 것이다.
- 실측에서 `border` 행은 106/122, `outline` 행은 90/106 이었다.

**대가**

- **이웃이 덮는다.** 나중에 그려지는 형제의 배경이 테·그림자 위에 온다 — 실측에서 겹친 지점은 이웃 배경색이었다.

**스크롤 영역**

- **안 늘어난다.** 60px 짜리 그림자·테를 붙여도 `scrollWidth` 는 200 으로 그대로였고, 같은 60px 을 `border` 로 주니 260 이 됐다.
- 명세도 「그림자는 오버플로를 만들지 않고 스크롤 영역에 들어가지 않는다」고 못 박는다.

**일부러 쓰는 자리**

- **포커스 링**이다. `:focus-visible` 에 `outline` 이나 `box-shadow: 0 0 0 3px` 를 주면 포커스가 옮겨갈 때 레이아웃이 안 흔들린다.
- 같은 걸 `border` 로 하면 **탭을 누를 때마다 화면이 들썩인다.**

### 9. 조용히 버려진 선언을 어떻게 찾나

**실행 결과** (Chrome 151 headless — 「진단 3창」)

```text
입력  .x { border-radius: 50; box-shadow: 10px #f00; outline: 10px groove blue; border: 10px dashed red }

창 1  cssRules[0] = .x { outline: blue groove 10px; border: 10px dashed red; }
창 2  querySelectorAll('.x').length = 1
창 3  getComputedStyle: border-radius=0px  box-shadow=none
                        outline=rgb(0,0,255) groove 10px  border=10px dashed rgb(255,0,0)
```

**왜 에러가 없나**

- **CSS 는 에러가 없는 언어**다. 파서는 무효한 선언을 만나면 **그 선언만 버리고 다음 선언으로 넘어간다**(오류 복구).
- 콘솔에도 화면에도 아무 신호가 없다. `border-radius: 50` 은 단위가 없어서, `box-shadow: 10px #f00` 은 길이가 하나뿐이라서 버려졌다.

**세 창이 묻는 것**

- 창 1 `cssRules` — **규칙·선언이 아예 안 담겼나.** 위 두 선언은 **여기서 잡힌다**(규칙 텍스트에 없다).
- 창 2 `querySelectorAll` — **선택자가 안 잡았나.** 여기서는 정상(1개).
- 창 3 `getComputedStyle` — **담겼는데 캐스케이드에서 졌나.** 여기서는 초깃값(`0px`·`none`)이 보인다.

**규칙 자체는**

- **살아남는다.** 유효한 `outline`·`border` 두 선언은 그대로 적용됐다. **선언 단위로만 죽는다.**

**`getComputedStyle` 이 거짓 안심을 주는 자리**

- **2번의 반지름 비례 축소**다. 거기서는 선언이 살아 있고 계산값도 `150px` 로 정상인데 **화면에 그려진 것은 100px** 이다.
- 세 창 전부 통과하는데 결과가 다른 **제4의 상태**다.

### 10. 다른 주제로 잇기

**`border-radius` 와 자식**

- **안 자른다.** 실측: 반지름 60인 부모 안의 네모난 자식 배경이 모서리에서 `(220,38,38)` 로 그대로 보였다.
- `overflow: hidden` 을 주면 같은 좌표가 `(255,255,255)` 페이지 배경으로 돌아왔다.
- 임의의 모양으로 자르려면 [49번](../49-clip-path-and-mask/2-summary.md)의 `clip-path` 가 필요하다.

**투명 PNG 아이콘의 그림자**

- **`filter: drop-shadow()`** 다. [47번](../47-filter-and-backdrop-filter/2-summary.md)이 정본이다.
- `box-shadow` 는 **상자 모양**을 따라가므로 투명한 구석에도 그림자가 생긴다. 실측에서 삼각형 PNG 의 투명한 구석에 `box-shadow` 는 `(220,38,38)` 빨강을, `drop-shadow` 는 `(255,255,255)` 흰색을 남겼다.

**`border-radius` 의 일반화**

- **`clip-path`** 이고 [49번](../49-clip-path-and-mask/2-summary.md) 주제다.
- `border-radius` 가 이미 「모양을 자르는 것」이고, `clip-path` 는 그 모양을 `circle`·`polygon`·`path` 로 넓힌 것이다.

**비례 축소가 일어나는 단계**

- **사용값(used value)** 단계다. 정본은 [04번](../04-value-processing-stages/2-summary.md)이다.
- 선언값 → 계산값 → 사용값 중 계산값까지는 `150px` 이고 사용값에서 `100px` 이 된다.

## 용어 풀이

- **`border-style`** — 테두리를 어떤 선으로 그릴지. 초깃값 `none` 이고, `none`/`hidden` 이면 계산된 `border-width` 가 0 이 된다.
- **`hidden`(테두리)** — 일반 상자에서는 `none` 과 결과가 같다. `border-collapse: collapse` 인 표에서만 「이웃 테두리까지 이긴다」로 갈린다.
- **비례 축소(scale factor)** — 한 변의 두 반지름 합이 변 길이보다 클 때, 네 변에서 구한 비율 중 가장 작은 것을 모든 반지름에 곱하는 것. 사용값 단계에서 일어난다.
- **`outline`** — 상자 위에 덧그려지는 선. 레이아웃 공간 0, 스크롤 영역에도 안 들어간다. Chrome 151 에서는 `border-radius` 를 따라 둥글게 돈다.
- **`outline-offset`** — 테와 상자 사이의 거리. 음수면 안쪽으로 파고든다. 이것도 공간을 안 차지한다.
- **`spread`** — 그림자 모양을 사방으로 N px 부풀리는 것. `blur` 는 경계를 흐리고 `spread` 는 크기를 키운다.
- **`inset`(그림자)** — 그림자를 상자 안쪽에 그린다. 바깥에는 아무것도 안 남는다.
- **오류 복구(error recovery)** — 무효한 선언을 만나면 그 선언만 버리고 다음으로 넘어가는 CSS 파서의 규칙. 정본은 [07번](../07-syntax-and-error-recovery/2-summary.md).
- **진단 3창** — `cssRules` → `querySelectorAll` → `getComputedStyle` 순으로 물어 「안 담겼나 / 안 잡혔나 / 졌나」를 가르는 것. 이 주제에는 **셋 다 통과하는데 화면이 다른 제4의 상태**(반지름 축소)가 있다.
- **안티앨리어싱(anti-aliasing)** — 곡선을 픽셀 격자에 맞출 때 경계에 중간색을 넣는 것.\
  예: 둥근 모서리에서 `(204,0,0)` 도 `(255,255,255)` 도 아닌 `(226,111,111)` 이 읽히는 것.

## 실행 검증

| 무엇을 | 어떻게 | 결과 |
|---|---|---|
| `border-style` 없을 때의 폭 | Chrome 151 headless · `--dump-dom` + `getComputedStyle` | `none`/`hidden` 둘 다 계산값 `0px` · `solid` 만 `8px` |
| 그때의 상자 치수 | `getBoundingClientRect()` | 232×32 대 248×48 |
| `border-radius` 비례 축소 | 150/120/100 세 판을 렌더해 40,000 픽셀 전수 비교 | 150↔100 은 2픽셀, 120↔100 은 279픽셀만 다름 — 전부 곡선 경계 |
| 같은 것의 계산값 | `getComputedStyle().borderRadius` | `"150px"` — **축소 미반영** |
| 실효 반지름 | 45도 대각선에서 첫 불투명 픽셀 | 세 판 모두 `d = 30` |
| `/` 두 반지름 | 위 변·왼 변의 첫 불투명 픽셀 좌표 | `60/20` → (59, 20) · `20/60` → (20, 60) |
| `border-radius` 가 배경을 자르는가 | 모서리 픽셀 `(0,0)` | `(255,255,255)` 페이지 배경 — 상자색 아님 |
| `border-radius` 가 자손을 자르는가 | 네모난 자식을 넣고 모서리 픽셀 | 기본 `(220,38,38)` 자식색 · `overflow:hidden` 이면 `(255,255,255)` |
| `outline` 의 레이아웃 공간 | 이웃 `rect.left` 대조 | `border` 122 대 `outline` 106 — **0** |
| `box-shadow` 의 레이아웃 공간 | 같은 실험 세 번째 행 | `outline` 과 동일(80/80) |
| 스크롤 영역 | 120px 스크롤 상자 안 200px 자식 | 그림자·테 60px → 200 유지 · `border` 60px → 260 |
| `outline` 이 둥근가 | 반지름 50 상자의 모서리·대각선 픽셀 | 모서리 `(255,255,255)` · 대각선 `d=10` 에서 고리 |
| `outline-offset` | 12px 오프셋 판의 픽셀·좌표 | `x=185` 초록 · `x=192` 흰 빈 자리 · 이웃 좌표 불변 |
| 그림자 순서 | 두 판의 `x=32`·`x=20` 픽셀 | 먼저 쓴 것이 위 — 빨강 먼저면 파랑이 안 보임 |
| `spread`·`inset` | 15px 띠의 경계 좌표 | 바깥 15px 에서 딱 끊김 · `inset` 은 바깥이 흰색 |
| 무효 선언 | 「진단 3창」 | `cssRules` 에서 두 선언이 사라짐 · 규칙은 생존 |
| demo 3개 | 각 블록을 `<!doctype>`·`<body>` 래퍼에 넣어 렌더 + 픽셀 대조 | 「보이는 것」·「바꿔 볼 것」 단언 전부 화면과 일치 |

**구현 의존 항목** — ①`getComputedStyle().borderRadius` 가 축소 **전** 값을 돌려주는 것 ②`outline` 이 `border-radius` 를 따라 **둥글게** 도는 것 ③곡선 경계의 **정확한 중간색**. 셋 다 Chrome 151 에서 관찰한 것이고, 특히 ③은 `--disable-gpu` **소프트웨어 렌더링** 결과라 GPU 합성과 다를 수 있다.\
**엔진은 Chrome 하나다.** Firefox 155.0.1 은 이 환경에서 headless 스크린샷이 산출되지 않고 WebKit 은 이 머신에 없다 — **「두 엔진에서 확인했다」고 적지 않았다.** 크로스 브라우저는 Baseline 데이터로만 접지했다(webstatus.dev 조회 2026-09-23: `border-radius`·`box-shadow` widely 2015-07-29/2018-01-29 · `outline` widely 2023-03-27/2025-09-27).
