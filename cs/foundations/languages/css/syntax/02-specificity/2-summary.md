# css/syntax/02 — 명시도 계산: (ID, 클래스, 타입) 세 자리와 무엇이 어디에 기여하나 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [Selectors Level 4 §Calculating a selector's specificity](https://drafts.csswg.org/selectors-4/#specificity-rules) · [CSS Cascade 5](https://drafts.csswg.org/css-cascade-5/) (명시도가 캐스케이드의 5단계라는 것). 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 `demo` 블록 **3개 전부**와 아래 「손으로 세어 보기」 표의 **16행 전부**를 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워 확인했다.\
> 표의 검증 방법은 그 절에 적어 두었다(동점 경쟁자 · 한 칸 낮은 경쟁자 양방향 대조).\
> **WebKit(Safari)은 이 머신에 없다** — Safari 관련 서술은 하지 않았다.
> **버전** — CSS 에 언어 버전은 없다. 여기 나오는 선택자의 Baseline(목록 README 의 지원 표): `:where()` **widely**(2021-01-21 → 2023-07-21) · `:has()` **widely**(2023-12-19 → 2026-06-19) · `:nth-child(… of S)` **widely**(2023-05-09 → 2025-11-09).
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 숫자는 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**명시도 = 금화·은화·동화 세 종류로 받은 점수다. 그리고 환전소가 없다.**

비유 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 금화 | **A 자리** — ID 선택자(`#id`)의 개수 |
| 은화 | **B 자리** — 클래스·속성 선택자·의사 클래스의 개수 |
| 동화 | **C 자리** — 타입 선택자·의사 요소의 개수 |
| 환전소가 없다 | 자리끼리 **올림이 없다** — 동화를 아무리 모아도 은화 하나가 안 된다 |
| 승부 판정 | 금화부터 세고, 같으면 은화, 그래도 같으면 동화 |

- 두 선택자를 비교할 때는 **금화 개수부터** 본다.\
  금화가 하나라도 많으면 **은화·동화는 세지도 않는다.**
- `.a.b.c.d.e.f.g.h.i.j`(은화 10개)는 `#x`(금화 1개)를 **못 이긴다.**\
  "256개 모으면 넘어간다" 같은 규칙은 없다 — 환전소가 없기 때문이다.
- 그래서 명시도는 **큰 수 하나가 아니라 세 칸짜리 순서쌍** `(A, B, C)` 으로 적는다.

```text
     A(금화)   B(은화)   C(동화)
      ID      클래스류   타입류

#nav .item a        (1, 1, 1)
.item .item a       (0, 2, 1)
a                   (0, 0, 1)

비교: A 부터 왼쪽으로            (1,1,1) > (0,2,1) > (0,0,1)
      A 가 갈리면 B·C 는 안 본다   ^ 여기서 이미 끝났다
```

실무에서 이게 터지는 자리는 **컴포넌트 라이브러리를 덮어쓸 때**다.\
라이브러리가 `#app .btn` 으로 썼으면 내 `.btn.btn-primary` 는 은화를 아무리 모아도 못 이기고, 결국 나도 ID 를 끌어오거나 `!important` 를 붙이게 된다.

> **명시도(specificity)** — 선택자 하나가 캐스케이드 5단계에서 갖는 세기. `(A, B, C)` 세 자리로 센다.\
> 예: `#nav .item a` 는 `(1, 1, 1)`, `a` 는 `(0, 0, 1)`.

> **선택자(selector)** — 어떤 요소에 이 규칙을 걸지 고르는 식.\
> 예: `#nav .item a` 는 "`#nav` 안의 `.item` 안의 `a`"를 고른다.

> **의사 클래스(pseudo-class)** — 요소의 상태나 위치를 가리키는 `:` 로 시작하는 선택자.\
> 예: `:hover`(마우스가 올라간)·`:nth-child(2)`(둘째 자식)·`:has(img)`(이미지를 가진).

> **의사 요소(pseudo-element)** — 문서에 없는 가상의 상자를 가리키는 `::` 로 시작하는 선택자.\
> 예: `::before`(요소 안 맨 앞에 끼워 넣는 상자)·`::first-line`(첫 줄).

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. 임의의 선택자를 받아 **`(A, B, C)` 로 손계산**할 수 있는가.
2. `:is()`·`:not()`·`:has()`·`:where()` 처럼 **안에 선택자를 담는 것**들은 몇을 보태는가.
3. 명시도를 **올리지 않고** 이기는 방법은 무엇인가 — 그리고 그것이 왜 더 나은가.

## 동작 방식

### (1) 세 자리 세기 — 무엇이 어느 자리에 들어가나

**언제 쓰나** — 선택자 두 개 중 어느 쪽이 이길지 판정할 때마다.

```text
선택자를 왼쪽부터 훑으며 부품을 세 바구니에 던져 넣는다

   #nav  >  ul.menu  li:first-child  a[href^="/"]::before
     |         |  |     |     |        |    |        |
     v         v  v     v     v        v    v        v
   A:[#nav]   C:[ul]  B:[.menu]  C:[li]  B:[:first-child]
                                  C:[a]  B:[href^="/"]  C:[::before]

   A = 1      B = 3      C = 4        ->  (1, 3, 4)
```

| 자리 | 여기 들어가는 것 | 예 |
|---|---|---|
| **A** | ID 선택자 | `#nav` |
| **B** | 클래스 · 속성 선택자 · 의사 클래스 | `.menu` · `[href^="/"]` · `:first-child` · `:hover` |
| **C** | 타입 선택자 · 의사 요소 | `div` · `li` · `::before` · `::first-line` |
| **0** | 전체 선택자 `*` · 조합자(`>` `+` `~` 공백) · `:where()` | 아무 자리에도 안 보탠다 |

그림 해설 (한 단계씩):

- **조합자는 0 이다.** `.a .b` 와 `.a > .b` 는 명시도가 같다 — 어떻게 이어졌는지는 세지 않는다.
- **같은 부품이 반복돼도 각각 센다.** `p.c1.c1.c1` 은 `(0, 3, 1)` 이다(같은 클래스를 세 번 썼어도 3).\
  *(Chrome 151 headless 로 `(0,3,1)` 임을 실측 확인했다 — 아래 표 16행 참고.)*
- **속성 선택자는 B 다.** `[id="nav"]` 는 `#nav` 와 **같은 요소를 고르지만 명시도는 `(0,1,0)`** 으로 다르다.

비용 — 없다. 계산 자체는 문자열을 훑는 일이고, 브라우저는 규칙을 파싱할 때 한 번 계산해 둔다.

### (2) 비교는 앞자리부터, 올림이 없다

**언제 쓰나** — 두 선택자가 같은 요소·같은 속성을 두고 붙었을 때(그리고 캐스케이드 1~4단계가 동점일 때).

```text
             A   B   C
  후보 1  (  0,  3,  0 )     .a.b.c
  후보 2  (  1,  0,  0 )     #x
             ^
             여기서 1 > 0 으로 갈린다 -> B, C 는 보지 않는다

  당선: 후보 2

  B 를 300개로 늘려도 결과는 같다:
  (0, 300, 0)  <  (1, 0, 0)        환전소가 없다
```

```html demo
<p id="x" class="a b c">ID 하나 대 클래스 셋</p>
<style>
  .a.b.c { color: #15803d; }  /* (0,3,0) */
  #x     { color: #b91c1c; }  /* (1,0,0) */
  p { font: 20px/1.6 system-ui, sans-serif; }
</style>
```

> **보이는 것** — 줄이 **빨강(#b91c1c)** 으로 나온다. 클래스를 셋 겹쳐도 ID 하나를 못 이긴다. `.a.b.c` 를 나중에 썼는데도 진다 — 등장 순서(6단계)는 명시도(5단계)가 갈리면 불리지 않는다.\
> **바꿔 볼 것** — `#x` → `[id="x"]` → **초록**이 된다(속성 선택자는 B 자리라 `(0,1,0)`, 같은 요소를 고르는데 세기가 달라진다) · `.a.b.c` → `.a.b.c.a.b.c.a.b.c` → 여전히 빨강

*(Chrome 151 headless 실측: 원본 `rgb(185, 28, 28)` / `[id="x"]` 로 바꾼 판 `rgb(21, 128, 61)`.)*

비용 — 없다. 다만 **A 자리를 한 번 쓰면 그 선택자 계열 전체가 A 자리로 올라간다** — 덮으려는 사람도 ID 를 끌어와야 하고, 그러면 다시 그 위를 덮을 사람도 그래야 한다.

### (3) 안에 선택자를 담는 의사 클래스 — 가장 센 인자로 치환된다

**언제 쓰나** — `:is()`·`:not()`·`:has()` 를 쓸 때. 셋 다 규칙이 같다.

명세는 이 셋의 명시도를 **인자 목록 중 가장 센 것으로 바꿔 넣는다**고 정한다.

```text
  p:is(#t1, .c1)

   ┌ p        C +1              (0, 0, 1)
   └ :is(...) 인자 중 가장 센 것 = #t1  (1, 0, 0)
                              합 =  (1, 0, 1)

  ★ :is() 자신은 세지 않는다 — 껍데기는 0 이고 안의 것으로 치환된다
  ★ "가장 센"은 목록 전체에서 하나. .c1 은 무시된다
```

```html demo
<div id="box"><p class="t">이 줄은 무슨 색일까?</p></div>
<style>
  :is(#box) .t    { color: #b91c1c; }  /* (1,0,0) + (0,1,0) = (1,1,0) */
  :where(#box) .t { color: #15803d; }  /* (0,0,0) + (0,1,0) = (0,1,0) */
  p { font: 20px/1.6 system-ui, sans-serif; }
</style>
```

> **보이는 것** — 줄이 **빨강(#b91c1c)** 으로 나온다. `:where()` 로 감싼 초록 규칙이 **더 나중에 쓰였는데도 진다** — `:where()` 안의 ID 가 명시도에 0 을 보태기 때문이다.\
> **바꿔 볼 것** — `:is(#box)` → `:where(#box)` → 둘 다 `(0,1,0)` 동점이 되어 **나중에 쓴 초록이 이긴다**(6단계 등장 순서로 내려간다)

*(Chrome 151 headless 실측: 원본 `rgb(185, 28, 28)` / 양쪽 `:where` 로 바꾼 판 `rgb(21, 128, 61)`.)*

`:not()` 도 같은 규칙이다 — 그리고 여기가 가장 조용히 틀리는 자리다.

```html demo
<p class="t">이 줄은 무슨 색일까?</p>
<style>
  .t.t.t            { color: #15803d; }  /* (0,3,0) */
  p:not(.zz, #nope) { color: #b91c1c; }  /* (0,0,1) + 가장 센 인자 (1,0,0) = (1,0,1) */
  p { font: 20px/1.6 system-ui, sans-serif; }
</style>
```

> **보이는 것** — 줄이 **빨강(#b91c1c)** 으로 나온다. `#nope` 라는 ID 는 **문서에 존재하지도 않고** `:not()` 안에서 "제외 대상"으로만 쓰였는데, 그 ID 하나가 A 자리에 1 을 올려 클래스 셋을 이긴다.\
> **바꿔 볼 것** — `#nope` → `.nope` → `(0,1,1)` 이 되어 **초록**이 이긴다 · `p:not(...)` → `p:where(:not(.zz, #nope))` → `(0,0,1)` 이 되어 초록

*(Chrome 151 headless 실측: 원본 `rgb(185, 28, 28)` / `.nope` 로 바꾼 판 `rgb(21, 128, 61)`.)*

그림 해설 (한 단계씩):

- `:is()`·`:not()`·`:has()` 는 **껍데기 값이 0** 이고, 안의 목록 중 가장 센 것의 값을 그대로 쓴다.
- 그래서 **목록에 강한 것 하나를 편의상 끼워 넣으면 전체가 그만큼 세진다.**\
  `:is(h1, h2, h3, #legacy)` 를 쓰는 순간 그 규칙은 `(1,0,0)` 짜리가 된다.
- `:has()` 도 같다 — `p:has(+ p#t2)` 는 `(1, 0, 2)` 다(바깥 `p` 1, 인자 안의 `p` 1, 인자 안의 `#t2` 가 A 자리 1).\
  *(Chrome 151 headless 로 `(1,0,2)` 임을 실측 확인했다.)*

비용 — 없다. 대신 **선택자를 읽는 사람이 인자 목록까지 봐야 세기를 알 수 있게 된다.**

### (4) `:where()` — 세기를 0 으로 눌러 두는 유일한 장치

**언제 쓰나** — "이 규칙은 누구나 쉽게 덮을 수 있어야 한다"고 선언하고 싶을 때. 라이브러리·리셋 시트의 기본값.

```text
  :is(#box) .t     ->  (1, 1, 0)      덮으려면 ID 를 끌어와야 한다
  :where(#box) .t  ->  (0, 1, 0)      클래스 하나로 덮을 수 있다
       ^^^^^^
       안에 무엇이 들어가든 0. #id 든 100줄짜리 목록이든 0.
```

- `:where()` 는 **명시도 기여만 0** 이고, 매칭은 `:is()` 와 똑같이 한다.
- 그래서 "이 요소를 고른다"와 "세게 고른다"를 **분리하는 유일한 문법**이다.
- 이것과 `@layer`(캐스케이드 4단계)가 오늘날 명시도 전쟁을 끝내는 두 도구다. 레이어는 [01번 주제](../01-cascade-and-priority/2-summary.md)가 정본.

### (5) `:nth-child(An+B of S)` — 자신 + S

**언제 쓰나** — `of S` 형태를 쓸 때. 이 형태만 규칙이 하나 더 있다.

```text
  p:nth-child(1 of .c1)

   ┌ p                 C +1                    (0, 0, 1)
   ├ :nth-child()      B +1 (의사 클래스)       (0, 1, 0)
   └ of .c1            S 의 명시도 그대로        (0, 1, 0)
                                       합 =    (0, 2, 1)

  of 절이 없으면 :nth-child(1) 은 그냥 (0, 1, 1)
```

*(Chrome 151 headless 실측: `p:nth-child(1 of .c1)` = `(0,2,1)`, `p:nth-child(1 of .c1.c2)` = `(0,3,1)`, `p:nth-child(1)` = `(0,1,1)`.)*

이 선택자 자체는 [목록의 **09번 주제**](../09-structural-pseudo-classes/)가 정본이고, 여기서는 **명시도 규칙만** 다룬다.

### (6) 명시도가 아예 없는 것들

**언제 쓰나** — "명시도를 올려도 안 먹는다"를 진단할 때.

| 것 | 명시도 | 어디서 판정되나 |
|---|---|---|
| `style=""` 속성 | **없음** (선택자가 없다) | 캐스케이드 **3단계** — 명시도보다 위 |
| `!important` | **안 올린다** | 캐스케이드 **1단계** — 명시도보다 위 |
| `@layer` | **안 올린다** | 캐스케이드 **4단계** — 명시도보다 위 |
| 선택자 목록 `.a, #b` | **따로 센다** | 쉼표로 나뉜 각 선택자가 자기 명시도를 갖는다 |

- 앞의 셋은 전부 **명시도를 계산하기 전에** 승부를 낸다. 정본은 [01번 주제](../01-cascade-and-priority/2-summary.md).
- 네 번째가 이 주제 고유의 규칙이다 — **`h1, #x { }` 는 `(1,0,0)` 짜리 규칙이 아니다.**\
  `h1` 에 매치될 때는 `(0,0,1)`, `#x` 에 매치될 때는 `(1,0,0)` 이다. **규칙이 아니라 매치된 선택자의 명시도**를 쓴다.

### (7) 손으로 세어 보기 — 16행을 브라우저로 핀 고정했다

**언제 쓰나** — 표를 외우는 게 아니라, 내가 센 값이 맞는지 대조할 때.

**검증 방법** — 각 선택자를 다음 두 판으로 돌렸다.

```text
판 1 (동점 검사)                        판 2 (한 칸 낮음 검사)
+--------------------------------+     +--------------------------------+
| 검사 대상   { color: rgb(1,1,1)}|     | 검사 대상   { color: rgb(1,1,1)}|
| (A,B,C) 경쟁자 { rgb(2,2,2) }   |     | 한 칸 낮은 경쟁자 { rgb(2,2,2) }|
|   <- 뒤에 썼다                  |     |   <- 뒤에 썼다                  |
+--------------------------------+     +--------------------------------+
 기대: 동점이므로 순서로 갈려          기대: 검사 대상이 더 세므로
       경쟁자가 이긴다 rgb(2,2,2)            검사 대상이 이긴다 rgb(1,1,1)

 두 판이 모두 기대대로면 (A,B,C) 가 위아래로 고정된다.
 경쟁자는 #t1 반복 · .c1.c2… 반복 · html body div p 사슬로 기계 생성했다.
```

16행 전부 두 판을 통과했다(Chrome 151.0.7922.173 headless).

| 선택자 | (A, B, C) | 왜 |
|---|---|---|
| `*` | (0, 0, 0) | 전체 선택자는 아무 자리에도 안 보탠다 |
| `p` | (0, 0, 1) | 타입 하나 |
| `#t1` | (1, 0, 0) | ID 하나 |
| `[id="t1"]` | (0, 1, 0) | **속성 선택자는 B** — 같은 요소를 골라도 세기가 다르다 |
| `p.c1` | (0, 1, 1) | 타입 1 + 클래스 1 |
| `p.c1.c1.c1` | (0, 3, 1) | 같은 클래스를 반복해도 **각각 센다** |
| `p::before` | (0, 0, 2) | **의사 요소는 C** (의사 클래스가 아니다) |
| `p:nth-child(1)` | (0, 1, 1) | 의사 클래스는 B |
| `p:nth-child(1 of .c1)` | (0, 2, 1) | 의사 클래스 B + `of` 의 `.c1` B |
| `p:nth-child(1 of .c1.c2)` | (0, 3, 1) | `of` 의 명시도가 통째로 더해진다 |
| `p:is(#t1, .c1)` | (1, 0, 1) | 인자 중 **가장 센 것**(`#t1`)으로 치환 |
| `:is(p, #t1)` | (1, 0, 0) | 바깥에 아무것도 없어도 인자가 A 를 올린다 |
| `p:where(#t1, .c1)` | (0, 0, 1) | `:where()` 는 **0** — 안의 ID 가 사라진다 |
| `p:not(.zz, #nope)` | (1, 0, 1) | `:not()` 도 가장 센 인자로 치환 — **없는 ID 도 센다** |
| `p:has(+ p#t2)` | (1, 0, 2) | 바깥 `p` 1 + 인자의 `p` 1 + 인자의 `#t2` |
| `section:is(div section) p` | (0, 0, 4) | `section`1 + `:is(div section)`2 + `p`1 |

비용 — 없다. 이 표를 외우는 것이 목적이 아니라, **"어느 자리에 들어가나"만 알면 전부 유도된다**는 것을 확인하는 것이 목적이다.

## 문법 — 형태와 규칙

직접 쓴 최소 예제다. 묻는 것 하나만 남겼다.

### 표기법

```text
(1, 2, 0)      이 문서가 쓰는 표기 — 세 칸 순서쌍
1-2-0          같은 뜻으로 쓰이는 표기
0,1,2,0        네 칸으로 쓰는 옛 표기 (맨 앞이 style="") — 이제 안 쓴다
120            ★ 이렇게 한 수로 붙이면 안 된다 — 올림이 없어서 수가 아니다
```

- 네 칸 표기가 사라진 이유는 `style=""` 가 **명시도가 아니라 캐스케이드 3단계**로 정리됐기 때문이다.

### 세기가 같을 때

```css
.a { color: red; }
.b { color: blue; }     /* 나중 — 이긴다 */
```

- `(0,1,0)` 동점이면 6단계(등장 순서)로 내려간다.
- **파일 순서가 바뀌면 결과가 바뀐다.** 번들러 설정 하나로 색이 달라질 수 있다.

### 세기를 0 으로 눌러 쓰기

```css
/* 라이브러리가 제공하는 기본값 — 누구나 클래스 하나로 덮을 수 있다 */
:where(.card) :where(h2, h3) { margin-block: 0; }

/* 같은 매칭, 덮기 어려움 */
.card h2, .card h3 { margin-block: 0; }   /* (0,1,1) */
```

- 위쪽은 `(0, 0, 0)` 이다 — 같은 요소를 고르지만 **아무 규칙에나 진다.**
- 리셋 시트·디자인 시스템 기본값이 이 형태를 쓰는 이유다.

## 어디서 틀리나

이 주제의 값어치는 전부 여기 있다. 여섯 다 **에러 없이 조용히 어긋난다.**

### 1. 자리끼리 올림이 있다고 생각한다

```text
잘못된 모델                              실제
+------------------------------+        +------------------------------+
| ID=100, 클래스=10, 타입=1     |        | (1, 0, 0)  vs  (0, 300, 0)   |
| 한 수로 더해서 비교           |        | A 부터 본다 — 300 은 안 본다  |
| 10개 모으면 100이 되나?       |        | 환전소가 없다                 |
+------------------------------+        +------------------------------+
```

`100/10/1` 모델은 **답이 자주 맞아서** 오래 살아남았다. 클래스를 10개 이상 겹치는 일이 드물기 때문이다.\
깨지는 자리는 자동 생성된 유틸리티 클래스가 길게 붙을 때다.

### 2. `:not()` 안의 강한 선택자를 세지 않는다

```css
.card:not(#legacy) { padding: 8px; }   /* (1, 1, 0) — ID 가 문서에 없어도 A=1 */
```

`#legacy` 가 문서에 아예 없어도 A 자리는 올라간다.\
**"제외했으니 안 세겠지"가 틀린다** — 명시도는 매칭 결과가 아니라 **선택자의 모양**만 본다.

### 3. `:is()` 목록에 강한 것 하나를 끼워 넣는다

```css
:is(h1, h2, h3, #hero-title) .sub { ... }   /* (1, 1, 0) */
```

`h1`·`h2`·`h3` 에 매치될 때도 `(1,1,0)` 이다 — **가장 센 인자가 목록 전체의 값**이 된다.\
섞기 싫으면 `:where()` 로 감싸거나 규칙을 쪼갠다.

### 4. 속성 선택자와 ID 선택자를 같은 것으로 본다

```css
#nav      { ... }   /* (1, 0, 0) */
[id="nav"]{ ... }   /* (0, 1, 0) */
```

**고르는 요소는 같고 세기는 다르다.**\
반대로 이것을 **의도적으로 쓰면** ID 를 쓰면서도 세기를 클래스 수준으로 낮출 수 있다.

### 5. 선택자 목록의 명시도를 하나로 본다

```css
h1, #x { color: red; }
```

`h1` 요소에 걸릴 때 이 규칙의 명시도는 `(0,0,1)` 이다. `(1,0,0)` 이 아니다.\
**매치된 선택자별로 따로 센다.**

### 6. 명시도로 해결할 수 없는 문제를 명시도로 푼다

```text
증상: 선택자를 늘려도 안 먹는다
      ↓
진짜 원인 후보 (전부 명시도보다 위 단계)
  1단계  상대가 !important 다
  3단계  요소에 style="" 가 있다
  4단계  상대가 더 나중 레이어에 있다 / 내 규칙만 레이어 안에 있다
```

명시도를 올리는 것은 **5단계에서만 효과가 있다.** 진단 순서는 [01번 주제](../01-cascade-and-priority/2-summary.md)에 있다.

## 구현 세부사항 대 언어 보장

| 항목 | 누가 보장하나 |
|---|---|
| A·B·C 세 바구니에 **무엇이 들어가나** | **명세**(Selectors 4 §15 — ID 를 세어 A, 「클래스·속성 선택자·의사 클래스」를 세어 B, 「타입 선택자·의사 요소」를 세어 C, 전체 선택자는 무시) |
| 자리끼리 **올림이 없는 것** | **명세** — 같은 절이 세 수를 「하나의 수」로 합치라고 하지 않는다. `(0, 300, 0)` 이 `(1, 0, 0)` 에 지는 것은 관찰이 아니라 정의다 |
| `:is()`·`:not()`·`:has()` 가 **가장 센 인자로 치환**되는 것 | **명세**(같은 절 — 「replaced by the specificity of the most specific complex selector in its selector list argument」) |
| `:where()` 가 **0** 인 것 | **명세**(같은 절 — 「replaced by zero」) |
| `:nth-child(An+B of S)` 가 **자신 + S** 인 것 | **명세**(같은 절). 명세가 든 예 `:nth-child(even of li, .item)` = `(0,2,0)` 이 본문의 `(0,2,1)` 계산과 같은 규칙이다 |
| 선택자 목록(`h1, #x`)을 **따로 세는 것** | **명세** — 다만 문구가 한 걸음 더 정밀하다: 「매치되는 것 중 **가장 센 것**」이다(「the specificity in effect is that of the most specific selector in the list that matches」). 한 요소가 `h1` 과 `#x` 에 **동시에** 매치되면 `(1,0,0)` 쪽이 쓰인다 |
| 문서에 없는 `#nope` 도 A 를 올리는 것 | **명세** — 명시도는 「a given element 에 대해 계산」하지만 **세는 대상은 선택자의 모양**이고, 매치 여부를 세라는 말이 어디에도 없다 |
| ★ **명시도를 직접 읽는 창이 없는 것** | ★ **CSSOM 의 한계다.** `getComputedStyle` 은 **이긴 값**만 주고 `cssRules[i]` 에도 명시도 필드가 없다. 이 문서의 16행은 전부 **「이겼나 졌나」로 되짚은 것**이지 잰 것이 아니다 |
| ★ `(0, 0, 0)` 의 **아래쪽을 못 고정한 것** | ★ **못 잰 것.** 두 판 방법은 「동점 경쟁자」와 「한 칸 낮은 경쟁자」로 위아래를 죄는데, `*` 는 **더 낮은 경쟁자가 존재하지 않는다.** 그래서 `*` 행만 「`(0,0,1)` 을 앞에 써도 그쪽이 이긴다」는 **위쪽 한 방향**으로만 고정했다 |
| 색이 `rgb(185, 28, 28)` 형태로 보이는 것 | ★ **CSSOM 직렬화**이지 언어가 아니다 |
| 개발자 도구가 선택자 옆에 `(1,2,0)` 을 띄워 주는 것 | ★ **도구의 기능**이다. 「더 알면 좋은 것」이 그것을 권하지만, **언어가 노출하는 API 가 아니다** |
| 중첩(`& .x`)이 `:is()` 로 감싸지며 명시도를 올리는 것 | ★ **이 문서에서 재지 않았다** — 정본은 [목록의 **14번 주제**](../14-css-nesting/) |

★ **「계산값 이후에서 갈리는」 자리는 이 주제에 없다.** 명시도 싸움의 결과는 전부 계산값에 나타난다.\
갈리는 것은 그 앞이다 — **매치가 없으면 애초에 잴 수가 없다.** 이 문서의 16행은 전부 매치가 있는 선택자라 잴 수 있었지만, `.panel:has(#legacy-root)` 처럼 **문서에 매치가 없는 선택자는 이 방법으로 못 잰다.**

★ **엔진은 Chrome 하나다.** Firefox 155 는 이 환경에서 headless 산출이 조용히 실패하고 WebKit 은 이 머신에 없다 — **「두 엔진에서 확인했다」고 적지 않았다.** 크로스 브라우저는 Baseline 데이터로만 접지했다(api.webstatus.dev 조회 2026-09-23: `is`·`where`·`not` **widely** 2021-01-21 → 2023-07-21 · `has` **widely** 2023-12-19 → 2026-06-19 · `nth-child-of` **widely** 2023-05-09 → 2025-11-09).

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 라이브러리·리셋의 기본값 | `:where(...)` 로 `(0,0,0)` | `.lib .card h2` 같은 긴 선택자 |
| 컴포넌트 내부 스타일 | 클래스 하나 `(0,1,0)` 로 평평하게 | ID · 자손 사슬 |
| 남의 시트를 통째로 아래에 깔기 | `@layer` (4단계) | 내 선택자 길이 늘리기 |
| 여러 태그를 한 번에 고르기 | `:is(h1, h2, h3)` (전부 같은 급일 때) | 강한 것 하나를 목록에 섞기 |
| ID 가 이미 마크업에 있다 | `[id="nav"]` 로 세기를 낮춰 쓰기 | `#nav` 로 A 자리 올리기 |
| 상태 예외 하나 | 같은 자리 수에서 순서로 | `!important` |

판단 규칙 두 줄.

- **명시도는 올리는 것이 아니라 평평하게 유지하는 것이다.** 한 번 올리면 그 위를 덮을 사람도 올려야 한다.
- **"세게 고르고 싶다"와 "그 요소를 고르고 싶다"를 분리하라** — 후자는 `:where()` 로 표현할 수 있다.

## 핵심 문장

- 명시도는 **`(A, B, C)` 세 칸 순서쌍**이고, 자리끼리 **올림이 없다** — 클래스를 아무리 모아도 ID 하나를 못 이긴다.
- 비교는 **A 부터**다. A 에서 갈리면 B·C 는 계산되지도 않는다.
- `:is()`·`:not()`·`:has()` 는 **인자 목록 중 가장 센 것의 명시도로 치환**된다 — `:not()` 안의 ID 는 문서에 없어도 센다.
- `:where()` 만이 **기여를 0 으로 만든다** — 매칭은 하되 세기는 포기하는 유일한 문법.
- 선택자 목록(`a, b`)은 **매치된 선택자별로 따로** 센다. 규칙 하나의 명시도라는 것은 없다.
- 명시도는 캐스케이드 **5단계**다 — `!important`(1단계)·`style=""`(3단계)·`@layer`(4단계)는 그 위에서 이미 끝난다.

## 용어 풀이

- **명시도(specificity)** — 선택자가 캐스케이드 5단계에서 갖는 세기. `(A, B, C)` 세 자리.
- **A 자리** — ID 선택자(`#id`)의 개수.
- **B 자리** — 클래스(`.c`) · 속성 선택자(`[x]`) · 의사 클래스(`:hover`)의 개수.
- **C 자리** — 타입 선택자(`div`) · 의사 요소(`::before`)의 개수.
- **올림이 없다** — 자리끼리 교환이 안 된다는 뜻. `(0, 300, 0) < (1, 0, 0)`.
- **타입 선택자(type selector)** — 태그 이름으로 고르는 선택자. `div`·`p`·`a`.
- **속성 선택자(attribute selector)** — 속성으로 고르는 선택자. `[href]`·`[id="x"]`·`[class^="btn"]`.
- **의사 클래스(pseudo-class)** — `:` 하나로 시작. 상태·위치를 가리킨다. B 자리.
- **의사 요소(pseudo-element)** — `::` 둘로 시작. 문서에 없는 가상 상자를 가리킨다. C 자리.
- **조합자(combinator)** — 선택자를 잇는 기호. 공백(자손)·`>`(자식)·`+`(인접 형제)·`~`(일반 형제). **0 이다.**
- **선택자 목록(selector list)** — 쉼표로 나열한 선택자들. 명시도는 매치된 것 하나만 센다.
- **`:where()`** — 안의 선택자로 매칭하되 명시도 기여를 0 으로 만드는 의사 클래스.
- **`:is()` / `:not()` / `:has()`** — 안의 목록 중 **가장 센 것**의 명시도를 그대로 갖는 의사 클래스.

  손계산이 안 맞으면 **먼저 거기서 대조**한다 — 이 문서의 16행 표도 같은 방식(브라우저에 물어보기)으로 만들었다.
- 명시도를 **내리는** 방향의 문법은 `:where()` 하나뿐이다.\
  `@layer`(4단계)와 `@scope` 의 근접성(4.5단계 격)은 명시도를 내리는 게 아니라 **명시도를 보기 전에 갈라 버리는** 장치다(목록의 [**05**](../05-cascade-layers/)·[**06**](../06-scope/)번).
- CSS 중첩(nesting)에서 `& .x` 를 쓰면 부모 선택자가 `:is(...)` 로 감싸져 들어간다.\
  그래서 **부모 목록에 강한 것이 하나라도 있으면 중첩된 자식 규칙의 명시도가 조용히 올라간다**([목록의 **14번 주제**](../14-css-nesting/)).
- `:has()` 안에 `:has()` 를 넣을 수 없는 것은 명시도 규칙이 아니라 매칭 제약이다([목록의 **12번 주제**](../12-has-relational-selector/)).
- 명시도 전쟁을 언어 기능으로 끝내는 조합은 오늘 기준 **`@layer` + `:where()`** 다.\
  BEM·ITCSS 같은 명명 방법론은 같은 문제를 **관례**로 풀던 시절의 도구다(목록 README 의 「뺀 것과 이유」).
