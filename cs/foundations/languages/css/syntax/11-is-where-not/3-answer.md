# css/syntax/11 — `:is()`·`:where()`·`:not()` 와 명시도 — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **모든 `(A, B, C)` 값과 모든 개수·색은 Google Chrome 151.0.7922.173 headless 에서 실제로 돌려 받은 것**이다.\
> 명시도는 **동점 경쟁자 · 한 칸 낮은 경쟁자 두 판**으로 위아래를 고정했고(방법은 [02번 2-summary](../02-specificity/2-summary.md) 「손으로 세어 보기」), 매칭은 `querySelectorAll().length`, 규칙 생존은 `cssRules` 로 읽었다.\
> **명시도 계산 규칙 자체의 정본은 [02번 주제](../02-specificity/2-summary.md)** 다. 여기서는 **이 셋이 그 계산에 무엇을 넣는가**만 다룬다.\
> 규칙은 [Selectors Level 4](https://drafts.csswg.org/selectors-4/) 로, 지원 상태는 `api.webstatus.dev` 조회(2026-09-23)로 접지했다. **엔진은 Chrome 하나다.**

## 정답

### 1. 세 껍데기가 값을 부르는 법

**실행 결과** (Chrome 151 headless — 16행 전부 두 판 통과)

```text
  명시도 (두 판 대조)                     매칭 (querySelectorAll)
  p:is(.t, #zz)     ->  (1, 0, 1)        p:is(.t, #zz)     ->  2개  t1, t2
  p:where(.t, #zz)  ->  (0, 0, 1)        p:where(.t, #zz)  ->  2개  t1, t2
  p:not(.zz, #zz)   ->  (1, 0, 1)        p:not(.zz, #zz)   ->  2개  t1, t2
```

**셋의 `(A, B, C)`**

- **`p:is(.t, #zz)` = `(1, 0, 1)`** · **`p:where(.t, #zz)` = `(0, 0, 1)`** · **`p:not(.zz, #zz)` = `(1, 0, 1)`**.

```text
   p:is(.t, #zz)
    ├ p                              (0, 0, 1)
    └ :is(...) 인자 중 가장 센 것 #zz  (1, 0, 0)
                              합 =   (1, 0, 1)

   p:where(.t, #zz)
    └ :where(...) 무엇이 들어가든 0   (0, 0, 0)
                              합 =   (0, 0, 1)
```

**셋은 각각 몇 개를 잡는가**

- **셋 다 2개**(`t1`, `t2`)다.

**답이 어느 쪽에서만 갈리는가**

- **명시도에서만** 갈린다. **매칭은 `:is` 와 `:where` 가 완전히 같다.**
- `:not()` 은 이 예제에서 우연히 같은 둘을 잡았을 뿐이고, 모양 규칙은 반대(뒤집기)다.

**껍데기 자신은 얼마를 보태는가**

- **0** 이다. 어느 자리에도 안 보탠다. **안의 목록에서 가장 센 하나를 뽑아 그 자리에 그대로 넣는다.**

### 2. 이 문단은 무슨 색인가

**실행 결과**

```text
  원본                      ->  rgb(185, 28, 28)   = red
  #nope 를 .nope 로 바꾼 판  ->  rgb(21, 128, 61)   = green
  cssRules: ['p:not(.zz, #nope)', 'p:is(.t, .u)', 'p:where(.t, #nope)', 'p']
```

**세 규칙의 `(A, B, C)`**

```text
  p:not(.zz, #nope)   ->  (1, 0, 1)    가장 센 인자가 #nope
  p:is(.t, .u)        ->  (0, 1, 1)    가장 센 인자가 클래스
  p:where(.t, #nope)  ->  (0, 0, 1)    :where 는 0
```

**이 문단은 무슨 색인가**

- **red.** `(1,0,1) > (0,1,1) > (0,0,1)` 이라 **맨 처음에 쓴 `:not()` 이 이긴다.**
- 등장 순서(6단계)는 명시도(5단계)가 갈리면 불리지 않는다.

**진 두 규칙은 `cssRules` 에서 사라졌는가**

- **사라지지 않았다.** 네 규칙 전부 담겨 있다(위 출력).
- ★ 이 구분이 중요하다 — **「규칙이 없다」와 「규칙은 있는데 졌다」는 다른 증상**이고, 6번의 사고와 여기의 승부는 진단법이 다르다.

**`#nope` 를 `.nope` 로 바꾸면**

- **green** 이 된다. `:not()` 이 `(0,1,1)` 로 내려와 `:is()` 와 동점이 되고, **나중에 쓴 초록이 이긴다.**

### 3. 목록에 강한 것 하나를 끼워 넣으면

**실행 결과**

```text
  p:is(.t, #zz, div p)  ->  (1, 0, 1)      매치 2개  t1, t2
  :is(#box) .t          ->  (1, 1, 0)
  :where(#box) .t       ->  (0, 1, 0)
```

**둘의 `(A, B, C)`**

- `:is(h1, h2, h3, #hero) .sub` = **`(1, 1, 0)`** — `#hero` 가 A 를 1 올리고 `.sub` 가 B 를 1.
- `p:is(.t, #zz, div p)` = **`(1, 0, 1)`** (실측).

**`h1` 에 매치될 때와 `#hero` 에 매치될 때 다른가**

- **다르지 않다.** 명시도는 **매치된 인자**가 아니라 **목록에서 가장 센 인자**로 정해진다.
- `h1` 에 걸려도 그 규칙은 `(1,1,0)` 짜리다.

**인자가 셋이면 셋을 다 더하는가**

- **아니다. 하나만 쓴다.** `p:is(.t, #zz, div p)` 가 `(1,0,1)` 인 것이 그 증거다 — `#zz`(1,0,0)와 `div p`(0,0,2)를 합치지 않았다.

**피하려면**

- **`:where()`** 로 감싸거나 **규칙을 쪼갠다.** `:is(h1,h2,h3) .sub` 와 `#hero .sub` 를 따로 쓰는 쪽이 읽기도 낫다.

### 4. 중첩하면 안쪽 값이 어디까지 올라오는가 ★

**실행 결과**

```text
  p:not(:is(#zz))     ->  (1, 0, 1)
  p:is(:where(#t1))   ->  (0, 0, 1)
  p:not(:where(#zz))  ->  (0, 0, 1)
```

**셋의 `(A, B, C)`**

- 위 출력 그대로다.

**어느 것이 ID 를 올려 보내고 어느 것이 끊는가**

```text
   p:not(:is(#zz))      :not -> :is -> #zz     A 가 끝까지 올라온다    (1,0,1)
   p:is(:where(#t1))    :is  -> :where -> #t1  :where 에서 끊긴다      (0,0,1)
   p:not(:where(#zz))   :not -> :where -> #zz  :where 에서 끊긴다      (0,0,1)
```

- **`:is()` 와 `:not()` 은 통과시키고, `:where()` 는 끊는다.**

**`:where()` 가 "벽"이라는 말**

- **어느 깊이에 있든 그 가지의 명시도를 0 으로 만든다**는 뜻이다. 바깥이 `:is` 든 `:not` 이든 상관없다.

**"제외는 하되 명시도는 안 올리고 싶다"면**

- **`:where(:not(#legacy))`** 로 쓴다. 매칭은 그대로 제외하고 명시도는 `(0,0,0)` 이 된다.
- 실측 `p:not(:where(#zz))` = `(0,0,1)` 이 그 형태다(바깥 `p` 의 C 만 남았다).

### 5. 문서에 없는 ID 가 승부를 가른다

**실행 결과**

```text
  p:not(.zz, #zz)  ->  (1, 0, 1)      #zz 는 이 문서에 존재하지 않는다
```

**문서에 `#legacy` 가 없어도 A 자리가 올라가는가**

- **올라간다.** 실측 선택자의 `#zz` 도 문서에 없는 ID 였는데 A=1 이었다.

**이유**

- **명시도는 매칭 결과가 아니라 선택자의 모양만 본다.** 파싱 시점에 한 번 계산되고, 문서에 무엇이 있는지는 보지 않는다.

**매칭 결과인가 모양인가**

- **모양이다.**

**`:is()` 보다 `:not()` 에서 더 조용한 이유**

- `:is()` 안의 것은 「**이것도 고르겠다**」는 뜻이라 눈에 걸린다.
- `:not()` 안의 것은 「**이건 빼겠다**」는 뜻이라 "그럼 안 세겠지"라는 오해가 자연스럽다. **제외 대상이 세기를 올린다**는 것이 직관에 정면으로 어긋난다.

### 6. 관대함 — 모르는 선택자 하나가 어디까지 죽이나 ★

**실행 결과** (일곱 규칙을 주입하고 `cssRules` 를 읽었다)

```text
  넣은 것                                   남은 것
  .t, :unknownzz           { … }            (없음)
  :is(.t, :unknownzz)      { … }            :is(.t)
  :where(.t, :unknownzz)   { … }            :where(.t)
  :not(.zz, :unknownzz)    { … }            (없음)
  :has(.t, :unknownzz)     { … }            (없음)
  :is(:unknownzz)          { … }            :is()
  :is(.t, div::bogus)      { … }            :is(.t)
```

**다섯 중 `cssRules` 에 남는 것**

- 질문의 다섯 중에서는 **둘** — **`:is(.t, :unknownzz)`** 와 **`:where(.t, :unknownzz)`** 다.
- 나머지 셋(맨몸 목록 · `:not()` · `:has()`)은 **규칙째 사라졌다.**

**`selectorText` 는 내가 쓴 그대로인가**

- **아니다.** `:is(.t, :unknownzz)` 는 **`:is(.t)`** 로, `:where(.t, :unknownzz)` 는 **`:where(.t)`** 로 찍혔다.
- 브라우저가 **모르는 인자를 실제로 목록에서 빼고 선택자를 다시 썼다.**

**관대한 것은 어느 둘인가**

- **`:is()` 와 `:where()`** 다. 명세 용어로 이 둘만 `<forgiving-selector-list>` 를 받는다.

**화면만 보고 진단할 수 있는가**

- **없다.** 규칙이 사라진 것과 규칙이 있는데 진 것이 화면에서 똑같이 보인다.
- **`document.styleSheets[*].cssRules` 를 읽어야** 「목록에 아예 없다」가 드러난다.
- 이 문서의 두 번째 `demo` 가 그 실물이다 — **첫 줄이 검은 이유는 화면 어디에도 안 적혀 있다.**

### 7. 인자가 전부 죽으면

**실행 결과**

```text
  :is(:unknownzz) { … }   ->  cssRules 에 남는다, selectorText 는 ':is()'
  document.querySelectorAll(':is(:unknownzz)').length  ->  0
  document.querySelectorAll(':is()').length            ->  0
```

**`cssRules` 에 남는가**

- **남는다.** 관대한 목록이라 규칙 자체는 살아 있다.

**`selectorText` 는 무엇인가**

- **`:is()`** — 빈 껍데기다. 인자가 전부 버려져 목록이 비었다.

**몇 개를 잡는가**

- **0개.** 빈 `:is()` 는 아무것도 안 잡는다.

**"규칙은 살아 있는데 매치가 0개"를 어떻게 진단하는가**

- 진단 순서 셋 중 **두 번째**에서 걸린다.

```text
  (1) cssRules      ->  있다        <- 여기서 "규칙이 죽었나?" 는 아니라고 판명
  (2) querySelectorAll ->  0개      <- 여기가 범인
  (3) getComputedStyle ->  볼 필요 없다
```

- ★ **(1)만 보고 넘어가면 못 잡는다.** 「담겼으니 되겠지」가 틀리는 유일한 형태다.

### 8. `:where()` 로 기본값을 준다

**실행 결과**

```text
  원본                          ->  color rgb(185, 28, 28)  = red
                                    margin-top / margin-bottom = 0px
  :where(.prose) h2 를 .prose h2 로  ->  color rgb(100, 116, 139) = gray
```

**제목은 무슨 색인가**

- **red**(`.lead`).

**두 선택자의 `(A, B, C)`**

- `:where(.prose) h2` = **`(0, 0, 1)`** — `:where()` 가 0 이고 `h2` 가 C 에 1.
- `.lead` = **`(0, 1, 0)`**.
- `(0,1,0) > (0,0,1)` 이므로 **클래스 하나로 기본값을 덮었다.**

**`margin: 0` 은 덮이는가**

- **안 덮인다.** `.lead` 는 `color` 만 선언했으므로 `margin` 은 경쟁자가 없다.
- 실측에서 `margin-top`·`margin-bottom` 이 `0px` 이었다. **같은 규칙에서 한 속성만 덮인 것**이고, 캐스케이드는 **속성별로** 따로 돈다.

**`.prose h2` 로 바꾸면**

- **gray** 로 돌아간다. `(0,1,1) > (0,1,0)` 이라 클래스 하나로는 못 덮는다.

### 9. `:not()` 의 인자 목록은 AND 인가 OR 인가

**실행 결과** (`.a` · `.b` · `.a .b` · 무클래스 네 문단)

```text
  p:not(.a, .b)      ->  1개   무클래스 문단
  p:not(.a):not(.b)  ->  1개   무클래스 문단     (같다)
  p:not(.a)          ->  2개   .b, 무클래스
  p:not(.b)          ->  2개   .a, 무클래스
  p:is(.a, .b)       ->  3개   .a, .b, .a .b
```

**둘은 같은 것을 잡는가**

- **같다.** 둘 다 무클래스 문단 하나만 잡았다.

**`:not(.a, .b)` 를 말로 읽으면**

- **"`.a` 도 아니고 `.b` 도 아닌 것"** — **AND** 다.
- "`.a` 가 아니거나 `.b` 가 아닌 것"으로 읽으면 세 개가 잡혀야 하는데 실측은 1개다.

**`:is(.a, .b)` 의 인자 목록은**

- **OR** 다. 실측 3개 — 둘 중 하나라도 맞으면 잡힌다.

**「모양」이 반대이고 「힘」이 같은 것을 한 문장으로**

- **`:not()` 은 `:is()` 의 매칭을 통째로 뒤집은 것**(OR → 전부 아님)**이고, 명시도 규칙은 그대로 물려받는다**(가장 센 인자).

### 10. 「안 잡혔다」와 「잡혔는데 졌다」

**각각 무엇으로 확인하는가**

```text
  안 잡혔다        ->  document.querySelectorAll(sel).length  가 0
  잡혔는데 졌다     ->  length 는 1 이상인데 getComputedStyle 이 내 값이 아니다
```

**`:is` 를 `:where` 로 바꿨더니 스타일이 사라졌다면**

- **「잡혔는데 졌다」** 쪽이다. `:where()` 는 **매칭을 안 바꾼다.**
- 실측: `p:is(.t, #zz)` 와 `p:where(.t, #zz)` 는 **둘 다 2개**를 잡았고 명시도만 `(1,0,1)` / `(0,0,1)` 로 갈렸다.

**진단 순서 셋**

```text
  (1) cssRules            규칙이 담겼나           <- 무효 선택자·미지원 문법
  (2) querySelectorAll    그 그물에 걸렸나        <- 선택자 모양
  (3) getComputedStyle    그 선언이 이겼나        <- 캐스케이드·명시도
```

**이 셋을 세운 주제**

- [08번 주제](../08-basic-selectors-and-combinators/2-summary.md)다(「한눈에」의 세 줄과 「어디서 틀리나」 6).

### 11. 관대함은 어디까지 공유되나

**실행 결과** (6번의 주입 실험과 [09번](../09-structural-pseudo-classes/2-summary.md)의 `of S` 실험)

```text
  :is(.t, :unknownzz)            ->  남는다 (:is(.t))
  :not(.zz, :unknownzz)          ->  사라진다
  :has(.t, :unknownzz)           ->  사라진다
  :nth-child(2n of :unknownzz)   ->  사라진다
```

**규칙이 살아남는 것**

- **`:is(...)` 하나**다(질문에 없지만 `:where(...)` 도 같다).

**셋이 공유하는 것과 안 하는 것**

| | `:is()` | `:where()` | `:not()` |
|---|---|---|---|
| 명시도 | 가장 센 인자 | **0** | 가장 센 인자 |
| 관대함 | **있다** | **있다** | **없다** |
| 매칭 | OR | OR | 전부 아님 |

- **명시도 규칙은 `:is`/`:not` 이 공유**하고, **관대함은 `:is`/`:where` 가 공유**한다. **묶이는 짝이 다르다.**

**명세 용어**

- 관대한 쪽이 **`<forgiving-selector-list>`**, 관대하지 않은 쪽이 **`<complex-selector-list>`** 다.

**`of S` 가 어느 쪽인지의 정본**

- [09번 주제](../09-structural-pseudo-classes/2-summary.md)다 — 거기 (3) 절에서 `of :unknownzz` 가 규칙째 사라지는 `cssRules` 출력을 실었다.

### 12. 다른 주제와 잇기

**명시도를 내리는 문법은 몇 개인가**

- **하나뿐이다 — `:where()`.** 올리는 방법은 여럿인데 내리는 것은 이것밖에 없다.

**`@layer` 와 `:where()` 는 어느 단계인가**

| 도구 | 단계 | 하는 일 |
|---|---|---|
| `@layer` | **4단계** | 명시도를 보기 **전에** 갈라 버린다 |
| `:where()` | **5단계 안** | 명시도 기여를 0 으로 만든다 |

- **층이 달라 경쟁 관계가 아니다.** 보통 같이 쓴다 — 레이어로 큰 덩어리를 나누고, 레이어 안에서 `:where()` 로 개별 기본값을 평평하게 한다.
- 정본은 [01번](../01-cascade-and-priority/2-summary.md)(단계)과 [02번](../02-specificity/2-summary.md)(명시도).

**중첩에서 `& .x` 가 명시도를 조용히 올리는 이유**

- 중첩 규칙이 펼쳐질 때 **부모 선택자가 `:is(...)` 로 감싸져** 들어간다.
- `:is()` 는 **가장 센 인자**의 값을 쓰므로, 부모 목록에 `#id` 가 하나라도 있으면 **자식 규칙 전체가 `(1, …)` 이 된다.**
- 정본은 [목록의 **14번 주제**](../14-css-nesting/). *(이 문서에서 중첩은 미실행.)*

**`:has()` 가 이 셋과 공유하는 것과 안 하는 것**

- **공유한다** — 명시도가 **가장 센 인자**로 정해진다([02번](../02-specificity/2-summary.md) 실측: `p:has(+ p#t2)` = `(1,0,2)`).
- **공유 안 한다** — **관대하지 않다.** 실측에서 `:has(.t, :unknownzz)` 는 규칙째 사라졌다.
- 정본은 [목록의 **12번 주제**](../12-has-relational-selector/).

## 용어 풀이

- **`:is()`** — 인자 목록 중 하나에라도 맞으면 매치(OR). 명시도는 **가장 센 인자**. 관대하다.
- **`:where()`** — 매칭은 `:is()` 와 같고 명시도 기여가 **언제나 0**. 관대하다.
- **`:not()`** — 인자 목록의 **어느 것에도** 안 맞아야 매치(AND 로 읽힌다). 명시도는 가장 센 인자. **관대하지 않다.**
- **가장 센 인자** — 목록에서 `(A, B, C)` 가 제일 큰 것 하나. **합치지 않는다.**
- **관대한 선택자 목록(`<forgiving-selector-list>`)** — 모르는 선택자를 그것만 버리는 목록. `:is()`·`:where()`.
- **관대하지 않은 목록(`<complex-selector-list>`)** — 하나라도 모르면 전체가 무효. 맨몸 목록·`:not()`·`:has()`·`of S`.
- **직렬화(serialization)** — 브라우저가 선택자를 다시 문자열로 써서 `cssRules` 에 보여 주는 것. `:is(.t, :몰라)` 가 `:is(.t)` 로 찍힌다.
- **`cssRules`** — 스타일시트에 실제로 담긴 규칙 목록. 규칙이 버려졌는지 확인하는 유일한 관측 창.
- **두 판 대조** — 동점 경쟁자를 뒤에 써서 경쟁자가 이기는지, 한 칸 낮은 경쟁자를 뒤에 써서 검사 대상이 이기는지 양쪽으로 확인하는 명시도 측정법([02번](../02-specificity/2-summary.md)).
- **덮어쓰기 쉬운 기본값** — `:where()` 로 싸서 `(0,0,0)` 으로 만든 규칙. 누구나 클래스 하나로 덮는다.

### 명시도를 어떻게 고정했나

```text
   판 1 (동점 검사)                        판 2 (한 칸 낮음 검사)
   +--------------------------------+     +--------------------------------+
   | 검사 대상   { color: rgb(1,1,1)}|     | 검사 대상   { color: rgb(1,1,1)}|
   | (A,B,C) 경쟁자 { rgb(2,2,2) }   |     | 한 칸 낮은 경쟁자 { rgb(2,2,2) }|
   |   <- 뒤에 썼다                  |     |   <- 뒤에 썼다                  |
   +--------------------------------+     +--------------------------------+
    기대: 동점이므로 순서로 갈려          기대: 검사 대상이 더 세므로
          경쟁자가 이긴다 rgb(2,2,2)            검사 대상이 이긴다 rgb(1,1,1)

   경쟁자는 #t1 반복(A) · .t 반복(B) · html body div p 사슬(C)로 기계 생성했다.
   두 판이 모두 기대대로면 그 (A,B,C) 가 위아래로 고정된다.
```

**16행 전부 두 판을 통과했다.** 한 칸 낮은 경쟁자가 `(0,0,0)` 이 되는 행은 `*` 를 경쟁자로 썼다.
