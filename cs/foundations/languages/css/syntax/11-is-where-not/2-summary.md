# css/syntax/11 — `:is()`·`:where()`·`:not()` 와 명시도 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [Selectors Level 4](https://drafts.csswg.org/selectors-4/) 의 [`:is()`](https://drafts.csswg.org/selectors-4/#matches) · [`:where()`](https://drafts.csswg.org/selectors-4/#zero-matches) · [`:not()`](https://drafts.csswg.org/selectors-4/#negation) · [§명시도 계산](https://drafts.csswg.org/selectors-4/#specificity-rules) · [§무효 선택자와 관대한 목록](https://drafts.csswg.org/selectors-4/#invalid). 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 명시도 값은 **Google Chrome 151.0.7922.173** headless 에서 **16개 선택자 × 두 판**(동점 경쟁자 / 한 칸 낮은 경쟁자)으로 위아래를 고정한 것이고, 매칭 개수는 같은 문서에서 `querySelectorAll().length` 로, 규칙이 살아남았는지는 `cssRules` 로 읽었다. `demo` 블록 **3개 전부**와 그 「바꿔 볼 것」도 돌려 확인했다.\
> **WebKit(Safari)은 이 머신에 없다** — Safari 관련 서술은 하지 않았다. **엔진은 Chrome 하나**다.
> **버전** — CSS 에 언어 버전은 없다. Baseline(2026-09-23 에 `api.webstatus.dev` 조회): `:is()`·`:where()`·`:not()`(목록 인자) **전부 widely**(newly 2021-01-21 → widely 2023-07-21, Chrome 88 · Firefox 82\~84 · Safari 9\~14).
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 숫자는 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**셋 다 「선택자를 인자로 받는 괄호」인데, 값을 부르는 방식이 다르다.**

08\~10 의 비유(그물 모양 / 그물의 힘)가 여기서 **정확히 갈라진다.**

| 비유 | 실체 | 모양(무엇이 걸리나) | 힘(명시도) |
|---|---|---|---|
| 대표 선수를 내보낸다 | `:is(A, B)` | A 또는 B | **인자 중 가장 센 것** |
| 대표는 내보내되 **점수는 포기** | `:where(A, B)` | A 또는 B | **언제나 `(0,0,0)`** |
| 명단에 없어야 통과 | `:not(A, B)` | A 도 B 도 아닌 것 | **인자 중 가장 센 것** |

- ★ **`:is()` 는 ①모양을 안 바꾸고 ②힘만 바꾼다.** `:where()` 는 **힘을 0 으로 만든다.**\
  실측에서 `p:is(.t, #zz)` 와 `p:where(.t, #zz)` 는 **둘 다 2개를 잡았고**(모양 같음), 명시도는 `(1,0,1)` 과 `(0,0,1)` 이었다(힘 다름).
- ★ **`:not()` 은 모양을 뒤집으면서 힘은 `:is()` 와 같은 규칙**을 쓴다. 그래서 **문서에 없는 ID 하나가 승부를 가른다.**
- 그리고 넷째 축이 있다 — **관대함**. `:is()`/`:where()` 안에서는 **모르는 선택자 하나만 죽고**, 맨몸 목록이나 `:not()` 안에서는 **전체가 죽는다**((4) 절).

```text
      같은 목록 (.t, #zz) 을 세 껍데기에 넣었을 때

      모양(querySelectorAll)          힘(getComputedStyle 로 확인한 명시도)
   ┌────────────────────────┐      ┌────────────────────────────────┐
   │ :is(.t, #zz)     2개   │      │ :is(.t, #zz)      가장 센 #zz  │
   │ :where(.t, #zz)  2개   │      │ :where(.t, #zz)   무조건 0     │
   │  -> 완전히 같다        │      │  -> 완전히 다르다              │
   └────────────────────────┘      └────────────────────────────────┘
```

실무에서 이게 터지는 자리는 「**`:is()` 목록에 편의상 ID 하나를 끼워 넣었을 때**」와 「**라이브러리 기본값을 못 덮을 때**」다.\
앞엣것은 `:is()` 가 힘을 올려서, 뒤엣것은 `:where()` 를 안 써서 생긴다.

> **명시도(specificity)** — 선택자가 캐스케이드에서 갖는 세기. `(A, B, C)` 세 자리.\
> **계산 규칙 자체의 정본은 [02번 주제](../02-specificity/2-summary.md)다.** 여기서는 **이 셋이 그 계산에 어떻게 들어가는지**만 다룬다.

> **관대한 선택자 목록(forgiving selector list)** — 모르는 선택자가 섞여도 **그것만 버리고 나머지는 살리는** 목록.\
> 예: `:is(.a, :몰라)` 는 `.a` 로 계속 동작한다. 맨몸 목록 `.a, :몰라` 는 규칙째 사라진다.

## 이 주제가 답하려는 질문

1. 같은 목록을 셋에 각각 담았을 때 **명시도가 어떻게 갈리는가** — `(A, B, C)` 로 적고 그 계산이 맞는지 확인할 수 있는가.
2. **모양은 같은데 힘만 다르다**는 것을 두 가지 근거로 각각 보일 수 있는가.
3. `:is()` 의 **관대함**이 정확히 어디까지인가 — `:where()`·`:not()`·`of S` 와 어떻게 갈리는가.

## 예시 데이터 — 이 편이 쓰는 문서

```text
div#box
 └─ p#t1 .t     "대상"
p#t2 .t         "둘째"

명시도 실험은 전부 #t1 의 color 를 읽어 판정했다.
경쟁자는 #t1 반복(A 자리) · .t 반복(B 자리) · html body div p 사슬(C 자리)로 기계 생성했다.
```

## 동작 방식

### (1) 세 껍데기가 값을 부르는 법

**언제 쓰나** — 선택자를 목록으로 묶어 쓸 때마다.

```text
   p:is(.t, #zz)
    ├ p              타입 1            (0, 0, 1)
    └ :is(.t, #zz)   인자 중 가장 센 것 = #zz   (1, 0, 0)
                                       합 =  (1, 0, 1)

   p:where(.t, #zz)
    ├ p                                (0, 0, 1)
    └ :where(...)    무엇이 들어가든 0  (0, 0, 0)
                                       합 =  (0, 0, 1)

   p:not(.zz, #zz)
    ├ p                                (0, 0, 1)
    └ :not(...)      인자 중 가장 센 것 = #zz   (1, 0, 0)
                                       합 =  (1, 0, 1)

   ★ 껍데기 자신(:is / :where / :not)은 어느 자리에도 안 보탠다.
     안의 목록에서 "가장 센 하나"를 뽑아 그 자리에 그대로 넣는 것이다.
```

**두 판으로 고정한 실측표**다. 판정 방법은 [02번](../02-specificity/2-summary.md) 「손으로 세어 보기」와 같다 — 동점 경쟁자를 뒤에 쓰면 경쟁자가 이겨야 하고, 한 칸 낮은 경쟁자를 뒤에 써도 검사 대상이 이겨야 한다. **16행 전부 두 판을 통과했다.**

| 선택자 | (A, B, C) | 왜 |
|---|---|---|
| `p:is(.t, #zz)` | (1, 0, 1) | `#zz` 가 가장 세다 |
| `p:where(.t, #zz)` | (0, 0, 1) | `:where()` 는 0 — ID 가 사라진다 |
| `p:not(.zz, #zz)` | (1, 0, 1) | `:not()` 도 가장 센 인자 |
| `p:is(.t, .b)` | (0, 1, 1) | 가장 센 것이 클래스 |
| `p:where(.t, .b)` | (0, 0, 1) | 0 |
| `p:not(.zz, .b)` | (0, 1, 1) | 가장 센 것이 클래스 |
| `p:is(div, p)` | (0, 0, 2) | 타입 1 + 인자의 타입 1 |
| `p:where(div, p)` | (0, 0, 1) | 0 |
| `p:not(div, span)` | (0, 0, 2) | 타입 1 + 인자의 타입 1 |
| `:is(#box) .t` | (1, 1, 0) | 인자의 ID + `.t` |
| `:where(#box) .t` | (0, 1, 0) | 0 + `.t` |
| `:not(#box) .t` | (1, 1, 0) | `:not()` 도 ID 를 센다 |
| `p:not(:is(#zz))` | (1, 0, 1) | 중첩해도 안쪽 ID 가 끝까지 올라온다 |
| `p:is(:where(#t1))` | (0, 0, 1) | **`:where()` 가 안쪽에서 0 으로 끊는다** |
| `p:not(:where(#zz))` | (0, 0, 1) | 같은 이유 — `:not()` 도 끊긴다 |
| `p:is(.t, #zz, div p)` | (1, 0, 1) | 목록이 길어도 **가장 센 하나**만 |

그림 해설 (한 단계씩):

- **`:where()` 는 안쪽으로도 전파를 끊는다.** `p:is(:where(#t1))` 이 `(0,0,1)` 인 것이 그 증거다 — 바깥이 `:is()` 인데도 ID 가 안 올라왔다.
- **목록이 길어도 세는 것은 하나**다. `p:is(.t, #zz, div p)` 는 `(1,0,1)` 이지 `#zz` 와 `div p` 를 합치지 않는다.
- **`:not()` 이 가장 조용히 틀린다.** `#zz` 는 문서에 없는 ID 이고 "제외 대상"으로만 쓰였는데 A 자리를 1 올린다.

비용 — 없다. 대신 **선택자를 읽는 사람이 괄호 안까지 봐야 세기를 알게 된다.**

### (2) 모양은 같고 힘만 다르다 — 근거를 둘로 나눠 쓴다

**언제 쓰나** — "`:is` 를 `:where` 로 바꿨더니 스타일이 사라졌다"를 진단할 때.

```text
   같은 문서에 두 근거를 나란히 실었다

   ① 무엇이 잡혔나 (querySelectorAll)     ② 무엇이 먹었나 (getComputedStyle)
   ─────────────────────────────────      ────────────────────────────────
   p:is(.t, #zz)        -> 2개  t1,t2      :is(#box) .t   -> (1,1,0)  이긴다
   p:where(.t, #zz)     -> 2개  t1,t2      :where(#box) .t-> (0,1,0)  진다
   :is(#box) .t         -> 1개  t1
   :where(#box) .t      -> 1개  t1
   p:is(.t, #zz, div p) -> 2개  t1,t2
   p:not(.zz, #zz)      -> 2개  t1,t2
   p:not(.t)            -> 0개
```

★ **①만 보면 `:is` 와 `:where` 가 완전히 같은 물건으로 보인다.** 개수도 잡힌 노드도 똑같다.\
★ **②를 봐야 갈린다.** 이 둘을 같은 실험에 나란히 싣지 않으면 "왜 안 먹지"에서 영영 못 빠져나온다.

```html demo
<p class="t">이 줄은 무슨 색일까?</p>
<style>
  p:not(.zz, #nope)  { color: #b91c1c; }
  p:is(.t, .u)       { color: #15803d; }
  p:where(.t, #nope) { color: #1d4ed8; }
  p { font: 20px/1.6 system-ui, sans-serif; }
</style>
```

> **보이는 것** — 줄이 **빨강(#b91c1c)** 으로 나온다. 세 규칙 **전부 이 줄에 매치되는데** 맨 처음에 쓴 `:not()` 이 이긴다. `#nope` 는 문서에 없는 ID 이고 「제외 대상」으로만 적혔는데 그것 하나가 `(1,0,1)` 을 만든다. `:where()` 로 싼 파랑은 `(0,0,1)` 이라 가장 약하고, 가장 나중에 쓰였는데도 진다.\
> **바꿔 볼 것** — `:not(.zz, #nope)` 의 `#nope` 를 `.nope` 로 바꾸면 `(0,1,1)` 이 되어 **초록**(`:is` 쪽)이 이긴다

*(Chrome 151 headless 실측: 원본 `rgb(185, 28, 28)` / `#nope` 를 `.nope` 로 바꾼 판 `rgb(21, 128, 61)`. 세 규칙 모두 `cssRules` 에 담겨 있었다 — 진 규칙이 버려진 것이 아니라 **매치되고 졌다.**)*

비용 — 없다. **진단 순서는 언제나 셋이다** — `cssRules`(담겼나) → `querySelectorAll`(잡혔나) → `getComputedStyle`(이겼나). [08번](../08-basic-selectors-and-combinators/2-summary.md)에서 세운 세 창이다.

### (3) `:where()` — 덮어쓰기 쉬운 기본값을 만드는 장치

**언제 쓰나** — 라이브러리·디자인 시스템이 기본값을 제공할 때.

```text
   .prose h2        ->  (0, 1, 1)   덮으려면 클래스 둘이나 타입을 더해야 한다
   :where(.prose) h2->  (0, 0, 1)   클래스 하나로 덮인다
        ^^^^^^^^^^
        "이 요소를 고른다"는 유지하고 "세게 고른다"만 포기했다
```

```html demo
<article class="prose"><h2 class="lead">제목</h2></article>
<style>
  h2 { font: 20px system-ui, sans-serif; }
  :where(.prose) h2 { color: #64748b; margin: 0; }
  .lead { color: #b91c1c; }
</style>
```

> **보이는 것** — 제목이 **빨강(#b91c1c)** 으로 나온다. 기본값 규칙이 `:where()` 로 싸여 `(0,0,1)` 이라, 뒤에 붙인 클래스 하나 `(0,1,0)` 에 진다. 여백을 없애는 `margin: 0` 은 덮이지 않았으므로 그대로 먹는다 — **같은 규칙에서 한 속성만 덮인 것**이다.\
> **바꿔 볼 것** — `:where(.prose) h2` 를 `.prose h2` 로 바꾸면 `(0,1,1)` 이 되어 **회색(#64748b)** 으로 돌아간다(클래스 하나로는 못 덮는다)

*(Chrome 151 headless 실측: 원본 `rgb(185, 28, 28)`, 같은 판에서 `margin-top`·`margin-bottom` 은 `0px` — 색만 덮였다. `.prose h2` 로 바꾼 판은 `rgb(100, 116, 139)`.)*

- **`:where()` 는 세기를 내리는 유일한 문법**이다. 올리는 문법은 여럿인데 내리는 것은 이것뿐이다.
- 더 큰 단위로 나누는 것은 `@layer`(캐스케이드 4단계, [목록의 **05번 주제**](../05-cascade-layers/))다. 둘은 **층이 달라 같이 쓴다.**
- ★ **주의** — `:where()` 로 싼 규칙은 **아무 규칙에나 진다.** 기본값에만 쓰고, 꼭 이겨야 하는 것에 쓰면 안 된다.

비용 — 없다. 대신 **덮인 것이 의도인지 사고인지 구분이 안 된다** — `:where()` 로 싸 놓으면 "누가 덮었나"를 추적할 단서가 줄어든다.

### (4) 관대함 — 모르는 선택자 하나가 어디까지 죽이나 ★

**언제 쓰나** — 아직 안 퍼진 선택자를 쓰면서 옛 브라우저를 버리지 않을 때.

한 스타일시트에 일곱 규칙을 넣고 `cssRules` 를 읽었다. **살아남은 것은 넷이다.**

```text
   넣은 규칙                                 cssRules 에 남은 것
   ──────────────────────────────────────    ─────────────────────────
   .t, :unknownzz          { … }             (없음)      <- 규칙째 사라졌다
   :is(.t, :unknownzz)     { … }             :is(.t)     <- 모르는 것만 빠졌다
   :where(.t, :unknownzz)  { … }             :where(.t)  <- 같다
   :not(.zz, :unknownzz)   { … }             (없음)      <- 규칙째 사라졌다
   :has(.t, :unknownzz)    { … }             (없음)      <- 규칙째 사라졌다
   :is(:unknownzz)         { … }             :is()       <- 빈 껍데기만 남았다
   :is(.t, div::bogus)     { … }             :is(.t)     <- 의사 요소도 같다
```

그림 해설 (한 단계씩):

- **맨몸 목록은 전부 아니면 전무다.** `.t` 가 멀쩡한데도 `:unknownzz` 하나 때문에 규칙이 통째로 사라졌다([08번](../08-basic-selectors-and-combinators/2-summary.md) (6) 과 같은 규칙).
- **`:is()`·`:where()` 안에서는 그 하나만 죽는다.** 브라우저가 **선택자 문자열까지 다시 써서** `:is(.t)` 로 남겼다 — 모르는 인자를 실제로 목록에서 빼 버린 것이다.
- **`:not()` 과 `:has()` 는 관대하지 않다.** 규칙째 사라졌다. 셋이 「가장 센 인자」 규칙은 같이 쓰는데 **관대함은 `:is`/`:where` 에만 있다.**
- **인자가 전부 죽으면 `:is()` 만 남고 아무것도 안 잡는다.** 실측에서 `:is(:unknownzz)` 의 매치 수는 **0개**였다. 규칙은 살아 있는데 매치가 없는 상태다.
- `of S` 도 관대하지 않다 — `p:nth-child(2n of :unknownzz)` 는 규칙째 사라졌다([09번](../09-structural-pseudo-classes/2-summary.md)).

```html demo
<p class="a">첫째 줄</p>
<p class="b">둘째 줄</p>
<style>
  p { font: 18px/1.6 system-ui, sans-serif; }
  .a, :zzz-unknown      { color: #b91c1c; }
  :is(.b, :zzz-unknown) { color: #15803d; }
</style>
```

> **보이는 것** — **첫째 줄은 검정(기본색)** 이고 **둘째 줄만 초록(#15803d)** 이다. 두 규칙 다 모르는 선택자 `:zzz-unknown` 을 하나씩 갖고 있는데, 맨몸 목록으로 쓴 첫째는 `.a` 까지 같이 죽었고 `:is()` 안에 넣은 둘째는 `.b` 가 살아남았다. 에러도 경고도 없이 색만 다르다.\
> **바꿔 볼 것** — `:is(.b, …)` 를 `:where(.b, …)` 로 바꿔도 **둘째 줄은 그대로 초록**이다(`:where()` 도 똑같이 관대하다 — 달라지는 것은 명시도뿐이고 여기서는 경쟁자가 없다)

*(Chrome 151 headless 실측: 첫째 줄 `rgb(0, 0, 0)` / 둘째 줄 `rgb(21, 128, 61)`. `cssRules` 에는 `p` 와 `:is(.b)` 만 남아 있었고 첫 규칙은 없었다. `:where` 로 바꾼 판도 `rgb(0, 0, 0)` / `rgb(21, 128, 61)` 로 같았다.)*

★ **이것이 「CSS 는 에러가 없는 언어다」의 실물이다.** 첫째 줄이 검은 이유는 화면 어디에도 안 적혀 있다. `cssRules` 를 읽어야만 "규칙이 아예 안 담겼다"가 보인다.

비용 — 없다. **`:is()` 로 감싸는 것이 점진적 향상의 값싼 수단**이 된다. 무엇을 어디까지 버리는지의 정본은 [목록의 **07번 주제**](../07-syntax-and-error-recovery/)다.

## 문법 — 어디서 헷갈리나

### 형태

```css
:is(h1, h2, h3) .sub      { }   /* 목록을 한 자리에 묶는다 */
:where(.card, .panel) h2  { }   /* 같은 매칭, 명시도 0 */
p:not(.a, .b)             { }   /* 둘 다 아닌 p — 인자 목록을 받는다 */
:is(.a, .b) :is(.c, .d)   { }   /* 곱해진다: 네 조합 전부 */
```

### 헷갈리는 자리

- **`:not(.a, .b)` 는 "`.a` 가 아니거나 `.b` 가 아닌"이 아니다.** **둘 다 아닌** 것이다(AND).\
  옛 문법 `:not(.a):not(.b)` 와 같은 뜻이고, 명시도만 다를 수 있다.\
  *(Chrome 151 headless 실측: `.a` · `.b` · `.a .b` · 무클래스 네 문단에서 `p:not(.a, .b)` 와 `p:not(.a):not(.b)` 가 **둘 다 마지막 하나**만 잡았다.)*
- **`:is()` 안에는 의사 요소를 못 넣는다.** `:is(.t, div::bogus)` 에서 그 인자는 버려졌다(위 실측).
- **`:is()` 를 곱하면 폭발한다.** `:is(a,b,c) :is(d,e,f)` 는 9개 조합이다 — 읽는 사람 머릿속에서 펼쳐진다.
- **`:where()` 안에서도 조합자를 쓸 수 있다** — `:where(.a > .b, .c)`.
- 명시도는 「매치된 인자」가 아니라 「**목록에서 가장 센 인자**」다. `.t` 로 매치됐어도 `#zz` 가 값을 정한다.

## 어디서 틀리나

### 1. `:is()` 목록에 강한 것 하나를 끼워 넣는다

```css
:is(h1, h2, h3, #hero) .sub { }   /* (1, 1, 0) — h1 에 매치될 때도 그렇다 */
```

편의상 `#hero` 를 추가한 순간 **목록 전체가 ID 급**이 된다. 실측 `p:is(.t, #zz, div p)` = `(1,0,1)`.\
섞기 싫으면 `:where()` 로 감싸거나 규칙을 쪼갠다.

### 2. `:not()` 안의 ID 가 안 세어진다고 생각한다 ★ 가장 조용하다

```css
.card:not(#legacy) { padding: 8px; }   /* (1, 1, 0) — #legacy 가 문서에 없어도 */
```

명시도는 **매칭 결과가 아니라 선택자의 모양**만 본다. `(2)` 의 demo 가 이 함정 하나로 서 있다.

### 3. `:where()` 가 매칭도 안 한다고 생각한다

실측에서 `p:is(.t, #zz)` 와 `p:where(.t, #zz)` 는 **둘 다 2개**를 잡았다.\
`:where()` 가 포기하는 것은 **세기뿐**이다. 「안 잡힌다」와 「잡혔는데 졌다」는 다른 증상이고 진단법도 다르다.

### 4. `:is()` 가 관대하니까 `:not()` 도 그렇다고 생각한다

```text
   :is(.t, :unknownzz)   -> 살아남는다 (:is(.t) 로)
   :not(.zz, :unknownzz) -> 규칙째 사라진다
   :has(.t, :unknownzz)  -> 규칙째 사라진다
   :nth-child(2n of :unknownzz) -> 규칙째 사라진다
```

**관대함은 `:is()`·`:where()` 둘만의 성질**이다. 셋이 명시도 규칙을 공유한다고 해서 관대함까지 공유하지 않는다.

### 5. `:where()` 안쪽이 바깥 `:is()` 로 전파된다고 생각한다

```text
   p:is(:where(#t1))   ->  (0, 0, 1)   <-- ID 가 안 올라온다
   p:not(:where(#zz))  ->  (0, 0, 1)
   p:not(:is(#zz))     ->  (1, 0, 1)   <-- 이쪽은 올라온다
```

**`:where()` 는 어느 깊이에 있든 그 가지를 0 으로 끊는다.** 「세기를 못 올리게 하는 벽」이다.

### 6. 명시도 계산 규칙 자체를 여기서 다시 세운다

`(A, B, C)` 를 세는 법·올림이 없다는 것·비교가 A 부터라는 것은 전부 **[02번 주제](../02-specificity/2-summary.md)가 정본**이다.\
여기서 새로 외울 것은 **「이 셋이 그 계산에 무엇을 넣는가」** 한 줄뿐이다 — 가장 센 인자 / 0 / 가장 센 인자.

## 구현 세부사항 대 언어 보장

| 것 | 성격 | 근거 |
|---|---|---|
| `:is()`/`:not()` 이 가장 센 인자의 명시도를 갖는 것 | **명세 보장** | Selectors 4 §specificity-rules |
| `:where()` 가 언제나 0 인 것 | **명세 보장** | Selectors 4 §zero-matches |
| `:is()`/`:where()` 가 관대한 것 | **명세 보장**(`<forgiving-selector-list>`) | Selectors 4 §matches · §zero-matches |
| `:not()`·`:has()` 가 관대하지 **않은** 것 | **명세 보장** — 이 둘은 `<complex-selector-list>` 다 | Selectors 4 §negation · §relational |
| 브라우저가 `:is(.t)` 로 **다시 써서** 보여 주는 것 | **직렬화 동작** — Chrome 151 의 관찰 | 이 문서 (4) 의 `cssRules` 출력 |
| 표의 16행 값 | **두 판 대조로 고정한 실측** | Chrome 151 headless |

★ **「가장 센 인자」는 명세 보장이고, `cssRules` 에 `:is(.t)` 라고 찍히는 모양은 직렬화 결과다.** 앞엣것에 결론을 세우고 뒤엣것은 근거로만 쓴다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 같은 급의 태그 여럿 | `:is(h1, h2, h3)` | 목록에 ID·강한 것 섞기 |
| 라이브러리·리셋 기본값 | `:where(...)` | 긴 자손 사슬 |
| 아직 안 퍼진 선택자 실험 | `:is(.old, :새문법)` | 맨몸 목록 — 규칙째 죽는다 |
| 특정 요소만 제외 | `:not(.excluded)` | `:not(#legacy)` — 명시도가 튄다 |
| 제외인데 명시도는 안 올리고 싶다 | `:where(:not(#legacy))` | `:not(#legacy)` |
| 큰 덩어리를 통째로 아래에 깔기 | `@layer`([목록의 **05번 주제**](../05-cascade-layers/)) | `:where()` 만으로 버티기 |
| "이 자식을 가진 부모" | `:has()`([목록의 **12번 주제**](../12-has-relational-selector/)) | `:is()` 로 시도 — 방향이 다르다 |
| 중첩에서 부모 목록 | `:where()` 로 감싸 두기 | 그냥 두기 — `&` 가 `:is()` 로 감싸며 올린다([목록의 **14번 주제**](../14-css-nesting/)) |

판단 규칙 두 줄.

- **`:is()` 는 "묶는 도구"이지 "약하게 만드는 도구"가 아니다.** 약하게 하려면 `:where()` 다.
- **목록에 무엇을 넣을지 고를 때 "가장 센 인자"를 먼저 보라.** 그 하나가 규칙 전체의 값이다.

## 핵심 문장

- 셋 다 **선택자를 인자로 받는 괄호**이고, **모양**은 `:is()`/`:where()` 가 같고 `:not()` 이 뒤집는다.
- **힘은** `:is()`·`:not()` 이 **인자 중 가장 센 것**, `:where()` 가 **언제나 0** 이다. 껍데기 자신은 아무 자리에도 안 보탠다.
- **`:is()` 는 ①무엇이 잡히나를 안 바꾸고 ②그 값이 이기나만 바꾼다.** 실측에서 `:is`/`:where` 는 매치 수가 같았고 명시도만 `(1,0,1)` / `(0,0,1)` 로 갈렸다.
- **`:where()` 는 어느 깊이에 있든 그 가지를 0 으로 끊는다** — `p:is(:where(#t1))` 은 `(0,0,1)` 이다.
- **관대함은 `:is()`·`:where()` 둘만의 성질이다.** `:not()`·`:has()`·`of S` 는 모르는 선택자 하나에 **규칙째 죽는다.**
- **맨몸 목록은 전부 아니면 전무** — `.t, :unknownzz` 는 `cssRules` 에서 통째로 사라졌고, `:is(.t, :unknownzz)` 는 `:is(.t)` 로 남았다.
- 명시도 계산 규칙 자체는 **[02번](../02-specificity/2-summary.md)이 정본**이다. 여기서 더할 것은 「가장 센 인자 / 0 / 가장 센 인자」 한 줄이다.

## 용어 풀이

- **`:is()`** — 인자 목록 중 하나에라도 맞으면 매치. 명시도는 **가장 센 인자**. 관대하다.
- **`:where()`** — 매칭은 `:is()` 와 같고 명시도 기여가 **언제나 0**. 관대하다.
- **`:not()`** — 인자 목록의 **어느 것에도** 안 맞아야 매치. 명시도는 가장 센 인자. **관대하지 않다.**
- **가장 센 인자** — 목록에서 `(A, B, C)` 가 제일 큰 것 하나. 합치지 않는다.
- **관대한 선택자 목록(forgiving selector list)** — 모르는 선택자를 그것만 버리는 목록. `:is()`·`:where()`.
- **관대하지 않은 목록(non-forgiving)** — 하나라도 모르면 전체가 무효. 맨몸 목록·`:not()`·`:has()`·`of S`.
- **직렬화(serialization)** — 브라우저가 선택자를 다시 문자열로 써서 `cssRules` 에 보여 주는 것. `:is(.t, :몰라)` 가 `:is(.t)` 로 찍힌다.
- **`cssRules`** — 스타일시트에 실제로 담긴 규칙 목록. 규칙이 버려졌는지 확인하는 유일한 관측 창.
- **덮어쓰기 쉬운 기본값** — `:where()` 로 싸서 `(0,0,0)` 으로 만든 규칙. 누구나 클래스 하나로 덮는다.

## 더 들어가면

- **`:is()` 가 없던 시절**에는 같은 선언을 선택자 목록으로 길게 나열했다. `:is()` 는 **그 나열을 한 자리로 접는** 문법이고, 부작용으로 명시도가 「가장 센 인자」로 통일된다.
- **`:where()` 의 진짜 값은 협상 비용을 없애는 것**이다. 라이브러리가 `(0,0,0)` 으로 주면 사용자가 무엇을 쓰든 덮인다 — "얼마나 세게 쓸지"를 아무도 안 정해도 된다.
- **중첩(nesting)에서 `& .x` 를 쓰면 부모 선택자가 `:is(...)` 로 감싸져 들어간다.** 부모 목록에 강한 것이 하나라도 있으면 중첩된 자식 규칙 전체의 명시도가 조용히 올라간다([목록의 **14번 주제**](../14-css-nesting/)). *(이 문서에서 중첩은 미실행.)*
- **`:has()` 도 「가장 센 인자」 규칙을 쓴다** — `p:has(+ p#t2)` 는 `(1,0,2)` 다([02번](../02-specificity/2-summary.md) 실측). 하지만 **관대하지 않다**는 것이 이 문서 (4) 의 실측이다.
- **명시도를 내리는 문법은 `:where()` 하나뿐이다.** `@layer`·`@scope` 는 명시도를 내리는 게 아니라 **명시도를 보기 전에 갈라 버리는** 장치다([목록의 **05번 주제**](../05-cascade-layers/)·**06번 주제**).
