# css/syntax/06 — `@scope`: 스코프 루트·하한과 근접성(proximity) — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **모든 색은 Google Chrome 151.0.7922.173 headless 에서 실제로 돌려 `getComputedStyle` 로 읽은 것**이다.\
> 규칙은 [CSS Cascading and Inheritance Level 6](https://drafts.csswg.org/css-cascade-6/) 「Scoped Styles」로 접지했다.\
> **엔진은 Chrome 하나다.** `@scope` 는 Baseline **newly available**(2026-03-24)이고 widely 가 아니다 — A9 참고.

### 1. 구역은 어디부터 어디까지인가

**출력** (Chrome 151 headless)

```text
1 (카드 안)        rgb(185, 28, 28)   빨강
2 (하한 .content 안) rgb(0, 0, 0)     검정
3 (카드 밖)        rgb(0, 0, 0)       검정
```

**세 문단의 색**

- **빨강 · 검정 · 검정.**

```text
<div class="card">          ← 루트.        구역 안
  <p class="txt">1</p>      ← 구역 안      빨강
  <div class="content">     ← 하한.        구역 '밖'
    <p class="txt">2</p>    ← 구역 밖      검정
  </div>
</div>
<p class="txt">3</p>        ← 구역 밖      검정
```

**하한 요소 자신에 스타일을 걸면**

- **안 먹는다.** 실측에서 `@scope (.card) to (.content) { .content { background-color: #fde68a } }` 를 걸었더니 `.content` 의 `background-color` 가 **`rgba(0, 0, 0, 0)`** 이었다.
- **「`to` 까지 포함」이 아니라** 「**`to` 부터 제외**」로 읽는다.

**스코프 루트 자신은**

- **구역 안**이다. 실측에서 `:scope { outline: 3px solid #b91c1c }` 가 `.card` 에 걸렸다(`outline-style: solid`).

**`to (.content)` 를 지우면**

- **1번과 2번 둘 다 빨강**이 된다(실측). 하한이 없으면 루트 아래 전부가 구역이다.

### 2. 테마가 중첩되면

**출력** (Chrome 151 headless)

```text
1 (light 안)          rgb(21, 128, 61)   초록
2 (light 안의 dark 안) rgb(29, 78, 216)   파랑
```

**두 문단의 색**

- **초록 · 파랑.**

**둘째가 두 규칙에 매치되는데 갈리는 기준**

- **근접성(proximity)** 이다. 그 요소에서 스코프 루트까지 **조상을 몇 칸 올라가나**를 센다.

```text
   <div class="theme-light">        ← light 까지 2칸
     <div class="theme-dark">       ← dark 까지 1칸   ← 더 가깝다. 이긴다
       <p class="prox">2</p>
```

**순서를 바꾸면**

- **안 달라진다.** 실측으로 `dark` 블록을 먼저 쓴 판을 따로 던져 같은 결과(`초록`/`파랑`)를 얻었다.
- 근접성이 **등장 순서보다 앞**이기 때문이다.

**이 기능이 없으면 손으로 써야 하는 것**

```css
.theme-light .prox { color: #15803d; }
.theme-dark  .prox { color: #1d4ed8; }
.theme-light .theme-dark .prox { color: #1d4ed8; }   /* 이런 조합을 전부 */
.theme-dark  .theme-light .prox { color: #15803d; }  /* 양방향으로 */
```

- 테마가 셋이 되면 조합이 폭발한다. `@scope` 는 이것을 **「가까운 쪽」 한 규칙**으로 대체한다.

### 3. 근접성 대 명시도

**출력** (Chrome 151 headless)

```text
X  rgb(29, 78, 216)   파랑   = 멀지만 명시도가 센 쪽
```

**이 문단의 색**

- **파랑**(`#1d4ed8`). 가까운 쪽이 졌다.

**어느 것이 먼저 판정되나**

```text
5   명시도      (1,1,1)  vs  (0,1,0)   ->  여기서 갈린다. 끝
5.5 근접성      2칸      vs  1칸       ->  부르지 않는다
6   등장 순서
```

- **명시도가 먼저**다. 근접성은 명시도가 **동점일 때만** 불린다.

**`@layer` 와 결정적으로 다른 점**

| | 캐스케이드 자리 | 명시도와의 관계 |
|---|---|---|
| `@layer` | **4단계** | 명시도 **앞** — 명시도를 무력화한다 |
| `@scope` 근접성 | **5.5단계** | 명시도 **뒤** — 명시도에 진다 |

**남의 시트를 `@scope` 로 덮을 수 있는가**

- **없다.** 남의 시트가 센 선택자를 쓰면 그대로 진다.
- 그 문제는 [05번 주제](../05-cascade-layers/2-summary.md)의 `@layer` 가 푼다. **`@scope` 는 「어디까지」를, `@layer` 는 「누가 이기나」를 푼다.**

### 4. 근접성 대 등장 순서

**출력** (Chrome 151 headless)

```text
Y  rgb(21, 128, 61)   초록   = 가깝고 '먼저' 쓴 쪽
```

**이 문단의 색**

- **초록**(`#15803d`).

**순서 모델로 설명하면**

- 나중에 쓴 `.far2` 의 **파랑**이 나와야 한다. **틀린다.**
- 틀리는 이유는 근접성이 **6단계보다 앞인 5.5단계**이기 때문이다. 순서는 근접성이 동점일 때만 불린다.

**근접성이 같을 때**

- **등장 순서**가 정한다. 실측: 같은 루트 `.n3` 로 두 번 쓴 판에서 **나중 것(파랑)** 이 이겼다.

**두 판이 자리를 가두는 방식**

```text
  5   명시도       ──── 3번 판이 여기서 졌다   → 근접성은 이보다 아래다
  5.5 근접성       ★ 갇힌 자리
  6   등장 순서    ──── 4번 판이 여기를 이겼다 → 근접성은 이보다 위다
```

- **한 판만으로는 자리를 못 정한다.** 위아래 양쪽에서 한 번씩 눌러야 칸 하나가 확정된다.

### 5. 스코프 루트 선택자의 명시도

**출력** (Chrome 151 headless)

```text
Q  rgb(29, 78, 216)   파랑   = 스코프 밖의 .q.q (0,2,0) 이 이겼다
V  rgb(21, 128, 61)   초록   = :scope .v (0,2,0) 이 근접성으로 이겼다
```

**이 문단의 색**

- **파랑**(`#1d4ed8`).

**`#big` 의 기여**

- **아무 자리에도 기여하지 않는다.** 프렐류드의 선택자는 명시도 계산에 들어가지 않는다.
- 기여했다면 스코프 안 규칙이 `(1,1,0)` 이 되어 `(0,2,0)` 을 이겼을 것이다. 파랑이 나왔다는 것이 반증이다.

**`:scope` 를 쓰면**

- **의사 클래스 하나만큼**, 곧 `(0,1,0)` 이 더해진다.
- 실측 판: `@scope (#big2) { :scope .v { … } }` 는 `(0,2,0)` 이 되어 스코프 밖 `.v.v` `(0,2,0)` 과 **동점**이 되었고, 그때 **근접성으로 스코프 안이 이겼다**(초록).

**스코프 밖 선언의 근접성**

- **무한히 먼 것**으로 취급된다.
- 그래서 **명시도가 같으면 스코프 안이 순서와 무관하게 언제나 이긴다.** 위 V 판이 그 증거다.
- ★ 도입할 때 예상 밖의 승패가 여기서 나온다 — 스코프를 한 곳에만 써도 **문서 전체의 판정에 새 칸이 생긴다.**

### 6. 스코프 안에서 루트 자신을 가리키기

**출력** (Chrome 151 headless — `.cardA` 가 두 겹 중첩된 판)

```text
바깥 .cardA  outline-style = none
안쪽 .cardA  outline-style = solid
```

**어느 요소에 걸리는가**

- **안쪽 `.cardA`** 에 걸린다. 바깥(=루트 자신)에는 **안 걸린다.**

**루트 자신을 노리려면**

- **`:scope`** 또는 **`&`** 를 쓴다.

```css
@scope (.card) { :scope { outline: 3px solid red; } }   /* 둘 다 루트를 가리킨다 */
@scope (.card) { &       { outline: 3px solid red; } }
```

**`@scope` 안의 `&`**

- **스코프 루트**를 가리킨다. 실측: `@scope (.amp) { & p { background-color: #fde68a } }` 가 `.amp` 안의 `p` 에 걸렸다(`rgb(253, 230, 138)`).
- 중첩([목록의 **14번 주제**](../14-css-nesting/))의 `&` 와 표면이 같아 섞어 쓰기 쉽다 — 「`&` = 바깥쪽 기준」이라는 감각은 같다.

**「상대 선택자」의 뜻**

- 규칙 안 선택자가 **루트에 대한 상대 경로**로 읽힌다는 뜻이다. `@scope (.card) { .txt }` 는 사실상 `.card` 의 **자손 중** `.txt` 다.
- 그래서 루트 자신은 그 경로에 안 들어간다 — 6번의 결과가 여기서 나온다.

### 7. 프렐류드 없는 `@scope`

**출력** (Chrome 151 headless)

```text
T  (div.w2 안)  rgb(185, 28, 28)   빨강
T2 (그 밖)      rgb(0, 0, 0)       검정
```

**두 문단의 색**

- **빨강 · 검정.**

**프렐류드가 없을 때의 루트**

- **그 `<style>` 요소의 부모 요소**다. 위 판에서는 `<div class="w2">` 다.

**어떤 사용 패턴을 위해 있나**

- **HTML 조각 안에 `<style>` 을 함께 내려보내는 패턴**이다.
- 서버나 템플릿이 조각을 만들 때 **고유 클래스 이름을 생성하지 않아도** 그 조각 안으로 범위가 갇힌다.

**`<head>` 로 옮기면**

```text
실측 — <style> 을 문서 맨 앞에 두었더니 파서가 <head> 로 올렸다
  style.parentElement.tagName = "HEAD"
  .t  color = rgb(0, 0, 0)      ← 안 걸렸다
```

- 루트가 `<head>` 가 되어 **`<body>` 안의 어떤 요소도 구역에 안 들어간다.**
- ★ **HTML 파서가 `<style>` 을 `<head>` 로 올려 버리는 자리**(본문 시작 전)가 있으므로, 암묵 루트를 쓸 때는 **그 `<style>` 이 실제로 어디에 놓였는지**를 확인해야 한다. 조용히 아무것도 안 걸린다.

### 8. 같은 컴포넌트가 중첩될 때

**출력** (Chrome 151 headless)

```text
B1 (바깥 카드)  rgb(21, 128, 61)   초록
B2 (안쪽 카드)  rgb(21, 128, 61)   초록
```

**두 문단의 색**

- **둘 다 초록.** 「안쪽은 안 칠해진다」가 아니다 — 여기서 자주 틀린다.

**바깥 구역이 잘리는 곳**

- **안쪽 `.cardB` 에서** 잘린다. 바깥 카드에서 출발한 구역은 거기서 끝난다.

**그런데도 안쪽이 칠해진 이유**

```text
.cardB 가 둘이면 스코프도 둘 생긴다

  구역 ①  바깥 .cardB 부터 안쪽 .cardB 전까지     -> B1 을 칠한다
  구역 ②  안쪽 .cardB 부터 (그 아래 .cardB 없음)  -> B2 를 칠한다
```

- **`.cardB` 마다 스코프 인스턴스가 하나씩 생긴다.** B2 의 색은 **구역 ②**에서 온 것이다.
- 곧 이 관용구의 뜻은 「안쪽을 안 칠한다」가 아니라 「**각 카드가 자기 것만 칠한다**」이다.

**막아 주는 사고**

- `.card .title { … }` 처럼 자손 선택자로 쓰면 **바깥 카드의 규칙이 안쪽 카드의 제목까지 잡는다.**
- 바깥 카드가 「제목은 크게」, 안쪽 카드가 「제목은 작게」를 원할 때 둘이 충돌한다.
- `to (.card)` 가 그 충돌을 **구조적으로** 없앤다 — 명시도를 안 건드리고.

### 9. 오늘 이것을 써도 되는가

**Baseline 상태**

- **newly available** 이고 **2026-03-24** 에 그렇게 됐다(Safari 26.4 가 마지막으로 따라왔다).
- **widely 가 아니다.** 「그냥 써도 되는 것」 기준선(주요 엔진 30개월)에 아직 못 미친다.
- 출처는 [목록 README](../README.md) 의 지원 표 — `webstatus.dev` API 를 직접 조회한 값이다(2026-09-21 기준).

**지원 안 하는 브라우저에서**

- **`@scope { … }` 블록이 통째로 버려진다.** 모르는 at-rule 의 규칙이라 블록까지 같이 사라진다([07번 주제](../07-syntax-and-error-recovery/2-summary.md)).
- **에러도 경고도 없다.** 그 안의 스타일이 전부 안 먹은 화면이 나온다.

**CSS 안에서 질의하려면**

```text
실측 (Chrome 151)
  @supports at-rule(@scope)           { .t2 { color: #15803d } }  -> 먹었다   rgb(21, 128, 61)
  @supports at-rule(@totally-unknown) { .t2 { background: gold } } -> 안 먹었다 rgba(0, 0, 0, 0)
  CSS.supports('at-rule(@scope)')                                  -> true
```

- `@supports at-rule(@scope)` 로 질의한다(목록의 **41번 주제**).

**「무시됐을 때의 화면」을 설계해야 하는 이유**

- 버려지는 것이 **선언 하나가 아니라 블록 전체**이기 때문이다. 스코프 안에 넣어 둔 스타일이 몽땅 사라진다.
- 그래서 **기본 모양은 스코프 밖에 두고, `@scope` 는 「더 나은 경우」만 담는** 배치가 안전하다 — 점진적 향상의 형태 그대로다.

### 10. 다른 주제와 잇기

**근접성의 자리**

- **명시도(5단계) 뒤, 등장 순서(6단계) 앞**이다.
- 앞: 명시도 · 뒤: 등장 순서. 이 문서의 3번·4번 두 판이 양쪽에서 이 칸을 가뒀다.

**넷이 다 걸린 판을 읽는 순서**

```text
1 출처·중요도  (01번)
      ↓
4 캐스케이드 레이어  @layer       (05번)   ← 여기서 갈리면 아래는 안 본다
      ↓
5 명시도             (02번)
      ↓
5.5 스코프 근접성    @scope       (이 주제)
      ↓
6 등장 순서
```

- **레이어 → 명시도 → 근접성 → 순서.** 레이어가 명시도 앞이고 근접성이 명시도 뒤라는 것만 붙들면 된다.

**그림자 DOM 과 같은 격리인가**

- **아니다.**

| | 어디서 갈리나 | 세기 |
|---|---|---|
| 그림자 DOM | **2단계(문맥)** | 진짜 격리 |
| `@scope` | **5.5단계(근접성)** | 같은 문서 안의 우선 규칙 |

- `@scope` 는 **밖에서 명시도나 `!important` 로 들어오면 그대로 뚫린다.** 캡슐화가 아니라 **편의**다.

**스코프 밖이라 아무 선언도 안 걸린 요소**

- **상속 또는 초기값**이 값을 채운다([03번 주제](../03-inheritance-and-global-keywords/2-summary.md)).
- 실측 판에서 스코프 밖 문단이 `rgb(0, 0, 0)` 이었던 것은 「스코프가 검정을 칠한 것」이 아니라 **아무도 칠하지 않아 상속·초기값이 남은 것**이다.

## 용어 풀이

- **`@scope`** — 선택자에 「어디서부터 어디까지」를 붙이는 at-rule.
- **스코프 루트(scope root)** — `@scope (선택자)` 가 고른 요소. 자신도 구역 안.
- **하한(scope limit)** — `to (선택자)` 가 고른 요소. **그 요소부터 아래가 구역 밖.**
- **도넛 스코프(donut scope)** — 루트부터 하한 전까지, 가운데가 뚫린 구역.
- **근접성(proximity)** — 요소에서 루트까지 조상 칸 수. 적을수록 이긴다. **5.5단계.**
- **스코프 인스턴스** — 루트 선택자에 매치되는 요소마다 하나씩 생기는 구역. 중첩된 컴포넌트에서 여러 개가 된다.
- **암묵 루트(implicit scope root)** — `@scope { }` 의 루트. 그 `<style>` 의 **부모 요소**.
- **`:scope`** — 루트를 가리키는 의사 클래스. 명시도에 `(0,1,0)` 을 더한다.
- **프렐류드(prelude)** — at-rule 이름 뒤 블록 앞. `@scope` 에서는 명시도에 **기여하지 않는다**.
- **상대 선택자(relative selector)** — 기준 요소에 대한 상대 경로로 읽히는 선택자.
- **Baseline newly available** — 주요 엔진 전부에 들어왔지만 저변 도달(30개월)은 아직인 상태.
