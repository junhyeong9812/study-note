# css/syntax/06 — `@scope`: 스코프 루트·하한과 근접성(proximity) — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Cascading and Inheritance Level 6](https://drafts.csswg.org/css-cascade-6/) 의 「Scoped Styles」·「Cascade Sorting Order」(Scope Proximity) 절. 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 모든 색은 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워 `getComputedStyle` 로 읽은 것이다. 하네스는 [3-answer.md](3-answer.md) 의 `## 실행 검증` 절에 있다.\
> **엔진은 Chrome 하나다** — Firefox 155.0.1 은 이 환경에서 headless 산출이 조용히 실패하고 WebKit 은 없다. 「두 엔진에서 확인했다」고 적지 않는다.
> **버전** — ★ `@scope` 는 Baseline **newly available**(2026-03-24 — Safari 26.4 가 마지막으로 따라왔다). **widely 는 아직 아니다.** 「그냥 써도 되는 것」 기준선(주요 엔진 30개월)에 못 미치므로, 쓸 때 대체 경로를 함께 생각한다. 출처는 [목록 README](../README.md) 의 지원 표(`webstatus.dev` API 조회, 2026-09-21).
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 값은 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**`@scope` = 선택자에 「여기서부터 저기까지」라는 구역을 붙이는 것이다.**

건물 층에 비유한다. 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 「3층에서」 | **스코프 루트** — `@scope (.card)` 의 `.card` |
| 「단, 옥상 정원부터는 제외」 | **하한(limit)** — `to (.content)` |
| 구역 안에서만 붙는 안내문 | 그 블록 안의 규칙들 |
| 안내문이 여럿 붙었을 때 가까운 층 것을 본다 | **근접성(proximity)** |
| 층 표시 자체 | `:scope` 또는 `&` |

- **구역은 도넛 모양으로 뚫을 수 있다.** 위는 `.card` 부터, 아래는 `.content` 전까지 — 그 사이만 칠한다.
- **근접성은 새 심사위원이다.** 명시도(5단계)와 등장 순서(6단계) **사이**에 끼어든다.
- 그래서 **스코프가 명시도를 이기지는 못한다.** 이것이 `@layer`(4단계)와 결정적으로 다른 점이다.

```text
  캐스케이드 정렬 (01번이 정본)          @scope 가 끼워 넣는 칸
  1 출처·중요도
  2 문맥
  3 요소 부착 스타일
  4 캐스케이드 레이어                    <- @layer (05번)
  5 명시도                               <- @scope 는 여기를 못 이긴다
  5.5 스코프 근접성     ★ 여기          <- @scope
  6 등장 순서                            <- 근접성이 이것보다는 앞이다
```

실무에서 이게 필요해지는 자리는 **테마가 중첩될 때**다.\
`.theme-light` 안에 `.theme-dark` 가 들어가면, 안쪽 요소는 두 테마의 규칙에 **둘 다 매치된다.**\
선택자로 풀려면 `.theme-light .theme-dark .txt` 같은 것을 손으로 다 써야 하는데, `@scope` 는 **「더 가까운 쪽」 하나로 끝낸다.**

> **스코프 루트(scope root)** — `@scope (선택자)` 가 고른 요소. 그 요소와 그 자손이 구역 안이다.\
> 예: `@scope (.card)` 면 `.card` 자신과 그 안쪽 전부.

> **하한(scope limit)** — `to (선택자)` 가 고른 요소. **그 요소부터 아래가 구역 밖**이다.\
> 예: `@scope (.card) to (.content)` 면 `.content` 자신도 구역 밖이다.

> **근접성(proximity)** — 그 요소에서 스코프 루트까지 조상을 몇 칸 올라가야 하나. 적을수록 이긴다.\
> 예: 부모가 루트면 1칸, 할아버지가 루트면 2칸.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. `@scope (.root) to (.limit)` 는 **정확히 어느 요소들에 걸리는가.** 하한 요소 자신은 안인가 밖인가.
2. **근접성이 캐스케이드의 어느 자리에 끼어드는가.** 명시도·등장 순서와 각각 붙으면 어느 쪽이 이기는가.
3. 스코프 루트 선택자는 **명시도에 기여하는가.** `:scope` 를 쓰면 달라지는가.

## 동작 방식

### (1) 구역 — 루트부터 하한 전까지

**언제 쓰나** — 컴포넌트 안쪽만 칠하고 싶은데 **안쪽에 또 다른 컴포넌트가 들어올 수 있을 때.**

```text
@scope (.card) to (.content) { .txt { color: #b91c1c } }

  <div class="card">              ← 스코프 루트.  구역 안
    <p class="txt">1</p>          ← 구역 안       실측 rgb(185, 28, 28)  빨강
    <div class="content">         ← 하한.         구역 '밖'
      <p class="txt">2</p>        ← 구역 밖       실측 rgb(0, 0, 0)      검정
    </div>
  </div>
  <p class="txt">3</p>            ← 구역 밖       실측 rgb(0, 0, 0)      검정
```

그림 해설 (한 단계씩):

- **하한 요소 자신도 구역 밖**이다. 실측에서 `.content` 에 직접 건 `background-color` 가 **안 먹었다**(`rgba(0, 0, 0, 0)`).\
  「`to` 앞까지」가 아니라 「`to` **부터** 밖」으로 읽는다.
- **루트 자신은 구역 안**이다. `:scope { outline: ... }` 이 `.card` 에 걸렸다(실측 `rgb(185, 28, 28) solid`).
- 이 모양을 **도넛 스코프(donut scope)** 라 부른다 — 가운데가 뚫린 구역이다.

```html demo
<div class="card">
  <p>1 카드 안 — 먹는다</p>
  <div class="content"><p>2 하한 안 — 안 먹는다</p></div>
</div>
<style>
  @scope (.card) to (.content) {
    p { color: #b91c1c; }
  }
  p { font: 18px/1.6 system-ui, sans-serif; margin: 6px 0; }
</style>
```

> **보이는 것** — 첫 줄만 **빨강**(`#b91c1c`)이고 둘째 줄은 **검정**이다. 둘 다 `.card` 의 자손이지만, 둘째 줄은 하한 `.content` 안에 있어 구역에서 잘려 나간다.\
> **바꿔 볼 것** — `to (.content)` 를 지우면 → **두 줄 다 빨강**이 된다(하한이 없으면 `.card` 아래 전부가 구역이다)

*(Chrome 151 headless 실측: 1번 `rgb(185, 28, 28)` · 2번 `rgb(0, 0, 0)`.)*

비용 — 없음(판정이다). 다만 **하한이 없는 `@scope` 는 그냥 자손 선택자와 거의 같다** — `to` 가 이 기능의 절반이다.

### (2) 근접성 — 가까운 스코프가 이긴다

**언제 쓰나** — 같은 종류의 스코프가 **중첩**될 때. `@scope` 를 쓰는 가장 큰 이유다.

```text
@scope (.theme-light) { .prox { color: #15803d } }    초록
@scope (.theme-dark)  { .prox { color: #1d4ed8 } }    파랑

  <div class="outer">
    <p class="prox">P0</p>                ← 어느 스코프에도 없다  실측 검정
    <div class="theme-light">
      <p class="prox">P1</p>              ← light 만 매치         실측 초록
      <div class="theme-dark">
        <p class="prox">P2</p>            ← 둘 다 매치            실측 파랑
      </div>                                  light 까지 2칸, dark 까지 1칸
    </div>
  </div>
```

그림 해설 (한 단계씩):

- P2 는 **두 규칙에 모두 매치된다.** 명시도가 같고(`(0,1,0)`), 등장 순서로는 나중에 쓴 `dark` 가 이길 텐데 — **그 이유로 이긴 게 아니다.**
- 실제로 이긴 이유는 **근접성**이다. 순서를 뒤집어 `dark` 를 먼저 써도 결과는 같다(다음 절의 실측).
- 이것이 `.theme-light .theme-dark .prox` 같은 선택자를 **손으로 안 써도 되게** 만든다.

```html demo
<div class="theme-light">
  <p class="txt">light 안</p>
  <div class="theme-dark">
    <p class="txt">dark 안 — 어느 쪽이 이길까</p>
  </div>
</div>
<style>
  @scope (.theme-light) { .txt { color: #15803d; } }
  @scope (.theme-dark)  { .txt { color: #1d4ed8; } }
  .theme-dark { padding: 2px 10px; background: #111827; }
  p { font: 18px/1.6 system-ui, sans-serif; margin: 6px 0; }
</style>
```

> **보이는 것** — 첫 줄은 **초록**(`#15803d`), 어두운 상자 안의 둘째 줄은 **파랑**(`#1d4ed8`). 둘째 줄은 두 스코프에 모두 들어 있는데, **더 가까운 `.theme-dark`** 쪽이 이긴다.\
> **바꿔 볼 것** — 두 `@scope` 블록의 **순서를 서로 바꿔도** → **결과가 그대로다**(근접성이 등장 순서보다 앞이라서)

*(Chrome 151 headless 실측: 첫 줄 `rgb(21, 128, 61)` · 둘째 줄 `rgb(29, 78, 216)`. 순서를 바꾼 판도 따로 던져 확인했다.)*

비용 — 근접성을 세려면 **조상을 거슬러 올라가야 한다.** 판정 비용은 있지만 실무에서 문제가 되는 수준은 아니다. *(이 문서에서 성능은 측정하지 않았다.)*

### (3) ★ 근접성의 자리 — 명시도 뒤, 순서 앞

**언제 쓰나** — 「스코프를 썼는데 왜 저쪽이 이기지」를 진단할 때. **이 절이 이 주제의 과녁이다.**

세 판을 따로 던져 자리를 양쪽에서 못 박았다.

```text
판 ①  근접성 대 명시도 — 먼 쪽이 훨씬 센 선택자를 쓴다
   @scope (.far)  { p#xid.x { color: #1d4ed8 } }    (1,1,1) · 2칸 멀다
   @scope (.near) { .x      { color: #15803d } }    (0,1,0) · 1칸 가깝다
   실측 -> rgb(29, 78, 216)  파랑.   ★ 명시도가 이겼다

판 ②  근접성 대 등장 순서 — 가까운 쪽을 '먼저' 쓴다
   @scope (.near2) { .y { color: #15803d } }        가깝다 · 먼저 썼다
   @scope (.far2)  { .y { color: #1d4ed8 } }        멀다   · 나중에 썼다
   실측 -> rgb(21, 128, 61)  초록.   ★ 근접성이 이겼다

판 ③  근접성이 같으면
   @scope (.n3) { .z { color: #15803d } }
   @scope (.n3) { .z { color: #1d4ed8 } }
   실측 -> rgb(29, 78, 216)  파랑.   순서가 정한다
```

```text
  이 세 판이 근접성의 자리를 양쪽에서 가둔다

  5 명시도        ──── 판 ① 이 여기서 졌다 (명시도가 더 세다)
  5.5 근접성      ★
  6 등장 순서     ──── 판 ② 가 여기를 이겼다 (근접성이 더 세다)
                       판 ③ 은 근접성이 동점일 때 여기로 내려간다
```

그림 해설 (한 단계씩):

- **명시도를 못 이긴다.** 이것이 `@layer`(4단계)와 결정적으로 다른 점이다 — 레이어는 명시도 **앞**, 스코프는 **뒤**다.
- 그래서 **`@scope` 는 명시도 싸움을 없애 주지 않는다.** 남의 시트를 덮는 용도로는 `@layer` 를, 중첩 테마를 푸는 용도로는 `@scope` 를 쓴다.
- 판 ②가 근접성이 **진짜 있는 단계**라는 증거다. 순서만으로 설명하면 판 ②에서 파랑이 나와야 한다.

비용 — 없음(판정 순서다).

### (4) 스코프 루트 선택자는 명시도에 기여하지 않는다

**언제 쓰나** — 스코프 안에서 선택자를 설계할 때. 놓치면 (3)의 판정을 잘못 세운다.

```text
판 ④  프렐류드에 ID 를 써도 기여가 없다
   @scope (#big) { .q   { color: #15803d } }    스코프 안 · (0,1,0)
   .q.q { color: #1d4ed8 }                      스코프 밖 · (0,2,0)
   실측 -> rgb(29, 78, 216)  파랑.   (0,2,0) 이 이겼다
                                     #big 이 기여했다면 (1,1,0) 이라 초록이어야 한다

판 ⑤  :scope 는 의사 클래스라 (0,1,0) 을 더한다
   @scope (#big2) { :scope .v { color: #15803d } }   (0,1,0)+(0,1,0) = (0,2,0)
   .v.v { color: #1d4ed8 }                            (0,2,0)
   실측 -> rgb(21, 128, 61)  초록.   명시도 동점 -> 근접성으로 갈렸다
                                     (스코프 밖 선언은 '무한히 멀다')
```

그림 해설 (한 단계씩):

- **프렐류드(`@scope (…)`)의 선택자는 명시도에 안 들어간다.** 판 ④가 그 증거다.
- 세고 싶으면 **규칙 안에 `:scope` 를 직접 쓴다.** 그때는 의사 클래스 하나만큼(`(0,1,0)`) 더해진다.
- **판 ⑤가 이 주제에서 가장 놓치기 쉬운 것**이다 — 스코프 밖 선언은 근접성이 **무한**으로 취급되므로, **명시도가 같으면 스코프 안이 언제나 이긴다.** 순서와 무관하게.

비용 — 없음.

### (5) 형태 넷 — `:scope`·`&`·암묵 루트·상대 선택자

**언제 쓰나** — `@scope` 를 실제로 쓸 때의 표면.

```text
① :scope 로 루트 자신을 가리킨다
   @scope (.card) { :scope { outline: 3px solid red } }   -> 실측 .card 에 걸렸다

② & 로도 가리킨다 (중첩의 & 와 같은 뜻)
   @scope (.amp) { & p { background-color: #fde68a } }    -> 실측 걸렸다

③ 프렐류드 없이 쓰면 암묵 루트 = 그 <style> 의 '부모 요소'
   <div class="w2">
     <p class="t">T</p>
     <style> @scope { .t { color: #b91c1c } } </style>
   </div>
   <p class="t">T2</p>
   -> 실측 T = rgb(185, 28, 28) 빨강 · T2 = rgb(0, 0, 0) 검정

④ 규칙 안 선택자는 루트에 대한 '상대 선택자'다
   @scope (.card) { .txt { ... } }  는 사실상 '.card 자손 중 .txt'
```

그림 해설 (한 단계씩):

- ③은 **HTML 안에 `<style>` 을 꽂는 컴포넌트 패턴**을 위한 형태다. 서버가 조각을 내려보낼 때 루트를 안 적어도 된다.
- ②의 `&` 는 중첩([목록의 **14번 주제**](../14-css-nesting/))의 `&` 와 같은 표면이라 섞어 쓰기 쉽다. `@scope` 안에서 `&` 는 **스코프 루트**를 가리킨다.
- ④ 때문에 `@scope (.card) { .card { ... } }` 는 **바깥 `.card` 가 아니라 그 안쪽의 또 다른 `.card`** 를 고른다. 루트 자신을 노리려면 `:scope` 를 쓴다.

비용 — 없음.

## 문법 — 형태와 규칙

CSS 는 문법 표면이 단순하므로 이 절은 「**형태 — 어디서 헷갈리나**」로 읽는다.

### 형태

```css
@scope (.card) { ... }                       /* 루트만 */
@scope (.card) to (.content) { ... }         /* 루트 + 하한 */
@scope (.card) to (:scope > .content) { ... }/* 하한을 루트 기준으로 */
@scope { ... }                               /* 암묵 루트 = <style> 의 부모 요소 */
@scope (.card) { :scope { ... } & p { ... } }/* 루트 자신 가리키기 */
```

### 금지 사례 — 뜻이 어긋나는 형태

```css
@scope (.card) { .card { color: red } }   /* 바깥 .card 가 아니라 안쪽의 또 다른 .card */
@scope (.a) to (.b) { .b { color: red } } /* 하한 요소 자신은 구역 밖 — 절대 안 걸린다 */
@scope (#big)  { .q { color: red } }      /* #big 은 명시도에 기여하지 않는다 */
```

**에러는 안 난다.** 전부 유효한 CSS 이고, 다만 **내가 생각한 요소에 안 걸릴 뿐**이다.

### 어디서 헷갈리나

- **`to` 는 「\~까지 포함」이 아니라** 「**\~부터 제외**」다.
- **프렐류드는 명시도에 기여하지 않는다.** 선택자를 쓴 자리가 보여서 셀 것 같지만 안 센다.
- **스코프 밖 선언은** 「**무한히 멀다**」로 취급된다 — 명시도가 같으면 스코프 안이 언제나 이긴다.
- **근접성은 명시도를 못 이긴다.** `@layer` 와 헷갈리면 방향을 거꾸로 잡는다.

## 어디서 틀리나

이 주제의 값어치는 전부 여기 있다. 여섯 다 **에러 없이 조용히 어긋난다.**

### 1. 하한 요소 자신이 구역 안일 거라 생각한다

```text
@scope (.card) to (.content) { .content { background: gold } }

기대                                실제 (실측)
+--------------------------+       +--------------------------+
| .content 에 금색 배경     |       | background-color =       |
|                          |       |   rgba(0, 0, 0, 0)       |
+--------------------------+       +--------------------------+
```

**하한 요소는 이미 밖**이다. 그 요소를 칠하려면 스코프 밖에서 따로 쓴다.

### 2. `@scope` 가 명시도를 이겨 줄 거라 기대한다

실측 판 ①에서 **먼 스코프의 `(1,1,1)` 이 가까운 스코프의 `(0,1,0)` 을 이겼다.**\
근접성은 명시도 **뒤**다. 남의 시트를 덮는 문제는 `@scope` 로 안 풀린다 — 그것은 [05번 주제](../05-cascade-layers/2-summary.md)의 일이다.

### 3. 프렐류드의 ID 가 명시도를 올려 줄 거라 생각한다

`@scope (#big) { .q { ... } }` 의 명시도는 **`(0,1,0)`** 이다(실측으로 `(0,2,0)` 에 졌다).\
세고 싶으면 규칙 안에 `:scope` 를 쓴다 — 그때 `(0,1,0)` 이 더해진다.

### 4. 「나중에 쓴 쪽이 이긴다」로 설명한다

판 ②에서 **가까운 쪽을 먼저 썼는데도 이겼다.** 근접성이 순서보다 앞이기 때문이다.\
순서 모델만 갖고 있으면 중첩 테마에서 예측이 절반씩 맞아 **틀린 모델이 오래 유지된다.**

### 5. `@scope (.card) { .card { … } }` 로 루트를 노린다

규칙 안 선택자는 **루트에 대한 상대 선택자**라, 이것은 **`.card` 안의 또 다른 `.card`** 를 고른다.\
루트 자신은 `:scope` 또는 `&` 로 가리킨다.

### 6. Baseline 을 확인하지 않고 쓴다

★ `@scope` 는 2026-09 기준 **newly available**(2026-03-24)이고 **widely 가 아니다.**\
저변 도달 전이므로 **구형 브라우저에서는 그 블록이 통째로 무시된다** — 무시됐을 때 화면이 어떻게 보이는지를 같이 설계해야 한다.\
`@supports at-rule(@scope)` 로 질의할 수 있다([목록의 **41번 주제**](../41-supports-feature-queries/)).

```text
실측 (Chrome 151)
  @supports at-rule(@scope)            { .t2 { color: #15803d } }   -> 먹었다  rgb(21, 128, 61)
  @supports at-rule(@totally-unknown)  { .t2 { background: gold } } -> 안 먹었다 rgba(0, 0, 0, 0)
  CSS.supports('at-rule(@scope)')                                    -> true
```

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 루트는 구역 안, 하한 요소는 구역 밖 | **명세**(css-cascade-6 「Scoped Styles」) |
| 근접성이 명시도 뒤·등장 순서 앞 | **명세**(「Cascade Sorting Order」) |
| 스코프 밖 선언이 「무한히 먼」 것으로 취급되는 것 | **명세** |
| 프렐류드가 명시도에 기여하지 않는 것 | **명세** |
| `:scope` 가 의사 클래스 하나만큼 기여하는 것 | **명세**(선택자 명세) |
| 암묵 루트가 `<style>` 의 부모 요소인 것 | **명세** |
| 위 전부가 Chrome 151 에서 그대로 관찰된 것 | **관찰.** 다른 엔진에서는 확인하지 않았다 |
| `@scope` 를 오늘 써도 되는가 | **Baseline newly available**(2026-03-24) — 2차 집계(`webstatus.dev`)로 접지. **widely 아님** |
| 근접성 판정의 성능 비용 | **측정하지 않았다.** 이 문서는 수치를 싣지 않는다 |
| `@supports at-rule(@scope)` 가 통과하는 것 | **관찰**(Chrome 151). 질의 문법 자체는 명세 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 테마가 중첩될 수 있다(`light` 안의 `dark`) | `@scope` 의 근접성 | `.light .dark .x` 조합을 손으로 나열 |
| 카드 안에 다른 카드가 들어올 수 있다 | `@scope (.card) to (.card)` 도넛 | `.card .title` (안쪽 카드까지 잡는다) |
| 슬롯 안쪽은 건드리면 안 된다 | `@scope (.wrap) to (.slot)` | `:not()` 조합으로 빼기 |
| 남의 시트를 덮어야 한다 | **`@layer`**(05번) | `@scope`(명시도를 못 이긴다) |
| 명시도를 0 으로 누르고 싶다 | `:where()`([목록의 **11번 주제**](../11-is-where-not/)) | `@scope` |
| 서버가 HTML 조각을 내려보낸다 | `@scope { }` 암묵 루트 | 조각마다 고유 클래스 생성 |
| 아직 구형 브라우저를 지원해야 한다 | 기존 선택자 + 대체 경로 | `@scope` 단독(newly 라 저변 미도달) |

판단 규칙 두 줄.

- **`@scope` 는 「어디까지」를 푸는 도구이지 「누가 이기나」를 푸는 도구가 아니다.** 후자는 `@layer` 다.
- **`to` 가 없으면 굳이 쓸 이유가 적다.** 하한과 근접성 둘 중 하나가 필요할 때만 꺼낸다.

## 핵심 문장

- `@scope (.root) to (.limit)` 의 구역은 **루트를 포함하고 하한 요소부터 제외**한다 — 가운데가 뚫린 도넛이다.
- **근접성은 캐스케이드의 새 칸**이다. **명시도 뒤, 등장 순서 앞**에 끼어든다.
- 그래서 **`@scope` 는 명시도를 못 이긴다** — 명시도 앞에 서는 `@layer`(4단계)와 층이 다르다.
- **스코프 밖 선언은** 「**무한히 멀다**」로 취급되므로, 명시도가 같으면 **스코프 안이 순서와 무관하게 이긴다.**
- **프렐류드의 선택자는 명시도에 기여하지 않는다.** 세고 싶으면 규칙 안에 `:scope` 를 쓴다.
- 규칙 안 선택자는 **루트에 대한 상대 선택자**라 `@scope (.card) { .card { … } }` 는 **안쪽의 또 다른 `.card`** 를 고른다.
- Baseline **newly available**(2026-03-24) — widely 가 아니다. 무시됐을 때의 화면을 같이 설계한다.

## 용어 풀이

- **`@scope`** — 선택자에 「어디서부터 어디까지」라는 구역을 붙이는 at-rule.
- **스코프 루트(scope root)** — `@scope (선택자)` 가 고른 요소. 자신도 구역 안이다.
- **하한(scope limit)** — `to (선택자)` 가 고른 요소. **그 요소부터 아래가 구역 밖**이다.
- **도넛 스코프(donut scope)** — 루트부터 하한 전까지, 가운데가 뚫린 구역 모양.
- **근접성(proximity)** — 요소에서 스코프 루트까지 조상을 몇 칸 올라가나. 적을수록 이긴다.
- **암묵 루트(implicit scope root)** — 프렐류드 없이 `@scope { }` 를 쓸 때의 루트. 그 `<style>` 의 부모 요소.
- **`:scope`** — 스코프 루트를 가리키는 의사 클래스. 명시도에 `(0,1,0)` 을 더한다.
- **`&`** — `@scope` 안에서 스코프 루트를 가리키는 표기. 중첩의 `&` 와 같은 표면.
- **프렐류드(prelude)** — at-rule 이름 뒤, 블록 앞의 부분. `@scope` 에서는 `(.root) to (.limit)` 이 그것이고 **명시도에 기여하지 않는다.**
- **상대 선택자(relative selector)** — 기준 요소에 대한 상대 경로로 읽히는 선택자. `@scope` 블록 안 선택자가 그렇다.
- **Baseline newly available** — 주요 엔진 전부에 들어왔지만 저변 도달(30개월)은 아직인 상태.

## 더 들어가면

- **`@scope (.card) to (.card)` 가 「같은 컴포넌트의 중첩」을 푸는 관용구**다. 바깥 카드에서 출발한 구역은 안쪽 카드를 만나는 순간 잘린다.\
  ★ 그렇다고 안쪽 카드의 내용이 안 칠해지는 것은 아니다 — **`.card` 마다 스코프가 하나씩 생기므로** 안쪽 카드는 *자기* 구역에서 칠해진다.\
  실측: 중첩된 `.cardB` 두 겹에서 바깥 글자와 안쪽 글자가 **둘 다 초록**이었다. 관용구의 뜻은 「안쪽을 안 칠한다」가 아니라 「**각 카드가 자기 것만 칠한다**」이다.
- **`@scope` 는 그림자 DOM 의 대체가 아니다.** 그림자 DOM 은 캐스케이드 **2단계(문맥)** 에서 갈리는 진짜 격리이고, `@scope` 는 5.5단계에 끼는 **같은 문서 안의 우선 규칙**이다. 스코프 밖에서 `!important` 로 들어오면 그대로 뚫린다.
- **`:scope` 는 `@scope` 전부터 있던 의사 클래스**다. `element.querySelector(':scope > li')` 처럼 DOM API 에서 「기준 요소」를 가리키는 데 쓰였고, `@scope` 가 그 의미를 CSS 쪽으로 가져온 것이다.
- **근접성이 「무한」인 선언**이라는 개념 덕분에, `@scope` 를 한 곳에만 써도 **문서 전체의 판정에 새 칸이 생긴다.** 스코프를 안 쓴 규칙이 스코프 안 규칙에 지는 판(판 ⑤)이 그 결과다 — 도입할 때 예상 밖의 승패가 여기서 나온다.
