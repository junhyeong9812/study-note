# css/syntax/35 — `calc()`·`clamp()`·`min()`/`max()` — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Values and Units Level 4](https://drafts.csswg.org/css-values-4/) 의 「Mathematical Expressions」 절(`calc()`·`min()`/`max()`/`clamp()` 의 문법·타입 검사·직렬화). 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 모든 값은 **Google Chrome 151.0.7922.173** headless 에 띄워 **두 창**으로 읽은 것이다 — `document.styleSheets[0].cssRules[i].style`(**무엇이 담겼나**)와 `getComputedStyle`(**무엇으로 계산됐나**). 둘이 다른 자리가 이 주제의 값이다. **손으로 계산해 유도한 수치는 없다.**\
> **엔진은 Chrome 하나다** — Firefox 155.0.1 은 이 환경에서 headless 산출이 조용히 실패하고 WebKit 은 이 머신에 없다. 「두 엔진에서 확인했다」고 적지 않는다.
> **버전** — CSS 에 언어 버전은 없다. `calc()` 는 CSS Values 3, `min()`/`max()`/`clamp()` 는 Baseline **widely**(newly 2020-07-28 · widely 2023-01-28)다. 근거는 [목록 README](../README.md) 의 지원 표다.
> **여기서 다루지 않는 것** — **계산이 어느 단계에서 끝나는가**는 [04번](../04-value-processing-stages/2-summary.md)이 정본이다. 여기는 **그 단계에 무엇을 넘겨주는가**까지다. 단위 자체는 [33번](../33-length-units/2-summary.md)·[34번](../34-viewport-and-container-units/2-summary.md), 무효한 선언이 버려지는 규칙은 [07번](../07-syntax-and-error-recovery/2-summary.md)이 정본이다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 값은 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**수학 함수 = 「단위가 다른 자 여러 개를 한 줄에서 섞어 쓰는 법」이다.**

CSS 의 값은 원래 **자 하나로만** 잰다 — `400px` 이거나 `50%` 이거나. `calc()` 는 그 둘을 더할 수 있게 해 주고, `min()`/`max()`/`clamp()` 는 **여러 자 중 하나를 고르게** 해 준다.

치수를 재는 목수에 비유한다. 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 「방 폭에서 문틀 20cm 를 뺀 만큼」 | **`calc()`** — 서로 다른 자의 값을 더하고 뺀다 |
| 「방 폭과 3m 중 작은 쪽」 | **`min()`** — 골라서 **상한**을 만든다 |
| 「방 폭과 1m 중 큰 쪽」 | **`max()`** — 골라서 **하한**을 만든다 |
| 「1m 이상 3m 이하로, 그 안에서는 방 폭만큼」 | **`clamp(하한, 원하는 값, 상한)`** |
| 「도면에 적을 때는 접어서 적는다」 | 파싱 시점에 **미리 접힌다** — `calc(2*100px)` 이 `calc(200px)` 로 담긴다 |

```text
  같은 선언을 두 창으로 읽으면 다르게 보인다

    적은 것            cssRules 에 담긴 것        getComputedStyle
    -----------------  ------------------------  ----------------
    calc(100% - 10px)  calc(100% - 10px)         390px
    calc(2 * 100px)    calc(200px)         ★      200px
    calc(100% -10px)   (비었다 — 버려졌다) ★       400px  (= auto)
    clamp(300px,10px,100px)  calc(300px)   ★      300px
```

*(Chrome 151 실측 — 부모 폭 400px. `cssRules[i].style.getPropertyValue('width')` 와 `getComputedStyle().width` 를 나란히 읽었다.)*

실무에서 이게 터지는 자리는 **`+`/`-` 양옆의 공백을 뺐을 때**다.\
선언 하나가 **에러도 경고도 없이 통째로 사라지고**, 화면에는 「아무것도 안 먹었다」로만 보인다.

> **토큰(token)** — CSS 파서가 문자열을 잘라 만드는 최소 단위. 숫자와 단위가 붙은 `10px` 은 **하나의 토큰**이다.\
> 예: `100% -10px` 에서 `-10px` 은 「빼기」가 아니라 **음수 길이 토큰 하나**로 읽힌다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. **`+`/`-` 양옆에 왜 공백이 필요한가** — 안 쓰면 무엇이 일어나고, `*`/`/` 는 왜 안 그런가.
2. **`clamp(a, b, c)` 에서 `a > c` 이면 누가 이기는가** — 직관과 다른 답이 나오는 이유는.
3. **계산은 언제 일어나는가** — 파싱 때 접히는 것과 레이아웃 때 풀리는 것이 어떻게 갈리나.

## 동작 방식

### (1) ★ `+`/`-` 는 양옆에 공백이 필수다 — 없으면 선언이 통째로 버려진다

**언제 쓰나** — 「`calc` 를 썼는데 아무 일도 안 일어난다」의 첫 번째 용의자. **이 절이 이 주제에서 가장 자주 터지는 자리다.**

```text
부모 폭 400px 에서 다섯 형태를 던졌다 (Chrome 151 실측)

  적은 것                cssRules 에 담긴 값        computed width
  ---------------------  ------------------------   --------------
  calc(100% - 10px)      calc(100% - 10px)          390px    <- 된다
  calc(100% -10px)       (비었다 — 버려졌다)          400px    <- auto
  calc(100% +10px)       (비었다 — 버려졌다)          400px
  calc(100%-10px)        (비었다 — 버려졌다)          400px
  ---------------------  ------------------------   --------------
  calc(100%/2)           calc(50%)                  200px    <- 공백 없어도 된다
  calc(2*100px)          calc(200px)                200px    <- 〃
```

```text
  왜 +/- 만 다른가 — 부호가 숫자에 붙기 때문이다

    "100% -10px" 을 파서가 자르면
        [100%]  [-10px]              <- 토큰 두 개. 사이에 연산자가 없다
                 └ 부호가 숫자에 붙어 '음수 길이' 한 덩어리가 된다
        => 연산자 없이 값 둘이 나란히 => 무효

    "100% - 10px" 을 자르면
        [100%]  [-]  [10px]          <- 가운데가 연산자 토큰이다
        => 유효

    "100%/2" 를 자르면
        [100%]  [/]  [2]             <- '/' 는 숫자에 붙지 않는다
        => 공백이 없어도 연산자가 보인다
```

그림 해설 (한 단계씩):

- **`-`·`+` 는 숫자의 부호로도 쓰이는 문자**라, 공백이 없으면 파서가 연산자인지 부호인지 가를 수 없다.
- `*`·`/` 는 숫자의 일부가 될 수 없으므로 **공백이 없어도 연산자로만 읽힌다**(실측: `calc(100%/2)` 가 `calc(50%)` 로 담겼다).
- 실패했을 때 **선언 하나가 통째로 사라진다** — `cssRules` 창으로 보면 속성 목록에 아예 없다. 「버려졌다」의 정본은 [07번](../07-syntax-and-error-recovery/2-summary.md)이다.
- 화면 증상은 「**선언을 안 쓴 것과 똑같다**」뿐이라 눈으로는 절대 안 잡힌다.

비용 — 없음. 다만 **규칙이 대칭이 아니라서 외우기 나쁘다.** 「`calc()` 안에서는 연산자 양옆에 항상 공백」으로 외우면 `*`/`/` 에도 안전하다.

### (2) 타입 검사 — `*` 와 `/` 는 한쪽이 숫자여야 한다

**언제 쓰나** — 길이끼리 곱하거나 나눴는데 선언이 사라질 때.

```text
Chrome 151 실측 (부모 폭 400px)

  적은 것                 담긴 값             computed   왜
  ----------------------  ------------------  ---------  -----------------------------
  calc(100% * 0.5)        calc(50%)           200px      길이 x 숫자 = 길이  OK
  calc(2 * 100px)         calc(200px)         200px      〃
  calc(100% / 4)          calc(25%)           100px      길이 / 숫자 = 길이  OK
  calc(100px * 0)         calc(0px)           0px        〃 (0 도 숫자다)
  ----------------------  ------------------  ---------  -----------------------------
  calc(10px * 20px)       (비었다)             400px      길이 x 길이 = 면적 — <length> 아님
  calc(400px / 10px)      (비었다)             400px      길이 / 길이 = 숫자 — <length> 아님
  calc(100px + 10)        (비었다)             400px      길이 + 숫자 — 타입이 안 맞는다
```

```text
  타입 계산 규칙

     길이  +  길이   =  길이      OK
     길이  +  %      =  길이      OK  (% 는 레이아웃 때 길이가 된다)
     길이  x  숫자   =  길이      OK
     길이  /  숫자   =  길이      OK
     길이  x  길이   =  면적      X   <length> 자리에 못 넣는다
     길이  /  길이   =  숫자      X   〃 (다만 <number> 자리에는 넣을 수 있다)
     길이  +  숫자   =  (없음)    X
```

그림 해설 (한 단계씩):

- **곱셈·나눗셈에서는 한쪽이 반드시 숫자**여야 길이가 나온다. 수학적으로 당연한데 **에러가 안 나와서** 잡기 어렵다.
- `calc(400px / 10px)` 는 **수학적으로는 40 이라는 숫자**다. 값 자체가 틀린 게 아니라 **`width` 가 `<length>` 를 요구해서** 안 맞는 것이다.
- 그래서 `opacity` 처럼 `<number>` 를 받는 속성에서는 나눗셈이 산다 — 실측: `opacity: calc(1 / 3)` 이 `calc(0.333333)` 으로 담기고 계산값 `0.333333` 이 됐다.

비용 — 없음. 다만 **「타입이 안 맞는다」와 「문법이 틀렸다」가 같은 증상**(선언이 사라짐)을 낸다.

### (3) ★ `calc()` 안에서는 0 에도 단위가 필요하다

**언제 쓰나** — 「`0` 은 단위를 생략해도 된다」를 `calc()` 안에 그대로 들고 들어갔을 때.

```text
Chrome 151 실측

  적은 것              담긴 값         computed   비고
  -------------------  --------------  ---------  --------------------------
  width: 0             (그대로)         0px        ★ calc 밖에서는 된다
  calc(100% - 0)       (비었다)         400px      ★ calc 안에서는 안 된다
  calc(0 + 100px)      (비었다)         400px      〃
  calc(100% - 0px)     calc(100% + 0px) 400px      단위를 붙이면 된다
  calc(100px * 0)      calc(0px)        0px        곱셈의 0 은 '숫자' 라 된다
```

그림 해설 (한 단계씩):

- **`calc()` 밖의 `0` 은 「길이 0」으로 특별 대우**를 받는다. 안에서는 **그냥 숫자 0** 이다.
- 그래서 `100% - 0` 은 「**길이 빼기 숫자**」가 되어 (2) 의 타입 검사에 걸린다.
- **곱셈의 0 은 문제가 없다** — 곱셈은 애초에 한쪽이 숫자여야 하므로 `0` 이 제자리에 있다.
- `calc(100% - 0px)` 이 **`calc(100% + 0px)` 로 담긴 것**도 볼 만하다 — 엔진이 뺄셈을 「음수 더하기」로 정규화한다.

비용 — 없음. **「`calc()` 안에서는 0 도 단위를 붙인다」** 한 줄로 외운다.

### (4) ★ `clamp(a, b, c)` 에서 `a > c` 이면 — **`a`(하한)가 이긴다**

**언제 쓰나** — 상하한을 변수로 넣었다가 뒤집혔을 때. **직관과 다른 답이 나오는 자리다.**

```text
Chrome 151 실측 (부모 폭 400px, 50% = 200px)

  적은 것                       담긴 값                     computed
  ----------------------------  --------------------------  --------
  clamp(100px, 50%, 300px)      clamp(100px, 50%, 300px)    200px    <- 정상
  clamp(300px, 50%, 100px)      clamp(300px, 50%, 100px)    300px    ★ a 가 이긴다
  clamp(300px, 10px,  100px)    calc(300px)            ★     300px
  clamp(300px, 999px, 100px)    calc(300px)            ★     300px
```

```text
  왜 a 가 이기나 — clamp 는 max 와 min 의 합성이기 때문이다

    clamp(a, b, c)  ==  max(a, min(b, c))

    clamp(300, 50%, 100) 을 풀면
        ① min(b, c) = min(200, 100) = 100     <- 상한 100 이 먼저 깎는다
        ② max(a, ①) = max(300, 100) = 300     <- 그 다음 하한 300 이 끌어올린다
                                                  ★ 하한이 나중이라 이긴다

    근거 실측: clamp(100px, 50%, 300px) 와
               max(100px, min(50%, 300px)) 가 둘 다 200px 이었다
```

그림 해설 (한 단계씩):

- **`clamp` 는 「하한을 나중에 적용」한다.** 그래서 상하한이 뒤집히면 **하한이 무조건 이긴다.**
- **직관**은 「**말이 안 되니 무효가 되겠지**」인데, 그렇지 않다 — **값이 나온다.** 무효가 아니라 **조용히 `a`** 다.
- ★ **`b` 가 무엇이든 상관없다.** `10px` 이든 `999px` 이든 똑같이 `300px` 이 나왔다.
- ★ **Chrome 151 은 `%`·뷰포트 단위가 없으면 파싱 시점에 아예 접어 버린다** — `clamp(300px,10px,100px)` 이 `cssRules` 에 **`calc(300px)`** 로 담혔다.\
  즉 **두 번째·세 번째 인자가 흔적도 없이 사라진다.** 디버깅할 때 「내가 적은 대로 안 보인다」가 여기서 나온다.
- 같은 이유로 `min(500px, 50%, 120px)` 은 **인자를 셋 이상 받는다** — 실측 120px(셋 중 최소).

비용 — 없음. 다만 **상하한을 변수로 넣을 때는 순서를 코드로 보장할 수 없다.** 뒤집혀도 에러가 안 난다.

### (5) `min()` 은 최댓값을 만든다 — 이름의 함정

**언제 쓰나** — 「최대 폭 300px」을 적으려다 `max()` 를 골랐을 때.

```text
Chrome 151 실측 (부모 폭 400px)

  적은 것              computed   무엇을 만들었나
  -------------------  ---------  --------------------------------
  min(100%, 300px)     300px      ★ 상한 300 (max-width 와 같은 일)
  max(100%, 300px)     400px      ★ 하한 300 (min-width 와 같은 일)
  min(150px, 50%)      150px
  max(150px, 50%)      200px
  min(500px, 50%, 120px)  120px   인자는 둘 이상 얼마든지
```

```text
  이름과 효과가 반대로 읽힌다

    min(..., 300px)  →  "300 보다 커지지 않는다"  →  상한(최대)
    max(..., 300px)  →  "300 보다 작아지지 않는다" →  하한(최소)

    기억법: 함수 이름은 '고르는 방법' 이고,
            효과는 그 반대편의 '한계' 다.
```

그림 해설 (한 단계씩):

- **함수 이름**은 「**어느 쪽을 고르나**」를 말하고, **효과**는 「**어느 쪽으로 못 넘어가나**」를 만든다.
- `min-width`/`max-width` 속성과 **짝이 반대**라서 실수가 잦다 — `max-width: 300px` 과 같은 일을 하는 것은 **`min(…, 300px)`** 이다.
- 인자 개수에 제한이 없다는 점도 실무에서 쓸모 있다(실측 3인자).

비용 — 없음. 이름 함정뿐이다.

### (6) 계산은 두 번에 나눠 일어난다 — 04번 위에 얹는다

**언제 쓰나** — `getComputedStyle` 이 `calc(...)` 를 그대로 돌려줄 때.

```text
  ① 파싱 시점 — 접을 수 있는 것은 접어서 담는다

     적은 것                        cssRules 에 담긴 것
     -----------------------------  -------------------------
     calc(2 * 100px)                calc(200px)
     calc(-100px + 300px)           calc(200px)
     calc(calc(100%/2) + calc(10px*2))  calc(50% + 20px)   <- 중첩이 평탄해졌다
     calc(100% - calc(10px + 10px))     calc(100% - 20px)
     calc(10em + 5% + 20px)         calc(5% + 10em + 20px) <- 순서가 바뀌었다
     rotate(calc(45deg + 45deg))    rotate(calc(90deg))
     calc(1e2px + 1px)              calc(101px)
     calc((100% - 40px) / 3)        calc(33.3333% - 13.3333px)  ★ 소수 4자리로 잘렸다

  ② 계산값·사용값 시점 — 나머지를 푼다

     calc(5% + 10em + 20px)  --(글꼴 20px, 부모 폭 400)-->  240px
     calc(33.3333% - 13.3333px)                        -->  119.984px  ★ 120 이 아니다
```

그림 해설 (한 단계씩):

- **`%`·뷰포트 단위·`var()` 가 없으면 파싱 때 숫자 하나로 접힌다.** 그래서 `cssRules` 에 적은 그대로 안 보인다.
- **`em` 은 접히지 않는다** — 글꼴이 정해져야 풀리므로 `calc(5% + 10em + 20px)` 처럼 남는다. 순서만 정규화됐다.
- ★ **`(100% - 40px) / 3` 이 `33.3333% - 13.3333px` 로 잘렸다.** 정확히 1/3 이 아니라 **소수 넷째 자리에서 끊긴 값**이 저장됐고, 계산값도 **119.984px**(120 이 아니다)로 나왔다.\
  **Chrome 151 의 직렬화 정밀도**이지 명세가 정한 것이 아니다.
- **상자가 없으면 `%` 를 못 푼다** — 실측: `display: none` 인 요소의 `getComputedStyle().width` 가 **`calc(100% - 10px)` 그대로** 나왔다.\
  이것이 [04번](../04-value-processing-stages/2-summary.md)의 「③ 사용값이 없으면 ② 계산값을 준다」의 `calc()` 판이다. **정본은 04번이고 여기서 다시 쓰지 않는다.**

비용 — 없음. 다만 **디버깅할 때 「적은 것」과 「담긴 것」을 따로 봐야 한다.**

### (7) 음수와 0으로 나누기 — 에러가 아니라 값이 나온다

**언제 쓰나** — 계산 결과가 음수가 되거나, 변수에 0 이 들어왔을 때.

```text
Chrome 151 실측 (부모 폭 400px)

  적은 것             담긴 값                 computed width
  ------------------  ----------------------  -----------------
  calc(10px - 100px)  calc(-90px)             0px        <- 속성이 0 으로 깎았다
  calc(100px / 0)     calc(infinity * 1px)    3.35544e+07px
```

그림 해설 (한 단계씩):

- **`calc()` 는 음수를 그대로 만든다.** 무효가 아니다 — `cssRules` 에 `calc(-90px)` 이 담겼다.
- 걸러 낸 것은 **속성 쪽**이다. `width` 는 음수를 못 받으므로 **사용값에서 0 으로 깎였다.**\
  그래서 「무효가 아니라 0 이 된다」 — `margin` 처럼 음수를 받는 속성에서는 그대로 산다.
- ★ **0 으로 나눠도 에러가 아니다.** `calc(infinity * 1px)` 이라는 값이 만들어지고, 계산값은 **3.35544e+07px**(Chrome 이 자르는 상한)이 됐다.\
  **에러가 없는 언어**라서 「말도 안 되는 값」이 조용히 화면에 나간다.
- `3.35544e+07` 은 **Chrome 151 의 내부 상한**이다(1/64px 격자에서 표현 가능한 최대치 근처). 명세 값이 아니다.

비용 — 없음. 다만 **변수에서 0 이 흘러들어오는 경로**를 막을 방법이 CSS 안에는 없다.

### (8) 변수와 섞기 — `var()` 는 계산 전에 펼쳐진다

**언제 쓰나** — 간격·폭을 변수로 빼고 계산에 쓸 때.

```text
Chrome 151 실측 (부모 폭 400px)

  적은 것                                       computed width
  --------------------------------------------  --------------
  --pad: 16px;  calc(100% - var(--pad) * 2)     368px
  --half: 50%;  clamp(100px, var(--half), 300px) 200px
  --expr: 100% - 20px;  calc(var(--expr))       380px   ★ 식 조각도 담긴다
  --bad: 100% -20px;    calc(var(--bad))        400px   ★ 펼친 뒤 무효 -> auto
  --n: 10;      calc(var(--n) * 1px)            10px
```

```text
  순서가 이렇다

    ① var() 를 토큰 뭉치로 펼친다       calc(var(--expr))  ->  calc(100% - 20px)
                 ↓
    ② 그 결과를 calc 문법으로 다시 읽는다
                 ↓
    ③ 문법이 깨지면?  선언이 버려지는 게 아니라
                      '무효 대체(IACVT)' 가 된다 -> width: auto
```

그림 해설 (한 단계씩):

- **`var()` 는 값이 아니라 토큰 뭉치를 펼친다.** 그래서 **연산자와 피연산자 전체**를 변수에 담을 수 있다(`--expr: 100% - 20px` 이 실제로 동작했다).
- 반대로 **변수 안의 문법 오류도 같이 펼쳐진다** — `--bad: 100% -20px` 은 (1) 의 공백 규칙에 걸려 무효가 됐다.
- ★ **그때 증상이 (1) 과 다르다.** (1) 은 **선언이 통째로 사라졌지만**, 여기서는 **선언이 남은 채 `unset` 처럼 처리**된다.\
  둘 다 화면에서는 `width: auto` 로 똑같이 보이지만 **`cssRules` 창으로 보면 갈린다.** 이 차이의 정본은 [36번](../36-custom-properties/2-summary.md)이다.
- `--n: 10` 처럼 **숫자만 담아 두고 단위는 계산에서 붙이는** 패턴이 이래서 성립한다.

비용 — 변수를 쓰면 **파싱 시점에 못 접는다.** 값이 확정되는 시점이 뒤로 밀린다.

### (9) 유동 타이포 — `clamp()` 의 대표 용도

**언제 쓰나** — 화면 크기에 따라 글자가 부드럽게 변하되, 너무 작거나 크지 않아야 할 때.

```text
Chrome 151 실측 (뷰포트 폭 780px)

  font-size: clamp(16px, 5vw, 32px)   ->  32px   <- 5vw = 39px 이 상한 32 에 깎였다
  font-size: 5vw                      ->  39px   <- 제한 없이 그대로
  font-size: clamp(16px, 5vw, 48px)   ->  39px   <- 상한을 올리니 가운데가 그대로 쓰였다

  같은 셋을 뷰포트 500px 로 줄여 다시 재면 (Chrome 의 창 폭 하한이 500 이다)
  clamp(16px, 5vw, 32px) = 25px · 5vw = 25px · clamp(16px, 5vw, 48px) = 25px
     -> 셋이 같아졌다. 5vw 가 16~32 사이라 아무 한계도 안 걸렸다

  ★ '하한 16px 이 이기는 구간' 은 재지 못했다 — 5vw < 16px 이 되려면 창이 320px 미만
    이어야 하는데 Chrome 의 창 폭 하한이 500 이라 이 환경에서 만들 수 없다
```

```text
  세 구간으로 갈린다

    창이 작을 때        창이 중간일 때        창이 클 때
    +--------------+    +--------------+    +--------------+
    | 16px 로 고정 |    | 5vw 를 따라감 |    | 32px 로 고정 |
    +--------------+    +--------------+    +--------------+
     하한이 이긴다        가운데가 이긴다       상한이 이긴다
```

```html demo
<p class="fluid">clamp(16px, 5vw, 32px)</p>
<p class="raw">5vw 그대로</p>
<style>
  .fluid { font-size: clamp(16px, 5vw, 32px); margin: 0; }
  .raw   { font-size: 5vw; margin: 0; }
</style>
```

> **보이는 것** — 두 줄 다 창 폭을 따라 커지는 글자인데, **아래 줄(`5vw`)이 위 줄보다 눈에 띄게 크다.** 위 줄은 상한 32px 에 걸려 더 안 커지고 아래 줄은 39px 까지 커졌기 때문이다.\
> **바꿔 볼 것** — `.fluid` 의 상한 `32px` → `48px` 로 올리면 → **두 줄의 크기가 같아진다**(상한이 안 걸려 가운데 `5vw` 가 그대로 쓰인다)

*(Chrome 151 headless 실측 — 뷰포트 780px 에서 `.fluid` `font-size: 32px` · `.raw` `font-size: 39px`.)*

그림 해설 (한 단계씩):

- **뷰포트 단위 단독(`font-size: 5vw`)은 접근성 문제를 만든다** — 사용자가 브라우저 글꼴을 키워도 안 커지고, 큰 화면에서 무한정 커진다.
- `clamp()` 로 감싸면 **양끝이 고정 단위**가 되어 그 문제가 완화된다.
- 완전한 해결은 아니다 — 가운데 구간에서는 여전히 뷰포트만 따라간다. `clamp(1rem, 2.5vw + 0.5rem, 2rem)` 처럼 **`rem` 을 섞는** 형태가 실무 관행이다. ★ 그 형태는 **이 문서에서 재지 않았다.**

비용 — 없음. 다만 **`clamp()` 안에 `vw` 만 쓰면 확대 접근성이 완전히 회복되지는 않는다.**

### (10) 어디서 쓸 수 있고 어디서 못 쓰나

**언제 쓰나** — 미디어 쿼리 조건이나 변수 안에 계산을 넣고 싶을 때.

```text
Chrome 151 실측

  @media (min-width: calc(100px + 100px)) { ... }
     -> conditionText = "(min-width: calc(200px))"   담겼다
     -> 규칙이 실제로 적용됐다 (outline: solid)        ★ 동작한다

  @media (min-width: var(--bp, 100px)) { ... }
     -> conditionText = "(min-width: var(--bp, 100px))"  담기긴 했다
     -> 규칙이 적용되지 않았다 (outline: none)           ★ 절대 참이 안 된다

  line-height: calc(1.2 + 0.2)   -> 담긴 값 calc(1.4),  계산값 28px (글꼴 20px)
  opacity: calc(1 / 3)           -> 담긴 값 calc(0.333333)
  transform: rotate(calc(45deg + 45deg)) -> 담긴 값 rotate(calc(90deg))
```

그림 해설 (한 단계씩):

- **`calc()` 는 미디어 쿼리 안에서 동작한다** — 조건 자체가 참이 되어 규칙이 적용됐다.
- **`var()` 는 미디어 쿼리 안에서 동작하지 않는다.** 규칙은 담기지만 **조건이 절대 참이 되지 않는다.**\
  미디어 쿼리는 **문서 트리 바깥**에서 평가되는데, 커스텀 속성은 **요소에 붙어 상속되는 것**이라 거기에 없기 때문이다([36번](../36-custom-properties/2-summary.md)).
- **`calc()` 는 길이 전용이 아니다** — 숫자(`line-height`·`opacity`)·각도(`rotate`)에서도 같은 문법이 돈다.
- `line-height: calc(1.2 + 0.2)` 가 `calc(1.4)` 로 담긴 것은 **무단위 숫자로 남았다**는 뜻이다. 상속 성질의 정본은 [04번](../04-value-processing-stages/2-summary.md)이다.

비용 — 없음. 다만 「미디어 쿼리에서 변수를 쓰고 싶다」는 요구는 CSS 안에서 안 풀린다.

## 문법 — 형태와 어디서 헷갈리나

### 최소 형태

```css
.a { width: calc(100% - 40px); }            /* +/- 양옆에 공백 필수 */
.b { width: calc(100% / 3); }               /* * / 는 공백 없어도 된다 */
.c { width: min(100%, 60ch); }              /* 상한을 만든다 */
.d { width: max(320px, 50%); }              /* 하한을 만든다 */
.e { font-size: clamp(1rem, 4vw, 2rem); }   /* 하한, 원하는 값, 상한 */
.f { width: calc(var(--w) - var(--gap) * 2); }  /* 변수와 섞기 */
```

### 헷갈리는 자리

| 적은 것 | 실제 | 왜 |
|---|---|---|
| `calc(100% -10px)` | **선언이 사라진다** | `-10px` 이 음수 토큰 하나로 읽힌다((1)) |
| `calc(100% - 0)` | **선언이 사라진다** | `calc()` 안의 0 은 단위 없는 숫자다((3)) |
| `calc(10px * 20px)` | **선언이 사라진다** | 면적은 `<length>` 가 아니다((2)) |
| `clamp(300px, 50%, 100px)` | **300px** | 하한이 나중에 적용된다((4)) |
| `min(100%, 300px)` | **상한** 300 | 이름과 효과가 반대다((5)) |
| `calc(100px / 0)` | **무효가 아니다** | `infinity` 가 된다((7)) |
| `@media (min-width: var(--bp))` | **절대 참이 안 된다** | 미디어 쿼리에 커스텀 속성이 없다((10)) |

### 금지에 가까운 형태

```css
/* 공백을 아끼기 */
.bad1 { width: calc(100%-2rem); }      /* 통째로 사라진다 */

/* 뷰포트 단위 단독 글꼴 */
.bad2 { font-size: 4vw; }              /* 사용자 확대가 무력화된다 */

/* 상하한을 변수로 받되 순서를 보장 못 하는 형태 */
.bad3 { width: clamp(var(--lo), 50%, var(--hi)); }
/* --lo > --hi 가 되어도 에러가 안 나고 조용히 --lo 가 이긴다 */
```

## 구현 세부사항 대 언어 보장

| 무엇 | 어느 쪽 |
|---|---|
| `+`/`-` 양옆의 공백이 필수인 것 | **명세**(css-values-4 의 토큰화 규칙) |
| `*`/`/` 의 한쪽이 숫자여야 하는 것 | **명세**(타입 대수) |
| `calc()` 안에서 0 에 단위가 필요한 것 | **명세** |
| `clamp(a,b,c)` = `max(a, min(b,c))` 이고 `a>c` 면 `a` 가 이기는 것 | **명세** — 실측으로도 확인했다 |
| `min()`/`max()`/`clamp()` 가 인자를 셋 이상 받는 것 | **명세**(`min()`/`max()` 는 가변 인자, `clamp()` 는 정확히 3개) |
| `calc()` 가 미디어 쿼리에서 동작하고 `var()` 가 안 되는 것 | **명세**(css-variables — 커스텀 속성은 요소에 붙는다) |
| `calc(2*100px)` 이 **`calc(200px)`** 으로 **담기는 것** | **명세**가 직렬화를 정의하지만, **어디까지 접는지는 구현 재량**이 있다 |
| `(100% - 40px)/3` 이 **`33.3333%`** 로 잘리는 것 | **Chrome 151 구현** — 소수 4자리 직렬화다 |
| `calc(100px/0)` 의 계산값 **`3.35544e+07px`** | **Chrome 151 구현** — 내부 상한이다. `infinity` 가 되는 것 자체는 명세 |
| `clamp(300px,10px,100px)` 이 `calc(300px)` 로 **접혀 담기는 것** | **Chrome 151 구현** — 인자가 사라져 보인다 |
| `clamp(1rem, 2.5vw + 0.5rem, 2rem)` 같은 실무 형태 | **미실행** — 이 문서에서 재지 않았다 |

## 어디서 틀리나

### 1. `+`/`-` 양옆의 공백을 뺀다

`calc(100%-2rem)` 은 **선언이 통째로 사라진다**(실측). 에러도 경고도 없다.\
진단 — `cssRules` 창으로 속성 목록을 찍어 본다. 목록에 없으면 문법 오류다([07번](../07-syntax-and-error-recovery/2-summary.md)).

### 2. `calc()` 안에 단위 없는 `0` 을 쓴다

`calc()` 밖에서는 되던 것이 안에서는 안 된다((3)). `0px`·`0%` 로 바꾼다.

### 3. `clamp()` 의 상하한이 뒤집힌 것을 무효라고 생각한다

**값이 나온다 — 하한이 이긴다**(실측 300px). 뒤집힌 것을 CSS 가 알려 주지 않는다((4)).\
변수로 상하한을 받는 설계라면 **뒤집힘을 CSS 밖에서 막아야 한다.**

### 4. 「최대 폭」을 `max()` 로 적는다

`max(…, 300px)` 은 **하한**이다((5)). 상한은 `min(…, 300px)` 이다.

### 5. `getComputedStyle` 값이 적은 것과 달라 당황한다

파싱 시점에 접히기 때문이다((6)). `calc(2*100px)` 은 `cssRules` 에 이미 `calc(200px)` 이다.\
**「적은 것」과 「담긴 것」은 다른 창이다.**

### 6. 미디어 쿼리 조건에 변수를 쓴다

규칙은 담기지만 **조건이 절대 참이 안 된다**(실측). 계산이 필요하면 `calc()` 는 되고 `var()` 는 안 된다((10)).

### 7. 변수 안에 문법 오류가 든 것을 (1) 과 같은 증상으로 본다

화면은 같지만 **`cssRules` 창에서 갈린다** — (1) 은 선언이 사라지고, 변수 쪽은 **선언이 남은 채 무효 대체**가 된다((8)).\
정본은 [36번](../36-custom-properties/2-summary.md)이다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 고를 것 | 왜 |
|---|---|---|
| 부모 폭에서 고정 여백을 뺀 칸 | `calc(100% - 40px)` | 두 자를 섞는 유일한 방법이다 |
| 본문 줄 길이 상한 | `min(100%, 65ch)` | 좁으면 부모를 채우고, 넓으면 가독 폭에서 멈춘다 |
| 최소 터치 영역 보장 | `max(44px, 2em)` | 글꼴이 작아도 하한이 지켜진다 |
| 유동 제목 | `clamp(1rem, 4vw, 2rem)` | 양끝이 고정 단위라 접근성이 덜 깨진다((9)) |
| 간격 토큰을 한 곳에서 조절 | `calc(var(--gap) * 2)` | 변수와 계산을 같이 쓴다((8)) |
| 미디어 쿼리 중단점 계산 | `calc()` 는 된다 | `var()` 는 안 된다((10)) |
| 상하한 순서를 코드로 보장해야 할 때 | (여기 아님) | CSS 가 뒤집힘을 안 막는다((4)) |
| 단순히 부모를 채우기 | `100%` | `calc(100% - 0px)` 보다 싸고 읽기 쉽다 |

## 핵심 문장

- **`+`/`-` 양옆에는 공백이 필수**다. 없으면 부호로 읽혀 **선언이 통째로 사라진다** — 에러도 경고도 없다.
- **`*`/`/` 는 한쪽이 숫자여야 한다.** 길이×길이·길이÷길이는 `<length>` 가 아니다.
- **`calc()` 안에서는 0 에도 단위가 필요하다.** 밖의 규칙이 안에서는 안 통한다.
- ★ **`clamp(a, b, c)` 에서 `a > c` 이면 `a` 가 이긴다** — `max(a, min(b, c))` 라 하한이 나중에 적용되기 때문이다. **무효가 되지 않는다.**
- **계산은 두 번 일어난다** — 파싱 때 접을 수 있는 만큼 접히고, `%`·`em`·`var()` 가 걸린 나머지는 계산값·사용값 단계에서 풀린다.

## 용어 풀이

- **`calc()`** — 값 안에서 사칙연산을 쓰게 해 주는 함수. 서로 다른 단위를 더할 수 있는 유일한 수단이다.
- **`min()` / `max()`** — 인자 중 최소/최대를 고르는 함수. 예: `min(100%, 300px)` 은 **상한 300** 을 만든다.
- **`clamp(a, b, c)`** — `max(a, min(b, c))` 와 같다. 예: 실측에서 `clamp(100px, 50%, 300px)` 와 `max(100px, min(50%, 300px))` 가 둘 다 200px 이었다.
- **토큰(token)** — 파서가 만드는 최소 단위. 예: `-10px` 은 부호까지 포함해 **토큰 하나**라 앞의 `-` 가 연산자가 되지 못한다.
- **타입 대수** — `calc()` 안에서 길이·숫자·각도 등이 곱셈·나눗셈으로 어떻게 결합되는지 정한 규칙. 예: 길이÷길이는 숫자가 되어 `<length>` 자리에 못 들어간다.
- **직렬화(serialization)** — 엔진이 값을 문자열로 다시 적는 방식. 예: `calc(2*100px)` 이 `calc(200px)` 로 담긴 것.
- **파싱 시점 접기(constant folding)** — 변수·`%`·상대 단위가 없어 미리 계산할 수 있는 식을 담을 때 미리 줄이는 것. `clamp` 가 `calc(300px)` 로 줄어든 것이 그 예다.
- **무효 대체(IACVT)** — 파싱은 됐는데 계산 시점에 무효가 되어 `unset` 처럼 처리되는 것. 정본은 [36번](../36-custom-properties/2-summary.md).
- **유동 타이포(fluid typography)** — 화면 폭에 따라 글꼴 크기가 연속적으로 변하는 설계. 예: `clamp(1rem, 4vw, 2rem)`.

## 더 들어가면

- **삼각·지수 함수가 더 있다** — `sin()`·`cos()`·`atan2()`·`pow()`·`sqrt()`·`round()`·`mod()`·`rem()`·`abs()`·`sign()`.\
  문법 규칙(공백·타입)은 전부 같다. 지원 상태는 [목록 README](../README.md) 의 Baseline 표로 확인한다. ★ **이 문서에서 재지 않았다.**
- **`round()` 는 격자 맞춤에 쓴다** — `round(down, 100%, 8px)` 로 「8px 배수로 내림」 같은 것이 CSS 안에서 된다.\
  예전에는 JS 로만 되던 일이다. ★ **재지 않았다.**
- **중첩 `calc()` 는 없어도 된다.** `calc(a + calc(b * c))` 는 `calc(a + (b * c))` 와 같고, 실측에서 **평탄화되어 담겼다**.\
  `min()`/`max()`/`clamp()` 안에서는 `calc` 키워드 없이 바로 식을 쓸 수 있다.
- **`calc()` 가 비싸다는 통념은 오래된 것이다.** 파싱 시점에 접을 수 있는 것은 접히고((6)), 못 접는 것은 어차피 `%` 와 같은 비용이다.\
  성능 문제가 되는 쪽은 계산 자체가 아니라 **값이 바뀔 때 무엇이 다시 도는가**다 — 정본은 [목록의 **56번 주제**](../56-rendering-pipeline-and-will-change/).
- **`clamp()` 의 가운데 인자를 직선식으로 설계하는 법**이 따로 있다 — 두 중단점 `(w1, s1)`·`(w2, s2)` 를 지나는 직선을 `vw` + `rem` 으로 적는 것.\
  자주 쓰이지만 **수식을 손으로 유도한 값이라 이 문서에서는 재지 않았고, 수치를 싣지 않았다.**
