# css/syntax/30 — `subgrid`: 부모 트랙을 자식이 잇는 것 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Grid Layout Level 2](https://drafts.csswg.org/css-grid-2/) (`subgrid` 키워드·라인 이름 상속·`gap` 상속·서브그리드 항목이 부모 트랙 크기에 기여하는 규칙). 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 `demo` 블록 **4개 전부**를 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워, **트랙은 `getComputedStyle(el).gridTemplateColumns`/`.gridTemplateRows` 로, 항목 자리는 `getBoundingClientRect()` 로 따로** 쟀다. 본문의 px 값은 전부 그 실측값이다.\
> **엔진은 Chrome 하나다** — Firefox 155.0.1 은 이 환경에서 headless 스크린샷이 산출되지 않고 WebKit 은 이 머신에 없다. 「두 엔진에서 확인했다」고 적지 않았다.
> **버전** — `subgrid` 는 Baseline **widely**(newly **2023-09-15** → widely **2026-03-15**). 목록 README 의 지원 표를 확인했다. Grid 본체(widely 2020-04-17)보다 **6년 가까이 늦다** — 오래된 코드가 `subgrid` 를 안 쓰는 이유가 이것이다.
> **여기서 다루지 않는 것** — **트랙을 만드는 것**은 [**27번**](../27-grid-track-sizing/), **번호로 놓는 것**은 [**28번**](../28-grid-placement/), **이름으로 놓는 것**은 [**29번**](../29-grid-template-areas/)이 정본이다(이 문서는 셋의 실측을 그대로 이어 쓴다). 정렬의 정본은 [**24번**](../24-flexbox-axes/), `gap` 의 정본은 [목록의 **26번 주제**](../26-flex-wrap-gap-order/)다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 수치는 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

`subgrid` = 자식이 자기 격자를 안 만들고 **부모의 격자선을 그대로 이어 쓰는 것**이다.

[27번](../27-grid-track-sizing/)에서 칸막이를 세웠고 [28번](../28-grid-placement/)·[29번](../29-grid-template-areas/)에서 그 위에 물건을 놓았다. 여기서는 **그 칸막이를 자식 방이 그대로 물려받는다.**

| 비유 | 실체 |
|---|---|
| 큰 방에 세운 칸막이 | 부모 격자의 트랙 |
| 큰 방 안에 놓인 작은 상자 | **서브그리드**(부모의 격자 항목이면서 자신도 격자 컨테이너) |
| 상자가 자기 칸막이를 새로 세운다 | 보통의 중첩 격자 — **부모의 칸과 안 맞는다** |
| 상자가 바닥에 그어진 큰 방의 선을 그대로 쓴다 | **`subgrid`** |
| 선 사이 간격도 큰 방 것을 따른다 | `gap` 상속 |

- **문제는 딱 하나다** — 카드 여러 장의 **내부 줄**(제목·본문·버튼)을 **카드끼리 맞추는 것.**
- 보통의 중첩 격자로는 **안 된다.** 카드마다 격자가 따로라 **서로의 줄을 모른다.**
- `subgrid` 는 그 격자를 **만들지 않게** 해서 푼다. 「맞추는 기능」이 아니라 「**안 만드는 기능**」이다.

```text
중첩 grid (안 맞는다)                    subgrid (맞는다)
+----------------+----------------+    +----------------+----------------+
| 짧은 제목      | 두 줄로 넘어가는|    | 짧은 제목      | 두 줄로 넘어가는|
|                | 아주 긴 제목   |    |                | 아주 긴 제목   |
| 본문           |                |    |                |                |
|                | 본문           |    | 본문           | 본문           |
+----------------+----------------+    +----------------+----------------+
   본문 줄이 어긋난다                      본문 줄이 딱 맞는다
```

*(Chrome 151 headless 실측 — 카드 안 `본문` 의 위쪽 좌표(카드 기준): 중첩 격자는 **28.5 대 38** 로 9.5px 어긋났고, `subgrid` 는 **둘 다 42** 로 같았다.)*

> **서브그리드(subgrid)** — 부모 격자의 항목이면서 자신도 격자 컨테이너인데, **자기 트랙을 만들지 않고 부모가 만든 트랙을 잇는** 요소.\
> 예: 카드 목록에서 카드 하나하나가 서브그리드가 되면 카드 안의 제목·본문이 카드끼리 같은 줄에 놓인다.

> **중첩 격자(nested grid)** — 격자 항목 안에 또 격자를 만든 것. **부모와 독립된 트랙**을 갖는다.\
> 예: `.card { display: grid }` 만 쓴 것. 카드마다 제목 높이가 달라지면 본문 시작 줄도 달라진다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. **중첩 격자로는 왜 안 되는가** — 무엇이 어긋나고 그것을 무엇으로 재나.
2. `subgrid` 는 부모에게서 **무엇까지** 물려받나 — 트랙·`gap`·라인 이름.
3. `getComputedStyle` 이 서브그리드에서 **무엇을 돌려주나** — 다른 주제와 다른 점.

## 동작 방식

### (0) 한 줄 요약 — 격자가 몇 개인가

**언제 쓰나** — `subgrid` 를 읽기 전에. 이 셈이 이 주제의 전부다.

```text
중첩 격자                              subgrid
격자 3개 (부모 + 카드1 + 카드2)         격자 1개 (부모) + 그것을 잇는 껍데기 둘
        ↓                                      ↓
카드끼리 서로의 줄을 모른다              같은 트랙을 쓰므로 맞을 수밖에 없다
```

### (1) 과녁 — 중첩 격자로는 왜 안 되나

**언제 쓰나** — 카드 목록·표 형태 목록에서 「카드마다 본문 시작 줄이 다르다」가 나왔을 때.

```text
왜 안 맞나 — 격자가 셋이기 때문이다

  부모 격자              카드1 격자             카드2 격자
  +----+----+            +--------+            +--------+
  |    |    |            | 제목   |            | 제목   |
  |    |    |            |        |            | (두 줄)|
  +----+----+            | 본문   |            |        |
                         +--------+            | 본문   |
                                               +--------+
   세 격자가 서로를 모른다 -> 카드1 의 「본문」 줄과 카드2 의 「본문」 줄이 다르다
```

```html demo
<div class="row"><div class="card"><b>짧은 제목</b><p>본문</p></div>
  <div class="card"><b>두 줄로 넘어가는 아주 긴 제목</b><p>본문</p></div></div>
<div class="row sub"><div class="card"><b>짧은 제목</b><p>본문</p></div>
  <div class="card"><b>두 줄로 넘어가는 아주 긴 제목</b><p>본문</p></div></div>
<style>
  .row { display: grid; width: 300px; margin-bottom: 8px; gap: 4px;
         grid-template-columns: 1fr 1fr; grid-template-rows: auto auto;
         border: 2px solid #94a3b8; }
  .card { display: grid; grid-row: span 2; grid-template-rows: auto auto;
          background: #e2e8f0; font: 13px system-ui; }
  .sub .card { grid-template-rows: subgrid; }   /* 자기 행을 안 만들고 부모 것을 잇는다 */
  .card b, .card p { margin: 0; background: #bfdbfe; outline: 1px solid #2563eb; }
</style>
```

> **보이는 것** — 위아래 두 묶음 다 카드 둘이고 오른쪽 카드의 제목이 두 줄이다. **위 묶음(중첩 격자)은 왼쪽 카드의 「본문」이 오른쪽 카드의 「본문」보다 위에** 있어 두 파란 줄이 어긋나 보인다. **아래 묶음(`subgrid`)은 두 「본문」의 윗변이 한 줄로 딱 맞는다.** 왼쪽 카드의 제목 칸은 내용이 한 줄뿐인데도 오른쪽 카드 제목과 같은 높이로 늘어나 있다.\
> **바꿔 볼 것** — `.sub .card` 의 `grid-template-rows: subgrid` 를 지우면 아래 묶음도 위 묶음처럼 어긋난다 · `.card` 의 `grid-row: span 2` 를 지우면 **`subgrid` 가 있어도 안 맞는 정도가 아니라 제목과 본문이 같은 칸에 겹쳐 버린다**(트랙을 하나만 물려받아 행이 하나뿐이다 — 계산값 `subgrid [] []`)

*(Chrome 151 headless 실측 — 카드 기준 좌표. **중첩 격자**: 카드1 의 행 계산값 `28.5px 28.5px`(본문 top 28.5) · 카드2 는 `38px 19px`(본문 top 38) → **9.5px 어긋난다.** **`subgrid`**: 두 카드 다 행 계산값이 `subgrid [] [] []` 이고 본문 top 이 **둘 다 42** 다. 부모 행 계산값도 `26.5px 26.5px` → `38px 19px` 로 바뀌었다.)*

```text
같은 내용, 같은 폭, 다른 결과 (실측 — 카드 기준 「본문」 의 top)

  중첩 격자                                subgrid
  카드1 행: 28.5px 28.5px  본문 top 28.5   카드1 행: subgrid [] [] []  본문 top 42
  카드2 행: 38px   19px    본문 top 38     카드2 행: subgrid [] [] []  본문 top 42
                   └─ 9.5px 어긋난다                          └─ 같다

  부모 행: 26.5px 26.5px                   부모 행: 38px 19px
                                                    ^ 서브그리드 안의 내용이
                                                      부모 트랙 크기를 정했다
```

그림 해설 (한 단계씩):

- 중첩 격자에서는 카드마다 `auto auto` 가 **자기 내용만 보고** 행을 나눈다. 카드1 은 57px 을 28.5/28.5 로, 카드2 는 38/19 로 쪼갰다.
- `subgrid` 를 주면 카드가 **행을 안 만든다.** 부모의 두 행을 그대로 쓰니 둘이 같을 수밖에 없다.
- ★ **부모의 행 크기도 바뀐다** — `26.5px 26.5px` 에서 `38px 19px` 로. 서브그리드 안의 항목이 **부모 트랙의 크기 결정에 참여**하기 때문이다. 이것이 「맞춰지는」 메커니즘의 핵심이다.

비용 — 서브그리드 안의 내용이 부모 트랙 크기에 기여하므로 **레이아웃 계산이 한 겹 더 엮인다.** 다만 실무에서 문제 되는 수준은 아니다.

### (2) 성립 조건 — 「부모의 트랙을 덮고 있어야」 한다

**언제 쓰나** — 「`subgrid` 를 썼는데 아무 일도 안 일어난다」가 나왔을 때.

```text
subgrid 가 성립하려면

① 그 요소가 격자 항목이어야 한다          부모가 display: grid (또는 inline-grid)
② 그 요소가 격자 컨테이너여야 한다        자신도 display: grid
③ 그 축에서 부모의 트랙을 덮고 있어야 한다  grid-row: span 2 처럼 범위를 잡아야 뜻이 있다
```

```text
세 조건이 한 줄씩 빠졌을 때

  ① 없음 (부모가 격자 아님)   ->  계산값 none        ... 눈에 띈다
  ② 없음 (display: grid 없음) ->  선언 자체가 무의미   ... 눈에 띈다
  ③ 없음 (span 이 없음)       ->  계산값 subgrid [] [] ... 안 띈다  <- 가장 위험
                                            └┬┘
                                      라인 둘 = 트랙 하나
```

- **③이 빠지면 아무 일도 안 일어난다.** 한 칸만 덮은 서브그리드는 트랙이 하나뿐이라 맞출 것이 없다.
- **①이 없으면 `subgrid` 가 `none` 으로 떨어진다.**\
  *(실측 — 부모가 격자가 아닌 요소에 `grid-template-columns: subgrid` 를 주면 계산값이 **`none`** 이고 자식이 1열 격자처럼 200px 을 다 차지했다.)*
- ★ **③이 빠졌을 때가 제일 안 보인다.** 실측 — `grid-row: span 2` 를 지운 카드의 계산값이 `subgrid [] []`(라인 둘 = 트랙 하나)였고,\
  **제목과 본문이 같은 칸에 겹쳐** 둘 다 y=0 에 놓였다. 문법도 유효하고 계산값에도 `subgrid` 가 보이는데 결과만 틀린다.
- 축마다 따로다 — `rows: subgrid` 만 주고 열은 자기가 만들어도 된다(위 demo 가 그렇다).

### (3) 덮는 만큼만 물려받는다

**언제 쓰나** — 서브그리드가 부모의 일부 칸만 차지할 때.

```html demo
<div class="outer"><div class="sub"><i>1</i><i>2</i><i>3</i></div></div>
<style>
  .outer { display: grid; width: 400px; border: 2px solid #94a3b8;
           grid-template-columns: 100px 100px 100px 100px; }
  .sub { display: grid; grid-column: 2 / 4;      /* 부모의 2~4 라인만 덮는다 */
         grid-template-columns: subgrid; background: #fde68a; }
  .sub i { background: #bfdbfe; font: 13px system-ui; font-style: normal;
           outline: 1px solid #2563eb; }
</style>
```

> **보이는 것** — 노란 상자가 격자의 **가운데 두 칸**을 차지하고, 그 안에 파란 칸 `1`·`2` 가 나란히 놓인 뒤 **`3` 은 아랫줄 왼쪽으로 내려간다.** 노란 상자의 왼쪽 한 칸과 오른쪽 한 칸은 비어 있다.\
> **바꿔 볼 것** — `grid-column: 2 / 4` → `1 / -1` 하면 서브그리드가 **네 칸 전부**를 덮어(계산값 `subgrid [] [] [] [] []`) `3` 이 아랫줄로 안 내려간다 · `grid-template-columns: subgrid` 를 지우면 노란 상자 안이 **1열 격자**가 되어 `1`·`2`·`3` 이 **세로로 쌓인다**(폭은 셋 다 200px)

*(Chrome 151 headless 실측 — 부모 열 계산값 `100px 100px 100px 100px`, 서브그리드 열 계산값 **`subgrid [] [] []`**(라인 세 개 = 트랙 둘). 서브그리드 자체는 x=102 w=200. 안의 항목은 `1`(x=0 w=100) `2`(x=100 w=100) `3`(x=0 **y=19**) — 트랙이 둘뿐이라 셋째가 줄바꿈됐다.)*

```text
부모        [100][100][100][100]      라인 1 2 3 4 5
서브그리드         └────┴────┘         grid-column: 2 / 4  -> 라인 2·3·4 만 물려받는다
                   [ 1 ][ 2 ]
                   [ 3 ]               트랙이 둘이므로 셋째 항목은 다음 줄
```

- ★ **계산값이 `subgrid [] [] []` 로 온다** — **px 이 아니다.** [27번](../27-grid-track-sizing/)·[28번](../28-grid-placement/)에서 계산값이 항상 px 로 풀려 왔던 것과 **다른 자리**다.
- 대괄호 개수는 **라인 개수**다. 트랙 둘이면 `[] [] []` 셋, 트랙 셋이면 넷이다. **이것으로 「몇 칸을 물려받았나」를 셀 수 있다.**
- 실제 px 이 궁금하면 **부모의 계산값을 읽는다.** 서브그리드에는 자기 트랙 크기라는 것이 없다.

### (4) `gap` 은 부모 것을 물려받고, 덮어쓸 수 있다

**언제 쓰나** — 서브그리드 안의 간격이 부모와 달라 보일 때.

```html demo
<div class="outer">
  <div class="sub">   <i>1</i><i>2</i><i>3</i></div>
  <div class="sub z"> <i>1</i><i>2</i><i>3</i></div>
</div>
<style>
  .outer { display: grid; width: 400px; gap: 30px; border: 2px solid #94a3b8;
           grid-template-columns: 100px 100px 100px; }
  .sub { display: grid; grid-column: 1 / -1; grid-template-columns: subgrid; }
  .z   { column-gap: 0; }        /* 물려받은 30px 을 0 으로 덮어쓴다 */
  .sub i { background: #bfdbfe; font: 13px system-ui; font-style: normal;
           outline: 1px solid #2563eb; }
</style>
```

> **보이는 것** — 두 줄 다 파란 칸이 셋인데 **모양이 다르다.** 윗줄은 칸 셋이 **떨어져** 있고(사이에 흰 틈이 보인다) 각 칸의 폭이 같다. 아랫줄은 칸 셋이 **서로 붙어** 있고 **가운데 칸이 양옆보다 넓다.** 두 줄의 전체 폭은 같다.\
> **바꿔 볼 것** — `.z` 의 `column-gap: 0` → `column-gap: 60px` 하면 칸이 **더 좁아지면서**(85·70·85) 더 벌어진다 · `.outer` 의 `gap: 30px` → `gap: 0` 하면 **두 줄이 똑같아진다**(둘 다 x=0·100·200, 폭 100 — 물려받을 간격이 없으므로)

*(Chrome 151 headless 실측 — 부모 열 계산값 `100px 100px 100px`, `gap` 30px. **물려받은 쪽**: 항목 x=0·130·260, 폭 전부 100 — 부모 트랙과 정확히 일치한다. **덮어쓴 쪽**(`column-gap: 0`): 항목 x=0·115·245, 폭 **115·130·115** — 부모의 `gap` 자리를 트랙이 흡수했다. 두 서브그리드의 `columnGap` 계산값은 각각 **`normal`** 과 `0px` 이었다.)*

```text
gap 을 물려받을 때 (30px)              column-gap: 0 으로 덮을 때
[ 100 ]  30  [ 100 ]  30  [ 100 ]     [  115  ][   130   ][  115  ]
 x=0          x=130       x=260        x=0      x=115      x=245
 부모 트랙과 자리가 정확히 같다          부모의 gap 자리를 트랙이 먹는다
                                       -> 칸은 넓어지고 부모와 어긋난다
```

- ★ **계산값 `column-gap` 이 `normal` 로 나오는데 화면에는 30px 간격이 있다.** 「간격이 없다」가 아니라 「**내 것이 없어서 부모 것을 쓴다**」는 뜻이다.\
  이것이 이 주제에서 계산값을 잘못 읽기 가장 쉬운 자리다.
- 덮어쓰면 **부모와 자리가 어긋난다.** 「맞추려고」 subgrid 를 썼으면 `gap` 은 건드리지 않는 것이 맞다.
- `gap` 자체의 정본은 [목록의 **26번 주제**](../26-flex-wrap-gap-order/)이고, [27번](../27-grid-track-sizing/)에서 「`gap` 이 자유 공간에서 먼저 빠진다」를 다뤘다. **여기서는 「부모 것을 쓴다」는 것만** 쓴다.

### (5) 라인 이름 — 부모 것을 그대로 쓰고, 내 것을 더할 수 있다

**언제 쓰나** — 부모가 `[main-start]` 같은 이름을 쓰고 있고 자식에서도 그 이름으로 놓고 싶을 때.

```html demo
<div class="outer"><div class="sub"><i class="m">b 라인</i></div></div>
<style>
  .outer { display: grid; width: 300px; border: 2px solid #94a3b8;
           grid-template-columns: [a] 100px [b] 100px [c] 100px [d]; }
  .sub { display: grid; grid-column: 1 / -1; grid-template-columns: subgrid; }
  .m { grid-column: b; }         /* 부모의 라인 이름을 자식이 그대로 쓴다 */
  .sub i { background: #bfdbfe; font: 13px system-ui; font-style: normal;
           outline: 1px solid #2563eb; }
</style>
```

> **보이는 것** — 격자 폭이 300px 인데 파란 상자 하나가 **가운데 칸**(왼쪽에서 100px 지점부터 100px)에 놓인다. 자식 쪽에는 `[b]` 라는 이름을 **한 글자도 안 썼는데** 부모의 이름으로 자리가 잡혔다.\
> **바꿔 볼 것** — `.m` 의 `grid-column: b` → `c` 하면 **오른쪽 칸**(x=200 w=100)으로 옮겨간다 · `.sub` 의 `grid-template-columns: subgrid` 를 지우면 부모 이름 `b` 를 못 찾아 **자기 격자의 암묵 라인**으로 떨어지고, 상자가 **x=145.97 · 폭 154.03** 이라는 엉뚱한 자리로 간다([29번](../29-grid-template-areas/)의 「이름을 못 찾으면 암묵 격자로」와 같은 규칙이다)

*(Chrome 151 headless 실측 — 부모 열 계산값 `[a] 100px [b] 100px [c] 100px [d]`. 서브그리드의 열 계산값은 **`subgrid [] [] [] []`** — **물려받은 이름이 안 보인다.** 그런데 항목의 `gridColumnStart`/`End` 계산값은 둘 다 `b` 이고 좌표는 x=100 w=100 으로 **정확히 `b`\~`c` 칸**이다.)*

```text
★ 계산값이 말해 주지 않는 것이 있다

  부모 계산값      "[a] 100px [b] 100px [c] 100px [d]"     이름이 보인다
  서브그리드 계산값 "subgrid [] [] [] []"                   이름이 안 보인다
  그런데 실제로는   grid-column: b 가 동작한다              (좌표 x=100 이 증거)

  -> 대괄호가 비어 있다고 "이름이 없다" 고 읽으면 틀린다.
     빈 대괄호는 "이 서브그리드가 추가로 붙인 이름이 없다" 는 뜻이다.
```

**내 이름을 더할 수도 있다.**

```text
grid-template-columns: subgrid [p] [q];
  -> 계산값 "subgrid [p] [q] [] []"
     내가 붙인 이름은 서브그리드의 첫 라인부터 차례로 붙는다
```

*(Chrome 151 headless 실측 — 위 선언을 준 서브그리드의 계산값이 `subgrid [p] [q] [] []` 였고, `grid-column: p` 인 항목이 **첫 칸**(x=0 w=100)에 놓였다.)*

- 부모가 [29번](../29-grid-template-areas/)의 **도면으로 만든 암묵 이름**(`hd-start` 등)도 같은 규칙으로 쓸 수 있다.
- 이름을 물려받는 것이 `subgrid` 의 잘 안 알려진 이득이다 — 자식 CSS 가 **부모의 좌표계를 그대로** 쓰게 된다.

### (6) 진단 — `subgrid` 가 안 먹을 때 무엇을 읽나

**언제 쓰나** — 「`subgrid` 를 썼는데 여전히 어긋난다」가 나왔을 때.

```text
① getComputedStyle(자식).gridTemplateRows
        "subgrid …"  -> 살아 있다. ②로
        "none"       -> 부모가 격자가 아니다 (또는 선언이 버려졌다)
        "38px 19px"  -> subgrid 가 아니라 제 트랙을 만들었다 = 선언이 안 먹었다
        ↓
② 대괄호 개수를 센다
        [] [] []     -> 라인 셋 = 트랙 둘을 물려받았다
        [] []        -> 라인 둘 = 트랙 하나뿐 = grid-row: span N 이 빠졌다  <- 가장 흔하다
        ↓
③ getComputedStyle(부모).gridTemplateRows 로 실제 px 을 읽는다
        자식 쪽에는 px 이 없다
```

- ②가 이 주제 고유의 진단이다. **「맞춰지지 않는다」의 대부분은 `subgrid` 가 아니라 `span` 이 빠진 것**이다.
- [27번](../27-grid-track-sizing/)의 「진단 3창」과 짝이다 — 거기가 **선언이 살았나**를 보는 것이라면, 여기는 **몇 칸을 물려받았나**를 본다.

## 문법 — 형태와 어디서 헷갈리나

### 최소 형태

```css
.parent {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: auto auto auto;      /* 카드가 덮을 세 줄 */
  gap: 16px;
}
.card {
  grid-row: span 3;                        /* ★ 이 줄이 없으면 아무 일도 안 일어난다 */
  display: grid;
  grid-template-rows: subgrid;             /* 행만 잇는다. 열은 자기 것 */
}
```

- `subgrid` 는 **`grid-template-columns`/`grid-template-rows` 의 값**이다. 별도 속성이 아니다.
- 두 축 다 쓰려면 두 줄을 쓴다 — `grid-template-columns: subgrid; grid-template-rows: subgrid;`
- 뒤에 **라인 이름만** 더할 수 있다 — `subgrid [p] [q]`. **트랙 크기는 못 쓴다.**

### 금지 사례 — 버려지거나 무력한 것

```css
.a { grid-template-rows: subgrid 100px; }   /* 크기를 같이 쓸 수 없다 — 버려진다 */
.b { grid-template-rows: subgrid; }          /* span 이 없으면 트랙 하나뿐 = 무력 */
.c { grid-template-rows: subgrid; }          /* 부모가 격자가 아니면 none 으로 떨어진다 */
```

*(Chrome 151 headless 실측 — `.a`: `grid-template-rows: 40px` 을 대조군으로 깔고 그 아래 `subgrid 100px` 을 쓴 판의 계산값이 **`40px`** 이었다 = **버려졌다.** `.c`: 부모가 격자가 아닌 판의 계산값이 **`none`**. `.b`: 계산값이 `subgrid [] []` 로 **살아 있다.**)*

- ★ **`.b` 가 가장 위험하다.** 문법도 유효하고 계산값도 `subgrid …` 로 나오는데 **아무것도 안 맞춰진다.**\
  대괄호 개수를 세야만 보인다 — (6)의 ②.
- `.c` 는 계산값이 `none` 이라 **그나마 눈에 띈다.**

### 헷갈리는 짝

| 헷갈리는 것 | 실제 |
|---|---|
| `subgrid` 가 「줄을 맞춰 주는 기능」 | **격자를 안 만드는 기능**이다. 맞는 것은 결과다 |
| 계산값에 px 이 온다 | **`subgrid [] [] []`** 가 온다. px 은 부모에게 있다 |
| 빈 대괄호 = 이름이 없다 | **내가 더한 이름이 없다**는 뜻. 부모 이름은 쓸 수 있다 |
| `column-gap` 계산값 `normal` = 간격 0 | **부모 것을 쓴다**는 뜻이다 |
| `subgrid` 만 쓰면 된다 | **`grid-row: span N`** 이 같이 있어야 뜻이 있다 |
| 중첩 격자로도 `align-items` 로 맞출 수 있다 | 칸 안에서만 맞춘다. **칸 자체가 다르면 못 맞춘다** |

## 구현 세부사항 대 언어 보장

- **`subgrid` 의 의미**(자기 트랙을 만들지 않고 부모 트랙을 잇는다)·**`gap` 상속**·**라인 이름 상속**·**서브그리드 항목이 부모 트랙 크기에 기여한다**는 것은 전부 **명세가 정한다.** CSS Grid Level 2 가 근거다.
- **계산값이 `subgrid [] [] []` 형태로 직렬화되는 것**은 **구현 관찰**이다. 명세는 resolved value 가 `subgrid` 계열임을 정하지만 **대괄호가 라인마다 하나씩 붙는 문자열 모양**은 Chrome 151 에서 본 것이다 — **버전이 오르면 다시 찍는 칸**이다.
- **`column-gap` 계산값이 `normal` 로 남는 것**도 구현 관찰이다.
- **부모가 격자가 아닐 때 `none` 으로 떨어지는 것**은 명세의 폴백 규정이고, 실측이 그것과 맞아떨어졌다.
- **구체적인 px 값**(28.5 · 38 · 42 · 115 · 130)은 이 머신의 폰트와 창 크기에 딸린 값이다. **재현되는 것은 「어긋난다/맞는다」와 「gap 자리를 트랙이 흡수한다」는 성질**이다.
- **Baseline 은 widely** — newly **2023-09-15** → widely **2026-03-15**(목록 README 의 지원 표). **오늘 기준으로 widely 가 된 지 반년쯤**이라, 「그냥 써도 되는 것」의 경계에 갓 들어온 기능이다.

## 어디서 틀리나

이 주제의 값어치는 여기 몰려 있다. 다섯 다 **에러 없이 조용히 어긋난다.**

### 1. `span` 을 안 준다

`subgrid` 만 쓰고 `grid-row: span 3` 을 안 쓰면 **트랙 하나만 물려받아 아무것도 안 맞춰진다.**\
계산값이 `subgrid [] []`(라인 둘)이면 그것이다. 「맞춰지지 않는다」의 대부분이 이것이다.

### 2. 계산값에서 px 을 찾는다

서브그리드의 `gridTemplateRows` 는 **`subgrid [] [] []`** 다. px 은 **부모 쪽**에 있다.\
[27번](../27-grid-track-sizing/)·[28번](../28-grid-placement/)에서 계산값이 늘 px 이었던 습관이 여기서 깨진다.

### 3. `column-gap` 이 `normal` 이라 「간격이 없다」고 읽는다

**부모 것을 쓴다**는 뜻이다. 실측에서 계산값이 `normal` 인 서브그리드의 항목이 **30px 간격**으로 놓였다.

### 4. 간격을 조정하려다 정렬을 깬다

서브그리드에서 `gap` 을 덮어쓰면 **부모의 `gap` 자리를 트랙이 흡수해** 칸 폭이 달라진다(실측 100 → 115·130·115).\
맞추려고 쓴 기능인데 간격을 만지면 도로 어긋난다.

### 5. 중첩 격자에 `align-items` 를 줘서 해결하려 한다

정렬은 **칸 안에서** 항목을 움직일 뿐이다. **칸(행) 자체가 카드마다 다르면** 아무리 정렬해도 안 맞는다.\
정렬 어휘의 정본은 [24번](../24-flexbox-axes/)이고, 이 문제는 정렬로 풀리지 않는다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 이유 |
|---|---|---|
| 카드 여럿의 내부 줄(제목·본문·버튼)을 맞춘다 | **`rows: subgrid`** | 이 기능의 본래 자리 |
| 폼의 라벨 열과 입력 열을 행마다 맞춘다 | **`columns: subgrid`** | 행마다 라벨 폭이 달라지는 문제 |
| 페이지 전체 그리드에 섹션을 맞춰 넣는다 | **`columns: subgrid`** + 부모 라인 이름 | 자식이 부모 좌표계를 그대로 쓴다 |
| 카드 안이 카드마다 완전히 다르다 | 중첩 격자 | 맞출 줄이 없으면 쓸 이유가 없다 |
| 칸 안에서 항목 하나를 위/아래로 붙인다 | `align-self`([24번](../24-flexbox-axes/)) | 칸이 같다면 정렬로 충분하다 |
| 2023 이전 브라우저까지 지원해야 한다 | 대체 경로를 둔다 | Baseline newly 가 2023-09-15 다 |

판단 규칙 두 줄.

- **「카드 사이에 맞춰야 할 가로줄이 있나」를 먼저 묻는다.** 없으면 중첩 격자로 충분하다.
- **`subgrid` 를 쓰기로 했으면 `span` 과 `gap` 을 건드리지 않는다.** 둘이 이 기능의 전제다.

## 핵심 문장

- `subgrid` 는 **맞추는 기능이 아니라 「자기 격자를 안 만드는」 기능**이다. 맞는 것은 그 결과다.
- 중첩 격자로는 안 되는 이유는 **격자가 셋이라 서로를 모르기** 때문이다(실측 9.5px 어긋남).
- **`grid-row: span N` 이 같이 있어야 뜻이 있다.** 없으면 트랙 하나만 물려받아 무력하다.
- 계산값은 **px 이 아니라 `subgrid [] [] []`** 다. **대괄호 개수 = 물려받은 라인 수.**
- `gap` 은 부모 것을 쓴다 — 계산값은 `normal` 인데 화면에는 간격이 있다. 덮어쓰면 **트랙이 그 자리를 먹어** 부모와 어긋난다.
- **라인 이름도 물려받는데 계산값에는 안 보인다.** 빈 대괄호는 「내가 더한 이름이 없다」는 뜻이다.
- 서브그리드 안의 항목이 **부모 트랙의 크기 결정에 참여한다** — 그래서 부모 행이 `26.5px 26.5px` 에서 `38px 19px` 로 바뀐다.

## 용어 풀이

- **서브그리드(subgrid)** — 부모 격자의 항목이면서 자신도 격자 컨테이너인데, **자기 트랙을 안 만들고 부모 트랙을 잇는** 요소.
- **중첩 격자(nested grid)** — 항목 안에 또 만든 격자. **부모와 독립된 트랙**을 갖는다.
- **트랙 상속** — 서브그리드가 **자기가 덮는 범위만큼** 부모의 트랙을 그대로 쓰는 것.
- **라인 이름 상속** — 부모의 `[이름]` 을 자식 안에서 그대로 쓸 수 있는 것. **계산값에는 안 보인다.**
- **`gap` 상속** — 서브그리드가 `gap` 을 안 주면 부모 것을 쓰는 것. 계산값은 `normal` 로 남는다.
- **`subgrid [] [] []`** — 서브그리드의 트랙 계산값 형태. 대괄호 하나가 **라인 하나**다.
- **`span N`** — 「N 칸」([28번](../28-grid-placement/)). `subgrid` 가 뜻을 가지려면 이것이 필요하다.
- **Baseline widely** — 주요 엔진 전부에서 30개월 이상 쓸 수 있는 상태. `subgrid` 는 2026-03-15 부터다.

## 더 들어가면

- **`subgrid` 는 두 축을 따로 정한다.** 행만 잇고 열은 자기가 만들 수 있고 그 반대도 된다.\
  실무에서 압도적으로 많은 것은 **행만 잇는 쪽**이다 — 카드 안의 가로줄을 맞추는 문제가 그만큼 흔하다.
- **`subgrid` 는 `display: grid` 인 요소에만 쓸 수 있다.** `display: contents`([16번](../16-display-inner-outer/))로 래퍼를 지우는 옛 기법과는 **다른 도구**다.\
  `contents` 는 래퍼를 **없애서** 자식을 부모의 직접 항목으로 만들고, `subgrid` 는 래퍼를 **남긴 채** 격자선만 잇는다.\
  래퍼에 배경·테두리를 그려야 하면 `contents` 로는 안 되고 `subgrid` 여야 한다.
- **Masonry(`grid-template-rows: masonry`)와는 별개**다. 그쪽은 Baseline **limited** 이고 문법도 아직 논쟁 중이라 이 목록에서 뺐다(목록 README 의 「뺀 것과 이유」).
- **`subgrid` 가 Grid 본체보다 6년 늦게 도착한 것**이 실무 코드에 남아 있다. `subgrid` 이전에는 같은 문제를\
  ① 카드 내부를 **부모 격자의 직접 항목**으로 올리거나(래퍼를 없앤다 — 배경·테두리를 못 그린다),\
  ② JS 로 높이를 재서 맞추거나, ③ 그냥 어긋난 채 두는 것으로 풀었다. 셋 다 대가가 있었다.
- **`grid-template-areas` 는 서브그리드에서도 쓸 수 있다.** 다만 물려받은 트랙 수와 도면의 칸 수가 맞아야 하고,\
  안 맞으면 [29번](../29-grid-template-areas/)의 규칙대로 **조용히 버려진다.** 이 문서에서는 **안 돌려 봤다.**
