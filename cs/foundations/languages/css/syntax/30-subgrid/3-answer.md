# css/syntax/30 — `subgrid`: 부모 트랙을 자식이 잇는 것 — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **트랙 값은 `getComputedStyle(el).gridTemplateColumns`/`.gridTemplateRows`, 항목 좌표는 `getBoundingClientRect()`** 로 **Google Chrome 151.0.7922.173** headless 에서 각각 따로 잰 값이다.\
> 좌표는 **그 항목을 담은 격자 컨테이너의 안쪽 왼쪽 위를 원점**으로 한 값이고 단위는 px 다(서브그리드 안의 항목은 서브그리드 기준, 서브그리드 자신은 부모 기준).\
> 규칙은 [CSS Grid Layout Level 2](https://drafts.csswg.org/css-grid-2/) 로 접지했다.

## 정답

### 1. 왜 중첩 격자로는 안 되나

**계산값과 좌표** (Chrome 151 headless — 카드 기준 좌표)

```text
부모 행 계산값      "26.5px 26.5px"
카드1 행 계산값     "28.5px 28.5px"    본문 top 28.5
카드2 행 계산값     "38px 19px"        본문 top 38
                                        └─ 9.5px 어긋난다
```

**같은 줄에 놓이는가**

- **안 놓인다.** 본문의 윗변이 28.5 와 38 로 **9.5px** 어긋난다.

**격자가 몇 개인가**

```text
  부모 격자              카드1 격자             카드2 격자
  +----+----+            +--------+            +--------+
  |    |    |            | 제목   |            | 제목   |
  |    |    |            |        |            | (두 줄)|
  +----+----+            | 본문   |            |        |
                         +--------+            | 본문   |
                                               +--------+
   격자가 셋이고 서로를 모른다
```

- 카드마다 `auto auto` 가 **자기 내용만 보고** 57px 를 나눈다. 카드1 은 28.5/28.5, 카드2 는 38/19.
- **서로의 제목 높이를 알 길이 없다.**

**무엇으로 재는가**

- **카드 안 `본문` 의 `getBoundingClientRect().top`** 둘을 비교한다. 카드의 `gridTemplateRows` 계산값을 읽어도 같은 답이 나온다.
- ★ 화면으로 「줄이 안 맞네」는 보이지만 **몇 px 인지는 눈으로 못 센다.**

**`align-items` 로 되나**

- **안 된다.** 정렬은 **칸 안에서** 항목을 움직일 뿐이고, **칸(행) 자체가 카드마다 다르다.**
- 정렬 어휘의 정본은 [24번](../24-flexbox-axes/)이지만, 이 문제는 그 도구로 풀리지 않는다.

### 2. `subgrid` 가 하는 일

**「맞춰 주는 기능」인가**

- **아니다.** 「자기 격자를 **안 만드는**」 기능이다. 맞는 것은 그 **결과**다.

**한 문장으로**

- **자식이 자기 트랙을 만들지 않고 부모가 만든 트랙을 그대로 잇는다.**

**부모의 행 크기는 그대로인가**

- **바뀐다.** 실측 — 부모 행 계산값이 **`26.5px 26.5px` → `38px 19px`** 로 바뀌었다.

**메커니즘과의 연결**

```text
중첩 격자
  부모 행:  내용 없이 57px 를 반씩 나눈다       26.5 / 26.5
  카드 행:  카드마다 자기 내용으로 나눈다        28.5/28.5  ·  38/19   <- 서로 다르다

subgrid
  카드 행:  안 만든다
  부모 행:  두 카드 안의 제목·본문이 전부 부모 트랙 크기 결정에 참여한다
            -> 제목 행 = 두 제목 중 큰 쪽(38), 본문 행 = 19
            -> 카드 둘이 같은 트랙을 쓰니 맞을 수밖에 없다   (본문 top 둘 다 42)
```

- ★ 「**서브그리드 안의 항목이 부모 트랙의 크기 결정에 참여한다**」가 핵심이다. 그냥 물려받기만 하는 게 아니다.

### 3. 성립 조건 셋

```text
① 그 요소가 격자 항목이어야 한다     부모가 display: grid
② 그 요소가 격자 컨테이너여야 한다   자신도 display: grid
③ 그 축에서 부모 트랙을 덮어야 한다  grid-row: span N
```

**계산값에 안 드러나는 것**

- **③**이다. ①이 없으면 계산값이 `none` 이라 눈에 띄지만, ③이 빠지면 계산값이 **`subgrid [] []` 로 멀쩡해 보인다.**

**부모가 격자가 아니면**

- 계산값이 **`none`**. 실측에서 자식이 1열 격자처럼 200px 을 다 차지했다.

**`span N` 을 안 줬을 때**

- **제목과 본문이 같은 칸에 겹친다.** 실측 — 카드 행 계산값 `subgrid [] []`(라인 둘 = 트랙 하나)이고\
  제목과 본문이 **둘 다 y=0, h=38** 로 같은 자리에 놓였다.
- 「안 맞는다」가 아니라 「**겹친다**」라 증상이 더 심한데도 계산값에는 `subgrid` 가 보인다.

### 4. 계산값이 무엇을 돌려주나

**계산값** (Chrome 151 headless — 부모 4열, 서브그리드가 `grid-column: 2 / 4`)

```text
getComputedStyle(.outer).gridTemplateColumns  ->  "100px 100px 100px 100px"
getComputedStyle(.sub  ).gridTemplateColumns  ->  "subgrid [] [] []"
```

**px 이 나오는가**

- **안 나온다.** ★ [27번](../27-grid-track-sizing/)·[28번](../28-grid-placement/)에서 계산값이 늘 px 로 풀려 왔던 것과 **갈리는 자리**다.
- 서브그리드에는 **자기 트랙 크기라는 것이 없다.**

**대괄호 개수**

- **물려받은 라인 수**다. `[] [] []` 셋이면 라인 셋 = **트랙 둘**.
- 그래서 **「몇 칸을 물려받았나」를 이것으로 센다.** 눈으로 세지 않는다.

**실제 폭은 어디서**

- **부모의 계산값**에서 읽는다.

### 5. 덮는 만큼만

**계산값과 좌표** (세 가지를 나란히 잰 결과)

```text
grid-column: 2 / 4  + subgrid   cols "subgrid [] [] []"    1(x=0) 2(x=100) 3(x=0, y=19)
grid-column: 1 / -1 + subgrid   cols "subgrid [] [] [] [] []"  1(x=0) 2(x=100) 3(x=200)
grid-column: 2 / 4  + subgrid 없음  cols "200px"           1(y=0) 2(y=19) 3(y=38) 폭 200
```

**셋째는 어디에**

- **아랫줄 왼쪽**(x=0, y=19). 트랙이 둘뿐이라 줄바꿈됐다.

**`1 / -1` 로 바꾸면**

- 계산값이 **`subgrid [] [] [] [] []`**(라인 다섯 = 트랙 넷)이 되고 셋이 **한 줄에** 놓인다(x=0·100·200).

**`subgrid` 를 지우면**

- 자기 격자가 **1열**이 되어 셋이 **세로로 쌓인다**(폭은 셋 다 200px).

**무엇으로 확인했는가**

- **계산값의 대괄호 개수**(물려받은 트랙 수)와 **항목 좌표**(줄바꿈 여부) 둘을 따로 봤다.\
  하나만 보면 「왜 세 번째가 내려갔지」의 원인을 못 짚는다.

### 6. `gap`

**계산값과 좌표** (Chrome 151 headless — 부모 `gap: 30px`, 열 `100px ×3`)

```text
물려받은 쪽        columnGap 계산값 "normal"   항목 x=0 · 130 · 260   폭 전부 100
column-gap: 0      columnGap 계산값 "0px"      항목 x=0 · 115 · 245   폭 115 · 130 · 115
column-gap: 60px   columnGap 계산값 "60px"     항목 x=0 · 145 · 275   폭 85 · 70 · 85
```

**`columnGap` 계산값**

- **`normal`** 이다.

**화면의 간격**

- **30px** 이다. 항목이 x=0 과 x=130 에 있고 첫 폭이 100 이므로 그 사이가 30 이다.
- ★ `normal` 은 「간격이 없다」가 아니라 「**내 것이 없어서 부모 것을 쓴다**」는 뜻이다. 이 주제에서 계산값을 가장 잘못 읽기 쉬운 자리다.

**`column-gap: 0` 을 주면**

- 트랙 폭이 **115 · 130 · 115** 로 커진다. 부모와 **자리가 어긋난다.**

**부모의 `gap` 자리는 어디로**

```text
부모        [ 100 ]  30  [ 100 ]  30  [ 100 ]        전체 360
서브그리드   [  115  ][   130   ][  115  ]            전체 360
              └─ 부모의 gap 30 씩이 양옆 트랙과 가운데 트랙에 흡수됐다
```

- **트랙이 먹는다.** 서브그리드의 라인 위치는 부모 라인에 고정돼 있는데 그 사이 간격을 0 으로 만들었으니,\
  간격이 차지하던 폭이 **트랙 쪽으로 넘어간다.**
- 그래서 **맞추려고 쓴 기능인데 `gap` 을 만지면 도로 어긋난다.** 실측 — 부모 `gap` 을 0 으로 바꾸면 두 서브그리드가 **다시 똑같아졌다**(둘 다 x=0·100·200, 폭 100).

### 7. 라인 이름

**계산값과 좌표**

```text
getComputedStyle(.outer).gridTemplateColumns  ->  "[a] 100px [b] 100px [c] 100px [d]"
getComputedStyle(.sub  ).gridTemplateColumns  ->  "subgrid [] [] [] []"
.m 의 gridColumnStart/End                      ->  "b" / "b"
.m 의 좌표                                      ->  x=100  w=100
```

**`.m` 은 어디에**

- **가운데 칸**(x=100, 폭 100). 부모의 `b` 라인이 자식 안에서 그대로 동작한다.

**계산값에 `[b]` 가 보이는가**

- **안 보인다.** 대괄호가 전부 비어 있다.

**빈 대괄호의 뜻**

```text
  부모 계산값      "[a] 100px [b] 100px [c] 100px [d]"     이름이 보인다
  서브그리드 계산값 "subgrid [] [] [] []"                   이름이 안 보인다
  그런데 실제로는   grid-column: b 가 동작한다              (좌표 x=100 이 증거)

  -> 빈 대괄호 = "이 서브그리드가 추가로 붙인 이름이 없다"
     "물려받은 이름이 없다" 가 아니다.
```

- 이것이 **계산값만 읽으면 틀리는 자리**다. 좌표를 같이 재야 보인다.

**자기 이름을 더하면**

- 실측 — `grid-template-columns: subgrid [p] [q]` 의 계산값이 **`subgrid [p] [q] [] []`** 이고,\
  `grid-column: p` 인 항목이 **첫 칸**(x=0 w=100)에 놓였다. **내가 붙인 이름은 서브그리드의 첫 라인부터** 차례로 붙는다.

### 8. 진단

```text
① getComputedStyle(자식).gridTemplateRows
        "subgrid …"  -> 살아 있다. ②로
        "none"       -> 부모가 격자가 아니다 (또는 선언이 버려졌다)
        "38px 19px"  -> subgrid 가 아니라 제 트랙을 만들었다 = 선언이 안 먹었다
        ↓
② 대괄호 개수를 센다
        [] [] []     -> 라인 셋 = 트랙 둘을 물려받았다
        [] []        -> 라인 둘 = 트랙 하나뿐 = grid-row: span N 이 빠졌다
        ↓
③ getComputedStyle(부모).gridTemplateRows 로 실제 px 을 읽는다
```

**셋의 뜻**

| 계산값 | 뜻 |
|---|---|
| `none` | 부모가 격자가 아니다(또는 선언이 버려졌다) |
| `subgrid [] []` | 살아 있는데 **트랙을 하나만** 물려받았다 — `span` 이 빠졌다 |
| `38px 19px` | `subgrid` 가 아니라 **제 트랙을 만들었다** — 선언이 안 먹었다 |

**가장 흔한 원인**

- **`grid-row: span N` 누락.** 「맞춰지지 않는다」의 대부분이 이것이고, 계산값에 `subgrid` 가 보여서 더 안 잡힌다.

**「진단 3창」과 무엇이 다른가**

- [27번](../27-grid-track-sizing/)의 3창은 **선언이 살아남았나**를 본다(담겼나 → 잡혔나 → 이겼나).
- 여기는 **살아남은 뒤 몇 칸을 물려받았나**를 본다. **둘은 짝이지 대체가 아니다.**

### 9. 무효한 형태

**`grid-template-rows: subgrid 100px`**

- **무효다.** `subgrid` 뒤에는 **트랙 크기를 쓸 수 없다.**

**어떻게 확인했는가**

- **대조군 기법** — 같은 규칙에 `grid-template-rows: 40px` 을 먼저 쓰고 그 아래 `subgrid 100px` 을 썼더니\
  계산값이 **`40px`** 로 남았다. 뒤 선언이 버려졌다는 뜻이다([27번](../27-grid-track-sizing/)의 진단 3창).

**뒤에 붙일 수 있는 것**

- **라인 이름만**. `grid-template-columns: subgrid [p] [q]` 처럼 쓴다.

**두 축 다**

```css
.sub { display: grid;
       grid-template-columns: subgrid;
       grid-template-rows: subgrid; }
```

- `subgrid` 는 **속성이 아니라 값**이므로 축마다 한 줄씩 쓴다.

### 10. 언제 쓰고 언제 안 쓰나

**본래 자리 둘**

| 상황 | 축 |
|---|---|
| 카드 여럿의 내부 줄(제목·본문·버튼)을 맞춘다 | **`rows: subgrid`** |
| 폼의 라벨 열과 입력 열을 행마다 맞춘다 | **`columns: subgrid`** |

**중첩 격자로 충분한 경우**

- **카드끼리 맞춰야 할 줄이 없을 때.** 카드 안이 카드마다 완전히 다르면 맞출 것이 없다.

**`display: contents` 와 무엇이 다른가**

```text
display: contents                     subgrid
래퍼 상자를 없앤다                      래퍼 상자를 남긴다
자식이 부모의 직접 항목이 된다           래퍼가 격자선만 잇는다
래퍼에 배경·테두리를 못 그린다           래퍼에 배경·테두리를 그릴 수 있다
```

**옛 기법이 못 하는 것**

- **래퍼에 배경·테두리·`border-radius` 를 그리는 것.** 카드에 테두리가 있어야 하면 `contents` 로는 안 되고 `subgrid` 여야 한다.
- `display` 값의 정본은 [16번](../16-display-inner-outer/)이다.

### 11. 버전과 보장

**Baseline**

- **widely.** newly **2023-09-15** → widely **2026-03-15**(목록 README 의 지원 표).

**Grid 본체와의 차이**

- Grid 는 newly 2017-10-17 → widely 2020-04-17. **`subgrid` 가 6년 가까이 늦다.**
- 그래서 2023 이전에 쓰인 코드는 같은 문제를 ① 래퍼를 없애거나 ② JS 로 높이를 재거나 ③ 그냥 어긋난 채 두는 것으로 풀었다.

**명세인가 구현인가**

| 항목 | 어느 쪽 |
|---|---|
| `subgrid` 의 의미(자기 트랙을 안 만든다) | **명세**(CSS Grid Level 2) |
| `gap` 을 물려받는다 | **명세** |
| 라인 이름을 물려받는다 | **명세** |
| 서브그리드 항목이 부모 트랙 크기에 기여한다 | **명세** |
| 부모가 격자가 아니면 `none` 으로 떨어진다 | **명세**(폴백 규정) |
| 계산값이 **`subgrid [] [] []`** 문자열로 온다 | **구현 관찰**(Chrome 151) |
| `columnGap` 계산값이 `normal` 로 남는다 | **구현 관찰**(Chrome 151) |
| 28.5 · 38 · 42 · 115 · 130 같은 px 값 | **이 판의 값** — 재현되는 것은 성질이다 |

### 12. 다른 주제와 잇기

**`span` 의 정본**

- 목록의 [**28번 주제**](../28-grid-placement/)(Grid 배치). 라인 번호·`span`·자동 배치·암묵 트랙이 거기다.

**라인 이름과 도면의 정본**

- 목록의 [**29번 주제**](../29-grid-template-areas/)(Grid 영역). 여기서는 **그 이름이 자식으로 내려가는 것**만 다룬다.

**`gap` 의 정본**

- [목록의 **26번 주제**](../26-flex-wrap-gap-order/)(flex 줄바꿈·`gap`·`order`)다. 이 주제는 「**부모 것을 물려받는다**」와 「**덮어쓰면 트랙이 그 자리를 먹는다**」까지만 다룬다.\
  [27번](../27-grid-track-sizing/)에서는 「`gap` 이 자유 공간에서 먼저 빠진다」를 다뤘다 — 셋이 겹치지 않게 갈라 놨다.

**정렬의 정본**

- 목록의 [**24번 주제**](../24-flexbox-axes/)다. 이 문서는 「**정렬로는 이 문제가 안 풀린다**」를 말하려고만 인용한다.

## 용어 풀이

- **서브그리드(subgrid)** — 부모 격자의 항목이면서 자신도 격자 컨테이너인데, 자기 트랙을 안 만들고 부모 트랙을 잇는 요소.
- **중첩 격자(nested grid)** — 항목 안에 또 만든 격자. **부모와 독립된 트랙**을 갖는다.
- **트랙 상속** — 서브그리드가 **자기가 덮는 범위만큼** 부모 트랙을 쓰는 것. 대괄호 개수로 센다.
- **라인 이름 상속** — 부모의 `[이름]` 을 자식 안에서 쓸 수 있는 것. **계산값에는 안 보인다.**
- **`gap` 상속** — `gap` 을 안 주면 부모 것을 쓰는 것. 계산값은 `normal` 로 남는다.
- **`subgrid [] [] []`** — 서브그리드 트랙의 계산값 형태. 대괄호 하나가 **라인 하나**다.
- **`span N`** — 「N 칸」(28번). `subgrid` 가 뜻을 가지려면 필요하다.
- **Baseline widely** — 주요 엔진 전부에서 30개월 이상 쓸 수 있는 상태. `subgrid` 는 2026-03-15 부터다.

## 실행 검증

| 무엇을 | 어떻게 | 결과 |
|---|---|---|
| 중첩 격자가 어긋나는 것 | Chrome 151.0.7922.173 headless · 카드 둘(제목 1줄 / 2줄) | 카드 행 `28.5px 28.5px` 대 `38px 19px` · 본문 top **28.5 대 38** |
| `subgrid` 가 맞추는 것 | 같은 마크업에 `grid-template-rows: subgrid` | 카드 행 둘 다 `subgrid [] [] []` · 본문 top **둘 다 42** |
| 부모 트랙이 바뀌는 것 | 같은 판의 부모 행 계산값 | `26.5px 26.5px` → **`38px 19px`** |
| `span` 누락 | `grid-row: span 2` 를 지운 판 | 계산값 `subgrid [] []` · 제목과 본문이 **둘 다 y=0 h=38 로 겹침** |
| 부모가 격자가 아닐 때 | 블록 컨테이너의 자식에 `columns: subgrid` | 계산값 **`none`** · 자식이 200px 전부 차지 |
| 덮는 만큼만 물려받기 | `grid-column: 2 / 4` 대 `1 / -1` | `subgrid [] [] []` 대 `subgrid [] [] [] [] []` · 셋째 항목 줄바꿈 여부가 갈림 |
| `subgrid` 를 뺐을 때 | 같은 상자에 `grid-template-columns: none` | 계산값 `200px` · 항목 셋이 y=0·19·38 로 세로로 쌓임 |
| `gap` 상속 | 부모 `gap: 30px` · 서브그리드는 선언 없음 | `columnGap` 계산값 **`normal`** · 항목 x=0·130·260, 폭 전부 100 |
| `gap` 덮어쓰기 | 같은 서브그리드에 `column-gap: 0` / `60px` | 폭 **115·130·115** / **85·70·85** — 트랙이 `gap` 자리를 먹는다 |
| 부모 `gap` 이 0 일 때 | 부모 `gap: 0` + 서브그리드 `column-gap: 0` | 두 서브그리드가 **동일**(x=0·100·200, 폭 100) |
| 라인 이름 상속 | 부모 `[a] 100px [b] …` + 자식 `grid-column: b` | 자식 계산값 `subgrid [] [] [] []`(이름 안 보임) · 항목 **x=100 w=100** |
| 이름을 못 쓰게 됐을 때 | 같은 판에서 `subgrid` 제거 | 항목이 **x=145.97 w=154.03** 인 엉뚱한 자리로 |
| 자기 이름 추가 | `grid-template-columns: subgrid [p] [q]` | 계산값 **`subgrid [p] [q] [] []`** · `grid-column: p` → x=0 w=100 |
| 무효한 형태 | 대조군 `40px` 아래 `subgrid 100px` | 계산값 `40px` = **버려짐** |
| demo 4개 | 완성된 문서에서 다시 뽑아(`extract-demo-blocks.py --render`) 재실행 + 스크린샷 | 「보이는 것」 4건 모두 화면·계산값과 일치 |

**안 돌려 본 것** — **서브그리드 안에서 `grid-template-areas` 를 쓰는 것**은 실행하지 않았다. 이 문서의 과녁(중첩 격자로는 왜 안 되나) 밖이라 **「안 돌려 봄」으로 남긴다.**

**구현 의존 항목** — **계산값의 직렬화 형태**(`subgrid [] [] []` 문자열 · `columnGap` 이 `normal` 로 남는 것)는 Chrome 151 에서 관찰한 것이다. 버전이 오르면 이 칸을 다시 찍는다.\
**px 값**(28.5 · 38 · 42 · 115 · 130)은 이 머신의 폰트·창 크기에 딸린 값이다 — 재현되는 것은 「어긋난다/맞는다」와 「트랙이 `gap` 자리를 먹는다」는 성질이다.\
**엔진은 Chrome 하나다.** Firefox 155.0.1 은 이 환경에서 headless 스크린샷이 산출되지 않고 WebKit 은 이 머신에 없다 — **「두 엔진에서 확인했다」고 적지 않았다.** 크로스 브라우저 상태는 `subgrid` 가 Baseline **widely**(newly 2023-09-15 → widely 2026-03-15)라는 데이터로만 접지했다.
