# css/syntax/28 — Grid 배치: 라인 번호·`span`·자동 배치 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Grid Layout Level 1](https://drafts.csswg.org/css-grid-1/) (격자 항목 배치 알고리즘·`grid-row`/`grid-column`/`grid-area`·`grid-auto-flow`). 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 `demo` 블록 **4개 전부**와 본문의 좌표를 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워 쟀다.\
> **트랙은 `getComputedStyle(el).gridTemplateColumns`/`.gridTemplateRows` 로, 항목의 자리는 `getBoundingClientRect()` 로 따로** 잰다 — 둘은 다른 질문이다. 본문의 px 값은 전부 그 실측값이다.\
> **엔진은 Chrome 하나다** — Firefox 155.0.1 은 이 환경에서 headless 스크린샷이 산출되지 않고 WebKit 은 이 머신에 없다. 「두 엔진에서 확인했다」고 적지 않았다.
> **버전** — Grid 는 Baseline **widely**(newly 2017-10-17 → widely 2020-04-17).
> **여기서 다루지 않는 것** — **트랙을 어떻게 만드는가**는 [**27번**](../27-grid-track-sizing/)이 정본이다(이 문서는 그 실측을 그대로 이어 쓴다). **이름으로 놓는 것**(`grid-template-areas`·이름 붙은 라인)은 [**29번**](../29-grid-template-areas/)이다. 정렬(`justify-*`/`align-*`)의 정본은 [**24번**](../24-flexbox-axes/)이고 여기서는 Grid 에서 갈리는 것만 쓴다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 수치는 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**라인 번호 = 주차장 바닥에 그어진 선의 번호. 항목은 「몇 번 선에서 몇 번 선까지」로 자리를 잡는다.**

[27번](../27-grid-track-sizing/)의 비유를 그대로 잇는다 — 거기서 칸막이를 세웠고, 여기서는 **그 칸막이에 번호를 매겨 물건을 놓는다.**

| 비유 | 실체 |
|---|---|
| 바닥에 그은 선 | **격자 라인(grid line)** — 트랙 사이의 경계 |
| 선에 매긴 번호 (왼쪽부터 1) | **양수 라인 번호** |
| 선에 매긴 번호 (오른쪽부터 −1) | **음수 라인 번호** |
| 「3번 선에서 5번 선까지 주차」 | `grid-column: 3 / 5` |
| 「3번 선에서 두 칸」 | `grid-column: 3 / span 2` |
| 아무 말 안 하면 빈자리에 알아서 | **자동 배치(auto-placement)** |
| 「뒤 차가 앞의 빈자리를 메워도 된다」 | `grid-auto-flow: dense` |

- **라인 번호는 화면에 안 보인다.** 그래서 Grid 배치는 **머릿속에 번호를 그려 넣는 것**이 전부다.\
  이 문서의 도식이 전부 번호를 붙인 격자인 이유가 그것이다.
- **번호는 1부터다.** 트랙이 아니라 **라인**을 세는 것이라, 4열 격자의 세로 라인은 1\~5 다섯 개다.
- **Grid 는 겹침을 허용한다.** 두 항목을 같은 칸에 놓을 수 있다 — flex 에는 없는 자리다.

```text
grid-template-columns: repeat(4, 100px)     (열 트랙 4개 -> 세로 라인 5개)

  1      2      3      4      5        <- 양수: 왼쪽부터
  │      │      │      │      │
  ├──────┼──────┼──────┼──────┤
  │ 트랙1│ 트랙2│ 트랙3│ 트랙4│
  ├──────┼──────┼──────┼──────┤
  │      │      │      │      │
 -5     -4     -3     -2     -1        <- 음수: 오른쪽부터
```

> **격자 라인(grid line)** — 트랙과 트랙 사이(와 양 끝)의 경계선. 화면에 안 보이고 번호만 있다.\
> 예: 열 트랙이 4개면 세로 라인은 5개이고 번호는 1\~5(= −5\~−1)다.

> **자동 배치(auto-placement)** — 자리를 안 정해 준 항목을 엔진이 커서를 움직이며 채워 넣는 것.\
> 예: `display: grid` 만 주고 항목을 넣으면 전부 자동 배치다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. `grid-column: 1 / 3` 과 `1 / span 2` 는 왜 같은 결과인가 — **무엇을 세는가.**
2. 자리를 안 정해 준 항목은 **어느 순서로 어디에** 놓이는가, `dense` 는 그 순서의 무엇을 바꾸나.
3. **정의하지 않은 자리**에 항목을 놓으면 무슨 일이 일어나는가.

## 동작 방식

### (1) 라인 번호 — 트랙이 아니라 라인을 센다

**언제 쓰나** — 항목의 자리를 손으로 지정할 때. 배치 이야기의 전부가 여기서 시작한다.

```text
grid-column: <시작 라인> / <끝 라인>

  grid-column: 1 / 3        라인 1 ~ 라인 3  = 트랙 1·2 를 덮는다 (두 칸)
  grid-column: 2 / 3        라인 2 ~ 라인 3  = 트랙 2 만        (한 칸)
  grid-column: 3            끝을 생략하면 한 칸 (= 3 / 4)
```

**「두 칸」을 원하면서 `1 / 2` 라고 쓰는 것이 이 주제의 첫 사고다.**

```text
  라인:  1      2      3      4      5
         ├──────┼──────┼──────┼──────┤
  1 / 3  │◄──────────►│      │      │    두 칸
  1 / 2  │◄────►│     │      │      │    한 칸 (라인 둘 사이는 트랙 하나)
```

- 세는 대상이 **라인**이므로 「3 − 1 = 트랙 2개」로 읽으면 된다.
- `grid-row` 도 똑같다. `grid-area` 는 넷을 한 줄에 쓴다 — (6).

### (2) `span N` — 시작만 알고 개수를 말하는 법

**언제 쓰나** — 트랙 수가 바뀌어도 「두 칸」은 유지하고 싶을 때.

```text
  grid-column: 1 / 3        "라인 1 에서 라인 3 까지"
  grid-column: 1 / span 2   "라인 1 에서 두 칸"          <- 같은 결과
  grid-column: span 2       "어디든 두 칸"               <- 시작은 자동 배치가 정한다
  grid-column: span 2 / 5   "라인 5 에서 왼쪽으로 두 칸"  = 3 / 5
```

```html demo
<div class="g"><i class="a">1 / 3</i><i class="b">1 / span 2</i><i class="c">-3 / -1</i></div>
<style>
  .g { display: grid; width: 400px; gap: 4px; border: 2px solid #94a3b8;
       grid-template-columns: repeat(4, 1fr); grid-auto-rows: 32px; }
  .a { grid-column: 1 / 3; }        /* 라인 1 에서 라인 3 까지 */
  .b { grid-column: 1 / span 2; }   /* 라인 1 에서 두 칸 — 위와 같은 결과 */
  .c { grid-column: -3 / -1; }      /* 끝에서 셋째 라인 ~ 마지막 라인 */
  .g i { background: #bfdbfe; font: 13px system-ui; font-style: normal;
         outline: 1px solid #2563eb; }
</style>
```

> **보이는 것** — 파란 상자 셋이 두 줄로 놓인다. **윗줄에는 `1 / 3` 하나**가 왼쪽 절반을 덮고 오른쪽 절반은 비어 있다. **아랫줄에는 `1 / span 2` 가 왼쪽 절반, `-3 / -1` 이 오른쪽 절반**을 덮는다. 세 상자의 **폭이 전부 똑같다**(각각 두 칸).\
> **바꿔 볼 것** — `.a` 의 `1 / 3` → `1 / 2` 하면 그 상자만 **절반 폭**(한 칸)이 된다 · `.c` 의 `-3 / -1` → `3 / -1` 하면 **자리가 안 바뀐다**(같은 두 칸을 가리킨다) · `.b` 의 `1 / span 2` → `span 2` 로 시작을 지우면 자동 배치가 자리를 정한다

*(Chrome 151 headless 실측 — 컨테이너 안쪽 400px, 트랙 계산값 `97px 97px 97px 97px`(gap 4px). 항목 좌표는 `getBoundingClientRect()` 로 따로 쟀다: `1 / 3` → x=2 y=2 w=198 · `1 / span 2` → x=2 y=38 w=198 · `-3 / -1` → x=204 y=38 w=198. 앞의 둘이 **폭도 시작점도 똑같다.**)*

- `1 / 3` 과 `1 / span 2` 는 **같은 것을 다르게 쓴 것**이다. 실측 폭이 둘 다 198px 이다.
- 어느 쪽을 쓰느냐는 **무엇이 안 변하길 바라나**로 고른다 — 끝 라인을 고정하려면 앞엣것, 칸 수를 고정하려면 뒤엣것.

### (3) 음수 라인 — 끝에서 오는 번호

**언제 쓰나** — 트랙 수가 몇 개든 「마지막 칸까지」를 쓰고 싶을 때.

```text
4열 격자
  양수:  1      2      3      4      5
  음수: -5     -4     -3     -2     -1

  grid-column: 1 / -1      전체 폭            <- 가장 많이 쓰는 형태
  grid-column: -3 / -1     마지막 두 칸
  grid-column: -2          마지막 한 칸
```

- **`-1` 은 「마지막 라인」이지 「마지막 트랙」이 아니다.** 그래서 「전체」는 `1 / -1` 이지 `1 / -0` 도 `0 / -1` 도 아니다.
- **`0` 이라는 라인 번호는 없다.** 양수는 1부터, 음수는 −1부터다.

★ **음수는 「명시 격자」의 끝에서 센다 — 암묵 트랙은 안 센다.**

```text
grid-template-columns: 100px 100px       (명시 열 2개)
+ 어떤 항목을 grid-column: 5 에 놓아서 암묵 열 3·4·5 가 생겼다

  실제 트랙:  [100][100][60][60][60]
  라인:        1    2    3   4   5   6
  음수:            -3   -1               <- 여기서 끝난다 (명시 격자의 끝)
                        ^ grid-column: -1 은 여기를 가리킨다
```

*(Chrome 151 headless 실측 — 명시 열 2개인 컨테이너에 `grid-column: 5` 인 항목을 넣어 계산값이 `100px 100px 60px 60px 60px` 가 된 판에서, `grid-column: -1` 인 항목의 x 가 **202**(세 번째 트랙의 시작)였다. 암묵 격자의 끝(x=382)이 아니다.)*

- 암묵 트랙에는 **라인 이름도 음수 번호도 없다.** 엔진이 만든 것이라 내가 셀 수 있는 좌표계 밖이다.
- 그래서 **`1 / -1` 이 「보이는 전체」가 아닐 수 있다.** 암묵 열이 생긴 격자에서는 오른쪽이 남는다.

### (4) 자동 배치 — 커서가 어떻게 움직이나

**언제 쓰나** — 항목 수가 정해지지 않은 목록을 격자에 부을 때(대부분의 실무 격자다).

```text
grid-auto-flow: row  (기본)          grid-auto-flow: column

커서가 행을 따라 왼→오, 끝나면 다음 행    커서가 열을 따라 위→아래, 끝나면 다음 열

  [1][2][3][4]                        [1][3][5]
  [5][6][7][8]                        [2][4][6]
   ─────────>                          │  │  │
   한 행을 다 쓰고 아래로               한 열을 다 쓰고 오른쪽으로
```

배치 알고리즘을 순서대로 읽으면 이렇다.

```text
① 행·열을 **둘 다** 지정한 항목을 먼저 놓는다        (완전 고정)
        ↓
② 행만(흐름이 row 면) 지정한 항목을 그 행에 놓는다    (부분 고정)
        ↓
③ 나머지를 커서로 훑으며 빈자리에 채운다             (자동)
        ↓
④ 자리가 모자라면 암묵 트랙을 만든다 -> (5)
```

- ★ **③의 커서는 기본적으로 뒤로 안 간다.** 앞에 빈칸이 남아도 지나친 자리는 다시 안 본다.\
  그래서 큰 항목 하나가 줄 끝을 못 채우면 **구멍이 남는다.** 그 구멍을 메우는 것이 `dense` 다 — (6).
- `grid-auto-flow: column` 은 **커서 방향만** 바꾼다. `flex-direction` 과 달리 정렬 속성의 의미는 안 바뀐다.\
  *(실측 — 명시 열 2개 · `grid-auto-flow: column` 컨테이너에 항목 5개: 계산값이 `100px 100px 60px 60px 60px` 로 **열이 세 개 자랐고**, 항목은 x=2·102·202·262·322 로 가로로 이어졌다.)*

### (5) 암묵 트랙 — 없는 자리에 놓으면 격자가 자란다

**언제 쓰나** — `grid-row: 3` 처럼 정의 안 한 번호를 쓸 때. **에러가 안 난다.**

```html demo
<div class="g"><i class="far">4 / 5</i><i class="low">row 3</i></div>
<style>
  .g { display: grid; width: 400px; gap: 4px; border: 2px solid #94a3b8;
       grid-template-columns: 100px 100px;   /* 명시 격자는 2열 1행뿐 */
       grid-template-rows: 32px;
       grid-auto-columns: 60px; grid-auto-rows: 24px; }
  .far { grid-column: 4 / 5; }   /* 없는 자리 -> 암묵 열이 자란다 */
  .low { grid-row: 3; }          /* 없는 자리 -> 암묵 행이 자란다 */
  .g i { background: #bfdbfe; font: 13px system-ui; font-style: normal;
         outline: 1px solid #2563eb; }
</style>
```

> **보이는 것** — 에러 없이 그려지되 **격자가 자란다.** 위쪽에 **좁은 상자(`4 / 5`)가 왼쪽이 아니라 한참 오른쪽에** 홀로 놓이고(왼쪽 두 칸은 비어 있다), 그 아래 **두 줄을 건너뛴 자리에 `row 3`** 이 왼쪽 끝에 놓인다. 둘 사이에 빈 줄이 하나 있다.\
> **바꿔 볼 것** — `grid-auto-columns: 60px` 을 지우면 암묵 열이 `auto` 가 되어 상자가 **오히려 넓어진다**(실측 폭 60 → **107.42px**) — `auto` 트랙은 남는 공간을 받아 늘어나기 때문이다([27번](../27-grid-track-sizing/)) · `.low` 의 `grid-row: 3` → `grid-row: 1` 하면 두 항목이 **같은 줄**(둘 다 y=2)에 온다

*(Chrome 151 headless 실측 — 트랙 계산값 `cols: 100px 100px 60px 60px` · `rows: 32px 24px 24px`. **선언에는 열 둘·행 하나뿐인데 계산값에 넷·셋이 왔다** — 뒤쪽 둘·둘이 암묵 트랙이다. 항목 좌표: `4 / 5` → x=274 y=2 w=60 h=32 · `row 3` → x=2 y=66 w=100 h=24.)*

```text
선언                          계산값 (= 엔진이 실제로 만든 것)
cols: 100px 100px             cols: 100px 100px [60px] [60px]
rows: 32px                    rows: 32px [24px] [24px]
                                          └────┴──── 대괄호가 암묵 트랙
```

- ★ **암묵 트랙이 생긴 것을 화면으로는 못 본다** — 빈 트랙에는 아무것도 안 그려진다.\
  **`gridTemplateColumns`·`gridTemplateRows` 를 읽어야** 「내가 안 만든 트랙이 둘 있다」가 보인다.
- 암묵 트랙의 크기는 `grid-auto-columns`/`grid-auto-rows` 가 정한다. 안 주면 `auto` 다 — 정본은 [**27번**](../27-grid-track-sizing/).
- 이것이 「레이아웃이 갑자기 이상해졌다」의 흔한 원인이다 — **오타 하나(`grid-column: 11`)가 열 아홉 개를 만든다.**

### (6) `dense` — 뒤 항목이 앞의 빈칸을 메운다

**언제 쓰나** — 크기가 제각각인 타일을 빈틈없이 채우고 싶을 때. **접근성 대가가 있다.**

```html demo
<div class="g">      <i class="w3">A</i><i class="w2">B</i><i>C</i><i>D</i></div>
<div class="g dense"><i class="w3">A</i><i class="w2">B</i><i>C</i><i>D</i></div>
<style>
  .g { display: grid; width: 400px; margin-bottom: 8px; border: 2px solid #94a3b8;
       grid-template-columns: repeat(4, 100px); grid-auto-rows: 32px; }
  .dense { grid-auto-flow: row dense; }   /* 뒤에 온 작은 항목이 앞의 빈칸을 메운다 */
  .w3 { grid-column: span 3; }
  .w2 { grid-column: span 2; }
  .g i { background: #bfdbfe; font: 13px system-ui; font-style: normal;
         outline: 1px solid #2563eb; }
</style>
```

> **보이는 것** — 위 격자는 **오른쪽 위에 빈칸 하나**가 남고 아랫줄이 `B B C D` 로 채워진다. 아래 격자는 그 빈칸에 **`C` 가 올라가 있고** 아랫줄이 `B B D` 로 끝나 **오른쪽 아래가 빈다.** 마크업 순서는 둘 다 A·B·C·D 로 똑같은데 **아래 격자만 화면에서 A → C → B → D 순으로 읽힌다.**\
> **바꿔 볼 것** — `.dense` 의 `row dense` → `row` 로 되돌리면 위 격자와 똑같아진다 · `.w2` 의 `span 2` → `span 1` 하면 빈칸이 안 생겨 **두 격자가 같아진다**(메울 구멍이 없으므로)

*(Chrome 151 headless 실측 — 두 격자의 트랙 계산값은 똑같이 `100px 100px 100px 100px`. 항목 좌표만 갈린다: 기본 흐름 `C`(x=202, y=34) · `D`(x=302, y=34) / `dense` `C`(**x=302, y=2**) · `D`(x=202, y=34). `grid-auto-flow` 계산값은 `row` 대 `dense` 였다 — `row` 는 기본값이라 직렬화에서 빠진다.)*

```text
기본 (row)                          dense
+-----+-----+-----+-----+          +-----+-----+-----+-----+
|     A     A     |  □  |          |     A     A     |  C  |   <- C 가 올라왔다
+-----+-----+-----+-----+          +-----+-----+-----+-----+
|   B     B |  C  |  D  |          |   B     B |  D  |  □  |
+-----+-----+-----+-----+          +-----+-----+-----+-----+
 읽는 순서 = 마크업 순서              화면 순서 A C B D ≠ 마크업 순서 A B C D
```

그림 해설 (한 단계씩):

- `dense` 는 커서를 **매번 격자의 처음부터** 다시 훑게 한다. 그래서 뒤에 온 작은 항목이 앞의 구멍을 메운다.
- **마크업 순서는 한 글자도 안 바뀐다** — 스크린 리더가 읽는 순서와 키보드 Tab 순서는 여전히 A → B → C → D 다.
- 그래서 **눈으로 읽는 순서와 기계가 읽는 순서가 어긋난다.** 이것은 [목록의 **26번 주제**](../26-flex-wrap-gap-order/)의 `order` 와 **같은 계열의 접근성 문제**다.\
  `order` 도 Grid 항목에 그대로 듣는다 — *(실측: `order: 2`·`order: 1` 을 준 두 항목의 x 가 102·2 로 **뒤바뀌었다**.)*
- 판단 규칙: **읽는 순서가 의미를 갖는 콘텐츠에는 `dense` 를 쓰지 않는다.** 장식적 타일(사진 갤러리)에만 쓴다.

비용 — `dense` 는 배치 패스를 더 돌지만 실무에서 문제 되는 비용은 그게 아니라 **접근성**이다.

### (7) Grid 는 겹침을 허용한다 — flex 와 갈리는 자리

**언제 쓰나** — 사진 위에 캡션, 카드 위에 배지처럼 **같은 칸에 둘을 쌓을 때.**

```html demo
<div class="g"><i class="p">먼저 · 1~3열</i><i class="q">나중 · 1~2열</i></div>
<style>
  .g { display: grid; width: 300px; border: 2px solid #94a3b8;
       grid-template-columns: 150px 150px; grid-auto-rows: 40px; }
  .p { grid-area: 1 / 1 / 2 / 3; background: #fca5a5; }  /* 같은 칸에 */
  .q { grid-area: 1 / 1 / 2 / 2; background: #86efac; }  /* 겹쳐 놓는다 */
  .g i { font: 13px system-ui; font-style: normal; outline: 1px solid #2563eb; }
</style>
```

> **보이는 것** — 한 줄짜리 격자인데 **왼쪽 절반이 초록, 오른쪽 절반이 빨강**으로 보인다. 빨강 상자는 사실 **두 칸 전체**에 깔려 있고, 뒤에 온 초록 상자가 **왼쪽 칸 위를 덮은** 것이다. 초록 상자의 글자만 보이고 빨강 상자의 글자는 가려져 안 보인다.\
> **바꿔 볼 것** — `.p` 에 `z-index: 1` 을 더하면 **빨강이 위로 올라와 줄 전체가 빨강**이 되고 초록이 사라진다 · `.q` 의 `grid-area` 를 `1 / 2 / 2 / 3` 으로 바꾸면 겹치지 않아 **빨강 왼쪽 절반 + 초록 오른쪽 절반**이 된다

*(Chrome 151 headless 실측 — 두 항목의 좌표가 **둘 다 x=2, y=2** 다. 폭만 300 과 150 으로 다르다. 트랙 계산값은 `150px 150px` 한 줄이고 행도 하나뿐이다 — **항목이 둘인데 행이 안 늘어난 것**이 겹쳤다는 증거다. `z-index: 1` 을 준 판을 스크린샷으로도 확인했다.)*

```text
flex                                  grid
  아이템은 주축 위에 줄지어 놓인다        항목은 「몇 번 라인부터 몇 번 라인까지」
  같은 자리에 둘을 못 놓는다             같은 칸에 여럿을 놓을 수 있다
  겹치려면 position: absolute          grid-area 만으로 겹친다
```

- 겹쳤을 때 **위에 오는 것은 마크업에서 뒤에 온 항목**이다(칠하는 순서).
- `z-index` 로 뒤집을 수 있다 — **grid 항목은 `position: static` 이어도 `z-index` 가 듣는다.**\
  이것은 flex 항목도 같고, 쌓임 맥락의 정본은 [목록의 **22번 주제**](../22-stacking-context-and-z-index/)다.

### (8) Grid 에는 `justify-self` 가 있다 — flex 에는 없는 자리

**언제 쓰나** — 항목 하나만 자기 칸 안에서 다르게 붙이고 싶을 때.

```text
flex 의 주축                            grid 의 칸
+--------------------------------+     +---------+---------+
| 자유 공간을 아이템들이 나눠 갖는다 |     | 칸마다   | 칸마다   |
| 한 아이템만 "끝으로"라고 하면     |     | 자유 공간이       |
| 나머지 배치가 정의되지 않는다      |     | 따로 있다        |
+--------------------------------+     +---------+---------+
   -> justify-self 가 없다                 -> justify-self 가 있다
```

*(Chrome 151 headless 실측 — 같은 선언 `justify-self: end` 를 준 항목: **grid** 에서는 x 가 261.7 로 칸 오른쪽 끝에 붙고 폭이 내용 크기(39.3px)로 줄었다. **flex** 에서는 계산값이 `end` 로 남는데도 x 가 9.69 로 **전혀 안 움직였다** — 무시된 것이다.)*

- ★ **정렬 어휘(`justify-*`/`align-*`)의 정본은 [24번](../24-flexbox-axes/)이다.** 여기서는 **Grid 에서 의미가 갈리는 것만** 적는다.
- 갈리는 것 셋:

| | flex | grid |
|---|---|---|
| `justify-self` | **없다**(무시된다) | **있다** — 칸 안에서 인라인 축 배치 |
| `justify-content` | 주축에서 **아이템 묶음**을 민다 | 인라인 축에서 **트랙 묶음**을 민다 |
| `align-content` | 줄바꿈이 켜졌을 때만 의미 | 행 트랙이 있으면 늘 의미가 있다 |

- `justify-items`/`align-items` 는 **모든 칸의 기본 배치**를 정하고, `*-self` 가 항목 하나를 예외로 만든다.
- `place-self`·`place-items`·`place-content` 는 **`align` 먼저, `justify` 나중**인 단축이다.

## 문법 — 형태와 어디서 헷갈리나

CSS 는 문법 표면이 단순하다. 외울 것은 형태가 아니라 **값이 무엇을 가리키는가**다.

### 최소 형태

```css
.item {
  grid-column: 2 / 4;        /* = grid-column-start: 2; grid-column-end: 4 */
  grid-row: 1 / span 2;      /* = grid-row-start: 1;    grid-row-end: span 2 */
  grid-area: 1 / 2 / 3 / 4;  /* row-start / column-start / row-end / column-end */
}
.container {
  grid-auto-flow: row;       /* 기본. column · row dense · column dense */
  grid-auto-rows: 100px;     /* 암묵 행의 크기 (27번) */
}
```

★ **`grid-area` 의 네 값 순서가 이 주제에서 가장 헷갈리는 자리다.**

```text
grid-area:  row-start / column-start / row-end / column-end
              ①           ②            ③         ④
              위           왼쪽          아래       오른쪽

  시계 방향이 아니다. "시작 둘 먼저, 끝 둘 나중" 도 아니다.
  외우는 법:  세로(행) → 가로(열) → 세로(행) → 가로(열)   — 번갈아 간다
              그리고 앞 둘이 시작, 뒤 둘이 끝.
```

*(Chrome 151 headless 실측 — 2열 × 40px 두 행짜리 격자에서 `grid-area: 2 / 1 / 3 / 3` 인 항목이 **2행 1\~3열**에 놓였다: x=2 y=42 w=200 h=40. 「2행부터 3행 전까지, 1열부터 3열 전까지」로 읽으면 맞는다. 같은 판에서 `grid-column` 의 계산값이 `1 / 3` 으로 직렬화됐다.)*

- 값이 **둘**이면 `grid-area: a / b` 는 `row-start / column-start` 다(끝은 자동).
- `grid-area` 에 **이름** 하나만 쓰는 형태(`grid-area: header`)는 [**29번**](../29-grid-template-areas/)의 자리다.

### 헷갈리는 짝

| 헷갈리는 것 | 실제 |
|---|---|
| `grid-column: 1 / 2` 로 「두 칸」 | **한 칸**이다. 라인 둘 사이는 트랙 하나 |
| `grid-column: 2` | 끝을 생략하면 **한 칸**(= `2 / 3`) |
| `span 2` 와 `2` | 앞엣것은 **개수**, 뒤엣것은 **라인 번호** |
| `grid-column: -1` 이 「마지막 트랙」 | **마지막 라인**이다. 마지막 트랙은 `-2 / -1` |
| `-1` 이 암묵 트랙 끝 | **명시 격자의 끝**이다. 암묵 트랙은 안 센다 |
| `grid-area` 의 순서 | row → column → row → column. 시계 방향이 아니다 |
| `grid-auto-flow: dense` | `row dense` 의 줄임이다. 계산값은 `dense` 로 온다 |

### 금지 사례 — 버려지거나 뒤집히는 것

```css
.a { grid-column: 0; }          /* 라인 0 은 없다 — 버려진다 */
.b { grid-column: 2 / 1; }      /* 뒤집힌 순서 — 버려지지 않고 서로 바뀐다 */
.c { grid-column: -1 / -2; }    /* 역시 서로 바뀐다 */
.d { grid-auto-flow: dense row; } /* 순서는 상관없다 — 유효하다 */
```

*(Chrome 151 headless 실측 — `grid-column: 2 / 1` 인 항목의 계산값은 `gridColumnStart: 2` / `gridColumnEnd: 1` **그대로**인데 **자리는 1열**(x=2 w=100)이었다. `-1 / -2` 도 같은 모양으로 2열(x=102)에 놓였다. **계산값만 읽으면 뒤집힌 줄 모른다** — 좌표를 같이 재야 보인다.)*\
*(같은 방법 — `grid-column: 2` 를 대조군으로 깔고 그 아래 `grid-column: 0` 과 `grid-column: 1.5` 를 쓴 판: 둘 다 `rule.style.gridColumn` 이 `"2"` 로 남고 항목이 x=102(2열)에 그대로 있었다 = **버려졌다.** `grid-auto-flow: dense row` 는 계산값 `dense` 로 살아남았다.)*

- **시작이 끝보다 뒤면 엔진이 둘을 맞바꾼다.** 에러도 아니고 무시도 아니다 — **조용히 고쳐서 쓴다.**
- ★ 이것이 「계산값과 좌표를 **따로** 재야 하는」 대표 사례다. 계산값에는 사고의 흔적이 안 남는다.

## 구현 세부사항 대 언어 보장

- **배치 알고리즘의 순서**(고정 → 부분 고정 → 자동 → 암묵 트랙 생성)와 **`dense` 의 동작**은 명세가 정한다. CSS Grid Level 1 의 「grid item placement algorithm」이 근거다.
- **음수 라인이 명시 격자에서 센다**는 것도 명세다 — 암묵 라인에는 번호가 없다고 명시돼 있다.
- **시작/끝이 뒤집혔을 때 맞바꾼다**는 것도 명세의 규정이다.
- **계산값의 직렬화 형태**는 구현 관찰이다 — `grid-auto-flow: row dense` 의 계산값이 `dense` 로 접히는 것, `grid-column-start` 의 계산값이 선언 그대로(`-1`) 남고 맞바꾼 결과가 안 보이는 것은 Chrome 151 에서 본 것이다. **버전이 오르면 다시 찍는 칸**이다.
- **겹친 항목의 칠하는 순서**(마크업 뒤엣것이 위)는 명세(쌓임 순서)가 정하고, 실측은 스크린샷으로 확인했다.
- Grid 자체는 Baseline **widely**(2020-04-17)다.

## 어디서 틀리나

이 주제의 값어치는 여기 몰려 있다. 여섯 다 **에러 없이 조용히 어긋난다.**

### 1. 라인이 아니라 트랙을 센다

`grid-column: 1 / 2` 로 두 칸을 기대한다. **한 칸이다.**\
바른 기억: **끝 − 시작 = 칸 수.**

### 2. `-1` 을 「마지막 트랙」으로 읽는다

`grid-column: -1` 은 **마지막 라인에서 한 칸**이라 암묵 열을 만든다.\
마지막 칸 하나는 `-2 / -1`, 전체는 `1 / -1` 이다.

### 3. 암묵 열이 생긴 격자에서 `1 / -1` 을 쓴다

`-1` 은 **명시 격자의 끝**이므로 암묵 열이 있으면 「보이는 전체」가 아니다.\
실측에서 `-1` 이 5열 격자의 **3번 라인**을 가리켰다.

### 4. 오타 하나가 격자를 늘린다

`grid-column: 11` 을 쓰면 **에러가 아니라 열이 아홉 개 늘어난다.**\
증상은 「오른쪽에 거대한 빈 공간」이고, 원인은 `gridTemplateColumns` 를 읽어야만 보인다.

### 5. `dense` 로 예쁘게 채우고 접근성을 깬다

`dense` 는 **화면 순서만** 바꾸고 마크업 순서는 안 바꾼다.\
읽는 순서가 의미를 갖는 곳에서는 쓰지 않는다. 26번의 `order` 와 같은 문제다.

### 6. `grid-area` 의 네 값 순서를 시계 방향으로 외운다

`margin: 위 오른쪽 아래 왼쪽` 과 **다르다.**\
`grid-area: row-start / column-start / row-end / column-end` — 세로·가로가 번갈아 간다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 이유 |
|---|---|---|
| 개수가 정해진 레이아웃 뼈대 | 라인 번호 또는 **영역 이름**([29번](../29-grid-template-areas/)) | 이름 쪽이 읽기 쉽다 |
| 「무조건 한 줄 전체」 | `grid-column: 1 / -1` | 트랙 수가 바뀌어도 그대로다 |
| 「어디든 두 칸」 | `grid-column: span 2` | 시작을 자동 배치에 맡긴다 |
| 개수가 정해지지 않은 목록 | 자동 배치 + `grid-auto-rows` | 배치를 안 쓰는 것이 정답이다 |
| 크기 제각각인 사진 갤러리 | `grid-auto-flow: dense` | 읽는 순서가 의미 없을 때만 |
| 본문·기사처럼 읽는 순서가 중요 | `dense` 를 **쓰지 않는다** | 마크업 순서와 어긋난다 |
| 같은 칸에 배지·캡션 겹치기 | `grid-area` 로 같은 칸 지정 | `position: absolute` 가 필요 없다 |
| 한 축만 신경 쓰면 되는 배치 | Grid 말고 **Flexbox** | [24번](../24-flexbox-axes/) |

판단 규칙 두 줄.

- **자리를 지정할 필요가 없으면 지정하지 않는 것이 가장 튼튼하다.** 자동 배치가 트랙 수 변화에 제일 강하다.
- **지정해야 한다면 번호보다 이름**([29번](../29-grid-template-areas/))**이 읽기 쉽다.** 번호는 트랙을 하나 끼워 넣는 순간 전부 밀린다.

## 핵심 문장

- 번호가 붙는 것은 트랙이 아니라 **라인**이다. `1 / 3` 은 **두 칸**이고 `1 / 2` 는 한 칸이다.
- `1 / 3` 과 `1 / span 2` 는 **같은 것**이다 — 끝 라인을 고정할지 칸 수를 고정할지가 다를 뿐이다.
- 음수 라인은 **명시 격자의 끝에서** 센다. 암묵 트랙에는 번호가 없다.
- 정의 안 한 자리에 놓으면 **에러가 아니라 격자가 자란다.** `gridTemplateColumns`/`Rows` 를 읽어야 보인다.
- `dense` 는 **화면 순서만** 바꾼다 — 마크업 순서·Tab 순서는 그대로라 읽는 순서가 어긋난다(26번의 `order` 와 같은 계열).
- **Grid 는 겹침을 허용하고 `justify-self` 가 있다.** 칸이 미리 나뉘어 있어 자유 공간이 칸마다 따로 있기 때문이다.
- 시작이 끝보다 뒤면 **조용히 맞바꾼다.** 계산값에는 흔적이 안 남으므로 좌표를 같이 재야 한다.

## 용어 풀이

- **격자 라인(grid line)** — 트랙 사이와 양 끝의 경계. 번호는 1부터, 음수는 −1부터다. 0은 없다.
- **양수 라인 번호 / 음수 라인 번호** — 시작 쪽부터 / 끝 쪽부터 센 번호. **둘 다 명시 격자 기준**이다.
- **`span N`** — 「N 칸」. 라인 번호가 아니라 개수다.
- **자동 배치(auto-placement)** — 자리를 안 정한 항목을 커서로 훑으며 채우는 것.
- **배치 커서(placement cursor)** — 자동 배치가 들고 다니는 위치. 기본 흐름에서는 뒤로 안 간다.
- **`grid-auto-flow`** — 커서가 행을 따라가나(`row`) 열을 따라가나(`column`), 그리고 구멍을 메우나(`dense`).
- **`dense`** — 커서를 매번 처음부터 다시 훑게 해 구멍을 메운다. **마크업 순서는 안 바꾼다.**
- **명시 격자 / 암묵 격자** — 내가 정의한 트랙 / 항목 때문에 엔진이 만든 트랙(27번).
- **`grid-area`** — `row-start / column-start / row-end / column-end` 네 값 단축. 또는 영역 이름 하나(29번).
- **`justify-self` / `align-self`** — 칸 **안에서** 항목 하나를 인라인 축 / 블록 축으로 배치한다. Grid 에만 둘 다 있다.

## 더 들어가면

- **`grid-auto-flow: column` 은 flex 의 `flex-direction: column` 과 다르다.** 앞엣것은 **커서 방향**만 바꾸고 정렬 속성의 의미는 그대로인데,\
  뒤엣것은 **주축 자체를 돌려서** `justify-content` 의 뜻까지 바꾼다([24번](../24-flexbox-axes/)). 이름이 비슷해서 헷갈리는 자리다.
- **명시 배치가 자동 배치를 방해할 수 있다.** 자동 배치는 「고정된 항목이 이미 차지한 칸」을 피해 가는데,\
  고정 항목이 커서보다 **앞줄**에 있으면 기본 흐름에서는 그 뒤의 구멍이 영영 안 메워진다. `dense` 가 이 문제를 푼다.
- **격자 항목의 마진은 상쇄되지 않는다.** 블록 흐름이 아니기 때문이다 — 마진 상쇄의 정본은 [18번](../18-margin-collapsing/)이고,\
  거기서 「상쇄가 안 되는 문맥」으로 flex·grid 가 나온다. 그래서 Grid 격자에서는 `gap` 과 마진이 **더해진다.**
- **`grid-template-areas` 를 쓰면 라인 이름이 자동으로 생긴다** — 그때부터는 번호 대신 이름을 쓰는 것이 낫다([29번](../29-grid-template-areas/)).
- **`order` 는 Grid 에서도 듣는다.** 자동 배치의 순서를 바꾸는데, `dense` 와 마찬가지로 **마크업 순서는 안 바꾼다.**\
  *(실측: `order: 2`/`order: 1` 을 준 두 항목의 x 가 102·2 로 뒤바뀌었다.)* 정본은 [목록의 **26번 주제**](../26-flex-wrap-gap-order/)다.
