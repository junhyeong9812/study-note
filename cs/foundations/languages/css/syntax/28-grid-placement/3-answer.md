# css/syntax/28 — Grid 배치: 라인 번호·`span`·자동 배치 — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **트랙 값은 `getComputedStyle(el).gridTemplateColumns`/`.gridTemplateRows`, 항목 좌표는 `getBoundingClientRect()`** 로 **Google Chrome 151.0.7922.173** headless 에서 각각 따로 잰 값이다.\
> 좌표는 별말이 없으면 **컨테이너의 바깥 왼쪽 위 모서리를 원점**으로 한 값이고 단위는 px 다(테두리 2px 을 포함하므로 내용 영역의 왼쪽 위는 x=2, y=2 다).\
> 규칙은 [CSS Grid Layout Level 1](https://drafts.csswg.org/css-grid-1/) 로 접지했다.

## 정답

### 1. 라인 번호가 세는 것

**좌표** (Chrome 151 headless — 내용 폭 400px, `repeat(4, 1fr)` + `gap: 4px` → 트랙 계산값 `97px 97px 97px 97px`)

```text
1 / 3         x=2    y=2    w=198
1 / span 2    x=2    y=38   w=198      <- 폭도 시작점도 위와 같다
-3 / -1       x=204  y=38   w=198
```

**`.a` 는 몇 칸인가**

- **두 칸.** 라인 1에서 라인 3까지 사이에 트랙이 둘 있다. **끝 − 시작 = 칸 수.**

**`.a` 와 `.b`**

- **같다.** `1 / span 2` = 「라인 1에서 두 칸」 = 라인 1\~3. 실측 폭이 둘 다 198px 이다.
- 다른 것은 **무엇이 고정되느냐**뿐이다 — 앞엣것은 끝 라인, 뒤엣것은 칸 수.

**`.c` 는 어느 칸**

- **마지막 두 칸**(트랙 3·4). x=204 로 격자의 오른쪽 절반이다.

**라인 개수**

```text
  1      2      3      4      5      <- 트랙이 4개면 라인은 5개
  ├──────┼──────┼──────┼──────┤
  │  1   │  2   │  3   │  4   │
  ├──────┼──────┼──────┼──────┤
 -5     -4     -3     -2     -1      <- 음수는 −1 부터. 0 은 없다
```

### 2. 「두 칸」을 쓰는 세 가지

| 쓴 것 | 칸 수 | 읽는 법 |
|---|---|---|
| `grid-column: 1 / 2` | **한 칸** | 라인 1\~2 사이에 트랙은 하나 |
| `grid-column: 2` | **한 칸** | 끝을 생략하면 `2 / 3` 과 같다 |
| `grid-column: span 2` | **두 칸** | 시작은 자동 배치가 정한다 |
| `grid-column: span 2 / 5` | **두 칸** | 라인 5에서 **왼쪽으로** 두 칸 = `3 / 5` |

**`span 2` 와 `2`**

- `span 2` 는 **개수**, `2` 는 **라인 번호**다. 같은 자리에 쓰이지만 전혀 다른 뜻이다.
- 그래서 `grid-column: 2 / span 2` 는 「라인 2에서 두 칸」 = `2 / 4` 이고, `2 / 2` 가 아니다.

### 3. 음수 라인과 암묵 트랙

**계산값과 좌표** (Chrome 151 headless — 명시 열 2개 + `grid-auto-columns: 60px`)

```text
gridTemplateColumns  ->  "100px 100px 60px 60px 60px"     (열이 5개로 자랐다)
grid-column: 5  인 항목   ->  x=322
grid-column: -1 인 항목   ->  x=202                        <- 오른쪽 끝이 아니다
```

**오른쪽 끝에 놓이는가**

- **아니다.** x=202 는 **세 번째 트랙의 시작**이다. 격자의 오른쪽 끝(x=382)이 아니다.

**어느 격자를 기준으로 세는가**

```text
  실제 트랙:  [100][100][60][60][60]
  라인 번호:   1    2    3   4   5   6
  음수 번호:  -3   -2   -1                <- 명시 격자(열 2개)의 끝에서 멈춘다
                        ^ grid-column: -1 이 가리키는 라인
```

- **명시 격자**다. 암묵 트랙에는 **번호도 이름도 없다** — 엔진이 만든 것이라 내가 셀 수 있는 좌표계 밖이다.

**`1 / -1` 이 「보이는 전체」가 아닌 경우**

- **암묵 열이 생겼을 때.** 위 격자에서 `1 / -1` 은 앞의 두 칸(200px)만 덮고 오른쪽 180px 은 남는다.
- 그래서 `1 / -1` 을 쓸 때는 **암묵 열이 없다는 것을 먼저 확인**해야 한다 — `gridTemplateColumns` 를 읽으면 된다.

### 4. 정의 안 한 자리에 놓으면

**계산값과 좌표** (Chrome 151 headless — 선언은 `cols: 100px 100px` · `rows: 32px` · `gap: 4px`)

```text
gridTemplateColumns  ->  "100px 100px 60px 60px"     선언에는 둘뿐인데 넷
gridTemplateRows     ->  "32px 24px 24px"            선언에는 하나뿐인데 셋

grid-column: 4 / 5   ->  x=274  y=2   w=60  h=32
grid-row: 3          ->  x=2    y=66  w=100 h=24
```

**에러가 나는가**

- **안 난다.** CSS 는 에러가 없는 언어다. 격자가 **조용히 자란다.**

**화면만 보고 알 수 있는가**

- **없다.** 빈 암묵 트랙에는 아무것도 안 그려진다. 「오른쪽에 여백이 넓네」로만 보인다.
- ★ **`gridTemplateColumns`·`gridTemplateRows` 를 읽어야** 「내가 안 만든 트랙이 둘 있다」가 보인다.\
  이것이 [27번](../27-grid-track-sizing/)의 「계산값에 암묵 트랙이 섞여 온다」가 배치 쪽에서 쓰이는 자리다.

**`grid-column: 11` 이라는 오타**

- **열이 아홉 개 늘어난다.** 증상은 「오른쪽에 거대한 빈 공간」이고 콘솔에는 아무것도 안 뜬다.
- `grid-auto-columns` 를 안 줬으면 그 아홉 개가 전부 `auto`(= 내용이 없으니 0 에 가깝다)라 **증상이 더 흐려진다.**

### 5. 자동 배치의 커서

**좌표** (Chrome 151 headless — `repeat(4, 100px)`, `grid-auto-rows: 32px`, 항목 A(span 3)·B(span 2)·C·D)

```text
기본 흐름(row)                    dense
A  x=2    y=2    w=300           A  x=2    y=2    w=300
B  x=2    y=34   w=200           B  x=2    y=34   w=200
C  x=202  y=34   w=100           C  x=302  y=2    w=100    <- 윗줄로 올라갔다
D  x=302  y=34   w=100           D  x=202  y=34   w=100
```

**각각 몇 행 몇 열인가** (기본 흐름)

```text
      열1    열2    열3    열4
 행1 [  A     A     A  ] [ □ ]      <- A 가 세 칸, 넷째가 빈다
 행2 [  B     B  ] [ C ] [ D ]      <- B 는 넷째 칸에 못 들어가 다음 행으로
```

- A 는 세 칸이라 행 1의 1\~3열. **넷째 칸이 남는다.**
- B 는 두 칸인데 행 1에 한 칸밖에 안 남아 **행 2**로 내려간다. 그 뒤에 C·D.

**빈칸이 왜 안 메워지는가**

- 기본 흐름의 **배치 커서는 뒤로 안 간다.** B 를 놓느라 커서가 행 2로 내려간 뒤에는 행 1의 빈칸을 다시 안 본다.

**`dense` 를 주면**

- **C 가 행 1의 넷째 칸으로 올라가고**(x=302 y=2) D 가 행 2의 셋째 칸(x=202 y=34)에 놓인다.
- 빈칸은 이제 **행 2의 넷째 칸**으로 옮겨간다.

**배치 알고리즘 네 단계**

```text
① 행·열을 둘 다 지정한 항목을 먼저 놓는다
② 행만(흐름이 row 면) 지정한 항목을 그 행에 놓는다
③ 나머지를 커서로 훑으며 빈자리에 채운다   <- dense 는 여기서 매번 처음부터 다시 훑는다
④ 자리가 모자라면 암묵 트랙을 만든다
```

### 6. `dense` 의 대가

**마크업 순서를 바꾸는가**

- **안 바꾼다.** DOM 은 A·B·C·D 그대로이고 **화면에서만** A → C → B → D 로 읽힌다.

**스크린 리더와 Tab 이 따르는 순서**

- **마크업 순서**다. 그래서 눈으로 읽는 순서와 기계가 읽는 순서가 어긋난다.

**같은 계열**

- [목록의 **26번 주제**](../26-flex-wrap-gap-order/)의 **`order`** 다. `order` 도 Grid 항목에 그대로 듣는다.\
  *(실측: `order: 2`·`order: 1` 을 준 두 항목의 x 가 **102·2** 로 뒤바뀌었다 — 마크업 순서는 그대로다.)*
- 둘 다 「시각 순서와 읽는 순서를 분리하는 기능」이고, 분리 자체가 접근성 문제다.

**가르는 기준**

| 써도 되는 것 | 쓰면 안 되는 것 |
|---|---|
| 사진 갤러리·타일 대시보드 — **순서에 의미가 없는 것** | 기사·목록·단계 안내 — **순서가 의미인 것** |
| 항목 하나하나가 독립적으로 읽히는 것 | 앞뒤 문맥이 필요한 것 |

- 판단 한 줄: **「순서를 섞어도 뜻이 안 변하나」를 먼저 묻는다.**

### 7. 겹침

**좌표** (Chrome 151 headless — `150px 150px` 한 행짜리 격자)

```text
.p (먼저, 빨강, 1/1/2/3)   x=2  y=2  w=300  h=40
.q (나중, 초록, 1/1/2/2)   x=2  y=2  w=150  h=40
gridTemplateRows          "40px"          <- 행이 하나뿐이다
```

**겹치는가**

- **겹친다.** 두 항목의 좌표가 **둘 다 x=2, y=2** 다. 행도 하나뿐이다 — 늘어나지 않았다.
- **Grid 는 겹침을 허용한다.** flex 에는 없는 자리다.

**위에 보이는 것**

- **마크업에서 뒤에 온 `.q`**(초록)다. 칠하는 순서가 마크업 순서를 따르기 때문이다.
- *(스크린샷으로 확인 — 왼쪽 절반이 초록, 오른쪽 절반이 빨강으로 보인다.)*

**뒤집으려면**

- **`z-index`.** grid 항목은 `position: static` 이어도 `z-index` 가 듣는다.
- *(실측 — `.p` 에 `z-index: 1` 을 준 판의 스크린샷에서 **줄 전체가 빨강**이 되고 초록이 안 보였다.)*
- 쌓임 맥락의 정본은 [목록의 **22번 주제**](../22-stacking-context-and-z-index/)다.

**flex 에서 같은 일을 하려면**

- **`position: absolute`** 가 필요하다. flex 는 아이템을 주축 위에 줄지어 놓으므로 같은 자리에 둘을 못 놓는다.

### 8. `grid-area` 의 네 값

```text
grid-area:  row-start / column-start / row-end / column-end
              ①           ②            ③         ④
             (위)        (왼쪽)        (아래)     (오른쪽)

  세로 → 가로 → 세로 → 가로.  앞 둘이 시작, 뒤 둘이 끝.
```

**`margin` 과 같은 순서인가**

- **다르다.** `margin: 위 오른쪽 아래 왼쪽` 은 **시계 방향**이고, `grid-area` 는 **축이 번갈아** 간다.
- 이 둘을 같다고 외우면 2·4번째 값이 서로 바뀐다 — 그리고 **에러가 안 나서** 화면이 이상할 때까지 모른다.
- *(실측 — `grid-area: 2 / 1 / 3 / 3` 인 항목이 **2행 1\~3열**(x=2 y=42 w=200 h=40)에 놓였다. 같은 판에서 `grid-column` 계산값이 `1 / 3` 으로 직렬화됐다.)*

**값을 둘만 쓰면**

- `grid-area: 2 / 1` 은 `row-start: 2` · `column-start: 1` 이고 **끝은 자동**(각각 한 칸)이다.

**이름 하나만 쓰는 형태**

- 목록의 [**29번 주제**](../29-grid-template-areas/)가 정본이다. `grid-area: header` 는 영역 이름을 가리킨다.

### 9. 무효한 값과 뒤집힌 값

**결과** (Chrome 151 headless — 같은 규칙에 `grid-column: 2` 를 대조군으로 먼저 쓰고 그 아래 검사 대상)

```text
검사 대상            rule.style.gridColumn   좌표      판정
grid-column: 0       "2"                     x=102     무효 — 버려졌다
grid-column: 1.5     "2"                     x=102     무효 — 버려졌다
grid-column: 2 / 1   "2 / 1"                 x=2       유효 — 맞바꿔서 1열에 놓였다
grid-column: -1 / -2 "-1 / -2"               x=102     유효 — 맞바꿔서 2열에 놓였다
grid-auto-flow: dense row   (계산값 "dense")  —        유효 — 순서 무관
```

**`grid-column: 0`**

- **무효다.** 라인 번호는 1부터, 음수는 −1부터이고 **0 은 없다.** 대조군 `2` 가 그대로 남았다.

**`2 / 1` 은 버려지는가**

- **안 버려진다.** 엔진이 **시작과 끝을 조용히 맞바꾼다.** 에러도 무시도 아니다.

**`getComputedStyle` 만으로 알 수 있는가**

- **없다.** 계산값은 `gridColumnStart: 2` / `gridColumnEnd: 1` **그대로**다 — 맞바꾼 흔적이 안 남는다.
- ★ 그래서 **좌표를 같이 재야 한다.** 이 주제에서 「계산값과 좌표를 따로 잰다」가 필요한 대표 사례다.

**대조군 기법**

- 쓸 수 있다. **무효/유효 판정에는 유효하고**(`0`·`1.5` 가 그렇게 걸렸다), **맞바꿈 판정에는 못 쓴다**(선언이 살아 있으므로).
- 진단 3창의 정본 서술은 [27번](../27-grid-track-sizing/)에 있다.

### 10. Grid 에만 있는 정렬

**flex 아이템에 `justify-self` 를 주면**

- **무시된다.** 에러도 경고도 없다.
- *(실측 — 같은 선언 `justify-self: end`: **grid** 항목은 x 가 261.7 로 칸 오른쪽 끝에 붙고 폭이 내용 크기(39.3px)로 줄었다. **flex** 항목은 계산값이 `end` 로 남는데도 x 가 9.69 로 **전혀 안 움직였다**.)*

**Grid 에서 성립하는 이유**

```text
flex 의 주축                            grid 의 칸
+--------------------------------+     +---------+---------+
| 자유 공간 하나를 아이템들이 나눈다 |     | 칸마다 자유 공간이 따로 |
| 한 아이템만 "끝으로"라고 하면     |     | 있으므로 한 항목만      |
| 나머지 배치가 정의되지 않는다      |     | 예외로 둘 수 있다       |
+--------------------------------+     +---------+---------+
```

- Grid 는 **트랙이 미리 나뉘어 있어** 자유 공간이 **칸마다 따로** 존재한다. 그래서 개별 예외가 정의된다.

**`justify-items` 와 `justify-self`**

- `justify-items` 는 **모든 칸의 기본 배치**, `justify-self` 는 **항목 하나의 예외**다.
- `align-items`/`align-self` 가 블록 축에서 같은 짝을 이룬다.

**정렬 어휘의 정본**

- 목록의 [**24번 주제**](../24-flexbox-axes/)다. 이 문서는 **Grid 에서 갈리는 것만** 적었다.

### 11. `grid-auto-flow: column`

**커서**

```text
row (기본)                     column
[1][2][3][4]                   [1][3][5]
[5][6][7][8]                   [2][4][6]
 ─────────>                     │  │  │
 행을 따라 가다 다음 행           열을 따라 가다 다음 열
```

**flex 의 `flex-direction: column` 과 무엇이 다른가**

- `grid-auto-flow: column` 은 **커서 방향만** 바꾼다. 정렬 속성의 뜻은 그대로다.
- `flex-direction: column` 은 **주축 자체를 돌려서** `justify-content` 가 세로를 가리키게 만든다([24번](../24-flexbox-axes/)).
- *(실측 — `justify-content: end` 를 준 같은 격자에서 흐름을 `row` → `column` 으로 바꿔도 항목 x 가 **202·302 로 똑같았다.** 의미가 안 바뀐다.)*

**항목 5개를 `column` 흐름으로**

- 실측 계산값 `100px 100px 60px 60px 60px` — **명시 열 둘 뒤에 암묵 열 셋**이 자랐다(`grid-auto-columns: 60px`).
- 항목은 x=2·102·202·262·322 로 가로로 이어졌다. 행이 하나뿐이라 열이 늘어난 것이다.

**`justify-content` 의 의미는**

- **안 바뀐다.** Grid 에서 `justify-content` 는 늘 **인라인 축에서 트랙 묶음**을 움직인다.

### 12. 다른 주제와 잇기

**트랙을 만드는 규칙**

- 목록의 [**27번 주제**](../27-grid-track-sizing/). `fr`·`minmax()`·`repeat()`·`auto-fill`/`auto-fit`·암묵 트랙 크기가 거기다.

**이름으로 놓는 것**

- 목록의 [**29번 주제**](../29-grid-template-areas/). `grid-template-areas` 와 이름 붙은 라인이다.

**Grid 항목의 마진은 상쇄되는가**

- **안 된다.** 블록 흐름이 아니기 때문이다.
- *(실측 — 위아래 마진 20px 을 준 항목 둘: **블록 컨테이너**에서는 A 아래 모서리(y=41)와 B 위(y=61) 사이가 **20px**(상쇄) · **grid 컨테이너**에서는 같은 자리가 **40px**(20+20, 상쇄 없음). 컨테이너 높이도 102 대 122 로 갈렸다.)*
- 「언제 상쇄되나」의 정본은 [목록의 **18번 주제**](../18-margin-collapsing/)다.

**명세 보장 대 구현 관찰**

| | 예 |
|---|---|
| **명세가 보장** | 배치 알고리즘 네 단계 · 음수 라인이 명시 격자에서 센다 · 시작/끝이 뒤집히면 맞바꾼다 |
| **Chrome 151 에서 관찰** | `grid-auto-flow: row dense` 의 계산값이 `dense` 로 접혀 직렬화되는 것 · `grid-column-start` 계산값에 맞바꿈 흔적이 안 남는 것 · `grid-area` 가 `grid-column: 1 / 3` 으로 직렬화되는 것 |

## 용어 풀이

- **격자 라인(grid line)** — 트랙 사이와 양 끝의 경계. 번호는 1부터, 음수는 −1부터. **0 은 없다.**
- **`span N`** — 「N 칸」. 라인 번호가 아니라 개수다.
- **명시 격자 / 암묵 격자** — 내가 정의한 트랙 / 항목 때문에 엔진이 만든 트랙. **음수 라인은 명시 격자에서만 센다.**
- **자동 배치(auto-placement)** — 자리를 안 정한 항목을 커서로 훑어 채우는 것.
- **배치 커서(placement cursor)** — 자동 배치가 들고 다니는 위치. 기본 흐름에서는 뒤로 안 간다.
- **`dense`** — 커서를 매번 처음부터 훑게 해 구멍을 메운다. **마크업 순서는 안 바꾼다.**
- **`grid-area`** — `row-start / column-start / row-end / column-end`. 시계 방향이 아니다.
- **`justify-self` / `align-self`** — 칸 안에서 항목 하나를 배치한다. **Grid 에만 둘 다 있다.**
- **칠하는 순서(paint order)** — 겹친 항목 중 무엇이 위에 오는가. 기본은 마크업 순서, `z-index` 로 뒤집는다.

## 실행 검증

| 무엇을 | 어떻게 | 결과 |
|---|---|---|
| `1 / 3` = `1 / span 2` | Chrome 151.0.7922.173 headless · 400px 4열 격자 · `getBoundingClientRect()` | 둘 다 x=2 w=198 — **같다** |
| 음수 라인 | 같은 격자의 `-3 / -1` | x=204 w=198 — 마지막 두 칸 |
| 음수 라인의 기준 | 명시 열 2 + 암묵 열 3 인 격자에서 `grid-column: -1` | x=**202**(명시 격자의 끝) — 암묵 끝(382)이 아니다 |
| 암묵 트랙 생성 | `grid-column: 4 / 5` · `grid-row: 3` | cols `100px 100px 60px 60px` · rows `32px 24px 24px` |
| 자동 배치 커서 | A(span 3)·B(span 2)·C·D | C x=202 y=34 · D x=302 y=34 · 행1 넷째 칸이 빈다 |
| `dense` | 같은 항목에 `grid-auto-flow: row dense` | C **x=302 y=2** · D x=202 y=34 · 트랙 계산값은 둘이 동일 |
| `order` 가 Grid 에서 듣나 | `order: 2` · `order: 1` 두 항목 | x 가 102·2 로 뒤바뀜 |
| 겹침 | `1/1/2/3` 과 `1/1/2/2` 두 항목 | 둘 다 x=2 y=2 · 행은 하나(`40px`) — 겹쳤다 |
| 겹침의 앞뒤 | 스크린샷 + `.p { z-index: 1 }` 판 | 기본은 뒤엣것(초록)이 위 · `z-index` 로 뒤집힘 |
| `grid-area` 네 값 순서 | `grid-area: 2 / 1 / 3 / 3` | x=2 y=42 w=200 h=40 = 2행 1\~3열 |
| 무효한 라인 번호 | 대조군 `grid-column: 2` 아래 `0` · `1.5` | 둘 다 `rule.style` 이 `"2"`, x=102 = 버려짐 |
| 뒤집힌 라인 | `2 / 1` · `-1 / -2` | 계산값은 그대로, 좌표는 맞바뀜(x=2 · x=102) |
| `justify-self` 대비 | 같은 선언을 grid 와 flex 에 | grid x=261.7 로 이동 · flex 계산값 `end` 인데 x=9.69 무변화 |
| `column` 흐름 | 명시 열 2 + 항목 5 + `grid-auto-flow: column` | cols `100px 100px 60px 60px 60px` · x=2·102·202·262·322 |
| 흐름과 `justify-content` | `justify-content: end` 를 `row`/`column` 두 흐름에 | 둘 다 x=202·302 — **의미가 안 바뀐다** |
| 마진 상쇄 | 위아래 마진 20px 인 항목 둘을 블록 / grid 컨테이너에 | 간격 20px(상쇄) 대 40px(상쇄 없음) · 높이 102 대 122 |
| demo 4개 | 완성된 문서에서 다시 뽑아(`extract-demo-blocks.py --render`) 재실행 + 스크린샷 | 「보이는 것」 4건 모두 화면·좌표와 일치 |

**구현 의존 항목** — **계산값의 직렬화 형태**(`row dense` → `dense` · `grid-area` → `grid-column: 1 / 3` · 맞바꿈 흔적이 안 남는 것)는 Chrome 151 에서 관찰한 것이다. 버전이 오르면 이 칸을 다시 찍는다.\
**px 값**은 이 머신의 폰트·창 크기에 딸린 값이다 — 재현되는 것은 숫자가 아니라 성질이다.\
**엔진은 Chrome 하나다.** Firefox 155.0.1 은 이 환경에서 headless 스크린샷이 산출되지 않고 WebKit 은 이 머신에 없다 — **「두 엔진에서 확인했다」고 적지 않았다.** 크로스 브라우저 상태는 Grid 가 Baseline **widely**(2020-04-17)라는 데이터로만 접지했다.
