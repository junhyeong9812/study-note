# css/syntax/12 — `:has()`: 관계 선택자와 그 한계 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [Selectors Level 4 §4.5 The Relational Pseudo-class: `:has()`](https://drafts.csswg.org/selectors-4/#relational) · [같은 문서 §3.9 Invalid Selectors and Error Handling](https://drafts.csswg.org/selectors-4/#invalid) · [같은 문서 §16.1 `<forgiving-selector-list>`](https://drafts.csswg.org/selectors-4/#forgiving-selector). 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 모든 매치 수·명시도·「버려졌나」 판정은 **Google Chrome 151.0.7922.173** headless 에서 실제로 돌렸다.\
> 근거를 **세 층**으로 나눠 뽑았다 — ① `document.styleSheets[].cssRules` 로 **규칙이 담겼나** ② `querySelectorAll().length` 로 **무엇이 잡혔나** ③ `getComputedStyle` 로 **무엇이 이겼나**. 명시도 주장은 전부 ③ 으로만 확인했다.\
> **엔진은 Chrome 하나다.** Firefox 155.0.1 은 이 환경에서 headless 스크린샷이 산출되지 않으므로(목록 README 의 정정) **「두 엔진에서 확인했다」고 적지 않았다.** 크로스 브라우저는 Baseline 으로만 접지한다.\
> **성능은 재지 않았다.** 아래 「구현 세부사항 대 언어 보장」에 그 사실을 그대로 남겼다.
> **버전** — CSS 에 언어 버전은 없다. `:has()` 의 Baseline 은 **widely available**(newly 2023-12-19 → widely 2026-06-19). 2026-09-23 에 `api.webstatus.dev` 를 직접 조회한 값이고, 엔진별 최초 지원은 Chrome/Edge 105(2022-09) · Safari 15.4(2022-03) · Firefox 121(2023-12) 이다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 숫자는 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**`:has()` 는 「고양이를 키우는 집 문에 스티커를 붙인다」이다. 스티커가 붙는 것은 고양이가 아니라 집이다.**

비유 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 집 | **기준 요소** — `:has()` **앞**에 쓴 것. 실제로 선택되는 것 |
| 고양이 | **조건** — `:has()` **안**에 쓴 것. 있는지만 본다 |
| 문에 스티커를 붙인다 | 스타일은 기준 요소에 걸린다 |
| 고양이에는 아무것도 안 붙인다 | 조건에 든 요소는 **선택되지 않는다** |
| 「현관에서 바로 보이는 고양이」 | `:has(> img)` 처럼 상대 선택자로 범위를 좁힌 것 |
| 관리실이 세는 것은 고양이 「있다/없다」 | 몇 마리인지는 안 센다 — 하나라도 있으면 참 |

```text
   .card:has(img)  가 잡는 것은?

   <div class="card">          <-- ★ 이것이 잡힌다 (기준 요소)
        │
        ├── <h3>제목</h3>
        ├── <img>              <-- 조건. 「있나」만 본다. 안 잡힌다
        └── <p>본문</p>
```

- CSS 의 조합자(`공백` `>` `+` `~`)는 전부 **오른쪽으로만** 간다 — 자손·자식·뒤 형제.\
  「이미지를 가진 카드」처럼 **위로 올라가는** 조건은 이전까지 CSS 로 쓸 수 없었다.
- `:has()` 는 그 방향을 뒤집지 않는다. **선택 대상은 그대로 왼쪽에 두고, 조건만 오른쪽을 본다.**
- 그래서 `:has()` 의 별명이 「부모 선택자」인 것은 절반만 맞다 — 부모만 고르는 게 아니라 **형제·손자까지 조건으로 쓸 수 있는 조건부 선택자**다.

실무에서 이게 터지는 자리는 **마크업을 못 바꿀 때**다.\
서버가 내려 준 HTML 에 클래스를 더 붙일 수 없을 때, 지금까지는 JS 로 부모에 클래스를 달았다. `:has()` 가 그 JS 를 없앤다.

> **관계 선택자(relational selector)** — 「어떤 관계에 있는 요소가 존재하는가」를 조건으로 요소를 고르는 선택자.\
> 예: `.card:has(img)` 는 「자기 안에 `img` 가 있는 `.card`」를 고른다.

> **기준 요소(anchor element)** — `:has()` 의 조건을 평가할 때 출발점이 되는 요소. `:has()` 앞에 쓴 것이고, 실제로 선택되는 것도 이것이다.\
> 예: `.card:has(img)` 에서 기준 요소는 `.card` 다.

> **조합자(combinator)** — 선택자를 잇는 기호. 공백(자손) · `>`(자식) · `+`(인접 형제) · `~`(뒤쪽 형제). 정본은 [목록의 **08번 주제**](../08-basic-selectors-and-combinators/).

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. `:has()` 가 쓰인 선택자를 받았을 때 **무엇이 잡히는지** 트리에서 짚을 수 있는가.
2. `:has()` 의 **명시도**는 어디서 오는가 — `:has()` 자체는 몇을 보태는가.
3. **무엇을 못 쓰는가** — 그리고 못 쓰는 것을 썼을 때 **무슨 일이 일어나는가**(에러인가 침묵인가).

## 동작 방식

### (1) 잡히는 것은 조건이 아니라 기준 요소다

**언제 쓰나** — `:has()` 가 들어간 선택자를 읽을 때마다. 이것을 놓치면 나머지가 전부 어긋난다.

실측에 쓴 문서는 이것 하나다. 아래 모든 매치 수가 이 문서에서 나왔다.

```text
#root
 ├── .card#c1 ── h3 · img · p
 ├── .card#c2 ── h3 · p
 ├── .card#c3 ── p ── img        (img 가 p 안에 있다 = 손자)
 └── .card#c4 ── p · span.x
```

```text
  .card:has(img)   을 평가하는 순서

  ① 기준 후보를 모은다        .card  ->  c1 c2 c3 c4
  ② 후보 하나씩 「안에 img 가 있나」를 묻는다
        c1 ── img 있음  -> 참
        c2 ── 없음      -> 거짓
        c3 ── p 안에 img 있음 -> 참  (자손이면 된다)
        c4 ── 없음      -> 거짓
  ③ 참인 후보만 남긴다        ->  c1 c3

  ★ img 자신은 결과에 들어가지 않는다
```

`querySelectorAll()` 로 실제로 잡힌 것 (Chrome 151 headless).

| 선택자 | 잡힌 것 | 읽는 법 |
|---|---|---|
| `.card:has(img)` | `c1`, `c3` | 자손 어디에든 `img` 가 있는 카드 |
| `.card:has(> img)` | `c1` | **직계 자식**으로 있는 것만 — `c3` 은 손자라 빠진다 |
| `.card:has(p)` | `c1`, `c2`, `c3`, `c4` | 넷 다 `p` 를 가졌다 |
| `.card:has(.x)` | `c4` | |
| `.card:not(:has(img))` | `c2`, `c4` | 「이미지가 없는 카드」 |
| `.card:has(+ .card)` | `c1`, `c2`, `c3` | **뒤에 형제 카드가 있는** 카드 — 마지막만 빠진다 |
| `.card:has(~ .card)` | `c1`, `c2`, `c3` | 이 문서에서는 `+` 와 결과가 같다 |
| `h3:has(+ img)` | `h3`(c1 안) | 바로 뒤가 이미지인 제목 |
| `div:has(.card)` | `root` | 카드를 품은 바깥 상자 |
| `img` | `img` 둘 | 비교용 — `:has()` 쪽 결과에 이것이 없다 |

그림 해설 (한 단계씩):

- **`:has()` 는 조합자를 왼쪽으로 뒤집지 않는다.** 기준 요소는 여전히 선택자의 왼쪽에 있고, 오른쪽은 조건일 뿐이다.
- **`> img` 와 `img` 는 다르다.** 앞엣것은 직계 자식만, 뒤엣것은 자손 전부. `c3` 하나가 이 차이를 가른다.
- **`+`·`~` 는 뒤쪽 형제를 본다.** 「뒤에 형제가 없는 마지막 것」을 찾는 데 쓴다(`:has(+ .card)` 의 반대를 취하면 된다).

비용 — 이 문서에서는 재지 않았다. 「구현 세부사항 대 언어 보장」 절을 보라.

```html demo
<div class="card"><img src="data:image/gif;base64,R0lGODlhAQABAIAAAP8AAAAAACH5BAEAAAAALAAAAAABAAEAAAICRAEAOw==" alt=""><p>이미지 있음</p></div>
<div class="card"><p>이미지 없음</p></div>
<style>
  .card { border: 3px solid #d4d4d4; padding: 8px; margin: 6px; }
  .card:has(img) { border-color: #2563eb; background: #eff6ff; }
  img { width: 60px; height: 14px; }
  p { margin: 6px 0 0; }
</style>
```

> **보이는 것** — 조작 없이 처음부터 이렇게 보인다. **위 카드만** 테두리가 파랗고 배경이 연한 파랑으로 칠해진다. 파란 테두리가 **이미지가 아니라 카드 전체를 두르는 것**이 요점이다 — 잡힌 것은 `img` 가 아니라 `.card` 다. 아래 카드는 회색 테두리에 배경 없음 그대로다.\
> **바꿔 볼 것** — `:has(img)` → `:has(> img)`(이 마크업에서는 이미지가 직계 자식이라 **결과가 같다**) · `:has(img)` → `:has(p)`(둘 다 `p` 를 가졌으므로 **두 카드가 모두 파래진다**)

*(Chrome 151 headless 실측: 위 카드 `border-top-color: rgb(37, 99, 235)` · `background-color: rgb(239, 246, 255)`, 아래 카드 `rgb(212, 212, 212)` · `rgba(0, 0, 0, 0)`. `:has(p)` 로 바꾼 판에서는 두 카드 모두 `rgb(37, 99, 235)`.)*

### (2) 상대 선택자 — 조건은 기준 요소에서 출발한다

**언제 쓰나** — `:has()` 안에 `>`·`+`·`~` 를 쓸 때. 「어디서부터 도는가」를 헷갈리면 결과가 뒤집힌다.

```text
  기준 요소에서 출발한다

      .card:has(> img)              .card:has(+ .card)
      기준 = .card                   기준 = .card
         │                              │
         └─(자식만)─> img               └─(바로 뒤 형제)─> .card

   ┌────────────┐                  ┌────────────┐  ┌────────────┐
   │  .card     │                  │  .card     │→ │  .card     │
   │   └ img ✔  │                  └────────────┘  └────────────┘
   │   └ p      │                        ^ 이것이 잡힌다
   │      └ img │  (손자 — ✘)
   └────────────┘
```

명세는 `:has()` 의 인자를 `<relative-selector-list>` 라고 정한다 — **조합자로 시작할 수 있는 선택자 목록**이다.\
조합자를 안 쓰면 **자손 조합자가 암묵으로 붙는다**. 그래서 `:has(img)` 는 `:has( img)`, 곧 「자손에 `img`」다.

- `:has(> img)` — 직계 자식.
- `:has(+ .x)` — 바로 뒤 형제.
- `:has(~ .x)` — 뒤쪽 형제 전부.
- **앞쪽 형제·부모를 조건으로 쓰는 문법은 없다.** `:has(< div)` 같은 것은 없고, 앞쪽 형제는 관계를 뒤집어서 쓴다(`.x:has(+ .card)` = 「뒤에 카드가 있는 `.x`」).

비용 — 재지 않았다.

### (3) 명시도 — `:has()` 자체는 0, 인자 중 가장 센 것

**언제 쓰나** — `:has()` 가 들어간 규칙이 다른 규칙에 지거나 이길 때.

★ **명시도 계산의 정본은 [02번 주제](../02-specificity/2-summary.md)다.** 세 자리 세는 법을 여기서 다시 쓰지 않는다.\
여기서 받아 올 결론은 한 줄이다 — **`:has()` 는 `:is()`·`:not()` 과 같은 규칙으로, 껍데기가 0 이고 인자 목록 중 가장 센 것의 값을 그대로 쓴다.**

```text
  p:has(img, #im)

   ┌ p              타입 하나           (0, 0, 1)
   └ :has(...)      껍데기 = 0
        ├ img       (0, 0, 1)
        └ #im       (1, 0, 0)   <- 가장 센 것
                    치환된 값 =  (1, 0, 0)
                          합 =  (1, 0, 1)

  ★ img 는 무시된다. 「가장 센」은 목록 전체에서 하나만 고른다
```

실측표다. 아래 문서에서 `#t1` 을 대상으로, **동점 경쟁자 · 한 칸 낮은 경쟁자 두 판**으로 위아래를 고정했다(방법은 [02번 주제](../02-specificity/2-summary.md)의 「손으로 세어 보기」와 같다).

```text
<div id="box" class="cbox"><section class="sec">
  <p id="t1" class="c1 c2"><img id="im" class="ic"><span class="sp">s</span></p>
  <p id="t2" class="c3">next</p>
</section></div>
```

| 선택자 | (A, B, C) | 왜 |
|---|---|---|
| `p:has(img)` | (0, 0, 2) | `p` 1 + 인자 `img` 1 — **둘 다 C 자리** |
| `p:has(> img)` | (0, 0, 2) | 조합자는 0 이라 `> img` 와 `img` 가 같다 |
| `p:has(.ic)` | (0, 1, 1) | 인자가 클래스면 B 로 들어온다 |
| `p:has(#im)` | (1, 0, 1) | 인자가 ID 면 **A 자리가 올라간다** |
| `p:has(img, #im)` | (1, 0, 1) | 목록 중 **가장 센 `#im`** 으로 치환 |
| `p:has(span, #im, .ic)` | (1, 0, 1) | 순서와 무관하게 가장 센 것 하나 |
| `p:has(.ic, span.sp)` | (0, 1, 2) | 가장 센 인자가 `span.sp` = (0,1,1) |
| `p:has(:is(#im))` | (1, 0, 1) | `:is()` 를 한 겹 더 씌워도 같다 |
| `p:has(+ p#t2)` | (1, 0, 2) | `p` 1 + 인자의 `p` 1 + 인자의 `#t2` |
| `p:has(img):has(span)` | (0, 0, 3) | `:has()` 를 **둘 쓰면 각각 더해진다** |
| `p.c2:has(#im)` | (1, 1, 1) | 바깥의 클래스도 그대로 더해진다 |
| `section:has(#im) p` | (1, 0, 2) | `section` 1 + `#im` + `p` 1 |
| `p:not(:has(#nope))` | (1, 0, 1) | ★ **문서에 없는 ID 도 센다** |
| `p:where(:has(#im))` | (0, 0, 1) | `:where()` 로 감싸면 안의 것이 통째로 0 |

그림 해설:

- **`:has()` 자체는 어느 자리에도 안 보탠다.** `p:has(img)` 가 (0,0,2) 인 것은 `p` 와 `img` 때문이지 `:has` 때문이 아니다.
- **인자에 ID 하나를 편의로 끼워 넣으면 규칙 전체가 A 자리로 올라간다.** `:is()` 에서 나는 사고와 같은 사고다([목록의 **11번 주제**](../11-is-where-not/)).
- **`:has()` 를 둘 겹치면 더해진다** — `p:has(img):has(span)` 은 하나짜리보다 세다. 「가장 센 것 하나」 규칙은 **한 `:has()` 안**에서만 적용된다.
- **세기를 죽이고 싶으면 `:where()` 로 감싼다** — 매칭은 그대로고 기여만 0 이 된다.

비용 — 없다. 다만 **선택자를 읽는 사람이 괄호 안까지 봐야 세기를 알 수 있게 된다.**

### (4) 한계 — 무엇을 던졌고 무엇이 사라졌나

**언제 쓰나** — 「분명히 맞게 썼는데 아무 일도 안 일어난다」일 때. 이 절이 이 주제의 값어치다.

★ **CSS 는 에러가 없는 언어다.** 무효한 선택자를 만나면 브라우저는 **규칙을 통째로 버리고 아무 말도 하지 않는다.**\
그래서 「버려졌나」는 눈으로 알 수 없고 `document.styleSheets[0].cssRules` 에 **담겼는지**를 봐야 안다.

```text
   무효한 선택자를 만났을 때

   CSS 시트                              같은 문자열을 JS 에 주면
   +----------------------------+        +----------------------------+
   | .card:has(:has(p)) { ... } |        | querySelectorAll(같은 것)  |
   |          ↓ 파싱            |        |          ↓                 |
   |   규칙째 조용히 버림       |        |   SyntaxError 를 던진다    |
   |   cssRules.length === 0    |        |   (콘솔에 빨간 줄)         |
   |   경고 없음 · 에러 없음    |        |                            |
   +----------------------------+        +----------------------------+
      -> 화면은 그냥 「안 먹는다」          -> 즉시 알 수 있다
```

던져서 확인한 전수 결과다 (Chrome 151 headless). `cssRules` 는 규칙이 담겼는지, `qSA` 는 같은 문자열을 `querySelectorAll` 에 준 결과다.

| 던진 것 | `cssRules` | `qSA` | 무슨 일이 일어났나 |
|---|---|---|---|
| `.card:has(p)` | 담김 | 1 | 정상 |
| `.card:has(:has(p))` | **버림** | `SyntaxError` | ★ `:has()` 안에 `:has()` — 명세가 금지 |
| `.card:has(:not(:has(p)))` | **버림** | `SyntaxError` | `:not()` 을 끼워도 중첩은 탐지된다 |
| `.card:has(::before)` | **버림** | `SyntaxError` | ★ 의사 요소는 `:has()` 안에 못 온다 |
| `.card:has(p::before)` | **버림** | `SyntaxError` | 조합해 넣어도 마찬가지 |
| `.card::before:has(p)` | **버림** | `SyntaxError` | ★ `:has()` 를 **의사 요소에 붙일 수 없다** |
| `::before:has(p)` | **버림** | `SyntaxError` | 〃 |
| `.card:has()` | **버림** | `SyntaxError` | 빈 인자 |
| `.card:has(> )` | **버림** | `SyntaxError` | 조합자만 남긴 것 |
| `.card:has(p, :bogus-xyz)` | **버림** | `SyntaxError` | ★ **관용적이지 않다** — 목록에 모르는 것 하나가 끼면 전체가 무효 |
| `::slotted(:has(p))` | **버림** | `SyntaxError` | 복합 선택자만 받는 자리라 인자가 무효 |
| `.card:has(:is(:has(p)))` | **담김** | **0** | ★★ 아래를 보라 |
| `.card:has(> p, + div)` | 담김 | — | 상대 선택자 목록은 정상 |
| `.card:has(:hover)` | 담김 | — | 상태 의사 클래스는 넣을 수 있다 |
| `.card:not(:has(p))` | 담김 | 0 | `:not()` **바깥**에 두는 것은 정상 |
| `.card:is(:has(p))` / `.card:where(:has(p))` | 담김 | — | 〃 |
| `.card:has(p) span::before` | 담김 | — | 의사 요소를 **뒤쪽 다른 요소에** 거는 것은 정상 |

★★ **가장 조용한 실패는 「담김 / 0」 줄이다.**

```text
   .card:has(:is(:has(p)))

   cssRules 에 담겼다            ->  「버려졌나」 검사를 통과한다
   selectorText 를 읽어 보면     ->  ".card:has(:is())"
                                          ^^^^^^ 안이 비었다
   :is() 는 관용적(forgiving) 목록이라
   무효한 :has(p) 를 조용히 빼 버리고 빈 :is() 만 남겼다
   빈 :is() 는 아무것도 매치하지 않는다  ->  qSA = 0, 색도 안 바뀜

   에러 0 · 경고 0 · 규칙은 살아 있음 · 그런데 아무 일도 안 일어남
```

- `:is()`·`:where()` 는 명세가 정한 **관용적 선택자 목록**(`<forgiving-selector-list>`)을 받는다 — 목록 안의 못 알아먹는 항목만 버리고 자신은 살아남는다.
- `:has()` 는 **그렇지 않다.** 목록에 무효한 항목이 하나라도 있으면 `:has()` 째 무효가 되고, 규칙이 통째로 버려진다.
- 그래서 **무효한 `:has()` 를 관용적 껍데기 안에 넣으면 규칙은 살고 내용만 증발한다.** 위 표에서 유일하게 `cssRules` 검사로 못 잡히는 줄이다.
- 같은 모양을 `.card:has(:where(:has(p)))` 에서도 확인했다 — `selectorText` 가 `.card:has(:where())` 로 나온다.

비교용으로 관용적 목록이 **정상 동작하는** 예도 같이 확인했다.

| 던진 것 | `selectorText` | `qSA` |
|---|---|---|
| `.card:is(:bogus-xyz, p, .card)` | `.card:is(p, .card)` | 1 |
| `.card:has(:is(p, :bogus-xyz))` | `.card:has(:is(p))` | 1 |

**모르는 항목만 빠지고 나머지는 살아서 매치한다.** 위험한 것은 그 규칙이 아니라, **그 규칙이 `:has()` 의 금지와 겹칠 때**다.

명세가 왜 이렇게 정했는지는 본문에 그대로 적혀 있다 —\
의사 요소는 **조상의 스타일에 따라 조건부로 존재**하므로, `:has()` 로 그것을 질의하면 **순환**이 생긴다. 그래서 `:has-allowed pseudo-element` 로 따로 허용되지 않는 한 의사 요소는 인자로 못 쓴다. (명세는 현재 그런 의사 요소를 **하나도 정의하지 않는다.**)

비용 — 없다. 단, **검사 비용은 개발자가 낸다.** 아래 「어디서 틀리나」의 진단 순서를 쓴다.

### (5) 세 층의 근거 — 무엇으로 무엇을 확인하나

**언제 쓰나** — `:has()` 가 안 먹을 때 원인을 좁힐 때.

```text
   층 1  규칙이 담겼나        document.styleSheets[0].cssRules.length
           ↓ 0 이면 여기서 끝 — 선택자가 무효다
   층 2  무엇이 잡혔나        document.querySelectorAll(sel).length
           ↓ 0 이면 조건이 안 맞는다 (또는 층 1 의 조용한 증발)
   층 3  무엇이 이겼나        getComputedStyle(el).color
           ↓ 기대한 색이 아니면 명시도·캐스케이드 문제 (01·02번)
```

- **층 1 을 건너뛰면** 「선택자가 무효라 안 먹는 것」을 「명시도가 낮아서」로 오진한다.
- **층 2 만 보면** 관용적 껍데기가 내용을 삼킨 경우(위 ★★)를 못 잡는다 — 층 1 도 통과하고 층 2 도 「0」이라 정상처럼 보인다. `selectorText` 를 **눈으로** 읽어야 한다.
- **층 3 이 명시도의 유일한 근거다.** 이 문서의 (A, B, C) 값은 전부 층 3 으로만 확인했다.

## 문법 — 형태와 규칙

CSS 는 문법 표면이 단순하므로 이 절은 「**형태 — 어디서 헷갈리나**」로 읽는다(§2-1 규칙 9).

### 형태

```css
/* 기준 요소:has(조건) */
.card:has(img)        { }   /* 자손에 img 가 있는 카드 */
.card:has(> img)      { }   /* 직계 자식으로 img 가 있는 카드 */
.card:has(+ .card)    { }   /* 뒤에 형제 카드가 있는 카드 */
label:has(input:checked) { }  /* 체크된 입력을 품은 라벨 */
form:has(:invalid)    { }   /* 유효하지 않은 필드를 가진 폼 */
section:not(:has(h1, h2, h3)) { }  /* 제목이 하나도 없는 섹션 */
```

- `:has()` 앞을 비우면 **암묵으로 `*` 가 붙는다** — `:has(#im)` 은 `*:has(#im)` 이고, 조상 전부가 잡힌다(실측에서 명시도 (1,0,0)).
- 인자에 조합자를 안 쓰면 **자손**이 기본이다.
- 인자는 **선택자 목록**이라 쉼표로 여럿 쓸 수 있다. 「하나라도 맞으면 참」(OR)이다.

### 금지 사례 — 던지면 규칙째 사라지는 것

```css
.card:has(:has(p))    { }   /* 중첩 금지 */
.card:has(::before)   { }   /* 의사 요소 금지 */
.card::before:has(p)  { }   /* 의사 요소에 붙이기 금지 */
.card:has()           { }   /* 빈 인자 */
.card:has(p, :bogus)  { }   /* 관용적이지 않다 — 목록 하나가 썩으면 전부 버림 */
```

- 위 다섯 줄은 **전부 에러 없이 사라진다.** 개발자 도구의 Styles 패널에도 안 나타난다.
- 「왜 안 먹지」를 물을 때 **선택자가 존재하는지부터** 확인해야 하는 이유다.

### 순서가 뜻을 바꾼다

```css
section:not(:has(h1, h2, h3))   /* 제목이 하나도 없는 섹션 */
section:has(:not(h1, h2, h3))   /* 제목 아닌 것을 하나라도 가진 섹션 */
```

- 명세가 이 두 줄을 나란히 들어 **뒤집으면 뜻이 달라진다**고 경고한다.
- 뒤엣것은 거의 모든 섹션에 맞는다 — 「제목이 아닌 것」은 어디에나 있다.

## 어디서 틀리나

이 절의 다섯은 전부 **에러 없이 조용히 어긋난다.**

### 1. 조건에 든 것이 잡힐 거라고 생각한다

```css
.card:has(img) { border: 2px solid blue; }
```

**테두리는 이미지가 아니라 카드에 그려진다.**\
「이미지에 테두리를 주려는」 의도였다면 `.card:has(img) img` 라고 한 칸 더 내려가야 한다.\
이것이 `:has()` 의 이름이 「관계」인 이유다 — 관계를 조건으로 쓰되 **선택 대상은 바뀌지 않는다.**

### 2. `:has()` 안의 ID 가 명시도를 올리는 것을 못 본다

```css
.panel:has(#legacy-root) { padding: 8px; }
```

- `#legacy-root` 가 **문서에 없어도** A 자리는 올라간다. 명시도는 **매칭 결과가 아니라 선택자의 모양**만 본다.
- ★ **이 줄 자체는 계산값으로 잴 수 없다** — 측정 방법(`getComputedStyle` 로 승부를 보는 것)이 **매치를 전제**하기 때문이다. 대신 두 행으로 나눠 쟀다.

| 실측한 것 | (A, B, C) | 무엇을 보이나 |
|---|---|---|
| `.panel:has(#im)` | (1, 1, 0) | 존재하는 ID 를 넣었을 때의 모양 |
| `p:not(:has(#nope))` | (1, 0, 1) | ★ **문서에 없는 ID 도 A 를 올린다** — `:not()` 이 뒤집어 줘서 이 줄은 매치되므로 잴 수 있었다 |

- 세기를 안 올리고 싶으면 `:where(:has(#legacy-root))` 로 감싼다. 실측에서 `p:where(:has(#im))` 이 `(0, 0, 1)` 이었다.

### 3. 무효한 선택자를 「안 먹는 스타일」로 오진한다

```text
증상: :has() 를 썼는데 아무 일도 안 일어난다
      ↓
진단 순서
  ① cssRules 에 규칙이 담겼나?      안 담겼으면 선택자가 무효다 (이 문서 (4)절)
  ② selectorText 가 내가 쓴 그대로인가?  :is()/:where() 가 내용을 삼켰을 수 있다
  ③ querySelectorAll 로 몇 개 잡히나?  0 이면 조건이 안 맞는다
  ④ 그래도 안 먹으면 명시도·캐스케이드 문제다 (01·02번)
```

**①을 건너뛰고 ④부터 보는 것이 가장 흔한 시간 낭비다.**

### 4. 관용적 껍데기가 내용을 삼킨 것을 못 본다

```css
.card:has(:is(:has(p))) { color: red; }
```

- 규칙은 **살아 있다.** `cssRules.length` 는 1 이다.
- 그런데 `selectorText` 는 `.card:has(:is())` 이고, 매치되는 요소는 **0 개**다.
- **「규칙이 있나」만 검사하면 통과해 버린다.** 이 한 줄이 이 주제에서 가장 조용한 실패다.

### 5. `:has()` 를 의사 요소에 붙이려 한다

```css
.card::before:has(p) { content: "!"; }   /* 규칙째 사라진다 */
```

- `:has()` 는 의사 요소 **뒤에 올 수 없고**, 의사 요소를 **인자로 받을 수도 없다.**
- 의사 요소를 조건에 따라 바꾸고 싶으면 **기준 요소 쪽에 `:has()` 를 걸고 의사 요소는 그 뒤에** 둔다.

```css
.card:has(img)::before { content: "🖼"; }   /* 이건 된다 */
```

*(Chrome 151 headless 로 `.card:has(p) span::before` 가 `cssRules` 에 담기는 것을 확인했다 — `:has()` 뒤쪽 다른 요소에 의사 요소를 거는 것은 정상이다.)*

## 구현 세부사항 대 언어 보장

| 항목 | 누가 보장하나 | 근거 |
|---|---|---|
| `:has()` 안에 `:has()` 를 못 쓴다 | **명세** | Selectors 4 §4.5 — "The `:has()` pseudo-class cannot be nested" |
| 의사 요소를 인자로 못 쓴다 | **명세** | 같은 절 — `:has-allowed pseudo-element` 로 허용된 것만 가능하고, 이 명세는 그런 것을 하나도 정의하지 않는다 |
| 명시도 = 인자 중 가장 센 것 | **명세** | Selectors 4 의 명시도 규칙 — `:is()`·`:not()` 과 같은 조항 |
| 인자 목록이 관용적이지 않다 | **명세** | `<forgiving-selector-list>` 는 `:is()`·`:where()` **에만** 쓰인다고 명시 |
| 무효하면 **규칙째** 버린다 | **명세** | §3.9 — 선택자 목록의 일부가 무효하면 목록 전체가 무효 |
| `querySelectorAll` 이 `SyntaxError` 를 던진다 | **DOM 명세** | 관찰로도 확인(위 표). CSS 쪽 침묵과 대비된다 |
| `selectorText` 가 `:has(:is())` 로 **직렬화**되는 것 | **관찰** | Chrome 151 에서 본 것이다. 직렬화 형태를 근거로 코드를 짜지 않는다 |
| **성능** | **아무도** | ★ 아래 |

★ **성능은 재지 않았다.**

- 명세 본문에는 `:has()` 의 성능에 대한 요구도, 경고도 **없다.** 「Selectors 는 성능이 중요한 코드에서 쓸 수 있게 설계됐다」는 문서 초록의 일반 문장이 전부다.
- 「`:has()` 는 느리다」는 말이 널리 도는데, **이 문서는 그것을 측정하지 않았다.** 근거 없이 적지 않는다.
- 엔진별 최적화는 구현 세부다. Baseline 이 **widely** 라는 것은 「쓸 수 있다」이지 「빠르다」가 아니다.
- 재려면 무엇을 재야 하는지만 남긴다 — **스타일 재계산 시간**을 DOM 변경마다 측정해야 하고, `:has()` 는 조건이 바뀔 때 **조상 쪽을 다시 계산**해야 하므로 정적 매치 시간만 재면 의미가 없다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 서버가 내려 준 마크업을 못 바꿀 때 | `:has()` | JS 로 부모에 클래스 달기 |
| 「자식이 있는 부모」 스타일 | `.card:has(img)` | 마크업에 `.card--with-image` 추가 |
| 폼 유효성 표시 | `form:has(:invalid)` | 제출 시 JS 로 클래스 토글 |
| 「마지막이 아닌 것」 | `.item:has(+ .item)` | `:not(:last-child)`(같은 결과지만 조건이 다르다) |
| 조건 안에 ID 를 넣어야 할 때 | `:where(:has(#x))` 로 감싸기 | 그냥 `:has(#x)` — A 자리가 올라간다 |
| 의사 요소를 조건에 따라 바꿀 때 | `.card:has(img)::before` | `.card::before:has(img)` — 사라진다 |
| 아주 오래된 환경을 받쳐야 할 때 | `@supports selector(:has(p))` 로 감싸기 | 그냥 쓰기 |

*(Chrome 151 headless 실측: `CSS.supports('selector(:has(p))')` = `true`, `@supports selector(:has(p)) { .card { color: rgb(7,7,7) } }` 가 실제로 적용됐다.)*

판단 규칙 두 줄.

- **`:has()` 는 마크업을 바꾸는 대신 쓰는 것이다.** 클래스를 하나 더 달 수 있는 상황이면 그게 여전히 더 읽기 쉽다.
- **조건 안에 무엇을 넣는지가 세기를 정한다.** 인자는 조건이지 「공짜 괄호」가 아니다.

## 핵심 문장

- `:has()` 가 잡는 것은 **조건에 든 것이 아니라 기준 요소**다 — `.card:has(img)` 는 `img` 가 아니라 `.card` 를 고른다.
- 조건은 **기준 요소에서 출발하는 상대 선택자**다. 조합자를 안 쓰면 자손이 기본이고, `>`·`+`·`~` 로 범위를 좁힌다.
- 명시도는 **`:has()` 자체 0 + 인자 중 가장 센 것**이다(`:is()`·`:not()` 과 같은 조항). 문서에 없는 ID 도 센다. 계산의 정본은 [02번 주제](../02-specificity/2-summary.md).
- 못 쓰는 것 셋 — **`:has()` 안의 `:has()`** · **인자로 쓰는 의사 요소** · **의사 요소에 붙이는 `:has()`**. 셋 다 규칙이 통째로 사라진다.
- 인자 목록은 **관용적이지 않다** — 하나가 썩으면 전부 버려진다. `:is()`·`:where()` 와 정반대다.
- 그래서 가장 조용한 실패는 **관용적 껍데기가 무효한 `:has()` 를 삼킨 것** — 규칙은 살고 `:is()` 만 텅 빈 채 남는다.
- **CSS 는 에러가 없다.** 같은 문자열을 `querySelectorAll` 에 주면 `SyntaxError` 가 난다 — 진단은 거기서 시작한다.

## 용어 풀이

- **`:has()`** — 관계 선택자. 「이런 관계에 있는 요소가 존재하는 요소」를 고른다.
- **기준 요소(anchor element)** — `:has()` 조건을 평가하는 출발점이자 실제로 선택되는 요소. `:has()` 앞에 쓴 것.
- **상대 선택자(relative selector)** — 조합자로 시작할 수 있는 선택자. `> img`·`+ .x`. 조합자가 없으면 자손이 암묵으로 붙는다.
- **`<relative-selector-list>`** — 상대 선택자들의 쉼표 목록. `:has()` 의 인자 형식.
- **관용적 선택자 목록(`<forgiving-selector-list>`)** — 못 알아먹는 항목만 버리고 나머지는 살리는 목록. **`:is()`·`:where()` 에만** 쓰인다.
- **명시도(specificity)** — 선택자의 세기. (A, B, C) 세 자리. 정본은 02번.
- **A 자리 / B 자리 / C 자리** — 각각 ID · 클래스류 · 타입류의 개수. 자리끼리 올림이 없다.
- **`cssRules`** — 시트에 실제로 담긴 규칙 목록. **무효한 선택자의 규칙은 여기 없다.**
- **`selectorText`** — 브라우저가 파싱한 뒤 다시 직렬화한 선택자 문자열. 내가 쓴 것과 다를 수 있다.
- **직렬화(serialization)** — 브라우저 내부의 파싱 결과를 다시 문자열로 되돌리는 것. 원문과 글자가 달라질 수 있다.
- **Baseline** — 주요 브라우저에서 쓸 수 있게 된 정도를 나타내는 지표. `widely` 는 주요 엔진 전부에서 30개월 이상.

## 더 들어가면

- **`:has()` 가 푸는 것은 조합자의 방향 문제만이 아니다.** 「형제 관계로 상태를 전파하는 것」도 같이 풀린다.\
  체크박스 해킹(`input:checked + label`)이 마크업 순서에 묶여 있던 이유가 조합자가 오른쪽으로만 가서였고, `:has()` 는 그 순서 제약을 없앤다.
- **섀도 DOM 안에서는 규칙이 하나 더 있다.** 명세는 섀도 호스트 같은 **featureless 요소**를 `:has(.foo)` 가 매치하지 않는다고 정한다 — `:host:has(.foo)` 라고 써야 한다. 이 문서에서는 **실행 확인하지 않았다**(섀도 DOM 은 이 목록의 다른 자리다).
- **`:has()` 는 `@supports selector()` 로 검사할 수 있다.** 다만 실측에서 `CSS.supports('selector(.card:has(:is(:has(p))))')` 가 **`false`** 였는데 같은 선택자의 규칙은 `cssRules` 에 **담겼다** — 두 검사의 기준이 다르다.\
  `@supports selector()` 는 「이 선택자를 전부 지원하나」를 묻고, 시트 파싱은 「버릴 것만 버리고 살릴 수 있나」를 본다. **기능 검사와 파싱 결과를 같은 것으로 보면 안 된다.**
- **`:has()` 를 `:nth-child(… of S)` 의 `S` 에 넣는 것**은 Chrome 151 에서 담겼다(`li:nth-child(1 of :has(img))`). `of S` 는 복합 선택자만 받는데 `:has()` 자체가 복합 선택자라 어긋나지 않는다. **이 조합의 매치 동작은 확인하지 않았다** — 담겼다는 것만 봤다.
