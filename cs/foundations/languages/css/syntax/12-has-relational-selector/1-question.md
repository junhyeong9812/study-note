> 이 주제의 질문은 **예측형 위주**다 — 「무엇이 잡히나」와 「무효한 것을 던지면 무슨 일이 나나」 둘이 과녁이다.

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

아래 1\~4번은 모두 이 문서를 대상으로 한다.

```html
<div id="root">
  <div class="card" id="c1"><h3>제목</h3><img><p>본문</p></div>
  <div class="card" id="c2"><h3>제목</h3><p>본문</p></div>
  <div class="card" id="c3"><p><img></p></div>
  <div class="card" id="c4"><p>본문</p><span class="x">x</span></div>
</div>
```

### 1. 무엇이 잡히는가 (예측)

```css
.card:has(img) { border: 2px solid blue; }
```

- 파란 테두리가 그려지는 요소는 무엇인가 — `img` 인가 `.card` 인가?
- `querySelectorAll('.card:has(img)')` 는 몇 개를 돌려주는가, 어느 것들인가?
- 「이미지 자체에 테두리를 주고 싶다」면 선택자를 어떻게 고치는가?
- `:has()` 가 조합자의 방향을 왼쪽으로 뒤집는다고 말해도 되는가?

### 2. `>` 를 넣으면 무엇이 달라지는가 (예측)

- `.card:has(> img)` 는 몇 개를 잡는가?
- `.card:has(img)` 와 결과가 갈리는 것은 어느 카드이고, 왜인가?
- `:has()` 안에 조합자를 아예 안 쓰면 무엇이 암묵으로 붙는가?
- `:has(> img)` 와 `:has(img)` 의 명시도는 다른가?

### 3. 형제를 조건으로 쓴다 (예측)

- `.card:has(+ .card)` 는 어느 카드들을 잡는가?
- 「마지막 카드」만 고르고 싶으면 이 선택자를 어떻게 뒤집는가?
- 「**앞쪽** 형제에 이미지가 있는 것」을 고르는 문법은 있는가?
- `:has(~ .card)` 와 `:has(+ .card)` 가 이 문서에서 같은 결과를 내는 이유는 무엇인가?

### 4. 이 규칙의 명시도는 얼마인가 (예측)

```css
p:has(img, #im)       { color: red; }
p:has(img):has(span)  { color: green; }
p:where(:has(#im))    { color: blue; }
```

- 세 선택자의 `(A, B, C)` 를 각각 계산할 수 있는가?
- `:has()` 껍데기 자체는 어느 자리에 얼마를 보태는가?
- 인자를 둘 썼을 때(`img, #im`) 둘 다 더해지는가, 하나만 쓰이는가?
- `:has()` 를 **둘 겹쳐 쓰면**(`:has(img):has(span)`) 왜 결과가 달라지는가?

### 5. 문서에 없는 ID 가 세기를 올린다 (경계)

```css
.panel:has(#legacy-root) { padding: 8px; }
```

- 문서에 `#legacy-root` 라는 요소가 **아예 없을 때** 이 규칙의 명시도는 얼마인가?
- 명시도는 매칭 결과를 보는가, 선택자의 모양을 보는가?
- 세기를 올리지 않고 같은 조건을 쓰려면 어떻게 감싸는가?
- 이 규칙은 `:is()`·`:not()` 과 다른 규칙인가, 같은 규칙인가?

### 6. 던지면 무엇이 사라지는가 (예측)

```css
.card:has(:has(p))   { color: red; }
.card:has(::before)  { color: red; }
.card::before:has(p) { color: red; }
.card:has(p, :bogus) { color: red; }
```

- 네 줄 중 `document.styleSheets[0].cssRules` 에 담기는 것은 몇 줄인가?
- 브라우저는 이때 콘솔에 무엇을 출력하는가?
- 같은 문자열을 `querySelectorAll()` 에 넘기면 무슨 일이 일어나는가?
- 네 번째 줄이 사라지는 것은 `:is(p, :bogus)` 와 무엇이 다르기 때문인가?

### 7. 규칙은 살아 있는데 아무 일도 안 일어난다 (경계)

```css
.card:has(:is(:has(p))) { color: red; }
```

- 이 규칙은 `cssRules` 에 담기는가?
- `selectorText` 를 읽으면 무엇이 나오는가?
- 매치되는 요소는 몇 개인가, 왜 그런가?
- 「규칙이 담겼는지」만 검사하는 진단이 여기서 왜 통과해 버리는가?

### 8. 왜 의사 요소를 금지하는가 (왜)

- 명세가 `:has()` 인자에서 의사 요소를 뺀 이유로 드는 것은 무엇인가?
- 「의사 요소는 조건부로 존재한다」가 무슨 뜻인가?
- `:has()` 를 의사 요소 **뒤에** 붙이는 것은 되는가?
- 「조건에 따라 `::before` 를 바꾸고 싶다」면 어떻게 쓰는가?

### 9. 안 먹을 때 무엇부터 보는가 (경계)

- `:has()` 규칙이 안 먹을 때 확인 순서 네 단계를 말할 수 있는가?
- 「규칙이 담겼나」·「무엇이 잡혔나」·「무엇이 이겼나」는 각각 무엇으로 확인하는가?
- 명시도 주장을 할 때 셋 중 어느 것을 근거로 써야 하는가?
- 이 순서에서 **첫 단계를 건너뛰면** 어떤 오진을 하게 되는가?

### 10. 성능은 어떤가 (경계)

- 이 주제의 3파일은 `:has()` 의 성능을 측정했는가?
- 명세는 `:has()` 의 성능에 대해 무엇을 요구하는가?
- Baseline 이 `widely` 라는 것은 성능에 대해 무엇을 말해 주는가?
- 만약 재려 한다면 **무엇을** 재야 의미가 있는가?

### 11. 다른 주제와 잇기 (연결)

- `:has()` 가 푸는 「08번 주제의 한계」는 정확히 무엇인가?
- `:is()`·`:where()` 의 관용적 목록과 `:has()` 의 인자 목록은 어떻게 다른가?
- `:has()` 안에 `:checked`·`:invalid` 같은 상태 의사 클래스를 넣을 수 있는가?
- 마크업에 클래스를 하나 더 달 수 있는 상황에서도 `:has()` 를 쓰는 것이 나은가?
