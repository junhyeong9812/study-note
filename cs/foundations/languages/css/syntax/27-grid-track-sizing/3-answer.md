# css/syntax/27 — Grid 트랙 정의: `fr`·`minmax()`·`repeat()`·`auto-fill`/`auto-fit` — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **모든 트랙 값은 Google Chrome 151.0.7922.173 headless 에서 실제로 렌더해 `getComputedStyle(el).gridTemplateColumns`(또는 `.gridTemplateRows`)로 읽은 값**이다.\
> 항목의 자리는 같은 판에서 `getBoundingClientRect()` 로 **따로** 쟀다 — 트랙 정의와 항목 배치는 다른 질문이다.\
> 규칙은 [CSS Grid Layout Level 1](https://drafts.csswg.org/css-grid-1/) 과 [CSS Box Sizing Level 3](https://drafts.csswg.org/css-sizing-3/) 으로 접지했다.

## 정답

### 1. `fr` 은 무엇을 나누는가

**계산값** (Chrome 151 headless — 컨테이너 내용 폭 500px)

```text
grid-template-columns: 200px 1fr 1fr   ->  "200px 150px 150px"
grid-template-columns: 100px 1fr 1fr   ->  "100px 200px 200px"
grid-template-columns: 200px 2fr 1fr   ->  "200px 200px 100px"
```

**왜 그런가**

- 엔진은 **고정·내재적 트랙을 먼저 확정**하고 그 합을 컨테이너 폭에서 뺀다. 남은 것이 **자유 공간**이다.
- 500 − 200 = 300 을 1:1 로 나눠 150·150. 500 − 100 = 400 을 1:1 로 나눠 200·200.
- 세 번째는 500 − 200 = 300 을 2:1 로 나눠 200·100 이다.

```text
              |<----------------- 500px ----------------->|
200px 1fr 1fr | [ 200 고정 ][   150   ][   150   ]        |
100px 1fr 1fr | [100][      200      ][      200      ]   |
200px 2fr 1fr | [ 200 고정 ][   200   ][ 100 ]            |
                            ^ 남은 것을 fr 의 비로 나눈다
```

**한 문장으로**

- **`fr` 이 나누는 것은 컨테이너 폭이 아니라 「고정 트랙과 `gap` 을 뺀 나머지」다.**

> **자유 공간(free space)** — 컨테이너에서 고정·내재적 트랙과 `gap` 을 뺀 나머지 공간.\
> 예: 500px 컨테이너에 `200px 1fr 1fr` 이면 자유 공간은 300px 이고, `1fr` 하나는 150px 이 된다.

### 2. 계산값은 선언인가 결과인가

**계산값** (Chrome 151 headless — `gap: 10px`)

```text
width 700px  ->  "132px 132px 132px 132px 132px"   (5칸)
width 500px  ->  "160px 160px 160px"               (3칸)
width 320px  ->  "155px 155px"                     (2칸)
```

**`repeat(...)` 이라는 글자가 나오는가**

- **안 나온다.** `grid-template-columns` 의 계산값은 **사용값**이라 전부 px 로 풀려서 온다.
- 그래서 이 값 하나로 **트랙 수와 트랙 폭을 동시에** 읽을 수 있다. ★ 이것이 이 묶음의 주 도구다.

**개수를 손으로 세는 식**

```text
n × 120 + (n-1) × 10 ≤ 컨테이너 폭      을 만족하는 가장 큰 정수 n

  320px:  n=2 -> 2×120 + 10  = 250 ≤ 320   OK
          n=3 -> 3×120 + 20  = 380 > 320   탈락      -> 2칸  (실측 2칸)
  700px:  n=5 -> 5×120 + 40  = 640 ≤ 700   OK
          n=6 -> 6×120 + 50  = 770 > 700   탈락      -> 5칸  (실측 5칸)
```

- 식은 「최솟값 120px 으로 몇 개가 들어가나」를 센 것이고, **센 다음에** `1fr` 이 남은 것을 다시 나눈다.
- 320px 은 2칸 — **실측값 `155px 155px` 이 그것을 확인해 준다.**

### 3. `1fr` 인데 왜 안 줄어드나

**계산값** (Chrome 151 headless — 컨테이너 내용 폭 300px, 첫 항목이 긴 영문 한 낱말)

```text
1fr 1fr                          ->  "215.031px 84.9688px"     반반이 아니다
minmax(0, 1fr) minmax(0, 1fr)    ->  "150px 150px"             반반
1fr 1fr  + 항목에 overflow:hidden ->  "150px 150px"             반반
```

**150px 씩으로 나뉘는가**

- **아니다.** 첫 트랙이 215.031px 까지 부풀고 둘째가 84.969px 로 눌린다.

**숨은 최솟값**

```text
        1fr   ==   minmax( auto , 1fr )
                           ^^^^
                    grid 항목에서 auto 는 「자동 최소 크기」로 풀리고
                    그 값이 대개 min-content (못 쪼개는 가장 긴 조각) 다

  +----------------------------------+
  | Supercalifragilisticexpialidocious |   <- 공백이 없어 못 쪼갠다
  +----------------------------------+
   이 폭(215.031px) 아래로는 트랙이 안 내려간다
```

**반반으로 만들려면**

- **`minmax(0, 1fr)`** — 최솟값을 0 으로 내려 자동 최소 크기를 무력화한다. 실측 `150px 150px`.

**항목 쪽을 고쳐서**

- 항목에 **`overflow: hidden`**(또는 `auto`·`scroll`) 을 준다. 실측 `150px 150px` 로 같아진다.
- 자동 최소 크기 규칙 자체가 「`overflow` 가 `visible` 일 때만 적용」이기 때문이다.
- ★ **트랙만 반반이 되고 글자는 여전히 넘친다.** 글자를 자르는 것은 `text-overflow` 의 일이지 트랙의 일이 아니다.

**더 좁은 컨테이너에서는 넘쳐 나간다** (같은 내용, 200px 컨테이너)

```text
1fr 1fr           ->  "251.312px 10.5156px"   합 261.8  scrollWidth 262  <- 가로 스크롤
minmax(0,1fr) x2  ->  "100px 100px"           합 200    scrollWidth 251  <- 트랙은 안 넘친다
                                              (clientWidth 는 둘 다 200)
```

**flex 의 어느 속성과 같은 모양인가**

- **`min-width: auto`**(flex 항목의 자동 최소 크기)와 같은 모양이다. 정본은 [목록의 **25번 주제**](../25-flex-shorthand-and-sizing/).
- 두 레이아웃 다 「`auto` 최솟값이 내용 폭에 묶여 있다」는 한 가지 규칙의 두 얼굴이다.

### 4. `auto-fill` 과 `auto-fit`

**계산값** (Chrome 151 headless — `width: 700px`, `gap: 10px`, `minmax(120px, 1fr)`, 항목 2개)

```text
auto-fill  ->  "132px 132px 132px 132px 132px"
auto-fit   ->  "345px 345px 0px 0px 0px"
```

**트랙 수는 다른가**

- **같다. 둘 다 5개를 만든다.** 접힌 트랙도 `0px` 로 계산값에 남아 있다.
- 다른 것은 `auto-fit` 이 그 다음에 **항목 없는 트랙을 `0px` 로 접는다**는 것뿐이다.

**접힌 트랙은 사라지는가**

- **안 사라진다.** 계산값에 `0px` 로 남는다 — 그래서 **화면으로 세면 3개를 놓치고, 계산값으로 세면 안 놓친다.**
- 접힌 트랙에 붙어 있던 `gap` 은 회수된다.\
  *(실측: `auto-fit` 판의 두 항목이 x=2 와 x=357 에 있고 첫 항목 폭이 345 — 둘 사이 간격이 10px 하나뿐이다. `auto-fill` 판은 x=2 와 x=144 로 역시 10px 이지만 오른쪽에 세 칸이 더 남아 있다.)*

```text
auto-fill (700px, 항목 2)                auto-fit (700px, 항목 2)
+-----+-----+-----+-----+-----+          +--------------+--------------+
| [1] | [2] |     |     |     |          |     [1]      |     [2]      |
+-----+-----+-----+-----+-----+          +--------------+--------------+
 132   132   132   132   132              345    10gap    345   0  0  0
```

**항목을 5개로 늘리면**

- **둘의 계산값이 똑같아진다** — 실측 둘 다 `132px 132px 132px 132px 132px`.
- 빈 트랙이 없으면 접을 것이 없기 때문이다. 폭을 320px 로 줄여도 같은 이유로 둘 다 `155px 155px` 이었다.

### 5. 무효한 트랙 정의를 어떻게 잡아내나

**결과** (Chrome 151 headless — 같은 규칙에 `grid-template-columns: 100px` 을 대조군으로 먼저 쓰고 그 아래 검사 대상을 씀)

```text
검사 대상                                      rule.style   계산값        판정
repeat(auto-fill, 1fr)                         ""           100px        무효
repeat(auto-fill, auto)                        ""           100px        무효
repeat(auto-fill, minmax(min-content, 1fr))    ""           100px        무효
repeat(auto-fill, 150px) repeat(auto-fit, 100px) ""         100px        무효
repeat(0, 100px)                               ""           100px        무효
minmax(1fr, 2fr)                               ""           100px        무효
repeat(auto-fill, minmax(150px, auto))         "repeat(…)"  150px ×4     유효
repeat(2, 100px 50px)                          "repeat(…)"  100px 50px 100px 50px  유효
```

**화면에서 알 수 있는가**

- **없다.** 에러도 경고도 없고, 화면에는 「앞서 이긴 값」이 그대로 그려진다.
- CSS 는 에러가 없는 언어라 **버려진 것과 안 먹는 것의 증상이 똑같다.**

**진단 3창**

```text
① document.styleSheets[i].cssRules[j].style.gridTemplateColumns
       -> "" 이면 파싱 단계에서 버려진 것 (CSSOM 에 아예 안 들어갔다)
② querySelectorAll(선택자).length
       -> 0 이면 선택자가 안 잡은 것
③ getComputedStyle(el).gridTemplateColumns
       -> 앞 선언 값이 남아 있으면 내 선언이 무효라 진 것
```

**대조군 기법이 대신해 주는 것**

- **①을 대신한다.** 같은 규칙 안에 유효한 값을 먼저 써 두면, ③만 읽어도 「뒤엣것이 버려졌나」를 알 수 있다.
- ②는 여전히 따로 봐야 한다 — 선택자가 안 잡으면 ③도 앞 선언 값을 돌려주기 때문이다.

**두 `repeat(auto-fill, minmax(...))` 를 가르는 기준**

- **최솟값이 컨테이너 폭을 몰라도 정해지는 값인가.**
- `minmax(150px, auto)` 는 최소 150px 이라 **먼저 셀 수 있다** → 유효.
- `minmax(min-content, 1fr)` 은 최소가 내용에 달려 있어 못 센다 → 무효.

### 6. 암묵 트랙

**계산값** (Chrome 151 headless — `grid-template-columns: 100px 100px`)

```text
grid-template-rows: 50px                 항목 4개  ->  "50px 20px"
  + grid-auto-rows: 80px                 항목 4개  ->  "50px 80px"
  + grid-auto-rows: 80px 30px            항목 6개  ->  "50px 80px 30px"
  + grid-auto-rows: 80px 30px            항목 8개  ->  "50px 80px 30px 80px"
```

**내가 안 쓴 트랙이 들어 있는가**

- **들어 있다.** 선언에는 `50px` 하나뿐인데 계산값에 둘째 행이 붙어 온다.
- ★ **`getComputedStyle` 은 「내가 만든 트랙」과 「엔진이 만든 트랙」을 한 줄에 섞어 돌려준다.**\
  개수를 셀 때 이것을 모르면 「내가 3열을 줬는데 왜 5개지」가 된다.

```text
grid-template-columns: 100px 100px      grid-template-rows: 50px    항목 4개

        열1       열2
 행1  [  1  ]  [  2  ]      <- 명시 행 (50px)
      ─────────────────
 행2  [  3  ]  [  4  ]      <- 암묵 행. grid-auto-rows 가 없으면 auto (실측 20px)
```

**값을 둘 주면**

- 암묵 행이 **80 · 30 을 번갈아** 쓴다. 항목 8개(암묵 행 셋)에서 실측 `50px 80px 30px 80px` — 넷째 행이 다시 80 이다.

### 7. `minmax()` 의 경계

**최대가 최소보다 작으면**

- **최소가 이긴다.** 실측: `minmax(300px, 100px) 1fr` 이 400px 컨테이너에서 `300px 100px`.

**`minmax(0, 1fr)` 과 `1fr` 이 같아지는 경우**

- 항목의 **자동 최소 크기가 트랙 몫보다 작을 때.** 내용이 짧으면 둘의 결과가 한 글자도 다르지 않다.
- 그래서 **개발 중에는 안 드러나고 실제 데이터에서 터진다.** 긴 낱말·URL·번역문이 들어오는 순간이다.

**`minmax(1fr, 2fr)`**

- **무효다.** 실측에서 대조군 `100px` 이 그대로 남았다.
- `fr` 은 **최대 자리에만** 올 수 있다. 최소 자리는 「폭을 몰라도 정해지는 값」이어야 하기 때문이고,\
  이것이 5번의 자동 반복 제약과 **같은 뿌리**다.

**`fit-content(100px)`**

```text
fit-content(x) 는 이렇게 동작한다

   내용이 작다  ->  내용 크기       (x 까지 안 간다)
   내용이 크다  ->  x 에서 멈춘다
   단, min-content 아래로는 안 내려간다
```

- 실측 — 긴 한글 문장에 `fit-content(100px) 1fr` 을 주면 `100px 500px`(600px 컨테이너).
- 실측 — 짧은 「짧다」에 `fit-content(20px) 1fr` 을 주면 `20px 380px`, `fit-content(60px)` 을 주면 `25.7656px …`\
  (그 글자의 `max-content` 가 25.766px 이라 **60px 까지 가지 않는다**).

### 8. `gap` 은 어디에 끼어드나

**계산값** (Chrome 151 headless — 600px 컨테이너)

```text
grid-template-columns: 1fr 1fr;  gap: 20px   ->  "290px 290px"
```

**몇 px 인가**

- **290px 씩.** (600 − 20) ÷ 2 다.

**계산값에 나타나는가**

- **안 나타난다.** `gap` 은 트랙이 아니다. 트랙 수를 셀 때 헷갈리면 안 된다.

**계산 순서**

```text
컨테이너 내용 폭
     │
     ├─ ① gap 을 뗀다            (트랙 수 − 1) × gap
     │
     ├─ ② 고정·내재적 트랙을 뗀다  200px, max-content, …
     │
     └─ ③ 남은 것 = 자유 공간  ->  fr 의 비로 나눈다
```

- `gap` 이 **먼저** 빠진다. 그래서 `gap` 을 키우면 `fr` 트랙이 그만큼 줄어든다.

**접힌 트랙의 `gap`**

- **회수된다.** 실측 `auto-fit` 판(700px, 항목 2)에서 항목이 x=2 와 x=357 이고 첫 폭이 345 —\
  둘 사이 간격이 10px **하나**뿐이다. 접힌 세 트랙에 붙었을 `gap` 세 개가 사라졌다는 뜻이다.

### 9. 내재적 크기 키워드가 트랙 값으로 올 때

**계산값** (Chrome 151 headless — 500px 컨테이너, `gap: 4px`, 항목은 「짧다」·「아주 아주 아주 긴 제목이다」·「C」)

```text
min-content max-content 1fr   ->  "12.8906px 157.359px 321.75px"   (행 높이 40px = 두 줄)
max-content max-content 1fr   ->  "25.7656px 157.359px 308.875px"  (행 높이 20px = 한 줄)
```

**무엇이 다른가**

```text
min-content                    max-content
+-----+                        +-----------+
|짧   |   줄바꿈을 최대한 해서   |  짧다     |   줄바꿈 없이 필요한 폭
|다   |   얻는 가장 좁은 폭      +-----------+
+-----+                          25.766px
12.891px
```

- 한글은 글자 사이에서 줄바꿈이 되므로 `min-content` 가 **한 글자 폭**이 된다.
- 그래서 같은 글자인데 트랙 폭이 12.891 대 25.766 으로 **정확히 두 배 가까이** 갈린다.

**`auto` 트랙은**

- **둘 중 어느 쪽과도 같지 않다.** `auto` 는 최소가 자동 최소 크기, 최대가 `max-content` 인데,\
  **남는 공간이 있으면 `stretch` 로 늘어날 수 있다.** `max-content` 트랙은 안 늘어난다.
- 이 차이는 3번의 `1fr` = `minmax(auto, 1fr)` 과 같은 자리를 건드린다.

**상한을 두고 싶다면**

- **`fit-content(<길이>)`** 를 쓴다. 7번의 실측 참고.

**정의 자체의 정본**

- [목록의 **31번 주제**](../31-intrinsic-sizing-and-aspect-ratio/)(내재적 크기). 이 문서는 **트랙 값으로 쓰일 때의 성질**까지만 다룬다.

### 10. 왜 자동 반복에는 `fr` 을 못 쓰는가

**두 단계**

```text
① 몇 개 들어가나 센다      n × <칸 최소 크기> + (n-1) × gap ≤ 컨테이너 폭
        ↓  n 이 정해진다
② 그 n 개 트랙의 크기를 푼다   여기서야 fr 이 남은 공간을 나눈다
```

**왜 성립하지 않는가**

- ①은 **트랙 크기를 이미 알아야** 돌아간다. `fr`·`auto`·`min-content` 는 **②에서야 정해지는 값**이다.
- 「`fr` 로 몇 개가 들어가나」는 **순환 정의**라 답이 없다 — 그래서 명세가 문법 단계에서 막는다.

**`minmax(150px, auto)` 는 왜 되나**

- ①이 쓰는 것은 **최솟값**이다. 150px 이라는 고정 최솟값으로 개수를 세고, ②에서 `auto` 로 늘린다.
- 실측 `repeat(auto-fill, minmax(150px, auto))` → `150px 150px 150px 150px`(600px 컨테이너).

**컨테이너 폭이 확정되지 않으면**

- **반복 횟수는 1이다.** 실측 — `width: max-content` 인 컨테이너에서\
  `repeat(auto-fill, 150px)` → `150px` 한 칸, `repeat(auto-fill, minmax(120px, 1fr))` → `120px` 한 칸.
- 「몇 개 들어가나」를 물을 상대(폭)가 없기 때문이다.

### 11. 다른 주제와 잇기

**항목을 놓는 규칙**

- 목록의 [**28번 주제**](../28-grid-placement/)(라인 번호·`span`·자동 배치). 이름으로 놓는 것은 [**29번**](../29-grid-template-areas/)이다.

**`justify-self` 가 Grid 에만 있는 이유**

- flex 의 주축 자유 공간은 **아이템들이 나눠 갖는 하나의 자원**이라, 한 아이템만 「끝으로」라고 하면 나머지 배치가 정의되지 않는다.
- Grid 는 **트랙이 미리 나뉘어 있어** 자유 공간이 **칸마다 따로** 있다. 그래서 칸 안에서 개별 예외가 성립한다.
- *(실측 — 같은 선언 `justify-self: end` 를 준 항목: grid 컨테이너에서는 x 가 261.7 로 칸 오른쪽 끝에 붙고 폭이 내용 크기로 줄었다. flex 컨테이너에서는 계산값이 `end` 로 남는데도 x 가 9.69 로 **전혀 안 움직였다**.)*
- 정렬 어휘 전반의 정본은 [목록의 **24번 주제**](../24-flexbox-axes/)다.

**카드 내부 줄을 카드끼리 맞추려면**

- **`subgrid`** — 목록의 [**30번 주제**](../30-subgrid/). 중첩 grid 로는 안 되는 이유도 거기 있다.

**`gap` 의 정본**

- [목록의 **26번 주제**](../26-flex-wrap-gap-order/)(flex 줄바꿈·`gap`·`order`)다. 이 주제는 **`gap` 이 `fr` 계산에 끼어드는 자리**와\
  **`auto-fit` 이 접은 트랙의 `gap` 이 회수된다**는 Grid 고유의 자리까지만 다룬다.

### 12. 계산값을 믿어도 되는가

**「`fr` 이 남은 공간을 나눈다」**

- **명세가 보장한다.** CSS Grid Level 1 의 트랙 크기 결정 알고리즘에 「자유 공간을 `fr` 의 합으로 나눈다」가 있다.

**「계산값에 암묵 트랙이 섞여 온다」**

- **관찰이다.** CSSOM 이 이 속성의 resolved value 를 사용값으로 정하고는 있지만,\
  **문자열이 어떤 모양으로 직렬화되는지**(암묵 트랙을 함께 싣는가, 접힌 트랙을 `0px` 로 남기는가, 라인 이름을 대괄호로 싣는가)는 Chrome 151 에서 본 것이다.

**다시 찍어야 하는 칸**

| 칸 | 성격 |
|---|---|
| 계산값의 **직렬화 형태** (암묵 트랙 포함 여부·`0px` 표기·`[이름]` 표기) | 구현 관찰 — 버전이 오르면 다시 찍는다 |
| `fr` 배분·`auto-fill` 개수 세는 식·`minmax` 최소 우선 | 명세 보장 — 안 흔들린다 |
| `12.8906px` 같은 **개별 px 값** | 폰트·창 크기에 딸린 값 — 재현되는 것은 숫자가 아니다 |

**재현되는 것**

- **성질이다.** 「한글 `min-content` 는 한 글자 폭이 된다」·「`max-content` 는 그 두 배 가까이 된다」가 재현되고,\
  `12.8906`·`25.7656` 이라는 숫자 자체는 이 머신의 폰트에 딸린 값이다.

## 용어 풀이

- **트랙(track)** — 격자의 행 하나 또는 열 하나.
- **격자 라인(grid line)** — 트랙 사이의 경계. 번호와 이름을 갖는다(28·29번).
- **`fr`** — 남은 공간의 몫. 비율이 아니다.
- **자유 공간(free space)** — 컨테이너 폭에서 `gap` 과 고정·내재적 트랙을 뺀 나머지.
- **`minmax(a, b)`** — 최소 `a`, 최대 `b`. `b < a` 면 `a` 가 이긴다. `fr` 은 `b` 자리에만 온다.
- **`auto-fill` / `auto-fit`** — 들어가는 만큼 트랙을 만든다. 뒤엣것만 **빈 트랙을 `0px` 로 접는다.**
- **명시 격자 / 암묵 격자** — 내가 정의한 트랙 / 엔진이 자동으로 만든 트랙.
- **자동 최소 크기(automatic minimum size)** — `auto` 최솟값이 실제로 풀리는 값. `overflow` 가 `visible` 일 때만 `min-content` 가 되고, 아니면 0 이다.
- **`min-content` / `max-content`** — 줄바꿈을 최대한 한 폭 / 줄바꿈 없는 폭. 정본은 31번.
- **`fit-content(x)`** — 내용만큼이되 `x` 에서 멈춘다.
- **계산값(resolved value)** — `getComputedStyle` 이 돌려주는 값. 이 속성에서는 **px 로 푼 사용값**이다.
- **진단 3창** — `cssRules`(담겼나) → `querySelectorAll`(잡혔나) → `getComputedStyle`(이겼나). CSS 에 에러가 없어 증상이 같기 때문에 필요하다.

**구현 의존 항목** — **계산값의 직렬화 형태**(암묵 트랙을 함께 싣는가 · 접힌 트랙을 `0px` 로 남기는가 · 라인 이름을 `[이름]` 으로 싣는가)는 Chrome 151 에서 관찰한 것이다. 버전이 오르면 이 칸을 다시 찍는다.\
**개별 px 값**은 이 머신의 폰트·창 크기에 딸린 값이다 — 재현되는 것은 숫자가 아니라 성질이다.\
