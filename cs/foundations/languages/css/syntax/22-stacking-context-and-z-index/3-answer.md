# css/syntax/22 — 쌓임 맥락과 `z-index` — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> ★★ **이 파일의 모든 판정은 Google Chrome 151.0.7922.173 headless 스크린샷의 픽셀 RGB 다.**
> 「누가 위에 있나」는 좌표로 안 나오므로 **겹치는 지점의 색을 읽어** 정했다. 겹침 좌표는 JS 로 뽑아 그대로 썼다.\
> **손으로 계산해 유도한 수치는 없다.** 규칙은 [CSS Positioned Layout Level 3](https://drafts.csswg.org/css-position-3/) 의 페인트 순서 절로 접지했다.

## 정답

### 1. 9999 가 지는 판

**실행 결과** (Chrome 151 headless — 겹치는 지점의 RGB. 빨강 `#ff0000`, 파랑 `#0000ff`)

```text
A 의 선언            겹침 픽셀        위에 있는 것
(아무것도 없음)      (255, 0, 0)      빨강 — 9999 가 통했다
position: relative   (255, 0, 0)      빨강 — 아직 담장이 없다
z-index: 1           (0, 0, 255)      파랑 — 담장이 생겼다
```

**①의 색**

- **빨강.** `A` 가 쌓임 맥락을 안 만들었으므로 빨강의 9999 가 **루트 리그에서** 파랑의 2 와 직접 겨뤘다.

**②의 색**

- **파랑.** `A` 가 담장을 세웠으므로 루트 리그에서는 **`A`(1) 대 `B`(2)** 만 겨룬다. `B` 가 이기고, 빨강의 9999 는 **`A` 안에서만** 유효하다.

**`getBoundingClientRect()` 는 다른가**

- ★ **완전히 같다.** 좌표로는 아무것도 안 갈린다. 이 주제를 좌표로 디버깅할 수 없는 이유다.

**빨강을 위로 올리는 방법 둘**

- **(a) `A` 의 `z-index` 를 `B` 보다 크게** — `z-index: 3` 으로 바꾸니 **(239,68,68) 빨강**으로 돌아왔다(실측).
- **(b) 빨강을 `A` 밖으로 옮긴다** — 담장 밖이면 다시 루트 리그에서 겨룬다. 모달 라이브러리가 쓰는 방법이다.
- (자식의 9999 를 99999 로 키우는 것은 **답이 아니다.**)

### 2. `opacity` 가 자식을 가둔다

**실행 결과** (Chrome 151 headless)

```text
A 의 선언          겹침 픽셀        쌓임 맥락
opacity: 0.99      (0, 0, 255)      ✓ 생긴다
opacity: 0.999     (0, 0, 255)      ✓ 생긴다
opacity: 1         (255, 0, 0)      ✗ 안 생긴다
```

**`opacity: 0.99`**

- **파랑.** 자식이 갇혔다.

**`opacity: 1`**

- **빨강.** 담장이 없다.

**`0.999` 와 경계**

- **`0.999` 도 생긴다.** 경계는 「**1 미만이냐**」다 — 값의 크기가 아니라 **1 이 아니냐**가 기준이다.

**눈으로 알아챌 수 있는가**

- ★★ **없다.** `0.99` 는 화면상 1% 흐려질 뿐이라 **육안으로는 `1` 과 구분되지 않는다.**
- 그런데 겹침 순서는 **완전히 뒤집힌다.** 이 주제에서 가장 당황스러운 자리이고, **애니메이션 중간 프레임의 `opacity`** 가 같은 사고를 낸다.

### 3. 목록을 속성 이름으로 외우면

**실행 결과** (Chrome 151 headless)

```text
선언                          겹침 픽셀        쌓임 맥락
mix-blend-mode: normal        (255, 0, 0)      ✗
mix-blend-mode: multiply      (0, 0, 255)      ✓
position: sticky (z 없음)     (0, 0, 255)      ✓
position: relative (z 없음)   (255, 0, 0)      ✗
```

**`mix-blend-mode: normal`**

- **안 만든다.** 「`mix-blend-mode` 가 있으면 만든다」로 외우면 여기서 깨진다.

**`mix-blend-mode: multiply`**

- **만든다.** **`normal` 이 아닌 값**이어야 한다.

**`sticky` 와 `relative`**

- **`sticky` 는 `z-index` 없이도 만든다**(실측 파랑). **`relative` 는 안 만든다**(실측 빨강).
- 둘을 「위치 지정」 한 덩어리로 묶으면 놓치는 자리다.

**무엇으로 외워야 하는가**

- 「**그 선언이 안쪽을 한 장으로 먼저 합성해야 하는가**」다.
- `opacity < 1` 은 **합쳐 놓고 흐려야** 하고, 혼합 모드는 **합쳐 놓고 섞어야** 하며, `transform`·`filter` 는 **합쳐 놓고 변형·필터**해야 한다. `normal`·`1` 은 합칠 이유가 없다.
- [17번](../17-block-formatting-context/2-summary.md)의 BFC 목록이 잡다한 것과 **같은 성질**이다 — 담장은 목적이 아니라 **부작용**이다.

### 4. `position` 없이 `z-index` 가 먹는 경우

**실행 결과** (Chrome 151 headless)

```text
항목                              겹침 픽셀        쌓임 맥락
flex 항목 + z-index: 0            (0, 0, 255)      ✓
flex 항목 + z-index: 1            (0, 0, 255)      ✓
grid 항목 + z-index: 0            (0, 0, 255)      ✓
flex 항목 + z-index: auto         (255, 0, 0)      ✗
보통 블록(static) + z-index: 0    (255, 0, 0)      ✗
```

**flex 항목의 `z-index: 0`**

- **먹는다.** `position` 이 없어도 flex 항목에는 `z-index` 가 적용되고 쌓임 맥락까지 만든다.

**보통 블록에 주면**

- **아무 일도 안 일어난다.** `position: static` 이면 `z-index` 가 통째로 무시된다 — **에러도 경고도 없다.**

**flex 항목 + `z-index: auto`**

- **안 생긴다.** 값이 `auto` 면 그냥 기본 상태다.

**grid 항목도 같은가**

- **같다**(실측 파랑). flex·grid 항목은 이 점에서 똑같이 다뤄진다.

### 5. 페인트 순서 일곱 층

**실행 결과** (Chrome 151 headless — 이웃한 두 층을 겹쳐 놓고 겹침 픽셀을 여섯 번 읽었다)

```text
대결                          아래층      위층        겹침 픽셀        이긴 것
① 맥락 배경 대 ② 음수 z       회 128       보라        (128,  0,128)    ② 음수 z
② 음수 z    대 ③ 블록         보라         초록        (  0,128,  0)    ③ 블록
③ 블록      대 ④ float        초록         주황        (255,128,  0)    ④ float
④ float     대 ⑤ 인라인       주황         하늘        (  0,255,255)    ⑤ 인라인
⑤ 인라인    대 ⑥ z:auto       하늘         자홍        (255,  0,255)    ⑥ z:auto
⑥ z:auto    대 ⑦ z:1          자홍         빨강        (255,  0,  0)    ⑦ z:1
```

**float 대 보통 블록의 배경**

- **float 이 위**다(실측 주황). float 은 ④층, 블록 배경은 ③층이다.

**float 대 글자**

- **글자가 위**다(실측 하늘). 인라인 내용은 ⑤층이다.

**`position: relative` 만 준 요소 대 float**

- **위치 지정 요소가 위**다. `z-index` 를 안 줘도 ⑥층이기 때문이다.
- 별도 확인 — 초록 블록에 `position: relative` 를 추가하니 겹침이 **(22,163,74) 초록**으로 뒤집혔다(그 전에는 주황이 이겼다).

**일곱 층(아래부터)**

1. 이 맥락을 연 상자 자신의 배경·테두리
2. `z-index` 음수인 위치 지정 자손
3. 보통 흐름의 블록 상자 배경·테두리
4. float 된 상자
5. 인라인 내용(글자·인라인 상자의 배경)
6. `z-index` 가 `auto`/`0` 인 위치 지정 자손
7. `z-index` 양수인 위치 지정 자손

### 6. `z-index: -1` 로 뒤로 보냈는데

**실행 결과** (Chrome 151 headless — `.wrap` 회색 `#e5e7eb`, `.card` 노랑 `#fef08a`, `.deco` 보라 `#7c3aed`)

```text
지점                          `.wrap` z-index: 0      `.wrap` z-index: auto
보라 ∩ 노란 카드              (254,240,138) 노랑      (254,240,138) 노랑
보라만 (회색 바탕 위)          (124, 58,237) 보라      (229,231,235) 회색 ← 아예 안 보인다
`.deco` 의 z-index 를 지우면   (124, 58,237) 보라      —
```

**노란 카드와 겹치는 지점**

- **노랑.** ②층(음수 z)은 **③층(블록 배경) 아래**라 카드 배경에 가린다.

**회색 배경 위에만 있는 지점**

- **보라.** ②층은 **①층(맥락 루트 자신의 배경) 위**라 회색은 못 가린다.
- ★ **같은 하나의 상자가 회색은 뚫고 노랑은 못 뚫는다.** 이것이 ①②③층의 순서를 한 그림에서 보여 준다.

**`.wrap` 의 `z-index: 0` 을 지우면**

- **보라가 아예 안 보인다**(실측 회색). `.wrap` 이 더 이상 맥락 루트가 아니므로 보라는 **더 위 조상의 맥락**에서 음수층에 놓이고, 거기서는 **`.wrap` 의 회색 배경이 ③층**이라 보라를 덮는다.

**관용구가 동작하는 조건**

- **뒤로 보낼 상자의 조상 중 하나가 쌓임 맥락이어야 하고, 가리고 싶지 않은 배경이 그 맥락 루트 자신의 배경이어야 한다.**
- 실무 형태 — 래퍼에 `position: relative; z-index: 0` 을 주고 그 안에서 `z-index: -1` 을 쓴다.

### 7. 세 구역을 가르기

**실행 결과** — 세 열의 근거가 서로 다르다. BFC 는 [17번](../17-block-formatting-context/2-summary.md)의 마진·float 실측, 포함 블록은 [21번](../21-position-and-containing-block/2-summary.md)의 `fixed` 좌표, 쌓임 맥락은 이 문서의 겹침 픽셀이다.

```text
선언                BFC(17번)   포함 블록(21번)   쌓임 맥락(여기)
overflow: hidden       ✓             ✗                ✗
overflow: clip         ✗             ✗                ✗
display: flow-root     ✓             ✗                ✗
opacity: 0.99          ✗             ✗                ✓
isolation: isolate     ✗ (미측정)     ✗                ✓
transform              ✗             ✓                ✓
filter                 ✗             ✓                ✓
contain: layout        ✓             ✓                ✓
position: absolute     ✓             ✗                ✗ (z-index 없을 때)

  (세 열 전부 실측이다. BFC 열은 17번의 마진·float 실험,
   포함 블록 열은 이 배치의 fixed 좌표 실험, 쌓임 맥락 열은 겹침 픽셀이다.
   「미측정」이라고 적은 칸만 안 재 봤다.)
```

**`overflow: hidden`**

- **BFC 는 만들고 쌓임 맥락은 안 만든다**(실측 겹침 픽셀 **(255,0,0) 빨강**). 포함 블록도 안 바꾼다(실측 — `fixed` 자식이 **(0,0)**).

**`opacity: 0.99`**

- **쌓임 맥락만 만든다.** BFC 도 아니고 포함 블록도 안 바꾼다(실측 — `fixed` 자식이 **(0,0)** 에 그대로).

**`transform`**

- **포함 블록과 쌓임 맥락 둘 다** 만들고 **BFC 는 아니다.**
- ★ **`contain: layout` 은 셋 다 한다** — 실측에서 BFC(17번 표) · `fixed` 자식이 **(32,32)** · 겹침 픽셀 파랑이었다. **세 구역을 한 번에 만드는 드문 선언**이다.

**같은 원인으로 진단해도 되는가**

- ★ **안 된다.** `transform` 자리에서는 원인이 같지만 **`opacity` 자리에서 갈린다.**
- 세 구역은 **다른 것**이고, 세 목록을 한 덩어리로 외우는 것이 이 사슬에서 가장 흔한 오진이다.

### 8. 실무에서 고치는 법

**숫자를 올리는 것이 왜 소용없나**

- **담장 밖에서는 부모 덩어리 하나로만 보이기 때문이다.** 자식끼리의 숫자는 담장 안에서만 뜻이 있다.
- 실측 1번 ②에서 **9999 가 2 에게 졌다.**

**모달을 `<body>` 밑에 붙이는 이유**

- 어떤 조상이 담장을 세웠는지 **미리 알 수 없기 때문**이다. 앱 어딘가의 `opacity` 애니메이션 하나로도 갇힌다.
- **담장 밖으로 나가는 것이 유일하게 확실한 방법**이다.

**`isolation: isolate`**

- **일부러 담장을 세우는 선언**이다. 위젯 안의 `z-index` 싸움이 밖으로 새지 않게 한다.
- ★ **투명도·색을 안 건드린다.** `opacity: 0.99` 로 같은 효과를 내던 옛 꼼수를 **부작용 없이** 대체한다(실측 — `isolation: isolate` 도 겹침 픽셀이 **(0,0,255)**).

**`will-change` 를 성능 옵션으로만 보면**

- **담장과 포함 블록이 딸려 오는 것**을 놓친다.
- 실측 — `will-change: opacity` 가 쌓임 맥락을 만들었고([21번](../21-position-and-containing-block/2-summary.md)) `will-change: transform` 은 `fixed` 자식의 벽까지 바꿨다.

### 9. 이 주제를 어떻게 재는가

**`getBoundingClientRect()` 로 알 수 있는가**

- ★ **없다.** 담장이 있든 없든 **좌표가 완전히 같다**(실측).
- 「누가 위인가」는 **레이아웃이 아니라 페인트**이기 때문이다. [17번](../17-block-formatting-context/2-summary.md)의 「잘렸나는 rect 로 못 잰다」와 같은 성질이다.

**무엇으로 재는가**

- **스크린샷을 찍어 겹치는 지점의 RGB 를 읽는다.** 이 문서의 모든 ✓/✗ 가 그 값이다.

**순색을 쓰는 이유**

- `#ef4444` 를 쓰면 픽셀이 **(239,68,68)** 로 나와 매번 대조표가 필요하다. **`#ff0000`·`#0000ff` 를 쓰면 (255,0,0)·(0,0,255)** 라 눈으로 바로 갈린다.
- 반투명이 섞이면 더 복잡해진다 — 예를 들어 빨강이 `opacity: 0.99` 로 파랑 위에 있으면 **순수 빨강이 아닌 값**이 나오므로, 그 자체가 「위에 있다」의 증거가 되기도 한다.

**여러 무대를 한 문서에 넣을 때**

- ★ **좌표가 밀린다.** 실측 중 실제로 **한 번 틀린 판정**이 나왔다 — 같은 문서 안의 다른 무대에 있던 `position: fixed` 요소가 **페이지 높이를 바꿔** 스크린샷 좌표가 어긋난 것이다.
- **무대를 하나씩 떼어 다시 재니** 정상이었다.
- 그래서 **겹침 좌표를 JS 로 뽑아(`getBoundingClientRect()` 로 계산) 그 값을 그대로 픽셀 읽기에 넘기는 것**까지가 한 실험이다. 좌표를 손으로 세면 안 된다.

### 10. 다른 주제로 잇기

**float 이 블록 배경 위에 그려지는 것**

- **③층(블록 배경) 대 ④층(float)** 이다. float 이 위다(실측 주황).
- 정본은 [20번 주제](../20-float-and-clear/2-summary.md)이고, 거기서 「배경이 float 밑으로 깔려 겹쳐 보인다」의 정확한 이유가 이 층 순서다.

**드롭다운이 사라지는 문제**

- **이 주제가 아니다.** 사라지는 것은 **잘림**이고 [23번 주제](../23-overflow-and-scroll-containers/2-summary.md)(오버플로)다.
- 갈라 보는 법 — **일부만 잘려 있으면 `overflow`**, **통째로 다른 것 밑에 깔려 있으면 `z-index`** 다.

**두 목록의 대조표**

- [21번 주제](../21-position-and-containing-block/2-summary.md)(`position` 과 포함 블록)의 (5)절에 있다.

**`mix-blend-mode` 의 혼합 규칙**

- [목록의 **48번 주제**](../48-blend-modes-and-isolation/)(혼합 모드와 `isolation`)다. 여기서는 **담장을 세우느냐**만 봤다.

## 용어 풀이

- **쌓임 맥락(stacking context)** — 그 안의 요소들끼리만 `z-index` 로 겨루는 독립 구역. **구역 전체가 한 덩어리로** 부모 구역에 끼어든다.
- **루트 쌓임 맥락** — `<html>` 이 만드는 최상위 맥락.
- **`z-index`** — 같은 맥락 안의 앞뒤 순서. `position: static` 에서는 무시된다(flex/grid 항목은 예외).
- **페인트 순서(painting order)** — 한 맥락 안에서 무엇을 먼저 그리는지의 차례. 일곱 층.
- **`isolation: isolate`** — 일부러 담장을 세우는 선언. **투명도를 안 건드린다.**
- **`mix-blend-mode`** — 아래와 색을 섞는 방식. **`normal` 이 아닌 값**일 때만 담장을 세운다.
- **`will-change`** — 「이 속성이 곧 바뀐다」는 힌트. **담장과 포함 블록이 딸려 온다.**
- **합성(compositing)** — 여러 층을 한 장으로 합치는 단계. 담장이 생기는 이유가 여기 있다.
- **겹침 픽셀 판정** — 겹치는 지점의 RGB 를 읽어 누가 위인지 정하는 방법. **이 주제의 유일한 측정 수단.**

## 실행 검증

| 무엇을 | 어떻게 | 결과 |
|---|---|---|
| `z-index` 가 맥락 안에서만 비교됨 | Chrome 151 headless · 겹침 픽셀 | 담장 없음 **(255,0,0)** / `z-index:1` **(0,0,255)** |
| 같은 두 경우의 좌표 | `getBoundingClientRect()` | **완전히 동일** — 좌표로는 안 갈린다 |
| `opacity` 경계 | `0.99` / `0.999` / `1` | **파랑 / 파랑 / 빨강** |
| 쌓임 맥락 목록 15가지 | 래퍼 선언을 바꿔 가며 겹침 픽셀 | 표 (2) 절 — `mix-blend-mode: normal` 과 `opacity: 1` 만 예외적으로 ✗ |
| flex/grid 항목 | `z-index: 0` / `auto`, grid 도 같이 | **0 은 ✓ · auto 는 ✗ · grid 도 같음** |
| 페인트 순서 일곱 층 | 이웃한 두 층을 겹쳐 6판 | 여섯 판 전부 위층 색 — 층 순서 확인 |
| 층 승격 | 초록 블록에 `position: relative` 추가 | 주황(float)이 이기던 겹침이 **(22,163,74) 초록**으로 뒤집힘 |
| `z-index: -1` 의 자리 | 맥락 배경 / 블록 배경과 각각 겹쳐 | 회색 위 **보라** · 노랑 위 **노랑** |
| 담장 제거의 효과 | `.wrap` 의 `z-index: 0` 제거 | 보라가 **아예 안 보임**(회색) |
| 잘못된 판정 1건 | 여러 무대를 한 문서에 넣고 측정 | **`fixed` 요소가 페이지 높이를 바꿔 좌표가 밀림** → 무대를 떼어 재측정 |
| demo 4개 | 완성 문서에서 `extract-demo-blocks.py --render` 재추출 + 스크린샷 픽셀 | 「보이는 것」 4건과 결과를 단언한 「바꿔 볼 것」 6건 모두 일치 |

**구현 의존 항목** — ★ **「무엇이 쌓임 맥락을 만드나」의 목록은 계속 늘어 왔다.** `will-change`·`contain`·`backdrop-filter`·`isolation` 은 나중에 들어온 것이라 오래된 글의 목록과 다르다. 이 표는 **이 브라우저에서 픽셀을 읽어 만든 것**이고, 브라우저가 바뀌면 다시 찍어야 한다.\
★ **판정 방법 자체가 관찰이다.** 「빨강이 보인다」는 관찰이고 「그러므로 담장이 없다」는 그 관찰에서의 추론이다 — 다만 **좌표로는 갈릴 수 없으므로 다른 방법이 없다.**\
**엔진은 Chrome 하나다.** Firefox 155.0.1 은 이 환경에서 headless 스크린샷이 산출되지 않고 WebKit 은 이 머신에 없다 — **「두 엔진에서 확인했다」고 적지 않았다.**
