# css/syntax/33 — 길이 단위: `px`·`em`·`rem`·`%`·`ch`·`ex` — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Values and Units Level 4](https://drafts.csswg.org/css-values-4/) 의 「Distance Units」(`<length>`)·「Percentages」 절. 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 모든 픽셀 값은 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워 `getComputedStyle`·`getBoundingClientRect()` 로 읽은 것이다. **손으로 계산해 유도한 수치는 없다.** 하네스는 [3-answer.md](3-answer.md) 의 `## 실행 검증` 절에 있다.\
> **엔진은 Chrome 하나다** — Firefox 155.0.1 은 이 환경에서 headless 산출이 조용히 실패하고 WebKit 은 이 머신에 없다. 「두 엔진에서 확인했다」고 적지 않는다.
> **버전** — CSS 에는 언어 버전이 없다. `px`·`em`·`%` 는 CSS1 부터, `rem` 은 CSS Values 3, `lh`/`rlh` 는 Values 4 의 것이다. 지원 상태는 [목록 README](../README.md) 의 Baseline 표로 읽는다.
> **여기서 다루지 않는 것** — 단위가 **어느 단계에서 픽셀이 되는가**는 [04번](../04-value-processing-stages/2-summary.md)이 정본이다. 여기는 **그 단계에 들어가기 전에 무엇을 기준으로 재는가**까지다. 뷰포트·컨테이너 기준은 [34번](../34-viewport-and-container-units/2-summary.md), 단위를 섞어 계산하는 것은 [35번](../35-calc-clamp-min-max/2-summary.md)이 정본이다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 수치는 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**길이 단위 = 「자를 어디에 대고 재느냐」다.** 숫자가 아니라 **기준점**이 단위의 정체다.

목수의 자에 비유한다. 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 눈금이 박힌 쇠자 | **절대 단위** — `px`·`in`·`cm`. 주변이 뭐든 길이가 같다 |
| 「내 손 두 뼘」 | **`em`** — 내 글자 크기의 배수. 재는 사람이 바뀌면 길이가 바뀐다 |
| 「현관 기둥 두 뼘」 | **`rem`** — 집에 하나뿐인 기준(루트 글꼴)의 배수 |
| 「이 방 폭의 절반」 | **`%`** — 부모의 어떤 치수의 비율. **어느 치수인지는 속성이 정한다** |
| 「이 글꼴의 0 자 열 개 폭」 | **`ch`** — 글꼴이 바뀌면 길이가 바뀐다 |

```text
  같은 글자 "2em" 이 세 자리에서 서로 다른 길이가 된다

     부모 #p  font-size: 20px
        │
        ├── 자식 #c 의 선언들
        │      font-size: 2em   →  40px   자를 "부모 글꼴 20px" 에 댄다
        │      width:     2em   →  80px   자를 "내 글꼴 40px" 에 댄다
        │      margin:    2em   →  80px   〃
        │
        └─ 같은 "2em" 인데 40 과 80 으로 갈렸다
```

*(Chrome 151 실측 — `#p{font-size:20px}` · `#c{font-size:2em; width:2em; margin-left:2em}` 의 계산값이 각각 `40px`·`80px`·`80px`.)*

실무에서 이게 터지는 자리는 **컴포넌트를 두 군데에 붙였는데 한쪽만 크기가 어긋날 때**다.\
`em` 으로 짠 패딩은 그 요소의 글꼴을 따라가므로, 글꼴이 다른 곳에 붙이면 패딩도 같이 달라진다.

> **기준점(reference)** — 단위가 「몇 배·몇 퍼센트」를 계산할 때 대고 재는 길이.\
> 예: `width: 50%` 의 기준점은 부모의 content 폭이고, `font-size: 50%` 의 기준점은 부모의 글꼴 크기다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. **`em` 은 무엇의 배수인가** — 같은 요소 안에서 속성마다 답이 달라지는 조건은 무엇인가.
2. **`%` 는 무엇의 비율인가** — 속성별로 기준이 어떻게 갈리고, 왜 세로 `padding` 이 가로를 보는가.
3. **`px` 은 화면의 점 하나인가** — 아니라면 무엇이고, `ch`·`ex` 처럼 「재야 아는」 단위는 무엇에 달려 있나.

## 동작 방식

### (1) 절대 단위 — 실은 `px` 하나에 전부 묶여 있다

**언제 쓰나** — `cm`·`pt` 로 적은 값이 인쇄물과 안 맞을 때. CSS 의 「절대」는 **종이가 아니라 `px` 기준**이다.

```text
Chrome 151 에서 폭 1단위짜리 상자를 띄워 잰 값 (devicePixelRatio = 1)

  선언        실제 폭(px)      정의
  ----------  ---------------  ---------------------------
  1in         96              ★ 이것이 못이다 — 1in ≡ 96px
  1pc         16              1pc = 1/6 in
  1pt         1.328125        1pt = 1/72 in  (= 1.3333… 을 1/64 격자에 맞춘 값)
  1cm         37.78125        1cm = 96/2.54 px
  1mm         3.765625        1mm = 1/10 cm
  1Q          0.9375          1Q  = 1/40 cm
  100px       100
```

그림 해설 (한 단계씩):

- **`in`·`cm`·`pt` 는 물리 길이가 아니라 `px` 로 환산된 이름표다.** 화면에서 `1in` 짜리 상자를 자로 재면 1인치가 아니다.
- 그래서 **화면용 CSS 에서 `cm`·`pt` 를 쓸 이유가 없다.** 인쇄 스타일시트에서만 뜻이 산다.
- `pt` 가 딱 떨어지지 않는 것은 엔진이 길이를 **1/64px 격자**에 저장하기 때문이다 — **Chrome 151 의 구현 세부**이고 정본은 [04번](../04-value-processing-stages/2-summary.md)이다.

비용 — 없음. 다만 **「절대」라는 낱말을 믿고 인쇄 치수를 기대하면 틀린다.**

### (2) `px` 은 물리 픽셀이 아니다 — 같은 `100px` 이 장치 점 200개가 된다

**언제 쓰나** — 고해상도 화면에서 1px 선이 흐리게 보이거나, 스크린샷 크기가 창 크기와 안 맞을 때.

```text
같은 문서를 --window-size=400,200 으로 두 번 찍었다 (Chrome 151)

  배율 설정                      CSS 가 본 것              나온 PNG 크기
  -----------------------------  ------------------------  --------------
  (기본)                         devicePixelRatio = 1      400 x 200
  --force-device-scale-factor=2  devicePixelRatio = 2      800 x 400
                                 1in = 96px (그대로)
                                 100px 상자 = 100px (그대로)
```

```text
  CSS 픽셀 1개              장치 픽셀
  +--------+                +--+--+
  |        |   dpr = 2      |  |  |
  |  1px   |  ---------->   +--+--+   장치 점 4개로 그려진다
  |        |                |  |  |
  +--------+                +--+--+
```

그림 해설 (한 단계씩):

- **CSS 의 `px` 은 「기준 픽셀」이라는 추상 단위**다. 장치 점 하나가 아니다.
- 배율이 2가 돼도 **CSS 쪽 숫자는 하나도 안 변한다** — `1in` 도 `96px`, `100px` 상자도 `100px` 이었다.
- 바뀐 것은 **그 CSS 픽셀을 장치 점 몇 개로 칠하느냐**뿐이다. 그래서 PNG 만 2배가 됐다.
- 이 「장치 점으로 내려가는」 단계가 [04번](../04-value-processing-stages/2-summary.md)의 **④ 실제값**이다.

비용 — `1px` 짜리 선은 dpr 이 정수가 아닐 때(1.5 등) 장치 격자에 안 떨어져 **흐려진다.** 고칠 자리는 CSS 가 아니라 실제값 단계다.

> **devicePixelRatio** — CSS 픽셀 하나를 장치 픽셀 몇 개로 그리는가의 비율.\
> 예: 위 실측에서 2로 두자 창 크기는 그대로인데 스크린샷만 가로세로 2배가 됐다.

### (3) ★ `em` 은 속성마다 기준이 다르다 — `font-size` 만 부모를 본다

**언제 쓰나** — 이 주제에서 가장 자주 틀리는 자리다. `2em` 을 두 군데 적었는데 길이가 다를 때.

```text
  #p { font-size: 20px }
  #c { font-size: 2em; width: 2em; padding-left: 2em;
       border-left: 0.5em solid; margin-left: 2em }

              선언          기준으로 삼은 글꼴        계산값
  ----------  ------------  ------------------------  --------
  font-size   2em           부모 #p 의 20px           40px
  width       2em           ★ 자기 #c 의 40px         80px
  padding-left 2em          ★ 자기 #c 의 40px         80px
  border-left 0.5em         ★ 자기 #c 의 40px         20px
  margin-left 2em           ★ 자기 #c 의 40px         80px
```

```text
  왜 이렇게 갈리나 — 순서가 하나뿐이기 때문이다

    ① font-size 를 먼저 정한다  ──> 이때는 자기 글꼴이 아직 없다
       그래서 부모 것을 쓴다        20px x 2 = 40px
                 │
                 v
    ② 나머지 속성의 em 을 푼다  ──> 이제 자기 글꼴 40px 이 있다
                                     40px x 2 = 80px
```

그림 해설 (한 단계씩):

- **`font-size` 의 `em` 만 부모 글꼴**이다. 나머지 전부는 **그 요소가 방금 확정한 자기 글꼴**을 쓴다.
- 예외가 아니라 **순서의 결과**다 — 자기 `font-size` 를 정하는 중에는 자기 `font-size` 를 쓸 수 없다.
- 그래서 `font-size: 2em` 을 같이 쓰면 다른 `2em` 들이 **조용히 4배**가 된다(20 → 80).

```html demo
<div class="outer">
  <div class="fs">font-size: 2em</div>
  <div class="w">width: 2em</div>
</div>
<style>
  .outer { font-size: 20px; font-family: monospace; }
  .fs { font-size: 2em; background: #fde68a; }
  .w  { font-size: 2em; width: 2em; background: #bfdbfe;
        outline: 2px solid #2563eb; }
</style>
```

> **보이는 것** — 두 상자의 글자 크기는 똑같이 커졌는데(둘 다 `font-size: 2em` → 40px), 파란 상자만 **가로 80px 짜리 좁은 기둥**이 되어 글자가 여러 줄로 접힌다. 같은 `2em` 인데 노란 쪽 글꼴은 부모 20px 의 2배(40px)를 재고, 파란 쪽 `width` 는 **자기 글꼴 40px** 의 2배(80px)를 잰 것이다.\
> **바꿔 볼 것** — `.w` 의 `width: 2em` → `width: 2rem` 으로 바꾸면 → **파란 기둥이 32px 로 더 좁아진다**(루트 16px 의 2배)

*(Chrome 151 headless 실측: `.outer` `font-size: 20px` · `.fs` `40px` · `.w` `font-size: 40px` / `width: 80px`.)*

비용 — 없음. 다만 **`font-size` 와 다른 `em` 을 같은 규칙에 쓰면 읽는 사람이 반드시 한 번 헷갈린다.**

### (4) `em` 사슬 — 조상으로 거슬러 올라가며 곱해진다

**언제 쓰나** — 중첩 목록·중첩 카드에서 글자가 계속 커지거나 작아질 때.

```text
  body { font-size: 32px }
  .chain { font-size: 1.25em }   <- 네 겹으로 중첩했다

    body 32px
      └ .chain (1겹)  32    x 1.25 = 40px
          └ .chain (2겹)  40    x 1.25 = 50px
              └ .chain (3겹)  50    x 1.25 = 62.5px
                  └ .chain (4겹)  62.5  x 1.25 = 78.125px
```

그림 해설 (한 단계씩):

- **`em` 은 한 칸 위만 본다.** 그런데 그 한 칸 위도 `em` 이면, 사슬이 루트까지 이어진다.
- 그래서 **깊이가 곧 배율**이 된다 — 같은 선언 하나가 깊이마다 다른 픽셀이 된다.
- 반대로 **`rem` 은 사슬을 끊는다.** 깊이가 몇이든 루트 하나만 본다.

```text
  em 이 보는 것                       rem 이 보는 것
  +---------------------------+       +---------------------------+
  | html                      |       | html  <-- 여기 하나만      |
  |  └ body                   |       |  └ body                   |
  |     └ .a   <- 부모        |       |     └ .a                  |
  |        └ .b  (1.25em)     |       |        └ .b  (1.25rem)    |
  +---------------------------+       +---------------------------+
   한 칸 위를 본다 (사슬이 이어진다)     루트를 본다 (사슬이 끊긴다)
```

비용 — `em` 사슬은 **깊이에 O(1)** 이지만(계산값이 상속되므로), 값을 예측하는 사람의 머리에는 O(깊이)다.

### (5) `rem` — 루트 하나만 본다, 단 루트 자신은 예외

**언제 쓰나** — 사용자 글꼴 설정을 존중하면서 치수를 한 군데서 조절하고 싶을 때.

```text
  html { font-size: 2rem }     <- 루트에서 rem 을 자기 자신에 썼다

  결과: html 의 계산된 font-size = 32px
        즉 "루트의 계산값 2배" 가 아니라 "초기값 16px 의 2배" 였다

  이어서
    #a { width: 1rem }     -> 32px   (이제는 루트의 계산값 32px 을 본다)
    #b { font-size: 200% } -> 64px   (% 는 부모 = html 의 32px 을 본다)
```

그림 해설 (한 단계씩):

- **루트 요소에서 쓴 `rem` 은 루트의 초기 글꼴(16px)을 기준으로 삼는다.** 자기 참조를 피하는 규칙이다.
- 루트가 확정된 뒤부터는 **모든 `rem` 이 그 계산값(32px)을 본다.**
- `html { font-size: 62.5% }` 로 「1rem = 10px」을 만드는 옛 관용구가 이 규칙 위에 서 있다 — 62.5% 는 **부모(브라우저 기본 16px)** 의 62.5% 다.

비용 — 없음. **접근성상 `rem` 이 기본 선택**이다 — 사용자가 브라우저 기본 글꼴을 키우면 따라 커진다.

### (6) ★ `%` 는 속성마다 기준이 다르다 — 실측 표

**언제 쓰나** — `%` 를 적었는데 예상과 다른 길이가 나올 때. **이 절이 이 주제의 결론이다.**

```text
포함 블록: width 400px / height 200px / font-size 20px  (Chrome 151 실측)

  선언                            계산값·실측         기준으로 삼은 것
  ------------------------------  ------------------  ----------------------------
  width: 50%                      200px               부모 content '폭'
  height: 50%                     100px               부모 content '높이'
  padding-left: 10%               40px                부모 content '폭'
  padding-top: 10%                40px                ★ 부모 content '폭' (높이 아님)
  margin-left: 10%                40px                부모 content '폭'
  margin-top: 10%                 40px                ★ 부모 content '폭' (높이 아님)
  text-indent: 25%                실폭 100px          부모 content '폭'
  left: 10%   (position:absolute) 40px                포함 블록 '폭'
  top: 10%    (position:absolute) 20px                포함 블록 '높이'
  font-size: 150%                 30px                ★ '부모'의 font-size
  line-height: 150%               30px                ★ '자기'의 font-size
  transform: translate(50%, 50%)  matrix(…, 50, 20)   ★ '자기' border 상자 (100x40)
  border-radius: 10%              가로 20px/세로 10px ★ 가로는 자기 폭, 세로는 자기 높이
  gap: 10%  (flex, 폭 400)        실거리 40px         자기 content '폭'
  flex-basis: 25%                 실폭 100px          flex 컨테이너의 주축 크기
```

그림 해설 (한 단계씩):

- **세 무리로 갈린다.** ① 부모를 보는 것 ② 자기 자신을 보는 것 ③ 축이 따로 도는 것.
- **부모를 보는 무리에서도 「폭이냐 높이냐」가 또 갈린다** — `height`·`top` 만 높이를 보고 나머지는 전부 폭이다.
- `font-size` 와 `line-height` 가 **바로 옆에 붙어 있는데 기준이 다르다**(부모 / 자기). 이 표에서 가장 자주 틀리는 짝이다.
- `transform` 의 `%` 는 **부모를 아예 안 본다** — 자기 border 상자다. `100x40` 상자에서 `translate(50%,50%)` 가 `50, 20` 으로 나온 것이 근거다.
- `border-radius` 와 `transform` 의 `%` 는 **축마다 다른 치수를 본다.** 한 선언 안에서 기준이 둘이다.

```text
  좌상단 모서리 히트테스트로 잰 border-radius: 10% (상자 200x100)

     상자 좌상단 기준 좌표      elementFromPoint
     ---------------------      ----------------
     (1, 1)                     HTML     <- 상자 밖 (둥글게 깎였다)
     (3, 3)                     상자     <- 안
     (21, 1)                    상자     <- 가로 20px 을 넘겼더니 들어왔다
     (1, 11)                    상자     <- 세로 10px 을 넘겼더니 들어왔다

  => 깎인 타원이 가로 20 x 세로 10 이다 = 폭의 10% x 높이의 10%
```

```text
  왜 세로 padding 이 '폭' 을 보나 — 높이를 보면 순환이 생긴다

  부모 높이 auto  <──────────┐
       │                     │
       v                     │
  자식 padding-top: 10%      │  자식 높이가 부모 높이를 만드는데
       │                     │  부모 높이가 자식 padding 을 만든다
       └─────────────────────┘  => 답이 정해지지 않는다

  그래서 명세가 '폭' 하나로 못을 박았다.
```

- 이 못 덕분에 **`padding-top: 100%` 로 정사각형을 만드는 옛 관용구**가 성립했다(오늘은 `aspect-ratio` — [목록의 **31번 주제**](../31-intrinsic-sizing-and-aspect-ratio/)).
- `height: 50%` 인데 **부모 높이가 `auto`** 면 `%` 를 풀 수 없어 `auto` 로 떨어진다(실측: 부모 `auto` 일 때 자식 실높이 24px = 글줄 높이, 부모 `200px` 일 때 100px).

비용 — `%` 는 **레이아웃을 돌려야 풀리므로** 계산값 단계에서는 `%` 그대로 남는다. 정본은 [04번](../04-value-processing-stages/2-summary.md)이다. `box-sizing` 이 걸리는 자리는 [15번](../15-box-model-and-box-sizing/2-summary.md)이 정본이다.

```html demo
<div class="frame"><div class="sq"></div></div>
<style>
  .frame { width: 200px; height: 40px; border: 2px dashed #dc2626; }
  .sq    { padding-top: 50%; background: #93c5fd; }
</style>
```

> **보이는 것** — 빨간 점선 상자는 높이 40px 인데, 그 안의 파란 칸이 **100px 높이로 자라 점선 아래로 60px 삐져나온다.** `padding-top: 50%` 가 부모 **높이** 40px 의 절반(20px)이 아니라 부모 **폭** 200px 의 절반(100px)을 잡았기 때문이다.\
> **바꿔 볼 것** — `.frame` 의 `width: 200px` → `400px` 로 바꾸면 → **파란 칸의 높이가 200px 로 같이 커진다**(높이는 건드리지 않았는데도)

*(Chrome 151 headless 실측: `.frame` 은 `204x44`, `.sq` 는 `200x100`.)*

### (7) `ch`·`ex` — 글꼴이 바뀌면 길이가 바뀐다

**언제 쓰나** — 「한 줄에 60자」 같은 가독성 폭을 정할 때. 그리고 그 폭이 글꼴 교체로 흔들릴 때.

```text
font-size 를 20px 로 고정하고 글꼴만 바꿔 width:10ch / width:10ex 를 쟀다
(Chrome 151 실측)

  글꼴                 10ch         10ex
  -------------------  -----------  -----------
  DejaVu Sans Mono     120.40625    110
  Liberation Serif     100          91.796875
  DejaVu Sans          127.234375   110
  JetBrains Mono       119.984375   110
  Liberation Sans      111.21875    105.65625

  같은 글꼴에서 "0" 한 글자를 span 으로 재니
    DejaVu Sans Mono = 12.046875     (x10 = 120.40625 — 표와 일치)
    Liberation Serif = 10            (x10 = 100      — 표와 일치)
```

그림 해설 (한 단계씩):

- **`ch` = 글꼴의 `0`(영) 한 글자 전진폭**이다. 위 표에서 `0` 한 글자 폭에 정확히 10을 곱한 값이 나왔다.
- **`ex` = 소문자 x 의 높이**다. 같은 20px 에서 91.8 \~ 110 까지 **20% 가까이 벌어졌다.**
- **`ch` 가 「글자 하나 폭」은 아니다** — 등폭 글꼴에서만 그렇게 읽힌다. 비례 글꼴(`DejaVu Sans`)에서 `10ch` 는 `0` 열 개 폭이지 임의의 글자 열 개 폭이 아니다.
- **글꼴 폴백까지 따라간다** — 없는 글꼴만 적은 요소와 `monospace` 를 덧붙인 요소는 같은 `10ch` 에서 서로 다른 폭이 나왔다(실측: 177.59375 대 160, 그때 루트 글꼴 32px).

```html demo
<div class="mono">0123456789</div>
<div class="serif">0123456789</div>
<style>
  div { width: 10ch; font-size: 20px;
        background: #bfdbfe; outline: 2px solid #2563eb; }
  .mono  { font-family: "DejaVu Sans Mono", monospace; }
  .serif { font-family: "Liberation Serif", serif; }
</style>
```

> **보이는 것** — 두 칸 다 `width: 10ch` 인데 **위(등폭) 칸이 아래(세리프) 칸보다 눈에 띄게 넓다.** 글자 크기는 둘 다 20px 로 같다. 숫자 열 개는 두 칸 모두 한 줄에 들어간다 — `ch` 가 그 글꼴의 `0` 자 폭을 잰 단위이기 때문이다.\
> **바꿔 볼 것** — `.serif` 의 글꼴을 `"DejaVu Sans Mono", monospace` 로 바꾸면 → **두 칸의 폭이 같아진다**

*(Chrome 151 headless 실측: `.mono` `120x24` · `.serif` `100x23`.)*

비용 — `ch`·`ex` 는 **글꼴 메트릭을 읽어야** 정해진다. 웹폰트가 늦게 오면 폭이 한 번 뛴다(`font-display` 는 [목록의 **50번 주제**](../50-fonts-and-webfonts/)).

### (8) `lh`·`rlh` — 줄높이를 단위로 쓴다

**언제 쓰나** — 본문 줄에 맞춰 여백을 떨어뜨리고 싶을 때(세로 리듬).

```text
  #lhu  { font-size: 20px; line-height: 1.5; width: 2lh }  -> 60px
  #rlhu { width: 2rlh }                                     -> 92px

  루트의 line-height 는 normal 이었고, 루트 글꼴 32px 에서
  2rlh = 92px 이 나왔다 (즉 rlh = 46px)
```

그림 해설 (한 단계씩):

- **`lh` = 자기 줄높이**, **`rlh` = 루트 줄높이**다. `em`/`rem` 과 같은 짝 구조다.
- `line-height: normal` 은 절대화되지 않는 값인데 **`rlh` 는 그것을 픽셀로 푼다** — 위에서 46px 이 나온 근거다.
- 「줄높이의 정수 배로 여백을 준다」가 이 단위의 용도다.

비용 — 없음. Baseline 확인이 필요한 비교적 새 단위이므로 [목록 README](../README.md) 의 지원 표를 먼저 본다.

### (9) 어느 단계에서 픽셀이 되나 — 04번 위에 얹는다

**언제 쓰나** — `getComputedStyle` 로 읽은 값이 `%` 인 채로 나올 때.

```text
  선언한 단위      계산값 단계에서               사용값 단계에서
  --------------   ---------------------------   -----------------------
  em / rem / ex    px 로 바뀐다                  (이미 끝)
  ch / lh / rlh    px 로 바뀐다                  (이미 끝)
  px / in / cm     px 로 바뀐다                  (이미 끝)
  %                ★ % 인 채로 남는다            레이아웃을 돌려 px 이 된다
```

- **상속되는 것은 계산값**이므로, 부모에서 `em` 으로 적은 값은 **부모 자리에서 이미 픽셀이 되어** 내려온다. 자식이 다시 계산하지 않는다.
- 이 규칙의 정본과 실측(`text-indent: 2em` 이 자식에서 다시 계산되지 않는 것, `line-height` 무단위만 예외인 것)은 전부 [04번](../04-value-processing-stages/2-summary.md)에 있다. **여기서 다시 쓰지 않는다.**
- 한 줄만 이어 둔다 — `line-height: 150%` 는 **퍼센트라서 픽셀이 된다.** 실측: 글꼴 10px 인 요소의 `line-height: 150%` 는 `15px` 이 됐고, 그 아래 `font-size: 40px` 짜리 자식도 **15px 을 그대로 물려받았다.** 무단위 `1.5` 와 갈리는 자리가 여기다.

## 문법 — 형태와 어디서 헷갈리나

### 최소 형태

```css
.a { width: 100px;  }   /* 숫자 + 단위, 사이에 공백 없음 */
.b { width: 0;      }   /* 길이 0 은 단위를 생략할 수 있다 */
.c { width: 50%;    }   /* % 는 <length> 가 아니라 <percentage> 다 */
.d { width: .5em;   }   /* 앞의 0 은 생략 가능 */
.e { width: 1E2px;  }   /* 지수 표기도 된다 — Chrome 151 은 calc(101px) 로 접었다 */
```

### 헷갈리는 자리

| 적은 것 | 실제 | 왜 |
|---|---|---|
| `width: 100 px` | **버려진다** | 숫자와 단위 사이에 공백이 있으면 한 토큰이 아니다 |
| `width: 0` | 된다 | `<length>` 의 0 은 단위 생략 가능 |
| `calc(100% - 0)` | **버려진다** | `calc()` 안에서는 0 도 단위가 필요하다([35번](../35-calc-clamp-min-max/2-summary.md)) |
| `font-size: 2em` 옆의 `width: 2em` | **길이가 다르다** | (3) — 기준 글꼴이 다르다 |
| `line-height: 150%` 대 `line-height: 1.5` | **상속되는 것이 다르다** | % 는 px 이 되어 내려가고, 숫자는 숫자로 내려간다([04번](../04-value-processing-stages/2-summary.md)) |

### 금지에 가까운 형태

```css
/* 화면용 스타일에 물리 단위 */
.print-ish { width: 8cm; }        /* 화면에서는 302.25px 일 뿐이다 */

/* font-size 와 다른 em 을 한 규칙에 섞기 */
.trap { font-size: 2em; padding: 2em; }   /* 패딩은 4배가 된다 */

/* 세로 여백을 % 로 주면서 "높이 기준" 을 기대하기 */
.wrong { margin-top: 10%; }       /* 부모 '폭' 의 10% 다 */
```

## 구현 세부사항 대 언어 보장

| 무엇 | 어느 쪽 |
|---|---|
| `1in = 96px`, `1pt = 1/72in`, `1Q = 1/40cm` | **명세**(css-values-4) — 고정 환산이다 |
| `em` 의 기준이 `font-size` 에서만 부모인 것 | **명세** — 계산값 정의에서 나온다 |
| 세로 `padding`·`margin` 의 `%` 가 폭 기준인 것 | **명세**(css-box-3) |
| `ch` = `0` 글리프 전진폭, `ex` = x-height | **명세** — 다만 **값은 글꼴이 정한다** |
| 위 표의 `10ch = 120.40625px` 같은 구체 숫자 | **글꼴 구현** — 글꼴이 바뀌면 바뀐다 |
| `1pt` 이 `1.328125px` 로 나오는 것(1.3333… 아님) | **Chrome 151 구현** — 1/64px 격자다 |
| 루트에서 쓴 `rem` 이 초기값 16px 을 보는 것 | **명세**(css-values-4) |
| 브라우저 기본 글꼴이 16px 인 것 | **구현 관행** — 명세가 정한 값이 아니다 |
| `ch` 를 지원하지 않는 글꼴에서의 대체 규칙 | **명세**에 대체 정의가 있으나 **이 문서에서 재지 않았다** |

## 어디서 틀리나

### 1. `font-size: 2em` 옆에 `padding: 2em` 을 쓴다

패딩이 **부모 글꼴의 4배**가 된다. `font-size` 가 먼저 확정되고 나머지가 그 위에서 계산되기 때문이다((3)).\
고치는 법 — 패딩만 `rem` 으로 옮기거나, `font-size` 를 다른 규칙으로 분리한다.

### 2. 세로 여백을 `%` 로 주고 「부모 높이 기준」을 기대한다

`margin-top: 10%`·`padding-top: 10%` 는 **부모 폭 기준**이다(실측 40px, 부모 폭 400 / 높이 200).\
「부모 높이가 바뀌어도 여백이 안 변한다」는 버그 제보가 여기서 나온다.

### 3. `height: 50%` 가 아무 일도 안 한다

부모 높이가 `auto` 면 `%` 를 풀 기준이 없어 `auto` 로 떨어진다(실측: 자식 실높이 24px).\
고치는 법 — 부모에 높이를 주거나, flex/grid 로 늘리거나, `dvh` 같은 뷰포트 단위를 쓴다([34번](../34-viewport-and-container-units/2-summary.md)).

### 4. `ch` 로 잡은 폭이 글꼴 교체 뒤 어긋난다

`ch` 는 그 요소에 **실제로 적용된 글꼴**의 `0` 폭이다. 폴백 글꼴이 쓰이면 값이 달라진다(실측 177.59375 대 160).\
고치는 법 — 폭을 잴 글꼴을 `font-family` 로 고정하거나, `max-width` 를 `ch` 와 `px` 중 작은 쪽으로 묶는다([35번](../35-calc-clamp-min-max/2-summary.md)).

### 5. `cm`·`pt` 로 인쇄 치수를 기대한다

화면에서 `1cm` 는 `37.78125px` 일 뿐이다((1)). 실제 종이 치수는 출력 단계에서 정해진다.

### 6. `1px` 선이 흐린 것을 CSS 문제로 본다

`px` 은 장치 점이 아니다((2)). 배율이 정수가 아니면 **실제값 단계**에서 격자에 안 떨어진다 — 정본은 [04번](../04-value-processing-stages/2-summary.md).

## 언제 쓰고 언제 안 쓰나

| 상황 | 고를 단위 | 왜 |
|---|---|---|
| 글자 크기·본문 여백 | `rem` | 사용자 글꼴 설정을 따라간다. 사슬이 없어 예측이 쉽다 |
| 그 요소의 글꼴에 붙는 여백(버튼 패딩 등) | `em` | 글꼴이 커지면 패딩도 같이 커져야 자연스럽다 |
| 테두리·그림자 같은 장식 두께 | `px` | 글꼴을 따라 커지면 되레 이상해진다 |
| 본문 한 줄의 최대 폭 | `ch` | 「한 줄에 몇 자」가 가독성 기준이다 |
| 부모를 채우는 칸 | `%` | 부모가 바뀌면 따라간다. 단 **어느 치수의 %인지** 확인한다((6)) |
| 세로 리듬(줄에 맞춘 여백) | `lh` | 줄높이 정수 배가 바로 나온다 |
| 인쇄 스타일시트 | `cm`·`pt` | 여기서만 물리 길이의 뜻이 산다 |
| 화면 크기에 따라 변하는 치수 | (여기 아님) | [34번](../34-viewport-and-container-units/2-summary.md)의 뷰포트·컨테이너 단위 |

## 핵심 문장

- 단위의 정체는 숫자가 아니라 **기준점**이다 — 「무엇에 자를 대나」를 먼저 묻는다.
- **`em` 은 `font-size` 에서만 부모를 보고, 나머지 속성에서는 자기 글꼴을 본다.** 순서의 결과이지 예외가 아니다.
- **`%` 의 기준은 속성이 정한다.** 세로 `padding`·`margin` 도 **부모 폭** 기준이고, `font-size` 는 부모 글꼴, `line-height` 는 자기 글꼴이다.
- **`px` 은 물리 픽셀이 아니다.** 배율이 바뀌어도 CSS 숫자는 그대로고, 장치 점 개수만 바뀐다.
- **`ch`·`ex` 는 글꼴이 정한다.** 같은 20px 에서 글꼴만 바꿔도 `10ex` 가 91.8 \~ 110px 로 벌어졌다.

## 용어 풀이

- **`<length>`** — 길이를 뜻하는 값 타입. `px`·`em`·`rem`·`ch`·`in` 등이 여기 속하고 **`%` 는 속하지 않는다**.
- **절대 단위(absolute unit)** — 주변 맥락과 무관하게 길이가 정해지는 단위. CSS 에서는 전부 `px` 로 환산된다. 예: `1in` 은 언제나 `96px`.
- **상대 단위(relative unit)** — 다른 길이를 기준으로 계산되는 단위. 예: `em` 은 글꼴 크기, `%` 는 부모 치수를 본다.
- **`em`** — 그 요소의 `font-size` 의 배수. 단 `font-size` 속성 자신에 쓰면 **부모의** `font-size` 의 배수다.
- **`rem`** — 루트 요소(`html`)의 `font-size` 의 배수. 루트 자신에 쓰면 초기값 16px 기준이다.
- **`ch`** — 그 요소에 적용된 글꼴의 `0`(영) 글리프 전진폭. 예: 실측에서 등폭 20px 의 `1ch` 가 `12.046875px` 이었다.
- **`ex`** — 그 글꼴의 x-height(소문자 x 높이). 예: 같은 20px 에서 글꼴에 따라 `10ex` 가 91.8 \~ 110px 로 갈렸다.
- **`lh` / `rlh`** — 자기 / 루트의 `line-height` 의 배수. 예: 실측에서 `line-height: 1.5` 인 20px 요소의 `2lh` 가 60px 이었다.
- **포함 블록(containing block)** — `%` 가 기준으로 삼는 조상 상자. 대개 부모의 content 상자이고, `position: absolute` 면 달라진다([목록의 **21번 주제**](../21-position-and-containing-block/)).
- **CSS 픽셀 / 장치 픽셀** — 앞은 CSS 가 쓰는 추상 단위, 뒤는 화면의 실제 점. 예: `devicePixelRatio = 2` 에서 CSS 1px 이 장치 점 4개(2×2)로 칠해졌다.
- **1/64px 격자** — Chrome 이 길이를 저장하는 내부 해상도. 예: `1pt` 이 `1.3333…` 이 아니라 `1.328125px` 로 나온 이유다. **Chrome 151 의 구현 세부다.**

## 더 들어가면

- **`cap`·`ic`·`ric` 같은 글꼴 상대 단위가 더 있다.** `cap` 은 대문자 높이, `ic` 는 CJK 「水」 자 폭이다.\
  한글·한자 레이아웃에서 `ic` 는 `ch` 보다 뜻이 정확하다. 지원 상태는 [목록 README](../README.md) 의 Baseline 표로 확인한다.
- **`em` 을 쓴 값이 상속되면 그 뒤로는 고정 픽셀이다.** 「자식에서 글꼴만 줄이면 여백도 줄겠지」가 조용히 깨진다.\
  이것은 단위 문제가 아니라 **상속이 계산값을 나른다**는 성질이다 — [04번](../04-value-processing-stages/2-summary.md)·[03번](../03-inheritance-and-global-keywords/2-summary.md)이 정본이다.
- **`%` 를 쓸 수 없는 속성이 있다.** `border-width` 가 대표다 — 명세가 `<length>` 만 받는다.\
  이런 자리에서 `%` 를 적으면 **선언 하나가 조용히 버려진다**([07번](../07-syntax-and-error-recovery/2-summary.md)).
- **사용자가 브라우저 기본 글꼴을 키우면 무엇이 따라 커지나**가 접근성의 실질 기준이다.\
  `rem`·`em` 은 따라 커지고 `px` 은 안 커진다. 그래서 「`px` 로 고정한 본문 글꼴」이 접근성 지적을 받는다.
- **`ch` 를 쓴 폭은 글꼴 로딩 전후로 달라진다.** 웹폰트를 쓰면 폭이 한 번 뛰는 것이 정상이고,\
  그 점프를 줄이는 수단은 `size-adjust`·`font-display` 쪽이다([목록의 **50번 주제**](../50-fonts-and-webfonts/)).
