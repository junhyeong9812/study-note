# css/syntax/26 — flex 줄바꿈·`gap`·`order` — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Flexible Box Layout Level 1](https://drafts.csswg.org/css-flexbox-1/) (§5.2 `flex-wrap`·§5.4 `order`·§8.4 `align-content`) · [CSS Box Alignment Level 3](https://drafts.csswg.org/css-align-3/) (`gap` 과 정렬 키워드의 정본). 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 모든 좌표·치수는 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워 `getBoundingClientRect()` 로 잰 값이다. `order` 의 탭 순서는 **CDP 로 실제 `Tab` 키를 넣어** 확인했다(`Runtime.evaluate` 로 값을 넣는 것은 사용자 조작이 아니다).\
> **WebKit(Safari)은 이 머신에 없고 Firefox 는 이 환경에서 headless 스크린샷이 산출되지 않는다** — 엔진 차이는 주장하지 않는다.
> **버전** — Flexbox 는 Baseline **widely**(newly 2015-09-30 → widely 2018-03-30). **flex 의 `gap` 은 더 늦다** — **widely**(newly 2021-04-26 → widely 2023-10-26). 옛 코드가 마진으로 간격을 준 이유가 이것이다.
> **여기서 다루지 않는 것** — 축·정렬 키워드의 정본은 [24번](../24-flexbox-axes/), 항목 크기 해결은 [25번](../25-flex-shorthand-and-sizing/)이다. 2차원 배치는 목록의 [**27**](../27-grid-track-sizing/)~[**30**](../30-subgrid/)번 주제(Grid)다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 수치는 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**줄바꿈을 켜면 flex 컨테이너는 「한 줄짜리 벨트」에서 「여러 줄짜리 선반」이 된다.**

[24번](../24-flexbox-axes/)의 컨베이어 벨트 비유를 그대로 이어받아 한 칸만 늘린다.

| 비유 | 실체 |
|---|---|
| 벨트 하나 | `flex-wrap: nowrap` — 줄이 하나뿐 |
| 선반 여러 칸 | `flex-wrap: wrap` — 줄(line)이 여러 개 생길 수 있다 |
| 선반 **한 칸 안에서** 물건을 위아래로 맞추는 일 | `align-items` |
| **선반 칸들 자체**를 위아래로 미는 일 | `align-content` |
| 물건 사이에 끼우는 스페이서 | `gap` — **양 끝에는 안 들어간다** |
| 진열만 바꾸고 재고 목록은 그대로 두는 것 | `order` — 그림 순서만 바꾸고 DOM 은 그대로 |

- 줄바꿈이 켜지면 [25번](../25-flex-shorthand-and-sizing/)의 크기 해결이 **줄마다 따로** 돈다. 자유 공간도 줄마다 따로 계산된다.
- ★ **`align-items` 와 `align-content` 는 대상이 다르다** — 앞엣것은 **줄 안의 항목**, 뒤엣것은 **줄들 자체**. 이름의 `items` 와 `content` 가 그것을 그대로 적은 것이다.
- ★ **`order` 는 「그리는 순서」만 바꾼다.** DOM·탭 순서·읽는 순서는 그대로여서, 화면 맨 왼쪽인데 `:first-child` 가 아닌 상황이 만들어진다. 접근성 사고의 자리다.

```text
nowrap (줄 하나)                     wrap (줄 여럿)
+--------------------------------+   +--------------------------------+
| [1][2][3]  ....... 넘치면 뚫는다 |   | [1][2]                         |  <- 1번 줄
+--------------------------------+   | [3]                            |  <- 2번 줄
                                     +--------------------------------+
  줄 하나라 align-content 가 안 쓰인다   줄이 여럿이라 align-content 가 그 줄들을 배치한다
```

실무에서 이게 터지는 자리는 **카드 그리드**다.\
`flex-wrap: wrap` 으로 카드를 여러 줄에 깔아 놓고 `align-items: center` 를 줬는데 **줄 사이 간격이 이상하게 벌어진다.**\
범인은 `align-content` 의 초기값이다 — (4)가 그 정본이다.

> **flex 줄(flex line)** — 줄바꿈이 켜졌을 때 항목들이 담기는 한 묶음. `nowrap` 이면 줄이 정확히 하나다.\
> 예: 120px 항목 셋을 300px 컨테이너에 `wrap` 으로 넣으면 첫 줄에 둘, 둘째 줄에 하나가 담긴다.

> **교차축(cross axis)** — 주축에 직각인 축. `row` 면 세로다. 줄들이 쌓이는 방향이기도 하다. 정본은 [24번](../24-flexbox-axes/).\
> 예: `row` + `wrap` 이면 줄이 위에서 아래로 쌓인다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. 줄바꿈이 켜지면 **무엇이 새로 생기고** 어떤 속성이 그제서야 의미를 갖는가.
2. `gap` 은 마진으로 간격을 주는 것과 **결과가 어떻게 다른가.**
3. `order` 가 바꾸는 것과 **바꾸지 않는 것**은 각각 무엇인가.

## 동작 방식

### (1) `flex-wrap` 세 값 — 줄이 생기는 방식

**언제 쓰나** — 항목이 컨테이너보다 많거나 클 때.

`flex: 0 0 120px` 인 항목 셋(합 360px)을 **300px 컨테이너**에 넣고 셋을 각각 걸어 쟀다.

```text
nowrap (초기값)                    wrap                        wrap-reverse
컨테이너 300 · 높이 30             컨테이너 300 · 높이 60        컨테이너 300 · 높이 60
+---------------------+---+       +---------------------+      +---------------------+
|[1]   [2]   [3]      |   |       |[1]      [2]         |      |[3]                  | y=0
+---------------------+---+       +---------------------+      +---------------------+
x: 0   120   240 -> 360           |[3]                  |      |[1]      [2]         | y=30
                                  +---------------------+      +---------------------+
줄이 하나라 넘친다                  y: 0,0,30                    첫 줄이 **아래**에 온다
```

*(Chrome 151 headless 실측 — `nowrap`: 컨테이너 높이 30, 항목 x=0 / 120 / 240(셋째의 오른끝이 360 으로 뚫는다). `wrap`: 높이 60, (x0,y0) (x120,y0) (x0,y30). `wrap-reverse`: 높이 60, 1 과 2 가 y=30, 3 이 y=0.)*

```html demo
<div class="c"><i>1</i><i>2</i><i>3</i></div>
<style>
  .c { display: flex; flex-wrap: wrap; width: 300px; background: #eee;
       font: 14px monospace; outline: 2px solid #c00; }
  .c i { display: block; font-style: normal; flex: 0 0 120px; height: 30px;
         background: #bfdbfe; outline: 1px solid #333; }
</style>
```

> **보이는 것** — 120px 칸 셋이 300px 상자에 다 안 들어가서 **첫 줄에 `1`·`2`, 둘째 줄에 `3`** 이 놓인다. 빨간 테두리 안에서 끝나고 상자 높이는 두 줄만큼(60px)이 된다.\
> **바꿔 볼 것** — `wrap` → `nowrap` → 칸 셋이 **한 줄로 늘어서며 빨간 테두리를 뚫고 나간다**(`flex-shrink: 0` 이라 안 줄어든다) · `wrap` → `wrap-reverse` → `3` 이 **위 줄**로 가고 `1`·`2` 가 아래 줄로 간다

그림 해설 (한 단계씩):

- `nowrap` 에서 항목이 안 줄어들면 **줄이 늘지 않고 그냥 뚫는다.** 줄바꿈은 「넘치면 자동으로」가 아니라 **명시적으로 켜는 것**이다.
- `wrap-reverse` 는 항목 순서가 아니라 **줄이 쌓이는 방향**을 뒤집는다. 항목 자체의 순서(`1 2` / `3`)는 그대로다.
- 줄에 몇 개가 담기는지는 [25번](../25-flex-shorthand-and-sizing/)의 basis 로 정해진다. **basis 합이 컨테이너를 넘는 순간 새 줄이 시작된다.**

비용 — 줄이 늘면 크기 해결이 **줄 수만큼** 반복된다.

### (2) 줄바꿈이 켜지면 크기 해결이 줄마다 따로 돈다

**언제 쓰나** — 「같은 `flex: 1` 인데 줄마다 칸 폭이 다르다」를 설명할 때.

```text
wrap 일 때 컨테이너는 이렇게 나뉜다

  컨테이너
  +------------------------------------------+
  | 줄 1 :  자유 공간을 이 줄의 항목끼리 나눈다  |
  +------------------------------------------+
  | 줄 2 :  자유 공간을 이 줄의 항목끼리 나눈다  |   <- 항목 수가 다르면 결과도 다르다
  +------------------------------------------+
        ↑
  align-content 가 **이 두 칸 자체**를 교차축에서 배치한다
        ↑
  align-items 는 **각 칸 안에서** 항목 하나하나를 배치한다
```

- [25번](../25-flex-shorthand-and-sizing/)의 ①\~⑥ 계산이 **줄 단위로 독립**이다. 마지막 줄만 항목이 하나면 그 항목이 줄 전체를 먹는다.
- 그래서 카드 그리드에서 **마지막 줄의 카드만 커지는** 현상이 생긴다. `flex-grow` 를 켜 두면 필연이다.

### (3) 줄의 교차축 크기 — 초기값이 `stretch` 다

**언제 쓰나** — 「줄 사이가 왜 이렇게 벌어지나」를 볼 때.

```text
컨테이너 높이 200, 항목 넷 (높이 20/60/20/40), 두 줄

줄의 자연 높이   줄1 = max(20,60) = 60      줄2 = max(20,40) = 40     합 100
교차축 자유 공간  200 − 100 = 100

align-content: normal (초기값 — flex 에서 stretch 처럼)
  줄마다 50 씩 더한다
  +-----------------------------+  y 0
  | 줄1 (60+50 = 110)           |
  +-----------------------------+  y 110
  | 줄2 (40+50 = 90)            |
  +-----------------------------+  y 200
```

*(Chrome 151 headless 실측 — `align-items: center` 만 준 판에서 항목 y 가 45 / 25 / 145 / 135 였다. 줄1 이 0\~110, 줄2 가 110\~200 이고 각 줄 안에서 가운데 정렬된 결과와 맞는다: (110−20)/2=45 · (110−60)/2=25 · 110+(90−20)/2=145 · 110+(90−40)/2=135.)*

- **줄이 늘어나는 것이 기본값**이다. 「줄 사이가 벌어진다」의 정체는 간격이 아니라 **줄 자체가 부풀어 있는 것**이다.
- 고치는 법은 `align-content` 를 명시하는 것이다 — 다음 항.

### (4) ★ `align-content` 와 `align-items` 가 갈리는 자리

**언제 쓰나** — 여러 줄 배치가 의도와 다를 때. **이 주제에서 가장 자주 사고가 나는 자리다.**

```text
align-items          align-content
= 줄 **안에서** 항목  = 줄들 **자체**를 교차축에 배치

+-------------------------+     +-------------------------+
|  줄1 [a][b][c]          |     |  줄1 [a][b][c]          |  ← 이 덩어리를
|      ↕ 각 항목이 움직인다 |     |                         |     통째로
|  줄2 [d][e]             |     |  줄2 [d][e]             |  ← 위/아래/가운데로
+-------------------------+     +-------------------------+
```

같은 컨테이너(260×200, 항목 넷)에 값만 바꿔 실제로 쟀다.

```text
선언                                    항목별 y (높이)
align-content: flex-start      1:y0(20)   2:y0(60)   3:y60(20)   4:y60(40)
align-content: center          1:y50(20)  2:y50(60)  3:y110(20)  4:y110(40)
align-content: space-between   1:y0(20)   2:y0(60)   3:y160(20)  4:y160(40)
align-items: center (content 초기값)
                               1:y45(20)  2:y25(60)  3:y145(20)  4:y135(40)
align-content:center + align-items:center
                               1:y70(20)  2:y50(60)  3:y120(20)  4:y110(40)
```

*(Chrome 151 headless 실측. `align-content` 만 준 판에서는 **같은 줄의 두 항목이 y 가 같다**(줄이 통째로 움직였다는 증거)이고, `align-items` 를 준 판에서는 **같은 줄인데 y 가 다르다**(항목이 줄 안에서 따로 움직였다는 증거)다.)*

```html demo
<div class="c"><i>1</i><i>2</i><i>3</i><i>4</i></div>
<style>
  .c { display: flex; flex-wrap: wrap; width: 260px; height: 200px;
       align-content: center;   /* 줄들 자체를 교차축 가운데로 */
       background: #eee; font: 14px monospace; outline: 2px solid #c00; }
  .c i { display: block; font-style: normal; flex: 0 0 120px;
         background: #bfdbfe; outline: 1px solid #333; }
  .c i:nth-child(1) { height: 20px; }  .c i:nth-child(2) { height: 60px; }
  .c i:nth-child(3) { height: 20px; }  .c i:nth-child(4) { height: 40px; }
</style>
```

> **보이는 것** — 칸 넷이 두 줄로 놓이고, **두 줄 덩어리가 상자 세로 가운데에 모여** 위아래에 똑같은 빈 공간이 남는다. 한 줄 안의 두 칸은 **높이가 달라도 위쪽이 나란히** 맞춰져 있다(줄만 움직였고 항목은 안 움직였다).\
> **바꿔 볼 것** — `align-content: center` → `space-between` → 두 줄이 **위 끝과 아래 끝**으로 갈라진다 · 그 줄을 **지우면** 두 줄이 늘어나 상자 높이를 나눠 갖고 **첫 줄이 맨 위로 올라붙는다**(칸의 높이 자체는 안 변한다 — 늘어나는 것은 줄이지 칸이 아니다) · `align-items: center` 를 **추가**하면 줄 안에서 칸들이 각자 세로 가운데로 모인다

*(Chrome 151 headless 실측 — 이 블록 그대로: 항목 y 가 50 / 50 / 110 / 110. 같은 줄의 두 항목이 y 가 같다.\
★ 「바꿔 볼 것」의 첫째도 돌려 봤다 — `align-content` 줄을 **지운 판**은 y 가 **0 / 0 / 110 / 110** 이고 **칸의 높이는 20/60/20/40 그대로**였다. 줄은 늘어났지만(줄1 이 0\~110, 줄2 가 110\~200) **칸은 안 늘어난다** — 칸에 높이를 명시했기 때문이다. 바뀌어 보이는 것은 **첫 줄이 위로 올라붙는 것**뿐이다.)*

그림 해설 (한 단계씩):

- `align-content` 만 주면 **같은 줄의 항목들이 같은 y 에** 있다 — 줄이 통째로 움직인 것이다.
- `align-items` 만 주면 **같은 줄인데 y 가 다르다** — 각 항목이 줄 안에서 따로 움직인 것이다.
- 둘을 같이 주면 **두 번 움직인다** — 줄이 먼저 배치되고, 그 줄 안에서 항목이 배치된다.
- 정렬 값(`flex-start`·`center`·`space-*`)의 뜻 자체는 [24번](../24-flexbox-axes/)이 정본이다. 여기서는 **대상이 무엇인가**만 다룬다.

비용 — 없다. 다만 **둘을 혼동하면 증상이 「간격이 이상하다」로 같아서** 어느 쪽을 고칠지 화면만 보고는 못 정한다.

### (5) ★★ `align-content` 가 안 먹는 조건 — 「줄 수」가 아니라 「`flex-wrap`」이다

**언제 쓰나** — `align-content` 를 줬는데 아무 일도 안 일어날 때.

흔한 설명은 「줄이 둘 이상일 때만 의미가 있다」인데, **실측은 그렇지 않았다.**

```text
컨테이너 260×200, 항목 하나(높이 20). 줄은 어느 판이든 하나뿐이다.

flex-wrap: nowrap + align-content: center   ->  항목 y = 0     (안 먹는다)
flex-wrap: wrap   + align-content: center   ->  항목 y = 90    (먹는다!)
flex-wrap: nowrap + align-content: center
                  + align-items: flex-start ->  항목 y = 0     (여전히 안 먹는다)
flex-wrap: wrap   (선언 없음)                ->  항목 y = 0
flex-wrap: nowrap (선언 없음)                ->  항목 y = 0

네 판 모두 getComputedStyle(container).alignContent 는 선언한 값 그대로다
(center 를 준 판은 전부 'center', 안 준 판은 'normal')
```

*(Chrome 151 headless 실측. 200 − 20 = 180, 그 절반이 90 — `wrap` 판의 y=90 이 정확히 가운데다.)*

```text
갈림길은 이것이다

  flex-wrap: nowrap   ──> 「한 줄짜리 컨테이너」  ──> align-content 는 정의상 적용되지 않는다
  flex-wrap: wrap     ──> 「여러 줄짜리 컨테이너」 ──> 줄이 **실제로 하나뿐이어도** 적용된다
     또는 wrap-reverse
```

- ★ **가르는 것은 실제 줄 수가 아니라 `flex-wrap` 값이다.** 명세가 `nowrap` 컨테이너를 「단일 줄(single-line) flex 컨테이너」로 정의하고 그 경우에만 `align-content` 를 배제한다.
- ★★ **계산값으로는 이 차이가 안 보인다.** 네 판 모두 `alignContent` 가 선언한 값 그대로 남는다 — 진단 3창(`cssRules` → `querySelectorAll` → `getComputedStyle`)을 다 통과하고도 **결과만 다른** 자리다. `getBoundingClientRect()` 로 재야 안다.
- [24번](../24-flexbox-axes/)의 「`align-content` 는 줄이 둘 이상일 때만」이라는 설명은 **실무에서 거의 맞지만 경계가 정확하지 않다.** 정확한 경계는 여기다.

비용 — 없다. 다만 **`flex-wrap` 을 안 쓴 컨테이너에서 `align-content` 로 세로 가운데를 맞추려는 시도는 무조건 실패한다.** 그때 쓸 것은 `align-items` 다.

### (6) `gap` — 사이에만 들어간다

**언제 쓰나** — 항목 간격을 줄 때. **마진과 결과가 다르다.**

300px 컨테이너에 `flex: 1 1 0` 항목 셋을 넣고 간격 20px 를 두 방식으로 줬다.

```text
gap: 20px                              margin-right: 20px
+------+  +------+  +------+           +-----+  +-----+  +-----+
|0→87  |  |107→193| |213→300|          |0→80 |  |100→180| |200→280|
+------+  +------+  +------+           +-----+  +-----+  +-----+
0                          300         0                       280   300
         오른쪽 끝에 딱 닿는다                     오른쪽에 20px 가 죽는다 ↑

margin: 0 10px
   +-----+  +-----+  +-----+
   |10→90|  |110→190| |210→290|
   +-----+  +-----+  +-----+
   ↑ 왼쪽에도 10 이 죽는다        오른쪽에도 10 이 죽는다 ↑
```

*(Chrome 151 headless 실측 — 컨테이너 300px 기준 각 항목의 `[왼쪽→오른쪽]`:\
`gap: 20px` → `[0→87] [107→193] [213→300]`\
`margin-right: 20px` → `[0→80] [100→180] [200→280]`\
`margin: 0 10px` → `[10→90] [110→190] [210→290]`.)*

```html demo
<div class="c g"><i>gap</i><i>gap</i><i>gap</i></div>
<div class="c m"><i>margin</i><i>margin</i><i>margin</i></div>
<style>
  .c { display: flex; width: 300px; background: #eee; margin-bottom: 8px;
       font: 12px monospace; outline: 2px solid #c00; }
  .c i { display: block; font-style: normal; flex: 1 1 0;
         background: #bfdbfe; outline: 1px solid #333; }
  .g { gap: 20px; }
  .m i { margin-right: 20px; }   /* 끝에도 붙는다 */
</style>
```

> **보이는 것** — 위 줄(`gap`)은 셋째 칸의 오른쪽이 **빨간 테두리에 딱 닿는다**. 아래 줄(`margin-right`)은 셋째 칸 오른쪽에 **회색 틈이 20px 남는다**. 칸 사이 간격은 두 줄이 같아 보인다.\
> **바꿔 볼 것** — `.m i` 를 `margin: 0 10px` 로 → **왼쪽 끝에도 틈이 생긴다**(양쪽 다 죽는다) · `.g` 에 `justify-content: space-between` 을 추가 → **아무 일도 일어나지 않는다**(`flex: 1 1 0` 이 이미 자유 공간을 다 먹었다 — 나눌 것이 없다. `gap` 이 「최소 간격」으로 동작하는 것을 보려면 (7)처럼 **항목을 고정 폭으로** 바꿔야 한다)

*(Chrome 151 headless 실측 — 위 블록 그대로: `gap` 판은 `[0→87] [107→193] [213→300]`, `margin-right` 판은 `[0→80] [100→180] [200→280]`.\
★ 「바꿔 볼 것」의 둘째도 돌려 봤다 — `.g` 에 `justify-content: space-between` 을 더한 판이 `[0→87] [107→193] [213→300]` 로 **한 픽셀도 안 바뀌었다.** `flex: 1 1 0` 항목이 자유 공간을 이미 0 으로 만들어 `space-between` 이 나눌 것이 없기 때문이다. 같은 실험을 고정 폭 항목으로 하면 결과가 다르다 — (7).)*

그림 해설 (한 단계씩):

- **`gap` 은 항목 **사이**에만 들어가고 양 끝에는 안 붙는다.** 항목 n 개면 간격은 n−1 개다.
- **마진은 항목의 일부**다. 끝에도 붙고, **[25번](../25-flex-shorthand-and-sizing/)의 자유 공간을 그만큼 먼저 줄인다.**
- `gap` 도 자유 공간을 줄이는 것은 같다 — `flex: 1` 셋에 `gap: 20px` 면 각 칸이 `(300 − 40) ÷ 3 = 86.67` 이다(실측의 87 이 그 값의 반올림 표시다).
- flex 항목끼리는 **마진 상쇄가 없다**([18번](../18-margin-collapsing/) §(6)). 그래서 `margin: 0 10px` 를 항목마다 주면 사이 간격이 **10 이 아니라 20** 이다.

비용 — `gap` 은 Baseline **widely** 가 2023-10-26 으로 늦다. 그보다 오래 지원해야 하는 코드는 마진 방식을 쓰고, 그때 **끝 여백을 지우는 `:last-child` 규칙이 따라붙는다.**

### (7) `gap` 과 `justify-content: space-*` 를 같이 쓰면

**언제 쓰나** — 「최소 간격은 20px 이되 남으면 더 벌려라」가 필요할 때.

```text
컨테이너 300, 항목 셋 flex: 0 0 60px (합 180)

gap: 20px + space-between
  자유 공간 = 300 − 180 − 40(gap 둘) = 80
  space-between 이 80 을 두 자리에 40 씩 더 넣는다  ->  실제 간격 = 20 + 40 = 60
  [0→60]        [120→180]        [240→300]

margin-right: 20px + space-between
  자유 공간 = 300 − 180 − 60(마진 셋) = 60
  두 자리에 30 씩  ->  마진 20 + 30 = 50 간격, 그리고 끝에 20 이 남는다
  [0→60]       [110→170]       [220→280]
```

*(Chrome 151 headless 실측 — 위 두 줄의 좌표가 실측값이다.)*

- **`gap` 은 「최소 간격」이지 「고정 간격」이 아니다.** `space-*` 가 그 위에 더 벌린다.
- 마진 방식은 **끝 여백까지 자유 공간에서 빠져** 계산이 한 겹 더 어긋난다. 이것이 「`space-between` 인데 끝이 안 맞는다」의 정체다.

### (8) 줄바꿈에서의 `gap` — 행 간격과 열 간격이 따로다

**언제 쓰나** — 카드 그리드의 가로·세로 간격을 다르게 줄 때.

```text
gap: 10px 20px          (행 간격 10, 열 간격 20)
        │      │
        │      └─ column-gap : 주축 방향(항목 사이)
        └──────── row-gap    : 교차축 방향(줄 사이)

컨테이너 260, 항목 110×30, 넷
  +--------------------------+
  |[1]        [2]            |  y=0     1:x0   2:x130   (110 + 20 = 130)
  |                          |
  |[3]        [4]            |  y=40    3:x0   4:x130   (30 + 10 = 40)
  +--------------------------+
  컨테이너 높이 = 30 + 10 + 30 = 70
```

*(Chrome 151 headless 실측: 1:(x0,y0) 2:(x130,y0) 3:(x0,y40) 4:(x130,y40), 컨테이너 높이 70.)*

- `gap: <행> <열>` 순서다. **한 값만 쓰면 둘 다** 그 값이 된다.
- `row-gap` 은 **줄 사이에만** 들어간다 — 줄이 하나면 아무 일도 안 한다.
- `flex-direction: column` 이면 두 이름의 역할이 **주축·교차축 기준으로는 그대로이고 화면 방향만 바뀐다.** 이름이 물리 방향(`row`/`column`)인 것이 혼란의 원인이다.

### (9) ★ `order` — 그리는 순서만 바꾼다

**언제 쓰나** — 마크업을 못 바꾸면서 시각 순서를 바꿔야 할 때. **접근성 사고가 여기서 난다.**

DOM 순서가 `A` → `B` → `C` 인 링크 셋에서 **마지막 `C` 에만 `order: -1`** 을 줬다.

```text
DOM 순서                      화면 순서                   Tab 순서
<a>A</a>                     [ C ][ A ][ B ]            1번째: A
<a>B</a>                      x0   x133  x267           2번째: B
<a class="first">C</a>                                   3번째: C
                             맨 왼쪽은 C                 맨 왼쪽 C 가 **마지막**에 온다
```

*(Chrome 151 headless 실측 — 위치: `A@x133 B@x267 C@x0`. **Tab 순서는 CDP 로 실제 `Tab` 키를 세 번 넣어** 확인했고 `document.activeElement.id` 가 차례로 `A` → `B` → `C` 였다.)*

```text
바뀐 것                        안 바뀐 것
+---------------------------+  +------------------------------------------+
| 화면에 그려지는 좌표        |  | nav.children 순서          -> A, B, C     |
| 겹쳤을 때 누가 위인가 (10)  |  | querySelectorAll 순서      -> A, B, C     |
+---------------------------+  | :first-child               -> A           |
                               | textContent 이어 읽기       -> "ABC"      |
                               | Tab 키 이동 순서            -> A, B, C     |
                               +------------------------------------------+
```

*(Chrome 151 headless 실측 — 같은 문서에서 한 번에 읽었다: `a:first-child` 가 잡은 것은 **`A`**, 화면 맨 왼쪽 항목은 **`C`**, `nav.textContent` 는 `"ABC"`. `Tab` 을 세 번 넣었을 때 `document.activeElement.id` 는 `A` → `B` → `C`.)*

```html demo
<nav><a href="#">A</a><a href="#">B</a><a href="#" class="first">C</a></nav>
<style>
  nav { display: flex; width: 400px; background: #eee; font: 16px monospace; }
  nav a { display: block; flex: 1 1 0; text-align: center;
          background: #bfdbfe; outline: 1px solid #333; }
  nav a.first { order: -1; background: #fca; }   /* 마지막 링크를 맨 왼쪽으로 */
</style>
```

> **보이는 것** — 링크 셋이 **왼쪽부터 `C`(주황) · `A` · `B`** 순서로 보인다. HTML 에 쓰인 순서는 `A B C` 인데 화면만 뒤바뀌었다.\
> **바꿔 볼 것** — 브라우저에서 `Tab` 키를 눌러 보라 — 포커스가 **주황 칸이 아니라 `A` 부터** 간다(화면 순서와 어긋난다) · `order: -1` → `order: 0` → 원래 순서로 돌아온다

*(Chrome 151 headless 실측 — 좌표 `A@x133 B@x267 C@x0`. CDP 로 `Tab` 을 세 번 넣었더니 포커스가 `A` → `B` → `C` 로 갔다.)*

그림 해설 (한 단계씩):

- `order` 는 **「order-modified document order」** 라는 별도의 순서를 만든다. 레이아웃과 그리기는 그 순서를 쓰고 **나머지는 전부 DOM 순서를 쓴다.**
- 그래서 **화면 맨 왼쪽인데 `:first-child` 가 아니고, 화면 맨 왼쪽인데 `Tab` 이 가장 늦게 간다.**
- 명세도 「`order` 는 **시각적 순서 변경만을 위한 것**이고 논리 순서를 바꾸는 데 쓰면 안 된다」고 못 박는다.

비용 — **키보드 사용자와 스크린 리더 사용자에게 순서가 어긋난다.** 시각 순서가 곧 의미 순서인 내비게이션·폼에서는 쓰지 않는다. 진짜로 순서가 바뀌어야 하면 **마크업을 바꾼다.**

### (10) `order` 는 쌓임(그리는 순서)에도 영향을 준다

**언제 쓰나** — 항목이 겹치는 배치(음수 마진·아바타 스택)에서.

```text
항목 둘이 40px 겹치게 배치했다 (width 120, margin-right -40)

order 없음                          1 에 order: 1
  [ 1 ][ 2 ]                          [ 2 ][ 1 ]
  x0-120 / x80-200                    x80-200 / x0-120
  겹침 구간(x 80~120) 맨 위 = 2        겹침 구간(x 80~120) 맨 위 = 1
  (DOM 이 뒤인 2 가 위)                (order 가 뒤인 1 이 위)
```

*(Chrome 151 headless 실측 — 겹침 구간 한가운데에서 `document.elementFromPoint()` 로 확인했다. `order` 없음 → `2`, `order: 1` → `1`. 둘 다에 `position: relative; z-index: 0` 을 준 판에서도 결과가 같았다.)*

- **그리는 순서가 order-modified document order 를 따른다.** 「DOM 이 뒤면 위」가 아니라 **「order 가 뒤면 위」** 다.
- 그래서 `order` 를 만지면 **겹친 항목의 앞뒤가 같이 뒤집힌다.** 의도하지 않았다면 `z-index` 로 따로 고정해야 한다.
- 쌓임 맥락 전반은 [목록의 **22번 주제**](../22-stacking-context-and-z-index/)가 정본이다. 여기서는 **`order` 가 순서를 바꾼다는 사실**까지만 다룬다.

## 문법 — 형태와 어디서 헷갈리나

CSS 는 문법 표면이 단순하므로 이 절은 **어디서 헷갈리나**로 읽는다.

### 최소 형태

```css
.container {
  display: flex;
  flex-wrap: wrap;          /* 초기값은 nowrap */
  gap: 10px 20px;           /* row-gap column-gap 순서 */
  align-content: center;    /* 줄들 자체 — wrap 일 때만 */
  align-items: center;      /* 줄 안의 항목 — 언제나 */
}
.container > .item { order: -1; }   /* 항목에 준다. 초기값 0 */
```

- `flex-flow` 는 `flex-direction` 과 `flex-wrap` 의 단축이다 — `flex-flow: row wrap`.
- `gap` 은 `row-gap` / `column-gap` 의 단축이다.

### 헷갈리는 자리 — 이름 넷

| 이름 | 대상 | 언제 의미가 있나 |
|---|---|---|
| `align-items` | 줄 **안**의 항목 하나하나 | 언제나 |
| `align-self` | 항목 **하나만** 예외 | 언제나 |
| `align-content` | **줄들 자체** | **`flex-wrap` 이 `wrap`/`wrap-reverse` 일 때만**((5)) |
| `justify-content` | 주축의 항목 **묶음** | 언제나 |

- `align-items` ↔ `align-content` 는 **글자 두 개 차이인데 대상이 완전히 다르다.** 이 표가 이 주제의 절반이다.
- 값 이름의 뜻(`flex-start`·`space-between` 등)은 [24번](../24-flexbox-axes/)이 정본이다.

### 금지에 가까운 형태

```css
/* ① nowrap 인데 align-content 로 세로 가운데를 맞추려 한다 — 아무 일도 안 한다 */
.c { display: flex; align-content: center; }        /* (5) — align-items 를 써라 */

/* ② order 로 읽는 순서를 바꾸려 한다 — 화면만 바뀐다 */
.c > .important { order: -1; }                       /* (9) — 마크업을 바꿔라 */

/* ③ gap 에 음수 */
.c { gap: -10px; }

/* ④ 항목에 gap 을 준다 — gap 은 컨테이너 속성이다 */
.c > .item { gap: 10px; }                            /* 그 항목이 또 컨테이너가 아니면 무의미 */
```

*(Chrome 151 headless 실측 — 진단 3창의 첫째 창(`cssRules`)으로 읽은 결과: `#g1 { }` ← `gap: -10px` · `#g2 { gap: 10px; }` ← 정상 · `#g3 { }` ← `order: 1.5` · `#g4 { order: -1; }` ← 음수 정수는 **유효하다**. `gap` 음수와 `order` 소수는 파싱에서 버려졌고 에러도 경고도 없다.)*

## 구현 세부사항 대 언어 보장

| 항목 | 누가 보장하나 |
|---|---|
| `flex-wrap` 세 값의 뜻과 `wrap-reverse` 가 줄 쌓임 방향을 뒤집는 것 | **명세** — css-flexbox-1 §5.2 |
| `align-content` 가 **단일 줄 컨테이너(`nowrap`)에서 적용되지 않는 것** | **명세** — css-flexbox-1 §8.4. 「줄이 하나면」이 아니라 「`nowrap` 이면」이다 |
| `gap` 이 항목 **사이에만** 들어가는 것 | **명세** — css-align-3 의 gutter 정의 |
| `order` 가 **시각 순서만** 바꾸고 DOM·순차 포커스 순서를 안 바꾸는 것 | **명세** — css-flexbox-1 §5.4 + HTML 의 순차 포커스 탐색 정의 |
| `order` 가 **그리는 순서**에 영향을 주는 것 | **명세** — css-flexbox-1 §5.4 (order-modified document order 로 그린다) |
| 위 표의 **구체 좌표**(y=90, x=133 등) | **이 머신의 Chrome 151 실측** |
| `86.67` 같은 나눗셈 잔차의 반올림 표시 | **구현** — 실제값 단계. [04번](../04-value-processing-stages/) |
| Tab 키가 실제로 A→B→C 로 간 것 | **이 Chrome 에서의 관찰.** 규칙 자체는 HTML 명세가 보장하지만 **관찰은 관찰로 적는다** |

## 어디서 틀리나

이 주제의 값어치는 대부분 여기 있다. 전부 **에러 없이 조용히 어긋난다.**

### 1. `align-items` 와 `align-content` 를 바꿔 쓴다

증상이 둘 다 「세로 배치가 이상하다」라서 화면만 보고는 못 가른다.\
가르는 법 — **같은 줄의 항목들 y 를 비교하라.** 같으면 줄이 움직인 것(`align-content`), 다르면 항목이 움직인 것(`align-items`)이다.

### 2. `nowrap` 에서 `align-content` 로 세로 가운데를 맞추려 한다

**절대 안 된다**((5)). 계산값은 `center` 로 멀쩡히 남아서 **진단 3창으로도 안 잡힌다.**\
`flex-wrap: wrap` 을 켜면 줄이 하나여도 먹는다 — 하지만 세로 가운데가 목적이면 **`align-items: center` 가 정답**이다.

### 3. 「줄이 하나면 `align-content` 가 안 먹는다」로 외운다

실측은 반대였다 — `flex-wrap: wrap` 이면 **줄이 하나여도 먹는다**(y=90). 경계는 **`flex-wrap` 값**이다((5)).

### 4. `gap` 을 고정 간격으로 믿는다

`justify-content: space-*` 와 같이 쓰면 **그 위에 더 벌어진다**((7)). `gap` 은 최소 간격이다.

### 5. 마진으로 간격을 주고 `space-between` 을 쓴다

끝 마진까지 자유 공간에서 빠져 **계산이 어긋나고 끝에 여백이 죽는다**((6)(7)).\
`gap` 이 쓸 수 있는 환경이면 `gap` 을 쓴다.

### 6. `order` 로 읽는 순서를 바꿨다고 생각한다

DOM·`:first-child`·`textContent`·Tab 순서는 **전부 그대로**다((9)).\
「화면 맨 왼쪽 버튼인데 Tab 이 마지막에 간다」는 **버그로 신고되는 종류의 것**이다.

### 7. `order` 를 만졌더니 겹친 요소의 앞뒤가 바뀌었다

`order` 는 **그리는 순서**이기도 하다((10)). 겹치는 배치에서는 `z-index` 로 따로 고정한다.

### 8. `flex-wrap` 없이 「넘치면 알아서 줄바꿈되겠지」라고 기대한다

`nowrap` 이 초기값이고, 항목이 `flex-shrink: 0` 이면 **줄이 안 늘고 그냥 뚫는다**((1)).

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 왜 |
|---|---|---|
| 항목 개수가 유동적인 태그·칩 목록 | `flex-wrap: wrap` + `gap` | 몇 개든 알아서 줄이 는다 |
| 열 수를 정확히 맞춘 카드 그리드 | **Grid**([목록의 **27번 주제**](../27-grid-track-sizing/)) | flex 의 줄은 **줄마다 독립**이라 열이 안 맞는다 |
| 줄 사이 간격 | `row-gap` | 마진은 상쇄도 없고 끝에도 붙는다 |
| 한 줄짜리 세로 가운데 | `align-items: center` | `align-content` 는 `nowrap` 에서 안 먹는다 |
| 여러 줄 덩어리의 세로 배치 | `align-content` | 줄들 자체를 움직인다 |
| 반응형에서 순서만 바꾸기 | `order` — **단, 의미 순서와 같을 때만** | 다르면 접근성이 깨진다 |
| 진짜로 읽는 순서가 바뀌어야 함 | **마크업을 바꾼다** | `order` 는 DOM 을 안 바꾼다 |

판단 규칙 두 줄.

- **열을 맞춰야 하면 flex 가 아니라 grid 다.** flex 의 줄은 서로 모르기 때문에 둘째 줄이 첫 줄과 안 맞는다.
- **`order` 를 쓰기 전에 「Tab 으로 눌러 보면 이상한가」를 물어라.** 이상하면 쓰지 않는다.

## 핵심 문장

- `flex-wrap` 의 초기값은 `nowrap` 이고, 줄바꿈은 **명시적으로 켜는 것**이다. 안 켜면 넘쳐도 줄이 안 는다.
- 줄이 생기면 [25번](../25-flex-shorthand-and-sizing/)의 크기 해결이 **줄마다 따로** 돈다.
- **`align-items` 는 줄 안의 항목, `align-content` 는 줄들 자체**를 배치한다.
- ★ `align-content` 가 적용되는 조건은 **줄 수가 아니라 `flex-wrap` 값**이다 — `wrap` 이면 줄이 하나여도 먹고, `nowrap` 이면 계산값이 남아도 안 먹는다.
- **`gap` 은 항목 사이에만** 들어가고 마진은 **끝에도 붙는다.** 둘 다 자유 공간을 먼저 줄인다.
- **`order` 는 그리는 순서만 바꾼다** — DOM·`:first-child`·`textContent`·Tab 순서는 그대로이고, **겹쳤을 때 누가 위인가는 같이 바뀐다.**

## 용어 풀이

- **flex 줄(flex line)** — 줄바꿈이 켜졌을 때 항목들이 담기는 한 묶음. `nowrap` 이면 정확히 하나다.
- **단일 줄 컨테이너(single-line flex container)** — `flex-wrap: nowrap` 인 컨테이너. **`align-content` 가 적용되지 않는 것은 이 정의 때문**이다.
- **여러 줄 컨테이너(multi-line flex container)** — `flex-wrap` 이 `wrap`/`wrap-reverse` 인 컨테이너. 줄이 실제로 하나여도 여기 속한다.
- **`flex-wrap`** — 줄바꿈 여부와 줄 쌓임 방향. `nowrap`(초기값) / `wrap` / `wrap-reverse`.
- **`align-content`** — 교차축에서 **줄들 자체**를 배치한다.
- **`align-items`** — 교차축에서 **줄 안의 항목 하나하나**를 배치한다.
- **`gap` / `row-gap` / `column-gap`** — 항목 **사이**의 간격. 양 끝에는 안 들어간다.
- **`order`** — 항목의 시각 순서를 바꾸는 정수. 초기값 0. **DOM 순서는 안 바꾼다.**
- **order-modified document order** — `order` 값 오름차순, 같으면 DOM 순서. **레이아웃과 그리기가 이 순서를 쓴다.**
- **순차 포커스 탐색(sequential focus navigation)** — `Tab` 키가 도는 순서. **DOM 순서를 따르고 `order` 를 보지 않는다.**
- **자유 공간(free space)** — 컨테이너 크기 − (항목 크기 합 + `gap` + 마진). 정본은 [25번](../25-flex-shorthand-and-sizing/).

## 더 들어가면

- **`place-content` 는 `align-content` 와 `justify-content` 의 단축**이다. 순서가 **`align` 먼저** — `place-content: center` 하나로 두 축이 가운데가 된다. 다만 `align-content` 부분은 (5)의 조건을 그대로 받는다.
- **`order` 는 정수만 받는다.** *(실측: `order: 1.5` 는 `cssRules` 에서 `{ }` 로 버려졌고, `order: -1` 은 유효하게 담겼다.)* 음수를 쓰면 기본값 0 인 항목들보다 앞에 오므로 **다른 항목을 안 건드리고 하나만 맨 앞으로** 보낼 수 있다.
- **같은 `order` 값끼리는 DOM 순서가 유지된다**(안정 정렬). 그래서 `order: 1` 을 여럿에 줘도 그들 사이 순서는 안 흔들린다.
- **`flex-wrap: wrap` 은 그 자체로 `align-content` 를 켜는 스위치이기도 하다**((5)). 「줄바꿈만 켜려던 것」이 세로 배치를 바꾸는 부작용을 낸다 — `wrap` 을 추가한 뒤 세로가 달라졌다면 이것을 의심한다.
- **줄마다 항목 수가 달라 마지막 줄이 이상해 보이는 문제**는 flex 로는 근본 해결이 안 된다. `flex-grow` 를 끄고 고정 폭을 쓰거나 Grid([목록의 **27번 주제**](../27-grid-track-sizing/))로 옮기는 것이 표준 처방이다.
