# css/syntax/26 — flex 줄바꿈·`gap`·`order` — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **모든 좌표·치수는 Google Chrome 151.0.7922.173 headless 에서 실제로 렌더해 `getBoundingClientRect()` 로 잰 값**이다.\
> 좌표는 별말이 없으면 **컨테이너의 바깥 왼쪽 위 모서리를 원점**으로 한 값이고 단위는 px 다.\
> 8번의 탭 순서는 **CDP 로 실제 `Tab` 키를 넣어** 확인했다 — `Runtime.evaluate` 로 값을 넣는 것은 사용자 조작이 아니기 때문이다.\
> 규칙은 [CSS Flexible Box Layout Level 1](https://drafts.csswg.org/css-flexbox-1/) 과 [CSS Box Alignment Level 3](https://drafts.csswg.org/css-align-3/) 으로 접지했다.

## 정답

### 1. 넘치면 알아서 줄바꿈되는가

**실행 결과** (Chrome 151 headless — 컨테이너 300px, 항목 `flex: 0 0 120px` 셋)

```text
nowrap        컨테이너 300x30   1:(x0,y0) 2:(x120,y0) 3:(x240,y0)
wrap          컨테이너 300x60   1:(x0,y0) 2:(x120,y0) 3:(x0,y30)
wrap-reverse  컨테이너 300x60   1:(x0,y30) 2:(x120,y30) 3:(x0,y0)
```

**한 줄인가 두 줄인가**

- **한 줄이다.** `flex-wrap` 의 초기값이 `nowrap` 이고 줄바꿈은 **명시적으로 켜는 것**이다.

**셋째 항목의 오른쪽 끝**

- **360px.** 300px 컨테이너를 **60px 뚫고 나간다.** `flex-shrink: 0` 이라 줄지도 않는다.

**`flex-wrap: wrap` 을 켜면**

- 첫 줄에 `1`·`2`, 둘째 줄에 `3` 이 놓인다. **컨테이너 높이가 30 → 60 으로** 는다.
- 줄이 갈리는 기준은 [25번](../25-flex-shorthand-and-sizing/)의 basis 다 — **basis 합이 컨테이너를 넘는 순간 새 줄이 시작된다.**

**`wrap-reverse` 가 뒤집는 것**

- **줄 쌓임 방향**이다. 항목 순서는 그대로(`1 2` 가 한 줄, `3` 이 다른 줄)이고 **첫 줄이 아래로** 간다.
- 실측에서 `1`·`2` 의 y 가 30, `3` 의 y 가 0 이었다.

### 2. 줄이 여럿일 때 크기 해결

**자유 공간은 어디서 계산되나**

- **줄마다 따로** 계산된다. [25번](../25-flex-shorthand-and-sizing/)의 ①\~⑥ 계산이 줄 단위로 독립이다.

**마지막 줄에서 생기는 일**

- 마지막 줄에 항목이 적으면 **그 항목들이 줄 전체의 자유 공간을 나눠 먹어 유난히 커진다.**
- `flex-grow` 를 켜 둔 카드 그리드에서 「마지막 한 장만 폭이 두 배」가 되는 것이 이것이다.

**flex 로 열을 못 맞추는 이유**

- **줄끼리 서로를 모르기 때문**이다. 첫 줄이 셋을 담고 둘째 줄이 둘을 담으면, 둘째 줄의 칸은 첫 줄의 칸과 **폭이 맞을 이유가 없다.**
- 열을 맞추려면 Grid([목록의 **27번 주제**](../27-grid-track-sizing/))로 옮긴다 — 거기는 트랙이 **컨테이너 단위로 미리 정해진다.**

### 3. ★ `align-items` 와 `align-content`

**실행 결과** (Chrome 151 headless — 컨테이너 260×200, 항목 넷 높이 20/60/20/40, 두 줄)

```text
선언                                항목별 y (괄호는 높이)
align-content: flex-start          1:0(20)    2:0(60)    3:60(20)   4:60(40)
align-content: center              1:50(20)   2:50(60)   3:110(20)  4:110(40)
align-content: space-between       1:0(20)    2:0(60)    3:160(20)  4:160(40)
align-items: center (content 초기값) 1:45(20)   2:25(60)   3:145(20)  4:135(40)
align-content:center + items:center 1:70(20)   2:50(60)   3:120(20)  4:110(40)
```

**`align-content: center` 만**

- **y = 50 / 50 / 110 / 110.**

**`align-items: center` 만**

- **y = 45 / 25 / 145 / 135.**

**같은 줄의 두 항목의 y 가 같은가 다른가**

- `align-content` 판 — **같다**(50, 50 / 110, 110). **줄이 통째로 움직였다**는 증거다.
- `align-items` 판 — **다르다**(45, 25 / 145, 135). **항목이 줄 안에서 따로 움직였다**는 증거다.
- ★ **이것이 두 속성을 화면에서 가르는 유일하게 확실한 방법**이다. 「간격이 이상하다」는 증상만으로는 못 가른다.

**아무것도 안 줬을 때 줄이 커지는 이유**

- `align-content` 의 초기값 `normal` 이 flex 에서 **`stretch` 처럼 동작**해 줄들이 교차축 자유 공간을 나눠 갖는다.

```text
줄의 자연 높이   줄1 = max(20,60) = 60      줄2 = max(20,40) = 40      합 100
교차축 자유 공간  200 − 100 = 100  ->  줄마다 50 씩 더한다
  줄1 = 110 (y 0~110)      줄2 = 90 (y 110~200)
  그 안에서 align-items: center  ->  (110−20)/2=45 · (110−60)/2=25
                                     110+(90−20)/2=145 · 110+(90−40)/2=135
```

- 위 손계산이 실측값과 맞는다. 「줄 사이가 벌어진 것」이 아니라 **줄 자체가 부푼 것**이다.

### 4. ★★ `align-content` 가 안 먹는 조건

**실행 결과** (Chrome 151 headless — 컨테이너 260×200, 항목 하나 높이 20. 줄은 어느 판이든 하나)

```text
flex-wrap: nowrap + align-content: center                     -> y=0    계산값 center
flex-wrap: wrap   + align-content: center                     -> y=90   계산값 center
flex-wrap: nowrap + align-content: center + items: flex-start -> y=0    계산값 center
flex-wrap: wrap   (선언 없음)                                  -> y=0    계산값 normal
flex-wrap: nowrap (선언 없음)                                  -> y=0    계산값 normal
```

**`.a`(`nowrap`)의 y**

- **0.** 아무 일도 일어나지 않았다.

**`.b`(`wrap`)의 y**

- **90.** (200 − 20) ÷ 2 = 90 — **정확히 세로 가운데다.** 줄이 하나뿐인데도 먹었다.

**가르는 것**

- ★ **`flex-wrap` 값이다.** 줄 수가 아니다.
- 명세는 `nowrap` 컨테이너를 **「단일 줄 flex 컨테이너」** 로 정의하고 **그 경우에만** `align-content` 를 배제한다. `wrap` 이면 줄이 실제로 하나여도 **여러 줄 컨테이너**이므로 적용된다.
- 「줄이 둘 이상일 때만 먹는다」는 흔한 설명은 **실무에서 거의 맞지만 경계가 틀렸다.**

**`getComputedStyle` 로 진단되는가**

- ★★ **안 된다.** 다섯 판 모두 계산값이 **선언한 값 그대로** 남는다(`center` 준 판은 전부 `center`).
- 「담겼나(`cssRules`) → 잡혔나(`querySelectorAll`) → 이겼나(`getComputedStyle`)」 **세 창을 다 통과하고도 결과만 다르다.** `getBoundingClientRect()` 로 재야 안다.

**한 줄에서 세로 가운데를 맞추려면**

- **`align-items: center`** 다. `align-content` 로는 안 된다.

### 5. `gap` 과 마진은 무엇이 다른가

**실행 결과** (Chrome 151 headless — 컨테이너 300px, 항목 셋 `flex: 1 1 0`, `[왼쪽→오른쪽]`)

```text
gap: 20px            [0→87]   [107→193]  [213→300]
margin-right: 20px   [0→80]   [100→180]  [200→280]
margin: 0 10px       [10→90]  [110→190]  [210→290]
```

**`.g` 의 좌표**

- `[0→87] [107→193] [213→300]`. **셋째의 오른쪽 끝이 컨테이너 끝(300)과 정확히 같다.**
- 각 칸의 폭은 (300 − 40) ÷ 3 = 86.67 이고 표시가 87 로 반올림된 것이다.

**`.m` 의 좌표**

- `[0→80] [100→180] [200→280]`. **셋째의 오른쪽 끝은 280 으로 컨테이너 끝과 다르다** — 끝에 20px 가 죽는다.

**`margin: 0 10px` 로 바꾸면**

- `[10→90] [110→190] [210→290]`. **왼쪽 끝에도 10px 가 죽는다.** 양쪽 다 낭비된다.

**flex 항목끼리 마진 상쇄**

- **일어나지 않는다**([18번](../18-margin-collapsing/) §(6)).
- 그래서 `margin: 0 10px` 셋의 사이 간격은 **10 이 아니라 20** 이다(실측: 90 → 110).
- 일반 블록이었다면 세로 마진은 상쇄되지만 **가로 마진은 애초에 상쇄되지 않는다** — flex 에서는 세로도 안 된다.

### 6. `gap` 은 고정 간격인가

**실행 결과** (Chrome 151 headless — 컨테이너 300px, 항목 셋 `flex: 0 0 60px`)

```text
gap: 20px + space-between          [0→60]  [120→180]  [240→300]
margin-right: 20px + space-between [0→60]  [110→170]  [220→280]
```

**좌표와 실제 간격**

- `[0→60] [120→180] [240→300]` — 실제 간격은 **60px** 다(60 → 120).

```text
자유 공간 = 300 − 180(항목) − 40(gap 둘) = 80
space-between 이 80 을 두 자리에 40 씩 더 넣는다  ->  20 + 40 = 60
```

**고정인가 최소인가**

- **최소 간격**이다. `justify-content: space-*` 가 그 위에 더 벌린다.

**마진으로 했다면**

- `[0→60] [110→170] [220→280]` — 간격은 50px 이고 **끝에 20px 가 죽는다.**
- 자유 공간이 300 − 180 − 60(마진 셋) = 60 이라 두 자리에 30 씩 들어가고, 마지막 항목 뒤 마진 20 이 남는다.
- 「`space-between` 인데 끝이 안 맞는다」의 정체가 이것이다.

### 7. 줄바꿈에서의 `gap`

**실행 결과** (Chrome 151 headless — 컨테이너 260px, 항목 110×30 넷, `gap: 10px 20px`)

```text
1:(x0,y0)  2:(x130,y0)  3:(x0,y40)  4:(x130,y40)     컨테이너 높이 70
```

**두 값의 방향**

- `gap: <row-gap> <column-gap>` 순서다.
- `10px` = **`row-gap`** — 교차축 방향, **줄 사이**.
- `20px` = **`column-gap`** — 주축 방향, **항목 사이**.

**네 항목의 좌표**

- x 는 0 과 130 (110 + 20 = 130), y 는 0 과 40 (30 + 10 = 40).

**컨테이너 높이**

- **70px** (30 + 10 + 30).

**줄이 하나일 때 `row-gap`**

- **아무 일도 안 한다.** 줄 사이에만 들어가는 값이라 줄이 하나면 들어갈 자리가 없다.

### 8. ★ `order` 가 바꾸는 것과 안 바꾸는 것

**실행 결과** (Chrome 151 headless — 400px `nav`, DOM 순서 A·B·C, `C` 에만 `order: -1`)

```text
위치            A@x133   B@x267   C@x0
:first-child                      -> A (DOM 첫째)
화면 맨 왼쪽 항목                   -> C
nav.children 순서                  -> A, B, C
querySelectorAll 순서              -> A, B, C
nav.textContent                    -> "ABC"
Tab 키 3회 (CDP Input.dispatchKeyEvent) -> A -> B -> C
```

**화면 왼쪽부터**

- **C · A · B.** `C` 가 x=0 으로 맨 왼쪽이다.

**`a:first-child`**

- **`A`** 다. `:first-child` 는 **DOM 기준**이라 `order` 를 보지 않는다.

**`nav.textContent`**

- **`"ABC"`.** DOM 순서 그대로다.

**`Tab` 키 세 번**

- **A → B → C.** 화면 맨 왼쪽인 `C` 가 **가장 늦게** 온다.
- 순차 포커스 탐색은 DOM 순서를 따르고 `order` 를 보지 않는다.

**`order` 가 실제로 바꾼 것**

- **그려지는 좌표(와 그리는 순서) 하나뿐이다.** 나머지 다섯은 전부 DOM 순서 그대로다.
- 그래서 「화면 맨 왼쪽 버튼인데 Tab 이 마지막에 간다」가 되고, 이것은 **접근성 버그로 신고되는 종류**다.
- 명세도 `order` 를 **시각적 순서 변경 전용**으로 못 박는다. 진짜로 순서가 바뀌어야 하면 **마크업을 바꾼다.**

### 9. `order` 와 겹침

**실행 결과** (Chrome 151 headless — 항목 둘이 40px 겹치게, 겹침 구간 한가운데에서 `document.elementFromPoint()`)

```text
① order 없음                                1:x0-120   2:x80-200   겹침점 맨 위 = 2
② 1 에 order: 1                             1:x80-200  2:x0-120    겹침점 맨 위 = 1
③ 둘 다 position:relative; z-index:0 + ②     1:x80-200  2:x0-120    겹침점 맨 위 = 1
```

**`order` 없을 때 위에 보이는 것**

- **2** 다. 같은 층에서는 **DOM 순서가 뒤인 쪽이 위**에 그려진다.

**`order: 1` 을 첫 항목에 주면**

- **1 이 위가 된다.** DOM 은 첫째인데 **order-modified document order 에서는 마지막**이기 때문이다.

**`z-index: 0` 을 줘도**

- **결과가 같다.** 같은 `z-index` 끼리의 앞뒤는 여전히 order-modified document order 로 정해진다.

**실무 함정**

- 아바타 스택·겹치는 칩처럼 **의도적으로 겹쳐 놓은 배치에서 `order` 를 만지면 앞뒤가 같이 뒤집힌다.**
- 겹침 순서를 유지하려면 `z-index` 로 따로 고정해야 한다. 쌓임 맥락의 정본은 [목록의 **22번 주제**](../22-stacking-context-and-z-index/).

### 10. 유효하지 않은 값

**실행 결과** (Chrome 151 headless — 진단 3창의 첫째 창 `cssRules`)

```text
#g1 { }                <- gap: -10px          (버려짐)
#g2 { gap: 10px; }     <- gap: 10px           (정상)
#g3 { }                <- order: 1.5          (버려짐)
#g4 { order: -1; }     <- order: -1           (정상 — 음수 정수는 유효)
#g5 { }                <- flex-wrap: reverse  (버려짐 — 그런 키워드가 없다)
```

**살아남는 것**

- **`order: -1` 과 `gap: 10px`.** `gap` 은 음수를 안 받고, `order` 는 **정수만** 받으며, `flex-wrap` 에 `reverse` 라는 값은 없다(`wrap-reverse` 다).

**에러를 내는가 / 어떻게 확인하는가**

- **에러도 경고도 없다.** 화면도 콘솔도 말해 주지 않는다.
- 확인은 **`cssRules` 로 규칙 본문을 읽는 것**이다. 버려졌으면 상자가 `{ }` 로 비어 있다.
- `getComputedStyle` 로 보면 초기값(`normal`/`0`)이 돌아와서 **「안 썼나」와 「썼는데 버려졌나」가 구분되지 않는다.**

**`gap` 은 어디에 주는가**

- **컨테이너**에 준다. 항목에 주면 그 항목이 또 다른 flex/grid 컨테이너일 때만 의미가 있다.

### 11. 다른 주제와 잇기

**정렬 값의 뜻**

- [24번](../24-flexbox-axes/)(주축·교차축과 정렬)이 정본이다. `flex-start` 가 왼쪽이 아니라 main-start 라는 것도 거기다.

**항목 크기 해결**

- [25번](../25-flex-shorthand-and-sizing/)(`flex` 단축의 세 값). 이 문서는 그 계산이 **줄마다 따로 돈다**는 것과 `gap` 이 자유 공간을 미리 줄인다는 것만 더한다.

**열을 맞춰야 하면**

- **Grid**(목록의 [**27**](../27-grid-track-sizing/)~[**30**](../30-subgrid/)번 주제). flex 의 줄은 서로를 모르므로 열이 맞을 이유가 없다.

**「누가 위인가」의 정본**

- [목록의 **22번 주제**](../22-stacking-context-and-z-index/)(쌓임 맥락과 `z-index`).

**`place-content`**

- **`align-content` + `justify-content`** 의 단축이고 **`align` 이 먼저**다.
- `place-content: center` 한 줄로 두 축 가운데가 되지만, `align-content` 부분은 **4번의 조건을 그대로 받는다** — `nowrap` 이면 그 절반이 무시된다.

|---|---|---|---|

| 두 방향 `gap` 과 줄바꿈 | 항목 넷 | 1 | 7번 표 |

**구현에 의존하는 항목** — 86.67 같은 나눗셈 잔차의 표시(87)는 실제값 단계의 반올림이다.
**엔진은 Chrome 하나다** — Firefox 는 이 환경에서 headless 스크린샷이 산출되지 않아 엔진 차이를 주장하지 않았다.
**★ 한 자리를 정정했다** — [24번](../24-flexbox-axes/) 이 「`align-content` 는 줄이 둘 이상일 때만 의미가 있다」고 적은 자리의 정확한 경계는 **`flex-wrap` 값**이다(4번). 실무 결론은 거의 같지만 `wrap` + 한 줄 판이 반례다.

## 이 주제가 답하려는 질문

1. 줄바꿈이 켜지면 무엇이 새로 생기는가 — **줄(line)** 이 생기고, 크기 해결이 줄마다 따로 돌며, `align-content` 가 의미를 갖는다(1\~4번).
2. `gap` 은 마진과 무엇이 다른가 — **사이에만 들어가고 끝에 안 붙는다.** 그리고 `space-*` 위에서 **최소 간격**으로 동작한다(5\~7번).
3. `order` 가 바꾸는 것과 안 바꾸는 것 — **좌표와 그리는 순서만** 바꾸고 DOM·`:first-child`·`textContent`·Tab 순서는 그대로다(8\~9번).

## 구현 세부사항 대 언어 보장

- **명세가 보장하는 것** — `flex-wrap` 세 값의 뜻 · `align-content` 가 단일 줄 컨테이너에서 적용되지 않는 것 · `gap` 이 항목 사이에만 들어가는 것 · `order` 가 order-modified document order 를 만들고 **그것이 레이아웃과 그리기에만 쓰이는 것** · 순차 포커스 탐색이 DOM 순서를 따르는 것(HTML 명세).
- **이 Chrome 의 관찰인 것** — 모든 구체 좌표 · 반올림 표시 · 버려진 선언이 `cssRules` 에서 빈 상자로 보이는 표현 형식 · Tab 이 실제로 A→B→C 로 간 한 판의 결과.
- **관찰을 보장으로 적지 않았다** — 특히 4번은 **계산값이 같은데 결과가 갈리는** 자리라 「계산값으로 확인했다」고 쓸 수 없다. 좌표로만 접지했다.

## 용어 풀이

- **flex 줄(flex line)** — 줄바꿈이 켜졌을 때 항목들이 담기는 한 묶음. `nowrap` 이면 정확히 하나다.
- **단일 줄 컨테이너(single-line flex container)** — `flex-wrap: nowrap` 인 컨테이너. `align-content` 가 적용되지 않는다.
- **여러 줄 컨테이너(multi-line flex container)** — `flex-wrap` 이 `wrap`/`wrap-reverse` 인 컨테이너. **줄이 실제로 하나여도** 여기 속한다.
- **`align-content`** — 교차축에서 **줄들 자체**를 배치한다. 초기값 `normal`(flex 에서 `stretch` 처럼).
- **`align-items`** — 교차축에서 **줄 안의 항목 하나하나**를 배치한다.
- **`gap` / `row-gap` / `column-gap`** — 항목 사이의 간격. 양 끝에는 안 들어가고, `space-*` 와 같이 쓰면 **최소 간격**이 된다.
- **`order`** — 항목의 시각 순서를 바꾸는 정수. 초기값 0. 소수는 유효하지 않다.
- **order-modified document order** — `order` 오름차순, 같으면 DOM 순서. **레이아웃과 그리기가 이것을 쓴다.**
- **순차 포커스 탐색(sequential focus navigation)** — `Tab` 키가 도는 순서. DOM 순서를 따르고 `order` 를 **보지 않는다**.
- **자유 공간(free space)** — 컨테이너 크기 − (항목 크기 합 + `gap` + 마진). 줄바꿈이 켜지면 **줄마다 따로** 계산된다.
- **진단 3창** — `cssRules`(담겼나) → `querySelectorAll`(잡혔나) → `getComputedStyle`(이겼나). 4번은 **셋을 다 통과하고도 결과가 갈리는** 자리다.
