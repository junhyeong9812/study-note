# css/syntax/18 — 마진 상쇄 — 인접·부모-자식·빈 상자 — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [CSS Box Model Level 3](https://drafts.csswg.org/css-box-3/) (마진 상쇄 규칙의 정본) · [CSS Display Module Level 3](https://drafts.csswg.org/css-display-3/) (서식 문맥이 상쇄를 막는 조건). 열어서 확인한 것만 적었다.
> **실행 검증** — 이 문서의 `demo` 블록 **5개 전부**와 **막는 법 6가지·음수 마진 4조합**을 **Google Chrome 151.0.7922.173** headless 에 실제로 띄워 `getBoundingClientRect()` 로 **두 상자 사이의 간격을 px 로** 재고 스크린샷으로 눈으로 확인했다.\
> ★ **이 주제는 「붙어 보인다」와 「상쇄됐다」가 다른 이야기다.** 본문의 간격은 전부 `rect.bottom` 과 다음 상자의 `rect.top` 을 빼서 얻은 실측값이다.\
> ★ **`body` 의 기본 `margin: 8px` 과 doctype 없는 문서의 쿼크 모드가 이 실험을 오염시킨다** — 모든 측정은 `<!doctype html>` 과 `html, body { margin: 0; padding: 0 }` 래퍼 안에서 했다.\
> **WebKit(Safari)은 이 머신에 없고 Firefox 는 이 환경에서 headless 스크린샷이 산출되지 않는다** — 크로스 브라우저 주장은 하지 않았다.
> **여기서 다루지 않는 것** — **BFC 의 생성 조건 전체와 그 밖의 효과**는 [17번](../17-block-formatting-context/2-summary.md)이 정본이다. `display` 값의 구조는 [16번](../16-display-inner-outer/2-summary.md), `margin` 이 `box-sizing` 밖이라는 것은 [15번](../15-box-model-and-box-sizing/2-summary.md), float 자체의 동작은 목록의 **20번 주제**다. **flex 의 배치 규칙은 [24번](../24-flexbox-axes/2-summary.md)이 정본**이고 여기서는 「항목에는 상쇄가 없다」는 결론만 실측으로 받는다.
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 간격은 실행으로 접지했다.

## 한눈에 — 쉽게 말하면

**마진은 더해지지 않는다. 겹쳐진다.**

비유 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 「내 주위 1m 는 비워 주세요」라는 개인 공간 요구 | **마진** |
| 두 사람이 각자 1m 를 요구했는데 **둘 사이가 2m 가 아니라 1m** 인 것 | **인접 형제 상쇄** — 큰 쪽 하나만 남는다 |
| 어린아이의 요구가 **부모 등 뒤로 새어 나가** 부모가 대신 물러서는 것 | **부모-자식 상쇄** |
| 두께가 0 인 사람의 앞뒤 요구가 **자기 안에서 겹치는** 것 | **빈 상자의 자기 상쇄** |
| 방음벽을 세워 요구가 밖으로 못 나가게 하는 것 | **BFC** ([17번](../17-block-formatting-context/2-summary.md)) |

- **마진은 「거리」의 요구이지 「두께」가 아니다.** 요구가 겹치면 **큰 쪽 하나를 들어주면 둘 다 만족**한다.
- 그래서 `margin-bottom: 20px` 인 상자 아래에 `margin-top: 20px` 인 상자를 놓으면 **간격이 40 이 아니라 20** 이다.\
  *(Chrome 151 headless 실측: 두 상자 사이 간격 **20px**.)*
- ★ **패딩은 두께다.** 그래서 **패딩은 절대 상쇄되지 않는다.** 이것이 "여백을 패딩으로 주면 예상대로 된다"의 이유다.

```text
   마진 = 거리 요구 (겹칠 수 있다)          패딩 = 두께 (겹칠 수 없다)
  +---------+                              +---------+
  |    A    |                              |    A    |
  +---------+ mb 20 ┐                      +---------+ pb 20
              ├ 겹쳐서 20                   +---------+ pt 20  -> 합쳐서 40
  +---------+ mt 20 ┘                      |    B    |
  |    B    |                              +---------+
  +---------+
```

실무에서 이게 터지는 자리는 **「카드에 배경을 줬더니 위쪽 제목 마진이 카드 밖으로 튀어나가는」** 순간이다.\
자식의 위 마진이 부모의 위 마진과 합쳐져 **부모 자신이 밀린다.** 해법은 [17번](../17-block-formatting-context/2-summary.md)의 BFC 다.

> **마진 상쇄(margin collapsing)** — 맞닿은 두 세로 마진이 하나로 합쳐져 **큰 쪽 값 하나만 남는 것**.\
> 예: 20 과 30 이 맞닿으면 50 이 아니라 **30** 이 된다.

> **맞닿는다(adjoining)** — 두 마진 사이에 **테두리·패딩·내용·높이·BFC 경계**가 하나도 없는 상태.\
> 예: 부모와 자식 사이에 `padding-top: 1px` 만 있어도 맞닿지 않게 되어 상쇄가 일어나지 않는다.

> **세로 마진만 상쇄된다.** `margin-left`/`margin-right` 는 상쇄되지 않는다 — 옆으로 나란한 상자의 마진은 그냥 더해진다.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. **마진을 20 과 20 줬는데 왜 간격이 20 인가** — 그리고 그것을 어떻게 **재서** 확인하나.
2. 자식의 마진이 **왜 부모 밖으로 나가고**, 무엇으로 막나.
3. **상쇄가 아예 일어나지 않는 자리**는 어디인가.

## 동작 방식

### (1) ① 인접 형제 — 큰 쪽 하나만 남는다

**언제 쓰나** — 목록·문단처럼 형제 상자가 줄줄이 있을 때. 가장 흔한 경우다.

```html demo
<div class="stage">
  <div class="b" style="margin-bottom: 20px">A — margin-bottom: 20px</div>
  <div class="b" style="margin-top: 20px">B — margin-top: 20px</div>
</div>
<style>
  .stage { display: flow-root; width: 300px; background: #fde68a; }
  .b { height: 30px; background: #bfdbfe; font: 13px system-ui; }
</style>
```

> **보이는 것** — 파란 상자 둘 사이에 **노란 띠 한 줄**이 보인다. 그 띠의 두께가 **20px 이지 40px 이 아니다** — 두 상자의 높이가 각각 30px 이므로 눈으로 대 보면 띠가 상자 높이의 3분의 2 정도다. 노란색은 부모(`.stage`)의 배경이 마진 자리에 비쳐 보이는 것이다.\
> **바꿔 볼 것** — `A` 의 `margin-bottom` 을 `40px` 로 → 띠가 **40px** 로 두꺼워진다(큰 쪽이 이긴다) · `B` 의 `margin-top` 을 `0` 으로 → 띠가 여전히 **20px** 이다(A 의 요구만 남는다) · 둘 다 `padding` 으로 바꾸면 → 파란 상자 자체가 두꺼워지고 노란 띠는 **사라진다**

*(Chrome 151 headless 실측 — A 의 `rect.bottom` = 30, B 의 `rect.top` = 50 → **간격 20px**. `20 + 20 = 40` 이 아니다. 같은 실험을 `mb: 40` / `mt: 10` 으로 바꾸니 간격이 **40** 이었다 — 합 50 도 아니고 작은 쪽 10 도 아닌 **큰 쪽**이다.)*

```text
   선언                  간격 (실측)
   mb 20  +  mt 20   ->   20      (합 40 이 아니다)
   mb 40  +  mt 10   ->   40      (큰 쪽)
   mb  0  +  mt  0   ->    0
```

- 규칙은 **`max(위 상자의 아래 마진, 아래 상자의 위 마진)`** 이다.
- 그래서 **「위아래 마진을 둘 다 주는」 습관은 값을 예측하기 어렵게 만든다.** 한쪽(보통 `margin-bottom` 또는 `margin-top`)만 주는 규약이 널리 쓰이는 이유다.

비용 — 없다. 다만 **눈으로는 확인이 안 된다** — 20 과 40 을 화면에서 구분하려면 자를 대야 한다. 그래서 이 주제는 **재는 것**이 본체다.

### (2) ② 부모-자식 — 자식의 마진이 부모 밖으로 새어 나간다

**언제 쓰나** — 부모에 배경이나 테두리를 주는 순간. **가장 당황스러운 자리다.**

```html demo
<div class="ruler"></div>
<div class="p"><div class="c">자식 margin-top: 40px</div></div>
<div class="ruler"></div>
<div class="p" style="display: flow-root"><div class="c">자식 margin-top: 40px</div></div>
<style>
  .ruler { width: 300px; height: 6px; background: #ef4444; }
  .p { width: 300px; background: #fde68a; }
  .c { height: 30px; margin-top: 40px; background: #bfdbfe; font: 13px system-ui; }
</style>
```

> **보이는 것** — 위쪽에서는 빨간 자 아래로 **흰 빈칸 40px** 이 있고 그 다음에 파란 자식이 온다. **부모의 노란 배경이 어디에도 안 보인다** — 부모 상자가 자식과 정확히 같은 자리에 있기 때문이다. 아래쪽(`flow-root`)에서는 같은 자리가 **노란 띠 40px** 로 칠해지고 그 아래에 파란 자식이 온다. **마진이 부모 안으로 들어왔다.**\
> **바꿔 볼 것** — `display: flow-root` 대신 `padding-top: 1px` → 아래쪽과 거의 같아진다(노란 띠가 41px) · `border-top: 1px solid red` → 역시 막힌다 · `overflow: hidden` → 역시 막힌다((4)의 표)

*(Chrome 151 headless 실측 — 보통 부모: 빨간 자 `bottom`=6, 부모 `top`=**46** → 부모가 자보다 **40px 아래**에서 시작한다. 부모 `height`=**30**(자식 높이뿐), 자식 `top`=46 으로 **부모와 완전히 같은 자리**다. `flow-root` 부모: 자 `bottom`=76, 부모 `top`=**82**(간격 **0**), 부모 `height`=**70**, 자식 `top`=122.)*

```text
   보통 부모                              display: flow-root
   ===== 기준선 =====                     ===== 기준선 =====
        ↕ 40  (부모 밖 — 흰색)            +------------------+  ← 부모 시작 (간격 0)
   +------------------+ ← 부모 시작       |   ↕ 40 (노란색)  |
   |   [자식 30]      |                  |   [자식 30]      |
   +------------------+ 부모 높이 30      +------------------+  부모 높이 70
```

그림 해설 (한 단계씩):

- 자식의 위 마진과 **부모의 위 마진이 맞닿아** 하나로 합쳐진다. 부모의 위 마진은 0 이므로 `max(0, 40) = 40`.
- 그 40 은 이제 **부모의 마진**이다 — 그래서 부모 자신이 40px 아래로 밀린다.
- **「샌다」는 비유이고, 실제로는 「부모의 마진이 되었다」** 가 정확하다.
- 아래쪽도 똑같다 — **마지막 자식의 아래 마진**도 부모의 아래 마진과 합쳐져 밖으로 나간다.\
  *(실측: `margin-bottom: 40px` 인 자식만 가진 부모의 높이가 **20**(자식 높이뿐)이고 그 아래 기준선까지의 간격이 **40** 이었다.)*

### (3) ③ 빈 상자 — 자기 위아래 마진이 자기 안에서 겹친다

**언제 쓰나** — 조건부로 비는 컴포넌트, 구분선용 빈 `<div>`.

```html demo
<div class="stage">
  <div class="b">위</div>
  <div class="empty"></div>
  <div class="b">아래</div>
</div>
<div class="stage">
  <div class="b">위</div>
  <div class="empty" style="height: 1px"></div>
  <div class="b">아래</div>
</div>
<style>
  .stage { display: flow-root; width: 300px; background: #fde68a; margin-bottom: 20px; }
  .b { height: 30px; background: #bfdbfe; font: 13px system-ui; }
  .empty { margin: 30px 0; background: #ef4444; }
</style>
```

> **보이는 것** — 위쪽 묶음에서는 파란 상자 둘 사이에 **노란 띠 하나(30px)** 만 있고 **붉은 선이 아예 안 보인다.** 아래쪽 묶음에서는 노란 띠가 **두 배로 두꺼워지고 그 한가운데에 얇은 붉은 선**이 보인다. 두 묶음의 차이는 빈 상자에 `height: 1px` 을 줬는지뿐이다.\
> **바꿔 볼 것** — `height: 1px` 대신 `padding-top: 1px` → 아래쪽과 같아진다 · `border-top: 1px solid red` → 역시 같아진다 · 빈 상자의 `margin` 을 `50px 0` 으로 → 위쪽 묶음의 띠가 **50px** 이 된다(자기 위아래 마진끼리도 큰 쪽이 이긴다)

*(Chrome 151 headless 실측 — 위쪽: 「위」 `bottom`=30, 「아래」 `top`=**60** → **간격 30px**. 빈 상자의 `rect.height` 는 **0** 이고 위아래 마진 30+30 이 자기 안에서 겹친 뒤 양옆 형제와도 겹쳤다. 아래쪽(`height: 1px`): 「위」 `bottom`=140, 빈 상자 `top`=170(간격 30), 빈 상자 `bottom`=171, 「아래」 `top`=**201**(간격 30) → **총 61px**.)*

```text
   빈 상자 (height 없음)                 빈 상자 (height: 1px)
   [ 위 30 ]                            [ 위 30 ]
       ↕ 30                                 ↕ 30
   (빈 상자: 높이 0)                     [ 빨간 선 1 ]
       ↕ (같은 30 안에 포함)                 ↕ 30
   [ 아래 30 ]                           [ 아래 30 ]
   총 간격 30                            총 간격 61
```

- 빈 상자는 **자기 위 마진과 아래 마진 사이를 가로막는 것이 없어** 둘이 먼저 자기 안에서 합쳐진다(자기 상쇄).
- 그러고 나면 그 하나가 **위 형제·아래 형제의 마진과도 다시 합쳐진다** — 셋이 한 덩어리가 된다.
- **막는 법은 「가로막을 것을 하나 넣는 것」** 이다 — `height`·`min-height`·`padding`·`border` 중 **1px 이면 충분하다.**

### (4) 막는 법 — 무엇이 상쇄를 끊나

**언제 쓰나** — ②를 고쳐야 할 때. **다섯 가지를 각각 실측으로 확인했다.**

*(Chrome 151 headless 실측 — 기준선 바로 아래 부모를 놓고 부모의 `top` 과 `height` 를 쟀다. 자식은 `height: 30px; margin-top: 40px`.)*

| 부모에 준 것 | 기준선과 부모의 간격 | 부모 높이 | 상쇄가 막혔나 | 대가 |
|---|---|---|---|---|
| (아무것도 안 줌) | **40** | 30 | ✗ | — |
| `padding-top: 1px` | **0** | 71 | **✓** | 1px 이 더해진다 |
| `border-top: 1px solid` | **0** | 71 | **✓** | 선이 보인다 |
| `display: flow-root` | **0** | 70 | **✓** | **없다** |
| `overflow: hidden` | **0** | 70 | **✓** | 넘치는 것이 잘린다([17번](../17-block-formatting-context/2-summary.md)) |
| `height`/`min-height` 고정 | **40** | (지정값) | **✗ — 위쪽은 안 막힌다** | 아래쪽만 막힌다 |

- **`padding` 이나 `border` 는 1px 이면 충분하다** — 「맞닿음」이 깨지기만 하면 되기 때문이다. 대신 그 1px 이 실제 치수에 더해진다.
- ★ **`height` 고정은 위쪽 상쇄를 막지 못한다.** 실측에서 `height: 60px` 인 부모도 자식의 40px 마진이 밖으로 나갔다.\
  대신 **아래쪽**은 막는다 — 자식의 아래 마진과 부모의 아래 경계 사이에 높이가 가로막기 때문이다.\
  *(실측: `margin-bottom: 40px` 인 자식 + `height: 20px` 인 부모 → 부모 아래 간격 **0**.)*
- ★ **`display: flow-root` 가 답이다** — 치수를 1px 도 안 바꾸고, 자르지도 않는다. 이유와 다른 조건들은 [17번](../17-block-formatting-context/2-summary.md)이 정본이다.

### (5) 음수 마진이 섞이면 규칙이 달라진다

**언제 쓰나** — 겹쳐 놓는 레이아웃, 「한 칸만 위로 올리기」.

```html demo
<div class="stage">
  <div class="b p">P — margin-bottom: 20px</div>
  <div class="b q">Q — margin-top: -40px</div>
</div>
<style>
  .stage { display: flow-root; width: 300px; background: #fde68a; }
  .b { height: 40px; font: 13px system-ui; }
  .p { background: #93c5fd; margin-bottom: 20px; }
  .q { background: #fca5a5; margin-top: -40px; width: 200px; }
</style>
```

> **보이는 것** — 분홍 상자 `Q` 가 파란 상자 `P` 의 **아래쪽 절반을 덮는다.** `Q` 는 폭이 200px 이고 무대가 300px 이라 그 오른쪽으로 파란 `P` 가 **100px** 드러나 보이고, `Q` 아래쪽 오른편으로는 노란 배경이 이어진다. **마진을 줬는데 벌어지기는커녕 겹쳤다.**\
> **바꿔 볼 것** — `Q` 의 `-40px` 을 `-10px` 로 → 겹치지 않고 **10px 벌어진다**(20 + (-10)) · `P` 를 `margin-bottom: -30px`, `Q` 를 `margin-top: -10px` 으로 → 양수가 하나도 없어 **30px 겹친다**(합 -40 이 아니라 가장 작은 음수)

*(Chrome 151 headless 실측 — `P.bottom`=40, `Q.top`=**20** → **간격 -20px**(= 20 + (-40)). 다른 조합도 재 보았다: `mb 20` + `mt -10` → 간격 **10** · `mb 20` + `mt -25` → 간격 **-5** · `mb -30` + `mt -10` → 간격 **-30**.)*

```text
   조합                   실측 간격     규칙
   mb  20 + mt -10   ->    10        20 + (-10)
   mb  20 + mt -25   ->    -5        20 + (-25)
   mb  20 + mt -40   ->   -20        20 + (-40)
   mb -30 + mt -10   ->   -30        (양수 없음) + (-30)

   -> 가장 큰 양수 + 가장 작은 음수
```

- 양수끼리는 **큰 쪽 하나**(max)인데, 음수가 섞이면 **가장 큰 양수와 가장 작은 음수를 더한다.**
- 양수가 하나도 없으면 **가장 작은 음수 하나**가 남는다(실측 -30 — 합 -40 이 아니다).
- ★ **음수 간격은 눈으로 「붙어 있다」와 구분이 안 된다.** -5px 짜리 겹침은 화면에서 그냥 맞닿은 것처럼 보인다.\
  **재야만 안다** — 이 주제에서 실측이 가장 필요한 자리다.

### (6) 상쇄가 아예 없는 자리 — flex·grid 항목

**언제 쓰나** — 「왜 여기서는 마진이 예상대로 더해지지?」 할 때.

```html demo
<div class="stage flow">
  <div class="b" style="margin-bottom: 20px">block · mb 20</div>
  <div class="b" style="margin-top: 20px">block · mt 20</div>
</div>
<div class="stage col">
  <div class="b" style="margin-bottom: 20px">flex 항목 · mb 20</div>
  <div class="b" style="margin-top: 20px">flex 항목 · mt 20</div>
</div>
<style>
  .stage { width: 300px; background: #fde68a; margin-bottom: 16px; }
  .flow { display: flow-root; }
  .col { display: flex; flex-direction: column; }
  .b { height: 30px; background: #bfdbfe; font: 13px system-ui; }
</style>
```

> **보이는 것** — 위 묶음의 노란 띠는 **20px**, 아래 묶음의 노란 띠는 **40px** 로 **두 배 두껍다.** 선언은 두 묶음이 한 글자도 다르지 않고 부모의 `display` 만 다르다.\
> **바꿔 볼 것** — `.col` 의 `display: flex` 를 `display: grid` 로 → 아래 묶음이 **그대로 40px** 이다(grid 도 상쇄가 없다) · `flex-direction: column` 을 지우면 두 항목이 가로로 늘어서고 세로 마진 이야기 자체가 사라진다

*(Chrome 151 headless 실측 — 보통 흐름: 간격 **20**. flex 열: 첫 항목 `bottom`=126, 둘째 `top`=166 → 간격 **40**. grid 로 바꾼 판: 간격 **40**.)*

- **마진 상쇄는 블록 서식 문맥(BFC)의 규칙**이다. flex 서식 문맥·grid 서식 문맥에는 **그런 규칙이 아예 없다.**
- 게다가 flex/grid 항목은 **각각 BFC 를 연다**([17번](../17-block-formatting-context/2-summary.md)) — 그래서 **항목 안쪽의 부모-자식 상쇄도 일어나지 않는다.**\
  *(실측: flex 항목 안에 `margin-top: 40px` 인 손자를 넣으니 그 항목의 높이가 **70** 으로 마진을 품었다.)*
- flex 의 축·정렬 자체는 [24번](../24-flexbox-axes/2-summary.md)이 정본이다. 여기서는 **「상쇄가 없다」는 결론만** 받는다.

## 문법 — 형태와 어디서 헷갈리나

### 상쇄가 일어나는 조건

```text
  두 마진이 「맞닿아」 있어야 한다. 사이에 이런 것이 하나도 없어야 한다:
    · 테두리(border)
    · 패딩(padding)
    · 내용(줄 상자)
    · (부모-자식 아래쪽에서는) 부모의 height / min-height
    · BFC 경계
  그리고 둘 다 세로 마진이어야 한다.
```

- **가로 마진은 상쇄되지 않는다.** 옆으로 나란한 두 상자의 `margin-right`·`margin-left` 는 그냥 더해진다.
- **흐름에서 빠진 상자는 상쇄되지 않는다** — `float` 된 상자, `position: absolute` 인 상자.

### 금지에 가까운 형태

```css
.list > li { margin: 20px 0; }        /* 위아래 둘 다 — 간격 예측이 어려워진다 */
.card      { background: #fff; }      /* 자식 마진이 카드 밖으로 샌다 — (2) */
.gap       { margin: 30px 0; }        /* 빈 상자면 자기 안에서 겹친다 — (3) */
```

- 셋 다 **에러가 아니고 경고도 없다.** 그냥 간격이 예상과 다를 뿐이다.
- 권장 형태는 **한쪽 마진만 주기** 또는 **부모에서 `gap`·`padding` 으로 간격 만들기**다 — 둘 다 상쇄가 개입하지 않는다.

## 구현 세부사항 대 언어 보장

- **상쇄 규칙 자체는 명세가 정한다.** CSS Box Model Level 3 의 collapsing margins 규정이 근거다.
- ★ **측정 환경이 결과를 바꾼다.** 이 문서의 실험은 전부 래퍼 안에서 했다.
  - `body` 의 기본 `margin: 8px` 이 **첫 자식의 마진과 상쇄**되어 좌표가 어긋난다.\
    *(실측: `margin-top: 40px` 인 첫 자식의 `rect.top` 이 **40**. `body` 의 8 과 자식의 40 이 상쇄돼 큰 쪽 40 이 남은 것이다. **8 + 40 = 48 이 아니다.**)*
  - **`<!doctype html>` 이 없으면 쿼크 모드가 된다.** *(실측: `document.compatMode` 가 `BackCompat` 이고, 같은 내용의 `body` 높이가 **445** 대 **110** 으로 갈렸다 — 쿼크 모드에서 `body` 가 뷰포트를 채운다.)*
  - ★ **다만 쿼크 모드가 `box-sizing` 을 바꾸지는 않았다** — 전설의 「쿼크 모드 = IE 박스 모델」이 Chrome 151 에서는 **재현되지 않았다**(양쪽 다 `rect.width` 350).
- **간격을 「눈으로」 판정하지 마라.** -5px 겹침과 0px 맞닿음은 화면에서 같아 보인다.

## 어디서 틀리나

### 1. 20 + 20 = 40 이라고 생각한다

실측 간격은 **20** 이다((1)). 마진은 **거리 요구**라 겹칠 수 있다.

### 2. 「붙어 보이니까 상쇄된 것」이라고 판정한다

★ **붙어 보이는 것과 상쇄는 다른 이야기다.**\
음수 마진이 섞이면 **겹쳐 있는데도 그냥 붙어 보인다**((5)). 판정은 `rect.bottom` 과 다음 상자의 `rect.top` 을 빼서 한다.

### 3. 부모에 `height` 를 주면 막힐 거라고 생각한다

**위쪽은 안 막힌다**((4) 실측). 아래쪽만 막힌다. 위아래를 다 막으려면 **BFC** 를 열어야 한다.

### 4. `overflow: hidden` 으로 막는다

막히긴 한다. 하지만 **넘치는 것이 잘린다** — 드롭다운·툴팁이 사라진다([17번](../17-block-formatting-context/2-summary.md)). `display: flow-root` 를 쓴다.

### 5. flex 로 감쌌는데 마진이 「없어졌다」고 생각한다

flex 항목에는 상쇄가 **없다** — 그래서 20+20 이 **40 으로 커진다**((6)). 「없어진」 게 아니라 **줄지 않은** 것이다.

### 6. 빈 상자를 구분선으로 쓴다

높이가 0 이면 **자기 마진이 자기 안에서 겹치고 형제와도 겹쳐** 간격이 예상의 절반이 된다((3)).

## 언제 쓰고 언제 안 쓰나

| 상황 | 권장 | 왜 |
|---|---|---|
| 목록 항목 사이 간격 | 부모에 `gap`(flex/grid) | 상쇄가 아예 개입하지 않는다 |
| 문단 사이 간격 | 한쪽 마진만(`margin-bottom` 등) | 상쇄가 일어나도 값이 그 하나로 정해진다 |
| 카드 안쪽 여백 | 부모의 `padding` | 패딩은 상쇄되지 않는다 |
| 자식 마진이 새는 것만 막기 | 부모에 `display: flow-root` | 치수를 안 바꾸고 안 자른다 |
| 상자를 일부러 겹치기 | 음수 마진 | 다만 **재서** 확인해야 한다 |
| 빈 상자로 간격 만들기 | 쓰지 않는다 | 자기 상쇄로 값이 반토막 난다 |

판단 규칙 두 줄.

- **간격을 확실히 하고 싶으면 상쇄가 없는 수단을 쓴다** — `gap` · `padding` · flex/grid.
- **마진을 쓸 거면 한쪽만 주고, 결과는 재서 확인한다.**

## 핵심 문장

- 마진은 **더해지지 않고 겹쳐진다** — 맞닿은 세로 마진은 **큰 쪽 하나**만 남는다(실측: 20+20 → **20**).
- 세 경우다 — ① **인접 형제** ② **부모-자식**(자식 마진이 부모의 마진이 된다) ③ **빈 상자**(자기 위아래가 자기 안에서 겹친다).
- **막는 것은 「맞닿음을 깨는 것」** 이다 — `padding` 1px · `border` 1px · **BFC**. ★ **`display: flow-root` 만 대가가 없다.**
- ★ **`height` 고정은 위쪽 상쇄를 못 막는다.** 아래쪽만 막는다(실측).
- ★ **음수가 섞이면 규칙이 바뀐다** — **가장 큰 양수 + 가장 작은 음수**(실측: 20 과 -25 → **-5**).
- **flex·grid 항목에는 상쇄가 없다** — 상쇄는 블록 서식 문맥의 규칙이기 때문이다(실측: 같은 선언이 20 대 **40**).
- ★ **「붙어 보인다」는 근거가 아니다.** `rect.bottom` 과 다음 상자의 `rect.top` 을 빼서 재야 안다.

## 용어 풀이

- **마진 상쇄(margin collapsing)** — 맞닿은 두 세로 마진이 하나로 합쳐져 큰 쪽만 남는 것.
- **맞닿는다(adjoining)** — 두 마진 사이에 테두리·패딩·내용·높이·BFC 경계가 하나도 없는 상태.
- **인접 형제 상쇄** — 위 상자의 아래 마진과 아래 상자의 위 마진이 합쳐지는 것.
- **부모-자식 상쇄** — 자식의 마진이 부모의 마진과 합쳐져 **부모 자신이 밀리는** 것.
- **자기 상쇄(self-collapsing)** — 높이·패딩·테두리·내용이 없는 빈 상자의 위아래 마진이 자기 안에서 합쳐지는 것.
- **음수 마진 규칙** — 양수와 음수가 섞이면 **가장 큰 양수 + 가장 작은 음수**.
- **BFC(블록 서식 문맥)** — 상쇄를 막는 구역. 정본은 [17번](../17-block-formatting-context/2-summary.md).
- **`display: flow-root`** — 치수를 안 바꾸고 BFC 만 여는 값. 상쇄를 막는 대가 없는 수단.
- **`gap`** — flex/grid 에서 항목 **사이에만** 넣는 간격. 상쇄가 개입하지 않는다.
- **쿼크 모드(quirks mode)** — `<!doctype html>` 이 없을 때 들어가는 호환 모드. `document.compatMode` 가 `BackCompat` 이다.

## 더 들어가면

- **루트 요소(`<html>`)의 마진은 상쇄되지 않는다.** 그래서 `body` 에 마진을 주면 그것이 페이지 가장자리 여백이 된다.\
  반대로 `body` 의 첫 자식 마진은 `body` 의 마진과 상쇄된다 — 실측에서 8 과 40 이 **40** 으로 합쳐졌다.
- **`margin: auto` 는 상쇄와 무관하다.** 가로 가운데 정렬에 쓰는 `auto` 는 **남는 공간을 먹는 계산**이고, 상쇄는 세로 마진의 규칙이다.\
  flex 에서 `margin: auto` 가 하는 일은 [24번](../24-flexbox-axes/2-summary.md)에 있다.
- **논리 속성에서도 상쇄는 「블록 축」의 이야기다.** `writing-mode` 를 바꾸면 상쇄되는 축이 가로로 바뀐다.\
  「세로 마진만 상쇄된다」는 정확히는 **「블록 축 마진만 상쇄된다」** 이다. 정본은 목록의 **32번 주제**.
- **왜 이런 규칙이 있나** — 문서의 문단 사이 간격을 위해서다. 모든 `<p>` 에 위아래 마진을 줘도 **문단 사이가 두 배가 되지 않게** 하려는 것이 원래 의도다.\
  오늘처럼 컴포넌트를 조립하는 방식에서는 그 의도가 오히려 방해가 되어, **`gap` 과 `flow-root` 로 상쇄를 피하는** 쪽이 표준 관행이 됐다.
