> `id()` 가 내놓는 **숫자 자체**는 실행할 때마다 달라진다 — 봐야 할 것은 두 값이 같은지다.

## 정답

### 1. (예측) 쌓인다

**출력**

```text
['사과']
['사과', '배']
['사과', '배', '감']
```

**왜 그런가**

- `def add_item(item, bag=[]):` 를 **실행할 때** 빈 리스트가 하나 만들어져 함수 객체에 붙는다.
- 호출할 때 `bag` 을 생략하면 파이썬은 **그 리스트를 그대로 넘긴다.** 새로 만들지 않는다.
- `append` 는 그 리스트를 제자리에서 고친다 → 다음 호출에 그대로 남는다.

```text
def 실행 직후            1회 호출 후        2회 호출 후        3회 호출 후
   [ ]            ->     ['사과']     ->   ['사과','배'] ->  ['사과','배','감']
   ^ 함수에 꿰매진 주머니 하나. 세 호출이 전부 이 상자를 쓴다
```

**기대와 어긋나는 지점**

읽는 사람은 `bag=[]` 를 "이 인자의 기본은 **빈** 리스트"로 읽는다.\
실제 뜻은 "이 인자의 기본은 **정의할 때 만든 그 리스트**"다.\
처음 한 번만 비어 있고, 그 뒤로는 비어 있지 않다.

### 2. (예측) `id` 는 같다

**출력**

```text
(['사과', '배', '감'],)
133723085001280
(['사과', '배', '감', '귤'],)
133723085001280
```

- 두 `id` 값은 **같다.** (숫자 자체는 실행할 때마다 달라진다.)

**그것이 1번을 어떻게 설명하나**

- `__defaults__` 는 함수 객체에 달린 **기본값 튜플**이다. 위 출력에서 튜플 안에 리스트가 하나 들어 있다.
- 호출 뒤 **내용은 늘었는데 `id` 는 그대로**다.\
  → 새 리스트로 **갈아 끼운 것이 아니라** 같은 리스트를 **고친 것**이다.
- 즉 1번의 누적은 "매번 이전 결과를 이어받는다"가 아니라 **"애초에 상자가 하나다"** 가 원인이다.

```text
   함수 객체 add_item
   +--------------------+          +--------------------------+
   | __defaults__  -----+--------> | ['사과','배','감','귤']  |
   +--------------------+          +--------------------------+
                                      id 가 안 바뀐다 = 같은 상자
```

**여기서 배울 것**

함수의 "기본값"은 **함수 바깥에서 들여다보고 고칠 수 있는 상태**다.\
`add_item.__defaults__[0].clear()` 로 실제로 비울 수도 있다.\
「기본값」이라는 이름과 달리 사실상 **전역 변수 하나**를 함수에 달아 둔 것이다.

### 3. (예측) `side()` 는 한 번, `def` 문 실행 중에

**출력**

```text
def 문 실행 전
   side() 실행됨
def 문 실행 끝
[1]
[1, 2]
```

- `side() 실행됨` 은 **한 번**, `def 문 실행 전` 과 `def 문 실행 끝` **사이**에 찍힌다.

**왜 그런가**

파이썬이 `def` 문을 만나면 이 순서로 한다.

```text
  1. 기본값 식을 왼쪽에서 오른쪽으로 지금 평가한다   <- side() 가 여기서 불린다
  2. 함수 객체를 만든다
  3. 평가한 값들을 __defaults__ 로 붙인다
  4. 이름 g 를 그 함수 객체에 바인딩한다
  ★ 함수 몸통은 아직 한 줄도 안 돌았다
```

문서가 그대로 적는다 — "**Default parameter values are evaluated from left to right when the function definition is executed.**"

- `g(1)`, `g(2)` 에서 `side()` 가 **다시 안 찍혔다** → 기본값은 재평가되지 않는다.
- 그래서 `[1]` 다음이 `[1, 2]` 다. 1번과 같은 원인이다.

**여기서 틀리는 자리**

이 성질은 가변성과 무관하게도 문다.

```python
def report(ts=time.time()):   # 프로그램이 시작된 시각이 영원히 박힌다
def new_id(k=uuid4()):        # 모든 호출이 같은 id 를 돌려준다
def conf(c=json.load(open("config.json"))):  # import 시점에 파일을 읽는다
```

전부 "부를 때마다 계산되겠지"라는 오해다.

### 4. (예측) `10` — 값이 박힌 것이지 공유된 것이 아니다

**출력**

```text
10
```

`clamp.__defaults__` 도 `(10,)` 이다.

**가변 기본값 함정과 같은 것**

원인이 같다 — **기본값 식이 `def` 때 한 번 평가된다.**\
`top=LIMIT` 은 "그때의 `LIMIT` 이 가리키던 객체"를 복사해 간다.

**다른 것**

- 가변 기본값은 **같은 객체가 계속 고쳐져서** 값이 **변한다**.
- 이쪽은 정수라 고칠 수 없으므로 값이 **안 변한다.** 대신 **바깥의 새 값을 못 따라간다.**

```text
가변 기본값                          바깥 값 캡처
  [ ] ->['사과'] -> ['사과','배']      10 -> 10 -> 10
  기본값이 계속 변한다                 기본값이 영영 안 변한다
  증상: 호출 사이에 오염              증상: 설정을 바꿔도 안 먹는다
```

**고치는 법**

기본값을 `None` 으로 두고 **호출 시점에** 읽는다.

```python
def clamp(v, top=None):
    if top is None:
        top = LIMIT
    return min(v, top)
```

가변 기본값의 해법과 같은 모양이다 — **계산을 `def` 시점에서 호출 시점으로 옮긴다.**

### 5. (왜) `None` 센티널이 옮긴 것

**한 문장** — **새 리스트를 만드는 일을 `def` 시점에서 호출 시점으로 옮겼다.**

**출력로 확인**

```python
print(add_item_fixed("사과"))
print(add_item_fixed("배"))
print(add_item_fixed.__defaults__)
```

```text
['사과']
['배']
(None,)
```

```text
고장난 형태                              고친 형태
 __defaults__ -> [ ]  (가변, 공유)        __defaults__ -> (None,)  (불변)
 호출은 그 상자를 쓴다                     호출마다 함수 안에서 새 상자를 만든다

  f(1) ->  [1]                              +----+   +----+
  f(2) ->  [1, 2]                      f(1)->| [1]|  | [2]|<-f(2)
           같은 상자                          +----+   +----+
                                           호출마다 자기 상자
```

**왜 `None` 이 안전한가**

- `None` 은 **불변 싱글턴**이다. 공유돼도 고칠 수가 없으니 상할 것이 없다.
- 판정을 **`is None`** 으로 하는 이유는 [02번 주제](../02-is-vs-eq-interning/2-summary.md)에 있다 — 상대의 `__eq__` 가 `== None` 을 뒤집을 수 있지만 `is` 는 못 뒤집는다.
- 문서가 권하는 해법도 같다 — 기본값을 `None` 으로 두고 몸통에서 명시적으로 검사하라.

**`None` 자체가 유효한 값이면**

"인자를 안 줬다"와 "`None` 을 줬다"를 구분해야 하므로 **나만 아는 표식**을 만든다.

```python
MISSING = object()

def setting(key, default=MISSING):
    if default is MISSING:
        return f"{key}: 기본값 없음"
    return f"{key}: {default!r}"

print(setting("a"))
print(setting("a", None))
```

```text
a: 기본값 없음
a: None
```

`object()` 는 속성이 하나도 없는 빈 객체라 **오직 정체로만 구분된다.**\
바깥에서 우연히 같은 것이 들어올 수 없으니 `is` 판정이 언제나 정확하다.\
표준 라이브러리의 `dataclasses.MISSING` 이 같은 물건이다.

### 6. (예측) 인스턴스끼리 상태가 섞인다

**출력**

```text
['a 의 로그']
True
```

**왜 그런가**

- `__init__` 도 그냥 함수다. `lines=[]` 는 **클래스를 정의할 때** 한 번 만들어져 `__init__` 에 붙는다.
- `Logger()` 를 두 번 불러도 **같은 리스트**가 `self.lines` 에 들어간다.
- `a.log(...)` 가 그 리스트를 고치므로 `b.lines` 에도 보인다.
- `a.lines is b.lines` 가 `True` 인 것이 그 증거다 — 상자가 하나다.

```text
   __init__ 의 __defaults__
   +---------------+        +------------------+
   |  ----------- -+------> | ['a 의 로그']    |
   +---------------+        +------------------+
                              ^            ^
                          a.lines      b.lines      서로 남남인데 같은 상자
```

**실무에서 이것이 어떤 모양으로 터지나**

- 사용자 A 의 장바구니에 사용자 B 가 담은 물건이 보인다.
- 요청마다 새로 만드는 줄 알았던 에러 목록이 계속 누적돼 메모리가 샌다.
- 로컬에서는 인스턴스를 하나만 만들어 보니 **재현이 안 된다.**

**고치는 법**

```python
class Logger:
    def __init__(self, lines=None):
        self.lines = [] if lines is None else lines
```

### 7. (경계) `dataclasses` 는 거부한다

**결과**

```text
ValueError: mutable default <class 'list'> for field items is not allowed: use default_factory
```

클래스를 정의하는 순간 — 즉 `@dataclass` 가 적용되는 시점에 — 예외가 난다.\
`dataclasses` 는 이 함정을 **경고가 아니라 에러로 승격**시켰다.

**대안**

```python
from dataclasses import dataclass, field

@dataclass
class CartOK:
    items: list = field(default_factory=list)

c1 = CartOK(); c2 = CartOK()
c1.items.append("사과")
print(c1.items, c2.items)
```

```text
['사과'] []
```

**왜 `None` 센티널과 같은 해법인가**

둘 다 **"값"이 아니라 "값을 만드는 방법"을 등록**한 것이다.

```text
None 센티널                          default_factory
 __defaults__ = (None,)              필드에 "list 를 불러라" 를 등록
 호출 때 몸통에서 [] 를 만든다         __init__ 생성 때 인스턴스마다 list() 를 부른다
        \                             /
         새 객체를 만드는 시점이 "정의할 때" 가 아니라 "쓸 때" 로 옮겨졌다
```

- `default_factory=list` 는 `list` **함수 자체**를 넘긴 것이다. `list()` 라고 부르면 안 된다 — 그러면 다시 빈 리스트 하나를 넘기는 꼴이다.
- `dataclasses` 가 막는 기준은 **해시할 수 없는 기본값**이다(3.12 에서 확인).\
  `list`·`dict`·`set` 은 `__hash__` 가 없어서 걸리고, **`__hash__` 가 살아 있는 내가 만든 가변 클래스는 그냥 통과한다.**

```python
class MyBag:
    def __init__(self): self.xs = []

@dataclass
class A:
    b: MyBag = MyBag()      # 막히지 않는다

a1 = A(); a2 = A()
a1.b.xs.append(1)
print(a2.b.xs, a1.b is a2.b)
```

```text
[1] True
```

  → **`dataclasses` 의 방어는 부분적이다.** 판정은 여전히 내 몫이다.

### 8. (경계) 전부 언어 보장이다

**답** — 이 주제는 **CPython 구현 세부사항이 아니라 언어가 보장하는 동작**이다.

**근거**

| 사실 | 지위 | 근거 |
|---|---|---|
| 기본값 식은 `def` 실행 시점에 왼쪽→오른쪽으로 평가된다 | **언어 보장** | 언어 레퍼런스 8.8 이 평서문으로 규정한다 |
| 그 값이 호출마다 재사용된다 | **언어 보장** | 같은 절이 "the same 'pre-computed' value is used for each call" 로 적는다 |
| 가변 기본값을 고치면 기본값 자체가 바뀐다 | **언어 보장** | 같은 절이 "the default parameter value is in effect modified… generally not what was intended" 로 경고한다 |
| `None` 센티널이 권장 해법 | **문서가 권하는 관용구** | 같은 절이 해법 코드를 싣는다 |
| `dataclasses` 의 `ValueError` | **문서화된 동작**(3.7+) | `dataclasses` 문서 |
| `__defaults__` / `__kwdefaults__` | **언어 보장** | 데이터 모델의 callable types |

**어떻게 구별했나 — 판정 기준**

1. 문서에 **"CPython implementation detail"** 표시나 **"the current implementation"** 같은 한정어가 붙어 있나?\
   → 붙어 있으면 구현 세부다. 기본 인자 절에는 그런 한정어가 **없다.**
2. 문서가 그 동작에 기댄 **권장 코드**를 싣고 있나?\
   → 싣고 있으면 보장이다. 구현 세부에 기대라고 권하지는 않는다.
3. 다른 구현에서 다르면 **같은 프로그램의 결과가 달라지나**?\
   → 기본 인자는 결과가 달라지면 안 된다. 이 동작에 기댄 코드가 정상 코드이기 때문이다.

**02번과의 대조**

```text
02번 — is 와 인터닝                    20번 — 가변 기본 인자
 is 의 정의만 언어 보장                 동작·경고·해법 전부 언어 보장
 "-5~256 캐시" 는 현재 구현             "CPython 이 그렇다" 라는 한정어 없음
 -> "파이썬은 이렇다" 로 쓰면 틀린다      -> "파이썬은 이렇다" 로 써도 된다
```

같은 「조용히 틀리는 자리」라도 **어느 층에 속한 사실인지**가 다르다.\
그 층을 구별하지 못하면, 맞는 관찰을 틀린 문장으로 적게 된다.
