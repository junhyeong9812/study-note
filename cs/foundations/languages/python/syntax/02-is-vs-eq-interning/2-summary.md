> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **이 본문은 원고가 아니라 Claude 작성이다**(문법·API 갈래는 원고 없이 공식 문서로 접지한다).
>
> **기준 소스** — 열어서 확인한 것만.
> - [6.10.3. Identity comparisons](https://docs.python.org/3.12/reference/expressions.html#is-not) — `is` 의 정의
> - [6.10.2. Membership test operations](https://docs.python.org/3.12/reference/expressions.html#membership-test-operations) — `in` 이 `is` 를 먼저 본다는 규정
> - [`id()`](https://docs.python.org/3.12/library/functions.html#id) — 정체의 정의와 CPython 구현 주석
> - [`PyLong_FromLong()`](https://docs.python.org/3.12/c-api/long.html) — 작은 정수 캐시(구현 주석)
> - [`sys.intern()`](https://docs.python.org/3.12/library/sys.html#sys.intern) — 문자열 인터닝
>

> **버전** — `is`/`==` 자체는 Python 3 전체 공통. 리터럴에 `is` 를 쓸 때 나는 `SyntaxWarning` 은 3.8+.
> **구현 대 명세** — 이 주제의 절반은 **CPython 구현 세부사항**이다. 「구현 세부사항 대 언어 보장」 절에서 선을 긋는다.

## 한눈에 — 쉽게 말하면

**이름표와 상자.**

- 파이썬에서 변수는 값을 담은 통이 아니라 **상자에 붙이는 이름표**다.
- `a == b` — **두 상자 안에 든 것이 같은가**.
- `a is b` — **이름표 둘이 같은 상자 하나에 붙어 있는가**.
- 인터닝 — 자주 쓰는 내용물은 파이썬이 상자를 새로 만들지 않고 **이미 있는 상자에 이름표를 하나 더 붙인다.**\
  그래서 "다른 상자일 줄 알았는데 같은 상자"인 일이 생긴다.

```text
a == b 를 묻는다                      a is b 를 묻는다
+---------+     +---------+          +---------+
|  [1,2]  |     |  [1,2]  |          |  [1,2]  |
+---------+     +---------+          +---------+
     ^               ^                 ^     ^
     a               b                 a     b
안의 내용이 같다 -> True            이름표 둘이 한 상자 -> True
```

이 이름표 모델이 **똑같은 구조로** 파이썬의 객체 모델이다.\
상자 = 객체, 이름표 = 변수, 상자의 주소 = `id()`.\
실무에서 이 차이가 드러나는 자리는 딱 하나로 굳어 있다 — **`if x is None:`** 은 `is` 로 쓰고, **값이 같은지**는 `==` 로 쓴다.

> **객체(object)** — 값과 타입을 가진, 메모리에 실제로 놓인 것 하나.\
> 예: `[1, 2]` 를 두 번 쓰면 겉보기가 같아도 메모리에는 리스트 객체가 **둘** 생긴다.

> **정체(identity)** — "메모리에 놓인 그것 자체"를 가리키는 표. `id()` 로 본다.\
> 예: 이름은 바꿔 붙일 수 있어도 상자 자체는 그대로 — 그 상자를 가리키는 번호가 정체다.

> **인터닝(interning)** — 같은 값을 매번 새로 만들지 않고, 이미 만들어 둔 객체 하나를 돌려쓰는 최적화.\
> 예: `-5`~`256` 사이 정수는 CPython 이 프로그램 시작 때 하나씩만 만들어 두고 계속 재사용한다.

## 이 주제가 답하려는 질문

1. **`==` 와 `is` 는 각각 무엇을 묻나** — 「값이 같다」와 「같은 객체다」가 갈리는 자리는 어디인가.
2. **같은 값인데 왜 같은 객체가 되기도 하나** — 인터닝이 어디서 끼어들고, 그것을 **누가** 보장하나.
3. **`is` 로 물어도 되는 것은 무엇인가** — `is None` 은 되는데 `is 257` 은 안 되는 이유.

## 동작 방식

> 이 절이 본문이다. 그림을 먼저 두고 그 그림을 문장으로 읽는다.

### 1. 같은 값, 다른 상자

**언제 쓰나** — 리스트·딕셔너리처럼 매번 새로 만드는 객체를 두 변수에 나눠 담았을 때.

```text
입력 코드                       파이썬이 하는 일
-------------------------      ------------------------------------
a = [1, 2, 3]                  리스트 객체를 새로 만들고 a 를 붙인다
b = [1, 2, 3]                  리스트 객체를 또 새로 만들고 b 를 붙인다

 전 상태 (대입 두 줄이 끝난 뒤)
        +-----------+                +-----------+
   a -> | [1, 2, 3] |           b -> | [1, 2, 3] |
        +-----------+                +-----------+
          상자 #1                       상자 #2

        a == b  ->  안의 내용을 비교  ->  True
        a is b  ->  #1 과 #2 는 다른 상자  ->  False
```

실행 결과:

```python
a = [1, 2, 3]
b = [1, 2, 3]
print(a == b, a is b)      # True False
print(id(a) == id(b))      # False
```

그림 해설.

- `[1, 2, 3]` 이라고 **쓸 때마다** 리스트 객체가 하나씩 새로 만들어진다.\
  그래서 상자가 둘이다.
- `==` 는 상자를 열어 안을 비교하므로 `True`.
- `is` 는 상자 자체가 같은지 보므로 `False`.
- `id(a) == id(b)` 가 `False` 인 것이 `is` 가 `False` 인 것과 같은 말이다.\
  문서상 `is` 의 정의가 그렇다 — "`x is y` 는 x 와 y 가 같은 객체일 때만 참이고, 객체의 정체는 `id()` 로 정해진다".

**비용** — `==` 는 원소를 하나씩 비교하므로 리스트 길이에 비례한다(O(n)).\
`is` 는 주소 하나를 비교할 뿐이라 언제나 O(1)이다.\
**그렇다고 빠른 `is` 로 바꿔 쓰면 안 된다** — 둘은 묻는 질문 자체가 다르다.

### 2. 같은 상자에 이름표 둘

**언제 쓰나** — 변수를 다른 변수에 대입했을 때. 복사가 아니다.

```text
c = a            a 가 가리키던 그 상자에 c 라는 이름표를 하나 더 붙인다

 전 상태                          후 상태 (c.append(4) 실행)
        +-----------+                    +--------------+
   a -> | [1, 2, 3] |               a -> | [1, 2, 3, 4] |
        +-----------+               c -> +--------------+
                                      이름표가 둘, 상자는 하나
```

```python
c = a
print(c == a, c is a)      # True True
c.append(4)
print(a)                   # [1, 2, 3, 4]
```

그림 해설.

- 대입은 **상자를 복사하지 않는다.** 이름표를 하나 더 붙일 뿐이다.
- 그래서 `c` 로 바꾼 것이 `a` 로 보인다.
- 여기서 `is` 는 "이 둘이 같이 움직이는 사이인가"를 묻는 도구가 된다.

**비용** — 대입은 상자 크기와 무관하게 O(1)이다.\
대신 **한쪽에서 바꾼 것이 다른 쪽에 보인다**는 값을 치른다(목록의 [**01**](../01-object-and-name-binding/)·[**03**](../03-mutability-and-copying/)번 주제).

### 3. 인터닝이 끼어드는 자리

**언제 쓰나** — 작은 정수·짧은 문자열을 두 번 만들었을 때. 여기서 `is` 가 **우연히** 참이 된다.

```text
왼쪽: 캐시 안 (-5 ~ 256)              오른쪽: 캐시 밖 (257)
int("100") 을 두 번                   int("257") 을 두 번

  이미 있는 상자를 돌려준다             그때그때 새 상자를 만든다
        +-------+                          +-------+   +-------+
   r -> |  100  | <- s                p -> |  257  |   |  257  | <- q
        +-------+                          +-------+   +-------+
   r is s  ->  True                   p is q  ->  False
   r == s  ->  True                   p == q  ->  True
```

```python
p = int("257"); q = int("257")
print(p == q, p is q)      # True False
r = int("100"); s = int("100")
print(r == s, r is s)      # True True
```

이 머신에서 캐시 경계를 직접 찾아본 결과다.

```python
lo = None
for n in range(-20, 400):
    same = int(str(n)) is int(str(n))
    if same and lo is None:
        lo = n
    if not same and lo is not None:
        print("캐시되는 구간:", lo, "~", n - 1)
        break
# 캐시되는 구간: -5 ~ 256
```

그림 해설.

- 왼쪽은 상자를 **새로 만들지 않았다.** 그래서 `is` 가 참이 됐다.
- 오른쪽은 만들었다. 그래서 거짓이 됐다.
- 두 경우 모두 `==` 는 참이다 — **내용은 언제나 같기 때문이다.**
- 값이 같은지 물으려던 사람이 `is` 를 쓰면, 작은 값으로 시험할 때만 맞고 큰 값에서 틀린다.\
  이것이 이 주제가 「조용히 틀리는 자리」인 이유다.
- `int("257")` 처럼 **런타임에** 만든 것을 쓴 이유가 있다. `p = 257; q = 257` 이라고 소스에 직접 쓰면 컴파일러가 같은 상수 하나를 돌려써서 `is` 가 참이 되기도 한다 — 그러면 캐시 때문인지 컴파일러 때문인지 구분이 안 된다.

**비용** — 인터닝은 메모리와 비교 속도를 아끼는 최적화다.\
대신 **`is` 의 결과가 값에 따라 달라진다**는 혼란을 낳는다.

### 4. 문자열도 같은 일이 일어난다

**언제 쓰나** — 문자열을 `==` 대신 `is` 로 비교했을 때.

```text
소스에 직접 쓴 "hello"                런타임에 이어 붙인 "hello"
h1 = "hello"                          h3 = "".join(["h","e","l","l","o"])
h2 = "hel" + "lo"   <- 컴파일 때 합침

        +---------+                         +---------+   +---------+
   h1 ->| "hello" |<- h2               h1 ->| "hello" |   | "hello" |<- h3
        +---------+                         +---------+   +---------+
   h1 is h2 -> True                    h1 is h3 -> False  (h1 == h3 은 True)
```

```python
h1 = "hello"
h2 = "hel" + "lo"
print(h1 is h2)            # True
h3 = "".join(["h", "e", "l", "l", "o"])
print(h1 == h3, h1 is h3)  # True False
import sys
h4 = sys.intern(h3)
print(h1 is h4)            # True
```

그림 해설.

- `"hel" + "lo"` 는 **컴파일 시점에** 하나의 상수로 접혀서 `"hello"` 와 같은 상자가 된다.
- `"".join([...])` 은 실행 중에 새 문자열을 만들므로 다른 상자다.
- `sys.intern()` 을 거치면 인터닝 표에 등록돼 같은 상자로 합쳐진다.\
  문서상 `sys.intern` 의 목적은 dict 조회에서 **문자열 비교를 포인터 비교로 바꿔** 조금 빠르게 하는 것이다.
- 즉 **같은 `"hello"` 라도 어떻게 만들었느냐에 따라 `is` 의 답이 달라진다.**

**비용** — 인터닝된 문자열은 비교가 빨라진다.\
대신 인터닝 표에 남는 메모리를 쓰고, `is` 의 답을 예측 불가능하게 만든다.

### 5. 반대 방향 — 값은 다른데 정체는 같다

**언제 쓰나** — `float("nan")` 을 다룰 때. 지금까지와 정반대의 어긋남이다.

```text
지금까지                              nan 의 경우
값이 같고 정체는 다르다                정체는 같고 값이 다르다

   a == b  True                       nan == nan  False   <- IEEE 754 규칙
   a is b  False                      nan is nan  True    <- 같은 상자니까
```

```python
nan = float("nan")
print(nan == nan)          # False
print(nan is nan)          # True
box = [nan]
print(nan in box)          # True
print(nan in [float("nan")])  # False
```

그림 해설.

- `nan` 은 "숫자가 아님"을 뜻하는 특수한 실수값으로, **자기 자신과도 같지 않다**고 정해져 있다.
- 그런데 상자는 하나다. 그래서 `is` 는 참이다.
- `nan in box` 가 `True` 인 것은 **`in` 이 `is` 를 먼저 보기 때문이다.**\
  문서가 규정한다 — 리스트·튜플·집합·dict 같은 컨테이너에서 `x in y` 는 `any(x is e or x == e for e in y)` 와 같다.
- 마지막 줄에서 `float("nan")` 은 새 상자라서 `is` 도 거짓, `==` 도 거짓 → `False`.

> **nan (Not a Number)** — 0/0 이나 `float("nan")` 처럼 답이 정의되지 않은 실수 연산의 결과.\
> 예: 평균을 구하다 빈 데이터가 들어오면 나오고, 비교하면 `==` 도 `<` 도 전부 거짓이 된다.

**비용** — `in` 이 `is` 를 먼저 보는 덕에 리스트에서 nan 을 찾을 수는 있다.\
대신 "같은 값인데 못 찾는" 일(`float("nan") in [float("nan")]`)이 생긴다.

### 6. `==` 는 메서드를 부르고 `is` 는 안 부른다

**언제 쓰나** — 직접 만든 클래스, 또는 `==` 를 재정의한 라이브러리 객체를 비교할 때.

```text
x == y 를 평가                        x is y 를 평가
   |                                     |
   +-> x.__eq__(y) 호출                  +-> id(x) 와 id(y) 를 비교
   |     NotImplemented 면                    끝. 사용자 코드는 안 돈다
   +-> y.__eq__(x) 호출
   |     그래도 안 되면
   +-> 정체 비교로 떨어진다
```

```python
class Loud:
    def __eq__(self, other):
        print("   Loud.__eq__ 호출됨")
        return NotImplemented

x = Loud(); y = Loud()
print(x == y)
#    Loud.__eq__ 호출됨
#    Loud.__eq__ 호출됨
# False
print(x is y)              # False   <- 아무것도 안 찍힌다
```

그림 해설.

- `==` 는 **사용자 코드를 실행한다.** 위 출력에서 `__eq__` 가 두 번 찍힌 것은 양쪽에 한 번씩 물어봤다는 뜻이다.
- 양쪽 다 `NotImplemented` 를 돌려주면 파이썬은 마지막 수단으로 정체 비교를 쓴다. 그래서 `False`.
- `is` 는 사용자 코드를 **부르지 않는다.** 그래서 느려질 일도, 예외가 날 일도, 거짓말할 일도 없다.
- 이것이 `x is None` 을 쓰는 진짜 이유다 — 상대가 무엇이든 **`None` 인지 아닌지는 남이 뒤집을 수 없다.**

> **`__eq__`** — `==` 를 만나면 파이썬이 대신 불러 주는 메서드.\
> 예: `datetime` 이나 numpy 배열이 `==` 를 자기 식으로 정의해 두었기 때문에 `==` 의 결과가 bool 이 아닐 수도 있다.

> **`NotImplemented`** — "이 조합은 내가 처리 못 한다"고 파이썬에게 되돌려 주는 특수한 값.\
> 예: `Loud.__eq__` 가 이걸 돌려주자 파이썬이 반대쪽에게 다시 물어봤다.

**비용** — `==` 는 상대 클래스의 구현에 달려 있다. 느릴 수도, 예외를 던질 수도, 언제나 참을 돌려줄 수도 있다.\
`is` 는 그 모든 위험이 없지만, **값을 묻는 데에는 쓸 수 없다.**

## 문법 — 형태와 규칙

```python
a is b          # 정체가 같은가
a is not b      # 정체가 다른가 (not (a is b) 보다 이 형태를 쓴다)
a == b          # 값이 같은가
a != b          # 값이 다른가
id(a)           # a 의 정체를 나타내는 정수
```

규칙은 넷이다.

1. **`is` 는 재정의할 수 없다.** `__eq__` 같은 후크가 없다. 언제나 정체 비교다.
2. **`==` 는 `__eq__` 로 위임된다.** 정의하지 않은 클래스의 기본 `__eq__` 는 정체 비교로 동작한다.\
   문서 표현으로 "동등 비교의 기본 동작은 객체의 정체에 기반한다".
3. **`is not` 은 한 덩어리 연산자다.** `a is not None` 은 `a is (not None)` 이 아니다.
4. **`is` 로 물어도 되는 것은 싱글턴뿐이다** — `None`, `True`, `False`, `Ellipsis`, 그리고 내가 직접 만든 센티널 객체.

> **싱글턴(singleton)** — 프로그램 전체에서 객체가 딱 하나만 존재하도록 보장된 값.\
> 예: `None` 은 아무리 많이 써도 상자가 하나다. 그래서 `is None` 이 항상 맞다.

## 어디서 틀리나

### (1) 값 비교에 `is` 를 썼는데 작은 값에서만 맞는다

```python
p = int("257"); q = int("257")
print(p is q)      # False   <- 같은 값인데 False
```

테스트 데이터가 전부 작은 수면 통과해 버린다. **"테스트 통과" ≠ "맞다"** 의 전형이다.

### (2) 리터럴에 `is` 를 쓰면 경고가 나온다 (3.8+)

```python
v = int("5")
print(v is 5)
```

```text
t02_c.py:2: SyntaxWarning: "is" with 'int' literal. Did you mean "=="?
  print(v is 5)
True
```

- 경고는 **컴파일 시점**에 나오므로 프로그램 출력보다 먼저 찍힌다.
  앞에 붙는 파일 이름은 돌린 파일에 따라 달라진다.
- 그리고 결과는 `True` 다 — 5가 캐시 범위 안이라 **우연히** 맞은 것이다.\
  경고를 무시하면 이 코드는 257에서 조용히 무너진다.

### (3) `== None` 으로 물었다가 남의 `__eq__` 에 속는다

```python
class Weird:
    def __eq__(self, other):
        return True

w = Weird()
print(w == None)   # True    <- None 이 아닌데 True
print(w is None)   # False   <- 이쪽이 사실
```

`== None` 은 상대에게 "너 None 이니?"를 **물어보는** 것이고, `is None` 은 **직접 확인하는** 것이다.

### (4) `id()` 로 확인하려다 재사용에 속는다

```python
print(id([1, 2, 3]) == id([4, 5, 6]))   # True
a = [1, 2, 3]; b = [4, 5, 6]
print(id(a) == id(b))                    # False
```

첫 줄의 리스트는 `id()` 를 부른 직후 아무도 안 가리키므로 곧바로 회수되고, 그 자리를 다음 리스트가 재사용한다.\
문서가 정확히 이것을 적어 두었다 — "**수명이 겹치지 않는 두 객체는 같은 `id()` 값을 가질 수 있다**".\
그래서 정체를 확인할 때는 `id()` 를 비교하지 말고 **`is` 를 쓴다.**

### (5) `True == 1` 에 걸린다

```python
print(True == 1, True is 1)   # True False   (SyntaxWarning 도 같이 난다)
print(1 in [True])            # True
print([1, 2].count(True))     # 1
```

`bool` 은 `int` 의 하위 타입이라 값으로는 `True == 1` 이다.\
정체는 다르다 — 상자가 다르다.\
`in` 과 `count` 는 `==` 를 쓰므로 `True` 와 `1` 을 **같은 것으로 센다.**

### (6) `0.0` 과 `-0.0`

```python
print(0.0 == -0.0, 0.0 is -0.0)   # True False
```

부호는 다르지만 값으로는 같다. 정체는 당연히 다르다.

## 구현 세부사항 대 언어 보장

**이 주제에서 가장 중요한 구분이다 — 틀린 요약은 전부 여기서 나온다.** 세 층으로 가른다.

| 층 | 무엇인가 | 어떻게 확인했나 |
|---|---|---|
| **언어 보장** | 언어·라이브러리 레퍼런스가 정한 것 | 공식 문서 문장을 열어서 인용 |
| **CPython 구현** | 이 구현이 그렇게 하는 것 | 실행으로 확인 |
| **이 판의 관찰** | 3.12.3 에서 그랬을 뿐 | 「관찰」로 명기 |

### 언어 보장

| 사실 | 근거 |
|---|---|
| `x is y` 는 x 와 y 가 같은 객체일 때만 참이다 | 언어 레퍼런스 6.10.3 |
| `==` 의 기본 동작은 정체 기반이고 `__eq__` 로 바꿀 수 있다 | 언어 레퍼런스 6.10.1 |
| 컨테이너의 `x in y` 는 `any(x is e or x == e for e in y)` 와 같다 | 언어 레퍼런스 6.10.2 |
| `id()` 가 돌려주는 정수는 **그 객체의 수명 동안** 유일하고 변하지 않는다 | `id()` — *"guaranteed to be unique and constant for this object during its lifetime"* |
| **수명이 겹치지 않는 두 객체는 같은 `id()` 를 가질 수 있다** | `id()` — *"Two objects with non-overlapping lifetimes may have the same id() value"* |
| `sys.intern()` 을 거친 같은 문자열은 같은 객체다 | `sys.intern()` |
| 파이썬 프로그램에 쓰인 **이름(식별자)** 은 보통 자동으로 인터닝된다 | `sys.intern()` — *"Normally, the names used in Python programs are automatically interned"* |
| `None` 은 싱글턴이다 | 내장 상수 |

★ 언어는 **인터닝을 허용**할 뿐, **어떤 값을 인터닝하라고 정하지 않는다.** 위 표에서 인터닝을 약속하는 줄은 `sys.intern()` 하나뿐이다.

### CPython 구현 세부사항

| 사실 | 어떻게 확인했나 |
|---|---|
| `id()` 가 메모리 주소다 | `id()` 문서의 **"CPython implementation detail: This is the address of the object in memory."** |
| `-5` \~ `256` 정수가 미리 만들어져 재사용된다 | C API 문서가 *"**The current implementation** keeps an array of integer objects for all integers between `-5` and `256`"* 라고 적는다 |
| 한 컴파일 단위 안의 같은 문자열 상수가 하나로 합쳐진다 | 아래 두 기계 ① — 같은 파일에서 `True`, 모듈을 나누면 `False` |
| 식별자 **모양**의 문자열 리터럴이 자동으로 인터닝된다 | 아래 두 기계 ② — `"helloworld"` 는 모듈이 달라도 `True` |
| `"hel" + "lo"` 가 컴파일 시점에 접힌다(상수 접기) | 파일에서 `h1 is h2` 가 `True`(위 「4. 문자열도 같은 일이 일어난다」) |
| 회수된 객체의 자리를 곧바로 재사용한다 | `id([1,2,3]) == id([4,5,6])` 이 `True`(위 「(4) `id()` 로 확인하려다 재사용에 속는다」) |

### ★ 인터닝은 하나가 아니라 두 기계다

「작은 문자열이 인터닝된다」는 **서로 다른 두 기계를 섞은 설명**이다. 둘은 경계가 다르다.

| | ① 한 컴파일 단위 안의 상수 합치기 | ② 식별자 모양 문자열의 자동 인터닝 |
|---|---|---|
| 무엇을 합치나 | **같은 코드 객체 안의 같은 상수** | **식별자로 쓸 수 있는 모양**의 문자열 리터럴 |
| 공백이 있는 `"hello world"` | 합친다 | 안 합친다 |
| 모듈을 나누면 | **안 합쳐진다**(컴파일 단위가 다르다) | **그래도 합쳐진다** |
| 대화형에서 한 줄씩 치면 | **안 합쳐진다**(줄마다 컴파일 단위가 다르다) | **그래도 합쳐진다** |
| 실행 중에 만든 문자열 | 해당 없음 | **해당 없음**(리터럴에만 걸린다) |

두 파일로 갈라 재어 본 것이다.

```python
# m02.py
s_space = "hello world"
s_ident = "helloworld"
```

```python
# main02.py
import m02

a = "hello world"
b = "helloworld"

x = "hello world"
y = "helloworld"

print("같은 파일 안  공백 있는 것:", a is x)
print("같은 파일 안  식별자 모양 :", b is y)
print("모듈이 다를 때  공백 있는 것:", a is m02.s_space)
print("모듈이 다를 때  식별자 모양 :", b is m02.s_ident)
```

```text
같은 파일 안  공백 있는 것: True
같은 파일 안  식별자 모양 : True
모듈이 다를 때  공백 있는 것: False
모듈이 다를 때  식별자 모양 : True
```

대화형에서도 같은 갈림이 보인다 — **줄마다 컴파일 단위가 다르기 때문이다.**

```text
>>> a = "hello world"
>>> b = "hello world"
>>> a is b
False
>>> c = "helloworld"
>>> d = "helloworld"
>>> c is d
True
```

- 공백이 있는 `"hello world"` 는 **한 파일 안에서만** 같은 객체다. 기계 ①이다.
- `"helloworld"` 는 **모듈이 달라도, 대화형에서도** 같은 객체다. 기계 ②다.
- 실행 중에 만든 문자열은 **둘 다 해당이 없다.** `"".join([...])` 이 `h1` 과 다른 객체인 것이 그 확인이다.
- 문서가 약속하는 것은 **이름(식별자)이 인터닝된다**는 것뿐이고, 그것도 *"Normally"* 가 붙어 있다.\
  **리터럴이 식별자 모양이면 같이 인터닝된다**는 것은 문서에 없다 — 컴파일러가 그렇게 할 뿐이다.

형제 주제가 같은 두 기계를 이름 바인딩 쪽에서 재어 두었다 — [01번](../01-object-and-name-binding/2-summary.md)「구현 세부사항 대 언어 보장」.

### 이 판(3.12.3)의 관찰 — 버전이 오르면 다시 찍어야 한다

| 관찰 | 어디가 흔들리나 |
|---|---|
| 캐시 구간이 `-5` \~ `256` 이었다 | **관찰이다.** 문서가 같은 값을 적지만 *"current implementation"* 이라는 한정어가 붙어 있다 |
| `id()` 값이 `133723085001280` 같은 15자리 정수다 | **실행할 때마다 다르다.** 값 자체는 아무 의미가 없다 |
| `SyntaxWarning` 문구가 `"is" with 'int' literal. Did you mean "=="?` 다 | 문구는 판마다 바뀐다. **경고가 난다는 사실**과 **그 문구**는 다른 층이다 |
| `id()` 재사용이 `True` 로 나왔다 | 문서는 「가질 수 **있다**」까지만 보장한다. 이번 판에서 실제로 그랬을 뿐이다 |
| `0.0 is -0.0` 이 `False` 였다 | 부호가 다른 float 리터럴을 합칠지는 컴파일러 사정이다 |

### 그래서 이렇게 적으면 틀린다

- ✗ 「파이썬은 -5부터 256까지의 정수를 캐싱한다」\
  → 「**CPython 의 현재 구현이** 그렇다」가 맞다. 다른 구현(PyPy 등)·다른 버전에서 달라질 수 있고, 문서도 *"current implementation"* 이라고만 말한다.
- ✗ 「같은 문자열은 같은 객체다」\
  → **어떻게 만들었느냐에 달렸다.** 두 기계 중 어느 것에 걸리는지가 답을 바꾼다.
- ✗ 「짧은 문자열은 인터닝된다」\
  → **길이가 기준이 아니다.** 공백 하나가 들어간 `"hello world"` 는 모듈을 나누는 순간 갈라진다. **글자 모양**이 기준이다.
- ✗ 「`id()` 는 메모리 주소다」\
  → `id()` 는 **정체를 나타내는 정수**다. 그것이 주소라는 것은 CPython 구현 세부사항이다.
- ✗ 「`id()` 가 같으면 같은 객체다」\
  → **수명이 안 겹치면 남의 `id()` 를 물려받는다.** 정체를 물으려면 `is` 를 쓴다.

**판정 기준 한 줄**: 어떤 코드가 `is` 의 결과에 기대고 있다면(`None` 류 싱글턴 제외) 그것은 **구현 세부사항에 기댄 코드**다. 같은 프로그램이 PyPy 에서, 또는 다음 CPython 판에서 다르게 돌 수 있다는 뜻이다.

## 언제 쓰고 언제 안 쓰나

| 쓰는 것 | 상황 |
|---|---|
| `is` / `is not` | `None` 판정 — `if x is None:` · `if x is not None:` |
| `is` / `is not` | 내가 만든 센티널 객체 판정 — `if default is MISSING:` ([목록의 **20번 주제**](../20-mutable-default-args/)) |
| `is` / `is not` | "두 이름이 같은 객체를 가리키나"를 **정말로** 물을 때 |
| `==` / `!=` | 그 밖의 전부 — 숫자·문자열·리스트·dict 값 비교 |

**`is` 를 쓰면 안 되는 자리**는 한 문장으로 정리된다.\
**값을 묻고 싶으면 `is` 를 쓰지 않는다.** 답이 맞아도 그것은 우연이다.

## 핵심 문장

- 파이썬의 변수는 값을 담은 통이 아니라 객체에 붙인 이름표다. `==` 는 상자 안을, `is` 는 상자 자체를 묻는다.
- 인터닝은 상자를 아끼려는 최적화이고, 그 부작용으로 **`is` 가 우연히 맞는 구간**이 생긴다. 그 구간 밖에서 코드가 조용히 무너진다.
- `is` 는 사용자 코드를 부르지 않는다. 그래서 `None` 판정처럼 **남이 뒤집을 수 없어야 하는 질문**에만 쓴다.
- `nan` 은 반대 방향의 어긋남이다 — 값은 자기 자신과도 다르고 정체는 같다. `in` 이 `is` 를 먼저 보기 때문에 리스트에서는 찾아진다.
- 이 주제의 절반은 CPython 구현 세부사항이다. 「파이썬은 이렇다」로 적는 순간 틀린 문장이 된다.

## 용어 풀이

- **객체(object)**: 값과 타입을 가지고 메모리에 실제로 놓인 것 하나.\
  파이썬에서는 숫자·문자열·함수·클래스까지 전부 객체다.
- **이름(name) / 바인딩(binding)**: 변수는 객체를 담는 통이 아니라 객체에 붙인 이름표이고, 대입은 그 이름표를 붙이는 일이다.
- **정체(identity)**: "메모리에 놓인 그것 자체". `id()` 로 보고 `is` 로 비교한다.\
  수명이 겹치지 않는 두 객체는 같은 `id()` 를 가질 수 있다.
- **`id()`**: 객체의 정체를 나타내는 정수.\
  수명 동안 유일하고 변하지 않는다는 것만 보장되며, 그 값이 메모리 주소라는 것은 CPython 구현 세부사항이다.
- **인터닝(interning)**: 같은 값을 새로 만들지 않고 이미 있는 객체를 돌려쓰는 최적화.\
  CPython 은 -5~256 정수와 일부 문자열에 적용한다.
- **`sys.intern()`**: 문자열을 인터닝 표에 직접 등록하는 함수.\
  dict 조회에서 문자열 비교를 포인터 비교로 바꿔 조금 빨라진다.
- **상수 접기(constant folding)**: `"hel" + "lo"` 나 `2 * 3` 처럼 컴파일 시점에 계산할 수 있는 식을 미리 계산해 하나의 상수로 만드는 최적화.\
  그래서 소스에 직접 쓴 두 값이 같은 객체가 되기도 한다.
- **`__eq__`**: `==` 를 만나면 파이썬이 대신 불러 주는 메서드.\
  정의하지 않으면 정체 비교로 동작한다.
- **`NotImplemented`**: "이 조합은 내가 처리 못 한다"를 뜻하는 특수한 값.\
  받은 파이썬은 반대쪽 피연산자에게 다시 물어본다.
- **싱글턴(singleton)**: 프로그램 전체에서 객체가 하나만 존재하는 값.\
  `None`·`True`·`False`·`Ellipsis` 가 그렇고, 그래서 `is` 로 비교해도 된다.
- **센티널(sentinel)**: "값이 없음"을 나타내려고 일부러 만든 표식 객체.\
  `None` 자체가 유효한 값일 때 `MISSING = object()` 같은 것을 만들어 `is` 로 판정한다.
- **nan (Not a Number)**: 답이 정의되지 않은 실수 연산의 결과.\
  자기 자신과 `==` 비교해도 거짓이다.
- **구현 세부사항(implementation detail)**: 언어 명세가 보장하지 않고 특정 구현(CPython 등)이 그렇게 만들어 둔 것.\
  버전·구현이 바뀌면 달라질 수 있으므로 코드가 여기에 기대면 안 된다.
- **`SyntaxWarning`**: 문법상 틀리지는 않았지만 의도와 다를 가능성이 큰 코드에 컴파일 시점에 나오는 경고.\
  리터럴에 `is` 를 쓰면 3.8부터 이 경고가 난다.
