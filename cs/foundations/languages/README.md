# foundations/languages — 언어

이 폴더는 언어를 **두 축**으로 다룬다. 축이 다르므로 폴더로 갈라 둔다.

| 축 | 묻는 것 | 어디에 |
|---|---|---|
| **언어 특성** | *어떤 언어를 고를 것인가* — 틀렸을 때 어떻게 틀리는가, 안전을 어느 통화로 지불하는가 | `<언어>/언어-특성/` · 여러 언어를 한 번에 비교하는 것은 이 폴더 바로 아래 |
| **문법·API** | *그 언어로 어떻게 쓰는가* — 문법과 표준 API를 기능 단위로 | `<언어>/syntax/NN-<주제>/` (3파일) |

같은 언어라도 `java/언어-특성/`은 **고를 때** 보는 것이고 `java/syntax/`는 **쓸 때** 보는 것이다.

## 축 ① 언어 특성 — 언어 선택

**은행 원장처럼 정합성이 1순위인 시스템의 언어 선택**을 소재로, 여러 언어를 "성능 순위"가 아니라 "**틀렸을 때 어떻게 틀리는가 · 안전을 어느 통화로 지불하는가 · 어느 층에서 값을 내는가**"로 정리한 노트 묶음이다.

- 원고: 한 은행 시스템의 언어 학습 노트(`jun-bank/docs/study/tech/languages/`)를 **주제(언어)별로 구조 보존해 이관**한 것. 원문 문체 유지, 프로젝트 고유명(특정 시스템·내부 결정 문서 번호·전용 도구 이름)은 일반형으로 바꿨다. 각 파일·절에 `출처:`를 남긴다.
- 상태: `이관(단일 파일)`. 이후 복습 대상으로 승격할 언어는 templates/ 3파일(질문·서머리·정답)로 전환한다.
- 이관일 2026-09-16.

> 다섯 노트가 서로를 상대 경로로 참조하며, 하나를 읽을 때 옆 언어와의 대비가 공짜로 따라오도록 같은 축·같은 대비 그림을 공유한다.\
> `c-cpp-csharp.md`는 **세 언어를 한 파일에서 나란히 비교**하는 문서라 언어 폴더에 넣지 않고 이 자리에 둔다.

## 이 묶음을 관통하는 한 문장

> **언어는 "얼마나 빠른가"가 아니라 "틀렸을 때 어떻게 틀리는가", "그 도메인의 지식이 어디에 쌓여 있는가", "5년 뒤 누가 고치는가"로 갈린다.**\
> 성능은 넷째 축이 아니라 이 셋 안에 흩어져 들어 있는 부분집합이다.

정합성이 1순위인 도메인에서 최악의 실패는 크래시가 아니라 **조용한 실패(silent failure) — 에러 없이 틀린 값을 남기는 것**이다(참고: [`../../ops-patterns/failure-modes/`](../../ops-patterns/failure-modes/)). 그래서 이 노트들이 반복해서 세는 것은 "실패 신호가 뜨는가"이다.

## 언어 비교 ③ — 층별 배치의 논리 (세로)

```text
질문: 이 층의 실패 모드를 무엇이 막는가?
        ↓
돈의 불변식을 타입으로 세워야 하는 층
   → sealed·null 안전·값 타입이 있는 언어 (Kotlin/JVM)
   → 관측 도구·성숙한 스택·조용한 오답 없음이 결정적
        ↓
인터넷 입력받고 호스트를 조작하며 가볍게 상주하는 층
   → 단일 바이너리·밀리초 기동·2KB 고루틴 (Go)
   → 도메인 불변식이 없어 "얕은 표현력"이 비용이 아니다
        ↓
런타임을 못 얹거나 공유 상태를 병렬화하거나 정지가 곧 위반인 층
   → 소유권으로 두 안전 축을 컴파일에 잠그는 언어 (Rust)
   → 단, 대안이 "조금 느린 다른 언어"가 아닐 때만 청구서가 싸 보인다
```

**핵심**: 이 배치는 "어느 언어가 우수한가"의 결론이 아니라 **"각 층의 실패 모드를 무엇이 가장 싸게 막는가"의 함수**다. 같은 시스템 안에서도 층마다 답이 다르다.

## 읽는 순서(권장)

1. [C·C++·C#](c-cpp-csharp.md) — "언어를 고를 때 무엇을 보는가"의 총론. 두 진영(네이티브 / 관리 런타임) 그림이 나머지 넷의 지도다.
2. [Java·JVM](java/언어-특성/README.md) — 관리 런타임의 원형. "결정을 실행 시점까지 미룬다"가 GC·JIT·클래스로더를 한 뿌리로 묶는다.
3. [Go](go/언어-특성/README.md) — 같은 GC 진영의 반대 극(가벼움). "작은 언어"의 장점과 청구서가 같은 결정의 양면임을 본다.
4. [Kotlin](kotlin/언어-특성/README.md) — JVM 위에서 기본값을 뒤집은 언어. "컴파일러가 무엇을 거부하게 만드는가"가 타입 방어선의 실전 배치를 보여 준다.
5. [Rust](rust/언어-특성/README.md) — GC를 거부한 제3의 답. 안전을 "사람의 시간"으로 사는 극단을 보면 앞 넷의 "실행 자원으로 사는" 선택이 상대화된다.

## 이관 규칙 메모

- **원고 문체 유지** — 본문은 원고 문장을 고쳐 쓰되 문체·순서·인용·측정치를 유지했다. Claude가 보탠 것(「한눈에」 비유·「전체 흐름」 그림·용어 풀이·`[Claude 추가]`)은 원고와 분리 표시.
- **일반화** — 특정 은행 시스템 이름, 내부 결정 문서 번호, 전용 도구 이름, 사내 규약 코드는 "은행 원장 시스템 / 한 팀의 규약 / 어떤 릴레이" 같은 일반형으로 바꿨다. 통찰과 수치는 보존.
- **실명 자료 유지** — 표준(ISO C·JVMS·ECMA)·실명 서적(K&R 등)·공개 블로그·논문 인용은 원고 그대로 두고 링크를 살렸다.
- **상호참조** — 다섯 노트가 서로를 가리키고, 컬렉션 밖 자매 주제는 상대 경로로 가리킨다.

## 축 ② 문법·API — 그 언어로 어떻게 쓰는가

`<언어>/syntax/` 아래에 **기능 단위**로 3파일(질문·서머리·정답) 주제를 둔다.
대상 언어 11개: **C · C++ · C# · Go · Java · Kotlin · Rust · SQL · Python · JavaScript · TypeScript**.

공식 문서(언어 명세·표준 라이브러리 레퍼런스)를 **기준 소스로 열어 대조**하고, 설명과 코드 예시는 직접 쓴다.
문서를 통째로 옮기거나 번역하지 않는다 — 고르고 압축해 **인출 가능한 크기로 자르는 것**이 이 자료의 값이다.
실행 가능한 언어는 예시를 **실제로 돌려 출력을 확인**한 채로 싣는다.

각 언어의 주제 목록·우선순위는 `<언어>/syntax/README.md`에 있다.
