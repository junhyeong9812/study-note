## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

### 1. ★ 생김새가 같은 두 줄 (예측)

```rust
// (가)
let s1 = String::from("안녕");
let s2 = s1;
println!("s1 = {s1} / s2 = {s2}");

// (나)
let n1 = 5;
let n2 = n1;
println!("n1 = {n1} / n2 = {n2}");
```

- 둘 중 컴파일되는 것은 어느 쪽인가?
- 안 되는 쪽의 **에러 번호**와 제목 줄은 무엇인가?
- 에러가 대는 **이유 한 구절**은 무엇인가 — 크기 때문인가, 힙 때문인가, 다른 무엇 때문인가?
- `rustc --explain` 은 이 규칙을 한 문장으로 어떻게 말하는가?

### 2. ★ 이동하면 힙은 어떻게 되나 (예측)

```rust
let s1 = String::from("안녕하세요");
let p1 = s1.as_ptr() as usize;          // 힙 버퍼 주소
let s2 = s1;
let p2 = s2.as_ptr() as usize;
let s3 = s2.clone();
let p3 = s3.as_ptr() as usize;
```

- `p1 == p2` 인가? `p2 == p3` 인가?
- `String` 이 스택에서 차지하는 크기는 몇 바이트이고, 그 안에 무엇이 들어 있나?
- 그 프로그램을 **릴리스(`-O`)로 돌리면** 답이 달라지나?
- 주소 실측에서 **근거로 읽어도 되는 칸**과 **읽으면 안 되는 칸**은 각각 무엇인가?

### 3. ★★ 이 프로그램의 출력 순서 (예측)

```rust
struct D(&'static str);
impl Drop for D {
    fn drop(&mut self) { println!("        [해제] {}", self.0); }
}
fn eat(d: D) { println!("    eat 안: {} 를 받았다", d.0); println!("    eat 끝"); }

fn main() {
    { let _a = D("a"); let _b = D("b"); println!("    블록 끝 직전"); }
    let c = D("c"); println!("    drop(c) 호출 직전"); drop(c); println!("    drop(c) 뒤");
    let d = D("d"); println!("    eat(d) 호출 직전"); eat(d); println!("    eat(d) 뒤");
    { let e1 = D("e"); let _e2 = e1; println!("    이동 완료, 블록 끝 직전"); }
}
```

- `[해제] a` 와 `[해제] b` 중 어느 쪽이 먼저 찍히는가?
- `[해제] d` 는 `eat(d) 뒤` 보다 먼저 찍히는가 나중에 찍히는가?
- 마지막 블록에서 `[해제] e` 는 **몇 번** 찍히는가?
- 해제 시점을 알아내는 방법이 왜 이것뿐인가 — 컴파일러는 왜 안 알려 주는가?

### 4. ★ 섀도잉·대입·임시값의 해제 시점 (예측)

```rust
{ let x = D("첫째"); let x = D("둘째"); println!("    블록 끝 직전"); let _ = &x; }
{ let mut y = D("옛값"); println!("    대입 직전"); y = D("새값"); println!("    대입 직후"); let _ = &y; }
{ D("이름없음"); println!("    다음 줄"); }
{ let _ = D("밑줄만"); println!("    let _ 다음 줄"); let _z = D("밑줄이름"); println!("    let _z 다음 줄"); }
```

- 「첫째」는 「둘째」를 만든 **그 줄에서** 해제되는가, 블록 끝에서 해제되는가?
- 「옛값」은 언제 해제되는가?
- `let _ = D("밑줄만");` 과 `let _z = D("밑줄이름");` 의 해제 시점이 다른가?
- 이 차이를 락 가드에 그대로 옮기면 어떻게 되는가 — 컴파일러는 가만히 있는가?

### 5. ★ 함수에 넘긴 값 (예측)

```rust
fn takes(s: String) -> usize { s.len() }

let s = String::from("hello");
let n = takes(s);
println!("{n} / {s}");
```

- 컴파일되는가? 안 되면 에러 번호는 무엇인가?
- 컴파일러가 **함수 선언 쪽을 가리키며** 붙이는 `note` 는 무엇을 말하는가?
- `help:` 가 제안하는 것은 무엇이고, 그 제안에 붙은 **단서**는 무엇인가?
- 소유권을 넘기고도 계속 쓰려면 길이 몇 가지이고, 각각의 대가는 무엇인가?

### 6. ★ 구조체에서 필드 하나만 꺼내면 (예측)

```rust
struct User { name: String, age: u32 }

let u = User { name: String::from("준"), age: 30 };
let name = u.name;
println!("남은 필드 = {}", u.age);
println!("구조체 전체 = {:?}", u);
```

- 세 줄 중 컴파일러가 거부하는 줄은 어느 것인가?
- 에러 메시지의 **꼬리 문구**가 1번·5번과 어떻게 다른가?
- `u.age` 가 되는 이유를 한 문장으로 말할 수 있는가?
- 이 상태를 부르는 이름은 무엇인가?

### 7. `Drop` 을 구현한 타입에서 꺼내면 (경계)

```rust
struct Guard { name: String }
impl Drop for Guard { fn drop(&mut self) { println!("[해제] {}", self.name); } }

let g = Guard { name: String::from("자원") };
let n = g.name;
```

- 6번과 같은 코드인데 결과가 다른가 — 에러 번호는?
- `rustc --explain` 이 대는 **이유**는 무엇인가(소멸자와 무슨 관계인가)?
- 컴파일러가 제안하는 두 가지는 무엇인가?
- 정말로 알맹이를 꺼내야 하면 어느 도구를 쓰고, 그 정본은 목록의 몇 번인가?

### 8. 이동이 일어나는 자리를 전부 짚어라 (경계)

- 아래 일곱 줄 중 **이동이 일어나는 것**은 몇 개인가?\
  `let b = a;` · `consume(a)` · `Wrap { inner: a }` · `v.push(a)` · `(a, 1)` · `match a { Some(d) => .. }` · `move || .. a ..`
- 각각에서 그 값은 **어느 자리에서 해제**되는가?
- 일곱 중 **해제가 다음 줄보다 먼저** 일어나는 것이 둘 있다 — 어느 것이고 왜인가?
- 이동이 나는 자리를 한 문장 규칙으로 말할 수 있는가?

### 9. `for` 와 소유권 (연결)

- `for x in v` 는 `v` 에 무엇을 하는가 — 컴파일러가 말하는 **암묵 호출**의 이름은?
- `for x in v` · `for x in &v` · `for x in &mut v` 에서 `x` 의 타입은 각각 무엇인가?
- `let a = [10, 20, 30];` 를 `for x in a` 로 돌린 뒤 `a` 를 쓸 수 있는가 — `Vec` 과 왜 갈리는가?
- 이 셋을 전수로 다루는 정본은 목록의 몇 번 주제인가?

### 10. 실행되지 않는 갈래와 루프 (경계)

```rust
let cond = std::env::args().count() > 99;   // 항상 거짓이다
let s = String::from("조건부");
if cond { eat(s); }
println!("{s}");
```

- 컴파일되는가? `cond` 가 **절대 참이 안 된다**는 사실이 판정에 영향을 주는가?
- 그 답이 말하는 것은 무엇인가 — 이 검사는 언제 이뤄지는가?
- `for _ in 0..3 { eat(s); }` 의 에러는 **꼬리 문구**가 어떻게 다른가?
- 그런데 **실행 시점**에는 갈래에 따라 해제가 달라진다 — 그것을 무엇이 한다고 부르는가, 그리고 그것은 보장인가 구현인가?

### 11. `clone()` 과 `drop()` (왜)

- `clone()` 은 정확히 무엇을 하는가 — 실측으로 무엇이 근거였나?
- 컴파일러의 `consider cloning the value` 제안에 붙은 조건절은 무엇이고, 왜 조건이 붙어 있나?
- `clone()` 을 쓰면 안 되는 자리 세 가지를 들 수 있는가?
- `drop(s)` 뒤에 `s` 를 쓰면 무슨 에러가 나는가 — 그 에러 번호가 말하는 것은 무엇인가?

- 이 불편함(넘기고 돌려받기)을 푸는 장치는 무엇이고 정본은 목록의 몇 번인가?
- `Copy` 판정과 `Drop` 시점을 전수로 다루는 주제는 몇 번인가?
- 한 소유자 규칙을 **런타임 비용을 내고** 완화하는 도구는 무엇이고 몇 번인가?
