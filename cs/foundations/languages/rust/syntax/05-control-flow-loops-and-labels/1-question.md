# rust/syntax/05 — 제어 흐름: `loop`·`while`·`for`·라벨 — 질문

> 이 주제의 질문은 **예측형 위주**다 — 아는지가 아니라 **컴파일러가 어느 줄에서 무엇을 거부하는지**를 맞힐 수 있는지 묻는다.

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

### 1. ★ 세 반복문을 값 자리에 놓으면 (예측)

```rust
let mut i = 0;
let a: i32 = while i < 3 { i += 1; };
let b: i32 = for _ in 0..3 { };
let c: i32 = loop { break; };
```

- 세 줄 중 컴파일되는 것이 있는가?
- 세 줄의 **에러 번호**는 각각 무엇인가 — 다 같은가?
- 세 메시지 중 **하나에만 붙는 `note`** 가 있다. 어느 줄이고 무슨 내용인가?
- `c` 줄의 `help:` 는 무엇을 하라고 하는가?

### 2. ★ `break` 에 값을 붙이면 (예측)

```rust
let a = while i < 3 { i += 1; break 7; };
let b = for k in 0..3 { break k; };
```

- 컴파일되는가? 안 된다면 **에러 번호**는 무엇인가?
- 메시지의 `^^^` 자리에 적히는 한 줄은 무엇인가?
- `help:` 는 무엇을 고치라고 하는가?
- `rustc --explain` 의 설명은 어느 루프들을 이름으로 지목하는가?

### 3. ★ 순회한 뒤에 원본이 남는가 (예측)

```rust
// (가)
let v = vec![String::from("a"), String::from("b")];
for x in v { println!("{x}"); }
println!("{:?}", v);

// (나)
let a = [10, 20, 30];
for x in a { print!("{x} "); }
println!("| a = {:?}", a);
```

- (가)와 (나) 중 컴파일되는 것은 어느 쪽인가?
- 안 되는 쪽의 **에러 번호**와, 컴파일러가 이름을 대는 **보이지 않는 호출**은 무엇인가?
- 그 `help:` 가 제안하는 수정은 글자 몇 개인가?
- 두 쪽이 갈리는 근거는 `for` 에 있는가, 아니면 다른 데 있는가?

### 4. 순회 형태 셋이 각각 주는 것 (예측)

```rust
let mut v = vec![10, 20, 30];
for x in &v      { let _: () = x; }
for x in &mut v  { let _: () = x; }
for x in v       { let _: () = x; }
```

- 세 `x` 의 타입은 각각 무엇인가 — 컴파일러가 뭐라고 말하는가?
- 둘째 형태로 원소를 고치려면 몸통에 무엇을 써야 하는가?
- 셋 중 순회 뒤에 `v` 를 다시 쓸 수 있는 것은 몇 개인가?
- `v.iter()` 는 이 셋 중 어느 것과 같은가?

### 5. 라벨을 붙이면 무엇이 달라지나 (예측)

```rust
// (1)
for a in 0..3 { for b in 0..3 { if b == 1 { break; } hit.push((a, b)); } }
// (2)
'outer: for a in 0..3 { for b in 0..3 { if a == 1 && b == 1 { break 'outer; } hit2.push((a, b)); } }
// (3)
'search: loop { for a in 1..100 { if a * a > 500 { break 'search a; } } break 0; }
```

- (1)과 (2)의 `hit`·`hit2` 에는 각각 무엇이 들어가는가?
- (3)은 컴파일되는가 — `break 'search a` 가 **`for` 문 안에 있는데도** 값을 낼 수 있는가?
- (3)이 되는 이유와, 라벨을 `for` 에 붙였을 때 거부되는 이유를 **한 기준**으로 묶어 말할 수 있는가?
- `continue 'row` 는 어디로 가는가?

### 6. 루프 밖의 `break` 와 없는 라벨 (예측)

```rust
fn main() {
    break;
    'a: for _ in 0..1 {}
    for _ in 0..1 { break 'nope; }
}
```

- 이 프로그램에서 나는 **에러 두 개**의 번호는 각각 무엇인가?
- **경고 한 개**도 난다 — 린트 이름과 지적 대상은 무엇인가?
- 그 경고는 어떤 상황에서 실제로 유용한가?
- 경고를 에러로 올리는 방법은 무엇인가?

### 7. `break` 가 하나도 없는 `loop` (왜)

- `fn forever() -> i32 { loop {} }` 가 컴파일되는 이유는 무엇인가?
- 같은 `loop {}` 를 `String` 을 기대하는 자리에 두면 어떻게 되는가?
- `loop { break; }` 로 바꾸면 무엇이 달라지는가?
- 이 성질의 **정본은 어느 주제**이고, 이 주제는 어디까지만 다루는가?

### 8. 라벨 있는 블록 (경계)

- `'blk: { ... }` 는 루프가 아닌데 `break` 가 되는가 — 어느 버전부터인가?
- E0571 메시지의 어느 낱말이 이 문법의 존재를 알려 주는가?
- 무엇을 하려 할 때 이 문법이 함수 쪼개기를 대신하는가?
- 라벨 있는 블록에서 `continue` 는 되는가?

### 9. `continue` 에 값을 붙이면 (경계)

- 컴파일되는가? 에러 **번호**가 있는가?
- 번호가 있고 없고가 말해 주는 것은 무엇인가 — E0571 과 무엇이 다른가?
- `continue` 뒤에 올 수 있는 것은 무엇뿐인가?

### 10. ★ 같은 파일, 다른 에디션 (경계)

```rust
let a = [10, 20, 30];
let mut sum = 0;
for x in a.into_iter() { sum += x; }
println!("sum = {sum}");
```

- 2018 에디션과 2021 에디션에서 **출력**이 다른가?
- 2018 에서만 나는 **경고**의 린트 이름은 무엇인가?
- 두 에디션에서 `x` 의 **타입**은 각각 무엇인가 — 어떻게 확인하는가?
- 원소가 `String` 이었다면 무엇이 달라졌겠는가?

### 11. 순회하면서 원본을 바꾸면 (경계)

- `for x in &v { v.push(99); }` 는 컴파일되는가? 에러 번호는?
- 다른 언어에서 이 상황은 보통 **언제** 드러나는가 — Rust 는 언제인가?
- 이 규칙의 정본은 목록의 몇 번 주제인가?

### 12. 다른 주제와 잇기 (연결)

- `while let` 의 정본은 목록의 몇 번 주제인가?
- `iter`/`iter_mut`/`into_iter` 규약 전수를 다루는 주제는 몇 번인가?
- 순회 결과를 **모으는** 관용의 정본은 몇 번인가?
- 배열과 `Vec` 이 갈리는 판정 기준(`Copy`)의 정본은 몇 번인가?
- 이 주제에서 **에러가 아니라 경고로만** 드러나는 자리는 어디였고, 그중 **출력까지 같았던** 것은 무엇이었나?
