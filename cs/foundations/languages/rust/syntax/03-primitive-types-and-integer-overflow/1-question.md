# rust/syntax/03 — 기본 타입·정수 오버플로·`as` 캐스트 — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,
> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.
> 정답까지 봤던 질문은 아래 복습 기록에 "틀림"으로 표시한다.
> 이 주제의 질문은 **예측형 위주**다 — 아는지가 아니라 **출력을 맞힐 수 있는지**를 묻는다.
> ★ **이 주제의 예측은 「디버그와 릴리스 두 답」이다.** 한 답만 적으면 절반만 맞힌 것이다.
> 던져 볼 때도 반드시 둘 다 돌린다 — `rustc --edition 2021 ex.rs -o a && ./a` 와 `rustc --edition 2021 -O ex.rs -o b && ./b`.

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

### 1. ★ 이 프로그램을 두 빌드로 돌리면 (예측)

```rust
fn add(a: u8, b: u8) -> u8 { a + b }

fn main() {
    let x: u8 = 250;
    println!("x = {x}");
    let y = add(x, 10);
    println!("y = {y}");
}
```

- `rustc ex.rs` 로 빌드해 돌리면 무엇이 찍히고 **종료 코드**는 무엇인가?
- `rustc -O ex.rs` 로 빌드해 돌리면?
- 패닉 메시지의 문장은 **문자 그대로** 무엇인가?
- `add` 를 함수로 빼지 않고 `let y = x + 10;` 로 썼으면 무엇이 달라지는가?
- 한 걸음 더 — `let y: u8 = 250 + 10;` 로 썼으면?

### 2. 네 손잡이의 결과를 채워라 (예측)

```rust
let a: u8 = 250;
a.checked_add(10)      // (1)
a.checked_add(3)       // (2)
a.wrapping_add(10)     // (3)
a.saturating_add(10)   // (4)
a.overflowing_add(10)  // (5)
0u8.wrapping_sub(1)    // (6)
0u8.saturating_sub(1)  // (7)
```

- (1)\~(7) 의 값은 각각 무엇이고, **돌려주는 타입**은 각각 무엇인가?
- 이 일곱 개는 디버그와 릴리스에서 **같은가, 다른가**?
- 그 답이 이 네 메서드를 쓰는 **이유**와 어떻게 이어지는가?
- 「넘치면 호출자가 알아야 한다」와 「넘치면 끝값에서 멈춰야 한다」에는 각각 무엇을 고르는가?

### 3. ★ 이 다섯 줄의 출력과 **진단**을 예측하라 (예측)

```rust
let n: i32 = 300;   println!("{}", n as u8);
let m: i32 = -1;    println!("{}", m as u8);
                    println!("{}", m as u32);
let big: i64 = 4_294_967_296;  println!("{}", big as u32);
let c: u8 = 200;    println!("{}", c as i8);
```

- 다섯 줄의 출력은 각각 무엇인가?
- 디버그와 릴리스가 다른가?
- **컴파일 경고는 몇 줄인가** — `-W warnings` 로 최대한 켜면 달라지는가?
- `clippy` 는 잡는가 — 기본 설정에서도 잡는가?

### 4. 부동소수를 정수로 떨구면 (예측)

```rust
tof(3.9) as i32
tof(-3.9) as i32
tof(1e30) as i32
tof(-1e30) as i32
tof(f64::NAN) as i32
tof(f64::INFINITY) as i32
tof(-1.5) as u8
tof(1e30) as u8
// fn tof(x: f64) -> f64 { x }  — 상수 접기를 막으려고 함수로 뺐다
```

- 여덟 개의 값은 각각 무엇인가?
- 3번 질문의 정수→정수 `as` 와 **규칙이 같은가, 다른가**?
- `NaN` 은 무엇이 되는가?
- 이 동작은 **어느 버전부터**인가?

### 5. 나눗셈은 어떤가 (예측)

```rust
fn div(a: i32, b: i32) -> i32 { a / b }
println!("i32::MIN / -1 = {}", div(i32::MIN, -1));
println!("10 / 0 = {}", div(10, 0));
```

- 디버그에서 무슨 일이 일어나는가?
- **릴리스(`-O`)** 에서는?
- `-C overflow-checks=off` 를 붙이면 달라지는가?
- 이 결과가 「릴리스는 감싼다」는 요약을 어떻게 고치게 하는가?

### 6. 크기를 맞혀라 (예측)

```rust
std::mem::size_of::<bool>()
std::mem::size_of::<char>()
std::mem::size_of::<()>()
std::mem::size_of::<(u8, u8)>()
std::mem::size_of::<(u8, u32)>()
std::mem::size_of::<[u8; 4]>()
std::mem::size_of::<&str>()
std::mem::size_of::<usize>()
```

- 여덟 개의 값은 각각 무엇인가?
- `char` 가 그 크기인 이유를 한 문장으로 말할 수 있는가?
- `(u8, u32)` 의 값이 5나 6이 아닌 이유는 무엇인가?
- `&str` 이 그 크기인 이유는 무엇인가?

### 7. 타입을 안 적으면 (경계)

- `let x = 42;` 의 타입은 무엇인가?
- 그것이 **언어 규칙**임을 `type_name` 류에 기대지 않고 증명하려면 무슨 코드를 던지겠는가?
- `'a'` 와 `"a"` 의 타입은 각각 무엇인가?
- `54620u32 as char` 는 컴파일되는가 — 안 된다면 에러 번호와 권하는 대안은?

### 8. 이 두 줄은 어디서 잡히는가 (경계)

```rust
let x: u8 = 300;
let y: u8 = 250 + 10;
```

- 두 줄은 컴파일 타임에 잡히는가, 런타임에 잡히는가?
- 각각의 **린트 이름**과 기본 수준(`warn`/`deny`)은 무엇인가?
- `-O` 를 붙이면 달라지는가?
- 이 사실이 만드는 **착시**는 무엇인가 — 왜 1번 질문에서는 함수 인자로 값을 넘겼는가?

### 9. 릴리스가 감싸는 것은 보장인가 (왜)

- 「디버그는 패닉, 릴리스는 랩어라운드」 중 **언어가 의무로 요구하는 쪽**은 어느 쪽인가?
- 나머지 쪽에 대해 기준 소스는 어떤 낱말을 쓰는가?
- 감쌀 때의 **값**은 보장되는가?
- 오버플로가 난 프로그램은 「정의된 동작」인가 「오류」인가 — 기준 소스의 첫 문장은 무엇인가?

### 10. `usize` 와 플랫폼 (경계)

- 이 머신에서 `size_of::<usize>()` 는 얼마인가?
- 32비트 타깃이라면?
- `s.len() - 1` 을 빈 문자열에 대고 돌리면 디버그와 릴리스에서 각각 무엇이 일어나는가?
- 그때 릴리스가 내놓는 값이 왜 특히 위험한가?

### 11. 다른 주제와 잇기 (연결)

- 좁히는 변환의 안전한 대안은 무엇이며 **무엇을 돌려주는가**?
- 넓히는 변환에는 무엇을 쓰는가, 그쪽은 왜 실패가 없는가?
- `"한".len()` 은 얼마이고, 그 규칙의 정본은 몇 번 주제인가?
- `()` 가 0바이트인 이유를 다루는 주제는 몇 번인가?
- 릴리스 프로필에서 오버플로 검사를 켜려면 `Cargo.toml` 에 무엇을 적는가?
