# sql/41-JSON 타입과 함수 — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,\
> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.\
> 정답까지 봤던 질문은 아래 복습 기록에 "틀림"으로 표시한다.

예시 테이블은 이 폴더의 SQL 주제들이 공유한다. **새로 만드는 표는 없다** — JSON 문서는 **CTE 안에서** 만든다.

```sql
-- 이 파일의 문항 대부분이 이 한 줄을 머리에 달고 있다
WITH j AS (SELECT CAST('{"a":1,"boss":{"name":"ann"},"tags":["x","y"]}' AS jsonb) AS doc)
--                                                                        ^^^^^ MySQL 은 JSON
```

```text
 doc 한 장의 구조
 {
   "a"    : 1                     스칼라
   "boss" : { "name": "ann" }     중첩 객체
   "tags" : [ "x", "y" ]          배열
 }
```

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

### 1. 세 타입에 같은 문자열을 넣으면 (예측)

```sql
CAST('{"b":2,"a":1,"a":9,"tags":["x","y","z"],"boss":{"name":"ann","id":1}}' AS <타입>)
-- PG jsonb · PG json · MySQL JSON
```

- 셋의 출력은 각각 무엇이고, **MySQL 의 `JSON` 은 PG 의 어느 타입에 해당하는가**?

### 2. 키 정렬 기준 (경계)

- `{"b":1,"aa":2}` 를 넣으면 키 순서가 어떻게 되는가? 사전순인가?

### 3. `->` 와 `->>` (예측)

```sql
SELECT doc -> 'boss' AS arrow, pg_typeof(doc -> 'boss') AS arrow_type,
       doc ->> 'boss' AS darrow, pg_typeof(doc ->> 'boss') AS darrow_type FROM j;
```

- 네 칸에 무엇이 나오는가? **보이는 글자로 둘을 구분할 수 있는가**?

### 4. MySQL 에서 `->>` 의 반환 타입 확인하기 (왜)

- MySQL 에는 `pg_typeof` 가 없다. `JSON_TYPE(doc ->> '$.boss.name')` 을 던지면 무엇이 나오고, 그것이 왜 증거가 되는가?

### 5. 배열의 마지막 원소 (경계)

- 두 엔진에서 `tags` 의 **마지막** 원소를 가리키는 문법은 각각 무엇인가?

### 6. 배열을 행으로 펴기 (연결)

- PG 와 MySQL 에서 배열을 행으로 펴는 도구는 각각 무엇이고, **두 엔진에 다 있는 것**은 무엇인가?

### 7. 서로의 경로 문법을 던지면 (예측)

```sql
-- (A) PG 에    : doc -> '$.a'
-- (B) MySQL 에 : doc -> 'a'
```

- 두 질의는 각각 무엇을 돌려주는가? **어느 쪽이 더 위험한가?**

### 8. `#>` 를 MySQL 에 (예측)

- `doc #> '{boss,name}'` 을 MySQL 에 던지면 `Unknown column 'doc'` 이 나온다. **왜 열 이름이 문제가 되는가?**

### 9. 키를 오타 내면 (예측)

- `doc ->> 'salery'`(오타)는 두 엔진에서 각각 무엇을 돌려주는가? 같은 오타를 **열 이름**에 냈을 때와 무엇이 다른가?

### 10. 타입이 틀린 값을 계산하면 (예측)

```sql
-- doc = {"salary":"삼백"}
-- (PG)    SELECT (doc ->> 'salary')::int + 1;
-- (MySQL) SELECT CAST(doc ->> '$.salary' AS SIGNED) + 1;
```

- 두 엔진은 각각 무엇을 돌려주는가? **MySQL 쪽에서 추가로 무엇을 물어봐야 진실이 보이는가?**

### 11. 인덱스가 걸리는 타입 (예측)

- PG 에서 `json` 과 `jsonb` 중 인덱스를 걸 수 있는 것은 무엇이고, 그 사실을 **카탈로그로 어떻게 확인**하는가?

### 12. GIN 이 타는 연산자 (경계)

- `jsonb` 에 GIN 인덱스를 걸면 `doc ->> 'name' = 'ann'` 이 그 인덱스를 타는가?

### 13. MySQL 의 인덱스 전략 (연결)

- MySQL 에서 JSON 안의 값에 인덱스를 거는 방법은 무엇이고, 이 주제에서 그것을 **실행으로 확인했는가**?

### 14. JSON 을 만드는 쪽 (예측)

- `emp`·`dept` 로 `{"dept": ..., "members": [...]}` 를 만드는 함수 이름은 두 엔진에서 각각 무엇인가? 결과는 같은가?

### 15. 쓰면 안 되는 자리 (왜)

- 스키마가 있는 값을 JSON 에 넣으면 **무엇을 잃는가**? 판정 기준을 한 줄로 쓰면?
