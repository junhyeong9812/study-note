# sql/47-인덱스를 언제 타고 언제 안 타나 — 질문

> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.\
> 정답까지 봤던 질문은 아래 복습 기록에 "틀림"으로 표시한다.

대상은 **PostgreSQL 18.6** 과 **MySQL 8.4.10** 두 서버다. 「두 엔진에서」라고 물으면 **각각** 답한다.\
★ **계획은 관찰이지 보장이 아니다.** 「무슨 계획이 나오나」보다 「**왜 그렇게 되나**」를 답한다.

```text
t47 (20,000행) — 이 편이 만들었다가 지운 표
+-----+-------------+------------------------------------------+
| id  | int PK      | 1 .. 20000                               |
| a   | int         | id % 100   -> 100가지, 각 200행 (1%)      |
| b   | int         | id % 10    -> 10가지, 각 2000행 (10%)     |
| k   | int         | = id       -> 저장 순서와 상관계수 1       |
| r   | int         | (id*7919)%20000+1 -> 상관계수 ~0          |
| v   | varchar(30) | 'name000001' .. 'name020000'             |
+-----+-------------+------------------------------------------+

인덱스: t47_pkey(id) · t47_ab_idx(a,b) · t47_k_idx(k) · t47_r_idx(r) · t47_v_idx(v)
측정 조건: ANALYZE 직후 · 기본 설정 · 다른 부하 없음
```

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

### 1. ★ 복합 인덱스의 선행 열 (예측)

```sql
SELECT * FROM t47 WHERE a=7 AND b=7;   -- (a)
SELECT * FROM t47 WHERE a=7;           -- (b)
SELECT * FROM t47 WHERE b=7;           -- (c)
```

- 세 질의가 `t47_ab_idx(a,b)` 를 쓰는가 — 두 엔진에서 각각?

### 2. MySQL 의 `key_len` 이 말해 주는 것 (연결)

- 1번 (a) 와 (b) 의 `key_len` 이 8 과 4 였다 — 이 숫자가 무엇을 뜻하는가?

### 3. ★ (c) 가 안 탄 이유는 선택도인가 (경계)

- `b=7` 은 2,000행(10%)이다. 인덱스를 안 쓴 것이 **행 수 때문인가** — 그것을 어떻게 확인하는가?

### 4. ★ 열에 함수를 씌우면 (예측)

```sql
SELECT * FROM t47 WHERE v = 'name000123';          -- (a)
SELECT * FROM t47 WHERE upper(v) = 'NAME000123';   -- (b)
```

- 두 엔진에서 (a)·(b) 의 계획이 각각 어떻게 되는가?

### 5. 왜 죽는가 (왜)

- 4번 (b) 가 인덱스를 못 쓰는 이유를 **인덱스가 무엇을 정렬해 두었는지**로 설명하면 무엇인가?

### 6. ★ 어떻게 살리나 (예측)

```sql
CREATE INDEX t47_upper_idx ON t47 ((upper(v)));
SELECT * FROM t47 WHERE upper(v) = 'NAME000123';
```

- 두 엔진에서 계획이 어떻게 바뀌는가 — 그리고 **이 문법이 양쪽 다 되는가**?

### 7. ★ 선택도의 경계 (예측)

```sql
SELECT * FROM t47 WHERE r <= 100;
SELECT * FROM t47 WHERE r <= 5000;
SELECT * FROM t47 WHERE r <= 10000;
```

- `N` 을 키우면 계획이 갈리는 지점이 있는가 — 두 엔진에서 각각 **몇 % 쯤**인가?

### 8. ★ 「못 쓴다」와 「안 쓴다」를 어떻게 가르나 (경계)

- MySQL `EXPLAIN` 의 어느 두 칸을 비교하면 이 둘이 구분되는가?

### 9. ★ 같은 50% 인데 계획이 다르다 (예측)

```sql
SELECT * FROM t47 WHERE r <= 10000;   -- (a)
SELECT r FROM t47 WHERE r <= 10000;   -- (b)
```

- 두 엔진에서 (a)·(b) 의 계획이 각각 어떻게 되고, 왜 갈리는가?

### 10. `k` 와 `r` 이 왜 다른가 (왜)

```sql
SELECT * FROM t47 WHERE k <= 10000;   -- 상관계수 1
SELECT * FROM t47 WHERE r <= 10000;   -- 상관계수 ~0
```

- 같은 50% 인데 PG 에서 계획이 갈린다 — 그 이유는 무엇인가?
