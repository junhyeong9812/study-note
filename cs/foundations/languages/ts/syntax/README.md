> 기준일 2026-09-20.

## 이 언어에서 무엇을 자르는 축

TS 는 **JS 문법에 타입 층을 덮고 실행 전에 지우는 언어**다. 그래서 이 목록은 **타입 시스템만** 다룬다 — JS 문법(구조 분해·클래스·모듈·`async`)은 [JS 목록](../../js/syntax/README.md)이 정본이고, 여기서는 필요한 자리에 **`JS n` 형식으로 선행을 건다**.
축은 ①**타입이 언제 사라지는가(소거와 방출)** ②**타입 표기와 할당 가능성(구조적 타이핑)** ③**좁히기 — 제어 흐름이 타입을 바꾸는 규칙** ④**함수 타입과 변성** ⑤**제네릭과 추론 제어** ⑥**타입 조작(`keyof`·조건부·`infer`·매핑·템플릿 리터럴)** ⑦**단언 계열 탈출구(`as`·`!`·`satisfies`)** ⑧**모듈과 선언 파일** ⑨`tsconfig` **에서 판단이 갈리는 플래그**로 자른다.
핸드북의 장 구분(Everyday Types·Narrowing·Type Manipulation·Modules·Reference)을 분류 참고로만 쓰고, 학습 단위는 **한 번에 인출할 규칙 하나**로 잡았다.
`선행` 칸의 숫자는 이 표 안의 번호, `JS n` 은 JS 목록의 번호다.

## 기존 주제와 겹치는 것

- **JS 목록 전체** — TS 목록은 JS 문법을 다시 쓰지 않는다. 필요한 자리마다 `JS n` 선행으로만 건다(#1·#12·#15·#18·#27·#32·#35·#42·#46).
- **`cs/foundations/compiler-pipeline/`** — 어휘 분석·AST·바이트코드 일반론은 그쪽. #2 는 **타입 검사 패스와 방출 패스가 분리돼 있다**는 TS 고유 구조만 다룬다.
- **`history/js/05-빌드-생태계.md`** — 트랜스파일·번들러의 역사. #2·#36 은 그 역사를 되풀이하지 않고 현재 플래그의 의미만 본다.
- `history/ts/` 는 **없다**. TS 버전 이력은 이 목록의 「버전 기준」과 각 행 표기가 대신한다.

## 뺀 것과 이유

- **JS 런타임 문법 전부** — 위 교차 대조대로 JS 목록의 몫이다. 구조 분해·스프레드·클래스 문법 자체·모듈 구문·`async`/`await`·이터러블·옵셔널 체이닝·템플릿 리터럴(값)·정규식·표준 내장 객체 메서드는 이 목록에 행이 없다.
- **JSX/TSX 타입** — 프레임워크 맥락이 붙어야 값이 난다. 프런트엔드 갈래를 만들 때로 미룬다.
- **`@types` 패키지 생태계·DefinitelyTyped 기여 절차** — 언어가 아니라 배포 관행이다.
- **`tsc` 이외 도구(ts-node·tsx·esbuild·SWC·Vite)** — 빌드 생태계 쪽.
- **`tsconfig` 의 모든 플래그 나열** — 판단이 갈리는 것만 #38·#39·#41·#42·#43·#44 에 모았다. 나머지는 TSConfig 레퍼런스를 링크한다.
- **믹스인·트리플 슬래시 지시자·`unique symbol`** — 빈도가 낮다. 필요해지면 #33(선언 병합)·#37(선언 파일)에 붙여 확장한다.

## 버전 기준

**TypeScript 7.0 기준**(2026-09-20 확인 시점 `npm typescript@latest` = **7.0.2**, 안정 릴리스 2026-07-08). 7.0 은 Go 로 다시 쓴 네이티브 포트이며, 타입 시스템 의미는 6.x 계보를 잇되 **기본값과 지원 범위가 크게 바뀌었다** — 이 목록에서 그 변화가 걸리는 행은 #27·#34·#35·#38·#39·#43·#45·#48 이다.

| 버전 | 이 목록에서 해당하는 것 |
|---|---|
| 4.9 | `satisfies` (#29) |
| 5.0 | `const` 타입 매개변수, 표준 데코레이터 구현, `verbatimModuleSyntax` (#21·#47·#36) |
| 5.2 | `using` 선언 지원 — 값 쪽 의미는 JS #51 (#36 방출과 함께 본다) |
| 5.4 | `NoInfer<T>` (#21) |
| 5.5 | 추론된 타입 술어, `isolatedDeclarations` (#13·#44) |
| 5.8 | `erasableSyntaxOnly` (#36) |
| 7.0 | `strict` 기본 `true`, `module` 기본 `esnext`, `types` 기본 `[]`, `rootDir` 기본 `./`, `es5`·`downlevelIteration`·`baseUrl`·`moduleResolution: node10/classic`·AMD/UMD 제거, `namespace` 의 `module` 표기 금지, 템플릿 리터럴 타입의 유니코드 취급 변경, JSDoc 해석 정렬 (#39·#43·#38·#35·#34·#27·#48) |

버전 의존 기능은 **행에 도입 버전을 적는 것을 원칙**으로 한다. 3파일 작성 시 `npx tsc --noEmit` 를 쓸 수 있게 되면, 각 주제의 정답 파일에 **어느 버전의 `tsc` 로 확인했는지**를 남긴다.
