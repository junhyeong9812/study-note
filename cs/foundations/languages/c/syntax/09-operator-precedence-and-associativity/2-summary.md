# c/syntax/09 — 연산자 우선순위와 결합성: 무엇이 먼저 **묶이나** — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [ISO/IEC 9899 공개 작업 초안 — WG14 프로젝트 문서 목록](https://www.open-std.org/jtc1/sc22/wg14/www/projects) · [cppreference — Operator precedence (C)](https://en.cppreference.com/w/c/language/operator_precedence) · [GCC 13 Warning Options](https://gcc.gnu.org/onlinedocs/gcc-13.3.0/gcc/Warning-Options.html)
> **실행 검증** — 이 문서의 모든 출력·경고는 **gcc (Ubuntu 13.3.0-6ubuntu2\~24.04.1) 13.3.0** · x86-64 Linux 에서 실제로 돌려 얻은 것이다.\
> 기본 플래그는 `-std=c17 -Wall -Wextra -pedantic`. **경고는 플래그 조합별로 세었고 종료 코드까지 확인했다.**\
> `clang 18.1.3` 을 쓴 자리는 그 자리에 밝혔다.

> ★★ **경계 — 이 주제는 「무엇이 먼저 **묶이나**」만 다룬다.**\
> 「무엇이 먼저 **도나**」는 [10번 형제](../10-evaluation-order-and-sequence-points/)가 정본이다. **둘은 다른 이야기다**(아래 (6)).\
> 비트 연산자 자체는 [11번 형제](../11-bitwise-operations-and-shifts/), `?:` 가 시퀀스 포인트인 것은 10번이다.

## 한눈에 — 쉽게 말하면

**우선순위는 「누가 누구를 먼저 데려가나」이고, 결합성은 「같은 힘끼리 마주쳤을 때 어느 쪽이 먼저 데려가나」다.**

문장으로 비유하면 이렇다. 「큰 빨간 사과 상자」에서 *큰*이 무엇을 꾸미는지는 **낱말의 힘 순서**가 정한다.\
C 도 똑같다. `a & b == c` 에서 `==` 가 `&` 보다 **세서** `b` 와 `c` 를 먼저 데려간다.

비유 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 낱말에 **꾸미는 힘의 순서**가 있다 | 연산자마다 **우선순위**가 있다 |
| 힘이 센 낱말이 **먼저 짝을 데려간다** | `a & b == c` 는 `a & (b == c)` |
| 힘이 같으면 **읽는 방향**이 정한다 | `a - b - c` 는 왼쪽부터, `a = b = c` 는 오른쪽부터 |
| ★ 짝을 짓는 것과 **말하는 순서**는 다르다 | ★ 우선순위는 **평가 순서를 정하지 않는다**(→ 10번) |
| 애매하면 **쉼표와 괄호**를 찍는다 | 괄호를 친다. 표를 외우지 않는다 |

```text
   식 : a & b == c          (a = 6, b = 2, c = 2)

   힘이 센 == 가 b 와 c 를 먼저 데려간다
        +-------+
   a  &  b == c
        +-------+
          = 1
   a & 1 = 6 & 1 = ★ 0

   내가 읽은 것          C 가 묶은 것
   (a & b) == c         a & (b == c)
      = 2 == 2 = 1         = 6 & 1 = 0
   ------------------   ------------------
   ★ 답이 반대다
```

- 그래서 이 주제의 결론은 **표를 외우는 것이 아니라 괄호로 푸는 법**이다.
- 그리고 **gcc 가 위험한 자리 대부분을 `-Wall` 에서 말해 준다**(`-Wparentheses`). 세어서 확인한다.

> **우선순위(precedence)** — 서로 다른 연산자가 이웃했을 때 **누가 먼저 피연산자를 가져가나**.\
> 예: `1 + 2 * 3` 에서 `*` 가 세서 `2`·`3` 을 먼저 가져간다 → `1 + (2*3)`.

> **결합성(associativity)** — **같은 우선순위**가 이웃했을 때의 방향.\
> 예: `a - b - c` 는 왼쪽 결합이라 `(a-b)-c`, `a = b = c` 는 오른쪽 결합이라 `a = (b = c)`.

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. **가장 자주 당하는 자리**가 어디인가 — 그리고 그 자리들이 왜 하필 거기인가.
2. **결합성이 실제로 답을 바꾸는 자리**는 어디인가.
3. ★★ **우선순위가 답하지 *않는* 질문**은 무엇인가 — 그것이 [10번 형제](../10-evaluation-order-and-sequence-points/)로 넘어가는 다리다.

## 동작 방식

### (1) ★ 비교가 비트 연산보다 세다 — 가장 많이 당하는 자리

**언제 쓰나** — 플래그를 검사할 때. `if (flags & MASK == 0)` 을 쓰려던 모든 순간.

이 프로그램 하나가 (1)\~(3)의 근거 전부다.

```text
===== 소스: ex.c =====
#include <stdio.h>
int main(void) {
    int a = 6, b = 2, c = 2;
    printf("a=6 b=2 c=2 : a & b == c   = %d   |  (a & b) == c = %d\n", a & b == c, (a & b) == c);
    printf("a=6         : a << 1 + 2   = %d   |  (a << 1) + 2 = %d\n", a << 1 + 2, (a << 1) + 2);
    int x = 0, y = 2;
    printf("x=0 y=2     : !x & y       = %d   |  !(x & y)     = %d\n", !x & y, !(x & y));
    int d = 6, e = 3, f = 1;
    printf("d=6 e=3 f=1 : d & e ^ f    = %d   |  d & (e ^ f)  = %d\n", d & e ^ f, d & (e ^ f));
    int g = 1, h = 3, i = 1;
    printf("g=1 h=3 i=1 : g | h ^ i    = %d   |  (g | h) ^ i  = %d\n", g | h ^ i, (g | h) ^ i);
    return 0;
}
```

```text
a=6 b=2 c=2 : a & b == c   = 0   |  (a & b) == c = 1
a=6         : a << 1 + 2   = 48   |  (a << 1) + 2 = 14
x=0 y=2     : !x & y       = 0   |  !(x & y)     = 1
d=6 e=3 f=1 : d & e ^ f    = 3   |  d & (e ^ f)  = 2
g=1 h=3 i=1 : g | h ^ i    = 3   |  (g | h) ^ i  = 2
```

다섯 줄 전부 **왼쪽과 오른쪽이 다르다.** 괄호 하나가 답을 바꾼다.\
gcc 는 이 다섯 줄에 **경고 5건**을 낸다(전문은 (9)).

```text
   힘의 순서 (센 것이 위)

   ==  !=             <- 관계·동등
   &                  <- 비트 AND
   ^                  <- 비트 XOR
   |                  <- 비트 OR
   &&
   ||

   -> ★ 비트 연산자 셋이 비교보다 전부 약하다.
      그래서 flags & MASK == 0 이 뜻대로 안 묶인다.
```

그림 해설 (한 단계씩):

- **`&`·`^`·`|` 는 `==` 보다 약하다.** 그래서 `a & b == c` 는 `a & (b == c)` 로 묶인다.
- 오른쪽 피연산자가 **0 아니면 1** 이 되므로, 사실상 `a` 의 **맨 아래 비트 하나만** 보는 식이 된다.
- 세 비트 연산자끼리도 순서가 있다 — 센 쪽부터 `&` · `^` · `|` 다. 실측으로 확인했다.

- `d & e ^ f` 는 `(d & e) ^ f` 다 — `&` 가 `^` 보다 세다.
- `g | h ^ i` 는 `g | (h ^ i)` 다 — `^` 가 `|` 보다 세다.

비용 — 없다. **비트 연산에는 무조건 괄호를 친다**가 관례인 이유가 이것이다.

### (2) 산술이 시프트보다 세다

**언제 쓰나** — `x << n + 1` 처럼 시프트량을 계산해 넣을 때.

(1)의 프로그램에서 둘째 줄이다.

```text
    printf("a=6         : a << 1 + 2   = %d   |  (a << 1) + 2 = %d\n", a << 1 + 2, (a << 1) + 2);
```

```text
a=6         : a << 1 + 2   = 48   |  (a << 1) + 2 = 14
```

```text
   a << 1 + 2        (a = 6)

   +  가 세다
         +---+
   a  << 1 + 2
         +---+
           = 3
   6 << 3 = ★ 48       내가 기대한 (6<<1)+2 = 14 와 34 만큼 다르다
```

- **`+`·`-` 가 `<<`·`>>` 보다 세다.** 시프트는 산술보다 약하다.
- 같은 집안에 `a + b << c` 도 있다 — 실측에서 `5 + 3 << 1 = 16`, `5 + (3<<1) = 11` 이었다.

비용 — 없다.

### (3) 단항 `!` 이 비트 `&` 보다 세다

**언제 쓰나** — `if (!x & MASK)` 처럼 부정과 마스크를 같이 쓸 때.

(1)의 프로그램에서 셋째 줄이다.

```text
    int x = 0, y = 2;
    printf("x=0 y=2     : !x & y       = %d   |  !(x & y)     = %d\n", !x & y, !(x & y));
```

```text
x=0 y=2     : !x & y       = 0   |  !(x & y)     = 1
```

```text
   !x & y            (x = 0, y = 2)

   단항 ! 이 가장 세다
   +--+
   ! x  &  y
   +--+
     = 1
   1 & 2 = ★ 0        (1 과 2 는 겹치는 비트가 없다)

   !(x & y) = !(0 & 2) = !0 = 1
```

- **모든 단항 연산자**(`!` `~` `-` `+` `*` `&` `sizeof` `(캐스트)`)는 **모든 이항 연산자보다 세다.**
- `!x` 의 결과는 **0 아니면 1** 이라 그것을 마스크와 `&` 하면 거의 언제나 뜻이 무너진다.
- gcc 의 진단 문구가 **고치는 법까지 말해 준다** — 「`&` 를 `&&` 로 바꾸거나 `!` 를 `~` 로 바꿔라」.

비용 — 없다.

### (4) `sizeof` 는 단항이다 — `sizeof a + b` 가 덫인 이유

**언제 쓰나** — 버퍼 크기를 계산할 때.

소스와 출력 전문은 아래 (5)에 있다(**한 프로그램이다**). 여기서는 그 앞 두 줄만 본다.

```text
    printf("sizeof a + b   = %zu   |  sizeof (a + b) = %zu\n", sizeof a + b, sizeof (a + b));
    printf("sizeof a * 2   = %zu   |  sizeof (a * 2) = %zu\n", sizeof a * 2, sizeof (a * 2));
```

```text
sizeof a + b   = 6   |  sizeof (a + b) = 4
sizeof a * 2   = 8   |  sizeof (a * 2) = 4
```

```text
   sizeof a + b       (int a, b = 2)

   sizeof 는 단항이라 a 하나만 데려간다
   +----------+
   sizeof  a   +  b
   +----------+
        = 4        4 + 2 = ★ 6

   sizeof a * 2  =  (sizeof a) * 2  =  4 * 2 = ★ 8
       -> "이만큼 두 배" 가 아니라 "크기의 두 배" 다. 우연히 맞는 날이 있다.
```

- **`sizeof` 는 단항 연산자**다. 괄호 없는 `sizeof a` 뒤에 이항 연산자가 오면 **거기서 끊긴다.**
- `sizeof(a + b)` 처럼 괄호를 쓰면 괄호 안 전체가 피연산자다 — 그때 괄호는 `sizeof` 의 일부가 아니라 **그냥 괄호**다.
- 크기 계산은 [08번 형제](../08-sizeof-alignment-and-offsetof/)가 정본이다. 여기서는 **묶이는 자리**만 본다.

비용 — 없다.

### (5) 결합성이 답을 바꾸는 자리 — 뺄셈과 대입

**언제 쓰나** — 같은 연산자가 셋 이상 늘어설 때.

```text
===== 소스: ex.c =====
#include <stdio.h>
int main(void) {
    int a = 10, b = 2, c = 100;
    printf("sizeof a + b   = %zu   |  sizeof (a + b) = %zu\n", sizeof a + b, sizeof (a + b));
    printf("sizeof a * 2   = %zu   |  sizeof (a * 2) = %zu\n", sizeof a * 2, sizeof (a * 2));
    int t = 0 ? 1 : 0 ? 2 : 3;
    printf("0 ? 1 : 0 ? 2 : 3       = %d   (0 ? 1 : (0 ? 2 : 3))\n", t);
    a = b = c;
    printf("a = b = c   ->  a=%d b=%d c=%d   (오른쪽 결합)\n", a, b, c);
    int p = 10, q = 2, r = 3;
    printf("p - q - r   = %d   ((p - q) - r)   |  p - (q - r) = %d\n", p - q - r, p - (q - r));
    int z = (1, 2, 3);
    printf("z = (1, 2, 3)  -> z = %d   (콤마는 마지막 값)\n", z);
    int w = 5; w = 1, 2;
    printf("w = 1, 2       -> w = %d   (= 가 , 보다 높다)\n", w);
    return 0;
}
```

```text
sizeof a + b   = 6   |  sizeof (a + b) = 4
sizeof a * 2   = 8   |  sizeof (a * 2) = 4
0 ? 1 : 0 ? 2 : 3       = 3   (0 ? 1 : (0 ? 2 : 3))
a = b = c   ->  a=100 b=100 c=100   (오른쪽 결합)
p - q - r   = 5   ((p - q) - r)   |  p - (q - r) = 11
z = (1, 2, 3)  -> z = 3   (콤마는 마지막 값)
w = 1, 2       -> w = 1   (= 가 , 보다 높다)
```

★ 이 프로그램은 **경고 3건**이 난다 — 전부 콤마 연산자에 대한 것이다.

```text
ex.c: In function ‘main’:
ex.c:12:15: warning: left-hand operand of comma expression has no effect [-Wunused-value]
   12 |     int z = (1, 2, 3);
      |               ^
ex.c:12:18: warning: left-hand operand of comma expression has no effect [-Wunused-value]
   12 |     int z = (1, 2, 3);
      |                  ^
ex.c:14:21: warning: right-hand operand of comma expression has no effect [-Wunused-value]
   14 |     int w = 5; w = 1, 2;
      |                     ^
```

```text
   왼쪽 결합                        오른쪽 결합
   +---------------------------+   +---------------------------+
   | p - q - r                 |   | a = b = c                 |
   |   ((p - q) - r)           |   |   a = (b = c)             |
   |   (10 - 2) - 3 = ★ 5      |   |   c 의 값이 b 로, 다시 a 로 |
   |                           |   |   전부 ★ 100              |
   | p - (q - r) = 11 과 다르다 |   | (a = b) = c 는 에러다      |
   +---------------------------+   +---------------------------+
```

그림 해설 (한 단계씩):

- **오른쪽 결합인 것은 넷뿐**이다 — **단항 연산자 · `?:` · 대입 계열(`= += <<=` …) · (그리고 `sizeof`·캐스트)**.\
  **나머지 이항 연산자는 전부 왼쪽 결합**이다.
- `a = b = c` 가 되는 이유는 **대입이 식이고 그 값이 대입된 값**이기 때문이다. 오른쪽 결합이 아니면 `(a=b)` 가 lvalue 가 아니라 에러가 난다.
- `?:` 가 오른쪽 결합이라 **`a ? b : c ? d : e` 는 사다리(else-if 체인)로 읽힌다.** 가장 쓸모 있는 자리다.
- **`,` 는 모든 연산자 중 가장 약하다** — `w = 1, 2` 가 `(w = 1), 2` 라서 `w` 는 1 이다.\
  그래서 `int z = (1, 2, 3);` 처럼 **초기자에서는 괄호가 필수**다(초기자 자리의 `,` 는 구분자로 먹힌다).

비용 — 없다.

### (6) ★★ 우선순위는 「무엇이 먼저 도나」가 아니다 — 10번으로 가는 다리

**언제 쓰나** — 「`*` 가 `+` 보다 세니까 곱셈이 먼저 돌겠지」라고 생각한 모든 순간.

```text
===== 소스: ex.c =====
static int f(void) { printf("  f 가 %d 번째\n", ++order); return 1; }
static int g(void) { printf("  g 가 %d 번째\n", ++order); return 2; }
static int h(void) { printf("  h 가 %d 번째\n", ++order); return 3; }
...
    int v = f() + g() * h();
```

```text
f() + g() * h() =   f 가 1 번째
  g 가 2 번째
  h 가 3 번째
  결과 7
```

```text
   f() + g() * h()

   묶이는 순서 (우선순위)            도는 순서 (실측)
   +--------------------------+     +--------------------------+
   |     +                    |     |  f 가 1 번째              |
   |    / \                   |     |  g 가 2 번째              |
   |  f()  *                  |     |  h 가 3 번째              |
   |      / \                 |     |                          |
   |    g()  h()              |     |  ★ f 가 제일 먼저 돌았다   |
   +--------------------------+     +--------------------------+
     * 가 트리에서 아래 = 먼저 묶임     그런데 f 가 먼저 돌았다

   -> ★ 「먼저 묶인다」와 「먼저 돈다」는 서로 아무 관계가 없다.
```

그림 해설 (한 단계씩):

- **`g() * h()` 가 먼저 묶인다**는 것은 **`g()` 의 결과와 `h()` 의 결과를 곱한다**는 뜻일 뿐이다.
- 세 호출이 **언제** 도는지는 우선순위가 정하지 않는다. 실측에서 `f` 가 제일 먼저 돌았다.
- ★★ **우선순위는 「값이 어떻게 조립되나」(문법)를 정하고, 평가 순서는 「부작용이 언제 나나」(의미)를 정한다.**\
  뒤엣것이 [10번 형제](../10-evaluation-order-and-sequence-points/)의 주제이고, **거기서는 gcc 와 clang 이 다른 답을 냈다.**

비용 — 없다. 다만 **이 구분을 못 하면 10번의 사고를 전부 당한다.**

### (7) `*p++` — 후위가 단항보다 세다

**언제 쓰나** — 포인터로 버퍼를 훑을 때. C 에서 가장 많이 쓰이는 관용구다.

```text
===== 소스: ex.c =====
    int arr[4] = {10, 20, 30, 40};
    int *p = arr, v;
    v = *p++;                       /* 문을 나눈다 — 한 printf 안에서 재지 않는다 */
    printf("*p++   = %d,  p - arr = %td\n", v, p - arr);
    p = arr;
    v = (*p)++;
    printf("(*p)++ = %d,  arr[0] = %d,  p - arr = %td\n", v, arr[0], p - arr);
    arr[0] = 10; p = arr;
    v = *++p;
    printf("*++p   = %d,  p - arr = %td\n", v, p - arr);
```

```text
*p++   = 10,  p - arr = 1
(*p++) = 10,  arr[0] = 11,  p - arr = 0
*++p   = 20,  p - arr = 1
```

```text
   후위 ++ 는 단항 * 보다 세다.

   *p++     =  *(p++)     포인터를 증가시키고, 증가 전 위치의 값을 읽는다
   (*p)++   =  가리키는 값을 증가시킨다. 포인터는 그대로
   *++p     =  *(++p)     포인터를 먼저 증가시키고, 그 자리의 값을 읽는다

   arr = [10, 20, 30, 40]
          ^
          p

   *p++   -> 값 10 을 내고  p 가 한 칸 간다   p - arr = 1
   (*p)++ -> arr[0] 이 11 이 되고 p 는 그대로  p - arr = 0
   *++p   -> p 가 먼저 한 칸 가고 값 20        p - arr = 1
```

그림 해설 (한 단계씩):

- **후위 `++`·`--`·`[]`·`()`·`.`·`->` 가 가장 센 무리**(후위 연산자)다. 단항 `*` 보다도 세다.
- 그래서 `*p++` 는 언제나 `*(p++)` 다. 「값을 증가」하려면 `(*p)++` 로 괄호를 쳐야 한다.
- `p->x++` 도 같은 집안 — `p->x` 가 먼저 묶이고 그 결과를 증가시킨다. **`(p->x)++` 와 같다.**
- ★ 위의 세 줄은 **문을 나눠서** 쟀다. **한 `printf` 안에서 재면 답이 뒤집힌다** — 그 사고는 [10번 형제](../10-evaluation-order-and-sequence-points/)에 실려 있다.

비용 — 없다.

### (8) `(a)(b)` — 괄호가 캐스트인지 호출인지는 **이름의 정체**가 정한다

**언제 쓰나** — 매크로가 `(X)(Y)` 를 만들어 냈을 때. 읽다가 막히는 자리다.

```text
===== 소스: ex.c =====
#include <stdio.h>
typedef int T;                       /* T 는 타입 이름 */
int f(int v) { return v * 10; }
int main(void) {
    int (*g)(int) = f;               /* g 는 함수 포인터 변수 */
    double d = 3.9;
    printf("(T)(d)  = %d   <- 캐스트다\n", (T)(d));
    printf("(g)(4)  = %d   <- 호출이다\n", (g)(4));
    return 0;
}
```

```text
(T)(d)  = 3   <- 캐스트다
(g)(4)  = 40   <- 호출이다
```

`T` 를 `typedef` 가 아니라 변수로 바꾸면 같은 글자가 다르게 읽힌다.

```text
===== 소스: ex.c (T 만 바꿈) =====
int T = 7;                           /* 이번엔 변수다 */
...
    printf("(T)(d)  = %d   <- 캐스트다\n", (T)(d));
```

```text
ex.c: In function ‘main’:
ex.c:7:44: error: called object ‘T’ is not a function or function pointer
    7 |     printf("(T)(d)  = %d   <- 캐스트다\n", (T)(d));
      |                                            ^
ex.c:2:5: note: declared here
    2 | int T = 7;                           /* 이번엔 변수다 */
      |     ^
```

```text
   (T)(d)

   T 가 typedef 이름이면        T 가 변수 이름이면
   +----------------------+    +----------------------+
   | 캐스트                |    | 호출                  |
   | (int)(3.9) = 3       |    | T(d) -> ★ 에러        |
   +----------------------+    +----------------------+

   -> 우선순위 표로는 절대 못 푼다. 파서가 "T 가 무엇으로 선언됐나" 를 봐야 안다.
```

그림 해설 (한 단계씩):

- **이것은 우선순위 문제가 아니라 문법 모호성**이다. C 파서는 **타입 이름 표**를 들고 있어야 한다.
- **에러 메시지가 파스가 바뀐 증거**다 — 「called object `T` is not a function」은 컴파일러가 그것을 **호출로 읽었다**는 뜻이다.
- 그래서 `typedef` 이름을 변수 이름과 같이 쓰면 읽는 사람도 컴파일러도 헷갈린다([06번 형제](../06-typedef-and-type-aliases/)).

비용 — 없다.

### (9) `-Wparentheses` 가 무엇을 잡나 — 세어서 확인

**언제 쓰나** — 빌드 플래그를 정할 때. 「괄호는 컴파일러가 봐 주겠지」를 검증하는 자리다.

여섯 함정을 한 파일에 넣고 플래그를 하나씩 켰다.

```text
[-std=c17] 0 건  exit=0
[-std=c17 -Wall] 5 건  exit=0
[-std=c17 -Wextra] 0 건  exit=0
[-std=c17 -Wall -Wextra] 5 건  exit=0
[-std=c17 -Wparentheses] 5 건  exit=0
[-std=c17 -Wall -Wextra -pedantic] 5 건  exit=0
[-std=c17 -Wall -Wno-parentheses] 0 건  exit=0
[-std=c17 -Wall -Wextra -Wconversion] 5 건  exit=0
```

- ★ **`-Wparentheses` 는 `-Wall` 에 들어 있다.** `-Wextra` 단독으로는 **0건**이다.
- `-Wno-parentheses` 로 끄면 **0건**이 된다 — 이 다섯 건이 전부 그 플래그의 것이라는 증거다.

두 번째 파일(비교 연쇄·대입 조건)도 같은 자리에서 잡혔다.

```text
[-std=c17] 0 건  exit=0
[-std=c17 -Wall] 4 건  exit=0
[-std=c17 -Wextra] 0 건  exit=0
[-std=c17 -Wall -Wextra] 4 건  exit=0
[-std=c17 -Wparentheses] 4 건  exit=0
[-std=c17 -Wall -Wextra -pedantic] 4 건  exit=0
```

★★ **그런데 이 세기가 거짓 0 을 낼 수 있다.** 실제로 재현했다.

```text
[-std=c17 -Wall -Wprecedence] ★컴파일실패 exit=1 (warning 줄 0 — 세지 않는다)
```

```text
gcc: error: unrecognized command-line option ‘-Wprecedence’
exit=1
--- grep -c warning 이 답한 것 ---
0
```

```text
   gcc -Wall -Wprecedence ex.c | grep -c warning
                                          |
                                          v
                                        ★ 0

   "이 플래그로는 경고가 없다" 가 아니라
   "컴파일 자체가 안 됐다" 였다.  exit=1 을 안 보면 못 가른다.
```

- ★★ **경고를 셀 때는 종료 코드를 같이 본다.** 이 문서의 모든 세기 표에 `exit=` 가 붙어 있는 이유다.
- `-Wprecedence` 라는 플래그는 **gcc 에 없다.** 우선순위 검사는 `-Wparentheses` 가 한다.

비용 — 없다.

## 문법 — 형태와 규칙

### 형태 — 힘의 순서를 한 장으로

```text
센 쪽
  ① 후위        a[i]   f(x)   s.m   p->m   a++   a--   (T){...}
  ② 단항        ++a  --a   !  ~  +  -  *  &   sizeof   _Alignof   (T)캐스트
  ③ 곱셈        *  /  %
  ④ 덧셈        +  -
  ⑤ 시프트      <<  >>
  ⑥ 관계        <  <=  >  >=
  ⑦ 동등        ==  !=
  ⑧ 비트 AND    &
  ⑨ 비트 XOR    ^
  ⑩ 비트 OR     |
  ⑪ 논리 AND    &&
  ⑫ 논리 OR     ||
  ⑬ 삼항        ?:
  ⑭ 대입        =  +=  -=  *=  /=  %=  <<=  >>=  &=  ^=  |=
  ⑮ 콤마        ,
약한 쪽

  결합성 — ②·⑬·⑭ 는 오른쪽 결합. ★ 나머지는 전부 왼쪽 결합.
```

★ **이 표를 외우라고 싣는 것이 아니다.** 아래 **네 줄**만 기억하면 실무의 덫이 거의 다 덮인다.

```text
  1. 단항은 전부 이항보다 세다              !x & y  는  (!x) & y
  2. 산술 > 시프트 > 비교 > 비트 > 논리       a & b == c  는  a & (b == c)
  3. 나머지 이항은 왼쪽 결합                 a - b - c  는  (a-b)-c
  4. ?: 와 대입만 오른쪽 결합                a = b = c  는  a = (b=c)
```

### 금지 사례 — 괄호 없이 쓰면 안 되는 형태

```c
/* (1) 비트 연산과 비교를 섞는다 -> -Wall 이 잡는다 */
if (flags & MASK == 0) { }          /* flags & (MASK == 0) */

/* (2) 시프트량을 계산한다 -> -Wall 이 잡는다 */
x = v << n + 1;                     /* v << (n + 1) */

/* (3) 부정과 비트 연산을 섞는다 -> -Wall 이 잡는다 */
if (!x & y) { }                     /* (!x) & y */

/* (4) 비교를 연쇄한다 -> -Wall 이 잡는다 */
if (a < b < c) { }                  /* (a < b) < c — 수학의 뜻이 아니다 */

/* (5) 조건에서 대입한다 -> -Wall 이 잡는다 */
if (x = y) { }                      /* 비교가 아니라 대입 */

/* (6) sizeof 뒤에 연산을 잇는다 -> ★ 아무도 안 잡는다 */
memset(buf, 0, sizeof buf * 2);     /* (sizeof buf) * 2 */

/* (7) 매크로 인자에 괄호를 안 친다 -> ★ 아무도 안 잡는다 (42번 주제) */
#define DOUBLE(x) x * 2
DOUBLE(1 + 1)                       /* 1 + 1 * 2 = 3 */
```

- (1)\~(5)는 **`-Wall` 이 전부 잡는다.** (6)·(7)은 **아무 플래그도 안 잡는다.**
- (7)의 정본은 목록의 **42번 주제**(함수형 매크로의 함정)다.

### 규칙 불릿

- **우선순위와 결합성은 문법(syntax)의 일부**다 — 어느 구현에서도 같고, C89 이후 바뀐 적이 없다.
- **단항 연산자는 전부 이항 연산자보다 세다.** 후위 연산자는 단항보다도 세다.
- **비트 연산자 셋(`&` `^` `|`)은 비교 연산자보다 약하다.** 이것이 이 주제 사고의 절반이다.
- **`&` > `^` > `\|`** 순으로 세다. 셋 사이에도 순서가 있다.
- **`+`·`-` 가 `<<`·`>>` 보다 세다.**
- **오른쪽 결합은 단항 · `?:` · 대입 계열뿐**이고 나머지 이항은 전부 왼쪽 결합이다.
- **`,` 가 가장 약하다** — 초기자·인자 자리에서는 괄호로 감싸야 연산자로 쓸 수 있다.
- ★★ **우선순위는 평가 순서를 정하지 않는다.** 그것은 [10번 형제](../10-evaluation-order-and-sequence-points/)의 주제다.
- **`(X)(Y)` 의 뜻은 `X` 가 타입 이름인지 아닌지로 갈린다** — 우선순위 밖의 문제다.

## 어디서 틀리나

### 1. 「비트 AND 가 비교보다 세겠지」 ★★

```text
a=6 b=2 c=2 : a & b == c   = 0   |  (a & b) == c = 1
```

- **답이 반대**로 나온다. `a & b == c` 는 `a & (b == c)` 다.
- `-Wall` 이 「suggest parentheses around comparison in operand of `&`」로 잡아 준다.
- 막는 법: **비트 연산에는 언제나 괄호.** `(flags & MASK) == 0`.

### 2. 시프트량을 괄호 없이 계산한다

```text
a=6         : a << 1 + 2   = 48   |  (a << 1) + 2 = 14
```

- `+` 가 `<<` 보다 세다. 34 만큼 다른 값이 나온다.
- `-Wall` 이 「suggest parentheses around `+` inside `<<`」로 잡아 준다.

### 3. `sizeof` 를 함수처럼 읽는다 ★

```text
sizeof a + b   = 6   |  sizeof (a + b) = 4
sizeof a * 2   = 8   |  sizeof (a * 2) = 4
```

- **`sizeof` 는 단항 연산자**라 괄호 없는 피연산자 하나만 데려간다.
- ★ **이 자리는 경고가 한 건도 안 난다.** `-Wall -Wextra -Wconversion -pedantic` 전부 조용하다.
- 막는 법: **`sizeof` 에는 언제나 괄호를 쓴다.** `sizeof(buf) * 2` 로 쓰면 뜻이 눈에 보인다.

### 4. 비교를 사슬로 쓴다

```text
a=5 b=3 c=1 : a < b < c   = 1   |  (a < b) < c = 1
```

- 수학의 `5 < 3 < 1` 은 거짓인데 **C 는 1(참)을 낸다.** `(5<3)` 이 0 이고 `0 < 1` 이 참이다.
- gcc 의 문구가 정확히 그렇게 말한다.

```text
ex.c:4:72: warning: comparisons like ‘X<=Y<=Z’ do not have their mathematical meaning [-Wparentheses]
    4 |     printf("a=5 b=3 c=1 : a < b < c   = %d   |  (a < b) < c = %d\n", a < b < c, (a < b) < c);
      |                                                                      ~~^~~
```

- 막는 법: `a < b && b < c`.

### 5. 조건에서 `=` 와 `==` 를 헷갈린다

```text
if (x = b)  -> 참으로 읽혔다, x = 3
```

- `-Wall` 이 「suggest parentheses around assignment used as truth value」로 잡는다.
- 일부러 쓸 때는 **괄호를 한 겹 더** 친다 — `if ((x = b))`. 그러면 경고가 사라진다.

### 6. `*p++` 를 「값을 증가」로 읽는다

- `*p++` 는 **포인터가 움직이고**, `(*p)++` 가 **값이 움직인다.**
- 후위 연산자가 단항보다 세기 때문이다. 경고는 나지 않는다 — **둘 다 합법이기 때문이다.**

### 7. ★★ 우선순위로 평가 순서를 설명한다

```text
f() + g() * h() =   f 가 1 번째
  g 가 2 번째
  h 가 3 번째
```

- `*` 가 더 세지만 **`f()` 가 먼저 돌았다.** 묶이는 순서와 도는 순서는 별개다.
- 여기서 멈추면 안 된다 — [10번 형제](../10-evaluation-order-and-sequence-points/)에서 **gcc 와 clang 이 반대 순서**로 도는 것을 본다.

## 구현 세부사항 대 언어 보장

C 에서는 **「돌아갔다」가 아무것도 증명하지 못한다.** 다섯 층을 갈라야 한다.\
★★ **이 주제는 다섯 층 중 「표준」 하나만 찬다.** 그것이 이 주제의 성격이다 —\
**우선순위와 결합성은 문법이고, 문법에는 자유도가 없다.** 위험은 전부 [10번 형제](../10-evaluation-order-and-sequence-points/)로 간다.

| 층 | 뜻 | 이 주제에서 해당하는 것 | 어떻게 확인했나 | **도구가 못 보는 것** |
|---|---|---|---|---|
| **표준** | 어느 구현에서도 같다 | 우선순위 15계단 전부 · 결합성(단항·`?:`·대입만 오른쪽) · `*p++` = `*(p++)` · `a & b == c` = `a & (b == c)` · `sizeof a + b` = `(sizeof a) + b` · `,` 가 가장 약한 것 · `(X)(Y)` 가 `X` 의 정체로 갈리는 것 | 두 형태를 나란히 찍어 값 대조 · 에러 메시지로 파스 확인 | **`sizeof a * 2` 는 어느 플래그도 말하지 않는다** |
| **조건부 표준** | 매크로가 정의될 때만 | **해당 없음** — 이 주제에 조건부 보장은 없다 | — | — |
| **구현 정의** | 문서화 의무가 있다 | **해당 없음** — 묶는 방식에 구현의 재량이 없다 | — | — |
| **미명시** | 몇 가지 중 하나 | **해당 없음** — 단, ★★ **이 주제가 답하지 않는 질문**(같은 식 안에서 무엇이 먼저 도나)이 [10번 형제](../10-evaluation-order-and-sequence-points/)에서 미명시가 된다 | (6)에서 `f() + g() * h()` 로 경계를 보였다 | — |
| **UB** | 아무 일이나 | **해당 없음** — 괄호를 잘못 쳐도 UB 가 아니라 **그냥 다른 값**이다 | 여덟 프로그램 전부 `exit=0`, UBSan 출력 0줄 | — |

### 이 주제에 sanitizer 가 등장하지 않는 이유

- ★ **여기에는 UB 가 없다.** 잘못 묶인 식도 **정의된 동작**이고, 다만 **내가 뜻한 것이 아닐 뿐**이다.
- 그래서 런타임 도구가 볼 것이 없고, **검사가 전부 컴파일 타임**에 있다.
- 그 컴파일 타임 검사는 **`-Wparentheses` 하나**이며 **`-Wall` 에 들어 있다.**
- ★ 그리고 그 하나도 **`sizeof` 자리는 못 본다**(위 「어디서 틀리나」 3).

### 「도구가 못 보는 것」을 한 표로

| 함정 | gcc `-Wall` | gcc `-Wextra` 단독 | gcc `+-pedantic` | clang `-Wall -Wextra` |
|---|---|---|---|---|
| `a & b == c` | **1건** | 0건 | 1건 | 잡는다(`-Wparentheses`) |
| `a << 1 + 2` | **1건** | 0건 | 1건 | 잡는다 |
| `!x & y` | **1건** | 0건 | 1건 | 잡는다 |
| `a & b ^ c` · `g \| h ^ i` | **2건** | 0건 | 2건 | 잡는다 |
| `a < b < c` | **1건** | 0건 | 1건 | 잡는다 |
| `if (x = y)` | **1건** | 0건 | 1건 | 잡는다 |
| ★ `sizeof a * 2` | **0건** | 0건 | **0건** | **0건** |
| ★ `*p++` 오해 | 0건 | 0건 | 0건 | 0건 (합법이다) |
| ★ 평가 순서 의존 | 0건 | 0건 | 0건 | 0건 (→ 10번) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 형태 | 쓰면 안 되는 것 |
|---|---|---|
| 플래그 검사 | `(flags & MASK) != 0` | `flags & MASK != 0` |
| 시프트량 계산 | `v << (n + 1)` | `v << n + 1` |
| 크기 계산 | `sizeof(buf) * 2` | `sizeof buf * 2` |
| 범위 비교 | `a < b && b < c` | `a < b < c` |
| 조건에서 일부러 대입 | `if ((x = y))` | `if (x = y)` |
| 포인터 훑기 | `*p++`(관용구 — 그대로 둔다) | `*(p++)`(장황하다) |
| 가리키는 값 증가 | `(*p)++` | `*p++` |
| `?:` 사다리 | `a ? x : b ? y : z`(오른쪽 결합이 원하는 모양) | 괄호로 왼쪽 결합 흉내 |
| 매크로 본문 | 인자마다 괄호 + 전체 괄호 | 맨 식 |
| 우선순위가 헷갈린다 | **괄호를 친다** | 표를 찾아본다 |

판단 규칙 두 줄.

- **괄호는 공짜다.** 읽는 사람이 표를 찾아보게 만드는 쪽이 비싸다.
- **`-Wall` 을 켜고 `-Werror` 로 못 박으면** 이 주제의 함정 여섯 중 다섯이 빌드에서 막힌다. 남는 하나는 `sizeof` 다.

## 핵심 문장

- **우선순위는 「무엇이 먼저 묶이나」이고 결합성은 「같은 힘끼리 어느 쪽부터 묶나」다.** 둘 다 **문법**이고, 구현의 재량이 없다.
- **비트 연산자 셋이 비교보다 약하다** — `a & b == c` 는 `a & (b == c)` 이고, 실측에서 `0` 과 `1` 로 답이 갈렸다.
- **단항은 전부 이항보다 세고, 후위는 단항보다 세다** — 그래서 `*p++` 는 언제나 `*(p++)` 다.
- **오른쪽 결합은 단항·`?:`·대입뿐**이고 나머지 이항은 전부 왼쪽 결합이다.
- **`-Wparentheses` 는 `-Wall` 에 있고 여섯 함정 중 다섯을 잡는다.** 못 잡는 하나가 **`sizeof a * 2`** 다.
- ★ **경고를 셀 때는 종료 코드를 같이 본다** — 없는 플래그(`-Wprecedence`)를 붙여 **거짓 0 건**을 받은 것을 재현했다.
- ★★ **우선순위는 평가 순서를 정하지 않는다.** `f() + g() * h()` 에서 `*` 가 세지만 **`f()` 가 먼저 돌았다.**\
  그 이야기는 [10번 형제](../10-evaluation-order-and-sequence-points/)가 정본이다.

## 용어 풀이

- **우선순위(precedence)** — 서로 다른 연산자가 이웃했을 때 누가 먼저 피연산자를 가져가나. 예: `*` 가 `+` 보다 세다.
- **결합성(associativity)** — 같은 우선순위끼리 이웃했을 때의 방향. 예: `a - b - c` 는 왼쪽, `a = b = c` 는 오른쪽.
- **단항 연산자(unary operator)** — 피연산자가 하나인 연산자. `!` `~` `-` `*` `&` `sizeof` 캐스트.
- **후위 연산자(postfix operator)** — 피연산자 뒤에 붙는 것. `a++` `a[i]` `f(x)` `s.m` `p->m`. **가장 세다.**
- **lvalue** — 대입의 왼쪽에 올 수 있는 식. `a = b = c` 가 되려면 `b` 가 lvalue 여야 한다.
- **정수 상수식(integer constant expression)** — 컴파일 시간에 값이 정해지는 정수 식. `case` 라벨·배열 크기에 쓴다.
- **`-Wparentheses`** — 괄호가 필요해 보이는 자리를 경고하는 gcc 플래그. **`-Wall` 에 포함**, `-Wextra` 에는 없다.
- **`-Wno-parentheses`** — 위를 끄는 플래그. 어떤 경고가 누구 것인지 **가르는 데** 쓴다.
- **문법 모호성(grammar ambiguity)** — 같은 글자가 문맥에 따라 다르게 파싱되는 것. `(T)(x)` 가 그 예.

## 더 들어가면

- ★ **C 의 우선순위 표에는 「설계 실수」로 널리 알려진 자리가 있다.** 비트 연산자가 비교보다 약한 것이다.\
  C 초기에 `&`·`\|` 가 논리 연산까지 겸했고, `&&`·`\|\|` 가 나중에 들어오면서 순서를 못 고쳤다는 설명이 흔하다.\
  ★ **그 역사적 서사는 이 문서에서 검증하지 않았다** — 기준 소스(표준·cppreference)로 접지되지 않는다.\
  연혁의 정본은 `history/` 와 [`../../../c-cpp-csharp.md`](../../../c-cpp-csharp.md) 쪽이다.

- **`-Wparentheses` 를 끄는 관용구**가 있다 — 일부러 대입할 때 괄호를 한 겹 더 치는 것(`if ((x = y))`).\
  이 문서에서는 **경고가 사라지는지 던져 보지 않았다.**

- **C++ 의 우선순위 표는 C 와 거의 같지만 같지 않다** — `::`·`new`·`delete`·`throw` 가 더 있고,\
  `<=>`(C++20)도 들어왔다. **이 문서에서는 C++ 를 던져 보지 않았다.** `../../cpp/syntax/` 의 몫이다.

- ★ **연산자 우선순위를 파서가 어떻게 구현하나**(재귀 하강 · Pratt 파싱 · 연산자 우선순위 파싱)는\
  이 갈래 밖이다. [`foundations/compiler-pipeline/`](../../../compiler-pipeline/) 쪽 주제다.

- **매크로 안에서 우선순위가 어떻게 무너지나**는 목록의 **42번 주제**가 정본이다.\
  `#define SQ(x) x*x` 에 `SQ(1+1)` 을 넣으면 `1+1*1+1 = 3` 이 되는 그 이야기다.\
  이 문서에서는 **매크로를 던져 보지 않았다.**
