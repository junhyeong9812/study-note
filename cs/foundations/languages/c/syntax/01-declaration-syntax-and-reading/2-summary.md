## 한눈에 — 쉽게 말하면

**C 의 선언은 타입을 적는 게 아니라, 「이 이름을 이렇게 쓰면 왼쪽의 타입이 나온다」는 사용 설명서다.**

비유 대응은 문서 끝까지 이것 하나로 고정한다.

| 비유 | 실체 |
|---|---|
| 자판기 앞의 안내문 「여기에 동전을 넣고 버튼을 누르면 **콜라**가 나옵니다」 | 선언 `int *p;` = 「`*p` 라고 쓰면 `int` 가 나온다」 |
| 안내문의 **굵은 글씨** (나오는 물건) | 기본 타입 지정자 (`int`·`char`·`double`) |
| 안내문의 **조작 순서** (동전 → 버튼) | 선언자(declarator) — `*`·`[]`·`()` 의 배치 |
| 조작 순서를 읽는 방향 | **이름에서 시작해 안에서 밖으로** |

- 다른 언어는 `int[] a` 처럼 **타입을 통째로 왼쪽에** 적는다.\
  C 는 그렇지 않다. `int a[10]` 은 「`a[10]` 이라고 쓰면 `int` 가 나온다」는 뜻이다.
- 그래서 `int *p[10]` 과 `int (*p)[10]` 이 **완전히 다른 것**이 된다.\
  앞은 `*p[i]` 가 `int`, 뒤는 `(*p)[i]` 가 `int` 다. 괄호 하나가 조작 순서를 바꾼 것이다.
- 이것을 「**선언은 사용을 닮는다**」(declaration mimics use)라고 부른다.

```text
선언       int   *p[10];
            ^      ^^^^^
            |      이렇게 쓰면
            +----- 이것이 나온다

사용       *p[3]  ->  int
```

실무에서 이게 터지는 자리는 **함수 포인터 매개변수**와 **다차원 배열 인자**다.\
`int (*)[4]` 를 `int **` 로 받으면 컴파일러가 경고 한 줄을 내고 넘어가는데, 실행하면 주소 계산이 통째로 어긋난다.

> **선언자(declarator)** — 선언에서 기본 타입 뒤에 오는 부분. 이름과 그 이름에 붙은 `*`·`[]`·`()` 전부.\
> 예: `int *p[10];` 에서 선언자는 `*p[10]` 이고 기본 타입은 `int` 다.

> **저장 기간(storage duration)** — 객체가 언제 생겨서 언제 사라지나.\
> 예: 함수 안의 보통 변수는 함수가 돌 동안만 살고(자동), `static` 이 붙으면 프로그램 내내 산다(정적).

> **연결(linkage)** — 같은 이름이 **다른 파일에서도 같은 물건**을 가리키나.\
> 예: `int g;` 는 다른 `.c` 에서 `extern int g;` 로 가리킬 수 있고(외부 연결), `static int g;` 는 못 한다(내부 연결).

## 이 주제가 답하려는 질문

원고가 없는 문법 주제라 「문제」 대신 이 세 질문을 둔다.

1. `char *(*ft[3])(int)` 같은 선언을 **어느 순서로 읽으면** 말로 옮길 수 있는가.
2. `*`·`[]`·`()` 가 섞였을 때 **누가 먼저 붙는가** — 괄호는 무엇을 바꾸는가.
3. 선언 앞에 붙는 낱말(`static`·`extern`·`const`)은 **타입이 아니라 무엇**을 정하는가.

## 동작 방식

### (1) 선언은 두 부분이다 — 기본 타입 + 선언자

**언제 쓰나** — 선언을 읽기 시작할 때 맨 처음 하는 일. 이걸 안 가르면 나머지가 안 된다.

```text
   static  const int   * const  ft[3]  ;
   ^^^^^^  ^^^^^^^^^   ^^^^^^^^^^^^^^
   저장     기본 타입     선언자
   클래스   지정자        (이름 + 그 이름에 붙은 * [] ())
```

그림 해설 (한 단계씩):

- **저장 클래스 지정자**(`static`·`extern`·`auto`·`register`·`typedef`)는 **타입이 아니다.**\
  저장 기간과 연결을 정한다. 한 선언에 하나만 올 수 있다.
- **기본 타입 지정자**는 선언자를 다 풀고 났을 때 **최종적으로 남는 타입**이다.
- **선언자**가 이 주제의 본체다. `*`·`[]`·`()` 를 이름 주위에 어떻게 배치했느냐가 전부를 정한다.
- 한 선언에 선언자가 여럿 올 수 있고 **선언자마다 타입이 다르다** — `int *p, q;` 가 그 함정이다.

비용 — 없다. 읽는 규칙이다.

### (2) 안에서 밖으로 읽기 — 우선순위 세 줄

**언제 쓰나** — 선언에 `*` 와 `[]` 나 `()` 가 같이 나오는 순간.

규칙은 세 줄뿐이다.

```text
① 이름에서 출발한다.
② 오른쪽을 먼저 본다 — [](배열)와 ()(함수)는 *보다 세다.
③ 오른쪽에 더 볼 게 없으면 왼쪽의 * 를 본다.
   괄호가 있으면 괄호 안을 다 끝내고 밖으로 나간다.
```

```text
int *p[10];

  ①  p            "p 는"
  ②  p[10]        "10개짜리 배열이고"        <- [] 가 * 보다 세다
  ③  *p[10]       "그 원소는 포인터이고"
  ④  int *p[10]   "가리키는 것은 int 다"

  -> "p 는 int 를 가리키는 포인터 10개짜리 배열"
```

```text
int (*p)[10];

  ①  p              "p 는"
  ②  (*p)           "포인터이고"            <- 괄호가 [] 를 막아 * 가 먼저 붙는다
  ③  (*p)[10]       "가리키는 것은 10개짜리 배열이고"
  ④  int (*p)[10]   "그 원소는 int 다"

  -> "p 는 int 10개짜리 배열을 가리키는 포인터"
```

그림 해설 (한 단계씩):

- 두 선언의 **글자는 괄호 두 개만 다르다.**
- 괄호가 없으면 `[]` 가 먼저 붙어 「배열」이 바깥이 되고, 괄호가 있으면 `*` 가 먼저 붙어 「포인터」가 바깥이 된다.
- **바깥에 있는 것이 그 이름의 정체**다. 앞은 배열, 뒤는 포인터다.

비용 — 없다. 다만 **괄호를 안 쓰면 언제나 `[]`·`()` 가 이긴다**는 것을 외워야 한다.

### (3) 메모리로 보면 완전히 다른 물건이다

**언제 쓰나** — 「그래서 뭐가 다른데?」를 판단할 때.

```text
int *p1[10];  — 포인터 10개가 줄지어 있다        int (*p2)[10];  — 포인터 하나다

 p1: +----+----+----+ ... +----+                 p2: +--------+
     |ptr0|ptr1|ptr2|     |ptr9|                     | 주소 1개 |
     +----+----+----+ ... +----+                     +--------+
       |    |    |          |                             |
       v    v    v          v                             v
      int  int  int        int                    +----+----+ ... +----+
                                                  |int |int |     |int |  <- 10개짜리 배열 하나
     sizeof p1 = 80                                +----+----+ ... +----+
                                                   sizeof p2 = 8
                                                   sizeof *p2 = 40
```

실제로 찍어 본 값이다(`gcc -std=c17 -Wall -Wextra`).

```text
sizeof(int *p1[10]) = 80   (포인터 8 x 10)
sizeof(int (*p2)[10]) =  8 (포인터 하나)
sizeof(*p2)          = 40  (가리키는 배열 전체)
sizeof(p1[0])        =  8
sizeof(int (*f1)(int)) = 8
sizeof(char *(*ft[3])(int)) = 24
f1(41) = 42
*f2(7) = 7
p2 vs p2+1 diff = 40 bytes
```

그림 해설 (한 단계씩):

- `p1` 은 **80바이트를 차지한다** — 8바이트 포인터가 10개.
- `p2` 는 **8바이트다** — 포인터 하나. 가리키는 것이 40바이트일 뿐이다.
- 마지막 줄이 결정적이다. `p2 + 1` 은 **40바이트를 건너뛴다** — 포인터 산술이 「가리키는 타입의 크기」만큼 움직이는데 그 타입이 `int[10]` 이기 때문이다.

비용 — `p1` 은 배열 하나 + 가리키는 객체 10개. `p2` 는 포인터 하나.

### (4) 함수 포인터 — 괄호가 필수인 자리

**언제 쓰나** — 콜백·디스패치 테이블을 선언할 때. 정본은 목록의 **35번 주제**이고 여기서는 **읽는 법**만 본다.

```text
int  *f(int);      ①f ②f(int) 함수이고 ③*f(int) 포인터를 돌려주고 ④int 를 가리킨다
                   -> "int 를 받아 int* 를 돌려주는 함수"       (포인터가 아니다!)

int (*f)(int);     ①f ②(*f) 포인터이고 ③(*f)(int) 함수를 가리키고 ④int 를 돌려준다
                   -> "int 를 받아 int 를 돌려주는 함수를 가리키는 포인터"
```

가장 두꺼운 형태를 단계별로 푼다.

```text
char *(*ft[3])(int);

  ① ft                      "ft 는"
  ② ft[3]                   "3개짜리 배열이고"          <- [] 가 먼저
  ③ (*ft[3])                "그 원소는 포인터이고"       <- 괄호 안이 끝났으니 밖으로
  ④ (*ft[3])(int)           "int 를 받는 함수를 가리키고"
  ⑤ char *(*ft[3])(int)     "그 함수는 char* 를 돌려준다"

  -> "ft 는, int 를 받아 char* 를 돌려주는 함수를 가리키는 포인터, 3개짜리 배열"
```

실제로 선언하고 불러 본 것이다.

```text
ft[0]('a') = "A"   ft2[0]('a') = "A"
ft[1]('a') = "a"   ft2[1]('a') = "a"
ft[2]('a') = "b"   ft2[2]('a') = "b"
sizeof ft = 24   sizeof ft2 = 24   sizeof ft[0] = 8
(*ft[0])('a') = "A"   ft[0]('a') = "A"
```

그림 해설 (한 단계씩):

- `ft2` 는 같은 것을 `typedef` 로 푼 것이다 — **크기도 같고 서로 대입된다.**
- 마지막 줄: 함수 포인터는 `(*ft[0])(...)` 로도 `ft[0](...)` 로도 부를 수 있다.\
  **함수 지시자는 호출 자리에서 자동으로 포인터가 되기 때문**이다. 형태가 둘인 것이지 뜻이 둘인 게 아니다.

비용 — 함수 포인터 하나는 이 환경에서 8바이트. 간접 호출이라 인라인이 안 된다.

> **`typedef`** — 기존 타입에 **별명**을 붙이는 저장 클래스 지정자. **새 타입을 만들지 않는다.**\
> 예: `typedef char *CharFn(int);` 뒤에 `CharFn *p;` 는 `char *(*p)(int);` 와 완전히 같다.\
> 정본은 목록의 **06번 주제**다. 여기서는 「선언을 푸는 도구」로만 쓴다.

### (5) `const` 의 자리 — 무엇이 얼어붙나

**언제 쓰나** — 포인터 매개변수에 `const` 를 붙일 때마다.

읽는 법은 (2)와 같다. **`const` 는 자기 바로 왼쪽을 얼린다**(왼쪽에 아무것도 없으면 오른쪽).

```text
const int *p;        int const *p;        <- 둘은 같은 것이다
    ^^^^^^^                ^^^^^
    "가리키는 int" 가 const

  p = &b;   OK      포인터는 바꿀 수 있다
  *p = 9;   에러    가리키는 값은 못 바꾼다


int * const q;
      ^^^^^^^
      "포인터 자신" 이 const

  q = &b;   에러    포인터를 못 바꾼다
  *q = 9;   OK      가리키는 값은 바꿀 수 있다


const int * const r;   둘 다 못 바꾼다
```

실제로 대입해서 받은 에러다(`gcc -std=c17 -Wall -Wextra -c`).

```text
ex.c: In function ‘main’:
ex.c:9:8: error: assignment of read-only location ‘*p’
    9 |     *p = 9;      /* (2) 에러 — 가리키는 값은 못 바꾼다 */
      |        ^
ex.c:10:7: error: assignment of read-only variable ‘q’
   10 |     q = &b;      /* (3) 에러 — 포인터를 못 바꾼다 */
      |       ^
ex.c:12:7: error: assignment of read-only variable ‘r’
   12 |     r = &b;      /* (5) 에러 */
      |       ^
```

그림 해설 (한 단계씩):

- **에러 문구가 둘을 가른다.** `*p` 쪽은 `read-only location ‘*p’`, `q` 쪽은 `read-only variable ‘q’`.\
  「위치」냐 「변수」냐가 **무엇이 얼었는지를 그대로 말해 준다.**
- `p = &b;` 는 **에러가 안 났다** — 목록에 있었는데 진단이 없다. 그것이 답이다.
- 외우는 법: **`*` 를 기준으로 `const` 가 왼쪽이면 값, 오른쪽이면 포인터.**

비용 — 없다. `const` 는 **계약**이고 최적화 보장이 아니다(정본은 목록의 **31번 주제**).

### (6) 저장 클래스 지정자 — 두 축을 동시에 정한다

**언제 쓰나** — 변수를 어디에 둘지 고를 때. 선택의 정본은 목록의 **28번 주제**·목록의 **29번 주제**이고, 여기서는 **선언 문법으로 무엇이 정해지나**만 본다.

```text
                     저장 기간              연결
                  (언제 생기고 사라지나)   (다른 파일이 같은 것을 보나)
  ------------------------------------------------------------------
  (아무것도 없음)   블록 안: 자동          블록 안: 없음
                    파일 수준: 정적        파일 수준: 외부
  static            언제나 정적            파일 수준이면 내부
  extern            정적                   외부 (정의는 다른 곳)
  auto              자동                   없음        (C17 기준, 기본값과 같다)
  register          자동 + 주소를 못 잡음  없음
```

돌려 본 결과다.

```text
10 20 1 2
counter: 3 2 1
&a = 0x7fff80c6dd84 (스택)
&file_static = 0x639c34ed6010 (정적 영역)
```

그림 해설 (한 단계씩):

- `&a`(자동)와 `&file_static`(정적)의 **주소 자릿수가 통째로 다르다** — 다른 영역이다.
- `counter: 3 2 1` 은 이 주제의 규칙이 아니라 **함수 인자 평가 순서**가 드러난 것이다.\
  그 순서는 **미명시**다 — 「구현 세부사항 대 언어 보장」에서 다시 본다.
- `register` 변수의 주소를 잡으면 **에러**다.

```text
ex2.c: In function ‘main’:
ex2.c:1:1: error: address of register variable ‘r’ requested
    1 | int main(void) { register int r = 2; int *p = &r; return *p; }
      | ^~~~~~~~~~~~~~
```

연결은 링커 심볼로 눈에 보인다(`gcc -c a.c` 후 `nm`).

```text
                 U printf
                 U puts
000000000000001a T exported
0000000000000000 t helper
0000000000000000 d hidden
0000000000000004 D shared
```

- **대문자 `T`/`D` 는 외부 연결**, 소문자 `t`/`d` 는 내부 연결(`static`)이다.
- `hidden`(소문자 `d`)을 다른 `.c` 에서 `extern` 으로 부르면 링크가 깨진다.

```text
/usr/bin/ld: /tmp/ccMiixhs.o: in function `main':
b.c:(.text+0x2b): undefined reference to `hidden'
/usr/bin/ld: b.c:(.text+0x46): undefined reference to `helper'
collect2: error: ld returned 1 exit status
```

비용 — 정적 저장 기간은 프로그램 내내 메모리를 차지한다. 자동은 스택 프레임과 함께 사라진다.

## 문법 — 형태와 규칙

직접 쓴 최소 예제다. 묻는 것 하나만 남겼다.

### 형태 — 선언 하나를 풀어 쓰면

```c
static const int * const p[3] = {0};
/*  ^      ^^^^^^^   ^^^^^^^^^^^^^
    |      |         선언자: p[3] 배열, 원소는 const 포인터
    |      기본 타입: const int (가리키는 것도 const)
    저장 클래스: 정적 저장 기간 + 내부 연결
    -> "p 는, const int 를 가리키는 const 포인터, 3개짜리 배열 (파일 안에서만 보임)" */
```

### 한 선언에 선언자가 여럿이면 — `*` 는 이름마다 따로 붙는다

```c
int *p, q;     /* p 는 int*,  q 는 int */
int *p, *r;    /* 둘 다 int* */
```

```text
int *p, q;  ->  p: int *   q: int
```

- `*` 는 **기본 타입 쪽이 아니라 선언자 쪽**에 속한다.
- 그래서 `int* p, q;` 로 붙여 써도 **뜻이 안 바뀐다** — `q` 는 여전히 `int` 다.
- 실무 규칙: **한 줄에 포인터 선언자 하나만** 쓴다.

### 함수 선언과 정의 — `()` 와 `(void)` 는 C17 에서 다르다

```c
int noproto();        /* 매개변수 정보를 안 밝힘 — 「없다」가 아니다 */
int proto(void);      /* 매개변수가 없다 */
```

C17 에서 `noproto(1, 2, 3)` 을 불러 봤다.

```text
##### -std=c17 -Wall -Wextra #####
(exit 0)
1
2
```

- **경고조차 없다.** `-Wall -Wextra` 가 아무 말도 안 한다.
- 잡으려면 플래그를 따로 켜야 한다.

```text
##### -std=c17 -Wall -Wextra -Wstrict-prototypes #####
ex.c:2:1: warning: function declaration isn’t a prototype [-Wstrict-prototypes]
ex.c:5:5: warning: function declaration isn’t a prototype [-Wstrict-prototypes]
```

C23(`-std=c2x`)에서는 **하드 에러**가 된다.

```text
##### -std=c2x -Wall -Wextra #####
ex.c: In function ‘main’:
ex.c:9:20: error: too many arguments to function ‘noproto’
    9 |     printf("%d\n", noproto(1, 2, 3));   /* 인자를 줘 본다 */
      |                    ^~~~~~~
ex.c:5:5: note: declared here
    5 | int noproto() { return 1; }
      |     ^~~~~~~
(exit 1)
```

**C23 부터 `f()` 는 `f(void)` 와 같은 뜻이다.** 같은 소스가 한쪽에서는 조용히 돌고 한쪽에서는 안 서는 것이다.

### 금지 사례 — 선언이 안 서거나 조용히 어긋나는 것

```c
int arr[3];
int (*ap)[3] = arr;    /* (1) 경고: arr 은 int* 로 감쇠한다 */
int (*bad)[3] = pa;    /* (2) 경고: pa 는 int** 로 감쇠한다 */
register int r; int *p = &r;   /* (3) 에러: register 의 주소 */
```

```text
ex2.c:4:20: warning: initialization of ‘int (*)[3]’ from incompatible pointer type ‘int *’ [-Wincompatible-pointer-types]
ex2.c:6:21: warning: initialization of ‘int (*)[3]’ from incompatible pointer type ‘int **’ [-Wincompatible-pointer-types]
```

- (1)·(2)는 **경고일 뿐 컴파일은 된다.** 실행하면 주소 계산이 어긋난다.
- **C 에서 타입이 틀렸는데 프로그램이 만들어지는 자리**가 여기다. 경고를 에러로 올려야(`-Werror`) 막힌다.

## 어디서 틀리나

이 주제의 값어치는 전부 여기 있다. 넷 다 **에러 없이, 또는 엉뚱한 자리에서 터진다.**

### 1. `int *p, q;` 에서 `q` 를 포인터로 읽는다

```text
왼쪽 — 읽은 대로                       오른쪽 — 실제
+------------------------------+      +------------------------------+
| int *p, q;                   |      | int *p, q;                   |
|   p: int*                    |      |   p: int*                    |
|   q: int*  <- 이렇게 읽는다   |      |   q: int   <- 실제           |
|                              |      |                              |
| q = &x;  가 될 거라 기대      |      | 경고 한 줄 나고 컴파일은 됨    |
+------------------------------+      +------------------------------+
```

`q = &x;` 는 경고 한 줄만 내고 **실행 파일이 만들어진다.**

```text
ex.c:6:7: warning: assignment to ‘int’ from ‘int *’ makes integer from pointer without a cast [-Wint-conversion]
--- 실행 ---
p=0x7ffe1e05fc68  q=503708776  (x 의 주소는 0x7ffe1e05fc68)
```

64비트 주소를 32비트 `int` 에 넣으니 상위 절반이 잘린다 — `0x7ffe1e05fc68` 의 아래 32비트가 `503708776` 이다.

### 2. `int (*)[N]` 을 `int **` 로 받는다

다차원 배열을 함수에 넘길 때 가장 흔하다. 정본은 목록의 **17번 주제**이고 여기서는 **선언이 왜 저 모양인가**만 본다.

```text
int a[3][4];
f(a);

  a 는 int (*)[4] 로 감쇠한다     <- "int 4개짜리 배열을 가리키는 포인터"

  void f(int **p)     경고 후 컴파일됨 -> p[1] 이 주소를 읽어 버린다 (사고)
  void f(int (*p)[4]) 맞다              -> p[1] 이 16바이트 건너뛴다
  void f(int p[][4])  위와 완전히 같다   (매개변수 자리의 [] 는 * 로 바뀐다)
```

실제로 `int a[3][4]` 를 세 형태에 넘겨 봤다. `good`·`same` 은 조용하고 `bad` 만 경고가 난다.

```text
ex2.c:7:27: warning: passing argument 1 of ‘bad’ from incompatible pointer type [-Wincompatible-pointer-types]
ex2.c:2:16: note: expected ‘int **’ but argument is of type ‘int (*)[4]’
--- 실행 ---
good: 5
same: 5
세그멘테이션 오류 (exit 139)
```

- **경고 한 줄이고 에러가 아니다.** 실행 파일이 만들어진다.
- `bad` 안의 `p[1]` 은 배열의 두 번째 행이 아니라 **`a[0][2]`·`a[0][3]` 의 비트를 주소로 읽는다.**\
  그 값(`3`, `4` 가 붙은 `0x400000003`)을 주소로 역참조해서 죽었다.
- **여기서 죽은 것은 운이 좋은 경우다.** 값이 유효한 주소 범위에 떨어지면 조용히 엉뚱한 값을 읽는다.

### 3. `f()` 를 「인자 없음」으로 읽는다 (C17 에서만 함정)

위 「문법」 절의 실측 그대로다. C17 에서 `noproto(1,2,3)` 은 `-Wall -Wextra` 로도 **아무 말이 없다.**

| 표준 | `int f();` 의 뜻 | `f(1,2,3)` |
|---|---|---|
| C17 이하 | 매개변수 정보를 밝히지 않음 | 조용히 통과 (`-Wstrict-prototypes` 로만 보임) |
| C23 | `int f(void);` 와 같음 | **에러** |

실무 결론: **C17 코드에서는 `-Wstrict-prototypes` 를 항상 켠다.** 이 플래그는 `-Wall -Wextra` 에 안 들어 있다.

### 4. `const` 를 붙였는데 안 얼었다

```c
void g(const char *s);     /* s 가 가리키는 문자를 안 바꾸겠다는 계약 */
void h(char * const s);    /* s 라는 지역 변수를 안 바꾸겠다는 것 — 호출자에게 의미 없다 */
```

- 매개변수에 의미가 있는 것은 **거의 언제나 앞엣것**이다.\
  뒤엣것은 함수 안의 지역 변수를 얼릴 뿐이라 **호출자가 알 필요가 없는 정보**다.
- 그래서 헤더에 `char * const s` 를 쓰면 **계약을 말하는 척하면서 아무 계약도 안 한 것**이 된다.

## 구현 세부사항 대 언어 보장

C 에서는 **「돌아갔다」가 아무것도 증명하지 못한다.** 네 층을 갈라야 한다.

| 층 | 뜻 | 이 주제에서 해당하는 것 | 어떻게 확인했나 |
|---|---|---|---|
| **표준이 정한 것** | 어느 구현에서도 같다 | 선언자 읽는 순서(`[]`·`()` 가 `*` 보다 셈) · `const` 의 자리별 의미 · `f(void)` 의 뜻 · 저장 기간·연결 규칙 | 표준 문서의 규정 + 실행 |
| **구현 정의** | 구현마다 다르지만 **문서화 의무가 있다** | 포인터의 크기(여기선 8) · 정적 영역과 스택의 주소 배치 · `register` 를 실제로 레지스터에 둘지 | `sizeof` 출력 · `nm` 심볼 표 |
| **미명시** | 몇 가지 중 하나인데 **문서화 의무가 없다** | **함수 인자의 평가 순서** | gcc 와 clang 이 **반대**였다(아래) |
| **UB** | 아무 일이나 일어날 수 있다 | (이 주제의 문법 자체에는 없다 — 잘못 선언한 포인터로 **접근**하는 순간부터 UB. 목록의 **56번 주제**) | — |

### 미명시를 출력으로 — 함수 인자 평가 순서

같은 소스, 같은 머신, 컴파일러만 바꿨다.

```c
static int n = 0;
int counter(void) { return ++n; }
printf("%d %d %d\n", counter(), counter(), counter());
```

```text
gcc -O0  : 3 2 1
gcc -O1  : 3 2 1
gcc -O2  : 3 2 1
gcc -O3  : 3 2 1
gcc -Os  : 3 2 1
clang -O0  : 1 2 3
clang -O2  : 1 2 3
--- ubsan 이 잡나 ---
3 2 1
```

- gcc 는 **오른쪽부터**, clang 은 **왼쪽부터** 평가했다.
- **최적화 수준을 다 바꿔도 gcc 안에서는 안 흔들렸다** — 그래서 더 위험하다.\
  한 컴파일러만 보고 「이렇게 된다」고 적으면 틀린다.
- **sanitizer 는 안 잡는다.** UB 가 아니라 미명시이기 때문이다.\
  미명시는 **도구로 잡히지 않는 층**이고, 그래서 이 층이 가장 조용하다.

> **미명시 동작(unspecified behavior)** — 표준이 여러 가능성을 허용하고 **어느 것을 골랐는지 밝힐 의무도 없는** 것.\
> 예: 함수 인자를 왼쪽부터 평가할지 오른쪽부터 할지. 골라야 하지만 알릴 필요가 없다.

> **구현 정의 동작(implementation-defined behavior)** — 구현마다 다르되 **문서에 적을 의무가 있는** 것.\
> 예: `int` 의 크기, `char` 의 부호. gcc 문서와 `<limits.h>` 를 보면 답이 나온다.

### 표준이 정한 것 — 「선언자 우선순위」는 보장이다

`[]`·`()` 가 `*` 보다 강하게 결합하는 것은 **문법 규칙 자체**라 어느 구현에서도 같다.\
`int *p[10]` 이 어떤 컴파일러에서 「배열의 포인터」가 되는 일은 없다.

### 구현 정의 — `register` 는 요청이지 명령이 아니다

`register` 는 **주소를 못 잡는다는 제약만 표준이 강제**하고, 실제로 레지스터에 둘지는 구현 마음이다.\
현대 컴파일러는 대개 무시한다 — 레지스터 배치는 이미 최적화기가 하는 일이다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 선언을 직접 쓴다 | `typedef` 로 푼다 |
|---|---|---|
| `int *p` · `char buf[64]` 같은 한 겹 | 쓴다 | 오히려 읽기 나빠진다 |
| 함수 포인터 매개변수 하나 | 써도 된다 | 반복되면 푼다 |
| 함수 포인터 배열·함수 포인터를 돌려주는 함수 | **읽을 수 없다** | 푼다 |
| 공개 헤더의 콜백 타입 | 쓰지 않는다 | **푼다** (호출자가 읽어야 한다) |

판단 규칙 두 줄.

- **괄호가 두 겹 이상 되면 `typedef` 로 자른다.**
- **매개변수의 `const` 는 `*` 왼쪽에 둔다** — 그것만 호출자에게 의미가 있다.

## 핵심 문장

- C 의 선언은 타입 표기가 아니라 **「이렇게 쓰면 이 타입이 나온다」는 사용식**이다 — 그래서 **선언은 사용을 닮는다**.
- 읽는 순서는 **이름 → 오른쪽(`[]`·`()`) → 왼쪽(`*`)**, 괄호가 있으면 안을 먼저 끝낸다.
- `int *p[10]` 은 **포인터 10개짜리 배열**(80바이트), `int (*p)[10]` 은 **배열 하나를 가리키는 포인터**(8바이트)다.
- `const` 는 **자기 바로 왼쪽**을 얼린다 — `*` 를 기준으로 왼쪽이면 가리키는 값, 오른쪽이면 포인터 자신.
- 저장 클래스 지정자는 타입이 아니라 **저장 기간과 연결** 두 축을 정하고, 그 결과는 `nm` 의 대소문자로 눈에 보인다.
- **C17 에서 `f()` 는 「인자 없음」이 아니다** — `-Wall -Wextra` 도 안 잡고, C23 에서 뜻이 바뀌었다.

## 용어 풀이

- **선언(declaration)** — 이름이 무엇인지 컴파일러에게 알리는 것. 저장 클래스 + 기본 타입 + 선언자(들)로 이루어진다.
- **정의(definition)** — 선언이면서 **실제 객체나 함수 본체를 만드는 것**. `extern int g;` 는 선언, `int g;` 는 정의.
- **선언자(declarator)** — 이름과 그에 붙은 `*`·`[]`·`()`. 기본 타입 뒤에 오는 부분 전부.
- **기본 타입 지정자(type specifier)** — `int`·`char`·`double`·`struct S` 처럼 선언자를 다 푼 뒤 남는 타입.
- **저장 클래스 지정자(storage-class specifier)** — `static`·`extern`·`auto`·`register`·`typedef`. 타입이 아니라 저장 기간·연결을 정한다.
- **저장 기간** — 객체가 언제 생기고 사라지나. 자동·정적·스레드·할당 네 가지.
- **연결(linkage)** — 다른 번역 단위에서 같은 이름이 같은 물건을 가리키나. 외부·내부·없음 세 가지.
- **번역 단위(translation unit)** — 전처리가 끝난 `.c` 파일 하나. 링크의 단위다.
- **프로토타입(prototype)** — 매개변수의 타입까지 밝힌 함수 선언. `int f(int)` 는 프로토타입이고 `int f()` 는 (C17 에서) 아니다.
- **감쇠(decay)** — 배열 이름이 식에서 「첫 원소를 가리키는 포인터」로 바뀌는 것. 정본은 목록의 **16번 주제**.
- **미명시 동작** — 표준이 여러 가능성을 허용하고 어느 것인지 밝힐 의무도 없는 것.
- **구현 정의 동작** — 구현마다 다르되 문서화 의무가 있는 것.

---

## 더 들어가면

- **`typeof` 는 C23 부터 표준**이다. gcc 13 에서 `-std=c17` 은 `typeof` 를 모르고(`implicit declaration of function ‘typeof’`), `-std=c2x` 는 받는다.\
  C17 에서 같은 일을 하려면 GNU 확장 `__typeof__` 를 쓴다 — **이식성이 없다.**
- `static_assert` 의 철자도 C23 에서 정리됐다. `-std=c17` 은 `<assert.h>` 없이 `static_assert` 를 모르고 `_Static_assert` 만 받는데, `-std=c2x` 는 헤더 없이 `static_assert` 를 받는다.
- **선언자 문법은 재귀적이라 원리상 무한히 깊어진다.** 그래서 「읽는 법」이 규칙 세 줄로 끝나고, 사람이 못 읽는 것은 깊이의 문제지 규칙의 문제가 아니다.
- 매개변수 자리의 `[]` 는 **언제나 `*` 로 바뀐다.** `void f(int a[10])` 은 `void f(int *a)` 와 완전히 같고, `10` 은 문서 효과뿐이다(C99 의 `static` 수식자는 예외 — 목록의 **16번 주제**).
- gcc 에는 선언을 말로 풀어 주는 기능이 없다. `cdecl` 이라는 별도 도구가 그 일을 하지만 **이 머신에는 없다** — 대신 위 (2)·(4)의 단계 규칙으로 손으로 푼다.
