## 이 언어에서 무엇을 자르는 축

C 는 기능이 적은 언어라 “기능 목록”으로 자르면 30개면 끝난다.
그런데 실제로 인출이 필요한 것은 기능이 아니라 **기능이 만나는 자리의 규칙**이다 — 배열이 포인터가 되는 자리, 정수가 말없이 승격되는 자리, 객체의 수명이 끝나는 자리.
그래서 다섯 축으로 자른다.

```text
① 선언과 타입    선언을 읽는 법 · 어떤 변환이 말없이 일어나는가
② 메모리 모델    포인터 · 배열 감쇠 · 집합체 레이아웃 · 저장 기간
③ 경계와 계약    const/volatile/restrict · 소유권 · errno · 헤더와 링크
④ 표준 라이브러리  stdio · string · stdlib — "함정이 있는 함수"가 본체다
⑤ 미정의 동작     조용히 틀리는 네 자리 + 그것을 잡는 도구
```

⑤는 다른 언어 목록에 없는 C 고유의 축이다. 다른 언어에서 “런타임 오류”인 것이 C 에서는 **증상이 없는 사건**이라, 규칙 자체를 인출 대상으로 세우지 않으면 배울 자리가 없다.

## 뺀 것과 이유

- **언어사·설계 정신·표준 개정 서사** — [`../../c-cpp-csharp.md`](../../c-cpp-csharp.md) 와 `history/` 의 축이다. 여기서 다시 쓰지 않는다.
- **C++ 문법 전부** — `../../cpp/syntax/` 로 간다. 이 목록은 C++ 목록의 **선행**이다(거기서 C 주제 번호를 가리킨다).
- **`<threads.h>`·`<stdatomic.h>`(C11 동시성)** — 선택 기능이고 실무에서는 POSIX 스레드나 상위 언어로 가는 경우가 많다. 동시성 개념 자체는 [`foundations/process-thread/`](../../../process-thread/) 에 있다. 2단계에서 수요가 확인되면 추가한다.
- **POSIX/시스템 콜(`open`·`fork`·소켓)** — ISO C 가 아니라 POSIX 표준이다. 축이 다르므로 `cs/systems/` 쪽 주제로 둔다.
- **컴파일러 확장(GNU C)** — `__attribute__`·statement expression 등은 이식성 축이 달라 기준 소스(ISO C)로 접지되지 않는다. 필요한 최소한만 58(도구)에서 플래그 수준으로 다룬다.
- **`<complex.h>`·`<fenv.h>`·`<tgmath.h>`·`<locale.h>`·와이드 문자(`<wchar.h>`)** — 면적 대비 인출 빈도가 낮다. 필요해지면 52의 자매 주제로 붙인다.

## 버전 기준

**C17(ISO/IEC 9899:2018) 기준**으로 쓰고, **C23 에서 달라지는 것은 주제 안에서 「C23부터」로 표기**한다.
C17 은 C11 의 결함 수정판이라 새 기능이 없다 — 그래서 “C99부터/C11부터”도 함께 적어야 의미가 산다.

| 표기 | 해당 주제 |
|---|---|
| **C99부터** | 21 지정 초기자 · 26 유연 배열 멤버 · 27 복합 리터럴 · 18 VLA(C99 필수) |
| **C11부터** | 08 `_Alignof`/`alignas` · 40 `_Generic` · 53 `static_assert` · 18 VLA가 선택 기능으로 |
| **C23부터** | 07 `enum` 고정 기반 타입 · 19 `nullptr` · 02 `bool`/`true`/`false` 키워드화 · 34 `f()` 가 `f(void)` 와 같아짐 · 08 `alignas`/`static_assert` 철자 정리 |

C23 항목은 **`gcc 13` 의 `-std=c2x` 에서 지원 여부가 기능마다 다르다.** 3파일을 쓸 때 각 항목을 실제로 컴파일해 보고, 이 머신에서 확인되지 않는 것은 「미확인」으로 적는다.
