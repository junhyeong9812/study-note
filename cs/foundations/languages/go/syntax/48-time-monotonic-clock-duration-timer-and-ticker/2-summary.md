# go/syntax/48 — `time`: `Time`·`Duration`·단조 시계·`Timer`/`Ticker`(1.23 변경) — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> **기준 소스** — [`time`](https://pkg.go.dev/time) 패키지 문서(`go doc time` 의 「Monotonic Clocks」 · `time.NewTimer` · `Timer.Stop`) · [GODEBUG](https://go.dev/doc/godebug) 문서(이 툴체인의 `doc/godebug.md`). **이 툴체인에서 직접 떴다.**\
> **실행 검증** — 이 문서의 출력은 전부 아래 판에서 실제로 돌려 **파일로 캡처한 것**이다. 소스 펜스도 같은 파일에서 떠 왔다. 손으로 옮겨 적은 블록은 없다.
> ★★ 판 격자에는 모듈 캐시에 있던 **`go1.25.12`** 를 같이 썼다(명령에는 `"$GO125"` 로 찍힌다). `GOTOOLCHAIN=local` 이라 **`go.mod` 의 `go` 줄이 툴체인을 바꾸지 않는다** — 줄은 **언어·GODEBUG 기본값**만 바꾼다.\
> **버전** — 타이머 채널이 동기(용량 0)가 되고 GC 가 멈추지 않은 타이머를 거두는 것은 **1.23**. ★★★ **그것을 되돌리던 `asynctimerchan` 은 1.27 에서 제거됐다** — 그래서 **1.22 의미는 `go1.25.12` 로만** 냈다((1)절).
> 이 본문은 Claude 작성이다(원고 없음). 규칙은 위 기준 소스로, 출력은 실행으로 접지했다.

★★★ **본체는 넷째 창이다** — 「**1.23 타이머 판 격자** — 탐침 7(`cap(t.C)` · 발화 뒤 `len` · 발화 뒤 `Stop()` · `Stop` 뒤 값 · `Reset` 뒤 옛 값 · 버린 `Ticker` 의 수거 · `time.After` 20만 번 뒤 힙) × 판 4(`go1.25.12` 의 `go 1.22`·`go 1.23` 줄 · `go1.27.1` 의 `go 1.22`·`go 1.27` 줄)」.

★★★ **이 주제의 경계** — `select` 의 타임아웃 가지로서의 `time.After` 는 [30번 주제](../30-select-default-and-timeouts/) (4)절 · 루프 안 `time.After` 가 **고루틴 누수가 아니라는 것**과 `asynctimerchan` 제거는 [31번 주제](../31-goroutine-leaks/) (7)절이 정본이다.

```text
The Time returned by time.Now contains a monotonic clock reading. If Time t
has a monotonic clock reading, t.Add adds the same duration to both the wall

they also strip any monotonic clock reading from their results. The canonical
way to strip a monotonic clock reading is to use t = t.Round(0).

t.After(u), t.Before(u), t.Equal(u), t.Compare(u), and t.Sub(u) are carried out

time.ParseInLocation, and time.Unix, as well as the unmarshalers t.GobDecode,
t.UnmarshalBinary. t.UnmarshalJSON, and t.UnmarshalText always create times with
no monotonic clock reading.
```

```text
    needed. As of Go 1.23, the garbage collector can recover unreferenced

    longer necessary to help the garbage collector. (Code may of course still
    want to call Stop to stop the timer for other reasons.)

    Before Go 1.23, the channel associated with a Timer was asynchronous
    (buffered, capacity 1), which meant that stale time values could be received
    even after Timer.Stop or Timer.Reset returned. As of Go 1.23, the channel is
    synchronous (unbuffered, capacity 0), eliminating the possibility of those
    stale values.

    a stale time value from before the Stop; if the program has not received

    true. Before Go 1.23, the only safe way to use Stop was insert an extra
```

## 한눈에 — 쉽게 말하면

**`time.Now()` 는 「벽시계 사진」과 「스톱워치 눈금」을 한 장에 찍는다.** 벽시계는 **지금 몇 시인가**를 말하고(누가 시계를 돌리면 바뀐다), 스톱워치는 **프로그램이 켜진 뒤 얼마나 지났나**만 센다(아무도 못 돌린다).
두 사진의 **차이(`Sub`)** 를 구할 때 Go 는 **스톱워치 눈금끼리** 뺀다 — 그래서 벽시계를 누가 돌려도 경과 시간은 틀리지 않는다.
그런데 사진을 **복사해 편지로 보내거나(`MarshalText`)** 「몇 시」로 **다시 써 붙이면(`Round(0)`·`UTC()`)** 스톱워치 눈금은 **떨어져 나간다.**

**`Timer` 는 「초인종」이다.** 1.23 전에는 초인종이 울리면 **우편함(용량 1 채널)에 쪽지를 넣어 두었다** — 초인종을 끈(`Stop`) 뒤에도 **옛 쪽지가 남아** 있었다. 1.23 부터는 **우편함이 없다** — 문 앞에 **사람이 서 있을 때만** 건넨다.

| 비유 | 실체 |
|---|---|
| 스톱워치 눈금 | ★★★ **단조 시계 값** — `String()` 끝의 `m=+…` |
| 눈금끼리 빼기 | ★★★ **`t.Sub(u)`·`time.Since`** — 둘 다 눈금이 있으면 그것으로만 |
| 눈금이 떨어진 사진 | ★★ **`Round(0)`·`AddDate`·`UTC()`·`UnmarshalText`** 의 결과((2)절) |
| 같은 순간, 다른 사진 | ★★★ **`t == u` 는 `false`, `t.Equal(u)` 는 `true`** |
| 우편함에 남은 옛 쪽지 | ★★★ **1.23 전 `Stop` 뒤 `<-t.C` 가 값을 받는다**((1)절 판 1) |
| 우편함이 없어짐 | ★★★ **1.23+ `cap(t.C) = 0`** |
| 끄지 않은 초인종이 치워짐 | ★★ **버린 `Ticker` 를 GC 가 거둔다**(1.23+) |

```text
   ★★★ time.Now() 한 장에 든 것 — 그리고 벗겨지는 자리

   t := time.Now()   ─▶ [ 벽시계 2026-… KST | 단조 m=+0.00… ]
        t.Add(1s)    ─▶ [ 벽시계 +1s        | 단조 +1s       ]   ← 둘 다 옮긴다
        t.Round(0)   ─▶ [ 벽시계            |  (없음)        ]   ← 벗기는 정석
        t.UTC()      ─▶ [ 벽시계(UTC 로 읽기) |  (없음)        ]
        t.AddDate()  ─▶ [ 벽시계 계산        |  (없음)        ]
        MarshalText → UnmarshalText ─▶ [ 벽시계 | (없음) ]         ← 프로세스 밖으로 못 나간다
```

> **단조 시계(monotonic clock)** — 되돌아가지 않는 시계. 벽시계 동기화(NTP 등)나 사람이 시계를 바꿔도 영향을 안 받는다. **「지금 몇 시」는 모른다** — 경과만 잰다.

> **`time.Timer` / `time.Ticker`** — `d` 뒤 **한 번** 채널로 보냄 / `d` 마다 **계속** 보냄. `time.After(d)` 는 `NewTimer(d).C` 와 같다(30번).

## 이 주제가 답하려는 질문

1. **경과 시간을 재는 올바른 방법은** — 무엇이 단조 시계를 쓰고 무엇이 그것을 벗기나.
2. **1.23 에서 타이머의 무엇이 바뀌었고, 그 변경은 무엇이 켜나** — `go.mod` 의 줄인가 툴체인인가.
3. **`Duration`·`Parse`·시간대에서 조용히 틀리는 자리는** — 에러 없이 다른 값이 나오는 곳.

### (1) ★★★ 1.23 타이머 판 격자 — 탐침 7 × 판 4

**언제 쓰나** — `t.Stop()` 뒤에 `<-t.C` 를 비우던 옛 관용구를 볼 때, 그리고 `go.mod` 의 `go` 줄을 올리거나 툴체인을 올릴 때.

```text
===== 소스: t48timer.go =====
package main

import (
	"fmt"
	"runtime"
	"time"
	"weak"
)

func main() {
	t := time.NewTimer(time.Millisecond)
	fmt.Printf("cap(t.C)\t%d\n", cap(t.C))
	time.Sleep(20 * time.Millisecond)
	fmt.Printf("발화 뒤 받기 전 len(t.C)\t%d\n", len(t.C))
	fmt.Printf("발화 뒤 받기 전 Stop()\t%v\n", t.Stop())
	select {
	case <-t.C:
		fmt.Printf("Stop 뒤 t.C 에서 값이 나오나\t%v\n", true)
	default:
		fmt.Printf("Stop 뒤 t.C 에서 값이 나오나\t%v\n", false)
	}

	t2 := time.NewTimer(time.Millisecond)
	time.Sleep(20 * time.Millisecond)
	t2.Reset(time.Hour)
	select {
	case <-t2.C:
		fmt.Printf("Reset(1h) 직후 t.C 에서 값이 나오나\t%v\n", true)
	case <-time.After(30 * time.Millisecond):
		fmt.Printf("Reset(1h) 직후 t.C 에서 값이 나오나\t%v\n", false)
	}

	w := func() weak.Pointer[time.Ticker] {
		tk := time.NewTicker(time.Millisecond) // Stop 하지 않고 참조를 버린다
		return weak.Make(tk)
	}()
	time.Sleep(10 * time.Millisecond)
	runtime.GC()
	runtime.GC()
	fmt.Printf("참조를 버린 Ticker 가 GC 뒤 사라졌나\t%v\n", w.Value() == nil)

	var ms runtime.MemStats
	runtime.GC()
	runtime.ReadMemStats(&ms)
	before := ms.HeapInuse
	ready := make(chan int, 1)
	for i := range 200000 {
		ready <- i
		select {
		case <-ready:
		case <-time.After(time.Hour):
		}
	}
	runtime.GC()
	runtime.ReadMemStats(&ms)
```

```text
	fmt.Println("t0.Add(24h)        :", a)
	fmt.Println("t0.AddDate(0,0,1)  :", b)
	fmt.Println("AddDate 결과 - t0   :", b.Sub(t0))
	fmt.Println("같은 순간 두 표기    :", t0.UTC(), "·", t0.Equal(t0.UTC()))
}

t0.Add(24h)        : 2026-03-08 13:00:00 -0400 EDT
t0.AddDate(0,0,1)  : 2026-03-08 12:00:00 -0400 EDT
```

그림 해설 (한 단계씩):

- ★★★ **뉴욕 2026-03-07 12:00 EST 에 `Add(24h)` 는 이튿날 `13:00 EDT`, `AddDate(0,0,1)` 은 `12:00 EDT`** — 그 사이 **서머타임이 시작돼** 하루가 23시간이다. `AddDate 결과 - t0 : 23h0m0s`.
  `Add` 는 **경과 시간**을 더하고, `AddDate` 는 **달력(벽시계)** 을 옮긴다.
- ★★ **[Python 49번](../../../python/syntax/49-datetime-and-zoneinfo/)과 견주면** — 파이썬은 **같은 `tzinfo` 끼리의 `+ timedelta(hours=24)` 가 벽시계 산술**이라 「뉴욕 `+ 24h` 가 실제 23·25시간」이 됐다. **Go 의 `Add` 는 파이썬과 반대로 경과**를, **Go 의 `AddDate` 가 파이썬의 `+` 쪽**이다. 「24시간 더하기」라는 같은 글자가 **두 언어에서 다른 연산**이다.
- ★★ **`t0.Equal(t0.UTC())` 는 `true`** — 같은 순간의 다른 표기다((2)절의 `==` 와 한 짝).

비용 — 없다.

## 문법 — 형태와 규칙

### 형태

```go
// t48mono.go
package main

import (
	"fmt"
	"strings"
	"time"
)

func hasM(t time.Time) bool { return strings.Contains(t.String(), " m=") }

func main() {
	t := time.Now()
	fmt.Println("[1] time.Now()           String 에 m= 가 있나:", hasM(t))
	fmt.Println("[2] t.Round(0)           String 에 m= 가 있나:", hasM(t.Round(0)))
	fmt.Println("[3] t.UTC()              String 에 m= 가 있나:", hasM(t.UTC()))
	fmt.Println("[4] t.Add(time.Second)   String 에 m= 가 있나:", hasM(t.Add(time.Second)))
	fmt.Println("[5] t.AddDate(0, 0, 1)   String 에 m= 가 있나:", hasM(t.AddDate(0, 0, 1)))

	b, _ := t.MarshalText()
	var u time.Time
	u.UnmarshalText(b)
	fmt.Println("[6] MarshalText → UnmarshalText 한 u 에 m= 가 있나:", hasM(u))

	fmt.Println("── 같은 순간을 == 와 Equal 로 ──")
	fmt.Println("    t == t.Round(0)   :", t == t.Round(0), "· t.Equal(t.Round(0)):", t.Equal(t.Round(0)))
	fmt.Println("    t == u            :", t == u, "· t.Equal(u)         :", t.Equal(u))
	fmt.Println("    t == t.UTC()      :", t == t.UTC(), "· t.Equal(t.UTC())   :", t.Equal(t.UTC()))
	fmt.Println("    t.Round(0) == u   :", t.Round(0) == u)

	fmt.Println("── 경과 시간 ──")
	s := time.Now()
	time.Sleep(20 * time.Millisecond)
	e := time.Since(s)
	fmt.Println("    time.Since(s) >= 20ms :", e >= 20*time.Millisecond)
	a, c := time.Now(), time.Now()
	fmt.Println("    c.Sub(a) >= 0         :", c.Sub(a) >= 0)
}
```

규칙 불릿.

- ★★★ **경과 시간은 `start := time.Now()` … `time.Since(start)`** — 시작점을 `Round(0)`·직렬화·파싱으로 만들면 단조 보호가 **없다.**
- ★★★ **`Time` 비교는 `Equal`** — `==`·맵 키는 Location·단조 값까지 본다.
- ★★★ **1.23+ 타이머(그리고 1.27+ 툴체인)에서는 `Stop` 뒤 `<-t.C` 를 비우는 관용구가 필요 없다** — 옛 코드에 남아 있으면 `select`/`default` 없이는 **막힌다**(용량 0, 보낼 값 없음) — ★ 막히는 것 자체는 **안 던졌다.**
- ★★ **`Duration` 은 `int64` 나노초** — 약 292년에서 넘친다. 날짜 단위는 `AddDate`.
- ★★ **레이아웃은 `2006-01-02 15:04:05`** — 자리를 바꾸면 **조용히 다른 날짜**.
- ★★ **「내일 같은 시각」은 `AddDate(0,0,1)`, 「24시간 뒤」는 `Add(24*time.Hour)`.**

### 금지 사례 — 누가 잡나

| 쓴 꼴 | 누가 잡나 | 어디서 |
|---|---|---|
| `t1 == t2` 로 같은 시각인지 | ★★★ **아무도 안 잡는다** — 순간이 같아도 `false` | (2)절 |
| 직렬화해 받은 시각으로 `time.Since` | ★★ **아무도 안 잡는다** — 벽시계로 떨어진다 | (2)절 |
| `go 1.22` 줄에 기대 1.23 타이머 의미를 피함(1.27 툴체인) | ★★ **아무도 안 잡는다** — 조용히 새 의미 · 스위치를 켜면 **`fatal error`/빌드 실패** | (1)절 |
| 긴 기간을 `Duration` 곱셈으로 | ★★★ **아무도 안 잡는다** — 음수 | (3)절 |
| 레이아웃 `"2006-02-01"` | ★★★ **아무도 안 잡는다** — 4월 3일 | (4)절 |
| `ParseDuration("1d")` | `unknown unit "d"` | (3)절 |

## 어디서 틀리나

### 1. ★★★ 「1.23 타이머 의미는 `go.mod` 의 `go` 줄이 정한다」

- (1)절 — **1.23\~1.26 툴체인에서만** 맞다(`7 / 7`). **1.27.1 에서는 `0 / 7`** — 스위치가 제거됐다.

### 2. ★★★ 「`Stop()` 이 `false` 면 `<-t.C` 로 비워야 한다」

- (1)절 — **1.23+ 에서는 발화했어도 안 받았으면 `Stop()` 이 `true`** 이고 남은 값이 **없다.** 비우는 코드는 옛 의미의 처방이다.

### 3. ★★★ 「`Ticker` 는 `Stop` 안 하면 영원히 샌다」

- (1)절 — **1.23+ 은 참조를 버리면 거둔다**(`true`). 1.22 의미는 **안 거뒀다**(`false`). ★ 그래도 `Stop` 은 **틱을 멈추는** 일이라 필요한 자리가 있다(문서).

### 4. ★★★ 「두 `Time` 이 같은 순간이면 `==` 도 참」

- (2)절 — **`false` 세 줄.** `Equal` 을 쓴다.

### 5. ★★ 「`time.Since` 는 늘 단조 시계로 잰다」

- (2)절 — **시작점에 단조 값이 있을 때만.** `Round(0)`·`UTC()`·직렬화한 값은 없다.

### 6. ★★ 「`Duration` 은 충분히 크다」

- (3)절 — **292년에서 음수로.** 300년 곱셈이 조용히 넘쳤다.

### 7. ★★ 「레이아웃이 틀리면 `Parse` 가 에러를 낸다」

- (4)절 — **`"2006-02-01"` 은 에러 없이 4월 3일.**

## 핵심 문장

- ★★★ **1.23 부터 타이머 채널은 용량 0 — `Stop`/`Reset` 뒤 옛 값이 없고, 버린 타이머·`Ticker` 도 GC 가 거둔다.** `go1.25.12` 에서 `go 1.22` 대 `1.23` 줄이 `7 / 7` 을 갈랐다.
- ★★★ **1.27 은 그 스위치(`asynctimerchan`)를 없앴다** — `go 1.22` 줄이어도 `0 / 7`, 켜려 하면 세 경로 모두 거부.
- ★★★ **경과 시간은 `time.Now()` 두 개의 `Sub` — 단조 시계로 잰다.** `Round(0)`·`UTC()`·`AddDate`·직렬화가 그것을 벗긴다.
- ★★★ **`Time` 은 `==` 가 아니라 `Equal`** — `==` 는 Location·단조 값까지 본다.
- ★★ **`Duration` 은 `int64` 나노초** — 292년에서 음수로 감싸 돈다. 레이아웃 자리를 바꾸면 **에러 없이** 다른 날짜.
- ★★ **`Add(24h)` 는 경과, `AddDate(0,0,1)` 은 달력** — 서머타임 날에 23시간이 갈린다. 파이썬의 `+ 24h` 는 달력 쪽이다.

## 용어 풀이

- **벽시계(wall clock) / 단조 시계(monotonic clock)** — 「지금 몇 시」(바뀔 수 있다) / 「얼마나 지났나」(되돌지 않는다).
- **`m=+…`** — `Time.String()` 끝에 붙는 단조 시계 값. 없으면 벗겨진 값이다.
- **`t.Round(0)`** — 단조 값을 벗기는 정석.
- **`Equal`** — 두 `Time` 이 같은 순간인지. `==` 와 다르다.
- **`time.Duration`** — `int64` 나노초.
- **`asynctimerchan`** — 1.23 의 타이머 변경을 끄던 GODEBUG 설정. 1.27 에서 제거.
- **`weak.Pointer`** — GC 가 대상을 거두는 것을 막지 않는 포인터(1.24). 거둬지면 `Value()` 가 `nil`.
- **레이아웃** — 기준 시각 `2006-01-02 15:04:05` 을 원하는 모양으로 쓴 문자열.
