# domain-modeling/12-time-money-and-units — 질문

## 질문

1. (왜) 금액·시각·물리량을 맨 숫자(`double`, `long`, `String`)로 들면 어떤 종류의 오류가 생기나? 그 오류가 "에러 없이" 나는 이유는?
2. (그림) 금액의 위험 세 겹(표현·자릿수·반올림)을 그리고, `BigDecimal`로 바꾸면 그중 무엇이 해결되고 무엇이 남는지 말하라.
3. (예측) 금액 `0.01`을 `double`로 100만 번 더하면 정확히 `10000.0`이 나오나? `BigDecimal("0.01")`로 더하면?
4. (예측) 거래 1,000건(1,000~100,000원)에 수수료율 3.3%를 매긴다. 거래마다 HALF_UP으로 원 단위 반올림해 더한 값과, 총액에 한 번 곱해 반올림한 값은 같은가? 다르면 왜 `BigDecimal`이 이를 막지 못하나?
5. (예측) America/New_York에서 2026-03-07, 2026-03-08, 2026-11-01의 하루 길이는 각각 몇 시간인가? Asia/Seoul의 2026-03-08은?
6. (경계) "하루 뒤"를 `Period.ofDays(1)`로 더할 때와 `Duration.ofHours(24)`로 더할 때는 언제 같고 언제 다른가?
7. (연결) 결제 시각·미래 회의 시작·생일을 각각 어떤 Java 타입과 PostgreSQL 타입으로 두나? 회의 시작을 결제 시각과 같은 타입으로 두면 무엇이 문제인가?
8. (장애 진단) Mars Climate Orbiter의 근본 원인은 무엇이었고, 값이 몇 배 틀렸나? 코드 수준에서 이 종류의 오류를 막는 방법 두 가지는?
9. (장애 진단) 다통화 장바구니 합계가 터무니없는 값으로 나왔다. 금액 타입이 `long`이었다. 원인과, 값 객체가 이를 어떻게 막는지 설명하라.
