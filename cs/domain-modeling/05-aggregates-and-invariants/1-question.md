# domain-modeling/05-aggregates-and-invariants — 질문

## 질문

1. (왜) 애그리거트가 없으면 "스프린트 포인트 합 ≤ 용량" 같은 규칙이 어떻게 깨지나? 반대로 애그리거트를 너무 크게 잡으면 무엇이 나빠지나?
2. (그림) Evans 『DDD Reference』의 Aggregates 항목이 루트·바깥 참조·불변식 책임·트랜잭션 경계에 대해 정한 것을 그림으로 그려라.
3. (암기·이해) Vernon "Effective Aggregate Design"(2011)의 4규칙을 대고, 각 규칙이 막는 실패를 한 줄씩 적어라. Vernon이 말한 "불변식"은 어떤 일관성을 뜻하나?
4. (예측) 사용자 8명이 서로 **다른** 백로그 항목을 50번씩 고친다. 버전을 `Product`(거대 애그리거트)에 둘 때와 `BacklogItem`(작은 애그리거트)에 둘 때 충돌 수는 각각 대략 얼마였나(PostgreSQL 17 실험)? 왜 거대 쪽에서 충돌이 나나?
5. (예측) 8명이 동시에 3점 항목을 용량 10인 스프린트에 넣는다. 앱 서비스가 합을 읽어 검사만 할 때와, 루트 `Sprint` 버전을 올리며 넣을 때 최종 합은? 첫 번째가 깨지는 이유를 격리 수준과 연결해 설명하라.
6. (경계) Evans와 Vernon은 애그리거트 크기와 트랜잭션당 수정 범위에 대해 어떻게 다르게 말하나? Vernon이 인정한 "규칙을 깨도 되는 이유" 네 가지는?
7. (장애 진단) JPA로 `Order`(루트, `@Version`)와 `@OneToMany(mappedBy)` 주문 줄을 매핑했다. 서로 다른 줄을 고친 두 요청이 모두 성공해 주문 한도를 넘었다. 왜 버전 검사가 막지 못했나? `@ElementCollection`이면 어떻게 달랐나(Hibernate 6.6 실험)? 대처는?
8. (장애 진단) 피크 때 "다른 사용자가 먼저 수정했습니다" 오류가 급증했다. 무엇을 확인해 거대 애그리거트 문제인지 판단하나(쿼리·지표)? 고치는 순서는?
9. (연결) 경계 밖 규칙을 결과적 일관성으로 맞출 때 쓰는 장치와, 그 방식을 쓰면 안 되는 규칙의 조건은?
