# domain-modeling/09-domain-events — 질문

## 질문

1. (왜) 주문 서비스가 메일·포인트·배송 요청을 직접 부르면 무엇이 나빠지나? 도메인 이벤트는 그중 무엇을 풀고, 무엇은 새 문제로 남기나?
2. (경계) 『DDD Reference』(2015)가 말하는 도메인 이벤트와 시스템 이벤트는 어떻게 다른가? 이벤트에 보통 담는 정보 셋과, 이벤트 ID를 두는 이유는?
3. (그림) 이벤트를 "기록하는 때"와 "내보내는 때"를 나눠, 트랜잭션 안 발행·AFTER_COMMIT·outbox 세 경우를 시간축으로 그려라. 롤백과 커밋 직후 프로세스 사망에서 각각 무엇이 새나?
4. (예측) 주문 10건 중 짝수 5건이 이벤트 발행 **뒤** 예외로 롤백된다. `@EventListener` 메일, `@TransactionalEventListener` 메일, 같은 트랜잭션 outbox 행은 각각 몇 건이 되나?
5. (예측) Spring 6.2.11 + pgjdbc 42.7.4 + `SimpleDriverDataSource`에서, 전파 지정 없는 AFTER_COMMIT 리스너가 DB에 INSERT하면 행이 남나? Spring Javadoc의 설명과 결과가 같은가, 다르다면 왜인가?
6. (예측) AFTER_COMMIT 리스너가 예외를 던지면 `place()`를 부른 호출자는 예외를 받나? 그 실패는 어디에 남나?
7. (경계) `@TransactionalEventListener` 메서드에 `@Transactional`(기본 전파)을 붙이면 Spring 6.2.11에서 무슨 일이 일어나나? 허용되는 전파는?
8. (적용) 후속 처리 세 종류 — 같은 DB 집계 갱신, 메일 발송, 다른 서비스로 가는 통합 이벤트 — 에 각각 어떤 발행 시점을 고르나? 근거는 "유실 허용 여부"로 설명하라.
9. (장애 진단) 고객이 "주문 완료" 메일을 받았는데 주문이 없다고 한다. 어떤 데이터를 대조해 원인을 확인하고, 코드는 어떻게 고치나?
10. (연결) outbox로 바꾼 뒤 포인트가 두 번 적립되는 건이 생겼다. 왜 생기며, 소비자 쪽에 무엇을 두면 막히나?
