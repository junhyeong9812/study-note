# domain-modeling/23-versioned-rules-and-effective-dating — 질문

## 질문

1. (왜) 요율표를 한 칸으로 두고 UPDATE로 바꾸면 어떤 질문에 답할 수 없게 되나? 판(version)을 쌓은 뒤에도 남는 결정 두 가지는?
2. (그림) v1 `[1/1, 7/1)`, v2 `[7/1, 11/1)`, v3 `[11/1, ∞)`를 시간축에 그리고, 정확히 7/1 00:00과 그 1마이크로초 전이 각각 어느 판에 속하는지 표시하라. 반열린 구간을 쓰는 이유는?
3. (예측) 1~10월 주문 1,002건에 주문 시각 기준 판으로 수수료를 매겨 저장했다. 덮어쓰기 모델(요율 0.0350)로 재계산하면 몇 건이 달라지나? 주문 시각으로 판을 다시 찾아 계산하면? 저장된 판 스탬프로 계산하면?
4. (예측) 6/30 23:59:30 주문, 7/1 00:00:30 결제인 10만 원 주문의 수수료는 주문 시각 기준과 결제 시각 기준으로 각각 얼마인가? 어느 쪽이 맞는지는 누가 정하나?
5. (경계) PostgreSQL 17의 `EXCLUDE USING gist (rule_id WITH =, effective WITH &&)`는 어떤 잘못된 데이터를 막고, 어떤 것은 못 막나? 못 막는 것은 어떻게 찾나?
6. (예측) 11/1 00:00 발효인 v3를 10/3에 미리 넣었다. 같은 조회 쿼리를 10/31 23:59:59와 11/1 00:00:00에 돌리면? 요율이 코드 상수이고 11/1 03:00에 배포됐다면 00:00~05:59 주문 72건 중 몇 건이 틀리나?
7. (연결) 결과 행에 `rule_id`·`rule_version`을 찍는 것은 재계산 점검을 어떻게 단순하게 만드나? 22번(결정 기록)이 여기에 더하는 것은?
8. (경계) `TreeMap.floorEntry(t)`로 판을 고를 때 빈틈이 있으면 무엇이 잘못되나? 어떻게 보완하나?
9. (장애 진단) 판 스탬프 기준 재현성 점검이 어느 날 갑자기 수백 건 불일치를 냈다. 무엇을 의심하고 어떻게 재발을 막나?
10. (경계) 규칙 변경이 요율 숫자가 아니라 계산 공식 자체라면, "발효는 데이터로 예약한다"는 원칙을 어떻게 적용하나?
