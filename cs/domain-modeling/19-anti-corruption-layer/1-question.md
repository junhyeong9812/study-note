# domain-modeling/19-anti-corruption-layer — 질문

## 질문

1. (왜) 외부 PG 응답의 `resCd`·`amt`를 도메인 서비스 여러 곳이 직접 읽으면 무엇이 문제인가? DDD Reference는 큰 상류 인터페이스가 하류 모델에 무슨 일을 한다고 적나?
2. (정의) ACL을 Reference의 말로 정의하라. ACL은 상류와 하류 중 누가 만들고, 상류에 무엇을 요구하나?
3. (구조) 퍼사드·어댑터·번역기는 각각 무엇을 하나? 작은 통합에서 셋을 합쳐도 되는 이유는?
4. (예측) PG가 성공 코드를 `"0000"`에서 `"00"`으로 바꿨다. ACL 없이 세 서비스가 `"0000".equals(resCd)`로 판단한다. 우리 코드를 안 바꾸면 결제 승인·금액·환불·정산 테스트 4개는 어떻게 되나? 운영에서는 어떤 형태로 보이나?
5. (예측) 같은 변경을 `switch(resCd) { case "0000" ...; case "9999" ...; default -> throw }` 번역기 하나로 받으면 무엇이 일어나고, 바로잡는 데 몇 파일을 고치나?
6. (경계) 번역기에서 모르는 코드를 `default -> 실패`로 두는 것과 `default -> 예외`로 두는 것은 무엇이 다른가?
7. (경계) Azure 문서는 ACL에 무엇을 넣지 말라고 하나? ACL이 맞지 않는 경우는 언제인가?
8. (장애 진단) 레거시 앞에 독립 서비스로 둔 ACL 때문에 신 시스템 전체가 멈췄다. 어떤 고려점을 빠뜨렸고, 어떻게 대처하나?
9. (적용) 외부 모델이 도메인으로 새어 들어왔는지 코드에서 찾는 방법과, 그것을 CI에서 강제하는 방법을 말하라.
10. (연결) 18번의 "하류 `getOrDefault(..., 0)` → 합계 0"과 이 노트의 "ACL이 기본값으로 덮는 번역"은 어떤 공통 원인을 갖나?
