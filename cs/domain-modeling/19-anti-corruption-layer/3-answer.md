# domain-modeling/19-anti-corruption-layer — 정답

## 정답

### 1. 외부 모델이 퍼질 때

- 외부의 이름·코드값·형식이 도메인 여러 곳에 박힌다. 외부가 바뀌면 그 모든 곳을 같이 고쳐야 하고, 한 곳을 놓치면 조용히 틀린다.
- Reference: 상류와의 큰 인터페이스는 결국 하류 모델의 의도를 압도해, 하류 모델이 상류 모델을 닮도록 즉흥적으로 고쳐지게 만든다.

### 2. 정의와 책임

- 정의: 하류 클라이언트가 상류 시스템의 기능을 **자기 도메인 모델의 말로** 쓸 수 있게 하는 격리 계층. 상류의 기존 인터페이스로 통신하고, 안에서 필요한 방향으로 두 모델 사이를 번역한다.
- 만드는 쪽: **하류**("as a downstream client").
- 상류에 요구하는 것: 거의 또는 전혀 없다("little or no modification to the other system").

### 3. 부품

| 부품 | 하는 일 |
|---|---|
| 퍼사드 | 외부의 큰 인터페이스를 우리가 쓰는 부분만으로 좁혀 감싼다(외부 말) |
| 어댑터 | 우리 포트를 구현하고 퍼사드로 넘긴다. 퍼사드의 말 ↔ 우리 말 |
| 번역기 | 외부 객체·코드값 ↔ 도메인 객체 변환 로직 |

- Evans 14장은 ACL을 퍼사드·어댑터와 번역기(translators)의 조합으로 짜는 것을 한 가지 방식("One way")으로 제시한다(원문 문장 인용으로 확인, 원서 미열람).
- 합쳐도 되는 이유: 핵심은 "외부 말을 아는 곳이 한 곳"이라는 것이다. 부품 수가 아니다. 외부 인터페이스가 작으면 클래스 하나로 충분하다.

### 4. ACL 없음 (실험)

- 4개 모두 `FAIL`(`failures=4`). 새 성공 코드 `"00"`이 `"0000"`과 달라 모두 실패로 분류됐다.
- 운영에서는: PG는 승인(고객 돈이 빠짐)했는데 우리는 결제 실패로 기록한다. **예외도 로그도 없다.** 실패율 지표 급등과 대사 불일치로 드러난다.
- 바로잡는 데 3파일(`PaymentService`, `RefundService`, `Settlement`)을 고쳤다. 외부 모델을 아는 파일은 4개였다.

### 5. ACL (실험)

- `IllegalStateException: UNKNOWN_PG_CODE resCd=00 tid=T1`이 바로 난다. 변화가 첫 호출에서 드러난다.
- 바로잡기: `PgTranslator.java` **1파일 1줄**(`case "00", "0000"`). 고친 뒤 테스트 4개 통과.
- 단, 고칠 때까지는 결제 요청이 모두 예외로 끝난다. 그 사이 PG가 승인한 건은 대사·취소 처리가 필요하다(해석).

### 6. `default -> 실패` vs `default -> 예외`

- `실패`: 처음 보는 코드가 "알려진 실패"와 구분되지 않는다. 새 **성공** 코드도 실패로 분류된다. 오염이 번역기를 조용히 통과한다.
- `예외`: 모르는 값이 들어온 사실이 드러난다(상관 ID와 함께). 사람이 매핑 표를 갱신할 때까지 잘못된 데이터가 쌓이지 않는다.
- 원칙: 기본값 없는 전수 매핑. 알려진 성공·실패만 명시한다.

### 7. 넣지 말 것과 맞지 않는 경우

- 넣지 말 것: 비즈니스 규칙과 오케스트레이션. ACL은 번역 로직에 집중한다.
- 맞지 않는 경우: 두 시스템 사이에 의미 차이가 크지 않을 때. 외부 모델을 읽는 곳이 하나뿐이고 우리 말과 거의 같으면 번역기는 코드·지연만 더한다.

### 8. 독립 ACL 서비스 장애

- 빠뜨린 고려점(Azure): 호출 지연 추가, 관리할 서비스 하나 추가, 확장 방식, 모니터링·배포·설정 통합.
- 대처
  - ACL을 다른 서비스처럼 확장·모니터링·배포 대상으로 관리한다.
  - 요청 경로에 둘 필요가 없으면 애플리케이션 안의 구성 요소로 두거나 비동기 메시지 번역으로 바꾼다.
  - 타임아웃·재시도 정책을 정한다(distributed/03).

### 9. 누수 찾기와 강제

- 찾기: 도메인 패키지에서 외부 SDK 타입·필드명(`LegacyPgResponse`, `resCd`)을 `grep`하고 ACL 패키지는 제외한다. 결과가 있으면 누수다. 실험의 "참조 파일 수"(ACL 없음 4, ACL 1)가 같은 진단이다.
- 강제: ArchUnit 같은 아키텍처 테스트로 "domain 패키지는 legacy 패키지에 의존하지 않는다"를 CI에서 검사한다.

### 10. 공통 원인

- 둘 다 **없는 필드·모르는 값을 기본값으로 덮어** 실패를 데이터 오류로 바꾼다.
- 18번은 하류가 계약 없이 순응하며 덮었고, 이 노트의 경우는 ACL이 있어도 번역기가 덮었다. ACL이 있다는 것만으로 오염을 막지 못한다. 실패를 드러내는 번역이어야 한다.
