# domain-modeling/20-event-storming — 질문

## 질문

1. (왜) 개발자끼리만 모델링하면 어떤 지식이 빠지기 쉽나? 데이터 모델(테이블·클래스)부터 그리는 것과 도메인 이벤트부터 붙이는 것은 무엇이 다른가?
2. (정의) 이벤트 스토밍과 도메인 이벤트를 각각 한 줄로 정의하라. 도메인 이벤트는 어떤 시제로 쓰고, 누구에게 의미가 있어야 하나?
3. (표기) 도메인 이벤트·명령·행위자·외부 시스템·정책·읽기 모델·핫스폿·애그리거트는 DDD Crew 용어집에서 각각 무슨 색인가? 2013년 원글의 색과 다른 점이 있다면 무엇이며, 워크숍에서는 어떻게 다루나?
4. (구분) Big Picture, Process Modeling, Software Design은 각각 무엇을 목적으로 하나? 2013년 원글의 권장 인원과 용어집의 Big Picture 인원은 어떻게 다른가?
5. (문법) Process Modeling에서 명령·애그리거트·이벤트·정책·읽기 모델은 어떤 순서로 이어지나? 각각 코드로 가면 대략 무엇이 되나?
6. (예측) 보드에 이벤트 "주문 접수됨 → 결제 승인됨 → 배송 시작됨", 명령 "주문하기(→주문 접수됨)·배송 시작(→배송 시작됨)", 정책 "주문 접수됨이면 결제 요청"만 있다. 문법 검사기는 무엇을 빈틈으로 보고하나?
7. (경계) 검사기가 "환불 완료됨 ← 다음은 누가 하나?"를 보고했다. 이것은 늘 결함인가? 검사기의 한계와 보완책은?
8. (경계) Brandolini의 "몇 주가 아니라 몇 시간에" 주장은 어떤 종류의 근거인가? 실험의 보드 검사는 무엇을 보이고 무엇을 보이지 않나?
9. (장애 진단) 워크숍 몇 달 뒤 팀마다 이벤트 이름이 다르고(`OrderCompleted` vs `OrderFinished`), 아무도 보드를 기억하지 못한다. 원인과 대처는?
10. (장애 진단) 출시 직전 "일부 품목만 재고가 있으면 부분 배송인가 전체 취소인가"가 미정이라는 것이 드러났다. 보드의 무엇을 어떻게 관리했어야 하나?
