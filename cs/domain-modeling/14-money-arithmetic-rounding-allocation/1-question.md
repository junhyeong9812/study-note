# domain-modeling/14-money-arithmetic-rounding-allocation — 질문

## 질문

1. (왜) 금액을 `BigDecimal`이나 최소 단위 정수로 들어도 돈이 생기거나 사라지는 이유는? Fowler가 구분한 두 연산(비례 요금 vs 배분)은 무엇인가?
2. (예측) 10,000원을 3명에게 "나눈 뒤 각자 원 단위로 자르면" 합은? 최대 잔여 방식으로 나누면 각 몫은? 100원을 1:1:1로 각자 HALF_UP 하면 합은? 5원을 1:1로 각자 HALF_UP 하면?
3. (계산) 7원을 2:3:5로 나눌 때 Fowler 초안의 `allocate(long[] ratios)`(앞 칸부터 남은 몫)와 최대 잔여 방식의 결과를 각각 구하고, 어느 쪽이 정확한 비례값에 더 가까운지 말하라.
4. (예측) `2.5`, `3.5`, `-2.5`를 HALF_UP·HALF_EVEN·DOWN·FLOOR로 정수 반올림한 결과는? `new BigDecimal("2.5").setScale(0)`처럼 모드를 안 주면? PostgreSQL 17의 `round(2.5::numeric)`과 `round(2.5::float8)`은?
5. (예측) 가격 105원 상품 3줄, 세율 10%(HALF_UP)일 때 줄별 세액 합과 합계 세액은? 무작위 주문 1만 건(seed 42)에서 두 방식이 갈린 비율은?
6. (경계) 정률 할인 15%와 세율 10%를 정확히 계산하면 순서가 결과에 영향을 주나? 단계마다 원 단위로 반올림하면? 정액 할인 100원은?
7. (연결) ISO 4217에서 KRW·JPY·USD·KWD·BHD·CLF의 minor unit은? JDK 21 `Currency.getDefaultFractionDigits()`와 같았나? 결제사 연동에서는 무엇을 기준으로 삼나?
8. (장애 진단) 같은 금액의 중복 청구 검사가 통과해 이중 청구가 나갔다. 금액은 `BigDecimal`이었고, 한 경로는 DB `numeric(19,4)`, 다른 경로는 JSON에서 왔다. 원인과 대처는? PostgreSQL에서 같은 비교를 하면 결과가 같은가?
9. (장애 진단) 일부 주문만 결제사가 "금액 불일치"로 거절한다. 무엇부터 의심하고, 어떻게 고치나?
10. (경계) 금액을 JSON 숫자로 보내면 어떤 값이 깨지나? `1.005.toFixed(2)`가 `1.00`인 이유는? 권장하는 직렬화 형식 두 가지는?
