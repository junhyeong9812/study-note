# domain-modeling/27-dm-symptom-index — 정답

## 정답

### 1. 왜 "에러 없음"인가

- 도메인 규칙은 대개 프레임워크·DB가 모르는 규칙이다("결제 전 배송 금지", "몫의 합 = 원금"). 그 규칙을 지키는 코드가 빠지거나 우회되면 아무도 예외를 던지지 않는다. 행은 저장되고 숫자는 계산된다.
- 처음 보이는 칸(§0): ① 컴파일·기동, ② 예외·로그, ③ 불법 상태 행, ④ 숫자 불일치, ⑤ 시각 어긋남, ⑥ 중복·유실·유령, ⑦ 외부와 다름(대사·민원·감사), ⑧ 변경 비용·팀 충돌. ③~⑦은 로그에 아무것도 남지 않는 경우가 많다.
- 그래서 첫 진단은 **데이터 쿼리**다. 규칙을 `WHERE`로 옮기거나, 부모와 자식 합을 비교하거나, 키당 건수를 세거나, 양쪽을 대조한다.

### 2. 1원의 흔한 원인 셋

| 원인 | 첫 진단 | leaf |
|---|---|---|
| 배분 — 나눗셈 후 각자 반올림 | 원금 vs 몫의 합 | 14-1 · 15-2 |
| 반올림 위치 — 줄마다 vs 합계에 한 번 | 두 계산의 반올림 위치 대조, 결제 요청 금액이 저장된 확정 금액인가 | 12-1 · 14-2 |
| 반올림 방식 불일치 — 두 계산이 다른 모드(앱 `HALF_EVEN` vs PG `numeric` 반올림, 조용히 자르는 `longValue()`) | 두 계산의 반올림 모드·경로 대조, 차이가 동률(.5)이나 잘린 소수부가 있는 금액에 몰리나 | 14 §3 |

- 1원처럼 보여도 다른 모양인 것: 스케일(`1.0` ≠ `1.00`, 14-4)은 같은 금액을 다르다고 판정해 이중 청구로, 통화 자릿수(JPY 0·KWD 3, 14-3)는 100배·1/10 배율이나 결제사 거절로 나타난다.
- 9,999원은 **배분**이다. `HALF_EVEN`으로 바꿔도 해결되지 않는다. 모드가 원인인 경우는 대개 두 계산(또는 코드와 약관)의 모드가 서로 다를 때이고, 그때의 대처도 "더 나은 모드"가 아니라 한 정책으로 맞추는 것이다(PostgreSQL 17.11 `round(2.5::numeric)` = 3, Java `HALF_EVEN` = 2).
- 실험(JDK 21.0.12, `10000/3`을 `setScale(0)` 후 ×3): `HALF_UP`·`HALF_EVEN`·`HALF_DOWN`·`DOWN`·`FLOOR`는 9,999, `UP`·`CEILING`은 10,002. 일곱 모드 모두 10,000이 아니었다. 배분기(남는 몫을 받는 규칙)와 "합 == 원금" 불변식이 대처다.

### 3. 실행 확인 예측

- 주문 2는 쿼리 (2)에 **나오지 않는다**. 총액도 9,999로 저장돼 줄 합 9,999와 같기 때문이다(출력: (2)에는 주문 6만 `12000 | 11000`).
- 쿼리 (4)에서는 `2 | 9999 | 10000 | AMOUNT_MISMATCH`로 나온다. 배분 소실이 일관되게 저장되면 내부 검사는 통과하고 외부 대조에서만 보인다.
- 주문 4는 **세 행**으로 갈린다: `EXTERNAL_ONLY`(T4), `EXTERNAL_ONLY`(T5), `INTERNAL_ONLY`(내부 7000). 내부에 거래 ID가 없어 키로 짝을 못 지었다 — 거래 ID 미저장(25-3)의 모양이다. 외부에는 같은 주문 ID의 승인이 둘인데, 이것은 멱등 키 없는 재시도(25의 DUPLICATE_EXTERNAL 분류)의 모양이다. 고객이 새 주문으로 재결제한 경우(25-1)는 주문 ID가 달라 이렇게 나오지 않는다. 쿼리 (3)도 주문 4를 `4 | 2 | T4,T5`(주문 ID·건수·거래 ID)로 잡았다.

### 4. 1시간·하루·2월

- (가) 정확히 1시간(30분 DST 지역이면 30분), 특정 지역: 미래 예약을 옛 tz 규칙으로 계산한 UTC 순간만 저장했다. tzdata 갱신 뒤부터인가, 그 지역 IANA NEWS 항목을 본다(13-1). DST 전환일 하루만이면 알람 계산(13-3)·집계 버킷(12-2).
- (나) 정확히 하루: 시각 없는 날짜(생일)를 자정 UTC 순간으로 저장했다(13-4). 숙박·구간이면 닫힌 구간 `[start, end]`(15-1).
- (다) 31일 가입자의 2월: 날짜 일치 스케줄러, 전 결제일에 1개월씩 더하는 연쇄 계산(13-2). 기준일을 저장하고 `기준일.plusMonths(n)`.

### 6. 0이 정상의 증거가 아닌 경우

- 시산표 0: 시산표는 전표마다 차대 합이 0인지만 본다. 동시 결제 두 건 승인으로 잔액 −3,000이 돼도 두 전표는 균형이다(24-4). 재시도로 생긴 이중 충전도 균형 잡힌 전표 둘이다(24-5).
- 대사 0건: 차이를 발견 즉시 내부를 외부 값으로 덮어썼거나(25-5), 금액으로 짝을 지어 엉뚱한 주문에 붙였다(26-3).
- 에러 로그 0건: 하류가 없는 필드를 기본값으로 덮어 합계 0원(18-1), ACL이 모르는 코드를 UNKNOWN으로 번역(19-2). 오류가 번역기에서 지워졌다.

### 7. 버전 충돌 급증

- 원인: 버전 단위가 업무상 독립적인 수정까지 묶는 거대 애그리거트(05-1).
- 재시도를 늘리면: 같은 충돌이 반복돼 재시도 로그와 응답 시간이 더 늘어난다.
- `@Version`을 빼면: 예외가 사라지고 경계 밖 불변식 위반 행이 생긴다(용량 10에 24점, 05-2). ②의 신호가 ③의 조용한 위반으로 내려간다.
- 근본: 진짜 불변식을 다시 적고, 그 불변식이 걸치지 않는 자식을 별도 애그리거트로 떼어 ID로 참조한다. 같은 시나리오로 충돌 수를 다시 잰다. 너무 잘게 쪼개 진짜 불변식을 못 지키지 않게 한다(05-5).

### 8. 504인데 결제됨

- 원인: 타임아웃을 실패로 처리하고 주문을 닫았다. 결과를 확정하는 경로가 없었다(25-1). 응답 없음을 성공·실패 중 하나로 뭉갠 것이다(26-2).
- 확정 경로: 결과를 UNKNOWN으로 두고 ① PG 조회 API로 1차 확정, ② 정기 대사로 2차 확정. 방치된 UNKNOWN은 PG 취소 또는 주문 생성으로 처리한다. 이미 새 주문으로 재결제한 고객은 주문 ID 키 대사로는 안 잡히므로, 같은 고객·같은 금액·가까운 시각의 결제를 "이중 청구 후보"로 묶어 사람이 확인한 뒤 한쪽을 취소·환불한다(25-1).
- 필요 데이터: 요청에 우리 주문 ID를 싣고, 응답의 외부 거래 ID를 저장한다(`UNIQUE`). 없으면 금액·시각으로 손 매칭하게 된다(25-3). 대사 날짜 경계를 외부와 같게 자른다(25-4).

### 9. 합계 0원 — 기본값 번역

- 공통 원인: 번역 지점이 없는 필드·모르는 코드를 **기본값**(0, UNKNOWN, `getOrDefault`)으로 바꿨다. 오류가 번역에서 지워져 로그가 없다(18-1 · 19-2).
- 첫 경우는 관계 미정의도 겹친다. 하류는 사실상 순응자인데 상류는 몰랐다(18-1).
- 대처: 기본값 없는 전수 매핑, 실패는 예외 + 상관 ID 로그 + 번역 실패 수 지표(19-2). 관계를 정하고, 고객/공급자라면 하류 계약 테스트를 상류 CI에 넣는다(18-1). 이미 0원으로 저장된 건은 대사로 찾아 정정한다(19-1).

### 10. 위 칸으로 끌어올리기

- 모델링 결정과 당긴 뒤 형태는 각 leaf의 대처·실험에서 왔다. "덮어 버리는 대응" 칸은 이 노트의 해석이다.

| 모델링 결정 | 당긴 뒤 형태 | 덮어 버리는 대응 | leaf |
|---|---|---|---|
| 기본 거부 전이 표, `default` 없는 `switch` 식 | 상태 누락이 컴파일 오류 | `default -> 기타`·`else` 분기 추가 | 11-3 · 08-2 |
| 의도 메서드 + DB `CHECK` | 불법 상태가 저장 시 거절 | setter 다시 열기, 제약 끄고 데이터 핫픽스 | 06-1 |
| `Money.plus`가 통화 불일치 거부 | 즉시 예외 | 금액을 `long`으로 되돌림 | 04-2 · 12-4 |
| ACL이 모르는 코드를 예외로 | 번역 실패 예외 | `getOrDefault`·UNKNOWN 기본값 | 19-1 · 19-2 |
| 전표·분개 한 트랜잭션 + 지연 제약 트리거 | 불균형 전표 커밋 거절 | 트리거 끄고 이관 스크립트 실행 | 24-3 |
| 정책이 모든 유형에 있는지 시작 시점 검사 | 기동·테스트 실패 | 맵 조회 null을 무시 | 08-3 |
| 낙관적 잠금(`@Version`) | 충돌 예외 | 버전 열 제거 | 05-1 · 05-2 |
