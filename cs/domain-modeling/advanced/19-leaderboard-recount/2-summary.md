## 한눈에 — 쉽게 말하면

**순위 재계산 = 운동회가 끝나고 메달까지 나눠줬는데, 며칠 뒤 한 선수의 기록이 취소됐을 때 "그럼 금메달은 누구 거냐"는 문제.**

- 발표 순간의 기록으로 보면 a가 1등이고, 지금 기록으로 보면 b가 1등이다. **두 답 중 어느 것도 틀리지 않았다 — 기준 시점이 다를 뿐이다.** 그리고 메달(경품)은 이미 나갔다.
- 이벤트 순위표도 똑같은 구조다. 참여는 이벤트 중에 하지만 **취소는 나중에**, 심지어 이벤트가 끝난 뒤에 들어온다(청약철회 등).
- 여기에 동점 문제가 겹친다: 동점을 안 가르면 "상위 3명"이 네 명이 될 수 있는데 경품은 세 개뿐이다.
- "참여 금액 순으로 상위 3명"이라는 한 문장에 **정해지지 않은 규칙이 3개** 숨어 있다.

```text
  3/31 23:00  a 가 10,000 참여
  3/31 22:00  b 가  8,000 참여
  4/01 00:00  이벤트 종료, 순위 발표          → 1등 a
  4/03 10:00  a 의 참여가 취소됨
  4/05        다시 계산하면                   → 1등 b

  발표할 때 1등이던 사람이 며칠 뒤 순위표에서 사라진다.
```

실무 예: 이벤트 경품 순위, 게임 시즌 랭킹 정산, 크라우드펀딩 후원 순위 — "발표 후 환불/취소"가 있는 모든 순위.

## 전체 흐름

```text
요구사항: "참여 금액 순으로 상위 3명" — 숨은 3택

  ① 언제 기준으로 세나 (Snapshot)
       AS_OF_END  종료 시점의 상태 — 그 뒤 취소는 안 본다. 발표한 값이 안 바뀐다
       AS_OF_NOW  지금 상태 — 늦은 취소도 반영. 발표한 값이 바뀐다

  ② 동점을 어떻게 가르나 (TieBreak)
       EARLIEST  먼저 그 금액에 도달한 사람이 위
       LATEST    나중에 도달한 사람이 위
       NONE      안 가른다 — 같은 등수

  ③ 등수를 어떻게 매기나 (RankStyle)
       COMPETITION  표준 경쟁: 1 2 2 4 (동점 다음이 건너뛴다)
       DENSE        조밀:      1 2 2 3 (안 건너뛴다)

  counts()    그 참여를 세나 (종료 정각 제외 + 스냅샷 규칙)
  standings() 사람별 합계 + 도달 시각 (합 0인 사람 제외)
  rank()      정렬 + 등수 부여
  winners()   rank ≤ topN 전부 — 동점을 안 가르면 정원이 넘칠 수 있다
```

## 규칙 1 — 기준 시점: 종료 시점인가 지금인가

**어떤 요구사항인가**: "취소는 나중에 들어온다. 그리고 그 나중이 이벤트 종료 뒤일 수 있다."

코드 번역 — `counts()`의 판정:

```text
참여가 종료 시각 이후            → 어느 규칙에서도 안 센다 (이벤트 밖)
안 취소된 참여                   → 센다
취소된 참여:
  AS_OF_NOW                     → 안 센다 (지금은 취소 상태니까)
  AS_OF_END + 취소가 종료 후     → 센다 (종료 시점엔 아직 없던 일)
  AS_OF_END + 취소가 종료 전     → 안 센다 (종료 시점에 이미 취소)
```

**갈리는 것은 "종료 시각과 지금 사이에 들어온 취소"뿐이다** — 종료 전 취소는 두 기준이 같은 답을 낸다. 그리고 그 구간은 개발할 때 만드는 자료에 잘 안 생긴다. 측정: 취소 0%면 두 기준이 100번 다 같고, 취소가 **5%만 되면 상위 3명이 33/100 회 바뀌고 1등이 11번 바뀐다.**

측정의 결정타: 재계산 시점 하나가 동점 규칙 둘보다 **16배** 크다 — 같은 시점 안에서 동점 규칙만 바꾸면 최대 5/100 갈리는데, 시점을 바꾸면 최소 82/100 갈린다. **동점 규칙은 회의에서 오래 얘기하고, 재계산 시점은 아무도 안 묻는다.**

## 규칙 2 — 종료 시각 정각은 이벤트 밖

**어떤 요구사항인가**: README 함정 1번 — "종료 시각을 포함으로 잡지 마라."

**손계산**: 종료 2026-04-01 00:00일 때 —

```text
  03/31 23:59:59 참여  → 센다
  04/01 00:00:00 참여  → 안 센다     (!at.isBefore(endsAt) → 제외)
```

"4월 1일까지"와 "4월 1일 0시까지"가 이 한 건을 가른다. 그리고 **이벤트 마감 직전 1초에 참여가 몰린다** — 경계값이 제일 붐비는 자리다.

## 규칙 3 — 합이 0인 사람은 순위표에서 뺀다

**어떤 요구사항인가**: README 함정 3번 — 전부 취소한 사람을 남기면 순위표 맨 아래 0원짜리 줄이 생기고, **그 줄이 등수를 하나 차지한다.** `standings()`는 totals에 올랐어도 합 0이면 안 낸다(구현상 취소된 참여는 애초에 안 더해지고, 유효 합이 있는 사람만 나온다).

**도달 시각(reachedAt)**: 그 금액에 도달한 시각 = **마지막 유효 참여 시각**. 참여를 시각 순으로 훑어야 한다 — 안 훑으면 도달 시각이 입력 순서를 탄다. 같은 시각끼리는 안 가른다(변종 검증: 번호 타이브레이커는 죽은 코드였다 — 어느 쪽을 나중으로 놓아도 도달 시각이 같으니까. 지우고 이유를 주석에 적었다).

## 규칙 4 — 동점: 같은 자료에서 1등이 셋으로 갈린다

**예시 입력**: a 10,000(종료 5시간 전 도달), b 10,000(1시간 전 도달), c 5,000.

```text
  EARLIEST(먼저 도달이 위)   a b c   등수 1 2 3
  LATEST(나중 도달이 위)     b a c   등수 1 2 3
  NONE(안 가름)              a b c   등수 1 1 3

  1등이 a도 되고 b도 되고 둘 다도 된다.
```

**안 가르면 정원이 넘친다**: a b c 셋 다 10,000이면 NONE에서 셋 다 1등 → **상위 2명이 세 명.** 경품은 두 개뿐이다(README 함정 4번). `winners()`는 rank ≤ topN을 전부 넣기 때문이다.

측정 — **동점은 금액 단위가 만든다**: 1원 단위면 동점이 아예 안 나서(0/100) 동점 규칙 없이도 돌아간다. 그런데 포인트·응모권처럼 값이 굵은 이벤트(500,000원 단위)로 옮기는 날 **52/100 회차에서 정원이 넘친다.**

**결정성**: 안 가르는 규칙에서도 목록 순서는 사용자 번호로 세운다 — 순위표는 화면에 줄로 나오고, 등수가 같아도 위아래가 새로고침마다 바뀌면 안 된다.

## 규칙 5 — 등수 방식은 "안 가를 때만" 일을 한다

**예시 입력**: a 10,000, b 10,000, c 5,000, d 3,000.

| 조합 | 등수 |
|---|---|
| 안 가름 + 표준 경쟁(COMPETITION) | 1 1 3 4 (동점 다음이 건너뛴다) |
| 안 가름 + 조밀(DENSE) | 1 1 2 3 |
| 가름 + 표준 경쟁 | 1 2 3 4 |
| 가름 + 조밀 | 1 2 3 4 — **같다** |

동점을 가르면 더 이상 동점이 없으므로 두 등수 방식이 통째로 같아진다 — **설정 화면에 둘을 두고 동점 가르기를 켜면 그 설정이 아무 일도 안 한다** (17장의 "되돌리기를 켜면 재시도 범위가 죽는다"와 같은 패턴: 규칙끼리의 간섭).

**조밀 등수의 함정**: a b 동점, c d 동점, e 다섯 명에서 "3등까지" 뽑으면 —

```text
  표준 경쟁  1 1 3 3 5  → 4명
  조밀       1 1 2 2 3  → 다섯 명 전부
```

조밀 등수는 번호가 촘촘해서 "3등까지"가 훨씬 넓다. 측정: 100회 × 상위 3명 = 정원 300에서, 가르면 정확히 300, 안 가름+표준 경쟁 301, 안 가름+조밀 **305**.

## 경계·모서리 케이스

| 함정 | 올바른 처리 |
|---|---|
| 종료 시각 정각 포함 | `at.isBefore(endsAt)`만 센다 — 마감 직전 1초에 참여가 몰린다 |
| 취소를 지금 상태로만 봄 | Snapshot 2택을 드러낸다 — 발표한 값이 말없이 바뀐다 |
| 종료 전 취소 vs 종료 후 취소 | 종료 전 취소는 두 기준이 같다 — 갈리는 건 종료~지금 사이의 취소뿐 |
| 전부 취소한 사람이 순위표에 남음 | 합 0인 사람 제외 — 0원 줄이 등수를 차지한다 |
| 참여하기 전에 취소 | 생성자에서 예외 (`cancelledAt < at` 금지), 금액 ≤ 0도 예외 |
| 동점 규칙 없음 | 상위 N명이 N명이 아니게 된다 — 경품 수와 어긋남 |
| 동점 목록 순서가 입력 순서를 탐 | userId 최종 타이브레이크로 결정성 보장 |
| 도달 시각이 입력 순서를 탐 | 시각 순 정렬 후 집계 |
| 개발 자료로 검증 | 취소도 동점도 없으면 12조합이 통째로 같다(1,100번 비교 0 갈림) — 갈래를 보려면 취소·동점을 일부러 넣어야 한다 |

## 핵심 문장

- 발표 순위와 재계산 순위가 다를 때 **어느 쪽도 틀리지 않았다 — 기준 시점이 다를 뿐이다.** 그래서 기준 시점(Snapshot)은 코드가 몰래 정할 게 아니라 도메인이 명시할 규칙이다.
- 재계산 시점 하나가 동점 규칙 둘보다 16배 크게 답을 바꾼다 — 회의에서 오래 얘기하는 것과 실제로 답을 바꾸는 것은 다르다.
- 동점을 안 가르면 "상위 3명"이 3명이 아니게 된다 — 그리고 동점은 규칙이 아니라 **금액 단위의 굵기**가 만든다(1원 단위 0건 → 500,000원 단위 52/100).
- 동점을 가르면 등수 방식(표준/조밀)이 죽는다 — 규칙 셋은 독립이 아니라 서로 간섭한다.
- 취소도 동점도 없는 개발 자료에서는 12조합이 전부 같은 답을 낸다 — 갈래는 저절로 안 보이고, 일부러 넣어야 보인다.

## 용어 풀이

- **스냅샷(snapshot)**: 어느 시점의 상태를 사진 찍듯 고정해서 보는 것. AS_OF_END는 종료 시점 사진, AS_OF_NOW는 지금 사진.
- **재계산(recount)**: 이미 발표한 순위를 나중에 다시 계산하는 것. 늦은 취소가 있으면 답이 달라진다.
- **타이브레이크(tie-break)**: 동점을 가르는 보조 규칙. 먼저 도달/나중 도달/안 가름.
- **도달 시각(reachedAt)**: 그 사람이 최종 합계 금액에 도달한 시각 — 마지막 유효 참여의 시각.
- **표준 경쟁 등수(competition ranking)**: 1 2 2 4 — 동점 다음 등수가 인원수만큼 건너뛴다.
- **조밀 등수(dense ranking)**: 1 2 2 3 — 안 건너뛴다. "3등까지"의 범위가 훨씬 넓어진다.
- **경계값(boundary)**: 규칙이 갈리는 정확한 지점. 여기서는 종료 시각 정각 — 포함이냐 제외냐가 한 건을 가른다.
- **결정성(determinism)**: 같은 자료면 입력 순서와 무관하게 같은 순위표. 화면의 위아래가 새로고침마다 바뀌면 안 된다.
- **청약철회**: 결제 후 일정 기간 안에 취소할 소비자의 법적 권리. "종료 뒤 취소를 막으면 되지 않나"가 안 되는 이유.
- **죽은 코드/죽은 설정**: 다른 규칙 때문에 실행돼도 아무 효과가 없는 코드나 설정. 동점을 가르면 등수 방식이 그렇게 된다.
