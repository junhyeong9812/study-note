### A. 과제

#### 0. 요구사항과 실제 기록 (원본 README)

```text
  09:00 IN                       정상
  09:00 IN, 09:03 IN, 18:00 OUT  출근을 두 번 찍었다
  22:00 IN, 다음날 06:00 OUT     자정을 넘겼다
  09:00 IN                       퇴근을 안 찍었다

  "출근부터 퇴근까지가 근무 시간" 은 맞는 말인데, 기록이 그렇게 안 생겼다.
```

- "근태는 규칙보다 데이터가 문제인 도메인"이라는 말은 무슨 뜻인가?
- "출근부터 퇴근까지가 근무 시간" 한 줄이 **안 말해주는** 결정은 무엇무엇인가?
- 출근이 두 번 찍히면 앞을 쓰나 뒤를 쓰나 — 각각 누구에게 유리한가?
- 자정을 넘긴 근무는 어느 날의 근무인가?
- 퇴근을 안 찍은 기록은 버리나 살리나?
- 휴게 시간을 "근무 시간에서 뺀다" 한 줄은 무엇을 안 정하는가?


### B. 개념

#### 6. 측정 — 자정 규칙 (원본 README 하나)

- 10일치 기록 500벌에서 날짜별 근무 시간이 다른 경우는 몇 회인가?
- 하루 기준 최대 차이는 몇 분인가?
- 22시 출근·다음날 6시 퇴근일 때 두 규칙의 3/1·3/2 값은 각각 얼마인가?
- 두 규칙의 **합계**는 어떻게 되는가?
- 합계가 같은데도 이 규칙이 중요한 이유는 무엇인가 — 어디서 갈리는가?
- "어차피 합계는 같으니까"로 넘어가면 무엇에서 틀리는가?

#### 7. 측정 — 휴게 공제 (둘)

- 기준 4시간·공제 30분을 넣으면 500벌 중 몇 벌에서 값이 달라지는가?
- 요구사항 한 줄("휴게 시간은 근무 시간에서 뺀다")이 안 정하는 것은 무엇인가?
- 하루에 한 번 출근하는 사람만 보면 두 방식이 왜 같은가?
- 전일 근무자 데이터로만 시험하면 무엇을 놓치는가?

#### 8. 측정 — 데이터의 지저분함 (셋)

- 기록 몇 줄 중 몇 줄이 짝이 안 맞았고, 몇 퍼센트인가?
- 그 데이터에 일부러 넣은 누락·중복 비율은 각각 얼마인가?
- "짝이 맞는다를 전제로 짠 코드"는 실데이터에서 어떻게 되는가?
- 버리기로 정했으면 무엇을 할 수 있어야 하는가?

#### 9. 변종 검증에서 고친 것 (원본 README 절 이관)

- 어떤 줄을 지웠고, 왜 지울 수 있었는가?
- 그 불변식을 지켜주는 것은 무엇인가?
- 정렬을 빼면 불변식이 깨지는데, 왜 그것을 두 곳에서 막지 않는가?
- "같은 것을 두 곳에서 막지 않는다"는 판단의 기준은 무엇인가?

#### 10. 생각해볼 것 (원본 README 이관)

- 퇴근을 안 찍은 사람을 버리는 대신 "자정까지 일한 것"으로 치면 무엇이 달라지는가?
- 출근 중복에서 뒤의 것을 쓰기로 했다 — 사원에게 불리한 쪽인데 규정에 어떻게 쓰는가?
- 근무 시간이 아니라 급여를 계산하려면 무엇이 더 필요한가?
- 기기 시계가 5분 어긋나 있으면 그것을 어떻게 알아채는가?

- 이 박스의 짝짓기는 실무의 어떤 로그 처리와 같은 구조인가?
