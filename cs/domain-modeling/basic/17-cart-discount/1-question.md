### A. 과제 (Cart 의 TODO 1~3)

#### 1. 챕터 지문 — 말로 된 요구사항

```text
10,000 원에 "10 퍼센트" 와 "1,000 원 할인" 을 적용하면 얼마인가.

  정률 먼저   10,000 -> 9,000 -> 8,000
  정액 먼저   10,000 -> 9,000 -> 8,100

100 원 차이다. 그리고 그 100 원이 어느 쪽인지는 아무 문서에도 없다.

정할 것이 셋이다. 순서, 정률의 기준, 반올림 시점. 셋 다 요구사항에 안 적힌다.
```

- "쿠폰을 여러 장 쓸 수 있다"는 한 줄에 안 들어 있는 결정 셋은 각각 무엇인가?
- 그 셋을 "안 정한 채" 코드를 쓰면 무슨 일이 생기는가?
- 이 챕터는 그 셋을 코드 어디에 두었는가 — 왜 그 자리인가?
- 세 결정 말고 요구사항이 침묵하는 것이 더 있는가(할인이 금액을 넘으면? 상한은?)?

#### 4. 계약으로 주어진 Discount — 여기서 이미 정해진 것들

```java
/** 이 할인이 base 에 적용될 때 깎이는 금액. 상한과 잔액을 넘지 않는다. */
public BigDecimal deductionFrom(BigDecimal base, BigDecimal remaining) {
    BigDecimal raw = kind == Kind.PERCENT
            ? base.multiply(BigDecimal.valueOf(value)).divide(BigDecimal.valueOf(100))
            : BigDecimal.valueOf(value);
    if (cap > 0 && raw.compareTo(BigDecimal.valueOf(cap)) > 0) {
        raw = BigDecimal.valueOf(cap);
    }
    return raw.min(remaining);
}
```

- 자르는 순서가 "상한 먼저, 잔액 나중"인데 뒤바꾸면 결과가 달라지는가?
- `cap == 0` 이 "상한 없음"을 뜻하게 한 설계의 위험은 무엇인가?
- `raw.min(remaining)` 한 줄이 막아주는 사고를 한 문장으로 말하면?
- 정률 100% 초과·0% 이하·빈 이름·음수 상한은 어디서 막히는가?
- 돈 계산에 `double` 이 아니라 `BigDecimal` 을 쓴 이유는 무엇인가?

### B. 개념

#### 5. 측정 하나 — 적용 순서

- 1,000건에서 순서 때문에 갈리는 건수와 합계 차이는 각각 얼마인가?
- 건당 평균과 최대 차이는 각각 얼마인가?
- 정률 먼저와 정액 먼저 중 손님에게 유리한 쪽은 어디이고 왜 그런가?
- `AS_GIVEN` 이 "가장 위험한 기본값"인 이유는 무엇인가?

#### 6. 측정 둘 — 정률의 기준 (순서보다 두 배 크고 더 조용하다)

- 원가 기준과 누적 기준의 1,000건 합계는 각각 얼마이고 차이는 얼마인가?
- 이 결정이 순서 결정보다 "더 조용하다"는 말은 무슨 뜻인가?
- 코드에서 이 결정은 어떤 단어 하나의 차이로 나타나는가?
- 원가 기준이 더하기이고 누적 기준이 곱하기인 이유를 수식으로 쓸 수 있는가?
- 12번 게임 버프의 무엇이 여기서 다시 나오는가?
- 원가 기준에서 60% 두 장이면 결제 금액은 얼마가 되는가?

#### 7. 측정 셋 — 반올림 시점 (금액은 작고 소리는 크다)

- 반올림 시점 때문에 갈리는 건수와 총액 차이는 각각 얼마인가?
- 앞의 두 결정보다 훨씬 작은데 왜 회계에서 문제가 되는가?
- "순서와 기준은 정하면 끝이고, 반올림은 정해도 안 맞는다"는 무엇이 안 맞는다는 것인가?
- 매 단계 버림을 고르면 무엇이 언제나 성립하는가?
- "금액이 큰 결정과 시끄러운 결정이 다르다"를 우선순위 정하기에 어떻게 쓰는가?

#### 8. 측정 넷 — 할인이 하나면 세 결정이 전부 사라진다

- 할인이 하나일 때 순서·기준·반올림이 각각 왜 무의미해지는가?
- 여섯 가지 조합이 1,000건 전부에서 같은 답을 낸다는 사실이 테스트 설계에 주는 교훈은?
- 15번 쿠폰의 "조건 하나"와 같은 자리라는 말은 무슨 뜻인가?

#### 9. 측정 다섯 — 정률끼리는 합계가 같고 내역이 다르다

- 10,000원에 10%와 20%(누적 기준)를 어느 순서로 넣어도 결제 금액이 같은 이유는?

- "결과가 같으니 순서는 상관없다"가 반쪽만 맞은 이유는 무엇인가?
