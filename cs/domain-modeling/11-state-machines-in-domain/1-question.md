# domain-modeling/11-state-machines-in-domain — 질문

## 질문

1. (왜) 메서드마다 "안 되는 상태"를 if문으로 막는 코드가 정상 경로 테스트를 다 통과하면서도 불법 전이를 허용하는 이유는? 허용 목록과 차단 목록의 차이로 설명하라.
2. (그림) 이 노트의 주문 명세(상태 8, 이벤트 7, 허용 9칸)를 상태 전이도로 그려라. 취소가 허용되는 상태는 어디까지인가?
3. (예측) 실험의 if문 예시는 56칸 중 몇 칸을 명세와 다르게 판정했나? 그중 커리큘럼 ⚠의 "환불된 주문 배송"에 해당하는 칸은? ON_HOLD를 추가하면 수가 어떻게 바뀌나?
4. (경계) 전이를 거부하는 두 경우 — 표에 칸이 없음, 칸은 있는데 가드가 거짓 — 는 어떻게 다르며, 왜 둘을 구분해 돌려주나?
5. (연결) Harel(1987) statechart가 평평한 상태 기계에 더한 세 요소는? 그중 계층과 직교 영역은 도메인 모델링에서 어떤 문제를 줄이나?
6. (예측) PostgreSQL 17 READ COMMITTED에서 두 트랜잭션이 같은 PREPARING 주문을 읽고 앱에서 검사한 뒤, 상태 조건 없이 각각 CANCELLED·SHIPPED로 UPDATE한다. 겹침을 강제한 200건에서 "둘 다 성공"은 몇 건인가? 조건부 UPDATE와 REPEATABLE READ에서는?
7. (적용) 동시 전이를 막는 조건부 UPDATE SQL을 써라. 영향 행 수 0을 받은 쪽은 무엇을 해야 하나?
8. (장애 진단) 배포 후 오래된 주문들의 상태가 엉뚱하게 보인다. enum에 상태 하나를 중간에 추가한 배포였다. 무엇을 의심하고, 어떻게 예방하나?
9. (적용) 상태가 `PAID_ON_HOLD`·`PREPARING_ON_HOLD`처럼 곱으로 불어난다. 원인과 고치는 방향은?
10. (장애 진단) "환불됐는데 배송도 됐다"는 민원이 들어왔다. 이미 저장된 데이터에서 불법 전이와 모순을 찾는 쿼리 두 가지를 말하라.
