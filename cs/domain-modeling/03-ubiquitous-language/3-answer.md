# domain-modeling/03-ubiquitous-language — 정답

## 정답

### 1. 언어가 둘일 때

- 번역이 곳곳에 낀다. 개발자는 전문가를 위해, 전문가는 개발자와 다른 전문가 사이에서 번역한다.
- Evans 2장이 든 해악
  - 번역은 부정확하고 이해의 단절을 숨긴다.
  - 양쪽 말을 하는 몇몇이 정보 흐름의 병목이 된다.
  - 같은 용어를 서로 다르게 쓰면서 그 사실을 모르는 균열이 생겨, 맞물리지 않는 소프트웨어가 된다. 번역 노력이 깊은 모델 통찰을 막는다.

### 2. 어휘와 범위

- 어휘: 모델의 클래스·주요 연산 이름, 모델에 명시된 규칙, 팀이 쓰는 패턴 이름, 컨텍스트 맵 같은 큰 구조의 이름(Evans 2장).
- 2003년 책: 보편 언어는 하나의 모델을 전제한다. 여러 모델의 공존은 14장(Maintaining Model Integrity)에서 다룬다.
- DDD Reference 2015: 처방에 "Within a bounded context"를 넣어, 바운디드 컨텍스트 안에서 그림·글·말에 같은 언어를 쓰라고 적는다.

### 3. 실험 A

- `COMPLETED` 주문 수: 5(결제된 5건이 모두 켜진다. 배송 끝 2건도 그 안에 있다).
- 배송 전인데 환불 거절: 3건(결제만 끝난 주문 3건).
- 물류팀이 기대한 "배송 끝" 2건과 대시보드 5건이 다르다. 용어를 `PAID`·`DELIVERED`로 나눈 코드에서는 환불 가능이 3건이다.

### 4. 실험 B

- 5 ms 뒤다. 호출자 의도(5000 ms)와 1000배 어긋나지만 컴파일·실행 모두 오류가 없다.
- `Duration` 인자에 `5`를 넘기면 `javac`가 `incompatible types: int cannot be converted to Duration`으로 거부한다. `Duration.ofSeconds(5)`를 넘기면 5000 ms다.

### 5. Modeling Out Loud

- 보편 언어 문장: 3번 "A Routing Service finds an Itinerary that satisfies a Route Specification."
- 1번: 기술 절차("DB에 넣는다")로 말해 모델 요소가 없다.
- 2번: 입력을 "출발지, 도착지 같은 것들"로 뭉뚱그리고 결과도 "필요한 게 다 든" 덩어리로 말한다. 경로 명세(Route Specification)라는 개념이 없다.

### 6. 용어집 한 줄 (예)

- 용어: 결제됨
- 정의(참이 되는 조건): PG 승인 응답을 받고 결제 기록이 저장됐다. 배송 여부와 무관하다.
- 코드 이름: `OrderStatus.PAID`, `Order.pay()`
- 쓰지 않는 말: 완료, done
- 단위·기준: 결제 금액은 원 단위 정수(`Money`), 기준 시점은 승인 응답 수신 시각
- 컨텍스트: 주문

### 7. 말과 이름의 불일치

- 빠진 것: 용어 변경을 모델 변경으로 보고 이름을 바꾸는 리팩터링. Evans·DDD Reference는 언어의 변화를 모델의 변화로 보고 클래스·메서드·모듈 이름을 맞추라고 한다.
- 바꾸기 비싼 외부 계약(DB 컬럼·이벤트 이름)은 매핑 계층에서 번역하고, 용어집에 "외부 이름" 칸을 둔다. 금지어 검사로 새 코드에 옛 이름이 들어오지 않게 한다.

### 8. 전사 단일 용어

- 잘못: 보편 언어의 범위를 조직 전체로 잡았다. DDD Reference 2015는 "Within a bounded context"로 범위를 한정한다.
- 바꾸기: 컨텍스트(예: 영업·청구·배송)마다 "고객"을 따로 정의한다. 컨텍스트 사이의 대응(같은 고객 ID, 다른 속성)을 명시적 번역으로 둔다(16·18·19번).

### 9. Mars Climate Orbiter

- 근본 원인(보고서 문장 요지): 궤적 모델에 쓰인 지상 소프트웨어 파일 "Small Forces"가 미터 단위를 쓰지 않았다. 인터페이스 명세는 N-s를 요구했는데 lbf-s로 전달됐고, 받는 쪽은 미터 단위로 가정해 추력 효과를 4.45배 작게 잡았다.
- 같은 구조: 장애 2 "단위 누락" — 만든 쪽과 쓰는 쪽이 서로 다른 단위를 가정했는데 값만 넘어갔다.
- 막는 방법: 단위를 타입에 넣는다(`Duration`, 값 객체 `Impulse(newtonSeconds)` 같은 것). 또는 이름·형식에 단위를 넣고(`impulseNewtonSeconds`, 설정 `5s`), 용어집 정의에 단위를 적는다.
