# domain-modeling/03-ubiquitous-language — 질문

## 질문

1. (왜) 팀에 언어가 둘(전문가 은어, 개발자 기술어)이면 무엇이 생기나? Evans 2장이 든 번역의 해악 세 가지를 대라.
2. (경계) 보편 언어의 어휘에는 무엇이 들어가나? 2003년 책과 DDD Reference(2015)는 보편 언어의 **범위**를 각각 어떻게 서술하나?
3. (예측) 주문 6건(결제·배송 끝 2건, 결제만 끝 3건, 아무것도 안 됨 1건)에 결제팀·물류팀이 같은 `COMPLETED`를 켜는 코드를 돌린다. "COMPLETED 주문 수"는? CS 정책 "완료 주문은 환불 대신 반품"을 `COMPLETED`면 환불 거절로 옮기면, 배송 전인데 거절되는 주문은 몇 건인가?
4. (예측) `retryAtMillis(now, 5)`를 호출자는 "5초 뒤"로 생각하고 불렀다. 실제로 몇 ms 뒤인가? 인자를 `Duration`으로 바꾼 메서드에 `5`를 넘기면 무슨 일이 생기나?
5. (연결) Evans의 "Modeling Out Loud" 예에서 세 문장 중 어느 것이 보편 언어로 한 문장인가? 나머지 둘은 무엇이 부족한가?
6. (판단) 용어집 한 줄에 무엇을 적어야 하나? "결제됨"을 예로 정의·코드 이름·쓰지 않는 말·단위·기준 시점 칸을 채워라.
7. (장애 진단) 회의에서는 "예약", 코드는 `Hold`, DB는 `reservation_tmp`다. 무엇이 빠졌고, DB 컬럼처럼 바꾸기 비싼 이름은 어떻게 다루나?
8. (장애 진단) 회사 전체의 "고객" 정의를 하나로 맞추려다 몇 달째 합의가 안 된다. DDD Reference 2015의 문구에 비춰 무엇이 잘못됐고 어떻게 바꾸나?
9. (연결) Mars Climate Orbiter 사고 보고서(1999-11-10)가 판정한 근본 원인은 무엇이고, 이 노트의 어느 장애와 같은 구조인가? 코드에서 같은 실수를 막는 두 방법은?
