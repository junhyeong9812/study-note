# web-platform/15-web-font-loading — 질문

## 질문

1. (왜) 웹 폰트는 왜 HTML·CSS보다 늦게 요청되나? 그동안 브라우저가 고를 수 있는 두 가지 표시 방식(FOIT·FOUT)은 각각 어떤 비용이 있나?
2. (경계) 폰트 표시 타임라인의 세 구간(block·swap·failure)은 각각 무엇을 뜻하나? `block`·`swap`·`fallback`·`optional`의 명세 권장 기간은?
3. (예측) 폰트를 4000ms 늦게 주면 Chrome 151에서 `auto`·`block`·`fallback`은 각각 언제 무엇이 보이나? `auto`가 명세 권장(3초)과 다르게 나오는 이유를 Chromium 소스로 설명하라. (실험 출력으로 확인)
4. (예측) 제목이 LCP 요소인 페이지에서 한글 폰트를 ① TTF 전체 4.5MB ② 37자 서브셋 7KB로 주면, 느린 모바일 망에서 `auto`와 `swap`의 LCP는 대략 어떻게 나오나? `swap`이면 큰 폰트도 문제없는가?
5. (경계) `unicode-range`로 라틴·한글 파일을 나눈 같은 `font-family`가 있다. 영어만 있는 페이지, 한글만 있는 페이지, 섞인 페이지는 각각 무엇을 받나?
6. (장애 진단) 폰트 preload를 넣었는데 Network에 같은 woff2가 두 번 보이고 콘솔에 경고가 있다. 경고 문구의 핵심과 원인, 고치는 법은?
7. (예측) `swap`으로 바꾼 뒤 폰트가 바뀌는 순간 본문이 한 줄 늘어 아래 상자가 24px 밀렸다. CLS는 대략 얼마였고, `optional`과 `size-adjust`로 맞춘 대체 폰트는 각각 어떻게 됐나? 각 방법의 대가는?
8. (경계) `optional`은 언제 웹 폰트를 쓰고 언제 끝까지 대체 폰트로 남나? preload와 함께 쓰면 Chrome 83 이후 무엇이 달라지나?
9. (장애 진단) Playwright로 FOIT 구간을 스크린샷으로 확인하려 했는데 매번 웹 폰트가 그려진 화면만 찍힌다. 왜 그런가?
10. (연결) 서브셋 대상 글자 집합 계산과 `unicode-range` 매칭은 어떤 자료구조·알고리즘으로 볼 수 있나? 사용자 입력 글자가 서브셋 밖이면 어떻게 그려지나?
