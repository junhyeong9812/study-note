# web-platform/16-long-tasks-and-web-workers — 질문

## 질문

1. (왜) 클릭 핸들러 안에서 300ms 계산을 하면 왜 **다른** 버튼의 클릭까지 늦어지나? 상호작용 지연의 세 조각(input delay·processing·presentation delay) 중 어느 조각이 각각 커지나?
2. (예측) 같은 300ms 일을 ① 한 덩어리 ② 30ms 조각 10개 + `scheduler.yield()` ③ 웹 워커로 할 때, 시작 60ms 뒤 누른 다른 버튼의 input delay와 긴 태스크 수는 대략 어떻게 나오나? (실험 출력으로 확인)
3. (경계) "긴 태스크"의 기준은 몇 ms인가? INP의 "좋음"·"나쁨" 경계와 집계 방식(백분위·무시 규칙)은?
4. (경계) `scheduler.yield()`와 `setTimeout(r, 0)`은 양보 뒤 이어지는 코드의 순서가 어떻게 다른가? 매 반복마다 양보하는 대신 문서가 권하는 방식은?
5. (예측) 32MB `Float64Array`를 워커에 ① 그냥 `postMessage` ② `postMessage(a, [a.buffer])`로 보내면 메인 스레드 비용과 보낸 뒤 `a.byteLength`는 각각 어떻게 되나? 객체 20만 개 배열은?
6. (장애 진단) 워커를 도입했는데 클릭 직후 화면이 여전히 굳는다. Performance 패널에서 무엇을 확인하고, 어떻게 고치나?
7. (장애 진단) 워커로 옮긴 코드가 `ReferenceError: document is not defined`를 낸다. 함수를 메시지에 넣으면 무슨 에러가 나나? 왜 그런가?
8. (연결) 양보로 긴 태스크는 0개가 됐는데 LoAF 항목(50ms 초과 프레임)이 남을 수 있는 이유는? 그때 INP를 더 줄이려면 어디를 봐야 하나?
9. (연결) 메인 스레드의 양보는 OS 스케줄링 관점에서 어떤 모델인가? 워커와 메인의 `postMessage` 통신은 어떤 자료구조·모델로 볼 수 있나?
