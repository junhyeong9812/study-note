# web-platform/09-js-modules-and-bundling — 질문

## 질문

1. (왜) 파일을 나눈 채로 보내는 것과 하나로 합쳐 보내는 것은 각각 무엇이 나쁜가? 번들러는 이 둘 사이에서 무엇을 하나(네 가지)?
2. (경계) CommonJS `require`와 ES 모듈 `import`의 차이를 "언제 불러오나"와 "값인가 바인딩인가"로 말하라. 트리 셰이킹이 ES 모듈에서 잘 되는 이유는?
3. (그림) ECMA-262 모듈 적재의 세 단계를 쓰고, 없는 이름을 import하면 어느 단계에서 어떤 오류가 나는지 표시하라. 순환 의존은 어떤 알고리즘으로 묶나?
4. (예측) `entry → m0 → … → m5` 사슬을 요청당 지연 100ms 조건에서 (a) 번들 없이 (b) `modulepreload`로 (c) 번들로 열면 마지막 모듈 실행 시각의 대략 순서와 값은? 왜 (a)가 느린가?
5. (예측) `utils.js`의 `export const TABLE = Array.from(...)`을 아무도 안 쓴다. esbuild 트리 셰이킹 뒤 번들에 남나? `/* @__PURE__ */`를 붙이면?
6. (예측) `"sideEffects": false`인 패키지에서 `import 'mylib/register.js'`(전역을 바꾸는 파일)를 하면 번들에 무슨 일이 생기나? esbuild는 무엇을 알려 주나? 같은 원리로 프로덕션에서만 생기는 증상은?
7. (예측) v1을 연 탭이 있는 상태에서 서버를 v2로 바꿔치기(옛 파일 삭제)하고, 그 탭에서 동적 import를 부르면 Chrome 151은 어떤 오류를 내나? webpack과 Vite는 같은 상황을 각각 어떻게 알리나?
8. (경계) `chart.js`만 고쳤는데 `main-*.js`의 해시도 바뀌었다. 왜인가? 이것이 캐시 효율에 주는 의미는?
9. (장애 진단) 배포 직후 기존 탭 사용자에게서 `ChunkLoadError`가 몰린다. 원인 두 가지와 예방 대책 세 가지는?
10. (연결) 첫 화면이 느려 번들을 보니 `main.js`가 크다. 분석·조치 순서를 말하라. 너무 잘게 나누면 어떤 문제가 다시 생기나?
