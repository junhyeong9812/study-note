# web-platform/10-rendering-strategies — 질문

## 질문

1. (왜) CSR·SSR·SSG를 "HTML을 어디서, 언제 만드나"로 구분해 보라. SSR과 SSG는 브라우저에 도착하는 HTML이 같을 수 있는데, 둘의 차이는 무엇에서 드러나나?
2. (그림) CSR과 SSR 페이지의 로드를 시간축으로 그리고, 각 방식에서 "보이는 시점"과 "반응하는 시점"을 표시하라. 왜 CSR은 두 시점이 거의 같고 SSR은 벌어지나?
3. (예측) 상품 2000개 페이지를 CPU 4×·150ms·1638.4kbps 스로틀에서 CSR과 SSR로 쟀다. FCP는 어느 쪽이 몇 배쯤 빠를까? SSR의 FCP와 반응 시작 사이 간격은 대략 얼마였나(실험 출력)?
4. (경계) 스트리밍 SSR에서 "셸"은 무엇인가? 느린 데이터를 기다리는 동안 브라우저에 먼저 가는 HTML과 나중에 가는 HTML은 어떻게 생겼고, 둘은 어떻게 맞물리나?
5. (예측) 서버는 `서버에서 렌더`, 클라이언트는 `typeof window`로 `브라우저에서 렌더`를 렌더한다. React 19 `hydrateRoot` 뒤 화면 글자와, 하이드레이션 전에 잡아 둔 `<p>` 노드가 그대로인지 예측하라. 운영 빌드에서 보이는 오류 형태는?
6. (적용) 날짜를 사용자 로캘로 보여 줘야 하는데 SSR에서 mismatch가 난다. react.dev가 권하는 두 가지 처리와 각각의 한계는?
7. (장애 진단) 배포 뒤 "다른 사람 주문 내역이 보인다"는 문의가 왔다. 앱 서버 로그에는 해당 사용자의 요청이 없다. 무엇을 의심하고, 어떻게 재현·확인·대처하나? 비슷한 실사건을 하나 들어라.
8. (장애 진단) 캐시를 다 꺼도 부하가 높을 때만 사용자 정보가 섞인다. SSR 서버 코드에서 무엇을 찾아야 하나?
9. (연결) SSR 문서에 마크업과 함께 JSON 데이터가 들어 있다. 왜 필요한가? 실험 페이지에서 둘의 크기는 각각 얼마였고, 이 중복을 줄이는 방향은 무엇인가(19·22번으로 이어짐)?
