# web-platform/22-islands-and-micro-frontends — 질문

## 질문

1. (왜) Islands와 마이크로 프론트엔드는 각각 어떤 문제를 푸나? 둘 다 "페이지를 조각으로 나눈다"면, 나누는 기준은 어떻게 다른가?
2. (경계) patterns.dev는 Islands와 진행형(progressive) 하이드레이션을 어떻게 구분하나? Astro의 `client:load`·`client:idle`·`client:visible`·`client:only`는 각각 언제 하이드레이션하나?
3. (그림) 마이크로 프론트엔드를 조합하는 장소(빌드 타임·서버·브라우저)와 방식(패키지·SSI/ESI·iframe·JS 런타임·Web Components)을 그리고, Jackson이 빌드 타임 통합을 권하지 않는 이유와 iframe의 한계를 말하라.
4. (예측) 셸은 React를 번들에 넣었다. 원격 팀이 React를 자기 번들에 넣은 컴포넌트를 셸의 React로 렌더하면 어떻게 되나? 원격이 셸이 공유한 React를 쓰면? 원격이 react-dom까지 넣고 자기 영역에 직접 마운트하면? 각 경우 JS 합계 바이트(실험 출력)는?
5. (원리) 4번의 첫 경우가 깨지는 이유를 react.dev의 설명으로 말하라. 이를 막는 Module Federation 설정 이름과 의미는?
6. (예측) 팀 A가 `.btn { background: blue }`, 나중에 배포된 팀 B가 같은 선택자에 red를 줬다. 팀 A 버튼의 배경은? 팀 A 위젯을 Shadow DOM 안에 자기 스타일과 함께 넣으면?
7. (예측) 헤더 섬과 사이드바 섬이 장바구니 수를 표시한다. 저장소 코드를 섬마다 번들에 넣으면 API 요청은 몇 번인가? 두 섬이 같은 URL의 ES 모듈을 import하면? HTML 표준의 어떤 개념이 이 차이를 설명하나?
8. (적용) 마이크로 프론트엔드 사이 통신을 공유 전역 객체 대신 무엇으로 하나? Jackson은 공유 상태를 왜 피하라고 하나?
9. (장애 진단) 셸이 React 메이저 버전을 올리자 오래된 원격 하나만 깨졌다. `singleton` 공유에서 무슨 일이 일어났고, 어떻게 예방하나?
10. (연결) 마이크로 프론트엔드 도입 전에 먼저 물어야 할 질문은? 서버 쪽 모놀리스 vs 마이크로서비스 판단과 어떻게 닮았나?
