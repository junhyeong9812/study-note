# web-platform/17-list-virtualization — 정답

## 정답

### 1. 무엇이 1만 행에 비례하나

- 요소 생성, 스타일 계산, 레이아웃, 메모리(DOM 노드)가 화면이 아니라 DOM 전체에 비례한다.
- 가상화는 보이는 행(+ overscan)만 DOM에 둔다 → DOM 크기가 **창 크기**에 비례한다.

### 2. 고정 높이 계산

- `first = floor(99840 / 30) - 5 = 3328 - 5 = 3323`
- `last = ceil((99840 + 600) / 30) + 5 = 3348 + 5 = 3353`
- 행 3323~3353(31행)을 `top = i × 30`으로 절대 배치한다.
- spacer(높이 `N × 30` = 300,000px)는 스크롤바 길이를 만드는 빈 상자다. 안 그린 행의 자리를 대신 차지한다.

### 3. 전체 DOM vs 가상화 (실험, headless Chrome 151, CPU 4×, 3회 + 사실 점검 재실행 3회)

| | 전체 DOM | 가상화 |
|---|---|---|
| `Nodes` | 108,589 | 300 |
| 로드 완료 | 5.7~7.8초 | 0.19~0.24초 |
| 폭 변경 레이아웃 | 2.1~2.7초 | 7~13ms |
| 렌더러 RSS(별도 실행, 스로틀 없음) | 약 321~322MB | 약 116~117MB |
| 스크롤 rAF 간격 p50 | 16.7ms | 16.7ms |

- 이 단순한 행에서는 스크롤 프레임이 병목이 아니었다. 비용은 로드·레이아웃·메모리에서 갈렸다.

### 4. 가변 높이

- 행마다 높이가 달라 `scrollTop / 높이`가 성립하지 않는다.
- 누적 높이 `pre[i]`(prefix sum)를 만들고 `pre[k] ≤ scrollTop`인 최대 k를 **이진 탐색**(O(log N))한다.
- 측정으로 높이가 자주 바뀌면 누적 배열 재계산이 O(N)이다 → **펜윅 트리**로 점 갱신·누적합 조회를 O(log N)에.

### 5. 측정 유무 (실험)

- ① 측정: 처음 그리기와 휠 스크롤 8번(그리기 9번)에 `scrollHeight`가 9가지 값(300,852 → … → 307,401)으로 바뀌었고, 점프 뒤 308,346이 됐다 → 스크롤바 길이·위치가 튄다. 겹침 0. 실제 전체 670,000px에는 아직 못 미친다(안 그린 행은 추정값).
- ② 측정 안 함: 높이 300,000 고정, 대신 화면 안 행 26쌍이 겹친다. 같은 `scrollTop=12000`에서 첫 행이 179(측정) vs 400(추정)으로 어긋난다.

### 6. 찾기·스크린리더

- 원인: DOM에 없는 행은 브라우저 찾기(실험의 `window.find('Row 9999')` = `false`)와 접근성 트리에도 없다.
- 보완: ① 앱 내 검색 + 결과 행으로 스크롤 ② `aria-setsize`·`aria-posinset`(표는 `aria-rowcount`·`aria-rowindex`)로 전체 크기·위치 전달 ③ 찾기가 핵심이면 `content-visibility:auto`(DOM에 남음).

### 7. `content-visibility:auto`

- DOM은 그대로 두고, 화면 밖 요소의 **내용물(자식)** 에 대한 스타일·레이아웃·페인트를 건너뛸 수 있다. 요소 자신의 상자는 남는다(크기는 `contain-intrinsic-size` — CSS Containment 2 §4). 찾기·접근성 트리에 남는다.
- 실험(4×, 재실행 포함): 로드 2.3~2.7초(전체 DOM 5.7~7.8초), 폭 변경 레이아웃 160~205ms(2.1~2.7초) — 좋아짐. 노드 수는 108,589 그대로.
- 대신 스크롤 중 프레임 p50 50~117ms, 최대 350~617ms(재실행 포함, 동시 부하로 흔들림 큼) — 나빠짐(화면에 들어오는 행의 렌더링을 스크롤 중에 하기 때문으로 해석). 이 조건의 값이고 실기기는 미확인.

### 8. 무한 스크롤 vs 가상화

- 가상화 = DOM 수를 묶는다. 무한 스크롤 = 데이터 로드를 페이지로 나눈다.
- 중복: 오프셋 페이지네이션 중 새 항목이 앞에 끼어 경계가 밀린다 → 커서(keyset) 페이지네이션, ID dedup, 가상화 키도 ID.

### 9. 포커스 소실

- 포커스된 행이 창 밖으로 나가면 가상화가 그 요소를 DOM에서 지운다 → 포커스가 `body`로 떨어진다.
- 대처: 포커스된 행을 렌더 범위에 고정하고, 키보드 이동 시 해당 행으로 스크롤한 뒤 포커스를 옮긴다.
