# web-platform/27-modal-dialog-behavior — 정답

## 정답

### 1. 바깥 클릭 안의 두 질문

- 판정: "이 클릭은 모달 안쪽인가?" — 관계 질문이다. 논리 트리에 묻는다. 클릭된 요소에서 부모 포인터를 따라 올라가되, portal로 띄운 요소에서는 논리 부모로 건너간다. dialog를 만나면 안쪽이다.
- 시점: "어느 이벤트·단계로 듣나?" — 시간 질문이다. 여는 click과 **다른 이벤트**(`pointerdown`)로, 앱의 `stopPropagation`에 막히지 않게 **캡처**로 듣는다.
- 둘을 섞으면 장애가 갈린다. 판정이 틀리면 portal 드롭다운을 누를 때 닫히고, 시점이 틀리면 열자마자 닫힌다.

### 2. 열자마자 닫힘

```text
click ── button ─ … ─ #card ◀ 핸들러: 열기 + document에 click 버블 닫기 등록 ★
                         ─ … ─ body ─ document ◀ ★ 실행: target=여는 버튼 → 바깥 → 닫기
```

- 닫기 리스너는 여는 click이 **올라가는 도중에** 등록됐다. 그 click은 아직 document에 도착하지 않았다. 도착하는 순간 document의 리스너 목록을 복사하므로 방금 붙인 닫기도 포함된다.
- 버블은 "처리됐다"고 멈추지 않는다. 위임 지점에서 열기를 처리해도 document까지 계속 간다.
- 즉 "두 번째 클릭"이 있는 게 아니다. 클릭 하나가 열기·닫기에 둘 다 쓰였다.
- `stopPropagation`을 부르는 버튼은 click이 document에 못 가서 버그가 가려진다(실험: `stopPropagation=true` → `open=true`).

### 3. 디스패치 도중에 붙인 리스너

- (가) document 버블: **실행된다.** 아직 들르지 않은 노드다.
- (나) document 캡처: 실행되지 않는다. 캡처 단계는 이미 지나갔다.
- (다) button 자신: 실행되지 않는다. button에 도착했을 때 목록을 이미 복사했다.
- 근거: WHATWG DOM §2.9의 invoke 단계 "Let listeners be a clone of event's currentTarget … event listener list" — "This avoids event listeners added after this point from being run."
- 실험 click 1의 출력에서 `document 버블 리스너[등록 click 1] 실행` 한 줄만 나왔다. (나)·(다)는 click 2부터 실행됐다.

### 4. `pointerdown`과 캡처

| 선택 | 막는 문제 |
|---|---|
| `pointerdown` | 모달은 여는 click에서 생긴다. 그 클릭의 `pointerdown`은 이미 끝났다 → 여는 클릭이 닫기 판정에 쓰이지 않는다 |
| 캡처 | 앱 코드가 버블에서 `stopPropagation`해도 document 캡처가 먼저 받는다 |

- click 캡처 대안: 열자마자 닫힘은 생기지 않는다(document 캡처는 여는 핸들러보다 먼저 지나감 — 3번 (나)). 그러나 입력창에서 눌러 끌다 오버레이에서 떼는 드래그에서 click이 공통 조상에서 나면 "바깥"으로 오판될 수 있다 (UI Events 원문 미대조) [?]. 누르는 순간 판정하는 `pointerdown`은 누른 지점 하나로만 판정한다.
- 알려진 위험(미검증): `pointerdown`에서 닫으면 이어지는 click이 모달이 사라진 자리 아래 요소에 떨어질 수 있다(click-through) [?]. jsdom 실험으로는 재지 못했다.

### 5. ESC가 전부 닫음

- 오해 정리: 같은 노드의 리스너는 "동시에"가 아니라 **등록 순서대로 하나씩** 실행된다. 부모가 닫히며 자식이 닫히는 것도 구조에 따라 실제로 일어난다.
- 예측(실험 출력과 같음):
  - 중첩(#2가 #1 dialog 안): `#2 닫힘(destroy), #1 닫힘(escape)` — 먼저 등록된 #1 리스너가 #1을 닫고, 정리가 자식 #2를 먼저 destroy한다. #2 리스너는 이미 해제돼 호출되지 않는다(표준의 removed 표시).
  - 형제: `#1 닫힘(escape), #2 닫힘(escape)` — 연쇄 없이 두 리스너가 각자 닫았다.
- 근본 원인: 각 리스너는 클로저로 자기 모달 하나만 안다. "내가 맨 위인가"를 아는 곳이 없다.
- 대처: 공유 keydown 리스너 하나 + 모달 스택. 리스너는 `stack[stack.length - 1]`만 닫는다. 스택이 0→1일 때 리스너를 붙이고 1→0일 때 뗀다. 비모달 portal은 스택에 넣지 않는다.

### 6. Tab이 빠져나감

```text
DOM 순서:  [뒤쪽1] [열기]  …  [A] [mid] [B]   (모달은 body 끝)
가두기 없음: [B] ─Tab─▶ 다음 요소 없음 → 브라우저 UI → 문서 처음 [뒤쪽1] → Enter → 보이지 않는 버튼

trapTab:   [A] ─▶ [mid] ─▶ [B] ─┐   가운데는 브라우저 기본 이동
            ▲                   │   [B]에서만 preventDefault + first.focus()
            └───────────────────┘
```

- 오버레이는 마우스만 막는다. Tab은 화면이 아니라 DOM 순서를 따른다.
- `trapTab`은 가장자리(마지막에서 Tab, 처음에서 Shift+Tab)와 포커스가 모달 밖일 때만 개입한다. 실험에서 mid는 `defaultPrevented=false`, B·A·뒤쪽1은 `true`였다.
- `preventDefault()`가 없으면 `first.focus()` 뒤에 브라우저가 원래의 "다음 요소로 이동"을 마저 해서 [mid]로 간다고 알려져 있다 (실브라우저 미측정) [?].
- 함께: 열 때 `previous` 기억 후 첫 요소로, 닫을 때 `previous.focus()`. 실험에서 복귀 없이 지우면 `active=body`였다.

### 7. 왜 Tab에서는 DOM인가

- Tab 이동은 브라우저가 DOM 순서로 한다. "Tab으로 닿는 요소와 처음·마지막"은 **위치·순서** 질문이라 DOM에 묻는 것이 맞다.
- 바깥 클릭의 "이 클릭이 모달에 속하나"는 **관계** 질문이라 논리 트리에 물어야 했다.
- 대가: 모달 안에서 연 portal 메뉴 항목은 DOM상 dialog 밖이라 순환 목록에 없다. 메뉴에 포커스가 있을 때 Tab을 누르면 `!inside`로 모달 첫 요소로 돌아간다. 메뉴가 열리면 포커스를 메뉴로 옮기고 메뉴가 자기 키보드를 처리하는 식으로 보완한다.

### 8. 세 잠금 구현

| 단계 | (가) naive | (나) 매번 저장 | (다) 참조 카운트 |
|---|---|---|---|
| 시작 | `'scroll'` | `'scroll'` (0) | `'scroll'` (0) |
| #1 열기 | `'hidden'` | `'hidden'` (1) | `'hidden'` (1) |
| #2 열기 | `'hidden'` | `'hidden'` (2) | `'hidden'` (2) |
| #2 닫기 | `''` ← #1이 열려 있는데 풀림 | `'hidden'` (1) | `'hidden'` (1) |
| #1 닫기 | `''` ← 원래 값 소실 | `'hidden'` (0) ← 영원히 잠김 | `'scroll'` (0) ✓ |

- (나)는 #2 열기 때 이미 `'hidden'`인 값을 "원래 값"으로 덮어썼다. 실험 출력과 같다.
- (다)는 실제 잠금·해제가 0↔1 경계에서만 일어난다.

### 9. 값 복사와 정리 경로

- `body.style.overflow`는 문자열을 돌려준다. 문자열은 원시값이라 변수에 **값이 복사**된다. 이후 스타일이 `'hidden'`으로 바뀌어도 `savedOverflow`는 저장할 때의 값 그대로다. 객체를 저장했다면 참조를 공유해 함께 바뀌었을 것이다.
- 모달이 사라지는 경로는 `close()`와 **논리 부모 destroy**(화면 전환·카드 삭제) 두 가지다. 해제를 `close()` 안에만 두면 두 번째 경로에서 카운트가 줄지 않는다. 스크롤이 계속 잠기고, 스택에 죽은 모달이 남아 ESC가 엉뚱한 것을 고르고, 포커스도 돌아가지 않는다.
- 대처: 해제(스택 제거·리스너 해제·`unlockScroll`·포커스 복귀)를 정리 함수 한 곳에 예약하고, 두 경로가 모두 그것을 부르게 한다. `closed` 플래그로 두 번 불려도 한 번만 실행한다.
