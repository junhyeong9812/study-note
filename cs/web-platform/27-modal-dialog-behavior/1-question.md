# web-platform/27-modal-dialog-behavior — 질문

## 질문

1. (왜) 모달의 "바깥 클릭 닫기"에는 서로 다른 질문 두 개가 들어 있다. 각각 무엇이고, 각각 무엇으로 답하나?
2. (장애 진단) 여는 버튼의 click 핸들러 안에서 `document.addEventListener('click', 바깥이면닫기)`를 붙였더니 모달이 열리지 않는다. "열 때는 아직 닫기 리스너가 없었는데 왜 닫히나?"에 답하고, `stopPropagation`을 부르는 버튼에서만 정상인 이유를 대라.
3. (예측) click 핸들러 안에서 (가) document 버블 리스너 (나) document 캡처 리스너 (다) 지금 처리 중인 button 자신의 리스너를 붙였다. 같은 click에서 실행되는 것은? DOM 표준의 어느 단계가 이를 정하나?
4. (경계) 바깥 감지를 `pointerdown` 캡처로 바꿨다. `pointerdown`과 캡처는 각각 어떤 문제를 막나? click을 캡처로 듣는 대안의 한계와, `pointerdown` 방식의 알려진 위험은?
5. (장애 진단) 모달마다 자기 ESC 리스너를 document에 붙였더니 ESC 한 번에 겹친 모달이 전부 닫힌다. "캡처라서 동시에 받아서인가, 부모가 닫히며 자식도 닫혀서인가?" 중첩·형제 두 구조에서 닫힘 reason이 각각 어떻게 찍힐지 예측하고, 근본 원인과 대처를 대라.
6. (그림) 모달 버튼 [A][mid][B] 뒤에 페이지 버튼이 있다. 가두기 없이 [B]에서 Tab을 누르면 포커스가 어디로 가는지 그리고, `trapTab`이 개입하는 위치와 `preventDefault()`가 필요한 이유를 설명하라.
7. (경계) 바깥 클릭 판정에서는 DOM `contains`가 틀렸는데, `trapTab`은 `contains`·`querySelectorAll`을 쓴다. 왜 여기서는 맞나? 그 선택의 대가는?
8. (예측) 원래 `body.style.overflow = 'scroll'`인 페이지에서 #1 열기 → #2 열기 → #2 닫기 → #1 닫기를 한다. (가) 카운트 없이 열 때 `'hidden'`, 닫을 때 `''` (나) 카운트는 있지만 잠글 때마다 원래 값 저장 (다) 참조 카운트 + 첫 잠금 때만 저장 — 단계마다 overflow 값을 예측하라.
9. (연결) `savedOverflow`에 저장한 값은 왜 나중에 `body.style.overflow`가 바뀌어도 그대로인가? 그리고 해제 코드를 `close()` 안에만 두면 어떤 경로에서 무엇이 깨지나?
