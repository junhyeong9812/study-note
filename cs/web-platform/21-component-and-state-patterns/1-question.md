# web-platform/21-component-and-state-patterns — 질문

## 질문

1. (왜) 서버 상태와 클라이언트 상태는 무엇이 다른가? "서버 상태는 클라이언트가 소유하지 않는다"는 말이 캐시 설계(키·신선도·무효화)로 이어지는 이유를 설명하라.
2. (그림) Flux, Redux, Elm Architecture의 데이터 흐름을 각각 그려라. Redux의 세 원칙은 무엇이고, 셋의 공통점은 무엇인가?
3. (예측) 행 1000개(`memo`로 감쌈)가 최상위 Context를 읽는다. 검색어를 그 Context에 두고 10글자를 입력하면 행 렌더는 몇 번인가? 검색어를 입력창 로컬 상태로 옮기면? 선택자 구독 스토어로 옮기면 렌더 수와 스크립트 시간은 어떻게 되나(실험 출력)?
4. (예측) 자식이 `const [p] = useState(price)`로 가격을 복사한다. 부모가 1000에서 +500을 두 번 하면 자식과 prop을 직접 쓰는 형제는 각각 무엇을 보이나? 일부러 첫 값만 써야 할 때 react.dev가 권하는 표기는?
5. (예측) 한 화면에 "각자 fetch" 컴포넌트 2개, 키 캐시(진행 중 promise 공유) 컴포넌트 2개, "전역 스토어에 한 번 복사" 컴포넌트 1개가 있다. 첫 화면의 API 요청 수는? 이름을 바꾸고 `invalidate('user')`하면 각 컴포넌트는 무엇을 보이나?
6. (경계) 제어 컴포넌트와 비제어 컴포넌트를 정의하라. `value`가 `undefined`로 시작했다가 문자열이 되면, 그리고 `onChange` 없이 `value`만 주면 개발 빌드는 무엇을 경고하나?
7. (적용) 상태 위치를 정하는 흐름(로컬 → 끌어올리기 → Context/스토어, 서버 데이터는 별도)을 그리고, 끌어올리기의 "가장 가까운 공통 부모"가 트리에서 무엇인지 말하라.
8. (연결) 리듀서가 폴드라는 말, 불변 상태 트리의 구조 공유가 얕은 비교를 O(1)로 만든다는 말을 각각 설명하라.
9. (장애 진단) 결제 후에도 주문 목록이 "미결제"로 보이고 새로고침하면 맞다. 코드에서 무엇을 찾고, 어떻게 고치나?
10. (장애 진단) 중간 컴포넌트 9개가 쓰지도 않는 prop을 넘기기만 한다. Context를 쓰기 전에 먼저 시도할 방법은?
