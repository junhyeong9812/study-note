# web-platform/08-web-performance-vitals — 질문

## 질문

1. (왜) `onload` 시간 하나로 페이지 성능을 판정하면 무엇을 놓치나? Core Web Vitals 세 지표는 각각 사용자 경험의 어느 면을 재나?
2. (경계) LCP·INP·CLS의 "좋음"과 "나쁨" 경계값은? 판정은 어떤 집계(백분위·분리 기준)로 하나?
3. (예측) 텍스트 문단이 먼저 그려지고 700ms 뒤 800×300 이미지가 그려진다. `largest-contentful-paint` 항목은 몇 개, 어떤 순서로 나오나? 사용자가 이미지 도착 전에 스크롤하면 어떻게 되나?
4. (계산) 뷰포트 800×600에서 높이 200px 문단이 y=129.875에서 y=429.875로 내려갔고, 이후 보이는 높이는 170.125px이다. 이동 점수를 계산하라. 영향 영역을 바운딩 박스로 잡으면 값이 어떻게 달라지나?
5. (예측) 클릭 핸들러가 20ms 일하는 페이지와 300ms 일하는 페이지에서 INP는 대략 얼마로 나오고 각각 어떤 등급인가? 300ms 쪽에서 세 조각(input delay·processing·presentation delay) 중 무엇이 큰가? (실험 출력으로 확인)
6. (경계) INP는 "가장 나쁜 상호작용"이라는데 정확히 어떻게 고르나? 상호작용이 한 번도 없으면? 호버·스크롤은 들어가나?
7. (예측) 같은 페이지를 데스크톱(스로틀 없음), 모바일(CPU 4×·150ms·1.6Mbps), 저사양(CPU 6×·400ms·0.4Mbps)으로 쟀다. 60/30/10% 비율로 섞은 20개 표본의 p50과 p75는 어느 조건의 값에 가까울까? 왜 p75를 쓰나?
8. (장애 진단) CI Lighthouse 점수는 95인데 Search Console에서 모바일 LCP가 "개선 필요"다. 랩과 필드가 다른 이유를 넷 이상 대고, 무엇부터 확인할지 순서를 말하라.
9. (장애 진단) RUM으로 모은 INP·CLS 건수가 모바일에서 유독 적다. 수집 코드의 어떤 부분을 의심하고 어떻게 고치나?
10. (연결) CLS 세션 창 계산과 INP 후보 선택은 각각 어떤 알고리즘·자료구조로 구현되나? 페이지별 p75를 평균 내 전체 p75로 쓰면 왜 틀리나?
