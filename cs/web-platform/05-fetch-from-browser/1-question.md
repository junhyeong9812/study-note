# web-platform/05-fetch-from-browser — 질문

## 질문

1. (왜) 서버의 HTTP 클라이언트와 달리 브라우저의 fetch는 헤더 일부를 직접 못 쓰고, 다른 출처의 응답을 마음대로 읽지 못한다. 브라우저가 이런 제한을 두는 이유는?
2. (예측) 같은 출처에서 `fetch('/status/404')`, `fetch('/status/500')`, 그리고 아무도 듣지 않는 포트로 `fetch('http://127.0.0.1:1/')`를 하면 각각 resolve인가 reject인가? `res.ok` 값은? 표준의 어느 규칙이 이를 정하나?
3. (예측) 다른 출처 서버가 CORS 헤더를 하나도 안 줄 때, (a) `GET` (b) `POST` + `Content-Type: text/plain` (c) `POST` + `Content-Type: application/json`을 보내면 서버 로그에는 각각 무엇이 찍히나? 페이지의 `catch`는 무엇을 받나?
4. (경계) 프리플라이트가 붙는 조건을 메서드와 헤더 두 축으로 말하라. `Access-Control-Max-Age`가 없으면 프리플라이트 결과는 얼마나 재사용되나? 실험에서 그것을 어떻게 확인했나?
5. (예측) 페이지(포트 A)가 쿠키 `sid=abc`를 받았다. 다른 포트 B로 `credentials: 'include'`를 주고 요청했고, B는 `Access-Control-Allow-Origin: *`를 돌려줬다. B 서버 로그의 Cookie 헤더와 페이지 결과는? 왜 쿠키가 포트 B로 갔나?
6. (경계) `AbortSignal.timeout(500)`으로 3초 걸리는 요청을 끊었다. 페이지가 받는 오류 이름은? 서버는 그 요청을 처리했나? 이 사실이 재시도 설계에 주는 의미는?
7. (연결) 응답 헤더를 받은 뒤 본문을 읽는 도중 `abort()`하면 어디에서 무슨 오류가 나나? `res.text()`와 `res.body.getReader()`는 200ms 간격 5청크 응답에서 각각 언제 값을 주나?
8. (장애 진단) 결제 API가 500을 줬는데 화면에 "결제 완료"가 떴다. 어디를 보면 원인을 알 수 있고, 재발을 막는 코드 구조는?
9. (장애 진단) 사용자가 "실패" 메시지를 보고 버튼을 다시 눌러 주문이 두 건 생겼다. 콘솔엔 `blocked by CORS policy`가 있다. 무슨 일이 일어났고, 무엇을 고쳐야 하나(두 가지)?
10. (연결) 자동완성에서 늦게 온 이전 응답이 최신 결과를 덮는다. fetch로 이를 막는 방법과, 그때 `catch`에서 걸러야 할 오류는?
