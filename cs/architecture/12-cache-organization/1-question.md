# architecture/12-cache-organization — 질문

## 질문

1. (계산) L1d가 48KB, 12-way, 라인 64B다. 집합은 몇 개이고, 주소의 몇 번째 비트가 오프셋·인덱스·태그인가? 주소 `0x1000`과 `0x2000`은 같은 집합인가?
2. (왜) 직접 사상·집합 연관·완전 연관은 무엇을 맞바꾸나? 지금 CPU의 L1이 완전 연관이 아닌 이유는?
3. (예측) 4096바이트 간격으로 놓인 라인 K개를 포인터 사슬로 돈다. 위 L1에서 K=12와 K=13의 접근 지연은 어떻게 다른가? 간격을 4160바이트로 바꾸면?
4. (경계) "데이터가 캐시 크기보다 작으면 미스가 안 난다"는 말은 언제 틀리나? 3번 실험의 64개 라인(4KB어치)을 예로 들어라.
5. (그림) 4-way 집합의 tree-PLRU를 비트 3개로 그리고, A에 접근한 뒤 다음 희생자를 어떻게 고르는지 보여라. 정확한 LRU 대신 이것을 쓰는 이유는?
6. (왜) write-back 캐시가 write-through보다 빠른 이유는? write-back이 멀티코어에서 만드는 새 문제는?
7. (예측) 스레드 2개가 각자 자기 카운터만 원자적으로 2천만 번 증가한다. 두 카운터가 8바이트 떨어진 경우와 64바이트 떨어진 경우, 서로 다른 P코어에서 걸린 시간은 대략 어떻게 다른가? 같은 코어의 두 하드웨어 스레드에서 돌리면?
8. (연결) Java `HashMap.hash()`가 `h ^ (h >>> 16)`을 하는 이유와 캐시의 2의 거듭제곱 stride 충돌은 어떻게 같은 문제인가?
9. (장애 진단) 워커별 통계 카운터를 `AtomicLongArray`의 인접 칸으로 바꾼 뒤 처리량이 떨어졌다. 무엇을 확인하고 어떻게 고치나?
10. (장애 진단) 1000×1000 이미지 처리는 빠른데 1024×1024에서 몇 배 느리다. 원인 후보와 확인 방법, 처방은?
