# architecture/10-calling-convention-and-stack-frame — 질문

## 질문

1. (왜) 호출 규약이 정하는 네 가지는 무엇인가? 규약이 없으면 어떤 조합의 코드가 서로를 부르지 못하나?
2. (그림) x86-64 System V에서 `sum7(1,2,3,4,5,6,7)`(정수 인자 7개)을 부를 때 각 인자는 어디로 가나? 같은 호출을 32비트 cdecl과 ARM64 AAPCS64로 하면 어떻게 달라지나? 반환 주소는 각각 어디에 저장되나?
3. (예측) `adder(a, b, n)`을 gcc `-O0`으로 컴파일하면 `push %rbp; mov %rsp,%rbp`는 있는데 `sub $N,%rsp`가 없다. 지역 변수는 어디에 저장되나? 왜 그래도 안전한가? `-O2`에서는 어떻게 바뀌나?
4. (경계) callee-saved와 caller-saved 레지스터의 차이는? x86-64 System V에서 함수 호출 뒤에도 값이 살아남는 범용 레지스터는 어느 것인가?
5. (예측) 프레임이 32바이트인 재귀 함수는 `ulimit -s 8192`에서 몇 단계쯤에서 `SIGSEGV`가 나나? 지역 배열 `char pad[1001]`을 더해 프레임이 1,056바이트가 되면? 스택 한도를 16 MiB로 올리면?
6. (장애 진단) 프로덕션 flame graph에서 중간 함수들이 빠져 호출 경로가 1~2단계로 짧다. 프레임 포인터 사슬이 무엇인지 그림으로 설명하고, C와 Java 각각에서 어떻게 고치나?
7. (연결) 지역 버퍼를 길게 넘치게 쓰면 왜 **자기** 함수의 반환 주소가 덮일 수 있나? 스택이 "아래로 자란다"는 사실과 배열 인덱스 방향을 함께 써서 설명하라.
8. (장애 진단) 깊게 중첩된 JSON 요청 하나에 `java.lang.StackOverflowError`가 났다. 트레이스는 1,024줄이다. 무엇을 알 수 있고, 같은 `-Xss1m`인데 재현 깊이가 실행마다 다른 이유는? 근본 대처와 임시 대처는?
9. (경계) 원고 memory-management §3의 첫 스택 그림은 위에서부터 a, b, n 순서로 인자를 그렸다. cdecl에서 실제 주소 순서는? 근거가 되는 기계어는?
