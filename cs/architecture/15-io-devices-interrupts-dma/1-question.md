# architecture/15-io-devices-interrupts-dma — 질문

## 질문

1. (왜) OSTEP의 "canonical protocol"에서 CPU가 낭비하는 시간은 두 종류다. 각각 무엇이고, 인터럽트와 DMA는 그중 어느 쪽을 없애나?
2. (경계) 인터럽트가 폴링보다 **나쁜** 경우를 두 가지 대라. OSTEP이 권하는 "2단계" 방식은 무엇인가?
3. (예측) 약 1ms마다 사건이 오는 상황에서, 바쁜 대기 소비자와 `LockSupport.park()` 소비자의 (a) 알아채는 지연 p50, (b) 기다리는 쪽 CPU 사용률은 대략 어느 자릿수일까? (`PollVsPark.java`, `--cpus=2`)
4. (예측) 같은 실험에서 상태 칸이 `volatile` 변수 하나뿐이면 어떤 일이 생길 수 있나? 이것이 장치가 "완료 링"을 두는 이유와 어떻게 이어지나?
5. (그림) NIC RX 디스크립터 링에서 장치와 드라이버가 각각 무엇을 하나 그려라. 링이 가득 차면 무엇이 일어나며 어느 카운터에 보이나?
6. (예측) CPU 하나에 고정해 `O_DIRECT` 4KiB 랜덤 읽기를 큐 깊이 1로 약 24,000번 했다. 그 CPU 칸의 NVMe 인터럽트는 대략 몇 번 늘까? 다른 CPU 칸은?
7. (장애 진단) 한 코어만 `%soft`가 100%이고 다른 코어는 한가하다. `/proc/interrupts`·`/proc/softirqs`·`/proc/irq/<n>/effective_affinity_list`에서 각각 무엇을 보며, 원인 후보와 대처는?
8. (장애 진단) 앱 로그에는 오류가 없는데 순간 폭주 때마다 재전송이 늘어난다. 어떤 카운터를 보며, 대처 순서는? 링 크기를 키우는 것의 대가는?
9. (연결) 수신 livelock은 무엇이고, Linux NAPI는 폴링과 인터럽트를 어떻게 섞어 이를 피하나?
