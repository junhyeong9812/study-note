# architecture/09-isa-and-machine-code — 질문

## 질문

1. (왜) ISA는 무엇과 무엇 사이의 계약인가? ISA와 마이크로아키텍처는 어떻게 다르며, "같은 ISA인데 속도가 다르다"는 이 호스트(i7-13700HX)에서 어떤 모습으로 나타나나?
2. (그림) `long big(long a) { return a + 0x12345678; }`를 x86-64(gcc -O2)와 ARM64(clang -O2)로 컴파일했다. 두 ISA의 명령 수와 명령 길이는 어떻게 다를 것이라 예측하나? 그 차이는 인코딩 방식의 어떤 성질에서 오나?
3. (예측) x86-64 호스트에서 ARM64용 최소 실행 파일 `exit7-arm64`를 ① bash에서 직접 ② `python:3.12-slim` 컨테이너의 엔트리포인트로 실행하면 각각 무엇이 출력되고 종료 코드는 얼마인가? (호스트에 QEMU binfmt 규칙은 없다.)
4. (그림) `xxd -l 24`로 본 실행 파일 첫 줄 두 개가 `7f45 4c46 0201 0100 ...` / `0200 b700 0100 0000`이다. 어느 바이트가 아키텍처를 알려 주며, 값은 무엇을 뜻하나? `file`은 이 정보를 어떻게 얻나?
5. (경계) 리눅스 커널은 아키텍처가 다른 ELF를 받으면 무엇을 하나? 같은 상황에서 QEMU가 설치된 Docker Desktop은 왜 실행에 성공하며, 그 대가는 무엇인가?
6. (장애 진단) 새 서버에선 잘 도는 C++ 바이너리가 오래된 서버에서 `Illegal instruction (core dumped)`, exit 132로 죽는다. 원인 후보와 확인 명령, 재발 방지책은? JVM은 같은 문제를 어떻게 피하나?
7. (연결) "Java는 한 번 빌드하면 어디서나 돈다"는 어디까지 맞나? ARM64 인스턴스로 옮긴 Java 서비스에서 `UnsatisfiedLinkError: ... No such file or directory (Possible cause: ...)`가 나왔다. 앞 문구와 괄호 안 문구는 각각 누가 만든 것이고, 어느 쪽을 믿어야 하나?
8. (경계) 원고 hardware-basics §9는 `LOAD BX, [0x02]`의 `[]`를 "주소를 담은 곳의 주소(간접)"로 설명한다. x86-64의 `mov (%rdi),%rax`에서 괄호는 메모리를 몇 번 읽나? 두 설명이 다른 이유는?
9. (장애 진단) 맥북에서 `docker build .`로 만든 이미지를 쿠버네티스(x86-64 노드)에 배포하자 `CrashLoopBackOff`가 된다. 로그 한 줄로 원인을 좁히는 법, 확인 명령 세 개, 빌드 쪽 고침은?
