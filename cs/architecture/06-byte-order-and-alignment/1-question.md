# architecture/06-byte-order-and-alignment — 질문

## 질문

1. (그림) `0x12345678`을 주소 a부터 빅 엔디안과 리틀 엔디안으로 놓은 모습을 그려라. "리틀 엔디안이면 비트도 거꾸로"라는 말은 왜 틀리나? 이 호스트의 순서를 확인하는 명령 두 가지는?
2. (예측) x86-64에서 `htons`를 빼고 포트 8080(0x1F90)을 소켓 주소에 넣으면 상대는 몇 번 포트로 읽나? 같은 코드를 빅 엔디안 호스트에서 테스트하면 왜 버그가 안 보이나?
3. (예측) 리틀 엔디안 장비가 길이 256을 4바이트로 보냈다. Java `ByteBuffer.wrap(wire).getInt()`의 값은? 그 이유와 고치는 코드는?
4. (경계) 정수 키 `-1, 0, 1, 256, 65536`을 4바이트로 인코딩해 바이트 사전순으로 정렬하면 리틀 엔디안·빅 엔디안·빅 엔디안 + 부호 비트 뒤집기에서 각각 어떤 순서가 되나? 왜 부호 비트를 뒤집으면 맞나?
5. (그림) x86-64 gcc에서 `struct Msg { uint8_t type; uint32_t len; uint16_t port; uint64_t id; }`의 오프셋과 패딩을 그려라. `sizeof`는? 멤버를 큰 것부터 놓으면? `-m32`(i386)로 빌드하면 무엇이 달라지나?
6. (경계) 비정렬 접근의 결과는 아키텍처마다 어떻게 다른가(커널 문서의 네 가지)? x86-64에서 비정렬 4바이트 load는 어떻게 되나, EFLAGS.AC를 켜면? 이식 가능한 비정렬 읽기 방법은?
7. (장애 진단) 구조체를 `write(fd, &msg, sizeof msg)`로 보내는 서버와 다른 플랫폼 클라이언트가 `id`를 다르게 읽고, 같은 메시지의 해시가 매번 다르다. 두 원인과 대처는?
8. (연결) `htons`·손으로 쓴 4바이트 교환·`__builtin_bswap32`는 x86-64 gcc `-O2`에서 각각 어떤 명령이 되나? Java에서 같은 일을 하는 API는?
