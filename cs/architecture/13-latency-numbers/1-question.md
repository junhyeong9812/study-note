# architecture/13-latency-numbers — 질문

## 질문

1. (왜) 지연 숫자를 외울 때 개별 값보다 자릿수와 비율이 중요한 이유는? 흔히 인용되는 "Latency Numbers" 표는 어떤 성격의 자료인가?
2. (계산) 캐시 안 연속 처리 원소 하나를 1ns, 같은 데이터센터 왕복을 500µs라고 하자. 왕복 한 번은 원소 처리 몇 개와 맞먹나? DRAM 무작위 접근(100ns) 기준이면?
3. (계산) L1 히트 5사이클, L2까지 추가 10사이클, DRAM까지 추가 175사이클이다. L1 미스율 5%, L1 미스 중 L2 미스 20%일 때 AMAT은? L1 미스율이 10%가 되면?
4. (계산) 캐시 히트 0.1ms, 미스 시 DB 5ms다. 히트율이 99%에서 95%로 떨어지면 평균 지연은 몇 배가 되나? 이 결과가 운영 지표 해석에 주는 교훈은?
5. (예측) 같은 JVM 안 루프백 서버에 id 1000개를 (a) 하나씩 1000번 (b) 한 줄로 묶어 1번 (c) 프로세스 안 HashMap으로 조회한다. 시간 순위와 대략의 배수는?
6. (경계) 지연과 처리량은 어떻게 다른가? 배치·파이프라이닝·프리페치는 둘 중 무엇을 바꾸나?
7. (예측) 이 호스트(측정 중 클록 약 0.9GHz)에서 L1 히트, 시스템 콜, 루프백 TCP 왕복, SSD 4KB 무작위 읽기, 4KB 쓰기+fdatasync를 쟀다. 각각 어느 자릿수(ns·µs·ms)가 나왔고, 표(~2012)와 비교해 어느 쪽이 크게 달랐나? 왜?
8. (장애 진단) 목록 API가 건수에 비례해 느리고, DB CPU는 한가한데 쿼리 수가 폭증한다. 무엇을 확인하고 어떻게 고치나?
9. (장애 진단) 10만 건 적재가 행당 약 3ms로 일정하게 느리다. 디스크 대역폭은 한가하다. 원인과 대처는?
10. (연결) AMAT은 평균이다. 평균만 보고 판단하면 무엇을 놓치나?
