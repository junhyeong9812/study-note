# architecture/13-latency-numbers — 정답

## 정답

### 1. 자릿수와 출처 성격

- 개별 값은 하드웨어 세대·클록·부하에 따라 바뀐다. 이 호스트에서도 클록이 낮은 상태라 L1이 표의 10배쯤으로 나왔다. 반면 "왕복 한 번 ≫ 메모리 접근 ≫ 캐시 접근" 같은 자릿수 관계는 오래 간다.
- 표는 1차 측정이 아니라 2차 정리다. 원형은 Norvig의 "Teach Yourself Programming in Ten Years" 표이고, jboner gist가 "~2012", "By Jeff Dean", "Originally by Peter Norvig"로 정리했다. 두 판의 줄도 서로 다르다.

### 2. 비율

- 500µs ÷ 1ns = **50만 개**. ⚠ 칸의 "메모리 접근 수십만 회"는 이 기준이다.
- DRAM 무작위 100ns 기준이면 500µs ÷ 100ns = 5천 번.

### 3. AMAT

- AMAT = 5 + 0.05 × (10 + 0.2 × 175) = 5 + 0.05 × 45 = **7.25 사이클**.
- L1 미스율 10%: 5 + 0.10 × 45 = **9.5 사이클**(31% 증가).

### 4. 애플리케이션 캐시

- 99%: 0.1 + 0.01 × 5 = 0.15ms. 95%: 0.1 + 0.05 × 5 = 0.35ms. **약 2.3배**.
- 교훈: 히트율 몇 %p는 작아 보여도, 페널티가 히트의 수십 배면 미스율이 평균을 지배한다. 히트율보다 초당 미스 수·페널티를 함께 본다. 미스가 DB 부하를 늘리면 페널티도 커진다.

### 5. N+1 실험

- 빠른 순: (c) 로컬 0.15~0.25ms < (b) 배치 3.3~9.3ms < (a) N+1 59~142ms(JIT 예열 뒤 4회씩, 2번 실행 범위).
- N+1은 같은 회차 배치의 14~25배, 로컬의 수백 배. HashMap 조회 일은 셋이 같고(로컬은 서버 없이 호출 스레드에서) 차이는 왕복 횟수다.

### 6. 지연 vs 처리량

- 지연은 한 건이 끝나는 시간, 처리량은 단위 시간당 끝나는 건수다. 겹쳐 처리하면 처리량 = 평균 동시 건수 ÷ 평균 지연(Little의 법칙 — 안정 상태의 장기 평균에서 성립).
- 배치·파이프라이닝·프리페치는 왕복·DRAM 접근 한 번의 지연을 줄이지 않는다. 한 번의 대기에 더 많은 일을 싣거나 대기를 앞당겨 처리량을 올린다. 그 결과 여러 건의 전체 완료 시간과 작업이 겪는 대기는 줄어든다(실험 2의 배치, 프리페치는 나중 접근을 히트로 바꾼다). 11번의 256MB 순차 사슬(약 8사이클/접근)이 DRAM 지연(약 190사이클)을 프리페치로 숨긴 것으로 본다(해석).

### 7. 이 호스트의 자릿수

| 항목 | 측정 | 자릿수 | 표 |
|---|---|---|---|
| L1 히트 | 4.8~6.1 ns | ns | 0.5 ns |
| 시스템 콜 `getppid` | 326~345 ns | 수백 ns | — |
| 루프백 TCP 왕복 | 34.1~41.9 µs | 수십 µs | (DC 왕복 500 µs) |
| SSD 4KB 무작위 | 90~109 µs | 100 µs | 150 µs |
| 4KB 쓰기+fdatasync | 2.63~2.89 ms | ms | — |

- CPU 안쪽(L1)은 표보다 약 10배 컸다. 측정 중 코어 클록이 약 0.8~0.93GHz로 낮아 사이클 수(약 5)는 그대로인데 ns가 늘었다. 장치 쪽(SSD)은 측정값 대부분이 장치 시간이라 클록 영향이 작아 표와 같은 자릿수였다는 해석이다(시스템 콜·블록 계층 처리는 CPU 몫이라 완전히 무관하지는 않다).

### 8. N+1 진단

1. 요청 하나의 쿼리 수를 센다. `pg_stat_statements`의 `calls`가 요청 수보다 수십 배 많은 짧은 쿼리, 트레이스에 줄지은 짧은 DB 스팬.
2. 네트워크 왕복은 `ss -tin dst <db-ip>`의 rtt(TCP 왕복 추정치)로, DB 요청 하나의 시간은 트레이스의 DB 스팬으로 확인한다. 응답 시간 ≈ 건수 × DB 스팬 시간이면 확정.
3. IN 절·fetch join·배치 API로 왕복을 1~몇 번으로 줄이고, 쿼리 수를 테스트로 단언한다.

### 9. 행당 3ms

- 커밋마다 로그를 디스크에 내리고(fsync) 기다린다. 이 호스트의 4KB 쓰기 + `fdatasync`가 2.6~2.9ms였다. 대역폭이 아니라 **횟수 × 지연**이 병목이다.
- 대처: 여러 행을 한 트랜잭션으로 묶는 배치 커밋, 다중 VALUES, `COPY`.

### 10. 평균의 함정

- 평균은 꼬리를 숨긴다. 미스는 드물게 크게 느린 요청을 만든다. 미스율이 1%를 넘으면 p99가 미스 지연으로 뛰고, 1% 미만이면 p99.9 같은 더 먼 꼬리가 움직인다. 같은 평균이어도 분포가 다를 수 있다.
- 요청 하나가 여러 하위 호출을 기다리면, 그중 하나라도 느리면 요청 전체가 느리다. 평균 대신 백분위수와 분포를 본다(reliability/34).
