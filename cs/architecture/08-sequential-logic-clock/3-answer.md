# architecture/08-sequential-logic-clock — 정답

## 정답

### 1. 기억과 클록

- 조합 회로의 출력은 지금 입력만으로 정해진다. 입력이 사라지면 결과도 사라지므로, "앞 명령의 결과로 다음 명령을 한다"가 안 된다.
- 기억(래치·플립플롭·레지스터): 값을 붙잡아 다음 단계의 입력으로 쓴다.
- 클록: 모든 레지스터가 같은 순간(에지)에 값을 잡게 해, 조합 회로가 계산 중인 어중간한 값이 퍼지지 않게 한다. 에지 사이에 조합 회로가 다음 값을 계산한다.

### 2. SR 래치

```text
  Q  = NOR(R, Q')        S R │ Q   Q'
  Q' = NOR(S, Q)         0 0 │ 유지
                         1 0 │ 1   0
                         0 1 │ 0   1
                         1 1 │ 0   0  (금지)
```

- 동시 해제: 실험 1에서 `QQ'`가 `11 00 11 00 …`으로 끝없이 흔들렸다. 두 NOR이 서로의 직전 출력으로 계산하는 대칭 상태이기 때문이다. 1단위만 어긋나게 내려도 `01`로 정해졌다.
- 실제 회로에서는 아날로그 현상인 메타안정성으로 나타난다. 대개 0이나 1로 나오되 정해지는 데 오래 걸리고, 그 시간에 상한이 없다(Ginosar 2011). 모델의 무한 진동은 그 디지털 그림자다(해석).

### 3. 래치 vs 플립플롭

- D 래치: 클록이 1인 동안 투명하므로 글리치가 Q에 그대로 나온다. 실험 2에서 t=14~16의 D 글리치가 Q래치에 나타났고, t=33의 D 하강도 클록 1 구간이라 따라 내려갔다.
- 에지 D 플립플롭: 상승 에지(t=10, 30, 50, 70)의 D만 잡는다. 같은 글리치와 t=33 변화를 무시하고, t=50의 0과 t=70의 1만 반영했다.
- 원고 §6 진리표(CLK=1이면 Q=D, CLK=0이면 유지)는 레벨 감지 **D 래치**의 동작이다.

### 4. 클록 주기

- `T ≥ t_clk→Q + t_조합(최장 경로) + t_setup`.
- 5 GHz → T = 1/(5×10^9) = 0.2 ns. 800 MHz → 1.25 ns.

### 5. 카운터 주기 줄이기

| 주기(단위) | 256클록 중 오답 |
|---|---|
| 40, 20, 17, 16 | 0 |
| 12 | 10 |
| 8 | 46 |
| 4 | 172 |

- 주기가 최악 경로(약 16)보다 짧아지면 레지스터가 가산기의 중간값을 잡는다(실험 3).
- 62 다음 127: 앞 에지에서 입력이 61→62로 바뀌었다. 옛 캐리(비트 0→1)가 사라지기 전에 새 전달 비트(비트 1~5)가 켜져, 짧은 캐리 펄스(글리치)가 위로 번졌다. 합 출력은 시각별로 `62, 61, 61, 59, 59, 55, 55, 47, 47, 31, 31, 127, …`이었고, t=12에 잡은 값이 127이다.

### 6. 유한 상태 기계

```text
  하드웨어:  입력 ─> [다음 상태 조합 논리] ─> [상태 레지스터 (CLK)] ─┬─> 출력
                         ▲─────────────────────────────────────────┘
  코드:      state = TABLE[state][event];  없으면 거부
             CLOSED ─CONNECT→ SYN_SENT ─SYNACK→ ESTABLISHED ─CLOSE→ FIN_WAIT ─ACK→ CLOSED
             (4상태 단순화 예 — 실제 TCP 종료 상태는 RFC 9293 §3.3.2)
```

- 2진 부호화면 상태 k개에 플립플롭 적어도 ⌈log2 k⌉개(one-hot이면 k개). 4상태 → 2개(실험 4).

### 7. MTBF 계산

- 진입률 T_W·F_C·F_D = 20×10^−12 × 10^9 × 10^8 = 2×10^6 회/초.
- S = 0.2주기 = 0.2 ns: e^(20) / (2×10^6) ≈ 243초.
- S = 1주기 = 1 ns: e^(100) / (2×10^6) ≈ 1.34×10^37초 ≈ 4.3×10^29년. 논문 값 4×10^29년과 같다(실험 6).
- MTBF를 지배하는 것은 해소 시간 S다. 지수에 들어가므로 S를 조금만 늘려도 자릿수가 크게 바뀐다. 진입 자체는 초당 200만 번으로 흔하다.

### 8. 클록을 올린 뒤의 간헐 오동작

- 의심: 동기화기의 해소 시간 S가 줄어 MTBF가 분 단위로 떨어졌다(실험 6 조건에서 S = 0.2주기면 약 4분). 동기화기 플립플롭 사이에 논리나 긴 배선이 끼어 S를 깎았을 수도 있다(Ginosar).
- 고치기: 동기화기 사이에 논리를 두지 않고 두 플립플롭을 가까이 둔다. 빠른 클록에서는 단을 셋 이상으로 늘린다. MTBF는 동기화기 수와 시스템 신뢰도 목표를 함께 보고 정한다(Ginosar의 예: 동기화기 1,000개면 각각을 목표보다 적어도 세 자릿수 크게).

### 9. 여러 비트·이중 동기화

- 비트마다 따로: 3→4는 `011 → 100`으로 세 비트가 바뀐다. 비트마다 해소 결과·주기 수가 다를 수 있어 0~7 어느 값으로도 읽힐 수 있다(실험 7).
- Gray 부호: 이웃 값이 1비트만 다르므로 3이나 4로만 읽힌다(비트 사이 스큐가 작다는 전제 — 실제 FIFO는 skew 제약을 건다). 두 클록 FIFO의 포인터를 Gray 부호로 넘기는 이유다.
- 이중 동기화: 같은 입력을 두 동기화기가 받으면 하나는 1, 하나는 0으로 해소될 수 있어 회로가 모순된 상태가 된다. Ginosar는 이를 금지하고, 우주선 J 예화의 원인으로 든다. 동기화기 하나의 출력을 나눠 쓴다.

### 10. 코드 FSM의 빈틈

- 빠진 것: 전이 규칙. 하드웨어 FSM은 다음 상태 논리가 정한 상태로만 간다. 코드는 아무 값이나 덮어쓸 수 있으므로, `CANCELLED → PAID`를 표로 검사해 거부해야 한다.
- 동시 전이: 에지에서 한 번에 바뀌는 것처럼, 검사와 전이를 원자적으로 한다. `UPDATE orders SET state='PAID' WHERE id=? AND state='CREATED'` — 영향 행 0이면 이미 다른 상태라는 뜻이다([database/18](../../database/18-app-level-concurrency-patterns/2-summary.md)).
