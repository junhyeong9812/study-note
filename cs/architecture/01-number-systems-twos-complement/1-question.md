# architecture/01-number-systems-twos-complement — 질문

## 질문

1. (왜) 메모리에 "부호"가 따로 저장되지 않는데 어떻게 음수를 표현하나? 2의 보수가 부호-크기·1의 보수보다 하드웨어에 유리한 이유를 덧셈기 관점에서 말하라.
2. (계산) 8비트 `1100 1000`을 무부호로, 2의 보수로 각각 읽어라. 두 값의 차이는 왜 256인가? 8비트 2의 보수로 −13을 비트로 만들어라.
3. (예측) C에서 `int m1 = -1; unsigned z = 0u;`일 때 `m1 > z`, `m1 > 0`, `strlen("abc") > -1`의 값은? gcc 13.3을 `-Wall`만 켰을 때와 `-Wall -Wextra`를 켰을 때 경고 수는?
4. (그림) `0xC8`을 `signed char`와 `unsigned char`에서 각각 `int`로 넓힐 때 32비트 결과를 그려라. x86-64 gcc는 두 경우에 어떤 명령을 내나?
5. (예측) Java에서 `byte b = (byte)0xC8; int x = b;`의 `x`, `b & 0xFF`, `-Integer.MIN_VALUE`, `0xFFFFFFFF`(int 리터럴)의 값은?
6. (경계) C11과 C23은 부호 있는 정수 표현을 어떻게 정했나? C23에서 2의 보수가 의무가 되었으니 `INT_MAX + 1`도 −2³¹로 정의되나?
7. (장애 진단) 바이너리 프로토콜 파서가 길이 127까지는 잘 되고 128 이상에서 `NegativeArraySizeException`을 낸다. 원인과 고친 코드, 테스트에 넣을 값은?
8. (연결) Java와 C로 같은 바이트 해시(`h = h*31 + b`)를 구현했더니 ASCII 키에서는 같고 "café"에서는 다르다. 왜이며, 명세에 무엇을 적어야 하나?
