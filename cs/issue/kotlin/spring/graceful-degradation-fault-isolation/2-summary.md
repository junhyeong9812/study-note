# cs/issue/kotlin/spring/graceful-degradation-fault-isolation — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

**한 문장:** 핵심 기능(검색)은 보조 기능(llm 재작성·의미 검색)의 장애나 부정확한 제안에 **인질로 잡히면 안 되고**, 그래서 각 보조 경로는 실패 시 조용히 없어지지 않고 "생략/강등"으로 흡수되며(폴백), 강등 여부는 응답 뱃지로 드러낸다.

```
[정상 흐름]                                  [장애 흐름 — 불변식이 지켜지는 자리]
GET /api/search?q=...                         GET /api/search?q=...
  ▼ llm /rewrite → 키워드·확장 합침            ▼ llm 503/타임아웃 → rewrite 생략   ← 폴백1
    (rewrite_on=true)                            (rewrite_on=false, 원본 q로 진행)
  ▼ BM25(nori) ─────────────┐                 ▼ BM25(nori) ─────────────┐
  ▼ kNN(임베딩) ────────────┤                 ▼ kNN → 임베딩 예외 → 빈 랭킹 ┤ ← 폴백2
  ▼ RRF 병합 (등수만)  ◀─────┘                 ▼ RRF 병합 — 한쪽 비어도 성립 ◀┘   (dense_on=false)
  ▼ 200 {results, rewrite_on, dense_on}        ▼ 여전히 200 (강등 뱃지 포함)

[결정권 분리]  llm이 kind=question 제안 → 하드 필터로 쓰면 답 문서 전멸
              → 제안은 "참고 자료": 버리지 않되 로그로만 축적, 하드 필터는 명시 파라미터만
```

**두 방어의 결:** **결함 격리(fault isolation)** 는 "한 부품의 고장이 다른 부품으로 번지지 않게 벽을 세우는 것"이고, **우아한 성능 저하(graceful degradation)** 는 "부품이 빠져도 전체가 축소된 형태로 계속 작동하는 것"이다. 여기선 kNN 호출을 try/catch로 감싸 임베딩 장애를 검색 스레드 안에 가두고(격리), 실패 시 BM25 단독으로 내려앉되 여전히 200을 준다(강등). llm 재작성도 어떤 예외든 `fallback(used=false)`로 흡수해 원본 질의로 계속 간다.

**RRF가 폴백과 궁합이 좋은 이유:** 원점수를 그냥 더하면 스케일 큰 BM25가 지배하고, 최대값 정규화는 이상치 하나가 전체를 휘두른다(정규화+가중합도 튜닝 데이터가 있으면 쓸 만하지만, 튜닝 없이는 불안정). RRF는 **점수를 버리고 등수만** 써서(`Σ 1/(k+rank)`, k=60) 스케일 문제를 없앤다. 그리고 등수 기반이라 **한쪽 랭킹이 통째로 비어도 수식이 그대로 성립** — "임베딩 죽으면 BM25 단독" 폴백과 구조적으로 맞물린다.

**약한 모델은 참고 자료지 결정권자가 아니다:** llm이 "세마포어가 뭐야"에 `kind=question`을 제안했는데, 이걸 하드 필터로 적용하니 정답·정리가 전멸했다(사람 의도는 질문의 **답**을 찾는 것). 그래서 하드 필터는 명시 파라미터만 쓰고, 모델 제안은 **버리지 않되 로그로만 축적**한다 — 나중에 "제안이 얼마나 맞았나"를 실데이터로 판단할 재료로. 리뷰어 둘 다 "제안을 쓰라"고 했지만 실측이 뒤집었다: 리뷰는 설계-코드 불일치는 잡아도 **설계 자체의 유해함은 실측만 잡는다.**

**상태 뱃지:** 폴백은 "조용히" 일어나면 안 된다 — 응답에 `rewrite_on`·`dense_on`를 실어 호출자가 "이번 결과가 강등된 것인지"를 알게 한다. 이 관측 가능성이 강등을 silent failure와 가른다.

## 핵심 문장

- 보조 기능의 장애가 핵심 기능을 죽이지 못하게 — "인질 금지"를 불변식으로 못 박는다.
- 결함 격리(장애를 가두는 벽) + 우아한 성능 저하(빠져도 축소 작동)가 함께 불변식을 지킨다.
- RRF는 점수를 버리고 등수만 써 스케일 문제를 없애고, 한쪽이 비어도 성립해 폴백과 궁합이 좋다.
- 약한 모델의 구조화 출력은 참고 자료지 결정권자가 아니다 — 제안은 로그로 축적, 하드 결정은 명시 입력만.
- 폴백은 시끄럽게(응답 뱃지 `*_on`) — 조용한 강등은 silent failure가 된다.
- 리뷰는 설계-코드 불일치를 잡고, 설계 자체의 유해함은 실측만 잡는다.
