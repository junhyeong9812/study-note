## 질문
1. (왜) KDoc 주석 본문에 `/admin/**` 같은 경로 패턴을 적었더니 `Unclosed comment` 컴파일 오류가 났다. 같은 주석이 Java에서는 멀쩡한데 Kotlin에서만 깨지는 이유는 무엇인가? 같은 문자열이 `requestMatchers("/admin/**")` 안에 있을 때는 왜 안전한가?
2. (예측) 테스트 함수 이름을 backtick으로 `` `Filter: age > 28` `` 처럼 지었다. 한글과 공백은 되는데 이 이름은 컴파일에 실패한다 — 왜 "backtick이면 아무 문자나 된다"가 틀렸는가? 어떤 층의 규칙이 끼어드는가?
3. (왜) `data class Record(val data: ByteArray)` 두 개가 같은 바이트를 담고 있어도 `==`가 false다. data class가 자동 생성한 `equals`가 왜 "내용 동등성"을 보장하지 못하는가? 고치는 두 가지 방법은?
4. (경계) sealed 계층에 새 케이스를 추가하자 여러 `when` 식이 `must be exhaustive`로 한꺼번에 깨졌다. 이것은 함정인가 안전망인가? `else ->` 분기를 넣어 조용히 넘기는 것과 무엇이 다른가?
5. (왜) 코루틴 안에서 `try { ... } catch (e: Exception) { RETRY }`로 모든 예외를 재시도로 바꿨더니 작업 취소가 "재시도"로 뒤집혔다. 코루틴 취소는 어떻게 전파되길래 광범위 catch에 걸리는가? catch 순서를 어떻게 바꿔야 하는가?
6. (예측) 생성자에 기본값 인자를 추가했더니 Kotlin 코드는 컴파일되는데, 리플렉션으로 그 클래스를 생성하는 Java 쪽 프레임워크가 런타임에 `NoSuchMethodException`을 냈다. 왜 컴파일 단계에서 안 잡히는가? 같은 변경이 트레일링 람다 호출부를 어떻게 바꿔 놓을 수 있는가?
7. (연결) 위 사례들의 공통점은 "Java를 아는 사람의 직관이 Kotlin 규칙과 어긋난다"이다. 이 중 **컴파일러가 잡아주는 것**과 **런타임·의미로만 드러나는 것**을 나누고, 후자를 잡으려면 어떤 테스트를 두어야 하는가?
