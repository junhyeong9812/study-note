## 정답
<!-- 질문 1:1 대응 -->

1. **should = 합, dis_max = 최댓값.**\
`bool.should`는 매칭된 **모든** 절의 점수를 더하고, `dis_max`는 가장 높은 절의 점수에 `tie_breaker × 나머지 절 점수`만 더한다.\
"A 또는 B"를 should로 풀면 양쪽에 약하게 걸린 문서(3+3)의 합이, 절·필드가 더 붙을수록 한쪽에만 강하게 걸린 문서(10)를 넘어설 수 있다 — 논리 OR의 의미("후보 중 가장 잘 맞는 것")와 달리 **다중 매칭 편향**이 생긴다.\
dis_max(tie_breaker 0)는 최선의 대안 하나만 반영하므로 OR의 의미에 맞는다.
   > **dis_max (disjunction max)** — 여러 하위 쿼리 중 최고 점수를 문서 점수로 쓰고, tie_breaker로 나머지를 약간만 반영하는 결합.

2. **상관된 절의 중복 계수 → 그룹별 dis_max.**\
같은 이름을 여러 분석기(음차·문자 분해·정렬 등)로 표현한 필드는 **같은 정보**다.\
이를 절 여러 개로 should에 나열하자 특정 계열 문서들이 여러 표현에서 동시에 매칭돼 교차 점수가 크게 누적됐고, 목표 문서가 최상위권에서 10위 밖으로 밀리며 무관한 문서가 상위에 들어왔다.\
교정: "같은 분석기 그룹 안의 필드 = 같은 정보"이므로 **그룹별 dis_max 4개**(tie_breaker 0.1)로 묶고 그룹 간은 should로 합산 → 교차 점수가 수 분의 1로 감소. 같은 절이 개별 should와 dis_max 내부에 **중복**으로 들어 있던 것도 제거.\
잃는 것: 여러 절에서 조금씩 점수를 받던 다단어 문서의 **누적 효과**가 사라져 순위가 수십 위에서 백 위권 밖으로 밀렸다 — 이를 되살리려 별도 계층 추가·constant_score를 시도했지만 구조적 한계로 적용하지 않았다.

3. **빈 OR → match_all은 fail-open.**\
OR 후보가 0개일 때 `match_all()`로 fallback하면 "조건 없음 = 전부 매칭"이 되어 필터가 **열린다** — 빈 집합의 합집합은 공집합이어야 한다.\
규칙: 0개 → `match_none`, 1개 → 래핑 없이 그대로, 2개 이상 → `dis_max(tie_breaker=0.0)`.\
부작용 리스크: 합산이 max로 바뀌면 점수 **스케일이 낮아져**, 절대값 `min_score` 필터 경계에 있던 문서가 새로 걸러질 수 있다.\
부수 발견: 수백 개 테스트가 통과했지만 **OR 분기의 쿼리 형태를 직접 검증하는 테스트는 없었다** — 테스트 통과가 결합 의미의 검증은 아니었다.

4. **TF 누적은 반복 토큰 문서를 편애한다.**\
BM25의 TF 항은 같은 term이 필드에 여러 번 나올수록 커진다(포화되지만 단조 증가).\
거친 음성 인코더가 토큰마다 같은 코드(`M`)를 내면, 다중값 배열 필드의 원소가 한 필드로 합쳐져 **짧은 반복 토큰 4개짜리 문서**가 TF 합으로 1위가 되고 목표 문서는 10위 밖으로 밀렸다.\
토큰 중 가장 긴 것 하나만 담는 **단일 문자열 필드**는 TF를 1로 고정하고 필드의 term 수도 줄여 이 편향을 원천 제거한다(토큰 배열 소문자 정규화도 함께).\
같은 계열: 언어별 변환 서브필드 여러 개에 같은 큰 boost로 match를 걸자 여러 서브필드에 중복 매칭된 문서가 원본 매칭보다 총점이 높아졌다(원인은 기록상 추정 단계라 여기선 구조만 언급).
   > **TF (term frequency)** — 문서의 필드에 term이 나온 횟수. BM25에선 k1로 포화되는 증가 함수로 점수에 반영된다.

5. **길이 정규화는 매핑이 결정하는 편향이다.**\
BM25는 `b`(기본 0.75)로 필드 길이 `dl/avgdl`에 비례해 TF 항을 깎는다 — 같은 매칭이라도 **긴 필드는 불리**하다.\
거의 같은 이름이 3토큰짜리 필드 안에 있어 단일 토큰 문서보다 한참 아래(백 위권 밖)로 밀렸다.\
게다가 원 필드는 keyword(토큰화 불가)였고, 보조 필드는 공백을 제거해 전체가 **단일 토큰**이라 "개별 단어 단위 유사매칭"이라는 요구 자체를 쿼리로 표현할 수 없었다.\
시도: 별도 dis_max 계층(누적이 차단돼 단일 토큰만 이득 → 미적용), constant_score(순위 역전 불가·노이즈 증가 → 미적용), 인덱스 `b=0`(전 쿼리 영향 → 보류).\
참고로 `b`는 검색 시점에 적용되는 값이라 인덱스 기본 similarity를 바꾸는 데 재색인까지는 필요 없지만(ES 기준 인덱스 close → 설정 변경 → open), 그 인덱스의 모든 쿼리 점수가 바뀌고 기존 필드의 필드별 similarity 매핑은 제자리에서 바꿀 수 없다.\
결론: keyword 필드에 **공백 토큰화 + 음성(phonetic) 분석 text 서브필드**를 추가하는 매핑 확장(재색인 필요, 제안 단계) — **검색 가능성은 매핑이 결정**한다.
   > **BM25** — TF·IDF·필드 길이 정규화로 관련도를 계산하는 기본 점수 함수. `k1`은 TF 포화, `b`는 길이 정규화 강도.

6. **순위는 점수 차이에서 나온다.**\
모든 절을 `constant_score`로 바꾸면 IDF(희소성)·TF 신호가 사라져 흔한 토큰의 매칭이 희귀 토큰과 같은 값을 받고, 대량의 **동점 늪**이 생겨 순위가 사실상 무작위가 됐다 → 롤백.\
가중치 1짜리 constant_score 몇 개를 끼워 넣는 것도, 다른 절 점수가 수 점~수만 점 스케일이라 **무력**했다.\
dis_max도 최댓값만 취하므로 같은 최고 점수를 받는 수십 건 사이의 **차등**을 지운다.\
대안: 정확 문자 분해 일치(3점) + 유사 일치(1점)의 이중 상수 점수, 문자 **위치 태깅** 절을 should로 걸어 "맞은 개수 = 점수"(일반 term 절은 BM25로 IDF가 섞이므로, 정확히 개수가 되려면 각 절을 상수 점수로 감싼다), 토큰 수가 같을 때만 교차 매핑 허용 — 신호를 지우지 않고 **의도한 신호로 교체**했다.

7. **상대·근사 점수에 고정 임계 = 조용한 recall 정책 변경.**\
`_score`는 쿼리 구조·필드 통계·boost에 따라 스케일이 달라지는 **상대값**이라, 고정 `min_score`는 데이터·쿼리가 바뀌면 걸러내는 비율이 달라진다 — 수집 단계에서 적용돼 "더 적게 반환"으로 작동하므로, 이는 튜닝이 아니라 **recall 정책 변경**이다.\
그래서 값을 적용하되 효과는 단위 테스트가 아니라 배포 후 실데이터로 검증할 대상으로 명시하고, 후속으로 점수 분포·explain 기반 백분위 스코어링을 검토했다(미정의 언어는 default에서 예외로 fail-closed, 결과 수 고정 후 전체 건수 표기가 거짓 다중 페이지 신호가 되던 것도 반환 수 기준으로 맞춤).\
벡터 근사 인덱스(다른 방안)는 더 극단적이었다: PQ 양자화는 벡터를 압축해 근사 점수에 **양자화 오차**가 생긴다 — 오차 방향이 항상 한쪽은 아니지만, 이 사례에선 높은 유사도 쌍의 근사 점수가 실제보다 낮게 나와 0.85라는 절대 임계를 어떤 쌍도 넘지 못했고 결과(edges)가 **에러 없이 0**이 됐다.\
여기서는 임계를 옮기지 않고 **점수를 왜곡하지 않는 인덱스로 교체**했다(아래 방안 비교) — IVF-Flat은 후보 벡터의 점수를 정확히 계산하고, 근사는 "탐색하지 않은 군집의 이웃을 놓치는" recall 쪽에만 남는다.

## 문제 구조 (추상화 코드)

### 변형 A — 합산 결합이 OR·상관 절을 부풀림 + 빈 OR fail-open
① 문제 코드
```python
def or_query(subs):
    if not subs:
        return match_all()                                   # 빈 OR = 전부 매칭 (fail-open)
    return bool_(should=subs, minimum_should_match=1)        # 대안 점수 합산

q = bool_(should=[*base, *[match(f, v) for f in SAME_INFO_FIELDS]])   # 같은 정보 여러 절 합산
```
② 고친 코드
```python
def or_query(subs):
    if len(subs) == 0: return match_none()
    if len(subs) == 1: return subs[0]
    return dis_max(queries=subs, tie_breaker=0.0)            # 최선의 대안만

q = bool_(should=[*base,
    dis_max([match(f, v) for f in GROUP_A], tie_breaker=0.1),   # 그룹 안 = 같은 정보 = max
    dis_max([match(f, v) for f in GROUP_B], tie_breaker=0.1),   # 그룹 간 = should 합산
    # ...
])
```
무엇이 깨졌나: "또는"과 "같은 정보의 다른 표현"을 합산으로 표현해 증거를 중복 계수했고, 빈 집합을 전체 집합으로 폴백했다.

### 변형 B — TF 누적 편향
① 문제 코드
```python
doc["name_tokens"] = ["mi", "o", "mi", "o"]                  # 배열 → 한 필드로 합쳐져 tf 누적
q.should(match("name_tokens.phonetic", query))               # 거친 인코더 → 같은 코드 반복
```
② 고친 코드
```python
doc["name_longest_one"] = max(tokens, key=len).lower()       # 단일값 → TF=1 고정, term 수 급감
q.should(match("name_longest_one", query, fuzziness="2", max_expansions=500))
```
무엇이 깨졌나: 다중값 필드와 거친 표현이 BM25의 TF 누적과 만나 노이즈 문서에 체계적 가점을 줬다.

### 변형 C — 길이 정규화 · 표현 불가능한 요구

무엇이 깨졌나: 요구(단어 단위 매칭)를 표현할 필드가 매핑에 없는데 쿼리 조정으로 풀려 했다.

### 변형 D — 신호 제거(constant_score)의 역효과
① 문제 코드
```python
q = bool_(should=[constant_score(match(f, v), boost=1) for f in FIELDS])   # IDF·TF 제거 → 대량 동점
```
② 고친 코드
```python
q = bool_(should=[
    constant_score(term("chars_exact", decompose(v)), boost=3),            # 정확 일치
    constant_score(terms("chars_similar", similar_chars(v)), boost=1),      # 유사 일치
    *[constant_score(term("char_pos", f"{i}:{j}"), boost=1)
      for i, j in enumerate(decompose(v))],                                # 위치 태깅: 절마다 1점 → 맞은 개수 = 점수
])
```
무엇이 깨졌나: 노이즈를 줄이려고 순위를 만드는 차등 정보까지 지웠다.

### 변형 E — 상대 점수에 고정 `min_score`
① 문제 코드
```java
search.minScore(language == KO ? 3.0 : 30.0);     // 상대 점수에 하드코딩 임계 = recall 정책 변경
```
② 고친 코드
```java
search.minScore(ScoreThresholds.of(language));     // 미정의 언어는 default -> throw (fail-closed)
// 효과 검증 = 배포 후 실데이터(점수 분포·explain) · 후속: 백분위 기반 스코어링
// 결과 수 고정 시 total/pages 는 반환 수 기준
```
무엇이 깨졌나: 스케일이 고정되지 않은 값에 고정 임계를 걸고, 그 효과를 단위 테스트로 검증할 수 있다고 여겼다.

## 방안 비교

기본 방안(위 변형 A~E)은 "점수를 만드는 결합·필드 구조를 의도에 맞게 고치고, 임계값은 분포로 검증한다"이다. 같은 원리(점수는 상대·근사값이라 고정 임계가 결과를 조용히 왜곡)에 다른 방안이 쓰인 사례:

### 방안 1 — 근사(양자화) 점수에 절대 임계 금지 → 점수를 왜곡하지 않는 근사 인덱스로 교체
```python
# 문제: 수백만 임베딩 군집화 — 쌍 유사도 ≥ 0.85 이면 edge
index = IndexIVFPQ(d, nlist, m, nbits)       # PQ 양자화 오차 → (이 사례) 근사 내적이 실제보다 낮음 → edges = 0 (에러 없음)

# 시도 2: 정확 검색
index = IndexFlatIP(d)                        # 정확하지만 brute-force → 예상 36시간

# 채택: 양자화 없이 탐색 범위만 근사
index = IndexIVFFlat(quantizer, d, nlist=4096)
index.nprobe = 128                            # 점수는 정확, 누락은 미탐색 군집에서만 — 정확 검색 대비 edge 0.02% 차이, 5배 빠름
edges = [(i, j) for i, j, s in knn_pairs(index) if s >= 0.85]
```

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|------|------|------|-----------|-----------|
| 기본: 결합·필드 구조 교정 + 분포 기반 임계 검증 | 점수 스케일이 쿼리·데이터에 따라 변한다 | 쿼리·매핑 재설계, 배포 후 검증 | 고정 임계가 남으면 recall이 조용히 변함 | 텍스트 관련도 점수(BM25 등) |
| 1. 점수 왜곡 없는 근사 인덱스로 교체 | 임계값이 실제 유사도 의미를 가진다(내적 임계 0.85 — 벡터 정규화 여부는 기록에 없어 코사인 해석은 일반론) | 인덱스 메모리·시간(PQ보다 큼) | 근사 방식이 점수를 깎으면 절대 임계가 전부 탈락 | 벡터 유사도에 절대 임계가 필요한 배치 작업 |

**결론**: BM25 같은 관련도 점수는 애초에 절대 의미가 없으므로 임계를 **분포로 검증**하거나 순위·결합 구조로 풀어야 한다(기본).\
정규화된 벡터의 내적(코사인)처럼 점수 자체에 절대 의미가 있는 경우엔 임계를 유지하되, **그 점수를 왜곡하는 근사(양자화)를 피해야** 한다 — 속도는 탐색 범위 근사(IVF)로 얻는다(방안 1).\
두 경우 모두 "결과가 0건·급감했는데 에러가 없다"면 먼저 점수 스케일과 임계의 관계를 의심한다.
