# cs/issue/search-engine/score-semantics-and-composition — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
점수 = f(쿼리 구조, 필드 통계(IDF·avgdl), boost, 결합 방식)   ← 상대값, 쿼리·데이터가 바뀌면 스케일이 바뀜

[결합]
  bool.should  = Σ 매칭 절 점수        ── 상관된 절·독립 대안을 풀면 증거 중복 계수 → 인플레이션
  dis_max      = max + tie × 나머지     ── 대안 중 최선만 → 누적 효과 소멸(여러 절에서 조금씩 받던 문서 하락)
  교정: 같은 정보 그룹 안 = dis_max, 그룹 간 = should
        OR 후보 0개 → match_none (match_all 은 fail-open) · 1개 → 그대로 · 2+ → dis_max

[TF·길이]
  BM25 TF항 = tf·(k1+1) / (tf + k1·(1 − b + b·dl/avgdl))
  거친 인코더 → 같은 코드 반복 → tf 누적 → 반복 토큰 문서 독식   ── 교정: 단일값 필드(TF=1)
  긴 필드 → dl/avgdl ↑ → 점수 ↓                                   ── 쿼리로 못 고침 → 매핑(토큰화 서브필드) 확장

[신호 제거]
  constant_score 전면 → IDF·TF 제거 → 동점 늪(1만+) · 흔한 토큰 지배
  교정: 정확(3점)/유사(1점) 이중 상수, 위치 태깅 terms should(맞은 개수 = 점수)

[임계값]
  min_score = 수집 단계 컷 ── 상대 점수에 고정값 → 쿼리·데이터 따라 걸러지는 비율 변함 → recall 정책 변경
  근사(PQ) 점수 ── 실제보다 낮음 → 절대 임계 0.85 → 아무 쌍도 못 넘음 → 결과 0 (조용히)
  교정: 분포·explain 기반 검증 / 양자화 없는 근사(IVF-Flat)로 교체
```

## 핵심 문장

- 점수는 **상대값**이다 — 쿼리 구조·필드 통계·boost에 따라 스케일이 바뀐다.
- `should`는 **합**, `dis_max`는 **최댓값**이다 — 같은 정보의 다른 표현은 dis_max로 묶는다.
- 빈 OR의 fallback이 `match_all`이면 **fail-open**이다.
- TF 누적과 길이 정규화는 **거친 표현·긴 필드**에 체계적 편향을 준다 — 쿼리가 아니라 매핑이 결정하는 것도 있다.
- 신호를 지우면(constant_score) 순위의 **차등 정보**도 사라진다.
- 상대·근사 점수에 **고정 임계**를 걸면 recall이 조용히 바뀐다.
