# cs/issue/search-engine/query-index-representation-mismatch — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
        색인측 변환                              질의측 변환
원문 ─▶ [index analyzer / normalizer] ─▶ 토큰     검색어 ─▶ [search analyzer | 없음(term류)] ─▶ 토큰
                                           │                                                  │
                                           └────────────── 바이트 비교 ────────────────────────┘
                                                 같으면 hit · 다르면 0점 (에러 없음)

어긋나는 방식
  term(분석 안 함)   "ACME"        vs 색인 "acme"(lowercase)            → 0건
  search_analyzer 없음  검색어도 edge n-gram → "마" 1글자 → 희귀 → IDF 최대 → 무관 문서 상위
                     검색어도 도메인 변환 재통과 → 쓰레기 토큰
  keyword 정규형     "9" vs "09" · "02.09.25" vs "020925" · "W0123" vs "123"   → 0건 / 집계 버킷 분열
  keyword 대소문자   .lower() wildcard vs 대문자 원본(normalizer 없음)          → 누락
  필드 부재          .keyword 오부착 · 옛 필드명 · 설계만 있고 매핑엔 없는 서브필드  → 0점 (조용히)
  index:false       저장만, 역색인 없음                                         → 어떤 쿼리로도 불가
  nested            숨은 문서 → 루트 레벨 쿼리·정렬 안 닿음                     → 무동작
  질의 정규화 ≠ 색인 토큰화   "foobar" vs ["fo","foo",...,"bar"]           → dead 필드 (디스크만)

교정 원칙
  질의측 변환 = 색인측 변환 (대칭)    ── 한쪽을 바꾸면 다른 쪽도 같이
  코드 작성 전 _mapping 확인 · 실데이터 확인 · 수정마다 카운트 질의로 실측
  근본 = 쓰기 경로 정규화 (읽기 경로 정규화는 임시)
```

## 핵심 문장

- 엔진은 쿼리와 인덱스의 표현이 어긋나도 **에러가 아니라 0건·0점**을 준다.
- `term`·`terms`·`wildcard`·`prefix`는 **분석하지 않는다** — 색인측 변환을 쿼리 쪽에서 똑같이 재현해야 한다.
- `search_analyzer`를 안 주면 **색인 분석기가 검색어에도** 걸린다.
- keyword는 **바이트 정확일치**다 — 자릿수·구분자·접두사·대소문자가 다 계약이다.
- 매핑에 없는 필드를 쿼리해도 조용하다 — **코드와 매핑을 대조**하고 카운트로 실측한다.
- 질의측과 색인측 변환은 **대칭**이어야 하고, 한쪽만 고치면 다른 쪽이 조용히 죽는다.
