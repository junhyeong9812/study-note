# cs/issue/search-engine/query-index-representation-mismatch — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
        색인측 변환                              질의측 변환
원문 ─▶ [index analyzer / normalizer] ─▶ 토큰     검색어 ─▶ [search analyzer | term류: 분석 없음(keyword면 normalizer만)] ─▶ 토큰
                                           │                                                  │
                                           └────────────── 바이트 비교 ────────────────────────┘
                                                 같으면 hit · 다르면 0점 (대개 에러 없음)

어긋나는 방식
  term(분석 안 함)   "ACME"        vs 색인 "acme"(lowercase)            → 0건
  search_analyzer 없음  검색어도 edge n-gram → "마" 1글자 토큰 → 매칭 범위 폭증 → 무관 문서 유입
                     (df(마) ≥ df(라마) — 희귀해서가 아님, 원인은 _explain으로 확인)
                     검색어도 도메인 변환 재통과 → 쓰레기 토큰
  keyword 정규형     "9" vs "09" · "A-01" vs "A01" · "K123" vs "123"   → 0건 / 값별 버킷 분열
  keyword 대소문자   .lower() wildcard vs 대문자 원본(normalizer 없음)          → 누락
  필드 부재          .keyword 오부착 · 옛 필드명 · 설계만 있고 매핑엔 없는 서브필드  → 검색 절은 0점(조용히)
                                                                              정렬은 기본 오류(unmapped_type 시 무시)
  index:false       역색인 없음 → text는 검색 불가(오류), doc values 있는 타입은 느린 검색만
  nested            숨은 문서 → 루트 레벨 쿼리·정렬 안 닿음                     → 무동작
  질의 정규화 ≠ 색인 토큰화   "foobar" vs ["fo","foo",...,"bar"]           → 공백 포함 질의 경로에선 무용

교정 원칙
  질의측 토큰이 색인측 토큰과 호환 (대칭 = 같은 파이프라인이 아니라 같은 표현 공간)
                                     ── n-gram 색인은 검색측엔 n-gram 안 함 · 한쪽을 바꾸면 다른 쪽도 같이
  코드 작성 전 _mapping 확인 · 실데이터 확인 · 수정마다 카운트 질의로 실측
  근본 = 쓰기 경로 정규화 (읽기 경로 정규화는 임시)
```

## 핵심 문장

- 엔진은 쿼리와 인덱스의 표현이 어긋나도 **에러가 아니라 0건·0점**을 준다.
- `term`·`terms`·`wildcard`·`prefix`는 **analyzer를 적용하지 않는다**(keyword 필드의 normalizer는 적용된다) — text 필드에 쓰면 색인측 변환을 쿼리 쪽에서 재현해야 하고, 매칭 단위는 원문 전체가 아니라 **토큰**이다.
- `search_analyzer`를 안 주면 **색인 분석기가 검색어에도** 걸린다 — `search_analyzer`는 기존 필드에도 매핑 업데이트로 지정할 수 있다(새 분석기 정의는 settings 변경 필요).
- keyword는 **바이트 정확일치**다 — 자릿수·구분자·접두사·대소문자가 다 계약이다.
- 매핑에 없는 필드에 대한 검색 절은 조용하다(정렬은 기본 오류) — **코드와 매핑을 대조**하고 카운트로 실측한다.
- 질의측과 색인측은 **호환되는 토큰 표현**을 만들어야 하고, 한쪽만 고치면 다른 쪽이 조용히 죽는다.
