# cs/issue/search-engine/cluster-ops-traps — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
운영 조건                         엔진이 조용히 들어가는 모드             드러나는 증상
─────────────────────────────    ─────────────────────────────────     ─────────────────────────
디스크 > flood_stage       ──▶    인덱스에 read_only_allow_delete 블록  ──▶ 쓰기 거부 (공간 회복 후에도)
디스크 100%                ──▶    샤드 할당·복구 거부                  ──▶ primary 미할당 → RED
노드 1개 + replica ≥ 1     ──▶    replica는 같은 노드에 못 놓임         ──▶ 영구 미할당 (green 불가)
refresh 소형 세그먼트 누적  ──▶    세그먼트 수백 개 · 병합 자원 경합     ──▶ 검색 지연
  └ force merge → 1개 거대    ──▶    병합 정책 상한 무시                  ──▶ 역효과 (더 느려짐)
alias 이름 = 기존 인덱스    ──▶    같은 이름공간 충돌                    ──▶ alias 생성 거부
라이선스 등급 basic         ──▶    고급 기능(RRF retriever) 게이팅      ──▶ 기능 부재
버전에 없는 설정 키         ──▶    부팅 검증에서 거부                    ──▶ 노드 기동 실패

교정 방향
  블록: 원인(디스크) 해소 + 블록을 명시적으로 해제 (단일 노드·전용 디스크면 워터마크 재조정)
  replica: 단일 노드는 number_of_replicas = 0
  세그먼트: 과도 병합 대신 세그먼트 크기 상한을 정해 재색인 + 남은 병목(정렬)은 요청 경로에서 분리
  alias: 이름 충돌을 경고로 삼키지 말고 원인(실제 인덱스)을 정리해야 함
  기능 게이팅: 앱 레벨에서 순위 기반 융합 1/(k + rank)
  설정: 버전 문서에 있는 키만 · 병렬 레버 = 샤드 수
```

## 핵심 문장

- 검색엔진 클러스터는 운영 조건에 따라 **에러 대신 모드를 바꾼다** — read-only, 미할당, 기능 게이팅.
- flood_stage 블록은 **자동으로 걸리지만 해제는 수동**이다(보호는 자동, 복구는 사람 몫).
- replica는 primary와 **같은 노드에 놓이지 않는다** — 단일 노드에서 replica ≥ 1은 영원히 미할당.
- 세그먼트가 너무 많아도, **너무 크게 합쳐도** 느리다 — force merge는 병합 정책의 크기 상한을 따르지 않는다.
- alias와 인덱스는 **같은 이름공간**이다.
- "오픈소스 엔진"도 기능은 **라이선스 등급**에 묶일 수 있다 — 순위 기반 융합은 앱에서 할 수 있다.
- 없는 설정은 **부팅 거부**(fail-closed)다 — 적용되는지 확인하지 않은 설정은 넣지 않는다.
