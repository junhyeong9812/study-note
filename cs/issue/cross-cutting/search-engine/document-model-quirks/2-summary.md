# cs/issue/search-engine/document-model-quirks — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
hit = { "_id": "...", "_score": 1.2, "_source": { ...원본 JSON... } }
        └ 메타필드 (_source 밖)          └ 저장된 원문

[메타필드]   hit["_source"]만 전달 ──▶ _id 소실 ──▶ 하위 로직이 "" 로 조용히 실패
            교정: {**hit["_source"], "_id": hit["_id"]}

[값 부재]    null / 필드 없음   ─▶ missing 정책 적용 (_first/_last)
            ""  (빈 문자열)     ─▶ 정상 값 → 사전순 맨 앞  ── missing 무력
            교정: 임시 = 스크립트 1차 정렬(빈값 뒤로) / 근본 = 색인 시 "" → null + 재색인

[스크립트]   정렬 스크립트는 매칭 문서 "전부"에서 실행
            doc[f].value (값 없는 문서) ─▶ 예외 ─▶ 요청 전체 실패
            결과가 클수록 값 없는 문서가 섞일 확률 ↑ ─▶ "특정 검색어에서만" 재현
            교정: if (doc[f].size() == 0) return 기본값;
            params._source 접근 ─▶ 문서마다 원문 파싱 ─▶ 느림 → 미리 계산한 필드로 정렬

[숨은 문서]  nested 원소 = 별도 Lucene 문서
            _cat/indices docs.count = 부모 + 자식 합   (최상위 건수 아님)
            최상위 건수 = _count / size=0 total
            완료 판정 = 기준 대비 비율 + 시간 간격 두고 2회 같은 값(건수 정지)

[키 충돌]    같은 _id 색인 = 덮어쓰기 (last-write-wins, 배치 경계면 비결정)
            불량 stub이 마지막 → 정상 문서 소실
            _id 규칙 변경 → 옛 _id 문서는 안 지워짐 (고아)
            교정: 읽기 단계에서 자연키로 collapse(유효값 병합, stub 최후순위) + 재색인 전 인덱스 삭제
```

## 핵심 문장

- `_id`는 `_source` 밖의 **메타필드**다 — `_source`만 넘기면 조용히 사라진다.
- `missing`은 **null·부재에만** 적용된다 — `""`은 값이고, 정렬 맨 앞에 온다.
- 정렬 스크립트는 **매칭된 모든 문서**에서 돈다 — 값 없는 문서 하나가 요청 전체를 깬다.
- `_source` 접근은 원문 파싱이라 doc_values보다 느리다 — 정렬용 값은 **색인 시점에 미리 계산**한다.
- nested 원소는 **숨은 문서**다 — 저수준 docs.count는 부모+자식 합이다.
- 같은 `_id`는 **마지막 쓰기가 이긴다** — 순서를 통제하지 않으면 누가 이길지 모른다.
