# cs/issue/search-engine/query-and-index-cost-limits — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
입력 분포 (키워드 수 · 토큰 수 · 후보 수 · 배치 부피)
     │
     ├─[쿼리 경로]──────────────────────────────────────────────────────────
     │   키워드 N개 → bool.should N절 ──▶ 절 한도(힙·스레드 기반, 기동 시 고정) ──▶ 400
     │        교정: OR + filter 컨텍스트 → 청크별 동일 쿼리 합집합 = 단일 쿼리 (수학적 동치)
     │              _msearch 1회 · _id dedupe · 재정렬 · 청크 1개 실패 = 전체 실패
     │   fuzzy → 사전순 확장 max_expansions에서 절단 ──▶ 정답 term 누락 (상한이 정확도를 깎음)
     │   wildcard *x* → term 사전 전체 순회 ──▶ 10ms → 297ms
     │        교정: 색인 시점 edge n-gram(앞·뒤) → 쿼리는 term 조회
     │
     └─[색인 경로]──────────────────────────────────────────────────────────
         토큰별 후보 k개, 토큰 n개 → 변형 k^n (cartesian)
             × 다중값 필드 × n-gram 서브필드 ──▶ 인덱스 수배 · 워커 메모리 spike
             교정: 곱하기 "전에" 토큰당 후보 cap · 결과 cap · 분석기는 상위 몇 개 변형에만
         bulk 부피 = 배치 × 변형 × 서브필드
             ──▶ 요청 메모리 > circuit breaker ──▶ 429 Data too large
             ──▶ 힙 초과 ──▶ 노드 OOM · 샤드 RED · 부분 실패
             ──▶ 처리 시간 > 클라이언트 타임아웃 ──▶ Read timeout
         동시 in-flight > 쓰기 큐 ──▶ 429 rejected
             교정: 배치·워커를 서버 큐·힙에 맞춤 · 힙은 32GB 미만 · 동시 실행 금지
```

## 핵심 문장

- 엔진 상한은 **설정보다 사양**이 정하기도 한다 — 절 한도는 힙·스레드로 자동 산정된다.
- OR + filter 쿼리는 **청크 합집합과 동치**다 — 단, 청크 하나라도 실패하면 전체를 실패시킨다(부분 결과 무음 금지).
- cartesian은 입력 길이에 **지수적**이다 — 결과 cap이 아니라 **곱하기 전 인자**를 줄여야 메모리를 막는다.
- 요청 크기(배치 × 변형 × 서브필드)와 동시성은 **서버 한도(breaker·큐·힙)에 맞춘다**.
- 상한은 양날이다 — max_expansions처럼 **정확도를 깎는** 상한은 값을 올리거나 색인 구조로 우회한다.
