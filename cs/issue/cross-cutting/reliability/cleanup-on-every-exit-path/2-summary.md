# cs/issue/reliability/cleanup-on-every-exit-path — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
 acquire(자원/락/permit/상태=alive)
    │
    ├─ 정상 종료 ─────────────┐
    ├─ 에러 return / `?` ─────┤      경로마다 release를 흩어 두면
    ├─ 취소 (future drop) ────┤  →   하나만 빠져도: 좀비·fd 누수·permit 0 수렴
    ├─ 패닉 / 예외 ───────────┤      "영원히 진행 중"·창이 안 닫힘·DB 잔존
    └─ spawn 실패(회수 담당 없음)┘
                               ↓ 교정
     스코프 소멸에 묶는다: RAII Drop · try/finally · trap(재진입 차단)
     → 모든 경로에서 정확히 1회

 추가 함정
   release 여부를 기억 안 함 → 획득 없이 반납 → 카운터 음수 → 한도 무력화
   예외를 던지는 호출이 try 밖   → 반납 누락
   정리 호출에 취소된 ctx          → 정리 자체가 즉시 실패
   프로토콜 raw 구간 전환 뒤 실패  → 에러를 보고할 길 없음 → 실패 가능 작업은 전환 전에
   정리 주체 부재                 → lazy reap(조회해야 풀림)·UI 연결 시에만 감시
                                    → 감시는 서버 기동 시 무장, 종료는 watch로 관측
   trap 핸들러의 exit → EXIT trap 재발화 → 이중 원복
```

## 핵심 문장

- 종료 경로가 여럿이면 정리를 경로에 흩지 말고 **스코프 소멸**에 묶는다.
- 반납은 "**획득했을 때만, 모든 경로에서 정확히 한 번**" — 획득 여부를 상태로 기억하고, 던질 수 있는 호출은 보호 범위 안에.
- 회수 담당을 띄우기 **실패한 분기**는 이미 확보한 자원을 직접 되돌린다.
- 여러 종료 경로에 걸린 규칙은 **유일한 종료 문** 하나로 모은다.
- 정리는 **취소되지 않는 별도 context**로, 감시는 **연결이 아니라 기동**에 매단다.
- trap 핸들러는 **재진입을 스스로 차단**한다.
