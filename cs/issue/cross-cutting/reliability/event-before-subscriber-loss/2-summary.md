# cs/issue/cross-cutting/reliability/event-before-subscriber-loss — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
보관 없는 채널:  발행 순간 연결된 구독자에게만 전달, 아무도 없으면 그냥 버림 (에러 없음)

시간축 ─────────────────────────────────────────────────────▶
생산자      create ── emit(e1) ── emit(e2) ──────────────── emit(e3)
구독자                       ↑ listen() 등록 완료
                              (e1 은 이미 지나감 = 영구 유실)

[유실이 나는 자리]
  ① 소비 조건 미충족인데 요청을 "소비 완료"로 지움 (api 미준비 → null 로 삭제)
  ② "창 생성됨" ≠ "리스너 준비됨"    → 생성 직후 emit 유실
  ③ listen() 을 await 안 함          → 빠른 ack 유실 → 타임아웃 → 재삽입 → 이중 소유
  ④ void create(); request(target)   → 대상 부재로 무음 드롭
  ⑤ backfill 없는 늦은 구독          → 중간 seq 부터 받음 (테스트가 seq==1 단언 → flaky)
  ⑥ 수신자 없는 메시지 / 늦게 연결된 소비자 → 페이지 로드 시점 데이터 누락
  ⑦ 이미 지난 로드 이벤트 구독       → 리스너 영영 안 불림
  ⑧ 소비자 다운 중 pub/sub 발행      → 다운 구간 전체 유실

[교정]
  구독 먼저, 발행 나중  : await listen() → 그 다음 emit
  준비 핸드셰이크       : 대상이 "모든 리스너 준비됨"을 ack → 그 후에 보냄
  수명 긴 전역 리스너   : 짧은 수명 컴포넌트 대신 항상 떠 있는 곳에서 받음
  캐시 + 재전송(backfill): 새 소비자 연결 시 마지막 상태를 다시 보냄
  이미 지난 사건        : 사건을 기다리지 말고 상태를 확인하고 직접 호출
  내구성 스트림         : 보관(maxlen 상한) + 소비자 그룹 + ACK + pending 복구
```

## 핵심 문장

- 보관 없는 채널에서 **구독 전·구독자 부재 중** 발생한 사건은 에러 없이 영구히 사라진다.
- "대상이 존재함"은 "대상이 들을 준비가 됨"이 아니다 — 준비는 **대상이 명시적으로 알려야** 한다(ready 핸드셰이크).
- 구독 등록이 비동기면 **등록 완료를 기다린 뒤** 상대를 움직인다 — 순서가 바뀌면 빠른 응답일수록 잃는다.
- 늦은 구독자에게 과거를 주려면 **backfill(스냅샷·재전송)**이 있어야 하고, 없다면 "처음부터 받는다"를 전제로 삼으면 안 된다.
- 소비자 다운 구간까지 지키려면 **보관하는 스트림 + ACK**로 바꾼다 — 재연결 루프는 "다시 듣기"만 할 뿐 "놓친 것"을 돌려주지 않는다.
