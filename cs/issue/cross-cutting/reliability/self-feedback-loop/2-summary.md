# cs/issue/reliability/self-feedback-loop — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[양의 피드백 루프 — 출력이 입력 공간으로 돌아간다]

  (1) 부산물 재처리
      scan(input_dir) ──▶ process(item) ──▶ 하위 도구가 cwd=input_dir 에 새 기록을 남김
            ▲                                              │
            └──────────── 다음 스캔의 입력 ◀───────────────┘      179 → 256 폭주

  (2) 브로드캐스트 echo
      창A: set(x) → emit(x) ──▶ 창A·창B 모두 수신 ──▶ 수신 핸들러가 다시 emit/persist ──▶ 핑퐁

  (3) 측정 대상이 측정 결과로 바뀜
      내 폭 < 기준 → 접음 → 내 폭 줄어듦 → 펼침 → 내 폭 늘어남 → 넘침 → 접음 → 진동

[차단 — 되돌아오는 간선을 구조로 끊는다]
  (1) 하위 도구의 작업 디렉토리를 입력 공간 밖(정확한 스크래치 경로)으로 격리
      + 2차 방어: 부산물 마커 필터 (단독으로는 생성이 계속되므로 부족)
  (2) 메시지에 출처를 싣고 self·같은 값이면 no-op, 원격 적용 경로는 emit/persist 하지 않음
  (3) 판정 기준을 자기 크기가 아니라 외부가 정하는 크기(부모 폭)로

[탐지]  장시간 배치의 "완료 수치 이상" = 즉시 중단 신호
```

## 핵심 문장

- 처리기가 자기 입력 공간에 산출물을 남기면 다음 주기에 그 산출물을 다시 처리한다 — 양의 피드백 루프.
- 필터는 증상을 거르고 생성은 계속된다 — 1차 차단은 산출물이 입력 공간에 안 생기게 하는 **경로 격리**, 필터는 2차 방어.
- 격리 제외 범위는 정확한 경로로 좁힌다(넓히면 정상 입력까지 빠진다).
- 브로드캐스트 수신 경로는 상태만 적용하고 재방송·재저장하지 않는다(출처 표식 + 같은 값 no-op).
- 측정 대상이 측정 결과로 바뀌면 진동한다 — 판정 기준은 외부가 정하는 크기로.
- 장시간 배치의 수치 이상은 즉시 중단 신호다.
