## 질문
1. (왜) 세션 기록을 읽어 요약하는 배치가, 요약하려고 부른 하위 도구가 **현재 디렉토리 기준으로** 새 세션 기록을 남긴다. 배치를 같은 디렉토리에서 돌리면 대상 개수가 179에서 256으로 늘어난 이유는? 이것이 "양의 피드백"인 이유는.
2. (예측) 이 루프는 리뷰 4번을 전부 통과했고, 단서는 "완료 수치가 이상하다(예상 3건이 10분 넘게, 완료 수가 목표보다 큼)"였다. 장시간 배치에서 이런 수치 이상을 보면 왜 **즉시 중단**해야 하는가?
3. (경계) 해결책 둘 — (a) 부산물을 알아보는 마커로 입력에서 걸러내기 (b) 부산물이 애초에 입력 공간에 안 생기도록 작업 디렉토리를 격리하기. 왜 (a) 단독은 선택하지 않았는가? "격리는 필터가 아니라 경로에서 파생한다"의 의미는.
4. (경계) 격리 제외 규칙을 "임시 디렉토리 전체"로 넓게 잡았더니 회귀가 생겼다. 제외 범위를 **정확한 스크래치 경로**로만 좁혀야 하는 이유는?
5. (왜) 창 여러 개가 상태를 동기화하려고 전역 브로드캐스트를 쓴다. 브로드캐스트가 **보낸 창에도** 돌아오고, 수신 핸들러가 받은 값을 다시 방송·저장하면 무슨 일이 생기는가? 수신 경로를 어떻게 설계해야 루프가 끊기는가.
6. (연결) 레이아웃에서 "자기 폭이 좁으면 접는다"는 규칙이 접힘↔펼침 진동을 만드는 이유는? 이것이 위 두 사례(부산물 재처리·브로드캐스트 echo)와 같은 구조인 이유를 "측정 대상이 측정 결과로 바뀐다"로 설명하라.
7. (연결) 세 사례에 공통인 루프 차단 방법을 한 문장으로: 출력이 입력으로 돌아가는 경로를 **어디서** 끊어야 하는가.
