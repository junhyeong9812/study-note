## 정답
<!-- 질문 1:1 대응 -->

1. **출력이 입력 공간으로 돌아갔다.** 배치는 "이 디렉토리의 세션 기록"을 입력으로 스캔하는데, 요약을 위해 부른 하위 도구가 **현재 작업 디렉토리 기준으로** 자기 실행 기록을 남긴다.\
배치를 대상 디렉토리에서 돌리면 처리 1건마다 새 입력 1건이 생기고, 다음 스캔(회수 패스)이 그것을 다시 처리해 또 새 기록을 만든다 — 179건이 256건으로 늘었고, 무의미한 호출이 약 60회 낭비됐으며 부산물이 산출물(아카이브·지식)을 오염시켰다.\
출력이 입력을 늘리고 늘어난 입력이 다시 출력을 늘리므로 **양의 피드백**이다.
   > **양의 피드백 루프(positive feedback loop)** — 시스템의 출력이 입력에 더해져 같은 방향의 변화를 증폭시키는 순환. 상한이 없으면 발산한다.

2. **수치 이상이 유일한 관측 신호였다.** 이 루프는 코드 한 줄의 결함이 아니라 도구의 부수효과(작업 디렉토리에 기록을 남김)와 배치의 입력 정의가 만나서 생긴 것이라, 코드 리뷰로는 보이지 않았다(리뷰 4번 모두 놓침).\
"완료 수가 목표보다 크다", "3건 예상이 10분 넘게 걸린다"는 입력 집합이 **처리 도중 늘고 있다**는 직접 증거다.\
양의 피드백은 시간이 갈수록 비용과 오염이 커지므로, 원인을 알기 전이라도 즉시 중단하는 게 손실을 가장 작게 한다.

3. **필터는 생성을 멈추지 않는다.** (a) 마커 필터는 부산물을 "처리하지 않을" 뿐, 부산물은 계속 입력 공간에 **생성**된다 — 공간을 오염시키고, 마커가 바뀌거나 다른 소비자가 같은 공간을 읽으면 다시 샌다.\
(b) 하위 도구의 작업 디렉토리를 입력 공간 밖의 고정 스크래치 경로로 옮기면 부산물이 입력 공간에 **존재하지 않게** 된다 — 루프의 되돌아오는 간선을 구조로 끊는다.\
"격리는 필터가 아니라 경로에서 파생한다": 제외 판정을 문자열 조건으로 덧대는 대신, 격리 경로 자체가 스캔 범위 밖이 되게 한다. 필터는 2차 방어로 함께 둔다.

4. **넓은 제외는 정상 입력을 삼킨다.** "임시 디렉토리 아래는 전부 부산물"이라고 넓게 잡으면, 사용자가 실제로 임시 디렉토리에서 작업한 정상 프로젝트까지 제외되는 회귀가 생긴다.\
제외 규칙은 격리에 쓴 **정확한 스크래치 경로**(또는 명시 플래그)에만 걸어야 부산물만 정확히 빠진다.
   (원 기록의 실제 경우: 스크래치 cwd에서 도구 등록을 건너뛰는 규칙을 임시 디렉토리 전체에 걸었다가, 임시 디렉토리의 실제 프로젝트까지 빠지는 회귀를 리뷰에서 지적받아 좁혔다.)

5. **보낸 쪽에도 돌아오는 브로드캐스트.** 이 사례의 앱 프레임워크 전역 이벤트는 보낸 창을 포함한 모든 창에 전달된다(채널마다 다르다 — 브라우저 `BroadcastChannel`·`storage` 이벤트처럼 보낸 쪽을 제외하는 채널도 있으나, 그래도 수신 쪽이 재방송하면 다른 창과 핑퐁한다). 수신 핸들러가 받은 값을 적용한 뒤 다시 방송하거나 저장하면, 그 방송이 또 모든 창에 가서 창끼리 핑퐁한다.\
설계: 메시지에 **출처 창 식별자**를 싣고, 수신 쪽은 `출처 == 자기` 또는 `값 == 현재 값`이면 무시한다.\
그리고 원격에서 온 값을 적용하는 경로는 **상태만 갱신하고 방송·저장을 하지 않는다** — "로컬 변경"과 "원격 적용"을 다른 함수로 나눈다.

6. **측정 대상이 측정 결과로 바뀐다.** 컨트롤 묶음의 폭은 콘텐츠 크기라서 접으면 줄고 펼치면 는다.\
"내 폭이 좁으면 접는다"에서 측정값(내 폭)은 판정 결과(접힘/펼침)에 따라 달라지므로, 판정이 자기 입력을 바꾼다 — 측정·판정 규칙에 따라 접힘↔펼침이 번갈아 뒤집히는 진동이 생기거나, 한 번 접히면 폭이 줄어 다시 펼 조건이 영영 안 오는 고착이 생긴다. 어느 쪽이든 판정에 안정점이 보장되지 않는다.\
같은 구조: 부산물 재처리는 "처리가 입력을 바꾸고", 브로드캐스트 echo는 "방송이 자기 수신을 부르고", 레이아웃 진동은 "판정이 판정 기준을 바꾼다" — 모두 출력이 자기 입력으로 되돌아간다.\
(이 사례는 버그 발생이 아니라 설계 단계에서 식별해 회피한 것이다.)

7. **되돌아오는 간선을 구조로 끊는다.** 출력이 입력 공간·자기 수신·자기 판정 기준에 닿지 않도록 **경로·출처·기준 자체를 분리**한다 — 산출물은 입력 공간 밖에, 원격 적용은 재방송 없이, 판정 기준은 외부가 정하는 크기로.\
사후 필터는 보조 방어이고, 1차 방어는 루프가 성립하지 않는 구조다.

## 문제 구조 (추상화 코드)

### 변형 A — 처리기가 자기 입력 공간에 부산물을 남김
① 문제 코드
```rust
for item in scan(project_dir) {                         // 입력 = project_dir 의 세션 기록
    Command::new("sub-tool").arg("-p").arg(prompt(&item))
        .current_dir(project_dir)                        // 하위 도구가 cwd 기준으로 새 기록을 남김
        .output()?;                                      // → 다음 스캔의 입력 (179 → 256)
}
```
② 고친 코드
```rust
pub fn scratch_workdir() -> PathBuf {
    let dir = std::env::temp_dir().join("app-extract");  // 고정 스크래치 경로 (입력 공간 밖)
    let _ = std::fs::create_dir_all(&dir);
    dir
}
pub const SCRATCH_MARKER: &str = "<추출 프롬프트 고정 첫 문장>";

Command::new("sub-tool").arg("-p").arg(prompt(&item))
    .current_dir(scratch_workdir())                   // 1차: 경로 격리 (구조 차단)
    .output()?;

// 스캔 쪽 2차 방어
if first_prompt(&t).starts_with(SCRATCH_MARKER) { continue; }   // 마커 필터
if is_scratch_dir(&dir) { continue; }                              // 정확한 스크래치 경로만 제외
```
무엇이 깨졌나: 처리기의 부수효과가 처리기의 입력 공간에 쓰여, 자기 산출물을 다시 입력으로 소비했다.\
같은 구조: 같은 하위 도구를 쓰는 후속 기능(정리·그래프 생성)도 같은 불변식을 상속(스크래치 cwd + 필요한 디렉토리만 추가 허용).\
같은 구조: 스크래치 cwd용 등록 스킵 규칙을 임시 디렉토리 전체로 넓혔다가 임시 디렉토리의 실제 프로젝트가 빠지는 회귀(리뷰 지적) → 정확한 스크래치 경로·명시 플래그로 축소.

### 변형 B — 브로드캐스트가 보낸 쪽에도 돌아와 echo
① 문제 코드
```ts
listen("state-sync", (e) => {
  store.setActiveProject(e.payload.activeProject);   // 로컬 변경 경로 재사용 → 내부에서 emit + persist
});
function setActiveProject(p) { set({ active: p }); emit("state-sync", { activeProject: p }); persist(p); }
```
② 고친 코드
```ts
const self = currentWindow().label;
emit("state-sync", { activeProject: p, sourceWindow: self });

listen("state-sync", (e) => {
  const { activeProject, sourceWindow } = e.payload;
  if (sourceWindow === self || activeProject === get().activeProject) return;   // 자기 것·같은 값 no-op
  get().applyRemote(activeProject);                                         // set 만 — emit·persist 없음
});
// 포커스 추적도 수신 경로에서는 상태만 갱신
```
무엇이 깨졌나: 원격 적용 경로가 로컬 변경 경로(방송·저장 포함)를 재사용해, 수신이 다시 송신을 불렀다.

## 방안 비교

기본 방안(위 변형 A·B)은 "되돌아오는 간선을 경로·출처로 끊는다"이다. 같은 원리(출력이 자기 입력으로 되돌아가는 루프)에 다른 방안이 쓰인 사례:

### 방안 1 — 측정 기준을 외부가 정하는 크기로 (레이아웃 진동)
```tsx
// 문제: 자기 폭(콘텐츠 크기, flex: 0 0 auto)을 재서 접힘 판정 → 접힘↔펼침 진동
const selfWidth = useWidth(controlsRef);
const collapsed = selfWidth < needed;

// 고친: 부모(host) 행 폭을 재서 판정 — 접어도 펼쳐도 기준이 변하지 않는다
const hostWidth = useResizeObserverWidth(hostRowRef);
const collapsed = shouldCollapse(hostWidth, needed);   // 순수 함수, 단위테스트
export function shouldCollapse(host: number, needed: number) {
  if (host === 0) return false;                          // 측정 전(폭 0)에는 접지 않음
  return host < needed;
}
// 래퍼는 display: contents — 감싸도 버튼 배치가 같음을 실측으로 확인
```
설계 단계에서 식별해 회피한 사례(실제 진동 버그 기록은 없음).

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|------|------|------|-----------|-----------|
| 기본 A: 경로 격리 + 마커 필터 | 부산물의 생성 위치를 호출자가 정할 수 있다 | 스크래치 경로 관리 | 제외 범위가 넓으면 정상 입력 누락 | 입력 공간을 스캔하는 배치가 같은 공간에 쓰는 도구를 부를 때 |
| 기본 B: 출처 표식 + 수신 경로 무방송 | 메시지에 출처를 실을 수 있다 | 로컬/원격 적용 경로 분리 | 새 수신 경로가 로컬 경로를 재사용하면 재발 | 보낸 쪽에도 돌아오는 브로드캐스트 동기화 |
| 1. 외부 기준 측정 | 판정 기준을 판정 결과와 독립인 값으로 바꿀 수 있다 | 측정 대상 변경 | 외부 값이 0(측정 전)일 때의 처리 필요 | 판정 결과가 측정값 자체를 바꾸는 레이아웃·제어 |

**결론**: 루프의 되돌아오는 간선이 **외부 부수효과**(파일·메시지)면 그 부수효과가 입력 공간·자기 수신에 닿지 않게 경로·출처로 끊는다(기본).\
되돌아오는 간선이 **판정 기준 자체**면 기준을 판정 결과와 독립인 외부 값으로 바꾼다(1).\
어느 쪽이든 사후 필터는 2차 방어이고, 장시간 작업의 수치 이상은 루프의 첫 관측 신호다.
