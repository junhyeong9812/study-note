# cs/issue/reliability/change-detection-key-design — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
두 종류의 키 — 역할이 반대다
 ┌──────────────────────────────┐        ┌──────────────────────────────┐
 │ 변경 감지·캐시 무효화 키       │        │ 잠금·정체성 키 ("이미 했나")   │
 │ = 결과에 영향 주는 입력 전부   │        │ = 불변 주소(host·id·path)만    │
 │ 하나라도 빠지면 → 갱신 누락     │        │ 가변값이 들어가면 → 무한 루프  │
 └──────────────────────────────┘        └──────────────────────────────┘

[갱신 누락 경로]  입력 변화 → 키 불변 → "변화 없음" → emit·재빌드 skip → 화면/산출물 stale (에러 0)
   지문이 표시 상태 일부만      → usage만 바뀐 레코드 무시
   revision 합(리셋 가능)       → 재구축 후 같은 합·다른 내용 (ABA)
   길이만 / uuid만 / revision만 → 같은 길이 재작성·uuid 없는 레코드·새 이미지 놓침
   디렉터리 mtime               → 직속 엔트리 변경만 반영, 깊은 파일 변경 무시
   mtime 보존 복원 · 초 해상도  → 증분 빌드가 옛 산출물 재사용 / 같은 초 연속 변경 누락
   자라는 값을 키로 게이팅       → 첫 조각에서 얼어붙음

[무한 루프 경로]  잠금 키 = f(가져온 결과·가변 서명) → 회수 → 키 바뀜 → 잠금 초기화 → 재회수 ...

[교정]  감지 키: 입력 전부(세대 카운터·파일 서명·ns mtime+경로 해시·길이+해시)
        정직한 키가 없으면 캐시 대신 비용 자체를 제거
        잠금 키: 주소만 / 신선도(isStale)는 별도 표시 / tail: (dev, ino, len, head) 정체성
```

## 핵심 문장

- 변경 감지 키는 **결과에 영향을 주는 입력 전부**의 함수여야 한다 — 빠진 입력의 변화는 무음으로 사라진다.
- 합·길이·mtime은 **근사 신호**다 — 리셋·동일 길이·해상도·디렉터리 의미가 구멍을 낸다.
- 자라는 값은 키가 아니라 **값(길이+해시)**으로 게이팅한다.
- 잠금·정체성 키에는 **가변값을 넣지 않는다** — 넣으면 잠금이 아니다. 신선도는 따로 표시한다.
- 오프셋 tail의 불연속은 **파일 정체성(dev·ino)과 길이 감소·선두 바이트**로 판정한다.
