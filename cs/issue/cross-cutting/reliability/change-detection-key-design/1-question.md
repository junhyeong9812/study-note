## 질문
1. 폴링 루프가 "지문(fingerprint)이 바뀌었을 때만 화면에 emit"한다. 지문이 표시에 영향을 주는 상태 하나를 빠뜨리면 어떤 증상이 나는가. 왜 이 버그는 에러 없이 조용한가.
2. 여러 카운터(revision)의 **합**이나 "파일 길이 하나", "마지막 id 하나"를 버전·동일성 키로 쓰면 어떤 경우에 "다른 내용인데 같은 키"가 되는가. 리셋될 수 있는 카운터의 합이 특히 위험한 이유는?
3. 디렉터리의 mtime은 언제 바뀌는가. 날짜별 폴더(`YYYY/MM/DD/`) 트리에서 상위 폴더 mtime으로 가지치기를 하면 오늘 만든 파일이 왜 통째로 빠지는가.
4. 예측: 뮤테이션 테스트 스크립트가 소스를 바꿨다가 **mtime을 보존하는 복사**로 원복한다. 증분 빌드(cargo·make) 위에서 다음 케이스의 결과는 믿을 수 있는가? 초 단위 mtime은 또 어떤 변경을 놓치는가.
5. 계속 자라는 값(스트리밍 답변)의 "이미 보냈음"을 **키 존재**로 판정하면 무엇이 멈추고, 게이트를 아예 없애면 무엇이 폭증하는가. 값 사본 대신 무엇을 보관하면 둘 다 피하는가.
6. 경계(반대 방향): "이미 가져왔나"를 막는 **잠금 키**에 `len-mtime` 같은 가변 서명을 넣었더니 자동 회수가 초당 수백 회 돌았다. 캐시 무효화 키에서는 미덕이던 "입력 전부 반영"이 잠금 키에서는 왜 무한 루프가 되는가. 두 역할을 어떻게 분리하는가.
7. 연결: 오프셋 기반 tail은 "같은 파일에 append만 된다"를 가정한다. 파일이 rename 교체·truncate 후 재성장·같은 길이로 원자 교체되면 오프셋만으로 왜 감지하지 못하고, 어떤 정체성 튜플로 불연속을 판정하는가.
