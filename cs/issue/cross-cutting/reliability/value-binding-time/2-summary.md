# cs/issue/cross-cutting/reliability/value-binding-time — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```text
  값의 원천(.env · 설정 파일 · 모듈 전역 · 토글 · 빌드 인자)
        │
        ▼  바인딩 시점 ── 여기서 "사본"이 만들어진다
  ┌───────────────┬────────────────┬───────────────┬─────────────────┬───────────────┐
  │ 빌드           │ import         │ 컨테이너 생성  │ 프로세스 기동    │ 작업 생성      │
  │ 공개 env 인라인│ from X import y│ env · mount   │ env 스냅샷       │ 설정 복사·풀크기│
  │ 이미지 플러그인│ 모듈 상수       │ (inode 고정)  │                 │ 작업 목록 물질화│
  │ 정적 생성 fetch│                │               │                 │ 토픽 자동 생성 │
  └───────────────┴────────────────┴───────────────┴─────────────────┴───────────────┘
        │
        ▼  이후 원천을 바꿔도 사본은 그대로  →  "고쳤는데 반영 안 됨"
           (restart · reload · 재배포는 바인딩 시점을 다시 지나지 않을 수 있다)

  교정
   ① 사용 시점에 다시 읽기     : 모듈 속성 접근 · 함수로 매번 평가 · 매 반복 공유 플래그 재독
   ② 바인딩 시점 다시 통과     : 재생성(up -d / force-recreate) · 부모 재기동 · 재빌드
   ③ 바인딩 시점에 값 공급     : 빌드 컨텍스트에 값 · 기동 순서 보장·사전 생성
   (④ 반영될 수 없는 런타임 조절은 제거 — 동작하는 척하는 UI보다 낫다)
```

**한 문장:** 값은 해석·고정되는 시점(빌드·import·컨테이너 생성·프로세스 기동·작업 생성)에 박제된다 — 이후 변경은 그 시점을 다시 거치지 않으면 반영되지 않는다.

- `restart`는 같은 컨테이너를 다시 켤 뿐이라 env를 다시 읽지 않는다. env·mount는 **생성** 시점에 정해진다.
- `from X import y`는 그 순간의 객체를 로컬 이름에 묶는다. 나중에 X의 전역이 재할당돼도 y는 옛 값이다.
- 모듈 스코프 상수는 import 때 한 번 평가된다. 갱신되는 토큰은 호출 때마다 평가되는 함수여야 담긴다.
- 공개 프론트엔드 env는 빌드 때 번들 문자열로 치환된다. 빌드 컨텍스트에 값이 없으면 런타임 env로 되살릴 수 없다.
- 단일 파일 bind mount는 생성 시점의 inode를 가리킨다. rename 기반 편집은 새 inode를 만들어 컨테이너와 끊긴다.
- 부모가 넘기는 pass-through env는 파일이 아니라 부모 프로세스의 기동 시 사본이다.
- 작업 생성 시 복사한 설정·미리 만든 작업 목록·생성자 인자로 준 풀 크기는 실행 중 변경을 받지 않는다.

## 핵심 문장

- "언제 읽히나"를 먼저 묻는다 — 반영이 안 되면 바인딩 시점을 지나지 않은 것이다.
- restart ≠ 재생성, reload ≠ 새 파일, 재배포 ≠ 부모 재기동.
- 런타임에 바뀌어야 하는 값은 사용 시점에 읽고, 한 번 정해지는 값은 그 시점에 올바르게 공급한다.
- 반영 여부는 원천이 아니라 실행 주체 쪽에서 확인한다(프로세스 environ·컨테이너 inspect·번들 내용).
