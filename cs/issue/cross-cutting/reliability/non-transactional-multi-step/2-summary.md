# cs/issue/cross-cutting/reliability/non-transactional-multi-step — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
트랜잭션 없는 다단계 변경:  step1 → step2 → step3 ... 어디서든 멈출 수 있다
                            ↓ 중간 실패 = half-state (롤백해 주는 사람 없음)

[순서가 틀린 경우]                          [순서로 격리한 경우]
close(old) → start(new) ✗                  start(new) ✓ → meta → seed → close(old)
  → 둘 다 잃음                                 → 실패해도 old 무손상, new 는 catch 에서 회수
메타 삭제 → 비밀 삭제 ✗(무시)              비밀 삭제 → 실패면 메타 보존 + 알림
  → UI 에선 사라지고 비밀은 고아               → 재시도 가능
이동 ✗(skip) → 원본 삭제                    이동 성공 확인 → 빈 디렉토리만 삭제
  → 과거 버전 소실                             → 충돌은 이름 유일화, 잔여는 통째 보존
판별하며 즉시 삭제 → 늦은 판별 실패          전수 판별 → 일괄 삭제, 판별 실패는 전파
persist(throw) → 상태 전이                  상태 전이는 항상 완주, persist 실패는 따로
무효화·한도 소비 → 발송 ✗                   발송 성공 → 발급·활성화
참조 영속화 → 생성 ✗                        생성 성공 → 참조 확정
mkdir → f1 → f2 ✗ → 폴더 잔존 → 재시도 409  try { ... } except: rm(이번에 만든 것); raise

[원칙]
  새것 확보·성공 확인  →  그 다음 파괴
  실패 가능한 쪽 먼저  →  그 결과로 나머지를 게이트
  중간 잔해            →  보상(역순) · 회수 — "내가 만든 것" 만
  소유권 이관          →  수신측 ACK 후 송신측 정리 (make-before-break)
```

## 핵심 문장

- 트랜잭션이 없으면 **단계 순서가 곧 실패 격리**다 — 되돌릴 수 없는 파괴는 마지막에 둔다.
- 두 저장소에 걸친 변경은 **실패 가능한 쪽을 먼저** 하고, 그 성공 여부로 다른 쪽을 게이트한다.
- 실패 분기에서 파괴(삭제)를 수행하는 경로는 **앞 단계 성공 가정 위에서만** 안전하다 — 가정을 확인하거나 파괴를 하지 않는다.
- 중간에 만든 자원은 실패 경로에서 **명시적으로 회수**한다. 보상은 **이번 호출이 만든 것만** — 판별은 연산 결과로 한다.
- 잔해는 존재 검사 가드를 **영구 오탐**으로 만든다 — "재시도 가능한 상태"를 불변식으로 삼는다.
