## 질문
1. 트랜잭션이 없는 다단계 변경(파일시스템·두 저장소·프로세스 교체)에서 "중간 실패"는 어떤 상태를 남기나. 단계 순서를 바꾸는 것만으로 왜 결과가 달라지나.
2. 예측: 세션 교체를 `close(old) → start(new)` 순서로 짠다. `start(new)`가 실패하면 사용자는 무엇을 잃나. make-before-break 순서로 바꾸면 같은 실패가 어떤 상태를 남기나.
3. 두 저장소(메타데이터 파일과 OS 비밀 저장소)에 걸친 저장·삭제에서 "실패 가능한 쪽을 먼저"는 구체적으로 어떤 순서인가. 메타데이터를 먼저 지우고 비밀 삭제 실패를 무시하면 무엇이 영구히 남나.
4. "이동 실패 → 그래도 원본 삭제", "판별하며 즉시 삭제" — 이 두 코드 경로가 왜 보존 대상을 잃게 만드나.
5. 경계: 다단계 생성이 중간에 실패해 폴더만 남았다. "이미 존재하면 409"라는 멱등 가드는 이 잔해를 어떻게 오인하나. 보상 삭제는 무엇을 지워야 하고 무엇을 지우면 안 되나.
6. 외부 부작용(메일 발송)이 실패할 수 있는 흐름에서, 되돌릴 수 없는 내부 상태 변경(기존 인증 코드 무효화·요청 한도 소비)을 먼저 하면 사용자는 무엇을 겪나. 외부 자원 생성 전에 그 자원을 가리키는 참조를 영속화하면?
7. 연결: 두 참여자 사이 소유권 이관에서 "보내는 쪽 해제"와 "받는 쪽 확정" 사이에 무엇이 있어야 하나(ack·재진입 방지·전제 재검증). 역순 보상 롤백을 하려면 각 단계가 "내가 만든 것"인지 어떻게 알아야 하나 — 사전 스냅샷은 왜 부족한가.
