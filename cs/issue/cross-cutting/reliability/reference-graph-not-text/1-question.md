## 질문
1. (왜) 구버전 기능 `legacy`를 제거하면서 이름에 `legacy_`가 붙은 함수를 전부 지우려 했다. 왜 "이름이 legacy 같다"는 삭제 근거가 될 수 없는가? 이름과 소유·의존 관계는 무엇이 다른가.
2. (방법) "컴파일러 주도 제거"란 무엇인가 — 의존선(모듈·패키지 의존)을 먼저 끊고 컴파일 오류가 짚는 지점만 지우는 방식이, 라인 단위 일괄 삭제보다 안전한 이유는?
3. (경계) 컴파일러가 참조 그래프를 다 보는가? 문자열 치환·패키지 이동 뒤 컴파일은 통과했는데 런타임에만 터지는 참조의 종류를 셋 이상 대 보라(이름 문자열 주입·설정 속 FQCN·SQL 매퍼 등).
4. (예측) `sed`로 `import a.b.Foo`를 `import a.b.sub.Foo`로 일괄 치환했다. 같은 패키지에 있어서 import 없이 `Foo`를 쓰던 클래스는 어떻게 되는가? 이 참조는 왜 문자열 검색에 안 잡혔는가?
5. (경계) 프레임워크가 컴포넌트 이름을 클래스명에서 파생할 때, 클래스 개명은 언제 "계약 변경"이 되는가? 반대로 타입으로만 주입받는 곳은 왜 안전하며, 구현이 2개가 되면 무엇이 깨지는가?
6. (방법) 대량 이름 변경 전에 "문자열 치환이 동작 불변인가"를 먼저 판정하려면 참조를 어떤 범주로 나눠 전수 조사하는가? 치환 뒤에는 무엇으로 3중 검증하는가?
7. (연결) 테스트 코드만 참조하는 대상(mock 대상 인터페이스 등)을 지웠더니 테스트가 컴파일 실패했다. 이것이 "참조 그래프에 테스트도 포함된다"는 것과 어떻게 이어지며, 삭제 계획의 "검증된 사실"은 무엇으로 확인해야 했나?
