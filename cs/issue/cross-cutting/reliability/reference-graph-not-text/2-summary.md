# cs/issue/reliability/reference-graph-not-text — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[삭제·이동 결정이 겪는 일]

  "이름이 legacy 같다" ──▶ 일괄 삭제 ──▶ 공유 코드까지 삭제 ──▶ 빌드 파괴 / 런타임 500
          ▲ 실패 지점 1: 이름 ≠ 소유·의존

  sed 문자열 치환 ──▶ 표기된 참조만 바뀜
          ├─ 같은 패키지 암묵 참조(import 없음)   → cannot find symbol
          ├─ 이름 문자열(@Qualifier·bean 이름·XML) → 기동 시 주입 실패
          ├─ 설정·리소스 속 FQCN · SQL 매퍼        → 컴파일 통과, 런타임 실패
          └─ 테스트 전용 참조(mock 대상)          → 테스트 컴파일 실패
          ▲ 실패 지점 2: 컴파일러 그래프 밖의 참조

[교정]
  1) 의존선(모듈·패키지 의존)을 먼저 끊는다
  2) 컴파일러가 짚는 참조만 제거한다 (컴파일러 = 그래프의 1차 판정자)
  3) 컴파일러가 못 보는 표면은 grep으로 범주별 전수 분류
       package/import · 문자열 리터럴 · 리소스(yml/xml) · 직렬화 타입 · 테스트
  4) 치환 후 3중 검증: 잔여 grep 0 + clean compile + 테스트(+ mock 없는 컨텍스트 부팅)
```

## 핵심 문장

- 심볼 이름은 소유·의존 관계를 보장하지 않는다 — 삭제 범위는 실제 참조 그래프로 정한다.
- 의존을 먼저 끊고 컴파일러가 짚는 지점만 지우면, "누가 아직 쓰나"를 사람 추측이 아니라 도구가 판정한다.
- 컴파일러의 그래프도 전부가 아니다: 이름 문자열 주입·설정 속 FQCN·SQL·직렬화 타입·같은 패키지 암묵 참조는 따로 전수 분류한다.
- 컴포넌트 이름이 클래스명에서 파생되면, 이름으로 주입받는 곳이 있는 한 개명은 계약 변경이다.
- 문자열 치환 뒤엔 잔여 grep 0 · clean compile · 테스트의 3중 검증으로 "표기된 참조"와 "실제 참조"의 차이를 닫는다.
