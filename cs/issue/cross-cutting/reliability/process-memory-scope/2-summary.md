# cs/issue/cross-cutting/reliability/process-memory-scope — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
프로세스 메모리 상태의 수명 = 프로세스 수명, 범위 = 그 프로세스 하나

[시간 경계: 재시작]
  발급 ── 토큰 T 를 메모리 registry 에 등록 ── 링크 발송
  재배포/재기동 ── registry = {} ──
  사용자 클릭 ── isActive(T) = false ── 401   ("권한/경로 문제" 로 오진하기 쉬움)
  진행 중 명령 ── pending[id] = future ── 재기동 ── 응답 받을 곳 없음 → timeout

[공간 경계: 인스턴스·워커]
  인스턴스 A: rateLimit{u:3}   인스턴스 B: rateLimit{u:0}   → 한도 우회
  인스턴스 A: lock=held        인스턴스 B: lock=free        → "동시 1작업" 깨짐
  인스턴스 A 가 발급한 토큰 → 인스턴스 B 에서 401
  워커 ×4 가 대용량 사전을 각자 로드 → 메모리 ×4

[교정]
  수명·공유가 필요한 상태 → 영속·공유 저장소 (DB 해시 저장·만료 정리 / 공유 캐시)
  읽기 전용 대용량 데이터   → 파일 저장소 + OS page cache (워커당 connection 만)
  재배포 확인               → "connected" 가 아니라 세대 ID(session_id + pid) 변화
  당장 못 옮기는 것         → "단일 인스턴스·단일 워커 전제" 를 문서에 명시 + 교체 계획
```

## 핵심 문장

- 프로세스 메모리는 **재시작(시간)**과 **인스턴스·워커(공간)** 경계를 넘지 못한다 — 그 가정이 깨지는 순간 상태의 의미가 바뀐다.
- "없으면 false"인 인메모리 검사는 재시작 후 **전 토큰 폐기**와 같다 — 증상은 401이지만 원인은 상태 소실이다.
- 수명·공유 범위가 필요한 상태는 **영속·공유 저장소**로 옮긴다. 비밀은 원문 대신 해시로 저장한다.
- 읽기 전용 대용량 데이터는 프로세스 힙 대신 **파일 + OS page cache**로 워커 간 물리 메모리를 공유한다.
- 당장 옮기지 않는다면 **"단일 인스턴스 전제"를 명문화**해 스케일아웃 전에 발견되게 한다.
