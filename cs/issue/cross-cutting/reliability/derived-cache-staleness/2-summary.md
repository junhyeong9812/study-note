# cs/issue/reliability/derived-cache-staleness — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
 정본(원본 파일·DB·쿠키·이벤트)  ──(주기 poll / 비동기 flush / 마운트 1회 / import 1회)──▶  사본(캐시·스냅샷·로그·Context·싱글톤)
                                               ↑ 항상 한 주기 이상 늦다

[실패 1] 사본이 늦다
   요약 = 스냅샷(150ms 뒤처짐)          → 마지막 턴 누락        → 정본을 새로 읽음
   승인 판정 = 비동기 flush 로그         → 이번 턴 승인 못 봄     → 이벤트 페이로드(사이드카)
   Context = 쿠키 1회 읽기              → 로그인 후에도 비로그인 → 변경 시 명시 갱신

[실패 2] 실패가 사본에 굳는다
   read 실패 → cache[path] = []        → 일시 장애가 영구 빈 목록
   첫 연결 실패 → singleton = None      → 서버 복구돼도 재시작 전까지 장애
   → 실패는 캐시하지 않거나 TTL·무효화·재시도, 연결은 lifespan이 소유

[실패 3] "갱신 호출이 에러 없이 끝남" ≠ "신선함"
   throttle 창 → refresh() 갱신 없이 nil → 만료 키 계속 사용
   → 반환 직전 now - fetchedAt < ttl 재확인, 아니면 Stale 에러
```

## 핵심 문장

- 파생 사본은 **정의상 원본보다 늦다** — 완결성·최신성이 필요한 판정은 정본을 읽는다.
- **실패를 성공과 같은 캐시에** 무효화 없이 넣으면 일시 장애가 영구 오답이 된다.
- 갱신이 "에러 없이 돌았다"는 신선함의 증거가 아니다 — **데이터의 나이**를 직접 확인한다.
- import 부작용으로 만든 연결은 재시도·deadline·종료를 제어할 수 없다 → **lifespan**.
- 외부 저장소의 사본 상태는 **바꾼 쪽이 명시적으로 갱신**한다.
- 같은 사건의 두 경로 중 **동기 페이로드**가 "지금"의 진실 소스다.
