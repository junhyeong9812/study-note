# cs/issue/cross-cutting/reliability/fail-closed-guard — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
요청 ──▶ [가드: 판정] ──▶ 허용 / 거부
             │
             └─ 판정 불가 (조회 실패·설정 누락·모르는 값·null) 가 어디로 흐르나?

fail-open  (장애 = 우회)                     fail-closed (장애 = 거부)
─────────────────────────                    ─────────────────────────
조회 실패 → 기본값 "" → 없음 → 진행          조회 실패 → 오류 전파 → 중단
/proc 못 읽음 → 목록에서 제거 → free          못 읽음 → opaque 로 남김 → 차단
검증기 크래시 → match                          크래시 → failed, 미확인 = None(tri-state)
모드 조회 실패 → dev(자동)                     → operational(승인 필요) + FailClosed 플래그
default 분기 → 가장 흔한 대상                  → 알려진 것만 분기, 그 외 요란한 거절
builder None → if q: skip → filter 만 = 전체    → None 은 예외
if key 설정됨 → 검사 / 아니면 통과             → 키 미설정도 401 + 기동 거부
if jti != null && !active → 401                → jti 는 항상 발급, null = 거부
enum 밖 상태값 → 통과                          → case 열거 + *) 차단

[설계 원칙]
  허용은 양성 증명(allowlist)으로만 — 열거+실패시 안전측은 경로가 늘 때마다 샌다
  폴백은 "특정 오류"에만 — 거부된 요청을 다른 방법으로 재시도하지 않는다
  "모름"의 종류를 나눈다 — 대상 여부 모름 = 통과+경고 / 허가 여부 모름 = 차단
  과차단은 판정 범위를 좁혀 푼다 — 가드를 끄는 것이 아니라
  필수 설정·인자는 기본값 없이 fail-fast · 검증은 보정 대신 거부
```

## 핵심 문장

- 가드에서 판정 불가를 기본값으로 삼키면 **장애가 곧 우회**다 — 공격자·버그는 가장 쉬운 실패 모드(빈 값·조회 실패)를 탄다.
- fail-open/closed는 **오답의 불가역성**이 정한다: 되돌릴 수 없는 파괴를 막는 가드는 닫히고, 되돌릴 수 있는 부가 작업은 열린다(best-effort).
- 허용은 **양성 증명으로만** 준다. "위험 목록 + 판별 실패 시 안전 쪽"은 판별 경로가 늘 때마다 새 누수를 만든다.
- 미확인은 0·false·일치가 아니라 **별도 상태(unknown)**다. 기록은 부수효과 전에 먼저 남기고, 최종 상태는 모든 검사 뒤에 정한다.
- 폴백은 **"대상이 없음"류 특정 오류에만** 건다. "요청 자체가 거부됨"·"만료됨"을 다른 경로로 재시도하면 의도와 다른 일이 일어난다.
- 필수 설정·인자에 기본값을 두거나 잘못된 입력을 보정하면 **누락과 오류가 조용한 오작동**으로 바뀐다 — 시작 시점에 시끄럽게 실패시킨다.
