# cs/issue/reliability/sibling-path-invariant-drift — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
불변식 I  (예: "저장된 배열은 정렬돼 있다", "부분 매치는 불일치 시 되감는다", "생성 키는 INSERT 에서 제외")
   │
   ├─ 형제 1 ── I 지킴 ✓
   ├─ 형제 2 ── I 지킴 ✓
   ├─ ...
   └─ 형제 k ── I 누락 ✗   ← 결함
          │
          ▼
   소비자는 I 를 가정 (이진 탐색 · 매치 길이만큼 제거 · placeholder 수 = 값 수)
          │
          ▼
   드러나는 조건이 좁다 → 오래 잠복
     - 기본 설정은 우연히 I 를 만족 (배포 값이 이미 정렬)
     - 폴백이 가림 (잘 알려진 값은 다른 경로가 처리)
     - 테스트가 빈 입력·대표 입력만 씀
     - 결과가 예외가 아니라 조용한 오답·유실

형제의 종류
   setter·접근자 / 분기(if-elif, switch case) / 서브클래스 오버라이드
   모듈 N벌 복사본 / 포팅 원본 ↔ 재구현 / 직렬화 ↔ equals·hashCode

탐지:  한 곳에서 결함을 찾으면 → 형제 전수 대조표 (같은 불변식을 지켜야 하는 모든 경로)
교정:  즉시 = 누락 형제에 합류 (관례 1줄)
       근본 = 불변식을 한 지점으로 (공통 지점으로 끌어올림 · 공통 베이스 · 저장 시 정규화)
       테스트 = 누락 형제를 직접 겨냥 (값 순서·자릿수 혼합·버퍼 경계 쪼개기·필드별 변이)
```

## 핵심 문장

- 같은 불변식을 여러 경로가 각자 구현하면, 결함은 "하나만 빠진" 비대칭으로 나타난다.
- 비대칭 결함은 기본 설정·폴백·대표 테스트에 가려 오래 잠복하고, 예외 대신 조용한 오답으로 드러난다.
- 한 곳에서 결함을 찾으면 형제 전수를 대조한다 — 같은 불변식을 지켜야 하는 경로를 모두 나열하고 하나씩 확인.
- 즉시 수정은 누락 형제를 관례에 합류시키고, 근본 수정은 불변식을 한 지점으로 모은다.
- 포팅은 원본의 모든 분기를 줄 단위로 대조한다 — 빈 값은 유효한 값이라 검사에 안 걸린다.
