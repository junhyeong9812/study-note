# cs/issue/cross-cutting/reliability/idempotent-retry-design — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
재시도가 "자동 복구 루프"가 되는 조건
  ① 연산이 멱등이다           f(f(x)) = f(x)   — 두 번 해도 한 번과 같다
  ② 진행 표지는 전량 성공 후에만 전진한다

[깨지는 자리]
  이벤트마다 append + 재독(replay)       → 같은 사실이 여러 번 기록, 카운트 부풀림
  exactly-once 원장 + 타임아웃 + 재시도  → claim/release/축출 경쟁 → 고칠수록 새 버그 (churn)
  최초 명령을 캡처해 재시도에 재사용     → "새로 생성" 을 두 번 → 상태 위반
  커밋 ─X─ 발행                          → 이벤트 소실 (dual write)
  outbox 재발송                          → 소비자 멱등 키 없으면 이중 처리
  핸들러 안 부분 커밋 ─ 실패 ─ 재전달    → 이미 반영된 부분을 또 씀
  워터마크를 실패와 무관하게 전진         → 실패분이 재시도 대상에서 영원히 빠짐

[교정]
  덮어쓰기 스냅샷 · (key,id) 병합                       ← 저장을 멱등하게
  at-least-once + 무해한 중복 수용                      ← 연산이 "채우기"류일 때
  재시도는 현재 영속 상태에서 명령 재도출               ← 비멱등 명령
  같은 커밋에 outbox INSERT + 소비자 유일 키            ← 전달은 at-least-once, 효과는 1회
  멱등 키(내용 digest) ≠ 재시도 축(attempt)             ← 두 의도를 다른 필드로
  핸들러 = 단일 트랜잭션, 멱등 가드 없는 쪽 먼저        ← 부분 커밋 제거
  if failed == 0: watermark.advance()                   ← 성공 후 전진
  기준점 소실 → 시끄럽게 전체 처리로 강등               ← 영구 스톨 탈출
  겹치는 증분 윈도우 (쓰기가 멱등일 때)                 ← 하루 실패를 다음 날이 흡수
```

## 핵심 문장

- 재시도는 연산이 **멱등**일 때만 복구다. 멱등이 아니면 재시도는 중복 부작용 생성기다.
- 전달 보장은 **at-least-once + 소비자 멱등**이 표준이다. exactly-once는 취소 불가 부작용 위에서 경쟁 창을 계속 만든다 — 중복이 무해하면 요구를 낮춘다.
- 재시도 경로는 "처음 명령"을 재생하지 말고 **현재 영속 상태**에서 다시 도출한다.
- "중복 무시"와 "의도적 재실행"은 **다른 축**(내용 digest vs 시도 번호)으로 표현한다.
- 진행 표지는 **전량 성공 후에만** 전진한다. 기준점이 사라질 수 있으면 **전체 처리로 강등**하는 출구를 둔다.
