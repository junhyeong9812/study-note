## 질문
1. (왜) 재시도 루프가 "모든 실패를 일시 실패로" 취급하면 어떤 실패가 무한 반복되는가? 인증 거부·키 없음·실행 파일 없음(exit 127)은 왜 몇 번을 다시 해도 결과가 같은가.
2. (예측) 저장된 비밀번호가 없을 때 `password.unwrap_or_default()`로 빈 문자열을 채우고, 인증 실패를 일시 오류로 분류해 15초마다 재접속한다. 상대 서버 쪽에서는 무슨 일이 일어나는가? 이것이 왜 "방어가 아군을 차단"하는 사고가 되는가.
3. (경계) 영구 실패 판정을 stderr 텍스트의 부분 문자열(`"not found"`)로 하면 무엇이 잘못될 수 있는가? 구조화된 신호(종료 코드)가 없을 때 판정을 어느 쪽으로 기울여야 하는가.
4. (왜) poison message란 무엇인가 — 결정적으로 처리 불가능한 입력을 "재연결·재동기"로 해결하려 하면 왜 라이브락이 되는가? 문제 바이트가 **재동기 스냅샷 자체**에 들어 있으면 어떻게 자기강화되는가.
5. (방법) 재시도 상한 카운터를 "언제" 0으로 리셋해야 하는가? 재접속 성공마다 리셋하면 왜 루프가 멈추지 않는가 — "진행을 증명하는 유일한 사건"으로 리셋한다는 말의 의미는.
6. (경계) 메시지 소비자(스트림·큐)에서 "예외 → 미확인(ACK 안 함) → 재처리" 계약이 있을 때, 핸들러가 모든 예외를 삼키면 무엇이 되고, 반대로 모든 예외를 재던지면 무엇이 되는가? 두 극단 사이의 분류 기준은.
7. (연결) 고정 지연 폴링(`fixedDelay`, 직전 실행 완료 기준)으로 실패 항목을 재처리하면 왜 "실패 후 N분 뒤 재시도"라는 백오프 의미가 보장되지 않는가? 무엇을 기준 시각으로 저장해야 하는가.
