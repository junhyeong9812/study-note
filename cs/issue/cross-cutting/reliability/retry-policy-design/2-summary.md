# cs/issue/reliability/retry-policy-design — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
실패 발생
   │
   ▼
[분류] ─────────────────────────────────────────────────────────────
   │ 일시(transient): 네트워크 끊김 · 인프라 미기동 · 타임아웃
   │     → 재시도 (백오프, 상한, 진행 시 리셋)
   │ 영구(permanent): 인증 거부 · 비밀 없음 · 실행 파일 없음(exit 127)
   │     → 중단 + 조치 안내 (재시도 = 아군 차단: 원격 fail2ban)
   │ poison(결정적 처리 불가 입력): 과대 줄 · 디코드 실패 · 데이터 결함
   │     → 건너뛰고 표시 / 폐기 / 격리 (재시도 = 라이브락)
   └──────────────────────────────────────────────────────────────────

실패 지점:
  ① 전부 일시로 분류          → 영구 실패 무한 재시도
  ② "없음"을 기본값으로 번역   → 없는 비밀이 "빈 비밀번호 인증 시도"가 됨
  ③ 텍스트 부분일치로 분류     → 오탐 (구조화 신호 없으면 단정하지 않음)
  ④ 재접속마다 카운터 리셋     → 스냅샷 속 poison 이 매 재접속 같은 자리에서 실패
  ⑤ 예외를 전부 삼킴(ACK)      → 일시 장애가 영구 유실
     예외를 전부 재던짐        → poison 무한 재처리
  ⑥ fixedDelay 폴링           → "마지막 실행 후 N" ≠ "실패 후 N", 재시도 몰림

교정:
  permanent_reason(): 구조화 신호(종료 코드)로만 영구 판정, 없으면 일시
  secret(): 없으면 에러 (조용한 기본값 금지)
  카운터 리셋 = 진행을 증명하는 사건(스냅샷 수신·진행)에서만
  핸들러: 인프라 오류 raise(재처리) · 데이터 결함 폐기(ACK) · 전달 N회 초과 폐기
  실패 항목에 nextRetryAt = 실패 시각 + 지연
```

## 핵심 문장

- 재시도 정책의 첫 단계는 실패 분류다 — 영구 실패를 재시도하면 무한 루프, 상대 서버에는 공격처럼 보인다.
- "없음"을 기본값(빈 문자열)으로 채우지 않는다 — 없는 비밀은 에러다.
- 구조화된 신호가 없으면 영구라고 단정하지 않는다(텍스트 부분일치 금지).
- poison 메시지는 재시도로 안 풀린다 — 상한 + 건너뛰고 표시(격리) 경로가 필요하다.
- 재시도 카운터는 "진행을 증명하는 사건"에서만 리셋한다.
- 소비자 핸들러는 인프라 오류(재처리)와 데이터 결함(폐기)을 가른다.
- 백오프는 실패 시점 기준으로 저장한다(nextRetryAt), 폴링 주기 기준이 아니다.
