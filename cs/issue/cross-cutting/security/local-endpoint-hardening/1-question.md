## 질문
1. (왜) 서버를 `127.0.0.1`에만 바인딩하면 "외부"는 막힌다. 그런데 같은 호스트의 **다른 프로세스**와 **브라우저에 열린 임의 웹페이지**는 왜 여전히 접근할 수 있는가?
2. (예측) 로컬 수신기의 인증 토큰과 포트를 자식 프로세스의 **명령행 인자**로 넘겼다. 같은 호스트의 다른 사용자가 이 토큰을 얻는 방법은? 대신 어떤 채널로 넘겨야 하나?
3. (경계) 브라우저의 same-origin 정책과 CORS는 JSON `fetch` POST는 막아 주는데, 왜 **WebSocket** 연결은 막아 주지 않는가? 서버는 무엇을 직접 검사해야 하나? `Origin` 헤더가 **없는** 연결은 어떤 전제(단일 사용자 호스트)에서 통과시켜도 되는가?
4. (예측) 블로킹 방식의 수제 HTTP 서버에 읽기 타임아웃과 동시 연결 상한이 없다. 느린 클라이언트 하나가 헤더를 한 바이트씩 보내면? 로컬 유닉스 소켓이 원격 요청의 끝점이 되면 같은 문제가 어떻게 커지는가?
5. (왜) `Host` 헤더 검사를 `starts_with("localhost")`로 하면 무엇이 통과하는가? `Content-Length`가 두 개이거나 숫자가 아니면 무엇이 문제인가? "무음 축소 없이 400"의 의미는?
6. (연결) 소켓 파일 경로를 "없으면 만들고 bind"하는 코드는 왜 TOCTOU인가? 소켓 파일과 런타임 디렉토리 권한은 어떻게 두어야 하나?
