# cs/issue/security/local-endpoint-hardening — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[루프백 바인드가 막는 것 / 못 막는 것]

  다른 호스트 ──X──▶ 127.0.0.1:port        막힘 (바인드 주소)
  같은 호스트 다른 프로세스 ──▶ 127.0.0.1:port   통과  ← 인증 필요
  브라우저의 임의 웹페이지 ──ws://127.0.0.1──▶  통과  ← Origin 검사 필요 (CORS 비적용)
  느린 클라이언트 1개 ──(바이트씩)──▶ 워커 점유   ← 자원 상한 필요
  이상한 요청 (Host·길이·경로 조작) ──▶ 파서 구멍  ← 엄격 입력 검증

[교정 체크리스트]
  인증     세션별 토큰 · argv 금지 → 0600 파일/env 로 전달 · 토큰↔세션 id 대조(위조 403)
  오리진   WebSocket accept 전 Origin 허용목록 (없으면 비브라우저 = 통과 — 단일 사용자 호스트 전제)
  입력     Content-Length 정확히 1개·숫자 · Host 정확 일치 · 이벤트 화이트리스트
           · id 형식 검증 · 인스턴스별 디렉토리 · 이상 요청은 400 (조용히 잘라 받지 않음)
  자원     읽기 타임아웃 · 동시 연결 상한 · 읽기 횟수 상한 (slowloris)
  소켓     파일 0600 · 런타임 디렉토리 0700 사전 생성 · bind 는 파일 락으로 원자화
  실패     수신기 실패 = 기능 저하일 뿐, 본 작업(세션)은 막지 않음
```

## 핵심 문장

- 루프백·유닉스 소켓 바인드는 **다른 호스트**만 막는다 — 같은 호스트의 프로세스·브라우저 오리진은 막지 못한다.
- 비밀은 **argv가 아니라** 권한 제한 파일·env로 넘긴다 — 명령행은 `/proc/<pid>/cmdline`·`ps`로 다른 사용자에게 보인다.
- WebSocket 핸드셰이크에는 CORS가 적용되지 않는다 → 서버가 **Origin을 직접** 검사한다.
- 로컬 끝점도 **읽기 타임아웃·연결 상한**이 없으면 느린 클라이언트 하나에 멈춘다.
- 입력 검증은 "대충 맞으면 통과"가 아니라 **정확 일치**, 어긋나면 400.
- 소켓 경로 점유는 **파일 락**으로 원자화하고, 권한은 0600/0700.
