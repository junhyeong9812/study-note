## 질문
1. (왜) 셸을 거치지 않고 argv 배열로 프로세스를 실행하면 셸 인젝션은 막힌다. 그런데도 사용자 값 `--force`가 대상 프로그램의 **옵션**으로 해석될 수 있는 이유는? 두 겹의 인터프리터를 구분하라.
2. (경계) 옵션 종결자 `--`, 등호형 `--opt=value`, 값 앞 `-` 거부 — 각각은 어떤 경우를 막는가? 가변 개수 값을 받는 옵션 뒤에 위치 인자를 두면 무슨 일이 생기는가?
3. (예측) 사용자가 고른 파일 경로가 `:(glob)*`처럼 생겼다. 이 값을 git 경로 인자로 그대로 넘기면? 경로를 "리터럴"로 해석시키는 전역 수단은?
4. (왜) CI 스크립트에서 `${{ 입력값 }}`을 `run:` 본문에 직접 보간한 뒤 셸에서 형식 검사를 하면 왜 이미 늦었는가? 보간을 어디로 옮겨야 하는가?
5. (예측) 시드 데이터 정리에 `LIKE 'SEED_%'`를 쓰면 어떤 행까지 지워질 수 있는가? FK CASCADE가 걸려 있으면 피해는 어떻게 커지는가? 그리고 "어느 컬럼을 검색할지"를 요청 문자열로 정하면 값 바인딩으로 막을 수 없는 이유는?
6. (연결) `str.format` 템플릿에 CSS를 넣으면, 마이그레이션 SQL 본문에 `${...}`가 든 HTML을 넣으면 각각 무엇이 깨지는가? 규칙 엔진 조건을 `eval()`하는 것, 검증 전의 입력을 한 줄 로그에 쓰는 것은 같은 문장으로 어떻게 설명되는가?
7. (경계) 데이터 채널을 분리하는 방법(옵션 종결자·바인딩·리터럴 모드·화이트리스트)과 이스케이프는 무엇이 다른가? 이스케이프를 쓸 때 반드시 지켜야 할 순서는?
