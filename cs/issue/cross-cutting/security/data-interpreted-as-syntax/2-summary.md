# cs/issue/security/data-interpreted-as-syntax — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[외부 값이 거치는 인터프리터들]

  사용자 값 ─▶ (셸?) ─▶ argv 파서 ─▶ 프로그램 내부 미니 언어 ─▶ 결과
                │           │              │
                │           │              ├ git: pathspec(:(glob)…) · revision(a..b, ^{…})
                │           │              ├ SQL: 구문 · LIKE(_ %) · 식별자(컬럼명)
                │           │              ├ 템플릿: str.format {} · 마이그레이션 ${}
                │           │              ├ eval: 파이썬 식 전체
                │           │              └ 줄 단위 로그: 개행 = 새 레코드
                │           └ 선두 "-" = 옵션 / 가변 옵션은 뒤 토큰을 흡수
                └ CI 표현식 보간 ${{ }} = 셸 파싱 "이전"의 문자열 치환

[교정 = 데이터 채널을 문법 채널에서 분리]
  argv      : 셸 없이 배열 실행 + "--" 종결자 + 선두 "-" 거부 + --opt=value
  미니 언어 : --literal-pathspecs · rev-parse --verify <r>^{commit} (단일 커밋만)
  CI        : 보간은 env: 로 → 셸에선 "$VAR" + 형식 검증
  SQL       : 값 = 바인딩, LIKE 메타 = ESCAPE, 컬럼 = enum 화이트리스트
  템플릿    : 문법 문자 있는 조각은 분리 조립 / placeholder 치환 끄기(운영·테스트 동일)
  eval      : 연산자 테이블 매핑
  로그      : 입구에서 형식 검증 후 기록 (검증 실패 = 로그·접수 전에 거절)
```

## 핵심 문장

- 데이터가 하위 인터프리터의 **문법**으로 해석되면 인젝션이다 — 셸만 인터프리터가 아니다.
- 셸 없는 argv 실행은 셸 인젝션만 막는다. **대상 프로그램의 argv 파서**는 선두 `-`를 여전히 옵션으로 읽는다.
- git 경로·리비전, SQL LIKE, 템플릿 `{}`·`${}`, 줄 단위 로그는 모두 자기만의 **미니 언어**를 갖는다.
- 보간이 파싱 **이전**에 일어나면, 그 뒤의 형식 검사는 이미 늦다.
- 교정의 핵심은 이스케이프보다 **채널 분리**(종결자·바인딩·리터럴 모드·화이트리스트)다.
- 이스케이프를 쓴다면 **이스케이프 문자 자신을 먼저** 이스케이프한다.
