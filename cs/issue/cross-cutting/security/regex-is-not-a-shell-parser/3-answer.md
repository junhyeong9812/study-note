## 정답
<!-- 질문 1:1 대응 -->

1. **가드와 셸이 서로 다른 언어를 읽는다.** 가드는 "이 글자열이 패턴과 맞나"를 보고, 셸은 인용·heredoc·리다이렉트·변수·cwd를 해석해 "무엇을 실행하나"를 정한다.\
   둘이 같은 결론을 내는 입력은 일부뿐이다. 셸은 실행하지만 패턴은 못 알아보는 표면형이 있으면 **false-allow**, 패턴은 맞지만 셸에게는 데이터일 뿐인 문자열이 있으면 **false-block**이다.\
   두 방향은 같은 원인(의미 모델 불일치)에서 나오므로, 한쪽을 좁히면 다른 쪽이 넓어지는 식으로 동시에 존재한다.
   > **parser differential** — 같은 입력을 두 파서가 다르게 해석하는 차이. 검사하는 쪽과 실행하는 쪽이 다르면 보안 경계가 새는 전형적 원인.

2. **옵션·경로·래퍼로 같은 동작을 쓴다.** `git -C repo push`(전역 옵션 선행), `git -c k=v push`, `/usr/bin/git push`(절대 경로), `command git push`(래퍼) 등이 모두 `git[[:space:]]+push`를 통과한다. 같은 구조로 CLI 발행 가드도 `-R owner/repo` 같은 전역 옵션이 서브커맨드 앞에 오면 미탐했다.\
   또 명령이 **실행 문맥을 바꾸면**(`cd other-repo &&`, `-C path`) 판정 대상도 바뀌어야 하는데, 가드가 자기 cwd에서 스테이징을 조회하면 엉뚱한 저장소를 검사한다.\
   교정은 명령 접두(경로·`command` 래퍼 허용)와 전역 옵션 구간을 패턴에 넣고, `-C` 대상 저장소 기준으로 판정하는 것이었다.

3. **변형의 수가 유한하지 않다.** 부정문("푸시하지 마"), 질문형("푸시해도 돼?" — 게다가 전처리의 `tr`이 `?`를 구분자로 먹음), "A 말고 B", 과광범위 동사("올려"·"배포") — 하나를 고치면 다른 표현이 샌다.\
   실제로 리뷰 루프는 18건 → 11건 → 3건 + 재점검 2건으로 줄기만 할 뿐 0에 닿지 않았고, 매 수정이 새 엣지를 노출했다. 적대적 리뷰 루프는 완결 불가능한 대상에 대해 **비수렴**한다.\
   근본 해법은 자연어 판정 함수를 전부 제거(−224줄)하고, 위험 명령을 감지하면 **네이티브 확인 UI**가 사용자에게 명령 전문을 보여주고 묻게 하는 것이었다 — 승인은 문장 해석이 아니라 구조화된 신호가 됐다.
   > **churn** — 같은 설계를 계속 고쳐도 새 결함이 나오는 상태. 같은 곳 2회면 토대가 틀렸다는 신호로 보고 설계를 되돌린다.

4. **셸 문법을 흉내 낸 휴리스틱이 토큰 경계를 틀린다.** `<<-`(탭 종결자 heredoc), `<<<`(here-string), `$((1<<8))`(산술 시프트)가 모두 heredoc 시작으로 오인되어, 그 뒤의 실제 명령이 "heredoc 본문"으로 지워졌다.\
   인용 안의 `<<tag`도 유령 heredoc을 만들었다.\
   보안상 위험한 이유: 지워진 부분에 **실제 push가 숨을 수 있다** — 오탐을 줄이려던 전처리가 우회 경로가 된다.\
   교정은 `<<-`·`<<<`·산술 문맥 제외 등으로 실사용 경로를 닫는 데서 멈춘 것이다 — 정규식으로 셸 문법을 재현하는 보정은 완결되지 않으므로 더 쌓지 않았다.

5. **regex의 토큰 경계 ≠ 셸의 word-split.** 예외 패턴은 공백만 토큰 경계로 봤지만, 셸은 탭도 단어 구분자이고 `>`는 리다이렉트 연산자다.\
   `echo X > 보호파일<TAB>.events` 류에서 regex는 ".events로 끝나는 토큰"을 보고 예외를 적용했지만, 셸은 보호 파일에 직접 썼다 — 게이트 자가 승인(P0).\
   경로 쪽도 같다 — 문자열 조상 탐색이 `a/../b`의 `..`를 풀지 못해 엉뚱한 상태를 채택했다.\
   교정은 예외 **전면 철회**(원래 오탐은 애초에 그 가드의 대상이 아니었음 — 잘못 식별된 문제), 탭·리다이렉트 위장 회귀 테스트 추가, 경로는 **정규화된 절대경로 도메인**에서만 비교하고 비정규 경로는 안전 기본값으로 폴백하는 것이다. 원칙: **보호 훅에 문자열 예외를 추가하지 않는다.**

6. **언급이 실행으로 판정된다.** 패턴은 인자·메시지·heredoc 본문·grep 인자 같은 데이터 영역과 실행 영역을 구분하지 못한다.\
   그래서 테스트 입력 속 "git push", 패턴 예시가 든 커밋 메시지, 발행 전 자기검증용 `grep -i '<금지어>'` 인자, 제품명이 언급된 커밋이 차단됐다.\
   복합 명령에서는 한 세그먼트 때문에 전체가 막혀, 같은 명령에 들어 있던 heredoc(파일 생성)이 실행되지 않고 다음 명령이 "No such file"로 연쇄 실패했다.\
   대응은 명령 분리·스크립트 파일 경유·테스트 문자열 분할(`"git pu""sh"`), 그리고 패턴을 bare 단어 대신 구조 문자열(`Co-Authored-By.*` 등)로 좁히고 수용한 오탐을 테스트 케이스로 잠그는 것이다.

7. **폴백에는 구조 정보가 없어 부분 문자열 매칭밖에 남지 않는다.** 폴백은 정제 기계가 실패했거나 전부 주석·인용이라 구조를 못 읽은 경우다.\
   여기에 정밀 판정(trailer 정책)을 넣자 순수 주석도 차단됐고, `commit|push` 게이트로 좁히자 `commitment`·`Pushkin` 같은 단어가 걸렸다 — 4라운드 churn.\
   "파싱 불가 경로에서 정밀 탐지"는 자기모순이다. 폴백은 **가장 중요한 안전망 하나**(push 감지 시 보수적 확인)만 맡고, 정밀 정책은 정제 가능한 정상 경로에만 둔다.

## 문제 구조 (추상화 코드)

### 변형 A — 자연어 승인을 regex로 판정
① 문제 코드
```sh
# 부정문·질문형·"A 말고 B"도 매칭
if echo "$USER_MSG" | grep -qiE '(push|푸시|배포|올려)'; then exit 0; fi
# pending 명령과 현재 명령의 exact-match 로 승인 결속 → 재시도마다 명령이 조금 바뀌어 연속 차단
[ "$PENDING_CMD" = "$CMD" ] && approved "$PROMPT" && exit 0
```
② 고친 코드
```sh
if is_push "$CMD"; then
  jq -n --arg r "push 확인" '{hookSpecificOutput:{permissionDecision:"ask", permissionDecisionReason:$r}}'
  exit 0                                   # 네이티브 확인 UI 가 명령 전문을 보여주고 사용자에게 묻는다
fi
```
무엇이 깨졌나: 무한한 변형을 유한한 패턴으로 판정하려 했다 — false-block(연속 차단·livelock)과 false-allow(부정문 통과)가 동시에.

### 변형 B — 같은 동작의 다른 표면형·실행 문맥
① 문제 코드
```sh
grep -qE 'git[[:space:]]+push' <<<"$CMD" && guard     # git -C r push · /usr/bin/git push · command git push 미탐
git diff --cached --name-only                         # 훅 cwd 기준 — "cd other && git commit" 이면 다른 저장소
```
② 고친 코드
```sh
PRE='(^|[^[:alnum:]_./-])(command[[:space:]]+)?([^[:space:]]*/)?git'
OPTS='([[:space:]]+-[^[:space:]]+([[:space:]]+[^-[:space:]][^[:space:]]*)?)*'   # 전역 옵션 구간
grep -qE "${PRE}${OPTS}[[:space:]]+push" <<<"$CMD" && guard
git -C "$(target_repo "$CMD")" diff --cached --name-only    # 명령이 가리키는 저장소 기준
```
무엇이 깨졌나: 표면형 하나를 고정했고, 명령이 바꾸는 실행 문맥을 무시했다.\
같은 구조: 발행 CLI 가드도 전역 옵션(`-R owner/repo`)이 서브커맨드·동사 앞에 올 수 있어 같은 옵션 구간을 양쪽에 재사용.

### 변형 C — awk로 셸 파서를 흉내
① 문제 코드
```sh
# "<<TAG" 부터 "TAG" 까지를 본문으로 보고 제거
strip_heredoc() { awk '/<</{skip=1; tag=...} skip&&$0==tag{skip=0; next} !skip' ; }
# <<- · <<< · $((1<<8)) 도 heredoc 으로 오인 → 뒤의 실제 명령까지 삭제
```
② 고친 코드
```sh
# <<- / <<< 제외, "<<" 직전이 "(" 나 숫자면 제외, 순수 숫자 태그 제외,
# 탐지는 인용을 치환한 사본에서, 태그는 원본에서 추출
# 휴리스틱 보정은 여기서 멈춤 — 셸 문법 재현은 정규식으로 완결되지 않는다
```
무엇이 깨졌나: 문맥 의존 문법(heredoc·인용·산술 확장)을 정규식 휴리스틱으로 재현하려 했다.

### 변형 D — 보호 훅의 문자열 예외가 우회를 신설
① 문제 코드
```sh
# 보호 경로 쓰기 차단, 단 모든 대상 토큰이 .events 로 끝나면 예외
toks=$(grep -oE '\.state/[^ |;&]*' <<<"$CMD")
all_events "$toks" && exit 0
# 셸:  echo MODE=auto > .state/SID<TAB>.events   → regex 는 ".events" 토큰, 셸은 .state/SID 에 씀
```
② 고친 코드
```sh
# 예외 삭제 (원래 오탐은 훅 서브프로세스의 쓰기라 이 가드 대상이 아니었음)
# 경로 비교는 정규화된 절대경로에서만; "..", ".", "//" 가 섞인 비정규 경로 → 안전 기본값
# 회귀 테스트: 탭·리다이렉트 위장 케이스
```
무엇이 깨졌나: regex가 본 토큰과 셸이 실제로 쓰는 대상이 어긋났다.\
같은 구조: 상태 쓰기 검사 regex `[^|]*`가 `;`·`&`를 넘어가 순수 읽기 명령을 오탐 → `[^|;&]*`로 교정.

### 변형 E — 데이터 속 패턴 "언급"을 실행으로 판정 (false-block)
① 문제 코드
```sh
if grep -qiE 'co-authored|<제품명>' <<<"$FULL_COMMAND"; then block; fi
# 발행 명령 + 자기검증 grep 인자 + heredoc 본문이 한 문자열 → 전부 매칭 대상
```
② 고친 코드
```sh
grep -qiE 'Co-Authored-By:.*|Generated with .*<제품명>' <<<"$MESSAGE_ONLY" && block   # 구조 문자열로 좁힘
# 운용: 검증 명령과 발행 명령 분리 · 패턴이 든 테스트는 스크립트 파일 경유 · 수용 오탐은 케이스로 잠금
```
무엇이 깨졌나: 인자·메시지·본문 같은 데이터 영역을 실행 영역과 구분하지 않았다.\
같은 구조: 경로에 보호 디렉토리 이름이 들어 있다는 이유로 그 잔재를 정리하는 `git rm --cached`·히스토리 정리 명령까지 차단 → 명령 분리로 우회.

### 변형 F — 파싱 불가 폴백에서 정밀 판정
① 문제 코드
```sh
fallback() {                       # 구조를 못 읽은 경우
  grep -q 'commit\|push' <<<"$RAW" && check_trailer "$RAW"   # commitment · Pushkin · 순수 주석도 차단
}
```
② 고친 코드
```sh
fallback() { is_raw_push "$RAW" && ask_user; }   # 안전망 하나만 — 정밀 정책은 정상 경로에만
```
무엇이 깨졌나: 구조 정보가 없는 경로에 구조가 필요한 판정을 요구했다.
