## 질문
1. (왜) 셸 명령을 문자열 패턴(regex)으로 검사하는 가드는 왜 **false-allow(우회)** 와 **false-block(오탐)** 을 동시에 만드는가? 가드가 보는 "의미 모델"과 셸이 실행하는 의미 모델의 차이로 설명하라.
2. (예측) 명령(세그먼트) 시작에 고정된 `git[[:space:]]+push`를 감지하는 가드가 있다. 같은 동작을 하면서 이 패턴을 통과하는 표면형을 세 가지 이상 들어라. 또 `cd other-repo && git commit`에서 가드가 스테이징을 **자기 cwd**에서 조회하면 무엇이 틀리는가?
3. (왜) 사용자의 자연어 승인("푸시해줘")을 regex로 판정하면, 부정문·질문형·"A 말고 B" 같은 변형을 고칠 때마다 새 엣지가 나온다. 이 반복이 **수렴하지 않는** 이유는? 근본 해법은 무엇이었나?
4. (예측) heredoc 본문 속 명령 텍스트 오탐을 막으려 awk로 heredoc을 벗겨내는 로직을 넣었다. `<<-`, `<<<`, `$((1<<8))`은 각각 어떻게 잘못 처리되는가? 이런 오인이 보안상 왜 위험한가?
5. (경계) 보호 대상 경로에 대해 "토큰이 `.events`로 끝나면 예외"라는 문자열 예외를 추가했다. 탭 문자·`>`·`..`를 섞으면 regex가 본 토큰과 셸이 실제로 쓰는 대상이 어떻게 달라지는가? 교정은 무엇이었나?
6. (예측) 명령 문자열 **전체**에 패턴을 걸면, 커밋 메시지·테스트 입력·검증용 grep 인자 안의 패턴 "언급"은 어떻게 판정되는가? 복합 명령에서 무관한 부분 때문에 차단되면 어떤 연쇄 실패가 생기는가?
7. (연결) 입력을 구조적으로 해석하지 못해 들어간 **폴백 경로**에서 정밀 판정을 요구하면 왜 오탐이 끝없이 생기는가? 폴백은 무엇만 책임져야 하나?
