# cs/issue/security/verify-what-you-use — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
입력 X ──┬──▶ [검증기]  해석 V(X)  → 통과
         │
         └──▶ [사용자]  해석 U(X') → 실행
                      ▲
     어긋나는 지점:   │
       ① 해석 차이   V ≠ U   (관대한 파서·정규화·이스케이프 전/후·경로 인코딩)
       ② 객체 차이   X ≠ X'  (재열람 TOCTOU·두 번 읽기·문자열 vs 실제 전송 hop)
       ③ 시점 차이   검사 시점엔 없던 상태를 실행이 만든다 (복합 명령)
       ④ 표시 차이   승인 화면이 보여준 대상 ≠ 실제 실행 대상

  결과: 검증은 "통과"했는데 실제로 쓰인 것은 검증되지 않은 무언가

[교정 — 하나로 결박]
  해석: 사용자와 같은 정규형·같은 파서로 검증 (엄격 파싱, 원문 정확 비교, 디코드 후 검사)
  객체: 검증한 바이트를 그대로 넘긴다 (한 번 읽기·해시 명명 불변 스냅샷·O_EXCL)
  전송: 문자열이 아니라 실제 hop마다 검사 (리다이렉트 훅 — 기존 정책과 합성)
  표시: 정확히 계산 못 하면 "참고용"으로 정직하게 축소
```

## 핵심 문장

- 검증의 효력은 **검증한 대상 = 사용하는 대상**일 때만 성립한다 — 같은 바이트, 같은 해석, 같은 시점.
- 관대한 정규화·파서는 "거부해야 할 변형"을 허용값으로 접는다 → 보안 값은 **원문 정확 비교**, 구조는 **엄격 파서**.
- 두 계층이 같은 입력을 다르게 해석하면(필터 vs 라우터, 서명자 vs 검증자) **한 정규형을 단일 출처**로 공유한다.
- 재검증은 창을 좁힐 뿐 없애지 못한다 → **검증한 바이트를 불변 스냅샷으로 굳혀** 실행기에 넘긴다.
- 문자열 검사는 실제 동작(리다이렉트 hop, 셸의 개행 strip, 정규식 `$`)을 보증하지 못한다 — 실제로 쓰일 형태에서 검사한다.
