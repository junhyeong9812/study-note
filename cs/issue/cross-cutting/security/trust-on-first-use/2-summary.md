# cs/issue/security/trust-on-first-use — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
서버 공개키 수신
   │
   ▼
check(known_hosts, host, port, key)
   ├─ 일치            → 진행
   ├─ 불일치(키 변경) → 거부   (MITM 가능성 — 묻지도 않는다)
   ├─ 판독 불가·오류  → 거부   (모름으로 접지 않는다)
   └─ 미지            → 지문(SHA256) 제시 → 사용자 결정 대기
                           ├─ 수신자(화면) 없음  → 거부
                           ├─ 취소·무응답        → 거부 (타임아웃과 분리된 상태)
                           ├─ 거절               → 거부
                           └─ 수락 → learn(기록)
                                      ├─ 성공 → 진행
                                      └─ 실패 → 이번 연결도 거부   ← 핵심

[실패 지점 — 고치기 전]
   불일치를 미지처럼 묻거나 조용히 신뢰      → MITM 통과
   수락 후 learn 실패를 무시하고 진행        → "신뢰했다"는 믿음 ≠ 저장 상태
                                               다음 접속에 또 미지로 질문
```

## 핵심 문장

- 호스트 신뢰는 **일치 / 불일치 / 미지** 세 상태다. 불일치는 공격 신호라 거부, 미지만 사용자 결정 대상이다.
- 신뢰 저장소의 **판독 실패**와 **기록 실패**는 성공이 아니다 — 판정·영속이 실패하면 신뢰로 진행하지 않는다(fail-closed).
- 사용자에게 묻는 경로의 모든 비정상(수신자 없음·취소·타임아웃)은 "거부"로 수렴해야 한다.
- 앱이 신뢰 결정을 기록하는 곳은 **앱 전용 저장소** — 전역 설정을 오염시키지 않는다.
