## 질문
1. TOFU(Trust On First Use)는 무엇을 믿고 무엇을 믿지 않는 모델인가. SSH 호스트키 검증의 결과를 "맞다/틀리다" 두 값이 아니라 **세 상태**로 나눠야 하는 이유는?
2. "알려진 키와 불일치"와 "아직 모르는 호스트"를 같은 분기로 처리하면 각각 어느 쪽으로 틀리는가(조용한 신뢰 vs 과잉 거부). 불일치가 의미하는 위협은 무엇인가.
3. 예측: 사용자가 새 호스트 지문을 "수락"했는데 known_hosts 기록(learn)이 실패했다. 이번 연결을 그대로 진행하면 사용자의 믿음과 저장 상태는 어떻게 어긋나며, 다음 접속에서 무슨 일이 생기는가.
4. known_hosts 파일을 **읽는 데** 실패(판독 불가·형식 오류)하면 어느 분기로 보내야 하는가. "읽을 수 없으니 모르는 호스트로 취급"이 왜 위험한가.
5. 결정을 사용자에게 묻는 동안 연결 타임아웃·사용자 취소·질문 받을 화면 없음이 겹칠 수 있다. 각각을 어떻게 처리해야 fail-closed가 유지되는가.
6. 경계: 앱이 사용자의 전역 `~/.ssh/known_hosts`가 아니라 **앱 전용** 신뢰 저장소를 쓰는 이유는 무엇인가.
