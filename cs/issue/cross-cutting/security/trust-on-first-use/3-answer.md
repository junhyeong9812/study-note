## 정답
<!-- 질문 1:1 대응 -->

1. **TOFU의 세 상태.** TOFU는 "처음 본 키는 사용자가 확인하고 기록하며, 이후에는 기록된 키와 같은지만 본다"는 모델이다 — 첫 접속의 진위는 사용자 판단에 맡기고, **그 이후의 변화**를 기계가 잡는다.\
그래서 결과는 세 가지다: 기록된 키와 **일치**(진행), 기록된 키와 **불일치**(키가 바뀜 — 공격 가능), 기록이 **없음**(최초 신뢰 결정 필요).\
두 값(맞다/틀리다)으로 접으면 "불일치"와 "없음" 중 하나를 다른 쪽 처리에 태우게 된다.
   > **TOFU** — Trust On First Use. 첫 접속 때 확인한 신원을 기록하고 이후 접속에서 그 기록과 비교하는 신뢰 모델.

2. **불일치 ≠ 미지.** 불일치를 미지처럼 처리하면 "새 호스트네요, 믿을까요?"를 묻거나 조용히 받아들여 **중간자(MITM)를 통과**시킨다(조용한 신뢰).\
반대로 미지를 불일치처럼 처리하면 처음 보는 정상 호스트를 영원히 거부한다(과잉 거부).\
불일치는 "같은 이름의 호스트가 다른 키를 내밀었다" — 서버 재설치일 수도 있지만 공격자가 가운데서 대신 응답하는 것일 수도 있으므로, 기계가 사용자 편의로 넘기지 않고 **거부**한다.
   > **MITM** — man-in-the-middle. 클라이언트와 서버 사이에서 양쪽인 척 중계하며 통신을 가로채는 공격.

3. **수락 후 learn 실패.** 사용자는 "이 호스트를 신뢰했다"고 믿지만 저장소엔 기록이 없다.\
이번 연결을 진행하면 **믿음과 저장 상태가 어긋난 채** 통신이 이뤄지고, 다음 접속에선 다시 "미지"가 되어 또 묻는다.\
(일반론 — 원 기록은 "저장 실패 시 신뢰하지 않음, 다음 접속 재프롬프트가 정직"까지) 사용자는 반복되는 질문에 습관적으로 수락하게 되고, 그 사이 키가 바뀌어도 "불일치"가 아니라 "미지"로 보이므로 **MITM 탐지 능력 자체가 사라진다**.\
그래서 learn이 성공했을 때만 진행하고, 실패하면 이번 연결도 거부한다 — 거부가 저장 실패 자체를 고치지는 않지만, 기록 없는 신뢰로 통신하는 일을 막고 저장 실패를 사용자에게 드러내 원인(권한·디스크 등)을 고치게 한다.

4. **판독 실패는 거부 쪽.** known_hosts를 읽지 못했다면 "기록이 없다"를 증명한 것이 아니라 **판정을 못 한 것**이다.\
이를 미지로 접으면 사용자에게 수락을 받아 진행하게 되고, 실제로는 기록된 키와 불일치였을 수도 있는 호스트를 신뢰하게 된다.\
판정 도구의 오류는 "안전 쪽 결론"(거부)으로 보낸다 — 이것이 fail-closed다.
   > **fail-closed** — 판정·설정이 불확실하면 열지 않고 닫는(거부하는) 기본값.

5. **묻는 경로의 비정상.** 질문을 받을 화면(수신자)이 없으면 결정이 올 수 없으므로 **즉시 거부**한다.\
사용자 결정 대기와 네트워크 연결 타임아웃은 서로 다른 상태로 분리한다 — 사람이 지문을 확인하는 시간이 네트워크 타임아웃에 걸려 엉뚱한 오류가 나지 않게 하고, 무응답·취소는 모두 거부로 끝낸다.\
취소로 대기 채널이 먼저 닫혀 화면 쪽 결정 송신이 실패하는 경우는 **정상 종료로 무시**한다(이미 거부로 끝난 연결이므로).

6. **앱 전용 저장소.** 전역 `~/.ssh/known_hosts`는 사용자의 다른 도구들이 함께 쓰는 신뢰 기록이다.\
앱이 거기에 쓰면 사용자가 앱 밖에서 한 적 없는 신뢰 결정이 전역에 퍼지고, 여러 프로세스의 동시 쓰기 경쟁도 생긴다.\
앱 전용 파일(쓰기는 잠금으로 직렬화)로 신뢰 결정의 범위를 **그 결정을 내린 앱**으로 한정한다 — 최소 권한의 저장소 버전이다.

## 문제 구조 (추상화 코드)

### 변형 A — 세 상태를 두 분기로 접음 / 영속 실패를 무시
① 문제 코드
```rust
async fn check_server_key(&self, key: &PublicKey) -> Result<bool> {
    match check_known_hosts(&self.host, self.port, key, &self.store) {
        Ok(true) => Ok(true),
        _ => {                                         // 불일치·판독 오류·미지를 한 분기로
            if self.ask_user(fingerprint(key)).await? == Accept {
                let _ = learn_known_host(&self.host, self.port, key, &self.store); // 실패 무시
                Ok(true)                               // 기록 없이 신뢰로 진행
            } else { Ok(false) }
        }
    }
}
```
② 고친 코드
```rust
async fn check_server_key(&self, key: &PublicKey) -> Result<bool> {
    match check_known_hosts(&self.host, self.port, key, &self.app_store) {  // 앱 전용 저장소
        Ok(true)  => Ok(true),                    // 일치
        Err(_)    => Ok(false),                   // 키 변경(불일치)·판독 불가 → 거부
        Ok(false) => {                            // 미지 → 사용자 결정
            let Some(prompt) = self.prompt_tx.as_ref() else { return Ok(false) };  // 수신자 없음 → 거부
            match prompt.ask(fingerprint_sha256(key)).await {   // 결정 대기 ≠ 연결 타임아웃
                Decision::Accept => match learn_known_host(&self.host, self.port, key, &self.app_store) {
                    Ok(()) => Ok(true),
                    Err(_) => Ok(false),          // 영속 실패 → 이번 연결도 거부
                },
                Decision::Reject | Decision::Cancelled => Ok(false),
            }
        }
    }
}
// 화면 쪽: 취소로 대기 채널이 먼저 닫혀 결정 송신이 실패하면 정상 종료로 무시
```
무엇이 깨졌나(계획·설계 리뷰에서 막은 실패 형태 — 실사고 아님): 공격 신호(불일치)와 판정 실패를 사용자 질문으로 흘렸고, 신뢰 결정의 기록 실패를 성공처럼 다뤄 저장 상태와 실제 신뢰가 어긋났다.
