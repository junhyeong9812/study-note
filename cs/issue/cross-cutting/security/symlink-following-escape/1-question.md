## 질문
1. `stat`과 `lstat`(Rust `metadata` vs `symlink_metadata`, Python `exists()` vs `is_symlink()`)의 차이는 무엇인가. 재귀 삭제 대상이 "디렉터리를 가리키는 심볼릭 링크"일 때 링크를 따라가는 판정을 쓰면 무엇이 지워지는가.
2. 예측: 허용 루트 안에 대상이 없는(dangling) 심볼릭 링크 `new.txt -> /outside/new.txt`가 있다. "`exists()`가 False면 새로 만든다 → `write_text()`" 코드에 `new.txt`를 요청하면 무슨 일이 생기는가. 왜 "중복 검사"와 "경로 한정" 두 불변식이 한 번에 뚫리는가.
3. `open(path, "x")`(O_CREAT|O_EXCL)는 "`is_symlink()` 검사 후 생성"보다 무엇이 더 강한가. 검사-사용 사이 경쟁(TOCTOU) 관점에서 설명하라.
4. 경계: 경로의 **마지막 성분만** 심볼릭 링크인지 검사하면 어떤 경로가 빠져나가는가. 포함 검사를 "전체 경로를 resolve한 실경로 기준"으로 해야 하는 이유는?
5. 새 파일 생성 분기에는 링크 비추종을 적용했는데 "이미 있으면 읽어서 갱신" 분기는 평범한 `read_text/write_text`를 쓴다. 검증된 폴더 안에서 무엇이 새는가 — "모든 분기 같은 링크 정책(패리티)"은 무슨 뜻인가.
6. `shutil.move`(또는 비슷한 "이동" 유틸)가 같은 파일시스템과 다른 파일시스템에서 다르게 동작하는 이유는 무엇이고, 그 차이가 왜 보안 성질을 조용히 바꾸는가.
7. 연결: 누구나 쓸 수 있는 `/tmp` 아래 **고정 이름** 작업 디렉터리를 `create_dir_all`로 만들면 왜 위험한가. 원자적 `create_dir` + 링크 재검사 + 소유자 확인 + 0700 조합은 각각 무엇을 막는가.
