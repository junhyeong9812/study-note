# cs/issue/security/complete-mediation — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[보호하려는 효과]  "파일이 바뀐다"  /  "원격 상태가 바뀐다"

[같은 효과로 가는 경로들]
  파일 변경 ─┬─ Edit/Write 도구 ──────▶ [게이트] 차단 가능       ← 강제 지점
             ├─ 셸: sed -i · tee · >  ──▶ (게이트 없음)          ← 보호 밖
             ├─ 셸: 인터프리터 스크립트 ─▶ (문자열로 판정 불가)
             └─ 셸: heredoc 으로 파일 생성 ─▶ 생성 이벤트 훅 미발화

  원격 변경 ─┬─ git push ───────────────▶ [승인] 확인 요청
             ├─ MR 생성 --fill ─────────▶ 내부적으로 push   ← 승인 밖
             └─ 이슈→브랜치 생성 명령 ───▶ 원격 브랜치 생성  ← 승인 밖

[교정]
  경계 = "효과를 내는 모든 경로" 로 재정의
  결정론적으로 판정 가능한 표면(구조화 도구) → 하드 차단 (실행 전 훅)
  판정 불가 표면(임의 셸)                   → 소프트 리마인더 + 절차 규칙
  편의 플래그 금지 · 명시 인자 · 원격 부작용은 별도 확인 단계로 분리
  잔여 경로는 문서에 "막지 못함"으로 기록 (위협 모델 = 실수 방지)
```

## 핵심 문장

- 강제 지점이 쓰기 경로 **일부**(특정 API·명령 이름)에만 있으면, 같은 효과의 다른 경로가 보호 밖에 남는다.
- 경계는 "명령 이름"이 아니라 "**그 효과를 내는 모든 경로**"로 정의한다.
- 임의 명령의 파일 쓰기 여부는 문자열로 결정론적으로 판정할 수 없다 → 하드 차단은 구조화 도구에만, 나머지는 리마인더·절차.
- 사후 훅은 되돌릴 수 없다 — 사후 자동 되돌리기는 정당한 변경까지 되돌린다.
- 고수준 CLI는 편의를 위해 원격 부작용을 묶어 수행한다 → 편의 플래그를 쓰지 않고 부작용을 분리한다.
- 막지 못하는 경로는 숨기지 말고 잔여 리스크로 기록한다.
