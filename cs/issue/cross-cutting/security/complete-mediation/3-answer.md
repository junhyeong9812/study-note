## 정답
<!-- 질문 1:1 대응 -->

1. **모든 접근은 매번 검사를 거쳐야 한다.** 보호 대상에 닿는 경로가 여러 개인데 검사가 그중 일부에만 붙어 있으면, 검사 없는 경로가 곧 우회로다.\
   전형적인 모양은 "검사를 **특정 API·명령 이름**에 걸었다"이다 — 같은 효과를 내는 다른 API·명령은 이름이 달라 검사를 비껴간다.
   > **complete mediation(완전 중재)** — 보호 자원에 대한 모든 접근이 예외 없이 접근 통제를 거쳐야 한다는 보안 설계 원칙.

2. **절반 이상이 보호 밖이다.** 실측에서 파일 변경의 셸 경유 건수가 편집 도구 경유보다 많았고, 극단 세션은 거의 전부가 셸 경유였다.\
   편집 도구 게이트는 "편집 도구로 쓰는 경우"만 막으므로, 셸로 쓰면 무경고로 통과한다. 모드마다 같은 방식으로 5회 이상 반복해 뚫렸다.\
   역효과도 있었다 — 편집 도구의 오차단이 오히려 셸 우회 행동을 부추겼다.

3. **명령 문자열은 실행 의미를 결정하지 않는다.** 쓰기는 `sed -i`·`tee`·리다이렉트뿐 아니라 인터프리터(`python -c`, 스크립트 파일)·변수 간접 참조로도 일어나며, 문자열만으로는 끝없이 열거할 수 없다.\
   반대로 `>` 같은 패턴을 하드 차단하면 `2>/dev/null` 같은 무해한 명령과 검증 실행까지 막는 오탐이 과다해진다.\
   그래서 **결정론적으로 판정 가능한 표면(구조화된 편집 도구)에만 하드 차단**을 걸고, 셸 쪽은 패턴 기반 **소프트 리마인더**와 절차 규칙으로 보강한다.

4. **실행 전 훅은 막을 수 있고, 실행 후 훅은 피드백만 줄 수 있다.** 사후 훅이 호출될 때 파일은 이미 바뀌었다.\
   사후 감지 + 자동 되돌리기(diff 감지 후 revert)는 정당한 변경(예: 테스트가 만든 스냅샷)까지 되돌려 선택하지 않은 방법이다.\
   또 사후 훅의 내부 오류를 "성공(exit 0)"으로 삼키면 판정 실패가 은폐되므로, 경로 정규화 실패는 양쪽 이벤트에서 모두 실패로 드러내게 고쳤다.
   > **PreToolUse / PostToolUse** — 도구 실행 직전·직후에 호출되는 훅. 차단 권한은 직전 훅에만 있다.

5. **승인 없이 push·원격 브랜치 생성이 일어난다.** MR 생성 CLI의 `--fill`류는 편의를 위해 브랜치 push를 함께 수행하고, `--title/--body`를 비우면 프롬프트·커밋으로 자동 채운다.\
   "이슈에서 브랜치 만들기" 명령은 원격에 브랜치를 만든다. 둘 다 `git push`라는 이름을 쓰지 않으므로 push 승인 경계를 통과한다.

6. **경계는 이름이 아니라 효과로 정의한다.** "파일을 바꾸는 모든 경로", "원격 상태를 바꾸는 모든 경로"가 보호 범위다.\
   원격 쪽 교정은 편의 플래그 금지·명시 인자(`--title/--body`·head/base 지정)·push는 확인 후 별도 단계·원격 브랜치 대신 로컬 브랜치 생성이다.\
   그래도 막지 못하는 경로(판정 불가 셸 쓰기)는 숨기지 않고 **잔여 리스크로 문서에 기록**한다 — 위협 모델이 "악의 차단"이 아니라 "실수 방지"임을 명시하고, 그 범위 안에서만 보장을 주장한다.

## 문제 구조 (추상화 코드)

### 변형 A — 강제 지점이 특정 도구(API)에만
① 문제 코드
```json
{ "PreToolUse": [
    { "matcher": "Edit|Write", "hooks": ["write-guard"] }        // exit 2 = 차단
] }
// 셸 도구는 매처에 없음 → sed -i / tee / > / 인터프리터 쓰기 무경고 통과
```
② 고친 코드
```json
{ "PreToolUse": [
    { "matcher": "Edit|Write", "hooks": ["write-guard"] },       // 하드 차단 (결정론적 표면)
    { "matcher": "Bash",       "hooks": ["write-guard --soft"] } // 쓰기 패턴 리마인더만
] }
// 문서: "셸 경유 쓰기는 결정론적으로 막지 못함 — 절차 규칙" (잔여 리스크 명시)
```
무엇이 깨졌나: 같은 효과(파일 변경)의 경로 중 하나에만 검사를 붙였다.\
같은 구조: 상태 리셋 훅이 "편집 도구로 파일 생성" 이벤트에만 반응 → 셸 heredoc으로 만든 문서는 리셋을 일으키지 않음 → "그 문서는 편집 도구로 만든다"를 절차 규칙으로 명시.

### 변형 B — 승인 경계를 명령 이름으로 정의
① 문제 코드
```sh
case "$CMD" in *"git push"*) ask_user ;; esac     # push 이름만 감시
mr create --fill                                  # 내부적으로 브랜치 push
issue develop 42                                  # 원격 브랜치 생성
```
② 고친 코드
```sh
git switch -c feature/42                          # 로컬에서만 브랜치 생성
# push 는 사용자 확인 후 별도 단계
mr create --title "$T" --body "$B" --head feature/42 --base main   # 편의 플래그 금지
```
무엇이 깨졌나: 원격 상태를 바꾸는 경로가 명령 이름 밖에도 있었다.
