## 질문
1. (왜) complete mediation(완전 중재) 원칙이란 무엇인가? "모든 접근이 검사를 거친다"가 깨지는 전형적인 모양은?
2. (예측) 파일 편집 도구(구조화된 Edit/Write)에만 게이트를 걸고, 임의 셸 명령 도구는 그대로 두었다. 실사용에서 파일 변경의 절반 이상이 셸 경유라면 이 게이트의 실효는?
3. (경계) 셸 명령의 "파일 쓰기 여부"를 명령 문자열로 결정론적으로 판정할 수 없는 이유는? 그래서 하드 차단과 소프트 리마인더를 어디에 나눠 걸어야 하나?
4. (왜) 실행 **전** 훅(PreToolUse)과 실행 **후** 훅(PostToolUse)의 능력 차이는? 사후 감지 + 자동 되돌리기가 선택되지 않은 이유는?
5. (예측) "push는 사용자 확인 후"라는 승인 경계를 `git push` 명령에만 걸었다. 그런데 MR 생성 CLI의 편의 플래그(`--fill` 류)나 "이슈에서 브랜치 만들기" 명령을 쓰면 무엇이 승인 밖에서 일어나는가?
6. (연결) 이 두 사례를 한 문장으로 묶어라. 승인·강제 경계를 "명령/API 이름"이 아니라 무엇으로 정의해야 하는가? 그리고 막지 못하는 잔여 경로는 어떻게 다뤄야 정직한가?
