## 질문
1. (왜) "권한 요청 → 실행"의 2단계 프로토콜에서 인가 게이트를 실행 단계에 두었더니, 앞단의 권한 요청 스텁이 늘 거부를 돌려줘 모든 도구가 막혔다. 게이트가 **어느 단계**에 있어야 하는지, 뒷단 "게이트"가 왜 도달 불가 코드가 됐는지 설명하라.
2. (예측) 읽기 전용 창이 쓰기를 못 하게 **UI만 잠갔다**. 그리고 서버는 프론트가 보내는 창 이름을 호출자 신원으로 믿는다. 이 설계에서 어떤 우회가 가능한가? 신원은 어디서 가져와야 하나?
3. (경계) 계정 id allowlist를 두었는데, 요청에 "자유 경로" 필드가 여전히 남아 있어 그 경로로 오면 검사 없이 통과했다. "필드를 제한"하는 것과 "와이어에서 필드를 제거 + 모르는 필드 거부"는 무엇이 다른가?
4. (예측) CI에서 후속 워크플로가 트리거 원본의 **브랜치 이름**만 보고 배포 신원을 결정한다. fork 저장소에서 브랜치 이름을 `main`으로 지으면 무슨 일이 생기는가? 출처를 증명하려면 무엇을 AND해야 하나?
5. (왜) 인가 검사를 멱등 키 선점 **뒤에** 두면, 또는 일부 코드 경로만 지나는 층(오케스트레이션)에 두면 각각 무엇이 깨지는가? 미들웨어 체인에서 "순서가 계약"이라는 말의 뜻은?
6. (연결) 게이트웨이가 하류 서비스에 넘기는 권한 헤더를 **요청 URL prefix**로 정하면 왜 권한 상승(confused deputy)이 되는가?
7. (경계) 인증 필터가 무효·만료 토큰에 **즉시 401을 확정**하면, 익명 허용인 공개 경로까지 막히는 이유는? "익명으로 강등하고 인가에 위임"이 인증과 인가의 책임을 어떻게 나누는가?
