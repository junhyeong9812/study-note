## 질문
1. (왜) 원격 호출에 read 타임아웃 10초를 넣었다. 서버는 요청을 접수해 처리 중인데 클라이언트는 타임아웃을 "실패"로 확정했다. 원격 호출의 결과는 왜 성공/실패 2상태가 아니라 3상태인가.
2. (예측) 1번 상황에서 원장은 FAILED(종결)로 기록되고, 나중에 서버가 SUCCESS 콜백을 보낸다. 콜백 핸들러가 "종결 상태와 상충하는 콜백은 무시"하면 최종 상태는 어떻게 되는가.
3. (경계) Java 소켓 예외 중 어떤 것은 "요청이 확실히 도달하지 않았다"를 뜻하고 어떤 것은 "모른다"를 뜻한다. `ConnectException`·`UnknownHostException`·`SocketTimeoutException`을 각각 어디에 넣어야 하는가. 연결 타임아웃은 왜 안전측(모름)으로 보내는가.
4. (경계) HTTP 클라이언트에서 "연결 수립(dial) 전 실패"와 "후 실패"를 가르는 것이 왜 미실행/UNKNOWN 경계가 되는가. 오류 문자열 파싱으로 이걸 가르면 무엇이 위험한가.
5. (예측) 원격 전환 API의 409·500·전송 실패를 호출자가 모두 "미전환"으로 보고 정리(idle 슬롯 down)를 했다. 409가 "소유권 상실"이었다면 그 슬롯은 무엇일 수 있는가.
6. (왜) 응답 body에 `state: NOT_ATTEMPTED | ROLLED_BACK | INDETERMINATE`를 실어도, 상태코드와 무관하게 이 필드를 믿으면 왜 위험한가. 응답 자체를 서명해야 하는 이유는.
7. (연결) 멱등성 키를 표준 헤더 이름(`Idempotency-Key`)으로 보내면 어떤 클라이언트 라이브러리는 자동 재전송을 한다 — 이것이 "모름" 상태에 무엇을 더하는가.
