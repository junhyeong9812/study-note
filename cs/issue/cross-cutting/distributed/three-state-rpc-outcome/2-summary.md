# cs/issue/distributed/three-state-rpc-outcome — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
client ──(dial)──▶ ──(write req)──▶ server 처리 ──(write resp)──▶ client
          │                 │                               │
          ▼                 ▼                               ▼
   dial 전 실패        dial 후 ~ 응답 전 실패            응답 수신·검증
   (DNS·connect)      (RST·timeout·단절·서명 불일치)
   = 미실행 보증       = UNKNOWN (서버가 했을 수도)       = 성공 / 명시적 거절

[실패 지점]
   timeout → FAILED(종결) 확정
        server는 실행 완료 → SUCCESS 콜백
        client: "종결 상태와 상충" → 무시  → 데이터는 있는데 원장은 영구 실패

   전환 API 409/500/전송실패 → 전부 "미전환" → 정리(down)
        409 = 소유권 상실 → 그 슬롯은 새 소유자의 라이브일 수 있음 → 라이브 절단

[교정]
   UNKNOWN(비종결) 상태 신설 → 늦은 콜백이 원장을 정정
   서버가 실패 응답에 보증 수준을 싣는다: NOT_ATTEMPTED / ROLLED_BACK / INDETERMINATE
   호출자: "정리는 미실행이 보증됐을 때만"
   응답도 서명, 정확한 상태코드에서만 state 신뢰
   자동 재전송 금지(표준 멱등 헤더 대신 전용 헤더)
```

## 핵심 문장
- 원격 호출의 결과는 **미실행 보증 · 결과 모름 · 성공** 3상태다. 타임아웃은 "모름"이다.
- "모름"을 종결 실패로 확정하고 늦은 성공 신호를 버리면 양쪽 상태가 영구히 어긋난다 — 비종결 상태로 두고 늦은 신호로 정정한다.
- 미실행 보증은 **요청 바이트가 나가기 전**(DNS·connect 실패)에만 성립한다. dial 이후의 모든 오류는 UNKNOWN.
- 파괴적 정리(롤백·down)는 미실행이 **보증**됐을 때만. 실패를 한 종류로 접으면 불명 상태에서 파괴한다.
- 상태 판정 근거가 되는 응답은 인증돼야 한다 — 위조·변조된 실패 응답은 "안전하게 정리해도 됨"으로 승격될 수 있다.
