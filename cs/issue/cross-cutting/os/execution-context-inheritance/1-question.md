## 질문
1. 자식 프로세스는 부모의 환경 변수를 기본으로 상속한다. 어떤 도구가 "나는 다른 세션 안에서 실행 중"이라는 표식 변수를 보고 동작 모드를 바꾼다면, 그 도구를 띄우는 오케스트레이터가 또 다른 세션 안에서 실행될 때 무슨 일이 생기는가. 왜 이것이 "조용한" 실패인가.
2. 같은 앱이 셸에서 실행하면 정상인데 데스크톱 아이콘(GUI 런처)이나 서비스 매니저로 실행하면 명령을 못 찾거나 터미널 출력이 깨진다. 로그인 셸과 GUI 런처·서비스 유닛·도구의 비대화 셸은 PATH·TERM을 각각 어디서 얻는가.
3. 예측: 실행 파일을 절대경로로 찾아 스폰했는데 `/usr/bin/env: 'node': No such file or directory`, 종료 코드 127이 났다. "경로 해석됨"과 "실행 가능"은 왜 다른가(shebang). 자식 PATH에 무엇을 넣어야 하는가.
4. 외부 호출자가 자식에게 줄 env·argv를 요청으로 넘길 수 있다. 데몬이 소유해야 하는 키(설정 디렉토리·세션 id 등)를 호출자가 덮어쓰지 못하게 하려면 병합 순서를 어떻게 해야 하는가. 거절한 값은 어떻게 처리해야 하는가.
5. 경계: 한 데몬이 여러 테넌트(계정)를 동시에 서비스하는데 테넌트별 홈 디렉토리를 프로세스 환경 변수로 고른다. 무엇이 깨지는가. "자식에게 주는 env"와 "내가 읽는 env"를 왜 구분해야 하는가.
6. 상태 파일을 현재 작업 디렉토리(cwd) 기준 상대경로로 찾는 훅이 있다. 셸의 `cd`가 영속되는 환경에서 무엇이 일어나는가(거짓 차단·유령 파일·다른 저장소 오염). 앵커를 무엇으로 바꿔야 하는가. 또 "저장소 루트 기준 상대경로"로 판정하는 규칙은 어떤 저장소 배치에서 뒤집히는가.
7. 연결: 오케스트레이션 플랫폼이 서비스 이름으로 `<NAME>_PORT=tcp://…` 같은 변수를 파드에 자동 주입했더니 앱 설정이 덮였다. 또 어떤 언어의 프로세스 API는 env 목록이 비어 있으면 부모 환경을 통째로 상속한다. 두 사건을 "허용 목록으로 env를 구성하라"는 원칙과 연결해 설명하라.
