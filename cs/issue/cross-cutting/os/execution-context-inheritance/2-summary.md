# cs/issue/os/execution-context-inheritance — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
실행 방식                 env 출처                    PATH                 TERM   cwd
─────────────────────────────────────────────────────────────────────────────────────────
대화형 로그인 셸           rc 파일 + 부모               ~/.local/bin 등 포함   있음   사용자가 cd
GUI 런처(.desktop)         데스크톱 세션(최소)          최소                   없음   고정
서비스 유닛(systemd 등)    유닛 파일에 적은 것만        /usr/local/bin:/usr/bin:/bin   없음   유닛 설정
도구의 비대화 셸           부모(부분 샌드박스)          rc 미적용              ?      영속 cd 추종
컨테이너 / 오케스트레이터   이미지 + 플랫폼 자동 주입     이미지                 ?      이미지
자식 프로세스              부모 전체(기본 상속)         부모                   부모   부모

실패 지점
  ① 표식 변수 상속      부모 세션 마커 → 자식이 "중첩 모드" → 산출물(전사) 미작성
  ② PATH 차이           홈 설치 CLI 못 찾음 / shebang 인터프리터 못 찾음(127) / 다른 python 선택
  ③ TERM 부재           GUI·서비스로 띄운 앱의 PTY 자식 → escape 시퀀스 깨짐
  ④ 호출자 env/argv      데몬 소유 키를 덮어씀
  ⑤ 프로세스 전역 env    다중 테넌트 경합
  ⑥ cwd 앵커            영속 cd → 상태를 하위 디렉토리에서 찾음 → 거짓 차단·유령 파일
  ⑦ 루트 전제           저장소 루트 없음 / 하위 디렉토리가 곧 루트 → 분류 뒤집힘
  ⑧ 플랫폼 주입·암묵 상속  <NAME>_PORT 충돌 / 빈 env = 부모 전체 상속 / .env 자동 로드

교정
  스폰 시 env를 "결정"한다: 스크럽(마커 제거) + 명시(TERM, PATH, 절대경로 바이너리) + 보호 키(데몬 값 우선, 거절 통지)
  설치 시점(로그인 셸 유효)에 바이너리 경로를 고정
  테넌트 값은 env가 아니라 인자로
  상태 앵커 = 조상 탐색 → 워크트리 루트, cwd 아님
  env = 허용 집합(PATH + 주입값), 암묵 상속·자동 로드 차단
  재현: env -i PATH=/usr/bin:/bin 으로 GUI/서비스 환경 흉내
```

## 핵심 문장

- 실행 문맥(env·PATH·cwd·TERM)은 **실행 방식**이 정한다. 개발 셸이 우연히 제공하던 값이 프로덕션 런처·서비스에는 없다.
- 자식은 부모 env를 **통째로** 상속한다 → 필요한 문맥은 스폰 시점에 **명시적으로 결정·정화**한다.
- "경로 해석됨" ≠ "실행 가능": shebang 인터프리터도 **자식의 PATH**로 찾는다.
- 호출자 입력 env는 **데몬 소유 키에 대해 데몬 값이 이긴다** — 거절은 조용히 하지 말고 통지.
- 환경 변수는 **프로세스 전역**이다 — 요청마다 다른 값은 인자로.
- 상태 위치를 **cwd에 앵커링하지 않는다** — cwd는 세션 도중 바뀐다.
- env는 **금지 목록이 아니라 허용 목록**으로 구성한다.
