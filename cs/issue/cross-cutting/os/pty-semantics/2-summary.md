# cs/issue/os/pty-semantics — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
주입 프로그램 ──write(bytes)──▶ PTY master ──[라인 디시플린: 현재 모드]──▶ slave ──▶ TUI 입력 핸들러

실패 지점
  ① 준비 전 쓰기     TUI가 핸들러 설치 전  → 바이트 버려짐 (고정 지연이 임계 바로 아래)
  ② LF 제출         raw 모드 Enter = CR(0x0D) → "\n"은 제출 아님
  ③ 같은 청크 CR     ESC[200~ body ESC[201~ \r  (한 read) → CR까지 본문으로 소비
  ④ 모드 미설정 paste  ?2004h 안 켠 화면(선택 프롬프트) → 붙여넣기 = 키 입력 → 의도치 않은 승인
  ⑤ canonical 모드   한 줄 > MAX_CANON(4096) → 커널이 받고 버림, write는 Ok
  ⑥ 자식 종료        master read → EIO (EOF 아님) → 종료 감지 누락
  ⑦ 제어 터미널 없음  setsid만 → 터미널 신호(SIGWINCH) 안 감

교정
  ① 지연을 실측 임계 위로 (근본 해법 = 준비 신호 감지, 후속 과제)
  ②③ 본문 = paste, 제출 = 별도 write CR (지연 두고), 꼬리 개행 제거, 제출 경로 단일화
  ④ blocked 상태 게이트를 클릭 시점 + 소비 직전 둘 다
  ⑤ 막을 수 없음 → 계약을 "큐에 넣음"으로 낮추고 위험 크기면 경고
  ⑥ EIO → EOF로 정규화 → 종료 통지
  ⑦ 자식에서 setsid() + ioctl(TIOCSCTTY)
```

## 핵심 문장

- PTY에 쓴 바이트의 의미는 **받는 쪽의 현재 모드**가 정한다. 쓰는 쪽은 그 모드를 보통 볼 수 없다.
- raw 모드에서 Enter는 **CR**이다. 붙여넣기(본문)와 제출(CR)은 **분리된 이벤트**로 보낸다.
- bracketed paste 격리는 수신 프로그램이 **모드를 켰을 때만** 성립한다. 아니면 주입 = 키 입력.
- `write` 성공 ≠ 상대 도달. canonical 모드는 한 줄 상한을 넘는 바이트를 **조용히 버린다**.
- Linux PTY master는 자식 종료 시 **EIO**를 돌려준다 → EOF로 정규화.
- 터미널 신호는 **제어 터미널을 가진 세션의 포그라운드 그룹**에만 간다 → setsid + TIOCSCTTY.
