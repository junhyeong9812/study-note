# cs/issue/os/path-canonical-identity — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
같은 대상, 다른 표기
   /repo/a   /repo/./a   /repo/a/   /repo/b/../a   /link-to-repo/a   \repo\a   /Repo/A(비구분 FS)

진입점 ─┬─ 기능 X: raw 경로로 키 생성       ─┐
        └─ 기능 Y: canonical 경로로 키 생성 ─┴─▶ 같은 대상이 다른 키 → 저장 폴더 분기·잠금 우회

실패 지점
  ① 문자열 동등 비교      a === b           → 표기 차이로 false-miss / false-positive
  ② 접두 문자열 포함 판정  t.startsWith(r)   → 끝 슬래시·중첩 루트·구분자 차이로 오판
  ③ 진입점별 정규화 불일치 → 키·잠금 분기
  ④ 퇴화 입력             "."·"/"·"..." → 빈 세그먼트 → 무동작인데 성공 보고
                          dirname("/a") = "" → 빈 문자열 = 프로세스 cwd
  ⑤ 구분자로 둘러싼 패턴   "/src/" 검색 → 선두 세그먼트 "src/x" 놓침

교정
  모든 진입점 ─▶ canonical(path) 단일 함수 ─▶ 비교·키·잠금
  포함 판정 = 조상 관계(세그먼트 단위), 여러 후보면 가장 긴 루트
  퇴화 입력은 정규화 후 비면 거부, dirname 결과가 비면 "/"
  세그먼트 목록으로 다룬다
  (정규화 불가 환경: 할 수 있는 만큼 + 잔여를 기록)
```

## 핵심 문장

- 경로는 **여러 표기가 한 대상**을 가리킨다. 비교·키·잠금 전에 **같은 정규형**을 거쳐야 한다.
- 정규화 함수는 **하나**여야 한다 — 진입점마다 다르면 같은 대상이 다른 키가 된다.
- 포함 관계는 문자열 접두가 아니라 **세그먼트 단위 조상 관계**.
- 빈 경로 문자열은 흔히 **현재 작업 디렉토리**로 해석된다. 멱등 API는 "무의미 입력"과 "이미 있음"을 구분하지 못한다.
- 대소문자 비구분 FS처럼 비교 규칙 자체가 환경에 따라 다르면, **입력 표기를 일관되게 강제**하는 방안이 맞을 수 있다.
