## 정답
<!-- 질문 1:1 대응 -->

1. **UDS 경로 길이.** 유닉스 도메인 소켓 주소 구조체의 경로 필드(`sun_path`)는 **고정 길이 버퍼**이고 리눅스에서 108바이트다(종료 NUL 포함이라 이식성 있게 쓸 수 있는 경로는 107바이트 이하, macOS·BSD는 104바이트).\
그보다 긴 경로의 소켓은 만들 수 없다 — 언어 런타임이 `bind` 호출 전에 거부하거나 `bind`가 거부한다.\
테스트 스크래치 디렉토리나 긴 사용자 런타임 디렉토리 아래에 소켓을 두면 이 한계를 넘어 데몬이 기동 중 죽었다.\
교정은 짧은 경로(`/tmp/<name>-<pid>` 류)를 쓰고, 배포 문서에 "소켓 경로 길이 제한"을 명시하는 것이다.\
단 `/tmp` 바로 아래는 모든 사용자가 쓰는 공유 디렉토리라 예측 가능한 이름은 선점될 수 있고, 2번의 "부모 디렉토리 0700" 전제와도 충돌한다 — 짧은 **사설 하위 디렉토리**(0700으로 새로 만든 임시 디렉토리) 안에 두는 편이 안전하다.
   > **sun_path** — UDS 주소 구조체 안의 경로 문자 배열. 크기가 플랫폼 헤더에 고정돼 있다.

2. **공유 디렉토리 chmod.** `/tmp`는 root 소유의 공유 디렉토리다.\
권한 변경(chmod)은 소유자(또는 특권)만 할 수 있으므로 일반 사용자 프로세스가 `/tmp`를 0700으로 바꾸려 하면 **EPERM**이다.\
코드가 "소켓 부모 디렉토리는 무조건 0700으로 조인다"를 전제로 했기 때문에, 사용자가 소켓을 `/tmp` 바로 아래에 두는 순간 기동이 실패하고 원인도 드러나지 않았다.

3. **닫히는 방향 실패의 등재.** 이 실패는 권한을 느슨하게 만드는 것이 아니라 **기동을 막는** 쪽이다 — 보안상 노출이 생기지 않는다.\
그래서 즉시 수정 대신 "알려진 창"으로 문서에 등재하는 판단이 가능했다.\
반대로 실패가 **열리는 방향**(권한을 못 조였는데 그냥 기동)이었다면 노출이 조용히 생기므로 등재로 끝낼 수 없고 수정하거나 기동을 거부하게 만들어야 한다.\
등재할 때도 "무엇을 하면 막히는지"를 운영 문서에 남겨야 원인 추적이 가능하다.

4. **순회 중 수정은 미규정.** 디렉토리 스트림을 읽는 도중 같은 디렉토리에 엔트리를 추가·삭제하면, 그 엔트리가 순회 결과에 나타날지는 **POSIX가 규정하지 않는다(unspecified)**.\
구현(파일시스템·libc)마다 보일 수도, 안 보일 수도 있다.\
그래서 자가 치유(사이드카 파일 생성)를 순회 루프 안에서 하던 코드는 결과가 플랫폼에 따라 달라질 수 있는 상태였다.

5. **모았다가 나중에 쓰기.** 루프 안에서는 "써야 할 것" 목록만 모으고, 루프가 끝난 뒤 일괄로 쓴다.\
순회가 끝난 뒤의 쓰기는 이미 닫힌 스트림과 무관하므로 **정의된 동작만** 남는다.\
어떤 FS에서도 같은 결과가 나오고, 순회 결과가 쓰기에 의해 오염될 여지가 없다.

6. **전제 확인 목록.** 예시:\
① 고정 크기 버퍼가 있는가(경로·이름·메시지 길이 상한).\
② 이 연산에 **소유권·권한 조건**이 있는가(chmod = 소유자 또는 특권, chown = 대개 특권, 신호 보내기 = 같은 사용자 또는 특권).\
③ 순회·반복 중 대상 컬렉션을 수정해도 되는가(미정의 여부).\
④ 실패 방향이 닫힘인가 열림인가.\
세 사건 모두 API 문서에 이미 적힌 전제였고, 설계 단계에서 이 목록으로 걸러낼 수 있었다.

## 문제 구조 (추상화 코드)

### 변형 A — 고정 길이 주소 버퍼
① 문제 코드
```rust
let path = runtime_dir.join("app").join("session").join("control.sock"); // 긴 경로
UnixListener::bind(&path)?;             // sun_path 108바이트 초과 → 거부
```
② 고친 코드
```rust
let dir = make_private_dir("/tmp", "app-")?;   // 짧은 경로 + 0700으로 새로 만든 사설 디렉토리(공유 /tmp 직하 이름 선점 회피)
let path = dir.join("s.sock");
UnixListener::bind(&path)?;
// + 배포 문서: 소켓 경로는 108바이트 미만(NUL 포함, 다른 OS는 더 짧음)
```
무엇이 깨졌나: 경로 길이가 커널 구조체의 고정 크기를 넘었다.

### 변형 B — 소유하지 않은 디렉토리 권한 변경
① 문제 코드
```rust
fn bind(path: &Path) -> io::Result<UnixListener> {
    let parent = path.parent().unwrap();
    set_permissions(parent, 0o700)?;    // parent = /tmp → EPERM → 기동 실패
    UnixListener::bind(path)
}
```
② 현재 처리
```rust
// 미수정 — 실패 방향이 "막힘"(안전)이라 알려진 창으로 운영 문서에 등재
// "소켓을 공유 디렉토리 바로 아래에 두면 기동 실패"
```
무엇이 깨졌나: "부모 디렉토리는 내가 소유한다"는 전제를 확인하지 않았다.

### 변형 C — 순회 중 같은 디렉토리 쓰기
① 문제 코드
```rust
for e in read_dir(dir)? {
    let meta = /* ... */;
    if meta.is_missing() { write(dir.join(sidecar_name(&e)), heal(&e))?; } // 순회 중 쓰기
}
```
② 고친 코드
```rust
let mut heals = Vec::new();
for e in read_dir(dir)? {
    if /* ... */ { heals.push((sidecar_name(&e), heal(&e))); }
}
for (name, data) in heals { write(dir.join(name), data)?; }    // 순회 뒤 일괄
```
무엇이 깨졌나: 새 엔트리가 순회에 보일지가 미정의인 상태에서 쓰기를 섞었다.
