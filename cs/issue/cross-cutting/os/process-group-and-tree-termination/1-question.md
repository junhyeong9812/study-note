## 질문
1. 셸을 거쳐 띄운 작업에 타임아웃이 걸려 셸 프로세스만 kill했다. 손자 프로세스는 어떻게 되는가(reparent). 그룹 단위로 죽이려면 스폰할 때 무엇을 해야 하고, 죽일 때 무엇을 호출하는가.
2. "취소" 버튼이 상태 플래그만 None으로 바꿨다. 이미 fork된 OS 프로세스는 왜 계속 도는가. 그리고 root 권한으로 띄운 자손에게 일반 사용자 프로세스가 그룹 kill을 보내면 무슨 일이 일어나는가.
3. `pkill -f <패턴>`을 실행했더니 대상은 살아 있고 내 셸(또는 SSH 세션)이 죽었다. 왜인가. `[j]ob` 같은 대괄호 트릭은 정확히 어떤 원리로 자기 매칭을 피하는가. pid 기반(`pgrep -P`) 순회는 왜 이 문제가 없는가.
4. 예측: 장시간 배치를 SSH 세션에서 `nohup cmd &`로 띄웠는데 세션 종료와 함께 죽었다. `nohup`이 막는 것과 못 막는 것은 무엇인가. `setsid cmd < /dev/null &`는 무엇을 더 끊는가.
5. 경계: 데몬이 PTY로 자식을 띄우고 자식은 `setsid`로 새 세션 리더가 됐다. SSH 채널 종료에는 살아남는데, 데몬 자신이 죽으면 자식이 SIGHUP으로 같이 죽는다. 왜 setsid가 이것까지 막지 못하는가(제어 터미널 hangup).
6. 런처가 서버를 SIGKILL하거나 프로세스 그룹 kill로 정리했더니 서버는 죽었지만 서버가 띄운 PTY 자식들이 고아로 남았다. 두 방법이 각각 왜 실패했는가. 무엇으로 정리 경로를 깨워야 하는가.
7. 연결: `ssh host "docker run …"`을 띄운 로컬 `Popen`을 terminate했다. 원격 컨테이너는 왜 계속 도는가. 종료를 "보냈다"와 "끝났다"를 가르려면 무엇을 해야 하는가. 그리고 종료 조건이 절대 참이 될 수 없는 대기 루프(`until [ -f /nonexistent ]`)는 이 카드의 어떤 원리와 이어지는가.
