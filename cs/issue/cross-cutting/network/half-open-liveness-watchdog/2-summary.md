# cs/issue/network/half-open-liveness-watchdog — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
원격 데몬 ──(출력만, 15s 하트비트)──▶ SSH 채널 ──▶ 브리지 ──▶ 화면 "Live"

[상대가 사라짐]
  데몬 쪽 호스트 소멸 / 경로 단절
  브리지는 받기만 함 → 보낼 세그먼트 없음 → ACK 기다릴 것도 없음 → TCP 에러 없음
  SSH 비활성 감지 꺼짐 (inactivity = 0)
  → (보낼 게 생긴 세그먼트의) 재전송 한도 소진(~15분, 커널 설정 의존)까지 "Live" + 낡은 화면   ← silent

[1차 워치독의 구멍]
  갱신 기준 = 도착 바이트        → 1바이트/100ms 흘리는 스트림이 무기한 회피
  검사 위치 = recv_timeout Err 분기 안 → 바이트가 계속 오면 검사 0회

[교정]
  시계 갱신 = consume()이 적용한 "완성 줄 수 > 0" 일 때만
  검사 = 루프 매 턴 (수신 결과와 무관)
  임계 = 하트비트 15s × 3 = 45s → 끊고 재연결 (지수 백오프)
  노출 = last_frame_at → "마지막 프레임 N초 전" (화면 나이 = 재연결 판정과 같은 사건)
  접속 초기 = Hello 20s 안에 없으면 실패
  이빨 = "600초 침묵" e2e ↔ "100ms마다 1바이트" e2e 둘 다 재연결

[같은 구조 — DB 스트리밍]
  서버 측 커서로 수억 행 스트리밍 → 클라 소비 느림 → 서버 쓰기 타임아웃으로 정리
  정리 신호가 클라에 안 닿거나 읽기 타임아웃이 없으면 → 에러 없이 무한 대기
  → 키셋 페이지네이션(WHERE key > :last LIMIT N) + --resume : 매 요청이 끝이 있는 단위
```

## 핵심 문장

- **half-open**: 한쪽이 사라졌는데 다른 쪽은 연결이 열려 있다고 믿는 상태. 보낼 게 없는 쪽은 TCP가 알려주지 않는다.
- 하트비트는 **판정에 쓰여야** 의미가 있다 — 받고 버리면 없는 것과 같다.
- liveness 시계는 **의미 있는 단위(완성 프레임)** 도착으로만 갱신한다. 바이트 도착은 "진행"의 증거가 아니다.
- 워치독 검사는 **수신 결과와 무관하게 매 턴** 실행돼야 한다 — 특정 분기에 숨기면 데이터가 올 때는 절대 안 돈다.
- 화면이 보여 주는 나이와 재연결 판정은 **같은 사건**으로 갱신해 두 신호가 어긋나지 않게 한다.
- 긴 단일 스트림이 끊김을 못 알리면, **끝이 있는 요청 단위(키셋 페이지 + resume)**로 쪼개 매 요청이 성공/실패를 돌려주게 한다.
