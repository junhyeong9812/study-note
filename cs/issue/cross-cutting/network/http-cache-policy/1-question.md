## 질문
1. `Cache-Control: public, max-age=604800, immutable`은 브라우저·중간 캐시에게 무엇을 약속하는가. `max-age`만 있을 때와 `immutable`이 붙었을 때, 사용자가 새로고침하면 동작이 어떻게 다른가.
2. 이미지 프록시가 upstream 응답이 2xx이기만 하면 7일 immutable을 붙였다. 204(본문 없음)나 206(부분 응답)에도 붙으면 무엇이 문제인가 — 왜 "200일 때만"이어야 하는가.
3. 예측: 이미지 URL에 버전·해시 토큰이 없다. 원본 이미지를 재적재(같은 URL, 다른 바이트)하면 이미 본 사용자는 언제까지 옛 이미지를 보는가. "콘텐츠 주소화된 URL"이란 무엇이고, 왜 immutable의 전제인가.
4. 배포했는데 사용자 브라우저가 구버전 JS를 계속 써서 새 로직(배포 완료 감지)이 동작하지 않았다. 해시 없는 정적 파일과 캐시 정책 없는 상태 엔드포인트는 각각 어떤 식으로 배포와 클라이언트를 어긋나게 하는가.
5. 상태 폴링 fetch에 `cache: 'no-store'`를 붙이는 것과 서버가 `Cache-Control: no-store`를 보내는 것은 무엇이 다른가 — 어느 쪽이 모든 클라이언트를 보호하는가.
6. 경계: 버전 없는 URL에 immutable 7일을 쓰는 리스크를 알고도 "유지"로 결정했다. 어떤 조건이면 이 결정이 합리적인가 — 되돌리기 쉬움(상수 한 곳)은 이 판단에 어떻게 기여하는가.
