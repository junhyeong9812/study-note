## 정답
<!-- 질문 1:1 대응 -->

1. **비ASCII는 요청 라인에 못 들어간다.** HTTP/1.1 요청 라인의 URI는 ASCII 문자로만 구성된다(RFC 3986 문법).\
비ASCII 문자는 UTF-8 바이트로 바꾼 뒤 `%XX`로 퍼센트 인코딩해야 한다.\
한글을 그대로 넣으면 (Python 표준 `http.client`/`urllib`처럼 자동 인코딩하지 않는) 클라이언트 라이브러리가 요청을 만들 때 ASCII로 변환하다 `ascii codec can't encode`로 실패한다. 브라우저나 일부 고수준 클라이언트는 자동으로 퍼센트 인코딩해 주기도 해서, 같은 URL이 도구마다 다르게 동작한다.\
공백만 `%20`으로 치환하는 것은 "문제가 보인 문자 하나"만 고친 것이다.\
값 하나하나를 인코딩 함수에 통과시켜야 비ASCII·예약문자가 처리된다. 단 Python `quote()`는 기본값으로 `/`를 남기므로(`safe='/'`), 쿼리 값에는 `urlencode()`나 `quote(v, safe='')`를 쓴다.
   > **퍼센트 인코딩** — URI에 허용되지 않는 바이트를 `%` + 16진수 두 자리로 표기하는 방식.

2. **경로 속 슬래시.** 인코딩하지 않으면 `/items/AB/123/10`이 되어 라우터가 세그먼트 3개로 쪼갠다 → 매칭 실패(404/400).\
`%2F`로 인코딩하면 의미상으로는 "세그먼트 안의 슬래시"지만, 흔한 서블릿 컨테이너(예: Tomcat 기본 설정)와 보안 필터 방화벽은 경로 우회 공격을 막으려고 **인코딩된 슬래시를 기본 거부**한다(400 등 — 설정으로 허용할 수 있지만 모든 홉·프록시가 같은 설정이어야 하고 보안 검토가 필요하다).\
그래서 슬래시가 들어갈 수 있는 식별자는 경로가 아니라 **쿼리 문자열**(`?id=AB%2F123%2F10`)로 보낸다.\
쿼리 값도 URI 템플릿 인코딩을 거쳐야 한다 — 중간 서버가 쿼리 값을 리터럴로 이어붙이면 `/`는 쿼리에서 유효해 통과하더라도 다른 예약문자(`&`·`#` 등)에 취약해진다.
   > **예약문자(reserved)** — `/ ? # & = +` 처럼 URI 문법에서 구분자 의미를 가진 문자.

3. **표준 Base64.** 표준 알파벳에는 `+`, `/`, `=`가 있다.\
`/`는 경로 구분자로 해석돼 세그먼트가 쪼개지고, `+`는 폼 인코딩(`application/x-www-form-urlencoded`) 규칙으로 디코딩되는 쿼리에서 공백으로 읽히며, `=`는 쿼리의 키=값 구분자라 파서·수작업 분리 코드에 따라 혼동될 수 있다.\
URL-safe Base64는 `+`→`-`, `/`→`_`로 알파벳을 바꾸고 보통 패딩 `=`를 뺀다. 인코더와 디코더를 **같은 알파벳**으로 맞춰야 한다.

4. **이중 인코딩.** 테스트 클라이언트의 문자열 오버로드는 인자를 **URI 템플릿**으로 취급해 값의 `%`를 다시 `%25`로 인코딩한다.\
`%20` → `%2520`이 되고, 서버는 한 번 디코딩해 글자 그대로의 `%20`을 받는다.\
이미 인코딩된 URI를 그대로 보내려면 문자열이 아니라 **URI 객체 오버로드**를 쓴다(인코딩을 더 하지 않음).\
원칙: 인코딩은 **정확히 한 번** — 누가 인코딩 책임을 지는지 API 계약을 확인한다.

5. **여러 홉.** 홉마다 "받은 URI를 디코딩해 값으로 쓰고, 다음 홉으로 보낼 때 다시 인코딩"해야 한다.\
깨지기 쉬운 곳은 ① 중간 홉이 값을 문자열 연결로 URL에 붙이는 곳(인코딩 누락) ② 이미 인코딩된 문자열을 템플릿에 다시 넣는 곳(이중 인코딩) ③ 앞단의 허용 목록·검증이 새 대상·형식을 막는 곳이다.\
실제로 백엔드만 쿼리 방식으로 고쳐도 앞단의 지원 대상 허용 목록에 그 대상이 없어 URL 자체가 만들어지지 않는 하드블로커가 리뷰에서 잡혔다 — **모든 홉을 한 계약으로 같이 바꿔야** 한다.\
컨테이너의 실제 디코딩 동작은 단위 테스트로 재현이 어려워 배포 후 종단 간(e2e) 확인이 필요했다.

6. **비ASCII 라우트.** 라우트 폴더명은 그대로 URL 경로 세그먼트가 된다.\
브라우저·서버는 비ASCII 세그먼트를 퍼센트 인코딩된 형태로 주고받는데, 라우트 테이블의 키(원문 이름)와 요청의 형태(인코딩된 이름)가 어긋나면 빌드 목록에는 있는데 매칭은 실패한다(이 사례에서 어긋나는 정확한 단계는 원문에 미기록 — 증상은 프리렌더 문자 오류 + 런타임 404).\
사람이 읽는 이름은 **메뉴 데이터**에, URL 세그먼트는 **ASCII 슬러그**에 두면 인코딩 경계 자체가 사라진다.

## 문제 구조 (추상화 코드)

### 변형 A — 경로 세그먼트 안의 슬래시
① 문제 코드
```java
// 서버
@GetMapping("/items/{id}")            // id = "AB/123/10"
Item get(@PathVariable String id) { /* ... */ }

// 중간 홉 클라이언트
client.get().uri(base + "/items/" + id) // 인코딩 없음 → 세그먼트 분리
```
② 고친 코드
```java
@GetMapping("/items")                 // 기존 경로 라우트는 하위호환으로 유지
Item get(@RequestParam("id") String id) { /* ... */ }

client.get().uri(base + "/items?id={id}", id)  // 템플릿이 값을 인코딩
// 주의: 인코딩 모드에 따라 쿼리 변수의 '&'·'+'·'/' 등을 인코딩하지 않을 수 있다 → 변수 값을 엄격 인코딩하는 모드인지 확인
// + 앞단 허용 목록도 같은 계약으로 확장
```
무엇이 깨졌나: 인코딩 안 하면 라우팅이 쪼개지고, `%2F`로 인코딩하면 컨테이너 방화벽이 거부한다.

### 변형 B — 비ASCII 쿼리 값
① 문제 코드
```python
url = f"{base}/search?q={query}&t={target}"
urlopen(url.replace(" ", "%20"))      # 한글 → ascii codec 오류
```
② 고친 코드
```python
url = f"{base}/search?" + urlencode({"q": query, "t": target})   # 값마다 예약문자까지 인코딩 (quote 기본값은 '/'를 남김)
urlopen(url)
```
무엇이 깨졌나: 공백만 치환하고 비ASCII는 그대로 넣었다.

### 변형 C — 비ASCII 라우트 세그먼트
① 문제 코드
```
app/admin/회원관리/page.tsx     → /admin/회원관리
```
② 고친 코드
```
app/admin/members/page.tsx      → /admin/members
menu = [{ label: "회원관리", href: "/admin/members" }]   // 한글은 데이터에만
```
무엇이 깨졌나: 라우트 이름이 인코딩 경계를 지나며 매칭이 어긋났다(프리렌더 문자 오류 + 런타임 404).

### 변형 D — 표준 Base64 토큰을 경로에
① 문제 코드
```java
String token = Base64.getEncoder().encodeToString(encrypted);   // + / = 포함 가능
return "/files/" + token;
```
② 고친 코드
```java
String token = Base64.getUrlEncoder().withoutPadding().encodeToString(encrypted);
byte[] raw   = Base64.getUrlDecoder().decode(token);             // 디코더도 같은 알파벳
```
무엇이 깨졌나: 표준 알파벳의 `/`·`+`·`=`가 URL 문법 문자로 해석됐다.

### 변형 E — 이중 인코딩
① 문제 코드
```java
mvc.perform(get("/items/%20"));        // 문자열 = URI 템플릿 → %2520
```
② 고친 코드
```java
mvc.perform(get(new URI("/items/%20"))); // 이미 인코딩된 URI 그대로 전송
```
무엇이 깨졌나: 인코딩된 값을 템플릿에 넣어 `%`가 한 번 더 인코딩됐다.
