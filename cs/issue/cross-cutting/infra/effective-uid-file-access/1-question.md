## 질문
1. (왜) 호스트에서 root로 만든 디렉터리를 컨테이너에 bind mount했더니, 컨테이너 안 프로세스가 lock 파일을 못 만들어 즉사했다. 호스트에서 `sudo docker compose up`으로 띄웠는데도 왜 root 권한이 아닌가.
2. (예측) 이미지 파일 서빙 API가 모든 이미지에 404를 낸다(텍스트 API는 200). 파일은 디스크에 분명히 **존재**한다. 컨트롤러가 `Files.isReadable()`로 검사한다면 무엇을 의심해야 하는가. `chown -R`로 고쳤는데 다음 적재 때 또 재발했다 — 왜인가.
3. (경계) 2번에서 "0~1ms 응답이니 핸들러가 없다"고 추론한 것은 왜 오진이었는가. `Content-Length: 0`인 404는 무엇을 말해 주는가.
4. (예측) `sudo rsync ... > /root소유경로/log`를 실행하면 rsync가 뜨기도 전에 `Permission denied`가 난다. 리다이렉트 대상 파일은 누가 여는가.
5. (왜) 사용자를 `docker` 그룹에 추가(`usermod -aG`)했는데 이미 돌고 있는 서비스는 여전히 소켓 권한 거부다. 보조 그룹은 언제 확정되는가.
6. (예측) 한 저장소에 두 계정(root clone·일반 사용자)이 섞여 `git pull`했더니 `unable to unlink ... Permission denied`로 중간에 실패했다. 작업 트리는 어떤 상태로 남으며, 어떻게 복구하는가.
7. (연결) 1~6번의 공통 원리를 한 문장으로 — "권한 판단의 주체"는 누구인가.
