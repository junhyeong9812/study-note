## 질문
1. (왜) `rsync -a`가 `--delete` 없이는 "삭제를 전달하지 못한다"는 게 무슨 뜻인가. 로컬에서 파일을 옮기거나 지운 뒤 배포하면 서버에는 무엇이 남는가.
2. (예측) backend 레이어 재편(`common/`→`api/` git mv) 후 배포하니 앱이 무한 재시작하며 `ConflictingBeanDefinitionException`이 났다. 서버에서 무슨 일이 벌어졌길래 같은 이름의 빈이 둘이 됐는가.
3. (경계) `--delete`를 켜면 새로 생기는 위험은 무엇이며, `.env` 같은 서버 전용 파일은 어떻게 보호하는가.
4. (연결) 이미지 채널(ghcr `docker compose pull`)이 **compose 파일 변경을 영원히 전달 못 한** 구조적 이유는 무엇인가. compose는 왜 이미지 안에 못 담는가.
5. (설계) 전달 채널이 둘(코드=이미지, 설정=???)로 갈렸을 때 생기는 drift를, `git fetch + reset --hard <sha>`로 어떻게 하나의 정본으로 수렴시켰는가. 배포 순서가 왜 "설정 동기화 → 컨테이너 갱신"이어야 하는가.
6. (경계) `reset --hard`가 `.env`(시크릿)를 안 지우는 이유는 무엇인가 — git의 추적/미추적 구분이 여기서 왜 안전장치가 되는가.
7. (일반화) "복사(copy)"와 "정본에서의 동기화(sync/reconcile)"의 차이를 한 문장으로. 이번에 잔재가 **시끄러운 실패**(기동 거부)로 잡힌 건 왜 오히려 운이 좋았는가.
