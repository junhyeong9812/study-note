## 질문
1. 예측: 20초 `@Timeout`을 단 테스트 안의 코드가 무한 루프에 빠졌다. JUnit 5 기본 설정에서 이 테스트는 20초 뒤 실패하는가, 영원히 도는가. 비선점(SAME_THREAD) 타임아웃은 무엇을 재는가. 어노테이션이 없는 테스트는?
2. 추상 계약 테스트 클래스의 `@Nested class Delay`와 **같은 이름**의 내부 클래스를 하위 테스트가 선언하면 무슨 일이 생기는가. 이 결함이 "실패"가 아니라 "소실"로 나타나는 것이 왜 더 위험한가.
3. `patch("pkg.module.func")`는 어느 모듈의 이름을 바꾸는가 — "정의된 곳"인가 "조회되는 곳"인가. 헬퍼 함수로 호출을 감싸거나 이름을 바꾼 뒤 mock이 빗나가는 이유는? 문자열 경로 patch가 리팩토링 도구의 이름 변경을 따라가지 않는 이유는?
4. 앱 기동(lifespan)에서 초기화하는 전역 상태나 정리 코드가, 테스트 클라이언트(`TestClient`를 `with` 없이, httpx `ASGITransport`)에서는 왜 실행되지 않는가. 어떤 증상(미등록 상태·자식 프로세스 누수)으로 나타나는가.
5. `vi.mock` 팩토리가 파일 위쪽에 선언한 `const`를 참조하면 왜 TDZ 오류가 나는가(호이스팅). `vi.hoisted`는 무엇을 보장하는가.
6. Mockito에서 같은 호출을 두 번 스텁하면? 스텁 구문 안에서 다른 mock을 만들며 또 스텁하면? 오버로드된 제네릭 메서드에 deep stub이나 `any()`를 쓰면 무엇이 매칭되지 않는가.
7. 연결: 로깅 설정의 `disable_existing_loggers=True`가 pytest의 로그 캡처를 무력화하는 이유, 슬라이스 테스트(`@DataJpaTest`)가 사용자 설정 빈을 못 찾는 이유, 테스트 컨테이너 DB가 운영과 다른 서버 기본값으로 뜨는 문제 — 공통으로 "테스트 도구의 기본값"에 대해 무엇을 알려 주는가.
