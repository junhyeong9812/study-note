## 질문
1. "테스트 더블·에뮬레이터가 검증하려는 동작 자체를 구현하지 않으면 테스트는 결함 유무와 무관하게 같은 결과를 낸다" — jsdom에서 "Tab을 눌러도 포커스가 모달 안에 남는다"는 단언이 취약한 코드에서도 통과한 이유로 이 문장을 설명하라. 그런 테스트가 진짜 검출력을 갖는지 어떻게 실증하는가.
2. 예측: 엔티티에 `@Table`을 빠뜨려 테이블 이름이 단수형으로 매핑됐다. 테스트는 H2 + `ddl-auto=create-drop`, 운영은 MySQL + 마이그레이션 도구(Flyway). 테스트는 어떻게 되고 운영 기동은 어떻게 되는가? 왜 `create-drop`은 이 결함을 **원리적으로** 볼 수 없는가.
3. 멀티스테이지 컨테이너 빌드에서 "빌드는 통과했는데 운영에서 404"가 났다. 설정 파일이 앱 소스를 import 했을 때 빌드 스테이지와 런타임 스테이지에서 각각 무슨 일이 일어나는가. 이것을 "그린 위장"이라 부르는 이유는?
4. 경계: 같은 코드를 헤드리스로 돌려 본 결과를 "대화형(TTY) 모드도 같다"로 일반화해도 되는가? 헤드리스 브라우저에서 `(hover:hover)` 미디어 쿼리가 거짓으로 나오는 사례와 함께, "실행 모드가 달라지면 무엇이 달라질 수 있는가"를 말하라.
5. `curl`로 한글 쿼리스트링을 보내면 400, 브라우저로는 정상이다. 이것은 서버 버그인가? "재현 실패가 코드 버그가 아니라 테스트 도구 차이일 수 있다"는 판단은 어떤 확인을 거쳐야 내릴 수 있는가.
6. standalone MockMvc·직접 생성한 `new ObjectMapper()`·테스트 슬라이스(`@DataJpaTest`)의 공통점은 무엇인가 — 각각 운영 컨텍스트의 무엇을 빠뜨리며, 그 빠진 부분(권한 AOP·예외 advice·모듈 등록·감사)은 어디서 검증해야 하는가.
7. 연결(방안 비교): "컴파일 OK ≠ 기동 OK" — 호출되지도 않는 `@Query` JPQL 오타가 왜 애플리케이션 기동을 막는가. 실 DB로 테스트를 옮기는 방안과 "기동까지 스모크"하는 방안은 각각 무엇을 잡고 무엇을 못 잡는가.
