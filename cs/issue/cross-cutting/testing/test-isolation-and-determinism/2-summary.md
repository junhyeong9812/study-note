# cs/issue/testing/test-isolation-and-determinism — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
테스트 결과 = f(코드)            ← 원하는 것
테스트 결과 = f(코드, 환경 이력) ← 실제로 일어난 것

 환경이 새는 통로
 ├ 공유 상태    : 재사용 DB 컨테이너(다른 실행·다른 브랜치의 마이그레이션 이력)
 │               공유 상태 디렉터리(두 데몬이 한 장부를 읽고 인수)
 ├ 외부 데이터  : 매일 갱신되는 실데이터·재색인 중 인덱스 → 정확값 단언 비결정
 ├ 원격 결합    : 시드의 ID·이름을 상수로 참조 → 시드 변경이 먼 테스트를 깸
 └ 스케줄링     : 스레드 간 happens-before 없음 → 순서 역전이 간헐 발생
                  경합 재현 하네스가 경합을 못 만듦 (배분·횟수·가짜 시계)
                  관측 시점에 상태 미확정 (finally·비동기 드레인·join 타임아웃)

[교정]
  격리      : 실행마다 fresh 컨테이너/사전 정리, 모든 영속 경로 env override
  결정성    : 테스트 전용 seam 으로 단일 스레드 직렬화 / 시계가 일을 촉발
  경합 재현 : 라운드로빈 배분·라운드 확대·배리어 동시 출발
  확정 후 관측: join 후 isAlive==false 단언·완전 드레인 후 단언·예외 캡처
  외부 데이터: 하한·허용 범위 단언, 긴 타임아웃, 순차 실행
  시드 결합 : 전수 grep + 전체 스위트 + 결정적 노드 존재로 단언
```

## 핵심 문장

- 테스트 결과는 **코드만의 함수**여야 한다 — 공유 상태·실행 이력·스케줄링이 끼어들면 가짜 실패와 가짜 성공이 모두 생긴다.
- 픽스처를 재사용하면 이전 실행의 상태가 누적된다 — 전부 에러면 **코드보다 재사용 픽스처를 먼저** 의심한다.
- 프로세스가 쓰는 영속 경로 중 **하나라도** 격리되지 않으면 인스턴스끼리 서로의 결과를 바꾼다.
- 동기화 없는 스레드 간 쓰기-읽기는 순서가 보장되지 않는다 → sleep 마진이 아니라 **구조적으로 한 스레드에서** 실행해 결정화한다.
- 관측 전에 대상 상태가 **확정됐음**(스레드 종료·드레인 완료)을 단언한다 — 하네스도 검증 대상이다.
