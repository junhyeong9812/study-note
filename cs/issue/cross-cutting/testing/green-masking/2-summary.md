# cs/issue/testing/green-masking — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
결함 있는 코드 ──▶ 테스트 ──▶ 초록?   초록이 거짓이 되는 지점들
                  │
   [실행]         ├─ 수집 누락 (include 패턴·@Nested 0 카운트·-Dtest 0건 매칭)
                  ├─ 실행 생략 (UP-TO-DATE 캐시·test 단계만·Dockerfile 이 테스트 안 돌림)
                  ├─ 판정 근거 오류 (exit code 버림·낡은 결과 XML·필터된 출력)
   [단언]         ├─ 무단언 (출력만 하고 assert 없음)
                  ├─ 약한 단언 (에러 "종류"만·anySatisfy·>= 하한·결과 존재만)
                  ├─ 대리 상태 단언 (is_alive 플래그 ≠ 실제 프로세스 종료)
   [관측]         ├─ 관측 시점 (메타 도착 순간만·호출 후 시점만)
                  ├─ 변하는 축을 고정 (실제로 바뀌는 입력을 상수로)
                  ├─ 문자열 부재 단언이 에코 메시지에 뒤집힘
   [픽스처]       ├─ 결함을 표현 못 함 (손자 없음·단일 브랜치·작은 그래프·같은 시드)
                  ├─ 프로덕션 경로 우회 (구성요소 직접 조립·전역 env 의존·가짜 대역)
   [기대값]       └─ 기대값이 구현에서 옴 (리터럴 사본·관찰값 박제·틀린 계약 고정)

[교정 — 초록에 이빨이 있음을 증명]
   뮤테이션: 방어 코드를 지우거나 되돌림 → 정확히 그 테스트가 red 인가
   대조군:   고치기 전 코드(또는 실패 조건)에서 먼저 red 를 본다
   실행 증명: exit code 전파·결과 파일 삭제 후 실행·0건이면 실패·--rerun
   독립 기대값: 생산자 타입·명세·손계산에서 — 구현 출력에서 가져오지 않음
   비용 계수: 결과 대신 커밋 횟수·회전 수·이동 횟수 등 결정적 계수기
```

## 핵심 문장

- 초록불은 **테스트가 실패할 수 있었을 때만** 증거다 — 결함 버전에서 red를 본 적 없는 테스트는 계약을 검증한다고 볼 수 없다.
- 테스트는 **관측한 값만** 검증한다 — 결함이 관측 밖(종류 vs 내용, 앞 4바이트, 작은 입력, 결과 vs 비용, 한 순간)에서만 차이를 내면 통과한다.
- 테스트의 커버리지 상한은 **픽스처의 표현력**이다.
- 기대값은 검증 대상과 **독립된 출처**(생산자 타입·명세·손계산)에서 와야 한다 — 관찰값 박제는 결함의 보호막이 된다.
- 많은 러너·리포터·린터는 도구·설정에 따라 대상이 0개여도 실패하지 않는다(pytest의 "수집 0건 = exit 5"처럼 막아 주는 도구도 있지만 의존하지 않는다) → **실행됐음**을 별도로 증명한다.
- 대칭: 음성 케이스가 엉뚱한 곳에서 실패하는 "레드 위장", 의도된 변경을 못 따라간 "낡은 레드"도 같은 불신 대상이다.
