# cs/issue/document-rendering/cjk-vs-western-text-rules — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
텍스트가 화면·PDF에 가기까지 거치는 규칙들 — 전부 서구 문자 기준 기본값

 [글리프 선택]   font-family: monospace
                  → 실제 폰트(라틴 전용) → 한글 글리프 없음 → 폴백 비어 깨짐
                  교정: 스택에 CJK 모노 폰트 명시

 [폰트 메트릭]   PDF 선택 박스 = ascent/descent/line gap 기반
                  → 메트릭 큰 CJK 폰트 = 박스 2.6배, 윗줄 가림
                  교정: 폰트 교체 + 임베드 폰트 목록으로 확인

 [표시 폭]       고정폭 격자: 라틴 1칸 / 한글(전각) 2칸
                  "문자 수 = 칸 수" 파서 → 좌표 어긋남, 음절 단위로 쪼개짐
                  교정: 폭 인지 셀 모델(한글 2칸)

 [구분자 규칙]   CommonMark: 닫는 ** 는 right-flanking이어야
                  "...)**으로" = 앞 구두점 + 뒤 문자 → 닫힘으로 인정 안 됨
                  교정: 구두점 앞에서 닫기 + 정규식 점검

 공통: 에러 0, 결과만 틀림 → 실물(렌더 결과·PDF)로 확인
```

## 핵심 문장
- generic `monospace`는 한글 글리프를 보장하지 않는다 — 코드 영역 폰트 스택에 CJK 모노 폰트를 명시한다.
- PDF 텍스트 선택 영역은 글자 모양이 아니라 **폰트 메트릭**으로 잡힌다 — 폰트 선택이 곧 선택 박스 크기다.
- 한글은 고정폭 격자에서 **2칸**(전각)이다. 문자 수로 좌표를 세면 어긋난다.
- CommonMark 강조 구분자는 앞뒤 문자 종류(구두점/공백/문자)로 열림·닫힘이 정해진다 — 구두점 뒤 닫힘 + 한글 조사는 닫히지 않는다.
- 전부 무음 실패다 — 점검은 렌더 결과·임베드 폰트·패턴 grep으로 한다.
