## 정답
<!-- 질문 1:1 대응 -->

1. **환경이 정한 실제 모노 폰트로 해석되고, 거기에 한글이 없으면 폴백 결과가 환경마다 달라져 깨진다.**\
   `monospace`는 특정 폰트가 아니라 "시스템이 고른 고정폭 폰트"라는 generic family다.\
   그 폰트에 한글 글리프가 없으면 브라우저는 스택 밖 시스템 폰트까지 뒤져 폴백한다 — 그래서 환경마다 다른(대개 비고정폭이라 폭이 어긋나는) 폰트로 그려지고, 한글 폰트가 아예 없는 환경(최소 컨테이너 등)이면 두부(□)가 된다.\
   교정: `"<라틴 모노>", "<라틴 모노 2>", "<CJK 모노>", monospace`처럼 CJK 모노 폰트를 명시한다.
   > **폰트 폴백** — 앞 폰트에 없는 글리프를 스택의 다음 폰트에서 찾는 과정.

2. **설치 의존성 vs 번들 크기.**\
   스택에 이름만 넣으면 가볍지만 그 폰트가 설치된 환경에서만 효과가 있다.\
   웹폰트 번들은 어디서나 같지만 CJK 폰트는 크기가 커서, 이 경우 과하다고 보고 선택하지 않은 방법이 됐다.

3. **폰트 메트릭(ascent·descent·line gap)으로 결정된다.**\
   PDF 뷰어는 대개 글자의 실제 잉크 모양이 아니라 폰트가 선언한 세로 메트릭으로 선택 영역을 잡는다(어떤 값 — ascent/descent, FontBBox 등 — 을 쓰는지는 뷰어마다 다르다).\
   메트릭 값이 큰 CJK 폰트는 실제 글자보다 훨씬 큰 박스가 생겨 윗줄을 덮는다(관측: 2.6배 → 교체 후 1.15배).\
   (메트릭 원인은 일반론에 따른 해석 — 원 기록은 현상과 폰트 교체 조치만 남겼다.)\
   교정: 폰트를 교체하고 CSS 폴백 목록에서도 문제 폰트를 빼서, PDF의 임베드 폰트 목록으로 의도한 폰트만 들어갔는지 확인한다.

4. **한글은 2칸을 차지하기 때문이다.**\
   Unicode East Asian Width에서 한글 음절(완성형)은 전각(Wide)이라 고정폭 격자에서 보통 2칸이다(결합용 자모처럼 폭 0·1인 문자도 있다).\
   "문자 1개 = 1칸"으로 세면 한글이 있는 줄마다 뒤 좌표가 밀려, 상자 경계·화살표 위치 판정이 틀린다.\
   셀을 전각만큼 확장하는 방식은 상자 밖 텍스트를 음절 단위로 쪼개고 하이픈을 잃었다 — 원문 줄 기반으로 토큰을 뽑는 쪽으로 재작성했다.
   > **East Asian Width** — 유니코드 문자 속성(N·Na·H·W·F·A). 고정폭 표시에서 W·F는 보통 2칸, Na·H는 1칸이며, A(Ambiguous)는 환경 설정에 따라 1칸 또는 2칸이다. 실제 칸 수는 터미널·라이브러리(wcwidth 류) 구현이 정한다.

5. **닫는 `**`가 right-flanking이 아니라서(left-flanking으로만 판정돼) 닫는 구분자로 인정되지 않는다.**\
   CommonMark에서 닫는 강조 구분자는 right-flanking이어야 한다.\
   right-flanking은 "앞이 구두점이면 뒤가 공백이나 구두점일 것"을 요구하는데, `)**으` 는 앞이 구두점이고 뒤가 문자(한글)라 이 조건을 못 채운다.\
   반대로 left-flanking 조건(뒤가 공백도 구두점도 아님)은 만족해 "여는 쪽"으로만 읽힌다.\
   영어는 강조 뒤에 공백이 오는 게 보통이라 잘 드러나지 않고, 조사가 바로 붙는 한국어(단어 사이 공백이 없는 중국어·일본어도 마찬가지)에서 자주 터진다.\
   교정: `**검색**(BM25 + 벡터)으로`처럼 구두점 앞에서 닫는다.
   > **flanking** — 구분자 앞뒤의 문자 종류(공백·구두점·일반 문자)로 여는/닫는 구분자 자격을 정하는 CommonMark 규칙.

6. **실물 확인 + 패턴 점검.**\
   글리프: 렌더 결과를 눈으로 보거나 캡처한다.\
   메트릭: PDF 임베드 폰트 목록(`pdffonts` 류)으로 의도한 폰트만 있는지 본다.\
   폭: 폭 인지 셀 모델을 쓰고, 파라미터(셀 폭 등)는 고정값 + assert로 못 박는다.\
   구분자: `grep -nP '[)\]]\*\*[가-힣]'`처럼 "구두점 + `**` + 한글" 패턴을 찾는다.\
   공통 교훈: 에러가 안 나므로 **산출물을 보는 점검**이 아니면 잡히지 않는다.

## 문제 구조 (추상화 코드)

### 변형 A — generic 폰트에 CJK 글리프 없음
① 문제 코드
```css
.code-block, .diff-old, .diff-new { font-family: monospace; }
```
② 고친 코드
```css
.code-block, .diff-old, .diff-new {
  font-family: "LatinMono", "LatinMono2", "CJK Mono KR", monospace;
}
```
깨진 것: generic family가 라틴 전용 폰트로 풀려 한글 폴백이 없었다.

### 변형 B — PDF 선택 박스가 폰트 메트릭을 따름
① 문제 코드
```css
body { font-family: "CJK Sans (메트릭 큼)", "Other KR", sans-serif; }
/* headless 브라우저 → PDF : 선택 박스 ≈ 2.6 × 글자 크기 */
```
② 고친 코드
```css
body { font-family: "KR Sans (메트릭 작음)", sans-serif; }  /* 폴백에서도 문제 폰트 제거 */
/* 검증: PDF 임베드 폰트 목록에 의도한 폰트만 있는지 확인 */
```
깨진 것: 글자는 멀쩡해 보이지만 폰트가 선언한 세로 메트릭 때문에 선택 영역이 윗줄을 덮었다.

### 변형 C — 문자 수 = 칸 수 가정
① 문제 코드
```python
for x, ch in enumerate(line):      # 한글도 1칸으로 셈
    grid[y][x] = ch
```
② 고친 코드
```python
col = 0
for ch in line:
    w = 2 if east_asian_width(ch) in ("W", "F") else 1   # 결합 문자(폭 0)·Ambiguous(A)는 별도 규칙 필요
    grid[y][col] = ch
    col += w                        # 한글은 2칸 전진
```
깨진 것: 전각 문자를 1칸으로 세어 한글이 있는 줄의 좌표가 전부 밀렸다.

### 변형 D — CommonMark 닫는 구분자 규칙
① 문제 코드
```markdown
**검색(BM25 + 벡터)**으로 찾는다      ← ')' 뒤 '**' 뒤에 한글 → 닫힘 불인정, 별표 노출
```
② 고친 코드
```markdown
**검색**(BM25 + 벡터)으로 찾는다      ← 구두점 앞에서 닫기
```
점검: `grep -nP '[)\]]\*\*[가-힣]'`\
깨진 것: 구분자 판정이 "강조 뒤엔 공백" 이라는 서구 문장 습관을 전제했다.
