# cs/issue/document-rendering/print-layout-traps — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
소스(HTML/CSS · 라이브러리 호출) ──▶ 렌더러/파서 ──▶ 페이지(PDF·docx·xlsx)
                                      │
                         여기서 "에러" 대신 "복구·기본값"이 결정

[1] 파서 자동 복구     </div> 중복 → .page가 일찍 닫힘
                        → 이후 요소는 페이지 밖 형제로 → 푸터 이탈·쪽번호 오류
                        교정: 검사(동일좌표 중복 단어 탐지)

[2] 독립 값의 충돌     .page padding-bottom 14mm   (본문 하한)
                        .footer bottom 10mm        (구분선 위치)
                        서로 모름 → 본문 하한 < 구분선 → 겹침
                        교정: 관계를 정하고 측정 선행

[3] paged media 함정   position:fixed → 여백 박스 밖에 그려져 클립
                        column-count:1 → 다단 컨테이너 생성 → 조각화 규칙 변경
                        큰 블록 break-inside:avoid → 통째로 다음 쪽 → 큰 공백
                        교정: @page margin box(counter(page)) · 다단 제거 · 줄 단위만 avoid

[4] 라이브러리 기본값   width만 → height 비율 자동(상한 없음) → 셀 넘침
                        셀 기본 여백 → 셀 폭 ≠ 가용 폭
                        문자열 앵커 → offset 0(좌상단 고정)
                        grid 미명시 → 워드가 열 폭 재계산
                        교정: 박스에 fit(width+height) · 여백 0 · 오프셋 앵커 · grid 명시

 검증 = 실물(PDF 좌표·쪽 수·텍스트 추출)로
```

## 핵심 문장
- HTML 파서는 틀린 마크업에 에러를 내지 않고 **복구**한다 — 복구 결과가 레이아웃을 조용히 바꾼다.
- 독립적으로 정한 두 값(본문 하한·푸터 위치)은 **관계를 명시**하지 않으면 한쪽이 움직일 때 겹친다.
- 인쇄 CSS는 화면 CSS와 규칙이 다르다: fixed는 쪽 여백 밖, `column-count:1`도 다단, 큰 블록의 `avoid`는 공백.
- 문서 라이브러리의 기본값은 "셀에 맞춤"을 보장하지 않는다 — 크기·오프셋·격자를 명시한다.
- 에러 0 ≠ 레이아웃 정상 — 좌표·쪽 수·텍스트 추출로 실물을 확인한다.
