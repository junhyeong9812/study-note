# cs/issue/data/in-band-signaling-collision — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
 한 채널에 [데이터 | 구분자 | 데이터 | 종료마커 | 센티널] 이 섞여 흐른다
                     │                  │            │
     데이터에 등장 ──┤                  │            │
                     ▼                  ▼            ▼
             필드 경계 오인        경계 조기 종료    리터럴 값으로 매칭
          (split·줄 파싱·표 칸)   (fence·END 마커)   ("전체" → 0건)
                     │                  │            │
                     └──── 대부분 예외 없이 "그럴듯한" 잘못된 결과 (silent) ────┘

[실측 사례]
   git 기본 출력     "a b.txt" C-quote, "old -> new" rename, 개행 파일명
   CSV/조인 구분자   값 안의 ,  ;  "
   DB 배치 출력      값 안의 탭·개행이 \t \n 로 이스케이프되어 나옴 (소비자가 역이스케이프)
   마크다운 표       코드 스팬 안 |  → 칸 분할이 인라인 해석보다 먼저
   코드 펜스         본문에 ``` → 최종본 잘림, 생성 규약(3중)·파서 규약 불일치
   LLM 출력 경계     고정 구분자를 본문이 포함/모델이 흉내 → 절단
   UI 센티널         "전체"를 값 목록에 → terms 필터 0건

[교정 — 신호를 데이터 밖으로]
   NUL 구분(-z)      NUL은 경로에 올 수 없다
   quoting 규약      RFC4180 "" 이스케이프
   더 긴/유일 경계   4중 fence 단일 상수 · <<<END-{nonce}>>>
   센티널 → 의미     "전체"/"all" 포함 시 필터 자체를 None

[다른 방안]
   이스케이프 왕복 계약  직렬화 \|  ↔  파싱 (?<!\\)\|
   마커 손상 복구 규칙   END 없으면 START~첫 표 줄 직전까지 교체
   센티널 인지 검증      센티널 분기를 일반 검증보다 먼저
```

## 핵심 문장

- 제어 신호(구분자·마커·센티널)를 데이터와 **같은 채널**에 두면, 데이터가 그 신호를 **흉내 내는 순간** 경계와 의미가 깨진다.
- 사람용 출력은 **기계 왕복을 보장하지 않는다** → 기계용 포맷(NUL 구분)을 쓴다.
- 가변 필드 레코드(rename = 두 경로)는 **형식 명세대로 소비**해야 한다.
- 경계 문자열은 **페이로드에 나올 수 없게**(NUL·nonce) 하거나, 나올 수 있다면 **이스케이프 규약을 양쪽이 공유**한다.
- 센티널은 값이 아니라 **의미**다 — 값 채널로 보내지 말고 의미(필터 없음)로 번역한다.
