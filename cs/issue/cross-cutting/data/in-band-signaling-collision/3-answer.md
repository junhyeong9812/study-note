## 정답
<!-- 질문 1:1 대응 -->

1. **in-band 신호.**\
   제어 정보(필드 구분자·레코드 끝·블록 종료 마커·"값 없음/전체" 같은 센티널)를 데이터와 **같은 채널, 같은 문자 집합**으로 보내는 방식이다.\
   데이터에 그 문자열이 등장하면 수신 측은 그것을 제어 신호로 읽어 **필드 경계를 오인**하거나, **경계를 일찍 닫거나**, 센티널을 **리터럴 값으로 매칭**한다.\
   대부분 예외 없이 "그럴듯한" 잘못된 결과를 내므로 조용히 퍼진다.
   > **in-band signaling** — 제어 신호를 데이터 채널 안에 섞어 보내는 방식. 반대는 별도 채널(out-of-band).

2. **git 기본 출력 파싱.**\
   `-z` 없는 porcelain 출력은 (스크립트용 포맷이지만) 공백·따옴표·개행 등 특수문자가 든 경로를 **C-quote**(따옴표·`\n`·8진수 이스케이프)하고, rename을 `old -> new` **한 문자열**로 보여 준다 → 역인용 없이 그 문자열을 경로로 되돌려 보내면 엉뚱한 파일을 스테이지하거나 실패한다. ` -> `로 단순 분할하면 그 문자열이 든 파일명이 오분할되고, 개행 파일명은 `\n` 이스케이프 문자열 그대로 경로로 쓰인다.\
   `-z`는 레코드를 **NUL**로 구분하고 경로를 원시 바이트로 준다 — NUL은 경로에 나올 수 없으므로 경계가 모호해지지 않는다.\
   rename/copy(`R`/`C`) 레코드는 `-z`에서 **다음 레코드에 원본 경로**를 실어 보내므로 그것까지 **소비**해야 한다. 소비하지 않으면 원본 경로가 다음 항목으로 읽혀 "지우지도 않은 파일이 삭제 목록에" 뜬다.\
   덧: 커밋 로그는 `%x1f`/`%x1e`(unit/record separator)로, 메시지 본문은 문자열 포맷 경유 대신 원시 바이트로 받는다. untracked 포함(`-uall`)·`core.quotePath=false`·카운트도 NUL 기준.

3. **고정 구분자 vs nonce.**\
   출력 본문에 그 구분자가 **이미 들어 있거나**(예: 본문에 코드 펜스), 모델이 구분자를 **흉내 내 일찍 쓰면** 파서가 거기서 끝나 결과가 잘린다(실측: 고정 구분자 방식에서 절단 80%).\
   요청마다 무작위 nonce를 박은 구분자(`<<<END-{nonce}>>>`)는 ① 본문에 우연히 등장할 확률을 사실상 없애고 ② 고정 문자열을 흉내 내는 경로를 줄인다(nonce도 프롬프트에 보이므로 모델의 조기 출력을 원리적으로 막지는 못한다). 여기에 요청 세대 번호·"잘림 = 오류"·경고 배지를 겹쳐 방어했다.

4. **센티널을 값 채널로.**\
   필터 빌더는 목록의 원소를 "이 값 중 하나와 정확히 일치"로 해석한다 → `"전체"`라는 **상태값을 가진 문서는 없으므로** 0건이다.\
   하위 계층 입장에서는 정상적인 질의(존재하지 않는 값으로 필터)라 에러가 날 이유가 없다 — 그래서 빈 결과로만 나타나고, 수집 로그에도 `"전체"`가 실제 값처럼 남아 혼란을 준다.\
   교정: 센티널 집합(`{"전체","all"}`)을 정의하고 하나라도 포함되면 필터 빌더가 **None(필터 없음)** 을 반환. 범용 조건 함수는 건드리지 않고 호출부에서 분기, 수집에는 실제 값만.

5. **표 칸 분할 vs 인라인 해석.**\
   GFM 표는 행을 먼저 `|` 기준으로 **칸으로 나누고**, 그다음에 각 칸 안의 인라인(코드 스팬 등)을 해석한다.\
   그래서 백틱 안에 있어도 `|`는 이미 칸 구분자로 소비된 뒤다 — 표 안의 리터럴 파이프는 `\|`로 이스케이프해야 한다(코드 스팬 안에서도).\
   검증은 "렌더했을 때 표가 실제로 N칸으로 갈라지는지"를 직접 확인한다.

6. **왕복 계약.**\
   "직렬화할 때 `|`를 `\|`로 바꾼다"와 "파싱할 때 이스케이프되지 않은 `|`로만 나눈다"가 **같은 규약의 양면**이어야, 어떤 값이든 저장 → 읽기 후 원래 값으로 돌아온다.\
   한쪽만 있으면(이스케이프 없이 쓰거나, 단순 split으로 읽거나) 값 속 `|`가 열 수를 바꾼다.\
   이때 "열 수가 안 맞는 행은 skip"으로 처리하면 **행이 통째로 사라진다** — 파싱 실패가 곧 무음 데이터 삭제가 된다. 열이 많으면 마지막(자유 텍스트) 열로 합쳐 **행을 보존**하고, skip은 구분선·헤더·빈 키로 한정한다.

7. **네 방안의 조건.**\
   **채널 분리**는 포맷을 고를 수 있을 때(도구가 `-z`를 제공, 경계를 우리가 생성) — 가장 강하다.\
   **이스케이프 왕복 계약**은 사람이 읽고 편집하는 텍스트 포맷을 저장소로 써야 할 때.\
   **마커 손상 복구 규칙**은 사람이 편집할 수 있는 문서 안에 관리 영역을 둘 때 — 마커가 지워질 수 있다는 전제.\
   **센티널 인지 검증**은 이미 필드에 특수값을 도입했을 때 — 그 필드를 검사하는 모든 지점이 센티널을 먼저 알아야 한다.

## 문제 구조 (추상화 코드)

### 변형 A — 줄 단위·인용 출력을 역인용 없이 파싱
① 문제 코드
```rust
for line in run("git status --porcelain").lines() {
    let path = &line[3..];                        // "\"a b.txt\"" (C-quote), "old -> new" (rename)
    changes.push(path.to_string());               // 이 문자열을 경로로 되돌려 보냄
}
```
② 고친 코드
```rust
let out = run("git status --porcelain=v1 -uall -z -b");
let mut recs = out.split('\0');
while let Some(rec) = recs.next() {
    if rec.is_empty() { continue; }               // 끝의 빈 토큰
    if rec.starts_with("## ") { continue; }       // -b 브랜치 헤더 레코드
    let (code, path) = (&rec[..2], &rec[3..]);
    if code.starts_with('R') || code.starts_with('C') { let _ = recs.next(); }   // 원본 경로 소비
    changes.push(Change { code: code.into(), path: path.into() });            // path = new
}
```
무엇이 깨졌나: 구분자·인용이 데이터에 섞이는 줄 단위 포맷을 역인용 없이 왕복에 썼고, 가변 필드 레코드를 명세대로 소비하지 않았다.

- 같은 구조: `show --name-status`를 탭·개행 기준으로 파싱 → `-z` 토큰 순회, R/C면 두 토큰(old, new) 소비 후 new 사용.
- 같은 구조: 파일명 판별 정규식이 접두사만 봐 `READMEevil.c`를 문서로 분류 → 접미 경계 `README($|[._-])`.

### 변형 B — 값 안의 구분자
① 문제 코드
```ts
const items = joined.split(",");                     // "Concentrates, syrups or powders" 가 둘로
```
② 고친 코드
```ts
const sep = valuesMayContainComma ? "; " : ", ";     // 값 집합별 구분자 선택
const items = joined.split(sep);
```
무엇이 깨졌나: 값에 등장할 수 있는 문자를 구분자로 써 split이 필드 경계를 오인했다.

- 같은 구조: CSV 내보내기 — 값 안의 `,`·`"`는 RFC4180 quoting(`"` → `""`)으로 처리됐는지 확인, 조인 구분자 `;`를 포함한 소수 행은 실측 후 합의 형식 유지.
- 같은 구조: DB 클라이언트 배치 모드는 값 내부의 탭·개행을 `\t`/`\n`으로 이스케이프해 출력 → 소비 측이 역이스케이프해야 원값(`sed 's/\\t/\t/g'` — 근사: `\\` 자체의 역이스케이프까지 순서대로 처리해야 정확).
- 같은 구조: 마크다운 표 코드 스팬 안의 `|` → `` `X \| Y` ``.

### 변형 C — 페이로드와 같은 문자로 된 경계 마커

### 변형 D — 센티널을 값 채널로
① 문제 코드
```python
def status_filter_of(statuses):
    return {"terms": {"status": statuses}}             # ["전체"] → 존재하지 않는 값 → 0건
```
② 고친 코드
```python
ALL_VALUES = {"전체", "all"}

def status_filter_of(statuses):
    if any(s in ALL_VALUES for s in statuses):
        return None                                       # 센티널 = "필터 없음"이라는 의미
    return {"terms": {"status": statuses}}
```
무엇이 깨졌나: "필터 없음"을 뜻하는 센티널이 하위 계층에서 리터럴 값으로 매칭됐다.

## 방안 비교

위 변형들의 기본 방안은 **채널 분리**(NUL·유일 경계·센티널의 의미 번역)다. 채널을 분리할 수 없을 때 쓴 세 가지 다른 방안.

### 방안 1 — 채널 분리 (기본)
```rust
let recs = out.split('\0');           // 데이터에 올 수 없는 구분자
```

### 방안 2 — 이스케이프 왕복 계약 (사람이 읽는 표를 저장소로)
```python
def serialize_cell(v):
    return v.replace("|", r"\|").replace("\n", " ")     # 개행 → 공백은 비가역(의도된 손실)

CELL_SPLIT = re.compile(r"(?<!\\)\|")                  # 파싱: 이스케이프 안 된 | 로만 분할
# 한계: 값이 \ 로 끝나면 뒤 구분자가 \| 로 오인된다 — 완전한 왕복은 \ 자체도 이스케이프해야 한다
cells = [c.strip() for c in CELL_SPLIT.split(body)]
if len(cells) < len(HEADER): continue                   # skip은 구분선·헤더·빈 키만
if len(cells) > len(HEADER):                            # 생 파이프 → 마지막(메모) 열로 합쳐 행 보존
    cells = cells[: len(HEADER) - 1] + [" | ".join(cells[len(HEADER) - 1:])]
# 갱신은 첫 연속 표 블록만 교체 → 표 밖 자유 기록 보존
# 추가 함수는 진입점에서 \r \n | 무력화 (결함 국소화)
```

### 방안 3 — 마커 손상 복구 규칙 (사람이 편집하는 문서 속 관리 영역)
```python
start = find(lines, START_MARKER)
end = find(lines, END_MARKER, after=start)
if end is None:                                         # 사용자가 END를 지웠다
    tbl = next((i for i in range(start, len(lines)) if is_table_line(lines[i])), len(lines))
    end = tbl - 1                                       # START ~ 첫 표 줄 직전 = 손상된 관리 영역
lines[start:end + 1] = render_summary()                 # 통째 교체 (요약 줄은 | 로 시작하지 않아 표 파서와 분리)
```

### 방안 4 — 센티널 인지 검증 (특수값을 이미 필드에 도입)
```python
# before: 일반 검증이 먼저 → 센티널이 "알 수 없는 값"으로 거부됨
server = resolve_target(target)
if not server: return error(f"Unknown target: {target}")
if action.startswith("system."): ...                    # 도달 불가

# after: 센티널 분기를 먼저 (guard clause 순서)
if action.startswith("system."):
    return await handle_system(action)          # target 인자를 받지 않는 시그니처 = "target 무관"
server = resolve_target(target)
```

| | 방안 1 채널 분리 | 방안 2 이스케이프 왕복 | 방안 3 마커 복구 규칙 | 방안 4 센티널 인지 검증 |
|---|---|---|---|---|
| 전제 | 포맷·경계를 우리가 고를 수 있음 | 사람이 읽고 편집하는 텍스트여야 함 | 관리 영역이 사람 편집 문서 안에 있음 | 필드에 특수값이 이미 존재 |
| 비용 | 파서 교체 | 직렬화·파싱 양쪽 동기화, 일부 비가역 손실 | 손상 판정 휴리스틱(첫 표 줄) 유지 | 모든 검증 지점 점검 |
| 실패 모드 | 거의 없음(NUL이 데이터에 없다는 전제) | 한쪽만 바뀌면 조용한 열 밀림 | 복구 범위 휴리스틱이 틀리면 사용자 영역 침범 | 새 검증 지점이 센티널을 모르면 재발 |
| 맞는 조건 | 기계 간 교환 | 사람 가독성이 요구되는 저장 | 사람과 기계가 한 문서를 공유 | 센티널을 없앨 수 없는 기존 프로토콜 |

**결론**: 채널을 분리할 수 있으면 대개 방안 1이 낫다 — 나머지는 "같은 채널을 유지해야 하는 이유"(사람 가독성·기존 프로토콜)가 있을 때의 차선이다.\
차선을 고르면 그 대가로 **양쪽 규약을 한 곳에서 관리**(단일 상수·왕복 테스트)하고, 파싱 실패를 skip이 아닌 보존·오류로 처리해야 조용한 손실이 생기지 않는다.
