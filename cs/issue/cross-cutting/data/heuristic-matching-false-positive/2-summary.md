# cs/issue/data/heuristic-matching-false-positive — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
판정하고 싶은 것(의미)          휴리스틱(추정 신호)              깨지는 입력
──────────────────────         ─────────────────────           ─────────────────────
"이 선택지가 골라졌나"      →   answer.includes(label)      →   auto ⊂ autonomous
"접두사 get/is인가"         →   name.indexOf("get")         →   issue, budget, history
"시크릿인가"                →   /sk-/                        →   task-
"내 설정 항목인가"          →   cmd.contains("my-tool")     →   not-my-tool-wrapper
"자기 부모인가"             →   text.contains(id)           →   자기 자신의 기록에 id 등장
"클래스인가 멤버인가"       →   마지막 식별자 대문자?        →   CONSTANT
"같은 타입변수인가"         →   이름 같음                   →   다른 선언의 동명 변수
"권한 프롬프트가 떴나"      →   화면에 문구 있음             →   스크롤백의 과거 프롬프트
"active 인스턴스는?"        →   ps 출력에 포트 문자열        →   방금 띄운 standby
            │
            └─ 공통: 신호에 "경계"가 없다 → 거짓 양성(가끔은 거짓 음성)이 예외 없이 결과로

[교정 3종]
   정확 일치    구분자·위치 고정: "label" 따옴표 / 줄 단위 == / startsWith / basename ==
                단어 경계 패턴 / 정확 이름 필터
   구조적 신호  문법·타입 사실: record 접근자 판정, static 키워드, 선언 클래스 하위타입 검사
                복수 신호 AND + 관찰 창 한정(화면 하단 N줄)
   영속 상태    "active = 마지막 성공 전환이 가리키는 쪽" — 라우팅 설정을 유일 진실 소스로,
                모호하면 None → 배포 중단(fail-closed)
```

## 핵심 문장

- 휴리스틱은 **경계가 없는 신호**로 의미를 추정한다 → 한 값이 다른 값의 부분일 수 있는 도메인에서는 오탐이 구조적으로 가능하다(입력 영역이 넓어지는 순간 드러난다).
- 레거시에서 `indexOf ≡ startsWith`였던 것은 **입력 영역이 좁았기 때문**이다 — 새 입력 영역이 열리면 숨어 있던 차이가 드러난다.
- 이름·대소문자 관례는 **의미를 보장하지 않는다** — 문법 키워드·타입 관계 같은 구조적 사실로 판정한다.
- 모르는 영역에서는 **침묵**이 오판보다 낫다(없는 경고 > 잘못된 경고).
- "지금 무엇이 active인가" 같은 상태는 부수 신호(포트·ps 순서)로 추론하지 말고 **영속된 단일 진실 소스**에서 읽는다.
