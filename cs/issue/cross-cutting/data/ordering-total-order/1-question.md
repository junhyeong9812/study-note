## 질문
1. `ORDER BY` 없이 읽은 행에 "첫 번째 것을 남기는" dedup(`keep="first"`)을 걸면 무엇이 보장되지 않는가. 지금까지 결과가 매번 같았다면 그건 무엇 덕분이며, 왜 계약이 아닌가.
2. `ORDER BY created_at DESC` 만으로 목록을 페이징하면 동점(같은 timestamp) 행이 페이지 경계에 걸렸을 때 무슨 일이 생기는가. **전순서(total order)** 가 되려면 정렬 키에 무엇을 덧붙여야 하나.
3. 예측: 날짜 문자열 컬럼에 `YYYYMM`·`YYYYMMDD`·ISO(`2026-12-31T09:00:00+09:00`) 형식이 섞여 있다. `MAX(col)` 로 "가장 최신"을 구하면 ISO 값은 어디에 정렬되는가 — 이유를 문자 코드로 설명하라.
4. `SELECT ... LIMIT 1000` 으로 뽑은 표본에서 오염률 0.6%, 전수에서는 46.7%였다. ORDER BY 없는 LIMIT 은 보통 어느 행부터 읽으며, 시간에 따라 품질이 변한 데이터에서 왜 편향 표본이 되는가.
5. 해시 기반 `Set` 을 JSON 배열로 직렬화해 스냅샷(골든) 테스트를 했더니 재실행마다 흔들렸다. 왜인가 — 그리고 "모든 배열을 정렬"하는 정규화가 틀릴 수 있는 이유는?
6. 경계: 여러 조각(청크)에서 각자 상위 N 개를 잘라 와 병합하는 분산 top-K 에서, 조각의 컷 정렬 키(score 단독)와 병합 정렬 키(score + id)가 다르면 어떤 결과가 나오나. "동점은 드문 엣지 케이스"라는 가정은 왜 틀리나.
7. 연결: 최소 비용 분할 DP 에서 비용이 같은 분할이 여럿이면 결과는 무엇이 결정하는가. `<` 와 `<=` 한 글자가 결과를 바꾸는 이유와, 이것이 SQL 동점 정렬과 같은 원리인 이유를 설명하라.
