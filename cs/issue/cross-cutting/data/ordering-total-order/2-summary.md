# cs/issue/data/ordering-total-order — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
"순서가 필요한 연산"                        순서의 출처
   dedup keep=first · LIMIT 샘플            ORDER BY 없음      → 실행계획·물리 저장 순서(우연)
   페이지 경계                              비유일 정렬 키      → 동점끼리 순서 미정
   MAX(문자열)                              사전식 비교        → 포맷이 섞이면 시간순 아님
   스냅샷 직렬화                            해시 Set 순회      → 실행마다 달라질 수 있음
   청크 컷 + 병합                           컷 키 ≠ 병합 키    → 경계 동점이 중복/누락
   DP 역추적                                비교 연산자(< / <=) → 동점 분할 중 하나가 "우연히" 선택

[실패 지점]  지금은 결과가 같다 → 테스트 통과 → 실행계획·JVM·데이터가 바뀌면 조용히 흔들림

[교정] 전순서를 "명시"한다
   ORDER BY <유일 키>              (PK = 클러스터 순서라 기존 산출물과 차이 0 확인)
   ORDER BY ts DESC, id ASC        (tie-breaker)
   집합 배열만 정렬 · 순서 의미 있는 곳은 LinkedHashSet 으로 계약화
   컷 키 == 병합 키 (같은 3키 전순서)
   DP 동점 규칙 명시 + 상태 타입 통일
   표본은 "추정(과소평가 가능)", 권위 수치는 전수
```

## 핵심 문장

- SQL 결과 순서는 `ORDER BY` 가 없거나 정렬 키가 **유일하지 않으면 보장되지 않는다**. 지금 같은 결과는 실행계획의 우연이지 계약이 아니다.
- 결정성이 필요하면 **전순서**(모든 두 원소의 앞뒤가 정해지는 순서)를 명시한다 — 비유일 키 뒤에 유일 키를 tie-breaker 로.
- 사전식 비교는 **고정 폭·동일 포맷**일 때만 시간순과 일치한다(`'-'(0x2D) < '0'(0x30)`).
- ORDER BY 없는 LIMIT 표본은 보통 클러스터 순서(초기 데이터)부터라 **편향 표본**이다.
- 해시 Set 순회 순서는 명세상 미보장 → 배열로 직렬화하면 비결정 스냅샷. 정규화는 "집합인 배열만" 정렬한다.
- 부분 결과를 잘라 합칠 때는 **컷 키와 병합 키가 같은 전순서**여야 한다. 동점은 엣지가 아니라 상수적으로 생긴다.
- DP 에서 동점 해를 고르는 규칙은 비교 연산자에 숨는다 — **명시**하라.
