# cs/issue/data/boundary-arithmetic — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
대부분의 입력 ─────────────▶ 정상
경계 입력     ─────────────▶ 터짐 (또는 조용히 틀림)

[경계 산술 유형]
  오프셋      min(len, src.length)            → start 만큼 덜 빼서 뒤로 넘침
              정답: min(len, src.length - start)
  overflow    int (page-1)*size               → 음수 wrap → 상한 clamp 통과 → 음수 인덱스
              Σ durations                    → 음수 → "lease ≥ 합" 통과 (fail-open)
              i * 큰 상수                    → 테스트 키 생성이 감겨 기대보다 적은 키
  0 분모      x / initial (initial=0 허용)    → ArithmeticException
  비교 방향   key == separator → left        → 오른쪽 서브트리 최소 키를 못 찾음
  부동소수    0.1 누적                        → 9.999999999999998
  센티넬      "없음" = MAX_VALUE, MAX - now   → 산술하면 의미 상실
  좌표계      스냅샷 길이 × 가변 버퍼 삭제    → 인덱스는 늘고 버퍼는 줄어 범위 초과
              split 배열 i ↔ 원 문자열 i      → 구분자 문자를 읽음
              삽입 위치 > 기준점인데 커서 이동 → overshoot

[교정 원칙]
  경계를 명시 계산: 남은 길이 = 전체 - 시작
  넓은 타입으로 계산 후 [하한, 상한] 양쪽 clamp
  합산 전에 항별 범위 검증
  허용된 설정이 분모가 되면 분기 (0이면 1 등 의도된 값)
  비교 분기는 "같음"의 방향을 먼저 결정
  센티넬은 산술하지 말고 분기로
  한 좌표계만 쓴다 (split 후엔 배열만, 삭제는 역방향)
  무효 입력은 조용히 자르지 말고 계약대로 예외
```

## 핵심 문장

- 경계 산술 결함은 **대부분의 입력에서 정상**이다가 경계(큰 값·0·같은 값·연속 중복·빈 prefix)에서만 터져 오래 숨는다.
- 오프셋이 있으면 남은 길이는 **전체 − 시작**이다. 상한 clamp는 **하한을 보장하지 않는다**.
- 고정폭 정수는 **조용히 감긴다** — 넓은 타입으로 계산하고 양쪽을 clamp하며, 합산 전에 **항별로 검증**한다.
- 허용된 설정값이 분모가 될 수 있으면 0 분기를 둔다. "없음"을 극값 센티넬로 표현했으면 **산술하지 말고 분기**한다.
- 인덱스는 **한 좌표계**에서만 쓴다. 순회 중 줄어드는 버퍼는 역방향으로.
- 무효 입력을 0으로 조용히 자르는 것은 수정이 아니라 **또 다른 버그**다.
