## 질문
1. `start` 오프셋부터 최대 `length`개를 복사할 때 상한을 `min(length, src.length)`로 잡으면 어떤 입력에서 넘쳐 읽는가. 올바른 상한은 무엇이고, 무효 입력(`start > src.length`)은 0으로 조용히 자를지 예외를 낼지 어떻게 정하는가.
2. 예측: `(page - 1) * size`를 32비트 int로 계산하고 `min(offset, rows.size())`로 상한만 막았다. 아주 큰 page 값이 들어오면 무엇이 일어나는가. 상한 clamp가 왜 하한을 보장하지 않는가.
3. 여러 duration 설정값을 더한 합이 "lease ≥ 합"인지 검사한다. 거대한 값 하나가 들어오면 왜 검사를 **통과**하는가(fail-open). 어떤 순서로 검증해야 하는가.
4. `jitter * (interval / initial)`에서 `initial = 0`이 허용된 설정이라면 무엇이 터지는가. "허용된 설정값"과 "분모"가 만날 때 무엇을 확인해야 하는가.
5. B+tree 내부 노드에서 separator와 **같은** 키는 왼쪽과 오른쪽 중 어디로 가야 하는가. 분기 순서(`slot == 0` 검사가 먼저)가 왜 결과를 바꾸는가.
6. 경계: 문자열 스냅샷의 길이로 루프 범위를 고정하고, 삭제는 가변 원본 버퍼에서 하면 언제 범위를 넘는가. 역방향 순회는 왜 안전한가.
7. 연결: `split(",")`한 배열의 인덱스로 원 문자열의 `charAt`을 읽는 것, 다중 편집에서 삽입 위치가 기준점보다 뒤인데도 커서를 민 것은 모두 "좌표계 혼용"이다. 이 결함들이 오래 숨는 이유는 무엇인가.
