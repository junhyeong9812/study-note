## 질문
1. "필드가 있으면 컬렉션 전체를 교체한다"는 update 의미에서 `if (!items.isEmpty()) replace(items)` 가드는 무엇을 잘못하는가. 빈 컬렉션은 "없음"인가 "새 값"인가.
2. 저장된 설정을 로드할 때 "키 없음", "있는데 파싱 실패", "있는데 모르는 버전"을 모두 `null`로 합치면 어떤 일이 생기는가. 왜 하필 "오래된 데이터가 부활"하는 쪽으로 틀리는가.
3. 역직렬화에서 생산자가 **항상** 보내는 필드에 기본값(`default`, `?? []`)을 달면 무엇이 "정상 빈 값"으로 둔갑하는가. 기본값은 어떤 필드에만 허용해야 하는가.
4. 예측: 값 타입 필드에서 "0이면 미설정으로 보고 기본값 60을 적용"하는 로직에 운영자가 명시적으로 0(가장 엄격)을 넣었다. 무엇이 일어나고, 어떻게 구분해야 하는가.
5. 보안 판정에서 "키 없음"과 "키는 있는데 형식 오류"를 같은 0으로 접으면 왜 fail-open이 되는가.
6. 경계: 화면 목록 상태의 초기값을 `[]`로 두고 조회 실패 catch에서도 `[]`를 넣으면 사용자는 무엇을 보는가. 최소 몇 가지 상태를 구분해야 하는가.
7. 연결: DB에서 "값 없음"을 `NULL`과 빈 문자열 두 표현으로 허용하면 어떤 쿼리가 무엇을 조용히 놓치는가. 이 모든 사례가 "silent failure"인 이유는?
