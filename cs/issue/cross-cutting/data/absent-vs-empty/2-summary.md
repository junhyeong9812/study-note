# cs/issue/data/absent-vs-empty — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
서로 다른 상태 ──────────────▶ 같은 값으로 뭉갬 ──────▶ 결함이 정상으로 위장
  없음(absent: 키/필드 부재)        null
  비어 있음(empty: [] 도 유효값)    []
  손상(corrupt: 파싱 실패)          0
  모르는 버전(unknown version)      ""
  기본값 적용 / 명시적 0            기본값
  로딩 중 / 실패

[실패 지점별]
  update 병합   "비어 있으면 무시" ── 빈 새 값 무시 → 옛 값 stale
  로드          parse 실패 → null → "부재" 경로 → 레거시 마이그레이션 → 옛 데이터 부활
  역직렬화      필수 필드 누락 → default [] → 빈 정상 메시지 → 커서 전진 → 영구 소실
  설정          0 == 미설정 → 기본값 → 명시한 "엄격"이 조용히 완화
  보안 판정     형식 오류 → 0 → 검사 스킵 → 통과 (fail-open)
  UI            초기값 [] / catch → [] → "0건" 표시 (로딩·실패 구분 불가)
  DB            NULL 만 검사 → "" 행 누락

[교정]
  상태를 타입으로 구분:  부재 | 손상 | 모르는 버전 | 값
                         Option/포인터로 미설정 vs 명시 0
                         (value, malformed) 반환
                         status = loading | done | error
  필수는 필수로: 생산자가 항상 쓰는 필드는 소비자도 필수 → 누락 = 오류(커서 미전진)
  default 는 생산자가 실제로 생략하는 필드에만
  "없음" 표현은 하나로 정규화 (NULL 로 통일)
```

## 핵심 문장

- "없음·비어 있음·손상·기본값·로딩 중·실패"는 **서로 다른 상태**다 — 같은 값(null·[]·0·"")으로 뭉개면 결함이 정상 데이터로 위장된다.
- 컬렉션 교체 의미에서 **빈 컬렉션은 유효한 새 값**이다. "비어 있으면 무시"는 absent와 empty의 혼동.
- 로드 경로는 **부재 / 손상 / 모르는 버전**을 분기한다. 손상·미지 버전은 보수적 기본값으로, 옛 데이터 부활 경로로 떨어뜨리지 않는다.
- 생산자가 항상 쓰는 필드는 **소비자도 필수**로 받는다. `default`는 생산자가 실제로 생략하는 필드에만 — 그래야 "못 읽었다"가 "0이라고 했다"로 둔갑하지 않는다.
- 미설정과 명시적 0은 **포인터/Option**으로 구분한다. 보안 판정에서 형식 오류는 **거절**이다.
- UI는 최소 `loading | done | error`를 구분하고, 건수·요약은 done일 때만 보인다.
