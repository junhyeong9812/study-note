# cs/issue/data/byte-stream-framing — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
바이트 스트림:  ... {"a":1}\n{"b":"한 ── 글"}\n ESC[3 ── 1m ...
                              ▲ read 경계        ▲ 청크 경계
                  read·청크 경계는 줄·문자·ESC 시퀀스 경계와 무관

[실패 지점]
  조각 파싱             → 레코드 통째로 유실
  청크 단위 UTF-8 디코드 → 문자 깨짐
  "창 첫 줄은 잘림" 가정 → 창이 줄 경계와 일치하면 온전한 줄 폐기
  truncate/재생성 무시  → 오프셋이 파일보다 큼
  상한 드롭을 스트림 중간에서 → ESC 시퀀스 중간 절단 → 이후 해석 전체 오염
  절단본을 스냅샷에 저장 → 재열기해도 손상 고정
  동기 reset + 비동기 write 큐 → FIFO 역전

[교정 — 완성된 프레임만 디코드, 절단도 프레임 경계에서]
  tail:   offset 이후 새 바이트 → buf 에 append
          '\n' 까지 완성된 줄만 디코드, 미완성 꼬리는 buf 보관
          file_len < offset → offset·buf 리셋
  UTF-8:  '\n'(0x0A)은 continuation 바이트(10xxxxxx)가 될 수 없음 → 줄 경계 = 문자 경계
          스트림 디코딩은 상태를 가진 쪽(수신 측 스트리밍 디코더)에 위임 → binary 프레임
  창:     창 직전 바이트가 '\n' 이면 첫 줄 보존
  상한:   raw 바이트 링버퍼, 앞에서부터 드롭 (선두 절단은 수신기가 흡수)
          중간 드롭이 생기면 신호 → 재스냅샷 + 초기화 후 재도장
          초기화도 같은 write 큐로 보냄 (FIFO)
```

## 핵심 문장

- 스트림·파일 읽기 경계는 **줄·문자·이스케이프 시퀀스 경계와 무관**하다.
- **완성된 프레임만** 디코드하고 미완성 꼬리는 버퍼에 남긴다. `\n`은 UTF-8 continuation 바이트가 될 수 없어 줄 경계 = 문자 경계.
- 멀티바이트 디코딩은 **스트림 상태를 가진 쪽**이 한다 — 청크를 문자열로 바꿔 보내지 말고 바이트로 보낸다.
- 상한 절단도 **프레임 경계**에서 — 앞에서부터 드롭하고, 중간이 잘렸으면 신호를 내 재동기한다. 절단본을 영속화하지 않는다.
- 동기 조작과 비동기 큐를 섞지 말고, 초기화 명령도 **같은 큐**로 보낸다.
