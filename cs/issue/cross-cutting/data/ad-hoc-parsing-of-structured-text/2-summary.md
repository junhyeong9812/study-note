# cs/issue/data/ad-hoc-parsing-of-structured-text — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[상태가 있는 문법]  "지금 어느 문맥 안인가"에 따라 같은 문자의 의미가 바뀜
   코드   /*  → 블록 주석 시작
   // …  /*  → 그냥 텍스트 (라인 주석 안)
   "…/*…"    → 그냥 텍스트 (문자열 안)
   { … "}" … } → 문자열 안 } 는 균형에 안 셈
   ( ( … ) )   → 중첩 깊이

[ad-hoc 파싱]  정규식 / 양끝 슬라이스 / 한 번씩 순서대로 벗기기
      │  문맥을 모름
      ▼
   과대 매칭:  주석 시작 오인 → 문서 잔여 전체 마스킹
               first{ ~ last} → 뒤 산문의 } 포함
               비탐욕 </div></div> → 다음 블록까지 삼킴
               넓은 prefix → 인접 목록 흡수
   과소 매칭:  틀린 이름·패턴 → 0건
               중첩 구분자 → 안쪽 층 잔존
               주석 행까지 매칭 → 옛 설정이 "첫 매칭"
      │
      ▼  예외 없음 — 행수·출력만 이상 (silent)

[교정]
   상태 기계 스캐너 (code | line | block | str | chr), 길이 보존 마스킹
   문자열 추적 포함 balanced 스캔 / 실파서(YAML·JSON)
   중첩 구분자는 깊이 추적 + 고정점까지 반복, 정규화 함수 단일화
   재귀 파서 + EOF 검사 + 불균형 시 명시적 degrade
   변환 뒤 검증: 매치 개수 assert · 조각 침범 검사 · 행수/지표 비교 · 샘플 대조
```

## 핵심 문장

- 주석·문자열·중첩 괄호는 **문맥(상태)에 의존하는 문법**이라 부분 패턴 검색·양끝 슬라이스로 경계를 잡을 수 없다(주석·문자열은 입력 전체를 순차 토큰화하는 lexer로는 가능하지만, 중첩 괄호는 정규식으로 원리적으로 불가).
- 틀린 정규식은 **예외 없이** 과대·과소 매칭한다 — 결과가 "그럴듯하게 틀린" 텍스트로 나온다.
- 해법은 **상태 기계 스캐너**나 **실파서**. 마스킹은 길이를 보존하면 오프셋을 원본에 그대로 쓸 수 있다.
- 중첩 구분자는 **깊이를 추적**해 짝이 맞을 때만, **변화가 없을 때까지** 벗긴다. 같은 정규화는 한 함수로 모든 경로가 공유한다.
- 정규식 변환을 쓸 수밖에 없다면 **매치 개수 assert·조각 침범 검사·결과 지표 비교**로 무음 오작동을 드러낸다.
