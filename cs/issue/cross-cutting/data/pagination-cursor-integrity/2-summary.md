# cs/issue/data/pagination-cursor-integrity — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
페이징 = 하나의 "집합"을 여러 요청으로 나눠 전달
 불변식:  page1 ∪ page2 ∪ ... = 전체  (빠짐·중복 없음)  +  "끝" 신호는 참이어야 함

[실패 1] 이어받기가 다른 집합을 가리킴
   page1 = log(--all)            모든 브랜치
   page2 = log(<마지막 해시>)     그 커밋의 조상만   → 다른 브랜치 도달 불가
   결과: 708 중 279 도달, 마지막 페이지 truncated=false

[실패 2] 커서가 "넘겨준 구간이 그대로인가"를 일부만 검사
   cursor = offset + tip 검사      branch -D (tip 불변) → 구간 길이 변화 통과 → 무음 유실
   cursor = offset + seam 검사     같은 초 커밋 재정렬(seam 제자리) → 못 잡음
   cursor = offset + tip + seam    양 끝 검사, 내부(1..offset-2)는 안 봄 → 잔여 창은 계약에 명시

[실패 3] 종료 판정을 필터 뒤 개수로
   scan(id > last, limit n) → filter(삭제분 제거) → 결과 < n → "끝"  ✗ (조기 종료)

[실패 4] "더 있음"을 두 신호의 OR 로
   truncated(생산자: 상한만큼 읽음) OR count<total → 마지막 페이지에서 가짜 "더 보기" → 빈 결과

[교정]
   모든 페이지가 같은 집합 쿼리를 읽고 커서는 "위치"만
   커서 검증 불일치 → 명시적 에러 (조용히 이어붙이지 않음)
   전진·종료는 "스캔한 키 윈도우"(마지막 스캔 키·스캔 건수)
   개수를 정본, 플래그는 개수가 모순일 때만 보는 백스톱
   픽스처: 미머지 브랜치 2개 · oracle: rev-list --all --count 대조
```

## 핵심 문장

- 이어받기 쿼리는 **첫 쿼리와 같은 집합**을 가리켜야 한다. 커서는 위치만 바꾼다.
- 오프셋 커서는 "이미 넘겨준 구간이 그대로인가"를 검사하지 않으면 삭제·삽입·재정렬을 **무음으로 흡수**한다.
- 검사 지점을 늘려도 완전 보장이 아니면 남은 창을 **계약에 조건부 보장으로 명시**한다.
- 커서 페이징의 전진·종료는 **스캔한 키 윈도우**에서 나와야 한다 — 그 뒤 필터 결과 수가 아니라.
- 두 신호를 OR 로 묶지 마라 — 의미가 다른 신호는 **정본 하나 + 모순 시 백스톱**.
- 가장 나쁜 실패는 유실이 아니라 **"전부다"라고 말하는 유실**이다.
- 무음 유실을 고칠 때 흔한 실패는 **같은 얼굴의 새 무음 유실**을 만드는 것 — "내가 새로 쓴 보장을 깨는 방법은 몇 가지인가"를 묻는다.
