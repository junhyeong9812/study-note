## 질문
1. 커밋 그래프(DAG)를 페이지로 나눠 받는다. 첫 페이지는 "모든 브랜치"로, 이어받기는 "직전 페이지 마지막 커밋의 조상"으로 조회했다. 왜 다른 브랜치 커밋이 2페이지부터 통째로 사라지는가 — 이 결함을 한 문장 원리로 말하라.
2. 위 결함이 있는데도 마지막 페이지 응답은 `truncated=false`(잘린 것 없음)였다. 왜 이것이 단순 누락보다 더 나쁜가.
3. 예측: 커서를 "전체 목록 + offset"으로 바꾸고, 첫 원소(tip)가 그대로인지 검사해 변경을 감지하게 했다. 이미 넘겨준 구간에서 브랜치 하나가 삭제됐는데 tip 은 그대로다. 다음 페이지에서 무슨 일이 일어나는가.
4. 커서에 tip 과 seam(직전 페이지 마지막 원소)을 **둘 다** 싣는 이유는? seam 만 검사하면 안 되는 이유를, 같은 초 타임스탬프 커밋의 재정렬로 설명하라. 그리고 두 끝을 검사해도 남는 잔여 창은 무엇이며 어떻게 다뤄야 하나.
5. keyset 페이징(`WHERE id > :last ORDER BY id LIMIT :n`) 뒤에 삭제 필터를 적용하고 "결과가 n 개보다 적으면 끝"으로 판정했다. 어떤 데이터에서 조기 종료가 나며, 전진·종료 판정은 무엇에서 나와야 하나.
6. 경계: "더 있음"을 판정하는 신호로 생산자의 `truncated` 플래그와 개수(`from + received < total`)를 OR 로 묶었다. 생산자가 "상한만큼 읽었음"의 의미로 플래그를 켜면 소비자 화면에서 무엇이 보이는가. 어느 신호를 정본으로 둬야 하나.
7. 연결: 단일 브랜치 9커밋 테스트 픽스처로는 1번 결함이 왜 **구조적으로** 재현되지 않는가. 페이징 테스트의 픽스처와 대조 기준(oracle)은 어떻게 골라야 하나.
