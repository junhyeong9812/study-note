# cs/issue/data/time-semantics — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
시간 값 = 숫자 + (시계 도메인 · 타임존 · 해상도 · 구간 규칙)
          ─────   ─────────────────────────────────────────
          보이는 것          빠지면 조용히 틀리는 것

[타임존]
  UTC 타임스탬프 앞 10자 → "날짜"          로컬 자정과 경계가 어긋남 (KST 오전 = UTC 전날)
  TZ 없는 ISO 문자열 → 도구가 로컬로 해석   UTC 로그 구간과 9시간 어긋남 → 빈 결과

[벽시계 ≠ 단조 ID]
  초 단위 이름                             같은 초 연속 작업 → 이름 충돌
  초 단위 키 + 접미사 상한(_2)              동시 3건 → 덮어쓰기
  "새 것 = 최대 timestamp" 가정의 prune     시계 역행·미래 ref·동일 값 → 방금 만든 백업 삭제 + Ok 반환

[서로 다른 시계]
  client.updatedAt vs server.now()  LWW    도메인이 다른 시계 비교 → 오프라인 편집 무음 유실
  upsert 와 커서 전진이 따로                부분 적용 후 커서만 전진 → 재시도가 건너뜀

[구간]
  BETWEEN from AND to (닫힌 구간)          경계 00:00 이 양쪽 버킷에 중복

[교정]
  로컬 날짜는 로컬 타임존 API 로 · 수용한 UTC 경계는 기록
  TZ 접미사(Z) 강제
  유일성 = 추가 엔트로피(나노초+커밋 해시 / UUID) · "새 것 보존" = 명시적 protect
  같은 시계 도메인끼리만 비교 · 데이터+커서 한 트랜잭션(커서 마지막)
  반열린 구간 [from, toExclusive)
```

## 핵심 문장

- 날짜는 **타임존의 함수**다. UTC 를 잘라 날짜로 쓰면 로컬 사용자에겐 다른 날이다.
- 타임존 없는 타임스탬프 문자열은 **도구마다 해석이 다르다** — 경계를 넘는 값에는 `Z`/오프셋을 붙인다.
- 벽시계는 **단조 증가 ID 가 아니다**(역행·해상도·외부 조작). 유일성은 엔트로피로, "새 것 보존"은 정렬 가정이 아니라 **명시적 보호**로.
- LWW 는 **같은 시계 도메인** 타임스탬프끼리만 의미가 있다.
- 커서와 데이터 반영은 **원자적**이어야 재시도가 건너뛰지 않는다.
- 연속 시간 축은 **반열린 구간** `[from, toExclusive)` 으로 나눈다.
