# cs/issue/data/time-semantics — 시간은 조용히 틀린다: 벽시계·타임존·구간 경계 — 질문

## 질문
1. "날짜"(캘린더 일)는 왜 타임존 없이는 정의되지 않는가. UTC ISO 타임스탬프의 앞 10자(`YYYY-MM-DD`)를 잘라 날짜 헤더로 쓰면, 한국 사용자에게 오전 8시에 일어난 일은 어느 날로 분류되는가.
2. 벽시계(system time)를 식별자나 "최신순" 기준으로 쓰면 안 되는 이유 세 가지(역행·해상도·외부 조작)를 들어라. "방금 만든 백업은 타임스탬프가 가장 크다"는 가정 위에 prune(오래된 것 삭제)을 짜면 어떤 최악의 결과가 나오는가.
3. 예측: 파일 키를 초 단위 타임스탬프로 만들고 충돌 시 `_2` 접미사까지만 붙인다. 같은 초에 동시 요청이 3건 오면 무슨 일이 생기는가. 근본 교정은?
4. 로그에 `2026-05-09T03:28:12Z` 줄이 분명히 있는데 `--since 2026-05-09T03:27:30 --until 2026-05-09T03:29:00` 조회가 빈 결과였다. 무엇이 어긋났나 — 이 빈 결과가 사고 조사에서 왜 위험한가.
5. 오프라인 편집 동기화를 Last-Writer-Wins 로 한다. 클라이언트의 `updatedAt` 과 서버의 `now()` 를 비교하면 왜 편집이 조용히 유실되나. 그리고 "데이터 반영"과 "동기화 커서 전진"이 한 트랜잭션이 아니면 재시도 때 무엇이 빠지나.
6. 경계: 일별 집계를 `BETWEEN from AND to` 로 나누면 익일 00:00:00 인 행은 어느 버킷에 들어가는가. 인접 구간을 겹치지 않게 나누는 표준 형태는?
7. 연결: 위 여섯 사례의 공통점은 "에러 없이 조용히 틀린다"이다. 시간 값을 다룰 때 **값과 함께 반드시 붙어 다녀야 하는 정보**는 무엇인가(시계 도메인·타임존·해상도·구간 열림/닫힘).
