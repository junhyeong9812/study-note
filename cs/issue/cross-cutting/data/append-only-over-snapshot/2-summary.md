# cs/issue/data/append-only-over-snapshot — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[스냅샷 복사 — 시간축 없는 현재값에서 과거 시점 값을 만든다]
   current_value ──(언제 복사?)──▶ value_at(D)
       ① 배치 복사: 마감 후 창에 D+1 거래가 섞임
       ② 단일 필드: 하루 어긋남
       ③ 행 + 현재값 복사: 늦게 도착한 D-1 거래 → 이미 복사된 D에 역순 귀속 오류
   → 같은 자리 3회 실패 = 토대가 틀림 (다듬지 말고 설계를 되돌린다)

[append-only 이동 기록]
   movement(id, key, 귀속일, Δ)   ← 절대 수정하지 않고 쌓기만
   value_at(D) = Σ Δ  where 귀속일 ≤ D
   → 도착 순서·재전송·늦은 도착과 무관 (합은 교환·결합 가능 = 구성적)

[재전송되는 원천]
   원천이 배치마다 전량 이력 재전송 → 적재 행 = 고유 키 × 배율
   판정: 적재 단위 키가 UNIQUE 인데 배치 수 > 1 → 재처리 아님, 원천 누적
         다른 테이블도 같은 배율인가 교차 확인
   소비 단계: key 별 MAX(version) 선택 (dedup)
   완료 판정식 선고정: 소비처 문서 수 ≈ COUNT(DISTINCT key)
```

## 핵심 문장

- 시간축 없는 현재값을 **복사**해 과거 시점 값을 만들면, 복사 시각·대상·값 중 하나가 **늦게 도착한 이벤트**에 의해 반드시 틀어진다.
- **append-only 이동 기록 + 귀속일**을 쌓고 소비 단계에서 합산하면 순서·재전송에 무관하게 **구성적**이다.
- 원천이 전량을 재전송하면 적재 배율이 생긴다 — 버그로 단정하지 말고 **반증적으로 판정**한 뒤, 소비 단계에서 **최신 버전 선택**으로 흡수한다.
- 같은 자리를 세 번 고쳐도 깨지면 **설계를 되돌린다** — 소급 보정(Δ 전파) 같은 패치는 틀린 토대 위의 덧칠이다.
