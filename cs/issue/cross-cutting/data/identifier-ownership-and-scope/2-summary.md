# cs/issue/data/identifier-ownership-and-scope — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
키가 되려면 두 가지가 정해져야 한다
   (1) 유일 범위(namespace)   — 어디 안에서 유일한가
   (2) 정본·발급 주체          — 누가 만들고, 어느 사본이 진짜인가

[실패 1] 외부 규칙을 "예측"        slug(cwd) + id 로 경로 조립 → 규칙이 다르면 빈 경로 (조용히)
          교정: 우리가 발급한 전역 유니크 id로 "탐색" / 없으면 None → 재시도

[실패 2] 키를 줄이거나 채움        "?" placeholder · 짧은 해시 · uuid 앞 8자
          → 단사(injective) 붕괴 → 서로 다른 대상이 같은 키 → 덮어씀·병합·무음 삭제
          교정: 구성 요소 없으면 항목 생략 / 가역 인코딩 / 판별 키는 전체 id

[실패 3] 스코프 누락               commit-hash (repo 여럿) · depth:name (트리) · "collector" (인스턴스 여럿)
                                   path#heading (한 절 = 여러 청크)
          교정: 키에 네임스페이스 포함  cwd:hash · 누적 경로 · agent_name · path#chunk_no

[실패 4] 결정적 상관 키 없는 추론   cwd + 시각 창으로 남의 산출물 역매칭
          "표식 없음" = ①미지원 ②아직 미생성 (정상 구간)  → 폴백이 ②에서 남의 것을 잡음
          교정: 표식(마커) 단독 매칭 · 폴백 삭제 · 후보 정확히 1개일 때만 · 경합이면 아무에게도 안 줌

[다른 방안]
   발급자별 키 공간 분할 (오프셋·접두) · 병행 스택의 이름공간 분리 (프로젝트·서비스·포트)
   키를 실제 소유 단위로 (세션 id · 축(방향)별 영속 키 · 안정 id/order)
   용도별 키 분리 (표시용 축약 ↔ 파괴 연산 판별) · 연산 안 하는 식별자는 문자열로
```

## 핵심 문장

- 식별자는 **그것이 유일한 범위 안에서만** 키다 — 컨텍스트가 여럿이 되는 순간 범위를 키에 넣어야 한다.
- 외부 규칙을 재구현해 **예측**하지 말고, 우리가 **발급**한 id로 **탐색**한다.
- placeholder·해시·축약은 **단사성**을 잃는다 → 판별 키로 쓰면 낮은 확률의 무음 파괴.
- 같은 id가 두 곳에 있으면 **정본을 하나로** 정하고 다른 쪽을 정규화한다.
- "신호 없음"을 폴백 조건으로 쓰면 **정상적인 "아직 없음"** 과 구분하지 못한다 → 추측하지 말고 가시적으로 강등.
- 두 발급자가 한 키 공간을 쓰면 **범위 분할·접두로 충돌을 구조적으로 불가능하게**.
