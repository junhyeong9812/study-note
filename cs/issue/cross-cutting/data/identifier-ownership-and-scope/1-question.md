## 질문
1. 외부 CLI가 남기는 상태 파일 경로를 "작업 디렉터리를 `-`로 치환한 slug + id" 규칙으로 **예측**해 조립하던 코드를, 우리가 만든 uuid를 넘기고 **탐색**하는 방식으로 바꿨다. 예측 방식은 규칙이 조금만 달라도 어떻게 실패하며, 왜 그 실패가 조용한가.
2. 합성 키 `think:<record_id>:<idx>`에서 record_id가 없을 때 `"?"`로 채우면 무엇이 일어나는가. 상수 placeholder·짧은 해시·앞 8자 축약이 공통으로 깨뜨리는 성질은 무엇인가.
3. 예측: 두 git 저장소를 동시에 보여 주는 화면에서 diff 캐시 키가 `diff:<commit-hash>`이다. 어떤 상황에서 다른 저장소의 diff가 떠오르는가. 트리 UI의 key가 `depth:name`이면?
4. 같은 엔티티의 id가 파일명과 본문 두 곳에 있을 때 무엇을 정본으로 삼아야 하는가. 정하지 않으면 어떤 입력이 정체성 혼동을 만드는가.
5. 세션 id를 지정할 수 없는 도구의 산출 파일을 "같은 cwd + 스폰 시각 창"으로 역매칭했다. "표식이 없으면 옛 규칙으로 폴백"이 결함이었던 이유는 "표식 없음"의 두 가지 의미에 있다 — 두 의미는 무엇인가.
6. 경계: 사용자가 복사할 수 있는 파일 안에 세션 uuid 마커를 두면 유일성이 왜 깨지는가. 마커 파싱은 어떤 조건을 모두 만족해야 "식별자"로 인정할 수 있는가.
7. 연결: 두 발급자(로컬 레지스트리·원격 브리지, 앱 채번기·마이그레이션 정적 시드)가 같은 키 공간에 값을 낼 때 충돌을 "확률적으로 드묾"이 아니라 "구조적으로 불가능"하게 만드는 방법은 무엇인가. JS로 넘어가는 정수에는 어떤 추가 제약이 있는가.
