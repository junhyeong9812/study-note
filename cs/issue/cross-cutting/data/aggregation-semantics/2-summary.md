# cs/issue/data/aggregation-semantics — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[값의 의미]
   누적(counter)   여러 관측의 합        → 합산해도 됨, "지금 크기"가 아님
   게이지(gauge)   마지막 관측 스냅샷    → 최신값으로 overwrite, 합산하면 안 됨
   DISTINCT        집합 크기            → 부분 집합 크기의 합 ≠ 전체 집합 크기

[틀린 집계 → 오류 없이 그럴듯한 수치]
   게이지 = Σ(턴 내 입력)              → 툴 왕복마다 부풀어 100% 초과
   분모 모름 → 기본값 200k              → 틀린 %가 정상처럼 표시
   합계 = Σ 버킷 COUNT(DISTINCT)        → 겹치는 원소 중복 → 과대
   "전체" = lastValue(연도별)           → 최신 연도만 → 과소
   누적 로그 + 단건 로그 같은 패턴      → 덮어쓰기 파서에 마지막 줄이 이김 → 고정·깜빡임

[교정]
   게이지: 최신 1건 overwrite, 점유 = 마지막 관측의 구성요소 합, min(100, 점유/용량)
   분모 모름 → 숨김 (거짓 수치보다 무표시)
   합계 DISTINCT: 원 데이터에서 전체 기간 별도 DISTINCT
   차원 "전체": 차원 의미에 맞는 함수(sum)
   누적은 생산자(메인)가 소유, 로그 포맷 통일, 파서는 지정 라인에서만 읽음
   기간: [from, to+1일) 반열린 구간 + 타임존 명시
```

## 핵심 문장

- 집계는 **값의 의미**(누적 vs 게이지, 집합 크기, 차원)에 맞는 함수를 써야 한다 — 틀려도 오류 없이 그럴듯한 수치가 나온다.
- 게이지는 **마지막 관측으로 덮어쓰고**, 누적은 더한다. 둘을 섞으면 100%를 넘는 게이지가 나온다.
- 분모를 모르면 기본값으로 그리지 말고 **숨긴다** — 거짓 수치는 눈에 띄지 않는다.
- `COUNT(DISTINCT)`는 **가산적이지 않다** — 합계는 원 데이터에서 별도 DISTINCT로.
- 누적은 **생산자가 소유**한다. 같은 텍스트 패턴에 서로 다른 의미를 싣고 파서가 덮어쓰면 마지막 줄이 이긴다.
