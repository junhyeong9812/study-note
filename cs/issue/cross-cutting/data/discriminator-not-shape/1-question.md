## 질문
1. 대화 로그의 레코드를 "content가 문자열이면 사용자 프롬프트"처럼 **모양**으로 분기하면 어떤 레코드가 오분류되는가. "user 레코드 = 프롬프트"라는 단순화는 왜 거짓인가.
2. 판별자(role·type)로 해석한다는 것은 구체적으로 무엇을 먼저 확인한다는 뜻인가. 판별자가 두 위치(중첩 필드·최상위 필드)에 있을 수 있으면 어떻게 읽는가.
3. 예측: 같은 대화를 "사용자에게 보이는 이벤트 층"과 "모델 입력 층"으로 이중 기록하는 로그에서 모델 입력 층만 읽어 화면을 만들면, 시스템이 주입한 컨텍스트는 어떻게 보이는가.
4. 판별 유니온(discriminated union) 스키마에서 판별자 필드(`type`)를 빠뜨리면 검증기는 왜 어느 분기로도 통과시키지 못하는가. 모양만 보고 추론하는 스키마와 무엇이 다른가.
5. 경계: 해석할 수 없는 레코드(암호화된 추론 내용, 모르는 종류)를 만났을 때, 모양이 비슷하다는 이유로 가장 가까운 종류로 보여 주는 것과 건너뛰고 세는 것 중 무엇이 맞는가.
