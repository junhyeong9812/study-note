# cs/issue/gui-platform/coordinate-space-consistency — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[사례 1: 혼합 DPI 멀티모니터 드롭]

 이벤트 좌표 screenX  = 소스 문서의 논리(CSS) px   (모니터마다 원점·배율 다름)
 창 bounds            = OS 물리 px(이 셸 API 기준)    (전역 하나 — Windows류 기준)

 1차: 물리 = screenX × 소스scale      ← 소스 모니터 기준, 경계 넘으면 틀림
 2차: bounds ÷ scale 로 논리에서 비교  ← 여전히 "소스 scale" 가정
 최종: 모든 hit-test = 물리 px 한 공간
       드롭 좌표 = OS 전역 커서 위치(물리)  (screenX×scale은 실패 시 fallback)
       배치만 논리로 환산 (창 생성 API가 논리 좌표를 받으므로)

[사례 2: 3D 좌표 부호 반전]

 x = -r·sin(φ)·cos(θ)
   └▶ winding 뒤집힘 → 법선 안쪽 → 앞면 컬링 시 정면 안 보임
   └▶ UV · 가시영역(atan2) · 라벨 투영도 각자 "보상"
 부분 수정 5종(winding·UV·부호 제거·차폐구·BackSide) → 전부 다른 곳 보상과 충돌
 채택: 구조 교체(타일 시스템 제거 → 단일 구면 + 단일 텍스처)

 원리: 좌표계는 하나로 통일한 뒤, 경계에서만 한 번 변환
```

## 핵심 문장
- 논리 px는 모니터마다 원점·배율이 달라 **전역 좌표계가 아니다**(물리 px가 전역인 플랫폼 기준 — macOS는 전역 좌표가 point) — 여러 모니터를 가로지르는 판정은 OS가 전역으로 주는 한 단위로 한다.
- "소스 scale을 곱한다"는 환산은 드래그가 모니터 경계를 넘는 순간 틀린다.
- 좌표는 **한 공간으로 통일**하고, 다른 단위를 요구하는 API 경계(창 배치)에서만 변환한다.
- 좌표 부호 반전은 winding·법선·UV·가시영역에 전부 전파된다 — 곳곳의 보상이 얽히면 한 곳 보정이 다른 곳을 깬다.
- 같은 결함을 여러 번 부분 수정해도 계속 깨지면 토대(좌표 규약)를 바꾸는 구조 교체가 다음 수다.
