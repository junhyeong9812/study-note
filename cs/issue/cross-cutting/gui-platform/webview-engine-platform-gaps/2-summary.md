# cs/issue/gui-platform/webview-engine-platform-gaps — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
사용자 드래그 ──▶ OS/네이티브 셸 ──▶ 웹뷰 엔진 ──▶ DOM 이벤트 ──▶ 앱 코드
                     │                 │                │
          [가로채기] 셸 기본값이      [승격 조건]     [문서 경계]
          파일 DnD를 먼저 잡음       dataTransfer    이벤트는 시작 문서 안에서만
          → DOM DnD 삼킴             비면 드래그 X   → 다른 창은 dragover 0
          (창 단위 택일)                             dragend 좌표 (0,0)/NaN 가능
                                                     (관측 엔진 기준 — 일반 브라우저는 창 간 전달)

[교정]
  셸 가로채기 끔(창 단위)  + dragstart에서 setData 호출
  파일 드롭이 필요하면 → 그 기능만 켠 보조 창을 따로 연다
  메인 영역은 Files 타입 드래그만 preventDefault (웹뷰 navigate 차단)
  다른 창 미리보기 → 소스가 판정해 IPC로 "지금 너 위" 알림(변경 시만)
  좌표는 유한값·(0,0) 검사 + 추적한 마지막 유효점으로 대체

[API 부재]
  창 목록 순서 ≠ z-order, 이식 가능한 z-order 조회 없음
  → 휴리스틱: focus 최근성(공유 순서) → 동률이면 작은 면적, 숨김·최소화 제외
  PDF iframe 미지원 → JS PDF 렌더러로 canvas 렌더
  바이너리를 텍스트 경로로 → 확장자 판별로 읽기 전 차단
```

## 핵심 문장
- 데스크톱 웹뷰 엔진은 크롬이 아니다 — DnD·내장 뷰어·창 API는 **대상 엔진에서 실측**한다.
- 네이티브 셸은 기본값으로 파일 드롭을 가로채 DOM 드래그를 삼킬 수 있고, 일부 엔진은 `dataTransfer`가 채워져야 드래그를 시작한다.
- 대상 엔진에서 드래그 이벤트가 **시작한 문서 밖으로 흐르지 않으면**(관측) 창 간 피드백은 별도 채널(IPC)로 만든다 — 일반 브라우저의 창 간 DnD를 가정하지 않는다.
- 목록 순서는 z-order가 아니다 — 조회 API가 없으면 관측 가능한 신호(focus 순서)로 근사하고 그 한계를 적는다.
- 크롬에서 되던 내장 기능(PDF iframe)은 엔진 무관한 라이브러리 렌더로 대체한다.
