## 질문
1. "삭제" 요청이 대상 프로젝트를 요청에 싣지 않고, 처리 시점에 전역 `activeProject`에서 유추한다. 사용자가 다른 프로젝트의 세션을 다시 연 뒤 삭제하면 무슨 일이 생기는가 — 이것이 왜 동시성 문제인가(스레드가 하나여도).
2. 예측: 클릭 핸들러가 `await writeFile()` 뒤에 전역 "현재 프로젝트"를 읽어 모드를 켠다. await 도중 사용자가 프로젝트를 바꾸면? "캡처값 == 현재값"을 dispatch 직전에 재검증하는 이유는 무엇인가.
3. 디바운스·타이머 같은 지연 지점은 트리거 시점과 실행 시점을 분리한다. "복원된 과거 데이터(snapshot)냐 새 이벤트(live)냐" 같은 출처 메타데이터를 실행 시점의 공유 변수에서 읽으면 어떤 오동작이 나는가.
4. 메시지 목적지를 발행 시점의 "현재 활성 대상"으로 정하고, 활성 대상이 바뀌는 전이마다 정규화를 덧붙였더니 5라운드 연속 새 구멍이 났다. 왜 전이별 보정으로는 끝나지 않는가. 결국 무엇으로 바꿨는가(동적 vs 렉시컬 바인딩).
5. 이벤트를 "현재 turn"이라는 가변 전역값으로 분류하면, 완료 이벤트와 업데이트가 거의 동시에 도착할 때 무엇이 틀어지는가. 귀속 키는 어디에 있어야 하는가.
6. 경계: 프로토콜 메시지에 상관 키가 아예 없으면(예: 쓰기 요청에 경로만 있음) 어떤 근사 상관밖에 할 수 없고, 그 한계는 무엇인가.
7. 연결: 같은 원리를 다른 방식으로 푼 세 해법 — (a) 이름을 한 번 불변 해시로 해석해 그 값으로 검증·실행 + CAS (b) 인스턴스 속성 대신 인자로 문맥 전달 (c) 비동기 제출 시점에 컬렉션 복사본 전달 + in-flight 상한 — 각각 무엇을 "요청 시점 값"으로 고정하는가.
