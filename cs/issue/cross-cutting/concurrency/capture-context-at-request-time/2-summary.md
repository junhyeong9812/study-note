# cs/issue/concurrency/capture-context-at-request-time — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[요청이 겪는 일]
  발행 (t0)                  대기 창                          실행 (t1)
  req = { op }  ──────▶  await / debounce / 큐 / 렌더  ──────▶  target = GLOBAL.current  ✗
                          │ 이 사이에 GLOBAL.current 변경:
                          │  프로젝트 전환 · 활성 패널 전환 · 오버레이 · 마운트/언마운트
                          │  · 새 live 이벤트 도착 · 다음 turn 시작
                          ▼
                     실행 대상/출처/귀속이 t1의 값으로 오염
                       → 엉뚱한 대상 삭제 · 다른 디렉터리에서 실행
                       → 복원 데이터가 "새 사건"으로 알림 · 요청 무음 유실

[교정]  t0 에 값으로 캡처해 메시지와 함께 운반
  req = { op, project, cwd, origin, turn, surfaceId }     ← 요청 자체가 문맥을 들고 감
  실행: target = req.project                              ← 전역 재조회 없음
  위험한 전이는: dispatch 직전 "req.project == current" 재검증, 불일치면 저장만+안내

[같은 원리의 다른 방안]
  이름 → 불변 해시 1회 해석 → 그 값으로 검증·실행 → CAS 반영
  인스턴스 속성으로 문맥 전달 → 인자로 전달 (호출 순서 계약 제거)
  가변 컬렉션 참조 넘김 → 제출 시점 복사본 + in-flight 상한
```

## 핵심 문장

- 대상·출처·귀속을 **실행 시점의 전역 "현재"**에서 다시 읽으면, 발행~실행 사이의 모든 상태 변화가 경합 창이 된다(await 하나면 단일 스레드에서도 발생).
- 요청을 만든 시점의 문맥을 **값으로 캡처해 메시지와 함께 운반**한다.
- 동적 앰비언트 값에 목적지를 묶고 전이마다 보정하면 **새 전이가 새 구멍**을 만든다 → 발행자의 렉시컬(컴파일 고정) 정체성으로 스탬프.
- 지연 지점(디바운스·타이머)은 트리거 시점 메타데이터를 **값으로** 넘겨야 한다.
- 이벤트 귀속 키는 전역 "현재"가 아니라 **이벤트 자체**에 있어야 한다.
