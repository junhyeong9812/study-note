# cs/issue/concurrency/aba-reusable-identifier — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[재사용되는 이름으로 수명 조작을 키잉]

  t0  spawn(id="S")        → handles["S"] = H1,  waiter1(id="S") 대기
  t1  S 종료               → waiter1 깨어남 ... (아직 정리 전)
  t2  spawn(id="S") 재사용  → handles["S"] = H2   ← 다음 세대
  t3  waiter1: handles.remove("S")                ← H2를 지움 (ABA)
        → 새 세션의 핸들 drop → 새 프로세스에 SIGHUP / 새 토큰 폐기 / 새 파일 삭제

  같은 모양:
    pid 재발급       kill(pid)          → 무관한 프로세스
    재시작 카운터    Kill("k1")         → 재기동 후의 다른 k1
    연결별 seq       seen[host] = 5     → 재접속 후 seq 1..5 "이미 봤음"
    txId 1부터       log: tx1(커밋됨)   → 새 tx1과 구별 불가 → 복구 오판

[교정 — 이름 대신 재사용 불가 키]
  key = 단조·불투명·0 거부 ("k<n>")          맵·토큰·파일명·이벤트·명령 주소 전부 key
  addr = "<epoch>:k<n>" 한 값                 epoch 불일치 → 거부 (fail-closed)
  pid  → (pid, start_time) 을 살아 있을 때 기록, 시그널 직전 재확인, 확인 불가 = 거부
  txId → 기동 시 로그에서 max(txId)+1 로 복원

  남는 것: 동시 spawn 상호배제(예약)는 키와 별개 — 예약=배제, 키=정체성
           이름 자체가 자원인 것(파일명=id)은 리스로 시간 분리
```

## 핵심 문장

- 재사용되는 이름으로 수명이 다른 자원을 지칭하면, **늦게 도착한 정리·발행이 같은 이름의 다음 세대**를 건드린다(ABA).
- 정리 경로마다 세대 비교를 덧붙이면 **잊은 자리가 다음 버그**가 된다 → 주소 자체를 재사용 불가 키로 바꿔 비교를 잊을 자리를 없앤다.
- 인스턴스 안에서만 유일한 카운터는 **epoch과 한 값**으로 묶어야 한다. 옆 필드는 기본값·누락으로 빠진다.
- 신원을 확인할 수 없으면 **통과가 아니라 거부**. 모든 대체 경로에도 같은 검사.
- 영속 기록과 비교되는 단조 id는 **영속 상태에서 복원**해야 한다(메모리 카운터 리셋 금지).
- 키는 정체성, 예약은 상호배제 — 둘은 다른 문제다.
