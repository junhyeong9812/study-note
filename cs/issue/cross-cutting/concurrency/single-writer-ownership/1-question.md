## 질문
1. 두 writer가 락 없이 같은 파일(또는 행)을 "읽고 → 고치고 → 전체를 쓰기" 하면 왜 한쪽 갱신이 조용히 사라지는가. 이것이 예외도 로그도 없이 일어나는 이유는 무엇인가.
2. 예측: 150ms마다 문서 본문을 통째로 다시 쓰는 폴링 스레드가 있다. 다른 기능이 같은 문서에 필드 하나(이름·링크)를 추가해 저장하면 다음 tick 이후 무엇이 보이는가. "쓰기 직전에 기존 값을 읽어 보존"하는 1차 대응은 왜 충분하지 않은가.
3. 저장 단위를 writer별로 쪼개는 것(사이드카 파일·세션별 상태 파일)과, 같은 단위를 두고 락·신선 읽기로 직렬화하는 것은 어떻게 다른가. 전자가 "구조적으로" 덮어쓰기를 불가능하게 만든다는 말의 뜻은?
4. DB에서 `SELECT`로 읽고 앱에서 계산한 뒤 `UPDATE ... SET col = <계산값>` 하는 것과 `UPDATE ... SET col = col - ? WHERE col >= ?` 하는 것의 차이는 무엇인가. 두 번째에서 "영향 행 수 0"은 무슨 의미로 쓰이는가.
5. 경계: "존재 확인 후 삽입"·`MAX()+1` 채번·"조회 후 claim"은 모두 같은 구조다. insert 직전에 한 번 더 확인하는 것으로는 왜 닫히지 않는가(TOCTOU). 마지막 방어선으로 무엇을 둬야 하는가.
6. ORM이 변경되지 않은 컬럼까지 로드 시점 값으로 전부 UPDATE하면, 내가 건드리지 않은 컬럼에서 왜 lost update가 나는가.
7. 연결: 같은 이벤트에 반응하는 두 핸들러가 같은 상태를 반대로 조작하는 문제, 여러 프로세스가 같은 로그 파일에 `>>` append하는 문제는 lost update와 어떤 점에서 같은 뿌리인가.
