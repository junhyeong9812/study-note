# cs/issue/concurrency/single-slot-handoff-loss — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[용량 1 슬롯]
  producer A ── set(slot = a) ─┐
  producer B ── set(slot = b) ─┤  소비 전 덮어쓰기 (last-write-wins)
                               ▼
                         slot = b        a 는 흔적 없이 사라짐 → a를 기다리던 쪽 영구 대기

[소비 경로의 실패 지점]
  slot ──▶ consumer effect
            ├─ 소비자가 둘 (숨긴 레이어도 살아 있음)   → 엉뚱한 곳이 소비 / 이중 소비
            ├─ 준비 전 도착 + 재실행 조건에 "준비됨" 없음 → 영구 대기
            ├─ clear 후 부작용 실패                      → 재시도 근거 소실
            └─ 전달 경로 둘 + 스냅샷 소비               → 이중 전달

[파이프라인 전 구간]
  상류 FIFO 큐 ──(동기 연속 드레인)──▶ 하류 1칸 슬롯   → 여전히 마지막만 생존
  고침: 하류 점유 시 wait, 비면 1건씩 (페이싱)

[교정 — 정확히 1회]
  응답 의무 요청 → 큐 / id별 맵
  생산자 여럿    → 생산자(표면)별 슬롯, 소유자 바뀌면 칸 비우기
  소비           → 소비자 단일화 · 행동 가능할 때만 · 성공(ACK) 후 clear · 준비 신호를 재실행 조건에
  중복 경로      → 항목 id + 최신 상태 재조회 + id로 멱등 제거
```

## 핵심 문장

- 용량 1 슬롯에 요청을 두면 동시·버스트 생산자가 서로를 **덮어 무음 유실**된다 — 응답 의무가 있는 요청은 큐나 id 맵에.
- 정확히 1회 = **소비자 단일화 + 행동 가능해진 뒤 소비 + 성공 후 clear + 준비 신호로 재실행**.
- 숨긴 것은 화면에서만 빠진다 — 마운트된 컴포넌트의 구독·effect는 계속 돈다.
- 무유실은 **파이프라인 전 구간의 계약** — 한 구간만 큐로 바꿔도 하류가 1칸이면 유실.
- 칸의 소유자가 바뀌면 칸을 비운다 — 실제로 무엇이 리마운트되는지 확인하라.
