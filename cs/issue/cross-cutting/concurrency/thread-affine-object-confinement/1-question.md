## 질문
1. "스레드에 묶인(thread-affine) 객체"란 무엇인가. 어떤 객체가 자기 I/O를 로컬 태스크(`spawn_local`)로 돌리면 왜 다른 스레드로 옮길 수 없게 되는가(`!Send`).
2. 예측: 임의 스레드에서 실행되는 요청 핸들러가 그런 연결 객체를 직접 들고 쓰려 하면 컴파일 단계와 런타임 단계에서 각각 무엇이 일어나는가.
3. actor 패턴은 이 문제를 어떻게 푸는가. 전용 스레드 + 단일 스레드 런타임 + 채널 구성에서 "외부에 노출되는 것"과 "안에 갇히는 것"을 구분해 보라.
4. asyncio `Queue`를 다른 이벤트 루프(또는 스레드)의 콜백에서 `put_nowait`로 직접 조작하면 왜 안전하지 않은가. 합법 진입점은 무엇인가.
5. 경계: 요청은 채널로 보내면 되지만, 응답(권한 확인처럼 호출자가 기다려야 하는 것)은 어떻게 돌려받는가. 채널 종류(동기 send 가능 여부)는 왜 신경 써야 하는가.
6. 연결: 이 원리는 "단일 writer 소유권"(lost update 방지)과 어떤 점에서 같은 생각인가. 테스트를 결정론적으로 만드는 데는 어떻게 이어지는가.
