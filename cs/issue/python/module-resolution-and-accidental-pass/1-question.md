## 질문

1. (왜) 똑같은 테스트 스위트가 `python -m pytest`로는 통과하고 `pytest`로는 import 에러로 죽었다. 두 실행 방식이 파이썬의 모듈 검색 경로(`sys.path`)에 각각 무엇을 다르게 넣기에 결과가 갈리는가?

2. (경계) "우연한 통과(accidental pass)"란 무엇인가? 코드가 옳아서가 아니라 **실행 환경이 우연히 틀을 맞춰줘서** 초록불이 되는 상황이 성립하려면 어떤 구조적 조건이 필요한가?

3. (예측) 로컬에서는 `python -m pytest`(초록불)로 개발했고, CI나 깨끗한 환경에서는 그냥 `pytest`를 돌린다고 하자. 무슨 일이 벌어지며, 왜 이 결함이 개발 중에는 안 보였는가?

4. (연결) 이 프로젝트는 두 곳을 함께 고쳤다 — 실행(런타임)에서 `uvicorn ... --app-dir src`, 테스트에서 `pyproject.toml`의 `pythonpath = ["src"]`. 서로 다른 두 설정이 사실 **같은 뿌리 문제**를 각자의 실행 경로에서 고정하는 것이다. 그 공통 뿌리는 무엇인가?

5. (왜) 빈 `conftest.py`를 테스트 폴더에 두면 import가 우연히 풀렸다 — 그래서 그것을 "임시방편"이라 불렀고, `pyproject.toml` 설정을 "정식 해법"이라 불렀다. 빈 conftest가 *부수효과로* 무엇을 했기에 통했고, 왜 그것이 정식 해법이 아닌가?

6. (경계) 이 문제를 두고 리뷰어 한쪽은 "문제다", 다른 쪽은 "문제 아니다"로 갈렸다. 이 프로젝트는 말싸움 대신 **conftest 없이 직접 pytest를 돌려 재현**하는 것으로 판정했다. 왜 "누가 맞나 따지기"보다 "직접 실행해 재현"이 옳은 판정 방식인가?

7. (연결) "실행 방식 차이로 초록불이 갈린다"는 더 큰 함정(성공 신호 ≠ 산출물, green 위장)의 한 사례다. 우연한 통과가 왜 silent failure(조용한 실패)의 친척인가? "테스트 통과 ≠ 검증 완료"와 어떻게 연결되는가?
