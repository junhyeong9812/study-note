# cs/issue/python/fastapi/response-normalization-framework-boundary — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

**한 문장:** 응답 계약(모든 응답을 같은 봉투로)은 **내 코드가 실행되는 범위**까지만 보장되고, 프레임워크가 내 핸들러 *밖에서* 만들어 내보내는 응답(입력 검증 실패·404·500)이 늘 그 계약의 구멍이므로, 그 경로를 **예외 핸들러로 되가로채** 같은 봉투로 정규화해야 계약이 완결된다.

요청이 라우터에 닿기까지 프레임워크가 먼저 처리하는 구간이 있다.

```
[요청] POST /rewrite  {"query": "no id"}   ← request_id 누락
   │
   ▼
┌─────────────────────────────────────────────┐
│ FastAPI 파이프라인 (내 코드 아님)              │
│  1. 라우팅 → 경로 없으면 404 (기본 모양)        │
│  2. pydantic 입력 검증 ──실패──▶ 422           │
│         RequestValidationError                 │
│         → {"detail":[{"type":"missing",...}]}  │  ← 봉투 없음! success 없음!
│  3. 검증 통과해야 ↓                             │
└───────────────────┬─────────────────────────┘
                    ▼
          내 라우터 함수 post_rewrite()
            try:  return ok(data)          ← 봉투 O
            except Busy: return fail(...)   ← 봉투 O
            (핸들러 안의 return만 봉투를 통과)
                    │
              미처리 예외 발생 시 ──▶ 500 (기본 모양)  ← 봉투 없음!
```

내가 봉투를 씌운 곳은 **3번 이후, 라우터 함수 안**뿐이다. 1·2번(그리고 미처리 500)은 프레임워크가 자기 형식으로 응답하므로 봉투가 새는 구멍이 된다.

**pydantic 검증 실패가 대표 구멍**인 이유: 검증은 라우터 함수 **진입 전**에 일어나고, 실패하면 FastAPI가 `RequestValidationError`를 잡아 `{"detail":[...]}`로 응답한다. 내가 함수 안에 써 둔 `try/except`는 한 줄도 실행되지 않는다 — 함수에 아예 못 들어왔기 때문이다.

**처방 = 그 경로를 되가로채기.** 전역 예외 핸들러로 프레임워크의 응답 지점을 다시 잡아 같은 봉투로 바꾼다.

```
@app.exception_handler(RequestValidationError)
   → fail("invalid_request", ...) + status_code=422
```

**상태코드는 그대로 둔다.** 봉투와 상태코드는 읽는 주체가 다르다 — 상태코드는 인프라(프록시·모니터링)가, 봉투(`success`/`error.code`)는 애플리케이션(backend)이 읽는다. 역할이 다르니 둘 다 남긴다.

**의도적 예외 ≠ 새는 구멍.** `/health`(인프라 계약)와 `/chat` 스트리밍 본문(스트림 자체가 계약)은 **설계 문서에 명시하고** 봉투 밖에 둔다. "규약에서 문서로 빼는 것"은 소비자가 예측할 수 있고, "규약이 조용히 새는 것"은 소비자가 KeyError로 터진다 — 완전히 다르다.

## 핵심 문장

- 응답 계약은 내 코드가 실행되는 범위까지만 보장된다 — 그 경계 밖은 프레임워크가 자기 형식으로 응답한다.
- pydantic 검증 실패는 라우터 진입 *전*에 일어나 함수 안의 try/except가 못 잡는다 → 전역 예외 핸들러로 되가로챈다.
- 정규화의 값어치는 "예외 없이 전부"에서 나온다 — 한 경로라도 새면 소비자가 두 모양을 다 처리해야 해 도입 의미가 반감된다.
- 상태코드(인프라용)와 봉투(앱용)는 읽는 주체가 달라 둘 다 남긴다.
- 규약에서 문서로 빼는 것(=/health)과 규약이 조용히 새는 것(=검증 실패)은 다르다.
