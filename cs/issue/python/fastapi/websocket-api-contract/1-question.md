## 질문
1. (예측) WebSocket 입력 루프가 `await ws.receive_text()`로 메시지를 받는다. 클라이언트가 binary 프레임을 하나 보내면 무슨 일이 일어나는가? "타입 특화 수신 API"를 외부 입력 루프에 쓰면 안 되는 이유는 무엇인가?
2. (왜) 다른 WebSocket 라이브러리에서 쓰던 `async for msg in ws:`를 Starlette/FastAPI에 그대로 옮겼더니 연결 직후 끊기기를 반복했다. 에러 메시지는 무엇을 말하고, 이 관용구가 통하려면 객체가 무엇을 구현해야 하는가?
3. (예측) WebSocket 엔드포인트 인자에 타입 힌트 없이 `async def ws_endpoint(ws):`로 썼다. 실제 브라우저·curl로 붙으면 핸드셰이크가 어떤 HTTP 상태로 거절되는가? FastAPI가 인자를 "타입 힌트로 해석한다"는 사실과 어떻게 연결되는가?
4. (경계) 같은 엔드포인트가 TestClient 기반 테스트에서는 정상 동작했다. 테스트 하네스와 실제 서버가 다른 결과를 낸 이유는 무엇이고, 이것은 "테스트 통과 ≠ 실제 경로 검증"의 어떤 형태인가?
5. (경계) 403의 원인 후보로 리버스 프록시 헤더 처리 미들웨어가 WS 요청의 scheme을 바꾸는 경우도 기록됐다. "Docker 때문"이라는 가설은 어떻게 배제했는가? 원인을 좁히는 순서를 설명하라.
6. (연결) 세 사건을 한 문장으로 묶어라 — "WebSocket"이라는 같은 이름의 API가 라이브러리마다 무엇이 다른가(수신 방식·주입 방식·반복 프로토콜)? 새 프레임워크로 관용구를 옮길 때 무엇을 먼저 확인해야 하는가?
