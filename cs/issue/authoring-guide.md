# cs/issue 작성 가이드 — 이 아카이브는 어떻게 쓰나

> 이 문서는 `cs/issue/` 아래 이슈-패턴 문서를 **어떤 형태로 쓸지**를 정의한다.
> 사람이 읽을 수 있는 일반 작성 기술은 [reference/writing](../../reference/writing/)·[reference/organize-guide](../../reference/organize-guide.md)에 이미 있다 — 여기는 그것을 전제로, **"겪은 이슈를 재사용 가능한 패턴으로 추상화"** 하는 이 아카이브 고유의 규약만 적는다.
> [portfolio](../../portfolio/)와의 차이: 포트폴리오는 **대외용 사례 서술**(한 프로젝트의 문제→해결→결과, 내부 식별자 감춤)이고, 여기는 **문제의 추상화 정리**(여러 프로젝트에 통하는 원리 + 실제 코드·파일 근거를 드러냄)다.

## 1. 무엇을 한 카드로 묶나 — 패턴 단위

이슈 하나 = 카드 하나가 **아니다**. 같은 근본원인·같은 대응을 공유하는 여러 이슈를 **한 패턴 카드**로 묶고, 각 이슈를 사례로 링크한다.
- 예: "성공 로그 ≠ 산출물"(silent-failure)은 7개 이슈에 걸치므로 카드 하나가 그 7개를 링크한다.
- 판별: "이 이슈들을 프로젝트 밖 사람에게 설명할 때 같은 문장으로 시작하나?" → 그렇다면 한 패턴.

## 2. 폴더 분류 (두 축)

**축1 = 소속(폴더 트리)**
```
cs/issue/
  <언어>/<프레임워크>/<패턴>/     예: kotlin/spring/serialization-contract-leak/
  cross-cutting/<계층>/<패턴>/     계층 = reliability · network · infra · security
```
- 언어가 뿌리인 이슈는 **언어별**, 프레임워크는 그 하위. 언어 무관 시스템·네트워크 이슈는 **cross-cutting** 아래 계층별.
**축2 = 메타 태그(폴더 밖 반복 주제)** — 각 카드 본문 상단에 `태그:` 로 표기: `silent-failure` · `resource-bounding` · `least-privilege` 등. 폴더로는 못 담는 교차 주제를 검색 가능하게 한다.

## 3. 파일 형태 (배포 사이트 렌더 규약과 정합)

- **하위 폴더가 있는 폴더**(`cs/issue/`, `cross-cutting/`, 각 계층·언어 폴더) → `README.md`가 본문. 역할 = **추상화 + 하위 링크 인덱스**(포트폴리오 상위 README처럼).
- **패턴 리프 폴더** → cs 컨벤션대로 `1-question.md` / `2-summary.md` / `3-answer.md` 3파일. (리프의 `post.md` 규약은 포트폴리오용이고, cs 주제는 1/2/3을 쓴다 — TreeBuilder가 둘 다 처리.)

## 4. 패턴 리프 3파일에 담을 것

기존 cs 리프 헤더(복습 안내·⚠️Claude 초안 줄·복습 기록 표)를 그대로 쓰고, 내용은 **문제 추상화** 관점으로:
- **1-question.md** — 이 패턴을 인출로 되묻는 질문 5~7개(왜/예측/경계/연결).
- **2-summary.md** — 힌트. 「전체 흐름」은 **ASCII 도식/워크플로우**로(요청이 겪는 일·실패 지점), 「핵심 문장」은 압축.
- **3-answer.md** — 질문 1:1 정답 + 핵심 용어 인라인 글로스(`> **term** — 한 줄`) + **「발생한 문제 / 해결」**의 추상 원리 + **「이번 프로젝트 사례」**(각 이슈를 `../../../../../project/study-note-deploy-system/<repo>/issueN/` 상대링크 + 한 줄 요약) + 「검증 기록」(근거 코드 파일·라인).

## 5. 서술 규칙

- **추상화 우선**: 프로젝트 특수사정이 아니라 "프로젝트 밖에서도 참인 원리"로 쓴다. 사례는 링크로 붙인다.
- **도식화**: 흐름·실패 전파·구조는 ASCII 코드블록으로 시각화(포트폴리오 도식 스타일). 말로만 풀지 않는다.
- **근거를 드러낸다**: 여기는 학습용이라 실제 파일·클래스·라인을 검증 기록에 적는다(포트폴리오와 반대). 단 **시크릿 값·내부 IP·자격증명은 금지**(개념·포트 형태로만).
- 문장은 한 줄에 하나, 줄 끝 `\`로 줄바꿈(사이트가 raw HTML을 렌더하지 않음). "기각" 대신 "선택하지 않은 방법".
- 날조 금지 — 코드/이슈에서 확인한 것만.
