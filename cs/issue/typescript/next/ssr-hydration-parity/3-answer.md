## 정답
<!-- 질문 1:1 대응 -->

1. **하이드레이션.** 서버가 렌더한 HTML로 먼저 화면을 보여 주고, 클라이언트 React가 같은 트리를 렌더해 **기존 DOM에 대응시키고 이벤트를 붙이는** 과정이다.\
React는 DOM을 새로 만들지 않고 재사용하므로, 첫 렌더 결과가 서버 DOM과 같다는 것이 전제다.\
다르면 hydration 경고·오류가 나고, React 18+는 불일치가 난 곳부터 가장 가까운 Suspense 경계(없으면 루트)까지를 버리고 클라이언트 렌더로 다시 그려 깜빡임·비용이 생긴다(구버전 React는 경고만 내고 일부 차이(속성 등)를 고치지 않은 채 남기기도 한다 — 버전마다 다름).
   > **하이드레이션(hydration)** — 서버가 보낸 정적 HTML에 클라이언트 React가 상태와 이벤트 핸들러를 연결해 상호작용 가능하게 만드는 단계.

2. **`typeof window` 분기.** 서버에는 `window`가 없으므로 빈 fragment를, 클라이언트 첫 렌더는 `<SiteIndex/>`을 그린다 — 첫 렌더부터 불일치다.\
이 패턴이 여러 페이지에 있어 7개 페이지에서 hydration 오류가 났다.

3. **lazy initializer도 첫 렌더.** 서버는 `0`으로 렌더(모바일 UI)하고, 클라이언트는 첫 렌더에서 실제 폭(데스크톱)을 읽는다.\
그 결과 데스크톱 진입 시 모바일 UI가 한 프레임 보였다 사라지고, 모바일용 이미지가 불필요하게 요청되며, hydration 경고가 났다.\
이 훅이 전역 푸터에서 쓰여 영향 범위가 넓었다 — 리뷰가 이를 분석해 롤백을 권고했다.

4. **마운트 후 반영.** `useIsMounted`는 서버와 클라이언트 첫 렌더 모두 `false` → 같은 결과(브라우저 의존 부분 미렌더)를 그린다.\
마운트 후 effect가 `true`로 바꿔 두 번째 렌더부터 브라우저 값을 쓴다 — 첫 렌더 일치가 구조적으로 보장된다.\
대가: 그 부분은 첫 페인트에 없고 한 번 더 렌더된다.\
폭처럼 값이 필요한 경우는 `useState(0)` + 마운트 effect에서 `setWidth(window.innerWidth)`로 같은 원리를 쓴다.\
대안으로 해당 컴포넌트를 SSR에서 제외하는 동적 import(`ssr:false`)도 기록됐다.

5. **HTML 파서의 자동 닫기.** 서버는 `<p><p>..</p></p>` 문자열을 보냈지만, 브라우저 HTML 파서는 `<p>` 안에서 블록 요소(`<p>`)를 만나면 **앞 `<p>`를 자동으로 닫는다**.\
DOM은 빈 `<p>`와 형제 `<p>`들로 재구성되고, React가 기대한 중첩 트리와 달라 불일치가 난다.\
React 코드가 아니라 **파서**가 DOM을 바꾼 것이다.
   > **HTML 콘텐츠 모델** — 요소마다 담을 수 있는 자식의 종류가 정해져 있다. `<p>`는 문구(phrasing) 콘텐츠만 담을 수 있다.

6. **한 원인, 세 증상.** 자동 닫기로 스타일 클래스가 붙은 바깥 `<p>`는 **빈 요소**가 되고 메시지 문단은 그 밖의 형제로 밀려난다 — 그래서 "빈 상태" 스타일은 빈 `<p>`에만 적용되고, 메시지 두 줄은 `nowrap`인 조상 아래에서 가로로 눌렸다.\
구조가 바뀌면 스타일 셀렉터가 가리키는 요소와 레이아웃 부모도 같이 바뀌기 때문이다(기록된 것은 "스타일이 빈 `<p>`에만 적용됨"이고, 클래스가 바깥 `<p>`에 있었다는 구조는 그 증상에서 역산한 추정이다).\
`<div>`로 바꾸기 전에 태그를 한정한 CSS 셀렉터(`p.xxx`)가 0건임을 확인했다 — 스타일이 클래스 셀렉터뿐이라 태그 전환이 안전했다.

7. **한 문장: 서버 HTML이 만든 DOM ≠ 클라이언트 첫 렌더 트리.** 원인 ①은 **렌더 단계**에서 생긴다 — 같은 컴포넌트가 환경(서버/브라우저)에 따라 다른 트리를 낸다.\
원인 ②는 **파싱 단계**에서 생긴다 — 트리는 같지만 서버 HTML 문자열이 DOM이 되는 과정에서 파서가 구조를 바꾼다.\
①은 첫 렌더를 환경 무관하게 만들어, ②는 HTML 중첩 규칙을 지켜 막는다.

## 문제 구조 (추상화 코드)

### 변형 A — 첫 렌더가 브라우저 전용 값에 의존
① 문제 코드
```tsx
function Nav() {
  return typeof window !== "undefined" ? <SiteIndex /> : <></>;       // 서버: 빈 것, 클라: SiteIndex
}
function useViewport() {
  const [w, setW] = useState(() => (isBrowser ? window.innerWidth : 0));   // 클라 첫 렌더 = 실제 폭
  // ...
}
```
② 고친 코드
```tsx
function useIsMounted() {
  const [m, setM] = useState(false);
  useEffect(() => setM(true), []);
  return m;
}
function Nav() {
  const mounted = useIsMounted();
  const w = useViewport();
  return <>{mounted && (w > BREAKPOINT ? <Menu /> : <SiteIndex />)}</>;
}
function useViewport() {
  const [w, setW] = useState(0);                                     // 서버·클라 첫 렌더 동일
  useEffect(() => { setW(window.innerWidth); /* + resize 구독 */ }, []);
  return w;
}
```
무엇이 깨졌나: 서버에 없는 값을 첫 렌더에 사용해 두 환경의 트리가 갈렸다.

## 방안 비교

기본 방안(위 변형 A)은 "첫 렌더를 환경 무관하게 만들고 브라우저 값은 마운트 후 반영"이다. 같은 원리(서버 HTML ≠ 클라이언트 첫 트리)에 다른 방안이 쓰인 사례:

### 방안 1 — HTML 콘텐츠 모델을 지키는 태그로 교체
```tsx
// 문제: <p> 안의 <p> → 파서가 앞 <p>를 자동으로 닫아 DOM 재구성
<p className="empty-msg">          {/* 파서: 여기서 자동 닫힘 → 빈 <p class="empty-msg"> */}
  <p>{line1}</p><p>{line2}</p>
</p>
// 고친: 블록 컨테이너는 div (태그 한정 CSS 셀렉터 0건 확인 후)
<div className="empty-msg">
  <p>{line1}</p><p>{line2}</p>
</div>
```

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|------|------|------|-----------|-----------|
| 기본: 마운트 후 반영 | 차이가 렌더 단계(환경 의존 값)에서 생긴다 | 한 번 더 렌더, 첫 페인트에 해당 부분 없음 | 여러 곳에 흩어진 같은 패턴 → 전수 조사 필요 | window·폭·저장소 등 브라우저 전용 값 |
| 1. 중첩 규칙 준수 | 차이가 파싱 단계(HTML 재구성)에서 생긴다 | 태그 교체 | 태그 한정 CSS가 있으면 스타일 깨짐 | 컴포넌트 합성으로 블록이 문단 안에 들어갈 때 |

**결론**: 불일치가 나면 먼저 **어느 단계에서** 갈렸는지 가른다 — 같은 트리가 다른 값을 내면 렌더 단계(기본), 트리는 같은데 DOM이 다르면 파싱 단계(1).\
렌더 단계 원인은 한 곳을 고쳐도 같은 패턴이 다른 곳에 남기 쉬우므로 공통 훅·컴포넌트로 모으고 전수 조사한다.
