# cs/issue/typescript/next/single-source-of-truth-routing — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

**한 문장:** "이 노드가 폴더냐 주제냐 문서냐"라는 판단은 백엔드의 `is_subject` 하나(단일 진실원)가 이미 주므로, URL 구조에 그 판단을 또 심어 이중 관리하지 말고 **라우트 하나가 노드 종류로 분기**하게 하고, 상대 링크의 웹 경로 변환은 "보이는 경로 = 프론트" 경계에 따라 렌더 시점에 한다.

### 라우트를 나누면 판단이 두 곳에 산다

```
[탈락] 라우트 셋
   /folder/... /subject/... /doc/...  ← URL 구조에 "종류"가 박힘 (판단 #1)
   + 백엔드 트리의 is_subject          ← 같은 판단이 여기도 (판단 #2)
   두 판단이 언젠가 어긋난다:
     is_subject=true 인데 URL은 /folder/... → 폴더 화면으로 잘못 렌더
```

같은 사실("노드 종류")을 두 곳에서 관리하면, 한쪽만 바뀌는 순간 어긋난다. 이건 정합성을 사람 규율에 맡기는 구조다.

### 라우트 하나가 단일 진실원으로 분기한다

```
[채택] 캐치올 라우트 하나
  /wiki/<경로>  ──▶ findNode 로 트리에서 노드 찾기
                        │
       ┌────────────────┼────────────────────────────┐
  폴더(!is_subject)   주제(is_subject)          트리에 없음
       │                   │                          │
  README/하위목록      1/2/3 탭(고정)          문서 직접 조회(폴백)
                                                  실패 → 404
```

종류 판단은 오직 `is_subject`(단일 진실원)에서 온다. 새 종류가 생겨도 URL 설계는 그대로, **분기 코드 한 곳만** 고치면 된다. "트리에 없음 → 문서 폴백"까지 한 라우트가 받으므로, 경로 해석이 한 군데로 수렴한다.

### 상대 링크는 "보이는 경로 = 프론트" 경계에서

노트 원문의 `](../kafka-why-fast/)`·`](2-summary.md)`를 그대로 두면 브라우저가 없는 경로로 간다. 백엔드는 "콘텐츠 JSON(원문)만" 주는 경계라, `/wiki/...` 웹 경로로의 변환은 프론트(렌더 시점) 몫이다. `resolveHref`가 문서 위치 기준으로 `..`/`.`를 스택으로 해소해 `/wiki/...`로 바꾼다.

```
resolveHref("../kafka-why-fast/", "cs/systems/lsm-tree") → "/wiki/cs/systems/kafka-why-fast"
resolveHref("2-summary.md",       "cs/lsm-tree")         → "/wiki/cs/lsm-tree/2-summary"
```

**숨은 결함:** `.md` 뒤에 `#절`/`?query`가 붙으면(`other.md#절`) `.md`를 못 떼어 깨진다. 이건 그런 링크가 **실제로 들어와야만** 드러나므로 빌드·화면 통과로는 안 잡힌다 → 리뷰에서 hash/query를 먼저 분리·보존하도록 수정. 교훈: **순항한 이슈의 코드가 무결한 코드는 아니다** — 빌드 통과·화면 뜸은 "모든 입력을 다룬다"를 보장하지 않는다.

## 핵심 문장

- 같은 판단(노드 종류)을 URL과 백엔드 모델 두 곳에서 관리하면 언젠가 어긋난다 → 단일 진실원(`is_subject`) 하나에서만.
- 라우트 하나(캐치올)가 노드 종류로 분기 → 새 종류는 URL 설계 불변, 분기 코드 한 곳만 수정.
- "트리에 없음 → 문서 폴백"까지 한 라우트에 모아 경로 해석을 한 곳으로 수렴.
- 콘텐츠(원문)는 백엔드, 보이는 경로(`/wiki/...` 변환)는 프론트 — 상대 링크 치환은 렌더 시점.
- 순항한 이슈의 코드도 무결하지 않다 — `resolveHref`의 hash/query 결함처럼, 특정 입력이 와야만 드러나는 버그는 빌드·화면 통과로 못 잡는다.
