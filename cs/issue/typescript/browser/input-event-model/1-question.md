## 질문
1. (왜) 웹뷰 터미널에서 한글 "프로젝트"를 치면 "프로로젝로젝트로젝트"처럼 음절이 중복·누적됐다. `compositionend`와 라이브러리의 데이터 이벤트(`onData`)가 같은 텍스트를 **두 경로로** 흘린다는 것으로 설명하라. "조합 중(composing) 플래그로 onData를 막는" 가설은 왜 실패했는가?
2. (예측) React controlled input에서 바이트 제한을 넘으면 `onInput`에서 value를 잘라 setState한다. 한글 조합 중에 이 절삭이 실행되면 무엇이 일어나는가? 언제 자르는 것이 안전한가?
3. (경계) 터미널 라이브러리의 키 핸들러에서 `return false`(= "처리했음")를 반환했는데, 상위 컨테이너의 keydown 핸들러가 같은 Ctrl+→를 또 처리해 패널이 두 칸 움직였다. 라이브러리의 "처리됨"과 DOM의 `preventDefault`·`stopPropagation`은 각각 무엇을 막는가?
4. (예측) 단축키 `v`에 modifier 검사가 없으면 Ctrl+V는 어떻게 되는가? `e.key`만 보는 판정의 경계는 무엇인가?
5. (왜) 자식 뷰어가 열리면서 자동으로 포커스를 가져가자 사이드바의 ↑↓ 탐색이 멈췄고, 뷰어를 닫으면 포커스가 body로 빠졌다. 키보드 탐색에서 "포커스의 소유권"이 왜 하나여야 하는가? 아직 렌더되지 않은 DOM에 focus()하면 어떻게 되는가?
6. (경계) HTML5 드래그 앤 드롭에서 `drop` 이벤트가 **오지 않고** 끝나는 경우는 무엇인가? 드롭존 하이라이트를 dragleave/drop 두 경로에서만 지우면 무엇이 남는가? `dragover`에서 `preventDefault()`를 빼면 무엇이 일어나는가?
7. (연결) 웹뷰에서 한글이 **아예** 안 되는 문제는 이벤트 코드가 아니라 OS 입력기 데몬과 환경변수의 불일치였다. 1~6의 "이벤트 계층" 교정과 이 "환경 계층" 교정은 어떻게 다르고, 어떤 순서로 의심해야 하는가?
