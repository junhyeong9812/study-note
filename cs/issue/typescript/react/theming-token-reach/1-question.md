## 질문
1. (왜) `:root[data-theme=light]`에서 CSS 커스텀 프로퍼티를 바꾸면 일반 DOM 요소는 즉시 라이트로 바뀐다. 그런데 canvas에 그리는 터미널 위젯·JS 옵션 객체로 테마를 받는 에디터는 어둡게 남는다. 왜 CSS 변수가 여기까지 닿지 않는가?
2. (예측) SVG 요소에 `stroke="var(--bg)"`처럼 **속성**으로 CSS 변수를 넣었다. 테마를 바꾸면 선 색이 따라 바뀌는가? 같은 값을 CSS 클래스 규칙(`stroke: var(--bg)`)으로 옮기면 무엇이 달라지는가?
3. (경계) 네이티브 `<select>`는 닫힌 박스에는 다크 테마 CSS가 먹는데, 펼친 옵션 목록은 테마와 다른 색으로 뜬다. 이 경계는 어디서 생기며, 스타일을 더 손질하는 대신 무엇으로 바꿔야 하나?
4. (경계) 테마가 바뀔 때마다 에디터 위젯을 통째로 다시 만들면 색은 맞는다. 그러면 무엇을 잃는가? "재생성"과 "라이브 재구성(reconfigure·옵션 갱신)"을 언제 골라야 하나?
5. (예측) 상태 배지의 글자색은 `var(--st-danger)` 토큰인데 같은 요소의 반투명 배경은 `rgba(R, G, B, .15)` 리터럴이다. 라이트 테마로 바꾸면 이 배지는 어떻게 보이나? 배경을 토큰에서 파생시키는 CSS 표현은?
6. (경계) 두 기능(git 추가 표시·상태 배지)이 우연히 같은 hex 색을 쓴다. 이 둘을 한 토큰으로 합치면 무엇이 깨질 수 있나? 그리고 "하드코딩 색 잔존 0"을 확인하는 grep이 `var(--accent, #89b4fa)` 같은 fallback까지 세면 왜 검증이 원천적으로 통과할 수 없나?
7. (연결) "단일 출처(single source of truth)" 원칙을 테마에 적용하면, 출처(토큰)는 하나로 두되 **전달 경로**는 표면마다 달라야 한다. 이 두 문장이 어떻게 동시에 참인지 설명하라.
