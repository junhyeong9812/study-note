## 질문

1. (왜) 보이는 탭만 마운트하는 도킹 레이아웃에서 탭을 바꾼 뒤, 오케스트레이터가 `setActive()` → 1 프레임(rAF) 뒤 `querySelector(".widget")?.focus()`를 한다. 가벼운 패널은 되는데 무거운 패널은 항상 실패했다 — 왜인가? rAF를 두 번, 세 번으로 늘리는 것이 해법이 아닌 이유는?

2. (경계) "콘텐츠 소유자 self-focus"(패널이 자기 위젯 생성 직후 스스로 포커스)는 타이밍 문제를 어떻게 **책임 위치** 문제로 바꾸는가? 리마운트 없이 활성만 바뀌는 경우(분할된 패널 전환)는 무엇으로 받는가?

3. (예측) 패널별 "마지막 포커스 영역"을 컴포넌트 state에 두면 탭 전환마다 무엇이 되는가? 모듈 스코프 Map으로 옮겼는데 삭제를 안 하면 어떤 두 가지 문제가 생기는가? 삭제는 **어느 이벤트**에서 해야 하는가?

4. (경계) 백그라운드 탭이 언마운트되면 그 탭 컴포넌트가 가진 이벤트 리스너도 사라진다. 백그라운드 세션의 상태 배지를 계속 갱신하려면 구독을 어디로 옮기는가? "컴포넌트 폐기"와 "패널 제거"가 다른 이벤트인 것은 왜 중요한가?

5. (왜) `mousedown`에서 포커스를 바꾸며 전체를 다시 그렸더니(`innerHTML` 재생성) 같은 클릭의 버튼·탭이 반응하지 않았다. `click` 이벤트의 발생 조건으로 설명하라. 매 프레임 DOM을 재생성하는 렌더 루프에서 말풍선 클릭이 안 먹는 것도 같은 원리인가?

6. (연결) `innerHTML = ''`는 자식 노드를 **파괴**하는가 **분리**하는가? 이 성질을 이용해 전면 재렌더 뷰 위에 영속 위젯(터미널)을 살려 두려면 무엇을 누가 소유해야 하는가? 분리된 상태에서 크기 맞춤(fit)을 부르면 왜 안 되는가?
