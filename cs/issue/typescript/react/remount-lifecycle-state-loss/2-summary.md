# cs/issue/typescript/react/remount-lifecycle-state-loss — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
"탭 전환" / "조건부 래퍼" / "innerHTML 재생성"
        │  사용자에겐 "잠깐 숨김"
        ▼  런타임에겐   unmount + mount (또는 노드 파괴·분리)
  사라지는 것:
    컴포넌트 state        (마지막 포커스 영역, 선택)
    컴포넌트 안 구독        (백그라운드 세션 이벤트)
    포커스 대상 DOM         (아직 생성 전 → 외부에서 찾으면 null)
    이벤트 대상 노드        (mousedown 과 click 사이에 교체 → click 없음)

[실패하는 대응]  바깥에서 타이밍 맞추기 — rAF 1회 → 무거운 패널은 아직 없음 (레이스)

[교정 = 수명 긴 것은 밖으로, 정리는 명시적으로]
   포커스        콘텐츠 소유자가 생성 직후 self-focus + 활성 변경 이벤트
   뷰 상태        모듈 Map (키 = 패널 id)  ── 삭제는 "실제 제거" 이벤트에서만
   세션 구독      앱 레벨 전역 리스너 1개 + 레지스트리 (마운트된 패널이 있으면 그쪽 우선)
   DOM 재생성     경량 갱신(class 토글) · 노드 풀링 · 데이터 변경 시에만 rebuild
   영속 위젯      JS 가 인스턴스 소유 → 재렌더 후 appendChild 재부착 → 붙은 뒤에만 fit
```

## 핵심 문장

- 가시성 전환·조건부 래퍼·DOM 재생성은 **리마운트**다 — 컴포넌트에 둔 상태·구독·포커스 대상은 그때 사라진다.
- 바깥에서 "몇 프레임 뒤 찾기"는 자식 초기화 시간과 경합한다 — **타이밍이 아니라 책임 위치**로 푼다(소유자 self-focus).
- 컴포넌트보다 오래 살아야 하는 상태는 밖(모듈·스토어)에 두되, 그 순간 **삭제 책임도 넘어온다** — 실제 제거 이벤트에서 지운다.
- "컴포넌트 폐기"(가시성)와 "패널 제거"(수명 종료)는 다른 이벤트다 — 세션 상태 정리는 후자에만.
- `click`은 같은 요소에서 down·up이 모두 일어나야 한다 — 그 사이에 DOM을 재생성하지 마라.
- `innerHTML = ''`는 분리일 뿐이다 — JS가 참조를 쥐면 위젯은 살아 있고 재부착할 수 있다. 레이아웃 계산은 붙은 뒤에만.
