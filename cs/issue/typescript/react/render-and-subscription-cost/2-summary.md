# cs/issue/typescript/react/render-and-subscription-cost — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
비용 = (한 번의 일) × (데이터 크기) × (갱신 빈도)
                          ▲               ▲
       묶어야 할 곳 ──────┘               └── 틱 150ms · mousemove · 모든 set

[새는 곳]                                     [묶는 법]
 전 행 DOM 렌더              O(행 수)          가상화: 보이는 창 + overscan  → O(뷰포트)
 셀렉터 없는 subscribe       모든 set × 전수 비교   변경 주체가 직접 통지   → O(변경분)
 set(() => ({}))             새 루트 → 전 리스너 wake   변화 없으면 state 자신 반환
 0건 삭제에도 새 객체         파생 이벤트(epoch) 폭주    삭제 0 → 기존 객체 반환
 노드당 includes             O(N·E) × set 마다       배열 identity 메모 Set → O(1)
 틱마다 딥클론·직렬화·전수 스캔  크기 × 빈도 churn        불변 결과 캐시 · debounce · drain 1회
 mousemove 마다 전체 렌더      이벤트 빈도 × 트리       rAF 묶기 + mouseup 커밋

       변경 감지 = Object.is  →  "내용이 같으면 참조도 같게" 가 비용 계약의 핵심
```

## 핵심 문장

- 렌더·구독 비용이 **전체 데이터 크기 × 갱신 빈도**에 비례하면 데이터가 커질수록 앱이 느려진다 — 뷰포트·변경분에 묶는다.
- 고정 높이 행은 가상화로 렌더 비용을 뷰포트 크기에 묶는다(가변 높이는 대상 밖).
- 셀렉터 없는 구독은 모든 갱신에 전수 비교를 치른다 — 변경을 만든 쪽이 변경분만 통지한다.
- 스토어·셀렉터는 참조 동등성으로 변경을 판단한다 — 변화가 없으면 **기존 참조를 그대로** 돌려준다.
- 선형 탐색을 렌더마다 반복하지 말고, 불변 입력의 identity를 키로 메모한다(입력 in-place 변경 금지가 계약).
- 결과가 불변인 계산은 한 번만 — 캐시로 바꿀 때는 특성 테스트로 동작 보존을 먼저 고정한다.
