## 질문

1. (왜) 목록에서 하나를 골라 둔 선택 상태(`selectedId`)가 있다. 목록을 다시 스캔했더니 그 항목이 사라졌다. 선택 상태를 그대로 두면 무엇이 되는가? 그 선택으로 **쓰기** 작업을 하면 어떤 위험이 생기는가?

2. (예측) 가상화 목록은 `scrollTop`에서 창의 시작 인덱스를 파생한다. 긴 데이터를 깊게 스크롤한 뒤 짧은 데이터로 교체하면 화면은 어떻게 되는가? 어떤 두 가지 수정이 필요한가?

3. (경계) 선택 항목을 스크롤·키보드 내비의 **앵커**로 쓰는데, 닫기 버튼이 선택을 `null`로 지우거나 선택된 항목이 접혀 목록에서 빠지면 `findIndex`는 무엇을 돌려주는가? 앵커를 잃지 않으려면 어떻게 하는가?

4. (연결) "기본 선택 = 데이터의 최신 키" 로직은 데이터에 키를 **추가하는** 모든 코드와 어떻게 결합되는가? 목 데이터가 없던 키를 새로 만들면 무슨 일이 나는가?

5. (예측) 이미지 컴포넌트가 로드 실패를 `failed` state로 기억한다. 리스트에서 같은 컴포넌트가 다른 `src`로 재사용되면 무엇이 보이는가? prop에서 파생된 로컬 state의 일반적인 함정으로 설명하라.

6. (경계) 여러 행에 "현재 브랜치" 배지를 보여줄 때, 선택된 행만 라이브 값으로 갱신하고 나머지는 스캔 당시 값으로 두는 것은 버그인가 설계인가? 신선도를 행별로 **분리해 표시**하는 것이 왜 유령 참조와 다른가?
