## 질문
1. (왜) 분할 토글이 켜질 때만 두 패널을 `<PanelGroup>`으로 감싸도록 조건부 래퍼를 썼다. 토글을 누르자 계속 보이던 위쪽 패널의 입력 중 텍스트가 사라졌다. React는 무엇을 기준으로 "같은 인스턴스"를 판단하며, 왜 여기서 리마운트가 일어났나?
2. (경계) 위 문제를 고치는 방법으로 "래퍼를 항상 렌더 + key 고정"과 "로컬 상태를 부모/스토어로 승격"이 있다. 각각 무엇을 보장하고, 두 자식의 자리를 맞바꾸는 스왑에서는 왜 전자만으로 부족한가?
3. (예측) "논리적으로 같은 영역"이라 생각한 사이드바 컴포넌트에서 `useScope()`를 호출했더니 throw가 났다. 프로바이더는 메인 영역만 감싸고 있었다. Context 값은 어디서 공급되며, 이 throw는 버그인가 설계인가?
4. (예측) `createPortal(modal, document.body)`로 띄운 모달 안에서 Ctrl+←를 눌렀다. DOM상 모달은 body 끝에 있는데, 모달을 연 패널의 `onKeyDown`(pane 이동)이 이 키를 받아 입력을 가로챘다. 왜인가?
5. (경계) 애초에 모달을 포털로 띄운 이유는 무엇인가 — CSS `transform`이 있는 조상은 `position: fixed` 자손에게 어떤 영향을 주나? 그리고 4번 문제를 "stopPropagation만 추가"하는 것보다 구조적으로 해소하는 방법은?
6. (예측) 팝오버를 body 포털로 옮긴 뒤 바깥클릭 판정을 `triggerRef.current.contains(e.target)`로만 했다. 팝오버 안을 클릭하면? 또 메뉴 안의 하위 팝오버(중첩 포털)를 클릭했을 때 부모 메뉴의 React `onClick`은 호출되는가, `closest('[data-keep-menu]')`는 래퍼를 찾는가?
7. (연결) 6번의 결함은 새 테스트 "항목을 누르면 메뉴는 닫힌다"가 green인 채로 들어왔다. 단일 포털 픽스처에서 관찰한 동작을 단언한 테스트가 어떻게 결함을 **계약으로 고정**하나? 이런 테스트의 "이빨"을 확인하는 방법은?
