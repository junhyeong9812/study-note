# cs/issue/typescript/react/css-negative-margin-overflow — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

**한 문장:** 부모 패딩을 상쇄하려는 음수 마진은 자식의 실제 폭을 컨테이너보다 넓게 만들고, 이 넘침이 `overflow` 컨테이너를 만나면 가로 스크롤바로 드러난다 — 근본 해법은 넘침을 잘라내는 게 아니라 **애초에 부모가 패딩을 갖지 않게** 해서 음수 마진 자체를 없애는 것이다.

### 원인 — 음수 마진이 폭을 부풀린다

```
[문제 구조]
  aside  padding: 0 1rem            안쪽 여백 좌우 1rem
    └ 자식  margin: 0 -1rem          그 여백을 "상쇄"하려 좌우로 튀어나감
            padding: 0 1rem          + 자기 안쪽 패딩

  자식의 점유 폭 = 컨테이너 콘텐츠폭 + 1rem(좌 음수마진) + 1rem(우 음수마진)
                = 컨테이너 + 2rem   ← 넘침(overflow)
```

margin은 요소의 폭에 **더해지는** 바깥 영역이라, 음수 마진은 요소를 컨테이너 경계 바깥으로 밀어낸다. 그 넘친 폭을 `overflow-y: auto`(세로 스크롤용) 같은 스크롤 컨테이너가 만나면, 가로 방향으로도 스크롤할 게 생겼다고 판단해 **가로 스크롤바**를 띄운다.

### 해법 — 여백의 소유권을 자식에게

```
[탈락] overflow-x: hidden 로 넘침을 잘라내기 (증상만 가림)
[채택] 부모(aside) 좌우 패딩 제거 → 각 행(자식)이 자기 padding 을 가짐
        음수 마진이 필요 없어짐 → 넘침 자체가 사라짐
        + overflow-x: hidden 은 "안전벨트"로만 추가
```

전폭(full-bleed)이 필요하면 "부모가 패딩을 주고 자식이 음수 마진으로 되무는" 대신, **부모는 패딩 0, 각 자식이 필요한 만큼 자기 패딩을 소유**하게 하면 된다. 그러면 자식이 자연스럽게 컨테이너 전폭을 쓰고, 튀어나갈 이유가 없다. `overflow-x: hidden`은 근본 수정 후의 안전벨트일 뿐, 그것만으로 원인을 덮으면 다음에 폭을 넘기는 요소가 또 조용히 잘려 디버깅이 어려워진다.

### 디버깅 감각 — 가로 스크롤은 "폭을 넘긴 한 요소"

가로 스크롤이 보이면 "누가 컨테이너보다 넓은가"를 좁힌다. 흔한 범인: **음수 마진**, 뷰포트보다 큰 **고정 `min-width`**, 줄바꿈 안 되는 **긴 문자열/코드블록/표**(이건 그 요소만 자기 스크롤 컨테이너에 담아 격리). 박스모델에서 폭에 더해지는 것(margin)과 폭 안에 드는 것(padding, `box-sizing` 의존)을 구분하는 게 진단의 핵심이다.

## 핵심 문장

- 음수 마진은 요소를 컨테이너 밖으로 밀어 폭을 부풀린다(자식 폭 = 컨테이너 + 2×마진).
- 그 넘침이 `overflow` 스크롤 컨테이너를 만나면 가로 스크롤바로 드러난다.
- 근본 해법 = 넘침을 잘라내기(`overflow-x:hidden`)가 아니라, 부모 패딩을 없애 음수 마진 자체를 제거.
- "여백의 소유권"을 부모(패딩+자식 음수마진)에서 자식(각자 자기 패딩)으로 옮기면 전폭이 정직하게 나온다.
- `overflow-x:hidden`은 근본 수정 뒤의 안전벨트일 뿐 — 그것만으로 원인을 덮으면 다음 넘침이 조용히 잘린다.
- 가로 스크롤 디버깅 = "어느 한 요소가 컨테이너보다 넓은가" 좁히기(음수 마진·고정 min-width·긴 코드블록).
