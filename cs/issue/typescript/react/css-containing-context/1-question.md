## 질문

1. (왜) `flex: 1`을 준 자식이 컨테이너가 좁아져도 줄지 않고 이웃 패널을 덮는다. flex 아이템의 `min-width`/`min-height` 기본값은 무엇이고, 왜 `min-width: 0`을 줘야 줄어드는가? CSS grid의 `1fr`이 `minmax(0, 1fr)`과 다른 점도 같은 원리로 설명하라.

2. (예측) 모달에 `max-height: 85vh`만 추가했는데 원래 `overflow: hidden`이 남아 있다. 내용이 85vh를 넘으면 사용자는 휠·터치·스크롤바로 하단 버튼에 도달할 수 있는가(키보드 포커스 이동·프로그램 스크롤과는 어떻게 다른가)? `overflow: hidden` 뒤에 `overflow-y: auto`를 쓰면 두 축은 각각 어떻게 되는가?

3. (경계) 스크롤을 "바닥으로 따라가게" 하려고 내용 크기만큼 늘어나는(content-sized) 목록 요소의 `scrollTop`을 바꿨더니 아무 일도 없었다. `scrollTop`은 어떤 요소에서만 효과가 있는가? 스크롤 박스를 중첩하면 키보드 스크롤이 왜 갇히는가?

4. (왜) `overflow: hidden` 조상 안의 드롭다운이 잘린다. `position: fixed` 자손이 있는 조상에 `container-type: inline-size`를 걸었더니(이 사례의 브라우저 기준) fixed 메뉴가 뷰포트가 아니라 그 조상 기준으로 배치됐다 — 둘을 "조상이 자손의 그리기 영역·좌표 기준을 바꾼다"는 관점으로 묶되, 클리핑과 containing block이 서로 다른 개념임을 구분해 설명하라.

5. (경계) 컨테이너 쿼리를 공용 클래스(모든 패널 헤더)에 걸었더니 원래 폭이 좁게 설계된 패널은 넓은 창에서도 항상 "좁은 상태"가 됐다. 컨테이너 쿼리는 무엇의 폭에 반응하는가? 어떻게 대상을 한정하는가?

6. (연결) 같은 특이도의 공용 클래스가 어떤 호출처에서는 이기고 어떤 곳에서는 지는 이유는? `:where()`는 무엇을 해결하는가? 넓은 후손 선택자·직계 선택자·타입 열거식 리셋은 각각 어떤 식으로 "의도하지 않은 요소"를 잡거나 놓치는가?

7. (예측) 컨테이너 크기를 재서 행·열을 계산하는 위젯(터미널 그리드)을 숨기는 방법 세 가지 — `display: none`, `visibility: hidden`(겹친 레이어), `height: 0`/`flex: 0` — 는 각각 위젯이 측정하는 크기를 어떻게 바꾸는가(측정 API에 따라 어떻게 달라지는가)? 어느 것이 실제 행·열을 망가뜨릴 수 있는가?
