# cs/issue/typescript/react/instance-scope-of-global-state — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
인스턴스 1개 시절:  "전역 X" ≡ "내 X"   (암묵 동치 — 코드에 안 보임)
   document id · 전역 activeProject · 모듈 Map · 전역 버스 구독 · 창 로컬 레지스트리 · 서버 모듈 객체

인스턴스 2개가 되는 순간 (보조 표면 / 두 번째 탭 / 다른 창 / 동시 요청)
   ┌────────────┐                 ┌────────────┐
   │ 인스턴스 A  │── 읽기/쓰기 ──▶ │  전역 X     │ ◀── 읽기/쓰기 ──│ 인스턴스 B │
   └────────────┘                 └────────────┘
   누출 유형:
     중복 id           → getElementById 가 첫 것만
     전역 stale-guard  → B 가 자기 응답을 전량 거절
     전역 리로드/키     → B 의 주기 작업이 A 를 리로드 · B 의 펼침이 A 에 기록
     전역 버스 이중 구독 → 요청 하나를 두 번 소비
     창별 런타임        → persist 는 디스크만, 다른 창 메모리는 그대로
     서버 모듈 싱글턴    → 요청 1 의 변형을 요청 2 가 봄

[교정]  식별자·가드·상태 키·구독을 인스턴스 스코프로 내린다
   id={instanceId} · projectRef(인스턴스) 비교 · reloadFor(project) · 키별 Map
   전역 소비는 primary 하나만(게이트) · writer 는 한 창만(불변식)
   서버: 공유 객체는 변형 전 복제
[또는] 구조적으로 "둘"을 금지 (같은 탭 양쪽 금지 → 자동 스왑 · 창 이동 차단)
```

## 핵심 문장

- 단일 인스턴스 시절의 "전역 = 내 것"은 코드에 드러나지 않는 가정이다 — 인스턴스가 둘이 되면 서로의 상태를 읽고 쓰는 누출이 된다.
- 해법은 식별자(DOM id)·가드(stale 비교)·상태 키·주기 작업을 **인스턴스 스코프로** 내리는 것.
- 전역 이벤트·요청 버스는 **한 인스턴스만 소비**하도록 게이트한다.
- 창(웹뷰)마다 런타임이 따로다 — persist는 다른 창의 메모리를 바꾸지 않는다. writer를 한 곳으로 고정한다.
- 비동기 등록 전의 "없음"은 "죽음"이 아니다.
- 서버 렌더에서 모듈 스코프 객체는 **모든 요청이 공유**한다 — 변형 전 복제한다.
