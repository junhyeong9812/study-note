## 질문

1. (왜) 트리 컴포넌트가 고정 `id="tree"`와 `getElementById("tree")`를 쓴다. 같은 컴포넌트를 두 개 띄우면 두 번째 트리의 동작은 어떻게 되는가? 이것과 "모듈 스코프 캐시", "전역 요청 버스 구독"이 같은 부류인 이유는?

2. (예측) 늦게 온 응답을 거르는 stale-guard가 `if (globalStore.activeProject !== project) return`이다. 보조 화면에 띄운 두 번째 인스턴스(다른 프로젝트)는 자기 응답을 어떻게 처리하게 되는가? 인스턴스 스코프 가드는 무엇을 비교해야 하는가?

3. (경계) 주기적 리로드 함수가 "전역 활성 프로젝트"를 리로드한다. 보조 트리의 4초 인터벌이 돌 때 무엇이 리로드되는가? 펼침 상태를 전역 활성 키 아래에 기록하면 무엇이 오염되는가?

4. (연결) 데스크톱 앱에서 창(웹뷰)마다 JS 런타임이 따로다. 스토어를 localStorage에 persist하면 다른 창의 **메모리 상태**도 갱신되는가? 소비자가 없는 창에서 발행한 요청은 어떻게 되는가? writer를 한 창으로 제한하는 불변식은 무엇을 막는가?

5. (예측) 창 로컬 레지스트리(id↔세션 매핑)를 가진 뷰를 다른 창으로 옮기면 이벤트는 어떻게 되는가? 새 세션 직후 "살아 있는 목록"을 조회했더니 등록 전이라 비어 있었다 — "없음"을 "죽음"으로 읽으면 무슨 일이 나는가?

6. (연결) 서버 렌더링에서 정적 import한 JSON 객체를 제자리 변형하면 왜 **다른 사용자의 요청**까지 영향을 받는가? ES 모듈의 평가 횟수로 설명하라. 복제(`structuredClone`)는 무엇을 보장하는가?

7. (경계) 같은 탭을 양쪽 영역에 동시에 여는 것을 **구조적으로 금지**(자동 스왑)하는 방식은, 모든 전역 지점을 인스턴스 스코프로 바꾸는 방식과 무엇을 교환하는가?
