# cs/issue/typescript/react/separation-structure-vs-style — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

**한 문장:** 마크다운 표에 선이 안 보인 건 렌더러 버그가 아니라, "렌더러는 구조(`<table>`)만 만들고 표시(선·배경)는 소비자(CSS)의 몫"이라는 경계에서 **우리가 채워야 할 절반(스타일)을 안 채운 것** — 전역 `.markdown table` CSS 하나로 메운다.

### 원인 — 경계의 절반이 비어 있었다

```
[구조 층]  react-markdown + remark-gfm
   | a | b |   ─변환─▶  <table><th>a</th><th>b</th>...</table>
   렌더러의 일 = 여기까지(구조 생성). 색·선은 손대지 않음.

[표시 층]  브라우저 기본 <table> = 테두리 없음  +  우리 CSS = (비어 있었음)
   → 구조는 있으나 선이 없어 셀 경계가 안 보임
```

렌더러는 자기 일(구조)을 다 했다. 브라우저 기본 표 스타일엔 테두리가 없다. 그러니 "표시"를 채우는 건 소비자인 우리 CSS의 몫인데, 그 절반이 비어 있었다. **렌더러 버그가 아니라 스타일 부재.**

### 해법 — 전역 규칙 하나로 표시 절반 채우기

```
.markdown table  border-collapse: collapse   인접 셀 테두리를 하나의 선으로 합침
                 display:block; overflow-x:auto  넘치는 표만 가로 스크롤(페이지 안 밀림)
.markdown th,td  border 1px var(--line)        모든 셀에 분할선
.markdown th     background                    헤더 행 배경으로 구분
.markdown tr:nth-child(even) td  줄무늬         짝수 행 옅은 배경(행 추적)
```

`.markdown table` 전역 규칙 하나면 모든 표에 일괄 적용된다(표시는 콘텐츠마다가 아니라 소비자 층에서 한 번 정하는 것). `border-collapse: collapse`는 인접 셀이 각자 갖는 테두리를 **하나의 선으로 합쳐**, 기본값(`separate`)에서 선이 이중으로 보이는 걸 막는다. 넓은 표는 `display:block; overflow-x:auto`로 **표만** 자기 안에서 가로 스크롤되게 해 페이지 전체가 밀리지 않게 격리한다(음수마진 overflow 패턴과 같은 "넘치는 요소는 자기 스크롤 컨테이너에" 원리).

### 진단이 먼저 — 책임 경계로 원인을 나눈다

"선이 안 보임"을 렌더러 문제로 오진했다면 remark-gfm 설정·플러그인을 헛되이 팠을 것이다. 원인을 **"구조의 문제인가 표시의 문제인가"**로 먼저 나누면, 구조(`<table>`가 생겼나 — 생겼음)는 정상이고 표시(CSS)가 빈 것이 즉시 드러난다. 관심사 분리는 코드 구조 원칙일 뿐 아니라 **디버깅에서 원인을 좁히는 렌즈**다.

## 핵심 문장

- 표에 선이 없던 건 렌더러 버그가 아니라 "표시 절반(CSS)을 안 채운 것" — 렌더러는 구조(`<table>`)만 책임진다.
- 브라우저 기본 `<table>`은 테두리가 없다 → 표시는 소비자(우리 CSS)가 채워야 한다.
- 전역 `.markdown table` 규칙 하나로 모든 표에 일괄 적용(표시는 소비자 층에서 한 번 정한다).
- `border-collapse: collapse` = 인접 셀 테두리를 하나로 합침(기본 `separate`는 선이 이중).
- 넓은 표는 `display:block; overflow-x:auto`로 표만 격리 스크롤 → 페이지 전체는 안 밀림(단 표의 display 변경은 폭 동작·접근성 표 의미에 영향을 줄 수 있어, 가능하면 스크롤 래퍼로 감싸는 편이 안전).
- 원인을 "구조 vs 표시" 책임 경계로 먼저 나누면 헛다리(렌더러 설정)를 짚지 않는다 — 관심사 분리는 디버깅 렌즈.
