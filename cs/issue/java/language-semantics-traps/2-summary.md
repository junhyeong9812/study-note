# cs/issue/java/language-semantics-traps — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[작성자의 직관]            [Java가 정의한 규칙]                 [결과]
"모든 실패를 잡는다"   ─▶  OOM은 Error, Exception 아님        ─▶ (직접 실행 스레드면) 스레드 무음 사망, 상태 RUNNING 고착
"필드는 다 준비됨"     ─▶  static 초기화 = 소스 선언 순서      ─▶ 생성자 시점 RULES == null → (역참조 시) NPE
"메서드가 실행된다"    ─▶  인자는 호출 전에 평가              ─▶ 인자에서 throw → 본문(보안 처리) 전부 건너뜀
"Sub는 Super다"        ─▶  제네릭은 불변 · 런타임 소거         ─▶ 대입 불가 / Class<T>로 중첩 타입 전달 불가
"같은 거 비교"         ─▶  equals(Object)는 아무 타입이나 받음 ─▶ Optional vs 값 → 항상 false
"순서 맞겠지"          ─▶  위치 인자, 같은 타입 순서는 무검사  ─▶ 뒤바뀐 인자 컴파일 통과
"알아서 고르겠지"      ─▶  오버로드 해석: 더 구체적인 것 없음  ─▶ 모호성 에러 (무관한 타입 varargs 0개 · any())
"주석은 주석"          ─▶  블록 주석은 첫 */ 에서 끝           ─▶ 컴파일 깨짐
"record에 달았다"      ─▶  @Target(FIELD) → backing 필드로 전파 ─▶ RecordComponent에서 안 보임
"\W = 특수문자"        ─▶  \W = [^A-Za-z0-9_] (기본 플래그)    ─▶ 문서 설명과 허용 집합 불일치

교정 = 규칙을 코드에 명시
   catch(Throwable)+상태 전이 · 선언 순서 고정 · 인자 파싱을 안전하게/필수 경로 분리
   타입 위트니스·타입 토큰 · id 비교 · 타입 매처 · 배열 타입 명시 · 실제 매칭 집합 역산
```

## 핵심 문장

- `catch (Exception)`은 `Error`(OOM 등)를 잡지 않는다 — 상태 전이가 catch 안에만 있으면 잡이 **조용히 죽고 상태가 고착**된다(`Future`로 제출했다면 스레드는 살고 예외가 `Future`에 묻힌다 — 어느 쪽이든 상태 전이는 없다).
- static 필드는 **소스 선언 순서**대로 초기화된다. 자기 자신 인스턴스를 만드는 필드가 그 생성자가 쓰는 필드보다 먼저 오면 null을 본다.
- 메서드 인자는 **호출 전에** 평가된다. 신뢰할 수 없는 입력 파싱을 인자 자리에 두면, 파싱 실패가 필수 처리(보안 카운트)를 통째로 건너뛰게 만든다.
- 제네릭은 **불변**이고 런타임에 **소거**된다 — `List<Sub>`는 `List<Super>`가 아니고, `Class<T>`로는 `Paged<Item>`을 표현할 수 없다(익명 서브클래스 타입 토큰으로 보존).
- `equals(Object)`·위치 인자·`any()`는 **타입 체커가 도와주지 못하는 자리**다 — 컴파일 green은 필요조건일 뿐이다.
- 주석 렉싱·어노테이션 전파·정규식 문자 클래스는 **사람이 읽는 의미와 언어 정의가 다르다** — 실제 동작을 역산해 확인한다.
