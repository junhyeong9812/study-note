# cs/issue/shell/quoting-expansion-layers — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
쓴 텍스트 ──▶ [인용 해석] ──▶ [변수·명령 확장] ──▶ [word-split(IFS)] ──▶ [glob] ──▶ 실행
               │                  │                     │                  │
   '...'"$l"'...'   바깥 셸이 $l 확장     "$VAR" 없으면 공백으로 쪼갬   * 는 0글자도 매칭
   → 안쪽 루프 변수가 아님(빈 값)   (값 속 '...'은 인용 아님)     → Test.java 도 *Test.java
   bash -c '...' 는 이 전체를 한 번 더 반복 (계층 × 2)

다른 해석기에 먹이는 텍스트
  . .env        → dotenv 값이 셸 문법으로 파싱 ( ( ) 는 메타문자 )
  heredoc       → 본문과 종료 태그는 "문자열"로만 구분 → 본문 속 태그 줄에서 조기 종료
                  → 나머지 본문이 명령으로 실행
  >> 덧붙이기    → 파일 끝 개행 없으면 기존 마지막 줄에 이어붙음 (주석 줄이면 통째로 주석)

[교정]
  같은 방안:  변수 루프 대신 명시 경로 · dotenv는 줄 단위 key=value 파서 · 인자는 인라인/배열
  다른 방안:  개행 확인 후 추가 · ?* 로 최소 1글자 · 셸 밖 도구(python)로 파일 쓰기
```

## 핵심 문장

- 셸은 한 번 읽고 끝나지 않는다 — **인용 → 확장 → 분할 → glob** 계층마다 텍스트를 다시 해석하고, `bash -c`는 그것을 한 번 더 반복한다.
- `'"$x"'` 중첩 인용은 작은따옴표를 **닫고 바깥 셸에서** `$x`를 확장한다.
- 인용 없는 `$VAR`는 IFS로 쪼개지고, 값 안의 따옴표는 인용이 아니라 글자다.
- dotenv를 `source`하면 값이 셸 문법을 거친다 — 데이터는 데이터 파서로 읽는다.
- glob `*`는 **0글자**도 매칭한다 — 가장 짧은 경계값을 테스트한다.
- heredoc 종료는 문자열 일치로만 결정된다 — 본문이 태그를 포함하면 나머지가 명령이 된다.
- `>>`는 파일 끝 개행을 확인하지 않는다.
