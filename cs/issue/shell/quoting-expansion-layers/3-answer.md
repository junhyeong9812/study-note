## 정답
<!-- 질문 1:1 대응 -->

1. **바깥 셸이 먼저 확장한다.** `'...'"$l"'...'`는 작은따옴표를 닫고, 큰따옴표 구간의 `$l`을 **바깥 셸**이 확장한 뒤, 다시 작은따옴표를 연다.\
바깥 셸에는 루프 변수 `l`이 없으므로 빈 값이 들어가고, 안쪽 `bash -c`는 `load /data//*` 같은 문자열을 받는다.\
그 결과 경로 glob이 깨져 일부 데이터만 적재됐다(416개 중 125개).\
고친 방법은 변수 루프를 버리고 종류별 명시 경로로 각각 적재한 것이다 — 셸이 아닌 언어의 glob 함수는 이 계층을 거치지 않아 애초에 안전했다.
   > **중첩 인용** — 인용 종류를 바꿔 이어 붙이는 기법. 각 조각이 어느 셸에서 해석되는지가 인용 경계로 결정된다.

2. **dotenv는 셸 스크립트가 아니다.** `source`는 파일을 셸 코드로 실행한다.\
값에 있는 `(`·`)`는 셸 메타문자라 서브셸·문법 오류로 해석되고, `$`·백틱·공백도 확장·분할을 거친다.\
dotenv 형식의 뜻은 "줄마다 key=value"일 뿐이므로 줄 단위로 읽어 첫 `=`에서 나누는 파서로 로드한다.

3. **word-split.** 인용 없는 `$AUTH`는 확장된 뒤 IFS(공백)로 쪼개져 `-c`, `credential.helper='!tool`, `auth'` 세 인자가 된다.\
값 안의 작은따옴표는 확장 **결과**의 일부라 인용으로 다시 해석되지 않는다 — 인용 해석은 확장보다 먼저 끝났다.\
그래서 인증 설정이 깨져 push가 실패했고, 인자를 명령에 인라인으로 적어 재실행했다(배열 `"${args[@]}"`도 같은 목적의 일반 도구다).
   > **word-split** — 인용되지 않은 확장 결과를 IFS 문자 기준으로 여러 인자로 나누는 셸 단계.

4. **파일 끝 개행.** POSIX 텍스트 파일의 마지막 줄은 개행으로 끝나야 하는데, 개행이 없으면 `>>`로 쓴 내용이 **기존 마지막 줄에 이어붙는다**.\
마지막 줄이 `pkg==1.0  # comment`였다면 결과는 `pkg==1.0  # commentnew-line` — 추가한 의존성이 통째로 주석이 되어 설치되지 않았다.\
추가 전에 파일 끝 개행을 확인하거나, 줄 삽입 도구로 별도 줄에 넣는다.

5. **glob `*`는 0글자도 매칭한다.** `*Test.java`는 `Test.java` 자체에도 매칭된다 — 접두어 0글자.\
그래서 도메인 클래스 `Test.java`·`Spec.java`가 테스트 파일로 오분류돼 로직 파일 쓰기가 허용됐다.\
"접미사 앞에 최소 한 글자"를 요구하려면 `?*Test.java`로 쓴다(`?` = 정확히 한 글자).\
교훈: 패턴 테스트에는 **가장 짧은 경계값**(접두어 0글자)을 넣는다.

6. **heredoc 조기 종료.** heredoc은 본문과 종료 태그를 **줄 문자열 일치**로만 구분한다.\
본문에 같은 태그 줄(또는 중첩 heredoc의 종료 줄)이 있으면 셸은 거기서 문서를 끝내고, 나머지 본문을 **명령으로 실행**한다.\
본문 뒷부분의 `git push ...` 문자열이 실제로 실행됐다(인자 오류로 무해하게 실패했을 뿐이다).\
복구는 셸을 거치지 않는 도구(python)로 파일에 덧붙이는 것이었다.

7. **계층을 다시 거치지 않는 방안.** 데이터는 데이터 파서로(dotenv 줄 파서), 경로는 셸 밖 glob 함수나 명시 경로로, 파일 쓰기는 인용 계층이 없는 도구로, 인자는 변수 문자열이 아니라 인라인·배열로 넘긴다.\
셸을 그대로 써도 괜찮은 경우는 입력 텍스트가 **해석 계층을 거쳐도 뜻이 변하지 않음을 보증**할 수 있을 때다 — 고정 리터럴, 인용된 단일 확장(`"$x"`), 본문에 태그가 나올 수 없는 heredoc.\
의도와 실행 사이 계층 수가 늘수록(`bash -c` 안의 `bash -c`) 검증 비용이 곱으로 커진다.

## 문제 구조 (추상화 코드)

### 변형 A — 중첩 인용에서 바깥 셸이 변수를 확장
① 문제 코드
```sh
nohup bash -c 'for l in css anim; do load /data/'"$l"'/*; done' &   # $l = 바깥 셸의 빈 값
```
② 고친 코드
```sh
nohup load /data/css/*  &          # 종류별 명시 경로
nohup load /data/anim/* &
```
무엇이 깨졌나: 인용 경계가 확장 주체(바깥 셸)를 바꿨다.

### 변형 B — dotenv를 셸로 source
① 문제 코드
```sh
. ./.env                            # DSN=user@tcp(host:3306)/db → ( ) 가 셸 문법
```
② 고친 코드
```sh
while IFS= read -r line; do
  case "$line" in ''|'#'*) continue ;; esac
  export "${line%%=*}=${line#*=}"   # 첫 '=' 기준 key/value, 값은 셸 해석 없음
done < ./.env
```
무엇이 깨졌나: 데이터 파일을 코드로 실행했다.

### 변형 C — 인용 없는 변수의 word-split
① 문제 코드
```sh
AUTH="-c credential.helper='!tool auth'"
git $AUTH push origin branch        # 3개 인자로 쪼개짐, 값 속 ' 는 글자
```
② 고친 코드
```sh
git -c "credential.helper=!tool auth" push origin branch     # 인자 인라인
# 또는 args=(-c "credential.helper=!tool auth"); git "${args[@]}" push ...
```
무엇이 깨졌나: 인용 해석이 확장보다 먼저 끝나므로 값 속 따옴표는 인자 경계를 만들지 못한다.

## 방안 비교

기본 방안(위 변형 A~C)은 "셸 확장 계층을 거치지 않도록 명시 경로·데이터 파서·인라인 인자를 쓴다"이다. 같은 원리(셸 계층이 텍스트를 다시 해석해 의도가 바뀜)에 다른 방안이 쓰인 사례:

### 방안 1 — `>>` 전에 파일 끝 개행을 확인
```sh
# 문제: 마지막 줄 무개행 → 이어붙음
echo "pkg-b==2.0" >> requirements.txt          # → "pkg-a==1.0  # commentpkg-b==2.0"
# 고친
[ -n "$(tail -c1 requirements.txt)" ] && echo >> requirements.txt
echo "pkg-b==2.0" >> requirements.txt
```

### 방안 2 — glob에 최소 길이를 명시
```sh
# 문제: * 는 0글자 매칭 → Test.java 도 테스트 파일
case "$base" in *Test.java|*Spec.java) is_test=1 ;; esac
# 고친
case "$base" in ?*Test.java|?*Spec.java) is_test=1 ;; esac
# + 회귀 테스트: 접두어 0글자 이름
```

### 방안 3 — heredoc 대신 셸 해석이 없는 도구로 쓰기
```sh
# 문제: 본문에 종료 태그(또는 중첩 heredoc)가 있으면 조기 종료 → 나머지가 명령
cat >> fixture.sh << 'EOF'
...
EOF          # ← 본문 속 줄에서 여기서 끝남
git push ... # ← 명령으로 실행됨
EOF
# 고친
python3 - fixture.sh <<'PY'
import sys; open(sys.argv[1], "a").write(BODY)   # 본문은 파일·변수로 전달
PY
```
같은 구조: 셸 명령 문자열을 검사하는 도구 쪽에서는 "heredoc 첫 태그 추출" 로직으로 본문을 명령과 구분하도록 고쳤다.

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|------|------|------|-----------|-----------|
| 기본: 확장 계층 회피 | 동적 값을 셸 문자열로 조립하지 않아도 된다 | 명시 경로·파서 작성 | 목록이 길면 반복 코드 | 변수·데이터 값을 명령에 넣을 때 |
| 1. 개행 확인 후 추가 | 대상 파일이 줄 단위 텍스트다 | 한 줄 | 확인을 빼먹으면 재발 | 설정·목록 파일에 줄 추가 |
| 2. `?*` 최소 길이 | 패턴이 "접두어 + 접미사"를 뜻한다 | 없음 | 다른 경계(대소문자 등)는 별도 | 파일명 분류 glob |
| 3. 셸 밖 도구로 쓰기 | 본문 내용을 통제할 수 없다 | 도구 의존 | 도구 호출 자체의 인용은 여전히 셸 | 본문에 셸 문법·태그가 섞일 수 있을 때 |

**결론**: 값이 셸을 **통과해야 할 이유가 없으면** 통과시키지 않는다(기본·3).\
셸 안에서 처리해야 하면 그 계층의 경계값을 명시한다 — glob은 최소 길이(2), 덧붙이기는 파일 끝 개행(1).\
어느 쪽이든 가장 짧은·비어 있는·태그가 섞인 입력으로 한 번 반증해 본다.
