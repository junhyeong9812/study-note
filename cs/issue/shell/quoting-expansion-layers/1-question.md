## 질문
1. (예측) `nohup bash -c 'for l in css anim; do load /data/'"$l"'/*; done' &` — 작성자는 안쪽 루프 변수 `$l`을 의도했다. 실제로 `$l`은 어느 셸에서, 언제 확장되며, 안쪽 `bash -c`가 받는 문자열은 무엇인가?
2. (왜) dotenv 파일(`KEY=value` 줄들)을 `. .env`로 불러오면 `DSN=user@tcp(host:3306)/db` 같은 값에서 무엇이 일어나는가? "dotenv는 셸 스크립트가 아니다"를 설명하라.
3. (예측) `AUTH="-c credential.helper='!tool auth'"; git $AUTH push` — 인용 없는 변수 확장 `$AUTH`는 몇 개의 인자로 쪼개지고, 작은따옴표는 왜 인용으로 동작하지 않는가?
4. (경계) 마지막 줄에 개행이 없는 파일에 `echo "new-line" >> file`을 하면 어떻게 되는가? 그 마지막 줄이 `pkg==1.0  # comment`였다면 추가한 내용은 어떤 운명이 되는가?
5. (경계) `case "$name" in *Test.java) ...` 패턴은 "Test로 끝나는 테스트 파일"을 의도했다. 이름이 정확히 `Test.java`인 파일은 매칭되는가? 가장 짧은 경계값을 막으려면 패턴을 어떻게 바꾸는가?
6. (왜) `cat >> fixture << 'EOF'`로 붙인 본문 안에 같은 태그 줄(또는 중첩 heredoc)이 있으면 무엇이 일어나는가? 본문 뒷부분에 `git push ...` 문자열이 있었다면?
7. (연결) 1~6은 모두 "쓴 텍스트"와 "셸이 실행하는 명령" 사이에 해석 계층(인용·확장·word-split·glob·heredoc·파일 끝 개행)이 끼어 의도가 바뀐 사례다. 셸 계층을 **다시 거치지 않는** 방안들은 무엇이고, 언제 셸을 그대로 쓰는 게 괜찮은가?
