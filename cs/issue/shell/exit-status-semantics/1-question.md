## 질문
1. (예측) `build-tool test | tail -20; echo $?` — 빌드 도구가 테스트 실패로 비0을 반환했다. 출력되는 `$?`는 무엇이고 왜 그런가? `pipefail`과 `${PIPESTATUS[0]}`는 각각 이것을 어떻게 바꾸는가?
2. (왜) `-e` 없이 `step1; step2; step3`로 이어 쓴 배치 스크립트가 매일 실패하는데 스케줄러에는 6일 내내 `SUCCESS`로 찍혔다. 스크립트의 종료 코드는 어느 명령의 것인가? 단계별로 무엇을 해야 하는가?
3. (경계) `{ cat "$SRC"; printf '%s\n' "$LINE"; } > "$TMP" && mv "$TMP" "$SRC"` — `cat`이 읽기에 실패하면 무엇이 일어나는가? "그룹 전체의 종료 코드"가 앞 단계 실패를 어떻게 가리며, 그 결과 원본에 무슨 일이 생기는가?
4. (왜) 종료 코드 자체가 호출자와의 **계약**인 프로그램(예: exit 0=통과, exit 2=차단인 훅)에 `set -e`를 걸었다. 손상된 JSON에서 `jq`가 exit 2로 죽거나, `$(( 09 ))`가 8진수 오류를 내면 호출자는 무엇을 받는가? 왜 이것이 "사용자 프롬프트 차단" 같은 엉뚱한 결과가 되는가?
5. (경계) `grep`이 매칭 0건일 때, `iconv`가 불완전 멀티바이트 꼬리를 만났을 때 각각 비0을 반환한다. 이것은 "실패"인가? 비0을 곧바로 폴백 조건으로 쓰면 어떤 회귀가 생기는가?
6. (연결) `head -400`으로 입력을 자르는 것과 `| tail`로 종료 코드를 가리는 것은 같은 부류의 사고다 — 무엇이 공통인가? 각각 무엇으로 반증하는가?
7. (연결) 이 카드의 모든 변형은 "종료 코드 0 ≠ 산출물이 올바름"의 셸 버전이다. 종료 코드 대신(또는 함께) 무엇을 확인해야 하는가?
