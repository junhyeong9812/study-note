# cs/issue/shell/exit-status-semantics — 정답

> 복습 시 이 파일은 **최후에만** 연다.
> ⚠️ 이 정답은 Claude 초안(2026-09-24) — 사건 기록 기준. 복습 전 읽지 말 것.

태그: `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **파이프라인의 rc = 마지막 명령.** `$?`는 `tail`의 종료 코드 0이다 — 빌드 도구의 실패는 사라진다.\
`set -o pipefail`을 켜면 파이프라인의 rc가 "비0으로 끝난 가장 오른쪽 명령"의 것이 되어 앞 단계 실패가 드러난다.\
`${PIPESTATUS[0]}`는 파이프라인 각 명령의 rc 배열이라 원 명령의 rc를 직접 꺼낼 수 있다.\
기록된 해결은 원 명령의 출력을 로그 파일로 받고 rc를 마커로 남기는 것이었다: `(cmd > log 2>&1; echo "EXIT=$?" >> log)`.
   > **pipefail** — 파이프라인 중 하나라도 실패하면 파이프라인 전체를 실패로 보게 하는 bash 옵션.

2. **순차 명령의 rc = 마지막 명령.** `-e` 없이 이어 쓴 스크립트의 종료 코드는 마지막 명령의 것이다.\
중간 단계가 매번 traceback으로 죽어도 마지막 명령이 성공하면 스크립트는 0으로 끝나고, 스케줄러는 SUCCESS를 기록한다.\
단계마다 rc를 캡처해 누적하고 마지막에 `exit "$rc"`로 내보낸다.\
실패 알림 경로(스케줄러의 실패 훅)도 없어서 발견이 늦었다 — rc가 정직해도 그것을 듣는 쪽이 있어야 한다.

3. **그룹 리다이렉트는 앞 단계 실패를 삼킨다.** `{ cat; printf; }`의 rc는 `printf`의 것이다.\
`cat`이 읽기에 실패해도 `printf`가 성공하면 그룹은 0 → `&& mv`가 실행되어 **새 줄 하나만 든 TMP가 원본을 덮어쓴다**.\
단계마다 rc를 검사해 실패하면 TMP를 지우고 빠져나가야 한다.\
같은 부류: `{ ... } >> "$LOG"`에서 리다이렉트 대상에 쓸 수 없으면 블록이 실행되지 않는다 — 그 그룹의 rc는 1(bash)이지만 아무도 검사하지 않아 스크립트는 뒤 명령의 rc로 성공처럼 끝났다 — 로그 쓰기 가능 여부를 먼저 검사하고 전용 rc로 끝낸다.

4. **errexit와 종료 코드 계약.** `set -e`는 예상 못 한 하위 명령 실패를 "그 명령의 rc로 즉시 종료"로 바꾼다.\
`jq`가 손상 JSON에 exit 2를 내면 스크립트도 exit 2로 끝나는데, 호출자 계약에서 2는 "차단"이다 — 파싱 오류가 사용자 프롬프트 차단으로 둔갑한다(사건 환경 기준 — 입력 파싱 오류의 jq 종료 코드는 버전마다 다르다(예: jq 1.7은 5). 어느 값이든 계약 밖 코드이거나 우연히 계약 코드와 겹친다는 점이 문제다).\
`$(( 09 ))`는 선행 0 때문에 8진수로 해석되어 오류가 난다 — 이것은 `set -e`와 무관하게 비대화형 bash를 즉시 종료시키는 확장 오류라(rc 1) 역시 계약 밖 조기 종료다.\
교정: jq 대입은 실패 시 빈 값을 주는 헬퍼로, 산술은 `10#$n`으로 10진 강제, `jq -e .`는 비객체 JSON(`5`)도 통과시키므로 `type=="object"`로 검사, 명령 치환은 `|| VAR=""` 가드.\
모든 실패가 exit 0으로 수렴해야 하는 관측 전용 스크립트는 아예 `set -e`를 쓰지 않았다.
   > **errexit(set -e)** — 명령이 비0을 반환하면 셸을 즉시 종료시키는 옵션. `if`/`while` 조건, `&&`·`||` 목록의 마지막이 아닌 명령, `!` 부정, (pipefail 없을 때) 파이프라인의 마지막이 아닌 명령은 예외.

5. **비0 ≠ 실패.** `grep`의 1은 "매칭 없음"이라는 정상 결과이고, `iconv`는 불완전 꼬리를 만나면 유효한 접두를 이미 출력한 뒤 비0을 낸다.\
`grep ... && 다음단계`는 매칭 0건에서 다음 단계를 조용히 건너뛴다.\
`out=$(iconv ...) || out="$raw"`처럼 비0을 "읽기 실패 폴백"으로 쓰자, 정상적인 부분 변환이 매번 폴백으로 빠져 원시 절단(문자 중간이 잘린 바이트열)으로 회귀했다.\
교정은 `out=$(iconv ... || true)` — rc는 무시하고 **출력을 채택**, 출력이 없을 때만 폴백.

6. **자르기와 가리기.** 둘 다 "오류 신호 없이 정보가 사라진다"가 공통이다.\
`head -400`은 초과분을 rc 0으로 버려서, 잘린 입력을 받은 소비자(리뷰어)가 판정할 근거를 잃었다 — 소비자는 입력이 잘렸다는 사실을 모른다.\
반증: 자른 경우 절단 구간을 직접 다시 확인하고, 종료 코드는 원 명령의 rc 마커로 판정한다.

7. **rc 너머를 본다.** 종료 코드 0은 "마지막 명령이 0을 냈다"일 뿐이다.\
빌드·테스트는 리포트 파일(BUILD 결과·테스트 수)을 직접 읽고, 배치는 단계별 rc와 산출물을 확인하고, 스텁으로 각 실패 경로를 일부러 재현해 **기대한 종료 코드가 나오는지** 음성 검증한다.\
테스트 수가 워커마다 다르게 보고되면 메인이 직접 재실행해 정합을 확인한다.

## 문제 구조 (추상화 코드)

### 변형 A — 파이프라인이 원 명령의 실패를 가림
① 문제 코드
```sh
build-tool test 2>&1 | tail -25          # rc = tail = 0
echo "exit=$?"                           # 0 → "green" 보고
build-tool verify | grep -E 'Tests|BUILD' | tail -5
```
② 고친 코드
```sh
( build-tool verify > build.log 2>&1; echo "EXIT=$?" >> build.log )
grep -q '^EXIT=0$' build.log || fail "build failed"
# 또는
build-tool test | tail -25; rc=${PIPESTATUS[0]}
# 또는 스크립트 상단
set -o pipefail
```
무엇이 깨졌나: 파이프라인의 rc가 마지막 명령(tail)의 것이었다.\
같은 구조: 빌드 실패를 모른 채 다음 단계(기존 서비스 정지)로 진행 → 교체는 빌드 성공 확인 뒤에만.

### 변형 B — `-e` 없는 순차 스크립트
① 문제 코드
```sh
echo "--- step A ---"; run step_a
echo "--- step B ---"; run step_b          # 스크립트 rc = 마지막 명령
```
② 고친 코드
```sh
rc=0
run step_a; a_rc=$?
if [ "$a_rc" -ne 0 ]; then echo "!!! step_a failed (exit=$a_rc)"; rc=$a_rc; fi
run step_b; b_rc=$?
if [ "$b_rc" -ne 0 ]; then echo "!!! step_b failed (exit=$b_rc)"; rc=$b_rc; fi
exit "$rc"
```
무엇이 깨졌나: 중간 단계 실패가 스크립트 종료 코드에 반영되지 않았다.

### 변형 C — 그룹 리다이렉트
① 문제 코드
```sh
{ cat "$SRC"; printf '%s\n' "$LINE"; } > "$TMP" && mv "$TMP" "$SRC"   # cat 실패 → 원본 덮어씀
{ main_body; } >> "$LOG"                                             # LOG 쓰기 불가 → 본문 미실행 (그룹 rc 1, 미검사 → 스크립트는 성공처럼 종료)
```
② 고친 코드
```sh
cat "$SRC" > "$TMP"            || { rm -f "$TMP"; exit 0; }   # 사건은 관측 전용 훅이라 0으로 수렴 — 일반 스크립트면 비0으로 끝낸다
printf '%s\n' "$LINE" >> "$TMP" || { rm -f "$TMP"; exit 0; }
mv -f "$TMP" "$SRC"            || rm -f "$TMP"

[ -w "$LOG_DIR" ] || exit 90                                         # 로그 쓰기 사전검사 (전용 rc)
```
무엇이 깨졌나: 복합 명령의 rc가 마지막 단계의 것이라 앞 단계 실패가 가려졌다.

### 변형 D — 종료 코드가 계약인 스크립트의 errexit
① 문제 코드
```sh
set -eu
field=$(printf '%s' "$input" | jq -r '.field')      # 손상 JSON → jq 비0(사건 버전 2) → 스크립트 exit 2 (= 차단)
n=$(( ts ))                                         # ts=09 → 8진수 오류 → 조기 종료 (set -e 무관, rc 1)
printf '%s' "$input" | jq -e . >/dev/null           # 5 같은 비객체도 통과 → 이후 필드 접근에서 사망
```
② 고친 코드
```sh
set -eu
jqr() { printf '%s' "$input" | jq -r "$1" 2>/dev/null || true; }   # 실패 = 빈 값(무해)
field=$(jqr '.field')
n=$(( 10#$ts ))
printf '%s' "$input" | jq -e 'type=="object"' >/dev/null 2>&1 || { echo "warn: bad input" >&2; exit 0; }
val=$(some_subst) || val=""
```
무엇이 깨졌나: "모든 실패 = 즉시 종료"가 호출자와의 종료 코드 계약(0/2)을 깨뜨렸다.\
같은 구조: 빈 stdin이 경고 없이 통과, 날짜 파싱 실패로 조기 종료 → 경고 1줄·승인 무효로 처리.

### 변형 E — 명령별 비0 의미를 실패로 오해
① 문제 코드
```sh
grep -q "$pat" "$f" && invoke_next_step            # 0건 = rc 1 → 후속 단계 미발화
out=$(iconv -f A -t B -c <<<"$raw") || out="$raw"   # 불완전 꼬리 rc≠0 → 정상 경로가 폴백으로
head -400 packet > review_input                    # 초과분 무음 절단
```
② 고친 코드
```sh
out=$(iconv -f A -t B -c <<<"$raw" || true)          # 출력 채택, 부재만 폴백
[ -n "$out" ] || out="$fallback"
# grep 0건은 정상 결과로 분기 처리, 잘린 입력은 절단 구간을 따로 재확인
```
무엇이 깨졌나: 비0을 일률적으로 "실패"로 해석했다.\
같은 구조: 문자열 길이를 문자 수(`${#s}`)와 바이트(`%.120s`)로 섞어 재서 UTF-8 문자 중간이 잘림 → 길이는 바이트 단위로 통일.
