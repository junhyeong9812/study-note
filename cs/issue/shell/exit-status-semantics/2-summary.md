# cs/issue/shell/exit-status-semantics — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
복합 명령의 종료 코드 = "마지막" 명령의 종료 코드

  A | B | C            → C 의 rc     (A 실패는 사라짐)     교정: pipefail / PIPESTATUS / 로그 파일 + rc 마커
  A; B; C  (-e 없음)   → C 의 rc     (A·B 실패 사라짐)     교정: 단계별 rc 캡처 → exit "$rc"
  { A; B; } > F        → B 의 rc     (A 실패가 B 성공에 가림) 교정: 단계마다 || { 정리; 탈출; }
  { ... } >> LOG       → 리다이렉트 실패 시 블록 미실행인데 성공처럼 끝남 → 쓰기 사전검사

errexit (set -e) = "모든 비0 = 즉시 종료"
  종료 코드가 계약인 프로그램(훅: 0=통과, 2=차단)
    jq 파싱 실패(2) · $((09)) 8진수 오류 · 치환 실패
      → 계약 밖 코드로 조기 종료 → 호출자는 "차단"으로 해석
  교정: 실패=무해한 값 헬퍼 · 10#$n · 타입 검사 · || VAR="" · 필요 구간 set +e

명령별 비0 의미 (비0 ≠ 실패)
  grep 0건 = 1   → && 체인 끊김, 후속 호출 미발화
  iconv 불완전 꼬리 = 비0 (유효 접두는 이미 출력) → 폴백 트리거로 쓰면 자충 회귀
  head -N = 초과분을 오류 없이 버림 (rc 0, 조용한 절단)
```

## 핵심 문장

- 파이프라인·그룹·순차 명령의 종료 코드는 **마지막 명령**의 것이다 — 앞 단계 실패는 명시적으로 캡처하지 않으면 사라진다.
- `| tail`·`| grep`을 붙인 뒤의 `$?`는 **tail의 것**이다 — 결과 판정은 원 명령의 rc 마커나 리포트 파일로 한다.
- errexit는 종료 코드가 계약인 프로그램에서 **계약 밖 코드**를 낸다 — 실패를 무해한 값으로 수렴시키는 쪽이 안전하다.
- 비0은 명령마다 의미가 다르다(grep 0건·iconv 부분 변환) — rc를 곧바로 분기 조건으로 쓰지 말고 **출력 자체**를 본다.
- 자르기(`head`)와 가리기(`| tail`)는 둘 다 "오류 없이 정보가 사라지는" 사고다 — 끝까지 읽었나, 원 rc인가를 반증한다.
