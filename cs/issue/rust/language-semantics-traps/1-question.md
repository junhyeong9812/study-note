## 질문
1. (예측) `for id in self.registry().ids() { self.kill(id); }` — `registry()`는 `Mutex`를 잠가 가드를 돌려주고, `kill()`도 같은 락을 잠근다. 이 코드는 무엇을 하는가? 가드 임시값은 언제 drop되는가? `match reg.lock().reserve(id) { ... sleep ... }`도 같은 문제를 갖는 이유는?
2. (경계) 위 교착을 고치는 방법 두 가지를 쓰라. "가드를 이름 있는 변수로 묶기"와 "락 안에서 필요한 것만 `collect()`로 꺼내고 락 없이 순회"는 각각 락을 얼마나 오래 쥐는가?
3. (왜) 프로젝트 경로를 해시해 영속 폴더 이름으로 쓰려 한다. 표준 `HashMap`의 기본 해셔(`RandomState`)나 `DefaultHasher`를 쓰면 왜 안 되는가? 표준 해셔가 그렇게 설계된 이유는?
4. (예측) 외부에서 받은 토큰 사용량을 `u64`로 누적한다. 값이 `u64::MAX` 근처로 들어오면 debug 빌드와 release 빌드에서 각각 무슨 일이 일어나는가? 외부 입력을 누적할 때 필요한 것은?
5. (예측) `password.or(lookup_keychain(id))` — 비밀번호 인자가 이미 있어도 키체인 조회가 일어나는가? 사용자에게는 어떤 증상으로 보이는가? `or`와 `or_else`의 차이는?
6. (경계) PTY 라이브러리의 `take_writer()`를 연결(attach)마다 호출했더니 첫 연결만 동작했다. "take" 이름이 붙은 API가 말하는 소유권 계약은 무엇이고, 여러 소비자가 필요하면 어떻게 나눠야 하는가?
7. (연결) 이 함정들은 모두 컴파일이 통과한 뒤에 드러났다. 각각을 코드 리뷰·테스트에서 잡으려면 무엇을 보면 되는가? (임시값 수명·해셔 시드·오버플로 정책·즉시 평가·1회 취득)
