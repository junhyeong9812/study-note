## 질문
1. (예측) `#[serde(tag = "event")] enum Event { Delta { entries: BTreeMap<u64, String> } }`를 JSON으로 직렬화하면 성공한다. 같은 JSON을 다시 역직렬화하면? 에러 메시지는 무엇이라고 말할까?
2. (왜) 같은 `BTreeMap<u64, String>`을 enum 밖의 평범한 struct 필드로 두면 역직렬화가 된다. internally tagged enum 안에서만 실패하는 이유를 "태그를 찾기 위한 버퍼링"으로 설명하라.
3. (경계) 이 결함은 기존 단위 테스트를 모두 통과했고, 실제 에이전트로 돌린 스모크에서야 드러났다. 테스트 픽스처의 무엇이 이 결함을 가렸는가? "쓰기 쪽은 정상"이라는 사실은 왜 발견을 더 늦추는가?
4. (예측) 빠른 우회로 필드 타입을 `BTreeMap<String, String>`으로 바꿨다. 키가 `1, 2, 10`이면 직렬화된 순서는? "와이어 바이트는 바뀌지 않는다"는 주장은 참인가?
5. (연결) 올바른 교정은 필드 단위 코덱(`#[serde(with = "...")]`)이었다. 역직렬화 쪽과 직렬화 쪽은 각각 무엇을 해야 하는가? 이 코덱이 제거되면 즉시 실패하는 테스트("이빨")는 왜 필요한가?
6. (경계) JSON 객체 키는 항상 문자열이다. 그렇다면 평범한 struct에서 `u64` 키 맵이 동작하는 것은 누가 변환해 주기 때문인가? 중간 버퍼(Content)를 거치면 그 변환이 왜 사라지는가?
