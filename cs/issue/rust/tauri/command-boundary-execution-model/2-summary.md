# cs/issue/rust/tauri/command-boundary-execution-model — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[웹뷰] invoke("cmd") ──IPC──▶ 커맨드 경계
                               │
        ┌──────────────────────┼─────────────────────────────┐
        │ #[command] fn         │ #[command] async fn          │
        │  → 메인(UI) 스레드     │  → async 런타임 워커          │
        │  블로킹 120s           │  본문에서 직접 블로킹          │
        │  💥 창 전체 프리즈      │  ⚠ 워커 점유 (차선)            │
        │                       │  spawn_blocking(본문)         │
        │                       │  ✓ 블로킹 전용 풀 (최선)       │
        └──────────────────────┴─────────────────────────────┘

[async 소비자로 보내기]
   sync 커맨드 ──blocking_send──▶ [bounded 채널: 가득] ──▶ 네트워크 루프 (연결·키 확인 대기 중)
        💥 호출 스레드가 소비자 속도에 묶여 멈춤
   교정: try_send (가득 차면 에러, 절대 안 막힘)
         resize 는 최신값만 (watch 병합) · 생성은 id 즉시 반환 · 연결은 백그라운드
         ready 전 입력은 큐에 버퍼 · 상태는 이벤트로 통지

[실패 전달]
   커맨드 안 expect/panic   💥 호출자는 구조화된 에러를 못 받음 · 프로세스 안정성 저하
   교정: io::Result 로 전파 → 앱 에러로 매핑 (JoinError 도 동일)
```

## 핵심 문장

- Tauri 동기 커맨드는 **메인(UI) 스레드**에서 돈다 — 블로킹하면 창 전체가 멈춘다.
- async 커맨드는 런타임 워커에서 돌지만, 본문의 블로킹 호출은 **워커를 점유**한다 — 블로킹 본문은 `spawn_blocking`으로 전용 풀에 보낸다.
- 동기 호출자가 async 소비자에게 **블로킹 전송**을 하면 소비자의 지연이 호출 스레드 정지로 전파된다 — `try_send` + 최신값 병합.
- 커맨드 경계는 **panic 대신 `Result`** 다 — 자원 할당 실패·태스크 실패도 값으로 전파해 호출자가 구조화된 에러를 받게 한다.
