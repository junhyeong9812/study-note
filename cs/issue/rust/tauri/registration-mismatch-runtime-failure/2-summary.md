# cs/issue/rust/tauri/registration-mismatch-runtime-failure — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.

## 전체 흐름

```
[선언]  권한 목록(capability) / DI 등록(.manage)       ← 파일 A
[사용]  plugin 커맨드 invoke / State<T> 요구            ← 파일 B
        두 곳을 대조하는 장치 = 컴파일러에 없음

컴파일  ── 통과 (권한은 JSON, State<T>는 제네릭)
테스트  ── 통과 (커맨드를 함수로 직접 호출 → 권한·DI 계층 우회)
런타임  ── invoke
            │
            ├─ 권한 없음 ──▶ 예외 throw ──▶ 호출부가 삼킴 ──▶ 기능 전체 무음 사망
            │                                   (열거 실패 → 이후 fallback까지 실패)
            └─ 타입 키 불일치 ──▶ "state not managed" ──▶ 커맨드가 절대 실행 안 됨

[교정]
  ① 선언을 사용처와 함께 추가 (새 커맨드 = 권한 동반, 창 라벨별 파일 둘 다)
  ② 등록 목록을 한 곳(register())으로 모으고
     "커맨드가 요구하는 State<T> ⊆ 등록 목록"을 대조하는 테스트
  ③ 보조 경로는 실패 시 안전한 기본값으로 폴백 (핵심 기능 유지)
```

## 핵심 문장

- 정적 권한 모델은 **런타임 승인 절차가 없다** — 빠진 권한은 묻지 않고 거부되고, 호출부가 예외를 삼키면 에러 없이 기능이 사라진다.
- 권한은 **창 라벨 패턴 단위**다 — 한 창에서 되는 것이 다른 창에서도 된다는 보장이 없다.
- 타입 키 DI에서 `T`와 `Arc<T>`는 **다른 키**다 — 등록과 요청이 어긋나면 컴파일·단위테스트는 통과하고 런타임에만 실패한다.
- 단위 테스트가 커맨드를 직접 부르면 권한·DI 계층을 **우회**하므로 이 부류를 원리적으로 못 본다.
- 재발 방지는 "조심"이 아니라 **선언 목록과 사용 목록을 대조하는 장치**(한 곳 등록 + 대조 테스트)다.
