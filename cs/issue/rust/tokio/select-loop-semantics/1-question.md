## 질문
1. (예측) `loop { select! { Some(msg) = rx.recv() => ..., Some(inp) = input.recv() => ... } }`에서 원격이 채널을 닫아 `rx.recv()`가 `None`을 반환하면 루프는 끝나는가? 두 분기가 모두 `None`이 되면 무엇이 일어나는가?
2. (왜) `watch::Receiver::changed()`는 송신측이 drop된 뒤 `Err`를 반환한다. 이 `Err`를 무시하고 루프를 계속 돌면 왜 CPU를 태우는 busy loop가 되는가? "닫힌 채널은 영원히 준비 상태"를 설명하라.
3. (왜) 입력 분기 본문에서 큰 붙여넣기를 `channel.write(...).await`로 끝까지 보내는 동안 출력이 멈췄다. 8KB 청크로 쪼개는 루프를 **같은 분기 본문 안에** 두는 1차 수정은 왜 효과가 없었는가?
4. (연결) 흐름제어 창(window)이 있는 양방향 채널에서, 쓰기가 상대의 창 열림(WINDOW_ADJUST)을 기다리는 동안 읽기를 멈추면 왜 **자기 자신을 가두는** 교착이 되는가? 창 열림 메시지를 배달하는 연결 루프가 수신 큐가 차면 멈춘다는 사실과 엮어 원을 그려라.
5. (경계) 교착 해결로 "읽기·쓰기를 독립 future로 나눠 `join!`으로 동시에 poll"을 골랐다. 두 future 사이에 신호가 2개(쓰기 허가, 채널 종료) 필요했다 — 종료 신호가 없으면 무엇이 영원히 끝나지 않는가?
6. (예측·실험 설계) 기본 창 크기(2MB)에서 옛 구조(대조군)와 새 구조(처치군)를 돌렸더니 **둘 다** 교착하지 않았다. 이 결과로 "새 구조가 교착을 고쳤다"고 말할 수 있는가? 무엇을 먼저 확인해야 했는가?
7. (왜) `Builder::new_current_thread().build()`로 만든 런타임에서 TCP I/O가 진행되지 않는다. 무엇이 빠졌고, 그것이 없으면 소켓 readiness는 누가 통지하는가?
