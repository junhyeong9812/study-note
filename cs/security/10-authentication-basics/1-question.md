# security/10-authentication-basics — 질문

## 질문

1. (왜) 비밀번호를 안전하게(salt + 느린 KDF) 저장하는 서비스도 크리덴셜 스터핑에 계정을 빼앗긴다. 왜 저장 방식으로는 못 막나? 무엇이 막나?
2. (경계) "비밀번호 + 비밀 질문", "비밀번호 + SMS OTP", "비밀번호 + WebAuthn 보안 키" 가운데 MFA가 아닌 것은? MFA인 것 중 NIST SP 800-63B-4 기준으로 피싱 저항인 것은? 이유를 대라.
3. (그림) TOTP 한 값이 만들어지는 과정을 그려라. T는 어떻게 구하고, HMAC 출력 20바이트에서 6자리는 어떻게 뽑나? 최상위 비트는 왜 버리나?
4. (예측) RFC 6238 부록 B 표의 SHA-256 값을 재현하려고 비밀 "12345678901234567890"(20바이트)으로 HMAC-SHA-256 TOTP를 계산했다. 시각 59에서 46119246이 나올까? 아니라면 무엇이 다른가?
5. (적용) TOTP 검증기를 짤 때 허용 창은 몇 칸으로 하고, 같은 30초 칸 안에 같은 코드가 두 번 오면 어떻게 하나? 그 규칙을 동시 요청에서도 지키려면?
6. (장애 진단) 로그인 실패 메시지는 이미 "아이디 또는 비밀번호가 올바르지 않습니다"로 통일했는데, 계정 존재 여부가 여전히 새어 나간다는 보고를 받았다. 어디를 의심하고 어떻게 고치나?
7. (장애 진단) 한 직원 계정에 1분 동안 MFA 푸시가 30건 갔고 마지막 1건이 승인됐다. 무슨 일이 일어났고, 즉시 할 일과 재발 방지책은?
8. (연결) WebAuthn에서 사용자가 피싱 사이트 `bank-login.example`에 접속해 보안 키를 눌렀다. 공격자가 받은 응답을 진짜 `bank.example`에 중계해도 통하지 않는 이유를 두 가지 대라. 서버 DB가 유출되면 비밀번호·TOTP와 무엇이 다른가?
9. (장애 진단) MFA 공급자 장애 동안 2단계 없이 로그인이 됐다. 로그와 코드에서 무엇이 보일 것이고, 가용성을 지키면서 fail-closed로 바꾸려면?
