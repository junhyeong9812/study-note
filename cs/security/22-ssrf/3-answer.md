# security/22-ssrf — 정답

## 정답

### 1. 외부 요청인데 위험한 이유

- SSRF 요청을 보내는 주체가 **방화벽 안쪽의 서버**다. 공격자 자신은 바깥에서 내부 주소(10/8·169.254.169.254·localhost)에 못 가지만, 서버는 간다.
- 그래서 서버를 발판 삼아 외부에서 닿을 수 없는 내부 서비스·클라우드 메타데이터·루프백 서비스를 두드린다. OWASP A10: 방화벽·VPN 같은 네트워크 보호를 우회한다.

### 2. 서버에는 SOP가 없다

- 브라우저의 SOP는 교차 출처 응답 읽기를 막지만, 서버 측 HTTP 클라이언트에는 그런 기본 경계가 없다. 서버는 자기 권한으로 어디든 요청하고 응답을 읽는다.
- 따라서 방어를 애플리케이션(허용 목록·주소 검사·리다이렉트 금지)과 네트워크(egress 방화벽)에서 **직접** 만들어야 한다.

### 3. 이름이 아니라 해석된 주소

- 최종적으로 소켓이 연결하는 것은 이름이 아니라 **IP 주소**다. 이름 검사는 그 이름이 무엇으로 해석되는지를 보지 않는다.
- DNS rebinding이 이름 검사를 우회한다: 검사 시점엔 외부 주소를, 연결 시점엔 내부 주소를 주도록 공격자가 짧은 TTL로 DNS를 바꾼다(TOCTOU). 그래서 해석된 주소를 검사하고, 그 주소로 직접 연결해야 한다.

### 4. contains 우회

- 통과한다. `169.254.169.254.partner.example.attacker.test`는 `partner.example`을 문자열로 포함하지만 실제 등록 도메인은 `attacker.test`다. 실험의 `naive`가 이렇게 뚫렸다(`naive=ALLOW`).
- 올바른 검사: URL을 파싱해 **호스트 전체**를 허용 집합과 정확히 비교한다(21번 Origin 검사와 같은 교훈). 실험 `guarded=DENY host=...`.

### 5. 허용 이름이 내부로 해석

- 안전한 가드는 **거부**한다. 호스트 이름 허용 목록은 통과하지만, 그 다음 단계에서 해석된 모든 주소를 CIDR 내부 대역과 비교해 `10.0.0.5`가 사설망(RFC 1918)이라 거부한다.
- 실험: `img.partner.example`(허용 이름) → `guarded=DENY resolved=10.0.0.5`. 이름만 믿으면 내부로 간다.

### 6. 리다이렉트 기본값

- 실험(OpenJDK 21.0.12): `HttpClient`는 `followRedirects()=NEVER`(안 따라감), `HttpURLConnection`은 `getFollowRedirects()=true`(따라감).
- 단 `HttpURLConnection`은 스킴이 같은 리다이렉트만 따라간다(`https`→`http`는 안 따라감 — OpenJDK 소스, 재실험 `http`→`https`는 302 그대로). 그래서 `https`로 시작한 요청이 `http://169.254.169.254/`로 가는 302는 기본 설정에서도 따라가지 않는다. 위험한 것은 같은 스킴의 내부 대상(예시: `https://10.0.0.5/`)이다.
- 대처: 리다이렉트를 끄거나(가능하면), 끌 수 없으면 리다이렉트 **매 홉마다** 가드를 다시 적용한다. OWASP A10도 "HTTP 리다이렉션 비활성화"를 든다. 쓰는 클라이언트의 기본값을 반드시 확인한다.

### 7. IMDSv2

- IMDSv2는 세션 토큰을 `PUT`으로 받아(`X-aws-ec2-metadata-token`) `GET`에 실어야 메타데이터를 준다. `PUT` 응답 홉 제한은 기본 `1`이다(AWS "Use IMDSv2"). 단 계정 기본값을 IMDSv2로 두면 새 인스턴스는 `2`, 홉 제한을 따로 정하지 않았고 AMI가 `ImdsSupport: v2.0`이면 `2`, 컨테이너 환경 권장도 `2`다.
- 단순 SSRF는 임의 헤더나 `PUT`을 넣지 못하는 경우가 많아 토큰을 못 받는다. 홉 제한 1은 한 홉 더 거치는 경로(브리지 네트워크의 컨테이너 등)로 토큰 응답이 닿지 않게 한다.
- 이것은 **심층 방어**다. 1차 방어는 애플리케이션의 URL 검증과 egress 방화벽이다.

### 8. deny list 우회

- `127.0.0.1`은 `0x7f.0.0.1`(16진), `2130706433`(32비트 10진), `127.1`, `[::ffff:127.0.0.1]` 등 여러 표기로 같은 주소를 가리킨다(`inet_aton` 계열 파서 기준 — 점검에서 python3 `socket.inet_aton`으로 앞의 셋이 `127.0.0.1`로 풀리는 것 확인). `[::1]`(IPv6 루프백)·`0`(=`0.0.0.0`, Linux에서는 연결 시 로컬 호스트로 간다)은 다른 주소지만 같은 로컬 대상에 닿는다. deny list·정규식은 전부 못 막는다.
- OWASP A10: "deny list나 정규식으로 SSRF를 완화하지 마라. 공격자는 우회 목록·도구·기술이 있다." 양성(허용) 목록 + 파싱·정규화 후 주소 대역 판정을 쓴다.

### 9. 내부 주소 판정의 자료구조

- CIDR 대역 비교 = 주소의 상위 접두 비트를 대역 접두와 맞추는 비트 연산이다. 라우팅의 최장 접두 일치와 같은 뿌리([network/08](../../network/08-routing-and-longest-prefix-match/2-summary.md)의 트라이).
- `InetAddress.isLoopbackAddress()`·`isSiteLocalAddress()`·`isLinkLocalAddress()`가 일부를 판정하지만 100.64/10(RFC 6598)·IPv6 ULA(fc00::/7)는 직접 비트 검사가 필요하다. 토대는 [network/07-ip-addressing-cidr](../../network/07-ip-addressing-cidr/2-summary.md).
