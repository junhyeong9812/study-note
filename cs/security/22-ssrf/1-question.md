# security/22-ssrf — 질문

## 질문

1. (왜) SSRF가 "외부로 나가는 요청"인데도 위험한 이유는? 서버가 방화벽 **안쪽**에 있다는 사실이 왜 핵심인가?
2. (연결) 브라우저에는 SOP(21번)가 있다. 서버에는 그에 해당하는 것이 있나? 그 차이가 방어 책임을 어디로 옮기나?
3. (경계) SSRF 방어에서 "이름(호스트)"을 검사하면 안 되고 "해석된 실제 주소"를 검사해야 하는 이유는? 어떤 공격이 이름 검사를 우회하나?
4. (예측) 허용 목록 검사가 `url.contains("partner.example")`이다. `http://169.254.169.254.partner.example.attacker.test/`는 통과하나? 올바른 검사는?
5. (예측) 호스트 이름은 허용 목록에 있는데 그 이름이 `10.0.0.5`로 해석된다. 안전한 가드는 허용하나 거부하나? 왜?
6. (경계) 검사를 통과한 URL이 `302`로 `http://169.254.169.254/`로 리다이렉트한다. 기본 설정의 `HttpClient`와 `HttpURLConnection`은 각각 따라가나? 대처는?
7. (경계) AWS IMDSv2는 단순 SSRF GET을 왜 막나(토큰·홉 제한)? 이것은 1차 방어인가 심층 방어인가?
8. (장애 진단) `127.0.0.1`을 deny list로 막았다. 어떤 표기들로 우회되나? OWASP는 deny list/정규식에 대해 뭐라 하나?
9. (연결) 내부 주소 판정은 어떤 자료구조·연산인가? 어느 cs 노트와 이어지나?
