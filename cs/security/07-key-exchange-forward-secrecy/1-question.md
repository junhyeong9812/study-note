# security/07-key-exchange-forward-secrecy — 질문

## 질문

1. (왜) 키 전송(정적 RSA)과 키 합의(Diffie-Hellman)는 무엇이 다른가? "선 위로 비밀이 지나가는가"로 설명하라.
2. (계산) p=23, g=5, a=6, b=15일 때 A, B와 공유 비밀 K는? 도청자가 본 값과, K를 구하려면 풀어야 하는 문제는?
3. (그림) 정적 RSA 키 교환과 ECDHE에서 "트래픽을 녹음해 두고 몇 년 뒤 서버 개인키를 얻은" 공격자가 할 수 있는 것을 각각 그려라. 장기 키는 ECDHE에서 무슨 역할만 하나?
4. (예측) 로컬 `openssl s_server`에 TLS 1.2 `AES128-GCM-SHA256`, TLS 1.2 `ECDHE-RSA-AES128-GCM-SHA256`, TLS 1.3으로 각각 붙으면 `s_client` 출력의 `Server Temp Key` 줄은 어떻게 나오나? 그 차이가 뜻하는 것은?
5. (경계) DH 공개값에 서명이 없으면 무슨 일이 생기나? TLS 1.3은 키 합의와 상대 인증을 각각 무엇으로 하나?
6. (경계) RFC 8446 부록 E.1이 말하는 전방 비밀성이 성립하지 않는 경우 두 가지는? (재개 모드, 세션 키 처리)
7. (연결) NIST SP 800-57의 cryptoperiod 표에서 임시 키 합의 키와 정적 키 합의 키의 수명은 각각 얼마인가? 이것이 전방 비밀성과 어떻게 이어지나?
8. (장애 진단) 서버 개인키가 유출됐다는 보고를 받았다. 과거 트래픽의 노출 범위를 산정하려면 무엇을 확인해야 하나? 재발 방지 설정은?
9. (장애 진단) nginx에 `ssl_ciphers HIGH:!aNULL`이 설정돼 있다. 전방 비밀성 관점에서 무엇이 문제이고, 어떻게 확인하고 고치나?
