# security/09-randomness-and-key-management — 질문

## 질문

1. (왜) 알고리즘이 공개된 AES·Ed25519가 안전하다면, 실제 사고는 왜 키와 난수 쪽에서 주로 나는가? 커리큘럼 ⚠의 두 경우(하드코딩 시크릿, 회전 절차 부재)를 예로 설명하라.
2. (예측) `new Random(System.currentTimeMillis()).nextLong()`으로 비밀번호 리셋 토큰을 만든다. 공격자가 발급 시각을 1분 범위로 안다면 후보는 몇 개이고, 실험에서는 시드를 찾는 데 얼마나 걸렸나? 고친 코드는?
3. (예측) JDK 21 Linux 컨테이너에서 `new SecureRandom()`에 `setSeed(42)`를 하고 8바이트를 뽑는 것을 두 번 하면 같은 값이 나오나? `SecureRandom.getInstance("SHA1PRNG")`로 같은 일을 하면? Javadoc의 어느 문장이 차이를 설명하나?
4. (경계) Linux `random(7)`은 장기 키 생성에도 `/dev/random`(또는 `GRND_RANDOM`)보다 무엇을 쓰라고 하나? 부팅 초기 엔트로피 문제는 무엇이 처리하나?
5. (그림) 봉투 암호화의 키 계층(KMS 키 → KEK → DEK → 데이터)을 그려라. KEK를 회전할 때 다시 하는 일과 하지 않는 일은?
6. (경계) AWS KMS 키의 자동 회전을 켜 두었다. 데이터 키가 로그로 유출됐을 때 이 회전이 도움이 되나? 무엇을 해야 하나?
7. (연결) NIST SP 800-57 표 1에서 대칭 데이터 암호화 키의 "만드는 쪽 사용 기간"과 "받는 쪽 사용 기간"이 다른 이유는? 이것이 회전 설계에 주는 요구는?
8. (장애 진단) 실수로 커밋한 클라우드 접근 키를 다음 커밋에서 지웠다. 안전해졌나? 확인 방법과 대응 순서를 대라.
9. (장애 진단) 키를 교체하는 배포 직후 `AEADBadTagException`과 `401`이 폭증했다. 무엇이 빠졌나? 어떻게 설계를 고치나?
