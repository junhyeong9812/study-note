# security/26-security-logging-and-audit — 질문

## 질문

1. (왜) 보안 사건의 답이 "사건 당시 기록에만 있다"는 것은 무슨 뜻인가? 로깅 실패가 쌍(덜 남김·잘못 남김)인 이유를 CWE로 설명하라.
2. (경계) 감사 로그와 앱 로그는 왜 분리해야 하나? 감사 사건을 앱 로그에 남기면 무엇이 조용히 사라지나?
3. (예측) 사용자 이름에 개행과 가짜 로그 줄을 넣어 평문 연결 로그에 남기면 출력이 어떻게 되나? 구조화(JSON) 로그는 왜 이걸 막나?
4. (그림) audit와 enforce가 (유효 서명/틀린 서명/서명 없음) 세 입력을 각각 어떻게 판정하나? audit가 봐주는 것은 정확히 무엇뿐인가?
5. (경계) 모드를 설정 안 했을 때, 오타로 적었을 때, 서명 키가 없을 때 — 각각 어떻게 떨어져야 하나? 그 이유(fail-closed)는?
6. (연결) enforce로 전환할 시점을 "감이 아니라 로그로" 정한다는 것은 무슨 뜻인가? audit 집계가 무엇을 보여 줘야 전환 가능한가?
7. (장애 진단) enforce로 바로 켰더니 cron·배치의 정상 호출이 전부 401이다. 원인과 올바른 순서, 롤백 방법은?
8. (장애 진단) 감사 로그가 지워졌을 수 있는데 확인할 길이 없다. 해시 체인은 무엇을 탐지하고 무엇은 못 잡나? 고정점(anchor)을 어디에 둬야 하나?
