# security/11-sessions-and-cookie-security — 질문

## 질문

1. (왜) 로그인에 성공한 사실을 다음 요청이 알게 하려면 무엇이 필요한가? 세션 ID가 "bearer"라는 말은 무슨 뜻이고, 그래서 세션 ID에 어떤 성질(엔트로피·내용·이름)이 필요한가?
2. (그림) 세션 고정 공격을 공격자·피해자·서버 세 줄로 그려라. 어느 한 줄을 바꾸면 공격이 무너지나? Spring Security는 기본으로 무엇을 하나?
3. (경계) 다음 쌍은 같은 출처인가, 같은 사이트인가? ① `https://a.shop.example` vs `https://b.shop.example` ② `http://127.0.0.1:18431` vs `http://localhost:18432` ③ `https://app.example:443` vs `https://app.example:8443`. ③에서 쿠키는 공유되나?
4. (예측) 다른 사이트 페이지에서 app으로 ① 링크 클릭(최상위 GET) ② 폼 제출(최상위 POST) ③ `<img>` 요청이 갔다. `SameSite=Strict`, `Lax`, `None; Secure`, 속성 없음(Chrome) 쿠키 중 각 경우에 실리는 것은? 속성 없는 쿠키는 왜 시점에 따라 결과가 달라지나?
5. (장애 진단) 외부 IdP로 로그인하면 콜백에서만 "state 불일치"가 난다. 로그인 시작 후 빨리 끝내면 가끔 성공한다. 원인과, 세션 쿠키 전체를 `SameSite=None`으로 바꾸지 않고 고치는 방법 두 가지는?
6. (경계) `HttpOnly`를 켜면 XSS로부터 무엇이 보호되고 무엇은 보호되지 않나?
7. (장애 진단) 하위 도메인 `promo.example.com`이 침해된 뒤 메인 서비스 사용자가 엉뚱한 계정으로 로그인돼 있다. 요청 헤더에서 무엇이 보이고, 쿠키 설정을 어떻게 바꿔야 하나?
8. (적용) 유휴 만료와 절대 만료는 각각 무엇을 막나? Spring Boot에서 유휴 만료의 기본값은 얼마이고, 절대 만료는 어떻게 구현하나?
9. (장애 진단) 로그아웃했는데 그 세션 ID로 API가 계속 된다. 무엇을 확인하고 어떻게 고치나? "모든 기기에서 로그아웃"에는 무엇이 더 필요한가?
