# security/28-dos-and-abuse — 정답

## 정답

### 1. 비대칭과 세 계층

- 비대칭: 공격자가 싼 자원(패킷·연결·요청)을 조금 쓰면 서버가 비싼 자원을 많이 쓴다. 그 격차가 공격의 지렛대다.
- 계층별 고갈 자원과 방어 위치
  - 볼륨(L3/4): 대역폭 → 망 앞단(CDN·DDoS 방어).
  - 프로토콜(L4): 연결 상태 테이블 → 커널·LB(SYN cookie, conntrack 한도).
  - 애플리케이션(L7): CPU·DB·워커 → 앱·게이트웨이(리미터·타임아웃·상한).

### 2. 증폭 공격

```text
  공격자 ──(작은 질의, 출발지=피해자로 위조)──▶ 공개 서버(DNS·memcached) ──(큰 응답)──▶ 피해자
```

- 출발지를 피해자로 위조하는 이유: 공개 서버의 **큰 응답이 피해자에게** 가도록. 공격자는 작은 질의만 보내고 증폭된 응답은 서버가 피해자에게 쏟는다(GitHub 2018 memcached, 최대 51,000배).
- 반사판이 안 되려면: 공개 UDP 서비스(memcached·열린 리졸버·NTP monlist)를 인터넷에 열어 두지 않는다. 출발지 검증(BCP 38)도 망 차원 방어다.

### 3. slowloris

- 수신 타임아웃 없는 서버: 클라이언트가 찔끔찔끔 보내는 **내내 연결을 붙잡는다**. 실험에서 10초간 연결 점유(그동안 워커 하나가 묶임).
- 1초 수신 타임아웃 서버: 간격이 타임아웃을 넘자 **1.0초에 끊었다**. 공격 연결이 워커를 오래 못 쥔다.
- 핵심: slowloris 방어 = "제시간에 요청을 못 끝맺으면 끊는다"(수신 타임아웃 + 최소 속도).

### 4. 토큰 버킷 (실험)

| | 허용 | 429 | DB비용 |
|---|---|---|---|
| 정상 1건/s cost1 | 60 | 0 | 60 |
| 남용 50건/s cost1 | 319 | 2681 | 319 |
| 남용 리포트 cost10 | 31 | 269 | 310 |

- 정상(보충 속도 5/s보다 느린 고른 1건/s)은 한 건도 안 막혔다. 순간적으로 용량 20을 넘게 몰리면 정상 요청도 막힐 수 있다. 남용은 초기 버스트(용량 20)만 통과하고 보충 속도(5/s)로 묶인다.
- cost 가중: 비싼 엔드포인트일수록 토큰을 많이 써 더 일찍 막힌다(cost10은 31건만 허용). 이번 실험의 cost 1과 10에서는 허용된 DB 비용이 319와 310으로 비슷했다 — 자원 소비에 비례해 제한된 것이다. 일반 성질은 아니다: cost가 용량(20)을 넘으면 통이 가득 차도 한 건도 통과 못 한다.

### 5. 거절의 비용

- 리미터·429 생성 자체가 CPU·커넥션을 쓴다. 방어도 공짜가 아니다.
- 429가 폭풍을 부르는 이유: 막힌 클라이언트가 **즉시 재시도**하면 더 큰 부하가 된다.
- 받는 법: `Retry-After` 헤더 + 클라이언트의 지수 백오프 + 지터(reliability/06). 방어는 가능한 앞단에서 싸게 건다("cheap validation first").

### 6. 복잡도 공격

- 공통 구조: 작은 입력이 서버 일을 지수·제곱으로 키운다 — 엔티티 폭탄(641B→10^10, 23번), ReDoS(백트래킹 정규식 지수 시간), 해시 충돌(연산당 O(1)→O(n), n개 삽입 전체 O(n²)).
- 공통 방어: 입력 크기·깊이·시간 상한, 선형 시간 정규식 엔진, 무작위 해시 시드. 연결: 23번(파서), data-structure/05-hashmap, [language 02](../../language/02-lexing-and-regular-languages/2-summary.md)(정규식).

### 7. SYN flood vs slowloris

- 구분
  - SYN flood: `ss -tan state syn-recv`가 폭증, 커널 `Possible SYN flooding ... Sending cookies`, `TcpExtSyncookiesSent` 증가. 연결이 **반쯤** 열린 채 쌓인다.
  - slowloris: 연결이 **완전히** 맺어진 뒤 "헤더 수신 중"으로 오래 머문다. syn-recv가 아니라 established가 오래 유지.
- 대처
  - SYN flood: `tcp_syncookies=1` 유지, `tcp_synack_retries` 축소, 대규모는 망 앞단(network/15).
  - slowloris: 수신 타임아웃(nginx `client_header_timeout`·Apache `mod_reqtimeout`), 헤더 수신 전 연결도 세는 IP당 연결 제한(nginx `limit_conn`은 헤더를 다 받은 연결만 세므로 해당 없음), 이벤트 기반 프록시.

### 8. 키 선택과 실패 모드

- 키 선택: IP로만 세면 NAT·회사 공유 IP 하나가 통째로 막힌다. 인증 사용자는 사용자 ID로, 익명은 IP+경로 등으로 세분한다(reliability/11 §4).
- 실패 모드: 리미터가 고장 났을 때 정책을 **명시**한다.
  - 과부하 보호가 목적이면 조심스러운 fail-open(리미터 없이 통과 — 단 하류 보호 장치가 있을 때).
  - 보안 게이트(인증·인가)면 fail-closed(거부 — 01번 fail-safe 기본값).
  - 과부하 시에는 우선순위 셰딩으로 중요한 트래픽부터 살린다(reliability/12).
