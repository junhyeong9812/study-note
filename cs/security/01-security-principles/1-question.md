# security/01-security-principles — 질문

## 질문

1. (왜) 기밀성·무결성·가용성은 각각 무엇을 잃는 것인가? 인가 서버 장애 때 "통과"와 "거부"는 셋 중 무엇을 지키고 무엇을 버리나?
2. (경계) Saltzer–Schroeder의 fail-safe 기본값은 왜 "배제"가 아니라 "허가"에 근거하라고 하나? 두 방식에서 설계 실수가 각각 어떤 모양으로 드러나는지 비교하라.
3. (예측) 인가 클라이언트가 `catch (Exception e) { return true; }`로 짜여 있다. 정상 상태 테스트, 인가 서버가 `403`을 줄 때, 인가 서버 포트가 닫혔을 때 각각 결과는? 정상 테스트로 이 결함이 안 잡히는 이유는?
4. (경계) 속도 제한기는 fail-open으로 두는 회사가 있다. fail-safe 기본값과 모순인가? 어떤 기준으로 fail-open/closed를 고르나?
5. (예측) 권한 판정을 만료 없는 맵에 캐시한다. 관리자가 사용자의 권한을 회수하면 어떻게 되나? 어느 원칙 위반이며, 캐시를 유지하면서 고치는 방법은?
6. (연결) 최소 권한은 공격을 "막는" 원칙인가? SQL 인젝션 1건이 난 앱에서 DB 계정 권한이 superuser일 때와 자기 스키마 DML만일 때를 비교하라.
7. (경계) 심층 방어의 층이 셋 있는데도 한 번에 다 뚫렸다. 어떤 공통 원인이 있었을 가능성이 큰가?
8. (장애 진단) 장애 시간대 대시보드에서 `authz.denied`가 0, `authz.error`가 급증, `/admin/**`의 2xx가 평소의 80배다. 무엇이 일어났고 무엇부터 확인·조치하나?
9. (연결) Spring Security에서 `anyRequest().permitAll()`과 `anyRequest().denyAll()`로 끝나는 설정은 새 엔드포인트가 추가될 때 어떻게 다르게 동작하나? `AuthorizationFilter`가 ERROR 디스패치에도 도는 것은 어느 원칙과 연결되나?
