# security/06-public-key-and-signatures — 질문

## 질문

1. (왜) HMAC으로도 메시지 변조를 막을 수 있는데, API 서버 수십 대가 토큰을 검증하는 구조에서는 왜 전자서명이 필요한가? "검증자 = 위조자" 문제로 설명하라.
2. (그림) 서명자와 검증자 사이의 흐름(해시 → Sign → 전송 → 해시 → Verify)을 그려라. 서명이 주는 성질 세 가지와 주지 않는 성질 하나는?
3. (계산) p=61, q=53, e=17로 교과서 RSA 키를 만들면 n, φ, d는? h=65의 서명 σ와 검증 결과는? 이 교과서 RSA를 그대로 쓰면 안 되는 이유와 RFC 8017이 새 응용에 요구하는 서명 방식은?
4. (예측) 같은 개인키로 같은 메시지를 두 번 서명하면 Ed25519와 JDK 21의 `SHA256withECDSA`는 각각 같은 서명을 낼까, 다른 서명을 낼까? 그 이유를 서명 알고리즘의 난수 k로 설명하라.
5. (경계) ECDSA에서 두 서명이 같은 k를 썼다면 공개된 값만으로 개인키가 나오는 이유를 식으로 보여라. 이를 막는 두 가지 설계(RFC 6979, RFC 8032)는 k를 어떻게 정하나?
6. (연결) NIST SP 800-57 표 2에서 128비트 보안 강도에 해당하는 RSA 모듈러스 크기와 ECC 키 크기(f)는? RSA-2048은 몇 비트 강도로 분류되나?
7. (장애 진단) 운영 중 JWT 헤더 `alg`가 평소의 RS256이 아니라 HS256인 토큰이 200을 받았다. 무엇이 일어났을 수 있나? 검증 코드를 어떻게 고치나?
8. (장애 진단) 서명 검증 코드가 있는데도 위조 웹훅이 처리됐다. 코드에서 찾아볼 흔한 실수 세 가지와, 재발을 막는 테스트는?
9. (연결) 서명이 "이 공개키 주인이 서명했다"를 증명해도, "이 공개키가 정말 그 서버 것인가"는 증명하지 못한다. 이 문제를 TLS와 JWT는 각각 무엇으로 푸나?
