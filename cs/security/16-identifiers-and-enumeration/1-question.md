# security/16-identifiers-and-enumeration — 질문

## 질문

1. (왜) 외부 ID를 랜덤으로 바꾸는 것이 객체 수준 인가를 대신하지 못하는 이유는? RFC 9562 §8은 UUID에 대해 무엇을 금지하나?
2. (경계) 인가가 제대로 있어도 순차 ID가 흘리는 정보 세 가지를 들어라.
3. (계산) 64비트 랜덤 ID 공간에 객체 10⁴개가 있고 공격자가 10⁵번 무작위로 추측한다. 기대 적중 수는? 같은 조건에서 순차 ID 1..10⁴라면?
4. (계산) 32비트 랜덤 ID를 10만 개 발급하면 충돌 쌍은 몇 개쯤 기대되나? 충돌 확률 50%가 되는 개수는 대략 얼마인가? 실험의 실측값과 비교하라.
5. (그림) UUIDv4와 UUIDv7의 비트 배치를 그리고, v7 문자열에서 생성 시각을 꺼내는 방법을 말하라. 이것이 문제가 되는 예는?
6. (예측) ULID 단조 모드에서 `01BX5ZZKBKACTAV9WEVGEMMVRZ`를 받은 사람이 같은 밀리초에 생성된 다음 값을 짐작할 수 있나? 왜?
7. (적용) 내부 PK와 외부 공개 ID를 나누는 스키마를 쓰고, 공개 ID 생성 코드에서 피해야 할 것 두 가지를 대라.
8. (장애 진단) 접근 로그에서 열거 시도를 알아보는 패턴 세 가지와 대처 순서는?
9. (연결) 원본(identity-and-ids)의 "이름은 참조, ID는 신원" 원칙은 이 노트의 "외부 ID는 노출 정보로 고른다"와 어떻게 다른 질문에 답하나?
10. (장애 진단) 공유 링크 ID가 8자리 16진수인 서비스에서 "남의 파일이 열렸다"는 신고가 왔다. 원인 후보와 고칠 것은?
