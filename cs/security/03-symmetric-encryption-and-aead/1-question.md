# security/03-symmetric-encryption-and-aead — 질문

## 질문

1. (왜) AES 자체는 안전하다고 하는데, 왜 AES로 암호화한 데이터가 패턴을 드러내거나 변조되는 사고가 나나? "알고리즘"과 "사용법" 중 어디가 깨지는가?
2. (그림) ECB·CBC·CTR·GCM을 각각 그림으로 그려라. 같은 16바이트 평문 블록이 4번 반복될 때 ECB와 GCM 암호문은 어떻게 다른가?
3. (예측) Java 21에서 `Cipher.getInstance("AES")`로 암호화하면 어떤 모드·패딩이 쓰이나? 그 근거(문서 vs 실험)는 각각 무엇을 말하나?
4. (계산) 같은 키·같은 nonce로 GCM 암호화한 `C1`, `C2`가 있다. 키를 모르는 사람이 `C1 ⊕ C2`로 무엇을 얻나? `P2`를 안다면? 그리고 기밀성 외에 무엇이 더 깨지나(SP 800-38D 부록 A)?
5. (경계) SunJCE는 GCM nonce 재사용을 어디까지 막아 주나? 같은 `Cipher` 객체, 새 객체, 다른 서버 인스턴스의 경우를 나눠 답하라.
6. (예측) 인증 없는 AES-CBC로 `"amount=100;to=bob"`을 암호화했다. 공격자가 IV의 인덱스 7 바이트(0부터 세어 8번째 — 평문 `'1'`의 자리)를 `'1' ^ '9'`로 XOR하면 복호 결과는? 같은 조작을 GCM 암호문에 하면?
7. (경계) 무작위 96비트 nonce를 쓸 때 한 키로 몇 번까지 암호화해도 되나(SP 800-38D)? 그 수를 넘기 전에 무엇을 하나?
8. (연결) AAD에 `"users:id=17"`을 넣고 암호화한 값을 id=42 행으로 복사하면 복호 결과는? AAD는 어떤 공격을 막나?
9. (장애 진단) 배포 직후 기존 암호화 데이터 전체가 `AEADBadTagException: Tag mismatch`로 열리지 않는다. 새 데이터는 열린다. 가능한 원인 세 가지와 재발 방지책은?
10. (장애 진단) 암호화 토큰을 받는 엔드포인트에 한 출처에서 짧은 시간에 수천 건, 응답이 `invalid padding`과 `invalid token`으로 갈려 나온다. 무엇을 의심하고, 당장과 근본 대처는?
