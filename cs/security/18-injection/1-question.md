# security/18-injection — 질문

## 질문

1. (왜) 인젝션을 "데이터가 코드로 읽히는 결함"이라고 한다. SQL 문자열 연결에서 그 일이 **언제**(파싱 전·후) 일어나나? 파라미터 바인딩은 그 순서를 어떻게 바꾸나?
2. (예측) 입력 `nobody' OR '1'='1`을 (a) 문자열 연결 쿼리와 (b) `PreparedStatement`에 넣었다. 각각 몇 행이 나오고, `log_statement=all`인 PostgreSQL 로그에는 각각 어떻게 찍히나?
3. (경계) 다음 중 `PreparedStatement`의 `?`로 안전하게 넘길 수 **없는** 것은 무엇이고, 각각 어떻게 처리하나? — `WHERE` 값, `ORDER BY` 열 이름, `ASC/DESC`, `LIKE` 검색어
4. (예측) `ORDER BY ?`에 `"name DESC"`를 바인딩하면 오류가 나나? 결과는 어떻게 되나?
5. (경계) `ProcessBuilder("ls", input)`처럼 셸 없이 인자 배열로 실행하면 무엇은 막히고 무엇은 남나? 남는 것은 어떻게 막나?
6. (연결) LDAP 필터 `(uid=` + 입력 + `)`에서 입력이 `*`이면 무슨 일이 생기나? RFC 4515의 이스케이프와 JNDI 필터 인자(`{0}`)는 SQL의 무엇에 대응하나?
7. (장애 진단) 이름에 따옴표가 든 고객만 `SQLState=42601`로 실패한다. 이것이 단순 기능 버그가 아니라 보안 결함의 신호인 이유와 올바른 수정은?
8. (장애 진단) "ORM을 쓰니까 인젝션은 없다"는 주장이 깨지는 코드 모양을 하나 들고, 탐지·예방 수단을 대라.
9. (연결) 입력 검증(허용 문자 제한)과 이스케이프가 "1차 방어가 아니라 보조"인 이유는? OWASP A03(2021)의 표현으로 답하라.
