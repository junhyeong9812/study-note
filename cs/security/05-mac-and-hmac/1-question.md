# security/05-mac-and-hmac — 질문

## 질문

1. (왜) MAC은 무엇과 무엇을 함께 증명하나? 공개 키 서명과 비교해 HMAC이 증명하지 못하는 성질은?
2. (그림) HMAC-SHA-256의 계산을 ipad·opad·B를 넣어 그려라. 키가 131바이트일 때와 4바이트일 때 각각 키는 어떻게 처리되나?
3. (계산) RFC 4231 TC1(키 `0x0b`×20, 데이터 `"Hi There"`)의 HMAC-SHA-256 값은? 직접 구현한 HMAC이 맞는지 어떻게 확인하나?
4. (예측) 태그 비교를 첫 불일치에서 멈추는 루프로 했다. 4096바이트 값에서 첫 바이트가 다를 때와 마지막 바이트만 다를 때 시간은 어떻게 다른가? `MessageDigest.isEqual`은?
5. (경계) 32바이트 태그에서 `Arrays.equals`의 시간 차이가 측정 노이즈에 묻혔다. 그러면 `Arrays.equals`로 태그를 비교해도 되나?
6. (예측) 보내는 쪽이 원문 `{"id":"evt_1","amount":100,"memo":"가"}`에 HMAC을 붙였다. 받는 쪽이 Python `json.dumps(json.loads(raw))`로 다시 만든 바이트로 검증하면 결과는? `sort_keys=True`를 쓰면?
7. (연결) Spring MVC에서 웹훅 본문을 서명 검증에 쓰려면 컨트롤러 인자를 어떻게 받아야 하나? 파싱은 언제 하나?
8. (장애 진단) 결제사 웹훅 중 한글이 든 이벤트만 401로 실패하고 재시도가 쌓인다. 원인 후보와 확인 순서는?
9. (장애 진단) 서명 검증을 통과한 같은 결제 완료 이벤트가 두 번 처리됐다. HMAC이 뚫린 것인가? 무엇이 빠졌나?
10. (경계) RFC 2104는 태그를 잘라 쓸 때 어떤 하한을 권하나? 키 길이에 대해서는 무엇을 권하나?
