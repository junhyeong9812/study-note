# cs/Hysteresis — 히스테리시스(Hysteresis) — 정리 (힌트)

> 복습 시 이 파일은 **질문에 막혔을 때만** 연다. 먼저 읽고 답하면 인출이 아니라 받아쓰기다.
> 원고는 내가 직접 쓴 Hysteresis 노트(2026-08-23). 1~5절은 원고 그대로(오탈자만 교정).
> 「전체 흐름」「핵심 문장」은 원고를 압축한 것이고, 맨 아래 「[Claude 추가]」 절만 원고에 없던 내용이다.
> 선행 주제: [thrashing](../thrashing/) — 이 문서는 그 해법을 일반 원리로 끌어올린 것.

## 전체 흐름

```text
정의     상태가 바뀌는 기준을 방향에 따라 다르게 두는 것
목적     값이 경계 근처에서 왔다 갔다 할 때 상태가 계속 전환되는 것을 막는다
예 1     동적 배열 — 확장 16 / 축소 4, 둘 다 8이면 7↔8에서 계속 resize
어원     물리학 — 현재 상태가 현재 입력만으로 결정되지 않고 이전 상태의 영향을 받는 현상
예 2     CPU 팬 — 80°C 이상 ON / 70°C 이하 OFF, 그 사이는 기존 상태 유지 = hysteresis band
구분     Thrashing = 반복되는 문제 현상 / Hysteresis = 그 반복을 막는 설계 원리
```

## 1. 히스테리시스란?

상태가 바뀌는 기준을 방향에 따라 다르게 두는 것이다.

특히 어떤 값이 경계 근처에 왔다 갔다 할 때 상태가 계속 전환되는 현상을 막기 위해 많이 사용한다.

## 2. 동적 배열로 보면

아까 동적 배열을 그대로 예로 들면:

```text
capacity = 16

확장 기준: size = 16
축소 기준: size = 4

     축소                         확장
      ↓                            ↓
------4----------------------------16------
       ←       안전 구간          →
```

만약 확장/축소 기준을 둘 다 8이라 하면:

```text
size 7 → 축소
size 8 → 확장
size 7 → 축소
size 8 → 확장
...
```

경계에서 계속 상태가 바뀔 수 있다.
반면 기준을 떨어뜨려 놓으면:

```text
확장:  16에 도달해야 함
축소:   4까지 내려가야 함
```

## 3. 이름이 Hysteresis인 이유

원래 물리학에서 나온 개념으로, 현재 상태가 현재 입력값만으로 결정되지 않고 이전 상태의 영향을 받는 현상을 의미한다.
컴퓨터에서는 이 아이디어를 가져와서 이런 식으로 많이 사용한다.

## 4. CPU 팬 예시 — hysteresis band

```text
CPU 온도

80°C 이상 → 팬 ON
70°C 이하 → 팬 OFF

70°C ~ 80°C에서는?
→ 기존 상태 유지
```

만약 기준이 하나뿐이면:

```text
75.0 → ON
74.9 → OFF
75.1 → ON
74.9 → OFF
```

팬이 미친 듯이 켜졌다 꺼졌다 할 수 있다.
그래서:

```text
OFF ─────── 80°C → ON
ON  ← 70°C ──────

       70 ~ 80
     기존 상태 유지
```

이 두 임계값 사이의 간격을 흔히 hysteresis band(히스테리시스 구간)라 한다.

## 5. Thrashing과의 구분

Thrashing은 확장 → 축소 → 확장 → 축소가 반복되는 문제 현상이고, Hysteresis는 확장 기준과 축소 기준을 떨어뜨려 그 반복을 방지하는 설계 원리라고 구분하면 된다.

## 핵심 문장

- 히스테리시스 = 올라갈 때 문턱과 내려갈 때 문턱을 다르게 두는 것.
- 문턱이 하나면 그 경계에서 값이 조금만 흔들려도 상태가 진동한다.
- 두 문턱 사이(hysteresis band)에서는 "현재 입력"이 아니라 "이전 상태"가 답을 정한다 — 그래서 물리학의 이력(履歷) 현상 이름을 빌렸다.
- Thrashing은 현상, Hysteresis는 해법.

## [Claude 추가] 더 알면 좋은 것

> 아래는 원고에 없던 내용이다. 복습 대상은 1~5절이고, 이 절은 확장 읽을거리다.

### A. 히스테리시스는 "상태 기계에 메모리 1비트를 추가하는 것"

- 문턱 하나짜리 규칙은 `상태 = f(입력)` — 입력만 보면 답이 나오는 순수 함수다.
- 히스테리시스 규칙은 `상태 = f(입력, 이전 상태)` — band 안에서는 이전 상태를 그대로 돌려준다. 즉 출력이 입력의 이력에 의존하는 것이 정의 그 자체이고, 물리학에서 자석의 자화 곡선이 "올라갈 때와 내려갈 때 경로가 다른" 것을 같은 이름으로 부른다.
- 전자공학에서는 이걸 회로로 만든 것이 **슈미트 트리거(Schmitt trigger)** — 노이즈 낀 아날로그 신호를 깨끗한 0/1로 바꿀 때 쓴다. 소프트웨어의 히스테리시스는 이 회로를 코드로 옮긴 것이다.

### B. 소프트웨어·인프라에서 만나는 자리

- **오토스케일링**: scale-out 임계(CPU 70%) ≠ scale-in 임계(30%) + cooldown 시간. 같은 값을 쓰면 인스턴스가 생겼다 사라졌다 하는 flapping이 난다. cooldown은 "시간 축의 히스테리시스"다.
- **서킷 브레이커**: 실패 N회에 open, half-open에서 성공 M회에 close — 성공 한 번으로 바로 닫지 않는다.
- **헬스체크 / BGP route damping**: unhealthy 판정 3회 연속, healthy 복귀 2회 연속처럼 들어올 때·나갈 때 횟수를 다르게 둔다.
- **GC / 메모리 풀**: 힙 확장 기준과 축소 기준(예: JVM `MinHeapFreeRatio` / `MaxHeapFreeRatio`)을 다르게 둬 힙이 요동치지 않게 한다.
- **해시 테이블**: load factor 0.75에서 확장, 축소는 훨씬 낮은 값에서(혹은 아예 안 함) — 동적 배열과 같은 이유.

### C. band 폭을 정하는 트레이드오프

- band가 **좁으면** 진동 위험이 남고, **넓으면** 반응이 둔해진다(팬이 늦게 켜지고, 배열이 메모리를 오래 쥐고 있고, 오토스케일러가 부하 증가에 늦게 대응한다).
- 그래서 band 폭은 "진동 비용(resize 복사, 인스턴스 기동, 릴레이 수명)"과 "지연 비용(메모리 낭비, 과열, 응답 저하)" 사이의 선택이다. 동적 배열의 C/4는 메모리 최대 4배 낭비를 감수하고 복사 비용을 줄인 선택이다.

### D. 히스테리시스 말고 다른 진동 억제 수단

- **Debounce / 시간 지연**: 조건이 일정 시간 유지될 때만 전환(버튼 입력, 헬스체크 grace period).
- **이동 평균 / 스무딩**: 입력 자체를 평활화해 경계 근처의 흔들림을 줄인다.
- **Cooldown**: 전환 후 일정 시간 재전환 금지.
- 셋 다 "경계 근처 진동"을 막는 도구이고, 실무에서는 히스테리시스와 함께 조합해 쓴다(오토스케일러 = 임계값 분리 + cooldown + 평균 윈도우).
