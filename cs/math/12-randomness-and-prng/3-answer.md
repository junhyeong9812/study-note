# math/12-randomness-and-prng — 정답

## 정답

### 1. 상태 + 갱신 + 출력

```text
  시드 → [s0] ─f→ [s1] ─f→ [s2] ...
                  │g       │g
                  x1       x2
```

- 시드가 같으면 상태 수열과 출력 수열 전체가 같다.
- 기능: 시뮬레이션·무작위 테스트를 같은 시드로 재현한다(시드를 로그에 남긴다).
- 장애: 운영 인스턴스들이 같은 시드로 지터를 만들면 지터가 없는 것과 같다(thundering herd).

### 2. 시드별 동시 재시도

- 실험 A(OpenJDK 21, 3회 실행): ① 100대(지터 값 1개) ② 34대(값 3개 — 같은 ms에 뜬 인스턴스끼리 같다) ③ 3~4대(값 91~96개 — 실행마다 다르다, 집필·점검 6회).
- ③의 서로 다른 값 수는 100개를 1000가지 값에 독립·균등하게 던졌을 때의 기대(약 95.2)와 맞고, 칸 최대 3~4는 100개를 100개의 10ms 칸에 던질 때 흔한 값이다. ①②는 시드가 겹쳐 지터가 무력해졌다.

### 3. `java.util.Random`

- 갱신: `s ← (s × 0x5DEECE66D + 0xB) mod 2^48`, 출력 `next(bits)` = s의 상위 bits비트.
- 주기 2^48(Javadoc "its period is only 2^48").
- `nextDouble() = (next(26)·2^27 + next(27)) × 2^−53` → 상태를 두 번 전진, 26비트와 27비트.

### 4. `Math.random()` 예측

- 값 하나에서 상태1의 상위 26비트와 상태2의 상위 27비트를 얻는다. 모르는 것은 상태1의 하위 22비트 → 2^22 ≈ 420만 후보.
- 후보마다 상태2를 계산해 상위 27비트를 대조한다. 어림으로는 틀린 후보가 남을 기대 수가 2^22/2^27 = 1/32이다. 실제 `Random` 상수에서는 0 < |d| < 2^22인 어떤 d도 a·d mod 2^48을 ±2^21 안에 넣지 못해, 후보는 언제나 1개다.
- 실험 C(집필 3회·점검 3회): 후보 1개, 탐색 32~43ms(`--cpus=2` 환경), 다음 `Math.random()` 5개 모두 일치.

### 5. 주기 vs 예측 불가능성

- 쓰면 안 된다. OpenJDK 21 Javadoc이 둘 다 "not cryptographically secure"라고 적고 `SecureRandom`을 권한다.
- 주기는 상태가 되풀이되기까지의 길이다. 예측 불가능성은 출력 일부로 다음 출력을 계산할 수 없다는 성질이다. 주기 2^48인 `Random`도 `nextDouble()` 값 하나로 상태가 복원됐다(4번. `nextInt()` 값 하나로는 후보 2^16개가 남는다). 주기가 길어도 구조가 공개된 비암호 생성기는 예측 대상이다.
- 토큰은 `SecureRandom` 128비트 이상(security/09).

### 6. 셔플의 경우의 수

- Fisher–Yates: i = n−1부터 1까지 `j ∈ [0, i]`를 고른다 → 경로 수 n·(n−1)·…·2 = n!. 각 순열이 정확히 한 경로에 대응하므로 균등하다.
- 잘못된 셔플: 매 단계 n가지 → n^n 경로. n=3이면 27 경로를 6 순열에 나눠야 하는데 27은 6으로 나뉘지 않아 균등할 수 없다(CLRS 연습문제 5.3-3). n ≥ 3이면 같은 이유로 균등할 수 없고, n=2는 4 경로가 두 순열에 둘씩이라 균등하다.
- 실험 B(270만 회, seed 42): Fisher–Yates 449,095~450,589. 잘못된 셔플 `[1,2,3]·[3,1,2]·[3,2,1]` ≈ 400,000(4/27), `[1,3,2]·[2,1,3]·[2,3,1]` ≈ 500,000(5/27).

### 7. 상태 공간 vs 순열 공간

- `Random`의 서로 다른 상태는 최대 2^48 ≈ 2.8×10^14가지다. 셔플 결과는 시작 상태로 정해지니, 서로 다른 결과도 최대 2^48가지다.
- 52! ≈ 8×10^67이므로 52장의 순열 대부분은 나올 수 없다.
- 16! ≈ 2.1×10^13 < 2^48 < 17! ≈ 3.6×10^14. 17장부터 나올 수 없는 순열이 생긴다.

### 8. LCG 하위 비트

- 실험 D(a=1664525, c=1013904223, m=2^32): 최하위 비트 `010101…`(주기 2), 최상위 비트는 불규칙.
- 법이 2^k면 하위 j비트는 법 2^j의 LCG처럼 움직여 주기가 2^j 이하다. 그래서 `Random`은 48비트 상태의 상위 비트를 내보낸다.
- `nextInt(bound)`에서 bound가 2의 거듭제곱이면 `% bound`가 하위 비트만 남기므로, 상위 비트를 곱셈·시프트로 가져온다(Javadoc: 하위 비트는 "short periods").

### 9. `Math.random()` 토큰 탈취

- 원인: `Math.random()`은 `new Random()` 하나(48비트 LCG)를 공유한다. 토큰에 반환값 전체가 드러나면 공격자는 자기 계정으로 받은 토큰 하나로 상태를 복원하고, 호출 순서를 따라가며 다음 사용자의 토큰을 계산할 수 있다(실험 C). 그래서 무차별 대입 흔적이 없다.
- 즉시 할 일: 발급된 재설정 토큰·세션을 모두 무효화하고 재발급한다. 해당 기간 재설정 로그를 감사한다.
- 고칠 코드: `static final SecureRandom SECURE = new SecureRandom();`, 16바이트 이상 `nextBytes` → Base64url. 정적 분석으로 보안 맥락의 `Math.random`·`new Random`을 찾는다.
