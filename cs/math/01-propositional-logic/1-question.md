# math/01-propositional-logic — 질문

## 질문

1. (왜) 권한 검사 조건을 리팩터링할 때 "읽어 보니 같은 뜻"으로는 부족한 이유는? 변수가 n개인 조건식 두 개가 같은지 확실히 판정하는 방법과 그 비용은?
2. (예측) 거부 조건 `!(member && verified)`를 `!member && !verified`로 바꿨다. (member, verified) 네 조합 중 결과가 달라지는 조합은 무엇이고, 그때 사용자는 허용되나 거부되나?
3. (계산) `!(a && (b || c))`를 부정이 변수에만 붙도록 펼쳐라. `!a || !b || !c`와는 몇 개의 (a, b, c) 조합에서 다른가? 반례 하나를 대라.
4. (경계) 규칙 "A이면 B다"(`A → B`)의 부정은? `NOT A → NOT B`는 그 부정인가? 이 규칙을 깨는 테스트 입력은 어떤 모양인가?
5. (예측) `User u = null;`일 때 `u != null && u.admin()`, `u.admin() && u != null`, `u != null & u.admin()`는 각각 어떻게 되나? 논리적으로 같은 식이 다르게 동작하는 이유를 JLS의 정의로 설명하라.
6. (경계) `List.of().stream().allMatch(x -> false)`의 값은? 이것이 인가 코드에서 어떤 사고로 이어질 수 있고 어떻게 막나?
7. (연결) SQL에서 `status = 'BANNED'`인 행과 `NOT(status = 'BANNED')`인 행을 합쳤는데 전체보다 적다. 어떤 행이 빠졌고, 2치 논리의 어떤 법칙이 깨진 것인가? 드모르간 법칙은 여전히 성립하나?
8. (연결) 두 조건식이 동치인지 묻는 문제를 SAT 문제로 바꾸면 어떤 식의 충족 가능성을 묻게 되나? 실무 조건식에서 진리표 전수가 충분한 이유와 한계는?
9. (장애 진단) 배포 직후 "비로그인 요청에서만 500"이 나고 로그에 `Cannot invoke "...isAdmin()" because "<parameter1>" is null`이 찍혔다. 무엇이 바뀌었을 가능성이 크고, 메시지에 변수 이름 대신 `<parameter1>`이 나온 이유는?
