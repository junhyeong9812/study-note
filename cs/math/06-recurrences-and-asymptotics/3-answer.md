# math/06-recurrences-and-asymptotics — 정답

## 정답

### 1. 하노이 vs 병합 정렬

- 하노이는 크기 n−1(원래와 거의 같은) 부분 문제 둘 → T(n) = 2^n − 1. n = 64면 10¹⁹ 단계를 넘는다.
- 병합 정렬은 크기 n/2 부분 문제 둘 → T(n) ≈ n log n. n = 64면 수백 번 비교다(MCS 22.5 표).
- 성능을 정하는 것은 **부분 문제의 크기와 개수**다. 호출당 일(+1 vs +n)은 대개 덜 중요하다(MCS 22.5 경험칙 — 나누기형에서는 g(n)이 해를 바꿀 수 있다, 예: 2T(n/2) + n² = Θ(n²)). 상수만큼 줄면 깊이 n, 비율만큼 줄면 깊이 log n이다.

### 2. 재귀 트리

```text
  층 0          [n]                 일 n
  층 1      [n/2]   [n/2]           일 n
  층 2   [n/4][n/4][n/4][n/4]       일 n
  ...   층 수 log₂n + 1
  합 = n(log₂n + 1) = Θ(n log n)
```

- 4T(n/2) + n: 층 i의 일 = 4^i·n/2^i = 2^i·n으로 **는다** → 잎(마지막 층)이 지배, Θ(n²).
- 2T(n/2) + n²: 층 i의 일 = n²/2^i로 **준다** → 뿌리가 지배, Θ(n²).
- 실험(일 카운트): 2T(n/2) + n은 n = 2^20에서 22,020,096 = n·21, 4T(n/2) + n과 2T(n/2) + n²은 2n² − n(비 2.000).

### 3. 마스터 정리 적용

| | a, b | n^(log_b a) | g(n) | 경우 | 해 |
|---|---|---|---|---|---|
| (a) | 3, 2 | n^1.585 | n — 다항식만큼 작다 | 1 | Θ(n^(log₂3)) ≈ Θ(n^1.585) |
| (b) | 1, 2 | n⁰ = 1 | 1 = Θ(1) | 2 (k=0) | Θ(log n) |
| (c) | 8, 2 | n³ | n³ = Θ(n³) | 2 (k=0) | Θ(n³ log n) |
| (d) | 2, 2 | n | n log n = Θ(n·log¹n) | 2 (k=1) | Θ(n log² n) |

- (d)는 MCS Theorem 22.4.2의 경우 2(log^k 포함)로 풀린다. CLRS 3판 4.5의 마스터 정리는 경우 2를 k = 0으로만 적어 (d)를 직접 다루지 않고, 연습문제 4.6-2에서 log^k 경우를 보이게 한다.

### 4. 마스터 정리를 못 쓰는 식

- 2T(n/2) + n / log n: n^(log_b a) = n이다. g(n) = n / log n은 n보다 작지만 n^ε배만큼 작지는 않다. 경우 1이 아니고, k ≥ 0인 경우 2도 아니다. → **Akra–Bazzi**(MCS 22.4.1)로 푼다. 해는 Θ(n log log n)이다.
- T(n) = T(n−1) + n: 빼기형이라 마스터 정리 형태(T(n/b))가 아니다. → 전개하면 T(0) + n + (n−1) + … + 1 = T(0) + n(n+1)/2 = Θ(n²)(T(0) = 0이면 정확히 n(n+1)/2).

### 5. `remove(0)` 시간 예측

- 점화식: 크기 s 리스트에서 앞을 지우면 s−1개를 옮긴다. T(n) = T(n−1) + (n−1) → 총 이동 n(n−1)/2 = Θ(n²).
- n이 2배면 4배: 20만 ≈ 1.35초 × 4 ≈ 5.4초. 실측은 4,797~5,343ms였다(네 번 실행). 호스트 부하가 높을 때 돈 사실 점검 재실행은 10만 1,678ms, 20만 7,094ms였다 — 절대 시간은 환경 따라 흔들리고, 2배당 약 4배라는 비율이 예측의 핵심이다.
- 30만은 20만의 (1.5)² = 2.25배 → 약 11~12초, 부하가 높으면 16초 근처(외삽, 실측 아님).

### 6. 피보나치 호출 수

- 4 늘 때마다 약 **6.854배** ≈ φ⁴(φ ≈ 1.618, φ⁴ ≈ 6.8541). 실험에서 21,891 → 150,049 → 1,028,457 → 7,049,155로 배율이 6.8544 → 6.8541 → 6.8541, φ⁴에 수렴했다(정확히 같지는 않다).
- 호출 수 C(n) = C(n−1) + C(n−2) + 1, C(0) = C(1) = 1을 풀면 C(n) = 2·F(n+1) − 1. F(33) = 3,524,578이므로 C(32) = 7,049,155.

### 7. 재귀 리스트 뒤집기의 스택 오버플로

- 점화식 T(n) = T(n−1) + 1 — 일은 Θ(n)으로 괜찮지만 **깊이가 n**이다. 노드마다 스택 프레임이 하나 쌓인다.
- 실험의 깊이 n 재귀도 1만은 통과, 10만에서 `StackOverflowError`였다(기본 스택, 한계는 실행마다 다름).
- 고침: 포인터 세 개(prev, cur, next)로 도는 루프로 바꾼다. 깊이 1, 일 Θ(n).

```java
static Node reverse(Node head) {
    Node prev = null, cur = head;
    while (cur != null) { Node next = cur.next; cur.next = prev; prev = cur; cur = next; }
    return prev;
}
```

### 8. `subList` 복사 재귀

- 호출마다 남은 n−1개를 새 `ArrayList`에 복사 → T(n) = T(n−1) + n = Θ(n²). 입력 2배면 시간 약 4배.
- 깊이도 n이라 큰 입력에서 `StackOverflowError`까지 난다(장애 1·2가 겹침).
- 고침: 인덱스를 넘기거나 루프로 합한다(정리 노트 적용 3의 `sumGood`). 일 Θ(n), 깊이 1.

### 9. 급수로 설명

- 동적 배열 2배 확장: 크기가 1, 2, 4, …, n이 될 때마다 복사 → 1 + 2 + 4 + … + n/2 = n − 1 < n. 비 2인 **등비급수**는 마지막 항이 지배해 총량이 O(n)이다. 원소당 상수(분할상환 O(1), [algorithm/02](../../algorithm/02-asymptotic-analysis/2-summary.md)).
- 쿠폰 수집(매번 n종 중 하나가 균일·독립으로 나올 때): 이미 i종을 모았으면 새 종이 나올 확률이 (n−i)/n, 기다리는 횟수 기댓값 n/(n−i). 다 더하면 n(1/n + 1/(n−1) + … + 1) = n·H_n. **조화수** H_n은 ln n + 1/n 이상 ln n + 1 이하(MCS 식 14.21)라 n ln n 근처다.
