# math/08-expectation-variance-tails — 정답

## 정답

### 1. 평균과 꼬리

- 로그정규 `20·e^G`(G 표준정규)의 평균 = `20·e^(1/2)` ≈ 33.0ms, p99 = `20·e^(2.326)` ≈ 204.8ms.
- 실험 C(OpenJDK 21, 100만 건, seed 42): 평균 33.0, p50 20.0, p99 204.8, p99.9 435.7ms, 평균보다 느린 요청 30.9%.
- p99가 평균의 6배다. 오른쪽 꼬리가 평균을 중앙값 위로 끌어올렸고, 평균 하나로는 꼬리 크기를 알 수 없다. 백분위 SLO와 히스토그램 지표가 필요하다.

### 2. 선형성 vs 분산의 덧셈

- 선형성은 독립이 필요 없다. MCS 19.5: "Linearity of Expectation … do not assume any independence."
- 분산의 덧셈은 무상관(쌍별 공분산 0)이면 성립한다. 쌍별 독립은 그 충분조건이다(MCS 정리 20.3.8). 일반식은 `Var[X+Y] = Var[X] + Var[Y] + 2·Cov[X,Y]`.
- 차이를 만드는 항은 공분산 `Cov[X,Y] = E[XY] − E[X]E[Y]`다.

### 3. 칸 하나의 기대 원소 수

- `I_i` = 키 i가 칸 j에 가면 1. `E[I_i] = 1/m`.
- 칸 j의 원소 수 = `Σ I_i` → 선형성으로 `E = n/m = α`.
- 키들 사이의 독립은 필요 없다. 각 키가 칸에 균등하게 간다는 것(주변 확률 1/m)만 쓴다. 다만 칸 길이의 **분포**(최대 칸 길이 등)를 말하려면 독립이 필요하다(09의 포아송 근사).

### 4. 쿠폰 수집

- 기대값 n·H_n: 29.3, 518.7, 7485.5.
- 실험 A(10,000회, seed 42): 평균 29.4, 517.3, 7501.1. p99는 66, 916, 11664 → 평균의 약 2.2, 1.8, 1.6배. n=10의 최댓값은 102(평균의 3.5배).
- 단계마다 "새 종류가 나올 때까지"가 기하분포이고, 그 기댓값 n/(n−k)를 선형성으로 더한 것이다.

### 5. 세 상한과 실제

| x | 실제(정확값) | 마르코프 E/x | 체비셰프 250/(x−500)² | 체르노프 e^(−β(c)·500) |
|---|---|---|---|---|
| 530 | 0.0310 | 0.943 | 0.278 | 0.414 |
| 550 | 0.000865 | 0.909 | 0.100 | 0.0889 |
| 600 | 1.36×10⁻¹⁰ | 0.833 | 0.025 | 8.3×10⁻⁵ |

- 600에서 체르노프가 가장 강하다(MCS 예제의 "< 0.0000834"와 같다). 그래도 실제보다 6자릿수 느슨하다.
- 530에서는 체비셰프(0.278)가 체르노프(0.414)보다 강하다. 평균에 가까운 x에서는 이런 역전이 생긴다.
- 시뮬레이션 100만 회는 600 이상을 한 번도 보지 못했다(관측 빈도 0/1,000,000 — 실제 확률 1.36×10⁻¹⁰은 0이 아니다). 극단 꼬리는 시뮬레이션으로 잴 수 없어 상한식을 쓴다.

### 6. 체르노프의 전제

- 전제(MCS 정리 20.5.1): `T = T1 + … + Tn`, Ti는 **상호 독립**이고 `0 ≤ Ti ≤ 1`. 결론은 `c ≥ 1`에서 `P(T ≥ c·E[T]) ≤ e^(−β(c)·E[T])`.
- 맞는 경우: 요청마다 키를 독립·균등하게 해시해 샤드를 고른다. "이 요청이 샤드 s로 가나"가 독립 0/1이다. E[T] = 1000, c = 1.2면 상한 ≈ 6.9×10⁻⁹.
- 깨지는 경우: 요청들이 묶여 온다(예: 한 배치가 같은 키를 연달아 보냄). 그러면 0/1들이 상호 독립이 아니다(해석).
- 함께 볼 것: 키 인기도가 Zipf면 독립으로 뽑더라도 핫키 샤드의 평균이 1000이 아니다. 균등 평균을 넣은 계산이 틀린다. 09 실험 C에서 최대 샤드 부하가 평균의 1.99배였다.

### 7. 공통 원인

- 공통 원인 모델: `P(둘 다) = z + (1−z)·x² = 0.0005 + 0.9995 × 0.0005² ≈ 5.0×10⁻⁴` → 가용성 99.95%.
- 독립 가정: `0.001² = 10⁻⁶` → 99.9999%. 500배 차이.
- 실험 D(1억 칸, seed 42): 같은 AZ 5.02×10⁻⁴, 독립 9.3×10⁻⁷.
- 차이를 만드는 항: `P(A∩B) = P(A)P(B) + Cov(I_A, I_B)`의 공분산.

### 8. p99의 평균

- 백분위는 선형이 아니다. 인스턴스별 p99의 평균은 전체 요청의 p99가 아니다.
- 트래픽이 적은 인스턴스의 p99는 표본이 적어 크게 흔들리는데, 평균에서는 큰 인스턴스와 같은 무게를 받는다.
- 고침: 인스턴스별 히스토그램 버킷을 합친 뒤 전체 백분위를 계산한다. Prometheus summary의 분위수는 합칠 수 없으니 histogram을 쓴다(reliability/16).

### 9. 무작위 데우기

- 한 키가 n번 동안 한 번도 안 뽑힐 확률 `(1 − 1/n)^n ≈ e⁻¹ ≈ 0.368`. 약 37%가 비어 있다.
- 다 덮는 데 필요한 기대 횟수 n·H_n ≈ 7,485번(n=1000, 실험 A 평균 7,501).
- 고침: 키 목록을 순서대로(또는 셔플한 순서로) 한 바퀴 돈다. 그러면 정확히 n번이다.
