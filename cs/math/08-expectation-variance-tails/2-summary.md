# math/08-expectation-variance-tails — 기댓값 선형성·분산·꼬리 부등식(마르코프·체비셰프·체르노프) — 정리 (힌트)

## 해결하는 문제

대시보드의 평균 지연은 33ms다. 그런데 사용자 100명 중 1명은 200ms 넘게 기다린다. 평균은 그 1명을 거의 보여 주지 않는다.

```text
  지연 분포 (로그정규, 중앙값 20ms — 실험 C)
  건수
   █
   ██
   ███
   ████▆▄▃▂▂▁▁▁▁ ▁  ▁    ▁            ▁
   └──┬──┬───────────────┬─────────────┬────> ms
     20  33             205           436
    p50  평균           p99          p99.9
```

- 평균 하나로는 꼬리를 알 수 없다. 꼬리가 얼마나 무거울 수 있는지 상한을 주는 도구가 꼬리 부등식이다.
- 반대로 기댓값이 **유난히 잘 계산되는** 경우도 있다. 기댓값의 선형성은 독립을 몰라도 성립한다.

쉬운 예: 평균 소득. 한 명의 큰 값이 평균을 끌어올린다. "평균적인 사람"은 평균보다 적게 번다.

똑같은 구조다.\
지연·배치 시간·큐 길이처럼 오른쪽 꼬리가 긴 값은 평균이 중앙값보다 크고, 꼬리는 평균으로 보이지 않는다.

실무 예:
- 평균 지연 SLO는 녹색인데 p99 민원이 온다.
- "각 99.9%짜리 복제본 두 개 = 99.9999%"로 계산했는데, 같은 AZ 장애 한 번에 둘 다 내려갔다.
- 해시 테이블·무작위 퀵정렬의 "기대 O(1)·기대 O(n log n)"이 무엇을 보장하고 무엇을 보장하지 않는지.

## 동작·원리

### 1. 확률 변수와 기댓값

```text
  확률 변수 X : 결과 → 수            예) 요청 하나 → 지연(ms)
  기댓값    E[X] = Σ x · P(X = x)    (이산형: 가능한 값마다 값 × 확률을 더한다)
            E[X] = ∫ x · f(x) dx     (연속형: 밀도 f로 적분 — 지연처럼 연속인 값)

  지시 확률 변수 I_A = 1 (A가 일어남) / 0 (아님)
  E[I_A] = 1·P(A) + 0·P(not A) = P(A)
```

- *확률 변수(random variable)*: 실험 결과마다 수를 하나 붙이는 함수(MCS 19장).
- *기댓값(expectation)*: 확률로 가중한 평균. 같은 분포에서 (쌍별) 독립으로 반복해 뽑으면 표본 평균이 여기로 모인다(큰수의 법칙, MCS 따름정리 20.4.2 — 분산 유한 전제).
- *지시 확률 변수(indicator)*: 사건이 일어나면 1, 아니면 0. 기댓값이 그 사건의 확률이다. "몇 개가 일어나나"를 지시 변수의 합으로 쓰면 계산이 쉬워진다(CLRS 5.2).

### 2. 기댓값의 선형성 — 독립이 필요 없다

```text
  E[X + Y] = E[X] + E[Y]          X, Y가 독립이든 아니든 성립 (MCS 따름정리 19.5.3)
  E[a·X]   = a·E[X]

  예) 해시 칸 m개, 키 n개, 각 키가 칸 j에 갈 확률 1/m
      칸 j의 원소 수 = Σ I(키 i가 칸 j)  →  E = n · (1/m) = n/m = α (적재율)
```

- MCS는 "Linearity of Expectation and Theorem 19.5.4 do not assume any independence"라고 적는다(19.5).
- 해시 테이블: 체이닝에서 칸 하나의 기대 길이는 α = n/m이다. 칸 하나의 기대 길이에는 "각 키가 칸에 균등"(주변 확률 1/m)만 필요하다. 실패 검색이 훑는 원소 수의 기댓값도 α인데, 여기에는 조회 키의 칸이 저장 키들의 칸과 독립이라는 가정이 더 든다(CLRS의 단순 균등 해싱 정의에 독립이 들어 있다). 칸 길이의 실제 분포는 [09-common-distributions](../09-common-distributions/2-summary.md) 실험 A(포아송).
- 무작위 퀵정렬: 원소 쌍마다 "비교되나"를 지시 변수로 두고 더한다 → 기대 비교 수 O(n log n). 자세히는 [algorithm/39-randomized-algorithms](../../algorithm/39-randomized-algorithms/2-summary.md) 3절.

### 쿠폰 수집 — 선형성으로 푸는 대표 문제

```text
  n종류를 전부 모을 때까지 무작위로 뽑는다 (각 종류 균등, 매번 독립)
  이미 k종 모은 상태 → 새 종류가 나올 확률 (n−k)/n → 기다리는 횟수의 기댓값 n/(n−k)

  E[총 횟수] = n/n + n/(n−1) + … + n/1 = n · H_n ≈ n · ln n
              H_n = 1 + 1/2 + … + 1/n (조화수)
```

- 단계마다 "새 것이 나올 때까지 뽑는 횟수"는 기하분포다(09). 그 기댓값들을 선형성으로 더한다(MCS 19.5.4 "The Coupon Collector Problem").
- 운영 의미: 키 n개를 "무작위로 n번" 건드리면 다 건드린 게 아니다. 다 덮으려면 기대 n·ln n번이 든다.

### 3. 분산 — 퍼진 정도

```text
  Var[X] = E[(X − E[X])²] = E[X²] − (E[X])²       표준편차 σ = √Var[X]

  Var[X + Y] = Var[X] + Var[Y] + 2·Cov[X, Y]
             = Var[X] + Var[Y]                    ← Cov = 0(무상관)일 때. 쌍별 독립이면 충분 (MCS 정리 20.3.8)
  Var[a·X]   = a² · Var[X]                        (MCS 정리 20.3.4)
```

- *분산(variance)*: 평균에서 벗어난 거리의 제곱의 기댓값.
- *공분산 Cov[X, Y]*: `E[XY] − E[X]E[Y]`. 둘이 함께 커지면 양수다. 독립이면 0이다(역은 성립하지 않는다).
- 동전 1000번의 앞면 수 T: 동전마다 분산 1/4, 독립이라 더하면 `Var[T] = 1000 × 1/4 = 250`, σ ≈ 15.8.
- 기댓값과 달리 **분산의 덧셈에는 무상관(쌍별 공분산 0)이 필요하다.** 독립은 그 충분조건이다. 상관이 양수면 합의 분산이 더 커진다. 같은 AZ의 장애가 그런 경우다(6절).

### 4. 꼬리 부등식 세 개 — 아는 것이 많을수록 강하다

```text
  아는 것                       부등식                                         전제
  ─────────────────────────────────────────────────────────────────────────────────
  평균만                        마르코프  P(X ≥ x) ≤ E[X] / x                   X ≥ 0
  평균 + 분산                   체비셰프  P(|X − E[X]| ≥ x) ≤ Var[X] / x²        분산 유한
  독립인 [0,1] 값들의 합 T       체르노프  P(T ≥ c·E[T]) ≤ e^(−β(c)·E[T])        c ≥ 1, 상호 독립
                                         β(c) = c·ln c − c + 1
  ─────────────────────────────────────────────────────────────────────────────────
  상한의 모양:   1/x          1/x²            지수적으로 감소
```

- 출처: 마르코프 MCS 정리 20.1.1, 체비셰프 정리 20.2.3, 체르노프 정리 20.5.1(전제 "mutually independent, 0 ≤ Ti ≤ 1" 그대로).
- *꼬리(tail)*: 분포에서 평균으로부터 먼 쪽의 확률. p99·p99.9가 꼬리의 위치다.
- 체비셰프는 양쪽 꼬리(위·아래)를 합친 상한이다. 한쪽 꼬리는 이 값 이하다.
- 셋 다 **상한**일 뿐이다. 실제 꼬리는 훨씬 가벼울 수 있다. 대신 분포를 몰라도 성립한다.

- 관찰 4: 100만 번 시뮬레이션은 600 이상을 한 번도 못 봤다. 극단 꼬리는 시뮬레이션으로 재기 어렵다 — 이것이 상한식이 필요한 이유다.

### 5. 평균 vs 백분위 — 꼬리가 무거운 지연

```text
  p 백분위수(p-quantile): 값을 정렬했을 때 비율 p 지점의 값
  p50 = 중앙값, p99 = 100건 중 가장 느린 1건 언저리
```

(실험 C, 같은 환경, 로그정규 지연 100만 건 — `20 · e^G`, G는 표준정규(Box–Muller), seed 42)

```text
(C) 로그정규 지연(중앙값 20ms, σ=1) 1,000,000건
평균 33.0ms (이론 33.0)  p50 20.0ms  p99 204.8ms (이론 204.8)  p99.9 435.7ms  평균보다 느린 요청 30.9%
마르코프로 본 P(X>=p99) 상한 = 평균/p99 = 0.161 (실제 0.010)
```

- 로그정규 이론값: 평균 = `20·e^(σ²/2)` = 33.0, p99 = `20·e^(2.326σ)` = 204.8.
- 관찰 1: p99는 평균의 6.2배다. 평균 33ms만 보고는 205ms를 짐작할 수 없다.
- 관찰 2: 평균보다 느린 요청은 31%뿐이다. 오른쪽 꼬리가 평균을 중앙값 위로 끌어올렸다.
- 관찰 3: 마르코프 상한(16%)은 참이지만 실제(1%)보다 16배 느슨하다. 평균만 남긴 지표로는 꼬리를 거의 말할 수 없다.
- 이 분포는 예시 모델이다. 실제 지연은 다봉형(캐시 적중/미스)·더 무거운 꼬리를 가질 수 있다(해석).

### 6. 독립을 가정한 가용성 곱셈

```text
  복제본 A, B. 각각 다운 확률 ≈ 0.1%

  독립이면       P(둘 다 다운) = P(A)·P(B) = 0.001 × 0.001 = 10⁻⁶   → 99.9999%
  공통 원인 Z    A 다운 = Z 또는 X_A,   B 다운 = Z 또는 X_B
  (같은 AZ)     P(둘 다 다운) = P(Z) + (1 − P(Z))·P(X_A)·P(X_B)
                            = 0.0005 + 0.9995 × 0.0005² ≈ 5.0 × 10⁻⁴  → 99.95%

  P(A∩B) = P(A)·P(B) + Cov(I_A, I_B)    ← 공분산이 곱셈과의 차이
```

- 주변 확률(각 복제본 0.1%)은 같다. 차이는 공분산 하나다. 공통 원인이 있으면 이중화 결과는 그 공통 원인의 가용성을 넘지 못한다.
- 가용성 합성 식(직렬·병렬)과 공통 원인 시뮬레이션은 [reliability/01-fault-error-failure-availability](../../reliability/01-fault-error-failure-availability/2-summary.md) 5절, AZ 배치는 [reliability/25-high-availability-topology](../../reliability/25-high-availability-topology/2-summary.md). 여기서는 "곱셈 = 독립 가정"이라는 수학만 본다.

## 적용 — 풀어나가는 법

### 1. 평균만 있는 지표를 받았을 때

1. 증상: SLO는 평균 지연 기준으로 녹색, 민원은 "가끔 느리다".
2. 식으로 어림: 평균만으로는 마르코프 `P(X ≥ x) ≤ 평균/x`뿐이다. 평균 33ms면 "330ms 이상은 10% 이하"까지만 말할 수 있다. 꼬리를 말하려면 분포(히스토그램)가 필요하다.
3. 코드로 확인 — 원시 지연을 모아 백분위를 본다:

```java
// 지연 표본 → p50·p99·평균. 운영에서는 히스토그램 지표(버킷)로 낸다.
static double pct(double[] sorted, double p) { return sorted[(int) Math.ceil(p * sorted.length) - 1]; }
double[] s = latencies.clone(); Arrays.sort(s);
double mean = Arrays.stream(s).average().orElse(Double.NaN);
System.out.printf("mean=%.1f p50=%.1f p99=%.1f p99.9=%.1f%n", mean, pct(s, .5), pct(s, .99), pct(s, .999));
```

4. 대처: SLO를 백분위로 정한다(예: "p99 < 300ms"). 인스턴스별 p99를 평균 내지 말고 히스토그램을 합쳐 다시 계산한다(Prometheus summary는 합칠 수 없다 — reliability/16).

### 2. 체르노프로 "드물게 몰림"을 어림

- 상황: 샤드 100개에 요청 10만 건을 무작위로 보낸다. 샤드 하나의 기대 부하 E[T] = 1000.
- 질문: 한 샤드가 1.2배(1200) 이상 받을 확률은? 요청이 독립이고 각 요청이 그 샤드로 갈지 여부가 0/1이므로 체르노프 전제를 만족한다.
- `β(1.2) = 1.2·ln 1.2 − 0.2 = 0.01879` → `e^(−0.01879 × 1000) ≈ 6.9×10⁻⁹`. 샤드 100개 중 하나라도(합집합 상한) ≤ 6.9×10⁻⁷.
- 키 인기도가 Zipf면 "평균 1000"이 틀린다: 핫키가 간 샤드의 선택 확률이 1/100보다 커서 E[T]가 다르다([09-common-distributions](../09-common-distributions/2-summary.md) 실험 C). 요청마다 키를 독립으로 뽑는 한 체르노프는 그 샤드의 실제 평균으로 다시 쓸 수 있다.
- 독립 전제 자체가 깨지는 경우는 요청들이 묶여 오는 경우다(예: 한 배치가 같은 키를 연달아 보냄). 그때는 이 계산을 쓸 수 없다(해석).

### 3. 가용성을 곱하기 전에

- 이중화 칸마다 공통 원인(같은 AZ·배포·설정·인증서)을 적는다. 공통 원인을 별도 직렬 블록으로 넣어 계산한다(6절 식).
- 로그로 확인: 두 복제본의 분 단위 다운 여부로 `P(A∩B) / (P(A)·P(B))`를 낸다. 1보다 훨씬 크면 곱셈은 낙관적이다.

## 장애 시나리오와 대처

### 1. 평균만 보고 꼬리를 무시 (⚠ 커리큘럼)

- 현상: 평균 지연 SLO는 지켰는데 결제 타임아웃 민원이 늘었다.
- 보이는 형태: 평균 30ms대, p99 수백 ms. 평균보다 느린 요청이 30% 남짓(실험 C).
- 원인: 오른쪽 꼬리가 긴 분포에서 평균은 꼬리의 크기를 거의 드러내지 않는다. 마르코프 상한만 남는다.
- 대처: 백분위(p50·p99·p99.9) SLO, 히스토그램 지표, 꼬리 원인 분석(GC·캐시 미스·락). 팬아웃이면 [reliability/34](../../reliability/34-tail-latency-and-stragglers/2-summary.md)의 hedge.

### 2. "독립" 가정한 가용성 곱셈 (⚠ 커리큘럼)

- 현상: 99.9999%로 계산한 이중화 DB가 AZ 장애 한 번에 둘 다 내려갔다.
- 보이는 형태: 두 복제본의 다운 시작 시각이 같다. 같은 AZ·같은 랙·같은 배포 시각과 겹친다.
- 원인: `P(A)·P(B)`는 독립일 때만 맞다. 공통 원인이 공분산을 만들어 동시 다운 확률을 500배 키웠다(실험 D).
- 대처: 복제본을 다른 장애 도메인에 둔다. 계산에 공통 원인 블록을 넣는다. 배포·설정 변경을 AZ별로 순차 적용한다.

### 3. 인스턴스별 p99를 평균 냈다

- 현상: "전체 p99 = 인스턴스 p99들의 평균"으로 대시보드를 만들었다. 실제 사용자 p99와 맞지 않는다.
- 보이는 형태: 트래픽이 적은 인스턴스의 p99가 크게 흔들리며 평균을 흔든다.
- 원인: 백분위는 선형이 아니다. 기댓값과 달리 평균을 내도 전체의 백분위가 되지 않는다.
- 대처: 히스토그램 버킷을 합친 뒤 백분위를 계산한다(reliability/16).

### 4. "무작위로 n번이면 다 덮는다"

- 현상: 키 1000개를 무작위로 1000번 골라 캐시를 데웠다(또는 무작위 헬스체크로 노드 1000개를 점검했다). 첫 요청에서 미스가 많다.
- 보이는 형태: 데운 뒤에도 키의 약 37%(`(1 − 1/n)^n ≈ e⁻¹`)가 비어 있다.
- 원인: 쿠폰 수집 — 다 덮으려면 기대 n·H_n ≈ 7,485번이 든다(실험 A, n=1000).
- 대처: 무작위가 아니라 목록을 순회한다. 무작위가 필요하면 셔플한 순서로 한 바퀴 돈다([12-randomness-and-prng](../12-randomness-and-prng/2-summary.md)의 Fisher–Yates).

## 핵심 문장

- 기댓값의 선형성은 독립을 요구하지 않는다. 그래서 해시 칸 길이·퀵정렬 비교 수·쿠폰 수집이 쉽게 풀린다.
- 분산의 덧셈은 (쌍별) 독립이 필요하다. 상관이 있으면 공분산 항이 붙는다.
- 마르코프(평균만) → 체비셰프(분산) → 체르노프(독립 [0,1] 합) 순으로 아는 것이 늘수록 상한이 강해진다. 셋 다 상한이지 실제 꼬리가 아니다.
- 꼬리가 긴 지연에서 평균은 p99를 보여 주지 않는다. 지표는 히스토그램으로 남긴다.
- 가용성 곱셈은 독립 가정이다. `P(A∩B) = P(A)P(B) + Cov`의 공분산이 같은 AZ 장애다.
