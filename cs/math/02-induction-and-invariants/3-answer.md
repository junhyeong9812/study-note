# math/02-induction-and-invariants — 정답

## 정답

### 1. 테스트 vs 귀납

- 테스트는 입력 몇 개만 본다. 루프는 반복 횟수만큼 다른 상태를 지나가고, 버그는 특정 상태(길이 1, 경계 키)에서만 드러난다.
- 귀납은 "기저 P(0)"와 "P(n) ⇒ P(n+1)" 두 가지를 보여 n ≥ 0 각각을 덮는다(MCS 5.1). 경우를 하나씩 확인하지 않고 "한 단계"만 확인한다.

### 2. 세 성질과 불변식 원리

- 초기화 = 시작 상태에서 I가 참(귀납의 기저).
- 유지 = I(q)이고 q → r이면 I(r)(귀납 단계, MCS 정의 6.2.5 "보존되는 불변식").
- 불변식 원리: 둘이 성립하면 도달 가능한 상태 각각에서 I가 참(MCS 6.2.2).
- 종료(CLRS의 세 번째 성질) = 끝났을 때 I와 종료 조건을 합치면 원하는 결과가 나온다.
- 여기까지가 *부분 정확성*이다. 정확성에는 루프가 **끝난다**는 것이 더 필요하다. 음이 아닌 정수 척도가 매 바퀴 엄격히 줄면 끝난다(MCS 정리 6.3.2).

### 3. lowerBound의 불변식

```text
  I(lo, hi):  a[0..lo) 전부 < key,   a[hi..n) 전부 ≥ key,   0 ≤ lo ≤ hi ≤ n
  척도:       hi - lo
```

- `lo = 0`이면 `a[0..0)`이 비었고, `hi = n`이면 `a[n..n)`이 비었다. 빈 구역에 대한 "전부 ~"는 공허하게 참이다([01-propositional-logic](../01-propositional-logic/2-summary.md) §3).

### 4. 두 버그가 깨는 것

- `hi = mid - 1`: a[mid] ≥ key만 확인했는데, 확인하지 않은 a[mid−1]까지 오른쪽 "≥ key" 구역(a[hi..n))에 넣었다. a[mid−1]이 key보다 작으면 **불변식(유지)** 이 깨진다. 증상: 예외 없이 틀린 답(있는 키를 "없음"으로).
- `lo = mid`: `hi - lo = 1`이면 `mid = lo`라 구간이 그대로다. **척도**가 깨진다. 증상: 무한 루프, CPU 100%, 요청 타임아웃.

### 5. `-ea` 유무에 따른 실패 수

실험(`Inv.java`, OpenJDK 21.0.12, Random(42), 10,000회):

```text
-ea 없음: 버그1(hi=mid-1): 2230/10000 실패
-ea:      버그1(hi=mid-1): 3973/10000 실패
          첫 오류: AssertionError: 유지 단계에서 깨짐: step=1 lo=0 hi=-1 a=[6] key=6
```

- 다르다. `-ea` 없이는 "최종 답이 선형 탐색과 다른가"만 센다. `-ea`면 불변식이 깨진 순간 실패로 센다.
- 차이 1,743회는 불변식은 깨졌지만 답은 우연히 맞은 실행이다. 불변식 검사가 결함을 더 일찍, 원인 가까이에서 잡는다.
- `lo = mid` 판은 두 경우 모두 6,478회였다(`-ea` 없이는 1000회 상한 예외, `-ea`면 척도 assert).

### 6. off-by-one은 종료 단계의 문제

- 불변식은 매 반복 참이다(유지 OK). 그러나 n ≥ 1이면 끝났을 때 `i = n - 1`이라(n = 0이면 i = 0으로 끝나고 합 0도 맞다), 불변식이 말하는 것은 "앞 n−1개의 합"이다.
- 종료 단계에서 "불변식 + 종료 조건 ⇒ 전체 합"이 성립하지 않는다. 실험에서 `[3,1,4,1,5]`의 합이 14 대신 9였고, `-ea`에서 `종료 시 i=4 != n=5`로 잡혔다.

### 7. 약한 감소와 고정폭 정수

- 끝나지 않을 수 있다. "같을 수 있는" 척도는 같은 값에 머문 채 영원히 돌 수 있다(MCS 6.3.3).
- `unsigned i`는 0 다음이 4294967295라 `i >= 0`이 거짓이 될 수 없다. 실험에서 7번째 반복에 `i=4294967293`이었고, gcc 13.3.0 `-Wextra`가 `comparison of unsigned expression in '>= 0' is always true`로 경고했다.
- 수학 정수의 "1씩 감소"는 척도지만, Java 정수·C `unsigned` 같은 고정폭 정수에서는 경계에서 반대편으로 넘어가 척도가 아니다(C의 부호 있는 정수 오버플로는 미정의 동작 — C11 N1570 §6.5p5).

### 8. 강한 귀납과 재귀

- 강한 귀납은 P(0)…P(n) 전부를 가정할 수 있다(MCS 5.2). 크기 n 문제를 n/2 같은 "바로 앞이 아닌" 더 작은 문제로 줄이는 재귀(병합 정렬, 이진 탐색 재귀판)를 논증할 때 쓴다.
- 기저 사례 ↔ 기저, 재귀 호출이 맞다고 믿는 것 ↔ 귀납 가정, 입력이 엄격히 작아지는 것 ↔ 척도([algorithm/03-recursion](../../algorithm/03-recursion/2-summary.md) §1).

### 9. 끝나지 않는 페이지네이션

- 척도(종료)가 깨졌을 가능성이 크다. 외부 API가 마지막 페이지에서 같은 커서를 돌려주거나 빈 페이지에 커서를 계속 준다. "커서가 매번 앞으로 간다"는 가정은 내 코드가 아니라 외부 시스템이 지키는 것이다.
- 방어: "진행 없음" 검사(`nextCursor == cursor`면 예외)와 반복 상한(`MAX_PAGES`)을 둘 다 둔다. 스레드 덤프(`jstack`)로 같은 줄에 `RUNNABLE`인 스레드를 확인한다.

### 10. 운영에서 사라지는 assert

- Java `assert`는 기본으로 꺼져 있다. 실험 첫 줄이 `assert 활성(-ea) = false`였다. JLS §14.10: 꺼진 assert는 아무 효과가 없다.
- Maven Surefire·Gradle은 테스트 JVM에 기본으로 assert를 켠다(Surefire `enableAssertions` 기본 `true`, Gradle `java` 플러그인 기본 `true`). 그래서 테스트에서는 잡히고 운영에서는 지나간다.
- 대처: 운영에서 지킬 불변식은 `if (!cond) throw new IllegalStateException(...)`으로 쓴다. O(n) 훑기 같은 비싼 검사는 테스트에만 둔다.
