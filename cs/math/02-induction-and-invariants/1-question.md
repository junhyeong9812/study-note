# math/02-induction-and-invariants — 질문

## 질문

1. (왜) 루프를 몇 가지 입력으로 테스트해 통과했는데도 정확하다고 말할 수 없는 이유는? 귀납은 이 문제를 어떻게 푸나?
2. (그림) 루프 불변식의 세 성질(초기화·유지·종료)을 MCS의 불변식 원리와 짝지어 설명하라. 정확성을 말하려면 불변식 말고 무엇이 하나 더 필요한가?
3. (그림) 반열린 lowerBound의 불변식과 척도를 적고, `lo = 0, hi = n`에서 불변식이 참인 이유를 설명하라.
4. (예측) `hi = mid` 대신 `hi = mid - 1`로 바꾸면 불변식과 척도 중 무엇이 깨지나? `lo = mid + 1` 대신 `lo = mid`로 바꾸면? 각각 운영에서 어떤 증상으로 보이나?
5. (예측) 위 두 버그 판을 각각 `-ea` 없이 돌릴 때와 `-ea`로 돌릴 때(같은 판이면 두 실행의 무작위 입력 10,000개는 같다), `hi = mid - 1` 판의 실패 수는 같나 다르나? 다르다면 왜인가?
6. (경계) 합계 루프 `for (i = 0; i < n - 1; i++) s += a[i];`에서 불변식 `s = a[0] + ... + a[i-1]`은 매 반복 참이다. 그런데 결과가 틀리는 이유를 세 성질 중 어디에서 찾나?
7. (경계) 매 바퀴 "줄어들거나 그대로"인 양이 있으면 루프가 끝나나? `for (unsigned i = n; i >= 0; i--)`는 왜 끝나지 않나?
8. (연결) 강한 귀납은 어떤 재귀를 논증할 때 필요한가? 재귀 함수의 기저 사례·재귀 호출은 귀납의 무엇에 대응하나?
9. (장애 진단) 외부 API 페이지네이션 배치가 어느 날부터 끝나지 않고 CPU 한 코어를 100% 쓴다. 어떤 성질이 깨졌을 가능성이 크고, 코드에 어떤 방어를 넣나?
10. (장애 진단) 테스트에서는 `AssertionError`로 잡히던 불변식 위반이 운영에서는 아무 로그 없이 데이터 오류로만 나타난다. 이유와 대처는?
