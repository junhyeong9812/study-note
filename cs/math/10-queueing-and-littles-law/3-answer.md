# math/10-queueing-and-littles-law — 정답

## 정답

### 1. Little 법칙의 조건과 세 가지 상자

- 필요: 장기 평균이 존재해야 한다. Little(1961)의 조건은 세 평균(L, λ, W)이 유한하고, 과정이 정상이며 도착 과정이 에르고딕하다는 것이다. 이후 표본 경로 증명은 정상성 없이 "λ와 W의 장기 극한이 존재·유한"이면 충분함을 보였다(Little 2011). 들어온 만큼 나가는 안정 상태라고 기억하면 된다.
- 필요 없음: 도착 분포, 서비스 시간 분포, 처리 순서(FIFO·LIFO 등).
- ρ ≥ 1이라 큐가 끝없이 자라면 평균이 수렴하지 않아 쓸 수 없다.
- 상자별
  - 시스템 전체: `L = λW`
  - 대기열만: `Lq = λ·Wq`
  - 서버만(1대): 서버에서 일하는 평균 건수 = `λ·E[S] = ρ`(이용률 법칙)

### 2. M/M/1 계산 (E[S] = 10 ms)

| ρ | Wq = ρ/(1−ρ)·E[S] | W = E[S]/(1−ρ) |
|---|---|---|
| 0.5 | 10 ms | 20 ms |
| 0.8 | 40 ms | 50 ms |
| 0.9 | 90 ms | 100 ms |
| 0.99 | 990 ms | 1,000 ms |

- 0.8 → 0.9: W가 50 → 100 ms로 **2배**. 이용률은 0.1 올랐을 뿐이다.
- 기울기 `dW/dρ = E[S]/(1−ρ)²`가 ρ → 1에서 폭발한다.

### 3. `P(n) = (1−ρ)ρⁿ` 유도

- 정상 상태에서 n과 n+1 사이 흐름이 균형을 이룬다: `λ·P(n) = μ·P(n+1)` → `P(n+1) = ρ·P(n)` → `P(n) = ρⁿ·P(0)`.
- `Σ P(n) = 1`이 되려면 `P(0) = 1 − ρ`(ρ < 1 필요).
- 기하 분포의 평균: `L = Σ n·(1−ρ)ρⁿ = ρ/(1−ρ)`.
- Little로 `W = L/λ = 1/(μ − λ) = E[S]/(1−ρ)`.

### 4. 시뮬레이션 대조

- ρ = 0.8: 이론 Wq 4.00(E[S] 단위), 시뮬레이션 3.98~4.05(시드 1~3). 잘 맞는다.
- ρ = 0.99: 이론 99, 시뮬레이션 98.32~150.86. **시드에 따라 크게 흔들린다.** 1 근처에서는 줄이 한 번 길어지면 오래 남아, 200만 명으로도 평균이 덜 수렴한다(해석).
- 시간 평균 L(도착·이탈을 훑어 직접 적분)과 λ×W: ρ = 0.8에서 3.99 vs 3.99, ρ = 0.99에서 98.34 vs 98.38. 이 시뮬레이션에서 Little이 맞는다(분포 무관성의 근거는 증명이고, 이 실험은 M/M/1 한 예다).

### 5. 분산의 효과 (P-K 공식)

- M/G/1 폴라체크–힌친: `Wq = ρ/(1−ρ) · (1 + Cs²)/2 · E[S]`. 여기서 ρ/(1−ρ) = 4.
  - 고정(D, Cs² = 0): 4 × 0.5 = **2**
  - 지수(M, Cs² = 1): 4 × 1 = **4**
  - 초지수(H2, Cs² = 5.5): 4 × 3.25 = **13**
- 시뮬레이션: 2.01, 3.98, 12.74. 평균 서비스 시간·이용률이 같아도 분산만으로 대기가 6배 넘게 다르다.

### 6. 공유 큐 vs 따로 줄

- 공유 큐(M/M/10): 시뮬레이션 Wq 0.203, Erlang C 이론 대기 확률 0.409 → Wq = 0.409/(10 − 8) ≈ 0.205.
- 따로 줄(M/M/1 × 10): 시뮬레이션 3.982, 이론 4.000.
- 약 20배 차이다. 공유 큐에서는 비는 서버가 하나라도 있으면 기다리지 않는다. 따로 줄에서는 내 줄이 길어도 옆 서버가 놀 수 있다.
- 실무 함의: 같은 총용량이라도 작은 풀 여러 개로 쪼개면 대기가 늘어난다.

### 7. 풀 200개의 함정

- `a = λ·E[S] = 200`은 **평균** 동시 점유 수다. 풀 c = 200이면 이용률 ρ = 200/200 = 1이라 대기가 발산한다.
- 보이는 형태: HikariCP `Connection is not available, request timed out after 30000ms`, 풀 대기 스레드 증가.
- Erlang C 계산(포아송 도착·지수 서비스 가정): c = 201 → 183 ms, 210 → 7.5 ms, 220 → 1.09 ms, **221 → 0.91 ms**. 목표 1 ms 이하는 **221개**다.
- 원고 §2의 "200개 필요"는 평균값이다. 여유를 Erlang C로 어림하고, 하류 DB 한도와 함께 부하 테스트로 확정한다.

### 8. 배치 시간대의 p99 상승

- P-K 공식에서 대기는 `E[S²]`에 비례한다. 리포트 배치처럼 가끔 아주 긴 작업이 섞이면 평균 E[S]가 거의 그대로여도 Cs²가 커져 **같은 큐에 선 요청들의 평균 대기**가 늘어난다(5번: Cs² 1 → 5.5에서 대기 약 3.2배).
- 대처
  - 느린 작업을 별도 풀·큐로 분리(벌크헤드 — [reliability/28](../../reliability/28-bulkhead/2-summary.md)).
  - 긴 작업을 쪼개거나 타임아웃으로 꼬리를 자른다.
  - 배치를 한산한 시간대로 옮긴다.

### 9. L ≠ λ×W, 랙 증가

- 불일치만으로는 단정할 수 없다. 먼저 관측 구간과 요청 집계 기준(창 경계에 걸친 건)을 맞춘다(Little 2011 §2).
- 그래도 다르고 랙이 계속 는다면 정상 상태가 아닐 가능성이 크다. 도착률이 처리율을 넘어(ρ ≥ 1) 큐가 계속 자라는 중이다. 평균이 수렴하지 않으니 Little·M/M/1 공식의 전제가 깨졌다.
- 또 하나의 가능성: 측정 창이 체류 시간에 비해 짧아 창 끝에 걸친 요청이 빠졌다([reliability/21](../../reliability/21-scaling-principles/2-summary.md) 실험의 N = 64 행 66.2 vs 64.0).
- 대처: 처리율을 늘리거나(스케일 아웃·병목 제거) 도착을 줄인다(셰딩·속도 제한). 측정 창을 체류 시간보다 충분히 길게 잡는다.
