# math/03-sets-relations-orders — 정답

## 정답

### 1. 컬렉션이 기대하는 수학

- `HashSet`(`HashMap`): `equals`가 동치관계(반사·대칭·추이)이고, 같으면 `hashCode`도 같기를 기대한다(`Object` Javadoc).
- `List.sort`·`TreeSet`: 비교자가 전전순서이기를 기대한다 — 부호 반대칭·추이·0의 일관성(`Comparator` Javadoc).
- 깨져도 통과하는 이유: 성질은 타입이 아니라 값들 사이의 관계라 컴파일러가 검사하지 않는다. 위반은 특정 값 조합(하위 타입이 섞인 쌍, 가까운 세 값)에서만 드러나고, 드러나도 대개 예외가 아니라 조용히 틀린 결과다.

### 2. 관계의 성질

- 반사: 꼭짓점마다 자기 고리. 비반사: 자기 고리 없음.
- 대칭: 간선이 있으면 반대 간선도. 추이: x→y→z 경로가 있으면 x→z 간선도.
- 비대칭: x R y면 y R x가 아님 → 두 점 사이 간선 ≤ 1이고 자기 고리도 없음.
- 반대칭: **서로 다른** x, y에서 x R y면 y R x가 아님 → 자기 고리는 허용(MCS 10.11).
- 예: `≤`는 반대칭(x ≤ x 허용), `<`는 비대칭.

### 3. `hashCode`는 단사일 수 없다

- `hashCode`는 객체 → `int`(2^32개 값) 함수다. 서로 다른 객체(예: 문자열)는 2^32개보다 많을 수 있어 단사일 수 없다(비둘기집 — [math 05](../05-counting-and-birthday-bound/2-summary.md)).
- 결론: 같은 해시값(같은 버킷)이어도 다른 키일 수 있으므로, 버킷 안에서 `equals`로 최종 확인해야 한다([data-structure/05-hashmap](../../data-structure/05-hashmap/2-summary.md)). 해시가 같다고 같은 키로 보면 안 된다.

### 4. 대칭이 깨진 `equals`

실험(`Rel.java`, OpenJDK 21.0.12):

```text
p.equals(cp)=true  cp.equals(p)=false
add(p) 후 add(cp): size=2
add(cp) 후 add(p): size=1
```

- `HashMap.putVal`·`getNode`는 해시가 같은 기존 키 k에 대해 `key.equals(k)`, 즉 **새로 넣거나 찾는 키**의 `equals`를 부른다(OpenJDK 21 소스).
  - p 다음 cp: `cp.equals(p)` = false → 다른 원소로 추가 → 2개.
  - cp 다음 p: `p.equals(cp)` = true → 이미 있음 → 1개.
- 실험에서 `distinct()`도 입력 순서에 따라 2·1이었다.

### 5. `BigDecimal` 두 동치관계

- 실험: `equals=false compareTo=0`, `HashSet size=2`, `TreeSet size=1`.
- `equals`는 값과 스케일을 함께 보고(1.0 ≠ 1.00), `compareTo`는 값만 본다. Javadoc이 "natural ordering이 equals와 일관되지 않다"고 적는다.
- 같은 집합에 서로 다른 동치관계 두 개가 걸려, 해시 컬렉션(equals)과 정렬 컬렉션(compareTo)이 다른 동치류로 나눈다. `stripTrailingZeros()` 뒤에는 `HashSet`도 1개였다.

### 6. "0.5 이내면 같다"

- 반례: 1.0 ≈ 1.4(차이 0.4), 1.4 ≈ 1.8(0.4)이지만 1.0과 1.8은 0.8 차이라 같지 않다. 추이성이 깨진다. 실험: `NEAR(1.0,1.4)=0 NEAR(1.4,1.8)=0 NEAR(1.0,1.8)=-1`.
- union-find 결과: `[[1.0, 1.4, 1.8, 2.2], [5.0, 5.3]]`. union-find는 관계의 추이 폐포를 계산하므로 사슬로 이어진 1.0과 2.2(차이 1.2)가 한 동치류가 된다.

### 7. 동치관계·분할·라벨 함수

- 동치관계의 동치류들은 분할의 블록이다(MCS 정리 10.10.4). 거꾸로 분할이 있으면 "같은 블록에 있다"는 동치관계다.
- 관계가 동치관계인 것과 "어떤 전체 함수 f에 대해 f(a) = f(b)"인 것은 같다(MCS 10.10, 문제 10.58).
- 지침: `equals`를 "키 함수 값이 같다"로 정의하면(값 객체는 `record`) 반사·대칭·추이가 자동으로 따라온다. "가까우면 같다"가 필요하면 먼저 양자화 함수로 키를 만든다.

### 8. 순서의 종류

- 엄격한 부분순서: 비반사·추이(MCS 정의 10.6.7). 비교 불가능한 쌍이 있을 수 있다. 예: 의존성, `⊂`.
- 선형순서: 서로 다른 두 원소가 비교 가능한 부분순서(MCS 정의 10.8.1). 예: 정수의 `<`.
- 전전순서: 반사·추이·어느 두 원소든 비교 가능. 비교자의 `compare <= 0`이 이것이고, `compare == 0`이 동치관계가 된다(나이순 정렬에서 같은 나이).
- 의존성 그래프는 비교 불가능한 쌍(서로 무관한 두 모듈)이 있어 비교자로 표현할 수 없다. 엄격한 부분순서의 그래프는 DAG이고, 유한 DAG는 위상정렬을 갖는다(MCS 정리 10.5.4). 위상정렬은 부분순서를 어기지 않는 전순서 하나를 고른다.

### 9. "가까우면 0" 비교자의 간헐 예외

- 실험(`Near.java`, 200회씩): 예외 빈도는 값의 **밀도**와 **크기**에 따라 달랐다. 범위 0.02·n·n ≥ 1000일 때 170~174회, 범위 0.6·n에서는 0회, n = 31에서는 어느 밀도에서도 0회.
- 예외가 안 난 경우 결과는 대부분 틀렸다. 예: 범위 0.6·n, n = 1000에서 200회 모두 비교자 기준으로도 0.5 넘게 역전된 쌍이 있었다(최대 1.41).
- 원인: `compare == 0`이 추이적이지 않아(6번) 비교자 계약의 0의 일관성을 어긴다. TimSort는 위반을 우연히 발견할 때만 예외를 던진다([algorithm/09](../../algorithm/09-sorting-in-practice/2-summary.md)).
- 고치기: 금액을 센트 등으로 양자화한 키로 `Comparator.comparing(...)`을 쓴다. 동점은 유일 키로 푼다. `useLegacyMergeSort`로 예외만 숨기지 않는다.
