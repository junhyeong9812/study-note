# math/04-graph-theory-basics — 정답

## 정답

### 1. 그래프로 그리면 얻는 것

- "꼬였다"는 느낌에 **사이클**이라는 정확한 이름이 붙는다. 이름이 붙으면 찾는 알고리즘(Kahn, 3색 DFS)과 고치는 방법(간선 끊기, SCC 묶기)이 따라온다.
- 유한 방향 그래프에서 "위상 순서가 있다" ⇔ "사이클이 없다(DAG)"다.
  - DAG → 순서 있음: MCS Theorem 10.5.4. 들어오는 간선이 없는 정점을 맨 앞에 놓고 지우기를 반복한다.
  - 사이클 → 순서 없음: 사이클 위 정점들이 서로보다 앞이어야 해서 한 줄에 놓을 수 없다.

### 2. 차수 합 계산

- 핸드셰이크 보조정리(MCS Lemma 12.2.1): Σ deg = 2|E| = **10,000**.
- 홀수 차수 정점이 501개일 수 없다. 홀수 501개를 더하면 홀수인데, 나머지(짝수 차수)를 더해도 전체 합이 홀수가 되어 10,000과 맞지 않는다. 홀수 차수 정점 수는 짝수다.
  - 실험(V=1000, E=5000, 시드 42)에서도 `sum(deg)=10000`, `oddDegreeVertices=502`였다.
- 인접 리스트 항목: 간선 하나가 양쪽 리스트에 한 번씩 → **10,000개**.

### 3. 트리의 간선 수 조건

- 유한 그래프 G가 트리 ⇔ **연결이고** |V| = |E| + 1(MCS Theorem 12.11.6). "사이클 없음 + |V| = |E| + 1"도 같다.
- "간선 n − 1개"만으로는 부족하다.
  - 반례: 정점 a, b, c, d에 간선 a-b, b-c, c-a(3개 = n − 1). 삼각형에 사이클이 있고 d는 떨어져 있다. 트리가 아니다.
- 그래서 연결 여부(또는 사이클 없음)를 함께 확인해야 한다.

### 4. 사이클 추가 후 세 방식의 반응

(실험 출력, OpenJDK 21.0.12, 2026-10-07)

```text
cyclic kahn order: [V1__users, V3__payments] (2/5) stuck=[V2__orders, V4__order_items, V5__report_view]
cyclic 3-color cycle: [V2__orders, V4__order_items, V5__report_view, V2__orders]
naive recursive resolve: java.lang.StackOverflowError after calls=10990
```

- Kahn: V1, V3 두 개를 꺼내고 멈춘다. V2는 V5를, V5는 V4를, V4는 V2를 기다려 진입 차수가 0이 되지 않는다. 꺼낸 수 2 < 5이므로 사이클이 있다고 판정한다.
- 3색 DFS: GRAY인 V2를 다시 만나 사이클 경로 `V2 → V4 → V5 → V2`를 보고한다.
- 방문 표시 없는 재귀: 사이클을 계속 돌다 `StackOverflowError`로 끝난다. 터지는 호출 수는 실행마다 다르다(세 번 실행 10,990·11,037·11,045).

### 5. 다이아몬드와 판정법

- 방향으로는 **사이클이 없다.** a에서 d로 가는 두 길이 다시 만날 뿐 a로 돌아오지 않는다.
- "이미 방문 = 사이클"은 b를 거쳐 d를 끝낸 뒤 c에서 d를 다시 만나는 순간 사이클로 오탐한다.
- union-find는 방향을 모른다. a-b, a-c, b-d를 합친 뒤 c-d를 넣을 때 c와 d가 이미 같은 덩어리라 사이클로 본다. 무방향으로는 a-b-d-c-a가 사이클이 맞지만 방향 그래프의 답은 아니다.
- 방향 그래프는 3색 DFS(역방향 간선, CLRS 3판 Lemma 22.11)나 Kahn으로 판정한다.

### 6. 사이클이 있는 그래프에서 순서 정하기

- 서로 닿는 정점끼리(u → v, v → u 경로가 둘 다 있음) 묶으면 강연결 요소(SCC)다. 이 관계는 동치관계라 정점이 겹치지 않는 덩어리로 나뉜다.
- SCC 하나를 점 하나로 줄인 응축 그래프는 DAG다(CLRS 3판 22.5 — 보조정리 번호 `[?]`). 그 위에서 위상 순서를 정한다.
- 실무로는 "사이클 덩어리를 한 단위로 보고 덩어리 사이의 순서를 정한다"는 뜻이다. 덩어리 안의 순환 선행 조건은 그대로 남으므로, 간선을 끊거나 단계별 초기화(먼저 만들고 나중에 연결)로 따로 해소한다. 알고리즘은 [algorithm/18-scc](../../algorithm/18-scc/2-summary.md).

### 7. Spring Boot 2.6 기동 실패

- 빈 = 정점, "생성에 필요하다" = 간선. 빈 의존 그래프에 사이클이 있다.
- 2.6부터 순환 참조가 기본 금지라 사이클이 그대로 기동 실패로 드러났다(Spring Boot 2.6 Release Notes).
- 임시 조치: `spring.main.allow-circular-references=true`(2.5 동작으로 되돌림).
- 근본 조치: 사이클의 간선 하나를 없앤다. 공통 책임을 새 빈으로 분리하거나, 역방향 호출을 이벤트로 바꾼다.

### 8. 코어를 늘려도 빌드가 안 빨라지는 이유

- 프로세서가 무제한이어도 DAG의 병렬 완료 시간은 가장 긴 사슬(critical path)이 정한다. 태스크 실행 시간이 모두 같으면 사슬의 정점 수만큼의 단계다(MCS 10.5.2 가정, Corollary 10.5.9). 실행 시간이 다르면 실행 시간 합이 가장 큰 경로다.
- 사슬 위 태스크는 앞 태스크가 끝나야 시작한다. 코어 수는 "같은 깊이에 있는 태스크"만 동시에 돌린다(Theorem 10.5.8).
- 대처는 코어가 아니라 사슬 자체를 줄이는 것이다. 불필요한 의존 간선을 지우거나 긴 사슬 위 태스크를 쪼갠다.

### 9. Java 교착을 그래프로 읽기

- 대기 그래프: 정점 = 스레드, 간선 t1 → t2 = "t1이 t2가 쥔 락을 기다린다".
- `jstack` 출력의 `"t1" waiting to lock ... which is held by "t2"`와 그 반대 줄이 간선 두 개, 즉 사이클 t1 → t2 → t1이다.
- 재발 방지: 락에 전역 순서(전순서)를 정하고 그 순서로만 잡는다. 그러면 각 스레드는 자기가 쥔 모든 락보다 높은 순번의 락만 기다린다. 대기 사이클이 있다고 하면 사이클을 따라 기다리는 락 순번이 계속 커져야 하는데, 한 바퀴 돌아 처음으로 오면 자기보다 큰 수가 되어야 하므로 모순이다. 그래서 사이클이 생길 수 없다. 자세히는 [os/19-deadlock](../../os/19-deadlock/2-summary.md).
