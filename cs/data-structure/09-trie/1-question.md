## 질문

### A. 문제

1. 문제 1(가장 긴 공통 접두사 — `longestCommonPrefix`)을 어떻게 푸는가. 뿌리에서 내려가다 언제 멈추는가 — 자식이 하나뿐인데도 멈춰야 하는 경우가 왜 있는가(`["a", "ab"]` 의 답이 `"a"` 인 이유).
2. 문제 2(접두사 자동완성 앞에서 k 개 — `autocomplete`)를 어떻게 푸는가. `keysWithPrefix(prefix).subList(0, k)` 는 답이 맞는데 왜 시간 제한에 걸리는가. 이 문제가 `Trie` 가 아니라 `MapTrie` 를 구체 타입으로 받는 이유는 무엇인가.
3. 문제 3(서로 다른 부분 문자열 개수 — `countDistinctSubstrings`)을 어떻게 푸는가. 접미사를 전부 넣는데 왜 중복 제거를 따로 안 해도 되는가, 그리고 이 풀이는 n 이 커지면 왜 무너지는가.

### B. 자료구조 특성

4. 트라이가 왜 필요한가. 05-hash-map 과 06-bst 로는 "car 로 시작하는 것 전부"가 왜 안 되는가 — 해시맵이 못 하는 이유와 BST 가 흉내는 내지만 비싼 이유는 서로 다른가.
5. 어떤 형태의 데이터·접근 패턴에 트라이가 적합하고, 언제 쓰면 안 되는가. `contains` 만 필요한 워크로드에서 해시맵 대신 트라이를 쓰면 무엇을 더 내고 무엇도 못 얻는가.
6. `contains(w)` 가 O(L) 이고 n 에 전혀 의존하지 않는 구조적 이유는 무엇인가. "키를 통째로 저장하지 않는다 — 경로가 곧 키다"가 비용 표의 어느 칸으로 나타나는가.
7. 노드가 있느냐만으로는 왜 부족한가. `end` 표시를 빼면 "app" 과 "apple" 이 왜 구분이 안 되는가. 그리고 `startsWith` 를 `findNode(p) != null` 로 쓰면 빈 트라이에서 `startsWith("")` 가 왜 true 가 되는가 — 이걸 막는 조건은 무엇인가.
8. `wordsBelow` 가 동시에 해결하는 두 가지는 무엇인가. `countWithPrefix` 가 왜 부분 트리를 안 훑어도 되는가, 그리고 `remove` 에서 "이 노드를 끊어도 되는가"를 어떻게 판단해 주는가. "app" 과 "apple" 이 있을 때 "apple" 을 지우다 "app" 을 날리는 실수는 왜 안 나는가(05번 tombstone 과 같은 계열인 이유).
9. `collect` 에서 `StringBuilder` 를 붙였다 떼는 이유는 무엇인가. 자식에서 돌아와 글자를 떼는 걸 빠뜨리면 결과가 어떻게 되는가. 매번 새 문자열을 만들면 비용이 어디에 붙는가.
10. 최악의 사용 패턴을 만들어 보라 — `WordDictionary` 에 `"....."` 처럼 전부 점인 패턴을 물으면 총 비용이 얼마인가. 반대로 최선(`"apple"`)은 얼마인가. 왜 앞쪽부터 점이면 가지치기가 안 되는가. `"....e"` 를 빠르게 하려면 무엇을 더 만들어야 하는가.
11. `MapTrie` 와 `ArrayTrie` 의 트레이드오프는 무엇인가. `ArrayTrie` 는 왜 사전순 정렬이 공짜로 따라오고(0~25 순회), 그 대가로 무엇을 내는가 — 20글자 단어 100개에 참조 슬롯이 5만 칸 잡히는 계산이 어떻게 나오는가. 범위 밖 문자를 `insert`/`remove` 는 예외로, 조회는 false/빈 리스트/0 으로 처리하는 이유는 무엇인가.
12. 10-lru-cache 로의 연결 — 트라이는 접두사를 공유해 노드를 아끼지만 그래도 노드 수가 폭발한다(문제 3의 n(n+1)/2). 저장 공간이 유한할 때 "무엇을 버릴 것인가"를 정하는 구조가 왜 따로 필요해지는가. 05번 `LinkedHashMap` 위에 접근 순서를 얹으면 LRU 가 된다고 했던 지점과 어떻게 이어지는가.
