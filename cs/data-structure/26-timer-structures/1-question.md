# data-structure/26-timer-structures — 질문

## 질문

1. (왜) 타이머 구조를 고를 때 "등록·취소 비용"이 "만료 비용"보다 중요한 이유는? 근거가 된 관찰(리눅스 timer.c 주석)은 무엇인가?
2. (그림) 타이머 힙에서 등록·만료·취소의 비용을 그려라. `PriorityQueue.remove(Object)`와 `ScheduledThreadPoolExecutor`의 취소는 왜 비용이 다른가?
3. (예측) `ScheduledThreadPoolExecutor`에 1시간 뒤 작업 10만 개를 등록하자마자 취소했다. 기본 설정과 `setRemoveOnCancelPolicy(true)`에서 `getQueue().size()`는 각각 얼마인가? 기본 설정이 운영에서 어떤 문제로 이어지나?
4. (그림) 칸 8개·틱 1 ms 해시 휠에서 now=2일 때 "21 ms 뒤" 타이머가 들어갈 칸과 rounds는? 바늘이 그 칸을 몇 번 지나야 만료되나?
5. (예측) 만료 시각이 1..100000 틱에 고르게 퍼진 타이머 100만 개를 등록·만료시킨다. 힙, 512칸 해시 휠, 131072칸 해시 휠 중 어느 것이 가장 빠르고 어느 것이 가장 느릴까? 이유를 Varghese–Lauck의 per-tick 비용으로 설명하라.
6. (경계) 틱 100 ms 휠에 "10 ms 뒤" 타임아웃을 걸면 실제로는 언제 울리나? 실제 지연의 범위를 식으로 쓰고, 실험 결과와 대조하라.
7. (연결) 계층형 휠은 시·분·초 시계판과 어떻게 같은가? Varghese–Lauck의 원래 계층형 휠과 리눅스 4.8 이후 휠은 "옮겨 담기(cascade)"에서 어떻게 다르며, 리눅스는 무엇을 포기했나?
8. (장애 진단) 요청량이 일정한데 힙 사용량이 계속 오르다 `OutOfMemoryError`가 났다. 클래스 히스토그램 상위에 `ScheduledFutureTask`가 있다. 원인과 확인 방법, 대처는?
9. (장애 진단) Netty로 바꾼 뒤 "50 ms 타임아웃 설정이 안 먹는다(100 ms 넘어서 끊긴다)"는 보고와 "타이머 스레드 CPU가 높다"는 보고가 동시에 왔다. 각각 무엇을 의심하고 어떤 설정을 보나?
