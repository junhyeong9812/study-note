# data-structure/02-linked-list — 질문

## 질문

### A. 문제

1. 문제 1(조건에 맞는 원소를 모두 제거 — `removeAllIf`)을 어떻게 푸는가.\
   인덱스로 도는 풀이가 왜 O(n²)이 되고, O(n)으로 만드는 풀이는 무엇에 기대는가.
2. 문제 2(가운데 값 찾기 — `findMiddle`)를 어떻게 푸는가.\
   `size()`를 못 쓰고 한 번만 훑는다는 조건이 왜 이 기법을 강제하는가.
3. 문제 3(정렬된 두 리스트 병합 — `mergeSorted`)을 어떻게 푸는가.\
   `Iterator`에 "미리 보기"가 없다는 제약을 어떻게 우회하고, 왜 O(n+m)인가.

### B. 자료구조 특성

4. 연결 리스트가 왜 필요한가.\
   01-dynamic-array로는 무엇이 안 되는가 — 맨 앞 삽입/삭제와 중간 삽입/삭제에서 배열이 치르는 비용은 무엇인가.
5. 어떤 형태의 데이터·접근 패턴에 연결 리스트가 적합하고, 언제 쓰면 안 되는가.\
   인덱스 임의 접근이 잦은 워크로드에서 왜 무너지는가.
6. `get(i)`가 O(n)이고 `addFirst`가 O(1)인 구조적 이유는 무엇인가.\
   "주소를 계산한다"와 "세면서 간다"의 차이가 어디서 오는가.
7. `tail`을 들고 있는데도 `SinglyLinkedList.removeLast()`가 O(n)인 이유는 무엇인가.\
   반대로 `addLast`는 왜 O(1)인가.
8. 최악의 사용 패턴을 만들어 보라 — 예를 들어 `for (int i = 0; i < list.size(); i++) list.get(i)` 로 n개를 순회하면 총 비용이 얼마인가.\
   `Iterator`로 돌면 얼마인가.\
   왜 이 챕터에만 `Iterator`가 있는가.
9. 단일 연결과 이중 연결의 트레이드오프는 무엇인가 — 참조 하나를 더 두는 대가로 무엇을 얻고 무엇을 잃는가(`removeLast`, 뒤쪽 인덱스 접근, 노드당 메모리, `reverse`의 방식).
10. `reverse()`와 `Iterator.remove()`가 사실 같은 문제라고 하는 이유는 무엇인가 — 링크를 고치는 순서가 왜 중요한가.
11. 떼어낸 노드의 `prev`/`next`를 끊지 않으면 무슨 일이 생기는가.\
    `clear()`에서 `head`/`tail`만 `null`로 두면 충분한가.
12. 03-stack으로의 연결 — 연결 리스트의 한계(인덱스 접근 O(n))가 왜 문제가 되지 않는 자료구조가 있는가.\
    스택/큐가 접근 지점을 양 끝으로 제한하면 배열 구현과 연결 구현 중 무엇이 유리해지는가.
