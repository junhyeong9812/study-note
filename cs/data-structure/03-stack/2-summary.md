## 한눈에 — 쉽게 말하면

**스택 = 접시 쌓기.** 설거지한 접시를 위로만 쌓고, 쓸 때도 맨 위 것부터 꺼낸다.

- 넣는 것(push)도 꺼내는 것(pop)도 오직 맨 위에서만 한다. 중간이나 바닥은 건드리지 않는다.
- 그래서 마지막에 넣은 것이 가장 먼저 나온다 — 이 규칙의 이름이 LIFO(Last In, First Out, 후입선출)다.
- 한 곳만 만지니까 넣기/꺼내기가 항상 즉시(O(1)) 끝난다.
- "되돌리기(Ctrl+Z)", 함수 호출이 끝나면 부른 곳으로 돌아가는 것, 웹 브라우저의 뒤로 가기 — 전부 이 접시 쌓기다.

```text
push(C)                pop() -> C
   |                      ^
   v                      |
+-----+                +-----+
|  C  |  <- 맨 위(top)  |  B  |  <- 새 맨 위
+-----+                +-----+
|  B  |                |  A  |
+-----+                +-----+
|  A  |
+-----+
```

이 접시 더미가 **똑같은 구조로** 스택이다: 접시 = 원소, 맨 위 접시 = top, 쌓기 = push, 집기 = pop, 들여다보기 = peek. 아래 두 구현(ArrayStack, LinkedStack)은 이 접시 더미를 각각 배열과 연결 리스트로 흉내 낸 것이다.

## 구현 — ArrayStack (`src/main/java/com/datastructure/stack/ArrayStack.java`)

<!-- 메서드마다 내 언어로. 복잡도는 "왜 그런지"까지. -->

### 구조

```
ArrayStack — 맨 위가 배열의 "끝"이다
+-----------------------------------------------------+
| top = 3        (다음에 쓸 자리. 담긴 개수와 같다)      |
| elements ---+  (size() 는 top 을 그대로 반환한다)     |
+-------------|---------------------------------------+
              v
    idx    0     1     2     3     4     5     6     7
        +-----+-----+-----+-----+-----+-----+-----+-----+
        |  A  |  B  |  C  |     |     |     |     |     |
        +-----+-----+-----+-----+-----+-----+-----+-----+
                       ^     ^
                맨 위 = C     top (아직 비어 있는 칸)

    맨 위    = elements[top - 1]      <- peek 이 읽는 곳
    쓸 자리  = elements[top]          <- push 가 쓰는 곳
    size     = top,  capacity = elements.length

바닥(0번)이 아니라 끝에서 넣고 뺀다 -> 시프트가 0회 -> push/pop 이 O(1)
바닥에서 넣고 빼는 스택이었다면 매번 전체를 밀어야 해서 O(n) 이 됐을 것이다
```

### 동작 — push

```
[1] push(D) : 빈 칸에 쓰고 top 을 올린다. O(1)
        +-----+-----+-----+-----+        +-----+-----+-----+-----+
        |  A  |  B  |  C  |     |   ->   |  A  |  B  |  C  |  D  |
        +-----+-----+-----+-----+        +-----+-----+-----+-----+
                          ^ top = 3                        ^ top = 4
    ensureCapacity(top + 1);  elements[top++] = D;

[2] push 인데 꽉 참 : 2배 배열로 전부 복사한 뒤 쓴다. 그 순간만 O(n), 상환하면 O(1)
        +-----+-----+-----+-----+   capacity 4, top 4 -> 가득
        |  A  |  B  |  C  |  D  |
        +-----+-----+-----+-----+
          |     |     |     |     전체 복사 (n 회)
          v     v     v     v
        +-----+-----+-----+-----+-----+-----+-----+-----+
        |  A  |  B  |  C  |  D  |  E  |     |     |     |   capacity 8
        +-----+-----+-----+-----+-----+-----+-----+-----+
    newCapacity = elements.length * 2   (길이가 0 일 때만 DEFAULT_CAPACITY = 4 로 점프)
    한 칸씩 늘리면 push 마다 O(n) 이 되어 총 O(n^2). 배수로 늘려야 상환 O(1) 이 된다
```

그림 해설 (한 단계씩):

- [1] 자리가 남으면 top이 가리키는 빈 칸에 쓰고 top을 1 올린다. 아무도 안 움직이니 O(1).
- [2] 꽉 찼을 때만 두 배 배열로 전부 이사한 뒤 쓴다. 그 순간만 O(n).
  - *상환(amortized) O(1)*: 가끔 드는 큰 이사비를 평소의 싼 push들에 나눠 평균 낸 것. 두 배씩 늘리면 이사가 드물어 평균은 O(1).
  - 한 칸씩 늘리면 왜 안 되나: 매번 이사하게 되어 push마다 O(n), n번 하면 O(n²).

### 동작 — pop

```
pop() : top 을 내리고 그 칸을 읽은 뒤 null 로 비운다. O(1)
        +-----+-----+-----+-----+        +-----+-----+-----+-----+
        |  A  |  B  |  C  |  D  |   ->   |  A  |  B  |  C  |null |
        +-----+-----+-----+-----+        +-----+-----+-----+-----+
                                ^ top=4                    ^ top=3
    E value = elements[--top];  elements[top] = null;

    null 을 안 넣고 top 만 줄이면 -> 논리적으로만 사라진다
        +-----+-----+-----+-----+
        |  A  |  B  |  C  |  D  |   D 는 "없는 값"인데 배열이 아직 붙잡고 있다
        +-----+-----+-----+-----+   -> GC 가 D 를 못 치운다 (동적 배열의 remove 와 같은 이유)
                       ^ top=3
    비어 있는데 pop -> EmptyStackException
    clear() 는 0..top-1 을 전부 null 로 지우고 top = 0. 배열 길이(capacity)는 그대로 둔다

LIFO — 넣은 순서 A B C D, 꺼내는 순서 D C B A
    마지막에 건드린 칸을 다음에도 건드린다. 그래서 끝 한 곳만 보면 된다
```

그림 해설 (한 단계씩):

- top을 1 내리고 그 칸의 값을 읽어 돌려준다. 끝 한 곳만 만지니 O(1).
- 읽은 칸은 `null`로 비운다. top만 내리면 사용자 눈에는 사라졌는데("논리적 삭제") 배열은 여전히 그 값을 가리키고 있다.
  - *GC(가비지 컬렉터)*: 아무도 가리키지 않는 객체를 치우는 자동 청소부. 배열이 붙잡고 있는 한 D는 "없는 값"인데도 못 치운다 — 동적 배열의 remove와 같은 이유.
- 빈 스택에서 pop하면 돌려줄 것이 없다 — `EmptyStackException`을 던진다.

## 구현 — LinkedStack (`src/main/java/com/datastructure/stack/LinkedStack.java`)

### 구조

```
LinkedStack — 맨 앞(head)이 스택의 top 이다. 배열도 용량도 확장도 없다
+---------------------+
| top ---+            |
| size=3 |            |
+--------|------------+
         v
     +-------+      +-------+      +-------+
     | item D|      | item B|      | item A|
     | next -+----> | next -+----> | next  +----> null
     +-------+      +-------+      +-------+
     마지막에 push                    가장 먼저 push
     (= 다음에 pop 될 것)              (= 마지막에 pop 될 것)

이름은 같은데 뜻이 다르다
    ArrayStack.top  = int   "다음에 쓸 배열 인덱스" (= 담긴 개수)
    LinkedStack.top = Node  "맨 위 노드 그 자체"

여기서 tail 은 아예 필요 없다. 스택은 한쪽 끝만 쓰는 자료구조이기 때문이다
```

### 동작 — push / pop

```
[1] push(E) : 새 노드가 옛 top 을 가리키고 top 을 새 노드로. 언제나 O(1)
    before  top -> +---+      +---+      +---+
                   | D +----> | B +----> | A +----> null
                   +---+      +---+      +---+

    after   top -> +---+      +---+      +---+      +---+
                   | E +----> | D +----> | B +----> | A +----> null
                   +---+      +---+      +---+      +---+
    top = new Node(E, top);  size++;
    확장 복사가 없다 -> ArrayStack 처럼 "가끔 O(n)" 인 순간이 아예 없다

[2] pop() : top 을 한 칸 내리고 떼어낸 노드의 참조를 끊는다. O(1)
    before  top -> +---+      +---+      +---+
                   | E +----> | D +----> | B +----> null
                   +---+      +---+      +---+

    after          +---+      +---+      +---+
                   | E |      | D +----> | B +----> null
                   +---+      +---+      +---+
                   버림         ^ top
    popped = top;  top = popped.next;  popped.item = null;  popped.next = null;
    next 를 안 끊으면 버린 노드가 D 를 붙잡아 사슬 전체가 GC 되지 않는다

같은 목적, 다른 손질
    ArrayStack.pop  : 칸을 null 로 비운다     (배열이 값을 붙잡는 것을 막는다)
    LinkedStack.pop : 링크를 null 로 끊는다   (버린 노드가 사슬을 붙잡는 것을 막는다)
```

그림 해설 (한 단계씩):

- [1] push: 새 노드가 옛 top을 가리키게 만들고, top 표지를 새 노드로 옮긴다. 연결 리스트의 addFirst와 똑같다. 확장 이사가 아예 없어 "가끔 O(n)"인 순간조차 없다 — 언제나 O(1).
- [2] pop: top 표지를 다음 노드로 내리고, 떼어낸 노드의 화살표(item, next)를 끊는다. 안 끊으면 버린 노드가 뒤 사슬을 붙잡아 GC가 못 치운다.
- 두 구현의 마무리 손질이 다른 이유: 배열은 "칸"이 값을 붙잡고, 연결 리스트는 "버린 노드"가 사슬을 붙잡는다. 붙잡는 주체가 달라서 null을 넣는 자리가 다르다.

### 문제 2. 후위 표기식 계산

> 문제 설명: 공백으로 구분된 후위 표기식을 계산한다. 정수와 `+ - * /` 만 나온다.
> `"3 4 +"` -> 7 / `"3 4 + 2 *"` -> 14 / `"5 1 2 + 4 * + 3 -"` -> 14
> 나눗셈은 정수 나눗셈이다. 0 으로 나누면 ArithmeticException 이 그대로 나가면 된다.
> 식이 올바르지 않으면 IllegalArgumentException.
> 생각할 것 — 연산자를 만났을 때 꺼내는 순서가 중요하다. `"3 4 -"` 는 3-4 인가 4-3 인가? /
> 다 계산하고 스택에 값이 정확히 하나 남아야 올바른 식이다.
> 시그니처: `static int evaluatePostfix(String expression, Stack<Integer> buffer)`

  - *중위/후위 표기(infix/postfix)*: 중위는 우리가 쓰는 `3 + 4`(연산자가 가운데), 후위는 `3 4 +`(연산자가 뒤). 후위는 괄호와 우선순위가 필요 없어서, "숫자는 쌓고 연산자를 만나면 두 개 꺼내 계산"만으로 기계가 읽기 쉽다.

### 문제 3. 오른쪽의 첫 번째 더 큰 값 (이 문제집의 함정)

> 문제 설명: 각 원소에 대해, 그 오른쪽에서 처음으로 나타나는 더 큰 값을 찾는다. 없으면 -1.
> `[2, 1, 3]` -> `[3, 3, -1]` / `[5, 4, 3]` -> `[-1, -1, -1]` / `[1, 3, 2, 4]` -> `[3, 4, 4, -1]`
> 함정 — 각 원소마다 오른쪽을 훑으면 O(n^2) 이다. 테스트에 20만 개짜리 케이스와 시간 제한이 있다.

> 새 값이 들어왔을 때, 그 값보다 작은 것들은 답이 한꺼번에 정해진다. /

### 문제 5. 중위 표기식을 후위 표기식으로

> 문제 설명: 우리가 쓰는 표기(중위)를 문제 2가 계산할 수 있는 표기(후위)로 바꾼다.
> 토큰은 공백으로 구분되고 정수, `+ - * /`, 괄호만 나온다.
> `"3 + 4 * 2"` -> `"3 4 2 * +"` / `"( 3 + 4 ) * 2"` -> `"3 4 + 2 *"` /
> `"3 - 4 - 5"` -> `"3 4 - 5 -"` — 왼쪽부터 묶인다
> 이 변환을 shunting yard 알고리즘이라고 부른다. 결과를 문제 2에 그대로 넣으면 계산이 된다. 두 문제가 이어진다.
> 규칙 — 숫자: 바로 출력한다 / 여는 괄호: 쌓는다 / 닫는 괄호: 여는 괄호를 만날 때까지 꺼내 출력하고, 여는 괄호는 버린다 /
> 연산자: 스택 위에 "우선순위가 같거나 높은 연산자"가 있으면 먼저 꺼내 출력한 뒤 쌓는다 / 끝나면: 남은 것을 전부 꺼내 출력한다
> 생각할 것 — 왜 "같거나 높은"인가? "높은"만 보면 `3 - 4 - 5` 가 어떻게 되는가?
> 사칙연산은 왼쪽부터 묶이는데, 그 성질이 이 조건 하나에 들어 있다. /
> 괄호가 안 맞으면 언제 알 수 있는가? 두 가지 경우가 있다.
> 괄호가 맞지 않으면 IllegalArgumentException.
> 시그니처: `static String infixToPostfix(String expression, Stack<Character> buffer)`

  - *shunting yard(입환장) 알고리즘*: 기차역에서 차량을 대기 선로에 잠깐 세워뒀다 순서를 바꿔 내보내는 것처럼, 연산자를 스택(대기 선로)에 쌓았다가 우선순위에 맞는 순서로 내보내는 변환법. Dijkstra가 만들었다.
  - *우선순위(precedence)*: `*` `/`가 `+` `-`보다 먼저 묶인다는 규칙. *왼쪽 결합(left-associative)*: 우선순위가 같으면 왼쪽부터 묶인다(`3 - 4 - 5` = `(3-4)-5`) — "같거나 높으면 먼저 내보내기" 조건이 이 성질을 구현한다.

## 용어 풀이

- **스택(stack)**: 한쪽 끝(맨 위)에서만 넣고 꺼내는 자료구조. 접시 쌓기.
- **push / pop / peek**: 쌓기 / 맨 위 꺼내기 / 꺼내지 않고 맨 위 들여다보기.
- **LIFO(후입선출)**: Last In, First Out — 마지막에 넣은 것이 가장 먼저 나온다.
- **top**: 맨 위의 위치. ArrayStack에서는 "다음에 쓸 배열 인덱스"(숫자), LinkedStack에서는 "맨 위 노드 그 자체"(참조) — 이름은 같은데 뜻이 다르다.
- **O(1), O(n)**: 데이터가 n개일 때 걸리는 시간의 대략적 표기. O(1)은 개수와 무관하게 즉시, O(n)은 개수에 비례. O(n²)은 n×n번 — 20만 개면 400억 번이라 시간 초과.
- **상환 분석(amortized, 분할상환)**: 가끔 한 번 비싼 작업(전체 복사)의 비용을 여러 번의 싼 작업에 나눠 평균 낸 것. 두 배 확장 덕에 push 1회 평균 O(1).
- **capacity / size**: 내부 배열의 칸 수(미리 잡아둔 여유) / 실제 담긴 개수.
- **시프트(shift)**: 배열 중간에 넣거나 뺄 때 뒤 원소들을 밀고 당기는 일. 스택은 끝에서만 조작하므로 시프트가 0회 — 이게 O(1)의 비밀.
- **GC(가비지 컬렉터)**: 아무도 가리키지 않는 객체를 자동으로 치우는 청소부. pop한 칸/노드의 참조를 null로 끊어야 청소가 된다.
- **논리적 삭제**: top만 내려서 "사용자 눈에만" 사라진 상태. 물리적으로는 배열이 아직 값을 붙잡고 있다.
- **노드(node) / 참조(reference)**: 연결 리스트의 한 칸 / 값이 있는 곳을 가리키는 화살표. `null`은 "아무것도 안 가리킴".
- **예외(exception)**: 계속 진행할 수 없을 때 던지는 오류 신호. `EmptyStackException`(빈 스택 pop), `IllegalArgumentException`(잘못된 입력), `ArithmeticException`(0으로 나눔).
- **중위/후위 표기(infix/postfix)**: 연산자가 가운데(`3 + 4`) / 뒤(`3 4 +`)에 오는 수식 표기. 후위는 괄호·우선순위 없이 스택만으로 계산된다.
- **shunting yard**: 중위→후위 변환 알고리즘. 연산자를 스택(대기 선로)에 세워뒀다 우선순위 순서로 내보낸다.
- **우선순위(precedence) / 왼쪽 결합(left-associative)**: 어떤 연산자가 먼저 묶이는가(`*` > `+`) / 우선순위가 같을 때 왼쪽부터 묶이는 성질.
- **단조 스택(monotonic stack)**: 문제 3의 기법 — 스택 안을 항상 한 방향(감소/증가) 정렬 상태로 유지하며, 새 값이 그 질서를 깨는 순간 쌓인 것들의 답이 한꺼번에 정해진다. 각 원소가 최대 1번 들어가고 1번 나와서 O(n).
