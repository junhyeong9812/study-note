# data-structure/01-data-structures-basics — 질문

## 질문

1. (왜) 배열과 연결 리스트는 "위치로 읽기"와 "중간에 끼우기"의 비용이 서로 반대다. 메모리 배치 그림으로 이유를 설명하라.
2. (예측) 원본 §5의 `Queue`(`list.pop(0)`)에 n개를 넣고 전부 꺼낸다. n을 20,000 → 40,000 → 80,000으로 두 배씩 늘리면 시간은 각각 몇 배쯤 되겠나? `collections.deque.popleft()`로 바꾸면?
3. (경계) "연결 리스트는 삽입·삭제가 잦을 때 쓴다"(원본 §6)는 말은 어떤 조건에서만 맞나? 조건이 깨지면 비용은?
4. (예측) 원본 §10의 BST에 1부터 2000까지를 차례로 넣으면 높이는? 같은 키를 무작위 순서로 넣으면 대략 어느 정도가 되나? 이 트리의 높이를 재귀 함수로 재면 CPython에서 무슨 일이 생기나?
5. (장애 진단) 원본 §9의 후위 순회 코드로 1~7 완전 이진 트리(1의 자식 2·3, 2의 자식 4·5, 3의 자식 6·7)를 돌렸더니 `4 5 2 3 6 7 1`이 나왔다. 무엇이 틀렸나?
6. (장애 진단) 원본 §10 `remove(99)`(없는 키)가 `AttributeError: 'NoneType' object has no attribute 'left'`를 낸다. 원인과 고치는 법은? 원본의 "BST는 중복을 가질 수 없다"는 설명과 `insert` 코드는 일치하나?
7. (계산) 원소 100만 개를 Java `ArrayList<Integer>`와 `LinkedList<Integer>`에 담으면 (원소 객체를 빼고) 컨테이너 메모리는 대략 얼마씩인가? 차이가 나는 이유는?
8. (연결) 스택·큐가 일반 리스트보다 "할 수 있는 연산이 적은" 것이 왜 장점인가? Sedgewick 1.3의 `java.util.Stack` 비판과 연결해 답하라.
9. (적용) "작업을 들어온 순서대로 처리하고, 대기 건수가 운영에서 수만 건까지 간다"는 요구가 있다. Java와 파이썬에서 각각 무엇을 쓰고 무엇을 피하나? 구조를 고르는 네 단계 순서로 답하라.
