### A. 문제 (ArrayProblems)

#### 1. 정렬된 배열에서 중복 제거 (제자리)

```java
/**
 * 문제 1. 정렬된 배열에서 중복 제거 (제자리)
 *
 * 오름차순으로 정렬된 배열이 주어진다. 중복을 없애고 남은 개수를 반환한다.
 * 새 배열을 만들지 말고 주어진 배열을 직접 줄여야 한다.
 *
 *   [1, 1, 2, 2, 2, 3]  ->  [1, 2, 3],  반환 3
 *
 * 생각할 것
 *   - 정렬되어 있다는 조건을 어디에 쓸 수 있는가?
 *   - 한 번의 순회로 끝낼 수 있는가?
 */
public static int removeDuplicatesSorted(DynamicArray<Integer> array)
```

- "정렬되어 있다"는 조건에서 무엇을 끌어낼 수 있는가?
- 새 배열에 담아 개수만 반환하는 풀이는 왜 정답이 아닌가?
- 순회하면서 `remove(i)` 를 부르는 풀이는 왜 뒤에서부터 돌아야 하는가?
- 그 풀이는 왜 최악에 O(n^2) 이 되는가?
- 그 최악을 만드는 입력을 하나 지어보라.
- 반대로 그 풀이가 빠르게 끝나는 입력은 어떤 모양인가?
- 한 번의 순회, O(n) 으로 끝내는 풀이는 무엇인가?
- 그 풀이에서 `write` 는 무엇을 뜻하고, 왜 배열을 뒤져서 정하면 안 되는가?
- 그 풀이는 왜 앞에서부터 돌아야 하는가?
- 비교 대상이 "다음 값"이 아니라 "마지막으로 쓴 값"이어야 하는 이유는?
- 데이터가 100만 건이면 두 풀이 중 어느 쪽이 살아남는가?

#### 2. k 칸 오른쪽으로 회전

```java
/**
 * 문제 2. k 칸 오른쪽으로 회전
 *
 *   [1, 2, 3, 4, 5], k=2  ->  [4, 5, 1, 2, 3]
 *
 * 생각할 것
 *   - k 가 size 보다 클 수 있다. k 가 음수일 수도 있다.
 *   - 임시 배열을 하나 써서 옮겨도 되고, 세 번 뒤집는 방법도 있다.
 *     (전체 뒤집기 -> 앞 k 개 뒤집기 -> 나머지 뒤집기)
 */
public static <E> void rotate(DynamicArray<E> array, int k)
```

- k 가 size 보다 크거나 음수일 때 가장 먼저 해야 할 일은 무엇인가?
- 자바의 `%` 가 음수를 줄 수 있는데 어떻게 0 이상으로 만드는가?
- 임시 배열을 쓰는 풀이의 시간·추가 공간 복잡도는 각각 얼마인가?
- 세 번 뒤집기 풀이의 시간·추가 공간 복잡도는 각각 얼마인가?
- 세 번 뒤집기가 왜 회전과 같은 결과를 내는가?
- `remove(0)` 을 k 번 부르고 뒤에 붙이는 풀이는 왜 안 되는가?
- 데이터가 커지면 두 풀이 중 어느 쪽이 먼저 한계에 닿는가?

#### 3. 정렬을 유지하며 삽입

```java
/**
 * 문제 3. 정렬을 유지하며 삽입
 *
 * 오름차순 배열에 값을 넣되 정렬이 깨지지 않게 한다. 삽입된 위치를 반환한다.
 * 같은 값이 이미 있으면 그 뒤에 넣는다.
 *
 *   [1, 3, 5], 4  ->  [1, 3, 4, 5],  반환 2
 *
 * 생각할 것
 *   - 위치를 찾는 데 이진 탐색을 쓰면 O(log n) 이다.
 *     그런데 삽입 자체가 O(n) 시프트다. 전체 복잡도는 결국 무엇인가?
 */
public static int insertSorted(DynamicArray<Integer> array, int value)
```

- 넣을 자리를 앞에서부터 훑어 찾는 풀이의 비용은 얼마인가?
- 이진 탐색으로 찾는 풀이는 무엇을 찾는 것인가(값의 위치인가, 경계인가)?
- "같은 값이 있으면 그 뒤"라는 조건은 비교 연산자를 어떻게 바꾸는가?
- 자리 찾기를 O(log n) 으로 줄여도 전체 복잡도가 그대로인 이유는?
- 그래도 이진 탐색이 무의미하지 않은 이유는?
- 정렬 삽입이 계속 반복되는 워크로드라면 동적 배열이 맞는 선택인가?

#### 4. 조건에 맞는 원소를 모두 제거 (이 문제집의 핵심)

```java
/**
 * 문제 4. 조건에 맞는 원소를 모두 제거 (이 문제집의 핵심)
 *
 * predicate 가 true 인 원소를 전부 없애고, 제거한 개수를 반환한다.
 *
 * 함정
 *   가장 먼저 떠오르는 방법은 훑으면서 remove(i) 를 부르는 것이다. 정답은 나온다.
 *   그런데 remove 한 번의 비용이 얼마인가? 그걸 n 번 부르면 총 비용은?
 *   테스트에 100만 개짜리 케이스가 있고 시간 제한이 걸려 있다.
 *
 * O(n) 이어야 한다.
 */
public static <E> int removeAllIf(DynamicArray<E> array, Predicate<? super E> predicate)
```

- 훑으면서 `remove(i)` 를 부르는 풀이는 총 몇 번의 복사를 일으키는가(식으로)?
- 그 풀이가 100만 건에서 통과하지 못하는 이유는?
- O(n) 풀이는 무엇에 기대는가?
- 문제 1의 O(n) 풀이와 무엇이 같고 무엇이 다른가?
- 마지막에 꼬리를 자르는 일은 왜 O(n) 안에 들어오는가?
- 꼬리를 앞에서부터 지우면 어떻게 되는가?
- `Predicate<? super E>` 로 받는 이유는 무엇인가?

#### 5. 정렬된 두 배열 병합

```java
/**
 * 문제 5. 정렬된 두 배열 병합
 *
 * 오름차순 배열 둘을 합쳐 오름차순 새 배열로 만든다. 원본은 건드리지 않는다.
 *
 *   [1, 3, 5] + [2, 3, 6]  ->  [1, 2, 3, 3, 5, 6]
 *
 * 생각할 것
 *   - 합쳐서 정렬하면 O((n+m) log(n+m)) 이다. 이미 정렬되어 있다는 조건을 쓰면 O(n+m) 으로 된다.
 *   - 결과 배열의 최종 크기를 미리 알 수 있다. 그러면 확장이 몇 번 일어나는가?
 */
public static DynamicArray<Integer> merge(DynamicArray<Integer> a, DynamicArray<Integer> b)
```

- 합쳐서 정렬하는 풀이는 왜 O((n+m) log(n+m)) 인가?
- 이미 정렬되어 있다는 조건을 쓰면 왜 log 가 사라지는가?
- 두 포인터로 합칠 때 한쪽이 먼저 소진되면 어떻게 하는가?
- 결과 배열의 최종 크기를 미리 잡으면 확장이 몇 번 일어나는가?
- 미리 잡지 않으면 확장과 복사가 얼마나 더 붙는가?
- 원본을 건드리지 않으려면 무엇을 지켜야 하는가?
- 같은 값이 양쪽에 있을 때 어느 쪽을 먼저 넣는가, 그 선택은 무엇과 관련 있는가?
- 두 배열이 메모리에 다 안 올라갈 만큼 크면 이 풀이는 어떻게 바뀌어야 하는가?

### B. 자료구조의 특성

#### 6. 동적 배열은 왜 필요한가

- 고정 길이 배열의 어떤 한계를 메우는가?
- 내부에서 실제로 무슨 일을 해서 "늘어나는 것처럼" 보이게 하는가?
- `size` 와 `capacity` 를 분리해서 갖는 것이 그 한계 극복에서 하는 역할은 무엇인가?
- 둘이 항상 같다면 add 의 비용은 어떻게 되는가?

#### 7. 어떤 데이터·접근 패턴에 적합한가

- 어떤 접근 패턴에서 동적 배열이 유리한가?
- 어떤 접근 패턴에서 불리한가?
- 어떤 형태의 데이터를 담기에 좋은가(크기 변동, 순서, 접근 방식 기준으로)?
- 연결 리스트(02번)와 비교했을 때 무엇을 얻고 무엇을 내주는가?
- 그 교환의 뿌리가 되는 설계 선택 한 가지는 무엇인가?
- 데이터가 수천만 건이 되면 연속 저장이 어떤 문제를 만드는가?

#### 8. 확장할 때 왜 2배로 키우는가

- 1씩 키우면 add 를 n 번 할 때 총 복사량은 얼마인가(식으로)?
- 2배로 키우면 확장은 몇 번 일어나고 총 복사량은 얼마인가(식으로)?
- "상환(amortized) O(1)" 은 정확히 무슨 뜻인가?
- "언제나 O(1)" 과는 어떻게 다른가?
- capacity 가 0 일 때 2배를 하면 어떤 일이 생기고 어떻게 막는가?
- 2배가 아니라 1.5배나 3배면 무엇이 달라지는가?
- 응답 지연이 중요한 시스템에서 "가끔 튀는 O(n)" 은 왜 문제가 되는가?

#### 9. 왜 1/4 이하에서 절반으로 줄이는가

- 늘리기만 하고 줄이지 않으면 무엇이 문제인가?
- 1/2 에서 줄이면 무슨 일이 생기는가(thrashing)?
- 1/4 에서 줄이면 왜 그 일이 안 생기는가?
- 축소에 하한(최소 용량)을 두지 않으면 어떤 일이 벌어지는가?
- 축소 정책이 구현 재량이 아니라 계약이 된 이유는?

#### 10. `remove(index)` 의 비용이 자리마다 다른 이유

- `remove` 가 실제로 하는 일은 무엇인가?
- 맨 뒤를 지울 때 O(1) 인 이유는?
- 맨 앞이나 중간을 지울 때 O(n) 인 이유는?
- 이 사실은 "여러 개를 지워야 할 때" 어떤 전략을 시사하는가?
- `remove(int)` 와 `remove(Object)` 는 왜 헷갈리고, `DynamicArray<Integer>` 에서 무엇이 문제인가?

#### 11. 최악 입력을 직접 만들어보라

- `add(0, x)` 를 n 번 하면 총 복사량은 얼마인가?
- 중간 `remove` 를 n/2 번 반복하면 총 복사량은 얼마인가?
- 반대로 총비용이 선형에 머무는 최선의 사용 패턴은 무엇인가?
- 최악 패턴이 실제 워크로드라면 무엇을 바꿔야 하는가?

#### 12. 지운 자리의 참조와 `toArray` 의 복사본

- `remove` 뒤에 마지막 칸의 참조를 왜 끊어야 하는가?
- 끊지 않으면 구체적으로 무슨 일이 생기는가?
- `clear()` 에서 size 만 0 으로 만들면 왜 안 되는가?
- 참조를 끊었는지를 공개 API 로는 왜 관측할 수 없는가?
- 테스트는 그것을 어떻게 검사하는가?
- 그래서 무엇이 "계약의 일부"가 되었는가?
- `toArray()` 가 내부 배열이 아니라 복사본을 주는 이유는(두 가지)?

#### 13. 루프 횟수가 아니라 루프 안 비용을 곱해야 하는 이유

- 총비용을 셀 때 루프 횟수만 보면 무엇을 놓치는가?
- `2n` 은 왜 O(n) 인가?
- `n번 x O(n)` 은 왜 O(n^2) 인가?
- m x k 로 계산되는 비용을 왜 O(n^2) 이라고 부르는가?
- 이 문제집에서 그 차이가 실제 시간으로 드러나는 곳은 어디인가?
- 더해지는 비용(순차 실행)과 곱해지는 비용(루프 안)은 어떻게 구분하는가?
