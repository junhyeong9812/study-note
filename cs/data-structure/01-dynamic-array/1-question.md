### A. 문제 (ArrayProblems)

1. **정렬된 배열 중복 제거(제자리)** — `[1,1,2,2,2,3] -> [1,2,3]` 을 한 번의 순회, O(n) 으로 하려면 어떻게 하는가?
   순회 중에 `remove(i)` 를 부르는 방식은 왜 최악에 O(n^2) 이 되는가 — 그 최악을 만드는 입력을 하나 지어보라.
   반대로 그 방식이 빠르게 끝나는 입력은 어떤 모양인가?
2. **k 칸 오른쪽 회전** — 추가 배열 없이 `[1,2,3,4,5], k=2 -> [4,5,1,2,3]` 을 만들려면?
   k 가 size 보다 크거나 음수일 때 무엇을 먼저 해야 하는가. 시간·추가 공간 복잡도는 각각 얼마이고 왜 그런가?
3. **정렬을 유지하며 삽입** — 넣을 자리를 어떻게 찾고, "같은 값이 있으면 그 뒤"라는 조건은 비교를 어떻게 바꾸는가?
   자리 찾기를 O(log n) 으로 줄여도 전체 복잡도가 그대로인 이유는?
4. **조건에 맞는 원소 일괄 제거(`removeAllIf`)** — 100만 건 시간 제한을 통과하는 O(n) 풀이는 무엇인가?
   `remove(i)` 반복이 총 몇 번의 원소 복사를 일으키는지 식으로 세어보라. 마지막에 꼬리를 자르는 일은 왜 O(n) 안에 들어오는가?
5. **정렬된 두 배열 병합** — 이미 정렬되어 있다는 조건을 쓰면 O((n+m) log(n+m)) 이 O(n+m) 으로 줄어드는 이유는?
   결과 배열의 최종 크기를 미리 아는 것이 확장 횟수를 어떻게 바꾸는가? 원본을 건드리지 않으려면 무엇을 지켜야 하는가?

### B. 자료구조의 특성

6. 동적 배열은 **왜 필요한가** — 고정 길이 배열의 어떤 한계를 메우는가?
   그리고 `size` 와 `capacity` 를 분리해서 갖는 것이 그 한계 극복에서 하는 역할은 무엇인가?
7. 어떤 **데이터·접근 패턴에 적합하고, 어떤 경우에 부적합한가**?
   연결 리스트(02번)와 비교했을 때 무엇을 얻고 무엇을 내주는가 — 그 교환의 뿌리는 어떤 한 가지 설계 선택인가?
8. 확장할 때 **왜 2배로 키우는가** — 1씩 키우면 add 를 n 번 할 때 총 복사량이 얼마이고, 2배면 얼마인가(식으로).
   그 차이가 만들어내는 **"상환(amortized) O(1)"** 은 정확히 무슨 뜻인가? "언제나 O(1)" 과 어떻게 다른가?
9. size 가 capacity 의 **1/4 이하**로 떨어질 때 절반으로 줄이는 이유는? 1/2 에서 줄이면 무슨 일이 생기는가(thrashing).
   그리고 축소에 하한(최소 용량)을 두지 않으면 어떤 일이 벌어지는가?
10. `remove(index)` 의 비용이 **지우는 자리에 따라 달라지는 이유**는 무엇인가 — 맨 뒤 O(1) 과 맨 앞/중간 O(n) 의 차이는 어디서 오는가?
    이 사실은 "여러 개를 지워야 할 때" 어떤 전략을 시사하는가?
11. **최악 입력을 직접 만들어보라.** `add(0, x)` 를 n 번 하면 총 복사량은 얼마인가?
    중간 `remove` 를 반복하면? 반대로 총비용이 선형에 머무는 최선의 사용 패턴은 무엇인가?
12. 지운 자리(size 밖)의 **참조를 왜 끊어야 하는가**(GC), 그리고 그 일을 공개 API 로는 왜 관측할 수 없는가 —
    테스트는 그것을 어떻게 검사하며, 그래서 무엇이 "계약의 일부"가 되었는가?
    같은 맥락에서 `toArray()` 가 내부 배열이 아니라 복사본을 주는 이유는?
13. 복잡도를 셀 때 **루프 횟수가 아니라 루프 안 메서드 한 번의 비용을 곱해야 하는 이유**는?
    `2n` 이 O(n) 인데 `n번 x O(n)` 은 왜 O(n^2) 인가 — 이 문제집에서 그 차이가 실제 시간으로 드러나는 곳은 어디인가?
