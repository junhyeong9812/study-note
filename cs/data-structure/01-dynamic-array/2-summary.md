## 한눈에 — 쉽게 말하면

**동적 배열 = 자리가 차면 두 배 큰 교실로 이사하는 반.**

- 학생(데이터)은 번호 순서대로 붙어 앉는다. "3번 학생 나와" 하면 바로 찾는다 — 자리가 붙어 있고 번호만 알면 되니까.
- 교실(내부 배열)의 크기는 처음부터 정해져 있다. 배열은 원래 한 번 만들면 크기를 못 바꾼다.
- 그래서 자리가 다 차면? 두 배 큰 교실을 새로 빌려서 **전원이 이사**한다. 이사하는 날만 힘들고, 평소에는 빈자리에 그냥 앉으면 끝.
- 이사를 두 배씩 하니까 이사 횟수가 아주 드물어서, 평균으로 나누면 한 명 추가하는 비용은 거의 공짜(상환 O(1))다.

```text
교실(capacity 4)이 꽉 참          두 배 교실로 전원 이사
+---+---+---+---+                +---+---+---+---+---+---+---+---+
| A | B | C | D |   --이사-->    | A | B | C | D | E |   |   |   |
+---+---+---+---+                +---+---+---+---+---+---+---+---+
                                  새로 온 E 는 빈자리에 앉음
```

이 반이 **똑같은 구조로** 동적 배열이다: 교실 = 내부 배열(`elements`), 학생 수 = `size`, 교실 칸 수 = `capacity`, 이사 = 확장(더 큰 배열로 전체 복사). Java의 `ArrayList`, Python의 `list`가 실제로 이렇게 동작한다.

### 구조

```
DynamicArray
+-----------------------------------------------+
| size = 3            (담긴 원소 수)             |
| elements ---+       (내부 배열)               |
+-------------|---------------------------------+
              v
    idx    0     1     2     3     4     5     6     7
        +-----+-----+-----+-----+-----+-----+-----+-----+
        |  A  |  B  |  C  |     |     |     |     |     |
        +-----+-----+-----+-----+-----+-----+-----+-----+
        |<--- size = 3 --->|<------- 빈 칸 (여유) ------>|
        |<------------ capacity = elements.length = 8 ----------->|

size  = 논리적 크기 (사용자에게 보이는 범위, 이 밖은 "없는 값")
capacity = 물리적 크기 (실제 배열 길이, 미리 잡아둔 여유)
```

### 동작 — 추가

```
[1] add(E) : 맨 뒤 추가 — 빈 칸에 쓰기만 한다. O(1)
    +-----+-----+-----+-----+        +-----+-----+-----+-----+
    |  A  |  B  |  C  |     |   ->   |  A  |  B  |  C  |  D  |
    +-----+-----+-----+-----+        +-----+-----+-----+-----+
                       ^ elements[size] = D; size++

[2] add(E) : 꽉 찼을 때 — 2배 배열을 만들어 전부 복사 후 추가. 이때만 O(n)
    +-----+-----+-----+-----+
    |  A  |  B  |  C  |  D  |  capacity 4, size 4 -> 가득
    +-----+-----+-----+-----+
      |     |     |     |      전체 복사 (n 회)
      v     v     v     v
    +-----+-----+-----+-----+-----+-----+-----+-----+
    |  A  |  B  |  C  |  D  |  E  |     |     |     |  capacity 8
    +-----+-----+-----+-----+-----+-----+-----+-----+
    확장은 가끔(log n 번), 총 복사량 < 2n -> add 1회 상환 O(1)

[3] add(index, E) : 중간 삽입 — index 뒤를 전부 한 칸씩 민다. O(n)
    add(1, X)
    idx    0     1     2     3                0     1     2     3
        +-----+-----+-----+-----+        +-----+-----+-----+-----+
        |  A  |  B  |  C  |     |   ->   |  A  |  X  |  B  |  C  |
        +-----+-----+-----+-----+        +-----+-----+-----+-----+
                 \     \_______________________________^     ^
                  \____________________________________/
                    B, C 를 뒤로 한 칸씩 (뒤에서부터 복사해야 안 덮임)
```

그림 해설 (한 단계씩):

- [1] 빈칸이 남아 있으면 `size` 위치에 쓰고 `size`를 1 올린다. 아무도 안 움직이므로 O(1).
- [2] 꽉 찼을 때만 두 배 배열을 새로 만들어 n개를 전부 복사한다. 이때만 O(n).
  - *상환(amortized, 분할상환) O(1)*: 가끔 드는 큰 이사비를 평소의 싼 추가들에 나눠 평균 낸 것 — "이사비를 매달 적금 든 셈 치기". 두 배씩 늘리면 총 복사량이 2n을 넘지 않아 평균은 O(1).
- [3] 중간에 끼우면 그 뒤 원소를 전부 한 칸씩 밀어야 한다. 미는 개수에 비례해 O(n). 뒤에서부터 밀어야 아직 안 옮긴 값을 덮지 않는다.

### 동작 — 삭제

```
remove(index) : index 뒤를 전부 한 칸씩 당기고, 마지막 칸 참조를 끊는다
    remove(1)
    idx    0     1     2     3                0     1     2     3
        +-----+-----+-----+-----+        +-----+-----+-----+-----+
        |  A  |  B  |  C  |  D  |   ->   |  A  |  C  |  D  |null |
        +-----+-----+-----+-----+        +-----+-----+-----+-----+
                 ^     /     /                              ^
                 당겨서 덮음 (C, D 가 앞으로)          elements[--size] = null
                                                       (안 끊으면 D 의 옛 참조가
                                                        남아 GC 를 막는다)

비용 = 당길 개수 = size - index - 1
    맨 뒤 remove(size-1) : 당길 것 0개  -> O(1)
    맨 앞 remove(0)      : n-1 개 당김 -> O(n)

축소 : size 가 capacity 의 1/4 이하로 떨어지면 절반 크기로 복사해 옮긴다
    (1/2 에서 줄이면 경계에서 add/remove 왕복마다 전체 복사 = thrashing)
```

그림 해설 (한 단계씩):

- 지운 칸을 비워두는 게 아니라, 뒤의 원소들을 앞으로 당겨 구멍을 메운다. 당기는 개수에 비례해서 맨 뒤 삭제는 O(1), 맨 앞 삭제는 O(n).
- 당기고 나면 마지막 칸에 옛 값의 참조가 남는다. `null`로 끊어야 한다.
  - *참조(reference)*: 값이 있는 곳을 가리키는 화살표. 칸에는 객체가 아니라 화살표가 담긴다.
  - *GC(가비지 컬렉터)*: 아무도 가리키지 않는 객체를 치우는 자동 청소부. 화살표를 안 끊으면 "아직 쓰는 중"으로 보여 청소를 못 한다.
- 많이 비면(1/4 이하) 절반 크기 배열로 이사해 메모리를 돌려준다.
  - *스래싱(thrashing)*: 절반(1/2)에서 바로 줄이면, 그 경계에서 add/remove 를 반복할 때마다 늘렸다 줄였다 전체 복사만 왕복하는 낭비. 그래서 1/4까지 기다렸다 줄인다.

## 용어 풀이

- **배열(array)**: 같은 종류의 값을 번호(0, 1, 2, …) 붙은 칸에 나란히 담는 저장 방식. 만들 때 칸 수가 정해지고 나중에 못 늘린다.
- **동적 배열(dynamic array)**: 겉보기엔 크기가 늘어나는 배열. 속으로는 고정 배열을 쓰다가 꽉 차면 더 큰 배열로 통째로 옮긴다.
- **size / capacity**: size는 실제로 담긴 개수(논리적 크기), capacity는 내부 배열의 칸 수(물리적 크기, 미리 잡아둔 여유). 예: 8칸 교실에 학생 3명이면 size=3, capacity=8.
- **인덱스(index)**: 칸의 번호. 0부터 시작한다.
- **O(1), O(n)** (빅오 표기): 데이터가 n개일 때 일이 얼마나 걸리는지 대략 나타내는 표기. O(1)은 개수와 무관하게 한 번에 끝, O(n)은 개수에 비례해서 오래 걸림. O(log n)은 n을 계속 반으로 쪼개는 횟수만큼(100만 개여도 약 20번).
- **상환 분석(amortized, 분할상환)**: 가끔 한 번 비싼 작업(전체 복사)의 비용을 여러 번의 싼 작업에 나눠서 평균 낸 것. "이사비를 매달 조금씩 적금 든 셈 치기". 두 배 확장 덕에 add 1회는 평균 O(1).
- **시프트(shift)**: 중간에 넣거나 뺄 때 뒤쪽 원소들을 한 칸씩 밀거나 당기는 것. 이게 중간 삽입/삭제가 O(n)인 이유.
- **참조(reference)**: 값 자체가 아니라 값이 있는 곳을 가리키는 화살표. 배열 칸에는 객체 자체가 아니라 이 화살표가 담긴다.
- **GC(가비지 컬렉터)**: 아무도 가리키지 않는 객체를 자동으로 치워 메모리를 되찾는 청소부. 삭제 후 칸을 null로 안 끊으면 화살표가 남아서 청소를 못 한다.
- **null**: "아무것도 가리키지 않음"을 뜻하는 값.
- **스래싱(thrashing)**: 경계 근처에서 늘리기/줄이기가 번갈아 반복돼 전체 복사만 계속 일어나는 낭비. 1/4까지 기다렸다 줄이는 이유.
- **제자리(in-place)**: 새 배열을 만들지 않고 주어진 배열 안에서만 고치는 방식.
- **두 포인터(two pointers)**: 읽는 위치(read)와 쓰는 위치(write) 두 개의 번호를 따로 움직이며 한 번의 순회로 끝내는 기법.
- **이진 탐색(binary search)**: 정렬된 배열에서 가운데를 보고 절반을 버리기를 반복해 위치를 찾는 방법. O(log n).
- **predicate(조건 함수)**: 원소 하나를 받아 참/거짓을 돌려주는 함수. "이거 지울까?"를 판정하는 심사관.
- **불변식(invariant)**: 어떤 조작을 해도 항상 지켜져야 하는 약속. 여기서는 "0 ≤ size ≤ capacity, size 밖의 칸은 사용자에게 없는 값" 같은 것.
- **연속 저장 / 캐시 지역성(cache locality)**: 원소들이 메모리에 붙어 있으면 CPU가 근처 데이터를 한꺼번에 미리 가져와서(캐시) 순회가 빨라진다. 배열이 연결 리스트보다 실측이 빠른 큰 이유.
