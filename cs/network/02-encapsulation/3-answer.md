## 정답

### 1. payload를 해석하지 않는 이점

- 층끼리 서로의 형식을 몰라도 된다. 그래서 한 층을 바꿔도 다른 층은 그대로다.
- 라우터는 IP 헤더(목적지 주소, TTL)로 다음 홉을 고른다. TCP 헤더나 HTTP 본문은 고치지 않는다.
  - 예외: ECMP 해시(리눅스 `fib_multipath_hash_policy=1`)나 ACL은 포트까지 읽는다. 읽을 뿐 바꾸지는 않는다.
  - 그래서 라우터는 새 응용 프로토콜이 나와도 바꿀 필요가 없다.
  - TLS로 암호화된 내용도 그대로 전달할 수 있다.

### 2. 헤더가 붙는 순서

```text
[이더넷 14][IPv4 20][TCP 20][ HTTP 메시지 ][FCS 4]
```

- 송신은 위에서 아래로 붙는다. TCP → IP → 이더넷 순이다.
- **이더넷만 뒤에도 붙인다.** 프레임 끝에 FCS 4바이트가 온다.
- 크기 근거: 이더넷 = MAC 6 + 6 + EtherType 2. IPv4 최소 20(RFC 791 IHL 최소 5). TCP 최소 20(RFC 9293 Data Offset).

### 3. 역다중화 필드

- 링크(이더넷): **EtherType**. 0x0800이면 IPv4, 0x86DD면 IPv6, 0x0806이면 ARP(RFC 7042).
- 인터넷: IPv4 **Protocol** / IPv6 **Next Header**. 6이면 TCP, 17이면 UDP.
- 전송: **목적지 포트**. 그 포트에 묶인 소켓을 찾는다.

### 4. MSS 계산

- IPv4: 1500 − IP 20 − TCP 20 = **1460바이트**.
- IPv6: 1500 − IP 40 − TCP 20 = **1440바이트**.
- 옵션이 붙으면 그만큼 더 줄어든다. 예: TCP 타임스탬프 옵션은 길이 10바이트다(RFC 7323 §3.2). 헤더가 32비트 배수여야 하니 실제로는 채움까지 더 든다.

### 5. 홉마다 바뀌는 것

| 필드 | 바뀌나 | 이유 |
|---|---|---|
| 이더넷 목적지 MAC | 바뀐다 | 라우터가 이더넷 헤더를 버리고 다음 홉 MAC으로 새로 붙인다 |
| IP 목적지 주소 | 그대로 | 끝까지 가는 주소다(NAT 장비를 지나면 예외) |
| TTL | 홉마다 1 감소 | 루프 도는 패킷을 없애기 위해 |
| TCP 포트 | 그대로 | 라우터는 전송 계층을 바꾸지 않는다(NAT 예외. ECMP 해시·ACL은 읽기만 한다) |

- IPv4 헤더 체크섬은 **헤더만** 덮는다. TTL이 바뀌면 헤더가 바뀌니 체크섬도 다시 계산해야 한다(RFC 791).
- IPv6에는 헤더 체크섬이 없다.

### 6. 고정 길이 파서의 함정

- IP 옵션이 있는 패킷, TCP 옵션이 있는 세그먼트에서 틀린다.
  - 특히 SYN에는 MSS·Window Scale·SACK 허용 같은 옵션이 흔히 붙는다.
  - TCP 헤더 시작점이 밀리니 포트·페이로드를 엉뚱한 자리에서 읽는다.
- 고치는 법
  - IPv4의 IHL(하위 4비트 × 4)로 IP 헤더 길이를 구한다.
  - TCP의 Data Offset(상위 4비트 × 4)으로 TCP 헤더 길이를 구한다.
  - 여러 바이트 필드는 빅 엔디언(네트워크 바이트 순서)으로 읽는다.

### 7. VXLAN 안쪽 MTU

- 안쪽 IP 패킷 최대 = 1500 − 50 = **1450바이트**.
- 50바이트 = 외부 IPv4 20 + UDP 8 + VXLAN 8 + 내부 이더넷 14.
  - 외부 이더넷 헤더 14는 MTU 계산에 들어가지 않는다. MTU는 링크 헤더를 뺀 payload 크기이기 때문이다.
  - 내부 이더넷 헤더는 외부 IP 입장에서 payload라 계산에 들어간다.
- VTEP은 VXLAN 패킷을 단편화하면 안 된다(RFC 7348 MUST NOT). 그래서 안쪽을 줄이거나 물리 MTU를 키운다.

### 8. VPN 뒤 큰 전송만 멈춤

- **추정 원인**: VPN 헤더만큼 패킷이 커져 경로 MTU를 넘었다. DF가 켜져 라우터가 버렸고, 크기를 줄이라는 ICMP가 방화벽에 막혀 송신자가 모른다(RFC 2923 "black hole").
  - 작은 패킷(로그인, 헬스체크)은 MTU 안에 들어가니 된다.
- **확인**
  - `ping -M do -s <크기> 대상`으로 크기를 바꿔 가며 통과하는 최대 크기를 찾는다.
  - `tcpdump`로 큰 세그먼트만 재전송되고 ACK가 없는지 본다.
  - `ip link`로 터널 인터페이스의 MTU를 본다.
- **대처**
  - 터널 인터페이스 MTU를 오버헤드만큼 낮춘다.
  - 경계에서 TCP MSS clamping(`TCPMSS --clamp-mss-to-pmtu`)을 건다.
  - ICMP "Fragmentation Needed"/"Packet Too Big"을 막지 않는다.
