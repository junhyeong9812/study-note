# network/34-http-caching — 질문

## 질문

1. (그림) 첫 요청에서 `ETag`를 받고, 두 번째 요청에서 304를 받는 흐름을 그려라. 304 응답에 반드시 들어가는 헤더와 들어가지 않는 것은 무엇인가?
2. (경계) `no-cache`, `no-store`, `private`의 차이를 한 줄씩 말하라. "브라우저 디스크에 남으면 안 되는 응답"에는 무엇을 써야 하나?
3. (예측) `Cache-Control`도 `Expires`도 없고 `Last-Modified`만 100일 전으로 찍힌 200 응답은 캐시되나? 된다면 얼마나 오래 쓰일 수 있나?
4. (왜) 공유 캐시의 신선도 수명은 어떤 순서로 정해지나? 수명 계산에 원 서버의 `Date`를 쓰는 이유는 무엇인가?
5. (장애 진단) 사용자 A가 마이페이지에서 사용자 B의 정보를 봤다. 응답 헤더에서 무엇을 확인하고, 원인과 근본 대처는 무엇인가?
6. (경계) `Authorization` 헤더가 붙은 요청의 응답과, 쿠키로 인증한 요청의 응답은 공유 캐시에서 기본 처리가 어떻게 다른가?
7. (적용) HTML, 파일명에 해시가 든 JS, 로그인 사용자 전용 API에 각각 어떤 `Cache-Control`을 주겠나? 이유는?
8. (왜) `Vary: Accept-Encoding`이 없으면 어떤 사고가 나나? 반대로 `Vary: User-Agent`를 넣으면 무엇이 나빠지나?
9. (연결) `POST /orders/42/cancel`이 200으로 끝났다. 어떤 캐시의 어떤 저장본이 무효화되고, 무엇은 무효화되지 않나?
10. (장애 진단) 조건부 요청을 보내는데도 304가 거의 안 나오고 매번 200과 전체 본문이 온다. 로드밸런서 뒤 서버가 여러 대다. 무엇을 의심하나?
