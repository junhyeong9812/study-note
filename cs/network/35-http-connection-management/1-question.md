# network/35-http-connection-management — 질문

## 질문

1. (왜) HTTPS 요청을 매번 새 연결로 보낼 때와 재사용할 때, 요청을 보내기까지 드는 왕복 수를 비교하라(TLS 1.3 기준). 재사용이 아끼는 것이 왕복 말고 또 무엇이 있나?
2. (경계) HTTP/1.1에서 연결이 유지될지 닫힐지는 무엇으로 정해지나? 응답 본문을 끝까지 읽지 않으면 왜 연결을 재사용할 수 없나?
3. (그림) 서버 keep-alive timeout 5초, 클라이언트 풀 idle 60초일 때 간헐 `ECONNRESET`이 생기는 과정을 시간축으로 그려라.
4. (적용) 브라우저 → AWS ALB → Node 서버 → 외부 API 경로에서 구간별로 어느 쪽 timeout이 더 길어야 하나? 기본값 그대로면 어느 구간이 역전되나?
5. (장애 진단) Apache HttpClient를 쓰는 서비스에서 `Timeout waiting for connection from pool`이 쏟아진다. 상류는 정상이다. 원인 후보 세 가지와 확인 방법을 말하라.
6. (예측) nginx 1.29.7 이전 버전에서 `upstream`에 `keepalive`만 넣고 `proxy_http_version`을 건드리지 않았다. 상류 연결이 재사용되나? 부하가 늘면 어떤 증상이 나나?
7. (경계) HTTP의 keep-alive와 TCP keepalive는 각각 무엇인가? 21번 주제와 어떻게 구분되나?
8. (왜) 풀에서 idle 연결을 꺼낼 때 LIFO와 FIFO는 어떤 차이를 만드나? Node `http.Agent`는 어느 쪽이 기본인가?
9. (장애 진단) 인스턴스를 늘렸는데 새 인스턴스에 트래픽이 거의 안 간다. 연결 관리 관점의 원인과 대처는 무엇인가?
10. (연결) 재사용 연결에서 `ECONNRESET`이 나면 자동 재시도해도 되나? 어떤 조건에서만 되는지 33번의 멱등 규칙과 묶어 답하라.
