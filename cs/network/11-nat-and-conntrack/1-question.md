## 질문

1. (왜) 사설 주소 호스트가 인터넷 서버에 요청을 보낼 때, NAT가 "주소를 바꾸는 것"만으로는 부족하고 무엇을 **기억**해야 하는가? 기억하지 못하면 무엇이 안 되나?
2. (구분) SNAT와 DNAT는 각각 패킷의 어느 필드를 바꾸나? 실무에서 각각 어디에 쓰이는지 하나씩 들어라.
3. (그림) conntrack 항목 하나에 튜플이 두 개 들어 있는 이유는 무엇인가? 응답 패킷이 왔을 때 어떤 튜플로 항목을 찾고 무엇을 되돌리나?
4. (예측) 공인 IP 하나를 쓰는 NAT 뒤에서 한 외부 API로 동시 연결을 계속 늘리면 어디서 막히나? 목적지별로 포트를 재사용하는 NAT라면 다른 목적지로 가는 연결은 왜 영향을 덜 받나?
5. (경계) RFC 5382는 TCP established 매핑의 idle timeout을 2시간 4분 이상으로 요구한다. 그런데 AWS NAT 게이트웨이 뒤의 연결은 6분도 못 버틴다. 왜 "RFC대로면 괜찮다"는 가정이 틀리나?
6. (장애 진단) 새벽 한가한 시간 뒤 첫 API 요청만 `Connection reset`으로 실패하고 재시도는 성공한다. 원인 가설과 확인 방법, 대처 두 가지를 말하라.
7. (장애 진단) 트래픽 피크 때 일부 **새** 연결만 타임아웃이 나고 이미 열린 연결은 멀쩡하다. 커널 로그에 무엇이 보일 것이며, 어떤 값을 확인·조정하나?
8. (연결) conntrack 표는 어떤 자료구조인가? `nf_conntrack_max`만 크게 올리고 버킷 수를 그대로 두면 무엇이 나빠지나?
9. (장애 진단) SYN은 나갔는데 응답이 상태 방화벽에서 INVALID로 버려진다. 라우팅 관점의 원인은 무엇인가?
10. (연결) NAT 매핑이 조용히 지워진 연결에서 클라이언트가 보내기만 기다리고 있으면 무슨 일이 생기나? 19번 노트의 어떤 개념과 같은가?
