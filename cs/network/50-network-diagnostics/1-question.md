# network/50-network-diagnostics — 질문

## 질문

1. (표) `dig`, `getent`, `ip route get`, `mtr`, `tcpdump`, `ss`, `openssl s_client`, `curl -v`가 각각 **어떤 질문**에 답하고 **어디서** 보는지 표로 적어라.
2. (왜) "도구 없이 추측 진단"을 하면 무엇을 잃나? 재시작이 특히 위험한 이유를 CLOSE-WAIT 누적 예로 설명하라.
3. (경계) `dig`은 되는데 앱은 이름을 못 푼다. 두 도구가 보는 경로는 어떻게 다르고, 앱과 같은 경로를 보려면 무엇을 쓰나?
4. (예측) `mtr` 결과에서 5번 홉만 40% 손실이고 6번 이후와 목적지는 0%다. 경로에 손실이 있나? 진짜 손실은 어떤 모양인가?
5. (정의) BPF 필터는 어디서 실행되나? `tcpdump -d 'tcp dst port 443'`이 보여 주는 것은 무엇이고, 필터를 좁게 쓰면 무엇이 좋아지나?
6. (경계) `tcp[tcpflags] & tcp-rst != 0` 필터로 RST를 찾았더니 한 건도 없었다. 이 결론을 믿으면 안 되는 경우는? 캡처 인터페이스 관련 함정도 하나 더 말하라.
7. (예측) `openssl s_client -connect 10.0.0.5:443`이 `Verify return code: 0 (ok)`를 냈다. 이것만으로 "앱의 인증서 오류는 서버 문제가 아니다"라고 할 수 없는 이유 두 가지와, 앱과 같은 조건으로 재현하는 명령을 적어라.
8. (적용) `curl -v` 출력에서 DNS·TCP·TLS·HTTP 구간은 각각 어느 줄로 알 수 있나? `--resolve`와 `--connect-to`는 무엇을 건너뛰고 무엇을 유지하나?
9. (장애 진단) 서버 tcpdump에 SYN은 들어오는데 연결이 안 된다. 다음으로 볼 것은 무엇이고, 왜 "tcpdump에 보였다 = 방화벽 통과"가 아닌가?
10. (장애 진단) `ss -o`에서 타이머 `persist`가 보이는 연결과, `ss -s`에서 timewait가 수만 개인 상황은 각각 무엇을 뜻하나? 다음에 무엇을 보나?
