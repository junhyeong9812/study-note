# network/39-http-content-encoding — 질문

## 질문

1. (그림) 클라이언트가 `Accept-Encoding: br, gzip;q=0.8`을 보내고 서버가 br로 답하는 요청·응답을 그려라. 응답에 반드시(또는 거의 반드시) 붙어야 할 헤더 세 가지를 표시하라.
2. (예측) `Accept-Encoding: gzip;q=0, *`를 받은 서버가 gzip·br 둘 다 가지고 있다. 무엇을 보낼 수 있나? `Accept-Encoding:`(빈 값)이면?
3. (왜) 압축해도 `Content-Type`은 왜 `application/json` 그대로인가? Content-Encoding과 Transfer-Encoding은 무엇이 다른가?
4. (장애 진단) CDN 뒤의 `/app.js`를 일부 내부 스크립트만 파싱하지 못한다. 받은 본문 첫 두 바이트가 `1f 8b`다. 무엇이 빠졌고 어떤 순서로 고치나?
5. (왜) RFC 9110은 왜 압축된 표현의 강한 ETag가 원본과 달라야 한다고 하나? 같으면 어떤 요청에서 문제가 되나?
6. (장애 진단) 원 서버는 `ETag: "abc"`를 주는데 프록시 뒤에서는 `ETag: W/"abc"`로 보인다. 304 재검증은 되는데 이어받기가 늘 처음부터다. 왜인가?
7. (경계) 이미 압축된 JPEG·ZIP이나 수십 바이트짜리 응답을 gzip하면 어떻게 되나? 근거가 되는 gzip 형식의 구조는?
8. (적용) 동적 API 응답과 빌드 산출물 정적 파일의 압축 전략(수준·시점)을 각각 정하라. 이유는?
9. (연결) gzip·zstd가 공통으로 쓰는 알고리즘 두 가지를 말하고, zstd를 HTTP에서 쓸 때 추가로 지켜야 하는 제약은?
10. (연결) SSE 스트림에 압축을 켰더니 이벤트가 뭉쳐서 온다. 왜 그런가? 켠 채로 고치려면?
