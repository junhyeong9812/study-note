# network/47-cdn-and-edge — 질문

## 질문

1. (그림) 브라우저 → 엣지 → 상위 계층(shield) → 원점의 캐시 계층을 그리고, 상위 계층이 원점 부하를 줄이는 이유를 설명하라.
2. (경계) 캐시 키의 최소 구성은 무엇이고, `Vary`는 키를 어떻게 바꾸나? 키에 너무 적게·너무 많이 넣었을 때 각각 어떤 사고가 나나?
3. (예측) 원점이 `Cache-Control: public, max-age=60, s-maxage=600`을 보냈다. 브라우저와 CDN은 각각 몇 초 동안 재사용하나?
4. (왜) "`Set-Cookie`가 있으니 CDN이 캐시하지 않겠지"라는 가정이 위험한 이유를 RFC와 CDN 기본값을 함께 들어 설명하라.
5. (적용) 정적 자원·HTML·공개 API·개인화 API에 각각 어떤 캐시 정책을 주나? 배포 때 무효화는 어떤 순서로 하나?
6. (연결) 같은 객체에 대한 동시 미스 1000건을 원점 요청 1건으로 줄이는 기법의 이름과, 그것이 기대는 자료구조는?
7. (장애 진단) 로그인한 사용자에게 다른 사람의 이름이 보인다는 신고가 왔다. 어떤 헤더·명령으로 확인하고, 즉시 조치와 근본 조치는?
8. (장애 진단) 전체 퍼지 직후 원점이 5xx를 쏟아냈다. 원인과 재발 방지책 세 가지는?
9. (경계) 웹 캐시 속임(web cache deception)은 캐시와 원점의 어떤 해석 차이를 이용하나? 막는 방법은?
