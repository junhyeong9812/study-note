# network/26-packet-journey — 질문

## 질문

1. (그림) 사설망 호스트의 프로세스가 인터넷의 서버 프로세스에 바이트를 보낼 때 거치는 구간을 순서대로 적어라. 구간마다 "관련 노트 번호"도 붙여 보라.
2. (예측) 호스트 A(10.0.1.10/24)가 203.0.113.50으로 보낼 때, ARP로 누구의 MAC을 찾나? A가 내보내는 이더넷 프레임의 목적지 MAC과 IP 헤더의 목적지 IP는 각각 무엇인가?
3. (표) 패킷이 A → 스위치 → R1(NAT) → R2 → 서버로 갈 때, src/dst MAC, src/dst IP, TTL, TCP 포트 중 무엇이 어느 장비에서 바뀌나?
4. (경계) 스위치와 라우터는 프레임을 각각 어디까지 보고 무엇을 바꾸나? NAT·방화벽은 왜 TCP 포트까지 보나?
5. (정의) 라우터가 TTL을 다루는 규칙을 RFC 1812의 규범 수준(MUST/MAY)과 함께 말하라. `traceroute`는 이를 어떻게 이용하나?
6. (연결) 패킷 한 개가 여행 중 조회하는 표를 위치별로 적고, 각 표의 자료구조를 말하라.
7. (장애 진단) `curl`이 `ETIMEDOUT`으로 실패한다. 구간을 좁히기 위해 어떤 명령을 어떤 순서로 쓰나?
8. (장애 진단) TCP 연결과 작은 요청은 되는데 큰 응답에서만 멈춘다. 어느 구간·어떤 원인을 의심하나?
9. (장애 진단) 서버 tcpdump에는 SYN이 오고 SYN-ACK도 나가는데 클라이언트는 연결이 안 된다. 원인 후보 두 가지는?
10. (연결) 커넥션 풀의 오래 쉰 연결로 보낸 첫 요청이 실패하고 재시도하면 성공한다. 이 여행 경로의 어느 표가 원인이고, 어떻게 막나?
