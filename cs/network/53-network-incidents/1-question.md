## 질문

1. (사슬) Facebook 2021-10-04 장애를 "백본 명령"에서 "사용자의 DNS 실패"까지 단계별 사슬로 복원하라. 각 단계에 해당하는 leaf 노트 번호를 붙여라.
2. (왜) Facebook의 DNS 서버들은 멀쩡히 동작 중이었는데 왜 인터넷에서 찾을 수 없었나? "서버가 죽었다"와 무엇이 다른가? 밖에서 이 차이를 어떤 명령·관측으로 가를 수 있나?
3. (경계) "데이터센터와 통신할 수 없으면 BGP 광고를 거둔다"는 로직은 한 시설에는 옳은 판단이다. 왜 전체 장애로 번졌고, 어떤 안전장치가 필요했나?
4. (연결) Facebook 복구가 느렸던 이유 둘과, 복구 직전에 조심해야 했던 점 하나를 Meta 글 기준으로 말하라. 여기서 내 시스템의 장애 대응 도구에 대해 무엇을 점검해야 하나?
5. (예측) 2021-10-01에 OpenSSL 1.0.2 기반 클라이언트가 Let's Encrypt 인증서 서버에 접속한다. 이 클라이언트 트러스트 스토어에는 ISRG Root X1과 DST Root CA X3가 모두 있다. 결과는 무엇이고 왜 그런가? 같은 서버에 OpenSSL 1.1.1 클라이언트는?
6. (예외) DST Root CA X3가 만료된 뒤에도 Android 7.1.1 미만 기기가 Let's Encrypt 인증서를 대체로 신뢰할 수 있었던 이유는 무엇인가? 그 방법의 수명은 언제까지였나?
7. (대처) OpenSSL 블로그가 제시한 대처 셋을 클라이언트 쪽과 서버 쪽으로 나눠 적고, 서버 쪽 대처의 대가를 말하라.
8. (메커니즘) 2008-02-24 Pakistan Telecom이 208.65.153.0/24를 광고했을 때 YouTube(208.65.152.0/22)로 가던 트래픽이 왜 파키스탄으로 갔나? YouTube가 /24를 먼저, /25를 나중에 광고한 이유는 각각 무엇인가?
9. (방어) YouTube 사건은 어디서 막을 수 있었나? 오늘날 대역 소유자가 평소에 해 둘 일 둘과 사고 때 할 일 둘을 말하라.
10. (공통점) 세 사건에서 "증상이 보인 곳"과 "원인이 있던 곳"을 각각 짝지어 말하고, 52번 색인에서 각 증상이 가리키는 leaf와 실제 원인 leaf가 어떻게 다른지 설명하라.
