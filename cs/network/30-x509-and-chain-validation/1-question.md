## 질문

1. (왜) TLS 1.3의 CertificateVerify가 이미 "상대가 개인키를 갖고 있다"를 증명하는데, 왜 인증서 체인 검증이 따로 필요한가?
2. (그림) 인증서 한 장의 구조를 tbsCertificate·서명 알고리즘·서명값으로 나눠 그리고, 체인 검증과 호스트명 검증에 쓰이는 확장을 각각 두 개 이상 표시하라.
3. (그림) 서버가 보내는 체인과 클라이언트 루트 스토어의 관계를 그려라. 서버는 어떤 인증서를 어떤 순서로 보내고, 무엇은 생략해도 되나?
4. (경계) RFC 5280 §6.1 경로 검증이 인증서마다 확인하는 네 가지와, CA 단계에서만 확인하는 세 가지는?
5. (장애 진단) 인증서 갱신 뒤 브라우저는 정상인데 Java 배치만 `PKIX path building failed`로 실패한다. 가장 유력한 원인, 브라우저가 멀쩡한 이유, 확인 명령과 해결책은?
6. (예측) 인증서 SAN이 `*.example.com` 하나다. `api.example.com`, `a.b.example.com`, `example.com` 각각의 호스트명 검증 결과는? CN에 `example.com`이 있으면 결과가 바뀌나?
7. (연결) 경로 **구축**이 규격 밖이라는 말은 무슨 뜻인가? 교차 서명된 루트가 만료됐을 때 어떤 구현은 실패하고 어떤 구현은 성공하는 이유를 그래프 탐색으로 설명하라.
8. (적용) Node에서 사내 API를 부르려고 `ca: [corpRoot]`를 줬더니 외부 API 호출이 실패하기 시작했다. 왜 그런가? Java에서 같은 실수는 무엇이고, 각각 어떻게 고치나?
9. (장애 진단) 새로 띄운 장비에서만 `certificate is not yet valid`가 난다. 무엇을 확인하나? 반대 방향으로 틀어지면 어떤 증상이 나오나?
10. (경계) Java에서 raw `SSLSocket`으로 연결하면 호스트명이 검증되나? `HttpsURLConnection`과 무엇이 다르고, raw 소켓에서는 무엇을 켜야 하나?
