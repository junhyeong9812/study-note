# network/09-icmp-ping-traceroute — 질문

## 질문

1. (왜) IP만으로는 왜 실패 이유를 알 수 없나? ICMP 오류 메시지는 무엇을 담고 돌아오며, 그 내용으로 커널은 무엇을 하나?
2. (암기) ping, traceroute 중간 홉, traceroute 종착(UDP 방식), PMTUD가 각각 쓰는 ICMP type/code는?
3. (경계) 라우터·호스트가 ICMP 오류를 보내서는 안 되는 경우를 세 가지 이상 들고, 그 규칙이 없으면 무슨 일이 생기는지 말하라.
4. (그림) traceroute가 3홉 떨어진 목적지까지 경로를 알아내는 과정을 TTL별로 그려라. 목적지에 도착했음은 어떻게 아나?
5. (예측) 연결된 TCP 소켓에 ICMP host unreachable(3/1)이 한 번 왔다. 연결은 즉시 끊기나? RFC 9293은 어떻게 정하나?
6. (경계) "ping 된다 ≠ 서비스 된다"와 "ping 안 된다 ≠ 서비스 안 된다"를 각각 이유와 함께 설명하라.
7. (장애 진단) traceroute에서 5번째 홉만 손실 40%, RTT 150ms이고 6번째 홉과 목적지는 정상이다. 5번째 홉 라우터에 장애가 있나?
8. (장애 진단) 보안 강화로 ICMP를 전부 막은 뒤, 작은 API는 되는데 큰 응답과 TLS 핸드셰이크가 멈춘다. 왜이고, 최소한 무엇을 다시 열어야 하나?
9. (적용) 헬스 체크에 Java `InetAddress.isReachable()`을 쓰면 무엇이 문제인가? 대신 무엇을 쓰나?
