# network/37-http3-quic — 질문

## 질문

1. (왜) HTTP/2 위에서 남은 문제 세 가지를 들고, QUIC이 각각을 어떻게 푸는지 말하라. 왜 TCP를 고치지 않고 UDP 위에 새로 만들었나?
2. (그림) 같은 패킷 하나가 손실됐을 때 HTTP/2(TCP)와 HTTP/3(QUIC)에서 무관한 스트림이 각각 어떻게 되는지 그려라.
3. (적용) 새 연결에서 첫 요청을 보내기까지의 왕복 수를 TCP + TLS 1.3과 QUIC에 대해 비교하라. 재개 연결이면 어떻게 달라지나?
4. (경계) 클라이언트가 브라우저에서 처음 방문한 사이트에 HTTP/3로 바로 접속할 수 있나? 서버는 HTTP/3 지원을 어떤 방법으로 알리나?
5. (예측) 휴대폰이 Wi-Fi에서 LTE로 바뀌었다. TCP 연결과 QUIC 연결은 각각 어떻게 되나? QUIC 서버는 새 주소를 받아들이기 전에 무엇을 하나?
6. (왜) QUIC은 재전송 패킷에 새 패킷 번호를 쓴다. TCP의 어떤 문제를 피하려는 것인가? 패킷 번호 공간은 왜 셋으로 나뉘나?
7. (장애 진단) 특정 회사망 사용자만 첫 로딩이 수 초 느리고, 브라우저 Protocol 열이 `h2`로 나온다. 무엇을 의심하고 어떤 명령으로 확인하나?
8. (장애 진단) 앱을 한동안 두었다가 쓰면 첫 요청이 멈췄다가 재연결된다. `tcpdump`에서 클라이언트 패킷만 반복되고 응답이 없다. 방화벽·NAT·로드밸런서 관점에서 원인과 대처를 말하라.
9. (경계) HTTP/3에서 0-RTT를 켜면 무엇을 반드시 해야 하나? QUIC 프레임 처리와 앱 요청의 재전송 위험은 어떻게 다른가?
10. (연결) QUIC 서버는 주소 검증 전 받은 바이트의 몇 배까지만 보낼 수 있고, 클라이언트 Initial은 왜 1,200바이트 이상이어야 하나? 작은 MTU 경로에서는 무엇이 일어나나?
