## 질문

1. (그림) HTTP/2 프레임 헤더의 필드와 크기를 그려라. 스트림 ID 0은 어떤 프레임에 쓰이나?
2. (왜) HTTP/2는 HTTP/1.1의 어떤 문제를 풀었고, 어떤 head-of-line blocking은 여전히 남았나? 남은 것이 생기는 과정을 TCP 세그먼트 수준에서 설명하라.
3. (경계) 클라이언트가 여는 스트림 ID는 홀수인가 짝수인가? 스트림 ID를 다 쓰면 어떻게 되나?
4. (예측) 서버가 `SETTINGS_MAX_CONCURRENT_STREAMS = 100`을 보냈고 클라이언트는 연결 하나로 동시에 300개 요청을 보내려 한다. 무슨 일이 일어나고, 어떻게 풀어야 하나?
5. (적용) RTT 100ms 구간에서 흐름 제어 창이 초기값 그대로다. 한 스트림의 최대 처리량을 어림하고, 무엇을 바꿔야 하는지 말하라. 흐름 제어가 적용되는 프레임은 무엇인가?
6. (왜) HPACK은 왜 gzip 같은 범용 압축을 쓰지 않았나? 정적 테이블과 동적 테이블은 각각 무엇을 담나?
7. (장애 진단) 서버가 GOAWAY(last-stream-id = 7)를 보냈다. 클라이언트에서 진행 중이던 스트림 5(GET)와 9(POST)는 각각 어떻게 처리해야 하나? 근거는?
8. (적용) 서버를 우아하게 종료하려면 GOAWAY를 어떤 순서로 보내야 하나? 한 번만 보내면 무엇이 문제인가?
9. (연결) L4 로드밸런서 뒤에 gRPC 서버 여러 대를 두었더니 한 대만 뜨겁다. 35번의 연결 관리와 묶어 원인과 대처를 말하라.
10. (장애 진단) 동시 스트림 수는 낮게 유지되는데 서버 CPU가 치솟는다. 프레임 로그에는 HEADERS 직후 RST_STREAM이 반복된다. 무엇이며 어떻게 막나?
