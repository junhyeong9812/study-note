## 정답

### 1. 층으로 나누는 이득과 비용

- 얻는 것
  - **교체 가능성**: 각 층은 바로 아래층의 서비스만 믿는다. 그래서 Wi-Fi를 이더넷으로 바꿔도 HTTP 코드는 그대로다.
  - **분리 진단**: "어느 층까지 정상인가"로 장애를 좁힐 수 있다.
- 잃는 것
  - **헤더 오버헤드**: 층마다 헤더가 붙는다(02번).
  - **정보 단절**: 위층은 아래층 사정(MTU, 지연)을 모른다. 그래서 MTU 초과처럼 층 사이 틈에서 생기는 장애가 있다.
  - **기능 중복**: 오류 검사가 링크 CRC, IP 헤더 체크섬, TCP 체크섬으로 겹친다.

### 2. 두 모델의 대응

```text
  OSI              RFC 1122
  7 응용        --+
  6 표현        --+-->  응용
  5 세션        --+
  4 전송        ----->  전송
  3 네트워크    ----->  인터넷
  2 데이터 링크 --+
  1 물리        --+-->  링크
```

- RFC 1122 §1.1.3은 응용·전송·인터넷·링크 4계층이다. K&R은 물리를 떼어 5계층으로 가르친다.
- L4·L7은 **OSI 번호**다. L4 로드밸런서는 TCP/UDP 포트까지, L7 로드밸런서는 HTTP 같은 응용 메시지까지 본다.

### 3. 각 층이 옮기는 범위와 주소

| 층 | 어디까지 | 주소 |
|---|---|---|
| 전송 | 프로세스 대 프로세스 | 포트 번호 |
| 인터넷 | 호스트 대 호스트(여러 망을 건너) | IP 주소 |
| 링크 | 같은 링크의 바로 옆 장비 | MAC 주소 |

- 여러 홉을 건너는 것은 인터넷 계층(IP)의 일이다. 링크 계층은 홉 하나만 책임진다.

### 4. PDU 이름

RFC 1122 §1.3.3의 정의를 따른다.

- **segment**: TCP의 단위. TCP 헤더 + 응용 데이터.
- **datagram**: IP의 단위. IP 헤더 + 전송 계층 데이터. (UDP의 단위도 흔히 데이터그램이라 부른다.)
- **packet**: 인터넷 계층과 링크 계층 사이 인터페이스로 넘어가는 단위.
- **frame**: 링크 계층의 단위. 링크 헤더 + packet.

### 5. 스위치 vs 라우터

- 스위치는 **링크 계층**까지 본다. 목적지 MAC 주소로 포트를 고른다.
- 라우터는 **인터넷 계층**까지 본다. 목적지 IP로 다음 홉을 고른다.
- 그래서 스위치 장애는 같은 망(같은 링크) 안의 통신을 깬다. 라우터 장애는 망과 망 사이의 통신을 깬다. 같은 서브넷 안 통신은 라우터 없이도 된다.
- 단, L4/L7 로드밸런서·NAT·방화벽은 라우터 자리에 있으면서 더 위층까지 들여다본다.

### 6. refused와 timeout이 알려 주는 것

- **refused**: 상대 호스트까지 패킷이 갔다가 답(RST)이 돌아왔다.
  - 그러니 인터넷 계층(경로)은 정상이다.
  - 전송 계층에서, 그 포트에 듣는 프로세스가 없다(connect(2) "no one listening").
  - 단, 중간 방화벽의 REJECT도 refused를 만든다. RST를 대신 보내거나, ICMP port unreachable(iptables `REJECT` 기본값)을 보낸다. 리눅스는 이 ICMP를 `ECONNREFUSED`로 바꾼다(`icmp_err_convert[]`). 그러면 상대 호스트까지 갔다고 단정할 수 없다. tcpdump로 응답의 출발 IP와 종류(RST/ICMP)를 본다.
- **timeout**: SYN에 아무 답이 없었다는 사실만 말한다.
  - 방화벽 DROP, 경로 문제, 상대 과부하 중 무엇인지 알 수 없다.
  - 그래서 다른 층부터 확인해 좁힌다.

### 7. `UnknownHostException`

- **응용 계층(DNS)** 문제다. 이름을 IP로 바꾸지 못했다. IP 경로나 TCP까지는 가지도 않았다.
- 확인
  - `dig 이름`으로 직접 질의한다. `dig @서버 이름`으로 DNS 서버별 응답을 비교한다.
  - 컨테이너라면 `/etc/resolv.conf`의 nameserver·search 설정을 본다.
  - IP로 직접 연결해 되는지 보면 DNS만의 문제인지 확정된다.

### 8. 역다중화 필드

| 층 | 필드 | 예 |
|---|---|---|
| 링크(이더넷) | EtherType | 0x0800 IPv4, 0x0806 ARP, 0x86DD IPv6(RFC 7042) |
| 인터넷(IP) | Protocol(IPv4) / Next Header(IPv6) | 6 TCP, 17 UDP(IANA) |
| 전송(TCP/UDP) | 목적지 포트 | 443이면 그 포트에 바인드한 프로세스 |

- 구현은 "키 → 처리기" 조회다. 배열 인덱스나 해시 테이블로 한다.
