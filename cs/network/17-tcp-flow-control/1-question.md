# network/17-tcp-flow-control — 질문

## 질문

1. (왜) 흐름 제어가 없으면 무엇이 낭비되나? 흐름 제어와 혼잡 제어는 각각 누구를 보호하나?
2. (그림) 수신 버퍼를 "앱이 안 읽은 데이터 / 광고한 윈도 / 미광고 공간"으로 나눠 그리고, 앱이 `read()`를 멈추면 광고 윈도가 어떻게 변하는지 말하라.
3. (왜) 수신자가 윈도 0을 광고한 뒤 송신자가 가만히 기다리기만 하면 어떤 교착이 생길 수 있나? TCP는 이를 어떻게 막나?
4. (예측) 수신 앱이 몇 시간 동안 `read()`를 안 했다. 연결은 에러로 끊기나? 송신 앱의 블로킹 `write()`는 어떻게 되나?
5. (계산) 윈도 스케일링 없이 RTT 100ms 경로의 처리량 상한은 대략 얼마인가? 식과 함께 답하라.
6. (경계) Window Scale 옵션은 언제, 어느 세그먼트에 실리며, 켜지려면 어떤 조건이 필요한가? shift 최댓값과 그때의 최대 윈도는?
7. (장애 진단) 대륙 간 파일 전송이 링크 속도와 무관하게 몇 Mbit/s에서 멈춘다. 어떤 것을 캡처·확인하고, 어떤 원인을 의심하나?
8. (예측) 리눅스에서 앱이 `SO_RCVBUF`를 64KB로 고정하면 고BDP 경로에서 무슨 일이 생기나? 설정 시점도 왜 중요하나?
9. (연결) Node에서 `socket.write()`의 반환값을 무시하고 계속 쓰면 무슨 일이 생기나? TCP 흐름 제어와 어떻게 이어지나?
10. (연결) zero window로 멈춘 연결을 TCP keepalive가 잡아내지 못하는 이유와, 대신 쓸 수 있는 커널 옵션은?
