# network/49-what-happens-when-url — 질문

## 질문

1. (그림) 주소창에 `https://example.com`을 치고 첫 화면이 뜨기까지의 구간을 순서대로 적어라. 구간마다 담당 노트 번호와 "끝났다는 신호"를 붙여 보라.
2. (경계) 26번 packet-journey와 이 노트는 무엇이 다른가? 이 노트의 "TCP 연결" 한 단계는 26번의 무엇과 대응하나?
3. (예측) DNS가 캐시에 있다고 할 때, 새 연결로 첫 바이트를 받기까지 몇 RTT가 드나? TCP+TLS 1.2, TCP+TLS 1.3, QUIC, 재사용 연결 각각에 대해 답하라. RTT가 100ms면 차이는 얼마인가?
4. (정의) 브라우저가 네트워크에 나가기 전에 하는 일 세 가지는? HSTS가 등록된 호스트에서 `http://`로 입력하면 무슨 일이 일어나고, 인증서 오류가 나면 사용자는 무엇을 할 수 있나(RFC 6797의 규범 수준과 함께)?
5. (연결) 응답 HTML을 받은 뒤 렌더링 구간에서 어떤 자원이 "렌더 차단"이고 어떤 자원이 "파서 차단"인가? 서드파티 출처의 스크립트 하나가 첫 화면을 몇 초 늦추는 경로를 구간 1~4로 설명하라.
6. (적용) `curl -w`의 `time_namelookup`, `time_connect`, `time_appconnect`, `time_starttransfer`로 구간별 시간을 어떻게 구하나? 값이 dns 0.001, tcp 0.034, tls 0.073, ttfb 0.111이면 각 구간은 몇 ms인가?
7. (적용) DNS 구간과 CDN 구간을 각각 건너뛰어 범인을 격리하는 `curl` 옵션은? `--connect-to`를 써도 인증서 검증이 원래 이름으로 되는 이유는?
8. (장애 진단) 구간별 실패 지도를 떠올려, 다음 증상의 첫 의심 구간과 첫 도구를 말하라. (a) `ERR_NAME_NOT_RESOLVED` (b) 즉시 `ECONNREFUSED` (c) 30초 넘게 멈춘 뒤 연결 시간 초과 (d) 서버 간 호출만 `PKIX path building failed` (e) 200인데 하얀 화면
9. (장애 진단) 서버를 옮기고 DNS를 바꿨는데 일부 서비스만 계속 옛 서버로 간다. 원인 층과 사전 대처 순서를 말하라.
10. (장애 진단) 브라우저가 `ERR_TOO_MANY_REDIRECTS`를 낸다. CDN이 원점에 HTTP로 붙는 구성에서 왜 루프가 생기고, 어떻게 확인·수정하나?
