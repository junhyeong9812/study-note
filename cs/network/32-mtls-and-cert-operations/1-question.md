## 질문

1. (왜) API 키·bearer 토큰 대신 mTLS를 쓰면 무엇이 달라지나? 신원이 무엇에 묶이나?
2. (그림) TLS 1.3에서 서버가 클라이언트 인증서를 요구하는 핸드셰이크를 그리고, CertificateRequest·클라이언트 Certificate·CertificateVerify의 위치와 역할을 적어라.
3. (경계) 클라이언트에게 알맞은 인증서가 없으면 클라이언트는 무엇을 보내나? 서버는 그다음 어떤 선택지를 갖고, `certificate_required`(116)는 언제 쓰이나?
4. (연결) mTLS가 "인증"만 한다는 말은 무슨 뜻인가? 사내 CA 하나로 모든 워크로드에 인증서를 줄 때 인가를 따로 하지 않으면 어떤 일이 생기나?
5. (적용) LB에서 mTLS를 종단하고 신원을 헤더로 앱에 넘긴다. 이 구성의 위험과 막는 법 두 가지는?
6. (그림) ACME로 인증서를 발급받는 단계를 순서대로 적고, http-01·dns-01·tls-alpn-01 도전 과제를 비교하라. 와일드카드 인증서는 어느 것으로 받나?
7. (장애 진단) 자동 갱신 로그는 "성공"인데 만료일에 장애가 났다. 무엇을 의심하고, 감시를 어떻게 바꿔야 하나?
8. (장애 진단) 사설 CA를 루트 → 중간 구조로 바꾼 뒤 nginx mTLS에서 새 클라이언트 인증서만 400으로 거부된다. 가장 유력한 설정 원인은?
9. (연결) 공인 서버 인증서를 mTLS 클라이언트 인증서로 재사용하던 연동이 2026년 갱신 뒤 깨졌다. 무엇이 바뀌었고 어떻게 옮겨야 하나?
10. (적용) 인증서 인벤토리에 들어갈 열과, 인벤토리를 채우는 수집 경로 세 가지는? 만료 타이머에는 어떤 자료구조가 맞나?
