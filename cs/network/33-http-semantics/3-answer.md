# network/33-http-semantics — 정답

> 복습 시 이 파일은 **최후에만** 연다.
> ⚠️ 이 정답은 Claude 초안(2026-09-30). 본인 검수 후 이 줄을 `✅ 검수 완료(날짜)`로 바꾼다.

## 정답

### 1. 의미론을 따로 뗀 이유

- 메서드·상태 코드·헤더의 "뜻"은 버전마다 같다. 바뀌는 것은 그 뜻을 바이트로 싣는 방법뿐이다.
  - HTTP/1.1은 텍스트 줄, HTTP/2는 이진 프레임, HTTP/3는 QUIC 스트림 위 프레임이다.
- 그래서 RFC 9110이 뜻을, RFC 9112·9113·9114가 전송 형식을 맡는다.
- 버전과 무관해지는 것
  - `GET`은 안전하고 `PUT`은 멱등이라는 성질
  - 상태 코드의 의미(예: 504 = 게이트웨이 타임아웃)
  - 캐시 규칙(RFC 9111)
- 덕분에 프록시가 앞은 HTTP/2, 뒤는 HTTP/1.1로 말해도 의미가 그대로 옮겨진다.

### 2. 안전 vs 멱등

- 안전: 클라이언트가 서버 상태 변경을 요청하지 않는다(RFC 9110 §9.2.1). GET·HEAD·OPTIONS·TRACE.
- 멱등: 같은 요청을 여러 번 보내도 **의도한 효과**가 한 번과 같다(§9.2.2). 안전 메서드 + PUT·DELETE.
- 안전하지 않지만 멱등: `PUT`, `DELETE`.
- 둘 다 아님: `POST`, `PATCH`(RFC 5789 §2).
- 두 번째 `DELETE`가 404를 받아도 멱등은 깨지지 않았다.
  - 멱등은 서버에 남는 효과("자원이 없다")가 같다는 뜻이다.
  - 응답까지 같다는 뜻은 아니다. RFC도 "응답은 다를 수 있다"고 적는다(§9.2.2).

### 3. 응답 전 연결 끊김 — 재시도 판단

- GET: 안전·멱등이다. 새 연결로 재시도해도 된다.
- PUT: 멱등이다. 원래 요청이 이미 적용됐더라도 다시 보내면 같은 결과가 된다. 재시도해도 된다.
- POST: 비멱등이다.
  - 클라이언트는 자동 재시도하지 않아야 한다(**SHOULD NOT**). 예외는 요청이 실제로 멱등임을 알거나, 원래 요청이 적용되지 않았음을 알 수 있을 때다(§9.2.2).
  - 프록시는 비멱등 요청을 자동 재시도하면 **안 된다**(**MUST NOT**).
  - 클라이언트는 실패한 자동 재시도를 다시 자동 재시도하지 않아야 한다(SHOULD NOT).
- POST를 안전하게 재시도하려면 멱등 키로 서버가 중복을 걸러야 한다.

### 4. 502 / 503 / 504

- 502 Bad Gateway: 게이트웨이가 상류에서 잘못된 응답을 받았다(§15.6.3).
  - 예: 상류가 연결 거부, 응답 도중 끊음·RST, 헤더가 깨짐.
  - 볼 곳: nginx `error.log`의 `connect() failed (111: Connection refused)`나 `upstream prematurely closed connection`. 상류 프로세스 생존 여부, keep-alive 수명 불일치(35번).
- 503 Service Unavailable: 응답하는 서버가 일시적 과부하·점검으로 처리 불가다(§15.6.4). `Retry-After`를 보낼 수 있다(MAY).
  - LB가 "건강한 대상 없음"을 503으로 표현하기도 한다(AWS ALB 문서).
  - 볼 곳: 용량 지표, 헬스체크 상태, 대상 수.
- 504 Gateway Timeout: 게이트웨이가 상류의 응답을 제때 못 받았다(§15.6.5).
  - 볼 곳: nginx `upstream timed out`, 상류 처리 시간(느린 쿼리·외부 호출), 게이트웨이 타임아웃 설정.
- 공통: 먼저 "LB가 만든 5xx인가, 앱이 만든 5xx인가"를 지표로 가른다.

### 5. 301 뒤 빈 요청

- 301·302를 받은 사용자 에이전트는 POST를 GET으로 바꿔도 된다(MAY, §15.4.2·§15.4.3).
- 실무 관행이 GET으로 바꾸는 쪽으로 굳었다(§15.4 Note). 메서드가 GET이 되면 본문 관련 헤더도 지운다(§15.4).
- 그래서 옮긴 경로로 본문 없는 GET이 도착한다.
- 영구 이전이면 **308**, 임시 이전이면 **307**을 쓴다. 둘 다 메서드와 본문을 유지하는 리다이렉트다.

### 6. 401 vs 403

- 401: 유효한 인증 정보가 없다. 서버는 `WWW-Authenticate` 헤더에 도전(challenge)을 하나 이상 **반드시** 담는다(MUST, §15.5.2).
- 403: 서버가 요청을 이해했지만 거절한다. 인증 정보가 있었다면 권한이 부족하다는 뜻이다.
  - 클라이언트는 같은 자격으로 자동 재시도하지 않아야 한다(SHOULD NOT, §15.5.4).
  - 자원의 존재 자체를 숨기려면 404로 대신 답할 수 있다(MAY).
- 요약: 401은 "누군지 모르겠다", 403은 "누군지는 알지만 안 된다".

### 7. 같은 이름 헤더 두 줄과 `Set-Cookie`

- 필드 이름은 대소문자를 무시한다(§5.1).
- 같은 이름이 여러 줄이면 순서대로 쉼표로 이은 하나의 목록 값이 된다(§5.2). 받는 쪽은 한 줄로 합쳐도 의미가 같다(MAY, §5.3).
- 그래서 목록 문법을 허용하지 않는 필드는 여러 줄로 보내면 안 된다(MUST NOT, §5.3).
- `Set-Cookie`는 실무에서 여러 줄로 오고 목록 문법이 아니다.
  - 쿠키 값의 `Expires=Wed, 21 Oct ...`처럼 쉼표가 들어가므로 쉼표로 합치면 경계가 깨진다.
  - RFC 9110 §5.3 Note는 받는 쪽이 `Set-Cookie`를 특별 취급해야 한다고 적는다.

### 8. 세션 쿠키 속성

- `Secure`: HTTPS에서만 보낸다. 평문 구간 도청으로 세션이 새는 것을 막는다.
- `HttpOnly`: JS로 못 읽는다. XSS로 `document.cookie`를 훔치는 것을 막는다.
- `SameSite=Lax` 또는 `Strict`: 크로스 사이트 요청에 붙지 않게 해 CSRF를 줄인다.
- `Path=/`, `Domain` 생략: 보낸 호스트에만 가는 host-only 쿠키가 된다. 하위 도메인에 새지 않는다.
- 만료: 세션 쿠키면 `Max-Age`를 두지 않거나 짧게 둔다. `Max-Age`와 `Expires`가 함께 있으면 `Max-Age`가 우선이다(RFC 6265 §4.1.2.2).
- `__Host-` 접두 이름: `Secure` 필수, `Domain` 금지, `Path=/` 필수를 브라우저가 강제한다(MDN). 하위 도메인이 같은 이름 쿠키를 심어 덮어쓰는 공격을 막는다.

### 9. 크로스 사이트 POST 콜백에서 로그인 풀림

- 원인 후보
  - 세션 쿠키에 `SameSite`가 없다. 일부 브라우저는 이를 `Lax`로 취급한다(MDN).
  - `Lax`는 크로스 사이트 요청 중 최상위 탐색 + 안전 메서드에만 쿠키를 붙인다. POST 콜백에는 붙지 않는다.
  - 단 기본값으로 적용된 `Lax`는 설정된 지 2분 안의 쿠키를 최상위 탐색 POST(폼 제출)에도 붙인다(MDN, RFC 6265bis 초안 "Lax-allowing-unsafe"). 결제 콜백이 폼 POST면 여기에 해당한다. 결제 페이지에 머문 시간이 길수록 증상이 난다.
  - 또는 세션 쿠키를 `SameSite=Strict`로 두었다.
- 확인: 콜백 요청에 `Cookie` 헤더가 없는지, 브라우저 개발자 도구에 SameSite 차단 경고가 있는지 본다.
- 대처
  - 콜백을 GET 리다이렉트로 받게 바꾼다.
  - 또는 콜백 처리용 쿠키만 `SameSite=None; Secure`로 두고 범위를 좁힌다. `None`은 CSRF 방어가 약해지므로 state 파라미터 검증 같은 별도 방어를 둔다.

### 10. `fetch`와 500

- `fetch()`는 요청 자체가 실패할 때(네트워크 오류, 잘못된 URL 등)만 reject한다(MDN). 4xx·5xx 응답은 "응답을 받았다"로 보고 resolve한다.
- 그래서 `try/catch`만 두면 500을 성공으로 처리한다.
- 고치는 법: `res.ok`(상태 200~299)나 `res.status`를 직접 확인한다.

```ts
const res = await fetch(url);
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const body = await res.json();
```

- 재시도는 메서드가 멱등이고 상태가 일시적(502·503·504·429)일 때만 건다.
