# network/33-http-semantics — 질문

## 질문

1. (왜) HTTP/1.1·HTTP/2·HTTP/3가 있는데 왜 "의미론"을 따로 한 문서(RFC 9110)로 떼어 냈나? 그 덕에 무엇이 버전과 무관해지나?
2. (경계) "안전"과 "멱등"을 각각 정의하고, 안전하지 않지만 멱등인 메서드와 둘 다 아닌 메서드를 하나씩 들어라. 두 번째 `DELETE`가 404를 받으면 멱등이 깨진 것인가?
3. (적용) 클라이언트가 응답을 받기 전에 연결이 끊겼다. GET, PUT, POST 각각을 자동 재시도해도 되나? RFC가 클라이언트와 프록시에 거는 규범 수준(SHOULD NOT / MUST NOT)을 구분해 답하라.
4. (장애 진단) nginx 뒤 서비스에서 502, 503, 504가 섞여 나온다. 각 숫자가 뜻하는 것과, 그때 가장 먼저 볼 로그·지표를 적어라.
5. (예측) 경로를 옮기며 301을 걸었더니 폼 제출이 빈 요청으로 들어온다. 왜 그런가? 어떤 코드로 바꿔야 하나?
6. (경계) 401과 403의 차이는 무엇인가? 각각 응답에 반드시 또는 권장으로 따라붙는 규칙을 하나씩 말하라.
7. (왜) 같은 이름의 헤더가 두 줄 오면 어떻게 해석하나? `Set-Cookie`는 왜 그 규칙의 예외인가?
8. (적용) 세션 쿠키에 붙일 속성을 고르고 각각이 막는 위협을 말하라. `__Host-` 접두 이름은 무엇을 강제하나?
9. (장애 진단) 외부 결제 페이지에서 POST로 돌아오는 콜백에서만 로그인이 풀린다. 원인 후보와 대처를 말하라.
10. (연결) `fetch()`로 호출한 API가 500을 돌려줬는데 `catch`에 걸리지 않았다. 왜 그런가? 코드를 어떻게 고치나?
