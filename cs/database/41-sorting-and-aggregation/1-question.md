# database/41-sorting-and-aggregation — 질문

## 질문

1. (그림) 메모리 버퍼 B 페이지로 N 페이지를 정렬하는 외부 병합 정렬의 두 단계를 그려라. 통과 횟수와 총 I/O 식은? N = 3,367, B = 512이면 통과는 몇 번인가?
2. (연결) 병합 단계에서 "다음으로 내보낼 행"을 고르는 데 쓰는 자료구조는? k개 런을 병합할 때 행 하나당 비용은? 같은 자료구조가 `ORDER BY … LIMIT 10`에서는 어떻게 쓰이나?
3. (경계) PostgreSQL 17의 `tuplesort`는 교과서 외부 정렬과 무엇이 다른가? 런 만들기 알고리즘, 병합 방식(15 전후), 마지막 병합의 처리를 말하라.
4. (비교) `GROUP BY`를 정렬 기반과 해시 기반으로 할 때 각각의 동작, 메모리 사용, 출력 순서를 비교하라. 입력이 이미 정렬돼 있으면 어느 쪽이 유리한가?
5. (그림) PostgreSQL 17의 해시 집계가 메모리 한도를 넘을 때 어떻게 동작하나? CMU 교과서의 "분할 → 재해시" 방식과 무엇이 다른가? 해시 연산의 기본 메모리 한도는 얼마인가?
6. (예측) 50만 행을 `ORDER BY note`로 정렬했더니 `Sort Method: external merge  Disk: 26936kB`가 나왔다. `work_mem`을 128MB로 올리면 항상 더 빨라지나? 로컬 재현 결과와 그 이유를 말하라.
7. (장애 진단) 스필을 없애려고 `work_mem`을 전역으로 512MB로 올렸더니 피크 시간에 DB 프로세스가 죽었다. 로그에 무엇이 보이고, 왜 그렇게 되며, 올바른 조정 방법은?
8. (장애 진단) 분석 쿼리 하나가 디스크를 채워 다른 쓰기까지 실패했다. 평소에 이런 쿼리를 찾아내는 설정과 뷰, 그리고 한 쿼리를 끊어 내는 안전장치는? 그 안전장치에 걸리면 어떤 오류가 나나?
9. (연결) MySQL 8.4에서 정렬이 디스크를 썼는지 무엇으로 확인하나? `GROUP BY`가 내부 임시 테이블을 디스크로 넘기는 기준은? 기본 `sort_buffer_size`는?
