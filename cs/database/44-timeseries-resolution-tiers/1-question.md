# database/44-timeseries-resolution-tiers — 질문

## 질문

1. (왜) 초당 1행짜리 지표를 원본 그대로 영원히 두면 조회와 저장에서 각각 무엇이 망가지나? 해상도 계층은 이 둘을 어떻게 동시에 푸나?
2. (계산) raw 1초·7일, 1분·90일, 1시간·2년 계층이면 지표 하나가 각 계층에 몇 행을 가지나? 6개월 추이 그래프는 어느 계층을 읽어야 하나?
3. (경계) 1분 버킷에 (n, sum, min, max)를 담았다. 1시간 버킷으로 다시 접을 때 정확히 구할 수 있는 것과 없는 것은? 샘플 10개(평균 100)와 1000개(평균 200) 버킷의 평균의 평균과 실제 평균은?
4. (예측) 3시간 동안 초당 1행(10,800행)을 `ts BETWEEN h AND h + interval '1 hour'`로 시간별로 집계했다. 시간별 건수와 합은? `date_bin`으로 하면?
5. (장애 진단) 장애 복구 뒤 특정 시간대 그래프만 두 배로 튀었다. 원인을 무엇으로 확인하고, 롤업 SQL을 어떻게 바꿔야 재발하지 않나? `n = n + EXCLUDED.n`은 왜 답이 아닌가?
6. (예측) 01:05에 [00:00, 01:00) 버킷을 롤업한 뒤 01:07에 `ts = 00:59:30` 행이 도착했다. 무슨 일이 생기고, 에러는 나나? 어떻게 흡수하나? 원본 보존 기간에는 어떤 조건이 붙나?
7. (연결) 원본 보존을 `DELETE WHERE ts < now() - interval '7 days'`로 했다. 디스크 파일 크기는 줄어드나? 파티션 DROP과 무엇이 다른가? 이 구조는 어떤 자료구조와 같은가?
8. (장애 진단) 매일 자정에 수집이 전부 실패한다. PostgreSQL과 MySQL에서 각각 어떤 에러가 보이고, 원인과 대처는? DEFAULT 파티션을 두면 해결되나?
9. (장애 진단) 몇 달 잘 돌던 시계열 DB가 디스크 풀로 멈췄다. 기록·조회는 그동안 정상이었다. 무엇이 빠졌고, 긴급 조치와 재발 방지 경보는 무엇인가?
