# database/39-hash-indexes — 질문

## 질문

1. (왜) 메모리 해시맵은 꽉 차면 전체를 두 배로 리해시한다. 디스크 위의 해시 인덱스에서 이 방식이 왜 문제이고, 확장 해싱·선형 해싱은 무엇을 바꿔 해결하나?
2. (그림) 확장 해싱에서 전역 깊이 2, 버킷 용량 2, 하위 비트 사용이다. 디렉터리는 00→A(지역 2)[4, 8], 01·11→B(지역 1)[1, 3], 10→C(지역 2)[2, 6]이다. 5를 넣고, 이어서 12를 넣을 때 무엇이 나뉘고 디렉터리는 어떻게 되나?
3. (계산) PostgreSQL 해시 인덱스 메타페이지가 `maxbucket = 9, highmask = 15, lowmask = 7`이다. 해시값 13과 9는 각각 어느 버킷에 가나? 다음 분할 때 새로 생기는 버킷 번호와, 항목을 내주는 옛 버킷 번호는?
4. (예측) `ffactor = 307`인 빈 해시 인덱스에 행을 1000, 2000, 3000개까지 넣었다. 각 시점의 버킷 수(`maxbucket + 1`)는 대략 몇 개일까? 분할은 누가, 언제 하나?
5. (경계) PostgreSQL 17 해시 인덱스로 할 수 없는 것 세 가지를 들라. 긴 URL 컬럼에서 해시 인덱스가 B-tree보다 작은 이유와 그 대가는?
6. (장애 진단) 해시 인덱스가 있는 테이블에서 대부분의 `INSERT`는 빠른데 가끔 한 건씩 튄다. 원인과, 분할이 "포기"되는 경우는 무엇이며, 대처는?
7. (장애 진단) 5만 행 중 4만 5천 행이 같은 값인 컬럼에 해시 인덱스를 걸었더니 그 값의 조회가 느리다. `pgstathashindex`에 무엇이 보이고 왜 분할로 해결되지 않나?
8. (연결) MySQL 8.4 InnoDB 테이블에 `INDEX (k) USING HASH`를 만들면 무엇이 생기나? MySQL에서 진짜 해시 인덱스는 어디에 있고, 적응형 해시 인덱스의 기본값과 주의점은?
