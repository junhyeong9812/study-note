# database/38-lsm-storage-engine — 질문

## 질문

1. (그림) RocksDB에서 `Put(k, v)` 하나가 WAL·memtable·immutable memtable·L0·L1…로 흘러가는 경로를 그려라. flush와 compaction이 각각 언제 일어나나(기본값 포함)?
2. (경계) L0와 L1 이하 레벨은 무엇이 다른가? 그 차이 때문에 점 조회가 L0에서 치르는 비용은?
3. (계산) Bloom filter를 키당 10비트, 해시 7개로 쓰면 거짓 양성률은 대략 얼마인가? Bloom filter가 범위 스캔에 도움이 안 되는 이유는?
4. (계산) 쓰기·읽기·공간 증폭을 각각 정의하라. RocksDB Tuning Guide의 예(L0 512MB, L1 512MB, L2 5GB, L3 51GB, L4 512GB, 데이터 500GB)에서 공간 증폭과 쓰기 증폭은 얼마인가? 쓰기 증폭 50, 디스크 500MB/s면 DB는 초당 얼마를 받을 수 있나?
5. (경계) Leveled와 Tiered(Universal) compaction은 세 증폭을 어떻게 맞바꾸나? Universal에서 디스크가 일시적으로 2배 필요할 수 있는 이유는?
6. (예측) 큐처럼 순번 키를 넣고 앞에서부터 지운다. 10만 개 중 앞 9만 9천 개를 지운 뒤 "첫 살아 있는 항목"을 찾으면 무슨 일이 생기나? tombstone은 언제 사라지나?
7. (장애 진단) RocksDB LOG에 `Stalling writes because we have 20 level-0 files`가 찍히고 쓰기 지연이 튄다. 무슨 뜻이고, 무엇이 더 나빠지면 완전히 멈추며, 어떤 손잡이로 대처하나? 트리거 값을 크게 올리면 무엇을 잃나?
8. (연결) B+트리(08번)와 LSM을 "제자리 갱신 vs 덧붙이기"로 비교하라. 무작위 키 삽입이 많은 워크로드에서 각각 어떤 증폭을 치르나?
9. (장애 진단) 삭제를 계속하는데 디스크 사용량이 줄지 않는다. 가능한 원인 두 가지(tombstone 쪽, 스냅숏·반복자 쪽)와 확인·대처법을 말하라.
