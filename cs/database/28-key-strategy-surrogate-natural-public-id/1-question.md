# database/28-key-strategy-surrogate-natural-public-id — 질문

## 질문

1. (왜) 키를 고를 때 답해야 하는 네 가지 질문은 무엇인가? 각각 무엇이 깨지면 드러나나?
2. (설계) 회원 테이블에서 이메일은 로그인 ID이고 유일해야 한다. 이메일을 PK로 두지 않고 유일성을 지키는 스키마를 PostgreSQL로 써라. 이메일이 PK일 때와 비교해 이메일 변경 비용은 어떻게 다른가?
3. (그림) bigint 시퀀스 PK와 UUIDv4 PK에 행을 계속 삽입할 때 B+Tree 리프에서 일어나는 일을 그림으로 비교하라. 버퍼 풀에는 어떤 차이가 생기나?
4. (예측) 20만 행을 넣은 뒤 PostgreSQL `pgstatindex`로 PK 인덱스를 보면 bigint, UUIDv4, UUIDv7의 `avg_leaf_density`는 대략 얼마로 나올까? bigint가 딱 그 값인 이유는?
5. (경계) UUIDv7의 비트 배치를 그려라. v4 대비 장점과 대가는? RFC 9562는 보안 목적이 있을 때 어느 버전을 권하나?
6. (연결) InnoDB에서 PK를 16바이트 랜덤 값으로 바꾸면 PostgreSQL보다 영향이 넓은 이유 두 가지는? MySQL `UUID()`를 PK로 쓸 때 `UUID_TO_BIN`의 두 번째 인자는 무엇을 하나?
7. (장애 진단) 웹 화면에서만 주문 상세가 404다. 서버 로그의 ID는 `1234567890123456789`, 브라우저가 보낸 ID는 `1234567890123456800`이다. 원인과 서버·클라이언트 쪽 대처는?
8. (장애 진단) 주문 URL `/orders/10231`에서 번호를 바꿔 보니 다른 사람 주문이 보였다는 제보가 왔다. 무엇이 1순위 조치이고, 외부 ID를 UUID로 바꾸는 것만으로 충분하지 않은 이유는?
9. (예측) PostgreSQL에서 `INSERT`(id 1) → 롤백된 트랜잭션 안 `INSERT` → `INSERT` 순으로 실행하면 id는? 이 성질 때문에 시퀀스로 만들면 안 되는 업무 번호의 예는?
