# database/37-row-vs-column-storage — 질문

## 질문

1. (그림) `id, country, status, amount` 세 행짜리 표를 NSM(행 저장), DSM(컬럼 저장), PAX 배치로 각각 그려라. DSM에서 흩어진 값을 한 행으로 다시 맞추는 두 방법은?
2. (왜) `SELECT country, sum(amount) … GROUP BY country`가 행 저장에서는 느리고 컬럼 저장에서는 빠른 이유를 "읽는 바이트"로 설명하라. 10만 행 `wide(id int, v int, pad char(500))`의 `sum(v)`는 PostgreSQL에서 몇 페이지를 읽었나?
3. (경계) 컬럼 저장은 무엇에 느린가? CMU L5가 드는 이유와, ClickHouse가 단건 UPDATE를 어떻게 처리하는지 연결해 설명하라.
4. (예측) 10만 행 합성 데이터(country 5종, status 3종, amount 무작위)를 행 단위로 압축할 때와 칼럼별로 압축할 때, 그리고 (country, status)로 정렬한 뒤 칼럼별로 압축할 때 크기가 어떻게 달라질까? 어떤 칼럼이 거의 줄지 않을까?
5. (연결) RLE·딕셔너리·비트맵 인코딩을 각각 한 줄로 설명하고, 어떤 칼럼(카디널리티·정렬 여부)에 맞는지 말하라. 딕셔너리 코드가 순서를 보존하면 무엇이 가능해지나?
6. (설계) 주문 서비스가 있다. 주문 상세 조회·상태 변경 API와 월간 국가별 매출 리포트를 각각 어느 저장소에 두겠나? 리포트 저장소에서 주문 상태가 바뀌면 어떻게 반영하나?
7. (장애 진단) 월말 리포트가 도는 30분 동안 주문 API p99가 3배로 뛴다. 어디서 무엇을 보고 확인하며, 어떻게 고치나?
8. (장애 진단) ClickHouse로 옮긴 뒤 상태 변경을 행마다 `ALTER TABLE … UPDATE`로 반영했더니 `system.mutations`에 미완료가 쌓이고 결과가 들쭉날쭉하다. 원인과 대처는?
