# database/21-connection-pooling — 질문

## 질문

1. (왜) 요청마다 DB 커넥션을 새로 열면 무엇이 비싼가? PostgreSQL 17과 MySQL 8.4는 커넥션 하나를 서버에서 각각 무엇으로 처리하나?
2. (그림) 풀 크기 3에 스레드 4개가 동시에 `getConnection()`을 부른다. 네 번째 스레드는 어떻게 되나? 첫 스레드가 `close()`를 부르면 소켓은 닫히나?
3. (계산) 초당 400건이 들어오고 건당 커넥션을 20ms 쥔다. 평균 몇 개가 동시에 쓰이나? 쿼리가 느려져 60ms를 쥐게 되면? 이때 풀을 키우는 것이 왜 답이 아닐 수 있나?
4. (계산) PostgreSQL 17 기본 설정에서 일반 역할이 쓸 수 있는 연결 수는? 앱 인스턴스 최대 12대, 배치 1개(풀 5), 모니터링 2개가 붙는다면 인스턴스당 풀은 최대 얼마인가?
5. (경계) HikariCP의 `maxLifetime`은 무엇보다 짧아야 하나? 반대로 두면 어떤 증상이 나고, 빌릴 때 검증이 있는데도 왜 늦어질 수 있나?
6. (예측) 풀 크기 2, 스레드 2개가 각각 커넥션 하나를 쥔 채 두 번째 커넥션을 요청한다. 어떤 일이 벌어지나? 스레드 8개가 최대 3개씩 동시에 쥔다면 교착을 피하는 최소 풀 크기는?
7. (연결) 풀은 개념적으로 어떤 자료구조인가? HikariCP의 `ConcurrentBag`은 대여 요청을 어떤 순서로 처리하나?
8. (장애 진단) 로그에 `HikariPool-1 - Connection is not available, request timed out after 30000ms (total=10, active=10, idle=0, waiting=37)`이 쏟아진다. 이 숫자로 무엇을 알 수 있고, 무엇을 어떤 순서로 확인하나?
9. (장애 진단) 오토스케일로 인스턴스가 늘자 새 인스턴스가 `FATAL: sorry, too many clients already`로 기동에 실패한다. SQLSTATE는? `max_connections`를 올리는 것 말고 무엇을 하나?
10. (설계) node-postgres `Pool`을 기본값으로 쓰면 풀이 바닥났을 때 무슨 일이 생기나? 어떤 옵션으로 막나?
