# database/50-temporal-and-bitemporal-tables — 질문

## 질문

1. (왜) 유효 시간과 기록 시간은 각각 무엇을 기록하나? 누가 값을 넣고, 과거로 고칠 수 있나? 둘 중 하나만 있을 때 답할 수 없는 질문을 하나씩 들어라.
2. (그림) 1/10에 "고객 1은 1/1부터 서울"을 기록했다. 3/10에 "사실 2/15에 부산으로 이사"라는 정정이 왔다. 바이템포럴 테이블의 행을 그리고, "2/20 주소를 지금 아는 대로"와 "2/20 주소를 3/1에 알던 대로"의 답을 구하라.
3. (경계) 기간을 `[시작, 끝)`로 두는 이유는? 닫힌 구간 `[from, to]`나 "끝 = 다음 시작 − 1초"로 저장하면 경계에서 어떤 일이 생기나?
4. (연결) SQL:2011의 application-time 테이블과 system-versioned 테이블은 무엇이 다른가? `FOR PORTION OF`와 `FOR SYSTEM_TIME AS OF`는 각각 무엇을 하나? PostgreSQL 17·18과 MySQL 8.4는 각각 어디까지 지원하나?
5. (설계) PostgreSQL 17에서 "같은 고객의 주소 기간이 겹치면 안 된다"를 DB 제약으로 걸어라. 필요한 확장과, 맞닿은 기간이 허용되는 이유는? 바이템포럴이면 제약을 어떻게 바꾸나?
6. (장애 진단) MySQL 8.4에서 가격표에 "기간 겹침 검사 후 INSERT"를 하는데 같은 상품의 겹친 가격 두 행이 생겼다. 왜 검사가 막지 못했고, 어떻게 고치나? 기존 겹침은 어떻게 찾나?
7. (예측) PostgreSQL 17에서 트리거로 system-time을 흉내 낸다(`sys_period tstzrange`, `now()` 사용). 한 트랜잭션에서 같은 행을 두 번 UPDATE하면 이력 테이블에 무엇이 남나? 이것은 버그인가?
8. (장애 진단) 2월 매출 리포트를 다시 뽑았더니 2월에 제출한 숫자와 다르다. 가능한 원인 두 가지와, 앞으로 재현 가능하게 만드는 방법은?
9. (경계) 요율표, 감사 로그, 급여 소급 인상 — 각각 유효 시간만, 기록 시간만, 바이템포럴 중 무엇이 필요한가? 두 축을 모두 두는 비용은?
