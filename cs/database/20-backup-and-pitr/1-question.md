# database/20-backup-and-pitr — 질문

## 질문

1. (왜) 크래시 복구(WAL 재생)와 복제본이 있는데도 백업이 따로 필요한 이유는? 각 장치가 살리는 사고와 못 살리는 사고를 표로 나눠라.
2. (경계) 논리 백업·물리 백업·연속 아카이브(PITR)를 이식성·복원 속도·복원 가능한 시점으로 비교하라. RPO 5분, RTO 30분이 목표라면 무엇을 고르나?
3. (예측) PostgreSQL에서 `pg_dump`가 돌고 있는 중에 배포 스크립트가 `ALTER TABLE orders ADD COLUMN …`을 실행했다. 이어서 들어오는 평범한 `SELECT * FROM orders`는 어떻게 되나? 락 모드 이름으로 설명하라.
4. (설계) MySQL 8.4 InnoDB에서 운영 중에 일관된 논리 백업을 뜨는 옵션은? 그 옵션이 보장하지 못하는 것 두 가지와, 옵션 없이 기본값으로 뜰 때의 문제는?
5. (경계) `archive_command`가 지켜야 할 exit code 계약은 무엇인가? 스크립트가 복사에 실패하고도 0을 돌려주면 어떤 일이 언제 드러나나?
6. (적용) 누군가 `DROP TABLE orders`를 실행했다. `pg_waldump`로 해당 트랜잭션이 xid 1525, 커밋 LSN `0/9B698090`임을 찾았다. 그 직전 상태로 되돌리는 복구 설정을 써라. 시각으로 목표를 잡는 것보다 나은 이유는?
7. (예측) PITR로 복구를 끝낸 서버가 새 WAL을 쓰기 시작했다. 옛 WAL 파일과 이름이 겹치지 않는 이유는? `recovery_target_action`을 기본값으로 뒀다면 목표에 닿았을 때 서버는 무엇을 하나?
8. (연결) PostgreSQL 17 증분 백업을 켜려면 서버에 무엇이 필요하고, 복원 때 무엇이 필요한가? 보존 정책이 날짜만 보고 오래된 백업을 지우면 무슨 일이 생기나?
9. (장애 진단) GitLab 2017-01-31 사고에서 매일 돌던 `pg_dump` 백업이 쓸모없었던 원인 사슬을 적어라. 같은 일을 막으려면 백업의 "성공"을 무엇으로 판정해야 하나?
10. (적용) MySQL에서 덤프를 뜬 뒤 실수로 `DELETE FROM orders`가 실행됐다. 덤프 파일과 binlog로 삭제 직전까지 되돌리는 절차를 좌표(파일·위치)를 어디서 얻는지까지 포함해 적어라.
