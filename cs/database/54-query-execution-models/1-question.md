# database/54-query-execution-models — 질문

## 질문

1. (그림) `SELECT * FROM ev WHERE amount = 7 LIMIT 3`을 반복자(Volcano) 모델로 실행하는 과정을 `next()` 호출로 그려라. 50만 행 테이블에서 조건에 맞는 행이 앞쪽에 있으면 스캔은 몇 행쯤 읽고 멈추나? 계획의 어느 숫자로 확인하나?
2. (경계) 파이프라인 차단 연산자란 무엇인가? 예를 셋 들어라. `ORDER BY note LIMIT 10`이 `LIMIT`에도 불구하고 테이블 전체를 읽는 이유는? 인덱스가 있으면 어떻게 바뀌나?
3. (비교) 반복자·구체화·벡터화 모델을 "연산자가 한 번에 넘기는 것", "호출 수", "맞는 부하" 기준으로 비교하라. 벡터화가 SIMD를 쓰기 쉬운 이유는?
4. (왜) 데이터가 전부 캐시에 있는데도 수억 행 집계가 CPU 코어 하나를 100% 쓰며 느린 이유를 처리 모델로 설명하라. 같은 DB 안에서 쓸 수 있는 대응과, 모델 자체를 바꾸는 대응은?
5. (읽기) PostgreSQL 병렬 계획 `Finalize Aggregate → Gather(Workers Planned: 2, Launched: 2) → Partial Aggregate(loops=3) → Parallel Seq Scan(actual rows=19144 loops=3)`에서 loops가 3인 이유와 스캔한 총 행 수는? 집계가 두 단계로 나뉜 이유는?
6. (장애 진단) 같은 병렬 쿼리가 한가할 때는 빠르고 바쁠 때는 두세 배 느리다. 계획에서 무엇을 보면 원인을 알 수 있나? 관련 설정 세 개와 기본값, 대처는?
7. (예측) PostgreSQL 17에서 추정 비용 9,307인 집계 쿼리에 `SET jit_above_cost = 10`을 하면 빨라지나? 로컬 재현 결과와 이유, OLTP 역할에 대한 권장 설정은?
8. (장애 진단) 같은 SQL이 psql에서는 `Gather`로 병렬 실행되는데 애플리케이션에서는 병렬로 돌지 않는다. PostgreSQL 문서 15.2 기준 원인 후보 세 가지와 대처는?
9. (연결) CMU 15-445 L14가 나누는 쿼리 안 병렬 세 종류와 교환 연산자 세 종류는? PostgreSQL 17과 MySQL 8.4 InnoDB는 각각 어떤 병렬을 제공한다고 문서에서 확인할 수 있나?
