# database/40-filters-and-specialized-indexes — 질문

## 질문

1. (왜) `WHERE name LIKE '%키보드%'`는 `name`에 B-tree 인덱스가 있어도 풀스캔이다. `LIKE '키보드%'`는 왜 다를 수 있고, PostgreSQL에서 그때 추가로 필요한 조건은?
2. (그림) 비트 16칸, 해시 3개인 블룸 필터에 A(2, 7, 11)와 B(7, 9, 14)를 넣었다. C(2, 9, 11)와 D(3, 7, 9)를 조회하면 각각 무엇이라고 답하나? 블룸 필터가 절대 하지 않는 실수는?
3. (연결) 블룸 필터가 데이터베이스 안에서 쓰이는 자리 세 곳을 들라. PostgreSQL `bloom` 확장 인덱스는 조회 때 인덱스의 얼마를 읽고, 어떤 쿼리에 맞나?
4. (예측) 문서 '삼성전자 주가가 올랐다'가 있다. PostgreSQL `to_tsvector('simple', …) @@ to_tsquery('simple', '삼성')`, MySQL 기본 FULLTEXT 파서의 `AGAINST('삼성')`, MySQL ngram 파서의 `AGAINST('삼성' IN BOOLEAN MODE)`는 각각 찾을까? 이유는?
5. (경계) MySQL ngram FULLTEXT 인덱스에서 `AGAINST('삼성전자' IN NATURAL LANGUAGE MODE)`와 `IN BOOLEAN MODE`의 결과가 다르다. 검색어가 각각 무엇으로 바뀌어 그런가? '성전 이야기' 문서는 어느 쪽에 걸리나?
6. (장애 진단) 게시판에 pg_trgm GIN 인덱스를 붙인 뒤 글 저장이 느려지고, 가끔 한 건이 유독 오래 걸린다. 검색 응답도 들쭉날쭉하다. 원인과 확인 방법, 대처는?
7. (예측) 시간순으로 적재된 30만 행 로그와, 같은 데이터를 무작위 순서로 넣은 테이블에 각각 BRIN(ts)을 걸었다. "1시간 구간" 조회는 각각 어떻게 될까? 무엇으로 미리 알 수 있나?
8. (설계) "지도 화면 안의 가게"와 "내 위치에서 가까운 가게 3곳"을 PostgreSQL과 MySQL에서 각각 무엇으로 인덱싱하나? R-tree는 무엇으로 가지를 건너뛰나?
9. (장애 진단) BRIN 인덱스가 걸린 로그 테이블에 방금 대량 적재한 구간을 조회하니 BRIN이 거의 걸러 주지 않는다. VACUUM 뒤에는 괜찮다. 왜인가?
