# database/11-join-algorithms — 질문

## 질문

1. (왜) 세 조인 알고리즘(중첩 루프·해시·정렬 병합)을 각각 "무엇을 한 번 준비하고, 무엇을 반복하는가"로 설명하라. 해시 조인은 왜 등호 조건에서만 쓰이나?
2. (계산) R은 M = 1000 페이지·m = 100,000행, S는 N = 500 페이지다. 버퍼 B = 100이다. 단순 중첩 루프, 블록 중첩 루프, Grace 해시 조인의 I/O 비용을 CMU 비용식으로 구하라.
3. (예측) 고객 5명(`id BETWEEN 100 AND 104`)의 주문을 가져오는 조인과, 주문 30만 행 전체를 고객 5만 행과 조인해 지역별 합계를 내는 쿼리가 있다. `orders.customer_id`에 인덱스가 있다. PostgreSQL은 각각 어떤 조인을 고를까? 왜?
4. (장애 진단) 리포트 쿼리가 갑자기 수 분 걸린다. `EXPLAIN ANALYZE`에 `Nested Loop`, 바깥 노드 `rows=5`(추정) · `actual rows=500`, 안쪽 `Rows Removed by Join Filter: 49749500`이 보인다. 무엇이 일어났고, 근본 대처와 긴급 대처는?
5. (경계) PostgreSQL 해시 조인 노드에 `Batches: 32`가 보였다. 무슨 뜻인가? 메모리 한도는 어떤 설정의 곱이고, 올릴 때 무엇을 계산해야 하나? MySQL은 같은 상황에서 어떻게 되나?
6. (연결) 정렬 병합 조인이 해시 조인보다 나은 경우 두 가지를 들라. MySQL 8.4에서 같은 쿼리를 돌리면 무엇이 다른가?
7. (장애 진단) `orders.customer_code varchar`와 `customers.id int`를 조인한다. PostgreSQL은 캐스트 없이 에러가 났고, 캐스트를 넣자 느려졌다. MySQL에서는 에러 없이 느리다. 각각 무엇이 일어났고, 어느 쪽을 캐스트해야 하며, 근본 해결은?
8. (연결) JPA에서 주문 1000건을 조회한 뒤 루프 안에서 `customerRepo.findById`를 부르는 코드는 조인 알고리즘으로 보면 무엇인가? DB에 조인을 맡기면 무엇이 달라지나?
