# database/47-autocomplete-and-typeahead — 질문

## 질문

1. (왜) 자동완성은 전문 검색과 무엇이 달라 별도 설계가 필요한가? 세 가지를 대라.
2. (예측) PostgreSQL(로케일 en_US.utf8)에서 `term LIKE '삼성%'`에 인덱스를 쓰려면 어떤 인덱스가 필요한가? 실행 계획의 `Index Cond`는 어떤 모양이 되나? `LIKE '삼%'`는 왜 같은 인덱스를 안 탔나?
3. (계산) '삼'(U+C0BC)의 초성·중성·종성 인덱스를 Unicode 3.12의 식으로 구하라. 반대로 초성 ㅅ(9)·중성 ㅓ(4)·종성 ㅇ(21)인 음절의 코드포인트 식을 써라.
4. (경계) 사용자가 "삼성"을 치는 도중 "삼ㅅ"이 서버로 간다. 음절 단위 접두사 검색은 왜 0건인가? 자모로 풀 때 겹모음·겹받침까지 풀어야 하는 이유를 예로 들어라.
5. (연결) edge n-gram 방식과 completion suggester 방식을 자료구조·갱신 비용·기능 면에서 비교하라. edge n-gram에 `search_analyzer`를 따로 두는 이유는?
6. (장애 진단) 캠페인 뒤 검색 클러스터 QPS가 평소의 몇 배가 됐고, 대부분 자동완성 요청이다. 원인 후보와 대처를 서버·클라이언트로 나눠 대라.
7. (장애 진단) "삼성"을 쳤는데 가끔 "삼" 결과가 보인다. 원인은? `AbortController`만으로 충분한가?
8. (예측) ES edge n-gram 색인 분석기가 `max_gram: 3`이다. "apple"을 검색하면? `truncate` 필터로 검색어를 3자로 자르면 무엇이 달라지나?
