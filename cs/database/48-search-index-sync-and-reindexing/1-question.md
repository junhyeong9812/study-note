# database/48-search-index-sync-and-reindexing — 질문

## 질문

1. (왜) 앱이 DB와 검색 엔진에 차례로 쓰는 이중 쓰기는 모든 쓰기가 성공해도 불일치가 생길 수 있다. 두 요청의 시간축을 그려 설명하라.
2. (경계) "`updated_at > 마지막 동기화 시각`을 주기적으로 조회해 색인"하는 방식이 놓치는 변경 두 가지는? 로그 기반 CDC는 이 둘을 어떻게 잡나?
3. (예측) 로컬 재현: 세션 A가 outbox에 INSERT해 seq 3을 받고 3초 뒤 커밋, 그사이 세션 B가 seq 4를 받아 바로 커밋했다. 폴러가 B 커밋 직후 `seq > 2`로 읽고 커서를 옮긴다. 폴러는 무엇을 보고, 결국 무엇을 놓치나? 해법 두 가지는?
4. (연결) Elasticsearch `version_type: external`은 무엇을 검사하나? 늦게 도착한 옛 upsert를 어떻게 막는가? `index.gc_deletes`는 이 보호에 어떤 한계를 만드나?
5. (그림) 매핑을 바꿔야 한다. 별칭을 써서 무중단으로 재색인하는 단계를 그려라. 별칭 교체가 "원자적"이라는 것은 무엇을 보장하나?
6. (장애 진단) 재색인 뒤 별칭을 바꿨더니 최근 몇 시간의 삭제·가격 변경이 새 인덱스에 없다. 왜인가? 다음 재색인에서는 무엇을 다르게 하나?
7. (장애 진단) CDC 색인기를 사흘간 내려 뒀더니 PostgreSQL 서버 디스크가 거의 찼다. 무엇이 디스크를 잡고 있나? 어디서 확인하고 어떻게 막나?
8. (예측) PostgreSQL에서 `BEGIN; INSERT …; NOTIFY ch; ROLLBACK;`을 하면 LISTEN 중인 세션은 알림을 받나? COMMIT이면? NOTIFY를 색인의 유일한 전달 수단으로 쓰면 안 되는 이유는?
