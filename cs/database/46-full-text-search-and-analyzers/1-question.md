# database/46-full-text-search-and-analyzers — 질문

## 질문

1. (왜) `LIKE '%냉장고%'`는 B-tree 인덱스를 못 쓴다. 왜인가? 역색인은 이 문제를 어떻게 푸나? 역색인으로도 풀리지 않는 LIKE 대비 이점 두 가지를 더 대라.
2. (그림) 분석기의 세 단계(문자 필터·토크나이저·토큰 필터)를 그리고, `'The runners were running quickly'`가 PostgreSQL `english` 설정에서 어떤 lexeme이 되는지 적어라.
3. (예측) MySQL 8.4 기본 설정에서 문서 "삼성전자 주가 상승", "삼성 라이온즈 우승"에 FULLTEXT(공백 파서)를 걸고 `MATCH AGAINST('삼성')`을 한다. 몇 건 나오나? ngram 파서(`ngram_token_size`=2)로 바꾸면? 두 경우의 이유를 각각 설명하라.
4. (경계) 한국어 검색에서 공백 단위, n-gram, 형태소 분석은 각각 어떤 실패를 낳나? nori의 `decompound_mode` 세 값은 무엇이 다른가?
5. (계산) N = 1000 문서에서 용어 A는 10개 문서, 용어 B는 500개 문서에 나온다. Lucene BM25의 idf를 각각 구하라. 문서 길이가 평균일 때 같은 용어가 1번 나온 문서와 10번 나온 문서의 tf는 각각 얼마인가(k1 = 1.2, b = 0.75)?
6. (연결) PostgreSQL `ts_rank`는 BM25와 무엇이 다른가? 그 차이 때문에 흔한 단어와 드문 단어를 함께 검색할 때 어떤 일이 생기나?
7. (장애 진단) 배포 뒤 제목 검색이 전부 0건이다. 에러는 없다. 무엇을 의심하고, PostgreSQL과 Elasticsearch에서 각각 어떻게 확인하나?
8. (장애 진단) 사용자 사전에 신조어를 추가했다. 새로 등록한 상품은 검색되는데 기존 상품은 안 된다. 왜인가? 재색인이 필요한 변경과 필요 없는 변경을 하나씩 대라.
9. (예측) pg_trgm GIN 인덱스가 있는 20만 행 테이블에서 `LIKE '%냉장고%'`와 `LIKE '%삼성%'`의 실행 계획은 각각 어떻게 나오나? 왜 다른가?
