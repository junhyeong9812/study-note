# database/15-two-phase-locking-and-deadlock — 질문

## 질문

1. (왜) 읽을 때 잠깐 락을 걸고, 쓸 때 다시 잠깐 락을 거는 방식으로는 왜 lost update를 못 막나? 2PL은 무슨 규칙을 더해서 이것을 막나?
2. (경계) 기본 2PL과 강한 엄격 2PL(rigorous)은 락을 언제 푸나? 기본 2PL에 남는 문제 두 가지는 무엇이고, 엄격 2PL은 그중 무엇을 없애고 무엇을 못 없애나?
3. (그림) 의도 락(IS·IX)은 왜 필요한가? MySQL 8.4 InnoDB에서 `SELECT ... FOR UPDATE`가 테이블과 행에 각각 무엇을 거는지, 의도 락끼리는 왜 충돌하지 않는지 설명하라.
4. (경계) PostgreSQL 17의 `ROW EXCLUSIVE` 모드는 행 락인가? 보통 `SELECT`를 막는 테이블 락 모드는 무엇인가? 키를 바꾸지 않는 `UPDATE`가 외래 키 검사와 충돌하지 않는 이유는?
5. (연결) PostgreSQL과 InnoDB는 행 락을 각각 어디에 기록하나? 그래서 PostgreSQL `pg_locks`에서 행 대기는 어떤 모양으로 보이나?
6. (예측) PostgreSQL 17 기본 설정에서 두 트랜잭션이 행 두 개를 반대 순서로 갱신한다. 오류는 대략 언제, 어느 쪽에, 어떤 SQLSTATE로 나오나? 같은 일을 MySQL 8.4에서 하면 무엇이 다른가?
7. (장애 진단) MySQL에서 한 요청이 50초 멈췄다 `ERROR 1205`로 실패했고, 나중에 데이터가 반만 반영된 것이 발견됐다. 왜 반만 반영될 수 있나? 1213과 롤백 범위는 어떻게 다른가?
8. (장애 진단) PostgreSQL에서 "빠른" `ALTER TABLE ... ADD COLUMN` 배포 직후 그 테이블의 모든 `SELECT`가 멈췄다. 락 큐 관점에서 원인을 설명하고 대처를 대라.
9. (설계) 이체 코드의 교착을 SQL과 Spring 재시도로 고쳐라. 재시도는 왜 트랜잭션 **바깥**에서 해야 하나?
10. (경계) wait-die와 wound-wait는 탐지와 무엇이 다른가? DB 탐지기가 끝내 못 찾는 교착은 어떤 것인가?
