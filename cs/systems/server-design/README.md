## 읽는 순서

**처음이라면**: 01 → 05 → 06 → 10\
이 4개가 뼈대다. 01(왜), 05(가용성 구조), 06(전파 차단), 10(실전).

**문제가 있는 상태라면**: **10번부터.** 증상으로 찾아가서 해당 개념 문서로 이동.

**설계 리뷰 중이라면**: 11번(안티패턴) + 각 문서 말미의 체크리스트.

## 전체 지도

```text
                    ┌─ 01 기본 원리 (병목·Little's Law·USL·무상태)
                    │
   [확장성] ────────┼─ 02 요청 경로 (LB·게이트웨이·앱)
                    ├─ 03 데이터 계층 (복제·샤딩·CQRS)   ← 최종 난이도
                    ├─ 04 캐시
                    └─ 07 비동기 (부하 평탄화)

                    ┌─ 05 토폴로지 (이중화·failover·쿼럼)
   [가용성] ────────┼─ 06 복원력 (타임아웃·서킷·벌크헤드)  ← 실제 장애의 대부분
                    └─ 08 배포/운영 (변경이 가용성을 깎는다)

   [공통 기반] ─────── 09 용량·SLO (숫자로 말하기)

   [실전] ─────────┬─ 10 증상별 플레이북
                   └─ 11 안티패턴
```

이 지도가 컬렉션의 뼈대다.\
확장성 계열(01·02·03·04·07)은 "더 많은 부하를 어떻게 받나", 가용성 계열(05·06·08)은 "죽어도 어떻게 계속되나"를 다룬다.\
09는 두 계열의 공통 기반(숫자), 10·11은 그 위에 세운 실전 카탈로그다.

## 핵심 원칙 10개 (이것만은)

1. **확장은 병목을 없애는 게 아니라 옮기는 것이다.** 지금 병목이 어디인지 말할 수 있어야 한다.
2. **가능한 한 앞 계층에서 끝낸다.** 뒤로 갈수록 비싸고 확장이 어렵다.
3. **상태를 앱에서 밀어낸다.** 확장의 최종 난이도는 항상 데이터 계층에 있다.
4. **타임아웃이 없으면 다른 모든 복원력 장치가 무의미하다.**
5. **재시도는 장애를 증폭시킨다.** 백오프 + 지터 + 예산, 한 계층에서만.
6. **가용성은 의존성마다 곱셈으로 떨어진다.** 그래서 격리(벌크헤드)가 필수.
7. **이중화했으면 용량도 (N−1)/N로.** 안 그러면 이중화가 연쇄 장애 장치가 된다.
8. **테스트하지 않은 복원력은 복원력이 아니다.** failover·백업 복원·캐시 다운을 실제로 해본다.
9. **가용성을 가장 많이 깎는 건 하드웨어 고장이 아니라 변경이다.** 롤백 가능성이 곧 MTTR.
10. **장애 시 완화가 진단보다 먼저다.**
