# cs/systems/call-stack — 콜 스택과 ESP 동작 방식

> 함수 호출 시 스택 메모리가 어떻게 확보·사용·해제되는가 — ESP 기준 어셈블리 예제로 정리.
> 원고: 내가 직접 쓴다. Claude 추가분은 요청 시 [Claude 추가] 절로 분리.

<!-- 여기부터 원고 -->
기본적인 동작 방식을 보면,
```text
_MyFunc:
    subl $8, %esp
    movl $456, 4(%esp)
    movl $123, (%esp)
    calll _AddNum
    addl $8, %esp
    ret
```
1. subl $8, %esp
->즉 ESP를 8만큼 감소시킨다.
```text
기존 ESP
   ↓
+-----------+
|           |
+-----------+
```
여기서
ESP -= 8 이걸 만나서,
```text
높은 주소
-----------------
기존 데이터
-----------------
       ↑ 이전 ESP

새로운 ESP
       ↓
+-----------+ ← (%esp)
| 4바이트   |
+-----------+
| 4바이트   |
+-----------+ ← 4(%esp)

낮은 주소
```
이렇게 8바이트가 현재 함수가 사용할 스택 공간이 된다.

2. 값 저장
```text
movl $123, (%esp)
movl $456, 4(%esp)
```
이걸보면
ESP를 기준으로
```text
ESP
│
├──123
└──456
```
이렇게 32비트 정수 두 개가 저장된다.

3. call _AddNum
```text
call _AddNum
```
여기서
call이 리턴 주소를 스택에 하나 더 push한다 즉
```text
리턴 주소
123
456
```
이렇게 되고 _AddNum은 이 스택을 이용해 인자를 읽는다.

4. addl $8, %esp
함수가 끝났으므로,
```text
ESP += 8
```
를 통해
즉
```text
subl $8, %esp
```
와

```
addl $8, %esp
```

는 한 쌍이다.

이때 왜 굳이 addl을 통해 다시 ESP를 반납할까?
만약 
```text
subl $8, %esp
```
만 하게 되면 ESP가 계속 아래로 내려가기만 해서 스택이 망가진다.
그래서 함수가 자신이 사용한 스택은 반드시 원래대로 복구 해야된다.
```text
ESP
 ↓
1. 8바이트 확보
 ↓
2. 123, 456 저장
 ↓
3. AddNum 호출
 ↓
4. 8바이트 반납
 ↓
5. ret
```
이 된다.
즉 이러한 미사용 영역은 운영체제가 비워둔 메모리라는 뜻이 아닌 현재 함수가 아직 사용하지 않고 있던 스택의 빈 공간이다.

결국 ESP가 현재 스택의 맨 위를 가리키고 있다

스택의 구조를 보면
```text
높은 주소
+----------------+
| 이전 함수 데이터 |
+----------------+
| 지역 변수       |
+----------------+
| 리턴 주소       |
+----------------+
↑
ESP (현재 스택의 최상단)

낮은 주소
```
이와 같은 구조인데
여기서 sub $8, %esp 이걸 사용하게 되면
```text
높은 주소
+----------------+
| 이전 함수 데이터 |
+----------------+
| 리턴 주소       |
+----------------+
|                |
+----------------+
|                |
+----------------+
↑
ESP
```
이렇게 새로 생긴 8바이트가 현재 함수가 마음대로 사용할 수 있는 공간이 된다.
그래서
```text
movl $123, (%esp)
movl $456, 4(%esp)
```
처럼 데이터를 저장하고,
연산이나 함수 호출이 끝나면
```text
add $8, %esp
```
를 통해 ESP를 원래 위치로 돌려놓는 것이다.

즉 1줄 요약을 하면
"기존에 이미 존재하던 스택 메모리 중 아직 사용하지 않던 영역을 '이제부터 내가 쓰겠다'고 ESP를 이동시켜 예약하는 것"

여기서 스택과 힙의 위치 관계를 정리할 필요가 있다.
일반적으로 프로세스의 메모리는 보통
```text
높은 주소 (0xFFFFFFFF)
┌──────────────────┐
│      Stack       │  ← 함수 호출, 지역 변수
│      ↓↓↓         │  아래 방향으로 성장
├──────────────────┤
│                  │
│   (빈 공간)      │
│                  │
├──────────────────┤
│      Heap        │  ← malloc, new
│      ↑↑↑         │  위 방향으로 성장
├──────────────────┤
│   Data/BSS       │  ← 전역 변수
├──────────────────┤
│      Text        │  ← 실행 코드
└──────────────────┘
낮은 주소 (0x00000000)
```
이러한 구조로 되어있고,
```text
sub $8, %esp
```
를 하면
```text
이전 ESP
    │
    ▼
+---------+
|         |
+---------+

↓

ESP -= 8

새 ESP
    │
    ▼
+---------+ ← 내가 사용할 8바이트
|         |
+---------+
|         |
+---------+
이전 ESP
```
즉 
ESP가 아래로 이동하면서,
ESP와 이전 ESP 사이의 8바이트가 현재 함수의 작ㅇ버 공간이 된다.
여기서 중요한 것은 힙은 이 작업과 직접 관련이 없다.
