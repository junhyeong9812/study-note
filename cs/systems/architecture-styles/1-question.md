# 아키텍처 스타일과 패턴 — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,
> 막히면 [2-summary.md](2-summary.md)를 힌트로 연다. (정답 파일 `3-answer.md`는 아직 없다 — 사용자 검토 후 확정한다.)
> 정답까지 봤던 질문은 아래 복습 기록에 "틀림"으로 표시한다.

> 질문 하나 = "?" 하나 = 한 줄. 세부 암기가 아니라 지도 수준(왜·예측·경계·연결·판단)으로 묻는다.

## 질문

**1. (연결)** 아키텍처 스타일 · 아키텍처 패턴 · 디자인 패턴은 어떻게 다른가? 마이크로서비스 · Saga · Command로 예를 들어 세 층의 추상화 레벨을 구분하라.

**2. (연결)** 모놀리식과 분산형은 배타적 선택인가? 한 시스템 안에서 섞일 수 있는가?
   - 힌트: 분산형은 **시스템 레벨**, 레이어드·헥사고날은 **애플리케이션 레벨** 이야기다.

**3. (경계)** 서비스 기반 아키텍처와 마이크로서비스를 가르는 **결정적 차이 하나**는 무엇인가? 그 하나가 트랜잭션·정합성·결합을 어떻게 바꾸는가?

**4. (경계)** **분산 모놀리스**란 무엇이고, 어떻게 알아채는가? 왜 "최악의 조합"이라 부르는가?
   - 힌트: 서비스를 하나만 따로 배포할 수 없다면 이미 그것이다.

**5. (판단)** "MSA를 쓰는 이유"로 자주 언급되는 것들(모듈 분리·팀 분리·도메인 경계·기술 부채 격리) 중 실제로는 **잘 나뉜 모놀리식으로도 되는 것**은 무엇인가?

**6. (판단)** 어떤 시스템에서 **서비스 기반(DB 공유)이 마이크로서비스보다 더 맞을** 가능성은 언제인가? 무엇을 재료로 그렇게 판정하는가?

**7. (판단)** 소규모 팀·개발자(극단적으로 1인)라는 제약에서 MSA의 대가는 얼마나 커지는가? 어느 대가가 팀 크기에 가장 민감한가?

**8. (판단)** 강한 일관성을 요구하는 도메인(예: 결제·원장)과 이벤트 기반의 결과적 일관성은 어떻게 공존시키는가?
   - 힌트: 모든 것에 결과적 일관성을 쓰지 않는다 — 승인 판단은 강하게, 알림·집계는 결과적으로.

**9. (예측)** 아키텍처 스타일을 나중에 바꿀 수 있는가? 바꾸는 비용은 무엇에 비례하는가?
   - 힌트: 데이터 소유권의 분리 정도.

**10. (왜)** 레이어드의 **의존 방향 문제**란 무엇이며, 헥사고날·클린 아키텍처는 그것을 어떻게 뒤집는가?

**11. (경계)** 싱크홀 안티패턴이란 무엇인가? "층이 과하다"고 판정하는 경험칙 수치는?

**12. (예측)** 마이크로커널에서 코어 계약(인터페이스)을 잘못 그으면 무슨 일이 벌어지는가? 이 스타일이 유효한 전제 조건은 무엇인가?

**13. (연결)** 이벤트 기반의 **브로커 토폴로지**와 **중재자 토폴로지**는 무엇이 다른가? 각각 코레오그래피/오케스트레이션 중 무엇에 해당하는가?

**14. (왜)** 이벤트 기반은 왜 디버깅이 극도로 어려워지는가? 그래서 무엇이 "선택이 아니라 필수"가 되는가?

**15. (판단)** 공간 기반 아키텍처는 무엇을 맞바꿔 극한의 확장성을 얻는가? 금융 원장 같은 정확성 우선 시스템에 왜 대체로 부적합한가? 부분 적용은 어디에 가능한가?

**16. (왜)** SOA는 왜 쇠퇴했다고 평가받는가? 거기서 나온 "덤 파이프, 스마트 엔드포인트" 교훈은 무엇을 경계하라는 말인가?

**17. (예측)** 잘 만든 API Gateway가 시간이 지나 "새로운 ESB"로 변질되는 징후는 무엇인가? 그것을 막으려면 게이트웨이의 역할을 어디까지로 제한해야 하는가?

**18. (판단)** 마이크로서비스에서 "중복 허용"은 무엇을 위한 것인가? 이것이 비중복(N)과 느슨한 결합(L)의 충돌을 어느 쪽으로 푸는 결정인가?

**19. (예측)** "모놀리스 우선(Monolith First)"이 널리 권장되는 이유는? 잘못 그은 서비스 경계가 왜 모놀리식보다 고치기 어려운가?

**20. (경계)** 모놀리식과 분산의 트레이드오프를 축(확장·정합성·격리·운영 난이도·가시성)별로 대보라. 시스템의 품질 우선순위가 결론을 어떻게 좁히는가?
