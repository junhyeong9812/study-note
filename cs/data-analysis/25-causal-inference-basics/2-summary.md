# data-analysis/25-causal-inference-basics — 인과 추론 기초: 인과 DAG·교란 통제·차분의 차분·도구 변수 — 정리 (힌트)

## 해결하는 문제

A/B 테스트([14](../14-ab-testing-design/2-summary.md))를 못 하는 질문이 많다. 이미 지난 정책, 일부 지역에만 적용한 변경, 사용자가 스스로 고른 기능.

```text
  "푸시 알림을 받은 사용자가 더 구매한다"  (관찰 데이터)
     ↑ 원래 활발한 사용자가 알림도 켜고 구매도 많다 (교란)
  → 회귀에 변수를 "많이 넣으면" 해결될까?
     넣어야 할 변수(교란)도 있고, 넣으면 안 되는 변수(매개·충돌)도 있다
```

- 무엇을 통제할지는 데이터가 아니라 **원인 구조에 대한 가정**이 정한다. 그 가정을 그림으로 적은 것이 인과 DAG다.
- DAG로 "이 변수를 통제하면 편향이 줄어드나, 생기나"를 기계적으로 판정할 수 있다.
- 통제할 변수를 못 재면 다른 설계를 쓴다. 전후 × 처리/비처리 비교(차분의 차분), 무작위에 가까운 외부 요인(도구 변수).

쉬운 예: "병원에 간 사람이 더 아프다"를 보고 병원이 병을 만든다고 결론 내지 않는다. 아파서 병원에 간다.

똑같은 구조다.\
변수 사이 화살표의 방향을 먼저 적고, 그 그림에서 어느 길을 막아야 하는지 따진다.

실무 예:
- "프리미엄 기능을 쓰는 고객의 매출이 높다" → 기능 효과인가, 원래 큰 고객이 기능을 쓰나.
- 서울 지점에만 새 배송 정책을 도입했다 → 서울의 원래 추세와 정책 효과를 가르기.
- A/B 테스트에서 "처리를 실제로 쓴 사람만" 분석 → 사용 여부가 결과와 엮여 편향.

## 동작·원리

### 1. 인과 DAG — 세 가지 기본 모양

```text
  사슬(chain)        X → M → Y      M = 매개: X의 효과가 M을 거쳐 Y로 간다
  분기(fork)         X ← Z → Y      Z = 교란: X와 Y의 공통 원인
  충돌(collider)     X → C ← Y      C = 충돌: X와 Y가 함께 C를 만든다

  통제(조건부) 하면     사슬: 막힘    분기: 막힘    충돌: 열림 (!)
  통제 안 하면          사슬: 열림    분기: 열림    충돌: 막힘
```

- *DAG(방향 비순환 그래프)*: 화살표에 방향이 있고 순환이 없는 그래프. 인과 DAG에서 화살표 `A → B`는 "A가 B의 원인 중 하나"라는 가정이다.
- Pearl·Glymour·Jewell, 『Causal Inference in Statistics: A Primer』(2016) 2.2(사슬·분기)·2.3(충돌)이 이 세 모양을 다룬다.
  - 충돌 변수를 조건부로 보면, 원래 독립이던 두 부모가 의존하게 된다. 충돌 변수의 **자손**을 조건부로 봐도 그렇다(Primer 2.3).
- 경로가 "열려" 있으면 그 경로를 따라 X와 Y 사이에 연관이 흐를 수 있다. 대부분은 실제로 의존하지만, 효과가 정확히 상쇄되는 예외가 있어 "열림 = 반드시 연관"은 아니다(Primer 2.4와 그 각주). 반대로 모든 경로가 막히면(d-분리) 독립이 보장된다. 인과 효과를 보려면 X → … → Y 방향의 길만 열어 두고, 나머지 길은 막는다.

### 2. 뒷문 기준 — 무엇을 통제하나

- Primer 정의 3.3.1(뒷문 기준): DAG에서 변수 집합 Z가 (X, Y)에 대해 뒷문 기준을 만족한다는 것은 다음 둘이다.
  - Z의 어떤 노드도 X의 자손이 아니다.
  - Z가 X로 **들어오는** 화살표를 가진 X–Y 경로를 모두 막는다.
- 그러면 `P(Y=y | do(X=x)) = Σ_z P(Y=y | X=x, Z=z) P(Z=z)`로 인과 효과를 관찰 데이터에서 구한다(같은 절의 조정 공식).
  - 조건: 관련된 z마다 X=x인 사례가 실제로 있어야 한다(`P(X=x | Z=z) > 0`, *양성성*). 어떤 z에서 모두 처리받았다면 그 z의 `P(Y | X=비처리, Z=z)`를 데이터로 구할 수 없다(What If 기술 노트 2.3).
  - *do(X=x)*: X를 x로 "개입해 정한" 상황. 그냥 X=x인 사람을 고른 것(관찰)과 다르다.
  - *뒷문 경로*: X로 들어오는 화살표로 시작하는 X–Y 경로. `X ← Z → Y`가 대표다.
- 같은 절은 통제할 집합이 지켜야 할 것을 셋으로 요약한다: 가짜 경로를 모두 막는다, X → Y 방향 경로는 건드리지 않는다, 새 가짜 경로를 만들지 않는다.
  - 매개 변수(X의 자손)를 통제하면 둘째를 어긴다. 충돌 변수(또는 그 자손)를 통제하면 셋째를 어긴다.

### 실험: 교란·매개·충돌을 통제하면 — 회귀 계수

선형 합성 데이터에서 참 인과 효과 X → Y를 1.0(매개 예는 전체 효과 1.0)으로 두고, 무엇을 회귀에 넣느냐에 따라 X의 계수가 어떻게 되나 봤다.

```python
# scratchpad/da/14/e25a_dag.py 핵심 (n = 20,000, seed 25)
Z = [g(0,1)]; X = [2*z + g(0,1)]; Y = [1.0*x + 3*z + g(0,1)]          # (1) 교란
X = [g(0,1)]; M = [2*x + g(0,1)]; Y = [0.5*m + g(0,1)]                # (2) 매개
X = [g(0,1)]; Y = [1.0*x + g(0,1)]; C = [x + y + g(0,1)]              # (3) 충돌
X = [g(0,1)]; Y = [g(0,1)]; 합격 = X + Y > 1.5                         # (4) 효과 0 + 충돌로 선택
```

(시뮬레이션, 호스트 Python 3.12.3, 정규방정식은 가우스 소거로 직접 풂, seed 25)

```text
(1) 교란 Z→X, Z→Y   : Y~X 기울기 2.202 | Y~X+Z 의 X 계수 1.004
(2) 매개 X→M→Y      : Y~X 기울기 1.020 | Y~X+M 의 X 계수 0.025
(3) 충돌 X→C←Y      : Y~X 기울기 1.005 | Y~X+C 의 X 계수 -0.006
(3') C>1 인 행만 분석 : Y~X 기울기 0.535  (남은 행 6847 / 20000)
(4) 독립인 X,Y      : 전체 상관 0.014 | 합격자(X+Y>1.5)만 상관 -0.676 (2862명)
```

- (1) 교란: Z를 빼면 2.20(이론값 `1 + 3·Cov(Z,X)/Var(X) = 1 + 3·2/5 = 2.2`). Z를 넣으면 1.00. **통제해야 한다.**
- (2) 매개: X만 넣으면 전체 효과 1.02. M을 넣으면 0.03 — X의 효과가 전부 M을 거치므로 "M을 고정하면" 남는 것이 없다. 전체 효과를 묻는다면 **통제하면 안 된다.**
- (3) 충돌: X만 넣으면 1.01. C를 넣으면 −0.01 — 효과가 사라진 것처럼 보인다. C > 1인 행만 남겨도(선택) 0.54로 줄었다. **통제·선택하면 안 된다.**
- (4) 실제로는 관계가 없는 X·Y도, 둘의 합으로 뽑힌 사람만 보면 상관 −0.68이 생긴다. "합격자 중에서는 재능과 운이 반비례한다" 같은 착시다.

### 실험: DAG에서 경로를 찾아 막힘을 판정 (그래프 탐색)

위 판단을 손으로 하지 않고 그래프 알고리즘으로 했다. 모든 X–Y 경로를 DFS로 찾고, 각 경로가 조정 집합에 의해 막히는지 판정한다.

```text
  Z(활동성) ─→ X(푸시 수신) ─→ M(앱 방문) ─→ Y(구매)
     └──────────────────────────────────────→ Y
               X ─→ C(고객센터 문의) ←─ Y      C ─→ D(문의 후 쿠폰)
```

```python
# scratchpad/da/14/e25b_paths.py 핵심 — 경로 위 각 중간 노드 v의 규칙 (Primer 2.4 d-분리)
collider = (a in par[v]) and (b in par[v])          # 앞뒤 화살표가 모두 v로 들어온다
if collider:
    if v not in Z and not (desc(v) & Z): return "막힘"   # 충돌: 자신도 자손도 통제 안 했으면 막힘
elif v in Z: return "막힘"                          # 사슬·분기: 통제하면 막힘
```

(실행, 호스트 Python 3.12.3. 이웃을 정렬해 탐색 — 문자열 `set`의 순서는 실행마다 다를 수 있어 출력 순서를 고정했다)

```text
조정 집합 {}:
   X → C ← Y                    비인과     막힘 C(충돌, 미통제)
   X → M → Y                    인과      열림
   X ← Z → Y                    뒷문      열림
조정 집합 ['Z']:
   X → C ← Y                    비인과     막힘 C(충돌, 미통제)
   X → M → Y                    인과      열림
   X ← Z → Y                    뒷문      막힘 Z(통제됨)
조정 집합 ['M', 'Z']:
   X → C ← Y                    비인과     막힘 C(충돌, 미통제)
   X → M → Y                    인과      막힘 M(통제됨)
   X ← Z → Y                    뒷문      막힘 Z(통제됨)
조정 집합 ['C', 'Z']:
   X → C ← Y                    비인과     열림
   X → M → Y                    인과      열림
   X ← Z → Y                    뒷문      막힘 Z(통제됨)
조정 집합 ['D', 'Z']:
   X → C ← Y                    비인과     열림
   X → M → Y                    인과      열림
   X ← Z → Y                    뒷문      막힘 Z(통제됨)
```

- `{Z}`만이 뒷문을 막고, 인과 경로는 열어 두고, 비인과 경로를 막힌 채로 둔다. 이 그래프에서 전체 효과를 위한 조정 집합이다.
- `{Z, M}`은 인과 경로까지 막는다. `{Z, C}`와 `{Z, D}`는 막혀 있던 충돌 경로를 연다. D는 C의 자손이라 D만 통제해도 열린다.
- 이 판정은 그래프 단위의 간단 버전이다. 모든 경로를 나열하므로 노드가 많으면 경로 수가 폭증한다. 실제 도구는 경로를 나열하지 않는 탐색으로 판정한다. 예: NetworkX의 d-분리 구현은 Darwiche(2009)의 선형 시간 알고리즘에 기반한다고 문서에 적혀 있다(https://networkx.org/documentation/stable/reference/algorithms/d_separation.html).

### 3. 차분의 차분(DiD) — 측정 못 한 차이를 전후 변화로 지운다

```text
  주문 수 (예시)   처리 전   처리 후    변화
  서울(처리)        100   →   108      +8   = 계절(+5) + 정책(+3)
  지방(비처리)       70   →    75      +5   = 계절(+5)
                                     ────
  DiD = (+8) − (+5) = +3   ← 수준 차이(100 vs 70)와 공통 계절 효과가 함께 지워진다

  전제(평행 추세): 정책이 없었다면 서울도 지방과 같은 만큼(+5) 변했을 것
```

- Hernán·Robins 『Causal Inference: What If』 기술 노트 7.3: 차분의 차분은 처리 전 결과를 "음성 대조 결과"로 쓰는 방법의 특수한 경우다. 처리 효과(처리군에서) = (처리 후 그룹 차) − (처리 전 그룹 차). 전제는 **가법적 동일 교란**이다. 측정 못 한 교란이 만드는 처리군−비교군 평균 차이가, 처리 전 결과와 "처리가 없었다면의" 처리 후 결과에서 같아야 한다(더하기 척도, `E[Y⁰|A=1] − E[Y⁰|A=0] = E[C|A=1] − E[C|A=0]`, C = 처리 전 결과). 개인마다 같은 크기일 필요는 없다. 흔히 "평행 추세" 가정이라 부른다.
- 같은 노트: 결과를 처리 전후 모두 같은 척도로 재야 한다는 제약이 있다.

### 4. 도구 변수(IV) — 무작위에 가까운 "밀어주기"를 이용한다

```text
  Z (무작위 초대 메일) ──→ X (프리미엄 기능 사용) ──→ Y (구매)
                               ↑                      ↑
                               └────── U (열성도, 관측 안 됨) ──┘
  조건: ① Z가 X와 연관  ② Z는 X를 거쳐서만 Y에 영향  ③ Z와 Y의 공통 원인 없음
  추정(Wald): 효과 = [E(Y|Z=1) − E(Y|Z=0)] / [E(X|Z=1) − E(X|Z=0)]
```

- 세 조건은 What If 16.1에서 가져왔다. 같은 절의 예가 "무작위 배정 Z, 실제 복용 A"인 이중맹검 시험이다. A/B 테스트에서 "배정"과 "실제 사용"이 다를 때(배정받고도 안 쓴 사용자) 같은 구조다.
- ①은 데이터로 확인할 수 있다. ②·③은 데이터만으로 증명할 수 없는 가정이다. What If 16.1은 세 조건 중 경험적으로 확인할 수 있는 것은 (i)뿐이라고 적는다. 무작위 배정이면 ③이 기대된다(16.1).
- 세 조건만으로는 효과 하나가 정해지지 않는다. What If 16.3·16.4는 넷째 조건으로 동질성 또는 단조성을 든다. 동질성은 여러 형태가 있고, 가장 강한 형태가 "모든 사람의 효과가 같다"다(16.3). 단조성 아래에서 Wald 추정치는 "도구에 따라 처리 여부가 바뀐 사람들(compliers)"의 효과다.
- Wald 추정량은 X에 대한 Z의 효과(1단계)로 나눈다. 1단계가 작으면(약한 도구) 작은 수로 나눠 추정이 크게 흔들린다.

### 실험: DiD와 IV

(시뮬레이션, 호스트 Python 3.12.3, seed 7, DiD는 그룹·시점당 관측 500개, IV는 n = 50,000, 약한 도구는 부트스트랩 재표집 seed 100~104)

```text
DiD [평행 추세 성립] 참 효과 +3 | 사후 그룹 차  33.19 | 처리군 전후 차  8.08 | DiD  3.36
DiD [서울만 원래 +4 더 오르는 추세] 참 효과 +3 | 사후 그룹 차  37.00 | 처리군 전후 차 11.99 | DiD  7.14
IV  참 효과 0.5 | 단순 회귀 Y~X 1.418 | IV(Wald) 0.539 | 1단계 X 차이(Z=1−Z=0) 0.828
약한 도구(Z→X 0.02) 부트스트랩 5회 IV 추정: 6.81 3.12 1.96 1.66 2.63
```

- DiD 관찰 1: 사후 그룹 차(33)는 원래 수준 차이를, 처리군 전후 차(8)는 계절 효과를 포함한다. DiD는 3.36으로 참 효과 3에 가깝다. 관측 잡음 표준편차 5, 그룹·시점당 500개라 DiD의 표준오차는 약 0.45(= 2 × 5/√500)이고, 3.36은 그 1배 안이다.
- DiD 관찰 2: 서울이 원래 +4 더 오르는 추세였다면 DiD는 7.14다. 추세 차이 4가 효과로 섞였다. 평행 추세가 깨지면 DiD도 편향된다.
- IV 관찰 1: U 때문에 단순 회귀는 1.42(이론값 `0.5 + 2·Cov(X,U)/Var(X) = 0.5 + 2/2.16 ≈ 1.43`). Wald 추정은 0.54로 참값 0.5에 가깝다. 이 합성 데이터는 Z를 무작위로 만들고(조건 ③), Z가 X를 거쳐서만 Y에 들어가게 했으며(조건 ②), 효과를 모든 사람에게 0.5로 같게(동질성) 만들었다. 그래서 Wald 추정이 평균 효과를 겨눈다. 실제 데이터에서는 이 조건들이 가정이다.
- IV 관찰 2: 1단계가 0.02뿐인 약한 도구에서는 재표집할 때마다 1.66 ~ 6.81로 흔들렸다. 모두 참값 0.5와 멀다.
- 해석: 통제할 변수를 못 재도 설계(DiD·IV)로 효과를 구할 수 있다. 대신 각 설계의 가정(평행 추세, 도구 조건)이 결과를 떠받친다. 가정은 데이터 밖에서 정당화해야 한다.

## 적용 — 풀어나가는 법

### 1. 관찰 데이터로 "효과"를 물을 때 순서

1. 처리 X, 결과 Y, 시간 순서를 적는다. 처리 **이후**에 정해지는 변수(매개·충돌 후보)를 표시한다.
2. 아는 원인 구조를 DAG로 그린다. 측정 못 한 변수(U)도 그린다.
3. 뒷문 기준을 만족하는 조정 집합을 찾는다(위 경로 판정 코드처럼).
4. 그 집합이 전부 측정돼 있고 각 층에 처리·비처리가 모두 있으면(양성성) 조정(회귀·층화)으로 추정한다. 아니면 DiD·IV 같은 설계를 찾는다. 그것도 없으면 "인과 주장 불가"로 보고한다.
5. 가정을 문서에 남긴다. 결론은 그 가정 아래에서만 성립한다.

### 2. 증상 → 원리 → 확인

- 증상: 변수를 하나 더 넣었더니 효과가 사라졌다(또는 뒤집혔다).
  - 원리: 넣은 변수가 매개(효과를 가로챔)이거나 충돌(가짜 경로를 염)일 수 있다.
  - 확인: 그 변수가 처리 이후에 정해지나? 처리와 결과 둘 다의 영향을 받나? DAG에 그려 본다.
- 증상: A/B 결과를 "처리를 실제로 쓴 사용자"만으로 분석했더니 효과가 크게 나왔다.
  - 원리: "실제 사용"은 처리와 사용자 성향이 함께 정한다. 사용 여부로 거르면 선택 편향이다([15](../15-ab-pitfalls-srm-peeking/2-summary.md)의 처리 후 필터와 같은 구조).
  - 확인: 배정 기준(ITT) 효과를 먼저 본다. 실제 사용의 효과가 필요하면 배정을 도구로 쓴 IV(Wald)로 추정한다.
  - *ITT(intention-to-treat)*: 실제 사용과 관계없이 배정받은 대로 비교하는 분석.

### 3. SQL로 DiD (PostgreSQL 17)

```sql
-- daily_orders(region, day date, orders int), 정책 시작 2026-09-01, 처리 지역 'seoul'
SELECT
  (avg(orders) FILTER (WHERE region = 'seoul' AND day >= date '2026-09-01')
 - avg(orders) FILTER (WHERE region = 'seoul' AND day <  date '2026-09-01'))
 - (avg(orders) FILTER (WHERE region <> 'seoul' AND day >= date '2026-09-01')
 - avg(orders) FILTER (WHERE region <> 'seoul' AND day <  date '2026-09-01')) AS did
FROM daily_orders;
-- 평행 추세 점검: 정책 전 기간만으로 같은 질의를 "가짜 시작일"에 돌려 0 근처인지 본다
-- (합성 데이터 실행: did = 3.667, 가짜 시작일 8/16의 placebo = −0.223)
```

## 장애 시나리오와 대처

### 1. 매개 변수를 통제해 효과를 지웠다 (⚠ 커리큘럼)

- 현상: "푸시 알림은 구매에 효과가 없다"는 분석으로 알림 기능을 줄였다. 이후 구매가 줄었다.
- 보이는 형태: 회귀에 "앱 방문 수"를 통제 변수로 넣었더니 알림 계수가 0 근처(위 실험 0.03).
- 원인: 알림 → 방문 → 구매. 방문은 알림의 효과가 지나가는 길(매개)이다. 방문을 고정하면 알림의 효과를 스스로 지운다.
- 대처: 처리 이후에 정해지는 변수는 전체 효과 추정에서 통제하지 않는다. 직접 효과가 궁금하면 매개 분석을 별도 질문으로 세운다.

### 2. 충돌 변수로 통제·선택해 가짜 관계를 만들었다 (⚠ 커리큘럼)

- 현상: "고객센터에 문의한 고객 중에서는 알림 수신자가 오히려 구매가 적다"는 분석.
- 보이는 형태: 전체에서는 관계가 양(+)인데, 문의 고객으로 좁히면 음(−)이 된다. 위 실험의 합격자 선택에서는 독립인 두 변수 사이에 상관 −0.68이 생겼다.
- 원인: 문의는 알림(처리)과 구매 문제(결과) 둘 다의 영향을 받는 충돌 변수다. 그걸로 거르면 두 부모 사이에 가짜 연관이 생긴다. 충돌 변수의 자손(문의 후 쿠폰)으로 걸러도 같다.
- 대처: 분석 대상 필터와 통제 변수가 처리·결과 이후에 정해지는지 확인한다. DAG에서 경로를 판정한다.

### 3. 평행 추세가 깨진 DiD

- 현상: 서울 정책의 효과가 +7로 보고됐는데, 확대 적용한 지역에서는 +3이다.
- 보이는 형태: 정책 전 기간에도 서울이 지방보다 빨리 성장하고 있었다. 가짜 시작일 점검에서 0이 아닌 값이 나온다.
- 원인: DiD는 정책이 없었다면 두 그룹이 같이 움직였을 것이라는 가정에 기댄다(위 실험 3.36 → 7.14).
- 대처: 정책 전 여러 기간으로 추세를 비교한다. 비슷한 추세의 비교군을 고른다. 결과에 가정을 명시한다.

### 4. 약한 도구 변수

- 현상: IV 추정이 표본을 조금 바꿀 때마다 크게 달라진다.
- 보이는 형태: 1단계(도구 → 처리) 차이가 아주 작다. 위 실험에서 1단계 0.02일 때 추정이 1.66 ~ 6.81로 흔들렸다.
- 원인: 작은 1단계 효과로 나누면 분자의 잡음이 확대된다.
- 대처: 1단계의 크기와 불확실성을 먼저 보고한다. 약하면 IV 결론을 쓰지 않는다. 더 강한 밀어주기(예: 배정 비율·권유 강도)를 설계한다.

### 5. 관찰 데이터의 회귀 계수를 그대로 인과로 보고

- 현상: "프리미엄 기능을 쓰면 매출이 1.4배"라는 수치로 기능 사용을 강제하는 정책을 냈다. 효과가 훨씬 작았다.
- 보이는 형태: 기능 사용자는 원래 구매가 많은 열성 고객이다. 회귀 계수(1.42)가 IV 추정(0.54)의 약 2.6배(위 실험의 구조).
- 원인: 측정 못 한 교란(열성도)이 기능 사용과 매출을 같이 올린다.
- 대처: 무작위 실험을 먼저 검토한다. 못 하면 DAG로 교란을 적고, 측정 가능한 교란은 통제하고, 못 재는 교란은 설계(IV·DiD)나 민감도 분석으로 다룬다.

## 핵심 문장

- 무엇을 통제할지는 데이터가 아니라 원인 구조의 가정이 정한다. 그 가정을 DAG로 적는다.
- 교란(분기)은 통제해 막는다. 매개(사슬)를 통제하면 효과를 지우고, 충돌을 통제·선택하면 없던 관계가 생긴다.
- 뒷문 기준: X의 자손이 아닌 변수로, X로 들어오는 경로를 모두 막는다.
- 차분의 차분은 측정 못 한 수준 차이를 지우지만, 평행 추세 가정이 깨지면 그 차이가 효과로 섞인다.
- 도구 변수는 교란을 못 재도 효과를 구하지만, 도구 조건은 데이터로 증명할 수 없고 약한 도구는 추정을 크게 흔든다.
