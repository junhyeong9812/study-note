# data-analysis/10-power-and-sample-size — 검정력·최소 탐지 효과·표본 크기 — 정리 (힌트)

## 해결하는 문제

두 팀이 같은 실수를 반대 방향으로 했다.

```text
  팀 A: 군당 2,000명으로 2주 돌림 → "유의하지 않음" → 기능 폐기
        (진짜 효과 +1%p였다. 이 설계로는 17%만 잡힌다 — 실험 D)
  팀 B: "상대 1% 개선도 잡자" → 필요한 표본이 군당 142만 명 → 하루 5천 명이면 284일
        (실험 C — 끝나지 않는 실험)
```

- 실험을 시작하기 **전에** "어떤 크기의 효과를, 어느 확률로 잡고 싶은가"를 정하지 않아서 생기는 일이다(⚠ 커리큘럼: 검정력 부족 → "효과 없음" 오결론, 너무 작은 효과 추적 → 영원히 안 끝나는 실험).
  - *검정력(power)*: 진짜 효과(정해 둔 크기)가 있을 때 검정이 그것을 잡아낼(H0를 기각할) 확률(OpenIntro 7.4.2). β를 2종 오류 확률이라 하면 `1 − β`다([09](../09-hypothesis-testing/2-summary.md) 2절).
  - *최소 탐지 효과(minimum detectable effect, MDE)*: 설계가 잡도록 목표로 삼은 가장 작은 효과. OpenIntro는 "관심 있는 최소 효과 크기(minimum effect size of interest)"라고 부른다(7.4.2).

쉬운 예: 어두운 방에서 손전등으로 바늘을 찾는다.
- 바늘이 작을수록(효과가 작을수록) 더 밝은 손전등(더 많은 표본)이 필요하다.
- 손전등이 약하면 바늘이 있어도 "없다"고 말하게 된다.
- 머리카락 한 올까지 찾겠다고 하면 손전등을 영원히 키워야 한다.

똑같은 구조다.\
바늘 크기 = MDE, 손전등 밝기 = 표본 크기, 찾을 확률 = 검정력이다.

실무 예:
- 카나리를 그룹당 200건만 보고 판정했더니 오류율이 두 배인 판도 약 4분의 1만 잡혔다([testing/19-testing-in-production](../../testing/19-testing-in-production/2-summary.md)).
- 트래픽이 적은 B2B 서비스에서 전환율 A/B를 몇 달째 돌리고 있다.
- "유의했던" 작은 실험들만 모아 보니 효과가 모두 크게 나왔다. 확대 적용하니 효과가 줄었다(실험 D).

## 동작·원리

### 1. 두 분포 사이의 거리 — α·β·검정력

```text
            대립 분포 (진짜 차이 = δ)          귀무 분포 (차이 0)
                 ▁▂▄▆█▆▄▂▁                       ▁▂▄▆█▆▄▂▁
        ░░░░░░░░░░░░░░░░░░|▒▒▒▒▒▒                ......|▓
        ← 검정력(1−β) ────→| β ─→                       |α/2
                          기각 경계 = 0 − 1.96·SE
        ├──── δ ────────────────────────────────────────┤
              δ = (z_{α/2} + z_β) · SE = (1.96 + 0.84) · SE = 2.8 · SE   (α 0.05 양측, 검정력 80%)
```

- 귀무 분포의 끝 α/2 지점이 기각 경계다. 대립 분포에서 그 경계 너머의 넓이가 검정력이다(OpenIntro 7.4.2).
  - 양측 검정은 반대쪽 기각역에서도 기각한다. 엄밀한 기각 확률은 두 기각역 넓이의 합이고, 그림과 `2.8·SE` 계산은 반대쪽을 뺀 근사다. OpenIntro 7.4.2도 반대쪽을 일부러 무시한다(혈압 예제에서 약 0.0001, 계산). 실험 D의 17.2%는 양쪽을 모두 센 값이다.
- 검정력 80%·α 0.05면 두 분포 중심 사이가 SE의 약 2.8배여야 한다(OpenIntro 7.4.3). 90%·α 0.01이면 2.58+1.28 ≈ 3.86배다(OpenIntro Guided Practice 7.38의 답 3.86·SE, 정밀한 z로 3.857).
  - *β*: 2종 오류 확률. 검정력 = 1 − β.
- 검정력을 올리는 손잡이는 네 개다.
  1. 효과 δ가 크다(설계로 바꿀 수 없음 — 목표로 정한다).
  2. SE를 줄인다: 표본 n을 늘리거나 개별 값의 분산 σ²를 줄인다.
  3. α를 키운다(1종 오류가 늘어난다).
  4. 단측 검정(방향을 미리 정한 경우에만, [09](../09-hypothesis-testing/2-summary.md) 장애 4).

### 2. 표본 크기 공식 — 거꾸로 풀기

두 그룹 평균 차이(군당 n, 각 군 표준편차 σ):

```text
  SE = √(σ²/n + σ²/n) = σ·√(2/n)
  δ = (z_{α/2} + z_β) · σ·√(2/n)
  ⇒  n = 2 · (z_{α/2} + z_β)² · σ² / δ²        (군당)
```

- 두 비율(p1 → p2): `n = (z_{α/2} + z_β)² · (p1(1−p1) + p2(1−p2)) / (p2 − p1)²`(군당). 두 군의 분산을 각각 쓴 정규 근사식이다.
  - 아래 `sim_power`의 검정은 귀무 아래 합동 비율 p̄로 SE를 낸다. 이 검정에 맞추려면 귀무 분산 `2p̄(1−p̄)`과 대립 분산 `p1(1−p1)+p2(1−p2)`를 나눠 `n = (z_{α/2}·√(2p̄(1−p̄)) + z_β·√(p1(1−p1)+p2(1−p2)))² / (p2 − p1)²`로 쓴다. 10% → 11%에서는 14,751로 위 식(14,749)과 거의 같다(계산).
- **n은 δ²에 반비례한다.** MDE를 절반으로 줄이면 표본이 4배 든다.
- 검정력 80% → 90%로 올리면 `((1.96+1.28)/(1.96+0.84))²` ≈ 1.34배가 든다(계산).
- α 0.05·검정력 80%이면 `2·(1.96+0.84)²` ≈ 15.7이라, 평균 차이의 군당 n ≈ `16σ²/δ²`로 어림할 수 있다(계산). Kohavi 외 2020에 같은 형태의 경험식이 있다 `[?]`(본문 미확인).
- 공식은 정규 근사다. 평균 차이 공식에서 σ를 표본으로 추정하는데 계산된 n이 작으면(대략 30 이하) t 분포로 다시 계산하고, 보통 조금 더 커진다(OpenIntro 7.4.3).
- 비율 공식에는 t를 쓰지 않는다. 각 군의 기대 성공·실패 건수가 충분한지(OpenIntro 6.2.1 성공-실패 조건, 10건 이상) 보고, 모자라면 정규 근사 대신 이항 분포로 시뮬레이션한다.

### 3. 실험 A — OpenIntro 7.4 혈압 예제를 다시 계산

(σ = 12 mmHg, 최소 효과 3 mmHg, α 0.05 양측, 정규 근사, Python `NormalDist`)

| 군당 n | SE | 기각 경계 | 검정력 |
|---|---|---|---|
| 100 | 1.70 | ±3.326 | 0.424 |
| 251 | 1.07 | ±2.099 | 0.800 |
| 500 | 0.76 | ±1.488 | 0.977 |

- OpenIntro: n=100에서 약 42%, n=500에서 97.7%, 80%를 위한 n은 250.88 → 251(7.4.2·7.4.3). 위 계산과 일치한다.
  - OpenIntro는 z를 0.84·1.96으로 반올림해 250.88, 정밀한 z로는 251.2다(실험 A 출력).
- n=100에서 진짜 효과가 3 mmHg여도 "유의하지 않음"이 58%다. OpenIntro 7.4.3은 이것을 "매우 나쁜 상황"이라 부른다 — 효과가 있는지 없는지 둘 다 말할 수 없다.

### 4. 실험 B — 비율 공식 vs 시뮬레이션

(전환율 10% → 11%, α 0.05 양측, 검정력 80% 목표 → 공식 군당 n = 14,749. 시뮬레이션은 `random.binomialvariate`, 반복 4000, seed 31)

```text
  군당 n     시뮬레이션 검정력
   3,687    ███████▏                28.8%   (n/4)
   7,374    ████████████▋           50.5%   (n/2)
  14,749    ███████████████████▋    78.8%   (공식 n)
  29,498    ████████████████████████▍ 97.5% (2n)
```

- 공식(정규 근사)이 시뮬레이션과 거의 맞았다(80% 목표 → 78.8%).
- 표본을 절반으로 줄이면 검정력은 절반이 아니라 50.5%로, 4분의 1이면 28.8%로 떨어진다.

### 5. 실험 C — MDE를 줄이면 n은 제곱으로 는다

(기준 전환율 10%, α 0.05 양측, 검정력 80%. 하루 군당 5,000명 유입은 예시 가정)

| 상대 개선 | 목표 전환율 | 군당 n | 기간(예시) |
|---|---|---|---|
| +10% | 11.00% | 14,749 | 2.9일 |
| +5% | 10.50% | 57,760 | 11.6일 |
| +2% | 10.20% | 356,332 | 71.3일 |
| +1% | 10.10% | 1,419,070 | 283.8일 |

- MDE를 10분의 1로 줄이면 n은 약 100배다.
- 기간은 표본 수만의 문제가 아니다. 요일 효과를 덮으려면 최소 한 주 단위로 돌리는 식의 제약이 따로 있다 → [14-ab-testing-design](../14-ab-testing-design/2-summary.md).

### 6. 실험 D — 검정력이 낮으면 "유의한 결과"가 부풀려진다

(진짜 효과 +1%p(10% → 11%), 군당 2,000명, 반복 20000, seed 32 — 아래 그림의 막대 모양은 개념도, 숫자는 실제 출력)

```text
  모든 실험의 추정 효과    ▁▂▄▆█▆▄▂▁            평균 +1.00%p (편향 없음)
                         −2   0  +1  +3  +5
  유의했던 실험만          .            ▂▅█▆▃▁    평균 +2.43%p (2.4배)
                                  ↑ 기각 경계 근처보다 큰 값만 살아남는다
```

- 검정력 17.2%. 유의했던 실험(양의 방향 3,406건)의 추정 효과 평균이 +2.43%p로, 진짜 +1.00%p의 2.4배였다.
- 반대 부호로 유의한 실험도 26건 나왔다. 진짜는 개선인데 "유의한 악화"로 결론 난 경우다.
- 이유: 검정력이 낮으면 SE가 커서 **우연히 크게 나온 추정값만** 기각 경계를 넘는다. 유의한 것만 골라 보고하면 효과가 체계적으로 커 보인다(해석). Gelman–Carlin(2014)은 이것을 부호 오류(Type S — 추정 방향이 틀릴 확률)와 크기 오류(Type M — 효과가 과대 추정되는 배율)로 부르고, 설계 단계에서 함께 계산하자고 제안한다(초록). 이 실험에서는 크기 배율 약 2.4, 유의한 것 중 부호가 틀린 비율 26/3,432 ≈ 0.8%다(계산).

## 쓰이는 자료구조·알고리즘

- **정규 역누적분포**: `statistics.NormalDist().inv_cdf(1 − α/2)`, `inv_cdf(power)`로 z 값을 구한다.
- **검정력 시뮬레이션(몬테카를로)**: 가정한 효과로 데이터를 생성 → 실제로 쓸 검정을 적용 → 기각 비율. 공식이 없거나 근사가 미덥지 않은 지표·검정(순열 검정, 순차 검정 등)의 검정력은 이렇게 잰다. 비율 지표(사용자당 클릭/세션 같은 분수형)는 델타 방법으로 분산을 근사해 공식에 넣을 수도 있다(Deng·Knoblich·Lu, KDD 2018)(Think Stats 2판 9.10도 재표집 시뮬레이션으로 검정력을 구한다). 이항 생성은 Python 3.12 `random.binomialvariate`.
- **이분 탐색**: 목표 검정력을 주는 n을 시뮬레이션으로 찾을 때 n에 대해 이분 탐색한다(검정력은 n에 대해 대체로 증가). [algorithm/07-parametric-search](../../algorithm/07-parametric-search/2-summary.md).

## 적용 — 풀어나가는 법

### 1. 실험 설계 전 — 증상 → 원리 → 코드

1. **증상**: 기간·표본을 "2주쯤"으로 정했다. 또는 "작은 개선이라도 잡자"는 요구.
2. **원리**: 사업적으로 의미 있는 MDE를 먼저 정한다. 그 MDE·α·검정력(보통 80% 또는 90%, OpenIntro 7.4.3)으로 n을 계산하고, 유입량으로 기간을 계산한다. 기간이 감당 못 할 만큼 길면 MDE를 키우거나, 분산을 줄이거나, 더 민감한 지표를 찾는다.
3. **코드로 확인** — Python 3.12 표준 라이브러리

```python
import math, random, statistics
Z = statistics.NormalDist()

def n_two_prop(p1, p2, alpha=0.05, power=0.80):        # 군당, 정규 근사
    a, b = Z.inv_cdf(1 - alpha / 2), Z.inv_cdf(power)
    return math.ceil((a + b) ** 2 * (p1 * (1 - p1) + p2 * (1 - p2)) / (p2 - p1) ** 2)

def sim_power(p1, p2, n, reps=4000, alpha=0.05, seed=0):   # 실제 쓸 검정으로 확인
    rng = random.Random(seed); za = Z.inv_cdf(1 - alpha / 2); hit = 0
    for _ in range(reps):
        k1, k2 = rng.binomialvariate(n, p1), rng.binomialvariate(n, p2)
        p = (k1 + k2) / (2 * n); se = math.sqrt(p * (1 - p) * 2 / n)
        hit += abs((k2 - k1) / n) / se > za
    return hit / reps

n = n_two_prop(0.10, 0.11)          # 14749
print(n, sim_power(0.10, 0.11, n))  # 시뮬레이션으로 약 0.79~0.80 확인
print("days =", n / 5000)           # 하루 군당 유입 5,000명(예시)
```

4. **설계 문서에 남길 것**: MDE, α, 검정력, 계산된 n, 기간, 분석 단위(사용자/세션), 중간에 보지 않는다는 약속(엿보기 → [15-ab-pitfalls-srm-peeking](../15-ab-pitfalls-srm-peeking/2-summary.md)).

### 2. 실험이 끝난 뒤 "유의하지 않음"을 읽을 때

- 설계 때 계산한 검정력을 함께 적는다. "MDE 1%p를 80%로 잡는 설계에서 유의하지 않음"과 "17%로 잡는 설계에서 유의하지 않음"은 다른 말이다.
- 차이의 신뢰구간을 보고한다. 구간 전체가 `−MDE ~ +MDE` 안에 있으면 "있더라도 작다"(위끝만 +MDE보다 작으면 "MDE 이상의 개선은 배제"까지만 말할 수 있다 — 큰 악화는 남는다), 구간이 넓으면 "모른다"([08](../08-confidence-intervals/2-summary.md)).

## 장애 시나리오와 대처

### 1. 검정력 부족 → "효과 없음" 오결론 (⚠ 커리큘럼)

- 현상: 군당 2,000명 A/B에서 "유의하지 않음"이 나와 기능을 폐기했다.
- 보이는 형태: 차이의 구간이 넓다. 설계의 검정력이 17% 남짓이었다(실험 D 설정). 진짜 +1%p 효과가 있어도 83%의 실험은 "유의하지 않음"이다.
- 원인: MDE에 맞는 n을 계산하지 않았다.
- 대처: 다음 실험은 n을 계산해 설계한다(군당 14,749명이면 80%, 실험 B). 이미 끝난 실험은 "결론 보류"로 기록한다.

### 2. 너무 작은 효과 추적 → 끝나지 않는 실험 (⚠ 커리큘럼)

- 현상: "상대 1% 개선도 의미 있다"며 실험을 시작했는데 석 달째 결론이 없다.
- 보이는 형태: 필요한 군당 n이 142만 명, 하루 군당 5,000명이면 284일(실험 C). 그 사이 제품이 바뀌어 실험 자체가 낡는다.
- 원인: n은 MDE²에 반비례한다.
- 대처: MDE를 사업적으로 정당화되는 크기로 다시 정한다. 분산을 줄이는 지표·방법(예: 이상값 절사, 실험 전 기간 공변량 보정)을 검토한다 `[?]`(이 노트에서 실측하지 않음). 감지 불가능하면 "실험하지 않고 결정"도 선택지다(해석).

### 3. 작은 실험의 "유의한 승리"만 모은 효과 과대평가

- 현상: 지난 분기 "유의한 승리" 실험들의 효과 합으로 매출 증가를 예측했는데 실제는 훨씬 작았다.
- 보이는 형태: 실험 D처럼 유의한 실험만의 평균 효과가 진짜의 2.4배다. 일부는 부호까지 틀렸다(26건).
- 원인: 검정력이 낮으면 우연히 크게 나온 추정값만 문턱을 넘는다. 선택 자체가 편향을 만든다.
- 대처: 검정력이 충분한 설계로 돌린다. 승리 실험을 재실험(holdout)으로 확인한다. 효과를 보고할 때 구간을 함께 쓴다. 여러 실험·지표를 고르는 문제는 [11-multiple-comparisons](../11-multiple-comparisons/2-summary.md).

### 4. 분석 단위가 설계와 달라 검정력 계산이 틀렸다

- 현상: 세션 수로 n을 계산해 "충분하다"고 했는데, 사용자 단위로 분석하니 검정력이 모자랐다(또는 세션 단위로 분석해 구간이 너무 좁았다).
- 보이는 형태: 같은 사용자의 세션들이 닮아 실제 SE가 순진한 SE의 1.45배였다([07](../07-sampling-distributions-and-clt/2-summary.md) 실험 E). SE가 1.45배면 같은 검정력에 n이 약 2.1배(1.45²) 필요하다(계산).
- 원인: 표본 크기 공식은 독립 관측을 가정한다.
- 대처: 배정 단위(사용자)로 n과 분산을 계산한다([14-ab-testing-design](../14-ab-testing-design/2-summary.md)).

## 핵심 문장

- 검정력은 정해 둔 크기의 진짜 효과가 있을 때 그것을 잡을 확률이다. 실험 전에 MDE·α·검정력으로 n을 계산한다.
- α 0.05 양측·검정력 80%면 귀무·대립 분포의 중심이 SE의 약 2.8배 떨어져야 한다.
- 표본 크기는 MDE²에 반비례한다. 효과를 절반 크기까지 잡으려면 표본이 4배 든다.
- 검정력이 낮은 실험의 "유의하지 않음"은 증거 부족이고, 그런 실험의 "유의함"은 효과를 부풀려 보인다.
- 공식은 정규 근사다. 실제로 쓸 검정·지표·분석 단위로 시뮬레이션해 확인한다.
