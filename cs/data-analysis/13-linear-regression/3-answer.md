# data-analysis/13-linear-regression — 정답

## 정답

### 1. 최소제곱

- 잔차 제곱합 `Σ(yi − b0 − b1·xi)²`을 최소로 하는 직선이다.
- 해: `b1 = Sxy/Sxx = r·sy/sx`, `b0 = ȳ − b1·x̄`(직선이 (x̄, ȳ)를 지난다, OpenIntro 8.2.4).
- 정규방정식: `Σ ei = 0`, `Σ xi·ei = 0`. 실험 (B)에서 각각 7.89e-13, 4.54e-11로 부동소수 오차 수준의 0이었다.
- 제곱은 큰 잔차에 큰 벌점을 준다. 멀리 떨어진 점 하나의 잔차를 줄이려고 직선 전체가 움직인다.

### 2. Elmhurst

- b1 = −0.499 × 5,460 / 63,200 ≈ **−0.0431**.
- b0 = 19,940 − b1 × 101,780. 반올림 전 기울기 −0.499 × 5,460 / 63,200 ≈ −0.04310981을 넣으면 ≈ **24,328**이다(반올림한 −0.0431을 넣으면 24,327). 책은 원자료로 24,319. 차이는 반올림된 R 때문.
- R² = 0.499² ≈ **0.249**(책 0.25).
- 소득 100만 달러: 24,319 − 0.0431 × 1,000,000 = **−18,781달러**. 음수 장학금이다. 데이터 범위 밖에 모형을 적용한 **외삽**이다(OpenIntro 8.2.6).

### 3. 대기열 외삽

- ρ = 0.9: 직선 예측 **3.10**, 실제 **10.00**(실험 D). ρ = 0.95에서는 3.23 vs 20.00.
- W = 1/(1 − ρ)는 1에 가까울수록 폭증하는 곡선이다. 낮은 구간에서는 거의 직선처럼 보여 R²가 높지만, 직선은 곡률을 모른다.

### 4. 레버리지

- x = 400의 점: 기울기 **0.808 → 0.474**. 레버리지 h = 0.482(평균 2/n ≈ 0.010의 약 48배).
  - 그 점의 잔차는 **−126**으로, 실제 이탈 −240보다 작아 보인다. 직선이 그 점 쪽으로 끌려왔기 때문이다.
- x = 55의 점: 기울기 **0.808 → 0.802**로 거의 그대로. h = 0.005. 잔차는 **−239**로 이탈 그대로 보인다.
- 두 경우 모두 R²는 떨어진다(0.572, 0.550). 영향점은 잔차가 아니라 **레버리지 + 빼고 재적합**으로 찾는다.

### 5. R²와 잔차

- 아니다. 실험 (E)는 곡선 데이터에 직선을 적합해 R² 0.937을 얻었지만, 구간별 평균 잔차가 +4.8, −4.2, −5.8, +5.2로 U자였다.
- 아니라고 판단하는 모양: U자·∩자(비선형), 나팔 모양(산포가 일정하지 않음), 멀리 떨어진 잔차(이상값·영향점), 시간 순으로 이어지는 잔차(독립 위반).
- OpenIntro 8.2.3 네 조건: 선형성, 정규에 가까운 잔차, 일정한 산포, 관측 독립.

### 6. 기울기 추론

- T = −0.0431 / 0.0108 ≈ **−3.99**(책 출력 −3.98).
- df = 50 − 2 = **48**. 양측 p ≈ **0.0002**(직접 계산, 책과 같음).
- 95% CI: t*(48) ≈ 2.01. −0.0431 ± 2.01 × 0.0108 = **(−0.0648, −0.0214)**.
- 자유도 n − 2: 잔차 표준오차를 구할 때 계수 두 개(b0, b1)를 같은 데이터로 추정했다. 잔차는 정규방정식 두 개를 만족해야 하므로 자유롭게 움직일 수 있는 개수가 2개 줄어든다.
- 이 계산은 네 조건을 가정한다. 소프트웨어는 조건을 검사하지 않는다(OpenIntro 8.4).

### 7. `regr_slope` 인자 순서

- `regr_slope(Y, X)`의 첫 인자가 반응 변수다(PostgreSQL 17 표 9.61). `regr_slope(x, y)`는 **x를 y로 예측하는 직선**의 기울기다.
- 역수가 아니다. 실험 (B): b1 = 0.8081, 1/b1 = 1.2375인데 `regr_slope(x, y)` = **1.0896** = r²/b1이다. |r| = 1일 때만 두 값이 같다.

### 8. 한 번 훑기와 수치 문제

- 기울기·절편·r은 n, Σx, Σy, Σx², Σy², Σxy만 있으면 계산된다. 이 합들은 행을 한 번 읽으며 누적할 수 있고, 부분 합끼리 더할 수도 있다. 그래서 PostgreSQL 표 9.61의 통계 집계는 부분 집계(병렬)를 지원한다.
- 수치 문제: `Σx² − (Σx)²/n` 같은 식은 값이 크고 분산이 작으면 비슷한 큰 수의 뺄셈이 되어 유효 자리를 잃는다(파국적 상쇄, [math/15](../../math/15-numerical-stability/2-summary.md)). 평균을 먼저 빼는 계산이 안정적이다.

### 9. 기울기 급락 진단

- 의심: 레버리지가 큰 영향점 하나. x가 혼자 크면 직선을 자기 쪽으로 당겨서 잔차가 작아 보인다(실험 C).
- 확인
  1. 레버리지 `h_i = 1/n + (xi − x̄)²/Sxx` 상위 점을 뽑는다.
  2. 그 점을 빼고 다시 적합해 기울기 변화를 본다(0.47 → 0.81로 돌아오면 영향점).
  3. 그 점의 원인(장애 재처리·로깅 오류·다른 요금제)을 확인한다.
- 대처: 원인이 데이터 오류면 고치고, 진짜 사례면 남기되 "그 점 포함/제외" 결과를 둘 다 보고한다. 이상값을 이유 없이 지우지 않는다(OpenIntro 8.3).
