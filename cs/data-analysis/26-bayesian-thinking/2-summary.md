# data-analysis/26-bayesian-thinking — 베이즈 사고: 사전·사후·베이즈 갱신 — 정리 (힌트)

## 해결하는 문제

별점순 정렬을 했더니 1위가 "5.0점, 리뷰 1개" 가게다. 리뷰 200개에 4.6점인 가게보다 정말 나을까?

```text
  원 평균으로 정렬                  사전 지식을 섞어 정렬 (베이즈)
  1. 가게 P  5.00 (리뷰 1개)        1. 가게 Q  4.58 (리뷰 200개)
  2. 가게 R  5.00 (리뷰 3개)        2. 가게 R  4.35 (리뷰 3개)
  3. 가게 Q  4.60 (리뷰 200개)      3. 가게 P  4.23 (리뷰 1개)
                                    → 리뷰가 적을수록 사이트 평균(4.15) 쪽으로 당겨진다
```

- 리뷰 1개의 평균은 우연에 크게 흔들린다. 우리는 "보통 가게는 4점대"라는 것을 이미 안다. 그 지식(사전)과 데이터(리뷰)를 합친 것이 사후다.
- 베이즈 정리 자체(사전·가능도·사후, 기저율)는 [math/07](../../math/07-probability-and-bayes/2-summary.md)에서 다뤘다. 이 노트는 그것을 **분포 전체에 대해 반복해서 쓰는 법**(갱신)과 데이터 분석에서의 쓰임을 다룬다.

쉬운 예: 신인 타자가 첫 타석에 안타를 쳤다. 기록상 관측 타율은 1.000이다. 하지만 이 타자가 매번 안타를 칠 실력(안타 확률 1)이라고 믿는 사람은 없다. "보통 타자는 2할 5푼쯤"이라는 사전 지식이 있어서, 한 타석으로는 거의 움직이지 않는다.

똑같은 구조다.\
데이터가 적을 때는 사전 쪽에, 데이터가 쌓이면 데이터 쪽에 무게가 실린다.

실무 예:
- 별점·좋아요 비율 정렬, 신규 상품의 클릭률 추정, 작은 지역의 전환율 비교.
- 베이즈 A/B: "B가 A보다 나을 확률"로 결과를 말한다.

## 동작·원리

### 1. 갱신 — 사후 ∝ 가능도 × 사전

```text
  사전 분포 P(θ)       ×    가능도 P(데이터 | θ)    ∝    사후 분포 P(θ | 데이터)
  "만족 비율 θ는          "θ라면 이 리뷰들이           "리뷰를 본 뒤 θ에 대한
   0.8 근처일 것"           나올 확률"                    믿음"
                                                          ↓ 다음 데이터의 사전이 된다
```

- *θ(모수)*: 모르는 값. 여기서는 "이 가게 리뷰가 만족일 확률".
- *사전 분포(prior)*: 데이터를 보기 전 θ에 대한 믿음을 분포로 적은 것.
- *사후 분포(posterior)*: 데이터를 본 뒤의 분포. 오늘의 사후가 내일의 사전이 된다.
- 결과가 숫자 하나가 아니라 분포다. 그래서 "얼마나 확실한가"가 같이 나온다.

### 2. 켤레 사전분포 — 베타-이항

```text
  사전 Beta(a, b)  +  n번 중 k번 만족  →  사후 Beta(a + k, b + n − k)
         │                                       │
  "가짜 리뷰 a+b개 중 a개가 만족"과 비슷      평균 = (a + k) / (a + b + n)

  사후 평균 = w · (k/n) + (1 − w) · a/(a+b),   w = n / (n + a + b)
              ↑ 데이터 평균        ↑ 사전 평균      n이 클수록 w → 1
```

- *켤레 사전분포(conjugate prior)*: 사전과 사후가 같은 분포 가족이 되는 사전. 갱신이 덧셈 두 번으로 끝난다.
- Downey 『Think Bayes』 2판 18.4(Binomial Likelihood): 이항 가능도의 켤레 사전분포는 베타 분포다. 베타는 0~1 사이에 있어 확률을 나타내기에 맞다.
- *베타 분포 Beta(a, b)*: 0~1 사이 값의 분포. 평균 a/(a+b). 분산은 평균·(1−평균)/(a+b+1)이라, **평균을 고정하면** a+b가 클수록 좁다(평균이 다르면 아닐 수 있다: Beta(1,9) 분산 약 0.0082 < Beta(6,6) 약 0.0192).
- 사후 평균은 데이터 평균과 사전 평균의 가중 평균이다(위 식은 베타 평균의 정의에서 바로 나온다). 데이터가 적을수록 사전 쪽으로 당겨진다. 이것을 *축소(shrinkage)*라 한다.

### 실험: 리뷰 1개짜리 100%와 500개짜리 90%

사이트 전체 만족 비율이 약 80%라는 지식을 `Beta(8, 2)`(가짜 리뷰 10개 중 8개 만족, 예시)로 넣었다.

```python
# scratchpad/da/14/e26a_beta.py 핵심
def post(a, b, k, n): return a + k, b + n - k          # 켤레 갱신: 덧셈 두 번
def mean(a, b): return a / (a + b)
xs = sorted(rng.betavariate(a, b) for _ in range(100_000))   # 95% 신용구간은 사후 표본의 2.5%·97.5% 지점
```

(계산·시뮬레이션, 호스트 Python 3.12.3 `random.betavariate`, seed 26, 사후 표본 100,000개)

```text
사전 Beta(8, 2)  사전 평균 0.800
상품 A (1개 중 1개 만족)          원 비율 1.000 | 사후 Beta(9,2) 평균 0.818 | 95% 신용구간 [0.552, 0.975]
상품 B (500개 중 450개 만족)      원 비율 0.900 | 사후 Beta(458,52) 평균 0.898 | 95% 신용구간 [0.870, 0.923]
상품 C (10개 중 10개 만족)        원 비율 1.000 | 사후 Beta(18,2) 평균 0.900 | 95% 신용구간 [0.738, 0.987]
  평탄 사전 Beta(1,1) 상품 A (1개 중 1개 만족)        사후 평균 0.667
  평탄 사전 Beta(1,1) 상품 B (500개 중 450개 만족)    사후 평균 0.898
  평탄 사전 Beta(1,1) 상품 C (10개 중 10개 만족)      사후 평균 0.917
순차 갱신 결과 Beta(458,52) — 한 번에 갱신 Beta(458, 52)
격자 근사 사후 평균 상품 A (1개 중 1개 만족): 0.8182  (공식 0.8182)
격자 근사 사후 평균 상품 C (10개 중 10개 만족): 0.9000  (공식 0.9000)
```

- 관찰 1: 원 비율로는 A(1.000) > B(0.900)다. 사후 평균으로는 B(0.898) > A(0.818)다. A의 신용구간 [0.55, 0.98]은 넓어 "아직 모른다"를 그대로 보여 준다. 구간 끝값은 사후 표본 10만 개에서 읽은 근사다. Beta(9,2)의 정확한 2.5%·97.5% 분위수는 0.555·0.975다(CDF `x⁹(10 − 9x)`를 이분법으로 풀어 확인).
- 관찰 2: B는 리뷰가 500개라 사전의 영향이 거의 없다(0.900 → 0.898). 평탄 사전에서도 0.898이다. 데이터가 많으면 사전 선택이 결과를 거의 바꾸지 않는다.
- 관찰 3: 평탄 사전 Beta(1,1)도 사전이다. A의 사후 평균을 0.667로 당긴다. "사전 없음"은 없다.
- 관찰 4: 리뷰를 50개씩 10번 나눠 넣어도 한 번에 넣은 것과 같은 Beta(458, 52)다. 갱신 순서와 묶음에 무관하다(θ가 주어졌을 때 리뷰가 서로 독립이라는 이항 가정 아래).
- 관찰 5: 켤레 공식을 쓰지 않고 θ를 0.0005 간격 격자로 나눠 `사전 × 가능도`를 직접 정규화해도 같은 사후 평균(0.8182, 0.9000)이 나왔다. 켤레 공식은 이 계산의 지름길이다.
  - *신용구간(credible interval)*: 사후 분포에서 θ가 들어갈 확률이 95%인 구간. "모수가 이 구간에 있을 확률 95%"라는 말이 **사후 분포라는 가정 아래에서** 성립한다. 빈도주의 신뢰구간([08](../08-confidence-intervals/2-summary.md))의 해석과 다르다.
    - 흔한 오해: 빈도주의 95% 신뢰구간도 "참값이 95% 확률로 이 안에 있다"는 뜻이라고 읽는다. OpenIntro 5.2.2는 "95% 신뢰"를 표본을 여러 번 뽑아 구간을 만들면 그중 약 95%가 모수를 포함한다는 뜻으로 설명하고, 5.2.5는 신뢰구간을 확률로 해석하는 것을 흔한 오류로 꼽는다.

### 3. 별점 1~5 — 디리클레 사전으로 확장

```text
  사이트 별점 분포 (예시)    1★ 5%  2★ 5%  3★ 10%  4★ 30%  5★ 50%   → 평균 4.15
  가짜 리뷰 10개로 넣기      α = (0.5, 0.5, 1, 3, 5)
  가게의 별점 수 c를 더해    사후 평균 별점 = Σ k·(α_k + c_k) / Σ(α_k + c_k)
```

- 별점이 다섯 범주면 이항 대신 다항 가능도, 베타 대신 디리클레 사전을 쓴다. 갱신은 같은 모양(가짜 개수 + 실제 개수)이다. Think Bayes 2판 18.6이 디리클레 분포를 다룬다.

### 실험: 별점 사후 평균 정렬

(계산, 호스트 Python 3.12.3, `scratchpad/da/14/e26b_stars.py`)

```text
사전 평균 별점 4.150 (가짜 리뷰 10개)
가게 P: 5점 1개            원 평균 5.000 → 사후 평균 4.227  (리뷰 1개)
가게 Q: 200개, 평균 4.6     원 평균 4.600 → 사후 평균 4.579  (리뷰 200개)
가게 R: 5점 3개            원 평균 5.000 → 사후 평균 4.346  (리뷰 3개)
```

- 관찰: 원 평균 순위는 P = R(5.0) > Q(4.6). 사후 평균 순위는 Q(4.58) > R(4.35) > P(4.23). 리뷰 1개로는 사이트 평균에서 0.08점만 움직였다.
- 해석: 가짜 리뷰 수(여기서 10)가 "얼마나 쉽게 움직일지"를 정한다. 크게 잡으면 신규 가게가 오래 못 뜨고, 작게 잡으면 1개짜리 5.0이 다시 위로 온다. 사이트 데이터로 정하고(예: 가게별 평균의 퍼짐), 정한 값을 문서에 남긴다.

### 4. 베이즈 A/B — "B가 A보다 나을 확률"

```text
  A 전환 100/2000, B 120/2000
  사후  p_A ~ Beta(1+100, 1+1900),  p_B ~ Beta(1+120, 1+1880)   (평탄 사전)
  두 사후에서 표본을 뽑아 p_B > p_A 인 비율을 센다 → P(B > A | 데이터)
```

- 두 사후에서 **따로** 뽑아도 되는 것은 가정 덕분이다: p_A·p_B의 사전이 서로 독립이고, 두 그룹 데이터가 (전환율이 주어졌을 때) 서로 독립이다. 그러면 결합 사후가 두 베타의 곱이 된다. 사전에 두 전환율을 엮어 두었다면 결합 사후에서 쌍으로 뽑아야 한다(Think Bayes 2판 11장: 독립일 때만 두 주변 분포로 결합 분포를 만든다).

(시뮬레이션, 호스트 Python 3.12.3 `random.betavariate`, seed 99, 몬테카를로 200,000회)

```text
A 100/2000 vs B 120/2000: P(B>A|데이터) ≈ 0.9172 (몬테카를로 200,000회, seed 99) | 단측 p = 0.0827 | 1−p = 0.9173
A 500/10000 vs B 560/10000: P(B>A|데이터) ≈ 0.9703 (몬테카를로 200,000회, seed 99) | 단측 p = 0.0291 | 1−p = 0.9709
```

- 관찰: 평탄 사전·이 크기의 표본에서 `P(B > A | 데이터)`는 단측 z 검정의 `1 − p`와 소수 셋째 자리 근처까지 비슷했다.
- 해석: 숫자가 비슷해도 뜻이 다르다.
  - `P(B > A | 데이터) = 0.92`: 사전과 모형을 받아들이면, B의 전환율이 A보다 높을 확률이 0.92다.
  - 단측 p = 0.083: 차이가 없다고 가정했을 때 이만큼 이상 극단적인 데이터가 나올 확률이다. "B가 나쁠 확률 8.3%"가 아니다(ASA 2016 p값 성명 원칙 2: p값은 연구 가설이 참일 확률을 재지 않는다).
- 사전이 강하거나 표본이 작으면 두 수는 벌어질 수 있다. 위 일치는 이 설정에서 본 것이지 일반 법칙이 아니다.
- 베이즈로 바꿔도 [15](../15-ab-pitfalls-srm-peeking/2-summary.md)의 SRM·간섭 문제는 그대로다. 데이터가 편향되면 사후도 편향된다.

## 적용 — 풀어나가는 법

### 1. 증상 → 원리 → 확인

- 증상: 순위 상단이 리뷰 1~3개짜리로 가득하다.
  - 원리: 작은 표본의 평균은 분산이 크다. 극단값이 우연으로 쉽게 나온다.
  - 확인: 순위 상위 N개의 리뷰 수 분포를 본다. 사후 평균 또는 사후 하한(예: 신용구간 아래쪽)으로 다시 정렬해 비교한다.
- 증상: 신규 상품이 한참 지나도 순위에 안 올라온다.
  - 원리: 사전(가짜 개수)이 너무 강하다.
  - 확인: 가짜 개수를 사이트 데이터로 다시 정한다. 신규 상품의 노출 기회를 따로 준다.

### 2. 코드 — 저장은 카운터 두 개 (Java 21)

```java
// 항목별로 만족 수·리뷰 수만 저장하면 사후 평균은 즉시 계산된다
record Rating(long liked, long total) {
    static final double A = 8, B = 2;                 // 사전 Beta(8,2) — 사이트 데이터로 정한 값(예시)
    double posteriorMean() { return (A + liked) / (A + B + total); }
    Rating add(boolean like) { return new Rating(liked + (like ? 1 : 0), total + 1); }
}
```

### 3. SQL — 사후 평균으로 정렬 (PostgreSQL 17)

```sql
-- review(shop_id, stars int 1..5). 사이트 평균을 사전 평균으로, 가짜 리뷰 10개
WITH prior AS (SELECT avg(stars)::numeric AS m FROM review),
     s AS (SELECT shop_id, count(*) AS n, sum(stars) AS total FROM review GROUP BY shop_id)
SELECT shop_id, n, round(total::numeric / n, 2) AS raw_avg,
       round((10 * prior.m + total) / (10 + n), 3) AS bayes_avg
FROM s, prior
ORDER BY bayes_avg DESC;
```

(실행, PostgreSQL 17.11, 가게 P·Q·R + 다른 가게 100곳의 리뷰 2,000건, 사이트 평균 4.192)

```text
 shop_id |  n  | raw_avg | bayes_avg
---------+-----+---------+-----------
 shop_Q  | 200 |    4.60 |     4.581
 shop_R  |   3 |    5.00 |     4.379
 shop_P  |   1 |    5.00 |     4.266
```

- 처음에는 가게 P·Q·R 셋만 넣고 돌렸다. 그러면 사전 평균이 리뷰 200개인 Q에 끌려 4.608(= 940/204)이 되고, 결과가 R 4.698 > P 4.643 > Q 4.600으로 원 평균 순서와 같았다. P·R도 당겨지긴 했지만 Q의 값 쪽으로 당겨져 순서가 바뀌지 않았다. 사전 평균을 **분석 대상 자신이 대부분인 데이터**로 구하면 사전이 사전 지식 노릇을 못 한다. 사전은 충분히 넓은 모집단(사이트 전체·같은 범주 전체)에서 구한다.
  - 이렇게 데이터로 사전의 모수를 추정하는 것을 *경험적 베이즈*라 한다(BDA3 5.1은 이를 완전한 계층 모형 분석의 근사로 본다). 미리 고정한 사전과는 다르다. 결론에 맞춰 바꾸지 않도록 **추정 규칙**(어느 범위의 평균, 가짜 리뷰 몇 개)을 결과를 보기 전에 정한다.

- 3절의 디리클레 사후 평균 별점은 `Σk·(α_k + c_k) / (W + n) = (W·m + 별점 합) / (W + n)`으로 정리된다(m = 사전 평균, W = 가짜 개수). 그래서 사전 평균을 사이트 평균으로, W = 10으로 두면 이 SQL과 같은 값이다. 별점을 숫자로 평균 내는 것 자체의 한계(순서형 척도)는 [01](../01-data-types-and-measurement/2-summary.md)에서 다룬다.

## 장애 시나리오와 대처

### 1. 리뷰 1개짜리 5.0이 1위 (⚠ 커리큘럼)

- 현상: "평점 높은 순" 상단이 리뷰 1~3개 가게로 채워져 사용자 불만이 늘었다.
- 보이는 형태: 상위 10개의 리뷰 수 중앙값이 1~2개. 일주일 뒤 리뷰가 쌓이면 순위에서 사라진다.
- 원인: 소표본 평균을 그대로 썼다. 사전 지식(보통 가게의 평점 분포)을 무시했다.
- 대처: 사후 평균(또는 신용구간 하한)으로 정렬한다. 위 실험에서 리뷰 1개의 5.0은 4.23으로, 200개의 4.6은 4.58로 바뀌어 순서가 뒤집혔다.

### 2. 사전이 너무 강하다

- 현상: 좋은 신규 가게가 몇 달째 순위 중간에 머문다.
- 보이는 형태: 가짜 리뷰 수가 실제 평균 리뷰 수보다 크다. 리뷰 50개짜리 가게도 사이트 평균에 붙어 있다.
- 원인: 사전의 무게(a+b)가 데이터보다 크다.
- 대처: 가짜 개수를 사이트 데이터(가게별 평균의 퍼짐)로 정한다. 정기적으로 다시 맞춘다.

### 3. 결과를 보고 사전을 골랐다

- 현상: 원하는 결론이 나오도록 사전을 바꿔 가며 분석했다.
- 보이는 형태: 분석 문서에 사전 선택 근거가 없다. 다른 사전에서는 결론이 바뀐다.
- 원인: 사전도 분석자가 정하는 가정이다. 결과를 보고 고르면 p-해킹과 같은 구조다([11](../11-multiple-comparisons/2-summary.md)).
- 대처: 사전(또는 사전을 데이터로 추정하는 규칙)은 결과를 보기 전에 정하고 근거를 남긴다. 다른 합리적 사전으로도 결론이 같은지(민감도 분석) 보인다.

### 4. "P(B > A) = 0.92"를 "출시하면 92% 성공"으로 읽었다

- 현상: B를 출시했는데 기대한 효과 크기가 나오지 않았다.
- 보이는 형태: P(B > A)는 높지만 차이의 사후 분포가 0 근처까지 넓다.
- 원인: "B가 조금이라도 나을 확률"과 "의미 있게 나을 확률"은 다르다. 효과 크기와 불확실성을 같이 봐야 한다.
- 대처: `P(p_B − p_A > 최소 의미 효과)`와 차이의 신용구간을 함께 보고한다.

### 5. 독립이 아닌 리뷰

- 현상: 리뷰가 많은데도 평점이 이상하게 높다.
- 보이는 형태: 같은 날 같은 기기에서 몰린 5점 리뷰, 같은 사용자의 반복 리뷰.
- 원인: 베타-이항은 θ(가게의 참 만족률)가 주어졌을 때 리뷰가 서로 독립이라고 가정한다. 몰아주기 리뷰는 실제 정보보다 n을 부풀린다.
- 대처: 사용자당 1건으로 줄이고, 중복·이상 패턴을 먼저 정제한다([18 data-cleaning](../18-data-cleaning-and-quality/2-summary.md)).

## 핵심 문장

- 사후는 사전과 가능도의 곱에 비례한다. 오늘의 사후가 내일의 사전이 된다.
- 베타-이항 켤레에서는 갱신이 덧셈 두 번이다. 사후 평균은 데이터 평균과 사전 평균의 가중 평균이고, 데이터가 적을수록 사전 쪽으로 당겨진다.
- 평탄 사전도 사전이다. 사전의 무게는 사이트 데이터로 정하고 근거를 남긴다.
- 신용구간의 "95% 확률"은 사후 분포라는 가정 아래에서의 말이다. 빈도주의 신뢰구간의 해석과 다르다.
- 베이즈로 바꿔도 데이터의 편향(SRM·간섭·중복 리뷰)은 사라지지 않는다.
