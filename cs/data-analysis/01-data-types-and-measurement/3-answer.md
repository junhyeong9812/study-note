# data-analysis/01-data-types-and-measurement — 정답

## 정답

### 1. 숫자 모양 ≠ 수치형

- OpenIntro 4판 1.2.2의 기준: 더하고 빼고 평균 내는 것이 뜻이 있으면(sensible) 수치형이다.
- 전화 지역번호는 숫자로 적지만 평균·합·차가 뜻이 없어 수치형이 아니다(OpenIntro 예). 우편번호·주문 상태 코드도 같다 — 숫자 모양의 이름표(명목형)다.

### 2. 나무와 사다리

```text
  변수 ─┬─ 수치형 ─┬─ 연속형 (지연 ms)
        │          └─ 이산형 (주문 수)
        └─ 범주형 ─┬─ 명목형 (국가·OS·우편번호)
                   └─ 순서형 (만족도·등급)

  비율   = < 차이 비율   진짜 0     평균·중앙값·최빈값
  구간   = < 차이        0이 임의   평균·중앙값·최빈값
  순서   = <                        중앙값·최빈값
  명목   =                          최빈값
```

- 나무는 OpenIntro 1.2.2, 사다리는 Stevens 1946(서지·허용 통계량은 Wikipedia "Level of measurement" 2차로 확인).

### 3. 코딩만 바꿨는데 승자가 바뀐다

- 1~5 코딩: 평균 A 3.40, B 3.70 → B 우세.
- "매우 만족 = 4.2": 평균 A 3.40, B 3.26 → A 우세.
- 중앙값(`median_low`)은 두 코딩 모두 A = 보통, B = 매우 만족. 순서만 쓰므로 순서를 지키는 코딩 변경에 영향을 받지 않는다.
- 실험 출력(Python 3.12)에서 그대로 확인된다. 1,2,3,4,9 코딩에서는 B 5.90으로 다시 B가 이긴다.

### 4. 섭씨 vs 지연

- 섭씨는 구간 척도다. 0°C가 임의의 원점이라 비율이 뜻이 없다. 켈빈으로 바꾸면 293.15/283.15 = 1.035배다(실험).
- 지연은 비율 척도다. 0ms가 "지연 없음"이므로 200ms는 100ms의 두 배라고 말할 수 있다.
- 구간 척도에서는 차이로 말한다: "+10°C".

### 5. `ENUM`과 집계

- PostgreSQL 17.11 실험: `percentile_disc(0.5) WITHIN GROUP (ORDER BY s)` → `보통`, `mode() WITHIN GROUP (ORDER BY s)` → `보통`, `avg(s)` → `ERROR: function avg(sat) does not exist`.
- `ENUM`은 선언 순서로 정렬된다(8.7.2). 순서만 쓰는 집계는 되고, 간격을 가정하는 산술은 타입이 막는다. 뜻 없는 계산을 리뷰가 아니라 타입이 거른다.

### 6. 4자리 "지역"

- 원인: 우편번호(명목형 코드값)를 정수 열에 적재 → `01234`가 `1234`가 됐다.
- 확인: `SELECT count(*) FROM addr WHERE zip_int < 10000;` 또는 문자열 열이면 `WHERE zip_text !~ '^\d{5}$'`.
- 복구: `lpad(zip_int::text, 5, '0')`. 단, 모든 값이 5자리 고정이라는 것을 알 때만 맞다.
- 재발 방지: 열을 `text`/`char(5)`로, 적재 단계 형식 검사, 앱에서는 값 객체(`record ZipCode(String value)`)로 검증.

### 7. 평균 만족도 개선 발표

- 놓친 것: 분포. 위 예시에서 B는 "매우 불만" 20%가 새로 생겼는데 "매우 만족" 55%가 평균을 끌어올렸다(양극화).
- 다시 보고할 묶음: 수준별 분포표, 중앙값, top-2-box(만족 이상 비율), bottom-2-box(불만 이하 비율). 평균은 코딩을 명시한 보조 지표로만.

### 8. 척도를 금지 규칙으로 쓰면

- Stevens의 허용 통계량 제한은 통계학자들이 일반적으로 받아들인 것이 아니라는 비판이 있다(Wikipedia "Level of measurement"의 논쟁 절, 2차 출처).
- 순서형 평균이 실무에서 유용한 경우도 있다(같은 코딩으로 내부 추세 비교 등).
- 이 노트는 척도를 질문으로 쓴다: "순서를 지키는 다른 코딩으로 바꿔도 결론이 같은가?" 같으면 평균을 써도 결론이 흔들리지 않고, 다르면(3번) 평균은 결론의 근거가 될 수 없다.
