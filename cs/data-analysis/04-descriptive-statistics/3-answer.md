# data-analysis/04-descriptive-statistics — 정답

## 정답

### 1. 평균이 꼬리에 끌린다

```text
  ●●●●●●●●●                                          ●
  12 ……………… 35                                      400
           ↑ 중앙값 23.5          ↑ 평균 60.4
```

- 평균은 모든 값이 같은 무게로 들어간다. 400 하나가 합을 크게 키워 평균을 오른쪽 꼬리 쪽으로 끈다. 10건 중 9건이 평균보다 빠르다.
- 중앙값은 순서상 가운데만 본다. 꼬리 값이 얼마나 큰지는 상관없다.

### 2. 질문이 다르다

- OpenIntro 2.1.6(대출 금액 예): 전형적인 한 건을 알고 싶으면 중앙값, 1,000건에 필요한 총액처럼 합계로 확장되는 것을 알고 싶으면 평균.
- 서버 비용·총 처리 시간·용량 = 합계 질문 → 평균 × 건수. 사용자 체감 = 개인 질문 → 중앙값과 상위 백분위.

### 3. 400 → 4000

- 평균 60.4 → 420.4, 표본표준편차 119.5 → 1257.8. 중앙값 23.5와 IQR 11.75는 그대로(실험 출력).
- 중앙값·IQR은 Q1·중앙값·Q3 근처 값에만 민감한 로버스트 통계량이다(OpenIntro 2.1.6).

### 4. Q1이 네 가지

| 방법 | Q1 |
|---|---|
| Python `quantiles` 기본(`'exclusive'`) | 16.5 |
| Python `method='inclusive'` | 17.75 |
| PostgreSQL 17 `percentile_cont(0.25)` | 17.75 |
| PostgreSQL 17 `percentile_disc(0.25)` | 17 |

- `'exclusive'`는 i번째 값 아래 비율을 i/(m+1), `'inclusive'`는 (i−1)/(m−1)로 보고 선형 보간한다(Python 3.12 문서). `percentile_cont`는 보간, `percentile_disc`는 위치가 비율 이상이 되는 첫 실제 값이다(PostgreSQL 17 문서).
- 이 데이터에서 `percentile_cont` = `'inclusive'`였다(실험). 도구 간 비교 전에 정의를 맞춘다.

### 5. n − 1

- 평균을 데이터에서 추정했기 때문에, 그 평균에서 잰 편차 제곱합은 참 평균에서 잰 것보다 작게 나온다. n − 1로 나눠 이 과소 추정을 바로잡는다(베셀 보정). Python 문서: 데이터가 대표적(예: 독립·동일 분포)이면 `variance`(n − 1)가 모분산의 불편 추정. 그 제곱근 `stdev`는 모표준편차의 불편 추정이 아니다(NIST 핸드북 6.3.2).
- n − 1: Python `variance`·`stdev`, PostgreSQL `var_samp`·`stddev_samp`(실험 119.53). n: Python `pvariance`·`pstdev`, PostgreSQL `stddev_pop`(실험 113.40).

### 6. 박스플롯

```text
   울타리 0.125                                울타리 47.125
       :   12├────[17.75 ══ 23.5 ══ 29.5]────┤35   :                ● 400
```

- 5수치: 12, 17.75, 23.5, 29.5, 400. IQR = 11.75. 울타리는 0.125~47.125다(실험 출력은 소수 둘째 자리로 찍어 [0.12, 47.12]). 밖 = 400 하나(실험 출력).
- 위쪽 수염은 울타리 안의 가장 큰 값 35까지, 아래쪽은 최솟값 12까지 뻗는다(OpenIntro 2.1.5).

### 7. 선택 알고리즘과 두 힙

- quickselect: 피벗으로 나눈 뒤 k가 있는 쪽만 계속 판다. 무작위 피벗이면 평균 O(n), 최악 O(n²). 실험에서 200,001개 중앙값이 `statistics.median`과 같았다.
- 스트림: 아래 절반은 최대 힙, 위 절반은 최소 힙. 크기 차이를 1 이하로 유지하면 중앙값을 힙 꼭대기에서 바로 읽는다. 개수가 홀수면 큰 쪽 힙의 꼭대기, 짝수면 두 꼭대기의 평균이다(data-structure/07-heap).

### 8. 이상치 삭제 보고

- 1.5 × IQR 울타리는 이상치 **후보** 표시 관례이지 오류 판정이 아니다. 지연 데이터에서 울타리 밖은 실제 느린 요청일 가능성이 높다.
- 확인: 지운 값의 개수와 원인 분류(측정 오류·봇·타임아웃·실제 느린 요청), 원천 로그 대조. 실제 경험이면 지우지 않고, 지웠다면 규칙과 개수를 함께 보고한다.

### 9. 상쇄 오차

- 원인: 1.79×10¹² 근처 값의 제곱합과 (합)²/n은 거의 같은 큰 수다. 그 뺄셈 결과(작은 분산)를 부동소수점 유효 자릿수가 담지 못한다.
- 실험(시드 42): 한 번에 계산 5.50306e+08, `statistics.variance` 0.0828404, 이론 1/12 ≈ 0.0833.
- 대처: 평균을 먼저 빼는 두 단계 계산, Welford 류 온라인 갱신, 또는 표준 라이브러리 함수(math/15-numerical-stability).
