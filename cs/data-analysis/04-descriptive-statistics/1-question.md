# data-analysis/04-descriptive-statistics — 질문

## 질문

1. (왜) 응답 시간 10건 `12 15 17 20 22 25 28 30 35 400`(ms)의 평균은 60.4, 중앙값은 23.5다. 평균이 "대부분의 경험"과 어긋나는 이유를 오른쪽 치우침 그림으로 설명하라.
2. (경계) OpenIntro 2.1.6은 평균과 중앙값 중 어느 것이 "더 맞다"고 하지 않는다. 어떤 질문에 평균이, 어떤 질문에 중앙값이 쓸모 있나? 서버 비용과 사용자 체감에 각각 대응시켜라.
3. (예측) 위 데이터의 마지막 값을 400 → 4000으로 바꾸면 평균·중앙값·표본표준편차·IQR은 각각 어떻게 되나? (실험 출력으로 확인)
4. (계산) 같은 10개 값의 Q1은 Python 3.12 `statistics.quantiles` 기본값, `method='inclusive'`, PostgreSQL 17 `percentile_cont`, `percentile_disc`에서 각각 얼마인가? 왜 다른가?
5. (경계) 표본분산을 n이 아니라 n − 1로 나누는 이유는? Python과 PostgreSQL에서 각각 어느 함수가 n − 1이고 어느 함수가 n인가?
6. (그림) 위 데이터의 박스플롯을 그려라. 5수치 요약과 투키 울타리(Q1 − 1.5·IQR, Q3 + 1.5·IQR)를 inclusive 사분위로 계산하고, 울타리 밖 값을 표시하라.
7. (연결) 중앙값을 O(n log n) 정렬 없이 구하는 알고리즘은? 평균·최악 비용은? 값이 스트림으로 하나씩 들어오면 어떤 자료구조를 쓰나?
8. (장애 진단) 1.5 × IQR 밖 값을 노이즈로 지웠더니 p99가 개선됐다는 보고가 올라왔다. 무엇을 확인해야 하나?
9. (장애 진단) epoch 밀리초 값의 분산을 `(Σx² − (Σx)²/n)/(n − 1)`로 계산했더니 5.5×10⁸이 나왔다(이론 약 0.083). 원인과 대처는?
