# data-analysis/20-categorical-inference — 정답

## 정답

### 1. SRM 예

- n = 100,000: X² = 800²/50,000 + 800²/50,000 = **25.6**, df = 1, p ≈ **4.2 × 10⁻⁷**. 설계대로 배정·기록됐다면 이 정도 불균형이 우연히 나오기 매우 어렵다. 배정·로깅 경로가 한쪽을 다르게 걸렀다는 신호다.
- n = 1,000(508 : 492): X² = 8²/500 × 2 = **0.256**, p ≈ **0.61**. 같은 비율이어도 표본이 작으면 우연으로 충분히 설명된다.
- 차이의 절대 크기는 n에 비례해 커지고, 우연의 크기(표준편차)는 √n에 비례해 커진다. 그래서 같은 비율 차이도 n이 클수록 X²가 커진다.

### 2. 배심원 적합도

- 기대: 0.72 × 275 = 198, 0.07 × 275 = 19.25, 0.12 × 275 = 33, 0.09 × 275 = 24.75.
- X² = 49/198 + 45.56/19.25 + 64/33 + 33.06/24.75 ≈ 0.25 + 2.37 + 1.94 + 1.34 = **5.89**.
- df = 4 − 1 = **3**.
- p값 0.1171 = 자유도 3인 카이제곱 분포에서 **5.89 이상인 위 꼬리 넓이**. 귀무(무작위 선발)와 모형 가정이 맞을 때 이만큼 또는 더 극단적인 X²가 나올 확률이다. 직접 계산도 0.1171이었다.

### 3. iPod 기대 빈도

- 기대(공개, 일반) = (공개 행 합 61) × (일반 열 합 73) / (전체 219) = **20.33**.
- df = (2 − 1)(3 − 1) = **2**.
- 칸별 기여(SQL 출력): 일반·공개 16.53, 부정 가정·공개 12.07, 일반·숨김 6.38, 부정 가정·숨김 4.66, 나머지 0.35·0.14. **일반 질문에서 공개가 너무 적고(2 vs 20.33), 부정 가정 질문에서 공개가 많은 것**이 X² = 40.13의 대부분이다.

### 4. 합동 비율

- 귀무가 "p1 = p2"이면 두 그룹은 같은 비율 하나를 공유한다. 그 공통 비율의 가장 좋은 추정은 두 그룹을 합친 비율이다. 귀무가 참이라는 가정 아래에서 통계량의 분포를 구하는 것이므로 그 가정에 맞는 SE를 쓴다(OpenIntro 6.2.3).
- 신뢰구간은 "차이가 얼마인가"를 추정한다. 같다고 가정하지 않으므로 각 그룹의 p̂로 SE를 만든다(OpenIntro 6.2.2).

### 5. 2×2 = 두 비율 z

- 연속성 보정 없는 2×2 X²는 합동 비율 z 검정의 Z²과 같다. 카이제곱 p값은 **양측** z 검정의 p값과 같아서 양측 검정끼리 같은 검정이다(단측 z와는 p값이 다르다).
- 유방촬영: Z = −0.164, Z² = 0.0269, 2×2 X² = 0.0269, p는 둘 다 0.8698(실험).
- 책의 −0.17은 반올림한 차이 −0.00012와 SE 0.00070으로 나눈 값(−0.171)이다. Z = −0.17을 넣으면 p = 0.865로 책과 같다.

### 6. 작은 기대 빈도

- 기대 0.6 칸이 있는 3칸(n = 30): α = 0.05 → **0.0455**(비슷), α = 0.01 → **0.0261**(2.6배), α = 0.001 → **0.0043**(4.3배)(실험, 40000회).
- 기대가 고르게 4인 5칸(n = 20): 0.0502, 0.0096, 0.0010으로 **명목에 가깝다**.
- 이 실험에서는 "작은 수" 자체보다 **아주 희귀한 칸 하나가 X²를 지배하는 것**이 문제였고, 작은 α(꼬리 깊은 곳)에서 근사가 더 틀렸다. 일반화하지는 않는다 — 모든 칸의 기대가 아주 작아도 근사는 깨진다(예: 기대 1건씩 2칸이면 X²는 0 또는 2뿐이라 α 0.05에서 한 번도 기각하지 않는다, 계산). 그래서 모든 칸의 기대 빈도를 확인한다(OpenIntro 6.3.4: 모든 기대 빈도 5 이상).

### 7. 이벤트 단위 분할표

- **크다.** 실험에서 0.173(명목 0.05의 3배 넘음). 사용자 단위로 세면 0.051.
- 한 사용자의 페이지뷰 10개는 같은 성향을 공유해 서로 독립이 아니다. 표의 건수(10,000)가 독립 정보의 양(사용자 1,000명)보다 훨씬 커 보여서, 우연한 흔들림이 실제보다 작게 계산된다.
- 배정 단위(사용자)로 집계해 검정한다(예: 사용자별 "한 번이라도 전환").

### 8. 빈 칸 누락

- 원인: 건수가 0인 (범주, 범주) 조합은 `GROUP BY`에 행이 생기지 않는다. 그 칸의 기여 (0 − 기대)²/기대가 빠져 X²가 틀린다. 이 사례에서 범주는 3 × 2 그대로 남아 있어, 자유도를 범주 목록(원자료 `count(DISTINCT …)`)으로 세면 2로 맞다. 결과 행 수(5)를 칸 수로 착각하거나 범주 전체가 사라진 경우에만 자유도도 틀린다.
- 고치는 모양

```sql
SELECT q.question, d.disclosed, count(r.id) AS o
FROM (SELECT DISTINCT question FROM resp) q
CROSS JOIN (VALUES (true), (false)) d(disclosed)
LEFT JOIN resp r ON r.question = q.question AND r.disclosed = d.disclosed
GROUP BY 1, 2;
```

- 결과 행 수가 R × C인지 검사한다(SQL 실험: 5행 → 6행, `general | t | 0`).

### 9. 희귀 칸 경보

- 믿기 어렵다. 기대 0.6인 칸에 3건이면 그 칸 하나의 기여가 (3 − 0.6)²/0.6 = 9.6으로 X²를 지배한다. 카이제곱 근사가 이 꼬리에서 틀린다.
- 다시 계산: 같은 귀무(기준 분포)에서 표본을 많이 다시 뽑아 X² ≥ 관측값인 비율로 몬테카를로 p를 구한다. 실험의 [13, 14, 3]에서는 근사 0.0073 vs 몬테카를로 **0.0249**였다.
- 함께: 희귀 유형을 "기타"로 합쳐 기대 빈도 5 이상을 맞춘 뒤 다시 본다. 기대 빈도를 리포트에 같이 출력한다.
