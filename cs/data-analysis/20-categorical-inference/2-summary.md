# data-analysis/20-categorical-inference — 비율 추론·카이제곱 적합도·독립성 검정 — 정리 (힌트)

## 해결하는 문제

50:50으로 설계한 A/B 실험에 사용자가 이렇게 들어왔다. 우연인가, 버그인가?

```text
              A          B          합
  관측      50,800     49,200     100,000
  기대      50,000     50,000     (설계 비율 50:50)
  차이       +800       −800

  "0.8%p 차이면 거의 반반 아닌가?"  →  X² = 25.6, df = 1, p ≈ 4 × 10⁻⁷
  같은 비율(50.8 : 49.2)이라도 n = 1,000이면  →  X² = 0.256, p ≈ 0.61
```

- 세는 데이터(범주형)에서도 "관측이 기대와 얼마나 다른가"를 우연의 크기와 비교해 판단한다.
- 같은 비율 차이라도 표본이 크면 우연으로 설명하기 어려워진다. 반대로 표본이 작으면 큰 차이도 우연일 수 있다.

쉬운 예: 동전을 100번 던져 앞면이 58번 나왔다. 동전이 공정한가?

똑같은 구조다.\
"기대 50 : 50, 관측 58 : 42"를 "기대 50,000 : 50,000, 관측 50,800 : 49,200"으로 바꾸면 위 문제다.

실무 예:
- A/B 실험의 표본 비율 불일치(SRM) 점검 — 배정·로깅 버그 신호([data-analysis 15](../15-ab-pitfalls-srm-peeking/2-summary.md)).
- 가입 경로 × 결제 수단, 지역 × 오류 유형이 서로 관련 있는지.
- 두 그룹의 전환율(비율) 차이가 우연인지.

## 동작·원리

### 1. 한 비율 — p̂의 흔들림

```text
  n명 중 성공 x명 → 표본 비율 p̂ = x / n

  p̂의 표본 분포 (독립 + 성공·실패 조건을 만족하면 정규에 가깝다)
            ┌─┐
          ┌─┤ ├─┐
        ┌─┤ │ │ ├─┐
     ───┴─┴─┴─┴─┴─┴─┴───   중심 p,  SE = √(p(1 − p) / n)
               p
```

- *성공·실패 조건(success-failure condition)*: np ≥ 10이고 n(1 − p) ≥ 10이면 p̂를 정규로 근사해도 된다는 경험 규칙(OpenIntro 5.1.3, 6.1.1).
  - 신뢰구간에서는 p 대신 p̂로, 가설 검정에서는 귀무값 p0로 확인한다(OpenIntro 6.1).
- 표본 분포·표준오차·신뢰구간 자체는 [07](../07-sampling-distributions-and-clt/2-summary.md)·[08](../08-confidence-intervals/2-summary.md), 검정의 틀은 [09](../09-hypothesis-testing/2-summary.md)에서 다룬다. 이항분포는 [math/09](../../math/09-common-distributions/2-summary.md).
- 조건을 못 맞추면(OpenIntro 6.1.4): 검정은 귀무값으로 시뮬레이션해 p값을 구하고, 신뢰구간은 Clopper–Pearson 구간 같은 다른 방법을 쓴다.

### 2. 두 비율의 차이 — 귀무에서는 합동 비율

```text
  H0: p1 = p2         Z = (p̂1 − p̂2) / SE

  H0가 참이면 두 그룹은 같은 비율 → 둘을 합쳐 하나로 추정
  p̂pooled = (x1 + x2) / (n1 + n2)
  SE = √( p̂pooled(1 − p̂pooled) · (1/n1 + 1/n2) )
```

- *합동 비율(pooled proportion)*: 귀무가 "두 비율이 같다"일 때 쓰는, 두 그룹을 합친 비율(OpenIntro 6.2.3). 성공·실패 조건 확인과 SE 계산에 쓴다.
- 신뢰구간(차이의 크기 추정)에서는 합치지 않고 각 그룹의 p̂로 SE를 낸다(OpenIntro 6.2.2).

### 3. 카이제곱 적합도 — 칸이 여럿인 한 변수

```text
  OpenIntro 6.3 배심원 예: 배심원 275명의 인종 구성 vs 모집단 비율

           백인     흑인     히스패닉   기타     합
  관측      205       26        25       19     275
  기대      198     19.25       33     24.75    275    ← 모집단 비율 × 275

  X² = Σ (관측 − 기대)² / 기대
     = (205−198)²/198 + (26−19.25)²/19.25 + (25−33)²/33 + (19−24.75)²/24.75 = 5.89

  카이제곱 분포(df = 칸 수 − 1 = 3)       오른쪽으로 치우침
     │▁▃▆█▇▅▃▂▁▁
     │          ▁▁▁▁   ← p값 = 5.89 이상의 위 꼬리 넓이 = 0.1171
     └──────────────────────
       0      5.89
```

- *카이제곱 통계량 X²*: 칸마다 "(관측 − 기대)² / 기대"를 더한 값. 기대에서 멀수록 커진다.
- *자유도(df)*: 한 변수 적합도에서는 칸 수 k − 1(OpenIntro 6.3.4). 합계가 정해져 있으니 마지막 칸은 자동으로 정해진다.
- 위 꼬리만 본다. 큰 X²만이 귀무에 반하는 증거이기 때문이다(OpenIntro 6.3).
- 조건(OpenIntro 6.3.4 "Conditions for the chi-square test" 상자)
  1. **독립**: 표의 각 건이 다른 모든 건과 독립.
  2. **표본 크기**: 모든 칸의 **기대** 빈도가 5 이상.
  - OpenIntro는 조건을 확인하지 않으면 검정의 오류율이 영향을 받을 수 있다고 적는다.

### 4. 독립성 검정 — 두 변수의 분할표

```text
  OpenIntro 6.4 iPod 실험: 판매자에게 던진 질문 유형 × 결함 공개 여부
  관측 (기대)

                   일반         긍정 가정       부정 가정        합
  공개          2 (20.33)    23 (20.33)     36 (20.33)       61
  숨김         71 (52.67)    50 (52.67)     37 (52.67)      158
  합             73           73             73             219

  기대 빈도(i행, j열) = (i행 합) × (j열 합) / 전체 합        예: 61 × 73 / 219 = 20.33
  X² = 40.13,   df = (행 − 1)(열 − 1) = (2 − 1)(3 − 1) = 2,   p ≈ 2 × 10⁻⁹
```

- *분할표(contingency table, two-way table)*: 두 범주형 변수의 조합별 건수를 센 표.
- *독립성 검정*: 귀무 "두 변수는 독립(행 비율이 열마다 같다)"에서 기대 빈도를 만들고, X²로 관측과의 거리를 잰다(OpenIntro 6.4).
- 2×2 표의 카이제곱 검정은 **양측** 두 비율 z 검정과 같은 검정이다(단측 z의 p값은 다르다). 합동 비율 z 검정의 Z²이 (연속성 보정 없는) 2×2 X²와 같다(아래 실험). OpenIntro 6.4.2도 2×2 표에는 두 비율 방법을 쓰라는 지침을 소개한다.

### 실험: 손으로 짠 카이제곱 계산 vs 교재 값

- 카이제곱 위 꼬리 `P(X² ≥ x) = Q(df/2, x/2)`를 정규화 불완전 감마 함수로 직접 구현했다(`dist.py`, `math.lgamma`만 사용). 닫힌 식으로 아는 값부터 대조했다.

```text
chi2(2) P(X>=3)         = 0.223130160148  (exp(-1.5) = 0.223130160148 )
chi2(1) at 1.96^2       = 0.049996  (= 정규 양측)
chi2(1) 3.841 / (3) 7.815 = 0.05 0.05
```

- df = 2이면 꼬리가 정확히 e^(−x/2)다. df = 1이면 X² = Z²이라 정규 양측 확률과 같다. 표의 5% 임계값 3.841·7.815도 0.05를 돌려준다.
- 이어서 OpenIntro 예제를 원래 숫자로 다시 계산했다(`e20_book.py`, 호스트 Python 3.12.3).

```text
[6.3 배심원] 기대=[198.0, 19.250000000000004, 33.0, 24.75] X2=5.89 df=3 p=0.1171   (책: 5.89, 0.1171)
[6.4 iPod] 기대 1행=[20.33, 20.33, 20.33] X2=40.13 df=2 p=1.93e-09   (책: 40.13, 0.000000002)
[6.2.3 유방촬영] p1-p2=-0.00012 pooled=0.0112 SE=0.00070 Z=-0.164 p=0.8698   (책: -0.00012, 0.0112, 0.00070, -0.17, 0.8650)
                 2x2 X2=0.0269  Z^2=0.0269  chi2 p=0.8698
[SRM 예시] 50800:49200 X2=25.6 df=1 p=4.2e-07
[같은 비율, n=1000] 508:492 X2=0.256 p=0.613
```

- 배심원·iPod은 책과 같다.
- 유방촬영 Z가 −0.164 vs 책 −0.17인 것은 책이 반올림한 값(−0.00012 / 0.00070 = −0.171)으로 나눴기 때문이다. 반올림된 Z = −0.17을 넣으면 p = 0.865로 책과 같다(`out_book_rounded.txt`).
- 같은 2×2 표의 X²(0.0269)와 Z²(0.0269)가 같고 p도 같다.

### 5. 기대 빈도가 작을 때 — 근사가 꼬리에서 틀린다

```text
  X²가 카이제곱 분포를 따른다는 것은 "칸마다 충분히 큰 수"를 전제한 근사다
  희귀한 칸(기대 0.6건)에 관측 3건 → (3 − 0.6)² / 0.6 = 9.6   ← 한 칸이 X²를 지배
```

### 실험: 귀무가 참일 때 실제 1종 오류율

- 귀무가 참인 다항 표본을 40000번 뽑아, 카이제곱 근사 p값이 명목 α보다 작은 비율을 셌다. seed 2020. 코드 `e20_small.py`.

```text
귀무가 참인 표본을 40000회 뽑아, 카이제곱 근사 p값이 명목 α보다 작은 비율(= 실제 1종 오류율), seed 2020
  n=200, 5칸 균등 (기대 40씩)         : 명목 0.05 → 0.0487 | 0.01 → 0.0098 | 0.001 → 0.0011
  n=40, 5칸 균등 (기대 8씩)           : 명목 0.05 → 0.0475 | 0.01 → 0.0080 | 0.001 → 0.0008
  n=20, 5칸 균등 (기대 4씩)           : 명목 0.05 → 0.0502 | 0.01 → 0.0096 | 0.001 → 0.0010
  n=100, 희귀 칸 1% (기대 1)         : 명목 0.05 → 0.0549 | 0.01 → 0.0130 | 0.001 → 0.0036
  n=30, 희귀 칸 2% (기대 0.6)        : 명목 0.05 → 0.0455 | 0.01 → 0.0261 | 0.001 → 0.0043

몬테카를로 p값 예: n=30, 칸 확률 0.49/0.49/0.02, 관측 [13, 14, 3]
  X²=9.83, 카이제곱(2) 근사 p=0.0073, 몬테카를로 p=(1+498)/(1+20000)=0.0249
```

- 관찰
  - 기대 빈도가 고르게 4~8이면 이 설정에서는 α = 0.05·0.01·0.001 모두 명목에 가깝다. 칸이 고른 이 설정에서는 "5 이상" 규칙이 보수적이었다(설정 하나의 시뮬레이션이라 일반화하지 않는다).
  - 기대 1 이하인 **희귀 칸**이 있으면, α = 0.05에서는 비슷해 보여도 α = 0.01에서 1.3~2.6배, α = 0.001에서 3.6~4.3배로 거짓 양성이 늘었다. 작은 α(SRM 경보처럼 0.001 같은 작은 문턱 — 예시)에서 더 위험하다.
  - 관측 [13, 14, 3]의 근사 p는 0.0073인데, 같은 귀무에서 X²를 다시 뽑아 센 몬테카를로 p는 0.0249다. 근사가 증거를 3배 넘게 부풀렸다.
- *몬테카를로 p값*: 귀무 분포에서 데이터를 B번 새로 뽑아, 관측 X² 이상이 나온 비율로 p값을 구하는 방법. (1 + 횟수) / (1 + B)로 0이 되지 않게 한다. OpenIntro 6.1.4가 권하는 "귀무값으로 시뮬레이션" 방식과 같은 생각이다.
- 대안: 칸 합치기(희귀 범주를 "기타"로), 몬테카를로·정확 검정. 2×2 표의 피셔 정확 검정(Fisher's exact test)은 OpenIntro 4판 PDF 본문에 나오지 않는다(본문 검색으로 확인). OpenIntro 6.1.4는 조건이 깨질 때의 신뢰구간 방법(Clopper–Pearson)도 "이 책의 범위 밖"이라고 적는다.

### 6. 독립 조건 — 무엇을 한 건으로 세나

- 사용자 단위로 배정했는데 페이지뷰(이벤트) 단위로 세면, 한 사용자의 여러 이벤트가 같은 성향을 공유한다. 건끼리 독립이 아니다.

### 실험: 이벤트 단위로 센 2×2 카이제곱

- 귀무 참(두 그룹 차이 없음). 사용자 1000명을 50:50 무작위 배정, 사용자마다 페이지뷰 10개가 같은 전환 성향(지수분포 평균 0.1, 1에서 자름, 예시)을 공유. 2000회, seed 2024. 코드 `e20_cluster.py`.

```text
귀무 참, 사용자 1000명 × 페이지뷰 10개, 반복 2000회, seed 2024
  이벤트(페이지뷰) 단위 2x2 카이제곱: p<0.05 비율 0.173
  사용자 단위(한 번이라도 전환) 2x2 카이제곱: p<0.05 비율 0.051
```

- 이벤트 단위로 세자 효과가 없는데도 17.3%가 "유의"했다. 명목의 3배가 넘는다. 표본이 10,000건처럼 보이지만 독립인 정보는 사용자 1,000명분뿐이다.
- 배정 단위(사용자)로 세면 0.051로 명목과 맞는다. 배정 단위와 분석 단위는 [data-analysis 14](../14-ab-testing-design/2-summary.md).

## 쓰이는 자료구조·알고리즘

- **분할표**: (행 범주, 열 범주) → 건수의 2차원 배열 또는 해시 맵. SQL에서는 `GROUP BY 행, 열`. 행·열 합은 윈도 함수 `sum(o) OVER (PARTITION BY …)`로 한 번에 붙인다([database/05](../../database/05-window-functions-and-cte/2-summary.md)).
  - 빈 칸은 `GROUP BY`에 나오지 않는다. 모든 조합을 `CROSS JOIN`으로 만들고 `LEFT JOIN`으로 0을 채운다([database/04](../../database/04-sql-joins-and-aggregation/2-summary.md)).
- **카이제곱 꼬리 확률**: 정규화 불완전 감마 함수 Q(df/2, x/2). 급수(x가 작을 때)와 연분수(클 때)로 계산한다. 표준 라이브러리의 `math.lgamma`만 쓴다.
- **몬테카를로 재표집**: 귀무 분포에서 B번 다시 뽑아 비율을 센다. 난수의 성질은 [math/12-randomness-and-prng](../../math/12-randomness-and-prng/2-summary.md)(셔플 편향을 카이제곱으로 잡는 예도 있다).

## 적용 — 풀어나가는 법

### 1. 증상 → 원리 → 확인

| 증상 | 의심할 원리 | 확인 |
|---|---|---|
| 50:50 설계인데 50.8 : 49.2 | 배정·로깅 버그(SRM) | 적합도 X²(df 1), 작은 α로 판정 |
| 희귀 오류 유형 한 칸 때문에 "유의" | 기대 빈도 작은 칸 | 모든 칸 기대 빈도 출력, 몬테카를로 p |
| 이벤트 수만 큰 분할표가 "매우 유의" | 독립 위반(같은 사용자 반복) | 배정 단위로 다시 세기 |
| SQL 결과의 X²가 손계산과 다름 | 빈 칸 누락 | 모든 조합을 만든 뒤 0 채우기 |
| 큰 n에서 아주 작은 비율 차이도 유의 | 통계적 유의 ≠ 실질적 크기 | 차이의 신뢰구간과 실무 기준 비교 |

### 2. 코드로 확인 — 독립성 검정 (Python 3.12)

```python
from dist import chi2_sf          # Q(df/2, x/2) 직접 구현

def chi2_independence(table):
    R, C = len(table), len(table[0])
    rt = [sum(r) for r in table]
    ct = [sum(table[i][j] for i in range(R)) for j in range(C)]
    n = sum(rt)
    exp = [[rt[i] * ct[j] / n for j in range(C)] for i in range(R)]
    if min(min(r) for r in exp) < 5:
        print('경고: 기대 빈도 5 미만 칸 — 근사가 부정확할 수 있다')
    x2 = sum((table[i][j] - exp[i][j]) ** 2 / exp[i][j] for i in range(R) for j in range(C))
    df = (R - 1) * (C - 1)
    return x2, df, chi2_sf(x2, df)

print(chi2_independence([[2, 23, 36], [71, 50, 37]]))   # (40.13…, 2, 1.93e-09)
```

### 3. SQL로 확인 — 행 단위 데이터에서 X²까지 (PostgreSQL 17.11)

```sql
WITH cell AS (
  SELECT question, disclosed, count(*)::numeric AS o
  FROM resp GROUP BY question, disclosed
), e AS (
  SELECT o, sum(o) OVER (PARTITION BY question) * sum(o) OVER (PARTITION BY disclosed) / sum(o) OVER () AS ex
  FROM cell
)
SELECT round(sum((o - ex)^2 / ex), 2) AS x2,
       (SELECT (count(DISTINCT question) - 1) * (count(DISTINCT disclosed) - 1) FROM resp) AS df,
       round(min(ex), 2) AS min_expected
FROM e;
```

- 환경: `postgres:17` 컨테이너(PostgreSQL 17.11, `--network none`). iPod 표의 건수를 `generate_series`로 219행으로 풀어 넣고 다시 집계했다. 코드 `e20_pg.sql`.

```text
 question | disclosed | o  | expected | contrib
----------+-----------+----+----------+---------
 general  | t         |  2 |    20.33 |   16.53
 negative | t         | 36 |    20.33 |   12.07
 positive | t         | 23 |    20.33 |    0.35
 general  | f         | 71 |    52.67 |    6.38
 negative | f         | 37 |    52.67 |    4.66
 positive | f         | 50 |    52.67 |    0.14

  x2   | df | min_expected
-------+----+--------------
 40.13 |  2 |        20.33
```

- 칸별 기여(contrib)를 보면 X²의 대부분이 "일반 질문 → 공개 2건"(16.53)과 "부정 가정 → 공개 36건"(12.07)에서 나온다. 어느 칸이 귀무에서 벗어났는지 읽는 방법이다.
- 함정 재현: "일반 질문·공개" 2행을 지우자 `GROUP BY` 결과가 6칸에서 5칸으로 줄었다. 0인 칸이 사라진 것이다. `CROSS JOIN` + `LEFT JOIN`으로 만들면 `general | t | 0`이 다시 나온다.

```text
 question | disclosed | count            question | disclosed | o
----------+-----------+-------          ----------+-----------+----
 negative | t         |    36            general  | t         |  0
 positive | t         |    23            negative | t         | 36
 general  | f         |    71            positive | t         | 23
 negative | f         |    37            general  | f         | 71
 positive | f         |    50            negative | f         | 37
 (5 rows — 빈 칸 누락)                    positive | f         | 50
```

## 장애 시나리오와 대처

### 1. 기대 빈도가 작은 칸에 카이제곱 → 부정확 (⚠ 커리큘럼)

- 현상: 배포 전후의 오류 유형 분포를 비교했더니 p = 0.007로 "오류 패턴이 바뀌었다"는 경보가 떴다. 조사해 보니 희귀 유형 3건이 전부였다.
- 보이는 형태: 기대 0.6건인 칸에 3건 → 그 칸 하나가 X²의 대부분. 근사 p 0.0073 vs 몬테카를로 p 0.0249(실험).
- 원인: X²가 카이제곱 분포를 따른다는 것은 칸마다 충분한 건수를 전제한 근사다. 희귀 칸이 있으면 꼬리에서 근사가 틀려 작은 α에서 거짓 양성이 3.6~4.3배까지 늘었다(실험, α = 0.001).
- 대처: 모든 칸의 기대 빈도를 출력하고 5 미만이면 경고한다. 희귀 범주를 합치거나, 몬테카를로·정확 검정으로 p값을 구한다.

### 2. 이벤트 단위로 세서 "매우 유의"

- 현상: 사용자 단위로 배정한 실험을 페이지뷰 단위 분할표로 검정해 p = 0.001을 얻었다. 재실험에서 재현되지 않는다.
- 보이는 형태: 표의 합계가 사용자 수의 몇 배(페이지뷰 수). 헤비 사용자 몇 명이 한쪽 그룹에 몰리면 칸이 크게 흔들린다.
- 원인: 같은 사용자의 이벤트는 서로 독립이 아니다. 독립 조건 위반으로 효과가 없어도 17.3%가 유의했다(실험, 명목 5%).
- 대처: 배정 단위(사용자)로 집계해 검정한다. 이벤트 지표가 꼭 필요하면 사용자 단위 분산을 반영하는 방법을 쓴다([data-analysis 15](../15-ab-pitfalls-srm-peeking/2-summary.md)·[16](../16-metrics-design/2-summary.md)).

### 3. 빈 칸이 사라진 분할표

- 현상: SQL로 낸 X²가 노트북 계산과 다르다.
- 보이는 형태: `GROUP BY` 결과 행 수가 (행 범주 수 × 열 범주 수)보다 적다(SQL 실험: 6 → 5).
- 원인: 건수 0인 조합은 `GROUP BY`에 행이 생기지 않는다. 그 칸의 (0 − 기대)²/기대 기여가 빠진다. 위 SQL처럼 자유도를 원자료의 `count(DISTINCT …)`로 세면 이 사례의 자유도는 2 그대로다. 결과 행 수(5)를 칸 수로 착각하거나 범주 전체가 사라진 경우에만 자유도도 틀어진다.
- 대처: 범주 목록을 `CROSS JOIN`으로 만들고 `LEFT JOIN … count(r.id)`로 0을 채운다. 결과 행 수 = R × C를 검사한다.

### 4. 50.8 : 49.2를 "거의 반반"으로 넘김

- 현상: 50:50 설계 실험의 그룹 크기가 50,800 : 49,200인데 그대로 효과를 분석해 발표했다.
- 보이는 형태: 효과 크기는 그럴듯하지만, 나중에 한쪽 그룹에서 특정 브라우저의 이벤트가 누락된 것이 드러났다.
- 원인: n = 100,000에서 이 불균형은 X² = 25.6, p ≈ 4 × 10⁻⁷이다. 우연으로 보기 어렵다. 배정·로깅 경로가 한쪽을 다르게 걸렀다는 신호다.
- 대처: 효과를 보기 전에 SRM 적합도 검정부터 한다. 실패하면 결과를 쓰지 않고 원인을 찾는다(Fabijan 외 KDD 2019, [data-analysis 15](../15-ab-pitfalls-srm-peeking/2-summary.md)).

## 핵심 문장

- 범주형 데이터의 검정은 "관측 건수가 귀무에서의 기대 건수와 얼마나 먼가"를 X² = Σ(관측 − 기대)²/기대로 잰다.
- 적합도는 df = 칸 수 − 1, 독립성은 df = (행 − 1)(열 − 1)이고, 위 꼬리 넓이가 p값이다.
- 기대 빈도는 (행 합 × 열 합) / 전체 합이다. 2×2 독립성 검정은 합동 비율 양측 두 비율 z 검정과 같다(X² = Z²).
- 카이제곱 분포는 근사다. 독립이 깨지거나(같은 사용자 반복) 기대 빈도가 아주 작은 칸이 있으면 명목 1종 오류율이 유지되지 않을 수 있고, 방향은 설정에 따라 다르다. 이 노트의 실험에서는 이벤트 단위 집계(α 0.05)와 희귀 칸(작은 α)에서 거짓 양성이 늘었다.
- SQL에서 분할표를 만들 때는 0인 칸을 채워야 X²가 맞다. 자유도는 결과 행이 아니라 범주 목록으로 센다.
