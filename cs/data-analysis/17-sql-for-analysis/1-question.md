# data-analysis/17-sql-for-analysis — 질문

## 질문

1. (왜) grain(한 행의 단위)이란 무엇이고, `users ⟕ orders ⟕ order_items` 뒤의 grain은 무엇인가? 그 상태에서 `count(*)`로 전환율을 내면 왜 1을 넘을 수 있나?
2. (예측) 실험 데이터(사용자 400, 주문 247, 품목 488)에서 세 테이블을 LEFT JOIN한 뒤 "주문이 붙은 행 수 ÷ 사용자 수"로 전환율을 내면 얼마가 나오나? 맞는 전환율은? 매출은 몇 배로 부풀었나?
3. (처방) 팬아웃을 피하는 방법 두 가지를 대고, `sum(DISTINCT amount)`가 왜 처방이 아닌지 설명하라.
4. (경계) 코호트 리텐션 표에서 관측 끝을 넘은 칸을 0으로 세면 어떤 모양이 되나? 실험의 09-07 코호트 w3는 두 방식에서 각각 몇 %이고 분모는 몇 명인가?
5. (그림) 30분 무활동 기준 세션화를 `lag`와 누적 `sum`으로 하는 두 단계를 이벤트 여섯 개 예로 그려라. 연속 방문일은 어떤 다른 트릭으로 묶나?
6. (예측) 같은 세션화 결과에서 "세션당 이벤트 수"를 (a) 이벤트 수 ÷ 세션 수, (b) 이벤트 행마다 붙인 세션 크기의 평균으로 내면 어느 쪽이 큰가? 실험 값은?
7. (계산) 값 10, 20, 30, 40, 1000에 대해 PostgreSQL 17의 `percentile_cont(0.9)`와 `percentile_disc(0.9)`를 계산하라. 왜 cont 결과가 `616.0000000000001`로 나왔나?
8. (장애 진단) 월요일 리포트의 "일요일 매출"이 결제 관리자 화면보다 작고, 토요일 매출은 더 크다. 의심할 원인과 확인 쿼리, 고치는 SQL 모양은?
9. (연결) 합성 데이터를 `FROM users u, generate_series(0,27) d WHERE random() < f(d)`로 만들었더니 모든 사용자가 가입 후 같은 경과일에만 방문했다. 왜 그런가? 어떻게 확인하고 고치나?
