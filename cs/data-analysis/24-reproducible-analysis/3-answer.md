# data-analysis/24-reproducible-analysis — 정답

## 정답

### 1. 결과가 달라지는 출처

| 출처 | 어디서 달라지나 |
|---|---|
| 시드 없는 무작위(표본 추출·부트스트랩) | 같은 프로세스 안에서도 실행마다 |
| 해시 순서(set 순회, 동률 처리 — dict는 삽입 순서라 무관, set에서 만든 dict는 물려받음) | 프로세스마다(해시 무작위화) |
| 라이브러리 버전·함수 기본값 | 환경마다 |
| 노트북 숨은 상태(셀 실행 순서·반복 실행) | 처음부터 다시 돌릴 때 |
| 원본 덮어쓰기·손으로 고친 단계 | 처음부터 다시 만들 수 없음 |

- `ORDER BY` 없는 SQL 결과 순서도 "실행 계획·데이터 배치에 따라" 달라지는 순서 의존의 한 형태다.

### 2. 저장된 출력 vs 재실행

- 저장된 출력: c1 → c2 → c4 상태에서 [100, 120, 90, 300]의 평균 = 152.5.
- 위에서 아래로: 상한 200 적용 후 [100, 120, 90, 200]의 평균 = 127.5.
- 보고서에 붙은 152.5는 지금 노트북 코드로는 재현되지 않는다.

### 3. 누적된 상태

- 셀들은 전역 변수 `rows`를 공유한다. 상한 150을 실행한 순간 300(이미 200으로 깎인 값)이 150으로 바뀌었다. 200으로 되돌려 다시 실행해도 `min(150, 200) = 150`이라 값이 돌아오지 않는다.
- 결과 [100, 120, 90, 150]의 평균 = 115.0(실험 C). 지금 코드로는 나올 수 없는 값이다.

### 4. `random`의 보장

- 보장: 같은 시드를 다시 쓰면 같은 수열이 재현된다(여러 스레드가 돌지 않는 한). 새 시딩 방법이 추가되면 하위 호환 시더를 제공하고, 호환 시더에 같은 시드를 주면 `random()` 메서드가 같은 수열을 낸다.
- 비보장: `random` 모듈의 대부분 알고리즘과 시딩 함수는 Python 버전마다 바뀔 수 있다.
- 그래서 "어느 버전에서나 같은 `choices` 결과"는 문서가 보장하지 않는다. 버전을 고정·기록한다. 이 노트의 실험은 3.12.3과 3.12.14(같은 마이너 버전)에서만 같음을 확인했다.

### 5. 해시 순서와 동률

- 프로세스마다 해시 시드가 무작위라 `set` 순회 순서가 바뀌고, `max`는 동률 중 먼저 본 것을 돌려준다. 실험 B에서 세 프로세스가 ios·android·android를 골랐다.
- `PYTHONHASHSEED` 고정은 재현은 되지만 ① 해시 충돌 공격 방어(해시 무작위화)를 끄거나(0이면 무작위화가 꺼진다 — 문서) 고정된 시드로 약하게 만들고 ② 시드 값에 따라 여전히 다른 "1등"을 고른다(0 → android, 1·2 → web). 문제는 순서에 기대는 코드다. 정렬 후 고르거나 동률 규칙을 명시하면 해시 시드와 무관하게 같다(항상 android).

### 6. 분위수 정의

- exclusive(기본): 위치 = (n+1)×0.9 = 11.7 → 11번째(30)와 12번째(80) 사이 0.7 → 30 + 0.7×50 = 65.0.
- inclusive: 위치 = (n−1)×0.9 = 9.9(0부터) → 16과 30 사이 0.9 → 16 + 0.9×14 = 28.6.
- PostgreSQL 17 `percentile_cont(0.9)`는 28.600000000000005로 inclusive와 같은 값(부동소수점 끝자리 차이). `percentile_disc(0.9)`는 30.

### 7. Wilson 외 2017

- 원본 데이터 저장(1a), 데이터 처리의 모든 단계 기록 — 스크립트로(1e), 의존성·요구사항 명시(2g), 주석 처리로 동작을 바꾸지 않고 조건문으로 제어(2h), 원본은 `data`·생성물은 `results` 디렉터리(4c). 그리고 버전 관리 시스템 사용(5h).
- 크고 안정된 데이터베이스는 로컬 사본을 만들지 말고, 원본을 얻은 정확한 절차와 공식 버전 번호나 내려받은 날짜 같은 정보를 기록하라고 한다(1a).

### 8. DAG 재실행

- dims만 변경: dims, report(실험 D).
- raw 변경: raw, clean, features, report(dims는 그대로).
- 단계 키 = hash(단계 이름, 단계 입력·코드 버전, 상류 키들). raw가 바뀌면 raw의 키가 바뀌고, 그 키를 입력으로 쓰는 clean의 키가 바뀌고 … 하류로 연쇄된다. 키가 그대로인 단계는 캐시를 쓴다. 위상 정렬은 그래프에 적힌 의존 순서를 보장하므로, 의존을 빠짐없이 적고 단계가 공유 가변 상태에 기대지 않으면 숨은 순서 의존이 없다.

### 9. 다른 부트스트랩 구간

- 확인: 원 분석에 시드가 있었나, 재표집 횟수·방법(백분위 구간)·데이터가 같은가.
- 고치기: 시드를 정해 보고서에 적는다(실험 A: 시드 7이면 두 번 모두 [12.08, 31.92]). 시드 없이 돌린 값끼리는 어느 쪽도 틀리지 않았지만 같은 값을 재현할 수 없다.
- 끝자리가 크게 흔들리는 것은 재표집 횟수가 그 정밀도에 비해 부족하다는 신호다. 표본이 작고 극단값(80)이 하나 있으면 위쪽 끝이 그 값의 포함 횟수에 민감하다.
