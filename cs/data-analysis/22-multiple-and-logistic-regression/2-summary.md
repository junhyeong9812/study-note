# data-analysis/22-multiple-and-logistic-regression — 다중 회귀·모델 선택·로지스틱 회귀 — 정리 (힌트)

## 해결하는 문제

단순 회귀([13](../13-linear-regression/2-summary.md))는 설명 변수가 하나다. 실무 질문에는 변수가 여럿 얽혀 있다.

```text
  질문: "문의 건수가 많은 고객이 더 이탈하나?"
  단순 회귀   이탈 ~ 문의          → 문의 계수 +  (문의 많은 고객 = 오래 안 쓴 고객일 수도)
  다중 회귀   이탈 ~ 문의 + 미접속일 → "미접속일이 같은 고객끼리" 비교한 문의의 계수
  결과가 0/1  → 직선은 0~1 밖으로 나갈 수 있다 → 로지스틱 회귀
```

- 다중 회귀는 "다른 변수를 고정했을 때" 한 변수의 관계를 본다. 단순 회귀의 계수에 섞여 있던 다른 변수의 몫을 떼어 낸다.
- 결과가 이탈/유지처럼 둘 중 하나면 확률을 모델링한다. 확률은 0~1에 갇혀 있는데, 직선을 그대로 쓰면 예측이 0~1 밖으로 나갈 수 있다(OpenIntro 9.5.2). 로지스틱 회귀는 예측 확률을 그 범위 안에 둔다.

쉬운 예: 집값을 "넓이"로만 설명하면 넓이 계수에 "넓은 집은 대개 교외"라는 위치 효과가 섞인다. 위치를 같이 넣으면 "같은 동네에서 넓이가 1평 늘 때"를 본다.

똑같은 구조다.\
다만 넣은 변수끼리 너무 닮았거나(다중공선성), 예측 시점에 없는 정보를 넣으면(누설) 모델이 그럴듯한 거짓말을 한다.

실무 예:
- 이탈 예측, 결제 사기 점수, 광고 클릭 확률, 배송 지연 예측.
- "회귀 계수 부호가 상식과 반대"라는 리뷰 지적, "오프라인 AUC 0.99인데 운영에서 맞지 않는다"는 장애.

## 동작·원리

### 1. 다중 회귀 — 다른 변수를 고정한 기울기

```text
  ŷ = b₀ + b₁·x₁ + b₂·x₂ + … + b_k·x_k
        b₁ = x₂…x_k를 고정하고 x₁만 1 늘릴 때 ŷ의 변화

  최소제곱: 잔차 제곱합 Σ(y − ŷ)²을 최소로 하는 b를 고른다
  정규방정식: (XᵀX) b = Xᵀy      ← X는 [1, x₁, …, x_k] 행을 쌓은 행렬
```

- 계수는 정규방정식을 풀어 구한다. 행렬·내적 기초는 [math/13](../../math/13-linear-algebra-essentials/2-summary.md)에 있다.
  - *정규방정식(normal equations)*: 잔차 제곱합의 기울기를 0으로 놓아 얻는 연립방정식.
- OpenIntro 9.1.2의 예 9.12: 대출 금리 모형에서 단순 회귀로 0.74였던 파산 이력의 계수가, 다른 변수를 함께 넣자 0.39가 됐다. 책은 설명 변수끼리의 상관 때문에 단순 회귀가 다른 변수의 몫을 떠안았다고 설명한다.
- 범주형 변수는 지시 변수(0/1)로 넣는다. 수준이 p개면 p−1개 변수가 된다(OpenIntro 9.1.1·9.1.3).

### 2. 다중공선성 — 닮은 변수 둘이면 계수가 흔들린다

```text
  x₁ (지난달 방문 수)  ●●●●●●●●     x₂ (지난달 페이지뷰) 가 x₁과 거의 같이 움직임
                                    → "x₁만 1 늘리고 x₂는 고정"인 데이터가 거의 없다
  b₁ + b₂ (합)        잘 추정됨       x₂ ≈ x₁일 때 데이터가 말해 주는 것은 합뿐
  b₁, b₂ (각각)       크게 흔들림     표본이 조금만 바뀌어도 한쪽 +8, 다른 쪽 −6
```

- OpenIntro 9.1.2: 두 설명 변수가 상관되어 있으면 *공선(collinear)*이라 하고, 이것이 모델 추정을 복잡하게 한다. 관찰 데이터에서는 막을 수 없고, 실험은 보통 설명 변수가 공선이 되지 않게 설계한다.
  - *다중공선성(multicollinearity)*: 설명 변수 사이 상관이 높아 개별 계수가 불안정해지는 상태.
- 예측값 자체는 크게 흔들리지 않을 수 있다. 흔들리는 것은 **개별 계수의 해석**이다.
- 안정적인 조합은 변수 사이 관계와 단위에 따라 다르다. 이 실험처럼 x₂ ≈ x₁이면 b₁ + b₂, 일반적으로 x₂ ≈ c·x₁이면 b₁ + c·b₂다(`b₁x₁ + b₂(c·x₁ + 잡음) = (b₁ + c·b₂)x₁ + …`). 변수가 셋 이상 얽히면 상관 행렬만으로는 다 안 보인다.

### 실험: 거의 같은 두 변수 — 계수 부호가 뒤집힌다

참 모형 `y = 1·x₁ + 1·x₂ + 잡음`. x₂ = x₁ + 작은 잡음(표준편차 0.1) 또는 큰 잡음(3.0). n = 50짜리 표본 10개를 뽑아 각각 최소제곱을 풀었다.

```python
# scratchpad/da/14/e22a_collinear.py 핵심 — 중심화 후 2×2 정규방정식을 직접 푼다
s11 = Σa²; s22 = Σb²; s12 = Σab; s1y = Σac; s2y = Σbc        # a,b,c = 중심화한 x1,x2,y
det = s11*s22 - s12*s12
b1 = (s22*s1y - s12*s2y)/det;  b2 = (s11*s2y - s12*s1y)/det
```

(시뮬레이션, 호스트 Python 3.12.3 표준 라이브러리, n = 50, seed 0~9)

```text
참값 b1 = 1.0, b2 = 1.0  (n=50, 표본 10개, seed 0~9)
[x1·x2 거의 같음] corr(x1,x2) 평균 0.999
  b1:   -0.35   3.61   8.47   0.81  -0.62   3.61  -0.68  -2.05   0.48  -1.56
  b2:    2.21  -1.55  -6.41   1.18   2.83  -1.60   2.80   4.30   1.50   3.27
  b1+b2:  1.86   2.06   2.07   1.98   2.21   2.01   2.11   2.26   1.98   1.71
  부호가 음수로 뒤집힌 표본: 8/10
[x1·x2 덜 겹침] corr(x1,x2) 평균 0.689
  b1:    0.82   1.15   1.32   0.98   1.15   1.10   1.05   1.15   0.96   0.63
  b2:    1.04   0.92   0.75   1.01   1.06   0.91   1.06   1.11   1.02   1.08
  b1+b2:  1.86   2.06   2.07   1.98   2.21   2.01   2.11   2.26   1.98   1.71
  부호가 음수로 뒤집힌 표본: 0/10
y~x1 단순 회귀 statistics.linear_regression: 기울기 1.8625 절편 1.8089  (x2의 몫까지 x1이 떠안는다)
직접 구현 Sxy/Sxx 기울기: 1.8625
```

- 관찰 1: 상관 0.999에서는 표본 10개 중 8개에서 b₁이나 b₂가 음수였다. 참값은 둘 다 +1이다.
- 관찰 2: 합 b₁ + b₂는 두 경우 모두 2 근처로 안정적이다. 같은 seed에서 합이 두 경우에 똑같은 것은 우연이 아니다. `x₂ = x₁ + σz`이므로 (x₁, x₂) 회귀는 (x₁, z) 회귀를 다시 쓴 것이고, x₁의 계수 = b₁ + b₂는 σ와 무관하다(대수적 사실).
- 관찰 3: x₂를 빼고 단순 회귀를 하면 기울기 1.86이다. x₁이 x₂의 몫까지 떠안는다. 직접 구현과 `statistics.linear_regression`(Python 3.10+)이 같은 값을 냈다.
- 대처: 닮은 변수 중 하나만 넣는다, 둘을 합친 변수를 만든다, 또는 계수 해석을 포기하고 예측에만 쓴다. 상관 행렬과 계수의 표준오차로 미리 알아챈다.

### 3. 모델 선택 — R²는 변수를 더하면 오르거나 같다

```text
  R²        = 1 − SSE / SST                    변수를 더하면 SSE가 줄거나 같다 → R²는 오르거나 같다
  수정 R²   = 1 − [SSE/(n−k−1)] / [SST/(n−1)]   k가 늘면 벌점 → 쓸모없는 변수에 덜 속는다
  새 데이터 R²                                   진짜로 알고 싶은 것
```

- 수정 R² 식은 OpenIntro 9.1.3에서 가져왔다. n은 사례 수, k는 설명 변수 수다. 범주형 변수는 수준 수 − 1개로 센다.
  - *SSE*: 잔차 제곱합. *SST*: y의 평균 주변 제곱합.
- OpenIntro 9.2는 두 선택 전략을 든다. *후진 제거*(전부 넣고 수정 R²가 오르면 하나씩 뺀다)와 *전진 선택*(하나씩 넣는다)이다. p값 기준 방법도 있다(9.2.3).
- 수정 R²도 같은 데이터 안에서의 보정이다. 표본에 비해 후보 변수가 많으면 그것도 속는다(아래 실험). 최종 판단은 맞추는 데 쓰지 않은 데이터로 한다.

### 실험: 쓸모없는 변수를 더하면

참 모형 `y = 2x + 잡음`, n = 40. 순수 잡음 변수를 0~15개 더해 맞췄다. 성능은 같은 생성 규칙으로 만든 새 데이터 1,000건으로도 쟀다.

(시뮬레이션, 호스트 Python 3.12.3, seed 3, 가우스 소거로 정규방정식 풀이, `scratchpad/da/14/e22b_adjr2.py`)

```text
n=40, 참 모형 y = 2x + 잡음, 잡음 변수를 하나씩 추가 (seed 3)
  변수  1개: R² 0.453  수정 R² 0.438  새 데이터 R² 0.483
  변수  2개: R² 0.454  수정 R² 0.425  새 데이터 R² 0.481
  변수  4개: R² 0.461  수정 R² 0.399  새 데이터 R² 0.480
  변수  6개: R² 0.623  수정 R² 0.554  새 데이터 R² 0.219
  변수 11개: R² 0.718  수정 R² 0.608  새 데이터 R² -0.025
  변수 16개: R² 0.813  수정 R² 0.682  새 데이터 R² -0.679
```

- 관찰 1: 잡음 변수를 더할수록 R²는 0.453 → 0.813으로 올랐다.
- 관찰 2: 수정 R²는 변수 2·4개에서는 내려갔지만, 6개 이상에서는 같이 올랐다. 이 seed에서 잡음 변수 몇 개가 표본 40개 안에서 우연히 y와 상관이 있었다.
- 관찰 3: 새 데이터 R²는 0.483 → −0.679로 떨어졌다. 음수는 "평균으로 예측하는 것보다 못하다"는 뜻이다.
- 해석: 표본 안 지표(R²·수정 R²)는 과적합을 다 걸러 주지 않는다. 맞추는 데 쓰지 않은 데이터(검증 집합·시간 분할)로 고른다.

### 4. 로지스틱 회귀 — 확률을 log-odds로 펴서 직선을 맞춘다

```text
  확률 p  ──logit──>  log(p/(1−p))  =  b₀ + b₁x₁ + … + b_k x_k   (−∞ ~ +∞)
            <──sigmoid──  p = 1 / (1 + e^{−(b₀ + b₁x₁ + …)})

  p    0.007  0.05  0.27  0.50  0.73  0.95  0.993
  logit  −5    −3    −1     0    +1    +3    +5        (OpenIntro 그림 9.22의 점들)
```

- OpenIntro 9.5.2: 로지스틱 회귀는 결과가 두 수준인 일반화 선형 모형이다. 좌변을 그대로 두면 0~1 범위인데 우변은 그 밖으로 나갈 수 있다. 그래서 확률을 *logit* 변환한다.
  - *odds*: p/(1−p). 확률 0.75면 odds 3(3:1).
  - *logit*: odds의 자연로그.
- 계수 해석: b₁은 x₁이 1 늘 때 **log-odds**의 변화다. 확률의 변화가 아니다. 확률 변화는 출발점 p에 따라 다르다(p가 0.5 근처일 때 가장 크다).
- 맞추는 법: 최소제곱이 아니라 로그 손실(교차 엔트로피)을 최소로 한다. 닫힌 해가 없어 반복 계산(경사 하강·뉴턴법)으로 푼다.
  - 로그 손실의 기울기는 `Σ (예측 확률 − 정답) · x`다. 경사 하강은 이 방향의 반대로 계수를 조금씩 옮긴다.
  - *경사 하강(gradient descent)*: 손실이 가장 빨리 줄어드는 방향(기울기의 반대)으로 매개변수를 조금씩 옮기는 반복.

### 5. 누설 변수 — 예측 시점에 없는 정보

```text
  시간 ─────────────── 예측 시점 ─────────── 결과 확정 ───────── 기록
  미접속일·문의 건수 (있음)  │        이탈 결정         "해지 확인 메일 발송" = 1
                            │                         ↑ 결과가 정해진 뒤에야 생기는 값
  학습 데이터는 전부 사후에 모은 표 → 이 열이 같이 들어가면 모델이 "답"을 본다
```

- *누설(leakage)*: 학습에는 있지만 실제 예측 시점에는 없는(또는 결과에서 파생된) 정보가 특징으로 들어가는 것.
- 겉으로는 성능이 훌륭하다. 운영에서는 그 값이 아직 비어 있어 성능이 무너진다.

### 실험: 경사 하강 로지스틱 회귀 — 계수 복원과 누설

참 모형 `logit(p) = −1 + 1.5·x₁ − 0.8·x₂`로 4,000명을 만들었다. 누설 변수 `leak`은 이탈자의 95%, 비이탈자의 1%에서 1이다(이탈 확정 후에 기록된다고 가정). 3,000명으로 학습, 1,000명으로 시험했다.

```python
# scratchpad/da/14/e22c_logit.py 핵심
def sigmoid(z):     # 큰 |z|에서 exp 넘침을 피하는 두 갈래
    return 1/(1+math.exp(-z)) if z >= 0 else math.exp(z)/(1+math.exp(z))
for _ in range(epochs):                       # 배치 경사 하강, lr=0.5, 2,000회
    g = [0.0]*p
    for row, t in zip(X, y):
        e = sigmoid(dot(w, row)) - t          # 예측 − 정답
        for j in range(p): g[j] += e*row[j]
    w = [wj - lr*gj/n for wj, gj in zip(w, g)]
```

(시뮬레이션, 호스트 Python 3.12.3, seed 42, 학습 3,000 / 시험 1,000)

```text
계수 복원 (참값 -1.0, 1.5, -0.8): 추정 -1.050, 1.483, -0.877
정직한 모형  (x1,x2)       시험 AUC 0.832  정확도 0.772
누설 모형  (x1,x2,leak)    시험 AUC 0.990  정확도 0.977   leak 계수 7.55
누설 모형을 실제 예측 시점에(leak=0)  AUC 0.831  정확도 0.622  이탈 예측 비율 0.003 (실제 이탈 비율 0.381)
```

- 관찰 1: 경사 하강이 참 계수(−1, 1.5, −0.8)에 가까운 값(−1.05, 1.48, −0.88, 차이 0.08 이내)을 냈다. 남은 차이는 표본 3,000명의 우연 변동과 반복 횟수 제한에서 온다(해석).
- 관찰 2: 누설 변수를 넣으면 시험 AUC가 0.832 → 0.990, 정확도 0.772 → 0.977로 "좋아진다". 시험 집합도 같은 사후 표에서 나눴기 때문에 누설을 못 잡는다.
- 관찰 3: 실제 예측 시점처럼 `leak = 0`을 넣으면 정확도가 0.622로 떨어진다. 이탈자가 38.1%인데 모델은 0.3%만 이탈로 예측한다. 모델이 "leak이 0이면 이탈 아님"에 기대고 있었다.
- 관찰 4: AUC(순위)는 0.831로 정직한 모형과 비슷하게 남았다. leak을 빼도 x₁·x₂ 계수의 순서 정보는 남기 때문이다. 하지만 확률 수준이 틀어져 문턱 0.5 판정이 무너진다. 누설은 지표 하나만 봐서는 크기를 다 보지 못한다.
  - *AUC*: 무작위로 고른 양성 하나가 음성 하나보다 높은 점수를 받을 확률(점수가 같으면 ½로 센다: P(양성 > 음성) + ½·P(같음)). 순위만 본다. 모든 점수가 같으면 0.5다. 이 실험의 순위 합 코드도 동점에 평균 순위를 줘 이 정의를 따른다.

## 적용 — 풀어나가는 법

### 1. 계수가 상식과 반대일 때

- 증상: "방문 수가 늘수록 주문이 준다"는 음의 계수가 나왔다.
- 원리: 다중공선성(닮은 변수가 같이 들어감), 또는 교란·충돌 변수 문제([25](../25-causal-inference-basics/2-summary.md)).
- 확인:
  - 설명 변수끼리의 상관(`statistics.correlation`)을 본다. 0.9 이상이면 의심한다(문턱은 예시).
  - 부트스트랩·다른 기간 데이터로 다시 맞춰 계수 부호가 뒤집히는지 본다(위 실험처럼).
  - 닮은 변수를 하나 빼고 다시 맞춘다. 두 변수의 관계에 맞는 조합(x₂ ≈ x₁이면 합 b₁ + b₂, x₂ ≈ c·x₁이면 b₁ + c·b₂)이 안정적인지 본다.

### 2. 오프라인 성능이 너무 좋을 때 — 누설 점검

- 증상: 시험 AUC 0.99, 운영에서는 기대만 못하다.
- 원리: 예측 시점에 없는 정보가 특징에 섞였다.
- 확인 순서:
  1. 특징마다 "이 값은 예측 시점에 이미 정해져 있나?"를 적는다. 기록 시각(`created_at`)이 예측 기준 시각 뒤인 열을 찾는다.
  2. 특징 하나씩 빼며 성능을 본다. 한 특징이 성능을 혼자 끌어올리면 의심한다(위 실험의 leak 계수 7.55).
  3. 무작위 분할 대신 **시간 분할**(과거로 학습, 미래로 시험)로 다시 잰다. 같은 사용자의 행이 학습과 시험에 나뉘어 들어가지 않게 사용자 단위로 나눈다.

```sql
-- PostgreSQL 17: 예측 기준 시각 이전에 생긴 값만 특징으로 (예: 이탈 예측 기준일 2026-09-01)
SELECT c.user_id,
       count(*) FILTER (WHERE t.created_at <  timestamptz '2026-09-01') AS tickets_before,   -- 사용 가능
       count(*) FILTER (WHERE t.created_at >= timestamptz '2026-09-01') AS tickets_after     -- 누설: 쓰지 않는다
FROM customer c LEFT JOIN ticket t USING (user_id)
GROUP BY c.user_id;
```

- `timestamptz '2026-09-01'`은 세션 시간대로 해석된다. 기준 시각은 시간대를 붙여 적는다(예: `'2026-09-01 00:00+09'`). 세션 시간대 함정은 [database/27](../../database/27-temporal-types-and-session-timezone/2-summary.md).

### 3. 로지스틱 계수를 말로 옮길 때

- "x₁이 1 늘면 이탈 확률이 1.5 늘어난다"는 틀린 문장이다. b₁ = 1.5는 log-odds 변화다.
- odds로 말하면 `e^{1.5} ≈ 4.5`배다. 확률로 말하려면 출발점을 정해 두 확률을 계산해 보인다.

## 장애 시나리오와 대처

### 1. 다중공선성으로 계수 부호가 뒤집힘 (⚠ 커리큘럼)

- 현상: 분석 보고서가 "페이지뷰가 늘수록 구매가 준다"고 결론 내고, 페이지뷰를 줄이는 개편을 제안했다.
- 보이는 형태: 같은 모형을 다른 달 데이터로 다시 맞추면 부호가 바뀐다. 방문 수와 페이지뷰의 상관이 0.99대다. 계수의 표준오차가 계수보다 크다.
- 원인: 닮은 두 변수의 몫을 데이터가 가르지 못한다. 두 변수가 거의 같은 이 경우에는 합만 안정적이다(위 실험 10개 중 8개 부호 뒤집힘).
- 대처: 하나만 넣거나 합친 변수를 쓴다. 계수 해석이 목적이면 상관 행렬을 먼저 본다. 인과 주장이 목적이면 회귀 계수가 아니라 설계(실험·[25](../25-causal-inference-basics/2-summary.md))로 간다.

### 2. 누설 변수로 과대 성능 (⚠ 커리큘럼)

- 현상: 이탈 예측 모델이 오프라인 정확도 97.7%로 배포됐는데, 운영에서 이탈자를 거의 못 잡는다.
- 보이는 형태: 운영 예측의 이탈 비율이 0.3%, 실제는 38%(위 실험). 특정 특징 하나의 계수가 유난히 크다.
- 원인: 결과가 정해진 뒤에 기록되는 값(해지 확인 메일, 환불 요청, 마지막 상태 코드)이 특징에 들어갔다.
- 대처: 특징별 "사용 가능 시각"을 문서화하고, 기준 시각 이전 데이터만 쓰는 질의로 특징을 만든다. 검증은 시간 분할로 한다.

### 3. 변수를 늘려 R²를 자랑했다

- 현상: 변수 16개 모형이 R² 0.81로 "설명력이 좋다"고 보고됐다. 다음 달 예측이 평균보다 못하다.
- 보이는 형태: 표본 40건에 변수 16개. 새 데이터 R² −0.68(위 실험).
- 원인: 표본 안 R²는 변수를 더하면 오르거나 같다. 수정 R²도 후보가 많으면 속는다.
- 대처: 맞추는 데 쓰지 않은 데이터로 성능을 잰다. 변수 수 대비 사례 수를 본다. 사전에 정한 소수의 변수로 시작한다.

### 4. 로지스틱 계수를 확률 차이로 읽었다

- 현상: "쿠폰 계수 0.4 → 구매 확률 40%p 상승"으로 보고했다.
- 보이는 형태: 실제 쿠폰 그룹과 비쿠폰 그룹의 구매율 차이는 몇 %p다.
- 원인: 계수는 log-odds 단위다. 확률 변화는 출발점에 따라 다르다.
- 대처: odds 배수(e^b)로 말하거나, 대표 고객 몇 명의 예측 확률 차이를 계산해 보인다.

### 5. 무작위 분할에서 시간·사용자 누설

- 현상: 시험 성능은 좋은데 다음 달 데이터에서 떨어진다.
- 보이는 형태: 같은 사용자의 행이 학습과 시험에 모두 있다. 시험 기간이 학습 기간 사이에 끼어 있다.
- 원인: 모델이 사용자 고유 특성이나 미래 기간의 패턴을 외웠다.
- 대처: 사용자 단위·시간 단위로 나눈다. 시험 집합은 학습 기간 이후로 둔다.

## 핵심 문장

- 다중 회귀의 계수는 "다른 변수를 고정했을 때"의 기울기다. 단순 회귀 계수에 섞인 다른 변수의 몫을 떼어 낸다.
- 설명 변수가 서로 닮으면 개별 계수는 흔들리고 부호까지 뒤집히지만, 두 변수의 관계에 맞는 조합(거의 같으면 합)은 안정적일 수 있다. 계수 해석 전에 상관을 본다.
- 표본 안 R²는 변수를 더하면 오르거나 같다. 모델은 맞추는 데 쓰지 않은 데이터로 고른다.
- 로지스틱 회귀는 확률을 logit으로 펴서 선형 모형을 맞춘다. 계수는 log-odds 단위다.
- 예측 시점에 없는 정보가 특징에 들어가면 오프라인 성능이 부풀고 운영에서 무너진다. 특징마다 사용 가능 시각을 확인한다.
