# data-analysis/22-multiple-and-logistic-regression — 정답

## 정답

### 1. 단순 회귀 계수와 다중 회귀 계수

- 단순 회귀의 문의 계수에는 "문의가 많은 고객은 미접속일도 길다" 같은 다른 변수의 몫이 섞인다.
- 다중 회귀의 문의 계수는 **미접속일을 같은 값으로 고정했을 때** 문의가 1 늘면 예측이 얼마나 바뀌나다.
- OpenIntro 9.1.2 예 9.12: 대출 금리 모형에서 파산 이력 계수가 단순 회귀 0.74 → 다중 회귀 0.39. 책은 설명 변수끼리의 상관을 이유로 든다.
- 고정해도 인과 효과가 되는 것은 아니다. 넣지 않은 교란은 여전히 남는다.

### 2. 공선성 실험

- 상관 0.999: b₁은 −2.05 ~ 8.47, b₂는 −6.41 ~ 4.30으로 크게 흔들렸다. 10개 중 8개 표본에서 b₁이나 b₂가 음수였다. 참값은 둘 다 +1이다.
- b₁ + b₂는 1.71 ~ 2.26으로 2 근처에 안정적이다.
- 상관 0.69: b₁ 0.63 ~ 1.32, b₂ 0.75 ~ 1.11. 부호 뒤집힘 0/10.

### 3. 합이 똑같은 이유

- 우연이 아니다. `x₂ = x₁ + σz`이므로 `b₁x₁ + b₂x₂ = (b₁ + b₂)x₁ + b₂σz`다. (x₁, x₂) 회귀는 (x₁, z) 회귀를 다시 쓴 것이고, x₁의 계수는 b₁ + b₂다.
- 같은 seed면 x₁·z·잡음이 같다. z에 곱한 σ(0.1 또는 3.0)는 z 계수의 크기만 바꾸고 x₁ 계수는 바꾸지 않는다. 그래서 합이 같다(대수적 사실).

### 4. 잡음 변수를 더할 때

| 변수 수 | R² | 수정 R² | 새 데이터 R² |
|---|---|---|---|
| 1 | 0.453 | 0.438 | 0.483 |
| 4 | 0.461 | 0.399 | 0.480 |
| 16 | 0.813 | 0.682 | −0.679 |

- R²는 계속 올랐다. 수정 R²는 2·4개에서는 내려갔지만 6개 이상에서는 같이 올랐다(이 seed에서 잡음 변수 몇 개가 우연히 y와 상관).
- 새 데이터 R²는 −0.679까지 떨어졌다. 수정 R²는 과적합을 다 막지 못했다. 맞추는 데 쓰지 않은 데이터로 골라야 한다.

### 5. logit 대응과 계수 해석

```text
  p      0.05  0.27  0.50  0.73  0.95
  logit   −3    −1     0    +1    +3
```

- b₁ = 1.5는 x₁이 1 늘 때 **log-odds**가 1.5 는다는 뜻이다. odds로는 e^1.5 ≈ 4.5배.
- 확률 변화는 출발점에 따라 다르다. p = 0.5 근처에서 가장 크고, 0이나 1 근처에서는 작다. 그래서 "확률이 1.5 오른다"는 단위부터 틀렸다(확률은 0~1).

### 6. 경사 하강의 기울기와 안정한 시그모이드

- 로그 손실의 기울기: `Σᵢ (σ(wᵀxᵢ) − yᵢ) · xᵢ`. 예측 확률에서 정답을 뺀 값을 특징에 곱해 더한다. 갱신은 `w ← w − lr · 기울기 / n`.
- `1/(1+exp(−z))`에서 z가 큰 음수(예: −1000)면 `exp(1000)`이 넘친다(Python은 `OverflowError`).
- 피하는 법: z ≥ 0이면 `1/(1+exp(−z))`, z < 0이면 `exp(z)/(1+exp(z))`로 갈래를 나눈다. exp의 인자가 0 이하로 유지된다([math/15](../../math/15-numerical-stability/2-summary.md)).

### 7. 누설 모델의 운영 성능

- 오프라인(leak 포함): AUC 0.990, 정확도 0.977. leak 계수 7.55.
- 운영 시점처럼 leak = 0: 정확도 0.622, AUC 0.831, 이탈 예측 비율 0.003(실제 이탈 0.381).
- AUC가 덜 떨어진 이유: AUC는 순위만 본다. leak을 0으로 고정해도 x₁·x₂로 매긴 순서는 남는다. 하지만 모델이 "leak = 0이면 이탈 아님"에 기대 확률을 낮게 잡아, 문턱 0.5 판정이 거의 전원 "유지"가 됐다.

### 8. 누설 점검

1. 특징마다 "예측 시점에 이미 정해진 값인가"를 적는다. 기록 시각이 기준 시각 이후인 열을 찾는다.
2. 특징을 하나씩 빼며 성능을 본다. 한 특징이 성능을 혼자 끌어올리면 의심한다.
3. 무작위 분할 대신 시간 분할(과거로 학습, 미래로 시험)과 사용자 단위 분할로 다시 잰다.

```sql
SELECT c.user_id,
       count(*) FILTER (WHERE t.created_at < timestamptz '2026-09-01 00:00+09') AS tickets_before
FROM customer c LEFT JOIN ticket t USING (user_id)
GROUP BY c.user_id;
```

- 기준 시각에는 시간대를 붙인다. 세션 시간대에 따라 해석이 달라지기 때문이다.

### 9. 부호가 반대일 때 다른 원인

- 교란 변수 누락: 넣지 않은 공통 원인이 계수를 끈다.
- 충돌 변수·매개 변수를 넣음: 결과에 의해 정해지는 변수나 원인과 결과 사이의 변수를 통제하면 계수가 바뀌거나 뒤집힌다([25](../25-causal-inference-basics/2-summary.md)).
- 부분군 반전(심슨의 역설, [12](../12-correlation-vs-causation/2-summary.md)): 집단을 합치면 방향이 반대로 보인다.
- 회귀 계수는 인과 효과가 아니다. 인과 주장은 설계(실험·DAG 조정)로 한다.
