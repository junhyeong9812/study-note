# data-analysis/16-metrics-design — 지표 설계: 목표·가드레일·대리 지표, 그리고 비율 지표의 단위 — 정리 (힌트)

## 해결하는 문제

실험(14번)을 돌릴 수 있게 되면 다음 질문은 "**무엇이 좋아져야 좋은 변경인가**"다. 이것을 미리 정하지 않으면 두 가지가 무너진다.

```text
  지표를 미리 안 정함
   ├─ 결과를 본 뒤 유리한 지표를 고른다  → 다중 비교(11번)와 같은 모양, "너무 좋은 결과"
   └─ 쉬운 지표(클릭)만 올린다          → 진짜 목표(재방문·매출)가 내려가도 모른다

  가드레일을 안 정함
   └─ 목표 지표는 +1%, 그사이 p99 지연 +40%·오류 2배  → "성공"으로 출시
```

- *지표(metric)*: 관찰한 데이터를 숫자 하나로 접는 규칙. "사용자당 7일 재방문 일수", "요청 p95 지연"처럼 **무엇을·어떤 단위로·어떻게 접는지**까지가 지표다.

쉬운 예: 학교가 "수학 실력"을 올리고 싶다. 실력은 바로 잴 수 없으니 시험 점수를 본다.
- 점수만 상을 주면 문제 유형 암기가 늘어난다. 점수는 오르는데 실력은 그대로다.
- 그래서 다른 시험(처음 보는 문제)을 같이 보고, 결석률이 늘지 않았는지도 본다.

똑같은 구조다.\
실력 = 장기 목표, 시험 점수 = 대리 지표, 처음 보는 문제 = 목표에 더 가까운 지표, 결석률 = 가드레일이다.

실무 예:
- 추천 화면 실험에서 썸네일을 자극적으로 바꾸자 클릭률이 올랐다. 7일 재방문은 내려갔다(아래 실험 B).
- 무거운 위젯을 붙인 변형이 클릭을 조금 올렸지만, 요청 p95 지연이 약 35% 늘었다.
- 플랫폼 팀이 "평균 클릭률"을 두 가지 방식으로 계산해 두 대시보드의 숫자가 0.14와 0.22로 다르다(아래 실험 A).

## 동작·원리

### 1. 지표의 층 — 장기 목표에서 가드레일까지

```text
  장기 목표 (몇 달~몇 년)          예) 고객 생애 가치, 유지율          ← 실험 기간 안에 직접 못 잰다
        ▲ 인과적으로 끈다고 "믿는다" (검증 대상)
  OEC (실험 기간에 잰다)           예) 사용자당 활동 일수              ← 출시 판단의 기준
        ▲ 움직이는 동인
  대리·동인 지표 (빠르고 민감)      예) 클릭률, 장바구니 담기 비율       ← 원인 진단·조기 신호
  ─────────────────────────────────────────────────────────────────────
  가드레일 (나빠지면 안 되는 것)    예) p95 지연, 오류율, 크래시, SRM    ← 넘으면 OEC가 좋아도 출시 금지
```

- *OEC(Overall Evaluation Criterion, 종합 평가 기준)*: 실험의 목적을 나타내는 정량 지표. Kohavi 외 2020 1장은 OEC가 "실험 기간 같은 단기에 잴 수 있으면서, 장기 전략 목표를 인과적으로 끈다고 믿어지는 것"이어야 한다고 적는다.
  - 흔한 오해: OEC = 매출. 1장은 "이익"이 좋은 OEC가 아니라고 적는다. 가격 인상 같은 단기 조치로 당장 이익을 올리고 장기적으로 해칠 수 있어서다.
- *대리 지표(surrogate metric)*: 목표를 직접 재기 어려울 때 대신 보는 지표. 1장은 목표를 재기 너무 어려우면 대리 지표에 합의하라고 하고, 상세는 7장으로 넘긴다.
- *가드레일 지표(guardrail metric)*: 조직이 바꾸지 않겠다고 정한 것을 지키는 지표. 1장의 비유는 침몰하는 배에서 음식·조명을 개선하는 실험이다. 승객 안전은 OEC에 아주 큰 가중치를 주거나, 같은 효과로 가드레일로 둔다. 소프트웨어에서는 크래시가 그 자리다.
- 책의 구성(목차로 확인): 6장 "Organizational Metrics"(지표 분류·공식화·평가·진화, 가드레일 사이드바, 게이밍 사이드바), 7장 "Metrics for Experimentation and the OEC"(사업 지표 → 실험 지표, OEC로 묶기, Goodhart·Campbell·Lucas), 21장 "Sample Ratio Mismatch and Other Trust-Related Guardrail Metrics".
  - 6장의 분류 이름(목표·동인·가드레일 지표)은 본문을 열지 못해 확인하지 못했다 `[?]`. 위 그림은 1장에서 확인한 OEC·대리·가드레일 개념으로 그렸다.

### 2. 좋은 실험 지표의 조건

```text
  사업 지표(분기 매출, 월 활성 사용자)
        │  실험 기간(1~2주)에 안 움직이거나 너무 느리다
        ▼
  실험 지표: 잴 수 있다 · 계산 가능하다 · 차이를 볼 만큼 민감하다 · 제때 나온다
```

- Cambridge의 7장 요약은 실험 지표가 "단기(실험 기간)에 잴 수 있고, 계산 가능하고, 충분히 민감하고, 제때 나와야" 한다고 적는다. 지표가 여럿이면 OEC 하나로 묶는 것이 이상적이고, OEC는 여러 번 다듬어야 한다고 적는다.
- 1장은 OEC를 "비교적 짧은 기간(예: 1~2주)"에 잴 수 있어야 한다고 예를 든다.
- *민감도(sensitivity)*: 실제 효과가 있을 때 지표가 그 차이를 통계적으로 보여 줄 수 있는 정도. 분산이 크면 민감도가 낮다(10번 검정력과 같은 이야기).

### 3. 굿하트 — 대리 지표를 목표로 걸면

```text
  평소:      대리(클릭) ──── 상관 ──── 목표(재방문)
  압력 후:   대리를 직접 올리는 수단(자극적 썸네일)이 생긴다
             대리 ↑  ┄┄ 상관이 끊김 ┄┄  목표 ↓
```

- *굿하트의 법칙(Goodhart's law)*: 측정값을 목표로 삼아 압력을 주면, 그 값이 원래 나타내던 것을 더는 나타내지 않게 된다는 관찰. 이름·문구의 출처는 [engineering-practice/09-dora-metrics](../../engineering-practice/09-dora-metrics/2-summary.md)에 정리돼 있다(원문 쪽수 `[?]`).
- Kohavi 외 2020 7장에 "Goodhart's Law, Campbell's Law, and the Lucas Critique" 절이 있다(목차 확인, 본문 미열람).
- 막는 법은 하나가 아니다.
  - 대리 지표만으로 출시하지 않는다. OEC와 가드레일을 같이 본다.
  - 대리 지표가 목표와 같이 움직이는지 과거 실험들로 다시 확인한다.

### 4. 비율 지표 — 분자·분모·분석 단위

클릭률처럼 **합 ÷ 합**으로 정의되는 지표는 "무엇의 평균인가"가 두 가지다.

```text
  사용자   노출  클릭  사용자 CTR
  u1        60     6     0.10      ← 헤비 사용자: 노출 많고 CTR 낮음
  u2         4     1     0.25
  u3         5     2     0.40
  ─────────────────────────────
  비율 지표      = (6+1+2)/(60+4+5)        = 0.130   ← 노출 한 건당
  사용자 평균    = (0.10+0.25+0.40)/3      = 0.250   ← 사용자 한 명당
```

- 둘 다 맞는 숫자다. **질문이 다르다.** 비율 지표는 노출 가중이라 헤비 사용자가 지배한다. 대시보드마다 정의가 다르면 숫자가 어긋난다.
- *분석 단위 vs 배정 단위*: 배정은 사용자 단위(14번)인데 분석은 노출 단위로 하면 문제가 생긴다. 같은 사용자의 노출들은 서로 닮아(사용자마다 CTR이 다름) 독립이 아니다.
  - 노출을 독립 베르누이로 보고 분산 p(1−p)/노출수를 쓰면 분산을 **과소 추정**한다.
  - 사용자 단위로 접은 뒤 비율의 분산을 *델타 방법*으로 근사한다.
- *델타 방법(delta method)*: 함수 g(평균들)의 분산을 1차 테일러 전개로 근사하는 방법. 비율 R = X̄/Ȳ(X = 사용자 클릭, Y = 사용자 노출)이면

```text
  Var(R) ≈ (1/n) · [ σx²/μy²  −  2·μx·σxy/μy³  +  μx²·σy²/μy⁴ ]
  전제: 사용자들이 서로 독립·같은 분포, 사용자별 분자·분모의 분산(과 공분산)이 유한,
        n이 충분히 커서 1차 근사가 맞을 것, μy > 0
```

  - 근사다. 표본이 작거나 분모가 0 근처면 맞지 않을 수 있다. 사용자 단위 부트스트랩(07번)이 대안이다. Deng·Knoblich·Lu(arXiv 1803.06336)가 실무 적용을 정리했다. 위 식은 그 논문 3절 식 (6)(클러스터 = 사용자, 분석 단위 = 노출)과 같은 꼴이다.

### 실험 A: 같은 데이터의 두 "평균 CTR", 그리고 노출 단위 분산의 거짓 양성

(시뮬레이션, `ratio_metric.py`, 호스트 Python 3.12.3 표준 라이브러리, 시드 16. 사용자 4,000명 — 20%는 헤비 사용자(노출 30~80, CTR 평균 0.10), 나머지는 노출 1~8·CTR 평균 0.25. A/A 시험은 같은 4,000명을 무작위로 2,000:2,000으로 나누기를 1,000번 반복.)

```python
def naive_var(users):             # 노출 하나하나를 독립 베르누이로 본 분산
    p = ratio(users); n = sum(v for _, v in users)
    return p * (1 - p) / n

def delta_var(users):             # 사용자 단위 델타 방법: R = X̄/Ȳ
    xs = [c for c, _ in users]; ys = [v for _, v in users]
    mx, my = st.fmean(xs), st.fmean(ys)
    vx, vy, cxy = st.variance(xs), st.variance(ys), st.covariance(xs, ys)
    return (vx / my**2 - 2 * mx * cxy / my**3 + mx**2 * vy / my**4) / len(users)
```

```text
[1] 같은 데이터, 두 '평균 CTR'
    비율 지표 sum(click)/sum(view) = 0.1399
    사용자별 CTR의 평균           = 0.2220
    헤비 사용자 741명이 노출의 73.6%를 차지
[2] A/A 시험 1000회 (사용자를 50:50 무작위 배정, 실제 차이 0), 양측 alpha=0.05
    노출 단위(베르누이) 표준오차 평균 = 0.00293  거짓 양성 272/1000 = 27.2%
    사용자 단위(델타) 표준오차 평균  = 0.00537  거짓 양성 43/1000 = 4.3%
```

관찰과 해석(이 합성 데이터 한정):
- 사용자의 18.5%(741명)가 노출의 73.6%를 낸다. 그래서 비율 지표(0.14)는 헤비 사용자의 낮은 CTR 쪽으로 끌린다. 사용자 평균(0.22)과 차이가 크다.
- 노출 단위 표준오차는 사용자 단위의 약 55%(0.00293/0.00537)였다. 그 결과 차이가 없는 A/A에서 **27.2%**가 "유의"로 나왔다. 명목 5%의 5배가 넘는다.
- 델타 방법은 4.3%였다. 1,000회 반복의 몬테카를로 표준오차(√(0.05×0.95/1000) ≈ 0.7%p, 95% 범위 약 ±1.4%p)를 감안하면 5%와 어긋나지 않는다. 시드 하나·이 합성 분포 한 가지의 결과다.
- A/A 시험 자체가 지표·분산 계산을 검증하는 도구다. 거짓 양성률이 5%에서 크게 벗어나면 지표 정의나 분산 공식을 의심한다.

### 실험 B: 대리 지표로 고르면 vs 목표 + 가드레일로 고르면

(시뮬레이션, `goodhart_guardrail.py`, 호스트 Python 3.12.3, 시드 2016, 변형당 사용자 20,000명. 변형의 효과는 내가 넣은 가정이다 — B: 클릭 확률 ×1.25·재방문 ×0.94, C: 클릭 ×1.06·재방문 ×1.03·지연 ×1.35·오류율 0.2%→0.45%. 차이의 구간은 사용자 단위 정규 근사 95%.)

```text
변형            CTR 차이(95%CI)                 7일 재방문 차이(95%CI)                  p95 ms      오류율
A(대조)         +0.0000 [-0.0031,+0.0031]   +0.0000 [-0.0096,+0.0096]      274.1   0.0021
B(자극적 썸네일)    +0.0367 [+0.0333,+0.0400]   -0.0227 [-0.0323,-0.0131]      272.0   0.0019
C(무거운 추천)     +0.0113 [+0.0081,+0.0145]   +0.0082 [-0.0014,+0.0178]      368.9   0.0042
가드레일 규칙(예시): p95가 대조 대비 +10% 초과 또는 오류율이 대조의 1.5배 초과면 출시 금지 (대조 p95 274.1ms)
```

| 판단 기준 | 고르는 변형 |
|---|---|
| 대리 지표(CTR)만 | B — CTR 차이가 가장 크고 구간이 0을 멀리 벗어난다 |
| 목표(7일 재방문) | B 탈락(구간 전체가 음수). C는 +0.0082이지만 구간이 0을 포함 → 이 표본으로는 판단 보류 |
| 목표 + 가드레일 | C도 탈락 — p95 368.9ms(+34.6%), 오류율 0.0042(대조의 2배) |

- 해석: 이 모형에서는 CTR만 보면 목표를 해치는 B를 출시한다. 가드레일이 없으면 C의 지연·오류 악화가 "클릭 +"에 묻힌다.
- A 행은 대조군을 자기 자신과 뺀 줄이라 차이는 0이고, 진짜 차이 구간도 [0, 0]이다. 표에 찍힌 구간은 코드(`diff_ci`)가 두 표본을 독립으로 보고 계산한 폭이다. "대조군 크기의 독립 표본과 비교하면 이만큼 흔들린다"는 참고값일 뿐이다. 표의 형식을 맞추려고 넣은 줄이다.

## 적용 — 풀어나가는 법

### 1. 순서

1. **증상**: 실험 결과를 본 뒤 "어느 지표가 좋았나"를 찾고 있다. 또는 대시보드 둘의 CTR이 다르다.
2. **지표 명세를 먼저 쓴다**(실험 시작 전).

```text
  지표 이름   : 사용자당 7일 재방문 일수
  역할       : OEC | 동인 | 가드레일
  분자/분모   : 재방문 일수 합 / 배정된 사용자 수   ← 배정 단위와 같은 분모
  분석 단위   : 사용자 (배정 단위와 같음)
  집계 창     : 배정 후 0~7일, KST 날짜 경계
  방향·임계   : ↑가 좋음 / 가드레일이면 허용 악화 폭(예: p95 +10%)
  분산 계산   : 사용자 단위 표본 분산 (비율이면 델타 방법 또는 사용자 부트스트랩)
```

3. **원리 확인**: 비율 지표면 분자·분모를 사용자 단위로 접고 델타 방법을 쓴다.
4. **코드·SQL로 확인**: A/A 시험을 수백 번 돌려 거짓 양성률이 α 근처인지 본다(실험 A).

### 2. 비율 지표를 사용자 단위로 접는 SQL (PostgreSQL 17)

```sql
-- 사용자 단위로 접은 뒤, 델타 방법 재료(평균·분산·공분산)를 변형별로
WITH u AS (
  SELECT variant, user_id,
         count(*) FILTER (WHERE kind = 'click') AS x,   -- 사용자 클릭
         count(*) FILTER (WHERE kind = 'view')  AS y    -- 사용자 노출
  FROM exposure_events
  GROUP BY variant, user_id
)
SELECT variant, count(*) AS n,
       avg(x) AS mx, avg(y) AS my,
       var_samp(x) AS vx, var_samp(y) AS vy, covar_samp(x, y) AS cxy,
       sum(x)::numeric / sum(y) AS ratio
FROM u GROUP BY variant;
```

- 이 결과로 실험 A의 `delta_var` 식을 적용한다. 원시 이벤트 행으로 바로 `count(click)/count(view)`의 분산을 구하지 않는다.

### 3. 가드레일 판정 (Python)

```python
def guardrail_ok(ctrl, treat, max_p95_lift=0.10, max_err_ratio=1.5):
    p95c = statistics.quantiles(ctrl.latencies, n=20)[18]   # Python 3.12 기본 method='exclusive'
    p95t = statistics.quantiles(treat.latencies, n=20)[18]
    return p95t <= p95c * (1 + max_p95_lift) and treat.err_rate <= ctrl.err_rate * max_err_ratio
```

- 임계값(10%, 1.5배)은 예시다. 조직이 "무엇을 포기하지 않을지"로 정한다.
- 가드레일도 통계적 판정이 필요하다. 표본이 작으면 p95 차이 자체가 잡음일 수 있다(05·08번).

## 장애 시나리오와 대처

### 1. 대리 지표를 최적화하다 본 목표를 훼손 (⚠ 커리큘럼 — 굿하트)

- **현상**: 분기 내내 클릭률 실험이 "성공"했는데, 분기 말 유지율이 내려갔다.
- **보이는 형태**: 실험 리포트마다 CTR +2~4%, 재방문·매출 칸은 없거나 "유의하지 않음"으로 묻혀 있다.
- **원인**: 대리 지표를 직접 올리는 수단(자극적 문구, 강제 클릭 경로)이 생겼다. 대리와 목표의 상관이 끊겼다.
- **대처**: 출시 기준을 OEC로 바꾼다. 대리 지표는 진단용으로 내린다. 과거 실험에서 대리 변화와 목표 변화가 같은 방향이었는지 다시 확인한다.

### 2. 가드레일 없음 → 지연·오류가 악화된 채 출시 (⚠ 커리큘럼)

- **현상**: 출시 뒤 고객 문의와 타임아웃 경보가 늘었다.
- **보이는 형태**: 실험 리포트에는 OEC +1%만 있다. 운영 대시보드에서 p95가 실험 시작일부터 계단처럼 올라 있다.
- **원인**: 지연·오류·크래시를 실험 판정에 넣지 않았다. 평균 지연만 봐서 꼬리를 놓친 경우도 있다([reliability/02](../../reliability/02-slo-sli-error-budget/2-summary.md)).
- **대처**: 가드레일 목록과 허용 악화 폭을 실험 템플릿에 고정한다. 백분위 지표로 본다. 표본 비율 불일치(SRM)도 신뢰 가드레일로 본다([data-analysis 15](../15-ab-pitfalls-srm-peeking/2-summary.md)).

### 3. 두 대시보드의 "평균 CTR"이 다르다

- **현상**: 팀 A는 0.14, 팀 B는 0.22라고 보고한다.
- **보이는 형태**: 같은 기간·같은 테이블인데 숫자가 크게 다르다(실험 A의 0.1399 vs 0.2220).
- **원인**: 한쪽은 합÷합(노출 가중), 다른 쪽은 사용자별 비율의 평균이다. 둘 다 틀리지 않았다. 정의가 다르다.
- **대처**: 지표 명세에 분자·분모·분석 단위를 적는다. 대시보드 제목에 정의를 붙인다.

### 4. 분석 단위가 배정 단위보다 잘다 → 너무 자주 유의

- **현상**: CTR 실험이 거의 매번 유의하게 나온다. A/A에서도 자주 "차이"가 보인다.
- **보이는 형태**: 표준오차가 작고 p값이 작다. A/A 거짓 양성률이 5%보다 훨씬 크다(실험 A 27.2%).
- **원인**: 사용자 단위로 배정했는데 노출을 독립 표본으로 셌다. 같은 사용자의 노출은 상관이 있다.
- **대처**: 사용자 단위로 접고 델타 방법·사용자 부트스트랩을 쓴다. 정기 A/A 시험으로 분산 계산을 검증한다.

### 5. 지표가 너무 둔하다 → 실험이 안 끝난다

- **현상**: 4주를 돌려도 OEC 구간이 0을 포함한다.
- **보이는 형태**: 효과 추정치는 양수인데 구간이 넓다(실험 B의 C 변형 재방문 [−0.0014, +0.0178]).
- **원인**: 지표 분산이 크다(드문 사건, 긴 꼬리 금액). 목표 효과가 최소 탐지 효과보다 작다(10번).
- **대처**: 더 민감한 지표(구매 여부 vs 구매 금액, 상한 처리)를 OEC 후보로 검토한다. 표본 크기를 미리 계산한다. 끝없이 연장하지 않는다(15번 엿보기).

## 핵심 문장

- 지표는 분자·분모·분석 단위·집계 창까지가 정의다. 정의가 다르면 같은 데이터에서 다른 숫자가 나온다.
- OEC는 실험 기간에 잴 수 있으면서 장기 목표를 끈다고 믿어지는 지표다. 그 믿음 자체가 검증 대상이다.
- 대리 지표를 목표로 걸면 대리를 직접 올리는 수단이 생겨 목표와의 연결이 끊긴다(굿하트).
- 가드레일은 "좋아져야 할 것"이 아니라 "나빠지면 안 되는 것"이다. OEC가 좋아도 가드레일을 넘으면 출시하지 않는다.
- 배정 단위보다 잘게 분석하면 분산 추정이 틀린다. 같은 사용자의 노출이 서로 닮은(양의 상관) 흔한 경우에는 과소 추정해 거짓 양성이 늘어난다(실험 A). 사용자 단위로 접고 델타 방법·부트스트랩을 쓴다.
