# data-analysis/19-data-visualization-principles — 시각화 원칙: 인코딩 선택·비례 잉크·축·색 — 정리 (힌트)

## 해결하는 문제

같은 숫자도 그리는 방법에 따라 다르게 읽힌다. 대시보드·보고서의 그림이 숫자보다 먼저 판단을 만든다. 그림이 숫자와 다른 말을 하면 판단이 틀린다.

```text
  전환율 A 52.0%, B 55.0%  (차이 1.06배)

  y축 0부터                    y축 50부터
  A ######################     A ########
  B ########################   B ####################     ← "B가 2.5배"로 보인다
```

쉬운 예: 키 170cm와 175cm를 비교하는데 160cm부터 그리면, 막대가 10과 15라 "한 명이 1.5배 크다"처럼 보인다. 눈은 막대의 끝 위치보다 **막대의 길이**를 읽는다.

똑같은 구조다.\
그림의 잉크(막대 길이·면적·밝기)가 데이터 값과 비례하지 않으면, 눈금이 맞아도 인상이 틀린다.

실무 예:
- 배포 전후 응답 시간 그래프의 y축이 200ms에서 시작해 3% 개선이 "절반으로 줄었다"로 보고됐다.
- 가입자 수와 지연 시간을 이중 축에 그려 "가입자가 늘면 지연도 같이 는다"는 인상을 줬다. 실제 지연 변화는 3%였다.
- 채널별 매출 비중을 3D 파이로 그려 앞쪽 조각이 실제보다 크게 보였다.

## 동작·원리

### 1. 데이터 → 미적 요소(aesthetics) 매핑

```text
  데이터 값 ──척도(scale)──▶ 미적 요소 ──▶ 그림
  매출 1,200     선형 척도     막대 높이(위치·길이)
  채널 "앱"      범주 척도     색(색상)
  지연 p95       순차 척도     색(밝기)
```

- Wilke 2장: 자주 쓰는 미적 요소는 위치·모양·크기·색·선 굵기·선 종류다. 위치·크기·선 굵기·색은 연속·이산 데이터 둘 다 나타낼 수 있고, 모양·선 종류는 보통 이산 데이터만 나타낸다(그림 2.1 설명).
- *척도(scale)*: 데이터 값을 미적 요소 값으로 바꾸는 규칙. 예: 매출 0~2,000 → 막대 높이 0~300픽셀.
- 데이터 유형(Wilke 2.1: 수치형 연속·이산, 범주형 순서 없음·있음)이 쓸 수 있는 척도를 정한다. 순서 없는 범주에 밝기 순서가 있는 색을 쓰면 없는 순서를 암시한다. 측정 척도 자체는 [data-analysis 01](../01-data-types-and-measurement/2-summary.md).
- 인코딩 고르기의 기준(Wilke 17.3): 사람의 지각은 면적보다 **거리**를 더 정확히 판단한다. 값이 길이 하나로 표현되면(막대) 두 거리의 곱인 면적(파이 조각·원 크기)보다 정확히 읽힌다.
  - 위치·길이 > 각도·면적 > 색 같은 지각 정확도 순위(Cleveland–McGill 1984)가 흔히 인용된다 `[?]`(원 논문 미열람).

### 2. 비례 잉크 — 막대는 0에서 시작한다

```text
  비례 잉크 원칙: 칠해진 면적의 크기는 그것이 나타내는 값에 비례해야 한다
                                  (Bergstrom·West 2016, Wilke 17장 인용)

  막대 = 끝점 + 길이, 두 가지로 값을 말한다
   y축 0부터   끝점 52 · 길이 52   → 일관
   y축 50부터  끝점 52 · 길이 2    → 같은 요소가 두 값을 말함 (모순)

  점 = 끝점만 값을 말한다 → 축을 잘라도 모순이 없다 (Wilke 6.3 점 그림)
```

- Wilke 17.1: "선형 척도의 막대는 항상 0에서 시작해야 한다." 0이 아닌 값에서 시작하면 막대 길이는 "시작값을 넘는 정도"라는 임의의 양이 된다.
- 막대 대신 점을 쓰면 축 범위를 좁혀도 된다(Wilke 6.3). 차이를 강조해야 하는데 0부터 그리면 차이가 안 보일 때의 대안이다.
- 면적을 칠한 시계열(영역 그래프)도 같다. 기준선 위의 면적이 "기준선과의 차이"로 읽힌다(Wilke 17.1 주가 예).
- 로그 축의 막대는 논쟁적이다. Wilke 17.2는 "양(amount)을 보이나 비율(ratio)을 보이나"로 판단하라고 적는다.

### 3. 이중 축 — 오른쪽 축 범위는 자유롭다

```text
  왼쪽 축(가입 수) 100~122        오른쪽 축(지연 ms) 210~216        → 두 선이 같이 오른다
  왼쪽 축          0~150          오른쪽 축          0~400          → 지연은 평평하다
  같은 데이터, 축 범위 두 개를 그리는 사람이 고른다
```

- 두 변수의 단위가 다르면 두 축의 범위·비율을 맞출 기준이 없다. 그리는 사람이 범위를 고르면 두 선을 교차시키거나, 나란히 움직이게 하거나, 떨어뜨릴 수 있다.
- 대안(Wilke 13.3): 두 시계열을 **위아래 두 패널**로 따로 그린다. 함께 움직이는지 보고 싶으면 두 변수를 축으로 하는 **연결 산점도**를 그린다. (해석) 상대 변화만 보이려면 둘 다 같은 기준(시작점 = 100)으로 바꿔 한 축에 그리는 방법도 있다 — Wilke 20장 그림 20.5~20.8의 주가 예가 이 형태다(13.3의 권고는 아니다).
- 같은 단위의 두 축이면 격자 간격을 같게 둔다(Wilke 3.1). 단위가 다르면 가로세로 비율을 바꿔도 유효하지만, 중요한 차이가 보이게 비율을 고른다.

### 4. 3D — 세 번째 차원이 데이터를 말하지 않으면

```text
  위에서 본 파이: 25% 조각 = 면적 25%
  기울인 3D 원판: 앞쪽 조각은 옆면(두께)까지 보여 커 보이고, 뒤쪽 조각은 옆면이 가려져 작아 보인다
        ____________
      /   뒤 25%    \
     |---------------|
      \   앞 25%    /  ← 옆면 띠
       \___________/
```

- Wilke 26.1: 파이를 3D로 돌리면 앞쪽 조각은 실제보다 커 보이고 뒤쪽은 작아 보인다. 같은 절의 3D 막대 예(타이타닉 승객 수)에서는 막대가 뒷면의 눈금선과 떨어져 있어 모든 막대가 실제보다 짧아 보인다.
- 3D 위치 척도(3D 산점도)도 2D 화면에서는 점의 실제 위치를 거꾸로 읽어 내기 어렵다(26.2). 회전 가능한 인터랙티브 화면이나 실제 3D 대상(지형)은 예외로 든다(26.3).

### 5. 색 — 세 종류 척도와 무지개의 함정

```text
  범주형(qualitative)   ■ ■ ■ ■ ■     구분만, 순서 없음 — 3~5개가 좋고 8~10개 넘으면 짝 맞추기가 부담
  순차(sequential)      □ ▢ ▣ ▤ ■     작다 → 크다, 밝기가 한 방향으로 변함
  발산(diverging)       ■ ▣ □ ▣ ■     가운데 기준(0, 목표)에서 양쪽으로
```

- 개수 기준은 Wilke 19.1의 경험칙이다(3~5개, 8~10개 이상은 부담).
- 무지개 척도는 밝기가 단조롭지 않다(Wilke 19.2). 회색으로 바꾸면 중간 어두움 → 밝음 → 아주 어두움 → 다시 중간 어두움으로 오르내린다(Wilke 그림 19.4 설명). 밝기 변화도 고르지 않다. 그래서 데이터의 특징을 가리거나 임의의 구간(밝은 띠)을 두드러지게 한다.
- 색각 이상 독자를 고려한다(19.3). 어두움 → 밝음으로 잘 만든 순차 척도는 대체로 문제가 없다. 발산 척도는 더 까다롭다. 흔한 빨강-초록 대비는 적록 색각 이상에서 거의 구분되지 않는다.
- 색만으로 구분하지 말고 모양·직접 레이블을 겹쳐 쓴다(Wilke 20장 중복 인코딩).

### 6. 순서와 맥락

- 순서 없는 범주의 막대는 값 크기순으로 정렬한다. 순서 있는 범주(나이대, 요일)는 원래 순서를 유지한다(Wilke 6.1).
- 기본값이 알파벳순인 도구가 많다. 알파벳순은 대부분 의미 없는 순서다.

### 실험: 같은 숫자, 다른 인상 — 수치로 확인

(실험, `viz.py`, 호스트 Python 3.12.3 표준 라이브러리. 데이터는 예시 값. 3D 파이는 단순 모형이다 — 윗면은 정사영 타원(세로 0.45배), 옆면은 화면 아래쪽 반원만 보이는 높이 0.18의 띠, 원근 효과 없음.)

```python
def bars(data, lo, width=40, hi=None):          # y축 시작 lo에서 그린 텍스트 막대
    hi = hi or max(v for _, v in data)
    for k, v in data:
        n = round((v - lo) / (hi - lo) * width)
        print(f"    {k:<4}{v:6.1f} |{'#' * n}")

def lum(r, g, b):                               # sRGB 상대 휘도 (WCAG 2.2 정의)
    return 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b)
```

## 쓰이는 자료구조·알고리즘

- 커리큘럼 🔧 칸은 "—"이다. 시각화 원칙은 계산보다 지각의 문제다.
- 그래도 그림 뒤에는 계산이 있다.
  - **선형 위치 척도 = 선형 사상** — (값 − 하한)/(상한 − 하한) × 길이. 실험 [1]·[2]의 왜곡은 이 식의 하한·상한 선택에서 나온다. 로그 척도처럼 같은 데이터 간격이 화면에서 다른 간격이 되는 비선형 척도도 있다(Wilke 3.2).
  - **구간 나누기(binning)** — 히스토그램 막대는 구간별 개수다. 구간 폭이 모양을 바꾼다(Wilke 7장, [data-analysis 06 EDA](../06-exploratory-data-analysis/2-summary.md)).
  - **색 공간 변환** — HSV → sRGB → 선형화 → 상대 휘도(실험 [4]). 순차 척도를 고를 때 밝기가 단조인지 이 계산으로 확인한다.

## 적용 — 풀어나가는 법

### 1. 순서

1. **증상**: 그림을 본 사람의 결론이 숫자 표의 결론과 다르다("두 배"·"같이 움직인다"·"앞쪽이 크다").
2. **원리로 내려간다**: 잉크가 값에 비례하나(막대·면적의 기준선), 축 범위를 누가 골랐나(이중 축), 3D·색이 값과 무관한 크기·밝기를 더하나.
3. **수치로 확인한다**: 막대 길이 비 vs 값의 비, 두 계열의 실제 변화율, 색 척도의 밝기 단조성.

### 2. 그림 점검표

```text
  [ ] 막대·영역의 기준선이 0인가? 아니면 점·선으로 바꿨나?
  [ ] 이중 축 대신 두 패널 / 지수화(시작=100) / 연결 산점도를 검토했나?
  [ ] 3D·그림자·원근을 뺐나?
  [ ] 범주 색이 5개 이하인가? 넘으면 묶거나 직접 레이블
  [ ] 연속 값의 색은 밝기가 한 방향으로 변하는 순차 척도인가? 기준점이 있으면 발산 척도
  [ ] 막대 순서: 순서 없는 범주는 값순, 순서 있는 범주는 원래 순서
  [ ] 축 제목에 단위·기간·시간대를 적었나?
```

### 3. 축 범위를 숫자로 점검 (Python)

```python
def ink_ratio(a, b, baseline):
    """막대 두 개의 길이 비와 값의 비. 둘이 크게 다르면 기준선이 인상을 왜곡한다."""
    return (b - baseline) / (a - baseline), b / a

print(ink_ratio(52, 55, 0))    # (1.0577, 1.0577)
print(ink_ratio(52, 55, 50))   # (2.5, 1.0577)
```

- 보고서 생성 코드에 이런 검사를 넣어 기준선이 0이 아닌 막대 그림에 경고를 띄울 수 있다.

## 장애 시나리오와 대처

### 1. 잘린 y축으로 차이 과장 (⚠ 커리큘럼)

- **현상**: "B 안이 압도적"이라는 결론으로 회의가 끝났는데 실제 차이는 3%p였다.
- **보이는 형태**: 막대 그래프의 y축이 50에서 시작한다. 막대 길이 비 2.5, 값의 비 1.06(실험 [1]).
- **원인**: 막대의 길이가 "50을 넘는 정도"를 나타냈다. 눈은 끝점보다 길이를 읽는다.
- **대처**: 막대는 0에서 시작한다. 좁은 범위를 보여야 하면 점 그림으로 바꾸고 축 범위를 명시한다.

### 2. 3D 파이로 비율 오독 (⚠ 커리큘럼)

- **현상**: 앞쪽에 배치된 채널의 비중을 실제보다 크게 기억한다.
- **보이는 형태**: 같은 25% 조각이 앞에서는 보이는 넓이 34.3%, 뒤에서는 19.9%(실험 [3] 단순 모형).
- **원인**: 3D를 2D로 투영하면 데이터가 왜곡되고, 눈의 보정은 부분적일 뿐이다(Wilke 26.1). 실험 모형에서는 앞쪽 조각에만 옆면이 보이는 것이 원인이었다. 면적 비교 자체도 길이 비교보다 부정확하다.
- **대처**: 2D 막대(정렬)나 2D 파이(조각 몇 개일 때)로 바꾼다. 비율을 숫자 레이블로 같이 쓴다.

### 3. 이중 축 조작 (⚠ 커리큘럼)

- **현상**: "가입자가 늘자 지연도 같이 늘었다"는 인상의 그래프가 용량 증설 결정에 쓰였다.
- **보이는 형태**: 두 선이 거의 겹쳐 오른다. 오른쪽 축이 210~216ms다(실험 [2] 범위 A). 실제 지연 변화 +2.9%.
- **원인**: 단위가 다른 두 축의 범위를 그리는 사람이 골라 두 선의 모양을 맞췄다.
- **대처**: 두 패널로 나눈다. 같은 기준 지수(시작 = 100)로 한 축에 그린다. 관계를 묻는다면 산점도·상관([data-analysis 12](../12-correlation-vs-causation/2-summary.md))으로 답한다.

### 4. 무지개 색 척도가 없는 경계를 만든다

- **현상**: 지역별 지연 지도에서 노란 띠 지역이 "문제 지역"으로 지목됐다. 값은 이웃과 크게 다르지 않았다.
- **보이는 형태**: 밝기가 튀는 노랑·청록 근처에서 경계가 보인다(실험 [4] 상대 휘도 0.928 지점).
- **원인**: 색상환 척도는 밝기가 단조롭지 않다(Wilke 19.2).
- **대처**: 밝기가 한 방향으로 변하는 순차 척도를 쓴다. 기준점이 있으면 발산 척도를 쓴다.

### 5. 범주 색이 너무 많아 범례 대조가 안 된다

- **현상**: 서비스 15개를 색 15개로 그린 그래프에서 아무도 특정 선을 찾지 못한다.
- **보이는 형태**: 비슷한 색이 여러 개, 범례와 선을 오가며 맞춘다.
- **원인**: 범주 색은 3~5개가 적당하고 8~10개를 넘으면 대조가 부담이다(Wilke 19.1).
- **대처**: 상위 몇 개만 색, 나머지는 회색. 작은 그림 여러 개(small multiples, Wilke 21장)로 나눈다. 선 끝에 직접 레이블을 단다.

## 핵심 문장

- 눈은 막대의 끝점보다 길이를, 면적보다 거리를 읽는다. 그래서 잉크(길이·면적)가 값에 비례해야 한다.
- 선형 척도의 막대는 0에서 시작한다. 좁은 범위를 보여야 하면 막대 대신 점을 쓴다.
- 이중 축의 범위는 그리는 사람이 고를 수 있어 두 선의 관계를 마음대로 만든다. 두 패널·지수화·산점도로 바꾼다.
- 3D는 데이터를 말하지 않는 크기를 더한다. 앞쪽 조각은 커 보이고 뒤쪽은 작아 보인다.
- 크기를 나타내는 순차 척도의 색은 밝기가 한 방향으로 변해야 한다. 의미 있는 가운데 기준이 있으면 가운데가 밝고 양쪽 끝으로 어두워지는 발산 척도를 쓴다(Wilke 4.2). 무지개 척도는 없는 경계를 만든다.
