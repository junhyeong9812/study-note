# testing/14-property-based-testing — 질문

## 질문

1. (왜) 예제 기반 테스트만 있으면 어떤 버그가 남나? 속성 기반 테스트를 이루는 세 요소(성질·생성기·축소)는 각각 무엇을 맡나?
2. (패턴) 다음 함수에 쓸 성질을 하나씩 대라: JSON 직렬화/역직렬화, 정렬 함수, 최적화한 새 가격 계산(옛 구현이 있음), 공백 정규화 함수. 성질이 구현을 베끼면 왜 안 되나?
3. (예측) `dedup`이 인접 중복만 지우는 버그가 있다. 성질 "결과에 중복이 없다"를 fast-check 기본 설정(100회)으로 돌릴 때, 원소 생성기가 전체 int 범위일 때와 0..3 범위일 때 반례를 찾는 비율은 어떻게 다를까? 축소된 반례는 어떤 모양일까?
4. (예측) `unrle`이 반복 횟수를 한 자리 숫자로만 읽는 버그가 있다. 문자 `a`·`b`·`c`를 하나씩 뽑아 최대 30자 문자열을 만드는 생성기로 왕복 성질을 돌리면 잡힐까? 생성기를 어떻게 바꾸면 잡히나?
5. (경계) 성질이 100회(또는 1000회) 통과했다는 것은 무엇을 뜻하고, 무엇을 뜻하지 않나? 통과 뒤에 무엇을 확인해야 하나?
6. (원리) 정수 축소는 어떤 모양으로 후보를 내나(fast-check 4.10.2 기준)? 축소 결과가 전역 최소가 아닐 수 있는 이유를 `[2147483618, 0, 2147483618]`로 설명하라.
7. (역사) QuickCheck 논문(ICFP 2000)의 본체에 축소가 있었나? 논문이 분포를 확인하라고 보인 도구와 그 예의 수치는?
8. (장애 진단) 속성 테스트가 CI에서 가끔(실행 네 번에 한 번꼴) 실패하고 로컬에서는 재현이 안 된다. 팀은 재시도를 붙이려 한다. 무엇을 의심하고, 어떻게 재현·고정하나?
9. (장애 진단) 정렬 성질의 반례가 `[68330691, -2079152958]`처럼 큰 수로 남는다(실행마다 값이 다르다). 축소가 왜 더 못 줄였고, 반례에서 무엇을 읽어야 하나?
10. (연결) 조건부 성질 `ordered xs ==> ordered (insert x xs)`에서 생기는 문제는? 논문이 권하는 해법은?
