## 질문

1. (왜) 단위·통합·계약 테스트를 다 통과해도 E2E가 필요한 이유는? 그런데도 E2E를 적게 두라고 하는 이유 세 가지는(Fowler 2012, Wacker 2015)?
2. (그림) 컴포넌트/UI 테스트, 브라우저 UI 테스트, 전 구간 E2E의 범위를 한 그림에 그려라. SWE@G 14장이 권하는 "UI/API 경계 분리"는 그림의 어디를 자르나?
3. (예측) 로그인 폼의 클래스 이름을 바꾸고 감싸는 div를 하나 추가했다(동작은 같다). CSS 경로 선택자로 쓴 테스트 4개와 역할·레이블로 쓴 테스트 4개는 각각 몇 개 실패하나?
4. (예측) 이메일 `<label for="mail">`이 `<input id="email">`과 어긋났다. 두 스타일의 테스트는 각각 어떻게 되나? Testing Library의 실패 메시지는 무엇을 알려 주나?
5. (경계) Testing Library 쿼리 우선순위를 대고, `getByTestId`를 마지막에 두는 이유를 말하라. `getBy`·`queryBy`·`findBy`의 차이는?
6. (연결) 고정 `sleep` 대신 무엇을 쓰나? Playwright의 actionability 검사 네 가지는?
7. (경계) jsdom으로 하는 UI 테스트가 못 잡는 문제는? 근거(jsdom 문서)와 함께 말하라.
8. (장애 진단) 디자인 개편 PR 하나에 UI 테스트 200개가 `Cannot read properties of null`로 실패했다. 진단 순서와 재발 방지책은?
9. (장애 진단) E2E 통과율이 날마다 5%·54%·1%·84%로 출렁이고 팀이 빨강을 무시하기 시작했다. 구조적 원인과 대처는?
