# testing/10-testing-time-and-concurrency — 질문

## 질문

1. (왜) `LocalDate.now()`를 직접 부르는 코드는 왜 "오늘"만 시험할 수 있나? Java `Clock` javadoc이 권하는 모범 사례와, SWE@G 13장이 제시하는 대안을 말하라.
2. (구분) `Clock.fixed`·`Clock.offset`·직접 만든 가변 시계는 각각 어떤 테스트에 맞나? 가변 시계를 직접 만들 때 `Clock` javadoc이 요구하는 성질은?
3. (예측) 운영 코드가 `LocalDate.now(clock)`으로 주문일을 정하고, 테스트가 기대값을 `LocalDate.now(clock)`으로 다시 계산한다. 시계가 읽을 때마다 1ms씩 흐른다면 12:00:00 시작과 23:59:59.999 시작에서 결과는?
4. (예측) `dueDate = today.plusMonths(1)`이고 테스트는 "다음 달 같은 일자"를 기대한다. 고정 시계로 2026년 365일을 훑으면 실패하는 날은 며칠이고 어떤 날인가? 같은 방식으로 `now.plusHours(24)`와 `now.plusDays(1)`이 갈리는 날을 서울과 뉴욕에서 세면?
5. (원리) 수동(결정적) 스케줄러는 어떤 자료구조로 작업을 보관하고, 같은 마감 시각의 순서를 어떻게 정하나? 100·200·400ms 백오프에서 "99ms 시점에는 재시도가 아직 없다"를 실제 스케줄러로 단언하기 어려운 이유는?
6. (예측) 스레드 4개가 같은 키로 check-then-act `getOrCreate`를 부르는 시행을 2000번 한다. 출발선(`CountDownLatch`)이 없을 때와 있을 때 중복 생성 횟수는 어떻게 다를까? `computeIfAbsent`로 고치면?
7. (경계) 스트레스 테스트(출발선 + 반복)와 강제 끼어들기(이음새 + 래치)는 각각 무엇을 잘하고 무엇을 못 하나? 두 스레드가 각각 10개 원자 단계를 가질 때 가능한 끼어들기 수는?
8. (장애 진단) 운영에서 1분 주기 정산 작업이 어느 날부터 조용히 멈췄다. 테스트(수동 스케줄러 사용)는 늘 초록이었다. `scheduleAtFixedRate`의 어떤 계약이 원인일 수 있고, 테스트와 코드를 어떻게 고치나?
9. (장애 진단) `Clock.fixed`를 주입한 타임아웃 테스트가 끝나지 않고 CI 잡 타임아웃으로 죽었다. 무엇이 잘못됐고 어떻게 고치나?
