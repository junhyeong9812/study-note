# testing/15-mutation-testing — 질문

## 질문

1. (왜) 라인·분기 커버리지가 같은 두 테스트 스위트의 품질이 다를 수 있는 이유는? 변이 테스트는 그 차이를 어떻게 드러내나?
2. (원리) 변이 테스트가 "작은 문법 변경 하나"짜리 결함만 심어도 의미가 있다고 보는 두 가설의 이름과 내용은? 이것은 측정된 사실인가, 가설인가?
3. (예측) `discountedPrice`(VIP·10만 원 이상 10%, 5만 원 이상 5%, 음수 거부)에 대해 단언 없이 전 경로를 호출하는 NoAssertTest를 PIT 1.20.4 기본 연산자로 돌리면 변이 14개 중 몇 개가 죽을까? 죽는 것이 있다면 왜 죽나?
4. (예측) 구간 한가운데 값만 단언하는 WeakTest는 JaCoCo 분기 7/8, 변이 11/14(79%)였다. 살아남은 3개는 어떤 연산자일까? 어떤 입력을 추가하면 죽나?
5. (계산) PartialTest는 `Generated 14 mutations Killed 6`, `Mutations with no coverage 6`이었다. PIT의 Killed %와 Test strength는 각각 얼마이고, 왜 다른가? Jia–Harman의 변이 점수 정의와는 무엇이 다른가?
6. (경계) `abs(x)`의 `if (x < 0) return -x;`에 경계 변이(`x <= 0`)를 넣으면 어떤 테스트로 죽일 수 있나? 이런 변이체를 무엇이라 부르고, 자동으로 걸러낼 수 있나?
7. (비용) 변이 테스트가 비싼 이유는? PIT와 Google은 비용을 각각 어떻게 줄이나? Google이 말하는 arid 노드란?
8. (장애 진단) PIT를 돌렸더니 `Mutation testing requires a green suite.`로 바로 멈췄다. 원인과 대처는? 불안정한 테스트가 섞여 있으면 결과가 어떻게 오염되나?
9. (장애 진단) 팀이 "변이 점수 100%"를 CI 게이트로 걸자고 한다. 생길 문제와 대안은?
10. (연결) 생존한 변이체 보고서를 테스트 설계 기법(경계값·결정 테이블)과 어떻게 연결해 쓰나?
