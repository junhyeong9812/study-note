# testing/19-testing-in-production — 질문

## 질문

1. (왜) 배포 전 테스트를 충분히 했는데도 운영에서 검증해야 하는 이유는? SWE@G 14장이 운영을 어떻게 부르고, 운영 검증의 대가를 무엇이라 적나?
2. (그림) 합성 모니터링·카나리 분석·섀도 트래픽을 한 그림에 그리고, 각각 "무엇과 비교하나", "사용자 노출이 있나"를 표로 정리하라.
3. (예측) 결제 게이트웨이 설정이 빠진 판에서 `/healthz`는 200, `/api/checkout`은 200 + `{"status":"ERROR"}`다. k6 체크 `healthz 200`·`checkout 200`·`checkout PAID`를 5회 돌리면 각각 어떻게 되나? 임계값이 없으면 k6 종료 코드는?
4. (예측) 기준·카나리의 오류 확률이 둘 다 1%다. "카나리 오류율 > 기준 오류율이면 실패" 규칙은 대략 몇 %를 실패로 판정하나? 단측 5% z-검정은?
5. (계산·경계) 카나리 오류율이 2%(기준 1%)일 때, 그룹당 200건과 2,000건에서 z-검정이 나쁜 판을 잡는 비율은 실험에서 대략 얼마였나? 무엇을 뜻하나?
6. (연결) 카나리를 운영 전체 집단과 비교하지 않고 같은 크기·같은 시각의 기준 집단과 비교하는 이유는? 배포 전후(before/after) 비교의 문제는?
7. (경계) 섀도 트래픽은 "응답을 버린다". 그런데도 위험한 이유는? 실험에서 무엇이 두 배가 됐나?
8. (장애 진단) 합성 점검을 운영에 넣었더니 매출 집계에 테스트 주문이 섞였다. 원인과 대처는? SWE@G의 Webdriver Torso 사례가 주는 교훈은?
9. (장애 진단) 카나리 단계는 매번 초록인데 100% 배포 뒤 오류가 오른다. 판정 쪽에서 의심할 것 두 가지는?
