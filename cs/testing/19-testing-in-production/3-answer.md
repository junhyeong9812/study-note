# testing/19-testing-in-production — 정답

## 정답

### 1. 운영에서 검증하는 이유

- 운영에만 있는 것: 운영 설정·비밀값·플래그 값, 운영 데이터의 모양과 양, 실제 트래픽, 다른 팀의 실제 판들.
- SWE@G 14장: 운영은 "충실도가 가장 높은 테스트 환경"이다. Google 대형 장애의 첫째 원인이 설정 변경이라고 적는다.
- 대가: 운영에서 잡은 문제는 이미 사용자에게 영향을 주고 있다(같은 장). 그래서 노출을 줄이는 장치(일부 트래픽, 가짜 사용자, 응답 버림)와 같이 쓴다.

### 2. 세 장치

```text
 합성 점검: 스크립트 ──▶ 운영 ── 기대값과 비교
 카나리:   트래픽 ─┬ 대부분 → 기준(구판) ─┐ 지표 비교
                  └ 일부  → 카나리(신판) ┘
 섀도:     요청 ─┬→ 구판 → 사용자
                └→ 신판 → 응답 버림, 구판과 diff
```

| | 비교 대상 | 사용자 노출 |
|---|---|---|
| 합성 점검 | 스크립트의 기대값 | 없음 |
| 카나리 | 같은 시각 기준 집단 | 일부 |
| 섀도 | 구판 응답 | 없음(부수 효과는 별개) |

### 3. 헬스 체크 초록, 여정 빨강

(실험, k6 1.2.3 · Node 22.23.2, 2026-10-03)

```text
    ✓ healthz 200
    ✓ checkout 200
    ✗ checkout PAID
      ↳  0% — ✓ 0 / ✗ 5
```

- 업무 결과를 본 `checkout PAID`만 5/5 실패. 전체 체크 66.66%(10/15).
- 임계값이 없으면 체크가 실패해도 k6는 실패 종료 코드를 내지 않는다(k6 Checks 문서). 임계값 `checks: ['rate==1.0']`을 걸자 종료 코드 99(`ThresholdsHaveFailed`)가 나왔다.

### 4. 같은 판끼리의 판정

(실험, 1,000회, 시드 42·7)

- 순진 규칙: 40.7~52.5%를 실패로 판정 — 대략 절반. 우연한 차이를 회귀로 본다.
- z-검정(단측 5%): 4.7~6.5% — 설계한 거짓 경보율 근처.

### 5. 검출력과 표본

- 그룹당 200건: 23.7%(시드 42)·25.3%(시드 7) — 나쁜 판의 약 4분의 1만 잡는다.
- 2,000건: 83.0%·82.9%. 20,000건: 100%.
- 뜻: 작은 카나리·짧은 기간은 나쁜 판을 대부분 통과시킨다. 표본(트래픽·기간)을 늘리거나 판정할 수 있을 만큼 기다려야 한다. Spinnaker 문서는 지표당 50개 이상의 시계열 데이터를 권한다.

### 6. 비교 대상

- 운영 전체 집단은 오래 떠 있어 캐시가 예열되고 힙 상태가 다르다. 갓 뜬 카나리와 비교하면 판 차이가 아닌 환경 차이가 섞인다. Spinnaker 문서는 같은 크기·같은 시각에 새로 띄운 기준 집단과 비교하라고 한다.
- before/after 비교는 시간대·요일·트래픽 변화가 섞인다. SRE Workbook 16장이 경고한다.

### 7. 섀도의 위험

- 응답만 버릴 뿐 신판이 한 일(메일·결제·DB 쓰기·외부 호출)은 그대로 일어난다.
- 실험: 부수 효과를 막지 않자 영수증 메일이 10,000 → 20,000건. 차이 비교 자체는 591/10,000건을 찾았다(예: 구판 842, 신판 841).

### 8. 테스트 데이터가 섞임

- 원인: 합성 요청·데이터를 표시하지 않았고 집계에서 거르지 않았다.
- 대처: 전용 계정·상품, `X-Synthetic` 같은 표시, 집계·청구 단계 필터, 생성 데이터 정리.
- Webdriver Torso: 유튜브 운영 영상 처리를 확인하려고 테스트 영상을 자동 업로드한 채널이 공개되어 Wired 기사로 퍼졌다. 운영에 넣은 테스트 데이터는 외부에서 보일 수 있다고 가정해야 한다.

### 9. 카나리 초록, 전체 배포 빨강

- 검출력 부족: 카나리 표본이 작았다(실험: 그룹당 200건이면 오류율 두 배인 판을 약 4분의 1만 잡음). 트래픽이 적은 시간대였을 수도 있다.
- 비교 대상·지표: before/after로 비교했거나, 변경에 귀속되지 않는 지표를 봤다. 같은 시각 기준 집단, 소수의 귀속 지표, 통계 판정으로 바꾼다.
