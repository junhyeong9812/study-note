# testing/06-outside-in-tdd-and-acceptance-tests — 질문

## 질문

1. (왜) 모든 부품의 단위 테스트가 초록인데도 기능이 동작하지 않을 수 있는 이유는? 인수 테스트는 그것을 어떻게 잡나?
2. (그림) 이중 루프 TDD를 그려라. 바깥 루프와 안쪽 루프는 각각 무엇을 단위로 돌며, 어느 쪽이 더 오래 빨강인가? 오래 빨강인 테스트를 CI에서 어떻게 다루라고 GOOS는 권하나?
3. (경계) Walking Skeleton을 계층별(수평) 개발과 비교해 그려라. GOOS의 정의 문장에 들어 있는 세 동사(자동으로 무엇을 한다)는?
4. (연결) 바깥에서 안으로 갈 때 mock은 어떤 역할을 하나? 이 쓰임이 04번 런던파·03번 "Only Mock Types That You Own"과 어떻게 이어지나?
5. (예측) Composition Root에서 가입 유스케이스와 조회 유스케이스에 저장소를 각각 새로 만들어 넣었다. 단위 테스트(가입 2·조회 1·HTTP 어댑터 1)와 인수 테스트 "가입 후 조회"는 각각 어떻게 되나? 왜 단위 테스트는 이 실수를 못 잡나?
6. (예측) 서버 경로를 `/users`에서 `/v2/members`로 바꿨다. 본문에 HTTP 세부를 쓴 인수 테스트와 DSL+드라이버로 쓴 인수 테스트는 각각 몇 군데를 고쳐야 하나(실험 기준)? 첫 DSL 드라이버에서 3개 중 2개만 실패한 이유는?
7. (경계) Given-When-Then 틀(North 2006)을 원문대로 말하고, 인수 테스트 본문에 "버튼 #submit 클릭"을 쓰면 어떤 추상화 수준 오류인지 설명하라.
8. (장애 진단) 배포 뒤 "가입은 되는데 조회가 안 된다". 단위 테스트는 전부 초록이다. 무엇을 의심하고, 어떤 테스트를 추가하나?
9. (장애 진단) 백엔드·프론트·배치를 두 달간 계층별로 완성하고 붙이는 주에 연결 버그가 수십 건 나왔다. 어떤 실천이 빠졌고, 다음 프로젝트에서는 어떻게 시작하나?
10. (연결) 테스트 DSL의 세 계층(시나리오·DSL·드라이버)은 각각 무엇이 바뀔 때 바뀌나? 이것이 도메인 모델링의 보편 언어와 어떻게 연결되나?
