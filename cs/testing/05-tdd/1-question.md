# testing/05-tdd — 질문

## 질문

1. (왜) 구현을 다 짠 뒤 테스트를 쓰면 생기기 쉬운 문제 세 가지는? TDD는 순서를 어떻게 뒤집나?
2. (그림) Canon TDD의 다섯 단계를 순환 그림으로 그려라. 3단계에서 "이 테스트"만이 아니라 "이전 테스트 전부"를 통과시키라는 이유는?
3. (경계) Beck이 나누는 두 설계 결정(인터페이스 설계·구현 설계)은 사이클의 어느 단계에서 정해지나? 테스트 목록에 구현 결정을 섞지 말라는 이유는?
4. (경계) Fake It·Triangulate·Obvious Implementation을 구분하라. TDD의 Fake It과 테스트 더블의 Fake는 무엇이 다른가?
5. (예측) 장바구니 실험에서 첫 테스트(`new Cart().total()`이 0)를 돌리면 빨강은 어떤 모양인가? "여러 품목 합" 테스트를 추가했을 때 처음부터 초록이었다면 그것은 무엇을 알려 주나?
6. (예측) 정수 연산 `subtotal * 9 / 10`으로 할인을 구현한 상태에서 9,005원·10개 장바구니의 기대값을 (가) 손으로 계산해 쓰면, (나) 실행 출력을 붙여 넣으면 각각 어떻게 되나? (나)의 테스트를 둔 채 구현을 HALF_UP으로 고치면?
7. (연결) 기대값을 "독립된 근거"에서 가져오라는 말과 Evident Data 패턴은 어떻게 이어지나? 골든 마스터(특성 테스트)는 붙여 넣기와 무엇이 다른가?
8. (장애 진단) 커밋 기록에 red·green만 있고 refactor가 없으며, 새 테스트 하나를 통과시키는 시간이 점점 길어진다. 무엇이 일어나고 있고 어떻게 바로잡나? 반대 방향의 실수는?
9. (장애 진단) 테스트 20개를 먼저 다 쓰고 구현을 시작했더니 첫 구현에서 인터페이스가 바뀌었다. 어떤 실수이고, 대신 어떻게 했어야 하나?
10. (연결) 빨강을 직접 보지 않은 테스트, 단언이 없는 테스트는 왜 위험한가? 이를 어떤 도구로 드러낼 수 있나?
