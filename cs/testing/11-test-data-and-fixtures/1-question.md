# testing/11-test-data-and-fixtures — 질문

## 질문

1. (왜) 테스트 데이터 준비에서 생기는 세 가지 문제(준비가 길다·같이 쓰면 얽힌다·바꾸면 번진다)를 예로 설명하라. 픽스처의 정의는?
2. (그림) Fresh/Shared × Minimal/Standard 2×2 표를 그리고, 칸마다 장단점을 한 줄로 적어라. Meszaros가 Fresh가 너무 느릴 때 Shared보다 먼저 고려하라는 것은?
3. (경계) JUnit 5 Jupiter에서 인스턴스 필드, `@BeforeEach`, `static` + `@BeforeAll`로 만든 객체는 각각 테스트 사이에 공유되나? `@TestInstance(PER_CLASS)`를 붙이면 무엇이 달라지나?
4. (예측) 재고 10개를 `@BeforeAll`로 한 번 만들고 세 테스트(4개 예약·5개 예약·"아직 10개")가 같이 쓴다. 무작위 순서 20회에서 언제 통과하고 언제 실패하나? 같은 세 테스트를 인스턴스 필드로 바꾸면?
5. (경계) JUnit 5의 기본 메서드 실행 순서는 문서에 어떻게 적혀 있나? 기본 순서에서 공유 픽스처 테스트가 늘 통과하던 팀이 테스트 하나를 추가한 뒤 무관한 테스트가 깨진 이유를 설명하라.
6. (경계) Creation Method·Object Mother·Test Data Builder를 구분하라. Pryce가 빌더의 네 요소로 꼽은 것은?
7. (예측) 생성자 인자를 하나 추가했을 때, 같은 테스트 6개를 생성자 직접 호출·마더(팩터리 3개)·빌더로 쓴 경우 각각 컴파일 오류는 몇 곳에서 나나? 마더의 `regular()` 데이터를 바꾸면 어떤 테스트가 깨지나?
8. (장애 진단) CI에서만 가끔 실패하고 로컬 단독 실행은 통과한다. 순서 의존을 확인하는 명령 두 가지(JUnit·Surefire)와, 원인을 찾을 때 실패 위치를 믿으면 안 되는 이유는?
9. (장애 진단) 두 번째 실행부터 `duplicate key value violates unique constraint`가 나거나, 두 CI 작업이 겹친 날만 실패한다. Meszaros의 이름(두 가지)과 격리 방법 세 가지를 대라.
10. (연결) SWE@G 12장의 "DAMP, Not DRY"와 "특정 값에 기대는 테스트는 그 값을 직접 적어라"는 빌더 사용법과 어떻게 이어지나? 거대 `setUp()`이 왜 Obscure Test를 만드나?
