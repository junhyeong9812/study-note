# os/10-paging-and-tlb — 질문

## 질문

1. (그림) x86-64 4단계 페이지 테이블에서 48비트 가상 주소를 비트 필드로 나누고, CR3에서 물리 주소까지 걷는 경로를 그려라. 표 하나의 크기는?
2. (계산) 32비트·4 KB 페이지의 선형 페이지 테이블은 프로세스당 몇 바이트인가? 48비트·4 KB·8바이트 항목이면? 다단계 표는 이 문제를 어떻게 푸나, 대가는 무엇인가?
3. (경계) PTE의 Present 비트가 0인 페이지는 어떤 상태들일 수 있나? 원고의 "유효 비트 0 = 디스크에 있다"는 어디까지 맞나?
4. (예측) 64 MB를 `mmap`하고 절반만 쓴 직후, `/proc/self/pagemap`의 present 페이지 수와 `VmRSS`는 대략 얼마일까? 일반 사용자가 읽은 PFN은 왜 0인가?
5. (그림) TLB 히트와 미스 때의 경로를 그려라. x86과 MIPS는 TLB 미스를 누가 처리하나?
6. (계산) TLB가 2,048칸이라고 하자(예시). 4 KB 페이지와 2 MB 페이지일 때 TLB 도달 범위는 각각 얼마인가? 256 MB를 무작위로 읽는 프로그램에서 어느 쪽이 유리한가? 이때 페이지 폴트 수는 몇 배 차이인가?
7. (경계) 문맥 전환 때 TLB를 어떻게 다루나? 두 방법과 x86 리눅스의 선택을 설명하라.
8. (장애 진단) 스레드 16개짜리 서버의 `sy`가 높고 `grep TLB /proc/interrupts`가 초당 크게 오른다. 무슨 일이 일어나고 있고, 어떤 코드 패턴이 원인일 수 있나?
9. (장애 진단) THP를 `always`로 켠 뒤 Redis에서 `BGSAVE` 직후 지연이 치솟고 메모리가 크게 늘었다. 원인과 대처는? THP가 오히려 도움이 되는 워크로드는?
10. (연결) 프로세스 500개가 32 GB 공유 메모리를 4 KB 페이지로 매핑한 DB 서버에서 `PageTables`가 크다. 대략 얼마가 될지 계산하고, 줄이는 방법을 설명하라.
