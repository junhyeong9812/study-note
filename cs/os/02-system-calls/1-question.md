# os/02-system-calls — 질문

## 질문

1. (그림) C 코드의 `write(fd, buf, n)` 한 줄이 커널에서 실제 작업을 하고 돌아오기까지의 경로를 그려라. 번호·인자·결과는 각각 어느 레지스터로 오가나?
2. (왜) 커널은 실패를 어떻게 알리고, 사용자는 왜 `-1`과 `errno`를 보나? 성공한 호출 뒤에 `errno`를 보면 안 되는 이유는?
3. (경계) "C 함수 이름 = 시스템 콜 이름"은 맞는가? `fork()`, `printf()`, `clock_gettime()`을 예로 설명하라.
4. (계산·예측) 1,000,000바이트를 (a) `write(fd, "x", 1)` 100만 번, (b) stdio `fputc` 100만 번으로 쓴다. 각각 `write` 시스템 콜은 몇 번 나가고, user/sys 시간은 어느 쪽이 클 것인가? 이유는?
5. (예측) 파이프에서 `read()`로 블록 중인데 `SIGALRM`이 왔다. 핸들러를 `sigaction`에 `SA_RESTART` 없이 단 경우와 단 경우 각각 `read`는 어떻게 되나? `poll()`이었다면?
6. (경계) 시그널이 `write()` 도중 도착해 일부 바이트만 옮겨졌다. `write`는 무엇을 돌려주나? 호출하는 쪽 코드는 무엇을 해야 하나?
7. (연결) x86-64 리눅스는 시스템 콜 번호로 핸들러를 어떻게 찾나? "시스템 콜 테이블 = 함수 포인터 배열"은 최신 커널에서도 그대로 맞는가?
8. (장애 진단) 로그를 많이 쓰는 서비스의 CPU가 치솟는데 `%system`이 `%usr`보다 크다. 무엇으로 확인하고 어떻게 고치나?
9. (장애 진단) C로 쓴 에이전트가 하루 몇 번 `read failed: Interrupted system call`로 작업을 실패 처리한다. 원인과 고치는 법은? Java·Node 앱에서는 왜 이런 로그를 거의 못 보나?
10. (설계) 운영 중인 서버 프로세스를 `strace -p`로 봐야 한다. 무엇을 조심하고 어떻게 붙이나?
