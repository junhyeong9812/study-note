# os/35-virtualization-hypervisor — 질문

## 질문

1. (왜) 하이퍼바이저가 게스트 OS의 모든 명령을 하나씩 흉내 내지 않고도 VM을 돌릴 수 있는 이유는? OS의 "제한된 직접 실행"과 어떻게 이어지나?
2. (경계) trap-and-emulate가 가능하려면 명령어 집합이 어떤 조건을 만족해야 하나? 옛 x86이 이 조건을 어겼을 때 나온 세 가지 해법은?
3. (그림) KVM에서 VM 하나가 호스트에서 어떻게 보이는지 그려라. vCPU는 호스트 입장에서 무엇인가? 게스트가 `out` 명령을 실행하면 제어가 어디로 가나?
4. (계산) 게스트·호스트 모두 4단계 페이지 테이블일 때, 중첩 페이지 테이블(EPT/NPT)에서 TLB 미스 한 번의 최악 메모리 참조 수는? 어떻게 세는지 보여라. 가상화가 없으면 몇 번인가?
5. (비교) 섀도 페이지 테이블과 중첩 페이지 테이블은 각각 어디서 비용을 치르나?
6. (경계) steal time은 정확히 무엇을 센 시간인가? vCPU가 할 일이 없어 쉬는 시간도 steal인가? 게스트 안에서 steal을 줄일 수 있나?
7. (장애 진단) 클라우드 VM에서 배포도 트래픽 변화도 없는데 p99 지연이 튄다. 프로파일러에는 원인이 안 보인다. 무엇을 어떤 순서로 보고, 원인이 steal이면 어떻게 대처하나?
8. (연결) CPU 제한에 걸린 것이 VM일 때와 컨테이너일 때, 게스트(또는 컨테이너) 안에서 보이는 지표는 각각 무엇인가?
