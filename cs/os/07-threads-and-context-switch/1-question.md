# os/07-threads-and-context-switch — 질문

## 질문

1. (그림) 리눅스에서 한 프로세스 안의 스레드 셋을 그려라. 무엇을 공유하고 무엇을 따로 갖나? `getpid()`와 `gettid()`는 각각 무엇을 돌려주나?
2. (연결) `pthread_create`는 커널에 무엇을 요청하나? 원고의 "PCB와 TCB"는 리눅스 커널에서 어떻게 나타나나?
3. (그림) 스레드 A에서 B로 컨텍스트 스위칭할 때 커널 안에서 일어나는 단계를 순서대로 그려라. 레지스터는 어디에 저장되나?
4. (경계) 같은 프로세스의 두 스레드 사이 스위칭과 서로 다른 프로세스 사이 스위칭은 무엇이 다른가? x86 리눅스는 프로세스 간 스위칭 때 TLB를 전부 비우나?
5. (예측) 스레드를 두 개 만든 C 프로그램의 `VmRSS`가 2 MB 미만인데, 스레드 스택이 각 8 MB라고 한다. 모순인가? 8 MB는 어디서 온 값이고, JVM 스레드라면 기본값은?
6. (계산) 같은 CPU에 고정한 파이프 핑퐁이 왕복 약 3.8 µs였다. 한 번의 컨텍스트 스위치는 대략 얼마인가? 이 측정이 담지 못하는 비용은 무엇인가?
7. (장애 진단) 피크 때 `vmstat 1`의 `cs`가 6만에서 190만으로, `sy`가 4%에서 71%로 올랐다. 무엇을 의심하고 어떤 명령으로 좁히나?
8. (장애 진단) 컨테이너의 JVM이 `OutOfMemoryError: unable to create native thread`로 죽었다. `-Xmx`를 늘리면 해결되나? 확인할 한도 네 가지는?
9. (경계) 자발적 스위치와 비자발적 스위치는 각각 언제 일어나나? `/proc/<pid>/status`의 값만 보면 무엇을 놓칠 수 있나?
10. (설계) 블로킹 원격 호출이 대부분인 서비스에서 스레드 1만 개가 필요하다. 플랫폼 스레드로 버틸 때와 가상 스레드(JDK 21+)로 바꿀 때, 컨텍스트 스위칭 관점에서 무엇이 달라지나?
