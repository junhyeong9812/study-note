## 질문

1. (그림) 이벤트 루프의 의사코드를 쓰고, OSTEP이 "다음 이벤트를 고르는 것이 곧 스케줄링"이라고 말하는 이유를 설명하라.
2. (왜) 싱글 코어·단일 루프 이벤트 서버에는 왜 락이 필요 없나? 멀티코어를 다 쓰려고 루프를 여러 개 돌리면 무엇이 돌아오나?
3. (그림) 리액터 패턴의 구성 요소(디멀티플렉서·디스패처·핸들러)를 그리고, 리눅스에서 디멀티플렉서 자리에 무엇이 들어가는지 적어라. 이 패턴의 "비선점" 한계는 무엇인가?
4. (예측) Node에서 100ms 간격 `setInterval`이 돌고 있다. 250ms 시점에 500ms짜리 동기 루프가 실행되면 타이머 간격은 어떻게 찍히나? 그 사이 들어온 HTTP 요청은?
5. (자료구조) libuv는 타이머를 어떤 자료구조로 관리하고, 그것으로 `epoll_wait`의 타임아웃을 어떻게 정하나? Redis `ae.c`의 타이머 구조와 비교하면?
6. (왜) OSTEP이 말하는 manual stack management는 무엇이고, continuation은 그것을 어떻게 푸나? JS의 `async/await`는 이것과 어떤 관계인가?
7. (경계) 코드에 블로킹 호출이 전혀 없는데도 이벤트 루프가 멈출 수 있는 경우를 OSTEP 33.8에서 하나 들어라. 어떤 지표로 확인하나?
8. (장애 진단) Node 서버에서 비밀번호 해시(`pbkdf2`) 요청이 몰리는 시간에만 외부 HTTP 호출의 연결 시작과 `fs.readFile`이 느려진다. CPU는 여유다. 무엇을 의심하고 어떻게 고치나?
9. (장애 진단) Netty 서버에서 엔드포인트와 무관하게 모든 요청 지연이 같은 시각에 튄다. 스레드 덤프에서 무엇을 찾고, Netty가 권하는 구조로 어떻게 고치나? 그 구조에도 남는 병목은?
10. (장애 진단) 운영 Redis에서 모든 클라이언트가 수 초간 타임아웃났다. `SLOWLOG`에 `KEYS`가 있다. 왜 한 명령이 모든 클라이언트를 멈추나? 대안은?
