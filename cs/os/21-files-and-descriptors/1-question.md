# os/21-files-and-descriptors — 질문

## 질문

1. (그림) fd 테이블 · 열린 파일 기록(OFD) · inode의 세 겹을 그려라. 파일 오프셋은 어느 층에 있고, 파일 이름은 어느 층에도 없다면 어디에 있나?
2. (예측) 같은 파일을 `open()`으로 두 번 연 경우와 `dup()`한 경우, 한쪽 fd로 5바이트를 읽은 뒤 다른 fd의 오프셋은 각각 얼마인가? `fork()`한 자식이 `lseek`하면 부모에게 보이나?
3. (예측) 0·1·2·4번 fd가 열려 있고 3번이 비어 있다. 새 `open()`은 몇 번을 돌려주나? 이 규칙이 멀티스레드 코드에서 어떤 위험을 만드나?
4. (왜) `close()`가 실패를 돌려줬다. 리눅스에서 close를 다시 부르면 안 되는 이유는? 그럼 반환값은 왜 확인하나?
5. (경계) `close()`가 성공하면 데이터가 디스크에 있다고 할 수 있나? 없다면 무엇이 필요한가?
6. (그림) 하드 링크와 심볼릭 링크를 inode 관점에서 그려라. 원본 이름을 지웠을 때 각각 어떻게 되나? 하드 링크가 다른 파일 시스템에 안 되는 이유는?
7. (장애 진단) 디스크가 꽉 차 20 GB 로그를 `rm`했는데 `df`가 그대로다. 원인과 확인 명령, 공간을 되찾는 방법 두 가지는?
8. (장애 진단) 서비스가 이틀째 `Too many open files`를 낸다. `EMFILE`과 `ENFILE`은 어떻게 다른가? 어떤 명령으로 누수인지 한도 부족인지 가리나?
9. (연결) 부모와 자식이 같은 로그 파일에 쓰는데 줄이 서로 덮인다. fork 전에 연 fd를 함께 쓰는 경우와 각자 `open()`한 경우를 오프셋 공유와 `O_APPEND`로 구분해 설명하라.
10. (자료구조) 커널은 "가장 작은 빈 fd"를 어떻게 빠르게 찾나? fd 테이블이 모자라면 어떻게 키우나?
