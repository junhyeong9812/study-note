# os/30-ipc — 질문

## 질문

1. (왜) 프로세스 A가 자기 변수 주소를 B에게 알려 줘도 B가 그 값을 읽을 수 없는 이유는? 파이프·소켓·큐가 데이터를 건네는 방식과 공유 메모리가 건네는 방식은 복사 횟수에서 어떻게 다른가?
2. (그림) 리눅스 파이프의 커널 버퍼 구조를 그려라. 기본 용량은 얼마이고, 가득 찼을 때와 비었을 때 `write`·`read`는 각각 어떻게 되나(블로킹·논블로킹)?
3. (예측) 부모가 `waitpid(자식)`을 먼저 하고 그 뒤에 파이프를 읽는다. 자식 출력이 60,000바이트일 때와 70,000바이트일 때 각각 무슨 일이 생기나? 멈췄을 때 두 프로세스는 어디서 자고 있나?
4. (경계) 자식이 끝났는데 부모의 `read`가 EOF를 못 본다. 가능한 원인 두 가지와 막는 법은?
5. (예측) `yes | head -1`에서 `yes`의 exit code는 몇이고 왜 그런가? 서버 프로그램에서는 같은 상황을 어떻게 다루나?
6. (경계) `PIPE_BUF`는 무엇을 보장하나? 여러 프로세스가 한 파이프에 로그 줄을 쓸 때 이 값이 왜 중요한가? 파이프에 "메시지 경계"가 있나?
7. (연결) 유닉스 도메인 소켓이 TCP loopback 대신 쓰이는 이유가 되는 기능 두 가지(`SCM_RIGHTS`, `SO_PEERCRED`)는 각각 무엇을 하나? 데몬이 비정상 종료 뒤 `EADDRINUSE`로 다시 안 뜨는 이유는?
8. (장애 진단) 프로세스 4개가 공유 메모리 카운터를 100만 번씩 올렸는데 합이 400만이 안 된다. 원인과 해결은? 재시작 뒤 이전 값이 남아 있는 이유는?
9. (적용) Java `ProcessBuilder`와 Node `child_process`로 외부 명령의 출력을 안전하게 받는 방법을 각각 설명하라. Node `exec`의 `maxBuffer`를 넘으면 무슨 일이 생기나?
