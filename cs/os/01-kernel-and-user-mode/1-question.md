## 질문

1. (왜) OS가 프로그램의 명령을 하나씩 흉내 내지(인터프리트) 않고 CPU에서 "직접" 실행하게 두는 이유는? 그러면 OS는 무엇으로 통제권을 지키나? "제한된 직접 실행"의 두 부분을 설명하라.
2. (그림) 유저 모드에서 커널 모드로 들어가는 세 개의 문을 그리고, 각각 누가(무엇이) 계기가 되는지 적어라. 셋의 공통점은 무엇인가?
3. (왜) 트랩 테이블을 부팅 때 커널이 등록하고, 그 등록 명령이 특권 명령이어야 하는 이유는? 유저가 등록할 수 있다면 무슨 일이 생기나?
4. (왜) 프로그램이 시스템 콜을 한 번도 부르지 않고 무한 루프를 돌면 협력형 OS와 현대 OS에서 각각 어떻게 되나?
5. (예측) x86-64 리눅스에서 유저 프로그램이 `hlt`를 실행하면 어떤 CPU 예외가 나고, 프로세스는 어떤 시그널로 죽으며, 셸 exit code는 얼마인가? `ud2`라면?
6. (경계) "특권 명령을 유저 모드에서 실행하면 항상 즉시 죽는다"는 맞는가? 반례 두 가지를 들어라.
7. (경계) root로 실행한 프로세스는 커널 모드인가? 권한 거부가 `EPERM`으로 오는 경우와 `SIGSEGV`로 오는 경우는 각각 어느 층의 검사인가?
8. (장애 진단) 개발 머신에서는 잘 도는 네이티브 바이너리가 특정 노드에서만 시작하자마자 exit 132로 죽는다. 무엇을 의심하고 무엇으로 확인하나?
9. (장애 진단) 서버 CPU 사용률이 높은데 애플리케이션 프로파일러에 뜨거운 함수가 없다. 유저/커널 시간 중 무엇부터 보고, 어떤 명령으로 보나?
