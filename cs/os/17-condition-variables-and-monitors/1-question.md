# os/17-condition-variables-and-monitors — 질문

## 질문

1. (왜) 락만 가지고 "큐가 빌 때까지 기다리기"를 하면 쓸 수 있는 방법 두 가지는 무엇이고, 각각 무엇이 나쁜가? `pthread_cond_wait`가 원자적으로 해 주는 일은 정확히 무엇인가?
2. (그림) 상태 변수 없이 `signal`/`wait`만으로 만든 join이 영원히 잠드는 실행 순서를 그려라. 상태 변수(`done`)를 두었지만 락 없이 확인하는 경우에는 어떤 순서로 같은 일이 생기나?
3. (예측) 아무도 기다리지 않을 때 `pthread_cond_signal`을 부르면 무슨 일이 생기나? 같은 상황에서 세마포어의 `sem_post`와 무엇이 다른가?
4. (그림) 생산자 1, 소비자 2, 버퍼 크기 1이고 소비자가 `if (count == 0) wait;`로 기다린다. 소비자 하나가 빈 버퍼에서 꺼내게 되는 순서를 그려라. Mesa 의미론과 Hoare 의미론 중 어느 쪽에서 이 일이 생기나?
5. (왜) POSIX는 spurious wakeup이 "일어날 수 있다"고 명시한다. 왜 구현이 이를 막지 않기로 했나? 이 허용이 응용 코드에 주는 "덤"은 무엇인가?
6. (예측) 조건 변수 **하나**를 생산자와 소비자가 같이 쓰고 `signal`로 하나만 깨운다(while은 제대로 씀). 세 스레드가 모두 잠드는 순서를 설명하고, 해법 두 가지를 비교하라.
7. (연결) Java 객체의 "모니터"는 무엇과 무엇을 묶은 것인가? `synchronized` 블록 밖에서 `wait()`를 부르면? `Condition`은 모니터의 어떤 한계를 푸나? `ArrayBlockingQueue`의 `put`·`take`는 이를 어떻게 쓰나?
8. (장애 진단) 드물게 요청 하나가 끝나지 않는다. CPU는 0%이고 `jstack`에 "Found one Java-level deadlock"도 없다. 무엇을 의심하고, 덤프의 어떤 줄로 확인하며, 어떻게 고치나?
9. (경계) `pthread_cond_timedwait`의 시간 인자는 왜 상대 시간이 아니라 절대 시각인가? 기본 시계는 무엇이고, 그 때문에 생길 수 있는 문제와 대처는?
