# os/12-swapping-and-page-replacement — 질문

## 질문

1. (그림) present 비트가 0인 페이지에 접근했을 때 커널이 하는 일을 순서대로 그려라. 희생 페이지가 dirty일 때와 깨끗할 때 무엇이 다른가?
2. (경계) 스왑 영역에 가는 페이지와 가지 않는 페이지를 구분하라. 실행 파일의 코드 페이지를 내보낼 때는 무엇을 하나?
3. (왜) OPT(Belady)는 최적인데 왜 실제 OS가 쓰지 못하나? 그럼 OPT는 어디에 쓰나?
4. (그림) CLOCK 알고리즘을 원형 그림으로 그리고, hand가 use=1인 페이지를 만났을 때와 use=0인 페이지를 만났을 때 각각 무엇을 하는지 적어라. 왜 LRU의 "근사"라고 하나?
5. (계산) 참조열 `1,2,3,4,1,2,5,1,2,3,4,5`에서 FIFO로 프레임 3개와 4개일 때 폴트 수를 세라. 결과가 이상한 이유와, LRU에는 왜 이 현상이 없는지 설명하라.
6. (예측) 캐시가 49페이지이고 페이지 0~49를 순서대로 반복 접근한다. LRU의 적중률은? 이것이 실무에서 어떤 모습(스캔 오염)으로 나타나나?
7. (그림) 리눅스의 inactive/active 두 목록을 그리고, 새 페이지·두 번째 접근·회수가 각각 어디서 일어나는지 표시하라. 이 구조가 스캔 오염을 어떻게 막나?
8. (연결) 작업 집합이란 무엇이고, 스래싱과 어떤 관계인가? 옛 시스템의 진입 제어와 리눅스의 OOM killer는 스래싱에 각각 어떻게 대응하나?
9. (장애 진단) "서버 전체가 멈춘 듯 느린데 CPU는 한가하다"는 제보다. 어떤 명령과 지표로 스래싱을 확인하나? 각 지표가 어떤 값이면 스래싱인가?
10. (경계) `vm.swappiness=0`이면 스왑을 절대 안 쓰나? swappiness는 정확히 무엇을 조절하나?
