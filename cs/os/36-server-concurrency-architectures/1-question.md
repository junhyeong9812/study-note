# os/36-server-concurrency-architectures — 질문

## 질문

1. (분류) 연결당 스레드·리액터·프로액터·반동기/반비동기·리더/팔로워를 "받는 알림(없음·준비·완료)", "스레드 수가 무엇에 비례하나", "핸드오프 큐 유무"로 표를 만들어라.
2. (예측) 64비트 리눅스에서 기본 스택(8MB)으로 유휴 스레드 1000개를 만들면 `VmSize`와 `VmRSS`는 대략 어떻게 되나? 그렇다면 연결당 스레드의 C10K 한계는 무엇에서 먼저 오나?
3. (그림) 멀티 리액터(main + sub)를 그리고, 연결을 루프에 고정하는 이유를 설명하라. accept를 나누는 두 방법은?
4. (경계) 프로액터는 리액터와 무엇이 다른가? Java NIO.2 `AsynchronousSocketChannel`은 리눅스에서 진짜 프로액터인가?
5. (왜) Half-Sync/Half-Async에서 큐잉 층의 "층 사이 흐름 제어"가 왜 필수인가? 동기 층과 비동기 층에서 넘침을 처리하는 방법은 각각 어떻게 다른가?
6. (비교) 리더/팔로워는 Half-Sync/Half-Reactive 스레드 풀보다 무엇을 줄이나? 대신 무엇을 잃나?
7. (계산) 평균 지연 50ms로 초당 200건을 처리하는 서비스가 초당 2000건을 받으려면 동시 처리 수가 얼마나 필요한가? 이것이 가상 스레드의 존재 이유와 어떻게 연결되나? 가상 스레드가 지연을 줄여 주나?
8. (장애 진단) 동시 연결이 늘자 Java 서버가 `OutOfMemoryError: unable to create native thread`를 낸다. 힙은 여유다. 무엇을 확인하나(명령 포함)? 근본 대처는?
9. (장애 진단) 하류 DB가 느려진 뒤 응답 시간이 수십 초까지 늘다가 `OutOfMemoryError: Java heap space`로 죽었다. 워커 풀은 `Executors.newFixedThreadPool(32)`였다. 무슨 일이 일어났고, 어떻게 고치나?
10. (장애 진단) 처리량을 올리려 워커를 가상 스레드로 바꿨더니 HikariCP `Connection is not available, request timed out`이 쏟아진다. 왜인가? 어떤 원칙으로 동시성 한도를 정해야 하나?
