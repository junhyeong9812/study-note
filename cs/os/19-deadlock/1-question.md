## 질문

1. (왜) 교착이 생기려면 동시에 성립해야 하는 네 조건은 무엇인가? 조건마다 그것을 깨는 예방법을 하나씩 대라.
2. (그림) 스레드 1은 L1→L2, 스레드 2는 L2→L1 순서로 락을 잡는다. 교착이 생기는 실행 순서와 그때의 wait-for 그래프를 그려라. 이 코드는 실행할 때마다 멈추나?
3. (계산) 자원 한 종류, cap = 10, need = [8, 4, 6], loan = [3, 2, 2]이다. 지금 상태가 안전한지 은행원 알고리즘으로 판정하라. 이어서 P0이 2개를 더 요청하면 은행원은 허락하나?
4. (설계) 계좌 이체 `transfer(from, to)`가 A→B와 B→A로 동시에 불려 교착이 난다. 락 순서로 고친 Java 코드를 써라. 순서를 정할 수 없을 때의 대안과 그 대안의 함정은?
5. (연결) pthread 기본 뮤텍스, JVM, InnoDB, PostgreSQL은 교착에 대해 각각 무엇을 하나(탐지하나? 푸나? 언제?)
6. (장애 진단) 스레드 덤프에 `Found one Java-level deadlock:`과 `waiting to lock monitor ..., which is held by "worker-2"`가 보인다. 이 출력으로 무엇을 알 수 있고, 긴급 조치와 근본 조치는 무엇인가? JVM이 찾지 못하는 교착은 어떤 것인가?
7. (장애 진단) MySQL에서 `ERROR 1213`과 `ERROR 1205`가 섞여 나온다. 둘은 무엇이 다르고, 롤백 범위는 어떻게 다르며, 애플리케이션은 각각 어떻게 처리해야 하나?
8. (예측) PostgreSQL에서 두 트랜잭션이 행 두 개를 반대 순서로 갱신한다. 오류는 대략 언제 나오고, 어느 쪽이 실패하며, 그 오류의 SQLSTATE는? 교착이 아닌 단순 락 대기는 얼마나 기다리나?
9. (경계) lockdep과 ThreadSanitizer는 실제로 멈춘 적이 없는 코드에서 어떻게 교착 위험을 보고하나? DB나 JVM의 탐지와 무엇이 다른가?
10. (장애 진단) C++ 서비스가 CPU 0%로 멈췄고 로그가 없다. 로드 평균도 낮다. 무엇을 어떤 순서로 확인해 교착을 확정하나?
