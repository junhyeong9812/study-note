# language/22-ir-and-optimization — 질문

## 질문

1. (왜) 컴파일러가 AST를 바로 기계어로 옮기지 않고 IR을 두는 이유 두 가지는? "최적화는 관찰 가능한 동작을 바꾸지 않는다"에서 "관찰 가능한 동작"은 누가 정하나?
2. (그림) `if (c) x = a; else x = b; return x + 1;`의 CFG를 기본 블록으로 그리고, SSA로 바꾼 모습(φ 포함)을 그려라. `clang -O1`은 이 갈래를 어떻게 바꿨나?
3. (예측) `use_square`(작은 static 함수 호출), `dead`(안 쓰는 곱셈), `fold`(`6*7`)를 gcc 13 `-O0`과 `-O2`로 컴파일하면 기계어가 각각 어떻게 다를까? `-O0`에서도 이미 되는 것은?
4. (그림) 동시에 살아 있는 값 a·b·c가 a–b, a–c 간섭을 가질 때 레지스터 두 개로 칠하라. 색이 모자라면 무엇이 일어나나? GCC의 레지스터 할당기가 쓰는 색칠 알고리즘 이름은?
5. (예측) 2억 회 `sum += i * (argc + 1)` 반복을 `-O2`로 재면, 결과를 출력하지 않을 때와 출력할 때 각각 몇 ns가 나올까? 출력해도 그런 이유를 GCC의 어떤 최적화로 설명하나?
6. (경계) `int v = *p; (void)v; if (p == 0) return -1; return 0;`에 NULL을 넣으면 gcc -O0, gcc -O2, gcc -O2 -fno-delete-null-pointer-checks, clang -O2에서 각각 어떻게 되나? 어느 것이 "맞는" 결과인가?
7. (연결) gcc가 null 검사를 지우는 추론을 C 표준(N1570)과 GCC 문서로 설명하라. 개발자는 무엇을 고쳐야 하나?
8. (장애 진단) 다른 스레드가 `stop = 1`로 바꿨는데 `while (!stop) {}`이 `-O2`에서만 끝나지 않는다. 기계어에서 무엇이 보이고, 원인과 고침은?
9. (장애 진단) 운영 서버만 같은 코드가 수 배 느리다. 배포 바이너리가 디버그 빌드인지 어떻게 확인하나? 기계어에서 보이는 흔적은?
10. (연결) JIT(HotSpot C2)는 AOT 컴파일러와 같은 최적화를 하면서 무엇을 더 할 수 있나? 그 대가는?
