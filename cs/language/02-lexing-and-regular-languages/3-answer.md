# language/02-lexing-and-regular-languages — 정답

## 정답

### 1. 토큰을 쓰는 이유

- 파서의 문법 규칙은 "식별자 `=` 식" 같은 **단어 단위**다. 글자 단위로 쓰면 규칙이 공백·주석·숫자 자릿수까지 다 떠안는다.
- 토큰 = 종류(IF·IDENT·NUM·GE…) + 원문 조각(lexeme) + 위치(줄·열). 위치는 오류 메시지에 쓰인다.
- 렉서는 문법이 맞는지 보지 않는다. `x = + 3 5`도 토큰으로는 잘 잘린다. 틀렸다고 말하는 것은 파서다.

### 2. `a--b`와 `>>`

- 컴파일되지 않는다. 실험(JDK 21.0.12): `error: ';' expected`.
- JLS 21 §3.2: 각 단계에서 **가장 긴 번역**을 쓴다. 다른 번역이면 올바른 프로그램이 되더라도 그렇다. 그래서 `a--b`는 `a`, `--`, `b`다. `a - -b`로 띄우면 7이 된다.
- 예외: §3.2가 "contextual keywords and adjacent `>` characters"를 별도 처리한다고 적는다. 그래서 타입 문맥의 `>>`는 `>` 두 개로 쪼개져 제네릭이 닫힌다. 식 문맥의 `16 >> 2`는 그대로 시프트(4)다.

### 3. `a(b|c)*d`의 Thompson NFA

```text
  후위: a b c | * & d &        (&는 연결)

                    ┌──────────── ε (몸통 끝 → 다시 S*) ────┐
                    ▼                                      │
  ─▶[a]──▶ (S*) ──ε──▶ (S|) ──ε──▶[b]──┬───────────────────┘
             │            └──ε──▶[c]──┘
             └──ε──▶[d]──▶(MATCH)
  S* = 반복용 분기 상태(몸통으로 / 빠져나가기), S| = 선택용 분기 상태
```

- 순서: `b`·`c` 조각 → `|`로 선택 조각 → `*`로 반복(분기 상태 하나가 몸통과 다음으로 갈라짐) → `a`와 연결 → `d`와 연결 → 끝 화살표를 MATCH에 잇는다.
- 실험의 `toPostfix("a(b|c)*d")` 출력은 `abc|*&d&`였고, `abcbd`·`ad`는 참, `abx`는 거짓이었다.

### 4. 나눔의 수

- `aaaa`를 1개 이상의 덩어리로 나누는 방법: 글자 사이 3곳마다 "자른다/안 자른다" → 2³ = 8가지.
- 일반식: n글자면 2^(n-1). 끝의 `!` 때문에 전부 실패하니 백트래킹 엔진은 이 나눔을 전부 시도한다.
- 상태 집합 시뮬레이션: 글자마다 집합 한 번 갱신. O(n·m)이다(m = NFA 상태 수). 실험의 직접 구현은 n=10⁵에 82~155ms였다.

### 6. Java 방어가 꺼지는 경우

- 꺼짐 조건(소스): 패턴에 역참조가 하나라도 있으면(`hasGroupRef`) 전체가 꺼진다. 또 대상은 "바깥(top) 탐욕 반복 `Loop`"뿐이다.
- `(a+)+$|(b)\2`: `\2`는 매칭과 무관한 선택지에 있지만 `hasGroupRef`를 켠다 → 메모이제이션 없음 → 2^(n-1) 나눔을 다 시도. 실험 n=26에 7.0~9.8초.
- `a?ⁿaⁿ`: 반복 그룹이 아니라 선택(`a?`) n개다. 메모이제이션 대상이 아니다. 각 `a?`가 "먹는다/안 먹는다"를 고르는 2ⁿ 조합을 되돌아가며 시도한다. 성공하는 입력인데도 n=26에 4.2~5.7초였다. Cox 2007이 Perl로 보인 그 패턴이다(원문: Perl은 29글자에 60초 이상).

### 7. 부분집합 구성의 상태 수

- 실험: NFA 9·12·15·18·30·42(k=1·2·3·4·8·12, 선형), DFA 4·8·16·32·512·8192(=2^(k+1)).
- DFA는 "지난 k+1글자 중 어느 자리가 a였나"를 다 구분해야 한다. 그래서 지수 개 상태가 필요하다.
- 지연 DFA를 쓰는 선형 엔진(RE2)은 입력에서 실제로 만난 집합 상태만 만들어 캐시한다(Cox 2007 "Caching the NFA to build a DFA"). 시간은 선형으로 두고 메모리는 캐시 크기로 제한한다. Go `regexp`처럼 캐시 없이 상태 집합을 글자마다 다시 계산하는 방식도 선형이다.

### 8. ReDoS 대응 순서

1. 즉시: 그 기능·규칙을 끄거나 롤백한다. 입력 길이 상한을 앞단에 건다.
2. 원인 확인: 스레드 덤프에서 정규식 프레임이 도는 스레드와 그 입력(같은 글자가 길게 이어짐)을 찾는다.
3. 근본: 패턴을 고친다(중첩 펴기 `(a+)+`→`a+`, 원자 그룹·소유 수량자, 손 파서). 시간 상한(`charAt`에서 인터럽트를 확인하는 `CharSequence` + `Future.cancel(true)`)을 둔다. 선형 엔진(Go `regexp`·RE2 계열)으로 옮긴다.
4. 회귀 테스트: `"a"*n + "!"` 꼴로 n을 늘려 시간이 배로 느는지 본다.

- Cloudflare 2019-07-02(원문): Lua WAF가 PCRE(백트래킹, 폭주 방지 장치 없음)를 썼다. 새 XSS 규칙의 끝부분 `.*(?:.*=.*)`가 과도한 백트래킹을 일으켰다. 13:42 UTC 배포 후 HTTP/HTTPS 처리 CPU가 거의 100%가 됐고, 27분 장애였다. 후속 조치로 re2 또는 Rust regex 엔진 전환과 규칙 성능 테스트를 적었다.

### 9. `(a|b)*`의 `StackOverflowError`

- `java.util.regex`는 재귀 매칭이다. `(a|b)*`는 반복 한 번마다 `Branch`·`GroupHead`·`Loop`·`GroupTail`·`BranchConn` 프레임을 쌓는다.
- 실험(JDK 21.0.12, 기본 스택 1MB): n=1,000 성공, n=10,000 `StackOverflowError`.
- 고친 패턴: `[ab]*`. 문자 클래스 반복은 한 노드가 반복문으로 처리해 n=100,000에서도 성공했다. 입력 길이 상한도 같이 둔다.

### 10. `find()`와 `String.matches`

- `find()`는 부분 일치다. `12abc`·`abc12`도 통과한다. 검증에는 `matches()`(전체 일치)를 쓰거나 `^…\z`로 고정한다.
- `s.matches(regex)`는 `Pattern.matches(regex, s)`와 같고, 호출마다 정규식을 컴파일한다(Java API 문서: 여러 번 쓸 패턴은 한 번 컴파일해 재사용). 실험(100만 회, 3라운드 × 2회): `String.matches` 514~1,835ms, 미리 컴파일한 `Pattern` 132~161ms.
- 대처: `static final Pattern P = Pattern.compile("user_[0-9]{3}");` 후 `P.matcher(s).matches()`.
