# language/08-error-handling-models — 질문

## 질문

1. (왜) 특수값(`atoi`)·에러 값(Go)·합 타입(Result)·예외·panic을 "실패가 가는 곳", "무시하면 보이는 것", "컴파일러 강제 여부"로 비교하라. 조용한 실패에 가장 취약한 것은?
2. (예측) C에서 `atoi("12a")`, `atoi("abc")`의 결과는? `strtol`은 같은 실패를 어떻게 알리나? `atoi`에 표현할 수 없는 큰 수를 주면 C 표준은 무엇이라 하나?
3. (그림) `try { return Integer.parseInt(s); } catch (NumberFormatException e) { return -1; }`가 바이트코드에서 어떻게 표현되나? 정상 경로에 추가 비용이 없는 이유와, 던질 때 JVM이 하는 일을 순서대로 그려라.
4. (예측) 실험 C에서 "예외(스택 채움) 깊이 0"과 "예외(스택 안 채움) 깊이 0"은 몇 배 차이였나? 깊이 200에서는 스택을 안 채워도 왜 여전히 비쌌나(해석)?
5. (예측) `try { throw new IllegalStateException("결제 실패"); } finally { return 1; }`를 부르면 무엇이 반환되고 예외는 어떻게 되나? 근거 조항과, 이를 잡아 주는 javac 옵션은?
6. (경계) Java의 검사 예외와 비검사 예외를 JLS 정의로 구분하라. 검사 예외가 오히려 조용한 실패를 부르는 경로는?
7. (장애 진단) 운영 로그에 스택 트레이스 없는 `java.lang.NullPointerException`이 수천 줄 있다. 기동 직후 로그에는 스택이 있었다. 무엇 때문이고, 어떻게 원인 줄을 찾나?
8. (연결) Go에서 `n, _ := strconv.Atoi(input)`이 운영에서 어떤 데이터 문제를 만드나? `go vet`은 잡나? Rust는 같은 실수를 어떻게 줄이나?
9. (장애 진단) 검증 실패율이 오르자 CPU가 급등했고 프로파일 상위에 `fillInStackTrace`가 있다. 원인과 대처 두 가지는?
