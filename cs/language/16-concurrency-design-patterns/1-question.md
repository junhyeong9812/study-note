# language/16-concurrency-design-patterns — 질문

## 질문

1. (왜) 요청마다 `new Thread()`를 만들고 공유 객체를 각자 잠그는 코드는 무엇이 무너지나? 스레드 풀·Future·Scoped Locking이 각각 어느 것을 막나?
2. (그림) `ThreadPoolExecutor.execute()`가 작업을 받았을 때의 판단 순서를 그려라. `newFixedThreadPool(2)`에서 `maximumPoolSize`를 100으로 바꿔도 스레드가 2개를 넘지 않는 이유는?
3. (예측) 워커 2개, 작업마다 10ms, 최대 속도로 2,000건을 제출한다. (a) 무한 큐 + `-Xmx64m`, (b) 유한 큐 100 + `AbortPolicy`, (c) 유한 큐 100 + `CallerRunsPolicy`에서 각각 무슨 일이 생기나? 총 시간은 어떻게 다른가?
4. (계산) 작업 하나가 CPU 2ms, 대기 18ms이고 코어가 2개다. 풀 크기를 몇으로 시작하나? 그보다 크게 하면 처리량은 어떻게 되나?
5. (예측·경계) 500ms 블로킹 작업 8개를 executor 없이 `supplyAsync`로 띄우고 바로 가벼운 작업 하나를 띄운다. JVM이 보는 코어가 4개일 때와 2개일 때 가벼운 작업의 대기 시간은 각각 얼마쯤인가? 왜 코어가 적은 쪽이 오히려 빠른가?
6. (경계) `submit()`·`execute()`·`CompletableFuture.runAsync()`로 같은 예외 던지는 작업을 돌리면 각각 예외가 어디로 가나? 조용한 실패를 막는 코드 한 줄은?
7. (연결) Active Object와 Monitor Object는 공유 상태를 어떻게 다르게 보호하나? 각 패턴의 병목은 어디인가?
8. (장애 진단) 익명 요청의 감사 로그에 가끔 다른 사용자 ID가 찍힌다. 예외는 없다. 무엇을 의심하고 어떻게 확인·수정하나? 가상 스레드로 옮기면 해결되나?
9. (경계) 설정 객체의 `lo`·`hi` 두 필드를 둘 다 `volatile`로 선언했다. 읽는 쪽이 `lo > hi`를 볼 수 있나? DCL에서 `volatile`이 필요한 이유와 비교해 설명하고, 둘 다를 피하는 설계를 대라.
