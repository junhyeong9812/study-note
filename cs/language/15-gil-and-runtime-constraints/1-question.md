# language/15-gil-and-runtime-constraints — 질문

## 질문

1. (왜) GIL은 언어(Python)의 성질인가, 구현(CPython)의 성질인가? 근거 하나를 대라. CPython이 GIL을 두는 이유를 참조 카운트로 설명하라.
2. (그림) 스레드 4개가 각각 (a) 순수 파이썬 계산, (b) `time.sleep`, (c) `hashlib.sha256(64MB)`를 할 때 GIL을 쥐고 놓는 모습을 시간축에 그려라.
3. (예측) CPython 3.12, 물리 코어 2개에서 `cpu()`(약 0.5초짜리 순수 파이썬 계산) 4개를 직렬 / 스레드 4개 / 프로세스 4개로 돌리면 각각 대략 몇 초인가? `sha256(64MB)` 4개를 스레드 4개로 돌리면?
4. (예측) 원고 §10의 `g += 1`(스레드 50개 × 10만 번)을 CPython 3.12로 돌리면 몇이 나오나? 읽기와 쓰기 사이에 `abs(0)` 호출을 끼우면? 두 결과가 다른 이유를 3.12 구현으로 설명하라.
5. (경계) `sys.getswitchinterval()`이 0.005라는 것은 "각 스레드가 정확히 5ms씩 돈다"는 뜻인가? 문서는 무엇이라고 하나?
6. (연결) PEP 703의 free-threaded 빌드는 GIL 없이 참조 카운트를 어떻게 안전하게 하나(기법 두 가지 이상)? 대가는 무엇인가?
7. (경계) Node.js와 Java(HotSpot)는 "GIL 같은" 제약이 있나? 각각 CPU 작업을 병렬로 하려면 무엇을 써야 하나?
8. (장애 진단) 배치를 스레드 8개로 나눴는데 시간이 그대로다. 무엇을 보면 GIL이 원인인지 알 수 있고, 어떤 순서로 대처하나?
9. (장애 진단) `multiprocessing`으로 바꾼 뒤 CPU 문제는 풀렸는데 컨테이너가 OOMKilled된다. 왜이며 어떻게 줄이나?
10. (연결) 원고 §9의 "멀티스레드 62.182초 / 싱글스레드 0.643초"를 같은 코드로 재현하면 어떻게 나왔나? 원고 결론 중 맞는 부분과 다시 봐야 할 부분은?
