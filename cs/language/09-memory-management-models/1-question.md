# language/09-memory-management-models — 질문

## 질문

1. (왜) 힙 객체의 해제 시점은 왜 컴파일 시점에 정하기 어려운가? 해제를 잘못 정했을 때 생기는 세 가지 실패(너무 이르게·두 번·안 함)를 각각 이름과 함께 말하라.
2. (그림) 수동·참조 카운팅·추적 GC·소유권 네 모델을 "해제를 정하는 주체 / 해제 시점 / 틀리면 어떻게 드러나나" 세 칸으로 표를 그려라.
3. (예측) CPython 3.12에서 `gc.disable()` 후 서로를 가리키는 노드 쌍(각 10KB)을 1000쌍 만들고 `del` 했다. 남은 메모리는 대략 얼마인가? 이어서 `gc.collect()`를 부르면 어떻게 되나?
4. (예측) Java 21에서 같은 순환 쌍을 만들고 지역 변수만 `null`로 바꾼 뒤 `System.gc()`를 불렀다. 한쪽에 걸어 둔 `WeakReference.get()`은 무엇을 돌려주나? 3번과 결과가 갈리는 이유는?
5. (예측) C에서 20바이트 구조체를 `free`한 직후 같은 크기를 `malloc`해 다른 사용자 데이터를 쓰고, 옛 포인터로 읽었다(gcc 13 `-O0`, glibc). 무엇이 출력될 수 있나? `-fsanitize=address`로 빌드하면 무엇이 달라지나?
6. (경계) "GC가 있는 언어에는 메모리 누수가 없다"는 말은 어디서 틀리나? "Rust는 메모리 누수를 막는다"는 말은?
7. (경계) `sys.getrefcount("abcde")`가 `4294967295`를 낸다는 원고의 관찰은 언제나 성립하나? 이 값을 코드에서 쓰면 안 되는 이유는?
8. (연결) 추적 GC의 "도달 가능성" 판정은 어떤 그래프 알고리즘인가? 참조 카운팅이 순환을 못 푸는 이유를 같은 그래프 언어로 설명하라.
9. (장애 진단) CPython 배치 워커의 메모리가 작업마다 계단식으로 오른다. 순환 누수인지, 도달 가능한 캐시 누수인지 어떻게 가르나? 각각의 대처는?
10. (장애 진단) Rust 빌드가 `E0382`로 실패했다. 무엇을 뜻하고, 고치는 선택지 세 가지와 각 선택의 대가는?
