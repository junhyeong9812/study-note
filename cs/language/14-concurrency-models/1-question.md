# language/14-concurrency-models — 질문

## 질문

1. (왜) 모든 동시성 모델이 다르게 답하는 두 질문은 무엇인가? OS 스레드·async/await·가상 스레드·액터를 그 두 질문으로 구분해 보라.
2. (그림) `const u = await db.user(id); const o = await db.orders(u); return render(u, o);`를 컴파일러가 상태 기계로 바꾼 모습을 그려라. 지역 변수 `u`는 기다리는 동안 어디에 있나? 이것을 왜 stackless라 부르나?
3. (예측) `--cpus=2` 컨테이너, JDK 21에서 `Thread.sleep(100)` 작업 10,000개를 (a) 고정 풀 200개, (b) `newVirtualThreadPerTaskExecutor()`로 돌리면 각각 대략 몇 초인가? 작업이 `sleep` 대신 100ms짜리 계산이면 어떻게 달라지나?
4. (예측) 같은 환경(캐리어 2)에서 가상 스레드 100개가 각자 **새로 만든** 락 안에서 `sleep(100)`한다. `synchronized`와 `ReentrantLock`은 각각 대략 얼마 걸리나? 경합이 없는데도 차이가 나는 이유는?
5. (경계) pinning은 JEP 444 기준 어떤 두 경우에 생기나? JDK 24의 JEP 491 뒤에도 남는 경우는? 파일 I/O나 `Object.wait()`는 어떻게 처리되나?
6. (예측) node 22에서 `async function handler()` 안에서 `pbkdf2Sync`(약 170ms)를 부르는 경우와 `await`로 콜백판 `pbkdf2`를 부르는 경우, 10ms 주기 타이머의 최대 지연은 각각 얼마쯤인가? 둘 다 `async`인데 왜 다른가?
7. (예측) Go에서 결과를 무버퍼 채널로 보내는 고루틴을 띄우고, 호출자는 5ms 타임아웃으로 먼저 떠난다(작업은 20ms). 1,000번 호출 뒤 남는 고루틴 수는? 버퍼 1 채널이면?
8. (연결) CSP와 액터는 둘 다 메시지로 협력한다. 메시지를 "어디로" 보내는지, 송신이 막히는지에서 어떻게 다른가? 각 모델에서 데이터 레이스 대신 생기는 장애 모양은?
9. (장애 진단) 가상 스레드로 바꾼 뒤 CPU는 놀고 처리량은 풀 시절보다 낮다. 무엇을 의심하고, 어떤 출력·이벤트로 확인하고, 어떻게 고치나?
10. (장애 진단) Node 서비스에서 API 하나가 무거워진 뒤 모든 API의 p99가 동시에 뛰었다. 원인 가설과 확인 방법, 대처를 대라.
