## 챕터 하나의 진행 순서 (작성 순서)

1. **코드 치며 공부** — 원본 챕터(README + impl + src)를 직접 치면서 이해한다. 모르는 것은 전부 질문으로 해소.
2. **`2-summary.md` 작성** — 공부 직후, 동작 워크플로우를 **내가 먼저 기억으로 서술**하고 Claude가 빠지거나 틀린 곳만 짚는다.
3. **`1-question.md` 작성** — summary를 보며 "안 까먹어야 하는 것"을 직접 판별해 5~7개 질문으로. 직접 쓴다.
4. **`3-answer.md` 작성** — **summary를 닫고** 기억만으로 답을 쓴다 → 실제 코드로 검증 → 틀린 부분만 수정. 기준 소스는 코드다.

> 작성 순서는 2 → 1 → 3, 복습(사용) 순서는 1 → 2 → 3.

## 질문 유형 (지도 수준 — 세부 암기 금지)

왜(why) · 예측(what if) · 경계(어느 계층의 책임인가) · 연결(다른 챕터와의 다리).
