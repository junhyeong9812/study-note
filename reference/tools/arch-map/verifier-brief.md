# 검증 워커 브리핑

다른 워커가 쓴 지도 문서가 **소스와 어긋난 곳**을 찾아 고친다. 너는 작성자가 아니다 — 문서를 믿지 말고 소스를 기준으로 반증한다. `<도구>`·`<소스>`·`<태그>`·`<워크트리>` 자리는 배정 메시지가 채운다.

## 경로

- 검증 대상: `<워크트리>/opensource/<도구>/architecture/<배정 경로>` (이 안쪽만 수정)
- 소스(읽기 전용): `<소스>` (`<태그>`). checkout·fetch·쓰기 금지.
- db-engine(읽기 전용): `~/project/db-engine/impl/*.md`
- 형식 규칙: [writer-brief.md](writer-brief.md)

## 할 일

1. 기계 대조: `python3 reference/tools/arch-map/check-code-blocks.py <소스> <배정 경로>` — bad 0 이 될 때까지 문서를 소스에 맞춘다.
2. 줄 번호 전수: 산문·그림의 모든 `L<숫자>`·`파일:줄`, `## 위치` 범위와 GitHub `#Lx-Ly` 를 sed 로 열어 서술과 맞는지 확인한다. 스크립트로 목록을 뽑아 빠뜨리지 않는다.
3. 서술 반증: 문서마다 동작 주장(분기 조건, 부등호와 경계값, 호출 순서, 반환값 의미, 스레드 경계, "왜") 최소 3개를 소스로 반증 시도. 근거 없는 "왜"는 삭제하거나 근거 있는 문장으로.
4. 예시 그림: 숫자·순서를 소스 규칙으로 손계산해 맞는지, 불가능한 시나리오가 아닌지.
5. db-engine 절: impl 문서에 실제로 있는 이름·동작인지. 따옴표 인용은 원문 그대로인지.
6. 형식: `@@` 0, 상대 링크 실존, 브리핑 절 구성.

## 규칙

- **하위 워커(fork·Agent)를 띄우지 않는다.** 동시 워커 수 상한은 메인이 관리한다 — 배정 범위는 혼자 끝낸다.
- 줄 번호를 **고칠 때는 새 값도 `sed -n '<N>p'` 한 줄 출력으로 다시 확인**하고 그 출력을 packet 에 붙인다. 여러 줄을 볼 때 몇 번째 줄인지 착각해 맞는 번호를 틀리게 바꾼 사례가 있었다. 확신이 없으면 고치지 말고 의심 항목으로 남긴다.
- 커밋 금지.

## 돌려줄 packet
