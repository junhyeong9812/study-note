# demo 블록 규칙 — 화면으로 봐야 아는 것을 문서에 담는 법

CSS·애니메이션·HTML 렌더링처럼 **눈으로 봐야 이해되는 주제**가 있다.
그런 주제의 `2-summary.md` 는 코드와 함께 **그 코드가 화면에서 무엇을 하는지**를 담는다.

이 문서는 그 형식을 정한다. 나중에 이 저장소로 공부 사이트를 만들 때 **이 규칙이 계약서**가 된다.

## 설계 기준

1. **지금 아무것도 깨지지 않아야 한다.** GitHub·에디터에서는 평범한 코드블록으로 보인다.
2. **사이트 없이 읽어도 이해돼야 한다.** 렌더러가 없어도 무슨 일이 일어나는지 글로 알 수 있어야 한다.
   문서가 사이트에 종속되면 안 된다.
3. **기계가 집어낼 수 있어야 한다.** 사이트가 어느 블록을 실행할지 문자열 하나로 판별한다.

## 형식

코드펜스의 언어 뒤에 **`demo`** 를 붙이고, 블록 **바로 아래**에 두 줄을 단다.

````markdown
```html demo
<button class="btn">호버해 보세요</button>
<style>
  .btn { padding: 8px 16px; transition: background .3s ease; }
  .btn:hover { background: #2563eb; color: #fff; }
</style>
```

> **보이는 것** — 마우스를 올리면 0.3초에 걸쳐 배경이 파란색으로 바뀐다. 뗄 때도 같은 시간으로 돌아온다.\
> **바꿔 볼 것** — `.3s` → `2s`(느리게) · `ease` → `linear`(등속) · `:hover` → `:focus`(키보드로도 되는지)
````

- **`보이는 것`은 필수다.** 없으면 렌더러 없이 읽는 사람이 아무것도 못 얻는다.
  「무엇이, 어떤 조작에, 얼마 동안, 어떻게」를 적는다.
- **`바꿔 볼 것`은 권장이다.** 사이트에서 값 조작 UI(슬라이더·토글)로 바뀔 자리다.
  바꿀 값과 **그때 무엇이 달라지는지**를 같이 적는다.
  ★ **결과를 단언하면 그것도 검증 대상이다** — 사실상 두 번째 demo 이기 때문이다.
  ★★ **환경이 만들 수 없는 조건을 `바꿔 볼 것`에 쓰지 마라.** 검증할 수 없는 단언이 된다.
  실측 사례: 「창을 300px 로 줄이면 뒤집힌다」를 썼다가 **Chrome 의 창 폭 하한이 500** 이라
  그 조건을 만들 수 없음이 드러났다(`--window-size=375,667` 을 줘도 `innerWidth` 가 500 이다).
  잴 수 있는 조건으로 바꾸고, **못 잰 구간이 있다는 사실을 본문에 적는다.**
  반면 「무엇을 보라」는 열린 권유(`:focus-visible` 로 바꿔 키보드로도 되는지)는 확인 대상이 아니다.
- **`실측` 줄(선택)** — `*(Chrome 151 headless 실측: 1초 시점 210.7px)*` 처럼 **측정치를 한 줄** 남긴다.
  ★★ **좌표를 싣는 실측은 「어느 창 폭에서 쟀나」를 함께 적는다.**
  실측: 24편의 절대 좌표가 **창 폭 804 에서만** 재현되고 기본 창(780)에서는 **정확히 24px 씩 어긋난다.**
  `3-answer` 머리말에만 적혀 있고 `2-summary` 의 demo 옆에는 없어 재현이 안 됐다.
  ★ **`실측` 줄에 창 폭을 적는다** — 색 실측의 「어느 좌표를 읽었나」와 같은 이유다.
- ★★ **문서 밖 실험은 재검증이 불가능하다.** demo 가 아닌 실험의 **마크업이 본문에 없으면**
  추출기도 사람도 그 수치를 다시 던질 수 없다(실측: 24편의 실험 3건이 그래서 재현 불가였다).
  **수치를 싣는 실험은 최소한 마크업을 코드블록으로 본문에 남긴다.**
  ★ 다시 못 던지는 수치는 **고치지도 마라** — 다른 마크업으로 잰 값을 바꿔 적으면 그게 날조다.
  「다시 던지지 못했다」고 적는 것이 맞다.
  ★★ **회차·프레임 경계를 샘플 지점으로 삼지 마라.** 「좌표가 결과를 바꾼다」의 **시간축 판**이다.
  실측에서 `iteration-count` 실험의 **1.00초 샘플이 정확히 회차 경계**라 재실행에서 값이 크게 뒤집혔다
  (첫 판 279.98 → 재확인 43.98). 같은 실험에서 **2.30초 지점은 두 판이 한 자리도 안 움직였다.**
  ★ **경계에서 비켜난 지점을 골라라.** 경계에서 재야 한다면 **그 값이 흔들린다는 사실 자체를 결론으로** 적는다.
  ★★ **색·픽셀 실측은 「어느 좌표를 읽었나」를 반드시 함께 적는다.** 스칼라와 달리 **샘플 좌표가 결과를 바꾼다** —
  실측에서 띠 중앙을 찍었더니 가운데 정렬된 글자 글리프에 걸려 다른 값이 나왔다.
  `*(Chrome 151 실측: x = 20·90·160·230·270 에서 …)*` 처럼 좌표를 명기한다.
  ★ **`--disable-gpu` 의 픽셀은 보장이 아니다** — 곡선 안티앨리어싱과 혼합 반올림이 GPU 와 다를 수 있다
  (실측에서 `multiply` 한 채널이 공식 10.2 대 픽셀 11 로 1 어긋났다).
  **경계의 중간색 하나로 판정하지 말고 띠 폭·불투명 지점처럼 흔들리지 않는 것으로 읽어라.**
  렌더러 없이 읽는 사람에게 지어낸 것이 아님을 보이고, 브라우저가 바뀌었을 때 대조 기준이 된다.

## 블록 안에 담는 것

- **자기완결이어야 한다.** 외부 파일·CDN·이미지에 기대지 않는다. `<style>` 을 블록 안에 둔다.
- **하나만 보여 준다.** 한 블록이 말하는 것은 하나다(§3.2 「그림 하나가 말하는 것은 하나」와 같은 규칙).
- **짧게.** 20줄을 넘기면 보여 주려는 것이 하나가 아닐 가능성이 크다.
- **이미지가 꼭 필요하면 data URI** 로 넣는다(8×8 GIF 한 줄이면 배경 반복은 보인다). 외부 파일에 기대지 않는다.
- **모션 접근성(`prefers-reduced-motion`)은 demo 안에 넣지 않는다** — 「하나만 보여 준다」가 깨진다.
  해당 주제로 **링크**한다.
- **움직임에는 멈출 방법을 둔다.** 끝없이 도는 애니메이션은 `:hover` 나 버튼으로 시작하게 하거나,
  `prefers-reduced-motion` 을 존중하는 형태로 쓴다.

## 정적 그림과의 관계

`demo` 는 **§3 도식을 대신하지 않는다.**
「선언 → 계산 → 렌더 결과」에서 **계산 단계는 화면에 안 보이므로** 여전히 ASCII 도식이 필요하다.
demo 는 그 도식의 **결과 칸을 실물로 확인시켜 주는 것**이다.

| | 담당 |
|---|---|
| ASCII 도식 | 왜 그렇게 되는가 — 캐스케이드 계산·박스 치수 결정·합성 단계 |
| `demo` 블록 | 그래서 실제로 이렇게 보인다 |

★★ **도식 개수를 셀 때 「그림」과 「실행 출력 덤프」를 갈라 세라.**
둘 다 ```` ```text ```` 펜스라 한꺼번에 세면 수가 부풀고, **그 부푼 수를 목표로 주면 워커가 채우려고 도식을 늘린다.**
실측(`2-summary.md` 기준) — **그림 4\~16개 · 출력 덤프 0\~10개.** 계산이 본체인 주제일수록 덤프가 많다
(`36-custom-properties` 는 그림 14 · 덤프 10). **개수는 목표가 아니라 사후 관찰**이다.
★ **한 가지 관찰로 두 질문에 답하지 마라 — 정의와 결과는 다른 창이다.**
`grid-column: 2 / 1` 은 계산값이 `2 / 1` 그대로인데 **놓이는 자리는 `1 / 2` 와 같다**(조용히 맞바뀐다).
계산값만 읽으면 못 잡고 좌표를 따로 재야 보인다. **선언을 읽는 창과 결과를 재는 창을 늘 함께 둔다.**

★ **2026-09-21 정정 — 「시각 주제일수록 도식이 줄어든다」는 사실이 아니다.**
첫 배치 실측에서 `transition` 주제의 도식이 **19개로 가장 많았다**(캐스케이드 16 · 명시도 15 · Flexbox 11).
demo 가 움직임을 보여 주면 **「왜 0.3초에 80%인가」·「왜 되돌아올 때 0.6초인가」라는 질문이 더 생겨서**
도식도 같이 는다. 분업 자체는 맞지만 비중 예측은 반대였다.

계산이 본체인 주제(캐스케이드·명시도)에서 demo 가 하는 일은 따로 있다 —
**결과가 눈에 안 보이므로 「내 손계산이 맞나」를 확인할 수단**이 된다.

## 리스트업의 `렌더` 칸

`<언어>/syntax/README.md` 주제 표의 `렌더` 칸이 이 규칙의 적용 대상을 정한다.

| 값 | 뜻 |
|---|---|
| `필수` | 화면 없이는 이해가 안 된다 → `demo` 블록을 반드시 둔다 |
| `도움` | 글·도식으로도 되지만 보면 빠르다 → 여유가 되면 둔다 |
| `불필요` | 정적 도식으로 충분하다 |

## 쓴 사람이 직접 확인한다 — 어떻게

★ **`보이는 것`에 적은 것이 실제로 그런지 확인하지 않으면 거짓이 된다.** 첫 배치에서 실제로 2건이 거짓이었고,
그중 하나는 **화면으로는 「넷이 비슷하게 간다」로 보여 눈으로는 잡을 수 없는** 것이었다
(단축 `transition` 이 `timing-function` 을 함께 선언해 명시도로 이겨서 막대 넷이 전부 같은 곡선으로 움직였다).

- **엔진은 Chrome 하나다.** Firefox 155 는 설치돼 있으나 이 환경에서 headless 스크린샷이 산출되지 않는다
  (`exit 0` 으로 끝나며 파일을 만들지 않는 **조용한 실패**). 크로스 브라우저 차이는 **Baseline 데이터로만** 접지한다.
- ★★ **색이 걸린 블록은 스크린샷 픽셀을 읽는다.** `:hover`·전환처럼 입력·시간이 걸린 것과 달리
  **정지 화면인데도 눈으로 못 잡는** 별개의 유형이다 — 「비슷한 파랑」은 구분이 안 되고,
  「점이 안 보인다」가 「칠 영역 밖이라 안 그려졌다」인지 「색이 같아서 안 보인다」인지도 눈으로는 모른다
  (실측에서 거짓 demo 1건이 정확히 그 모양이었다).
  ★ **`extract-demo-blocks.py --render` 는 계산값만 보므로 이 유형을 못 잡는다** —
  계산값이 같고 **픽셀만 다른** 경우(보간 공간·영역 잘림·타일 `round`)가 통째로 사각지대다. `--shot` 으로 PNG 를 남겨 읽어라.
- ★ **계산값만으로도 부족하다 — UA 가 그리는 것은 `getComputedStyle` 에 안 나온다.**
  `color-scheme: dark` 가 페이지 바탕과 스크롤바 트랙을 다시 그리는 것은 **스크린샷 픽셀 표본으로만** 잡혔다.
- **스크린샷만으로는 부족하다.** `:hover`·전환처럼 **입력과 시간이 걸린 것**은 찍을 수가 없다.
  CDP(`--remote-debugging-port`)에 붙어 `Input.dispatchMouseEvent` 로 실제 입력을 넣고,
  시각마다 `getComputedStyle`·`getBoundingClientRect` 를 샘플링한다.
- ★★ **`--virtual-time-budget` 은 시간이 걸린 실험을 조용히 무효화한다.**
  가상 시간이 먼저 다 흘러 **「아무 일도 안 일어남」이 찍힌다** — 실측에서 `font-display` 다섯 값이
  전부 「안 바뀜」으로 나와 한 번 헛다리를 짚었다. **시간 축이 실시간이어야 하는 실험은 CDP 로만 잰다.**
- ★★ **「이 글꼴이 있나」를 `document.fonts.check()` 로 묻지 마라 — 없는 글꼴에도 `true` 를 돌려준다.**
  실측: `check("40px Zzzznope")` 가 `true` 다. 그 함수가 답하는 것은 **웹폰트 로드 상태**이지
  「이 이름이 풀리나」가 아니다. `fc-match` 도 없는 이름에 항상 답하므로 판정 도구가 아니다.
  ★ **판정은 「센티넬 폭 대조」로 한다** — 후보를 폴백과 짝지어(`Georgia, monospace`) 같은 글자의 폭을 재고,
  **폴백만 쓴 것과 폭이 같으면 그 글꼴은 안 쓰인 것**이다(실측: Georgia 200.00 = monospace 200.00,
  Noto Sans 221.77 ≠ 200.00).
- **검증용 사본에는 래퍼를 붙인다.** 문서의 블록에는 `<!doctype>`·`<body>` 가 없으므로,
  그대로 띄우면 기본 여백 때문에 실측 좌표가 문서와 어긋난다.
- **스크린샷·측정 파일은 저장소에 넣지 않는다.** 확인용으로만 쓰고 버린다.
- ★★ **제출 직전에 「완성된 문서에서」 demo 를 다시 뽑아 재실행한다.**
  §2-1 에는 실행 블록을 문서에서 추출해 다시 던지는 검사가 있는데(`reference/tools/extract-exec-blocks.py`),
  demo 쪽에도 같은 짝이 필요하다. 이유가 같다 — **「돌려 봤다」와 「옮겨 적은 게 맞다」는 다른 검사**이고,
  옮겨 적기 사고는 실측에서 손으로 재배치한 블록에 몰렸다.
  ```` ```html demo ```` 펜스를 정규식으로 뽑아 전부 다시 띄우고 값을 대조한다 — 20줄짜리 스크립트면 된다.
- ★★ **병렬 작업에서 정리 명령을 넓게 쓰지 마라 — 남의 브라우저를 죽인다.**
  실측 사고: 한 워커가 `pkill -9 -f 'remote-debugging-port=9'` 로 정리하다가
  **다른 워커의 headless Chrome(포트 9741)을 같이 죽였다.** 저장소 파일에는 영향이 없었지만
  **그 워커가 측정 중이었다면 그 판이 무효**가 된다.
  ★ **자기 것만 지워라** — 띄울 때 받은 **PID 를 기억해 그 PID 만** 죽이고,
  포트·프로필 디렉터리도 **자기 작업 이름으로 고유하게** 잡는다(`--user-data-dir=/tmp/<작업명>-<시각>`).
  ★ **여러 워커가 같은 기계에서 도는 것을 전제로 짜라.** 포트가 겹치면 **뒤 브라우저가 앞에 붙어**
  엉뚱한 결과가 나온다 — 실측에서 「`--force-prefers-reduced-motion` 이 안 먹는다」는 **틀린 결론**이 그렇게 나왔다.
- ★ **`:hover`·`:focus` 실험은 매 판 문서를 다시 띄우고 시작한다.**
  앞선 실험이 포커스를 남기면 `Tab` 이 엉뚱한 요소로 간다(실측에서 첫 판이 그렇게 어긋났다).
- ★ **`Runtime.evaluate` 로 값을 넣는 것은 「사용자 조작」이 아니다.**
  `el.value = …` 로는 `:user-invalid` 가 켜지지 않는다. 사용자 상태가 걸린 의사 클래스는
  **반드시 `Input.dispatch*` 로 실제 입력을 넣어야** 한다.
- ★ **갈리는 축을 하나로 단정하지 마라.** `:focus-visible` 을 「마우스 대 키보드」로만 갈라 보면 틀린다 —
  실측에서 **요소 종류**가 축 하나 더였다(버튼은 마우스 클릭에 안 켜지는데 **텍스트 입력칸은 켜진다**).
  버튼만 쟀으면 「마우스면 안 켜진다」는 틀린 일반화를 적었을 것이다.

## 사이트를 만들 때 (나중)

- `demo` 가 붙은 블록만 골라 **격리된 프레임**에서 실행한다. 문서의 나머지는 평소대로 렌더한다.
- 사용자 입력을 받는 블록은 없다 — 전부 저장소 안에서 온 정적 코드다.
- `바꿔 볼 것` 에 적힌 값을 조작 UI 로 승격한다.
