# Python 변천사 — 쉽게 다시 쓴 판

> 원본: `~/project/python-history/README.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-20).\
> 원문 README의 소개 문단·「읽는 법」·「큰 줄기」는 원문 그대로이고, 「구성」 표의 **「시대/주제」 열 문구**는 열을 따로 두지 않고 각 행 「한 줄 요약」 끝에 ` — `로 그대로 붙였다.\
> 「한눈에」 ASCII 도식 1개와 목차의 「시기」·한 줄 요약, 「급하면 이렇게 골라 읽어도 된다」 길찾기는 원문 README에 없는 보충이다.\
> 그중 「시기」와 한 줄 요약은 **각 편에서 발췌한 보충**이다 — 04·05·06은 이 폴더의 같은 편에서, 01·02·03은 원본 `~/project/python-history/`의 해당 편에서 발췌했다.\
> 「시기」의 출처는 편마다 다르다 — 01·02·03은 그 편 제목 괄호의 범위를, 04·05는 그 편 「한눈에 보는 타임라인」 표의 첫 행과 마지막 행을 옮겼다. 원문이 시기를 밝히는 형식이 편마다 달라 하나의 기준으로 통일하지 않았다.\
> **06은 시기 칸을 비웠다(`—`)** — 04·05에 쓴 기준(「한눈에 보는 타임라인」 표의 첫 행과 마지막 행)을 06에는 적용할 수 없기 때문이다. 06에는 그런 연표가 아예 없고, 대신 놓인 「정리: 얽혀 있는 진화」 표는 연대순이 아니라 축(GIL·타이핑·async·GC·최적화)별로 묶여 있어 첫 행·끝 행이 시기의 양 끝을 뜻하지 않는다.

Python의 역사를 **시대순 + 생태계 + 개념사**로 정리한 문서 모음이다. 어떤 기능이 언제·왜 들어왔고, 2→3 분열은 무엇이었으며, Python이 어떻게 데이터·ML의 표준이 됐는지를 다룬다. 모든 문서는 한국어. (자매: `java-history`·`database-history`)

## 한눈에 — 6편이 이어지는 순서

```text
원문 README 「읽는 법」이 적은 순서 — 01→06
오른쪽은 그 문장이 각 편에 붙인 말이다.

 01 탄생 ~ Python 2.x   ──  단순·가독성(탄생)
   │
 02 Python 3 대전환     ──  3 전환의 고통
   │
 03 현대 Python         ──  타입·async·속도의 현대화
   │
 04 패키징·도구         ┐
   │                    ├──  왜 Python이 살아남고 지배했나 (생태계·글루)
 05 데이터·ML 생태계    ┘
   │
 06 핵심 개념 진화      ──  그 바탕의 구현 (GIL·타이핑·async)
```

그림 읽는 법 — 세로선은 원문 README가 적은 **읽는 순서**이고, 편들 사이의 파생·인과 관계를 뜻하지 않는다.\
오른쪽 다섯 마디는 원문 「읽는 법」의 두 문장을 토막 내 그 자리에 붙인 것이다 — 04와 05가 한 괄호로 묶인 것은 원문이 그 둘을 「04·05는 *왜 Python이 살아남고 지배했나*(생태계·글루)를」 한 마디로 적었기 때문이다.

## 읽는 법

01→06으로 읽으면 **단순·가독성(탄생) → 3 전환의 고통 → 타입·async·속도의 현대화**가 보인다. 04·05는 *왜 Python이 살아남고 지배했나*(생태계·글루)를, 06은 *그 바탕의 구현*(GIL·타이핑·async)을 다룬다.

> 큰 줄기: **가독성 우선 스크립트 언어 → 2→3 청산 → 타입·동시성·성능 완성 → 데이터·ML·LLM 시대의 글루 언어.**

급하면 이렇게 골라 읽어도 된다.

- Python이 왜 이렇게 생긴 언어인지부터 알고 싶다 → **01**
- Python 2와 3이 왜 그렇게 오래 갈라져 있었는지 궁금하다 → **02**
- 요즘 Python에 매년 무엇이 들어왔는지 훑고 싶다 → **03**
- `pip`·`poetry`·`conda`·`uv`가 왜 다 있는지 모르겠다 → **04**
- `requirements.txt`만으로 왜 부족한지 알고 싶다 → **04의 「requirements.txt의 한계 — 왜 그것으로 충분하지 않았나」**
- `setup.py`와 `pyproject.toml`이 무슨 관계인지 모르겠다 → **04의 「pyproject.toml과 PEP들 — 도구에서 표준으로 (2016~2020)」**
- conda 세계와 pip 세계를 섞으면 왜 환경이 깨지는지 궁금하다 → **04의 「conda — 다른 길을 간 과학 생태계 (2012)」**
- NumPy가 왜 생태계의 주춧돌이라 불리는지 알고 싶다 → **05의 「1세대: 수치 배열의 탄생 — Numeric에서 NumPy까지」**
- 느린 언어인 Python이 어떻게 ML의 표준이 됐는지 궁금하다 → **05의 「왜 Python이 데이터·ML의 표준 언어가 됐나」**
- PyTorch와 TensorFlow가 무엇이 다른지 잡고 싶다 → **05의 「딥러닝의 폭발 — Theano에서 PyTorch까지」**
- 스레드를 늘렸는데 빨라지지 않는다 → **06의 「1.2 동시성의 한계」**
- GIL이 정말 없어지는 건지 알고 싶다 → **06의 「1.5 PEP 703 — GIL을 선택적으로 (free-threading, Python 3.13~)」**
- 타입 힌트를 붙이면 실행 중에 검사되는지 궁금하다 → **06의 「4.2 무엇을 해결하나 (그리고 무엇을 하지 않나)」**
- `async`/`await`가 왜 `yield`에서 나왔는지 알고 싶다 → **06의 5절**
- `del` 했는데 메모리가 안 줄어든다 → **06의 「6.1 1차 메커니즘 — 레퍼런스 카운팅」**
- Python 3.11이 왜 빨라졌는지 궁금하다 → **06의 「7.1 특수화 적응형 인터프리터 (PEP 659, Python 3.11 / 2022)」**
- Python 전체 지도를 한 번에 잡고 싶다 → **01→06 전체** (위 「읽는 법」이 적은 순서 그대로)
