> 원본: `~/project/js-history/README.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-19).\
> 연도·인명·표준 이름은 원문 그대로다.\
> 「한눈에」 ASCII 도식 1개와 목차의 「시기」·한 줄 요약, 「급하면 이렇게 골라 읽어도 된다」 길찾기는 원문 README에 없는 보충이다.\
> 그중 「시기」와 한 줄 요약은 **각 편 본문에서 발췌한 보충**이다 — 04·05·06은 이 폴더의 같은 편에서, 01·02·03은 원본 `~/project/js-history/`의 해당 편에서 발췌했다.

JavaScript의 역사를 **언어 진화 + 런타임 + 생태계 + 프레임워크**로 정리한 문서 모음이다.\
10일 만에 만들어진 언어가 어떻게 ES6로 거듭나고, 서버(Node)로 나가고, 프론트엔드 프레임워크 생태계를 이뤘는지를 다룬다.\
모든 문서는 한국어. (자매: `java-history`·`python-history`·`rust-history`)

## 읽는 법

01→02는 *언어*, 03은 *런타임 확장*, 04는 *비동기 모델*, 05는 *도구*, 06은 *프레임워크*.\
04·06은 corpus의 `에러-부재-표현`·`동시성-제어`·frontend 문서와 직접 이어진다.

> 큰 줄기: **브라우저 스크립트 → ES6로 진짜 언어 → Node로 서버 진출 → 빌드·타입 생태계 → 프레임워크는 `UI = f(state)`로 수렴(반응성·렌더 위치의 진화).**

급하면 이렇게 골라 읽어도 된다.

- JavaScript가 왜 이렇게 생긴 언어인지부터 알고 싶다 → **01**
- `let`/`const`·화살표 함수·`class`가 언제 왜 생겼는지 궁금하다 → **02**
- Node·Deno·Bun이 뭐가 다른지 알고 싶다 → **03**
- `setTimeout`과 `Promise.then` 중 뭐가 먼저 실행되는지 늘 헷갈린다 → **04의 「이벤트 루프 상세」**
- 콜백 지옥이 왜 나빴고 async/await가 무엇을 되돌려 줬는지 알고 싶다 → **04의 1~5단계**
- 무거운 계산 때문에 화면이 얼어붙는 중이다 → **04의 「동시성 — 진짜 병렬이 필요할 때」**
- `import`와 `require`가 왜 둘 다 있는지 알고 싶다 → **05의 1절**
- webpack 대신 Vite를 쓰라는 말이 무슨 뜻인지 알고 싶다 → **05의 2절**
- TypeScript를 왜 다들 쓰는지 알고 싶다 → **05의 4절**
- React·Vue·Angular·Svelte 중 무엇을 고를지 기준을 잡고 싶다 → **06 → 06의 「진화의 논리」**
- SSR·hydration·서버 컴포넌트가 무슨 말인지 알고 싶다 → **06의 6~7절**
- JS 전체 지도를 한 번에 잡고 싶다 → **01 → 02 → 04 → 06**
