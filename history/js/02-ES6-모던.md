# ES6 대변혁 ~ 현대 ECMAScript (2015~)

> 원본: `~/project/js-history/02-ES6-모던.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-19).\
> 연도·인명·표준번호·코드·표는 원문 그대로다.\
> ASCII 도식 6개(그중 1개는 원문 mermaid 그림을 글자로 옮긴 것)와 「한눈에」의 집 공사 비유(대응표 포함), 용어 블록의 「예:」, 「용어 풀이」는 원문에 없는 보충이다.

## 한눈에 — 쉽게 말하면

원문이 제목 아래에 적은 한 줄 요약은 이것이다.

> `let`/`const`·화살표 함수·`class`·모듈·`Promise`·구조 분해·템플릿 리터럴을 한꺼번에 들고 온 ECMAScript 2015(ES6)는 자바스크립트를 "브라우저 스크립트"에서 "대규모 애플리케이션 언어"로 끌어올린 분기점이다. 이후 언어는 거대 릴리스 한 방이 아니라 **매년 작게 합의되는 흐름**으로 바뀌었고, 그 합의를 굴리는 엔진이 TC39 프로세스다.

이 편을 하나의 비유로 읽으면 **집 공사**의 이야기다.\
문서 전체를 꿰는 비유는 이 하나뿐이다(도식 해설의 "계단처럼 깊어진다" 같은 표현은 그 자리에서만 쓰는 재서술자의 말이다).\
용어 블록의 「예:」는 **대부분** 이 편의 코드와 원문 문장에서 가져왔고, 원문에 없는 예에는 그 자리에 「(원문에 없는 예)」를 달았다.

| 비유 | 실체 |
|------|------|
| 6년 동안 손대지 못한 집 | 2009년 ES5 이후 사실상 멈춰 있던 언어 본체 |
| 한 번에 몰아서 한 대공사 | ES2015 — ES5.1의 약 245쪽에 비해 약 600쪽 |
| 그 뒤로 매년 정해진 달에 하는 정기 보수 | 매년 6~7월 Ecma 총회에 제출·비준하는 연간 릴리스 |
| "준비 끝" 도장을 받은 공정만 그해 공사에 넣는다 | Stage 4에 도달한 제안만 그해 에디션에 실린다 |
| 새 자재를 옛 규격에 맞게 바꿔 끼워 주는 변환기 | ES6를 ES5로 변환해주는 Babel |

- **대공사는 한 번으로 끝났다.**\
  원문은 ES2015를 "단일 에디션으로는 역대 최대 증분"이라고 적는다.
- **그 뒤로는 공사 방식 자체가 바뀌었다.**\
  "다음 큰 버전"이라는 개념을 폐기하고, 그해에 준비된 것만 싣는 방식으로 갔다.
- **집을 부수지 않는 것이 제1원칙이었다.**\
  원문의 표현대로 위원회의 제1원칙은 "Don't break the web"(웹을 깨지 말 것)이었다.

```text
릴리스 모델이 바뀌었다 — 원문 「영향과 의의」의 문장을 두 칸에 놓은 것

before                               after
+---------------------------------+  +---------------------------------+
| 6년에 한 번 거대 릴리스         |  | 매년 준비된 만큼                |
| 다음 버전을 기다림              |  | Stage 3부터 Babel로 먼저 씀     |
+---------------------------------+  +---------------------------------+
```

- 두 칸에 적힌 네 문구는 원문 「영향과 의의」가 **"…에서 …으로"로 대비해** 적은 네 표현 그대로다.
- 두 칸의 대립축도 원문의 대립축 그대로다 — **언제 릴리스하느냐, 그리고 언제부터 쓰느냐**.
- 열 머리에 연도를 쓰지 않은 이유가 있다.\
  원문은 이 전환에 **연도 경계를 적지 않고**, 바뀌기 전과 바뀐 뒤를 "…에서 …으로"로만 적는다.\
  게다가 Babel은 원문이 2014년 등장(당시 6to5)이라 적으므로, 오른쪽 칸을 특정 연도부터라고 못 박으면 원문과 어긋난다.

## 릴리스 정보
- 정식 승인: 2015년 6월, Ecma 총회(General Assembly) — 표준 번호 **ECMA-262 6th Edition**
- 공식 명칭 변경: 개발 기간 내내 "ES6"로 불렸으나, 표준화 시점에 연도 기반 명칭 **ECMAScript 2015(ES2015)**로 확정. 이후 모든 에디션은 연도로 부른다(ES2016, ES2017 …).
- 표준화 주체: Ecma International **TC39**(Technical Committee 39)
- 분량: ES5.1이 약 245쪽이었던 데 비해 ES2015는 약 600쪽 — 단일 에디션으로는 역대 최대 증분.
- 호환성: 기존 코드와 **완전한 하위 호환**. 위원회의 제1원칙은 "Don't break the web"(웹을 깨지 말 것)이었다.

> **하위 호환(backward compatibility)** — 새 판을 내놓아도 예전에 쓰던 코드가 그대로 돌아가는 성질.\
> 예: ES2015가 `let`을 새로 들여왔어도 ES5로 짠 `var` 코드는 그대로 돈다(원문에 없는 예).

> **TC39** — Ecma International 안에서 이 언어의 표준을 만드는 기술 위원회(Technical Committee 39).\
> 예: 매년 6~7월 Ecma 총회에 그해 에디션을 제출하는 주체가 여기다.

## 시대적 배경

자바스크립트의 직전 표준은 2009년의 **ES5**였다.\
그 사이 6년 동안 언어 본체는 사실상 멈춰 있었지만, 현실의 자바스크립트는 폭발하고 있었다.\
2008년 V8 엔진과 Chrome, 2009년 Node.js의 등장으로 자바스크립트는 브라우저를 벗어나 서버까지 진출했고, jQuery·Backbone·AngularJS 같은 라이브러리/프레임워크가 수만 줄짜리 SPA(Single Page Application)를 자바스크립트로 짜기 시작했다.

> **SPA(Single Page Application)** — 한 페이지 안에서 화면을 바꿔 가며 도는 앱.\
> 예: 원문이 든 대로 jQuery·Backbone·AngularJS로 짜던 수만 줄짜리 앱이 여기에 해당한다.

문제는 언어가 그 규모를 감당할 문법을 주지 않았다는 점이다.\
변수는 함수 스코프인 `var`뿐이라 블록 스코프가 없었고, 클래스·모듈이 없어 프로토타입 조작과 IIFE(즉시 실행 함수)·`this` 바인딩 트릭으로 캡슐화를 흉내 냈으며, 비동기는 콜백을 중첩한 "콜백 지옥(callback hell)"으로 처리했다.\
CommonJS(Node)·AMD(RequireJS) 같은 모듈 규약이 난립한 것도 언어에 표준 모듈이 없었기 때문이다.

> **스코프(scope)** — 어떤 이름이 통하는 범위.\
> 예: `var`는 함수 하나가 통째로 그 범위이고, `let`은 중괄호로 묶인 블록이 그 범위다(아래 절).

원래 차기 버전이 될 뻔했던 **ES4**는 클래스·타입·네임스페이스를 한꺼번에 넣으려다 진영 간 이견으로 2008년 폐기됐다.\
그 실패 후 위원회는 "**Harmony**"라는 이름 아래 야심을 쪼개 합의 가능한 것부터 쌓는 노선으로 선회했고, 그 결실이 ES2015다.\
즉 ES6는 "한 번에 다 넣자"는 ES4의 실패를 교훈 삼아 **6년치 숙원을 모은** 거대 릴리스인 동시에, 다시는 이런 6년 공백을 만들지 않겠다는 **연간 릴리스 체제의 출발점**이기도 했다.

## 주요 추가 기능 (ES2015)

### let / const — 블록 스코프와 상수
- `var`의 함수 스코프·호이스팅·재선언 허용이 만들던 버그를 제거. `let`/`const`는 **블록 스코프**이며, 선언 전 접근은 TDZ(Temporal Dead Zone)로 막힌다.
- `const`는 재할당을 금지(바인딩 불변 — 객체 내부 값까지 얼리는 것은 아님).

> **블록 스코프(block scope)** — 중괄호 `{ }`로 묶인 그 블록 안에서만 이름이 통하는 것.\
> 예: `for (let i = ...)`의 `i`는 그 반복 블록 안에서만 통한다.

> **호이스팅(hoisting)** — 선언이 그 범위의 **맨 위에서 먼저 처리되는 것**. `var`·`let`·`const` 모두 그렇게 처리된다.\
> 예: 그래도 선언 줄보다 위에서 써 보면 결과가 갈린다 — `var`는 `undefined`로 통과하고, `let`/`const`는 같은 자리에서 TDZ로 막힌다(원문에 없는 예).

> **TDZ(Temporal Dead Zone)** — `let`/`const`로 선언한 이름을 그 선언 줄에 닿기 전에 쓰려고 하면 막히는 구간.\
> 예: 원문의 표현대로 "선언 전 접근은 TDZ(Temporal Dead Zone)로 막힌다".

> **바인딩(binding)** — 이름 하나가 값이 담긴 자리 하나에 묶여 있는 상태.\
> 예: `const`가 금지하는 것은 그 묶음을 다른 값으로 바꾸는 일이고, 객체 내부 값까지 얼리는 것은 아니다(원문).

```javascript
// Before (ES5): var는 함수 스코프 — 루프 클로저의 고전적 함정
var funcs = [];
for (var i = 0; i < 3; i++) {
  funcs.push(function () { return i; });
}
console.log(funcs[0]()); // 3 (기대: 0) — i가 공유됨
```

```javascript
// After (ES6): let은 반복마다 새 바인딩
const funcs = [];
for (let i = 0; i < 3; i++) {
  funcs.push(() => i);
}
console.log(funcs[0]()); // 0
```

```text
루프 클로저 — 위 두 코드의 차이

var (함수 스코프)                    let (블록 스코프)
+--------------------------------+   +--------------------------------+
| i 는 루프 밖까지 하나뿐        |   | 반복마다 새 바인딩이 생긴다    |
| 함수 세 개가 같은 i 를 본다    |   | 함수 세 개가 각자의 i 를 본다  |
+--------------------------------+   +--------------------------------+
  funcs[0]() -> 3 (기대: 0)            funcs[0]() -> 0
  "i 가 공유됨"
```

- 두 칸의 값과 따옴표는 위 코드의 주석에서 그대로 가져온 것이다 — 왼쪽은 `3 (기대: 0) — i가 공유됨`, 오른쪽은 `0`이다.
- 오른쪽 칸의 "반복마다 새 바인딩"도 원문이 그 코드에 붙인 표현 그대로다.

> **클로저(closure)** — 함수가 만들어진 자리의 바깥 변수를 나중에 불려도 계속 들여다보는 것.\
> 예: 위 `var` 코드의 함수 세 개가 전부 같은 `i` 하나를 들여다본다 — 그래서 `funcs[0]()`이 0이 아니라 3을 낸다.

### 화살표 함수 (Arrow Function)
- `=>` 문법으로 익명 함수를 축약. 핵심은 문법뿐 아니라 **`this` 동작**이다: 화살표 함수는 자신의 `this`를 만들지 않고 **둘러싼 렉시컬 스코프의 `this`를 그대로 캡처**한다.
- `var self = this` / `.bind(this)` 관용구를 없앴다.

> **렉시컬 스코프(lexical scope)** — 코드가 실제로 **쓰여 있는 자리**를 기준으로 정해지는 바깥 범위.\
> 예: 화살표 함수는 자기 `this`를 만들지 않고, 그 함수가 쓰인 자리를 둘러싼 `this`를 그대로 쓴다.

```javascript
// Before (ES5): this를 살리려 self에 보관
function Timer() {
  var self = this;
  self.seconds = 0;
  setInterval(function () {
    self.seconds++; // 여기의 this는 Timer가 아니므로 self 필요
  }, 1000);
}
```

```javascript
// After (ES6): 화살표가 바깥 this를 캡처
function Timer() {
  this.seconds = 0;
  setInterval(() => {
    this.seconds++; // 바깥 Timer 인스턴스를 그대로 가리킴
  }, 1000);
}
```

```text
this 가 무엇을 가리키나 — 위 두 코드에서 주석만 뽑아 붙인 것

ES5
function Timer() {
  var self = this;            <- this를 살리려 self에 보관
  self.seconds = 0;

    self.seconds++;           <- 여기의 this는 Timer가 아니므로 self 필요
  }, 1000);

ES6

  setInterval(() => {
    this.seconds++;           <- 바깥 Timer 인스턴스를 그대로 가리킴
  }, 1000);

```

- 화살표 옆 설명은 원문 코드의 주석에서 옮긴 것이다.\
  뒤의 둘은 **그 줄에 달린 주석 그대로**이고, 첫 줄만 코드 블록 머리 주석(`// Before (ES5): this를 살리려 self에 보관`)에서 가져왔다.
- 두 그림의 대립축은 원문의 대립축 그대로다 — **`this`를 따로 보관해 옮기느냐, 바깥 `this`를 그대로 쓰느냐**.

### class — 프로토타입의 문법적 외피
- `class`/`constructor`/`extends`/`super`/`static`. 새 객체 모델이 아니라 기존 **프로토타입 상속을 감싼 문법 설탕(syntactic sugar)** 이지만, 상속·생성자·메서드 정의를 표준화된 한 가지 형태로 통일했다.

> **문법 설탕(syntactic sugar)** — 돌아가는 방식은 그대로 두고 적는 모양만 편하게 바꾼 문법.\
> 예: 원문이 적은 대로 `class`는 새 객체 모델이 아니라 기존 프로토타입 상속을 감싼 문법 설탕이다.

> **프로토타입 상속** — 클래스 틀이 아니라 다른 객체를 원형으로 삼아 그 성질을 물려받는 방식.\
> 예: 아래 ES5 코드의 `Dog.prototype = Object.create(Animal.prototype);`이 그 배선을 손으로 한 것이다.

```javascript
// Before (ES5): 프로토타입 수동 배선
function Animal(name) { this.name = name; }
Animal.prototype.speak = function () {
  return this.name + ' makes a sound';
};
function Dog(name) { Animal.call(this, name); }
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;
Dog.prototype.speak = function () { return this.name + ' barks'; };
```

```javascript
// After (ES6): class 문법
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
}
class Dog extends Animal {
  speak() { return `${this.name} barks`; }
}
```

### 모듈 (import / export)
- 언어 차원의 **표준 모듈 시스템(ES Modules, ESM)** 도입. `export`로 공개하고 `import`로 가져온다. 파일 단위 스코프, 정적(static) 구조라 빌드 도구가 트리 셰이킹(미사용 코드 제거)을 할 수 있다.
- CommonJS(`require`/`module.exports`)·AMD로 갈라져 있던 모듈 생태계를 표준 한 곳으로 수렴시켰다.

> **모듈(module)** — 코드를 파일 단위로 끊어 놓고, 밖에 내줄 것만 골라 내주는 단위.\
> 예: `export const PI = 3.14159;`로 내주고, 다른 파일이 `import { PI } from './math.js';`로 가져온다(아래 코드).

> **트리 셰이킹(tree shaking)** — 미사용 코드 제거(원문의 표현 그대로).\
> 예: 어느 파일도 `import`하지 않은 함수는 최종 결과물에서 빼 버릴 수 있다(원문에 없는 예).

```javascript
// Before (ES5, CommonJS 관용): 런타임 require
var math = require('./math');
module.exports.area = function (r) { return math.PI * r * r; };
```

```javascript
// After (ES6, ESM): 정적 import/export
// math.js
export const PI = 3.14159;
export function square(x) { return x * x; }

// app.js
import { PI, square } from './math.js';
export const area = (r) => PI * square(r);
```

```text
                                                    |
                                                    v
                                      빌드 도구가 트리 셰이킹을 할 수 있다
```

- 오른쪽 아래 화살표는 원문이 밝힌 인과다 — "정적(static) 구조라 빌드 도구가 트리 셰이킹(미사용 코드 제거)을 할 수 있다".
- 왼쪽에는 대응하는 화살표를 그리지 않았다. 원문은 이 절에서 CommonJS 쪽의 한계를 적지 않는다.

**언제 쓸 수 있게 됐나** — 원문이 괄호로 덧붙인 문장은 이것이다.

> (브라우저·Node의 실제 런타임 보급은 수년이 더 걸렸다.)

### Promise — 콜백 지옥의 탈출구
- 비동기 작업의 최종 결과(또는 실패)를 표현하는 **1급 객체**. `then`/`catch`로 체이닝하고, `Promise.all`/`race`로 조합한다. 깊은 콜백 중첩을 평평한 체인으로 편다.
- 훗날 ES2017 `async`/`await`의 토대가 된다.

> **콜백(callback)** — 나중에 일이 끝나면 불러 달라고 미리 넘겨 두는 함수.\
> 예: 아래 ES5 코드의 `function (err, user) { ... }`가 `getUser`가 끝난 뒤 불리는 콜백이다.

> **콜백 지옥(callback hell)** — 콜백 안에 콜백을 **중첩한**(원문의 표현) 상태. 그럴수록 코드가 계단처럼 오른쪽으로 깊어진다(계단은 재서술자의 표현이다).\
> 예: 아래 ES5 코드처럼 `getUser` 안에 `getOrders`, 그 안에 `getDetails`가 들어앉은 모양.

> **`Promise`** — 비동기 작업의 최종 결과(또는 실패)를 표현하는 1급 객체(원문의 정의 그대로).\
> 예: `.then`으로 다음 단계를 잇고 `.catch(handle)` 한 곳에서 실패를 받는다(아래 코드).

```javascript
// Before (ES5): 콜백 중첩 — "콜백 지옥"
getUser(id, function (err, user) {
  if (err) return handle(err);
  getOrders(user, function (err, orders) {
    if (err) return handle(err);
    getDetails(orders, function (err, details) {
      if (err) return handle(err);
      render(details);
    });
  });
});
```

```javascript
// After (ES6): Promise 체인
getUser(id)
  .then(user => getOrders(user))
  .then(orders => getDetails(orders))
  .then(details => render(details))
  .catch(handle);
```

```text
모양이 어떻게 달라지나 — 원문의 "깊은 콜백 중첩을 평평한 체인으로 편다"

콜백 중첩                          Promise 체인
getUser                            getUser(id)
    getOrders                        then  getOrders
        getDetails                   then  getDetails
            render                   then  render
        (닫기)                       catch handle
    (닫기)
(닫기)
들여쓰기가 오른쪽으로 깊어진다     들여쓰기가 한 칸에서 멈춘다
```

- 이 그림은 코드가 아니라 위 두 코드의 **모양**만 옮긴 것이다. 실제 호출 형태는 위 코드 블록을 보면 된다.
- 왼쪽에서 오른쪽으로 갈수록 깊어지는 계단이 원문이 말한 "깊은 콜백 중첩"이다.

### 구조 분해 할당 (Destructuring)
- 배열·객체에서 값을 꺼내 변수에 한 번에 바인딩. 기본값·이름 변경·중첩 분해를 지원한다.

> **구조 분해(destructuring)** — 객체나 배열의 모양을 그대로 적어 두고, 그 자리의 값을 한 번에 꺼내 변수에 담는 것.\
> 예: `const { x, y } = point;`는 `point.x`·`point.y`를 각각 꺼내 담는다(아래 코드).

```javascript
// Before (ES5)
var x = point.x;
var y = point.y;
var first = arr[0], second = arr[1];
```

```javascript
// After (ES6)
const { x, y } = point;
const [first, second] = arr;
const { name = 'anonymous' } = user;     // 기본값
function move({ dx = 0, dy = 0 } = {}) { /* ... */ } // 인자 구조 분해
```

### 템플릿 리터럴 (Template Literal)
- 백틱(`` ` ``) 문자열. `${expr}` 보간과 여러 줄 문자열을 네이티브로 지원해 `+` 연결과 `\n` 이스케이프를 없앴다. 태그드 템플릿(tagged template)으로 함수가 보간을 가로채는 메타 기능도 제공.

> **보간(interpolation)** — 문자열 중간에 값이 들어갈 자리를 뚫어 두고 그 자리에 값을 끼워 넣는 것.\
> 예: `` `Hello, ${name}!` `` 은 `${name}` 자리에 변수 `name`의 값이 들어간다(아래 코드).

```javascript
// Before (ES5)
var msg = 'Hello, ' + name + '!\n' +
          'You have ' + count + ' messages.';
```

```javascript
// After (ES6)
const msg = `Hello, ${name}!
You have ${count} messages.`;
```

### 기본값 · Rest · Spread 파라미터
- **기본 파라미터**: `function f(a, b = 10)` — `arguments` 검사 관용구 제거.
- **Rest 파라미터** `...args`: 가변 인자를 진짜 배열로 수집(`arguments` 유사 배열 대체).
- **Spread** `...`: 배열/이터러블을 펼쳐 함수 호출·배열 리터럴·(ES2018부터 객체)에 전개.

> **Rest 파라미터 / Spread** — 넘어온 인자를 하나로 모으는 쪽 / 하나를 여러 자리로 펼치는 쪽.\
> 예: `const sum = (...nums) => ...`가 모으는 쪽이고, `[...arr1, ...arr2]`가 펼치는 쪽이다(아래 코드).

```javascript
// Before (ES5)
function sum() {
  var args = Array.prototype.slice.call(arguments);
  return args.reduce(function (a, b) { return a + b; }, 0);
}
var merged = arr1.concat(arr2);
```

```javascript
// After (ES6)
const sum = (...nums) => nums.reduce((a, b) => a + b, 0);
const merged = [...arr1, ...arr2];
Math.max(...[3, 1, 4, 1, 5]);   // 배열을 인자로 전개
```

### 그 외 ES2015 추가
- **이터레이터 / `for...of` / 제너레이터(`function*`·`yield`)**: 순회 프로토콜 표준화와 지연 시퀀스.
- **`Map` · `Set` · `WeakMap` · `WeakSet`**: 객체 키 해시맵·집합 등 진짜 컬렉션.
- **`Symbol`**: 충돌 없는 유일 식별자, `Symbol.iterator` 등 메타 프로토콜 훅.
- **`Proxy` · `Reflect`**: 객체 동작을 가로채는 메타프로그래밍.
- **객체 리터럴 단축**: 단축 속성(`{ x, y }`), 메서드 단축, 계산된 속성 키(`{ [key]: v }`).
- **타입드 배열 / `Number`·`Math` 확장**: `Number.isNaN`, `Number.isInteger`, `Math.trunc` 등.

## 왜 이 릴리스가 컸나

ES2015가 "대변혁"으로 불리는 이유는 추가 기능 수가 아니라 **언어가 표현할 수 있는 프로그램의 규모가 바뀌었다**는 데 있다.

1. **모듈·클래스로 대규모 구조화가 가능해졌다.**\
   그전까지 캡슐화·의존성 관리는 라이브러리와 관용구(IIFE·CommonJS)의 몫이었다.\
   언어가 이를 흡수하면서 자바스크립트는 처음으로 "대형 애플리케이션을 위한 1급 문법"을 갖췄다.
2. **`Promise`가 비동기의 공통 통화(currency)가 되었다.**\
   콜백 규약이 라이브러리마다 제각각이던 시대를 끝냈고, `async`/`await`라는 후속 도약의 토대를 깔았다.
3. **블록 스코프·화살표 함수가 `var`/`this`의 고질적 버그를 구조적으로 제거**해 코드의 예측 가능성을 끌어올렸다.
4. **트랜스파일러 문화가 정착했다.**\
   브라우저 보급이 느렸기에 **Babel**(2014년 등장, 당시 6to5)이 ES6를 ES5로 변환해주면서, 개발자는 런타임 지원을 기다리지 않고 최신 문법을 쓸 수 있었다.\
   이 "먼저 쓰고 나중에 네이티브화" 패턴이 이후 연간 릴리스 모델과 맞물려 자바스크립트 진화의 표준 작동 방식이 된다.

> **트랜스파일러(transpiler)** — 한 언어의 새 문법으로 쓴 코드를 같은 언어의 옛 문법으로 바꿔 주는 도구.\
> 예: Babel이 ES6 코드를 ES5로 변환해, 아직 ES6를 모르는 런타임에서도 돌게 했다.

## 연간 릴리스로의 전환 (ES2016~)

ES4의 6년 표류와 ES2015의 600쪽짜리 거대 통합은 같은 교훈을 남겼다 — **큰 묶음은 늦고 위험하다.**\
TC39는 그래서 모델을 통째로 바꿨다.

- **명칭을 연도로**: ES6 이후 에디션은 출시 연도로 부른다(ES2016 = ES7 …). "다음 큰 버전"이라는 개념을 폐기한 것이다.
- **매년 6~7월 비준**: 그해까지 **Stage 4에 도달한 제안만** 모아 매년 Ecma 총회에 제출·비준한다. 준비된 것만 싣고, 아닌 것은 다음 해로 — 릴리스가 특정 기능을 기다리지 않는다.
- **작은 증분**: 그래서 **ES2016은 단 2개 기능**(`Array.prototype.includes`, 지수 연산자 `**`)만 담은 초소형 릴리스였다. "준비된 만큼만, 매년"이라는 새 철학의 상징적 첫 사례다.

```javascript
// ES2016: 딱 두 가지
[1, 2, 3].includes(2);   // true (NaN도 올바르게 탐지)
console.log(2 ** 10);    // 1024 (Math.pow 대체 연산자)
```

이 전환으로 자바스크립트의 진화 단위는 "에디션"에서 "개별 제안(proposal)"으로 옮겨갔다.\
어떤 기능이 언제 들어오느냐는 더 이상 다음 메이저 버전이 아니라 **그 제안이 Stage 4에 닿는 시점**의 문제가 되었다.

> **제안(proposal)** — 언어에 무엇을 넣자고 하나씩 올리는 건의. 진화의 단위가 에디션에서 이것으로 옮겨갔다.\
> 예: 어떤 기능을 쓸 수 있느냐는 그 제안이 지금 몇 단계인지로 따진다(아래 「TC39 프로세스」).

## 이후 주요 도약

### async / await (ES2017)
- `Promise` 위에 얹은 문법으로, 비동기 코드를 **동기 코드처럼** 보이게 쓴다. `async` 함수는 `Promise`를 반환하고, `await`는 그 이행을 기다린다. `try/catch`로 비동기 에러까지 잡는다. ES2015 `Promise`가 깔아둔 길의 종착점.

> **`async` / `await`** — 함수 앞의 `async`는 그 함수가 `Promise`를 반환하게 하고, `await`는 그 `Promise`의 이행을 기다린다(원문의 서술을 풀어 쓴 것).\
> 예: `const user = await getUser(id);`처럼 적으면 결과가 그 자리 변수에 담겨, 코드가 동기 코드처럼 보인다(아래 코드).

```javascript
// Before (ES2015): Promise 체인 + 분기 처리가 길어진다
function loadDashboard(id) {
  return getUser(id)
    .then(user => Promise.all([getOrders(user), getStats(user)]))
    .then(([orders, stats]) => render(orders, stats))
    .catch(handleError);
}
```

```javascript
// After (ES2017): 동기처럼 읽히는 비동기
async function loadDashboard(id) {
  try {
    const user = await getUser(id);
    const [orders, stats] = await Promise.all([getOrders(user), getStats(user)]);
    render(orders, stats);
  } catch (err) {
    handleError(err);
  }
}
```

### 옵셔널 체이닝 · Nullish 병합 (ES2020)
- **옵셔널 체이닝 `?.`**: 중간 값이 `null`/`undefined`면 에러 대신 `undefined`로 단락(short-circuit). 깊은 `&&` 가드 체인을 없앴다.
- **Nullish 병합 `??`**: 좌변이 `null`/`undefined`일 때만 우변을 쓴다. `0`·`''`·`false`를 "없음"으로 오인하던 `||`의 함정을 고친다.

> **단락(short-circuit)** — 뒤를 더 따라가지 않고 그 자리에서 값을 내고 끝내는 것.\
> 예: `user?.address?.city`는 `user`가 `null`이면 거기서 멈추고 에러 대신 `undefined`를 낸다.

> **Nullish** — `null`과 `undefined` 둘만 가리키는 말.\
> 예: `config.pageSize ?? 20`은 `pageSize`가 `0`이어도 `0`을 유지한다 — `0`은 nullish가 아니기 때문이다(아래 코드의 주석).

```javascript
// Before (ES5/ES2015): 단계마다 방어
var city = (user && user.address && user.address.city) || 'Unknown';
var limit = (config.pageSize !== undefined && config.pageSize !== null)
              ? config.pageSize : 20;
```

```javascript
// After (ES2020)
const city = user?.address?.city ?? 'Unknown';
const limit = config.pageSize ?? 20;   // pageSize가 0이어도 0을 유지
```

> ES2020은 이 둘 외에 `BigInt`(임의 정밀도 정수), `Promise.allSettled`, 동적 `import()`, `globalThis`도 함께 표준화했다.

### Top-level await (ES2022)
- 모듈 최상위에서 `async` 래퍼 없이 `await`를 직접 쓴다. 모듈이 비동기 초기화(설정 로드·동적 의존성 선택·DB 연결)를 마칠 때까지 그 모듈의 평가를 보류한다 — 모듈 자체가 하나의 비동기 단위가 된다.

> **경쟁 조건(race condition)** — 어느 쪽이 먼저 끝나느냐에 따라 결과가 달라지는 상태.\
> 예: 아래 ES2017 코드의 주석대로, `config` 사용 시점과 로드 완료 사이에 그 위험이 있다.

```javascript
// Before (ES2017): 모듈 최상위는 await 불가 → IIFE로 감쌈
let config;
(async () => {
  config = await fetch('/config.json').then(r => r.json());
})(); // config 사용 시점과 로드 완료 사이에 경쟁 조건 위험
```

```javascript
// After (ES2022): 모듈 top-level에서 직접 await
const config = await fetch('/config.json').then(r => r.json());
export default config; // 이 모듈을 import하는 쪽은 config 준비 완료를 보장받는다
```

> 그 밖에 ES2018 객체 spread/rest·비동기 이터레이션, ES2019 `Array.flat`·`Object.fromEntries`, ES2021 `String.replaceAll`·논리 할당 연산자(`??=` 등), ES2022 클래스 필드·`#private`·`Array.at`, ES2023 `Array.findLast`·`toSorted`(불변 배열 메서드) 등이 매년 차곡차곡 더해졌다.

## TC39 프로세스 (제안이 표준이 되는 길)

연간 릴리스를 굴리는 실제 엔진은 **TC39의 5단계 스테이지 프로세스**다.\
모든 기능은 아래 단계를 순서대로 통과해야 표준에 들어간다.\
각 단계는 "이 아이디어가 다음 단계로 갈 자격이 있는가"를 위원회 합의로 판정하는 관문이다.

원문의 그림을 글자 도식으로 옮기면 이렇다(노드 문구는 그대로다).

```text
Stage 0         Stage 1          Stage 2       Stage 3        Stage 4
Strawperson --> Proposal     --> Draft     --> Candidate  --> Finished
아이디어        문제·해법 형태   스펙 초안     구현·피드백    표준 편입
                                                                 :
                                                                 : 매년 6~7월 비준
                                                                 v
                                                            ES20XX 에디션
```

- 다섯 칸의 이름과 그 아래 문구는 원문 그림의 노드 문구 그대로다.
- 원문 그림은 가로 방향(`flowchart LR`)이고, 실선 화살표 넷의 방향도 그대로 왼쪽에서 오른쪽이다.
- 마지막 점선 화살표만 폭 때문에 아래로 꺾어 그렸다. 라벨 "매년 6~7월 비준"은 원문 그대로다.

| 단계 | 이름 | 의미 | 통과 기준(요지) |
|------|------|------|------|
| **0** | Strawperson | 아무 아이디어/논의. 형식 제안 이전 | 없음(누구나) |
| **1** | Proposal | 풀려는 문제와 해법의 대략적 형태, 챔피언 지정 | 위원회가 "다뤄볼 가치 있음"에 합의 |
| **2** | Draft | 형식 스펙 언어로 쓴 초안. 사실상 "넣기로 함" | 문법·의미의 초안 완성 |
| **2.7** | (Test) | 스펙 확정 + 테스트 작성 (2024년 신설된 세분 단계) | 스펙 완성, 테스트 준비 |
| **3** | Candidate | 구현체·사용자 피드백을 받는 후보 | 스펙 완료, 검토 통과, 구현 시작 |
| **4** | Finished | 표준 편입 확정 | 테스트 통과 + **2개 이상 호환 구현** + PR 머지 |

표를 읽는 법 — 위에서 아래로 갈수록 뒷단계이고, 맨 오른쪽 열은 원문의 열 제목 그대로 **통과 기준(요지)** 이다.\
그림에 없는 **2.7** 행이 표에만 있는데, 원문이 "2024년 신설된 세분 단계"라고 적은 그 단계다.

핵심 규칙은 **"Stage 4에 도달한 제안만 그해 에디션에 실린다"** 는 것이다.\
그래서 에디션의 크기는 매년 다르고(2개짜리 ES2016부터 풍성한 ES2020까지), 어떤 기능을 "쓸 수 있느냐"는 메이저 버전이 아니라 그 제안의 스테이지로 추적한다.\
**Stage 3**는 특히 중요한 신호다 — 브라우저·Node·Babel이 이 시점부터 선제 구현하므로, 실무에서는 표준 비준 전에 이미 그 기능을 쓰는 경우가 많다.

이 프로세스가 만든 문화가 자바스크립트 진화의 성격을 규정한다: **점진적·합의 기반·구현 선행.**\
ES4식 "혁명적 빅뱅"은 폐기됐고, 대신 작은 제안이 공개적으로 단계를 밟아 올라가는 투명한 파이프라인이 그 자리를 채웠다.

## 영향과 의의

*(이 편의 「남긴 것」에 해당한다. 아래 불릿은 원문 이 절의 문장들이다.)*

- ES2015는 자바스크립트 역사의 "before/after"를 가르는 선이다.
- 모듈·클래스·`Promise`·블록 스코프가 동시에 들어오면서, 자바스크립트는 장난감 스크립트 언어라는 오랜 평판을 벗고 브라우저·서버·데스크톱(Electron)·모바일(React Native)을 아우르는 범용 애플리케이션 언어로 올라섰다.
- React·Vue·Angular 2+ 같은 현대 프레임워크는 모두 ES6 문법(클래스·모듈·화살표·구조 분해)을 전제로 설계됐다.
- 더 오래 가는 유산은 **개발 모델 자체의 전환**이다.\
  "6년에 한 번 거대 릴리스"에서 "매년 준비된 만큼"으로, "다음 버전을 기다림"에서 "Stage 3부터 Babel로 먼저 씀"으로 바뀌면서, 자바스크립트는 어떤 주류 언어보다 빠르고 예측 가능하게 진화하는 언어가 되었다.
- ES2015가 가져온 진짜 변화는 문법 목록이 아니라, **언어가 변하는 방식**이었다.

## 용어 풀이

- **ECMAScript 2015(ES2015 / ES6)** — 2015년 6월 Ecma 총회가 승인한 ECMA-262 6th Edition. 약 600쪽.
- **TC39** — Ecma International 안에서 이 언어의 표준을 만드는 기술 위원회(Technical Committee 39).
- **하위 호환(backward compatibility)** — 새 판을 내도 예전 코드가 그대로 도는 성질. 제1원칙은 "Don't break the web".
- **SPA(Single Page Application)** — 한 페이지 안에서 화면을 바꿔 가며 도는 앱.
- **스코프(scope) / 블록 스코프** — 이름이 통하는 범위 / 중괄호로 묶인 블록이 그 범위인 것.
- **호이스팅(hoisting)** — 선언이 그 범위 맨 위에서 먼저 처리되는 것. 선언 줄보다 위에서 쓰면 `var`는 `undefined`로 통과하고, `let`/`const`는 TDZ로 막힌다.
- **TDZ(Temporal Dead Zone)** — `let`/`const`를 선언 줄에 닿기 전에 쓰려 하면 막히는 구간.
- **바인딩(binding)** — 이름 하나가 값이 담긴 자리 하나에 묶여 있는 상태. `const`는 그 묶음의 변경을 금지한다.
- **클로저(closure)** — 함수가 만들어진 자리의 바깥 변수를 나중에도 계속 들여다보는 것.
- **렉시컬 스코프(lexical scope)** — 코드가 쓰여 있는 자리를 기준으로 정해지는 바깥 범위.
- **문법 설탕(syntactic sugar)** — 동작은 그대로 두고 적는 모양만 편하게 바꾼 문법. `class`가 그렇다.
- **프로토타입 상속** — 다른 객체를 원형으로 삼아 성질을 물려받는 방식.
- **모듈(module) / ESM** — 파일 단위로 코드를 끊고 `export`·`import`로 잇는 단위 / 그 표준 모듈 시스템.
- **CommonJS / AMD** — `require`·`module.exports` 규약(Node) / RequireJS의 모듈 규약. ESM 이전에 난립하던 것들이다.
- **트리 셰이킹(tree shaking)** — 미사용 코드 제거. ESM이 정적 구조라 가능해졌다.
- **콜백(callback) / 콜백 지옥(callback hell)** — 끝나면 불러 달라고 넘겨 두는 함수 / 그것이 중첩돼 계단처럼 깊어진 상태.
- **`Promise`** — 비동기 작업의 최종 결과(또는 실패)를 표현하는 1급 객체.
- **`async` / `await`** — `Promise`를 반환하게 하는 함수 표시 / 그 이행을 기다리는 연산자. ES2017.
- **구조 분해(destructuring)** — 객체·배열의 모양을 적어 두고 그 자리의 값을 한 번에 꺼내 담는 것.
- **템플릿 리터럴 / 보간** — 백틱 문자열 / `${expr}` 자리에 값을 끼워 넣는 것.
- **Rest 파라미터 / Spread** — 인자를 배열로 모으는 쪽 / 하나를 여러 자리로 펼치는 쪽.
- **단락(short-circuit)** — 뒤를 더 따라가지 않고 그 자리에서 값을 내고 끝내는 것. `?.`의 동작이다.
- **Nullish** — `null`과 `undefined` 둘만 가리키는 말. `??`가 보는 대상이다.
- **경쟁 조건(race condition)** — 어느 쪽이 먼저 끝나느냐에 따라 결과가 달라지는 상태.
- **트랜스파일러(transpiler)** — 새 문법 코드를 같은 언어의 옛 문법으로 바꿔 주는 도구. Babel이 대표.
- **제안(proposal) / 스테이지** — 언어에 무엇을 넣자는 건의 / 그것이 표준이 되기까지 밟는 단계.
- **Stage 3 / Stage 4** — 구현·피드백을 받는 후보 / 표준 편입 확정. 그해 에디션에 실리는 것은 Stage 4뿐이다.
