# Rust 변천사 — 쉽게 다시 쓴 판

> 원본: `~/project/rust-history/README.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-19).\
> 원문 README의 소개 문단·「읽는 법」·「큰 줄기」는 원문 그대로이고, 「구성」 표의 **주제 열 문구**는 열을 따로 두지 않고 각 행 「한 줄 요약」 끝에 ` — `로 그대로 붙였다.\
> 「한눈에」 ASCII 도식 1개와 목차의 「시기」·한 줄 요약, 「급하면 이렇게 골라 읽어도 된다」 길찾기는 원문 README에 없는 보충이다.\
> 그중 「시기」와 한 줄 요약은 **각 편에서 발췌한 보충**이다 — 04·05·06은 이 폴더의 같은 편에서, 01·02·03은 원본 `~/project/rust-history/`의 해당 편에서 발췌했다.\
> 「시기」의 출처는 편마다 다르다 — 01·02·03은 그 편 제목 괄호의 범위를, 04는 그 편 「한눈에 보는 타임라인」 표의 첫 행과 마지막 행을, 05는 그 편 본문이 짚는 처음과 끝을 옮겼다. 원문이 시기를 밝히는 형식이 편마다 달라 하나의 기준으로 통일하지 않았다.\
> **06은 시기 칸을 비웠다(`—`)** — 개념사는 연표가 아니라 설계 축의 역사이고, 원문 06이 마지막에 "이 축은 바뀌지 않을 것이다"라고 적어 끝나는 연도를 두지 않기 때문이다.

Rust의 역사를 **시대순 + 핵심 시스템 + 개념사**로 정리한 문서 모음이다. GC 없이 메모리 안전과 동시성을 어떻게 얻었고, 에디션으로 어떻게 진화하며, 무엇이 Rust를 "가장 사랑받는 언어"로 만들었는지를 다룬다. 모든 문서는 한국어. (자매: `java-history`·`database-history`·`python-history`)

## 한눈에 — 6편이 이어지는 순서

```text
원문 README 「읽는 법」이 적은 순서 — 01→06
오른쪽은 그 문장이 각 편에 붙인 말이다.

 01 탄생 ~ 1.0       ──  "정체성을 깎아낸 역사"(1.0)
   │
 02 에디션           ──  호환 유지 진화(에디션)
   │
 03 소유권 시스템    ──  소유권이라는 핵심
   │
 04 비동기·동시성    ┐
   │                 ├──  동시성·생태계   (원문은 이 둘을 한 마디로 묶었다)
 05 생태계·도구      ┘
   │
 06 핵심 개념 진화   ──  그 바탕 개념
```

그림 읽는 법 — 세로선은 원문 README가 적은 **읽는 순서**이고, 편들 사이의 파생·인과 관계를 뜻하지 않는다.\
오른쪽 다섯 마디는 원문 「읽는 법」 한 문장을 토막 내 그 자리에 붙인 것이다 — 04와 05가 한 괄호로 묶인 것은 원문이 그 둘을 「동시성·생태계」 한 마디로 적었기 때문이다.\
원문은 **03(소유권)·06(개념)이 Rust의 본질**이라고 따로 짚는다.

## 읽는 법

01→06으로 읽으면 **"정체성을 깎아낸 역사"(1.0) → 호환 유지 진화(에디션) → 소유권이라는 핵심 → 동시성·생태계 → 그 바탕 개념**이 보인다. 03(소유권)·06(개념)이 Rust의 본질이고, corpus의 `불변성-값타입`·`에러-부재-표현`·`동시성-제어`와 직접 이어진다.

> 큰 줄기: **C++ 대체 목표 → GC·런타임 깎아냄 → 소유권으로 컴파일타임 안전 → fearless concurrency → 시스템·웹·도구로 확산.**

급하면 이렇게 골라 읽어도 된다.

- Rust가 왜 이렇게 생긴 언어인지부터 알고 싶다 → **01**
- `Cargo.toml`의 `edition = "2021"`이 무슨 뜻인지 모르겠다 → **02**
- 소유권·이동·빌림·라이프타임이 각각 무엇인지 잡고 싶다 → **03의 「핵심 메커니즘 1~4」**
- borrow checker가 왜 예전보다 덜 까다로워졌는지 궁금하다 → **03의 「borrow checker의 진화」**
- `Rc`를 스레드로 넘기려다 컴파일 에러를 만났다 → **04의 「`Rc` vs `Arc` — 트레이트가 막아주는 실제 사례」**
- `async fn`을 불렀는데 아무 일도 일어나지 않는다 → **04의 「`async fn`의 게으름 — 흔한 함정」**
- Rust는 왜 async 런타임을 표준에 두지 않는지 알고 싶다 → **04의 4부**
- `Pin`이 왜 나오는지, async 트레이트가 왜 아직 불편한지 알고 싶다 → **04의 5부**
- Cargo·crates.io·rustup·clippy가 각각 무엇을 맡는지 정리하고 싶다 → **05의 「Cargo」~「rustfmt와 clippy」 네 절**
- Rust가 커널·브라우저·마이크로컨트롤러까지 어떻게 갔는지 궁금하다 → **05의 「확산 ①~④」**
- `impl Trait`과 `dyn Trait` 중 무엇을 쓸지 기준을 잡고 싶다 → **06의 2절 표**
- `?` 연산자와 `panic!`을 언제 각각 쓰는지 헷갈린다 → **06의 4절**
- `unsafe`가 정확히 무엇을 푸는지 알고 싶다 → **06의 6절**
- "zero-cost"가 진짜 공짜라는 뜻인지 궁금하다 → **06의 「정직한 단서 — "zero-cost"의 진짜 의미」**
- Rust 전체 지도를 한 번에 잡고 싶다 → **01 → 03 → 04 → 06**
