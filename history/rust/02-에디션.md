# Rust 에디션 (2015 / 2018 / 2021 / 2024)

> 원본: `~/project/rust-history/02-에디션.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-19).\
> 연도·버전·RFC 번호·Rust 코드블록 12개·원문이 직접 그린 `text` 도식 1개·「에디션 비교 한눈에」 표는 원문 그대로다.\
> 내가 새로 그린 ASCII 도식은 3개다 — 2개는 원문 mermaid 그림을 글자로 옮긴 것이고, 1개는 원문이 「① → ② → ③」으로 적은 3단계를 세로로 편 것이다.\
> 「한눈에」의 방언 비유, 용어 블록의 「예:」, 「용어 풀이」도 원문에 없는 보충이다.

## 한눈에 — 쉽게 말하면

원문이 제목 아래에 적은 한 줄 요약은 이것이다.

> 하위 호환을 깨지 않으면서도 언어를 계속 진화시키기 위해 Rust가 택한 장치. "에디션"은 6주마다 나오는 일반 릴리스와 달리, 키워드·문법·기본 동작처럼 **깨질 수밖에 없는 변화**들을 약 3년 주기로 한데 묶어 **크레이트 단위로 opt-in** 하게 만든 호환성 경계선이다.

한 언어 안에 **방언**이 여러 개 있다고 생각하면 쉽다.\
마을마다 말버릇이 조금씩 다르지만 서로 말은 통하고, 어느 말버릇을 쓸지는 마을이 스스로 정한다.\
**에디션도 똑같은 구조다** — 원문 자신이 이것을 "언어 자체에 '방언(dialect)'의 경계를 두고"라고 적는다.

내가 새로 든 비유는 이 방언 하나뿐이고, 용어 블록의 「예:」에서 잠깐 쓰는 국소 비유(식당에서 자리 맡아 두기)가 하나 더 있다.\
원문이 직접 쓴 비유(「하위 호환의 닻」·「이사」·「에디션이 길을 닦고, 일반 릴리스가 차를 굴린다」)는 원문 문장 그대로 두었다.

| 비유 | 실체 |
|------|------|
| 마을마다 쓰는 말버릇 | 크레이트마다 고르는 에디션 |
| 어느 말버릇을 쓸지 마을이 직접 정한다 | `Cargo.toml`의 `edition` 필드 — opt-in |
| 아무것도 적지 않은 마을은 옛 말버릇 그대로 | `edition` 필드가 없으면 2015 에디션으로 간주 |
| 말버릇이 달라도 서로 말이 통한다 | 에디션이 다른 크레이트끼리 아무 문제 없이 링크된다 |
| 말버릇을 바꿀 때 낡은 말투를 대신 고쳐 주는 손 | `cargo fix --edition` — 새 에디션에서 깨질 코드를 원문 표현대로 "미리 자동 수정"해 준다 |

초보자가 가장 자주 하는 오해부터 짚어 두면 이렇다.

- **에디션이 새로 나와도 내 코드는 그대로 돈다.**\
  원문 표현으로 "새 에디션이 나와도 기존 크레이트는 자동으로 바뀌지 않는다".
- **내가 `edition` 필드를 올릴 때 비로소** 그 크레이트에 새 규칙이 적용된다.\
  이때 고쳐야 할 코드가 생길 수 있는데, 그것을 원문 표현대로 "미리 자동 수정"해 주는 것이 `cargo fix --edition`이다.
- **에디션이 다른 크레이트끼리도 함께 빌드된다.**\
  원문 표현으로 "아무 문제 없이 링크된다".

## 에디션이란 무엇인가 — 메커니즘

Rust는 "안정성 없는 진화는 무책임하고, 진화 없는 안정성은 무의미하다"는 입장에서 출발했다.\
1.0(2015) 이후 Rust는 **"안정성 보장(stability guarantee)"** — 한 번 stable로 풀린 코드는 이후의 모든 컴파일러에서 계속 빌드된다 — 을 핵심 약속으로 삼았다.\
그런데 이 약속은 곧 딜레마를 낳는다.\
`async`를 키워드로 만들고 싶어도, 이미 `async`를 변수 이름으로 쓰는 코드가 세상에 존재하면 그 코드를 깨뜨리게 된다.\
모듈 경로 규칙을 더 직관적으로 바꾸고 싶어도 마찬가지다.

> **안정성 보장(stability guarantee)** — 한 번 stable로 풀린 코드는 이후의 모든 컴파일러에서 계속 빌드된다는 약속(원문 정의 그대로).\
> 예: 2015년에 쓴 크레이트를 오늘 컴파일러로 빌드해도, `edition` 필드를 그대로 두는 한 계속 빌드된다.

에디션은 이 딜레마의 해법이다.\
**언어 자체에 "방언(dialect)"의 경계를 두고, 각 크레이트가 자기 `Cargo.toml`에서 어느 에디션으로 컴파일될지 선택**하게 한다.\
핵심 규칙은 다음과 같다.

- **opt-in(자발적 선택)**: 새 에디션이 나와도 기존 크레이트는 자동으로 바뀌지 않는다. `Cargo.toml`의 `edition` 필드를 직접 올려야만 새 규칙이 적용된다. `edition` 필드가 없으면 호환성을 위해 **2015 에디션**으로 간주한다.
- **크레이트 단위 격리 + 무결한 상호운용**: 에디션 선택은 **크레이트마다 독립적**이다. 2015 에디션 크레이트가 2024 에디션 크레이트를 의존성으로 쓰거나 그 반대도 **아무 문제 없이 링크**된다. 즉 에디션은 컴파일 시점의 소스 해석 규칙일 뿐, 산출되는 바이너리/ABI 경계가 아니다. 덕분에 생태계 전체가 동시에 이사할 필요 없이, 각 크레이트가 **자기 페이스로** 마이그레이션할 수 있다.
- **마이그레이션 자동화**: `cargo fix --edition`이 새 에디션에서 깨질 코드를 **이전 에디션에서 미리 자동 수정**해 준다(예: `gen` 식별자를 `r#gen`으로 치환). 자동으로 못 고치는 부분은 경고로 알려 수동 수정을 유도한다. 보통 ① `cargo fix --edition`으로 호환 패치 → ② `edition` 필드 상향 → ③ 테스트로 검증의 3단계를 밟는다.
- **새 기능 ≠ 에디션 전용**: 흔한 오해 하나. 대부분의 새 기능(예: `impl Trait`, `?` 연산자, `async`/`await`의 실제 동작)은 **에디션과 무관하게** 일반 릴리스에서 모든 에디션에 풀린다. 에디션이 진짜로 가르는 것은 **하위 호환을 깨는 변화** — 새 키워드 예약, 문법 의미 변경, 기본 동작(default) 전환 — 뿐이다.

> **크레이트(crate)** — Rust가 한 번에 컴파일하고 배포하는 단위(원문은 이 말을 정의하지 않고 쓴다).\
> 예: 내가 만든 프로그램도 크레이트 하나이고, 의존성으로 끌어다 쓰는 `serde`도 각각 크레이트 하나다.

> **opt-in(자발적 선택)** — 새로 나온 것이 저절로 적용되지 않고, 쓰겠다고 직접 표시해야 적용되는 방식(원문 정의 그대로).\
> 예: `Cargo.toml`에 `edition = "2024"`라고 적기 전까지는, 2024 에디션이 나와 있어도 내 크레이트는 옛 규칙으로 컴파일된다.

세 번째 불릿의 3단계를 세로로 펴면 이렇다.

```text
에디션 올리기 — 원문이 적은 3단계 (원문 문장의 "→" 두 개를 그대로 세로로 폈다)

① cargo fix --edition      새 에디션에서 깨질 코드를 이전 에디션에서 미리 자동 수정
        |
        v
② edition 필드 상향        Cargo.toml 의 edition 을 직접 올린다
        |
        v
③ 테스트로 검증
```

- 왼쪽은 **무엇을 하는 단계**, 오른쪽은 **그 단계가 하는 일**이다.
- 화살표는 둘뿐이고, 원문 문장에 있는 `→` 두 개와 같은 자리다.
- ①에서 자동으로 못 고치는 부분은 원문 표현대로 "경고로 알려 수동 수정을 유도한다".

```text
일반 릴리스(6주 주기)          에디션(약 3년 주기)
──────────────────────        ─────────────────────────────
하위호환 유지되는 모든 변화     하위호환을 "깨는" 변화만 묶음
모든 에디션에 즉시 적용         크레이트가 opt-in 해야 적용
예: impl Trait, async/await    예: dyn 키워드화, 모듈 경로 규칙,
    let-else, GAT ...              클로저 캡처 규칙, unsafe extern ...
```

- 이 그림은 원문에 있는 것을 그대로 옮긴 것이다(내가 만든 도식이 아니다).
- 왼쪽 칸이 6주마다 나오는 **일반 릴리스**, 오른쪽 칸이 약 3년 주기의 **에디션**이다.

아래는 에디션 간 상호운용 모델이다. 서로 다른 에디션의 크레이트가 하나의 빌드 그래프 안에서 공존한다.

```text
하나의_최종_바이너리

  내 크레이트    ──의존──>   serde          ──의존──>   core/std
  edition = 2024             edition = 2021            (에디션 무관)
      │                                                     ^
      ├──의존──>  오래된 lib  ──────────────────────────────┤
      │           edition = 2015                            │
      └─────────────────────────────────────────────────────┘
```

- 이것은 원문 mermaid 그림을 글자로 옮긴 것이다 — 노드 문구·화살표 방향·`하나의_최종_바이너리`라는 묶음 이름까지 원문 그대로다.
- 화살표는 다섯 개이고, 그중 `의존` 라벨이 붙은 셋만 원문에 라벨이 있다.\
  나머지 둘(오래된 lib → core/std, 내 크레이트 → core/std)은 원문 mermaid에도 라벨이 없어 무라벨로 두었다.

에디션은 **소스 코드를 해석하는 규칙의 버전**일 뿐이라서, 컴파일이 끝나 같은 IR/머신코드로 내려오면 서로 구분되지 않는다.\
그래서 위처럼 에디션이 뒤섞인 의존성 그래프가 단일 바이너리로 무결하게 합쳐진다.

## Rust 2015 — 기준선 (Rust 1.0, 2015년 5월)

> 모든 것의 출발점. "에디션"이라는 개념조차 아직 없던, 그러나 소급해서 *2015 에디션*으로 이름 붙은 원점.

*(아래 세 에디션 절은 「무엇이 바뀌었나 → 전/후 코드 대비 → 왜 그렇게 했나」 순서로 읽으면 된다. 「대가는 무엇인가」 표제는 쓰지 않았다 — 원문에서 "비용"이라는 낱말이 나오는 두 곳은 동적 디스패치 자체의 비용(2018 `dyn` 절)과 에디션 전환 비용(「영향과 의의」)이고, 둘 다 원문 문장 자리에 그대로 두었다. 원문이 「함정」이라고 부른 자리(2021 절 머리말의 "작은 함정들", 배열 `.into_iter()`, 2024 절 머리말의 "수명/임시값 함정들")도 전부 원문 문장 자리에 그대로 두었다.)*

### 위치

Rust 1.0이 곧 2015 에디션이다.\
에디션 메커니즘 자체는 2018에 와서야 도입됐지만, 그 이전의 모든 코드를 "2015 에디션"으로 소급 정의했다.\
`Cargo.toml`에 `edition`을 적지 않은 모든 크레이트는 지금도 2015로 컴파일된다 — 즉 **하위 호환의 닻** 역할을 한다.

### 2015 시대의 특징 (이후 에디션이 바꾸게 될 것들)

- **모듈 경로가 `extern crate`와 `::` 접두사에 의존적**이었다. 외부 크레이트를 쓰려면 `extern crate serde;`를 선언해야 했고, `use` 경로에서 최상위 모듈과 외부 크레이트, 로컬 항목이 한 네임스페이스에 뒤섞여 혼란스러웠다.
- **`dyn`은 평범한 식별자**였다. 트레잇 객체는 `Box<Trait>`처럼 `dyn` 없이 썼고, 이 때문에 "타입 자리에 트레잇 이름이 그냥 오는" 모호함이 있었다.
- `async`/`await`/`try`는 **아직 키워드가 아니어서** 변수·함수 이름으로 자유롭게 쓸 수 있었다.

```rust
// 2015 스타일
extern crate rand;            // 외부 크레이트 명시적 선언 필요

use rand::Rng;

fn make() -> Box<Foo> {       // dyn 없는 트레잇 객체
    Box::new(Bar)
}

let async = 1;                // async는 그냥 식별자 — 합법
```

> **키워드(keyword)** — 언어가 문법을 위해 이미 가져다 쓴 낱말이라, 변수·함수 이름으로는 쓸 수 없는 말.\
> 예: 위 코드의 `let async = 1;`이 2015에서는 합법이다 — 그때 `async`는 아직 키워드가 아니라 평범한 식별자였다.

2015는 그 자체로 "혁신적"이라기보다, **이후 에디션이 무엇을 고쳤는지 가늠하는 기준선**으로서 의미가 크다.

## Rust 2018 — 생산성 (Rust 1.31, 2018년 12월)

> 1.0 이후 첫 에디션. "Rust를 더 쓰기 쉽게(productivity)"를 슬로건으로, 모듈 시스템·트레잇 객체 문법·차용 검사기를 한꺼번에 손봤다. async 시대를 여는 키워드 예약도 이때 이뤄졌다.

### 시대적 배경

2015~2018 사이 Rust는 빠르게 성장했지만, 초심자들이 가장 많이 걸려 넘어진 두 곳이 **모듈/경로 시스템**과 **차용 검사기(borrow checker)의 경직성**이었다.\
2018 에디션은 "언어 자체를 더 키우기보다, 이미 있는 것을 **덜 헷갈리게** 만든다"는 방향으로 이 마찰들을 정조준했다.\
동시에, 곧 다가올 비동기(async) 생태계를 위해 키워드를 미리 확보해 뒀다.

> **차용 검사기(borrow checker)** — 참조를 언제부터 언제까지 쓸 수 있는지를 컴파일러가 따져 보는 검사. 그 판정 기준이 "불변 참조는 여러 개, 가변 참조는 정확히 하나"라는 차용 규칙이다(이 규칙 문장은 01·03편의 원문에서 가져왔다 — 02편 원문에는 없다).\
> 예: 원문이 이 절에서 든 문제는 이 검사의 **경직성**이고, 그 구체적 모습은 아래 NLL 절의 "멀쩡한 코드가 '이미 빌렸다'며 거부되던" 쪽이다.

### 모듈 경로 시스템 정비 (path clarity / uniform paths)

가장 체감되는 변화.\
`use` 경로의 의미를 재정의해, **로컬 모듈 경로와 외부 크레이트 경로를 일관되게** 다루도록 했다.\
대부분의 경우 `extern crate` 선언이 더 이상 필요 없어졌고, 경로 앞에 `crate::`(현재 크레이트 루트), `self::`, `super::`를 붙여 출처를 분명히 하게 됐다.

```rust
// Before (2015)
extern crate serde;                 // 선언 필요
use serde::Serialize;
use ::std::collections::HashMap;    // 최상위 경로 모호성

mod foo {
    // 형제 모듈 참조가 직관적이지 않음
}
```

```rust
// After (2018)
use serde::Serialize;               // extern crate 불필요
use std::collections::HashMap;

mod foo { /* ... */ }

use crate::foo::Bar;                // crate:: 로 현재 크레이트 루트를 명시
use self::sibling::Baz;             // self:: 로 형제 모듈
```

- 위가 2015, 아래가 2018이다 — 두 코드블록 모두 원문 그대로이고, `// Before (2015)` / `// After (2018)` 주석도 원문이 붙여 둔 것이다.
- `extern crate serde;`가 없어지고, `use ::std::collections::HashMap;`의 `::` 접두사가 빠졌으며, `use crate::foo::Bar;`·`use self::sibling::Baz;`가 새로 생겼다.

### `dyn Trait` — 트레잇 객체 문법의 명시화

트레잇 객체를 쓸 때 `dyn` 키워드를 **명시**하도록 바뀌었다(2018에서 `dyn`은 진짜 키워드가 되어 식별자로 못 쓴다).\
`Box<Foo>`처럼 트레잇 이름이 타입 자리에 그냥 오던 모호함을 없애고, "이건 동적 디스패치(가상 호출)다"라는 비용을 코드에 드러냈다.

```rust
// Before (2015):  타입인지 트레잇 객체인지 시각적으로 모호
fn draw(shape: Box<Shape>) { /* ... */ }

// After (2018):  dyn 으로 동적 디스패치임을 명시
fn draw(shape: Box<dyn Shape>) { /* ... */ }
```

> **트레잇 객체 / 동적 디스패치(dynamic dispatch)** — 어느 구현이 불릴지 컴파일 때 정하지 않고 실행 중에 정해 부르는 방식.\
> 예: 위 코드의 `Box<dyn Shape>`는 "무슨 도형이 들어올지는 실행할 때 정해진다"는 뜻이고, 원문은 그 **비용**이 코드에 드러나게 된 것을 이 변화의 이유로 든다.

### NLL — Non-Lexical Lifetimes (비어휘적 수명)

차용 검사기가 참조의 수명을 **어휘 블록(`{}`) 끝까지**가 아니라 **실제 마지막 사용 지점까지**로 보도록 정밀해졌다.\
멀쩡한 코드가 "이미 빌렸다"며 거부되던 가장 흔한 좌절을 크게 줄였다.\
2018 에디션에서 먼저 기본 활성화됐고, 이후 2015 에디션에도 소급 적용됐다.

```rust
// Before (2015 / NLL 이전):  컴파일 에러
let mut v = vec![1, 2, 3];
let first = &v[0];          // 불변 차용 시작
println!("{}", first);      // 마지막 사용
v.push(4);                  // ❌ 어휘 블록 끝까지 first가 살아있다고 봐서 거부

// After (2018 / NLL):  통과
let mut v = vec![1, 2, 3];
let first = &v[0];
println!("{}", first);      // 여기서 first의 수명이 끝남(마지막 사용)
v.push(4);                  // ✅ 이제 가변 차용 허용
```

> **수명(lifetime)** — 참조를 유효하게 쓸 수 있는 코드 구간.\
> 예: 위 코드에서 달라진 것은 `first`의 수명을 **검사기가 어디까지로 보느냐**다 — 원문 표현으로 "어휘 블록(`{}`) 끝까지"에서 "실제 마지막 사용 지점까지"로.

### async / await 키워드 예약 — 비동기 시대 준비

2018 에디션 출시 시점에는 `async`/`await`의 **실제 동작은 아직 안 들어왔지만**, `async`·`await`·`try`를 **키워드로 예약**해 뒀다.\
미래에 비동기 문법을 깨짐 없이 도입하기 위한 포석이었다.\
실제 `async fn`/`.await`의 안정화는 1년 뒤 일반 릴리스 1.39(2019년 11월)에서 — **2018 이후 전 에디션에 동시에** — 이뤄졌다. (에디션이 한 일은 "키워드 자리 확보", 기능 자체는 일반 릴리스가 푼 전형적 사례.)

> **키워드 예약** — 아직 쓰지 않을 낱말을 미리 키워드로 잡아 두어, 나중에 문법을 넣을 때 남의 코드를 깨지 않게 하는 것.\
> 예: 식당에서 자리를 미리 맡아 두는 것과 같다 — 2018 에디션이 `async`·`await`·`try` 자리를 맡아 두었고, 2024 에디션이 `gen` 자리를 맡아 두었다.

### 그 외 2018 변화

- **익명 트레잇 파라미터 폐지**: `fn foo(Box<Foo>)`처럼 이름 없는 인자를 금지하고 `fn foo(_: Box<Foo>)`처럼 이름(또는 `_`)을 요구.
- **`?` 연산자 / `impl Trait` 정착**: 둘 다 엄밀히는 일반 릴리스에서 풀린 기능이지만, 2018 시대에 들어 표준 관용구로 자리 잡았다.
- **raw identifiers (`r#async`)**: 새 키워드와 충돌하는 식별자를 `r#` 접두사로 계속 쓸 수 있게 해, 에디션 간 마이그레이션의 탈출구를 제공.

## Rust 2021 — 다듬기 (Rust 1.56, 2021년 10월)

> 큰 패러다임 전환보다 **오래 거슬리던 작은 함정들**을 정리한 에디션. 클로저 캡처, 배열 이터레이터, prelude, panic 매크로의 일관성을 손봤다.

### 시대적 배경

2018이 "큰 수술"이었다면 2021은 **연마(polish)**다.\
Rust가 프로덕션에서 널리 쓰이며 쌓인, 사소하지만 반복적으로 사람을 놀라게 하던 동작들을 바로잡았다.\
변화 하나하나의 크기는 작지만, "직관과 어긋나던 구석"을 줄였다는 점에서 일상 코드의 품질을 올렸다.

### 클로저의 분리 캡처 (disjoint closure capture, RFC 2229)

클로저가 구조체를 캡처할 때, 2018까지는 **구조체 전체**를 캡처했다.\
2021부터는 클로저가 **실제로 쓰는 필드만** 따로 캡처한다.\
덕분에 "필드 하나만 쓰는데 구조체 전체가 빌려져서" 발생하던 차용 충돌이 사라졌다.

```rust
struct Point { x: i32, y: i32 }
let mut p = Point { x: 0, y: 0 };

// Before (2018):  클로저가 p 전체를 캡처 → 아래 p.y 접근과 충돌
let c = || println!("{}", p.x);
// p.y = 10;   // ❌ p가 통째로 빌려진 상태

// After (2021):  클로저는 p.x 만 캡처
let c = || println!("{}", p.x);
p.y = 10;      // ✅ p.y 는 자유 — 분리 캡처
c();
```

> **클로저(closure)와 캡처(capture)** — 바깥의 변수를 끌어다 쓰는 익명 함수, 그리고 그 "끌어다 쓰기".\
> 예: 위 코드의 `|| println!("{}", p.x)`가 클로저이고, 2021부터 이 클로저가 붙드는 것은 `p` 전체가 아니라 `p.x`다.

### `IntoIterator for arrays` — 배열의 `.into_iter()` 의미 변경

2021 이전엔 배열 `[1, 2, 3]`에 `.into_iter()`를 호출하면 (하위 호환 때문에) **참조 이터레이터**(`&T`를 내놓음)로 동작하는 함정이 있었다.\
2021부터는 배열이 진짜로 `IntoIterator`를 구현해, `.into_iter()`가 **값(`T`) 이터레이터**를 내놓는다 — 직관과 일치.

```rust
let arr = [1, 2, 3];

// Before (2021 이전):  arr.into_iter() 가 &i32 를 내놓음(혼란)
for x in arr.into_iter() {  // x: &i32
}

// After (2021):  값으로 순회
for x in arr.into_iter() {  // x: i32
}
```

### prelude에 세 항목 추가

자동으로 import되는 prelude에 `TryInto`, `TryFrom`, `FromIterator`가 추가됐다.\
이전엔 매번 `use std::convert::TryInto;` 등을 손으로 적어야 했다.\
(prelude를 바꾸면 기존 코드의 메서드 해석이 달라질 수 있어 — 동명의 트레잇 메서드 충돌 — 에디션 경계가 필요했다.)

```rust
// Before (2018):  명시적 import 필요
use std::convert::TryInto;
let n: u8 = 1000i32.try_into().unwrap_or(0);

// After (2021):  prelude에 포함 — import 불필요
let n: u8 = 1000i32.try_into().unwrap_or(0);
```

> **prelude** — 아무것도 적지 않아도 자동으로 import돼 있는 이름들의 묶음.\
> 예: 원문이 적은 대로 `TryInto`·`TryFrom`·`FromIterator`가 2021부터 여기에 들어가, `use std::convert::TryInto;`를 손으로 적지 않아도 된다.

### `panic!` 매크로의 일관성

`panic!("{}")`처럼 **포맷 문자열로 보이는데 인자가 없는** 호출을, 2021부터 `println!`과 **동일하게** 포맷 문자열로 해석하도록 통일했다.\
이전엔 `panic!`이 인자 하나면 포맷 처리 없이 그대로 패닉 메시지로 쓰던 비일관성이 있었다.

```rust
// Before (2021 이전):  panic!의 단일 인자는 포맷 처리 안 함
panic!("{}");          // 메시지가 문자 그대로 "{}"

// After (2021):  println! 과 동일하게 포맷 문자열로 처리
panic!("{}", value);   // 일관된 포맷 동작
// panic!("{}");        // 인자 누락 → 컴파일 에러로 잡힘
```

### 그 외 2021 변화

- **reserved syntax (`ident"..."` 예약)**: `prefix"string"`이나 `prefix#ident` 같은 접두사 토큰 문법을 미래 확장(예: 커스텀 리터럴)을 위해 예약.
- **Cargo feature resolver v2가 기본**: 의존성 feature 통합 방식을 더 정확한 v2로 전환(플랫폼별·빌드 의존성 feature 누수 방지).
- 여러 경고성 린트가 정식 오류로 승격.

## Rust 2024 — 최신 (Rust 1.85, 2025년 2월)

> 역대 **가장 큰 규모**의 에디션. `unsafe`의 경계를 더 엄격히 긋고, 수명(lifetime) 캡처 규칙·임시값(temporary) 수명·미래 키워드 예약을 대대적으로 정비했다.

### 시대적 배경

2024 에디션은 2025년 2월 20일 Rust 1.85와 함께 출시됐다.\
변경 항목 수로는 역대 최다로, "안전성의 빈틈을 메우고(`unsafe` 명시), 다음 10년의 문법 진화 공간을 확보(`gen` 예약 등)"하는 데 방점이 찍혔다.\
async 생태계의 성숙, 대규모 코드베이스에서 드러난 미묘한 수명/임시값 함정들이 배경이다.

### `unsafe extern` 블록 — FFI 안전 계약의 명시

외부(C 등) 함수를 선언하는 `extern` 블록에 **`unsafe` 키워드를 의무화**했다.\
extern 블록 안의 선언은 "이 시그니처가 실제 외부 정의와 맞다"는 **검증 불가능한 약속**을 담으므로, 그 위험을 코드에 드러내게 한 것이다.

```rust
// Before (2021):
extern "C" {
    fn strlen(s: *const u8) -> usize;
}

// After (2024):  extern 블록 자체가 unsafe 계약임을 명시
unsafe extern "C" {
    // 개별 항목의 안전성도 표시 가능
    safe fn abs(input: i32) -> i32;          // 호출이 항상 안전
    unsafe fn strlen(s: *const u8) -> usize; // 호출자에 안전 책임
}
```

> **`extern` 블록 / FFI** — 다른 언어(C 등)로 만들어진 함수를 Rust에서 부르려고 그 모양만 적어 두는 선언.\
> 예: 위 코드의 `fn strlen(s: *const u8) -> usize;`는 C의 `strlen`이 이런 모양일 것이라고 적어 둔 것이고, 그게 맞는지는 원문 표현대로 "검증 불가능한 약속"이다.

> **`unsafe`** — 컴파일러가 스스로 확인할 수 없는 약속을 사람이 대신 책임진다고 코드에 표시하는 것.\
> 예: 위 코드에서 개별 항목까지 나뉘는 것을 보라 — `safe fn abs`는 "호출이 항상 안전", `unsafe fn strlen`은 "호출자에 안전 책임"이라고 원문 주석이 적고 있다.

### `if let` 임시값 수명 단축 (temporary scope)

`if let $pat = $expr { .. } else { .. }`에서, `$expr`이 만든 **임시값의 수명**을 2024부터는 `else` 진입 전 / then-블록 평가 직후에 끝내도록 줄였다.\
이전엔 임시값이 `if let` 전체가 끝날 때까지 살아남아, **락(lock) 가드 같은 것이 else 블록에서도 잡혀 있어** 데드락이나 의외의 동작을 일으키곤 했다.\
(꼬리 표현식 임시값 수명(tail expression temporary scope)도 비슷한 취지로 함께 단축됐다.)

```rust
// Before (2021):  else 블록에서도 mutex 가드가 살아있어 재잠금 데드락 위험
if let Some(v) = data.lock().unwrap().get(&key) {
    use_it(v);
} else {
    data.lock().unwrap().insert(key, ...); // ❌ 위의 가드가 아직 안 풀림
}

// After (2024):  else 진입 전에 임시 가드가 drop 됨 → 안전
```

> **임시값(temporary)** — 식 하나를 계산하는 동안에만 생겼다 사라지는 이름 없는 값.\
> 예: 위 코드의 `data.lock().unwrap()`이 만들어 내는 락 가드가 그것이고, 원문이 문제 삼은 것은 그 가드가 언제 풀리느냐다.

### RPIT 수명 캡처 규칙 — `use<..>` 바운드

반환 위치 `impl Trait`(RPIT, Return-Position `impl Trait`)이 **시야 안의 모든 제네릭 파라미터(수명 포함)를 암묵적으로 캡처**하도록 통일했다.\
2021까지는 수명이 시그니처에 *문법적으로 등장할 때만* 캡처되어 직관에 어긋났다.\
캡처 대상을 제한하려면 새 `use<..>` 바운드로 명시한다.

```rust
// 2024: 반환 impl Trait 이 'a 를 암묵 캡처(직관적). 제한하려면 use<> 명시.
fn names<'a>(v: &'a [String]) -> impl Iterator<Item = &'a str> { /* ... */ }

fn only_t<T>(t: T) -> impl Sized + use<T> { t }  // T만 캡처, 수명은 제외
```

### `gen` 키워드 예약 — 제너레이터의 미래

`gen` 블록(제너레이터/이터레이터를 손쉽게 만드는 미래 문법)을 도입하기 위해 `gen`을 **키워드로 예약**했다.\
기존에 `gen`을 식별자로 쓰던 코드는 `cargo fix --edition`이 자동으로 `r#gen`으로 바꿔 양쪽 에디션에서 계속 동작하게 한다.

### never type(`!`) fallback 변경

타입 추론이 미결정 타입을 채울 때의 기본값(fallback)을 `()`에서 **never 타입 `!`로** 바꿨다.\
`unsafe` 코드로 흘러드는 미묘한 추론 차이를 막기 위한 정비로, 관련 린트도 경고에서 거부(deny)로 승격했다.

### 그 외 2024 변화 (대규모)

- **unsafe 속성**: `#[no_mangle]`, `#[export_name]`, `#[link_section]` 등 안전성에 영향을 주는 속성을 `#[unsafe(no_mangle)]`처럼 **`unsafe(..)`로 감싸도록** 변경.
- **새로 unsafe가 된 함수**: `std::env::set_var`/`remove_var`, 일부 `std::os` 함수가 `unsafe`로 표시됨(스레드 안전성 문제 반영).
- **`static mut` 참조 금지**: `static mut`에 대한 참조(`&`/`&mut`) 생성을 거부(`static_mut_refs`) — 데이터 레이스의 흔한 원천을 차단.
- **match ergonomics 예약**: 기본 바인딩 모드가 명시적이지 않을 때 `mut` 바인딩을 금지하는 등, 미래 개선을 위해 일부 패턴 조합을 보수적으로 막음.
- **reserved syntax 확장**: guarded string literal 등 추가 토큰 문법 예약.
- **Cargo: rust-version 인지 의존성 해석기(resolver v3)**: `edition = "2024"`는 `resolver = "3"`을 함의하며, 의존성의 `rust-version`(MSRV)을 고려해 호환 버전을 고르는 해석기를 기본화.

## 에디션 비교 한눈에

| 에디션 | 릴리스 | 슬로건 | 대표 변화 |
|--------|--------|--------|-----------|
| **2015** | 1.0 (2015.05) | 기준선 | `extern crate`, `Box<Trait>`, async/await 키워드 아님 |
| **2018** | 1.31 (2018.12) | 생산성 | 모듈 경로 정비, `dyn Trait`, NLL, async 키워드 예약 |
| **2021** | 1.56 (2021.10) | 연마 | 분리 클로저 캡처, 배열 `IntoIterator`, prelude 3종, `panic!` 일관성 |
| **2024** | 1.85 (2025.02) | 안전·미래 확보 | `unsafe extern`, `if let` 임시값 수명, RPIT `use<>`, `gen` 예약, never fallback |

이 표는 원문 그대로다. 아래 그림도 원문 mermaid를 글자로 옮긴 것이다.

```text
  2015           2018                  2021                  2024
  기준선  --->   모듈·dyn·NLL   --->   클로저·prelude  --->   unsafe·수명·gen
                    :
                    :  async 키워드 예약   (원문에서는 점선 화살표)
                    v
                 릴리스 1.39
                 async/await 안정화
                 (2018 이후 전 에디션)
```

- 노드 안의 문구(`2015 기준선`, `2018 모듈·dyn·NLL` …)와 화살표 방향, 점선에 붙은 `async 키워드 예약` 라벨은 원문 mermaid 그대로다.
- 가로 실선 셋(2015→2018, 2018→2021, 2021→2024)은 에디션이 나온 **순서**이고, 아래로 내려가는 점선 하나만 라벨이 붙어 있다.
- 원문이 이 점선을 어떻게 읽었는지는 바로 아래 문단에 그대로 있다.

위 다이어그램의 점선처럼, 에디션은 **하위 호환을 깨는 변화를 묶고 키워드 자리를 예약**하는 역할을 하고, 실제 기능(예: async/await 동작)은 종종 그 뒤의 일반 릴리스가 전 에디션에 동시 배포한다.\
"에디션이 길을 닦고, 일반 릴리스가 차를 굴린다"는 분업이 Rust 진화의 골격이다.

## 영향과 의의

*(이 편의 「남긴 것」에 해당한다 — 아래 문장은 전부 원문 「영향과 의의」 두 문단의 것이다.)*

에디션은 Rust가 **"안정성과 진화를 동시에"**라는 모순적 목표를 푼 핵심 설계다.\
C++가 하위 호환의 무게에 눌려 오래된 기본값을 떠안고, Python이 2→3 전환에서 생태계를 수년간 분열시킨 것과 대비된다.\
Rust는 ① 깨는 변화를 에디션에 격리하고, ② 크레이트 단위 opt-in과 무결한 상호운용으로 **빅뱅 마이그레이션을 회피**하며, ③ `cargo fix --edition`으로 전환 비용을 자동화함으로써, "언어를 계속 고치면서도 누구의 코드도 깨지 않는다"를 실현했다.

그래서 에디션은 단순한 버전 표기가 아니라 **Rust의 거버넌스 철학 그 자체**다 — 6주 주기의 작은 호환 변화(릴리스)와 3년 주기의 경계선(에디션)을 분리함으로써, 빠른 진화와 장기 안정성을 한 언어 안에 양립시켰다.

## 용어 풀이

- **에디션(edition)** — 하위 호환을 깨는 변화들을 약 3년 주기로 묶어, 크레이트 단위로 골라 쓰게 만든 호환성 경계선.
- **크레이트(crate)** — Rust가 한 번에 컴파일하고 배포하는 단위. 에디션은 이 단위마다 따로 고른다.
- **`Cargo.toml` / `edition` 필드** — 크레이트의 설정 파일과, 그 안에서 에디션을 고르는 칸. 이 칸이 없으면 2015로 간주한다.
- **opt-in(자발적 선택)** — 직접 표시해야만 적용되는 방식. 새 에디션이 나와도 기존 크레이트는 자동으로 바뀌지 않는다.
- **안정성 보장(stability guarantee)** — 한 번 stable로 풀린 코드는 이후의 모든 컴파일러에서 계속 빌드된다는 약속.
- **`cargo fix --edition`** — 새 에디션에서 깨질 코드를 이전 에디션에서 미리 자동 수정해 주는 명령.
- **raw identifier (`r#async`, `r#gen`)** — 키워드가 된 낱말을 그래도 식별자로 쓰게 해 주는 `r#` 접두사.
- **키워드 예약** — 아직 기능을 넣기 전에 낱말만 미리 키워드로 잡아 두는 것. 2018의 `async`, 2024의 `gen`이 그랬다.
- **트레잇 객체 / 동적 디스패치** — 어느 구현이 불릴지 실행 중에 정해 부르는 방식. 2018부터 `dyn`으로 명시한다.
- **차용 검사기(borrow checker)** — "불변 참조는 여러 개, 가변 참조는 정확히 하나"라는 차용 규칙을, 참조를 언제까지 쓸 수 있는지 따져 가며 컴파일러가 판정하는 검사(01·03편은 같은 것을 원문 용어대로 「빌림 검사기」로 적는다).
- **NLL(Non-Lexical Lifetimes)** — 참조의 수명을 어휘 블록 끝이 아니라 실제 마지막 사용 지점까지로 보는 방식.
- **클로저(closure) / 캡처(capture)** — 바깥 변수를 끌어다 쓰는 익명 함수와 그 끌어다 쓰기. 2021부터 쓰는 필드만 캡처한다.
- **prelude** — 아무것도 적지 않아도 자동으로 import돼 있는 이름들의 묶음.
- **`extern` 블록 / FFI** — 다른 언어로 만들어진 함수의 모양만 적어 두는 선언. 2024부터 `unsafe extern`이다.
- **`unsafe`** — 컴파일러가 스스로 확인할 수 없는 약속을 사람이 대신 책임진다고 표시하는 것.
- **임시값(temporary)** — 식 하나를 계산하는 동안에만 생겼다 사라지는 이름 없는 값.
- **RPIT(Return-Position `impl Trait`)** — 반환 자리에 쓰는 `impl Trait`. 2024부터 시야 안 제네릭을 암묵 캡처한다.
- **never 타입(`!`)** — 값이 하나도 없는 타입. 2024부터 타입 추론의 fallback 기본값이 됐다.
- **MSRV(`rust-version`)** — 그 크레이트가 요구하는 최소 Rust 버전. resolver v3가 이것을 고려해 의존성을 고른다.
