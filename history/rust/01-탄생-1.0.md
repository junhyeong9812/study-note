# Rust 탄생 ~ 1.0 (2006 ~ 2015)

> 원본: `~/project/rust-history/01-탄생-1.0.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-19).\
> 연도·인명·버전·원문 인용문은 원문 그대로다(원문에는 코드블록도 표도 없다).\
> ASCII 도식 2개와 「한눈에」의 깎아내기 비유(대응표 포함), 용어 블록의 「예:」, 「용어 풀이」는 원문에 없는 보충이다.

## 한눈에 — 쉽게 말하면

원문이 제목 아래에 적은 한 줄 요약은 이것이다.

> 한 개인의 취미 프로젝트로 시작해, "가비지 컬렉터 없이 메모리 안전과 동시성을 모두 잡는다"는 목표 아래 수년간의 대격변을 거쳐 2015년 5월 첫 안정 버전 1.0에 도달하기까지의 이야기다.

조각가는 큰 돌덩이에 무언가를 덧붙이지 않는다 — 떼어 낼 것을 떼어 내면 남는 것이 형태다.\
**1.0까지의 9년도 똑같은 구조다** — 원문 자신이 이 시기를 "기능을 쌓아 올린" 역사가 아니라 "정체성을 깎아낸" 역사라고 부른다.

본문 흐름에 쓰는 비유는 이 깎아내기 하나뿐이다.\
용어 블록의 「예:」에서 잠깐 쓰는 국소 비유(종이에 숫자 고쳐 적기)가 하나 더 있다.\
원문이 직접 쓴 비유(「열차(train) 릴리스」·「다음 칸이 출발한다」)는 원문 문장 그대로 두었다.

| 비유 | 실체 |
|------|------|
| 처음의 큰 덩어리 | GC·그린 스레드·런타임·특수 포인터 문법까지 품고 있던 초기 Rust |
| 깎여 나간 부스러기 | 2012~2015년에 제거된 것들 |
| 깎고 남은 형태 | 소유권·빌림이라는 단 하나의 메모리 모델 |
| 이미 깎은 자리를 **되돌리지 않겠다**는 약속 | 1.0의 하위 호환성 보장 — 깨는 변경을 하지 않겠다는 약속이지, 언어가 더 자라지 않는다는 뜻이 아니다 |

```text
버린 것 — 원문 「4)」 (2012 ~ 2015)              대신 남은 것
+--------------------------------------------+   +-----------------------------------------+
| 가비지 컬렉터(GC)가 있었다                 |   | "GC 없는 메모리 안전"이라는 정체성 확정 |
|                                            |   | 그 빠진 자리를 메운 것이 소유권·빌림    |
| 경량 그린 스레드 + 그것을 받쳐 주는 런타임 |   | OS 네이티브 스레드 모델로 정리          |
| 타입스테이트, `pure` 키워드, 채널 문법     |   |                                         |
| sigil 포인터 표기 `@`, `~`                 |   | `Box<T>` 같은 일반 타입으로 흡수        |
+--------------------------------------------+   +-----------------------------------------+
```

- 같은 행의 왼쪽·오른쪽은 원문 「4)」 절이 한 불릿 안에서 짝지은 문장이다 — 1행은 불릿 1, 2행은 불릿 2, 3·4행은 불릿 4에서 왔다. 1행 오른쪽의 둘째 줄만 불릿 3(「GC가 빠진 자리를 메운 것이 바로 이것이다」)에서 가져왔다.
- 3행 오른쪽이 빈 것은 원문이 그 제거들에 대해 "대신 남은 것"을 따로 적지 않기 때문이다.
- 왼쪽 열 머리의 연도는 원문 절 제목의 `(2012 ~ 2015)`에서 온 것이다. 오른쪽 열을 한 시점으로 묶는 경계는 원문에 없어 연도를 붙이지 않았다 — 원문은 GC 제거를 "2013년경"·"0.8 사이클 전후"로, 런타임·그린 스레드 제거를 "1.0 직전"으로 따로 적는다.
- 원문이 이 절 전체를 요약해 둔 「핵심」 인용은 아래 「4) pre-1.0 대격변」 절 끝에 있다.

## 연표 정보
- 시작: 2006년 — Graydon Hoare의 개인 프로젝트
- Mozilla 공식 후원: 2009년
- 첫 공개 릴리스: 0.1 (2012년 1월 20일)
- 첫 안정 릴리스: 1.0 (2015년 5월 15일)
- 개발 주체: Graydon Hoare(창시자) → Mozilla Research → 오픈소스 커뮤니티(RFC 거버넌스)
- 이름의 유래: 생존을 위해 "과하게 설계된(over-engineered)" 균류 rust(녹병균)에서 따왔다

## 시대적 배경

2000년대 중반의 시스템 프로그래밍 세계는 사실상 C와 C++의 독무대였다.\
운영체제, 브라우저 엔진, 데이터베이스처럼 성능과 메모리 제어가 생명인 영역에서 이 두 언어를 대체할 현실적 후보는 없었다.\
그러나 C/C++는 수동 메모리 관리의 대가로 끊임없는 위험을 안고 있었다 — use-after-free, 이중 해제(double free), 버퍼 오버플로, 데이터 레이스(data race) 같은 메모리·동시성 버그가 보안 취약점의 절대 다수를 차지했다.

반대편에는 Java, C# 같은 가비지 컬렉션(GC) 기반 언어들이 있었다.\
이들은 메모리 안전을 보장했지만, 그 대가로 런타임과 GC 일시 정지(pause)를 짊어졌고, 바로 그 때문에 OS 커널이나 브라우저 엔진의 핵심 경로에는 들어갈 수 없었다.

> **가비지 컬렉션(GC)** — 프로그램이 다 쓴 메모리를 런타임이 알아서 찾아 되돌려 주는 방식.\
> 예: Java와 C#이 그렇게 한다 — 원문은 그 대가로 "런타임과 GC 일시 정지(pause)를 짊어졌"다고 적는다.

> **데이터 레이스(data race)** — 여러 실행 흐름이 동기화 없이 같은 데이터에 동시에 접근하고, 그중 하나 이상이 쓰기인 상황.\
> 예: 두 사람이 같은 종이에 동시에 숫자를 고쳐 적으면, 누가 먼저 적었느냐에 따라 남는 값이 달라진다.

두 진영이 각각 무엇을 치렀는지를 위 두 문단에서 가져와 두 칸에 놓으면 이렇다.

```text
C / C++                                       Java, C# (GC 기반)
+------------------------------------------+  +------------------------------------------------+
| 성능과 메모리 제어가 생명인 영역에서 이  |  | 메모리 안전을 보장했다                         |
| 두 언어를 대체할 현실적 후보는 없었다    |  |                                                |
| 대가: 수동 메모리 관리의 대가로 끊임없는 |  | 대가: 런타임과 GC 일시 정지(pause)를           |
| 위험 — use-after-free, 이중 해제,        |  | 짊어졌고, 바로 그 때문에 OS 커널이나           |
| 버퍼 오버플로, 데이터 레이스             |  | 브라우저 엔진의 핵심 경로에는 들어갈 수 없었다 |
+------------------------------------------+  +------------------------------------------------+
```

- 두 칸의 문구도, "대가:"라는 말도 바로 위 두 문단에서 가져온 것이고, 대립축 역시 원문의 대립축 그대로다 — **수동 메모리 관리의 위험**이냐, **런타임·일시 정지를 짊어지는 것**이냐.

Rust가 던진 질문은 이 둘 사이의 오래된 트레이드오프 자체를 향했다 — **"GC 없이도, C++만큼 빠르면서, 메모리 안전하고 동시성까지 안전한 언어를 만들 수 있는가?"**\
이 질문에 "그렇다"고 답하기 위한 10년 가까운 실험이 곧 1.0까지의 역사다.

## 주요 변화 (언제·왜)

*(각 절은 「무엇이 있었나 → 무엇이 바뀌었나 → 왜 그렇게 갔나」 순서로 읽으면 된다. 「대가는 무엇인가」 표제는 쓰지 않았다 — 원문이 "대가"라고 적은 문장은 위 「시대적 배경」의 두 곳뿐이고, 그 둘은 그 절의 도식 안에 그대로 두었다.)*

### 1) 개인 프로젝트로 출발 (2006)

Rust는 Mozilla 직원이던 Graydon Hoare가 2006년 자신의 여가 시간에 시작한 개인 프로젝트였다.\
자주 회자되는 일화로, 그가 살던 아파트의 엘리베이터 소프트웨어가 자꾸 고장 나 멈춰 서던 경험이 "왜 우리는 이렇게 잘 깨지는 소프트웨어를 만드는가"라는 문제의식의 계기가 되었다고 한다.\
초기 Rust는 안전성과 견고함을 최우선으로 두되, 당시에는 오늘날 우리가 아는 Rust와 사뭇 다른 — 여러 실험적 기능을 잔뜩 품은 — 모습이었다.

이 시기 컴파일러는 **OCaml로 작성**되어 있었다(약 3.8만 줄).\
2006년부터 2009년까지 Rust는 Mozilla 내부에도 알려지지 않은 채 Hoare 혼자 다듬던, 말 그대로 "선사시대(prehistory)" 프로젝트였다.

> **왜 OCaml이었나**: 새 언어는 처음에는 자기 자신으로 자신을 컴파일할 수 없다(닭과 달걀 문제). 그래서 표현력 좋은 기존 함수형 언어인 OCaml로 첫 컴파일러를 만들어 언어를 부트스트랩한 뒤, 언어가 충분히 자라면 그 언어 자신으로 컴파일러를 다시 작성(self-hosting)하는 길을 택했다.

> **자체 호스팅(self-hosting)** — 어떤 언어의 컴파일러를 그 언어 자신으로 작성해 두는 것.\
> 예: 위 인용이 적은 대로, OCaml로 만든 첫 컴파일러로 언어를 키운 뒤 그 언어로 컴파일러를 다시 쓰는 것이다.

### 2) Mozilla의 후원 (2009)

2009년경 Mozilla 내부의 소수 인원이 이 프로젝트에 관심을 보이기 시작했고, Hoare도 비로소 언어를 공개적으로 이야기하기 시작했다.\
그리고 그해 **Mozilla가 Rust를 공식 후원**하며 프로젝트를 자사 연구 조직(Mozilla Research)으로 끌어들였다.

Mozilla의 동기는 분명했다 — 안전한 차세대 브라우저 엔진을 만들 언어가 필요했다.\
Brendan Eich를 비롯한 경영진은 Rust를 그 토대로 쓸 가능성에 주목했고, Patrick Walton, Niko Matsakis, Felix Klock 등 엔지니어를 투입했다.\
이 후원 덕분에 Rust는 한 사람의 취미를 넘어, 실제 대규모 시스템(훗날의 병렬 브라우저 엔진 프로젝트 Servo)을 겨냥한 진지한 언어로 성장할 자원을 얻었다.

### 3) 자체 호스팅 컴파일러와 첫 공개 릴리스 (2010 ~ 2012)

2009년부터 2012년 사이, 컴파일러는 초기 OCaml 구현에서 **Rust 자신으로 작성되어 LLVM을 백엔드로 삼는 자체 호스팅 컴파일러(rustc)로 이전**되었다.\
LLVM을 코드 생성 백엔드로 채택한 덕에 Rust는 최적화·다중 타깃 지원이라는 무거운 짐을 직접 짊어지지 않고도 네이티브 수준의 성능을 얻을 수 있었다.\
핵심 개념인 **소유권(ownership) 시스템의 골격도 2010년경 잡히기 시작**했다.

2012년 1월 20일, **첫 공개 버전 0.1**이 Windows, Linux, macOS를 대상으로 릴리스되었다.\
이때부터 1.0까지는 안정성을 약속하지 않은, 언어 설계를 공개적으로 실험하고 부수는 시기였다.

### 4) pre-1.0 대격변 — 무엇을 *버렸는가* (2012 ~ 2015)

1.0으로 가는 길은 기능을 더하는 과정이 아니라, 오히려 초기 Rust가 품었던 많은 것을 **덜어내며 핵심을 벼리는** 과정이었다.\
이 시기 Rust의 정체성을 결정한 것은 추가가 아니라 제거다.

이 절의 전·후 대비를 두 칸으로 놓은 것이 맨 앞 「한눈에」의 도식이다 — 도식의 네 행은 아래 불릿 1·2·4·4에서, 1행 오른쪽의 둘째 줄은 불릿 3에서 왔다.

- **가비지 컬렉터(GC) 제거**: 초기 Rust에는 GC가 있었다. 그러나 소유권 시스템이 성숙하면서 GC의 쓸모는 점점 줄었고, 2013년경에는 거의 쓰이지 않다가 결국 제거되었다(0.8 사이클 전후). 이로써 Rust는 "GC 없는 메모리 안전"이라는 정체성을 확정했다.
- **런타임·그린 스레드 제거**: 초기 Rust는 언어에 내장된 경량 그린 스레드(green thread)와 그것을 받쳐 주는 런타임을 갖고 있었다. 이는 Go와 비슷한 모델이었지만, "런타임 없이 C를 대체한다"는 목표와 충돌했다. 1.0 직전 그린 스레드와 무거운 런타임은 표준 라이브러리에서 들어내어 OS 네이티브 스레드 모델로 정리되었다 — Rust 바이너리가 C처럼 가볍게 동작하고, C 코드를 직접 대체할 수 있게 하기 위해서였다.
- **소유권·빌림(borrow) 시스템 정립**: GC가 빠진 자리를 메운 것이 바로 이것이다. 모든 값에는 단 하나의 소유자가 있고, 소유자가 스코프를 벗어나면 값은 자동으로 해제된다. 값은 **빌릴(borrow)** 수 있되, 컴파일러의 **빌림 검사기(borrow checker)** 가 "여러 개의 불변 참조는 허용하되, 가변 참조는 동시에 단 하나만"이라는 규칙을 컴파일 시점에 강제한다. 이 규칙이 use-after-free와 데이터 레이스를 *컴파일 단계에서* 원천 차단한다 — 런타임 비용 0으로.
- **언어 단순화를 위한 추가 제거**: 타입스테이트(typestate), `pure` 키워드, 여러 특수 포인터 타입, 채널(channel) 문법 지원 등도 언어를 단순하게 만들기 위해 이 시기에 함께 제거되었다. 한때 흔하던 sigil 포인터 표기(`@`, `~`)도 정리되어 `Box<T>` 같은 일반 타입으로 흡수되었다.

> **그린 스레드(green thread)** — 언어에 내장되고, 그것을 받쳐 주는 런타임이 굴려 주는 경량 실행 단위.\
> 예: 원문은 1.0 직전 이것을 표준 라이브러리에서 들어내고 "OS 네이티브 스레드 모델로 정리"했다고 적는다.

> **빌림 검사기(borrow checker)** — "여러 개의 불변 참조는 허용하되, 가변 참조는 동시에 단 하나만"이라는 규칙을 강제하는 컴파일러의 검사(원문 정의 그대로).\
> 예: 원문이 이 검사로 막는다고 적은 것은 use-after-free와 데이터 레이스 둘이고, 막는 시점은 원문 표현대로 "컴파일 시점"·"컴파일 단계"다.

> **핵심**: 2012~2015년은 "Rust가 무엇이 *아닌가*"를 정한 시기다. GC도, 무거운 런타임도, 잡다한 특수 문법도 버리고 — 소유권·빌림이라는 단 하나의 메모리 모델 위에 언어를 다시 세웠다.

### 5) Rust 1.0 — 안정성의 약속 (2015년 5월 15일)

2015년 5월 15일, Rust 코어 팀은 **첫 안정 릴리스 1.0**을 발표했다.\
공식 발표문은 이 버전의 의미를 이렇게 못박았다 — "1.0 릴리스는 그동안의 격변(churn)의 끝이다. 이 릴리스는 **안정성에 대한 우리 약속의 공식적인 시작**이다."

1.0이 가져온 것은 새 문법이 아니라 **하위 호환성 보장**이었다.\
이 시점 이후로 깨지는 변경(breaking change)은 원칙적으로 범위 밖이 되었다(컴파일러 버그 같은 사소한 예외만 남겼다).\
즉, 1.0에서 컴파일되던 코드는 이후 버전에서도 계속 컴파일된다는 약속이다.\
이는 라이브러리와 애플리케이션을 안심하고 쌓아 올릴 수 있는 단단한 토대가 되었다.

> **하위 호환성 보장(backward compatibility)** — 새 판을 내놓아도 예전에 쓰던 코드가 그대로 컴파일되는 성질.\
> 예: 원문 문장 그대로 — "1.0에서 컴파일되던 코드는 이후 버전에서도 계속 컴파일된다."

이를 뒷받침하기 위해 Rust는 **6주 주기의 열차(train) 릴리스 모델**을 채택했다 — Firefox나 Chrome처럼 stable / beta / nightly 세 채널을 두고, 정해진 6주마다 다음 칸이 출발한다.\
1.0과 동시에 1.1 베타를 함께 내놓으며 이 리듬을 시작했다.\
새 기능은 nightly에서 실험하고, 안정화가 끝나야만 stable로 흘러드는 구조라, **빠른 개선과 굳건한 안정성을 동시에** 추구할 수 있었다.

거버넌스 역시 1.0과 함께 오픈 모델로 정착했다.\
**RFC(Request for Comments) 프로세스** 를 통해 "Rust에 대한 모든 주요 결정은 공개적으로 작성되고 논의"되며, 영역별 책임을 지는 서브팀(subteam) 체제가 도입되었다.\
창시자 Hoare는 이미 2013년에 프로젝트의 일선에서 물러난 상태였고, Rust는 한 개인이 아니라 커뮤니티가 RFC로 함께 끌어가는 언어가 되어 있었다.

## 영향과 의의

*(이 편의 「남긴 것」에 해당한다 — 아래 문장은 전부 원문 「영향과 의의」 두 문단의 것이다.)*

1.0까지의 9년은 "기능을 쌓아 올린" 역사가 아니라 "정체성을 깎아낸" 역사다.\
GC와 런타임과 특수 문법을 차례로 버리고 남은 **소유권·빌림 모델**은, 메모리 안전과 시스템 수준 성능이라는 오랜 트레이드오프를 컴파일러로 해소한 보기 드문 사례가 되었다.\
"가비지 컬렉터도 런타임도 없이, 저수준 제어와 고수준 안전을 동시에"라는 1.0 발표문의 약속은 이후 Rust가 C/C++의 영역으로 진격하는 모든 행보의 출발점이다.

1.0의 진짜 선물은 특정 기능이 아니라 **신뢰**였다 — 하위 호환 보장과 예측 가능한 6주 릴리스, 그리고 공개 RFC 거버넌스.\
이 세 가지가 갖춰지고 나서야 기업과 개발자들은 Rust 위에 진지하게 투자하기 시작했다.\
1.0은 언어의 완성이 아니라, 언어가 *비로소 믿고 쓸 수 있게 된* 출발선이었다.

## 용어 풀이

본문 안에서 이미 인용 블록으로 푼 말(가비지 컬렉션·데이터 레이스·그린 스레드·빌림 검사기·하위 호환성 보장)은 그 자리에 두고 여기서 되풀이하지 않았다.

- **use-after-free / 이중 해제(double free) / 버퍼 오버플로** — 원문이 C/C++의 "끊임없는 위험"으로 함께 든 메모리 버그들.
- **부트스트랩(bootstrap) / 자체 호스팅(self-hosting)** — 다른 언어로 만든 첫 컴파일러로 새 언어를 띄우는 일 / 그 뒤 그 언어 자신으로 컴파일러를 다시 쓰는 것.
- **LLVM** — 여러 언어의 컴파일러가 공통으로 쓰는 코드 생성·최적화 기반. rustc의 백엔드다.
- **소유권(ownership) / 빌림(borrow)** — 값마다 소유자가 하나이고 소유자가 스코프를 벗어나면 자동 해제되는 규칙 / 소유권을 넘기지 않고 빌려 쓰는 것.
- **타입스테이트(typestate) / sigil 포인터(`@`, `~`)** — 언어 단순화를 위해 pre-1.0에 제거된 초기 기능들.
- **열차(train) 릴리스 모델** — stable / beta / nightly 세 채널을 두고 6주마다 다음 칸이 출발하는 방식(원문 용어).
- **RFC(Request for Comments) 프로세스** — 주요 결정을 공개적으로 작성하고 논의하는 거버넌스 절차.
