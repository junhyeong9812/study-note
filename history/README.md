# history — 기술 변천사 아카이브

각 기술이 **언제·왜 지금 모양이 되었는지**를 다룬다.\
`~/project/*-history` 저장소의 문서를 초보자가 읽을 수 있게 다시 쓴 판이며, 원본 저장소가 정본으로 그대로 남아 있다.

다른 갈래와 무엇이 다른가.

- `cs/`는 **개념이 무엇인가**를 묻는다 — 질문·서머리·정답 3파일로 인출 연습을 한다.
- `history/`는 **왜 그 개념이 그 모양인가**를 묻는다 — 읽는 문서이고 3파일 구조가 아니다.

그래서 `cs/`에서 개념이 안 잡힐 때 여기로 와서 그 개념이 무엇에 대한 반작용이었는지를 보면 된다.

## 99번 — 「그 뒤」

각 원본 저장소가 멈춘 시점부터 **2026-09-20 까지**를 주제마다 한 편씩 더 썼다.\
이 여덟 편은 **재서술이 아니다** — 원본에 없는 내용이라, 문장마다 1차 출처를 달고 검증 패스가 그 URL 을 직접 열어 대조했다(출처 180건).

| 주제 | 원본이 멈춘 자리 | 편 |
|------|------------------|-----|
| database | 2026-05-10 (원본이 인용한 가장 늦은 출처) | [그 뒤](database/99-그-뒤.md) |
| java | Java 26 | [그 뒤](java/99-그-뒤.md) |
| js | 갈래마다 다름 — 언어는 ES2023, 런타임·도구는 2026 초 | [그 뒤](js/99-그-뒤.md) |
| network | 2022-06 (HTTP/3 RFC 9114) | [그 뒤](network/99-그-뒤.md) |
| python | 3.13 (2024-10) · 패키징 2025-04 | [그 뒤](python/99-그-뒤.md) |
| rust | 1.85 / 2024 에디션 (2025-02-20) | [그 뒤](rust/99-그-뒤.md) |

골격이 다른 편들과 다르다 — `원본이 멈춘 자리 → 그 뒤 무슨 일이 있었나 → 원문이 「예정」이라 한 것은 어떻게 됐나 → 아직 안 끝난 것 → 용어 풀이 → 출처`.\
기준일이 박혀 있으므로 시간이 지나면 낡는다. 갱신할 때는 각 편의 「출처」 절을 출발점으로 삼는다.

## 문서 한 편의 골격

```text
한눈에 — 쉽게 말하면      일상 비유로 한 문장 + 단순 그림
        v
시대 배경 — 그전에는 어땠나   무엇이 불편했는지를 그림으로
        v
무엇이 바뀌었나            절마다: 무엇 -> (그림) 전/후 대비 -> 왜 나은가 -> 대가는
        v
왜 그렇게 갔나             남은 선택지와 트레이드오프
        v
남긴 것 — 오늘 우리가 쓰는 것
        v
용어 풀이 / 참고 출처
```

원문의 절 제목은 문자 그대로 살리고, 위 골격의 표제는 그 아래 한 줄로 붙인다.\
그래야 원문에서 찾던 제목을 여기서도 찾을 수 있다.

## 읽을 때 알아 둘 것

- **인용 층과 보충 층이 나뉘어 있다.**\
  연도·인명·논문명·표준번호·RFC·코드블록·표는 **원문 그대로**다.\
  ASCII 도식, 「한눈에」의 비유, 용어 블록의 「예:」, 「용어 풀이」는 **원문에 없는 보충**이며, 각 문서 머리말이 그 사실을 선언한다.
- **전문용어를 없애지 않았다.**\
  대신 처음 나오는 자리 바로 아래에 「정의 + 예」 인용 블록을 달았다.
- **깊이가 필요하면 원본으로 간다.**\
  각 문서 머리말에 원본 경로가 있고, 「참고 출처」는 원문 것을 그대로 옮겼다.

## 어떻게 만들어졌나

작성 워커가 재서술하고, **작성자와 컨텍스트가 분리된 검증 워커**가 원문과 대조한 뒤 수정했다.\
여덟 주제를 그렇게 돌린 결과가 이렇다.

| 주제 | 원문 | 결과 | 인용 층 오류 | 새 층 지적 | S1 |
|------|------|------|--------------|-----------|----|
| database | 1,151줄 | 3,329줄 | **0건** | 26건 | 0 |
| web | 1,424줄 | 4,071줄 | **0건** | 49건 | 1 |
| network | 1,455줄 | 3,829줄 | **0건** | 39건 | 0 |
| js | 1,832줄 | 3,504줄 | **0건** | 47건 | 2 |
| rust | 1,627줄 | 3,133줄 | **0건** | 34건 | 0 |
| python | 1,950줄 | 3,666줄 | **0건** | 36건 | 0 |
| spring | 2,344줄 | 4,110줄 | **0건** | 28건 | 1 |

- **인용 층은 여덟 번 다 오류가 없었다** — 연도·인명·버전·JEP/JSR/RFC 번호·코드블록·표·참고 출처.
- **지적 317건이 전부 재서술자가 새로 만든 층에서 났고**, S1(사실 왜곡) 4건은 모두 「남긴 것」·용어 블록 「예:」·코드 대비 해설에서 났다.
- 그래서 검증은 기계 대조보다 **새로 만든 도식·표·해설만 골라 읽는 패스**에 무게를 둔다.
- **새 층을 적게 만든 주제가 지적도 적게 받았다.** spring·java 후반부는 신규 도식을 0\~3개로 두고 원문 mermaid 전사에 맡겼다.

### 99번 편은 검증 방식이 다르다

대조할 원문이 없으므로 실패가 **「원문과 다르다」에서 「사실이 아니다」로 바뀐다.**\
그래서 원문 대조 자리에 **출처 접지**를 놓았다 — 문장마다 1차 출처를 달고, 검증 패스가 그 URL 을 직접 열어 대조했다.

실측된 실패 모드는 재서술본과 달랐다.

| 유형 | 예 |
|------|-----|
| **인용부호 안에서 원문을 바꿔 씀**(가장 많음) | RFC 에 없는 문장을 인용문으로 적음 · 떨어져 있는 두 표기를 「/」로 이어 붙임 · 복수형·부사 한 단어가 빠짐 |
| **근거 없는 부정 주장** | 「A 는 B 를 지목하지 않았다」(실제로는 두 곳에서 지목) · 「\~뿐이다」(확인하지 않은 후보가 있었음) |
| **수치에 다른 표의 조건을 붙임** | 한 공지에 벤치마크 절이 여럿인데 조건 줄을 섞어 씀 |
| **시리즈 대조 누락** | CVE 번호가 한 칸 밀려 CVSS 5.3 과 10.0 이 뒤바뀌고 최상위 항목이 빠짐 |
| **조사 창이 문서 안에서 흔들림** | 시작 날짜를 두 값으로 씀 |

그래서 이 여덟 편은 **영문 인용을 전수로 원문 substring 대조**하고, **부정 주장마다 「어디를 열어 무엇을 못 찾았는지」를 표로** 남긴다.\
기준일(2026-09-20)이 박혀 있어 시간이 지나면 낡는다.
