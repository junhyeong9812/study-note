# JDK 1.1 (1997년 2월)

> 원본: `~/project/java-history/java/jdk-1.1.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-20).\
> 연도·버전·클래스/패키지 이름·코드블록 6개·「릴리스 정보」와 「그 외 변경 / API 추가」의 목록은 원문 그대로다.\
> ASCII 도식 1개와 「한눈에」의 창구 비유·대응표, 용어 블록의 「예:」, 「용어 풀이」, 다른 편을 가리키는 교차 주 2개는 원문에 없는 보충이다.

## 한눈에 — 쉽게 말하면

원문이 제목 아래에 적은 한 줄 요약은 이것이다.

> 자바를 "장난감 언어"에서 본격적인 엔터프라이즈 개발 플랫폼으로 끌어올린 버전. 내부 클래스, JDBC, RMI, 리플렉션, JavaBeans 등 오늘날까지 쓰이는 핵심 인프라가 대거 등장했다.

이 편의 이벤트 모델 개편을 하나의 비유로 읽으면 **민원이 들어올 때마다 위층으로 계속 올려 보내던 것을, 창구마다 담당자를 미리 등록해 두는 것으로 바꾼 일**이다.\
위로 올려 보내는 방식에서는 민원이 어디까지 올라가 누가 처리할지가 층 구조에 달려 있다.\
창구마다 담당자를 등록해 두면 그 창구의 민원은 등록된 담당자가 받는다.

**1.1의 위임 이벤트 모델도 똑같은 구조다** — 원문 자신이 「시대적 배경」에서 1.0의 방식을 "이벤트를 컴포넌트 계층 위로 전파시키는 방식"이라 적고, 「새로운 AWT 이벤트 모델 (위임 이벤트 모델)」에서 1.1의 방식을 "리스너(listener)를 컴포넌트에 "등록"하는 위임(delegation) 모델"이라 적는다.

본문 흐름에 쓰는 비유는 이 창구 하나뿐이다 — 용어 블록의 정의에 쓰는 낱말은 비유가 아니라 그 용어의 풀이다.

| 비유 | 실체 |
|---|---|
| 민원을 받는 창구 | 컴포넌트 — 원문이 든 예가 `button` |
| 위층으로 계속 올려 보내던 방식 | 원문 표현으로 1.0의 "이벤트를 컴포넌트 계층 위로 전파시키는 방식" |
| 창구마다 담당자를 미리 등록해 두는 것 | 원문 표현으로 "리스너(listener)를 컴포넌트에 "등록"하는 위임(delegation) 모델" |

초보자가 가장 자주 하는 오해부터 짚어 두면 이렇다.

- **익명 클래스는 람다가 아니다.**\
  원문이 코드 주석에 직접 적어 둔 그대로다 — "당시 문법은 익명 내부 클래스; 람다는 Java 8부터".
- **리플렉션이 1.1에서 지금 모습으로 완성된 것은 아니다.**\
  원문은 "(1.1에서는 주로 인트로스펙션 위주)"라고 범위를 한정해 적는다.
- **이 편의 코드에는 제네릭도 for-each도 없다.**\
  원문이 리플렉션 코드 주석에 적어 둔 그대로다 — "제네릭(Class<?>)은 J2SE 5.0부터 — 1.1에선 raw type", "for-each도 5.0부터".\
  *(교차 주: 같은 시리즈의 `java-5` 편이 실제로 제네릭(JSR 14)과 향상된 for문(JSR 201)을 그 버전의 기능으로 적는다 — 두 편의 서술이 맞물린다.)*

## 릴리스 정보
- 정식 출시일: 1997년 2월 (위키피디아는 1997-02-19, Oracle·javaalmanac 릴리스 표는 1997-02-18로 출처에 따라 하루 차이가 난다) — 흔히 인용되는 1997-03-28은 JDK 1.1이 아니라 후속 패치 릴리스 JDK 1.1.1의 날짜다
- 개발 주체: Sun Microsystems
- 공식 명칭: JDK 1.1
- 코드네임: 없음

첫 불릿은 출처가 갈리는 날짜를 원문이 스스로 밝혀 둔 자리다 — 어느 하나로 고르지 않고 양쪽을 적고, 자주 잘못 인용되는 날짜가 무엇의 날짜인지까지 적는다.

## 시대적 배경

JDK 1.0이 "자바가 가능하다"를 증명했다면, JDK 1.1은 "자바로 실제 시스템을 만들 수 있다"를 목표로 했다.\
1.0의 AWT 이벤트 모델은 비효율적이었고(이벤트를 컴포넌트 계층 위로 전파시키는 방식), 데이터베이스 연동·분산 처리·재사용 가능한 컴포넌트 모델 같은 기업용 기능이 부족했다.\
JDK 1.1은 이 공백들을 한꺼번에 메웠다.

*(원문이 「시대적 배경」에서 부족·비효율로 적은 자리는 위 둘째 줄이다 — "1.0의 AWT 이벤트 모델은 비효율적이었고"와 "기업용 기능이 부족했다". 이는 1.1이 치른 대가가 아니라 1.1이 나온 동기다.)*

> **엔터프라이즈(enterprise)** — 기업이 실제 업무를 돌리는 데 쓰는 규모와 성격의 시스템.\
> 예: 원문이 이 자리에서 부족하다고 든 "기업용 기능"이 데이터베이스 연동·분산 처리·재사용 가능한 컴포넌트 모델이다.

## 주요 추가 기능

### 내부 클래스(Inner Classes)

- 클래스 안에 클래스를 정의할 수 있게 되었다. 익명 클래스(anonymous class)도 이때 도입되어, 새 AWT 이벤트 모델의 리스너 구현을 간결하게 해주었다.

> **내부 클래스(inner class)** — 클래스 안에 정의한 클래스.\
> 예: 원문이 이 자리에서 적는 것이 "클래스 안에 클래스를 정의할 수 있게 되었다"이다.

> **익명 클래스(anonymous class)** — 이름을 붙이지 않고, 쓰는 자리에서 바로 만들어 쓰는 클래스.\
> 예: 아래 코드의 `new ActionListener() { … }`가 그것이고(원문이 그 줄에 붙인 주석이 "익명 내부 클래스"다), 원문은 이 익명 클래스의 쓰임을 "새 AWT 이벤트 모델의 리스너 구현을 간결하게 해주었다"로 든다.

```java
button.addActionListener(new ActionListener() {   // 익명 내부 클래스
    public void actionPerformed(ActionEvent e) {
        System.out.println("버튼 클릭됨");
    }
});
```

### 새로운 AWT 이벤트 모델 (위임 이벤트 모델)

- 1.0의 상속 기반 이벤트 처리를 버리고, 리스너(listener)를 컴포넌트에 "등록"하는 위임(delegation) 모델로 전면 개편했다.
- 이 모델은 이후 Swing을 포함한 모든 자바 GUI 이벤트 처리의 표준이 되었다.

아래 코드블록이 원문 주석으로 1.0과 1.1을 나란히 적어 두었다. 그 두 줄을 두 칸에 옮기면 이렇다.

```text
왼쪽 칸 = 원문 주석의 "1.0:" 줄            오른쪽 칸 = "1.1:" 주석 아래 이어지는 코드
+---------------------------------+       +---------------------------------+
| public boolean action(          |       | button.addActionListener(       |
|     Event e, Object arg) { ... }|       |     new ActionListener() { ... })|
|                                 |       |                                 |
| 원문 주석: "(오버라이드 방식)"   |       | 원문 주석: "리스너 등록 방식"    |
+---------------------------------+       +---------------------------------+
  원문 본문: "1.0의 상속 기반           원문 본문: "리스너(listener)를 컴포넌트에
  이벤트 처리를 버리고"                  "등록"하는 위임(delegation) 모델"
```

왼쪽 칸은 원문이 코드블록 첫 주석에 `1.0:`으로 적어 둔 줄이고, 오른쪽 칸은 `1.1:` 주석 바로 아래 이어지는 실제 코드다 — 원문이 한 블록 안에 위아래로 짝지어 적어 둔 것을 좌우로 옮겼다.\
각 칸 안의 "원문 주석"은 그 두 주석에서, 칸 아래 문장은 같은 절 본문의 첫 불릿에서 뽑았다.

> **리스너(listener)** — "이런 일이 일어나면 나를 불러 달라"고 미리 등록해 두는 객체.\
> 예: 위 코드의 `ActionListener`가 그것이고, 원문이 이 등록 방식을 부르는 이름이 "위임(delegation) 모델"이다.

```java
// 1.0: public boolean action(Event e, Object arg) { ... }  (오버라이드 방식)
// 1.1: 리스너 등록 방식 (당시 문법은 익명 내부 클래스; 람다는 Java 8부터)
button.addActionListener(new ActionListener() {
    public void actionPerformed(ActionEvent e) { /* ... */ }
});
```

### JavaBeans

- 재사용 가능한 소프트웨어 컴포넌트 모델. getter/setter 명명 규약, 이벤트, 인트로스펙션(introspection)을 기반으로 한다.
- 비주얼 개발 도구에서 컴포넌트를 드래그&드롭으로 조립하는 시대를 열었고, 이후 자바 생태계 전반의 "POJO + 프로퍼티" 관례의 뿌리가 되었다.

> **인트로스펙션(introspection)** — 객체가 어떤 프로퍼티·메서드를 가졌는지 밖에서 들여다보는 것.\
> 예: 원문은 이것을 JavaBeans가 기반으로 삼는 셋(getter/setter 명명 규약, 이벤트, 인트로스펙션) 중 하나로 든다.

```java
public class Person {
    private String name;
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
}
```

위 코드의 `getName`/`setName`이 원문이 말한 "getter/setter 명명 규약"이다.

### JDBC (Java Database Connectivity)

- 데이터베이스 접속을 위한 표준 API. 드라이버를 통해 어떤 DB든 동일한 인터페이스로 다룰 수 있게 했다.

> **드라이버(driver)** — 특정 데이터베이스 제품에 맞춰 실제 통신을 담당하는 부품. 표준 API 뒤에 갈아 끼운다.\
> 예: 원문 표현으로 "드라이버를 통해 어떤 DB든 동일한 인터페이스로 다룰 수 있게 했다".

```java
Connection con = DriverManager.getConnection(url, user, pwd);
Statement st = con.createStatement();
ResultSet rs = st.executeQuery("SELECT name FROM users");
while (rs.next()) {
    System.out.println(rs.getString("name"));
}
```

*(교차 주: 이 JDBC가 뒤에서 어떻게 다듬어지는지는 `java-6` 편이 적는다 — 그 편은 "JDBC 4.0 (JSR 221)"에서 "드라이버 자동 로딩(`Class.forName` 불필요)"을 든다.)*

### RMI (Remote Method Invocation)와 객체 직렬화

- 원격 JVM에 있는 객체의 메서드를 마치 로컬 객체처럼 호출하는 분산 컴퓨팅 기능.
- 이를 뒷받침하기 위해 객체 직렬화(`Serializable`)가 함께 도입되었다.

> **직렬화(serialization)** — 메모리 안의 객체를 줄줄이 이어진 바이트로 바꿔, 저장하거나 보낼 수 있게 하는 것.\
> 예: 원문은 이것이 RMI를 "뒷받침하기 위해" 함께 도입됐다고 적고, 그 표시로 `Serializable`을 든다.

```java
public interface Hello extends java.rmi.Remote {
    String sayHello() throws java.rmi.RemoteException;
}
```

### 리플렉션(Reflection)

- 실행 중에 클래스의 필드·메서드·생성자 정보를 조회하는 기능(1.1에서는 주로 인트로스펙션 위주). JavaBeans, 직렬화, 후일의 프레임워크(Spring 등)의 근간이 되었다.

> **리플렉션(reflection)** — 원문 표현 그대로 "실행 중에 클래스의 필드·메서드·생성자 정보를 조회하는 기능". 1.1에서의 범위는 원문이 "주로 인트로스펙션 위주"로 한정해 적는다.\
> 예: 아래 코드의 `c.getMethods()`가 그 조회다.

```java
Class c = obj.getClass();   // 제네릭(Class<?>)은 J2SE 5.0부터 — 1.1에선 raw type
java.lang.reflect.Method[] methods = c.getMethods();
for (int i = 0; i < methods.length; i++) {   // for-each도 5.0부터
    System.out.println(methods[i].getName());
}
```

위 코드의 두 주석이 이 시점의 문법 한계를 그대로 알려 준다 — `Class`에 타입 인자가 붙지 않은 것이 첫 주석이 말하는 raw type이고, 둘째 주석 "for-each도 5.0부터"가 `for (int i = 0; …)` 형태의 반복문을 쓴 이유를 적는다.

### 국제화(i18n)와 유니코드

- `Locale`, `ResourceBundle`, `java.text` 패키지 도입으로 다국어 애플리케이션 작성이 가능해졌다. 유니코드 지원이 강화되었다.

> **국제화(i18n)** — 프로그램을 여러 나라 말·표기 관습에 맞춰 쓸 수 있게 만드는 일. `i`와 `n` 사이 글자가 18개라 i18n이라 줄여 쓴다.\
> 예: 원문이 이 자리에서 든 수단이 `Locale`, `ResourceBundle`, `java.text` 패키지다.

## 그 외 변경 / API 추가
- JAR(Java ARchive) 파일 포맷 도입 — 여러 클래스와 리소스를 하나로 묶어 배포.
- Windows 환경에서의 JIT(Just-In-Time) 컴파일 지원으로 실행 성능 향상.
- `java.math`(BigInteger, BigDecimal) 추가.

둘째 불릿의 범위는 원문이 "Windows 환경에서의"로 한정해 적어 둔 그대로다.

## 영향과 의의

*(이 편의 「남긴 것」에 해당한다 — 아래 세 불릿은 원문 한 문단을 문장 단위로 끊은 것이다.)*

- JDK 1.1은 자바의 "엔터프라이즈 시대"를 본격적으로 연 버전이다.
- JDBC·RMI·JavaBeans·리플렉션은 이후 J2EE와 수많은 프레임워크의 기반이 되었고, 위임 이벤트 모델은 자바 GUI의 표준으로 굳어졌다.
- 이 시점부터 자바는 단순 웹 애플릿 언어를 넘어 서버·기업용 시스템 언어로 자리잡기 시작했다.

## 용어 풀이

- **엔터프라이즈(enterprise)** — 기업이 실제 업무를 돌리는 데 쓰는 규모와 성격의 시스템. 원문이 1.0에 부족했다고 든 "기업용 기능"이 데이터베이스 연동·분산 처리·재사용 가능한 컴포넌트 모델이다.
- **내부 클래스(inner class)** — 클래스 안에 정의한 클래스. 원문은 이 편에서 "클래스 안에 클래스를 정의할 수 있게 되었다"고 적는다.
- **익명 클래스(anonymous class)** — 이름을 붙이지 않고 쓰는 자리에서 바로 만들어 쓰는 클래스. 원문이 든 쓰임은 "새 AWT 이벤트 모델의 리스너 구현을 간결하게 해주었다"이고, 원문 주석은 이를 "익명 내부 클래스"라 적으며 람다는 Java 8부터라고 덧붙인다.
- **리스너(listener)** — "이런 일이 일어나면 나를 불러 달라"고 미리 등록해 두는 객체. 원문이 이 등록 방식을 부르는 이름이 "위임(delegation) 모델"이다.
- **위임(delegation) 이벤트 모델** — 이벤트를 위로 전파시키는 대신, 컴포넌트에 등록된 리스너에게 맡기는 방식. 원문은 이 모델이 "이후 Swing을 포함한 모든 자바 GUI 이벤트 처리의 표준이 되었다"고 적는다.
- **JavaBeans** — 원문 표현 그대로 "재사용 가능한 소프트웨어 컴포넌트 모델". getter/setter 명명 규약, 이벤트, 인트로스펙션을 기반으로 한다.
- **인트로스펙션(introspection)** — 객체가 어떤 프로퍼티·메서드를 가졌는지 밖에서 들여다보는 것. 원문은 JavaBeans가 기반으로 삼는 셋 중 하나로 든다.
- **드라이버(driver)** — 특정 데이터베이스 제품에 맞춰 실제 통신을 담당하는 부품. 원문은 "드라이버를 통해 어떤 DB든 동일한 인터페이스로 다룰 수 있게 했다"고 적는다.
- **RMI(Remote Method Invocation)** — 원문 표현 그대로 "원격 JVM에 있는 객체의 메서드를 마치 로컬 객체처럼 호출하는 분산 컴퓨팅 기능".
- **직렬화(serialization)** — 메모리 안의 객체를 줄줄이 이어진 바이트로 바꿔 저장하거나 보낼 수 있게 하는 것. 원문은 RMI를 뒷받침하기 위해 `Serializable`과 함께 도입됐다고 적는다.
- **리플렉션(reflection)** — 원문 표현 그대로 "실행 중에 클래스의 필드·메서드·생성자 정보를 조회하는 기능". 1.1에서의 범위는 원문이 "주로 인트로스펙션 위주"로 한정해 적는다.
- **raw type** — 타입 인자를 붙이지 않은 제네릭 타입. 원문 주석은 1.1의 `Class`가 그 상태라고 적는다.
- **국제화(i18n)** — 프로그램을 여러 나라 말·표기 관습에 맞춰 쓸 수 있게 만드는 일. 원문이 든 수단이 `Locale`, `ResourceBundle`, `java.text` 패키지다.
- **JAR(Java ARchive)** — 원문 표현 그대로 "여러 클래스와 리소스를 하나로 묶어 배포"하는 파일 포맷.
- **JIT(Just-In-Time) 컴파일** — 같은 시리즈 `jdk-1.2` 편이 "바이트코드를 실행 시점에 네이티브 코드로 변환"이라 적는 방식. 1.1에서의 지원 범위를 원문은 "Windows 환경에서의"로 한정해 적는다.
