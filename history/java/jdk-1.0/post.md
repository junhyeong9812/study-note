# JDK 1.0 (1996년 1월)

> 원본: `~/project/java-history/java/jdk-1.0.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-20).\
> 연도·버전·패키지/클래스 이름·코드블록 3개·「릴리스 정보」와 「그 외 변경 / API 추가」의 목록은 원문 그대로다.\
> ASCII 도식 1개와 「한눈에」의 통역 비유·대응표, 용어 블록의 「예:」, 「용어 풀이」, 다른 편을 가리키는 교차 주 3개는 원문에 없는 보충이다.

## 한눈에 — 쉽게 말하면

원문이 제목 아래에 적은 한 줄 요약은 이것이다.

> 자바의 최초 정식 릴리스. "한 번 작성하면 어디서나 실행된다(Write Once, Run Anywhere)"는 비전을 처음으로 세상에 내놓은 버전이다.

이 편을 하나의 비유로 읽으면 **원고를 나라마다 다시 쓰는 대신, 중간 언어로 한 부만 적어 두고 나라마다 통역사를 한 명씩 두는 일**이다.\
원고를 나라별로 따로 쓰면 원고가 여러 벌이 되지만, 중간 언어로 한 부만 적어 두면 원고는 한 부인 채로 어느 나라에서든 같은 내용이 전달된다.

**JDK 1.0이 세운 모델도 똑같은 구조다** — 원문 자신이 「시대적 배경」에서 이렇게 적는다: "소스를 바이트코드로 컴파일하고 각 운영체제에 맞는 JVM(자바 가상 머신)이 이를 실행함으로써, 윈도우/맥/유닉스를 가리지 않고 같은 프로그램이 돌아간다".

본문 흐름에 쓰는 비유는 이 통역 하나뿐이다 — 용어 블록의 정의에 쓰는 낱말은 비유가 아니라 그 용어의 풀이다.

| 비유 | 실체 |
|---|---|
| 내가 쓴 원고 | 소스(`.java`) |
| 중간 언어로 옮겨 적어 둔 한 부 | 바이트코드(`.class`) |
| 나라마다 한 명씩 둔 통역사 | 원문 표현으로 "각 운영체제에 맞는 JVM(자바 가상 머신)" |
| 나라를 가리지 않고 같은 내용이 전달됨 | 원문 표현으로 "윈도우/맥/유닉스를 가리지 않고 같은 프로그램이 돌아간다" |

초보자가 가장 자주 하는 오해부터 짚어 두면 이렇다.

- **이 편이 자랑하는 것은 "기능"이 아니다.**\
  원문이 「영향과 의의」에서 직접 적는다 — "이 버전은 기능보다도 "방향성"을 제시했다는 점에서 역사적 의의가 크다".
- **애플릿과 자바는 같은 말이 아니다.**\
  원문은 애플릿을 "웹 브라우저 안에서 실행되는 자바 프로그램"이라 적고, "JDK 1.0을 대중에게 각인시킨 대표 기능"으로 든다 — 자바 전체가 아니라 그 안의 한 기능이다.
- **원문이 이 편에서 적은 실행 방식은 "해석 실행"까지다.**\
  원문 표현은 "JVM이 이를 해석 실행하는 모델을 확립했다"이다.\
  *(교차 주: 이 실행 방식이 계속 그대로인 것은 아니다 — 같은 시리즈의 `jdk-1.2` 편이 "JIT(Just-In-Time) 컴파일러가 기본 포함"을, `jdk-1.3` 편이 HotSpot JVM의 기본 탑재를 적는다.)*

## 릴리스 정보
- 정식 출시일: 1996년 1월 23일
- 개발 주체: Sun Microsystems
- 공식 명칭: JDK 1.0 (안정판은 JDK 1.0.2)
- 코드네임: 통상 Oak로 기록됨 (정확히는 자바의 전신 언어/프로젝트 이름으로, 1.0의 공식 릴리스 코드네임이라기보다 비공식적으로 Oak라 불린다)

## 시대적 배경

1990년대 중반은 웹 브라우저가 막 대중화되던 시기였다.\
당시 웹은 정적인 HTML 문서 중심이었고, 브라우저 안에서 동적인 프로그램을 실행할 방법이 마땅치 않았다.\
Sun Microsystems는 원래 가전기기용 임베디드 언어(Oak 프로젝트)로 출발했던 기술을 인터넷 시대에 맞게 재정비하여 "자바"로 발표했다.

> **임베디드(embedded)** — 컴퓨터 자체가 아니라 다른 기기 안에 들어가 그 기기를 움직이는 소프트웨어.\
> 예: 원문이 이 자리에서 든 출발점이 "가전기기용 임베디드 언어(Oak 프로젝트)"다.

JDK 1.0의 핵심 메시지는 플랫폼 독립성이었다.\
소스를 바이트코드로 컴파일하고 각 운영체제에 맞는 JVM(자바 가상 머신)이 이를 실행함으로써, 윈도우/맥/유닉스를 가리지 않고 같은 프로그램이 돌아간다는 점이 당시로서는 혁신이었다.\
특히 Netscape Navigator 브라우저가 자바 애플릿을 지원하면서 자바는 급속히 주목받았다.

> **플랫폼 독립성** — 어느 운영체제에서 돌리든 같은 프로그램이 같이 돌아가는 성질.\
> 예: 원문이 이 자리에서 든 범위가 "윈도우/맥/유닉스를 가리지 않고"다.

## 주요 추가 기능

### 자바 언어와 가상 머신(JVM)

- 객체지향 언어의 기본 구조(클래스, 상속, 인터페이스, 예외 처리)와 자동 메모리 관리(가비지 컬렉션)를 갖춘 최초 버전이다.
- 소스(`.java`)를 바이트코드(`.class`)로 컴파일하고, JVM이 이를 해석 실행하는 모델을 확립했다.

위 둘째 불릿의 두 단계를 두 칸에 나눠 놓으면 이렇다.

```text
왼쪽 칸 = 개발자 손에서 만들어지는 것      오른쪽 칸 = 그것을 받아 돌리는 쪽
+--------------------------------+        +--------------------------------+
|  소스        `.java`           |        |  윈도우/맥/유닉스 각각의 JVM   |
|     (컴파일)                   |        |                                |
|  바이트코드  `.class`          |        |                                |
+--------------------------------+        +--------------------------------+
```

왼쪽 칸은 원문의 "소스(`.java`)를 바이트코드(`.class`)로 컴파일하고"를, 오른쪽 칸은 「시대적 배경」의 "각 운영체제에 맞는 JVM(자바 가상 머신)이 이를 실행"을 옮긴 것이다.\
오른쪽 칸은 원문이 든 "윈도우/맥/유닉스" 셋을 한 줄로 적은 것이다 — 원문은 이 셋을 왼쪽 칸의 단계와 한 줄씩 짝지어 적지 않으므로, 같은 행에 놓아 짝으로 읽히지 않게 한 줄로 두었다.

> **바이트코드(bytecode)** — 사람이 쓴 소스도 아니고 특정 CPU의 기계어도 아닌, 그 중간의 형식.\
> 예: 원문이 이 자리에서 든 것이 확장자 `.class` 파일이다.

> **JVM(자바 가상 머신)** — 바이트코드를 받아 실제로 돌려 주는 프로그램. 운영체제마다 그 운영체제용이 따로 있다.\
> 예: 원문 표현으로 "JVM이 이를 해석 실행하는 모델"이 이 편에서 확립됐다.

> **가비지 컬렉션(garbage collection)** — 다 쓴 메모리를 개발자가 직접 돌려놓지 않아도 되게 해 주는 자동 메모리 관리.\
> 예: 원문은 이 자리에서 "자동 메모리 관리(가비지 컬렉션)"라고 이름만 들고, 언제 어떻게 회수하는지는 적지 않는다.

```java
// 최초의 전형적인 자바 프로그램
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

### AWT (Abstract Window Toolkit)

- 최초의 GUI 라이브러리. 버튼, 텍스트필드, 레이아웃 등 기본 컴포넌트를 제공했다.
- "피어(peer)" 방식으로 각 OS의 네이티브 위젯을 그대로 사용했기 때문에, 플랫폼마다 모양과 동작이 조금씩 달라지는 한계가 있었다(이른바 "최소 공통 분모" 문제).

*(원문이 이 편에서 비용·한계로 적은 문장은 위 둘째 불릿의 "플랫폼마다 모양과 동작이 조금씩 달라지는 한계가 있었다"와, 「영향과 의의」의 "AWT는 무겁고 일관성이 부족했으며 애플릿은 후일 보안과 성능 문제로 쇠퇴했지만"이다.)*

> **GUI(그래픽 사용자 인터페이스)** — 글자 명령이 아니라 창·버튼 같은 그림 요소로 다루는 화면.\
> 예: 원문이 이 자리에서 든 기본 컴포넌트가 "버튼, 텍스트필드, 레이아웃"이다.

> **피어(peer) 방식** — 자바가 화면 요소를 직접 그리지 않고, 그 운영체제가 원래 가진 네이티브 위젯을 그대로 빌려 쓰는 방식.\
> 예: 원문 표현으로 "각 OS의 네이티브 위젯을 그대로 사용했기 때문에, 플랫폼마다 모양과 동작이 조금씩 달라지는 한계가 있었다".

> **"최소 공통 분모" 문제** — 운영체제마다 가진 것이 다르니, 어디에나 있는 것만 골라 쓸 수밖에 없어지는 상황.\
> 예: 원문은 위 피어 방식의 한계에 이 이름을 붙인다.

```java
import java.awt.*;

public class MyFrame extends Frame {
    public MyFrame() {
        setTitle("AWT 예제");
        add(new Button("클릭"));
        resize(200, 100);  // JDK 1.0에는 setSize/setVisible이 없다
        show();
    }
    public static void main(String[] args) {
        new MyFrame();
    }
}
```

### 애플릿(Applet)

- 웹 브라우저 안에서 실행되는 자바 프로그램. JDK 1.0을 대중에게 각인시킨 대표 기능이다.
- `java.applet.Applet`을 상속하고 `paint()` 등을 구현하여, HTML의 `<applet>` 태그로 페이지에 삽입했다.

```java
import java.applet.Applet;
import java.awt.Graphics;

public class HelloApplet extends Applet {
    public void paint(Graphics g) {
        g.drawString("Hello from Applet!", 20, 20);
    }
}
```

위 코드가 원문 둘째 불릿의 두 항을 그대로 보여 준다 — `extends Applet`이 "`java.applet.Applet`을 상속"이고, `public void paint(Graphics g)`가 "`paint()` 등을 구현"이다.

*(교차 주: 이 애플릿이 어디서 끝나는지는 뒤의 편이 적는다 — `java-17` 편은 "JEP 398"로 `java.applet.Applet`을 "제거 예정으로 표시"했다고 적고, `java-26` 편은 "JEP 504"로 "완전히 제거"했다고 적는다.)*

## 그 외 변경 / API 추가
- 초기 릴리스는 8개 패키지로 구성되었다: `java.applet`, `java.awt`, `java.awt.image`, `java.awt.peer`, `java.io`, `java.lang`, `java.net`, `java.util`.
- `java.io`: 스트림 기반 입출력.
- `java.net`: 소켓, URL 등 네트워킹.
- `java.util`: `Vector`, `Hashtable`, `Enumeration` 등 초기 자료구조(아직 Collections Framework 이전).

*(교차 주: 넷째 불릿의 괄호가 미리 알려 주는 대로, 여기 있는 `Vector`·`Hashtable`은 뒤의 `jdk-1.2` 편에서 "기존의 산발적인 `Vector`/`Hashtable`을 일관된 체계로 대체"한다고 적히는 그 대상이다.)*

## 영향과 의의

*(이 편의 「남긴 것」에 해당한다 — 아래 세 불릿은 원문 한 문단을 문장 단위로 끊은 것이다.)*

- JDK 1.0은 "플랫폼 독립적 실행"이라는 개념을 산업 표준급으로 끌어올렸다.
- 비록 AWT는 무겁고 일관성이 부족했으며 애플릿은 후일 보안과 성능 문제로 쇠퇴했지만, 바이트코드 + JVM 모델은 이후 30년 가까이 이어지는 자바 생태계의 토대가 되었다.
- 이 버전은 기능보다도 "방향성"을 제시했다는 점에서 역사적 의의가 크다.

## 용어 풀이

- **임베디드(embedded)** — 컴퓨터 자체가 아니라 다른 기기 안에 들어가 그 기기를 움직이는 소프트웨어. 원문이 자바의 출발점으로 든 것이 "가전기기용 임베디드 언어(Oak 프로젝트)"다.
- **플랫폼 독립성** — 어느 운영체제에서 돌리든 같은 프로그램이 같이 돌아가는 성질. 원문이 든 범위는 "윈도우/맥/유닉스를 가리지 않고"다.
- **바이트코드(bytecode)** — 사람이 쓴 소스도 아니고 특정 CPU의 기계어도 아닌, 그 중간의 형식. 원문이 든 것이 `.class` 파일이다.
- **JVM(자바 가상 머신)** — 바이트코드를 받아 실제로 돌려 주는 프로그램. 운영체제마다 그 운영체제용이 따로 있다. 원문은 이 편의 실행 방식을 "해석 실행"이라 적는다.
- **가비지 컬렉션(garbage collection)** — 다 쓴 메모리를 개발자가 직접 돌려놓지 않아도 되게 해 주는 자동 메모리 관리. 원문은 이 편에서 이름만 들고, 언제 어떻게 회수하는지는 적지 않는다.
- **GUI(그래픽 사용자 인터페이스)** — 글자 명령이 아니라 창·버튼 같은 그림 요소로 다루는 화면. 원문이 든 AWT의 기본 컴포넌트가 "버튼, 텍스트필드, 레이아웃"이다.
- **피어(peer) 방식** — 자바가 화면 요소를 직접 그리지 않고, 그 운영체제가 원래 가진 네이티브 위젯을 그대로 빌려 쓰는 방식. 원문은 그 결과로 "플랫폼마다 모양과 동작이 조금씩 달라지는 한계가 있었다"고 적는다.
- **"최소 공통 분모" 문제** — 운영체제마다 가진 것이 다르니 어디에나 있는 것만 골라 쓸 수밖에 없어지는 상황. 원문이 피어 방식의 한계에 붙인 이름이다.
- **애플릿(Applet)** — 원문 표현 그대로 "웹 브라우저 안에서 실행되는 자바 프로그램". `java.applet.Applet`을 상속하고 HTML의 `<applet>` 태그로 페이지에 삽입했다.
