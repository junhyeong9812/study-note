# 웹의 탄생 (1989~1999)

> 원본: `~/project/web-history/01-웹-탄생-HTML.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-18).\
> 연도·인명·논문명·표준번호·코드는 원문 그대로다.\
> ASCII 도식 7개와 「한눈에」의 비유, 용어 블록의 「예:」, 「용어 풀이」는 원문에 없는 보충이다.

## 한눈에 — 쉽게 말하면

> 인터넷이라는 물리적 네트워크 위에 "하이퍼텍스트"라는 발상을 얹어, 누구나 문서를 링크로 연결하고 따라갈 수 있게 만든 시대다. 한 사람의 사내 제안서에서 시작해 10년 만에 전 세계의 정보 공유 방식을 바꿔 놓았다.

**웹 = 문서마다 "주소"를 붙이고, 문서 안에 다른 문서의 주소를 적어 둘 수 있게 만든 것.**

- 종이 백과사전을 떠올려 보자.\
  "자세한 것은 3권 412쪽을 보라"라고 적혀 있으면, 나는 책장에서 3권을 꺼내 412쪽을 직접 펴야 한다.
- 웹은 **그 "412쪽을 편다"를 대신 해 주는 장치**다.\
  적혀 있는 곳을 누르면 그 문서가 곧바로 화면에 나타난다.
- 놀라운 점은 그 3권이 **내 책장에 없어도 된다**는 것이다.\
  지구 반대편 컴퓨터에 있어도, 주소만 적혀 있으면 따라갈 수 있다.
- 이것을 가능하게 한 부품은 딱 셋이다 — **URL**(어디), **HTTP**(어떻게 가져오나), **HTML**(무엇으로 표현하나).

그 셋이 링크 한 줄 안에서 어떻게 나뉘는지를 그림으로 보면 이렇다.\
**[보충]** — URL을 scheme·host·path로 쪼개 보는 것은 원문에 없는 세부다.

```text
브라우저 주소창에 넣는 한 줄

    http://example.com/WhatIs.html
    ^^^^   ^^^^^^^^^^^ ^^^^^^^^^^^
     |          |           |
     |          |           +-- 그 컴퓨터 안의 어느 문서인가
     |          +-- 어느 컴퓨터에 있는가
     +-- 어떤 약속으로 가져오는가

   위의 한 줄 전체  = URL   (문서의 주소)
   가져오는 절차    = HTTP  (주고받는 약속)
   받아온 문서 내용 = HTML  (제목, 문단, 링크를 표시하는 언어)
```

이 세 부품이 **똑같은 구조로** 오늘도 그대로 돌아간다.\
지금 쇼핑몰에서 상품을 누르는 것도, 30년 전 CERN에서 연구 문서를 누르던 것도 부품 구성이 같다.

## 시기 정보

시기 정보를 한 줄씩 정리하면 이렇다.

- 출발점: 1989년 3월 12일, CERN(유럽입자물리연구소) 내부 제안서
- 창시자: 팀 버너스리(Tim Berners-Lee), 영국 출신 컴퓨터 과학자
- 핵심 산물: URL · HTTP · HTML 3대 요소와 최초의 브라우저·웹 서버
- 공개: 1991년 외부 공개, 1993년 CERN의 로열티 무료(royalty-free) 선언

> **하이퍼텍스트(hypertext)** — 문서의 한 지점에서 다른 문서로 "가리켜-누르기"로 건너뛰는 개념. 1960년대에 등장했다.\
> 예: 이 문단의 파란 글씨를 누르면 다른 글로 넘어가는 것 — 그게 하이퍼텍스트다.

> **인터넷(internet)** — 세상의 컴퓨터들을 서로 잇는 기반 네트워크 기술.\
> 예: 인터넷은 깔려 있는 도로이고, 웹은 그 도로 위를 달리는 배달 서비스 중 하나다.

## 시대적 배경

*(이 편의 「시대 배경」에 해당한다)*

1980년대 말 인터넷은 **이미 존재했다.**\
문제는 도로가 없는 게 아니라, 그 도로 위의 정보가 흩어져 있다는 것이었다.

CERN처럼 거대한 연구 조직에서는 수많은 문서·실험 데이터·연락처가 서로 다른 컴퓨터와 서로 다른 형식에 갇혀 있었다.\
필요한 정보를 찾으려면 **어디에 무엇이 있는지를 사람이 일일이 알아야 했다.**

```text
1989년 이전 — CERN의 정보              웹 이후 — 하나의 그물
+------------------------------+       +------------------------------+
| 컴퓨터 A : 실험 데이터       |       | 문서마다 주소(URL)가 있다    |
| 컴퓨터 B : 보고서(다른 형식) |       | 문서 안에 다른 문서의 주소를 |
| 컴퓨터 C : 연락처 목록       |       | 링크로 적어 둔다             |
+------------------------------+       +------------------------------+
  어디에 무엇이 있는지를                 누르면 그 문서가 어느 컴퓨터에
  사람이 외우고 있어야 했다              있든 따라온다
```

왼쪽은 "아는 사람에게 물어봐야" 하고, 오른쪽은 "적혀 있는 곳을 누르면" 된다 — 이 차이가 웹이 만든 핵심이다.

버너스리의 발상은 **"새로운 것을 발명"하기보다 이미 있던 두 가지를 결합**하는 데 있었다.

- 하나는 전 세계를 잇는 **인터넷**.
- 다른 하나는 1960년대에 등장한 **하이퍼텍스트**.

이 둘을 합치면, 어느 컴퓨터에 있든 문서를 링크로 엮어 누구나 따라갈 수 있는 거대한 정보 그물이 된다 — 이것이 핵심 아이디어였다.

## 주요 사건과 변화

*(이 편의 「무엇이 바뀌었나」에 해당한다)*

먼저 10년 전체를 한 장에 놓고 본다.

```text
[연대순 구분선 — 원문은 항목 간 파생 관계를 다루지 않는다. 순서만 표시한다]

1989.03.12   "Information Management: A Proposal"  (Tim Berners-Lee, CERN)
               상사 Mike Sendall 의 승인 메모 : "vague, but exciting"
----------
1990.12      WorldWideWeb (후에 Nexus로 개칭) — 최초의 브라우저 겸 편집기
             최초의 웹 서버. CERN 안에서 가장 기본적인 형태로 작동 시작
----------
1991.08.06   CERN 외부 사람들이 공개 인터넷 서비스로 웹에 처음 접속
----------
1993.01      Mosaic 출시 (NCSA, 미국 일리노이대학교) — 9월 무렵 폭발적 확산
1993.04      CERN, 웹의 바탕 코드를 영구히 로열티 없이 공개하기로 선언
----------
1994.10      Netscape Navigator 출시 (Netscape Communications)
1994.10      W3C 설립 (MIT LCS 본부, CERN 협력, DARPA·유럽위원회 지원)
----------
1995         HTML 2.0 — IETF의 RFC 1866, 첫 공식 표준

[원문이 관계를 명시한 연결만 화살표로 잇는다 — 라벨이 관계의 종류다]

Mosaic 팀을 이끌던 Marc Andreessen --(NCSA를 떠나 창업)--> Netscape Communications
Netscape Navigator --(시장을 휩쓸며 밀어냄)--> Mosaic
```

그림 해설 (한 단계씩):

- 세로로 늘어선 칸들은 **화살표가 아니라 연대순 구분선**이다.\
  원문은 항목 간 파생 관계를 다루지 않는다 — 순서만 표시한다.
- 화살표는 **원문이 관계를 명시한 두 곳에만** 그었다. 화살표의 라벨이 곧 관계의 종류다.\
  하나는 사람이 옮겨 가 회사를 세운 관계이고, 다른 하나는 제품이 제품을 밀어낸 관계다.
- 1993년 한 해에 두 사건이 겹친 것이 이 연표의 분수령이다 — 아래에서 따로 본다.

### 1989 — "Information Management: A Proposal"

**무엇** — 1989년 3월 12일, 버너스리는 동료들에게 한 문서를 돌렸다.\
제목은 수수하게도 "정보 관리: 하나의 제안(Information Management: A Proposal)"이었다.

세상을 바꾸려는 의도가 아니라, **CERN에 흩어진 정보를 서로 연결해 어느 컴퓨터에서나 접근할 수 있게 하자**는 실무적 제안이었다.

그의 상사 마이크 센들(Mike Sendall)은 이 제안에 "**모호하지만, 흥미롭다(vague, but exciting)**"라고 적어 승인했다.\
이 한 줄이 웹의 출발 허가였다.

### 1990~1991 — 3대 요소와 최초의 브라우저

**왜 세 가지가 필요했나.**\
문서를 링크로 잇는 시스템을 실제로 만들려면, 세 가지 질문에 답해야 했다 — 그 문서가 *어디*에 있는가, *어떻게* 가져오는가, *무엇으로* 표현하는가.

버너스리는 이 셋을 각각의 요소로 설계했다.

- **URL(Uniform Resource Locator)** — 문서의 "주소". 인터넷 어디에 있는 자원이든 하나의 문자열로 식별한다.
- **HTTP(HyperText Transfer Protocol)** — 그 주소의 문서를 "주고받는 약속". 브라우저가 서버에 요청하고 서버가 응답하는 규칙이다.
- **HTML(HyperText Markup Language)** — 문서를 "표현하는 언어". 제목·문단·그리고 무엇보다 다른 문서로 가는 링크(`<a>`)를 태그로 표시한다.

> **URL(Uniform Resource Locator)** — 인터넷 위의 자원 하나를 가리키는 문자열 주소.\
> 예: 택배 송장에 적힌 "서울시 ○○구 ○○로 12, 3층"처럼 목적지를 한 줄로 특정한다.

> **HTTP(HyperText Transfer Protocol)** — 브라우저가 "이걸 주세요"라고 묻고 서버가 "여기 있습니다"라고 답하는 절차 규약.\
> 예: 식당에서 주문서를 넘기고 음식을 받는 정해진 순서와 같다.

> **HTML(HyperText Markup Language)** — 글의 어디가 제목이고 어디가 문단이고 어디가 링크인지를 태그로 표시하는 언어.\
> 예: 원고에 빨간 펜으로 "여기는 제목", "여기는 각주"라고 표시해 두는 것과 같다.

> **태그(tag)** — HTML에서 `<h1>` 처럼 꺾쇠로 감싸 역할을 표시하는 표기.\
> 예: `<a href="...">` 는 "여기부터 여기까지가 링크다"라는 표시다.

링크 하나를 누를 때 이 셋이 차례로 일하는 순서를 세로로 펼치면 이렇다.

```text
사용자가 문서 안의 링크를 누른다
        |
        v
URL     그 문서가 "어디"에 있는지를 한 줄 주소로 정한다
        |
        v
HTTP    브라우저가 그 서버에 요청을 보내고, 서버가 문서를 응답한다
        |
        v
HTML    돌아온 문서를 제목·문단·링크로 해석해 화면에 그린다
        |
        v
그 문서 안의 또 다른 링크 -> 다시 맨 위로
```

그림 해설 (한 단계씩):

- 세 부품은 순서대로 한 번씩 일하고, 각자 맡은 질문에만 답한다.
- 마지막 줄이 핵심이다 — 도착한 문서 안에 또 링크가 있으므로 이 고리가 **끝없이 이어진다.**\
  "그물"이라는 말이 나온 이유가 이것이다.

**무엇을 만들었나.**\
1990년 말, 버너스리는 이 셋을 묶어 최초의 웹 브라우저이자 편집기인 **WorldWideWeb**(공백 없이 한 단어, 후에 Nexus로 개칭)과 최초의 웹 서버를 만들었다.

1990년 12월 무렵 CERN 안에서 가장 기본적인 형태로 작동하기 시작했다.\
1991년 8월 6일에는 CERN 외부 사람들이 공개 인터넷 서비스로서 웹에 처음 접속할 수 있게 되었다.\
이 날이 웹이 연구실 밖으로 나온 순간이다.

> **브라우저(browser)** — 서버에서 받은 HTML을 해석해 사람이 읽을 화면으로 그려 주는 프로그램.\
> 예: 악보(HTML)를 받아 소리로 연주해 주는 연주자에 해당한다.

> **웹 서버(web server)** — 요청받은 주소의 문서를 찾아 돌려주는, 늘 켜져 있는 쪽의 프로그램.\
> 예: 주문이 들어오면 창고에서 물건을 꺼내 보내는 배송 센터 역할이다.

**초창기 HTML은 어떻게 생겼나.**\
지금 기준으로는 태그 몇 개뿐인 소박한 문서 언어였다.\
화면을 꾸미는 것이 아니라 **"문서의 구조"와 "링크"를 표시하는 것이 전부**였다.

```html
<!-- 초기 HTML의 모습 — 구조와 링크가 핵심이었다 -->
<title>The World Wide Web project</title>
<h1>World Wide Web</h1>
<p>The WorldWideWeb (W3) is a wide-area
<a href="WhatIs.html">hypermedia</a> information retrieval
initiative aiming to give universal access to a large universe
of documents.</p>
```

코드에서 볼 것은 두 가지뿐이다.

- `<title>`·`<h1>`·`<p>` — 이건 제목이고 저건 문단이라는 **구조 표시**.
- `<a href="WhatIs.html">` — 다른 문서로 건너뛰는 **링크**.

그리고 글자 색이나 크기를 지정하는 것은 하나도 없다.

### 1993 — CERN의 무료 공개, 그리고 Mosaic

**왜 폭발했나.** 두 가지 결정적 사건이 1993년에 겹쳤다.

**첫째, 공짜가 됐다.**\
CERN은 1993년 4월 웹의 바탕 코드를 영구히 **로열티 없이** 누구나 쓸 수 있도록 공개하기로 선언했다.\
특정 회사의 사유 기술이 아니라 공공재가 된 것이며, 이는 전 세계의 자발적 참여와 창작을 촉발했다.

> **로열티 무료(royalty-free)** — 쓸 때마다 사용료를 내지 않아도 되는 상태.\
> 예: 누가 웹 서버를 만들어 팔아도 CERN에 돈을 낼 필요가 없으니, 만들어 볼 이유가 생긴다.

**둘째, 글과 그림이 한 화면에 나왔다.**\
미국 일리노이대학교 NCSA(국립슈퍼컴퓨팅응용센터)에서 **Mosaic** 브라우저가 등장했다(1993년 1월 출시, 9월 무렵 폭발적 확산).

Mosaic의 결정적 차이는 **이미지를 텍스트와 같은 페이지에 함께 보여 준 것**이다.

```text
Mosaic 이전 브라우저                    Mosaic
+-----------------------------+        +-----------------------------+
| 본문 창                     |        | 본문 창                     |
|  글 글 글 글 글             |        |  글 글 [그림] 글 글         |
|  글 글 글 글 글             |        |  글 글 글 글 글             |
+-----------------------------+        +-----------------------------+
        +----------------+               글과 그림이 한 화면에
        | 그림은 별도 창 |               섞여서 한꺼번에 보인다
        +----------------+
  그림은 따로 띄운 창에서 봐야 했다
```

**왜 이게 나은가** — 글과 그림을 한 화면에 섞어 보여 주니, **기술자가 아닌 일반인도 직관적으로 쓸 수 있게** 됐다.\
웹이 "연구자의 도구"에서 "누구나의 매체"로 넘어가는 전환점이었다.

### 1994 — Netscape와 W3C

**상용 경쟁이 시작됐다.**\
Mosaic 팀을 이끌던 **마크 안드레센**(Marc Andreessen)은 NCSA를 떠나 회사를 세웠고, 이는 곧 넷스케이프 커뮤니케이션즈(Netscape Communications)가 된다.

넷스케이프는 1994년 10월 대표 제품 **Netscape Navigator**를 내놓았고, 이듬해 시장을 휩쓸며 Mosaic을 빠르게 밀어냈다.\
상용 브라우저 경쟁의 시작이자, 웹 대중화의 본격적인 가속 페달이었다.

**동시에 표준 기구가 생겼다.**\
같은 1994년 10월, 버너스리는 웹이 한 회사의 사유물로 파편화되는 것을 막기 위해 **W3C**(World Wide Web Consortium)를 설립했다.

- MIT 컴퓨터과학연구소(LCS)에 본부를 두었다.
- 웹의 발상지 CERN과 협력했다.
- DARPA와 유럽위원회의 지원을 받았다.

W3C의 사명은 **웹의 표준을 한곳에서 합의해 어느 브라우저에서나 같은 문서가 동작하도록 보장하는 것**이었다.

> **표준(standard)** — 여러 만드는 쪽이 같은 규칙을 따르도록 글로 못 박아 둔 합의문.\
> 예: 콘센트 규격이 표준이라서, 어느 회사 가전을 사도 집 벽에 꽂힌다.

같은 해에 일어난 두 사건을 나란히 놓으면 이 시기의 성격이 보인다.

```text
1994년 10월 — 같은 달의 두 사건
+---------------------------------+  +---------------------------------+
| Netscape Navigator 출시         |  | W3C 설립                        |
| 회사들이 각자 더 좋은 브라우저를|  | 어느 브라우저에서나 같은 문서가 |
| 만들어 경쟁한다                 |  | 동작하도록 규칙을 합의한다      |
+---------------------------------+  +---------------------------------+
  경쟁이 웹을 빠르게 키운다            경쟁이 웹을 쪼개지 못하게 막는다
```

원문은 넷스케이프와 마이크로소프트의 경쟁이 1990년대 후반 "브라우저 전쟁"으로 번져 표준화의 중요성을 역설적으로 일깨우게 된다고 적는다.

### 1995 — HTML 2.0, 첫 공식 표준

브라우저마다 제멋대로 확장하던 HTML을 처음으로 하나의 문서로 못 박은 것이 **HTML 2.0**이다(1995년, IETF의 **RFC 1866**으로 발행).

"2.0"이라는 이름은 이전에 사실상 쓰이던 HTML을 정리해 *첫 공식 표준*으로 명문화했다는 뜻이다.\
폼(form)을 통한 사용자 입력 등 당시 실제로 쓰이던 기능을 표준에 담았다.

이로써 서로 다른 브라우저가 같은 규약을 기준 삼을 토대가 마련되었다.

> **IETF · RFC** — 인터넷 기술 규격을 논의하는 기구와, 그 기구가 번호를 붙여 발행하는 문서.\
> 예: "RFC 1866"이라고 하면 그 번호의 문서 한 편이 곧 HTML 2.0의 정본이라는 뜻이다.

> **폼(form)** — 사용자가 값을 입력해 서버로 보내는 입력 양식.\
> 예: 로그인 화면의 아이디·비밀번호 칸과 "로그인" 버튼이 폼이다.

## 왜 그렇게 갔나 — 남은 선택지와 트레이드오프

원문이 "왜"를 직접 밝힌 대목은 두 곳이다.

**① 왜 공짜로 풀었나.**\
CERN은 1993년 4월 웹의 바탕 코드를 영구히 로열티 없이 공개하기로 선언했다.\
원문은 그 결과를 이렇게 적는다 — **특정 회사의 사유 기술이 아니라 공공재가 된 것.**\
그리고 원문의 평가는 분명하다 — 이 **개방성이 폭발적 확산의 진짜 원동력이었다.**

**② 왜 표준 기구를 세웠나.**\
버너스리는 웹이 **한 회사의 사유물로 파편화되는 것을 막기 위해** 1994년 10월 W3C를 세웠다.

### 대가는 무엇인가

원문이 "다만"이라고 적은 이 시기의 한계는 하나다.

- **웹이 정적이었다.**\
  이 시기의 웹은 정적인 HTML 문서가 중심이었고, 페이지 안에서 무언가를 *동적으로 실행*하거나 *꾸미는* 일은 아직 빈약했다.\
  이 빈자리는 곧 CSS(스타일), JavaScript(동작), 그리고 서버 측 동적 페이지 기술로 채워지며 다음 시대로 이어진다.

원문은 이어서, 1994년 시작된 넷스케이프와 마이크로소프트의 브라우저 경쟁이 1990년대 후반 "**브라우저 전쟁**"으로 번져 **표준화의 중요성을 역설적으로 일깨우게 된다**고 적는다.

```text
1995년 시점의 웹 — 무엇이 있었고 무엇이 없었나
+---------------------------------+  +---------------------------------+
| 있던 것                         |  | 없던 것                         |
| URL  : 문서의 주소              |  | 꾸미기 : 스타일을 따로 지정하는 |
| HTTP : 주고받는 약속            |  |          수단이 빈약했다        |
| HTML : 구조와 링크 표시         |  | 동작   : 페이지 안에서 무언가를 |
| 폼   : 사용자 입력              |  |          실행하는 수단이 빈약   |
+---------------------------------+  +---------------------------------+
  문서를 보여 주는 데는 충분했다       실행하거나 꾸미는 일은 빈약했다
```

원문에 따르면 오른쪽 칸의 빈자리는 곧 CSS·JavaScript·서버 측 동적 페이지 기술로 채워지며 다음 시대로 이어진다.

## 영향과 의의

*(이 편의 「남긴 것」에 해당한다)*

웹의 첫 10년은 **"방향성"을 세운 시기**였다.

- **URL·HTTP·HTML이라는 세 요소**는 30년이 지난 지금까지도 웹의 변하지 않는 뼈대로 남아 있다.
- **CERN의 무료 공개 결정**은 웹을 특정 기업의 자산이 아닌 공공 인프라로 만들었다.
- 그 **개방성이 폭발적 확산의 진짜 원동력**이었다 — 원문의 평가다.

## 용어 풀이

- **하이퍼텍스트(hypertext)** — 문서의 한 지점에서 다른 문서로 건너뛰는 개념. 1960년대에 등장했다.
- **인터넷(internet)** — 컴퓨터들을 서로 잇는 기반 네트워크 기술. 웹은 그 위에 얹힌 것이다.
- **URL(Uniform Resource Locator)** — 인터넷 위 자원 하나를 가리키는 한 줄 주소.
- **HTTP(HyperText Transfer Protocol)** — 브라우저가 요청하고 서버가 응답하는 절차 규약.
- **HTML(HyperText Markup Language)** — 제목·문단·링크 같은 문서 구조를 태그로 표시하는 언어.
- **태그(tag)** — `<h1>`, `<a>` 처럼 꺾쇠로 감싸 역할을 표시하는 HTML 표기.
- **브라우저(browser)** — HTML을 해석해 화면으로 그려 주는 프로그램.
- **웹 서버(web server)** — 요청받은 주소의 문서를 찾아 돌려주는 프로그램.
- **WorldWideWeb** — 1990년 버너스리가 만든 최초의 브라우저 겸 편집기. 후에 Nexus로 개칭.
- **Mosaic** — NCSA가 만든 브라우저(1993). 이미지를 텍스트와 같은 페이지에 보여 준 것이 결정적 차이였다.
- **Netscape Navigator** — 넷스케이프 커뮤니케이션즈가 1994년 10월 내놓은 상용 브라우저.
- **로열티 무료(royalty-free)** — 사용료 없이 누구나 쓸 수 있는 상태. CERN이 1993년 4월 선언했다.
- **W3C(World Wide Web Consortium)** — 1994년 10월 설립된 웹 표준 합의 기구. 본부는 MIT LCS.
- **IETF** — 인터넷 기술 규격을 논의하는 기구. HTML 2.0을 RFC 1866으로 발행했다.
- **RFC** — IETF가 번호를 붙여 발행하는 규격 문서.
- **폼(form)** — 사용자가 값을 입력해 서버로 보내는 입력 양식. HTML 2.0에서 표준에 담겼다.
- **브라우저 전쟁** — 1990년대 후반 넷스케이프와 마이크로소프트의 브라우저 경쟁.
