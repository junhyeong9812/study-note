# 웹 플랫폼 변천사 — 쉽게 다시 쓴 판

> 원본: `~/project/web-history/README.md` — 이 문서는 그 내용을 초보자용으로 다시 쓴 것이다(2026-09-18).\
> 연도·인명·표준번호는 원문 그대로이며, 「한눈에」 도식·목차의 한 줄 요약·「급하면 이렇게 골라 읽어도 된다」는 원문에 없는 보충 설명이다.\
> 목차의 「시기」와 한 줄 요약은 각 편 본문에서 발췌한 보충이다.

웹(브라우저 플랫폼)의 역사를 **프로토콜 + 마크업/스타일 + 엔진 + API + 아키텍처**로 정리한 문서 모음이다.\
문서를 주고받던 하이퍼텍스트가 어떻게 앱 플랫폼이 됐는지를 다룬다.\
모든 문서는 한국어. (자매: `js-history`·`java-history`·`network-history`)

## 한눈에 — 6편이 하나로 이어지는 그림

```text
1989 ──── 1995 ──── 2000 ──── 2005 ──── 2010 ──── 2015 ──── 2020 ──── 현재
  │
  ▼
┌──────────────┐
│ 01 웹의 탄생 │  CERN 제안서(1989) · URL/HTTP/HTML · 최초의 브라우저와 서버
└──────────────┘
  │
  └─ 그 뒤로는 다섯 개의 '층'이 같은 세월을 각자 자란다
     (아래 다섯 줄은 서로 파생된 관계가 아니라, 한 시대를 보는 다섯 개의 단면이다)

02 전송        HTTP/0.9 ─ 1.0 ─ 1.1 ────────────── HTTP/2 ─────── HTTP/3
03 표현        생김새를 태그로 ─ XHTML 좌초 ─ HTML5 ─ Flexbox/Grid ─ 반응형
04 실행 엔진   Netscape/IE ─ IE6 정체 ─ Firefox/Chrome ─── Blink 로 수렴
05 능력        DOM ─ AJAX ─ Canvas/WebGL ─ SW/PWA ─ WASM ─── WebGPU
06 아키텍처    정적 ─ CGI ─ 서버사이드 ─ SPA ─ SSR/Jamstack ─ 엣지·RSC
```

그림 읽는 법 — 맨 위 01편이 출발점이고, 아래 다섯 줄은 그 위에서 **동시에 자란 층**이다.\
02가 "무엇을 어떻게 실어 나르나", 03이 "그것을 어떻게 보여 주나", 04가 "그걸 누가 실행하나", 05가 "무엇까지 할 수 있나", 06이 "그 능력으로 앱을 어떻게 짓나"를 본다.\
그래서 한 연도를 세로로 잘라 보면 그 해의 웹이 전부 보인다.

| 04 | [브라우저 엔진](04-브라우저-엔진.md) | 1994~2020 | 누가 페이지를 그리는가를 놓고 벌어진 두 번의 전쟁 — Netscape/IE·IE6 정체기·Firefox/Chrome·Trident/Gecko/WebKit/Blink 계보·V8과 JIT·Blink 독점 우려 |
| 05 | [웹 플랫폼 API](05-웹플랫폼-API.md) | 1998~2023 | 문서 뷰어였던 브라우저가 플러그인이 하던 일을 표준 기능으로 흡수해 앱 플랫폼이 된 25년 — DOM·AJAX/fetch·Canvas/WebGL/WebGPU·WebSocket/WebRTC·Service Worker/PWA·Web Components·WebAssembly |
| 06 | [웹 아키텍처 진화](06-웹아키텍처-진화.md) | 1991~2020s | "HTML을 어디서·언제 만드나"를 두고 왕복한 진자 — 정적 → CGI → 서버사이드(PHP/Rails) → AJAX·SPA → API 분리(REST/GraphQL) → SSR/Jamstack → 엣지·RSC·아일랜드 |

## 읽는 법

02(전송)·03(표현)·04(실행 엔진)·05(능력)·06(아키텍처)는 한 흐름이다 — **하이퍼텍스트 문서 → 앱 플랫폼**.\
06은 `js-history`의 프레임워크 진화, corpus의 `렌더링-전략`과 직접 이어지고, 02는 `network-history`의 HTTP/TLS와 맞물린다.

> 큰 줄기: **문서 열람(1991) → 동적 웹(CGI·AJAX) → 리치 앱(SPA·플랫폼 API) → 렌더링 진자(SSR↔CSR)와 엣지로, 브라우저가 OS가 되다.**

급하면 이렇게 골라 읽어도 된다.

- 웹이라는 게 원래 무엇이었는지부터 알고 싶다 → **01**
- "왜 요청이 이렇게 오가지"가 궁금하다(네트워크·성능 쪽) → **02**
- CSS 레이아웃이 왜 이렇게 생겼는지 알고 싶다 → **03**
- "IE6에서만 도는 웹"이 "Chrome에서만 도는 웹"으로 재현될 수 있다는 우려가 무슨 말인지 알고 싶다 → **04**
- 브라우저에서 카메라·GPU·오프라인이 어떻게 가능한지 알고 싶다 → **05**
- SSR이냐 CSR이냐를 지금 고르는 중이다 → **06 → 05의 2절(AJAX·fetch)**
- 프론트엔드 전체 지도를 한 번에 잡고 싶다 → **06 → 04 → 05**
