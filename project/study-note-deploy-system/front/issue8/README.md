## 1. 배경

첫 시안은 접이식 트리(전체 트리를 사이드바에 두고 ▸로 펼침)였는데, 사용자 사양으로
재설계: **사이드바는 현재 폴더의 하위만**, 콘텐츠는 그 폴더의 README, 위에는
`< 뒤로`(상위 폴더로)와 `전체트리 >`(전체 구조는 별도 화면). 파일 탐색기가 아니라
**정보 사이트의 섹션 내비게이션** 모델.

## 2. 화면 확인 반복으로 다듬은 것들 (각각이 사용자 피드백 1회)

```
1  가운데 정렬 컨테이너 → 전체 폭: 사이드바가 화면 왼쪽 끝, 헤더 아래 전체 높이
2  버튼 스타일 → 글자 링크(< 뒤로 · 전체트리 >), 색 선명하게
3  구분선을 사이드바 좌우 끝까지
4  📁/📄 아이콘 제거 → 카테고리(굵게 + 하위 개수 "12 ›") vs 문서(제목만)
   — 폴더 은유는 구현(파일시스템)을 노출한다. 개수 표기가 직관·접근성 모두 낫다
5  전체트리: 모달 → /tree 페이지(콘텐츠 영역 렌더), 접기/펼치기, 기본 전부 접힘
6  뒤로가기 = 경로 문자열 계산이 아니라 트리 객체의 prev 링크(backend issue10)
```

## 3. 곁가지 — portfolio가 트리에서 뭉개진 문제

**상황**: portfolio/k-brand-guard 아래 `01_….md ~ 05_….md`가 폴더 바로 밑에 나열.
**문제**: 우리 트리 모델에서 "하위 폴더 없이 문서만 있는 폴더"는 리프(주제) —
클릭하면 문서 하나만 렌더되고 나머지 4편이 화면에서 사라진다.
**접근**: (a) 모델을 바꿔 리프에서 문서 목록 렌더 (b) 문서를 폴더로 승격.
**결론**: (b) — `NN_제목/post.md`로 재구조화(study-note 커밋). 각 글이 트리 노드가
되고, `post` 종류라 검색·자동완성에도 잡힌다. 실제로 자동완성 스모크에서 portfolio
글이 최상위로 올라온 게 이 재구조화의 효과.

## 4. 구현 중 마주친 문제 — 사이드바 횡스크롤 (#23)

**상황**: 구분선을 사이드바 좌우 끝까지 보내려고 패딩 있는 컨테이너 안에서 음수
마진을 썼다: `margin: 0 -1rem; padding: 0 1rem`.
**문제**: 가로 스크롤바가 생김 — 음수 마진만큼 nav 콘텐츠 폭이 컨테이너를 넘었다.
**결론(수정)**: 음수 마진 트릭 제거 — **aside의 패딩을 없애고** 각 섹션이 자기
패딩을 갖게 재배치(구분선 행은 패딩만, 전폭 자연 확보) + `overflow-x: hidden` 안전벨트.
**배경**: "부모 패딩 상쇄용 음수 마진"은 overflow 컨테이너와 만나면 스크롤을 만든다 —
전폭이 필요하면 애초에 부모가 패딩을 갖지 않게 설계하는 쪽이 정직하다.
