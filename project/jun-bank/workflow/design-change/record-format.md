# 변천 문서 — 양식과 작성법

---

## 1. 목적

**어떤 설계 결정이 왜 실패했고, 무엇으로 바꿨고, 그 결과 기존 지적들이 어떻게 됐는지를 한 문서에 남긴다.**

> **결정만 남기면 다음에 같은 자리가 흔들릴 때 아무것도 못 한다.** "그때 왜 이렇게 정했나"와 "그전 것은 왜 실패했나"가 둘 다 있어야 재검토가 가능하다.

---

## 2. 독자

| 독자 | 이 문서에서 얻는 것 |
|---|---|
| **다음 라운드 리뷰어** | 이미 소멸한 결함을 다시 지적하지 않을 근거 |
| 구현자 | 왜 이 구조인지 — 표면만 보면 과해 보이는 설계의 이유 |
| 미래의 나 | 같은 자리가 또 흔들릴 때의 재검토 출발점 |

> **하나의 결정으로 특정한다.** "여러 문제가 얽혀 있다"는 진단이 아니다.

| 항목 | 내용 |
|---|---|

| **왜 이것이 뿌리인가** | <위 실패들이 전부 이 결정에서 파생됨을 보인다> |

## 4. 기각 근거 재심 (T4) ★

> 그 결정을 내릴 때 **다른 선택지를 왜 기각했는지**를 다시 읽는다.

| 당시 기각한 선택지 | 당시 기각 근거 | **지금도 유효한가** |
|---|---|---|
| | | ✅ 유효 / ❌ **채택안에도 그대로 적용됨** |

> ❌가 하나라도 있으면 **그 기각은 성립하지 않았다.** 그 선택지를 다시 후보에 올린다.

|---|---|---|---|

## 9. 검증

> ②의 실패 이력이 **재현되지 않는지** 확인한다. 새 설계가 좋아 보이는 것과 옛 실패를 막는 것은 다르다.

| 옛 실패 | 새 구조에서 | 확인 결과 |
|---|---|---|
| | | ✅ 해소 / ⚠️ 부분 / ❌ 미검증 — **근거** |

---

## 10. 반증 신호 채점 ★

> §5.4에 등록한 위험마다 **발화했는지**, 발화했다면 **어떻게 판정했는지**.

| 신호 (§5.4) | 발화했나 | 판정 | 근거 |
|---|---|---|---|
| | 예 / 아니오 | 기각 / 수용 / 보류 | **기각이면 반드시 근거를 적는다** |

> **채점하지 않은 반증 기준은 장식이다.** 신호를 세운 이유는 *"내가 틀렸을 때 알아채기 위해서"* 인데, 채점을 안 하면 틀렸어도 모른 채 지나간다.

## 4. 작성법

### 실패 이력을 요약하지 않는다 (§2)

**요약하면 뿌리가 안 보인다.** "미수 관련 문제들"로 뭉뚱그리는 순간, 그것들이 *같은 결정*에서 나왔는지 *비슷해 보이는 다른 문제*인지 구분할 수 없다.

| 나쁜 기록 | 좋은 기록 |
|---|---|
| "환불 관련 결함이 반복됨" | "1차: 상한 부재 / 2차: 상한이 스스로 커짐 / 3차: 계좌 상계와 충돌 / 4차: 계좌 합계 감소 경로 없음" |

**심각도와 '그때 무엇을 고쳤나'를 반드시 함께 적는다.** 고친 내용이 다음 라운드 지적의 원인이 되는 패턴이 여기서 드러난다.

### 뿌리는 하나로 특정한다 (§3)

**"여러 문제가 얽혀 있다"는 진단이 아니다.** 그렇게 적으면 무엇을 바꿔야 하는지가 안 나온다.

특정하는 질문:

```
이 실패들을 전부 없애려면, 바꿔야 하는 결정은 최소 몇 개인가?
  1개    → 그것이 뿌리다
  2개+   → 아직 덜 파고들었거나, 애초에 토대 문제가 아니다
```

### 기각 근거 재심이 핵심이다 (§4)

**대부분의 토대 문제는 "그때 기각한 것이 사실은 맞았다"로 판명된다.** 기각 근거를 그대로 두면 같은 논리로 또 기각한다.

재심 질문: **그 기각 근거가 채택한 안에도 적용되는가?**

> 예: "이 규칙을 지키려면 승인 이력을 봐야 한다"로 A를 기각했는데, 채택한 B도 **같은 이력을 본다**면 — 그 기각 근거는 A만 겨냥한 것이 아니었다. **성립하지 않았다.**

#### ⚠️ 축이 다른 비용을 같다고 놓지 않는다

**"저장 크기"와 "조회 비용"은 다른 축이다.** 이걸 뭉개면 재심이 억지가 된다.

| 축 | 예 |
|---|---|
| 저장 크기 · 락 범위 | 애그리게이트가 커진다 · 동시성이 죽는다 |
| 조회 비용 | 읽을 때마다 쿼리가 나간다 |
| 갱신 빈도 | 쓰기가 몰린다 |

> 같은 양식이 **①(파생값 — 저장하지 않고 조회)** 을 선택지로 두는 것 자체가 **둘이 다른 축이라는 전제**다. "부담이 같다"고 하면 ①이 선택지일 수 없게 된다.

#### 재심의 결론은 §5 선택지에 반영되어야 한다 ★

**기각이 무효라고 판정했으면 그 선택지를 후보로 다시 올린다.** 판정만 하고 선택지에 안 올리면, 재심이 **이미 정한 결론을 정당화하는 데만 쓰인 것**이다 — 사후 합리화의 전형이다.

```
④에서 (c)의 기각이 무효라고 판정  →  ⑤ 선택지에 (c)가 있어야 한다
                                       없으면 ④는 장식이다
```

### 위험을 미리 적는다 (§5)

새 토대도 완벽하지 않다. **감수하는 것을 미리 적어야** 나중에 문제가 생겼을 때 "예상하고 받아들인 것"인지 "놓친 것"인지 구분된다. 안 적으면 전부 "또 실패했다"로 보인다.

### 재판정을 건너뛰지 않는다 (§8)

토대를 바꾼 직후, 리뷰 findings 목록은 **절반쯤 무효**다. 그대로 소화하면:

- 이미 사라진 결함을 고치느라 **없어도 되는 코드·규칙을 만든다**
- 그 규칙이 다음 라운드의 새 지적을 낳는다

**소멸 판정에는 "어떻게 사라졌는지"를 반드시 적는다.** 그게 없으면 다음 리뷰어가 같은 것을 다시 지적하고, 반박할 근거가 없다.

## 6. 완료 기준

- [ ] 발동 조건(§2 절차 문서 T1~T6)이 **명시**돼 있다
- [ ] 실패 이력이 **라운드별 원문**으로 있다 — 요약 아님
- [ ] 뿌리가 **하나의 결정**으로 특정됐다
- [ ] 과거 기각 근거를 **재심**하고 판정했다
- [ ] 재심에서 **기각 무효**로 판정한 선택지가 §5 후보에 **올라가 있다**
- [ ] 안고 가는 **위험**이 적혀 있다
- [ ] **사용자 합의**와 "답변에 없어 내가 판단한 것"이 구분돼 있다
- [ ] 변경 순서가 **기준소스 → 파생**이다
- [ ] 기존 findings가 **전부** 소멸/잔존/변형으로 재판정됐고, 소멸에는 근거가 있다
- [ ] 옛 실패마다 **재현되지 않음을 확인할 방법**이 적혀 있고 §9에 **결과**가 있다
- [ ] §5.4의 **반증 신호가 전부 채점**됐다 (§10)
- [ ] 소멸 판정에 **"그 결과에 도달할 경로가 없다"의 근거**가 있다
