## 1. 이 양식이 강제하는 것 (한 문장)

> **개발 규약은 규칙의 목록이 아니라, 규칙마다 「무엇이 그것을 강제하나」를 적은 표다. 강제 수단 칸이 빈 행은 규약이 아니라 희망이다.**

규칙만 나열하면 *"다른 컨텍스트의 도메인을 직접 참조하지 않는다"* 와 *"변수명은 의미를 담는다"* 가 **같은 무게로** 적힌다. 앞의 것은 빌드 그래프가 거부할 수 있고 뒤의 것은 사람만 볼 수 있는데, 표가 그 차이를 안 적으면 **둘 다 사문화된다** — 이 프로젝트의 실측 결론이다(`verification-by-construction.md` · ADR-002 §5 *"규칙을 문서로만 두면 사문화된다"*).

> ★ 그래서 이 양식의 중심 칸은 **①(규칙 분류)이 아니라 ②(강제 수단)** 이다. 분류는 읽는 순서를 만들 뿐이고, 규약이 실제로 서는 것은 강제 수단 칸에서다.

## 2. 필수 칸 (하나라도 비면 규약이 아니다)

| 칸 | 무엇을 적나 | 비어 있으면 생기는 일 |
|---|---|---|
| **① 규칙 분류** | 규칙을 **분류 축**으로 나눈다 — 언어(코딩) · 모듈(구조) · 오류·값 타입 · 테스트 작성 · PR·리뷰 절차 · 도구. 각 규칙에 ★ **grep 가능한 ID**(`KO-1`·`MO-1` 류)를 붙인다 | 규칙이 산문에 섞여 **커밋·리뷰가 지목할 수 없다.** *"규약 위반"* 이라고만 적히고 어느 줄인지 남지 않는다 |
| ★ **② 강제 수단 (의무)** | ★ **규칙마다 한 칸** — **컴파일**(빌드 그래프·타입) / **테스트**(아키텍처 테스트 · CI 테스트 게이트) / **린트·자동 검사**(포매터·훅·생성물 drift) / **리뷰**(사람) 중 **무엇이 이 규칙을 막나**. 도구가 아직 미확정이라 **잠정적으로 리뷰인 것**은 그 사실을 적는다(`잠정 리뷰`) | ⑴ 강제력이 다른 규칙이 **같은 무게로** 읽힌다 ⑵ *"규약에 있으니 지켜지겠지"* 가 성립하고, 아무도 안 지켜도 **아무 데서도 빨간불이 안 뜬다** ⑶ 자동화할 수 있었던 규칙이 **영원히 사람 몫**으로 남는다 |
| ★ **③ 도구 확정 절차 (성질 → 판정 → 기록)** | ⑴ **성질**: 상위 문서(E2 §4.1)가 적은 *"계층이 요구하는 성질"* 과 **충족 판정 기준**을 **인용**한다(재작성 금지) ⑵ **판정**: 후보 도구를 그 기준에 **한 줄씩 대조**하고 충족/부분 충족/미충족을 적는다 — 부분 충족은 **무엇이 남았는지**를 적는다 ⑶ **기록**: C-08 형식으로 확정한다 — **요구 → 계약 → 도구 · 도입 조건 · 되돌리는 조건**. 도입하지 않은 후보는 상위 문서의 **도입 조건을 인용**하고 **보류를 유지**한다 | 도구가 **취향으로** 들어오고, 그 도구가 만든 문제를 도메인 문제로 오인한다(C-08 · ADR-021 §1 실측 — 브로커 제외로 선검증 결함 6건이 자동 소멸). 판정 기준을 다시 쓰면 **기준이 도구에 맞춰 휘어진다** |
| **④ PR·리뷰 절차** | 브랜치 · 커밋 단위 · ★ **머지 게이트는 상위 문서를 인용**(재정의 금지) · 리뷰 관점(무엇을 보고 무엇을 안 보나) · 외부 발행 규칙. 각 항목에도 ②의 강제 수단 칸을 붙인다 | 게이트가 **두 곳에 적혀** 갈린다 — *"테스트 녹색이니 머지"* 와 *"저건 아직 안 끝났다"* 가 둘 다 근거를 갖는다. 리뷰 관점이 없으면 리뷰가 **표기·포맷 지적**으로 채워진다(검증 정책 v2 §1 — 그 유형이 60%) |
| **⑤ 상위 정본 인용** | 규약은 **규칙을 새로 만들지 않는다.** 모듈 규칙은 ADR, 업무 규칙은 BR, 계층·게이트는 테스트 전략이 정본이고 규약은 **그 규칙의 실행 형태**(무엇으로 강제하나·코드에서 어떤 모양인가)만 적는다. 인용은 **ID로** 한다 | 정본이 둘이 된다. 규약과 ADR이 갈리면 **어느 쪽이 이기는지 아무도 모른다** |
| **⑥ 수치·설정값 이연** | 포매터 설정값 · 타임아웃 · 커버리지 · 컨테이너 격리 단위 같은 **접촉해야 알 수 있는 값**은 `[구현 검증]`으로 이연하고 중앙 대장에 등재한다(V2-3) | 규약이 **추측을 정본화**한다(검증 정책 v2 §1의 세 번째 유형 — *"문서 판정 = 추측의 정본화, 해롭다"*) |
| **⑦ 강제 수단 분포 집계** | 문서 끝에 ★ **컴파일 / 아키텍처 테스트 / 테스트 게이트 / 린트 / 리뷰가 각각 몇 규칙**인지를 ★ **「현재 / 도구 확정 후」 2열로**(D10) 싣고, **리뷰로만 강제되는 규칙의 전량 목록 + 자동화 조건**(D2)과 **잠정 리뷰 전량 + 기다리는 도구**(D10)를 **분리해** 싣는다. 검산 행(절별 합 = 수단별 합)을 **두 열 모두**에 붙인다 | 리뷰 강제 규칙이 조용히 늘어난다. 집계가 없으면 *"규약이 커졌다"* 는 알아도 *"사람이 볼 것이 늘었다"* 는 모른다. ⚠️ 한 열로만 세면 **잠정 리뷰가 자동화된 것으로 집계**되어 *"사람 몫"* 이 실제보다 작아 보인다 |

## 3. 작성 규칙

| # | 규칙 |
|---|---|
| **D1** | ★ **규칙 한 행에 강제 수단 한 칸.** 빈칸·`—`·*"권장"* 은 허용하지 않는다. 강제할 수단이 정말 없으면 그것은 규칙이 아니라 **가이드**이므로 규약에서 빼고 참고 자료로 내린다. ★ **명시 예외 — 메타 규칙**: *"리뷰라는 수단을 어떻게 쓰나"* · *"도구 확정 절차 자체"* 처럼 **다른 규칙의 강제 수단이 아니라 강제 수단의 운용을 정하는 행**은 자동 강제가 **정의상 성립하지 않는다**(기계가 렌즈를 강제하면 그 기계가 곧 그 렌즈다 — 자기 참조). 이런 행은 **가이드로 내리지 않고 「메타 규칙」 소절에 모아 예외임을 명시**하며, D2의 승격 조건 칸에는 *"조건이 성립할 수 없다"* 를 적는다(조건을 빠뜨린 것과 구분한다) |
| **D2** | ★ **리뷰로만 강제되는 규칙을 최소화한다.** 리뷰 전용으로 남기려면 **⑴ 왜 자동화할 수 없나 ⑵ 무엇이 관찰되면 자동화로 올리나**(승격 조건)를 **함께** 적는다. 조건 없는 리뷰 전용 규칙은 *"지켜지지 않아도 아무 일도 안 일어나는 문장"* 이다. ★ **⑶ 규칙을 통째로 리뷰에 넣지 않는다** — 한 규칙 안에 **기계 판정 가능한 부분**(존재·위치·타입·의존·필드 유무·경로·패턴)과 **의미 판정 부분**(*"이것이 도메인 로직인가" · "이 배정이 옳은가" · "이 단언이 그 실패모드를 반증하나"*)이 섞여 있으면 **나눠 적고 앞의 것은 자동 검사로 올린다.** 통째로 리뷰에 넣으면 **자동화할 수 있었던 몫이 영원히 사람에게 남는다**(양식 ② ⑶). ★ **⑷ 「리뷰 전용」과 「잠정 리뷰」는 다른 집합이다** — 잠정 리뷰(D10)는 *"기계가 막아야 하는데 도구가 없는 것"* 이라 정의상 리뷰 전용이 아니다. **한 규칙을 두 목록에 함께 올리지 않는다**(올리면 리뷰 전용 수가 부풀고 승격 조건이 두 벌이 된다) |
| **D3** | ★ **강제 사다리 — 위로 올릴 수 있으면 올린다.** **컴파일 > 아키텍처 테스트 > 테스트 게이트 > 린트·자동 검사 > 리뷰** 순으로 강하다(ADR-002 §5의 강제력 표와 같은 순서). 같은 규칙을 낮은 칸에 두었다면 **왜 위로 못 올렸는지**를 적는다. ⚠️ ★ **아키텍처 테스트와 테스트 게이트를 한 칸으로 묶지 않는다** — 아키텍처 테스트는 **구조 위반을 전수로 거부**하고(규칙 하나 = 단언 하나), 테스트 게이트는 **케이스가 있는 만큼만** 막는다(★ **케이스가 빠진 것을 게이트는 스스로 알지 못한다**). 묶어 세면 강제력이 다른 둘이 같은 무게로 읽힌다. ★ **지금 자동화할 수 있는 부분을 「N회 관측 후 승격」으로 유예하지 않는다** — 관측 조건은 *"자동화 가치가 아직 불확실한 것"* 에 붙이는 것이지, **이미 기계 판정이 성립하는 것**(경로·패턴·필드 유무)에 붙이면 D3 위반이다 |
| **D4** | ★ **규칙을 재발명하지 않는다.** 모듈 경계·업무 규칙·계층·게이트는 **정본이 이미 있다** — 규약은 **ID로 인용**하고 *"코드에서 어떤 모양인가 · 무엇이 막나"* 만 새로 적는다. 인용문을 옮겨 적어 정본을 둘로 만들지 않는다 |
| **D5** | ★ **도구는 성질 → 판정 → 기록 순서로만 확정한다**(C-08). ⑴ **판정 기준은 상위 문서(E2 §4.1)가 소유**하므로 규약이 다시 쓰지 않는다 ⑵ 후보를 기준에 **한 줄씩 대조**한 표가 없으면 그것은 확정이 아니라 **선호**다 ⑶ **부분 충족은 부분 충족으로 적는다** — 남은 것을 `[구현 검증]` 또는 열린 의문으로 등재한다 |
| **D6** | ★ **도입하지 않은 도구의 도입 조건을 재판정하지 않는다.** 상위 문서가 이미 조건을 적었으면 **인용하고 보류를 유지**한다. 조건이 이미 충족됐다고 판단되면 그것 자체가 **별도 판단**이며, 규약이 조용히 통과시키지 않는다(*"나중에 필요하면"* 도, *"이제 필요해 보이니"* 도 판정 불가다) |
| **D7** | ★ **수치·설정값을 확정하지 않는다.** 포매터 설정·타임아웃·병렬도·격리 단위는 접촉해야 정해진다 — `[구현 검증]` + 중앙 대장 등재(V2-3). 규약이 임의값을 적으면 **그 값이 근거 없이 인용되기 시작한다** |
| **D8** | ★ **PR 절차가 게이트를 재정의하지 않는다.** 머지 조건은 테스트 전략(E2 §3.0)이 정본이고 규약은 **인용**한다. 규약이 조건을 다시 적으면 **머지 게이트와 마일스톤 게이트의 분리가 무너진다** |
| **D9** | **규칙 ID는 grep 가능해야 하고 유일해야 한다.** 다른 문서가 이미 쓰는 접두어(`M-`·`K-`·`BR-`·`CL-` 등)와 **겹치지 않게** 고른다 — 겹치면 인용이 어느 문서를 가리키는지 갈린다 |
| **D10** | ★ **잠정 강제를 정직하게 표기한다.** 도구가 아직 확정되지 않아 **지금은 사람이 보는** 규칙은 `잠정 리뷰`로 적고 **무엇이 확정되면 자동으로 올라가는지**를 적는다. `아키텍처 테스트`라고만 적으면 **그 테스트가 없는 동안 아무것도 막지 않는다**는 사실이 숨는다. ★ **분포 집계(⑦)는 「현재 / 도구 확정 후」 2열로 센다** — 한 열로 세면 잠정 리뷰가 **이미 자동화된 것처럼** 집계되어, 양식이 막으려던 바로 그 착시(*"규약에 있으니 지켜지겠지"*)가 집계표에서 되살아난다. ★ **잠정 리뷰가 기다리는 도구를 묶어 세라** — 한 도구가 푸는 건수가 곧 **조기 확정 우선순위**다 |
| **D11** | ★ **「N회 누적」 조건에는 관측 대장을 지정한다.** 되돌리는 조건·승격 조건·도입 조건에 *"…가 2회 관측될 때"* 를 적었으면 **그 사건을 어디에 append하는지**(대장 위치 · 행 형식 · 누가 적나)를 같은 문서에 둔다. ⚠️ **카운터 없는 누적 조건은 영원히 발동하지 않는다** — 조건 없는 리뷰 전용 규칙(D2)과 **같은 결함**이며, 되돌리는 조건 쪽이 더 위험하다(*"조건을 적어 뒀다"* 는 안심만 남는다). ★ 카운트는 **대장에 등재된 행 수로만** 세고 기억·인상으로 세지 않는다 |

| ⚠️ **경계** | **4.5.3 절차서**(배포·장애 대응 절차)와 **4.6 구성 관리·CI/CD**는 **E4**가 소유한다. 규약은 *"파이프라인이 무엇을 돌리나"* 를 정하지 않고 *"머지 게이트가 무엇을 요구하나"* 만 인용한다 |

## 5. 자기 점검 (이 문서가 끝났다고 말할 수 있는 조건)

- [ ] 필수 칸 ①~⑦이 전부 채워졌다 (한 칸이라도 비면 아직 초안)
- [ ] ★ **모든 규칙 행에 강제 수단 칸이 채워져 있다** — 빈칸·`—`·*"권장"* **0건** (D1)
- [ ] 규칙마다 **grep 가능한 유일 ID**가 있고, 다른 문서의 접두어와 겹치지 않는다 (D9)
- [ ] ★ **리뷰 전용 규칙 전량**이 목록으로 있고, 각각 **왜 자동화 못 하나 + 승격 조건**을 달고 있다 (D2)
- [ ] ★ **한 규칙 안의 기계 판정 부분이 분리**돼 자동 검사로 올라갔고, 리뷰에는 **의미 판정만** 남았다 (D2 ⑶)
- [ ] ★ **「리뷰 전용」과 「잠정 리뷰」 목록이 겹치지 않는다** — 한 규칙이 두 곳에 없다 (D2 ⑷)
- [ ] ★ **잠정 리뷰**(도구 미확정으로 지금은 사람이 보는 것)가 그렇게 표기돼 있고, 무엇이 확정되면 올라가는지 적혀 있다 (D10)
- [ ] ★ **분포 집계가 「현재 / 도구 확정 후」 2열**이고 두 열 모두 검산이 맞는다 (⑦ · D10)
- [ ] ★ **「N회 누적」 조건 전부에 관측 대장이 지정**돼 있다 — 대장 위치·행 형식·기록 주체 (D11)
- [ ] ★ **메타 규칙**(자동 강제가 정의상 불가한 행)이 있으면 **별도 소절에 모여 D1 예외로 명시**돼 있다 (D1)
- [ ] 도구 확정이 **성질 → 판정 → 기록** 순서로 적혔고, ★ **판정 기준을 인용했지 다시 쓰지 않았다** (D5)
- [ ] 확정한 도구마다 **요구 · 계약 · 도입 조건 · 되돌리는 조건**이 있다 (C-08 형식)
- [ ] 도입하지 않은 후보마다 **상위 문서의 도입 조건이 인용**돼 있고 **보류가 유지**됐다 (D6)
- [ ] 확정한 **수치·설정값이 0개**다 — 전부 `[구현 검증]` 또는 인용 (D7)
- [ ] 머지 게이트를 **인용**했고 **다시 정의하지 않았다** (D8)
- [ ] 상위 정본을 **한 줄도 고치지 않았다** (D4)
- [ ] 문서 끝에 **강제 수단 분포 집계**가 있다 (⑦)
