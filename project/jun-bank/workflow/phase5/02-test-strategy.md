# 테스트 전략 문서 양식 — 자산을 계층에 배정하는 절차 (워크플로우 정본)

- 상태: 작성중 (2026-08-06 — E2 산출물 ②. 작업 기록 = `plans/2026-08-06/e2-test-strategy/`)
- 목적: 산출물 ②(워크플로우) — **"이미 쌓인 검증 자산을 구현 전에 어떻게 계층에 배정하는가"** 의 재사용 가능한 절차. 교과서 **5장(품질 보증과 테스트)** 대응.
- 이 양식으로 쓰는 문서: `docs/architecture/test-strategy.md`(내용 정본)

## 1. 이 양식이 강제하는 것 (한 문장)

> **테스트 전략은 계층을 나열하는 문서가 아니라, 이미 있는 검증 자산을 하나도 빠뜨리지 않고 계층에 배정하는 문서다.**

계층(피라미드)부터 그리면 *"단위 70% · 통합 20% · E2E 10%"* 같은 **비율 선언**이 나온다. 비율은 검증할 수 없고, 배정 누락은 드러나지 않는다.
자산 대장에서 출발하면 **누락이 산술로 드러난다** — 대장의 원소 **집합**과 배정된 원소 **집합**이 다르면 그것이 결함이다.

> ★ 이 프로젝트에서 이 순서가 성립하는 이유: 구현 전에 이미 **규칙마다 검증 방법 칸**(BR)·**품질 시나리오**(QS)·**실험 시나리오**·**[구현 검증] 대장**(IV)이 있다. 테스트 전략이 만들 것은 **새 검증 항목이 아니라 배정**이다. 자산 대장이 없는 프로젝트라면 이 양식의 §2 ③ 앞에 *"대장부터 만든다"* 가 붙는다.

## 2. 필수 칸 (하나라도 비면 전략이 아니다)

| 칸 | 무엇을 적나 | 비어 있으면 생기는 일 |
|---|---|---|
| **① 계층 정의** | 계층마다 — **판정 대상**(무엇이 틀렸다고 말할 수 있나) · **격리 수준**(무엇을 실물로 쓰나) · **실행 비용·주기** · **실패했을 때 알게 되는 것**. ★ 계층은 *"어디서 실행되나"* 하나의 축이며 **4단을 넘기지 않는다** | 계층 이름만 있고 경계가 없어, 같은 검증이 세 계층에 중복되거나 아무 계층에도 없다 |
| ★ **①-b 태그 축** | 계층과 **직교하는** 축 — **오라클이 어디서 오나**. **판정**(오라클 = 정본 · 산출 = 통과/실패 · 실패하면 구현을 고친다) / **탐색**(오라클 없음·[미확정] · 산출 = **값과 판정** · 불일치는 **정본 반증 후보**). ★ 탐색 자산도 **①~④ 중 한 계층에서 실행되므로 계층 배정을 면제받지 않는다** | ★ 탐색을 **다섯 번째 계층**으로 두면 *"실험 계층은 나중에"* 가 **배정 누락의 합법 통로**가 된다. 실행 계층이 비어 있어 **언제 어디서 도는지 아무도 모른다** |
| **② 자산 → 계층 매핑 규칙** | 배정 **판별 질문** 하나 + ★ **하한 규칙**(판별 질문이 "가장 싼 곳"을 잘못 고르는 것을 막는다) + 예외 처리(둘 이상에 걸칠 때 · 어느 계층으로도 못 갈 때) | 배정이 작성자의 취향이 되고, 다음 사람이 재현하지 못한다. 하한이 없으면 **경계·순서 규칙이 인메모리 등식으로 내려간다** |
| **③ 자산 매핑 표 (전수)** | 자산 대장별 **전 원소**의 배정 — 주 계층 1 + ★ **보조 계층(의무)** · 근거 1행 · 탐색 연결. 문서 끝에 **집계**(주 · 보조 · 계층 × 태그)와 ★ **ID 집합 diff** | 큰 대장의 뒤쪽이 조용히 빠진다(**silent failure — 이 프로젝트 실측 최다 사고 유형**). 수만 세면 **다른 ID가 들어 있어도 통과**한다 |
| **④ 게이트** | ★ **게이트를 둘로 나눈다** — **머지 게이트**(매 머지에 실행 가능하고 정본을 오라클로 쓰는 계층) / **마일스톤 게이트**(부하·다중 인스턴스 환경이 필요한 것 + 탐색) · **재실행 촉발 조건** · **머지 전 최소 안전선**과의 관계 · stakes별 강도 · 계층이 **대체하지 못하는 것** | 게이트가 하나면 *"실험이 안 끝나 머지 못 한다"* 와 *"테스트 녹색이니 머지한다"* 가 **둘 다 같은 문서를 근거로** 성립한다. 그리고 *"테스트 통과 = 검증 완료"* 로 읽혀 그린 위장(fail-open 골든·exit 마스킹)이 그대로 통과한다 |
| **⑤ 소유** | ★ **stakes 우선 선언**(계층별 기본값은 낮음·중간용이고, 높음이면 계층 무관하게 구현 diff 미열람 계약) + 계층마다 **설계 주체 / 검증 책임자 / 차단 주체** 3축 · 탐색은 **독립 판정** | 구현자가 자기 diff를 보고 테스트를 쓰면 **테스트가 구현의 사본**이 된다. 차단 주체가 없으면 red가 **무시**되고, 검증 책임자가 없으면 결과를 **아무도 읽지 않는다** |
| **⑥ 도구** | 계층이 **요구하는 성질** → 그 성질의 ★ **충족 판정 기준**(다음 단계가 도구를 고를 때 쓴다) → 후보 도구는 **도입 조건과 함께** 보류. ★ **도구 이름의 지목·등재는 개발 규약(E3) 소유** | 요구가 실증되지 않은 스택이 들어오고, 도구가 만든 문제를 도메인 문제로 오인한다(C-08). 전략 문서가 이름을 적으면 개발 규약은 **이미 정해진 것을 추인**하게 된다 |
| **⑦ [구현 검증] 연결** | IV 대장의 각 항목이 **어느 계층의 입력**인가 — ★ **재진입은 의무이며 집계에 편입한다**(주석으로만 적힌 재진입은 집계되지 않아 조용히 빠진다) · 이 문서가 **확정하지 않는 수치**의 목록 | 문서가 추측을 정본화한다(검증 정책 v2 §1의 세 번째 유형 — *"판정 = 추측의 정본화, 해롭다"*) |
| ★ **⑧ 정본 반증 처리** | 탐색이 *"정본이 틀렸을 수 있다"* 를 공식 결과로 만드는 순간 필요한 **실행자 절차** — ⑴ 불일치 분기(케이스 오독 / 구현 이탈=기본값 / **정본 반증 후보 승격**=재현 가능한 관측 필수 / 정본 충돌) ⑵ **재판정 트리거**(정본 개정 시 그 정본을 오라클로 쓴 판정이 만료 — 시간 경과는 트리거가 아니다) ⑶ **상시 회귀 승격 기준**(탐색 → 판정 태그 전환) | 실행자가 그 자리에서 **정본을 고치거나**(스코프 혼합 — R5 위반), 결과를 **조용히 버린다**. 승격 기준이 없으면 탐색이 1회성으로 끝나 같은 결함이 되돌아온다 |

## 3. 작성 규칙

| # | 규칙 |
|---|---|
| **R1** | ★ **자산 대장이 먼저다.** 계층 정의는 대장을 훑고 나서 쓴다 — 피라미드는 **결과**이지 입력이 아니다 |
| **R2** | ★ **배정은 전수이고, 전수는 "수"가 아니라 "집합"으로 보인다.** 대장별로 **정본에서 뽑은 ID 집합 ↔ 표에서 뽑은 ID 집합**을 `diff` 하고 **출력이 비어 있음**을 문서에 실행 결과로 남긴다. 원소 수만 맞추면 **다른 ID가 들어 있어도 통과**한다. 불일치 = **결함**이며 "대표 사례"로 대체하지 않는다 |
| **R3** | **배정 판별 질문 하나로 통일하되, ★ 하한을 건다** — 질문은 *"이 규칙이 틀렸다는 것을 드러내는 **가장 싼 실행 단위**는 무엇인가?"* 이고 가장 싼 곳이 주 계층이다. ★ 하한: ⑴ **트랜잭션 경계의 원자성·다중 레코드 동시 이동·순서**를 포함하면 **통합 이상**(상태 전이·원자성·순서를 인메모리 등식으로 흉내 낸 것은 그 규칙을 검증한 것이 아니다) ⑵ **물리 규격·직렬화 표면·버전 호환**이면 **계약** ⑶ 통과 기준이 **품질 시나리오의 측정 수치**면 **인수**. ⚠️ 예외는 **정적 규칙**(실행 없이 소스·스키마에서 판정)뿐이며 예외임을 표에 적는다 |
| **R4** | **주 계층은 하나만 고른다.** 걸치는 것은 보조로 적는다 — 둘 다 주로 두면 **둘 다 안 짜인다**. ★ **보조는 의무다** — 빈칸(`—`)을 남기면 *"주 하나만 짜면 된다"* 로 읽힌다. 보조도 **집계 열에 넣어** 센다(주 열만 보면 실제 작업량 분포가 반대로 보인다) |
| **R5** | ★ **정본을 재해석하지 않는다.** 검증 방법 칸·시나리오 측정 칸은 **인용하고 배정만** 한다. 문면이 틀렸다고 판단되면 배정을 멈추고 **정본 개정을 별도 작업**으로 올린다(스코프 혼합 금지). ★ 실행 중 불일치가 났을 때의 분기·승격 경로는 필수 칸 ⑧이 소유한다 |
| **R6** | ★ **수치를 확정하지 않는다.** 커버리지 목표·성능 목표는 `[미확정]` 또는 `[구현 검증]`이다. 성능 수치는 **품질 시나리오가 이미 소유**하고 있으므로 테스트 전략이 새로 정하면 정본이 둘이 된다 |
| **R7** | **도구는 마지막 칸이고, ★ 이 문서가 소유하는 것은 「성질」까지다.** 계층이 요구하는 **성질**과 그 **충족 판정 기준**을 적고, **도구 이름의 지목·등재는 개발 규약(E3)** 에 넘긴다. 넣지 않기로 한 도구는 ★ **도입 조건**을 함께 적는다(C-08 — *"나중에 필요하면"* 은 판정 불가) |
| **R8** | ★ **게이트는 계층으로 대체되지 않고, ★ 하나로 두지도 않는다.** 머지 전 최소 안전선(스모크·기존 테스트·diff self-review·rollback 판단·public contract 영향·반증 질문)은 **stakes 무관 유지**다(검증 정책 v2 **V2-5**의 명시적 존치 항목). 그 위에 **머지 게이트 / 마일스톤 게이트**를 분리하고, 마일스톤 게이트가 **머지를 막지 않게** 한다 — 막으면 인수·탐색이 *"머지 전에 통과시켜야 할 것"* 이 되어 **통과하도록 약하게 쓰인다** |
| **R9** | **어느 계층으로도 못 가는 자산은 `[구현 검증]`으로 이연하고 중앙 대장에 등재한다**(V2-3). 무음 이연은 금지 — 태그와 대장 등재가 같은 커밋에 있어야 한다. ★ **이연된 항목의 재진입도 의무다** — 되돌아가는 계층을 **주 계층으로 배정하고 집계에 넣는다.** ★ 배정 중 **대장에 없는 자산 유형**(예: 계약 표면을 피고로 세우는 탐색 자산)이 드러나면 **승격 후보로 열린 의문에 등재**하고, **이번 배정에서 만들지 않는다** — 만들면 *"새 검증 항목을 만들지 않는다"* 전제를 스스로 깬다 |
| ★ **R10** | **red-first는 조건부다.** *"테스트가 구현보다 먼저 실패해야 한다"* 를 그대로 쓰면 **감도 0인 테스트도 red**다. ⑴ 변경 전 코드에서 **실행 가능**해야 판정할 수 있다 ⑵ red의 원인이 **규칙 위반**이어야 한다(컴파일 실패·NPE·미구현 예외는 red가 아니다) ⑶ ★ **감도 증명** — green이 된 뒤 **규칙을 일시 반전**시키면 다시 red가 되어야 한다. 아니면 그 케이스는 규칙을 안 건드린다. ⚠️ **높음 stakes 한정** — 확대하면 테스트가 아니라 의식이 된다 |
| ★ **R11** | **ID 접두어 규범은 이 문서 안에서만 유효하다.** 여러 출처가 같은 ID 형태를 쓸 때 배정 표는 접두어로 구분하되, ⑴ **출처 문서의 원 ID는 바꾸지 않는다**(R5) ⑵ **다른 문서·커밋 메시지에 접두어를 강제하지 않는다**(강제하려면 정본 개정 = 별도 판단) ⑶ **같은 형태의 다른 네임스페이스**(예: 규격 항목 번호)는 규범 대상이 아니며 **문맥을 붙여** 적는다 |

## 4. 교과서 5장 대응

| | |
|---|---|
| 대응 장 | **5장 「품질 보증과 테스트」** (`reference/architect-textbook-toc.md` 전체 장 구성 — 본 프로젝트에서의 쓰임 = *"검증 전략(후속)"*) |
| ⚠️ **절 단위 대응** | ★ **[미확인]** — 저장소의 목차 판독본은 **2~4장만** 절·소절을 담고 있고 **5장은 장 제목까지만** 확보돼 있다. 따라서 이 양식은 *"5.x 어느 절에 대응한다"* 를 **주장하지 않는다.** 절 대응이 필요해지면 책 실물에서 5장 목차를 판독해 이 절을 채운다 |
| 대응의 성격 | 교과서가 **개발 주기 뒤에 두는 품질 보증**을, 이 프로젝트는 **구현 전 마지막 문서화 사이클(E2)** 로 당겨 놓는다. 이유는 `01-entry-procedure.md` §1과 같다 — 자산이 이미 쌓여 있어 **배정만 하면 되는 상태**이고, 배정을 구현 뒤로 미루면 **구현 diff가 테스트 설계의 입력**이 되어 절단선(⑤)이 깨진다 |

## 5. 자기 점검 (이 문서가 끝났다고 말할 수 있는 조건)

- [ ] 필수 칸 ①~⑧이 전부 채워졌다 (한 칸이라도 비면 아직 초안)
- [ ] 계층이 **4단 이하**이고, 오라클 축은 **태그**로 분리돼 있다 (①-b — 탐색이 계층 자리를 차지하지 않는다)
- [ ] 탐색 태그 자산이 **전부 ①~④ 중 한 계층에 배정**돼 있다 (계층 면제 0건)
- [ ] 자산 대장별 **집계표**가 문서 끝에 있고, **주 배정 = 원소 수**이며 **보조 배정 = 원소 수**다 (R4)
- [ ] ★ **ID 집합 `diff` 명령과 실행 결과(출력 없음)** 가 문서에 있다 (R2 — 수만 센 집계는 통과가 아니다)
- [ ] 배정 판별 질문(R3)이 **한 개**이고, **하한 규칙**이 함께 적혀 있으며, 하한이 실제로 움직인 항목이 지목돼 있다
- [ ] 게이트가 **머지 / 마일스톤**으로 분리돼 있고 **재실행 촉발 조건**이 적혀 있다 (R8)
- [ ] 소유 표에 **stakes 우선 선언**과 **설계 주체 / 검증 책임자 / 차단 주체** 3축이 있다 (⑤)
- [ ] 확정한 수치가 **0개**다 (R6 — 성능 수치는 QS 인용, 커버리지는 [미확정])
- [ ] **도구 이름을 지목하지 않았다** (R7 — 성질과 충족 판정 기준까지). 도입하지 않은 도구마다 **도입 조건**이 적혀 있다
- [ ] 어느 계층에도 못 간 자산이 `[구현 검증]` 태그 + 중앙 대장에 있고, **재진입 계층이 집계에 들어 있다** (R9)
- [ ] 정본 문서를 **한 줄도 고치지 않았다** (R5)
