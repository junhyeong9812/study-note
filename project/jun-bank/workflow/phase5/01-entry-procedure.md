## 2. ★ 도구 최소주의 (2026-08-06 확정 — 두 번째 실측 개선)

**순서 강제: 요구(불변식) → 계약 → 도구.** 도구는 마지막에, 갈아끼울 수 있게.

- **v1 스택 = 현 정본이 이미 요구하는 것만.** 후보 도구마다 **도입 조건을 명시**하고, 조건이 실증되기 전에는 넣지 않는다(불도입도 ADR로 남긴다 — 재개 조건 포함).
- 실측 근거: Phase 5 아키텍처 스케치에서 Kafka를 제외하자 선검증 결함 6건(드레인 축·파티션 오독·fencingToken 경유·watermark 등)이 **자동 소멸**했다 — 도구가 만들던 문제였다. 브로커 도입 시 꺼낼 설계는 ADR-021 부록에 "예약된 설계"로 보존(만들어 본 것은 버리지 않고 뽑아쓸 수 있게).
- 판별 질문: *"이 도구가 풀 문제가 지금 여기 있는가?"* — 없으면 도입 조건만 적고 넘어간다.

## 3. 스케치 선검증 (검증 정책 v2 V2-1의 실행 형태 — 이 단계에서 특히)

아키텍처는 **스케치(scratchpad) → 듀얼 선검증(Opus ∥ codex — 기존 ADR 충돌·경계 공격) → 판정 병합 → 그 다음에야 ADR 본문**. 실측: C7 선검증 치명 6건·아키텍처 선검증 차단 3건+27건이 전부 본문 작성 전에 잡혔다 — 재작성 비용 0.
