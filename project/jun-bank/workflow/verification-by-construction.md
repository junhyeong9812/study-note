# 검증을 주의력에서 구조로 옮기기

> **왜 문서를 표로 만들고 스크립트로 돌리는가.**
> 이 문서는 Phase 2 리뷰 7라운드의 실측에서 나왔다 — 근거는 `docs/design-changes/DC-001-review-log.md`.

---

## 1. 무엇이 반복됐나

7라운드 동안 결함이 **89건** 나왔고 치명이 **22건**이었다. 그런데 마지막 세 라운드의 결함은 성격이 하나로 수렴했다.

| 유형 | 예 |
|---|---|
| **목록에서 하나 빠짐** | E2 참여자에 카드가 없다 · E4에 회수 대상 미수가 없다 · `Discrepancy`에 M9·M10이 없다 |
| **한 곳만 고침** | 기준소스는 고치고 파생은 안 고침 · §8.1은 정정하고 하단은 그대로 |
| **선언과 실제가 다름** | *"● 2개 이상인 행은 7개"* ← 실제 10개 · *"어긋나는 구간이 없다"* ← 검증 안 함 |

**셋 다 "생각을 잘못한 것"이 아니라 "대조를 안 한 것"이다.**

---

## 2. 실측 — 세 번의 같은 실패

| 시점 | 기록에 남긴 말 | 실제 |
|---|---|---|
| 단계 2 | 커밋 메시지 *"E3 재작성 · E4 신설"* | **안 바뀜** (치환이 조용히 실패) |
| 단계 10b | 커밋 메시지 *"E3를 계좌+미수들로 교체"* | **또 안 바뀜** |
| 단계 12 | 표에 *"● 2개 이상인 행은 7개"* | **실제 10개** |

> ★ **세 번 다 "했다"고 믿은 상태였다.** 안 했다는 것을 몰랐다.

---

## 3. 왜 주의력 기반 검증이 실패하는가

### 읽은 것과 대조한 것은 다르다

문서를 읽으면 **이해한 느낌**이 생긴다. 그런데 *"18행 중 몇 행을 실제로 대조했는가"* 는 그 느낌에 들어 있지 않다. 둘을 구분하는 신호가 없으므로 **확신을 가지고 틀린다.**

| | 사람 | 문서를 다루는 도구(AI 포함) |
|---|---|---|
| 대충 본 것을 자각하나 | 비교적 자각한다 | **자각하지 못한다** |
| 틀렸을 때의 확신 | 낮아진다 | **그대로 높다** |
| 반복 대조의 정확도 | 낮다 | **낮다** |

> **마지막 행이 핵심이다.** 이건 도구 특유의 결함이 아니라 **반복 대조라는 작업 자체의 한계**다. 사람 구현자도 18행짜리 표를 매번 정확히 대조하지 않는다.

### 리뷰를 한 번 더 도는 것으로는 안 된다

라운드를 늘리면 **다른 항목이 빠진다.** 실측:

```
R5  E4가 예외 목록에 아예 없다        → 예외를 신설했다
R6  E4 목록에 회수 대상 미수가 빠졌다  → 참여자를 추가했다
R7  E4 목록에 매입 배치가 빠졌다      → ???
```

**같은 자리, 형태만 바뀌며 네 번.** 리뷰어를 바꿔도, 둘로 늘려도 같았다.

---

## 4. 대안 — 판정을 실행으로 옮긴다

**"빠진 것을 알아채라"** 를 **"빈 칸이 곧 결함이다"** 로 바꾼다.

| 주의력 기반 | 구조 기반 |
|---|---|
| 문서를 읽고 빠진 걸 찾는다 | 표를 채우고 **빈 칸을 본다** |
| 리뷰어의 집중력에 의존 | **행·열이 자동 생성**되어 누락이 불가능 |
| "확인했다"가 주장 | "확인했다"가 **스크립트 종료 코드** |

### 효과 (실측)

단계 12에서 변경 매트릭스를 그리자 **즉시 세 개**가 나왔다 — E2의 카드 · E4의 회수 대상 · E5 자체. **그전 세 라운드 동안 사람 리뷰로 하나씩 나오던 것들**이다.

---

## 5. 그러나 표를 만드는 것만으로는 부족하다

R7이 이것을 정확히 잡았다. 단계 12의 스크립트는 *"● 2개 이상인 행의 마지막 칸에 E1~E5 문자열이 있는가"* 만 검사했고, 그래서:

| 실제 결함 | 스크립트 |
|---|---|
| 켜져야 할 칸이 **꺼져 있음** | ✅ 통과 |
| 조작이 **표에서 빠짐** | ✅ 통과 (행이 없으니 검사 대상 아님) |
| 애그리게이트 **열이 없음** | ✅ 통과 |

**형태만 구조 기반이고 실제로는 주의력에 의존했다.** 그리고 스크립트가 통과했다는 신호가 나오므로 **사람 리뷰보다 위험했다** — 거짓 안심.

### 기계 검산이 성립하는 조건

| # | 조건 | 안 지키면 |
|---|---|---|
| **①** | **행·열을 문서에서 생성**한다 (손으로 쓰지 않는다) | 빠진 행은 영원히 검사되지 않는다 |
| **②** | 각 칸의 값을 **정본과 대조**한다 (칸이 있다는 것만 보지 않는다) | 꺼진 칸을 못 잡는다 |
| **③** | 참조하는 집합(경계·유형·번호)을 **기계 판독 가능한 형태**로 둔다 | 사람이 읽어 비교하게 되고, 그건 다시 주의력이다 |
| **④** | **실패를 검출**하도록 쓴다 — "사라져야 할 것이 0건인가" | 치환이 조용히 실패한다 |

## 6. 무엇을 기계가 잡고 무엇을 못 잡나

| 기계가 잡는다 | 사람이 잡아야 한다 |
|---|---|
| 목록 누락 · 차집합 | **논리 오류** (전제-결론 불일치, 사후 합리화) |
| 심볼 잔재 · 없는 번호 참조 | **자금 보존 반례** (시나리오를 숫자로 굴리기) |
| 선언값과 실제의 불일치 | **"문서에 없는 것"** — 빠져나올 수 없는 상태, 없는 능력 |
| 표 구조 정합 | **경계가 옳은가** (판정 자체) |

> ★ **기계화는 사람 리뷰를 대체하지 않는다.** 사람이 **판단**에 집중할 수 있게 **대조**를 덜어내는 것이다. 실측에서도 논리 오류 7유형 중 6유형은 사람 리뷰만 잡았다.

### 판별 기준

```
결함이 "목록에서 하나 빠졌다" 계열로 수렴하면
   → 리뷰를 한 번 더 돌릴 문제가 아니라 검산을 기계화할 문제다

결함이 "이 판단이 틀렸다" 계열이면
   → 기계로 안 된다. 사람 리뷰를 돌린다
```

### 기계화가 실제로 일어났는지 재는 법

첫 시도는 **"스크립트가 잡은 결함 > 사람이 잡은 결함"** 이었다. **이 기준은 틀렸다.**

```
절차:  스크립트를 먼저 돌린다 → 잡힌 것을 고친다 → 통과 → 사람 리뷰
결과:  측정 라운드의 스크립트 점수는 구조적으로 항상 0이다
       0 > N 은 항상 거짓이고, 0 > 0 도 거짓이라
       ★ 결함이 하나도 없는 문서에도 "기계화 실패" 판정이 난다
```

> **성공이 불가능한 기준은 기준이 아니다.** 이것을 잡은 것은 사람 리뷰였다 —
> 기준을 세운 사람은 자기 기준의 산술을 검산하지 않는다.

**대신 둘로 나눠 잰다.**

#### ① 커버리지 — 사람이 잡은 것 중 기계가 잡을 수 있었던 비율

```
커버리지 = (사람이 잡은 결함 중 기계 검산 가능한 것 중, 스크립트가 실제로 잡은 것)
           ────────────────────────────────────────────────────────────
           (사람이 잡은 결함 중 기계 검산 가능한 것)
```

**분모에서 "사람만 잡을 수 있는 것"(논리·자금 보존·판단의 옳음)을 뺀다.**
그것까지 기계에 요구하면 분모가 영원히 안 채워지고, 그 기준도 성공 불가능해진다.

| 커버리지 | 뜻 |
|---|---|
| 낮다 | 검사가 **덜 만들어졌다** — 잡을 수 있었는데 안 잡았다 |
| 높다 | 검사가 따라잡았다 — 다음 라운드는 사람이 **판단**에 집중한다 |

#### ② 변이 검사 — 과거 결함을 되돌려 넣고 잡히는지 본다

커버리지만으로는 **다음 라운드에 안 나온 결함**을 못 잰다. 그래서:

```
지금까지 나온 치명 결함을 하나씩 문서에 다시 주입한다
   → 스크립트가 잡으면 ✅
   → 통과하면 그 검사는 존재하지 않는 것이다
```

> ★ **R7 U1이 이것을 손으로 했다** — *"R6가 잡은 치명 3건을 되돌려도 전부 통과한다"*.
> 그 한 문장이 단계 12의 스크립트가 **형태만 구조 기반**임을 증명했다.
> 손으로 할 수 있으면 스크립트로도 할 수 있다.

---

## 7. 부수 효과 — 도구가 다루기 쉬워진다

표와 기계 판독 가능한 목록은 **문서를 다루는 도구가 정확해지는** 부수 효과가 있다. 다만 이것은 **목적이 아니라 결과**다.

목적은 하나다 — **"확인했다"를 주장이 아니라 실행 결과로 만드는 것.**
