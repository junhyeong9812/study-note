# 컨텍스트 맵 — 양식과 작성법

---

## 1. 목적

**경계를 확정하고, 경계를 넘는 관계와 데이터 소유권을 정한다.**

이벤트 스토밍이 컨텍스트 **후보**를 냈다면, 컨텍스트 맵은 그것을 **확정하고 관계를 정의**한다.

> **이 문서의 실질은 두 가지다.**
> 1. **데이터 소유권** — 각 데이터의 주인이 정확히 하나인가
> 2. **관계 유형** — 경계를 넘을 때 누가 누구에게 맞추는가
>
> 이 둘이 정해지지 않은 채 서비스를 나누면, 같은 데이터가 두 곳에 저장되고 아무도 진실이 아니게 된다.

## 4. 작성법

### 관계 유형 — DDD 표준 7종

| 유형 | 뜻 | 언제 쓰나 |
|---|---|---|
| **파트너십 (Partnership)** | 함께 성공/실패. 긴밀히 조율 | 두 컨텍스트가 서로 없으면 의미 없을 때 |
| **공유 커널 (Shared Kernel)** | 모델 일부를 공유 | 공유 비용 < 중복 비용일 때. **가장 위험한 관계** |
| **고객-공급자 (Customer-Supplier)** | 하류가 상류에 요구할 수 있다 | 상류가 하류 요구를 반영할 의사가 있을 때 |
| **순응자 (Conformist)** | 하류가 상류 모델을 그대로 받는다 | 상류를 바꿀 수 없고 번역 비용도 아까울 때 |
| **부패 방지 계층 (ACL)** | 상류 모델이 침투하지 않게 번역 | **외부 시스템 연동의 기본값** |
| **공개 호스트 서비스 (OHS)** | 공개 프로토콜로 다수에게 제공 | 소비자가 여럿일 때 |
| **각자의 길 (Separate Ways)** | 통합하지 않는다 | 통합 비용 > 이득일 때 |

**선택 요령**:

```
상대가 외부 시스템인가?
 └ 예 → 부패 방지 계층 (ACL). 예외 없이.
 └ 아니오 ↓
소비자가 여럿인가?
 └ 예 → 공개 호스트 서비스 (OHS)
 └ 아니오 ↓
하류가 상류에 요구할 수 있는 관계인가?
 └ 예 → 고객-공급자
 └ 아니오 → 순응자
```

> **공유 커널은 마지막 수단이다.** 모델을 공유하면 두 컨텍스트가 **같이 배포**되어야 한다. 경계를 나눈 이유가 사라진다.

### 데이터 소유권 정하는 법

**질문 하나로 결정된다: "이 데이터를 변경할 권한이 있는 곳은 어디인가?"**

| 상황 | 판단 |
|---|---|
| 한 곳만 변경한다 | 그곳이 소유자 |
| 여러 곳이 변경한다 | **경계가 잘못됐다.** 다시 나눈다 |
| 여러 곳이 읽기만 한다 | 변경하는 곳이 소유자, 나머지는 복제본 |

**복제본을 두기로 했다면 반드시 명시할 것**:
- 어떻게 동기화되는가 (이벤트 / 주기 조회)
- **얼마나 늦어도 되는가**
- 불일치가 발견되면 **무엇이 진실인가**

> **가장 흔한 실패**: 같은 데이터를 두 곳에서 각각 "정본"이라고 생각하는 것. 그 순간부터 두 값은 조용히 갈라진다.

### 다이어그램 그리는 법

- **화살표는 의존 방향**(하류 → 상류). 데이터 흐름과 반대일 수 있으니 **범례 필수**
- 각 화살표에 **관계 유형을 라벨로** 단다
- 외부 시스템은 다른 모양·색으로 구분
- Mermaid 또는 PlantUML로 **텍스트 관리**한다 (이미지는 낡는다)

### 경계 근거 쓰는 법

**"왜 나누는가"보다 "왜 합치지 않는가"가 더 중요하다.** 나누는 이유는 쉽게 나오지만, 합치지 않는 이유를 못 대면 그 경계는 근거가 약한 것이다.

```
| 결제 ↔ 원장 | 결제는 실시간·거절 가능, 원장은 append-only·거절 불가 |
              | 합치면 원장의 불변식이 실시간 응답 SLA에 끌려간다 |
              | 승인 응답을 위해 원장 기록을 건너뛰는 우회가 생긴다 |
```

## 5. 흔한 실수

| # | 실수 | 왜 문제인가 | 고치는 법 |
|---|---|---|---|
| 1 | **데이터 소유자가 둘** | 조용히 갈라진다 | 하나로 정하고 나머지는 복제본으로 명시 |
| 2 | **관계 유형을 안 정함** | 통합 방식이 구현자 재량이 된다 | 7종 중 하나를 고르고 근거를 쓴다 |
| 3 | **외부 시스템에 ACL 없음** | 외부 모델이 도메인에 침투한다 | 외부는 무조건 ACL |
| 4 | **공유 커널 남용** | 배포가 묶인다 | 중복을 감수하고 나눈다 |
| 5 | **컨텍스트 = 서비스로 가정** | Phase 3의 판단을 미리 해버린다 | 컨텍스트는 논리 경계, 서비스는 배포 단위. **여기선 논리만** |
| 6 | **화살표 방향을 데이터 흐름으로** | 의존 방향을 오해한다 | 범례를 달고 의존 방향으로 통일 |
| 7 | **복제본의 지연 허용치 미정** | 구현 시 임의로 정해진다 | "몇 초까지 늦어도 되는가"를 적는다 |

## 6. 완료 기준

- [ ] 모든 컨텍스트에 **한 문장 책임**이 있다
- [ ] 모든 관계에 **7종 중 하나의 유형**과 근거가 있다
- [ ] **모든 데이터에 소유 컨텍스트가 정확히 하나**다
- [ ] 복제본이 있는 데이터마다 **동기화 방식·허용 지연·진실의 출처**가 적혀 있다
- [ ] 외부 시스템과의 관계가 **전부 ACL**이다 (아니라면 이유가 있다)
- [ ] 각 경계에 **"왜 합치지 않는가"** 가 적혀 있다
- [ ] 다이어그램에 **범례**가 있다
- [ ] 이 문서만 보고 **"이 서비스가 저 데이터를 직접 고쳐도 되나"** 에 답할 수 있다
