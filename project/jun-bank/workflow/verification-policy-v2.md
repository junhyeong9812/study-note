# 검증 정책 v2 — 문서 설계 단계의 리뷰 재조정

- 상태: ★ **확정** (2026-08-06 사용자 합의 — `plans/2026-08-06/verification-policy-v2/`)
- 대체: 문서 작업에 대한 종전 관행(코드용 강도표 그대로 적용 — 높음 = 듀얼 리뷰 3루프)

---

## 1. 왜 바꾸나 (실측 근거 — 2026-08-06 세션)

계약 전수·C7 명세의 리뷰 지적 전수를 유형별로 나눈 결과:

| 유형 | 비중 | 판정 |
|---|---|---|
| **구조·불변식 결함** (권한 세탁 경로 · resume 권한 부활 · 경계 충돌 · 이중 적재) | ~25% | **문서 단계가 우위** — 테스트는 생각해낸 경로만 검증한다. 구현 후 발견 = 재설계 비용 |
| **동기화·표기·색인** (버전 충돌 · 색인 미갱신 · 문구 불일치 · 잔재) | ~60% | **구현이 공짜로 잡는다** — 문서 단계에서는 사람이 산문을 grep해야 한다 |
| **구현 접촉 전 판정 불가** (캐시 수명 · 페이징 · 판정 비용 · 코드 세부) | ~15% | 문서 판정 = **추측의 정본화** — 해롭다 |

수익 최고 지점은 루프가 아니라 **스케치 선검증**이었다 — C7 치명 6건을 본 작성 전에 차단(재작성 비용 0). 문서에는 "green"이 없어 루프 종료 조건(신규 0)이 사실상 오지 않는다.

## 2. 정책 (문서 설계 산출물에 적용 — 실행물·tools는 종전 core §4 그대로)

| # | 규칙 |
|---|---|
| **V2-1** | **문서 작업의 리뷰 상한 = 스케치 선검증 + 듀얼 1패스.** 3루프 폐지. 선검증은 신설 정본·불변식 덩어리(권한·자금·경계 모델)에 의무 — 모델 스케치를 작성 전에 듀얼 검증한다 |
| **V2-2** | **리뷰 렌즈에서 동기화·표기·색인류 제외.** 이 유형은 ① 검산 도구(check_docs 계열)가 잡거나 ② [구현 검증]으로 이연한다. 리뷰어 프롬프트에 명시: *"버전·색인·문구 동기화는 지적 대상이 아니다 — 구조·불변식·판정 충돌만"* |
| **V2-3** | **[구현 검증] 태그** — 문서에서 판정하지 않는(못 하는) 항목의 공식 출구. 각 문서 의문 표에 `[구현 검증]` 표기 + **중앙 대장(`docs/implementation-verification.md`)에 같은 커밋 등재**(C-6 색인 선례). 구현 착수 시 그 대장이 실험·테스트 목록의 입력이 된다 |
| **V2-4** | **종료 조건 = 채택된 구조 결함 전부 fixed + 타깃 재점검 1회.** 재점검이 새 구조 결함을 내면 그것만 수정하고 종료 — 재재점검 없음 |
| **V2-5** | **유지되는 것**: 머지 전 최소 안전선(검산·diff self-review·반증 질문) · 게이트·spec·log · 선검증 · 정직 보고. 이번 세션의 실질 가치(자금 결함·무음 실패 적발)의 출처라 축소 대상이 아니다 |
| **V2-6** | 판정이 필요하지만 답의 근거가 문서 안에 있는 것(정본 충돌·판정 공백)은 종전대로 사용자 합의 — [구현 검증]은 **근거가 구현 접촉에만 있는 것** 한정. 헷갈리면 질문: *"이 답이 틀렸다는 걸 문서만 읽고 알 수 있나?"* — 알 수 있으면 문서 판정, 없으면 이연 |
