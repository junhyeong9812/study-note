# 제약 명세 양식

---

## 1. 목적

**우리가 고를 수 없는 것을 먼저 적는다.**

제약을 안 적으면 **고를 수 없는 안을 놓고 논의**하게 되고, 그 논의는 전부 버려진다.
제약은 선택지를 좁히는 것이 일이지 설계를 정하는 것이 일이 아니다.

> ★ **제약과 품질 속성은 다르다.** 제약은 **협상 불가**이고, 품질 속성은 **우리가 고른 것**이다.
> 이것을 섞으면 *"성능이 제약이다"* 같은 말이 나오고, 그러면 **포기할 수 없게 된다.**

---

## 2. 독자

| 누가 | 무엇을 위해 |
|---|---|
| 아키텍처 결정자 | 검토할 필요 없는 안을 **미리 제거** |
| 신규 참여자 | *"왜 이 뻔한 방법을 안 썼나"* 에 대한 답 |
| 이해관계자 | 제약을 **바꿀 수 있는지** 협상하기 위해 |

## 4. 작성법

### 종류를 먼저 가른다

| 종류 | 예 | 특징 |
|---|---|---|
| **기술** | 사내 표준 런타임, 기존 시스템과의 프로토콜 | 시간이 지나면 바뀔 수 있다 |
| **조직** | 팀 규모·기술 숙련도, 운영 인력 없음 | **가장 자주 무시되고 가장 자주 실패 원인이 된다** |
| **법·규제** | 데이터 보관 기간, 국외 이전 금지 | 협상 불가인 경우가 많다 |
| **비용** | 인프라 예산 상한 | 수치로 적을 수 있다 |
| **일정** | 특정 일자 이전 오픈 | 범위를 줄이는 근거가 된다 |

> ★ **조직 제약을 빠뜨리지 마라.** *"운영 인력이 없다"* 는 곧 *"복잡한 운영이 필요한 구조를
> 고를 수 없다"* 는 뜻이다. 이것을 안 적으면 **운영할 수 없는 아키텍처**를 고른다.

### 제약인지 판별하는 법

```
이것을 어기면 무슨 일이 일어나는가?
  → 법·계약 위반, 예산 초과, 물리적으로 불가       → 제약
  → "느려진다 / 불편해진다 / 비용이 는다"           → 제약이 아니라 품질 속성
  → 답이 안 나온다                                  → 근거 없는 관행. 제약이 아니다
```

> ⚠️ **"우리 회사는 원래 이렇게 한다"는 제약이 아니다** — 출처를 못 대면 §2에 넣는다.
> 진짜 제약이면 **누가 언제 정했는지**를 댈 수 있다.

### "무엇을 못 하게 되나"를 반드시 채운다

제약을 적는 이유는 **선택지를 지우기 위해서**다. 지워지는 것이 없으면 그 제약은 적을 필요가 없다.

```
C-01  운영 인력이 없다 (조직)
      → 제거: 수동 개입이 필요한 배치 · 운영 콘솔이 필요한 복구 절차
      → 남는 것: 자동 재시도 + 실패 시 알림
```

### 협상 가능성을 적는다

| 값 | 뜻 | 다음 행동 |
|---|---|---|
| **불가** | 법·물리 | 받아들이고 설계한다 |
| **조건부** | 근거를 대면 예외 가능 | §3에 시도 기록을 남긴다 |
| **가능** | 관행일 뿐 | **먼저 협상한다.** 제약을 하나 없애는 것이 설계를 잘하는 것보다 싸다 |

## 5. 흔한 실수

| # | 실수 | 왜 문제인가 | 고치는 법 |
|---|---|---|---|
| 1 | **품질 속성을 제약으로 적음** | 포기할 수 없게 되어 트레이드오프가 불가능해진다 | *"어기면 무슨 일이"* 로 판별한다 |
| 2 | **조직 제약 누락** | 운영할 수 없는 구조를 고른다 | 팀 규모·숙련도·운영 인력을 반드시 적는다 |
| 3 | **출처 없는 제약** | 아무도 안 정한 것이 설계를 묶는다 | 출처를 못 대면 §2로 옮긴다 |
| 4 | **"무엇을 못 하게 되나" 빈칸** | 제약이 선택지를 안 지운다 = 적을 이유가 없다 | 제거되는 안을 구체적으로 |
| 5 | **협상 시도 없이 받아들임** | 없앨 수 있는 제약을 지고 간다 | *가능*·*조건부*는 먼저 협상 |
| 6 | ★ **제약을 나중에 발견** | 설계를 다시 한다 | Phase 3 **첫 문서**로 쓰는 이유가 이것이다 |

---

## 6. 완료 기준

- [ ] 각 제약에 **종류·출처·협상 가능성**이 있다
- [ ] 각 제약에 **무엇을 못 하게 되는지**가 구체적으로 적혀 있다
- [ ] **조직 제약**(팀 규모·숙련도·운영 인력)이 최소 1개 있다
- [ ] 출처를 못 대는 것은 **§2 제약이 아닌 것**으로 옮겨져 있다
- [ ] *협상 가능* · *조건부* 제약에 **시도 기록**이 있다 (안 했으면 그 사실을 적는다)
- [ ] 제약 중 **품질 속성인 것**이 없다 (*"어기면 무슨 일이"* 로 전수 점검)
