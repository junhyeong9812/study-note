# 품질 시나리오 양식

---

## 1. 목적

**품질 속성을 측정 가능한 문장으로 바꾼다.**

*"응답이 빨라야 한다"* 는 검증할 수 없다. *"승인 요청 3,000 TPS에서 p99 응답이 300ms 이하"* 는
검증할 수 있다. **이 문서는 그 변환을 강제한다.**

> ★ **Phase 2가 미룬 수치가 여기서 근거를 얻는다.** TTL·보관 기간·재시도 임계 같은 것들이
> *"미확정"* 으로 남아 있는데, **품질 시나리오가 그 값의 출처**다.
> 여기서 안 정하면 근거 없는 상수가 코드에 박힌다.

## 4. 작성법

### 여섯 칸을 전부 채운다

```
출처 → 자극 → [환경] → 대상 → 응답 → 측정
```

| 칸 | 비면 무슨 일이 |
|---|---|
| **출처** | 누구를 막을지 몰라 방어 지점을 못 정한다 |
| **자극** | 무엇을 재현할지 몰라 테스트를 못 짠다 |
| **환경** | *"평시 300ms"* 인지 *"장애 중 300ms"* 인지에 따라 **설계가 완전히 다르다** |
| **대상** | 어느 컴포넌트의 책임인지 모른다 |
| **응답** | 성공의 정의가 없다 |
| **측정** | **검증 불가.** 시나리오가 아니다 |

> ★ **환경 칸이 가장 자주 비고 가장 비싸다.** 평시 기준으로 설계하면 피크에 무너지고,
> 피크 기준으로 설계하면 평시에 과투자한다.

### 측정은 "수치 + 단위 + 지점"이다

| 나쁨 | 좋음 |
|---|---|
| 빠르게 | **p99 300ms** |
| p99 300ms | p99 300ms, **매입사 게이트웨이 수신~응답 구간** |
| 항상 정확 | **영업일 마감 후 대사에서 불일치 0건** |

**지점이 없으면 측정할 때마다 다른 값이 나온다.**

### 근거를 반드시 적는다

```
근거 없음   "p99 300ms"                     ← 왜 300인가? 아무도 모른다
근거 있음   "p99 300ms — 매입사 규약상 타임아웃 500ms.
             재시도 여유를 두려면 우리 몫은 300 이하"
```

> ⚠️ **근거 없는 수치는 나중에 아무도 못 바꾼다.** 낮추자니 왜 300이었는지 모르고,
> 올리자니 근거가 없다. **바꿀 수 없는 상수가 된다.**

### 수치 근거 대장 — Phase 2의 미확정을 여기서 닫는다 ★

Phase 2 인계 문서의 *"수치 미확정"* 항목을 **전부 이 대장에 올린다.**

```
| 상수                    | 값     | 출처 시나리오 | 미정이면 왜 |
| 취소 예약 TTL           | 90초   | QS-03        | — |
| 멱등키 보관 기간         | 미정   | —            | 매입사 재전송 정책 확인 필요 (Phase 4) |
```

> **미정이어도 대장에 올린다.** 올라와 있으면 *"아직 안 정했다"* 가 보이고,
> 대장에 없으면 **구현자가 임의로 정한 값이 그대로 굳는다.**

### 몇 개를 쓰나

**채택한 품질 속성마다 최소 1개.** 그리고 다음 셋은 **거의 항상** 필요하다:

| 유형 | 왜 |
|---|---|
| **피크 부하** | 평시만 재면 무너지는 지점을 모른다 |
| **의존 대상 장애** | 외부가 죽었을 때의 응답이 정의돼야 한다 |
| **복구** | 죽은 뒤 얼마 만에 정상으로 돌아오나 |

## 5. 흔한 실수

| # | 실수 | 왜 문제인가 | 고치는 법 |
|---|---|---|---|
| 1 | **측정 칸에 형용사** | 검증 불가 | 수치 + 단위 + 지점 |
| 2 | **환경 미기재** | 평시/피크/장애가 섞여 설계가 흔들린다 | 환경을 명시하고, 필요하면 시나리오를 나눈다 |
| 3 | **근거 없는 수치** | 나중에 못 바꾼다 | 업무·계약·관측에서 도출 |
| 4 | **측정 지점 없음** | 잴 때마다 값이 다르다 | 구간을 명시 |
| 5 | **장애 시나리오 없음** | 정상 경로만 설계된다 | 의존 대상 장애를 최소 1개 |
| 6 | **속성과 연결 안 됨** | 왜 이걸 재는지 모른다 | `02`의 속성 ID를 단다 |
| 7 | ★ **Phase 2의 미확정 수치를 안 가져옴** | 구현자가 임의로 정한다 | **수치 근거 대장**에 전부 올린다 |

## 6. 완료 기준

- [ ] 각 시나리오에 **여섯 칸**(출처·자극·환경·대상·응답·측정)이 전부 있다
- [ ] 측정이 **수치 + 단위 + 지점**으로 적혀 있다
- [ ] 각 시나리오에 **측정 방법**과 **근거**가 있다
- [ ] `02`의 **채택 속성마다 시나리오가 최소 1개** 연결돼 있다
- [ ] **피크 부하 · 의존 대상 장애 · 복구** 시나리오가 각각 최소 1개 있다
- [ ] ★ **Phase 2 인계의 수치 미확정 항목이 전부 수치 근거 대장에 올라와 있다** (미정이면 미정 사유와 함께)
