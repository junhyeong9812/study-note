## 1. 목적

**되돌리기 어려운 결정을 근거·대안·되돌리는 조건과 함께 남긴다.**

몇 달 뒤 *"왜 이렇게 했지"* 에 답하는 것이 절반이고,
**"언제 다시 열어야 하는지"** 를 남기는 것이 나머지 절반이다.

> ★ **결론만 남기면 같은 논의를 처음부터 다시 한다.** 이 프로젝트는 Phase 2에서
> 그것을 이미 겪었다 — 의문을 닫으며 결론만 적었다가 **선택지와 기각 이유를 다시 복원**해야 했다.

## 4. 작성법

### 무엇을 ADR로 쓰나

```
이 결정을 6개월 뒤에 바꾸려면 무엇이 필요한가?
  → 데이터 이관 · 서비스 재분할 · 계약 변경           → ★ ADR 필수
  → 코드 여러 곳 수정                                  → ADR 권장
  → 파일 하나 수정                                     → 안 쓴다
```

| ADR로 쓴다 | 안 쓴다 |
|---|---|
| 서비스 경계 · 데이터 소유 위치 | 로깅 라이브러리 |
| 동기/비동기 · 일관성 모델 | 커넥션 풀 크기 |
| 저장소 종류 · 파티션 키 | 변수 명명 규칙 |
| 인증 방식 · 멀티테넌시 전략 | 테스트 프레임워크 |

### 고려한 안을 **먼저** 쓴다

결정을 먼저 쓰면 **그 결정을 정당화하는 대안만** 떠올린다.
안을 셋 이상 나열한 뒤에 고른다 — 셋을 못 채우면 **아직 문제를 이해하지 못한 것**이다.

> ⚠️ **"현행 유지"도 하나의 안이다.** 항상 후보에 넣는다.

### 근거는 반증 가능해야 한다

| 반증 불가 | 반증 가능 |
|---|---|
| 확장성이 좋아서 | QS-04(피크 3,000 TPS)를 단일 노드로 못 넘긴다 — 측정치 있음 |
| 업계 표준이라서 | C-02(사내 표준 런타임)가 다른 안을 제거한다 |
| 더 깔끔해서 | 트랜잭션 경계 E2가 두 서비스로 갈리지 않는 유일한 분할이다 |

**근거 칸의 각 줄이 제약(C) 또는 시나리오(QS)를 가리켜야 한다.**
아무것도 못 가리키면 그것은 취향이다.

### 기각 이유에 "이 이유가 바뀌면"을 적는다

기각은 **지금 조건에서의 기각**이다. 조건이 바뀌면 다시 봐야 한다.

```
B  이벤트 소싱          기각: 팀에 경험자가 없고(C-03) 운영 인력이 없다(C-01)
                        이 이유가 바뀌면: 감사 요구가 현 구조로 감당 안 될 때 재검토
```

### 되돌리는 조건은 **측정 가능**해야 한다

| 나쁨 | 좋음 |
|---|---|
| 성능이 안 나오면 | QS-04 측정에서 p99가 2회 연속 500ms를 넘으면 |
| 복잡해지면 | 한 유스케이스가 3개 이상 서비스를 동기 호출하게 되면 |
| 문제가 생기면 | M9~M15 대사 불일치가 주 1회 이상 적재되면 |

> ★ **되돌리는 조건이 비면 그 결정은 영원히 안 열린다.** 문제가 생겨도
> *"원래 그렇게 정했다"* 로 끝난다. **Phase 2의 변천 문서(DC)가 쓰는 반증 신호와 같은 장치다.**

### 상태를 바꿀 때

결정을 바꾸면 **원 ADR을 수정하지 않는다.** 새 ADR을 쓰고 원본을 `대체됨`으로 바꾼다.
**왜 바꿨는지가 사라지지 않게 하려는 것**이고, 이것은 원장의 역분개와 같은 원리다.

## 5. 흔한 실수

| # | 실수 | 왜 문제인가 | 고치는 법 |
|---|---|---|---|
| 1 | **결론만 있음** | 같은 논의를 처음부터 다시 한다 | 고려한 안과 기각 이유 |
| 2 | **근거가 반증 불가** | 틀렸는지 알 방법이 없다 | 각 근거가 C 또는 QS를 가리키게 |
| 3 | **되돌리는 조건 빈칸** | 영원히 안 열린다 | 측정 가능한 신호로 |
| 4 | **안이 둘뿐** | 대개 결정을 정당화하려고 만든 들러리다 | 셋 이상. "현행 유지" 포함 |
| 5 | **결과의 "새로 생기는 일" 누락** | 운영 비용을 안 세고 고른다 | 모니터링·학습·당직 비용 |
| 6 | **원 ADR을 수정** | 왜 바꿨는지가 사라진다 | 새 ADR + `대체됨` |
| 7 | ★ **품질 시나리오 없이 씀** | 근거가 취향이 된다 | `03`을 먼저 쓴다 |
| 8 | ★ **트랜잭션 경계를 확인 안 함** | 분할이 Phase 2의 경계를 깬다 | E1~En이 서비스를 넘지 않는지 전수 확인 |
| 9 | ★★ **역방향 경로를 안 봄** | 컨텍스트 맵의 관계는 *"누가 누구에게 말하는가"* 다. 배포 경계로 옮길 때는 **"누가 누구를 읽는가"** 를 따로 물어야 한다 | 분할 후보마다 *"밖으로 나간 것이 안을 다시 봐야 하는가"* 를 전수 확인 |

## 6. 완료 기준

- [ ] **되돌리기 어려운 결정마다** ADR이 하나씩 있다
- [ ] 각 ADR에 **고려한 안이 3개 이상**이고 *현행 유지*가 포함돼 있다
- [ ] 각 근거가 **제약(C) 또는 시나리오(QS)** 를 가리킨다
- [ ] 각 기각 이유에 **"이 이유가 바뀌면"** 이 있다
- [ ] **되돌리는 조건이 측정 가능**하다 (형용사 없음)
- [ ] 결과에 **새로 생기는 일**(운영·학습 비용)이 적혀 있다
- [ ] 서비스 분할 ADR이 **트랜잭션 경계를 넘지 않음**을 확인했다
- [ ] ★ 분할 후보마다 **역방향 경로**(밖에서 안을 읽거나 되돌려주는 것)를 전수 확인했다
      — *"읽기 전용"* 은 **쓰기를 안 한다**는 뜻이지 **읽을 수 있다**는 보장이 아니다
- [ ] 대체된 ADR은 **수정되지 않고** `대체됨`으로 표시돼 있다
