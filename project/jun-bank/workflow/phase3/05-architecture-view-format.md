# 아키텍처 뷰 양식

---

## 1. 목적

**하나의 그림으로 전부 설명하려는 시도를 막는다.**

구조를 보는 관점은 여럿이고, 관점마다 **독자와 답하는 질문이 다르다.**
한 장에 다 담으면 **아무도 못 읽는 그림**이 된다.

> ★ **뷰는 그림이 아니라 "질문에 대한 답"이다.** 답할 질문을 먼저 적고 그리기 시작한다.

---

## 2. 독자

| 뷰 | 누가 읽나 | 답하는 질문 |
|---|---|---|
| **컨텍스트 뷰** | 전원 · 이해관계자 | 이 시스템은 **누구와** 무엇을 주고받나 |
| **컨테이너 뷰** | 개발자 · 운영 | **배포 단위**가 몇 개이고 어떻게 통신하나 |
| **컴포넌트 뷰** | 그 컨테이너 개발자 | 안에 무엇이 있고 **책임**이 어떻게 나뉘나 |
| **런타임 뷰** | 개발자 · 장애 대응 | 한 요청이 **어떤 순서로** 흐르나 |
| **배포 뷰** | 운영 · 인프라 | 어디에 몇 개가 뜨나 |
| **데이터 뷰** | 개발자 · DBA | 누가 무엇을 **소유**하나 |

## 4. 작성법

### 답할 질문을 먼저 적는다

```
질문이 없다 → 그 뷰는 그리지 않는다
질문이 5개다 → 뷰를 나눈다
```

**"답하지 않는 질문" 칸이 이 양식의 핵심이다.** 그것을 적어야 뷰가 커지지 않는다.

### 최소 셋으로 시작한다

| 뷰 | 언제 필요한가 |
|---|---|
| **컨텍스트** | 항상 — 외부 의존이 하나라도 있으면 |
| **컨테이너** | 항상 — 배포 단위가 하나여도 그 사실이 정보다 |
| **데이터** | ★ 소유권이 갈리는 시스템이면 항상 |
| 런타임 | 순서가 중요한 흐름이 있으면 (자금 이동·보상 트랜잭션 등) |
| 컴포넌트 | 그 컨테이너가 커졌을 때 |
| 배포 | 다중화·리전이 있을 때 |

> ★ **데이터 뷰를 빠뜨리지 마라.** Phase 2가 정한 **데이터 소유권**이 여기서 배포 단위와
> 대조된다. *"소유자는 C1인데 저장은 다른 서비스"* 같은 어긋남이 이 뷰에서만 보인다.

### 관계 표에 "실패하면"을 반드시 채운다

그림의 화살표는 **정상 경로만** 보여준다. 실패가 안 그려지면 설계되지 않는다.

```
결제서비스 → 매입사 게이트웨이 · 승인 요청 · 동기
  실패하면: 타임아웃 500ms → 망취소 예약 기록 후 거절 (BR-13·22)
```

### 런타임 뷰는 **자금이 움직이는 흐름**부터

Phase 2의 트랜잭션 경계(E1~En)마다 하나씩 그린다.
**커밋 지점을 그림에 표시**한다 — 어디까지가 한 트랜잭션인지가 뷰에서 보여야 한다.

### 그림과 표가 어긋나지 않게 한다

**그림은 표에서 생성하거나, 최소한 요소 이름이 일치**해야 한다.
Phase 2에서 *"두 곳에 손으로 쓴 것은 반드시 갈라진다"* 를 열 라운드에 걸쳐 확인했다.

## 5. 흔한 실수

| # | 실수 | 왜 문제인가 | 고치는 법 |
|---|---|---|---|
| 1 | **한 그림에 전부** | 아무도 못 읽는다 | 질문별로 나눈다 |
| 2 | **답할 질문 없음** | 그리는 목적이 없다 | 질문 없으면 안 그린다 |
| 3 | **"답하지 않는 질문" 빈칸** | 뷰가 계속 커진다 | 다른 뷰로 보낼 것을 적는다 |
| 4 | **실패 경로 없음** | 정상 경로만 설계된다 | 관계마다 *실패하면* |
| 5 | **데이터 뷰 누락** | 소유권 위반이 안 보인다 | Phase 2 소유권 표와 대조 |
| 9 | ★ **"누가 읽는가"를 안 그림** | 화살표가 *말하는 방향*만 보여주면 **읽기 의존이 안 보인다.** 나누는 순간 그것이 결함이 된다 | 데이터 뷰에 **읽기 화살표**를 따로 그린다 |
| 6 | **그림과 표가 다름** | 어느 쪽이 정본인지 모른다 | 이름을 일치시키고 한쪽을 정본으로 |
| 7 | ★ **커밋 경계 미표시** | 분산 트랜잭션이 그림에 안 보인다 | 런타임 뷰에 트랜잭션 범위를 그린다 |
| 8 | **ADR과 연결 안 됨** | 왜 이 구조인지 뷰만 봐선 모른다 | §4에 ADR을 연결 |

---

## 6. 완료 기준

- [ ] 각 뷰에 **독자 · 답하는 질문 · 답하지 않는 질문**이 있다
- [ ] **컨텍스트 · 컨테이너 · 데이터** 뷰가 있다
- [ ] 관계마다 **동기/비동기**와 **실패하면**이 채워져 있다
- [ ] 데이터 뷰가 Phase 2의 **소유권 표와 일치**한다
- [ ] 자금이 움직이는 흐름마다 **런타임 뷰**가 있고 **커밋 경계가 표시**돼 있다
- [ ] 각 뷰가 **관련 ADR**을 가리킨다
- [ ] 그림의 요소 이름이 **표·용어사전과 일치**한다
