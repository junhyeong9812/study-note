# db-engine-lab 공부 노트

원본: `/home/jun/project/db-engine-lab` — impl/ 폴더의 구현 문서 순서(01~21)를 따라 DB 엔진을 직접 구현하며 공부한다.
복습 접근 순서·간격 규칙 등 공통 규칙은 상위 [README](../README.md)를 따른다. 이 문서는 이 프로젝트의 진행 방식을 기록한다.

## 챕터 하나의 진행 순서 (작성 순서)

1. **코드 치며 공부** — impl 문서의 챕터를 직접 치면서 이해한다. 한 줄도 그냥 넘어가지 않는다
   (모르는 문법·약어·설계 의도를 전부 질문으로 해소).
2. **`2-summary.md` 작성** — 공부 직후, 동작 워크플로우를 Claude와 대화로 정리한다.
   방식: **내가 먼저 기억으로 흐름을 서술하고, Claude가 빠지거나 틀린 곳을 짚는다.**
   Claude가 처음부터 써주는 게 아니다 — 서술 자체가 즉석 출력이다.
3. **`1-question.md` 작성** — summary를 내려다보며 "이 챕터에서 안 까먹어야 하는 건 뭔가"를
   직접 판별해 질문으로 만든다. 5~7개. **직접 쓴다** (판별이 곧 설계 훈련).
4. **`3-answer.md` 작성** — **summary를 닫고** 기억만으로 답을 쓴다 → **실제 코드**로 검증
   → 틀린 부분만 수정. 기준 소스는 문서가 아니라 코드다.

> 작성 순서는 2 → 1 → 3, 복습(사용) 순서는 1 → 2 → 3. 순서가 다른 게 정상이다.

## 질문 유형 (지도 수준으로 — 세부 암기 금지)

- **왜(why)**: 이 설계가 아니면 뭐가 깨지나? — "replay는 왜 2패스인가?"
- **예측(what if)**: 이 상황이면 어떻게 동작하나? — "마지막 레코드가 크래시로 반쯤 잘렸다면?"
- **경계(layer)**: 이 판단은 어느 계층의 책임인가? — "커밋 반영 여부는 누가 결정하나?"
- **연결(bridge)**: 이전 챕터와 어떻게 이어지나? — "버퍼풀이 있는데 WAL이 왜 필요한가?" (02-02 → 08-01)

## 진행 계획

- **주 트랙**: 08번부터 전진. 새 챕터를 공부할 때마다 위 순서로 노트를 만든다.
- **부 트랙(백필)**: 01~07은 세션당 하나씩, **impl 문서를 다시 읽지 않고 맨기억으로**
  질문+정답을 먼저 쓴 뒤 코드로 검증한다. 백필 자체가 그 챕터의 복습이다.
  기억이 전혀 안 나는 챕터 = 재공부 대상이라는 진단 결과.
- 새 챕터 시작 전에 이전 챕터 하나를 골라 셀프 테스트한다 (자연스러운 간격 반복).

## 새 세션에서 (Claude에게)

이 프로젝트의 공부를 도울 때:

- 설명은 의존성 순서로, 한 턴에 한 개씩.
- summary 정리 시: 사용자가 먼저 기억으로 서술하게 하고, 교정만 한다. 대신 써주지 않는다.
- question / answer 는 사용자가 직접 쓴다. Claude는 질문 품질(지도 수준인지)에 대한 피드백만.
- 복습 시: 정답·정리를 먼저 보여주지 않는다. 사용자의 답을 들은 뒤 코드 기준으로 채점한다.
