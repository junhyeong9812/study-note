# 문서 포맷 템플릿

새 챕터/주제 폴더를 만들 때 이 폴더의 세 파일과 [metadata.md](metadata.md)(진행 단계·날짜)를 복사해서 시작한다.\
**cs 주제는 예외** — 파일 구성(1/2/3)만 같고 작성 주체·순서·골격은 [cs/README.md](../cs/README.md) 「작성 규칙」을 따른다(2026-09-28).
파일명·접근 순서·작성 순서 규칙은 루트 [README](../README.md)를 따른다.

| 템플릿 | 역할 | 작성 시점 |
|--------|------|-----------|
| [1-question.md](1-question.md) | 핵심 질문 + 복습 기록 | summary 완성 후 |
| [2-summary.md](2-summary.md) | 흐름 정리 (힌트) | 공부 직후 |
| [3-answer.md](3-answer.md) | 정답 | 질문 작성 후, summary 닫고 기억으로 |

- **작성 순서는 2 → 1 → 3.** 순수 서머리가 완성되기 전에는 질문·정답을 만들지 않는다.
- **복습(사용) 순서는 1 → 2 → 3.** 항상 질문에서 시작해 맨기억으로 답하고, 막혔을 때만 다음 파일을 연다.

## 파일별 작성 방식 (2026-10-01 — 예전 템플릿 머리말에서 옮김)

템플릿 파일에는 제목 아래 머리말을 두지 않는다. 예전에 머리말로 적던 사용법은 여기가 정본이다.

- `1-question.md` — 복습은 항상 이 파일에서 시작한다. 맨기억으로 답을 시도하고, 막히면 2-summary를 힌트로, 최후에만 3-answer를 연다. 정답까지 봤던 질문은 복습 기록에 "틀림"으로 표시한다.
- `2-summary.md` — 질문에 막혔을 때만 연다. 작성 방식: 내가 먼저 기억으로 흐름을 서술하고, Claude는 빠지거나 틀린 곳을 짚는다. 대신 써주지 않는다. 따라 치며 만든 정리본이 따로 있으면(organize류) 이 파일은 핵심 문장 압축 + 링크만 담는다.
- `3-answer.md` — 최후에만 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다. 작성 방식: 2-summary를 닫고 기억만으로 쓴다 → 실제 코드/원전으로 검증 → 틀린 부분만 수정. 기준 소스는 문서가 아니라 코드다.
- `metadata.md` — 단계(원고·초안·검수·학습)와 각 날짜. 형식은 [cs/README.md](../cs/README.md) §4.
