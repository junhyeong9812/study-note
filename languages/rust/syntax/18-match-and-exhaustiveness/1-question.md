### 1. ★★★ 같은 열거형에 변형 한 줄을 더하면 (예측)

아래 파일에는 `match` 가 **네 자리** 있다. `Event` 에 `Drag` 한 줄만 더하고 `match` 는 한 글자도 안 고친다.

```rust
// b18-04a.rs
// ex.rs
// 변형 추가 실험 — 전. `_` 팔이 하나도 없는 판. 지금은 통과한다
#[derive(Debug, Clone, Copy)]
enum Event { Click, Key, Scroll }

fn label(e: Event) -> &'static str {
    match e { Event::Click => "클릭", Event::Key => "키", Event::Scroll => "스크롤" }
}

fn code(e: Event) -> u8 {
    match e { Event::Click => 1, Event::Key => 2, Event::Scroll => 3 }
}

fn needs_focus(e: Event) -> bool {
    match e { Event::Key => true, Event::Click | Event::Scroll => false }
}

fn main() {
    let all = [Event::Click, Event::Key, Event::Scroll];
    for e in all {
        let kind = match e {
            Event::Click => "포인터",
            Event::Key => "키보드",
            Event::Scroll => "포인터",
        };
        println!("{:?} {} {} {} {}", e, label(e), code(e), needs_focus(e), kind);
    }
}
```

- 변형을 더하면 에러가 **몇 곳**에서 나는가? 번호는 무엇인가?
- 네 자리 각각의 `help:` 는 무엇을 제안하는가?
- **같은 파일에서 네 자리의 마지막 팔을 전부 `_` 로 바꾼 뒤** `Drag` 를 더하면 에러가 몇 곳인가?
- 그 판에서 컴파일러가 하는 **유일한 불평**은 무엇이며, 그것은 「처리를 빠뜨렸다」는 뜻인가?
- 그래서 내 열거형에 `_` 를 쓸 때 **대신 쓸 것**은 무엇인가?

### 2. ★★ 변형 넷 중 둘만 적은 `match` (예측)

```rust
// b18-03.rs
// ex.rs
// 완전성 검사 — 변형 하나를 빼면 컴파일러가 「무엇이 빠졌는지」 이름으로 댄다
enum Event { Click, Key, Scroll, Drag }

fn label(e: &Event) -> &'static str {
    match e {
        Event::Click => "클릭",
        Event::Key => "키",
    }
}

fn main() {
    println!("{}", label(&Event::Click));
    println!("{}", label(&Event::Drag));
}
```

- 에러 번호와 제목 줄은 무엇인가? 빠진 것을 **몇 개나** 대 주는가?
- `note:` 는 어디를 가리키며, 거기서 **무엇에만** 밑줄을 긋는가?
- `help:` 가 주는 고친 코드는 어떤 문법을 쓰는가?
- 진단의 패턴에 `&` 가 붙어 있다. 왜인가?
- 이 진단은 **에러 하나**인가 **빠진 변형마다 하나**인가?

### 3. ★★ 정수 범위로 덮은 `match` (예측)

```rust
// b18-09.rs
// ex.rs
// 한 칸이라도 비면 컴파일러가 「빈 구간」을 숫자로 짚어 준다
fn grade(n: i32) -> &'static str {
    match n {
        i32::MIN..=-1 => "음수",
        0 => "영",
        1..=9 => "한 자리",
        11..=i32::MAX => "두 자리 이상",
    }
}

fn byte(b: u8) -> &'static str {
    match b {
        0..=127 => "ASCII",
    }
}

fn main() {
    println!("{} {}", grade(10), byte(200));
}
```

- 에러가 몇 개이며, 각각 **무엇이 안 덮였다**고 하는가?
- 컴파일러는 그 답을 어떻게 얻는가 — 나열인가 계산인가?
- `i32` 전체를 범위 넷으로 덮으면 `_` 없이 통과하는가?
- `char` 는 왜 그렇게 못 하는가?
- 이 사실이 「`_` 를 언제 써도 되나」에 어떤 답을 주는가?

### 4. ★ 튜플 한 칸을 비우면 (예측)

```rust
// b18-13.rs
// ex.rs
// 한 칸을 빼면 — 튜플에서도 「빠진 조합」을 그대로 적어 준다
fn cell(a: bool, b: Option<u8>) -> &'static str {
    match (a, b) {
        (true, Some(0)) => "참·영",
        (true, None) => "참·없음",
        (false, Some(_)) => "거짓·수",
        (false, None) => "거짓·없음",
    }
}

fn main() {
    println!("{}", cell(true, Some(9)));
}
```

- 에러가 짚는 **안 덮인 조합**을 그대로 적을 수 있는가?
- 그 조합에 `Some(0)` 이 왜 안 들어 있는가?
- `(bool, Option<u8>)` 를 **팔 다섯**으로 빠짐없이 덮을 수 있는가? 갈래는 몇 가지인가?
- 이 계산은 중첩이 깊어져도 되는가?

### 5. ★★ 팔에서 경로를 빼먹으면 (예측)

```rust
// b18-11.rs
// ex.rs
// 변수 패턴은 「무엇이든」 잡는다 — 경로를 안 쓰면 안전망이 조용히 사라진다
#[derive(Debug)]
enum Event { Click, Key, Scroll }

fn main() {
    let e = Event::Scroll;
    let s = match e {
        Click => "클릭",          // ★ Event:: 를 빼먹었다 — 이건 새 변수다
        Event::Key => "키",
        Event::Scroll => "스크롤",
    };
    println!("{}", s);
}
```

- 에러인가 경고인가? 번호는 무엇인가?
- 경고는 **몇 개** 붙으며 각각 무엇인가?
- `Click` 은 무엇으로 해석됐는가 — 진단의 어느 구절이 그것을 말하는가?
- `use Event::*;` 를 먼저 써 두었다면 이 진단이 나는가?
- 그래서 17번 주제가 `use Enum::*` 에 대해 한 말은 무엇이었나?

### 6. ★★ 팔에서 `String` 을 이름으로 받은 뒤 원본을 또 쓰면 (예측)

```rust
// b18-10.rs
// ex.rs
// 묶인 값의 이동 — 팔에서 값을 「이름으로 받으면」 그 자리에서 옮겨진다
#[derive(Debug)]
enum Msg { Text(String), Num(u32) }

fn main() {
    let m = Msg::Text(String::from("가나다"));
    match m {
        Msg::Text(s) => println!("글 {}", s),
        Msg::Num(n) => println!("수 {}", n),
    }
    println!("{:?}", m);
}
```

- 에러 번호와 제목 줄은 무엇인가?
- `help:` 가 제안하는 낱말 하나는 무엇이며, 그것은 어느 주제의 도구인가?
- 같은 일을 하되 원본을 살리는 방법을 **셋** 댈 수 있는가?
- `Msg::Num(n)` 을 묶는 것은 왜 괜찮은가?

### 7. `#[non_exhaustive]` 의 경계 (경계)

- 같은 크레이트 안에서 `#[non_exhaustive]` 열거형을 `_` 없이 `match` 하면 어떻게 되는가?
- 크레이트를 갈라 같은 코드를 컴파일하면 어느 번호가 나며, **무엇이 안 덮였다**고 하는가?
- 그 진단의 `= note:` 한 줄을 적을 수 있는가?
- 같은 라이브러리의 **표시 없는** 열거형은 크레이트가 달라도 `_` 가 필요한가?
- 이 표시를 내가 **붙이는 쪽**이라면 무엇을 얻고 무엇을 잃는가?

### 8. `match` 가 식이라는 것 (왜)

- `let v = match c { … };` 에서 세미콜론은 누구 것인가?
- 팔 하나가 블록이면 그 팔의 값은 무엇인가?
- 팔 타입이 다르면 어느 번호가 나고, 진단은 **어느 팔의 타입을 먼저** 정하는가?
- 값이 필요 없을 때 `match` 의 타입은 무엇인가?
- 이 성질이 어느 주제의 규칙을 그대로 쓰는 것인가?

### 9. 완전성 검사가 세는 단위 (경계)

- 완전성 검사가 다루는 값 공간을 **넷** 대라.
- 빈 열거형(`enum Never {}`)을 `match` 하면 팔이 몇 개 필요한가?
- `_` 를 맨 위 팔에 두면 무슨 일이 생기는가 — 에러인가 경고인가?
- `..` 와 `_` 는 무엇이 다른가?
- 가드가 붙은 팔은 완전성 계산에 들어가는가?
