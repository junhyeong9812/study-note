# c/syntax/15 — 포인터 산술과 인덱싱: 「**`a[i]` 는 문법이 아니라 축약이다**」 — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,
> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.
> 정답까지 봤던 질문은 아래 복습 기록에 "틀림"으로 표시한다.
> 이 주제의 질문은 **예측형 위주**다 — 아는지가 아니라 **출력을 맞힐 수 있는지**를 묻는다.
> **환경** — gcc 13.3.0 · clang 18.1.3 · x86-64 Linux · 기본 `-std=c17 -Wall -Wextra -pedantic`.
> ★★ **이 주제는 UB 가 본체**다. [13번 형제](../13-goto-cleanup-idiom/)가 **표준이 본체**였던 것과 정반대다 —
> 그래서 「**무엇이 출력되나**」보다 「**어느 도구가 무엇이라 하나**」가 더 자주 답이 된다.
> ★★★ **UB 가 걸린 문항에서는 「값」을 답으로 외우지 마라.** 값이 갈리는 것 자체가 답인 자리가 있다.
> ★ **「경고 0건」은 종료 코드와 sanitizer 출력을 같이 봐야 뜻이 있다.**
> 선행 — [14번 형제](../14-pointers-address-dereference-and-pointer-types/) · [09번 형제](../09-operator-precedence-and-associativity/).

## 질문

### 1. 세 타입의 포인터에 각각 1 을 더하면 (예측) ★★

```c
int    ai[5];   char   ac[5];   double ad[5];
int *pi = ai;   char *pc = ac;  double *pd = ad;

/* 각 줄에서 sizeof *p 와 (uintptr_t)(p+1) - (uintptr_t)p 를 찍는다 */

ptrdiff_t d = &ai[4] - &ai[1];
/* d 와 바이트 차이와 &ai[1] - &ai[4] 를 찍는다 */
```

- 세 줄의 **주소 차이**는 각각 얼마인가 — 무엇과 같은가?
- `&ai[4] - &ai[1]` 은 얼마이고 **바이트 차이**는 얼마인가?
- `&ai[1] - &ai[4]` 는 얼마인가 — 그것이 뜻하는 **타입의 성질**은?
- ★ 이 출력에서 **다시 돌리면 달라지는 것**은 무엇인가?

### 2. 인덱싱을 일곱 가지로 써 보면 (예측) ★★★ 이 주제의 축

```c
int a[5] = {10, 20, 30, 40, 50};
int i = 2;
int *p = a;

a[i];   *(a + i);   *(i + a);   i[a];   p[i];   i[p];   2[a];

/* 그리고 a[i]==*(a+i), a[i]==i[a], &a[i]==&i[a] 를 찍는다 */
i[a] = 99;   /* a[2] 는? */
```

- **일곱 식 중 몇 개가 컴파일되는가** — 값은 각각 얼마인가?
- 경고는 몇 건인가 — **어느 플래그**이고 **gcc 와 clang 이 같은 수**인가?
- ★ 그 경고 이름이 **증명하는 것**은 무엇인가?
- `i[a] = 99` 는 되는가 — 왜인가?

### 3. 배열 끝 한 칸 뒤를 만들고 읽으면 (예측) ★★

```c
int a[5] = {10, 20, 30, 40, 50};
int *end = a + 5;

printf("%td\n", end - a);
printf("%d\n", end > a);
for (int *p = a; p != end; p++) sum += *p;   /* sum 은? */

printf("*end = %d\n", *end);                 /* 여기서는? */
```

- 앞의 세 줄은 각각 무엇을 내는가 — **경고나 진단이 나오는가?**
- 마지막 줄에서 **평범한 실행**은 어떻게 되는가 — 종료 코드는?
- **ASan+UBSan** 을 붙이면 **어느 줄에서** 무엇이 나오는가?
- ★ 이 갈라짐이 말하는 규칙을 한 문장으로?

### 4. 배열 범위를 넘는 포인터를 만들면 (예측) ★★★

```c
int a[5] = {1, 2, 3, 4, 5};
volatile int i = 10;
int *p = a + i;                 /* 포인터를 "만드는" 줄 */
printf("%p\n", (void *)p);
printf("%d\n", a[i]);           /* 실제로 "읽는" 줄 */
```

- 컴파일 경고는 몇 건인가?
- `gcc -fsanitize=undefined,address` 는 **어느 행**을 가리키는가?
- `clang -fsanitize=undefined,address` 는 **어느 행**을 가리키는가 — ★ **왜 다른가?**
- `volatile` 을 떼고 `-O0`·`-O2` 로 던지면 각각 몇 건인가 — **두 컴파일러가 같은가?**

### 5. 서로 다른 배열의 포인터를 빼고 비교하면 (예측) ★★★

```c
int a[4] = {1, 2, 3, 4};
int b[4] = {5, 6, 7, 8};
ptrdiff_t d = b - a;
printf("b - a = %td\n", d);
printf("b < a ? %d\n", b < a);
```

- 컴파일 경고는 몇 건이고 **어느 줄**에 대한 것인가 — gcc 와 clang 의 **플래그 이름이 같은가?**
- `b - a` 는 얼마인가 — ★ **컴파일러·최적화 수준·sanitizer 를 바꾸면 같은 값인가?**
- sanitizer 는 뺄셈에 대해 무엇이라 하는가?
- ★ gcc 가 다는 `note:` 대로 고치면 문제가 없어지는가?

### 6. 널 포인터에 정수를 더하면 (예측) ★★

```c
int *n = NULL;
volatile int k = 1;
int *p = n + k;        /* NULL + 1 */
printf("%p\n", (void *)p);
int *q = n + 0;        /* NULL + 0 */
printf("%p\n", (void *)q);
```

- 두 줄은 무엇을 찍는가 — 컴파일 경고는?
- `gcc -fsanitize=undefined,address` 는 몇 줄을 내는가 — `-fsanitize=pointer-overflow` 를 **직접 켜면**?
- `clang -fsanitize=undefined` 는 몇 줄을 내는가 — 문구는?
- ★ `-std=c2x` 로 바꾸면 `NULL + 0` 쪽이 조용해지는가 — 왜 그런가?

### 7. `void *` 로 산술을 하면 (경계)

```c
char buf[8] = {0,1,2,3,4,5,6,7};
void *vp = buf;
printf("%zu\n", sizeof(void));
void *v1 = vp + 1;
printf("%ld\n", (long)((uintptr_t)v1 - (uintptr_t)vp));
```

- `gcc -Wall -Wextra` 는 몇 건인가 — `-pedantic` 을 붙이면?
- `sizeof(void)` 는 얼마이고 `vp + 1` 은 몇 바이트 가는가?
- clang 의 진단 문구가 gcc 보다 **무엇을 더 말해 주는가?**
- 표준 안에서 바이트 단위로 걸으려면 무엇을 쓰는가?

### 8. `*p++` 와 `(*p)++` 와 `*++p` (경계) ★

- 셋은 각각 **무엇을 움직이는가** — `p - arr` 는 각각 얼마인가?
- `*p++` 가 `*(p++)` 인 근거는 무엇인가 — 어느 주제가 정본인가?
- ★ 왜 **한 `printf` 안에서** 값과 `p - arr` 를 같이 재면 안 되는가?

### 9. `ptrdiff_t` 를 잘못 받으면 (경계) ★
