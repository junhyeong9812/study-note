# c/syntax/10 — 평가 순서와 시퀀스 포인트: 무엇이 먼저 **도나** — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,
> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.
> 정답까지 봤던 질문은 아래 복습 기록에 "틀림"으로 표시한다.
> 이 주제의 질문은 **예측형 위주**다 — 아는지가 아니라 **출력을 맞힐 수 있는지**를 묻는다.
> **환경** — gcc 13.3.0 · clang 18.1.3 · x86-64 Linux · 기본 `-std=c17 -Wall -Wextra -pedantic`.\
> ★★ **이 주제는 컴파일러 한 대로는 아무것도 증명하지 못한다.** 그래서 아래 예측형은
> **「gcc 는 무엇을 찍고 clang 은 무엇을 찍나」를 따로 답해야 한다.**
> ★★ **이 주제의 본체는 「미명시」다.** [09번 형제](../09-operator-precedence-and-associativity/)가 다섯 층 중 「표준」 하나만 찼다면
> 여기는 **「미명시」 칸이 가장 두껍고 「구현 정의」 칸이 비어 있다.** 왜 그런지가 8번 질문이다.
> 선행 — [09번 형제](../09-operator-precedence-and-associativity/)(무엇이 먼저 **묶이나**).

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

### 1. 한 `printf` 안에서 두 번 꺼내면 (예측) ★★ 이 주제의 대표 사고

```c
static int stack[4] = {10, 20, 30, 40};
static int top = 4;
static int pop(void) { return stack[--top]; }
/* ... */
printf("pop() 두 번을 한 printf 에 : %d %d\n", pop(), pop());
top = 4;
int first = pop();
int second = pop();
printf("문을 나눠 부르면            : %d %d\n", first, second);
```

- 첫 줄은 **gcc 에서** 무엇을 찍고 **clang 에서** 무엇을 찍는가?
- 둘째 줄은 두 컴파일러에서 같은가 다른가?
- 이 프로그램에 경고가 **몇 건** 나는가?
- `-fsanitize=undefined` 로 돌리면 무엇이 나오고 종료 코드는 무엇인가?

### 2. 세 함수를 한 호출의 인자로 넣으면 (예측) ★★

```c
static int order = 0;
static int f(void) { printf("  f 가 %d 번째\n", ++order); return 1; }
static int g(void) { printf("  g 가 %d 번째\n", ++order); return 2; }
static int h(void) { printf("  h 가 %d 번째\n", ++order); return 3; }
static void take(int a, int b, int c) { printf("  받은 값 = %d %d %d\n", a, b, c); }
/* ... */
take(f(), g(), h());
order = 0;
int v = f() + g() * h();
```

- `take` 가 **받은 값**은 무엇인가 — 컴파일러에 따라 달라지는가?
- 세 함수가 불린 **순서**는 gcc 와 clang 에서 각각 무엇인가?
- `f() + g() * h()` 에서는 어느 쪽이 먼저 도는가 — [09번](../09-operator-precedence-and-associativity/)의 우선순위로 설명되는가?
- 인자를 2개·7개로 늘리거나 최적화 수준을 다섯 벌로 바꾸면 방향이 흔들리는가?

### 3. 같은 객체를 한 식에서 두 번 건드리면 (예측) ★★

```c
int i = 5;   i = i++;
int j = 5;   int k = j++ + j++;
int a[8] = {0};  int n = 2;   a[n] = n++;
int m = 1;   m = m++ + ++m;
/* i · k · j · n · a[2] · a[3] · m 을 찍는다 */
```

- 일곱 값은 각각 무엇인가?
- 그 값들을 **「정답」이라고 불러도 되는가?**
- `gcc -O0 -O1 -O2 -O3 -Os` · `clang -O0 -O2` · UBSan **여덟 벌**에서 값이 갈리는가?
- 이 자리에서 위험을 말해 준 도구는 **무엇 하나**인가?

### 4. 시퀀스 포인트가 사이에 있을 때 (예측)

```c
struct Node *p = NULL;
if (p && p->val == 3) printf("안 찍힌다\n");
calls = 0; (void)(0 && side(1));          /* side 는 호출 수를 센다 */
calls = 0; (void)(1 || side(1));
calls = 0; (void)(0 ? side(1) : side(2));
int i = 5;   i = (i++, i++);
int k = 5;   int r = k++ && k++;
```

- `p` 가 `NULL` 인데 첫 줄에서 프로그램이 죽는가?
- `side` 는 세 줄에서 각각 **몇 회** 불리는가?
- `i` 와 `r`·`k` 는 각각 무엇이 되는가?
- 이 프로그램에서 경고는 **몇 건**이고 **어느 줄**인가?

### 5. 대입 대상만 바꾸면 (예측) ★

```c
int i = 5;   int t = (i++, i++);
int j = 5;   int u = j++ && j++;
int k = 5;   int w = k++ ? k++ : k++;
```

- 여섯 값(`t`·`i`·`u`·`j`·`w`·`k`)은 각각 무엇인가?
- 이 프로그램의 경고 건수는 몇 건인가 — 4번의 `i = (i++, i++)` 와 무엇이 다른가?
- UB 인지 아닌지를 가르는 기준을 **한 문장**으로 쓰면?
- 「부작용이 몇 개냐」로 세면 왜 틀리는가?

### 6. 부작용을 한 `printf` 안에서 재면 (예측) ★★

```c
int arr[4] = {10, 20, 30, 40};
int *p = arr;
printf("*p++   = %d, p 는 이제 arr[%td]\n", *p++, (ptrdiff_t)(p - arr));
p = arr;
printf("(*p)++ = %d, arr[0] 은 이제 %d\n", (*p)++, arr[0]);
arr[0] = 10; p = arr;
printf("*++p   = %d, p 는 이제 arr[%td]\n", *++p, (ptrdiff_t)(p - arr));
```

- 세 줄은 각각 무엇을 찍는가?
- 문을 나눠 다시 재면 답이 어떻게 바뀌는가?
- 두 답 중 **어느 쪽이 「아무 일도 안 일어난 것처럼」 보이는가?**
- 이 사고가 이 갈래에서 **몇 번째**인가 — 앞선 두 번은 어느 주제였나?

### 7. 미명시와 UB 의 경계 (왜) ★★★ 이 주제의 축

- `printf("%d %d", pop(), pop())` 은 미명시인데 `i = i++` 은 UB 다 — **무엇이 둘을 가르는가?**
- 미명시의 최악은 무엇이고 UB 의 최악은 무엇인가?
- 이 구분을 못 하면 **도구의 침묵**을 어떻게 잘못 읽게 되는가?

### 8. 평가 순서가 「구현 정의」가 아닌 이유 (경계) ★★

- gcc 는 늘 오른쪽부터 평가하는데 왜 그것을 「구현 정의」라고 부르면 안 되는가?
- 「구현 정의」와 「미명시」의 차이를 **의무 한 가지**로 말하면?
- 그래서 gcc 문서에서 무엇을 찾을 수 없는가?

### 9. sanitizer 가 침묵한 두 가지 이유 (경계) ★★

- 인자 평가 순서에서 UBSan 이 침묵한 이유는 무엇인가?
- `i = i++` 에서도 UBSan 이 침묵했다 — 이쪽은 **같은 이유인가 다른 이유인가?**
- 두 침묵은 각각 「원리상 못 본다」인가 「지금 안 본다」인가?
- 그래서 이 주제에 남는 검사는 무엇인가?

### 10. 경고 이름과 건수가 갈리는 자리 (경계)

- `-Wsequence-point` 는 `-Wall` 인가 `-Wextra` 인가?
- clang 의 대응 플래그 이름은 무엇이고, clang 이 쓰는 **말**이 gcc 와 어떻게 다른가?
- 같은 프로그램에서 gcc 와 clang 의 **건수**가 다른 줄이 하나 있다 — 어느 줄인가?
- ★ 그 건수를 `grep -c warning` 으로 세면 clang 쪽이 **하나 더 나온다.** 왜인가?

### 11. 두 함수 호출은 섞이는가 (연결)

- `F() + G()` 에서 `F` 의 몸통과 `G` 의 몸통이 **번갈아** 실행될 수 있는가?
- 그 보장의 이름은 무엇인가 — 「미명시」와 어떻게 다른 말인가?
- 이 관찰(`둘 다 F 부터였다`)에서 **무엇까지만** 주장할 수 있는가?

### 12. 그래서 어떻게 쓰나 (연결)

- 이 주제의 함정 전부를 덮는 **규칙 한 줄**은 무엇인가?
- 빌드 플래그로 무엇을 켜고, 그것이 **못 잡는 것**은 무엇인가?
- 「무엇이 먼저 묶이나」의 정본은 어느 주제이고, 「UB 가 본체인 주제」는 어느 형제인가?
