# html/syntax/03 — 파서와 오류 복구: 태그 수프가 트리가 되는 과정·암묵 태그 삽입 — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,
> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.
> 정답까지 봤던 질문은 아래 복습 기록에 「틀림」으로 표시한다.
> ★ 이 주제의 답은 **트리를 그려서** 하는 것이다. 「어떻게 보이나」가 아니라 「**노드가 몇 개이고 어디에 붙나**」까지 말한다.
> ★ 소스 펜스 첫 줄의 `<!-- 파일이름 -->` 은 **어느 파일을 던진 것인지 표시**이지 파일 내용이 아니다.

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

### 1. 문단 안에 블록을 넣으면 (예측)

```html
<!-- html01b-p-div.html -->
<!DOCTYPE html>
<meta charset="utf-8">
<title>p 안에 쓴 div</title>
<p>앞<div>안</div>뒤</p>
```

- 트리를 그려라. `body` 의 직계 자식은 몇 개이고 각각 무엇인가?
- `뒤` 라는 글자는 어느 요소 안에 있는가?
- 소스에 없는데 트리에 생긴 요소가 있는가? 있다면 무엇이 만들었는가?
- `p { color: red }` 를 주면 어느 글자가 빨개지는가?

### 2. 표를 손으로 쓰면 (예측)

```html
<!-- html01b-implied.html -->
<!DOCTYPE html>
<meta charset="utf-8">
<title>암묵으로 끼워 넣는 것</title>
<table><tr><td>셀</td></tr></table>
<select><option>가</option></select>
```

- `table` 의 직계 자식은 무엇인가?
- `select` 쪽에서도 같은 일이 일어나는가?
- `table > tr` 이라는 CSS 선택자는 몇 개를 잡는가?
- 이 삽입은 02번 주제의 「생략 가능 태그」와 같은 것인가?

### 3. 표 안에 표가 아닌 것을 넣으면 (예측)

```html
<!-- html01b-foster.html -->
<!DOCTYPE html>
<meta charset="utf-8">
<title>표 밖으로 밀려나는 것</title>
<table><div>표 안에 쓴 div</div><tr><td>셀</td></tr></table>
```

- `div` 는 트리의 어디에 있는가?
- 그 내용은 남았는가, 사라졌는가?
- `table.previousElementSibling` 은 무엇인가?
- 이 동작에 명세가 붙인 이름은 무엇이고 왜 그렇게 불리는가?

### 4. 서식 태그를 잘못 겹치면 (예측)

```html
<!-- html01b-adoption.html -->
<!DOCTYPE html>
<meta charset="utf-8">
<title>잘못 겹친 서식 태그</title>
<p><b>굵게<i>둘 다</b>기울임만</i>맨몸</p>
<p><em>하나<strong>둘</em>셋</strong>넷</p>
```

- 첫 문단에서 `i` 요소는 몇 개가 되는가?
- 「기울임만」이라는 글자는 어느 요소들 안에 있는가?
- 화면으로 이 사고를 잡을 수 있는가?
- 이 알고리즘의 이름은 무엇인가?

### 5. 닫는 태그로 쓴 빈 요소 (예측)

```html
<!-- html01b-close-void.html -->
<!DOCTYPE html>
<meta charset="utf-8">
<title>닫는 태그로 쓴 빈 요소</title>
<p>앞</br>뒤</p>
<p>앞</img>뒤</p>
<p>앞</hr>뒤</p>
```

- 세 문단의 트리를 각각 예측하라.
- 셋 중 하나만 다른 대우를 받는다. 무엇이고 왜인가?
- 「빈 요소의 닫는 태그는 무시된다」는 일반화가 맞는가?
- `</p>` 는 이 셋 중 어느 쪽과 같은 부류인가?

### 6. 「오류 복구」의 뜻 (왜)

- 여기서 「오류」는 무엇이고 「복구」는 무엇을 하는 것인가?
- 파서가 오류를 알려 주는 방법은 무엇인가?
- 이 주제의 모든 블록에서 `(exit N)` 이 같은 값인 이유는?
- 그래서 이 갈래에서 종료 코드는 근거가 되는가?

### 7. 명세가 정한 것과 구현이 정한 것 (경계)

- 이 주제의 트리 모양 중 **명세 보장**인 것과 **구현 관찰**인 것을 갈라라.
- 다른 언어의 같은 표와 비교하면 이 주제의 모양이 어떤가?
- 그렇게 된 역사적 이유는 무엇인가?
- 그러면 「브라우저마다 다르다」는 이 주제에서 어디까지 참인가?

### 8. 에러를 내는 파서 (경계)

- 같은 마크업을 `.xhtml` 확장자로 주면 무엇이 달라지는가?
- 그 에러는 어디에 나타나는가? 콘솔인가 트리인가?
- 그 에러 메시지를 근거로 쓸 수 있는가?
- 이 대비가 설명하는 웹 역사의 사건은 무엇인가?

### 9. 트리가 맞는지 확인하는 법 (연결)

- 이 주제의 다섯 가지 교정 중 **화면으로 잡히는 것**과 **안 잡히는 것**을 갈라라.
- 「화면이 맞으니 구조도 맞겠지」가 틀리는 사례를 하나 대라.
- 트리를 확인하는 창은 무엇이고, 그것만으로 부족한 자리는 어디인가?
- 콘텐츠 모델을 외우는 것과 던져 보는 것 중 무엇이 빠른가?

### 10. 다른 갈래와 잇기 (연결)

- CSS 파서와 HTML 파서가 모르는 것을 만났을 때의 차이를 한 문장으로 답하라.
- 서버 쪽 파서와 브라우저 파서가 다르면 왜 보안 문제가 되는가?
- 02번 주제의 어떤 규칙이 그것과 같은 집안인가?
- `innerHTML` 로 넣은 조각도 같은 알고리즘을 거치는가? 그 API 는 어느 갈래가 정본인가?
