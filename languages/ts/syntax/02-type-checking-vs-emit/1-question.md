# ts/syntax/02 — 타입 검사와 코드 방출의 분리 — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,
> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.
> 정답까지 봤던 질문은 아래 복습 기록에 「틀림」으로 표시한다.
>
> 이 갈래는 **예측형**이다. ★★★ 이 주제에서 예측할 것은 **셋**이다 —
> ① 진단이 무엇이 나오나 ② **종료 코드가 몇인가** ③ **산출물이 생기나**.
> **셋을 다 적지 않으면 답이 아니다.** 「에러가 난다」만 적으면 이 주제의 절반을 놓친다.
> 실행 환경: `tsc` **7.0.2** · `node` **v18.19.1**. 모든 블록은 `--pretty false` 로, 옵션은 배너에 적힌 것만 줬다.
> ★ 소스 펜스 첫 줄 `// 파일명` 은 대조용 배너다 — **진단의 행 번호는 그 줄을 뺀 기준**이다.

## 질문

<!-- 형식: 질문 하나 = "?" 하나 = 한 줄.
     유형 태그: (왜) / (예측) / (경계) / (연결) -->

### 1. 에러 한 줄을 넣고 그냥 돌리면 (예측)

```ts
// ex.02a.ts
// 타입 에러가 한 줄 있지만 나머지는 멀쩡히 돌아가는 코드다
export function twice(n: number): number {
    return n * 2;
}
const label: string = 42;
console.log(twice(21), label);
```

- `tsc ex.02a.ts` 의 **종료 코드**는 몇이고, `ex.02a.js` 는 **생기는가**?
- 생긴다면 `node ex.02a.js` 는 무엇을 찍고 **종료 코드**는 몇인가?

### 2. 네 가지 플래그를 각각 주면 (예측)

- 같은 파일에 `--noEmitOnError` · `--noEmit` · `--noCheck` · `--declaration` 을 각각 주면
  **진단 · 종료 코드 · 산출물** 세 칸이 각각 어떻게 되는가?
- 네 판 중 **진단이 아예 안 나오는 것**은 어느 것인가?

### 3. 구문이 깨진 파일을 돌리면 (예측)

```ts
// ex.02b.ts
// 괄호가 안 닫힌 구문 에러 — 타입 에러보다 앞 단계에서 걸린다
function twice(n: number {
    return n * 2;
}
```

- 진단은 **몇 건**이고, `ex.02b.js` 는 **생기는가**? 생긴다면 **내용이 무엇**인가?
- 종료 코드는 1번과 같은가 다른가?

### 4. 진단을 파이프로 받으면 (예측)

- `tsc --pretty false ex.02a.ts 1>out 2>err` 로 갈라 받으면 **`out` 과 `err` 중 어디에** 진단이 들어오는가?
- 그래서 `tsc ... 2>log.txt` 로 로그를 남기면 어떻게 되는가?

### 5. `isolatedModules` 를 켜면 (예측)

```ts
// ex.02c.ts
// 타입인지 값인지는 다른 파일을 봐야 안다 — isolatedModules 가 막는 자리
import { Point, origin } from "./ex.02c-types.js";

export { Point };
export const start = origin;
```

- 옵션 없이 돌리면 방출된 `ex.02c.js` 의 **두 줄**이 무엇이고, `--isolatedModules` 를 켜면 무슨 에러가 나는가?
- 왜 **컴파일러는 통과시키는데** 파일 하나만 보는 도구는 못 하는가?

### 6. `verbatimModuleSyntax` 가 만든 파일을 돌리면 (예측)

```ts
// ex.02d.ts
// verbatimModuleSyntax 를 켜면 타입 이름이 import 목록에 그대로 남는다
import { Shape, Circle } from "./ex.02d-lib.js";

const s: Shape = new Circle(2);
console.log(s.area());
```

- `tsc --module esnext --verbatimModuleSyntax` 의 **종료 코드**와 **방출된 첫 import 줄**은?
- 그 파일을 `node` 로 돌리면 어떻게 되고 **종료 코드**는 몇인가?

### 7. 종료 코드 세 값 (경계)

- 이 배치에서 본 종료 코드는 **0·1·2** 셋이다. 각각이 「진단」과 「산출물」 두 축에서 무엇을 뜻하는지 표로 채울 수 있는가?
- **종료 코드 `0` 이 두 가지 뜻을 갖는 자리**는 어디인가?

### 8. 선언 파일도 에러 중에 나오나 (경계)

- `--declaration` 을 켠 채 타입 에러가 있으면 `.d.ts` 는 나오는가?
- 나온다면 **에러가 난 선언**은 그 안에 들어 있는가, 없다면 왜인가?

### 9. 왜 이렇게 설계했나 (왜)

- 「타입 에러가 있어도 방출한다」가 **버그가 아니라 설계**인 이유를 [**01번 주제**](../01-what-ts-adds-and-erases/)의 결론에서 이을 수 있는가?

### 10. 5.x 설정을 7.0 에 올리면 (경계)

- `target: "es5"` 와 `moduleResolution: "node10"` 이 든 `tsconfig.json` 으로 돌리면 어떤 에러 코드가 나오고, **어느 파일의 어느 좌표**를 가리키는가?
- 그때도 산출물은 나오는가?
- `tsc ex.ts` 처럼 파일을 직접 주면 그 `tsconfig.json` 이 읽히는가?

### 11. 세 층 가르기 (연결)

- 이 주제에서 **언어 보장** · **이 판(7.0.2)의 관찰** · **7.0 에서 바뀐 것**에 각각 해당하는 항목을 하나씩 댈 수 있는가?

### 12. CI 에 무엇을 쓰나 (연결)

- 「빌드가 통과했다」를 **무엇으로 판정**해야 하는지 한 줄 명령과 판정 기준으로 답할 수 있는가?
