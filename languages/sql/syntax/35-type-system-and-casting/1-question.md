대상은 **PostgreSQL 18.6** 과 **MySQL 8.4.10** 두 서버다. 「두 엔진에서」라고 물으면 **각각** 답한다.

예시 표는 이 폴더의 주제들이 공유한다. 이 주제는 `emp`·`dept` 를 읽기만 하고, 인덱스 실험만 별도 표를 쓴다.

```text
emp (사원)                          dept (부서)         t35 (인덱스 실험용, 20,000행)
+----+------+---------+--------+    +----+-------+      +-------+-----------+
| id | name | dept_id | salary |    | id | name  |      | id    | code      |  <- code 는 varchar(20)
+----+------+---------+--------+    +----+-------+      +-------+-----------+     인덱스 있음
|  1 | ann  |      10 |    300 |    | 10 | sales |      |     1 | C000001   |
|  2 | bob  |      10 |    500 |    | 20 | dev   |      |   ... | ...       |
|  3 | cho  |      20 |   NULL |    | 30 | hr    |      | 20000 | C020000   |
|  4 | dan  |    NULL |    400 |    +----+-------+      +-------+-----------+
+----+------+---------+--------+
```

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

### 1. `CAST` 의 타입 이름 (예측)

```sql
SELECT CAST('123' AS INTEGER) + 1 AS r;
SELECT CAST('123' AS SIGNED)  + 1 AS r;
```

- 두 엔진에서 각각 어느 문이 돌고 어느 문이 죽는가?

### 2. ★ 둘 다 통과하는데 답이 다른 것 (예측)

```sql
SELECT CAST(10 AS CHAR)        AS r;   -- (a)
SELECT CAST(10 AS CHAR(10))    AS r;   -- (b)
SELECT CAST(10 AS VARCHAR)     AS r;   -- (c)
SELECT CAST(10 AS TEXT)        AS r;   -- (d)
```

- 네 문이 두 엔진에서 각각 어떻게 되고, 그중 **양쪽에서 같은 답을 내는 것**은 무엇인가?

### 3. 변환이 실패하면 (예측)

```sql
SELECT 'abc' + 1 AS r;
SELECT 1 = 'abc' AS r;
```

- 두 엔진에서 각각 무엇이 나오는가?

### 4. ★ 따옴표 하나를 지우면 (예측)

```sql
-- t35.code 는 varchar(20) 이고 인덱스가 걸려 있다
SELECT * FROM t35 WHERE code = 'C000123';   -- (a)
SELECT * FROM t35 WHERE code = 123;         -- (b)
```

- 두 엔진에서 (b) 는 각각 어떻게 되고, 실행 계획은 (a) 와 무엇이 달라지는가?

### 5. `BOOLEAN` 은 어디까지 타입인가 (예측)

```sql
SELECT TRUE + TRUE AS sum;
SELECT CAST(1 AS BOOLEAN) AS b;
```

- 두 엔진에서 각각 무엇이 나오는가?

### 6. 집합 연산의 열 타입 (예측)

```sql
SELECT 1 AS c UNION SELECT 'a' AS c;
```

- 두 엔진에서 각각 무엇이 나오는가?

### 7. `NULL` 에 타입이 있나 (경계)

- `SELECT NULL AS x` 로 만든 열의 타입은 두 엔진에서 각각 무엇인가?

### 8. 암시 변환은 언제나 인덱스를 죽이나 (경계)

- `int` 열을 `bigint` 값과 비교하면 인덱스를 타는가, 못 타는가 — 그 판단의 기준은 무엇인가?

### 9. 양쪽이 다 문자열이면 (왜)

- `'10' > '9'` 가 거짓인데 `10 > 9` 는 참인 이유는 무엇인가?

### 10. 조용히 넘어간 것을 어떻게 아나 (연결)

- MySQL 이 변환 실패와 인덱스 포기를 결과에 안 싣는다면, 그것을 알아내는 통로는 무엇인가?

### 11. 그래서 어떻게 고치나 (연결)

- 문자열 열을 수치와 비교하는 코드를 발견했을 때, 인덱스를 살리는 처방과 살리지 못하는 처방은 각각 무엇인가?
