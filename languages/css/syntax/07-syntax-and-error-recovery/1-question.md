# css/syntax/07 — CSS 구문과 오류 복구: 선언·규칙·at-rule 단위로 버리는 규칙 — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,
> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.
> 정답까지 봤던 질문은 아래 복습 기록에 "틀림"으로 표시한다.
> 이 주제의 질문은 **예측형 위주**다 — 에러가 없는 언어라 **무엇이 남았는지 맞히는 것**이 인출의 전부다.
> ★ 답할 때는 「화면이 어떻게 보이나」가 아니라 「**`cssRules` 에 무엇이 남았나**」까지 말한다.

## 질문

### 1. 무엇이 사라지고 무엇이 남는가 (예측)

```css
.c1 { color: redd; background-color: #fde68a; }
.c2 { width: 10; height: 30px; }
.c3 { margin: 10px;; padding: 5px; }
```

- 세 규칙이 실제로 담고 있는 속성 목록을 각각 예측하라.
- `color: redd` 가 버려질 때 브라우저는 무엇을 출력하는가?
- 세미콜론이 둘(`;;`)이면 무슨 일이 일어나는가?
- 「버려졌다」를 눈이 아니라 값으로 확인하려면 무엇을 읽어야 하는가?

### 2. 선택자 하나가 목록 전체를 죽인다 (예측)

```css
.s1, ::totally-bogus, .s2 { color: #b91c1c; }
:is(.s3, ::totally-bogus, .s4) { color: #15803d; }
.s5 { color: #1d4ed8; }
```

- 이 시트에 남는 규칙은 몇 개이고, `.s1`\~`.s5` 는 각각 무슨 색인가?
- 두 번째 규칙의 `cssText` 를 읽으면 무엇이 보이는가?
- `:is()` 가 이 자리에서 하는 일을 한 낱말로 무엇이라 부르는가?
- `.card, .panel:has(> img) { padding: 16px }` 을 안전하게 고치면?

### 3. 모르는 at-rule 은 어디까지 삼키나 (예측)

```css
@totally-unknown { .a1 { color: #b91c1c; } }
.a2 { color: #b91c1c; }
@another-unknown some stuff here;
.a3 { color: #15803d; }
```

- `.a1`·`.a2`·`.a3` 는 각각 무슨 색인가?
- 블록이 있는 at-rule 과 없는 at-rule 의 회복 지점은 각각 무엇인가?
- 구형 브라우저에서 `@scope { … }` 안의 스타일이 전부 사라지는 이유가 이것과 같은가?
- 그래서 새 at-rule 을 쓸 때 기본 모양은 어디에 두어야 하는가?

### 4. 중괄호를 안 닫으면 (예측)

```css
.b1 { color: #b91c1c;
.b2 { color: #15803d; }
.b3 { color: #1d4ed8; }
```

- 이 시트에 남는 규칙은 몇 개인가?
- 그 규칙의 `cssText` 에 `&` 가 나타난다면 무슨 뜻인가?
- 문서 아무 데나 있는 `.b2` 와 `.b1` 안에 있는 `.b2` 는 각각 무슨 색인가?
- 중첩(nesting)이 표준이 되기 전에는 같은 코드가 어떻게 처리됐고, 왜 지금이 더 늦게 들키는가?

### 5. 괄호를 안 닫으면 (예측)

```css
.v3 { color: rgb(1,2,3; background-color: #fde68a; }
.v4 { color: #1d4ed8; }
.v5 { color: #15803d; }
```

- 이 시트에 남는 규칙은 몇 개이고 `.v3` 는 무엇을 담고 있는가?
- `;` 와 `}` 가 여기서 회복 지점이 되지 못하는 이유는 무엇인가?
- 닫히지 않은 주석(`/*`)도 같은 성질을 갖는가?
- 「어느 줄 아래로 전부 안 먹는다」는 증상에서 무엇을 먼저 의심해야 하는가?

### 6. 최상위에 선언을 두면 (예측)

```css
color: #b91c1c;
.y1 { color: #15803d; }
```

- `.y1` 은 무슨 색인가?
- 세미콜론이 왜 다음 규칙을 지켜 주지 못하는가?
- 파서가 최상위에서 기대하는 것은 무엇이고 프렐류드는 어디까지인가?
- `@layer base, theme`(세미콜론 없음) 뒤의 규칙이 죽는 것과 같은 모양인가?

### 7. 담겼는데 값이 안 먹는 경우 (경계)

```css
.v2 { --x: redd; color: var(--x); background-color: #fde68a; }
@media (totally-unknown-feature: 1) { .a4 { color: #b91c1c; } }
```

- `.v2` 규칙이 담고 있는 속성 목록은 무엇이고 `.v2` 의 `color` 는 무엇이 되는가?
- `getComputedStyle(v2).getPropertyValue('--x')` 는 무엇을 돌려주는가?
- `@media` 규칙은 `cssRules` 에 남는가? 남는데 왜 안 먹는가?
- 「미지원」을 한 낱말로 적으면 안 되는 이유를 세 경우로 갈라 말하라.

### 8. `!important` 는 어디까지 봐주나 (예측)

```css
.x1 { color: red! important; }     .x1 { color: #1d4ed8; }
.x2 { color: red !IMPORTANT; }     .x2 { color: #1d4ed8; }
.x3 { color: red important; }      .x3 { color: #1d4ed8; }
.x4 { color: red; !important }
```

- 네 문단의 색을 각각 예측하라.
- `!` 와 `important` 사이의 공백·주석은 허용되는가?
- `.x4` 처럼 선언 밖에 쓴 `!important` 는 앞 선언까지 죽이는가?
- 내가 쓴 형태와 `cssText` 가 보여 주는 형태가 다를 수 있는 이유는?

### 9. 진단 도구가 거짓말하는 자리 (경계)

```js
CSS.supports('selector(::totally-bogus)')
CSS.supports('selector(:is(.a, ::totally-bogus))')
document.styleSheets[0].cssRules
```

- 위 두 질의는 각각 무엇을 돌려주는가?
- 두 번째 질의의 답과 실제 규칙의 동작이 어긋나는 이유는 무엇인가?
- 세 번째 줄이 예외를 던지는 상황은 언제인가?
- 개발자 도구에서 「줄 그어진 선언」은 버려진 것인가?

### 10. 다른 주제와 잇기 (연결)

- 이 규칙이 **점진적 향상**의 토대라는 말이 무슨 뜻인가?

- 같은 속성을 두 줄로 쓰는 관용구가 동작하려면 캐스케이드의 어느 단계가 필요한가?
- 오류 복구로 충분한 경우와 `@supports` 가 필요한 경우를 가르는 기준은 무엇인가?
