# css/syntax/29 — Grid 영역: `grid-template-areas`·이름 붙은 라인 — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **판정은 「진단 3창」으로** 냈다 — `cssRules[i].style.gridTemplateAreas`(담겼나) → 매치(잡혔나) → `getComputedStyle(el).gridTemplateAreas`(이겼나).\
> **항목 좌표는 `getBoundingClientRect()` 로 따로** 쟀다. 전부 **Google Chrome 151.0.7922.173** headless 에서 실제로 렌더한 값이다.\
> 좌표는 별말이 없으면 **컨테이너의 바깥 왼쪽 위 모서리를 원점**으로 한 값이고, 테두리 2px 을 포함하므로 내용 영역의 왼쪽 위는 x=2, y=2 다.\
> 규칙은 [CSS Grid Layout Level 1](https://drafts.csswg.org/css-grid-1/) 로 접지했다.

## 정답

### 1. 도면을 읽는다

**계산값과 좌표** (Chrome 151 headless — 내용 폭 360px, `gap: 4px`)

```text
gridTemplateColumns  ->  "100px 256px"
gridTemplateRows     ->  "32px 64px 32px"
gridTemplateAreas    ->  "\"hd hd\" \"sb mn\" \". ft\""

hd  x=2    y=2    w=360  h=32
sb  x=2    y=38   w=100  h=64
mn  x=106  y=38   w=256  h=64
ft  x=106  y=106  w=256  h=32      <- x 가 106 = 왼쪽 칸이 비었다
```

**몇 행 몇 열인가**

- **3행 2열.** 문자열 개수가 행, 한 문자열의 토큰 개수가 열이다.

**`hd` 가 덮는 칸**

- **1행의 1\~2열 전부.** 같은 이름이 가로로 붙어 있으므로 한 영역이 된다(실측 w=360 = 내용 폭 전부).

**`.` 자리**

- **비어 있다.** 3행 1열에는 아무 항목도 없다 — `ft` 의 x 가 106 인 것이 그 증거다.
- 다만 **`grid-area` 를 안 준 항목이 있으면 자동 배치로 그 자리에 들어간다.** 4번 참고.

**트랙의 크기를 정하는가**

- **안 정한다.** 도면은 **자리만** 정한다. 크기는 `grid-template-columns`/`-rows` 의 몫이고 정본은 [27번](../27-grid-track-sizing/)이다.
- 그래서 **도면을 그대로 두고 트랙 크기만 바꾸는** 반응형이 가능하다.

### 2. 도면이 무효가 되는 세 조건

**결과** (Chrome 151 headless — 진단 3창)

```text
도면                  ① rule.style.gridTemplateAreas   ③ 계산값     판정
"a a b" "a c c"       ""                                none        무효 (a 가 ㄴ 자)
"a a"   "b b b"       ""                                none        무효 (열 개수 2 ≠ 3)
"a b a"               ""                                none        무효 (a 가 떨어져 있다)
"a a b" "c c b"       "\"a a b\" \"c c b\""             그대로      유효
```

**각각 어느 규칙**

```text
① 영역은 직사각형         ② 행마다 열 개수가 같을 것     ③ 같은 이름은 붙어 있을 것
   "a a b"                  "a a"                        "a b a"
   "a c c"                  "b b b"                       └─┬─┘
    └ a 가 ㄴ 자              2개 ≠ 3개                     떨어져 있다
```

**그 줄만인가 선언 전체인가**

- **선언 전체**다. 「세 번째 행만 버린다」 같은 부분 복구는 없다.

**어디서 확인하는가**

- **두 자리** — ① `cssRules[i].style.gridTemplateAreas` 가 **빈 문자열**인가, ③ `getComputedStyle(el).gridTemplateAreas` 가 **`none`** 인가.
- ①은 「파싱 단계에서 버려졌다」를, ③은 「최종 값이 없다」를 말한다.

**진단 3창**

```text
① cssRules[i].style.gridTemplateAreas   -> "" 이면 파싱 단계에서 버려짐
② 선택자가 그 요소를 잡았나              -> 안 잡았으면 선택자 문제
③ getComputedStyle(el).gridTemplateAreas -> none 이면 최종적으로 없다
```

- ①과 ③이 다를 수 있다 — 규칙은 담겼는데 **다른 규칙이 이겨서** ③이 `none` 인 경우다. 그래서 둘을 나눠 본다.

### 3. 무효일 때 화면에 무엇이 보이나

**계산값과 좌표** (Chrome 151 headless — `.bad` 의 도면이 무효)

```text
gridTemplateAreas    ->  "none"
gridTemplateColumns  ->  "100px 100px 100px 0px 8.04688px"   <- 암묵 열 둘이 자랐다
gridTemplateRows     ->  "30px 30px 0px 19px"                <- 암묵 행 둘이 자랐다

a  x=302  y=62  w=8.05  h=19
b  x=302  y=62  w=8.05  h=19      <- 셋이 같은 자리
c  x=302  y=62  w=8.05  h=19
```

**사라지는가**

- **안 사라진다.** 격자 **바깥 오른쪽 아래**에 셋이 겹쳐 쌓인다. 화면에는 맨 위 `c` 만 보인다.
- ★ 증상이 「안 그려진다」가 아니라 **「엉뚱한 데 겹쳐 있다」** 라는 것이 이 주제의 핵심이다.

**계산값에 생기는 일**

- **암묵 열과 암묵 행이 둘씩 자란다.** 선언에는 3열 2행뿐인데 계산값에 5열 4행이 온다.
- [28번](../28-grid-placement/)의 「정의 안 한 자리에 놓으면 격자가 자란다」가 여기서 **이름을 못 찾아** 일어난 것이다.

**`a` 가 무엇으로 읽히는가 — 네 단계**

```text
① grid-template-areas 가 무효 -> 선언이 통째로 버려진다 (계산값 none)
        ↓
② .a { grid-area: a } 의 a 는 이제 "영역 이름"이 아니다 -> "라인 이름 a" 로 읽힌다
        ↓
③ a 라는 이름의 라인도 없다 -> 명세 규칙: 암묵 라인이 전부 그 이름을 가진 셈 친다
        ↓
④ 네 축(row-start/column-start/row-end/column-end) 전부가 암묵 격자로 떨어져
   세 항목이 같은 자리에 겹친다
```

- ④가 「행·열 **양쪽**으로 밀려난다」의 이유다 — `grid-area: a` 한 줄이 **네 축을 동시에** `a` 로 만들기 때문이다(8번).

### 4. `.` 의 정확한 뜻

| 쓴 것 | 칸 수 |
|---|---|
| `.` | **한 칸** |
| `...` | **한 칸** (마침표 여럿이 붙어 있으면 하나) |
| `. . .` | **세 칸** (공백으로 갈라지면 각각) |

**`.` 자리에 자동 배치 항목이 들어가는가**

- **들어간다.** 실측 — 도면 `"a . b" "a . b"` 에 `grid-area` 를 안 준 항목을 넣었더니 **가운데 빈 칸**(x=102 y=2 w=100 h=40)에 들어갔다.
- `.` 은 「막아 둔 칸」이 아니라 「**이름이 없는 칸**」이다.

**계산값에서 `...` 은**

- **마침표 하나로 접힌다.** 실측 — 선언 `"a . b" "a ... b"` 의 계산값이 `"a . b" "a . b"` 였다.
- 같은 판에서 `a`(x=2)와 `b`(x=202)가 각각 **두 행을 덮었다**(h=80) — `...` 이 칸 하나로 읽혀 두 행의 열 개수가 맞았다는 뜻이다.

### 5. 이름 붙은 라인

**계산값과 좌표** (Chrome 151 headless)

```text
gridTemplateColumns
  -> "[full-start] 50px [main-start] 100px 100px [main-end] 50px [full-end]"
     ^ 라인 이름이 계산값에 그대로 실려 온다

grid-column: main   인 항목  ->  x=52  w=200
grid-column: full   인 항목  ->  x=2   w=300
```

**`main` 이 덮는 칸**

- **가운데 두 칸**(각 100px). x=52 는 첫 50px 트랙 바로 뒤다.

**`main-start / main-end` 와 같은가**

- **같다.** `grid-column: main` 은 `-start`/`-end` 짝이 있을 때의 **줄임**이다.

**계산값에 이름이 나오는가**

- **나온다.** [27번](../27-grid-track-sizing/)에서 본 「계산값은 px 로 푼 결과」에 **대괄호 이름까지 얹혀 온다.**

**번호로 쓰면**

```text
  [full-start]  50px  [main-start] 100px  100px  [main-end] 50px  [full-end]
       1                   2              3           4              5

  grid-column: main   ==   grid-column: main-start / main-end   ==   grid-column: 2 / 4
```

### 6. `-start`/`-end` 접미사 규칙

**결과** (Chrome 151 headless — `grid-template-areas` 를 안 쓴 격자)

```text
gridTemplateAreas   ->  "none"
gridTemplateColumns ->  "50px [main-start] 100px 100px [main-end] 50px"
gridTemplateRows    ->  "30px [main-start] 40px [main-end] 30px"

grid-area: main  인 항목  ->  x=52  y=32  w=200  h=40
```

**도면 없이 듣는가**

- **듣는다.** 영역 계산값은 `none` 인데 항목이 정확히 가운데에 놓였다.
- `-start`/`-end` 로 끝나는 **짝이 맞는 두 라인 이름**이 같은 이름의 영역을 만들기 때문이다.

**반대 방향도 성립하는가**

```text
  grid-template-areas 에 영역 hd        ->  라인 이름 hd-start · hd-end 가 생긴다
  [hd-start] … [hd-end] 라인 이름       ->  영역 hd 가 생긴 셈이 된다
```

- **성립한다.** 실측 — 도면 `"hd hd x" "y y y"` 만 쓴 격자에서 `grid-column: hd-start / hd-end` 인 항목이 **x=2 w=200** 으로 `hd` 영역과 정확히 겹쳤다.

**`-end` 가 없으면**

- **영역이 안 생긴다.** 실측 — `cols: 50px [main-start] 100px 100px 50px` 에 `grid-column: main` 을 주면\
  항목이 x=52 **w=250** 으로 **오른쪽 끝까지 삼켰고**, 트랙 계산값에 `0px` 짜리 암묵 열이 하나 붙었다.
- `main-start` 는 찾았고 `main-end` 를 못 찾아 **암묵 라인까지 밀고 간** 것이다 — 3번의 ③과 같은 규칙이다.

**행 쪽 이름을 지우면**

- **세로로 암묵 행까지 내려간다.** 실측 — x=52(가로는 그대로) **y=102**, 행 계산값이 `30px 40px 30px 0px 19px` 로 **암묵 행이 둘 자랐다.**
- 반대로 `grid-area: main` 대신 `grid-column: main` 을 쓰면 세로만 자동 배치로 가 **x=52 y=2** 가 된다.

### 7. 이름이 겹치면

**결과** (Chrome 151 headless — 두 경우를 나란히)

```text
경우 A   cols: [hd-start] 100px [hd-end] 100px 100px     areas: "x hd hd" "x y y"
         라인 이름 hd-start = 라인 1 · 도면의 hd-start = 라인 2
         -> 항목 x=2  w=100    (1열)   = 라인 이름이 이겼다

경우 B   cols: 100px [hd-start] 100px [hd-end] 100px     areas: "hd hd x" "x y y"
         도면의 hd-start = 라인 1 · 라인 이름 hd-start = 라인 2
         -> 항목 x=2  w=200    (1~2열) = 도면이 이겼다
```

**어느 쪽이 이기는가**

- **선언의 종류가 아니라 라인의 순서**가 정한다. **먼저 나온 라인이 이긴다.**
- 두 경우 모두 **라인 1**이 이겼다 — A 에서는 그게 라인 이름이었고 B 에서는 도면이 만든 이름이었다.

**둘 중 하나가 버려지는가**

- **아니다.** A 에서 영역 계산값은 `"x hd hd" "x y y"` 로 **살아 있고** 트랙 계산값도 `[hd-start] 100px [hd-end] 100px 100px` 로 **살아 있다.** 둘 다 유효한 채로 **좌표계만 섞인** 것이다.

**한 규칙으로**

- 명세의 표현으로는 「그 이름을 가진 **첫 번째 라인**부터」이고, 도면이 만든 암묵 이름도 **같은 줄에 선다.**

**실무 처방**

- **이름을 겹치지 않게 짓는 것.** 규칙을 외워 두는 것보다 안 겹치게 하는 편이 싸고 안전하다.

### 8. `grid-area` 의 네 얼굴

| 쓴 것 | 뜻 |
|---|---|
| `grid-area: hd` | 영역 이름 하나 — 영역이 없으면 **라인 이름**으로 읽힌다 |
| `grid-area: 2 / 1` | `row-start / column-start`(끝은 자동) |
| `grid-area: 2 / 1 / 3 / 3` | `row-start / column-start / row-end / column-end` |
| `grid-area: 2 / hd-start / 3 / hd-end` | **번호와 이름을 섞은 것** |

**섞어 쓸 수 있는가**

- **된다.** 실측 — 도면 `"hd hd x" "y y y"` 인 격자에서 `grid-area: 2 / hd-start / 3 / hd-end` 인 항목이\
  **2행 1\~2열**(x=2 y=32 w=200 h=30)에 놓였다. 번호와 도면이 만든 이름이 한 선언 안에서 같이 동작한다.

**이름 하나가 네 축 전부에 들어가는가**

- **들어간다.** `grid-area: hd` 는 `grid-row-start`·`grid-column-start`·`grid-row-end`·`grid-column-end` 를 **모두 `hd`** 로 만든다.
- 실측에서 항목의 `gridColumnStart`/`End` 계산값이 둘 다 `hd` 였다.

**3번과의 연결**

- 그래서 영역이 없을 때 **네 축이 동시에** 라인 이름 찾기로 떨어지고, 항목이 **행·열 양쪽 모두** 암묵 격자로 밀려난다.
- 실측의 x=302 **y=62** 가 그 결과다 — 한 축만 밀렸으면 x 나 y 하나만 튀었을 것이다.

### 9. 도면을 쓰는 자리와 안 쓰는 자리

**중단점마다 바꿀 때 유리한 점**

- **항목 쪽 CSS 를 안 고친다.** 미디어 쿼리 안에서 `grid-template-areas` 와 `grid-template-columns` 두 줄만 바꾸면 되고,\
  `.header { grid-area: hd }` 같은 선언은 한 글자도 안 건드린다.
- 레이아웃 변경이 **한 자리에 모인다** — 어디를 고쳐야 하는지 찾을 필요가 없다.

**항목 수가 정해지지 않은 목록에**

- **못 쓴다.** 도면은 칸 수가 **고정**이다. 개수가 유동적이면 자동 배치([28번](../28-grid-placement/))가 맞다.

**`order`·`dense` 보다 접근성에서 나은가**

- ★ **「도면이니까 안전하다」는 말은 아니다.** 도면으로도 마크업 순서와 다른 시각 순서를 얼마든지 만들 수 있다.
- 갈리는 점은 **엉킴이 자동으로 생기느냐 내가 적어 넣느냐**다 —\
  도면은 **눈으로 검토할 수 있고**, `dense` 는 **항목 수에 따라 결과가 바뀌어** 검토 시점에 안 보이던 엉킴이 나중에 생긴다.
- 어느 쪽이든 **마크업 순서와 시각 순서가 어긋나면 접근성 문제**라는 것은 같다([28번](../28-grid-placement/)·[목록의 **26번 주제**](../26-flex-wrap-gap-order/)).

**카드 내부 줄 맞추기**

- **도면으로는 안 된다.** 카드마다 격자가 따로라 서로의 줄을 모른다. **`subgrid`**([30번](../30-subgrid/))가 필요하다.

### 10. 무엇이 보장이고 무엇이 관찰인가

| 항목 | 어느 쪽 | 근거 |
|---|---|---|
| 직사각형이 아니면 무효 | **명세** | CSS Grid Level 1 의 `grid-template-areas` 문법 |
| 행마다 열 개수가 같아야 한다 | **명세** | 같은 자리 |
| `-start`/`-end` 양방향 규칙 | **명세** | 암묵 이름 규정 |
| 「그 이름의 첫 번째 라인」 규칙 | **명세** | 라인 이름 해석 규정 (7번의 실측은 그것을 **확인한 것**) |
| `...` 이 계산값에서 `.` 하나로 접힘 | **구현 관찰** | Chrome 151 |
| 무효한 도면이 `cssRules` 에서 빈 문자열 | **구현 관찰** | Chrome 151 (CSSOM 직렬화) |
| 라인 이름이 `[이름]` 으로 실려 오는 것 | **구현 관찰** | Chrome 151 |
| 밀려난 항목의 **정확한 좌표**(x=302 y=62) | **이 판의 값** | 재현되는 것은 「암묵 격자로 밀려난다」는 성질 |

**다시 찍어야 하는 칸**

- **계산값의 직렬화 형태** 셋(`...` 접힘 · 빈 문자열 · `[이름]` 표기). 버전이 오르면 이 칸을 다시 읽는다.
- 유효성 규칙과 이름 해석 규칙은 명세이므로 안 흔들린다.

### 11. 다른 주제와 잇기

**트랙 크기**

## 용어 풀이

- **영역(grid area)** — 라인 넷으로 둘러싸인 직사각형 구역.
- **도면(`grid-template-areas`)** — 문자열 목록으로 그린 격자 지도. 문자열 하나가 한 행이다.
- **`.`(null cell token)** — 이름이 없는 칸. `...` 도 **칸 하나**이고 `. . .` 은 셋이다.
- **이름 붙은 라인(named grid line)** — `[이름]` 으로 이름을 준 라인. 하나에 여럿 붙일 수 있다.
- **암묵 라인 이름** — 도면이 자동으로 만들어 주는 `<이름>-start`/`<이름>-end`.
- **`-start`/`-end` 접미사 규칙** — 짝이 맞는 두 라인 이름이 영역을 만들고, 영역이 두 라인 이름을 만든다. 양방향이다.
- **진단 3창** — `cssRules`(담겼나) → 매치(잡혔나) → `getComputedStyle`(이겼나).
- **명시 격자 / 암묵 격자** — 내가 정의한 트랙 / 엔진이 만든 트랙. 이름을 못 찾은 항목이 뒤로 밀려난다(28번).

| 무엇을 | 어떻게 | 결과 |

| 유효 대조군 | `"a a b" "c c b"` | 계산값 그대로 · a(x=2 w=200) b(x=202 h=60) c(x=2 y=32) |
| 무효일 때 항목이 어디로 | `.bad` 격자의 세 항목 좌표 | **셋 다 x=302 y=62 w=8.05** — 겹침 · cols `100px ×3 0px 8.04688px` |

**안 돌려 본 것** — 도면 이름에 `-start`/`-end` 접미사를 **직접 쓰는 형태**(`"a-start b"`)는 실행하지 않았다. 명세가 금지하는 형태이고 이 문서에서 쓸 일이 없어 **「안 돌려 봄」으로 남긴다.** 도면 이름에 한글을 쓰는 것도 같다.

**구현 의존 항목** — **계산값의 직렬화 형태**(`...` → `.` 접힘 · 무효한 선언이 `cssRules` 에서 빈 문자열 · 라인 이름 `[이름]` 표기)는 Chrome 151 에서 관찰한 것이다. 버전이 오르면 이 칸을 다시 찍는다.\
**밀려난 항목의 좌표**(x=302 y=62)는 이 판의 값이다 — 재현되는 것은 「암묵 격자로 밀려나 겹친다」는 성질이다.\
**엔진은 Chrome 하나다.** Firefox 155.0.1 은 이 환경에서 headless 스크린샷이 산출되지 않고 WebKit 은 이 머신에 없다 — **「두 엔진에서 확인했다」고 적지 않았다.** 크로스 브라우저 상태는 Grid 가 Baseline **widely**(2020-04-17)라는 데이터로만 접지했다.
