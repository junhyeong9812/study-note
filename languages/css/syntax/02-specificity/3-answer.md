# css/syntax/02 — 명시도 계산: (ID, 클래스, 타입) 세 자리와 무엇이 어디에 기여하나 — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **모든 색과 모든 `(A, B, C)` 값은 Google Chrome 151.0.7922.173 headless 에서 실제로 돌려 확인한 것**이다.\
> `(A, B, C)` 는 **동점 경쟁자 · 한 칸 낮은 경쟁자 두 판**으로 위아래를 고정했다(방법은 [2-summary.md](2-summary.md) 「손으로 세어 보기」).\
> 규칙은 [Selectors Level 4 §Calculating a selector's specificity](https://drafts.csswg.org/selectors-4/#specificity-rules) 로 접지했다.

## 정답

### 1. 이 문단은 무슨 색인가

**실행 결과** (Chrome 151 headless, `getComputedStyle(p).color`)

```text
원본                 ->  rgb(185, 28, 28)   = red
#x 를 [id="x"] 로     ->  rgb(21, 128, 61)   = green
```

**이 문단은 무슨 색인가**

- **red.**

```text
             A   B   C
  .a.b.c  (  0,  3,  0 )
  #x      (  1,  0,  0 )
             ^ 여기서 1 > 0 -> 끝. B·C 는 보지 않는다

  당선: #x  ->  red
```

**`.a.b.c` 가 더 나중에 쓰였는데 왜 순서가 안 통하는가**

- 등장 순서는 캐스케이드 **6단계**이고 명시도는 **5단계**다.
- 5단계에서 승자가 갈리면 **6단계는 불리지 않는다.**\
  순서는 "명시도까지 같을 때"의 마지막 수단이다.

**클래스를 열 개로 늘리면**

- **바뀌지 않는다.** `(0, 10, 0)` 도 `(1, 0, 0)` 에 진다.
- 자리끼리 **올림(환전)이 없다.** B 를 아무리 모아도 A 가 0 이면 A=1 을 못 이긴다.

**`#x` 를 `[id="x"]` 로 바꾸면**

- **green** 이 된다.

```text
  #x        (1, 0, 0)      ID 선택자    -> A 자리
  [id="x"]  (0, 1, 0)      속성 선택자   -> B 자리

  고르는 요소는 완전히 같다. 세기만 다르다.
  (0,3,0) > (0,1,0)  ->  .a.b.c 가 이긴다
```

- **같은 요소를 고르면서 세기를 낮추는 실용 기법**이기도 하다 — 마크업에 ID 가 이미 있을 때 쓴다.

### 2. 세 자리를 한 수로 더해도 되는가

**`(0, 3, 0)` 과 `(1, 0, 0)` 중 어느 쪽이 센가**

- **`(1, 0, 0)`** 이 세다. A 자리부터 비교하고, 거기서 갈리면 끝이다.

**"ID=100, 클래스=10, 타입=1" 모델은 어디서 깨지는가**

```text
그 모델대로면                            실제
+------------------------------+        +------------------------------+
| .a.b.c.d.e.f.g.h.i.j.k       |        | (0, 11, 0)  <  (1, 0, 0)     |
|   = 10 x 11 = 110            |        | A 가 0 이면 B 가 몇이든 진다  |
|   > 100 (#x)  -> 클래스가 이김|        | -> #x 가 이긴다               |
+------------------------------+        +------------------------------+
```

- **자릿수를 넘길 만큼 같은 종류를 쌓았을 때** 깨진다.
- 오늘날 유틸리티 클래스·자동 생성 클래스가 열 개 넘게 붙는 일은 드물지 않다.

**그 모델이 오래 살아남은 이유**

- **대부분의 경우 같은 답을 준다.** 클래스를 10개 이상 겹치는 CSS 를 사람이 손으로 잘 안 쓰기 때문이다.
- 즉 **반례를 만나기 전까지는 반증되지 않는 모델**이라, 틀린 채로 학습이 굳는다.

**실제로 어느 자리부터 보는가**

- **A → B → C** 순서로, 사전식(lexicographic) 비교다.
- 앞자리에서 갈리면 뒷자리는 **계산조차 하지 않는다.**

> **사전식 비교(lexicographic comparison)** — 앞자리부터 차례로 비교해 처음 갈리는 자리에서 승부를 내는 방식.\
> 예: 사전에서 `apple` 과 `az` 를 비교할 때 둘째 글자 `p` 와 `z` 에서 갈리고 나머지는 안 보는 것과 같다.

### 3. 두 규칙 중 어느 쪽이 이기는가

**실행 결과** (Chrome 151 headless)

```text
원본                        ->  rgb(185, 28, 28)   = red
:is(#box) 를 :where(#box) 로 ->  rgb(21, 128, 61)   = green
```

**두 선택자의 `(A, B, C)`**

```text
  :is(#box) .t
   ├ :is(#box)  인자 중 가장 센 것 = #box   (1, 0, 0)
   └ .t                                    (0, 1, 0)
                                    합 =   (1, 1, 0)

  :where(#box) .t
   ├ :where(#box)  무조건 0                 (0, 0, 0)
   └ .t                                    (0, 1, 0)
                                    합 =   (0, 1, 0)
```

**이 문단은 무슨 색인가**

- **red.** `(1,1,0) > (0,1,0)` 이라 `:is()` 쪽이 이긴다.
- 초록 규칙이 **더 나중에 쓰였지만** 6단계는 불리지 않는다.

**`:is(#box)` 를 `:where(#box)` 로 바꾸면**

- **green.** 둘 다 `(0, 1, 0)` 동점이 되어 6단계(등장 순서)로 내려가고, 나중에 쓴 초록이 이긴다.

**`:where()` 는 매칭도 안 하는가**

- **매칭은 한다.** `:is()` 와 **완전히 같은 요소**를 고른다.
- 다른 것은 **명시도 기여뿐**이다 — 안에 `#id` 가 백 개 있어도 `(0, 0, 0)`.
- 그래서 `:where()` 는 "그 요소를 고른다"와 "세게 고른다"를 **분리하는 유일한 문법**이다.

### 4. 문서에 없는 ID 가 승부를 가른다

**실행 결과** (Chrome 151 headless)

```text
원본              ->  rgb(185, 28, 28)   = red
#nope 를 .nope 로  ->  rgb(21, 128, 61)   = green
```

**`p:not(.zz, #nope)` 의 `(A, B, C)`**

```text
   ┌ p                        (0, 0, 1)
   └ :not(.zz, #nope)
        인자 목록 중 가장 센 것 = #nope   (1, 0, 0)
                          합 =  (1, 0, 1)
```

**문서에 `#nope` 가 없는데도 A 자리가 올라가는 이유**

- **명시도는 매칭 결과가 아니라 선택자의 모양만 본다.**\
  브라우저는 규칙을 **파싱할 때** 명시도를 계산해 둔다 — 그 시점에 문서에 무엇이 있는지는 보지 않는다.
- `:not()` 은 "제외한다"는 뜻이지만, 명시도 계산에서는 **그 안의 선택자가 그냥 거기 쓰여 있는 것**으로 취급된다.

**이 문단은 무슨 색인가**

- **red.** `(1,0,1) > (0,3,0)`.

**`#nope` 를 `.nope` 로 바꾸면**

- **green.** `p:not(.zz, .nope)` 는 `(0, 1, 1)` 이 되고, `.t.t.t` 의 `(0, 3, 0)` 이 이긴다.

### 5. 이 규칙의 명시도는 얼마인가

**`h1` 요소에 걸릴 때**

- **`(0, 0, 1)`** — 매치된 선택자는 `h1` 이다.

**`#x` 요소에 걸릴 때**

- **`(1, 0, 0)`** — 매치된 선택자는 `#x` 다.

**"규칙 하나의 명시도"가 성립하지 않는 이유**

```text
  h1, #x { color: red; }

  이것은 두 규칙을 짧게 쓴 것과 같다
  ┌ h1 { color: red }     매치 시 (0, 0, 1)
  └ #x { color: red }     매치 시 (1, 0, 0)

  명시도는 "규칙"이 아니라 "이번에 매치된 선택자"의 것이다
```

- 그래서 선택자 목록으로 묶어도 **세기가 가장 센 쪽으로 통일되지 않는다.**
- 이것이 `:is(h1, #x)` 와 갈리는 지점이다 — `:is()` 는 하나의 선택자라서 **가장 센 인자로 통일된다.**

**조합자는 어느 자리에 얼마를 보태는가**

- **아무 자리에도 0 이다.**
- `.a .b`(자손) · `.a > .b`(자식) · `.a + .b`(인접 형제) · `.a ~ .b`(일반 형제)는 **전부 `(0, 2, 0)`** 으로 같다.
- 전체 선택자 `*` 도 0 이다.

### 6. 다섯 개를 손으로 세어 보라

**실행 결과** (Chrome 151 headless — 다섯 행 모두 동점·한 칸 낮음 두 판을 통과했다)

| 선택자 | (A, B, C) |
|---|---|
| `p::before` | (0, 0, 2) |
| `p:nth-child(1 of .c1)` | (0, 2, 1) |
| `:is(p, #t1)` | (1, 0, 0) |
| `p:has(+ p#t2)` | (1, 0, 2) |
| `section:is(div section) p` | (0, 0, 4) |

**각각의 계산**

```text
p::before
   p         C +1
   ::before  C +1   (의사 '요소'다)          ->  (0, 0, 2)

p:nth-child(1 of .c1)
   p             C +1
   :nth-child()  B +1  (의사 클래스)
   of .c1        B +1  (S 의 명시도를 그대로) ->  (0, 2, 1)

:is(p, #t1)
   :is()  껍데기 0, 인자 중 가장 센 #t1       ->  (1, 0, 0)
   (바깥에 아무것도 없어도 A 가 올라간다)

p:has(+ p#t2)
   p                  C +1
   :has()  인자 "+ p#t2" 의 명시도
             p    C +1
             #t2  A +1                       ->  (1, 0, 2)

section:is(div section) p
   section              C +1
   :is(div section)  인자 = div section = C 2
   p                    C +1                 ->  (0, 0, 4)
```

**의사 요소와 의사 클래스는 다른 자리인가**

- **그렇다.** 의사 **요소**(`::before`·`::first-line`)는 **C 자리**, 의사 **클래스**(`:hover`·`:nth-child`)는 **B 자리**다.
- 콜론 개수(`:` 하나 / `::` 둘)가 그대로 자리 구분이 된다 — 외우기 좋은 대응이다.

**`of S` 가 더하는 것**

- **`S` 의 명시도 전체**를 더한다. `:nth-child()` 자신의 B +1 과는 **별도**다.
- `p:nth-child(1 of .c1.c2)` 는 `(0, 3, 1)` 이다(의사 클래스 1 + `.c1` + `.c2`, 타입 1). *(실측 확인.)*

**같은 클래스를 반복하면**

- **3 이다.** `p.c1.c1.c1` 은 `(0, 3, 1)`. *(실측 확인.)*
- 명시도는 **부품의 개수**를 세지, 서로 다른 부품의 종류 수를 세지 않는다.
- 이것을 일부러 쓰는 관용구가 `.btn.btn.btn` 이다 — ID 없이 B 자리만 올려 덮는다.

### 7. 명시도를 올려도 안 먹는다

**명시도보다 위에 있는 단계 셋**

```text
 1단계  출처와 중요도      상대가 !important 다
 3단계  요소 부착 스타일    요소에 style="" 가 있다
 4단계  캐스케이드 레이어    상대가 더 나중 레이어 / 내 규칙만 레이어 안이다
 -----------------------------------------------------
 5단계  명시도             <- 내가 올리려던 것
 6단계  등장 순서
```

- 이 셋 중 하나라도 걸려 있으면 **5단계는 실행되지 않는다.**
- 진단은 **위에서부터** 한다 — 선택자를 늘리기 전에 개발자 도구에서 이긴 선언을 먼저 본다.

**명시도는 몇 번째 단계인가**

- **5단계.** 여섯 중 다섯 번째다.

**`style=""` 는 명시도가 얼마인가**

- **명시도라는 것이 없다.** 선택자가 없기 때문이다.
- 옛 문헌의 "1,0,0,0" 네 칸 표기는 이것을 명시도 안에 넣어 보려던 흔적이고, 지금은 **캐스케이드 3단계**로 따로 빠져 있다.

**`!important` 는 어느 자리를 올리는가**

- **한 자리도 올리지 않는다.** 선언에 붙는 표시이지 선택자의 일부가 아니다.
- 하는 일은 **1단계에서 다른 칸으로 옮겨 타는 것**뿐이다. 칸이 다르면 명시도는 비교되지 않는다.
- 정본은 [01번 주제](../01-cascade-and-priority/2-summary.md).

### 8. 다른 주제와 잇기

**라이브러리가 "덮기 쉬운 기본값"을 주고 싶다면**

- **`:where()`** 로 감싼다.

```css
:where(.card) :where(h2, h3) { margin-block: 0; }   /* (0, 0, 0) */
```

- 이러면 사용자가 **클래스 하나**(`(0,1,0)`)로 덮을 수 있다.
- 더 큰 단위로는 라이브러리 전체를 **가장 앞 레이어**에 넣는다(`@layer`).

**`@layer` 와 `:where()` 는 각각 어느 단계인가**

| 도구 | 단계 | 하는 일 |
|---|---|---|
| `@layer` | **4단계** | 명시도를 보기 **전에** 갈라 버린다 |
| `:where()` | **5단계 안** | 명시도 기여를 0 으로 만든다 |

- 둘은 경쟁 관계가 아니라 **층이 다르다.** 보통 같이 쓴다 — 레이어로 큰 덩어리를 나누고, 레이어 안에서 `:where()` 로 개별 기본값을 평평하게 한다.

**중첩에서 `& .x` 가 명시도를 조용히 올리는 이유**

- 중첩 규칙이 펼쳐질 때 부모 선택자가 **`:is(...)` 로 감싸져** 들어간다.
- `:is()` 는 **가장 센 인자**의 명시도를 가지므로, 부모 목록에 `#id` 가 하나라도 있으면 **자식 규칙 전체가 `(1, …)` 이 된다.**
- 정본은 [목록의 **14번 주제**](../14-css-nesting/)(중첩). *(이 문서에서 중첩은 실행 확인하지 않았다.)*

**명시도가 동점이면**

- **6단계(등장 순서)** — 나중에 읽힌 선언이 이긴다.
- 그래서 6단계에 의존하는 CSS 는 **파일을 읽는 순서**에 취약하다 — 번들러 설정·`<link>` 순서·`@import` 위치가 바뀌면 조용히 결과가 달라진다.
- 순서 대신 **레이어로 의도를 명시**하는 것이 오늘의 처방이다.

## 용어 풀이

- **명시도(specificity)** — 선택자가 캐스케이드 5단계에서 갖는 세기. `(A, B, C)` 세 자리.
- **A / B / C 자리** — 각각 ID · (클래스·속성·의사 클래스) · (타입·의사 요소)의 개수.
- **올림이 없다** — 자리끼리 교환되지 않는다. `(0, 300, 0) < (1, 0, 0)`.
- **사전식 비교** — 앞자리부터 보고 처음 갈리는 자리에서 승부를 내는 방식.
- **타입 선택자** — 태그 이름으로 고르는 선택자(`div`). C 자리.
- **속성 선택자** — 속성으로 고르는 선택자(`[id="x"]`). **B 자리** — ID 선택자와 다르다.
- **의사 클래스** — `:` 하나. 상태·위치. B 자리.
- **의사 요소** — `::` 둘. 가상 상자. C 자리.
- **조합자** — 선택자를 잇는 기호(공백 `>` `+` `~`). 명시도 0.
- **선택자 목록** — 쉼표로 나열한 선택자들. 매치된 것 하나의 명시도만 쓴다.
- **`:where()`** — 매칭은 하되 명시도 기여가 0 인 의사 클래스.
- **`:is()` / `:not()` / `:has()`** — 인자 목록 중 **가장 센 것**의 명시도를 갖는 의사 클래스.
- **`of S`** — `:nth-child(An+B of S)` 의 필터 부분. 그 명시도가 통째로 더해진다.

**못 잰 것(「안 돌려 본 것」과 다르다)**\
① **명시도 그 자체.** `getComputedStyle` 도 `cssRules` 도 명시도를 노출하지 않는다 — 이 문서의 모든 `(A, B, C)` 는 **승패로 되짚은 값**이다. 방법이 그것뿐이다.\
② **`(0, 0, 0)` 의 아래쪽.** 더 낮은 경쟁자가 없어 `*` 행은 위쪽으로만 죄었다.\
③ **매치가 없는 선택자.** 되짚기는 매치를 전제하므로, 문서에 잡히는 요소가 없는 선택자는 이 방법으로 잴 수 없다.

**돌리지 않은 것** — 중첩(`& .x`)이 `:is()` 로 감싸지며 명시도를 올리는 것. 본문에도 「실행 확인하지 않았다」고 적혀 있고 정본은 [목록의 **14번 주제**](../14-css-nesting/)다.

**구현 의존 항목** — ① 색이 `rgb(…)` 형식으로 직렬화되는 것 ② 개발자 도구가 명시도를 `(1,2,0)` 으로 띄워 주는 것. **언어의 보장이 아니다.**

**엔진은 Chrome 151.0.7922.173 하나다.** Firefox 155 는 이 환경에서 headless 산출이 조용히 실패하고 WebKit 은 이 머신에 없다 — **「두 엔진에서 확인했다」고 적지 않았다.**
