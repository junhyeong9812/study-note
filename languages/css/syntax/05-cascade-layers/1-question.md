### 1. 레이어 밖 규칙은 어디에 서는가 (예측)

```html
<p class="u1">무슨 색?</p>
<style>
  @layer base, theme;
  @layer base  { .u1 { color: #b91c1c; } }
  @layer theme { .u1 { color: #15803d; } }
  .u1 { color: #1d4ed8; }
</style>
```

- 이 문단은 무슨 색인가?
- 레이어 밖 규칙이 서는 자리를 명세의 표현으로 말할 수 있는가?
- 레이어를 열 개 만들면 레이어 밖 규칙의 자리는 달라지는가?
- 기존 시트에 `@layer` 를 도입할 때 이 규칙이 만드는 첫 점검 항목은 무엇인가?

### 2. `!important` 하나로 뒤집히는 것 (예측)

```html
<p class="u2">무슨 색?</p>
<style>
  @layer base, theme;
  @layer base  { .u2 { color: #b91c1c !important; } }
  @layer theme { .u2 { color: #15803d !important; } }
  .u2 { color: #1d4ed8 !important; }
</style>
```

- 이 문단은 무슨 색인가?
- 1번과 선언 집합이 같은데 결과가 다른 이유를 명세 문장으로 설명하라.
- 뒤집히는 것은 레이어끼리만인가, **레이어 밖**도 같이 뒤집히는가?
- 이 설계가 출처 사다리(01번)의 무엇과 같은 꼴인가?

### 3. 레이어 순서는 무엇이 정하는가 (예측)

```css
@layer base  { .u1 { color: #b91c1c; } }
@layer theme { .u1 { color: #15803d; } }
@layer base  { .u1 { color: #1d4ed8; } }
```

- 이 문단은 무슨 색인가?
- `base` 를 마지막에 다시 열었는데도 자리가 안 바뀌는 이유는 무엇인가?
- 맨 아래에 `@layer theme, base;` 를 덧붙이면 결과가 달라지는가?
- 사전 선언 줄을 파일 맨 위에 두라는 관례가 이 답에서 어떻게 나오는가?

### 4. 익명 레이어 둘 (예측)

```css
@layer { .an { color: #b91c1c; } }
@layer { .an { color: #15803d; } }
```

- 이 문단은 무슨 색인가?
- 두 블록은 같은 레이어인가 다른 레이어인가? 판별 근거는?
- 두 블록을 `@layer solo { }` 두 개로 바꾸면 결과가 달라지는가? 이유는 같은가?
- 익명 레이어를 두 개 넘게 쓰면 안 되는 실무적 이유는 무엇인가?

### 5. 레이어와 명시도가 맞붙으면 (예측)

```html
<div id="app"><p class="t1">무슨 색?</p></div>
<style>
  @layer base, theme;
  @layer base  { #app .t1 { color: #b91c1c; } }
  @layer theme { p.t1    { color: #15803d; } }
</style>
```

- 이 문단은 무슨 색인가?
- `(1,1,0)` 이 `(0,1,1)` 에 지는 것을 캐스케이드 단계 번호로 설명하라.
- 이 결과가 `@layer` 의 존재 이유와 어떻게 이어지는가?
- 명시도로 싸우고 있다는 것은 무엇이 없다는 신호인가?

### 6. 중첩 레이어의 안과 밖 (예측)

```css
@layer outer {
  @layer inner { .ne { color: #b91c1c; } }
  .ne { color: #15803d; }
}
```

- 이 문단은 무슨 색인가?
- `outer` 안에 쓴 `.ne` 는 「레이어 밖」인가 아닌가?
- 이 결과가 1번의 규칙과 어떤 관계인가?
- `@layer outer.inner { }` 와 위 형태는 같은 것인가?

### 7. `@import` 로 서드파티를 아래에 깔기 (경계)

```css
@import url("vendor.css") layer(vendor);
@layer vendor, app;
@layer app { .btn { color: green; } }
```

- `vendor.css` 안의 `#id .btn { color: red }` 와 위 `app` 규칙 중 어느 것이 이기는가?
- `@import` 줄을 다른 규칙 **뒤로** 옮기면 무슨 일이 일어나는가?
- `layer(vendor)` 대신 `layer` 만 쓰면 무엇이 달라지는가?
- 이 실험을 `file://` 로 연 문서에서 하면 왜 거짓 결론이 나오는가?

### 8. 이 at-rule 들은 살아남는가 (경계)

```css
@layer base, theme
@layer base { .z { color: red } }
```

- 이 시트에 남는 규칙은 몇 개인가?
- 무엇이 잘못됐고, 파서는 어디까지 삼키는가?
- 이 실패는 에러로 드러나는가, 어떻게 확인하는가?
- 올바른 형태로 고치면 무엇이 달라지는가?

### 9. 레이어 안에서 예외 하나를 덮으려면 (왜)

- 이미 레이어 설계가 있는 프로젝트에서 상태 하나만 예외로 덮어야 한다. 어떤 수단을 쓰는가?
- 그 자리에 `!important` 를 쓰면 왜 두 번 실패하는가?
- 「레이어는 올리는 장치가 아니라 내리는 장치」라는 말이 무엇을 뜻하는가?
- 유틸리티 클래스(`.mt-0`)가 항상 이기게 하려면 어디에 두어야 하는가?
