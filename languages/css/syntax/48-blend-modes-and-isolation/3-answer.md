# css/syntax/48 — 혼합 모드와 `isolation` — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **모든 색은 Google Chrome 151.0.7922.173 headless 로 렌더한 스크린샷 PNG 를 파이썬 표준 라이브러리(`zlib`)로 디코드해 그 좌표의 `(r,g,b)` 를 읽은 값**이다.\
> **공식 값은 [Compositing and Blending Level 1](https://drafts.fxtf.org/compositing-1/) §blending 의 정의를 그대로 옮긴 파이썬 함수로 계산해 픽셀과 대조했다** — 손으로 유도한 수치는 없다.\
> ★ 렌더는 `--disable-gpu` **소프트웨어 렌더링**이다. 정확한 픽셀 값을 「보장」으로 읽지 마라.

## 정답

### 1. 공식을 손으로 따라가라

**실행 결과** (Chrome 151 headless — backdrop `(51,153,204)`, source `(204,102,51)`)

```text
모드          픽셀            공식 값         일치
multiply     ( 41, 61, 41)   ( 41, 61, 41)   ○
screen       (214,194,214)   (214,194,214)   ○
difference   (153, 51,153)   (153, 51,153)   ○
darken       ( 51,102, 51)   ( 51,102, 51)   ○
lighten      (204,153,204)   (204,153,204)   ○
```

**겹친 자리의 픽셀**

- **`(41, 61, 41)`** 이다. 채널별로 따라가면 이렇다.

```text
R: 51 x 204 / 255 = 40.8  -> 41
G: 153 x 102 / 255 = 61.2 -> 61
B: 204 x 51 / 255 = 40.8  -> 41
```

**`screen`**

- **`(214,194,214)`** 다. `255 - (255-Cb)(255-Cs)/255` — `multiply` 를 뒤집어서 한 것이라 항상 밝아진다.

**`difference`**

- **`(153, 51,153)`** 이다. `|Cb - Cs|` — `|51-204|=153`, `|153-102|=51`, `|204-51|=153`.

**`darken` 과 `lighten`**

- `darken` 은 채널별 **작은 쪽**: `(51,102,51)`.
- `lighten` 은 채널별 **큰 쪽**: `(204,153,204)`.

### 2. backdrop 이 하나가 아니다

**실행 결과** (Chrome 151 headless)

```text
띠의 왼쪽  (뒤 = #3399cc)   픽셀 (41, 61, 41)   공식 (41, 61, 41)   ○
띠의 오른쪽 (뒤 = #66cc33)   픽셀 (82, 82, 11)   공식 (82, 82, 10)   1 차이
띠 밖 왼쪽                   픽셀 (51,153,204)   = 무대 색 그대로
띠 밖 오른쪽                 픽셀 (102,204, 51)   = 무대 색 그대로
```

**왼쪽 픽셀**

- **`(41,61,41)`** — `#3399cc` 와 섞인 값.

**오른쪽 픽셀**

- **`(82,82,11)`** — `#66cc33` 와 섞인 값. 공식은 `(82,82,10)` 이라 **B 채널이 1 차이**였다(반올림 — 구현 세부다).

**섞는 대상**

- **뒤쪽 전부**다. 부모 하나도, 바로 뒤 형제 하나도 아니다.
- 그래서 **좌표마다 결과가 달라진다** — 한 요소 안에서 두 색이 나온 것이 그 증거다.

**범위의 경계**

- **쌓임 맥락**이다. 혼합은 그 경계를 못 넘는다. 그것이 4·5번의 격리다.

### 3. 손잡이 두 개

**실행 결과** (Chrome 151 headless — 페이지 배경 `#ffcc00` = `(255,204,0)`)

```text
선언                              픽셀            무엇과 무엇을 섞었나
background-blend-mode: multiply   ( 41, 61, 41)   #3399cc(자기 배경색) x #cc6633(자기 배경 이미지)
mix-blend-mode: multiply          (204, 82,  0)   #ffcc00(페이지) x #cc6633(합쳐진 자기 배경)
background-color 를 transparent   (204,102, 51)   섞을 아래 레이어가 없다 — 원본 그대로
```

**`.a` 의 픽셀**

- **`(41,61,41)`** — **자기 배경 이미지와 자기 배경색**을 섞은 값이다. 페이지 배경은 개입하지 않는다.

**`.b` 의 픽셀**

- **`(204,82,0)`** — **페이지 배경과 (합쳐진) 자기 배경**을 섞은 값이다.
- 자기 배경 스택이 먼저 합쳐져 불투명한 `#cc6633` 이 되고, 그것이 노랑과 섞인다.

**`background-color` 를 `transparent` 로**

- **`(204,102,51)`** — 원본 주황 그대로다. 섞을 아래 레이어가 없어졌다.

**바깥을 보는가**

- **안 본다.** `background-blend-mode` 의 backdrop 은 **자기 배경 스택의 아래쪽**뿐이다.

### 4. 한 줄로 혼합을 끈다

**실행 결과** (Chrome 151 headless)

```text
어디에 isolation 을 걸었나        픽셀             판정
(없음)                          (102,122,  0)   섞인다 — multiply(#ffcc00, #6699ff)
.g (배경 없는 중간 껍데기)         (102,153,255)   격리 — 원색 그대로
.src 자신                        (102,122,  0)   ★ 안 바뀐다
.page (배경 #ffcc00 을 가진 조상)  (102,122,  0)   ★ 안 바뀐다
```

**`.src` 의 픽셀**

- **`(102,122,0)`** 이다. `multiply((255,204,0), (102,153,255))` = `(102, 122.4→122, 0)`.

**`.g` 에 걸면**

- **`(102,153,255)`** — `#6699ff` 원색이다. `.g` 안에는 배경이 없으니 섞을 backdrop 이 없다.

**`.src` 자신에게 걸면**

- **안 바뀐다.** `isolation` 은 **자손의 혼합**을 끊는 선언이다. 자기 `mix-blend-mode` 는 못 끈다.

**`.page` 에 걸면**

- ★ **안 바뀐다.** `.page` 의 노란 배경은 `.page` **자신의 쌓임 맥락 안**에서 그려지므로 자손이 여전히 그것과 섞인다.
- 곧 「조상에 걸면 된다」는 절반만 맞다 — **배경을 가진 조상과 혼합 요소 사이**에 배경 없는 껍데기를 두고 거기에 걸어야 한다.
- 위 네 판은 **같은 문서에서 같은 색·같은 좌표**로 잰 것이다. 격리가 먹은 것은 `.g` 하나뿐이었다.

### 5. `isolation` 을 안 썼는데 격리된다

**실행 결과** (Chrome 151 headless — 여덟 판, 같은 좌표)

```text
부모에 붙인 것                     픽셀            판정
(1) 아무것도 없음                  (102,122,  0)   섞인다
(2) isolation: isolate            (102,153,255)   격리
(3) opacity: .999                 (102,153,255)   격리
(4) filter: brightness(1)         (102,153,255)   격리
(5) transform: translateZ(0)      (102,153,255)   격리
(6) will-change: opacity          (102,153,255)   격리
(7) position:relative; z-index:0  (102,153,255)   격리
(8) mix-blend-mode: normal        (102,122,  0)   섞인다
```

**섞이는 것**

- **(1) 과 (8) 둘**이다. 나머지 여섯은 전부 격리됐다.

**공통점**

- **쌓임 맥락**이다. 쌓임 맥락을 만드는 선언은 값이 무해해 보여도 전부 격리를 만든다.
- `mix-blend-mode: normal` 은 초깃값이라 쌓임 맥락을 안 만든다 — 그래서 유일한 예외였다.

**화면이 안 바뀌는 값도**

- **그렇다.** `opacity: .999`·`brightness(1)`·`translateZ(0)` 은 픽셀을 거의/전혀 안 바꾸는데 격리는 만든다.

**대표 사고**

- **「페이드인 애니메이션(`opacity`)을 붙였더니 혼합이 사라졌다.」**
- 계산값은 `multiply` 그대로라 개발자 도구로도 안 잡힌다. 조상을 거슬러 올라가며 `opacity`·`transform`·`filter`·`will-change`·`z-index` 를 훑어야 한다.

### 6. 공식이 안 통하는 자리

**분리 가능이 아닌 넷**

- **`hue`·`saturation`·`color`·`luminosity`** 다. RGB 를 한 덩어리로 보고 색상·채도·명도를 옮기므로 채널별 곱으로는 설명이 안 된다. 이 문서는 이 넷을 재지 않았다.

**흰 배경 위의 `multiply`**

- **아무 일도 안 일어난 것처럼 보인다.** `multiply(255, Cs) = 255 × Cs / 255 = Cs` — 흰색이 `multiply` 의 **항등원**이다.

**검정 배경 위의 `screen`**

- 같은 이유로 **아무 일도 안 일어난다.** `screen(0, Cs) = Cs` — 검정이 `screen` 의 항등원이다.

**보색일 때의 `color-dodge`**

- **전 채널이 255**(흰색)가 된다. `Cb / (1 - Cs)` 에서 분모가 `Cb` 와 같아져 1 로 포화되기 때문이다.
- 실측에서도 `color-dodge` 가 `(255,255,255)`, `color-burn` 이 `(0,0,0)` 이었다 — **공식과는 맞지만 그 모드의 성격을 보여 주는 값이 아니다.** 다른 색 조합으로 다시 재야 한다.

### 7. `overlay` 를 손으로

**표현**

```text
overlay(Cb, Cs) = hard-light(Cs, Cb)      <- 인자가 뒤바뀐다
hard-light(b, s) = multiply(b, 2s)        (s <= 127.5)
                 = screen(b, 2s - 255)    (s >  127.5)
```

곧 `overlay` 는 **backdrop 이 밝은지 어두운지로 분기**하고, `hard-light` 는 **source 로 분기**한다.

**R 채널** (`Cb = 51`, `Cs = 204`)

- `Cb = 51 <= 127.5` 이므로 `multiply(204, 2×51=102) = 204 × 102 / 255 = 81.6` → **82**.

**G 채널** (`Cb = 153`, `Cs = 102`)

- `Cb = 153 > 127.5` 이므로 `screen(102, 2×153-255=51) = 255 - (255-102)(255-51)/255 = 132.6` → **133**.

**실행 결과** (Chrome 151 headless)

```text
overlay      픽셀 ( 82,133,173)   공식 ( 82,133,173)   ○
hard-light   픽셀 (173,122, 82)   공식 (173,122, 82)   ○
```

**둘이 다른 이유**

- **분기 기준이 다르다** — `overlay` 는 backdrop 으로, `hard-light` 는 source 로 갈린다. 같은 식에 인자만 바꿔 넣은 것이다.

### 8. 조용히 버려지는 선언

**실행 결과** (Chrome 151 headless — 「진단 3창」)

```text
입력  .x { mix-blend-mode: multiplyy; background-blend-mode: 50%; isolation: isolated; }

창 1  cssRules[0] = .x { }                      ★ 세 선언이 전부 사라졌다
창 2  querySelectorAll('.x').length = 1         선택자는 잡혔다
창 3  mix-blend-mode = normal · background-blend-mode = normal · isolation = auto

대조   .y { mix-blend-mode: multiply; background-blend-mode: multiply, screen; isolation: isolate; }
      cssRules 에 셋 다 남았고 계산값도 그대로였다
```

**세 창**

- 창 1 에서 **셋 다 잡힌다** — 규칙 텍스트가 빈 `{ }` 다.
- 창 2 는 정상, 창 3 은 초깃값을 돌려준다.

**규칙은**

- **살아남는다.** 선언 단위로만 죽는다.

**세 계산값**

- `normal` · `normal` · `auto` — 전부 초깃값이다.

**제4의 상태**

- **격리**다. `cssRules` 에 `multiply` 가 담겨 있고, 선택자도 잡혔고, 계산값도 `"multiply"` 인데 **화면은 원색**인 경우다.
- 조상 어딘가의 쌓임 맥락이 섞을 backdrop 을 잘라 버린 것이고, **계산값으로는 절대 안 잡힌다.** 픽셀을 읽어야 한다.

### 9. 값은 몇 개 쓰나

**`mix-blend-mode`**

- **하나**다. 요소는 하나이므로 섞을 관계도 하나다.

**`background-blend-mode`**

- **레이어마다 하나**, 쉼표로 나열한다. 실측에서 `multiply, screen` 이 그대로 `cssRules` 와 계산값에 남았다.
- 값이 레이어 수보다 적으면 목록이 되풀이된다(배경 속성 공통 규칙 — [목록의 **44번 주제**](../44-backgrounds-and-object-fit/)).

**레이어가 하나뿐이면**

- **아무 일도 안 일어난다.** 실측: `background-color: transparent` + 이미지 한 겹에 `multiply` 를 걸었더니 픽셀이 `(204,102,51)` 원본 그대로였다.

**`isolation` 의 값**

- **`auto`(기본)와 `isolate`** 둘이다.

### 10. 다른 주제로 잇기

**혼합의 경계**

- **쌓임 맥락**이고 정본은 [목록의 **22번 주제**](../22-stacking-context-and-z-index/)다. 이 문서는 「쌓임 맥락 = 격리」라는 등식까지만 다룬다.

**backdrop root 와 격리**

- ★ **같은 축이 아니다.** [47번](../47-filter-and-backdrop-filter/2-summary.md)의 실측이 그것을 갈랐다.

```text
                     쌓임 맥락(=격리)   backdrop root
  isolation: isolate      O                X     ★ 여기서 갈렸다
  opacity: .999           O                O
  filter: brightness(1)   O                O
```

- `isolation: isolate` 가 걸린 조상 아래에서도 `backdrop-filter` 는 **그대로 뒤를 흐렸다**(범위 `17~244`). `opacity`·`filter` 는 껐다(`0~255`).

**배경 레이어 순서**

- [목록의 **44번 주제**](../44-backgrounds-and-object-fit/)(배경과 대체 요소 맞춤)다.

**합성 연산자의 표면**

- **`mask-composite`** 이고 [49번](../49-clip-path-and-mask/2-summary.md) 주제다. `mix-blend-mode` 가 「색을 어떻게 섞나」라면 그쪽은 「알파를 어떻게 합치나」다.

## 용어 풀이

- **backdrop(배경판)** — 지금 그리는 것의 뒤에 이미 그려진 모든 것을 합친 결과. 좌표마다 다르다.
- **source(원본)** — 지금 그리는 요소 또는 배경 레이어.
- **분리 가능(separable) 모드** — R·G·B 를 따로 계산하는 12개 모드. 공식 대조가 가능하다.
- **분리 불가(non-separable) 모드** — `hue`·`saturation`·`color`·`luminosity`. 채널별 산술로 설명되지 않는다.
- **항등원(identity)** — 그 연산에서 상대를 안 바꾸는 값.\
  예: `multiply` 에서 흰색(255), `screen` 에서 검정(0). 그 배경 위에서는 모드를 걸어도 결과가 안 바뀐다.
- **격리(isolation)** — 한 묶음을 먼저 한 장으로 합쳐 바깥과 더 이상 안 섞이게 하는 것. 쌓임 맥락을 만드는 모든 선언이 이것을 만든다.
- **`isolation: isolate`** — 격리 전용 선언. **자손의** 혼합을 끊는다. 자기 자신에게는 효과가 없고, **자기 배경을 가진 조상**에 걸어도 그 배경과는 계속 섞인다.
- **쌓임 맥락(stacking context)** — 그 안의 `z-index` 가 바깥과 겨루지 못하는 독립 층이자 **혼합의 경계**. 정본은 [목록의 **22번 주제**](../22-stacking-context-and-z-index/).
- **backdrop root** — `backdrop-filter` 가 읽을 수 있는 「뒤」의 범위. 격리와 겹치지만 같은 축이 아니다. 정본은 [47번](../47-filter-and-backdrop-filter/2-summary.md).
- **진단 3창** — `cssRules` → `querySelectorAll` → `getComputedStyle`. 이 주제에는 **셋 다 통과하는데 화면이 다른 제4의 상태**(격리)가 있다. 정본은 [07번](../07-syntax-and-error-recovery/2-summary.md).
