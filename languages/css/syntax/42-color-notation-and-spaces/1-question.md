# css/syntax/42 — 색 표기와 색 공간 — 질문

> 먼저 답해 보고, 막히면 [2-summary.md](2-summary.md), 그래도 막히면 [3-answer.md](3-answer.md).
> 예측형은 **출력을 먼저 적고** 이유를 적는다. 기준: **Google Chrome 151.0.7922.173** headless.
> 색은 눈으로 구분이 안 되므로 답에 **RGB 수치**를 적는다 — 「비슷한 파랑」은 답이 아니다.
> 선행: 없음. 이 주제가 [43번](../43-color-mix-and-relative-color/1-question.md)·[45번](../45-gradients-and-interpolation/1-question.md)의 선행이다.

### 1. 다섯 표기는 같은 색인가 (예측)

```css
.a { color: #f80; }
.b { color: rgb(255, 136, 0); }
.c { color: rgb(255 136 0); }
.d { color: hsl(32 100% 50%); }
.e { color: hwb(32 0% 0%); }
```

다섯 요소의 `getComputedStyle(el).color` 를 각각 적어라.\
**다섯 문자열이 서로 같은가, 다른가.** 다르다면 어디가 다른가.

### 2. 범위를 넘긴 수와 모르는 함수 — 어느 쪽이 살아남나 (예측)

```css
.a { color: notacolor(1 2 3); }
.b { color: rgb(300 -20 0); }
.c { color: hsl(32 100 50); }
```

셋의 `cssRules[i].style.cssText` 와 `getComputedStyle(el).color` 를 각각 적어라.\
**셋 중 선언째 버려진 것은 몇 번인가.**

### 3. `getComputedStyle` 이 색을 무엇으로 돌려주나 (예측)

```css
.a { color: hsl(32 100% 50%); }
.b { color: oklch(0.75 0.17 60); }
.c { color: lab(70 40 70); }
.d { color: color(display-p3 1 0.5 0); }
.e { color: rgb(255 136 0 / 1); }
.f { color: rgba(255, 136, 0, 0.5); }
```

여섯의 계산값을 적어라.\
**어느 것이 `rgb(...)` 로 접히고 어느 것이 적은 그대로 남는가** — 그 경계를 한 줄로 말해라.

### 4. 같은 `l` 인데 밝기가 같은가 (예측)

```css
.y { background: hsl( 60 100% 50%); }   /* 노랑 */
.g { background: hsl(120 100% 50%); }   /* 초록 */
.r { background: hsl(  0 100% 50%); }   /* 빨강 */
.b { background: hsl(240 100% 50%); }   /* 파랑 */
```

네 칸의 픽셀 RGB 를 적고, **눈에 보이는 밝기가 같은지** 답해라.\
같지 않다면 **가장 밝은 칸과 가장 어두운 칸의 상대 휘도가 몇 배 차이인지** 적어라.\
그리고 **`hsl` 대신 무엇을 쓰면 고정되는지**를 선언 한 줄로 적어라.

### 5. 넓은 색 영역 색을 sRGB 화면에 칠하면 (예측)

```css
.p3  { background: color(display-p3 1 0 0); }
.srgb{ background: rgb(255 0 0); }
```

두 칸의 **픽셀 RGB** 와 두 칸의 **계산값**을 각각 적어라.\
**픽셀이 같은가 다른가. 계산값은 같은가 다른가.** 둘의 답이 갈린다면 왜 갈리는가.

### 6. `transparent` 의 계산값은 무엇인가 (예측)

```css
.t { color: transparent; }
```

계산값 문자열을 적어라. **거기 들어 있는 세 숫자가 왜 하필 그 값인지** 한 줄로 설명해라.

### 7. 둘 중 어느 쪽이 더 위험한가 (왜)

모르는 색 함수(`notacolor(1 2 3)`)와 범위를 넘긴 수(`rgb(300 -20 0)`) 중, **디버깅할 때 더 위험한 것은 어느 쪽이고 왜인가.**

### 8. `currentColor` 는 상속되는가 (경계)

`border-color` 를 한 번도 안 적었는데 테두리가 부모 글자색을 따라간다. **무엇이 상속된 것인가** — `border-color` 인가, `currentColor` 인가, `color` 인가.

### 9. 「계산값이 `oklch(...)` 다」와 「화면이 그 색이다」는 왜 다른 문장인가 (경계)

두 문장이 갈리는 지점을 **색 하나가 지나는 네 칸** 중 어느 칸과 어느 칸으로 짚어라.

### 10. 색이 안 나올 때 어느 창부터 여나 (연결)

`color: oklch(...)` 를 적었는데 검정으로 보인다. **진단 3창** 중 「내가 적은 표기 자체가 안 먹혔다」를 잡아 주는 창은 어느 것이고, 그때 무엇이 보이나.

### 11. `oklch` 에서 `C` 를 0 으로 하면 (예측)

`oklch(0.7 0 150)` 은 어떤 색인가. 그리고 그것이 `#808080` 같은 평범한 회색과 **어떻게 다른가.**

### 12. 접근성 대비를 `hsl` 의 `l` 로 맞추면 안 되는 이유 (왜)

「본문 글자색은 전부 `l: 45%` 로 통일했으니 대비는 일정하다」는 주장의 어디가 틀렸는지, **4번에서 잰 수치를 근거로** 말해라.
