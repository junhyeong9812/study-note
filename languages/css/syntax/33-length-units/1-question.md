# css/syntax/33 — 길이 단위: `px`·`em`·`rem`·`%`·`ch`·`ex` — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,
> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.
> 정답까지 봤던 질문은 아래 복습 기록에 "틀림"으로 표시한다.
> 이 주제의 질문은 **예측형 위주**다 — 아는지가 아니라 **몇 px 이 될지 맞힐 수 있는지**를 묻는다.
> ★ **답을 px 숫자로 적어라.** "커진다"는 답이 아니다.

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

### 1. 같은 `2em` 이 두 숫자가 된다 (예측)

```css
#p { font-size: 20px; }
#c { font-size: 2em; width: 2em; margin-left: 2em; }
```

- `#c` 의 계산된 `font-size` 는 몇 px 인가?
- `#c` 의 계산된 `width` 는 몇 px 인가?
- 두 값이 다르다면, `font-size` 만 다른 기준을 쓰는 이유를 한 문장으로 말할 수 있는가?

### 2. `em` 사슬을 네 겹 내려간다 (예측)

```css
body   { font-size: 32px; }
.chain { font-size: 1.25em; }   /* .chain 을 네 겹으로 중첩했다 */
```

- 1겹 \~ 4겹의 계산된 `font-size` 를 네 숫자로 적을 수 있는가?
- `1.25em` 을 `1.25rem` 으로 바꾸면 네 숫자는 어떻게 되는가?

### 3. `%` 의 기준을 속성별로 가른다 (예측)

```css
#cb { width: 400px; height: 200px; font-size: 20px; }
/* #cb 의 자식들 */
.a { width: 50%; }         .b { height: 50%; }
.c { padding-top: 10%; }   .d { margin-left: 10%; }
.e { font-size: 150%; }    .f { line-height: 150%; }
```

- 여섯 선언의 계산값을 각각 px 로 적을 수 있는가?
- 그중 **부모가 아니라 자기 자신**을 기준으로 삼는 것은 어느 것인가?
- `.e` 와 `.f` 는 둘 다 `150%` 인데 기준이 다르다 — 각각 무엇인가?

### 4. 세로 여백의 `%` 는 무엇을 보는가 (왜)

- `padding-top: 10%` 가 부모의 **높이**가 아니라 **폭**을 기준으로 삼는 이유를 순환 구조로 설명할 수 있는가?
- 그 규칙 덕분에 성립했던 옛 관용구는 무엇이고, 오늘은 무엇으로 대체되는가?

### 5. `height: 50%` 가 아무 일도 안 한다 (경계)

```css
.parent { height: auto; }
.child  { height: 50%; }
```

- `.child` 의 실제 높이는 어떻게 되는가?
- 왜 `%` 를 풀지 못하는가?

### 6. `transform` 과 `border-radius` 의 `%` (예측)

```css
.t { width: 100px; height: 40px; transform: translate(50%, 50%); }
.r { width: 200px; height: 100px; border-radius: 10%; }
```

- `.t` 가 실제로 몇 px 씩 움직이는가? 그 기준은 부모인가 자기 자신인가?
- `.r` 의 모서리에서 깎이는 타원은 가로·세로 몇 px 인가?

### 7. `ch` 와 `ex` 는 무엇에 달려 있나 (예측)

```css
div { width: 10ch; font-size: 20px; }
.mono  { font-family: "DejaVu Sans Mono", monospace; }
.serif { font-family: "Liberation Serif", serif; }
```

- 두 칸의 폭이 같은가 다른가? 다르다면 무엇이 그 차이를 만드는가?
- `ch` 가 재는 것을 한 문장으로 말할 수 있는가? `ex` 는?
- 지정한 글꼴이 없어 폴백이 쓰이면 `ch` 값은 어떻게 되는가?

### 8. `px` 은 화면의 점 하나인가 (왜)

- `devicePixelRatio` 가 1에서 2로 바뀌면, `width: 100px` 상자의 계산값은 어떻게 되는가?
- 그때 실제로 달라지는 것은 무엇인가?
- `1in` 은 화면에서 몇 px 이고, 그 값은 어디서 정해졌는가?

### 9. 루트에서 쓴 `rem` (경계)

- `html { font-size: 2rem }` 이라고 쓰면 루트의 계산된 글꼴은 몇 px 이 되는가?
- 왜 그 숫자인가?
- 그 뒤에 나오는 다른 요소의 `1rem` 은 몇 px 인가?

### 10. 다른 주제로 잇기 (연결)

- 단위가 **어느 단계에서 픽셀이 되는지**의 정본은 목록의 몇 번 주제인가?
- `%` 만 계산값 단계에서 `%` 인 채로 남는 이유는 무엇인가?
- 기준이 **뷰포트**나 **컨테이너**인 단위는 목록의 몇 번 주제인가?
- `min(100%, 60ch)` 처럼 단위를 섞어 고르는 문법은 목록의 몇 번 주제인가?
- `%` 가 잰 폭이 **네 겹 상자 중 어느 칸**인지는 목록의 몇 번 주제인가?
