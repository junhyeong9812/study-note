# css/syntax/11 — `:is()`·`:where()`·`:not()` 와 명시도 — 질문

> 복습은 항상 이 파일에서 시작한다. **맨기억으로 답을 시도**하고,
> 막히면 [2-summary.md](2-summary.md)를 힌트로, 최후에만 [3-answer.md](3-answer.md)를 연다.
> 정답까지 봤던 질문은 아래 복습 기록에 "틀림"으로 표시한다.
> 이 주제의 질문은 **예측형 위주**이고, 답을 **두 갈래로 나눠** 적는다 —
> ① 무엇이 잡히나(개수) ② 그래서 이겼나(`(A, B, C)`). 하나만 맞으면 절반만 맞은 것이다.
> 명시도 **계산 규칙 자체**는 [02번 주제](../02-specificity/1-question.md)가 묻는다. 여기는 **이 셋이 그 계산에 무엇을 넣는가**만 묻는다.
> ★ **예측형이 7개로 §2-1 의 상한(6개)을 넘는다.** 세 함수 × 두 축(명시도·관대함)이 각각 독립 실패 모드라 묶으면 복합 문항이 된다.

## 질문

<!-- 질문 하나 = "?" 하나 = 한 줄. 유형: (왜) / (예측) / (경계) / (연결) -->

1\~5번은 아래 문서 위에서 답한다.

```html
<div id="box"><p class="t" id="t1">대상</p></div>
<p class="t" id="t2">둘째</p>
```

### 1. 세 껍데기가 값을 부르는 법 (예측)

```css
p:is(.t, #zz)     { }
p:where(.t, #zz)  { }
p:not(.zz, #zz)   { }
```

- 셋의 `(A, B, C)` 는 각각 얼마인가?
- 셋은 각각 **몇 개**를 잡는가?
- `:is()` 와 `:where()` 의 답이 **어느 쪽에서만** 갈리는가?
- 껍데기 자신(`:is`·`:where`·`:not`)은 어느 자리에 얼마를 보태는가?

### 2. 이 문단은 무슨 색인가 (예측)

```html
<p class="t">이 줄</p>
<style>
  p:not(.zz, #nope)  { color: red; }
  p:is(.t, .u)       { color: green; }
  p:where(.t, #nope) { color: blue; }
</style>
```

- 세 규칙의 `(A, B, C)` 를 각각 계산할 수 있는가?
- 이 문단은 무슨 색인가?
- 진 두 규칙은 `cssRules` 에서 사라졌는가, 담겨 있는가?
- `#nope` 를 `.nope` 로 바꾸면 무슨 색이 되는가?

### 3. 목록에 강한 것 하나를 끼워 넣으면 (예측)

```css
:is(h1, h2, h3, #hero) .sub { }
p:is(.t, #zz, div p)        { }
```

- 둘의 `(A, B, C)` 는 각각 얼마인가?
- `h1` 에 매치될 때와 `#hero` 에 매치될 때 명시도가 다른가?
- 목록 인자가 셋이면 셋을 다 더하는가?
- 이것을 피하려면 무엇을 쓰는가?

### 4. 중첩하면 안쪽 값이 어디까지 올라오는가 (예측) ★

```css
p:not(:is(#zz))     { }
p:is(:where(#t1))   { }
p:not(:where(#zz))  { }
```

- 셋의 `(A, B, C)` 는 각각 얼마인가?
- 어느 것이 ID 를 끝까지 올려 보내고 어느 것이 끊는가?
- `:where()` 가 "벽"이라는 말은 무슨 뜻인가?
- "제외는 하되 명시도는 안 올리고 싶다"면 어떻게 쓰는가?

### 5. 문서에 없는 ID 가 승부를 가른다 (왜)

```css
.card:not(#legacy) { padding: 8px; }
```

- 문서에 `#legacy` 가 아예 없어도 A 자리가 올라가는가?
- 그 이유를 한 문장으로 말할 수 있는가?
- 명시도는 **매칭 결과**를 보는가, **선택자의 모양**을 보는가?
- 이 함정이 `:is()` 보다 `:not()` 에서 더 조용한 이유는 무엇인가?

### 6. 관대함 — 모르는 선택자 하나가 어디까지 죽이나 (예측) ★

```css
.t, :unknownzz          { color: red; }
:is(.t, :unknownzz)     { color: blue; }
:where(.t, :unknownzz)  { color: green; }
:not(.zz, :unknownzz)   { color: teal; }
:has(.t, :unknownzz)    { color: navy; }
```

- 다섯 중 `cssRules` 에 남는 것은 몇 개이고 무엇인가?
- 남은 것들의 `selectorText` 는 내가 쓴 그대로인가?
- 관대한 것은 어느 둘인가?
- 이것을 화면만 보고 진단할 수 있는가, 없다면 무엇을 읽어야 하는가?

### 7. 인자가 전부 죽으면 (경계)

```css
:is(:unknownzz) { color: red; }
```

- 이 규칙은 `cssRules` 에 남는가?
- 남는다면 `selectorText` 는 무엇인가?
- 이 선택자는 몇 개를 잡는가?
- "규칙은 살아 있는데 매치가 0개"인 상태를 어떻게 진단하는가?

### 8. `:where()` 로 기본값을 준다 (예측)

```html
<article class="prose"><h2 class="lead">제목</h2></article>
<style>
  :where(.prose) h2 { color: gray; margin: 0; }
  .lead             { color: red; }
</style>
```

- 제목은 무슨 색인가?
- 두 선택자의 `(A, B, C)` 는 각각 얼마인가?
- `margin: 0` 은 덮이는가?
- `:where(.prose) h2` 를 `.prose h2` 로 바꾸면 무슨 색이 되는가?

### 9. `:not()` 의 인자 목록은 AND 인가 OR 인가 (경계)

```css
p:not(.a, .b)      { }
p:not(.a):not(.b)  { }
```

- 둘은 같은 것을 잡는가?
- `:not(.a, .b)` 를 말로 읽으면 무엇인가?
- `:is(.a, .b)` 의 인자 목록은 AND 인가 OR 인가?
- 이 둘의 「모양」이 반대인 것과 「힘」이 같은 것을 한 문장으로 말할 수 있는가?

### 10. 「안 잡혔다」와 「잡혔는데 졌다」 (연결)

- 이 둘을 각각 무엇으로 확인하는가?
- `:is` 를 `:where` 로 바꿨더니 스타일이 사라졌다면 어느 쪽인가?
- 진단 순서 셋을 대고, 각각 무엇을 읽는지 말할 수 있는가?
- 이 셋을 세운 주제는 어느 것인가?

### 11. 관대함은 어디까지 공유되나 (경계)

```css
:is(.t, :unknownzz)             { }
:not(.zz, :unknownzz)           { }
:has(.t, :unknownzz)            { }
:nth-child(2n of :unknownzz)    { }
```

- 넷 중 규칙이 살아남는 것은 무엇인가?
- 셋(`:is`·`:where`·`:not`)이 공유하는 성질과 공유하지 **않는** 성질을 각각 대라.
- 「관대한 목록」과 「관대하지 않은 목록」은 명세 용어로 무엇과 무엇인가?
- `of S` 가 어느 쪽인지의 정본은 어느 주제인가?

### 12. 다른 주제와 잇기 (연결)

- 명시도를 **내리는** 문법은 몇 개이고 무엇인가?
- `@layer` 와 `:where()` 는 각각 캐스케이드의 어느 단계를 건드리는가?
- 중첩(nesting)에서 `& .x` 가 명시도를 조용히 올리는 이유는 무엇인가?
- `:has()` 가 이 셋과 공유하는 것과 안 하는 것은 각각 무엇인가?
