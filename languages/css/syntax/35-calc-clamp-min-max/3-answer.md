# css/syntax/35 — `calc()`·`clamp()`·`min()`/`max()` — 정답

> 복습 시 이 파일은 **최후에만** 연다. 정답을 봤으면 닫고 자기 말로 한 번 재산출한다.
> 이 파일의 **모든 값은 Google Chrome 151.0.7922.173 headless 에서 실제로 렌더해 두 창으로 읽은 것**이다 —
> `document.styleSheets[0].cssRules[i].style`(**담긴 것**)과 `getComputedStyle`(**계산된 것**).\
> **손으로 계산해 유도한 수치는 없다.** 규칙은 [CSS Values and Units 4](https://drafts.csswg.org/css-values-4/) 로 접지했다.

## 정답

### 1. 공백 하나가 선언을 지운다

**실행 결과** (부모 폭 400px)

```text
  적은 것              cssRules 에 담긴 값       computed width
  -------------------  ----------------------    --------------
  calc(100% - 10px)    calc(100% - 10px)         390px
  calc(100% -10px)     (비었다 — 버려졌다)         400px
  calc(100%-10px)      (비었다 — 버려졌다)         400px
  calc(100%/2)         calc(50%)                 200px
  calc(2*100px)        calc(200px)               200px
```

**왜 그런가**

- **담기는 것은 `.a`·`.d`·`.e`** 셋이다. `.b`·`.c` 는 **선언이 통째로 사라진다.**
- 버려진 것들의 `width` 는 **`auto` 로 떨어져 400px**(부모를 채운 값)이 됐다. 선언을 안 쓴 것과 똑같은 결과다.
- **토큰 설명** — CSS 파서는 `-10px` 을 **부호까지 포함해 토큰 하나**(음수 길이)로 자른다.\
  그러면 `[100%] [-10px]` 처럼 **값 둘이 연산자 없이 붙은 모양**이 되어 무효가 된다.\
  공백을 넣으면 `[100%] [-] [10px]` 로 잘려 가운데가 연산자 토큰이 된다.
- **`*`·`/` 는 숫자의 일부가 될 수 없는 문자**라 공백 없이도 연산자로만 읽힌다. 그래서 `.d`·`.e` 가 살았다.
- 외울 것은 **「`calc()` 안에서는 연산자 양옆에 항상 공백」** — `*`/`/` 에도 써 두면 규칙이 하나가 된다.

### 2. 곱셈·나눗셈의 타입

**실행 결과**

```text
  적은 것              담긴 값            computed
  -------------------  -----------------  --------------
  calc(100% * 0.5)     calc(50%)          width 200px
  calc(10px * 20px)    (비었다)            width 400px (auto)
  calc(400px / 10px)   (비었다)            width 400px (auto)
  opacity: calc(1 / 3) calc(0.333333)     opacity 0.333333
```

**왜 그런가**

- **살아남는 것은 `.a` 와 `.d`** 다.
- 곱셈·나눗셈에서는 **한쪽이 숫자**여야 결과가 길이로 남는다.
- `.c` 의 결과는 수학적으로 **숫자 40** 이다. 값이 틀린 게 아니라 **`width` 가 `<length>` 를 요구해서** 안 맞는 것이다.\
  근거 — 같은 나눗셈을 `<number>` 를 받는 `opacity` 에 넣으니 **멀쩡히 담기고 계산됐다**(`.d`).
- `10px * 20px` 은 면적(길이²)이다. CSS 에는 그 값을 받는 속성이 없다.

### 3. `calc()` 안의 0

**실행 결과**

```text
  적은 것              담긴 값             computed width
  -------------------  ------------------  --------------
  width: 0             (그대로)             0px
  calc(100% - 0)       (비었다)             400px
  calc(100% - 0px)     calc(100% + 0px)    400px
  calc(100px * 0)      calc(0px)           0px
```

**왜 그런가**

- **버려지는 것은 `.b`** 하나다.
- **`calc()` 밖의 `0` 은 「길이 0」으로 특별 대우**를 받는다(`<length>` 문법이 단위 없는 0 을 허용한다).
- **`calc()` 안에서는 그냥 숫자 0** 이다. 그래서 `100% - 0` 은 「**길이 빼기 숫자**」가 되어 타입 검사에 걸린다(A2).
- `.d` 가 되는 이유 — 곱셈은 **원래 한쪽이 숫자여야** 하므로 `0` 이 제자리에 있다.
- 곁가지 — `calc(100% - 0px)` 이 **`calc(100% + 0px)`** 으로 담혔다. 엔진이 뺄셈을 「음수 더하기」로 정규화한다.

### 4. ★ `clamp()` 의 상하한이 뒤집히면

**실행 결과** (부모 폭 400px, 50% = 200px)

```text
  적은 것                      담긴 값                    computed width
  ---------------------------  -------------------------  --------------
  clamp(100px, 50%, 300px)     clamp(100px, 50%, 300px)   200px
  clamp(300px, 50%, 100px)     clamp(300px, 50%, 100px)   ★ 300px
  clamp(300px, 10px,  100px)   ★ calc(300px)               300px
  clamp(300px, 999px, 100px)   ★ calc(300px)               300px
```

**왜 그런가**

- **네 값은 200 / 300 / 300 / 300** 이다. 뒤집힌 세 개 모두 **하한 `a` 가 이겼다.**
- `clamp(a, b, c)` 는 **`max(a, min(b, c))`** 다. 순서가 이렇다.

```text
      ① min(b, c)      상한 c 가 먼저 값을 깎는다
      ② max(a, ①)      그 다음 하한 a 가 끌어올린다   <- 나중이라 이긴다
```

- 그래서 **`b` 가 무엇이든 ①의 결과가 `c`(=100) 이하로 눌린 뒤 ②에서 `a`(=300)로 끌려 올라간다.** 가운데 인자가 무력해진다.
- 근거 대조 — `clamp(100px, 50%, 300px)` 과 `max(100px, min(50%, 300px))` 가 **둘 다 200px** 이었다. 동치가 실측으로 확인됐다.
- ★ **`%`·뷰포트 단위가 없으면 Chrome 151 이 파싱 시점에 아예 접어 버린다** — `.c`·`.d` 가 `cssRules` 에 **`calc(300px)`** 으로 담혔다.\
  적은 인자 셋 중 둘이 문자열에서 사라진다. 디버깅할 때 「내가 적은 대로 안 보인다」가 여기서 나온다. **Chrome 151 의 구현 세부다.**
- **무효가 되지 않는다**는 점이 핵심이다. 뒤집힌 것을 CSS 가 알려 주지 않으므로, 변수로 상하한을 받는 설계라면 **CSS 밖에서 막아야 한다.**

### 5. `min()` 이 만드는 것

**실행 결과** (부모 폭 400px)

```text
  min(100%, 300px)  ->  300px     <- 400 이 300 에 깎였다 = 상한
  max(100%, 300px)  ->  400px     <- 400 이 그대로 = 하한 300 은 안 걸렸다
  min(150px, 50%)   ->  150px
  max(150px, 50%)   ->  200px
  min(500px, 50%, 120px) -> 120px  <- 인자 셋도 받는다
```

**왜 그런가**

- **`min(100%, 300px)` 은 상한이다.** 「300 보다 커지지 않는다」를 만든다.
- **`max-width: 300px` 과 같은 일을 하는 것은 `min()`** 이다.
- 헷갈리는 이유 한 문장 — **「함수 이름은 고르는 방법이고, 효과는 그 반대편의 한계다.」**\
  `min` 은 작은 쪽을 고르므로 결과가 커질 수 없고, 그것이 곧 **최댓값 제한**이다.
- 속성 이름(`min-width`/`max-width`)과 **짝이 반대**라 실수가 잦다.

### 6. 적은 것과 담긴 것이 다르다

**실행 결과** (글꼴 20px, 부모 폭 400px)

```text
  적은 것                              cssRules 에 담긴 값              computed width
  -----------------------------------  -------------------------------  --------------
  calc(calc(100%/2) + calc(10px*2))    calc(50% + 20px)                 220px
  calc(10em + 5% + 20px)               calc(5% + 10em + 20px)           240px
  calc((100% - 40px) / 3)              calc(33.3333% - 13.3333px)       119.984px
```

**왜 그런가**

- **`.a` 는 중첩이 평탄해져 `calc(50% + 20px)`** 로 담겼다. `calc` 안의 `calc` 는 괄호와 같아서 흔적이 남지 않는다.
- **`.b` 는 순서가 바뀌어 `calc(5% + 10em + 20px)`** 로 담겼다. `em` 은 글꼴이 정해져야 풀리므로 **접히지 않고 남는다.**\
  계산값 **240px** = 5%(=20) + 10em(=200) + 20.
- ★ **`.c` 가 정확히 120px 이 아닌 이유** — 담긴 값이 이미 **`33.3333% - 13.3333px`** 로 **소수 넷째 자리에서 잘린** 상태다.\
  그 잘린 값을 400px 에 적용하니 **119.984px** 이 나왔다.
- 이것은 **Chrome 151 의 직렬화 정밀도**다. 명세가 정한 수치가 아니다 — 브라우저가 바뀌면 다시 찍을 칸이다.
- 교훈 — **「적은 것」과 「담긴 것」은 다른 창이다.** `getComputedStyle` 만 보면 이 손실을 못 본다.

### 7. 음수와 0으로 나누기

**실행 결과**

```text
  적은 것             담긴 값                 computed width
  ------------------  ----------------------  -----------------
  calc(10px - 100px)  calc(-90px)             0px
  calc(100px / 0)     calc(infinity * 1px)    3.35544e+07px
```

**왜 그런가**

- **둘 다 버려지지 않는다.** `cssRules` 에 멀쩡히 담겼다.
- **`.a` 를 0 으로 만든 것은 `calc()` 가 아니라 `width` 다.** `calc()` 는 `-90px` 을 정상적으로 만들었고, `width` 가 음수를 못 받아 **사용값에서 0 으로 깎았다.**\
  그래서 `margin` 처럼 음수를 받는 속성에서는 `-90px` 이 그대로 산다.
- ★ **`.b` 는 에러가 아니다.** 0 으로 나눈 결과가 **`infinity`** 라는 값이 되고, 계산값은 **3.35544e+07px** 로 나왔다.
- `infinity` 가 되는 것 자체는 명세가 정의했지만, **3.35544e+07 이라는 상한은 Chrome 151 의 구현**이다.
- **에러가 없는 언어**라서 「말이 안 되는 값」이 조용히 화면에 나간다 — 변수에서 0 이 흘러드는 경로를 CSS 안에서 막을 방법이 없다.

### 8. 변수와 섞기

**실행 결과** (부모 폭 400px)

```text
  적은 것                                        computed width
  ---------------------------------------------  --------------
  --pad: 16px;  calc(100% - var(--pad) * 2)      368px
  --expr: 100% - 20px;  calc(var(--expr))        380px
  --bad:  100% -20px;   calc(var(--bad))         400px  (auto)
```

**왜 그런가**

- **368 / 380 / 400** 이다.
- **`var()` 는 「값」이 아니라 「토큰 뭉치」를 펼친다.** 그래서 `--expr` 에 **연산자까지 통째로** 담아 둘 수 있었다.\
  펼쳐진 뒤 `calc(100% - 20px)` 이 되어 정상 계산됐다.
- 반대로 **변수 안의 문법 오류도 같이 펼쳐진다** — `--bad` 는 A1 의 공백 규칙에 걸려 무효가 됐다.
- ★ **그런데 증상이 A1 과 다르다.**

```text
  A1 의 실패 (직접 적은 문법 오류)
     cssRules 의 속성 목록에  width 가 아예 없다       <- 선언이 버려졌다

  A8 의 실패 (변수 안의 문법 오류)
     cssRules 의 속성 목록에  width: calc(var(--bad)) 가 남아 있다
     계산 시점에만 무효가 되어 unset 처럼 처리된다      <- 무효 대체(IACVT)
```

- 화면에서는 둘 다 `width: auto` 로 **똑같이 보인다.** `cssRules` 창으로 봐야 갈린다.
- 이 차이의 정본은 [36번](../36-custom-properties/2-summary.md)이다.

### 9. 어디서 쓸 수 있나

**실행 결과**

```text
  @media (min-width: calc(100px + 100px))
     conditionText = "(min-width: calc(200px))"
     안쪽 규칙 1개 담김 · 실제 적용됨 (outline-style = solid)

  @media (min-width: var(--bp, 100px))
     conditionText = "(min-width: var(--bp, 100px))"
     안쪽 규칙 1개 담김 · 적용 안 됨 (outline-style = none)
```

**왜 그런가**

- **`calc()` 는 동작한다.** 조건이 참이 되어 규칙이 적용됐다.
- **`var()` 는 동작하지 않는다.** 규칙은 담기고 조건 문자열도 보존되는데, **조건이 참이 되지 않는다.**
- 이유 — **커스텀 속성**은 「**요소에 붙어 상속되는 것**」이다. 미디어 쿼리는 **문서 트리 바깥**에서 평가되므로 참조할 요소가 없다.
- 즉 「담겼다」와 「동작한다」가 갈린다 — **[07번](../07-syntax-and-error-recovery/2-summary.md)의 「담겼는데 조건이 거짓」 유형**이다. 무효도 아니고 버려진 것도 아니다.

### 10. 다른 주제로 잇기

- **계산 결과가 어느 단계에서 확정되는가** — [04번](../04-value-processing-stages/2-summary.md)(값 처리 단계)이 정본이다.
- **`display: none` 에서 `calc(100% - 10px)` 이 그대로 나오는 이유** — 상자가 없어 **③ 사용값이 존재하지 않으므로** `getComputedStyle` 이 **② 계산값**을 돌려준다.\
  계산값 단계에서는 `%` 를 풀 수 없으므로 식이 남아 있다. 이 규칙의 정본은 04번이고 실측도 거기 있다(`width: 50%` 가 렌더 시 `200px`, `display:none` 시 `50%`).
- **무효한 `var()` 가 `unset` 처럼 되는 규칙** — [36번](../36-custom-properties/2-summary.md)(사용자 정의 속성)이 정본이다.
- **`calc()` 결과를 애니메이션하려면** — 커스텀 속성을 `@property` 로 **등록**해야 한다. [목록의 **37번 주제**](../37-at-property/)가 정본이다.

## 용어 풀이

- **`calc()`** — 값 안에서 사칙연산을 쓰게 해 주는 함수. 서로 다른 단위를 더할 수 있는 유일한 수단이다.
- **`min()` / `max()`** — 인자 중 최소/최대를 고르는 함수. 예: `min(100%, 300px)` 은 **상한 300** 을 만든다(실측 300px).
- **`clamp(a, b, c)`** — `max(a, min(b, c))` 와 같다. 예: 실측에서 두 형태가 모두 200px 로 일치했다.
- **토큰(token)** — 파서가 만드는 최소 단위. 예: `-10px` 은 부호까지 한 토큰이라 앞의 `-` 가 연산자가 되지 못한다.
- **타입 대수** — `calc()` 안에서 길이·숫자·각도가 결합되는 규칙. 예: 길이÷길이는 숫자가 되어 `<length>` 자리에 못 들어간다.
- **직렬화(serialization)** — 엔진이 값을 문자열로 다시 적는 방식. 예: `calc(2*100px)` 이 `calc(200px)` 로 담긴 것.
- **파싱 시점 접기** — 미리 계산할 수 있는 식을 담을 때 줄이는 것. 예: `clamp(300px,10px,100px)` 이 `calc(300px)` 로 담겼다.
- **무효 대체(IACVT)** — 파싱은 됐는데 계산 시점에 무효가 되어 `unset` 처럼 처리되는 것. 정본은 [36번](../36-custom-properties/2-summary.md).
- **유동 타이포(fluid typography)** — 화면 폭에 따라 글꼴이 연속적으로 변하는 설계. 예: 실측에서 `clamp(16px, 5vw, 32px)` 이 뷰포트 780px 에서 32px 로 깎였다.

| `*`/`/` 는 공백 불필요 | `calc(100%/2)`·`calc(2*100px)` 의 담긴 값 | `calc(50%)` · `calc(200px)` |
| 타입 검사 | 길이×길이 · 길이÷길이 · 길이+숫자 | 셋 다 선언 사라짐 |
| 나눗셈이 `<number>` 자리에서 사는 것 | `opacity: calc(1 / 3)` | `calc(0.333333)` 으로 담김 |
| `calc()` 안의 0 | `calc(100% - 0)` 대 `calc(100% - 0px)` 대 `width: 0` | 첫째만 사라짐 |
| ★ `clamp(a,b,c)` 에서 `a > c` | 세 형태(`50%`/`10px`/`999px`)를 가운데에 넣어 대조 | **전부 300px** (하한이 이김) |
| `clamp` = `max(a, min(b,c))` | 두 형태를 나란히 선언해 계산값 대조 | 둘 다 200px |
| 파싱 시점 접기 | `clamp(300px,10px,100px)` 의 `cssRules` 문자열 | **`calc(300px)`** — 인자 둘이 사라짐 |

**구현 의존 항목** — ① `calc((100%-40px)/3)` 의 **소수 4자리 절단**과 계산값 119.984px ② `calc(100px/0)` 의 상한 **3.35544e+07px** ③ `clamp` 가 **`calc(300px)`** 로 접혀 담기는 범위. 셋 다 **Chrome 151 에서 관찰한 것**이고, 브라우저가 바뀌면 다시 찍어야 한다.\
**재지 않은 것** — 삼각·지수 함수(`sin()`·`round()` 등) · `clamp()` 의 직선식 설계(수식을 손으로 유도해야 해서 수치를 싣지 않았다).\
**엔진은 Chrome 하나다.** Firefox 155.0.1 은 이 환경에서 headless 산출이 조용히 실패하고 WebKit 은 이 머신에 없다 — **「두 엔진에서 확인했다」고 적지 않았다.**
