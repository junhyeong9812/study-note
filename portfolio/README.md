# portfolio

대외용 정리 - 경력기술서(정본 PDF, 29쪽)의 사례 8건을 위키에서 이어 읽을 수 있게 계층으로 다시 쓴 것.

## 구조 (2026-09-14 기준)

PDF는 제출본이라 사례마다 문제 상황 / 해결 과정 / 결과를 한 흐름으로 서술한다. 위키는 같은 사례를 **판단 단위로 쪼개고 근거를 붙인 상세본**이다. PDF의 문제 상황 제목과 해결 과정 소제목이 이 위키의 사례 페이지와 단계 페이지로 링크되어 있다.

```text
portfolio/<프로젝트>/NN_사례명/
├── README.md            사례 페이지 - 폴더 URL에서 바로 보인다
│   ├── 한 줄 요약
│   ├── 문제 상황        2~3줄 요약 + 항목 링크
│   ├── 해결 과정        판단 N + 근거 한 줄 + 번호 링크(단계), 선택하지 않은 방법
│   ├── 결과
│   └── 회고
├── 문제상황/NN_이름/post.md   문제 항목 상세 (본문, 도식)
└── 해결과정/NN_이름/post.md   단계 상세 (도식, 원리 -> 문제 -> 무엇을 얼마로 바꿨나 -> 왜, 근거)
```

- 단계 파일마다 사례로 돌아가기, 이전/다음 링크가 있어 순서대로 읽을 수 있다. 원리를 설명하는 단계는 관련 CS 문서로 링크한다(예: [저장 매체와 워크로드](../cs/systems/storage-media-workload/2-summary.md)).
- 도식은 정본 도식정의.py(DSL)를 ASCII로 렌더링한 코드블록이고 번호와 캡션은 정본 PDF와 같다. 도식 제목은 코드블록 밖의 `###` 소제목이다.
- 근거 절의 코드는 실제 코드가 아니라 구조를 보여 주는 예시다. 회사 내부 식별자(클래스, 파일 경로, 상수, 엔드포인트, 인덱스명)는 쓰지 않는다.

## 편집 규칙

- **수치와 사실은 정본 PDF와 같아야 한다.** 정본에 없는 판단 서술, 근거, 덧붙임은 위키에만 있다 - 위키가 정본보다 깊고, 정본이 위키보다 넓지는 않다.
- 정본이 바뀌면 해당 사례의 문장을 손으로 맞춘다. 정본 -> 위키 자동 변환기(위키_변환.py)는 초기 이관용이라 지금 구조를 덮어쓴다 - 돌리지 않는다.
- 문장은 한 줄에 하나, 줄 끝 `\`로 줄바꿈한다(사이트가 raw HTML을 렌더링하지 않는다).
- 안 한 선택은 "선택하지 않은 방법"으로 적는다. "기각" 같은 표현은 쓰지 않는다.
- 배포 사이트 규약: 하위 폴더가 있는 폴더는 `README.md`가 본문이고, 리프 폴더는 `post.md`가 본문이다. 사례 폴더에 문서를 더 만들 때 이 규약을 지킨다.
