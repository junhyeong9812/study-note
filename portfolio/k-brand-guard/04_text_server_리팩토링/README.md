# text-server 리팩토링 (LLM 프로토타입의 유지보수성 개선)

> 소속 경력: 한국지식재산보호원 K-브랜드 지킴이 - 해외 상표 무단선점 경보 서비스 개발 (검색 서버 text-server)
> 회사 내부 식별자(클래스명, 파일 경로, 커밋 해시)는 노출하지 않고 맥락만 서술합니다.

## 한 줄 요약

검증은 통과했지만 읽기 어려운 LLM 프로토타입을, 특성화 테스트로 동작을 고정한 뒤 죽은 코드 제거, 재배치, 모듈화, 정책 추상화 순으로 구조만 바꿔 테스트 577개를 668개로 늘리고 숨은 결함 19건을 찾았습니다.

## 문제 상황

제가 도메인 요구사항을 정리해 Claude Code로 빠르게 만든 프로토타입으로, **동작 검증과 부하테스트까지 통과한 코드베이스**였습니다.\
기능은 입증됐지만 **문제는 유지보수**였습니다.\
인수인계 시 이해에 오래 걸렸고, **구현 당시 맥락을 아는 제가 다시 봐도 어려운 코드**였습니다.

가드레일 테스트는 존재했지만, **메서드와 클래스 구조가 깊고 흐름과 알고리즘이 혼재**해 있었으며, 여러 번의 요구사항 변경을 거치며 네이밍도 일관성을 잃었습니다.\
코드가 여기저기 흩어져 있어 **응집도가 떨어졌고, 캡슐화와 추상화가 부족**해 읽는 사람이 길을 잃기 쉬운 구조였습니다.

## 해결 과정

세 번의 판단으로 진행했습니다. 현재 동작을 스펙으로 고정하고, 구조만 바꾸고, 규칙을 테스트로 고정했습니다.

**판단 1. 현재 동작이 곧 스펙이다**\
버그로 의심되는 출력도 일단 그대로 고정하고 수정은 별도 작업으로 분리했습니다.

1. **[과제 정의 동작 보존](해결과정/01_과제_정의_동작_보존/post.md)**\
   과제를 죽은 코드 제거, 재배치, 모듈화, 정책 추상화로 정의하고 동작 보존을 전제로 매 단계 전체 테스트 0실패를 확인하는 워크플로우 확정
2. **[가드레일 특성화 테스트](해결과정/02_가드레일_특성화_테스트/post.md)**\
   현재 입출력을 실측한 특성화 테스트로 기존 동작을 고정하고, 바이트 보존이 필요한 파이프라인은 구코드로 골든 픽스처를 먼저 만들어 비교

**판단 2. 구조만 바꾼다**\
매 단계 전체 테스트 0실패를 확인하며 죽은 코드, 위치, 관심사, 정책 순으로 손댔습니다.

3. **[죽은 코드 제거](해결과정/03_죽은_코드_제거/post.md)**\
   참조 없는 구세대 아키텍처 잔재 클래스 8개(약 750줄)와 호출부 없는 메서드를 먼저 삭제
4. **[재배치 응집도](해결과정/04_재배치_응집도/post.md)**\
   섞여 있던 폴더 구조, 클래스 위치, 이름을 사내 표준으로 통일하고 복제된 국가별 라우팅을 제네릭 디스패치 하나로
5. **[모듈화 관심사 분리](해결과정/05_모듈화_관심사_분리/post.md)**\
   검증, 정규화, 중복검사, 저장을 이름 있는 메서드로 분리해 진입점이 도메인 문장처럼 읽히게 하고, 판단을 컨벤션 규칙 13개로 축적, 의미가 다른 정규화 세 벌은 통합하지 않음
6. **[정책 추상화](해결과정/06_정책_추상화/post.md)**\
   상태 전이 9개의 트랜잭션 골격을 함수형 인자 메서드 하나로, 흩어진 분기를 결과 enum과 분류 enum으로, 국가 enum은 정책 판정 지점까지만 적용하고 저장 계층은 문자열 유지

**판단 3. 규칙을 테스트로 고정한다**\
암묵적 필드 규칙을 타입과 테스트로 드러내 결함을 찾았습니다.

7. **[모듈 단위 테스트](해결과정/07_모듈_단위_테스트/post.md)**\
   실제 데이터 기반 모듈 테스트를 더해 577개에서 668개로, 암묵적 필드 규칙을 타입과 테스트로 고정하며 규칙 이탈 21건 중 결함 19건 발견

선택하지 않은 방법: 버그 의심 출력의 즉시 수정(동작 변경 작업으로 분리), 정규화 로직 세 벌 통합(공백 처리 의미가 달라 API 응답이 바뀜), 국가 enum을 저장 계층까지 확장(마이그레이션 없이는 되돌릴 수 없음).

## 결과

**분리해 둔 결함 19건은 후속 동작 변경 작업에서 모두 수정**했습니다.\
리팩토링 이후 코드 리뷰와 인수인계, 신입 온보딩에서 이전보다 빨리 적응할 수 있게 됐고, **기존 1~2시간 걸리던 요구사항 변경 대응을 약 30분 안에 처리**할 수 있게 되었습니다.\
**이 과정 전체에서 동작 보존을 지켰습니다**.

### 리팩토링 워크플로우 - 가드레일을 먼저, 매 단계 전체 테스트 0실패 확인

```text
     +----------------------------------------------+    +----------------------------------------------+    +----------------------------------------------+
     | 0. 가드레일                                  |    | 1. 죽은 코드 제거                            |    | 2. 재배치 (응집도)                           |
     | 현재 입출력을 실 데이터로 실측               |    | 참조 없는 클래스 8개(약 750줄)               |    | 폴더, 클래스 위치, 이름 사내 표준 통일       |
     | characterization 테스트로 고정               |----> 호출부 없는 레거시 메서드                    |----> 국가별 라우팅 복제 -> 제네릭 디스패치        |
     | 버그 의심 출력도 그대로 고정                 |    |                                              |    |                                              |
     | 바이트 보존 경로는 골든 픽스처               |    |                                              |    |                                              |
     +----------------------------------------------+    +----------------------------------------------+    +----------------------------------------------+

     +----------------------------------------------+    +----------------------------------------------+    +----------------------------------------------+
     | 3. 모듈화 (캡슐화)                           |    | 4. 정책 추상화 (타입화)                      |    | 5. 모듈 단위 테스트 추가                     |
     | 검증/정규화/중복검사/저장을 관심사 단위 분리 |----> 트랜잭션 골격 통합, 결과/복구 enum           |----> 실 데이터 기반, 577 -> 668개                 |
     | 공통 유틸 승격, 컨벤션 규칙 13개 축적        |    | 국가 enum (정책 판정 지점까지만)             |    | 암묵적 필드 규칙 위반 21건 발견              |
     |                                              |    |                                              |    |                                              |
     +----------------------------------------------+    +----------------------------------------------+    +----------------------------------------------+

     * 각 단계 끝 = 전체 테스트 실행 -> 0실패 확인 -> 다음 단계. 실패하면 되돌림 (현재 동작이 곧 스펙, 수정은 별도 작업)
```

도식 20. 리팩토링 워크플로우 - 가드레일(0) -> 죽은 코드 제거(1) -> 재배치(2) -> 모듈화(3) -> 정책 추상화(4) -> 모듈 단위 테스트 추가(5), 매 단계 전체 테스트 0실패

### 30분의 근거

"1~2시간에서 약 30분"은 체감이 아니라 실제 요구사항 두 건의 처리 시간입니다.\
리팩토링 전후로 비슷한 수준이라고 판단한 검색 구조 변경 요구를 하나씩 받았고, 접수부터 반영까지 걸린 시간을 비교했습니다.\
요구의 세부는 대외비라 적지 않습니다.
