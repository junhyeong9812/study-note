# 5. 검증, 정규화, 중복검사, 저장을 이름 있는 메서드로 분리해 진입점이 도메인 문장처럼 읽히게 하고, 판단을 컨벤션 규칙 13개로 축적, 의미가 다른 정규화 세 벌은 통합하지 않음

> text-server 리팩토링 - 해결 과정 5/7. [사례로 돌아가기](../../) | [이전 4단계](../04_재배치_응집도/post.md) | [다음 6단계](../06_정책_추상화/post.md)

검증, 정규화, 중복검사, 저장처럼 한 메서드에 섞여 있던 절차를 **의도가 드러나는 이름의 메서드로 분리해 진입점이 도메인 문장처럼 읽히게** 했습니다.\
분리 기준은 "**if문 단위가 아니라 관심사 단위**"로 확정하고, 세션에서 확정된 판단들을 **리팩토링 컨벤션 규칙 13개로 축적**해 다음 세션이 같은 기준으로 이어가게 했습니다.

여러 클래스가 공유하는 순수 유틸(음절 처리, 인코딩 스켈레톤)은 공용 패키지로 승격하되 통합 여부를 개별 검토했습니다.\
예를 들어 정규화 로직 세 벌은 모양만 같고 공백 처리의 의미가 서로 달라, **통합하면 API 응답이 바뀌므로 의도적으로 그대로 두었습니다**.
