# 3. 리프레시 토큰 없이 sliding 갱신, 절대 만료 8시간, 화이트리스트 단일 활성 세션으로 재시작 시 안전한 방향으로 실패하는 세션 모델 확정

> 약 50억 행 저장소 계층 설계와 레거시 통합 - 해결 과정 3/5. [사례로 돌아가기](../../post.md) | [이전 2단계](../02_레거시_통합_인증_재설계/post.md) | [다음 4단계](../04_접근_패턴별_계층_분리/post.md)

### 로그인 세션 갱신 워크플로우 - 리프레시 토큰 없는 sliding, 절대 만료 8시간, 단일 활성 세션

```text
     +----------------------------------+   +-----------------------------------+  +----------------------------------+  +------------------------------------+
     | 유효한 액세스 토큰 제시          |   | 절대 만료 확인                    |  | DB에서 사용자 재조회             |  | 새 토큰 발급                       |
     | (만료 1시간)                     |---> 최초 로그인 시각 클레임 기준     -|--> 권한, 계정 상태 재파생          -|--> 화이트리스트 식별자 교체           |
     |                                  |   | 8시간 경과 -> 갱신 거부, 재로그인 |  | 정지 전이 시에만 즉시 폐기 가드  |  | -> 이전 토큰 자동 폐기 (단일 세션) |
     |                                  |   |                                   |  |                                  |  |                                    |
     +----------------------------------+   +-----------------------------------+  +----------------------------------+  +------------------------------------+

     * 화이트리스트 선택 근거: 재시작으로 목록이 비면 전부 무효 = 안전한 방향의 실패 (블랙리스트는 폐기 토큰이 되살아남)
     * 절대 만료로 연장 거부 시: 강제 로그아웃 대신 안내 후 현재 토큰의 자연 만료로 전환 (서버 상태와 일치하도록 정책 정정)
```

도식 6. 세션 갱신 - 절대 만료 확인, DB 재파생, 화이트리스트 교체로 단일 활성 세션

레거시와 로그인을 공유하는 회원, 관리자 경로의 세션 모델은 다음 원칙으로 설계했습니다(비회원 이메일 OTP 인증은 경력 1 - 03).

- **리프레시 토큰을 발급하지 않습니다.** 유효한 액세스 토큰을 제시하면 새 액세스 토큰을 내주는 **sliding 방식**이고, 액세스 만료는 1시간입니다. 무한 연장을 막기 위해 **최초 로그인 시각을 별도 클레임으로 고정**해 실어, 그 시점부터 **8시간이 지나면 갱신을 거부**하고 재로그인을 요구합니다.
- 단일 활성 세션은 블랙리스트(쓰인 토큰을 등록해 재사용을 거절)가 아니라 **화이트리스트(사용자별 활성 토큰 식별자 1개만 유지)**로 택했습니다. 새로 발급하면 이전 토큰이 자동으로 폐기되고, 인스턴스가 재시작해 목록이 비면 전부 무효가 되어 **안전한 방향으로 실패**합니다. 블랙리스트는 반대로 재시작하면 비어서 폐기된 토큰이 되살아납니다. 이 정리 과정에서 토큰에 식별자가 아예 발급되지 않아 정책이 사실상 무력했던 결함을 발견해 함께 고쳤습니다.
- **갱신 시 사용자를 DB에서 다시 조회해 권한과 계정 상태를 재파생**하도록 했습니다. 권한 변경과 비활성 전환이 갱신 시점에 반영됩니다. 계정 상태나 자격증명이 바뀌는 흐름에는 즉시 폐기를 추가했는데, 무조건 폐기하면 남의 계정을 강제 로그아웃시키는 수단이 되므로 **실제로 정지 상태로 전이된 경우만 폐기**하도록 가드를 걸었습니다.
- 헤더에 남은 시간과 연장을 붙일 때는 코드 리뷰를 하는 과정에서 **정책이 서버 상태와 어긋나는 문제**를 발견해 정책을 정정했습니다. 절대 만료로 연장이 거부되면 즉시 로그아웃시키려 했지만, 서버는 현재 토큰이 만료될 때까지는 인증을 허용합니다. 그래서 강제 로그아웃 대신 안내를 띄우고 로그인을 유지한 뒤 **실제 만료 시점에 자연 전환**하게 바꿨습니다.
