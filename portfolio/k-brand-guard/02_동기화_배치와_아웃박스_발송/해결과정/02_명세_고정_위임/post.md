# 2. 구독 두 테이블 정규화와 동기화 직후 발송 구조를 명세로 먼저 고정해 팀원에게 위임하고, 아웃박스와 발송 배치 분리는 직접 발전시켜 Claude와 Codex 리뷰로 점검

### 명세 고정 -> 팀원 위임 -> 직접 발전 -> 리뷰 점검

```text
   +----------------------------------+   +---------------------------------+    +---------------------------------+    +---------------------------------+
   | 명세로 먼저 고정                 |   | 팀원 구현 (위임)                |    | 직접 발전                       |    | 리뷰 점검                       |
   | 구독자 1행 + 출원번호 N행 정규화 |   | 명세 기준으로                   |    | 아웃박스(대기 이력) +           |    | Claude, Codex 교차 리뷰로       |
   | 발송은 동기화 완료 직후          |---> 구독 도메인 기본 구조           |----> 별도 발송 배치로 분리           |----> 놓친 부분 점검                  |
   +----------------------------------+   +---------------------------------+    +---------------------------------+    +---------------------------------+
```

도식 11. 명세 고정 -> 팀원 위임 -> 직접 발전(아웃박스 + 발송 배치 분리) -> Claude, Codex 리뷰 점검

구독 정보를 **사용자당 1행의 구독자와 구독자당 N행의 출원번호 두 테이블로 정규화**하고, **발송을 별도 스케줄 없이 동기화 완료 직후에 잇는 구조를 명세로 작성**했습니다.\
동기화가 끝난 데이터라야 최신 사례로 매칭할 수 있기 때문입니다.\
이 명세를 기준으로 **팀원이 구독 도메인의 기본 구조를 구현**했고, 일정이 촉박해 이후 작업은 위임하지 않고 제가 직접 맡아 **발송을 대기 이력(아웃박스)과 별도 발송 배치로 분리하는 구조로 발전**시켰습니다.\
직접 구현하면서 놓친 부분이 있는지는 **Claude와 Codex 리뷰로 점검**했습니다.
