# 6. insert-only 동기화가 최신본을 반영하지 못함을 실측(신규 305건 삽입 0, 활성 전환 235건 미전파)하고 보존형 전량 미러로 전환, 통지 기준은 활성 전환 시점

> 레거시 동기화와 경보 메일 발송 파이프라인 - 해결 과정 6/6. [사례로 돌아가기](../../post.md) | [이전 5단계](../05_고도화_전이_버그_채널_교체/post.md)

### 전량 미러 - insert-only의 미전파를 실측으로 확인하고 교체, 통지는 활성 전환 시점만

```text
     +-------------------------------------------------------------------+          +-------------------------------------------------------------------+
     | 전: insert-only (실측으로 확인한 한계)                            |          | 후: 전량 미러 (보존형)                                            |
     | 신규 305건 전부 비활성(공개 전) -> 삽입 대상 0건                  |  교체    | 없는 건은 삽입, 있는 건은 레거시 현재 값으로 갱신                 |
     | 비활성 -> 활성 전환 235건 -> 갱신 경로 없어 미전파                |----------> 삭제는 반영하지 않음 - 이력 유지                                  |
     |                                                                   |          |                                                                   |
     |                                                                   |          |                                                                   |
     |                                                                   |          |                                                                   |
     +-------------------------------------------------------------------+          +-------------------------------------------------------------------+

     * 통지 기준 = 활성으로 전환되는 시점:
     * 비활성 -> 활성 = 통지  /  활성 유지 갱신 = 재통지 없음  /  비활성 갔다가 재공개 = 활성 전환으로 다시 잡혀 재통지
```

도식 15. 전량 미러 전환 - insert-only 미전파 실측(305건, 235건)과 활성 전환 시점 통지 기준

배포를 앞두고 원천 데이터를 최신본으로 교체하면서 실측해 보니, 초기의 **insert-only 동기화로는 최신본을 반영할 수 없다**는 사실이 드러났습니다.\
**신규 305건**이 전부 비활성(공개 전) 상태로 들어와 **삽입 대상이 0건**이었고, 기존 건 중 비활성에서 활성으로 바뀐 **235건은 갱신 경로가 없어 전파되지 않았습니다**. 없는 건은 삽입하고 있는 건은 레거시 현재 값으로 갱신하는 **전량 미러(삭제는 반영하지 않는 보존형)**로 바꾸고, **통지 기준은 "활성으로 전환되는 시점"**으로 못 박았습니다.\
비활성 사례는 통지하지 않고, 활성 상태가 유지되는 갱신은 재통지하지 않으며, 비활성으로 내려갔다가 다시 활성으로 돌아오는 재공개는 활성 전환으로 다시 잡혀 재통지합니다.\
**레거시에서 사라진 행은 지우지 않아 이력을 보존**했습니다.
