### 측정 경로 - 애플리케이션 경유 배제, ES 직접 측정

```text
     +---------------------------+                 +--------------------------------------------------+                +--------------------------------+
     | k6                        |                 | 애플리케이션 서버                                |                | Elasticsearch                  |
     |                           |-----------------> 직렬화, 커넥션 풀 효과가 섞임                   -|---------------->                                |
     |                           |                 |                                                  |                |                                |
     +---------------------------+                 +--------------------------------------------------+                +--------------------------------+
                                                   x 경유 측정 배제 - 엔진 성능에 다른 효과가 섞인다


                                                                        +-------------------------------------------------------------------------------+
     +---------------------------+                                      | Elasticsearch 직접 요청                                                       |
     | k6                        |              직접 요청               | 엔진 자체 처리시간(took) / 전체 응답시간 분리 기록                            |
     |                           |--------------------------------------> 비교 인덱스, 시나리오, 램프, 지표 수집 직접 설계                              |
     |                           |                                      |                                                                               |
     +---------------------------+                                      +-------------------------------------------------------------------------------+
```

도식 26. 측정 경로 - 애플리케이션 경유 배제, ES 직접 요청으로 엔진 처리시간과 전체 응답시간 분리

서버 코드를 경유하면 **직렬화와 커넥션 풀 효과가 섞이므로**, 이 실험은 **ES에 직접 요청해 엔진 자체 처리시간과 전체 응답시간을 분리해 기록**했습니다.\
비교 인덱스 구성부터 k6 시나리오와 램프 프로파일 설계, 지표 수집까지 **제가 직접 설계하고 실행**했습니다.

### 근거 - 두 경로의 분리

- 서버 경유: 검색 서버의 검색 API로 요청하는 시나리오.
- ES 직접: ES의 검색 엔드포인트로 직접 요청하고, 응답의 took를 커스텀 메트릭으로 따로 기록해 엔진 처리시간과 전체 응답시간을 분리합니다.
- 상세 조회(MySQL): 국가별 상세 API를 무작위 출원번호로 호출하는 시나리오(경력 1 - 01 결과의 23,899 요청, p95 12.7ms 측정 경로).
- 기준선 실행은 ES 직접을 상한 2,500 req/s(단계 250), 서버 경유를 1,500 req/s(단계 150)로 나눠 돌렸습니다.
