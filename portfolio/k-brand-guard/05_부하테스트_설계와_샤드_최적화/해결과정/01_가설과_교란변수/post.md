# 1. 샤드마다 스레드 하나라 병렬도는 코어 수(12)에 묶이며 어딘가에 수확 체감 구간이 있다는 가설을 세우고, 샤드 수를 바꾸면 세그먼트 분포도 바뀌는 교란변수를 정의

> 검색 서버 부하테스트 설계와 샤드 구조 최적화 - 해결 과정 1/4. [사례로 돌아가기](../../) | [다음 2단계](../02_비교_인덱스_구성/post.md)

### 검색 한 건의 처리 - 샤드마다 스레드 하나, 병렬도는 코어 수(12)에 묶인다

```text
     +--------------------------------+    +--------------------------------+    +--------------------------------+    +--------------------------------+
     | 검색 요청                      |    | 코디네이터                     |    | 샤드 병렬 처리                 |    | 결과 병합                      |
     |                                |----> 샤드 수만큼 분배               |----> shard 1 -> 스레드 1            |----> 응답                           |
     |                                |    |                                |    | shard 2 -> 스레드 2            |    |                                |
     |                                |    |                                |    | ... (샤드당 스레드 1개)        |    |                                |
     +--------------------------------+    +--------------------------------+    +--------------------------------+    +--------------------------------+


     +----------------------------------------------+  +-------------------------------------------------++----------------------------------------------+
     | 한 검색의 병렬도 = 샤드 수                   |  | 포화 처리량의 상한 = 코어                       ||그래서                                        |
     | 샤드 1 = 코어 1개만 일함                     |  | 총 처리량은 데이터량이 아니라 코어 수(12)가 상한||실험 범위 = 1, 2, 4, 8 (12코어 안)            |
     | 샤드 8 = 코어 8개 (fan-out 오버헤드 증가)    |  | 4샤드에서 CPU 포화, 8샤드는 이득 없음           ||규모가 다른 두 나라 결과를 통합 인덱스에 적용 |
     |                                              |  |                                                 ||                                              |
     +----------------------------------------------+  +-------------------------------------------------++----------------------------------------------+
```

도식 21. 검색 한 건의 처리 - 샤드마다 스레드 하나, 포화 처리량의 상한은 데이터량이 아니라 코어 수(12)가 정한다

"샤드를 늘리면 병렬성이 올라 빨라지지만 무한정은 아니고 어딘가에 **수확 체감 구간**이 있다"가 가설이었습니다.\
문제는 이를 일반론이 아니라 **우리 데이터와 우리 서버에서 확인**해야 한다는 점이었습니다.

또 하나의 과제는 **교란변수**였습니다.\
**샤드 수를 바꾸면 세그먼트 분포도 함께 달라지기** 때문에, 그대로 비교하면 성능 차이를 무엇에 귀속해야 할지 알 수 없습니다.
