# 이메일 OTP 인증과 토큰 상태 관리 설계 (로그인 없는 대국민 서비스)

> 소속 경력: 한국지식재산보호원 K-브랜드 지킴이 - 해외 상표 무단선점 경보 서비스 개발
> 회사 내부 식별자(클래스명, 파일 경로, 커밋 해시)는 노출하지 않고 맥락만 서술합니다.

## 한 줄 요약

로그인 없는 대국민 서비스에서 이메일만으로 구독과 결과 열람을 열기 위해, 보안 경계를 세 갈래로 나눠 OTP 검증을 키 단위 원자 구간으로 묶고 열람 토큰은 fragment 전달과 SHA-256 해시 저장으로 설계해 테스트 108건과 보안 테스트 30건을 통과했습니다.

## 문제 상황

대국민 공개 서비스라 경보 구독과 결과 열람에 회원가입을 요구할 수 없었습니다.\
기존 알림 화면은 마이페이지처럼 로그인을 전제로 만들어져 있었고, 요구는 "**로그인 없이 이메일만으로 신청하고 조회한다**"였습니다.\
인증과 인가는 제가 담당한 영역이라 이 전환의 설계와 구현을 맡았습니다.

**요구는 하루 사이 두 번 뒤집혔습니다**. 이메일 인증(OTP)으로 구현한 뒤 "인증 없이 이메일만 입력"으로 내려갔고, 다시 "이메일 인증 방식으로" 돌아왔습니다.\
두 번째 단계에서 지웠던 인증 도메인은 **형상관리 이력에서 리뷰 완료본을 되살려 복원**했고, 그 사이 새로 생긴 발송내역, 해지 엔드포인트까지 **같은 토큰 인증으로 통일해 최종 상태를 하나로** 맞췄습니다.

## 해결 과정

세 번의 판단으로 진행했습니다. 얇은 근거 위에 경계를 세 갈래로 세우고, 버그는 로그로 귀속하고, 토큰은 유출돼도 쓸 수 없게 했습니다.

**판단 1. 얇은 근거 위에 경계를 세 갈래로**\
메일함 소유라는 근거 하나에 기대므로 무차별 대입, 상태 경합, 유출 경로를 따로 막았습니다.

1. **[보안 경계 정의](해결과정/01_보안_경계_정의/post.md)**\
   보안 경계를 코드 무차별 대입, 동시 요청의 상태 경합, 토큰 유출 경로 세 갈래로 정의하고, 제3자 이메일 위협은 제외하며 별도 저장소 없이 해결한다는 제약을 둠
2. **[OTP 발급 검증 원자 구간](해결과정/02_OTP_발급_검증_원자_구간/post.md)**\
   암호학적 난수 6자리, 발송 성공 뒤 코드 활성화, 검증 4단계를 키 단위 원자 구간으로 묶어 병렬 시도와 이중 발급 차단, 용도 계층화 토큰과 이메일별 재발송 슬라이딩 윈도

**판단 2. 버그는 로그로 귀속한다**\
현상이 아니라 서버 로그 실측으로 어느 쪽 문제인지 정한 뒤 고쳤습니다.

3. **[재전송 제한 문제](해결과정/03_재전송_제한_문제/post.md)**\
   "요청이 많습니다" 반복을 로그로 실측해 프론트 중복이 아니라 쿨다운을 알 수 없는 화면 문제로 특정, 제한은 유지하고 카운트다운과 도착 안내로 수정
4. **[실버그 만료 오발화](해결과정/04_실버그_만료_오발화/post.md)**\
   인증 직후 만료 오발화를 서버 로그 0건으로 프론트에 귀속, 남은시간 0인 낡은 프레임이 원인이라 매 렌더 만료 시각 도출로 수정하고 회귀 테스트가 실패 모드를 재현하는지 확인

**판단 3. 유출돼도 쓸 수 없게**\
토큰의 전달 경로와 저장 형태를 함께 바꿨습니다.

5. **[결과 열람 토큰](해결과정/05_결과_열람_토큰/post.md)**\
   열람 토큰을 URL fragment로 옮겨 접근로그와 Referer 유출을 차단하고 저장소에는 SHA-256 해시만, 발송마다 새 토큰, 인메모리에서 DB 영속으로 전환하며 재기동 시뮬레이션까지 검증

선택하지 않은 방법: 사내 순번 채번 서비스(예측 가능), 쿨다운 완화 1초 1건(시간당 3,600통 허용), 열람 토큰 재사용 발급(해시 저장과 양립 불가).

## 결과

**2026-07-27 대국민 서비스로 배포를 완료**했습니다.

검증은 **인증과 구독 영역 108개 테스트**(구독 영역은 실 DB 컨테이너, 인증 저장소는 단위 테스트)를 통과시키고, OTP 발송 수락, 오답 거절, 재발송 제한, 무토큰 거절이 계약대로 응답하는지 **E2E 스모크로 확인**했습니다.\
결과 열람 토큰은 만료, 위조, 권한 격리를 다룬 **보안 테스트 30건**과, **영속화 이후 재기동 시뮬레이션 및 정리 스케줄러 통합 테스트**를 통과했습니다.

한계와 트레이드오프는 분명합니다.\
OTP 코드와 이메일 인증 토큰 상태가 **인메모리 단일 인스턴스 전제**입니다.\
재기동하면 재인증이 필요하고 수평 확장도 불가합니다.\
서비스 자체 부하가 크지 않다는 피드백 위에서 복잡도를 줄이려고 의도적으로 택한 트레이드오프이며, 저장소를 인터페이스로 분리해 다중 인스턴스가 필요해지면 구현체 교체로 전환할 경로를 남겨 뒀습니다.\
그중 **유출 시 피해가 가장 큰 결과 열람 토큰만 먼저 DB로 옮겼습니다**.
