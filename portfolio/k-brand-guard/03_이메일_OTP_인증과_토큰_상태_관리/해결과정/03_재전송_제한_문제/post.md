# 3. "요청이 많습니다" 반복을 로그로 실측해 프론트 중복이 아니라 쿨다운을 알 수 없는 화면 문제로 특정, 제한은 유지하고 카운트다운과 도착 안내로 수정

### 재전송 제한 문제 - 어디서 어긋났나: 사용자는 쿨다운을 알 수 없었다

```text
     요청 흐름 (기능 테스트 실측)

     +---------------------------+   +---------------------------+   +---------------------------+  +---------------------------+   +---------------------------+
     | 인증 메일 요청            |   | 발송 성공                 |   | 사용자 화면               |  | 23~54초 사이 재클릭       |   | 서버 거절                 |
     |                           |   | 서버: 쿨다운 60초 시작    |   | 쿨다운 정보가 전혀 없음   |  | (밀리초 중복 없음         |   | "요청이 많습니다" 반복    |
     |                           |--->                           |---> 버튼은 그대로 눌림        |--> = 프론트 중복 아님)       |--->                           |
     |                           |   |                           |   |                           |  |                           |   |                           |
     +---------------------------+   +---------------------------+   +---------------------------+  +---------------------------+   +---------------------------+
                                                                     <- 문제 지점: 프론트, 백엔드 설계



     +------------------------------------------------------------------------+        +----------------------------------------------------------------+
     | 판단 - 제한은 유지                                                     |        | 수정 - 알 수 있게                                              |
     | 제한은 이메일별 - 대국민 트래픽 총량과 무관                            |        | 재전송 버튼에 남은 초 카운트다운                               |
     | "1초에 1건"으로 풀면 한 주소에 시간당 3,600통 허용                     |--------> 메일 도착 소요 안내                                            |
     | -> 완화가 아니라 알림 문제로 판정                                      |        |                                                                |
     |                                                                        |        |                                                                |
     |                                                                        |        |                                                                |
     +------------------------------------------------------------------------+        +----------------------------------------------------------------+
```

도식 17. 재전송 제한 문제 - 쿨다운을 알 수 없는 화면(문제 지점), 제한 유지 판단과 카운트다운 UI 수정

기능 테스트 중 "요청이 많습니다"가 반복되던 문제가 있었습니다.\
로그를 실측하니 거절된 요청은 전부 **발송 성공 후 23초에서 54초 사이의 재클릭**이었고(쿨다운 60초 이내), 밀리초 간격의 중복 발사는 없었습니다.\
프론트의 중복 요청이 아니라, **사용자가 쿨다운이 걸려 있다는 사실을 알 수 없는 상태**에서 재전송 버튼이 그대로 눌리는 프론트와 백엔드 설계의 문제였습니다.\
제한 자체는 이메일별이라 대국민 트래픽 총량과 무관하고, "1초에 1건"으로 풀면 **한 주소에 시간당 3,600통을 허용**하게 되므로 **제한은 유지**했습니다.\
대신 재전송 버튼에 **남은 초 카운트다운과 도착 소요 안내**를 붙여 설계를 고쳤습니다.
