# 4. 오픈소스 g2p-en의 한글 표기 정확도 26%(검증셋 50단어)를 원인 분석 후 영어 발음 패턴 약 30개를 추린 룰 기반 변환기로 대체해 96%, 확장셋 121단어 94.2%, fuzzy 확대는 노이즈 때문에 배제

### 한/영 교차 유사도 - 자체 룰 기반 G2P 변환기 (발음 필드 빌트인)

```text
     +--------------------------------------------------+          +--------------------------------------------------+      +----------------------------+
     | 전: 오픈소스 g2p-en                              |직접 구현 | 후: 자체 룰 기반 G2P                             |      | 발음 필드에 저장           |
     | 영어권 화자 기준 발음 출력                       |----------> 발음 변환 패턴 조사 -> 유의미한 약 30개 룰      -|------> 한글 상표와 같은 기준 비교 |
```

도식 41. 한/영 교차 유사도 - 자체 룰 기반 G2P 변환기를 발음 필드에 빌트인, 검증셋 26% -> 96%

1. 발음 유사 검색에서 영어 상표를 한글 발음으로 변환해야 했는데, 처음에는 오픈소스(g2p-en)에 의존했고 **검증셋 50단어 기준 한글 표기 정확도가 26%**에 불과했습니다. 검증셋 50단어는 기존 검색이 놓치던 한/영 발음 유사 케이스에서 선별해 **고정한 회귀 검증셋**입니다. 변환이 부정확하니 '에펠라 - effera' 같은 케이스가 검색 단계에서 대량 누락됐고, 이는 **변리사가 거절 위험이 있는 유사 상표를 놓치는 문제**로 곧장 이어졌습니다.
2. 근본 원인은 영어 발음 규칙의 복잡함이었습니다. 한국어는 구개음화, 자음동화 등 **약 7가지 유형의 정형화된 변동**으로 설명되는 반면, **영어는 같은 철자도 맥락에 따라 발음이 갈립니다**(어두 G가 ㄱ 'go'와 ㅈ 'gem'으로 갈리고, magic-e 규칙에는 'ee', 'else' 같은 예외가 많은 식). 오픈소스가 영어권 화자 기준의 발음을 출력해 한국어 화자가 인식하는 표기와 어긋나는 것이 원인이라 판단하고, 오픈소스를 키우는 대신 영어 발음 변환 패턴을 조사할 수 있는 만큼 조사해 **가장 유의미한 약 30개 패턴을 추려 룰 기반 변환기를 직접 구현**했습니다. 영어 발음을 일관된 규칙으로 한글 표기에 맞춰, 한글과 영어 발음을 같은 기준 위에서 비교하게 한 것입니다.
3. 단순히 **fuzzy 검색의 허용 오차를 늘려 누락을 메우는 방법은 의도적으로 배제**했습니다. **535만 건 인덱스에서는 무관한 후보가 폭증해 이미 잘 잡히던 정답이 노이즈에 밀리는 부작용**이 있었기 때문입니다. 정밀도를 깨는 무차별 확장 대신 **'의미 있는 변형'만 선별**했습니다.
4. **결과**: 동일 검증셋에서 **한글 표기 정확도 26% -> 96%**, 룰 구현 후 실제 검색 기록에서 추린 **121단어 확장셋에서도 94.2%**를 기록했습니다.

### 규칙의 예 - 영어 철자가 한글 발음으로 갈리는 지점

- 어말 e(magic-e): 단어 끝에 e가 오면 앞 모음이 알파벳 이름 소리로 바뀝니다. make는 "마크"가 아니라 "메이크"입니다. 이 규칙을 추적해 어말 e를 발음하지 않고 앞 모음을 바꾸도록 했고, 예외(ee, else 등)는 따로 두었습니다.
- 어두 ph: 단어 첫머리의 ph는 ㅍ 소리입니다. phone은 "프혼"이 아니라 "폰"입니다.
- 어두 g: 뒤 모음에 따라 ㄱ(go)과 ㅈ(gem)으로 갈립니다.

이런 식으로 조사한 패턴 중 검증셋에서 실제로 정확도를 바꾸는 약 30개를 먼저 추려 규칙으로 고정했고, 이후 확장셋 121단어를 맞추며 규칙이 늘어 현재 코드 기준으로는 아래와 같습니다.

### 근거 - 규칙 파일과 검증 기록

- 규칙은 파이썬 파일 하나(약 690줄)에 있습니다. 문자 패턴 44개, 접미사 규칙 39개(예: ation -> 에이션, tion -> 션, sion -> 전), 접두사와 묵음, 이중 자음 목록이 따로 있습니다.
- 어두 ph는 ㅍ 계열 음소에 매핑되고, nk는 종성 ㅇ + ㅋ(pink -> 핑크), nge는 ㄴ + ㅈ + ㅔ(orange의 ng가 종성 ㅇ으로 잡히던 문제 해결)로 정의돼 있습니다.
- 문맥 의존 모음은 다음 자음에 따라 후보를 여럿 내는 variant 방식입니다. 예를 들어 e는 다음이 r이면 허/베 두 후보(her, berry), y나 z면 이, p/f/h/m/s/x면 에/이 두 후보(premium)입니다.
- 규칙의 근거는 63만 건 영한 매핑 통계입니다(2026-03-28 정리 문서. tion -> 션 3,754건, ing -> 잉 2,721건 순).
- 검증 기록(2026-04-06 문서): 기존 67단어 67/67, 확장 121단어 114/121(94.2%), g2p-en과의 비교셋 50단어에서 g2p-en 13/50(26%) 대 자체 규칙 48/50(96%). 남은 7건은 orange, chocolate, chicken, cheese, service, tiger, luxury.
- 단어 목록 파일과 정확도 측정 스크립트는 저장소에 남아 있지 않고 수치는 문서에만 있습니다. 이후 이 규칙은 검색 서버의 Java 구현(magic-e 처리 포함)으로 옮겨져 11개국 파이프라인에서 쓰였습니다.
