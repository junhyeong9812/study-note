# 데이터 모니터링/무중단 배포 시스템 구축 (중앙 관제, blue/green)

> 소속 경력: MarkView 서비스 개발 및 고도화 - 변리사 대상 글로벌 다국어 유사 상표 검색 서비스 (한국, 중국, 일본, 미국, 유럽) - 검색 알고리즘 설계, 검색 성능 개선, 데이터 모니터링/무중단 배포 시스템 구축

## 한 줄 요약

메트릭 없이 SSH로 컨테이너를 하나씩 보던 운영을, 에이전트 수집과 임계점 자동 대응, OOM 자동 복구와 서킷브레이커, 검증 통과 시에만 전환하는 blue/green 배포를 갖춘 Python 중앙 관제로 바꿔 SSH 접속 없이 운영하게 했습니다.

## 문제 상황

서버 2대(Data Hub, Control)에 5개국 ES와 검색 서버가 있었지만 상태와 부하를 보는 수단이 없어 **매번 SSH로 컨테이너를 확인**했습니다.\
검색 서버는 단일 인스턴스라 배포가 곧 중단이었고 장애 시 수동으로 재구동했습니다.\
데이터 최신화도 자동화되어 있지 않았습니다.

1. [상태, 부하 메트릭 수집이 없어 서버 상황을 보려면 SSH로 컨테이너를 일일이 조회해야 함](문제상황/01_관측_없는_서버_2대/post.md)
2. [검색 서버가 단일 인스턴스라 무중단 배포가 없고 장애 시 수동 재구동](문제상황/02_배포가_곧_중단/post.md)

## 해결 과정

세 번의 판단으로 진행했습니다. 먼저 보이게 만들고, 사람보다 정책이 먼저 대응하게 하고, 검증을 통과한 빌드만 트래픽을 받게 했습니다.

**판단 1. 먼저 보이게 만든다**\
메트릭과 로그, 에러를 한 곳에 모아야 그다음이 가능합니다.

1. [흩어진 시스템을 한 곳에서 모니터링하고 자원까지 제어하는 중앙 관제 구조로 바꾸고, 서버별 임계점을 정해 넘으면 알림 또는 자동 대응하는 방향 설정](해결과정/01_중앙_관제_방향/post.md)
2. [에이전트가 주기적으로 컨테이너 메트릭, 호스트 자원, ES 클러스터와 JVM heap, 마이그레이션 진행을 중앙으로 올리고 로그는 WebSocket 스트리밍, 에러와 인시던트는 별도 DB로](해결과정/02_수집_워크플로우/post.md)

**판단 2. 사람보다 정책이 먼저 대응한다**\
임계점, 자동 복구, 스케줄링을 정책으로 두되 무한 재시작은 서킷브레이커로 막았습니다.

3. [힙 고갈로 떠 있기만 한 ES를 도커 healthcheck가 못 잡아 호스트 자원까지 수집하고, 부하 테스트로 정한 임계점을 넘으면 알림과 마이그레이션 동시성 자동 하향](해결과정/03_임계점_자동_대응/post.md)
4. [컨테이너 사망은 원인(OOM)과 마지막 로그를 수집한 뒤 자동 재구동, 힙 고갈 상태는 서비스 코드로 감지해 재기동, 무한 재시작은 서킷브레이커로 차단 후 사람 개입 알림](해결과정/04_장애_자동_복구/post.md)
5. [국가별 정해진 시각에 증분 마이그레이션을 자동 트리거하고 변경분 기준 ES upsert로 멱등하게 재처리해 누락 건만 다시 처리](해결과정/05_데이터_최신화_스케줄링/post.md)

**판단 3. 검증을 통과한 빌드만 트래픽을 받는다**\
자동 검증에 사람 확인을 더한 blue/green 전환입니다.

6. [GitLab 러너를 고정할 수 없어 오케스트레이션 서버의 파이프라인으로 빌드, 헬스체크, 단위 테스트, 실제 검색 결과 대조를 전부 통과한 경우에만 blue/green 전환, 마지막은 사람 확인](해결과정/06_무중단_배포/post.md)
7. [k3s의 중앙 오케스트레이션 + 노드 에이전트 구성을 2대 서버 환경에 맞게 Python으로 응용한 최종 구조](해결과정/07_구축_후_구조/post.md)

선택하지 않은 방법: 도커 restart와 healthcheck에만 의존(힙 고갈 상태를 못 잡음), 별도 GitLab CI(러너 고정 불가), 완전 자동 배포(검색 서버는 마지막에 사람 확인).

## 결과

구축 이후 **운영 문제로 서버에 SSH로 접속할 필요가 사실상 없어졌습니다**. 부하로 인한 다운을 근본적으로 없애려면 IDC 서버 증설이 필요해 시간이 걸렸지만, 그동안에도 **자동 감지, 복구 구조가 다운타임을 짧게 억제**해 안정성을 유지했습니다.\
**서버 자원 관리, 로그와 에러 모니터링, 데이터 최신화 스케줄링, 무중단 배포까지를 대시보드 한 곳에서 처리하는 인프라**를 갖추게 되었습니다.
