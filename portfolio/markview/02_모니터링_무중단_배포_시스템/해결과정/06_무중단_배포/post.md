# 6. GitLab 러너를 고정할 수 없어 오케스트레이션 서버의 파이프라인으로 빌드, 헬스체크, 단위 테스트, 실제 검색 결과 대조를 전부 통과한 경우에만 blue/green 전환, 마지막은 사람 확인

### 무중단 배포 워크플로우 - 검증 단계 전부 통과 + 사람 확인 -> nginx 전환 (blue/green)

```text
     검증
     +--------------------------------+    +--------------------------------+   +--------------------------------+   +--------------------------------+
     | merge                          |    | 빌드                           |   | 헬스체크                       |   | 단위 테스트                    |
     |                                |    | 새 색상 컨테이너               |   |                                |   |                                |
     |                                |----> (현재 blue면 green)           -|--->                                |--->                                |
     +--------------------------------+    +--------------------------------+   +--------------------------------+   +--------------------------------+
                                                                                                                                      |
                           -----------------------------------------------------------------------------------------------------------|
     +---------------------v--------------------+     +------------------------------------------+
     | API 테스트                               |     | [사람 확인]                              |
     | 실제 요청으로 검색 결과 대조             |-----> 테스트 결과 검토 후 승인 (안전장치)      |
     |                                          |     |                                          |
     +------------------------------------------+     +------------------------------------------+

     승인 후 전환

     +-----------------------------------+  +-----------------------------------+ +-----------------------------------+ +-----------------------------------+
     | nginx upstream 전환               |--> 트래픽이 새 컨테이너로            |-> 구 컨테이너 대기                  |-> 안정 확인 후 정리                 |
     | blue -> green                     |  | 사용자 단절 없음                  | | 문제 시 upstream 되돌려 즉시 롤백 | | 다음 배포의 대기 슬롯             |
     |                                   |  |                                   | |                                   | |                                   |
     +-----------------------------------+  +-----------------------------------+ +-----------------------------------+ +-----------------------------------+
     * 한 단계라도 실패 -> 배포 중단, 기존 컨테이너 그대로 서비스 (검증되지 않은 빌드는 실제 검색에 노출되지 않음)
```

도식 39. 무중단 배포 워크플로우 - 검증 통과와 사람 확인 뒤 nginx upstream 전환, 구 컨테이너로 즉시 롤백 가능

GitLab 서버의 IP가 동적이라 러너를 고정해 등록해 둘 수 없어, 별도 GitLab CI 대신 **오케스트레이션 서버의 배포 파이프라인으로 처리**했습니다.\
merge 이후 git pull -> 빌드 -> 헬스체크 -> 단위 테스트 -> API 테스트(실제 API에 요청을 보내 검색 결과가 기대값과 맞는지 검증) 순으로 진행하고, **모든 단계를 통과한 경우에만 blue/green 방식으로 트래픽을 전환**하며 **한 단계라도 실패하면 배포를 중단**합니다.\
**검증되지 않은 빌드가 실제 검색에 노출되는 일을 막았습니다**. 검색 서버는 메인 비즈니스와 직결된 서비스라, 자동 API 테스트로 정합성까지 검사하더라도 실제 장애 시 서비스 신뢰성 문제가 남아 **마지막 단계에서 사람이 테스트 결과를 확인한 뒤 배포하는 안전장치**를 두었습니다.
