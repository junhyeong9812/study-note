# 2. 에이전트가 주기적으로 컨테이너 메트릭, 호스트 자원, ES 클러스터와 JVM heap, 마이그레이션 진행을 중앙으로 올리고 로그는 WebSocket 스트리밍, 에러와 인시던트는 별도 DB로

> 데이터 모니터링/무중단 배포 시스템 구축 - 해결 과정 2/7. [사례로 돌아가기](../../) | [이전 1단계](../01_중앙_관제_방향/post.md) | [다음 3단계](../03_임계점_자동_대응/post.md)

- 수집: 에이전트가 일정 주기로 **도커 컨테이너 메트릭, 호스트 자원, ES 클러스터와 JVM heap 상태, 마이그레이션 진행 정보를 수집해 중앙으로** 올리고, **로그는 WebSocket으로 스트리밍**하며 에러와 인시던트 기록은 저장해 두고 알림으로 연결해 **대시보드 한 곳에서 확인**하게 했습니다.

### 수집 워크플로우 - 에이전트 주기 수집 + 로그 스트리밍

```text
     +----------------------------------+    +-----------------------------------+  +----------------------------------+   +----------------------------------+
     | Data Hub 에이전트                |    | 수집 항목                         |  | 별도 엔드포인트로                |   | 오케스트레이션 서버              |
     | 일정 주기 실행                   |----> 도커 컨테이너 메트릭             -|--> 중앙에 전송                      |---> 대시보드 한 곳에서 확인          |
     |                                  |    | 호스트 자원 (CPU, 메모리, 디스크) |  |                                  |   |                                  |
     |                                  |    | ES 클러스터, JVM heap             |  |                                  |   |                                  |
     |                                  |    | 마이그레이션 진행 정보            |  |                                  |   |                                  |
     +----------------------------------+    +-----------------------------------+  +----------------------------------+   +----------------------------------+

     로그와 에러
     +------------------------------------------+     +------------------------------------------+     +------------------------------------------+
     | 컨테이너 로그                            |     | 대시보드 실시간 표시                     |     | 에러, 인시던트                           |
     | WebSocket 스트리밍                       |----->                                          |-----> 별도 DB 저장 (분석 가능한 형태)          |
     | (누적 방지: 컨텍스트 윈도우)             |     |                                          |     | 알림 연결                                |
     +------------------------------------------+     +------------------------------------------+     +------------------------------------------+
```

도식 35. 수집 워크플로우 - 에이전트 주기 수집, 로그 스트리밍(컨텍스트 윈도우), 에러 별도 DB

### 근거 - 주기와 보관

- 관제 서버의 자체 수집 주기는 5초, 에이전트의 push 주기는 10초(타임아웃 5초)입니다.
- 컨테이너별 메트릭 이력은 10초 단위 360개, 즉 1시간을 메모리에 보관합니다.
- 에이전트 heartbeat 타임아웃은 180초입니다.
