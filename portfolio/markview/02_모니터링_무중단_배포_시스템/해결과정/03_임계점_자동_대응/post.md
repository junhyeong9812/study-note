# 3. 힙 고갈로 떠 있기만 한 ES를 도커 healthcheck가 못 잡아 호스트 자원까지 수집하고, 부하 테스트로 정한 임계점을 넘으면 알림과 마이그레이션 동시성 자동 하향

> 데이터 모니터링/무중단 배포 시스템 구축 - 해결 과정 3/7. [사례로 돌아가기](../../post.md) | [이전 2단계](../02_수집_워크플로우/post.md) | [다음 4단계](../04_장애_자동_복구/post.md)

- 임계점 기반 자동 대응: ES는 **힙이 고갈되면 컨테이너는 떠 있는데 응답을 못 하는 상태**가 빈번했고 **도커의 restart나 healthcheck로는 잡히지 않아**, 호스트 자원까지 함께 수집했습니다. **부하 테스트로 정한 임계점**을 넘으면 알림을 보내는 한편, **실행 중인 마이그레이션의 동시성(워커 수, 배치 크기)을 자동으로 낮춰 부하를 흡수**했습니다.

### 임계점 기반 자동 대응 워크플로우

```text
                                                                                               +----------------------+
     +------------------------------------+      +------------------------------------+        |                      |
     | 메트릭 수신                        |------> 임계점 비교                        |-------->        초과?         |
     |                                    |      | (부하 테스트로 정한 값)            |        |                      |
     +------------------------------------+      +------------------------------------+        |                      |
                                                                                     ----------+----------------------+-------------yes
                                                                                     |no                                           |
                                                                                     |                                             |
                                                                                     v                                             v
                                                                   +-----------------------------------+      +------------------------------------------+
                                                                   | 계속 관측                         |      | 자동 대응                                |
                                                                   |                                   |      | 알림 발송                                |
                                                                   |                                   |      | 실행 중 마이그레이션 동시성 하향         |
                                                                   +-----------------------------------+      | (워커 수, 배치 크기)                     |
                                                                                                              | 부하 흡수, 회복 후 복원                  |
                                                                                                              +------------------------------------------+
```

도식 34. 임계점 기반 자동 대응 - 초과 시 알림 + 마이그레이션 동시성 하향

### 임계점 값과 커스텀

임계점은 사용자가 바꿀 수 있게 두었고(CSV로 영속, 수정 API), 코드의 기본값은 컨테이너(API) **CPU 80%**, 컨테이너 메모리 90%, 호스트 CPU 90%, 호스트 메모리 85%, 디스크 90%입니다.\
이 값을 넘으면 알림을 보내면서(같은 알림은 300초 쿨다운) 실행 중인 마이그레이션의 동시성(워커 수, 배치 크기)을 자동으로 낮춰 부하를 흡수합니다.

### 근거 - 임계치와 스로틀 규칙

- 임계치 정본은 관제 서버의 임계치 관리 모듈 기본값(5개국 x 3항목)이고 CSV로 저장됩니다. 항목별 수정, 삭제, 켜고 끄기 함수가 있고, 알림 모듈에도 카테고리별 임계치가 있어 API로 바꿉니다.
- 판단 규칙은 판단 엔진 모듈에 있습니다. 규칙 1: 호스트 CPU가 90%를 넘으면 마이그레이션 워커 수를 1 줄임(최소 1). 규칙 2: 최근 100건 이상에서 에러율이 10%를 넘으면 배치 크기를 절반으로(최소 100). 규칙 3: CPU가 60% 아래이고 에러율이 1% 미만이면 워커를 1 늘려 초기값까지 복귀. 규칙 4: 처리 속도가 10 docs/s 아래면 알림.
- 스로틀 기본값은 배치 1,000, 워커 4이고, 에이전트의 스로틀 제어 객체가 공유 메모리 값으로 받아 배치 크기는 다음 배치부터, 워커 수는 실행기 재생성으로 적용합니다.
- ES의 JVM 힙 상태는 수집해 대시보드에 보이고, 임계 판정 자체는 컨테이너 메모리 비율(90%)로 합니다. 힙 값을 별도 임계치로 두지는 않았습니다.
