# 4. 컨테이너 사망은 원인(OOM)과 마지막 로그를 수집한 뒤 자동 재구동, 힙 고갈 상태는 서비스 코드로 감지해 재기동, 무한 재시작은 서킷브레이커로 차단 후 사람 개입 알림

- 장애 자동 복구: 컨테이너 사망은 **메트릭으로 감지해 원인(OOM 여부)과 마지막 로그를 수집한 뒤 자동 재구동**하고, 힙 고갈로 떠 있기만 한 상태는 **서비스 코드 차원에서 별도 감지**해 다시 띄웠습니다. 무한 재시작으로 번지지 않도록 **서킷브레이커**를 두어, 재시작이 반복되면 **쿨다운 후 재시도하고 회복되지 않으면 복구를 멈추고 사람이 개입**하도록 알림을 보냈습니다.

### 장애 자동 복구 워크플로우 - 서킷브레이커로 무한 재시작 차단

```text
     +----------------------------+  +----------------------------+  +----------------------------+  +----------------------------+  +----------------------------+
     | 감지                       |  | 원인 수집                  |  | 자동 재구동                |  | 재시작 반복?               |  | 복구 판정                  |
     | 컨테이너 사망 (메트릭)     |  | OOM 여부, 마지막 로그      |  |                            |  | (서킷브레이커)             |  | yes: 쿨다운 후 재시도      |
     | 힙 고갈로 응답 없음        |-->                            |-->                            |-->                            |--> 회복 안 되면 중단          |
     | (서비스 코드 차원 감지)    |  |                            |  |                            |  |                            |  | -> 사람 개입 알림          |
     |                            |  |                            |  |                            |  |                            |  | no: 정상 복귀              |
     +----------------------------+  +----------------------------+  +----------------------------+  +----------------------------+  +----------------------------+
```

도식 35. 장애 자동 복구 - 감지, 원인 수집, 재구동, 서킷브레이커

### 근거 - 감지, 원인 수집, 서킷브레이커

- 헬스체크는 3회 연속 실패(10초 주기, 약 30초)면 재시작 대상이 됩니다.
- 사망 원인은 Docker 소켓으로 컨테이너를 inspect해 `State.OOMKilled`, 종료 코드, 오류를 읽고 마지막 로그 50줄(3,000자)을 함께 남깁니다. OOM이면 심각도를 critical로 올립니다.
- 서킷브레이커는 2단계입니다. 5분 안에 재시작 3회가 실패하면 트립해 10분 쿨다운, 그 뒤 서버 메트릭이 재시작 가능한 상태(CPU와 메모리 98% 미만)일 때만 3회를 더 시도하고, 그래도 실패하면 영구 중단(open) 상태로 두고 사람에게 알립니다.
- 어떤 서비스를 자동 재시작할지는 국가와 서비스별 설정 파일로 정합니다.
