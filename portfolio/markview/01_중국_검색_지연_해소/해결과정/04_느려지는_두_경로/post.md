# 4. 느려지는 두 경로 분리: 세그먼트별 고정 순회 비용과 끝나지 않는 백그라운드 병합의 CPU/IO 경합

### 검색이 느려지는 두 경로 - 세그먼트별 고정 순회 비용 + 끝나지 않는 병합 부하

```text
                                           +-----------------------------------------------------------+
     +---------------------------+         | 세그먼트마다 고정 비용                                    |         +------------------------------------+
     | 검색 쿼리 1건             |         | seg 1 (2.7GB) 순회                                        |         | 결과 병합 -> 응답 5~6초            |
     |                           |----+    | seg 2 (1.1GB) 순회                                        |    +---->                                    |
     +---------------------------+    +----> seg 3 (28MB) 순회  <- 데이터는 적은데 비용은 그대로       |----+    +------------------------------------+
                                           | ...  x 153                                                |
                                           |                                                           |
                                           |                                                           |
                                           +-----------------------------^-----------------------------+
                                                                     자원 경합
                                                                         |
                                           +-----------------------------------------------------------+
                                           | 동시에: 백그라운드 병합                                   |
                                           | 소형 세그먼트 계속 생성 -> 병합 스레드 상시 가동          |
                                           | CPU, 디스크 대역폭을 검색과 나눠 씀                       |
                                           |                                                           |
                                           +-----------------------------------------------------------+
     * 검색 = 세그먼트 수만큼 붙는 순회 오버헤드  +  서버 = 끝나지 않는 병합 IO  ->  동시에 느려짐
```

도식 28. 느려지는 두 경로 - 세그먼트별 고정 순회 비용, 동시에 도는 백그라운드 병합의 CPU, 디스크 IO 경합

검색은 **세그먼트마다 순회 비용이 고정으로 붙기** 때문에, 28MB짜리 세그먼트 수십 개는 담고 있는 데이터량에 비해 오버헤드만 키우는 셈이었습니다.\
여기에 더해, 작은 세그먼트가 계속 생기는 동안에는 백그라운드 병합 작업이 쉬지 않고 돌면서 **CPU와 디스크 대역폭을 검색과 나눠 쓰게** 됩니다.\
즉 **검색은 세그먼트마다 붙는 순회 비용으로, 서버는 끝나지 않는 병합 부하로 동시에 느려지는 상태**였습니다.
