# 2. 인덱스 상태를 점검해 원인이 데이터 크기가 아니라 세그먼트 구조(153개, 28MB~2.7GB 불균형)임을 특정

### 인덱스 상태 점검 - 가정과 실측

```text
 가정: "데이터가 커서 느리다"                        실측: 세그먼트 구조가 문제
 +--------------------------------+                +--------------------------------------------------+
 | 중국 실 상표 약 8,600만 건     |                | 세그먼트 153개, 크기 28MB ~ 2.7GB 로 불균형      |
 | 분석 인덱스 포함 약 12억 건    |   --> (접음)   |                                                  |
 | ES 적재 약 350GB               |                |  2.7GB  ||||||||||||||||||||||||||||             |
 |                                |                |  1.1GB  ||||||||||||                             |
 | -> 규모를 줄이거나 증설?       |                |   ...                                            |
 +--------------------------------+                |   28MB  |  x 수십 개  <- 담긴 데이터는 적은데    |
                                                   |                          순회 비용은 그대로      |
                                                   +--------------------------------------------------+

 * 절대 크기가 아니라 구조: 세그먼트 수와 크기 불균형이 병목이라 규모 축소나 증설로는 풀리지 않는다
```

위키 추가 도식. 인덱스 상태 점검 - 가정과 실측 (정본 경력기술서에는 없는 도식)

처음에는 "데이터 규모가 커서 느린 것 아닌가"라고 가정했지만, 인덱스 상태를 들여다보니 **원인은 절대 크기가 아니라 구조**였습니다.\
**세그먼트가 153개까지 늘어나 있었고 크기도 28MB에서 2.7GB까지 크게 불균형**했습니다.
