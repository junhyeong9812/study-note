# 덧붙임. 병합 정책의 하한(floor_segment)이 동작하는 방식 - 처음부터 두었다면 파편화를 막았을 설정

> 중국 검색 지연 해소 - 해결 과정 덧붙임. [사례로 돌아가기](../../) | [이전 8단계](../08_정렬_병목_분기/post.md)

이 사례에서는 적용하지 못한 설정입니다. 재색인 뒤 force merge로 5GB 구간을 만들었지만, 처음부터 아래 하한을 두었다면 153개 파편화 자체가 생기지 않았을 것이라 회고에 남겼습니다.

### 하한이 없을 때와 있을 때

```text
 하한 낮음 (기본 2MB)                                       하한 5GB
 +--------------------------------------------------+       +--------------------------------------------------+
 | refresh -> 28MB, 40MB, 35MB ... 소형 세그먼트 생성 |       | refresh -> 28MB, 40MB, 35MB ... 소형 세그먼트 생성 |
 |        |                                         |       |        |                                         |
 |        v  병합 후보 선정 (크기 계층별)             |       |        v  병합 후보 선정                           |
 | 소형끼리만 같은 계층 -> 조금씩 합쳐 중형           |       | 5GB 미만은 전부 5GB 로 취급 -> 같은 계층          |
 | 2.7GB 대형은 계층이 달라 후보에서 빠짐             |       | -> 곧바로 묶여 5GB 구간으로 합쳐짐                |
 |        |                                         |       |        |                                         |
 |        v                                         |       |        v                                         |
 | 결과: 대형 몇 개 + 소형 수십 개 = 153개 누적       |       | 결과: 5GB 안팎 세그먼트만 남음 (상한 5GB 와 결합) |
 +--------------------------------------------------+       +--------------------------------------------------+

 * 하한(index.merge.policy.floor_segment)보다 작은 세그먼트는 병합 후보를 고를 때 하한 크기로 취급된다
 * 상한(max_merged_segment)과 하한을 같은 값으로 두면 세그먼트 크기가 한 구간으로 수렴한다
```

### 동작 방식

Elasticsearch의 병합 정책(tiered)은 세그먼트를 크기 계층으로 나누고, **같은 계층 안에서** 병합 후보를 고릅니다.\
하한(index.merge.policy.floor_segment, 기본 2MB)보다 작은 세그먼트는 후보를 고를 때 **하한 크기인 것처럼 취급**됩니다.\
기본값에서는 28MB짜리가 그대로 소형 계층에 남아 소형끼리만 조금씩 합쳐지고, 이미 커진 2.7GB 세그먼트와는 계층이 달라 섞이지 않습니다. 대량 적재 중 refresh가 소형 세그먼트를 계속 만들면 이 구조가 누적됩니다.\
하한을 5GB로 두면 5GB 미만 세그먼트가 전부 같은 계층으로 취급돼 곧바로 묶이고, 상한 5GB와 결합해 세그먼트 크기가 5GB 구간으로 수렴합니다.

### 이번 사례에서 쓴 방법과의 차이

이번에는 재색인 뒤 force merge로 같은 결과를 만들었습니다. 다만 force merge는 되돌릴 수 없고 적재가 끝난 뒤 한 번 도는 작업이라, 이후 증분 색인에서 다시 소형 세그먼트가 쌓이는 것은 막지 못합니다.\
하한 설정은 적재 중에도 정책이 계속 동작하므로, 처음부터 두었다면 파편화가 생기지 않았고 force merge도 필요 없었습니다.
