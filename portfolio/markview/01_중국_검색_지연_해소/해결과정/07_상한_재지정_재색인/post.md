# 7. 세그먼트 최대 크기 상한을 데이터 규모에 맞춰 재지정하고, 파편화된 운영 인덱스를 재색인으로 정리

> 중국 검색 지연 해소 - 해결 과정 7/8. [사례로 돌아가기](../../post.md) | [이전 6단계](../06_되돌릴_수_없는_제약/post.md) | [다음 8단계](../08_정렬_병목_분기/post.md)

### 해결 - 세그먼트 최대 크기 상한 고정 + 재색인 (병합은 단방향, 분할 API 없음)

```text
     +----------------------------------+    +----------------------------------+   +----------------------------------+   +----------------------------------+
     | 분할 API 없음 확인               |    | 최대 크기 상한 지정              |   | 운영 인덱스 재색인               |   | 적정 구간 유지                   |
     | 병합 = 되돌릴 수 없음            |----> 데이터 규모에 맞춰 고정         -|---> 파편화 누적분 정리               |---> 이후 인덱스 구조 변경은          |
     | 되돌리려면 재색인                |    | 병합이 한 덩어리로 쏠리지 않음   |   |                                  |   | 재색인 전제로 설계               |
     |                                  |    |                                  |   |                                  |   |                                  |
     +----------------------------------+    +----------------------------------+   +----------------------------------+   +----------------------------------+
```

도식 30. 해결 - 세그먼트 최대 크기 상한 고정 + 재색인, 이후 인덱스 구조 변경은 재색인 전제

이후 **세그먼트 최대 크기 상한을 데이터 규모에 맞춰 지정**해 병합이 한 덩어리로 쏠리지 않고 **적정 구간을 유지**하도록 했고, 이미 파편화가 누적된 **운영 인덱스는 재색인으로 정리**했습니다.

### 무엇을 얼마로, 왜

**설정과 값** - 세그먼트 최대 크기 상한(index.merge.policy.max_merged_segment)을 **5GB**로 두었습니다.\
값은 상한을 바꿔 가며 쿼리 한 건의 **IO 시간과 실제 연산 시간을 따로 재서** 정했고, 5GB에서 둘의 합이 가장 작았습니다.\
5GB는 Elasticsearch 병합 정책의 기본 상한과 같은 값입니다. 기본값이라서 둔 것이 아니라 우리 데이터에서 실측으로 같은 지점이 나왔다는 뜻이고, 이후 11개국 통합 인덱스(경력 1 - 05)에서도 같은 기준을 썼습니다.

**원리** - 세그먼트가 크면 세그먼트마다 붙는 고정 순회 비용은 줄지만, 한 세그먼트의 역색인과 doc values가 커져 페이지 캐시에 올라가는 단위가 커지고 조건에 맞지 않는 세그먼트를 통째로 건너뛰는 이점이 사라집니다.\
작으면 그 반대라, 두 비용이 만나는 지점이 상한이 됩니다. 5단계의 단일 세그먼트(약 120GB) 역효과가 그 반대편 끝을 보여 준 실측입니다.

**재색인** - 파편화가 누적된 운영 인덱스는 상한을 적용한 새 인덱스로 재색인해 정리했습니다.\
재색인이 끝난 뒤에는 force merge로 소형 세그먼트를 합쳐, 세그먼트 하나가 약 5GB가 되도록 개수를 정해 정리했습니다.\
5단계에서 단일 세그먼트(약 120GB)까지 합쳤을 때 느려진 것을 실측했으므로, 이번에는 하나로 합치지 않고 5GB 구간에 맞춘 여러 세그먼트로 두는 것이 원칙이었습니다.\
이후 일상 색인에서 생기는 세그먼트는 상한 5GB 안에서 병합 정책이 관리하므로, 153개까지 갈라졌던 파편화는 재현되지 않습니다. 재색인 방식과 소요 시간의 당시 기록은 남아 있지 않습니다.
