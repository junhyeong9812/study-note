# 다국어 유사 상표 검색 시스템 설계 및 개발

> 소속 경력: MarkView 서비스 개발 및 고도화 - 변리사 대상 글로벌 다국어 유사 상표 검색 서비스 (한국, 중국, 일본, 미국, 유럽) - 검색 알고리즘 설계, 검색 성능 개선, 데이터 모니터링/무중단 배포 시스템 구축
> 이 서비스는 5개 지역(한국, 중국, 일본, 미국, 유럽) 대상입니다. 11개국 확장분(단일 통합 인덱스, 어댑터, k6 부하테스트)은 "한국지식재산보호원 K-브랜드 지킴이 - 해외 상표 무단선점 경보 서비스 개발" 경력에 해당합니다.

## 문제 상황

이 시스템의 주 사용자는 변리사입니다. 변리사는 의뢰받은 상표를 출원하기 전에 유사한 상표가 이미 존재하는지 사전 조사하는데, 유사 상표가 있으면 심사 단계에서 의견제출통지서와 함께 출원이 거절되기 때문입니다. 따라서 "유사 상표를 더 정확하고 빠르게 찾는 것"이 변리사 업무 효율과 직결되는 핵심 문제였습니다.

## 해결 과정

변리사인 대표의 실무 경험과 실제 의견제출통지서 데이터를 바탕으로 유사성을 세 유형으로 나눴습니다. 자모의 생김새가 비슷한 형태 유사(ㅏ/ㅑ, ㅁ/ㅂ), 발음이 비슷한 발음 유사(에펠라 - effera), 음절 순서가 바뀐 도치 유사(양아지 - 아지양)입니다. 특히 한국어와 영어 발음 간 유사성, 그리고 한글과 영문 표기가 교차하는 한/영 교차 케이스(우드스프링 - springwood)를 처리하는 것이 가장 큰 난관이었습니다.

### 형태 / 도치 / 발음 유사의 분리 구현

```text
## 유사 상표 검색 - 유사성 세 유형과 한/영 교차 처리

  기준 소스: 변리사(대표) 판단 기준 + 실제 의견제출통지서 데이터

    +-------------------------------------------------------------------------------------------------+
    | 입력 상표명  예) 우드스프링  ->  세 유형 + 교차 처리                                            |
    +-------------------------------------------------------------------------------------------------+
                                                     |
               +----------------------+--------------+---------+--------------------------+
               |                      |                        |                          |
               v                      v                        v                          v
    +- 형태 유사 --------+  +- 발음 유사 -------+  +- 도치 유사 -----------+  +- 한/영 교차 ----------+
    | 자모 분해, 정규화  |  | 한글 -> 음소(G2P) |  | 음절/토큰 순서 뒤집기 |  | 발음 필드 + 도치 매칭 |
    | ㅏ/ㅑ, ㅁ/ㅂ 등    |  | 영문과 같은 기준  |  | 양아지 = 아지양       |  | 동시 적용             |
    | 생김새 비슷한 글자 |  | 에펠라 = effera   |  |                       |  | 우드스프링            |
    | -> 형태 필드       |  | -> 발음 필드      |  | -> 도치 필드          |  | = springwood          |
    +--------------------+  +-------------------+  +-----------------------+  +-----------------------+

  상표명 하나 -> 세 유형의 필드로 분리 저장 (Lucene 커스텀 토큰 필터 플러그인 + ES 튜닝)
  가장 큰 난관 = 한국어/영어 발음 간 유사성 + 한글, 영문 표기가 교차하는 케이스
```

*도식 28. 유사성 세 유형과 한/영 교차 처리 - 상표명 하나를 형태, 발음, 도치 필드로 분리 저장*

형태 유사는 자모 분리, 유사 자모 그룹핑 전처리를 거치고, 한국어 상표의 자모를 분리, 정규화하는 커스텀 토큰 필터를 Lucene API로 직접 구현해 플러그인(.jar)으로 빌드한 뒤 Elasticsearch에 탑재했습니다. 도치 유사는 문자열을 순차 회전시킨 토큰의 term 매칭에 constant score로 가중치를 고정했고, 발음 유사는 한국어 발음 변형을 정의하고 영어는 자체 룰 기반 G2P 변환으로 일관되게 변형해 한글과 영어 발음을 같은 기준 위에서 비교하게 했습니다(G2P 구현은 아래 절).

3가지 케이스로 상표명을 분리한 데이터 필드를 구성했고, '우드스프링 - springwood'처럼 한/영 표기가 섞이고 어순까지 바뀐 복합 케이스는, 한글을 소리 단위(음소)로 변환해 영문과 같은 기준으로 맞춘 뒤 도치 토큰 매칭을 함께 적용해 처리했습니다. 도메인 정의부터 유사성 기준 설계, Lucene 플러그인 개발과 Elasticsearch 튜닝, 다국어 발음 변환 파이프라인까지 단독으로 진행했습니다. 기본 프로토타입(데이터 수집, 가공 파이프라인 설계와 적재, 검색, 테스트)은 2025.06~09에 개발했고, 재입사 후 2026.02부터 G2P 개발과 성능 개선 등 고도화를 이어갔습니다.

### 한/영 교차 유사도 - 자체 G2P 변환기 빌트인

```text
## 한/영 교차 유사도 - 자체 룰 기반 G2P 변환기 (발음 필드 빌트인)

                            +- 전 --------------------+     +- 후 ----------------------------+                                +--------------------------------+
 +--------------------+     | 오픈소스 g2p-en         |     | 자체 룰 기반 G2P                |     +--------------------+     | 발음 필드에 저장               |
 | 영문 상표          | --> | 영어권 화자 기준 발음   | --> | 패턴 조사 -> 유의미한 약 30개   | --> | 한글 발음 표기     | --> | 한글 상표와 같은 기준으로 비교 |
 | effera, springwood |     | -> 한글 표기 정확도 26% |     | 어두 G(go/gem), magic-e 예외 등 |     | 에펠라, 스프링우드 |     | + 도치 매칭 = 우드스프링       |
 +--------------------+     +-------------------------+     | -> 한글 표기 정확도 96%         |     +--------------------+     +--------------------------------+
                                                            +---------------------------------+                                                                  

 +---------------------------------+                        +-------------------------+
 | 검증셋 50단어                   |     +------------+     | 121단어 확장셋          |
 | 기존 검색이 놓치던 한/영 케이스 | --> | 26% -> 96% | --> | 실제 검색 기록에서 추림 |
 | 고정 회귀 검증셋                |     +------------+     | 94.2%                   |
 +---------------------------------+                        +-------------------------+

   배제한 길: fuzzy 허용 오차 확대 - 535만 건 인덱스에서 무관한 후보 폭증, 잘 잡히던 정답이 노이즈에 밀림 -> '의미 있는 변형'만 선별
```

*도식 29. 한/영 교차 유사도 - 자체 룰 기반 G2P 변환기를 발음 필드에 빌트인, 검증셋 26% -> 96%*

발음 유사 검색에서 영어 상표를 한글 발음으로 변환해야 했는데, 처음에는 오픈소스(g2p-en)에 의존했고 검증셋 50단어 기준 한글 표기 정확도가 26%에 불과했습니다. 검증셋 50단어는 기존 검색이 놓치던 한/영 발음 유사 케이스에서 선별해 고정한 회귀 검증셋입니다. 변환이 부정확하니 '에펠라 - effera' 같은 케이스가 검색 단계에서 대량 누락됐고, 이는 변리사가 거절 위험이 있는 유사 상표를 놓치는 문제로 곧장 이어졌습니다.

근본 원인은 영어 발음 규칙의 복잡함이었습니다. 한국어는 구개음화, 자음동화 등 약 7가지 유형의 정형화된 변동으로 설명되는 반면, 영어는 같은 철자도 맥락에 따라 발음이 갈립니다(어두 G가 ㄱ 'go'와 ㅈ 'gem'으로 갈리고, magic-e 규칙에는 'ee', 'else' 같은 예외가 많은 식). 오픈소스가 영어권 화자 기준의 발음을 출력해 한국어 화자가 인식하는 표기와 어긋나는 것이 원인이라 판단하고, 오픈소스를 키우는 대신 영어 발음 변환 패턴을 조사할 수 있는 만큼 조사해 가장 유의미한 약 30개 패턴을 추려 룰 기반 변환기를 직접 구현했습니다. 영어 발음을 일관된 규칙으로 한글 표기에 맞춰, 한글과 영어 발음을 같은 기준 위에서 비교하게 한 것입니다.

단순히 fuzzy 검색의 허용 오차를 늘려 누락을 메우는 방법은 의도적으로 배제했습니다. 535만 건 인덱스에서는 무관한 후보가 폭증해 이미 잘 잡히던 정답이 노이즈에 밀리는 부작용이 있었기 때문입니다. 정밀도를 깨는 무차별 확장 대신 '의미 있는 변형'만 선별했고, 동일 검증셋에서 한글 표기 정확도를 26%에서 96%로 끌어올렸으며 룰 구현 후 실제 검색 기록에서 추린 121단어 확장셋에서도 94.2%가 나왔습니다.

### 한계선의 명시적 분리

```text
## 한계선의 명시적 분리 - 검출 실패 사례를 원인별로 나눔

+----------------------------------------------+
| 검출하지 못한 사례 전수 -> 원인별 분류       |
+----------------------------------------------+
                       |
      +----------------------------------+----------------------------------+
      v                                                                     v
  +- 현재 접근으로 풀 수 있는 영역 ---+   +- 도달할 수 없는 영역 ------------+
  | 음차 (소리 옮김)                  |   | 의미 번역 관계                   |
  | 도치 (순서 바뀜)                  |   | 체리블라썸 = 벚꽃                |
  | 부분 매칭 (일부 겹침)             |   | 문자도 발음도 겹치지 않음        |
  |                                   |   | 심사관은 관념의 유사로 거절      |
  | -> 어휘, 발음 규칙으로 개선 가능  |   | -> 의미 기반 검색(임베딩)의 영역 |
  | -> 자원 집중                      |   | -> 한계선으로 분리, 이번 범위 밖 |
  +-----------------------------------+   +----------------------------------+
```

*도식 30. 검출 실패 사례의 원인별 분리 - 개선 가능 영역에 자원 집중, 의미 번역은 한계선 밖*

검출하지 못한 사례를 원인별로 나눠, 현재 접근으로 풀 수 있는 영역(음차, 도치, 부분매칭)과 도달할 수 없는 영역을 구분했습니다. 후자는 체리블라썸 - 벚꽃처럼 문자도 발음도 겹치지 않지만 심사관이 관념의 유사로 거절한 의미 번역 관계로, 의미 기반 검색(임베딩)의 영역이라 한계선으로 분리해 두고 어휘, 발음으로 실제 개선 가능한 구간에 자원을 집중했습니다.

### 다국가 확장 - 어댑터와 단일 통합 인덱스

```text
## 다국가 확장 - 국가별 정규화 어댑터와 단일 통합 인덱스

  +- 원천 상표 데이터 ---+        +- 국가별 정규화 어댑터 -------------+        +- 단일 통합 인덱스 -------------------------+
  | 미국 (US)            |        | US: 자체 G2P 변환                  |        | 문서 1건 = 상표명 + 검색 필드              |
  | 중국 (CN)            |  --->  | CN: 병음 데이터                    |  --->  |                                            |
  | 일본 (JP)            |        | JP: 로마자 + 형태소 분석기         |        |   자국어 필드      [1:N 변형]              |
  | 유럽 23개 언어       |        | EU: 계열 단위 (라틴/게르만/슬라브) |        |   영어 필드        [1:N 변형]              |
  | ... 11개국           |        | 공통: 상표명 + 검색 필드만 추출    |        |   한국어 번역 필드 [1:N 변형]              |
  +----------------------+        +------------------------------------+        |                                            |
                                                                                | 변환은 색인 시 미리 -> 검색 시 변환 최소화 |
                                                                                +--------------------------------------------+

  검색 시:  출원인 국가로 언어 1차 추정 --> 언어별 필드 레이어에 점수 차등 --> 추정이 빗나가도 누락 없음

  4개국 -> 11개국 확장 = 국가별 개별 인덱스 없이 어댑터 추가만으로 흡수
  (한국지식재산보호원 K-브랜드 지킴이 text-server, 2026-07-27 대국민 배포)
```

*도식 31. 국가별 정규화 어댑터와 단일 통합 인덱스 - 변환은 색인 시, 검색 시 변환 최소화*

언어마다 음운 체계와 문자 구조가 달라, 미국은 자체 G2P 변환, 중국은 병음 데이터, 일본은 로마자 표기와 형태소 분석기, 유럽 23개 언어는 계열(라틴, 게르만, 슬라브 등) 단위로 처리했습니다. 출원인 국가로 언어를 1차 추정하되 추정이 빗나가도 누락되지 않도록, 언어별 검색 필드를 레이어로 분리하고 점수에 차이를 두었습니다.

현재 이 검색 엔진은 한국지식재산보호원 "해외 상표 무단선점 시스템"의 검색 서버(text-server)로 채택되어 2026-07-27 대국민 서비스 K-브랜드 지킴이로 배포됐으며, 발주처 요구에 따른 4개국 -> 11개국 확장은 국가별 개별 인덱스 대신 단일 통합 인덱스로 흡수했습니다. 11개국 인덱스의 상표명과 검색에 필요한 필드만 통합 인덱스로 가져오고, 자국어 필드, 영어 필드, 한국어 번역 필드로 분리해 각 필드를 1:N 변형으로 미리 저장함으로써 실제 검색 시 변환 과정을 최소화했습니다.

## 결과

의견제출통지서 기준으로 정제한 28,407쌍 테스트셋에서 약 62.7% 검출률(top-100)을 기록했고(2026년 G2P 고도화 반영 후 측정 기준), 대표(변리사)가 기존 경쟁사 검색과 직접 비교해 낫다고 평가했으며, 여러 변리사가 실제 서비스를 채택해 사용하고 있습니다. 사용 피드백도 대표를 통해 받아 성능 개선에 반영했습니다.
