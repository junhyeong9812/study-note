# storage-labs — 스토리지 엔진 직접 구현 실험 기록

인덱스·페이지·버퍼풀 같은 스토리지 엔진 부품을 **직접 구현하고 측정**하는 실험의 기록.

- **실 구현** = 코드 repo `/home/jun/project/lab/storage-labs/<주제>/` (주제별 독립 git repo · Rust)
- **기록** = 이 폴더 `lab/storage-labs/<주제>/README.md`
- 목록·상태·선행 cs 챕터 = [index.md](index.md)

## README 규칙 — 원본 위 고정, 아래로 append-only

[backend-labs](../backend-labs/README.md)와 같은 규칙이다. 각 주제 README 상단은 **원본 설계(repo README)의 질문·실험 설계·로드맵**을 옮긴 것이고 고치지 않는다.
구현 기록은 **로드맵 단계마다 파일 끝에 덧붙인다**. 이미 쓴 기록도 고치지 않는다 — 틀린 게 드러나면 새 기록에서 정정한다.

```markdown
---

## 작업 기록

### YYYY-MM-DD — <로드맵 N단계: 한 줄>
- 대응 질문: 원본 "목적"의 질문 번호
- 코드: <repo> @ <commit 해시>
- 한 것 / 설계 결정(트레이드오프 → 선택 → 이유)
- 도식: 구조·알고리즘 (ASCII — 단계마다 1개 이상)
- 확인: 테스트·변이·측정 결과 (수치는 실제 결과만 — 추정 금지, 없으면 "미측정")
- 배운 개념 / 틀렸던 이해 (오답 노트 요약)
- cs/ 추출 후보
```

- `## 작업 기록` 헤더는 첫 기록 때 한 번만 붙인다.
- 측정 단계(벤치마크)가 끝나면 README 끝에 `## 종합 결론`을 추가한다.
