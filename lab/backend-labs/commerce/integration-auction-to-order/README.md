# 09. Integration Scenario B — Auction to Order

경매 마감 순간의 입찰 폭주가 알림 · 주문 · 결제 · 포인트로 번질 때 드러나는
알림 폭주 / 낙찰 승계 충돌 / 결제 기한 경합을 검증하는 통합 실험

## Flow

```
Client
  ↓
Bid API ──────────────────────── (05) 입찰 경합
  ↓
Outbid Event → 상회 입찰 알림 ── (06) 알림 (입찰 1건당 알림 1건)
  ↓
Auction Close ────────────────── (05) 마감 판정 / 연장 규칙
  ↓
Winner Confirm → Order 생성 ──── (03) 주문 (결제 기한 24시간)
 ├── Point Use ──────────────── (04) 포인트
 └── Card Payment ───────────── (02) 결제
        ↓
  미결제 시 → 차순위 승계 또는 재경매
  ↓
Auction Result Cache ─────────── (07) 경매 현재가 조회 캐시
```

## Load Baseline

기준은 05. Auction Lab을 따른다.

| 단계 | 부하 (파생값) | 도출 근거 |
|------|-------------|---------|
| 동시 진행 경매 | 1,000개 + 핫 경매 1개 | 05 Lab 기준 |
| 핫 경매 입찰 | 입찰의 10%가 마지막 10초에 집중 | 경매 연구 관찰을 참고한 설계값 |
| 상회 입찰 알림 | 수락된 입찰 수와 동일 | 입찰 1건 = 직전 최고가 입찰자 1명에게 알림 |
| 현재가 조회 | 참여자 10,000명 × 1초 주기 = 10,000 RPS | 마감 직전 새로고침 가정 |
| 낙찰 후 주문 | 경매당 1건 | |
| 미결제 → 차순위 승계 | 낙찰의 10% | 05 Lab 변수 |

## Questions (통합에서만 생기는 문제)

1. 마감 10초 전 입찰 폭주가 상회 알림 폭주로 번지면, 알림이 마감 이후에 도착하지 않는가?
2. 연장 마감 규칙이 알림 지연과 만나면 입찰자가 연장 사실을 모른 채 끝나지 않는가?
3. 차순위에게 승계하는 중에 원 낙찰자의 결제가 뒤늦게 성공하면?
4. 현재가 캐시가 몇 초 늦을 때 사용자는 이미 진 입찰을 계속 시도하는가?
5. 낙찰 결제 기한 만료와 결제 승인이 동시에 일어나면?
6. 포인트로 일부 결제한 낙찰이 취소되면 포인트 환원은 어떻게 되는가?

| 시나리오 | 주입 내용 | 관찰 포인트 |
|---------|---------|-----------|
| S1. 정상 | 없음 | 마감 판정 정확도, 알림 지연 |
| S2. 알림 지연 | 발송사 p99 5s | 마감 이후 도착한 상회 알림 비율 |
| S3. 캐시 지연 | 현재가 반영 3s 지연 | 무효 입찰 시도 증가율 |
| S4. 결제 기한 경합 | 기한 만료 1초 전 결제 승인 | 차순위 승계와 결제 충돌 |
| S5. 시계 오차 | 서버 간 ±200ms | 마감 판정 불일치 |
