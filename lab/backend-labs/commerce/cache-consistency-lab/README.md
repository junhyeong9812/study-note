## Questions

1. DB는 갱신됐는데 캐시는 옛 값이라면? 몇 ms까지 허용할까?
2. 인기 키가 만료되는 순간 요청 1만 건이 동시에 몰리면?
3. Redis가 죽으면 DB가 전체 조회 트래픽을 버틸 수 있나?
4. 캐시 갱신과 DB 쓰기의 순서가 뒤바뀌면?
5. Cache-aside, Write-through, CDC 기반 무효화 중 무엇을 쓸까?
6. 데이터마다 허용 가능한 신선도가 다르다면? (좌석맵 vs 상품 상세 vs 포인트 잔액)

## Architecture

```
Client
  ↓
Query API
  ↓
Cache Layer (전략 비교)
 ├── A. Cache-aside + TTL
 ├── B. Write-through
 └── C. CDC(DB 변경 로그) 기반 무효화
        ↓ miss
   Stampede 방어 (락 / 조기 갱신 / 요청 병합)
        ↓
       DB

Command API → DB → (B/C) Cache 갱신 또는 무효화
Fallback: Redis 장애 시 DB 직접 조회 + 부하 차단기
```
