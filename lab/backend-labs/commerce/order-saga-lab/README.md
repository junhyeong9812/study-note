# 03. Order Saga Lab

재고 · 쿠폰 · 포인트 · 결제를 하나의 주문으로 묶을 때 발생하는
부분 실패 / 보상 누락 / 초과 판매 / 중간 상태 방치를 다룬 실험 프로젝트

**채택 기준 (제안값)**: 일반 주문 200 TPS 상시 + 한정 특가(재고 1,000개)에 1분간 5만 건 요청 (경쟁률 50:1)

## Questions

1. 재고는 차감됐는데 쿠폰 사용이 실패했다면?
2. 포인트는 차감됐는데 카드 결제가 실패했다면? (복합결제)
3. 결제는 성공했는데 그 사이 재고가 바닥났다면?
4. 보상 트랜잭션 자체가 실패했다면?
5. 주문이 PENDING 상태로 영원히 남는다면?
6. 재고는 주문 시점에 잡을까, 결제 시점에 잡을까?
7. Orchestration과 Choreography 중 무엇이 장애 추적에 유리한가?

## Architecture

```
Client
  ↓
Order API
  ↓
Order Orchestrator (상태 머신)
 ├── 1. Inventory  : 재고 예약
 ├── 2. Coupon     : 쿠폰 사용
 ├── 3. Point      : 포인트 차감 (→ 04. Ledger Lab)
 └── 4. Payment    : 카드 결제 (→ 02. Payment Lab)
        ↓
  실패 시 역순 보상 (4 → 1)

Timeout Scanner → PENDING 주문 정리
```
