## 한눈에 — 쉽게 말하면

**`%` 는 「월급의 몇 퍼센트」로 정하는 예산이다.**
「월급의 30% 를 저금한다」고 정해 두면, 월급이 바뀔 때 저금액도 저절로 따라 바뀐다.
그런데 어떤 항목은 월급이 아니라 다른 돈을 기준으로 삼는다.
예를 들어 경조사비는 「지난달 경조사비의 150%」처럼 따로 정할 수 있다.
CSS 의 `%` 도 똑같은 구조다.
값 자체는 비율일 뿐이고, 무엇을 100 으로 삼는지는 속성마다 정해져 있다.

| 비유 | 실체 |
|---|---|
| 월급 | 부모 요소의 기준 길이(너비 · 높이 · 글자 크기) |
| 30% 같은 비율 | `50%` 같은 `%` 값 |
| 실제로 떼어 놓는 금액 | 브라우저가 계산한 실제 길이 |
| 항목마다 다른 기준 | 속성마다 다른 기준(`width` 는 부모 너비, `font-size` 는 부모 글자 크기) |

```text
부모 콘텐츠 너비 300px
├────────────────────────────────────────┤
├───────────────────┤                       width: 50%  → 150px
├─────────────────────────────┤             width: 75%  → 225px
├────────────────────────────────────────┤  width: 100% → 300px
```

## 이 주제가 답하려는 질문

1. `%` 는 무엇을 100 으로 놓고 계산하나?
2. 속성마다 기준이 어떻게 다른가 — 특히 `padding` · `margin` 은 무엇을 기준으로 하나?
3. `height: 100%` 는 왜 어떤 때는 먹히고 어떤 때는 안 먹히나?

## 동작 방식

### (1) `width` 의 `%` — 부모의 콘텐츠 너비가 기준

**언제 쓰나** — 부모 크기가 바뀌어도 「절반」「4분의 3」처럼 비율을 유지하고 싶을 때 쓴다.

```text
.parent { width: 300px; padding: 12px; }
.child  { width: 50%; }
        │
        ▼
기준 = 부모의 콘텐츠 너비 300px   (부모 padding 12px 은 기준에 들지 않는다)
        │
        ▼
자식 콘텐츠 너비 = 300 × 0.5 = 150px
```

- 부모가 `width: 300px` 으로 콘텐츠 너비를 정한다.
- 자식의 `width: 50%` 는 그 300px 을 100 으로 놓는다.
- 부모의 `padding` 은 콘텐츠 너비 바깥에 있으므로 기준에 더해지지 않는다.
- 그래서 자식의 콘텐츠 너비는 150px 이 된다.

> **콘텐츠 영역** — 박스에서 `padding` · `border` · `margin` 을 뺀 안쪽, 글자와 자식이 놓이는 자리.\
> 예: `width: 300px; padding: 12px` 인 박스의 콘텐츠 영역 너비는 300px 이다.

엄밀히 말하면 기준은 「부모」가 아니라 **포함 블록**이다.
보통의 흐름(문서에 차례로 쌓이는 블록)에서는 포함 블록이 곧 부모의 콘텐츠 영역이라, 「부모 기준」이라고 불러도 맞다.

> **포함 블록** — 자식의 `%` 크기와 위치를 계산할 때 기준으로 삼는 사각형.\
> 예: 보통 흐름의 `div` 안 `div` 라면 바깥 `div` 의 콘텐츠 영역이다.

### (2) `padding` · `margin` 의 `%` — 위아래도 언제나 부모의 너비가 기준

**언제 쓰나** — 부모 너비에 비례하는 여백을 줄 때 쓴다.

```text
.parent { width: 400px; height: 1000px; }
.child  { padding-top: 10%; margin-bottom: 5%; }
        │
        ▼
padding-top 은 「위쪽」이지만 기준 = 부모 너비 400px   (높이 1000px 이 아니다)
        │
        ▼
padding-top = 40px, margin-bottom = 20px
```

- `padding-top` 과 `margin-bottom` 은 세로 방향 여백이다.
- 그래도 `%` 의 기준은 부모의 높이가 아니라 부모의 **너비**다.
- 네 방향(`top` · `right` · `bottom` · `left`) 모두 같은 기준을 쓴다.
- 그래서 400px 의 10% 인 40px, 5% 인 20px 이 된다.

> **inline-size** — 글이 흘러가는 방향의 크기. 가로쓰기 문서에서는 너비와 같다.\
> 예: 보통의 한국어 · 영어 페이지에서 `inline-size` 는 `width` 다.

까닭은 두 가지로 풀 수 있다 (원본에 근거 없음 — 추론).
첫째, 네 방향이 같은 기준을 쓰면 `padding: 5%` 한 줄로 사방이 똑같은 여백이 된다.
둘째, 블록의 높이는 보통 내용으로 정해지는데, 내용 높이에 `padding` 이 들어가므로 세로 여백을 높이 기준으로 잡으면 「높이가 여백을 정하고 여백이 높이를 정하는」 고리가 생긴다.

### (3) `height` 의 `%` — 부모 높이가 명시돼 있어야 한다

**언제 쓰나** — 높이가 정해진 부모를 위아래로 꽉 채우거나 비율로 나눌 때 쓴다.

```text
경우 ①  .parent { height: 200px; }   .child { height: 100%; }
        → 기준 200px 이 있다 → 자식 높이 200px

경우 ②  .parent { /* height 없음 = auto */ }   .child { height: 100%; }
        → 부모 높이는 자식 내용으로 정해진다 → 기준이 정해지지 않는다
        → 자식의 height: 100% 는 auto 로 계산된다 → 자기 내용 높이만큼
```

- 경우 ①은 부모가 높이를 직접 밝혔으므로 100% 를 계산할 수 있다.
- 경우 ②에서 부모 높이는 「자식이 얼마나 큰가」로 정해진다.
- 자식은 「부모 높이의 100%」를 원하고, 부모는 「자식 높이」를 원하니 서로 기다리게 된다.
- 브라우저는 이 고리를 끊으려고 자식의 `height: 100%` 를 `auto` 처럼 다룬다.
- 그래서 자식은 자기 내용만큼의 높이를 갖는다.

> **명시적 높이** — 내용과 상관없이 정해진 높이. `200px` 처럼 고정 값이거나, 그 자신도 높이가 정해진 부모를 기준으로 한 `%` 다.\
> 예: `height: 200px` 은 명시적이고, `height` 를 안 쓴 `auto` 는 명시적이 아니다.

부모의 높이가 또 `%` 라면, 그 부모의 부모에도 높이가 있어야 한다.
이 사슬은 고정 높이를 가진 조상을 만날 때까지 거슬러 올라간다.

### (4) `font-size` 의 `%` — 부모의 글자 크기가 기준

**언제 쓰나** — 부모 글자보다 조금 크게 · 작게처럼 상대적으로 키울 때 쓴다.

```text
.parent { font-size: 20px; }
.child  { font-size: 150%; }
.grand  { font-size: 150%; }   (.child 안의 손자)
        │
        ▼
child = 20 × 1.5 = 30px
grand = 30 × 1.5 = 45px      (부모인 child 의 30px 이 기준)
```

- `font-size` 의 `%` 는 너비 · 높이가 아니라 부모의 계산된 글자 크기를 기준으로 한다.
- 자식이 30px 이 되면 손자는 그 30px 을 다시 기준으로 삼는다.
- 그래서 겹겹이 쓰면 비율이 곱해진다.

## 문법 — 형태와 규칙

```html demo
<div class="p">
  <div class="a">50%</div>
  <div class="b">100%</div>
</div>
<style>
  .p { width: 200px; padding: 8px; background: #f1f5f9; }
  .a { width: 50%;  background: #3b82f6; color: white; }
  .b { width: 100%; background: #ef4444; color: white; font-size: 120%; }
</style>
```

> **보이는 것** — 회색 상자 안에 파란 막대(100px)와 그 아래 빨간 막대(200px)가 쌓이고, 빨간 막대의 글자가 조금 더 크다 (코드에서 읽은 것 — 렌더 실측 아님)

- 꼴은 `<number>%` — 숫자 바로 뒤에 `%` 를 붙인다.
- 숫자와 `%` 사이를 띄우지 않는다(`50 %` 는 잘못된 값이다).
- 숫자에 소수를 쓸 수 있다(예: `33.333%`).
- 값은 비율일 뿐이고, 실제 길이는 속성마다 정해진 기준과 곱해서 나온다.

| 속성 | `%` 의 기준 |
|---|---|
| `width` | 부모(포함 블록)의 콘텐츠 너비 |
| `height` | 부모의 높이 — 부모 높이가 명시적일 때만, 아니면 `auto` |
| `font-size` | 부모의 `font-size` |
| `padding` (네 방향 모두) | 부모의 너비(`inline-size`) |
| `margin` (네 방향 모두) | 부모의 너비(`inline-size`) |

## 어디서 틀리나

### 1. 「`padding-top: 10%` 는 높이의 10%」라고 생각한다

`padding` 과 `margin` 의 `%` 는 방향과 상관없이 언제나 부모의 너비(`inline-size`) 기준이다.
부모가 가로 400px · 세로 1000px 이면 `padding-top: 10%` 는 100px 이 아니라 40px 이다.

### 2. `height: 100%` 를 줬는데 높이가 늘지 않는다

부모에 명시적 높이가 없으면 `height: 100%` 는 `auto` 처럼 동작한다.
부모(필요하면 그 위 조상까지)에 높이를 정해 줘야 한다.
페이지 전체를 채우려 할 때 `html` · `body` 에 높이가 없어 막히는 경우가 흔하다.

### 3. `width: 100%` 에 `padding` 을 더하면 부모 밖으로 넘친다

원본 주석은 `.child-100` 을 「부모 300px의 100% = 300px」이라고 적는다.
이 300px 은 자식의 **콘텐츠 너비**이고, 박스 전체 너비가 아니다.
기본 상자 모델에서는 `width` 가 콘텐츠 영역만 정하고, `padding` 은 그 바깥에 더해진다.
그래서 `.child-100` 의 테두리 바깥 너비는 300 + 12 + 12 = 324px 이다.
이 박스는 부모 콘텐츠 영역의 왼쪽 끝에서 시작하므로, 오른쪽으로 부모의 `padding` 12px 을 다 덮고도 12px 을 더 나간다.
`.child-50` 도 같은 셈으로 콘텐츠 150px + 여백 24px = 174px 이다.
`padding` 까지 포함해 `width` 를 맞추려면 `box-sizing: border-box` 를 준다.

> **상자 모델** — 박스를 콘텐츠 · `padding` · `border` · `margin` 네 겹으로 보는 방식.\
> 예: 기본값 `box-sizing: content-box` 에서는 `width` 가 가장 안쪽 콘텐츠만 정한다.

### 4. 부모의 `padding` 까지 기준에 넣는다

`width` 의 `%` 는 부모의 콘텐츠 영역을 기준으로 한다.
`.parent { width: 300px; padding: 12px; }` 의 자식에게 기준은 324px 이 아니라 300px 이다.

### 5. `font-size` 의 `%` 를 겹쳐 쓰고 놀란다

`font-size: 150%` 를 중첩된 요소마다 쓰면 1.5 × 1.5 = 2.25배처럼 곱해진다.
기준이 「부모의 글자 크기」이고, 부모 글자 크기가 이미 커져 있기 때문이다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `width` 의 `%` 는 포함 블록의 너비가 기준이다 | CSS 명세 |
| `padding` · `margin` 의 `%` 는 포함 블록의 `inline-size` 가 기준이다 | CSS 명세 |
| 부모 높이가 명시적이지 않으면 `height` 의 `%` 는 `auto` 로 계산된다 | CSS 명세 (절대 위치 요소 같은 예외는 「더 들어가면」) |
| `font-size` 의 `%` 는 부모의 계산된 `font-size` 가 기준이다 | CSS 명세 |
| 33.333% 처럼 소수 픽셀이 나올 때 화면 픽셀에 어떻게 맞추나 | 브라우저 구현 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 부모 크기가 바뀌어도 비율을 유지하는 너비 | `width: 50%` | 고정 `px` |
| 크기가 변하면 안 되는 테두리 · 아이콘 | `px` | `%` |
| 높이가 정해지지 않은 부모를 채우는 높이 | 부모에 높이를 먼저 정한 뒤 `%` | 부모 높이 없이 `height: 100%` |
| 부모 너비에 비례하는 여백 | `padding` · `margin` 의 `%` | 「세로 여백은 높이 기준」이라 믿고 쓰는 `%` |
| `padding` 이 있는 박스를 부모 너비에 딱 맞추기 | `width: 100%` + `box-sizing: border-box` | 기본 `content-box` 그대로의 `width: 100%` |

## 핵심 문장

1. **`%` 는 비율일 뿐이고, 무엇을 100 으로 삼는지는 속성이 정한다.**
2. **`width` 는 부모 콘텐츠 너비, `font-size` 는 부모 글자 크기가 기준이다.**
3. **`padding` · `margin` 의 `%` 는 위아래까지 언제나 부모의 너비 기준이다.**
4. **`height` 의 `%` 는 부모 높이가 명시돼 있어야 먹힌다 — 아니면 `auto` 가 된다.**
5. **기본 상자 모델에서 `width: 100%` 는 콘텐츠만 채우고, `padding` 은 그 위에 더해진다.**

## 관련 자료

- `px` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `vw` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `vh` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- 원본: study-site 항목 데이터 `data/css/units-values.json` 의 `percent`

## 용어 풀이

- **`%`(퍼센트)** — 기준 길이를 100 으로 놓은 비율 단위.
- **부모 요소** — 어떤 요소를 바로 감싸는 요소.
- **포함 블록** — 자식의 `%` 크기와 위치를 계산할 때 기준으로 삼는 사각형.
- **콘텐츠 영역** — 박스에서 `padding` · `border` · `margin` 을 뺀 안쪽.
- **inline-size** — 글이 흘러가는 방향의 크기. 가로쓰기에서는 너비.
- **명시적 높이** — 내용과 상관없이 미리 정해진 높이.
- **`auto`** — 브라우저가 내용과 맥락으로 크기를 정하게 맡기는 값.
- **상자 모델** — 박스를 콘텐츠 · `padding` · `border` · `margin` 네 겹으로 보는 방식.
- **`box-sizing`** — `width` · `height` 가 박스의 어느 겹까지 정하는지 고르는 속성.

## 더 들어가면

- `position: absolute` 인 요소의 포함 블록은 가장 가까운 「위치가 지정된」 조상의 `padding` 영역이다. 그래서 이때는 부모 높이가 `auto` 여도 `height: %` 가 계산될 수 있다 (확인 필요).
- 세로쓰기(`writing-mode: vertical-rl` 등)에서는 `inline-size` 가 세로 길이가 되므로 `padding` · `margin` 의 `%` 기준도 그쪽으로 바뀐다 (확인 필요).
- `line-height` 의 `%` 는 부모가 아니라 요소 자신의 `font-size` 기준이다 (확인 필요).
- `transform: translate(50%)` 의 `%` 는 부모가 아니라 요소 자신의 박스 크기 기준이다 (확인 필요).
- `margin` 은 음수 `%` 를 쓸 수 있지만 `width` · `padding` 의 음수는 잘못된 값으로 버려진다 (확인 필요).
- 부모 너비 기준인 `padding-top: 56.25%` 로 16:9 비율 상자를 만드는 옛 기법이 있다. 요즘은 `aspect-ratio` 속성으로 같은 일을 한다 (확인 필요).
- flex · grid 아이템의 높이 `%` 는 부모가 늘어난(stretch) 높이를 명시적인 것으로 볼 때가 있어 블록 흐름과 다르게 보일 수 있다 (확인 필요).
