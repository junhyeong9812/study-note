## 한눈에 — 쉽게 말하면

**fluid spacing 은 「늘었다 줄었다 하는 고무줄인데, 양 끝에 매듭이 있는 것」이다.**
고무줄은 당기는 만큼 길어지지만, 매듭 때문에 어느 길이 아래로는 줄지 않고 어느 길이 위로는 늘지 않는다.
CSS 의 `clamp()` 로 만든 여백도 똑같은 구조다.
화면(뷰포트)이 넓어지면 여백이 함께 늘고, 정해 둔 최솟값과 최댓값에서 멈춘다.

| 비유 | 실체 |
|---|---|
| 고무줄 | `padding` · `gap` · `margin` 같은 여백 값 |
| 당기는 힘 | 뷰포트 폭(`vw` 단위) |
| 아래쪽 매듭 | `clamp()` 의 첫째 값(최솟값) |
| 위쪽 매듭 | `clamp()` 의 셋째 값(최댓값) |
| 고무줄의 탄성 | 가운데 값(`0.5rem + 1.5vw` 처럼 고정값 + 뷰포트 비례값) |

```text
 여백
  ▲
MAX ┤                    ●━━━━━━━━━━   ← 위쪽 매듭: 더 넓어져도 그대로
    │                 ╱
    │              ╱      ← 가운데 값: 뷰포트에 비례해 부드럽게 증가
    │           ╱
MIN ┤━━━━━━━━●              ← 아래쪽 매듭: 더 좁아져도 그대로
    └────────┴──────────┴──────────▶ 뷰포트 폭
```

## 이 주제가 답하려는 질문

1. 미디어 쿼리(브레이크포인트) 없이 여백이 화면 크기에 맞춰 변하게 하려면 어떻게 쓰나?
2. 그 여백이 너무 작아지거나 너무 커지지 않게 막는 장치는 무엇인가?
3. 여러 곳의 여백을 일관되게 유지하려면 어떻게 정리하나?

## 동작 방식

### (1) `clamp()` 하나로 여백 한 개를 유동화한다

**언제 쓰나** — 하나의 `padding` · `gap` · `margin` 이 화면 폭에 따라 부드럽게 커지고 작아지길 원할 때 쓴다.

```text
입력:  .fs-card { padding: clamp(0.75rem, 0.5rem + 1vw, 1.5rem); }

무엇이 일어나나 (1rem = 16px 로 가정):
  가운데 값 = 8px + (뷰포트 폭 × 1%)
  ┌──────────────┬───────────────┬───────────┐
  │ 뷰포트 폭     │ 가운데 값       │ 실제 값    │
  ├──────────────┼───────────────┼───────────┤
  │ 300px        │ 8 + 3  = 11px │ 12px(최소) │
  │ 400px        │ 8 + 4  = 12px │ 12px      │
  │ 1000px       │ 8 + 10 = 18px │ 18px      │
  │ 1600px       │ 8 + 16 = 24px │ 24px      │
  │ 2000px       │ 8 + 20 = 28px │ 24px(최대) │
  └──────────────┴───────────────┴───────────┘

결과:  400px ~ 1600px 사이에서는 직선으로 늘고, 그 바깥에서는 멈춘다
```

- 브라우저는 가운데 값을 지금의 뷰포트 폭으로 계산한다.
- 그 값이 최솟값보다 작으면 최솟값을 쓴다.
- 그 값이 최댓값보다 크면 최댓값을 쓴다.
- 그 사이면 가운데 값을 그대로 쓴다.
- 뷰포트 폭은 연속으로 변하므로 여백도 계단 없이 연속으로 변한다.

> **`clamp(MIN, VAL, MAX)`** — 가운데 값 `VAL` 을 `MIN` 과 `MAX` 사이로 묶는 CSS 함수다. 명세상 `max(MIN, min(VAL, MAX))` 와 같다.\
> 예: `clamp(1rem, 5vw, 2rem)` 은 `5vw` 를 1rem~2rem 안에 가둔다.

> **`vw`** — 뷰포트 폭의 1% 를 1 로 하는 길이 단위다.\
> 예: 뷰포트 폭 1000px 이면 `1vw` = 10px.

> **`rem`** — 루트 요소(`html`)의 글꼴 크기를 1 로 하는 길이 단위다.\
> 예: 루트 글꼴이 16px 이면 `0.75rem` = 12px.

### (2) 가운데 값이 「고정값 + 비례값」인 까닭

**언제 쓰나** — 가운데 값을 어떻게 짤지 정할 때 이 구조를 따른다.

```text
입력:  0.5rem + 1.5vw

무엇이 일어나나:
  0.5rem  → 화면이 아무리 좁아도 깔리는 바닥 (루트 글꼴 크기를 따른다)
  1.5vw   → 화면 폭에 비례하는 기울기 (뷰포트 1px 늘 때 0.015px 증가)

결과:  y = 8 + 0.015 × (뷰포트 폭)  꼴의 직선
```

- `rem` 부분은 직선의 출발 높이를 정한다.
- `vw` 부분은 직선의 기울기를 정한다.
- 두 값을 바꾸면 「몇 px 폭에서 최솟값에 닿고, 몇 px 폭에서 최댓값에 닿는지」가 바뀐다.
- 가운데 값에 `rem` 을 섞으면 사용자가 브라우저 글꼴 크기를 키울 때 여백도 함께 커진다.
- `vw` 만 쓰면 글꼴 설정과 상관없이 화면 폭만 따른다.

예제의 여백 넷을 같은 방식으로 풀면 이렇다(1rem = 16px 가정).

| 대상 | 식 | 범위 | 최소에 닿는 폭 | 최대에 닿는 폭 |
|---|---|---|---|---|
| `.fs-section` 의 `gap` | `clamp(0.75rem, 0.5rem + 1.5vw, 2rem)` | 12 ~ 32px | 약 267px | 1600px |
| `.fs-section` 의 `padding` | `clamp(1rem, 0.5rem + 2vw, 2.5rem)` | 16 ~ 40px | 400px | 1600px |
| `.fs-card` 의 `padding` | `clamp(0.75rem, 0.5rem + 1vw, 1.5rem)` | 12 ~ 24px | 400px | 1600px |
| `.fs-card-title` 의 `margin-bottom` | `clamp(4px, 2px + 0.5vw, 10px)` | 4 ~ 10px | 400px | 1600px |

닿는 폭은 「(경계값 − 고정값) ÷ (vw 계수 ÷ 100)」으로 구한다.
예: 카드 패딩의 최대 → (24 − 8) ÷ 0.01 = 1600px.

### (3) 커스텀 프로퍼티로 간격 스케일을 만든다

**언제 쓰나** — 여백이 여러 곳에 흩어져 있어 크기 단계를 통일하고 싶을 때 쓴다.

```text
입력:
  --space-s: clamp(0.5rem, 0.3rem + 1vw,   1rem);   →  8 ~ 16px
  --space-m: clamp(1rem,   0.7rem + 1.5vw, 2rem);   → 16 ~ 32px
  --space-l: clamp(1.5rem, 1rem + 2.5vw,   3rem);   → 24 ~ 48px
  .section { padding: var(--space-l); gap: var(--space-m); }

무엇이 일어나나:
  var(--space-l) 자리에 clamp(...) 식이 그대로 들어간다
  → 그 자리에서 지금의 뷰포트 폭으로 계산된다

결과:  모든 「큰 여백」은 같은 l, 모든 「중간 여백」은 같은 m 을 따른다
```

- 간격 크기를 s · m · l 같은 몇 단계로 정해 두면 여백마다 식을 새로 짤 필요가 없다.
- 단계를 고치면 그 단계를 쓰는 모든 곳이 한꺼번에 바뀐다.
- 예제 스케일은 셋 다 뷰포트 320px 에서 최솟값에 닿는다(예: `--space-s` → 4.8 + 3.2 = 8px).

> **커스텀 프로퍼티** — `--이름: 값;` 으로 정의하고 `var(--이름)` 으로 꺼내 쓰는 CSS 변수다.\
> 예: `--space-m: 1rem;` 후 `gap: var(--space-m);`.

> **간격 스케일(spacing scale)** — 문서 전체에서 쓸 여백 크기를 몇 단계로 정해 둔 목록이다.\
> 예: s = 8~16px, m = 16~32px, l = 24~48px.

### (4) 미디어 쿼리와의 차이 — 계단 대 비탈

**언제 쓰나** — 브레이크포인트 방식과 fluid 방식 중 무엇을 쓸지 고를 때 비교한다.

```text
미디어 쿼리:                       clamp():
 여백                               여백
  ▲        ┌────                     ▲          ╱────
  │   ┌────┘                          │       ╱
  │───┘                               │────╱
  └──┬────┬──▶ 폭                      └────────────▶ 폭
     768  1024                       (중간 지점이 없다)
```

- 미디어 쿼리는 정해 둔 폭에서 값이 한 번에 뛴다.
- `clamp()` 는 모든 폭에서 값이 조금씩 바뀌므로 뛰는 지점이 없다.
- 그래서 원본은 이것을 「브레이크포인트 없이 부드러운 반응형 간격」이라 부른다.

> **브레이크포인트** — 미디어 쿼리로 스타일을 바꾸는 기준 화면 폭이다.\
> 예: `@media (min-width: 768px) { … }` 의 768px.

### (5) 줄바꿈은 `clamp()` 가 아니라 flex 가 맡는다

**언제 쓰나** — 예제에서 카드가 다음 줄로 내려가는 까닭을 볼 때 쓴다.

```text
입력:
  .fs-section { display: flex; flex-wrap: wrap; gap: clamp(...); }
  .fs-card    { flex: 1; min-width: 120px; }

무엇이 일어나나:
  카드는 남는 폭을 같은 비율로 나눠 가진다 (flex: 1)
  카드 하나가 120px 아래로 줄어야 할 상황이면 → 다음 줄로 넘어간다 (flex-wrap: wrap)

결과:  여백은 clamp 가 부드럽게, 배치는 flex 가 줄 단위로 바꾼다
```

- `clamp()` 는 간격의 크기만 바꾼다.
- 카드를 몇 줄로 놓을지는 `flex-wrap` 과 `min-width` 가 정한다.
- 다만 `gap` 이 커지면 한 줄에 필요한 폭도 커지므로, 줄바꿈이 일어나는 폭에 간접적으로 영향을 준다.

> **`flex-wrap: wrap`** — flex 아이템이 한 줄에 다 들어가지 않으면 다음 줄로 넘기게 하는 속성이다.\
> 예: 카드 셋이 좁은 화면에서 2개 + 1개로 나뉜다.

## 문법 — 형태와 규칙

```html demo
<div class="box">
  <div>A</div><div>B</div><div>C</div>
</div>
<style>
  :root { --space-m: clamp(1rem, 0.7rem + 1.5vw, 2rem); }
  .box { display: flex; gap: var(--space-m); padding: clamp(1rem, 0.5rem + 2vw, 2.5rem); background: #f1f5f9; }
  .box > div { flex: 1; padding: clamp(0.75rem, 0.5rem + 1vw, 1.5rem); background: white; }
</style>
```

> **보이는 것** — 회색 상자 안에 흰 칸 셋이 가로로 놓이고, 창 폭을 바꾸면 칸 사이와 칸 안쪽 여백이 함께 늘고 준다. (코드에서 읽은 것 — 렌더 실측 아님)

- 꼴은 `clamp(최솟값, 가운데 값, 최댓값)` 이다.
- 가운데 값에는 `0.5rem + 1.5vw` 처럼 덧셈을 바로 쓸 수 있다(`calc()` 로 감싸지 않아도 된다).
- 덧셈 · 뺄셈 기호 양옆에는 공백이 있어야 한다(`0.5rem+1.5vw` 는 잘못된 식이다).
- 최솟값 · 최댓값은 보통 `rem` 으로 쓴다(예제의 `margin-bottom` 처럼 `px` 도 쓸 수 있다).
- `gap` · `padding` · `margin` 처럼 길이를 받는 속성이면 어디든 쓸 수 있다.
- 커스텀 프로퍼티에 담으면 `var()` 로 꺼낸 자리에서 계산된다.
- 최솟값이 최댓값보다 크면 `max(MIN, min(VAL, MAX))` 정의에 따라 최솟값이 이긴다.

| 예제의 값 | 범위(1rem = 16px) | 쓰인 곳 |
|---|---|---|
| `clamp(0.75rem, 0.5rem + 1.5vw, 2rem)` | 12 ~ 32px | 카드 사이 `gap` |
| `clamp(1rem, 0.5rem + 2vw, 2.5rem)` | 16 ~ 40px | 섹션 `padding` |
| `clamp(0.75rem, 0.5rem + 1vw, 1.5rem)` | 12 ~ 24px | 카드 `padding` |
| `clamp(4px, 2px + 0.5vw, 10px)` | 4 ~ 10px | 제목 아래 `margin-bottom` |
| `--space-s` | 8 ~ 16px | 스케일(코드 상자에 보이는 예시) |
| `--space-m` | 16 ~ 32px | 스케일 |
| `--space-l` | 24 ~ 48px | 스케일 |

## 어디서 틀리나

### 1. 간격 식을 여기저기 따로 짜면 일관성이 깨진다

원본 팁: CSS 커스텀 프로퍼티로 spacing scale 을 정의하면 일관된 간격 시스템을 유지할 수 있다.
예제 데모의 실제 CSS 는 스케일을 쓰지 않고 여백마다 식을 따로 적었다.
그래서 `gap` 은 약 267px 에서, 나머지는 400px 에서 최솟값에 닿는다 — 바닥에 닿는 폭이 서로 다르다.
스케일(`--space-s/m/l`)은 코드 상자에 글로 보여 줄 뿐 데모에 적용되지 않았다는 점도 알아 두라.

### 2. 식을 손으로 짜기 번거롭다

원본 팁: utopia.fyi 에서 spacing scale 도 자동 생성할 수 있다.
최솟값 · 최댓값과 「어느 폭에서 어느 값」을 정하면 가운데 값의 `rem` · `vw` 계수를 계산해 주는 도구다.
손으로 짤 때는 (2) 의 「닿는 폭」 공식으로 거꾸로 확인하면 된다.

### 3. 한 속성만 유동이면 나머지가 어긋난다

원본 팁: `gap` · `padding` · `margin` 모두에 `clamp()` 를 적용하면 레이아웃이 자연스럽게 축소/확대된다.
`padding` 만 유동이고 `gap` 이 고정이면, 넓은 화면에서 안쪽은 넉넉한데 카드 사이만 비좁아 보인다.
예제는 섹션 `gap` · 섹션 `padding` · 카드 `padding` · 제목 `margin-bottom` 넷을 다 유동으로 만들었다.

### 4. `vw` 는 컨테이너가 아니라 뷰포트 기준이다

카드가 좁은 사이드바 안에 있어도, 창이 넓으면 `vw` 값은 크다.
즉 「이 상자의 폭」이 아니라 「브라우저 창의 폭」을 따른다.
좁은 상자 안에서 여백이 지나치게 커 보이면 이 까닭이다.

### 5. `px` 로 묶으면 글꼴 설정을 따르지 않는다

예제의 `margin-bottom: clamp(4px, 2px + 0.5vw, 10px)` 은 전부 `px` 과 `vw` 다.
사용자가 브라우저 기본 글꼴을 키워도 이 여백의 범위는 그대로다.
나머지 여백은 `rem` 을 써서 루트 글꼴 크기를 따른다.

### 6. 주석의 px 환산은 「1rem = 16px」 가정이다

원본 주석의 「12px ~ 32px」 같은 숫자는 루트 글꼴이 16px 일 때의 환산이다.
루트 글꼴이 바뀌면 `rem` 부분이 바뀌므로 범위도 바뀐다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `clamp(MIN, VAL, MAX)` 는 `max(MIN, min(VAL, MAX))` 와 같다 | CSS 명세(Values and Units) |
| `1vw` 는 뷰포트 폭의 1% 다 | CSS 명세 |
| `1rem` 은 루트 요소의 글꼴 크기다 | CSS 명세 |
| `1rem` = 16px | 브라우저 기본 설정일 뿐 — 사용자가 바꿀 수 있다 |
| 주석의 「12px ~ 32px」 등 환산값 | 위의 16px 가정에 기댄 계산 |
| utopia.fyi 가 스케일을 만들어 준다 | 제3자 도구(CSS 와 무관) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 화면 폭에 따라 여백이 연속으로 변하길 원함 | `clamp()` + `rem` · `vw` | 미디어 쿼리 여러 개로 계단 만들기 |
| 여백 단계를 문서 전체에서 통일 | 커스텀 프로퍼티 스케일 | 여백마다 따로 짠 식 |
| 특정 폭에서 배치 자체를 바꿔야 함(열 수 변경 등) | 미디어 쿼리 · flex 줄바꿈 | `clamp()` 만으로 해결하려 하기 |
| 상자 자신의 폭에 맞춰야 함 | (확인 필요 — 이 항목의 범위 밖) | `vw` 기반 식 |
| 사용자 글꼴 설정을 따라야 함 | `rem` 섞은 식 | `px` · `vw` 만 쓴 식 |

## 핵심 문장

1. **`clamp(MIN, VAL, MAX)` 는 가운데 값을 양 끝 사이에 가둔다** — 그 사이에서는 뷰포트를 따라 연속으로 변한다.
2. **가운데 값은 「`rem` 바닥 + `vw` 기울기」인 직선이다** — 두 계수가 최솟값 · 최댓값에 닿는 폭을 정한다.
3. **커스텀 프로퍼티로 간격 스케일을 만들면 여백이 일관된다** — 한 곳을 고치면 모두 따라온다.
4. **`gap` · `padding` · `margin` 을 함께 유동화해야 레이아웃이 고르게 줄고 는다.**
5. **여백의 크기는 `clamp()` 가, 카드의 줄바꿈은 flex 가 맡는다.**

## 용어 풀이

- **fluid spacing(유동적 간격)** — 뷰포트 폭에 따라 연속으로 변하는 여백.
- **`clamp()`** — 값을 최솟값과 최댓값 사이로 묶는 CSS 함수.
- **뷰포트** — 웹 페이지가 그려지는 브라우저 창의 영역.
- **`vw`** — 뷰포트 폭의 1% 단위.
- **`rem`** — 루트 요소 글꼴 크기 단위.
- **커스텀 프로퍼티** — `--이름` 으로 정의하고 `var()` 로 쓰는 CSS 변수.
- **`var()`** — 커스텀 프로퍼티의 값을 꺼내는 함수.
- **간격 스케일** — 여백 크기를 몇 단계로 정한 목록.
- **브레이크포인트** — 미디어 쿼리가 스타일을 바꾸는 기준 폭.
- **미디어 쿼리** — 화면 조건에 따라 스타일을 적용하는 `@media` 규칙.
- **`gap`** — flex · grid 아이템 사이의 간격.
- **`flex-wrap`** — flex 아이템을 여러 줄로 넘길지 정하는 속성.
- **`flex: 1`** — 남는 공간을 다른 아이템과 같은 비율로 나눠 갖게 하는 단축 속성.

## 더 들어가면

- 같은 `clamp()` 패턴을 `font-size` 에 쓰면 「fluid typography」라 부른다 — 글자 크기와 여백 스케일을 같은 폭 범위로 맞추면 리듬이 맞는다. (확인 필요)
- `vw` 는 세로 스크롤바 폭을 포함한 뷰포트 기준이라, 스크롤바가 있는 환경에서 `100vw` 가 실제 내용 폭보다 넓을 수 있다. (확인 필요)
- 상자 자신의 폭을 기준으로 하려면 컨테이너 쿼리 단위(`cqi` 등)를 `vw` 대신 쓸 수 있다. (확인 필요)
- 브라우저 확대(zoom)에서 `vw` 만 쓴 값은 기대만큼 커지지 않을 수 있어, 접근성 지침에서는 `rem` 을 섞으라고 권하는 글이 많다. (확인 필요)
- `clamp()` 는 최근 주요 브라우저가 대부분 지원한다고 알려져 있다. (확인 필요 — 지원 범위 수치는 이 문서가 확인하지 않았다)
