# css/responsive/13 — Viewport Units for Full-screen — 정리 (힌트)

> 출처 — study-site 항목 `css/viewport-units-fullscreen`(항목 데이터 `data/css/responsive.json`) · 정답 코드 study-practice `css/responsive/reference/viewport-units-fullscreen.html`\
> 집필 — `claude-opus-5-5` 가 원본 재료를 뼈대로 쓴 **검수 전 초안**이다(2026-11-28).\
> 실행 — 실행하지 않음 — 브라우저 화면에서 결과를 보는 예제다 — 글로 옮길 출력이 없다.

## 한눈에 — 쉽게 말하면

**`100vh` 는 「블라인드를 다 걷었을 때 잰 창문 높이」에 맞춰 자른 포스터다.**
버스 창문 위쪽에 블라인드가 내려와 있으면 보이는 창은 그만큼 짧아진다.
그런데 포스터는 블라인드가 걷혔을 때의 창 높이로 잘라 두었기 때문에 아래쪽이 창틀 밖으로 밀려 보이지 않는다.
모바일 브라우저의 주소창과 `100vh` 도 똑같은 구조다.
주소창이 블라인드이고, `100vh` 로 높이를 준 요소가 포스터다.
`svh` · `lvh` · `dvh` 는 「어느 순간의 창 높이로 잴지」를 골라 주는 새 자다.

| 비유 | 실체 |
|---|---|
| 버스 창문 | 뷰포트(브라우저에서 페이지가 보이는 영역) |
| 위에서 내려오는 블라인드 | 모바일 주소창 |
| 창 높이에 맞춰 자른 포스터 | `height: 100vh` 인 요소 |
| 블라인드를 내린 창 높이 | `svh` (가장 작은 뷰포트) |
| 블라인드를 다 걷은 창 높이 | `lvh` (가장 큰 뷰포트) |
| 지금 이 순간의 창 높이 | `dvh` (동적 뷰포트) |

> **뷰포트** — 브라우저 창에서 페이지 내용이 실제로 그려지는 사각 영역이다.\
> 예: 모바일에서 주소창 아래부터 화면 아래 끝까지의 영역.

```text
 주소창 보임                 100vh 요소              100dvh 요소
┌──────────┐              ┌──────────┐            ┌──────────┐
│  주소창   │              │  주소창   │            │  주소창   │
├──────────┤              ├──────────┤            ├──────────┤
│          │              │ ████████ │            │ ████████ │
│ 보이는    │              │ ████████ │            │ ████████ │
│ 영역      │              │ ████████ │            │ ████████ │
└──────────┘              └──────────┘            └──────────┘
                            ████████  ← 잘림         딱 맞음
```

## 이 주제가 답하려는 질문

1. 모바일에서 `height: 100vh` 인 전체 화면 요소는 왜 아래가 잘리나?
2. `svh` · `lvh` · `dvh` 는 각각 어느 순간의 뷰포트를 기준으로 삼나?
3. `dvh` 를 모르는 구형 브라우저까지 어떻게 함께 챙기나?
4. 가로 방향에도 같은 단위가 있나?

## 동작 방식

### (1) `100vh` 가 모바일에서 잘리는 까닭

**언제 쓰나** — 히어로 섹션이나 풀스크린 모달처럼 「화면을 꽉 채우는」 요소를 만들 때 이 문제를 만난다.

```text
.hero { height: 100vh; }
   │
   ▼
모바일 Safari/Chrome 이 100vh 를 계산한다
   │  주소창이 차지하는 자리를 빼지 않은 높이
   ▼
주소창이 보이는 상태: 실제 보이는 영역 < 100vh
   │
   ▼
요소 아래쪽이 화면 밖으로 밀려 잘린다
```

- `100vh` 는 뷰포트 높이의 100% 라는 뜻이다.
- 원본 팁에 따르면 모바일 Safari/Chrome 에서 이 값은 주소창을 고려하지 않고 잡힌다.
- 그래서 주소창이 화면 위를 차지하고 있으면, 실제로 보이는 높이보다 요소가 더 크다.
- 넘친 만큼 아래쪽 콘텐츠가 보이지 않는다.

### (2) 세 가지 새 단위 — `svh` · `lvh` · `dvh`

**언제 쓰나** — 「주소창이 있을 때와 없을 때 중 어느 쪽에 맞출지」를 직접 고르고 싶을 때 쓴다.

```text
주소창 보임 ────────── 주소창 숨김
   │                       │
 svh 기준                 lvh 기준
 (가장 작은 뷰포트)       (가장 큰 뷰포트)
   │                       │
   └──── dvh: 지금 상태를 따라 둘 사이를 오간다 ────┘
```

- `svh` (Small Viewport) 는 주소창이 보일 때를 기준으로 한 높이다 — 가장 작은 뷰포트다.
- `lvh` (Large Viewport) 는 주소창이 숨겨질 때를 기준으로 한 높이다 — 가장 큰 뷰포트다.
- `dvh` (Dynamic Viewport) 는 현재 상태에 따라 값이 동적으로 바뀐다.
- 주소창이 보이면 `dvh` 는 작은 쪽을, 숨으면 큰 쪽을 따라간다.
- 원본은 이 셋 가운데 `dvh` 를 권장한다.

> **dvh** — dynamic viewport height. 지금 이 순간 보이는 뷰포트 높이의 1% 다.\
> 예: `height: 100dvh` 는 주소창 상태가 바뀌면 높이도 따라 바뀐다.

### (3) 폴백 두 줄 — 구형 브라우저 대비

**언제 쓰나** — `dvh` 를 쓰되, 그 단위를 모르는 구형 브라우저에서도 높이가 비지 않게 하고 싶을 때 쓴다.

```text
.hero {
  height: 100vh;    ← ① 먼저 선언
  height: 100dvh;   ← ② 나중 선언
}
   │
   ├─ dvh 를 아는 브라우저: ①②가 둘 다 유효 → 나중 선언 ② 가 이긴다 → 100dvh
   │
   └─ dvh 를 모르는 브라우저: ② 를 해석하지 못해 버린다 → ① 만 남는다 → 100vh
```

- CSS 는 한 규칙 안에서 같은 속성이 두 번 나오면 나중 선언을 쓴다.
- CSS 는 해석하지 못하는 값이 든 선언을 통째로 무시하고, 앞 선언을 그대로 둔다.
- 이 두 규칙 덕분에 「옛 값 먼저, 새 값 나중」 순서로만 적으면 브라우저가 알아서 고른다.
- 순서를 뒤집으면 새 브라우저에서도 `100vh` 가 이겨 `dvh` 가 쓸모없어진다.
- 이 패턴은 `dvh` 에만 묶인 것이 아니다 — 새 CSS 값을 쓰면서 옛 브라우저를 챙길 때 같은 방식으로 쓴다.

> **폴백** — 새 기능이 통하지 않을 때 대신 쓰이도록 먼저 깔아 두는 값이다.\
> 예: `height: 100dvh` 앞에 둔 `height: 100vh`.

### (4) 가로 방향 — `svw` · `lvw` · `dvw`

**언제 쓰나** — 너비를 뷰포트 기준으로 잡을 때도 같은 선택지가 필요하면 쓴다.

```text
svh / lvh / dvh   (세로)
   │ 같은 원리
   ▼
svw / lvw / dvw   (가로)
```

- 원본 팁에 따르면 `svw` · `lvw` · `dvw` 도 같은 원리로 가로에 적용된다.
- 작은 · 큰 · 동적 뷰포트라는 세 기준이 그대로 너비에 옮겨진 것이다.

### (5) 예제 데모가 문제를 흉내 내는 방법

**언제 쓰나** — 데스크톱 화면에서 모바일 주소창 문제를 그림으로 보여 주고 싶을 때 쓰는 방식이다.

```text
.vu-viewport { height: 140px; overflow: hidden; }   ← 폰의 「보이는 영역」
   │
   ├─ .vu-100vh  { height: 160px; }  → 140px 보다 20px 큼 → 아래가 잘림
   └─ .vu-100dvh { height: 140px; }  → 영역과 같음 → 딱 맞음
```

- 데모는 실제 `vh` · `dvh` 단위를 쓰지 않는다.
- 폰 모형 안의 「보이는 영역」을 140px 고정 높이에 `overflow: hidden` 으로 만든다.
- 왼쪽 폰의 콘텐츠는 일부러 160px 로 크게 잡아 「100vh 가 넘치는 모습」을 흉내 낸다.
- 오른쪽 폰의 콘텐츠는 140px 로 영역과 같게 잡아 「100dvh 가 딱 맞는 모습」을 흉내 낸다.
- 주소창 모형은 보이는 영역 위에 따로 놓인 막대다.
- 아래쪽에는 세 단위 설명 목록과, 폴백 두 줄을 담은 코드 상자가 놓인다.

## 문법 — 형태와 규칙

```html demo
<section class="hero">전체 화면 히어로</section>
<style>
  body { margin: 0; }
  .hero {
    height: 100vh;    /* 폴백: dvh 를 모르는 브라우저용 */
    height: 100dvh;   /* 동적 뷰포트 높이 */
    display: flex;
    align-items: center;
    justify-content: center;
    background: #dbeafe;
  }
</style>
```

> **보이는 것** — 화면 높이를 꽉 채운 파란 영역 한가운데에 「전체 화면 히어로」 글자가 놓인다. (코드에서 읽은 것 — 렌더 실측 아님)

- 단위는 숫자 뒤에 붙인다 — `100dvh` 는 동적 뷰포트 높이의 100% 다.
- 폴백은 반드시 **먼저**, 새 단위는 **나중에** 쓴다.
- 히어로 섹션 · 풀스크린 모달처럼 화면을 꽉 채워야 하는 요소에서 특히 중요하다.

| 단위 | 방향 | 기준 | 원본 설명 |
|---|---|---|---|
| `vh` | 세로 | 뷰포트 높이 | 모바일에서 주소창을 고려하지 않아 잘린다 |
| `svh` | 세로 | Small Viewport | 주소창이 보일 때 기준 (가장 작은 뷰포트) |
| `lvh` | 세로 | Large Viewport | 주소창이 숨겨질 때 기준 (가장 큰 뷰포트) |
| `dvh` | 세로 | Dynamic Viewport | 현재 상태에 따라 동적으로 변경 (권장) |
| `svw` · `lvw` · `dvw` | 가로 | 위와 같은 세 기준 | 같은 원리로 가로에 적용 |

## 어디서 틀리나

### 1. 폴백 순서를 뒤집는다

`height: 100dvh;` 다음에 `height: 100vh;` 를 쓰면, 새 브라우저에서도 나중 선언인 `100vh` 가 이긴다.
결과적으로 `dvh` 를 쓴 효과가 사라진다.
옛 값이 먼저, 새 값이 나중이다.

### 2. `100vh` 하나만 쓴다

데스크톱에서는 멀쩡해 보여도 모바일 Safari/Chrome 에서는 주소창 때문에 아래가 잘린다.
히어로 섹션의 버튼이나 풀스크린 모달의 닫기 버튼이 아래에 있으면 사용자가 보지 못할 수 있다.

### 3. 폴백 없이 `100dvh` 만 쓴다

`dvh` 를 모르는 구형 브라우저는 그 선언을 무시한다.
다른 선언이 없으면 높이가 지정되지 않은 것처럼 그려진다.

### 4. 원본 설명의 표현이 서로 엇갈린다

- 원본 팁은 「100vh는 주소창을 포함하지 않아 콘텐츠가 잘린다」라고 쓴다.
- 원본 코드 상자의 주석은 「모바일에서 100vh가 주소창 포함」이라고 쓴다.
- 왜 의심스러운가: 한쪽은 「포함하지 않아」, 한쪽은 「포함」이라 글자만 보면 반대다.
- 두 문장이 가리키는 현상은 같다 — `100vh` 가 주소창이 차지한 자리를 빼지 않은 높이로 잡혀, 보이는 영역보다 크다는 것이다.
- 「주소창을 고려하지 않는다」로 읽으면 두 문장이 함께 맞는다. (원본에 근거 없음 — 추론)

### 5. 데모를 실제 단위의 측정으로 착각한다

- 데모의 160px · 140px 은 실제 `vh` · `dvh` 계산값이 아니라 그림을 위한 고정값이다.
- 데모의 「이 부분이 주소창 뒤로 숨음!」 뱃지는 실제로는 폰 모형 **아래쪽**에서 `overflow: hidden` 으로 잘린다 — 주소창 모형은 위에 따로 있다.
- `.vu-phone.fixed .vu-viewport { overflow: hidden; }` 은 이미 `.vu-viewport` 에 있는 값을 되풀이한 규칙이라 없어도 결과가 같다. (원본에 근거 없음 — 추론)
- `.vu-viewport` 의 `position: relative` 는 「자식 absolute 기준」이라는 주석이 달렸지만 `absolute` 자식이 없어 하는 일이 없다. (원본에 근거 없음 — 추론)

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 모바일에서 `100vh` 가 주소창을 고려하지 않아 잘린다 | 브라우저 구현 (원본은 모바일 Safari/Chrome 을 든다) — 브라우저와 버전마다 다를 수 있다 (확인 필요) |
| `svh` · `lvh` · `dvh` 의 세 기준(작은 · 큰 · 동적 뷰포트) | CSS 명세의 단위 정의 (확인 필요) |
| 같은 속성의 나중 선언이 이긴다 | CSS 명세 (캐스케이드) |
| 해석하지 못하는 값이 든 선언은 무시된다 | CSS 명세 (오류 처리) |
| 구형 브라우저는 `dvh` 를 모른다 | 브라우저 지원 범위 — 어느 버전부터인지는 원본에 없다 (확인 필요) |
| `dvh` 가 권장이다 | 원본 자료의 판단 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 모바일까지 화면을 꽉 채우는 히어로 섹션 | `100vh` 폴백 + `100dvh` | `100vh` 만 |
| 풀스크린 모달 | `100vh` 폴백 + `100dvh` | 폴백 없는 `100dvh` 만 |
| 주소창이 보여도 반드시 다 보여야 하는 요소 | `svh` (가장 작은 뷰포트 기준이라 넘치지 않는다 — 정의에서 추론) | `lvh` |
| 뷰포트 기준 너비 | `svw` · `lvw` · `dvw` 중 기준에 맞는 것 | 세로 단위를 가로에 쓰기 |
| 폴백을 함께 쓸 때 | 옛 값 먼저, 새 값 나중 | 새 값 먼저 |

## 핵심 문장

1. **모바일 Safari/Chrome 에서 `100vh` 는 주소창을 고려하지 않아 보이는 영역보다 커지고, 아래가 잘린다.**
2. **`svh` 는 주소창이 보일 때, `lvh` 는 숨겨질 때, `dvh` 는 지금 상태를 기준으로 한다.**
3. **`height: 100vh; height: 100dvh;` 순서로 쓰면 새 브라우저는 `dvh` 를, 구형 브라우저는 `vh` 를 쓴다.**
4. **이 폴백이 통하는 까닭은 「나중 선언이 이긴다」와 「모르는 값은 무시된다」 두 규칙이다.**
5. **가로에는 `svw` · `lvw` · `dvw` 가 같은 원리로 있다.**

## 용어 풀이

- **뷰포트** — 브라우저에서 페이지가 실제로 그려지는 영역.
- **`vh`** — 뷰포트 높이의 1%.
- **`svh`** — Small Viewport 높이의 1%, 주소창이 보일 때 기준.
- **`lvh`** — Large Viewport 높이의 1%, 주소창이 숨겨질 때 기준.
- **`dvh`** — Dynamic Viewport 높이의 1%, 현재 상태에 따라 바뀐다.
- **`svw` · `lvw` · `dvw`** — 위 세 기준을 가로(너비)에 적용한 단위.
- **폴백** — 새 기능이 통하지 않을 때 대신 쓰이도록 먼저 둔 값.
- **히어로 섹션** — 페이지 맨 위에서 화면을 크게 채우는 첫 영역.
- **풀스크린 모달** — 화면 전체를 덮는 대화 상자.
- **캐스케이드** — 여러 선언이 겹칠 때 어느 것을 쓸지 정하는 CSS 규칙 체계.
- **`overflow: hidden`** — 상자 밖으로 넘치는 내용을 잘라 보이지 않게 하는 설정.

## 더 들어가면

- 모바일 브라우저에서 `100vh` 는 대체로 `100lvh` 와 같은 값으로 잡힌다고 알려져 있다. (확인 필요)
- `dvh` 는 주소창이 나타나고 사라질 때마다 값이 바뀌므로, 스크롤 중 요소 크기가 흔들려 보일 수 있다. 이것이 싫으면 `svh` 를 쓰는 선택도 있다. (확인 필요)
- 화면 키보드가 올라올 때 `dvh` 가 그 높이를 반영하는지는 브라우저마다 다를 수 있다. (확인 필요)
- 폴백 대신 `@supports (height: 100dvh) { … }` 로 지원 여부를 물어 분기하는 방법도 있다. (확인 필요)
- 새 단위가 나오기 전에는 JS 로 `window.innerHeight` 를 읽어 CSS 변수(`--vh`)에 넣는 우회법을 많이 썼다. (확인 필요)
- `vmin` · `vmax` 에도 `svmin` · `dvmax` 같은 짝이 있다. (확인 필요)
