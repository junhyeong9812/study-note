## 한눈에 — 쉽게 말하면

**mobile-first 는 「작은 방에 짐을 먼저 꾸리고, 큰 방으로 옮길 때 가구를 더 들이는 이사」다.**
desktop-first 는 거꾸로 「큰 집에 가구를 다 채워 놓고, 작은 집으로 옮길 때 하나씩 빼는 이사」다.
CSS 의 두 접근법도 똑같은 구조다.
mobile-first 는 좁은 화면의 스타일을 기본으로 쓰고, 화면이 넓어질 때 `min-width` 미디어 쿼리로 스타일을 덧붙인다.
desktop-first 는 넓은 화면의 스타일을 기본으로 쓰고, 화면이 좁아질 때 `max-width` 미디어 쿼리로 스타일을 덮어쓴다.

> **미디어 쿼리** — 화면 조건이 참일 때만 안쪽 규칙을 적용하게 하는 `@media` 블록이다.\
> 예: `@media (min-width: 768px) { … }` 는 뷰포트 너비가 768px 이상일 때만 안쪽 규칙이 적용된다.

> **뷰포트** — 페이지가 그려지는 브라우저 창의 보이는 영역이다.\
> 예: 휴대폰을 세로로 들면 뷰포트 너비가 좁다.

| 비유 | 실체 |
|---|---|
| 작은 방에 꾸린 기본 짐 | 미디어 쿼리 밖의 기본 스타일(모바일용) |
| 큰 방에서 더 들이는 가구 | `min-width` 쿼리 안에서 덧붙이는 규칙 |
| 큰 집에 채운 가구 전부 | 미디어 쿼리 밖의 기본 스타일(데스크톱용) |
| 작은 집으로 갈 때 빼는 가구 | `max-width` 쿼리 안에서 덮어쓰는 규칙 |
| 방의 크기 | 뷰포트 너비 |

```text
mobile-first                       desktop-first
  작은 화면 (기본)                    큰 화면 (기본)
     │ + min-width 768                 │ - max-width 1023
     ▼                                 ▼
  중간 화면                           중간 화면
     │ + min-width 1024                │ - max-width 767
     ▼                                 ▼
  큰 화면                             작은 화면
  (위로 쌓아 올린다)                  (아래로 덜어 낸다)
```

## 이 주제가 답하려는 질문

1. 어느 화면을 「기본」으로 쓰고, 어느 쪽으로 스타일을 바꿔 나가나?
2. 왜 mobile-first 는 `min-width` 를, desktop-first 는 `max-width` 를 쓰나?
3. 쿼리 여러 개가 동시에 참이면 어떤 값이 이기나?
4. 왜 mobile-first 가 권장되고, desktop-first 는 언제 쓸 만한가?

## 동작 방식

### (1) mobile-first — `min-width` 로 위로 쌓기

**언제 쓰나** — 새 프로젝트를 시작할 때, 좁은 화면을 먼저 완성하고 넓은 화면에서 배치를 넓히고 싶을 때 쓴다.

```text
입력 (원본 예의 mobile-first 쪽)
  .nav { flex-direction: column; }                       ← 쿼리 밖: 항상 적용
  @media (min-width: 768px)  { .nav { flex-direction: row; } }
  @media (min-width: 1024px) { .nav { gap: 24px; } }

무엇이 일어나나 (너비 축)
  0 ─────────────── 768 ─────────────── 1024 ─────────────→
  기본: column ────────────────────────────────────────────
                    ≥768: row ─────────────────────────────
                                        ≥1024: gap 24px ──

결과
  [0, 768)     column
  [768, 1024)  row
  [1024, ∞)    row + gap 24px
```

- 쿼리 밖의 `column` 은 모든 너비에서 먼저 깔린다.
- 너비가 768px 이상이면 첫 쿼리가 참이 되어 `row` 가 `column` 을 덮는다.
- 너비가 1024px 이상이면 두 쿼리가 모두 참이다 — `row` 는 그대로 남고 `gap: 24px` 이 더해진다.
- 너비가 커질수록 참인 쿼리가 늘어나므로, 규칙이 「쌓이는」 모양이 된다.
- 1024px 쪽 블록은 `flex-direction` 을 다시 적지 않는다 — 아래 단계(768px)에서 이미 `row` 가 되었기 때문이다.

> **브레이크포인트** — 레이아웃을 바꾸는 기준 너비다.\
> 예: 이 예의 브레이크포인트는 768px 과 1024px 이다.

### (2) desktop-first — `max-width` 로 아래로 덜어내기

**언제 쓰나** — 데스크톱용으로 이미 만든 사이트(레거시)에 모바일 대응을 덧붙일 때, 데스크톱 화면을 중심으로 설계할 때 쓴다.

```text
입력 (원본 예의 desktop-first 쪽)
  .nav { flex-direction: row; gap: 24px; }               ← 쿼리 밖: 항상 적용
  @media (max-width: 1023px) { .nav { gap: 12px; } }
  @media (max-width: 767px)  { .nav { flex-direction: column; } }

무엇이 일어나나 (너비 축)
  0 ─────────────── 767|768 ─────────── 1023|1024 ─────────→
  기본: row + gap 24px ────────────────────────────────────
  ≤1023: gap 12px ──────────────────────────┘
  ≤767: column ─────┘

결과
  [0, 767]       column + gap 12px
  [768, 1023]    row + gap 12px
  [1024, ∞)      row + gap 24px
```

- 쿼리 밖의 `row` 와 `gap: 24px` 이 모든 너비에서 먼저 깔린다.
- 너비가 1023px 이하이면 첫 쿼리가 참이 되어 `gap` 이 12px 로 덮인다.
- 너비가 767px 이하이면 두 쿼리가 모두 참이다 — `gap: 12px` 은 남고 `column` 이 더해진다.
- 좁은 화면일수록 기본값을 덮어쓰는 규칙이 늘어난다.
- 그래서 원본은 「모바일에서 불필요한 CSS 오버라이드 증가」를 desktop-first 의 단점으로 든다.

> **오버라이드** — 앞에서 정한 속성값을 뒤의 규칙이 덮어쓰는 것이다.\
> 예: 기본 `row` 를 767px 이하에서 `column` 으로 바꾸는 것.

### (3) 여러 쿼리가 동시에 참일 때 — 캐스케이드와 순서

**언제 쓰나** — 쿼리를 둘 이상 쓰는 모든 경우에 이 규칙이 적용된다.

```text
입력
  .nav { flex-direction: column; }                      (1번째)
  @media (min-width: 768px)  { .nav { flex-direction: row; } }   (2번째)

너비 1200px 에서
  1번째 규칙: 참 (쿼리 없음)   → column 후보
  2번째 규칙: 참 (1200 ≥ 768)  → row 후보
  선택자 .nav 의 명시도가 같다 → 나중에 나온 규칙이 이긴다

결과
  flex-direction: row
```

- `@media` 블록은 안쪽 규칙의 명시도를 바꾸지 않는다.
- 그래서 같은 선택자 · 같은 속성이 겹치면 소스에서 나중에 나온 쪽이 이긴다.
- mobile-first 는 `min-width` 값을 작은 것부터 큰 것 순서로 적어야 한다 — 넓은 화면일수록 참인 블록이 많고, 그중 가장 큰 기준이 마지막에 와야 이긴다.
- desktop-first 는 거꾸로 `max-width` 값을 큰 것부터 작은 것 순서로 적어야 한다.
- 원본 예는 768px · 1024px 블록이 서로 다른 속성(`flex-direction` 과 `gap`)을 건드리므로, 그 둘끼리는 순서가 바뀌어도 충돌하지 않는다.
- 같은 속성을 두 블록이 다르게 정하면, 순서를 거꾸로 적었을 때 넓은 화면에서 작은 기준의 값이 이긴다.

> **캐스케이드** — 같은 요소에 여러 규칙이 걸릴 때 어느 값을 쓸지 정하는 CSS 의 규칙 체계(명시도 · 소스 순서 등)다.\
> 예: 명시도가 같으면 나중에 적은 규칙이 이긴다.

> **명시도** — 선택자가 얼마나 구체적인지를 나타내는 점수다.\
> 예: `.nav` 와 `.nav` 는 명시도가 같다.

### (4) 원본의 두 예는 같은 화면을 만드나

**언제 쓰나** — 한 접근법에서 다른 접근법으로 옮겨 쓸 때, 결과가 정말 같은지 구간별로 확인할 때 쓴다.

```text
구간            mobile-first 예          desktop-first 예
[0, 767]        column, gap 없음         column, gap 12px
[768, 1023]     row,    gap 없음         row,    gap 12px
[1024, ∞)       row,    gap 24px         row,    gap 24px
```

- 방향(`column` ↔ `row`)은 두 예가 같은 경계(767 / 768)에서 바뀐다.
- 간격은 다르다 — mobile-first 예에는 12px 단계가 없고, 1024px 아래에서는 `gap` 을 정하지 않는다.
- `gap` 을 적지 않으면 flex 아이템 사이에 따로 간격이 생기지 않는다.
- 즉 원본의 두 코드는 접근법의 차이를 보이는 예일 뿐, 서로 똑같은 결과를 내도록 맞춘 쌍은 아니다.

## 문법 — 형태와 규칙

```html demo
<nav class="nav">
  <a href="#">홈</a><a href="#">소개</a><a href="#">문의</a>
</nav>
<style>
  /* 기본: 좁은 화면 */
  .nav { display: flex; flex-direction: column; gap: 8px; }

  /* 768px 이상: 가로로 */
  @media (min-width: 768px) {
    .nav { flex-direction: row; }
  }

  /* 1024px 이상: 간격 넓힘 */
  @media (min-width: 1024px) {
    .nav { gap: 24px; }
  }
</style>
```

> **보이는 것** — 창이 768px 보다 좁으면 링크 셋이 세로로 쌓이고, 768px 이상이면 가로로 늘어서며, 1024px 이상이면 링크 사이가 넓어진다 (코드에서 읽은 것 — 렌더 실측 아님)

| 조건 | 참이 되는 너비 | 주로 쓰는 접근법 | 쿼리 순서 |
|---|---|---|---|
| `(min-width: N)` | 뷰포트 너비 ≥ N (N 포함) | mobile-first | N 이 작은 것부터 큰 것으로 |
| `(max-width: N)` | 뷰포트 너비 ≤ N (N 포함) | desktop-first | N 이 큰 것부터 작은 것으로 |

- 기본 스타일은 미디어 쿼리 **밖**에 쓴다 — 어떤 너비에서도 깔리는 바탕이다.
- `min-width` 와 `max-width` 는 둘 다 경계값을 **포함**한다.
- 그래서 desktop-first 는 mobile-first 의 경계보다 1 작은 값을 쓴다 — 768 ↔ 767, 1024 ↔ 1023.
- 같은 경계를 양쪽에 그대로 쓰면(`max-width: 768px` 과 `min-width: 768px`) 정확히 768px 에서 두 쿼리가 함께 참이 된다.
- 한 단계의 쿼리 블록에는 그 단계에서 **바뀌는 속성만** 적는다 — 아래(또는 위) 단계의 값은 캐스케이드로 이어진다.

## 어디서 틀리나

### 1. mobile-first 인데 `max-width` 를 섞어 쓴다
원본의 팁은 「`min-width` 미디어 쿼리를 사용하고 작은 화면부터 스타일을 쌓아 올린다」이다.
기본 스타일이 모바일인데 `max-width` 쿼리를 쓰면, 이미 모바일인 값을 모바일에서 또 덮어쓰는 꼴이 되어 방향이 엉킨다.

### 2. 쿼리 순서를 거꾸로 적는다
`min-width: 1024px` 블록을 `min-width: 768px` 블록보다 앞에 두고 둘이 같은 속성을 정하면, 1200px 에서 768px 쪽 값이 이긴다.
미디어 쿼리는 명시도를 올려 주지 않으므로, 소스 순서가 결과를 정한다.

### 3. 경계를 겹치게 적는다
`max-width: 768px` 과 `min-width: 768px` 을 함께 쓰면 768px 에서 두 쿼리가 다 참이다.
원본의 desktop-first 예가 767 · 1023 을 쓰는 까닭이 이것이다.

### 4. 「두 접근법의 예가 같은 결과」라고 믿는다
원본의 두 코드는 1024px 아래의 `gap` 이 다르다(동작 방식 (4)).
접근법을 바꿔 옮겨 쓸 때는 구간마다 결과를 대 보아야 한다.

### 5. 원본의 「성능: 모바일에서 불필요한 CSS 로드 최소화」
원본의 주장 → mobile-first 가 모바일에서 불필요한 CSS 로드를 최소화한다.
왜 의심스러운가 → 한 스타일시트 안의 `@media` 블록은 조건이 거짓이어도 파일과 함께 내려받아진다.
mobile-first 가 줄이는 것은 「로드」라기보다 모바일에서 **덮어쓰는 선언(오버라이드)의 수**라고 보는 편이 맞다 (원본에 근거 없음 — 추론).

### 6. desktop-first 의 「단점」 목록에 든 두 항목
원본 데모는 「레거시 프로젝트 마이그레이션에 적합」「데스크톱 중심 디자인 시 직관적」을 단점(`.con`) 칸에 넣었다.
내용으로 보면 두 항목은 단점이 아니라 desktop-first 를 고를 만한 **상황**이다.
진짜 단점은 첫 항목 「모바일에서 불필요한 CSS 오버라이드 증가」 하나다.

### 7. 「업계 표준」 · 「모바일 트래픽 50% 이상」을 규칙으로 여긴다
원본의 팁은 mobile-first 가 업계 표준이고, 모바일 트래픽이 전체의 50% 이상인 현실을 반영했다고 말한다.
이것은 관행과 통계에 기댄 이유다 — CSS 명세가 어느 쪽을 요구하지는 않는다.
트래픽 수치는 시점과 출처에 따라 다르다 (확인 필요).

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `min-width` · `max-width` 조건은 경계값을 포함한다 | CSS 미디어 쿼리 명세 |
| `@media` 블록은 안쪽 규칙의 명시도를 바꾸지 않고, 명시도가 같으면 나중 규칙이 이긴다 | CSS 캐스케이드 명세 |
| mobile-first 가 업계 표준이다 | 관행 — 명세가 정한 것 아님 |
| 모바일 트래픽이 전체의 50% 이상이다 | 원본의 주장 — 통계 출처 · 시점 확인 필요 |
| Tailwind CSS 등 프레임워크가 mobile-first 를 기본으로 채택한다 | 각 프레임워크의 설계 선택 — CSS 언어가 보장하지 않음 |
| mobile-first 가 모바일에서 CSS 로드를 줄인다 | 원본의 주장 — 「어디서 틀리나 5」 참고 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 새 프로젝트를 시작한다 | mobile-first(`min-width`) | 데스크톱 기본에 모바일을 덧대는 방식 |
| 데스크톱 전용으로 만든 레거시에 모바일 대응을 붙인다 | desktop-first(`max-width`) | 기본 스타일 전체를 뒤집는 대수술 |
| 데스크톱 화면이 설계의 중심이다 | desktop-first 가 직관적일 수 있다 | — |
| 핵심 콘텐츠부터 설계하고 넓은 화면에서 꾸밈을 더하고 싶다 | mobile-first(점진적 향상) | — |
| 한 파일에서 두 방식을 섞는다 | 한 방향으로 통일 | `min-width` · `max-width` 를 같은 속성에 뒤섞기 |

> **점진적 향상(Progressive Enhancement)** — 가장 제한된 환경에서 핵심이 돌아가게 만든 뒤, 여유 있는 환경에서 기능 · 꾸밈을 더하는 설계 방식이다.\
> 예: 좁은 화면에서 세로 메뉴를 완성하고, 넓은 화면에서 가로 배치와 넓은 간격을 더한다.

## 핵심 문장

1. **mobile-first 는 모바일을 기본으로 쓰고 `min-width` 로 위로 쌓는다** — 쿼리는 작은 기준부터 적는다.
2. **desktop-first 는 데스크톱을 기본으로 쓰고 `max-width` 로 아래로 덮어쓴다** — 쿼리는 큰 기준부터 적는다.
3. **미디어 쿼리는 명시도를 올리지 않는다** — 겹치면 소스 순서가 이긴다.
4. **두 조건 모두 경계값을 포함하므로 두 방식의 경계는 1 차이(768 ↔ 767)로 맞춘다.**
5. **mobile-first 가 권장되는 이유는 오버라이드 감소 · 점진적 향상 · 핵심 콘텐츠 우선이고, desktop-first 는 레거시와 데스크톱 중심 설계에 맞는다.**

## 용어 풀이

- **mobile-first** — 좁은 화면 스타일을 기본으로 쓰고 넓은 화면에서 덧붙이는 접근법.
- **desktop-first** — 넓은 화면 스타일을 기본으로 쓰고 좁은 화면에서 덮어쓰는 접근법.
- **미디어 쿼리** — 조건이 참일 때만 안쪽 규칙을 적용하는 `@media` 블록.
- **뷰포트** — 페이지가 그려지는 브라우저 창의 보이는 영역.
- **브레이크포인트** — 레이아웃을 바꾸는 기준 너비.
- **`min-width`** — 뷰포트 너비가 값 이상일 때 참인 조건.
- **`max-width`** — 뷰포트 너비가 값 이하일 때 참인 조건.
- **캐스케이드** — 여러 규칙이 겹칠 때 쓸 값을 정하는 규칙 체계.
- **명시도** — 선택자의 구체성 점수. 같으면 소스 순서로 정한다.
- **오버라이드** — 앞에서 정한 값을 뒤 규칙이 덮어쓰는 것.
- **점진적 향상** — 최소 환경에서 핵심을 먼저 만들고 여유 있는 환경에서 더하는 설계.
- **레거시** — 예전 방식으로 이미 만들어져 운영 중인 코드.

## 더 들어가면

- desktop-first 의 반대말 격으로 「우아한 성능 저하(Graceful Degradation)」라는 설계 용어가 쓰인다 — 풍부한 환경을 먼저 만들고 제한된 환경에서 무너지지 않게 다듬는 방식이다 (확인 필요).
- Tailwind CSS 에서는 접두사 없는 유틸리티 클래스가 모든 너비에 적용되고, `md:` 같은 접두사가 붙은 클래스가 `min-width` 쿼리로 감싸진다고 알려져 있다 (확인 필요).
- 확대 · 축소나 고해상도 화면에서 뷰포트 너비가 소수(예: 767.5px)가 되면, `max-width: 767px` 과 `min-width: 768px` 사이의 틈에 들어가 어느 쿼리도 참이 아닐 수 있다는 지적이 있다 (확인 필요).
- 최신 미디어 쿼리 문법에는 `(width >= 768px)` 같은 범위 표기가 있어, 경계를 1 차이로 맞추는 수고를 덜 수 있다 (확인 필요 — 지원 범위도 확인 필요).
- 별도 파일을 `<link media="…">` 로 나누면 브라우저가 조건이 거짓인 스타일시트의 우선순위를 낮춰 내려받는다고 알려져 있다 — 그래도 내려받기 자체는 일어난다고 한다 (확인 필요).
