# css/responsive/01 — viewport meta tag — 정리 (힌트)

> 출처 — study-site 항목 `css/viewport-meta`(항목 데이터 `data/css/responsive.json`) · 정답 코드 study-practice `css/responsive/reference/viewport-meta.html`\
> 집필 — `claude-opus-5-5` 가 원본 재료를 뼈대로 쓴 **검수 전 초안**이다(2026-11-28).\
> 실행 — 실행하지 않음 — 브라우저 화면에서 결과를 보는 예제다 — 글로 옮길 출력이 없다.

## 한눈에 — 쉽게 말하면

**viewport 메타 태그는 「신문을 휴대폰 크기로 다시 짤지, 큰 신문을 그대로 찍어 줄여 넣을지」 정하는 인쇄소 지시서다.**
지시서가 없으면 인쇄소는 늘 쓰던 큰 판형으로 신문을 짠 뒤, 작은 액자에 맞게 사진 축소하듯 줄여 넣는다.
글씨는 개미만 해지고, 읽으려면 손가락으로 벌려 확대해야 한다.
지시서에 「액자 너비에 맞춰 짜라, 줄이지 마라」라고 적으면, 처음부터 액자 크기로 조판해 글씨가 제 크기로 들어간다.
모바일 브라우저도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 인쇄소 지시서 | `<meta name="viewport" content="…">` |
| 늘 쓰던 큰 판형 | 메타 태그가 없을 때 브라우저가 쓰는 기본 너비(원본 기준 980px) |
| 액자 너비에 맞춰 짜라 | `width=device-width` |
| 줄이지 마라(1:1) | `initial-scale=1` |
| 손가락으로 벌려 확대 | 핀치줌 |
| 「확대 금지」 도장 | `user-scalable=no` · `maximum-scale=1` |

```text
[메타 태그 없음]                     [width=device-width, initial-scale=1]

 980px 너비로 조판                     기기 너비로 조판
 ┌──────────────────────────┐         ┌────────┐
 │ 데스크톱 레이아웃 그대로  │          │ 기기에 │
 └──────────────────────────┘         │ 맞춘   │
        │ 화면에 맞게 축소              │ 레이아웃│
        ▼                             └────────┘
 ┌────────┐                            글씨가 제 크기
 │ 작게…  │  글씨가 개미만 함
 └────────┘
```

## 이 주제가 답하려는 질문

1. 메타 태그가 없으면 모바일 브라우저는 페이지를 어떤 너비로 그리고, 화면에는 어떻게 보이나?
2. `width=device-width` 와 `initial-scale=1` 은 각각 무엇을 정하나?
3. 확대를 막는 값(`maximum-scale=1` · `user-scalable=no`)은 왜 피해야 하나?
4. 이 태그가 왜 「반응형 디자인의 필수 전제 조건」인가?

## 동작 방식

### (1) 메타 태그가 없을 때 — 넓게 그리고 줄인다

**언제 쓰나** — 쓰는 경우가 아니라 빠뜨렸을 때 일어나는 일이다.
모든 반응형 페이지가 피해야 할 출발점이다.

```text
<head> 에 viewport 메타 태그 없음
   │
   ▼
모바일 브라우저: 페이지를 980px 너비로 렌더링
   │
   ▼
그 980px 그림을 기기 화면 너비에 맞게 통째로 축소
   │
   ▼
결과: 데스크톱 레이아웃이 작게 보이고, 글씨를 읽으려면 확대해야 한다
```

- 브라우저는 페이지가 모바일용으로 짜였는지 모른다.
- 그래서 데스크톱 화면쯤의 너비(원본 팁 기준 980px)를 가정하고 그린다.
- 그 그림이 화면보다 넓으니, 화면에 다 들어오도록 비율을 줄여 보여 준다.

> **뷰포트** — 브라우저가 페이지를 그릴 때 기준으로 삼는 보이는 영역의 크기다.\
> 예: 메타 태그가 없으면 모바일 브라우저는 뷰포트 너비를 980px 로 잡는다.

### (2) `width=device-width` — 뷰포트 너비를 기기 너비로

**언제 쓰나** — 모바일에서도 제대로 보여야 하는 모든 페이지에 쓴다.

```text
content="width=device-width"
   │
   ▼
뷰포트 너비 = 기기 너비 (980px 가정을 버린다)
   │
   ▼
결과: 레이아웃이 처음부터 기기 너비에 맞춰 짜인다
```

- 「몇 px 로 그릴지」를 고정 숫자 대신 기기 자신의 너비로 정한다.
- 그러면 `width: 100%` 같은 값도 기기 너비를 기준으로 계산된다.

> **device-width** — 「이 기기의 화면 너비」를 뜻하는 viewport 메타 태그의 키워드다.\
> 예: `width=device-width` 는 뷰포트 너비를 기기 너비와 같게 만든다.

### (3) `initial-scale=1` — 처음 배율을 1:1 로

**언제 쓰나** — `width=device-width` 와 짝으로 쓴다.

```text
content="width=device-width, initial-scale=1"
   │
   ▼
페이지를 처음 열 때 확대/축소 비율 = 1
   │
   ▼
결과: 축소도 확대도 없이 CSS 의 크기 그대로 보인다
```

- `initial-scale` 은 페이지가 처음 열릴 때의 배율이다.
- 1 은 「줄이지도 키우지도 않는다」는 뜻이다.
- 사용자는 이후에 핀치줌으로 여전히 확대할 수 있다.

> **스케일링** — 그려진 페이지 전체를 비율로 확대하거나 축소해 보여 주는 일이다.\
> 예: `initial-scale=1` 은 처음 스케일을 1배로 둔다.

### (4) `maximum-scale=1` · `user-scalable=no` — 확대를 막는 값

**언제 쓰나** — 원칙적으로 쓰지 않는다.
`maximum-scale=1` 은 꼭 필요한 까닭이 있을 때만 신중하게 쓴다.

```text
content="…, maximum-scale=1"   → 최대 배율이 1 → 1보다 크게 확대할 수 없다
content="…, user-scalable=no"  → 핀치줌 자체를 끈다
   │
   ▼
결과: 작은 글씨를 키워 읽어야 하는 사람이 확대할 수 없다
```

- 두 값 모두 결과적으로 사용자가 화면을 키우지 못하게 한다.
- 시력이 약한 사람 등은 확대에 기대 글을 읽는다.
- 그래서 원본은 `user-scalable=no` 를 접근성을 해친다며 비권장으로, `maximum-scale=1` 도 같은 이유로 신중하게 쓰라고 한다.

> **핀치줌** — 두 손가락을 벌리거나 오므려 화면을 확대·축소하는 동작이다.\
> 예: `user-scalable=no` 는 핀치줌을 비활성화한다.

> **접근성** — 장애가 있거나 환경이 다른 사람도 내용을 쓸 수 있게 하는 성질이다.\
> 예: 확대를 막으면 저시력 사용자의 접근성이 떨어진다.

### (5) 왜 반응형의 「전제 조건」인가

**언제 쓰나** — 미디어 쿼리로 화면 너비마다 레이아웃을 바꿀 때 늘 함께 생각한다.

```text
@media (max-width: 600px) { … 모바일용 레이아웃 … }
   │
   ├─ 메타 태그 없음 → 브라우저가 아는 너비 = 980px → 600px 이하 아님 → 규칙이 안 맞는다
   │
   └─ width=device-width → 너비 = 기기 너비 → 작은 기기면 규칙이 맞는다
```

- 반응형 CSS 는 「지금 너비가 얼마인가」를 보고 갈라진다.
- 메타 태그가 없으면 그 너비가 늘 980px 로 잡혀, 작은 화면용 규칙이 깨어날 기회가 없다 (원본에 근거 없음 — 원본 팁의 980px 동작에서 추론).
- 그래서 메타 태그가 먼저 있어야 반응형 CSS 가 뜻대로 움직인다.

### (6) 예제 데모가 이것을 흉내 내는 방법

**언제 쓰나** — 예제는 실제 기기 대신 화면 모형 두 개로 차이를 보여 준다.

```text
.screen.without  → 박스 셋에 transform: scale(0.5) → 절반 크기로 줄어든 모습 = 「축소된 데스크톱 레이아웃」
.meta-tag        → 메타 태그 소스를 글자로 보여 준다(&lt; &gt; 로 꺾쇠를 찍는다)
.screen.with     → 박스 셋을 축소 없이 = 「기기 너비에 맞게 렌더링」
```

- 왼쪽 박스 묶음은 `transform: scale(0.5)` 와 `transform-origin: center` 로 중심을 기준으로 절반 크기가 된다.
- 너비 40px 짜리 박스는 화면에서 20px 너비로 보인다.
- `transform` 은 그려지는 모습만 바꾸고, 레이아웃이 잡아 둔 자리 크기는 바꾸지 않는다.
- 가운데 상자는 진짜 메타 태그가 아니라 **글자로 쓴 소스**다 — 페이지의 뷰포트에는 아무 영향이 없다.
- 이 데모 파일의 `<head>` 에는 viewport 메타 태그가 들어 있지 않다.

> **HTML 엔티티** — `<` 처럼 HTML 에서 특별한 뜻이 있는 글자를 글자 그대로 보이게 쓰는 표기다.\
> 예: `&lt;meta` 는 화면에 `<meta` 라는 글자로 찍힌다.

```html demo
<div style="display:flex; gap:16px;">
  <div style="width:140px; border:3px solid #374151; padding:8px;">
    <div style="display:flex; gap:2px; transform:scale(0.5);">
      <div style="width:40px;height:30px;background:#94a3b8"></div>
      <div style="width:40px;height:30px;background:#94a3b8"></div>
    </div>
  </div>
  <div style="width:140px; border:3px solid #374151; padding:8px;">
    <div style="display:flex; gap:4px;">
      <div style="width:35px;height:30px;background:#3b82f6"></div>
      <div style="width:35px;height:30px;background:#3b82f6"></div>
    </div>
  </div>
</div>
```

> **보이는 것** — 왼쪽 틀 안의 회색 박스들은 절반 크기로 작게, 오른쪽 틀 안의 파란 박스들은 제 크기로 보인다 (코드에서 읽은 것 — 렌더 실측 아님)

## 문법 — 형태와 규칙

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>반응형 페이지</title>
</head>
<body>
  <p>기기 너비에 맞춰 그려진다.</p>
</body>
</html>
```

- 태그는 `<head>` 안에 둔다.
- `name="viewport"` 로 이 메타 태그가 뷰포트 지시임을 밝힌다.
- 지시 내용은 `content` 속성에 `키=값` 을 쉼표로 이어 적는다.
- 기본으로 쓰는 조합은 `width=device-width, initial-scale=1` 이다.
- 이 태그는 HTML 이다 — CSS 파일 안에는 쓰지 않는다.

| `content` 의 값 | 뜻 | 권장 |
|---|---|---|
| `width=device-width` | 뷰포트 너비를 기기 너비에 맞춤 | 쓴다 |
| `initial-scale=1` | 초기 확대/축소 비율 1:1 | 쓴다 |
| `maximum-scale=1` | 최대 확대 제한 | 접근성 주의 — 신중하게 |
| `user-scalable=no` | 핀치줌 비활성화 | 비권장 |

## 어디서 틀리나

### 1. 메타 태그를 빠뜨린다

- 태그가 없으면 모바일 브라우저는 페이지를 980px 너비로 렌더링한 뒤 축소한다.
- CSS 를 아무리 잘 짜도 화면에는 작게 줄어든 데스크톱 레이아웃이 보인다.
- 미디어 쿼리의 작은 화면 규칙도 맞지 않는다(동작 방식 (5)).

### 2. 「앱처럼 보이게」 하려고 확대를 막는다

- `user-scalable=no` 는 핀치줌을 꺼 접근성을 해친다 — 쓰지 않는 것이 좋다.
- `maximum-scale=1` 도 1보다 크게 키울 수 없게 해 같은 이유로 신중해야 한다.
- 「확대가 거슬린다」는 디자인 이유는 확대가 필요한 사람의 불편보다 가볍다.

### 3. 데모의 글자 상자를 진짜 태그로 착각한다

- 예제의 `.meta-tag` 는 `&lt;meta …&gt;` 를 글자로 보여 주는 `div` 다.
- 브라우저는 이것을 메타 태그로 읽지 않는다.
- 진짜로 효과를 내려면 `<head>` 안에 `<meta>` 요소로 넣어야 한다.

### 4. 데모의 축소를 실제 동작으로 착각한다

- 왼쪽 화면 모형의 축소는 `transform: scale(0.5)` 로 만든 흉내다.
- 실제 브라우저의 축소 비율은 980px 와 기기 너비의 비로 정해지며 0.5 로 정해져 있지 않다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 메타 태그가 없으면 980px 너비로 렌더링한다 | 모바일 브라우저의 구현 관례다 — CSS · HTML 이 이 숫자를 보장하지 않는다 (확인 필요) |
| `name="viewport"` 를 읽어 뷰포트를 바꾼다 | 브라우저(특히 모바일 브라우저)의 동작이다 — 데스크톱 브라우저에서의 효과는 다를 수 있다 (확인 필요) |
| `transform` 은 레이아웃 자리를 바꾸지 않는다 | CSS 규칙이다 |
| `&lt;` 가 `<` 글자로 찍힌다 | HTML 규칙이다 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 모바일에서도 보일 모든 페이지 | `width=device-width, initial-scale=1` | 태그 생략 |
| 미디어 쿼리로 반응형을 짤 때 | 위 조합을 먼저 넣기 | 태그 없이 미디어 쿼리만 |
| 확대가 디자인을 망친다고 느낄 때 | 레이아웃을 고쳐 확대해도 깨지지 않게 | `user-scalable=no` |
| 확대 상한이 정말 필요할 때 | 까닭을 따져 본 뒤 신중하게 | 습관처럼 `maximum-scale=1` |

## 핵심 문장

1. **viewport 메타 태그는 모바일 브라우저가 페이지를 어떤 너비 · 배율로 그릴지 정한다.**
2. **태그가 없으면 980px 너비로 그린 뒤 화면에 맞게 줄인다** — 그래서 작게 보인다.
3. **`width=device-width, initial-scale=1` 이 기본 조합이다** — 기기 너비로, 1:1 배율로.
4. **확대를 막는 `user-scalable=no` · `maximum-scale=1` 은 접근성을 해친다.**
5. **이 태그가 있어야 반응형 CSS 가 기기 너비를 보고 움직인다.**

## 용어 풀이

- **뷰포트** — 브라우저가 페이지를 그릴 때 기준으로 삼는 보이는 영역.
- **메타 태그** — `<head>` 안에서 문서에 대한 정보나 지시를 주는 `<meta>` 요소.
- **`device-width`** — 기기 화면 너비를 뜻하는 키워드.
- **`initial-scale`** — 페이지를 처음 열 때의 확대/축소 비율.
- **`maximum-scale`** — 사용자가 확대할 수 있는 최대 비율.
- **`user-scalable`** — 사용자의 확대/축소(핀치줌)를 허용할지 정하는 값.
- **스케일링** — 그려진 페이지를 비율로 확대·축소해 보여 주는 일.
- **핀치줌** — 두 손가락으로 화면을 확대·축소하는 동작.
- **접근성** — 누구나 내용을 쓸 수 있게 하는 성질.
- **반응형 디자인** — 화면 크기에 따라 레이아웃이 알맞게 바뀌는 설계.
- **`transform: scale()`** — 요소의 그려지는 크기를 비율로 바꾸는 CSS 함수.
- **`transform-origin`** — 변형의 기준점.
- **HTML 엔티티** — 특수 문자를 글자 그대로 찍게 하는 표기(`&lt;` 등).
