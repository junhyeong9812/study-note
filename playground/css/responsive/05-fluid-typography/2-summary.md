## 한눈에 — 쉽게 말하면

**`clamp()` 로 정한 글자 크기는 「멈춤쇠가 달린 샤워기 온도 손잡이」다.**
손잡이를 돌린 만큼 물 온도가 고르게 오른다.
다만 너무 차가운 쪽과 너무 뜨거운 쪽에는 멈춤쇠가 있다.
손잡이를 더 돌려도 그 너머로는 가지 않는다.
유동 타이포그래피도 똑같은 구조다.
브라우저 창의 너비가 손잡이이고, 글자 크기가 온도다.
`clamp()` 의 첫 값과 셋째 값이 두 멈춤쇠다.

| 비유 | 실체 |
|---|---|
| 손잡이를 돌린 정도 | 뷰포트 너비 |
| 물 온도 | 계산된 `font-size` |
| 돌린 만큼 고르게 오르는 온도 | 이상적 값(`1rem + 2vw` 같은 식) |
| 찬물 쪽 멈춤쇠 | 최소값(`clamp()` 의 첫 인자) |
| 뜨거운 물 쪽 멈춤쇠 | 최대값(`clamp()` 의 셋째 인자) |

```text
글자 크기
 40px ┤                    ●━━━━━━━━━  최대 2.5rem 에서 멈춤
      │                  ╱
      │              ╱          ← 1rem + 2vw 직선을 그대로 따름
      │          ╱
 20px ┤━━━━━━━●                  최소 1.25rem 에서 멈춤
      └───────┬───────────┬─────────→ 뷰포트 너비
            200px       1200px
      (예제의 제목 .fluid-heading · 1rem = 16px 가정)
```

> **유동 타이포그래피(fluid typography)** — 글자 크기가 화면 너비를 따라 끊김 없이 변하게 하는 기법이다.\
> 예: 창을 천천히 넓히면 제목이 조금씩 커진다.

## 이 주제가 답하려는 질문

1. `clamp(최소, 이상적, 최대)` 는 세 값 가운데 무엇을 언제 고르나?
2. 이상적 값에 `vw` 만 쓰지 않고 `rem + vw` 를 섞는 까닭은 무엇인가?
3. 「이 너비에서 이 크기, 저 너비에서 저 크기」를 원할 때 이상적 값은 어떻게 구하나?
4. 미디어 쿼리 없이도 반응형이 되는 까닭은 무엇인가?

## 동작 방식

### (1) `clamp()` 가 세 값 중 하나를 고르는 방식

**언제 쓰나** — 값이 어떤 범위를 넘지 않게 묶어 두고 싶을 때 쓴다.
글자 크기에 쓰면 「너무 작지도, 너무 크지도 않은」 크기가 된다.

```text
font-size: clamp(1.25rem, 1rem + 2vw, 2.5rem);
                    │          │          │
                    ▼          ▼          ▼
                 최소 20px  이상적 값   최대 40px
                            먼저 계산
                               │
        ┌──────────────────────┼───────────────────────┐
   이상적 < 최소            최소 ≤ 이상적 ≤ 최대       이상적 > 최대
        │                      │                       │
   최소를 쓴다             이상적 값을 쓴다          최대를 쓴다
```

- 브라우저는 먼저 가운데 이상적 값을 지금의 뷰포트로 계산한다.
- 그 값이 최소보다 작으면 최소를 쓴다.
- 최대보다 크면 최대를 쓴다.
- 둘 사이에 있으면 이상적 값을 그대로 쓴다.

> **뷰포트(viewport)** — 브라우저에서 페이지가 그려지는 보이는 영역이다.\
> 예: 창 너비를 1000px 로 두면 뷰포트 너비도 그 근처다.

### (2) 이상적 값 `rem + vw` 가 직선을 그리는 방식

**언제 쓰나** — 글자가 화면 너비에 비례해 커지게 하되, 출발점을 사용자 글꼴 크기에 맞추고 싶을 때 쓴다.

```text
1rem + 2vw   (1rem = 16px 가정)
   │     │
   │     └─ 2vw = 뷰포트 너비 × 2/100   ← 너비를 따라 오르는 몫(기울기)
   └─────── 16px                         ← 너비와 상관없이 깔리는 몫(출발점)

뷰포트  300px → 16 + 6  = 22px
뷰포트  800px → 16 + 16 = 32px
뷰포트 1500px → 16 + 30 = 46px  → 최대 40px 에 걸린다
```

- `1vw` 는 뷰포트 너비의 100분의 1이다.
- 그래서 `2vw` 는 너비가 100px 늘 때마다 2px 씩 커진다.
- `1rem` 은 너비와 상관없이 늘 같은 몫을 더한다.
- 두 몫을 더하면 「출발점 + 기울기 × 너비」 꼴의 직선이 된다.
- 이 직선을 (1)의 멈춤쇠가 위아래에서 자른다.

> **`vw`** — 뷰포트 너비의 1% 를 1로 치는 길이 단위다.\
> 예: 뷰포트가 1200px 이면 `2vw` 는 24px 이다.

> **`rem`** — 루트 요소(`html`)의 글자 크기를 1로 치는 길이 단위다.\
> 예: 루트 글자 크기가 16px 이면 `1.25rem` 은 20px 이다.

### (3) 최소 · 최대 크기에서 이상적 값을 만드는 공식

**언제 쓰나** — 「뷰포트 A 에서 크기 a, 뷰포트 B 에서 크기 b」처럼 양 끝을 먼저 정한 뒤 가운데 식을 거꾸로 구할 때 쓴다.

원본 팁의 공식은 이것이다.

```text
preferred = minSize + (maxSize - minSize) * (100vw - minViewport) / (maxViewport - minViewport)
```

```text
목표: 뷰포트 400px 에서 16px, 1600px 에서 40px

기울기   = (40 - 16) / (1600 - 400) = 24 / 1200 = 0.02   → 0.02 × 100 = 2vw
출발점   = 16 - 0.02 × 400          = 8px                → 8 / 16   = 0.5rem
이상적 값 = 0.5rem + 2vw

결과: clamp(1rem, 0.5rem + 2vw, 2.5rem)   ← 데모의 공식 박스 예시와 같다
```

- 기울기는 「크기 차이 ÷ 뷰포트 차이」다.
- 기울기에 100을 곱하면 `vw` 앞의 숫자가 된다.
- 출발점은 「최소 크기 − 기울기 × 최소 뷰포트」다.
- 출발점을 16으로 나누면 `rem` 값이 된다(1rem = 16px 가정).
- 최소 · 최대 크기는 그대로 `clamp()` 의 첫 인자와 셋째 인자가 된다.

### (4) 데모의 세 글자 단계

**언제 쓰나** — 제목 · 본문 · 캡션처럼 크기 단계가 여럿일 때 단계마다 `clamp()` 를 따로 준다.

| 요소 | `font-size` | 최소 ~ 최대 (1rem = 16px) | 실제로 변하는 뷰포트 구간 |
|---|---|---|---|
| `.fluid-heading` | `clamp(1.25rem, 1rem + 2vw, 2.5rem)` | 20px ~ 40px | 200px ~ 1200px |
| `.fluid-body` | `clamp(0.875rem, 0.75rem + 0.5vw, 1.125rem)` | 14px ~ 18px | 400px ~ 1200px |
| `.fluid-caption` | `clamp(0.7rem, 0.6rem + 0.3vw, 0.85rem)` | 11.2px ~ 13.6px | 약 533px ~ 약 1333px |

```text
구간 계산 (제목)
1rem + 2vw = 20px  →  16 + 0.02·w = 20  →  w = 200px   ← 이보다 좁으면 최소에 걸림
1rem + 2vw = 40px  →  16 + 0.02·w = 40  →  w = 1200px  ← 이보다 넓으면 최대에 걸림
```

- 단계마다 최소와 최대가 따로 있어 제목은 크게, 캡션은 작게 움직인다.
- 기울기도 다르다: 제목은 `2vw`, 본문은 `0.5vw`, 캡션은 `0.3vw` 다.
- 그래서 창을 넓힐 때 제목이 가장 많이 커진다.
- 구간 밖에서는 각 글자가 멈춤쇠에 붙어 더는 변하지 않는다.
- 공식 박스의 `.formula-title` 과 `.formula-code` 는 `12px` 고정이라 너비를 따라 변하지 않는다.

### (5) `rem` 이 사용자 글꼴 설정을 따라가는 방식

**언제 쓰나** — 사용자가 브라우저 기본 글꼴 크기를 키워 둔 경우에도 글자가 따라 커지게 하고 싶을 때다.

```text
사용자가 기본 글꼴을 16px → 20px 로 바꿈
          │
          ▼
1rem 이 20px 로 바뀜
          │
          ├─ clamp(1.25rem, 1rem + 2vw, 2.5rem)
          │     최소 25px · 출발점 20px · 최대 50px  → 전부 따라 커짐
          │
          ├─ 2vw 만 쓴 값          → 뷰포트에만 묶여 그대로
          │
          └─ font-size: 12px       → 고정, 그대로
```

- `rem` 으로 쓴 몫은 루트 글자 크기를 따라 바뀐다.
- 원본 팁대로, `rem` 으로 쓰면 사용자 폰트 크기 설정이 반영된다.
- `vw` 몫과 `px` 고정값은 루트 글자 크기와 상관이 없어 사용자 설정을 따라가지 않는다.
- 그래서 이상적 값을 `vw` 하나로만 쓰면 사용자 설정이 무시된다.

## 문법 — 형태와 규칙

```html demo
<p class="t">창 폭을 바꿔 보라</p>
<p class="fixed">나는 고정 크기다</p>
<style>
  .t     { font-size: clamp(1rem, 0.5rem + 2vw, 2.5rem); } /* 400px~1600px 에서 16px→40px */
  .fixed { font-size: 12px; }                             /* 너비와 상관없이 같음 */
</style>
```
> **보이는 것** — 창이 좁으면 첫 줄이 16px 근처에서 멈추고, 넓힐수록 커지다 40px 에서 멈춘다; 둘째 줄은 늘 같은 크기다 (코드에서 읽은 것 — 렌더 실측 아님)

- 꼴은 `clamp(최소값, 이상적값, 최대값)` 이다.
- 인자는 쉼표로 가른 세 개다.
- 이상적 값에는 `1rem + 2vw` 처럼 덧셈 식을 바로 쓸 수 있다.
- 이상적 값은 보통 `rem + vw` 조합으로 쓴다.
- 최소와 최대도 `rem` 으로 쓰면 사용자 글꼴 설정을 따라간다.
- 미디어 쿼리 없이 `font-size` 한 줄로 반응형이 된다.
- 값을 손으로 구하기 번거로우면 원본 팁이 권하는 계산 도구 `utopia.fyi` 를 쓴다.

| 자리 | 하는 일 | 흔한 꼴 |
|---|---|---|
| 첫 인자 | 이보다 작아지지 않는다 | `1rem`, `0.875rem` |
| 둘째 인자 | 평소에 쓰일 값, 뷰포트를 따라 변한다 | `1rem + 2vw`, `0.75rem + 0.5vw` |
| 셋째 인자 | 이보다 커지지 않는다 | `2.5rem`, `1.125rem` |

## 어디서 틀리나

### 1. 이상적 값을 `vw` 하나로만 쓴다

`font-size: clamp(1rem, 3vw, 2.5rem)` 처럼 가운데를 `vw` 만으로 쓰면 그 구간의 크기는 뷰포트에만 묶인다.
사용자가 기본 글꼴 크기를 키워도 구간 안의 글자는 따라 커지지 않는다.
가운데에 `rem` 몫을 섞어야 사용자 설정이 반영된다.

### 2. 주석의 px 값은 1rem = 16px 가정이다

정답 코드 주석의 「20px ~ 40px」, 「14px ~ 18px」, 「11.2px ~ 13.6px」 는 루트 글자 크기가 16px 일 때만 맞다.
사용자가 기본 글꼴을 바꾸면 이 px 값도 함께 바뀐다.
공식 박스의 「16px 이하로 줄지 않음 · 40px 이상으로 커지지 않음」도 같은 가정 위에 있다.

### 3. 멈춤쇠가 닿는 뷰포트 구간을 확인하지 않는다

이상적 값의 직선이 최소 · 최대에 닿는 너비는 식마다 다르다.
캡션은 약 1333px 에서야 최대에 닿는다.
이보다 좁은 화면만 다루는 사이트라면 최대값은 사실상 쓰이지 않는다.
양 끝 너비를 먼저 정하고 (3)의 공식으로 거꾸로 구해야 의도한 구간에서 변한다.

### 4. 공식을 CSS 에 그대로 옮긴다

원본 팁의 공식은 수학 식이다.
`calc()` 로 옮길 때는 나눗셈의 오른쪽이 단위 없는 수여야 오래된 규칙에서도 통한다(확인 필요).
예: `calc(16px + 24 * (100vw - 400px) / 1200)` 은 나누는 쪽이 수다.
보통은 (3)처럼 미리 계산해 `0.5rem + 2vw` 꼴로 줄여 쓴다.

### 5. 고정 `px` 과 섞여 있는 것을 놓친다

데모의 `.formula-title` · `.formula-code` 는 `font-size: 12px` 고정이다.
같은 화면 안에서도 이 글자는 뷰포트와 사용자 설정 어느 쪽도 따라가지 않는다.
유동으로 만들 글자와 고정으로 둘 글자를 일부러 골라야 한다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `clamp()` 는 결과를 최소 ~ 최대 사이로 자른다 | CSS 명세의 정의 |
| `1vw` 는 뷰포트 너비의 1% 다 | CSS 명세의 정의 |
| `1rem` 은 루트 요소의 글자 크기다 | CSS 명세의 정의 |
| 1rem = 16px | 브라우저 기본값일 뿐, 사용자가 바꿀 수 있다 — 명세가 보장하지 않는다 |
| 주석의 「20px ~ 40px」 같은 px 범위 | 위 16px 가정에 기대는 계산값 |
| `clamp()` 를 지원하는 브라우저 범위 | 원본에 없음 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 제목 · 본문 크기를 화면 너비에 맞춰 부드럽게 바꾸고 싶다 | `clamp(rem, rem + vw, rem)` | 브레이크포인트마다 `font-size` 를 바꾸는 미디어 쿼리 여러 개 |
| 사용자 글꼴 설정을 존중해야 한다 | `rem` 이 섞인 이상적 값 | `vw` 만 쓴 이상적 값 |
| 코드 조각 · 작은 라벨처럼 크기가 늘 같아야 한다 | 고정값(`12px` 등) | `clamp()` |
| 「이 너비에서 이 크기」가 정해져 있다 | (3)의 공식이나 계산 도구 | 눈대중으로 고른 `vw` 숫자 |

## 핵심 문장

1. **`clamp(최소, 이상적, 최대)` 는 이상적 값을 먼저 계산하고, 범위를 넘으면 가까운 끝으로 자른다.**
2. **이상적 값 `rem + vw` 는 「출발점 + 기울기 × 뷰포트 너비」 직선이다.**
3. **양 끝 너비와 크기를 정하면 공식으로 기울기(`vw`)와 출발점(`rem`)을 거꾸로 구할 수 있다.**
4. **`rem` 몫이 있어야 사용자 글꼴 설정이 반영된다** — `vw` 와 `px` 은 따라가지 않는다.
5. **미디어 쿼리 없이 한 줄로 끊김 없는 반응형 글자가 된다.**

- **유동 타이포그래피** — 글자 크기가 화면 너비를 따라 끊김 없이 변하게 하는 기법.
- **`clamp()`** — 값 하나를 최소와 최대 사이로 묶는 CSS 함수.
- **이상적 값(preferred)** — `clamp()` 의 가운데 인자, 범위 안에서 실제로 쓰이는 값.
- **뷰포트** — 브라우저에서 페이지가 그려지는 보이는 영역.
- **`vw`** — 뷰포트 너비의 1% 를 1로 치는 단위.
- **`rem`** — 루트 요소 글자 크기를 1로 치는 단위.
- **브레이크포인트** — 미디어 쿼리에서 스타일이 바뀌는 화면 너비의 경계.
- **미디어 쿼리** — 화면 조건(너비 등)에 따라 다른 CSS 를 적용하는 문법.
- **기울기** — 뷰포트가 늘 때 글자가 얼마나 빨리 커지는지, `vw` 앞의 숫자.
- **출발점** — 뷰포트와 상관없이 깔리는 몫, 이상적 값의 `rem` 부분.

## 더 들어가면

- `clamp(MIN, VAL, MAX)` 는 명세에서 `max(MIN, min(VAL, MAX))` 와 같게 정의된다고 알려져 있다 — 그래서 최소가 최대보다 크면 최소가 이긴다 (확인 필요).
- 브라우저 확대(줌)를 하면 CSS 기준 뷰포트 너비가 줄어 `vw` 몫이 작아진다. `vw` 비중이 큰 글자는 확대해도 덜 커질 수 있어 접근성 지침과 부딪힌다는 지적이 있다 (확인 필요).
- `100vw` 에 세로 스크롤바 폭이 들어가는지는 브라우저와 운영체제에 따라 다를 수 있다 (확인 필요).
- 같은 방식으로 `padding` · `gap` 같은 간격 값도 유동으로 만들 수 있다 (확인 필요).
- 뷰포트 대신 부모 상자 너비를 기준으로 삼으려면 컨테이너 쿼리 단위(`cqi` 등)를 쓴다 (확인 필요).
