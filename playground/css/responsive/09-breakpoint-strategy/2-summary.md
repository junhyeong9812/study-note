## 한눈에 — 쉽게 말하면

**브레이크포인트는 「옷을 고쳐 입는 기온」이다.**
날씨가 조금씩 바뀔 때마다 옷을 갈아입지는 않는다.
「이 기온부터는 반팔이 춥다」처럼 **몸이 불편해지는 지점**에서만 옷을 바꾼다.
화면 너비도 똑같은 구조다.
너비는 연속으로 바뀌지만, 레이아웃은 **콘텐츠가 불편해지는(깨지는) 너비**에서만 바꾼다.
그 너비가 브레이크포인트다.

| 비유 | 실체 |
|---|---|
| 기온 | 뷰포트 너비 |
| 옷차림 한 벌 | 한 가지 레이아웃(1단 · 2단 · 3단 …) |
| 「이 기온부터 반팔이 춥다」 | `@media (min-width: 640px)` 같은 조건 |
| 남의 옷 기준(달력의 계절) | 디바이스 기준(「아이패드 너비」) |
| 내 몸이 느끼는 기준 | 콘텐츠가 깨지는 지점 |

```text
너비 →  0 ────────── 640 ──── 768 ──────── 1024 ──────── 1280 ──────── 1536 ───→
        │   기본(1단)  │  sm     │   md        │   lg        │   xl        │  2xl
        └ 조건 없음    └ 여기서부터 바뀐다 (min-width: 이 값 이상)
```

## 이 주제가 답하려는 질문

1. 브레이크포인트 값은 어떤 기준으로 정하나 — 디바이스인가, 콘텐츠인가?
2. 흔히 쓰는 값은 무엇이고, 몇 개쯤 두나?
3. 여러 파일에서 같은 값을 쓰려면 그 값을 어디에 모아 두나?
4. (데모) 눈금 막대와 눈금 표시는 CSS 로 어떻게 그리나?

## 동작 방식

### (1) `min-width` 조건이 레이아웃을 갈아 끼운다

**언제 쓰나** — 작은 화면용 스타일을 기본으로 두고, 넓어질 때만 덧씌우고 싶을 때 쓴다.
원본의 코드 예시가 모두 `min-width` 로 쓰여 있는 까닭이 이것이다.

```text
입력:  .cards { 1단 }                              ← 조건 없음: 모든 너비
       @media (min-width: 640px) { .cards { 3단 } }

너비 500  → 조건 거짓 → 1단만 적용      → 1단
너비 640  → 조건 참   → 3단이 덧씌움    → 3단
너비 1200 → 조건 참   → 3단이 덧씌움    → 3단
```

1. 조건 없는 규칙은 어떤 너비에서도 적용된다.
2. `min-width: 640px` 는 「너비가 640px **이상**」일 때 참이다 — 640px 자체도 포함한다.
3. 조건이 참이면 안의 규칙이 뒤에서 같은 선택자를 덮어쓴다.
4. 그래서 작은 화면 스타일을 먼저 쓰고, 브레이크포인트마다 「여기서부터 바뀌는 것」만 덧쓴다.

> **브레이크포인트(breakpoint, 중단점)** — 레이아웃이 바뀌는 뷰포트 너비.\
> 예: 640px 에서 1단 카드가 3단으로 바뀐다.

> **미디어 쿼리** — 화면 조건이 참일 때만 안의 CSS 를 적용하는 `@media` 규칙.\
> 예: `@media (min-width: 768px) { … }`.

### (2) 값을 고르는 두 기준 — 디바이스 대 콘텐츠

**언제 쓰나** — 프로젝트에서 브레이크포인트 목록을 처음 정할 때 쓴다.

```text
디바이스 기준:  「이 폰은 몇 px, 이 태블릿은 몇 px」 → 그 너비에 맞춘다
                → 새 기기가 나오면 기준이 흔들린다
                → 두 기기 사이 너비에서 콘텐츠가 깨져도 모른다

콘텐츠 기준:    창을 천천히 줄인다 → 줄이 너무 길다 / 카드가 찌그러진다 / 메뉴가 넘친다
                → 그 너비가 곧 브레이크포인트
```

1. 디바이스 너비는 기기마다 다르고 계속 바뀌어서, 기기 목록에 맞춘 값은 금방 낡는다.
2. 사용자는 기기 너비 「사이」의 어떤 너비로도 볼 수 있다.
3. 콘텐츠 기준은 「이 레이아웃이 실제로 깨지는 곳」을 직접 찾으므로 어떤 너비에서도 깨지지 않게 된다.
4. 원본이 소개하는 Ethan Marcotte 의 조언이 이것이다 — 브라우저 창을 줄여 가며 레이아웃이 깨지는 지점을 브레이크포인트로 잡는다.
5. 출발점으로는 Tailwind 기본값(640 · 768 · 1024 · 1280 · 1536)이 가장 보편적이다.
6. 다만 이 값은 출발점이고, 프로젝트 콘텐츠를 기준으로 조정하는 것이 이상적이다.
7. 개수는 3~5개가 적정하다 — 많을수록 너비마다 확인할 레이아웃이 늘어 유지보수가 어려워진다.

### (3) 값을 한 곳에 모은다 — Sass 변수 · PostCSS custom media

**언제 쓰나** — 같은 브레이크포인트를 여러 파일 · 여러 규칙에서 쓸 때 쓴다.

```text
입력:  $bp-md: 768px;                         (Sass)
       @custom-media --md (min-width: 768px); (PostCSS)

빌드:  @media (min-width: $bp-md)  ─┐
       @media (--md)               ─┴→  @media (min-width: 768px)

결과:  값을 바꿀 곳이 한 줄뿐이다
```

1. 숫자를 미디어 쿼리마다 직접 쓰면, 값을 조정할 때 모든 곳을 찾아 고쳐야 한다.
2. 원본 팁은 이 값을 CSS 커스텀 프로퍼티(`--bp-md: 768px`)로 관리하기 어렵다고 말한다.
3. 까닭은 미디어 쿼리의 조건 안에는 `var(--bp-md)` 를 쓸 수 없기 때문이다 — 커스텀 프로퍼티는 요소에 적용되는 값이고, 미디어 쿼리 조건은 요소와 상관없이 판단된다.
4. 그래서 원본은 빌드 단계에서 값이 숫자로 바뀌는 두 도구를 권한다 — Sass 변수, PostCSS 의 `@custom-media`.
5. `@custom-media --md (min-width: 768px);` 는 조건 전체에 이름을 붙이고, `@media (--md)` 로 부른다.

> **커스텀 프로퍼티** — `--이름: 값` 으로 정의하고 `var(--이름)` 으로 읽는 CSS 변수.\
> 예: `--gap: 8px; gap: var(--gap);`.

### (4) 데모의 눈금 막대 — flex 비율과 절대 배치

**언제 쓰나** — 막대를 비율로 나누고, 그 아래 특정 위치에 라벨을 꽂을 때 쓴다.

```text
.bp-bar { display: flex }
  mobile flex 2.4 │ tablet 1.6 │ laptop 1.6 │ desktop 1.6 │ wide 1.6     합 8.8
  → 각 구간 폭 = 자기 값 / 8.8

.bp-markers { position: relative }          ← 기준 상자
  .bp-mark { position: absolute; left: 24%; transform: translateX(-50%) }
  → 왼쪽 끝을 24% 에 둔 뒤, 자기 폭의 절반만큼 왼쪽으로 → 가운데가 24% 에 온다
```

1. `display: flex` 인 막대 안에서 `flex: 2.4` · `flex: 1.6` 은 남는 폭을 2.4 : 1.6 비율로 나눈다 — Mobile 이 다른 구간보다 1.5배 넓다.
2. `.bp-markers` 의 `position: relative` 가 마커들의 좌표 기준이 된다.
3. 각 마커는 `position: absolute` 와 인라인 `left: 24%` 같은 백분율로 놓인다.
4. `left` 만 쓰면 마커의 **왼쪽 끝**이 그 좌표에 온다.
5. `transform: translateX(-50%)` 의 50% 는 마커 **자기 폭**의 절반이라, 마커의 가운데가 좌표에 맞는다.
6. 팁 상자는 `flex-direction: column` 과 `gap` 으로 세로로 쌓이고, 코드 상자는 `white-space: pre` 로 줄바꿈과 들여쓰기를 그대로 보인다.

## 문법 — 형태와 규칙

```html demo
<div class="cards">
  <div>A</div><div>B</div><div>C</div>
</div>
<style>
  .cards { display: grid; grid-template-columns: 1fr; gap: 8px; }
  .cards div { padding: 12px; background: #e0e7ff; }
  @media (min-width: 640px) {
    .cards { grid-template-columns: repeat(3, 1fr); }
  }
</style>
```

> **보이는 것** — 창이 640px 보다 좁으면 A · B · C 가 세로 한 줄로, 640px 이상이면 가로 세 칸으로 놓인다. (코드에서 읽은 것 — 렌더 실측 아님)

Tailwind 기본 브레이크포인트:

| 이름 | 값 | 흔한 뜻(대략) |
|---|---|---|
| (없음) | 0 ~ | 기본 · 가장 좁은 화면 |
| `sm` | 640px | 큰 폰 · 작은 태블릿 |
| `md` | 768px | 태블릿 |
| `lg` | 1024px | 랩톱 |
| `xl` | 1280px | 데스크톱 |
| `2xl` | 1536px | 넓은 화면 |

값을 모아 두는 두 꼴(원본 코드 예시와 같은 꼴):

```css
/* PostCSS custom media */
@custom-media --sm (min-width: 640px);
@media (--sm) { .nav { display: flex; } }
```

- `min-width` 는 경계값을 포함한다(이상).
- 작은 화면 규칙을 먼저, 넓은 화면 규칙을 뒤에 둔다 — 뒤의 규칙이 덮어쓴다.
- 값은 3~5개로 두고, 한 곳(Sass 변수 · `@custom-media`)에 모은다.
- 「흔한 뜻」 열은 출발점이지 기준이 아니다 — 최종 값은 콘텐츠가 깨지는 곳으로 정한다.

## 어디서 틀리나

### 1. 기기 목록에 맞춰 값을 고른다
「아이폰 몇 px · 갤럭시 몇 px」을 다 브레이크포인트로 만들면 값이 계속 늘고, 그 사이 너비에서는 여전히 깨질 수 있다.
창을 줄이며 깨지는 지점을 찾는 것이 원본의 권고다.

### 2. Tailwind 기본값을 정답으로 여긴다
640 · 768 · 1024 · 1280 · 1536 은 가장 보편적인 **출발점**일 뿐이다.
내 콘텐츠가 700px 에서 깨진다면 768 을 고집할 까닭이 없다.

### 3. 브레이크포인트가 너무 많다
원본은 3~5개를 적정으로 본다.
하나 늘 때마다 확인할 레이아웃이 하나 늘어 유지보수가 어려워진다.

### 4. 커스텀 프로퍼티로 미디어 쿼리 값을 쓰려 한다
`@media (min-width: var(--bp-md))` 는 미디어 쿼리 조건에서 쓸 수 없다.
Sass 변수나 PostCSS `@custom-media` 처럼 빌드 때 숫자로 바뀌는 방법을 쓴다.

### 5. 데모 막대를 px 비례 눈금자로 읽는다
데모의 마커 좌표는 0 → 24% → 40% → 56% → 72% → 88% 로 16%씩 벌어진다.
그런데 640 → 768 은 128px, 768 → 1024 는 256px 차이다.
즉 막대는 px 비례가 아닌 개념 그림이다.
또 구간 폭은 flex 비율로 2.4/8.8 ≈ 27.3% 에서 Mobile 이 끝나, 640px 마커(24%)와 구간 경계가 어긋난다. (코드에서 읽은 것 — 렌더 실측 아님)

### 6. `translateX(-50%)` 를 부모 폭의 절반으로 오해한다
`transform` 의 백분율은 요소 **자기 상자** 기준이다.
`left: 24%` 의 백분율(기준 상자 폭)과 기준이 다르다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 640 · 768 · 1024 · 1280 · 1536 이 기본 브레이크포인트다 | Tailwind CSS 의 기본 설정 — CSS 표준이 아니다. 버전에 따라 다를 수 있다(확인 필요) |
| `@custom-media` 로 조건에 이름을 붙인다 | PostCSS 플러그인이 빌드 때 바꿔 준다 — 브라우저가 그대로 읽는다고 기대하지 않는다(확인 필요) |
| `$bp-md` 같은 변수가 숫자로 바뀐다 | Sass 컴파일러 |
| `min-width` 는 경계값을 포함한다 · `var()` 는 미디어 쿼리 조건에 못 쓴다 | CSS 명세 |
| `flex` 값의 비율로 폭이 나뉜다 · `translateX(%)` 는 자기 폭 기준이다 | CSS 명세 |
| 브레이크포인트는 3~5개가 적정 · 콘텐츠 기준으로 잡는다 | 누구도 보장하지 않는다 — 원본의 경험칙 · Ethan Marcotte 의 조언 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 새 프로젝트 출발 | Tailwind 기본값을 출발점으로 | 기기 목록 전체를 값으로 |
| 특정 너비에서 카드가 찌그러짐 | 그 너비를 새 브레이크포인트로(또는 기존 값 조정) | 가장 가까운 「표준 값」에 억지로 맞추기 |
| 값을 여러 파일에서 씀 | Sass 변수 · `@custom-media` | 미디어 쿼리마다 숫자 직접 쓰기 · `var()` |
| 값이 여섯 개를 넘어감 | 비슷한 지점을 합쳐 3~5개로 | 너비마다 새 값 추가 |

## 핵심 문장

1. **브레이크포인트는 디바이스가 아니라 콘텐츠가 깨지는 지점에 둔다** — 창을 줄여 가며 찾는다(Ethan Marcotte).
2. **Tailwind 기본값(640 · 768 · 1024 · 1280 · 1536)은 보편적인 출발점이고, 프로젝트 콘텐츠로 조정한다.**
3. **3~5개가 적정하다** — 많으면 유지보수가 어렵다.
4. **값은 한 곳에 모은다** — 미디어 쿼리 조건에는 `var()` 가 안 되므로 Sass 변수나 PostCSS `@custom-media` 를 쓴다.
5. **`min-width` 조건은 「이 값 이상」이며, 작은 화면 규칙 위에 덧씌운다.**

## 용어 풀이

- **브레이크포인트(중단점)** — 레이아웃이 바뀌는 뷰포트 너비.
- **뷰포트** — 브라우저에서 페이지가 그려지는 보이는 영역.
- **미디어 쿼리** — 화면 조건이 참일 때만 CSS 를 적용하는 `@media` 규칙.
- **`min-width` 조건** — 뷰포트 너비가 주어진 값 이상일 때 참인 조건.
- **콘텐츠 기준 브레이크포인트** — 레이아웃이 실제로 깨지는 너비를 값으로 삼는 방식.
- **커스텀 프로퍼티** — `--이름` 으로 정의하고 `var()` 로 읽는 CSS 변수.
- **Sass 변수** — `$이름: 값` 꼴로, 컴파일 때 값으로 바뀌는 변수.
- **PostCSS `@custom-media`** — 미디어 조건에 `--이름` 을 붙여 `@media (--이름)` 으로 부르게 하는 문법(빌드 때 변환).
- **`flex` (단축 속성)** — flex 아이템이 남는 폭을 얼마의 비율로 나눠 가질지 정하는 값.
- **`transform: translateX(-50%)`** — 요소를 자기 폭의 절반만큼 왼쪽으로 옮긴다.

## 더 들어가면

- `@custom-media` 는 CSS 명세 초안(Media Queries Level 5)에 있는 문법이며, 브라우저 기본 지원은 아직 넓지 않아 PostCSS 로 변환해 쓰는 경우가 많다(확인 필요).
- 컨테이너 쿼리(`@container`)는 뷰포트가 아니라 부모 상자의 너비로 조건을 걸어, 콘텐츠 기준 사고를 컴포넌트 단위로 옮길 수 있다(확인 필요).
- 브레이크포인트를 `px` 대신 `em` 으로 쓰면 사용자가 글꼴 크기를 키울 때 레이아웃도 함께 바뀐다는 주장이 있다(확인 필요).
- 레이아웃 대신 `clamp()` 같은 유동 값으로 글자 크기 · 여백을 연속으로 바꾸면 필요한 브레이크포인트 수가 줄어든다(확인 필요).
