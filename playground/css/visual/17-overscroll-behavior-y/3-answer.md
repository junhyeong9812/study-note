## 퀴즈 정답

### 1. 바깥 페이지는 움직이지 않는다

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
`.list` 는 높이 100px 에 문단 다섯이 들어 세로 스크롤이 생긴다.
맨 아래에 닿은 뒤 더 굴린 휠은 `contain` 때문에 바깥 페이지로 넘어가지 않으므로, 2000px 짜리 바깥 페이지는 제자리에 있다.

**왜 그런가**
`contain` 은 원본 설명대로 「세로 스크롤 체이닝 방지」다.
끝에 닿기 전까지는 보통처럼 스크롤되고, 끝 너머의 세로 스크롤만 바깥으로 이어지지 않는다.
근거: 2-summary 「동작 방식 (2)」.

### 2. 바깥 페이지가 이어서 스크롤된다

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
속성 줄을 지우면 기본값 `auto` 가 된다.
`.list` 가 맨 아래에 닿은 뒤의 휠은 감싸는 스크롤 영역인 페이지로 넘어가, 긴 페이지가 아래로 스크롤된다.

**왜 그런가**
`auto` 는 기본 동작, 곧 스크롤 체이닝을 허용하는 값이다.
1번과 2번의 차이가 바로 이 속성이 하는 일이다.
근거: 2-summary 「동작 방식 (1)」 · 「문법 — 형태와 규칙」 표.

### 3. 생기지 않는다 — 상자 안에 스크롤 자체가 없다

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
높이 제한이 없으니 상자가 문단 다섯만큼 늘어나 내용이 넘치지 않는다.
상자 안에서 스크롤될 것이 없으므로 「끝에 닿은 뒤」라는 상황도 없고, 휠은 처음부터 바깥 페이지를 움직인다고 보는 것이 자연스럽다.

**왜 그런가**
`overscroll-behavior-y` 는 스크롤 영역이 끝에 닿은 뒤를 정하는 속성이라, 스크롤이 생기는 상자에서만 뜻이 있다.
스크롤이 없는 상자에서 브라우저가 체이닝을 정확히 어떻게 처리하는지는 정리에서 다루지 않는다 (원본에 근거 없음 — 추론).
근거: 2-summary 「동작 방식 (4)」 · 「어디서 틀리나 1」.

### 4. 끝에서 튕기는 바운스를 남길지 없앨지가 다르기 때문이다

둘 다 세로 체이닝은 막는다.
`none` 은 원본 설명대로 「세로 체이닝과 바운스 모두 방지」이고, `contain` 은 체이닝 방지만 적혀 있다.
그래서 바깥 페이지는 지키되 끝에서 튕기는 느낌은 남기고 싶으면 `contain`, 튕김까지 없애려면 `none` 을 고른다.
근거: 2-summary 「동작 방식 (2)」 · 「동작 방식 (3)」 · 「어디서 틀리나 4」.

### 5. 상자 안에 세로 스크롤이 있어야 「끝」이 생기기 때문이다

`overflow-y: auto` 는 넘치는 내용에 세로 스크롤바를 띄워 그 상자를 스크롤 영역으로 만든다.
`height: 100px` 은 정답 코드 주석대로 「콘텐츠보다 작아 스크롤 발생」을 만든다.
이 둘이 있어야 상자 안에서 스크롤하다 끝에 닿는 상황이 생기고, 그 끝 너머를 `contain` 이 막는다.
근거: 2-summary 「동작 방식 (4)」.

### 6. 끊기지 않는다 — 상속되지 않는다

원본 재료에 「상속: False」로 되어 있다.
바깥 `div` 에 건 값은 그 `div` 자신의 스크롤 끝에만 적용되고, 안쪽 스크롤 상자의 값은 기본값 `auto` 그대로다.
안쪽 상자의 체이닝을 끊으려면 그 상자 자신에 걸어야 한다.
근거: 2-summary 「문법 — 형태와 규칙」 · 「어디서 틀리나 2」.

### 7. 막히지 않는다 — 세로 방향만 다룬다

원본 설명은 「**세로** 방향의 오버스크롤 동작을 제어」이고 값 설명도 모두 「세로 체이닝」이다.
가로 끝에서의 오버스크롤은 이 속성이 손대지 않으므로, 가로 캐러셀 끝에서 넘어가는 동작은 그대로 남는다.
근거: 2-summary 「동작 방식 (5)」 · 「어디서 틀리나 3」.

### 8. 페이지 자체의 세로 오버스크롤이다 — 원본 팁은 `body` 에 `none` 또는 `contain` 을 걸라고 한다

페이지 맨 위에서 더 아래로 당기는 것은 페이지라는 스크롤 영역이 위 끝에 닿은 뒤 그 너머로 더 스크롤하려는 움직임, 곧 세로 오버스크롤이다.
그래서 원본 팁은 모바일에서 pull-to-refresh 를 막으려면 `body` 에 `overscroll-behavior-y: none` 또는 `contain` 을 설정하라고 한다.
다만 브라우저에 따라 `body` 대신 `html` 에 걸어야 할 수 있다는 의심이 정리에 적혀 있다 (확인 필요).
근거: 2-summary 「어디서 틀리나 5」 · 「구현 세부사항 대 언어 보장」.

## 실습 정답

### 실습 1. 바깥 페이지로 새지 않는 세로 스크롤 상자 만들기

**요구 조건 → 정답 코드의 자리**

| 요구 조건 | 정답 코드 |
|---|---|
| 1. `scroll-y` 상자 안에 문단 셋 | `<div class="scroll-y">` 안의 `<p>` 셋 (소개 · 안내 · `overscroll-behavior-y: contain` 표기) |
| 2. 세로 스크롤바가 필요할 때만 | `.scroll-y { overflow-y: auto; }` |
| 3. 내용보다 낮은 고정 높이 | `.scroll-y { height: 100px; }` |
| 4. 세로 끝에서 바깥으로 전파 차단(체이닝만) | `.scroll-y { overscroll-behavior-y: contain; }` |

**정답 코드** — study-practice 의 줄 단위 주석판이다(코드 동작은 원본 예제와 같다).

`css/visual/reference/overscroll-behavior-y.html`

```html
<!DOCTYPE html>
<!-- 문서 타입 선언: HTML5 -->
<html lang="ko">
<!-- 문서 언어: 한국어 -->
<head>
  <meta charset="utf-8">
  <!-- 문자 인코딩: UTF-8 -->
  <title>overscroll-behavior-y - 세로 방향의 오버스크롤 동작을 제어합니다</title>
  <!--
    [시각 효과] overscroll-behavior-y
    설명: 세로 방향의 오버스크롤 동작을 제어합니다
    구문: overscroll-behavior-y: auto | contain | none
    팁: 모바일에서 body의 pull-to-refresh를 방지하려면 body에 overscroll-behavior-y: none 또는 contain 설정.
  -->
  <style>
    /* .scroll-y: 세로 스크롤 영역 - 페이지 전파 차단 */
    .scroll-y {
      overscroll-behavior-y: contain;             /* 세로 스크롤 끝나도 페이지로 전파 차단 - 모바일 당겨서 새로고침 방지에도 유용 */
      overflow-y: auto;                           /* 세로 스크롤바 자동 */
      height: 100px;                              /* 높이 100px - 콘텐츠보다 작아 스크롤 발생 */
      background: #fef3c7;                        /* 연노랑 배경 */
      padding: 16px;                              /* 안쪽 여백 16px */
      border-radius: 8px;                         /* 모서리 둥글게 */
      width: 220px;                               /* 너비 220px */
      margin: 30px auto;                          /* 위아래 30px, 가로 중앙 */
      border: 2px solid #f59e0b;                  /* 주황 테두리 */
      font-size: 13px;                            /* 글자 13px */
      color: #92400e;                             /* 짙은 갈색 글자 */
      line-height: 1.6;                           /* 줄간격 1.6배 */
    }
  </style>
</head>
<body>
  <!-- 세로 오버스크롤 격리 데모 -->
  <div class="scroll-y">
    <!-- contain으로 페이지 스크롤 전파 차단된 세로 영역 -->
    <p>세로 스크롤 영역입니다.</p>
    <!-- 첫 번째 문단 -->
    <p>아래로 더 스크롤해도 바깥 페이지가 스크롤되지 않습니다.</p>
    <!-- 두 번째 문단 -->
    <p>overscroll-behavior-y: contain</p>
    <!-- 적용된 속성 표기 -->
  </div>

</body>
</html>
```

원본 예제의 나머지 조각(study-practice 에는 없고 study-site 항목 데이터에만 있다):

```css
.scroll-y { overscroll-behavior-y: contain; overflow-y: auto; height: 100px; background: #fef3c7; padding: 16px; border-radius: 8px; width: 220px; margin: 30px auto; border: 2px solid #f59e0b; font-size: 13px; color: #92400e; line-height: 1.6; }
```

**실행 결과** — 실행하지 않음 — 브라우저 화면에서 결과를 보는 예제다 — 글로 옮길 출력이 없다.

**풀이 요점**
- 핵심은 `overscroll-behavior-y: contain` 한 줄이다 — 상자 끝 너머의 세로 스크롤을 바깥 페이지로 넘기지 않는다.
- `overflow-y: auto` 와 `height: 100px` 은 상자에 세로 스크롤을 만들어 「끝」이 생기게 하는 짝이다.
- 요구 조건 4가 「체이닝만 막는 값」이라 `none` 이 아니라 `contain` 이다 — `none` 은 바운스까지 막는다.
- 정답 코드의 페이지에는 상자 말고 내용이 거의 없어 페이지 자체가 스크롤되지 않으므로, 차단 효과를 보려면 바깥 페이지를 길게 만들어 봐야 한다 (원본에 근거 없음 — 추론).
- 배경 · 테두리 · 글꼴 같은 나머지 줄은 꾸밈이며 오버스크롤 동작과 관계없다.
