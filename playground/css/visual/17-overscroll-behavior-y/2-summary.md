## 한눈에 — 쉽게 말하면

**`overscroll-behavior-y` 는 「엘리베이터의 맨 위·맨 아래 층에 다는 차단막」이다.**
엘리베이터(안쪽 스크롤 영역)가 맨 아래 층에 닿았는데도 계속 「아래로」 버튼을 누르면, 보통은 그 힘이 건물 전체(바깥 페이지)로 넘어가 건물이 움직인다.
차단막을 달면 엘리베이터가 끝 층에 닿은 뒤로는 아무리 눌러도 건물이 꿈쩍하지 않는다.
세로 스크롤 영역도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 엘리베이터 | 안쪽 세로 스크롤 영역(`overflow-y: auto` 인 상자) |
| 맨 위·맨 아래 층 | 스크롤 영역의 위 끝·아래 끝 |
| 건물 전체가 움직임 | 바깥 페이지로 스크롤이 넘어감(스크롤 체이닝) |
| 차단막 | `overscroll-behavior-y: contain` 또는 `none` |
| 끝 층에서 덜컹하는 반동 | 바운스(끝에서 튕기는 효과) |

```text
┌──────── 페이지 ────────┐
│                        │
│   ┌── .scroll-y ──┐    │
│   │ 문단 1        │    │   ← 안쪽을 아래로 스크롤
│   │ 문단 2        │    │
│   │ 문단 3 (끝)   │    │   ← 끝에 닿은 뒤 더 굴리면?
│   └───────────────┘    │
│                        │        auto    → 페이지가 이어서 스크롤된다
└────────────────────────┘        contain → 페이지는 그대로다
```

## 이 주제가 답하려는 질문

1. 안쪽 세로 스크롤 영역이 끝에 닿은 뒤 더 스크롤하면 그 움직임은 어디로 가나?
2. `auto` · `contain` · `none` 세 값은 각각 무엇을 막고 무엇을 남기나?
3. 모바일에서 페이지를 아래로 당겨 새로고침되는 동작을 막으려면 어디에 무엇을 거나?
4. 이 속성이 효과를 내려면 그 상자가 어떤 조건을 갖춰야 하나?

## 동작 방식

### (1) 기본값 `auto` — 끝에 닿으면 바깥으로 넘어간다

**언제 쓰나** — 따로 지정하지 않은 모든 상자의 기본 동작이다.
안쪽과 바깥이 하나로 이어져 스크롤되는 것이 자연스러울 때 그대로 둔다.

```text
입력: .box { overflow-y: auto; height: 100px; }   (overscroll-behavior-y 지정 없음 = auto)

안쪽 아래로 스크롤 ──▶ 안쪽 끝에 닿음 ──▶ 계속 굴림 ──▶ 바깥 페이지가 스크롤됨
```

- 사용자가 안쪽 상자 위에서 아래로 스크롤하면 먼저 안쪽 상자가 스크롤된다.
- 안쪽 상자가 아래 끝에 닿으면 더 갈 곳이 없다.
- 그 뒤의 스크롤은 감싸고 있는 바깥 스크롤 영역(대개 페이지)으로 넘어간다.
- 이렇게 넘어가는 것을 스크롤 체이닝이라 한다.

> **스크롤 체이닝** — 안쪽 스크롤 영역이 끝에 닿은 뒤의 스크롤이 바깥 스크롤 영역으로 이어지는 동작.\
> 예: 모달 안 목록을 끝까지 내린 뒤 더 굴렸더니 모달 뒤 페이지가 내려간다.

> **오버스크롤** — 스크롤 영역이 끝에 닿은 상태에서 그 너머로 더 스크롤하려는 움직임.\
> 예: 목록 맨 아래에서 손가락으로 한 번 더 위로 밀어 올리는 것.

### (2) `contain` — 세로 체이닝만 끊는다

**언제 쓰나** — 안쪽 영역을 끝까지 내려도 바깥 페이지가 따라 움직이지 않게 할 때 쓴다.
원본 예제가 바로 이 값을 쓴다.

```text
입력: .scroll-y { overscroll-behavior-y: contain; overflow-y: auto; height: 100px; }

안쪽 아래로 스크롤 ──▶ 안쪽 끝에 닿음 ──▶ 계속 굴림 ──▶ 바깥 페이지는 그대로
                                                    (바운스 같은 그 상자 안의 끝 효과는 남을 수 있다)
```

- 안쪽 상자가 끝에 닿을 때까지는 `auto` 와 똑같이 스크롤된다.
- 끝에 닿은 뒤의 세로 스크롤은 바깥으로 넘어가지 않는다.
- 원본은 `contain` 을 「세로 스크롤 체이닝 방지」라고만 설명한다.
- `none` 의 설명이 「체이닝과 바운스 **모두**」인 것과 견주면, `contain` 은 바운스까지 막지는 않는 값으로 읽힌다.

> **바운스** — 스크롤 영역 끝에서 더 밀면 내용이 살짝 늘어났다가 튕겨 돌아오는 효과.\
> 예: 모바일 브라우저에서 페이지 맨 위를 아래로 당기면 내용이 출렁인다.

### (3) `none` — 세로 체이닝과 바운스를 모두 막는다

**언제 쓰나** — 바깥으로 넘어가는 것도, 끝에서 튕기는 효과도 둘 다 원하지 않을 때 쓴다.

```text
입력: .panel { overscroll-behavior-y: none; overflow-y: auto; height: 100px; }

안쪽 아래로 스크롤 ──▶ 안쪽 끝에 닿음 ──▶ 계속 굴림 ──▶ 바깥 페이지 그대로 + 튕김 없음
```

- 끝에 닿기 전까지는 다른 값과 같다.
- 끝에 닿은 뒤에는 바깥으로 넘어가지 않는다.
- 끝에서 튕기는 효과도 일어나지 않는다.

### (4) 이 속성은 「스크롤되는 상자」에서만 뜻이 있다

**언제 쓰나** — 속성을 걸었는데 아무 변화가 없을 때 가장 먼저 확인할 조건이다.

```text
입력: overflow-y: auto  +  height: 100px  +  높이보다 긴 내용(문단 셋)

내용 > 상자 높이 ──▶ 상자 안에 세로 스크롤 발생 ──▶ 끝이 생김 ──▶ overscroll-behavior-y 가 끝에서의 동작을 정함
```

- 원본 정답 코드는 `overflow-y: auto` 로 세로 스크롤바를 필요할 때 띄운다.
- `height: 100px` 은 주석대로 「콘텐츠보다 작아 스크롤 발생」을 노린 값이다.
- 오버스크롤은 「끝에 닿은 뒤」의 일이므로, 스크롤 자체가 없는 상자에는 정할 「끝 너머」가 없다.
- 그래서 세 줄(`overscroll-behavior-y` · `overflow-y` · 고정 높이)이 한 묶음으로 쓰인다.

> **스크롤 영역(스크롤 컨테이너)** — 내용이 넘칠 때 그 안에서 스크롤되도록 `overflow` 가 설정된 상자.\
> 예: `overflow-y: auto; height: 100px;` 인 `div`.

### (5) 이름의 `-y` — 세로 방향만 다룬다

**언제 쓰나** — 가로 스크롤과 세로 스크롤을 따로 다뤄야 할 때 이 이름을 고른다.

```text
입력: overscroll-behavior-y: contain;

세로 끝에서의 오버스크롤 ──▶ contain 적용 (바깥으로 안 넘어감)
가로 끝에서의 오버스크롤 ──▶ 이 속성과 무관 (가로 쪽은 손대지 않음)
```

- 원본 설명은 「**세로** 방향의 오버스크롤 동작을 제어」다.
- 값 설명도 모두 「세로 스크롤 체이닝」 「세로 체이닝」이라고 방향을 밝힌다.
- 따라서 이 속성은 가로 방향의 동작을 바꾸지 않는다.

```html demo
<div style="height:400px;padding:20px;">
  <div class="scroll-y">
    <p>문단 1</p><p>문단 2</p><p>문단 3</p><p>문단 4</p>
  </div>
  <p>바깥 페이지의 내용</p>
</div>
<style>
  .scroll-y {
    overscroll-behavior-y: contain;
    overflow-y: auto;
    height: 100px;
    width: 220px;
    border: 2px solid #f59e0b;
    background: #fef3c7;
  }
</style>
```

> **보이는 것** — 높이 100px 인 노란 상자 안에 문단 넷이 들어가 상자 안에 세로 스크롤이 생기고, 상자 아래에 바깥 문단이 놓인다 (코드에서 읽은 것 — 렌더 실측 아님)

## 문법 — 형태와 규칙

```css
/* 모달 안 목록: 끝까지 내려도 뒤 페이지는 그대로 */
.modal-list {
  overflow-y: auto;               /* 세로로 스크롤되는 상자로 만든다 */
  max-height: 300px;              /* 내용이 넘치도록 높이를 제한한다 */
  overscroll-behavior-y: contain; /* 세로 체이닝을 끊는다 */
}

/* 원본 팁: 모바일 당겨서 새로고침 막기 */
body {
  overscroll-behavior-y: none;    /* 또는 contain */
}
```

`overscroll-behavior-y: auto | contain | none`

| 값 | 원본 설명 | 바깥으로 넘어가나(체이닝) | 끝에서 튕기나(바운스) |
|---|---|---|---|
| `auto` | 기본 동작 (기본값) | 넘어간다 | 기본 동작대로 |
| `contain` | 세로 스크롤 체이닝 방지 | 막는다 | 원본은 막는다고 하지 않는다 |
| `none` | 세로 체이닝과 바운스 모두 방지 | 막는다 | 막는다 |

- 기본값은 `auto` 다.
- 상속되지 않는다(원본 「상속: False」) — 부모에 걸어도 자식 상자의 값은 `auto` 그대로다.
- 애니메이션되지 않는다(원본 「애니메이션 가능: False」) — `transition` 을 걸어도 값이 서서히 바뀌지 않고 바로 바뀐다.
- 값은 키워드 셋뿐이다 — 길이나 숫자를 받지 않는다.
- 효과는 그 상자가 세로로 스크롤될 때 드러난다 — `overflow-y: auto`(또는 스크롤이 생기는 다른 값)와 내용보다 작은 높이를 함께 둔다.
- 키워드: 세로 오버스크롤 · 수직 스크롤 체이닝 · 당겨서 새로고침 방지.

## 어디서 틀리나

### 1. 속성만 걸고 상자가 스크롤되지 않는다

`overscroll-behavior-y` 는 「끝에 닿은 뒤」를 정한다.
`overflow-y` 가 없거나 높이 제한이 없어 상자가 내용만큼 늘어나면, 상자 안에 스크롤이 없고 끝도 없다.
원본 정답 코드가 `overflow-y: auto` 와 `height: 100px` 을 같이 둔 까닭이다.

### 2. 부모에 걸면 안쪽 상자까지 적용될 거라 기대한다

이 속성은 상속되지 않는다.
바깥 `div` 에 `contain` 을 걸어도 그 안의 다른 스크롤 상자는 여전히 `auto` 다.
체이닝을 끊고 싶은 **그 스크롤 상자 자신**에 건다.

### 3. `-y` 로 가로 스크롤까지 막힐 거라 기대한다

이름 그대로 세로만 다룬다.
가로로 스크롤되는 캐러셀 끝에서 넘어가는 것을 막는 일은 이 속성의 몫이 아니다.

### 4. `contain` 과 `none` 을 같은 값으로 여긴다

둘 다 바깥으로 넘어가는 것은 막는다.
차이는 바운스다 — 원본은 `none` 만 「바운스까지 모두 방지」라고 적는다.
끝에서 튕기는 손맛을 남기고 싶으면 `contain`, 그마저 없애려면 `none` 을 고른다.

### 5. 원본 팁 — 모바일 당겨서 새로고침 막기

원본 팁: 「모바일에서 body 의 pull-to-refresh 를 방지하려면 body 에 `overscroll-behavior-y: none` 또는 `contain` 설정.」
페이지 맨 위에서 아래로 당기는 움직임은 페이지 자체의 세로 오버스크롤이다.
그래서 페이지 쪽에 세로 오버스크롤 제어를 걸면 그 움직임이 새로고침으로 이어지지 않게 할 수 있다.
`none` 은 바운스까지 없애고, `contain` 은 체이닝만 막는다는 차이는 위 4번과 같다.

원본의 주장 → 왜 의심스러운가: 팁은 「body 에」 걸라고 하지만, 브라우저에 따라 페이지 전체 스크롤을 맡는 것이 `body` 가 아니라 루트 `html` 요소일 수 있어 `body` 에만 걸면 효과가 없을 수 있다 (확인 필요).

### 6. 애니메이션으로 서서히 바꾸려 한다

애니메이션 가능하지 않은 속성이다.
`transition: overscroll-behavior-y 1s` 같은 것을 써도 중간 단계 없이 한 번에 바뀐다.
애초에 「반쯤 막힌」 중간값이 있는 속성이 아니다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `contain` · `none` 이 세로 스크롤 체이닝을 막는다 | CSS 속성의 정의(원본 값 설명) |
| 끝에서 튕기는 바운스가 생기는지, 어떤 모양인지 | 브라우저 · 운영체제의 스크롤 구현 — 플랫폼마다 다르다 (확인 필요) |
| 당겨서 새로고침(pull-to-refresh)이 있는지 | 브라우저 기능 — 모든 브라우저에 있는 동작이 아니다 (확인 필요) |
| 당겨서 새로고침을 막으려면 `body` 에 건다 | 원본 팁 — 실제로 `body` 와 `html` 중 어디에 걸어야 듣는지는 브라우저에 따라 다를 수 있다 (확인 필요) |
| 기본값 `auto` · 상속 안 됨 · 애니메이션 불가 | CSS 속성의 정의(원본 재료) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 모달 · 사이드 패널 안 목록을 끝까지 내려도 뒤 페이지가 움직이면 안 된다 | 그 목록 상자에 `contain` | 아무것도 안 건 `auto` |
| 채팅창처럼 끝에서 튕김조차 없어야 한다 | `none` | `contain`(바운스가 남을 수 있다) |
| 모바일 웹앱에서 당겨서 새로고침을 막는다 | 페이지 쪽에 `none` 또는 `contain` (원본 팁) | 안쪽 작은 상자에만 걸기 |
| 안쪽과 바깥이 하나로 이어져 내려가야 자연스럽다 | `auto`(기본값 그대로) | `contain` · `none` |
| 가로 캐러셀 끝에서 넘어가는 것을 막는다 | 세로가 아닌 가로용 속성 | `overscroll-behavior-y` |
| 상자 안에 스크롤이 생기지 않는다 | 먼저 `overflow-y` 와 높이 제한 | 이 속성만 덩그러니 |

## 핵심 문장

1. **`overscroll-behavior-y` 는 세로 스크롤 영역이 끝에 닿은 「뒤」의 동작을 정한다** — 그 전의 스크롤은 바꾸지 않는다.
2. **`auto` 는 바깥으로 넘어가게 두고, `contain` 은 체이닝을 끊고, `none` 은 체이닝과 바운스를 모두 끊는다.**
3. **스크롤되는 상자에 걸어야 뜻이 있다** — `overflow-y` 와 내용보다 작은 높이가 짝이다.
4. **상속되지 않고 세로만 다룬다** — 막고 싶은 그 스크롤 상자에, 세로 문제에만 건다.
5. **모바일 당겨서 새로고침은 페이지 쪽에 `none` 또는 `contain` 으로 막는다**(원본 팁).

## 용어 풀이

- **오버스크롤** — 스크롤 영역이 끝에 닿은 상태에서 그 너머로 더 스크롤하려는 움직임.
- **스크롤 체이닝** — 안쪽 스크롤 영역 끝에서의 스크롤이 바깥 스크롤 영역으로 이어지는 동작.
- **바운스** — 스크롤 끝에서 더 밀면 내용이 살짝 밀렸다가 튕겨 돌아오는 효과.
- **스크롤 영역(스크롤 컨테이너)** — 내용이 넘칠 때 그 안에서 스크롤되도록 `overflow` 가 설정된 상자.
- **당겨서 새로고침(pull-to-refresh)** — 모바일에서 페이지 맨 위를 아래로 당기면 페이지가 새로 불러와지는 동작.
- **`overflow-y`** — 세로로 넘치는 내용을 어떻게 다룰지(숨김 · 스크롤 등) 정하는 속성.
- **상속** — 부모에 건 속성 값이 자식에게 저절로 이어지는 것.

## 더 들어가면

- 가로 방향을 맡는 짝 속성 `overscroll-behavior-x` 와, 두 방향을 한 번에 쓰는 축약 속성 `overscroll-behavior` 가 있다 (확인 필요).
- 축약 `overscroll-behavior: contain none;` 처럼 값 둘을 주면 첫 값이 가로, 둘째 값이 세로에 들어가는 것으로 알려져 있다 (확인 필요).
- 논리 속성판으로 `overscroll-behavior-block` · `overscroll-behavior-inline` 이 있어, 세로쓰기 문서에서는 이쪽이 쓰기 방향을 따른다 (확인 필요).
- `overflow-y: auto` 여도 내용이 높이를 넘지 않아 실제 스크롤이 없는 상자에서 체이닝이 어떻게 처리되는지는 브라우저마다 다를 수 있다 (확인 필요).
- 예전에는 모달 뒤 페이지 스크롤을 막으려고 JavaScript 로 `body` 에 `overflow: hidden` 을 붙이거나 터치 이벤트의 기본 동작을 막는 방법을 썼는데, 이 속성은 그 일의 일부를 CSS 만으로 맡는다 (확인 필요).
