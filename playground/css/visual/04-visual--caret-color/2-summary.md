## 한눈에 — 쉽게 말하면

**`caret-color` 는 「원고지 위에 꽂아 두는 자리 표시 핀의 색」이다.**
원고지에 글을 쓰다 잠깐 멈출 때, 다음 글자가 들어갈 칸에 핀을 꽂아 둔다고 해 보자.
핀의 색을 바꿔도 이미 쓴 글자의 색은 그대로이고, 핀이 가리키는 자리도 그대로다.
바뀌는 것은 오직 「다음 글자가 들어갈 자리」를 알려 주는 표시의 색뿐이다.
입력 칸 안에서 깜빡이는 세로 막대(캐럿)도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 원고지 | `<input>` · `<textarea>` · `contenteditable` 요소 |
| 이미 쓴 글자 | 입력된 텍스트 (`color` 가 정한다) |
| 자리 표시 핀 | 캐럿(깜빡이는 입력 커서) |
| 핀의 색 | `caret-color` 값 |
| 핀 색을 따로 정하지 않음 | `caret-color: auto` (기본값) |

```text
 ┌────────────────────────────┐
 │ hello│                     │   ← 글자 "hello" 의 색 = color
 └────────────────────────────┘
        ↑
        캐럿(깜빡이는 막대)의 색 = caret-color
```

> **캐럿(caret)** — 텍스트를 입력할 자리에서 깜빡이는 세로 막대다.\
> 예: 검색창을 클릭하면 글자 앞에서 깜빡이는 `|` 모양의 막대.

## 이 주제가 답하려는 질문

1. 입력 칸 안의 깜빡이는 막대 색은 무엇이 정하고, 어떻게 바꾸나?
2. 값을 정하지 않으면(`auto`) 막대는 무슨 색이 되나?
3. 부모에 준 `caret-color` 는 자식 입력 칸까지 내려가나?
4. 캐럿 색을 바꿀 때 함께 손봐야 할 포커스 스타일은 무엇인가?

## 동작 방식

### (1) 값이 `auto` 인가, 색인가

**언제 쓰나** — 캐럿을 글자색과 다른 색(예: 브랜드 색)으로 보이게 하고 싶을 때 쓴다.
아무것도 쓰지 않으면 `auto` 가 적용된다.

```text
입력 코드                          무엇이 일어나나                       결과
─────────────────────────────    ──────────────────────────────     ─────────────────────
input { color: #333;             caret-color 를 안 썼다              캐럿 = 브라우저 기본색
        }                         → 기본값 auto                       (보통 글자색 #333)
input { color: #333;             caret-color 에 <color> 를 줬다       캐럿 = #f43f5e
        caret-color: #f43f5e; }   → 글자색과 상관없이 그 색             글자는 여전히 #333
```

- 첫째 줄: `caret-color` 를 적지 않으면 기본값 `auto` 가 쓰인다.
- 원본은 `auto` 를 「브라우저 기본 색상, 보통 `currentColor`」라고 설명한다.
- 그래서 `auto` 일 때 캐럿은 대개 글자색(`color`)을 따라간다.
- 둘째 줄: `<color>` 를 주면 캐럿만 그 색이 되고, 입력된 글자의 색은 `color` 가 그대로 정한다.

> **`currentColor`** — 「이 요소의 현재 `color` 값」을 가리키는 CSS 키워드다.\
> 예: `color: blue` 인 요소에서 `border-color: currentColor` 는 파란 테두리가 된다.

### (2) 부모에서 자식으로 상속된다

**언제 쓰나** — 폼 전체의 캐럿 색을 한 번에 맞추고 싶을 때, 입력 칸마다 쓰지 않고 감싸는 부모에 한 번 쓴다.

```text
입력 코드                              무엇이 일어나나                     결과
─────────────────────────────────    ─────────────────────────────     ──────────────────────
.form { caret-color: teal; }         caret-color 는 상속되는 속성이다    .form 안의 모든 input,
<form class="form">                   → 자식이 값을 따로 안 쓰면           textarea 캐럿 = teal
  <input> <textarea>                    부모 값을 물려받는다
</form>
```

- 원본 재료에 따르면 `caret-color` 는 상속(`True`)된다.
- 자식에 `caret-color` 를 따로 쓰지 않으면 부모의 계산된 값을 물려받는다.
- 자식에 따로 쓰면 그 자식에서는 자식의 값이 이긴다.

> **상속(inheritance)** — 자식 요소가 값을 정하지 않은 속성을 부모의 값으로 채우는 CSS 규칙이다.\
> 예: `body { color: navy; }` 이면 `color` 를 따로 안 쓴 `<p>` 도 남색 글자다.

### (3) 포커스 스타일과 짝지어 쓴다 · `contenteditable` 에도 된다

**언제 쓰나** — 캐럿 색을 브랜드 색으로 바꿨다면, 포커스가 들어온 입력 칸의 테두리도 같은 색으로 바꿔 「지금 여기에 입력 중」이라는 신호를 하나로 맞출 때 쓴다.

```text
입력 코드                                     무엇이 일어나나                          결과
──────────────────────────────────────     ─────────────────────────────────      ──────────────────────
.styled-input { caret-color: #f43f5e;       평소: 연회색 테두리, 외곽선 없음         클릭 전: 회색 테두리
  border: 2px solid #e2e8f0;
  outline: none;
  transition: border-color 0.2s; }
.styled-input:focus {                        클릭 → :focus 가 맞는다                 클릭 후: 핑크 테두리 +
  border-color: #f43f5e; }                   → 테두리 색이 0.2초에 걸쳐 바뀐다       핑크 캐럿 깜빡임
```

- 평소에는 연회색 테두리이고, 브라우저 기본 포커스 외곽선은 `outline: none` 으로 지워져 있다.
- 입력 칸을 클릭하면 `:focus` 선택자가 맞아 테두리 색이 캐럿과 같은 핑크로 바뀐다.
- `transition: border-color 0.2s` 때문에 그 색 변화가 0.2초에 걸쳐 부드럽게 일어난다.
- 캐럿은 포커스가 있을 때만 깜빡이므로, 캐럿 색과 포커스 테두리 색이 같은 순간에 함께 나타난다.
- 원본 팁대로 `caret-color` 는 `contenteditable` 요소(편집 가능한 일반 요소)에도 적용된다.

> **`:focus`** — 요소가 키보드 입력을 받을 상태(포커스)일 때 맞는 의사 클래스다.\
> 예: 입력 칸을 클릭하거나 Tab 으로 옮겨 오면 `input:focus` 규칙이 적용된다.

> **`contenteditable`** — 일반 요소를 사용자가 직접 편집할 수 있게 만드는 HTML 속성이다.\
> 예: `<div contenteditable>` 을 클릭하면 그 안에 글자를 쓸 수 있고 캐럿도 생긴다.

## 문법 — 형태와 규칙

```html demo
<input class="a" type="text" placeholder="기본 캐럿">
<input class="b" type="text" placeholder="핑크 캐럿">
<div class="c" contenteditable>여기도 편집해 보세요</div>
<style>
  input, .c { display: block; margin: 12px; padding: 8px; border: 1px solid #ccc; }
  .a { color: #334155; }                      /* caret-color 생략 → auto */
  .b { color: #334155; caret-color: #f43f5e; } /* 캐럿만 핑크 */
  .c { caret-color: #0ea5e9; }                 /* contenteditable 에도 적용 */
</style>
```

> **보이는 것** — 첫 칸은 글자색과 비슷한 어두운 캐럿, 둘째 칸은 글자는 어둡고 캐럿만 핑크, 셋째 편집 영역은 하늘색 캐럿이 깜빡인다 (코드에서 읽은 것 — 렌더 실측 아님)

| 값 | 뜻 | 비고 |
|---|---|---|
| `auto` | 브라우저 기본 색상 | 기본값. 원본 설명으로는 보통 `currentColor` 와 같다 |
| `<color>` | 지정한 색 | `#f43f5e` · `rgb(…)` · `hsl(…)` · `red` · `currentColor` 등 색이면 무엇이든 |

- 형태: `caret-color: auto | <color>`
- 기본값은 `auto` 다.
- 상속된다 — 부모에 한 번 쓰면 자식 입력 칸들이 물려받는다.
- 애니메이션 가능하다 — `transition` · `@keyframes` 로 색이 바뀌는 과정을 보간할 수 있다.
- 바뀌는 것은 캐럿의 색뿐이다 — 글자색 · placeholder 색 · 마우스 포인터 모양은 그대로다.

## 어디서 틀리나

### 1. 캐럿 색과 글자색을 헷갈린다

`caret-color` 는 입력된 글자의 색을 바꾸지 않는다.
글자색은 `color` 가 정한다.
`caret-color` 만 쓰고 「글자도 핑크가 되겠지」라고 기대하면 틀린다.

### 2. placeholder 색도 바뀐다고 생각한다

안내 문구(`placeholder`)는 캐럿이 아니다.
`caret-color` 를 바꿔도 안내 문구의 색은 그대로다.

### 3. 마우스 포인터 색이 바뀐다고 생각한다

「커서」라는 말 때문에 마우스 포인터와 섞기 쉽다.
`caret-color` 의 대상은 글을 쓸 자리에서 깜빡이는 텍스트 커서(캐럿)뿐이다.
마우스 포인터의 모양은 다른 속성(`cursor`)의 일이다.

### 4. `auto` 는 늘 「검정」이라고 외운다

원본은 `auto` 를 「브라우저 기본 색상, 보통 `currentColor`」라고 설명한다.
즉 대개 글자색을 따라가므로, 글자색을 흰색으로 바꾼 어두운 입력 칸에서는 캐럿도 밝게 보이는 것이 보통이다.
「보통」이라는 말대로 정확한 색은 브라우저가 고른다.

### 5. 브랜드 색과 통일하라 (원본 팁)

캐럿 색을 브랜드 색과 맞추면 작지만 눈에 띄는 UX 디테일이 된다.
원본 정답 코드는 캐럿과 `:focus` 테두리를 같은 `#f43f5e` 로 맞춰 「입력 중」 신호를 한 색으로 묶는다.

### 6. `contenteditable` 에도 적용된다 (원본 팁)

`<input>` · `<textarea>` 만이 아니라 `contenteditable` 로 편집 가능해진 요소에도 쓸 수 있다.
리치 텍스트 편집기처럼 `<div>` 를 편집 영역으로 쓰는 경우에도 캐럿 색을 맞출 수 있다.

### 7. `outline: none` 만 쓰고 대체 표시를 빠뜨린다

원본 정답 코드는 기본 포커스 외곽선을 `outline: none` 으로 지운다.
대신 `:focus` 에서 테두리 색을 바꿔 포커스를 알린다.
외곽선만 지우고 대체 표시를 두지 않으면, 키보드로 이동하는 사람은 지금 어느 칸에 있는지 알기 어렵다.
캐럿 색만으로는 그 역할을 맡기기 부족하다 — 캐럿은 가는 막대라 눈에 잘 안 띌 수 있다.

### 8. 원본 주석의 「16px = 모바일 줌 방지 임계값」

원본 정답 코드의 `font-size: 16px` 주석은 「모바일 줌 방지 임계값」이라고 적는다.
이것은 `caret-color` 와 상관없는 이야기이고, 특정 모바일 브라우저의 동작에 대한 주장이다.
CSS 가 보장하는 규칙이 아니다 — 아래 「구현 세부사항 대 언어 보장」 표를 본다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `caret-color` 의 기본값은 `auto` 다 | CSS 명세 (원본 재료의 기본값) |
| `caret-color` 는 상속된다 · 애니메이션 가능하다 | CSS 명세 (원본 재료의 상속 · 애니메이션 표기) |
| `auto` 일 때 캐럿은 「보통」 `currentColor` 와 같다 | 브라우저 — 원본도 「보통」이라 쓴다. 정확한 색은 브라우저가 고른다 (확인 필요) |
| 캐럿의 깜빡임 · 굵기 · 모양 | 브라우저 · 운영체제 — `caret-color` 는 색만 다룬다 (확인 필요) |
| 입력 글자가 16px 보다 작으면 포커스 때 화면이 확대된다 | 특정 모바일 브라우저의 동작 — CSS 명세가 아니다. 원본 주석의 주장일 뿐이다 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 입력 칸의 깜빡이는 막대 색만 브랜드 색으로 | `caret-color: <color>` | `color` (글자까지 바뀐다) |
| 폼 전체의 캐럿 색을 한 번에 | 부모에 `caret-color` (상속) | 입력 칸마다 같은 값 반복 |
| 글자색에 맞춰 캐럿이 따라가게 | `caret-color: auto` (기본값) 그대로 | 고정 색 지정 |
| 포커스를 시각적으로 알리기 | `:focus` 의 테두리 · 외곽선 | 캐럿 색만으로 알리기 |
| 마우스 포인터 모양 바꾸기 | `cursor` | `caret-color` |
| 편집 가능한 `div` 의 캐럿 | `contenteditable` 요소에 `caret-color` | — |

## 핵심 문장

1. **`caret-color` 는 깜빡이는 입력 커서의 색만 바꾼다** — 글자색 · placeholder · 마우스 포인터는 그대로다.
2. **기본값 `auto` 는 브라우저가 고르는 색이고, 보통 글자색(`currentColor`)을 따른다.**
3. **상속되므로 부모에 한 번 쓰면 안쪽 입력 칸 모두에 적용된다.**
4. **캐럿 색은 포커스 스타일과 짝지어 쓴다** — 기본 외곽선을 지웠다면 `:focus` 테두리 같은 대체 표시를 둔다.
5. **`input` · `textarea` 만이 아니라 `contenteditable` 요소에도 된다.**

## 관련 자료

- `color` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `outline` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- 원본: study-site 항목 데이터 `data/css/visual.json` 의 `visual--caret-color`

## 용어 풀이

- **캐럿(caret)** — 텍스트를 입력할 자리에서 깜빡이는 세로 막대. 「텍스트 커서」「입력 커서」라고도 부른다.
- **`currentColor`** — 그 요소의 현재 `color` 값을 가리키는 CSS 키워드.
- **상속** — 값을 정하지 않은 속성을 부모의 값으로 채우는 규칙.
- **포커스** — 요소가 키보드 입력을 받는 상태.
- **`:focus`** — 포커스를 받은 요소에 맞는 의사 클래스.
- **`outline`** — 테두리 바깥에 그려지는 선. 브라우저는 포커스된 요소에 기본 외곽선을 그린다.
- **`transition`** — 속성 값이 바뀔 때 그 변화를 정한 시간에 걸쳐 보간하는 속성.
- **`contenteditable`** — 일반 요소를 편집 가능하게 만드는 HTML 속성.
- **`placeholder`** — 입력 칸이 비었을 때 보이는 안내 문구.

- 캐럿이 배경과 대비가 낮으면 잘 안 보인다. 브랜드 색을 쓸 때는 입력 칸 배경과의 대비를 따로 따져 볼 만하다 (확인 필요).
- 색이 「애니메이션 가능」하다고 해서 깜빡임 주기를 CSS 로 조절할 수 있는 것은 아니다. 깜빡임은 브라우저 · 운영체제가 다룬다 (확인 필요).
- `caret-color: transparent` 로 캐럿을 숨겨 직접 그린 커서로 대체하는 기법이 쓰인다고 알려져 있다 (확인 필요).
