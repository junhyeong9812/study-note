## 한눈에 — 쉽게 말하면

**`max-block-size` 는 「책장 선반의 높이 한도」다.**
선반에 책을 쌓으면 쌓이는 방향(위로)으로만 높이가 자란다.
선반 높이에 한도를 두면 그 이상은 자라지 않고, 넘친 책은 어떻게 처리할지(삐져나오게 둘지, 서랍처럼 넘겨 보게 할지)를 따로 정한다.
CSS 상자도 똑같은 구조다.
글이 쌓이는 방향(블록 방향)으로 상자가 자라는데, `max-block-size` 는 그 방향의 상한을 정하고, 넘친 내용은 `overflow` 가 처리한다.
선반을 옆으로 눕혀 책이 옆으로 쌓이게 하면 한도도 옆 방향에 걸린다 — 이것이 「논리적」 속성이라는 뜻이다.

| 비유 | 실체 |
|---|---|
| 책이 쌓이는 방향 | 블록 방향(block axis) |
| 선반 높이 한도 | `max-block-size` 값 |
| 넘친 책을 처리하는 방식 | `overflow` 값 |
| 선반을 눕히기 | `writing-mode` 를 세로 쓰기로 바꾸기 |

```text
가로 쓰기 (horizontal-tb)

  인라인 방향 →
 ┌────────────────────┐  ↑
 │ 글 첫 줄            │  │ 블록 방향 크기
 │ 글 둘째 줄          │  │ (상한 = max-block-size)
 └────────────────────┘  ↓
   셋째 줄부터는 넘침 → overflow 가 처리
```

## 이 주제가 답하려는 질문

1. 상자가 블록 방향으로 어디까지 자라게 둘 것인가?
2. 상한을 넘은 내용은 어떻게 되는가?
3. 쓰기 방향이 바뀌면 이 상한은 어느 쪽에 걸리는가 — `max-height` 와는 무엇이 다른가?

## 동작 방식

### (1) 블록 방향 크기에 상한을 건다

**언제 쓰나** — 내용 길이를 모르는 상자(댓글, 설명문, 목록)가 너무 길게 늘어나지 않게 막고 싶을 때 쓴다.

```text
입력:  .box { max-block-size: 60px; }
          │
          ▼
브라우저: 내용이 필요로 하는 블록 크기를 계산한다
          │
          ├─ 필요 크기 ≤ 60px → 필요한 만큼만 차지한다
          └─ 필요 크기 > 60px → 60px 에서 멈춘다
          │
          ▼
결과:  상자의 블록 크기 = min(필요 크기, 60px)
```

- 브라우저는 먼저 내용이 원하는 블록 크기를 잰다.
- 그 값이 상한보다 작으면 상한은 아무 일도 하지 않는다.
- 상한보다 크면 상자는 상한에서 멈춘다.
- `max-block-size` 는 크기를 「정하는」 속성이 아니라 「넘지 못하게 하는」 속성이다.

> **블록 방향(block axis)** — 문단·줄이 차례로 쌓여 나가는 방향.\
> 예: 가로 쓰기 한국어 문서에서는 위에서 아래로가 블록 방향이다.

> **논리적 속성** — 위·아래·왼쪽·오른쪽 같은 물리 방향 대신 블록·인라인 방향으로 말하는 속성.\
> 예: `max-block-size` 는 쓰기 방향에 따라 높이에도 너비에도 걸린다.

### (2) 넘친 내용은 `overflow` 가 처리한다

**언제 쓰나** — 상한을 걸었다면 거의 언제나 넘친 내용의 처리 방식도 함께 정한다.

```text
입력:  max-block-size: 60px; overflow: auto;   + 60px 를 넘는 글
          │
          ▼
상자는 60px 에서 멈춘다 → 남은 글은 상자 밖으로 갈 곳이 생긴다
          │
          ├─ overflow: visible(기본값) → 글이 상자 밖으로 삐져나와 그려진다
          ├─ overflow: hidden          → 넘친 글이 잘려 보이지 않는다
          └─ overflow: auto            → 넘칠 때만 스크롤 막대가 생긴다
```

- 상한은 상자의 크기만 묶고, 내용 자체를 줄이지는 않는다.
- 그래서 넘친 내용의 운명은 `overflow` 가 정한다.
- `overflow` 의 기본값은 `visible` 이라 아무것도 안 쓰면 글이 상자 아래로 삐져나온다.
- `auto` 는 넘칠 때만 스크롤을 보여 준다.

> **overflow** — 내용이 상자보다 클 때 넘친 부분을 어떻게 다룰지 정하는 속성.\
> 예: `overflow: auto` 는 넘칠 때만 스크롤 막대를 단다.

### (3) 쓰기 방향이 바뀌면 상한이 걸리는 축도 바뀐다

**언제 쓰나** — 세로 쓰기를 섞는 문서나, 쓰기 방향이 다른 언어를 함께 지원하는 화면에서 같은 CSS 를 쓰고 싶을 때.

```text
writing-mode: horizontal-tb (기본)      writing-mode: vertical-rl
  블록 방향 = 위 → 아래                  블록 방향 = 오른쪽 → 왼쪽
  max-block-size  ≈ max-height          max-block-size ≈ max-width
  max-inline-size ≈ max-width           max-inline-size ≈ max-height
```

- 가로 쓰기에서는 줄이 위에서 아래로 쌓이므로 블록 방향은 세로다.
- 그래서 가로 쓰기에서 `max-block-size` 는 `max-height` 에 매핑된다(원본 팁).
- 세로 쓰기(`vertical-rl`)에서는 줄이 오른쪽에서 왼쪽으로 쌓이므로 블록 방향은 가로다.
- 그때 `max-block-size` 는 너비의 상한이 된다.
- 짝이 되는 `max-inline-size` 는 글자가 한 줄 안에서 흘러가는 방향의 상한이다.

> **writing-mode** — 글이 흐르고 줄이 쌓이는 방향을 정하는 속성.\
> 예: `vertical-rl` 은 글자가 위에서 아래로, 줄은 오른쪽에서 왼쪽으로 쌓인다.

### (4) 상한은 내용 상자에 걸린다 (기본 `box-sizing`)

**언제 쓰나** — 화면에서 상자 크기를 재다가 숫자가 안 맞을 때 떠올린다.

```text
입력:  max-block-size: 60px; padding: 16px;   (box-sizing 기본값 content-box)
          │
          ▼
내용 영역 상한 60px + 위 패딩 16px + 아래 패딩 16px
          │
          ▼
배경이 칠해지는 블록 크기 상한 = 92px
```

- `box-sizing` 의 기본값 `content-box` 에서는 크기 속성이 내용 영역에 걸린다.
- 패딩과 테두리는 그 바깥에 더해진다.
- `box-sizing: border-box` 로 바꾸면 패딩·테두리까지 포함한 크기가 상한이 된다.

> **box-sizing** — 크기 속성이 내용 영역만 재는지, 패딩·테두리까지 재는지 정하는 속성.\
> 예: `content-box` 에서 `max-block-size: 60px; padding: 16px` 이면 바깥은 92px 까지 자란다.

### (5) 다른 크기 속성과 부딪칠 때

**언제 쓰나** — `block-size` · `min-block-size` 와 함께 쓸 때.

```text
block-size: 200px; max-block-size: 60px;     → 60px  (max 가 이긴다)
min-block-size: 100px; max-block-size: 60px; → 100px (min 이 max 를 이긴다)
```

- 지정한 크기(`block-size`)가 상한보다 크면 상한이 이긴다.
- 하한(`min-block-size`)과 상한이 충돌하면 하한이 이긴다.
- 이 순서는 `height` · `max-height` · `min-height` 의 관계와 같다.

## 문법 — 형태와 규칙

```html demo
<div class="note">
  길이를 모르는 설명문이다. 내용이 길어지면 상자는 블록 방향으로 자라려 하지만
  max-block-size 가 상한을 걸어 일정 크기에서 멈춘다. 넘친 줄은 스크롤로 넘겨 본다.
  한 줄 더, 또 한 줄 더 쓰면 스크롤 막대가 생긴다.
</div>
<style>
  .note {
    max-block-size: 4em;   /* 블록 방향 상한 */
    overflow: auto;        /* 넘치면 스크롤 */
    padding: 8px;
    border: 1px solid #ccc;
  }
</style>
```

> **보이는 것** — 상자는 몇 줄 높이에서 멈추고, 나머지 글은 상자 안 스크롤로 넘겨 보게 된다 (코드에서 읽은 것 — 렌더 실측 아님)

- 문법: `max-block-size: none | <length> | <percentage> | min-content | max-content | fit-content`
- 기본값은 `none` 이다.
- 상속되지 않는다(자식에게 같은 상한이 걸리지 않는다).
- 애니메이션할 수 있다.

| 값 | 뜻 | 쓰는 자리 |
|---|---|---|
| `none` | 최대 크기 제한 없음 (기본값) | 앞서 건 상한을 풀 때 |
| `<length>` | 고정 최대 크기 (`60px`, `4em` 등) | 대부분의 경우 |
| `<percentage>` | 포함 블록의 블록 크기에 대한 백분율 | 부모 크기에 비례한 상한 |
| `min-content` | 콘텐츠의 고유 최소 크기 | 콘텐츠 자체 크기에 맞춘 상한 |
| `max-content` | 콘텐츠의 고유 선호 크기 | 콘텐츠 자체 크기에 맞춘 상한 |
| `fit-content` | 가용 공간 안에서 콘텐츠에 맞춤 | 공간과 콘텐츠 사이에서 맞출 때 |

> **포함 블록(containing block)** — 백분율 크기의 기준이 되는 바깥 상자.\
> 예: 보통은 가장 가까운 블록 부모의 내용 영역이다.

## 어디서 틀리나

### 1. 가로 쓰기에서는 `max-height` 와 같다

원본 팁 그대로, 가로 쓰기(`horizontal-tb`)에서 `max-block-size` 는 `max-height` 에 매핑된다.
「블록」이라는 말을 보고 너비라고 착각하기 쉽다.
가로 쓰기에서 블록 방향은 세로다.

### 2. `overflow` 를 안 쓰면 글이 상자 밖으로 삐져나온다

상한은 상자만 멈추게 한다.
`overflow` 의 기본값 `visible` 에서는 넘친 글이 배경 바깥까지 그려져 아래 요소와 겹친다.

### 3. 패딩만큼 상자가 더 크다

기본 `box-sizing: content-box` 에서는 `max-block-size: 60px; padding: 16px` 인 상자의 배경이 92px 까지 자란다.
상한을 「겉 크기」로 읽고 싶으면 `box-sizing: border-box` 를 함께 쓴다.

### 4. 상한일 뿐 크기를 정하지 않는다

내용이 짧으면 상자는 상한보다 작게 끝난다.
항상 그 크기여야 한다면 `block-size` 를 쓴다.

### 5. 상속되지 않는다

부모에 건 상한은 자식에게 전해지지 않는다.
자식이 부모 안에 갇혀 보이는 것은 부모의 `overflow` 때문이지 상속 때문이 아니다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 가로 쓰기에서 `max-block-size` 는 `max-height` 에 매핑된다 | CSS 명세(논리 속성) |
| 세로 쓰기에서는 너비의 상한이 된다 | CSS 명세(논리 속성 + 쓰기 방향) — 원본에 근거 없음, 추론 |
| 기본값 `none` · 상속 안 됨 · 애니메이션 가능 | CSS 명세(원본 재료) |
| 스크롤 막대의 생김새·두께 | 브라우저·운영체제 구현 |
| 브라우저 지원 범위 | 원본에 없음 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 길이 모르는 글을 일정 크기에서 멈추고 스크롤 | `max-block-size` + `overflow: auto` | `block-size`(짧은 글도 빈칸이 생긴다) |
| 쓰기 방향이 바뀔 수 있는 화면 | `max-block-size` | `max-height`(세로 쓰기에서 축이 어긋난다) |
| 항상 정확히 그 크기여야 할 때 | `block-size` | `max-block-size` |
| 한 줄 안에서 흐르는 방향을 제한할 때 | `max-inline-size` | `max-block-size` |

## 핵심 문장

1. **`max-block-size` 는 블록 방향(줄이 쌓이는 방향) 크기의 상한이다** — 크기를 정하지 않고 넘지 못하게만 한다.
2. **가로 쓰기에서는 `max-height` 와 같고, 쓰기 방향이 바뀌면 상한이 걸리는 축도 따라 바뀐다.**
3. **넘친 내용은 `overflow` 가 처리한다** — 상한과 짝으로 쓴다.
4. **기본 `content-box` 에서는 패딩이 상한 바깥에 더해진다.**
5. **`min-block-size` 와 부딪치면 하한이 이긴다.**

## 관련 자료

- `max-height` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `block-size` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)

## 용어 풀이

- **블록 방향** — 문단·줄이 차례로 쌓이는 방향.
- **인라인 방향** — 한 줄 안에서 글자가 흘러가는 방향.
- **논리적 속성** — 물리 방향 대신 블록·인라인 방향으로 말하는 속성.
- **writing-mode** — 글이 흐르고 줄이 쌓이는 방향을 정하는 속성.
- **overflow** — 상자보다 큰 내용을 어떻게 다룰지 정하는 속성.
- **box-sizing** — 크기 속성이 어느 영역을 재는지 정하는 속성.
- **포함 블록** — 백분율 크기의 기준이 되는 바깥 상자.
- **min-content / max-content / fit-content** — 콘텐츠의 고유 크기를 기준으로 삼는 크기 키워드.

## 더 들어가면

- 포함 블록의 블록 크기가 정해져 있지 않으면(예: 부모 높이가 `auto`) 백분율 `max-block-size` 는 `none` 처럼 다뤄진다고 알려져 있다 (확인 필요).
- 블록 축에서는 `min-content` · `max-content` · `fit-content` 가 대체로 콘텐츠의 블록 크기와 같은 값이 되어 서로 차이가 거의 없다 (확인 필요).
- `none` 과 길이 사이는 보간되지 않아, `none` 에서 `200px` 로의 전환은 부드럽게 움직이지 않고 한 번에 바뀐다 (확인 필요).
- 접었다 펴는 UI 에서 `max-block-size` 를 넉넉한 길이로 두고 전환하는 기법이 쓰인다 (확인 필요).
