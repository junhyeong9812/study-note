## 한눈에 — 쉽게 말하면

**`min-block-size` 는 「물컵의 최소 눈금」이다.**
컵에 물을 조금만 부어도 컵 높이는 줄어들지 않는다.
물이 넘칠 만큼 많으면 컵이 늘어난다고 생각하면 된다.
CSS 박스도 똑같은 구조다.
박스 안의 콘텐츠가 적어도 박스는 정한 크기 아래로 줄지 않고, 콘텐츠가 많으면 그 크기를 넘어 커진다.
다만 이 눈금은 「위아래」가 아니라 **글이 쌓여 가는 방향**에 붙어 있다.

| 비유 | 실체 |
|---|---|
| 컵 | 요소의 박스 |
| 물 | 박스 안의 콘텐츠 |
| 최소 눈금 | `min-block-size` 값 |
| 컵이 서 있는 방향 | 블록 방향(쓰기 모드가 정한다) |

```text
 콘텐츠 적음              콘텐츠 많음
┌──────────┐            ┌──────────┐
│ 글 한 줄  │            │ 글 …     │
│          │ ← 최소     │ 글 …     │
│          │   100px    │ 글 …     │
└──────────┘   유지     │ 글 …     │ ← 100px 넘어 늘어남
                        └──────────┘
```

## 이 주제가 답하려는 질문

1. 박스가 블록 방향으로 일정 크기 아래로 줄지 않게 하려면 어떻게 하나?
2. `min-height` 가 있는데 왜 `min-block-size` 라는 이름이 따로 있나?
3. 콘텐츠가 최소 크기보다 많거나 적으면 박스는 어떻게 되나?
4. 쓰기 방향을 세로로 바꾸면 이 속성은 어느 쪽 크기를 막나?

## 동작 방식

### (1) 블록 방향의 바닥을 정한다

**언제 쓰나** — 내용이 짧아도 카드 · 배너 · 칸이 일정 크기를 유지해야 할 때 쓴다.

```text
.box { min-block-size: 100px; }   콘텐츠 높이 = 한 줄(약 20px 남짓)
        │
        ▼
브라우저가 블록 방향 크기를 정함
  = max(콘텐츠가 원하는 크기, 100px)
        │
        ▼
화면: 콘텐츠 영역이 100px 로 잡힌다
```

1. 브라우저는 먼저 콘텐츠가 필요로 하는 블록 방향 크기를 잰다.
2. 그 크기가 `min-block-size` 보다 작으면 `min-block-size` 값으로 끌어올린다.
3. 그 크기가 더 크면 그대로 둔다 — 최소값은 바닥일 뿐 천장이 아니다.

> **블록 방향** — 문단 같은 블록이 차례로 쌓여 가는 방향.\
> 예: 가로 쓰기(`horizontal-tb`)에서는 위에서 아래로 쌓이므로 세로 방향이다.

> **논리적 속성** — 위 · 아래 · 왼쪽 · 오른쪽 대신 블록 방향 · 인라인 방향 같은 쓰기 기준 방향으로 크기나 위치를 정하는 속성.\
> 예: `min-block-size` 는 `min-height` 의 논리적 짝이다.

### (2) 쓰기 모드가 물리 방향을 정한다

**언제 쓰나** — 같은 CSS 를 가로 쓰기 문서와 세로 쓰기 문서에 함께 쓸 때 쓴다.

```text
writing-mode: horizontal-tb          writing-mode: vertical-rl
블록 방향 = 위 → 아래                 블록 방향 = 오른쪽 → 왼쪽
        │                                    │
        ▼                                    ▼
min-block-size 가 막는 것 = 높이       min-block-size 가 막는 것 = 너비
(min-height 처럼 동작)                 (min-width 처럼 동작)
```

1. 원본의 팁대로 가로 쓰기에서 `min-block-size` 는 `min-height` 에 대응한다.
2. 세로 쓰기에서는 글 줄이 옆으로 쌓이므로 블록 방향이 가로가 된다.
3. 그래서 같은 선언이 세로 쓰기에서는 박스의 가로 크기 바닥이 된다.

> **쓰기 모드** — 글줄의 방향과 블록이 쌓이는 방향을 정하는 설정(`writing-mode`).\
> 예: `vertical-rl` 은 세로로 쓰고 줄을 오른쪽에서 왼쪽으로 쌓는다.

### (3) 안쪽 여백은 따로 더해진다

**언제 쓰나** — 최소 크기를 정한 박스에 `padding` 을 줄 때 겉 크기를 셈한다.

```text
.box { min-block-size: 100px; padding: 16px; }   (box-sizing 기본값 content-box)
        │
        ▼
100px 은 콘텐츠 영역에 걸린다
위 padding 16px + 콘텐츠 100px + 아래 padding 16px
        │
        ▼
화면: 테두리까지의 블록 방향 크기 = 132px  (코드에서 읽은 것 — 렌더 실측 아님)
```

1. `box-sizing` 이 기본값 `content-box` 이면 크기 속성은 콘텐츠 영역에 걸린다.
2. `padding` 은 그 바깥에 붙으므로 겉 크기는 최소값보다 커진다.
3. `box-sizing: border-box` 로 바꾸면 100px 안에 padding 이 들어간다.

> **`box-sizing`** — 크기 속성이 콘텐츠 영역에 걸리는지(`content-box`), 테두리까지의 영역에 걸리는지(`border-box`) 정하는 속성.\
> 예: `content-box` 에서 `min-block-size: 100px; padding: 16px` 이면 겉 크기는 132px 이다.

### (4) 남는 공간 안에서 콘텐츠를 가운데 놓기

**언제 쓰나** — 최소 크기 때문에 생긴 빈 공간에서 글자를 세로 가운데에 두고 싶을 때 쓴다.

```text
.box { min-block-size: 100px; display: flex; align-items: center; }
        │
        ▼
flex 의 주축 = 가로(row), 교차축 = 세로
교차축 정렬 center → 글자 덩어리를 100px 안의 세로 가운데에 놓음
        │
        ▼
화면: 글자가 박스 세로 가운데에 보임  (코드에서 읽은 것 — 렌더 실측 아님)
```

1. 원본 예제는 박스를 flex 컨테이너로 만든다.
2. 기본 방향 `row` 에서 교차축은 세로다.
3. `align-items: center` 가 아이템을 교차축 가운데에 놓으므로, 최소 크기로 생긴 여유 공간의 가운데에 글자가 온다.

> **교차축** — flex 컨테이너에서 아이템이 늘어서는 주축에 수직인 축.\
> 예: `flex-direction: row` 면 교차축은 세로다.

```html demo
<div style="min-block-size: 100px; background: #3b82f6; color: white; padding: 16px; display: flex; align-items: center;">
  짧은 글 한 줄
</div>
```

> **보이는 것** — 파란 박스가 글 한 줄보다 훨씬 높고, 글자가 그 높이의 세로 가운데에 놓인다 (코드에서 읽은 것 — 렌더 실측 아님)

## 문법 — 형태와 규칙

```css
.card {
  min-block-size: 100px;      /* 블록 방향으로 100px 아래로 줄지 않는다 */
}
.half {
  min-block-size: 50%;        /* 포함 블록의 블록 크기의 절반 */
}
.fit {
  min-block-size: min-content; /* 콘텐츠의 고유 최소 크기를 바닥으로 */
}
.vertical {
  writing-mode: vertical-rl;
  min-block-size: 200px;      /* 세로 쓰기 — 가로 크기의 바닥이 된다 */
}
```

| 값 | 뜻 (원본) | 풀어 쓰면 |
|---|---|---|
| `auto` | 기본값 | 따로 바닥을 정하지 않는다 |
| `<length>` | 고정 최소 크기 값 | `100px` · `5rem` 처럼 정해진 길이 |
| `<percentage>` | 포함 블록 블록 크기의 백분율 | 부모 쪽 박스의 블록 방향 크기를 기준으로 한 비율 |
| `min-content` | 콘텐츠의 고유 최소 크기 | 콘텐츠가 가장 좁게 접혔을 때의 크기 |
| `max-content` | 콘텐츠의 고유 선호 크기 | 콘텐츠가 접히지 않고 펼쳐졌을 때의 크기 |
| `fit-content` | 가용 공간 내에서 콘텐츠에 맞춤 | 공간이 허락하는 한 콘텐츠에 맞춘 크기 |

- 상속되지 않는다(원본: 상속 `False`) — 부모에 주어도 자식은 자기 값(기본값)을 쓴다.
- 애니메이션할 수 있다(원본: `True`) — 길이 · 백분율 사이를 `transition` 으로 옮겨 갈 수 있다.
- 블록 방향 하나만 다룬다 — 인라인 방향(글줄 방향)의 크기에는 관여하지 않는다.

> **포함 블록** — 요소의 크기와 위치를 셀 때 기준이 되는 바깥 박스.\
> 예: 보통 가장 가까운 블록 수준 부모의 콘텐츠 영역이다.

## 어디서 틀리나

### 1. 「가로 쓰기에서 min-height」만 외우면 세로 쓰기에서 헛짚는다

원본의 팁은 가로 쓰기의 대응만 말한다.
세로 쓰기에서는 블록 방향이 가로이므로 `min-block-size` 가 너비의 바닥이 된다.
「높이 속성」이라고 외우지 말고 「블록 방향 속성」이라고 외워야 한다.

### 2. 최소값을 고정 크기로 착각한다

`min-block-size: 100px` 은 「100px 이다」가 아니라 「100px 보다 작아지지 않는다」다.
콘텐츠가 길면 박스는 100px 을 넘어 늘어난다.
정확히 고정하려면 `block-size` 를, 위쪽 한도를 두려면 `max-block-size` 를 써야 한다.

### 3. padding 까지 100px 안에 들어간다고 생각한다

기본 `box-sizing: content-box` 에서는 최소값이 콘텐츠 영역에 걸린다.
`padding: 16px` 이면 겉 크기는 위아래 32px 가 더해진다.

### 4. 원본의 기본값이 두 곳에서 서로 다르다

원본의 주장 → 「기본값: `0`」, 그리고 값 목록에서는 「`auto` — 기본값」.
왜 의심스러운가 → 한 속성의 기본값이 둘일 수 없으므로 둘 중 하나는 틀렸다.
어느 쪽이 맞는지 원본만으로는 가릴 수 없다 (확인 필요).

### 5. 백분율의 기준을 잘못 잡는다

`<percentage>` 는 포함 블록의 **블록 방향 크기**를 기준으로 한다.
포함 블록의 블록 크기가 콘텐츠에 따라 정해지는(정해진 값이 없는) 경우 백분율이 기대대로 먹지 않을 수 있다 (확인 필요).

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 가로 쓰기에서 `min-height` 에 대응한다 | CSS 논리 속성 명세 |
| 세로 쓰기에서 가로 크기의 바닥이 된다 | CSS 논리 속성 · 쓰기 모드 명세 (블록 방향의 정의에서 나온다) |
| 기본값이 `auto` 또는 `0` 이다 | 명세가 정한다 — 원본 안에서 두 값이 엇갈린다 (확인 필요) |
| 상속되지 않고 애니메이션할 수 있다 | 명세의 속성 정의 (원본 재료 기준) |
| 각 브라우저가 이 속성을 지원하는 범위 | 브라우저 구현마다 다르다 — 이 문서는 적지 않는다 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 짧은 카드도 일정 높이를 유지 | `min-block-size` | `block-size` (긴 내용이 넘친다) |
| 가로 · 세로 쓰기를 함께 지원 | `min-block-size` | `min-height` (세로 쓰기에서 엉뚱한 축) |
| 크기를 딱 고정 | `block-size` | `min-block-size` |
| 크기에 위 한도를 둠 | `max-block-size` | `min-block-size` |
| 가로 쓰기만 쓰는 오래된 코드와 맞춤 | 어느 쪽이든 같은 축 — 팀 규칙을 따른다 | 둘을 한 요소에 섞어 쓰기 |

## 핵심 문장

1. **`min-block-size` 는 블록 방향 크기의 바닥이다** — 콘텐츠가 적어도 그 아래로 줄지 않고, 많으면 늘어난다.
2. **블록 방향은 쓰기 모드가 정한다** — 가로 쓰기에서는 `min-height`, 세로 쓰기에서는 가로 크기의 바닥이 된다.
3. **`content-box` 에서는 padding 이 바깥에 더해진다** — 겉 크기는 최소값보다 크다.
4. **상속되지 않고 애니메이션할 수 있다.**
5. **원본은 기본값을 `0` 과 `auto` 로 엇갈리게 적었다** — 그대로 믿지 말고 확인해야 한다.

## 관련 자료

- `min-height` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `block-size` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)

## 용어 풀이

- **블록 방향** — 블록이 차례로 쌓여 가는 방향. 가로 쓰기에서는 위 → 아래다.
- **인라인 방향** — 한 줄 안에서 글자가 이어지는 방향. 가로 쓰기에서는 왼쪽 → 오른쪽이다.
- **논리적 속성** — 물리 방향 대신 쓰기 기준 방향으로 정하는 속성.
- **쓰기 모드(`writing-mode`)** — 글줄과 블록이 쌓이는 방향을 정하는 설정.
- **포함 블록** — 크기 · 위치 계산의 기준이 되는 바깥 박스.
- **`box-sizing`** — 크기 속성이 어느 영역에 걸리는지 정하는 속성.
- **교차축** — flex 주축에 수직인 축.
- **`min-content`** — 콘텐츠가 가장 좁게 접혔을 때의 고유 크기.
- **`max-content`** — 콘텐츠가 접히지 않고 펼쳐졌을 때의 고유 크기.
- **`fit-content`** — 가용 공간 안에서 콘텐츠에 맞춘 크기.

## 더 들어가면

- `min-block-size` 와 `max-block-size` 가 부딪치면(최소가 최대보다 크면) 최소값이 이긴다 (확인 필요).
- 인라인 방향의 짝은 `min-inline-size` 다 — 가로 쓰기에서 `min-width` 에 대응한다 (확인 필요).
- 같은 요소에 `min-height` 와 `min-block-size` 를 함께 쓰면 같은 축을 다루므로 캐스케이드에서 나중 선언이 이긴다고 알려져 있다 (확인 필요).
- `min-content` 같은 키워드 값 사이는 길이처럼 부드럽게 보간되지 않을 수 있다 (확인 필요).
- 명세상 `min-width` · `min-height` 의 초기값은 `auto` 로 정의되어 있고 논리 속성도 이를 따른다고 알려져 있다 (확인 필요).
