## 한눈에 — 쉽게 말하면

**`padding-block` 은 「글이 쌓여 가는 방향의 앞뒤 쿠션」이다.**
공책에 가로로 글을 쓰면 줄은 위에서 아래로 쌓인다.
그 쌓이는 방향의 맨 앞(위)과 맨 뒤(아래)에 대는 쿠션이 `padding-block` 이다.
공책을 돌려 세로로 쓰면 줄이 쌓이는 방향이 바뀌고, 쿠션이 붙는 자리도 따라 바뀐다.
CSS 박스도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 줄이 쌓여 가는 방향 | 블록 방향(블록 축) |
| 앞쪽 쿠션 | 블록 시작(block-start) 쪽 패딩 |
| 뒤쪽 쿠션 | 블록 끝(block-end) 쪽 패딩 |
| 공책을 돌려 쓰기 | 쓰기 모드(`writing-mode`) 바꾸기 |

```text
가로 쓰기(기본)에서의 박스

 ┌──────────────────────────┐
 │   ↑ padding-block (시작)  │  ← 위
 │ ┌──────────────────────┐ │
 │ │       내용            │ │
 │ └──────────────────────┘ │
 │   ↓ padding-block (끝)    │  ← 아래
 └──────────────────────────┘
```

> **블록 방향** — 글의 줄(블록)이 차례로 쌓여 가는 방향이다.\
> 예: 가로 쓰기에서는 위 → 아래가 블록 방향이다.

## 이 주제가 답하려는 질문

1. `padding-block` 은 박스의 어느 변에 여백을 넣나?
2. 값을 하나 줄 때와 둘 줄 때 무엇이 다른가?
3. 퍼센트 값은 무엇을 기준으로 계산되나?
4. 왜 `padding-top` · `padding-bottom` 대신 「논리적」 속성을 쓰나?

## 동작 방식

### (1) 값 하나 — 블록 양끝에 같은 여백

**언제 쓰나** — 위아래(블록 양끝) 여백을 같게 줄 때 쓴다.

```text
.box { padding-block: 30px; }
        │
        ▼  값이 하나 → 시작 쪽과 끝 쪽에 같은 값
 block-start 패딩 = 30px
 block-end   패딩 = 30px
        │
        ▼  가로 쓰기(horizontal-tb)
 padding-top = 30px, padding-bottom = 30px
```

- 값을 하나만 쓰면 블록 시작 쪽과 끝 쪽에 같은 값이 들어간다.
- 가로 쓰기에서 블록 시작은 위, 블록 끝은 아래다.
- 그래서 결과는 `padding-top` 과 `padding-bottom` 을 둘 다 30px 로 준 것과 같다.

> **논리적 속성** — 위 · 아래 · 왼쪽 · 오른쪽 대신 쓰기 방향(블록 · 인라인, 시작 · 끝)으로 변을 가리키는 속성이다.\
> 예: `padding-block`, `padding-inline`.

> **물리적 속성** — 화면의 위 · 아래 · 왼쪽 · 오른쪽으로 변을 가리키는 속성이다.\
> 예: `padding-top`, `padding-left`.

### (2) 값 둘 — 시작과 끝을 따로

**언제 쓰나** — 위와 아래 여백을 다르게 줄 때 쓴다.

```text
.box { padding-block: 10px 40px; }
        │
        ▼  첫 값 → block-start, 둘째 값 → block-end
 block-start 패딩 = 10px
 block-end   패딩 = 40px
        │
        ▼  가로 쓰기
 padding-top = 10px, padding-bottom = 40px
```

- 첫 번째 값은 블록 시작 쪽으로 간다.
- 두 번째 값은 블록 끝 쪽으로 간다.
- 값은 1~2개까지만 받는다.

### (3) 퍼센트 — 기준은 포함 블록의 인라인 크기

**언제 쓰나** — 부모 너비에 비례하는 여백이 필요할 때 쓴다.

```text
부모(포함 블록) 너비 400px, 높이 1000px
.child { padding-block: 10%; }
        │
        ▼  기준 = 포함 블록의 「인라인 크기」(가로 쓰기에서는 너비)
 10% × 400px = 40px
        │
        ▼
 위 40px, 아래 40px   (높이 1000px 은 쓰이지 않는다)
```

- 퍼센트는 블록 방향 여백이라도 포함 블록의 **인라인 크기**를 기준으로 계산한다.
- 가로 쓰기에서 인라인 크기는 너비다.
- 그래서 위아래 여백인데도 부모의 높이가 아니라 너비에 비례한다.

> **포함 블록** — 요소의 크기 · 위치 계산의 기준이 되는 바깥 상자다.\
> 예: 보통은 가장 가까운 블록 수준 부모의 내용 영역이다.

> **인라인 크기** — 글자가 한 줄로 나아가는 방향의 길이다.\
> 예: 가로 쓰기에서는 너비(width)다.

### (4) 쓰기 모드가 바뀌면 붙는 변이 바뀐다

**언제 쓰나** — 세로 쓰기 등 여러 쓰기 방향을 지원하는 화면을 만들 때 의미가 생긴다.

```text
writing-mode: horizontal-tb (기본)    writing-mode: vertical-rl
  블록 방향: 위 → 아래                  블록 방향: 오른쪽 → 왼쪽
  padding-block → 위 · 아래             padding-block → 오른쪽 · 왼쪽
```

- 가로 쓰기에서는 줄이 위에서 아래로 쌓이므로 `padding-block` 은 위아래에 붙는다.
- 세로 쓰기(`vertical-rl`)에서는 줄이 오른쪽에서 왼쪽으로 쌓이므로 블록 방향이 가로가 된다.
- 그때 `padding-block` 은 오른쪽(시작)과 왼쪽(끝)에 붙는다.
- 코드를 고치지 않아도 쓰기 방향에 맞춰 여백 자리가 따라간다 — 이것이 논리적 속성을 쓰는 까닭이다.

> **쓰기 모드** — 글자가 나아가는 방향과 줄이 쌓이는 방향을 정하는 설정(`writing-mode`)이다.\
> 예: `horizontal-tb` 는 가로로 쓰고 위에서 아래로 줄을 쌓는다.

### (5) 짝 속성 `padding-inline` 과 함께

**언제 쓰나** — 네 변 여백을 논리적 속성만으로 다 정할 때 쓴다.

```html demo
<div style="padding-block: 30px; padding-inline: 16px; background: #3b82f6; color: white; border-radius: 4px;">padding-block</div>
```

> **보이는 것** — 파란 박스 안 흰 글자 위아래에 30px, 좌우에 16px 여백이 생겨 세로로 두툼한 띠가 된다 (코드에서 읽은 것 — 렌더 실측 아님)

- `padding-inline` 은 인라인 방향(가로 쓰기에서 좌우) 양끝 여백을 정한다.
- 가로 쓰기에서 `padding-block: 30px; padding-inline: 16px;` 은 `padding: 30px 16px;` 과 같은 결과다.
- 다만 `padding` 은 물리적 단축이라 쓰기 모드가 바뀌어도 늘 위아래 · 좌우에 붙는다.

## 문법 — 형태와 규칙

```css
/* 값 하나: 블록 시작 · 끝 모두 같은 값 */
.a { padding-block: 30px; }

/* 값 둘: 첫 값 = 시작, 둘째 값 = 끝 */
.b { padding-block: 10px 40px; }

/* 퍼센트: 포함 블록 인라인 크기 기준 */
.c { padding-block: 5%; }

/* 인라인 방향 짝 */
.d { padding-block: 30px; padding-inline: 16px; }
```

| 값 | 뜻 | 음수 |
|---|---|---|
| `<length>` | 고정 단위 값(`px`, `em`, `rem` 등) | 불가 |
| `<percentage>` | 포함 블록 **인라인 크기**의 백분율 | 불가 |

| 성질 | 값 |
|---|---|
| 기본값 | `0` |
| 상속 | 안 됨 |
| 애니메이션 | 가능 |
| 값 개수 | 1~2개 |

- 값 1개 = 시작 · 끝 동일, 값 2개 = 시작 / 끝 따로.
- 음수는 허용되지 않는다 — 음수를 쓴 선언은 잘못된 선언이라 무시된다.
- 상속되지 않으므로 부모에 준 값이 자식의 패딩으로 내려가지 않는다.
- 애니메이션 가능하므로 `transition` 으로 여백이 부드럽게 늘고 줄게 할 수 있다.

## 어디서 틀리나

### 1. 가로 쓰기에서만 「위아래」다

원본 팁은 「가로 쓰기에서 `padding-top`/`padding-bottom` 에 매핑」이라고 한다.
「가로 쓰기에서」가 핵심이다.
`padding-block` 을 늘 위아래라고 외우면 세로 쓰기 화면에서 여백이 좌우로 간 것을 보고 당황한다.

### 2. 값 둘의 순서는 「위 · 아래」가 아니라 「시작 · 끝」이다

원본 팁은 「1~2개 값 지정 가능」이라고 한다.
두 번째 값은 블록 끝 쪽이다.
가로 쓰기에서는 우연히 위 · 아래와 같지만, 뜻은 시작 · 끝이다.

### 3. 퍼센트는 높이가 아니라 인라인 크기 기준이다

위아래 여백이니 부모 높이에 비례하리라 생각하기 쉽다.
기준은 포함 블록의 인라인 크기(가로 쓰기에서는 너비)다.

### 4. 음수로 박스를 줄일 수 없다

`margin` 과 달리 패딩은 음수가 안 된다.
`padding-block: -10px` 은 무시되고, 다른 선언이 없으면 기본값 `0` 이 그대로 남는다.

### 5. 상속되지 않는다

부모 상자에 `padding-block` 을 준다고 자식들도 각자 위아래 여백을 갖는 것이 아니다.
여백은 그 요소 자신의 박스 안쪽에만 생긴다.

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 가로 쓰기에서 `padding-block` 은 위 · 아래에 매핑된다 | CSS 명세(논리적 속성) |
| 퍼센트는 포함 블록 인라인 크기 기준이다 | CSS 명세 |
| 음수는 허용되지 않는다 | CSS 명세 |
| 각 브라우저가 이 속성을 지원하는 버전 | 브라우저 구현 — 원본에 정보 없음 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 위아래 여백만 한 번에 정하기 | `padding-block` | `padding-top` + `padding-bottom` 따로 두 줄 |
| 세로 쓰기 · 여러 쓰기 방향 지원 | `padding-block` / `padding-inline` | 물리적 `padding-top` 등 |
| 쓰기 방향과 무관하게 화면 위쪽에만 여백 | `padding-top` | `padding-block` |
| 박스를 안쪽으로 줄이기 | 다른 방법(크기 조정 등) | 음수 `padding-block` |

## 핵심 문장

1. **`padding-block` 은 블록 방향 양끝(시작 · 끝)의 안쪽 여백을 정한다** — 가로 쓰기에서는 위아래다.
2. **값 1개는 양끝 같게, 값 2개는 시작 / 끝 따로다.**
3. **퍼센트는 포함 블록의 인라인 크기 기준이다** — 위아래 여백도 부모 너비에 비례한다.
4. **쓰기 모드가 바뀌면 여백이 붙는 변이 따라 바뀐다** — 이것이 논리적 속성의 존재 이유다.
5. **음수 불가 · 상속 안 됨 · 기본값 0 · 애니메이션 가능.**

## 관련 자료

- `padding-block-start` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `padding-block-end` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)

## 용어 풀이

- **블록 방향** — 줄이 차례로 쌓여 가는 방향.
- **인라인 방향** — 한 줄 안에서 글자가 나아가는 방향.
- **블록 시작 / 블록 끝** — 블록 방향의 앞쪽 변과 뒤쪽 변.
- **논리적 속성** — 쓰기 방향 기준(블록 · 인라인, 시작 · 끝)으로 변을 가리키는 속성.
- **물리적 속성** — 화면 기준(위 · 아래 · 왼쪽 · 오른쪽)으로 변을 가리키는 속성.
- **쓰기 모드(`writing-mode`)** — 글자와 줄의 진행 방향을 정하는 설정.
- **`horizontal-tb`** — 가로로 쓰고 위에서 아래로 줄을 쌓는 기본 쓰기 모드.
- **포함 블록** — 요소의 크기 · 위치 계산의 기준이 되는 바깥 상자.
- **인라인 크기** — 인라인 방향의 길이(가로 쓰기에서는 너비).
- **단축 속성** — 여러 속성을 한 줄에 함께 정하는 속성.

## 더 들어가면

- `padding-block` 은 `padding-block-start` 와 `padding-block-end` 두 개의 롱핸드를 묶은 단축 속성이다 (확인 필요).
- 같은 요소에 `padding-top` 과 `padding-block` 을 함께 쓰면, 둘은 같은 변을 가리키므로 캐스케이드에서 나중에 오는(또는 우선순위가 높은) 선언이 이긴다 (확인 필요).
- `direction: rtl` 은 인라인 방향을 뒤집지만 가로 쓰기의 블록 방향(위 → 아래)은 바꾸지 않는다 — 그래서 `padding-block` 은 영향을 받지 않는다 (확인 필요).
- `margin-block` · `border-block` · `inset-block` 처럼 같은 꼴의 논리적 속성 가족이 있다 (확인 필요).
