## 퀴즈 정답

### 1. 위 10px, 아래 40px — 첫 값이 시작, 둘째 값이 끝

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
위쪽 패딩 10px, 아래쪽 패딩 40px 이다.

**왜 그런가**
값이 둘이면 첫 값은 블록 시작 쪽, 둘째 값은 블록 끝 쪽으로 간다.
가로 쓰기에서 블록 시작은 위, 블록 끝은 아래다.
근거: 2-summary 「동작 방식 (2)」.

### 2. 위아래 30px, 좌우 16px

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
위 30px, 아래 30px, 왼쪽 16px, 오른쪽 16px 이다.

**왜 그런가**
`padding-block` 값이 하나라 블록 양끝(가로 쓰기에서 위아래)에 같은 30px 이 들어간다.
`padding-inline` 값이 하나라 인라인 양끝(가로 쓰기에서 좌우)에 같은 16px 이 들어간다.
근거: 2-summary 「동작 방식 (1)」 · 「동작 방식 (5)」.

### 3. 40px — 부모 높이가 아니라 너비 기준

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
위쪽 패딩은 40px 이다(아래쪽도 40px).

**왜 그런가**
퍼센트는 포함 블록의 인라인 크기를 기준으로 한다.
가로 쓰기에서 인라인 크기는 너비이므로 10% × 400px = 40px 이다.
높이 1000px 은 계산에 쓰이지 않는다.
근거: 2-summary 「동작 방식 (3)」.

### 4. 쓰기 방향이 바뀌어도 여백 자리가 따라가게 하려고

물리적 속성은 늘 화면의 위 · 아래에 붙는다.
논리적 속성은 「블록 방향의 시작 · 끝」을 가리키므로 쓰기 모드가 바뀌면 붙는 변도 따라 바뀐다.
그래서 세로 쓰기처럼 다른 쓰기 방향을 지원할 때 CSS 를 고치지 않아도 의도한 쪽(줄이 쌓이는 방향의 앞뒤)에 여백이 남는다.
또 위아래 두 줄을 단축 속성 한 줄로 쓸 수 있다.
근거: 2-summary 「동작 방식 (4)」 · 「언제 쓰고 언제 안 쓰나」.

### 5. 오른쪽(시작)과 왼쪽(끝)

`vertical-rl` 에서는 줄이 오른쪽에서 왼쪽으로 쌓이므로 블록 방향이 가로가 된다.
그래서 `padding-block` 은 오른쪽(블록 시작)과 왼쪽(블록 끝)에 붙는다.
근거: 2-summary 「동작 방식 (4)」.

### 6. 선언이 무시되어 여백은 기본값 그대로다

`padding-block` 은 `<length>` · `<percentage>` 모두 음수를 허용하지 않는다.
음수를 쓴 선언은 잘못된 선언이라 무시되고, 다른 선언이 없으면 기본값 `0` 이 남는다.
근거: 2-summary 「문법 — 형태와 규칙」 · 「어디서 틀리나 4」.

### 7. 아니다 — 상속되지 않는다

`padding-block` 은 상속되지 않는 속성이다.
부모의 여백은 부모 박스 안쪽에만 생기고, 자식은 자기 기본값 `0` 을 그대로 갖는다.
근거: 2-summary 「문법 — 형태와 규칙」 · 「어디서 틀리나 5」.

### 8. `padding: 30px 16px;` — 쓰기 모드가 바뀌면 갈라진다

가로 쓰기에서는 `padding: 30px 16px;` 이 같은 결과(위아래 30px, 좌우 16px)를 낸다.
하지만 `padding` 은 물리적 단축이라 쓰기 모드가 바뀌어도 늘 위아래 30px, 좌우 16px 이다.
`padding-block` · `padding-inline` 은 세로 쓰기에서 블록 방향(가로)에 30px, 인라인 방향(세로)에 16px 로 자리가 바뀐다.
근거: 2-summary 「동작 방식 (4)」 · 「동작 방식 (5)」.

## 실습 정답

### 실습 1. 위아래가 두툼한 파란 라벨 박스 만들기

**요구 조건 → 정답 코드의 자리**

| 요구 조건 | 정답 코드 |
|---|---|
| 1. 클래스 `box` 인 `div` 에 글자 | `<div class="box">padding-block</div>` |
| 2. 블록 양끝 여백을 단축 속성 하나 · 값 하나로 | `.box { padding-block: 30px; }` |
| 3. 인라인 양끝 여백을 논리적 단축 속성 하나 · 값 하나로 | `.box { padding-inline: 16px; }` |
| 4. 위아래가 좌우보다 두툼 | `padding-block` 30px > `padding-inline` 16px |
| 5. 물리적 패딩 속성을 쓰지 않음 | `.box` 규칙에 `padding-top` 등이 없음 |
| 6. 꾸밈은 그대로 | `background` · `color` · `border-radius` |

**정답 코드** — study-practice 의 줄 단위 주석판이다(코드 동작은 원본 예제와 같다).

`css/box-model/reference/padding-block.html`

```html
<!DOCTYPE html>                                                <!-- HTML5 문서 선언 -->
<html lang="ko">                                              <!-- 루트 요소, 한국어 문서 -->
<head>                                                        <!-- 문서 메타정보 영역 -->
<meta charset="utf-8">                                        <!-- 문자 인코딩 UTF-8 -->
<title>padding-block - 블록 방향(가로 쓰기에서 상하)의 안쪽 여백을 설정하는 논리적 단축 속성</title>
<!--
  [박스 모델] padding-block
  설명: 블록 방향(가로 쓰기에서 상하)의 안쪽 여백을 설정하는 논리적 단축 속성
  구문: padding-block: <length> | <percentage>
  팁: 가로 쓰기에서 padding-top/padding-bottom에 매핑. 1~2개 값 지정 가능.
       1값=양쪽 동일, 2값=start/end 분리.
-->
<style>
/* .box: 블록축 양끝(상하) 패딩 단축 시연 */
.box {
  padding-block: 30px;             /* 블록축 시작/끝 모두 30px - horizontal-tb면 padding-top+padding-bottom */
  padding-inline: 16px;            /* 인라인축 양쪽 모두 16px - horizontal-tb면 padding-left+padding-right */
  background: #3b82f6;             /* 배경색: 파란색 */
  color: white;                    /* 글자색: 흰색 */
  border-radius: 4px;              /* 모서리 4px 둥글게 */
}
</style>
</head>
<body>
<div class="box">padding-block</div>                          <!-- 블록축 양끝 패딩 박스 -->

</body>
</html>
```

원본 예제의 나머지 조각(study-practice 에는 없고 study-site 항목 데이터에만 있다):

```css
.box { padding-block: 30px; padding-inline: 16px; background: #3b82f6; color: white; border-radius: 4px; }
```

**풀이 요점**
- `padding-block` 에 값을 하나만 주면 블록 시작 · 끝(가로 쓰기에서 위아래)에 같은 값이 들어간다.
- `padding-inline` 은 짝이 되는 인라인 방향(가로 쓰기에서 좌우) 단축 속성이다.
- 두 줄을 합치면 가로 쓰기에서 `padding: 30px 16px;` 과 같은 박스가 된다.
- 물리적 속성을 쓰지 않았으므로 `writing-mode` 를 바꾸면 여백 자리가 쓰기 방향을 따라간다.
- 확인은 개발자 도구의 박스 모델 그림에서 padding 칸의 숫자를 보면 된다.
