## 한눈에 — 쉽게 말하면

**`A ~ B` 는 「줄 선 형제들 중에서, 맏이 A 보다 뒤에 선 B 를 모두 부르기」다.**
한 부모 아래 아이들이 한 줄로 서 있다고 하자.
「A 뒤에 선 아이 중 B 인 아이는 다 나와라」라고 부르면, A 바로 뒤가 아니어도 나온다.
A 앞에 선 아이는 B 여도 나오지 않는다.
다른 집 아이(다른 부모의 자식)도 나오지 않는다.
CSS 의 일반 형제 결합자도 똑같은 구조다.

> **결합자** — 두 선택자 사이에 놓여 두 요소의 관계(자손 · 자식 · 형제)를 정하는 기호다.\
> 예: 공백(자손), `>`(자식), `+`(바로 다음 형제), `~`(뒤의 모든 형제).

> **형제** — 같은 부모를 둔 요소들이다.\
> 예: `<div>` 안에 나란히 있는 `<h3>` 과 `<p>` 는 형제다.

| 비유 | 실체 |
|---|---|
| 한 부모 아래 한 줄로 선 아이들 | 같은 부모 요소 안의 형제 요소들 |
| 줄의 앞뒤 | 문서 순서(HTML 에 적힌 차례) |
| 기준이 되는 맏이 A | `~` 왼쪽의 선택자 |
| 불려 나오는 B | `~` 오른쪽의 선택자 — 실제로 스타일을 받는 쪽 |

```text
부모 div
 ├─ h3      ← A (기준, 스타일 안 받음)
 ├─ span    ← B 아님 → 건너뜀
 ├─ p  ✔    ← A 뒤의 형제 p → 선택
 └─ p  ✔    ← A 뒤의 형제 p → 선택
```

## 이 주제가 답하려는 질문

1. `A ~ B` 는 어떤 요소를 고르고, 어떤 요소는 고르지 않는가?
2. 바로 다음 형제만 고르는 `+` 와는 무엇이 다른가?
3. 체크박스 상태로 떨어져 있는 형제 요소를 바꾸는 CSS-only 인터랙션은 어떻게 되는가?

## 동작 방식

### (1) 기준 뒤의 형제를 모두 고른다

**언제 쓰나** — 어떤 요소(예: 제목) 뒤에 오는 같은 종류의 형제를 한꺼번에 꾸미고 싶을 때 쓴다.
사이에 다른 요소가 끼어 있어도 상관없다.

```text
입력 코드:  .gen-demo h3 ~ p { background: …; }

HTML 순서:  h3 → span → p → p   (모두 .gen-demo 의 자식)

판정:       p(1번째) — 앞쪽 형제 중에 h3 이 있나? 있음 → 선택
            p(2번째) — 앞쪽 형제 중에 h3 이 있나? 있음 → 선택
            span     — p 가 아님 → 대상 아님
            h3       — 기준일 뿐 → 대상 아님

결과:       두 p 만 배경이 바뀐다
```

- 브라우저는 B 후보(여기서는 `p`) 하나하나에 대해 「나보다 앞에 있는 형제 중에 A 가 있나」를 따진다.
- 바로 앞이 아니어도, 몇 칸 떨어져 있어도 앞에 A 가 하나라도 있으면 맞는다.
- 사이에 낀 `span` 은 `p` 가 아니므로 스타일을 받지 않지만, 사이에 있다고 해서 매칭을 막지도 않는다.
- 기준 `h3` 자신은 `~` 오른쪽이 아니므로 스타일을 받지 않는다.

### (2) 앞쪽 형제 · 다른 부모의 요소는 고르지 않는다

**언제 쓰나** — 「왜 이 요소는 안 바뀌지?」를 따질 때 이 경계를 떠올린다.

```text
입력 코드:  h3 ~ p { … }

<div>
  <p>A</p>          ← h3 보다 앞 → 선택 안 됨
  <h3>제목</h3>
  <p>B</p>          ← h3 뒤 형제 → 선택
  <div>
    <p>C</p>        ← h3 의 형제가 아니라 조카(형제의 자식) → 선택 안 됨
  </div>
</div>
<p>D</p>            ← 부모가 다르다 → 선택 안 됨
```

- `~` 는 한 방향, 즉 문서 순서상 뒤쪽만 본다.
- A 보다 앞에 있는 B 는 아무리 가까워도 고르지 않는다.
- 형제의 자식은 형제가 아니다 — 같은 부모를 둔 요소만 형제다.
- 부모가 다른 요소는 앞뒤와 상관없이 형제가 아니다.

### (3) 체크박스 상태로 떨어진 형제를 바꾼다 (CSS-only 인터랙션)

**언제 쓰나** — JavaScript 없이 「체크하면 패널이 보인다」 같은 상호작용을 만들 때 쓴다.

> **CSS-only 인터랙션** — 스크립트 없이 CSS 의 상태 선택자와 결합자만으로 사용자 조작에 반응하게 만드는 기법이다.\
> 예: `input:checked ~ .panel { display: block; }`

```text
입력 코드:  #toggle:checked ~ .panel { display: block; }

HTML 순서:  input#toggle → label → .panel   (같은 부모)

체크 안 함: #toggle:checked 가 거짓 → 규칙 안 맞음 → .panel 숨김
체크 함:    #toggle:checked 가 참   → 뒤 형제 .panel 맞음 → .panel 보임
```

- `:checked` 는 체크된 입력 요소에만 맞는 상태 의사 클래스다.
- 체크 상태가 바뀌면 브라우저가 선택자를 다시 따지고, 뒤쪽 형제 `.panel` 의 스타일이 바뀐다.
- `~` 를 쓰므로 `input` 과 `.panel` 사이에 `label` 같은 다른 요소가 끼어 있어도 된다.
- 반대로 `input` 이 `.panel` 보다 뒤에 있으면 (2)의 규칙 때문에 맞지 않는다.

```html demo
<div>
  <input type="checkbox" id="t">
  <label for="t">펼치기</label>
  <div class="panel">숨은 내용</div>
</div>
<style>
  .panel { display: none; padding: 8px; background: #ede9fe; }
  #t:checked ~ .panel { display: block; }
</style>
```
> **보이는 것** — 처음엔 「펼치기」 체크박스만 있고, 체크하면 연보라 「숨은 내용」 상자가 나타난다. (코드에서 읽은 것 — 렌더 실측 아님)

### (4) 명시도 — `~` 자체는 점수를 더하지 않는다

**언제 쓰나** — 같은 요소에 여러 규칙이 걸려 어느 값이 이기는지 따질 때 쓴다.

> **명시도** — 여러 규칙이 같은 속성을 놓고 다툴 때 이기는 쪽을 정하는 선택자의 점수다(아이디 · 클래스 · 태그의 개수).\
> 예: `.gen-demo p` 는 (0,1,1), `.gen-demo h3 ~ p` 는 (0,1,2).

```text
.gen-demo p        → 클래스 1, 태그 1  → (0,1,1)
.gen-demo h3 ~ p   → 클래스 1, 태그 2  → (0,1,2)   ← 결합자 ~ 는 0점

두 규칙이 같은 p 의 color 를 정하면 → (0,1,2) 가 이긴다
```

- 결합자(공백 · `>` · `+` · `~`)는 명시도에 아무것도 더하지 않는다.
- `h3 ~ p` 쪽은 태그 `h3` 이 하나 더 있어 점수가 높다.
- 명시도가 같았다면 나중에 적힌 규칙이 이긴다.

## 문법 — 형태와 규칙

```css
/* 기본 꼴: A 뒤에 오는 모든 형제 B */
h3 ~ p { color: purple; }

/* 앞에 조상 조건을 붙여 범위를 좁힌다 */
.card h3 ~ p { margin-left: 1em; }

/* 상태 의사 클래스와 엮는다 */
input:checked ~ .panel { display: block; }

/* 오른쪽을 * 로 두면 뒤의 모든 형제 */
.marker ~ * { opacity: 0.5; }
```

- 꼴은 `A ~ B { }` 다. 기호 `~` 는 물결표다.
- 스타일을 받는 것은 오른쪽 `B` 뿐이다. `A` 는 조건일 뿐이다.
- `A` 와 `B` 는 같은 부모의 자식이어야 한다.
- `A` 는 `B` 보다 문서 순서상 앞에 있어야 한다. 바로 앞일 필요는 없다.
- `~` 앞뒤의 공백은 있어도 없어도 같다(`h3~p` = `h3 ~ p`).

| 결합자 | 꼴 | 고르는 것 |
|---|---|---|
| 자손 | `A B` | A 안의 모든 깊이의 B |
| 자식 | `A > B` | A 의 바로 아래 자식 B |
| 인접 형제 | `A + B` | A 바로 다음 형제가 B 일 때 그 하나 |
| 일반 형제 | `A ~ B` | A 뒤에 오는 모든 형제 B |

## 어디서 틀리나

### 1. 앞쪽 형제도 고를 거라고 생각한다
`h3 ~ p` 는 `h3` 뒤의 `p` 만 고른다.
`h3` 앞에 있는 `p` 는 그대로다.
「형제」라는 말 때문에 양쪽 다 고른다고 오해하기 쉽다.

### 2. `+` 와 헷갈린다
원본 예제처럼 `h3` 과 `p` 사이에 `span` 이 끼어 있으면 `h3 + p` 는 아무것도 고르지 못한다.
`h3` 바로 다음이 `span` 이기 때문이다.
「사이에 뭐가 끼어도 된다」면 `~` 다.

### 3. 기준 요소도 스타일을 받는다고 생각한다
`h3 ~ p` 에서 `h3` 은 조건일 뿐이다.
원본 예제에서 `h3` 의 색은 `.gen-demo h3` 규칙이 정한다.

### 4. 중첩된 요소까지 닿는다고 생각한다
형제 안에 들어 있는 `p` 는 형제가 아니다.
`~` 는 깊이 내려가지 않는다 — 깊이로 내려가는 것은 자손 결합자(공백)다.

### 5. 체크박스 트릭에서 순서를 거꾸로 둔다
원본 팁: CSS-only 인터랙션에서 `~` 를 쓰면 체크박스 상태에 따라 떨어져 있는 형제 요소를 꾸밀 수 있다.
이때 체크박스(`input`)가 꾸밀 요소보다 **앞**에, **같은 부모** 아래 있어야 한다.
`label` 을 감싸는 다른 `div` 안에 `input` 을 넣어 버리면 형제 관계가 깨져 동작하지 않는다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `A ~ B` 는 A 뒤에 오는 같은 부모의 형제 B 를 고른다 | CSS 선택자 명세 |
| 결합자는 명시도에 점수를 더하지 않는다 | CSS 선택자 명세 |
| 체크 상태가 바뀌면 `:checked ~ …` 규칙이 다시 적용된다 | 명세의 `:checked` 정의와 브라우저의 스타일 재계산 — 명세 동작의 조합 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 제목 뒤의 단락을 모두 꾸미기(사이에 다른 요소가 낄 수 있음) | `h3 ~ p` | `h3 + p` (첫 하나만, 끼면 0개) |
| 제목 바로 다음 단락 하나만 꾸미기 | `h3 + p` | `h3 ~ p` (뒤의 것까지 다 걸림) |
| 체크박스로 떨어진 패널 열고 닫기 | `input:checked ~ .panel` | 패널이 체크박스와 다른 부모 아래 있는 구조 |
| 깊이 들어 있는 요소 꾸미기 | 자손 결합자(공백) | `~` (형제만 본다) |
| 앞쪽 형제를 꾸미기 | 클래스를 직접 붙이기 | `~` (뒤쪽만 본다) |

## 핵심 문장

1. **`A ~ B` 는 A 뒤에 오는 모든 형제 B 를 고른다** — 바로 다음이 아니어도 된다.
2. **방향은 뒤쪽 하나뿐이다** — A 앞의 형제, 형제의 자식, 다른 부모의 요소는 고르지 않는다.
3. **`+` 는 바로 다음 하나, `~` 는 뒤의 전부다.**
4. **체크박스 상태와 엮으면 JS 없이 떨어진 형제를 바꿀 수 있다** — 체크박스가 앞에, 같은 부모 아래 있어야 한다.
5. **결합자는 명시도 점수가 0 이다** — 점수는 양쪽 선택자에서만 나온다.

## 용어 풀이

- **결합자** — 두 선택자의 관계를 정하는 기호(공백 · `>` · `+` · `~`).
- **형제** — 같은 부모를 둔 요소들.
- **일반 형제 결합자(`~`)** — 앞의 요소 뒤에 오는 모든 형제를 고르는 결합자.
- **인접 형제 결합자(`+`)** — 앞의 요소 바로 다음 형제 하나만 고르는 결합자.
- **자손 결합자(공백)** — 앞의 요소 안에 있는 모든 깊이의 요소를 고르는 결합자.
- **문서 순서** — HTML 에 요소가 적힌 차례.
- **명시도** — 규칙끼리 다툴 때 이기는 쪽을 정하는 선택자 점수.
- **`:checked`** — 체크된 체크박스 · 라디오 등에 맞는 상태 의사 클래스.
- **CSS-only 인터랙션** — 스크립트 없이 CSS 만으로 사용자 조작에 반응하는 기법.

## 더 들어가면

- 「앞쪽 형제」를 고르는 결합자는 없지만, 최근 CSS 의 `:has()` 를 쓰면 `h3:has(~ p)` 처럼 「뒤에 p 형제가 있는 h3」을 고를 수 있다(지원 범위 확인 필요).
- 브라우저는 선택자를 보통 오른쪽(`B`)부터 따져 거꾸로 올라가는 식으로 매칭한다고 알려져 있다 — 엔진 구현의 이야기이고 명세가 정한 순서가 아니다(확인 필요).
- 체크박스 트릭은 키보드 접근성 · 스크린 리더 안내가 부족해질 수 있어, 실제 서비스에서는 `<details>` 나 스크립트 쪽을 고르기도 한다(확인 필요).
- `A ~ B` 와 `A + B` 는 둘 다 Selectors Level 3 에 들어 있다(확인 필요).
