## 한눈에 — 쉽게 말하면

**`:fullscreen` 은 「무대에 올라간 배우에게만 켜지는 조명」이다.**
배우는 객석에 있을 때 평상복 차림이다.
누군가 그 배우를 무대로 올리면, 그 순간부터 무대 조명과 무대 의상이 적용된다.
무대에서 내려오면 조명도 의상도 사라지고 원래 차림으로 돌아간다.
`:fullscreen` 도 똑같은 구조다.
요소가 전체 화면 모드에 들어가 있는 동안에만 그 규칙이 적용되고, 빠져나오면 원래 스타일로 돌아간다.

| 비유 | 실체 |
|---|---|
| 배우 | 스타일을 받는 요소(`.fs-demo`) |
| 무대에 올리는 사람 | Fullscreen API(`requestFullscreen()`) |
| 무대 조명·의상 | `.fs-demo:fullscreen { … }` 규칙 |
| 무대 뒤 배경막 | `::backdrop` |
| 무대에서 내려옴 | 전체 화면 해제 → 규칙이 더는 맞지 않음 |

```text
  [평소]                         [전체 화면 중]
  ┌────────────┐                ┌──────────────────────────┐
  │ .fs-demo   │   requestFull  │                          │
  │ (기본 규칙) │ ─────────────▶ │  .fs-demo:fullscreen      │
  └────────────┘   screen()     │  (기본 규칙 + 전체화면 규칙) │
                 ◀───────────── │                          │
                   전체 화면 해제  └──────────────────────────┘
```

## 이 주제가 답하려는 질문

1. 요소가 전체 화면일 때만 스타일을 바꾸려면 무엇을 쓰나?
2. CSS 선택자만으로 전체 화면에 들어갈 수 있나, 아니면 다른 무엇이 필요한가?
3. 전체 화면 상태의 스타일은 평소 스타일과 어떻게 겹치고, 언제 사라지나?
4. 전체 화면 요소 뒤의 배경은 어떻게 꾸미나?

## 동작 방식

### (1) 상태를 고르는 의사 클래스

**언제 쓰나** — 요소가 「지금 전체 화면으로 표시되는 중인가」에 따라 모양을 달리하고 싶을 때 쓴다.

`:fullscreen` 은 요소의 이름이나 클래스가 아니라 **상태**를 보고 고르는 선택자다.

> **의사 클래스** — 요소의 상태나 위치처럼 HTML 에 적혀 있지 않은 조건으로 요소를 고르는 선택자. 콜론 하나(`:`)로 쓴다.\
> 예: `:hover` 는 마우스가 올라가 있는 동안, `:fullscreen` 은 전체 화면인 동안 맞는다.

```text
입력:  .fs-demo:fullscreen { background: #0f172a; }

브라우저가 요소마다 묻는다
  ① class 에 fs-demo 가 있나?        ── 아니오 → 안 맞음
  ② 지금 전체 화면으로 표시 중인가?    ── 아니오 → 안 맞음
  ③ 둘 다 예                         → 규칙 적용

결과:  전체 화면 중인 .fs-demo 만 배경이 바뀐다
```

- ① `.fs-demo` 부분이 「어떤 요소인가」를 거른다.
- ② `:fullscreen` 부분이 「지금 어떤 상태인가」를 거른다.
- ③ 두 조건이 동시에 참일 때만 규칙이 붙는다.

### (2) 상태를 만드는 것은 Fullscreen API 다

**언제 쓰나** — 사용자가 버튼이나 박스를 눌렀을 때 그 요소를 전체 화면으로 키우고 싶을 때 쓴다.

`:fullscreen` 은 상태를 **읽기만** 한다.
요소를 전체 화면에 **넣는** 일은 JavaScript 의 Fullscreen API 가 한다.
원본 팁도 「Fullscreen API와 함께 사용한다」고 말한다.

> **Fullscreen API** — 요소를 화면 전체로 띄우고 해제하는 브라우저의 JavaScript 기능 묶음.\
> 예: `element.requestFullscreen()` 은 그 요소를 전체 화면으로 띄워 달라고 요청한다.

```text
입력:  <div class="fs-demo" onclick="this.requestFullscreen()">

  사용자가 박스를 클릭
        │
        ▼
  onclick 실행 → this(클릭된 div).requestFullscreen()
        │
        ▼
  브라우저가 그 div 를 전체 화면으로 띄움
        │
        ▼
  이제 그 div 에 :fullscreen 이 맞음 → .fs-demo:fullscreen 규칙 적용

결과:  클릭한 박스만 전체 화면 스타일로 바뀐다
```

- `onclick` 속성은 클릭 때 실행할 코드를 담는다.
- `this` 는 클릭된 그 요소 자신을 가리키므로, 박스가 여럿이어도 누른 박스만 전체 화면이 된다.
- 전체 화면에 들어간 뒤에야 `:fullscreen` 이 그 요소에 맞는다.

### (3) 평소 규칙 위에 덮어쓰기

**언제 쓰나** — 평소 모양은 그대로 두고 전체 화면일 때 달라질 속성만 골라 바꿀 때 쓴다.

```text
입력:
  .fs-demo            { background: #1e293b; border-radius: 12px; color: white; … }
  .fs-demo:fullscreen { background: #0f172a; border-radius: 0; }

전체 화면 중인 .fs-demo 에 두 규칙이 모두 맞는다
  background     : #1e293b (명시도 0,1,0)  vs  #0f172a (명시도 0,2,0)  → #0f172a
  border-radius  : 12px    (0,1,0)        vs  0       (0,2,0)        → 0
  color          : white   (0,1,0)        vs  (선언 없음)              → white 유지

결과:  배경·모서리만 바뀌고 나머지는 평소 값이 그대로 남는다
```

- 전체 화면 중에는 평소 규칙과 전체 화면 규칙이 **둘 다** 맞는다.
- 같은 속성이 부딪히면 명시도가 높은 쪽이 이긴다.
- `.fs-demo:fullscreen` 은 클래스 하나 + 의사 클래스 하나라서 `.fs-demo`(클래스 하나)보다 명시도가 높다.
- 전체 화면 규칙에 없는 속성(`color`, `display` 등)은 평소 값이 그대로 쓰인다.

> **명시도** — 같은 속성을 두고 여러 규칙이 부딪힐 때 어느 쪽이 이길지 정하는 점수. 클래스와 의사 클래스는 같은 무게로 센다.\
> 예: `.a:hover` 는 클래스 1 + 의사 클래스 1 이라 `.a` 보다 높다.

### (4) 자손까지 바꾸기

**언제 쓰나** — 전체 화면이 된 요소 **안쪽**의 글자 · 이미지 크기도 함께 키우고 싶을 때 쓴다.

```text
입력:  .fs-demo:fullscreen p { font-size: 32px; }

  .fs-demo  ← 전체 화면인가?  예
     └─ p   ← 그 안에 있는 p 인가?  예  → 32px

  .fs-demo  ← 전체 화면인가?  아니오
     └─ p   → 규칙 안 맞음 → 평소 글자 크기

결과:  전체 화면일 때만 안내 문구가 커진다
```

- 공백은 자손 선택자다 — 「앞 요소 안에 들어 있는」 `p` 를 고른다.
- 상태 조건(`:fullscreen`)은 바깥 요소에 붙어 있으므로, 바깥 요소가 전체 화면이 아니면 `p` 도 고르지 않는다.

> **자손 선택자** — 두 선택자를 공백으로 이어, 앞 요소 안에 들어 있는 뒤 요소를 고르는 꼴.\
> 예: `.card p` 는 `.card` 안의 모든 `p` 를 고른다.

### (5) 전체 화면에서 나오면 원래대로

**언제 쓰나** — 따로 「되돌리는 코드」를 쓰지 않아도 된다는 점을 알아 둘 때.

```text
전체 화면 중:  .fs-demo + .fs-demo:fullscreen 규칙 적용
      │
      ▼  (전체 화면 해제)
평소:         .fs-demo 규칙만 적용 → 배경·모서리·글자 크기가 원래 값
```

- 의사 클래스는 상태가 참인 동안에만 맞는다.
- 상태가 끝나면 규칙이 저절로 빠지므로, 스타일을 되돌리는 JavaScript 는 필요 없다.

### (6) 배경막 `::backdrop`

**언제 쓰나** — 전체 화면 요소 **뒤**에 깔리는 배경을 꾸밀 때 쓴다(원본 팁).

> **의사 요소** — HTML 에 없는 「가상의 부분」을 만들어 꾸미는 선택자. 콜론 둘(`::`)로 쓴다.\
> 예: `::backdrop` 은 전체 화면 요소 바로 뒤에 깔리는 배경 판이다.

```text
  ┌──────────────── 화면 ────────────────┐
  │  ::backdrop  (뒤에 깔린 배경 판)       │
  │   ┌──────────────────────────────┐   │
  │   │  .fs-demo:fullscreen (요소)   │   │
  │   └──────────────────────────────┘   │
  └──────────────────────────────────────┘
```

- `:fullscreen` 은 요소 자신을, `::backdrop` 은 그 요소 뒤의 판을 고른다.
- 둘은 「상태(:)」와 「가상의 부분(::)」이라는 다른 종류의 선택자다.

## 문법 — 형태와 규칙

```html demo
<div class="stage" onclick="this.requestFullscreen()">
  <p>눌러서 크게 보기</p>
</div>
<style>
  .stage { width: 160px; height: 90px; background: #334155; color: white;
           display: flex; align-items: center; justify-content: center; cursor: pointer; }
  .stage:fullscreen { background: #000; }
  .stage:fullscreen p { font-size: 40px; }
  .stage::backdrop { background: #000; }
</style>
```

> **보이는 것** — 평소에는 작은 회색 박스에 문구가 있고, 누르면 그 박스가 전체 화면이 되어 배경이 검게, 문구가 크게 바뀐다 (코드에서 읽은 것 — 렌더 실측 아님)

- 형태: `selector:fullscreen { }` — 앞의 선택자로 요소를 고르고, `:fullscreen` 으로 「전체 화면 중」 조건을 더한다.
- 자손에 적용: `selector:fullscreen 자손선택자 { }`.
- 배경막: `selector::backdrop { }` — 콜론이 둘이다.
- 전체 화면 진입은 CSS 가 아니라 JavaScript 의 `requestFullscreen()` 이 한다.
- 평소 규칙과 함께 쓰면 전체 화면 규칙이 명시도로 이긴다.

| 조각 | 하는 일 |
|---|---|
| `.fs-demo` | 클래스로 요소를 고른다 |
| `:fullscreen` | 그 요소가 전체 화면 중일 때만 맞게 한다 |
| `p` (공백 뒤) | 그 안의 `p` 까지 범위를 넓힌다 |
| `::backdrop` | 전체 화면 요소 뒤의 배경 판을 고른다 |
| `this.requestFullscreen()` | 클릭된 요소를 전체 화면으로 띄워 달라고 요청한다 |

## 어디서 틀리나

### 1. CSS 만 쓰고 「왜 전체 화면이 안 되지?」

`:fullscreen` 규칙을 써 두는 것만으로는 아무 일도 일어나지 않는다.
선택자는 상태를 읽을 뿐이고, 상태를 만드는 것은 Fullscreen API 다(원본 팁: 「Fullscreen API와 함께 사용한다」).

### 2. 배경을 `:fullscreen` 으로만 꾸미고 뒤의 판을 잊는다

요소 바깥, 뒤에 깔린 영역은 요소의 스타일이 아니다.
그 부분은 `::backdrop` 으로 따로 꾸민다(원본 팁).

### 3. `::backdrop` 을 콜론 하나로 쓴다

`::backdrop` 은 의사 요소라 콜론 둘이다.
`:fullscreen` 은 의사 클래스라 콜론 하나다.

### 4. 되돌리는 코드를 따로 쓴다

전체 화면을 나오면 `:fullscreen` 이 더는 맞지 않아 원래 스타일로 돌아간다.
평소 모양을 복원하는 JavaScript 는 필요 없다.

### 5. `this` 대신 고정된 요소를 부른다

`onclick` 안에서 `this` 는 클릭된 요소다.
다른 요소를 가리키면 누른 박스가 아닌 엉뚱한 요소가 전체 화면이 된다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 전체 화면 중인 요소에 `:fullscreen` 이 맞는다 | 웹 표준(Fullscreen 명세) |
| 클래스와 의사 클래스는 명시도에서 같은 무게다 | CSS 표준(선택자 명세) |
| `::backdrop` 이 전체 화면 요소 뒤에 깔린다 | 웹 표준(확인 필요 — 원본은 팁으로만 언급) |
| 전체 화면을 나가는 키 · 화면에 뜨는 안내 문구 | 브라우저마다 다름 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 동영상 · 슬라이드 · 이미지 뷰어를 크게 띄울 때 모양 바꾸기 | `:fullscreen` | 클래스를 JS 로 붙였다 떼기 |
| 전체 화면 요소 뒤 배경 꾸미기 | `::backdrop` | 요소 자신의 `background` |
| 요소를 전체 화면으로 띄우기 | `requestFullscreen()` | CSS 선택자 |
| 창 크기에 따라 모양 바꾸기(전체 화면과 무관) | 미디어 쿼리 | `:fullscreen` |

## 핵심 문장

1. **`:fullscreen` 은 「전체 화면 중」이라는 상태를 고르는 의사 클래스다.**
2. **상태를 만드는 것은 Fullscreen API(`requestFullscreen()`)이고, CSS 는 그 상태를 읽어 꾸밀 뿐이다.**
3. **전체 화면 규칙은 명시도가 높아 평소 규칙 위에 덮이고, 상태가 끝나면 저절로 빠진다.**
4. **`selector:fullscreen 자손` 으로 안쪽 요소까지, `::backdrop` 으로 뒤 배경까지 꾸민다.**

## 관련 자료

- `::backdrop` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `:modal` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- 원본: study-site 항목 데이터 `data/css/selectors.json` 의 `fullscreen`

## 용어 풀이

- **의사 클래스** — 상태나 위치로 요소를 고르는 선택자, 콜론 하나.
- **의사 요소** — 가상의 부분을 만들어 꾸미는 선택자, 콜론 둘.
- **`:fullscreen`** — 전체 화면으로 표시되는 중인 요소에 맞는 의사 클래스.
- **`::backdrop`** — 전체 화면 요소 뒤에 깔리는 배경 판.
- **Fullscreen API** — 요소를 전체 화면으로 띄우고 해제하는 JavaScript 기능.
- **`requestFullscreen()`** — 요소를 전체 화면으로 띄워 달라고 요청하는 메서드.
- **명시도** — 부딪히는 규칙 가운데 이길 쪽을 정하는 점수.
- **자손 선택자** — 공백으로 이어 앞 요소 안의 뒤 요소를 고르는 꼴.
- **`this`(onclick 안)** — 이벤트가 일어난 요소 자신.

- 예전 브라우저에는 `:-webkit-full-screen` 같은 접두사 붙은 이름이 있었다 (확인 필요).
