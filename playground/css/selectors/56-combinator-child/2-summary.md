## 한눈에 — 쉽게 말하면

**`A > B` 는 「팀장의 직속 팀원만 불러 모으기」다.**
팀장이 「내 팀원 모여라」라고 하면 바로 아래 팀원만 온다.
팀원 밑에 있는 인턴(팀장의 손자뻘)은 오지 않는다.
CSS 의 자식 결합자도 똑같은 구조다.
`A` 의 바로 아래 한 단계에 있는 `B` 만 고르고, 그보다 깊은 `B` 는 고르지 않는다.

| 비유 | 실체 |
|---|---|
| 팀장 | 왼쪽 선택자 `A` (예: `.child-demo`) |
| 직속 팀원 | `A` 의 직접 자식인 `B` (예: 바깥 `ul` 바로 아래 `li`) |
| 팀원 밑의 인턴 | `A` 의 손자 이하인 `B` (예: 안쪽 `ul` 안의 `li`) |
| 「직속만 모여라」 | 결합자 `>` |

```text
ul.child-demo            ← A
├── li  "직접 자식 1"     ← A > li 에 걸린다
│   └── ul
│       └── li "손자"     ← A > li 에 걸리지 않는다 (부모가 A 가 아니다)
└── li  "직접 자식 2"     ← A > li 에 걸린다
```

## 이 주제가 답하려는 질문

1. `A > B` 는 문서 트리에서 어떤 `B` 를 고르고, 어떤 `B` 를 빼나?
2. 손자처럼 더 깊은 요소를 정확히 짚으려면 어떻게 쓰나?
3. `>` 로 손자를 뺐는데도 손자에 스타일이 닿아 보이는 것은 왜인가?
4. 띄어쓰기(자손 결합자)와는 무엇이 다른가?

## 동작 방식

### (1) 직접 자식만 고른다

**언제 쓰나** — 목록 · 카드 · 메뉴처럼 중첩될 수 있는 구조에서 바깥 한 단계에만 꾸밈을 주고 싶을 때 쓴다.

```text
규칙: .child-demo > li { ... }

각 li 에 대해 묻는다: "내 부모가 .child-demo 인가?"

li "직접 자식 1" → 부모 = ul.child-demo → 예 → 매칭
li "손자"        → 부모 = ul (class 없음) → 아니오 → 매칭 안 됨
li "직접 자식 2" → 부모 = ul.child-demo → 예 → 매칭

결과: 매칭 2개 (직접 자식 1, 직접 자식 2)
```

- 규칙이 고르는 요소는 맨 오른쪽 `li` 다.
- 그 `li` 의 **바로 위 부모**가 왼쪽 선택자 `.child-demo` 에 맞는지만 본다.
- 손자 `li` 의 부모는 class 가 없는 안쪽 `ul` 이라 조건에 맞지 않는다.
- 그래서 직접 자식 둘만 걸린다.

### (2) `>` 를 이어 붙여 깊이를 정확히 짚는다

**언제 쓰나** — 손자처럼 특정 깊이의 요소만 따로 꾸밀 때 쓴다.

```text
규칙: .child-demo > li > ul > li

오른쪽부터 한 칸씩 올라가며 확인한다:
li "손자"
  부모가 ul 인가?            → 예 (안쪽 ul)
  그 ul 의 부모가 li 인가?    → 예 ("직접 자식 1")
  그 li 의 부모가 .child-demo? → 예
→ 매칭

li "직접 자식 1"
  부모가 ul 인가? → 예 (ul.child-demo)
  그 ul 의 부모가 li 인가? → 아니오 (body)
→ 매칭 안 됨
```

- 체인의 각 `>` 는 「바로 한 단계 위」를 뜻한다.
- 모든 칸이 빈틈없이 이어져야 매칭된다.
- 정답 코드는 이 방식으로 세 규칙을 깊이별로 나눴다: `.child-demo > li`(1단계) · `.child-demo > li > ul`(2단계) · `.child-demo > li > ul > li`(3단계).

### (3) 매칭은 막아도 상속은 막지 않는다

**언제 쓰나** — `>` 로 바깥만 꾸몄는데 안쪽도 같이 바뀐 것처럼 보일 때 이 원리로 따진다.

```text
.child-demo > li { font-weight: bold; background: <연녹색>; }

li "직접 자식 1"   font-weight: bold (규칙이 직접 줌)
  └ ul             font-weight: bold (부모에게서 상속)
     └ li "손자"   font-weight: bold (상속) ← 규칙은 안 걸렸는데 굵다
                   background: 투명 (배경은 상속 안 됨)
                   → 부모 li 의 연녹색이 비쳐 보인다
```

- `>` 가 막는 것은 **규칙이 어느 요소에 걸리나(매칭)** 뿐이다.
- `font-weight` 처럼 상속되는 속성은 부모에서 자식으로 그대로 흘러 내려간다.
- `background` 는 상속되지 않지만, 손자 `li` 의 배경이 기본값(투명)이면 그 뒤의 부모 배경이 보인다.
- 그래서 정답 코드는 손자 규칙에 `font-weight: normal` 과 자기 배경(회색)을 따로 적어 되돌린다.

> **상속** — 부모 요소에 정해진 값을 자식 요소가 따로 지정이 없을 때 물려받는 것.\
> 예: 부모 `li` 의 `font-weight: bold` 를 안쪽 `li` 가 물려받는다.

### (4) 띄어쓰기(자손 결합자)와 비교

**언제 쓰나** — 깊이와 상관없이 모두 고를지, 한 단계만 고를지 정할 때 비교한다.

```text
.child-demo li    (띄어쓰기) → 직접 자식 1, 손자, 직접 자식 2   (3개)
.child-demo > li  (꺾쇠)     → 직접 자식 1, 직접 자식 2        (2개)
```

- 띄어쓰기는 「어디든 안에 있으면」이고, `>` 는 「바로 아래에 있으면」이다.
- 중첩이 없는 구조에서는 둘의 결과가 같다.
- 중첩이 생기는 순간 차이가 드러난다.

> **자손 결합자** — 선택자 사이의 띄어쓰기. 깊이와 상관없이 안에 든 요소를 모두 고른다.\
> 예: `.child-demo li` 는 손자 `li` 도 고른다.

## 문법 — 형태와 규칙

```html demo
<style>
  .menu { list-style: none; padding: 0; }
  .menu > li { font-weight: bold; background: #dcfce7; margin: 4px 0; padding: 8px; }
  .menu > li > ul > li { font-weight: normal; background: #f3f4f6; }
</style>
<ul class="menu">
  <li>메뉴 A
    <ul><li>하위 A-1</li></ul>
  </li>
  <li>메뉴 B</li>
</ul>
```

> **보이는 것** — 「메뉴 A」「메뉴 B」는 굵은 글씨에 연녹색 띠, 「하위 A-1」은 보통 굵기에 회색 띠로 연녹색 띠 안쪽에 들여쓰기되어 놓인다. (코드에서 읽은 것 — 렌더 실측 아님)

| 형태 | 고르는 것 |
|---|---|
| `A > B` | `A` 의 직접 자식인 `B` |
| `A > B > C` | `A` 의 직접 자식 `B` 의 직접 자식인 `C` |
| `A B` | `A` 안 어디든 있는 `B` (자손 결합자 — 비교용) |

- 스타일을 받는 것은 언제나 **맨 오른쪽** 선택자에 맞는 요소다.
- `A` · `B` 자리에는 태그 · 클래스 · 속성 선택자 등 무엇이든 올 수 있다.
- `>` 양옆의 띄어쓰기는 있어도 없어도 같다(`A>B` = `A > B`).
- `>` 와 띄어쓰기를 한 선택자 안에 섞어 쓸 수 있다(`.nav > ul li`).

> **결합자** — 두 선택자 사이에 놓여 두 요소의 관계(부모-자식 · 조상-자손 등)를 정하는 기호.\
> 예: `>` · 띄어쓰기.

## 어디서 틀리나

### 1. 「하위 컴포넌트 침투를 막는다」는 팁은 절반만 맞다

원본 팁은 「컴포넌트 스타일링 시 `>` 결합자를 사용하면 하위 컴포넌트에 스타일이 침투하는 것을 방지할 수 있다」고 한다.
맞는 부분: 규칙이 안쪽 컴포넌트의 요소에 **직접 걸리는 것**은 막는다.
의심스러운 부분: `font-weight` · `color` 같은 **상속되는 속성**은 바깥 요소에서 안쪽으로 그대로 흘러 들어간다.
정답 코드가 손자에 `font-weight: normal` 을 다시 적은 것이 바로 그 증거다.

### 2. 배경은 상속되지 않지만 비쳐 보인다

손자 규칙을 지우면 손자 `li` 의 배경은 투명이다.
그러면 손자를 감싼 부모 `li` 의 연녹색이 그 뒤로 보인다.
「규칙이 손자에도 걸렸다」로 오해하기 쉽다.

### 3. 사이에 한 겹이 끼면 끊긴다

`.card > p` 는 `.card` 와 `p` 사이에 `section` 같은 래퍼가 하나라도 끼면 그 `p` 를 고르지 않는다.
마크업 구조를 바꾸면 `>` 규칙이 조용히 안 걸리게 된다.

### 4. 고르는 것은 왼쪽이 아니라 오른쪽이다

`.child-demo > li` 의 스타일은 `.child-demo` 가 아니라 `li` 에 붙는다.
`.child-demo > li > ul` 은 `ul` 을 꾸민다(정답 코드에서 위쪽 여백 `margin-top`).

### 5. 바깥 `ul` 에 준 값이 안쪽 `ul` 에 닿는지는 속성마다 다르다

정답 코드는 `.child-demo` 에만 `list-style: none` 과 `padding: 0` 을 준다.
`list-style` 은 상속되는 속성이라 안쪽 목록의 마커도 사라진다.
`padding` 은 상속되지 않아 안쪽 `ul` 은 브라우저 기본 들여쓰기를 그대로 가진다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `A > B` 는 `A` 의 직접 자식인 `B` 만 고른다 | CSS 선택자 명세 |
| `font-weight` · `list-style` 은 상속되고 `background` · `padding` 은 상속되지 않는다 | CSS 명세(속성마다 정해짐) |
| 안쪽 `ul` 이 기본으로 들여쓰기된다 | 브라우저 기본 스타일시트 — 브라우저마다 값이 다를 수 있다 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 중첩 목록의 바깥 항목만 꾸민다 | `.list > li` | `.list li` |
| 깊이와 상관없이 안쪽 링크를 전부 꾸민다 | `.article a` | `.article > a` |
| 카드 컴포넌트 바로 아래 요소만 꾸미고 안쪽 컴포넌트는 건드리지 않는다 | `.card > p` (+ 상속 속성은 안쪽에서 되돌리기) | `.card p` |
| 마크업 사이에 래퍼가 자주 바뀐다 | 클래스 하나로 직접 고르기 | 긴 `>` 체인 |

## 핵심 문장

1. **`A > B` 는 바로 한 단계 아래의 `B` 만 고른다** — 손자 이하는 빠진다.
2. **`>` 를 이어 붙이면 깊이를 정확히 짚는다** — 모든 칸이 빈틈없이 이어져야 매칭된다.
3. **`>` 는 매칭을 막을 뿐 상속은 막지 않는다** — 상속 속성은 안쪽에서 되돌려야 한다.
4. **스타일을 받는 것은 맨 오른쪽 요소다.**
5. **띄어쓰기는 「어디든 안」, `>` 는 「바로 아래」다.**

## 용어 풀이

> **결합자** — 두 선택자 사이에서 요소의 관계를 정하는 기호.\
> 예: `>` · 띄어쓰기.

> **자식 결합자** — `>`. 왼쪽 요소의 직접 자식인 오른쪽 요소만 고른다.\
> 예: `.child-demo > li`.

> **자손 결합자** — 띄어쓰기. 깊이와 상관없이 안에 든 요소를 고른다.\
> 예: `.child-demo li`.

> **직접 자식** — 부모 바로 아래 한 단계의 요소.\
> 예: `ul.child-demo` 바로 아래의 `li` 두 개.

> **손자(자손)** — 두 단계 이상 아래에 있는 요소.\
> 예: 안쪽 `ul` 안의 「손자」 `li`.

> **매칭** — 선택자가 어떤 요소를 고르는 것.\
> 예: `.child-demo > li` 가 「직접 자식 1」에 매칭된다.

> **상속** — 지정이 없을 때 부모의 값을 자식이 물려받는 것.\
> 예: `font-weight: bold` 가 손자에게 내려간다.

## 더 들어가면

- 결합자 자체는 명시도(specificity)에 아무것도 더하지 않는다는 것이 일반적인 설명이다 — `.a > b` 와 `.a b` 의 명시도는 같다 (확인 필요).
- 브라우저는 선택자를 오른쪽에서 왼쪽으로 맞춰 본다고 흔히 설명한다 — 엔진의 구현 방식이다 (확인 필요).
- 다른 결합자로 `+`(바로 다음 형제) · `~`(뒤따르는 형제)가 있다.
- `:has(> img)` 처럼 `:has()` 안에서 `>` 로 시작하는 상대 선택자를 쓸 수 있다 — 지원 범위는 (확인 필요).
