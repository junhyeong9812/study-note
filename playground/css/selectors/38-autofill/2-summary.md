# css/selectors/38 — :autofill — 정리 (힌트)

> 출처 — study-site 항목 `css/autofill`(항목 데이터 `data/css/selectors.json`) · 정답 코드 study-practice `css/selectors/reference/autofill.html`\

## 한눈에 — 쉽게 말하면

**`:autofill` 은 「남이 대신 써 준 칸에 찍히는 도장」이다.**
은행 창구에서 직원이 내 이름을 대신 적어 주면, 그 칸에는 「직원 대필」 도장이 찍힌다.
내가 직접 쓴 칸에는 도장이 없다.
도장이 찍힌 칸만 형광펜으로 칠하라는 규칙을 정해 두면, 대신 써 준 칸만 눈에 띈다.
웹 폼도 똑같은 구조다.
브라우저가 저장해 둔 값으로 칸을 채우면 그 `input` 에 `:autofill` 상태가 붙는다.
CSS 는 그 상태가 붙은 칸에만 스타일을 입힌다.

| 비유 | 실체 |
|---|---|
| 은행 서류의 빈칸 | `input` 요소 |
| 대신 써 주는 직원 | 브라우저의 자동완성 기능 |
| 「직원 대필」 도장 | `:autofill` 상태 |
| 도장 찍힌 칸만 칠하는 형광펜 | `input:autofill { … }` 규칙 |
| 직원이 멋대로 칠하는 기본 색 | 브라우저가 강제로 넣는 기본 배경색 |

```text
  [ 사용자 이름 칸 ]
        │
        ├─ 사용자가 직접 타이핑 ──────▶ 상태 없음   → .af-input 규칙만
        │
        └─ 브라우저가 저장값으로 채움 ─▶ :autofill   → .af-input + .af-input:autofill 규칙
```

## 이 주제가 답하려는 질문

1. 어떤 `input` 에, 언제 `:autofill` 이 걸리나?
2. 자동완성된 칸의 모양을 내 디자인대로 바꾸려면 무엇을 써야 하나?
3. 브라우저가 강제로 넣는 기본 배경색은 왜 일반 `background` 로 잘 안 바뀌고, 어떻게 덮나?

## 동작 방식

### (1) 자동완성이 일어나면 선택자가 걸린다

**언제 쓰나** — 브라우저가 채운 칸을 사용자가 알아보게 표시하고 싶을 때 쓴다.
「이 값은 내가 친 게 아니라 저장된 값이다」를 눈으로 확인시켜 주는 용도다.

> **자동완성(autofill)** — 브라우저가 전에 저장해 둔 값(이름 · 주소 · 아이디 등)을 폼 칸에 대신 채워 넣는 기능.\
> 예: 로그인 칸을 누르면 전에 쓴 아이디가 후보로 뜨고, 고르면 칸이 채워진다.

> **의사 클래스(pseudo-class)** — 요소의 HTML 에 적혀 있지 않은 「상태」를 보고 고르는 선택자. 콜론 하나(`:`)로 시작한다.\
> 예: `:hover` 는 마우스가 올라간 상태, `:focus` 는 입력 포커스를 받은 상태, `:autofill` 은 자동완성으로 채워진 상태.

```text
입력 코드
  <input class="af-input" name="username" autocomplete="username">
  .af-input:autofill { border-color: #f59e0b; }

무엇이 일어나나
  ① 사용자가 칸을 누른다
  ② 브라우저가 저장된 사용자 이름 후보를 보여 준다
  ③ 사용자가 후보를 고른다 → 브라우저가 값을 채운다
  ④ 그 순간 input 이 :autofill 상태가 된다
  ⑤ .af-input:autofill 규칙이 걸린다

결과
  테두리가 주황(#f59e0b)으로 바뀐다 (코드에서 읽은 것 — 렌더 실측 아님)
```

- ①~③ 은 CSS 가 아니라 브라우저와 사용자가 하는 일이다.
- ④ 에서 상태를 붙이는 주체는 브라우저다 — 사용자가 직접 친 값에는 이 상태가 붙지 않는다.
- ⑤ 부터가 CSS 의 몫이다.
- `autocomplete="username"` 은 브라우저에게 「이 칸은 사용자 이름 칸」이라고 알려 주는 힌트다 — 이 힌트가 있어야 브라우저가 어떤 저장값을 넣을지 판단하기 쉽다.

> **`autocomplete` 속성** — 입력 칸에 어떤 종류의 값이 들어가는지 브라우저에 알려 주는 HTML 속성.\
> 예: `autocomplete="username"` 은 사용자 이름, `autocomplete="off"` 는 자동완성을 하지 말라는 뜻.

### (2) 브라우저의 기본 배경색과 box-shadow 로 덮는 트릭

**언제 쓰나** — 자동완성된 칸의 배경이 디자인과 어울리지 않는 색으로 바뀔 때 쓴다.

원본 팁에 따르면 Chrome 등 브라우저는 자동완성 때 **기본 배경색을 강제로 적용한다**.
그래서 작성자가 `background` 를 적어도 그 색이 보이지 않는 일이 생긴다.
이때 쓰는 우회로가 `box-shadow` 로 배경 위를 덮는 트릭이다.

```text
입력 코드
  input:autofill { box-shadow: inset 0 0 0 1000px white; }

무엇이 일어나나 (칸을 그리는 층, 아래 → 위)
  ┌──────────────────────────────────┐
  │ 글자(값)                          │  ← 맨 위
  │ inset 그림자 (흰색, 두께 1000px)   │  ← 배경을 가린다
  │ 배경 (브라우저가 강제한 색)         │  ← 맨 아래, 가려진다
  └──────────────────────────────────┘

결과
  칸 안쪽이 흰색으로 보인다 (코드에서 읽은 것 — 렌더 실측 아님)
```

- 배경색 자체를 바꾸는 싸움을 피하고, 배경 **위**에 다른 층을 깐다.
- `inset` 그림자는 요소 테두리 안쪽, 배경 위에 그려진다.
- 두께(네 번째 값, 퍼짐)를 칸보다 크게 주면 안쪽 전체가 그림자 색으로 덮인다.
- 바깥 그림자(`inset` 없는 것)는 테두리 **밖**에 그려지므로 배경을 덮지 못한다.

> **`box-shadow`** — 요소 둘레에 그림자를 그리는 속성. 값 순서는 `가로 세로 흐림 퍼짐 색`, 앞에 `inset` 을 붙이면 안쪽 그림자가 된다.\
> 예: `box-shadow: 0 0 0 1px orange` 는 흐림 없는 1px 주황 테두리 같은 고리, `box-shadow: inset 0 0 0 1000px white` 는 안쪽을 흰색으로 가득 덮는다.

### (3) 원본 예제에서 규칙이 겹치는 방식

**언제 쓰나** — 평소 모양과 자동완성 모양을 나눠 적을 때, 어느 규칙이 이기는지 알아야 한다.

```text
입력 코드
  .af-input          { border: 2px solid #d1d5db; transition: all 0.2s; }
  .af-input:autofill { border-color: #f59e0b; box-shadow: 0 0 0 1px #f59e0b;
                       background: #fef3c7 !important; }

무엇이 일어나나
  평소      : .af-input 만 걸림 → 회색 테두리
  자동완성  : 두 규칙이 모두 걸림
             .af-input:autofill 이 더 구체적(클래스 + 의사 클래스)
             → border-color 는 주황이 이긴다
  전환      : transition: all 0.2s → 바뀌는 속성이 0.2초에 걸쳐 변한다

결과
  자동완성 순간 테두리가 회색에서 주황으로 0.2초 동안 바뀌고,
  바깥에 1px 주황 고리가 생긴다 (코드에서 읽은 것 — 렌더 실측 아님)
```

- 두 규칙 모두 같은 `input` 을 고른다.
- `.af-input:autofill` 은 클래스 하나 + 의사 클래스 하나라서 `.af-input`(클래스 하나)보다 명시도가 높다.
- 그래서 겹치는 속성(`border-color`)은 자동완성 규칙의 값이 쓰인다.
- 겹치지 않는 속성(`padding` · `width` 등)은 평소 규칙의 값이 그대로 남는다.
- `transition: all 0.2s` 는 평소 규칙에 있으므로 상태가 바뀔 때마다 변화가 부드럽게 이어진다.
- 원본의 `box-shadow: 0 0 0 1px #f59e0b` 는 바깥 고리라서 (2)의 「배경 덮기」가 아니라 테두리 강조용이다.

> **명시도(specificity)** — 같은 요소에 규칙이 여럿 걸릴 때 어느 쪽이 이기는지 정하는 점수. 의사 클래스는 클래스와 같은 무게로 센다.\
> 예: `.a:focus` 는 `.a` 보다 명시도가 높다.

> **`!important`** — 선언 하나의 우선순위를 크게 끌어올리는 표시. 일반 선언끼리의 싸움에서는 거의 언제나 이긴다.\
> 예: `color: red !important;`

## 문법 — 형태와 규칙

```html demo
<input class="name" type="text" name="username" autocomplete="username" placeholder="사용자 이름">
<style>
  .name {
    padding: 8px 12px;
    border: 2px solid #d1d5db;
    border-radius: 6px;
    transition: all 0.2s;
  }
  .name:autofill {
    border-color: #2563eb;
    box-shadow: inset 0 0 0 1000px #eff6ff; /* 기본 배경 위를 연한 파랑으로 덮는다 */
  }
</style>
```

> **보이는 것** — 평소에는 회색 테두리의 빈 칸이고, 저장된 이름으로 자동완성하면 테두리가 파랗게 바뀌고 안쪽이 연한 파랑으로 덮인다 (코드에서 읽은 것 — 렌더 실측 아님)

| 부분 | 뜻 |
|---|---|
| `input` | 고를 요소 — 원본 설명은 `input` 요소를 대상으로 한다 |
| `:autofill` | 「브라우저가 자동완성으로 값을 채운 상태」라는 조건 |
| `.af-input:autofill` | 클래스로 좁힌 형태 — 그 클래스를 가진 `input` 중 자동완성된 것만 |
| `{ … }` | 그 상태일 때만 덧입힐 선언 |

- 꼴은 `input:autofill { }` 이다(원본 문법).
- 의사 클래스는 선택자 뒤에 띄어 쓰지 않고 붙인다 — `input :autofill` 처럼 띄우면 「`input` 의 자손 중 자동완성된 것」이라는 다른 뜻이 된다.
- 평소 모양은 일반 규칙에, 자동완성 때 달라질 부분만 `:autofill` 규칙에 적는다.
- 배경색은 브라우저가 강제할 수 있으므로, 배경을 바꾸려면 `box-shadow: inset …` 으로 덮는 방법을 함께 생각한다.
- `autocomplete` 속성으로 칸의 종류를 알려 주면 자동완성이 일어날 자리가 분명해진다.

## 어디서 틀리나

### 1. `background` 를 적었는데 색이 안 바뀐다

원본 팁 그대로, Chrome 등 브라우저는 자동완성 때 기본 배경색을 강제 적용한다.
그래서 `input:autofill { background: … }` 만으로는 원하는 색이 보이지 않을 수 있다.
해결은 `box-shadow` 로 덮는 트릭이다 — 동작 방식 (2) 참고.

### 2. 원본 예제의 `background: #fef3c7 !important`

원본의 주장 → 주석은 「자동완성 시 노란색 배경 강제 적용」이라고 적는다.
왜 의심스러운가 → 같은 원본의 팁이 「브라우저가 기본 배경색을 강제 적용하니 box-shadow 로 덮으라」고 말한다.
`!important` 를 붙여도 브라우저가 강제하는 색을 이긴다는 보장은 원본 어디에도 없다.
브라우저에 따라 이 노란 배경이 보이지 않을 수 있다 (확인 필요).

### 3. 바깥 그림자로는 배경을 덮을 수 없다

원본 예제의 `box-shadow: 0 0 0 1px #f59e0b` 는 `inset` 이 없는 바깥 그림자다.
바깥 그림자는 테두리 밖에 그려지므로 칸 안쪽 배경에는 닿지 않는다.
팁이 말하는 「덮는 트릭」은 `inset` 에 칸보다 큰 퍼짐 값을 준 그림자다.
두 용도(테두리 강조 · 배경 덮기)를 헷갈리지 않는다.

### 4. 직접 타이핑한 값에는 걸리지 않는다

`:autofill` 은 「값이 있다」가 아니라 「브라우저가 채웠다」를 보는 조건이다.
「값이 들어간 칸을 모두 칠하고 싶다」면 이 선택자가 아니다.

### 5. 자동완성이 아예 일어나지 않으면 규칙도 영영 안 걸린다

저장된 값이 없거나, 사용자가 자동완성을 끄거나, `autocomplete="off"` 인 칸이면 상태가 붙을 일이 없다.
그래서 `:autofill` 규칙에 꼭 필요한 정보를 담으면 안 된다 — 덧입힘 장식으로만 쓴다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 브라우저가 자동완성으로 채운 `input` 에 `:autofill` 이 걸린다 | 선택자의 정의(원본 설명) |
| Chrome 등은 자동완성 때 기본 배경색을 강제 적용한다 | 브라우저 구현 — 원본 팁의 서술, 브라우저마다 다를 수 있다 |
| 강제 배경색이 작성자의 `background … !important` 를 이긴다 | 브라우저 구현 — 보장 없음 (확인 필요) |
| `inset` 그림자는 배경 위에 그려진다 | CSS 의 그리기 규칙 |
| 어떤 칸에 어떤 저장값을 제안하나, 언제 제안하나 | 브라우저 구현 — `autocomplete` 는 힌트일 뿐이다 |
| `.af-input:autofill` 이 `.af-input` 보다 명시도가 높다 | CSS 의 명시도 규칙 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 자동완성된 칸을 사용자에게 표시 | `input:autofill { border-color: … }` | 값만 보고 칠하는 다른 방법 |
| 브라우저 기본 노랑·파랑 배경을 없애기 | `box-shadow: inset 0 0 0 1000px 원하는색` | `background` 한 줄에만 기대기 |
| 값이 들어간 칸 전부를 칠하기 | 값 유무를 보는 다른 방법 | `:autofill` |
| 반드시 보여야 하는 안내 | 평소 규칙 · 별도 문구 | `:autofill` 규칙 안에만 넣기 |
| 상태 변화를 부드럽게 | 평소 규칙에 `transition` | 자동완성 규칙에만 `transition` |

## 핵심 문장

1. **`:autofill` 은 「브라우저가 채웠다」는 상태를 고르는 의사 클래스다** — 사용자가 친 값에는 걸리지 않는다.
2. **평소 모양은 일반 규칙, 달라질 부분만 `:autofill` 규칙에** 적으면 명시도 덕분에 덮어쓰기가 깔끔하다.
3. **브라우저는 자동완성 배경을 강제할 수 있다** — 배경을 바꾸려면 `inset` 그림자로 위를 덮는다.
4. **바깥 그림자는 테두리 강조, 안쪽 큰 그림자는 배경 덮기** — 같은 `box-shadow` 라도 용도가 다르다.
5. **자동완성이 없으면 규칙도 없다** — 장식으로만 쓴다.

## 관련 자료

- `:focus` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `::placeholder` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- 원본: study-site 항목 데이터 `data/css/selectors.json` 의 `autofill`

## 용어 풀이

- **자동완성(autofill)** — 브라우저가 저장해 둔 값을 폼 칸에 대신 채워 넣는 기능.
- **의사 클래스** — HTML 에 적히지 않은 요소의 상태를 보고 고르는 `:` 로 시작하는 선택자.
- **`:autofill`** — 자동완성으로 값이 채워진 `input` 을 고르는 의사 클래스.
- **`autocomplete` 속성** — 칸에 들어갈 값의 종류를 브라우저에 알려 주는 HTML 속성.
- **`box-shadow`** — 요소 둘레(또는 `inset` 이면 안쪽)에 그림자를 그리는 속성.
- **`inset`** — `box-shadow` 를 테두리 안쪽, 배경 위에 그리게 하는 낱말.
- **퍼짐(spread)** — `box-shadow` 의 네 번째 길이 값, 그림자를 사방으로 키우는 양.
- **명시도** — 겹친 규칙 중 이길 쪽을 정하는 선택자의 점수.
- **`!important`** — 선언 하나의 우선순위를 끌어올리는 표시.
- **`transition`** — 속성 값이 바뀔 때 정해진 시간에 걸쳐 바뀌게 하는 속성.

## 더 들어가면

- 오래된 WebKit · Blink 계열에서는 접두사가 붙은 `:-webkit-autofill` 로 같은 상태를 골랐고, 지금도 호환을 위해 둘을 함께 적는 코드가 많다 (확인 필요).
- 브라우저의 기본 스타일 시트가 자동완성 배경을 `!important` 로 선언하면, 캐스케이드 규칙상 브라우저의 `!important` 가 작성자의 `!important` 보다 앞선다 — 원본 예제의 노란 배경이 안 보일 수 있는 까닭으로 짐작된다 (확인 필요).
- 배경을 덮은 뒤 글자색까지 바뀌는 경우 `-webkit-text-fill-color` 로 글자색을 정하는 방법이 쓰인다 (확인 필요).
- 배경 전환에 아주 긴 `transition` 지연을 줘서 기본 배경색이 사실상 나타나지 않게 하는 우회로도 알려져 있다 (확인 필요).
- 자동완성된 값을 사용자가 고쳐 쓰면 `:autofill` 상태가 풀리는 것이 일반적인 동작이다 (확인 필요).
- `input` 말고 `select` · `textarea` 에도 같은 상태가 붙는지는 브라우저마다 다를 수 있다 (확인 필요).
