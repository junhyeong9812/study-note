## 한눈에 — 쉽게 말하면

**자손 결합자는 「우리 집안 사람이면 몇 대손이든 다 부른다」는 호출이다.**
「김씨 집안의 아이들 모두 나와라」라고 하면 아들도, 손자도, 증손자도 나온다.
족보에서 몇 칸 아래에 있는지는 묻지 않고, 그 집안 아래에 있기만 하면 된다.
`.parent-d p` 도 똑같은 구조다.
`.parent-d` 라는 집안 아래에 있는 `p` 는 몇 겹 안쪽에 있든 모두 고른다.

| 비유 | 실체 |
|---|---|
| 집안(조상) | 앞쪽 선택자 `A` 에 맞는 요소 (`.parent-d`) |
| 불려 나오는 사람 | 뒤쪽 선택자 `B` 에 맞는 요소 (`p`) |
| 「몇 대손이든」 | 모든 깊이 — 자식, 손자, 그 아래까지 |
| 「아들만 나와라」 | 자식 결합자 `>` |

```text
.parent-d            ← 집안 (A)
├── p                ← 자식 : 고른다
└── div
    └── p            ← 손자 : 고른다
```

## 이 주제가 답하려는 질문

1. `A B` 에서 「B 가 A 안에 있다」는 말은 몇 겹 안쪽까지를 뜻하나?
2. 선택자 사이의 공백 한 칸은 무슨 일을 하나 — 지우거나 옮기면 무엇이 바뀌나?
3. 직접 자식만 고르고 싶을 때는 무엇을 쓰나?

## 동작 방식

### (1) 공백 하나가 「조상–자손」 관계를 뜻한다

**언제 쓰나** — 어떤 영역 안에 들어 있는 특정 요소만 꾸미고 싶을 때 쓴다.
영역 바깥의 같은 요소는 건드리지 않는다.

```text
입력 코드            .parent-d p { color: #2563eb; }

무엇이 일어나나       문서의 모든 p 를 하나씩 본다
                     → 그 p 의 위쪽(부모, 부모의 부모 …)에
                       .parent-d 가 하나라도 있나?
                     → 있으면 매칭, 없으면 건너뜀

결과                 .parent-d 안쪽의 p 만 파란 글자
```

- 규칙이 실제로 꾸미는 대상은 맨 오른쪽의 `p` 다.
- 왼쪽의 `.parent-d` 는 꾸밈 대상이 아니라 「이 안에 있어야 한다」는 조건이다.
- 조건을 따질 때 부모만 보지 않고 문서 맨 위까지 조상을 거슬러 올라가며 본다.
- 조상 가운데 하나라도 `.parent-d` 면 조건이 채워진다.

> **결합자** — 두 선택자 사이에 놓여 두 요소의 관계(조상·부모·형제)를 정하는 기호다.\
> 예: 공백(자손), `>`(자식), `+`(바로 다음 형제), `~`(뒤쪽 형제).

> **자손** — 어떤 요소 안에 들어 있는 요소 전부(자식, 손자, 그 아래까지)다.\
> 예: `div` 안의 `ul` 안의 `li` 는 `div` 의 자손이다.

### (2) 깊이는 따지지 않는다 — 자식도 손자도 고른다

**언제 쓰나** — 중간에 감싸는 요소가 끼어 있어도 상관없이 영역 안의 요소를 모두 잡고 싶을 때 쓴다.

```text
입력 HTML
<div class="parent-d">
  <p>직접 자식 p</p>        깊이 1
  <div>
    <p>손자 p</p>           깊이 2
  </div>
</div>

.parent-d p 로 매칭
  직접 자식 p   → 위로 1칸에 .parent-d   → 매칭
  손자 p        → 위로 2칸에 .parent-d   → 매칭
  중간 div      → p 가 아님              → 대상 아님
```

- 직접 자식 `p` 는 부모가 곧 `.parent-d` 라서 매칭된다.
- 손자 `p` 는 부모가 그냥 `div` 지만, 한 칸 더 올라가면 `.parent-d` 가 있어 매칭된다.
- 중간 `div` 는 `p` 가 아니라서 이 규칙의 대상이 되지 않는다.
- 감싸는 층이 세 겹, 열 겹이어도 위쪽 어딘가에 `.parent-d` 만 있으면 같은 결과다.

```html demo
<div class="parent-d">
  <p>직접 자식 p</p>
  <div><p>손자 p</p></div>
</div>
<style>
  .parent-d { padding: 16px; background: #f3f4f6; border-radius: 8px; }
  .parent-d p { color: #2563eb; font-weight: bold; padding: 8px; margin: 4px 0; background: #dbeafe; border-radius: 4px; }
</style>
```

> **보이는 것** — 회색 상자 안에 두 `p` 가 모두 연한 파란 배경 위 굵은 파란 글자로 보인다 (코드에서 읽은 것 — 렌더 실측 아님).

> **직접 자식** — 다른 요소를 사이에 두지 않고 바로 한 칸 아래에 있는 요소다.\
> 예: 위 HTML 에서 첫 번째 `p` 와 중간 `div` 가 `.parent-d` 의 직접 자식이다.

### (3) 직접 자식만 원하면 `>` 로 바꾼다

**언제 쓰나** — 바로 한 칸 아래만 꾸미고, 더 깊이 묻힌 같은 요소는 그대로 두고 싶을 때 쓴다.

```text
입력 코드            .parent-d > p { … }

무엇이 일어나나       p 의 부모 한 칸만 본다
                     → 부모가 .parent-d 인가?

결과                 직접 자식 p   → 매칭
                     손자 p        → 부모가 div 라서 매칭 안 됨
```

- 공백은 「조상 어딘가」를 보고, `>` 는 「바로 위 부모 하나」만 본다.
- 그래서 `>` 로 고르는 요소는 언제나 공백으로 고르는 요소의 일부다.

> **자식 결합자** — `A > B` 꼴로, `A` 의 직접 자식인 `B` 만 고르는 결합자다.\
> 예: `ul > li` 는 안쪽 목록의 `li` 는 고르지 않는다.

## 문법 — 형태와 규칙

```css
/* 기본 꼴: A 안(모든 깊이)에 있는 B */
.parent-d p { color: #2563eb; }

/* 셋 이상 이어 쓰기: nav 안의 ul 안의 a */
nav ul a { text-decoration: none; }

/* 공백과 > 섞기: .card 안 어딘가의 ul, 그 직접 자식 li */
.card ul > li { margin: 4px 0; }

/* 공백이 없으면 결합자가 아니다: 두 클래스를 함께 가진 한 요소 */
.parent-d.highlight { outline: 1px solid; }
```

- 꼴은 `A B { }` 이고, `A` 와 `B` 사이의 공백이 결합자다.
- 공백 대신 줄바꿈이나 여러 칸을 써도 자손 결합자 하나로 읽힌다.
- 꾸밈 대상은 맨 오른쪽 선택자다.
- `A B C` 는 「`A` 안의 `B` 안의 `C`」다 — 조건이 하나씩 늘어난다.
- `A` 와 `B` 자리에는 태그·클래스·id·속성 선택자 무엇이든 올 수 있다.
- 공백을 지우면(`A.B`) 「한 요소가 두 조건을 다 가짐」이라는 전혀 다른 뜻이 된다.
- 순서를 바꾸면(`B A`) 조상과 자손이 뒤바뀐다.

| 쓴 것 | 뜻 |
|---|---|
| `.parent-d p` | `.parent-d` 안(모든 깊이)의 `p` |
| `.parent-d > p` | `.parent-d` 의 직접 자식 `p` |
| `p.parent-d` | 클래스 `parent-d` 를 가진 `p` 자신 |
| `p .parent-d` | `p` 안에 있는 `.parent-d` |

## 어디서 틀리나

### 1. 「안쪽 바로 아래만」이라고 생각한다

자손 결합자는 모든 깊이의 자손을 고른다.
중간 `div` 가 끼어 있어도 손자 `p` 까지 꾸며진다.
직접 자식만 고르려면 `>`(자식 결합자)를 쓴다.

### 2. 공백 한 칸을 사소하게 본다

`.parent-d p` 와 `.parent-d.p` 는 한 칸 차이지만 뜻이 완전히 다르다.
앞은 「두 요소의 관계」, 뒤는 「한 요소의 두 조건」이다.

### 3. 왼쪽 선택자가 꾸며진다고 생각한다

`.parent-d p` 의 선언은 `p` 에 붙는다.
`.parent-d` 상자 자신의 배경·여백은 따로 `.parent-d { }` 규칙으로 줘야 한다.

### 4. 상속과 선택자 매칭을 헷갈린다

`color` 처럼 자식에게 물려 내려가는 속성은 `.parent-d { color: … }` 만 써도 안쪽 `p` 글자색이 바뀐다.
하지만 `padding` · `background` 처럼 물려 내려가지 않는 속성은 `p` 를 직접 골라야 `p` 에 붙는다.
`p` 마다 배경과 여백을 주려면 `.parent-d p` 처럼 `p` 를 고르는 선택자가 필요하다.

> **상속** — 부모에게 준 값이 따로 지정하지 않은 자손에게 그대로 내려가는 성질이다.\
> 예: `color` 는 상속되고 `padding` 은 상속되지 않는다.

### 5. 너무 넓게 잡아 원하지 않는 곳까지 꾸민다

`.card p` 는 카드 안에 나중에 끼워 넣은 다른 부품 속 `p` 까지 고른다.
꾸밀 범위가 「한 칸 아래」로 정해져 있다면 `>` 가 더 안전하다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 공백 결합자는 모든 깊이의 자손에 매칭한다 | CSS 선택자 명세 |
| `>` 는 직접 자식에만 매칭한다 | CSS 선택자 명세 |
| 공백 대신 줄바꿈·여러 칸도 자손 결합자다 | CSS 선택자 명세 (확인 필요) |
| 깊이가 달라도 매칭 결과는 같다 | CSS 선택자 명세 — 결과만 보장, 걸리는 시간은 보장 안 함 |
| 브라우저가 맨 오른쪽 선택자부터 거슬러 올라가며 맞춰 본다 | 브라우저 엔진의 구현 방식 — 명세가 정한 것 아님 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 어떤 영역 안의 같은 요소를 깊이 상관없이 모두 꾸민다 | `A B` | `A > B` (손자를 놓친다) |
| 바로 한 칸 아래 요소만 꾸민다 | `A > B` | `A B` (안쪽 깊이까지 번진다) |
| 한 요소가 두 클래스를 함께 가졌는지 본다 | `.a.b` | `.a .b` (관계로 읽힌다) |
| 상속되는 속성을 영역 전체에 준다 | `A { color: … }` 로 충분할 때가 많다 | 자손마다 일일이 고르기 |
| 상속되지 않는 속성(배경·여백)을 안쪽 요소에 준다 | `A B` | `A { … }` (`A` 에만 붙는다) |

## 핵심 문장

1. **선택자 사이 공백 한 칸이 자손 결합자다** — `A B` 는 「`A` 안에 있는 `B`」다.
2. **깊이는 묻지 않는다** — 자식·손자·그 아래 모두 고른다.
3. **꾸밈 대상은 맨 오른쪽 선택자다** — 왼쪽은 「안에 있어야 한다」는 조건이다.
4. **직접 자식만 원하면 `>`** — 공백은 조상 어딘가, `>` 는 바로 위 부모만 본다.
5. **공백을 지우거나 옮기면 뜻이 바뀐다** — `A.B` 는 한 요소, `B A` 는 관계 뒤집기다.

- `~ 일반 형제 결합자` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)

## 용어 풀이

- **결합자** — 두 선택자 사이에서 요소 관계를 정하는 기호(공백, `>`, `+`, `~`).
- **자손 결합자** — 공백. `A` 의 모든 깊이 자손인 `B` 를 고른다.
- **자식 결합자** — `>`. `A` 의 직접 자식인 `B` 만 고른다.
- **자손** — 어떤 요소 안에 들어 있는 요소 전부.
- **직접 자식** — 사이에 다른 요소 없이 바로 한 칸 아래의 요소.
- **조상** — 어떤 요소를 감싸는 위쪽 요소 전부(부모, 부모의 부모 …).
- **상속** — 부모의 값이 지정 없는 자손에게 내려가는 성질.
- **매칭** — 선택자 조건에 요소가 들어맞아 규칙이 그 요소에 붙는 것.

## 더 들어가면

- 결합자 자체는 명시도(선택자 우선순위 점수)를 올리지 않는다고 알려져 있다 — `.parent-d p` 의 명시도는 클래스 하나와 태그 하나를 더한 값이다 (확인 필요).
- 브라우저는 선택자를 오른쪽부터 맞춰 보는 방식을 쓰기 때문에, 맨 오른쪽이 `*` 나 흔한 태그인 긴 자손 선택자는 비용이 클 수 있다는 이야기가 있다 — 실제 차이는 엔진과 문서 크기에 달려 있다 (확인 필요).
- 명세에서는 공백 결합자를 `>>` 로도 적을 수 있게 하자는 논의가 있었으나 브라우저 지원은 불분명하다 (확인 필요).
- `:has()` 는 반대 방향, 곧 「어떤 자손을 가진 조상」을 고르는 선택자다 (확인 필요).
