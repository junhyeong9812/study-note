## 한눈에 — 쉽게 말하면

**`:local-link` 는 「지도에 찍힌 '현재 위치' 핀」이다.**
쇼핑몰 안내도에서 여러 매장 표시 중 지금 내가 서 있는 자리만 빨간 핀으로 따로 보인다.
안내도를 그린 사람이 층마다 핀을 손으로 옮겨 그리지 않아도 된다.
`:local-link` 도 똑같은 구조다.
여러 링크 가운데 **지금 보고 있는 문서의 URL 을 가리키는 링크**만 골라 낸다.

| 비유 | 실체 |
|---|---|
| 안내도 | `<nav>` 안의 링크 묶음 |
| 매장 표시 하나 | `<a href="…">` 하나 |
| 내가 서 있는 자리 | 현재 문서의 URL |
| 현재 위치 핀 | `:local-link` 에 매칭되어 강조된 링크 |

```text
현재 문서 URL = page.html
  ┌─────────── nav ───────────┐
  │ [#section1]  [example.com] │
  │   ▲ 같은 문서     ▲ 다른 문서 │
  │   :local-link    매칭 안 됨  │
  └───────────────────────────┘
```

## 이 주제가 답하려는 질문

1. 어떤 링크가 `:local-link` 에 매칭되고, 어떤 링크는 빠지나?
2. 네비게이션에서 「현재 페이지」 링크를 강조할 때 이 선택자가 무엇을 덜어 주나?
3. 브라우저가 이 선택자를 모르면 규칙은 어떻게 되나?

## 동작 방식

### (1) 링크의 목적지와 현재 문서 URL 을 비교한다

**언제 쓰나** — 같은 페이지 안을 가리키는 링크(앵커 링크 등)만 다르게 보이게 하고 싶을 때 쓴다.

```text
입력:  <a href="#section1">          <a href="https://example.com">
         │                              │
         ▼ 목적지를 절대 URL 로 풀기     ▼
       page.html#section1             https://example.com/
         │                              │
         ▼ 현재 문서 URL(page.html)과 비교
       같은 문서 → 매칭                 다른 문서 → 매칭 안 됨
결과:  .ll-link:local-link 규칙 적용    기본 .ll-link 모양 그대로
```

- `href` 값은 먼저 현재 문서를 기준으로 절대 URL 로 풀린다.
- `#section1` 처럼 `#` 으로 시작하는 값은 「이 문서의 한 지점」이라 문서 부분이 현재 URL 과 같다.
- `https://example.com` 은 다른 문서라 비교에서 떨어진다.
- 원본은 이 결과로 「섹션 1」은 매칭, 「외부 링크」는 매칭 안 됨이라고 적는다.

> **앵커 링크** — 같은 문서 안의 한 위치(`id`)로 가는 링크다.\
> 예: `<a href="#section1">` 은 `id="section1"` 인 요소로 간다.

> **프래그먼트** — URL 에서 `#` 뒤의 부분으로, 문서 안의 위치를 가리킨다.\
> 예: `page.html#section1` 의 프래그먼트는 `section1` 이다.

### (2) 매칭은 「링크」에만 걸린다

**언제 쓰나** — 무엇에 스타일이 붙는지 헷갈릴 때 떠올린다.

```text
<a href="#section1">섹션 1</a>   ← 링크(href 있음) → 후보
<a>이름만 있는 앵커</a>           ← href 없음 → 링크가 아님 → 후보 아님
<section id="section1">…</section> ← 목적지 요소 → :local-link 대상 아님
```

- `:local-link` 는 하이퍼링크의 **출발점**(`<a href>` 같은 요소)에 붙는다.
- `href` 가 없는 `<a>` 는 링크가 아니므로 대상이 아니다.
- 링크가 가리키는 **목적지 요소**를 꾸미는 것은 `:target` 쪽 일이다.

> **의사 클래스** — 요소의 상태나 위치처럼 HTML 에 직접 적히지 않은 조건으로 요소를 고르는 선택자다.\
> 예: `:hover` · `:local-link`.

### (3) 클래스 선택자와 겹쳐 범위를 좁힌다

**언제 쓰나** — 페이지의 모든 링크가 아니라 네비게이션 링크만 강조하고 싶을 때 쓴다.

```text
.ll-link              → 네비게이션 링크 전부: 회색 버튼
.ll-link:local-link   → 그중 현재 문서를 가리키는 것: 녹색·흰 글자·굵게
```

- `.ll-link:local-link` 는 「`ll-link` 클래스를 가졌고, **동시에** 현재 문서를 가리키는 링크」다.
- 두 조건이 붙어 있으므로 `.ll-link` 하나보다 구체적이라 겹치는 속성(`background` · `color`)을 덮어쓴다.
- 그래서 페이지마다 「현재」 클래스를 손으로 옮겨 달지 않아도 된다 — 원본 팁의 「네비게이션 하이라이트」가 이 자리다.

### (4) 모르는 선택자는 규칙 전체를 버린다

**언제 쓰나** — 원본 팁의 「브라우저 지원이 제한적이다」를 실제 화면으로 옮겨 생각할 때 쓴다.

```text
브라우저가 :local-link 를 안다     → 규칙 적용 → 섹션 1 녹색
브라우저가 :local-link 를 모른다   → 선택자 무효 → 규칙 통째로 무시 → 두 링크 모두 회색
a:hover, a:local-link { … }       → 목록 중 하나라도 무효면 이 규칙 전체가 무시된다
```

- CSS 는 이해하지 못하는 선택자가 들어간 규칙을 오류로 보고 건너뛴다.
- 쉼표로 묶은 선택자 목록도 하나가 무효면 규칙 전체가 사라진다 — `a:hover` 까지 함께 죽는다.
- 그래서 지원이 불확실한 선택자는 **따로 떼어 쓴다**.

## 문법 — 형태와 규칙

```html demo
<nav class="nav">
  <a href="#top" class="link">처음으로</a>
  <a href="https://example.com" class="link">바깥</a>
</nav>
<style>
  .nav { display: flex; gap: 8px; }
  .link { padding: 6px 12px; background: #eee; color: #333; text-decoration: none; }
  .link:local-link { background: #16a34a; color: white; }
</style>
```

> **보이는 것** — 지원하는 브라우저라면 「처음으로」만 녹색, 「바깥」은 회색이고, 지원하지 않으면 둘 다 회색이다 (코드에서 읽은 것 — 렌더 실측 아님)

- 형태: `selector:local-link { }` — 앞의 선택자(`a` · `.ll-link` 등)에 붙여 쓴다.
- 혼자 쓴 `:local-link { }` 는 `*:local-link` 와 같아 문서의 모든 해당 링크에 걸린다.
- 대상은 `href` 를 가진 링크뿐이다.
- 지원이 불확실하므로 다른 선택자와 쉼표로 묶지 않는다.

## 어디서 틀리나

### 1. 브라우저 지원이 제한적이다

원본 팁 그대로, `:local-link` 는 아직 브라우저 지원이 제한적이다.
지원 범위가 어디까지인지는 (확인 필요) 다.
지원하지 않는 브라우저에서는 「동작 방식 (4)」처럼 규칙이 통째로 무시되어 강조가 아예 보이지 않는다.
현재 페이지 강조를 꼭 보여야 한다면 클래스나 속성을 직접 다는 방법을 함께 둔다.

### 2. 쉼표로 묶으면 멀쩡한 선택자까지 죽는다

`.ll-link:hover, .ll-link:local-link { … }` 처럼 쓰면 `:local-link` 를 모르는 브라우저는 `:hover` 효과까지 버린다.
규칙을 둘로 나누어 쓴다.

### 3. 프래그먼트가 다를 때의 매칭 — 원본 주장이 단순하다

- **원본의 주장** — `#section1` 같은 같은 페이지 앵커 링크는 `:local-link` 에 매칭된다.
- **왜 의심스러운가** — Selectors Level 4 초안은 링크 목적지에 프래그먼트가 있으면 현재 URL 의 프래그먼트까지 같아야 한다고 적는 것으로 보인다 (확인 필요).
  그 읽기대로라면 주소창이 `page.html` 일 때 `#section1` 링크는 매칭되지 않고, `page.html#section1` 일 때만 매칭된다.
  어느 쪽이든 지원 브라우저에서 직접 확인해야 한다.

### 4. 목적지 요소를 꾸미려는 실수

`:local-link` 는 링크 자신에 붙는다.
`#section1` 으로 스크롤된 **섹션**을 강조하고 싶다면 `:target` 을 써야 한다.

### 5. 외부 링크라고 영원히 빠지는 것은 아니다

매칭 기준은 「외부냐」가 아니라 「현재 문서 URL 과 같으냐」다.
같은 `<nav>` 를 `https://example.com` 문서에 넣으면 그 링크가 현재 위치가 된다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `:local-link` 는 현재 문서 URL 을 가리키는 링크에 매칭된다 | CSS Selectors Level 4 초안의 정의 (아직 표준 초안 — 확인 필요) |
| 지원 브라우저가 제한적이다 | 브라우저 구현 현황 — 원본 팁의 주장, 범위는 확인 필요 |
| 프래그먼트까지 비교하는지 | 초안의 서술과 구현에 달림 — 확인 필요 |
| 모르는 선택자가 든 규칙은 통째로 무시된다 | CSS 문법 규칙 (언어 보장) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 같은 문서를 가리키는 링크를 강조(실험·학습) | `a:local-link` | 손으로 단 클래스만 믿고 URL 이 바뀔 때마다 고치기 |
| 모든 브라우저에서 현재 페이지 표시가 꼭 보여야 함 | 서버·스크립트가 다는 `.current` 클래스나 `aria-current="page"` 속성 선택자 | `:local-link` 만 단독으로 |
| 앵커로 이동한 목적지 섹션 강조 | `:target` | `:local-link` |
| 호버 효과와 함께 쓰기 | 규칙 두 개로 나누기 | `a:hover, a:local-link { }` 묶기 |

## 핵심 문장

1. **`:local-link` 는 링크의 목적지 URL 이 현재 문서 URL 과 같을 때 그 링크에 걸린다.**
2. **대상은 링크(출발점)이지 목적지 요소가 아니다** — 목적지는 `:target` 의 몫이다.
3. **네비게이션의 「현재 페이지」를 클래스 없이 고를 수 있다** — 그것이 쓰임새다.
4. **지원이 제한적이라 모르는 브라우저는 규칙 전체를 버린다** — 쉼표로 묶지 말고 대안을 함께 둔다.

## 관련 자료

- `:any-link` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `:target` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)

## 용어 풀이

- **의사 클래스** — HTML 에 적히지 않은 상태·조건으로 요소를 고르는 선택자(`:hover` 등).
- **앵커 링크** — 같은 문서 안의 `id` 위치로 가는 링크(`href="#…"`).
- **프래그먼트** — URL 의 `#` 뒤 부분, 문서 안 위치.
- **절대 URL** — 스킴부터 경로까지 다 적힌 완전한 주소(`https://example.com/`).
- **문서 URL** — 지금 브라우저에 열린 문서의 주소.
- **선택자 목록** — 쉼표로 묶은 여러 선택자(`a, b`).
- **`:target`** — 현재 URL 프래그먼트와 같은 `id` 를 가진 요소를 고르는 의사 클래스.

## 더 들어가면

- 예전 초안에는 `:local-link(1)` 처럼 경로 단계 수를 받아 「사이트 안 같은 구역」을 고르는 함수형이 있었다가 빠진 것으로 알려져 있다 (확인 필요).
- `:is()` · `:where()` 안의 선택자 목록은 「관대한 목록」이라 모르는 선택자 하나가 전체를 죽이지 않는다고 알려져 있다 — 다만 `:local-link` 를 지원하지 않으면 그 갈래가 매칭되지 않을 뿐이다 (확인 필요).
- `@supports selector(:local-link)` 로 지원 여부를 분기할 수 있다 (확인 필요).
- `:any-link` 는 방문 여부와 상관없이 모든 링크를 고르고, `:local-link` 는 그 부분집합으로 볼 수 있다 (확인 필요).
