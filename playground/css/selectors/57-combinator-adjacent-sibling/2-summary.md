## 한눈에 — 쉽게 말하면

**`A + B` 는 「줄 서 있는 사람 중 A 바로 뒤에 선 사람」을 부르는 말이다.**
A 뒤에 서 있어도 사이에 누가 한 명 끼어 있으면 부르지 않는다.
A 앞에 선 사람도 부르지 않는다.
CSS 의 인접 형제 결합자도 똑같은 구조다.
같은 부모 아래 나란히 놓인 요소들이 줄이고, `+` 는 A 바로 다음 칸에 B 가 있을 때 그 B 하나를 고른다.

> **결합자(combinator)** — 두 선택자 사이에 놓여 두 요소의 관계(자손 · 자식 · 형제)를 조건으로 거는 기호다.\
> 예: `h3 + p` 의 `+`, `div > p` 의 `>`.

> **형제(sibling)** — 같은 부모 요소를 둔 요소끼리의 관계다.\
> 예: 한 `div` 안에 나란히 있는 `h3` 와 `p` 는 형제다.

| 비유 | 실체 |
|---|---|
| 한 줄로 선 사람들 | 같은 부모 안에 문서 순서대로 놓인 형제 요소들 |
| A 라는 사람 | `+` 왼쪽 선택자에 맞는 요소 |
| A 바로 뒤 사람 | `+` 오른쪽 선택자에 맞는, 바로 다음 형제 요소 |
| 사이에 끼어든 사람 | A 와 B 사이에 놓인 다른 요소 — 있으면 매칭이 깨진다 |
| 부름을 받는 사람 | 스타일을 받는 요소 = B |

```text
부모 div
 ├─ h3        (A)
 ├─ p   ◀──── h3 + p 가 고르는 요소 (A 바로 다음)
 └─ p         (바로 다음이 아니다 → 안 고른다)
```

## 이 주제가 답하려는 질문

1. `A + B` 는 어떤 요소를 고르고, 스타일은 A 와 B 중 누가 받나?
2. 「바로 다음」이 깨지는 경우는 무엇인가 — 사이에 다른 요소가 있을 때, 순서가 거꾸로일 때, 부모가 다를 때?
3. 폼의 `label + input` 이나 「제목 뒤 첫 단락」처럼 실제로 어디에 쓰나?

## 동작 방식

### (1) 바로 다음 형제 하나만 고른다

**언제 쓰나** — 어떤 요소 바로 뒤에 오는 요소 하나에만 다른 모양을 주고 싶을 때 쓴다.
제목 바로 아래 첫 단락을 강조하는 것이 대표적이다.

```text
입력 코드                        무엇이 일어나나                   결과
.adj-demo h3 + p { … }   →   각 p 마다 "바로 앞 형제가     →   첫 p: 바로 앞 = h3 → 매칭
                             h3 인가?"를 본다                  둘째 p: 바로 앞 = p  → 매칭 안 됨

<div class="adj-demo">
  <h3>제목</h3>
  <p>제목 바로 다음 단락</p>     ← 스타일 적용
  <p>두 번째 단락</p>            ← 적용 안 됨
</div>
```

- 브라우저는 오른쪽 선택자 `p` 에 맞는 요소를 후보로 잡는다.
- 각 후보마다 바로 앞 형제 요소가 `h3` 인지 확인한다.
- 첫 단락은 바로 앞이 `h3` 라 조건을 채운다.
- 두 번째 단락은 바로 앞이 `p` 라 조건을 채우지 못한다.
- 결국 스타일을 받는 것은 `+` 오른쪽의 요소(B)이고, 왼쪽 `h3`(A)는 조건으로만 쓰인다.

### (2) 사이에 다른 요소가 끼면 깨진다

**언제 쓰나** — 마크업이 바뀌었는데 스타일이 갑자기 사라졌을 때, 이 규칙을 먼저 떠올린다.

```text
입력 마크업                     무엇이 일어나나                       결과
<h3>제목</h3>                   p 의 바로 앞 형제 = div          →   h3 + p 매칭 안 됨
<div>끼어든 상자</div>          (h3 가 아니다)
<p>단락</p>
```

- `p` 의 바로 앞 형제 요소는 `div` 다.
- `h3` 는 그보다 한 칸 더 앞이라 「바로 다음」 조건이 깨진다.
- 원본 팁이 말하는 「두 요소 사이에 다른 요소가 있으면 매칭되지 않는다」가 이 경우다.
- 「요소」만 칸으로 센다 — 태그 사이의 줄바꿈 · 공백 글자나 HTML 주석은 요소가 아니라 칸을 차지하지 않는다.

### (3) 방향은 앞에서 뒤로만, 부모는 같아야 한다

**언제 쓰나** — 「A 앞에 있는 B」나 「A 안쪽에 있는 B」를 고르려다 안 될 때 이유를 따진다.

```text
경우 ①  순서가 거꾸로                경우 ②  부모가 다르다
<p>앞 단락</p>   ← 매칭 안 됨       <h3>제목</h3>
<h3>제목</h3>                       <div>
<p>뒤 단락</p>   ← 매칭             <p>안쪽 단락</p>   ← 매칭 안 됨
                                    </div>
```

- 경우 ① 에서 앞 단락은 `h3` 보다 먼저 나오므로 「`h3` 바로 다음」이 아니다.
- `+` 는 문서 순서에서 뒤쪽 요소만 고른다 — 「바로 앞 형제」를 고르는 뜻이 없다.
- 경우 ② 에서 `p` 의 부모는 `div` 이고 `h3` 의 부모는 바깥 요소라 둘은 형제가 아니다.
- `h3` 바로 다음 형제는 `div` 이므로 `h3 + div` 라면 맞는다.

### (4) 긴 선택자에서 `+` 가 묶는 범위

**언제 쓰나** — `.adj-demo h3 + p` 처럼 다른 결합자와 섞일 때 읽는 법이다.

```text
.adj-demo h3 + p
└───┬───┘ └┬┘   └ p : 실제로 스타일을 받는 요소
    │      └ h3 : .adj-demo 의 자손인 h3
    └ 공백(자손 결합자)

뜻: ".adj-demo 안의 h3" 바로 다음 형제인 p
```

- 선택자는 결합자마다 한 단계씩 관계를 건다.
- `p` 는 그 `h3` 의 형제이므로 저절로 같은 부모 아래, 즉 `.adj-demo` 안에 있게 된다.
- 예제에서 `.adj-demo p` 규칙은 두 단락 모두에 여백 · 안쪽 여백 · 둥근 모서리를 주고, `.adj-demo h3 + p` 규칙은 첫 단락에만 배경 · 굵기 · 글자색을 더한다.
- 두 규칙이 겹치는 속성이 없으므로 첫 단락은 두 규칙의 선언을 모두 받는다.

## 문법 — 형태와 규칙

```html demo
<div class="note">
  <h3>공지</h3>
  <p>첫 단락 — 강조된다</p>
  <p>두 번째 단락 — 평범하다</p>
  <label>이름</label>
  <input placeholder="label 바로 다음 input">
</div>
<style>
  .note h3 + p { font-weight: bold; background: #fef3c7; }
  .note label + input { margin-left: 8px; }
</style>
```

> **보이는 것** — 「첫 단락」만 굵고 노란 배경이며, 입력 칸이 라벨 오른쪽으로 조금 떨어져 놓인다. (코드에서 읽은 것 — 렌더 실측 아님)

| 형태 | 고르는 것 |
|---|---|
| `A + B` | A 의 바로 다음 형제이면서 B 에 맞는 요소 |
| `h3 + p` | `h3` 바로 뒤의 `p` (제목 뒤 첫 단락) |
| `label + input` | `label` 바로 뒤의 `input` |
| `A + B + C` | A 바로 다음 B, 그 B 바로 다음 C — 스타일은 C 가 받는다 |

- 스타일을 받는 것은 맨 오른쪽 선택자에 맞는 요소다.
- A 와 B 는 같은 부모를 둔 형제여야 한다.
- B 는 A 보다 문서 순서에서 뒤, 그것도 바로 다음 요소여야 한다.
- A 하나에 대해 고를 수 있는 B 는 많아야 하나다.
- `+` 양옆 공백은 있어도 없어도 같다 — `h3+p` 와 `h3 + p` 는 같은 선택자다.

## 어디서 틀리나

### 1. 「A 뒤의 B 전부」로 착각한다

`h3 + p` 는 `h3` 뒤의 단락 전부가 아니라 바로 다음 단락 하나만 고른다.
예제에서 두 번째 단락이 강조되지 않는 까닭이 이것이다.

### 2. 사이에 다른 요소가 끼어 매칭이 사라진다

원본 팁 그대로 — 두 요소 사이에 다른 요소가 있으면 매칭되지 않는다.
제목과 단락 사이에 이미지 · 구분선 · 감싸는 `div` 를 넣는 순간 스타일이 빠진다.
반대로 줄바꿈 공백이나 주석은 요소가 아니라 깨뜨리지 않는다.

### 3. A 가 스타일을 받는다고 생각한다

`label + input` 에서 꾸며지는 쪽은 `input` 이다.
`label` 은 「바로 앞에 label 이 있어야 한다」는 조건일 뿐이다.

### 4. 앞쪽 형제를 고르려 한다

`+` 는 뒤쪽으로만 본다.
「`p` 바로 앞의 `h3`」를 `p + h3` 로 쓰면 「`p` 바로 다음의 `h3`」라는 전혀 다른 뜻이 된다.

### 5. 폼에서 `label + input` 은 마크업 순서에 기댄다

원본 팁처럼 폼에서 라벨 바로 뒤 입력 칸을 고를 때 유용하다.
하지만 `input` 을 `label` 안에 넣는 마크업이라면 둘은 형제가 아니라 부모-자식이라 매칭되지 않는다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `A + B` 는 A 의 바로 다음 형제 요소인 B 만 고른다 | CSS 선택자 명세 |
| 텍스트(공백)와 주석은 형제 「요소」로 세지 않는다 | CSS 선택자 명세 — 결합자는 요소 사이 관계만 본다 |
| 예제의 노란 배경 · 굵은 글씨가 첫 단락에만 보인다 | 브라우저 렌더링 — 코드에서 읽은 것이며 렌더 실측 아님 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 제목 바로 뒤 첫 단락만 강조 | `h3 + p` | `h3 ~ p` (뒤의 단락 전부를 고른다) |
| 라벨 바로 뒤 입력 칸 꾸밈 | `label + input` | 입력 칸이 라벨 안에 있을 때의 `label + input` |
| A 뒤에 오는 같은 종류 전부 | `A ~ B` | `A + B` |
| 부모 바로 아래 자식 | `A > B` | `A + B` (형제 관계용이다) |
| 사이 마크업이 자주 바뀌는 곳 | 클래스를 직접 붙이기 | 위치에 기대는 `A + B` |

## 핵심 문장

1. **`A + B` 는 A 바로 다음에 오는 형제 B 하나를 고르고, 스타일은 B 가 받는다.**
2. **사이에 다른 요소가 하나라도 끼면 매칭되지 않는다** — 공백 글자와 주석은 요소가 아니라 상관없다.
3. **방향은 문서 순서의 앞 → 뒤 하나뿐이고, 두 요소는 같은 부모를 둔 형제여야 한다.**
4. **「바로 다음 하나」는 `+`, 「뒤의 전부」는 `~` 다.**

## 용어 풀이

- **결합자** — 두 선택자 사이의 관계를 조건으로 거는 기호(공백 · `>` · `+` · `~`).
- **인접 형제 결합자** — `+`. 왼쪽 요소 바로 다음 형제를 고른다.
- **일반 형제 결합자** — `~`. 왼쪽 요소 뒤에 오는 형제를 모두 고른다.
- **자손 결합자** — 공백. 안쪽 어느 깊이에 있든 고른다.
- **자식 결합자** — `>`. 바로 한 단계 아래 자식만 고른다.
- **형제** — 같은 부모를 둔 요소끼리.
- **문서 순서** — HTML 에 적힌 차례. 「다음」 「앞」은 이 차례로 정한다.

## 더 들어가면

- 결합자 자체는 선택자의 우선순위(명시도)에 더하지 않고, 양쪽 단순 선택자만 센다 (확인 필요).
- 「B 바로 앞의 A」를 꾸미고 싶다면 `:has()` 를 써서 `A:has(+ B)` 처럼 쓸 수 있다 — 지원 브라우저 범위는 (확인 필요).
- `* + *` 처럼 「첫째를 뺀 모든 형제」에 위 여백을 주는 기법이 널리 쓰인다 (확인 필요).
- 명세의 새 판에서는 이 결합자를 「next-sibling combinator」라고도 부른다 (확인 필요).
