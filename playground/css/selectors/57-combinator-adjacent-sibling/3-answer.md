## 퀴즈 정답

### 1. 「첫째」 단락만 굵게 된다

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
「첫째」만 굵고 「둘째」는 그대로다. (코드에서 읽은 것 — 렌더 실측 아님)

**왜 그런가**
`h3 + p` 는 `h3` 의 바로 다음 형제인 `p` 하나만 고른다.
「둘째」의 바로 앞 형제는 `h3` 가 아니라 「첫째」 `p` 라 조건을 채우지 못한다.
근거: 2-summary 「동작 방식 (1)」.

### 2. 적용되지 않는다 — 사이에 `div` 가 끼었다

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
「설명 단락」은 갈색이 되지 않는다. (코드에서 읽은 것 — 렌더 실측 아님)

**왜 그런가**
`p` 의 바로 앞 형제 요소는 `div` 이고, `h3` 는 그보다 한 칸 더 앞이다.
두 요소 사이에 다른 요소가 있으면 매칭되지 않는다.
이 마크업에서 `h3` 바로 다음을 고르려면 `h3 + div` 가 맞는다.
근거: 2-summary 「동작 방식 (2)」 · 「어디서 틀리나 2」.

### 3. 「뒤 단락」만 칠해진다

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
「뒤 단락」만 노란 배경이고 「앞 단락」은 그대로다. (코드에서 읽은 것 — 렌더 실측 아님)

**왜 그런가**
`+` 는 문서 순서에서 A 뒤쪽, 바로 다음 요소만 본다.
「앞 단락」은 `h3` 보다 먼저 나오므로 「`h3` 바로 다음」이 아니다.
근거: 2-summary 「동작 방식 (3)」.

### 4. 스타일은 맨 오른쪽 선택자에 맞는 요소가 받기 때문이다

결합자가 섞인 선택자에서 실제로 고르는 대상은 맨 오른쪽 선택자(`p`)에 맞는 요소다.
왼쪽 `h3` 는 「바로 앞 형제가 `h3` 여야 한다」는 조건을 거는 역할만 한다.
그래서 `label + input` 에서도 꾸며지는 쪽은 `input` 이다.
근거: 2-summary 「동작 방식 (1)」 · 「문법 — 형태와 규칙」 · 「어디서 틀리나 3」.

### 5. 고른다 — 줄바꿈과 주석은 요소가 아니다

결합자는 요소 사이의 관계만 본다.
줄바꿈 · 공백 글자와 HTML 주석은 요소가 아니라 형제 「칸」을 차지하지 않는다.
따라서 `p` 의 바로 앞 형제 요소는 여전히 `h3` 이고 매칭된다.
근거: 2-summary 「동작 방식 (2)」 · 「구현 세부사항 대 언어 보장」.

### 6. 둘이 형제가 아니라 부모-자식이기 때문이다

`input` 이 `label` 안에 있으면 `label` 은 부모, `input` 은 자식이다.
`+` 는 같은 부모를 둔 형제 사이에서만 성립하므로 매칭되지 않는다.
이 마크업이라면 `label > input` 이나 `label input` 처럼 자식 · 자손 결합자를 써야 한다.
근거: 2-summary 「동작 방식 (3)」 · 「어디서 틀리나 5」.

### 7. 두 단락 모두를 고르게 된다

`~` 는 A 뒤에 오는 형제 B 를 바로 다음이 아니어도 전부 고른다.
예제에서 두 단락 모두 `h3` 뒤의 형제이므로 둘 다 강조된다.
「바로 다음 하나」는 `+`, 「뒤의 전부」는 `~` 다.
근거: 2-summary 「언제 쓰고 언제 안 쓰나」 · 「핵심 문장 4」.

### 8. 공백은 「안쪽 어디든」, `+` 는 「바로 다음 형제」를 건다

공백(자손 결합자)은 `h3` 가 `.adj-demo` 안쪽 어느 깊이에 있으면 된다는 조건이다.
`+` 는 `p` 가 그 `h3` 의 바로 다음 형제여야 한다는 조건이다.
`p` 는 `h3` 의 형제이므로 저절로 같은 부모 아래, 즉 `.adj-demo` 안에 놓인다.
근거: 2-summary 「동작 방식 (4)」.

## 실습 정답

### 실습 1. 제목 바로 다음 단락만 강조하기

**요구 조건 → 정답 코드의 자리**

| 요구 조건 | 정답 코드 |
|---|---|
| 1. 상자 안에 `h3` 하나, `p` 둘 | `<div class="adj-demo">` 안의 `<h3>제목</h3>` · `<p>제목 바로 다음 단락</p>` · `<p>두 번째 단락</p>` |
| 2. 제목 기본 스타일 | `.adj-demo h3 { margin; color }` |
| 3. 모든 단락 공통 스타일 | `.adj-demo p { margin; padding; border-radius }` |
| 4. `h3` 바로 다음 `p` 만 강조 | `.adj-demo h3 + p { background; font-weight; color }` |
| 5. 두 번째 단락은 강조 없음 | 두 번째 `p` 의 바로 앞 형제가 `p` 라 `.adj-demo h3 + p` 에 맞지 않음 |

**정답 코드** — study-practice 의 줄 단위 주석판이다(코드 동작은 원본 예제와 같다).

`css/selectors/reference/combinator-adjacent-sibling.html`

```html
<!DOCTYPE html>
<!-- 문서 타입 선언: HTML5 -->
<html lang="ko">
<head>
<meta charset="utf-8">
<title>+ 인접 형제 결합자 - 첫 번째 요소 바로 다음에 오는 형제 요소를 선택한다.</title>
<!--
  [선택자] + 인접 형제 결합자
  설명: 첫 번째 요소 바로 다음에 오는 형제 요소를 선택한다.
  구문: A + B { }
  팁: 폼에서 label + input, 제목 뒤 첫 단락 등을 선택할 때 유용하다. 두 요소 사이에 다른 요소가 있으면 매칭되지 않는다.
-->
<style>
  /* .adj-demo h3: .adj-demo의 자손인 h3 요소 매칭 */
  .adj-demo h3 {
    margin: 0 0 4px;             /* 위/좌/우 0, 아래 4px 마진 */
    color: #1f2937;              /* 진한 회색 텍스트 */
  }
  /* .adj-demo p: .adj-demo의 자손인 p 요소 매칭 */
  .adj-demo p {
    margin: 4px 0;               /* 위아래 4px, 좌우 0 마진 */
    padding: 8px;                /* 안쪽 여백 8px */
    border-radius: 4px;          /* 4px 둥근 모서리 */
  }
  /* .adj-demo h3 + p: .adj-demo 안에서 h3 바로 다음에 오는 p만 매칭 */
  .adj-demo h3 + p {
    background: #fef3c7;         /* 노란색 배경으로 강조 */
    font-weight: bold;           /* 굵게 */
    color: #92400e;              /* 진한 갈색 텍스트 */
  }
</style>
</head>
<body>
  <div class="adj-demo">
    <!-- 제목 요소 -->
    <h3>제목</h3>
    <!-- h3 바로 다음 단락 (인접 형제로 강조됨) -->
    <p>제목 바로 다음 단락</p>
    <!-- 두 번째 단락 (인접 형제 아님) -->
    <p>두 번째 단락</p>
  </div>

</body>
</html>
```

원본 예제의 나머지 조각(study-practice 에는 없고 study-site 항목 데이터에만 있다):

```css
.adj-demo h3 { margin: 0 0 4px; color: #1f2937; }
.adj-demo p { margin: 4px 0; padding: 8px; border-radius: 4px; }
.adj-demo h3 + p { background: #fef3c7; font-weight: bold; color: #92400e; }
```

**실행 결과** — 실행하지 않음 — 브라우저 화면에서 결과를 보는 예제다 — 글로 옮길 출력이 없다.

**풀이 요점**
- 핵심은 `.adj-demo h3 + p` 한 줄이다 — 공백으로 상자 안의 `h3` 를 잡고, `+` 로 그 바로 다음 `p` 를 고른다.
- 공통 단락 규칙과 강조 규칙은 겹치는 속성이 없어, 첫 단락은 두 규칙의 선언을 모두 받는다.
- 두 번째 단락은 바로 앞이 `p` 라 강조 규칙에서 빠진다 — 클래스를 따로 달 필요가 없다.
- 제목과 첫 단락 사이에 다른 요소를 넣으면 강조가 사라진다 — 위치에 기대는 선택자의 약점이다.
