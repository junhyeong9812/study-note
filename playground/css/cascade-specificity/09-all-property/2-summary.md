## 한눈에 — 쉽게 말하면

**`all` 은 「방 전체 초기화 버튼」이다.**
가구를 하나씩 빼는 대신 버튼 하나로 방을 한꺼번에 되돌린다.
버튼에는 되돌릴 방식이 몇 가지 있다.
공장 출고 상태로 돌리거나, 부모 방을 그대로 따라 하거나, 집주인이 처음 꾸며 둔 상태로 돌린다.
CSS 의 `all` 도 똑같은 구조다.
속성 수백 개를 하나씩 적지 않고, 한 선언으로 거의 모든 속성에 같은 키워드를 건다.

> **단축 속성** — 여러 속성을 한 선언으로 한꺼번에 정하는 속성이다.\
> 예: `margin: 0` 은 위·오른쪽·아래·왼쪽 바깥 여백 넷을 한 번에 정한다.

| 비유 | 실체 |
|---|---|
| 방 전체 초기화 버튼 | `all` 속성 |
| 공장 출고 상태 | `initial` — 명세가 정한 속성의 초깃값 |
| 부모 방 따라 하기 | `inherit` — 부모 요소의 값 |
| 물려받는 것은 부모 따라, 나머지는 출고 상태 | `unset` |
| 집주인이 처음 꾸며 둔 상태 | `revert` — 브라우저 기본 스타일 |
| 바로 앞 층의 상태 | `revert-layer` — 앞 캐스케이드 레이어의 값 |
| 초기화해도 남는 벽지·문패 | `direction` · `unicode-bidi` · 커스텀 속성 |

```text
   요소 하나                      all: <키워드>
 ┌───────────────┐            ┌───────────────┐
 │ color ...     │            │ color   → 키워드 │
 │ display ...   │  ───────▶  │ display → 키워드 │
 │ margin ...    │            │ margin  → 키워드 │
 │ --accent ...  │            │ --accent  (그대로) │
 │ direction ... │            │ direction (그대로) │
 └───────────────┘            └───────────────┘
```

## 이 주제가 답하려는 질문

1. 한 요소에 걸린 스타일을 한 줄로 걷어내려면 어떻게 하나?
2. `initial` · `inherit` · `unset` · `revert` · `revert-layer` 는 각각 값을 어디서 가져오나?
3. 왜 `all: unset` 보다 `all: revert` 가 리셋 용도로 더 안전한가?
4. `all` 을 쓴 뒤 필요한 속성만 다시 주려면 무엇을 지켜야 하나?

## 동작 방식

### (1) `all` 은 「속성마다 같은 키워드를 적은 것」과 같다

**언제 쓰나** — 어떤 요소의 스타일을 통째로 비우고 새로 시작할 때 쓴다.
속성을 하나씩 나열하지 않고 한 줄로 끝낸다.

```text
입력 코드                         무엇이 일어나나                     결과
.reset { all: unset; }   →   color: unset;               →   거의 모든 속성이
                              display: unset;                  unset 으로 정해진다
                              margin: unset; …(전부)
                              단, direction · unicode-bidi ·
                              --커스텀속성 은 빼고
```

- `all` 은 `unicode-bidi` · `direction` · 커스텀 속성을 뺀 모든 속성에 키워드를 건다.
- 그래서 `--accent` 같은 CSS 변수는 `all` 을 써도 지워지지 않고, 글 쓰는 방향(`direction`)도 그대로 남는다.
- `all` 은 특별한 힘이 없는 보통 선언이다.
- 펼쳐진 속성 하나하나가 그 규칙의 명시도와 순서를 그대로 들고 캐스케이드에서 겨룬다.
- 그래서 명시도가 더 높은 규칙이 같은 속성을 정하면 그 규칙이 이긴다.
- 같은 선언 블록 안에서는 뒤에 쓴 선언이 이긴다.
- 그래서 `all` 뒤에 적은 개별 속성은 살아남고, `all` 앞에 적은 개별 속성은 `all` 에 덮인다.

> **캐스케이드** — 한 요소의 한 속성에 선언이 여럿 걸릴 때 어느 것을 쓸지 정하는 규칙이다.\
> 예: 출처 → 레이어 → 명시도 → 순서 차례로 비교해 이긴 선언 하나만 쓴다.

> **명시도** — 선택자가 얼마나 구체적인지를 (id, 클래스, 태그) 개수로 센 값이다.\
> 예: `.reset-heading` 은 (0,1,0), `#title` 은 (1,0,0) 이라 `#title` 이 이긴다.

> **커스텀 속성** — `--` 로 시작하는 이름에 값을 담아 두고 `var()` 로 꺼내 쓰는 속성(CSS 변수)이다.\
> 예: `--accent: tomato;` 를 두고 `color: var(--accent);` 로 쓴다.

### (2) `initial` · `inherit` · `unset` — 값이 명세와 부모에서 온다

**언제 쓰나** — 브라우저 기본 꾸밈까지 모두 지운 「빈 캔버스」가 필요할 때 쓴다.

```text
입력 코드                       속성 종류            가져오는 값
all: initial             →   모든 속성       →   명세의 초깃값 (display 는 inline)
all: inherit             →   모든 속성       →   부모 요소의 값
all: unset               →   상속 속성       →   부모 요소의 값   (color, font-size, font-weight …)
                              비상속 속성     →   명세의 초깃값    (display, margin, padding, border …)
```

- `initial` 은 「브라우저 기본값」이 아니라 「명세가 정한 초깃값」이다.
- `display` 의 초깃값은 `inline` 이다.
- 그래서 `div` 나 `h3` 에 `all: initial` 을 주면 블록이던 요소가 인라인으로 바뀐다.
- `inherit` 은 상속 여부와 상관없이 모든 속성을 부모에게서 받는다.
- `unset` 은 속성마다 갈린다.
- 원래 물려받는 속성(글자색 · 글자 크기 · 굵기)은 부모 값을 쓴다.
- 원래 물려받지 않는 속성(표시 방식 · 여백 · 테두리 · 배경)은 초깃값으로 간다.
- 그래서 `h3` 에 `all: unset` 을 주면 브라우저가 주던 굵은 글씨 · 큰 글자 · 위아래 여백이 모두 사라진다.
- 남는 것은 부모와 같은 글자색 · 크기 · 굵기를 가진 맨 글자다.

> **상속 속성** — 값을 정하지 않으면 부모의 값을 그대로 받는 속성이다.\
> 예: 부모에 `color: navy` 를 주면 자식 글자도 navy 가 된다.

> **초깃값** — 명세가 속성마다 정해 둔 출발값이다.\
> 예: `display` 의 초깃값은 `inline`, `margin` 의 초깃값은 `0` 이다.

```html demo
<div style="font-size:16px; color:#334155;">
  <h3>보통 h3 제목</h3>
  <h3 style="all: unset;">all: unset 을 준 h3</h3> 바로 뒤 글자
</div>
```

> **보이는 것** — 첫 제목은 크고 굵은 블록이고, 두 번째 제목은 부모와 같은 크기의 보통 굵기 글자로 「바로 뒤 글자」와 한 줄에 이어진다 (코드에서 읽은 것 — 렌더 실측 아님)

### (3) `revert` · `revert-layer` — 앞 단계의 스타일로 물러난다

**언제 쓰나** — 작성자가 입힌 꾸밈만 걷어내고 브라우저가 원래 주던 모양(버튼 테두리 · 제목 굵기)은 살리고 싶을 때 쓴다.

```text
입력 코드                              무엇이 일어나나                            결과
.reset-btn {                    →   작성자 출처의 선언을 없던 셈 치고     →   브라우저 기본
  all: revert;                        사용자 · 브라우저 출처 값으로 물러남        버튼 모양
  align-self: flex-start;       →   all 뒤에 적었으니 이 줄은 살아남음    →   시작점에 붙음
}
```

- 스타일에는 출처가 있다 — 브라우저(사용자 에이전트) · 사용자 · 작성자.
- 작성자 스타일에서 `revert` 를 쓰면 그 속성은 작성자 선언이 없었던 것처럼 앞 출처의 값으로 돌아간다.
- 그래서 `<button>` 은 브라우저가 주던 기본 버튼 모양을 되찾는다.
- 브라우저도 정하지 않은 속성은 결국 `unset` 처럼 부모 값이나 초깃값으로 간다.
- `align-self` 는 브라우저 기본 버튼 스타일에 없으니 `revert` 뒤에는 초깃값 `auto` 가 된다.
- `auto` 는 부모 flex 컨테이너의 정렬을 따르고, 따로 정하지 않은 세로 flex 컨테이너는 아이템을 가로로 꽉 차게 늘린다.
- 그래서 원본 코드는 `all: revert` 뒤에 `align-self: flex-start` 를 다시 적어 버튼이 시작점에 붙게 한다.
- `revert-layer` 는 출처가 아니라 캐스케이드 레이어 단위로 물러난다.
- 지금 레이어의 선언을 없던 셈 치고 바로 앞 레이어의 값을 쓴다.

> **출처(origin)** — 스타일 선언이 누가 쓴 것인지에 따른 구분이다.\
> 예: 브라우저 기본 스타일시트, 사용자 설정, 페이지 작성자의 CSS.

> **캐스케이드 레이어** — `@layer` 로 작성자 스타일을 층으로 나눠 층의 차례로 우선순위를 정하는 장치다.\
> 예: `@layer reset, components;` 처럼 선언하면 `components` 층이 `reset` 층을 이긴다.

## 문법 — 형태와 규칙

```css
/* 빈 캔버스: 브라우저 기본 꾸밈까지 지운다 */
.plain {
  all: unset;
  cursor: text;           /* 다시 줄 것은 all 뒤에 */
}

/* 브라우저 기본 모양으로 되돌린다 */
.native-btn {
  all: revert;
  align-self: flex-start; /* revert 로 사라진 배치를 다시 준다 */
}
```

- 꼴은 `all: initial | inherit | unset | revert | revert-layer;` 다.
- 다른 값(길이 · 색)은 받지 않는다 — 키워드만 받는다.
- `unicode-bidi` · `direction` · 커스텀 속성은 영향받지 않는다.
- 같은 블록에서 `all` 뒤에 적은 속성만 살아남는다.
- `all` 은 보통 선언이라 명시도 · 순서 규칙을 그대로 따른다.

| 키워드 | 상속 속성 (`color` 등) | 비상속 속성 (`display` · `margin` 등) | 쓰임 |
|---|---|---|---|
| `initial` | 명세 초깃값 | 명세 초깃값 | 상속까지 끊고 완전히 출발값으로 |
| `inherit` | 부모 값 | 부모 값 | 모든 것을 부모와 똑같이 |
| `unset` | 부모 값 | 명세 초깃값 | 「빈 캔버스」 — 꾸밈 전부 제거 |
| `revert` | 앞 출처(브라우저 · 사용자)의 값 | 앞 출처의 값 | 작성자 꾸밈만 걷고 브라우저 기본으로 |
| `revert-layer` | 앞 캐스케이드 레이어의 값 | 앞 레이어의 값 | 레이어 하나만 물리기 |

## 어디서 틀리나

### 1. `all: unset` 은 `display` 까지 지운다

`display` 는 비상속 속성이라 `unset` 이면 초깃값 `inline` 이 된다.
`h3` · `div` 처럼 블록이던 요소가 앞뒤 글자와 한 줄에 붙을 수 있다.
버튼 · 목록 · 표 요소도 브라우저가 주던 표시 방식을 잃는다.
그래서 팁은 리셋 용도에는 `all: revert` 가 대부분 더 안전하다고 말한다.

### 2. 「`display` 까지 `inline` 으로 돌아감」은 놓인 자리에 따라 다르다

원본의 주장 — 정답 코드 주석은 `.reset-heading` 에 대해 「display까지 inline으로 돌아감」이라고 적는다.
왜 의심스러운가 — 그 `h3` 은 `display: flex` 인 `.all-demo` 의 자식, 곧 flex 아이템이다.
flex 아이템은 지정된 `display` 가 `inline` 이어도 블록 수준으로 바뀌어(blockify) 배치된다.
그래서 이 데모에서는 제목이 버튼과 한 줄로 붙지 않고 따로 한 줄을 차지할 것으로 읽힌다.
`inline` 이 되는 것은 사실이지만, 화면에서 그것이 드러나는 것은 보통 블록 흐름 안에 놓였을 때다.

> **blockify(블록화)** — flex · grid 아이템의 `display` 를 블록 수준 값으로 바꿔 계산하는 규칙이다.\
> 예: flex 컨테이너 안의 `span` 은 `display: inline` 이어도 블록처럼 놓인다.

### 3. `initial` 은 「브라우저 기본값」이 아니다

이름 때문에 「처음 모양」으로 착각하기 쉽다.
`initial` 은 명세의 초깃값이라 `div` 에도 `display: inline` 을 준다.
브라우저가 원래 주던 모양을 원하면 `revert` 를 쓴다.

### 4. 다시 줄 속성은 `all` 뒤에 적는다

원본은 `all: unset` 뒤에 `cursor: text`, `all: revert` 뒤에 `align-self: flex-start` 를 적는다.
같은 블록에서 순서를 바꿔 `all` 을 뒤에 두면 앞의 속성까지 덮여 사라진다.

### 5. `all` 이 언제나 이기지는 않는다

`all` 은 속성마다 보통 선언으로 펼쳐질 뿐이다.
같은 요소에 명시도가 더 높은 규칙이 `color` 를 정하면 그 `color` 는 남는다.
「한 줄로 모든 스타일을 무조건 지운다」가 아니라 「이 규칙이 이기는 속성만 지운다」다.

### 6. 데모의 before / after 는 같은 꾸밈을 지운 비교가 아니다

`.reset-heading` 요소에는 처음부터 `.styled-heading` 의 규칙이 걸리지 않는다 — 클래스가 다르다.
그래서 `all: unset` 이 실제로 걷어내는 것은 브라우저가 `h3` 에 주던 큰 글자 · 굵기 · 위아래 여백이다.
파란 배경 · 왼쪽 강조선이 없는 것은 `all` 때문이 아니라 애초에 그 규칙을 받지 않아서다.

### 7. 변수와 글 방향은 남는다

`all` 은 커스텀 속성 · `direction` · `unicode-bidi` 를 건드리지 않는다.
「초기화했는데 `var(--색)` 이 여전히 먹는다」는 정상이다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `all` 이 `direction` · `unicode-bidi` · 커스텀 속성을 빼고 모두에 적용된다 | CSS 명세 |
| `initial` · `inherit` · `unset` 이 값을 정하는 방식 | CSS 명세 (캐스케이드) |
| `display` 의 초깃값이 `inline` 이다 | CSS 명세 |
| flex 아이템의 `display` 가 블록화된다 | CSS 명세 (Display · Flexbox) |
| `revert` 뒤 버튼이 갖는 구체적인 모양(테두리 · 배경 · 여백) | 각 브라우저의 기본 스타일시트 — 브라우저마다 다르다 |
| 데모를 열었을 때 보이는 모습 | 코드에서 읽은 것 — 렌더 실측 아님 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 작성자 꾸밈만 걷고 브라우저 기본 버튼 · 입력 모양을 되찾기 | `all: revert` | `all: unset` (버튼다운 모양까지 사라진다) |
| 브라우저 기본 꾸밈까지 없앤 맨 요소에서 새로 꾸미기 | `all: unset` + 필요한 속성 다시 주기 | `all: initial` (글자색 · 크기 상속까지 끊긴다) |
| 부모와 완전히 같은 값만 쓰기 | `all: inherit` | 개별 속성 수십 줄 |
| 레이어로 나눈 스타일에서 한 층만 물리기 | `all: revert-layer` | `all: revert` (작성자 레이어 전부가 물러난다) |
| 속성 한두 개만 되돌리기 | 그 속성에 `unset` · `revert` | `all` (지울 필요 없는 것까지 지운다) |

## 핵심 문장

1. **`all` 은 `direction` · `unicode-bidi` · 커스텀 속성을 뺀 모든 속성에 같은 키워드를 거는 단축 속성이다.**
2. **`unset` 은 상속 속성은 부모 값, 비상속 속성은 초깃값으로 보낸다** — 그래서 `display` 까지 `inline` 이 된다.
3. **`revert` 는 작성자 선언을 없던 셈 치고 브라우저 기본 스타일로 물러난다** — 리셋 용도로 대부분 더 안전하다.
4. **`all` 도 보통 선언이다** — 명시도 · 순서 규칙을 따르니 다시 줄 속성은 같은 블록에서 `all` 뒤에 적는다.

## 관련 자료

- `initial-inherit-unset-revert` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `inheritance` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- 원본: study-site 항목 데이터 `data/css/cascade-specificity.json` 의 `all-property`

## 용어 풀이

- **단축 속성** — 여러 속성을 한 선언으로 한꺼번에 정하는 속성이다.
- **캐스케이드** — 한 속성에 걸린 여러 선언 가운데 쓸 것 하나를 고르는 규칙이다.
- **출처(origin)** — 선언을 누가 썼는지(브라우저 · 사용자 · 작성자)에 따른 구분이다.
- **명시도** — 선택자의 구체성을 (id, 클래스, 태그) 개수로 센 값이다.
- **상속 속성** — 값을 정하지 않으면 부모 값을 받는 속성이다.
- **비상속 속성** — 값을 정하지 않으면 초깃값을 쓰는 속성이다.
- **초깃값** — 명세가 속성마다 정해 둔 출발값이다.
- **사용자 에이전트 스타일시트** — 브라우저가 요소마다 기본으로 입히는 스타일 모음이다.
- **캐스케이드 레이어** — `@layer` 로 작성자 스타일을 층으로 나누는 장치다.
- **커스텀 속성** — `--이름` 으로 값을 담아 `var()` 로 꺼내는 CSS 변수다.
- **blockify(블록화)** — flex · grid 아이템의 `display` 를 블록 수준으로 바꿔 계산하는 규칙이다.

## 더 들어가면

- `direction` · `unicode-bidi` 가 빠진 까닭은 문서의 글 방향(오른쪽에서 왼쪽으로 쓰는 언어)을 스타일 초기화가 망가뜨리지 않게 하려는 것으로 보인다 (확인 필요).
- `all` 은 CSS 속성만 건드린다 — HTML 속성(`disabled` · `hidden` 등)이나 요소의 동작(버튼 누르기 · 폼 제출)은 그대로다 (확인 필요).
- `all: unset` 을 준 버튼은 키보드 포커스 표시까지 사라질 수 있어 접근성을 위해 `:focus-visible` 스타일을 다시 주는 경우가 많다 (확인 필요).
- 웹 컴포넌트 안쪽에서 바깥의 상속 스타일을 끊을 때 `:host { all: initial; }` 꼴을 쓰기도 한다 (확인 필요).
- 브라우저마다 `revert` · `revert-layer` 를 지원하기 시작한 시점은 다르다 (확인 필요).
