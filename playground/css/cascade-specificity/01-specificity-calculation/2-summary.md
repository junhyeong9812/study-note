## 한눈에 — 쉽게 말하면

**명시도는 「올림픽 메달 순위표」다.**
메달 순위는 금메달 수를 먼저 비교하고, 금메달 수가 같을 때만 은메달 수를 본다.
은메달이 열한 개여도 금메달 한 개를 이기지 못한다.
CSS 명시도도 똑같은 구조다.
한 요소에 여러 규칙이 맞으면 브라우저는 선택자마다 네 칸짜리 점수를 매기고, 왼쪽 칸부터 비교해 더 큰 쪽의 값을 쓴다.

> **명시도(specificity)** — 한 요소에 여러 규칙이 맞을 때 어느 규칙의 값을 쓸지 정하는, 선택자의 가중치다.\
> 예: `#target` 은 `.text` 보다 명시도가 높아서 둘이 같은 속성을 정하면 `#target` 의 값이 쓰인다.

| 비유 | 실체 |
|---|---|
| 금메달 칸 | 인라인 스타일 자리 (1,0,0,0) |
| 은메달 칸 | ID 선택자 자리 (0,1,0,0) |
| 동메달 칸 | 클래스 · 속성 · 가상클래스 자리 (0,0,1,0) |
| 참가상 칸 | 요소 · 가상요소 자리 (0,0,0,1) |
| 금메달부터 비교하는 순위 규칙 | 왼쪽 자리부터 비교하는 자릿수 비교 |

```text
                    인라인  ID  클래스  요소
  #target       →    0      1    0      0    ← 왼쪽에서 두 번째 칸에서 이미 앞선다
  .text.highlight →  0      0    2      0
                         ↑
                    여기서 승부가 난다 (1 > 0)
```

## 이 주제가 답하려는 질문

1. 선택자 하나의 명시도는 어떻게 세나?
2. 두 명시도 중 어느 쪽이 큰지는 어떻게 비교하나 — 덧셈인가, 자릿수 비교인가?
3. 한 요소에 여러 규칙이 동시에 맞으면 최종 값은 어떻게 정해지나?
4. `:is()` · `:not()` 처럼 안에 선택자를 받는 가상클래스는 몇 점으로 세나?

## 동작 방식

### (1) 선택자에서 점수 세기

**언제 쓰나** — 두 규칙이 부딪칠 때 각각의 점수를 알아야 할 때 쓴다.

```text
선택자 p.text.highlight
   p          → 요소 1개       → 요소 칸 +1
   .text      → 클래스 1개     → 클래스 칸 +1
   .highlight → 클래스 1개     → 클래스 칸 +1
                                  ↓
                     명시도 0,0,2,1
```

- 선택자를 조각으로 나눈다.
- 조각마다 어느 칸에 들어가는지 정한다: ID 는 둘째 칸, 클래스 · 속성 선택자(`[type="text"]`) · 가상클래스(`:hover`)는 셋째 칸, 요소(`p`) · 가상요소(`::before`)는 넷째 칸이다.
- 칸마다 개수를 센다.
- 네 칸을 쉼표로 이어 적은 것이 그 선택자의 명시도다.

> **선택자(selector)** — 스타일을 줄 요소를 고르는 식이다.\
> 예: `p.text` 는 `text` 클래스를 가진 `p` 요소를 고른다.

> **가상클래스(pseudo-class)** — 요소의 상태나 위치로 고르는 선택자 조각이다.\
> 예: `:hover` 는 마우스가 올라간 요소를 고른다.

> **가상요소(pseudo-element)** — 요소 안의 특정 부분을 따로 다루게 해 주는 조각이다.\
> 예: `p::before` 는 `p` 내용 앞에 생기는 가상의 상자를 다룬다.

### (2) 왼쪽 자리부터 비교하기

**언제 쓰나** — 두 명시도 중 어느 쪽이 이기는지 정할 때 쓴다.

```text
A = 0,1,0,0   (#target)
B = 0,0,11,0  (클래스 11개)

칸1: 0 vs 0  → 같다, 다음 칸
칸2: 1 vs 0  → A 가 크다 → A 승리 (나머지 칸은 보지 않는다)
```

- 맨 왼쪽 칸부터 두 값을 비교한다.
- 같으면 다음 칸으로 넘어간다.
- 처음으로 다른 칸에서 큰 쪽이 이긴다.
- 그 뒤 칸의 값은 아무리 커도 보지 않는다.
- 그래서 명시도는 10진수 덧셈(100 + 10 + 1 …)이 아니다.
  덧셈으로 생각하면 클래스 11개(110)가 ID 1개(100)를 이기는 것처럼 보이지만, 실제로는 이기지 못한다.

### (3) 한 요소에 여러 규칙이 맞을 때

**언제 쓰나** — 화면의 색이 기대와 다를 때 원인을 찾을 때 쓴다.

```text
<p class="text highlight" id="target">

맞는 규칙 (color 를 정하는 것만)
  p               0,0,0,1  gray
  .text           0,0,1,0  green
  p.text          0,0,1,1  orange
  .text.highlight 0,0,2,0  purple
  #target         0,1,0,0  #3b82f6   ← 가장 큼 → color 는 파랑
```

- 이 요소에 맞는 규칙을 모두 모은다.
- 같은 속성(여기서는 `color`)을 정하는 규칙끼리만 겨룬다.
- 그중 명시도가 가장 큰 규칙의 값이 쓰인다.
- 다른 속성은 따로 겨룬다.
  데모의 `#demo p`(0,1,0,1)는 `font-size` · `padding` 같은 속성만 정하고 `color` 는 정하지 않는다.
  그래서 `color` 경쟁에는 끼지 않고, 자기 속성들은 겨룰 상대가 없어 그대로 쓰인다.

```html demo
<div id="demo">
  <p class="text highlight" id="target">이 텍스트는 어떤 색일까?</p>
</div>
<style>
  p { color: gray; }
  .text { color: green; }
  p.text { color: orange; }
  .text.highlight { color: purple; }
  #target { color: #3b82f6; }
</style>
```

> **보이는 것** — 문장이 파란 글자로 보인다 (코드에서 읽은 것 — 렌더 실측 아님).

### (4) `:is()` · `:not()` 안의 선택자

**언제 쓰나** — 선택자 목록을 묶는 가상클래스를 쓸 때 점수를 셀 때 쓴다.

```text
:is(.a, #b) p
   :is(.a, #b) → 안의 목록 중 가장 높은 것 = #b → 0,1,0,0
   p           → 0,0,0,1
                     ↓
              명시도 0,1,0,1
```

- `:is()` · `:not()` 자체는 가상클래스지만 셋째 칸에 1점을 더하지 않는다.
- 대신 괄호 안 선택자 중 가장 높은 명시도를 그 자리의 점수로 쓴다.
- 실제로 요소가 목록의 어느 선택자에 맞았는지와 상관없이 가장 높은 것으로 센다.
  요소가 `.a` 에만 맞아도 `#b` 의 점수가 적용된다.

### (5) 인라인 스타일

**언제 쓰나** — HTML 의 `style` 속성으로 준 값과 스타일시트 규칙을 비교할 때 쓴다.

```text
<p id="target" style="color: red">
   style 속성  → 1,0,0,0
   #target     → 0,1,0,0
   칸1: 1 vs 0 → 인라인 승리 → 빨강
```

- `style` 속성에 적은 선언은 맨 왼쪽 칸에 점수를 가진 것으로 본다.
- 그래서 ID 를 몇 개 이어 붙인 선택자보다도 이긴다.
- 선택자 중 가장 구체적인 ID 보다도 「이 요소 하나에만 직접 적은 값」이 더 구체적이라는 생각과 이어진다.

> **인라인 스타일** — HTML 요소의 `style` 속성에 직접 적은 선언이다.\
> 예: `<p style="color: red">`.

## 문법 — 형태와 규칙

```css
p                { color: gray; }    /* 0,0,0,1 */
[type="text"]    { color: teal; }    /* 0,0,1,0 — 속성 선택자 */
a:hover          { color: navy; }    /* 0,0,1,1 — 가상클래스 + 요소 */
p::before        { content: "*"; }   /* 0,0,0,2 — 가상요소 + 요소 */
.text.highlight  { color: purple; }  /* 0,0,2,0 */
#demo p          { font-size: 20px; } /* 0,1,0,1 */
:not(#x) .card   { color: black; }   /* 0,1,1,0 — :not 안의 #x 가 점수 */
```

| 칸 | 무엇이 들어가나 | 1개일 때 |
|---|---|---|
| 1번째 | 인라인 `style` 속성 | 1,0,0,0 |
| 2번째 | ID 선택자 `#id` | 0,1,0,0 |
| 3번째 | 클래스 `.class` · 속성 `[attr]` · 가상클래스 `:hover` | 0,0,1,0 |
| 4번째 | 요소 `p` · 가상요소 `::before` | 0,0,0,1 |

- 순서: `인라인(1,0,0,0) > #id(0,1,0,0) > .class(0,0,1,0) > element(0,0,0,1)`.
- 같은 종류 조각은 그 칸의 수를 늘린다(`.a.b` → 0,0,2,0).
- 비교는 자릿수 비교다 — 왼쪽 칸이 크면 오른쪽 칸은 보지 않는다.
- `:is()` · `:not()` 은 괄호 안 목록 중 가장 높은 명시도를 쓴다.

## 어디서 틀리나

### 1. 명시도를 덧셈으로 계산한다

ID = 100, 클래스 = 10, 요소 = 1 로 더해 비교하면 틀린다.
클래스 11개는 덧셈으로 110 이지만 ID 1개(100)를 이기지 못한다.
명시도는 10진수 덧셈이 아니라 자릿수 비교다.

### 2. `:is()` · `:not()` 을 클래스 하나로 센다

`:is(.a, #b)` 를 가상클래스 하나(0,0,1,0)로 세면 틀린다.
괄호 안 목록 중 가장 높은 명시도, 여기서는 `#b` 의 0,1,0,0 이 쓰인다.
요소가 `.a` 에만 맞아도 마찬가지다.

### 3. 가상클래스와 가상요소를 같은 칸에 넣는다

`:hover`(콜론 하나, 가상클래스)는 클래스 칸이다.
`::before`(콜론 둘, 가상요소)는 요소 칸이다.
이름이 비슷해도 들어가는 칸이 다르다.

### 4. 속성이 다른 규칙끼리 겨룬다고 생각한다

명시도 경쟁은 같은 속성을 정하는 규칙끼리만 일어난다.
`#demo p`(0,1,0,1)가 `#target`(0,1,0,0)보다 높아도, `color` 를 정하지 않으면 글자색에는 아무 영향이 없다.

### 5. 높은 명시도로 계속 덮어쓴다

덮어쓸 때마다 ID 를 붙이면 다음 번에는 ID 를 둘 붙여야 이길 수 있다.
명시도는 한번 올리면 내리기 어렵다.
꼭 필요한 만큼만 올린다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| ID > 클래스 · 속성 · 가상클래스 > 요소 · 가상요소 의 자릿수 비교 | CSS 선택자 명세 — 언어 보장 |
| 클래스 11개가 ID 1개를 이기지 못한다 | 명세의 자릿수 비교에서 나오는 결과 — 언어 보장 |
| `:is()` · `:not()` 은 안의 목록 중 가장 높은 명시도를 쓴다 | CSS 선택자 명세(Level 4)의 규칙 — 오래된 브라우저의 지원 여부는 (확인 필요) |
| 인라인 스타일을 1,0,0,0 의 첫 칸으로 적는다 | 원본의 주장 → 의심스러운 점: 이 네 칸 표기는 널리 쓰는 설명용 표기이고, 명세는 `style` 속성 선언을 선택자 명시도와 별개 단계로 다룬다고 알려져 있다 (확인 필요). 「인라인이 어떤 선택자보다 이긴다」는 결과는 같다 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 여러 요소에 같은 모양을 준다 | 클래스 하나 (0,0,1,0) | ID — 한 요소에만 붙고 명시도가 너무 높다 |
| 기본 모양을 한 경우에만 바꾼다 | 클래스 하나 더 붙이기 (`.text.highlight`) | ID 를 덧붙여 억지로 이기기 |
| 색이 왜 안 바뀌는지 찾는다 | 맞는 규칙들의 명시도를 칸별로 적어 비교 | 덧셈 점수로 어림하기 |
| 선택자 목록을 묶는다 | `:is()` — 단, 가장 높은 명시도가 적용됨을 기억 | 안에 ID 를 넣고 클래스 하나쯤으로 여기기 |
| 한 요소만 급히 바꾼다 | 스타일시트의 구체적 규칙 | 인라인 `style` — 스타일시트로 덮기 어렵다 |

## 핵심 문장

1. **명시도는 네 칸(인라인 · ID · 클래스 · 요소)의 점수다** — 선택자 조각을 칸별로 센다.
2. **비교는 왼쪽 칸부터 하는 자릿수 비교다** — 클래스 11개도 ID 1개를 못 이긴다.
3. **같은 속성을 정하는 규칙끼리만 겨룬다** — 이긴 규칙의 값이 그 속성의 값이 된다.
4. **`:is()` · `:not()` 은 안의 목록 중 가장 높은 명시도를 쓴다.**
5. **가상클래스는 클래스 칸, 가상요소는 요소 칸이다.**

## 용어 풀이

- **명시도(specificity)** — 선택자의 가중치. 여러 규칙이 부딪칠 때 이기는 쪽을 정한다.
- **선택자(selector)** — 스타일을 줄 요소를 고르는 식.
- **ID 선택자** — `#이름` 꼴. `id` 속성이 같은 요소를 고른다.
- **클래스 선택자** — `.이름` 꼴. `class` 속성에 그 이름이 있는 요소를 고른다.
- **속성 선택자** — `[attr]` · `[attr="값"]` 꼴. 속성으로 요소를 고른다.
- **요소 선택자** — `p` 처럼 태그 이름으로 고른다.
- **가상클래스** — `:hover` 처럼 상태 · 위치로 고르는 조각.
- **가상요소** — `::before` 처럼 요소의 일부를 다루는 조각.
- **인라인 스타일** — HTML 요소의 `style` 속성에 직접 적은 선언.
- **자릿수 비교** — 왼쪽 칸부터 비교해 처음 달라지는 칸에서 승부를 내는 방식.
- **`:is()` · `:not()`** — 선택자 목록을 받는 가상클래스. 명시도는 목록 중 가장 높은 것.

## 더 들어가면

- 명시도가 완전히 같으면 스타일시트에서 나중에 나온 선언이 이긴다 (확인 필요 — 원본에 없는 캐스케이드 규칙).
- `!important` 를 붙인 선언은 명시도 비교보다 앞선 단계에서 우선한다 (확인 필요).
