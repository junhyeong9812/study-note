## 한눈에 — 쉽게 말하면

**커스텀 속성은 「집안에 붙여 둔 가훈 쪽지」다.**
할아버지가 거실(문서 루트)에 「밥은 흰 그릇에」라고 붙여 두면 온 가족이 그 쪽지를 따른다.
작은방(어떤 요소)에서 「우리 방은 검은 그릇」이라고 새 쪽지를 붙이면, 그 방과 그 방 안쪽만 새 쪽지를 따르고 거실과 다른 방은 그대로다.
그릇을 꺼내는 사람(`var()` 를 쓰는 속성)은 「지금 내 자리에서 보이는 쪽지」를 읽을 뿐이다.
CSS 변수도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 거실에 붙인 쪽지 | `:root { --bg: …; }` |
| 작은방에 붙인 새 쪽지 | `.dark { --bg: …; }` |
| 쪽지를 읽고 그릇을 고르는 사람 | `background: var(--bg);` |
| 쪽지가 아예 없을 때 쓰는 기본 그릇 | `var(--bg, white)` 의 두 번째 인자 |

```text
html (:root)   --bg = 흰색  ──상속──┐
  └ .theme-demo                     │
      ├ .card        → var(--bg) = 흰색   (물려받은 값)
      └ .card.dark   --bg = 네이비 (새로 선언)
            └ button → var(--primary) = 다크 쪽 값
```

## 이 주제가 답하려는 질문

1. 값 하나를 한곳에 정해 두고 여러 속성에서 다시 쓰려면 어떻게 하나?
2. 같은 HTML 을 그대로 두고 테마(색 묶음)만 바꾸려면 무엇을 바꾸나?
3. 변수가 정의되지 않았거나 값이 엉뚱할 때 `var()` 를 쓴 속성은 어떻게 되나?
4. 변수의 타입 · 초기값 · 상속 여부를 직접 정하려면 무엇을 쓰나?

## 동작 방식

### (1) 정의하고 참조하기

**언제 쓰나** — 같은 색 · 같은 길이가 여러 규칙에 되풀이될 때 한 이름으로 모은다.

```text
:root { --radius: 8px; }            정의: 이름이 -- 로 시작하는 속성
        │
.card { border-radius: var(--radius); }   참조: var(이름)
        │
계산된 값 단계에서 var(--radius) 가 8px 로 바뀐다 → border-radius: 8px
```

- `--` 로 시작하는 이름은 브라우저가 뜻을 모르는 「사용자 정의 속성」으로 받아들여진다.
- 다른 속성의 값 자리에 `var(--이름)` 을 쓰면 그 자리에 변수 값이 끼워진다.
- 값을 한곳에서 바꾸면 그 변수를 참조하는 모든 속성이 함께 바뀐다.

> **커스텀 속성** — 이름이 `--` 로 시작하고 작성자가 직접 만든 CSS 속성.\
> 예: `--primary: #3b82f6;`

> **`var()`** — 커스텀 속성의 값을 다른 속성의 값 자리에 끼워 넣는 함수.\
> 예: `color: var(--text);`

### (2) 상속 — `:root` 에 두면 전역이 된다

**언제 쓰나** — 문서 전체에서 같은 디자인 토큰을 쓰고 싶을 때 `:root` 에 모아 둔다.

```text
:root(=html) 에 --text 선언
   ↓ 상속 (부모 → 자식, 기본 동작)
body → div → p → span …
   ↓
어느 요소에서 var(--text) 를 써도 html 의 값이 보인다
```

- 커스텀 속성은 기본으로 상속되는 속성이다.
- `:root` 는 문서 루트(`html`)를 가리키므로, 거기 선언한 변수는 모든 자손에게 물려진다.
- 그래서 `:root` 가 사실상 「전역 변수 자리」가 된다.

> **`:root`** — 문서의 루트 요소를 고르는 가상 클래스, HTML 에서는 `html` 요소다.\
> 예: `:root { --radius: 8px; }` 의 명시도는 (0,1,0).

> **디자인 토큰** — 색 · 간격 · 모서리 같은 디자인 결정을 이름 붙인 값으로 모아 둔 것.\
> 예: `--primary` · `--surface` · `--radius`.

### (3) 덮어쓰기 — 테마는 「같은 이름, 다른 값」

**언제 쓰나** — 컴포넌트 CSS 는 건드리지 않고 한 구역의 색 묶음만 바꿀 때.

```text
<div class="card dark">
   │  .dark { --bg: 네이비; --primary: 밝은 파랑; … }   ← 이 요소가 직접 선언
   │  :root 에서 물려받은 --bg(흰색)는 가려진다
   ├ .card { background: var(--bg) }   → 네이비
   └ button  var(--primary)            → 밝은 파랑 (카드에서 물려받음)
   --radius 는 .dark 가 다시 정하지 않았다 → :root 값이 그대로 물려진다
```

- `.dark` 는 `.card` 가 쓰는 변수와 **같은 이름**에 새 값을 준다.
- 요소가 직접 선언한 값은 부모에서 물려받은 값보다 언제나 앞선다 — 명시도 겨루기가 아니다(`:root` 와 `.dark` 는 서로 다른 요소에 붙어 있다).
- 덮어쓴 값은 그 요소와 자손에게만 퍼진다; 옆 카드(형제)와 부모는 그대로다.
- 그래서 「같은 HTML, 변수만 변경」으로 두 테마가 나란히 설 수 있다.

### (4) 동적 변경 — 클래스나 JS 로 값만 바꾼다

**언제 쓰나** — 버튼 하나로 테마를 바꾸는 것처럼 실행 중에 스타일을 바꿀 때.

```text
버튼 클릭
  ├ 방법 1: 요소에 class="dark" 를 붙였다 뗐다 → 변수 묶음이 통째로 바뀜
  └ 방법 2: el.style.setProperty('--primary', '…') → 변수 하나만 바뀜
        ↓
var(--primary) 를 쓰는 모든 속성이 새 값으로 다시 계산된다
```

- 변수는 실제 CSS 속성이라 클래스를 바꾸거나 인라인 스타일로 값을 넣으면 캐스케이드가 다시 일어난다.
- 참조하는 쪽 규칙(`.card` · `.btn`)은 한 줄도 고칠 필요가 없다.

> **동적 스타일링** — 페이지가 떠 있는 동안 스타일 값을 바꾸는 일.\
> 예: 클릭할 때 `document.documentElement.classList.toggle('dark')`.

### (5) `@property` — 변수에 타입을 붙이기

**언제 쓰나** — 변수의 값 꼴 · 초기값 · 상속 여부를 명시하고 싶을 때.

```text
@property --angle {
  syntax: '<angle>';      값의 타입
  inherits: false;        상속 안 함
  initial-value: 0deg;    아무도 선언 안 했을 때의 값
}
```

- 평범한 커스텀 속성은 타입이 없고, 늘 상속되며, 초기값이 없다.
- `@property` 로 등록하면 세 가지를 직접 정할 수 있다.
- `inherits: false` 면 자식은 부모 값을 물려받지 않고 `initial-value` 를 쓴다.

> **`@property`** — 커스텀 속성의 타입(`syntax`) · 상속(`inherits`) · 초기값(`initial-value`)을 등록하는 at-규칙.\
> 예: `@property --size { syntax: '<length>'; inherits: true; initial-value: 0px; }`

## 문법 — 형태와 규칙

```html demo
<div class="box">기본</div>
<div class="box alt">덮어씀</div>
<style>
  :root { --accent: #3b82f6; --pad: 12px; }
  .alt  { --accent: #ef4444; }
  .box  {
    padding: var(--pad);
    border-left: 6px solid var(--accent);
    color: var(--missing, #334155);  /* --missing 은 어디에도 없다 → 대체값 */
  }
</style>
```

> **보이는 것** — 첫 상자는 파란 왼쪽 띠, 둘째 상자는 빨간 왼쪽 띠, 두 상자 모두 글자는 회청색이다 (코드에서 읽은 것 — 렌더 실측 아님)

| 형태 | 뜻 |
|---|---|
| `--<name>: <value>;` | 커스텀 속성 정의 |
| `var(--<name>)` | 값 참조 |
| `var(--<name>, <fallback>)` | 변수가 정의되지 않았으면 `<fallback>` 사용 |
| `@property --<name> { … }` | 타입 · 상속 · 초기값 등록 |

- 이름은 반드시 `--` 로 시작한다.
- 이름은 대소문자를 가린다 — `--Bg` 와 `--bg` 는 다른 변수다.
- `var()` 는 속성의 **값** 자리에서만 쓴다.
- 대체값(fallback)은 변수가 **정의되지 않았을 때**만 쓰인다.
- 커스텀 속성 선언도 다른 선언처럼 캐스케이드를 따른다 — 같은 요소에 두 번 선언되면 명시도 · 순서로 이긴 쪽이 남는다.

> **대체값(fallback)** — `var()` 의 두 번째 인자, 변수가 없을 때 대신 쓰는 값.\
> 예: `var(--accent, crimson)`.

## 어디서 틀리나

### 1. 상속되므로 `:root` 에 정의하면 전역 — 거꾸로 말하면 「자손에게만」 간다

원본의 팁 그대로 커스텀 속성은 상속되므로 `:root` 에 두면 어디서나 쓸 수 있다.
반대로 `.dark` 같은 안쪽 요소에 둔 값은 그 요소의 부모 · 형제에게 가지 않는다.
「변수를 정의했는데 다른 카드에서 안 보인다」는 대개 이 경우다.

### 2. `:root` 와 `.dark` 의 명시도를 비교하지 않는다

둘 다 (0,1,0) 이지만 서로 다른 요소에 붙는다.
`.card.dark` 요소는 `--bg` 를 직접 선언했고, 직접 선언은 물려받은 값을 늘 이긴다.

### 3. 대체값은 「값이 틀렸을 때」 쓰이지 않는다

`--gap: red;` 처럼 변수는 정의되어 있는데 그 값이 `padding` 에 맞지 않으면 대체값은 무시된다.
이때 `padding: var(--gap, 20px)` 선언은 계산된 값 단계에서 무효가 되고, 속성은 상속되는 속성이면 물려받은 값, 아니면 초기값이 된다(`unset` 처럼).
같은 규칙에 앞서 쓴 `padding: 10px` 으로 돌아가지도 않는다 — 캐스케이드는 이미 `var()` 쪽 선언을 고른 뒤이기 때문이다.

> **계산된 값 시점의 무효** — 문법은 맞아 캐스케이드에서 이겼지만, 변수를 끼운 뒤 값이 속성에 맞지 않는 상태.\
> 예: `width: var(--c)` 인데 `--c: blue`.

### 4. 덮어쓰지 않은 변수는 위에서 그대로 물려진다

예제의 `.dark` 는 `--radius` 를 다시 정하지 않는다.
그래서 다크 카드의 모서리도 `:root` 의 값을 쓴다 — 테마마다 바뀌어야 할 것만 덮어쓰면 된다.

### 5. `@property` 로 `inherits: false` 를 주면 팁의 전제가 바뀐다

원본의 「상속되므로 전역」은 등록하지 않은 평범한 변수의 이야기다.
`@property` 로 상속을 끄면 `:root` 에 선언해도 자손은 `initial-value` 를 본다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `--` 이름 · `var()` · 대체값 · 기본 상속 | CSS 명세(Custom Properties) |
| 값이 맞지 않으면 계산된 값 시점에 무효 → 상속값 또는 초기값 | CSS 명세 |
| `@property` 의 `syntax` · `inherits` · `initial-value` | CSS 명세(Properties and Values API) — 브라우저마다 지원 시점이 다르다 (확인 필요) |
| 두 카드가 어떤 색으로 보이나 | 브라우저 렌더링 — 이 문서는 코드에서 읽었을 뿐이다 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 색 · 간격이 여러 규칙에 되풀이 | `:root` 의 커스텀 속성 | 같은 리터럴 값 복사 |
| 라이트/다크 테마 | 테마 클래스에서 같은 이름 덮어쓰기 | 테마마다 컴포넌트 규칙 전부 다시 쓰기 |
| 한 구역만 다른 색 | 그 구역 요소에 변수 재정의 | `!important` 로 덮기 |
| 변수가 없을 수도 있는 곳 | `var(--x, 기본값)` | 대체값이 잘못된 값을 막아 주리라 기대하기 |
| 상속되면 안 되는 값 | `@property` 의 `inherits: false` | 평범한 변수 |

## 핵심 문장

1. **`--이름` 으로 정의하고 `var(--이름)` 으로 값 자리에 끼운다.**
2. **커스텀 속성은 기본으로 상속된다** — `:root` 에 두면 전역, 안쪽 요소에 두면 그 아래만.
3. **테마는 같은 이름에 다른 값을 주는 일이다** — 컴포넌트 CSS 는 그대로다.
4. **대체값은 변수가 없을 때만 쓰인다** — 값이 틀리면 속성은 상속값이나 초기값이 된다.
5. **`@property` 로 타입 · 초기값 · 상속 여부를 명시할 수 있다.**

## 용어 풀이

- **커스텀 속성** — 이름이 `--` 로 시작하는 작성자 정의 속성.
- **`var()`** — 커스텀 속성 값을 다른 속성 값 자리에 넣는 함수.
- **대체값(fallback)** — 변수가 정의되지 않았을 때 `var()` 가 쓰는 두 번째 인자.
- **`:root`** — 문서 루트 요소(HTML 에서는 `html`)를 고르는 가상 클래스.
- **상속** — 자식 요소가 부모의 계산된 값을 물려받는 것.
- **디자인 토큰** — 디자인 결정을 이름 붙인 값으로 모은 것.
- **테마** — 같은 구조에 입히는 색 · 모양 값의 묶음.
- **동적 스타일링** — 실행 중에 클래스나 JS 로 스타일 값을 바꾸는 일.
- **계산된 값 시점의 무효** — 변수를 끼운 결과가 속성에 맞지 않아 선언이 무효가 되는 상태.
- **`@property`** — 커스텀 속성의 타입 · 상속 · 초기값을 등록하는 at-규칙.
- **명시도** — 같은 요소에 걸린 선언끼리 누가 이기나를 가르는 선택자 점수.

## 더 들어가면

- `var()` 는 미디어 쿼리 조건이나 선택자 안에서는 쓸 수 없다 (확인 필요).
- `@property` 로 `syntax` 를 준 변수는 `transition` · `@keyframes` 로 부드럽게 바뀌게 할 수 있다; 등록하지 않은 변수는 값이 한 번에 바뀐다 (확인 필요).
