## 한눈에 — 쉽게 말하면

**커스텀 속성의 범위는 「집안에서 물려주는 가훈」이다.**
할아버지 대(`:root`)에서 정한 가훈은 온 집안이 물려받는다.
한 집(`.card-a`)이 자기만의 가훈을 정하면 그 집 식구만 따른다.
옆집(`.card-b`)은 같은 이름의 가훈을 전혀 다르게 정해도 서로 섞이지 않는다.
가훈을 물려받지 못한 사람은 「없으면 이렇게 한다」는 예비 규칙(폴백)을 따른다.
CSS 커스텀 속성도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 할아버지 대의 가훈 | `:root` 에 선언한 전역 변수 `--global-radius` |
| 한 집만의 가훈 | `.card-a` 에 선언한 `--accent` |
| 옆집의 같은 이름 가훈 | `.card-b` 에 선언한 `--accent` (다른 값) |
| 물려받기 | CSS 상속 |
| 예비 규칙 | `var(--accent, #94a3b8)` 의 두 번째 인자 |

```text
:root            --global-radius
 └ .scope-demo
    ├ .card-a    --accent = 파랑   → 안의 h4 · .badge · .bar 는 파랑
    ├ .card-b    --accent = 보라   → 안의 h4 · .badge · .bar 는 보라
    └ .outside   (--accent 없음)   → 안의 .badge 는 폴백 회색
```

## 이 주제가 답하려는 질문

1. 커스텀 속성은 어느 요소에서 쓸 수 있고 어느 요소에서는 못 쓰나?
2. 같은 이름의 변수를 컴포넌트마다 다른 값으로 두려면 어떻게 하나?
3. 변수가 없는 자리에서도 스타일이 깨지지 않게 하려면 어떻게 하나?

## 동작 방식

### (1) 선언된 요소와 그 자손에서만 쓸 수 있다

**언제 쓰나** — 변수를 어느 높이에 둘지 정할 때 쓴다.
전역으로 쓸 값은 `:root` 에, 한 컴포넌트에서만 쓸 값은 그 컴포넌트의 루트 요소에 둔다.

```text
입력:  .card-a { --accent: #3b82f6; }

   .card-a        --accent = #3b82f6   (선언된 곳)
    ├ h4          --accent = #3b82f6   (상속)
    ├ .badge      --accent = #3b82f6   (상속)
    └ .bar        --accent = #3b82f6   (상속)
   .card-b        영향 없음            (형제 — 자손이 아니다)

결과:  .card-a 안에서만 var(--accent) 가 파랑이 된다
```

커스텀 속성은 CSS 상속을 따른다.
선언된 요소 자신이 그 값을 갖는다.
그 요소의 자손은 값을 물려받는다.
부모 · 형제 · 형제의 자손에게는 값이 가지 않는다.

> **커스텀 속성** — `--` 로 시작하는 이름을 가진, 작성자가 직접 만든 CSS 속성이다. 흔히 CSS 변수라 부른다.\
> 예: `--accent: #3b82f6;`

> **상속** — 부모 요소의 계산된 값이 자식 요소로 그대로 내려가는 CSS 규칙이다.\
> 예: `.card-a` 의 `--accent` 를 안쪽 `h4` 가 그대로 받는다.

### (2) 같은 이름, 다른 값 — 컴포넌트 스코프

**언제 쓰나** — 같은 스타일 규칙을 여러 컴포넌트가 함께 쓰면서 색만 다르게 하고 싶을 때 쓴다.

```text
입력:  .card-a { --accent: 파랑; }
       .card-b { --accent: 보라; }
       .badge  { background: var(--accent, 회색); }

   .card-a > .badge   → 가장 가까운 조상 .card-a 의 값 → 파랑
   .card-b > .badge   → 가장 가까운 조상 .card-b 의 값 → 보라

결과:  .badge 규칙은 하나인데, 놓인 자리에 따라 색이 달라진다
```

`.badge` 규칙은 하나뿐이다.
`var(--accent)` 는 그 요소가 물려받은 값을 읽는다.
그래서 같은 규칙이 놓인 컴포넌트에 따라 다른 색을 낸다.
조상 여럿이 같은 이름을 선언했으면 가장 가까운 조상의 값이 이긴다 — 가까운 조상의 선언이 위에서 내려온 값을 덮어쓰기 때문이다.

> **스코프** — 어떤 이름이 유효하게 보이는 범위다.\
> 예: `.card-a` 에 선언한 `--accent` 의 스코프는 `.card-a` 와 그 자손이다.

### (3) 폴백 — 변수가 없을 때의 대비

**언제 쓰나** — 컴포넌트 밖처럼 변수가 정의되지 않은 자리에서도 같은 규칙이 쓰일 수 있을 때 쓴다.

```text
입력:  .outside 안의 .badge { background: var(--accent, #94a3b8); }

   .badge   --accent?  → 자신에 없음
   .outside --accent?  → 없음
   .scope-demo, body, :root → 모두 없음

결과:  물려받을 값이 없으므로 두 번째 인자 #94a3b8 (회색)
```

`var()` 의 두 번째 인자가 폴백이다.
폴백은 변수가 정의되지 않았을 때만 쓰인다.
조상 어디에서든(`:root` 포함) 같은 이름이 정의되어 있으면 그 값이 쓰이고 폴백은 무시된다.
폴백이 없으면 변수가 없는 자리의 선언은 의도한 값을 얻지 못한다.

> **폴백** — 원래 값을 얻지 못할 때 대신 쓰는 값이다.\
> 예: `var(--accent, #94a3b8)` 의 `#94a3b8`.

### (4) 선언 자체는 보통 선언처럼 캐스케이드를 탄다

**언제 쓰나** — 한 요소에 같은 변수를 선언하는 규칙이 둘 이상일 때 어느 값이 남는지 따질 때 쓴다.

```text
입력:  .card-a        { --accent: 파랑; }   (0,1,0)
       .card-a.dark   { --accent: 남색; }   (0,2,0)

   한 요소에 두 선언 → 명시도가 높은 쪽이 이긴다
결과:  .card-a.dark 요소의 --accent 는 남색, 그 자손도 남색을 물려받는다
```

`--accent: 값;` 은 `color: 값;` 과 다르지 않은 선언이다.
한 요소에서 경쟁하면 명시도와 순서로 이긴 쪽이 정해진다.
이긴 값이 그 요소의 값이 되고, 그것이 자손에게 상속된다.

> **캐스케이드** — 한 요소에 걸린 여러 선언 가운데 이길 하나를 고르는 CSS 의 규칙이다.\
> 예: 명시도가 같으면 뒤에 쓴 선언이 이긴다.

> **명시도** — 선택자의 구체성을 (id, 클래스·가상 클래스·속성, 타입) 세 칸으로 센 점수다.\
> 예: `:root` 는 (0,1,0), `.card-a h4` 는 (0,1,1).

## 문법 — 형태와 규칙

```html demo
<div class="box"><span class="dot">안</span></div>
<span class="dot">밖</span>
<style>
  .box { --tone: tomato; padding: 8px; border: 2px solid var(--tone); }
  .dot { display: inline-block; padding: 4px 10px; color: white;
         background: var(--tone, gray); }
</style>
```

> **보이는 것** — 상자 안의 「안」 점은 토마토색, 상자 밖의 「밖」 점은 회색 배경이다 (코드에서 읽은 것 — 렌더 실측 아님).

원본의 기본 꼴은 이렇다.

```css
.component { --local-var: value; }
.component .child { property: var(--local-var); }
```

- 이름은 `--` 로 시작한다.
- 선언은 아무 선택자 안에서나 할 수 있다 — 그 선택자에 맞는 요소와 자손이 범위가 된다.
- 전역 변수는 `:root` 에 둔다 (`:root` 는 문서 루트인 `html` 을 가리킨다).
- 컴포넌트 변수는 컴포넌트의 루트 요소에 둔다.
- 읽을 때는 `var(--이름)`, 대비가 필요하면 `var(--이름, 폴백)` 으로 쓴다.
- 선언한 요소 자신에서도 읽을 수 있다 — 원본의 `.card-a` 는 자기 `border` 에 `var(--accent)` 를 쓴다.

| 자리 | 예 | 범위 |
|---|---|---|
| `:root` | `--global-radius: 6px;` | 문서 전체 |
| 컴포넌트 루트 | `.card-a { --accent: …; }` | 그 카드와 자손 |
| `var()` 폴백 | `var(--accent, #94a3b8)` | 변수가 없는 곳에서 대신 쓰임 |

## 어디서 틀리나

### 1. 형제 컴포넌트의 변수를 읽으려 한다

`.card-b` 안에서 `.card-a` 에 선언한 값을 읽을 수 없다.
상속은 위에서 아래로만 흐르고, 형제는 그 길 밖에 있다.
두 컴포넌트가 함께 써야 하는 값이면 공통 조상(또는 `:root`)으로 올린다.

### 2. 「컴포넌트 안에서만」을 완전한 격리로 믿는다

원본 팁은 「루트 요소에 --변수를 정의하면 해당 컴포넌트 내에서만 적용」이라고 한다.
**원본의 주장 → 왜 의심스러운가** — 형제 사이는 격리되지만 자손 쪽으로는 막히지 않는다.
카드 안에 다른 컴포넌트를 넣으면 그 안쪽도 바깥 카드의 `--accent` 를 물려받는다.
안쪽 컴포넌트가 같은 이름을 다시 선언해야 그 값으로 덮인다.

### 3. 폴백이 「항상 안전망」이라고 믿는다

폴백은 변수가 정의되지 않았을 때만 쓰인다.
`:root` 에 누군가 같은 이름을 선언해 두면 컴포넌트 밖의 요소도 그 값을 물려받고, 폴백은 쓰이지 않는다.
전역에 흔한 이름(`--accent` 같은)을 두면 이런 일이 생긴다.

### 4. 폴백 없이 컴포넌트 변수를 바깥 규칙에서 쓴다

원본 팁처럼 `var()` 의 폴백을 쓰면 변수가 없는 자리에서도 안전하게 동작한다.
`.badge` · `.bar` 는 카드 안에도 밖에도 놓일 수 있으므로 폴백을 단다.
반면 `.card-a h4` 처럼 늘 카드 안에서만 매칭되는 규칙은 폴백 없이도 값을 얻는다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 커스텀 속성은 상속되어 자손이 값을 물려받는다 | CSS 명세 (커스텀 속성 명세) |
| `var()` 의 폴백은 변수가 정의되지 않았을 때 쓰인다 | CSS 명세 |
| 한 요소에서 경쟁하는 변수 선언은 캐스케이드로 정해진다 | CSS 명세 |
| 데모에서 보이는 실제 색 · 모양 | 브라우저 렌더링 — 이 문서는 렌더 실측 아님 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 문서 전체가 함께 쓰는 값 (모서리 반경 등) | `:root` 의 전역 변수 | 컴포넌트마다 같은 값 반복 선언 |
| 컴포넌트마다 다른 강조색 | 컴포넌트 루트에 같은 이름 · 다른 값 | `:root` 에 `--accent-a` · `--accent-b` 를 늘어놓기 |
| 안팎 어디에나 놓이는 작은 부품 | `var(--x, 폴백)` | 폴백 없는 `var(--x)` |
| 형제 컴포넌트끼리 값을 나눔 | 공통 조상에 선언 | 한쪽 컴포넌트에 선언하고 다른 쪽에서 읽기 |

## 핵심 문장

1. **커스텀 속성은 상속을 따른다** — 선언된 요소와 그 자손에서만 쓸 수 있다.
2. **컴포넌트 루트에 선언하면 컴포넌트 스코프 변수가 된다** — 같은 이름이라도 형제 컴포넌트끼리는 섞이지 않는다.
3. **`var()` 는 가장 가까운 조상에서 물려받은 값을 읽는다** — 그래서 규칙 하나가 자리마다 다른 값을 낸다.
4. **폴백은 변수가 없을 때만 쓰인다** — 조상 어디에든 정의가 있으면 쓰이지 않는다.
5. **변수 선언도 보통 선언이다** — 한 요소에서는 캐스케이드와 명시도로 이긴 값이 남는다.

## 용어 풀이

- **커스텀 속성** — `--` 로 시작하는 작성자 정의 CSS 속성. CSS 변수.
- **`var()`** — 커스텀 속성의 값을 읽는 함수. 두 번째 인자로 폴백을 받는다.
- **상속** — 부모의 계산된 값이 자식에게 내려가는 규칙.
- **스코프** — 이름이 유효한 범위.
- **전역 변수** — `:root` 에 선언해 문서 전체가 물려받는 변수.
- **컴포넌트 변수 (지역 변수)** — 컴포넌트 루트에 선언해 그 안에서만 쓰는 변수.
- **폴백** — 변수가 없을 때 대신 쓰는 값.
- **`:root`** — 문서 루트 요소(`html`)를 가리키는 가상 클래스. 명시도 (0,1,0).
- **캐스케이드** — 경쟁하는 선언 가운데 이길 하나를 고르는 규칙.
- **명시도** — 선택자의 구체성 점수.

## 더 들어가면

- 변수가 정의되지 않았고 폴백도 없으면, 그 선언은 「계산값 시점에 무효」가 되어 속성이 `unset` 처럼 동작한다 — 상속 속성은 부모 값, 아니면 초기값 (확인 필요).
- 변수가 정의되어 있지만 그 속성에 맞지 않는 값(예: `color` 에 `10px`)이면 폴백도 쓰이지 않고 같은 「무효」 처리가 된다 (확인 필요).
- `@property` 로 등록한 커스텀 속성은 `inherits: false` 로 상속을 끌 수 있다 — 그러면 이 문서의 스코프 규칙이 달라진다 (확인 필요).
- 커스텀 속성 이름은 대소문자를 구분한다 — `--accent` 와 `--Accent` 는 다른 변수다 (확인 필요).
- JS 에서 `element.style.setProperty('--accent', …)` 로 한 요소의 변수만 바꿔 그 아래만 다시 칠하게 할 수 있다 (확인 필요).
