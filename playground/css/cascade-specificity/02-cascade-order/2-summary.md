## 한눈에 — 쉽게 말하면

**캐스케이드는 「동점이면 다음 기준으로 넘어가는 심사」다.**
대회 심사를 떠올려 보자.
먼저 본선 진출 자격(급수)을 보고, 같은 급이면 소속 리그 순위를 보고, 그것도 같으면 점수를 보고, 점수까지 같으면 나중에 연기한 사람이 이긴다.
한 기준에서 승부가 나면 그 뒤의 기준은 보지 않는다.
CSS 도 똑같은 구조다.
한 요소의 한 속성에 선언이 여럿 닿으면 브라우저는 정해진 차례대로 기준을 하나씩 보고, 처음으로 갈리는 기준에서 승자를 정한다.

| 비유 | 실체 |
|---|---|
| 참가자 | 같은 요소 · 같은 속성을 노리는 선언 하나하나 |
| 급수(자격) | 출처와 중요도(브라우저 기본 · 사용자 · 작성자, `!important` 여부) |
| 리그 순위 | `@layer` 순서 |
| 점수 | 명시도 |
| 연기 순서 | 소스 순서(스타일시트에 나온 차례) |
| 우승 | 그 속성에 실제로 쓰이는 값 |

```text
같은 요소 · 같은 속성에 선언이 여럿
        │
        ▼
 [1] 출처와 중요도 ──갈리면──▶ 승자 결정
        │ 같으면
        ▼
 [2] @layer 순서  ──갈리면──▶ 승자 결정
        │ 같으면
        ▼
 [3] 명시도       ──갈리면──▶ 승자 결정
        │ 같으면
        ▼
 [4] 소스 순서    ─────────▶ 나중에 나온 선언이 승자
```

> **캐스케이드(cascade)** — 한 요소의 한 속성에 닿은 여러 선언 가운데 하나를 고르는 CSS 의 규칙 묶음.\
> 예: `.a { color: red }` 와 `.a { color: blue }` 가 둘 다 닿으면 캐스케이드가 하나를 고른다.

## 이 주제가 답하려는 질문

1. 한 요소의 한 속성에 선언이 여럿 닿으면 어느 값이 쓰이나?
2. 판정 기준(출처 · `@layer` · 명시도 · 소스 순서)은 어떤 차례로 적용되나?
3. 어떤 속성에서 진 규칙의 다른 선언은 어떻게 되나?
4. 「같은 명시도면 나중 것이 이긴다」는 말은 어디까지 맞나?

## 동작 방식

### (1) 겨루기는 규칙 단위가 아니라 속성 단위다

**언제 쓰나** — 한 규칙 안에 속성이 여럿 있고, 그중 일부만 다른 규칙과 부딪힐 때.

```text
입력
  .styled { color: red;  padding: 12px; }   ← 규칙 A
  .styled { color: #3b82f6; }               ← 규칙 B

무엇이 일어나나
  color   : A 의 red  vs B 의 #3b82f6  → 겨룸
  padding : A 의 12px 하나뿐          → 겨룰 상대 없음 (이 두 규칙끼리는)

결과
  color   = #3b82f6
  padding = 12px  (다른 규칙이 padding 을 건드리지 않는다면)
```

- 브라우저는 속성마다 따로 후보를 모은다.
- `color` 에는 후보가 둘이라 캐스케이드가 판정한다.
- `padding` 은 이 두 규칙 사이에서는 후보가 하나뿐이라 그대로 남는다.
- 그래서 규칙 A 가 `color` 에서 졌다고 A 전체가 버려지지는 않는다.

### (2) 소스 순서 — 마지막 동점 처리

**언제 쓰나** — 출처 · 중요도 · `@layer` · 명시도가 모두 같은 두 선언이 부딪힐 때.

```text
입력 (같은 <style> 안, 위에서 아래로)
  .multi { color: gray; }                         ← 먼저
  .multi { color: #8b5cf6; font-weight: 700; }    ← 나중

무엇이 일어나나
  [1] 출처·중요도 : 둘 다 작성자 일반      → 같음
  [2] @layer      : 둘 다 레이어 없음       → 같음
  [3] 명시도      : 둘 다 0,1,0             → 같음
  [4] 소스 순서   : 두 번째가 나중          → 두 번째 승

결과
  color = #8b5cf6, font-weight = 700
```

- 앞의 세 기준이 모두 동점이라 마지막 기준까지 내려온다.
- 소스 순서에서는 스타일시트에 **나중에 나온** 선언이 이긴다.
- `font-weight` 는 겨룰 상대가 없어 그대로 적용된다.

> **소스 순서(order of appearance)** — 선언이 스타일시트에 나타난 차례.\
> 예: 같은 `<style>` 안에서 아래쪽 규칙이 위쪽 규칙보다 「나중」이다.

### (3) 명시도가 다르면 소스 순서는 보지 않는다

**언제 쓰나** — 선택자가 서로 다른 두 규칙이 같은 요소 · 같은 속성을 노릴 때.

```text
입력 (<div class="cascade-demo"><p class="styled">…</p></div>)
  .styled          { padding: 12px; }    ← 명시도 0,1,0  (먼저 나옴)
  .cascade-demo p  { padding: 16px; }    ← 명시도 0,1,1  (나중 나옴)

무엇이 일어나나
  [3] 명시도 : 0,1,1 > 0,1,0  → 여기서 승부가 남
  [4] 소스 순서 : 보지 않음

결과
  padding = 16px  (두 규칙의 위아래를 바꿔도 같다)
```

- 명시도는 왼쪽 자리부터 비교한다.
- 클래스 개수(가운데 자리)가 같고, 요소 개수(오른쪽 자리)에서 `.cascade-demo p` 가 하나 더 많다.
- 명시도에서 갈렸으므로 소스 순서는 판정에 쓰이지 않는다.
- 같은 이치로 `.cascade-demo p:last-child`(0,2,1)는 `.cascade-demo p`(0,1,1)를 이긴다 — 마지막 `p` 의 `margin-bottom` 이 `8px` 이 아니라 `0` 이 된다.

> **명시도(specificity)** — 선택자가 얼마나 구체적인지를 (ID 수, 클래스·속성·가상 클래스 수, 요소·가상 요소 수) 세 자리로 센 값.\
> 예: `.cascade-demo p:last-child` 는 클래스 1 + 가상 클래스 1, 요소 1 이라 0,2,1 이다.

### (4) 출처와 중요도 — 가장 먼저 보는 기준

**언제 쓰나** — 선언이 서로 다른 곳(브라우저 기본 · 사용자 · 작성자)에서 오거나, 한쪽에 `!important` 가 붙었을 때.

```text
입력
  #title.big h1   { color: black; }            ← 작성자 일반, 명시도 높음
  h1              { color: red !important; }   ← 작성자 !important, 명시도 낮음

무엇이 일어나나
  [1] 출처·중요도 : !important 쪽이 위  → 여기서 승부가 남
  [3] 명시도      : 보지 않음

결과
  color = red
```

- 출처와 중요도는 첫 번째 기준이라, 여기서 갈리면 명시도가 아무리 높아도 소용없다.
- 원본 팁이 적은 캐스케이드 전체 순서는 아래와 같다(위가 더 셈).

| 차례 | 원본 팁의 단계 | 단계 안의 순서(원본 팁 그대로) |
|---|---|---|
| 1 | Transitions(전환 중인 값) | — |
| 2 | `!important` 선언 | UA > user > author > @layer |
| 3 | Animations(애니메이션 중인 값) | — |
| 4 | 일반 선언 | author @layer > author > user > UA |

- 출처가 같으면 명시도로, 그것도 같으면 소스 순서로 넘어간다(원본 팁).
- `!important` 쪽은 출처 순서가 일반 선언과 **거꾸로** 놓인다 — 일반 선언에서는 작성자가 가장 세지만, `!important` 에서는 브라우저 기본(UA)이 가장 세다.
- 표의 `@layer` 자리는 원본 팁 그대로 옮긴 것이고, 의심스러운 점은 「어디서 틀리나 6」에 적었다.

> **출처(origin)** — 선언이 어디서 왔는가: 브라우저 기본 스타일시트(UA), 사용자가 지정한 스타일(user), 페이지 작성자의 CSS(author).\
> 예: 아무 CSS 없이도 `<h1>` 이 굵고 큰 것은 UA 스타일시트 때문이다.

> **`!important`** — 선언 끝에 붙여 그 선언을 중요도가 높은 쪽 단계로 올리는 표시.\
> 예: `color: red !important;`

### (5) `@layer` — 명시도보다 먼저 본다

**언제 쓰나** — 작성자 CSS 를 레이어로 나눠, 명시도와 상관없이 우선순위를 정하고 싶을 때.

```text
입력
  @layer base, theme;
  @layer base  { .btn.primary { color: gray; } }   ← 명시도 0,2,0
  @layer theme { .btn         { color: blue; } }   ← 명시도 0,1,0

무엇이 일어나나
  [1] 출처·중요도 : 둘 다 작성자 일반 → 같음
  [2] @layer      : theme 이 base 보다 나중에 선언된 레이어 → theme 승

결과
  color = blue  (명시도는 base 쪽이 높지만 판정에 쓰이지 않는다)
```

- 원본 설명의 차례대로 `@layer` 순서는 명시도보다 앞이다.
- 그래서 레이어가 다르면 명시도 경쟁이 시작되기도 전에 승부가 난다.
- 같은 레이어 안에서는 다시 명시도 → 소스 순서로 내려간다.

> **`@layer`** — 작성자 CSS 를 이름 붙인 층으로 나눠 층끼리의 우선순위를 정하는 at-규칙.\
> 예: `@layer reset, base, theme;` 는 층의 차례를 미리 선언한다.

## 문법 — 형태와 규칙

원본의 구문은 `출처 > @layer > 명시도 > 소스 순서` 다.
왼쪽 기준이 먼저 적용되고, 왼쪽에서 동점일 때만 오른쪽 기준으로 넘어간다는 뜻이다.

```html demo
<div class="box">
  <p class="note">첫 단락</p>
  <p class="note">마지막 단락</p>
</div>
<style>
  .note { color: red; padding: 12px; }       /* 0,1,0 · 먼저 */
  .note { color: #3b82f6; }                  /* 0,1,0 · 나중 → color 승 */
  .box p { padding: 16px; margin-bottom: 8px; }  /* 0,1,1 → padding 승 */
  .box p:last-child { margin-bottom: 0; }    /* 0,2,1 → 마지막 p 의 margin 승 */
</style>
```

> **보이는 것** — 두 단락 모두 파란 글자에 안쪽 여백 16px, 첫 단락 아래에만 8px 바깥 여백이 있다 (코드에서 읽은 것 — 렌더 실측 아님)

- 판정은 **요소마다, 속성마다** 따로 한다.
- 같은 출처 · 같은 중요도 · 같은 레이어 · 같은 명시도면 **나중에 나온 선언**이 이긴다.
- 명시도는 자리별로 왼쪽부터 비교한다 — 앞자리에서 크면 뒷자리 개수는 보지 않는다.
- `!important` 는 명시도를 올리는 장치가 아니라, 첫 번째 기준(중요도)을 바꾸는 장치다.
- 겨룰 상대가 없는 선언은 판정 없이 그대로 쓰인다.

## 어디서 틀리나

### 1. 「나중 것이 이긴다」를 언제나 맞는 말로 여긴다

원본 설명은 「**같은 명시도라면** 나중에 선언된 스타일이 적용된다」고 한정한다.
원본 팁도 「출처가 같으면 명시도, 그것도 같으면 소스 순서」라고 적는다.
소스 순서는 맨 마지막 동점 처리일 뿐이라, 명시도 · 레이어 · 출처 · 중요도 중 하나라도 다르면 나중에 썼어도 진다.

### 2. 진 규칙 전체가 무시된다고 생각한다

`.styled` 첫 규칙은 `color` 에서 졌지만 `padding` 선언까지 버려지는 것은 아니다.
판정은 속성 단위라서, 각 선언은 자기 속성의 후보들 사이에서만 겨룬다.

### 3. 원본 주석 「padding 12px (충돌 없음 → 적용됨)」

- 원본의 주장 → `.styled` 첫 규칙의 `padding: 12px` 는 충돌이 없어 적용된다.
- 왜 의심스러운가 → 같은 문서에 `.cascade-demo p { padding: 16px; }` 가 있고, `p.styled` 는 `.cascade-demo` 안에 있으니 이 규칙도 닿는다.
- 명시도는 `.cascade-demo p` 가 0,1,1, `.styled` 가 0,1,0 이라 `.cascade-demo p` 가 이긴다.
- 그래서 코드를 읽으면 `p.styled` 의 안쪽 여백은 16px 이 된다 — `.styled` 끼리는 충돌이 없지만, 다른 규칙과는 충돌한다.
- `.cascade-demo p` 가 소스에서 나중에 나오지만, 승부는 명시도에서 이미 났으므로 순서는 상관없다.

### 4. 원본 데모의 `.multi` 가 「출처 비교」를 보여 준다고 여긴다

- 원본의 주장 → 주석은 「브라우저 기본 < 작성자 일반 < 작성자 !important」를 내걸고, 단락 글은 「여러 스타일시트에서 온 스타일」이다.
- 왜 의심스러운가 → 두 `.multi` 규칙은 같은 `<style>` 안에 있고 `!important` 도 없다.
- 둘 다 작성자 일반 · 명시도 0,1,0 이라, 실제로 보여 주는 것은 `.styled` 와 같은 **소스 순서** 비교다.
- 출처나 중요도 단계를 보려면 `!important` 를 붙인 선언이나 브라우저 기본 스타일과 겨루는 예가 따로 있어야 한다.

### 5. 명시도 표기 `0,0,1,0` 과 `0,1,0` 을 다른 값으로 읽는다

원본 주석은 같은 `.styled` 를 한 곳에서는 `0,0,1,0`, 다른 곳에서는 `0,1,0` 으로 적는다.
네 자리 표기는 맨 앞에 인라인 `style` 속성 자리를 둔 것이고, 세 자리 표기는 그 자리를 뺀 것이다.
클래스 하나라는 같은 값을 두 방식으로 쓴 것뿐이다.

### 6. 원본 팁의 `@layer` 자리

- 원본의 주장 → `!important` 단계에서 「author > @layer」, 일반 단계에서 「author @layer > author」.
- 왜 의심스러운가 → 이 표기대로라면 일반 선언에서는 레이어 안 선언이 레이어 밖 작성자 선언보다 세다.
- 레이어 밖 선언이 마지막 레이어처럼 취급되어 일반 선언에서는 오히려 레이어 밖이 더 세고, `!important` 에서는 그 관계가 뒤집힌다는 설명이 흔하다 — 원본 팁과 정반대다 (확인 필요).
- 이 문서는 원본 팁을 고치지 않고 그대로 옮겼다. 레이어 안팎의 정확한 순서는 명세에서 확인해야 한다 (확인 필요).

### 7. 명시도를 한 숫자처럼 더한다

0,1,0 은 「10」이 아니다.
클래스 하나(0,1,0)는 요소 선택자를 몇 개 쌓아도(0,0,n) 진다.
왼쪽 자리에서 크면 그 자리에서 끝난다.

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 출처·중요도 → `@layer` → 명시도 → 소스 순서의 판정 차례 | CSS 명세(Cascade 모듈) |
| 같은 조건이면 나중에 나온 선언이 이긴다 | CSS 명세 |
| 명시도를 자리별로 센다 | CSS 명세(Selectors 모듈) |
| 브라우저 기본 스타일시트(UA)에 무엇이 들어 있나(예: `p` 의 기본 바깥 여백) | 브라우저마다 다르다 — 명세는 권장 스타일만 제시한다 (확인 필요) |
| `@layer` 를 지원하는가 | 브라우저 구현 · 버전 — 지원 범위는 (확인 필요) |
| 진 선언에 줄을 그어 보여 주는 화면 | 브라우저 개발자 도구의 기능 — CSS 와 무관 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 같은 컴포넌트를 나중에 조금 덮어쓰기 | 같은 명시도의 규칙을 뒤에 둔다(소스 순서) | 일단 `!important` |
| 특정 자식 하나만 예외 처리 | 명시도를 한 단계 올린 선택자(`:last-child` 등) | 순서만 믿고 아래에 쓰기 — 명시도가 낮으면 진다 |
| 라이브러리 CSS 와 내 CSS 의 서열 정리 | `@layer` 로 층 나누기 | 선택자를 길게 늘여 명시도 경쟁 |
| 사용자·접근성 설정을 꼭 지켜야 할 값 | 출처·중요도 단계에 맡긴다 | 작성자 `!important` 로 덮기 |
| 원인 모를 스타일 충돌 디버깅 | 판정 차례를 위에서부터 하나씩 확인 | 규칙을 아래로 옮겨 보며 운에 맡기기 |

## 핵심 문장

1. **캐스케이드는 출처·중요도 → `@layer` → 명시도 → 소스 순서 차례로 보고, 처음 갈리는 기준에서 승자를 정한다.**
2. **판정은 속성 단위다** — 한 속성에서 진 규칙의 다른 선언은 살아남는다.
3. **소스 순서는 마지막 동점 처리다** — 앞 기준이 하나라도 다르면 나중에 썼어도 진다.
4. **`!important` 는 첫 기준을 바꾼다** — 명시도가 아무리 높은 일반 선언도 이긴다.
5. **`!important` 단계에서는 출처 순서가 거꾸로다** — 일반은 작성자가, 중요 선언은 브라우저 기본이 가장 세다(원본 팁).

## 용어 풀이

- **캐스케이드** — 한 요소 · 한 속성에 닿은 여러 선언 중 하나를 고르는 규칙 묶음.
- **선언** — `속성: 값` 한 쌍.
- **규칙** — 선택자와 `{ }` 안의 선언 묶음.
- **출처** — 선언이 온 곳: 브라우저 기본(UA) · 사용자(user) · 작성자(author).
- **UA 스타일시트** — 브라우저가 기본으로 깔아 두는 스타일.
- **중요도** — 선언에 `!important` 가 붙었는지 여부.
- **`@layer`** — 작성자 CSS 를 층으로 나눠 층 사이 우선순위를 정하는 at-규칙.
- **명시도** — 선택자의 구체성을 (ID, 클래스·속성·가상 클래스, 요소·가상 요소) 개수로 센 값.
- **소스 순서** — 선언이 스타일시트에 나온 차례.
- **가상 클래스** — `:last-child` 처럼 상태나 위치로 요소를 고르는 선택자 조각.
- **자손 결합자** — 선택자 사이의 공백. `.cascade-demo p` 는 `.cascade-demo` 안의 모든 `p`.
- **Transitions / Animations** — 전환 · 애니메이션이 진행 중일 때 만드는 값. 원본 팁의 캐스케이드 순서에 각각 한 단계로 들어간다.

## 더 들어가면

- 인라인 `style` 속성으로 준 선언은 선택자 명시도와 따로 취급되어 일반 선택자 규칙보다 세다는 설명이 일반적이다 (확인 필요).
- 최근 명세에는 출처·중요도와 `@layer` 사이에 Shadow DOM 의 문맥(context) 단계와 「요소에 직접 붙은 스타일」 단계가 더 있다고 한다 (확인 필요).
- `:where()` 안의 선택자는 명시도를 0 으로 친다고 알려져 있다 — 명시도 경쟁을 피하는 데 쓴다 (확인 필요).
- `revert` · `revert-layer` 키워드는 캐스케이드의 앞 단계 값으로 되돌린다 (확인 필요).
- 상속된 값은 그 요소에 직접 닿은 선언이 하나도 없을 때만 쓰여서, 명시도가 아무리 높은 조상 규칙도 자식의 직접 선언을 이기지 못한다 (확인 필요).
