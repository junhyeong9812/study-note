## 한눈에 — 쉽게 말하면

**`orphans` 는 「버스 막차에 태울 최소 인원」이다.**
한 무리(단락)가 버스(페이지 · 열)에 나눠 타야 할 때, 앞 버스 맨 뒷자리에 한두 명만 덜렁 태워 보내지 않는다.
최소 인원보다 적게 탈 거라면 그 무리는 앞 버스에 타지 않고 다음 버스부터 탄다.
CSS 의 `orphans` 도 똑같은 구조다.
단락이 페이지나 열의 끝에서 잘릴 때, 잘리기 전 아래쪽에 남는 줄이 정한 수보다 적으면 그 자리에서 자르지 않는다.

| 비유 | 실체 |
|---|---|
| 무리 | 하나의 단락(블록) |
| 버스 | 페이지 또는 열(column) |
| 앞 버스 맨 뒷자리에 탄 사람 | 분절 직전, 앞 조각 아래쪽에 남은 단락의 첫 줄들 |
| 최소 인원 | `orphans` 의 정수 값 |

```text
  열 1              열 2
 ┌──────────┐     ┌──────────┐
 │ ...      │     │ 줄 3     │
 │ ...      │     │ 줄 4     │
 │ 줄 1  ◀─┐│     │ 줄 5     │
 │ 줄 2  ◀─┘│     │          │
 └──────────┘     └──────────┘
   아래쪽에 남은 줄 = 2
   orphans: 3 이면 → 이 자리에서 자르지 않는다
```

## 이 주제가 답하려는 질문

1. 단락이 페이지 · 열 끝에서 잘릴 때, 앞 조각 아래쪽에 남는 줄 수를 어떻게 제한하나?
2. 그 제한을 못 채우면 브라우저는 단락을 어디서 자르나?
3. 이 속성은 어떤 상황에서만 효과가 보이나?

## 동작 방식

### (1) 분절과 「앞 조각 아래쪽에 남은 줄」

**언제 쓰나** — 다단(`column-count`) 배치나 인쇄 페이지에서 단락이 둘로 잘리는 일이 생길 때 쓴다.

```text
입력: .multicol { column-count: 2; height: 100px; }
      긴 단락 하나

무엇이 일어나나:
  열 1 이 가득 참 → 단락을 잘라 나머지를 열 2 로 보냄 (= 분절)

결과:
  열 1 아래쪽: 단락의 앞부분 N 줄
  열 2 위쪽 : 단락의 나머지
```

- 내용이 한 페이지나 한 열에 다 들어가지 않으면 브라우저는 내용을 잘라 다음 페이지 · 열로 넘긴다.
- 이렇게 자르는 일을 분절이라 한다.
- `orphans` 가 세는 것은 잘린 자리 **앞쪽 조각 하단**에 남는 그 단락의 줄 수다.

> **분절(fragmentation)** — 내용을 페이지 · 열 같은 조각으로 나누는 일.\
> 예: 긴 단락이 열 1 끝에서 잘려 열 2 로 이어지는 것.

> **고아 줄(orphan)** — 타이포그래피에서 페이지 · 열 하단에 홀로 남은 단락의 첫 줄.\
> 예: 열 1 맨 아래에 단락 첫 줄 하나만 있고 나머지는 열 2 에 있는 모양.

### (2) 최소 줄 수를 못 채우면 그 자리를 피한다

**언제 쓰나** — 열 끝에 단락 첫 부분이 한두 줄만 걸려 읽기 어려워지는 것을 막고 싶을 때.

```text
입력: orphans: 3
      열 1 에 이 단락 줄이 들어갈 자리 = 2 줄 (단락 전체는 5 줄)

무엇이 일어나나:
  여기서 자르면 앞 조각에 2 줄 → 3 보다 적음 → 이 분절 위치는 허용 안 됨
  → 단락 시작 전에서 자름

결과:
  열 1: 이 단락 줄 0 개 (아래쪽이 비어 보임)
  열 2: 단락 5 줄이 위에서부터
```

- 브라우저는 잘릴 자리를 고를 때 「앞 조각 하단에 남는 줄 ≥ `orphans`」를 지켜야 한다.
- 지킬 수 없는 자리는 피하고, 더 앞의 자리(단락 시작 전 등)에서 자른다.
- 값을 키울수록 열 끝에 남는 단락 조각이 두꺼워지고, 그 대신 열 하단에 빈 공간이 생길 수 있다.

### (3) 분절이 없으면 아무 일도 없다

**언제 쓰나** — 효과를 확인하려 할 때 이 점을 먼저 떠올린다.

```text
입력: 일반 블록 (다단 아님, 화면 스크롤)
      p { orphans: 5; }

무엇이 일어나나:
  내용이 잘리지 않음 → 셀 「앞 조각」이 없음

결과: 변화 없음
```

- 일반 화면은 스크롤로 내려갈 뿐 내용을 자르지 않는다.
- 그래서 `orphans` 는 다단 배치나 인쇄(페이지 나누기)에서만 효과가 드러난다.
- 원본 팁이 「인쇄 미리보기에서 효과를 확인할 수 있다」고 권하는 까닭이 이것이다.
- 원본 예제가 `height: 100px` 로 높이를 고정한 것도 열에 들어갈 양을 묶어 분절을 일으키려는 것이다(원본 주석: 「고정 높이로 분할 유발」).

### (4) 상속된다

**언제 쓰나** — 여러 단락에 한꺼번에 적용하고 싶을 때.

- 원본 재료에 따르면 `orphans` 는 상속된다.
- 그래서 원본 예제처럼 바깥 `.multicol` 에만 `orphans: 3` 을 주어도 안쪽 `p` 가 그 값을 물려받는다.
- 줄은 `p` 안에 있으므로, 실제로 줄을 세는 단락이 값을 물려받는 셈이다.

> **상속** — 부모에 준 속성 값이 따로 지정하지 않은 자식에게 그대로 넘어가는 것.\
> 예: `.multicol { orphans: 3 }` 이면 그 안의 `p` 도 `orphans` 가 3 이다.

## 문법 — 형태와 규칙

```html demo
<div class="cols">
  <p>첫 단락이다. 열을 채울 만큼 문장을 길게 이어 쓴다. 문장이 이어지고 또 이어진다.</p>
  <p>둘째 단락이다. 열 끝에서 잘릴 수 있도록 길게 쓴다. 문장이 이어지고 또 이어지고 또 이어진다.</p>
</div>
<style>
  .cols { column-count: 2; height: 120px; orphans: 3; }
  .cols p { margin: 0 0 8px; line-height: 1.6; }
</style>
```

> **보이는 것** — 두 열로 글이 흐르고, 어느 단락이 열 1 끝에서 잘린다면 열 1 하단에 그 단락이 3줄 이상 남는 자리에서만 잘린다 (코드에서 읽은 것 — 렌더 실측 아님)

| 값 | 뜻 |
|---|---|
| `<integer>` | 양의 정수. 분절 전 블록 하단에 남겨야 할 최소 줄 수 |
| (기본값) `2` | 아무것도 주지 않으면 하단에 최소 2줄 |

- 꼴은 `orphans: <integer>` 하나뿐이다.
- 값은 **양의 정수**다 — `0` 이나 음수, 소수, 단위가 붙은 값은 올바른 값이 아니다.
- 올바르지 않은 값을 주면 그 선언은 무시되고, 상속값(없으면 기본값 `2`)이 쓰인다.
- 기본값은 `2`, 상속된다.
- 애니메이션할 수 없다(원본 재료) — `transition` 을 걸어도 중간 값을 거치지 않는다.
- 값은 「줄 수」다 — px 같은 길이가 아니다.

## 어디서 틀리나

### 1. 화면에서 아무 변화가 없다고 고장으로 여긴다

- 분절이 없으면 셀 앞 조각이 없다(동작 방식 (3)).
- 다단 배치를 만들거나 인쇄 미리보기로 확인해야 한다 — 원본 팁도 인쇄 미리보기를 권한다.

### 2. 예제에서 차이가 안 보인다

- 단락이 짧거나 열 하나에 들어가는 줄이 이미 `orphans` 이상이면, 어느 자리에서 잘라도 조건이 채워진다.
- 이때는 `orphans` 를 바꿔도 결과가 같다.
- 차이를 보려면 열 끝에 단락 첫 줄이 1~2줄만 걸리는 상황을 만들어야 한다 (원본에 근거 없음 — 추론).

### 3. `orphans` 를 「단락 첫 줄」이 아니라 아무 줄의 개수로 착각한다

- 세는 것은 잘린 자리 **앞**, 즉 앞 조각 **하단**에 남는 그 단락의 줄이다.
- 다음 조각 상단으로 넘어간 줄의 수는 이 속성이 다루지 않는다.

### 4. 길이 단위를 붙인다

- `orphans: 3px` 는 틀린 값이다. 값은 정수 하나다.

### 5. 0 으로 「제한 없음」을 만들려 한다

- 값은 양의 정수라 `0` 은 올바른 값이 아니다. 가장 느슨한 값은 `1` 이다.

### 6. 값을 크게 주면 빈 공간이 생긴다

- 조건을 못 채우는 자리를 피하다 보니 단락 전체가 다음 열로 넘어가고, 앞 열 하단이 비어 보일 수 있다(동작 방식 (2)).

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 신문 · 잡지 같은 다단 본문 | `column-count` + `orphans` | 아무 설정 없이 기본값만 믿기(기본값 2 로 충분하면 괜찮다) |
| 인쇄용 스타일(문서 · 보고서) | `orphans` 로 페이지 하단 조각 다듬기 | 길이 단위 값 |
| 분절 없는 일반 화면 블록 | (필요 없음) | `orphans` — 효과가 없다 |
| 짧은 단락이 많은 목록 | 기본값 | 큰 값 — 빈 공간만 늘어난다 |

## 핵심 문장

1. **`orphans` 는 분절 직전 앞 조각 하단에 남길 단락의 최소 줄 수다.**
2. **조건을 못 채우는 분절 자리는 피하고 더 앞에서 자른다** — 그래서 앞 열이 비어 보일 수 있다.
3. **분절(다단 · 인쇄)이 없으면 효과가 없다.**
4. **값은 양의 정수, 기본값 2, 상속되고, 애니메이션되지 않는다.**

## 용어 풀이

- **분절(fragmentation)** — 내용을 페이지 · 열 같은 조각으로 나누는 일.
- **분절 위치** — 내용이 잘리는 자리.
- **고아 줄(orphan)** — 페이지 · 열 하단에 홀로 남은 단락의 첫 줄.
- **다단(multi-column)** — `column-count` 등으로 내용을 여러 열에 흘려 넣는 배치.
- **상속** — 부모의 속성 값이 지정 없는 자식에게 넘어가는 것.
- **기본값(initial value)** — 아무 값도 정하지 않았을 때 쓰이는 값. `orphans` 는 `2`.
- **`column-count`** — 내용을 몇 개의 열로 나눌지 정하는 속성.
- **`<integer>`** — CSS 의 정수 값 자료형.

## 더 들어가면

- `orphans` 의 짝으로 `widows` 가 있다 — 분절 **뒤** 다음 조각 상단에 남길 최소 줄 수를 정한다 (확인 필요).
- 두 속성은 CSS Fragmentation 명세에서 정의된다 (확인 필요).
- 조건을 지킬 분절 위치가 하나도 없을 때 브라우저가 제한을 완화하고 어쩔 수 없이 자를 수 있다 (확인 필요).
- 일부 브라우저는 `orphans` 를 지원하지 않거나 다단에서는 적용하지 않는 것으로 알려져 있다 — 구체적인 지원 범위는 (확인 필요).
- 타이포그래피 전통에 따라 orphan 과 widow 의 뜻을 서로 반대로 쓰는 경우도 있다 (확인 필요).
- 인쇄에서는 `break-inside: avoid` 처럼 블록 전체가 잘리지 않게 하는 속성과 함께 쓰기도 한다 (확인 필요).
