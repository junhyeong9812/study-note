## 한눈에 — 쉽게 말하면

**`column-width` 는 「신문 편집자가 정한 단 너비의 기준」이다.**
편집자는 「한 단은 대략 이 정도 폭이면 읽기 좋다」는 기준을 정한다.
종이가 넓으면 단을 더 늘리고, 단을 다 놓고 남는 폭은 단마다 조금씩 나눠 준다.
종이가 기준 폭보다 좁으면 단 하나에 글을 몰아넣고, 그 단은 기준보다 좁아진다.
CSS 다단 레이아웃의 `column-width` 도 똑같은 구조다.

> **다단 레이아웃** — 한 상자 안의 글을 신문처럼 여러 세로 단(열)으로 나눠 흘려 보내는 배치.\
> 예: 긴 문단이 왼쪽 단 끝까지 차면 오른쪽 단 맨 위로 이어진다.

| 비유 | 실체 |
|---|---|
| 신문 종이의 폭 | 다단 컨테이너(`.multicol`)의 안쪽 폭 |
| 편집자가 정한 단 너비 기준 | `column-width` 값 (예: `150px`) |
| 단과 단 사이의 흰 띠 | `column-gap` |
| 단을 몇 개 둘지 | 브라우저가 폭을 보고 정하는 열 수 |

```text
좁은 종이                 넓은 종이
┌──────────┐            ┌──────────┬──────────┬──────────┐
│ 글 글 글 │            │ 글 글 글 │ 글 글 글 │ 글 글 글 │
│ 글 글 글 │            │ 글 글 글 │ 글 글 글 │ 글 글    │
│ 글 글 글 │            └──────────┴──────────┴──────────┘
│ 글 글    │             단이 늘어난다 · 단 폭은 기준 이상
└──────────┘
 단 하나 · 기준보다 좁을 수 있다
```

## 이 주제가 답하려는 질문

1. 열 수를 직접 적지 않았는데, 브라우저는 열을 몇 개로 나누나?
2. `column-width: 150px` 이면 열은 정말 150px 인가?
3. 컨테이너 폭이 바뀌면 열은 어떻게 달라지나?
4. 값이 `auto` 이면 열 너비는 누가 정하나?

## 동작 방식

### (1) 기준 너비로 열 수가 정해진다

**언제 쓰나** — 열 수보다 「한 열이 대략 이만큼은 돼야 읽기 좋다」는 폭이 더 중요할 때 쓴다.

```text
.multicol { column-width: 150px; column-gap: 20px; }

  컨테이너 안쪽 폭을 잰다
        │
        ▼
  「150px 열 + 20px 간격」이 몇 번 들어가나 본다
        │
        ▼
  들어가는 만큼 열 수를 정한다
        │
        ▼
  남는 폭을 열들에 나눠 준다 → 각 열은 150px 보다 넓어질 수 있다
```

- 브라우저는 먼저 컨테이너 안쪽 폭을 잰다.
- 그 폭에 기준 너비의 열이 간격과 함께 몇 개 들어가는지 본다.
- 그 개수가 열 수가 된다.
- 열을 놓고 남는 폭은 버리지 않고 열마다 나눠 주므로, 실제 열은 기준보다 넓어질 수 있다.

> **이상적 너비** — 꼭 그 값이 된다는 약속이 아니라, 열 수를 정할 때 브라우저가 기준으로 삼는 목표 폭.\
> 예: `column-width: 150px` 이어도 실제 열은 170px 일 수 있다.

### (2) 공간이 모자라면 열이 기준보다 좁아진다

**언제 쓰나** — 좁은 화면(휴대폰 등)에서 다단 상자가 어떻게 보일지 짐작할 때.

```text
컨테이너 안쪽 폭 < 150px
        │
        ▼
  150px 열이 하나도 다 들어가지 않는다
        │
        ▼
  열은 하나 · 그 열은 컨테이너 폭만큼만 → 150px 보다 좁다
```

- 기준 너비보다 컨테이너가 좁으면 기준대로 열을 놓을 수 없다.
- 그래도 글은 보여야 하므로 열 하나에 모두 담는다.
- 그 열은 컨테이너 폭을 넘지 않으니 기준보다 좁아진다.
- 그래서 `column-width` 는 「최소 너비」가 아니다(원본 팁).

### (3) 폭이 바뀌면 열 수가 저절로 바뀐다

**언제 쓰나** — 미디어 쿼리 없이 창 폭에 맞춰 1열 · 2열 · 3열로 바뀌는 글 상자를 만들 때.

```text
창을 넓힌다 → 컨테이너 폭이 커진다 → 들어가는 열 수가 늘어난다
창을 줄인다 → 컨테이너 폭이 작아진다 → 열 수가 줄어든다
```

- 열 수는 고정값이 아니라 그때그때의 폭으로 다시 정해진다.
- 정답 코드의 주석도 「가용 공간에 따라 열 수 자동 결정」이라고 적는다.

### (4) `auto` 면 이 속성은 물러난다

**언제 쓰나** — 열 수를 `column-count` 같은 다른 속성으로 정하고 싶을 때.

- 기본값 `auto` 는 「열 너비를 이 속성으로 정하지 않는다」는 뜻이다.
- 그때 열 너비는 다른 속성(열 수를 정하는 `column-count` 등)과 컨테이너 폭으로 정해진다.

## 문법 — 형태와 규칙

```css
.article {
  column-width: 150px;   /* 이상적 열 너비 */
  column-gap: 20px;      /* 열 사이 간격 */
}
.article p {
  margin: 0;             /* 문단 기본 여백이 열 머리를 밀어내지 않게 */
}
```

```html demo
<div style="column-width:150px; column-gap:20px; background:#f1f5f9; padding:16px;">
  <p style="margin:0">짧은 문단 하나를 여러 열로 흘려 보낸다. 창 폭을 바꾸면 열의 개수가 바뀐다. 각 열은 150px 근처의 폭을 가진다.</p>
</div>
```

> **보이는 것** — 회색 상자 안의 글이 폭에 따라 한 열 또는 여러 열로 나뉘어 흐른다 (코드에서 읽은 것 — 렌더 실측 아님)

| 값 | 뜻 |
|---|---|
| `auto` | 기본값. 열 너비를 다른 속성(열 수 등)이 정한다 |
| `<length>` | 이상적 열 너비. 양수만 된다. 실제 너비는 공간에 따라 달라진다 |

- 형태: `column-width: auto | <length>`.
- 기본값은 `auto` 다.
- 상속되지 않는다 — 부모에 줘도 자식 요소가 저절로 다단이 되지 않는다.

> **상속** — 부모 요소에 준 속성값이 자식 요소에 저절로 넘어가는 것.\
> 예: `color` 는 상속되지만 `column-width` 는 상속되지 않는다.

- 애니메이션 가능한 속성이다(원본 데이터).
- 길이 값은 양수만 된다 — 0 이하나 퍼센트 같은 길이가 아닌 값은 허용 값이 아니다.
- CSS 는 허용되지 않는 값의 선언을 버리고, 그 속성은 이전 값(여기서는 기본값 `auto`)으로 남는다.
- 다단이 되는 것은 이 속성을 준 컨테이너의 내용이다 — 컨테이너 자신이 쪼개지는 게 아니다.

## 어디서 틀리나

### 1. 「150px 이면 열이 150px 이다」라고 믿는다

설정값은 최소 너비도 고정 너비도 아니고 **이상적 너비**다(원본 팁).
공간이 부족하면 더 좁아지고, 남으면 더 넓어질 수 있다.
픽셀 단위로 맞춘 디자인(예: 열 폭에 딱 맞춘 이미지)은 이 속성으로 보장할 수 없다.

### 2. 「최소 너비」로 쓰려 한다

좁은 화면에서는 열 하나가 기준보다 좁아진다.
「적어도 이만큼」을 지켜야 하는 곳에 쓰면 기대가 깨진다.

### 3. 문단 여백을 그대로 둔다

`p` 의 기본 위아래 여백이 첫 열 머리에 빈 띠를 만든다.
정답 코드가 `p { margin: 0; }` 을 두는 까닭이다.

### 4. 음수 · 0 을 준다

길이는 양수만 된다.
허용되지 않는 값이면 선언이 무시되고 `auto` 그대로 남는다.

### 5. 부모에 주고 손자까지 다단이 되길 기대한다

상속되지 않는 속성이다.
다단으로 만들 상자마다 직접 준다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 값은 이상적 너비라서 실제 열은 좁아지거나 넓어질 수 있다 | CSS 다단 레이아웃 명세의 동작(원본 팁과 같다) |
| 기본값 `auto` · 상속 안 됨 · 애니메이션 가능 | CSS 명세의 속성 정의(원본 데이터) |
| 남는 폭을 열마다 나눠 준다 | CSS 명세의 열 계산 규칙(정확한 식은 「더 들어가면」 · 확인 필요) |
| 화면에 보이는 열 수 · 폭 | 브라우저의 렌더링 결과 — 렌더 실측 아님 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 긴 글을 폭에 맞춰 여러 단으로 | `column-width` | 미디어 쿼리마다 열 수 고정 |
| 열 수를 정확히 정해야 한다 | `column-count` | `column-width` 만 |
| 열 폭을 픽셀 단위로 지켜야 한다 | grid 의 고정 트랙 | `column-width` (이상적 너비일 뿐) |
| 카드 묶음을 가로세로 칸에 맞춰 | grid · flex | 다단(글이 열을 따라 흐른다) |

## 핵심 문장

1. **`column-width` 는 이상적 열 너비다** — 최소도 고정도 아니다.
2. **열 수는 브라우저가 폭을 보고 정한다** — 폭이 바뀌면 열 수도 바뀐다.
3. **공간이 모자라면 좁아지고, 남으면 넓어진다** — 남는 폭은 열들이 나눠 갖는다.
4. **`auto` 면 열 너비는 다른 속성이 정한다** — 기본값이고 상속되지 않는다.

## 용어 풀이

- **다단 레이아웃** — 상자 안 글을 여러 세로 열로 나눠 흘려 보내는 배치.
- **열(단)** — 다단 레이아웃에서 글이 위에서 아래로 채워지는 세로 칸 하나.
- **이상적 너비** — 열 수를 정할 때 기준이 되는 목표 폭. 실제 폭은 달라질 수 있다.
- **`column-gap`** — 열과 열 사이 간격.
- **`column-count`** — 열 수를 정하는 속성.
- **상속** — 부모의 속성값이 자식에게 저절로 넘어가는 것.
- **`auto`** — 이 속성으로 값을 정하지 않고 다른 규칙에 맡기는 키워드.

## 더 들어가면

- 명세의 열 수 계산은 대략 `열 수 = max(1, floor((안쪽 폭 + gap) / (column-width + gap)))` 이고, 실제 열 폭은 `(안쪽 폭 − (열 수 − 1) × gap) / 열 수` 다 (확인 필요).
- 위 식대로면 안쪽 폭 400px · `150px` · gap `20px` 에서 2열, 열 폭 190px 이 된다 (확인 필요).
- `column-width` 와 `column-count` 를 함께 주면 `column-count` 는 열 수의 상한처럼 동작한다 (확인 필요).
- 단축 속성 `columns` 로 `columns: 150px 3;` 처럼 둘을 한 번에 줄 수 있다 (확인 필요).
- 애니메이션 가능하지만 열 수는 정수로 바뀌므로 전환 중 열이 갑자기 늘거나 줄 수 있다 (확인 필요).
