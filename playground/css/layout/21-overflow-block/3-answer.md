# css/layout/21 — overflow-block — 정답

> 복습 때 이 파일은 **맨 마지막에만** 연다.\

## 퀴즈 정답

### 1. 세로 스크롤바가 생긴다

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
단락이 200px 너비에 맞춰 여러 줄로 줄바꿈되고, 쌓인 줄이 60px 높이를 넘으므로 세로축에 스크롤바가 생긴다 (코드에서 읽은 것 — 렌더 실측 아님).

**왜 그런가**
기본 쓰기 모드는 가로쓰기라 블록 방향이 세로축이다.
`auto` 는 블록 방향으로 넘칠 때만 스크롤바를 그리고, 이 상자는 넘치므로 세로 스크롤바가 나타난다.
근거: 2-summary 「동작 방식 (1)」 · 「동작 방식 (3)」.

### 2. 가로축에 생긴다

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
`vertical-rl` 에서는 줄이 오른쪽에서 왼쪽으로 쌓이므로 블록 방향이 가로축이고, 스크롤바는 가로축에 생긴다 (코드에서 읽은 것 — 렌더 실측 아님).

**왜 그런가**
원본 팁대로 세로 쓰기 모드에서 `overflow-block` 은 `overflow-x` 자리를 맡는다.
`scroll` 은 넘침 여부와 상관없이 늘 스크롤바를 그리므로 내용 길이와 무관하게 가로 스크롤바가 보인다.
근거: 2-summary 「동작 방식 (2)」 · 「동작 방식 (3)」.

### 3. 스크롤바가 생기지 않는다

**예상** (실행하지 않음 — 코드를 읽어 추론한 것이다)
상자 높이가 콘텐츠만큼 늘어나 단락 전체가 보이고 스크롤바는 없다 (코드에서 읽은 것 — 렌더 실측 아님).

**왜 그런가**
블록 방향 크기가 묶여 있지 않으면 넘침이 생기지 않는다.
`auto` 는 넘칠 때만 스크롤바를 그리므로 할 일이 없다.
근거: 2-summary 「동작 방식 (1)」 · 「어디서 틀리나 2」.

### 4. 쓰기 모드가 바뀌어도 「줄이 쌓이는 방향」이라는 뜻을 지키려고

`overflow-y` 는 언제나 세로축에 묶여 있다.
세로쓰기로 바꾸면 줄이 쌓이는 방향이 가로가 되는데, `overflow-y` 는 여전히 세로를 다뤄 의도와 어긋난다.
`overflow-block` 은 쓰기 모드에 따라 축을 따라가므로 같은 스타일을 가로쓰기 · 세로쓰기 양쪽에서 쓸 수 있다.
근거: 2-summary 「동작 방식 (3)」 · 「어디서 틀리나 1」.

### 5. 스크롤을 허용하느냐가 다르다

`hidden` 은 잘라 내되 스크롤 컨테이너라서 스크립트로는 스크롤 위치를 옮길 수 있다.
`clip` 은 원본 설명대로 잘라 내고 스크롤 자체가 불가하다.
잘린 부분을 코드로 보여 줄 일이 있으면 `hidden`, 완전히 막으려면 `clip` 을 고른다.
근거: 2-summary 「동작 방식 (2)」 · 「어디서 틀리나 3」.

### 6. 처리되지 않는다 — 자식은 기본값 `visible` 이다

`overflow-block` 은 상속되지 않는다.
부모 상자 경계에서 넘친 부분은 부모가 자르지만, 자식 상자 자신의 넘침 처리는 자식의 값(기본 `visible`)을 따른다.
근거: 2-summary 「문법 — 형태와 규칙」.

### 7. 바꿀 수 없다 — 애니메이션 가능한 속성이 아니다

원본 재료에 「애니메이션 가능: 아니오」로 되어 있다.
`transition` 을 걸어도 값 사이를 부드럽게 옮겨 가지 않는다.
근거: 2-summary 「문법 — 형태와 규칙」.

### 8. `overflow-block` 은 `overflow-y`, `overflow-inline` 은 `overflow-x` 자리

가로쓰기에서 블록 방향은 세로축, 인라인 방향은 가로축이다.
그래서 블록 쪽은 `overflow-y`, 인라인 쪽은 `overflow-x` 에 대응한다.
세로쓰기로 바꾸면 둘의 짝이 서로 뒤바뀐다.
근거: 2-summary 「동작 방식 (3)」 · 「문법 — 형태와 규칙」 · 「용어 풀이」.

## 실습 정답

### 실습 1. 블록 방향으로만 넘겨 보는 메모 상자

**요구 조건 → 정답 코드의 자리**

| 요구 조건 | 정답 코드 |
|---|---|
| 고정 크기 상자에서 단락이 블록 방향으로 넘친다 | `.box` 의 `width` · `height` 선언 |
| 블록 방향으로 넘칠 때만 스크롤바 | `.box { overflow-block: auto; }` |
| 논리 속성으로 쓴다 | `overflow-y` 가 아닌 `overflow-block` |
| 단락의 기본 바깥 여백 제거 | `p { margin: 0; }` |

**정답 코드** — study-practice 의 줄 단위 주석판이다(코드 동작은 원본 예제와 같다).

`css/layout/reference/overflow-block.html`

```html
<!DOCTYPE html>
<!-- HTML5 문서 선언 -->
<html lang="ko">
<head>
<meta charset="utf-8">
<title>overflow-block - 블록 방향의 넘침 처리 방식을 설정합니다</title>
<!--
  [레이아웃] overflow-block
  설명: 블록 방향의 넘침 처리 방식을 설정합니다
  구문: overflow-block: visible | hidden | clip | scroll | auto
  팁: 수평 쓰기 모드에서는 overflow-y에 대응합니다. 세로 쓰기 모드에서는 overflow-x에 대응합니다.
-->
<style>
  /* .box: 블록 방향 자동 스크롤 박스 */
  .box {
    overflow-block: auto;        /* 블록 방향(수평 쓰기 모드 기준 세로) 자동 스크롤 */
    width: 200px;                /* 고정 너비 */
    height: 60px;                /* 고정 높이로 넘침 유발 */
    background: #f1f5f9;         /* 회색 배경 */
    padding: 8px;                /* 안쪽 여백 */
    border: 2px solid #3b82f6;   /* 파란 테두리 */
    border-radius: 4px;          /* 모서리 둥글게 */
  }
  /* p: 단락 기본 마진 제거 */
  p {
    margin: 0;                   /* 기본 마진 제거 */
  }
</style>
</head>
<body>
<!-- 논리적 블록 방향 넘침 처리 -->
<div class="box">
  <p>블록 방향으로 넘치는 긴 콘텐츠입니다. Lorem ipsum dolor sit amet, consectetur adipiscing elit.</p>
</div>

</body>
</html>
```

원본 예제의 나머지 조각(study-practice 에는 없고 study-site 항목 데이터에만 있다):

```css
.box {
  overflow-block: auto;
  width: 200px;
  height: 60px;
  background: #f1f5f9;
  padding: 8px;
  border: 2px solid #3b82f6;
  border-radius: 4px;
}
p {
  margin: 0;
}
```

**실행 결과** — 실행하지 않음 — 브라우저 화면에서 결과를 보는 예제다 — 글로 옮길 출력이 없다.

**풀이 요점**
- 넘침은 `height` 로 블록 방향 크기를 묶었기 때문에 생긴다.
- `auto` 는 넘칠 때만 스크롤바를 그리므로 단락을 짧게 하면 스크롤바가 사라진다.
- 가로쓰기 기본 상태이므로 `overflow-block` 은 `overflow-y` 자리를 맡아 세로 스크롤이 된다.
- `p { margin: 0; }` 은 단락의 기본 여백이 첫 줄을 아래로 밀어내지 않게 한다.
- `overflow-block` 을 처리하지 못하는 브라우저라면 선언이 무시되어 글이 상자 밖으로 삐져나온다 — 그 경우 `overflow-y` 를 함께 두어 확인한다.
