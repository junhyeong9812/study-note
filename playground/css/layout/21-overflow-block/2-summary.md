## 한눈에 — 쉽게 말하면

**`overflow-block` 은 「글이 쌓여 가는 방향으로 넘쳤을 때 어떻게 할지」를 정하는 규칙이다.**
공책에 글을 쓰면 줄이 위에서 아래로 쌓인다.
쪽이 꽉 차면 넘친 줄을 쪽 밖으로 삐져나가게 둘 수도 있고, 잘라 버릴 수도 있고, 두루마리처럼 말아서 넘겨 보게 할 수도 있다.
세로쓰기 책이면 줄이 오른쪽에서 왼쪽으로 쌓이므로 「쌓이는 방향」이 가로가 된다.
CSS 상자도 똑같은 구조다.
줄이 쌓이는 방향이 블록 방향이고, `overflow-block` 은 그 방향의 넘침만 다룬다.

> **블록 방향** — 줄(블록)이 차례로 쌓여 가는 방향이다.\
> 예: 가로쓰기(`horizontal-tb`)에서는 위 → 아래, 즉 세로축이다.

| 비유 | 실체 |
|---|---|
| 공책 한 쪽 | 고정 크기(`width` · `height`)를 가진 상자 |
| 줄이 쌓이는 방향 | 블록 방향 |
| 쪽 밖으로 삐져나간 줄 | `visible` 로 그대로 보이는 넘친 콘텐츠 |
| 잘라 낸 줄 | `hidden` · `clip` |
| 두루마리 | `scroll` · `auto` 의 스크롤 |
| 가로쓰기 / 세로쓰기 | `writing-mode` |

```text
 가로쓰기 (horizontal-tb)          세로쓰기 (vertical-rl)
 ┌──────────┐                      ┌──────────┐
 │ 첫째 줄  │  ↓ 블록 방향          │ 셋 둘 첫 │  ← 블록 방향
 │ 둘째 줄  │  = 세로축             │ 째 째 째 │  = 가로축
 │ 셋째 줄  │  → overflow-y 자리    │ 줄 줄 줄 │  → overflow-x 자리
 └──────────┘                      └──────────┘
```

## 이 주제가 답하려는 질문

1. 상자 안의 콘텐츠가 블록 방향으로 넘치면 다섯 가지 값은 각각 무엇을 하나?
2. `overflow-block` 은 `overflow-x` · `overflow-y` 가운데 어느 쪽에 해당하며, 그것은 무엇에 따라 바뀌나?
3. 넘침이 실제로 생기려면 상자에 무엇이 필요한가?

## 동작 방식

### (1) 넘침을 만드는 조건

**언제 쓰나** — `overflow-block` 이 할 일이 생기려면 먼저 블록 방향 크기가 콘텐츠보다 작아야 한다.

```text
.box { height: 60px; }  + 긴 단락
        │
        ▼
 단락이 줄바꿈되며 줄이 블록 방향으로 쌓인다
        │
        ▼
 쌓인 줄의 높이 합 > 상자 높이 60px  →  블록 방향 넘침 발생
        │
        ▼
 overflow-block 값이 넘친 부분을 어떻게 다룰지 정한다
```

- 가로쓰기에서 단락은 상자 너비에 맞춰 줄바꿈된다.
- 줄이 늘수록 콘텐츠의 세로 길이가 커진다.
- 상자 높이가 고정이면 어느 순간 콘텐츠가 상자보다 길어진다.
- 그때부터 `overflow-block` 의 값이 의미를 갖는다.
- 높이를 정하지 않으면 상자가 콘텐츠만큼 늘어나 넘침이 생기지 않는다.

### (2) 다섯 값이 넘친 부분에 하는 일

**언제 쓰나** — 넘친 콘텐츠를 보일지, 자를지, 스크롤로 볼지를 고를 때.

```text
           넘친 부분     스크롤바            스크롤 가능?
visible  → 상자 밖에 보임  없음               해당 없음
hidden   → 잘림           없음               사용자는 못 함 · 스크립트로는 가능
clip     → 잘림           없음               불가
scroll   → 잘림           항상 있음          가능
auto     → 잘림           넘칠 때만 생김     가능 (넘칠 때)
```

- `visible` 은 기본값이며 넘친 줄이 상자 경계를 뚫고 그대로 그려진다.
- `hidden` 은 넘친 부분을 잘라 보이지 않게 하고 스크롤바를 만들지 않는다.
- `hidden` 상자는 스크롤 컨테이너이기는 해서, 사용자가 스크롤바로 움직일 수는 없어도 스크립트(`scrollTop` 등)로는 위치를 옮길 수 있다.
- `clip` 도 잘라 내지만 원본 설명대로 「스크롤 불가」다 — 스크립트로도 옮길 수 없다.
- `scroll` 은 넘치든 안 넘치든 블록 방향 스크롤바를 늘 그린다.
- `auto` 는 넘쳤을 때만 스크롤바를 그린다.

> **스크롤 컨테이너** — 넘친 콘텐츠를 잘라 두고 스크롤 위치를 가지는 상자다.\
> 예: `overflow-block: auto` 인 상자.

### (3) 블록 방향이 물리 축으로 바뀌는 과정

**언제 쓰나** — 같은 스타일을 가로쓰기와 세로쓰기 양쪽에서 쓸 때.

```text
overflow-block: auto
        │
        ├─ writing-mode: horizontal-tb → 블록 방향 = 세로 → overflow-y: auto 와 같은 효과
        │
        └─ writing-mode: vertical-rl   → 블록 방향 = 가로 → overflow-x: auto 와 같은 효과
```

- 브라우저는 먼저 그 상자의 쓰기 모드를 본다.
- 가로쓰기면 블록 방향은 세로축이므로 `overflow-block` 이 `overflow-y` 자리를 맡는다.
- 세로쓰기면 블록 방향은 가로축이므로 `overflow-block` 이 `overflow-x` 자리를 맡는다.
- 그래서 쓰기 모드를 바꿔도 「줄이 쌓이는 방향의 넘침」이라는 뜻은 그대로 유지된다.

> **논리 속성** — 위·아래·왼쪽·오른쪽 대신 블록 · 인라인 방향으로 말하는 속성이다.\
> 예: `overflow-block` · `overflow-inline` · `margin-block`.

```html demo
<div style="overflow-block: auto; width: 200px; height: 60px; padding: 8px; border: 2px solid #3b82f6;">
  <p style="margin: 0">줄이 여럿으로 쌓일 만큼 긴 단락이다. 상자 높이 60px 를 넘으면 세로 스크롤이 생긴다. Lorem ipsum dolor sit amet.</p>
</div>
```

> **보이는 것** — 파란 테두리 상자 안에 단락 첫 몇 줄만 보이고 세로 스크롤바로 나머지를 내려 볼 수 있다 (코드에서 읽은 것 — 렌더 실측 아님)

## 문법 — 형태와 규칙

```css
/* 가로쓰기: 세로로 넘치면 스크롤 */
.panel {
  height: 120px;          /* 블록 방향 크기를 묶어야 넘침이 생긴다 */
  overflow-block: auto;   /* 넘칠 때만 블록 방향 스크롤바 */
}

/* 세로쓰기: 같은 선언이 가로 스크롤이 된다 */
.panel.vertical {
  writing-mode: vertical-rl;
  width: 120px;           /* 세로쓰기의 블록 방향 크기는 너비다 */
}
```

| 값 | 뜻 |
|---|---|
| `visible` | 기본값. 넘치는 콘텐츠가 잘리지 않는다 |
| `hidden` | 블록 방향으로 넘치는 콘텐츠가 잘린다 |
| `clip` | 블록 방향으로 넘치는 콘텐츠가 잘리며 스크롤이 불가하다 |
| `scroll` | 블록 방향에 항상 스크롤바가 표시된다 |
| `auto` | 블록 방향으로 넘칠 때만 스크롤바가 표시된다 |

- 꼴: `overflow-block: visible | hidden | clip | scroll | auto`.
- 기본값은 `visible` 이다.
- 상속되지 않는다 — 부모에 주어도 자식 상자의 넘침 처리는 기본값 `visible` 그대로다.
- 애니메이션 가능하지 않다 — `transition` 으로 값 사이를 부드럽게 옮길 수 없다.
- 짝이 되는 인라인 방향 속성은 `overflow-inline` 이다.

## 어디서 틀리나

### 1. 물리 축으로 외워 두면 세로쓰기에서 틀린다

원본 팁: 수평 쓰기 모드에서는 `overflow-y` 에 대응하고, 세로 쓰기 모드에서는 `overflow-x` 에 대응한다.
「`overflow-block` = 세로 스크롤」로 외우면 `writing-mode: vertical-rl` 상자에서 가로 스크롤이 생길 때 당황한다.
기준은 언제나 「줄이 쌓이는 방향」이다.

### 2. 높이를 안 주면 아무 일도 없다

`auto` · `scroll` 을 줬는데 스크롤이 안 생긴다면 대개 블록 방향 크기가 정해지지 않은 것이다.
가로쓰기에서 `height` 가 없으면 상자가 콘텐츠만큼 커져 넘칠 것이 없다.

### 3. `hidden` 과 `clip` 을 같은 것으로 본다

둘 다 화면에서는 잘라 낸다.
차이는 스크롤 가능 여부다 — `hidden` 은 스크립트 스크롤이 남고, `clip` 은 원본 설명대로 스크롤이 불가하다.
「잘린 부분을 코드로 보여 줄 일이 있나」로 고른다.

### 4. `scroll` 은 넘치지 않아도 스크롤바를 그린다

내용이 짧을 때 빈 스크롤바가 거슬린다면 `auto` 를 쓴다.
반대로 내용 길이가 바뀔 때 스크롤바가 생겼다 사라지며 폭이 흔들리는 것이 싫다면 `scroll` 이 낫다.

### 5. 브라우저가 모르는 속성은 그냥 버려진다

CSS 는 해석하지 못한 선언을 무시한다.
`overflow-block` 을 처리하지 못하는 브라우저에서는 선언이 없던 것처럼 기본 `visible` 로 그려지고, 넘친 글이 상자 밖으로 삐져나온다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 블록 방향이 쓰기 모드에 따라 세로축 또는 가로축이 된다 | CSS 명세(쓰기 모드 · 논리 속성) |
| 다섯 값의 뜻, 기본값 `visible`, 상속 안 됨, 애니메이션 불가 | CSS 명세(원본 재료) |
| 해석하지 못한 선언을 무시한다 | CSS 명세(파싱 규칙) |
| 어느 브라우저가 `overflow-block` 을 처리하나 | 브라우저 구현마다 다름 — 이 문서는 범위를 적지 않는다 (확인 필요) |
| 스크롤바의 모양 · 두께 | 브라우저 · 운영체제 구현 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 가로쓰기 · 세로쓰기를 모두 지원하는 컴포넌트 | `overflow-block` | `overflow-y` 고정 |
| 긴 목록을 고정 높이 영역에서 넘겨 보기 | `overflow-block: auto` | `visible` |
| 넘친 장식을 잘라 내고 스크롤도 막기 | `clip` | `hidden`(스크립트 스크롤이 남는다) |
| 내용 길이와 무관하게 스크롤바 자리를 고정 | `scroll` | `auto` |
| 처리 여부가 불확실한 환경에서 확실히 스크롤 | `overflow-y` 를 함께 두기 | `overflow-block` 만 단독 |

## 핵심 문장

1. **`overflow-block` 은 줄이 쌓이는 방향의 넘침만 다룬다** — 축은 쓰기 모드가 정한다.
2. **가로쓰기에서는 `overflow-y`, 세로쓰기에서는 `overflow-x` 자리다.**
3. **넘침은 블록 방향 크기가 묶여 있어야 생긴다** — 없으면 값이 할 일이 없다.
4. **`hidden` 과 `clip` 은 둘 다 자르지만, `clip` 은 스크롤 자체를 막는다.**
5. **`scroll` 은 늘, `auto` 는 넘칠 때만 스크롤바를 그린다.**

## 용어 풀이

- **넘침(overflow)** — 콘텐츠가 상자의 크기보다 커서 경계를 벗어나는 상태.
- **블록 방향** — 줄(블록)이 쌓여 가는 방향. 가로쓰기에서는 세로축.
- **인라인 방향** — 한 줄 안에서 글자가 이어지는 방향. 가로쓰기에서는 가로축.
- **쓰기 모드(`writing-mode`)** — 글자와 줄의 진행 방향을 정하는 속성.
- **논리 속성** — 물리 방향 대신 블록 · 인라인 방향으로 말하는 속성.
- **스크롤 컨테이너** — 넘친 콘텐츠를 잘라 두고 스크롤 위치를 가지는 상자.
- **상속** — 부모에 준 값이 자식에게 저절로 넘어가는 것. `overflow-block` 은 상속되지 않는다.

## 더 들어가면

- 명세에서 한 축만 `visible` 이고 다른 축이 `hidden` · `scroll` · `auto` 면, `visible` 쪽은 `auto` 로 계산된다고 한다 — 한쪽만 스크롤시키고 다른 쪽만 삐져나오게 하는 조합은 안 된다 (확인 필요).
- `clip` 과 함께 `overflow-clip-margin` 으로 잘라 내는 경계를 상자 밖으로 조금 넓힐 수 있다고 한다 (확인 필요).
- `overflow-block` · `overflow-inline` 을 처리하는 브라우저는 물리 속성 `overflow-x` · `overflow-y` 보다 적다고 알려져 있다 — 실서비스에서는 물리 속성을 대비책으로 함께 두는 경우가 많다 (확인 필요).
- 스크롤바가 생겼다 사라질 때 폭이 흔들리는 문제는 `scrollbar-gutter` 로 자리를 미리 잡아 두는 방법도 있다 (확인 필요).
