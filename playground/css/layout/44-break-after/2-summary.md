## 한눈에 — 쉽게 말하면

**`break-after` 는 「이 줄 다음에서 공책 장을 넘겨라」라는 표시다.**
공책에 글을 이어 쓰다가 소제목 하나를 쓰고, 그 뒤에 「여기서 다음 칸으로 넘김」 표시를 붙여 둔 것과 같다.
글이 아직 남은 칸을 다 채우지 않았어도, 그 표시 뒤의 글은 다음 칸에서 시작한다.
CSS 의 다단(여러 열) 레이아웃과 인쇄 페이지도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 공책의 칸 · 장 | 열(column) · 페이지(page) |
| 「여기서 넘김」 표시 | `break-after: column` · `break-after: page` |
| 「여기서는 넘기지 마」 표시 | `break-after: avoid` · `avoid-column` · `avoid-page` |
| 표시가 없는 줄 | `break-after: auto` (기본값) |

```text
 표시 없음 (auto)              break-after: column 을 제목에
┌──────────┬──────────┐       ┌──────────┬──────────┐
│ 제목      │ 문단 2    │       │ 제목      │ 문단 1    │
│ 문단 1    │          │       │          │ 문단 2    │
└──────────┴──────────┘       └──────────┴──────────┘
  내용이 알아서 흘러 나뉨          제목 뒤에서 다음 열로 넘김
```

## 이 주제가 답하려는 질문

1. 어떤 요소 **뒤에서** 열이나 페이지를 억지로 나누려면 어떻게 하나?
2. 반대로, 어떤 요소 뒤에서 나뉘지 않게 하려면 어떻게 하나?
3. 「열 나누기」와 「페이지 나누기」는 어떻게 따로 다루나?
4. 옛 속성 `page-break-after` 와는 어떤 관계인가?

## 동작 방식

### (1) 나누기는 「조각나는 흐름」 안에서만 일어난다

**언제 쓰나** — 내용이 여러 열이나 여러 페이지로 쪼개져 흐르는 곳에서 쪼개지는 자리를 고르고 싶을 때.

```text
입력:  .multicol { column-count: 2; }  안에  h3, p, p
          │
          ▼
무엇이 일어나나: 브라우저가 내용을 위에서 아래로 쌓다가
               두 열의 높이가 비슷하도록 중간 어딘가에서 끊어 둘째 열로 넘긴다
          │
          ▼
결과:  끊기는 자리를 브라우저가 고른다 (break-after: auto 의 상태)
```

- `column-count: 2` 를 받은 컨테이너는 내용을 두 열로 나눠 흘린다.
- 이렇게 내용이 여러 조각(열 · 페이지)으로 쪼개지는 흐름이 있어야 「나누기」라는 말이 의미를 갖는다.
- 기본값 `auto` 에서는 나누기가 허용되지만 강제되지 않는다 — 어디서 끊을지는 브라우저가 정한다.
- 쪼개지는 흐름이 없는 평범한 블록 안에서는 열 나누기를 걸어도 넘어갈 「다음 열」이 없다 (원본에 근거 없음 — 추론).

> **다단 레이아웃** — 한 컨테이너의 내용을 신문처럼 여러 열로 나눠 흘리는 배치다.\
> 예: `column-count: 2` 를 준 `div` 는 내용이 두 열로 흐른다.

### (2) 강제 나누기 — `column` · `page` · `always` · `left` · `right`

**언제 쓰나** — 「이 요소 다음 내용은 반드시 새 열(새 페이지)에서 시작」하게 만들 때.

```text
입력:  h3.break { break-after: column; }
       <h3 class="break">  <p>1</p>  <p>2</p>
          │
          ▼
무엇이 일어나나: h3 를 첫 열에 놓은 직후, 첫 열에 자리가 남아도
               열을 끊는다 → 다음 형제인 p 부터는 둘째 열에서 시작
          │
          ▼
결과:  첫 열 = h3 만 / 둘째 열 = p, p
```

- `break-after` 는 요소 **뒤**, 즉 그 요소와 다음 내용 사이의 경계를 다룬다.
- `column` 은 그 경계에서 열 나누기를 강제한다.
- `page` 는 그 경계에서 페이지 나누기를 강제한다.
- `always` 는 그 경계에서 나누기를 강제한다 (어떤 종류의 나누기인지는 놓인 흐름에 따른다 — 원본에 근거 없음 — 추론).
- `left` · `right` 는 페이지 나누기를 강제하되, 다음 페이지가 각각 왼쪽 · 오른쪽 페이지가 되게 한다.

```html demo
<div style="column-count: 2; column-gap: 20px; padding: 12px; background: #f1f5f9;">
  <h3 style="break-after: column; margin: 0 0 8px;">제목</h3>
  <p>문단 하나.</p>
  <p>문단 둘.</p>
</div>
```

> **보이는 것** — 왼쪽 열에는 「제목」만 있고, 두 문단은 오른쪽 열에서 위부터 쌓인다. (코드에서 읽은 것 — 렌더 실측 아님)

> **강제 나누기** — 공간이 남아 있어도 그 자리에서 반드시 끊는 것이다.\
> 예: `break-after: page` 를 준 표지 뒤의 내용은 인쇄하면 다음 페이지에서 시작한다.

### (3) 나누기 방지 — `avoid` · `avoid-column` · `avoid-page`

**언제 쓰나** — 제목만 한 열(한 페이지) 끝에 홀로 남고 그 본문은 다음으로 넘어가는 꼴을 막고 싶을 때.

```text
입력:  h3 { break-after: avoid; }
          │
          ▼
무엇이 일어나나: 브라우저가 끊을 자리를 고를 때
               h3 바로 뒤는 되도록 피한다
          │
          ▼
결과:  h3 와 그 다음 문단이 같은 열 · 같은 페이지에 붙어 있으려 한다
```

- `avoid` 는 그 경계에서 모든 종류의 나누기를 피한다.
- `avoid-column` 은 열 나누기만 피한다 — 페이지 나누기는 막지 않는다.
- `avoid-page` 는 페이지 나누기만 피한다 — 열 나누기는 막지 않는다.
- 「피한다」는 「끊을 자리를 고를 때 여기는 빼 달라」는 요청이다 — 다른 자리가 없으면 끊길 수 있다 (원본에 근거 없음 — 추론, 「어디서 틀리나 3」).

### (4) 상속되지 않는다

**언제 쓰나** — 컨테이너에 걸지, 자식에 걸지 고를 때.

```text
입력:  .multicol { break-after: column; }   ← 컨테이너에 걸었다
          │
          ▼
무엇이 일어나나: break-after 는 상속되지 않으므로 자식 h3 · p 는 값을 물려받지 않는다
               → 컨테이너 자기 자신의 「뒤」 경계에만 적용된다
          │
          ▼
결과:  컨테이너 안의 열 배치는 그대로 (auto 처럼 흐른다)
```

- 원본 데이터에서 상속은 `False` 다.
- 그래서 「이 뒤에서 끊어라」는 끊고 싶은 자리 바로 앞의 요소에 직접 건다.
- 애니메이션 가능도 `False` 다 — 키워드 값이라 중간값이 없다.

## 문법 — 형태와 규칙

```css
/* 2단 컨테이너 */
.cols {
  column-count: 2;
}

/* 이 제목 다음 내용은 새 열에서 */
.cols h3.split {
  break-after: column;
}

/* 이 제목 바로 뒤에서는 끊지 마 */
.cols h3.keep {
  break-after: avoid;
}

/* 인쇄할 때 표지 다음은 새 페이지 */
.cover {
  break-after: page;
}
```

- 꼴: `break-after: <키워드>;` — 키워드 하나만 쓴다.
- 기본값: `auto`.
- 상속: 안 된다.
- 애니메이션: 안 된다.

| 값 | 무엇을 하나 | 종류 |
|---|---|---|
| `auto` | 기본값. 나누기를 허용하지만 강제하지 않는다 | 허용 |
| `avoid` | 요소 뒤에서의 모든 나누기를 피한다 | 방지 |
| `avoid-column` | 열 나누기만 피한다 | 방지 |
| `avoid-page` | 페이지 나누기만 피한다 | 방지 |
| `always` | 요소 뒤에서 나누기를 강제한다 | 강제 |
| `column` | 요소 뒤에서 열 나누기를 강제한다 | 강제 |
| `page` | 요소 뒤에서 페이지 나누기를 강제한다 | 강제 |
| `left` | 다음 페이지가 왼쪽 페이지가 되도록 강제한다 | 강제(페이지) |
| `right` | 다음 페이지가 오른쪽 페이지가 되도록 강제한다 | 강제(페이지) |

- 레거시 속성 `page-break-after` 를 대체하는 현대적 속성이다.
- 이름에 `page` 가 빠진 까닭은 페이지뿐 아니라 열 · 영역 나누기까지 한 속성으로 다루기 때문이다 (원본 설명 「페이지, 열 또는 영역 나누기」에서 읽은 것).

## 어디서 틀리나

### 1. 끊고 싶은 자리의 「앞」 요소에 건다
`break-after` 는 요소 **뒤**를 끊는다.
「문단 1 부터 둘째 열」을 원하면 문단 1 이 아니라 그 앞의 제목에 건다.
문단 1 에 걸면 문단 1 까지 첫 열에 남고 문단 2 부터 넘어간다.

### 2. 컨테이너에 걸어도 안의 자식에는 퍼지지 않는다
상속이 `False` 이므로 `.multicol { break-after: column; }` 은 자식들의 경계를 바꾸지 않는다.
그 선언은 컨테이너 자기 뒤의 경계에만 해당한다.

### 3. 방지는 보장이 아니다
원본의 주장: `avoid` 는 「요소 뒤에서의 모든 나누기를 방지합니다」.
의심스러운 까닭: 내용이 한 열(한 페이지)에 다 들어가지 않으면 어딘가는 끊어야 한다.
그때 브라우저가 피하라는 자리에서도 끊을 수 있으므로 「방지」보다 「되도록 피함」으로 읽는 편이 안전하다 (원본에 근거 없음 — 추론).

### 4. 열 나누기와 페이지 나누기를 헷갈린다
`column` · `avoid-column` 은 다단 레이아웃의 열을 다룬다.
`page` · `avoid-page` · `left` · `right` 는 페이지를 다룬다 — 화면이 아니라 인쇄처럼 페이지가 있는 출력에서 의미가 있다 (원본에 근거 없음 — 추론).
화면의 다단 컨테이너에서 열을 끊으려고 `page` 를 쓰면 기대와 다를 수 있다 (확인 필요).

### 5. 옛 속성만 쓰고 끝낸다
팁: 레거시 `page-break-after` 속성의 현대적 대체다.
`page-break-after` 는 이름 그대로 페이지만 다루므로 열 나누기를 표현할 수 없다 (원본에 근거 없음 — 추론).
새 코드는 `break-after` 를 쓴다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 기본값 `auto` · 상속 안 됨 · 애니메이션 안 됨 | CSS 명세의 속성 정의 (원본 데이터) |
| `column` 은 요소 뒤에서 열 나누기를 강제한다 | CSS 명세의 값 정의 (원본 데이터) |
| `avoid` 계열은 다른 자리가 없으면 끊길 수 있다 | 명세가 나누기 자리를 고르는 규칙 — 세부는 확인 필요 |
| 각 브라우저가 열 나누기 값을 실제로 따르는지 | 브라우저 구현 — 원본에 없음 (확인 필요) |
| `left` · `right` 가 왼쪽 · 오른쪽 페이지를 맞추는 방식 | 인쇄 엔진 구현 — 확인 필요 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 다단에서 제목 뒤 본문을 새 열에서 시작 | 제목에 `break-after: column` | 본문에 `break-after` (한 칸 늦게 끊긴다) |
| 인쇄 시 표지 다음을 새 페이지로 | `break-after: page` | `break-after: column` |
| 책 인쇄에서 다음 장을 오른쪽 페이지에서 시작 | `break-after: right` | `page` 만 쓰기 |
| 제목이 열 끝에 홀로 남는 것을 막기 | 제목에 `break-after: avoid` (또는 `avoid-column`) | 빈 줄 · 여백으로 위치 맞추기 |
| 열은 끊어도 되지만 페이지만 막기 | `avoid-page` | `avoid` (열까지 막는다) |
| 새 코드에서 페이지 나누기 | `break-after: page` | `page-break-after` |

## 핵심 문장

1. **`break-after` 는 요소 「뒤」의 경계를 다룬다** — 끊고 싶은 자리 바로 앞 요소에 건다.
2. **강제 값(`column` · `page` · `always` · `left` · `right`)은 자리가 남아도 끊고, 방지 값(`avoid` 계열)은 끊을 자리에서 빼 달라고 한다.**
3. **열과 페이지를 따로 고를 수 있다** — `column` / `avoid-column` 과 `page` / `avoid-page`.
4. **상속되지 않는다** — 컨테이너에 걸면 자식 경계는 그대로다.
5. **`page-break-after` 의 현대적 대체다.**

## 용어 풀이

- **나누기(break)** — 흐르는 내용을 한 조각(열 · 페이지)에서 끊고 다음 조각으로 넘기는 것.
- **다단 레이아웃** — 한 컨테이너의 내용을 여러 열로 나눠 흘리는 배치.
- **열 나누기** — 다단 레이아웃에서 다음 열로 넘기는 나누기.
- **페이지 나누기** — 인쇄처럼 페이지가 있는 출력에서 다음 페이지로 넘기는 나누기.
- **영역 나누기** — 열 · 페이지 말고 다른 조각 단위로 넘기는 나누기 (원본 설명의 「영역」).
- **강제 나누기** — 공간이 남아도 그 자리에서 반드시 끊는 것.
- **나누기 방지** — 끊을 자리를 고를 때 그 자리를 피해 달라는 요청.
- **왼쪽 · 오른쪽 페이지** — 책을 펼쳤을 때 왼쪽과 오른쪽에 오는 페이지.
- **상속** — 부모에 준 속성 값을 자식이 따로 정하지 않아도 물려받는 것.
- **`column-count`** — 다단 컨테이너를 몇 개의 열로 나눌지 정하는 속성.
- **`column-gap`** — 열과 열 사이 간격을 정하는 속성.

## 더 들어가면

- 짝 속성으로 요소 **앞**을 다루는 `break-before`, 요소 **안**에서 끊기지 않게 하는 `break-inside` 가 있다 (확인 필요).
- 한 경계에 앞 요소의 `break-after` 와 뒤 요소의 `break-before` 가 함께 걸리면, 강제 나누기가 방지보다 앞선다는 규칙이 있다 (확인 필요).
- 명세의 이 속성들은 「CSS Fragmentation」 모듈에서 정의되며, 그쪽 값 목록에는 `recto` · `verso` · `all` · `avoid-region` · `region` 같은 값도 있다 (확인 필요).
- `left` · `right` 를 맞추려고 빈 페이지가 하나 끼어들 수 있다 (확인 필요).
- 브라우저마다 다단 안의 열 나누기 값 지원이 고르지 않았던 시기가 있다 — 실제 지원 범위는 직접 확인해야 한다 (확인 필요).
