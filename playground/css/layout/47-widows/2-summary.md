## 한눈에 — 쉽게 말하면

**`widows` 는 「다음 쪽 맨 위에 혼자 넘어간 마지막 줄을 막는 규칙」이다.**
신문 기사가 한 단에서 끝나지 못하고 다음 단으로 넘어갈 때, 다음 단 맨 위에 문단의 끝 한 줄만 덩그러니 있으면 보기 흉하다.
편집자는 「다음 단으로 넘어가는 줄은 적어도 두 줄」이라는 규칙을 정하고, 모자라면 앞 단에서 줄을 더 끌어와 함께 넘긴다.
CSS 의 `widows` 도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 신문의 단 · 책의 쪽 | 다단(column)의 열 · 인쇄 페이지 · 영역 같은 조각(fragment) |
| 단이 바뀌는 자리 | 분절(break) 지점 |
| 다음 단 맨 위에 혼자 남은 끝 줄 | 위도우(widow, 과부 줄) |
| 「적어도 두 줄은 함께 넘긴다」 | `widows: 2` |

```text
  widows 규칙이 없을 때            widows: 2 일 때
 ┌──────────┬──────────┐       ┌──────────┬──────────┐
 │ 줄 1     │ 줄 4 ←혼자│       │ 줄 1     │ 줄 3     │
 │ 줄 2     │          │       │ 줄 2     │ 줄 4     │
 │ 줄 3     │          │       │          │          │
 └──────────┴──────────┘       └──────────┴──────────┘
   1열        2열                 1열        2열
```

## 이 주제가 답하려는 질문

1. 문단이 열이나 페이지 경계에서 잘릴 때, 새 조각의 맨 위에는 몇 줄이 있어야 하나?
2. 그 조건을 못 채우면 브라우저는 줄을 어떻게 옮기나?
3. `widows` 는 어디에 적고, 어떤 요소에 효과가 미치나?
4. 짝꿍 속성 `orphans` 와는 무엇이 다르고, 둘이 부딪치면 어떻게 되나?

## 동작 방식

### (1) 분절 뒤 새 조각 맨 위의 최소 줄 수

**언제 쓰나** — 다단 레이아웃이나 인쇄 페이지에서 문단이 다음 열·페이지로 넘어갈 때, 끝 줄 하나만 넘어가는 모양을 막고 싶을 때 쓴다.

```text
입력:  .box { column-count: 2; widows: 2; }   문단 4줄, 1열에 3줄까지 들어갈 공간
           │
           ▼
 브라우저가 먼저 잡은 분절 자리:  1열 = 줄1·줄2·줄3 / 2열 = 줄4   (2열 맨 위 1줄)
           │  1 < 2 → 조건 위반
           ▼
 분절 자리를 한 줄 앞으로 당긴다:  1열 = 줄1·줄2 / 2열 = 줄3·줄4  (2열 맨 위 2줄)
           │
           ▼
결과:  새 열 맨 위에 그 문단의 줄이 2줄 이상 있다
```

- 브라우저는 먼저 공간이 허락하는 데까지 줄을 채워 분절 자리를 정한다.
- 분절 뒤 새 조각에 넘어가는 줄 수가 `widows` 값보다 적으면 조건 위반이다.
- 그러면 분절 자리를 앞으로 당겨 앞 조각의 줄을 새 조각으로 더 넘긴다.
- 그 결과 앞 조각의 아래쪽에는 빈 공간이 생길 수 있다.

> **분절(break)** — 내용이 한 조각(열 · 페이지 · 영역)에 다 들어가지 못해 다음 조각으로 나뉘어 이어지는 것.\
> 예: 2단 레이아웃에서 문단이 1열 아래에서 끊겨 2열 위로 이어지는 것.

> **조각(fragment)** — 분절로 나뉜 내용 하나하나가 담기는 칸(열 · 페이지 · 영역).\
> 예: `column-count: 2` 인 상자의 1열과 2열.

> **위도우(widow, 과부 줄)** — 분절 뒤 새 페이지·열 맨 위에 홀로 남은 문단의 마지막 줄.\
> 예: 2열 꼭대기에 앞 문단의 끝 한 줄만 있는 모습.

### (2) 상속으로 문단에 닿는다

**언제 쓰나** — 다단 컨테이너 하나에 적어 그 안의 모든 문단에 한꺼번에 규칙을 걸 때.

```text
입력:  .multicol { widows: 2; }      <p> 는 .multicol 의 자식, p 에는 widows 를 안 적음
           │
           ▼
 widows 는 상속되는 속성 → <p> 의 widows 도 2
           │
           ▼
결과:  <p> 의 줄들이 열 경계에서 잘릴 때 규칙이 적용된다
```

- `widows` 는 줄(line)을 가진 블록, 곧 문단 같은 요소의 줄 나눔에 작용한다.
- 상속 속성이라 부모에 적으면 자식 문단이 그 값을 물려받는다.
- 그래서 원본 예제처럼 컨테이너 `.multicol` 에 적어도 그 안의 `<p>` 에 효과가 미친다.

> **상속(inheritance)** — 자식 요소가 값을 따로 받지 않으면 부모의 계산된 값을 물려받는 CSS 규칙.\
> 예: `body { color: red; }` 이면 그 안의 `<p>` 글자도 빨갛다.

### (3) `orphans` 와 짝을 이룬다

**언제 쓰나** — 분절의 앞쪽(끊기기 전 조각의 아래)과 뒤쪽(새 조각의 위)을 함께 다듬을 때.

```text
           1열(앞 조각)            2열(새 조각)
        ┌──────────────┐       ┌──────────────┐
        │ …            │       │ 줄 k+1  ┐    │
        │ 줄 k-1 ┐     │       │ 줄 k+2  ┘ ← widows 가 지키는 줄 수
        │ 줄 k   ┘ ← orphans 가 지키는 줄 수   │
        └──────────────┘       └──────────────┘
```

- `orphans` 는 분절 **앞** 조각의 아래쪽에 남아야 할 최소 줄 수다.
- `widows` 는 분절 **뒤** 새 조각의 위쪽에 있어야 할 최소 줄 수다.
- 둘을 함께 쓰면 문단이 어느 쪽에서도 한두 줄만 따로 떨어지지 않아 인쇄 품질이 좋아진다.
- 문단 줄 수가 `orphans + widows` 보다 적으면 두 조건을 다 지키며 문단을 나눌 자리가 없다.
- 이때 브라우저는 문단을 통째로 다음 조각으로 넘기거나, 넘길 공간도 없으면 규칙을 어기고 나눈다 (확인 필요 — 구체적인 선택은 구현에 달려 있다).

> **오펀(orphan, 고아 줄)** — 분절 앞 페이지·열 맨 아래에 홀로 남은 문단의 첫 줄.\
> 예: 1열 맨 밑에 다음 문단의 첫 줄만 있고 나머지는 2열에 있는 모습.

### (4) 분절이 없으면 아무 일도 없다

**언제 쓰나** — `widows` 를 적었는데 변화가 없을 때 원인을 찾을 때.

```text
입력:  .plain { widows: 5; }   다단도 아니고 인쇄도 아닌 보통 블록
           │
           ▼
 화면에서 문단이 조각으로 나뉘지 않음 → 분절 지점이 없다
           │
           ▼
결과:  widows 가 따질 「새 조각의 맨 위」가 없으므로 보이는 변화 없음
```

- `widows` 는 분절이 일어날 때만 의미가 있다.
- 다단(`column-count` 등), 인쇄 페이지(`@media print`), 영역 같은 조각 나눔이 있어야 한다.

## 문법 — 형태와 규칙

```html demo
<div class="cols">
  <p>첫째 줄부터 여러 줄로 이어지는 문단이다. 열이 두 개라 이 문단은 중간에서 끊겨 오른쪽 열로 넘어간다. widows 값이 3 이므로 오른쪽 열 맨 위에는 이 문단의 줄이 적어도 세 줄 오도록 브라우저가 분절 자리를 조정한다.</p>
</div>
<style>
  .cols {
    column-count: 2;   /* 두 열로 나눠 분절을 만든다 */
    widows: 3;         /* 새 열 맨 위 최소 3줄 */
    orphans: 2;        /* 앞 열 맨 아래 최소 2줄 */
    width: 320px;
    padding: 12px;
    background: #f1f5f9;
  }
  p { margin: 0; line-height: 1.6; }
</style>
```

> **보이는 것** — 문단이 두 열로 나뉘고, 오른쪽 열이 문단의 줄 몇 개로 시작한다. 오른쪽 열 위에 세 줄 미만이 오게 될 때 왼쪽 열 아래가 비는 모습이 될 수 있다 (코드에서 읽은 것 — 렌더 실측 아님)

- 형태는 `widows: <integer>` 다.
- 값은 양의 정수 하나뿐이다. 키워드 값은 없다(CSS 전역 키워드 `inherit` · `initial` 등은 모든 속성에 쓸 수 있다).
- 0 이나 음수는 양의 정수가 아니라 잘못된 값이다. CSS 는 잘못된 값의 선언을 통째로 버리므로 그 줄은 없었던 것처럼 된다.
- 기본값은 `2` 다. 아무것도 적지 않아도 이미 「새 조각 맨 위 최소 2줄」이다.
- 상속된다. 부모에 적으면 자식 문단이 물려받는다.
- 애니메이션이 되지 않는다. `transition` 으로 값을 바꿔도 사이 값을 거치지 않는다.

| 값 | 뜻 |
|---|---|
| `<integer>` | 양의 정수. 분절 뒤 새 블록 상단에 표시해야 할 최소 줄 수 |
| (기본값) `2` | 새 조각 맨 위에 그 문단의 줄이 적어도 2줄 |
| `1` | 사실상 제한 없음 — 끝 줄 하나만 넘어가도 허용 |
| `0` · 음수 | 잘못된 값 — 선언이 무시된다 |

## 어디서 틀리나

### 1. 기본값을 적어 놓고 효과를 기대한다

원본 예제는 `widows: 2` 를 적는다.
그런데 기본값이 이미 `2` 라서, 부모가 다른 값을 주지 않았다면 이 줄을 지워도 결과가 같다.
`widows` 의 효과를 눈으로 보려면 3 이상처럼 기본값과 다른 값을 넣어 비교해야 한다.

### 2. 「위도우」와 「오펀」을 헷갈린다

타이포그래피에서 widow 는 새 페이지·열 **상단**에 홀로 남은 단락의 **마지막** 줄이다.
orphan 은 반대로 앞 페이지·열 **하단**에 남은 단락의 **첫** 줄이다.
`widows` 는 뒤 조각의 위, `orphans` 는 앞 조각의 아래를 지킨다.
`orphans` 와 함께 쓰면 인쇄 품질이 좋아진다(원본의 팁).

### 3. 분절이 없는 곳에 적고 왜 안 되냐고 한다

보통 화면의 일반 블록에는 열·페이지 경계가 없다.
분절이 없으면 `widows` 가 할 일이 없다.

### 4. 원본 주석의 「고정 높이로 분할 유발」

원본 정답 코드는 `height: 100px` 에 「고정 높이로 분할 유발」이라는 주석을 단다.
그런데 열 나누기 자체는 `column-count: 2` 가 만든다 — 높이를 주지 않아도 문단은 두 열로 나뉜다.
`height` 는 열의 높이를 묶어 한 열에 들어갈 줄 수를 제한하는 쪽에 가깝다 (확인 필요 — 내용이 넘칠 때의 동작은 `column-fill` 등에 따라 다르다).

### 5. 줄 수가 모자란 문단에 큰 값을 준다

`widows` 와 `orphans` 를 합친 수보다 줄이 적은 문단은 규칙을 다 지키며 나눌 수 없다.
문단이 통째로 밀리거나 규칙이 지켜지지 않는 결과가 나올 수 있다.
값을 크게 잡을수록 앞 조각 아래에 빈 공간이 커진다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 기본값 `2` · 상속됨 · 양의 정수만 허용 | CSS 명세(원본 재료) |
| 잘못된 값의 선언은 무시된다 | CSS 문법 규칙 |
| 두 조건을 다 못 지킬 때 문단을 통째로 넘기는지, 규칙을 어기는지 | 브라우저 구현 (확인 필요) |
| 실제로 어떤 브라우저가 다단에서 `widows` 를 지키는지 | 브라우저 구현 (확인 필요) |
| `line-height: 1.6` 의 줄 높이 px 값 | 글자 크기에 달림 — 기본 글자 크기는 브라우저 설정 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 다단 기사에서 열 맨 위에 끝 한 줄만 넘어가는 모양을 막기 | `widows: 2` 이상 (기본값이 이미 2) | 열마다 수동 `<br>` |
| 인쇄용 문서의 페이지 위·아래 외톨이 줄 정리 | `@media print` 안에서 `widows` + `orphans` | 화면용 스타일에만 적기 |
| 짧은 문단(2~3줄)이 많은 글 | 기본값 그대로 | `widows` · `orphans` 를 크게(빈 공간이 커짐) |
| 분절 없는 보통 블록 | (필요 없음) | `widows` — 효과 없음 |

## 핵심 문장

1. **`widows` 는 분절 뒤 새 조각 맨 위에 있어야 할 문단의 최소 줄 수다.**
2. **조건이 모자라면 브라우저가 분절 자리를 앞으로 당겨 줄을 더 넘긴다.**
3. **기본값 2 · 상속됨 · 애니메이션 불가 · 값은 양의 정수뿐이다.**
4. **`orphans` 는 앞 조각 아래, `widows` 는 뒤 조각 위 — 함께 써야 외톨이 줄이 양쪽에서 사라진다.**
5. **분절(다단 · 인쇄 페이지 등)이 없으면 `widows` 는 아무 일도 하지 않는다.**

## 용어 풀이

- **분절(break)** — 내용이 한 조각에 다 들어가지 못해 다음 조각으로 나뉘어 이어지는 것.
- **조각(fragment)** — 분절로 나뉜 내용이 담기는 칸(열 · 페이지 · 영역).
- **위도우(widow, 과부 줄)** — 새 페이지·열 맨 위에 홀로 남은 단락의 마지막 줄.
- **오펀(orphan, 고아 줄)** — 앞 페이지·열 맨 아래에 홀로 남은 단락의 첫 줄.
- **다단(multi-column)** — `column-count` 등으로 한 상자의 내용을 여러 열로 흘려 넣는 레이아웃.
- **상속(inheritance)** — 자식이 값을 따로 받지 않으면 부모의 값을 물려받는 규칙.
- **기본값(initial value)** — 아무 선언도 없고 상속도 받지 않을 때 쓰이는 값.
- **`line-height`** — 한 줄이 차지하는 높이. 단위 없는 수는 글자 크기의 배수다.

## 더 들어가면
