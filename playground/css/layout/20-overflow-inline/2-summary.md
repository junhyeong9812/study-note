## 한눈에 — 쉽게 말하면

**`overflow-inline` 은 「글이 흘러가는 방향으로 넘친 것을 어떻게 할지」 정하는 규칙이다.**
공책에 글을 쓰다가 줄 끝을 넘어갔다고 해 보자.
넘친 글자를 그냥 종이 밖으로 내보낼 수도 있고, 가위로 잘라 버릴 수도 있고, 종이를 옆으로 이어 붙여 밀어 보게 할 수도 있다.
그런데 「줄 끝」이 어디인지는 글을 쓰는 방향에 따라 다르다.
가로쓰기 공책이면 줄 끝은 오른쪽이고, 세로쓰기 공책이면 줄 끝은 아래쪽이다.
CSS 상자도 똑같은 구조다.
`overflow-inline` 은 「오른쪽」이나 「아래쪽」이 아니라 「글이 흐르는 방향」을 기준으로 넘침을 다룬다.

| 비유 | 실체 |
|---|---|
| 공책 한 장 | 크기가 정해진 상자(`.box`) |
| 한 줄에 쓰는 글 | 인라인 방향으로 늘어선 콘텐츠 |
| 줄 끝을 넘어간 글자 | 인라인 방향 넘침 |
| 종이 밖으로 내보내기 | `visible` |
| 가위로 자르기 | `hidden` · `clip` |
| 옆으로 이어 붙여 밀어 보기 | `scroll` · `auto` |
| 가로쓰기 / 세로쓰기 | `writing-mode` |

```text
가로쓰기 (horizontal-tb)          세로쓰기 (vertical-rl)
인라인 방향 = 가로 →               인라인 방향 = 세로 ↓
┌──────────┐                      ┌───┐
│글이 흐르는│방향 →  넘침          │ 글│
└──────────┘                      │ 이│
                                  │ 흐│
                                  └───┘
                                    ↓ 넘침
```

## 이 주제가 답하려는 질문

1. 상자 너비보다 긴 한 줄짜리 콘텐츠는 어떻게 처리되나?
2. 다섯 값(`visible` · `hidden` · `clip` · `scroll` · `auto`)은 서로 무엇이 다른가?
3. 「인라인 방향」은 화면의 가로인가 세로인가 — 무엇이 그것을 정하나?
4. `overflow-x` 와는 어떤 관계인가?

## 동작 방식

### (1) 인라인 방향 넘침이 생기는 조건

**언제 쓰나** — 상자 크기는 고정인데 한 줄로 늘어선 내용이 그보다 길 때 쓴다.

```text
.box { width: 200px; }                 상자 폭이 200px 로 묶인다
.content { white-space: nowrap; }      글이 줄바꿈 없이 한 줄로 이어진다
        │
        ▼
한 줄의 길이 > 상자 폭  →  인라인 방향으로 넘침 발생
        │
        ▼
overflow-inline 값이 그 넘침을 어떻게 다룰지 정한다
```

- 상자 폭이 고정되어야 「넘칠 경계」가 생긴다.
- `white-space: nowrap` 이 없으면 글은 상자 폭에 맞춰 다음 줄로 내려가므로, 인라인 방향으로는 넘치지 않는다.
- 넘침이 생겨야 비로소 `overflow-inline` 의 값이 의미를 가진다.

### (2) 다섯 값이 넘침을 다루는 방식

**언제 쓰나** — 넘친 부분을 보여 줄지, 자를지, 스크롤로 보게 할지 고를 때 쓴다.

```text
넘친 콘텐츠
   │
   ├─ visible → 잘리지 않고 상자 밖으로 삐져나온다 (기본값)
   ├─ hidden  → 상자 경계에서 잘린다
   ├─ clip    → 상자 경계에서 잘리고, 스크롤로도 볼 수 없다
   ├─ scroll  → 넘치든 말든 인라인 방향 스크롤바가 늘 있다
   └─ auto    → 넘칠 때만 인라인 방향 스크롤바가 생긴다
```

- `visible` 은 아무것도 하지 않는다 — 넘친 글자가 테두리 밖에 그대로 그려진다.
- `hidden` 과 `clip` 은 둘 다 자른다.
- 원본 설명은 `clip` 에만 「스크롤 불가」를 붙인다 — 잘린 부분을 스크롤로 꺼내 볼 길까지 막는 쪽이 `clip` 이다.
- `scroll` 은 넘치지 않아도 스크롤바 자리가 있다.
- `auto` 는 넘칠 때만 스크롤바를 만든다 — 그래서 넘침 여부에 따라 모양이 달라진다.

```html demo
<div style="width:200px; overflow-inline:auto; padding:8px; border:2px solid #3b82f6;">
  <div style="white-space:nowrap;">인라인 방향으로 넘치는 매우 긴 콘텐츠입니다.</div>
</div>
```

> **보이는 것** — 파란 테두리 상자 안에 문장이 한 줄로 이어지고, 상자 폭을 넘는 부분은 가로 스크롤로 밀어 봐야 보인다 (코드에서 읽은 것 — 렌더 실측 아님).

### (3) 「인라인 방향」은 writing-mode 가 정한다

**언제 쓰나** — 같은 CSS 를 가로쓰기와 세로쓰기 문서에 함께 쓰고 싶을 때 쓴다.

```text
writing-mode: horizontal-tb  →  글이 왼→오른쪽으로 흐름  →  인라인 = 가로  →  overflow-x 와 같은 일
writing-mode: vertical-rl    →  글이 위→아래로 흐름      →  인라인 = 세로  →  overflow-y 쪽 일
```

- 원본 팁대로 이 속성은 「논리적 속성」이다.
- 수평 쓰기 모드에서는 인라인 방향이 가로라서 `overflow-x` 에 대응한다.
- 세로 쓰기 모드로 바꾸면 글이 위에서 아래로 흐르므로 인라인 방향은 세로가 된다.
- 그러면 같은 `overflow-inline: auto` 가 이번에는 세로 넘침을 다룬다.

> **논리적 속성** — 화면의 위·아래·왼쪽·오른쪽이 아니라 글이 흐르는 방향을 기준으로 정의된 속성.\
> 예: `overflow-inline` 은 가로쓰기에선 가로, 세로쓰기에선 세로를 다룬다.

> **인라인 방향** — 한 줄 안에서 글자가 이어지는 방향.\
> 예: 한국어 가로쓰기에서는 왼쪽에서 오른쪽.

### (4) 상속되지 않고, 애니메이션되지 않는다

**언제 쓰나** — 중첩된 상자나 상태 전환에 이 속성을 걸 때 알아 둔다.

```text
부모 .box { overflow-inline: auto }
   └─ 자식 .content  → 물려받지 않음 → 자기 값은 기본값 visible

.box { overflow-inline: hidden } → :hover 에서 auto
   → 중간 단계 없이 한 번에 바뀜
```

- 원본 기준 상속이 `False` 다 — 부모에 준 값은 부모 상자 하나에만 걸린다.
- 자식이 따로 넘침 처리를 하려면 자식에게 직접 값을 줘야 한다.
- 애니메이션 가능도 `False` 다 — `transition` 을 걸어도 값은 서서히 바뀌지 않고 즉시 바뀐다.

## 문법 — 형태와 규칙

```css
.box {
  width: 200px;            /* 경계를 만든다 */
  overflow-inline: auto;   /* 인라인 방향으로 넘칠 때만 스크롤 */
}
.content {
  white-space: nowrap;     /* 한 줄로 이어서 인라인 넘침을 일으킨다 */
}
```

- 형태: `overflow-inline: visible | hidden | clip | scroll | auto`
- 기본값은 `visible` 이다.
- 상속되지 않는다.
- 애니메이션되지 않는다.

| 값 | 넘친 부분 | 스크롤바 | 언제 |
|---|---|---|---|
| `visible` | 상자 밖에 그대로 보임 | 없음 | 기본 동작을 바꾸지 않을 때 |
| `hidden` | 잘림 | 없음 | 넘친 부분을 감출 때 |
| `clip` | 잘림 | 없음, 스크롤 불가 | 잘린 부분에 다가갈 길까지 막을 때 |
| `scroll` | 스크롤로 봄 | 항상 | 스크롤바 유무로 레이아웃이 흔들리면 안 될 때 |
| `auto` | 스크롤로 봄 | 넘칠 때만 | 대부분의 스크롤 상자 |

## 어디서 틀리나

### 1. 「인라인 = 가로」로 외우기

원본 팁대로 이 속성은 `writing-mode` 에 따라 실제 방향이 달라진다.
가로라고 단정하면 세로쓰기 문서에서 엉뚱한 축이 스크롤된다.
수평 쓰기 모드에서만 `overflow-x` 에 대응한다고 기억한다.

### 2. 값만 주고 넘침을 안 만들기

`overflow-inline: auto` 를 줘도 내용이 줄바꿈되면 인라인 방향으로는 넘치지 않는다.
그러면 스크롤바도 안 생긴다.
예제가 `.content` 에 `white-space: nowrap` 을 둔 이유다.

### 3. `hidden` 과 `clip` 을 같은 것으로 보기

둘 다 자르지만 원본은 `clip` 에만 「스크롤 불가」를 적는다.
잘린 내용에 스크롤로 다가갈 여지까지 없애려면 `clip` 이다.

### 4. `scroll` 과 `auto` 를 같은 것으로 보기

`scroll` 은 넘치지 않아도 스크롤바가 늘 있다.
`auto` 는 넘칠 때만 생긴다.

### 5. 자식에게 물려준다고 생각하기

상속되지 않으므로 부모에 준 값은 자식의 넘침에 쓰이지 않는다.

### 6. `transition` 으로 부드럽게 바꾸려 하기

애니메이션 가능이 아니므로 값은 즉시 바뀐다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 기본값 `visible` · 상속 안 됨 · 애니메이션 안 됨 | CSS 명세의 속성 정의 (원본 재료 기준) |
| 수평 쓰기 모드에서 `overflow-x` 에 대응 | CSS 명세의 논리 ↔ 물리 대응 (원본 팁) |
| 스크롤바의 모양 · 두께 · 항상 보이는지 | 브라우저와 운영체제의 구현 — 같은 `scroll` 도 환경마다 다르게 그려질 수 있다 (확인 필요) |
| 이 속성을 실제로 알아듣는 브라우저 범위 | 브라우저 구현 — 원본에 정보 없음 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 가로·세로쓰기를 모두 지원하는 컴포넌트 | `overflow-inline` | 물리 방향 고정인 `overflow-x` |
| 긴 한 줄(코드, 표 행)을 필요할 때만 밀어 보게 | `overflow-inline: auto` | `visible` (테두리 밖으로 삐져나옴) |
| 스크롤바 유무로 높이가 바뀌면 곤란 | `scroll` | `auto` |
| 넘친 부분을 감추고 스크롤도 막기 | `clip` | `hidden` |
| 넘침을 그대로 보여도 되는 장식 요소 | 기본값 `visible` | 굳이 값 지정 |

## 핵심 문장

1. **`overflow-inline` 은 글이 흐르는 방향의 넘침만 다룬다** — 그 방향은 `writing-mode` 가 정한다.
2. **수평 쓰기 모드에서는 `overflow-x` 와 같은 일을 한다.**
3. **넘침이 있어야 값이 의미를 가진다** — 고정 폭과 `white-space: nowrap` 이 넘침을 만든다.
4. **`hidden`·`clip` 은 자르고, `scroll`·`auto` 는 스크롤로 보여 준다** — `clip` 은 스크롤도 막고, `auto` 는 넘칠 때만 스크롤바를 단다.
5. **상속되지 않고 애니메이션되지 않는다.**

## 용어 풀이

- **넘침(overflow)** — 콘텐츠가 상자의 크기보다 커서 경계를 넘어가는 일.
- **인라인 방향** — 한 줄 안에서 글자가 이어지는 방향.
- **블록 방향** — 줄이 쌓여 가는 방향, 인라인 방향과 직각.
- **논리적 속성** — 물리 방향(가로·세로) 대신 글의 흐름을 기준으로 한 속성.
- **물리적 속성** — 화면의 가로·세로를 기준으로 한 속성, 예: `overflow-x`.
- **`writing-mode`** — 글이 가로로 흐를지 세로로 흐를지 정하는 속성.
- **`white-space: nowrap`** — 줄바꿈을 막아 글을 한 줄로 이어 붙이는 설정.
- **스크롤바** — 넘친 부분을 밀어서 보게 하는 막대.
- **상속** — 부모의 속성값을 자식이 따로 지정하지 않아도 이어받는 것.

## 더 들어가면

- 블록 방향을 다루는 짝 속성으로 `overflow-block` 이 있다 (확인 필요).
- 명세상 한 축이 `visible` 이고 다른 축이 `visible`·`clip` 이 아닌 값이면, `visible` 쪽이 `auto` 로 계산된다고 알려져 있다 (확인 필요).
- `hidden` 은 사용자가 스크롤할 수는 없어도 스크립트로는 스크롤 위치를 바꿀 수 있고, `clip` 은 그것까지 막는다고 알려져 있다 (확인 필요).
- `overflow-inline` 은 지원하는 브라우저가 많지 않다고 알려져 있어, 실무에서는 `overflow-x` 를 함께 적는 경우가 있다 (확인 필요).
