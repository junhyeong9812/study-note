## 한눈에 — 쉽게 말하면

**`place-self` 는 「주차 칸 안에서 내 차를 어디에 세울지 정하는 운전자의 선택」이다.**
주차장(그리드)은 칸을 그어 놓을 뿐이고, 칸 안에서 차를 앞쪽에 붙일지, 가운데 둘지, 칸을 꽉 채울지는 차마다 따로 정할 수 있다.
다른 차의 자리는 바뀌지 않고, 칸을 넘어 옆 칸으로 가지도 않는다.
그리드 아이템도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 주차장 | 그리드 컨테이너 (`display: grid`) |
| 주차 칸 | 그리드 셀(아이템이 차지한 영역) |
| 차 | 그리드 아이템 |
| 칸 안에서 세우는 위치 | `place-self` 값 |
| 주차장 전체 규칙 | 부모의 `place-items` |

```text
┌──────── 셀 ────────┐
│ [차]               │  ← start  : 시작 쪽에 붙는다
│                    │
└────────────────────┘
┌──────── 셀 ────────┐
│                    │
│       [차]         │  ← center : 정중앙
│                    │
└────────────────────┘
┌──────── 셀 ────────┐
│████████████████████│  ← stretch: 칸을 꽉 채운다
│████████████████████│
└────────────────────┘
```

## 이 주제가 답하려는 질문

1. 컨테이너의 정렬은 그대로 두고, 아이템 **하나만** 셀 안에서 다르게 놓으려면 어떻게 하나?
2. 값 하나와 값 둘은 어떻게 다르고, 둘일 때 어느 값이 어느 축으로 가나?
3. `auto` · `start` · `center` · `end` · `stretch` 는 셀 안에서 아이템의 위치와 크기를 어떻게 바꾸나?
4. `place-self` 는 부모의 `place-items` 와 어떻게 맞물리나?

## 동작 방식

### (1) 단축 속성 — 두 속성을 한 줄에

**언제 쓰나** — 세로 정렬과 가로 정렬을 한 번에 적고 싶을 때 쓴다.

```text
place-self: center;          ──►  align-self: center;  justify-self: center;
place-self: start end;       ──►  align-self: start;   justify-self: end;
             └─①─┘ └─②─┘
```

- 값이 하나면 그 값이 `align-self` 와 `justify-self` 양쪽에 똑같이 들어간다.
- 값이 둘이면 첫째가 `align-self`, 둘째가 `justify-self` 로 간다.
- 원본 문법 `place-self: <align-self> <justify-self>?` 의 `?` 는 둘째 값을 생략해도 된다는 뜻이다.

> **단축 속성** — 여러 개별 속성을 한 번에 지정하는 속성이다.\
> 예: `place-self` 는 `align-self` 와 `justify-self` 를 한 줄로 쓴다.

### (2) 두 축 — 블록축과 인라인축

**언제 쓰나** — 두 값의 순서를 헷갈리지 않으려면 축을 먼저 떠올린다.

```text
   인라인축 (justify) ──────────►
  ┌──────────────────────────────┐
  │                              │  │
  │          셀                  │  │ 블록축 (align)
  │                              │  ▼
  └──────────────────────────────┘
  가로로 글을 쓰는 보통의 문서 기준
```

- `align` 은 블록축, 곧 문단이 쌓이는 방향을 맡는다 — 보통 문서에서는 세로다.
- `justify` 는 인라인축, 곧 글자가 흐르는 방향을 맡는다 — 보통 문서에서는 가로다.
- 그래서 `place-self: <세로> <가로>` 순서가 된다 — 흔히 쓰는 「x, y」 순서와 반대다.

> **블록축** — 블록(문단 등)이 차례로 쌓이는 방향의 축이다.\
> 예: 가로쓰기 문서에서는 위→아래 방향이다.

> **인라인축** — 한 줄 안에서 글자가 흐르는 방향의 축이다.\
> 예: 가로쓰기 문서에서는 왼쪽→오른쪽 방향이다.

### (3) 값마다 셀 안에서 일어나는 일

**언제 쓰나** — 아이템 하나만 다른 자리에 두고 싶을 때 그 아이템에 값을 준다.

```text
값          위치(블록축 · 인라인축)       크기
─────────   ─────────────────────────   ─────────────────
start       둘 다 시작 쪽 (좌상단)        내용만큼 줄어든다
center      둘 다 가운데 (정중앙)         내용만큼 줄어든다
end         둘 다 끝 쪽 (우하단)          내용만큼 줄어든다
stretch     —                            셀 전체로 늘어난다
```

- `start` · `center` · `end` 는 아이템을 셀의 한 점에 붙이므로, 아이템은 셀을 다 채우지 않고 내용 크기로 놓인다.
- `stretch` 는 셀을 채우도록 늘린다 — 원본 정답 코드의 주석 「셀 전체로 확장」이 이것이다.
- 「좌상단 · 우하단」은 가로쓰기 · 왼쪽→오른쪽 문서를 기준으로 한 말이다.
- 아이템은 자기 셀 **안에서만** 움직인다 — 다른 셀로 옮겨 가거나 이웃 아이템을 밀지 않는다.

```html demo
<div style="display:grid; grid-template-columns:1fr 1fr; grid-auto-rows:80px; gap:8px; background:#f1f5f9; padding:8px;">
  <div style="background:#3b82f6; color:white; place-self:start;">start</div>
  <div style="background:#8b5cf6; color:white; place-self:center;">center</div>
  <div style="background:#ec4899; color:white; place-self:end;">end</div>
  <div style="background:#f59e0b; color:white; place-self:stretch;">stretch</div>
</div>
```

> **보이는 것** — 파란 상자는 첫 셀 좌상단에 글자 크기만큼, 보라 상자는 둘째 셀 정중앙에, 분홍 상자는 셋째 셀 우하단에 놓이고, 주황 상자만 넷째 셀을 꽉 채운다. (코드에서 읽은 것 — 렌더 실측 아님)

### (4) `auto` 와 부모의 `place-items`

**언제 쓰나** — 아이템 대부분은 컨테이너 규칙을 따르게 두고, 몇 개만 바꾸고 싶을 때 이 관계를 쓴다.

```text
컨테이너  place-items: center
   │
   ├─ 아이템 A  place-self: auto (기본값)  ──►  부모 값 center 를 따른다
   ├─ 아이템 B  place-self: auto           ──►  center
   └─ 아이템 C  place-self: end            ──►  end  (자기 값이 이긴다)
```

- 기본값 `auto` 는 「부모의 `place-items` 값을 따른다」는 뜻이다.
- 아이템에 `auto` 가 아닌 값을 주면 부모 값 대신 그 값이 그 아이템에만 쓰인다.
- 원본 정답 코드는 컨테이너에 정렬을 주지 않고 아이템 넷에 각기 다른 `place-self` 를 줘서 이 「개별 정렬」을 보인다.

> **`place-items`** — 컨테이너에 주는 속성으로, 모든 아이템의 기본 자기 정렬을 한 번에 정한다.\
> 예: `place-items: center` 면 `place-self` 가 `auto` 인 아이템이 모두 셀 정중앙에 놓인다.

## 문법 — 형태와 규칙

```css
.grid {
  display: grid;
  grid-template-columns: 1fr 1fr;
  grid-auto-rows: 120px;
  place-items: start;        /* 모든 아이템의 기본: 좌상단 */
}
.badge   { place-self: center; }      /* 이 아이템만 정중앙 */
.corner  { place-self: end start; }   /* 세로는 끝, 가로는 시작 → 좌하단 */
.full    { place-self: stretch; }     /* 이 아이템만 셀을 채운다 */
.normal  { place-self: auto; }        /* 부모의 start 를 따른다 */
```

- 형태: `place-self: <align-self> <justify-self>?`
- 기본값은 `auto` 다.
- 상속되지 않는다(상속: 아니오).
- 원본 데이터에는 애니메이션 불가로 적혀 있다.

| 값 | 뜻 |
|---|---|
| `auto` | 부모의 `place-items` 값을 따른다 (기본값) |
| `normal` | 레이아웃 모드에 따른 기본 동작 |
| `center` | 양 축 모두 가운데 정렬 |
| `start` | 양 축 모두 시작 정렬 |
| `end` | 양 축 모두 끝 정렬 |
| `self-start` | 아이템 자신의 시작 쪽에 정렬 |
| `self-end` | 아이템 자신의 끝 쪽에 정렬 |
| `stretch` | 늘려서 셀을 채운다 |
| `<align> <justify>` | 블록축과 인라인축을 따로 지정 |

## 어디서 틀리나

### 1. 두 값의 순서를 「가로 세로」로 읽는다

원본 팁대로 두 값을 쓰면 세로 · 가로를 각각 제어하는데, 순서는 **세로(align) 먼저, 가로(justify) 나중**이다.
`place-self: start end` 를 「왼쪽 · 아래」로 읽으면 틀린다 — 세로는 시작(위), 가로는 끝(오른쪽)이라 우상단이다.

### 2. 컨테이너에 걸어 놓고 아무 변화가 없다고 한다

`place-self` 는 **아이템**에 거는 속성이다.
모든 아이템을 한꺼번에 정렬하려면 컨테이너에 `place-items` 를 쓴다.
원본 팁의 핵심도 「해당 아이템**만**」이다.

### 3. `center` 를 주자 아이템이 작아져 놀란다

`center` · `start` · `end` 는 아이템을 셀의 한 점에 붙이므로 셀을 채우지 않고 내용 크기로 줄어든다.
셀을 꽉 채운 모습이 필요하면 `stretch` 를 쓴다.

### 4. 아이템을 다른 셀로 옮기려 한다

`place-self` 는 이미 정해진 셀 **안에서의** 위치만 바꾼다.
어느 셀에 놓일지는 바뀌지 않는다.

### 5. 원본의 「상속」이라는 말을 CSS 상속으로 읽는다

원본의 주장: `auto` 는 「부모의 `place-items` 값을 상속」한다.
왜 의심스러운가: 같은 원본 데이터에 「상속: False」가 함께 적혀 있다.
`auto` 는 CSS 의 상속(부모의 같은 속성 값을 물려받기)이 아니라, 부모의 **다른 속성**(`place-items`) 값을 참조해서 따르는 것이다.
이 문서는 그래서 「상속」 대신 「따른다」로 적는다.

### 6. 「좌상단 · 우하단」을 언제나 참이라고 믿는다

`start` 가 좌상단이 되는 것은 가로쓰기 · 왼쪽→오른쪽 문서에서다.
`start` · `end` 는 축의 시작과 끝을 뜻하는 말이지 「왼쪽 · 위」 자체가 아니다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 값 하나는 두 축에, 값 둘은 align → justify 순서로 들어간다 | CSS 명세(단축 속성의 정의) |
| `start` = 좌상단, `end` = 우하단 | 가로쓰기 · 왼쪽→오른쪽 문서일 때만 참이다 — 명세는 「축의 시작 · 끝」만 정한다 |
| `auto` 는 부모의 `place-items` 를 따른다 | CSS 명세 (원본은 이를 「상속」이라 불렀지만 CSS 상속과 다르다) |
| 애니메이션 불가 | 원본 데이터의 표기 — 명세상 애니메이션 방식은 (확인 필요) |
| 브라우저 지원 범위 | 원본에 없다 — (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 아이템 하나만 셀 정중앙에 | 그 아이템에 `place-self: center` | 컨테이너에 `place-items: center` (전부 바뀐다) |
| 모든 아이템을 같은 자리에 | 컨테이너에 `place-items` | 아이템마다 `place-self` 반복 |
| 세로 · 가로를 다르게 | `place-self: <세로> <가로>` | 「가로 세로」 순서로 적기 |
| 셀을 꽉 채우기 | `stretch` | `center` (내용 크기로 줄어든다) |
| 아이템을 다른 칸으로 옮기기 | 그리드 배치 속성 | `place-self` (셀 안에서만 움직인다) |

## 핵심 문장

1. **`place-self` 는 `align-self` 와 `justify-self` 의 단축 속성이다** — 값 하나는 양쪽에, 값 둘은 세로(align) · 가로(justify) 순서다.
2. **아이템 하나만 자기 셀 안에서 따로 정렬한다** — 다른 아이템과 셀 배치는 그대로다.
3. **기본값 `auto` 는 부모의 `place-items` 를 따른다** — 자기 값을 주면 그 아이템에서만 부모 값을 이긴다.
4. **`start` · `center` · `end` 는 아이템을 내용 크기로 한 점에 붙이고, `stretch` 만 셀을 채운다.**

## 관련 자료

- `align-self` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `justify-self` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `place-items` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- 원본: study-site 항목 데이터 `data/css/grid.json` 의 `grid--place-self`

## 용어 풀이

- **그리드 컨테이너** — `display: grid` 를 준 요소로, 자식들을 행과 열의 칸에 배치한다.
- **그리드 아이템** — 그리드 컨테이너의 직계 자식이다.
- **셀** — 행과 열이 만나 생기는 한 칸이다.
- **단축 속성** — 여러 개별 속성을 한 줄로 지정하는 속성이다.
- **`align-self`** — 블록축(보통 세로) 방향의 자기 정렬 속성이다.
- **`justify-self`** — 인라인축(보통 가로) 방향의 자기 정렬 속성이다.
- **블록축** — 블록이 쌓이는 방향의 축이다.
- **인라인축** — 글자가 흐르는 방향의 축이다.
- **`place-items`** — 컨테이너에 주어 모든 아이템의 기본 자기 정렬을 정하는 속성이다.
- **`fr`** — 그리드에서 남은 공간을 나누는 비율 단위다.
- **상속** — 자식이 부모의 같은 속성 값을 물려받는 CSS 의 동작이다.

## 더 들어가면

- flex 컨테이너에서는 `justify-self` 가 무시되고 `align-self` 만 듣는다고 알려져 있다 — flex 에서 `place-self` 의 가로 값은 효과가 없을 수 있다. (확인 필요)
- `stretch` 는 아이템의 크기가 `auto` 일 때만 늘어난다 — `width` · `height` 를 직접 주면 늘어나지 않는다. (확인 필요)
- 그리드 아이템의 `normal` 은 이미지처럼 고유 크기가 있는 요소가 아니면 대개 `stretch` 처럼 동작한다 — 그래서 정렬을 안 줘도 셀이 차 보인다. (확인 필요)
- `self-start` · `self-end` 는 아이템 자신의 쓰기 방향이 컨테이너와 다를 때(`writing-mode` · `direction` 이 다를 때) `start` · `end` 와 달라진다. (확인 필요)
- 블록 레이아웃의 `justify-self` 지원은 비교적 최근에 들어왔다는 이야기가 있다. (확인 필요)
