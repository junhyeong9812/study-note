## 한눈에 — 쉽게 말하면

**`masonry-auto-flow` 는 「줄이 여럿인 계산대에서 손님을 어느 줄에 세울지 정하는 규칙」이다.**
안내원이 「지금 가장 짧은 줄로 가세요」라고 할 수도 있고, 「1번, 2번, 3번 줄 차례대로 가세요」라고 할 수도 있다.
메이슨리 레이아웃도 똑같은 구조다.
열(트랙)이 계산대 줄이고, 높이가 제각각인 아이템이 손님이다.
아이템이 하나씩 들어올 때마다 어느 열 밑에 붙일지를 이 속성이 정한다.

| 비유 | 실체 |
|---|---|
| 계산대 줄 | 메이슨리 축의 트랙(열) |
| 손님 | 그리드 아이템 |
| 줄의 현재 길이 | 그 열에 이미 쌓인 아이템 높이의 합(+ 간격) |
| 「가장 짧은 줄로」 | `pack` |
| 「다음 줄로 차례대로」 | `next` |
| 예약 손님을 먼저 세우기 | `definite-first` |
| 예약 손님도 도착 순서대로 | `ordered` |

```text
  열1   열2   열3
 ┌──┐ ┌──┐ ┌──┐
 │1 │ │  │ │3 │
 │  │ │2 │ └──┘   ← 다음 아이템은 어디로?
 └──┘ │  │        pack : 가장 짧은 열(열3) 밑
      └──┘        next : 마지막에 넣은 열(열3)의 다음 열(열1) 밑
```

## 이 주제가 답하려는 질문

1. 높이가 제각각인 아이템을 빈칸 없이 위로 붙여 쌓을 때, 다음 아이템은 어느 열로 가나?
2. 「가장 짧은 열」과 「DOM 순서대로 다음 열」은 결과가 어떻게 다른가?
3. `grid-column` 으로 위치를 정해 둔 아이템과 정하지 않은 아이템 가운데 무엇을 먼저 놓나?
4. 이 기능을 지원하지 않는 브라우저에서는 무엇이 보이나?

## 동작 방식

### (1) 메이슨리 축 만들기 — `grid-template-rows: masonry`

**언제 쓰나** — 핀터레스트 같은 「워터폴」 화면처럼 열은 고정하고 세로로는 아이템을 빈틈 없이 위로 붙여 쌓고 싶을 때 쓴다.

```text
입력 코드                                 무엇이 일어나나                         결과
display: grid;                       →   그리드 컨테이너가 된다
grid-template-columns: repeat(3,1fr) →   열 트랙 3개(같은 너비)               열 3개
grid-template-rows: masonry;         →   행 축은 행 트랙을 만들지 않는다       각 열이 독립된 「기둥」
                                         아이템을 열 안에서 위로 바짝 붙인다    아래 끝이 들쭉날쭉한 벽돌 벽
```

- 열 쪽은 보통 그리드처럼 트랙이 정해진다.
- 행 쪽은 `masonry` 라서 「행」이라는 칸이 없다.
- 그래서 한 아이템이 옆 열의 큰 아이템 높이에 맞춰 칸을 비워 두지 않는다.
- 각 열은 쌓인 높이(이 문서에서는 「열의 현재 길이」라 부른다)를 따로 가진다.
- `masonry-auto-flow` 는 이 상태에서 「다음 아이템을 어느 열에 붙이나」만 정한다.

> **메이슨리 레이아웃** — 한 축은 트랙으로 고정하고 다른 축은 아이템을 빈칸 없이 이어 붙이는 배치.\
> 예: 열 3개에 높이가 다른 사진 카드를 위에서부터 붙여 쌓는 갤러리.

> **트랙** — 그리드의 한 열 또는 한 행.\
> 예: `repeat(3, 1fr)` 은 열 트랙 3개를 만든다.

### (2) `pack` — 가장 짧은 열로 (기본값)

**언제 쓰나** — 열들의 아래 끝을 되도록 고르게 맞추고 싶을 때 쓴다. 기본값이라 아무것도 안 쓰면 이것이다.

```text
아이템 높이: 1=100, 2=40, 3=60, 4=50  (gap 없음으로 단순화)

1~3번 배치 후 열 길이      4번 차례                       결과
열1 100                →  가장 짧은 열 = 열2(40)     →   4번은 열2, 40~90 위치
열2  40
열3  60
```

- 처음에는 세 열 모두 길이가 0 이라 1·2·3번이 열1·열2·열3에 차례로 들어간다(같은 길이면 앞 열 — 원본에 근거 없음, 추론).
- 4번 차례에 각 열의 현재 길이를 비교한다.
- 가장 짧은 열2 밑에 4번을 붙인다.
- `gap` 이 있으면 열 길이에 간격이 더해진 값으로 비교한다.

### (3) `next` — DOM 순서대로 다음 열로

**언제 쓰나** — 아이템이 열을 1→2→3→1… 처럼 돌아가며 들어가야 읽는 순서가 예측될 때 쓴다.

```text
같은 높이 1=100, 2=40, 3=60, 4=50

마지막 배치 = 3번(열3)    →   그다음 열 = 열1(한 바퀴 돎)   →   4번은 열1, 100~150 위치
```

- 열의 길이는 보지 않는다.
- 바로 앞 아이템이 들어간 열의 다음 열을 고른다.
- 그래서 열 길이 차이가 커져도 그대로 돌아가며 넣는다.
- 결과적으로 아래 끝이 `pack` 보다 더 들쭉날쭉해질 수 있다.

### (4) `definite-first` 와 `ordered` — 위치가 정해진 아이템의 차례

**언제 쓰나** — 몇몇 아이템에 `grid-column: 3` 처럼 열을 직접 지정했을 때, 그 아이템을 먼저 놓을지 순서대로 놓을지 정한다.

```text
아이템: A(열 미지정) B(grid-column:3) C(열 미지정)

definite-first : B 를 먼저 열3에 놓는다 → 그다음 A, C 를 pack/next 규칙대로
ordered        : A → B(열3) → C 를 DOM 순서대로 하나씩 놓는다
```

- `definite-first` 는 위치가 지정된 아이템을 먼저 배치한다(원본은 이것도 기본값이라 적는다).
- `ordered` 는 지정 여부와 상관없이 모든 아이템을 순서대로 배치한다.
- 두 갈래(`pack`/`next` 와 `definite-first`/`ordered`)는 서로 다른 질문에 답하므로 함께 쓸 수 있다.

> **위치가 지정된 아이템** — `grid-column` 등으로 들어갈 트랙을 직접 정한 아이템(원본의 「위치가 지정된 아이템」).\
> 예: `.hero { grid-column: 1 / 3; }`

### (5) 지원하지 않는 브라우저에서

**언제 쓰나** — 실험적 기능이라 대부분의 환경에서 이 경로를 탄다고 보고 대비해야 한다.

```text
grid-template-rows: masonry;   →   값을 모르는 브라우저는 선언 전체를 버린다   →   평범한 그리드
masonry-auto-flow: next;       →   모르는 속성도 버린다                         →   영향 없음
```

- CSS 는 모르는 속성이나 값이 잘못된 선언을 무시하고 나머지를 계속 적용한다.
- 그러면 행은 자동 행 트랙이 되고, 아이템은 행 단위로 1·2·3 / 4·5 처럼 채워진다.
- 한 행의 높이는 그 행에서 가장 높은 아이템에 맞춰지고, 키 작은 아이템 밑에는 빈칸이 생긴다.

```html demo
<div style="display:grid; grid-template-columns:repeat(3,1fr); grid-template-rows:masonry; masonry-auto-flow:pack; gap:8px; padding:8px; background:#f1f5f9;">
  <div style="height:100px; background:#3b82f6;">1</div>
  <div style="height:40px; background:#8b5cf6;">2</div>
  <div style="height:60px; background:#ec4899;">3</div>
  <div style="height:50px; background:#f59e0b;">4</div>
</div>
```

> **보이는 것** — 지원 환경이면 4번이 2번(가장 짧은 열) 밑에 붙고, 미지원 환경이면 4번이 둘째 행 첫 칸에 놓이며 2·3번 밑이 비어 보인다. (코드에서 읽은 것 — 렌더 실측 아님)

## 문법 — 형태와 규칙

```css
.wall {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: masonry;          /* 메이슨리 축을 만든다 — 없으면 아래 줄은 할 일이 없다 */
  gap: 8px;
  masonry-auto-flow: next ordered;      /* 다음 열로 + 모두 순서대로 */
}
.wall .pinned { grid-column: 3; }       /* 위치가 지정된 아이템 */
```

- 문법: `masonry-auto-flow: [ pack | next ] || [ definite-first | ordered ]`.
- `||` 는 「둘 중 하나 또는 둘 다, 순서 무관」이라는 뜻이다.
- 기본값은 `pack` 이다.
- 상속되지 않는다(`inherit` 를 쓰지 않는 한 부모 값이 내려오지 않는다).
- 애니메이션할 수 없다 — `transition` 을 걸어도 중간 단계 없이 바뀐다.

| 값 | 뜻 |
|---|---|
| `pack` | 가장 빈(짧은) 트랙에 아이템 배치 (기본값) |
| `next` | DOM 순서대로 다음 트랙에 배치 |
| `definite-first` | 위치가 지정된 아이템을 먼저 배치 (원본 표기: 기본값) |
| `ordered` | 모든 아이템을 순서대로 배치 |
| `pack definite-first` | 빈 공간 채우기 + 지정 아이템 우선 |
| `next ordered` | 순차 배치 + 모두 순서대로 |

## 어디서 틀리나

### 1. 실험적 기능이다

- 원본 팁: 아직 실험적 기능이다.
- Firefox 에서 `layout.css.grid-template-masonry-value.enabled` 플래그를 켜야 쓸 수 있다.
- 플래그는 사용자가 직접 켜는 것이라 일반 방문자 화면에서는 꺼져 있다고 봐야 한다.
- 그래서 원본은 프로덕션에서 JavaScript 라이브러리 사용을 권장한다.

### 2. `grid-template-rows: masonry` 없이 쓰면 아무 일도 없다

- 이 속성은 메이슨리 레이아웃 안에서의 배치만 정한다.
- 평범한 그리드에서 자동 배치를 바꾸는 속성은 `grid-auto-flow` 다.

### 3. 「빈틈 없이」는 위쪽 이야기다

- 원본 정답 코드 주석은 「높이가 다른 아이템을 빈틈 없이 쌓음」이라 적는다.
- 아이템 위쪽(열 안)은 빈틈이 없지만, 열들의 아래 끝은 높이가 달라 맞지 않는다.
- `pack` 은 차이를 줄일 뿐 없애지 않는다.

### 4. 기본값 두 개의 표기

- 원본의 「기본값」 줄은 `pack` 하나만 적지만, 값 목록은 `definite-first` 도 기본값이라 적는다.
- 두 갈래가 따로 있으니 각 갈래의 기본이 `pack` 과 `definite-first` 라는 뜻으로 읽힌다(원본에 근거 없음 — 추론).

### 5. 화면 순서와 DOM 순서가 어긋난다

- `pack` 은 길이로 열을 고르므로 4번이 1번 아래가 아니라 엉뚱한 열에 갈 수 있다.
- 눈으로 읽는 순서와 탭 키 이동 순서(DOM 순서)가 달라질 수 있다.
- 순서가 중요하면 `next` 를 고려한다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 실험 · 학습, 플래그를 켠 Firefox | `grid-template-rows: masonry` + `masonry-auto-flow` | — |
| 일반 사용자에게 내보내는 사이트 | JavaScript 메이슨리 라이브러리 | 이 속성에만 기대기 |
| 아래 끝을 고르게 | `pack` | `next` |
| 열을 돌아가며 순서 유지 | `next` (`ordered` 함께) | `pack` |
| 평범한 그리드의 빈칸 메우기 | `grid-auto-flow: dense` | `masonry-auto-flow` |

## 핵심 문장

1. **`masonry-auto-flow` 는 메이슨리 축에서 다음 아이템을 붙일 열을 고르는 규칙이다.**
2. **`pack` 은 가장 짧은 열, `next` 는 직전 열의 다음 열을 고른다.**
3. **`definite-first` 는 위치 지정 아이템을 먼저, `ordered` 는 모두를 DOM 순서대로 놓는다.**
4. **`grid-template-rows: masonry` 가 있어야 의미가 있고, 미지원 환경에서는 선언이 버려져 평범한 그리드가 된다.**
5. **실험적 기능이라 프로덕션에서는 JavaScript 라이브러리를 쓴다.**

## 관련 자료

- `grid-template-columns` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `grid-template-rows` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- `grid-auto-flow` — 같은 사이트의 관련 항목(이 폴더에 없어 링크를 걸지 않았다)
- 원본: study-site 항목 데이터 `data/css/grid.json` 의 `masonry-auto-flow`

## 용어 풀이

- **메이슨리(벽돌 · 워터폴) 레이아웃** — 열은 고정하고 세로로 아이템을 빈칸 없이 붙여 쌓는 배치.
- **트랙** — 그리드의 한 열 또는 한 행.
- **열의 현재 길이** — 이 문서에서 쓰는 말로, 그 열에 쌓인 아이템 높이와 간격의 합.
- **위치가 지정된 아이템** — `grid-column` 등으로 들어갈 트랙을 직접 정한 아이템.
- **DOM 순서** — HTML 에 적힌 요소의 순서.
- **실험적 기능** — 명세와 구현이 확정되지 않아 플래그 등으로만 켜지는 기능.
- **플래그** — 브라우저 설정에서 켜고 끄는 시험용 스위치.
- **`||` (문법 표기)** — 앞뒤 항목 중 하나 이상을 순서와 관계없이 쓸 수 있다는 뜻.

## 더 들어가면

- 메이슨리 명세는 CSS Grid Layout Level 3 초안에서 다뤄졌고, 문법을 둘러싼 논의가 길게 이어졌다 (확인 필요).
- 논의 과정에서 `masonry-auto-flow` 를 대신하는 새 속성 이름이나 별도 `display` 값이 제안되었다는 이야기가 있다 (확인 필요).
- `pack` 이 「가장 짧은 열」을 고를 때 아주 작은 차이는 같다고 보는 허용 오차 개념이 초안에 있었다 (확인 필요).
- Safari 의 시험판 브라우저에서도 메이슨리 구현을 시험했다는 소식이 있다 (확인 필요).
