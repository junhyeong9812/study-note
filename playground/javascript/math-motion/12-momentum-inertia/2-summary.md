## 한눈에 — 쉽게 말하면

**관성 이동은 「얼음판 위에서 밀어 보낸 컵」이다.**
손으로 컵을 밀다가 손을 떼면 컵은 그 빠르기 그대로 미끄러지기 시작한다.
얼음판에도 약한 마찰이 있어서 컵은 조금씩 느려지다가 결국 선다.
벽에 부딪히면 튕겨 나오는데, 튕긴 뒤에는 부딪히기 전보다 느리다.
드래그한 카드를 놓았을 때 미끄러지는 효과도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 손으로 미는 동안 | 드래그 중(`dragging === true`) — 카드가 마우스를 그대로 따라간다 |
| 손을 떼는 순간의 빠르기 | 마지막으로 잰 마우스 변위(`velX`, `velY`) |
| 얼음판의 마찰 | 매 프레임 속도에 곱하는 `friction` (예: `0.95`) |
| 벽에서 튕겨 나옴 | 속도에 음수 `bounce` (예: `-0.5`)를 곱함 |
| 컵의 자리 | 카드 중심 좌표 `posX`, `posY` |

```text
  드래그 중                 놓은 뒤 (매 프레임)
  ──────────               ─────────────────────────────
  마우스 →→→ 카드 따라감    속도 × 0.95 → 위치 += 속도 → 벽이면 튕김
  속도 = 마우스 변위        ●──────●─────●────●───●──●─● 멈춤
                           (간격이 점점 줄어든다)
```

## 이 주제가 답하려는 질문

1. 손을 떼는 순간의 「빠르기」를 어떻게 재나?
2. 놓은 뒤 카드는 어떤 규칙으로 움직이고, 왜 점점 느려지다 서나?
3. 벽에 닿으면 무엇을 바꿔야 튕겨 나오나?
4. 계산한 위치 · 속도를 화면에 어떻게 반영하나?

## 동작 방식

이 기법의 공식은 세 줄이다.

```text
velocity = currentPos - prevPos   ← 드래그 중: 속도를 잰다
position += velocity              ← 매 프레임: 속도만큼 옮긴다
velocity *= friction              ← 매 프레임: 마찰로 깎는다
```

> **관성(inertia, momentum)** — 움직이던 물체가 밀어 주는 힘이 없어도 계속 움직이려는 성질.\
> 예: 카드를 놓은 뒤에도 마지막 속도로 계속 미끄러진다.

### (1) 드래그 중 — 속도를 잰다

**언제 쓰나** — 사용자가 카드를 잡고 움직이는 동안이다.
놓는 순간 쓸 「마지막 속도」를 이때 계속 새로 적어 둔다.

```text
mousedown(카드)      dragging = true, velX = velY = 0, prevMouse = 지금 마우스
      │
mousemove(window)    dx = 지금 마우스 X - prevMouseX
      │              velX = dx   (속도 = 직전 이벤트와의 변위)
      │              posX += dx  (카드가 마우스를 그대로 따라감)
      │              prevMouseX = 지금 마우스 X
      ▼
mouseup(window)      dragging = false  → 이제 (2)의 관성만 남는다
```

- 잡는 순간 속도를 0 으로 지운다 — 미끄러지던 카드를 잡으면 그 자리에서 멈춰야 하기 때문이다.
- 이동량 `dx` 를 위치에 더하고, 같은 값을 속도로 적어 둔다.
- `mousemove` 와 `mouseup` 은 `window` 에 건다 — 마우스가 빠르게 움직여 카드 밖으로 벗어나도 놓치지 않으려는 것이다.
- 드래그 중에는 (2)의 마찰 · 벽 검사가 돌지 않는다.

### (2) 놓은 뒤 — 마찰로 감속하는 관성 이동

**언제 쓰나** — `dragging` 이 `false` 인 모든 프레임이다.
`requestAnimationFrame` 이 부르는 `animate()` 안에서 매 프레임 한 번 돈다.

> **requestAnimationFrame** — 브라우저가 다음 화면을 그리기 직전에 콜백을 한 번 불러 달라고 맡기는 함수.\
> 예: `animate()` 끝에서 `requestAnimationFrame(animate)` 를 부르면 프레임마다 반복된다.

```text
프레임 0   velX = 10
프레임 1   velX = 10 × 0.95   = 9.5     posX += 9.5
프레임 2   velX = 9.5 × 0.95  = 9.025   posX += 9.025
프레임 3   velX ≈ 8.57                   posX += 8.57
   …        (매번 5%씩 줄어든다)
```

- 순서는 「속도에 마찰을 먼저 곱하고 → 그 속도만큼 위치를 옮긴다」다.
- n 프레임 뒤 속도는 `v₀ × friction^n` 이다 — 같은 비율로 계속 줄어드는 지수 감쇠다.
- 그래서 속도는 0 에 계속 가까워지지만, 수학적으로 정확히 0 이 되지는 않는다.
- 놓은 뒤 미끄러지는 총거리는 등비급수 합 `v₀ × f + v₀ × f² + … = v₀ × f / (1 − f)` 다(`f` 는 `friction`).
- `f = 0.95` 이면 `f / (1 − f) = 0.95 / 0.05 = 19` 라서, 놓을 때 속도의 19 배만큼 미끄러진다(벽이 없을 때의 이론값).
- `friction` 이 0 이면 첫 프레임에 속도가 0 이 되어 즉시 멈추고, 1 이면 속도가 줄지 않아 영원히 미끄러진다.

> **지수 감쇠(exponential decay)** — 매 단계 같은 비율을 곱해 줄어드는 것.\
> 예: 10 → 9.5 → 9.025 → … 처럼 줄어드는 양은 점점 작아진다.

> **마찰 계수(friction)** — 매 프레임 속도에 곱해 남길 비율.\
> 예: `0.95` 는 매 프레임 속도의 5% 를 잃는다는 뜻이다.

### (3) 벽 반사 — 위치를 고정하고 속도를 뒤집는다

**언제 쓰나** — (2)에서 옮긴 뒤 카드가 컨테이너 밖으로 삐져나갔을 때다.

```text
왼쪽 벽 검사:  posX - hw < 0 ?        (hw = 카드 절반 폭)
                 │ 예
                 ▼
               posX = hw              ← 카드 가장자리를 벽에 딱 붙인다
               velX *= bounce         ← bounce = -0.5 : 방향 반전 + 절반으로
결과:  velX = -9.5  →  +4.75  (오른쪽으로, 더 느리게 튕겨 나온다)
```

- 카드 좌표는 중심이므로, 가장자리는 「중심 ± 절반 크기」로 구한다(`hw`, `hh`).
- 넷 벽(왼쪽 · 오른쪽 · 위 · 아래)을 각각 따로 검사하고, 왼쪽 · 오른쪽은 `velX`, 위 · 아래는 `velY` 만 바꾼다.
- 위치를 경계로 되돌리는 줄이 없으면, 카드가 벽 밖에 남아 다음 프레임에 또 반전되며 벽에 끼일 수 있다.
- 팁의 표현으로는 「속도를 음수로 뒤집고 bounce 계수(0~1)를 곱한다」이다.
  원본 코드는 두 일을 한 상수 `-0.5` 에 합쳐 두었다.

> **반사 계수(bounce)** — 벽에 부딪혔을 때 속도에 곱하는 값.\
> 예: `-0.5` 는 방향을 뒤집고 빠르기를 절반으로 만든다.

### (4) 화면 반영 — 위치 · 기울기 · 수치 표시

**언제 쓰나** — 드래그 중이든 아니든 매 프레임 마지막에 한다.

```text
card.style.left = posX + 'px'
card.style.top  = posY + 'px'
card.style.transform = translate(-50%, -50%) rotate(velX × 0.5 deg)
readout ← "velocity: (velX, velY) | speed: hypot(velX, velY) px/frame"
requestAnimationFrame(animate)   ← 다음 프레임 예약
```

- `left` · `top` 은 원래 카드의 왼쪽 위 모서리를 정한다.
  `translate(-50%, -50%)` 로 카드를 자기 크기의 절반만큼 되돌려, `posX`, `posY` 가 카드 **중심**이 되게 한다.
- `rotate(velX * 0.5 deg)` 는 가로 속도에 비례해 카드를 기울인다 — 움직이는 방향이 느껴지게 하는 연출이다.
- `Math.hypot(velX, velY)` 는 속도 벡터의 크기 `√(velX² + velY²)` 다.
- `toFixed(1)` 로 소수 한 자리까지 표시한다.
- 처음에 `animate()` 를 한 번 불러 반복을 시작한다.

> **속도 벡터** — 가로 성분과 세로 성분을 묶은 속도.\
> 예: `(3, 4)` 의 크기(speed)는 `Math.hypot(3, 4)` = 5 다.

## 문법 — 형태와 규칙

한 축만 남긴 최소 예제다.

```javascript
let pos = 0, vel = 0;
const friction = 0.95, bounce = -0.5, min = 0, max = 300;

function step() {
  vel *= friction;            // 마찰
  pos += vel;                 // 이동
  if (pos < min) { pos = min; vel *= bounce; }  // 벽 반사
  if (pos > max) { pos = max; vel *= bounce; }
  box.style.left = pos + 'px';
  requestAnimationFrame(step);
}
step();
```

- 상태는 위치 · 속도 · 드래그 여부 · 직전 마우스 좌표 넷이다.
- 속도는 「직전 좌표와의 차」로 잰다: `velocity = currentPos - prevPos`.
- 관성 구간에서는 매 프레임 `velocity *= friction` → `position += velocity` 를 한다.
- `friction` 은 0 과 1 사이 — 팁은 0.95~0.98 이 자연스럽다고 한다.
- `bounce` 는 음수(방향 반전)이고, 그 크기(0~1)가 튕긴 뒤 남는 빠르기 비율이다.
- 벽에 닿으면 위치를 경계로 되돌린 뒤 속도를 바꾼다.

| 값 | 결과 |
|---|---|
| `friction = 0` | 놓는 즉시 멈춘다 |
| `friction = 0.95` | 매 프레임 5% 감속 — 비교적 빨리 선다 |
| `friction = 0.98` | 매 프레임 2% 감속 — 더 오래 미끄러진다 |
| `friction = 1` | 줄지 않아 영원히 미끄러진다 |
| `bounce = -1` | 빠르기 그대로 튕긴다 |
| `bounce = -0.5` | 절반 빠르기로 튕긴다 |
| `bounce = 0` | 벽에 붙어 그 축의 움직임이 멈춘다 |

## 어디서 틀리나

### 1. `friction` 범위를 벗어난다

팁대로 0.95~0.98 이 자연스럽다.
0 에 가까우면 놓자마자 서서 관성이 느껴지지 않고, 1 이면 끝없이 미끄러진다.
1 보다 크면 매 프레임 속도가 커져 오히려 가속한다.

### 2. 벽에서 속도를 뒤집지 않거나 위치를 되돌리지 않는다

반사의 핵심은 「속도를 음수로 뒤집고 bounce 계수(0~1)를 곱한다」이다.
`bounce` 를 양수로 두면 속도 방향이 그대로라 카드가 벽에 계속 붙어 있게 된다.
위치를 경계로 되돌리지 않으면 카드가 벽 밖에 남아 매 프레임 반전을 반복할 수 있다.

### 3. 마우스를 멈춘 채 놓아도 날아간다

`velX` 는 마지막 `mousemove` 때의 변위로 남는다.
사용자가 빠르게 끌다가 멈춘 뒤 한참 있다가 놓아도, 멈춤은 `mousemove` 를 일으키지 않으므로 옛 속도가 그대로 남아 카드가 미끄러진다.
흔한 보완은 마지막 이동 시각을 재어 오래됐으면 속도를 0 으로 두는 것이다(원본에 근거 없음 — 추론).

### 4. 드래그 중에는 벽 검사가 없다

벽 검사는 `if (!dragging)` 안에만 있다.
그래서 끄는 동안 카드는 컨테이너 밖으로 나갈 수 있고(`overflow: hidden` 이라 잘려 보인다), 놓은 첫 프레임에 경계 안으로 순간 이동한다.

### 5. 속도의 단위 — 원본 주석이 의심스럽다

원본 주석은 마우스 변위를 「프레임당 이동 픽셀」이라 부른다.
그러나 `dx` 는 **직전 `mousemove` 이벤트**와의 차이다.
`mousemove` 가 화면 프레임과 같은 간격으로 온다는 보장은 없으므로, 「이벤트당 이동 픽셀」을 「프레임당」으로 그대로 쓰는 셈이다.
그래서 놓는 순간의 빠르기가 손의 실제 빠르기와 어긋날 수 있다(확인 필요).

### 6. 「0.5 는 절반 에너지 손실」 — 원본 주석이 의심스럽다

원본 주석은 `bounce = -0.5` 를 「절반 에너지 손실」이라 적는다.
그러나 운동에너지는 속도의 제곱에 비례하므로, 속도가 절반이 되면 에너지는 1/4 만 남는다(3/4 손실).
「속도가 절반이 된다」가 정확한 말이다.

### 7. 좌표가 중심이라는 것을 잊는다

`posX`, `posY` 는 `translate(-50%, -50%)` 덕분에 카드 중심이다.
`transform` 을 바꾸면서 이 `translate` 를 빠뜨리면 좌표가 왼쪽 위 모서리로 바뀌어, `hw` · `hh` 로 하는 벽 검사가 어긋난다.
원본도 회전을 넣을 때 `translate(-50%, -50%)` 를 함께 다시 적는다.

### 8. 마우스 이벤트만 다룬다

예제는 `mousedown` · `mousemove` · `mouseup` 만 듣는다.
키워드에 「스와이프」가 있지만, 터치 화면의 손가락 이동은 이 코드만으로 다뤄지지 않을 수 있다(원본에 근거 없음 — 추론).

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 카드 · 지도 · 목록을 던지듯 밀어 보내기 | 속도 측정 + `friction` 감속 | 놓는 즉시 멈추는 단순 드래그 |
| 영역 안에서 튕기며 멈추게 | 경계 고정 + 음수 `bounce` | 위치만 자르고 속도는 그대로 두기 |
| 정해진 시간 안에 정확한 자리로 가야 함 | CSS transition · 이징 함수 | 끝점을 모르는 관성 이동 |
| 아주 자연스러운 감속 | `friction` 0.95~0.98 | 0 근처(즉시 멈춤) · 1(영원히) |

## 핵심 문장

1. **속도는 직전 좌표와의 차다** — 드래그하는 동안 계속 새로 적어 두고, 놓는 순간의 값이 관성의 출발 속도가 된다.
2. **놓은 뒤에는 매 프레임 「속도 × 마찰 → 위치 += 속도」** — 같은 비율로 줄어드는 지수 감쇠라 총거리는 `v₀ × f / (1 − f)` 다.
3. **벽 반사는 「경계로 되돌리고 속도를 뒤집어 줄인다」** — 음수 `bounce` 하나로 반전과 감쇠를 함께 한다.
4. **좌표는 카드 중심이다** — `translate(-50%, -50%)` 와 절반 크기 `hw` · `hh` 가 짝을 이룬다.

## 용어 풀이

- **관성(momentum, inertia)** — 밀어 주지 않아도 움직이던 대로 움직이려는 성질.
- **속도 벡터** — 가로 성분 `velX` 와 세로 성분 `velY` 를 묶은 속도.
- **speed** — 속도 벡터의 크기, `Math.hypot(velX, velY)`.
- **마찰 계수(friction)** — 매 프레임 속도에 곱해 남길 비율.
- **지수 감쇠** — 매 단계 같은 비율을 곱해 줄어드는 것.
- **등비급수** — 일정한 비율로 줄어드는 항들의 합, 여기서는 미끄러지는 총거리.
- **반사 계수(bounce)** — 벽에서 속도에 곱하는 음수, 크기가 남는 빠르기 비율.
- **`requestAnimationFrame`** — 다음 화면을 그리기 전에 콜백을 한 번 불러 달라고 맡기는 함수.
- **변위** — 두 시점 사이 위치의 차.
- **드래그** — 마우스 버튼을 누른 채 끌어 옮기는 조작.

- 속도가 아주 작아지면(예: 0.01 미만) 0 으로 잘라 반복 계산을 멈추는 처리도 흔하다(확인 필요).
