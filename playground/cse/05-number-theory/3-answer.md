## 퀴즈 정답

### 1. q = -2, r = 3

`q = ⌊a/b⌋ = ⌊-7/5⌋ = ⌊-1.4⌋ = -2` 다.
`r = a - bq = -7 - 5·(-2) = -7 + 10 = 3` 이다.
검산: `5·(-2) + 3 = -7` 이고 `0 ≤ 3 < 5` 를 만족한다.
`q = -1`, `r = -2` 도 `-7 = 5·(-1) + (-2)` 를 만족하지만, 나머지는 `0 ≤ r < b` 여야 하므로 정리가 말하는 유일한 답이 아니다.
근거: 장 본문 「2.1 나눗셈 정리」의 조건 `0 ≤ r < b` 와 `q = ⌊a/b⌋`.
(직접 계산한 값 — 실행하지 않음)

### 2. n 의 배수 부분은 나머지에 영향을 주지 않기 때문이다

`a = nq₁ + a'`, `b = nq₂ + b'` 로 쓰면 `a·b = n(nq₁q₂ + q₁b' + q₂a') + a'b'` 가 된다.
앞부분은 `n` 의 배수라 `n` 으로 나눈 나머지에 아무것도 보태지 않는다.
그래서 `(ab) mod n = (a'b') mod n` 이고, 덧셈과 거듭제곱도 같은 논리로 보존된다.
따라서 곱할 때마다 `mod n` 으로 줄여 둔 작은 수로 계산을 이어 가도 최종 나머지는 같다.
이 덕분에 중간값이 항상 `n` 미만으로 유지되고, 빠른 모듈러 거듭제곱이 가능하다.
근거: 장 본문 「2.2 합동 — 합동의 산술」.

### 3. 7²⁵⁶ ≡ 9 (mod 13)

본문의 계산을 이어 제곱을 거듭한다.

```text
7^2   = 49        ≡ 10 (mod 13)
7^4   ≡ 10^2 = 100 ≡ 9
7^8   ≡ 9^2  = 81  ≡ 3
7^16  ≡ 3^2  = 9   ≡ 9
7^32  ≡ 9^2  = 81  ≡ 3
7^64  ≡ 3^2        ≡ 9
7^128 ≡ 9^2        ≡ 3
7^256 ≡ 3^2        ≡ 9
```

`256 = 2^8` 이라 제곱을 여덟 번 하면 된다.
검산: 페르마 소정리로 `7^12 ≡ 1 (mod 13)` 이고, `256 = 12·21 + 4` 이므로 `7^256 ≡ 7^4 ≡ 9` 다 — 같은 값이다.
근거: 장 본문 「2.2 합동」의 CS 연결, 「5.1 페르마 소정리」.
(직접 계산한 값 — 실행하지 않음)

### 4. gcd(84, 36) = 12

```text
gcd(84, 36) = gcd(36, 84 mod 36) = gcd(36, 12)    ← 84 = 2·36 + 12
gcd(36, 12) = gcd(12, 36 mod 12) = gcd(12, 0)     ← 36 = 3·12 + 0
gcd(12, 0)  = 12                                  ← 기저
```

나머지를 구하는 단계 두 번 뒤에 기저 `gcd(a, 0) = a` 에 닿는다.
검산: `84 = 12·7`, `36 = 12·3` 이고 `7` 과 `3` 은 서로소다.
근거: 장 본문 「3.2 유클리드 호제법」.
(직접 계산한 값 — 실행하지 않음)

### 5. a, b 의 공약수 집합과 b, a−b 의 공약수 집합이 똑같기 때문이다

`d` 가 `a` 와 `b` 를 나누면 `d` 는 `a - b` 도 나눈다(약수는 뺄셈에 보존된다).
그러므로 `a, b` 의 공약수는 모두 `b, a - b` 의 공약수다.
역으로 `d` 가 `b` 와 `a - b` 를 나누면 `d` 는 그 합인 `a` 도 나누므로 역도 성립한다.
공약수의 집합이 같으니 그중 가장 큰 것인 gcd 도 같다.
뺄셈을 거듭하는 것이 나눗셈이므로 이를 압축하면 `gcd(a, b) = gcd(b, a mod b)` 가 된다.
근거: 장 본문 「3.2 유클리드 호제법 — 왜 이것이 성립하는가」.

### 6. 존재하지 않는다 — 6 과 9 는 서로소가 아니다

`gcd(6, 9) = 3` 이라 서로소가 아니다.
장 본문은 서로소(`gcd = 1`)를 모듈러 역원이 존재할 조건으로 든다.
까닭을 풀면, `6x ≡ 1 (mod 9)` 는 `6x + 9y = 1` 인 정수 `x, y` 가 있다는 뜻인데, 좌변은 언제나 `3` 의 배수라 `1` 이 될 수 없다. (원본에 근거 없음 — 추론)
실제로 `6x mod 9` 는 `x` 가 무엇이든 `0, 6, 3` 중 하나만 나온다.
근거: 장 본문 「3.1 GCD」의 서로소 설명, 「3.3 확장 유클리드」.

### 7. 9 까지(√97 ≈ 9.8) 나눠 보면 충분하다

`97 = ab` 이고 `a ≤ b` 라면 `a ≤ √97 ≈ 9.8` 이어야 한다.
그래서 2 부터 9 까지 나눠 보아 하나도 나누어떨어지지 않으면 `97` 은 소수다.
`√n` 보다 큰 약수가 있다면 그 짝이 되는 `√n` 이하의 약수도 반드시 있기 때문이다.
실제로 `97` 은 2~9 의 어느 수로도 나누어떨어지지 않으므로 소수다.
근거: 장 본문 「4.3 소수 판정」의 시행 나눗셈법.

### 8. 아니다 — N 은 목록에 없는 소인수를 가질 뿐이다

증명이 보이는 것은 「`N` 이 목록의 어느 `pᵢ` 로도 나누어지지 않는다」는 것뿐이다.
그러므로 `N` 의 소인수(산술의 기본정리로 반드시 있다)는 목록 밖에 있어야 한다.
`N` 이 소수일 수도 있지만 합성수일 수도 있다.
예를 들어 `2·3·5·7·11·13 + 1 = 30031 = 59 × 509` 로 합성수다.
그래도 `59` 와 `509` 는 목록에 없는 새 소수이므로 증명은 그대로 성립한다.
본문의 「새로운 소수(또는 새로운 소인수)」라는 괄호가 바로 이 경계를 가리킨다.
근거: 장 본문 「4.2 소수의 무한성」.

### 9. 성립하지 않는다 — 좌변은 0 과 합동이다

`a` 가 `p` 의 배수이면 `a ≡ 0 (mod p)` 이므로 `a^(p-1) ≡ 0 (mod p)` 다.
예: `p = 5`, `a = 10` 이면 `10^4 ≡ 0 (mod 5)` 이지 `1` 이 아니다.
그래서 정리는 `gcd(a, p) = 1` 을 조건으로 단다.
증명에서도 이 조건이 있어야 `{a·1, …, a·(p-1)}` 이 `{1, …, p-1}` 의 재배열이 된다.
반면 동치 표현 `a^p ≡ a (mod p)` 는 모든 정수에 대해 성립한다 — `a ≡ 0` 이면 양변이 모두 `0` 이다.
근거: 장 본문 「5.1 페르마 소정리」.

### 10. φ(15) = 8

`15 = 3 × 5` 이고 `3`, `5` 는 서로 다른 소수이므로 `φ(15) = (3-1)(5-1) = 2 × 4 = 8` 이다.
직접 세어 확인하면 1~15 중 15 와 서로소인 수는 `1, 2, 4, 7, 8, 11, 13, 14` 로 8 개다.
포함-배제로 세어도 `15 - 5(3의 배수) - 3(5의 배수) + 1(15) = 8` 이다.
근거: 장 본문 「5.2 오일러 정리와 오일러 파이 함수」.
(직접 계산한 값 — 실행하지 않음)

### 11. d 를 구하려면 φ(n) 이 필요하고, φ(n) 을 구하려면 n 을 인수분해해야 하기 때문이다

`d = e⁻¹ mod φ(n)` 이므로 `φ(n) = (p-1)(q-1)` 을 모르면 `d` 를 계산할 수 없다.
그런데 `φ(n)` 을 알려면 `n` 을 `p·q` 로 쪼개야 한다.
`p, q` 를 곱해 `n` 을 만드는 것은 쉽지만, `n` 이 2048비트쯤 되면 인수분해는 현재 기술로 불가능하다.
키 주인은 `p, q` 를 알고 있으니 `φ(n)` 과 `d` 를 쉽게 구한다 — 이 비대칭성이 보안의 근거다.
근거: 장 본문 「5.3 RSA — 왜 안전한가」, 「1. 출발점」.

### 12. mod p 와 mod q 로 따로 계산한 뒤 CRT 로 합친다

`m = c^d mod pq` 를 직접 하지 않고 `m₁ = c^d mod p`, `m₂ = c^d mod q` 를 각각 구한다.
`p` 와 `q` 는 서로 다른 소수라 서로소이므로, CRT 에 의해 `m₁`, `m₂` 로부터 `mod pq` 의 `m` 이 유일하게 복원된다.
각 계산은 더 작은 수 위에서 이루어지므로 장 본문은 약 4배 빠르다고 적는다(지수도 절반, 모듈러스도 절반).
「서로소 = 정보가 겹치지 않는다」는 직관이 이 분할을 가능하게 한다.
근거: 장 본문 「6. 중국인의 나머지 정리」의 CS 연결, 「5.3 RSA」의 단계 목록.

### 13. 아니다 — 2 의 거듭제곱은 1, 2, 4 만 만든다

```text
2^1 = 2
2^2 = 4
2^3 = 8 ≡ 1 (mod 7)
2^4 ≡ 2,  2^5 ≡ 4,  2^6 ≡ 1
```

`2^1 ~ 2^6` 은 `{2, 4, 1}` 만 돌고, `ℤ₇* = {1, 2, 3, 4, 5, 6}` 전체를 만들지 못한다.
`φ(7) = 6` 개를 모두 생성해야 원시근이므로 `2` 는 원시근이 아니다.
비교: 본문의 `3` 은 `{3, 2, 6, 4, 5, 1}` 을 모두 만들어 원시근이다.
근거: 장 본문 「7.1 원시근」.
(직접 계산한 값 — 실행하지 않음)

### 14. 「정방향 계산은 쉽고 역방향 계산은 어렵다」는 비대칭성이다

RSA 는 「두 소수를 곱하기는 쉽지만 `n` 을 인수분해하기는 어렵다」는 비대칭에 기댄다.
Diffie-Hellman 은 「`g^a mod p` 를 계산하기는 쉽지만(`O(log n)`), `g^a` 에서 `a` 를 찾는 이산 로그는 어렵다(준-지수 시간)」는 비대칭에 기댄다.
도청자는 `g, p, A = g^a, B = g^b` 를 모두 보지만, 공유 비밀 `g^(ab)` 를 얻으려면 `a` 나 `b` 를 구해야 하므로 막힌다.
두 방식 모두 정당한 사용자는 쉬운 방향만 계산하고, 공격자는 어려운 방향을 풀어야 하도록 짜여 있다.
근거: 장 본문 「1. 출발점」의 핵심 아이디어, 「5.3 RSA」, 「7.2 이산 로그 문제」.

## 실습 정답

### 실습 1. 확장 유클리드로 5 의 mod 17 역원 구하기

**1단계 — 유클리드 호제법**

```text
17 = 3·5 + 2
 5 = 2·2 + 1    ← gcd = 1 (서로소 → 역원이 있다)
 2 = 2·1 + 0
```

**2단계 — 역추적**

```text
1 = 5 - 2·2
  = 5 - 2·(17 - 3·5)
  = 5 - 2·17 + 6·5
  = 7·5 - 2·17
```

**3단계 — mod 17 을 취한다**

`7·5 - 2·17 = 1` 의 양변에 `mod 17` 을 취하면 `7·5 ≡ 1 (mod 17)` 이다.
따라서 `5⁻¹ ≡ 7 (mod 17)` 이다.

**4단계 — 검증**

`5 × 7 = 35 = 2·17 + 1 ≡ 1 (mod 17)` ✓

기대는 절: 장 본문 「3.2 유클리드 호제법」, 「3.3 확장 유클리드」(7 의 mod 11 역원 예와 같은 절차).
(직접 계산한 값 — 실행하지 않음)

### 실습 2. 장난감 RSA 한 바퀴

**1단계 — 키 생성**

```text
n    = p·q = 5·11 = 55
φ(n) = (5-1)(11-1) = 4·10 = 40
gcd(3, 40) = 1   ← 40 = 13·3 + 1, 3 = 3·1 + 0
```

**2단계 — d = 3⁻¹ mod 40 (확장 유클리드)**

`40 = 13·3 + 1` 에서 `1 = 40 - 13·3` 이다.
양변에 `mod 40` 을 취하면 `-13·3 ≡ 1` 이므로 `d ≡ -13 ≡ 27 (mod 40)` 이다.
검증: `3 × 27 = 81 = 2·40 + 1 ≡ 1 (mod 40)` ✓
공개키는 `(55, 3)`, 개인키는 `(55, 27)` 이다.

**3단계 — 암호화**

`c = 2^3 mod 55 = 8` 이다.

**4단계 — 복호화 `8^27 mod 55` (빠른 모듈러 거듭제곱)**

```text
8^1  = 8
8^2  = 64        ≡ 9   (mod 55)
8^4  ≡ 9^2  = 81  ≡ 26
8^8  ≡ 26^2 = 676 ≡ 16   (676 - 12·55 = 676 - 660)
8^16 ≡ 16^2 = 256 ≡ 36   (256 - 4·55 = 256 - 220)

27 = 16 + 8 + 2 + 1
8^27 ≡ 36 · 16 · 9 · 8
     36·16 = 576 ≡ 26     (576 - 550)
     26·9  = 234 ≡ 14     (234 - 220)
     14·8  = 112 ≡ 2      (112 - 110)
```

복호화 결과가 `2` 로, 원래 평문과 같다.

**왜 돌아오나**

`ed = 81 = 1 + 2·40 = 1 + 2·φ(n)` 이므로 `m^(ed) = m · (m^φ(n))^2` 이다.
`gcd(2, 55) = 1` 이라 오일러 정리로 `2^40 ≡ 1 (mod 55)` 이고, 따라서 `m^(ed) ≡ m` 이다.

기대는 절: 장 본문 「5.3 RSA」(키 생성 · 암호화 · 복호화 · 복호화가 작동하는 이유), 「2.2 합동」(빠른 모듈러 거듭제곱), 「3.3 확장 유클리드」, 「5.2 오일러 정리」.
(직접 계산한 값 — 실행하지 않음)

### 실습 3. 세 시계를 맞추는 연립 합동식

**1단계 — 서로소 확인**

`gcd(3, 5) = gcd(3, 7) = gcd(5, 7) = 1` 이므로 쌍마다 서로소다.
CRT 에 의해 해는 `mod 3·5·7 = mod 105` 에서 유일하다.

**2단계 — 앞의 두 식 합치기**

`x ≡ 3 (mod 5)` 인 후보 `3, 8, 13` 을 `mod 3` 으로 본다.

```text
3  mod 3 = 0
8  mod 3 = 2   ← 맞다
13 mod 3 = 1
```

따라서 `x ≡ 8 (mod 15)` 이다.

**3단계 — 세 번째 식 합치기**

`x ≡ 8 (mod 15)` 인 후보 `8, 23, 38, …` 을 `mod 7` 로 본다.

```text
8  mod 7 = 1
23 mod 7 = 2   ← 맞다
```

따라서 `x ≡ 23 (mod 105)` 이다.

**4단계 — 검증**

`23 = 7·3 + 2`, `23 = 4·5 + 3`, `23 = 3·7 + 2` 로 세 식을 모두 만족한다 ✓

기대는 절: 장 본문 「6. 중국인의 나머지 정리」(쌍마다 서로소 조건과 유일성, 시계 직관).
