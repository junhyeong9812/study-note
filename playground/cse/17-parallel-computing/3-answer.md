## 퀴즈 정답

### 1. 전력은 8배가 되고, 그래서 멀티코어로 갔다

전력이 주파수의 세제곱에 비례하므로 `2³ = 8` 이다.
클록을 2배로 올리면 전력 소비가 약 8배로 뛴다.
발열과 전력이 물리적 한계에 부딪혀 2005년 이후 클록은 ~4GHz 에서 정체했다.
그래서 주파수 대신 코어를 여러 개 넣는 멀티코어로 방향을 틀었다.
그 대가로 여러 코어를 쓰려면 프로그래머가 병렬 프로그래밍을 해야 한다 — 「공짜 점심」이 끝났다는 말이 이 뜻이다.
(직접 계산한 값 — 실행하지 않음)

근거: 장 본문 1.1 「무어의 법칙의 종말」.

### 2. 상한은 20배, 프로세서 20개로는 약 10.26배

상한은 `n → ∞` 에서 `1/(1-p)` 이다.
`1/(1 - 0.95) = 1/0.05 = 20` 배다.

`n = 20` 일 때는 공식 `1 / ((1-p) + p/n)` 에 넣는다.
`p/n = 0.95/20 = 0.0475` 다.
분모는 `0.05 + 0.0475 = 0.0975` 다.
`1 / 0.0975 ≈ 10.26` 배다.

프로세서를 20개 붙여도 20배는커녕 절반 남짓에 머문다.
겨우 5% 의 직렬 부분이 상한을 정하기 때문이다.
(직접 계산한 값 — 실행하지 않음)

근거: 장 본문 1.2 「암달의 법칙」.

### 3. 문제 크기를 고정하느냐, 시간을 고정하느냐의 차이다

암달은 문제 크기를 고정하고 「몇 배 빨라지나」를 묻는다.
그러면 직렬 부분이 시간에서 차지하는 몫이 줄지 않아 상한 `1/(1-p)` 에 막힌다 — 그래서 비관적이다.
구스타프슨은 시간을 고정하고 「같은 시간에 몇 배 큰 문제를 풀 수 있나」를 묻는다.
프로세서가 늘면 병렬 부분의 일을 키울 수 있어 속도 향상이 `n` 에 거의 비례해 자란다 — 그래서 낙관적이다.
장 본문은 「현실은 둘 다 맞다. 관점의 차이」라고 정리한다.

근거: 장 본문 1.2 「구스타프슨의 법칙」.

### 4. x 는 2 가 아니라 1 이 될 수 있다

`x = x + 1` 은 「읽기 → 1 더하기 → 쓰기」 세 단계이고, 이 묶음이 원자적이지 않다.
다음처럼 끼어들면 증가분 하나가 사라진다.

```text
스레드 1: x 를 읽는다 (0)
스레드 2: x 를 읽는다 (0)
스레드 1: 0 + 1 = 1 을 쓴다
스레드 2: 0 + 1 = 1 을 쓴다   ← 스레드 1 의 결과를 덮어씀
최종 x = 1
```

끼어들지 않고 차례로 실행되면 2 가 된다.
그래서 결과는 1 또는 2 이며, 어느 쪽인지는 실행 순서에 달려 있다.
(직접 계산한 값 — 실행하지 않음)

**왜 그런가**
공유 메모리에서는 여러 스레드가 같은 주소를 읽고 쓰므로 동기화가 필수다.
Lock 으로 임계 구역을 보호하거나 CAS 같은 원자적 연산을 써야 한다.

근거: 장 본문 2.1 「원리와 문제」.

### 5. Lock 은 전체가 멈출 수 있고, Lock-free 는 나머지가 진행한다

Lock 시스템에서 한 스레드가 잠금을 잡은 채 죽으면 그 잠금을 기다리는 스레드가 모두 멈춘다.
Lock-free 시스템은 잠금이 없으므로 어떤 스레드가 멈춰도 나머지는 계속 진행할 수 있다.
CAS 는 「현재 값이 expected 이면 new_value 로 바꾸고, 아니면 실패」하는 연산이고 하드웨어가 원자성을 보장한다.
의사코드는 CAS 가 실패하면(그 사이 다른 스레드가 값을 바꿨다는 뜻) 값을 다시 읽어 새 값을 계산하고 재시도한다.
그래서 Lock-free 는 고성능 시스템과 실시간 시스템에서 중요하다.

근거: 장 본문 2.2 「동기화 도구」.

### 6. 데이터 병렬 · 생산자-소비자 · 분할 정복

- 벡터 덧셈 `a[i] = b[i] + c[i]` — 같은 연산을 다른 데이터에 동시에 적용하므로 **데이터 병렬**이다(SIMD · GPU 의 핵심 모델).
- 웹 서버의 요청 큐 — 생산자가 큐에 넣고 소비자가 꺼내 처리하므로 **생산자-소비자**다.
- 병렬 머지 정렬 — 문제를 나눠 각 부분을 병렬로 풀고 합치므로 **분할 정복**이다.

나머지 하나인 태스크 병렬은 로딩 · 계산 · 저장처럼 서로 다른 작업을 동시에 돌리는 경우다.

근거: 장 본문 2.3 「병렬 패턴」.

### 7. 공유 메모리는 일관성 유지 비용이 코어 수에 따라 급증한다

공유 메모리는 같은 메모리를 여럿이 보므로 메모리 일관성을 맞추는 비용이 코어 수가 늘수록 급증한다.
메시지 전달은 각 노드가 독립된 메모리를 가지므로 그런 비용이 없다.
동기화도 메시지 자체로 명시적으로 이뤄진다.
그래서 수천~수만 노드까지 확장되고, 슈퍼컴퓨터와 클라우드 클러스터의 기반이 된다.
대가는 통신 비용이다.

근거: 장 본문 3 「메시지 전달 모델」 · 8 「정리」 원리 4.

### 8. 공유 상태가 없기 때문이다

경쟁 상태는 여러 실행 단위가 같은 상태를 동시에 읽고 쓸 때 생긴다.
액터는 각자 독립된 상태와 메시지 큐를 갖고, 남의 상태를 직접 건드리지 않고 메시지로만 소통한다.
공유 상태가 없으니 경쟁 상태가 생길 자리 자체가 없다.
장 본문은 이것을 WhatsApp 이 Erlang 으로 수백만 동시 접속을 처리한 이유로 든다.

근거: 장 본문 3 「Erlang/Elixir 의 액터 모델」.

### 9. 분기가 많거나, 순차 의존이 있거나, 데이터 전송이 병목일 때

장 본문이 드는 세 경우다.
1. 분기(if/else)가 많은 코드 — GPU 스레드는 같은 명령어를 실행해야 효율적인데, 분기가 갈리면 일부 스레드가 대기해 효율이 급락한다(warp divergence).
2. 순차적 의존성 — 다음 계산이 이전 결과에 의존하면 병렬화할 수 없다.
3. 데이터 전송 비용 — CPU↔GPU 복사가 병목이 될 수 있다.

행렬 곱 `Y = WX` 는 출력 원소 하나하나가 독립적인 내적이다.
분기도 의존도 없는 수천 개의 내적을 수천 코어가 동시에 계산하므로 GPU 에 잘 맞는다.

근거: 장 본문 4 「GPU 컴퓨팅」.

### 10. Shuffle 은 a → [1, 1] · b → [1, 1] · c → [1], 결과는 a 2 · b 2 · c 1

Map — 문자열마다 단어별로 `(단어, 1)` 을 만든다.

```text
"a b a" → [("a",1), ("b",1), ("a",1)]
"b c"   → [("b",1), ("c",1)]
```

Shuffle — 같은 key 의 값을 모은다.

```text
"a" → [1, 1]
"b" → [1, 1]
"c" → [1]
```

Reduce — key 마다 값을 더한다.

```text
"a" → 2,  "b" → 2,  "c" → 1
```

같은 문자열 안의 "a" 두 번도 Map 에서는 각각 `("a",1)` 로 따로 나오고, 합치는 것은 Reduce 의 일이다.
(직접 계산한 값 — 실행하지 않음)

근거: 장 본문 5.1 「MapReduce — 왜 이 구조인가」의 단어 빈도 예.

### 11. 중간 결과를 디스크가 아니라 메모리에 유지하기 때문이다

MapReduce 는 매 단계마다 결과를 디스크에 쓰고 다시 읽는다.
반복 계산은 단계를 여러 번 거치므로 이 디스크 왕복이 쌓여 느려진다.
Spark 는 중간 결과를 메모리(RDD · DataFrame)에 유지해 그 왕복을 없앤다.
장 본문은 머신러닝 같은 반복 알고리즘에서 10~100배 빠르다고 적는다.

근거: 장 본문 5.1 「Spark — MapReduce 의 한계 극복」.

### 12. 비동기 시스템 + 노드 하나라도 장애 가능 → 타임아웃 가정으로 우회

FLP 불가능성 정리(1985)는 비동기 시스템에서 노드 하나라도 장애가 날 수 있으면 결정적 합의 알고리즘이 존재하지 않는다고 말한다.
비동기 시스템에서는 응답이 느린 노드와 죽은 노드를 구별할 수 없기 때문이다.
현실의 합의 알고리즘은 타임아웃 같은 현실적 가정을 더해 이 조건을 벗어난다.
Raft 의 리더 선출이 「리더가 죽으면 → 타임아웃 → Candidate 가 투표 요청」으로 시작하는 것이 그 예다.

근거: 장 본문 6.1 「합의 문제」 · 6.2 「Raft」.

### 13. 과반수 4개 · 장애 3개 허용 / 노드 4개면 장애 1개

과반수는 `⌊n/2⌋ + 1` 이다.
노드 7개: `⌊7/2⌋ + 1 = 3 + 1 = 4` 개가 동의해야 한다.
남은 노드가 4개 이상이면 되므로 최대 `7 - 4 = 3` 개 장애를 버틴다.

노드 4개: `⌊4/2⌋ + 1 = 2 + 1 = 3` 개가 동의해야 한다.
버틸 수 있는 장애는 `4 - 3 = 1` 개다.
노드 3개일 때(과반수 2, 장애 1개)와 버티는 수가 같아, 노드를 하나 더 넣어도 장애 허용 수가 늘지 않는다.
(직접 계산한 값 — 실행하지 않음)

**왜 과반수인가**
과반수 두 그룹은 반드시 한 노드 이상 겹치므로 두 그룹이 서로 다른 결정을 내릴 수 없다.

근거: 장 본문 6.2 「왜 과반수인가」.

### 14. 링 위에서는 새 노드와 이전 노드 사이의 키만 주인이 바뀐다

`hash(key) % n` 은 모든 키의 자리가 `n` 에 달려 있어, `n` 이 바뀌면 거의 모든 키의 나머지가 달라진다.
일관성 해싱은 노드와 키를 같은 해시 링에 두고 각 키를 시계 방향으로 가장 가까운 노드에 맡긴다.
노드 하나가 들어오거나 나가면 그 노드와 이전 노드 사이 구간의 키만 주인이 바뀌고 나머지는 그대로다.
그 구간이 링 전체의 약 1/n 이라 재배치도 약 1/n 이다.
이것은 Ch.09 자료구조의 해시를 분산 환경으로 넓힌 것이고, DynamoDB · Cassandra · CDN 이 쓴다.

근거: 장 본문 6.3 「일관성 해싱」 · 7 「분야 간 연결」.

## 실습 정답

### 실습 1. 암달과 구스타프슨으로 속도 향상 계산하기

장 본문 1.2 의 두 공식에 기댄다.

**1단계 — 암달, n = 10**
`1 - p = 0.1` 이다.
`p/n = 0.9/10 = 0.09` 다.
분모는 `0.1 + 0.09 = 0.19` 다.
`Speedup = 1/0.19 ≈ 5.26` 배다.

**2단계 — 암달, n → ∞**
`p/n → 0` 이므로 분모는 `0.1` 로 수렴한다.
`Speedup_max = 1/0.1 = 10` 배다.

**3단계 — 구스타프슨, n = 10**
`(1-p)(n-1) = 0.1 × 9 = 0.9` 다.
`Speedup = 10 - 0.9 = 9.1` 배다.
근사식은 `n·p + (1-p) = 9 + 0.1 = 9.1` 로 같은 값이 나온다(전개하면 `n - (1-p)n + (1-p) = n·p + (1-p)` 이라 사실 같은 식이다).

**4단계 — 왜 다른가**
암달은 문제 크기를 고정해 직렬 10% 가 상한을 묶으므로 5.26배, 아무리 늘려도 10배다.
구스타프슨은 같은 시간에 병렬 부분을 키운 더 큰 문제를 푼다고 보므로 9.1배로 `n` 에 가깝다.

```text
암달 (n=10)       ≈ 5.26 배
암달 (n→∞)        = 10 배
구스타프슨 (n=10)  = 9.1 배
```

(직접 계산한 값 — 실행하지 않음)

### 실습 2. 단어 빈도를 MapReduce 세 단계로 손으로 처리하기

장 본문 5.1 의 단어 빈도 예와 같은 절차다.

**1단계 — Map**

```text
"cat dog"     → [("cat",1), ("dog",1)]
"dog cat cat" → [("dog",1), ("cat",1), ("cat",1)]
"bird"        → [("bird",1)]
```

**2단계 — Shuffle**

```text
"cat"  → [1, 1, 1]
"dog"  → [1, 1]
"bird" → [1]
```

**3단계 — Reduce**

```text
"cat"  → 3
"dog"  → 2
"bird" → 1
```

**4단계 — 독립적으로 나눌 수 있는 단계**
Map 이다.
문자열 하나를 처리하는 데 다른 문자열이 필요 없으므로 세 문자열을 서로 다른 노드가 동시에 처리할 수 있다.
Shuffle 은 프레임워크가 자동으로 같은 key 를 모으고, Reduce 는 key 별로 나뉘어 처리된다.

(직접 계산한 값 — 실행하지 않음)

### 실습 3. 해시 링에 노드를 하나 더하기

장 본문 6.3 「일관성 해싱」에 기댄다.

**1단계 — 처음 배치 (노드 20 · 50 · 80)**
각 키에서 수가 커지는 쪽으로 처음 만나는 노드를 찾는다.

```text
키 10 → 노드 20
키 30 → 노드 50
키 55 → 노드 80
키 85 → 99 를 넘어 0 으로 돌아가 → 노드 20
키 95 → 99 를 넘어 0 으로 돌아가 → 노드 20
```

**2단계 — 노드 65 추가**
새 노드 65 의 이전 노드는 50 이다.
50 과 65 사이에 있는 키만 주인이 바뀐다.
그 구간의 키는 55 하나다.

```text
키 55 → 노드 80 에서 노드 65 로 이동
나머지 키 10 · 30 · 85 · 95 → 그대로
```

옮기는 키는 5개 중 1개다.

**3단계 — 단순 해싱과 비교 (`키 % 3` → `키 % 4`)**

```text
키 10:  10 % 3 = 1  →  10 % 4 = 2   바뀜
키 30:  30 % 3 = 0  →  30 % 4 = 2   바뀜
키 55:  55 % 3 = 1  →  55 % 4 = 3   바뀜
키 85:  85 % 3 = 1  →  85 % 4 = 1   그대로
키 95:  95 % 3 = 2  →  95 % 4 = 3   바뀜
```

바뀌는 키는 5개 중 4개다.

**4단계 — 비교**
노드 하나를 더할 때 단순 해싱은 5개 중 4개를 옮겼지만 일관성 해싱은 1개만 옮겼다.

(직접 계산한 값 — 실행하지 않음)
