## 퀴즈 정답

### 1. 명확성과 유한성

「소금을 적당히」는 **명확성**(각 단계가 모호하지 않음)을 어긴다.
「적당히」가 얼마인지 정해지지 않아서 실행하는 사람마다 다르게 한다.
끝나지 않는 절차는 **유한성**(유한 단계 뒤에 반드시 종료)을 어긴다.

근거: 장 본문 §1.1 「알고리즘이란」의 다섯 조건과 레시피 비교.

### 2. 큰 n 에서는 최고차 항만 남고, 상수는 컴퓨터마다 바뀐다

하위 항: `n` 이 충분히 크면 `n²` 항이 압도적으로 지배한다.
`n = 1000` 이면 `3,000,000 + 5,000 + 100` 이라 `5n + 100` 은 전체의 0.17% 정도다.
상수 `3`: 컴퓨터마다 실행 속도가 달라서 상수는 바뀌지만, `n²` 이라는 성장의 본질은 바뀌지 않는다.
알고 싶은 것은 「`n` 이 두 배가 되면 시간이 몇 배가 되나」이고, 그것은 상수와 상관없다.

근거: 장 본문 §2.1 「Big-O — 왜 이 정의인가」.

### 3. 약 4배와 약 2배

`O(n²)`: `(2n)² = 4n²` 이므로 약 **4배**다.
`O(n log n)`: `2n · log(2n) = 2n(log n + 1)` 이다.
`n` 이 크면 `log n` 에 비해 `+1` 이 작아서 약 **2배**(2배보다 조금 많음)다.
(직접 계산한 값 — 실행하지 않음)

근거: 장 본문 §2.1 「O(n²)이면 → 4배. O(n log n)이면 → 약 2배」.

### 4. 비싼 복사의 총합이 `O(n)` 이라 `n` 번에 나눠 내면 한 번에 `O(1)`

용량을 두 배씩 늘리면 `n` 번 `push` 동안 복사 비용의 합은 `1 + 2 + 4 + … + n = 2n - 1 = O(n)` 이다.
일반 `push` 비용 `O(n)` 과 더해도 총 `O(n)` 이다.
이를 `n` 번으로 나누면 한 번에 `O(1)` 이다.
비싼 연산이 일어나기까지 싼 연산이 충분히 많아서 비용을 그 연산들에 나눠 지운다.

근거: 장 본문 §2.3 「Amortized 분석」.

### 5. (가) Case 1 → `Θ(n²)`, (나) Case 3 → `Θ(n²)`

(가) `a = 4`, `b = 2` 이므로 `c_crit = log₂4 = 2` 다.
`f(n) = n = O(n^{2-ε})`(예: `ε = 1`) 이므로 **Case 1** — 재귀 비용이 지배한다.
따라서 `T(n) = Θ(n^{c_crit}) = Θ(n²)` 이다.

(나) `a = 2`, `b = 2` 이므로 `c_crit = log₂2 = 1` 이다.
`f(n) = n² = Ω(n^{1+ε})`(예: `ε = 1`) 이므로 **Case 3** — 합치기 비용이 지배한다.
따라서 `T(n) = Θ(f(n)) = Θ(n²)` 이다.
(직접 계산한 값 — 실행하지 않음)

근거: 장 본문 §3.3 「마스터 정리」의 세 케이스.

### 6. `2ᵏ ≥ n!` 에서 나오고, 기수 정렬은 데이터 종류가 제한된다

`n` 개 원소의 순열은 `n!` 가지다.
비교 한 번은 예/아니오 두 갈래라서 `k` 번 비교로는 최대 `2ᵏ` 가지를 가를 수 있다.
모든 순열을 갈라야 하므로 `2ᵏ ≥ n!` 이고, `k ≥ log₂(n!) ≈ n log₂ n` 이다.
정보이론으로 말하면 `log₂(n!)` 비트가 필요한데 비교 하나가 1비트를 준다.

기수 정렬은 비교를 하지 않아서 이 하한에 걸리지 않는다(`O(d·n)`).
그러나 정수 · 문자열처럼 자릿수로 나눌 수 있는 데이터에만 쓸 수 있어 범용성이 떨어진다.
비교 기반 정렬은 어떤 데이터에든 쓸 수 있다.

근거: 장 본문 §4.1 「비교 기반 정렬의 하한」, §4.2 「기수 정렬」.

### 7. 힙 정렬은 캐시에 불리하고 상수가 크며, 랜덤 퀵 정렬은 라스베이거스다

힙 정렬은 부모-자식 접근이 메모리에서 비연속적이라 캐시에 불리하고, 실제 상수가 퀵 정렬보다 크다.
퀵 정렬은 in-place(추가 메모리는 재귀 스택 `O(log n)`)이고, 연속 메모리를 순회해 캐시 친화적이며, 상수가 작다.
랜덤 피벗 퀵 정렬은 항상 정확히 정렬되고 실행 시간만 랜덤하므로(기대 `O(n log n)`) **라스베이거스** 알고리즘이다.

근거: 장 본문 §4.2 「퀵 정렬」·「힙 정렬」, §11 「랜덤 알고리즘」.

### 8. 「작으면 왼쪽에 있다」는 보장이 정렬에서 나오고, 결정 문제로 바꾸면 쓸 수 있다

이진 탐색은 중간값과 비교해 절반을 버린다.
「중간값보다 작으면 왼쪽에 있다」는 보장은 정렬에서만 나온다.
정렬되지 않으면 이 보장이 없어서 절반을 버릴 수 없다.

파라메트릭 서치는 최적화 문제를 「K 로 가능한가?」라는 **결정 문제**로 바꾼 뒤, K 를 이진 탐색한다.

근거: 장 본문 §5.1 「이진 탐색」과 그 🔵 CS 연결.

### 9. 순수 재귀는 3번, 메모이제이션은 1번

순수 재귀: `fib(5)` → `fib(4)`, `fib(3)`.
`fib(4)` → `fib(3)`, `fib(2)`.
`fib(3)` 은 두 번 불리고, 각각 `fib(2)` 를 한 번씩 부른다.
`fib(2)` 는 `1 + 2 = 3` 번 계산된다.

메모이제이션: `fib_memo(2)` 를 처음 계산할 때 `memo` 에 저장하고, 그 뒤 호출은 `memo` 에서 바로 돌려준다.
따라서 값은 **1번**만 계산된다.
각 `F(k)` 를 한 번씩만 계산하므로 지수 시간이 `O(n)` 이 된다.
(직접 계산한 값 — 실행하지 않음)

근거: 장 본문 §6.1 「피보나치로 이해」, §6.2 Top-down 코드.

### 10. 단위 가치가 높은 물건이 무거우면 다른 물건이 들어갈 자리를 막는다

0/1 배낭에서는 물건을 쪼갤 수 없다.
비율이 가장 높은 물건이 무거우면 그것을 넣은 뒤 남은 용량에 다른 좋은 물건 조합이 들어가지 못한다.
즉 이 문제에는 「전체 최적해에 지역 최적 선택이 반드시 들어간다」는 그리디 선택 속성이 없다.
그래서 남은 용량별 부분 문제를 모두 푸는 DP 를 써야 한다.

근거: 장 본문 §7.1 「그리디 선택 속성」, §7.2 「그리디가 안 되는 예시」.

### 11. 확정한 거리가 다시 줄어들 수 있고, 최단 경로의 간선은 `V-1` 개 이하다

다익스트라는 미확정 노드 가운데 가장 가까운 노드를 확정하고 되돌리지 않는다.
가중치가 음이 아니면 다른 경로로 돌아와도 거리가 더 짧아질 수 없어서 이 그리디가 통한다.
음의 간선이 있으면 그 간선을 거쳐 이미 확정한 거리가 줄어들 수 있어서 그리디 선택이 무효가 된다.

벨만-포드: 사이클이 없는 최단 경로는 `V` 개 노드를 지나므로 간선이 최대 `V-1` 개다.
반복마다 적어도 한 노드의 최단 거리가 확정되므로 `V-1` 번이면 모두 확정된다.
`V` 번째 반복에서도 거리가 줄면 음수 사이클이 있다는 뜻이다.

근거: 장 본문 §8.2 「다익스트라」·「벨만-포드」.

### 12. BFS 는 거리 순 방문, 크루스칼은 유니온-파인드, 프림은 트리에서 거리를 잰다

BFS 는 거리 1, 거리 2, … 순서로 레벨별로 방문하므로 처음 닿은 경로가 최단이다.
DFS 는 한 방향으로 끝까지 가므로 이런 보장이 없다.
크루스칼은 **유니온-파인드**로 새 간선이 사이클을 만드는지 판별한다.
프림과 다익스트라는 둘 다 그리디 + 최소 힙 구조다.
다익스트라는 「시작점에서의 거리」를 재고, 프림은 「지금 만든 트리에서의 거리」를 잰다.

근거: 장 본문 §8.1 「BFS와 DFS」, §8.3 「최소 신장 트리」.

### 13. 이미 얻은 정보를 버리지 않거나, 가망 없는 가지를 통째로 버린다

KMP 는 불일치가 나도 처음부터 다시 비교하지 않는다.
실패 함수(매칭된 접두사 가운데 접미사이기도 한 가장 긴 것)로 「다시 시작할 위치」를 미리 계산해 두어, 텍스트의 각 문자를 최대 2번만 비교한다.
그래서 `O(n + m)` 이다.

백트래킹은 「이 선택은 절대 답이 될 수 없다」를 일찍 판단해 그 아래 탐색 전체를 건너뛴다(가지치기).

근거: 장 본문 §9.1 「KMP」, §10 「백트래킹」.

### 14. P = NP 가 되고, 최적해도 고른 간선마다 끝점을 하나는 가져야 한다

모든 NP 문제는 NP-complete 문제로 다항 환원된다.
그래서 NP-complete 문제 하나가 다항 시간에 풀리면 NP 의 모든 문제가 다항 시간에 풀리고, **P = NP** 가 된다.

정점 커버 근사에서 고른 간선들은 끝점을 서로 공유하지 않는다(고른 간선의 끝점을 넣으면 그 끝점에 붙은 간선이 덮인다).
최적해도 이 간선 각각의 끝점을 최소 하나는 넣어야 한다.
근사 알고리즘은 간선마다 끝점 둘을 넣으므로 최적의 2배를 넘지 않는다.
(「고른 간선끼리 끝점을 공유하지 않는다」는 설명은 장 본문의 한 줄 근거를 풀어 쓴 것이다.)

근거: 장 본문 §13.1 「NP-complete」, §13.3 「다항 환원」, §12 「정점 커버 2-근사」.

## 실습 정답

### 실습 1. 머지 정렬을 손으로 따라가기

**나누기** (홀수면 왼쪽에 하나 더)

```text
레벨 0: [5, 2, 8, 1, 9, 3]
레벨 1: [5, 2, 8]        [1, 9, 3]
레벨 2: [5, 2]  [8]      [1, 9]  [3]
레벨 3: [5] [2] [8]      [1] [9] [3]
```

**합치기**

```text
[5]+[2]        → [2, 5]      (비교 1번: 5 대 2)
[1]+[9]        → [1, 9]      (비교 1번: 1 대 9)
[2, 5]+[8]     → [2, 5, 8]   (비교 2번: 2 대 8, 5 대 8 → 남은 8)
[1, 9]+[3]     → [1, 3, 9]   (비교 2번: 1 대 3, 9 대 3 → 남은 9)
[2, 5, 8]+[1, 3, 9] → [1, 2, 3, 5, 8, 9]
```

**마지막 합치기의 비교**

```text
1) 2 대 1 → 1 을 꺼낸다
2) 2 대 3 → 2 를 꺼낸다
3) 5 대 3 → 3 을 꺼낸다
4) 5 대 9 → 5 를 꺼낸다
5) 8 대 9 → 8 을 꺼낸다
   왼쪽이 비었으므로 남은 9 를 비교 없이 붙인다
```

비교는 **5번**이다.
길이 6 을 합치는 일은 많아야 `n - 1 = 5` 번 비교라서 merge 가 `O(n)` 이라는 장 본문의 말과 맞는다.
(직접 계산한 값 — 실행하지 않음)

기대는 절: 장 본문 §3.2 「머지 정렬」(알고리즘 단계, merge 단계가 핵심).

### 실습 2. 다익스트라를 표로 돌리기

```text
처음:            A=0  B=∞  C=∞  D=∞
A 확정 (0):      B=min(∞, 0+4)=4   C=min(∞, 0+1)=1
                 → A=0  B=4  C=1  D=∞
C 확정 (1):      B=min(4, 1+2)=3   D=min(∞, 1+5)=6
                 → A=0  B=3  C=1  D=6
B 확정 (3):      D=min(6, 3+1)=4
                 → A=0  B=3  C=1  D=4
D 확정 (4):      남은 갱신 없음
```

확정 차례: `A → C → B → D`.
최단 거리: `A = 0`, `C = 1`, `B = 3`(A→C→B), `D = 4`(A→C→B→D).
`B` 는 직접 간선 `4` 보다 `C` 를 거친 `3` 이 짧다.
(직접 계산한 값 — 실행하지 않음)

기대는 절: 장 본문 §8.2 「다익스트라」(아직 확정되지 않은 노드 중 가장 가까운 것을 확정).

### 실습 3. 0/1 배낭 — 그리디와 DP 비교

**그리디**
비율은 1번 `5/3 ≈ 1.67`, 2번 `3/2 = 1.5`, 3번 `1.5` 다.
1번(무게 3)을 넣으면 남은 용량이 1 이라 2번 · 3번이 들어가지 않는다.
그리디 결과 가치는 **5** 다.

**DP 표** (`dp[i][w]`, 행 = 물건 1..i 까지 고려, 열 = 용량)

```text
        w=0  w=1  w=2  w=3  w=4
i=0      0    0    0    0    0
i=1      0    0    0    5    5     (1번: 무게 3, 가치 5)
i=2      0    0    3    5    5     (2번: 무게 2, 가치 3)
i=3      0    0    3    5    6     (3번: 무게 2, 가치 3)
```

몇 칸의 계산:

```text
dp[2][2] = max(dp[1][2]=0, dp[1][0]+3=3) = 3
dp[2][4] = max(dp[1][4]=5, dp[1][2]+3=3) = 5
dp[3][4] = max(dp[2][4]=5, dp[2][2]+3=6) = 6
```

최적 가치는 `dp[3][4] = **6**` 이다.
`dp[3][4]` 는 3번을 넣은 쪽에서 왔고, 그 앞 `dp[2][2] = 3` 은 2번을 넣은 쪽에서 왔다.
그래서 고른 물건은 2번 · 3번(무게 4, 가치 6)이다.
그리디(5)는 최적(6)보다 작다 — 단위 가치가 높은 1번이 무거워 나머지 자리를 막았다.
(직접 계산한 값 — 실행하지 않음)

기대는 절: 장 본문 §6.3 「배낭 문제」의 점화식, §7.2 「그리디가 안 되는 예시」.
