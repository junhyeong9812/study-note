### 1. 단어 수준은 OOV · 거대 어휘, 문자 수준은 너무 긴 시퀀스 — 서브워드가 절충한다

단어 수준은 어휘 크기가 매우 크고, 어휘에 없는 단어(OOV)는 `<UNK>` 로 뭉개져 처리할 수 없다.
문자 수준은 시퀀스가 너무 길어지고 토큰 하나가 의미를 담기 어렵다.
서브워드 수준은 자주 나오는 단어(「the」, 「is」)는 통째로 한 토큰으로 두고, 드문 단어는 조각(「un」+「friend」+「ly」)으로 나눈다.
그래서 처음 보는 단어도 조각의 조합으로 표현되어 OOV 문제가 풀리고, 어휘 크기는 보통 30K~50K 로 적당하다.
덤으로 「un-」= 부정, 「-ly」= 부사 같은 형태론적 정보도 잡힌다.

### 2. 첫 병합은 `ug`, 두 번째는 `hug`

이웃한 쌍의 등장 횟수를 단어 횟수만큼 더해 센다.

```text
h-u : 3 (hug) + 1 (hugs)           = 4
u-g : 3 (hug) + 2 (pug) + 1 (hugs) = 6
p-u : 2 (pug)                      = 2
g-s : 1 (hugs)                     = 1
```

가장 빈번한 쌍은 `u-g`(6번)이므로 첫 병합 토큰은 `ug` 다.
병합 뒤 말뭉치는 `h ug`(3), `p ug`(2), `h ug s`(1)가 된다.
다시 세면 `h-ug` = 4, `p-ug` = 2, `ug-s` = 1 이므로 두 번째 병합 토큰은 `hug` 다.

**왜 그런가**
BPE 는 「가장 빈번한 문자 쌍을 합쳐 새 토큰으로 추가」하는 일을 원하는 어휘 크기까지 되풀이한다.
매 단계 그때 가장 잦은 쌍만 고르므로 그리디 방식이다.

(직접 계산한 값 — 실행하지 않음)

### 3. 모든 단어 쌍의 거리가 같다 — 의미의 가까움을 담지 못한다

원핫 벡터는 단어마다 서로 다른 한 자리만 1 이므로, 어느 두 단어를 골라도 거리가 똑같다.
그래서 `cat` 과 `dog` 이 `cat` 과 `fish` 보다 가깝다는 의미적 유사성을 전혀 담지 못한다.
여기에 더해 차원이 어휘 크기만큼 높고(10,000차원), 거의 모든 원소가 0 인 희소 벡터라 메모리도 낭비한다.

### 4. 비슷한 문맥 → 비슷한 벡터, 그래서 벡터 덧셈 · 뺄셈과 내적이 의미를 다룬다

분포 가설은 「비슷한 문맥에서 나타나는 단어는 비슷한 의미를 가진다」는 것이다.
「나는 __을 먹었다」의 빈칸에 들어가는 사과 · 밥 · 빵처럼, 같은 문맥 패턴을 벡터로 담으면 비슷한 단어가 비슷한 벡터를 얻는다.
Word2Vec 은 중심 단어로 주변 단어를 예측(Skip-gram)하거나 그 반대(CBOW)로 이 문맥 패턴을 학습한다.
그 결과 「남성→여성」, 「나라→수도」 같은 방향이 벡터 공간에 일관되게 나타나 `king - man + woman ≈ queen` 이 성립한다.
의미가 가까운 단어는 벡터 방향이 비슷해서 `cos(king, queen) > cos(king, apple)` 이 된다.
즉 Ch.02 선형대수의 벡터 덧셈 · 뺄셈과 내적(코사인 유사도)이 「의미」를 다루게 된 예다.

### 5. 다의어에도 벡터가 하나뿐이라 뜻을 가르지 못한다 — 문맥화된 임베딩으로 넘는다

Word2Vec 은 단어 하나에 벡터 하나만 준다.
그래서 「은행」의 bank 와 「강둑」의 bank 가 같은 벡터로 표현되어 다의어를 처리하지 못한다.
「배가 아프다」의 「배」처럼 문맥 없이는 과일 · 복부 · 선박을 정할 수 없는 모호성도 같은 뿌리다.
이를 넘으려고 문맥에 따라 벡터가 달라지는 모델(ELMo, BERT, GPT)이 나왔고, 이를 「문맥화된 임베딩(contextualized embedding)」이라 부른다.

### 6. 0.5 는 약 1/1000 배로 소실, 2 는 1024 배로 폭발

곱해지는 값이 0.5 일 때 10단계 뒤 그래디언트는 처음의 다음 배수가 된다.

```text
0.5^10 = 1 / 2^10 = 1 / 1024 ≈ 0.00098
```

곱해지는 값이 2 일 때는 다음 배수가 된다.

```text
2^10 = 1024
```

**왜 그런가**
역전파에서는 연쇄법칙 때문에 그래디언트가 시간 단계마다 곱해진다.
|곱해지는 값| < 1 이면 기하급수적으로 작아져(소실) 초기 정보가 학습에 반영되지 않고, > 1 이면 기하급수적으로 커진다(폭발).

(직접 계산한 값 — 실행하지 않음)

### 7. 기울기가 곱셈 대신 덧셈으로 전달되고, 시그모이드가 「문의 열린 정도」를 정한다

셀 상태는 정보가 직접 흐르는 통로라서 기울기가 단계마다 곱해지는 대신 덧셈으로 전달된다.
곱셈이 거듭되지 않으니 기하급수적인 소실이 완화된다.
게이트(Forget · Input · Output)는 시그모이드 σ 를 쓰는데, σ 의 출력이 0~1 이라 「얼마나 통과시킬지」의 비율로 읽힌다.
σ = 0 이면 완전히 닫혀 정보를 막고, σ = 1 이면 완전히 열려 통과시킨다.
그래서 네트워크가 학습으로 무엇을 기억하고 무엇을 잊을지 스스로 정한다.

### 8. `love` 의 가중치는 약 0.787

softmax 는 각 점수의 지수를 지수 합으로 나눈다.

```text
e^0 = 1,  e^2 ≈ 7.389
합 = 1 + 7.389 + 1 = 9.389

I    : 1     / 9.389 ≈ 0.107
love : 7.389 / 9.389 ≈ 0.787
NLP  : 1     / 9.389 ≈ 0.107
```

**왜 그런가**
softmax 는 점수를 합이 1 인 확률분포로 바꾼다.
점수가 높은 입력에 큰 가중치가 몰리므로 「좋아한다」를 만들 때 `love` 에 집중하게 된다.
장 본문의 예(I 0.1, love 0.8, NLP 0.1)와 거의 같은 분포다.

(직접 계산한 값 — 실행하지 않음)

근거: 장 본문 「5.1 왜 Attention 이 필요한가」, 「5.2 Self-Attention」의 「softmax = 점수를 확률로 변환」.

### 9. 큰 값이 softmax 를 원핫처럼 만들어 그래디언트가 사라지기 때문 — 내적의 분산이 `d_k` 에 비례한다

`d_k` 가 크면 `QK^T` 의 값이 커진다.
softmax 에 큰 값이 들어가면 출력이 거의 원핫이 되고, 그러면 그래디언트가 사라진다.
내적의 분산이 `d_k` 에 비례하므로 표준편차는 `√d_k` 에 비례한다.
그래서 `√d_k` 로 나누면 분산이 1 로 맞춰져 값의 스케일이 적절히 유지된다.

근거: 장 본문 「5.2 Self-Attention」의 「왜 √d_k 로 나누는가」.

### 10. 4억 개 — 길이가 두 배면 점수는 네 배

attention 은 모든 위치 쌍의 점수를 계산하므로 점수 개수는 n² 이다.

```text
n = 10,000 → 10,000² = 100,000,000 (1억)
n = 20,000 → 20,000² = 400,000,000 (4억)
```

n 이 두 배가 되면 n² 은 2² = 4 배가 된다.
이것이 Transformer 의 대가인 메모리 O(n²) 이고, 긴 시퀀스에서 병목이 된다.

(직접 계산한 값 — 실행하지 않음)

### 11. RNN 은 순차 의존이라 병렬화가 안 되고, Self-Attention 은 모든 위치를 동시에 · 직접 잇는다

RNN 은 t 번째를 계산하려면 t-1 번째 결과가 있어야 해서 단계를 하나씩 차례로 밟아야 한다.
그래서 일을 동시에 나눠 줄 수 없어 GPU 의 수천 코어를 활용하지 못한다.
Self-Attention 은 모든 위치를 동시에 처리하므로 완전 병렬화가 되고, 그 계산은 대규모 행렬 곱이라 GPU(Ch.17 병렬)에서 극적으로 빨라진다.
장거리 의존성도 RNN 은 많은 단계를 건너 기억을 넘겨야 하지만, Self-Attention 은 멀리 떨어진 두 위치도 attention 으로 직접 연결한다.
병렬화가 되니 규모를 키울 수 있었고, 이것이 「규모의 법칙」으로 이어진다.

### 12. 구별할 수 없다 — sin/cos 는 상대적 위치를 선형 변환으로 표현할 수 있어서

Self-Attention 은 순서 정보가 없어 집합 연산에 가깝다.
그래서 위치 정보 없이는 「cat sat」과 「sat cat」을 구별하지 못한다.
각 위치에 고유한 벡터를 더해 순서 정보를 주입하는 것이 Positional Encoding 이다.
원래 논문은 `PE(pos, 2i) = sin(pos / 10000^(2i/d))`, `PE(pos, 2i+1) = cos(pos / 10000^(2i/d))` 를 썼다.
sin/cos 를 고른 까닭은 상대적 위치를 선형 변환으로 표현할 수 있기 때문이다.

### 13. 빈칸 채우기는 앞뒤가 다 필요하고, 다음 토큰 예측은 왼쪽만 보아야 한다

BERT 는 인코더만 쓰고 MLM(Masked Language Model), 곧 「The [MASK] sat on the mat」에서 빈칸을 맞히는 과제로 사전학습한다.
빈칸 채우기는 앞뒤 맥락이 모두 필요하므로 양방향이고, 그래서 분류 · NER · QA 같은 이해 과제에 강하다.

이전 토큰들만 보고 다음을 예측하므로 단방향이다.
텍스트는 왼쪽에서 오른쪽으로 생성하므로 이 방식이 생성 · 대화 · 코드 생성에 맞는다.

## 실습 정답

### 실습 1. 작은 말뭉치로 BPE 두 번 돌리기

**1단계 — 처음 쌍 세기**

```text
c-a : 4 (cat) + 3 (car) = 7
a-t : 4 (cat) + 2 (bat) = 6
a-r : 3 (car)           = 3
b-a : 2 (bat)           = 2
```

가장 빈번한 쌍은 `c-a`(7) → 첫 병합 토큰 `ca`.

**2단계 — 병합 뒤 다시 세기**

말뭉치가 `ca t`(4), `ca r`(3), `b a t`(2)가 된다.

```text
ca-t : 4
ca-r : 3
b-a  : 2
a-t  : 2 (bat 에만 남는다)
```

가장 빈번한 쌍은 `ca-t`(4) → 두 번째 병합 토큰 `cat`.

**3단계 — 결과**

```text
cat → [cat]          (토큰 1개)
car → [ca, r]        (토큰 2개)
bat → [b, a, t]      (토큰 3개)

어휘 = 초기 문자 {a, b, c, r, t} 5개 + {ca, cat} 2개 = 7개
```

가장 자주 나오는 단어(cat)는 통째로 한 토큰이 되고, 드문 단어(bat)는 조각으로 남는다.
장 본문이 말한 「자주 나오는 단어는 통째로, 드문 단어는 서브워드로」가 빈도만으로 자동으로 생긴 것이다.
매 단계 그 순간 가장 잦은 쌍을 고르는 그리디 방식이다.

### 실습 2. 크로스 엔트로피와 Perplexity 오가기

**1. 크로스 엔트로피 → Perplexity**

```text
H = 2비트 → PPL = 2^2 = 4
H = 5비트 → PPL = 2^5 = 32
```

**2. Perplexity → 크로스 엔트로피**

```text
PPL = 16 = 2^H → H = log₂ 16 = 4비트
```

**3. 비교**

모델 A(PPL 8)가 낫다.
A 는 다음 토큰을 평균 8가지 선택지에서 고민하고 B 는 32가지에서 고민하므로, 선택지가 적은 A 가 더 확신 있게 예측한다.
Perplexity 는 낮을수록 좋고, PPL = 1 이면 완벽한 예측이다.

(직접 계산한 값 — 실행하지 않음)

### 실습 3. 손으로 하는 Scaled Dot-Product Attention

**1. 내적과 스케일링** — `√d_k = √4 = 2`

```text
q·k1 = 1·2 + 1·2 + 0 + 0 = 4  → 4 / 2 = 2
q·k2 = 0 + 0 + 0·1 + 0·1 = 0  → 0 / 2 = 0
q·k3 = 1·1 + 1·1 + 0 + 0 = 2  → 2 / 2 = 1
```

**2. softmax**

```text
e^2 ≈ 7.389,  e^0 = 1,  e^1 ≈ 2.718
합 ≈ 11.107

w1 = 7.389 / 11.107 ≈ 0.665
w2 = 1     / 11.107 ≈ 0.090
w3 = 2.718 / 11.107 ≈ 0.245
```

**3. 가중 합산**

