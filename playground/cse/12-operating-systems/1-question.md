## 퀴즈

### 1. 유저 프로그램이 하드웨어를 직접 만지지 못하게 막는 까닭 (왜)

- 일반 프로그램을 유저 모드에 가두고 시스템 콜로만 OS 에 부탁하게 하는 까닭은 무엇인가?
- 시스템 콜을 될 수 있는 한 적게 부르는 것이 성능 최적화의 기본이 되는 까닭은 무엇인가?

### 2. 디스크를 읽으러 간 프로세스의 여정 (예측)

- Running 상태의 프로세스가 디스크 읽기를 요청한 순간부터 다시 CPU 에서 실행될 때까지 어떤 상태를 차례로 거치는가?
- 그 사이에 CPU 는 무엇을 하는가?

### 3. 문맥 교환은 왜 공짜가 아닌가 (왜)

- 문맥 교환 동안 CPU 가 「유용한 일」을 하지 못하는 까닭은 무엇이며, 교환이 너무 잦을 때와 너무 드물 때 각각 무엇이 나빠지는가?

### 4. 스레드끼리 나눠 쓰는 것과 나눠 쓰지 않는 것 (경계)

- 같은 프로세스 안의 두 스레드는 메모리 구조의 어느 부분을 공유하고 어느 부분을 따로 가지는가?
- 그 공유 때문에 생기는 대가 두 가지는 무엇인가?

### 5. 세 작업을 FCFS 와 SJF 로 돌리면 (예측)

```text
(질문용 발췌)
세 작업이 모두 시각 0 에 이 순서로 도착한다.
  A: 실행 시간 24
  B: 실행 시간 3
  C: 실행 시간 3
```

- FCFS 와 SJF 의 평균 대기 시간은 각각 얼마인가?
- 두 값의 차이를 만든 현상의 이름은 무엇인가?

### 6. Round Robin 의 시간 할당량을 키우고 줄이면 (경계)

- 시간 할당량 q 를 아주 크게 하면 RR 은 어떤 알고리즘처럼 되고, 아주 작게 하면 무엇이 문제인가?
- Ready 프로세스가 5개이고 q = 20ms 일 때, 한 프로세스가 CPU 를 다시 받기까지 기다리는 시간의 최댓값은 얼마인가?

### 7. MLFQ 와 SJF 의 다리 (연결)

- MLFQ 가 「실행 시간 예측이 필요 없는 SJF」라고 불리는 까닭은 무엇인가?
- MLFQ 가 주기적으로 모든 프로세스를 최고 우선순위 큐로 올리는 까닭은 무엇인가?

### 8. 두 스레드가 이 순서로 끼어들면 (예측)

```text
(질문용 발췌)
잔고 = 1000
스레드 A: 잔고 += 500      스레드 B: 잔고 -= 200

실제 실행 순서:
  B: 잔고 읽기
  A: 잔고 읽기
  B: 잔고 쓰기
  A: 잔고 쓰기
```

- 최종 잔고는 얼마이며, 기대한 값과 비교해 무엇이 사라지거나 생겼는가?
- 이 사고를 막으려면 「읽기-수정-쓰기」를 어떤 구간으로 만들어야 하는가?

### 9. 뮤텍스와 세마포어를 둘 다 두는 까닭 (왜)

- 뮤텍스가 있는데도 세마포어가 따로 필요한 까닭을 「소유권」이라는 말로 설명하면 무엇인가?
- 주차 자리가 3개인 주차장을 세마포어로 나타낼 때, 네 번째 차가 들어오려 하면 어떻게 되는가?

### 10. 자원에 번호를 매기면 데드락이 사라지는 까닭 (경계)

- 모든 자원에 번호를 매기고 번호 순서대로만 요청하게 하면 데드락의 네 조건 가운데 어느 것이 깨지는가?
- 네 조건 가운데 하나만 깨도 충분한 까닭은 무엇인가?
- Linux · Windows 같은 범용 OS 가 데드락을 그냥 무시하는 전략을 고르는 까닭은 무엇인가?

### 11. 페이징이 바꿔 놓은 단편화 (왜)

- 페이징이 외부 단편화를 없애는 까닭은 무엇인가?
- 페이징이 대신 남기는 단편화는 무엇이며, 한 프로세스에서 그 낭비는 최대 얼마인가?

### 12. 페이지 테이블 위에 TLB 를 얹는 까닭 (연결)

- TLB 가 없으면 메모리 접근 한 번에 실제로 몇 번의 메모리 접근이 필요한가?
- 작은 TLB 로도 대부분의 접근을 덮을 수 있는 까닭을 Ch.11 의 어떤 성질로 설명하는가?

### 13. 참조열 하나를 FIFO 와 LRU 로 (예측)

```text
(질문용 발췌)
프레임 3개, 처음엔 모두 비어 있다.
페이지 참조 순서: 1, 2, 3, 1, 4, 1, 2
```

- FIFO 와 LRU 의 페이지 폴트 수는 각각 몇 번인가?

### 14. 스래싱과 저널링 — 버티는 법과 되살리는 법 (연결)

- 스래싱이 일어날 때 프로세스 일부를 중단하는 것이 오히려 나은 까닭은 무엇인가?
- 파일 시스템의 저널링은 데이터베이스의 어떤 기법과 같은 원리이며, 그 원리는 무엇인가?

## 실습

### 실습 1. 네 작업을 FCFS · SJF · RR 로 스케줄링하기

**문제** — 네 프로세스가 모두 시각 0 에 P1, P2, P3, P4 순서로 Ready 큐에 들어온다.
실행 시간은 P1 = 6, P2 = 8, P3 = 7, P4 = 3 이다.
FCFS, SJF(비선점), RR(q = 4) 로 각각 스케줄링한다.
RR 에서 할당량을 다 쓴 프로세스는 Ready 큐 맨 뒤로 간다.
문맥 교환 시간은 0 으로 본다.

**요구 조건**
1. 세 알고리즘마다 실행 순서를 시간 축(간트 차트) 꼴로 적는다.
2. 각 프로세스의 반환 시간 · 대기 시간 · 응답 시간을 표로 적는다.
3. 세 알고리즘의 평균 대기 시간과 평균 응답 시간을 구해 비교하고, 그 결과를 장 본문의 설명(SJF 의 최적성, RR 의 응답 시간 보장)과 잇는다.

### 실습 2. 같은 참조열을 OPT · FIFO · LRU 로 교체하기

**문제** — 프레임이 3개이고 처음에는 모두 비어 있다.
페이지 참조열은 `7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2` (13번 참조)다.

**요구 조건**
1. OPT, FIFO, LRU 마다 참조 한 번씩 프레임의 내용과 폴트 여부를 표로 적는다.
2. 각 알고리즘의 페이지 폴트 수를 구한다.
3. 세 값의 크기 순서를 적고, 「LRU 가 OPT 에 가깝다」는 장 본문의 주장과 비교한다.

### 실습 3. 4KB 페이지에서 가상 주소를 물리 주소로 바꾸기

**문제** — 페이지 크기는 4KB(4096 바이트)다.
한 프로세스의 페이지 테이블 일부는 아래와 같다.

```text
페이지 0 → 프레임 7
페이지 1 → 프레임 3
페이지 2 → 프레임 5
페이지 3 → (메모리에 없음, invalid)
```

**요구 조건**
1. 가상 주소 10000 과 4100 (모두 10진수)을 [페이지 번호 | 오프셋] 으로 나누고 물리 주소를 구한다.
2. 가상 주소 13000 에 접근하면 무슨 일이 일어나는지 장 본문의 처리 단계로 적는다.
3. 이 프로세스의 전체 크기가 10000 바이트라면 페이지가 몇 개 필요하고, 내부 단편화로 낭비되는 바이트는 얼마인지 구한다.
