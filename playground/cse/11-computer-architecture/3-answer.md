## 퀴즈 정답

### 1. `NAND(A, A)` 는 NOT 이다

계산 과정:
- `A = 0` → `AND(0, 0) = 0` → 반전하면 `1`.
- `A = 1` → `AND(1, 1) = 1` → 반전하면 `0`.

입력을 뒤집어 내놓으므로 NOT 과 같다 — 장 본문의 `NOT(A) = NAND(A, A)` 다.
NAND 하나로 NOT · AND · OR 를 모두 만들 수 있으므로(함수적 완전성), 모든 부울 함수를 NAND 만으로 구현할 수 있다.
그래서 칩 제조에서 NAND 를 기본 단위로 삼는다.
(직접 계산한 값 — 실행하지 않음)

근거 — 장 본문 §2.1 「논리 게이트」.

### 2. `Sum = 1`, `Cout = 1` — 1 + 1 + 1 = 3 = 11₂

계산 과정:
- 세 입력을 더하면 1 + 1 + 1 = 3 이다.
- 3 을 이진으로 쓰면 `11₂` 다 — 아래 자리 `1` 이 `Sum`, 윗자리로 넘어가는 `1` 이 `Cout` 이다.
- 전가산기 진리표의 마지막 줄 `1 1 1 │ 1 1` 과 같다.

ripple carry adder 는 올림이 아래 자리부터 한 칸씩 전파되어야 하므로 지연이 O(n) 이다.
올림을 미리 계산하는 carry-lookahead adder 는 O(log n) 이다.
나눗셈은 20~90 사이클로 비싸므로 `x / 2` 는 `x × 0.5` 나 `x >> 1` 로 바꿔 쓸 수 있다.
(직접 계산한 값 — 실행하지 않음)

근거 — 장 본문 §2.2 「조합 회로」, §8 「산술의 하드웨어 비용」.

### 3. 조합 회로는 기억하지 못한다 — 레지스터는 플립플롭 64개다

조합 회로는 현재 입력만으로 출력이 정해지므로 기억이 없다.
값을 다음 틱까지 붙들어 두려면 현재 입력과 이전 상태로 출력이 정해지는 순서 회로, 곧 플립플롭이 필요하다.
D 플립플롭 하나가 1비트를 저장하므로 64비트 레지스터에는 D 플립플롭이 64개 든다.

근거 — 장 본문 §2.3 「순서 회로」.

### 4. 0이 하나이고, 덧셈기 하나로 뺄셈까지 하기 때문이다

부호-크기법은 0이 두 개(+0, −0)이고 덧셈 회로가 복잡하다.
1의 보수도 0이 두 개이고 올림 보정이 필요하다.
2의 보수에서는 `A − B = A + (B의 2의 보수)` 이므로 덧셈기 하나로 덧셈과 뺄셈을 모두 처리한다.
뺄셈 전용 회로가 사라지면 하드웨어가 단순해져 칩이 작고 빠르고 싸진다.

근거 — 장 본문 §3.1 「정수 표현 — 왜 2의 보수인가」, §11 원리 3.

### 5. 아니다 — 0.1 은 이진수로 무한 소수다

`0.1₁₀ = 0.0001100110011...₂` 로 끝없이 반복되므로 비트를 아무리 늘려도 어딘가에서 잘라야 하고, 오차가 남는다.
더 넓게 보면 유한 비트로 무한한 실수를 표현해야 하므로 비둘기집 원리에 따라 대부분의 실수는 정확히 표현할 수 없다.
금융 계산에서는 정수(센트 단위)나 Decimal 타입을 쓰라고 권한다.

근거 — 장 본문 §3.2 「부동소수점」.

### 6. 「프로그램 = 데이터」가 범용성과 병목을 함께 낳았다

프로그램을 데이터처럼 메모리에 저장하면 배선을 바꾸지 않고 메모리만 바꿔 프로그램을 바꿀 수 있다 — 범용 컴퓨터의 탄생이다.
그러나 명령어와 데이터가 모두 같은 메모리에서 CPU 로 오가야 하므로 CPU-메모리 사이 전송이 병목이 된다.
메모리 접근은 ~100ns 로 CPU 사이클의 ~300배 느려, CPU 는 대부분의 시간을 기다린다.
하버드 구조는 명령어와 데이터를 별도 메모리에 두어 둘을 동시에 읽게 한다 — 현대 CPU 는 내부(L1 캐시)가 하버드, 외부가 폰 노이만이다.

근거 — 장 본문 §4.1, §4.3, §11 원리 2.

### 7. CISC 명령어 대부분이 거의 쓰이지 않았기 때문이다

CISC 의 복잡한 명령어 가운데 실제로 자주 쓰이는 것은 20% 미만이고, 나머지 80%를 위한 회로가 칩을 복잡하게 만든다.
단순한 명령어만 두면 파이프라이닝이 쉬워지고 클록을 높일 수 있어 실제 성능이 오른다.
ARM 은 명령어가 간단해 회로가 단순하고 전력 소비가 적어 배터리에 유리하다.
현대 x86 은 겉은 CISC 이지만 안에서 RISC 마이크로 연산으로 분해한다.
배열 원소 접근에는 베이스+오프셋 방식이, 포인터 역참조에는 간접 방식이 맞는다.

근거 — 장 본문 §5.2 「CISC vs RISC」, §5.3 「주소 지정 방식」.

### 8. 순차 50 사이클, 파이프라인 14 사이클

계산 과정:
- 순차: 명령어 하나가 5 사이클, 10개이므로 5 × 10 = 50 사이클.
- 파이프라인: 첫 명령어가 끝나는 데 5 사이클, 그 뒤 명령어마다 1 사이클씩 더해지므로 5 + 9 = 14 사이클.
- 속도 향상은 50 / 14 ≈ 3.57 배다 — 명령어가 많아질수록 이상적 값인 단계 수(5배)에 가까워진다.

(직접 계산한 값 — 실행하지 않음)

근거 — 장 본문 §6.1 「5단계 파이프라인」.

### 9. 첫 `ADD` 와 `SUB` 사이의 데이터 해저드 — 포워딩으로 푼다

첫 `ADD` 는 `R1` 에 결과를 WB 단계(5번째 사이클)에 쓰는데, 바로 뒤 `SUB` 는 ID 단계(3번째 사이클)에서 `R1` 을 읽는다.
아직 계산이 끝나지 않은 값을 쓰려는 상황이므로 데이터 해저드다.
세 번째 `ADD R6, R7, R8` 은 앞 두 명령어의 결과를 쓰지 않으므로 충돌이 없다.
기다리는 스톨 대신 EX 결과를 WB 를 거치지 않고 다음 명령어로 바로 넘기는 포워딩을 쓰면 대부분의 데이터 해저드가 풀린다.

근거 — 장 본문 §6.2 「해저드 (2) 데이터 해저드」.

### 10. 평균 0.75 사이클 — 패턴이 규칙적이면 예측이 맞는다

계산 과정:
- 맞을 때: 0.95 × 0 = 0 사이클.
- 틀릴 때: 0.05 × 15 = 0.75 사이클.
- 합: 0.75 사이클 — 추측하지 않을 때 항상 잃는 2~3 사이클보다 훨씬 작다.

정렬된 배열에서는 분기 결과가 한동안 같다가 한 번 바뀌는 규칙적 패턴이라 예측 정확도가 높다.
비정렬 배열은 분기 패턴이 무작위라 예측 실패와 파이프라인 플러시가 잦다.
(직접 계산한 값 — 실행하지 않음)

근거 — 장 본문 §6.3 「분기 예측」.

### 11. 충돌 미스가 되풀이되고, cold · capacity 미스는 연관도와 상관없다

직접 매핑에서는 각 블록이 갈 수 있는 자리가 하나뿐이므로, 같은 인덱스를 두 블록이 번갈아 쓰면 서로를 계속 밀어내 충돌 미스가 되풀이된다.
충돌 미스는 연관도를 높이면 줄어든다.
cold miss 는 처음 접근하는 데이터라 피할 수 없고 프리페칭으로 완화한다.
capacity miss 는 캐시가 워킹 셋보다 작아서 생기므로 캐시 크기를 키워야 줄어든다.

근거 — 장 본문 §7.3 「캐시 매핑」, §7.4 「3C 모델」.

### 12. 공간적 지역성 때문이다 — LRU 는 시간적 지역성에 기댄다

행 우선 순회는 연속한 주소를 차례로 접근하므로 공간적 지역성이 살아 있어 캐시에 올라온 블록을 잘 쓴다.
열 우선 순회는 이 지역성이 깨져 같은 알고리즘 · 같은 복잡도인데도 10배 이상 느릴 수 있다.
LRU 는 오래 안 쓴 것은 앞으로도 안 쓸 가능성이 높다는 시간적 지역성을 근거로 그것을 버린다.

근거 — 장 본문 §7.2 「지역성」, §7.3 「교체 정책」, §7.4 「CS 연결」.

### 13. 최대 20배 — 직렬 부분이 한계를 정한다

`n → ∞` 이면 `p/n → 0` 이므로 속도 향상 = 1 / (1 − p) = 1 / 0.05 = 20 배다.
직렬 부분 5% 가 아무리 많은 프로세서로도 줄지 않아 전체를 지배하기 때문이다.
그래서 성능 향상의 핵심은 프로세서를 더하는 것보다 직렬 부분을 줄이는 것이다.
(직접 계산한 값 — 실행하지 않음)

근거 — 장 본문 §9.2 「암달의 법칙」, §11 원리 7.

### 14. 멀티코어는 MIMD — GPU 는 독립적인 내적을 수천 코어에 나눈다

멀티코어 CPU 는 여러 코어가 각자 다른 명령어를 다른 데이터에 실행하므로 MIMD 다.
SIMD 는 같은 연산을 여러 데이터에 한꺼번에 적용한다(예: float 4개를 한 번에 더하기).
행렬 곱 `Y = W × X + b` 에서 각 출력 원소는 서로 독립적인 내적이다.
GPU 는 제어 로직을 줄이고 연산 장치에 면적을 모은 수천 개의 코어로 그 내적들을 동시에 계산하므로, CPU 대비 10~100배 빠른 학습이 가능하다.

근거 — 장 본문 §9.1 「플린 분류」, §9.3 「GPU」.

## 실습 정답

### 실습 1. 2의 보수로 7 − 12 를 덧셈 하나로 계산하기

1단계 — 양수를 이진으로 적는다.

```text
+12 = 00001100
 +7 = 00000111
```

2단계 — `−12` 를 구한다(비트 반전 + 1).

```text
 00001100   (+12)
 11110011   (반전)
+       1
 11110100   (−12)
```

3단계 — 더한다.

```text
  00000111   (+7)
+ 11110100   (−12)
  11111011
```

장 본문 §3.1 의 예에서 `−5 = 11111011` 이므로 결과는 `−5` 다.
거꾸로 확인하면 `11111011` 을 반전한 `00000100` 에 1을 더해 `00000101 = 5` 이므로 크기 5 의 음수다.
뺄셈 회로 없이 덧셈기 하나로 `7 − 12 = −5` 를 얻었다.
(직접 계산한 값 — 실행하지 않음)

근거 — 장 본문 §3.1 「정수 표현 — 왜 2의 보수인가」.

### 실습 2. 6.5 를 IEEE 754 float 로 쪼개기

1단계 — 이진으로 바꾼다.

```text
정수 부분: 6 = 4 + 2      → 110₂
소수 부분: 0.5 = 2⁻¹      → .1₂
6.5 = 110.1₂
```

2단계 — 정규화한다.
소수점을 왼쪽으로 두 칸 옮겨 `110.1₂ = 1.101₂ × 2²` 이다.

3단계 — 필드를 채운다.

```text
s = 0                       (양수)
E = 2 + 127 = 129 = 10000001₂
M = 101 0000 0000 0000 0000 0000   (23비트, 101 뒤는 0)
```

4단계 — 거꾸로 확인한다.

```text
1.101₂ = 1 + 0.5 + 0.125 = 1.625
(-1)^0 × 1.625 × 2^(129 − 127) = 1.625 × 4 = 6.5
```

6.5 는 2의 거듭제곱의 합으로 딱 떨어지므로 0.1 과 달리 오차 없이 표현된다.
(직접 계산한 값 — 실행하지 않음)

근거 — 장 본문 §3.2 「부동소수점」 (`1.01101 × 2⁵ → E = 5 + 127 = 132` 예와 같은 방법).

### 실습 3. 암달의 법칙 — 프로세서를 늘릴까, 직렬 부분을 줄일까

1단계 — `p = 0.8` 에서 프로세서 수를 바꾼다.

```text
n = 4 :  1 / (0.2 + 0.8/4)  = 1 / (0.2 + 0.2)  = 1 / 0.4  = 2.5 배
n = 16:  1 / (0.2 + 0.8/16) = 1 / (0.2 + 0.05) = 1 / 0.25 = 4 배
n → ∞:  1 / 0.2 = 5 배
```

2단계 — 프로세서 16개에서 직렬 부분을 10% 로 줄인다(`p = 0.9`).

```text
1 / (0.1 + 0.9/16) = 1 / (0.1 + 0.05625) = 1 / 0.15625 = 6.4 배
```

3단계 — 비교한다.
`p = 0.8` 로는 프로세서를 무한히 늘려도 5배를 넘지 못하지만, 직렬 부분을 절반으로 줄이면 프로세서 16개만으로 6.4배가 나오므로 직렬 부분을 줄이는 쪽이 더 효과적이다.
(직접 계산한 값 — 실행하지 않음)

근거 — 장 본문 §9.2 「암달의 법칙」, §11 원리 7.
