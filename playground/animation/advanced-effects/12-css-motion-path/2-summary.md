## 한눈에 — 쉽게 말하면

**CSS Motion Path 는 「장난감 기차와 레일」이다.**
레일을 먼저 깔아 두면 기차는 레일 위에서 「얼마나 왔나」만 정하면 된다.
x, y 좌표를 하나하나 정할 필요가 없고, 레일이 휘면 기차도 따라 휜다.
CSS Motion Path 도 똑같은 구조다.
`offset-path` 로 레일(경로)을 깔고, `offset-distance` 로 「경로의 몇 % 지점에 있나」를 정한다.
그 `offset-distance` 를 0% 에서 100% 로 애니메이션하면 요소가 경로를 따라 달린다.

| 비유 | 실체 |
|---|---|
| 레일 | `offset-path: path('…')` |
| 기차가 온 거리 | `offset-distance` (0% ~ 100%) |
| 기차 머리가 레일 방향을 따라 돎 | `offset-rotate: auto` |
| 바닥에 그려 둔 레일 그림 | SVG `<path d="…">` 점선 가이드 |
| 한 바퀴 도는 데 걸리는 시간 | `animation: followPath 4s linear infinite` |

```text
  offset-path (레일)
   ╭──────────────╮
   │   0%        ●│ 50%      ● = 요소
   ╰──────────────╯
  offset-distance: 0% → 100% 로 움직이면
  요소가 레일을 한 바퀴 돈다
```

> **모션 패스(motion path)** — 요소가 따라 움직일 경로를 CSS 로 정해 두고, 경로 위의 위치를 값 하나로 움직이는 기법.\
> 예: 로켓 이모지가 점선 고리를 따라 계속 도는 것.

## 이 주제가 답하려는 질문

1. 요소를 곡선 경로를 따라 움직이려면 어떤 속성 셋이 각각 무슨 일을 하나?
2. 경로 문자열 `M … C …` 를 읽어 요소가 어디를 지나는지 알 수 있나?
3. 눈에 보이는 가이드 선(SVG)과 실제 이동 경로가 정확히 겹치려면 무엇을 맞춰야 하나?
4. 시간이 흐를 때 요소는 경로의 어디에 있고, 반복할 때 어떻게 이어지나?

## 동작 방식

### (1) `offset-path` 로 경로를 깐다

**언제 쓰나** — 요소가 지나갈 궤적을 정할 때 쓴다.
요소의 위치를 left/top 으로 정하는 대신 「경로 위의 한 점」으로 정하게 된다.

```text
입력:  offset-path: path('M 30,100 C 30,20 270,20 270,100 C 270,180 30,180 30,100');

무엇이 일어나나:
  M 30,100                  → 펜을 (30,100) 에 놓는다 (출발점)
  C 30,20 270,20 270,100    → 제어점 (30,20)·(270,20) 쪽으로 끌려 위로 부푼 곡선을 그리며 (270,100) 까지
  C 270,180 30,180 30,100   → 제어점 (270,180)·(30,180) 쪽으로 끌려 아래로 부푼 곡선을 그리며 (30,100) 으로 복귀

결과:
   (30,20)············(270,20)     ← 제어점 (곡선은 여기까지 가지 않는다)
        ╭─────────────╮
 (30,100)              (270,100)
        ╰─────────────╯
   (30,180)···········(270,180)
```

- `M x,y` 는 펜을 그 점으로 옮기는 명령이다.
- `C x1,y1 x2,y2 x,y` 는 3차 베지어 곡선이다 — 앞의 두 점은 제어점이고 마지막 점이 끝점이다.
- 제어점은 곡선을 그쪽으로 끌어당길 뿐, 곡선이 그 점을 지나가지는 않는다.
- 그래서 위쪽 곡선은 y=20 까지 올라가지 않는다.
- 대칭인 3차 베지어의 한가운데(t=0.5) 점은 `(시작 + 3×제어1 + 3×제어2 + 끝) ÷ 8` 로 구한다.
- 위쪽 곡선이면 x = (30+90+810+270)÷8 = 150, y = (100+60+60+100)÷8 = 40 — 꼭대기는 (150, 40) 이다.
- 아래쪽 곡선은 y=100 을 축으로 위쪽 곡선을 뒤집은 꼴이라 길이가 같고, 바닥은 (150, 160) 이다.
- 마지막 끝점 (30,100) 이 출발점과 같으므로 이 경로는 **닫힌 경로**다.
- 경로의 좌표 단위는 CSS px 이다.

> **베지어 곡선(Bézier curve)** — 시작점 · 끝점과, 곡선을 끌어당기는 제어점으로 모양을 정하는 곡선.\
> 예: `C 30,20 270,20 270,100` 은 제어점 둘을 가진 3차 베지어다.

> **닫힌 경로** — 끝점이 출발점과 같은 경로.\
> 예: `M 30,100 … 30,100` 처럼 같은 점에서 시작해 같은 점에서 끝나는 경로.

### (2) `offset-distance` 로 경로 위의 위치를 정한다

**언제 쓰나** — 요소가 경로의 어느 지점에 있을지 정할 때 쓴다.
애니메이션할 대상은 이 값 하나다.

```text
입력:  @keyframes followPath {
         from { offset-distance: 0%; }
         to   { offset-distance: 100%; }
       }
       animation: followPath 4s linear infinite;

무엇이 일어나나:
  시간   0s     1s       2s        3s       4s
  거리   0%     25%      50%       75%      100%
  위치  (30,100)(150,40) (270,100) (150,160) (30,100) → 다시 0%

결과: 요소가 위쪽 곡선 → 오른쪽 끝 → 아래쪽 곡선 → 왼쪽 끝으로 4초에 한 바퀴
```

- `offset-distance` 의 % 는 **경로 전체 길이**에 대한 비율이다.
- `linear` 이므로 시간에 비례해 거리가 늘고, 요소는 경로 위를 같은 빠르기로 달린다.
- 위쪽 곡선과 아래쪽 곡선의 길이가 같으므로 50% 는 위쪽 곡선의 끝, 곧 (270,100) 이다.
- 위쪽 곡선은 좌우 대칭이라 그 절반(전체의 25%)은 한가운데 꼭대기 (150,40) 이다.
- 100% 는 (30,100) 이고 출발점과 같으므로, `infinite` 로 0% 에 돌아가도 위치가 튀지 않는다.
- timing function(`linear`, `ease` 등)은 다른 애니메이션 속성과 똑같이 `offset-distance` 의 진행에 적용된다.

> **timing function** — 애니메이션의 진행 비율을 시간에 따라 어떻게 바꿀지 정하는 함수.\
> 예: `linear` 는 등속, `ease` 는 천천히 시작해 빨라졌다가 천천히 끝난다.

### (3) `offset-rotate: auto` 로 방향을 맞춘다

**언제 쓰나** — 요소가 진행 방향을 바라보게 하고 싶을 때 쓴다(로켓 · 자동차 · 화살표).

```text
입력:  offset-rotate: auto;

무엇이 일어나나:
  경로의 각 점에서 진행 방향(접선 방향)을 구해 요소를 그만큼 돌린다

결과:
  위쪽 곡선 왼쪽  ↗    꼭대기 →    오른쪽 끝 ↓    바닥 ←    왼쪽 끝 ↑
```

- 요소가 꺾이는 곡선을 따라 머리를 돌리므로 움직임이 자연스럽다(원본 주석).

> **접선 방향** — 곡선의 한 점에서 곡선이 나아가는 방향.\
> 예: 위쪽 곡선의 꼭대기에서는 오른쪽 방향이다.

### (4) SVG 가이드와 경로를 겹친다

**언제 쓰나** — 요소가 지나갈 길을 화면에 점선으로 보여 줄 때 쓴다.

```text
입력:
  <svg viewBox="0 0 300 200">  (무대 300×200 을 꽉 채움)
    <path d="M 30,100 C … 30,100" stroke-dasharray="4 4" />
  </svg>
  .motion-element { position: absolute; top: 0; left: 0; offset-path: path('M 30,100 C … 30,100'); }

무엇이 일어나나:
  viewBox 300×200 이 실제 300×200px 에 그려짐 → SVG 의 1 단위 = 1px
  path() 의 좌표도 px → 두 좌표계가 같다
  요소는 top:0 left:0 → 무대 왼쪽 위 = 경로 좌표의 원점

결과: 점선 가이드 위를 로켓이 정확히 지나간다 (코드에서 읽은 것 — 렌더 실측 아님)
```

- `path()` 문자열과 SVG 의 `d` 속성을 **글자 하나 다르지 않게** 맞춰야 가이드와 이동이 겹친다(원본 팁).
- `viewBox` 는 SVG 안의 좌표를 SVG 크기에 맞춰 늘리거나 줄인다.
- 반면 `path()` 의 좌표는 px 그대로라 늘어나지 않는다.
- 그래서 무대 크기가 viewBox 와 같을 때만 두 선이 겹친다.
- `top: 0; left: 0` 인 까닭: 위치는 `offset-path` 가 정하므로 시작 기준을 무대의 원점에 둔다(원본 주석).
- 무대의 `position: relative` 는 SVG 와 요소의 절대 위치 기준점이고, `overflow: hidden` 은 무대 밖으로 나간 부분을 숨긴다.

> **viewBox** — SVG 안쪽 좌표계의 범위를 정하는 속성. SVG 의 실제 크기에 맞춰 늘거나 준다.\
> 예: `viewBox="0 0 300 200"` 을 600×400px 로 그리면 좌표 1 이 2px 이 된다.

```html demo
<div style="position:relative;width:300px;height:120px;background:#f8fafc;">
  <svg style="position:absolute;inset:0;width:100%;height:100%" viewBox="0 0 300 120">
    <path d="M 20,100 C 100,0 200,0 280,100" fill="none" stroke="#94a3b8" stroke-dasharray="4 4"/>
  </svg>
  <div style="position:absolute;top:0;left:0;width:16px;height:8px;background:#2563eb;
              offset-path:path('M 20,100 C 100,0 200,0 280,100');offset-rotate:auto;
              animation:go 3s linear infinite alternate;"></div>
</div>
<style>@keyframes go { from { offset-distance:0%; } to { offset-distance:100%; } }</style>
```

> **보이는 것** — 파란 막대가 점선 아치를 따라 왼쪽에서 오른쪽으로 갔다가 되돌아오고, 오르막에서는 위로, 내리막에서는 아래로 기운다 (코드에서 읽은 것 — 렌더 실측 아님)

## 문법 — 형태와 규칙

```css
.mover {
  position: absolute;
  top: 0;
  left: 0;
  offset-path: path('M 30,100 C 30,20 270,20 270,100 C 270,180 30,180 30,100');
  offset-rotate: auto;
  animation: followPath 4s linear infinite;
}
@keyframes followPath {
  from { offset-distance: 0%; }
  to   { offset-distance: 100%; }
}
```

| 속성 | 값 | 하는 일 |
|---|---|---|
| `offset-path` | `path('SVG 경로 문자열')` | 요소가 따라갈 경로. 좌표는 px |
| `offset-distance` | `0%` ~ `100%` | 경로 전체 길이 중 요소가 있는 지점 |
| `offset-rotate` | `auto` | 진행 방향에 맞춰 요소를 회전 |
| `animation` | `이름 시간 timing 반복` | `offset-distance` 를 움직이는 키프레임을 돌린다 |

| 경로 명령 | 꼴 | 뜻 |
|---|---|---|
| `M` | `M x,y` | 펜을 그 점으로 옮긴다 |
| `C` | `C x1,y1 x2,y2 x,y` | 제어점 둘을 지나는 쪽으로 휜 3차 베지어로 끝점까지 |

- `path()` 안의 문자열은 따옴표로 감싼다.
- 가이드를 그린다면 SVG `d` 와 `path()` 문자열을 똑같이 쓴다.
- 애니메이션하는 속성은 `offset-distance` 하나뿐이다 — 경로 자체는 그대로 둔다.
- 끊김 없이 반복하려면 닫힌 경로와 `0% → 100%` 를 짝짓는다.

## 어디서 틀리나

### 1. `path()` 와 SVG `d` 가 조금 다르다

숫자 하나만 달라도 로켓과 점선이 어긋난다.
두 문자열을 한 곳에서 복사해 쓰는 것이 안전하다(원본 팁).

### 2. 무대 크기와 viewBox 가 다르다

SVG 가이드는 viewBox 에 따라 무대 크기만큼 늘어나지만, `path()` 의 px 좌표는 늘지 않는다.
무대를 키우면 점선은 커지고 로켓은 원래 크기의 고리를 돈다.

### 3. `top` · `left` 를 경로 좌표에 맞추려 한다

위치는 `offset-path` 가 정하므로 원본은 `top: 0; left: 0` 으로 둔다.
여기에 다른 값을 주면 경로 원점이 어디로 잡히는지가 달라질 수 있다 (확인 필요).
경로 좌표의 원점을 무대 왼쪽 위에 맞추려면 0 으로 두는 것이 원본의 방식이다.

### 4. 열린 경로에 `infinite` 를 건다

끝점이 출발점과 다르면 100% 에서 0% 로 돌아갈 때 요소가 끝점에서 출발점으로 순간이동한다.
원본은 끝점을 (30,100) 으로 닫아 이 점프를 없앴다.

### 5. 원본 주석의 「무한대(∞) 모양」

- **원본의 주장** — 경로가 「가로로 누운 무한대(∞) 모양」이다.
- **왜 의심스러운가** — 경로를 읽으면 위로 부푼 곡선 하나와 아래로 부푼 곡선 하나가 양 끝에서 만나는 고리다.
- ∞ 라면 가운데에서 선이 엇갈려야 하는데, 두 곡선은 (30,100) 과 (270,100) 에서만 만난다.
- 그래서 실제 모양은 가로로 긴 타원에 가까운 닫힌 고리다(원본에 근거 없음 — 추론).

### 6. 이모지 자체의 기울기

`offset-rotate: auto` 는 요소를 진행 방향으로 돌리지만, 이모지 글리프가 원래 어느 쪽을 향해 그려졌는지는 글꼴마다 다르다 (확인 필요).
로켓 머리가 진행 방향과 딱 맞지 않아 보일 수 있다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `offset-distance` 의 % 는 경로 전체 길이 기준이다 | CSS Motion Path 명세 (확인 필요) |
| `path()` 좌표는 px 이고 viewBox 처럼 늘지 않는다 | CSS Motion Path 명세 (확인 필요) |
| viewBox 가 SVG 내용을 SVG 크기에 맞춰 늘린다 | SVG 명세 |
| 🚀 이모지가 원래 향하는 방향 | 글꼴(플랫폼)마다 다름 — 보장 없음 |
| 브라우저별 지원 범위 | 이 문서에서 다루지 않음 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 곡선 궤적을 따라 계속 움직이기 | `offset-path` + `offset-distance` 애니메이션 | 점을 잔뜩 찍은 left/top 키프레임 |
| 진행 방향을 바라보는 로켓 · 자동차 | `offset-rotate: auto` | 키프레임마다 `rotate()` 손으로 맞추기 |
| 궤적 가이드를 함께 보여 주기 | 같은 문자열의 SVG `d` + viewBox = 무대 크기 | 크기가 바뀌는 무대에 고정 px 경로 |
| 직선으로 한 번 미끄러지기 | `transform: translate` 애니메이션 | 굳이 모션 패스 |

## 핵심 문장

1. **경로는 `offset-path`, 위치는 `offset-distance`, 방향은 `offset-rotate`** — 애니메이션하는 것은 `offset-distance` 하나다.
2. **`offset-distance` 의 % 는 경로 길이의 비율**이라 `linear` 면 경로 위를 등속으로 달린다.
3. **가이드와 이동을 겹치려면 `path()` = SVG `d`, viewBox = 무대 크기** 둘 다 맞아야 한다.
4. **닫힌 경로 + `infinite`** 여야 반복 이음매에서 튀지 않는다.
5. **`M`/`C` 를 읽으면 궤적이 보인다** — 제어점은 곡선을 끌 뿐 곡선 위의 점이 아니다.

## 용어 풀이

- **모션 패스** — 경로를 정해 두고 경로 위의 위치 값 하나로 요소를 움직이는 기법.
- **`offset-path`** — 요소가 따라갈 경로를 정하는 속성.
- **`offset-distance`** — 경로 위에서 요소가 있는 지점을 길이 비율로 정하는 속성.
- **`offset-rotate`** — 경로를 따라갈 때 요소의 회전을 정하는 속성.
- **베지어 곡선** — 시작점 · 끝점 · 제어점으로 모양을 정하는 곡선.
- **제어점** — 곡선을 끌어당기지만 곡선이 지나가지는 않는 점.
- **닫힌 경로** — 끝점이 출발점과 같은 경로.
- **접선 방향** — 곡선의 한 점에서 곡선이 나아가는 방향.
- **viewBox** — SVG 내부 좌표계의 범위. SVG 크기에 맞춰 늘거나 준다.
- **timing function** — 애니메이션 진행 비율을 시간에 따라 바꾸는 함수.
- **`stroke-dasharray`** — SVG 선을 점선으로 그리는 속성. `4 4` 는 4 그리고 4 쉬기.

## 더 들어가면

- `offset-rotate` 의 초기값이 `auto` 라서, 원본의 `offset-rotate: auto` 선언은 뜻을 드러내는 구실이 크다 (확인 필요).
- `offset-rotate` 에는 `auto 45deg` 처럼 각도를 더하거나 `0deg` 처럼 고정 각도를 줄 수도 있다 — 기울어진 이모지를 보정할 때 쓸 수 있다 (확인 필요).
- 요소의 어느 점이 경로 위에 놓이는지는 `offset-anchor` 가 정하며, 기본은 요소의 가운데 쪽이다 (확인 필요).
- `offset-path` 에는 `path()` 말고 `circle()` · `ray()` 같은 다른 꼴도 있다 (확인 필요).
- `offset-*` 이동은 `transform` 과 함께 적용되어, 따로 준 `scale` 등과 겹쳐 쓸 수 있다 (확인 필요).
