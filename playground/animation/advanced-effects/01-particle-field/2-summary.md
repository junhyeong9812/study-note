## 한눈에 — 쉽게 말하면

**파티클 필드는 「매 장을 지우고 다시 그리는 플립북」이다.**
플립북은 장마다 그림을 조금씩 옮겨 그린다.
그래서 빠르게 넘기면 움직이는 것처럼 보인다.
이 효과도 똑같은 구조다.
한 장(프레임)마다 캔버스를 지운다.
그다음 점마다 위치를 조금 옮기고, 가까운 점끼리 실을 잇고, 점을 찍는다.
그리고 다음 장을 넘겨 달라고 브라우저에 부탁한다.
마우스는 플립북 위에 부는 입김과 같다.
입김이 닿는 곳의 점은 바깥으로 밀려난다.

| 비유 | 실체 |
|---|---|
| 플립북 한 장 | `animate()` 한 번 호출 = 한 프레임 |
| 장 넘기기 | `requestAnimationFrame(animate)` |
| 지우개 | `ctx.clearRect(0, 0, W, H)` |
| 점 하나 | 파티클 객체 `{ x, y, vx, vy }` |
| 가까운 점을 잇는 실 | 거리가 `CONNECT_DIST` 미만인 두 점 사이의 선 |
| 입김 | 마우스 반경 `MOUSE_RADIUS` 안의 밀어내기 |

```text
animate() 한 번 = 플립북 한 장

 ┌─ 지운다 ─→ 점을 옮긴다 ─→ 가까운 점끼리 선 ─→ 점을 찍는다 ─┐
 │                                                         │
 └───────────── requestAnimationFrame(animate) ←───────────┘
```

## 이 주제가 답하려는 질문

1. DOM 요소 없이 점 수십 개를 어떻게 매 순간 움직이나?
2. 마우스 위치를 어떻게 캔버스 좌표로 받아 근처 점을 밀어내나?
3. 가까운 점끼리 어떻게 찾아 선으로 잇고, 그 계산 비용은 얼마나 커지나?

## 동작 방식

### (1) 캔버스에 매 프레임 다시 그리기

**언제 쓰나** — 그릴 대상이 많고, 모양과 위치가 쉬지 않고 바뀔 때 쓴다.

`<canvas>` 는 픽셀을 칠하는 판 하나다.
판 위에 그린 점과 선은 HTML 요소가 아니다.
그래서 CSS 선택자로 고르거나 CSS 애니메이션(`@keyframes` · `transition`)을 걸 수 없다.
캔버스는 무엇을 그렸는지 기억하지 않는다.
그러니 움직임을 보이려면 매 프레임 전부 지우고 새 위치에 다시 그려야 한다.

> **캔버스(canvas)** — 스크립트로 픽셀을 그리는 HTML 요소다.\
> 예: `<canvas id="particles" width="400" height="300">`.

> **2D 컨텍스트** — 캔버스에 선 · 원 · 색을 그리는 도구 묶음이다.\
> 예: `canvas.getContext('2d')` 가 돌려주는 `ctx`.

```text
입력 코드                          무엇이 일어나나                     결과
function animate() {
  ctx.clearRect(0,0,W,H);     →   판 전체를 투명하게 지운다
  (옮기기 · 선 · 점)           →   새 위치로 다시 그린다              한 장 완성
  requestAnimationFrame(...)  →   "다음 화면 그리기 전에 또 불러 줘"   다음 장 예약
}
animate();                    →   첫 장을 직접 시작한다              루프가 돈다
```

- `clearRect` 가 앞 장의 그림을 지운다.
- 그 위에 이번 장의 그림을 새로 그린다.
- `requestAnimationFrame` 은 브라우저가 다음 화면을 그리기 직전에 함수를 **한 번** 불러 달라고 예약한다.
- 한 번만 부르므로 `animate` 끝에서 매번 다시 예약해야 루프가 이어진다.
- 몇 번 불리는지(초당 횟수)는 코드가 아니라 브라우저가 화면 갱신에 맞춰 정한다.

> **프레임** — 화면에 한 번 그려지는 한 장면이다.\
> 예: `animate()` 가 한 번 끝나면 한 프레임이 그려진다.

> **`requestAnimationFrame`** — 다음 화면 그리기 직전에 콜백을 한 번 부르도록 예약하는 브라우저 함수다.\
> 예: `requestAnimationFrame(animate);`.

### (2) 파티클 하나의 상태와 이동

**언제 쓰나** — 많은 대상이 각자 자기 속도로 움직여야 할 때 쓴다.

파티클은 위치 `x, y` 와 속도 `vx, vy` 네 값만 가진 객체다.
처음에는 위치를 캔버스 안 무작위로, 속도를 `(Math.random() - 0.5) * 0.8` 로 정한다.
`Math.random()` 이 0 이상 1 미만이므로 속도는 −0.4 이상 0.4 미만이다.

```text
한 프레임의 갱신 (파티클 p 하나)

 vx *= 0.98            마찰: 속도가 2% 줄어든다
 x  += vx              속도만큼 옮긴다
 x < 0 또는 x > W 이면  vx *= -1   벽에서 방향을 뒤집는다
 x = max(0, min(W, x))             위치를 0~W 안으로 가둔다
 (y 도 똑같이, 경계는 H)
```

- 마찰 `0.98` 이 매 프레임 속도를 조금씩 줄인다.
- 속도를 위치에 더해 점을 옮긴다.
- 위치가 벽을 넘으면 그 축의 속도 부호를 뒤집어 튕겨 낸다.
- 마지막으로 위치를 캔버스 안으로 잘라 넣는다.

마찰 때문에 마우스가 밀어 주지 않으면 속도는 계속 줄기만 한다.
속도를 늘리는 코드는 마우스 밀어내기 하나뿐이다.
벽 반사는 방향만 바꾸고 크기는 그대로 둔다.
60 프레임 뒤 속도는 처음의 0.98⁶⁰ ≈ 0.30 배다.
그래서 마우스를 대지 않고 두면 점들은 점점 느려져 거의 멈춘다.
몇 초 만에 멈추는지는 초당 프레임 수에 따라 달라진다.

> **마찰(감쇠)** — 매 프레임 속도에 1 보다 작은 수를 곱해 점점 줄이는 것이다.\
> 예: `p.vx *= 0.98`.

### (3) 마우스 좌표 받기와 밀어내기

**언제 쓰나** — 사용자의 포인터 위치에 따라 그림이 반응해야 할 때 쓴다.

캔버스의 그리기 해상도는 속성 `width="400" height="300"` 이다.
화면에 보이는 크기는 CSS `width: 100%` 가 정한다.
둘이 다르면 화면의 1px 이 그리기 좌표의 1 과 같지 않다.
그래서 마우스 좌표를 그리기 좌표로 환산한다.

```text
mousemove 이벤트
 e.clientX           화면(뷰포트) 기준 x
 - rect.left         캔버스 왼쪽 끝 기준으로 옮김
 * (W / rect.width)  화면 크기 → 그리기 해상도로 비율 환산
 = mouse.x           파티클과 같은 좌표계
```

- `getBoundingClientRect()` 가 캔버스가 화면에서 차지한 위치와 크기를 준다.
- 캔버스 왼쪽 위를 0 으로 맞춘다.
- `W / rect.width` 를 곱해 CSS 로 늘어나거나 줄어든 비율을 되돌린다.
- `mouseleave` 에서는 마우스를 `(-999, -999)` 로 보낸다.
- 캔버스 안의 어느 점에서도 이 자리까지는 1000 이 넘게 떨어져 있다(가장 가까운 `(0,0)` 까지도 약 1413).
- 그래서 반경 100 안에 드는 점이 없고, 밀어내기가 멈춘다.

```text
밀어내기 (반경 MOUSE_RADIUS = 100)

 dx = p.x - mouse.x ,  dy = p.y - mouse.y     마우스 → 점 방향
 dist = √(dx² + dy²)
 dist < 100 이고 dist > 0 이면
   vx += (dx / dist) * 0.3                    단위 방향 × 0.3
   vy += (dy / dist) * 0.3
```

- `dx` 는 「점 − 마우스」라 방향이 마우스에서 멀어지는 쪽이다.
- `dx / dist` 는 길이 1 인 방향(단위 벡터)이다.
- 거기에 0.3 을 곱해 매 프레임 속도에 더한다.
- 반경 안이면 거리와 상관없이 같은 세기(0.3)로 민다 — 반경 밖은 0 이다.
- `dist > 0` 은 0 으로 나누기를 막는다.
- 마우스와 점이 정확히 겹치면 `dx / dist` 가 `0 / 0` 이 되어 `NaN` 이 되고, 그 점의 위치가 망가진다.

> **단위 벡터** — 방향만 남기고 길이를 1 로 맞춘 벡터다.\
> 예: `(dx / dist, dy / dist)`.

### (4) 가까운 점 잇기 — 모든 쌍 비교

**언제 쓰나** — 대상끼리의 관계(거리)를 그림으로 보여 줄 때 쓴다.

```text
for i = 0 .. n-1
  for j = i+1 .. n-1          같은 쌍을 두 번 보지 않는다 (i<j)
    dist < CONNECT_DIST(80) 이면
      선 긋기, 투명도 = (1 - dist/80) * 0.5

 거리 0  → 0.5  (가장 진함)
 거리 40 → 0.25
 거리 80 → 0    (이 거리부터는 선을 긋지 않는다)
```

- 바깥 고리가 점 하나를 고르고, 안쪽 고리가 그보다 뒤 번호의 점만 본다.
- 그래서 쌍마다 한 번씩, 모두 n(n−1)/2 번 거리를 잰다.
- 80개면 80×79÷2 = 3160 번, 200개면 200×199÷2 = 19900 번이다.
- 점 수가 2.5 배가 되면 비교 수는 약 6.3 배가 된다 — 이것이 원본 팁의 O(n²) 이다.
- 가까울수록 선이 진하고, 80 에 다가갈수록 흐려지다 사라진다.

그리는 차례는 「선 → 점」이다.
캔버스는 나중에 그린 것이 위에 덮인다.
그래서 점이 선 끝을 덮어 선 위에 동그랗게 보인다.

> **O(n²)** — 개수 n 이 늘 때 일의 양이 n 의 제곱에 비례해 늘어난다는 뜻이다.\
> 예: 모든 쌍의 거리 재기.

## 문법 — 형태와 규칙

```html demo
<canvas id="c" width="200" height="100" style="background:#0f172a"></canvas>
<script>
  const ctx = document.getElementById('c').getContext('2d');
  let x = 0, vx = 2;
  function frame() {
    ctx.clearRect(0, 0, 200, 100);
    x += vx;
    if (x < 0 || x > 200) vx *= -1;
    ctx.beginPath();
    ctx.arc(x, 50, 4, 0, Math.PI * 2);
    ctx.fillStyle = '#60a5fa';
    ctx.fill();
    requestAnimationFrame(frame);
  }
  frame();
</script>
```

> **보이는 것** — 어두운 띠 안에서 파란 점 하나가 좌우 끝을 오가며 튕긴다 (코드에서 읽은 것 — 렌더 실측 아님)

| 호출 | 하는 일 |
|---|---|
| `canvas.getContext('2d')` | 2D 그리기 도구를 얻는다 |
| `ctx.clearRect(x, y, w, h)` | 사각형 영역을 투명하게 지운다 |
| `ctx.beginPath()` | 새 경로를 시작한다(앞 경로와 끊는다) |
| `ctx.moveTo(x, y)` · `ctx.lineTo(x, y)` | 선의 시작점과 끝점을 정한다 |
| `ctx.arc(x, y, r, 0, Math.PI * 2)` | 중심 `(x, y)`, 반지름 `r` 인 원 경로를 만든다 |
| `ctx.strokeStyle` · `ctx.stroke()` | 선 색을 정하고 경로를 선으로 그린다 |
| `ctx.fillStyle` · `ctx.fill()` | 채움 색을 정하고 경로 안을 칠한다 |
| `requestAnimationFrame(fn)` | 다음 화면 그리기 직전에 `fn` 을 한 번 부른다 |

- 색은 `stroke()` · `fill()` 을 부르기 **전에** 정해야 그 색으로 그려진다.
- 경로마다 `beginPath()` 를 부르지 않으면 앞 경로가 이어 붙어 함께 다시 그려진다.
- 캔버스의 그리기 해상도는 HTML 속성 `width` · `height` 이고, 보이는 크기는 CSS 가 정한다 — 둘은 따로 논다.
- `Array.from({ length: n }, () => ({ ... }))` 는 길이 n 인 배열을 만들며 칸마다 새 객체를 넣는다.
- `(function() { ... })();` 는 함수를 만들자마자 부르는 꼴(즉시 실행 함수)이다.
- 그 안의 `const` 들은 함수 안에 갇혀 전역 이름과 부딪히지 않는다.
- `animate` 는 이 함수 안의 `particles` · `mouse` 를 계속 쓴다 — 바깥 함수의 변수를 붙잡은 클로저다.

> **즉시 실행 함수(IIFE)** — 정의하자마자 한 번 호출되는 함수다.\
> 예: `(function() { const W = 400; })();`.

> **클로저** — 함수가 자기가 만들어진 자리의 변수를 붙잡아 계속 쓰는 것이다.\
> 예: `animate` 가 바깥의 `particles` 를 매 프레임 읽는다.

## 어디서 틀리나

### 1. 파티클을 너무 많이 넣는다

원본 팁은 「파티클 수가 많으면 성능 저하 — 200개 이하 권장」이다.
200 은 원본이 권하는 기준이고, 측정한 값으로 적혀 있지는 않다 (확인 필요).
얼마나 버티는지는 기계와 브라우저에 달렸다.

### 2. 연결선 계산이 O(n²) 임을 잊는다

원본 팁대로 연결선 계산은 O(n²) 이다.
80개 → 3160 쌍, 200개 → 19900 쌍이다.
선마다 `beginPath` · `stroke` 를 따로 부르므로 선이 많을수록 그리기도 늘어난다.

### 3. 원본 설명의 「끌려온다」를 믿는다

원본 설명: 「마우스를 피하거나 끌려온다」.
의심스러운 까닭: 코드에서 속도에 더하는 방향은 `dx = p.x - mouse.x`, 곧 마우스에서 **멀어지는** 쪽뿐이다.
끌어당기는 코드는 없다.
끌려오게 하려면 더하는 부호를 바꾼 다른 코드가 필요하다.

### 4. CSS 크기와 그리기 해상도를 헷갈린다

CSS `width: 100%` 로 캔버스가 늘어나도 그리기 좌표는 여전히 400×300 이다.
`W / rect.width` 환산을 빼면 마우스와 밀려나는 자리가 어긋난다.

### 5. `clearRect` 나 다음 프레임 예약을 빼먹는다

`clearRect` 가 없으면 앞 장의 점과 선이 지워지지 않고 겹겹이 쌓인다.
`animate` 끝의 `requestAnimationFrame` 이 없으면 한 장만 그리고 멈춘다.

### 6. `dist > 0` 을 뺀다

마우스가 점과 정확히 겹치면 `0 / 0 = NaN` 이 속도에 들어간다.
`NaN` 은 이후 모든 계산을 `NaN` 으로 만들어 그 점이 사라진 것처럼 된다.

### 7. 반사만 하고 위치를 가두지 않는다

벽을 넘은 점의 속도를 뒤집어도, 다음 프레임에 아직 벽 밖이면 또 뒤집힌다.
그러면 점이 벽 밖에서 방향만 번갈아 바꾸며 갇힐 수 있다.
`Math.max(0, Math.min(W, p.x))` 가 점을 곧바로 안으로 돌려놓아 이 일을 막는다.

### 8. 점이 왜 멈추는지 모른다

마찰 `0.98` 이 속도를 계속 줄이고, 다시 늘리는 것은 마우스뿐이다.
가만두면 점들이 거의 멈추는 것은 버그가 아니라 이 코드의 동작이다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `Math.random()` 은 0 이상 1 미만을 돌려준다 | ECMAScript 언어 명세 |
| `Math.random()` 의 생성 알고리즘과 분포의 품질 | JS 엔진 구현 |
| `requestAnimationFrame` 이 다음 화면 그리기 전에 콜백을 한 번 부른다 | 브라우저 API(HTML 표준) — JS 언어 자체가 아니다 |
| 초당 몇 번 불리는가 | 보장 없음 — 브라우저와 화면에 달렸다 (확인 필요) |
| 0.98⁶⁰ ≈ 0.30 이 몇 초에 해당하나 | 보장 없음 — 프레임 빈도에 달렸다 |
| 선과 원의 픽셀 모양(가장자리를 부드럽게 다듬는 방식) | 브라우저 구현 |
| 「200개 이하 권장」 | 원본 팁 — 측정치가 아니다 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 배경에 떠다니는 점 수십 개 | 캔버스 + `requestAnimationFrame` | 점마다 DOM 요소 + CSS 애니메이션 |
| 마우스에 반응하는 장식 | `mousemove` 좌표를 그리기 좌표로 환산 | 화면 좌표를 그대로 쓰기 |
| 점 수가 수백 개를 넘는다 | 점 수 줄이기(원본 권장 200개 이하) | 모든 쌍 비교를 그대로 두기 |
| 몇 개의 요소가 정해진 길로 움직인다 | CSS `@keyframes` · `transition` | 캔버스로 직접 그리기 |

## 핵심 문장

1. **캔버스는 그린 것을 기억하지 않는다** — 매 프레임 `clearRect` 로 지우고 전부 다시 그린다.
2. **루프는 `animate` 끝에서 `requestAnimationFrame(animate)` 로 다음 장을 예약해 돈다.**
3. **파티클은 `x, y, vx, vy` 네 값이고, 매 프레임 마찰 → 이동 → 반사 → 가두기를 거친다.**
4. **마우스 반경 안의 점은 마우스 반대 방향으로 밀린다** — 끌어당기는 코드는 없다.
5. **연결선은 모든 쌍을 재는 O(n²) 계산이다** — 점 수를 늘리면 비교 수가 제곱으로 는다.

## 용어 풀이

- **캔버스(canvas)** — 스크립트로 픽셀을 그리는 HTML 요소다.
- **2D 컨텍스트** — 캔버스에 그리는 도구 묶음(`ctx`)이다.
- **파티클** — 위치와 속도만 가진 작은 점 하나다.
- **프레임** — 화면에 한 번 그려지는 한 장면이다.
- **`requestAnimationFrame`** — 다음 화면 그리기 직전에 콜백을 한 번 부르도록 예약하는 함수다.
- **마찰(감쇠)** — 매 프레임 속도에 1 보다 작은 수를 곱해 줄이는 것이다.
- **단위 벡터** — 길이를 1 로 맞춰 방향만 남긴 벡터다.
- **O(n²)** — 일의 양이 개수의 제곱에 비례해 느는 것이다.
- **`getBoundingClientRect`** — 요소가 화면에서 차지한 위치와 크기를 돌려주는 메서드다.
- **즉시 실행 함수(IIFE)** — 정의하자마자 호출되는 함수다.
- **클로저** — 함수가 바깥 변수를 붙잡아 계속 쓰는 것이다.
- **`NaN`** — 「숫자가 아님」을 뜻하는 값으로, `0 / 0` 같은 계산에서 나온다.

## 더 들어가면

- 캔버스를 격자 칸으로 나눠 같은 칸과 이웃 칸의 점끼리만 비교하면 모든 쌍 비교를 줄일 수 있다 (확인 필요).
- 많은 브라우저가 보이지 않는 탭에서는 `requestAnimationFrame` 호출을 멈추거나 늦춘다 (확인 필요).
- 고해상도 화면에서 선을 또렷하게 하려면 `window.devicePixelRatio` 만큼 그리기 해상도를 키우는 방법이 쓰인다 (확인 필요).
- `requestAnimationFrame` 콜백이 받는 시각 인자로 프레임 사이 시간을 재서 곱하면, 화면 갱신 빈도가 달라도 같은 빠르기로 움직이게 할 수 있다 (확인 필요).
- `mousemove` 대신 `pointermove` 를 쓰면 터치 입력도 함께 받을 수 있다 (확인 필요).
