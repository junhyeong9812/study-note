## 한눈에 — 쉽게 말하면

**이터레이터는 「버튼을 누를 때마다 번호표가 한 장씩 나오는 발급기」다.**
버튼을 누르면 번호표 한 장이 나오고, 번호표가 다 떨어지면 「마감」 표지가 뜬다.
발급기는 번호표를 미리 다 찍어 두지 않는다.
누를 때마다 안쪽 카운터를 보고 한 장씩 찍는다.
Rust 의 `Iterator` 도 똑같은 구조다.
`next()` 가 버튼이고, `Some(값)` 이 번호표이고, `None` 이 마감 표지다.

| 비유 | 실체 |
|---|---|
| 발급기 | 이터레이터 값(구조체) |
| 버튼 누르기 | `next()` 호출 |
| 번호표 한 장 | `Some(item)` |
| 마감 표지 | `None` |
| 발급기 안의 카운터 | 구조체 필드(상태) |
| 수첩을 들고 번호표마다 메모하며 새 표를 써 주는 직원 | `scan` |
| 지나가는 번호표를 비추기만 하는 CCTV | `inspect` |
| 발급기를 잠깐 빌려 주고 돌려받기 | `by_ref` |
| 「한 번 마감이면 영영 마감」 스티커 | `fuse` |

```text
  상태 (a=0, b=1) ──next()──▶ Some(0)    상태 (1, 1)
  상태 (1, 1)     ──next()──▶ Some(1)    상태 (1, 2)
  상태 (1, 2)     ──next()──▶ Some(1)    상태 (2, 3)
        …                       …
  다음 값을 못 만든다 ──next()──▶ None  (마감)
```

## 이 주제가 답하려는 질문

1. 내가 만든 타입을 이터레이터로 쓰려면 최소한 무엇을 구현해야 하나?
2. 요소를 하나씩 바꾸면서 「지금까지의 상태」를 들고 가거나, 흐름을 건드리지 않고 들여다보려면 어떻게 하나?
3. 이터레이터의 앞부분만 쓰고 나머지를 같은 이터레이터로 이어서 쓰려면 어떻게 하나?
4. `None` 이 나온 뒤 `next()` 를 또 부르면 무엇이 나오나, 그리고 그것을 어떻게 못 박나?

## 동작 방식

### (1) `Iterator` 트레이트 — `next()` 하나가 전부를 끌고 온다

**언제 쓰나** — 「다음 값을 하나씩 내는」 모든 것을 `for` · `map` · `collect` 와 함께 쓰고 싶을 때다.

```text
impl Iterator for T {
    type Item = X;                         ← 무엇을 내는지 정한다
    fn next(&mut self) -> Option<X> {…}    ← 이것만 직접 쓴다
}
        │
        ▼
T 에 map · filter · take · find · collect · scan · inspect · by_ref · fuse … 가 기본 구현으로 붙는다
        │
        ▼
T::new().take(15).collect() 를 바로 쓸 수 있다
```

- `type Item` 은 이터레이터가 내는 요소의 타입을 정하는 연관 타입이다.
- `next` 는 `&mut self` 를 받으므로 부를 때마다 안쪽 상태를 바꿀 수 있다.
- `next` 만 구현하면 나머지 메서드는 트레이트의 기본 구현이 `next` 를 불러 해결한다.
- `map` · `filter` · `inspect` · `scan` · `take` 같은 어댑터는 이터레이터를 감싸기만 하고 아무 일도 하지 않는다.
- `collect` · `find` 처럼 값을 끝까지(또는 필요한 만큼) 당기는 소비자가 `next` 를 부를 때 비로소 일이 일어난다.

> **연관 타입** — 트레이트 안에서 이름만 정해 두고 구현하는 쪽이 실제 타입을 채우는 타입 자리다.\
> 예: `impl Iterator for Fibonacci` 안의 `type Item = u64;`.

> **지연 평가** — 값이 실제로 필요해질 때까지 계산을 미루는 방식이다.\
> 예: `.map(|x| x * x)` 만 써 두면 `collect` 를 부르기 전까지 곱셈이 한 번도 일어나지 않는다.

`for x in v` 는 `v` 에 `IntoIterator` 트레이트의 `into_iter()` 를 불러 이터레이터를 얻는다.
`Vec` 에서 `.iter()` 는 요소의 참조(`&T`)를 내고, `.into_iter()` 는 벡터를 써 버리면서 요소 자체(`T`)를 낸다.
그래서 `nums.iter()` 로 모은 것은 `Vec<&i32>` 가 되고, `data.into_iter()` 로 모은 것은 `Vec<i32>` 가 된다.

> **`IntoIterator`** — 「이터레이터로 바뀔 수 있는 것」을 나타내는 트레이트로, `into_iter()` 를 준다.\
> 예: `for x in vec![1, 2]` 는 안에서 `vec![1, 2].into_iter()` 를 부른다.

### (2) `Fibonacci` — 상태 두 개와 `checked_add(...)?` 로 끝내기

**언제 쓰나** — 앞 값들로 다음 값을 만드는 수열을 구조체 하나로 담고 싶을 때다.

```text
next() 한 번:
  result = a                          ← 낼 값을 먼저 빼 둔다
  next   = a.checked_add(b)?          ← 넘치면 None → next() 가 곧바로 None 을 돌려준다
  a = b ; b = next                    ← 한 칸 밀기
  Some(result)
```

- `checked_add` 는 덧셈이 `u64` 범위를 넘으면 `None`, 아니면 `Some(합)` 을 돌려준다.
- 뒤에 붙은 `?` 는 `None` 을 만나면 그 자리에서 함수 전체가 `None` 을 돌려주게 한다.
- 그래서 `Fibonacci` 는 무한 수열처럼 보이지만 `u64` 가 넘치는 지점에서 스스로 끝난다.
- `None` 을 돌려줄 때는 `a` · `b` 를 바꾸기 전에 빠져나가므로, 다시 불러도 같은 덧셈이 넘쳐 계속 `None` 이다.
- `?` 가 `result` 를 내기 전에 빠져나가므로, 넘치기 직전의 `a` 값은 내지 못하고 끝난다.
- `take(15)` 는 앞 15개만 당기고, `find(|&x| x > 1_000_000)` 은 조건을 처음 만족하는 값에서 멈춘다.
- 원본 주석대로 `find` 는 찾는 즉시 멈추는 지연 소비자다.

### (3) `StepRange` 와 `size_hint` — 남은 개수를 미리 알려 주기

**언제 쓰나** — 남은 개수를 정확히 계산할 수 있는 이터레이터를 만들 때 `size_hint` 까지 구현한다.

```text
StepRange::new(0, 20, 3)
  next 조건: step > 0 이면 current < end, step < 0 이면 current > end
  current: 0 → 3 → 6 → 9 → 12 → 15 → 18 → 21(조건 실패 → None)
  처음 size_hint: (20 - 0 + 3 - 1) / 3 = 22 / 3 = 7  →  (7, Some(7))

StepRange::new(10, 0, -2)
  current: 10 → 8 → 6 → 4 → 2 → 0(10..0 은 0 을 넣지 않음 → None)
  처음 size_hint: (10 - 0 + 2 - 1) / 2 = 11 / 2 = 5  →  (5, Some(5))
```

- `size_hint` 는 `(하한, Some(상한))` 을 돌려준다.
- 상한을 모르면 `None` 을 쓰고, 정확히 알면 원본 주석대로 `(n, Some(n))` 이다.
- 구현하지 않으면 기본값은 `(0, None)` 이다.
- `(차이 + step - 1) / step` 은 나눗셈을 올림하는 흔한 꼴이다.
- 원본 팁대로 `size_hint` 를 구현하면 `collect` 가 `Vec` 자리를 미리 잡을 수 있다.
- step 이 0 이면 `next` 의 두 조건이 모두 거짓이라 바로 `None` 이고, `size_hint` 도 0 을 돌려준다.

> **`size_hint`** — 「앞으로 몇 개 남았나」를 (하한, 상한) 짝으로 알려 주는 `Iterator` 의 메서드다.\
> 예: 일곱 개가 남았으면 `(7, Some(7))`.

### (4) `Windowed` — 다른 이터레이터를 품는 어댑터

**언제 쓰나** — 연속한 `size` 개씩 묶은 「미끄러지는 창」을 이터레이터로 내고 싶을 때다.

```text
안쪽: 1 2 3 4 5 6 , size = 3
첫 호출  : 3개 채움          buffer [1,2,3]  → Some([1,2,3])
둘째     : remove(0), push 4 buffer [2,3,4]  → Some([2,3,4])
셋째     : remove(0), push 5 buffer [3,4,5]  → Some([3,4,5])
넷째     : remove(0), push 6 buffer [4,5,6]  → Some([4,5,6])
다섯째   : remove(0) → [5,6], 안쪽 next() 가 None → ? 로 None
```

- `Windowed<I: Iterator>` 는 안쪽 이터레이터 `I` 를 필드로 들고 있어서 어떤 이터레이터든 감쌀 수 있다.
- `first` 깃발로 「처음 채우기」와 「한 칸 밀기」를 나눈다.
- 안쪽이 모자라면 `self.iter.next()?` 의 `?` 가 `None` 을 그대로 바깥으로 전한다.
- 창을 내보낼 때 `buffer.clone()` 으로 복사본을 주므로 `I::Item: Clone` 조건이 붙는다.
- 버퍼는 계속 재사용하고 바깥에는 복사본만 나간다.

### (5) `scan` — 상태를 들고 다니는 `map`

**언제 쓰나** — 요소마다 「지금까지의 누적」을 반영한 값을 내고 싶을 때다.

```text
[1, 2, 3, 4, 5].iter().scan(0, |state, &x| { *state += x; Some(*state) })

x:      1   2   3    4    5
state:  1   3   6   10   15     ← state 는 &mut 로 들어와 다음 요소까지 살아남는다
낸 값:  1   3   6   10   15     → [1, 3, 6, 10, 15]
```

- 첫 인수는 상태의 처음 값이고, 클로저는 `(&mut 상태, 요소)` 를 받는다.
- 클로저가 `Some(v)` 를 돌려주면 `v` 가 다음으로 흐르고, `None` 을 돌려주면 그 자리에서 이터레이션이 끝난다.
- 상태는 튜플이어도 된다.
- 원본은 `(0.0, 0usize)` 를 상태로 두고 합과 개수를 함께 늘려 `합 / 개수` 를 낸다.
- 이 값은 처음부터 지금까지 본 모든 값의 평균(누적 평균)이다.

### (6) `inspect` — 흐름을 건드리지 않고 들여다보기

**언제 쓰나** — 파이프라인 중간에 무엇이 지나가는지 찍어 보고 싶을 때(디버깅)다.

```text
(1..=10).inspect(원본 찍기).filter(3의 배수).inspect(필터후 찍기).map(제곱).collect()

요소 1 → [원본:1] → filter 탈락
요소 2 → [원본:2] → filter 탈락
요소 3 → [원본:3] → 통과 → [필터후:3] → 9 를 Vec 에
요소 4 → [원본:4] → 탈락
  …
```

- `inspect` 의 클로저는 요소의 참조를 받아 부수 효과만 낸다.
- 요소는 바뀌지 않은 채 다음 단계로 넘어간다.
- 지연 평가라서 요소 하나가 파이프라인 끝까지 흐른 뒤에 다음 요소가 출발한다.
- 그래서 「원본 꼬리표 전부 → 필터후 꼬리표 전부」가 아니라 둘이 요소마다 섞여 찍힌다.
- 원본은 `print!` 로 꼬리표를 한 줄에 이어 찍고, 끝에 `println!()` 으로 줄을 닫는다.

### (7) `by_ref` — 이터레이터를 빌려 일부만 쓰기

**언제 쓰나** — 앞 몇 개를 따로 모은 뒤 같은 이터레이터로 나머지를 이어 쓰고 싶을 때다.

```text
let mut iter = nums.iter();              ← 1..10 의 참조를 내는 이터레이터
iter.by_ref()   → &mut iter              ← 이터레이터를 빌려준다
     .take(3)   → 빌린 것에서 3개만 당긴다
     .collect() → [1, 2, 3]
iter.collect()  → [4, 5, 6, 7, 8, 9, 10] ← iter 는 그대로 살아 있고 위치만 4 로 가 있다
```

- `take` 는 받은 이터레이터를 값으로 가져간다(소유권 이동).
- `iter.take(3)` 이라 쓰면 `iter` 자체가 옮겨가서 다음 줄의 `iter` 를 쓸 수 없다.
- `by_ref()` 는 `&mut iter` 를 돌려주고, `&mut` 이터레이터도 이터레이터로 쓸 수 있다.
- 그래서 `take` 가 가져가는 것은 빌림뿐이고, 빌림이 끝나면 원래 `iter` 를 다시 쓸 수 있다.

> **소유권 이동(move)** — 값을 다른 곳에 넘기면 원래 이름으로는 더 쓸 수 없게 되는 Rust 의 규칙이다.\
> 예: `let b = a;` 뒤에 `a` 를 쓰면 컴파일 오류다(`Copy` 가 아닌 타입일 때).

### (8) `fuse` — 「한 번 `None` 이면 영영 `None`」

**언제 쓰나** — `None` 뒤의 동작을 모르는 이터레이터를 넘겨받아, 끝난 뒤에는 확실히 끝난 채로 두고 싶을 때다.

```text
일반 이터레이터: Some, Some, None, (그다음은 이터레이터 마음대로 — Some 이 다시 올 수도, 패닉할 수도)
.fuse() 를 거치면: Some, Some, None, None, None, …  ← 첫 None 뒤에는 안쪽 next() 를 부르지 않는다
```

- 원본 주석대로 `Iterator` 의 약속에는 「`None` 다음 호출」이 들어 있지 않다.
- 그래서 일부 이터레이터는 `None` 뒤에 다시 `Some` 을 줄 수 있다.
- `fuse()` 는 안쪽이 한 번 `None` 을 낸 것을 기억하고, 그 뒤로는 안쪽을 부르지 않고 `None` 만 낸다.
- 원본 예제는 `vec![1, 2, 3].into_iter().fuse()` 에 `next()` 를 다섯 번 불러 `Some(1), Some(2), Some(3), None, None` 을 기대한다.
- `Vec` 의 `into_iter()` 는 원래부터 끝난 뒤 계속 `None` 을 내므로, 이 예제는 `fuse` 를 빼도 같은 결과일 것이다 (확인 필요).
- `fuse` 의 차이가 드러나는 것은 `Windowed` 처럼 `None` 뒤 호출에 무방비한 이터레이터다(「어디서 틀리나」 5).

### (9) `std::iter` 의 생성 함수 — 구조체 없이 이터레이터 만들기

**언제 쓰나** — 한 번 쓰고 말 간단한 이터레이터를 위해 구조체와 `impl` 을 쓰기 번거로울 때다.

```text
from_fn(|| -> Option<T>)          클로저가 곧 next(). 바깥 변수를 바꾸며 값을 낸다  → [1, 2, 3, 4, 5]
successors(Some(1), |&p| p.checked_mul(2))  앞 값으로 다음 값. None 이면 끝  → 1, 2, 4, 8, … (take(10))
repeat(5)                         같은 값을 끝없이  → take(4) 로 [5, 5, 5, 5]
once("=== 헤더 ===")               요소 하나짜리
  .chain(다른 이터레이터)           뒤에 이어 붙이기  → ["=== 헤더 ===", "데이터1", "데이터2"]
```

- `from_fn` 의 클로저는 `FnMut() -> Option<T>` 꼴이라 바깥 변수 `count` 를 바꿀 수 있다.
- `successors` 는 첫 값을 `Option` 으로 받고, 클로저가 이전 값의 참조로 다음 값을 `Option` 으로 만든다.
- `successors` 와 `checked_mul` 을 함께 쓰면 넘치는 곳에서 스스로 끝나는 수열이 된다.
- `repeat` 는 끝이 없으므로 `take` 없이 `collect` 하면 끝나지 않는다.
- 원본 주석은 `repeat_with`(클로저로 값을 매번 만들어 반복)와 `empty`(요소가 없는 이터레이터)도 언급하지만 예제에서 쓰지는 않는다.

## 문법 — 형태와 규칙

```rust
struct Countdown(u32);

impl Iterator for Countdown {
    type Item = u32;
    fn next(&mut self) -> Option<u32> {
        if self.0 == 0 { return None; }
        self.0 -= 1;
        Some(self.0 + 1)
    }
}

fn main() {
    let all: Vec<u32> = Countdown(3).collect();
    let mut it = Countdown(5);
    let head: Vec<u32> = it.by_ref().take(2).collect();
    let tail: Vec<u32> = it.collect();
}
```

- `impl Iterator for 타입` 안에 `type Item = …;` 과 `fn next(&mut self) -> Option<Self::Item>` 을 쓴다.
- 값을 내려면 `Some(값)`, 끝내려면 `None` 을 돌려준다.
- 상태는 구조체 필드에 두고 `next` 안에서 바꾼다.
- `Option` 을 돌려주는 연산(`checked_add` · 안쪽 `next()`) 뒤에 `?` 를 붙이면 `None` 이 곧 종료가 된다.
- 남은 개수를 정확히 알면 `fn size_hint(&self) -> (usize, Option<usize>)` 도 구현한다.
- 제네릭 어댑터는 `struct 이름<I: Iterator> { iter: I, … }` 꼴로 안쪽 이터레이터를 품는다.
- `scan(처음상태, |상태, 요소| Option<출력>)` · `inspect(|참조| 부수효과)` · `by_ref()` · `fuse()` 는 모두 `Iterator` 의 메서드다.
- `std::iter::from_fn` · `successors` · `repeat` · `once` 는 함수로 부른다.

## 어디서 틀리나

### 1. 「이동 평균」이라는 이름과 실제 계산이 다르다

원본의 주장 → `scan` 으로 「이동 평균」을 구한다고 한다(변수 이름 `moving_avg`).
왜 의심스러운가 → 상태 `(sum, count)` 가 처음부터 계속 쌓이기만 하므로, 나오는 값은 「최근 k 개의 평균」이 아니라 「처음부터 지금까지의 평균(누적 평균)」이다.
`[10.0, 20.0, 30.0, 25.0, 15.0, 35.0]` 이면 `10/1, 30/2, 60/3, 85/4, 100/5, 135/6` 을 계산한다.
최근 k 개의 평균이 필요하면 창 안에서 빠지는 값을 합에서 빼야 한다.

### 2. `fuse` 예제는 `fuse` 의 효과를 보여 주지 못한다

원본 주석은 「일부 이터레이터는 `None` 뒤에 다시 `Some` 을 줄 수 있다」고 옳게 말한다.
그러나 예제가 감싼 `Vec` 의 `into_iter()` 는 원래 끝난 뒤 계속 `None` 을 내므로 `fuse` 를 빼도 다섯 번째까지 같은 결과일 것이다 (확인 필요).
`fuse` 가 의미 있는 것은 `None` 뒤의 동작을 모르는 이터레이터를 감쌀 때다.

### 3. `Fibonacci` 는 마지막 몇 값을 내지 못하고 끝난다

`next` 는 `result = a` 를 잡은 뒤 `a + b` 가 넘치는지 확인하고, 넘치면 `result` 를 내지 않고 `None` 을 돌려준다.
그래서 `u64` 에 들어가는 피보나치 수 가운데 마지막 것들은 나오지 않는다.
「넘치는 지점에서 자연스럽게 끝난다」는 원본 주석은 맞지만, 「`u64` 에 들어가는 값을 전부 낸다」는 뜻은 아니다.

### 4. `StepRange::size_hint` 는 「이미 끝났거나 처음부터 빈」 범위를 다루지 않는다

`self.end - self.current` 가 음수가 되는 경우가 있다.
`StepRange::new(5, 0, 1)` 처럼 처음부터 빈 범위이거나, `0..20 step 3` 이 `current = 21` 까지 간 뒤가 그렇다.
음수 `i32` 를 `as usize` 로 바꾸면 `usize` 의 최댓값에 가까운 아주 큰 수가 된다.
그러면 힌트가 실제 남은 개수(0)와 크게 어긋나고, step 이 크면 뒤따르는 덧셈이 넘쳐 디버그 빌드에서 패닉할 수도 있다 (확인 필요).
`current` 가 `i32` 범위 끝 근처에서 `+= step` 하면 그 덧셈도 넘칠 수 있다.

### 5. `Windowed` 는 `None` 뒤에 계속 부르면 패닉할 수 있다

안쪽이 다 떨어진 뒤의 호출도 `else` 가지로 가서 `buffer.remove(0)` 을 먼저 하고 `?` 로 빠져나간다.
그래서 `None` 을 낼 때마다 버퍼가 하나씩 줄어든다.
버퍼가 비었는데 또 부르면 빈 `Vec` 에 `remove(0)` 을 하게 되고, `Vec::remove` 는 범위 밖 위치에서 패닉한다.
`size` 가 0 이면 첫 호출에 빈 창을 내고, 둘째 호출에서 곧바로 빈 버퍼에 `remove(0)` 을 한다.
`collect` 는 첫 `None` 에서 멈추므로 원본 예제에서는 드러나지 않는다.

### 6. `by_ref` 없이 `take` 를 부르면 원본 이터레이터가 사라진다

`take` 는 이터레이터를 값으로 가져간다.
`iter.take(3).collect()` 뒤의 `iter.collect()` 는 「옮겨진 값을 썼다」는 컴파일 오류가 된다.
원본 팁대로 일부만 소비하고 나머지를 쓸 때는 `by_ref()` 로 빌려서 넘긴다.

### 7. `inspect` 로 값을 바꿀 수는 없고, 찍히는 차례는 요소 단위다

`inspect` 의 클로저는 요소의 참조만 받으므로 값을 바꾸는 자리가 아니다.
원본 팁대로 디버깅에 알맞다.
지연 평가 때문에 여러 `inspect` 의 출력은 단계별로 모이지 않고 요소마다 섞인다.

### 8. 끝없는 이터레이터에 `take` 없이 `collect` 하면 끝나지 않는다

`repeat(5).collect()` 는 영원히 값을 모으려 한다.
`Fibonacci` 와 `successors(…, checked_mul)` 은 넘치는 곳에서 끝나긴 하지만, 그 길이를 원하는 경우는 드물다.
끝없는 이터레이터는 `take` · `find` · `take_while` 처럼 멈추는 쪽과 짝지어 쓴다.

### 9. 「`next()` 만 구현하면 된다」는 최소 조건이지 최선이 아니다

원본 팁대로 `next` 하나로 모든 어댑터를 쓸 수 있다.
다만 `size_hint` 는 기본값 `(0, None)` 으로 남아 `collect` 가 미리 자리를 잡지 못한다.
남은 개수를 정확히 안다면 `size_hint` 를 같이 구현하는 편이 낫다.
그 계산이 틀리면 4번처럼 거짓 힌트가 된다는 점도 함께 기억한다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `next` 만 구현하면 `map` · `take` · `collect` 등을 쓸 수 있다 | 표준 라이브러리의 `Iterator` 트레이트(기본 구현) |
| 어댑터는 소비자가 당길 때까지 일하지 않는다(지연 평가) | 표준 라이브러리 어댑터들의 문서화된 동작 |
| `size_hint` 를 구현하면 `collect` 가 `Vec` 자리를 미리 잡는다 | 표준 라이브러리 `Vec` 구현이 힌트를 쓰는 방식 — 트레이트는 「힌트」라고만 약속한다 (확인 필요) |
| `None` 뒤의 `next` 결과 | 보장 없음 — 이터레이터마다 다르다 · `fuse()` 를 거치면 계속 `None` 이 보장된다 |
| `Vec` 의 `into_iter()` 는 끝난 뒤 계속 `None` 을 낸다 | 표준 라이브러리의 `vec::IntoIter` 구현 (확인 필요) |
| `checked_add` · `checked_mul` 은 넘치면 `None` | 표준 라이브러리 정수 메서드의 약속 |
| `+=` 같은 일반 연산이 넘치면 패닉한다 | 빌드 설정 — 디버그 빌드는 보통 패닉, 릴리스 빌드는 보통 감싸 돈다 (확인 필요) |
| `println!` 안의 `fused.next()` 다섯 개가 왼쪽부터 차례로 불린다 | 형식 인수를 적힌 차례대로 평가하는 언어 · 매크로 동작 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 누적합 · 누적 평균처럼 앞의 결과에 기대는 변환 | `scan` | 바깥 `let mut` 변수를 `map` 클로저에서 몰래 바꾸기 |
| 파이프라인 중간에 무엇이 지나가는지 보기 | `inspect` | 값을 바꾸려는 용도의 `inspect` |
| 앞 n 개만 따로 쓰고 나머지를 이어 쓰기 | `by_ref().take(n)` | `take(n)` 을 원본에 바로 걸기 |
| `None` 뒤 동작을 모르는 이터레이터를 넘겨받음 | `fuse()` | 「끝났으니 다시 안 부르겠지」라는 가정 |
| 상태가 여럿이고 여러 곳에서 재사용할 이터레이터 | 구조체 + `impl Iterator` | 매번 새로 쓰는 `from_fn` 클로저 |
| 한 번 쓰고 마는 간단한 생성기 | `from_fn` · `successors` | 구조체와 `impl` 을 따로 만들기 |
| 남은 개수를 정확히 아는 커스텀 이터레이터 | `size_hint` 구현 | 음수 차이를 검사하지 않는 `as usize` 계산 |
| 같은 값을 n 번 / 앞에 머리글 하나 붙이기 | `repeat(v).take(n)` / `once(h).chain(…)` | `take` 없는 `repeat(v).collect()` |

## 핵심 문장

1. **이터레이터는 `type Item` 과 `next()` 하나로 완성되고, 나머지 메서드는 모두 그 위에 공짜로 얹힌다** — 끝은 `None` 으로 알린다.
2. **어댑터는 지연 평가라서 요소 하나가 파이프라인 끝까지 흐른 뒤에 다음 요소가 출발한다** — `inspect` 의 출력이 섞이는 까닭이다.
3. **`scan` 은 `&mut` 상태를 들고 다니는 `map` 이고, 클로저가 `None` 을 돌려주면 거기서 끝난다.**
4. **`by_ref()` 는 이터레이터를 빌려 넘겨서, 일부를 소비한 뒤에도 원본을 이어 쓰게 한다.**
5. **`None` 뒤의 `next()` 는 약속된 것이 없고, `fuse()` 가 그것을 「계속 `None`」으로 못 박는다.**

## 용어 풀이

- **이터레이터(iterator)** — `next()` 를 부를 때마다 값을 하나씩 내는 것.
- **`Iterator` 트레이트** — `type Item` 과 `next` 를 요구하고 수많은 어댑터를 기본으로 주는 표준 트레이트.
- **`next()`** — 다음 요소를 `Some(값)` 으로, 끝이면 `None` 으로 돌려주는 메서드.
- **연관 타입(`type Item`)** — 트레이트를 구현하는 쪽이 채우는 타입 자리.
- **`IntoIterator`** — 이터레이터로 바뀔 수 있는 것을 나타내는 트레이트로, `for` 루프가 쓴다.
- **어댑터** — 이터레이터를 받아 새 이터레이터를 돌려주는 메서드(`map` · `scan` · `inspect` · `take` · `fuse`).
- **소비자** — 이터레이터를 당겨 결과를 만드는 메서드(`collect` · `find`).
- **지연 평가** — 필요할 때까지 계산을 미루는 방식.
- **`scan`** — 바뀌는 상태를 들고 요소를 변환하는 어댑터.
- **`inspect`** — 요소를 참조로 들여다보며 부수 효과만 내는 어댑터.
- **`by_ref`** — 이터레이터의 가변 참조를 돌려주어 빌려 쓰게 하는 메서드.
- **`fuse`** — 첫 `None` 뒤로 항상 `None` 을 내게 하는 어댑터.
- **`size_hint`** — 남은 개수의 (하한, 상한) 힌트.
- **`checked_add` · `checked_mul`** — 넘치면 `None` 을 돌려주는 정수 연산.
- **`?` 연산자(`Option` 에서)** — `None` 이면 함수가 즉시 `None` 을 돌려주게 하는 표기.
- **슬라이딩 윈도우** — 연속한 n 개를 한 칸씩 밀며 본 묶음.
- **`from_fn`** — 클로저를 `next` 로 삼는 이터레이터를 만드는 함수.
- **`successors`** — 이전 값으로 다음 값을 만드는 이터레이터를 만드는 함수.
- **`repeat` · `once` · `chain`** — 같은 값 끝없이 / 하나만 / 두 이터레이터 이어 붙이기.
- **소유권 이동(move)** — 값을 넘기면 원래 이름으로 쓸 수 없게 되는 규칙.

## 더 들어가면

- `FusedIterator` 라는 표시 트레이트가 있어서, 이미 끝난 뒤 `None` 만 내는 이터레이터는 이것을 구현해 `fuse()` 를 거의 공짜로 만든다고 알려져 있다 (확인 필요).
- 정확한 길이를 아는 이터레이터는 `ExactSizeIterator` 를 구현해 `len()` 을 줄 수 있다 (확인 필요).
- `size_hint` 는 힌트일 뿐이라 틀려도 메모리 안전이 깨지면 안 되고, `unsafe` 코드는 그것을 믿으면 안 된다는 것이 표준 라이브러리 문서의 입장이다 (확인 필요).
- `Windowed` 의 `buffer.remove(0)` 은 뒤 요소를 모두 한 칸씩 옮기므로 창이 클수록 느리다 — `VecDeque` 의 `pop_front` 가 흔한 대안이다 (확인 필요).
- 이미 슬라이스로 가진 데이터라면 표준 슬라이스 메서드 `windows(n)` 이 복사 없이 겹치는 창을 빌려 준다 (확인 필요).
- 「조건이 깨지면 멈추기」만 필요하면 `scan` 보다 `take_while` 이 읽기 쉽고, 다음 요소를 미리 보려면 `peekable()` 을 쓴다 (확인 필요).
- 뒤에서도 꺼낼 수 있는 이터레이터는 `DoubleEndedIterator` 의 `next_back` 을 구현해 `rev()` 를 쓸 수 있다 (확인 필요).
