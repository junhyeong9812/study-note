## 한눈에 — 쉽게 말하면

**newtype 은 「같은 흰 알약을 서로 다른 라벨의 약병에 담는 것」이다.**
알약(값) 자체는 똑같이 생겼어도, 라벨(타입)이 다르면 약사는 「두통약 자리」에 「소화제 병」을 놓지 않는다.
Rust 의 newtype 도 똑같은 구조다.
`f64` 하나를 `Meters` 병에 담느냐 `Kilometers` 병에 담느냐에 따라 컴파일러가 둘을 다른 것으로 본다.

| 비유 | 실체 |
|---|---|
| 알약 | 안에 든 값 (`f64` · `u64` · `String` · `Vec<T>`) |
| 약병과 라벨 | 필드 하나짜리 튜플 구조체 (`struct Meters(f64);`) |
| 약사가 라벨을 보고 자리를 가림 | 컴파일러의 타입 검사 |
| 병에 담기 전에 알약을 검사하는 창구 | 검증하는 생성자 (`Email::new`) |
| 병을 열지 않고 안을 들여다보는 투명 창 | `Deref` 구현 |

```text
   42.195 (f64)                42.195 (f64)
       │                           │
  ┌────▼──────┐              ┌─────▼──────┐
  │ Kilometers│              │   Meters   │
  └───────────┘              └────────────┘
   값은 같은 꼴이어도 타입이 달라 서로의 자리에 들어가지 못한다
```

## 이 주제가 답하려는 질문

1. 같은 원시 타입(`f64`, `u64`)을 여러 뜻으로 쓸 때, 뜻이 섞이는 실수를 어떻게 컴파일 단계에서 막나?
2. 「이 값은 늘 유효하다」는 약속(불변 조건)을 어떻게 한 곳에서 지키나?
3. 감싼 타입에서 안쪽 타입의 메서드를 쓰고 싶을 때 `Deref` 는 무엇을 해 주고, 무엇을 조심해야 하나?
4. 이렇게 감싸면 실행할 때 비용이 드나?

## 동작 방식

### (1) 감싸면 새 타입이 생긴다 — 단위 구분

**언제 쓰나** — 미터 · 킬로미터 · 마일처럼 같은 `f64` 로 나타내지만 뜻이 다른 값을 섞지 않게 하고 싶을 때.

> **newtype** — 기존 타입 하나를 필드 하나짜리 튜플 구조체로 감싸 만든 새 타입.\
> 예: `struct Meters(f64);`

```text
struct Meters(f64);
struct Kilometers(f64);
        │
        ▼  컴파일러는 이름이 다른 두 구조체로 본다
let wrong: Meters = Kilometers(5.0);
        │
        ▼
컴파일 에러 — 타입 불일치 (Meters 자리에 Kilometers)
```

- 줄 1 — 두 구조체는 안에 든 것이 둘 다 `f64` 다.
- 줄 2 — 그래도 Rust 의 타입 검사는 구조체 이름으로 타입을 가른다.
- 줄 3 — 그래서 `Meters` 가 와야 할 자리에 `Kilometers` 를 넣으면 프로그램이 만들어지지 않는다.

안의 값은 `.0` 으로 꺼낸다.
`Meters(5.0).0` 은 `5.0` 이다.

### (2) 변환 메서드와 `Display` — 단위를 타입에 실어 다니기

**언제 쓰나** — 단위 사이를 오갈 때 계산을 한 곳에 묶고, 찍을 때 단위 글자가 자동으로 붙게 하고 싶을 때.

```text
Kilometers(42.195)
   │ .to_meters()  → Meters(self.0 * 1000.0)
   │ .to_miles()   → Miles(self.0 * 0.621371)
   ▼
println!("{}", ...)  → Display 구현이 "{:.1}m" · "{:.2}km" · "{:.2}mi" 꼴로 글자를 만든다
```

- 변환 메서드는 계산한 값을 **목표 단위의 타입**으로 다시 감싸 돌려준다.
- 그래서 결과를 받은 쪽은 숫자가 아니라 「미터」를 받는다.
- `Display` 를 구현하면 `{}` 로 찍을 때 그 구현이 불린다 — 소수 자리 수와 단위 글자를 타입마다 정해 둘 수 있다.

변환 메서드는 `self` 를 값으로 받는다(`fn to_meters(self)`).
값으로 받으면 원래 변수는 원칙적으로 **이동**해 버린다.

> **이동(move)** — 값의 소유권이 다른 곳으로 넘어가 원래 변수를 더는 쓸 수 없게 되는 것.\
> 예: `let a = String::new(); let b = a;` 뒤에는 `a` 를 쓸 수 없다.

단위 타입들은 `#[derive(Clone, Copy)]` 를 달았다.
`Copy` 타입은 이동 대신 **복사**되므로, `distance.to_meters()` 를 부른 뒤에도 다음 줄에서 `distance.to_miles()` 를 또 부를 수 있다.
`Copy` 를 빼면 첫 호출에서 `distance` 가 이동해 둘째 호출이 컴파일 에러가 된다.

> **`Copy`** — 대입 · 인자 전달 때 값을 비트 그대로 복사하는 타입 표시. 안의 필드가 모두 `Copy` 여야 달 수 있다.\
> 예: `f64` · `u64` 는 `Copy` 이고 `String` 은 아니다.

### (3) ID 구분 — 함수 시그니처가 뜻을 말한다

**언제 쓰나** — 사용자 ID · 주문 ID 처럼 똑같이 `u64` 인 식별자를 함수 인자로 주고받을 때.

```text
fn find_orders_by_user(user_id: UserId) -> Vec<Order>
                       ──────────────
find_orders_by_user(UserId(42))   → 통과, 주문 두 개(OrderId(1001), OrderId(1002))가 담긴 Vec
find_orders_by_user(OrderId(1))   → 컴파일 에러 (타입 불일치)
```

- 그냥 `u64` 를 받는 함수였다면 주문 번호를 잘못 넘겨도 컴파일러는 모른다.
- 인자 타입이 `UserId` 이면 시그니처만 읽어도 무엇을 넘겨야 하는지 드러난다.
- `Order` 구조체도 `id: OrderId, user_id: UserId` 로 두어, 두 필드를 바꿔 넣는 실수가 막힌다.

`{:?}` 로 찍으면 `derive(Debug)` 가 만든 꼴이 나온다 — 튜플 구조체는 `OrderId(1001)` 처럼 **타입 이름과 괄호가 붙는다**.
`{:.0}` 은 소수 자리 없이 찍으라는 뜻이라 `29900.0` 이 `29900` 꼴이 된다.

ID 타입에는 `Eq, Hash` 까지 파생했다.
정수를 감쌌으므로 「완전히 같다」를 정의할 수 있고, `HashMap` 의 키로 쓸 수 있게 된다.
반면 `f64` 는 `NaN` 이 자기 자신과 같지 않아 `Eq` 가 없으므로, 단위 타입은 `PartialEq` 까지만 파생했다.

### (4) 생성자에서 검사 — 불변 조건 지키기

**언제 쓰나** — 「이 문자열은 이메일 꼴이다」「비어 있지 않다」처럼 값이 늘 만족해야 할 조건이 있을 때.

> **불변 조건(invariant)** — 그 타입의 값이라면 언제나 참이어야 하는 성질.\
> 예: `NonEmptyString` 이면 안의 문자열이 공백만으로 되어 있지 않다.

```text
Email::new("user@example.com")
   │ '@' 있음 && '.' 있음?  ── 예 ──▶ Ok(Email("user@example.com"))
   │
Email::new("invalid")
   │ '@' 없음              ── 아니오 ─▶ Err("유효하지 않은 이메일: invalid")

NonEmptyString::new("")
   │ trim() 뒤 비었음?      ── 예 ──▶ Err("빈 문자열은 허용되지 않습니다")
```

- 줄 1 — `new` 는 `Result<Self, String>` 을 돌려준다 — 실패할 수 있다는 것이 타입에 드러난다.
- 줄 2 — 조건을 통과해야만 `Email(...)` 이 만들어진다.
- 줄 3 — 통과하지 못하면 왜 안 되는지 담은 `Err` 가 온다.
- 줄 4 — `NonEmptyString` 은 앞뒤 공백을 잘라(`trim`) 본 뒤 비었으면 거절한다. 그래서 `"   "` 도 거절된다.

이렇게 하면 `Email` 을 받는 함수는 다시 검사할 필요가 없다 — 「`Email` 타입이면 이미 검사를 통과했다」고 믿을 수 있기 때문이다.
안의 값은 `as_str()` 처럼 **읽기 전용** 접근 메서드로만 내준다.
가변 접근을 열어 두면 만든 뒤에 내용을 바꿔 조건을 깨뜨릴 수 있다.

단, 이 믿음은 「`new` 를 거치지 않고는 만들 수 없을 때」만 성립한다 — 아래 「어디서 틀리나」 3번을 보라.

### (5) `Deref` — 안쪽 타입처럼 쓰기

**언제 쓰나** — 감싼 뒤에도 안쪽 타입의 읽기 메서드(길이, 포함 여부, 인덱싱)를 하나하나 다시 만들지 않고 쓰고 싶을 때.

> **`Deref`** — `*x` 와 자동 역참조 때 `x` 를 무엇의 참조로 바꿀지 정하는 트레이트. `type Target` 과 `fn deref(&self) -> &Target` 을 구현한다.\
> 예: `impl Deref for SortedVec<T> { type Target = [T]; ... }`

```text
SortedVec::new(vec![3, 1, 4, 1, 5, 9])
   │ items.sort()
   ▼
SortedVec([1, 1, 3, 4, 5, 9])
   │ .insert(2) → binary_search(&2) 가 Err(2) → 2번 자리에 끼움
   ▼
SortedVec([1, 1, 2, 3, 4, 5, 9])
   │ sorted.len()      → SortedVec 에 len 없음 → deref 로 [T] 에서 찾음
   │ sorted[0]         → 인덱스 식도 자동 역참조 → 슬라이스 인덱싱
   │ sorted.contains(&7)
   ▼
&*sorted  →  *sorted 는 [T], & 를 붙여 &[T] (슬라이스로 찍힘)
```

- 줄 1 — `new` 가 받자마자 정렬한다. 정렬 상태가 이 타입의 불변 조건이다.
- 줄 2 — `insert` 는 `binary_search` 로 자리를 찾는다. 값이 있으면 `Ok(위치)`, 없으면 「넣으면 정렬이 유지되는 위치」를 담은 `Err(위치)` 가 온다. `unwrap_or_else(|p| p)` 는 둘 중 어느 경우든 위치 숫자 하나를 꺼낸다.
- 줄 3 — 메서드를 부르면 컴파일러는 먼저 `SortedVec` 자신의 메서드를 찾고, 없으면 `Deref` 의 `Target` 쪽에서 찾는다.
- 줄 4 — `{:?}` 로 `&*sorted` 를 찍으면 슬라이스로 찍히고, `sorted` 를 그대로 찍으면 `derive(Debug)` 의 꼴(`SortedVec([...])`)이 된다.

이 예는 `Deref` 만 구현하고 `DerefMut` 는 구현하지 않았다.
`deref` 가 돌려주는 것은 `&[T]` — 공유(읽기) 참조 — 이므로, 슬라이스의 `sort` 나 원소 바꾸기 같은 **가변 메서드는 이 길로 열리지 않는다**.
`push` 는 애초에 `Vec` 의 메서드라 `[T]` 로 풀리는 이 길로는 닿지 않는다.
그래서 바깥에서는 `SortedVec` 이 직접 준 `insert` 로만 원소를 넣을 수 있고, 정렬 상태가 깨지지 않는다.

### (6) 비용은 컴파일 때 치른다

**언제 쓰나** — 「타입을 하나 더 만들면 느려지지 않을까」가 걱정될 때.

```text
소스: Meters(5.0) + 타입 검사         ── 컴파일 때 ──▶  타입이 맞는지 확인 끝
기계어: 안에 든 f64 하나만 남음        ── 실행 때 ──▶   추가 검사 · 추가 포장 없음 (원본 팁: zero-cost)
```

- 타입이 맞는지 따지는 일은 컴파일 단계에서 끝난다.
- 원본 팁은 newtype 이 런타임 비용이 없다(zero-cost)고 말한다 — 필드가 하나뿐이라 실행 때 다룰 것은 안의 값뿐이기 때문이다.
- 다만 「메모리 배치가 안쪽 타입과 똑같다」를 언어가 어디까지 약속하는지는 아래 「구현 세부사항 대 언어 보장」에 따로 적었다.
- 검증 생성자의 검사(`contains`, `trim`)는 newtype 자체의 비용이 아니라 내가 넣은 코드의 비용이다 — 만들 때 한 번 치른다.

> **zero-cost** — 추상화를 써도, 그것을 손으로 직접 짠 코드보다 실행 비용이 더 들지 않는다는 뜻.\
> 예: `Meters(f64)` 를 넘기는 것과 `f64` 를 넘기는 것이 실행 때 같은 일을 한다.

## 문법 — 형태와 규칙

```rust
use std::fmt;

#[derive(Debug, Clone, Copy, PartialEq)]
struct Meters(f64);                       // 필드 하나짜리 튜플 구조체

impl Meters {
    fn double(self) -> Meters { Meters(self.0 * 2.0) }  // .0 으로 안의 값
}

impl fmt::Display for Meters {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "{:.1}m", self.0)       // 찍는 꼴을 타입이 정한다
    }
}
```

- 선언은 `struct 이름(안쪽타입);` — 필드에 이름이 없고 `.0` 으로 꺼낸다.
- 만들 때는 `이름(값)` — 튜플 구조체 이름이 곧 생성 함수처럼 쓰인다.
- 안쪽 타입의 트레이트는 **저절로 따라오지 않는다**. 필요한 것은 `#[derive(...)]` 로 붙이거나 `impl` 로 직접 쓴다.
- `Copy` 를 파생하려면 `Clone` 도 함께 파생해야 하고, 안쪽 타입이 `Copy` 여야 한다.
- `Eq, Hash` 는 안쪽 타입이 그것을 가질 때만 파생된다 (`u64` 는 되고 `f64` 는 `Eq` 가 안 된다).
- 검증 newtype 은 `fn new(...) -> Result<Self, E>` 꼴의 생성자를 두고, 안쪽 값은 `as_str(&self) -> &str` 같은 읽기 전용 메서드로 내준다.
- `Deref` 는 `use std::ops::Deref;` 뒤 `impl<T> Deref for 감싼타입<T> { type Target = ...; fn deref(&self) -> &Self::Target { ... } }` 꼴이다.
- 제네릭 newtype 은 경계를 선언에 달 수 있다: `struct SortedVec<T: Ord>(Vec<T>);` — 정렬하려면 `Ord` 가 필요하다.

| 원본에 나오는 꼴 | 뜻 |
|---|---|
| `struct UserId(u64);` | 정수 ID 를 뜻이 다른 타입으로 |
| `self.0 / 1000.0` | 안의 값을 꺼내 계산 |
| `write!(f, "{:.2}km", self.0)` | 소수 둘째 자리까지 + 단위 글자 |
| `Result<Self, String>` | 검증 실패를 오류 문자열로 알림 |
| `type Target = [T];` | 자동 역참조의 목적지는 슬라이스 |
| `&*sorted` | `deref` 를 명시적으로 불러 `&[T]` 를 얻음 |

## 어디서 틀리나

### 1. 「같은 원시 타입을 여러 의미로 쓸 때 반드시」를 놓친다

원본 팁은 같은 원시 타입을 여러 의미로 쓸 때 newtype 을 **반드시** 쓰라고 한다.
`fn transfer(from: u64, to: u64, amount: u64)` 같은 시그니처는 인자 순서를 바꿔 넣어도 컴파일된다.
뜻이 다르면 타입도 달라야 컴파일러가 실수를 잡아 준다.

### 2. 타입 별칭(`type`)을 newtype 으로 착각한다

`type Meters = f64;` 는 **이름만 하나 더** 붙인 것이다.
`Meters` 와 `f64` 는 완전히 같은 타입이라, `Kilometers` 를 같은 식으로 만들어도 둘이 자유롭게 섞인다.
타입을 가르려면 반드시 `struct Meters(f64);` 처럼 새 구조체로 감싸야 한다.

> **타입 별칭** — `type 새이름 = 기존타입;` 으로 기존 타입에 다른 이름을 붙이는 것. 새 타입은 생기지 않는다.\
> 예: `type Km = f64;` 이면 `Km` 자리에 아무 `f64` 나 들어간다.

### 3. 「생성자에서만 만들 수 있다」는 모듈 안에서는 거짓이다

원본 주석은 「생성자에서만 만들 수 있게 → 불변 조건 강제」라고 적었다.
그런데 Rust 의 비공개(private)는 **모듈 단위**다.
예제처럼 모든 코드가 한 파일 · 한 모듈에 있으면 `main` 안에서도 `Email("bad".to_string())` 이 그대로 컴파일된다.
불변 조건을 정말 지키려면 타입을 따로 모듈에 두고, 구조체는 `pub` 으로 열되 필드는 비공개로 남겨야 한다(`pub struct Email(String);`).
그러면 그 모듈 바깥에서는 `Email::new` 말고 만들 길이 없다.

### 4. 검증이 너무 느슨하다

`Email::new` 는 `'@'` 와 `'.'` 이 **어딘가에 있기만** 하면 통과시킨다.
`"@."` 같은 문자열도 통과한다.
원본 주석도 「매우 단순한 검증 (실무는 더 정교)」이라고 적었다.
newtype 이 보장하는 것은 「생성자의 검사를 통과했다」뿐이지, 검사 자체가 옳다는 것이 아니다.

### 5. `NonEmptyString` 은 잘라 낸 값을 저장하지 않는다

검사는 `value.trim().is_empty()` 로 하지만, 저장은 `value.to_string()` — 원래 문자열 그대로다.
`"  Alice "` 를 넣으면 앞뒤 공백이 붙은 채로 들어간다.
「공백만으로 되어 있지 않다」는 보장되지만 「앞뒤 공백이 없다」는 보장되지 않는다.

### 6. `Deref` 를 남용한다

원본 팁: `Deref` 를 구현하면 내부 타입의 메서드를 투명하게 쓸 수 있지만, 남용하면 혼란을 준다.
- 읽는 사람이 `sorted.len()` 을 보고 그 메서드가 어디서 왔는지 바로 알기 어렵다 — `SortedVec` 의 `impl` 에는 없다.
- 감싼 타입이 안쪽 타입의 메서드를 전부 「물려받은」 것처럼 보여, 막고 싶던 조작까지 열어 버릴 위험이 있다. `Target` 을 무엇으로 두느냐(`Vec<T>` 인가 `[T]` 인가), `DerefMut` 까지 구현하느냐에 따라 불변 조건이 지켜지기도 깨지기도 한다.
- 예제는 `Target = [T]` 와 `Deref` 만으로 읽기 메서드만 열었다 — 이것이 불변 조건을 지키는 선이다.

### 7. 이동된 값을 다시 쓴다

`self` 를 값으로 받는 메서드는 `Copy` 가 아닌 newtype 을 소비한다.
`Email` · `NonEmptyString` 처럼 `String` 을 감싼 타입은 `Copy` 를 달 수 없으니, 값으로 받는 메서드를 부른 뒤에는 그 변수를 다시 쓸 수 없다.

### 8. `{:?}` 의 꼴을 숫자만으로 기대한다

`derive(Debug)` 로 찍으면 `OrderId(1001)` 처럼 타입 이름이 붙는다.
숫자만 찍고 싶으면 `order.id.0` 을 찍거나 `Display` 를 따로 구현한다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `Meters` 자리에 `Kilometers` 를 넣으면 컴파일 에러 | 언어(타입 시스템)가 보장한다 |
| newtype 은 런타임 비용이 없다(zero-cost) | 실행 성능은 컴파일러(rustc)의 최적화가 만든다. 기본 표현에서 「크기 · 배치가 안쪽 타입과 같다」를 언어가 약속하지는 않고, `#[repr(transparent)]` 를 달 때 약속된다 (확인 필요) |
| `new` 를 거쳐야만 만들 수 있다 | 언어의 모듈 가시성 규칙이 보장한다 — 단 필드가 비공개이고 다른 모듈에서 쓸 때만 |
| `sorted.len()` · `sorted[0]` 이 슬라이스 쪽으로 풀린다 | 언어(자동 역참조 규칙)가 보장한다 |
| 같은 값이 여럿일 때 `binary_search` 가 돌려주는 위치 | 표준 라이브러리는 그중 아무 하나라고만 한다 (확인 필요). 어느 것이든 그 자리에 넣으면 정렬은 유지된다 |
| `{:.2}` 의 반올림 | 표준 라이브러리 포매팅이 정한다 — 10진 표기가 아니라 `f64` 에 실제로 저장된 이진 값을 기준으로 반올림한다 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 같은 `f64` 가 미터 · 킬로미터 · 마일을 뜻한다 | 단위마다 newtype + 변환 메서드 | 그냥 `f64` · 타입 별칭 |
| 사용자 ID 와 주문 ID 가 둘 다 `u64` 다 | `UserId(u64)` · `OrderId(u64)` | `u64` 인자 여러 개 |
| 값이 늘 지켜야 할 조건이 있다 | `Result` 를 돌려주는 생성자 + 비공개 필드 | 쓰는 곳마다 다시 검사 |
| 감싼 뒤 안쪽 타입의 읽기 메서드가 많이 필요하다 | `Deref`(Target 을 좁게) | 불변 조건을 깨는 `DerefMut` |
| 그냥 긴 타입 이름을 줄이고 싶다 | 타입 별칭 | newtype (쓸데없는 감싸기) |
| 안쪽 타입의 메서드 몇 개만 열면 된다 | 그 메서드만 직접 위임 | 모든 메서드를 여는 `Deref` |

## 핵심 문장

1. **newtype 은 필드 하나짜리 튜플 구조체다** — 안의 값이 같은 꼴이어도 타입이 달라 컴파일러가 섞임을 막는다.
2. **뜻은 함수 시그니처에 드러난다** — `fn f(user_id: UserId)` 는 무엇을 넘길지를 타입으로 말한다.
3. **검증을 생성자에 두면 불변 조건을 한 곳에서 지킨다** — 단, 필드가 모듈 바깥에 닫혀 있어야 한다.
4. **`Deref` 는 안쪽 메서드를 투명하게 열지만, 여는 만큼 불변 조건이 위험해진다.**
5. **타입 검사는 컴파일 때 끝난다** — 원본 팁은 newtype 의 런타임 비용이 없다고 말한다.

## 용어 풀이

- **newtype** — 기존 타입 하나를 필드 하나짜리 튜플 구조체로 감싼 새 타입.
- **튜플 구조체** — 필드에 이름 없이 순서로만 접근(`.0`, `.1`)하는 구조체.
- **타입 안전성** — 타입이 맞지 않는 값의 사용을 컴파일러가 막아 주는 성질.
- **불변 조건(invariant)** — 그 타입의 값이면 언제나 참이어야 하는 성질.
- **타입 별칭** — `type A = B;` 로 기존 타입에 이름만 더 붙이는 것.
- **`derive`** — `Debug` · `Clone` · `PartialEq` 같은 트레이트 구현을 컴파일러가 자동으로 만들게 하는 속성.
- **`Copy`** — 대입 · 인자 전달 때 이동 대신 비트 복사되는 타입 표시.
- **이동(move)** — 소유권이 넘어가 원래 변수를 더 못 쓰게 되는 것.
- **`Display`** — `{}` 로 찍을 때 쓰는 사람용 꼴을 정하는 트레이트.
- **`Debug`** — `{:?}` 로 찍을 때 쓰는 개발자용 꼴을 정하는 트레이트.
- **`Deref`** — `*x` 와 자동 역참조의 목적지를 정하는 트레이트.
- **`DerefMut`** — `Deref` 의 가변 참조판. 구현하면 `&mut Target` 쪽 메서드도 열린다.
- **자동 역참조** — 메서드 호출 · 인덱싱 때 컴파일러가 `Deref` 를 따라가며 맞는 메서드를 찾는 것.
- **슬라이스(`[T]`)** — 연속된 원소들의 보기. `&[T]` 로 빌려 쓴다.
- **`binary_search`** — 정렬된 슬라이스에서 값을 찾아 `Ok(위치)` 또는 넣을 자리 `Err(위치)` 를 돌려주는 메서드.
- **zero-cost** — 추상화가 손으로 짠 코드보다 실행 비용을 더 들게 하지 않는다는 뜻.
- **모듈 가시성** — 비공개 항목은 그 항목을 정의한 모듈(과 그 하위 모듈) 안에서만 보인다는 규칙.

## 더 들어가면

- **`#[repr(transparent)]`** — 필드 하나짜리 구조체에 달면 메모리 표현이 안쪽 타입과 같다고 약속한다. C 와 주고받는 FFI 에서 newtype 을 쓸 때 필요하다 (확인 필요).
- **고아 규칙 우회** — 남의 크레이트의 트레이트를 남의 크레이트의 타입에 직접 구현할 수는 없다. 그 타입을 newtype 으로 감싸면 내 타입이 되어 구현할 수 있다. 예: `Vec<String>` 에 `Display` 를 붙이려면 `struct Wrapper(Vec<String>);` 로 감싼다 (확인 필요).
- **`From` · `TryFrom`** — 검증 없는 newtype 은 `impl From<f64> for Meters`, 검증 있는 newtype 은 `impl TryFrom<&str> for Email` 로 변환 관례를 맞출 수 있다 (확인 필요).
- **위임 보일러플레이트** — 메서드를 하나하나 위임하는 수고를 줄이는 매크로 크레이트들이 있다. `derive_more` 가 그중 하나로 알려져 있다 (확인 필요).
- **`std` 안의 newtype** — `std::num::Wrapping<T>` 처럼 표준 라이브러리도 감싼 타입으로 동작(넘침 때 감아 돌기)을 바꾸는 예가 있다 (확인 필요).
