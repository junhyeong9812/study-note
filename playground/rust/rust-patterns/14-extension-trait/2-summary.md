## 한눈에 — 쉽게 말하면

**확장 트레이트는 「도서관 책에 붙이는 내 포스트잇 묶음」이다.**
도서관 책(남이 만든 타입)에는 직접 글씨를 쓸 수 없다.
대신 내 포스트잇(내가 만든 트레이트)을 붙이면, 그 책을 펼칠 때 내 메모가 원래 있던 내용처럼 함께 보인다.
다만 포스트잇 묶음은 내 가방에서 꺼내 들어야(`use`) 보인다.
책에 같은 내용이 이미 인쇄되어 있으면 인쇄된 쪽을 먼저 읽는다.
Rust 의 확장 트레이트도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 도서관 책 | 외부 타입 (`str` · `Vec<T>` · `f64` · `i32`) |
| 책에 직접 쓰지 못하게 하는 규칙 | 고아 규칙 |
| 내 포스트잇 묶음 | 내가 정의한 트레이트 (`StringExt` · `VecExt` …) |
| 포스트잇을 붙이기 | `impl StringExt for str { … }` |
| 가방에서 꺼내 들기 | `use` 로 트레이트를 범위에 들이기 |
| 책에 이미 인쇄된 내용 | 그 타입의 고유 메서드 |
| 같은 시리즈의 모든 책에 한 번에 붙이기 | blanket impl (`impl<I: Iterator> IteratorExt for I {}`) |

```text
 외부 타입 str              내 트레이트 StringExt
 (표준 라이브러리 소속)        (내 크레이트 소속)
          \                      /
           impl StringExt for str      ← 트레이트가 내 것이라 허용
                     |
            use 로 트레이트를 범위에 들임
                     |
           "   ".is_blank()            ← 원래 메서드처럼 점(.)으로 부른다
```

> **확장 트레이트** — 남의 타입에 메서드를 덧붙이려고 내가 정의해 그 타입에 구현하는 트레이트.\
> 예: `StringExt` 를 만들어 `str` 에 `is_blank` 를 덧붙인다.

## 이 주제가 답하려는 질문

1. 내가 고칠 수 없는 남의 타입(`str`, `Vec`)에 메서드를 어떻게 덧붙이나?
2. 덧붙인 메서드는 언제 보이고, 원래 메서드와 이름이 겹치면 어느 쪽이 불리나?
3. 타입 하나가 아니라 어떤 트레이트를 구현한 모든 타입에 한꺼번에 덧붙이려면 어떻게 하나?
4. 덧붙인 메서드 자체는 어떤 경계에서 예상과 다르게 동작하나?

## 동작 방식

### (1) 고아 규칙과 그것을 비켜 가는 길

**언제 쓰나** — 표준 라이브러리나 남의 크레이트 타입에 「있었으면 좋겠는」 메서드가 있을 때 쓴다.

```text
 impl 트레이트 for 타입          트레이트 소속   타입 소속     허용?
 ------------------------------------------------------------------
 impl Display for Vec<i32>      외부(std)      외부(std)     ✗ 고아 규칙 위반
 impl Display for MyType        외부(std)      내 것         ✓
 impl StringExt for str         내 것          외부(std)     ✓  ← 확장 트레이트
```

- 고아 규칙은 「트레이트나 타입 중 하나는 현재 크레이트에 정의되어 있어야 한다」는 규칙이다.
- 그래서 외부 트레이트를 외부 타입에 구현하는 첫 줄은 막힌다.
- 트레이트를 내가 새로 만들면 트레이트 쪽이 「내 것」이 되어 규칙을 만족한다.
- 이것이 확장 트레이트가 고아 규칙을 우회하는 방식이다.

> **고아 규칙(orphan rule)** — 트레이트 구현은 트레이트나 타입 가운데 적어도 하나가 현재 크레이트 소속일 때만 허용된다는 규칙.\
> 예: `impl Display for Vec<i32>` 는 둘 다 표준 라이브러리 소속이라 거부된다.

> **크레이트** — Rust 의 컴파일 단위 한 덩어리(라이브러리 하나 또는 실행 파일 하나).\
> 예: 표준 라이브러리 `std` 도, 내가 만든 프로젝트도 각각 크레이트다.

### (2) 점(.)을 찍었을 때 확장 메서드가 찾아지는 길

**언제 쓰나** — 확장 메서드가 「안 보인다」거나 「다른 메서드가 불린다」고 느낄 때 이 길을 따라가 본다.

```text
 "   ".is_blank()
    │
    ├─① 이 타입(과 자동 역참조한 타입)에 고유 메서드 is_blank 가 있나? → 있으면 그것을 부른다
    │
    ├─② 없으면, 지금 범위에 들어온 트레이트 가운데 is_blank 를 가진 것이 있나?
    │      StringExt 가 범위에 있다(같은 모듈에 정의됐거나 use 했다) → StringExt::is_blank
    │
    └─③ 범위에 없으면 → 컴파일 오류 (메서드를 찾지 못함)
```

- 원본 예제는 트레이트와 `main` 이 한 파일 · 한 모듈에 있어서 `use` 없이도 범위에 있다.
- 트레이트를 다른 모듈이나 다른 크레이트에 두면 쓰는 쪽에서 `use 경로::StringExt;` 를 해야 메서드가 보인다.
- 원본 규칙 3번대로, 확장 메서드와 이름이 같은 고유 메서드가 있으면 고유 메서드가 먼저 불린다.
- 그래서 원본은 이름이 겹치지 않도록 `clamp_to` · `is_between` · `truncate_with_ellipsis` 처럼 고유한 이름을 붙였다.
- `impl StringExt for str` 은 `str` 에 구현했지만, `String` 값에서도 부를 수 있다 — 메서드 호출 때 `String` 이 자동 역참조되어 `str` 로 보이기 때문이다.

> **고유 메서드(inherent method)** — 트레이트를 거치지 않고 `impl 타입 { … }` 으로 타입에 직접 붙은 메서드.\
> 예: `str::trim` · `Vec::sort` 는 고유 메서드다.

> **자동 역참조(auto-deref)** — 메서드를 찾을 때 컴파일러가 `*` 를 대신 붙여 가며 안쪽 타입까지 살펴보는 것.\
> 예: `String` 값에 `str` 메서드를 그대로 부를 수 있다.

### (3) 문자열 확장 `StringExt for str`

**언제 쓰나** — 자르기 · 빈칸 검사 · 대소문자 바꾸기처럼 문자열에 자주 하는 일을 메서드 한 번으로 부르고 싶을 때.

```text
 "abcdefghij".truncate_with_ellipsis(6)
   self.len() = 10  >  max_len = 6        → else 쪽
   max_len.saturating_sub(3) = 3          → "..." 세 글자 자리를 남긴다
   chars().take(3) = "abc"
   format!("{}...", "abc")                → "abc..."   (전체 6글자)
```

- `truncate_with_ellipsis` 는 길이가 `max_len` 이하면 그대로 복사하고, 넘으면 앞에서 `max_len - 3` 글자만 남기고 `...` 를 붙인다.
- `saturating_sub(3)` 는 `max_len` 이 3보다 작아도 음수로 넘치지 않고 0에서 멈춘다.
- 길이 비교는 `self.len()`(바이트 수)로 하고, 자르기는 `chars().take(..)`(문자 수)로 한다 — 두 단위가 다르다(「어디서 틀리나 4」).
- `is_blank` 는 `trim()` 으로 앞뒤 공백을 지운 뒤 비었는지 본다 — 빈 문자열도, 공백만 있는 문자열도 `true` 다.
- `to_title_case` 는 `split_whitespace()` 로 단어를 나누고, 단어마다 첫 글자는 대문자로, 나머지는 소문자로 바꾼 뒤 공백 하나로 다시 잇는다.
- 첫 글자를 `to_uppercase()` 로 바꾼 결과를 `String` 으로 모으는 까닭은, 대문자 변환 결과가 한 글자가 아니라 여러 글자일 수 있는 반복자로 나오기 때문이다.
- `repeat_with_separator(n, sep)` 는 자기 자신을 `n` 개 만들어 `sep` 으로 잇는다 — `"ha"` 에 `3, ", "` 를 주면 `"ha, ha, ha"` 꼴이다.

> **`saturating_sub`** — 빼서 0 아래로 내려가면 0(그 타입의 최솟값)에서 멈추는 뺄셈.\
> 예: `2usize.saturating_sub(3)` 는 0 이다.

### (4) Vec 확장 `VecExt<T> for Vec<T>`

**언제 쓰나** — 「정렬한 새 벡터」「중복을 뺀 벡터」처럼 결과를 식 하나로 받고 싶을 때.

```text
 vec![2, 1, 2, 3].unique()
   seen = {}                         결과
   2 → seen.insert(2) = true   통과   [2]
   1 → seen.insert(1) = true   통과   [2, 1]
   2 → seen.insert(2) = false  버림   [2, 1]
   3 → seen.insert(3) = true   통과   [2, 1, 3]
```

- `sorted(mut self)` 와 `unique(self)` 는 `self` 를 값으로 받아 소유권을 가져간다(소비한다) — 원래 벡터를 다시 쓰려면 부르기 전에 `clone()` 해야 한다. 원본 `main` 이 `numbers.clone().sorted()` 로 부르는 까닭이다.
- `sorted` 는 제자리 정렬(`sort`) 뒤 자기 자신을 돌려준다.
- `unique` 는 `HashSet::insert` 가 「처음 넣는 값이면 `true`」를 돌려주는 성질을 `filter` 조건으로 써서, 처음 나온 순서를 지키며 중복을 뺀다.
- `frequencies(&self)` 는 빌려 읽기만 하며, 키가 `&T`(벡터 안 원소를 가리키는 참조)인 `HashMap` 에 개수를 센다 — 그래서 결과 맵은 원래 벡터보다 오래 살 수 없다.
- `entry(item).or_insert(0)` 는 키가 없으면 0을 넣고, 그 칸을 가리키는 참조를 돌려준다. `*… += 1` 로 1을 더한다.
- 트레이트 `VecExt<T>` 의 메서드마다 `where T: Ord` · `where T: Eq + Hash + Clone` 같은 조건이 따로 붙어 있다. 덕분에 `impl<T> VecExt<T> for Vec<T>` 는 모든 `Vec<T>` 에 구현되고, 각 메서드는 그 조건을 만족하는 `T` 에서만 부를 수 있다.
- `HashMap` 을 순회하는 순서는 정해져 있지 않다. 원본 `main` 은 빈도를 `sort_by_key(… Reverse(count))` 로 개수 내림차순 정렬하지만, 개수가 같은 원소끼리의 순서는 순회 순서를 따른다.

> **where 절** — 제네릭 타입이 만족해야 할 조건(트레이트 경계)을 시그니처 뒤에 모아 적는 자리.\
> 예: `fn sorted(self) -> Self where T: Ord;`

> **entry API** — `HashMap` 에서 「키가 있으면 그 칸, 없으면 새 칸」을 한 번에 다루는 방법.\
> 예: `*freq.entry(k).or_insert(0) += 1;`

### (5) Iterator 확장 — 기본 메서드 + blanket impl + 어댑터 구조체

**언제 쓰나** — 모든 반복자에 공통 어댑터를 덧붙이고 싶을 때(타입마다 하나씩 구현하지 않고).

```text
 trait IteratorExt: Iterator + Sized {      ← 슈퍼트레이트: Iterator 이면서 크기가 정해진 타입만
     fn tap_each(self, f) -> TapEach<Self, F> { TapEach { iter: self, f } }  ← 본문까지 있는 기본 메서드
     fn intersperse_with(self, sep) -> IntersperseWith<Self> { … }
 }
 impl<I: Iterator> IteratorExt for I {}     ← blanket impl: 본문이 비어도 기본 메서드를 그대로 물려받음

 vec![1, 2].into_iter().tap_each(A).map(제곱).tap_each(B).collect()

 collect 가 next() 요청 ─▶ TapEach(B) ─▶ Map ─▶ TapEach(A) ─▶ IntoIter
                                                       1 꺼냄
                                          A(&1) 호출, 1 넘김
                              1*1 = 1
              B(&1) 호출, 1 넘김
 collect 가 다시 next() 요청 ─▶ … 2 가 같은 길로 끝까지 흐른다 …
```

- 트레이트 안의 메서드에 본문까지 쓰면 기본 메서드가 된다. 구현하는 쪽에서 다시 쓸 필요가 없다.
- `impl<I: Iterator> IteratorExt for I {}` 는 「`Iterator` 를 구현한 모든 타입 `I`」에 `IteratorExt` 를 구현한다. 본문이 비어도 기본 메서드가 있으니 `tap_each` 를 바로 쓸 수 있다.
- `Sized` 슈퍼트레이트가 붙은 까닭은 `tap_each(self, …)` 가 `self` 를 값으로 받아 구조체 필드에 담기 때문이다. 크기가 정해진 타입이어야 값으로 옮길 수 있다.
- `tap_each` 는 반복자를 `TapEach` 구조체로 감싸 돌려줄 뿐 아무것도 실행하지 않는다. 실제 일은 누군가 `next()` 를 부를 때(여기서는 `collect`) 일어난다.
- `TapEach::next` 는 안쪽에서 하나 꺼내 콜백에 참조로 보여 준 뒤 그 값을 그대로 넘긴다. 값은 바꾸지 않는다.
- 그래서 원소 하나가 파이프라인 끝까지 흐른 다음에야 다음 원소가 출발한다. 첫 `tap_each` 가 전부 돈 다음 두 번째가 도는 것이 아니다.
- `IntersperseWith` 는 `needs_sep`(다음에 구분자를 낼 차례인가)과 `next_item`(미리 꺼내 둔 다음 원소) 두 상태로 `a, 구분자, b, 구분자, c` 를 만든다.

```text
 [a, b, c].intersperse_with(S)
 호출  needs_sep  next_item(호출 전)  하는 일                          돌려줌
  1     false      None              iter 에서 a 꺼내고 b 를 미리 꺼냄    a
  2     true       Some(b)           b 를 도로 보관, 구분자 복제          S
  3     false      Some(b)           b 를 내고 c 를 미리 꺼냄             b
  4     true       Some(c)           c 를 도로 보관                     S
  5     false      Some(c)           c 를 내고 다음을 꺼냄 → None         c
  6     true       None              보관 없음 → iter.next() 다시 호출    None
```

- 원본 `main` 은 `intersperse_with` 를 부르지 않는다. 위 표는 코드를 읽어 따라간 흐름이다.

> **blanket impl** — 구체 타입 하나가 아니라 「어떤 조건을 만족하는 모든 타입」에 한꺼번에 트레이트를 구현하는 것.\
> 예: `impl<I: Iterator> IteratorExt for I {}`

> **기본 메서드(default method)** — 트레이트 정의 안에 본문까지 적어 두어 구현 쪽이 따로 쓰지 않아도 되는 메서드.\
> 예: `IteratorExt::tap_each` 는 본문이 트레이트 안에 있다.

> **어댑터** — 반복자를 감싸 새 반복자를 돌려주는 구조체(또는 그것을 만드는 메서드).\
> 예: `map` 이 돌려주는 `Map`, 여기서 만든 `TapEach`.

### (6) 숫자 확장 — 같은 트레이트를 타입마다 따로 구현

**언제 쓰나** — 여러 숫자 타입에 같은 이름의 편의 메서드를 주고 싶을 때.

```text
 trait NumExt { fn clamp_to(self, min: Self, max: Self) -> Self … }
        │
        ├── impl NumExt for f64 { … }   ← Self = f64
        └── impl NumExt for i32 { … }   ← Self = i32

 (-5_i32).clamp_to(0, 100)    -5 < 0  → 0
 -5_i32.clamp_to(0, 100)      메서드 호출이 단항 마이너스보다 먼저 묶인다
                              → -(5_i32.clamp_to(0, 100)) → -(5) → -5
```

- 트레이트 시그니처의 `Self` 는 구현하는 타입으로 바뀐다. 그래서 `f64` 구현에서는 `min: f64`, `i32` 구현에서는 `min: i32` 가 된다.
- `clamp_to` 는 범위 밖이면 가까운 경계값을, 안이면 자기 자신을 돌려준다.
- `is_between` 은 양 끝을 포함(`>=` · `<=`)해 범위 안인지 본다.
- 리터럴에 `_i32` · `_f64` 접미사를 붙여 어느 구현을 부를지 정한다.
- 음수 리터럴에 메서드를 부를 때는 괄호로 감싸야 한다. 점 호출이 앞의 `-` 보다 먼저 묶이기 때문이다.

## 문법 — 형태와 규칙

```rust
mod ext {
    pub trait ShoutExt {                 // ① 내 트레이트 정의
        fn shout(&self) -> String;
    }
    impl ShoutExt for str {              // ② 외부 타입에 구현
        fn shout(&self) -> String {
            format!("{}!", self.to_uppercase())
        }
    }
}
use ext::ShoutExt;                       // ③ 쓰는 쪽에서 범위에 들이기

fn main() { println!("{}", "hi".shout()); }
```

- 이름은 관례상 `타입이름 + Ext` 로 짓는다(`StringExt` · `VecExt` · `IteratorExt` · `NumExt`).
- 트레이트를 다른 모듈에 두면 `pub trait` 로 공개하고, 쓰는 쪽에서 `use` 한다.
- 구현 꼴은 세 가지다.
  - 구체 타입 하나: `impl StringExt for str { … }`
  - 제네릭 타입 전체: `impl<T> VecExt<T> for Vec<T> { … }`
  - 조건을 만족하는 모든 타입(blanket): `impl<I: Iterator> IteratorExt for I {}`
- 메서드마다 필요한 조건만 `where` 로 붙이면, 구현은 넓게 두고 호출만 좁힐 수 있다.
- 기본 메서드를 트레이트 안에 쓰면 blanket impl 의 본문을 비울 수 있다.
- 어댑터를 만들 때는 「감쌀 구조체 정의 → 그 구조체에 `Iterator` 구현(`type Item`, `fn next`)」 두 단계를 거친다.

## 어디서 틀리나

### 1. `use` 를 빠뜨려 메서드가 「없다」고 나온다
확장 메서드는 트레이트가 범위에 있을 때만 보인다.
트레이트를 다른 모듈 · 크레이트에 정의했다면 쓰는 파일에서 `use` 해야 한다.
`impl` 이 있어도 `use` 가 없으면 컴파일러는 메서드를 찾지 못한다.

### 2. 외부 트레이트를 외부 타입에 직접 구현하려 한다
`impl Display for Vec<i32>` 처럼 둘 다 남의 것이면 고아 규칙에 걸린다.
트레이트를 새로 만들어(확장 트레이트) 트레이트 쪽을 내 것으로 만든다.

### 3. 고유 메서드와 이름이 겹쳐 내 메서드가 불리지 않는다
이름이 같은 고유 메서드가 있으면 그쪽이 우선한다(원본 규칙 3).
오류 없이 다른 메서드가 불릴 수 있으니, 원본처럼 겹치지 않는 이름(`clamp_to`, `truncate_with_ellipsis`)을 고른다.

### 4. `truncate_with_ellipsis` 는 바이트 수와 문자 수를 섞는다
비교는 `self.len()`(UTF-8 바이트 수), 자르기는 `chars().take(..)`(문자 수)다.
한글처럼 한 글자가 여러 바이트인 문자열은 바이트로는 길다고 판정되어 잘리러 들어가지만, 문자로는 하나도 잘리지 않을 수 있다.
그러면 원래 문자열 뒤에 `...` 만 붙어 오히려 길어진다.

### 5. `max_len` 이 3보다 작으면 결과가 `max_len` 보다 길다
`saturating_sub(3)` 덕에 넘침은 없지만 `take(0)` 이 되어 결과는 `"..."` 세 글자다.
「결과는 `max_len` 이하」라는 약속을 이 코드는 지키지 않는다.

### 6. 빈도 결과의 순서를 고정된 것으로 믿는다
`HashMap` 순회 순서는 정해져 있지 않다.
개수로 정렬해도 개수가 같은 원소끼리의 순서는 순회 순서를 따른다.

### 7. 소비 메서드를 부른 뒤 원래 벡터를 다시 쓴다
`sorted` · `unique` 는 `self` 를 가져간다.
부른 뒤 같은 변수를 쓰면 「이동된 값을 사용」하는 오류가 난다 — 다시 쓸 거면 먼저 `clone()` 한다.

### 8. 음수 리터럴에 괄호 없이 메서드를 부른다
`-5_i32.clamp_to(0, 100)` 은 `-(5_i32.clamp_to(0, 100))` 로 묶여 `-5` 가 된다.
`(-5_i32).clamp_to(0, 100)` 처럼 감싸야 `-5` 에 대해 부른다.

### 9. 어댑터가 「지연」된다는 것을 잊는다
`tap_each` 만 붙이고 `collect` · `for` 같은 소비를 하지 않으면 콜백은 한 번도 불리지 않는다.
불리는 차례도 「원소 하나가 끝까지 흐른 뒤 다음 원소」다.

### 10. `IntersperseWith` 는 끝난 뒤에도 안쪽 반복자를 다시 부른다
원소를 다 낸 뒤의 호출에서 `or_else(|| self.iter.next())` 와 `None` 갈래가 안쪽 `next()` 를 한 번 더 부른다.
안쪽 반복자가 「한 번 `None` 이면 계속 `None`」인 반복자가 아니면 끝난 뒤에 원소가 더 나올 수 있다 (원본에 근거 없음 — 추론).
`needs_sep = false` 를 같은 갈래에서 세 번 쓰는 등 정리되지 않은 줄도 있다 — 흐름은 「동작 방식 (5)」의 표를 따른다.

|---|---|
| 트레이트나 타입 중 하나는 현재 크레이트 소속이어야 구현할 수 있다(고아 규칙) | 언어(컴파일러의 구현 일관성 규칙) |
| 트레이트가 범위에 있어야 그 메서드를 점으로 부를 수 있다 | 언어(메서드 해석 규칙) |
| 이름이 같으면 고유 메서드가 트레이트 메서드보다 먼저 불린다 | 언어(메서드 해석 규칙) — 자동 역참조 단계마다 따지는 세부는 (확인 필요) |

| `HashSet::insert` 는 새 값이면 `true` | 표준 라이브러리 문서의 약속 |
| `HashMap` 순회 순서는 정해져 있지 않다 | 표준 라이브러리는 순서를 약속하지 않는다 — 실행마다 달라질 수 있다 |
| 개수가 같은 원소의 순서가 정렬 뒤에도 순회 순서를 따른다 | `sort_by_key` 가 안정 정렬이라는 표준 라이브러리 문서의 약속 + 순회 순서는 무보장 |
| 어댑터는 소비될 때까지 실행되지 않는다 | `TapEach` 를 이렇게 짠 이 코드의 설계(`next` 안에서만 콜백 호출) |
| `truncate_with_ellipsis` 결과가 `max_len` 이하 | 아무도 보장하지 않음 — 이 코드는 어긴다(「어디서 틀리나 4 · 5」) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 남의 타입에 편의 메서드 몇 개를 덧붙이고 싶다 | 확장 트레이트 | 외부 트레이트를 외부 타입에 직접 `impl`(고아 규칙 위반) |
| 모든 반복자 · 모든 어떤 트레이트 구현체에 덧붙이고 싶다 | 기본 메서드 + blanket impl | 타입마다 하나씩 `impl` 복붙 |
| 여러 숫자 타입에 같은 이름의 메서드를 주고 싶다 | 트레이트 하나 + 타입별 `impl` | 타입마다 다른 이름의 자유 함수 |
| 이미 같은 이름의 고유 메서드가 있다 | 다른 이름으로 짓기 | 같은 이름(조용히 고유 메서드가 불린다) |
| 한 군데서 한 번만 쓰는 작은 동작 | 그냥 자유 함수 | 트레이트까지 만들기(`use` 부담만 는다) |
| 한글 등 여러 바이트 문자를 자르는 함수 | 문자 수로 비교 · 자르기를 맞춘 구현 | `len()` 과 `chars()` 를 섞은 원본식 비교 |

## 핵심 문장

1. **확장 트레이트는 「내 트레이트 for 남의 타입」으로 고아 규칙을 비켜 간다** — 트레이트 쪽이 내 것이면 된다.
2. **확장 메서드는 트레이트가 범위에 있을 때만 보인다** — 다른 모듈에 두면 `use` 가 필수다.
3. **이름이 겹치면 고유 메서드가 이긴다** — 그래서 겹치지 않는 이름을 고른다.
4. **기본 메서드 + blanket impl 이면 조건을 만족하는 모든 타입에 한 줄로 덧붙는다** — `impl<I: Iterator> IteratorExt for I {}`.
5. **덧붙인 메서드도 보통 코드다** — 바이트/문자 단위, `HashMap` 순서, 소유권 소비 같은 함정을 그대로 가진다.

## 용어 풀이

- **확장 트레이트** — 남의 타입에 메서드를 덧붙이려고 내가 정의해 구현하는 트레이트.
- **고아 규칙(orphan rule)** — 트레이트나 타입 중 하나는 현재 크레이트 소속이어야 구현을 허용하는 규칙.
- **크레이트** — Rust 의 컴파일 단위 한 덩어리.
- **외부 타입** — 다른 크레이트(표준 라이브러리 포함)에 정의된 타입.
- **고유 메서드** — `impl 타입 { … }` 으로 타입에 직접 붙은 메서드.
- **자동 역참조** — 메서드 호출 때 컴파일러가 `*` 를 대신 붙여 안쪽 타입까지 찾는 것.
- **blanket impl** — 조건을 만족하는 모든 타입에 한꺼번에 하는 트레이트 구현.
- **기본 메서드** — 트레이트 안에 본문까지 적힌 메서드.
- **슈퍼트레이트** — 「이 트레이트를 구현하려면 저 트레이트도 구현해야 한다」고 요구하는 트레이트(`IteratorExt: Iterator + Sized`).
- **`Sized`** — 컴파일 시점에 크기가 정해진 타입을 나타내는 트레이트.
- **어댑터** — 반복자를 감싸 새 반복자를 돌려주는 구조체.
- **지연 실행** — 소비하는 쪽이 `next()` 를 부를 때까지 실제 일을 미루는 것.
- **소비(move) 메서드** — `self` 를 값으로 받아 소유권을 가져가는 메서드.
- **where 절** — 제네릭 조건을 시그니처 뒤에 모아 적는 자리.
- **`saturating_sub`** — 0 아래로 내려가지 않는 뺄셈.
- **entry API** — `HashMap` 에서 있으면 그 칸, 없으면 새 칸을 다루는 방법.
- **안정 정렬** — 키가 같은 원소끼리 원래 순서를 지키는 정렬.

## 더 들어가면

- 고아 규칙은 더 큰 규칙인 「구현 일관성(coherence)」의 일부다 — 한 타입에 같은 트레이트 구현이 둘 생기지 않게 막는 것이 목적이다 (확인 필요).
- 확장 트레이트 대신 새 타입으로 감싸기(newtype, `struct MyVec(Vec<i32>)`)로도 고아 규칙을 비켜 갈 수 있다 — 외부 트레이트(`Display` 등)를 구현하고 싶을 때는 이쪽이 맞다.
- 크레이트 `itertools` 의 `Itertools` 트레이트가 「`Iterator` 에 대한 확장 트레이트 + blanket impl」의 대표적인 예로 알려져 있다 (확인 필요).
- 표준 `Iterator` 에 나중에 같은 이름의 메서드가 추가되면(예: 불안정 기능 `intersperse`), 확장 트레이트 메서드와 충돌해 경고나 모호성 오류가 날 수 있다 — `unstable_name_collisions` 린트가 이를 알린다 (확인 필요).
- `i32` 에는 `Ord` 트레이트의 `clamp` 가 있고 `f64` 에는 고유 메서드 `clamp` 가 있다 — 트레이트 메서드끼리 이름이 겹치면 고유 메서드처럼 한쪽이 이기는 것이 아니라 모호성 오류가 날 수 있다 (확인 필요).
- 외부 크레이트가 내 트레이트를 구현하지 못하게 막고 싶으면 「봉인된 트레이트(sealed trait)」 기법을 쓴다 (확인 필요).
- `main` 이 쓰지 않는 `intersperse_with` 와 `IntersperseWith` 는 컴파일 때 「쓰이지 않는다」는 경고 대상이 될 수 있다 (확인 필요).
