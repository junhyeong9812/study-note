## 한눈에 — 쉽게 말하면

**정규 표현식은 「글자용 거름망 틀」이다.**
틀을 한 번 깎아 두면, 모래(문자열)를 부을 때마다 같은 모양의 알갱이만 걸러 낸다.
걸러진 알갱이를 칸칸이 나눠 담을 수도 있고(캡처 그룹), 걸린 알갱이를 다른 것으로 바꿔 끼울 수도 있다(교체).
틀을 깎는 일은 오래 걸리지만, 깎아 둔 틀로 거르는 일은 빠르다.
Rust 의 `regex` 크레이트도 똑같은 구조다.

> **정규 표현식** — 문자열의 모양을 기호로 적은 패턴이다.\
> 예: `^010-\d{4}-\d{4}$` 는 「010, 하이픈, 숫자 넷, 하이픈, 숫자 넷으로 끝까지」라는 뜻이다.

> **크레이트** — Rust 의 패키지 단위다. `Cargo.toml` 에 적어 가져온다.\
> 예: `regex = "1"` 한 줄로 `regex` 크레이트 1.x 를 쓴다.

| 비유 | 실체 |
|---|---|
| 틀을 깎는다 | `Regex::new(r"패턴")` 으로 컴파일 |
| 틀을 한 번만 깎아 선반에 둔다 | `OnceLock` · `lazy_static!` 으로 한 번만 컴파일 |
| 걸리나 안 걸리나 | `is_match` → `bool` |
| 걸린 알갱이 하나 / 전부 | `find` / `find_iter` |
| 칸칸이 나눠 담기 | `captures` (캡처 그룹) |
| 걸린 것을 바꿔 끼우기 | `replace` / `replace_all` |

```text
  패턴 문자열 ──(Regex::new, 비쌈, 한 번)──▶ [ 컴파일된 Regex ]
                                                 │
        입력 문자열 ──────────────────────────────┤ (싸다, 여러 번)
                                                 ▼
             is_match → bool │ find_iter → 매치들 │ captures → 칸들 │ replace_all → 새 문자열
```

이 항목의 예제는 `regex` 크레이트를 쓰지 않는다.
`split` · `split_once` · `find` · 문자 검사 같은 표준 라이브러리 도구로 정규식이 하는 일을 손으로 흉내 내고, 각 함수 위 주석에 「진짜 regex 라면 이 패턴」을 적어 둔다.
그래서 이 문서는 두 겹이다 — 정규식이 **무엇을 해 주는지**를 손 구현으로 보고, **실제 크레이트에서는 어떻게 부르는지**를 함께 본다.

## 이 주제가 답하려는 질문

1. 문자열이 어떤 모양인지 「맞다/아니다」로 판정하려면 무엇을 검사해야 하나?
2. 문자열에서 필요한 조각(scheme · host · port, 로그의 시각 · 등급 · 메시지)을 어떻게 이름 붙여 뽑아내나?
3. 문자열 속의 모든 매치를 찾고, 찾은 것을 바꿔 끼우려면 어떻게 하나?
4. 실제 `regex` 크레이트는 무엇을 보장하고, 어떻게 써야 비용이 적게 드나?

## 동작 방식

### (1) 판정 — `is_match` 흉내: 이메일 · 전화번호

**언제 쓰나** — 입력값 검증처럼 「이 문자열이 이 모양인가」만 알면 될 때.

```text
"010-1234-5678"
   │ split('-')
   ▼
["010", "1234", "5678"]      ← 조각이 정확히 3개인가?        → 아니면 false
   │
   ├─ parts[0] == "010" ?
   ├─ parts[1] 길이 4, 전부 ASCII 숫자 ?
   └─ parts[2] 길이 4, 전부 ASCII 숫자 ?
   ▼
모두 참 → true   (regex: ^010-\d{4}-\d{4}$)
```

- 먼저 구분 문자로 잘라 조각 수를 본다 — 조각 수가 틀리면 바로 `false` 다.
- 조각마다 고정 문자열 비교 · 길이 · 문자 종류를 `&&` 로 이어 검사한다.
- `&&` 는 앞이 거짓이면 뒤를 보지 않는다 — 그래서 싼 검사(길이)를 앞에 두어도 좋다.
- `is_email` 도 같은 꼴이다 — `@` 로 잘라 정확히 2조각인지, 앞쪽(local)이 비지 않았는지, 뒤쪽(domain)에 `.` 이 있고 `.` 으로 시작하거나 끝나지 않는지, local 이 영숫자 · `.` · `_` · `-` 로만 되어 있는지 본다.
- 그래서 `"invalid"` 는 조각이 1개라 거짓이고, `"@bad.com"` 은 local 이 비어 거짓이다.

### (2) 모양 + 값의 범위 — IPv4

**언제 쓰나** — 모양만으로 모자라고 숫자 범위까지 따져야 할 때.

```text
"192.168.1.1" ─split('.')─▶ ["192","168","1","1"]   조각 4개?
       각 조각:  parse::<u8>() 가 성공?   (0~255 안인가)
              그리고 (길이 1 이거나 '0' 으로 시작하지 않음)  (앞자리 0 금지)
       ▼
   all(...) → 모든 조각이 참이면 true
```

- 원본 주석의 정규식 `^(\d{1,3}\.){3}\d{1,3}$` 은 모양만 본다 — `999.1.1.1` 도 모양은 맞는다.
- 그래서 「+ 범위 검사」가 따로 붙는다 — 여기서는 `u8` 로 파싱이 되는지로 0~255 를 확인한다.
- `"0"` 처럼 한 글자는 허용하고, `"01"` 처럼 0 으로 시작하는 두 글자 이상은 막는다.

> **옥텟** — IPv4 주소를 `.` 으로 나눈 네 조각 각각이다. 한 조각이 8비트(0~255)다.\
> 예: `192.168.1.1` 의 옥텟은 192, 168, 1, 1 이다.

### (3) 캡처 그룹 — URL 쪼개기

**언제 쓰나** — 매치 여부가 아니라 「매치 안의 어느 부분이 무엇인지」를 뽑아야 할 때.

```text
"https://api.example.com:8443/v1/users"
   │ split_once("://")?            ← 없으면 함수 전체가 None
   ▼
scheme="https"   rest="api.example.com:8443/v1/users"
   │ split_once('/') .unwrap_or((rest, ""))   ← 첫 '/' 에서만 자른다
   ▼
host_port="api.example.com:8443"   path="v1/users"
   │ split_once(':') 가 있으면 port = p.parse::<u16>().ok()
   ▼
UrlParts { scheme, host, port: Some(8443), path: "/" + "v1/users" }
```

- `split_once` 는 처음 나온 구분자에서 한 번만 잘라 `Option<(&str, &str)>` 를 준다.
- 뒤에 붙은 `?` 는 `None` 이면 그 자리에서 `parse_url` 이 `None` 을 돌려주게 한다.
- 경로가 없으면 `unwrap_or((rest, ""))` 로 빈 경로를 쓰고, 마지막에 `format!("/{}", path)` 로 앞에 `/` 를 붙인다.
- 포트 문자열이 숫자가 아니거나 `u16` 을 넘으면 `.ok()` 때문에 `None` 이 된다 — 오류로 멈추지 않는다.
- 결과를 담는 `UrlParts` 의 필드 이름이 바로 캡처 그룹의 이름 역할이다 — 원본 주석의 정규식은 `^(\w+)://([^:/]+)(?::(\d+))?(/.*)?$` 이다.

> **캡처 그룹** — 패턴에서 괄호 `( )` 로 묶은 부분이다. 매치되면 그 부분의 글자를 따로 꺼낼 수 있다.\
> 예: `(\w+)://` 의 첫 그룹은 `https` 를 담는다.

> **`?` 연산자** — `Option` · `Result` 값이 실패(`None` · `Err`)면 함수를 바로 끝내고 그 실패를 돌려준다.\
> 예: `url.split_once("://")?` 는 `://` 가 없으면 `None` 을 돌려준다.

### (4) 모든 매치 찾기 — `find_iter` 흉내

**언제 쓰나** — 문장 속에 흩어진 같은 모양의 조각(숫자 · 날짜 등)을 위치와 함께 전부 모을 때.

```text
input ─chars().collect()─▶ Vec<char>   i = 0
 반복:
   chars[i] 가 숫자?  또는  ('-' 이고 다음 글자가 숫자)?
     ├─ 예 → start = i, '-' 면 한 칸 넘김
     │        숫자나 '.' 이 이어지는 동안 i 전진
     │        chars[start..i] 를 문자열로 → (start, 숫자문자열) 저장
     └─ 아니오 → i 한 칸 전진
```

- 한 글자씩 보며 「숫자 밖」과 「숫자 안」 두 상태를 오가는 상태 머신이다.
- 매치가 끝난 자리에서 다시 찾기 시작하므로 매치끼리 겹치지 않는다.
- 위치 `start` 는 `Vec<char>` 의 번호 — 즉 몇 번째 **문자**인지다.
- 원본 주석의 정규식은 `-?\d+(\.\d+)?` 다.

> **상태 머신** — 지금 어느 상태인지와 다음 글자에 따라 할 일과 다음 상태가 정해지는 구조다.\
> 예: 「숫자 밖」에서 숫자를 만나면 「숫자 안」으로 바뀐다.

### (5) 교체 — `replace_all` 흉내

**언제 쓰나** — 민감 정보 마스킹처럼 찾은 부분을 다른 글자로 바꿀 때.

```text
"... 010-1234-5678 ..."
  for pattern in ["1234","5678","9876","5432"]:
      result = result.replace(pattern, "****")   ← 매번 새 String
  ▼
"... 010-****-**** ..."
```

- `str::replace` 는 고정된 글자열을 **전부** 찾아 바꾼 새 `String` 을 돌려준다.
- 패턴 목록을 차례로 적용하므로, 앞의 교체 결과가 다음 교체의 입력이 된다.
- 바꿀 대상을 「글자 그대로」 나열해야 한다는 것이 정규식과의 큰 차이다 — 정규식이면 「숫자 넷」이라는 모양 하나로 모든 번호를 덮는다.

> **마스킹** — 민감한 값의 일부를 `*` 같은 글자로 가려 보이지 않게 하는 일이다.\
> 예: `010-1234-5678` → `010-****-****`.

### (6) 이름 붙은 캡처 — 로그 파서와 필터

**언제 쓰나** — `[시각] [등급] 메시지` 같은 줄 형식에서 필드를 꺼내 구조체로 다룰 때.

```text
"[2026-04-04 15:30:00] [INFO] 서버 시작됨"
  trim, '[' 로 시작?  아니면 None
  첫 ']' 위치 = ts_end        → timestamp = line[1..ts_end]
  rest = ts_end 뒤를 trim_start, '[' 로 시작? 아니면 None
  rest 의 첫 ']' = level_end   → level = rest[1..level_end]
  나머지 trim                  → message
  ▼
Some(LogEntry { timestamp, level, message })
```

- 원본 주석의 정규식은 `^\[(?P<ts>[^\]]+)\] \[(?P<level>\w+)\] (?P<msg>.*)$` 이다 — `ts` · `level` · `msg` 라는 **이름**이 붙은 그룹이다.
- 손 구현에서는 `LogEntry` 의 필드 이름이 그 이름을 대신한다.
- 형식이 맞지 않는 줄은 `None` 이 되어, `main` 은 `파싱 실패:` 를 찍는다.
- ERROR 만 모을 때는 `filter_map(|line| parse_log_line(line))` 로 `Some` 만 남기고 `None` 은 버린 뒤, `filter(|e| e.level == "ERROR")` 로 거른다.

> **이름 붙은 캡처** — 캡처 그룹에 `(?P<이름>...)` 꼴로 이름을 붙인 것이다. 번호 대신 이름으로 꺼낸다.\
> 예: `(?P<level>\w+)` 로 잡은 부분은 `caps["level"]` 로 꺼낸다.

> **`filter_map`** — 이터레이터의 각 원소에 `Option` 을 돌려주는 함수를 적용해 `Some` 안의 값만 남기는 어댑터다.\
> 예: 로그 4줄에서 파싱 실패한 1줄은 빠진다.

### (7) 진짜 `regex` 크레이트에서는

**언제 쓰나** — 패턴이 복잡하거나 많을 때, 손 구현 대신 크레이트를 쓴다.

```text
let re = Regex::new(r"패턴").unwrap();   ← Result 를 돌려준다(패턴이 잘못되면 Err)
re.is_match(text)        → bool
re.find(text)            → Option<Match>        (첫 매치)
re.find_iter(text)       → 모든 매치 이터레이터
re.captures(text)        → 캡처 그룹
re.replace(text, "대체") → 교체 (처음 하나)
re.replace_all(...)      → 전체 교체
```

- `Regex::new` 는 비용이 크다(원본 팁) — 반복문이나 자주 불리는 함수 안에서 매번 부르지 않는다.
- 그래서 `OnceLock`(표준 라이브러리) 이나 `lazy_static!`(외부 크레이트) 으로 **처음 한 번만** 컴파일해 두고 다시 쓴다.
- `regex` 크레이트는 기본으로 유니코드를 지원하고, 역추적 없이 입력 길이에 선형인 시간에 동작한다(원본 팁).
- 원본 설명에 따르면 크레이트는 분할(문자열을 패턴 기준으로 나누기)도 다룬다 — 예제에서는 그 자리를 `str::split` 이 맡았다.

> **역추적(backtracking)** — 매칭이 실패하면 되돌아가 다른 갈래를 다시 시도하는 방식이다. 패턴에 따라 시도가 폭발할 수 있다.\
> 예: 역추적 엔진은 어떤 패턴에서 입력이 조금만 길어져도 시간이 크게 는다.

> **선형 시간** — 입력 길이가 두 배가 되면 걸리는 시간도 대략 두 배인 성질이다.\
> 예: 1KB 를 훑는 데 걸린 시간의 약 1000 배면 1MB 를 훑는다.

## 문법 — 형태와 규칙

직접 쓴 최소 예제다(실제 `regex` 크레이트 사용 꼴).

```rust
use std::sync::OnceLock;
use regex::Regex;

fn phone_re() -> &'static Regex {
    static RE: OnceLock<Regex> = OnceLock::new();
    RE.get_or_init(|| Regex::new(r"^010-\d{4}-\d{4}$").unwrap())
}

fn main() {
    let ok = phone_re().is_match("010-1234-5678");
    let log = Regex::new(r"^\[(?P<ts>[^\]]+)\] \[(?P<level>\w+)\] (?P<msg>.*)$").unwrap();
    if let Some(caps) = log.captures("[2026-04-04 15:30:00] [INFO] 서버 시작됨") {
        println!("{} {} {}", ok, &caps["level"], &caps["msg"]);
    }
}
```

- `Cargo.toml` 에 `regex = "1"` 을 적어야 `use regex::Regex;` 가 된다.
- 패턴은 원시 문자열 `r"..."` 로 쓴다 — `\d` 의 역슬래시를 두 번 쓰지 않아도 된다.
- `Regex::new` 는 `Result` 를 돌려준다 — 패턴이 틀리면 `Err` 이다.
- `static` + `OnceLock::get_or_init` 은 처음 부를 때만 클로저를 실행하고, 그 뒤로는 같은 `Regex` 를 빌려준다.
- `^` · `$` 는 문자열의 시작 · 끝에 묶는다 — 빼면 문자열 「안 어딘가」에 있기만 해도 매치된다.
- `(...)` 는 번호 그룹, `(?P<name>...)` 는 이름 그룹, `(?:...)` 는 캡처하지 않는 묶음이다(원본 URL 주석의 `(?::(\d+))?`).
- `\d` 숫자, `\w` 단어 글자, `[^\]]` 「`]` 가 아닌 글자」, `{4}` 정확히 4번, `+` 1번 이상, `?` 있거나 없거나, `.*` 아무 글자 0개 이상.

> **원시 문자열** — `r"..."` 꼴로, 역슬래시를 이스케이프로 해석하지 않는 문자열 리터럴이다.\
> 예: `r"\d+"` 는 `"\\d+"` 와 같다.

> **`OnceLock`** — 값을 한 번만 초기화해 담아 두는 표준 라이브러리 타입이다. 여러 스레드에서 안전하게 쓸 수 있다.\
> 예: `static RE: OnceLock<Regex>` 로 정규식을 한 번만 컴파일한다.

## 어디서 틀리나

### 1. `Regex::new` 를 반복문 안에서 부른다

원본 팁: `Regex::new()` 는 비용이 크다.
매 줄마다 같은 패턴을 컴파일하면 정작 매칭보다 컴파일에 시간을 쓴다.
`OnceLock` 이나 `lazy_static!` 으로 한 번만 컴파일한다.

### 2. 번호 그룹만 쓰다가 몇 번이 무엇인지 헷갈린다

원본 팁: 캡처 그룹에 이름을 붙이면 `(?P<name>...)` 가독성이 좋아진다.
그룹이 셋만 넘어도 `caps[3]` 이 무엇인지 패턴을 다시 읽어야 안다.
이름을 붙이면 꺼내는 쪽 코드가 `caps["level"]` 처럼 스스로 설명된다 — 예제의 `LogEntry` · `UrlParts` 필드 이름이 같은 효과를 낸다.

### 3. 다른 엔진의 정규식 습관을 그대로 가져온다

원본 팁: `regex` 크레이트는 기본으로 유니코드를 지원하고 역추적 없이 선형 시간에 동작한다.
그래서 입력이 길어도 매칭 시간이 갑자기 폭발하지 않는다.
대신 역추적에 기대는 기능(앞뒤 살피기 등)은 이 크레이트에서 막혀 있을 수 있다(확인 필요).

### 4. 주석의 정규식과 손 구현이 같은 일을 한다고 믿는다

원본의 주장 → 「`is_email` 은 `^[\w.+-]+@[\w.-]+\.\w+$` 를 흉내 낸다」.
왜 의심스러운가 → 정규식의 local 부분은 `+` 를 허용하지만, 손 구현은 영숫자 · `.` · `_` · `-` 만 허용한다.
또 손 구현은 domain 의 글자 종류를 검사하지 않는다.

원본의 주장 → 「`find_numbers` 는 `-?\d+(\.\d+)?` 를 흉내 낸다」.
왜 의심스러운가 → 손 구현은 숫자와 `.` 을 섞어 계속 모으므로 `1.2.3` 이나 `5.` 도 한 덩어리가 된다 — 정규식은 소수점 뒤에 숫자가 있어야 하고 소수점은 하나뿐이다.

원본의 주장 → URL 정규식에서 경로 `(/.*)?` 는 없어도 된다.
왜 의심스러운가 → 손 구현은 경로가 없어도 항상 `/` 를 붙여 `path` 를 `"/"` 로 만든다 — 「경로 없음」과 「경로가 `/`」를 구분하지 못한다.

### 5. 고정 문자열 교체를 패턴 교체로 착각한다

`replace_pattern` 은 목록에 적힌 글자열만 바꾼다.
목록에 없는 새 전화번호가 들어오면 가려지지 않는다.
정규식 `replace_all` 은 「숫자 넷」 같은 모양으로 찾으므로 이런 빈틈이 없다.

### 6. `?` 와 `filter_map` 이 실패를 조용히 삼킨다

`parse_url` 은 `://` 가 없으면 `None` 이고, `main` 은 `if let Some` 이라 아무것도 찍지 않는다.
ERROR 필터의 `filter_map` 도 형식이 틀린 줄을 말없이 버린다.
실패를 알려야 하는 자리라면 `None` 을 따로 세거나 찍어야 한다 — 로그 루프의 `match` 처럼.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 역추적 없이 선형 시간에 동작한다 | `regex` 크레이트의 설계 — Rust 언어가 아니다 |
| 기본으로 유니코드를 지원한다 | `regex` 크레이트의 기본 설정 |
| `Regex::new` 는 비용이 크다 | `regex` 크레이트 구현의 성질(얼마나 큰지는 확인 필요) |
| `(?P<name>...)` 이름 그룹 문법 | `regex` 크레이트의 패턴 문법 |
| `OnceLock` 으로 한 번만 초기화 | Rust 표준 라이브러리 |
| `lazy_static!` | 외부 크레이트 `lazy_static` |
| `split` · `split_once` · `replace` · `parse::<u8>` 의 동작 | Rust 표준 라이브러리 |
| `&&` 가 앞이 거짓이면 뒤를 평가하지 않는다 | Rust 언어 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 구분자가 하나뿐인 단순 쪼개기(`key:value`) | `split_once` · `split` | 정규식 컴파일 |
| 고정 글자열 몇 개 바꾸기 | `str::replace` | 정규식 |
| 「숫자 넷」처럼 모양으로 찾기 · 바꾸기 | `regex` 의 `find_iter` · `replace_all` | 글자열 목록 나열 |
| 필드가 여럿인 줄 형식 해석 | 이름 붙은 캡처 `(?P<name>...)` | 번호 그룹만 |
| 같은 패턴을 여러 번 사용 | `OnceLock` · `lazy_static!` 에 보관 | 반복문 안의 `Regex::new` |
| 숫자 범위(0~255) 검증 | 정규식으로 모양 + `parse` 로 범위 | 정규식 하나로 범위까지 |

## 핵심 문장

1. **정규식이 하는 일은 넷이다** — 판정(`is_match`) · 찾기(`find` · `find_iter`) · 쪼개 담기(`captures`) · 바꾸기(`replace` · `replace_all`).
2. **컴파일은 비싸고 매칭은 싸다** — `Regex::new` 는 `OnceLock` · `lazy_static!` 으로 한 번만 한다.
3. **그룹에는 이름을 붙인다** — `(?P<name>...)` 이 구조체 필드처럼 코드를 읽히게 한다.
4. **`regex` 크레이트는 역추적 없이 선형 시간, 기본 유니코드** — 크레이트의 보장이지 언어의 보장이 아니다.
5. **단순한 일엔 표준 문자열 도구로 충분하다** — 다만 손 구현은 주석의 정규식과 미묘하게 다를 수 있다.

## 용어 풀이

- **정규 표현식** — 문자열의 모양을 기호로 적은 패턴.
- **크레이트** — Rust 의 패키지 단위.
- **컴파일(정규식)** — 패턴 문자열을 매칭에 쓸 수 있는 `Regex` 값으로 만드는 일.
- **캡처 그룹** — 패턴 속 괄호로 묶어 매치된 글자를 따로 꺼낼 수 있는 부분.
- **이름 붙은 캡처** — `(?P<name>...)` 꼴로 이름을 단 캡처 그룹.
- **역추적** — 실패하면 되돌아가 다른 갈래를 다시 시도하는 매칭 방식.
- **선형 시간** — 입력 길이에 비례해 시간이 드는 성질.
- **`OnceLock`** — 값을 한 번만 초기화해 담는 표준 라이브러리 타입.
- **`lazy_static!`** — 정적 값을 처음 쓸 때 초기화하게 해 주는 외부 크레이트의 매크로.
- **원시 문자열** — 역슬래시를 해석하지 않는 `r"..."` 리터럴.
- **옥텟** — IPv4 주소의 8비트 조각 하나.
- **`split_once`** — 처음 나온 구분자에서 한 번만 잘라 `Option<(앞, 뒤)>` 를 주는 메서드.
- **`?` 연산자** — 실패 값이면 함수를 바로 끝내고 그 실패를 돌려주는 연산자.
- **상태 머신** — 현재 상태와 입력에 따라 다음 상태가 정해지는 구조.
- **마스킹** — 민감한 값을 `*` 등으로 가리는 일.
- **`filter_map`** — `Some` 안의 값만 남기는 이터레이터 어댑터.

## 더 들어가면

- 실제 `regex` 의 `Match::start()` 는 **바이트** 위치를 준다 — 예제의 `find_numbers` 가 주는 **문자** 위치와 한글이 섞이면 값이 달라진다(확인 필요).
- 유니코드 모드에서 `\d` 는 ASCII 숫자 말고 다른 문자 체계의 숫자도 받는다 — 예제의 `is_ascii_digit` 와 범위가 다르다. ASCII 만 원하면 `[0-9]` 나 `(?-u:\d)` 를 쓴다(확인 필요).
- `replace_all` 의 대체 문자열에서 `$name` · `${1}` 으로 캡처한 부분을 다시 넣을 수 있다(확인 필요).
- `Regex::split` 메서드로 패턴 기준 분할을 한다(확인 필요).
- 패턴이 여럿이면 `RegexSet` 으로 한 번에 어느 패턴들이 맞는지 볼 수 있다(확인 필요).
- 이름 그룹은 `(?<name>...)` 꼴도 받는다(크레이트 버전에 따라 다름 — 확인 필요).
- 역추적 기능(앞뒤 살피기 · 역참조)이 필요하면 `fancy-regex` 같은 다른 크레이트를 쓰는 선택지가 있다(확인 필요).
