## 한눈에 — 쉽게 말하면

**힙은 「응급실 대기 피라미드」다.**
환자들이 피라미드 모양으로 앉고, 규칙은 하나뿐이다.
윗자리 사람은 바로 아래 두 사람보다 덜 급하면 안 된다.
그래서 꼭대기에는 언제나 가장 급한 사람이 앉는다.
새 환자는 맨 아래 빈자리에 앉고, 윗사람보다 급하면 자리를 바꾸며 올라간다.
꼭대기 환자가 진료실에 들어가면 맨 아래 마지막 사람을 꼭대기에 올리고, 아랫사람보다 덜 급하면 자리를 바꾸며 내려간다.
최소 힙도 똑같은 구조다.
「급하다」를 「값이 작다」로 바꾸면 된다.

| 비유 | 실체 |
|---|---|
| 피라미드 자리 | 완전 이진 트리의 노드(배열의 칸) |
| 꼭대기 자리 | 루트 = `data[0]` |
| 「윗사람이 더 급하다」 규칙 | 힙 속성(부모 ≤ 자식) |
| 새 환자가 올라가기 | `sift_up` |
| 꼭대기에 올린 사람이 내려가기 | `sift_down` |
| 진료실에 들어가기 | `pop` |
| 지금 꼭대기 확인하기 | `peek` |

```text
        [1]            ← 꼭대기 = 가장 작은 값
       /   \
     [3]   [2]
     / \   /
   [5][4][8]

  부모는 자기 두 자식보다 작거나 같다
  형제끼리(3 과 2)는 순서가 정해져 있지 않다
```

> **힙(heap)** — 부모가 자식보다 언제나 작거나 같은(또는 크거나 같은) 완전 이진 트리.\
> 예: 위 그림에서 1 ≤ 3, 1 ≤ 2, 3 ≤ 5, 3 ≤ 4, 2 ≤ 8 이 모두 성립한다.

> **우선순위 큐(priority queue)** — 넣은 순서가 아니라 우선순위가 높은 것부터 꺼내는 큐.\
> 예: 응급실은 먼저 온 사람이 아니라 가장 급한 사람부터 부른다.

## 이 주제가 답하려는 질문

1. 트리 모양의 힙을 포인터 없이 배열(`Vec`) 하나에 어떻게 담나?
2. 값을 넣거나 뺀 뒤 깨진 힙 속성을 어떻게 되살리나(`sift_up` · `sift_down`)?
3. 표준 `BinaryHeap` 은 큰 값과 작은 값 중 어느 쪽이 위에 오며, 반대로 쓰려면 어떻게 하나?
4. 힙으로 「K번째로 큰 수」를 어떻게 전체 정렬 없이 찾나?

## 동작 방식

### (1) 배열로 표현한 완전 이진 트리

**언제 쓰나** — 힙을 직접 구현할 때 저장 방식으로 쓴다.
트리를 위에서 아래로, 왼쪽에서 오른쪽으로 읽은 순서대로 배열에 담는다.

```text
  data = [1, 3, 2, 5, 4, 8]
  index:  0  1  2  3  4  5

  index i 의
    부모       = (i - 1) / 2   (정수 나눗셈)
    왼쪽 자식  = 2i + 1
    오른쪽 자식 = 2i + 2

  예) i = 4 (값 4) → 부모 (4-1)/2 = 1 (값 3)
      i = 1 (값 3) → 자식 3 (값 5), 4 (값 4)
```

- 루트는 언제나 0번 칸이다.
- 자식 칸 번호는 `2i+1`, `2i+2` 로 계산하므로 포인터가 필요 없다.
- 부모 칸 번호는 `(i-1)/2` 로 거꾸로 계산한다.
- 완전 이진 트리라서 빈칸 없이 배열 앞쪽부터 채워진다.
- 자식 번호가 `len` 이상이면 그 자식은 없다.

> **완전 이진 트리** — 마지막 층을 빼고 모든 층이 꽉 차 있고, 마지막 층은 왼쪽부터 채워진 이진 트리.\
> 예: 노드 6개면 1층 1개, 2층 2개, 3층에 왼쪽부터 3개가 놓인다.

### (2) push — 끝에 넣고 위로 올린다(sift_up)

**언제 쓰나** — 값을 하나 넣을 때 쓴다.
끝 칸에 넣으면 트리 모양은 유지되지만, 새 값이 부모보다 작으면 힙 속성이 깨진다.

```text
  push(1)   (넣기 전 data = [3, 5, 8])

  ① 끝에 추가        [3, 5, 8, 1]     1 은 index 3
  ② 부모 index 1(5)와 비교: 1 < 5 → swap
                     [3, 1, 8, 5]     1 은 index 1
  ③ 부모 index 0(3)와 비교: 1 < 3 → swap
                     [1, 3, 8, 5]     1 은 index 0
  ④ idx == 0 → 루프 끝
```

- ① `self.data.push(val)` 로 끝에 넣고 `sift_up(len - 1)` 을 부른다.
- ② 부모보다 작으면 자리를 바꾸고 `idx = parent` 로 한 층 올라간다.
- ③ 같은 비교를 되풀이한다.
- ④ 루트에 닿거나(`idx > 0` 이 거짓) 부모보다 작지 않으면(`else { break; }`) 멈춘다.
- 한 층에 비교 한 번이고 높이가 log n 쯤이라 push 는 O(log n) 이다.

> **sift_up** — 아래 노드를 부모와 비교해 작으면 바꾸며 위로 올려 힙 속성을 되살리는 과정.\
> 예: 끝에 넣은 1 이 5, 3 과 차례로 자리를 바꿔 루트까지 오른다.

### (3) pop — 루트와 끝을 바꾸고 아래로 내린다(sift_down)

**언제 쓰나** — 가장 작은 값(루트)을 꺼낼 때 쓴다.
루트를 그냥 지우면 트리 꼭대기에 구멍이 나므로, 끝 칸과 바꾼 뒤 끝을 떼어 낸다.

```text
  pop()   (data = [1, 3, 2, 5, 4, 8])

  ① swap(0, 끝)       [8, 3, 2, 5, 4, 1]
  ② Vec::pop          [8, 3, 2, 5, 4]   → 돌려줄 값 Some(1)
  ③ sift_down(0): 자식 3, 2 중 더 작은 2(index 2) < 8 → swap
                      [2, 3, 8, 5, 4]
  ④ index 2 의 자식 5, 6 은 len(5) 이상 → 자식 없음 → 끝
```

- ① 루트와 마지막 원소를 바꾼다(`self.data.swap(0, len - 1)`).
- ② `Vec` 의 끝에서 떼어 내는 일은 다른 원소를 움직이지 않는다 — 그래서 최솟값을 끝으로 보낸 뒤 뗀다.
- ③ 새 루트를 **두 자식 중 더 작은 쪽**과 비교해 자식이 더 작으면 바꾸고 내려간다.
- ④ `smallest == idx`(자식이 둘 다 작지 않거나 자식이 없음)면 멈춘다.
- 남은 원소가 없으면 `sift_down` 을 부르지 않는다(`if !self.data.is_empty()`).
- 비어 있는 힙의 `pop` 은 처음부터 `None` 을 돌려준다.
- 내려가는 길이도 높이만큼이라 pop 은 O(log n) 이다.

> **sift_down** — 위 노드를 두 자식 중 작은 쪽과 비교해 자식이 더 작으면 바꾸며 아래로 내려 힙 속성을 되살리는 과정.\
> 예: 루트에 올라온 8 이 자식 중 작은 2 와 자리를 바꾼다.

### (4) peek 과 「pop 반복 = 정렬」

**언제 쓰나** — 꺼내지 않고 최솟값만 볼 때 `peek` 을, 모든 값을 작은 순서로 받을 때 pop 반복을 쓴다.

```text
  push 5, 3, 8, 1, 4, 2  →  data = [1, 3, 2, 5, 4, 8]
  peek  → Some(&1)        (data.first(), O(1))

  pop 반복 → 1, 2, 3, 4, 5, 8   (오름차순)
  data 배열 자체 [1, 3, 2, 5, 4, 8] 은 정렬되어 있지 않다
```

- `peek` 은 `self.data.first()` 라서 `Option<&i32>` 를 돌려준다(빈 힙이면 `None`).
- 힙이 보장하는 것은 「루트가 최소」뿐이다.
- 배열을 앞에서부터 읽어도 정렬 순서가 아니다(3 이 2 보다 앞에 있다).
- pop 할 때마다 그다음 최솟값이 루트로 오므로, 반복해 꺼내면 오름차순이 된다 — 원본 주석은 이것을 「힙 정렬」이라 부른다.

### (5) 표준 `BinaryHeap` 과 `Reverse`

**언제 쓰나** — 직접 구현할 필요 없이 우선순위 큐가 필요할 때 표준 라이브러리 `std::collections::BinaryHeap` 을 쓴다.

```text
  BinaryHeap (최대 힙)
    push 5, 3, 8, 1  → peek = Some(&8)
    pop 반복          → 8, 5, 3, 1   (큰 값부터)

  BinaryHeap<Reverse<i32>> (최소 힙처럼)
    push Reverse(5), Reverse(3), Reverse(8), Reverse(1), Reverse(4)
    pop 반복 → Reverse(1), Reverse(3), Reverse(4), Reverse(5), Reverse(8)
              → 안의 값 1, 3, 4, 5, 8
```

- `BinaryHeap` 은 **최대 힙**이다 — 루트에 가장 큰 값이 온다.
- `std::cmp::Reverse` 는 값을 감싸 비교 순서를 뒤집는 래퍼다.
- 「더 크다」가 「더 작다」로 바뀌므로, 최대 힙이 가장 큰 `Reverse` 를 꺼낼 때 실제로는 가장 작은 값이 나온다.
- 꺼낸 `Reverse(v)` 에서 값을 꺼내려면 패턴 매칭(`while let Some(Reverse(v)) = heap.pop()`)이나 `.0` 필드를 쓴다.
- `pop` 은 `Option` 을 돌려주므로 `while let Some(..)` 로 빌 때까지 꺼내는 꼴이 자연스럽다.

> **`Reverse<T>`** — 감싼 값의 대소 비교를 거꾸로 만드는 표준 래퍼 구조체(`std::cmp::Reverse`).\
> 예: `Reverse(1) > Reverse(3)` 이다.

> **래퍼(wrapper)** — 값 하나를 감싸 동작 일부만 바꾸는 타입.\
> 예: `Reverse(5)` 는 5 를 담고 비교만 뒤집는다.

### (6) Top K — 크기 k 최소 힙으로 K번째로 큰 수 찾기

**언제 쓰나** — 큰 값 K개, 또는 K번째로 큰 값만 필요하고 전체 정렬은 아까울 때 쓴다.

```text
  nums = [3, 1, 5, 2, 4, 8, 7, 6],  k = 3
  최소 힙(Reverse) 크기를 3 이하로 유지

  넣은 값  힙에 남은 것(작은 것이 루트)   크기 > 3 이면 pop
   3       {3}
   1       {1, 3}
   5       {1, 3, 5}
   2       {1, 2, 3, 5} → 1 제거 → {2, 3, 5}
   4       {2, 3, 4, 5} → 2 제거 → {3, 4, 5}
   8       → 3 제거 → {4, 5, 8}
   7       → 4 제거 → {5, 7, 8}
   6       → 5 제거 → {6, 7, 8}

  루트 = 6 = 3번째로 큰 수
```

- 넣을 때마다 크기가 k 를 넘으면 가장 작은 것을 뺀다.
- 그래서 힙에는 언제나 「지금까지 본 값 중 큰 k개」만 남는다.
- 그 k개 중 가장 작은 것(최소 힙의 루트)이 곧 K번째로 큰 수다.
- 루트는 `peek().unwrap().0` 으로 읽는다(`.0` 은 `Reverse` 안의 값).
- 힙 크기가 k 정도라 연산 한 번이 O(log k), 원소 n 개를 지나므로 전체 O(n log k) 다.
- 방향이 핵심이다 — 「큰 것을 남기려면」 가장 작은 것을 바로 버릴 수 있는 **최소** 힙을 쓴다.

## 문법 — 형태와 규칙

```rust
use std::collections::BinaryHeap;
use std::cmp::Reverse;

fn main() {
    let mut max_h = BinaryHeap::new();      // 최대 힙
    max_h.push(2);
    max_h.push(9);
    let top: Option<&i32> = max_h.peek();   // Some(&9)

    let mut min_h: BinaryHeap<Reverse<i32>> = BinaryHeap::new();
    min_h.push(Reverse(2));
    min_h.push(Reverse(9));
    if let Some(Reverse(v)) = min_h.pop() { // v = 2
        let _ = (top, v);
    }
}
```

- `use std::collections::BinaryHeap;` · `use std::cmp::Reverse;` 로 가져온다.
- `BinaryHeap::new()` 는 빈 힙을 만든다 — 원소 타입은 첫 `push` 나 타입 표기(`BinaryHeap<Reverse<i32>>`)로 정해진다.
- `push(v)` 는 넣기, `pop()` 은 꺼내기(`Option<T>`), `peek()` 은 보기(`Option<&T>`), `len()` 은 원소 수다.
- 최소 힙이 필요하면 넣을 때 `Reverse(v)`, 꺼낼 때 `Reverse(v)` 패턴이나 `.0` 을 쓴다.
- 직접 구현은 `struct MinHeap { data: Vec<i32> }` 에 `new` · `push` · `pop` · `peek` · `len` · `sift_up` · `sift_down` 을 둔다.
- 값을 바꾸는 메서드(`push` · `pop` · `sift_*`)는 `&mut self`, 읽기만 하는 `peek` · `len` 은 `&self` 다.
- 인덱스는 `usize` 다 — 부모 `(i-1)/2`, 자식 `2i+1` · `2i+2`.

## 어디서 틀리나

### 1. `BinaryHeap` 을 최소 힙으로 착각한다

표준 `BinaryHeap` 은 **최대 힙**이다.
`push 5, 3, 8, 1` 뒤 `peek` 은 8 이고, pop 순서는 8, 5, 3, 1 이다.
작은 값부터 꺼내려면 `Reverse<T>` 로 감싸야 한다.

### 2. `Reverse` 를 벗기지 않고 쓴다

`BinaryHeap<Reverse<i32>>` 의 `pop` 은 `Option<Reverse<i32>>` 를 돌려준다.
`i32` 가 필요하면 `Some(Reverse(v))` 패턴으로 꺼내거나 `.0` 으로 꺼낸다.
`peek().unwrap().0` 처럼 `.0` 을 빠뜨리면 타입이 맞지 않는다.

### 3. `sift_up` 에서 `idx > 0` 검사를 빼먹는다

부모 번호 `(idx - 1) / 2` 는 `idx` 가 0 이면 `0 - 1` 을 계산하게 된다.
`usize` 는 음수를 담을 수 없어 이 뺄셈은 넘침(overflow)이다.
그래서 루프 조건 `while idx > 0` 이 루트에서 멈추게 하는 안전장치 노릇도 한다.

### 4. `sift_down` 에서 한쪽 자식하고만 비교한다

두 자식 중 **더 작은 쪽**과 바꿔야 한다.
더 큰 자식과 바꾸면 그 자식이 다른 자식보다 커진 채 부모가 되어 힙 속성이 깨진다.
또 `left < len` · `right < len` 검사 없이 인덱싱하면 범위를 벗어나 패닉이 난다.

### 5. 힙 배열이 정렬되어 있다고 생각한다

`[1, 3, 2, 5, 4, 8]` 처럼 루트만 최소다.
정렬된 순서가 필요하면 pop 을 반복해야 한다.

### 6. 루트를 바로 지운다

`Vec` 의 0번을 지우면 뒤 원소가 모두 한 칸씩 당겨져 부모 · 자식 관계가 통째로 뒤바뀐다.
그래서 루트와 마지막을 바꾼 뒤 끝에서 떼고, 새 루트만 `sift_down` 한다.

### 7. Top K 에서 힙 방향을 거꾸로 고른다

K번째로 **큰** 수에는 크기 k 의 **최소** 힙을 쓴다.
최대 힙으로 같은 일을 하면 넘칠 때마다 가장 큰 값이 버려져, 작은 k개만 남는다.

### 8. 시간복잡도를 헷갈린다

원본 팁은 push · pop 을 O(log n) 으로 적는다 — 트리 높이만큼 올라가거나 내려가기 때문이다.
`peek` 은 0번 칸을 읽을 뿐이라 O(1) 이다.
Top K 는 힙 크기를 k 로 묶어 O(n log k) 가 된다.

### 9. 빈 힙에서 `unwrap` 한다

`pop` · `peek` 은 빈 힙에서 `None` 이다.
원본 예제의 `heap.pop().unwrap()` 은 `while heap.len() > 0` 안에서만 부르므로 안전하다.

|---|---|
| `BinaryHeap` 은 최대 힙이고 `pop` 은 가장 큰 값을 꺼낸다 | 표준 라이브러리 API 문서가 정한 동작 |
| `Reverse` 로 감싸면 비교가 뒤집힌다 | 표준 라이브러리 `std::cmp::Reverse` 의 정의 |
| 부모 `(i-1)/2`, 자식 `2i+1` · `2i+2` | 이 문서의 직접 구현(`MinHeap`)의 설계 — 표준 `BinaryHeap` 이 내부에서 같은 배치를 쓰는지는 API 가 약속하지 않는다 (확인 필요) |
| push · pop 은 O(log n) | 원본 팁의 주장. 직접 구현에는 맞는다. 표준 `BinaryHeap` 의 `push` 는 문서에서 기대 비용을 더 낮게 적는다는 말이 있다 (확인 필요) |
| `usize` 에서 `0 - 1` 은 넘침이다 | 언어(타입 범위)가 정한다. 넘침 때 패닉하는지 감싸 도는지는 빌드 설정에 달렸다 (확인 필요) |
| 직접 구현의 `pop` 반복은 오름차순 | `MinHeap` 코드의 동작 — `sift_up` · `sift_down` 이 힙 속성을 지키기 때문 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 가장 큰 값부터 처리 | `BinaryHeap<T>` | 매번 `Vec` 전체 정렬 |
| 가장 작은 값부터 처리 | `BinaryHeap<Reverse<T>>` | 꺼낸 뒤 `Vec` 을 뒤집기 |
| K번째로 큰 수 · 큰 K개 | 크기 k 최소 힙 (O(n log k)) | 크기 n 최대 힙에서 k번 pop, 또는 최대 힙에 크기 제한 |
| 힙의 원리를 익히기 | `Vec` 기반 직접 구현(`sift_up` · `sift_down`) | — |
| 실제 코드의 우선순위 큐 | 표준 `BinaryHeap` | 검증 안 된 직접 구현 |
| 모든 원소를 정렬된 순서로 한 번 훑기만 | 정렬(`sort`) | 굳이 힙 (힙의 장점은 넣고 빼기를 섞을 때다) |

## 핵심 문장

1. **힙은 「부모 ≤ 자식」만 지키는 완전 이진 트리이고, 배열 하나에 `(i-1)/2` · `2i+1` · `2i+2` 로 담는다.**
2. **넣을 때는 끝에 두고 `sift_up`, 뺄 때는 루트와 끝을 바꿔 떼고 `sift_down` — 둘 다 O(log n) 이다.**
3. **루트만 최솟값이 보장되며, 배열 자체는 정렬되어 있지 않다 — pop 을 반복해야 정렬 순서가 나온다.**
4. **표준 `BinaryHeap` 은 최대 힙이고, `Reverse<T>` 로 감싸면 최소 힙처럼 쓴다.**
5. **K번째로 큰 수는 크기 k 의 최소 힙을 유지하면 루트에 남는다 — O(n log k).**

## 용어 풀이

- **힙** — 부모가 자식보다 언제나 작거나 같은(최소 힙) 또는 크거나 같은(최대 힙) 완전 이진 트리.
- **최소 힙** — 루트가 가장 작은 값인 힙.
- **최대 힙** — 루트가 가장 큰 값인 힙. `BinaryHeap` 이 이것이다.
- **우선순위 큐** — 우선순위가 높은 것부터 꺼내는 큐. 힙으로 흔히 구현한다.
- **완전 이진 트리** — 마지막 층만 빼고 꽉 차 있고 마지막 층은 왼쪽부터 채운 이진 트리.
- **힙 속성** — 모든 부모가 자식과의 대소 규칙을 지키는 상태.
- **루트** — 트리 맨 위 노드. 배열 0번 칸.
- **`sift_up`** — 노드를 부모와 비교해 바꾸며 위로 올리는 과정.
- **`sift_down`** — 노드를 더 작은 자식과 비교해 바꾸며 아래로 내리는 과정.
- **heapify** — 깨진 힙 속성을 되살리는 일. 원본 키워드의 하나로, 이 문서에서는 `sift_up` · `sift_down` 이 그 일을 한다.
- **`peek`** — 꺼내지 않고 루트를 보는 연산.
- **`BinaryHeap`** — 표준 라이브러리의 최대 힙 우선순위 큐(`std::collections::BinaryHeap`).
- **`Reverse<T>`** — 비교 순서를 뒤집는 래퍼(`std::cmp::Reverse`).
- **래퍼** — 값을 감싸 동작 일부만 바꾸는 타입.
- **Top K** — 큰(또는 작은) 값 K개, 또는 K번째 값을 찾는 문제.
- **힙 정렬** — 힙에서 pop 을 반복해 정렬된 순서를 얻는 방식.
- **`while let`** — 패턴이 맞는 동안 반복하는 Rust 반복문. `Some(v)` 가 나오는 동안 돈다.

## 더 들어가면

- 표준 `BinaryHeap` 에는 `into_sorted_vec` · `into_vec` · `from(Vec)` 같은 메서드가 있다 (확인 필요).
- `Vec` 에서 한꺼번에 힙을 만드는 bottom-up heapify 는 O(n) 이라고 알려져 있다 — 원소를 하나씩 push 하는 O(n log n) 보다 빠르다 (확인 필요).
- `BinaryHeap::iter()` 는 정해지지 않은 순서로 돈다고 문서가 적는다 (확인 필요).
- 같은 값(동률)이 여럿일 때 어느 것이 먼저 나오는지 `BinaryHeap` 은 보장하지 않는 것으로 안다 — 안정 정렬이 아니다 (확인 필요).
- 직접 정의한 구조체를 `BinaryHeap` 에 넣으려면 `Ord` 를 구현해야 한다. `f64` 는 `Ord` 가 아니라 그대로 넣을 수 없다 (확인 필요).
- 다익스트라 최단 경로는 `BinaryHeap<Reverse<(거리, 노드)>>` 꼴을 흔히 쓴다 (확인 필요).
