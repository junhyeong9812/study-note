## 한눈에 — 쉽게 말하면

**`scipy.optimize` 는 「눈 감고 골짜기 바닥을 찾는 등산객」이다.**
등산객은 지도가 없다.
발밑의 높이만 재 보면서, 내려가는 쪽으로 한 걸음씩 옮긴다.
더 내려갈 곳이 없으면 「여기가 바닥」이라고 멈춘다.
출발 지점이 어디냐에 따라 다른 골짜기에 닿을 수도 있다.
`minimize` 도 똑같은 구조다.
함수값(높이)만 재면서 더 작은 값 쪽으로 x 를 옮기고, 더 줄일 수 없으면 멈춘다.

| 비유 | 실체 |
|---|---|
| 땅의 높이 | 목적함수 `f(x)` 의 값 |
| 출발 지점 | 초기값 `x0` (`curve_fit` 에서는 `p0`) |
| 걷는 요령(지팡이로 더듬기 · 경사 재기) | `method` (`Nelder-Mead` · `BFGS` …) |
| 울타리 | `bounds` (경계 조건) |
| 「이 길로만 가라」는 규칙 | `constraints` (제약 조건) |
| 도착 보고서 | 결과 객체 (`result.x` · `result.fun` · `result.success`) |

```text
 높이 f(x)
   │ ●출발(x0)
   │   ╲
   │    ╲   한 걸음씩 내려간다
   │     ╲
   │      ╲__●__╱   ← 바닥: result.x, 그때 높이: result.fun
   └────────────────── x
```

## 이 주제가 답하려는 질문

1. 함수가 가장 작아지는 x 를 어떻게 찾나 — 그리고 문제 꼴(기울기 · 경계 · 제약)에 따라 어떤 방법을 고르나?
2. 잡음 섞인 데이터에 모델 함수를 맞춰 파라미터를 어떻게 얻나 — 그 파라미터를 얼마나 믿을 수 있나?
3. `f(x) = 0` 이 되는 x(근)를 어떻게 찾나 — 초기값 방식과 구간 방식은 무엇이 다른가?

## 동작 방식

### (1) `minimize` — 함수의 최솟값 찾기

**언제 쓰나** — 「이 값을 가장 작게 만드는 입력」을 찾을 때 쓴다.
비용 · 오차 · 에너지처럼 줄이고 싶은 양을 함수로 적을 수 있으면 된다.

```text
def f(x): return (x - 3)**2 + 5
minimize(f, x0=0)
      │
      ▼
 x=0 에서 f 를 잰다 → 줄어드는 쪽으로 x 를 옮긴다 → 반복
      │
      ▼
 더 줄지 않으면 멈춤 → 결과 객체
   result.x    ≈ [3.0]   (배열이다)
   result.fun  ≈ 5.0
   result.success → 수렴했는가
   result.nit  → 반복 횟수
```

- 목적함수 `f` 는 x 하나를 받아 숫자 하나를 돌려준다.
- `minimize` 는 출발점 `x0` 에서 시작해 `f` 값이 줄어드는 쪽으로 x 를 고쳐 나간다.
- 결과의 `x` 는 숫자 하나가 아니라 **배열**이라서, 1차원 문제여도 `result.x[0]` 으로 꺼낸다.
- `fun` 은 그 위치의 함수값, `success` 는 수렴 여부, `nit` 은 반복 횟수다.

> **목적함수** — 최적화에서 가장 작게(또는 크게) 만들려는 함수.\
> 예: `(x - 3)**2 + 5` 는 x=3 에서 가장 작다.

변수가 여럿이어도 꼴은 같다.
x 가 배열이 되고, `x[0]` · `x[1]` 로 각 변수를 꺼내 쓴다.
원본은 최적화 벤치마크로 쓰이는 Rosenbrock 함수 `(1 - x[0])**2 + 100*(x[1] - x[0]**2)**2` 를 `x0=[0, 0]` · `method='BFGS'` 로 풀고, 최솟값 위치가 (1, 1), 최솟값이 0 근처라고 적어 둔다.

> **벤치마크 함수** — 최적화 방법이 잘 찾는지 겨루려고 일부러 까다롭게 만든 시험용 함수.\
> 예: Rosenbrock 함수는 바닥이 길고 휜 골짜기 모양이라 바닥 (1, 1) 까지 가기 어렵다.

### (2) `method` — 걷는 요령 고르기

**언제 쓰나** — 같은 문제라도 기울기를 쓸 수 있는지, 울타리 · 규칙이 있는지에 따라 알맞은 알고리즘이 다르다.

```text
목적함수 objective(x) = x0² + x1² + x0·x1,  x0 = [5, 5]
      │
      ├─ 'Nelder-Mead' : 함수값만 비교하며 더듬는다 (기울기 불필요, 로버스트)
      ├─ 'BFGS'        : 기울기를 써서 내려간다 (빠름)
      ├─ 'L-BFGS-B'    : 기울기 + 변수마다 울타리(bounds)
      └─ 'SLSQP'       : 등식 · 부등식 제약(constraints)
      │
      ▼
 각자 res.x, res.fun 을 돌려준다
```

- 원본의 팁은 이렇게 고르라고 한다 — 기울기를 모르면 `Nelder-Mead`, 경계 조건이 있으면 `L-BFGS-B`, 등식 · 부등식 제약이면 `SLSQP`.
- 주요 method 로 `Nelder-Mead` · `BFGS` · `L-BFGS-B` · `SLSQP` · `Powell` 이 꼽힌다(`Powell` 은 이름만 나오고 예제는 없다).
- `objective` 는 모든 점에서 0 이상이고 (0, 0) 에서 0 이다.
  그래서 제약 없는 세 방법은 모두 (0, 0) 근처, 함수값 0 근처에 닿아야 한다(손 계산으로 확인한 사실이다).

> **기울기(gradient)** — 각 변수를 조금 늘렸을 때 함수값이 얼마나 바뀌는지 모은 것. 내려갈 방향을 알려 준다.\
> 예: `x**2` 의 기울기는 `2*x` 라서 x=5 에서는 왼쪽으로 가야 줄어든다.

### (3) 경계와 제약 — 울타리와 규칙

**언제 쓰나** — 「x 는 0 이상」 같은 범위나 「x + y = 10」 같은 관계를 지키면서 최솟값을 찾을 때 쓴다.

```text
bounds=[(0, None), (0, None)]            → x ≥ 0, y ≥ 0   (None = 한쪽 끝 없음)

constraints=[
  {'type': 'eq',   'fun': lambda x: x[0] + x[1] - 10},   → fun(x) == 0  즉 x + y = 10
  {'type': 'ineq', 'fun': lambda x: x[0] - 2},           → fun(x) >= 0  즉 x ≥ 2
]
      │
      ▼
 규칙을 지키는 점들 가운데서만 가장 작은 값을 찾는다
```

- `bounds` 는 변수마다 `(아래, 위)` 짝 하나다. `None` 은 그쪽으로 끝이 없다는 뜻이다.
- `constraints` 는 딕셔너리의 리스트다. `'type'` 은 `'eq'`(등식) 또는 `'ineq'`(부등식), `'fun'` 은 x 를 받아 숫자를 돌려주는 함수다.
- `'eq'` 는 `fun(x) == 0` 을, `'ineq'` 는 `fun(x) >= 0` 을 요구한다. 그래서 「x ≥ 2」 는 `x[0] - 2` 로 적는다(원본 주석 `# x >= 2` 와 맞물린다).
- 울타리 안에 원래 바닥이 있으면 울타리는 답을 바꾸지 않는다. `objective` 의 바닥 (0, 0) 은 `x ≥ 0, y ≥ 0` 안(경계 위)에 있으므로 `L-BFGS-B` 의 답도 (0, 0) 근처다.
- 제약 `x + y = 10` 아래에서는 `objective = (x + y)² − xy = 100 − xy` 가 되어, xy 가 가장 클 때(x = y = 5) 가장 작다. 값은 100 − 25 = 75 이고, x = 5 는 x ≥ 2 도 지킨다.

> **제약 조건** — 해가 반드시 만족해야 하는 식.\
> 예: 예산이 10 이면 `x + y = 10` 을 지키는 x, y 만 후보가 된다.

### (4) `curve_fit` — 데이터에 모델 맞추기

**언제 쓰나** — 측정값 `(xdata, ydata)` 가 있고, 그것을 설명할 모델의 꼴(직선 · 지수 · 가우시안)은 아는데 계수를 모를 때 쓴다.

```text
def linear(x, a, b): return a*x + b      ← 첫 인자는 x, 나머지는 찾을 파라미터
xdata, ydata (y = 2.5x + 1.3 + 잡음)
      │
      ▼
curve_fit(linear, xdata, ydata [, p0=초기 추정])
      │  모델과 데이터의 차이(잔차)의 제곱합이 가장 작아지는 a, b 를 찾는다
      ▼
(popt, pcov)
  popt → [a, b] 최적 파라미터
  pcov → 공분산 행렬. np.sqrt(대각) = 각 파라미터의 표준 오차
```

- 모델 함수의 첫 인자는 독립변수 x, 그 뒤가 찾을 파라미터다. `curve_fit` 은 파라미터 개수를 이 꼴에서 안다.
- 돌려주는 값은 튜플 두 개짜리 `(popt, pcov)` 다.
- `popt` 는 최적 파라미터, `pcov` 는 공분산 행렬로 불확실도 평가에 쓴다. 대각 원소의 제곱근 `np.sqrt(pcov[0,0])` 이 `a` 의 표준 오차다.
- 원본은 이 작업을 「비선형 최소제곱 피팅」이라 부른다. 잔차 제곱합이라는 목적함수를 최소화하는 일이므로, 속은 (1) 의 최소화와 같은 일이다.
- 원본은 `np.random.seed(42)` 로 잡음을 고정하고, 직선 `2.5x + 1.3` 에 잡음을 얹은 50점에 `linear` 를 맞춘다. 피팅된 a, b 는 2.5, 1.3 에 가깝게 나와야 하지만 잡음 때문에 정확히 같지는 않다.
- 가우시안 피팅에는 `p0=[3, 1, 1]` 을 준다. 데이터를 만든 참값(amp 3, mu 1, sigma 1)과 같은 초기 추정이다.
- 원본에는 `exponential(x, a, b, c)` 모델도 정의되어 있지만 쓰이지 않는다.

> **잔차(residual)** — 데이터값에서 모델값을 뺀 차이.\
> 예: 데이터 y=6, 모델 예측 5.5 면 잔차는 0.5 다.

> **공분산 행렬** — 파라미터마다의 흔들림(분산)과 서로 같이 흔들리는 정도를 모은 표.\
> 예: `pcov[0,0]` 은 a 의 분산이라 제곱근을 씌우면 a 의 표준 오차가 된다.

### (5) 근 찾기 — `fsolve` · `brentq` · `root_scalar`

**언제 쓰나** — `f(x) = 0` 을 만족하는 x 를 손으로 풀 수 없을 때 쓴다.

```text
f(x) = x³ − 6x² + 11x − 6   (근: 1, 2, 3)

초기값 방식                    구간 방식
fsolve(f, x0=0.5)              brentq(f, 0.5, 1.5)
  출발점에서 기울기를 따라        f(0.5) < 0, f(1.5) > 0  ← 부호가 바뀐다
  0 쪽으로 건너간다               그 사이를 좁혀 들어간다
  → 가까운 근(대개)               → 구간 안의 근 1.0
  → 배열을 돌려줌: root[0]        → 숫자 하나를 돌려줌

root_scalar(f, bracket=[0.5, 1.5], method='brentq')
  → 결과 객체: result.root, result.iterations
```

- `fsolve` 는 출발점 `x0` 에서 시작한다. 돌려주는 값은 배열이라 `root1[0]` 으로 꺼낸다.
- 출발점이 다르면 다른 근에 닿는다. 원본은 0.5 · 1.5 · 3.5 에서 출발해 근 셋을 각각 노린다.
- `brentq` 는 구간 `[a, b]` 를 받는다. 양 끝의 함숫값 **부호가 달라야** 한다 — 그래야 「그 사이 어딘가에서 0 을 지난다」가 보장된다.
- `root_scalar` 는 여러 근 찾기 방법을 한 인터페이스로 묶은 것이다. `bracket` 과 `method` 를 주고, 결과 객체에서 `root` 와 `iterations` 를 읽는다.
- `fsolve` 는 연립방정식도 푼다. 함수가 변수 배열을 받아 식마다의 「좌변 − 우변」을 리스트로 돌려주면 된다(`x² + y² = 25`, `xy = 12` 를 `[x**2 + y**2 - 25, x*y - 12]` 로).

> **근(root)** — 함수값을 0 으로 만드는 입력.\
> 예: `x**2 - 4` 의 근은 2 와 −2 다.

> **브래킷(bracket)** — 양 끝 함숫값의 부호가 다른 구간. 그 안에 근이 적어도 하나 있다.\
> 예: f(0.5) = −1.875, f(1.5) = 0.375 이므로 [0.5, 1.5] 는 브래킷이다.

## 문법 — 형태와 규칙

```python
from scipy.optimize import minimize, curve_fit, fsolve, brentq
import numpy as np

res = minimize(lambda x: (x[0] - 1)**2 + (x[1] + 2)**2, x0=[0, 0],
               method='L-BFGS-B', bounds=[(0, None), (None, None)])
print(res.x, res.fun, res.success)

popt, pcov = curve_fit(lambda x, a, b: a * x + b,
                       np.array([0, 1, 2]), np.array([1, 3, 5]))
print(popt, np.sqrt(np.diag(pcov)))

print(fsolve(lambda x: x**2 - 4, x0=1)[0])
print(brentq(lambda x: x**2 - 4, 0, 5))
```

- 원본이 정리한 시그니처는 넷이다.
  - `minimize(fun, x0, method, bounds, constraints)`
  - `curve_fit(f, xdata, ydata, p0) -> (popt, pcov)`
  - `fsolve(func, x0)` / `brentq(f, a, b)` / `root_scalar(f, bracket)`
  - 방법: `Nelder-Mead`, `BFGS`, `L-BFGS-B`, `SLSQP`, `Powell`
- `minimize` 의 목적함수는 배열 x 를 받아 **숫자 하나**를 돌려준다.
- `curve_fit` 의 모델 함수는 `(x, 파라미터1, 파라미터2, …)` 꼴이다.
- `fsolve` 의 함수는 연립이면 식 개수만큼의 값을 돌려준다.
- 결과를 꺼내는 자리가 함수마다 다르다.

| 함수 | 돌려주는 것 | 꺼내는 법 |
|---|---|---|
| `minimize` | 결과 객체 | `.x`(배열) · `.fun` · `.success` · `.nit` |
| `curve_fit` | 튜플 `(popt, pcov)` | 언패킹 |
| `fsolve` | 배열 | `[0]` |
| `brentq` | 숫자 | 그대로 |
| `root_scalar` | 결과 객체 | `.root` · `.iterations` |

- 준비: `pip install scipy numpy`.

## 어디서 틀리나

### 1. `method` 를 문제 꼴에 맞추지 않는다

원본의 팁 그대로 — 기울기를 모르면 `Nelder-Mead`, 경계 조건이 있으면 `L-BFGS-B`, 등식/부등식 제약이면 `SLSQP`.
제약이 있는데 제약을 다루지 못하는 방법을 고르면 제약을 지키는 답을 기대할 수 없다.

### 2. `curve_fit` 의 `p0` 를 아무렇게나 둔다

원본의 팁 — `p0`(초기 추정값)가 수렴 속도와 결과에 큰 영향을 준다.
가우시안처럼 모양이 봉우리 하나인 모델은 출발점이 봉우리에서 멀면 엉뚱한 곳에서 멈출 수 있다.
그래서 원본은 가우시안에만 `p0=[3, 1, 1]` 을 주고, 직선 모델에는 주지 않는다.

### 3. 출발점이 하나의 답만 낸다는 것을 잊는다

`minimize` 와 `fsolve` 는 출발점 근처를 따라간다.
근이나 바닥이 여럿이면 출발점이 어느 것에 닿을지를 정한다.
특히 출발점에서 기울기가 0 에 가까우면 위험하다.
`f(x) = x³ − 6x² + 11x − 6` 은 x ≈ 1.42 와 2.58 에서 기울기가 0 이다(봉우리와 골).
x0 = 1.5 는 그 봉우리 근처라 기울기가 −0.25 로 아주 작다.
기울기로 「0 까지 얼마나 가야 하나」를 재는 방식이라면, 작은 기울기로 나누는 탓에 한 번에 멀리 튀어 근 2 가 아닌 곳으로 갈 수 있다.
결과가 원본 주석 「근 2」와 같다고 장담하지 않는 편이 맞다.

### 4. `brentq` 에 부호가 안 바뀌는 구간을 준다

원본 주석 — 「부호 변화 필요」.
양 끝 함숫값이 같은 부호면 근이 있다는 보장이 없어 `brentq` 는 일을 시작하지 못하고 오류를 낸다(오류의 종류는 확인 필요).
구간 안에 근이 둘이면(부호가 다시 같아지므로) 그런 구간도 쓸 수 없다.

### 5. 결과를 배열인 줄 모르고 쓴다

`minimize` 의 `.x` 와 `fsolve` 의 반환값은 배열이다.
1차원 문제여도 `result.x[0]` · `root1[0]` 으로 꺼내야 숫자 서식(`:.4f`)에 넣을 수 있다.

### 6. `'ineq'` 의 방향을 거꾸로 쓴다

`'ineq'` 는 `fun(x) >= 0` 을 요구한다.
「x ≤ 2」 를 원하면 `2 - x[0]`, 「x ≥ 2」 를 원하면 `x[0] - 2` 다.

### 7. 원본 예제 파일은 계산하지 않는다

원본 예제는 각 절의 코드를 `print("""…""")` 로 감싸 **글자로 출력**한다.
세 따옴표 문자열 안의 코드는 실행되지 않으므로, 파일을 돌리면 계산된 숫자 대신 코드 본문이 나온다.
값을 보려면 따옴표 안의 코드를 따로 떼어 실행해야 한다.

### 8. 이름 그림자

연립방정식 예제의 `def equations(vars):` 는 내장 함수 `vars` 와 이름이 같다.
그 함수 안에서는 내장 `vars` 를 쓸 수 없게 된다. 동작에는 문제가 없지만 다른 이름이 낫다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 세 따옴표 문자열을 `print` 하면 안의 코드는 실행되지 않고 글자로 나온다 | Python 언어 |
| `minimize` 결과에 `x` · `fun` · `success` · `nit` 가 있다 | SciPy 라이브러리 API |
| `'eq'` 는 `fun == 0`, `'ineq'` 는 `fun >= 0` 을 뜻한다 | SciPy 라이브러리 API |
| 최솟값이 「≈ 3.0」「≈ 5.0」「≈ (1, 1)」로 나온다 | 아무도 정확히 보장하지 않는다 — 수치 알고리즘의 근삿값이며 허용 오차 · 버전에 따라 끝자리가 다를 수 있다 |
| 기울기 기반(`BFGS`)이 빠르다, `Nelder-Mead` 는 로버스트하다 | 일반적 경향(원본 주석) — 문제마다 다르다 |
| `fsolve(f, x0=1.5)` 가 근 2 에 닿는다 | 보장 없음 — 출발점과 알고리즘에 달렸다 |
| `np.random.seed(42)` 로 같은 잡음이 다시 나온다 | NumPy 의 전역 난수 생성기 동작 — 버전 간 동일성은 확인 필요 |

원본 팁 「기울기를 모르면 `Nelder-Mead`」 → 의심스러운 점: 원본 예제 자신이 기울기 함수를 건네지 않고도 `BFGS` 를 쓴다. 따라서 「기울기를 모르면 기울기 기반 방법은 못 쓴다」로 읽으면 안 된다. 기울기를 따로 주지 않으면 SciPy 가 함수값 차이로 어림한다(확인 필요). `Nelder-Mead` 가 알맞은 것은 오히려 함수가 매끄럽지 않아 기울기 자체가 믿을 만하지 않을 때다(원본에 근거 없음 — 추론).

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 매끄러운 함수, 제약 없음 | `minimize(…, method='BFGS')` | 손으로 x 를 촘촘히 훑는 반복문 |
| 함수가 울퉁불퉁하거나 기울기를 믿기 어렵다 | `Nelder-Mead` | 기울기 기반 방법만 고집하기 |
| 변수마다 범위가 있다 | `L-BFGS-B` + `bounds` | 범위를 무시하고 푼 뒤 잘라 내기 |
| `x + y = 10` 같은 등식 · 부등식 | `SLSQP` + `constraints` | `bounds` 로 흉내 내기 |
| 데이터에 모델 계수를 맞춘다 | `curve_fit` (+ 적절한 `p0`) | 잔차를 직접 적어 `minimize` 로 돌리기(가능하지만 `pcov` 를 직접 구해야 한다) |
| 부호가 바뀌는 구간을 안다 | `brentq` / `root_scalar(bracket=…)` | 구간을 아는데 출발점만 주는 `fsolve` |
| 연립방정식 | `fsolve` | `brentq`(변수 하나짜리다) |

## 핵심 문장

1. **최적화는 출발점에서 시작해 값이 줄어드는 쪽으로 걷는 일이다** — 그래서 `x0` · `p0` 가 어느 답에 닿을지를 정한다.
2. **`method` 는 문제 꼴로 고른다** — 제약 없으면 `BFGS`/`Nelder-Mead`, 범위면 `L-BFGS-B`, 등식 · 부등식이면 `SLSQP`.
3. **`curve_fit` 은 잔차 제곱합을 최소화하는 최적화다** — `popt` 는 답, `pcov` 대각의 제곱근은 그 답의 표준 오차다.
4. **근 찾기는 두 갈래다** — 출발점을 주는 `fsolve`, 부호가 바뀌는 구간을 주는 `brentq`.
5. **결과는 근삿값이고, 꺼내는 자리가 함수마다 다르다** — 배열(`[0]`) · 객체(`.x` · `.root`) · 튜플.

## 용어 풀이

- **최적화** — 어떤 값을 가장 작게(또는 크게) 만드는 입력을 찾는 일.
- **목적함수** — 최적화에서 줄이려는 함수.
- **초기값(`x0`, `p0`)** — 탐색을 시작하는 출발점.
- **수렴** — 반복할수록 답이 한 점에 모여 더 바뀌지 않게 되는 것.
- **기울기(gradient)** — 변수를 조금 바꿨을 때 함수값이 바뀌는 비율. 내려갈 방향을 알려 준다.
- **경계 조건(`bounds`)** — 변수마다 허용 범위.
- **제약 조건(`constraints`)** — 해가 지켜야 하는 등식 · 부등식.
- **등식 제약(`'eq'`)** — `fun(x) == 0` 을 요구한다.
- **부등식 제약(`'ineq'`)** — `fun(x) >= 0` 을 요구한다.
- **피팅** — 모델 함수의 계수를 데이터에 맞추는 일.
- **잔차** — 데이터값과 모델값의 차이.
- **최소제곱** — 잔차 제곱의 합을 가장 작게 하는 방식.
- **`popt`** — `curve_fit` 이 찾은 최적 파라미터 배열.
- **`pcov`** — 그 파라미터들의 공분산 행렬.
- **표준 오차** — 추정한 파라미터가 흔들리는 정도. `pcov` 대각의 제곱근.
- **근** — 함수값을 0 으로 만드는 입력.
- **브래킷** — 양 끝 함숫값 부호가 다른 구간.
- **벤치마크 함수** — 최적화 방법을 시험하려고 만든 까다로운 함수(Rosenbrock 등).

## 더 들어가면

- `minimize` 에 `method` 를 주지 않으면 SciPy 는 문제 꼴을 보고 고른다 — 제약도 경계도 없으면 `BFGS`, 경계만 있으면 `L-BFGS-B`, 제약이 있으면 `SLSQP` (확인 필요).
- `BFGS` 에 `jac=` 로 기울기 함수를 직접 주면 유한차분 어림이 필요 없어 더 정확하고 빨라질 수 있다 (확인 필요).
- `fsolve` 는 MINPACK 의 `hybrd`(Powell 의 hybrid 방법)를 쓴다고 알려져 있다. 그래서 순수 뉴턴법과 걸음이 다르고, x0 = 1.5 에서 어느 근에 닿는지는 직접 돌려 봐야 안다 (확인 필요).
- `curve_fit` 은 `p0` 를 주지 않으면 모든 파라미터를 1 로 두고 시작한다 (확인 필요). `bounds=` 를 주면 내부 방법이 바뀐다 (확인 필요).
- `minimize` 는 지역 최솟값만 찾는다. 전역 최솟값이 필요하면 `basinhopping` · `differential_evolution` 같은 전역 최적화 함수가 있다 (확인 필요).
- `root_scalar` 는 `brentq` 외에도 `bisect` · `newton` · `secant` 같은 method 를 받는다 (확인 필요).
