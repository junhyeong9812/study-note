## 한눈에 — 쉽게 말하면

**해시 함수는 「데이터의 지문을 뜨는 기계」다.**
사람을 기계에 넣으면 정해진 크기의 지문 카드가 나온다.
같은 사람을 넣으면 언제나 같은 지문이 나온다.
점 하나만 달라도 전혀 다른 지문이 나온다.
`hashlib` 도 똑같은 구조다.
바이트를 넣으면 정해진 길이의 다이제스트가 나온다.

> **해시 함수** — 임의 길이의 입력을 정해진 길이의 값으로 바꾸는 함수다.\
> 예: `hashlib.sha256(b"abc")` 는 입력 길이와 상관없이 256비트 값을 만든다.

> **다이제스트** — 해시 함수가 내놓은 결과 값이다.\
> 예: `hexdigest()` 는 다이제스트를 16진수 문자열로 돌려준다.

| 비유 | 실체 |
|---|---|
| 지문을 뜨는 기계 | `hashlib.sha256()` 같은 해시 객체 |
| 기계에 넣는 사람 | 바이트 데이터(`b"..."`, `str.encode()` 의 결과) |
| 지문 카드 | 다이제스트(`hexdigest()` 의 결과) |
| 기계 종류(손가락 수가 다른 기계) | 알고리즘(SHA-256 · SHA-512 · MD5) |
| 사람마다 다르게 붙이는 표식 | 솔트 |

```text
 "Hello, World!"  ──encode──▶  b"Hello, World!"
                                     │
                                     ▼
                            ┌──────────────────┐
                            │  hashlib.sha256  │
                            └──────────────────┘
                                     │ hexdigest()
                                     ▼
                         64글자 16진수 문자열 (256비트)
```

## 이 주제가 답하려는 질문

1. 문자열 · 데이터 · 파일의 해시 값을 `hashlib` 으로 어떻게 만드나?
2. 데이터를 한꺼번에 넣지 않고 조각조각 넣어도 같은 해시가 나오나?
3. 비밀번호는 왜 그냥 해시하면 안 되고, 솔트와 느린 해시를 써야 하나?
4. 어떤 알고리즘을 어떤 용도에 쓰고, 어떤 알고리즘을 보안에 쓰면 안 되나?

## 동작 방식

### (1) 한 번에 해시하기 — `sha256` · `sha512` · `md5`

**언제 쓰나** — 짧은 문자열이나 이미 메모리에 있는 데이터의 다이제스트를 한 줄로 얻을 때 쓴다.

```text
message = "Hello, World!"
hashlib.sha256(message.encode('utf-8')).hexdigest()

  "Hello, World!"            (str)
        │ .encode('utf-8')
        ▼
  b"Hello, World!"           (bytes)
        │ hashlib.sha256(...)
        ▼
  해시 객체 (입력이 이미 들어간 상태)
        │ .hexdigest()
        ▼
  "dffd60...986f"            (64글자 str)
```

- 해시 함수는 바이트를 받으므로 문자열은 먼저 `encode('utf-8')` 로 바이트로 바꾼다.
- `hashlib.sha256(데이터)` 는 해시 객체를 만들면서 데이터를 바로 넣는다.
- `hexdigest()` 는 결과를 16진수 문자열로 돌려준다.
- 16진수 한 글자는 4비트를 나타내므로 256비트는 64글자다.
- 같은 방식으로 SHA-512 는 512비트 = 128글자가 된다.
- 원본은 SHA-512 가 더 긴 다이제스트라서 충돌 저항이 더 높다고 설명한다.
- MD5 도 같은 꼴로 부르지만, 원본은 보안 용도로 쓰지 말고 파일 체크섬 용도로만 쓰라고 못 박는다.

> **충돌** — 서로 다른 두 입력이 같은 다이제스트를 내는 일이다.\
> 예: MD5 는 충돌을 일부러 만드는 공격이 발견되어 보안 용도에서 빠졌다.

### (2) 나눠서 넣기 — `update()` 스트리밍

**언제 쓰나** — 데이터가 한꺼번에 오지 않거나 너무 커서 조각으로 나눠 넣어야 할 때 쓴다.

```text
h = hashlib.sha256()          빈 해시 객체
h.update(b"Hello, ")          누적: "Hello, "
h.update(b"World!")           누적: "Hello, World!"
h.hexdigest()                 누적된 전체에 대한 다이제스트
        │
        ▼
hashlib.sha256(b"Hello, World!").hexdigest() 와 같은 값
```

- 인자 없이 `hashlib.sha256()` 을 부르면 빈 해시 객체가 생긴다.
- `update()` 는 몇 번이든 부를 수 있고, 부를 때마다 입력이 이어 붙는다.
- `hexdigest()` 는 지금까지 넣은 입력 전체에 대한 다이제스트를 낸다.
- 그래서 조각을 어떻게 나눴든 이어 붙인 바이트가 같으면 일괄 방식과 결과가 같다.
- 원본은 이 성질 덕분에 대용량 스트림을 해싱하기 좋다고 설명한다.

### (3) 파일 해시 — 청크 읽기와 `hashlib.new`

**언제 쓰나** — 큰 파일의 무결성을 확인할 체크섬을 메모리를 아끼며 만들 때 쓴다.

```text
file_hash(path, algorithm='sha256', chunk_size=8192)

  hashlib.new('sha256')         ← 알고리즘 이름(문자열)으로 객체 생성
        │
  open(path, 'rb')              ← 바이너리 모드
        │
  ┌─▶ chunk = f.read(8192) ─── 비었나? ── 예 ──▶ break
  │         │ 아니오
  │     h.update(chunk)
  └─────────┘
        │
  h.hexdigest()
```

- `hashlib.new(algorithm)` 은 알고리즘 이름 문자열로 해시 객체를 만든다.
- 그래서 `file_hash(path, 'md5')` 처럼 인자 하나로 알고리즘을 바꿀 수 있다.
- 파일은 `'rb'` 바이너리 모드로 연다 — 텍스트 인코딩이 바이트를 바꾸는 일을 막는다.
- `f.read(chunk_size)` 로 정해진 크기만큼만 읽고 `update()` 에 넣는다.
- 파일 끝에 닿으면 `read()` 가 빈 바이트를 돌려주고, 그때 반복을 끝낸다.
- 한 번에 메모리에 올라가는 양이 청크 하나뿐이라 파일이 커도 메모리 사용량이 일정하다.
- 원본은 테스트 파일을 `tempfile.NamedTemporaryFile(..., delete=False)` 로 만들고, 다 쓴 뒤 `os.unlink` 로 지운다.

> **청크** — 큰 데이터를 나눈 한 조각이다.\
> 예: `f.read(8192)` 는 최대 8192바이트짜리 청크를 읽는다.

> **체크섬** — 데이터가 바뀌지 않았는지 확인하려고 계산해 두는 값이다.\
> 예: 내려받은 파일의 SHA-256 을 배포처가 공개한 값과 비교한다.

### (4) 솔트 해싱 — 비밀번호를 저장하는 기본 꼴

**언제 쓰나** — 비밀번호를 원문 대신 해시로 저장하고, 로그인 때 다시 계산해 맞춰 볼 때 쓴다(원본은 이 꼴을 학습용이라 하고, 실무에는 bcrypt · scrypt 를 권한다).

```text
가입:
  salt = os.urandom(32)                     32바이트 랜덤
  h = sha256(salt + password.encode())
  저장: (salt, h.hexdigest())               ← 둘 다 저장

로그인 검증:
  입력 password ─┐
  저장된 salt ───┴─▶ 같은 계산 다시 ─▶ 새 해시
                                          │ == 저장된 해시 ?
                                          ▼
                                   True / False
```

- 솔트가 없으면 `salt` 를 `os.urandom(32)` 로 새로 만든다.
- `os.urandom` 은 OS 의 안전한 난수 생성기(CSPRNG)를 써서 예측할 수 없는 값을 준다.
- 솔트 바이트와 비밀번호 바이트를 이어 붙여 해시한다.
- 가입 때마다 솔트가 새로 생기므로 같은 비밀번호라도 저장되는 해시가 달라진다.
- 검증 함수는 저장된 솔트를 다시 넘겨 같은 계산을 하고, 결과를 저장된 해시와 비교한다.
- 솔트를 잃으면 같은 계산을 다시 할 수 없으므로 솔트는 해시와 함께 저장한다.
- 원본 주석은 솔트가 레인보우 테이블 · 사전 공격을 무력화하는 데 필수라고 한다.

> **솔트** — 해시하기 전에 입력에 덧붙이는 무작위 바이트다.\
> 예: `salt + password.encode('utf-8')` 를 해시한다.

> **레인보우 테이블** — 흔한 비밀번호들의 해시를 미리 계산해 둔 표다.\
> 예: 솔트 없는 SHA-256 해시를 표에서 찾아 원래 비밀번호를 알아낸다.

> **CSPRNG** — 암호 용도로 쓸 수 있게 예측이 불가능하도록 만든 난수 생성기다.\
> 예: `os.urandom(32)` 는 OS 의 CSPRNG 에서 32바이트를 얻는다.

### (5) PBKDF2 — 일부러 느리게 만든 비밀번호 해시

**언제 쓰나** — 표준 라이브러리만으로 비밀번호 해시를 제대로 만들어야 할 때 쓴다.

```text
hashlib.pbkdf2_hmac('sha256', password_bytes, salt, 600_000, dklen=32)

  password + salt
        │
        ▼
  HMAC-SHA256 ──▶ HMAC-SHA256 ──▶ … (600,000번 반복)
        │
        ▼
  32바이트 키  ──.hex()──▶  64글자 16진수 문자열
```

- `pbkdf2_hmac` 의 인자는 차례대로 해시 알고리즘 이름 · 비밀번호 바이트 · 솔트 · 반복 횟수이고, `dklen` 은 만들 키의 바이트 길이다.
- 반복 횟수만큼 HMAC 해시를 거듭 적용한다.
- 반복이 많을수록 한 번 계산하는 데 오래 걸린다.
- 정당한 사용자는 로그인 때 한 번만 계산하지만, 공격자는 후보 비밀번호마다 이 비용을 치러야 한다.
- 그래서 무차별 대입 비용이 커진다 — 원본의 표현으로 「높을수록 안전, 느림」이다.
- 결과는 바이트이므로 `key.hex()` 로 16진수 문자열로 바꾼다 — 32바이트는 64글자다.
- 함수는 `(salt, key.hex(), iterations)` 셋을 돌려준다.
- 검증은 저장된 솔트와 **같은 반복 횟수**로 다시 계산해 비교한다 — 반복 횟수가 다르면 키도 달라지므로 반복 횟수도 함께 저장해야 한다.

> **PBKDF2** — 비밀번호와 솔트에 HMAC 해시를 여러 번 반복 적용해 키를 만드는 키 유도 함수다.\
> 예: `hashlib.pbkdf2_hmac('sha256', pw, salt, 600_000, dklen=32)`.

> **HMAC** — 해시 함수에 키를 섞어 계산하는 방식이다.\
> 예: PBKDF2 는 비밀번호를 키로 삼아 HMAC-SHA256 을 반복한다.

> **무차별 대입** — 가능한 비밀번호를 하나씩 모두 넣어 보는 공격이다.\
> 예: 해시 하나가 느리면 시도 횟수가 같아도 걸리는 시간이 늘어난다.

### (6) 쓸 수 있는 알고리즘과 고르는 기준

**언제 쓰나** — 코드가 돌아갈 모든 환경에서 확실히 있는 알고리즘을 고를 때, 그리고 용도별로 알고리즘을 정할 때 쓴다.

```text
hashlib.algorithms_guaranteed   ← 모든 플랫폼에서 보장되는 이름들(set)
        │ sorted(...)
        ▼
  정렬된 이름 목록을 출력

용도 ─▶ 알고리즘
  비밀번호        ─▶ bcrypt, scrypt, argon2 (또는 PBKDF2)
  데이터 무결성    ─▶ SHA-256, SHA-3
  파일 체크섬      ─▶ SHA-256 (빠른 확인: MD5, SHA-1)
  보안 목적        ─▶ MD5, SHA-1 절대 금지
```

- `hashlib.algorithms_guaranteed` 는 모든 플랫폼에서 쓸 수 있다고 보장된 알고리즘 이름의 집합이다.
- 집합이라 순서가 없으므로 원본은 `sorted()` 로 정렬해 출력한다.
- 비밀번호에는 느린 해시를 쓴다 — 원본 주석은 GPU 공격 방어를 까닭으로 든다.
- 보안과 상관없는 단순 비교(파일 체크섬)에는 MD5 · SHA-1 도 허용된다.

## 문법 — 형태와 규칙

```python
import hashlib, os

d1 = hashlib.sha256("abc".encode("utf-8")).hexdigest()   # 한 번에

h = hashlib.new("sha256")                                # 이름으로 고르기
h.update(b"a")
h.update(b"bc")                                          # 나눠 넣기
d2 = h.hexdigest()

salt = os.urandom(16)
key = hashlib.pbkdf2_hmac("sha256", b"pw", salt, 100_000, dklen=32)

print(d1 == d2, len(d1), len(key.hex()))
```

- `hashlib.<알고리즘>(바이트)` — 객체를 만들며 데이터를 바로 넣는다.
- `hashlib.<알고리즘>()` — 빈 객체를 만든다.
- `hashlib.new("이름")` — 이름 문자열로 알고리즘을 고른다.
- `객체.update(바이트)` — 입력을 이어 붙인다, 여러 번 부를 수 있다.
- `객체.hexdigest()` — 지금까지의 입력에 대한 다이제스트를 16진수 문자열로 준다.
- 입력은 언제나 바이트다 — 문자열은 `encode('utf-8')` 로 바꾸고, 리터럴은 `b"..."` 로 쓴다.
- `hashlib.pbkdf2_hmac(알고리즘, 비밀번호, 솔트, 반복, dklen=길이)` — 바이트 키를 돌려준다.
- `bytes.hex()` — 바이트를 16진수 문자열로 바꾼다(솔트 · PBKDF2 키 출력에 쓴다).
- 16진수 글자 수 = 비트 수 ÷ 4 = 바이트 수 × 2.

| 알고리즘 | 출력 비트 | hex 글자 수 | 원본의 용도 |
|---|---|---|---|
| SHA-256 | 256 | 64 | 데이터 무결성 · 파일 체크섬 |
| SHA-512 | 512 | 128 | 더 긴 다이제스트, 더 높은 충돌 저항 |
| MD5 | 128 | 32 | 보안 아닌 빠른 체크섬만 |
| PBKDF2 (`dklen=32`) | 256 | 64 | 비밀번호 저장 |

## 어디서 틀리나

### 1. MD5 · SHA-1 을 보안 용도로 쓴다

- MD5 와 SHA-1 은 충돌이 발견되어 보안 용도로 쓰면 안 된다.
- 원본 주석은 디지털 서명 · 비밀번호 같은 보안 목적을 콕 집어 금지한다.
- `hashlib.md5()` 는 문제없이 호출된다 — 막아 주는 것은 언어가 아니라 쓰는 사람의 판단이다.
- 보안과 상관없는 빠른 파일 비교라면 원본도 MD5 · SHA-1 을 허용한다.

### 2. 비밀번호를 솔트 없이, 빠른 해시로 저장한다

- 비밀번호는 반드시 솔트와 함께 해시한다.
- 솔트가 없으면 같은 비밀번호가 같은 해시가 되어 미리 계산한 표(레인보우 테이블)로 풀린다.
- 솔트를 붙여도 SHA-256 한 번은 빠르다 — 빠른 해시는 무차별 대입도 빠르게 해 준다.
- 그래서 PBKDF2 · bcrypt · scrypt 같은 느린 해시를 쓴다.
- 원본의 `hash_password_simple` 은 학습용이라고 스스로 밝힌다.

### 3. 큰 파일을 통째로 읽는다

- `f.read()` 로 파일 전체를 한 번에 읽으면 파일 크기만큼 메모리를 쓴다.
- 파일 해시는 청크 단위로 읽어 `update()` 로 넣어 메모리 효율을 유지한다.
- 원본 주석은 이것을 OOM(메모리 부족) 없이 해싱하는 표준 패턴이라 부른다.

### 4. 알고리즘을 `if` 로 갈라 고른다

- `hashlib.new(algorithm)` 으로 알고리즘을 동적으로 고를 수 있다.
- 알고리즘마다 분기문을 쓰지 않고, 이름 문자열을 인자로 받으면 된다.

### 5. 문자열을 그대로 넣거나 텍스트 모드로 파일을 연다

- 해시는 바이트 입력이 필요하다 — 문자열은 `encode` 를 거쳐야 한다.
- 같은 글자라도 인코딩이 다르면 바이트가 달라지고 해시도 달라진다.
- 파일은 `'rb'` 로 열어 텍스트 인코딩의 영향을 없앤다.

### 6. 검증 때 다른 솔트 · 다른 반복 횟수를 쓴다

- 검증은 저장된 솔트와 같은 반복 횟수로 다시 계산해야 맞는다.
- 그래서 가입 때 솔트(PBKDF2 는 반복 횟수까지)를 해시와 함께 저장한다.

### 7. 원본 주석의 「출력」을 실제 출력으로 믿는다

- 원본 끝의 `# 출력:` 주석은 `# MD5: 65a8...` 처럼 적혀 있다.
- 그러나 코드의 실제 `print` 는 `MD5:     … (보안 용도 사용 금지)` 꼴이라 주석과 모양이 다르다.
- 주석에는 단계별 해시 · 파일 해시 · 솔트 해싱의 줄도 없다 — 출력 전체가 아니라 일부를 손으로 적은 것으로 보인다.
- 솔트와 PBKDF2 키는 실행할 때마다 달라지므로 고정된 출력으로 적을 수도 없다.

### 8. 「600,000회 = NIST 권장」을 그대로 받아 적는다

- 원본의 주장: `pbkdf2_hmac` 은 NIST SP 800-132 의 표준 키 유도 함수이고, 60만 회 반복이 2024 NIST 가이드라는 것이다.
- 왜 의심스러운가: 원본은 600,000 이라는 숫자가 어느 문서의 어느 권고인지 대지 않는다(확인 필요).
- 반복 횟수 권고는 기관과 해에 따라 바뀌는 값이므로, 쓸 때마다 출처를 직접 확인해야 한다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 같은 입력이면 SHA-256 다이제스트가 언제나 같다 | 알고리즘 표준(SHA-2) — 파이썬 · 플랫폼과 무관 |
| SHA-256 은 64글자, SHA-512 는 128글자 hex | 알고리즘의 출력 길이 정의 |
| `update` 를 나눠 불러도 일괄과 같다 | `hashlib` 해시 객체의 동작(이어 붙인 입력 전체를 해시) |
| `algorithms_guaranteed` 의 이름은 모든 플랫폼에서 쓸 수 있다 | 파이썬 `hashlib` 이 보장한다고 원본 주석이 적음 |
| 그 밖의 알고리즘이 있는지 | 파이썬이 빌드된 환경(연결된 암호 라이브러리)에 달림 (확인 필요) |
| `os.urandom` 이 예측 불가능한 값을 준다 | 파이썬은 OS 의 CSPRNG 에 맡긴다 — 품질은 OS 가 진다 |
| `chunk_size=8192` | 원본이 고른 값 — 언어 규칙이 아니다 |
| MD5 · SHA-1 을 보안에 쓰지 않는다 | 보안 권고 · 관례 — 언어는 호출을 막지 않는다 |
| 반복 600,000회가 NIST 권장이다 | 원본의 주장, 출처 불분명 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 비밀번호 저장 | bcrypt · scrypt · argon2, 표준 라이브러리만이면 `pbkdf2_hmac` + 솔트 | 솔트 없는 해시, SHA-256 한 번, MD5 · SHA-1 |
| 데이터 무결성 확인 | SHA-256 · SHA-3 | MD5 · SHA-1(보안이 걸린 경우) |
| 큰 파일 체크섬 | `hashlib.new` + 청크 `update` | `f.read()` 로 통째로 읽기 |
| 보안과 무관한 빠른 파일 비교 | SHA-256, 또는 MD5 · SHA-1 | — |
| 알고리즘을 설정으로 바꾸기 | `hashlib.new(이름)` | 알고리즘마다 `if` 분기 |
| 솔트 만들기 | `os.urandom(n)` | 예측 가능한 값(고정 문자열 등) |

## 핵심 문장

1. **해시는 바이트를 받아 정해진 길이의 다이제스트를 낸다** — 문자열은 `encode`, 결과는 `hexdigest()`.
2. **`update()` 로 나눠 넣어도 결과는 일괄과 같다** — 그래서 큰 파일은 청크로 읽어 해싱한다.
3. **비밀번호는 솔트 + 느린 해시** — 솔트는 미리 계산한 표를 막고, 반복은 무차별 대입을 비싸게 만든다.
4. **검증은 저장한 솔트 · 반복 횟수로 다시 계산해 비교하는 것이다.**
5. **MD5 · SHA-1 은 충돌이 발견되어 보안에 쓰지 않는다** — 단순 체크섬에만.

## 용어 풀이

- **해시 함수** — 임의 길이 입력을 정해진 길이 값으로 바꾸는 함수.
- **다이제스트** — 해시 함수의 결과 값.
- **`hexdigest()`** — 다이제스트를 16진수 문자열로 돌려주는 메서드.
- **충돌** — 서로 다른 입력이 같은 다이제스트를 내는 일.
- **청크** — 큰 데이터를 나눈 한 조각.
- **체크섬** — 데이터가 바뀌지 않았는지 확인하려고 계산하는 값.
- **솔트** — 해시 전에 입력에 덧붙이는 무작위 바이트.
- **레인보우 테이블** — 흔한 입력의 해시를 미리 계산해 둔 표.
- **사전 공격** — 자주 쓰이는 비밀번호 목록을 차례로 넣어 보는 공격.
- **CSPRNG** — 암호 용도로 쓸 수 있는, 예측 불가능한 난수 생성기.
- **PBKDF2** — HMAC 해시를 반복 적용해 비밀번호에서 키를 만드는 함수.
- **HMAC** — 해시 함수에 키를 섞어 계산하는 방식.
- **무차별 대입** — 가능한 값을 모두 넣어 보는 공격.
- **`hashlib.new`** — 알고리즘 이름 문자열로 해시 객체를 만드는 함수.
- **`algorithms_guaranteed`** — 모든 플랫폼에서 보장되는 알고리즘 이름의 집합.

## 더 들어가면

- 검증에서 `==` 로 해시를 비교하면 비교가 일찍 끝나는 시점 차이가 새어 나갈 수 있어, `hmac.compare_digest` 로 비교하라는 권고가 있다 (확인 필요).
- `digest()` 는 다이제스트를 16진수 문자열이 아닌 바이트로 돌려준다 — 저장 공간이 절반이다.
- `hashlib.algorithms_available` 은 지금 환경에서 실제로 쓸 수 있는 이름의 집합으로, `algorithms_guaranteed` 보다 클 수 있다 (확인 필요).
- 파이썬 3.11 이상에는 파일 객체를 받아 청크 읽기를 대신 해 주는 `hashlib.file_digest` 가 있다 (확인 필요).
- 파이썬 3.9 이상에서는 `hashlib.md5(usedforsecurity=False)` 처럼 보안 용도가 아님을 밝히는 인자가 있고, 일부 보안 규정 모드의 환경에서 의미가 있다 (확인 필요).
- `hashlib.scrypt` 는 표준 라이브러리에 있지만 빌드 환경에 따라 없을 수 있다 — bcrypt · argon2 는 외부 패키지가 필요하다 (확인 필요).
