## 한눈에 — 쉽게 말하면

**`secrets` 는 「봉인된 추첨함」이고, `random` 은 「순서를 외울 수 있는 카드 더미」다.**
추첨함에서 나오는 공은 이전 공을 아무리 지켜봐도 다음 공을 짐작할 수 없다.
카드 더미는 섞인 것처럼 보여도, 나온 카드를 충분히 많이 보면 섞은 규칙을 되살려 다음 카드를 맞힐 수 있다.
비밀번호 · 토큰 · API 키를 뽑는 일도 똑같은 구조다.
공격자가 다음 값을 짐작할 수 없어야 하므로 추첨함(`secrets`)에서 뽑아야 한다.

| 비유 | 실체 |
|---|---|
| 봉인된 추첨함 | OS 의 암호학적 난수 생성기(CSPRNG)를 쓰는 `secrets` 모듈 |
| 순서를 외울 수 있는 카드 더미 | Mersenne Twister 를 쓰는 `random` 모듈 |
| 공 몇 개를 한 번에 꺼내기 | `secrets.token_bytes(n)` — n 바이트 |
| 꺼낸 공을 글자로 적기 | `token_hex` · `token_urlsafe` — 같은 바이트를 다른 글자 꼴로 |
| 당첨 번호를 소리 없이 맞춰 보기 | `secrets.compare_digest` — 걸린 시간으로 정답을 흘리지 않는 비교 |

```text
   OS 난수원(CSPRNG)
         │  예측 불가한 바이트
         ▼
   ┌───────────────┐
   │  secrets 모듈  │
   └───────────────┘
     │      │       │         │          │
 token_bytes token_hex token_urlsafe  choice   randbelow
   (bytes)  (16진수)  (URL 안전)    (고르기)  (0..n-1 정수)
```

> **CSPRNG** — 출력 일부를 보아도 다음 출력이나 이전 출력을 계산해 낼 수 없도록 설계된 난수 생성기다.\
> 예: 세션 토큰 · 비밀번호 재설정 토큰을 만들 때 쓰는 생성기.

## 이 주제가 답하려는 질문

1. 보안용 난수는 왜 `random` 이 아니라 `secrets` 로 만들어야 하나?
2. `token_bytes` · `token_hex` · `token_urlsafe` 는 무엇이 같고 무엇이 다르며, 각각 몇 글자가 되나?
3. 비밀번호 · PIN · OTP 처럼 규칙이 있는 값은 `secrets` 의 어떤 함수로 어떻게 만드나?
4. 토큰을 비교할 때 `==` 대신 `compare_digest` 를 쓰는 까닭은 무엇인가?

## 동작 방식

### (1) 토큰 세 가지 — 같은 바이트, 다른 글자 꼴

**언제 쓰나** — 세션 ID · API 키 · 비밀번호 재설정 링크처럼 「추측할 수 없는 문자열」이 필요할 때 쓴다.
바이트 그대로 쓸지, 16진수 글자로 쓸지, URL 에 넣을 글자로 쓸지에 따라 함수를 고른다.

```text
secrets.token_bytes(32)    → 무작위 32바이트 (bytes)          → len = 32
secrets.token_hex(32)      → 32바이트를 16진수로 적은 str     → 1바이트=2자 → 64자
secrets.token_urlsafe(32)  → 32바이트를 URL 안전 Base64 str   → 256비트÷6 ≈ 42.7 → 43자
```

- `token_bytes(n)` 은 n 바이트짜리 `bytes` 를 돌려준다.
- `token_hex(n)` 은 n 바이트를 16진수 글자로 적는다. 한 바이트가 `00`~`ff` 두 글자이므로 길이는 2n 이다.
- `token_urlsafe(n)` 은 n 바이트를 Base64 로 적되 `+` `/` 대신 `-` `_` 를 쓴다. Base64 한 글자는 6비트를 나르므로 32바이트(256비트)는 43글자가 된다(끝을 채우는 `=` 는 붙지 않는다).
- 세 함수 모두 **인자는 바이트 수**다. 글자 수가 아니다.
- 글자 수가 달라도 들어 있는 무작위성(엔트로피)은 바이트 수가 정한다. `token_hex(32)` 와 `token_urlsafe(32)` 는 둘 다 256비트다.

원본 예제는 `raw_token.hex()[:32]` 처럼 앞부분만 잘라 보여 준다.
32바이트를 hex 로 바꾸면 64자이므로, 앞 32자는 앞쪽 16바이트에 해당한다.

> **Base64** — 바이트를 영문자 · 숫자 · 기호 두 개(64가지 글자)로 적는 방식이다. 한 글자가 6비트를 나른다.\
> 예: 3바이트(24비트)가 4글자가 된다.

> **엔트로피** — 값이 얼마나 짐작하기 어려운지를 비트로 센 양이다.\
> 예: 32바이트 무작위 토큰은 256비트 — 가능한 값이 2²⁵⁶ 가지다.

### (2) 고르기와 정수 — `choice` · `randbelow`

**언제 쓰나** — 목록에서 하나를 뽑거나(`choice`), 0 이상 n 미만 정수가 필요할 때(`randbelow`) 쓴다.
비밀번호 · PIN · OTP 는 모두 이 둘을 조합해 만든다.

```text
secrets.choice(["red","blue",...])     → 목록 원소 하나 (균등)
secrets.randbelow(10)                  → 0,1,...,9 중 하나 (10은 나오지 않는다)
''.join(str(secrets.randbelow(10)) for _ in range(6))   → "048213" 같은 6자리 PIN
f"{secrets.randbelow(1_000_000):06d}"  → 0~999999 를 6자리로 0 채움 → "000042" 꼴도 가능
```

- `randbelow(n)` 의 범위는 **0 이상 n 미만**이다. `randbelow(100)` 은 0~99, `randbelow(256)` 은 0~255 다.
- PIN 은 한 자리씩 `randbelow(10)` 을 여섯 번 불러 이어 붙인다.
- OTP 는 한 번에 `randbelow(1_000_000)` 을 뽑고 `:06d` 로 앞을 0 으로 채워 늘 6자리를 만든다. 뽑힌 수가 42 라면 `000042` 가 된다.
- 원본 주석은 `randbelow(10)` 이 「모듈로 편향이 없다」고 말한다. 무작위 바이트(0~255)를 `% 10` 으로 줄이면 256 이 10 으로 나누어떨어지지 않아 0~5 가 조금 더 자주 나온다. `randbelow` 는 그런 치우침 없이 0~9 를 고르게 고른다.

> **모듈로 편향** — 큰 범위의 난수를 `%` 로 작은 범위에 접을 때, 범위가 나누어떨어지지 않아 일부 값이 더 자주 나오는 치우침이다.\
> 예: 0~255 를 `% 10` 하면 0~5 는 26번, 6~9 는 25번씩 걸린다.

### (3) 정책을 지키는 비밀번호 — 다시 뽑기(rejection sampling)

**언제 쓰나** — 「대문자 · 소문자 · 숫자 · 기호를 각각 하나 이상」 같은 비밀번호 규칙을 지켜야 할 때 쓴다.

```text
alphabet = 대소문자 + 숫자 + 기호
while True:
    password = alphabet 에서 choice 를 length 번
    대문자? 소문자? 숫자? 기호? ── 모두 있음 → return
                               └─ 하나라도 없음 → 버리고 처음부터 다시
```

- 글자는 `string.ascii_letters + string.digits + string.punctuation` 에서 고른다.
- 한 글자씩 `secrets.choice(alphabet)` 로 뽑아 `length` 개를 이어 붙인다.
- `any(...)` 네 개로 네 가지 글자 종류가 다 들어 있는지 확인한다.
- 하나라도 빠지면 그 비밀번호를 **통째로 버리고** 새로 뽑는다. 이것이 rejection sampling 이다.
- 원본 주석은 이 방식이 「편향 없음」이라고 말한다. 통째로 다시 뽑으면 규칙을 지키는 비밀번호들이 서로 같은 확률로 남는다. 반대로 빠진 종류를 특정 자리에 끼워 넣는 식으로 고치면 「그 자리에는 숫자가 올 확률이 높다」 같은 무늬가 생긴다(원본에 근거 없음 — 추론).

> **rejection sampling** — 조건에 맞지 않는 표본을 버리고 다시 뽑아, 조건을 만족하는 것만 남기는 방법이다.\
> 예: 네 종류 글자가 다 없으면 새 비밀번호를 처음부터 다시 뽑는다.

### (4) 안전한 비교 — `compare_digest`

**언제 쓰나** — 사용자가 보낸 토큰과 저장해 둔 토큰이 같은지 확인할 때 쓴다.

```text
보통 비교(==)        "abc123def456" vs "abc123def789"
                    앞에서부터 글자를 보다가 다른 곳에서 곧바로 멈춘다
                    → 앞부분이 많이 맞을수록 조금 늦게 끝난다
                    → 공격자가 응답 시간을 재며 한 글자씩 맞혀 갈 수 있다

compare_digest      어디서 달라지든 끝까지 같은 방식으로 본다
                    → 걸린 시간으로 「몇 글자가 맞았나」를 알 수 없다
                    → 돌려주는 값은 == 와 같다: 같으면 True, 다르면 False
```

- `compare_digest(a, b)` 는 같으면 `True`, 다르면 `False` 를 돌려준다. 결과값만 보면 `==` 와 같다.
- 차이는 **걸리는 시간**이다. 원본 주석은 「항상 전체 길이만큼 비교 → 응답 시간으로 정답 추론 불가」라고 설명한다.
- 원본 예제의 `token_a` 와 `token_b` 는 같은 문자열이라 `True`, `token_c` 는 끝 세 글자가 달라 `False` 다.

> **타이밍 공격** — 처리에 걸리는 시간 차이를 재서 비밀 값을 조금씩 알아내는 공격이다.\
> 예: 첫 글자가 맞을 때 응답이 미세하게 늦으면 첫 글자를 확정하고 다음 글자로 넘어간다.

### (5) `secrets` 와 `random` — 왜 갈라 쓰나

**언제 쓰나** — 난수가 필요할 때마다 「이 값이 누군가에게 맞혀지면 문제가 되나?」를 묻고 모듈을 고른다.

```text
random   : Mersenne Twister ── 출력 624개를 모으면 내부 상태 복원 → 다음 값 예측
           → 시뮬레이션 · 게임 · 통계용
secrets  : OS 의 CSPRNG ── 출력을 모아도 다음 값을 계산할 수 없다
           → 토큰 · 비밀번호 · API 키 · 세션 ID
```

- `random` 은 Mersenne Twister 알고리즘을 쓴다. 원본 주석은 출력 624개로 내부 상태를 되살릴 수 있다고 적는다. 상태를 알면 이후의 모든 값을 맞힌다.
- 그래서 `random` 은 재현 가능하고 빠른 난수가 필요한 시뮬레이션 · 게임 · 통계에 쓰고, 보안 목적에는 절대 쓰지 않는다.
- `secrets` 는 OS 의 암호학적 난수 생성기를 쓴다. 원본 주석은 그 예로 `/dev/urandom` 과 `BCryptGenRandom` 을 든다.

> **Mersenne Twister** — `random` 모듈이 쓰는 의사난수 알고리즘이다. 통계적으로 고르지만 출력으로 상태를 되살릴 수 있다.\
> 예: 공격자가 `random` 으로 만든 토큰을 충분히 모으면 다음 토큰을 계산한다.

## 문법 — 형태와 규칙

```python
import secrets
import string

t = secrets.token_hex(32)               # 64자 16진수 문자열
u = secrets.token_urlsafe(32)           # 43자 URL 안전 문자열
b = secrets.token_bytes(32)             # 32바이트 bytes

pick = secrets.choice(["a", "b", "c"])  # 목록에서 하나
n = secrets.randbelow(100)              # 0~99

code = f"{secrets.randbelow(1_000_000):06d}"   # 6자리 OTP

ok = secrets.compare_digest(t, t)       # True
```

- `token_*(n)` 의 `n` 은 **바이트 수**다.
- `token_hex(n)` 의 길이는 `2n`, `token_urlsafe(n)` 의 길이는 바이트를 6비트씩 나눈 수(32 → 43, 48 → 64)다.
- `choice(seq)` 는 시퀀스에서 원소 하나를 고른다. 문자열도 시퀀스라 `choice(alphabet)` 이 글자 하나를 고른다.
- `randbelow(n)` 은 0 이상 n 미만이다.
- 규칙 있는 값은 `''.join(... for _ in range(k))` 꼴로 한 글자씩 모아 만든다.
- `string` 모듈 상수: `ascii_letters`(대소문자) · `digits`(0~9) · `punctuation`(기호).
- 원본의 토큰 길이 가이드:

| 용도 | 원본 권장 길이 |
|---|---|
| 세션 토큰 | 32바이트(256비트) 이상 |
| API 키 | 32~48바이트 (48바이트 = 384비트) |
| 비밀번호 재설정 | 32바이트 |
| CSRF 토큰 | 32바이트 |

- 원본 팁의 결론: 토큰 길이는 **최소 32바이트(256비트)** 를 권장한다.
- 비밀번호 재설정 링크는 토큰만 무작위로 만든다고 끝이 아니다. 원본 주석대로 **시간 제한 + 일회성**으로 운영한다.

## 어디서 틀리나

### 1. 보안 값을 `random` 으로 만든다

`random.choice` · `random.randint` 도 겉보기에는 무작위다.
하지만 Mersenne Twister 는 출력이 쌓이면 다음 값을 예측할 수 있다.
원본 팁 그대로, 보안 관련 랜덤 값은 반드시 `secrets` 로 만든다.

### 2. 인자를 글자 수로 착각한다

`token_hex(32)` 는 32글자가 아니라 64글자다.
`token_urlsafe(32)` 도 32글자가 아니라 43글자다.
「32자짜리 토큰」을 원해 `token_hex(16)` 을 쓰면 엔트로피는 128비트로 줄어든다.

### 3. 원본의 세션 ID 가 원본의 가이드보다 짧다

원본 예제는 세션 ID 를 `secrets.token_hex(16)` 으로 만든다. 16바이트 = 128비트다.
그런데 같은 예제의 가이드는 「세션 토큰: 32바이트(256비트) 이상」이라고 적는다.
가이드를 따르려면 `token_hex(32)` 처럼 32바이트 이상을 써야 한다.

### 4. 토큰을 `==` 로 비교한다

결과는 같아도, 비교가 멈추는 위치가 시간 차이로 드러날 수 있다.
원본 팁대로 `compare_digest()` 로 비교해 타이밍 공격을 막는다.

### 5. OTP 를 `str(randbelow(1_000_000))` 로 만든다

뽑힌 수가 42 이면 `"42"` 두 글자가 된다.
`:06d` 로 0 을 채워야 늘 6자리다.

### 6. 정책 미달 비밀번호를 「고쳐서」 쓴다

빠진 종류를 정해진 자리에 넣으면 그 자리의 글자 종류가 짐작 가능해진다.
원본처럼 통째로 버리고 다시 뽑는다.

### 7. 원본의 예시 주석 블록을 그대로 믿는다

원본 코드 끝의 `# 출력:` 아래 줄들은 실제 흐름과 어긋난다.
- `token_bytes` 줄이 빠져 있다.
- `token_hex: a1b2c3d4...` 처럼 앞부분을 줄여 적었지만 코드는 앞 32자를 찍는다.
- 제목이 `=== 안전한 비교 ===` 로 적혀 있지만 코드가 찍는 제목은 `=== 안전한 비교 (compare_digest) ===` 다.
- 비밀번호 줄은 코드에서 앞에 공백 두 칸이 붙고 16자 전체가 찍힌다.
이 블록은 꼴을 보여 주는 예시일 뿐, 무작위 값은 돌릴 때마다 달라진다.

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `secrets` 는 OS 의 CSPRNG 를 쓴다 | Python 표준 라이브러리 문서가 밝히는 설계다 |
| 그 난수원이 `/dev/urandom` · `BCryptGenRandom` 이다 | OS 와 CPython 구현의 몫이다 — 언어가 특정 장치를 약속하지 않는다 (확인 필요) |
| `random` 은 Mersenne Twister 를 쓴다 | 표준 라이브러리 문서에 적힌 `random` 모듈의 구현 선택이다 |
| 출력 624개로 상태를 복원할 수 있다 | Mersenne Twister(MT19937) 알고리즘의 성질이다 — 원본 주석의 주장 |
| `compare_digest` 는 「항상 일정한 시간」에 비교한다 | 원본의 주장 → 문서는 타이밍 분석을 막도록 설계됐다고 설명한다. 두 값의 길이가 다를 때도 시간이 같은지는 단정할 수 없다 (확인 필요) |
| `token_hex(32)` 는 64자, `token_urlsafe(32)` 는 43자 | 16진수 · Base64 인코딩 규칙에서 나오는 값이다 |
| 토큰은 최소 32바이트를 권장한다 | 원본의 권장이다 — 언어나 모듈이 강제하지 않는다 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 세션 ID · API 키 · CSRF 토큰 | `secrets.token_hex` / `token_urlsafe` (32바이트 이상) | `random` 으로 만든 문자열 |
| 비밀번호 재설정 링크 | `secrets.token_urlsafe(32)` + 시간 제한 · 일회성 | `token_hex` 를 URL 인코딩 없이 쓸 이유도 없지만, `+` `/` 가 섞이는 일반 Base64 |
| 임시 비밀번호 | `secrets.choice` + 다시 뽑기 | 빠진 종류를 끼워 넣어 고치기 |
| PIN · OTP | `secrets.randbelow` + `:06d` | `random.randint`, `바이트 % 10` |
| 토큰 비교 | `secrets.compare_digest` | `==` |
| 게임 · 시뮬레이션 · 통계 | `random` | 굳이 `secrets` (재현이 필요할 때) |

## 핵심 문장

1. **보안 관련 랜덤 값은 반드시 `secrets` 로 만든다** — `random` 은 예측 가능하다.
2. **`token_*` 의 인자는 바이트 수다** — 엔트로피는 바이트 수가 정하고, 글자 수는 인코딩이 정한다.
3. **토큰은 최소 32바이트(256비트)** 를 권장한다.
4. **규칙 있는 값은 `choice` · `randbelow` 를 조합하고, 규칙 미달은 통째로 다시 뽑는다.**
5. **토큰은 `compare_digest` 로 비교한다** — 비교 시간이 정답을 흘리지 않게.

## 용어 풀이

- **CSPRNG** — 출력으로 다음 · 이전 출력을 계산할 수 없게 설계된 암호학적 난수 생성기.
- **엔트로피** — 값을 짐작하기 어려운 정도를 비트로 센 양.
- **Base64** — 바이트를 64가지 글자로 적는 방식. 한 글자가 6비트.
- **URL 안전 Base64** — `+` `/` 대신 `-` `_` 를 써서 URL 에 그대로 넣을 수 있게 한 Base64.
- **16진수(hex)** — 한 바이트를 `00`~`ff` 두 글자로 적는 꼴.
- **Mersenne Twister** — `random` 이 쓰는 의사난수 알고리즘. 출력으로 상태를 되살릴 수 있다.
- **타이밍 공격** — 처리 시간 차이로 비밀 값을 알아내는 공격.
- **rejection sampling** — 조건에 안 맞는 표본을 버리고 다시 뽑는 방법.
- **모듈로 편향** — `%` 로 범위를 줄일 때 일부 값이 더 자주 나오는 치우침.
- **OTP** — 한 번만 쓰는 일회용 코드. 이 예제에서는 6자리 숫자.
- **PIN** — 숫자로 된 짧은 비밀 번호.
- **세션 ID** — 로그인한 사용자를 가려내려고 쿠키에 담는 무작위 식별자.
- **CSRF 토큰** — 다른 사이트가 사용자 몰래 요청을 보내지 못하게 폼에 넣는 무작위 값.

## 더 들어가면

- `token_bytes()` · `token_hex()` · `token_urlsafe()` 는 인자를 빼면 모듈이 정한 기본 바이트 수를 쓴다. 기본값은 Python 버전에 따라 바뀔 수 있다 (확인 필요).
- `secrets` 의 함수들은 내부적으로 `random.SystemRandom` 과 `os.urandom` 위에 서 있다 (확인 필요).
- `compare_digest` 에 `str` 을 넘길 때는 두 값이 같은 타입이어야 하고, ASCII 가 아닌 글자가 섞인 `str` 은 거부될 수 있다. 바이트로 비교하는 편이 안전하다 (확인 필요).
- `secrets.choice` 에 빈 시퀀스를 주면 고를 것이 없어 예외가 난다 (확인 필요).
- 비밀번호 정책이 까다로울수록(길이가 짧고 요구 종류가 많을수록) 다시 뽑는 횟수가 늘어난다. 길이 16 에서는 대개 몇 번 안에 끝난다 (확인 필요).
- `secrets` 는 `hmac.compare_digest` 와 같은 비교 함수를 다시 내보낸 것이다 (확인 필요).
