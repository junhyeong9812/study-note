## 한눈에 — 쉽게 말하면

**`struct` 는 「칸 크기가 정해진 신고서 양식」이다.**
양식에는 「1칸: 숫자 4자리, 2칸: 숫자 2자리, 3칸: 글자 10자」처럼 칸마다 너비가 미리 적혀 있다.
값을 양식에 채워 넣으면 한 줄로 이어진 종이 띠가 나온다.
띠를 받은 쪽은 같은 양식을 대고 칸 경계를 따라 잘라 읽으면 원래 값을 되찾는다.
날짜를 「연-월-일」로 쓸지 「일-월-연」으로 쓸지도 양식이 정해 두어야 서로 헷갈리지 않는다.
`struct` 도 똑같은 구조다.
포맷 문자열이 양식이고, `pack` 이 채워 넣기, `unpack` 이 잘라 읽기, 접두사(`>` · `<` · `!` …)가 날짜 쓰는 순서다.

| 비유 | 실체 |
|---|---|
| 양식(칸과 너비) | 포맷 문자열 `'>H 4s f'` |
| 칸 하나 | 포맷 문자 하나(`H` · `4s` · `f`) |
| 양식을 채운 종이 띠 | `bytes` 객체 |
| 채워 넣기 | `struct.pack(포맷, 값들…)` |
| 잘라 읽기 | `struct.unpack(포맷, 바이트)` → 튜플 |
| 날짜 쓰는 순서 | 바이트 순서 접두사(엔디안) |
| 양식의 총 너비 | `struct.calcsize(포맷)` |
| 자주 쓰는 양식을 코팅해 둔 것 | `struct.Struct` 객체 |

```text
 Python 값            포맷 '>H 4s f'               bytes
 (1001, b'TEMP', 36.5) ──pack──▶ [ H:2 ][ 4s:4 ][ f:4 ] ──▶ 10바이트 띠
                       ◀─unpack─ 같은 포맷으로 칸을 잘라 읽음
```

> **바이너리 데이터** — 사람이 읽는 글자가 아니라 바이트 값 그대로 저장 · 전송되는 데이터.\
> 예: 네트워크 패킷 헤더, BMP 파일 머리 14바이트.

## 이 주제가 답하려는 질문

1. Python 의 정수 · 실수 · 바이트열을 정해진 크기의 바이트로 어떻게 바꾸고 되돌리나?
2. 같은 수가 바이트 순서(엔디안)에 따라 어떻게 다르게 놓이며, 왜 순서를 정해 줘야 하나?
3. 포맷 하나가 몇 바이트를 차지하는지는 어떻게 정해지고, 패딩은 언제 끼어드나?
4. 같은 포맷을 여러 번 쓰거나 큰 버퍼의 일부만 다룰 때는 무엇을 쓰나?

## 동작 방식

### (1) `pack` 과 `unpack` — 값 ↔ 바이트

**언제 쓰나** — Python 값을 파일 · 소켓으로 보낼 바이트로 만들 때(`pack`), 받은 바이트를 값으로 되돌릴 때(`unpack`).

```text
struct.pack('ihf', 42, 256, 3.14)
        │
        ▼  포맷 문자마다 값 하나씩 짝지어 칸을 채운다
  i ← 42     → 2a 00 00 00
  h ← 256    → 00 01
  (패딩)      → 00 00          ← '@'(기본) 이라 float 앞을 정렬
  f ← 3.14   → c3 f5 48 40
        │
        ▼
  b'*\x00\x00\x00\x00\x01\x00\x00\xc3\xf5H@'   (12바이트)

struct.unpack('ihf', 위 바이트) → (42, 256, 3.140000104904175)
```

- 포맷 문자 `i` · `h` · `f` 가 차례로 값 `42` · `256` · `3.14` 와 짝지어진다.
- 접두사가 없으면 기본 `@` 이고, `@` 는 네이티브 바이트 순서와 네이티브 정렬을 쓴다.
- 네이티브 순서가 리틀 엔디안인 플랫폼(x86/x64 등)에서는 `42` 가 `2a 00 00 00` 처럼 작은 바이트부터 놓인다.
- `h`(2바이트) 다음에 `f`(4바이트)를 4의 배수 위치에 맞추느라 2바이트 패딩이 끼어, 4+2+4=10 이 아니라 12바이트가 된다.
- `unpack` 은 언제나 **튜플**을 돌려준다 — 값이 하나여도 `(값,)` 꼴이다.
- `f` 는 4바이트 실수라 `3.14` 를 정확히 담지 못하고 가장 가까운 4바이트 실수로 저장한다. 되돌리면 `3.140000104904175` 가 된다.
- `bytes` 를 사람이 보기 좋게 찍으려면 `.hex()` 를 쓴다.

> **패딩** — 다음 칸을 정렬된 위치에서 시작시키려고 칸 사이에 끼워 넣는 빈 바이트(`\x00`).\
> 예: `'ihf'` 에서 `h` 와 `f` 사이의 `00 00`.

### (2) 바이트 순서 접두사 — 엔디안

**언제 쓰나** — 두 바이트 이상인 수를 다른 기계 · 다른 프로그램과 주고받을 때, 순서를 명시해 오해를 막는다.

```text
value = 0x01020304

'>I'  빅 엔디안     → 01 02 03 04   (큰 바이트부터)
'<I'  리틀 엔디안   → 04 03 02 01   (작은 바이트부터)
'=I'  네이티브      → 플랫폼 순서를 따른다 (리틀 엔디안 플랫폼이면 04 03 02 01)
```

- `>` 는 가장 큰 자리 바이트 `01` 을 맨 앞에 둔다.
- `<` 는 가장 작은 자리 바이트 `04` 를 맨 앞에 둔다.
- `=` 는 실행 중인 플랫폼의 순서를 따르므로 플랫폼이 바뀌면 결과도 바뀔 수 있다.
- 접두사는 포맷 문자열의 **맨 앞**에 한 번 쓰고, 문자열 전체에 적용된다.

| 접두사 | 바이트 순서 | 패딩(정렬) |
|---|---|---|
| `@` | 네이티브 (기본) | 있음 |
| `=` | 네이티브 | 없음 |
| `<` | 리틀 엔디안 | 없음 |
| `>` | 빅 엔디안 (네트워크) | 없음 |
| `!` | 네트워크 (= 빅 엔디안) | 없음 |

> **엔디안** — 여러 바이트로 된 수를 메모리 · 전송에서 어떤 순서로 놓는지.\
> 예: `0x01020304` 를 `01 02 03 04` 로 둘지 `04 03 02 01` 로 둘지.

### (3) 크기 계산 — `calcsize`

**언제 쓰나** — 헤더가 몇 바이트인지 알아야 바이트를 정확히 잘라 `unpack` 에 넘길 수 있을 때.

```text
struct.calcsize('>HH4sf')   → 2 + 2 + 4 + 4 = 12   (패딩 없음)
struct.calcsize('<2sIHHI')  → 2 + 4 + 2 + 2 + 4 = 14 (패딩 없음)
struct.calcsize('!BH')      → 1 + 2 = 3
'ihf' (기본 '@')            → 4 + 2 + (2) + 4 = 12   (패딩 포함)
```

- `calcsize` 는 패딩까지 포함한 정확한 바이트 수를 돌려준다.
- `@` 가 아닌 접두사를 쓰면 칸 너비를 그대로 더한 값이 크기다.
- BMP 헤더는 `<2sIHHI` 로 14바이트이며, 파일 포맷이 리틀 엔디안이라 `<` 를 쓴다.
- `unpack` 은 **정확히 `calcsize` 만큼**의 바이트를 요구한다 — 길거나 짧으면 오류가 난다.

### (4) 바이트 문자열 — `s`

**언제 쓰나** — 태그 · 서명(`b'BM'`) 같은 고정 길이 바이트 칸을 다룰 때.

```text
struct.pack('10s', b'Hello')
   → b'Hello\x00\x00\x00\x00\x00'      (모자란 5칸을 \x00 으로)
struct.unpack('10s', 위 값)
   → (b'Hello\x00\x00\x00\x00\x00',)   (패딩까지 그대로 돌아온다)
   [0].rstrip(b'\x00') → b'Hello'
```

- `10s` 는 정확히 10바이트 칸이다 — 짧으면 `\x00` 으로 채우고, 길면 잘린다.
- `unpack` 은 패딩을 지워 주지 않으므로 `rstrip(b'\x00')` 으로 직접 걷어 낸다.
- `s` 칸에는 `str` 이 아니라 `bytes` 가 들어간다 — 글자는 `encode` 로 바이트로 바꿔 넣고, 꺼낸 뒤 `decode` 로 글자로 돌린다.
- 포맷 문자열 안의 공백(`'>H 4s f'`)은 읽기 좋게 하려는 것이고 `struct` 가 무시한다.

### (5) 헤더 + 본문 패킷

**언제 쓰나** — 길이가 바뀌는 본문 앞에 「종류 · 길이」를 담은 고정 크기 헤더를 붙여 보낼 때.

```text
create_packet(1, 'Hello, Network!')
  body   = 'Hello, Network!'.encode('utf-8')   → 15바이트
  header = struct.pack('!BH', 1, 15)           → 01 | 00 0f
  header + body → 01 000f 48656c6c6f2c204e6574776f726b21  (3 + 15 = 18바이트)

parse_packet(packet)
  header_size = calcsize('!BH')                → 3
  unpack('!BH', packet[:3])                    → (1, 15)
  packet[3:3+15].decode('utf-8')               → 'Hello, Network!'
```

- `B`(1바이트 unsigned)에 종류, `H`(2바이트 unsigned)에 본문 길이를 담는다.
- `!` 라서 길이 `15` 가 `00 0f` 처럼 큰 바이트부터 놓인다.
- 받는 쪽은 `calcsize` 로 헤더 크기를 구해 **헤더만** 잘라 `unpack` 한다 — `unpack` 이 정확한 길이를 요구하기 때문이다.
- 헤더에서 읽은 길이로 본문을 잘라 `decode` 한다.

### (6) 재사용과 버퍼 — `Struct` · `pack_into` · `unpack_from` · `iter_unpack`

**언제 쓰나** — 같은 포맷을 반복해 쓰거나, 큰 버퍼 안 특정 위치에 바로 쓰고 읽을 때.

```text
point_struct = struct.Struct('>ff')      .format → '>ff'   .size → 8
buffer = bytearray(8 * 3)                 24바이트 빈 버퍼

pack_into(buffer, 0,  1.0, 2.0)  → [3f800000 40000000][........][........]
pack_into(buffer, 8,  3.0, 4.0)  → [........][40400000 40800000][........]
pack_into(buffer, 16, 5.0, 6.0)  → [........][........][40a00000 40c00000]

unpack_from(buffer, 8) → (3.0, 4.0)

struct.iter_unpack('>i', pack('>3i', 10, 20, 30))
  → (10,) → (20,) → (30,)   4바이트씩 차례로
```

- `Struct('>ff')` 는 포맷을 한 번 해석해 두고, 같은 포맷을 반복할 때 재사용한다 — 원본 팁은 이쪽이 빠르다고 한다.
- `.size` 로 한 레코드의 크기(8)를 얻어, `i` 번째 점의 오프셋을 `i * size` 로 계산한다.
- `pack_into` 는 새 `bytes` 를 만들지 않고 가변 버퍼 `bytearray` 의 그 오프셋에 바로 쓴다.
- `unpack_from` 은 버퍼가 포맷보다 길어도 오프셋부터 포맷 크기만큼만 읽는다 — 24바이트 버퍼에서 8바이트씩 읽는 것이 그 예다.
- `iter_unpack` 은 같은 포맷이 되풀이되는 바이트를 처음부터 한 레코드씩 풀어 튜플을 하나씩 내준다(원본은 Python 3.4+ 라고 적었다).
- 튜플이라 값 하나만 쓸 때는 `values[0]` 으로 꺼낸다.

> **오프셋** — 버퍼의 맨 앞에서부터 센 바이트 위치.\
> 예: 8바이트 레코드의 세 번째 것은 오프셋 16에서 시작한다.

## 문법 — 형태와 규칙

```python
import struct

fmt = '>H 4s f'                       # 접두사 + 포맷 문자들 (공백은 무시)
size = struct.calcsize(fmt)           # 2 + 4 + 4 = 10
raw = struct.pack(fmt, 7, b'ABCD', 1.5)
seq, tag, val = struct.unpack(fmt, raw)   # 튜플로 돌아온다
print(seq, tag.decode(), val)

rec = struct.Struct('>hh')
buf = bytearray(rec.size * 2)
rec.pack_into(buf, rec.size, -1, 2)   # 두 번째 칸에 바로 쓰기
print(rec.unpack_from(buf, rec.size))
```

- 포맷 = `[접두사] 포맷문자 [포맷문자 …]`. 접두사를 빼면 `@` 다.
- 숫자를 앞에 붙이면 반복이다 — `'3i'` 는 `'iii'`, `'10s'` 는 10바이트 문자열 하나다.
- 대문자는 unsigned(음수 없음), 소문자는 signed(음수 있음)다.
- `pack` 에 넘기는 값의 개수와 형은 포맷 문자와 하나하나 맞아야 한다.

원본의 포맷 문자 표 (크기는 원본 표의 값):

| 문자 | C 형 | 크기 | 담는 Python 값 |
|---|---|---|---|
| `b` | signed char | 1 | 정수 |
| `B` | unsigned char | 1 | 0 이상 정수 |
| `h` | short | 2 | 정수 |
| `H` | unsigned short | 2 | 0 이상 정수 |
| `i` | int | 4 | 정수 |
| `I` | unsigned int | 4 | 0 이상 정수 |
| `q` | long long | 8 | 정수 |
| `Q` | unsigned long long | 8 | 0 이상 정수 |
| `f` | float | 4 | 실수 (정밀도 낮음) |
| `d` | double | 8 | 실수 |
| `?` | bool | 1 | `True` / `False` |
| `s` | char[] | N | `bytes` (앞의 숫자가 N) |

| 함수 · 메서드 | 하는 일 |
|---|---|
| `struct.pack(fmt, *값)` | 값 → `bytes` |
| `struct.unpack(fmt, 바이트)` | `bytes` → 튜플 (길이가 정확히 맞아야 함) |
| `struct.calcsize(fmt)` | 포맷의 바이트 수 (패딩 포함) |
| `struct.Struct(fmt)` | 포맷을 담은 재사용 객체 (`.format` · `.size`) |
| `pack_into(버퍼, 오프셋, *값)` | 가변 버퍼의 오프셋에 바로 쓰기 |
| `unpack_from(버퍼, 오프셋)` | 버퍼의 오프셋에서 바로 읽기 |
| `struct.iter_unpack(fmt, 바이트)` | 반복 레코드를 하나씩 튜플로 |

## 어디서 틀리나

### 1. 접두사를 빼서 `@` 가 끼어든다
기본 `@` 는 네이티브 정렬 때문에 패딩을 넣는다.
`'ihf'` 가 10이 아니라 12바이트가 되는 것이 그 예다.
다른 기계 · 다른 언어와 주고받는 데이터에는 `<` · `>` · `!` 처럼 순서와 크기가 정해진 접두사를 쓴다.

### 2. 네트워크에 리틀 엔디안이나 네이티브를 쓴다
원본 팁: 네트워크 프로토콜에는 항상 빅 엔디안(`>` 또는 `!`)을 쓴다.
네트워크 바이트 순서가 빅 엔디안으로 정해져 있어, 양쪽이 이 약속을 따라야 같은 수로 읽는다.
`=` 는 플랫폼마다 결과가 다를 수 있다.

### 3. 크기를 짐작으로 센다
원본 팁: `calcsize()` 로 포맷의 바이트 크기를 미리 확인한다.
패딩이 끼면 손으로 더한 값과 달라진다.
헤더를 자를 때 상수를 박아 두지 말고 `calcsize` 결과를 쓰면 포맷을 바꿔도 맞는다.

### 4. `unpack` 에 길이가 안 맞는 바이트를 준다
`unpack` 은 정확히 `calcsize` 만큼의 바이트를 요구한다.
패킷 전체를 헤더 포맷으로 `unpack` 하면 실패한다.
앞부분만 잘라 넘기거나, 오프셋부터 필요한 만큼만 읽는 `unpack_from` 을 쓴다.

### 5. `s` 칸에 `str` 을 넣거나, 꺼낸 바이트를 그대로 글자로 쓴다
`s` 는 바이트 단위이고 유니코드 글자를 모른다.
넣을 때 `encode`, 꺼낼 때 `decode` 가 필요하다.
고정 길이 칸은 남는 자리를 `\x00` 으로 채우므로 꺼낸 뒤 `rstrip(b'\x00')` 으로 걷어 낸다.
넣을 바이트가 칸보다 길면 조용히 잘린다.

### 6. `f` 로 담은 실수가 원래 값과 다르다
`f` 는 4바이트 실수라 `3.14` 가 `3.140000104904175` 로 돌아온다.
정밀도가 중요하면 8바이트 `d` 를 쓴다.
같은지 비교할 때 `==` 대신 반올림하거나 표시 자릿수를 줄인다(원본은 `{value:.1f}` 로 찍었다).

### 7. 같은 포맷 문자열을 반복 호출마다 넘긴다
원본 팁: 같은 포맷을 반복해 쓰면 `struct.Struct` 객체를 만들어 재사용하는 것이 빠르다.
원본 팁: `pack_into` / `unpack_from` 은 버퍼를 직접 조작할 때 유용하다.

### 8. 예제 출력의 「N bytes bytes」
원본 예제의 포맷 표에서 `s` 의 크기가 문자열 `'N bytes'` 라서 찍을 때 `bytes` 가 두 번 붙는다.
`struct` 의 동작과는 상관없는 출력 문구의 흠이다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `<` · `>` · `!` · `=` 는 패딩 없이 칸 너비를 그대로 더한 크기를 쓴다 | `struct` 모듈 문서의 표준 크기 규칙 (확인 필요) |
| `'ihf'` 가 `@` 에서 12바이트다 | 플랫폼의 C 정렬 규칙 — 언어 보장 아님. 원본 주석의 주장 |
| 원본 표의 `i` = 4바이트, `q` = 8바이트 등 | 표준 크기 모드에서의 값이다. `@` 에서는 플랫폼 C 형의 크기를 따른다 (확인 필요) |
| `=` · `@` 의 바이트 순서가 리틀 엔디안이다 | x86/x64 같은 플랫폼의 성질 — 언어 보장 아님 |
| 네트워크 바이트 순서는 빅 엔디안이다 | 네트워크 프로토콜의 관례 · 표준 — Python 이 정한 것이 아님 |
| `Struct` 재사용이 더 빠르다 | 구현(CPython)의 성능 성질 — 원본 팁. 얼마나 빠른지는 확인 필요 |
| `f` 가 `3.14` 를 `3.140000104904175` 로 돌려준다 | 4바이트 부동소수점 형식의 한계 — 형식은 확인 필요 |
| `iter_unpack` 은 Python 3.4+ | 원본의 주장 (확인 필요) |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 네트워크 패킷 헤더 | `!` 또는 `>` 고정 포맷 | 접두사 없는 `@` · `=` |
| 리틀 엔디안 파일 포맷(BMP 등) | 포맷이 정한 `<` | 네이티브에 맡기기 |
| 헤더를 잘라 읽기 | `calcsize` 로 구한 길이 | 손으로 센 상수 |
| 같은 포맷을 여러 번 | `struct.Struct` 객체 | 매번 포맷 문자열 |
| 큰 버퍼의 특정 위치 | `pack_into` / `unpack_from` | 잘라 만든 조각을 다시 이어 붙이기 |
| 같은 레코드가 줄지은 바이트 | `iter_unpack` | 오프셋을 손으로 늘리는 반복 |
| 길이가 바뀌는 글자 | `encode` 한 바이트 + 길이 필드 | `s` 칸에 `str` 직접 |
| 정밀한 실수 | `d` | `f` |

## 핵심 문장

1. **포맷 문자열이 바이트의 양식이다** — `pack` 은 값을 그 양식대로 바이트로, `unpack` 은 같은 양식으로 튜플로 되돌린다.
2. **바이트 순서는 접두사로 명시한다** — 네트워크는 `!` · `>`, 파일은 포맷이 정한 순서, 기본 `@` 는 네이티브 순서에 패딩까지 넣는다.
3. **크기는 `calcsize` 로 구하고, `unpack` 에는 정확히 그만큼만 준다.**
4. **`s` 는 바이트 칸이다** — 글자는 `encode` / `decode` 로 오가고, 남는 칸은 `\x00` 이다.
5. **반복은 `Struct`, 버퍼 직접 조작은 `pack_into` / `unpack_from`, 반복 레코드는 `iter_unpack`.**

## 용어 풀이

- **바이너리 데이터** — 바이트 값 그대로 저장 · 전송되는 데이터.
- **`bytes`** — 바꿀 수 없는 바이트열. `pack` 의 결과다.
- **`bytearray`** — 바꿀 수 있는 바이트열. `pack_into` 가 쓰는 버퍼다.
- **포맷 문자열** — 칸의 순서 · 형 · 바이트 순서를 적은 문자열(`'>H 4s f'`).
- **포맷 문자** — 칸 하나의 형을 뜻하는 문자(`i` · `H` · `s` …).
- **접두사** — 포맷 문자열 맨 앞에서 바이트 순서와 정렬을 정하는 문자(`@` · `=` · `<` · `>` · `!`).
- **엔디안** — 여러 바이트로 된 수를 놓는 순서.
- **빅 엔디안** — 큰 자리 바이트부터 놓는 순서. 네트워크 바이트 순서다.
- **리틀 엔디안** — 작은 자리 바이트부터 놓는 순서. x86/x64 의 네이티브 순서다.
- **네이티브** — 실행 중인 플랫폼의 순서 · 정렬을 따르는 것.
- **정렬 · 패딩** — 칸을 정해진 배수 위치에서 시작시키려고 빈 바이트를 끼우는 것.
- **signed / unsigned** — 음수를 담을 수 있는 형 / 0 이상만 담는 형.
- **오프셋** — 버퍼 맨 앞에서 센 바이트 위치.
- **헤더** — 패킷 · 파일 앞쪽의 고정 크기 정보 칸.
- **본문(body)** — 헤더 뒤에 오는 실제 내용.
- **hex** — 바이트를 두 자리 16진수로 늘어놓은 표기(`bytes.hex()`).

## 더 들어가면

- 포맷과 길이가 맞지 않거나 값이 칸 범위를 넘으면 `struct.error` 예외가 난다 (확인 필요).
- `iter_unpack` 에 넘기는 바이트 길이는 포맷 크기의 배수여야 한다 (확인 필요).
- 포맷 문자 `x` 는 값 없이 빈 바이트 하나를 넣는 패딩 문자이고, `e` 는 2바이트 실수다 (확인 필요).
- `@` 정렬은 칸 앞에만 패딩을 넣고 맨 끝에는 넣지 않는다 — 끝 정렬이 필요하면 `'0l'` 같은 0개 반복 문자를 붙이는 방법이 있다 (확인 필요).
- CPython 의 `struct` 모듈은 최근에 쓴 포맷 문자열을 내부에서 캐싱하므로, `Struct` 재사용의 이득은 캐시 조회를 건너뛰는 정도일 수 있다 (확인 필요).
- `unpack_from` 과 `pack_into` 는 `bytearray` 말고도 `memoryview` · `mmap` 같은 버퍼 프로토콜 객체를 받는다 (확인 필요).
- 길이가 정해지지 않은 큰 이진 구조를 다룰 때는 `ctypes` 구조체나 전용 직렬화 라이브러리를 쓰기도 한다 (확인 필요).
