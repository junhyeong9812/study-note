## 한눈에 — 쉽게 말하면

**재귀는 「극장에서 내가 몇 번째 줄인지 앞사람에게 묻기」다.**
나는 내 줄 번호를 모르니 앞사람에게 「당신은 몇 번째 줄이에요?」라고 묻는다.
앞사람도 모르니 또 앞사람에게 묻고, 질문은 맨 앞줄까지 전해진다.
맨 앞줄 사람은 묻지 않고 바로 「1번째」라고 답한다.
그 답이 뒤로 돌아오면서 한 사람씩 1을 더해, 마지막에 내가 답을 받는다.
재귀 함수도 똑같은 구조다.
함수가 더 작은 문제로 자기 자신을 부르고, 가장 작은 문제에서 멈추고, 답이 거꾸로 돌아오며 완성된다.

> **재귀** — 함수가 자기 자신을 더 작은 입력으로 다시 부르는 방식이다.\
> 예: `factorial(5)` 가 `factorial(4)` 를 부른다.

| 비유 | 실체 |
|---|---|
| 「몇 번째 줄이에요?」라는 질문 | 재귀 호출 `f(n - 1)` |
| 맨 앞줄 사람이 바로 답하기 | base case (`if n <= 1: return 1`) |
| 답을 기다리며 서 있는 사람들 | 호출 스택에 쌓인 프레임 |
| 돌아온 답에 1을 더해 넘기기 | 돌아온 값으로 남은 계산(`n * …`)을 끝내기 |
| 줄이 너무 길어 극장이 감당 못 함 | 재귀 한도 초과 · 스택 오버플로 |

```text
질문이 앞으로 간다 (펼침)              답이 뒤로 온다 (감김)
f(3) ──▶ f(2) ──▶ f(1)                f(1) = 1
                   │ base case         f(2) = 2 * 1 = 2
                   ▼                   f(3) = 3 * 2 = 6
             바로 1 을 돌려준다   ──▶
```

## 이 주제가 답하려는 질문

1. 재귀 함수는 무엇이 있어야 끝나고, 호출은 어떤 차례로 펼쳐졌다가 감기는가?
2. 꼬리 재귀란 무엇이고, Python 에서 꼬리 재귀가 왜 깊은 재귀를 구해 주지 못하는가?
3. 재귀 한도는 무엇이고, 한도를 올리는 것만으로 충분하지 않을 때 무엇으로 바꾸는가?
4. 분할 정복(머지 소트 · 빠른 거듭제곱 · 하노이 탑)은 재귀를 어떻게 쓰는가?

## 동작 방식

### (1) base case 와 recursive case

**언제 쓰나** — 문제를 「같은 모양의 더 작은 문제」로 줄일 수 있을 때 쓴다.
`n!` 은 `n * (n-1)!` 이므로 재귀로 그대로 옮겨 적을 수 있다.

> **base case** — 더 이상 자기 자신을 부르지 않고 바로 값을 돌려주는 종료 조건이다.\
> 예: `factorial` 의 `if n <= 1: return 1`.

> **recursive case** — 자기 자신을 더 작은 인자로 부르는 갈래다.\
> 예: `return n * factorial(n - 1)`.

```text
factorial(3)
  └─ n <= 1 ? 아니다 → 3 * factorial(2) 의 답을 기다린다
       └─ n <= 1 ? 아니다 → 2 * factorial(1) 의 답을 기다린다
            └─ n <= 1 ? 그렇다 → 1 을 돌려준다          (base case)
       ← 2 * 1 = 2 를 돌려준다
  ← 3 * 2 = 6 을 돌려준다
```

- `factorial(3)` 은 base case 가 아니므로 `factorial(2)` 를 부르고 곱셈을 미룬다.
- `factorial(2)` 도 같은 일을 하고 `factorial(1)` 을 부른다.
- `factorial(1)` 은 `n <= 1` 에 걸려 더 부르지 않고 `1` 을 돌려준다.
- 돌아온 값으로 미뤄 둔 곱셈이 안쪽부터 차례로 끝난다.
- 모든 재귀에는 base case 가 반드시 있어야 하고, 매 호출이 base case 쪽으로 다가가야 한다.
- 원본은 `factorial` 의 시간과 공간을 모두 O(n) 으로 본다(공간은 호출 스택 때문이다).
- `5!` 은 `120`, `10!` 은 `3628800` 이다.

### (2) 호출 스택 — 펼침과 감김

**언제 쓰나** — 재귀가 어떤 차례로 실행되는지 눈으로 확인하고 싶을 때 쓴다.
`factorial_trace` 는 깊이(`depth`)만큼 들여쓰기를 붙여 호출과 반환을 찍는다.

> **호출 스택** — 아직 끝나지 않은 함수 호출들을 쌓아 두는 곳이다.\
> 예: `factorial(3)` 이 `factorial(2)` 를 기다리는 동안 둘 다 스택에 있다.

> **프레임** — 호출 스택에 쌓이는 호출 하나분의 기록(지역 변수 · 돌아갈 자리)이다.\
> 예: `factorial(2)` 의 `n = 2` 는 그 프레임에 들어 있다.

```text
factorial_trace(n, depth)
  1) 들여쓰기("  " * depth) + "factorial(n)" 을 찍는다     ← 들어갈 때
  2) n <= 1 이면 같은 들여쓰기로 "-> 1" 을 찍고 1 을 돌려준다
  3) 아니면 factorial_trace(n - 1, depth + 1) 을 부른다
  4) 돌아오면 같은 들여쓰기로 "-> 결과" 를 찍는다          ← 나올 때

스택 모양 (n = 3 이라면)
  [f(3)] → [f(3) f(2)] → [f(3) f(2) f(1)] → [f(3) f(2)] → [f(3)] → []
           쌓인다(펼침) ─────────────────▶ 줄어든다(감김)
```

- 호출마다 `depth` 가 1 늘어 들여쓰기가 두 칸씩 깊어진다.
- 「factorial(n)」 줄은 들어가는 차례대로, 바깥쪽 호출부터 찍힌다.
- 「->」 줄은 나오는 차례대로, 가장 안쪽 호출부터 찍힌다.
- 한 호출이 찍는 두 줄(들어갈 때 · 나올 때)은 같은 들여쓰기를 쓴다.
- 그래서 출력은 오른쪽으로 파고들었다가 다시 왼쪽으로 돌아오는 꼴이 된다.

### (3) 꼬리 재귀와 반복문 변환

**언제 쓰나** — 재귀 호출이 함수의 마지막 동작이 되도록 다시 쓰면, 그 재귀를 `while` 로 기계적으로 옮길 수 있다.

> **꼬리 재귀** — 재귀 호출이 함수의 마지막 동작이라, 호출이 돌아온 뒤 할 계산이 남지 않는 재귀다.\
> 예: `return factorial_tail(n - 1, n * acc)`.

> **누적값(`acc`)** — 지금까지 계산한 중간 결과를 인자로 들고 다니는 변수다.\
> 예: `factorial_tail(3, 4)` 의 `4` 는 `4 * 1` 을 미리 곱해 둔 값이다.

> **TCO(꼬리 호출 최적화)** — 꼬리 호출이면 지금 프레임을 다시 써서 스택이 자라지 않게 하는 최적화다.\
> 예: TCO 가 있는 언어에서는 꼬리 재귀가 반복문처럼 스택을 하나만 쓴다.

```text
보통 재귀    factorial(4) = 4 * factorial(3)      ← 돌아온 뒤 곱셈이 남는다

꼬리 재귀    factorial_tail(4, 1)
           → factorial_tail(3, 4)
           → factorial_tail(2, 12)
           → factorial_tail(1, 24) → 24 를 그대로 돌려준다
             호출 뒤 할 일은 없지만, Python 은 프레임 넷을 모두 쌓는다

반복문       (n, acc) = (4, 1) → (3, 4) → (2, 12) → (1, 24) → 24
             while n > 1: acc *= n; n -= 1
```

- 보통 재귀는 `n *` 이라는 할 일을 남겨 두고 내려간다.
- 꼬리 재귀는 곱셈을 먼저 해서 `acc` 에 담아 넘기므로 돌아와서 할 일이 없다.
- 그러나 Python 은 TCO 를 하지 않으므로 꼬리 재귀도 호출마다 프레임을 하나씩 쌓는다.
- 따라서 Python 에서 꼬리 재귀는 「반복문으로 옮기기 쉬운 모양」일 뿐, 깊이 문제를 풀어 주지 않는다.
- 꼬리 재귀의 인자 `(n, acc)` 를 `while` 의 변수로 바꾸면 그대로 반복문이 된다.
- 두 방식 모두 `5!` 을 `120` 으로 계산한다.

### (4) 재귀 한도 — `sys.getrecursionlimit` · `sys.setrecursionlimit`

**언제 쓰나** — 재귀 깊이가 기본 한도를 넘을 수 있는 입력을 다룰 때 한도를 확인하거나 올린다.

> **재귀 한도** — 인터프리터가 허용하는 호출 스택 깊이의 최댓값이다.\
> 예: `sys.getrecursionlimit()` 이 돌려주는 값.

> **`RecursionError`** — 호출 깊이가 재귀 한도를 넘을 때 CPython 이 일으키는 예외다.\
> 예: base case 에 닿지 못하는 재귀가 끝없이 내려가다 이 예외로 멈춘다.

> **스택 오버플로** — 운영체제가 준 실제 스택 메모리가 바닥나는 일이다.\
> 예: 한도를 너무 높게 올린 뒤 아주 깊이 재귀하면 예외 대신 프로세스가 죽을 수 있다.

```text
sys.getrecursionlimit()       → 지금 한도를 읽는다 (CPython 기본값 1000)
sys.setrecursionlimit(10000)  → 한도를 10000 으로 바꾼다

깊이 ≤ 한도         : 정상 동작
깊이 > 한도         : RecursionError (예외 — 잡을 수 있다)
한도는 높지만
실제 스택이 모자람  : 스택 오버플로 (프로세스가 죽을 수 있다 — 한도가 막아 주지 못한다)
```

- 한도는 「몇 단계까지 허용할지」라는 숫자일 뿐, 실제 스택 메모리를 늘리지 않는다.
- 실제 스택 크기는 운영체제에 달려 있다.
- 그래서 한도만 크게 올리면 예외로 안전하게 멈추는 대신 스택 오버플로가 날 수 있다.
- 원본은 깊이가 10^5 이상이면 한도를 올리지 말고 반복문을 쓰라고 권한다.

### (5) 분할 정복 ① — 머지 소트

**언제 쓰나** — 문제를 반으로 나눠 각각 풀고, 두 답을 합쳐 전체 답을 만들 수 있을 때 쓴다.

> **분할 정복** — 분할(divide) → 정복(conquer) → 결합(combine) 세 단계로 푸는 방식이다.\
> 예: 머지 소트는 반으로 나눠 각각 정렬하고 병합한다.

```text
merge_sort([38, 27, 43, 3, 9, 82, 10])          mid = 7 // 2 = 3
├─ merge_sort([38, 27, 43])                     mid = 1
│    ├─ [38]                          (길이 1 → base case)
│    └─ [27, 43] → [27] | [43] → 병합 → [27, 43]
│    병합 → [27, 38, 43]
└─ merge_sort([3, 9, 82, 10])                   mid = 2
     ├─ [3, 9]  → 병합 → [3, 9]
     └─ [82, 10] → 병합 → [10, 82]
     병합 → [3, 9, 10, 82]
병합: [27, 38, 43] + [3, 9, 10, 82] → [3, 9, 10, 27, 38, 43, 82]

merge(left, right) 의 한 걸음
  left[i] <= right[j] 이면 left[i] 를 넣고 i += 1
  아니면                  right[j] 를 넣고 j += 1
  한쪽이 끝나면 남은 쪽(left[i:] · right[j:])을 통째로 이어 붙인다
```

- base case 는 `len(arr) <= 1` 이다 — 원소가 하나 이하면 이미 정렬돼 있다.
- `mid = len(arr) // 2` 로 나누고 `arr[:mid]` · `arr[mid:]` 를 각각 재귀로 정렬한다(분할 · 정복).
- `merge` 가 정렬된 두 리스트를 앞에서부터 비교하며 하나로 합친다(결합).
- `merge` 는 O(n), 머지 소트 전체는 O(n log n) 이다.
- 비교가 `<=` 라서 값이 같으면 왼쪽 것을 먼저 넣는다 — 같은 값의 원래 차례가 유지된다.

### (6) 분할 정복 ② — 빠른 거듭제곱

**언제 쓰나** — `base ** exp` 를 곱셈 `exp` 번이 아니라 O(log exp) 번으로 구하고 싶을 때 쓴다.

```text
power(3, 5)    5 는 홀수 → 3 * power(3, 4)
power(3, 4)    4 는 짝수 → half = power(3, 2); half * half
power(3, 2)    2 는 짝수 → half = power(3, 1); half * half
power(3, 1)    1 은 홀수 → 3 * power(3, 0)
power(3, 0)    0         → 1                      (base case)

돌아오며     power(3,1) = 3 * 1  = 3
             power(3,2) = 3 * 3  = 9
             power(3,4) = 9 * 9  = 81
             power(3,5) = 3 * 81 = 243
```

- `exp == 0` 이면 `1` 을 돌려준다(base case).
- 짝수면 `power(base, exp // 2)` 를 **한 번만** 불러 `half` 에 담고 `half * half` 로 제곱한다.
- 홀수면 `base` 하나를 떼어 내 `exp - 1`(짝수)로 줄인다.
- 짝수 단계마다 지수가 반으로 줄므로 호출 수는 O(log exp) 다.
- `2^10` 은 `1024`, `3^5` 는 `243` 이다.

### (7) 하노이 탑

**언제 쓰나** — 「n 개를 푸는 법」을 「n-1 개를 푸는 법」으로 설명할 수 있는 고전 문제다.
막대 셋(`source` · `target` · `auxiliary`)에서 원판을 한 장씩, 작은 것 위에 큰 것을 올리지 않고 옮긴다.

```text
hanoi(n, source, target, auxiliary)
  n == 1 이면  "원판 1: source -> target" 을 찍고 끝   (base case)
  아니면
    1) hanoi(n-1, source, auxiliary, target)   위 n-1 장을 보조 막대로
    2) "원판 n: source -> target"               가장 큰 원판을 목표로
    3) hanoi(n-1, auxiliary, target, source)   보조의 n-1 장을 목표로

예: hanoi(2, 'A', 'C', 'B')
    1) hanoi(1, A, B, C) → 원판 1: A -> B
    2)                     원판 2: A -> C
    3) hanoi(1, B, C, A) → 원판 1: B -> C
```

- 1)과 3)에서 막대의 역할(목표 · 보조)이 서로 바뀐다는 점이 핵심이다.
- 가장 큰 원판의 이동(2단계)은 정확히 가운데에서 한 번 일어난다.
- 이동 횟수는 `2^n - 1` 이다 — n=2 면 3번, n=3 이면 7번이다.
- 출력 줄은 두 칸 들여쓴 `  원판 {n}: {source} -> {target}` 꼴이다.

### (8) 재귀 → 반복 — 명시적 스택

**언제 쓰나** — 데이터가 깊어 재귀 깊이가 한도를 넘을 위험이 있을 때, 호출 스택 대신 리스트를 스택으로 써서 같은 일을 한다.

> **명시적 스택** — 호출 스택에 맡기던 「나중에 처리할 일」을 직접 리스트에 넣고 빼는 방식이다.\
> 예: `stack.pop()` 으로 다음 처리할 원소를 꺼낸다.

```text
flatten([1, [2, 3]])                재귀판: 리스트를 만나면 flatten(item) 을 불러 extend
flatten_iterative([1, [2, 3]])      반복판:
  stack = reversed → [[2, 3], 1]     (맨 끝이 다음에 꺼낼 것)
  pop 1        → result [1]
  pop [2, 3]   → reversed 로 넣기 → stack [3, 2]
  pop 2        → result [1, 2]
  pop 3        → result [1, 2, 3]
  stack 이 비면 끝
```

- `pop()` 은 리스트의 **맨 끝**을 꺼낸다 — 마지막에 넣은 것이 먼저 나온다.
- 그래서 원래 차례대로 꺼내려면 거꾸로(`reversed`) 넣어야 한다.
- 안쪽 리스트를 만나면 그 원소들을 다시 `reversed` 로 넣어, 재귀판이 그 자리에서 파고드는 것과 같은 차례를 만든다.
- 재귀판과 반복판은 같은 결과를 내지만, 반복판은 깊이가 커져도 호출 스택을 쌓지 않는다.

## 문법 — 형태와 규칙

```python
import sys

def total(xs):
    """리스트의 합 (재귀)"""
    if not xs:                      # base case: 빈 리스트
        return 0
    return xs[0] + total(xs[1:])    # recursive case: 한 칸 줄인 리스트

def total_tail(xs, acc=0):
    """꼬리 재귀 꼴"""
    if not xs:
        return acc
    return total_tail(xs[1:], acc + xs[0])

print(total([1, 2, 3]), total_tail([1, 2, 3]))
print(sys.getrecursionlimit())
sys.setrecursionlimit(5000)
```

- 재귀 함수는 보통 맨 위에 base case 를 두고, 그 아래에 recursive case 를 둔다.
- recursive case 의 인자는 base case 쪽으로 반드시 줄어들어야 한다(`n - 1` · `exp // 2` · `xs[1:]` · `arr[:mid]`).
- 누적값이나 깊이처럼 「처음엔 정해진 값」인 인자는 기본 인자(`acc=1` · `depth=0`)로 둔다.
- `sys.getrecursionlimit()` 은 현재 한도를 돌려주고, `sys.setrecursionlimit(n)` 은 한도를 `n` 으로 바꾼다 — `import sys` 가 필요하다.
- 리스트 슬라이스(`arr[:mid]`)는 새 리스트를 만든다.
- `isinstance(item, list)` 로 원소가 리스트인지 가려 재귀할지 정한다.
- `list.pop()` 은 맨 끝 원소를 꺼내고, `list.extend(reversed(x))` 는 `x` 를 거꾸로 이어 붙인다.

## 어디서 틀리나

### 1. base case 가 없거나 닿지 못한다

모든 재귀에는 base case 가 반드시 필요하다.
base case 가 있어도 인자가 그쪽으로 다가가지 않으면 없는 것과 같다.
예를 들어 base case 를 `n == 1` 로 쓰면 `n = 0` 은 `0 → -1 → -2 …` 로 영영 1 에 닿지 않는다.
이런 재귀는 끝없이 내려가다 한도를 넘어 `RecursionError` 로 멈춘다.
원본의 `n <= 1` 은 0 과 음수도 base case 로 받아 `1` 을 돌려준다(음수의 계승이 1 이라는 뜻은 아니다 — 그냥 멈출 뿐이다).

### 2. 꼬리 재귀로 쓰면 깊어도 괜찮다고 믿는다

Python 은 꼬리 재귀 최적화(TCO)를 지원하지 않는다.
`factorial_tail` 도 호출마다 프레임이 쌓이므로 깊이 한도는 `factorial` 과 똑같이 걸린다.
깊은 재귀는 반복문이나 명시적 스택으로 바꿔야 한다.

### 3. `sys.setrecursionlimit` 를 만능으로 쓴다

한도를 올릴 수는 있지만 실제 스택 크기는 운영체제에 달려 있다.
한도를 너무 크게 잡으면 `RecursionError` 대신 스택 오버플로로 프로세스가 죽을 위험이 있다.
원본은 깊이가 10^5 이상이면 반복문을 쓰라고 권한다.
이 「10^5」는 원본의 경험칙이고, 어디서도 보장하는 경계가 아니다.

### 4. 기본 한도를 「언제나 1000」이라고 외운다

원본은 기본 한도를 「보통 1000」이라 적는다.
이것은 CPython 의 기본값이고 실행 환경이나 앞선 `setrecursionlimit` 호출로 달라질 수 있다.
코드에서 한도가 중요하면 `sys.getrecursionlimit()` 로 읽어 확인한다.

### 5. 같은 하위 문제를 두 번 부른다

`power` 는 `half = power(base, exp // 2)` 로 **한 번** 부르고 `half * half` 로 재사용한다.
`power(base, exp // 2) * power(base, exp // 2)` 처럼 두 번 부르면 호출이 갈래마다 두 배로 늘어 O(log n) 의 이점이 사라진다(원본에 근거 없음 — 추론).

### 6. 머지 소트의 비교를 `<` 로 바꾼다

`merge` 가 `left[i] <= right[j]` 를 쓰기 때문에 같은 값이면 왼쪽 것이 먼저 나온다.
`<` 로 바꾸면 같은 값에서 오른쪽 것이 먼저 나와, 같은 값끼리의 원래 차례가 지켜지지 않는다(원본에 근거 없음 — 추론).
또 `merge_sort` 는 슬라이스로 리스트를 새로 만들어 넘기므로 원래 `arr` 를 바꾸지 않고 새 리스트를 돌려준다.
단, 길이 1 이하의 리스트를 바로 넣으면 base case 가 받은 리스트 그 객체를 그대로 돌려준다.

### 7. 원본의 복잡도 주석을 너무 그대로 믿는다

원본의 주장: `factorial` 은 시간 · 공간 모두 O(n) 이다.
왜 의심스러운가: 곱셈 한 번을 상수 시간으로 볼 때만 맞다.
Python 의 `int` 는 크기 제한이 없어 `n` 이 커지면 곱하는 수 자체가 커지고 곱셈 한 번의 비용도 늘어난다(확인 필요).
호출 횟수와 스택 깊이가 n 에 비례한다는 뜻으로 읽으면 맞다.

## 핵심 문장

1. **재귀는 base case 에서 멈추고, 호출은 펼쳐졌다가 안쪽부터 감기며 답을 완성한다.**
2. **꼬리 재귀는 반복문으로 옮기기 쉬운 모양일 뿐, Python 은 TCO 를 하지 않아 프레임이 그대로 쌓인다.**
3. **재귀 한도는 숫자일 뿐 실제 스택을 늘리지 않는다 — 깊은 재귀는 반복문이나 명시적 스택으로 바꾼다.**
4. **분할 정복은 나누고 · 각각 풀고 · 합친다 — 머지 소트는 반씩 나눠 병합하고, 빠른 거듭제곱은 절반의 답을 한 번 구해 제곱한다.**
5. **명시적 스택은 호출 스택이 하던 「나중에 할 일 기억하기」를 리스트가 대신 맡는다.**

## 용어 풀이

- **재귀** — 함수가 자기 자신을 더 작은 입력으로 다시 부르는 방식.
- **base case** — 자기 자신을 더 부르지 않고 바로 값을 돌려주는 종료 조건.
- **recursive case** — 자기 자신을 더 작은 인자로 부르는 갈래.
- **호출 스택** — 아직 끝나지 않은 함수 호출들을 쌓아 두는 곳.
- **프레임** — 호출 스택에 쌓이는 호출 하나분의 기록(지역 변수 · 돌아갈 자리).
- **펼침 · 감김** — 호출이 깊어지는 단계와, 값이 돌아오며 스택이 줄어드는 단계.
- **꼬리 재귀** — 재귀 호출이 마지막 동작이라 돌아온 뒤 할 계산이 없는 재귀.
- **누적값(`acc`)** — 중간 결과를 인자로 들고 다니는 변수.
- **TCO(꼬리 호출 최적화)** — 꼬리 호출에서 프레임을 다시 써 스택이 자라지 않게 하는 최적화.
- **재귀 한도** — 인터프리터가 허용하는 호출 깊이의 최댓값.
- **`RecursionError`** — 호출 깊이가 재귀 한도를 넘을 때 CPython 이 일으키는 예외.
- **스택 오버플로** — 운영체제가 준 실제 스택 메모리가 바닥나는 일.
- **분할 정복** — 분할 → 정복 → 결합 세 단계로 푸는 방식.
- **머지 소트** — 반으로 나눠 각각 정렬한 뒤 병합하는 O(n log n) 정렬.
- **병합(`merge`)** — 정렬된 두 리스트를 하나의 정렬된 리스트로 합치는 O(n) 단계.
- **빠른 거듭제곱** — 지수를 반씩 줄여 O(log n) 번 곱하는 거듭제곱.
- **하노이 탑** — n 장의 원판을 세 막대 사이로 옮기는 고전 재귀 문제(이동 `2^n - 1` 회).
- **명시적 스택** — 호출 스택 대신 직접 리스트에 넣고 빼며 처리할 일을 기억하는 방식.

## 더 들어가면

- 같은 하위 문제를 여러 번 부르는 재귀(예: 피보나치)는 `functools.lru_cache` 로 결과를 기억해 두면 호출 수가 크게 준다(확인 필요).
- 실제 스택 크기를 늘리려면 `threading.stack_size()` 로 크기를 정한 뒤 새 스레드에서 재귀를 돌리는 방법이 알려져 있다 — 플랫폼마다 허용 범위가 다르다(확인 필요).
- 최근 CPython 버전에서 재귀 한도가 Python 코드 호출과 C 수준 호출을 따로 다루도록 바뀌었다는 이야기가 있다 — 버전별 동작은 확인 필요.
- `sys.setrecursionlimit` 에 현재 깊이보다 낮은 값을 주면 오류가 날 수 있다(확인 필요).
- 표준 라이브러리 `sorted` · `list.sort` 는 머지 소트 계열인 Timsort 를 쓰는 것으로 알려져 있고, 같은 값의 차례를 지키는 안정 정렬이다(확인 필요).
- 하노이 탑의 `2^n - 1` 은 이동 횟수 T(n) = 2T(n-1) + 1, T(1) = 1 이라는 점화식을 풀어 나온다.
