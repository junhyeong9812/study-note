## 한눈에 — 쉽게 말하면

**`bisect` 는 「키 순서로 선 줄에 새 사람을 끼울 자리를 찾아 주는 안내원」이다.**
안내원은 줄 전체를 앞에서부터 훑지 않는다.
줄 한가운데 사람과 키를 견주어 보고, 앞쪽 절반인지 뒤쪽 절반인지를 정한다.
범위가 한 자리로 좁혀질 때까지 이 일을 되풀이한다.
새 사람과 키가 똑같은 사람들이 이미 있으면, 안내원은 「그 사람들 맨 앞」이나 「그 사람들 맨 뒤」 가운데 하나를 골라 알려 준다.
정렬된 파이썬 리스트에서 값이 들어갈 자리를 찾는 일도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 키 순서로 선 줄 | 정렬된 리스트 `a` |
| 새로 온 사람의 키 | 찾는 값 `x` |
| 한가운데 사람과 견주기 | 이진 탐색의 한 단계 |
| 「같은 키인 사람들 맨 앞」 | `bisect_left` |
| 「같은 키인 사람들 맨 뒤」 | `bisect_right` (= `bisect`) |
| 자리를 찾고 실제로 끼워 넣기 | `insort` |

```text
틈 번호:  0   1   2   3   4   5   6   7
          | 1 | 3 | 3 | 3 | 5 | 7 | 9 |
              ↑           ↑
     bisect_left(3) = 1   bisect_right(3) = 4
```

`bisect` 가 돌려주는 수는 원소의 번호가 아니라 원소 사이 **틈의 번호**다.
틈 `i` 는 `a[i]` 바로 앞자리다.

## 이 주제가 답하려는 질문

1. 정렬된 리스트에 값을 넣을 때, 정렬을 깨지 않으려면 어느 인덱스에 넣어야 하나?
2. 같은 값이 이미 여러 개 있으면, 그 무리의 앞에 넣나 뒤에 넣나?
3. 정렬된 리스트에 어떤 값이 있는지, 몇 개 있는지를 처음부터 훑지 않고 알 수 있나?
4. 「60 미만은 F, 60 이상 70 미만은 D …」처럼 구간마다 이름을 붙이는 일을 짧게 쓸 수 있나?

## 동작 방식

### (1) `bisect_left` 와 `bisect_right` — 두 경계

**언제 쓰나** — 정렬된 리스트에서 값 `x` 가 들어갈 자리를 알고 싶을 때 쓴다.
같은 값이 이미 있으면 그 무리의 앞(`left`)과 뒤(`right`) 가운데 어느 쪽을 원하는지에 따라 고른다.

```text
입력:  a = [1, 3, 3, 3, 5, 7, 9]

bisect_left(a, 3)   → 「값이 3 이상인 첫 자리」   → 인덱스 1 (첫 번째 3)
bisect_right(a, 3)  → 「값이 3 초과인 첫 자리」   → 인덱스 4 (5 가 있는 자리)
bisect_left(a, 4)   → 「값이 4 이상인 첫 자리」   → 인덱스 4
bisect_right(a, 4)  → 「값이 4 초과인 첫 자리」   → 인덱스 4
bisect(a, 3)        → bisect_right 와 같다       → 인덱스 4
```

- `bisect_left` 는 `x` 와 같은 값이 처음 나오는 자리를 준다 — 같은 값들의 왼쪽 끝 틈이다.
- `bisect_right` 는 `x` 와 같은 값이 끝난 바로 다음 자리를 준다 — 같은 값들의 오른쪽 끝 틈이다.
- 리스트에 없는 값(4)이면 같은 값의 무리가 없으므로 두 함수의 답이 같아진다.
- `bisect` 는 `bisect_right` 의 별칭이라 결과가 늘 같다.

> **별칭** — 같은 함수를 다른 이름으로도 부를 수 있게 한 것.\
> 예: `bisect.bisect` 는 `bisect.bisect_right` 와 같은 함수다.

이 두 함수는 C++ 표준 라이브러리의 이름으로 하면 `bisect_left` 가 `lower_bound`, `bisect_right` 가 `upper_bound` 에 해당한다.

> **lower_bound** — 정렬된 범위에서 「값이 x 이상인 첫 위치」를 돌려주는 C++ 함수.\
> 예: `[1, 3, 3, 5]` 에서 3 의 lower_bound 는 1 이다.

> **upper_bound** — 정렬된 범위에서 「값이 x 초과인 첫 위치」를 돌려주는 C++ 함수.\
> 예: `[1, 3, 3, 5]` 에서 3 의 upper_bound 는 3 이다.

### (2) 이진 탐색 — 왜 빠른가

**언제 쓰나** — 리스트가 길수록 이 원리가 효과를 낸다.
앞에서부터 하나씩 견주는 방법은 원소 수에 비례해 오래 걸리지만, 이진 탐색은 매번 범위를 반으로 줄인다.

```text
bisect_left([1, 3, 3, 3, 5, 7, 9], 3) 을 손으로 따라가 본 것 (설명용 흐름)

범위 lo=0, hi=7   mid=3  a[3]=3  「3 < 3」 아님  → hi=3
범위 lo=0, hi=3   mid=1  a[1]=3  「3 < 3」 아님  → hi=1
범위 lo=0, hi=1   mid=0  a[0]=1  「1 < 3」 맞음  → lo=1
범위 lo=1, hi=1   범위가 비었다                  → 1 을 돌려준다
```

- 한가운데 `mid` 의 값이 `x` 보다 작으면 답은 `mid` 보다 오른쪽에 있으므로 `lo` 를 `mid+1` 로 옮긴다.
- 그렇지 않으면 답은 `mid` 이하에 있으므로 `hi` 를 `mid` 로 옮긴다.
- 범위가 한 번에 반씩 줄어서, 원소가 `n` 개면 대략 `log₂ n` 번만 견준다.
- 이 견주기는 「리스트가 정렬되어 있다」는 전제 위에서만 맞는 답을 낸다.

> **이진 탐색** — 정렬된 범위를 매번 반으로 나눠 한쪽을 버리며 찾는 방법.\
> 예: 1~100 사이 숫자 맞히기에서 늘 50, 25, … 처럼 가운데를 부르는 것.

> **O(log n)** — 원소 수가 두 배가 될 때 일이 한 단계만 느는 비용.\
> 예: 원소 1,000 개에서 약 10 번, 1,000,000 개에서 약 20 번 견준다.

원본 팁은 「`bisect` 는 C 로 구현되어 있어 순수 Python 으로 짠 이진 탐색보다 빠르다」고 적는다.
이것은 CPython 이라는 구현에 대한 이야기다 — 아래 「구현 세부사항 대 언어 보장」을 본다.

### (3) `insort` — 자리를 찾아 끼워 넣기

**언제 쓰나** — 리스트를 늘 정렬된 상태로 두면서 값을 하나씩 넣을 때 쓴다.
넣을 때마다 `sort()` 를 다시 부를 필요가 없다.

```text
data = [1, 3, 5, 7, 9]

insort(data, 4)        자리 찾기: bisect_right(data, 4) = 2  → 2 에 끼움
                       → [1, 3, 4, 5, 7, 9]
insort_left(data, 4)   자리 찾기: bisect_left(data, 4) = 2   → 2 에 끼움
                       → [1, 3, 4, 4, 5, 7, 9]
```

- `insort` 는 `insort_right` 와 같다 — `bisect_right` 로 자리를 찾는다.
- `insort_left` 는 `bisect_left` 로 자리를 찾는다 — 같은 값이 있으면 그 앞에 들어간다.
- 정수처럼 같은 값이 서로 구별되지 않으면, 둘 다 넣고 난 리스트는 똑같아 보인다.
- 비용은 두 부분이다: 자리 찾기 O(log n) + 끼워 넣기 O(n).
- 끼워 넣을 때 뒤쪽 원소를 한 칸씩 밀어야 해서 끼워 넣기가 O(n) 이다.

> **O(n)** — 원소 수에 비례해 늘어나는 비용.\
> 예: 원소가 두 배면 밀어야 할 원소도 대략 두 배다.

그래서 삽입이 아주 잦으면 탐색이 빨라도 전체는 느리다.
원본 팁은 이럴 때 `SortedContainers` 라이브러리를 고려하라고 권한다.

> **SortedContainers** — 정렬된 상태를 유지하는 컨테이너를 제공하는 바깥(서드파티) 파이썬 라이브러리.\
> 예: 값을 아주 자주 넣고 빼면서 정렬을 유지해야 할 때 후보가 된다.

### (4) 값 검색 — 위치를 찾은 뒤 두 번 확인한다

**언제 쓰나** — 정렬된 리스트에 `target` 이 있는지, 있으면 몇 번째인지 알고 싶을 때 쓴다.

```text
nums = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]

target=23:  i = bisect_left(nums, 23) = 5
            i < len(nums) (5 < 10) ✓  nums[5] == 23 ✓  → 5
target=25:  i = bisect_left(nums, 25) = 6
            i < len(nums) (6 < 10) ✓  nums[6] == 38 ≠ 25  → -1
```

- `bisect_left` 는 값이 **있든 없든** 들어갈 자리를 준다 — 자리만으로는 있는지 모른다.
- 그래서 그 자리의 값이 `target` 과 같은지 견준다.
- `target` 이 리스트의 모든 값보다 크면 `i` 가 `len(nums)` 가 된다.
- 그 자리는 리스트 바깥이라 `nums[i]` 를 읽으면 `IndexError` 가 난다 — 그래서 `i < len(...)` 을 먼저 본다.
- `and` 는 앞 조건이 거짓이면 뒤를 계산하지 않으므로, 이 순서가 안전장치가 된다.

### (5) 개수 세기 — 두 경계의 차

**언제 쓰나** — 정렬된 리스트에서 특정 값이 몇 개인지 알고 싶을 때 쓴다.

```text
data = [1, 2, 2, 2, 3, 4, 4, 5]

target=2:  left=1, right=4  → 4 - 1 = 3
target=4:  left=5, right=7  → 7 - 5 = 2
target=6:  left=8, right=8  → 8 - 8 = 0
```

- `bisect_left` 는 그 값 무리의 시작 틈, `bisect_right` 는 끝 틈이다.
- 두 틈 사이에 들어 있는 원소 수가 곧 그 값의 개수다.
- 없는 값은 두 틈이 겹치므로 0 이 나온다.
- 이진 탐색 두 번이라 비용은 O(log n) 이다.

### (6) 성적 등급 — 구간에 이름 붙이기

**언제 쓰나** — 연속된 값을 몇 개의 구간으로 나눠 이름을 붙일 때 쓴다.
원본 팁에 따르면 이 패턴은 공식 문서의 대표 예제다.

```text
breakpoints = [60, 70, 80, 90]
grades      = 'F  D  C  B  A'
인덱스          0  1  2  3  4

        F      |  D  |  C  |  B  |   A
   ────────────60────70────80────90──────
score=77  → bisect([60,70,80,90], 77) = 2  → grades[2] = 'C'
score=70  → bisect([60,70,80,90], 70) = 2  → grades[2] = 'C'
```

- 분기점 리스트에서 점수가 들어갈 틈 번호를 찾고, 그 번호로 등급 문자열을 인덱싱한다.
- 분기점이 4 개면 틈은 0~4 로 5 개이고, 등급 문자도 5 개다.
- `bisect`(= `bisect_right`)를 쓰므로 분기점과 **같은** 점수는 분기점의 오른쪽 틈으로 간다.
- 그래서 70점은 D 가 아니라 C, 90점은 A 다 — 「70 이상 80 미만이 C」라는 규칙과 맞는다.

> **분기점** — 구간이 바뀌는 경계 값.\
> 예: `[60, 70, 80, 90]` 의 60 은 F 와 D 를 가른다.

### (7) 정렬을 유지하는 클래스 — `SortedList`

**언제 쓰나** — 위 패턴들을 한 곳에 모아, 넣고 빼고 찾는 일을 늘 정렬된 상태로 하고 싶을 때 쓴다.

```text
add(5) → [5]
add(2) → [2, 5]
add(8) → [2, 5, 8]
add(1) → [1, 2, 5, 8]
...
5 in sl  → __contains__(5) → bisect_left 로 자리 찾고 값 확인 → True
remove(5) → bisect_left 로 자리 찾고 값 확인 → pop(자리)
```

- `add` 는 `insort` 로 넣으므로 아무 순서로 넣어도 내부 리스트는 정렬된다.
- `remove` 는 (4)의 검색 패턴으로 자리를 확인한 뒤 `pop(i)` 로 뺀다 — 값이 없으면 아무 일도 하지 않는다.
- `__contains__` 를 정의했으므로 `5 in sl` 이 이 메서드를 부른다.
- `__repr__` 은 객체를 출력할 때 `SortedList([...])` 꼴의 글자를 돌려준다.
- 보통 리스트의 `in` 은 앞에서부터 하나씩 견주지만, 이 클래스의 `in` 은 이진 탐색으로 O(log n) 에 답한다.

> **`__contains__`** — `x in obj` 를 계산할 때 파이썬이 부르는 특수 메서드.\
> 예: `5 in sl` 은 `sl.__contains__(5)` 를 부른다.

> **`__repr__`** — 객체를 글자로 나타낼 때 쓰이는 특수 메서드.\
> 예: f-string 안의 `{sl}` 이 `SortedList([1, 2])` 로 찍힌다(이 클래스에 `__str__` 이 없어서 `__repr__` 이 쓰인다).

## 문법 — 형태와 규칙

```python
import bisect

a = [10, 20, 20, 30]
i = bisect.bisect_left(a, 20)    # 20 이 처음 나오는 자리
j = bisect.bisect_right(a, 20)   # 20 무리가 끝난 바로 다음 자리
k = bisect.bisect(a, 20)         # bisect_right 와 같다

bisect.insort(a, 25)             # 정렬을 지키며 25 를 넣는다 (insort_right 와 같다)
bisect.insort_left(a, 20)        # 같은 값이 있으면 그 앞에 넣는다

count = j - i                    # 20 의 개수
```

- `bisect_left(a, x)` — `a` 에서 `x` 이상인 첫 인덱스를 돌려준다.
- `bisect_right(a, x)` · `bisect(a, x)` — `a` 에서 `x` 초과인 첫 인덱스를 돌려준다.
- 돌려주는 값의 범위는 `0` 부터 `len(a)` 까지다 — `len(a)` 는 「맨 끝 뒤」라는 뜻이다.
- `insort(a, x)` · `insort_right(a, x)` — `bisect_right` 자리에 `x` 를 넣는다. 반환값 없이 `a` 를 직접 바꾼다.
- `insort_left(a, x)` — `bisect_left` 자리에 `x` 를 넣는다.
- 모든 함수는 `a` 가 오름차순으로 정렬되어 있다고 **가정**한다.
- 값이 있는지는 `i < len(a) and a[i] == x` 로 따로 확인한다.

## 어디서 틀리나

### 1. 정렬되지 않은 리스트에 쓴다

`bisect` 함수들은 리스트가 정렬되어 있는지 검사하지 않는다.
정렬되지 않은 리스트를 넘겨도 오류 없이 어떤 수를 돌려주지만, 그 수에는 의미가 없다.
`insort` 로 넣으면 이미 깨진 순서가 더 엉킨다.

### 2. 돌려받은 자리를 바로 인덱싱한다

`bisect_left(a, x)` 는 `len(a)` 를 돌려줄 수 있다.
이 값으로 `a[i]` 를 읽으면 `IndexError` 가 난다.
`binary_search` 가 `i < len(sorted_list)` 를 먼저 보는 까닭이다.

### 3. 「자리」를 「찾았다」로 착각한다

`bisect_left` 는 값이 없어도 들어갈 자리를 준다.
`bisect_left(nums, 25)` 는 6 이지만 `nums[6]` 은 38 이다.
있는지 알려면 그 자리의 값을 반드시 견줘야 한다.

### 4. `left` 와 `right` 를 바꿔 쓴다

경계 값을 어느 쪽에 붙일지가 바뀐다.
등급 예제에서 `bisect_left` 를 쓰면 70점은 `[60, 70, 80, 90]` 의 1 번 틈으로 가서 D 가 된다.
「이상」으로 끊는 구간이면 `bisect_right`(= `bisect`)가 맞다.

### 5. `bisect` 가 `left` 인 줄 안다

이름에 방향이 없어 헷갈리지만 `bisect` 는 `bisect_right` 의 별칭이다.
`insort` 도 `insort_right` 와 같다.

### 6. `insort` 를 빠른 삽입으로 여긴다

탐색은 O(log n) 이지만 끼워 넣기는 O(n) 이다.
삽입이 빈번하면 이 O(n) 이 전체 비용을 좌우한다.
원본 팁은 이때 `SortedContainers` 라이브러리를 고려하라고 한다.

### 7. 이진 탐색을 직접 짠다

경계 조건(`<` 와 `<=`, `mid` 와 `mid+1`)을 하나만 틀려도 무한 반복이나 한 칸 어긋남이 생긴다.
원본 팁은 `bisect` 가 C 로 구현되어 있어 순수 Python 으로 짠 이진 탐색보다 빠르다고 적는다(CPython 기준).
가능하면 직접 짜지 말고 `bisect` 를 쓴다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| `bisect` 는 C 로 구현되어 순수 Python 이진 탐색보다 빠르다 | CPython 구현의 이야기다. 언어가 보장하지 않으며, 다른 구현(예: PyPy)에서 어떤지는 원본에 근거가 없다 (확인 필요) |
| `insort` 의 끼워 넣기가 O(n) 이다 | 리스트가 연속된 배열로 구현된 데 따른 결과다. 언어 명세가 정한 값이 아니라 구현(CPython 리스트)의 성질이다 |
| `bisect_left` 는 x 이상인 첫 자리, `bisect_right` 는 x 초과인 첫 자리를 준다 | `bisect` 모듈의 공개 동작이다 — 구현이 바뀌어도 지켜지는 약속이다 |
| `bisect` 는 `bisect_right`, `insort` 는 `insort_right` 의 별칭이다 | `bisect` 모듈의 공개 API 다 |
| 리스트가 정렬되었는지 검사하지 않는다 | 모듈이 정렬을 「가정」한다는 약속에서 나온 것이다 — 검사해 준다는 보장이 없다 |
| `x in obj` 가 `obj.__contains__(x)` 를 부른다 | 파이썬 언어(데이터 모델)가 보장한다 |
| 보통 리스트의 `in` 은 앞에서부터 하나씩 견준다 | 시퀀스의 `in` 의미가 「원소 중 같은 것이 있나」로 정해져 있어, 정렬을 모르는 리스트는 훑을 수밖에 없다 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 정렬된 리스트에서 값이 있는지 찾기 | `bisect_left` + 값 확인 | 앞에서부터 훑기(`in`, `index`) |
| 정렬된 리스트에서 특정 값의 개수 | `bisect_right - bisect_left` | `list.count`(전체를 훑는다) |
| 점수 → 등급처럼 구간에 이름 붙이기 | `bisect(분기점, 값)` 로 인덱싱 | 길게 늘어놓은 `if/elif` |
| 정렬을 지키며 가끔 하나씩 넣기 | `insort` | 넣을 때마다 `append` 후 `sort()` |
| 삽입 · 삭제가 아주 잦은 정렬 컨테이너 | `SortedContainers` 같은 라이브러리 | `insort` 반복(O(n) 삽입이 쌓인다) |
| 정렬되지 않은 리스트 | 먼저 정렬하거나 다른 방법 | `bisect` 함수들 |

## 핵심 문장

1. **`bisect` 함수들은 정렬된 리스트에서 값이 들어갈 「틈 번호」를 이진 탐색으로 O(log n) 에 찾는다.**
2. **`bisect_left` 는 같은 값 무리의 앞, `bisect_right`(= `bisect`)는 뒤를 가리킨다** — 각각 `lower_bound`, `upper_bound` 에 해당한다.
3. **자리는 존재가 아니다** — 검색은 `i < len(a) and a[i] == x` 로 확인하고, 개수는 `right - left` 로 센다.
4. **`insort` 는 O(log n) 탐색 + O(n) 삽입이다** — 삽입이 잦으면 다른 자료구조를 고려한다.
5. **분기점 리스트 + `bisect` + 인덱싱은 구간에 이름을 붙이는 짧은 패턴이다.**

## 용어 풀이

- **이진 탐색** — 정렬된 범위를 반씩 나눠 한쪽을 버리며 찾는 방법.
- **정렬된 리스트** — 원소가 작은 것부터 큰 것 순서(오름차순)로 놓인 리스트.
- **틈 번호(삽입 위치)** — 원소 사이의 자리 번호. 틈 `i` 는 `a[i]` 바로 앞이며 `0` ~ `len(a)` 까지 있다.
- **`bisect_left`** — `x` 이상인 첫 인덱스를 돌려주는 함수.
- **`bisect_right` / `bisect`** — `x` 초과인 첫 인덱스를 돌려주는 함수(둘은 같은 함수다).
- **`insort` / `insort_right` / `insort_left`** — 정렬을 지키며 값을 리스트에 직접 넣는 함수.
- **lower_bound / upper_bound** — C++ 에서 「x 이상인 첫 위치」 · 「x 초과인 첫 위치」를 주는 함수.
- **별칭** — 같은 함수를 부르는 다른 이름.
- **O(log n)** — 원소 수가 두 배가 될 때 한 단계만 느는 비용.
- **O(n)** — 원소 수에 비례하는 비용.
- **분기점** — 구간이 바뀌는 경계 값.
- **`__contains__`** — `in` 연산자가 부르는 특수 메서드.
- **`__repr__`** — 객체를 글자로 나타내는 특수 메서드.
- **SortedContainers** — 정렬을 유지하는 컨테이너를 주는 서드파티 라이브러리.

## 더 들어가면

- `bisect` 함수들은 `lo` · `hi` 인자로 탐색 범위를 리스트의 일부로 좁힐 수 있다 (확인 필요).
- 파이썬 3.10 부터 `bisect` · `insort` 함수에 `key` 인자가 생겨, 객체의 특정 필드를 기준으로 찾을 수 있다고 알려져 있다 (확인 필요).
- 연습 파일 이름을 `bisect.py` 로 지으면, 그 폴더에서 `import bisect` 가 표준 모듈 대신 그 파일을 가져올 수 있다 — 파일 이름은 다르게 짓는 편이 안전하다 (확인 필요).
- `sortedcontainers` 라이브러리의 `SortedList` 는 내부를 여러 작은 리스트로 나눠 삽입 비용을 줄이는 방식이라고 알려져 있다 (확인 필요).
- 가장 작은 값만 자주 꺼내면 된다면 정렬 리스트보다 `heapq`(힙)가 맞는 경우가 많다 (확인 필요).
- 내림차순 리스트에는 `bisect` 를 그대로 쓸 수 없다 — 값의 부호를 뒤집어 저장하거나 `key` 를 쓰는 방법이 있다 (확인 필요).
