## 한눈에 — 쉽게 말하면

**투 포인터와 슬라이딩 윈도우는 「두 손가락으로 책꽂이 훑기」다.**
책꽂이에 책이 한 줄로 꽂혀 있고, 왼손 손가락과 오른손 손가락을 책 위에 하나씩 올린다.
두 손가락은 앞으로만 움직이고 뒤로 돌아가지 않는다.
그래서 책꽂이 전체를 한 번만 훑으면 일이 끝난다.
배열을 다루는 두 인덱스 변수도 똑같은 구조다.

| 비유 | 실체 |
|---|---|
| 책꽂이의 책 한 권 | 배열(또는 문자열)의 원소 하나 |
| 두 손가락 | 인덱스 변수 두 개(`left`/`right`, `slow`/`fast`) |
| 두 손가락 사이에 낀 책들 | 윈도우 — 연속 구간 `arr[left..right]` |
| 손가락이 뒤로 가지 않는다 | 각 포인터가 한 방향으로만 움직인다 → 전체 O(n) |
| 지금까지 훑은 책 수를 적은 쪽지 | 부분합(누적합)과 그 빈도를 적은 해시맵 |

```text
양끝 타입                     같은 방향 타입
 L→               ←R           slow→   fast→
[1, 3, 5, 7, 9, 11]           [1, 1, 2, 2, 3, ...]
 양끝에서 가운데로 좁힌다        둘 다 오른쪽으로 간다 (fast 가 앞선다)
```

> **투 포인터** — 배열 위의 인덱스 두 개를 규칙에 따라 움직여 이중 반복을 한 번의 훑기로 바꾸는 기법이다.\
> 예: 정렬 배열의 양끝에서 출발해 합이 목표보다 작으면 왼쪽을, 크면 오른쪽을 옮긴다.

> **슬라이딩 윈도우** — 연속 구간(윈도우)의 양 끝을 밀면서 구간의 합 · 조건을 다시 계산하지 않고 갱신하는 기법이다.\
> 예: 크기 3 윈도우를 한 칸 밀 때 들어온 원소를 더하고 나간 원소를 뺀다.

## 이 주제가 답하려는 질문

1. 모든 쌍 · 모든 구간을 보는 O(n²) 이중 반복을 어떻게 O(n) 한 번 훑기로 줄이나?
2. 포인터를 양끝에서 좁힐 때와 같은 방향으로 보낼 때는 각각 언제인가?
3. 연속 구간의 합이나 「중복 없음」 같은 조건을 구간이 움직일 때마다 어떻게 싸게 유지하나?
4. 윈도우로 풀 수 없는 「합이 정확히 k 인 구간의 개수」는 무엇으로 푸나?

## 동작 방식

### (1) 양끝 투 포인터 — 정렬 배열에서 두 수의 합

**언제 쓰나** — 정렬된 배열에서 합이 `target` 인 두 원소를 찾을 때 쓴다.
정렬이 필수다.

```text
arr = [1, 3, 5, 7, 9, 11], target = 16   (손으로 따라간 것 — 실행 아님)

 L                R
[1, 3, 5, 7, 9, 11]   1+11=12 < 16  → L 오른쪽으로
    L             R
[1, 3, 5, 7, 9, 11]   3+11=14 < 16  → L 오른쪽으로
       L          R
[1, 3, 5, 7, 9, 11]   5+11=16 == 16 → (2, 5) 반환
```

- 합 `s` 를 `target` 과 비교한다.
- 같으면 `(left, right)` 를 돌려준다.
- `s < target` 이면 `left += 1` 로 합을 키운다.
- `s > target` 이면 `right -= 1` 로 합을 줄인다.
- `left < right` 가 깨지면 쌍이 없으므로 `None` 을 돌려준다.

왜 버려도 되나:
`s < target` 이면 `arr[left]` 는 남은 원소 중 가장 큰 `arr[right]` 와 짝지어도 모자란다.
배열이 정렬돼 있으니 다른 어떤 짝과도 모자라고, 그래서 `arr[left]` 를 후보에서 버릴 수 있다.
반대로 `s > target` 이면 `arr[right]` 는 가장 작은 `arr[left]` 와도 넘치므로 버릴 수 있다.
매 걸음 후보가 하나씩 줄고 포인터가 서로 만나면 끝나므로 시간은 O(n)이다.

### (2) 같은 방향 투 포인터 — 중복 제거(slow/fast)

**언제 쓰나** — 배열을 제자리에서 걸러 낼 때 쓴다.
`fast` 는 읽는 위치, `slow` 는 결과를 쓸 마지막 위치다.

```text
[1, 1, 2, 2, 3, ...]   slow=0 (값 1)
 fast=1: 1 == 1  → 아무것도 안 함
 fast=2: 2 != 1  → slow=1, arr[1]=2   → [1, 2, 2, 2, 3, ...]
 fast=3: 2 == 2  → 아무것도 안 함
 fast=4: 3 != 2  → slow=2, arr[2]=3   → [1, 2, 3, 2, 3, ...]
 ...
반환값 slow+1 = 앞쪽 유효 구간의 길이
```

- 빈 배열이면 0 을 돌려준다.
- `fast` 는 1부터 끝까지 모든 원소를 본다.
- `arr[fast] != arr[slow]` 일 때만 `slow` 를 한 칸 옮기고 그 자리에 새 값을 쓴다.
- 결과는 `arr[:slow+1]` 이고 새 리스트를 만들지 않는다 — 시간 O(n), 추가 공간 O(1).
- 「직전에 남긴 값과 다른가」만 비교하므로 같은 값이 붙어 있는(정렬된) 배열을 전제로 한다.

### (3) 고정 크기 슬라이딩 윈도우 — 크기 k 구간의 최대 합

**언제 쓰나** — 길이가 정해진 연속 구간마다 합 · 평균 같은 값을 구할 때 쓴다.

```text
arr = [2, 1, 5, 1, 3, 2], k = 3   (손으로 따라간 것 — 실행 아님)

[2, 1, 5] 1  3  2    첫 합 = 8
 2 [1, 5, 1] 3  2    8 + 1 - 2 = 7
 2  1 [5, 1, 3] 2    7 + 3 - 1 = 9   ← 최대
 2  1  5 [1, 3, 2]   9 + 2 - 5 = 6
```

- 첫 윈도우의 합만 `sum(arr[:k])` 로 직접 구한다.
- 그다음은 `window_sum += arr[i] - arr[i - k]` 로 들어온 원소를 더하고 나간 원소를 뺀다.
- 윈도우마다 k 개를 다시 더하지 않으므로 O(n·k) 가 O(n) 이 된다.

### (4) 가변 크기 슬라이딩 윈도우 — 합이 target 이상인 최소 길이

**언제 쓰나** — 「조건을 만족하는 가장 짧은(긴) 연속 구간」을 찾을 때 쓴다.
`right` 로 늘리다가 조건이 맞으면 `left` 로 줄인다.

```text
arr = [2, 3, 1, 2, 4, 3], target = 7   (손으로 따라간 것 — 실행 아님)

right=3: 합 8 ≥ 7 → 길이 4 기록, 2 를 빼고 left=1 (합 6)
right=4: 합 10 ≥ 7 → 길이 4, 3 빼고 left=2 (합 7) → 길이 3, 1 빼고 left=3 (합 6)
right=5: 합 9 ≥ 7 → 길이 3, 2 빼고 left=4 (합 7) → 길이 2, 4 빼고 left=5 (합 3)
최소 길이 2 ([4, 3])
```

- 바깥 `for` 가 `right` 를 끝까지 한 번 옮긴다.
- 안쪽 `while` 은 합이 `target` 이상인 동안 길이를 기록하고 `left` 를 옮긴다.
- `while` 이 안에 있어도 `left` 는 전체 실행 동안 배열 길이만큼만 움직인다.
- 각 인덱스는 들어올 때 한 번, 나갈 때 한 번, 최대 두 번 방문된다 → O(n).
- 한 번도 조건을 못 맞추면 `min_len` 이 `float('inf')` 로 남고, 이때 0 을 돌려준다.
- 「원소를 빼면 합이 줄어든다」를 믿고 줄이므로 양수 배열을 전제로 한다(「어디서 틀리나 3」).

### (5) 중복 없는 최장 부분 문자열 — 마지막 위치로 점프

**언제 쓰나** — 문자열에서 같은 문자가 두 번 나오지 않는 가장 긴 연속 구간을 찾을 때 쓴다.

```text
s = "abba"   (손으로 따라간 것 — 실행 아님)

right=0 'a': seen={a:0}            윈도우 "a"
right=1 'b': seen={a:0,b:1}        윈도우 "ab"   (길이 2)
right=2 'b': seen[b]=1 ≥ left 0 → left=2, 윈도우 "b"
right=3 'a': seen[a]=0 < left 2 → 점프하지 않음, 윈도우 "ba"
```

- `seen` 은 문자 → 마지막으로 나온 인덱스를 담는 dict 다.
- 지금 문자가 윈도우 안에서 이미 나왔으면 `left` 를 그 위치 다음으로 한 번에 점프시킨다.
- `seen[char] >= left` 검사는 「그 기록이 지금 윈도우 안인가」를 본다.
- 이 검사가 없으면 위 그림의 `right=3` 에서 `left` 가 1 로 뒤로 돌아가 윈도우 "bba" 가 된다 — 중복이 생긴다.
- 그 뒤 `seen[char] = right` 로 마지막 위치를 고치고, 길이가 최대를 넘으면 문자열과 길이를 기록한다.
- 결과는 `(문자열, 길이)` 튜플이고 시간은 O(n)이다.

### (6) 부분합 + 해시맵 — 합이 정확히 target 인 구간의 개수

**언제 쓰나** — 구간 합이 「이상」이 아니라 「정확히」 k 인 구간의 **개수**를 셀 때 쓴다.

> **부분합(prefix sum)** — 배열 앞에서부터 지금 원소까지 더한 누적합이다.\
> 예: `[1, 2, 1]` 의 부분합은 1, 3, 4 이다.

구간 `i..j` 의 합은 「j 까지의 누적합 − i 앞까지의 누적합」이다.
그래서 지금 누적합이 `current_sum` 일 때 합이 `target` 인 구간이 여기서 끝나려면, 앞에 누적합 `current_sum - target` 이 있었어야 한다.
그 누적합이 몇 번 나왔는지를 dict 에 세어 두면 한 번 훑기로 개수를 센다.

```text
arr = [1, 2, 1], target = 3   (손으로 따라간 것 — 실행 아님)

시작              prefix_count = {0:1}
num=1  누적 1   1-3=-2 없음           {0:1, 1:1}
num=2  누적 3   3-3= 0 있음(1번) → +1  {0:1, 1:1, 3:1}     구간 [1,2]
num=1  누적 4   4-3= 1 있음(1번) → +1  {..., 4:1}          구간 [2,1]
개수 2
```

- `prefix_count = {0: 1}` 은 「아무것도 더하지 않은 빈 앞부분의 합 0」을 한 번 센 것이다.
- 이것이 있어야 배열 맨 앞(인덱스 0)부터 시작하는 구간이 세어진다.
- 개수를 더한 **뒤에** 지금 누적합의 빈도를 올린다.
- 음수가 섞여도 동작한다 — 윈도우를 줄이는 판단이 없기 때문이다.

고정 윈도우와의 관계: 크기 k 윈도우의 합은 「`i+k` 까지의 누적합 − `i` 까지의 누적합」과 같다.
(3)의 「더하고 빼기」는 이 차이를 매번 한 칸씩 갱신하는 것이다.

### (7) 3Sum — 하나 고정 + 양끝 투 포인터

**언제 쓰나** — 합이 0 인 세 수의 조합을 중복 없이 모두 찾을 때 쓴다.

```text
정렬 → [-4, -1, -1, 0, 1, 2]
 i 를 하나 고정 → 나머지 [i+1 .. 끝] 에서 (1) 의 양끝 투 포인터로 합 -nums[i] 찾기
 i 가 앞과 같은 값이면 건너뜀
 답을 찾으면 left·right 가 같은 값인 동안 건너뛰고 둘 다 한 칸 이동
```

- `nums.sort()` 로 먼저 정렬한다 — 양끝 투 포인터의 전제를 만든다.
- `i` 를 고정하고 안쪽에서 양끝 투 포인터를 돌린다 — 바깥 n번 × 안쪽 O(n) = O(n²).
- 같은 조합이 두 번 들어가지 않게 `i` 의 중복, 그리고 답을 찾은 뒤 `left`/`right` 의 중복을 건너뛴다.
- 결과는 `[a, b, c]` 리스트의 리스트다.

## 문법 — 형태와 규칙

```python
# 세 가지 뼈대 (직접 쓴 최소 예제)
left, right = 0, len(a) - 1          # 양끝
while left < right:
    ...                              # 비교 후 left += 1 또는 right -= 1

slow = 0                             # 같은 방향
for fast in range(1, len(a)):
    if a[fast] != a[slow]:
        slow += 1; a[slow] = a[fast]

left = 0                             # 가변 윈도우
for right, x in enumerate(a):
    ...                              # x 를 윈도우에 넣는다
    while 조건:                      # 조건이 맞는 동안 줄인다
        left += 1

count = {0: 1}                       # 부분합 빈도
count[s] = count.get(s, 0) + 1
```

- `left, right = 0, len(a) - 1` 은 튜플 풀기로 두 변수를 한 줄에 정한다.
- `enumerate(s)` 는 `(인덱스, 값)` 쌍을 내놓는다 — `for right, char in enumerate(s)`.
- `float('inf')` 는 어떤 정수보다 큰 값이라 「아직 못 찾음」을 나타내는 최솟값 초기값으로 쓴다.
- `d.get(key, 0)` 은 키가 없으면 0 을 돌려준다 — 빈도 세기에 쓴다.
- `key in d` 는 dict 에 키가 있는지 본다.
- `arr[:k]` · `s[left:right + 1]` 슬라이스는 끝 인덱스를 포함하지 않는다 — 그래서 `right + 1` 이다.
- 윈도우 길이는 `right - left + 1` 이다.
- 함수가 쌍을 못 찾으면 `None` 을 돌려주고, 여러 값은 `(result, max_len)` 처럼 튜플로 돌려준다.

| 기법 | 포인터 움직임 | 전제 | 시간 |
|---|---|---|---|
| 양끝 투 포인터 | 양끝 → 가운데 | 정렬 필수 | O(n) |
| 같은 방향(slow/fast) | 둘 다 오른쪽 | 중복 제거는 같은 값이 붙어 있어야 | O(n), 공간 O(1) |
| 고정 윈도우 | 크기 k 유지하며 밀기 | 연속 구간 | O(n) |
| 가변 윈도우 | right 확장, left 축소 | 연속 구간 · 합 조건은 양수 | O(n) |
| 부분합 + 해시맵 | 한 번 훑기 | 연속 구간 | O(n) |
| 3Sum | i 고정 + 양끝 | 정렬 | O(n²) |

## 어디서 틀리나

### 1. 정렬하지 않은 배열에 양끝 투 포인터

`left` 나 `right` 를 버리는 근거는 「정렬돼 있어서 버린 원소는 어떤 짝과도 답이 안 된다」였다.
정렬이 없으면 이 근거가 무너지고 있는 답을 지나칠 수 있다.
3Sum 이 맨 먼저 `nums.sort()` 를 부르는 까닭이 이것이다.

### 2. 원본 주석의 결과 줄은 실제 출력과 다르다

원본의 주장 → 맨 끝 「출력」 주석에 `결과: 인덱스 (1, 4) -> 3 + 9 = 12` 라고 적혀 있다.
왜 의심스러운가 → 코드는 `left=0`, `right=5` 에서 시작하고 첫 비교 `1 + 11` 이 이미 12 다.
그래서 첫 걸음에 `(0, 5)` 를 돌려준다.
실제 출력도 `결과: 인덱스 (0, 5) -> 1 + 11 = 12` 다.
양끝 투 포인터는 답이 될 쌍이 여럿일 때 「가장 바깥쪽 쌍」을 먼저 만난다.
원본 주석은 또 `배열: …` 줄과 다른 문자열 두 개의 줄을 빠뜨렸다 — 주석은 출력의 요약이지 출력 자체가 아니다.

### 3. 가변 윈도우는 음수가 섞이면 깨진다

`min_subarray_len` 은 「원소를 더하면 합이 늘고 빼면 준다」를 믿고 줄일지 말지 정한다.
음수가 있으면 이 믿음이 틀린다.
`arr = [2, -5, 4]`, `target = 4` 를 손으로 따라가면 누적 합이 2 → −3 → 1 이라 한 번도 4 이상이 안 되어 0 을 돌려준다.
그러나 `[4]` 하나만으로 합이 4 이므로 답은 1 이다(손으로 따라간 것 — 실행 아님).
음수가 섞인 「합이 정확히 k」 문제는 (6) 부분합 + 해시맵으로 푼다.

### 4. 중복 제거는 같은 값이 붙어 있어야 한다

`remove_duplicates` 는 직전에 남긴 값과만 비교한다.
`[1, 2, 1]` 을 손으로 따라가면 1, 2, 1 이 모두 「직전과 다르다」로 남아 길이 3 이 된다(손으로 따라간 것 — 실행 아님).
떨어져 있는 중복은 못 지운다.

### 5. `{0: 1}` 을 빠뜨린다

`prefix_count = {}` 로 시작하면 누적합이 정확히 `target` 인 순간(=인덱스 0 부터 시작하는 구간)을 세지 못한다.
`[1, 1, 1, 2, 3]`, `target = 3` 에서 `[1, 1, 1]` 이 빠진다.

### 6. `seen[char] >= left` 검사를 빠뜨린다

윈도우 밖의 옛 기록을 보고 `left` 를 뒤로 되돌린다.
(5)의 `"abba"` 그림이 그 예다.

### 7. 3Sum 의 중복 처리와 정렬의 부작용

`i` 중복을 건너뛰지 않으면 `[-1, -1, 2]` 같은 조합이 두 번 들어간다.
답을 찾은 뒤 `left`/`right` 를 옮기지 않으면 `while` 이 끝나지 않는다.
`nums.sort()` 는 제자리 정렬이라 호출한 쪽의 리스트도 정렬된다 — 예제는 정렬 전에 `nums` 를 출력해 두었다.

### 8. 경계 입력

`two_sum_sorted` 가 `None` 을 돌려주면 예제의 출력 줄 `arr[result[0]]` 에서 `TypeError` 가 난다(코드에서 읽은 것).
`max_sum_subarray` 는 `len(arr) < k` 여도 오류 없이 `sum(arr[:k])`(전체 합)를 돌려준다 — 「크기 k 구간이 없다」를 알려 주지 않는다.

### 9. 연속이 아니면 윈도우가 아니다

슬라이딩 윈도우와 부분합은 **연속** 부분 배열 · 부분 문자열 문제의 도구다.
원소를 골라 뽑는 부분 수열 문제에는 맞지 않는다.

## 구현 세부사항 대 언어 보장

| 이 문서의 서술 | 누가 보장하나 |
|---|---|
| 포인터가 한 방향으로만 움직여 전체 O(n) | 알고리즘의 성질 — 언어와 무관 |
| dict 의 `in` · `get` · 대입이 평균 O(1) 이라 부분합 · `seen` 풀이가 O(n) | 해시 테이블 구현의 평균 성능 — 언어 명세가 정한 수치가 아니며 최악은 더 느릴 수 있다(확인 필요) |
| `list.sort()` 는 제자리 정렬이고 안정 정렬이다 | 파이썬 문서가 보장한다(확인 필요) |
| `list.sort()` 가 O(n log n) 이다 | 정렬 알고리즘(CPython 은 Timsort)의 성질 — 특정 구현의 세부사항이다(확인 필요) |
| `float('inf')` 가 모든 정수보다 크다 | 언어(부동소수 비교 규칙)가 보장한다 |
| 슬라이스 `arr[:k]` 는 새 리스트를 만든다(k 에 비례하는 비용) | 리스트 슬라이스의 정의 — 언어가 보장한다 |

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 정렬 배열에서 합이 target 인 쌍 | 양끝 투 포인터 | 이중 반복 O(n²) |
| 정렬 안 된 배열에서 쌍 찾기 | 정렬 후 양끝, 또는 해시맵 | 정렬 없이 양끝 투 포인터 |
| 배열을 제자리에서 걸러 내기 | slow/fast | 새 리스트를 계속 만드는 방식(공간이 문제일 때) |
| 길이 k 연속 구간의 합 · 최대 | 고정 윈도우 | 구간마다 `sum()` 다시 계산 |
| 조건 만족하는 최소/최대 길이 연속 구간(양수) | 가변 윈도우 | 음수가 섞인 배열에서 가변 윈도우 |
| 합이 정확히 k 인 구간 개수(음수 포함) | 부분합 + 해시맵 | 가변 윈도우 |
| 합이 0 인 세 수 조합 | 정렬 + i 고정 + 양끝 | 삼중 반복 O(n³) |

## 핵심 문장

1. **포인터가 뒤로 가지 않으면 한 번 훑기로 끝난다** — 이중 반복이 O(n) 이 되는 까닭이다.
2. **양끝 투 포인터는 정렬이 있어야 원소를 버릴 수 있다** — 같은 방향 slow/fast 는 읽기와 쓰기 위치를 가른다.
3. **슬라이딩 윈도우는 연속 구간 전용이다** — 고정 크기는 더하고 빼며 밀고, 가변 크기는 오른쪽으로 늘리고 왼쪽으로 줄인다.
4. **「합이 정확히 k 인 구간 개수」는 누적합 차이 + 해시맵** — `{0: 1}` 로 시작한다.
5. **3Sum 은 하나를 고정한 양끝 투 포인터다** — O(n²), 중복 건너뛰기가 핵심이다.

## 용어 풀이

- **투 포인터** — 인덱스 두 개를 규칙대로 움직여 한 번 훑기로 푸는 기법.
- **양끝 투 포인터** — 배열 양끝에서 출발해 가운데로 좁혀 가는 투 포인터.
- **같은 방향 투 포인터(slow/fast)** — 둘 다 오른쪽으로 가되 `fast` 가 읽고 `slow` 가 쓰는 투 포인터.
- **슬라이딩 윈도우** — 연속 구간을 밀면서 구간 값을 갱신하는 기법.
- **윈도우** — 지금 보고 있는 연속 구간 `arr[left..right]`.
- **고정 크기 윈도우** — 길이 k 를 유지하며 한 칸씩 미는 윈도우.
- **가변 크기 윈도우** — 조건에 따라 늘었다 줄었다 하는 윈도우.
- **연속 부분 배열** — 배열에서 이어진 원소들만으로 이루어진 구간.
- **부분합(prefix sum)** — 맨 앞부터 지금까지의 누적합.
- **해시맵** — 키로 값을 평균 빠르게 찾는 표 — 파이썬에서는 `dict`.
- **제자리(in-place)** — 새 자료구조를 만들지 않고 원래 배열을 고쳐 쓰는 것.
- **3Sum** — 합이 0 인 세 수의 조합을 중복 없이 모두 찾는 문제.

## 더 들어가면

- 정렬 안 된 배열의 두 수의 합은 `dict` 에 「본 값 → 인덱스」를 저장해 O(n)에 푸는 방식이 흔하다(확인 필요).
- 가변 윈도우는 「서로 다른 문자가 최대 k 개인 최장 구간」처럼 `dict` 로 윈도우 안 빈도를 세는 꼴로 넓혀 쓴다(확인 필요).
- 고정 윈도우의 **최댓값**(합이 아니라)은 더하고 빼기로 갱신할 수 없어 단조 덱(`collections.deque`)을 쓰는 기법이 있다(확인 필요).
- 3Sum 을 넘어 4Sum 은 두 개를 고정하고 양끝 투 포인터를 돌려 O(n³) 로 푸는 것이 흔하다(확인 필요).
- 연결 리스트의 사이클 찾기에서 한 칸 · 두 칸씩 가는 slow/fast 포인터도 같은 방향 투 포인터의 친척이다(확인 필요).
