## 한눈에 — 쉽게 말하면

**연결 리스트는 「보물찾기 쪽지」다.**
쪽지 한 장에는 적힌 내용(값)과 「다음 쪽지는 어디에 있다」는 안내가 함께 있다.
첫 쪽지의 위치만 알면 안내를 따라 마지막 쪽지까지 갈 수 있다.
마지막 쪽지의 안내 칸은 비어 있다.
연결 리스트도 똑같은 구조다.

> **노드(node)** — 값 하나와 다른 노드를 가리키는 참조를 묶은 객체다.\
> 예: `ListNode(3)` 은 값 3과 `next` 참조를 가진 노드다.

> **참조(포인터)** — 다른 객체를 가리키는 이름표다. 파이썬에서는 속성(`next` · `prev`)에 객체를 넣어 둔다.\
> 예: `n1.next = n2` 는 `n1` 이 `n2` 를 가리키게 한다.

| 비유 | 실체 |
|---|---|
| 쪽지 한 장 | 노드(`ListNode`) |
| 쪽지에 적힌 내용 | `val` |
| 「다음 쪽지는 저기」 안내 | `next` 참조 |
| 첫 쪽지의 위치 | `head` |
| 빈 안내 칸 | `None` |
| 앞뒤 위치가 모두 적힌 쪽지 | 이중 연결 노드(`DoublyNode`) |
| 출발점 · 도착점 표지판 | sentinel 노드 |

```text
head
 │
 ▼
[1|●]──▶[2|●]──▶[3|●]──▶[4|●]──▶[5|●]──▶ None
 val next
```

## 이 주제가 답하려는 질문

1. 값을 연속된 칸이 아니라 참조로 이어 두면 앞 삽입 · 삭제 · 탐색의 비용은 어떻게 달라지나?
2. 링크를 잃지 않고 리스트의 방향을 통째로 뒤집으려면 무엇을 어떤 차례로 바꿔야 하나?
3. 길이를 모르는 채 한 번만 훑어서 중간 노드와 사이클을 찾을 수 있나?
4. 단일 연결과 이중 연결은 무엇이 다르고, sentinel 노드는 무엇을 덜어 주나?

## 동작 방식

### (1) 단일 연결 리스트 — 붙이기 · 앞에 넣기 · 지우기

**언제 쓰나** — 노드가 다음 노드만 가리키는 가장 단순한 꼴이다.
삽입 · 삭제는 바꿀 자리의 노드 참조를 쥐고 있으면 참조 몇 개만 바꾸면 되고, 탐색은 처음부터 훑어야 한다.

> **시간복잡도 O(1) · O(n)** — 원소 수 n 과 상관없이 일정한 시간이 O(1), n 에 비례하는 시간이 O(n) 이다.\
> 예: 맨 앞 삽입은 O(1), 끝까지 걸어가는 `append` 는 O(n) 이다.

```text
append(6)       curr 를 head 에서 출발해 curr.next 가 None 일 때까지 옮긴다 → 그 뒤에 새 노드
   [1]→[2]→[3]→None   ⇒   [1]→[2]→[3]→[6]→None            O(n)

prepend(0)      새 노드의 next 를 옛 head 로 두고, head 를 새 노드로 바꾼다
   head→[1]→…   ⇒   head→[0]→[1]→…                          O(1)

delete(3)       직전 노드(curr)의 next 를 대상 하나 건너뛰게 바꾼다
   [2]→[3]→[4]   ⇒   [2]────▶[4]     ([3] 은 더는 닿지 않는다)   최악 O(n)
```

- `append` 는 리스트가 비었으면 새 노드를 `head` 로 삼고 끝낸다.
- 비어 있지 않으면 `while curr.next:` 로 마지막 노드까지 걸어가 `curr.next` 에 새 노드를 단다.
- `prepend` 는 `ListNode(val, self.head)` 한 줄로 새 노드를 만들면서 옛 `head` 를 뒤에 달고, 그 노드를 새 `head` 로 둔다.
- `delete` 는 세 경우로 나뉜다: 빈 리스트면 아무것도 안 한다, `head` 가 대상이면 `head` 를 다음 노드로 옮긴다, 그 밖에는 대상의 **직전 노드**에서 `next` 를 건너뛰게 바꾼다.
- 단일 연결에서는 노드가 자기 앞 노드를 모른다. 그래서 `delete` 는 `curr.next.val` 을 보며 한 칸 앞에서 멈춘다.
- `delete` 는 일치하는 첫 노드 하나만 지우고 `return` 한다.
- `ListNode.__repr__` 은 자기부터 `None` 을 만날 때까지 값을 모아 `' -> '` 로 잇는다. `SinglyLinkedList.__repr__` 은 비었으면 `'Empty'` 를 돌려준다.

### (2) 역전 — prev · curr · next 세 포인터

**언제 쓰나** — 리스트의 방향을 한 번의 순회로 뒤집는다.
새 노드를 만들지 않고 각 노드의 `next` 만 고쳐서, 시간 O(n) · 추가 공간 O(1) 이다.

```text
처음      prev=None   curr=[1]→[2]→[3]→None

한 바퀴   next_node = curr.next        ([2] 를 기억)
          curr.next = prev             ([1]→None 으로 뒤집음)
          prev = curr ; curr = next_node

1회 뒤    None←[1]   [2]→[3]→None        prev=[1]  curr=[2]
2회 뒤    None←[1]←[2]   [3]→None        prev=[2]  curr=[3]
3회 뒤    None←[1]←[2]←[3]               prev=[3]  curr=None → 끝, prev 반환
```

- 한 바퀴의 첫 줄은 `next_node = curr.next` 다. 다음 줄에서 `curr.next` 를 덮어쓰면 나머지 노드로 가는 길이 사라지므로 먼저 적어 둔다.
- 둘째 줄이 실제로 방향을 뒤집는 일이다: 현재 노드가 이제 앞 노드(`prev`)를 가리킨다.
- 셋째 · 넷째 줄에서 `prev` 와 `curr` 가 한 칸씩 나아간다.
- `curr` 가 `None` 이 되면 `prev` 는 원래 마지막 노드이고, 그것이 새 `head` 로 반환된다.
- 노드 객체는 그대로이므로 원래 `head` 변수는 여전히 값 1 인 노드를 가리킨다. 그 노드는 이제 **꼬리**이고 `next` 가 `None` 이다.

### (3) 중간 노드 — 토끼와 거북이

**언제 쓰나** — 길이를 먼저 세지 않고 한 번 훑어서 가운데 노드를 찾는다. O(n) 이다.

> **토끼와 거북이(Floyd 의 기법)** — 한 칸씩 가는 `slow` 와 두 칸씩 가는 `fast` 를 함께 움직여 둘의 위치 차이로 무언가를 알아내는 기법이다.\
> 예: `fast` 가 끝에 닿을 때 `slow` 는 절반만큼 와 있다.

```text
홀수 5개   [1] [2] [3] [4] [5]
시작        s,f
1회             s   f
2회                 s       f      f.next 가 None → 멈춤 → slow = [3]

짝수 4개   [1] [2] [3] [4]
시작        s,f
1회             s   f
2회                 s        f=None  → 멈춤 → slow = [3]  (뒤쪽 중간)
```

- 반복 조건은 `while fast and fast.next:` 다. 두 칸을 가려면 `fast` 도, `fast.next` 도 있어야 한다.
- `and` 는 왼쪽이 거짓이면 오른쪽을 보지 않는다. 그래서 `fast` 가 `None` 일 때 `fast.next` 를 읽다가 나는 오류가 생기지 않는다.
- 노드가 홀수 개면 `fast` 가 마지막 노드에서 멈추고 `slow` 는 정확히 가운데다.
- 노드가 짝수 개면 `fast` 가 `None` 까지 넘어가고 `slow` 는 가운데 둘 중 **뒤쪽**에 선다.

### (4) 사이클 감지

**언제 쓰나** — 어떤 노드의 `next` 가 앞쪽 노드로 되돌아가 고리가 생겼는지 알아낸다. 시간 O(n) · 공간 O(1) 이다.

> **사이클(cycle)** — 참조를 따라가다 이미 지난 노드로 돌아오는 고리다. 사이클이 있으면 `None` 에 끝내 닿지 않는다.\
> 예: `1→2→3→4→5→3` 은 3·4·5 가 고리를 이룬다.

```text
1 → 2 → 3 → 4 → 5
        ▲       │
        └───────┘

         slow  fast
시작      1     1
1회       2     3
2회       3     5
3회       4     4     ← slow is fast → True
```

- 사이클이 없으면 `fast` 가 먼저 끝(`None`)에 닿아 반복이 끝나고 `False` 다.
- 사이클이 있으면 둘 다 고리 안에서 돈다. 매 바퀴 `fast` 가 `slow` 와의 간격을 한 칸씩 좁히므로 결국 같은 노드에 선다.
- 만남 판정은 `slow is fast` 다. `is` 는 두 이름이 **같은 객체**인지 본다. 값이 같아도 다른 노드면 거짓이다.

### (5) 사이클 시작점 찾기

**언제 쓰나** — 사이클이 있음을 안 뒤, 고리가 시작되는 노드를 찾는다.

```text
a = head 에서 시작점까지 거리       (예: 1→2→3, a = 2)
b = 시작점에서 만난 점까지 거리     (예: 3→4,   b = 1)
c = 고리의 길이                     (예: 3,4,5, c = 3)

만날 때까지  slow 는 a+b 걸음, fast 는 2(a+b) 걸음
fast 가 더 걸은 a+b 는 고리를 k 바퀴 돈 것 → a+b = k·c
따라서 a = k·c − b  →  만난 점에서 a 걸음 가면 시작점에 선다

2단계  slow=head(1), fast=만난 점(4) 에서 둘 다 한 칸씩
       (2, 5) → (3, 3)  ← 시작점 3 에서 만남
```

- 첫 단계는 `has_cycle` 과 같다.
- 만나면 `slow` 만 `head` 로 되돌리고, 이번에는 **둘 다 한 칸씩** 움직인다.
- `slow` 는 `head` 에서 a 걸음 가면 시작점에 닿는다.
- `fast` 는 만난 점에서 a 걸음, 곧 「k 바퀴에서 b 를 뺀 거리」를 가므로 역시 시작점에 닿는다.
- 그래서 둘이 처음 겹치는 노드가 시작점이고, 그 노드를 반환한다. 사이클이 없으면 `None` 을 반환한다.

### (6) 이중 연결 리스트와 sentinel

**언제 쓰나** — 노드가 앞(`prev`)과 뒤(`next`)를 모두 가리키게 하면, 노드 참조 하나만으로 그 노드를 O(1) 에 빼낼 수 있다.

> **sentinel 노드(더미 노드)** — 실제 데이터가 아니라 경계를 지키려고 양 끝에 둔 노드다. 빈 리스트에도 늘 있다.\
> 예: `DoublyNode(0)` 두 개를 `head` · `tail` 로 두고 서로 잇는다.

```text
빈 리스트     [H] ⇄ [T]                        (H, T 는 sentinel)

append(1)    prev_node = T.prev (= H)
             [H] ⇄ [1] ⇄ [T]                   참조 4개를 고쳐 끼워 넣기

remove(x)    x.prev.next = x.next
             x.next.prev = x.prev
             [a] ⇄ [x] ⇄ [b]  ⇒  [a] ⇄ [b]
```

- `append` 는 `tail` 직전에, `prepend` 는 `head` 직후에 새 노드를 끼운다. 둘 다 참조 네 개를 고치고 `size` 를 1 늘린다. O(1) 이다.
- `remove` 는 앞 노드와 뒤 노드가 서로를 가리키게 하고 `size` 를 1 줄인다. 앞 노드를 `node.prev` 로 바로 알 수 있어 처음부터 훑지 않는다.
- sentinel 이 있으므로 실제 노드의 `prev` · `next` 는 언제나 노드다. 「앞이 `None` 이면…」「리스트가 비었으면…」 같은 갈래가 필요 없다.
- `__repr__` 은 `head.next` 부터 `tail` 직전까지만 훑어 sentinel 을 빼고 `' <-> '` 로 잇는다. 실제 노드가 없으면 `'Empty'` 다.
- `size` 는 `append` · `prepend` · `remove` 에서만 바뀌므로 sentinel 두 개는 세지 않는다.

## 문법 — 형태와 규칙

```python
class Node:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

head = Node(1, Node(2, Node(3)))   # 안쪽부터 만들어져 1 → 2 → 3

node = head
while node:                        # None 에 닿으면 멈춘다
    print(node.val)
    node = node.next

a, b = Node(7), Node(7)
print(a is b)                      # 서로 다른 객체 — 값이 같아도 다른 노드
```

- 노드는 보통 작은 클래스로 만들고, 값과 참조를 속성으로 둔다.
- `Node(1, Node(2, Node(3)))` 처럼 생성자를 겹쳐 부르면 리스트를 한 줄로 만들 수 있다. 가장 안쪽 노드가 먼저 만들어진다.
- 순회는 `while node:` 와 `node = node.next` 의 짝이다. `None` 은 거짓으로 취급되어 반복이 끝난다.
- 사이클처럼 일부러 고리를 만들 때는 노드를 따로 만든 뒤 `n5.next = n3` 처럼 참조를 직접 넣는다. 한 줄에 여러 문장을 쓸 때는 `;` 로 나눈다.
- 노드가 「같은가」는 `is` 로 본다. 값 비교 `==` 를 쓰면 같은 값을 가진 다른 노드와 헷갈린다.
- 사용자 클래스에 `__eq__` 를 따로 만들지 않으면 `==` · `!=` 도 객체가 같은지로 판단한다. 그래서 `while curr != self.tail:` 은 「`tail` 객체에 닿기 전까지」를 뜻한다.
- `__repr__` 을 정의하면 `print` 와 `repr()` 이 그 문자열을 쓴다.

## 어디서 틀리나

### 1. 「파이썬 list 가 있는데 왜?」 — 쓰임새를 헷갈린다

원본의 팁: 파이썬 `list` 가 동적 배열이라 연결 리스트를 직접 쓸 일은 적지만, 코딩 테스트에서 자주 출제된다.
동적 배열은 원소를 연속된 칸에 두므로 번호로 바로 접근할 수 있지만, 맨 앞에 넣거나 빼면 뒤 원소를 한 칸씩 밀거나 당겨야 한다.
연결 리스트는 반대로 맨 앞 삽입이 O(1) 이지만 k 번째 원소를 보려면 k 칸을 걸어야 한다.
실무에서는 대개 `list` 로 충분하고, 연결 리스트는 포인터 조작 문제로 더 자주 만난다.

### 2. 역전에서 링크를 먼저 끊는다

원본의 팁: 역전은 prev/curr/next 세 포인터로 구현한다.
`curr.next = prev` 를 `next_node = curr.next` 보다 먼저 쓰면 나머지 노드로 가는 유일한 참조가 사라져 순회가 끊긴다.
또 역전 뒤에는 반환값을 새 `head` 로 받아야 한다. 원래 `head` 변수는 이제 꼬리 노드 하나만 가리킨다.

### 3. 토끼와 거북이의 조건을 잘못 쓴다

원본의 팁: 중간 노드와 사이클 감지는 Floyd 의 토끼와 거북이 알고리즘이다.
조건 `fast and fast.next` 에서 앞쪽 검사를 빼면 `fast` 가 `None` 일 때 `None.next` 를 읽어 `AttributeError` 가 난다.
짝수 길이에서 `find_middle` 은 가운데 둘 중 뒤쪽을 준다. 앞쪽을 기대하면 틀린다.

### 4. 만남을 값으로 판정한다

`has_cycle` 은 `slow is fast` 로 **같은 노드**인지 본다.
`slow.val == fast.val` 로 바꾸면 사이클이 없어도 값이 같은 서로 다른 노드에 둘이 동시에 서는 순간 `True` 가 나올 수 있다.

### 5. 사이클이 있는 리스트를 찍는다

`ListNode.__repr__` 은 `None` 을 만날 때까지 걷는다.
사이클이 있으면 `None` 에 닿지 않으므로 `print(n1)` 은 끝나지 않고 문자열 목록만 계속 불어난다.
그래서 예제는 사이클 리스트에 대해 `.val` 만 찍는다.

### 6. `delete` 의 경계

빈 리스트, `head` 가 대상인 경우를 따로 다루지 않으면 `None.val` 을 읽거나 `head` 를 갱신하지 못한다.
`delete` 는 같은 값이 여럿이어도 첫 노드 하나만 지운다.

### 7. 이중 연결의 sentinel 을 잊거나 건드린다

원본의 팁: 이중 연결 리스트는 sentinel 노드를 쓰면 경계 조건 처리가 깔끔하다.
sentinel 이 없으면 `append` · `prepend` · `remove` 마다 「앞이 없나 · 뒤가 없나 · 하나뿐인가」를 따져야 한다.
`remove` 는 넘겨받은 노드를 의심하지 않는다. sentinel 이나 이미 빠진 노드를 넘기면 구조가 깨지고 `size` 가 틀어진다.

### 8. 원본 주석 「삽입/삭제 O(1)(노드 참조 시)」

원본의 주장 → 단일 연결 리스트에서 노드 참조가 있으면 삭제가 O(1) 이다.
왜 의심스러운가 → 단일 연결의 노드는 자기 앞 노드를 모른다. 지울 노드 자체의 참조만으로는 앞 노드의 `next` 를 고칠 수 없다. 같은 정답 코드도 이중 연결의 `remove` 에 「노드 참조만 있으면 O(1) 에 제거 (단일 연결 리스트와의 핵심 차이)」라고 적는다. O(1) 은 「직전 노드의 참조를 쥐고 있을 때」로 읽어야 맞다.

### 9. 원본 코드 끝의 `# 출력:` 주석

원본의 주장 → 코드 끝 주석이 출력을 보여 준다.
왜 의심스러운가 → 실제 출력에는 `prepend(0):` · `delete(3):` · `원본:` · `사이클 없음:` · `크기:` 줄도 있고, 중간 노드 절의 제목 줄도 주석과 다르다. 주석은 출력의 요약이지 실제 출력이 아니다.

## 언제 쓰고 언제 안 쓰나

| 상황 | 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 번호로 자주 꺼내 본다 | 파이썬 `list` | 연결 리스트(매번 k 칸을 걸어야 한다) |
| 맨 앞에 자주 넣는다 | 연결 리스트의 `prepend` | 동적 배열의 맨 앞 삽입(뒤 원소를 민다) |
| 쥐고 있는 노드를 바로 빼야 한다 | 이중 연결 + `remove(node)` | 단일 연결(앞 노드를 다시 찾아야 한다) |
| 방향을 뒤집는다 | prev/curr/next 세 포인터 | 값을 새 리스트에 담아 다시 만들기(추가 공간) |
| 중간 · 사이클을 한 번에 | `slow` / `fast` 두 포인터 | 방문한 노드를 모두 따로 저장하기(공간 O(n)) |
| 만남 판정 | `is` | `.val` 비교 |

## 핵심 문장

1. **연결 리스트는 값과 「다음」 참조를 묶은 노드의 사슬이다** — 앞 삽입은 참조 몇 개로 끝나고, 탐색은 처음부터 걷는다.
2. **역전은 「다음을 기억 → 뒤집기 → 한 칸 전진」의 반복이다** — 순서를 바꾸면 나머지를 잃는다.
3. **두 배 빠른 포인터 하나로 중간과 사이클을 함께 다룬다** — 끝에 닿으면 중간, 만나면 사이클이다.
4. **사이클 시작점은 만난 뒤 한쪽을 `head` 로 돌려 같은 속도로 걸으면 나온다.**
5. **이중 연결 + sentinel 은 노드 하나로 O(1) 삭제를 주고 경계 검사를 없앤다.**

## 용어 풀이

- **노드(node)** — 값과 다른 노드에 대한 참조를 묶은 객체.
- **참조(포인터)** — 다른 객체를 가리키는 이름표. 여기서는 `next` · `prev` 속성.
- **head** — 리스트의 첫 노드(또는 이중 연결에서는 앞쪽 sentinel).
- **tail** — 리스트의 끝. 이중 연결 예제에서는 뒤쪽 sentinel.
- **단일 연결 리스트** — 노드가 다음 노드만 가리키는 리스트.
- **이중 연결 리스트** — 노드가 앞뒤 노드를 모두 가리키는 리스트.
- **sentinel 노드** — 데이터 없이 경계를 지키려고 양 끝에 둔 더미 노드.
- **역전** — 모든 `next` 의 방향을 뒤집어 순서를 거꾸로 만드는 일.
- **사이클** — 참조를 따라가면 이미 지난 노드로 돌아오는 고리.
- **토끼와 거북이(Floyd 의 기법)** — 한 칸 · 두 칸씩 가는 두 포인터로 중간이나 사이클을 찾는 기법.
- **동적 배열** — 연속된 칸에 원소를 두고 모자라면 늘리는 배열. 원본 팁에 따르면 파이썬 `list` 가 이것이다.
- **O(1) · O(n)** — 원소 수와 무관한 시간 · 원소 수에 비례하는 시간.
- **`__repr__`** — 객체를 문자열로 보일 때 파이썬이 부르는 메서드.

## 더 들어가면

- 단일 연결 리스트에 꼬리 참조(`self.tail`)를 따로 두면 `append` 도 O(1) 이 된다. 대신 `delete` 가 마지막 노드를 지울 때 꼬리를 고쳐야 한다.
- 짝수 길이에서 앞쪽 중간을 원하면 조건을 `while fast.next and fast.next.next:` 로 바꾸는 변형이 흔하다. (확인 필요)
- 사이클을 찾은 뒤 만난 점에서 한쪽만 한 바퀴 돌며 세면 고리의 길이를 얻는다.
- 역전은 재귀로도 쓸 수 있지만, 긴 리스트에서는 재귀 깊이 한도에 걸릴 수 있다. (확인 필요)
- 앞뒤 양쪽 삽입 · 삭제가 필요하면 표준 라이브러리 `collections.deque` 가 이 일을 맡는다. 내부가 블록을 이은 구조라는 설명이 있다. (확인 필요)
- 노드 클래스에 `__slots__` 를 두면 노드마다 드는 메모리를 줄일 수 있다는 이야기가 있다. (확인 필요)
- 사이클 감지에는 Brent 의 방법 같은 다른 두 포인터 기법도 있다. (확인 필요)
