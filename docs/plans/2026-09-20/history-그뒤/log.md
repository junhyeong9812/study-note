## 이 문서 유형의 실패 모드 (실측 40건 + 워커 자체발견 13건)

원본이 없으므로 「원문과 다르다」가 아니라 「**사실이 아니다**」가 실패다.
출처 접지가 원문 대조를 대신한다. 실측된 유형:

1. **인용부호 안 바꿔쓰기** — 가장 많다.
   - RFC 9484 의 인용문이 **RFC 전문에 없었다**(세 문장을 뭉갠 결과)
   - Ladybird `"Status: … / Target: …"` — **` / ` 가 원문에 없는 접속 기호**
   - `waypoint`(원문 `waypoints`) · `also` 누락 · 직선 따옴표 vs 둥근 따옴표
   - → **영문 인용 전수를 원문 substring 으로 기계 대조**해야 잡힌다
2. **근거 없는 부정 주장** — 「~하지 않았다」·「~뿐이다」
   - JEP 537 은 실제로 JEP 401 을 **두 곳에서** 지목한다
   - 분산 SQL 새 메이저는 하나가 아니라 **둘**(YugabyteDB 미확인)
   - Wasm GC 언어 목록은 **인용한 바로 그 출처에** 있었다
   - → 부정 주장마다 **어디를 열어 무엇을 못 찾았는지**를 표로 남긴다
3. **수치에 다른 표의 조건을 붙임** — Bun 1.4 Fastify 메모리.
   한 공지에 벤치마크 절이 여럿이면 조건 줄도 여럿이다.
   → **같은 표에 물리적으로 붙은 caption 만** 쓴다
4. **시리즈 대조 누락** — RSC CVE 번호가 한 칸 밀려 **5.3 과 10.0 이 뒤바뀌고**
   최상위 항목(무인증 RCE)이 통째로 빠졌다.
   → 보안 공지는 **ID↔설명↔CVSS↔수정판 쌍으로 전수** 대조
5. **절 제목을 상태로 읽음** — JEP 0 의 `In-flight JEPs` 는 h2 제목이지 Status 값이 아니다
6. **조사 창이 문서 안에서 흔들림** — database 가 창 시작을 두 값으로 썼다.
   → 창을 **날짜 하나로 못박고** 포함·제외를 전부 그 기준으로
