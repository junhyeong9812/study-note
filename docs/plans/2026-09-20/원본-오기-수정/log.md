## ★ 메인의 브리핑이 틀린 사례 2 (B4)

브리핑에 「코드 주석 쪽이 틀렸을 가능성이 높지만 출처로 확정한 뒤 고쳐라」라고 썼다.
**반대였다.** 워커가 PEP 526 을 열어 확인했다 — 값 없는 `x: int` 는 그 PEP 의 어휘로
*instance variable* 이고, 옆줄의 `origin: ClassVar[bool]` 이 *class variable* 이다.
PEP 557(dataclasses)도 dataclass 가 읽는 것을 「`__annotations__` 에 있는 변수」라 할 뿐
"class variable" 이라 쓰지 않는다.

메인이 로컬에서 직접 실증:
```
class Point:
    origin: 'ClassVar' = None
    x: int
__annotations__ → {'origin': 'ClassVar', 'x': <class 'int'>}
hasattr(Point,'x') → False        # 클래스 속성이 만들어지지 않는다
'x' in vars(Point) → False
```
→ **코드 주석(L138)이 맞고 산문(L143)이 틀렸다.** 산문을 고쳤다.
**교훈: 브리핑의 「~쪽이 틀렸을 가능성이 높다」는 지시가 아니라 가설이다.**
워커가 출처로 뒤집을 수 있게 써야 하고, 실제로 뒤집혔다.

### ★ A4 — 「택일」이라는 틀 자체가 틀렸다
앞선 워커는 「한 단어만」 제약 때문에 `게이트마스크` → **`게이트웨이`** 로 골랐다.
그 선택이 **마스크 쪽 절반을 버리는 것**이었다.

- `게이트마스크` 는 네트워크 용어로 **존재하지 않는다**(검색 용례 0).
  게이트(웨이) + (서브넷)마스크 **두 반쪽을 모두 품은 합성**이다.
- **RFC 1122 §3.3.1.6** 이 호스트가 수동으로 입력받을 수 있어야 하는 것으로
  「(1) IP address(es) (2) Address mask(s) (3) A list of default gateways」 **셋을 번호로 열거**하고
  "A manual method of entering this configuration data MUST be provided" 라 적는다.
  — 「관리자가 손으로 박았다」의 직접 원문이다.
- DHCP 가 자동화한 것도 그 셋 + DNS(RFC 2132 option 6) = **넷**이다.
- 어순은 RFC 1122 의 (1)(2)(3) 과 RFC 2132 옵션 코드 순서(1<3<6)를 따랐다.
  RFC 2132 §3.3 — "If both the subnet mask and the router option are specified in a DHCP reply,
  **the subnet mask option MUST be first**."

→ `IP·**서브넷 마스크**·게이트웨이·DNS 서버` 넷으로 복원.

**브리핑이 만든 제약이 오답을 강제했다.** 「한 단어만 고쳐라」가
「둘이 뭉개진 자리」를 볼 수 없게 만들었다.
→ 교훈: **제약은 개입을 줄이려고 거는 것이지, 답의 모양을 미리 정하는 것이 아니다.**
   「최소 개입」은 *글자 수*가 아니라 *의미 단위*로 재야 한다.

### ★ D — 보류가 옳지 않았다. 실제로 어긋난 것이었다
`rust-history/01-탄생-1.0.md` 절 제목 `(2010 ~ 2012)` vs 본문 「2009년부터 2012년 사이」.
이관 로그는 「제목이 절 전체의 대략 구간일 수 있어 단정 보류」로 남겼다.
**둘은 같은 사건(OCaml → 자체 호스팅 rustc 이전)의 시작점을 다르게 적고 있었다.**

결정적 근거는 **같은 편 L27** 이다 — 「2006년부터 **2009년까지** Rust는 Mozilla 내부에도
알려지지 않은 채 Hoare 혼자 다듬던 … 선사시대 프로젝트였다」.
저자 자신이 2009년까지를 OCaml 단독 시기로 못박으므로 L39 는 **자기 편과 충돌**한다.

1차 확인:
- LLVM 백엔드 첫 등장 = `rust-prehistory` **2010-03-31** 「Stub the LLVM backend」
- `rust-lang/rust` 첫 커밋 자체가 **2010-06-16**, `src/comp` LLVM 작업 **2010-07-13**
- 자체 호스팅 달성 = **2011-04-29** 「rustc: Remove the wrong-compiler warning; we're self-hosting now.」
- 0.1 = 2012-01-20 (RELEASES.md) — 본문 값 그대로

→ 본문 2009 → **2010**. repo 전체에서 `2009` 는 Mozilla 후원 연도 전용으로 수렴했다.

### 지시한 「가장 강한 근거」가 부재했던 것
브리핑은 A4 판정의 핵심 근거로 「이 문서의 DHCP 절이 무엇을 열거하는가」를 들었다.
워커가 §6 전문을 읽은 결과 **그 문서에는 DHCP 가 주는 항목을 세는 자리가 하나도 없었다.**
→ 워커가 근거 부재를 **보고하고 다른 축(RFC + 합성어 구조)으로 판정**했다. 올바른 처리다.
   브리핑이 지목한 근거가 없을 때 **억지로 찾아내지 않은 것**이 이 건의 성공 요인이다.
