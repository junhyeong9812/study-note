## 사용자 제안 하나를 채택하지 않았다 — 공식 문서 전문 이식·번역

사용자 제안: 「각 언어 docs 페이지 내용을 그대로 전부 가져와 더 작게 나누고 번역」.
**채택하지 않고 기준 소스 방식으로 진행하기로 했다**(사용자 동의 2026-09-20). 이유 둘:

1. **라이선스가 갈린다.** Python·Go·Rust·Kotlin·TS·MDN·PostgreSQL 문서는 재배포를 허용하는 편이나
   **Oracle 의 Java 언어 명세·API 문서와 MySQL 문서는 그렇지 않다.** 이 repo 는 공개 저장소다.
2. ★ **방식이 목적과 맞지 않는다.** 이 repo 의 값은 **골라내고 압축해 인출 가능한 크기로 자른 것**이다.
   전문 번역본은 「읽는 것」이지 「인출하는 것」이 아니고, Java API 문서만 해도 수만 쪽이다.

→ 대신 공식 문서를 **기준 소스로 열어 대조**하고 설명·예시는 직접 쓴다.
   규칙 문구가 중요한 자리만 짧게 인용하고 링크를 건다. history 8주제에서 이 방식으로 인용 층 오류 0건을 냈다.
→ 여기에 **실행 검증**이 더해진다 — Java·Python·Rust·JS 는 예시를 실제로 돌려 출력을 확인한 채로 싣는다.
   번역본으로는 못 하는 검증이고, 이것이 이 자료가 공식 문서보다 나은 유일한 지점이다.

### ★ 워커가 잡아낸 기준 변화 2건 (메인 재확인)

   Go 네이티브 포트이고 **기본값이 크게 바뀌었다** — `strict` 기본 `true` · `module` 기본 `esnext` ·
   `types` 기본 `[]` · `rootDir` 기본 `./` · `target: es5`·`downlevelIteration`·`baseUrl`·
   `moduleResolution: node10/classic`·AMD/UMD 제거.
   → **tsconfig 주제 6개(#34·35·38·39·43·48)가 이 변화에 직접 걸린다.** 2단계에서 옛 기본값으로 쓰면 전부 틀린다.

2. **`tc39.es/ecma262` 는 이미 ES2027 초안**이다. 확정 기능은 ES2026 까지.
   Temporal 과 `using`(명시적 자원 관리)은 **ES2027 초안 단계**라 그렇게 표기했다.

### SQL — 이 repo 에 언어로서 처음 들어온 것
분류: 질의 29 · 함수 18 · DDL·제약 6 · 트랜잭션·동시성 3 · 실행·최적화 4

- **01 논리적 질의 처리 순서**를 맨 앞 A 로 두고 **13개 주제가 직접 선행으로** 걸게 했다.

- MySQL 전용 주제 0은 **의도한 결과** — `REPLACE`·`INSERT IGNORE`·`STRAIGHT_JOIN` 은 독립 주제가 될 만큼 크지 않아 해당 주제의 방언 메모로 돌렸고 그 이유를 README 에 적었다.

### ★ 워커가 스스로 건 경고 (좋은 처리)
- 「방언 차이가 큰 자리」 **24행 표의 항목은 전부 공식 문서에서 문장을 확인**했으나,
  **표의 나머지 `차이` 표시는 확신도가 낮다**고 README 에 명시하고 **2단계 재확인 대상으로 걸었다.**

→ 이 세션 내내 문제였던 **「근거 없는 부정 주장」**과 **「확인 못 한 값 적기」**를 워커가 스스로 피했다.
