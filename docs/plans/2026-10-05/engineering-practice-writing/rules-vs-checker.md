## 0. 요약

1. **가장 큰 드리프트는 노트가 아니라 정본 README다.** `cs/README.md` §3은 서머리 골격을 **6절**로 적는데, 검사기(C:6-7)와 모든 브리핑은 **7절**(`핵심 문장` 포함)을 강제하고 새 leaf 387편도 전부 7절이다.
2. **형식 규칙 상당수가 README가 아니라 영역별 브리핑에만 있다**(질문 6~10, 핵심 문장 3~6, 장애 3~5, 금지어, 실험 환경 라벨, 용어 풀이 형식, 제목 형식, 리프에 md만, 질문 유형 태그). 브리핑 11개가 복사로 이어 가 — 정본이 사실상 "가장 최근 브리핑"이다.
3. **검사기 범위 안에서는 387편 전부 PASS.** 검사기가 안 보는 기계 검사 가능 규칙의 실제 위반은 작다: 장애 6개 노트 8편, 실험 절 위치 이탈 3편, 언어 태그 없는 코드 펜스 3개. 나머지는 형식 변종(장애 항목 굵은 번호 10편, 실험 라벨 4가지 형태).
4. **영역 표(생성 문서) 19개는 생성기 출력과 바이트 단위로 같다**(드리프트 0) — 다만 이를 확인하는 검사가 없다.
5. **검사기는 자동화에 연결되어 있지 않다** — 작업 폴더에 있고, 브리핑 §8이 손으로 돌리라고 할 때만 돈다.

## 2. 검사기 코드의 빈틈·오탐

- `links()`(C:37-45)는 `](`만 보고 링크로 취급 — 옛 컬렉션의 `[0](첫째)` 같은 대괄호 표기를 오탐(새 leaf 0건).
- 옛 컬렉션의 **진짜 깨진 링크 3건**: domain-modeling/domain-vs-application-logic → `../clean-code/`, engineering/development-standards/operational-standards → `../../straggler/`, ops-patterns/failure-at-scale → `../multi-tenancy/`.
- Q/A 검사(C:95-98): 질문·정답이 둘 다 0개면 "질문 수 0"으로 보고(옛 형식이 이렇게 걸림).
- H1 검사(C:78-80)는 `# `로 시작하는지만 본다.
- cs 전체 573폴더: 387 PASS / 186 FAIL — FAIL은 전부 옛 컬렉션(algorithm 30·data-structure 36·domain-modeling basic/advanced 62·ops-patterns 22·systems 20·engineering 9·api-design 6·foundations 1). 검사기가 새 leaf 전용이라는 전제를 README에 적어 두는 것이 좋다.

## 3. 옛 사례 노트(api-design 22~27)가 FAIL하는 이유

- 질문·정답을 `1. …` 목록·`### N.` 헤딩이 아니라 `#### N.` 소제목(A. 문제 / B. 개념 / C. 통일 골격)으로 묶어 검사기 정규식이 0개로 읽는다.
- 옛 흔적: 제목이 옛 번호(예: 22 폴더에 `# api-design/01-order-point — 질문` — 이름 변경 커밋 861c50e6 이후 그대로), 본문 소제목의 `(Claude 초안 2026-09-28)` 표식, 3-answer의 `## 실행 환경` 절. 최상위 7절·metadata·링크는 통과.
