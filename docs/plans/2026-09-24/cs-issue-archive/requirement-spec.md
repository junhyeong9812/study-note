## 0. 요구사항 원문 (인터뷰 기록)

- 원문(요지): 개인 프로젝트 작업 공간·회사 작업 공간 두 작업 전반에서 발생한 문제와 해결방안을 탐사해 `cs/issue`에 정리 — 도메인 이슈 말고 CS 이슈(언어·프레임워크 오류, 시스템, 네트워크 등). 폴더가 없으면 새로 분할. 도식화 최대 활용 — 사람과 AI가 모두 읽기 좋은 ASCII 도식을 코드블록 안에. 문서마다 커밋.
- Q/A: B1 upstream 클론 제외, 출처 = 각 프로젝트 `docs/plans/**/log.md`·`study-note 프로젝트 이슈 문서`·개인 프로젝트 troubleshooting·회사 작업 docs/handover(대화 전사·커밋 메시지 제외) / B2(수정) **카드에 실제 파일·라인 근거 비노출** — 검증 시에만 사용, 코드는 단순화·추상화, 원리로 같은 이슈를 묶는 것이 역할. **B2 확정(2차)**: 규칙 변경 — 출처(프로젝트·파일·라인) 대신 **문제 코드와 연결 코드를 가져와 추상화한 코드로 구조를 직접 표현**, 출처 기재 불필요, 기존 카드에도 적용. 회사 작업는 시스템 동작 이슈만·도메인 제외·실코드 유출 금지 / B3(→B2 확정으로 대체: 출처 미기재) / B4 하네스 자체 CS 이슈 포함 / B5 새 분류 폴더 허용 / B6 Opus 워커 병렬(≤10, Workflow 미사용) / B7 stakes 중간, 기존 카드 append-only / A6 카드 1개 = 커밋 1개, push는 배치 끝 1회 확인 / 모드 auto. "이번 작업으로 전체 정리 한번 싹".

## 1. 목표·대상 (필수)

study-note `cs/issue/`에 두 작업 공간의 CS 이슈를 패턴 카드로 전수 정리(신규 카드·기존 카드 사례/방안 비교 append·새 분류 폴더·인덱스 README)하고, **authoring-guide를 B2(출처 비기재·추상화 코드로 구조 표현)로 개정 + 기존 카드의 출처·파일·라인을 추상화 코드로 이번에 한해 일괄 전환**한 뒤 카드별 커밋·push하면 끝.

## 2. 경계·불변식 (필수)

- 카드에 실제 파일 경로·라인·클래스명·내부 서비스명·도메인·IP·시크릿·실코드 없음(예시 코드는 단순화된 일반 코드). 출처(프로젝트명·회사명) 자체를 적지 않는다 — 추상화 코드(일반 이름·축약 로직)로 구조만 보인다.
- 도메인 이슈 제외 — "프로젝트 밖 사람에게 같은 문장으로 설명되는 CS 원리"만.
- 모든 카드 내용은 출처 원문에서 확인된 것만(날조 금지) — 검증 근거(파일·라인)는 작업 log.md(또는 로컬 scratchpad 원장)에만.
- 기존 카드: 본문은 append-only(사례·방안 비교 섹션 추가). **단 B2 개정에 따른 출처·파일·라인 → 추상화 코드 전환은 이번 1회 예외로 수정 허용.** 같은 문제·같은 방안은 변경 없음, 다른 방안은 `## 방안 비교` append.
- 커밋마다 해당 카드 파일 + 인덱스 README만 스테이징. **작업은 별도 worktree `<별도 worktree>`(브랜치 `archive/2026-09-24`, base main f5501c5)** — 원 작업트리는 다른 세션이 사용 중(브랜치 docs/nextjs-response-out)이라 건드리지 않는다.
- 형식: authoring-guide(1/2/3 파일·ASCII 도식 코드블록·줄 끝 `\`).

## 3. 기준소스 (필수)

출처 원문(각 프로젝트 log.md·이슈 문서·troubleshooting·회사 작업 docs) + `cs/issue/authoring-guide.md`(개정본) + 사용자 답변.

## 4. 금지영역 (필수)

- 출처 프로젝트들(읽기만), upstream 클론, study-note의 `cs/issue` 밖 파일(인덱스 링크 필요 시 `cs/index.md` 1줄 제외), 원 작업트리(`<원 작업트리>` — 다른 세션 사용 중), force push.

## 5. 검증 방법 (필수)

- 사실검증 워커(작성 워커와 분리): 카드마다 주장 ↔ 출처 원문 대조 결과를 log.md에 기록.
- 노출 스캔: `cs/issue/**`에 파일경로 패턴(`\.(java|kt|py|ts|tsx|go|rs|sh|yml|sql):[0-9]`)·IP·회사/서비스명·시크릿 패턴 grep 0건.
- 링크 점검(상대 링크 대상 존재), 형식 점검(리프 1/2/3 존재·도식 코드블록).
- 커밋 수 = 카드 수 확인, 원 작업트리 무변경 확인.

## 6. stakes (필수)
