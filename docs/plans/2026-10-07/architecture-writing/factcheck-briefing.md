2. **조건·범위 혼동**: 한 CPU·한 컴파일러·JIT 결과를 일반화, 캐시·분기 효과를 하드웨어 카운터 없이 단정, 표준 요구 vs 구현 동작 혼동, x86 동작을 모든 아키텍처로 일반화.
3. **조건 없는 단정**: "항상·모든·반드시·절대" + 예외 존재.
4. **지어낸 것**: 출처 없는 수치·로그 문구·API·사례. 예시 수치에 "(예시)" 누락. **실험 출력이 out 파일·재실행과 다르거나 손으로 만든 흔적**.
5. **`[?]` 판정**: 확인되면 떼고 근거를 붙인다. 틀렸으면 고친다. 확인 불가면 둔다.
6. **정답-본문 불일치**, **노트 안 모순**(그림 vs 글, 요약 vs 정답, 정답 N vs M, **실험 출력 vs 본문 해석**) — 반드시 대조한다.
7. **노트 간 모순**: 담당 노트끼리, 링크한 노트(network/29~32(TLS 단일 출처)·api-design·web-platform·reliability·engineering-practice/15·algorithm/12, 원본 foundations/security 등)와 모순이면. **링크가 실제 폴더를 가리키는지**(커리큘럼 번호 ≠ myway 폴더 번호)도 확인 packet에 보고(담당 밖은 고치지 않는다).
8. **책 인용**: 집필자 대부분이 책 본문을 열지 못하고 목차·출판사 발췌·저자 블로그·독자 노트로 확인했다. 그 범위를 넘는 단정(장 안의 세부 주장·쪽 번호)은 확인 가능한 출처로 대조하고, 못 하면 `[?]` 또는 장 단위로 낮춘다. 2차 출처(Wikipedia·독자 노트)로만 확인한 것은 그렇게 밝혀져 있는지 본다. **개인정보 금지**: 요청·파일 어디에도 사용자 식별 정보를 넣지 않는다.

## 3. 실험 재현 (V1b — 필수)

- 편마다 실험 **최소 1개를 다시 돌린다**(집필자 코드·명령 그대로, briefing §6 규칙: 공용 컨테이너 없음 — 모든 실험은 자기 전용 `sn-arch-f<묶음>-*` 일회용 컨테이너, 끝나면 확인).
- 결정적 출력은 일치해야 한다. 비결정적 값(시간·순서·무작위)은 범위·경향이 맞는지 본다. 노트가 범위를 너무 좁게 단정하면 고친다.
- 재현이 실패하거나 출력이 다르면 노트를 실제 결과에 맞게 고치고 packet에 적는다.
- briefing §6 그대로: 자기 전용 `sn-arch-f<묶음>-*` 일회용 컨테이너(`--rm --pull never --cpus=2 -u $(id -u):$(id -g) -e HOME=/tmp`, 가능하면 `--network none`), 호스트 gcc·python3·gzip·zstd·xz 가능, 새 패키지·이미지 금지. 집필자 폴더를 복사해 쓰고 원본 out 파일은 덮어쓰지 않는다. 재실행 산출물은 `scratchpad/arch/fc-<묶음>/`.
