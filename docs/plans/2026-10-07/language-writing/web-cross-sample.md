## 확인 불가·관찰 상세

확인 불가 0건. 아래는 사실과 어긋나지는 않지만 보충하면 좋은 관찰이다. 노트를 고칠지는 메인이 판단한다.

1. **05 :161 — 인용 문서가 근거 목록에 없음.** 본문은 Microsoft Learn "Variance in Generic Interfaces"를 인용하지만, §관련 주제·근거 :303에는 "Generics in the runtime" 링크만 있다.
   - 제안: :303 줄에 `· "Variance in Generic Interfaces (C#)" — <https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/concepts/covariance-contravariance/variance-in-generic-interfaces>`를 덧붙인다.
2. **20 :45 — 절 번호가 표준판마다 다름.** "§6.5.6"은 N1570 번호로 맞다. N3220에서는 같은 J.2 (46) 항목이 "(6.5.7)"을 가리킨다.
   - 제안(선택): "… — §6.5.6(N1570). C23 초안 N3220에서는 J.2의 46번 항목(§6.5.7)이다."
3. **21 :109 — Kotlin 버전 조건.** `when`을 *식*으로 쓸 때는 완결성이 늘 요구된다(명세). `sealed`·`enum`·`Boolean` 대상의 *문*은 Kotlin 1.6에서 경고였고, 1.7부터 오류다(호환성 가이드 KT-47709: "1.6.0: introduce a warning … 1.7.0: raise …"). 노트 문장은 1.7 이후 기준으로 맞다. 현재 Control flow 문서는 String 대상 예시로 "If you use when as a statement, you don't need to cover all possible cases"라고 적어서, 문장만 보면 반대로 읽힐 수 있다.
   - 제안(선택): "… 컴파일 오류가 된다(Kotlin 1.7+, 식으로 쓴 `when`은 항상) …"
4. **19 :89 — "그 참조를 쓰는 지점"의 범위.** 원문은 "a point in the program that (directly or indirectly) uses a symbolic reference"다. 간접 사용도 포함된다. 현재 문장도 틀리지는 않는다.
5. **14 :102 — 확인 범위.** "거의 모든 경우"(JEP 491, Release 24)는 원문과 일치한다. 괄호 안 "`LM_LEGACY` 잠금 모드에서는 고쳐지지 않았다 — JEP 491 구현 PR 설명"은 JEP 본문에 해당 문구가 없다(`LM_LEGACY`·legacy 0회). 구현 PR은 이번 표본에서 열지 않아 대조하지 않았다.

부수 관찰: Rust Reference "Behavior not considered unsafe"는 release 빌드의 넘침을 "may result in panics or silently wrapped values … at the implementation’s discretion"이라고 적는다. 21 :57의 "`--release`에서 2의 보수 감김"은 인용한 The Rust Book 3.2 서술과는 맞지만, Reference는 이를 구현 재량으로 둔다. 표본 79건에는 넣지 않았다.
