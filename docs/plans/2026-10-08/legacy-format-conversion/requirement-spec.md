## 0. 요구사항 원문 (인터뷰)

- 원문: "다른 영역 오류들 수정하자" 중 "옛 형식 노트 2편 형식 전환" → 2편이 컬렉션 형식임을 보고 → **"컬렉션 전체 전환"**.
- Q/A (2026-10-08): 질문 6~10개 압축안 → 사용자 "개들은 실제 문제들을 거기 질문에 이식해놓은거 아니야?"(= 과제·질문을 줄이면 안 됨) → 메인 제안 "내용은 하나도 줄이지 않고 헤딩·번호·답 짝만 통일, 질문 수 상한은 과제 이식 컬렉션 예외(검사기 수정)" → **"진행하자"** · 검증 **가볍게, 합의 auto**.

## 1. 목표·대상 (필수)

- `cs/data-structure/` check FAIL 35편(01-dynamic-array~35-allocator 중 옛 형식) + `cs/domain-modeling/advanced/` 30편 = **65편**의 1-question·2-summary·3-answer·metadata를 check_new PASS 형식으로.
  - 1-question: 질문 단위를 줄 머리 `N. `로(그룹 소제목 `### A./B./C.`는 유지). domain-modeling의 `#### N. 제목` 절 = 질문 단위 하나(아래 코드블록·불릿 하위 질문은 그대로 붙여 둔다). `- C1.`~ 통일 골격 질문은 이어지는 번호 `N. (C1) …`.
  - 3-answer: 답 `#### N.` → `### N.`(C 항목도 `### N. (C1) …`), 그룹 소제목은 빈 절이 되지 않게 굵은 줄 `**A. 과제**`로.
  - 2-summary: data-structure 최상위 헤딩 '쓰이는 곳' → '쓰이는 자료구조·알고리즘'(절 본문 유지).
  - metadata: `| 형식 | 과제 이식 |` 행 추가.
- `docs/plans/2026-09-30/network-writing/check_new.py`: metadata에 `형식 | 과제 이식`이 있으면 질문 수 상한(10)만 면제(하한 6·번호 일치 등 나머지 규칙은 그대로).

## 2. 경계·불변식 (필수)

- **I1 내용 무손실**: 헤딩 기호·번호·굵게 표시·`(C1)` 꼬리표를 걷어낸 본문 토큰열이 전환 전후 같다(스크립트로 65편 전수 대조). 문장·코드·표·링크 텍스트 변경 0.
- **I2 번호 보존**: 기존 번호(domain-modeling의 0번 포함)는 바꾸지 않는다 — 본문의 "정답 N번 참고" 교차 참조가 그대로 맞아야 한다. C 항목만 새 번호를 받는다.
- **I3 검사기 최소 변경**: 면제 조건 1개만 추가, 다른 노트의 판정 결과 불변(전환 대상 외 leaf 전수 실행 결과가 전과 같음).
- **I4** 새로 깨는 링크 0, 생성기 재실행이 오류 없이 돌고 단계 집계 불변(초안 644).
