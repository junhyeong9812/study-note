원문과 선택의 흐름은 같은 폴더 `log.md` · `decisions.md` 에 인용으로 있다. 정해진 것:

study-site(옛 학습 사이트)의 항목 가운데 **study-note 에 없는 것 225개 + CSE 22장**(= 247 주제)을 study-note 의 새 폴더 `playground/` 에 주제 폴더(4파일)로 넣는다.

- 대상 목록의 정본: `…/scratchpad/api-jobs/gap2/gap-items.tsv` 의 `verdict = 없음`(93) + `none_candidate = 예`(132 — 기계는 "일부"로 봤으나 없음일 수 있는 것: 가르는 값보다 넣는 값이 싸다) + `platform = cse` 전부(22 — 일부는 위와 겹친다). 착수 때 워커가 목록 파일(`targets.tsv`)로 굳히고 수를 보고한다.
- 재료: 항목 데이터 `/home/jun/project/use-css/data/` · 정답 코드 `/home/jun/project/study-practice/<갈래>/<분류>/reference/` · CSE 원본 `/home/jun/project/study_docs/cs/cse-fundamentals/`.
- 꼴과 생성 방법의 정본: 시범의 `…/scratchpad/api-jobs/pilot/DESIGN.md` · `generate.py` · `prompt_common.md` · `check.py`(이 일에서 고쳐 쓴다).
- 함께: 원본 항목 데이터(JSON 88 · 7.3MB)를 `playground/_source/` 에 그대로 보존한다(그 폴더에만 있고 git 에 없는 자료다 · 사이트는 `*.md` 만 본다 — 색인에 들어가지 않는다).

## 2. 경계 · 불변식 (필수)

- **지어내지 않는다**: 원본 코드 · 정답 코드 · 실행 출력 · 출처는 스크립트가 원본에서 그대로 넣는다(모델은 자리표시만). 실행 출력은 **실제로 돌린 것만** "출력"으로 적고, 돌리지 못한 것은 "(실행하지 않음 — 까닭)"으로 적는다. 검사기가 이것을 본다(출력 한 줄을 바꿔치기하면 잡는다).
- **조용한 실패가 없다**: 대상 247 = 만들어진 폴더 247 = 검사 통과 247. 실패 · 잘림 · 거절은 목록으로 드러나고, 다시 돌리면 실패한 것만 돈다. 수가 맞지 않으면 올리지 않는다.
- **주제 폴더마다 4파일** · 질문과 정답은 1:1 · 글 하나 150KB 미만 · 깨진 상대 링크 0 · 원본 예제 코드가 빠지지 않는다.
- **study-note 의 다른 폴더는 그대로**: 기존 글을 고치지 않는다(`languages/` · `cs/` 와 겹치는 주제도 두 벌로 둔다 — 관련 자료의 링크로만 잇는다). 더하는 것은 `playground/**` 와, 폴더를 알리는 세 곳(`reference/study-note-guide.md` §1 갈래 표의 한 줄 · 루트 `README.md` 의 폴더 구조 · `index.md`)뿐.
- **초안임을 숨기지 않는다**: `metadata.md` 에 "단계 초안 · 검수 —" 와 출처(study-site 항목 · 집필 모델 · 날짜)를 적는다. `playground/README.md` 에 이 폴더가 무엇이고 어떻게 만들어졌는가(모델이 집필 · 검수 전)를 적는다.
- **운영 사이트를 고장 내지 않는다**: 한 번의 push 가 색인에서 실패하면 그 뒤의 모든 갱신이 멈춘다(`SyncService.kt:94~96`) — 갈래마다 나눠 올리고(가장 작은 갈래부터), 올릴 때마다 색인이 끝난 것(sync 워크플로 · 사이트의 글 · 검색)을 확인한 뒤 다음을 올린다.
- 시범이 드러낸 약점 셋을 본 실행 전에 고친다: 실습의 요구 조건을 동작 · 구조 중심으로(색 · px 값은 시작 코드에) · 실행하지 못한 까닭을 환경 중립의 글로 쓰고 퀴즈의 소재로 삼지 않는다 · 예측형 코드 문항은 셋 이하(검사기로 강제).

## 3. 기준소스 (필수)

- study-note: `README.md` · `reference/study-note-guide.md`(§1 · §2 · §2-1 · §3 · §4) · `.github/workflows/{notes-check,sync}.yml` · `scripts/notes/`.
- 운영 사이트(백엔드): `indexing/domain/DocClassifier.kt`(파일 이름 → 종류) · `shared/infra/GitRepository.kt:50,62`(`*.md` 만) · `SyncService.kt`.
- 모델 API: 워커의 `claude-api` 스킬(모델 ID · 값 · 배치 · 캐시 — 기억으로 쓰지 않는다).

## 4. 금지영역 (필수)

- study-note 의 push 는 사용자 확인 뒤(갈래마다 수 · 견본 · 검사 결과를 먼저 보인다). 다른 세션이 동시에 커밋할 수 있다 — 파일을 먼저 쓰고 · 이 일의 파일만 골라 스테이징하고 · 브랜치를 바꾸는 조작은 하지 않는다(따로 된 작업 트리에서 일한다).
- `use-css` · `study-practice` · `study_docs` 는 읽기만.
- API 키의 값을 문서 · 로그 · 커밋 · 생성물에 옮기지 않는다. 커밋 메시지에 작성 도구의 표기를 넣지 않는다(글의 출처로서의 "집필 모델" 표기는 metadata 에 둔다 — 초안임을 숨기지 않기 위한 것이다).
- 이번 단계의 API 비용 상한 **$60**(견적 약 $45 — 넘을 것 같으면 멈추고 보고).

## 5. 검증 방법 (필수)

- 생성 스크립트 · 검사기의 테스트(구현자와 다른 워커가 명세에서): 실패의 드러내기(429 · 5xx · 잘림 · 형식 어긋남) · 다시 돌리기 · 자리표시의 채움 · 검사기의 열한 가지 고장 내기(시범의 `test_check.py` 를 잇는다).
- 본 실행 뒤: 대상 = 폴더 = 통과의 **세 수의 대조**(메인이 직접 센다) · 실패 목록 0 · `usage` 의 합.
- **메인의 표본 읽기**: 갈래마다 다섯 주제를 끝까지 읽는다(틀린 사실 · 지어낸 것 · 질문이 정리로 풀리는가 · 실습과 정답 코드의 맞물림). + 독립 검증 워커가 다른 표본 40개를 읽고 원본과 대조한다.
- 올리기 전: study-note 의 검사기(`notes-check`)가 새 폴더로 깨지지 않는가 · 로컬에서 백엔드의 분류기에 새 경로를 넣어 종류가 맞게 나오는가.
- 올린 뒤(갈래마다): sync 워크플로의 성공 · 사이트에서 그 갈래의 글 · 퀴즈 화면 · 검색에 나오는가.
- 리뷰: 생성 스크립트 · 검사기는 듀얼 1패스(Opus ∥ codex) + 재점검.

## 6. stakes (필수)

- **중간**. 내용 저장소에 247 주제(약 990 파일)를 더한다 — git 으로 되돌릴 수 있다. 위험은 둘: 틀린 내용이 공부에 들어가는 것(초안 표지 · 표본 읽기로 줄인다) · 색인의 실패가 사이트의 갱신을 막는 것(나눠 올리기로 줄인다).

## 7. 자율성 · 허가 범위

- auto. push 는 갈래마다 확인.
- 워커는 API 과금의 화면 없는 세션(Opus) · 동시에 넷까지($120 을 쓴 뒤로는 둘).

## 8. load-bearing 가정

1. 배치 API 가 시범의 프롬프트(공통 머리말의 캐시 포함)로 그대로 돌고 값이 반이다 — **착수 직후 다섯 항목을 배치로 먼저 돌려** 결과의 꼴 · 걸린 시간 · 값을 잰다. 배치가 맞지 않으면 바로 부르는 방식으로(그때는 상한 안에서 대상 수를 줄여 보고).
2. 운영 사이트가 새 최상위 폴더 `playground/` 의 3파일 주제를 기존 주제와 같게 보여 준다 — 가장 작은 갈래를 올렸을 때 화면으로 확인한다(안 맞으면 멈춘다).

## 기본으로 정한 것 (합의 때 함께 본다)

- 폴더의 이름 `playground/`(원래 사이트의 이름 Code Playground) · 주제 폴더 `playground/<갈래>/<분류>/<NN-id>/` · CSE 는 `playground/cse/<장 폴더 이름>/`.
- CSE 는 장을 그대로 `2-summary` 로 두고 질문 · 정답만 만든다(쪼개지 않는다 — 원본이 사람이 쓴 완결된 글이다).
- 실행 환경은 지금 있는 것(`python3` · `node`)만 쓴다 — Java · Rust · 브라우저 화면의 예제는 "실행하지 않음"으로 적는다(뒤에 러너 ⑭ 가 생기면 채운다).
- 모델의 effort 는 시범과 같은 medium.
- 뒤로 미룬 것: 나머지 약 1,300 항목(있음 · 일부) · 프론트의 실습 화면에 CSS/JS 미리보기를 붙이는 일(⑭) · 검수.
