## 2. 표본에서 나온 오류 유형 (모두 찾아서 고친다)

1. **제품 내부 구조를 단정**: 예) "SQLite·ext4는 잎에만 값을 두는 B+트리". 제품별로 다르면 한정하거나 `[?]`를 붙이거나 삭제한다.
2. **수치·계산 오류**: 예) 100만 키를 높이 3으로 계산, BHD 1.234→12.34를 "100분의 1"로 설명. 직접 다시 계산하고, 원본 측정치와 대조한다.
3. **과도한 일반화·단정**: 예) "메모리에서는 레드블랙 트리가 맞다", "버림은 언제나 회사에 유리". 조건을 붙인다.
4. **원본에 없는 구체 설정·결과를 지어냄**: 예) "중간 정밀도 20자리", "왕복 143원" — README·impl에 없으면 지우거나 `[?]`를 붙인다.
5. **개념 혼동**: 예) 페이지 방문과 물리적 디스크 I/O를 같은 것으로 씀, 계산 순서가 반대. 바로잡는다.
6. **C절 정답이 본문 오류를 되풀이**하거나 질문과 맞지 않는 경우. 고친다.

## 3. 수정 규칙

- **새로 쓴 부분의 오류 → 직접 고친다.** 잘 모르는 구체 사실은 삭제하거나 `[?]`를 붙인다. 지어내서 메우지 않는다.
- **원래 본문(이동해 온 기존 내용)의 오류 → 기존 문장은 고치지 않는다.** 그 문단 바로 아래에 한 줄을 **추가**한다.

  - 원래 줄은 그대로 둔다. check.py 보존 검사가 이를 확인한다.
- 이미 `[?]`가 붙은 주장 처리:
  - 확인해서 맞으면 `[?]`를 떼고 근거를 짧게 붙인다.
  - 틀렸으면 고친다.
  - 확인할 수 없으면 그대로 둔다.
- 쓰는 방식(쉽게 쓰기, 그림 우선)과 코드 언어(Java 우선)는 `briefing.md`와 같다.
