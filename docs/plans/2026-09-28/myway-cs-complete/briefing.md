# 워커 공통 브리핑 — myway 5 cs 주제 완성 (2026-09-28)

## 1. 목표

담당 노트 폴더마다 `2-summary.md`·`1-question.md`·`3-answer.md` 세 파일을 다음 상태로 만든다.

1. **2-summary.md — 양식 통일.** 최상위(`##`) 헤딩을 아래 7개로, 이 순서로 맞춘다. 제목 줄(`# …`)과 그 아래 안내 인용문(`>`)은 맨 위에 그대로 둔다.

   ```
   ## 해결하는 문제
   ## 동작·원리
   ## 쓰이는 곳                        ← data-structure·algorithm 컬렉션
   ## 쓰이는 자료구조·알고리즘          ← 그 밖의 컬렉션(ops-patterns·api-design·domain-modeling)
   ## 적용 — 풀어나가는 법
   ## 장애 시나리오와 대처
   ## 핵심 문장
   ## 관련 주제·근거
   ```

2. **기존 절은 옮기기만 한다.** 기존 `##` 절은 아래 대응표의 새 절 아래로 옮기고, 헤딩 레벨을 한 단계씩 내린다(`##`→`###`, `###`→`####`…). 본문 문장·그림·코드블록·표는 **한 글자도 고치거나 지우지 않는다.**
3. **새로 쓰는 것**(아래 §3)은 비어 있는 새 절의 본문과 DS의 빈 절뿐이다.
4. **1-question.md / 3-answer.md**: 기존 내용(A·B절 등)은 그대로 둔다. 맨 끝, `## 복습 기록`이 있으면 그 **앞**에 `### C. 통일 골격 (Claude 초안 2026-09-28)`을 추가한다.
   - 질문: 새로 쓴 절마다 1~2개, 합계 4~6개. 번호는 C1, C2, …로 붙인다.
   - 3-answer에는 같은 번호로 정답을 단다.
5. **2-summary 헤더**: 제목 아래 인용문 블록 끝에 한 줄을 추가한다. `> 2026-09-28: 통일 골격 양식으로 재배치 + 새 절 추가(Claude 작성 — 기존 본문은 이동만).`

## 2. 기존 절 → 새 절 대응표

| 기존 `##` 절(이름에 포함된 말) | 옮길 새 절 |
|---|---|
| 한눈에 | 해결하는 문제 (새 본문 **아래**에 `### 한눈에 …`) |
| 사전 지식 | 동작·원리 (맨 앞) |
| 전체 흐름 | 동작·원리 |
| 동작 … / 구현 … / 계약 / 규칙 N / 설계 N / 결정 N / 보조 / 예시 그래프 | 동작·원리 (원래 순서 유지) |
| 문제 (과제·요구사항·TODO 목록) | 적용 — 풀어나가는 법 (맨 앞) |
| 비교 / 구현 전략 비교 / 나머지 축 / 측정 / 측정이 알려준 것 / 변종 … / 검증 / 테스트 이야기 / 요구사항 → 코드 … | 적용 — 풀어나가는 법 |
| 경계·모서리 케이스 / 실패 … / 실패 사례 / 한계 / 대가 … / 무엇을 잃는가 / 고칠 수 없는 것 … / 특히 생각해볼 것 | 장애 시나리오와 대처 (새 본문 **아래**) |
| 핵심 문장 | 핵심 문장 (`##` 그대로 — 이름이 같으므로 레벨 유지) |
| 관련 자료 / 용어 풀이 / 곁가지 / 이 챕터가 앞의 것들과 만나는 곳 | 관련 주제·근거 (새 링크 목록 **아래**) |
| 그 밖의 절 | 가장 가까운 새 절 — 판단 근거를 packet에 적는다 |

## 3. 새로 쓰는 내용

- **해결하는 문제**(3~8줄): 이 구조·기법·패턴이 없으면 무엇이 안 되나. 쉬운 예 → "똑같은 구조다" → 실무 예.
- **쓰이는 곳** / **쓰이는 자료구조·알고리즘**(불릿 4~8개): 다른 시스템·라이브러리·영역에서 실제로 쓰이는 자리를 적는다. 예: 동적 배열 → `ArrayList`·JS `Array`·Redis 리스트 인코딩.
  - 커리큘럼 해당 leaf의 🔧 칸을 씨앗으로 쓴다(`docs/plans/2026-09-27/cs-fundamentals-roadmap/curriculum.md` — slug로 검색).
- **적용 — 풀어나가는 법**: 기존 「문제」 절이 옮겨 오면 그 위에 2~4줄 도입만 쓴다. 기존 내용이 없으면 이 주제를 실제 문제에 적용하는 순서를 3~6단계로 쓴다.
- **장애 시나리오와 대처**(2~4개): 각각 **현상 → 보이는 형태(에러·증상·수치) → 원인 → 대처**를 쓴다. 커리큘럼 leaf의 ⚠ 칸을 씨앗으로 쓴다. 기존 경계·실패 절이 옮겨 오면 그것과 겹치지 않게 쓴다.
- **관련 주제·근거**: 같은 저장소 cs 노트 상대 링크 2~5개(실존 확인), 해당 영역 커리큘럼 표 링크, myway 원본 경로.
- **장애 절과 기존 정답의 관계**: 기존 「경계·실패」 절이 없으면 장애 절은 새로 쓰되, 기존 3-answer의 A·B절 정답과 내용이 겹치지 않게 하고, 필요하면 "정답 N번 참고"처럼 번호로 상호 참조한다.
- **DS 35편만**: 「전체 흐름」(ASCII 워크플로우)과 「핵심 문장」(3~5문장)이 템플릿 주석(`<!-- … -->`)과 빈 불릿(`-`)뿐이다. 주석과 빈 불릿을 내용으로 **교체**한다. 템플릿 주석에 적힌 순서 힌트(예: 고정 배열 → size/capacity → 확장/축소 → 대가)는 **구성 지시로 따른다**. 이 두 절에 한해 주석 삭제를 허용한다.

## 4. 쓰는 방식 (합의된 기준)

1. **그림 먼저, 글은 그림 해설.** 단순 ASCII(`+--+`, `->`)를 쓰고, 복잡한 그림 1개보다 단순한 그림 여러 개를 쓴다.
2. **용어는 처음 나오는 자리 바로 아래에서 푼다.** 형식: `  - *용어*: 설명`
3. 한 문장 = 한 개념. 용어가 3개 넘게 든 문장은 쪼갠다.
4. **코드 스니펫**: myway 원본이 Java이므로 Java가 기본이다. 필요하면 JS·TS를 쓰고, 저수준만 C를 쓴다.
5. 줄 끝 `\` 줄바꿈 등 **그 문서에 이미 있는 관례**를 따른다.
6. **사실 근거**
   - myway 원본 `/home/jun/project/myway/<컬렉션>/<챕터>/`(README·impl·src — 읽기 전용)과 기존 노트 본문을 근거로 쓴다.
   - 일반 지식은 교재 수준만 쓴다.
   - 확인하지 못한 수치·버전·출처에는 `[?]`를 붙인다. **지어내지 않는다.**
   - 컬렉션 이름 대응: domain-modeling/basic → `myway/domain-modeling-basic`, advanced → `myway/domain-modeling-advanced`. api-design은 `NOTES.md`·`REQUIREMENTS.md`·`solution`을 본다.
