# 요구사항 명세서 — network-writing

## 0. 요구사항 원문 (인터뷰)

- 원문: "그럼 이제 커리큘럼에 대한 학습자료 만들어야겠네"
- Q/A
  - 범위: **네트워크 51개 먼저**(미작성). 한 영역을 끝까지(집필 → 전수 점검 → 커밋) 진행하고 결과를 본 뒤 다음 영역으로 간다.
  - 검증: **집필 + Opus 전수 점검 + 웹 표본**
  - 집필 모델: 사용자 질문 "Fable이 필요한가, 점검을 Fable이 하는 게 맞는가?"
    - Claude 권장: 원본 없는 새 집필이라 정확성이 우선이니 Opus가 쓰고, 점검은 독립 컨텍스트의 Opus와 codex가 한다.
    - 사용자 결정: **먼저 주제 2개로 A/B 시범**. 같은 주제를 Fable과 Opus가 각각 쓰고 같은 점검을 거쳐 오류 수와 가독성을 비교한 뒤 정한다.
  - 형식: `cs/network/NN-slug/` 3파일, 통일 골격, 코드 스니펫은 Java·JS·TS(저수준은 C), "Claude 초안" 표기, 영역 README 자동 갱신

## 1. 목표·대상 (필수)

1. **A/B 시범**
   - 주제: `network/19-tcp-termination-fin-rst-half-open`, `network/29-tls-handshake`
   - Fable 판과 Opus 판을 각각 쓰고, 이름을 가린 독립 점검으로 비교표를 만든다.
   - 사용자가 집필 모델을 결정한다.
2. **본 집필**: 결정한 모델로 네트워크 미작성 51개를 `cs/network/NN-slug/{1-question,2-summary,3-answer}.md`로 완성한다.
3. **검증**: 전수 사실 점검과 웹 표본 교차 확인을 거친 뒤 커밋·push한다.

## 2. 경계·불변식 (필수)

- **I1 골격**: 2-summary의 최상위 헤딩은 7절이고 이 순서다.
  - 해결하는 문제 → 동작·원리 → 쓰이는 자료구조·알고리즘 → 적용 — 풀어나가는 법 → 장애 시나리오와 대처 → 핵심 문장 → 관련 주제·근거
  - 1-question의 질문 번호와 3-answer의 정답 번호는 일치하고, 개수는 6~10개다.
- **I2 근거**
  - 사실 주장은 RFC, 공식 문서, 표준 교재(Kurose&Ross, Stevens, HPBN 등)나 1차 출처로 확인한 것만 쓴다.
  - 확인하지 못한 수치·버전·기본값은 `[?]`로 표시한다.
  - 지어낸 수치·사례·API는 0이다.
- **I3 커리큘럼 일치**: leaf의 요지·⚠·🔧 칸을 모두 다룬다. 선행 주제에는 링크를 건다.
- **I4 기존 보존**: 기존 노트는 수정하지 않는다. 대상은 `원고 있음`인 46과 `초안(Claude)`인 24다. 링크만 건다.
- **I5 링크·트리**: 새로 깨지는 링크 0, 리프 폴더에는 md만 둔다.
