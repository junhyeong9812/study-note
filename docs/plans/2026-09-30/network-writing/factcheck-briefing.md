## 1. 대상

- 담당 폴더의 `2-summary.md`·`1-question.md`·`3-answer.md` 전부(새 파일이라 전체가 점검 대상).

## 2. 무엇을 찾나 (우선순위 순)

1. **사실 오류**: RFC 절·MUST/SHOULD 수준, 기본값·수치·버전, errno·예외 이름, 명령 옵션, 헤더 필드 크기, 날짜.
2. **계층·개념 혼동**: TCP 사건 vs 응용 사건, 커널 상태 vs fd 상태, 표현(representation) vs 전송, 권고 vs 규범.
3. **조건 없는 단정**: "항상·모든·반드시·절대" + 예외 존재. 구현 의존 동작을 보편으로 씀.
4. **지어낸 것**: 출처 없는 수치·로그 문구·API·사례. 예시 수치에 "(예시)" 누락.
5. **`[?]` 판정**: 확인되면 떼고 근거를 붙인다. 틀렸으면 고친다. 확인 불가면 둔다. 확인된 주장에 붙은 `[?]`도 뗀다.
6. **정답-본문 불일치**: 3-answer가 2-summary와 다르게 말하거나 질문에 안 맞음.
7. **노트 간 모순**: 담당 노트끼리, 또는 링크한 노트와 모순이면 packet에 보고(담당 밖은 고치지 않는다).

## 3. 수정 규칙

- 오류는 **직접 고친다**(새 노트라 정정 줄 방식이 아님). 확인 못 하는 구체 사실은 삭제하거나 `[?]`.
- 구조(헤딩·질문 수·번호)와 "Claude 초안" 표기는 바꾸지 않는다. 쉬운 문체·그림 우선은 유지.
- 근거는 원문을 직접 연다: rfc-editor.org txt(curl 후 grep), man7.org, kernel.org docs, 공식 문서. 웹 검색 결과 요약만으로 판정하지 않는다.
